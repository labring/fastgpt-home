# Security and Compliance Material Review for Warranty Defect Response: Citation Sources and Traceability

## What this category of data looks like
Typical users include after-sales service engineers, project managers, and R&D support staff. Daily used documents include warranty work orders, defect confirmation sheets, repair records, and customer confirmation sheets. Data sources are customer-submitted work orders, system operation logs, contract warranty clauses, and software or hardware version records. Update frequency is daily or synchronized with each individual task. Documents typically contain fields such as defect ID, responsibility boundary markers, repair execution steps, and customer confirmation markers. There is no unified mandatory format, but documents must be linked to relevant information from the original project delivery.

## What constraints do these characteristics impose on the citation sources and traceability link
Data for this category is scattered and covers the entire project delivery process. The citation traceability link must support associative retrieval across multiple data types to avoid fragmented information segments. Documents are updated per task or daily, so the retrieval pipeline must adapt to high-frequency, small-batch data updates without full reindexing. Document fields include key compliance information such as responsibility boundaries and customer confirmation markers, so traceability results must accurately match specific defect work orders, repair records, or contract clause entries. In warranty dispute scenarios, original metadata of cited content must also be retained to ensure every citation can be traced back to the original business node.

## How to set up configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 1200–1500 token | Adapts to the average length of single documents such as warranty work orders and repair records, avoiding truncation of key compliance fields |
| `responseData` | Retain original source identifier | Records metadata such as the document storage path and update time corresponding to the cited content |
| `detail` | Enable full field traceability | Displays business fields associated with the cited content, such as defect ID and responsible party |
| Single search recall count | Top 6–8 entries | Covers multiple types of associated documents corresponding to a single defect, avoiding omission of contract clauses or version records |
| Similarity threshold | 0.75–0.85 | Matches warranty-related keywords and filters irrelevant operation and maintenance documents |
| Rerank toggle | Enabled | Prioritizes documents containing customer confirmation markers to improve compliance review efficiency |

## Three common misconfigurations
- Phenomenon: After enabling the rerank function, search results return empty or citation snippets are empty. Cause: The rerank similarity threshold is set too high, filtering out low-relevance but warranty-related document fragments that meet requirements.
- Phenomenon: Data sources or plugins referenced in import/export workflows cannot be recognized. Cause: The associated data source path configuration from the original environment was not retained, or the plugin version does not match the target environment.
- Phenomenon: Associated business fields are not displayed in cited content. Cause: The full traceability configuration of the `detail` parameter was not enabled, so only text snippets were returned without accompanying metadata.

## How to confirm the configuration is complete
- Submit a typical warranty defect query, and check whether the returned results include document fragments such as associated warranty work orders and contract clauses.
- In FastGPT v4.17.0, view the details panel of cited content to confirm whether it includes business fields such as the source document's update time and defect ID.
- Test adjusting the similarity threshold, and compare the number of search results under different thresholds to verify the rationality of the threshold configuration.
- Export relevant data for citation traceability, and check whether it includes complete identifier information for the `responseData` field.
