# Security and Compliance Material Review for On-site Outsourced Operations Services: Document Parsing and Chunking

## What this category’s data looks like
Daily documents for on-site outsourced operations services mainly include daily on-site reports, helpdesk tickets, inspection reports, and SLA monthly reports. Data sources are the customer’s ITSM system, monitoring platform, asset inventory, and duty records. Update frequencies fall into two categories: daily updates (daily on-site reports, tickets) and monthly updates (SLA monthly reports). Document structures include natural paragraphs, multi-row business tables, and statistical fields. Common fields include ticket number, inspection point, SLA achievement rate, and duty time period. Units include hours, quantity counts, percentages, and similar metrics.

## Constraints imposed by these characteristics on document parsing and chunking
Documents are sourced from multiple customer systems, with supported file formats including XLSX, PDF, PPT, and plain text. The parsing link must adapt to multiple file types. Batch document requirements for daily and monthly updates require configurations that support batch scheduled parsing and reasonable timeout thresholds. On-site documents mostly contain multi-row business tables. Chunking must retain table context to avoid split misalignment. Compliance review requires that parsing does not lose sensitive fields, and must accurately restore document structures. Some older customer documents use non-UTF-8 encoding, which may trigger parsing errors.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Effective single-paragraph information length for daily on-site reports and inspection reports. Avoids overly fragmented chunks or splitting across key business information |
| `chunkSplitter` | Split by paragraph + table | Tickets and inspection reports contain multi-row tables and natural paragraphs. Mixed splitting preserves complete business context |
| `customPdfParse` | Enabled | On-site inspection reports are mostly formatted or scanned PDFs. Custom parsing restores table and layout structures |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Typical maximum size of monthly SLA reports and aggregated ticket packages for batch uploads |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Typical parsing time for large-volume PDFs or multi-table PPTs. Prevents task interruption due to timeout |
| `chunkSettingMode` | Manual mode | On-site document formats vary widely. Manual configuration adapts to chunking needs for different document types |

## Three common configuration mistakes
- Symptom: An error "the argument ‘windows-1252’ is invalid encoding" appears when uploading PPTs or documents. Cause: The document’s non-UTF-8 encoding is not adapted, and the default parsing encoding cannot recognize the character set.
- Symptom: Multi-row ticket tables in XLSX format are split into scattered chunks. Cause: Chunking rules that split by table are not configured. Splitting only by character length loses table context associations.
- Symptom: Parsing times out and fails when uploading monthly SLA reports in batches. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` configuration value is too low, and does not adapt to the parsing time of large-volume, multi-table documents.

## How to verify correct configuration
- Upload a daily on-site report document, check if the parsed chunked content retains key fields such as ticket number and processing result, with no obvious content truncation.
- Upload an XLSX-format inspection report, verify that table content is fully imported, and no cell content split misalignment occurs.
- Upload a monthly SLA report within 1000 MB, confirm that the parsing task completes within 600 seconds, with no timeout errors.
- Check the backend configuration logs of FastGPT v4.17.0, confirm that configuration items such as `customPdfParse` and `chunkSettingMode` have taken effect as preset.
