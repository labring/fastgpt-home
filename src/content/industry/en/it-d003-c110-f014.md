# Security and Compliance Material Review for On-site Outsourced Operations Services: Model Access and Configuration

## What This Category of Data Looks Like
This type of data typically originates from customer ITSM systems, operation and maintenance monitoring platforms, internal asset inventories, and on-duty records. Daily generated documents include on-site daily reports, service desk tickets, inspection reports, and SLA monthly reports. Data update cycles are primarily daily and monthly. Individual documents contain fields such as on-site personnel identification, ticket number, inspection item name, service response time window, and asset number. Field coverage and update frequency vary across different document types.

## Constraints on Model Access and Configuration Posed by These Characteristics
The scattered data sources and varied update cycles of this category require the model access link to support multi-source API docking and differentiated synchronization frequency configuration. Field differences across different documents require the model to adapt to non-standardized text input formats. On-site services involve customer internal assets and ticket data, which impose higher compliance requirements for model calls. Restrictions on model inference modes and data output scope are necessary. Processing long-text documents such as monthly SLA reports requires configuring sufficient context windows and token limits to avoid truncation of critical information.

## How to Configure Parameters
The following configurations are formulated based on the logic of FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the length requirements of individual documents such as on-site daily reports and inspection reports, avoiding long text truncation |
| `maxTokens` | 2000–3000 token | Meets the output length requirements for compliance material review, covering scenarios such as ticket summarization and SLA statistics |
| `toolChoice` | none | Restricts the model to only perform text generation, avoiding tool calls and meeting compliance review requirements in on-site scenarios |
| `temperature` | 0.1–0.3 | Reduces output randomness, ensuring consistency and accuracy of compliance review results |
| `AIPROXY_API_ENDPOINT` | The root address of the AI Proxy service, for example http://aiproxy:3000. Do not append /v1 or /chat/completions | Required environment variable for FastGPT App/Admin server, used to connect to the AI Proxy service |
| `AIPROXY_API_TOKEN` | The non-empty administrator token consistent with the AI Proxy server configuration | Required environment variable for FastGPT App/Admin server, used for AI Proxy service authentication |

## Three Common Configuration Errors
- Phenomenon: Model output includes content related to inference modes, and restriction of the model to only use text generation mode cannot be achieved. Cause: The `toolChoice` parameter is not configured correctly, or the parameter value does not match the modes supported by the target model.
- Phenomenon: An access denied error is prompted when configuring access to Alibaba Cloud models, and no such issue occurs when accessing models from other platforms. Cause: Upstream model channel configuration is incorrect, such as Alibaba Cloud model vendor credentials or interface addresses, and the configuration does not adapt to Alibaba Cloud's interface access rules.
- Phenomenon: After adding an embedding model configuration with the same name, the existing configuration is automatically overwritten, and retention of multiple versions of configurations is not possible. Cause: Unique identifiers are not added for different model configurations, resulting in overwriting of configuration items with the same name.

## How to Verify Successful Configuration
- A single on-site daily report document is uploaded, model review is initiated, output content is checked against compliance requirements, and parameters are adjusted until output meets expectations.
- Documents from multiple data sources are tested for access, confirming content from ITSM systems and monitoring platforms can be read and processed normally.
- Interface access logs are checked to confirm no access denied or timeout errors exist, and `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` configurations are verified as valid.
- Multiple model configurations with unique identifiers are added to confirm same-name configurations are not automatically overwritten, ensuring stability of multi-model calls.

The values provided are common starting points and should be measured against samples appropriate for the specific deployment.
