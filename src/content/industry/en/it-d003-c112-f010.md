# Security and Compliance Material Review for Incident Management and Root Cause Analysis: Citation Sourcing and Traceability

## What the Data for This Category Looks Like
This category’s data originates from incident timelines, operational logs, monitoring metrics, and code commit records. Updates trigger on major incident launches or monthly. Daily produced documents include root cause analysis (RCA) reports, incident tickets, post-incident review minutes, and rectification tracking sheets. Document structures center on incident events, root cause hypotheses, verification processes, and rectification items. Fields include incident occurrence time, impact scope, associated code commits, rectification closure status, and more. No unified fixed units exist; field units adjust based on document type and content.

## Constraints Imposed on Citation Sourcing and Traceability
The time-series nature of data sources such as incident timelines and operational logs requires citation traceability tools to match event time windows. This prevents cross-cycle referencing of irrelevant data. Document structures updated monthly or per major incident require traceability tools to link to the exclusive document set of the corresponding incident. This avoids mixing data across incidents. Variations in fields across documents such as RCA reports and rectification tracking sheets require traceability links to identify metadata tied to document types. This ensures cited compliance materials align with root cause analysis business logic. Mixed referencing of multi-source data requires clear priority setting for each data source. This prevents data conflicts during root cause verification.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Matches the core content length of single RCA reports and rectification tracking sheets for this category. Prevents truncation of critical information required for compliance reviews, and aligns with FastGPT v4.17.0 parameter logic |
| Maximum Knowledge Base Citations | `Top 3–5 matching results` | Excessive citations in this category’s incident-related datasets will distract from focused verification of root cause hypotheses |
| `responseData` | `Full citation including document metadata` | Root cause analysis and compliance reviews require linking to metadata such as incident occurrence time and code commit records. This ensures traceability |
| Maximum Context | `4000–6000 token` | Covers the complete analysis context of multiple incident documents and log snippets. Supports root cause verification across source data |
| `detail` | Enabled | Displays the surrounding context of cited passages. Facilitates verification of the logical validity of root cause hypotheses |
| Maximum Response Tokens | `1500–2000 token` | Matches the standard output length of root cause analysis reports. Prevents truncation of cited compliance materials |

## Three Common Misconfigurations
- Symptom: Cited compliance passages in root cause analysis results are truncated, preventing access to full content. Cause: The `quoteMaxToken` parameter is set too small, failing to match the core content length of documents such as RCA reports.
- Symptom: Data conflicts occur during root cause verification, making it impossible to determine the incident associated with cited compliance materials. Cause: The metadata inclusion option for `responseData` is not configured, leading to failure to retrieve information such as incident occurrence time and commit records during traceability.
- Symptom: Knowledge base searches return a large number of irrelevant non-incident documents, distracting from root cause hypothesis verification. Cause: The maximum knowledge base citations setting is too high, without adjusting parameters to match the characteristics of this category’s incident datasets.

## How to Verify Proper Configuration
- Upload a typical RCA report, trigger a root cause analysis task, and check whether the displayed length of cited passages falls within the expected range.
- Review the attached information for each citation, confirming that it includes metadata such as incident occurrence time and associated code commit records.
- Adjust the maximum knowledge base citations setting, and verify whether the number of returned matching results aligns with the set range.
- Test toggling the `detail` configuration, and check whether the display format of cited passages meets compliance review requirements.

The values provided are common starting points, and should be assessed against the reader’s own sample data.
