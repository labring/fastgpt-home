# Security and Compliance Material Review for Integration and Interface Testing: Document Parsing and Chunking

## What data in this category looks like
Data in this category primarily comes from interface management platforms, test environment logs, databases, and message queues. The update frequency is daily or per version iteration. Commonly processed documents include interface test cases, joint debugging issue tickets, environment descriptions, and test reports.
Interface test cases contain structured fields such as interface addresses, request methods, parameter lists, and expected return values. Joint debugging issue tickets record issue numbers, associated modules, error messages, and troubleshooting progress. Environment descriptions include static configurations such as deployment addresses and dependent service versions. Test reports include summary data such as test case pass rates and exception statistics.

## What constraints these characteristics impose on the "document parsing and chunking" workflow
Diverse data sources require parsing modules to adapt to multiple formats including structured parameters, semi-structured logs, and unstructured documents. High-frequency update rhythms require parsing processes to support incremental synchronization and batch processing, avoiding repeated parsing of historical data. Differences in document structure require chunking logic to balance semantic integrity and granularity adaptation. It must neither split cross-module joint debugging records into unrelated fragments nor merge long test reports into a single chunk that impairs retrieval. Some data comes from real-time logs and message queues, requiring support for low-latency parsing triggers and timeout control.

## How to configure these settings
These configurations apply to FastGPT v4.17.0:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the length of parameter lists in interface test cases and single-segment descriptions in joint debugging issue tickets, avoiding splitting semantically complete troubleshooting records |
| `chunkSplitter` | Split by paragraph | Matches the natural paragraph logic of joint debugging issue tickets and test reports, preserving contextual connections in troubleshooting processes |
| `customPdfParse` | Enabled | Supports parsing uploaded PDF-format test reports and environment description documents, adapting to compliance material formats archived by teams |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapts to batch-imported version-level test reports and log archive packages, avoiding upload failures caused by oversized files |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Matches the parsing time of large log archive packages, avoiding full parsing of compliance materials being interrupted by timeouts |
| `chunkSettingMode` | Manual configuration | Adjusts chunking granularity for structured fields in interface test cases, adapting to document specifications of different teams |

## Three common configuration errors
- Uploading a CSV-format interface test case only returns the first two columns of data: This occurs because the column range for CSV parsing is not configured. The default setting only reads the first two columns of fields, which does not match the structural requirements of multi-parameter columns in test cases.
- Uploading compliance materials in a Docker deployment environment prompts a 413 error: This occurs because the `UPLOAD_FILE_MAX_SIZE` configuration is not adjusted. The default upload size limit of the container does not match the configured value, causing large file upload failures.
- Feishu multi-level directory documents cannot be fully parsed: This occurs because the recursive directory parsing switch is not enabled. Only documents in the root directory are parsed, failing to cover joint debugging issue tickets and test reports archived in multi-level directories.

## How to confirm configurations are correctly applied
- Upload a CSV-format interface test case with multiple parameter columns, verify that all column fields are included in the parsing results to confirm CSV parsing configuration is correct.
- Upload a test report archive package larger than 500 MB, verify that the upload and parsing processes complete normally to confirm the `UPLOAD_FILE_MAX_SIZE` configuration takes effect.
- After configuring the external pdf-maker parser key, upload a PDF-format test report, verify that the parsed text content is complete to confirm parser calls operate normally.
- Upload a link to Feishu multi-level directory documents, verify that all joint debugging issue tickets in subdirectories are included to confirm the recursive parsing switch is enabled.

The values provided here are common starting points, and should be evaluated against the user's own samples.
