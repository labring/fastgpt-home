# Security and Compliance Material Review for Requirements Analysis and PRD Management: Citation Sources and Traceability

## What the data for this category looks like
The typical data for this category comes from daily outputs of internet product teams, business analysts and product managers. This includes requirement research notes, PRD documents, user story lists and requirement change forms. Data sources cover customer interview records, internal ticket systems, public competitor pages and dashboard analytics. Update frequency is mostly weekly or per release cycle. Document structures include fields such as requirement items, acceptance criteria, associated user stories, change times and version numbers. Content length and format vary significantly across different document types.

## What constraints these characteristics impose on the "citation sources and traceability" workflow
Mixed multi-source data requires the traceability system to support unified identification and jumping across document types. This prevents confusion between compliance materials from different channels. Weekly or per-release update cycles require the traceability process to refresh indexes regularly. This ensures cited materials use the latest versions. Differences in document structures require configuration items to adapt to varying content lengths. This avoids truncating critical acceptance conditions or change descriptions. The time-consuming nature of the requirements analysis phase requires the traceability process to quickly locate original materials. This reduces repetitive work for categorization and boundary confirmation. Accurate traceability also lowers the risk of development rework and schedule delays.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum citation token count | Set `quoteMaxToken` to 800–1200 tokens | Adapts to single-paragraph content length of PRDs and requirement research notes. Prevents truncation of compliance-related acceptance criteria and change descriptions |
| Single recall citation limit | Top 5 entries | Matches the range of materials associated with a single requirement. Prevents information overload that reduces requirements analysis efficiency |
| Citation detail display | Enable `detail` | Shows the original document's storage path and last modified time. Meets traceability requirements for compliance audits |
| Attach source data to responses | Enable `responseData` | Carries original document metadata. Facilitates quick synchronization of associated materials during subsequent requirement changes |
| Context splicing limit | 10000 characters | Adapts to the splicing length of multiple requirement documents. Covers all associated compliance and business materials |

## Three common configuration mistakes
- Phenomenon: The number of citations recalled by the knowledge base does not match expectations. Some associated requirement change forms are not returned. Cause: The recall refresh cycle is not configured according to the weekly or per-release update frequency. This causes old version materials to not be synchronized and updated.
- Phenomenon: Metadata fields for citation sources are empty. The specific version and path of the original document cannot be traced. Cause: The `responseData` parameter is not enabled, and metadata extraction rules are not configured.
- Phenomenon: Citation content is truncated. Key compliance terms cannot be fully displayed. Cause: `quoteMaxToken` is set too low. This forces truncation of long PRD content.

## How to verify correct configuration
- Upload a complete PRD document to trigger the citation traceability process. Check if the returned results include the original storage path and last modified time of the document.
- Adjust the `quoteMaxToken` parameter to 1500 tokens. Upload a requirement research note with over 1000 characters. Verify that the content is not truncated.
- Simulate a multi-source material recall scenario. Confirm that interview records and ticket content from different channels are correctly merged and displayed.
- Confirm that the current FastGPT version is v4.17.0. Verify that all configuration items are within supported ranges.
