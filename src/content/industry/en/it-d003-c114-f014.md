# Security and Compliance Material Review for Requirements Analysis and PRD Management: Model Access and Configuration

## What data looks like for this category
Data for this category comes from daily outputs of internet product teams, business analysts, and product managers. This includes requirement research notes, PRD documents, user story lists, and requirement change orders.
Data sources cover customer interview records, internal ticketing systems, competitor public pages, and analytics dashboards. Update cadence follows a weekly schedule or aligns with product version iterations.
Document structures include fields such as business goal descriptions, acceptance criteria, functional boundary notes, and change records. No unified mandatory units apply. Most content consists of natural language descriptions of business rules and user requests.
This page applies to the configuration logic of FastGPT v4.17.0.

## What constraints these characteristics impose on model access and configuration
This category's data characteristics create multiple constraints for model access and configuration.
First, daily documents primarily use natural language business rules. Configure context length parameters optimized for natural language understanding to fully capture requirement descriptions and boundary conditions.
Second, data updates occur weekly or with product version iterations. Enable configuration items that support dynamic sync of the latest documents to prevent models from using outdated requirement information.
Third, data sources are scattered with no unified format. Ensure model call permissions cover access to multi-source data, while retaining call logs for compliance tracing.
Fourth, frequent updates to requirement change orders require models to handle incremental data efficiently. Avoid call timeouts caused by context overload.

## How to set configurations
The following configuration items apply to the FastGPT v4.17.0 model access logic:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | Enter the root address of the AI Proxy service, for example http://aiproxy:3000. Do not append /v1 or /chat/completions paths | Used as an environment variable for the FastGPT App/Admin server to specify the AI Proxy service address |
| `AIPROXY_API_TOKEN` | Enter the administrator token matching the AI Proxy server configuration. Do not leave this field empty | Used as an environment variable for the FastGPT App/Admin server for AI Proxy service identity verification |
| `maxContext` | `8000–12000 token` | Matches the average length of requirement analysis documents, prevents loss of requirement boundary information due to insufficient context |
| `maxTokens` | `2000–3000 token` | Limits the output length of a single review, ensures compliance material review results are complete and do not exceed platform limits |
| `temperature` | `0.2–0.4` | Reduces output randomness, ensures compliance review results align with fixed business rules and compliance requirements |
| `toolChoice` | `auto` | Allows the model to independently choose whether to call tools for complex rule validation in requirement analysis, adapts to review needs across multiple scenarios |

## Three Common Configuration Mistakes
- Symptom: Model call rate is limited, with only 1 review request completed per second. Troubleshooting steps: Check if multi-key configuration is missing, and if only a single key is used to trigger requests.
- Symptom: Compliance review results returned by the model do not match the actual requirement documents, with incorrect boundary condition judgments. Troubleshooting steps: Check if the `temperature` configuration value is too high, leading to excessive model output randomness.
- Symptom: Models from specified platforms cannot be accessed, such as Tongyi Qianwen-Max. Troubleshooting steps: Check if the upstream model address and vendor credentials configured for the model channel are correct. Verify that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are configured as FastGPT server environment variables as required.

## How to Confirm Configurations Are Correct
- Run a single model call test. Check if the returned results include core business goals and acceptance criteria from the requirement documents. Verify that results match expected outcomes.
- Check the FastGPT service startup logs. Confirm there are no startup validation failure records for unconfigured `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN`, and no related identity verification failure logs.
- Simulate concurrent calls with multiple keys. Check if request processing rate meets expectations. Confirm that load balancing logic is active.
- Adjust the `maxContext` and `maxTokens` configuration values. Verify that context overflow error messages disappear, confirming that parameters match current document lengths.
