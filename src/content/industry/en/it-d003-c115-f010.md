# Security and Compliance Material Review for Project Implementation Plan Management: Citation Sources and Traceability

## What the Data for This Category Looks Like
Core data for the project implementation plan management category typically comes from project contracts, work breakdown structures (WBS), client schedules, and enterprise project management systems. Daily generated documents include overall project plans, milestone node lists, weekly progress reports, and risk and issue tracking lists. Data update frequency is usually once per week or triggered by individual milestone nodes. Most document structures are broken down by task hierarchy, with fields such as task ID, responsible person, estimated duration, current progress, and associated risk items. There are no unified fixed units of measurement. Some fields use percentages or calendar days as measurement standards.

## How These Characteristics Impact Citation Sources and Traceability
Data sources for this category are scattered and updated frequently. The citation traceability process must link the latest version of data to its generation source. This avoids citing expired project plans or incorrect task nodes. The hierarchical structure of documents requires traceability information to record parent-task and child-task associations. This ensures cited content can be traced back to specific WBS entries. The multi-field structure of documents requires configuration to accurately match core retrieval keywords such as task ID and progress status. This prevents recall of irrelevant risk items or weekly report content from non-current cycles. Cross-system data sources require the traceability process to uniformly record the original storage location of data. This allows quick location of original materials during subsequent compliance reviews.

## Configuration Settings
This configuration applies to FastGPT v4.17.0 and later versions.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `8000–12000 token` | Single content length of project implementation plan documents is relatively long, needs to cover complete task breakdown and associated information |
| `responseData` | Return results include original source fields | Compliance review requires clear identification of original document name, generation time, and storage path for cited content |
| `detail` | Enable full-field traceability | Project data includes multi-dimensional fields, needs to fully retain all retrieved associated information for compliance verification |
| Context version matching | Match by document update time | Project data is updated frequently, needs to ensure that cited content uses the currently active plan version |
| Single recall limit | Top 8 entries | Core associated information of project implementation plans is concentrated in a small number of high-priority tasks; excessive recall increases context redundancy |

## Three Common Configuration Mistakes
- Phenomenon: `quoteMaxToken` is set to 12000 token, but the actual number of recalled content items does not match the set context limit. Cause: The context version matching rule is not configured synchronously. This causes the system to simultaneously recall expired historical document versions, consuming token quota.
- Phenomenon: Original sources of cited content cannot be found during compliance review. Cause: The `responseData` configuration is not enabled. The storage path and generation time of the original document are not recorded in the returned results.
- Phenomenon: Retrieved content includes weekly report content from non-current cycles. Cause: The rule matching by document update time is not set. The system recalls historical weekly report data older than one week.

## How to Verify Configuration is Correct
- Check environment variables on the App/Admin server. Confirm that `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service, for example http://aiproxy:3000; do not append /v1 or individual model service addresses) and `AIPROXY_API_TOKEN` (AI Proxy administrator token, must match the AI Proxy server configuration and cannot be empty) are correctly configured. Ensure these values are not filled in workflow global variables, application API request headers, or the general model management page.
- Initiate a compliance review request for a project plan. Check whether the returned results include fields related to original sources, to confirm traceability information has been recorded.
- Adjust the value of `quoteMaxToken`, observe changes in the length and number of recalled content, to verify configuration effectiveness.
- Import an expired historical project plan document. Verify that the system automatically filters non-current version content.

The values provided here are common starting points. They should be evaluated against the reader's own samples.
