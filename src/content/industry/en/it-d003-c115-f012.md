# Security and Compliance Material Review for Project Implementation Plan Management: Document Parsing and Chunking

This configuration guide is based on FastGPT v4.17.0, and is tailored to meet security and compliance material review requirements for project implementation plan management scenarios.

## What Data for This Category Looks Like
Data for this category typically comes from project contracts, work breakdown structures (WBS), client scheduling, and project management systems. Update frequency is weekly or upon completion of a milestone node. Daily processed documents include project implementation plans, milestone lists, weekly progress reports, and risk issue lists. Document fields often include responsible parties, progress nodes, risk levels, budget amounts, and similar items. Some documents include structured scheduling tables and task breakdown entries.

## Constraints for Document Parsing and Chunking
Diverse document sources lead to mixed formats, including structured tables, plain text schedules, and list-style entries. Parsing tools must support both structured content extraction and non-text content parsing. Weekly or milestone-level update frequency requires the parsing process to support batch rapid processing, to avoid delaying project progress synchronization due to overly long processing times. Documents include structured fields such as progress nodes, responsible parties, and risk levels. Chunking must retain field association relationships, to avoid splitting that breaks task logic. Some documents include compliance-related risk descriptions. Parsing must retain the original key expression boundaries, to prevent compliance information from being fragmented and causing review failures.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Matches the information density of single chunks in task breakdown and scheduling tables in project documents, to avoid splitting that breaks task associations |
| `chunkSplitter` | Split by paragraph + heading hierarchy | Aligns with the hierarchical structure of project documents, such as chapters of project plans and subsections of weekly reports, retaining logical boundaries |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time required for batch project documents, to avoid parsing interruptions due to large document size or complex formats |
| `customPdfParse` | Enabled | Optimizes extraction completeness of table content for project documents that include structured tables |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Meets the upload requirements for large project plan documents, supporting batch processing scenarios for multiple versions of documents |
| `chunkSettingMode` | Manual configuration | Flexibly adjusts chunking parameters for different types of project documents, such as weekly reports and risk lists, to adapt to specific scenario needs |

## Three Common Mistakes
- Symptom: A "parsing service not ready" error is returned when calling the file parsing tool, or the tool call does not respond. Cause: The `customPdfParse` parameter is not correctly enabled, or the parsing service container was not started per configuration.
- Symptom: Structured table content is missing or formatted incorrectly in the parsed document. Cause: The `customPdfParse` configuration is not enabled, or chunking parameters do not adapt to table column width and row count, leading to incorrect splitting of table content.
- Symptom: Parsing tasks time out and fail, returning status code 504. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` setting is lower than the actual parsing time required for batch project documents, or the size of a single document exceeds the `UPLOAD_FILE_MAX_SIZE` limit.

## How to Verify Correct Configuration
- Upload a typical weekly project report document, check if the parsed text retains the report’s section headings and task entries, confirming that the chunking logic meets expectations.
- Review the background logs of parsing tasks, confirm that the `PARSE_FILE_TIMEOUT_SECONDS` parameter did not trigger a timeout error, and that uploaded files were not blocked due to size.
- Test batch upload of 3 different types of project documents, such as project plans, risk lists, and weekly reports, checking that all complete parsing and chunking processes successfully run.
- Adjust the `chunkSize` parameter to 1000 characters, compare the chunking results before and after adjustment, confirming that the parameter configuration takes effect.
