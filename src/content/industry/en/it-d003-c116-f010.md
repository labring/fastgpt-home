# Security and Compliance Material Review for Project Document Handover and Archiving: Citation Sources and Traceability

## What Data for This Category Looks Like
This category of data mainly comes from project document libraries, configuration lists, meeting minutes, and test reports. The update cadence follows the end of each project phase or overall project delivery. Daily processed documents include as-built documents, configuration manuals, training records, and acceptance certificates. Each single document typically contains fields such as project number, delivery node identifier, version number, and seal record. Some documents include binary seal files and test attachments. Data volume fluctuates with project scale, and there is no fixed unified unit standard.

## What Constraints These Characteristics Impose on the Citation Sources and Traceability Link
Data sources are scattered across multiple storage locations, so the traceability link must implement cross-storage-source association matching. Document updates trigger dynamically with project phases. Unstandardized version management requires the traceability system to identify and associate different iterative versions of the same document. Documents such as as-built documents and acceptance certificates include seals and binary attachments, so traceability must record both text content and storage paths of original files. Precise matching requirements for fields such as project number and delivery node mean traceability configuration must limit searches to the project dimension, avoiding interference from irrelevant cross-project data.

This configuration is formulated based on FastGPT v4.17.0.

## How to Set the Configuration
| Configuration Item | Recommended Value | Basis for This Setting |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the average length of single documents such as as-built documents and acceptance certificates, ensuring complete citation of core content |
| `responseData` | Only return text fields and original file paths | Matches the feature that this category of documents includes seal attachments, avoiding redundant unnecessary fields interfering with traceability |
| `detail` | Enable full traceability mode | Retains associated information such as project number and delivery node, meeting the requirement for precise matching within the project dimension |
| Single recall limit | Top 3 entries | Adapts to the average number of documents per project, avoiding excessive irrelevant documents causing traceability confusion |
| Version matching switch | Enable | Adapts to the feature that documents update with project phases, ensuring citations use the current delivery version of documents |

## Three Common Misconfigurations
- An error of empty fields appears when viewing knowledge base citations in chat responses after configuration, and associated information for seal attachments cannot be displayed. The cause is that the return fields for `responseData` were not set correctly, and the configuration item for original file paths was omitted.
- The response forcibly displays workflow invocation input and response citation content, and cannot display only the answer. The cause is that non-essential traceability display switches were not closed, and display content was not filtered according to category requirements.
- Recalled documents exceed the reasonable range of a single project, and irrelevant cross-project data appears. The cause is that the project dimension for traceability was not limited, and the configured search range was not associated with the project number field.

## How to Confirm the Configuration Is Effective
- Initiate a search for a single as-built document, check if the returned citation content includes the original file path field, and confirm that the `responseData` configuration is effective.
- View the citation module in chat responses, confirm that only document content related to the current project is displayed, and no irrelevant cross-project data appears, confirming that the project dimension search configuration is effective.
- Trigger a complete document handover and archiving process, check if the citation traceability link can correctly associate document versions from different phases, and confirm that the version matching switch is effective.
- View log records, confirm that the single citation token count does not exceed the preset range, and no overflow errors related to `quoteMaxToken` occur.
