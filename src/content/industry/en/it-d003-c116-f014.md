# Security and Compliance Material Review for Project Document Handover and Archiving: Model Access and Configuration

## What data for this category looks like
Data for this category primarily comes from project document libraries, configuration lists, meeting minutes, and test reports. Updates occur during project phase deliveries or when a full project concludes.
Daily processed documents include four types: completion documents, configuration manuals, training records, and acceptance certificates. Each document has fixed fields: document number, version identifier, signature status, and associated project identifier.
Data is stored in MB units. The content complexity of a single document varies based on project scale.

## Constraints imposed on the model access and configuration workflow
Multi-source, scattered data sources require the model access link to support cross-library data association and pulling. Data mapping rules must be configured ahead of time.
Irregular document update cycles require the context synchronization mechanism to support on-demand triggering.
Field differences across document types require the configuration to allow flexible specification of the field set to be validated.
Wide variation in single document storage sizes requires the context length configuration to be adjustable based on actual scenarios.
Compliance reviews require validation of specific fields such as signatures and version consistency. This requires binding extraction and validation rules for corresponding fields during model access.

## How to set configurations
These configurations are based on FastGPT v4.17.0.
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | The total content of a single batch of transferred project documents typically covers multiple completion and acceptance documents. Sufficient context must be retained to validate version consistency |
| `maxTokens` | `2000–3000 token` | Compliance reviews require complete validation results to be output. This avoids truncating descriptions of key signature and version information |
| `quoteMaxToken` | `1500 token` | Original document fragments that need quoting are mostly key pages from acceptance certificates and configuration manuals. Controlling quote length ensures readability |
| `toolChoice` | `auto` | Automatic triggering of document integrity and version consistency validation tools is required to adapt to review needs across multiple document types |
| `temperature` | `0.1–0.3` | Compliance reviews require objective, unbiased validation results. This avoids generating subjective judgment content |
| `AIPROXY_API_ENDPOINT` | Root address of the AI Proxy service, for example http://aiproxy:3000 | This variable is a required environment variable for the App/Admin server. It specifies the access address of the AI Proxy service. Do not append /v1 or /chat/completions paths. Do not use single-model vendor addresses |
| `AIPROXY_API_TOKEN` | Admin token consistent with the AI Proxy server configuration | This variable is a required environment variable for the App/Admin server. It cannot be empty. It is used to complete authentication with the AI Proxy service |

## Three common mistakes
- Issue: Model test returns inconsistent results compared to web debug results. Cause: The `maxContext` parameter is not unified. Web debug and formal access use different context length limits, leading to differences in the range of raw data called.
- Issue: Service startup verification fails or AI Proxy-related functions cannot be called after configuring `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`. Error prompt: Connection timeout. Troubleshooting steps: Verify that the configured AI Proxy root address is accessible. Confirm that the AI Proxy service is running normally. Troubleshooting steps: Confirm that `AIPROXY_API_TOKEN` matches the admin token configured on the AI Proxy server and is not empty.
- Issue: Garbled text appears in model return results. Cause: The non-standard encoding format of raw documents is not adapted, or the `quoteMaxToken` parameter is not correctly limiting the length of quoted content, leading to truncation exceptions.

## How to confirm configurations are complete
- Execute a test call for a single acceptance certificate. Check whether the returned results include preset validation fields.
- View model call logs. Confirm that the actual values of each configuration parameter match the preset configuration.
- Test a multi-source data pulling scenario. Check whether the returned results cover associated content from different data sources.
- Trigger an exception test scenario, such as passing a document without a signature status. Confirm that the model returns corresponding compliance validation prompts.

The values given are common starting points and should be measured against the reader's own samples.
