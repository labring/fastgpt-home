# Customer Technical Support and Pre-Sales Q&A for CDN and Edge Acceleration Configuration: HTTP Interfaces and External Systems

## What data looks like for this category
Common data sources include CDN consoles, DNS resolution records, public network access logs, and node monitoring alerts. Daily produced documents include domain access forms, cache rule configuration tables, refresh and preheating operation records, and fault analysis reports. Data updates occur daily or in real time when configuration changes. Data fields include domain names, cache rule IDs, node IPs, access status codes, cache hit rates, and similar items. Data is stored in a structure aligned only with business scenarios, with no fixed unified statistical standard.

## Constraints on HTTP interfaces and external systems
Data sources rely on pulling via CDN open APIs, so HTTP interfaces must adapt to official CDN authentication rules and parameter formats. Data updates occur daily or in real time when configurations change, so interface polling intervals must match this cadence to avoid outdated data or redundant requests. Daily business documents require interfaces to return structured business data, including core fields such as domain names and cache rules. The public network content distribution feature requires interfaces to adapt to cross-domain access and public network environment stability requirements, and also handle error feedback for abnormal scenarios such as node failures and cache misalignment.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `Authorization` | API authentication token generated in the CDN console | Complies with official authentication requirements for CDN open APIs |
| `variables` | Key-value pairs containing target domain names, cache rule IDs, and alert thresholds | Matches core field requirements for daily business documents |
| `responseData` | Structured data containing access status codes, node IPs, and cache hit status | Aligns with output standards for fault analysis reports |
| Interface polling interval | 300–600 seconds | Matches daily or real-time update frequency of CDN data |
| Authentication method | CDN official signature authentication | Ensures security of interface calls |
| Data time range | Returns only access logs from the last 24 hours | Aligns with daily operation and maintenance query habits |

## Three common mistakes
- An interface authentication failure error with a 401 status code occurs during workflow debugging. The cause is mistakenly using the AI Proxy administrator token as the authentication parameter for the CDN interface.
- No data is returned after calling the interface. The cause is that the correct target domain name or cache rule ID is not configured in `variables`.
- A request timeout error is returned by the interface. The cause is that the polling interval is set too short, exceeding the rate limit threshold of the CDN console API.

## How to confirm configurations are correct
- Call the CDN open API to pull access logs from the last hour, and check that the returned `responseData` contains expected business fields.
- View the FastGPT workflow log to confirm that the `Authorization` authentication parameter is correctly carried and a 200 status code is returned.
- Verify that the domain name configured in `variables` exactly matches the actual connected CDN domain name.
- Simulate a cache rule change, and check whether the interface can synchronously pull the latest rule configuration data.
