# Customer Technical Support and Pre-sales Q&A for IT Helpdesk Ticket Processing: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
Typical entities for this category include enterprise IT helpdesks, desktop support teams, and second-tier technical support groups. Daily generated documents cover service request tickets, incident tickets, processing records, and user satisfaction surveys.
Data sources include ITSM systems, user phone or chat logs, enterprise asset systems, and internal knowledge bases. Update frequency is daily or real-time synchronization.
Individual ticket data contains fields such as ticket ID, user information, problem description, and processing steps. There is no fixed unified long-text structure. Most records are spliced from short paragraphs. Data formats vary across different sources.

## What Constraints These Characteristics Impose on the Knowledge Base Retrieval and Recall Link
Multi-source, heterogeneous data sources require the retrieval link to support different ticket, record, and asset formats. This prevents valid matching content from being lost due to format mismatches.
Real-time or daily update frequency requires recall logic to sync the latest ticket processing records. This ensures retrieval results align with current business status.
The short-paragraph spliced document structure means single long-text matching cannot cover scattered business details. Adjust chunking and recall rules to adapt to short-snippet matching.
The unified service entry attribute leads to wide coverage of retrieval queries. Improve matching accuracy to prevent incorrect ticket assignment or ineffective troubleshooting. Also ensure retrieval results meet SLA requirements.

## How to Set Configurations
These configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Adapt to the short-text matching needs of ticket problems, balance recall coverage and accuracy, and avoid filtering valid business content with high thresholds |
| `limit` | Top 6–10 entries | Cover the multi-step troubleshooting reference needs common in IT helpdesks, avoid excessive redundant results interfering with manual processing |
| `usingReRank` | Enabled | Optimize matching sorting for short-paragraph ticket problems, improve the recall priority of highly relevant knowledge base content |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expand query terms for common abbreviations and industry terms in tickets, improve cross-source matching success rate |
| `collectionIds` | Bind dedicated dataset ID for IT helpdesk tickets | Ensure retrieval only calls the business knowledge base of the corresponding category, avoid interference from irrelevant content |

## Three Common Misconfigurations
- The symptom is empty search test results. The cause is failure to bind `collectionIds` to the dedicated IT helpdesk ticket knowledge base, or setting the `similarity` threshold above 0.85 which filters valid matching content with overly high barriers.
- The symptom is no parsing completion prompt after uploading a PDF, and no search results. The cause is failure to enable document parsing status push, and failure to confirm that the uploaded file is of a supported vectorization type.
- The symptom is the answer not calling knowledge base content. The cause is failure to enable `datasetSearchUsingExtensionQuery`, or setting `limit` too low which results in insufficient recalled entries to cover required business reference content.

## How to Confirm Configurations Are Correct
- Enter the FastGPT knowledge base management page, confirm that `collectionIds` is bound to the dedicated IT helpdesk ticket dataset, and no irrelevant datasets are associated.
- Submit a simulated IT helpdesk ticket query, run a search test, check that the number of returned results matches the `limit` setting, and the content matches the ticket business scenario.
- Upload a test PDF file, wait for parsing to complete, check the interface status prompt, confirm that parsing progress and results are normal.
- Enable answer traceability function, check whether the returned answer content is associated with matching fragments from the IT helpdesk ticket knowledge base, confirm that the correct data source is called.
