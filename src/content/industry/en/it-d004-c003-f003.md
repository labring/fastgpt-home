# Customer Technical Support and Pre-sales Q&A for IT Asset Inventory: Sharing and Embedding

## What data looks like for this category
IT asset inventory data originates from asset management systems, procurement systems, financial fixed asset modules, and terminal management platforms. Daily generated documents include asset ledgers, inventory lists, loan and return forms, and scrap applications. Core fields include asset number, name, specification model, user, storage location, purchase date, and usage status. Common units are sets, pieces, or units. Data update frequency is monthly, quarterly, or annually. A single update covers current period asset change information.

## What constraints do these characteristics impose on the sharing and embedding workflow
IT asset inventory data has dispersed sources and includes sensitive information such as ownership and financial details. The sharing and embedding links must strictly restrict access permissions to prevent unauthorized personnel from obtaining sensitive data. Data update frequency is low but fields are fixed. Shared context caching does not need frequent refreshes. However, access permissions for associated external data sources must align with the configuration of the sharing entry. Since asset verification requires linking to specific users, embedded chat windows must support session isolation via uid returned by external systems or local session identifiers. This prevents mixing of asset information from different users. Additionally, structured content from asset ledgers can be delivered directly via structured display on embedded pages. Markdown export is not required.

## How to configure settings
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| Sharing entry `shareId` | Copy the full sharing link generated by the system; do not manually replace the identifier | Identifies the sharing entry; IT asset inventory business records and data permissions must still be handled by external systems |
| Sharing link validity period | Test starting point: 7 days; adjust based on actual IT asset inventory collaboration cycles and revocation requirements | Verify availability during the valid period and access behavior after expiration; this value is not an official default or industry statistic |
| QPM | Test starting point: 20 requests per user per minute; adjust based on actual load | Restricts access frequency for a single user; requires validation combined with request logs and actual load |
| Identity verification | When identity permission requirements exist, first verify commercial edition capabilities and uid returned by third-party identity services | Holding a sharing link does not equal having business data permissions; third-party identity and data scope must be verified separately |
| Referenced content display | Select display configurations for snippets, full text, or original text based on the sensitivity of IT asset inventory materials | Check displayed content within authorized data ranges; hidden interfaces cannot replace data permission controls |
| Chat record verification | Test example: Prepare 10 IT asset inventory Q&A samples, check in the same browser and another device respectively | Anonymous records rely on browser local identity; retention is not guaranteed across devices or after cache clearance |

## Three common configuration errors
- IT asset inventory-related sharing links fail to open. First verify the full system-generated link and its validity period, then check browser request status; do not manually replace `shareId`.
- The visible scope of IT asset inventory data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately; the sharing entry identifier itself does not provide business authorization.
- The same IT asset inventory Q&A is not visible on another device. For anonymous scenarios, first check device, browser, and local identity status; record retention is not guaranteed across devices or after cache clearance, so this phenomenon alone cannot be used to judge service anomalies.

## How to confirm configuration is complete
- Open the embedded iframe page, check that there are no Markdown export buttons in the top or side toolbar.
- Use two different external system accounts (commercial edition scenario) or the same device with different browsers (anonymous scenario) to access the embedded page, initiate asset-related inquiries respectively, and confirm that neither party can see the other's chat records.
- View the network request logs of the embedded page, confirm that the `shareId` parameter is correctly passed in requests, and returned data fields match the core configuration of the asset ledger.
- Refresh the embedded page, confirm that the rendering configuration of the external embedded page takes effect, and there are no cached old settings.

The values provided here are common starting points and should be evaluated against the reader's own samples.
