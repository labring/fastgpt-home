# Customer Technical Support and Pre-sales Q&A for Special Event Operations: Reranking and Hybrid Retrieval

## What this category of data looks like
Daily documents for special event operations include event plans, resource slot schedules, event page copy, and post-event review reports. Data sources include content libraries, event backends, traffic data, and user feedback. Updates follow a weekly cycle, with temporary additional updates around holidays. Most documents include fields such as event cycle, resource slot location, copy content, and traffic metrics. Some documents include timestamps and event ID identifiers. This category of data ties to specific event cycles and exclusive page resource slots, with no long-term generic non-event content.

## Constraints on reranking and hybrid retrieval
Systems tie retrieval to specific event cycles, so retrieval processes limit content to the event time window to avoid recalling expired past event documents. Document types vary widely, ranging from long-text event plans to short-text page copy. Hybrid retrieval workflows balance relevance weights for different text lengths. High-frequency data updates require systems to adapt to weekly and temporary updates to ensure real-time retrieval results. Resource slot schedule documents include strongly correlated fields such as location and time. Reranking workflows prioritize matching the spatial and temporal attributes of the event scenario to improve retrieval accuracy.

## Configuration settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Recall data source scope | Content library, event backend export files, user feedback summary table | Matches the core data sources for this category |
| Recall content time window | 7 days prior to the end of the corresponding event | Adapts to the business characteristic of clearly defined event cycles, filters expired content |
| Reranking model invocation threshold | Similarity score ≥ 0.6 | Filters low-relevance event copy and schedule content, focuses on valid information |
| Single recall result limit | Top 15 entries | Balances retrieval efficiency and content richness, adapts to the concentrated volume of event-related documents |
| Retrieval content filtering rules | Exclude expired post-event review reports and past event documents | Matches data update rhythm and event cycle attributes |

## Three common errors
- Online recall tests do not display reranking results. The cause is failing to enable the reranking switch in the knowledge base retrieval configuration, or failing to bind the corresponding reranking model.
- The reranking model returns an Invalid URL (POST /v1/rerank) error. The cause is an incorrectly configured reranking model deployment address, or the interface forwarding path not matching the format required by FastGPT.
- Retrieval results include documents outside the active event cycle. The cause is not setting a time window filtering rule, resulting in recall of expired past event content.

## How to confirm the configuration is correct
- Enter the knowledge base retrieval test page of FastGPT v4.17.0, input pre-sales consultation-related questions, and check if the returned results include the reranking model’s score annotations.
- Enter the model management page, check the connection status of the reranking model, confirm that the interface shows the model is online normally with no error prompts.
- Manually input exclusive keywords within the active event cycle, verify that the retrieval results only include event documents from the corresponding time period.
- Trigger a complete retrieval process, check if the number of returned results matches the configured single recall result limit.
