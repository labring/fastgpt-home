# Customer Technical Support and Pre-sales Q&A for Personal Information Protection Compliance: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data for this category comes from business systems, App permission lists, privacy policies, and user request records. Update frequency is quarterly or with each product version change.
Daily supporting documents include personal information lists, processing rules, impact assessment reports, and user authorization texts. Each document field corresponds to dimensions such as natural person information identification, processing scenarios, legal basis, and authorization scope. There is no unified fixed unit. Field content must align with the business scenario.

## Constraints for Multi-turn Dialogue and Prompt Engineering
Data for this category has scattered sources and update schedules that adjust with product changes. Multi-turn dialogue must use `chatId` to maintain consistent session context, preventing cross-session mixing of compliant data.
Daily document fields cover multiple dimensions including natural person identification and processing scenarios. Prompts must strictly limit calls to specified fields to avoid outputting unauthorized personal information. Single processing requires associating multiple document contents, so single-round context loading volume must be limited to avoid exceeding the dialogue node's input limit. Multi-turn dialogue must also support passing historical questions and scenario fields to meet the need for step-by-step breakdown of compliance consultations.

## Configuration Settings
This configuration is adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | 800–1200 characters | Adapts to the average content of documents such as personal information lists and processing rules loaded in a single round for this category, avoiding exceeding the dialogue node's input limit |
| `messages` Array Limit | First 10 historical sessions | Limits multi-turn dialogue context count to prevent errors from exceeding context limits, while covering recent compliance-related consultation scenarios |
| `variables` Bound Field Scope | Only bind personal information identification fields and legal basis fields | Restricts the data range prompts can call, ensuring only compliance-related document content is used, preventing leakage of irrelevant information |
| Session Timeout | 600 seconds | Matches the average response time of compliance teams handling complex scenarios, avoiding context loss from mid-session disconnection |
| History Display Rule | Hide thought process fields | Meets requirements for not displaying internal thought processes in conversation records, while ensuring compliance consultation content only retains user and reply text |

## Three Common Misconfigurations
- Symptom: The dialogue node returns an input limit exceeded error, or has no response. Cause: No reasonable maximum context length is set, and loaded documents such as personal information lists and processing rules exceed the dialogue node's input limit.
- Symptom: Multi-turn dialogue cannot continue the previous compliance consultation scenario, or does not follow up on replies using historical questions. Cause: `chatId` is not used to bind session context, or historical questions and scenario fields in `variables` are not passed correctly.
- Symptom: The dialogue request interface returns results without a cite reference ID field. Cause: Compliance document source association configuration is not enabled, or the prompt does not require binding the corresponding document's reference identifier.

## How to Verify Proper Configuration
- Upload a single personal information list document, initiate a compliance consultation test, and check whether an input limit exceeded error triggers after the conversation context loads.
- Initiate two or more rounds of compliance consultations, verify that conversation history retains session context, and that the previous round's questions are correctly passed for subsequent replies.
- Call the dialogue interface, confirm that returned results include the source-associated reference identifier field.
- View conversation history records after the agent runs, ensure the large model's thought process does not appear in the user-visible conversation list.
