# Customer Technical Support and Pre-sales Q&A for Personal Information Protection Compliance: Knowledge Base Retrieval and Recall

## What Data Looks Like for This Category
This category of data mainly comes from daily outputs of privacy compliance teams, security consulting and legal departments, and collection from business systems. Daily documents include personal information inventories, processing rules, impact assessment reports, user authorization texts, and similar materials. It covers multiple formats such as structured inventories, long-text reports, and clause-based authorization. Data sources include business systems, App permission lists, privacy policies, and user request records. The update frequency is quarterly or each time a product version is updated.

## What Constraints These Characteristics Impose on the Knowledge Base Retrieval and Recall Link
Since document formats vary and contain sensitive information that can identify natural persons, the retrieval and recall link must strictly limit scope to avoid irrelevant content being added to the context. Structured personal information inventories differ greatly from unstructured compliance reports and authorization texts. Multiple matching logic must be adapted to ensure recall accuracy. The low-frequency but batch update rhythm requires the knowledge base synchronization mechanism to support incremental updates for batch documents, reducing resource consumption from repeated verification. In technical support and pre-sales Q&A scenarios, user questions are mostly colloquial. These questions must be expanded into professional compliance keywords to accurately locate corresponding documents.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the sensitivity level of personal information-related documents, filters low-match irrelevant content to avoid risks of sensitive information leakage |
| `limit` | Top 10 entries | Controls the number of single recall results, prevents excessive compliance documents from causing context overflow, and adapts to the short context requirements of technical support scenarios |
| `searchMode` | Hybrid retrieval | Adapts to structured personal information inventories and unstructured compliance reports and authorization texts, balancing exact matching and semantic matching |
| `usingReRank` | Enabled | Re-ranks recall results, prioritizes core keywords in compliance scenarios, and improves matching accuracy for user questions |
| `datasetSearchUsingExtensionQuery` | Enabled | Expands colloquial technical support questions from users into professional compliance keywords, covering more retrieval scenarios for compliance documents |
| `collectionIds` | Specified by compliance knowledge base groups | Limits the retrieval scope, only searches within the dedicated dataset for personal information protection compliance, avoiding confusion with other business knowledge bases |

## Three Common Mistakes
- Phenomenon: When importing compliance documents such as personal information inventories and impact assessment reports, the page continuously refreshes and cannot select the import page count. Cause: Most compliance documents are long-text or structured tables. The system triggers additional verification logic during format parsing, causing the page state to freeze.
- Phenomenon: Semantic retrieval returns no results in technical support scenarios, only full-text retrieval can hit target content. Cause: The `datasetSearchUsingExtensionQuery` configuration is not enabled. Colloquial user questions cannot be expanded into professional keywords for compliance documents, leading to matching failure.
- Phenomenon: After uploading compliance documents in an offline environment, the task remains in a loading state, and returns to normal only after connecting to the internet. Cause: The knowledge base upload function of FastGPT v4.17.0 relies on loading some public resources. Initialization verification cannot be completed offline.

## How to Confirm the Configuration Is Successfully Applied
- Input a compliance-related technical support question, and check whether the recall results only include dedicated documents for personal information protection compliance.
- Adjust the `similarity` parameter, verify whether the match degree of the recall results meets the business requirements for sensitive information retrieval.
- After enabling `usingReRank`, check whether the recall results are sorted to prioritize core keywords in compliance scenarios.
- View the knowledge base retrieval logs, confirm that content is only recalled from the specified compliance dataset `collectionIds`.

The values provided are common starting points and should be measured against the reader's own samples.
