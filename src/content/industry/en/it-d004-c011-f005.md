# Customer Technical Support and Pre-sales Q&A for Cloud Host Provisioning and Resource Activation: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
This category's data primarily comes from cloud management platforms, order systems, IAM permission systems, and billing systems, with updates synced in real time per order. Daily associated documents include resource activation tickets, instance configuration sheets, account permission tickets, and delivery confirmation sheets. Core fields include instance specification, deployment region, image type, billing mode, and permission scope. Field units are mostly cores, GB, hours, and similar units.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering step
Scattered data sources and real-time updates for this category require multi-turn dialogue contexts to link the `chatId` and `messages` parameters, preventing cross-session data contamination. Structural differences across multiple associated documents require prompts to extract fields grouped by ticket type, such as resource activation tickets and instance configuration sheets, to avoid cross-ticket information confusion. Varied field units and types require prompts to clearly define formats for required fields like instance specification and deployment region, reducing error rates during specification verification and permission configuration. Real-time sync updates require the dialogue flow to pull latest data from order systems and IAM systems in real time, avoiding information lag during delivery confirmation.

## Three common configuration errors
- The first issue: A workflow configured with a text content extraction node and set chat record count exhibits abnormal extracted dialogue content during execution. The root cause is failure to clearly specify dialogue content extraction rules in the prompt, causing the node to return fields in an unexpected format.
- The second issue: The dialogue flow remains unresponsive for a long time after triggering, with the knowledge base search step stuck. The root cause is failure to configure a reasonable context cache duration, causing the system to repeatedly pull expired order and permission data.
- The third issue: An empty field error occurs during the instance specification verification step in multi-turn dialogue. The root cause is failure to clearly specify the required field extraction logic in the prompt, leading to missing key configuration information.

## How to confirm correct configuration
- Launch a simulated pre-sales consultation, check that the dialogue flow extracts fields from resource activation tickets and instance configuration sheets categorized by ticket type.
- Check session logs to confirm whether the `chatId` and `messages` parameters are correctly associated with interaction content for the current session.
- Trigger a specification verification step, check that the specified required fields are returned in accordance with prompt requirements.
- Simulate an order update operation, confirm that the dialogue flow pulls the latest permission and billing data in real time.
