# Customer Technical Support and Pre-sales Q&A for Cloud Host Provisioning and Resource Activation: Reranking and Hybrid Retrieval

## What the Data for This Category Looks Like
The data for this category primarily comes from cloud management platforms, order systems, IAM permission systems, and billing systems. The system triggers updates in real time per order or by delivery milestones. Daily business documents include resource activation forms, instance configuration sheets, account permission forms, and delivery confirmation forms. Core fields include instance specifications (vCPU, memory), architecture type, security group configurations, customer account identifiers, image IDs, and billing rules. There is no uniform fixed length for individual data entries. Lengths change dynamically based on order complexity.

## What Constraints Do These Characteristics Impose on Reranking and Hybrid Retrieval?
The real-time requirements of this category mean that hybrid retrieval must prioritize matching real-time order data. Delayed archived documents only serve as auxiliary recall content. Data formats from multiple system sources differ. The reranking workflow requires unified field mapping rules to avoid matching errors caused by cross-system field ambiguity. A single order links to a limited number of documents, but fields have strong correlations. Hybrid retrieval must first recall instance configuration and permission form data strongly linked to the current activation form. Enumeration fields such as architecture type and security group configurations require exact matching. The reranking model must set exclusive weighting rules for these fields.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Hybrid retrieval recall limit | Top 20 entries | Documents associated with a single order in this category typically do not exceed 15 entries. Recalling the top 20 entries covers all associated data while avoiding redundancy |
| Reranking model input length | 800–1200 characters | Matches the average length of core documents for this category, preventing truncation of key field information |
| Similarity threshold | 0.72–0.85 | Calibrated through actual testing, balancing the need for exact matching of architecture and specification fields with the recall of associated documents |
| Reranking return count | Top 5 entries | Pre-sales Q&A for this category typically only requires three types of information: core configuration, permissions, and delivery details. The top 5 entries cover core requirements |
| Real-time data sync interval | 600 seconds | Matches the real-time requirements of order delivery for this category, preventing configuration errors caused by outdated data |
| Field weighting configuration | Set architecture type and instance specification weights to 1.5 | Core decision-making for this category relies on these two field types, raising their priority in retrieval and reranking |

## Three Common Misconfigurations
- Symptom: Search results include image configurations with mismatched architecture types. Cause: No exclusive weighting is set for the architecture type field, or the similarity threshold is set too low, leading to recall of low-relevance documents
- Symptom: No results are returned from the reranking stage after configuration is complete. Cause: Real-time data sync interval is set too long, so the latest configuration for the current order has not been synced to the retrieval index pool
- Symptom: Returned results are redundant and have a low proportion of core fields when using hybrid + reranking mode. Cause: Recall limit is set too high, and non-core fields are not assigned lower weights

## How to Confirm Configuration Is Complete
- A real resource activation form and instance configuration sheet may be uploaded, retrieval executed, and returned results checked to confirm whether they include the core fields of the current order
- The similarity threshold may be adjusted to 0.75, and reranked results checked to confirm whether sorting prioritizes core fields such as architecture type and instance specifications
- Retrieval index sync logs may be viewed to confirm that order data from the last 600 seconds has completed index updates
- In the scenario configuration panel of FastGPT v4.17.0, field weighting rules may be confirmed to have been correctly applied
