# Customer Technical Support and Pre-Sales Q&A for Code Review and Merge Management: Sharing and Embedding

## What the data for this category looks like
The data for this category primarily comes from Git repositories, CI pipelines, static scanning reports, and defect databases. The system generates daily documents including merge requests, code review comments, commit records, and branch strategy descriptions. Data updates occur daily or in real time with code commits. Fields include changed file lists, reviewer comments, conflict markers, build statuses, defect linked items, and more. The system only records core information about code changes and review processes, with no unnecessary extra statistical fields. This category includes manual review comments and business semantic judgment fields, which is the core difference from static code scanning tools.

## What constraints these characteristics impose on sharing and embedding
Because this category of data includes undisclosed code changes, review comments, and other sensitive content, strict access permission restrictions are required during sharing and embedding to avoid leaking internal business logic. The FastGPT sharing entry only provides content loading capabilities. The associated external business system and sharing configuration jointly control access permissions. The real-time data update feature requires the associated external business system to support quickly pulling the latest merge request status and review records to assist with change impact assessment and conflict resolution. The FastGPT sharing entry is only responsible for loading compliant content. The fixed field structure of structured documents such as merge requests and review comments means that the display content range configuration for the FastGPT sharing entry must clearly specify the loaded field range, to avoid redundant information interfering with users. At the same time, the data source relies on Git repository access permissions. Associated external business system calls must be bound to valid repository credentials. The FastGPT sharing entry only loads authorized compliant content, to prevent unauthorized users from accessing sensitive code content and avoid consequences such as defects entering the main branch or build failures.

## Three Common Misconfigurations
- Sharing entries related to code review and merge management fail to open. First verify the full system-generated link and its validity period, then check browser request statuses; do not replace `shareId` yourself.
- The visible scope of code review and merge management data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately; the sharing entry identifier itself does not provide business authorization.
- The same code review and merge management Q&A cannot be viewed on another device. In anonymous scenarios, first check device, browser, and local identity status; retention cannot be guaranteed across devices or after clearing cache, do not use this phenomenon alone to judge service abnormalities.

## How to Confirm the Configuration is Complete
- Access the embedded page via the generated sharing link, check that the corresponding business content loads normally.
- Update the target code review or merge request content via the associated external business system, refresh the embedded page to confirm that the content loaded by the FastGPT embedded page updates synchronously.
- Attempt to open the embedded page using unauthorized access methods, confirm that sensitive business content cannot be accessed.
- Check the browser console to confirm there are no error messages about invalid sharing links or insufficient permissions.
