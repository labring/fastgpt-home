# Customer Technical Support and Pre-sales Q&A for Enterprise Software License Management: Knowledge Base Retrieval and Recall

## What the data for this category looks like
This category of data is generated by software asset management systems, procurement systems, terminal scan results, and vendor authorization documents. Daily documents include license ledgers, software usage lists, procurement contracts, and compliance audit reports.
Data updates occur monthly or quarterly. Fields include software name, authorized quantity, authorization type, number of installed terminals, renewal expiration date, and more. Common units are units, sets, and days.
The corresponding relationship between software authorizations and actual installed usage must be strictly matched. The core focus of this data is software authorization compliance.

## Constraints Imposed on Knowledge Base Retrieval and Recall
Data sources are scattered, and update cycles are long. When performing retrieval, prioritize matching the latest monthly or quarterly updated ledger data. This avoids invoking expired information that could create compliance risks.
Fields cover multi-dimensional authorization and installation correspondence relationships. Single-keyword recall often leads to matching deviations. Multiple fields such as software name, authorization number, and terminal information must be associated at the same time.
Multiple document types are supported. Cross-document associated retrieval must be enabled. For example, combine authorization clauses in procurement contracts with actual usage data in ledgers.
Non-compliant data recall must be avoided. This ensures retrieval results meet audit requirements.

## Configuration Settings
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Match precise fields in license ledgers, prevent low-similarity irrelevant authorization information from being included |
| `limit` | `Top 6–10 entries` | Cover multiple software authorizations that may be involved in a single query, while controlling context length |
| `searchMode` | `keyword + semantic` | Balance keyword matching for authorization numbers and semantic matching for compliance needs of query scenarios |
| `usingReRank` | `Enabled` | Re-rank recall results by compliance relevance, prioritize displaying high-priority authorization and usage data |
| `datasetSearchUsingExtensionQuery` | `Disabled` | Prevent extended queries from introducing irrelevant IT asset data outside this category |
| `collectionIds` | `Specify the dedicated knowledge base ID for license management` | Limit retrieval scope, only invoke compliance documents such as ledgers and contracts for this category |

This configuration is based on FastGPT v4.17.0.

## Three Common Configuration Errors
- Phenomenon: An error occurs during knowledge base retrieval reading: "No available channel for model gpt-4o-mini under current group default". Cause: The dedicated license management knowledge base has not been bound to the channel group for the corresponding model, or the group configuration is not associated with the correct API key.
- Phenomenon: Retrieval results include expired license data from prior to the current quarter. Cause: Update time-based filtering for recall results has not been configured, or the data source has not synchronized the latest monthly or quarterly updated data.
- Phenomenon: Irrelevant device data from IT asset inventory appears in retrieval results. Cause: `collectionIds` has not been restricted to the dedicated knowledge base ID, leading to retrieval of non-authorization management data across categories.

## How to Verify Correct Configuration
- Submit a query containing "2024 Q3 license ledger". Confirm that retrieval results only include documents from this category, with no other IT asset-related data.
- Adjust the `similarity` parameter. Verify that the matching degree of retrieval results falls within the preset range, with no low-relevance redundant content.
- Check the `limit` parameter. Confirm that the number of single retrieval results matches the preset value, to avoid exceeding model context limits.
- Simulate a renewal expiration reminder query. Confirm that the recalled authorization expiration date data matches the latest ledger.

The values provided are common starting points and should be evaluated against the reader's own samples.
