# Customer Technical Support and Pre-sales Q&A for Enterprise Software License Management: Reranking and Hybrid Retrieval

## What the Data for This Category Looks Like
Data for this category primarily comes from software asset management systems, procurement systems, terminal scanning tools, and vendor authorization documents. Daily maintained documents include license ledgers, software usage lists, procurement contracts, and compliance audit reports. Data update frequency is monthly or quarterly. Fields include authorization number, authorized quantity, bound terminal count, effective date, expiration date, software version number, and others. Units include units, pieces, days, and others. There is some variation in field alignment across documents from different sources.

## Constraints on Reranking and Hybrid Retrieval
Data sources for this category are scattered, and format differences are significant. Aligning fields across ledgers and lists exported from different systems is difficult. This requires hybrid retrieval to support unified mapping of multi-source fields. Data update frequency is low. Retrieval must prioritize matching the latest authorization data from the past month or quarter to avoid using expired information. Documents include structured ledgers and unstructured contracts. Hybrid retrieval must balance keyword matching and semantic understanding. The reranking link must prioritize associating core compliance fields such as authorized quantity and expiration date. This ensures retrieval results match business requirements for technical support and pre-sales Q&A.

| Enable Reranking | Yes | Address field differences across multi-source data, optimize display priority of core compliance fields via reranking |
| Reranking Call Timeout Threshold | 300 seconds | Adapt to unstructured content parsing duration of vendor authorization documents, avoid retrieval process interruption |

## Three Common Misconfigurations
- Phenomenon: Reranking service calls return a 503 status code or an empty result list. Cause: Custom channel parameters for the reranking service are not configured correctly, or the channel interface response times out.
- Phenomenon: A large number of expired license data appears in hybrid retrieval results. Cause: No update time filtering rule is set, or the similarity threshold is set too low, resulting in recall of non-recent data.
- Phenomenon: Retrieval results do not filter invalid over-installation identification entries. Cause: No field filtering for terminal installation status is added before hybrid retrieval, or the search mode does not associate the installation status field of the software usage list.

## How to Verify Successful Configuration
- Import a single license ledger and software usage list, perform retrieval, and check the field completeness and sorting priority of returned results.
- Trigger the reranking service, check the calling parameters of the reranking model and the sorting order of returned results in the system log, confirm that core compliance fields are displayed first.
- Adjust the similarity threshold, compare the number of recall results under different thresholds, confirm that the threshold meets the precision requirements of the business scenario.
- Simulate the retrieval scenario for over-installation identification, verify whether results automatically filter terminal installation records that do not have authorization.

The values given are common starting points and should be measured against the reader's own samples.
