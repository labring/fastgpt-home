# Customer Technical Support and Pre-Sales Q&A for Supply Chain Security and Open Source Dependency Governance: Sharing and Embedding

## What the data for this category looks like
The core data for this category typically includes four types of core documents: SBOM lists, dependency risk reports, license lists, and repair tickets. Data sources include public package managers, code repositories, public vulnerability databases, and license databases, with an update frequency of daily or upon each software version release. Most documents use structured fields, including core content such as dependency package name, version number, license type, vulnerability CVE number, and risk level, with no additional custom statistical indicators.

## What constraints these characteristics impose on the "Sharing and Embedding" workflow
The core data for this category is highly real-time structured risk and dependency information. When sharing and embedding, both data accuracy and access permissions must be balanced. Since the data updates daily or per version, the associated external data sources must synchronize the latest content on a regular basis. Embedded pages can configure cache duration via the external embedding system to adapt to the update rhythm. Additionally, the documents include multi-dimensional security-related fields, so the embedding configuration must clearly define the display scope to prevent omission of critical governance information. Furthermore, the data sources involve multiple external systems, so the embedded page must support cross-source data loading, with data provided by the associated external supply chain data system. FastGPT is only responsible for sharing entry distribution.

## Three common errors
- Failure to open supply chain security and open source dependency governance related sharing entries. First verify the full system-generated link and its validity period, then cross-check browser request status; do not manually replace `shareId`.
- Visibility of supply chain security and open source dependency governance data does not match expectations. Cross-check third-party identity verification results, workflow request parameters, and external system data permissions respectively; the sharing entry identifier itself does not provide business authorization.
- The same supply chain security and open source dependency governance Q&A cannot be viewed on another device. For anonymous scenarios, first verify device, browser, and local identity status; retention is not guaranteed across devices or after cache clearance, so do not judge service anomalies solely based on this phenomenon.

## How to confirm the configuration is complete
- Directly access the generated unlogged share link, confirm that supply chain related documents and data load normally.
- Access the associated external supply chain data system, confirm that it returns the corresponding risk reports and license information (requires the external system to support corresponding access permissions)
- Open the browser console, check for no cross-domain request failures or error messages related to the share link
- Wait for the external data source update cycle, then refresh the embedded page, confirm that the data has been updated to the latest version
