# Customer Technical Support and Pre-sales Q&A for Supply Chain Security and Open Source Dependency Governance: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
This category's data primarily comes from package managers, code repositories, public vulnerability databases, and license databases. Updates occur daily or upon each software version release. Daily generated documents include SBOM manifests, dependency risk reports, license compliance lists, and vulnerability repair tickets. Data fields include dependency package names, version numbers, CVE IDs, license types, risk impact levels, and more. All data centers around the security and compliance attributes of third-party components.

## What constraints these characteristics impose on the "multi-turn dialogue and prompt engineering" link
High data update frequency requires limiting the context scope of multi-turn dialogue to sync the latest dependency risk and license information, avoiding use of expired data. Fixed document structure requires prompts to match the standard fields of SBOM manifests and risk reports, ensuring that key information such as dependency package names and version numbers can be accurately identified during dialogue. Error consequences involve compliance and launch risks, so multi-turn dialogue must strengthen verification logic for vulnerability matching and license compliance to avoid misjudgments. It is also necessary to clearly distinguish self-developed code from third-party dependencies to avoid confusing security boundaries.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chatId` | Enable persistent storage | Adapts to the session storage logic of FastGPT v4.17.0, preventing loss of conversation records after version upgrades or page refreshes |
| `messages` | Limit context rounds to the first 5 rounds | Adapts to the single-batch processing scale of category data, avoiding redundant data occupying computing resources |
| `variables` | Bind dependency package names, CVE IDs, license types | Ensure that fields passed during multi-turn dialogue align with category data standards, improving matching accuracy |
| Maximum context length | 6000–10000 characters | Matches the conventional data volume of SBOM manifests and risk reports, avoiding exceeding platform processing limits |
| Single recall upper limit | Top 8 entries | Matches the conventional return entries of vulnerability and license databases, balancing accuracy and response speed |

## Three common mistakes
- After upgrading the version and refreshing the conversation page, conversation records show as empty, and the interface prompts for a new conversation. The cause is that persistent storage for `chatId` is not enabled, so the session identifier is not retained across version updates.
- The AI cannot read the document content bound by the system prompt, and prompts that no file has been uploaded. The cause is that `variables` are not correctly bound to category-specific SBOM or risk report fields, causing the prompt to fail to match the actual data structure.
- Real-time knowledge base entries cannot be called during multi-turn dialogue. The cause is that the dynamic context update logic for `messages` is not configured, and real-time selected knowledge base content is not synchronized to the dialogue workflow.

## How to confirm configurations are correct
- Perform a version upgrade operation, refresh the conversation page, and check whether the session identifier is retained, confirming that original conversation records are not lost.
- Enter a query related to dependency package names, check whether the system can normally read the bound document content, with no prompts about unuploaded files.
- Launch a multi-turn dependency risk query, check whether the conversation context includes key information from previous rounds, ensuring dialogue continuity.
- Launch a real-time knowledge base selection operation, check whether the dialogue workflow can synchronize and call the selected entries to complete dependency risk matching.
