# Customer Technical Support and Pre-sales Q&A for IT Budget and Project Portfolio Management: Multi-turn Dialogue and Prompt Engineering

## What data looks like for this category
The data for this category typically comes from financial systems, project management systems, contract ledgers, and business department requirements. Daily processed documents include annual budget sheets, project proposal documents, project portfolio dashboards, and investment review reports. Document fields include project ID, budget amount, priority marker, revenue calculation value, and similar items. Update frequencies are mostly monthly, quarterly, or annually. Associated entities include CIO offices, PMO teams, and financial business partners. The core focus is the full lifecycle flow of projects and budgets.

## What constraints do these characteristics impose on multi-turn dialogue and prompt engineering
The dispersed, multi-source nature of data requires multi-turn dialogue to integrate field information from different systems. This prevents deviations caused by relying solely on a single data source. The fixed document structure and long update cycle mean prompts must clearly specify fixed field extraction rules for documents such as budget sheets and project proposals. Multi-turn dialogue must retain historical interaction context to support coherent business requirements like budget priority ranking and project revenue review. Additionally, since the decision consequences linked to data are clear, prompts must include basic verification logic to prevent budget misalignment issues.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Dialogue context window | Retain the first 20 rounds of dialogue content | Adapt to coherent discussion needs of project budget-related business, avoid losing historical priority judgment basis |
| Prompt variable binding | Bind project ID and budget cycle parameters in `variables` | Extract fixed fields from financial and project management systems, reduce manual input errors |
| Role preset | Set as "IT Budget and Project Portfolio Management Consultant" | Clarify the business scenario boundary of the dialogue, align with the consulting needs of target users |
| Maximum context length | 8000–12000 characters | Match the conventional content length of documents such as annual budget sheets and project portfolio dashboards |
| Message delivery rules | Pass historical interactions via the `messages` field | Ensure context coherence of multi-turn dialogue, comply with the progressive questioning logic of pre-sales Q&A |
| Dialogue timeout | 600 seconds | Adapt to the conventional interaction duration of pre-sales Q&A, avoid session interruption mid-process |

This configuration is based on FastGPT v4.17.0.

## Three common misconfigurations
- Phenomenon: When uploading documents associated with budget data, the interface displays a 503 error, but backend logs show the file was uploaded successfully. Cause: The `chatId` parameter was not bound correctly, causing the session context to fail to match the permission verification logic for document uploads.
- Phenomenon: When configuring multi-turn dialogue, the historical interaction `messages` field is not passed, causing the AI to fail to continue the previous round's budget priority discussion and only generate content based on a single query. Cause: The context dependency of multi-turn dialogue was ignored, and historical message delivery configuration was not enabled.
- Phenomenon: When configuring an AI dialogue module in a workflow, the business scope of the prompt was not clearly specified, causing the AI's returned content to deviate from the budget and project management scope. Cause: The role preset was not bound to the category's business attributes, and only a generic customer service role template was used.

## How to confirm the configuration is correct
- Initiate a test query that includes historical context to verify whether the dialogue can continue the previous round's budget priority discussion content.
- Upload documents of the corresponding category, such as annual budget sheets, to check whether Q&A based on document content can be triggered normally and no interface errors occur.
- Review the variable binding in the configuration items to confirm that business fields such as project ID and budget cycle in `variables` have been associated.
- Initiate a test interaction lasting more than 300 seconds to verify that the dialogue session is not interrupted due to timeout.
