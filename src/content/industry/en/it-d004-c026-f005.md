# Client Technical Support and Pre-sales Q&A for Level Content Creation: Multi-turn Dialogue and Prompts

## What Data for This Category Looks Like
This category's data primarily comes from level editors, art resource libraries, player test data, and defect tracking systems. Daily produced documents include level design drafts, resource requirement lists, test feedback sheets, and version submission records. Core fields cover map coordinates, resource IDs, test feedback entries, and version numbers. Data updates follow a weekly or per-version iteration cycle. Core work focuses on level path design, resource placement, and playability tuning. Operational errors can cause players to get stuck on levels, reduced content quality, or delayed launches.

## What Constraints Do These Characteristics Impose on Multi-turn Dialogue and Prompts
Data for this category is scattered across multiple independent systems. Multi-turn dialogue must bind conversation context via `chatId` to consistently track historical debugging feedback for a single level. Daily documents include structured fields such as coordinates and resource IDs. Prompts must be configured to reference these fields to ensure dialogue content accurately corresponds to design and test information for a specific level. The weekly or per-version update cycle requires dialogue to support filtering historical data by version to avoid cross-version confusion. Core work revolves around specific maps and tasks. Prompts must bind resource parameters for a specific level to prevent debugging deviations caused by generalized calls.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique identifier of the current level | Associate historical debugging records for a single level in this category, avoid cross-level session confusion, and adapt to FastGPT v4.17.0 session binding logic |
| `variables` | Reference structured fields from level design drafts and resource requirement lists | Accurately call document data exclusive to this category, matching the field characteristics of its core work |
| `messages` | Retain the first 20 rounds of conversation context | Balance context completeness and call costs, adapting to the weekly update debugging cycle |
| Maximum context length | 8000–12000 characters | Cover complete debugging dialogue for a single version level, prevent truncation of critical test feedback |
| Session timeout duration | 600 seconds | Adapt to long-duration interactive scenarios for playability tuning, avoid mid-interaction dialogue interruptions |
| Variable reference scope | Limit to the current level set | Prevent cross-level resource data from being included, matching the independent development business model of this category |

## Three Common Misconfiguration Issues
- Phenomenon: When configuring variable references, no temperature setting entry is found, and large model generation parameters cannot be adjusted. Cause: The advanced parameter configuration entry was not enabled on the variable binding page, and the parameter setting module corresponding to `variables` was not associated.
- Phenomenon: Dialogue call duration exceeds 600 seconds, but the backend shows only one call group. Cause: The context length of `messages` was not limited, redundant historical dialogue caused excessive processing time for the large model, and the configuration did not adapt to the weekly update debugging cycle of this category.
- Phenomenon: After adding a database connection plugin, calls throw errors, and level resource library data cannot be read. Cause: The database query scope was not limited to the current level set, leading to cross-database permission conflicts or incorrect data matching.

## How to Confirm Configuration Is Complete
- A single-turn dialogue is initiated to verify that level fields referenced by `variables` display correctly in large model replies.
- Multi-turn dialogue is enabled, and checks are run to confirm whether `chatId` is automatically bound with the session and whether historical debugging records are displayed consistently.
- Session timeout scenarios are tested to confirm that a reasonable interrupt prompt triggers after the interaction duration exceeds the preset threshold, with the threshold calibrated to the debugging interaction rhythm of this category.
- The knowledge base search function is checked to confirm that only document data within the current level set can be retrieved.
