# Customer Technical Support and Pre-sales Q&A for Content Review Rule Operations: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Daily documents for content review rule operations include review rules, disposal guidelines, appeal records, and quality inspection reports. Data comes from content review backends, user reports, regulatory policies, and sample libraries. Documents include fields such as rule number, applicable scenario, disposal threshold, and appeal process. Updates happen daily, or trigger when regulatory policies change. Fast retrieval by rule type and scenario keywords must be supported.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
High data update frequency and policy-triggered changes require the retrieval pipeline to support near-real-time knowledge base synchronization. This prevents use of expired rules. Documents include clear rule number and scenario fields. Multi-dimensional precise matching must be supported, combining semantic and keyword retrieval. Errors in review scenarios carry direct compliance risks. Recall result matching accuracy must stay at a high level. This avoids incorrectly recalling irrelevant rules or missing key clauses. Data covers multiple review scenarios. Retrieval scope must be limited to exclusive datasets to prevent cross-business data from interfering with results.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | Review rules require high matching accuracy to avoid misjudging compliance or violation scenarios |
| `limit` | `Top 8–12 entries` | Covers common review scenarios while controlling context length to avoid redundancy |
| `searchMode` | `Semantic matching + keyword hybrid` | Adapts to the structure of review rules that have both semantic scenarios and clear keywords |
| `usingReRank` | `Enabled` | Improves recall accuracy for complex rule combinations and reduces false recall rates |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Optimizes matching accuracy between user questions and review rule terminology |
| `collectionIds` | `Specify exclusive dataset ID for review rules` | Isolates business data to avoid interference from irrelevant content such as appeal records and quality inspection reports |

## Three common errors
- Retrieval works during debug preview, but knowledge base search cannot be triggered after embedding in a self-owned page. Returns empty results or unexpected content. Troubleshooting step: Confirm the application API request uses the application's exclusive API Key for authentication. Do not use the AI Proxy administrator Token as the request authentication parameter.
- Imported Markdown-format review rule documents cannot be retrieved, or retrieval results do not match rule content. This occurs because rule numbers and applicable scenarios from the documents have not been extracted as retrieval fields. Keyword mapping for document chunks has not been configured.
- The number of retrieval results does not match the configured `limit`. Results may exceed or fall short of the preset quantity. This occurs because `collectionIds` have not been correctly specified. The retrieval scope covers multiple datasets, leading to unexpected result counts.

## How to confirm proper configuration
- Check the FastGPT v4.17.0 server environment variables. Confirm `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service; do not add `/v1` or other path suffixes) and a non-empty `AIPROXY_API_TOKEN` (administrator Token consistent with the AI Proxy server configuration) are configured.
- Trigger a test retrieval. Verify that matching scores of returned results fall within the configured `similarity` range.
- Review the dataset source of retrieval results. Confirm only the exclusive review rule dataset specified by `collectionIds` is included.
- Verify that after `usingReRank` is enabled, retrieval result sorting for complex rule combinations meets expectations.

The values provided are common starting points and should be evaluated against the reader's own samples.
