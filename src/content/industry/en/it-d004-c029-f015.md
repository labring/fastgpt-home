# Customer Technical Support and Pre-sales Q&A for Content Copyright and Authorization Management: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
This category's data primarily comes from contract systems, copyright registration databases, internal content repositories, and complaint inboxes. Daily processed documents include authorization contracts, copyright ledgers, takedown notices, and infringement complaint materials. Each document contains core fields such as authorized entity, authorization scope, validity period, authorized party, and complainant information. Data updates follow a cycle of individual business orders or monthly. Each piece of data is associated with a specific content copyright item, and there are no high-frequency bulk update scenarios. The data structure is primarily structured text, with a small amount of non-standardized complaint text mixed in.

## Constraints on Knowledge Base Retrieval and Recall Imposed by These Characteristics
The core association of this category's data is based on individual copyright items. A single retrieval must accurately match fields such as authorization scope and validity period, and low-relevance unrelated entries must be prevented from appearing in results. Data updates primarily follow individual orders or monthly cycles, so high-frequency incremental synchronization is not required, but full recall of historical data must be ensured to avoid missing expired authorizations or unresolved complaint records. Document types include structured contracts and unstructured complaint text, so retrieval matching logic must adapt to different text structures. Non-standardized text imported from complaint inboxes requires additional format alignment, otherwise recall accuracy will be affected and subsequent manual verification workload will increase.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the precise field matching requirements for authorization scope, validity period, etc., to avoid low-match irrelevant authorization entries appearing in results |
| `limit` | Top 10 entries | The number of authorized documents and complaint materials associated with a single copyright item is usually limited, limiting the number of results reduces manual verification costs |
| `usingReRank` | Enabled | Differentiates the relevance of structured contract fields and unstructured complaint text, optimizing the sorting results for authorization scope verification |
| `datasetSearchUsingExtensionQuery` | Enabled | Supplements synonymous extensions for fields such as authorized entity and validity period, improving recall rates for cross-field retrieval |
| `collectionIds` | Specify dedicated dataset IDs for copyright ledgers and authorization contracts | Isolates knowledge base data unrelated to this category, preventing irrelevant content from interfering with authorization-related retrieval results |

## Three Common Configuration Mistakes
- The symptom is that the number of retrieval results does not meet expectations, and the maximum number of returned results cannot be adjusted. The cause is that the `limit` parameter is not configured correctly, or the parameter value exceeds the actual data volume of the current dataset.
- The symptom is a format verification error when importing old version knowledge base data. The cause is that the field order and required items were not adjusted according to the CSV template for the current FastGPT v4.17.0 version.
- The symptom is that the re-ranking model does not take effect during large model calls, but the knowledge base search test interface works normally. The cause is that the re-ranking function was not enabled in the large model call configuration, and the option was only configured in the separate retrieval test.

## How to Verify Proper Configuration
- Retrieve authorization scope keywords, and check whether the matching scores of returned results fall within the preset interval.
- View the number of retrieval results, confirm that the returned quantity matches the configured `limit` value.
- Import a test authorization contract sample, check whether associated copyright ledger data can be recalled.
- After enabling the re-ranking function, compare the result sorting before and after enabling, confirm that entries related to authorization scope are ranked higher.

The values provided are common starting points and should be measured against the reader's own samples.
