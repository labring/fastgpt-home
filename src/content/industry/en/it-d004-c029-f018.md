# Customer Technical Support and Pre-sales Q&A for Content Copyright and Authorization Management: Re-ranking and Hybrid Retrieval

## What the data for this category looks like
This category’s data comes from contract systems, copyright registration databases, content material libraries, and infringement complaint inboxes. Daily processed documents include authorization contracts, copyright ledgers, takedown notices, and infringement complaint materials. Each data entry contains fields such as rights holder information, authorization scope, expiration date, and associated content ID. Data updates follow per-order or monthly cycles. Individual document sizes range from a few pages to dozens of pages. Core fields have no unified fixed unit, and matching formats must be aligned based on document type.

## What constraints these characteristics impose on the re-ranking and hybrid retrieval link
Integrate multi-source data via hybrid retrieval. Establish clear field mapping rules for different data sources to avoid data omissions caused by field mismatches. There are significant field differences between authorization contracts and infringement complaint materials. Prioritize matching core fields such as authorization scope and associated content ID during the re-ranking link to correct semantic deviations from basic retrieval. Refresh the retrieval index regularly for monthly updated copyright ledgers to prevent expired authorization information from interfering with retrieval results. Adjust the recall range for hybrid retrieval to match wide variations in individual document sizes, preventing redundant data from occupying display space for valid results.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.65–0.75 | Aligns with the matching precision required for core fields such as authorization scope and associated content ID, avoiding low-relevance contracts or complaint materials from being included in results |
| `limit` | Top 8 entries | Matches the volume of authorization or complaint materials processed per round for this category, avoiding excessive data that increases verification costs |
| `usingReRank` | Enabled | Addresses matching for non-standard text such as authorization scope, corrects semantic deviations from basic retrieval, and improves matching precision between infringement materials and authorization clauses |
| `searchMode` | Hybrid retrieval mode | Integrates data from contract systems, copyright databases, and complaint inboxes, covering multi-source authorization and infringement-related information |

## Three Common Mistakes
- Phenomenon: Retrieval results do not trigger re-ranking, and the interface shows the re-ranking toggle is enabled but results remain unchanged. Cause: The corresponding re-ranking model is not bound in the retrieval configuration, or the re-ranking model’s call parameters do not match the field format of the current data source.
- Phenomenon: The number of hybrid retrieval return results is far lower than expected, and only data from a single source is returned. Cause: The `limit` parameter is set too low, or multi-data source field mapping rules are not configured correctly, leading to data from some sources being filtered out.
- Phenomenon: Retrieval results include expired authorization contracts unrelated to the query. Cause: The retrieval index for the copyright ledger is not refreshed at the monthly update frequency, causing expired authorization information to be included during `similarity` matching.

## How to Confirm Proper Configuration
- Access the retrieval configuration page in FastGPT v4.17.0, confirm that the `usingReRank` toggle is enabled, and bind a re-ranking model adapted for copyright text.
- Submit a test query such as "Query currently valid authorization contracts", and verify that the number of returned results matches the `limit` setting.
- Compare basic retrieval results with re-ranked results, confirm that re-ranked results prioritize content with higher authorization scope matching precision.
- Manually import an expired authorization contract, submit a retrieval query, and confirm that the result does not include this expired data, or confirm that the index refresh cycle aligns with the monthly update requirement.
