# Customer Technical Support and Pre-Sales Q&A for Internal Network and WiFi Operations: Reranking and Hybrid Retrieval

## What this category of data looks like
Typical business data for internal network and WiFi operations comes from switch consoles, wireless controllers, enterprise monitoring systems, and frontline user trouble report channels. Daily retained documents include network topology diagrams, configuration change orders, historical fault records, and wireless coverage inspection forms. Data update cadence follows daily synchronization or real-time updates triggered by configuration changes.
Data fields include device MAC addresses, port numbers, VLAN configurations, signal strength thresholds, fault occurrence times, and trouble report workstation locations. Some documents include hierarchical topology structure and port mapping information.

## What constraints do these characteristics impose on reranking and hybrid retrieval
The characteristics of internal network and WiFi operation business data impose clear constraints on the reranking and hybrid retrieval process.
Multi-source heterogeneous data sources require the retrieval pipeline to support structured device configurations, semi-structured fault records, and unstructured topology documents. It must adapt to matching rules for different field types.
Flexible update cadences require support for daily incremental synchronization or real-time refresh triggered by configuration changes. This avoids retrieving expired configuration data.
The need for precise matching of specialized fields such as MAC addresses, port numbers, and VLAN configurations requires hybrid retrieval to first recall device data strongly relevant to the current trouble report scenario. This reduces interference from irrelevant documents.

## How to configure
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `usingReRank` | Enabled | Troubleshooting for internal network operations requires precise matching of device status. Enabling reranking filters low-relevance historical records and expired configurations |
| `similarity` | `0.72–0.85` | Balances precise recall of device parameters and coverage of relevant scenarios, adapting to the matching accuracy of specialized network fields |
| `limit` | `Top 8–12 entries` | Troubleshooting in operation and maintenance scenarios requires a limited candidate set, avoiding excessive documents exceeding the context window |
| `searchMode` | Hybrid Retrieval (Vector + Keyword) | Balances keyword matching for specialized fields and semantic association-based vector recall, adapting to multi-source heterogeneous operation and maintenance data |

## Three common misconfigurations
- Symptom: The reranking link returns `false` fields or no valid reranking results. Cause: The `usingReRank` configuration is not correctly enabled, or the reranking model's API access permission is not bound to the current knowledge base.
- Symptom: When using the Qwen/Qwen3-Embedding-8B configuration for the reranking model, the existing configuration is automatically overwritten. Cause: FastGPT system limits one configuration per model name. Use names with version identifiers to distinguish different instances.
- Symptom: Calling the Alibaba Bailian Cloud gte-rerank-v2 model returns empty content. Cause: The model's API key or calling parameters are not correctly configured, preventing the model from returning sorting results normally.

## How to confirm successful configuration
- Navigate to the retrieval configuration interface of the target knowledge base, confirm that the `usingReRank` configuration item is enabled.
- Submit a simulated network trouble report query, check whether the retrieval result list includes reranking-related scoring fields.
- Attempt to add a new retrieval model with the same name as the configured model, confirm that the system displays a duplicate configuration prompt.
- Retrieve historical documents containing expired configurations, verify that the retrieval results prioritize displaying the latest device status data.
