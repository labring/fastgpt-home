# Customer Technical Support and Pre-sales Q&A for Creator Onboarding and Verification: Knowledge Base Retrieval and Recall

## What this category’s data looks like
Data for this category primarily comes from creator backends, enterprise credit inquiry platforms, account history records, and contract systems. Daily processed documents include onboarding application forms, identity qualification scan descriptions, verification audit records, and cooperation agreement texts.
Data updates run on a daily batch sync schedule or trigger updates per individual application. Each entry corresponds to a single creator’s application or verification process. Fields include account identifier, qualification type, audit status, cooperation validity period, and more. Single document length has no fixed standard, and varies dynamically based on application complexity.

## What constraints do these characteristics impose on knowledge base retrieval and recall
Creator onboarding and verification knowledge base data includes unstructured qualification materials, contract texts, and structured audit records. Document structures differ widely across applications, so retrieval logic must adapt to multiple content types.
The per-application update feature requires the retrieval pipeline to support incremental document updates. This prevents recalling outdated audit status or qualification information.
The fact that each entry maps to an independent application process requires retrieval results to link to the corresponding creator’s application identifier. This avoids mismatched results across applications.
Non-plain-text content such as images and encrypted texts in qualification materials reduces retrieval completeness for basic retrieval. Additional adaptation for the content parsing process is required.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches semantic similarity for qualification texts and contract texts, filters low-relevance audit records |
| `limit` | Top 8–12 entries | Controls the number of documents returned per retrieval round, avoids context overload that impacts qualification verification judgments |
| `searchMode` | Semantic Retrieval | Adapts to semantic matching across multiple document types, covers qualification materials and structured audit records |
| `usingReRank` | Enabled | Re-ranks initial retrieval results, prioritizes content that better matches onboarding qualifications and verification requirements |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands retrieval terms, covers abbreviations and industry terms that appear in creator applications |
| `collectionIds` | Exclusive knowledge base ID for creator onboarding and verification | Limits retrieval scope, prevents mixing with knowledge base data from other categories |

## Three Common Mistakes
- After uploading a docx document for onboarding applications, knowledge base retrieval fails to recall qualification scan descriptions within the document. The cause is that the document parsing image text extraction configuration is not enabled, and only plain text content is extracted.
- Calling the published knowledge base Q&A interface returns a 422 status code. Troubleshooting steps: Check if the AIPROXY_API_ENDPOINT (root address of the AI Proxy service, do not append path suffixes such as /v1 or /chat/completions) and AIPROXY_API_TOKEN (administrator token matching the AI Proxy service configuration, cannot be empty) environment variables on the App/Admin server are correctly configured and non-empty.
- Retrieval results return audit records from unrelated creators. The cause is that the retrieval scope is not limited via the collectionIds parameter, and the call uses full platform knowledge base data.

## How to Confirm Proper Configuration
- Check environment variables on the App/Admin server. Confirm that AIPROXY_API_ENDPOINT (root address of the AI Proxy service, do not append path suffixes such as /v1 or /chat/completions) and AIPROXY_API_TOKEN (administrator token matching the AI Proxy service configuration, cannot be empty) are correctly configured and non-empty.
- Upload a test document containing qualification images and structured audit records. Initiate retrieval and confirm that text content corresponding to images and structured fields can be recalled.
- Initiate a retrieval request. Confirm that the number of returned results does not exceed the value set by the limit parameter, and similarity falls within the range specified by the similarity parameter.
- Initiate a retrieval after limiting collectionIds to the exclusive knowledge base ID. Confirm that returned results only come from this knowledge base, with no cross-category irrelevant content.
- Confirm that FastGPT v4.17.0 startup verification passes, with no prompts for missing required environment variables.
