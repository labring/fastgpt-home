# Customer Technical Support and Pre-sales Q&A for Office System Workflow Configuration: Reranking and Hybrid Retrieval

## What data looks like for this category
The primary data stakeholders for this category are enterprise IT administrators, OA administrators, and business workflow administrators. Daily generated documents include workflow configuration sheets, approval node tables, form field descriptions, and change records. Data originates primarily from enterprise OA systems, organizational structure libraries, internal system documents, and user feedback. Update frequency aligns with business changes, typically once per change event. The most time-consuming daily tasks are approval rule sorting, node permission configuration, and test validation. Incorrect configuration may lead to approval freezes, permission errors, or deviations in system implementation. Unlike identity and account permission management categories, this category focuses on business approval paths and form configuration.

## What constraints do these characteristics impose on reranking and hybrid retrieval
The data characteristics of office system workflow configuration impose clear constraints on reranking and hybrid retrieval. First, data includes structured approval node tables, form field descriptions, and unstructured system documents. Hybrid retrieval must support both semantic matching and structured field matching, to avoid returning irrelevant permission configuration content. Second, data update frequency follows business changes. Retrieval must prioritize matching the latest change records, to prevent administrators from using outdated workflow configurations. Finally, daily time-consuming tasks focus on rule sorting. Retrieval results must quickly locate specific approval nodes or configuration entries, to reduce manual troubleshooting time for administrators.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `usingReRank` | Enabled | Office system workflow configuration data includes multiple types of entries. Reranking filters low-relevance historical configurations and irrelevant permission rules |
| `similarity` | 0.75–0.85 | Workflow configuration has high matching precision requirements, to avoid introducing old change records unrelated to the current query |
| `limit` | Top 10 entries | The number of configuration entries returned per retrieval adapts to administrators' need for quick location, to avoid information overload |
| `searchMode` | Hybrid retrieval mode | Combines semantic matching and structured field matching, to adapt to the multi-type data structure of workflow configurations |
| Reranking model access | Calibrated based on the actual text length of business data | Must match the average length of workflow configuration documents, to avoid model input overflow or reduced accuracy |

## Three common misconfigurations
- After configuring the reranking model, testing shows an error, but the system runs when referenced, and reranking displays abnormally. Cause: The ACCESS Token for the reranking model is not configured correctly, or the port used for model deployment is not opened to the FastGPT service network.
- The knowledge base shows a cross mark after enabling result reranking. Cause: The connectivity check for the reranking model has not been completed, or the number of results returned by retrieval does not meet the minimum input requirement of the reranking model.
- Old workflow configuration entries have higher priority than latest change records in retrieval results. Cause: A reasonable similarity threshold for filtering old data is not set, or latest workflow change records are not prioritized for matching.

## How to confirm successful configuration
- Access the knowledge base retrieval configuration page of FastGPT v4.17.0, confirm that the `usingReRank` switch is enabled, and the configuration information for the reranking model is complete.
- Initiate a query related to current workflow configuration, verify that the number of returned results matches the value set for the `limit` configuration item.
- Compare retrieval results before and after enabling reranking, confirm that highly relevant approval node configuration entries appear earlier in the sorted order.
- Run a retrieval test, confirm that no error prompts are displayed, and the results include the latest workflow change records.
