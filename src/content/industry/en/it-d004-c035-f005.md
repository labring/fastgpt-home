# Customer Technical Support and Pre-Sales Q&A for Unit Testing and Component Testing: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data for this category primarily originates from code repositories, test framework reports, requirement specifications, and interface definitions. Updates occur daily or after each code commit. Daily associated documents include test cases, coverage reports, Mock instructions, and defect tickets. Data fields include test case numbers, code coverage ranges, Mock configuration parameters, defect status and repair progress, among others. Data is updated per commit node or daily as business processes progress, with no additional statistical percentage data.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
Data sources are scattered and updated in real time with code commits. Multi-turn dialogue must associate with the latest code repositories, test framework reports and other data sources, and avoid calling expired test document content. Test documents include structured test cases, coverage reports and similar materials. Prompts must adapt to the field formats of different documents to accurately extract corresponding information. The high-frequency update feature requires limiting the effective scope of dialogue context, to prevent accumulated old data from interfering with the current conversation. Additionally, constructing test data and completing boundary conditions is time-consuming. Multi-turn dialogue must support gradual guidance to supplement missing parameters, reducing manual organization costs.

## How to Set Configurations
This document is compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind code repository branch and session timestamp | Ensure multi-turn dialogue associates with the latest test data for the corresponding branch |
| `messages` | Retain the most recent 8 rounds of interaction content, with no single round exceeding 7000 characters | Adapt to the high-frequency update feature of test data, avoid context overload |
| `variables` | Only pass the test case ID and defect ticket number for the current session | Narrow the scope of variable usage, accurately match associated document fields |
| Prompt template | First clarify the current test phase, then extract fields from the corresponding document | Adapt to the structures of different documents such as test cases and coverage reports |
| Timeout setting | 60 seconds | Match the typical response duration for test data queries |

## Three Common Mistakes
- Symptom: Responses from multiple AI dialogue nodes within a workflow all appear in the workflow’s chat session. Cause: No output hiding configuration item is set for non-target nodes.
- Symptom: A connection error pop-up appears when using model-based dialogue. Cause: No valid model API access key is configured, or network access restrictions are in place.
- Symptom: The conversation icon cannot be modified in login-free scenarios. Cause: No custom icon file meeting format requirements is uploaded in system settings.

## How to Confirm Configurations Are Set Correctly
- Trigger a multi-turn dialogue for test data query, and verify that the number of retained interaction rounds matches the preset configuration.
- Check whether the session identifier is bound to the corresponding code branch, and confirm that the data source matches the current business scenario.
- Submit a query associated with a test case, and verify that the prompt only calls variable content allowed for the current session.
- Trigger a time-consuming test data request, and confirm that the session response duration matches the preset timeout configuration.
