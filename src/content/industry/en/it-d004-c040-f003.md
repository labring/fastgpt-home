# Customer Technical Support and Pre-sales Q&A for Pre-sales Technical Solutions: Sharing and Embedding

## What Pre-sales Technical Solution Data Looks Like
Sources of pre-sales technical solution data include customer interview records, bidding documents, vendor public product materials, and historical project plans. Daily output documents include technical proposal books, customer requirement research forms, quotation lists, and demo scripts. Core fields cover technical routes, implementation boundaries, quotation details, and customer requirement items.
Data is updated per order or weekly. Each update covers all supporting documents for the corresponding project. Data correlation between different projects is low, so each project must be managed separately.

## Constraints Imposed on Sharing and Embedding Workflows
Since data is managed per project and has a fixed update frequency, sharing and embedding configurations must match the exclusive data source of a single project. This prevents cross-project data confusion.
Documents include undisclosed quotations and implementation boundary content. Access permissions for embedded pages must be strictly controlled to prevent sensitive information leaks.
Documents are scattered across multiple independent files. Support must be provided for retrieval by a specified document set, to avoid irrelevant content interfering with pre-sales Q&A.
Data has a relatively high update frequency. A cache synchronization mechanism must be configured via an external business system or FastGPT knowledge base nodes. This ensures that Q&A content after embedding is synchronized with the latest solutions.

## Three Common Misconfigurations
- Sharing entries for pre-sales technical solutions fail to open. First verify the complete system-generated link and its validity period, then check browser request status. Do not manually replace `shareId`.
- The visible scope of pre-sales technical solution data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately. The sharing entry identifier itself does not provide business authorization.
- The same pre-sales technical solution Q&A is not visible on another device. For anonymous scenarios, first check device, browser, and local identity status. Retention cannot be guaranteed across devices or after cache clearance. Do not use this phenomenon alone to judge service abnormalities.

## How to Confirm Configuration Completion
- Copy the generated embedding code and the share link bound to `shareId`, open it in a non-office network environment, and verify that the Q&A module loads normally and retrieves content corresponding to the pre-sales solution.
- Modify the content of a document in the FastGPT-bound knowledge base, wait for the knowledge base synchronization to complete, then initiate a targeted question again, and verify that the returned answer has been updated to the modified content.
- Check whether the `shareId` parameter in the embedding code comes from the login-free window link generated in the corresponding pre-sales solution sharing scenario, to avoid parameter misalignment leading to incorrect sharing entry calls.
- Open the embedded page in mainstream browsers such as Chrome and Firefox, verify normal operation, and pay attention to compatibility performance for IE browsers.
