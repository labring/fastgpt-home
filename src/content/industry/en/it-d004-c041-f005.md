# Customer Technical Support and Pre-sales Q&A for Image Annotation Projects: Multi-turn Dialogue and Prompt Engineering

## What data for this category looks like
Image annotation project data primarily comes from image samples uploaded via annotation platforms, preset category dictionaries, bounding box records generated during annotation, subsequent quality inspection reports, and rework lists. Data updates follow a daily schedule or per annotation batch, with each batch of annotation tasks corresponding to an independent dataset. Daily circulating documents include unified annotation specifications, standard bounding box examples, single-task quality inspection results, and detailed rework lists for annotation. Data fields include bounding box coordinates of visual targets, category labels, random inspection judgment results, and similar content. There are no unified unit requirements, and field formats are matched according to the specific rules of each annotation task.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
The data characteristics of image annotation projects impose multiple constraints on multi-turn dialogue and prompt configuration. First, the data includes visual image samples and bounding box coordinates. Prompts must clearly distinguish between visual target descriptions and text annotation rules to avoid confusion between the two types of information. Second, daily documents include structured content such as annotation specifications and quality inspection reports. Multi-turn dialogue must support associating annotation documents for a specified batch to prevent cross-batch data from interfering with current tasks. Additionally, data updates daily or per batch. Dialogue context must limit the valid data range for a single session to prevent loading expired rework lists or outdated annotation specifications. At the same time, fields include non-text content such as bounding box coordinates. Prompts must clearly specify output formats to ensure annotation results meet the team’s unified requirements.

## How to set up configurations
The following configurations are optimized for the customer technical support and pre-sales Q&A scenario of image annotation projects, and are compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---|---|--- |
| Maximum context length | 8000–12000 characters | Documents for image annotation projects include long text such as annotation specifications and bounding box examples, requiring sufficient context information to ensure rule matching |
| `variables` | Bind annotation batch ID and category dictionary fields | Data for image annotation projects updates per batch. Binding batch information via variables allows accurate association with annotation documents for the corresponding batch |
| `messages` | Limit single-session history to the first 10 dialogues | Avoid excessive historical dialogue interfering with prompt matching for current annotation tasks |
| Question optimization | Enabled | Technical questions related to annotations are often vaguely phrased; optimization improves the accuracy of rule matching |
| `chatId` | Generate unique session IDs based on annotation task IDs | Distinguish session data from different annotation teams to prevent cross-task context confusion |
| Single search limit | Top 3 results | Annotation-related documents are usually concentrated in a small number of specifications or examples; too many search results will interfere with prompt precision |

## Three common mistakes
- Phenomenon: The model’s output language does not match the preset prompt requirements, such as returning only Chinese content when an English response instruction is preset. Cause: The language attribute of the knowledge base is not clearly bound in the prompt, or the `variables` do not configure language variables to override the default model output rules.
- Phenomenon: An error is returned during the parsing stage after uploading annotation image samples. Cause: No file parsing trigger rule is configured in `messages`, or the configured context length is insufficient to accommodate metadata parsed from images.
- Phenomenon: Interactive records within the application cannot be viewed on the conversation details page. Cause: Session log storage configuration is not enabled, or `chatId` is not correctly associated with the log index for the current session.

## How to confirm the configuration is complete
- Initiate a conversation containing keywords related to annotation specifications, and check whether the content returned by the model matches the preset annotation rules.
- Upload a single annotation image sample, and verify whether the image metadata is returned normally during the parsing stage.
- Generate a new `chatId` to initiate a conversation, and confirm that the complete interaction log can be viewed on the conversation details page.
- Initiate a conversation after configuring an English prompt, and check whether the model’s output language meets the preset requirements.

The values provided here are common starting points and should be evaluated against the reader’s own samples.
