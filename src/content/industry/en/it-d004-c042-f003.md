# Customer Technical Support and Pre-Sales Q&A for Backup Recovery and Disaster Recovery Drills: Sharing and Embedding

## What Data for This Category Looks Like
Data for this category primarily comes from backup systems, database logs, object storage, and disaster recovery platforms. Four types of documents are produced regularly: backup policies, recovery drill reports, disaster recovery switchover plans, and data verification records. Data update cycles fall into three categories: daily, monthly, and quarterly. Core fields include Recovery Point Objective, Recovery Time Objective, drill execution duration, and data verification consistency rate. Their units are seconds, seconds, minutes, and percentage respectively. The most time-consuming daily operations are recovery point confirmation, drill script execution, and data consistency verification. All data centers around cross-system recoverability, which differs from single-database maintenance work.

## Three Common Misconfigurations
- Sharing entries for backup recovery and disaster recovery drills fail to open. First verify the full system-generated link and its validity period, then check browser request statuses. Do not manually replace `shareId`.
- Visibility of backup recovery and disaster recovery drill data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately. The sharing entry identifier itself does not provide business authorization.
- Original conversation for the same backup recovery and disaster recovery drill question is not visible on another device. For anonymous scenarios, first check device, browser, and local identity status. Retention cannot be guaranteed across devices or after cache clearance; do not use this phenomenon alone to judge service anomalies.

## How to Confirm Successful Configuration
- View network request logs in the browser console to confirm no interception of cross-domain requests for embedded pages, and that the `shareId` parameter matches the system-generated value for the corresponding guest sharing link.
- Initiate a query containing the keyword "recovery point confirmation" to verify that returned document fragments match the latest recovery drill report content in the external knowledge base.
- Attempt to embed the page using an unauthorized domain name to confirm inability to load target knowledge base content. Authorized domains may access content normally.
- Trigger a guest sharing window query request to confirm that the output format matches the configured streaming or static requirements.
