# Customer Technical Support and Pre-sales Q&A for Security Incident Emergency Response: Multi-turn Dialogue and Prompt Engineering

## Data Profile for This Category
Core data for security incident emergency response originates from SIEM, EDR, firewall logs, and host images. Updates are triggered in real time or per individual incident. Daily support materials include standardized emergency response reports, forensics records, isolation and disposal plans, and incident notifications. Document fields include attack source IP, affected assets, disposal timestamps, evidence chain hash values, and more. There is no unified fixed format, and formats are dynamically adjusted based on incident complexity.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
Decentralized, real-time updated data sources require multi-turn dialogue to associate context across different log sources. Prompts must explicitly specify priority access to correlated data from SIEM and EDR tools. Unstructured document formats require prompts to include field mapping rules, to guide models to extract standardized fields. The real-time update feature requires conversation contexts to retain event data from the last hour, to avoid calling expired logs. Evidence chain-related conversations must strictly retain operation records. Prompts must prohibit tampering with or omitting disposal step fields, as this may introduce evidence chain failure risks.

## Configuration Settings
Reference configurations for FastGPT v4.17.0 are listed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context | Previous 20 dialogues or 1200–1500 characters | Matches the typical dialogue rounds for a single security incident, avoids context overload that interferes with attack path restoration |
| Question Optimization | Enabled, calibrated via actual testing | Adapts to non-standard field descriptions in SIEM and EDR logs, improves question-and-answer accuracy |
| `chatId` | Bound to the unique incident identifier | Associates all dialogue records for a single incident, enabling complete evidence chain tracing |
| `messages` | Stored in ascending order of event time | Ensures multi-turn dialogue restores attack paths and operational logic in disposal order |
| `variables` | Pre-set attack source IP, affected asset ID | Quickly retrieves forensics records and disposal plans from corresponding log sources |
| Single Recap Limit | Top 5 results | Covers key information from multi-source logs, avoids redundant data interfering with response decision-making |

## Three Common Misconfiguration Scenarios
- Symptom: A "No available index model detected" error appears after page refresh, and new conversation agents function normally. Cause: The event index bound to `chatId` is not persistently stored across sessions, or the index model’s associated configuration was not saved to the target session configuration.
- Symptom: Dialogue responses do not include jump links or original text snippets from source materials. Cause: The prompt does not configure the traceability field for log sources linked to `variables`, or the context reference output rule is not enabled.
- Symptom: Forensics report attachments generated during dialogue cannot have their download validity period restriction removed. Cause: The mandatory binding of document download validity periods was not disabled in the conversation configuration, or the disposal plan document permissions were not set to permanently accessible.

## How to Verify Correct Configuration
- Initiate a multi-turn dialogue for a single incident, confirm that `chatId` is consistently bound to the incident’s unique identifier, and ensure context is retained across sessions.
- Test a query containing an attack source IP, verify that pre-set variables in `variables` automatically associate with forensics records from the corresponding log source.
- Review the conversation context storage, confirm that `messages` are ordered by event time, with no chaotic or missing dialogue rounds.
- Trigger a conversation without a bound incident identifier, and confirm the error prompt matches expected behavior.

The values provided here are common starting points, and should be evaluated against local test samples tailored to the relevant environment.
