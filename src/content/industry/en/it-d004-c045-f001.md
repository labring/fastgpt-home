# Customer Technical Support and Pre-sales Q&A for Security Training and Phishing Drills: HTTP Interfaces and External Systems

## What this category’s data looks like
Daily documents for this category include training courseware, drill plans, phishing email templates, and drill result reports. Data sources typically include employee contact lists, email gateways, internal training platforms, and user click statistics systems. Data update frequency is mostly quarterly or annual. Core fields include drill participant lists, email sending records, click feedback data, rectification records, and other relevant items. Typical users are security operations teams, internal training departments, or external security service providers. Core work focuses on improving personnel security awareness and implementing phishing drills.

## What constraints these characteristics impose on HTTP interfaces and external systems
Differences exist between the field formats of employee contact lists and the interface specifications of email gateways. HTTP interfaces must be used to align fields and complete data synchronization. Quarterly or annual update frequencies require interfaces to support batch pulling or incremental updates, to avoid repeated resource calls. Phishing email templates and drill result reports have large file sizes. Interfaces must adapt to large file transfer and chunked upload logic. Time-consuming steps such as drill participant screening and result review can be automated through external system integration. Interface call stability and error retry mechanisms must be implemented. Compatibility with different source data encoding formats is also required to avoid garbled text issues.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer ${apiKey}` | Complies with HTTP interface authentication standards to ensure request legitimacy |
| Interface timeout period | `300–600 seconds` | Meets time requirements for quarterly-level data pulling, avoids task interruption from short timeouts |
| `responseData` | Return the first 100 records sorted in descending order by drill date | Prioritizes returning the latest drill result data to meet review and analysis needs |
| Single upload file size limit | `1000 MB` | Adapts to upload requirements for large drill result reports, avoids file truncation |
| File encoding format | UTF-8 | Compatible with Chinese file names and document content, avoids garbled text issues |
| `variables` | Pass business parameters such as drill participant ID and email template ID | Enables parameter linkage between the interface and internal systems, completes automated task triggering |

This document applies to FastGPT v4.17.0.

## Three common configuration mistakes
- Issue: Garbled text appears when uploading training courseware with Chinese file names, and the interface returns an encoding error prompt. Cause: The UTF-8 encoding format was not specified, and the default encoding is incompatible with Chinese file names.
- Issue: A 503 status code is returned when calling the interface to pull drill data, with a prompt that no available model exists for group default. Cause: Interface permission for the corresponding model was not configured, or model resource scheduling encountered an exception.
- Issue: Some personnel information is omitted when synchronizing employee contact list data in batches. Cause: Incremental update logic was not enabled, and pulling only full data resulted in incomplete field filtering.

## How to confirm the configuration is complete
- Initiate a file upload request with a Chinese file name. Verify that the return result contains no garbled text prompts, and the file can be parsed normally.
- Call the authentication interface to verify the validity of the `Authorization` parameter. Confirm that the request can pass authentication normally.
- Configure the `variables` parameter to pass a test business ID. Trigger an interface call, and confirm that the internal system can normally receive linked parameters.
- Check the interface logs. Confirm that the returned `responseData` includes the latest drill result records, and the sorting matches expected requirements.
