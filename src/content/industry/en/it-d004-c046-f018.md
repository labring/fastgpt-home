# Customer Technical Support and Pre-sales Q&A for Security Baseline Checking: Reranking and Hybrid Retrieval

## What the data for this category looks like
Core data for security baseline checking comes from server configuration files, middleware parameter configurations, security device policy logs, and outputs from dedicated baseline scanning tools.
Daily documents include standardized baseline checklists, single-time verification configuration records, rectification suggestion sheets, and exception approval documents.
Data updates occur monthly or quarterly.
Each document contains fields such as configuration item identifiers, compliance status, and associated resource information.
The overall structure is orderly, with no complex nested content.

## What constraints these characteristics impose on reranking and hybrid retrieval
Multi-source heterogeneous data sources require hybrid retrieval to adapt to field formats of different data sources. This avoids chaotic retrieval results.
Single documents have orderly structures but come from dispersed sources.
The input threshold of the reranking model must match the average length of baseline documents. This prevents key configuration information from being truncated.
Semantic differences between exception approval documents and regular configuration items are significant.
Reranking must adjust the sorting weight of the two types of results. This prioritizes content with higher relevance to customer inquiries.
Low-update-frequency data does not require high-frequency retrieval cache refreshes.
It must ensure retrieval results cover the latest quarterly updated content.

## How to set configurations
The following configurations are formulated for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Reranking Switch | Enabled, bound to TEI-deployed reranking service | Configuration item relevance for security baseline checking requires precise sorting. Reranking improves matching accuracy of retrieval results, and adapts to the reranking service call logic of FastGPT v4.17.0 |
| Single Retrieval Limit | Top 10 entries | The number of configuration items in a single baseline checklist typically ranges from 5 to 15. Limiting returns to the top 10 entries covers core verification content |
| Retrieval Mode | Hybrid retrieval | Multi-source data such as server configurations and security device policies must be integrated. Hybrid retrieval unifies the display logic of cross-source results |
| Similarity Threshold | 0.75-0.85 | Semantic similarity of security baseline configuration items must fall within this range to filter irrelevant non-configuration documents |
| Reranking Input Length | 800-1200 characters | The average length of security baseline documents falls within this range. Matching the model's input length requirements prevents key configuration information from being truncated |

## Three common configuration errors
- Symptom: The reranking model passes deployment tests, but each retrieval returns a reranking result field with a value of false.
  Cause: The reranking service call address is not bound in the retrieval workflow. Or the reranking model input format does not match FastGPT requirements.
- Symptom: After knowledge base retrieval content exceeds 1200 characters, the reranking model is not triggered.
  Cause: The reranking model has an input length limit. Retrieval results exceeding the limit are not sent to the reranking link. The sorting step is skipped directly.
- Symptom: The Qwen3-Reranker-8B reranking model cannot be adapted.
  Cause: Model inference parameters are not configured per FastGPT's reranking model adaptation requirements. Or the deployed model version does not match FastGPT's compatible version.

## How to confirm configuration is complete
- Access the FastGPT knowledge base management interface. Navigate to the security baseline checking knowledge base configuration page. Check if the reranking switch is enabled.
- Initiate a retrieval request simulating a customer inquiry. Check if the retrieval result list includes a reranked sorting identifier.
- Adjust the length of the retrieval content. Verify that the reranking model is called normally when content falls within the 800-1200 character range.
- View the retrieval log. Confirm that a reranking model call record exists. Confirm that returned sorting results match expected configuration item relevance.

The values provided are common starting points and should be measured against the reader's own samples.
