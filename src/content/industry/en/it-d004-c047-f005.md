# Customer Technical Support and Pre-sales Q&A for Security Vulnerability Disclosure Handling: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data for this category comes from private vulnerability reports, code repositories, CVE numbering authorities, and official release channels. Daily maintained documents include security advisories, vulnerability reports, fix patches, and CVE submission materials. Core fields include CVE ID, vulnerability CVSS score, impact scope, patch submission records, and disclosure coordination progress. Data updates follow a single vulnerability event cycle. Each event updates its associated documents and records exactly once from report submission to disclosure completion.

## What Constraints Do These Characteristics Impose on the "Multi-turn Dialogue and Prompt Engineering" Link
Permission restrictions on private vulnerability reports require dialogue context to be visible only to authorized maintainers. Use `chatId` to isolate dialogue data for different events. The data update cycle for single events is fixed. Dialogue context must be limited to documents associated with the current vulnerability event to avoid irrelevant content. Documents contain structured fields such as CVE ID and patch links. Prompt engineering must preset extraction rules to automatically associate and fill corresponding fields into the dialogue context. Decentralized data sources require the dialogue module to pre-aggregate multiple types of documents, including security advisories and vulnerability reports. This ensures input content is complete and accurate.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context length | 800–1200 characters | The total length of associated documents for a single vulnerability event typically falls within this range, which avoids exceeding model input limits. This configuration requires FastGPT v4.17.0 or later |
| Dialogue session isolation | Divide by `chatId` | Private vulnerability reports require strict isolation of dialogue data for different events to prevent sensitive information leaks |
| Variable binding configuration | Bind the `CVE ID` and `impact scope` fields in the `variables` array | Structured fields from documents must be automatically filled into the prompt context to ensure reply content accurately matches the current vulnerability event |
| Multi-turn dialogue history management | Retain the first 3 core interactions in the `messages` array | Key information for vulnerability handling is concentrated in early communication and patch coordination stages. Redundant history reduces model response efficiency |
| Prompt template configuration | Preset a dedicated vulnerability disclosure template | Unify reply standards for pre-sales and technical support, ensuring compliance with public disclosure specifications |
| Context source filtering | Only call associated documents for the current event | Avoid introducing irrelevant vulnerability or project data, ensuring dialogue content focuses on the current processing task |

## Three Common Misconfigurations
- Issue: Input content exceeding the model context limit returns an error directly, with no prior interception. Cause: Maximum context length limit is not configured, and no input length check step is added before the dialogue node.
- Issue: Dialogue records cannot be deleted in bulk by vulnerability event, only single deletion is supported. Cause: Sessions and vulnerability events are not bound via `chatId`, and no bulk cleanup rules by event ID are configured.
- Issue: Reply content does not associate the citation source for the corresponding CVE ID. Cause: Variable binding rules are not configured, and structured fields from documents are not automatically filled into the prompt template.

## How to Verify Successful Configuration
- Submit simulated data for a test vulnerability event, confirm that the dialogue context only includes associated documents for that event, with no irrelevant content.
- Trigger test input content that exceeds the preset length, confirm that the system intercepts the input at the input stage and returns a prompt, instead of waiting for a model error.
- Initiate a multi-turn dialogue, confirm that reply content automatically associates the CVE ID and impact scope fields for the current event.
- Switch between different `chatId` sessions, confirm that session data does not leak across events, and only authorized users can access corresponding sessions.

The values provided are common starting points and should be measured against the reader's own samples.
