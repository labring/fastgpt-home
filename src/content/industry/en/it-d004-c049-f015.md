# Customer Training and Usage Manual Technical Support and Pre-sales Q&A: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Core data for this category comes from product help centers, customer organizational structures, training recording videos, and ticket systems. Daily documents include training courseware, user manuals, training attendance sheets, and Q&A lists.
Training courseware includes chapter titles and duration fields. User manuals have numbered operation steps. Attendance sheets record participants and training times. Q&A lists map question IDs to standard answers.
Data update frequency is per order or per version. Most single updates consist of new operation instructions or revised training content.

## What constraints these characteristics impose on knowledge base retrieval and recall
Data sources for this category are scattered and have diverse formats. Structured documents include Q&A lists and attendance sheets, while unstructured content includes training courseware and transcribed video text. This requires retrieval systems to support chunking and encoding for different content formats.
The high-frequency update characteristic requires retrieval workflows to support incremental synchronization, avoiding resource consumption from full reindexing.
Documents contain large amounts of operation step and role permission explanation content. Retrieval results must accurately match the specific steps corresponding to the query, avoiding overly general recall of irrelevant content.
Core business content is concentrated in user manuals and Q&A lists. These documents should be prioritized for recall to improve retrieval efficiency.

## Configuration Settings
This configuration is based on FastGPT v4.17.0. Specific parameters and recommendations are listed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75-0.85 | This category of documents mostly contains standardized operation steps and precise Q&A content. This range filters low-relevance results and prevents irrelevant documents from being included in retrieval results |
| `limit` | 100-300 items | The core retrieval content of this category is concentrated in user manuals and Q&A lists. Excessive recall will interfere with core results. This range balances coverage and precision |
| `usingReRank` | Enabled | This category of documents contains a large number of sequentially arranged operation steps. The re-ranking function adjusts the semantic matching order of retrieval results, improving the accuracy of responses to step-based queries |
| `collectionIds` | Restricted to training and manual knowledge base IDs | This category requires distinguishing business scenarios. Restricting collections prevents irrelevant customer tickets or organizational structure data from being recalled across knowledge bases |
| `datasetSearchUsingExtensionQuery` | Enabled | User queries for this category often include scenario-based descriptions. Extended queries cover more relevant training courseware and user manual content |

## Three Common Misconfigurations
- Symptom: Garbled text appears in the knowledge base after online deployment, with no issues in the local deployment version. Cause: The file encoding configuration of the online environment differs from the local environment, or the correct encoding format was not specified when importing transcribed training recording files.
- Symptom: Retrieval recalls documents outside the target range, including training courseware or attendance sheets unrelated to the current query. Cause: The `collectionIds` parameter was not used to restrict the retrieved knowledge base collections, resulting in all knowledge base content being included in the retrieval scope.
- Symptom: After enabling segmented retrieval, the returned content deviates significantly from the operation step order in the original document. Cause: Contextual associations of operation steps were not preserved during chunking, or the `usingReRank` function was not enabled, leading to disordered semantic matching result order.

## How to Verify Proper Configuration
- Upload a test fragment of a user manual, retrieve a query corresponding to an operation step, and confirm that the returned results include the step and contain no irrelevant content.
- Check the similarity scores of retrieval results, confirming that the scores fall within the range specified by the `similarity` configuration.
- Verify the total number of retrieval results, confirming that it matches the value range specified by the `limit` configuration.
- Import the same transcribed training recording file into both online and local environments, confirming that no encoding garbled text issues occur.

The values provided are common starting points and should be measured against the reader's own samples.
