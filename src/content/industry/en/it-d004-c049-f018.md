# Customer Technical Support and Pre-sales Q&A for Customer Training and Usage Manuals: Reranking and Hybrid Retrieval

## What this category of data looks like
Data sources for this category include product help centers, customer organizational structures, training recording videos, and ticket systems. Daily produced documents include training courseware, user manuals, training attendance sheets, and Q&A lists. Training courseware and user manuals are mostly long-text structures containing operation steps, role permission descriptions and other content. Q&A lists and ticket system data are mostly short texts focused on specific customer questions. The data update frequency is per order or per version, adjusted alongside product version iterations or customer training cycles.

## What constraints do these characteristics impose on reranking and hybrid retrieval
The data structure of this category varies significantly, with long-text operation manuals and short-text Q&A content coexisting. Hybrid retrieval must balance relevance judgment for different lengths of content. The data update frequency is high, so the reranking and retrieval process must adapt to real-time updated Q&A and training content. Role permission explanations and operation steps are the most time-consuming explanation sections. Relevant content must obtain reasonable priority during retrieval to avoid being covered by low-relevance general Q&A entries. At the same time, this category focuses on establishing customers' first-time usage capabilities. Recalled content must accurately match the customer's first-time use question scenarios, avoiding interference from irrelevant information.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `usingReRank` | Enabled | This category contains a large amount of operation step and permission description content. Enabling reranking filters low-relevance general Q&A entries and improves result accuracy |
| `similarity` | 0.65–0.75 | This category has a high proportion of short-text Q&A. A threshold that is too low introduces irrelevant ticket content, while a threshold that is too high misses relevant matching results for permission explanation content. Adjust based on actual testing |
| `limit` | Top 8 entries | Documents in this category have long individual lengths. Too many recalled results exceed the context window. The top 8 entries cover core training and Q&A content |
| `searchMode` | Hybrid Retrieval | This category of data includes structured Q&A lists and unstructured recording video text. Hybrid retrieval balances exact matching and semantic matching, adapting to multiple types of data sources |

## Three Common Mistakes
- Phenomenon: Search results are empty or returned reference snippets are empty. Cause: The `similarity` threshold was not adjusted after enabling `usingReRank`, filtering out low-relevance but actually matching Q&A entries that could have been recalled.
- Phenomenon: No obvious improvement in result relevance after reranking. Cause: Reranking weight was not adjusted based on the permission explanation and operation step content of this category. Only general reranking parameters were used, without matching the category's data characteristics.
- Phenomenon: An error occurs when configuring the local Ollama BGE Reranker V2 M3 model module. Cause: The model path and port were not correctly configured in FastGPT v4.17.0, or the module version does not match platform compatibility requirements.

## How to Confirm the Configuration Is Complete
- Upload a test user manual fragment, enter the corresponding operation question, and check that the recalled results include relevant step content.
- View the platform retrieval log to confirm that `usingReRank` is enabled and the `similarity` threshold is within the set range.
- Test different types of queries, including permission-related and operation-related questions, and check that hybrid retrieval can cover content from multiple data sources.
- Call the test interface to confirm that the number of returned results matches the set value of the `limit` configuration item.

The values provided are common starting points and should be measured against the reader's own samples.
