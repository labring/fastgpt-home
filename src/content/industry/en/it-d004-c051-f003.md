# Customer Data Import and Migration Customer Technical Support and Pre-sales Q&A: Sharing and Embedding

## What this category of data looks like
This category of data typically comes from customer legacy systems, CSV or Excel templates, database exports, and product import logs. Daily associated documents include data templates, migration plans, field mapping tables, and migration verification reports. Data update frequency is adjusted irregularly per individual project. Data fields include business entity identifiers, business attribute values, validation rules, etc. Units are matched to specific business scenarios, with no unified fixed unit. Core time-consuming steps in the processing workflow include field mapping confirmation, dirty data cleaning, and post-import sampling verification. Data anomalies can cause issues such as lost historical data and misaligned fields.

## What constraints these characteristics impose on the sharing and embedding link
Most of this category’s data is structured business data that is updated irregularly alongside project cycles. Therefore, the sharing and embedding link must ensure data permission isolation to prevent leakage of different customers’ data. Documents such as field mapping tables and migration verification reports contain sensitive configuration information, so sharing must restrict edit and export permissions via an external permission system. Data import logs contain operation traces; in embedding scenarios, an external permission system must control log access scope, allowing only authorized personnel to view them. Additionally, single-project data volume fluctuates, so embedded tools must adapt to data import processes of varying scales to avoid loading errors caused by excessive data volume.

## Three common mistakes
- Sharing entries related to customer data import and migration fail to open. First verify the full system-generated link and its validity period, then cross-check browser request statuses; do not manually replace `shareId`.
- The visible scope of customer data import and migration data does not match expectations. Cross-check third-party identity verification results, workflow request parameters, and external system data permissions; the sharing entry identifier itself does not provide business authorization.
- The same customer data import and migration Q&A is not visible on another device. In anonymous scenarios, first verify the device, browser, and local identity status; retention cannot be guaranteed across devices or after cache clearing, and service abnormalities cannot be judged solely based on this phenomenon.

## How to confirm configurations are set correctly
- Access the embedded page, check the export button status for associated business documents, confirm the button does not appear when export is disabled.
- Use an unauthorized domain to access the embedded page, confirm the page fails to load or prompts insufficient permissions (must be verified via an external permission system).
- Use an unauthorized user identity to access the share link, confirm session records cannot be viewed; use an authorized identity to access, confirm import session records for your own project can be viewed (session records rely on local storage, retention cannot be guaranteed across devices or after cache clearing).
- Check the URL parameters of the share link, confirm the `shareId` field is included, and the link validity period matches the project cycle settings.
