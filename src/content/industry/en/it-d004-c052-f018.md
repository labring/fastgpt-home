# Customer Technical Support and Pre-sales Q&A for Customer Permission and Organizational Structure Configuration: Reranking and Hybrid Retrieval

## What This Category's Data Looks Like
Core data for this category comes from customer HR systems, identity directories, product backends, and audit logs. Update frequency is per order or irregular. Daily produced documents include permission matrices, organizational structure tables, role configuration records, and permission change tickets. Data fields include role ID, department hierarchy, permission nodes, change time, and operator information. Each data entry contains both structured fields and non-standardized text descriptions, with an overall semi-structured structure.

## What Constraints These Characteristics Impose on Reranking and Hybrid Retrieval
Multi-source, scattered data sources require hybrid retrieval to connect to both structured permission matrices and unstructured configuration records. This avoids missing cross-system permission association information. Irregular update frequency requires the retrieval pipeline to support incremental synchronization, ensuring returned permission configurations are up to date. Structured field characteristics require the reranking stage to prioritize matching core fields such as department hierarchy and role permissions. Relying solely on basic semantic similarity reduces matching accuracy. At the same time, the high relevance requirement for permission configurations mandates strict filtering of low-match irrelevant results. This avoids distracting technical support staff with redundant information.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `usingReRank` | Enabled | This category of data requires accurate matching of permission hierarchies and role association relationships. Reranking filters low-relevance cross-department and cross-role results, improving retrieval accuracy for technical support scenarios |
| `searchMode` | Hybrid retrieval mode | It is necessary to retrieve both structured permission matrices, organizational structure tables, and unstructured role configuration records and permission change tickets. Hybrid mode covers multi-source heterogeneous category data |
| `similarity` | 0.75–0.85 | Semantic differences in permission configuration text are usually small. An overly high threshold will miss similar permission configuration entries, while an overly low threshold will introduce irrelevant non-permission results. Calibrated based on actual testing |
| `limit` | Top 10 entries | The number of single knowledge base entries for permission configurations is usually limited. Limiting returned entries avoids redundant display, adapting to technical support staff's need to quickly view core configurations |
| Rerank model call timeout threshold | 300 seconds | The retrieval pipeline for permission configuration data requires stable connections. Setting a timeout threshold avoids retrieval failures caused by data volume fluctuations, meeting real-time response requirements for customer technical support |

## Three Common Configuration Mistakes
- Symptom: Returns empty results or no permission-related content after enabling `usingReRank`. Cause: The rerank model call key is not configured, or API permissions for the corresponding model are not bound.
- Symptom: Hybrid retrieval results are not sorted by department hierarchy priority. Cause: No weight configuration for department hierarchy fields is added during the reranking stage, and only basic semantic similarity calculations are used.
- Symptom: Cannot retrieve permission change tickets after setting the `similarity` threshold higher than 0.85. Cause: Text descriptions of permission change tickets usually have subtle format differences. An overly high threshold filters out matching results that meet business requirements.

## How to Confirm Configuration Is Complete
- The knowledge base configuration page of FastGPT v4.17.0 is accessed, and the `usingReRank` switch is verified to be enabled.
- A query including department hierarchy or role names is submitted, and returned results are checked to confirm they first display permission configuration entries matching the department or role.
- The `similarity` threshold is adjusted, changes in the number of returned results are observed, and it is confirmed that threshold adjustments have the expected impact on retrieval results.
- Retrieval logs are viewed, and it is confirmed that hybrid retrieval has called category-specific data sources such as permission matrices and organizational structure tables.
