# Customer Requirement Pool Management for Customer Technical Support and Pre-sales Q&A: Sharing and Embedding

## What this category of data looks like
This category of data comes from ticketing systems, customer interview records, CRM customer profiles, and product roadmap documents. Daily maintained documents include requirement pool lists, requirement evaluation forms, customer feedback records, and version planning descriptions. The data update frequency is usually once per week or synchronized when a product version is released. Each data entry contains fields such as requirement source identifier, associated customer information, priority tag, evaluation cost, and scheduling status. These fields support duplicate requirement merging, value evaluation, and scheduling communication.

## What constraints these characteristics impose on the sharing and embedding workflow
Since data sources are scattered and contain customer sensitive information, the sharing and embedding process must rely on external data source system configurations to filter scope, preventing leakage of cross-customer requirement content. Since update frequencies are fixed, the synchronization cycle of shared content must match the update rhythm of the external requirement pool to avoid displaying outdated requirement information. Since documents include multi-dimensional requirement fields, embedded conversation windows must rely on external business systems to support custom display of specified fields, adapting to pre-sales Q&A and technical support communication scenarios. Additionally, audience language requirements vary across use cases, requiring external business systems to support language configuration independent of the console’s main interface.

## Three common mistakes
- Sharing entry access fails for customer requirement pool management related content. First verify the full system-generated link and its validity period, then check browser request status; do not manually replace `shareId`.
- The visible scope of customer requirement pool management data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately; the sharing entry identifier itself does not provide business authorization.
- The same customer requirement pool management Q&A is not visible on another device. For anonymous scenarios, first check device, browser, and local identity status; retention cannot be guaranteed across devices or after cache clearing, do not use this phenomenon alone to determine service abnormalities.

## How to confirm successful configuration
- Open the language configuration page of the external business system, confirm that the language setting is different from the console’s main interface language, and verify that the language displayed on the sharing link matches.
- Copy the FastGPT basic embedding code to a test page, combine with the external business system’s custom prompt configuration, check if the conversation window displays the preset custom prompt text.
- Log in to the log management page of the external business system, confirm that Q&A records and interaction data for the corresponding sharing link can be viewed.
- Modify a test data entry in the external requirement pool system, wait for the externally configured synchronization cycle, confirm that the content displayed on the sharing link has been updated synchronously.
