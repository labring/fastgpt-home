# Customer Technical Support and Pre-sales Q&A for Capacity Planning and Resource Scaling: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Core data for this category comes from cloud billing, monitoring systems, business forecast reports, and stress test results. Daily deliverables include capacity planning reports, expansion application forms, resource utilization reports, and budget calculation sheets. Data update frequency is typically weekly or monthly. Some high-frequency business scenarios can be adjusted on demand. Document fields include resource type, current utilization, peak threshold, budget amount, and other related items. Common units include cores, GB, yuan/month, and similar units.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
The scattered data sources, fixed update cycles, and large number of document fields in this category impose multiple constraints on multi-turn dialogue and prompt configuration. First, information from different data sources must be linked in the dialogue context to avoid information gaps across stages. Second, the fixed update frequency requires prompts to clearly specify the latest data range of the knowledge base, preventing the use of expired resource utilization or budget data. Third, the diversity of document fields requires prompts to guide users to provide information step by step according to dimensions such as resource type and utilization, reducing invalid input. Finally, the complex process of peak prediction and bottleneck positioning requires multi-turn dialogue to break down problems gradually, avoiding requesting too much information at one time.

## How to Set the Configuration
The following configurations apply to FastGPT v4.17.0:

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the user's exclusive conversation ID | Associate historical capacity planning and resource application data to maintain context consistency |
| `messages` | Retain the last 10 rounds of conversation content | Adapt to the weekly or monthly data update cycle, avoiding interference from expired information on current queries |
| `variables` | Pre-set variables for resource type, current utilization, and budget amount | Match the core fields of documents in this category, reducing repeated user input |
| Maximum context length | 8000–12000 token | Accommodate capacity planning-related information from multi-turn conversations, avoiding truncation of critical data |
| Single search limit | Top 5 results | Control the volume of resource data returned by retrieval, preventing information overload |
| Single request timeout | 600 seconds | Adapt to the retrieval and calculation requirements of large-capacity resource data |

## Three Common Misconfigurations
- Phenomenon: The system prompts that no answer is found when the knowledge base returns image addresses. Cause: The prompt does not configure parsing rules for image content, and only supports matching of text-form knowledge base content.
- Phenomenon: Two conversation requests sent at a short interval cause the subsequent request to wait for the previous request to complete before starting generation. Cause: The concurrency control logic for `chatId` is not configured correctly, leading to serial execution of requests under the same conversation ID.
- Phenomenon: An error prompt "No permission to operate this conversation record" pops up when operating records from a non-current conversation. Cause: The `chatId` is not correctly bound to the user permission identifier, leading to cross-user access to conversation data.

## How to Verify Successful Configuration
- Initiate a multi-turn query that includes resource type and utilization information, and check whether the dialogue context retains the historically input capacity planning-related data.
- Upload image-form knowledge base content, initiate a relevant query, and check whether matching results are returned correctly.
- Initiate two conversation requests at a short interval, and check whether the request execution logic conforms to the configured requirements.
- Attempt to operate records from a non-current conversation, and check whether the permission error prompt pops up to verify that the permission check logic is active.
