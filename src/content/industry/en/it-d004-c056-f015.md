# Customer Technical Support and Pre-sales Q&A for Object Storage and Backup Services: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
Data for this category originates primarily from object storage consoles, backup systems, access logs, and customer policy tables. Updates occur either daily or in real time when storage buckets or backup policies are modified. Daily documents include storage bucket configuration parameters, backup execution policies, recovery operation records, and lifecycle rule entries. Fields cover permission policy entries, backup task status, recovery duration, access request IP addresses, and more. No uniform fixed units exist; specific units vary based on the configuration item type.

## Constraints Imposed on Knowledge Base Retrieval and Recall
Dispersed data sources require retrieval to cover multiple data types, so cross-source associated recall logic must be configured. Differences in update rhythms require distinguishing between full and incremental recall triggers to avoid reloading expired data. Diverse document structures, including parameter entries, policy text, and log records, require adaptation to chunking rules of varying lengths. The presence of permission policy fields means retrieval results must verify access permissions and filter unauthorized content to prevent leaks of sensitive configuration information.

## How to Configure
The following are adapted configurations for FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | Semantic similarity threshold for matching professional documents such as object storage configurations and backup policies, balancing recall precision and coverage |
| `limit` | Top 5–10 entries | Adapts to the context length of single-round technical support scenarios, preventing excessive content from exceeding conversation window limits |
| `searchMode` | Semantic retrieval | Adapts to mixed structured and semi-structured document types such as storage configurations and policy text |
| `usingReRank` | Enabled | Performs secondary sorting on recall results to correct deviations from single semantic matching and improve the display priority of highly relevant content |
| `datasetSearchUsingExtensionQuery` | Enabled | Generates extended query terms based on user questions, covering potential keywords for high-frequency consultation scenarios such as backup task monitoring and recovery sampling |

## Three Common Misconfigurations
- Symptom: FastGPT deployed via Docker fails to upload object storage-related knowledge base files. Cause: Local file directories such as storage bucket configurations and backup logs are not properly mounted, preventing FastGPT from reading target documents.
- Symptom: After creating a knowledge base vector via the API and executing retrieval, server disk or memory usage continues to rise, triggering resource exhaustion on a daily scheduled basis. Cause: Incremental recall is not configured, or chunk size is set improperly, leading to daily full scans of massive amounts of data from backup systems and access logs without sharding processing.
- Symptom: Unauthorized storage bucket permission policy content appears in retrieval results. Cause: Knowledge base permission verification configuration is not enabled, and filtering is not performed by associating with policy table fields from the customer's IT department.

## How to Confirm Proper Configuration
- Upload a storage bucket configuration document, execute a query containing configuration keywords, and confirm that returned results include configuration parameters from the document.
- View retrieval logs to confirm that recalled data sources cover specified sources such as object storage consoles and backup systems, with no omissions.
- Test a query containing permission keywords, and confirm that results only return content compliant with preset permission rules, with no unauthorized entries.
- Adjust the `similarity` parameter range, and verify that the relevance of recall results changes in line with expected adjustment directions.

The values provided are common starting points and should be measured against the reader's own samples.
