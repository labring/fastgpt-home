# Customer Technical Support and Pre-sales Q&A for Advertising Compliance Record-Keeping: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
This category's data supports daily archiving needs for advertising platform compliance teams, agency legal teams, and brand marketing teams. Data sources include advertising platform backends, customer qualification upload systems, contract management systems, and public regulatory rule databases. Core documents processed daily include four types: advertising review forms, qualification attachments, delivery records, and rectification notices. Data is updated per single advertising campaign or on a monthly cycle. Data fields include advertising ID, compliance status, attachment count, campaign cycle, and more. Custom field mapping rules from external systems must be matched.

## Constraints on HTTP Interfaces and External Systems
Data sources for advertising compliance record-keeping are scattered, requiring integration with multiple external systems. HTTP interfaces must support parallel retrieval and consolidation of data from multiple sources. Data is updated per campaign or monthly. Interfaces must support two modes: campaign-triggered synchronization or scheduled synchronization, to adapt to different customers' deployment rhythms. Errors may lead to regulatory inspections, customer liability, or account penalties. Interfaces must include authentication, retry, and data validation capabilities to ensure the integrity and security of archived data. Additionally, this category focuses on preserving audit and delivery evidence, not advertising materials themselves. Interface design must focus on transmitting metadata and attachments, to avoid unnecessary resource usage.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {platform-allocated compliance interface secret}` | Identity authentication when connecting to external systems, meets security storage requirements for advertising compliance data |
| `variables` | `{"source": "ad_platform", "update_trigger": "event"}` | Marks the source and trigger mode of compliance record-keeping data, matches the business rhythm of campaign-based updates |
| `responseData` | `Only return ad_id, compliance_status, attachment_count fields` | Reduces invalid data transmission, speeds up interface response during technical support |
| Interface retry configuration | `2 retries, 5-second interval` | Addresses temporary fluctuations in advertising platform backends, ensures complete archiving of delivery records |
| Access whitelist configuration | `Only allow export IP ranges from advertising platforms and contract systems` | Limits interface access scope, reduces risk of compliance data leaks |

## Three Common Configuration Mistakes
- Symptom: Interface calls return `401 Unauthorized` errors, or the interface prompts authentication failure. Cause: The exclusive secret allocated by the compliance platform is not used, or the `Authorization` parameter format does not meet interface requirements, leading to failed identity verification.
- Symptom: Interface returns database errors like `column vector does not exist`, or structured data storage fails. Cause: Extended initialization of the dedicated compliance record-keeping database was not completed in advance, leading to missing fields that prevent storage of qualification attachment metadata.
- Symptom: `responseData` returns empty fields after a call, or delivery record data is not obtained. Cause: The data source or trigger mode parameters in `variables` are not configured correctly, leading the interface to not match the exclusive data scope of advertising compliance record-keeping.

## How to Verify Proper Configuration
- Call the test interface, pass the preset `Authorization` parameter, check that the return status code is 200 and authentication is successful.
- Pass a test advertising ID, check if `responseData` returns matching compliance status and attachment count fields.
- Simulate a trigger for the end of an advertising campaign, check if the interface completes data synchronization according to the mode configured in `variables`.
- Check the request logs of the external system, confirm that the `variables` parameters match the preset configuration.
