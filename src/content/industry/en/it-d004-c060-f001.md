# Customer Technical Support and Pre-sales Q&A for Ad Account Opening Audit: HTTP Interfaces and External Systems

## What the data for this category looks like
Data for this category typically includes four types of documents: account opening application forms, scanned business license copies, corresponding industry qualification documents, and account opening audit records. Data sources include account application ledgers from ad platform backends, subject verification data from the national enterprise credit information public disclosure system, paper or electronic materials submitted by customers, and industry access rule libraries. Data updates are triggered with each account opening application. Daily summaries generate that day's audit batch records, which include both structured fields and unstructured attachments. ## What constraints do these characteristics impose on the "HTTP Interfaces and External Systems" link
Multi-source data access requires HTTP interfaces to support both structured field queries and unstructured file transfers, to meet the circulation needs of attachments such as business licenses and industry qualifications. Data updates triggered by a single batch application require the interface to support targeted calls bound to a single application ID, avoiding resource usage caused by bulk pulls. Daily summarized audit records require the interface to support pulling batch data by application date range, to meet the synchronization needs of that day's audit ledger. The main qualification verification link takes the longest time, so the interface needs a reasonable timeout threshold configured to prevent process blocking due to delayed responses from external disclosure systems.

## How to configure settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Random 2048-bit string with Bearer prefix | Meets the identity verification requirements of ad platform APIs, prevents unauthorized access |
| `variables` | Bind two core variables: application ID and industry category | Adapts to targeted query needs for single-batch applications, matches the trigger logic of data updates |
| `responseData` | Structured format containing two fields: audit status and correction prompt | Directly corresponds to the core fields of account opening audit records, simplifies information extraction for pre-sales Q&A |
| Timeout setting | 300 seconds | Covers the maximum time required for main qualification verification, adapts to the response pace of external disclosure systems |
| File upload size limit | 100 MB | Meets storage needs for high-definition scanned copies of business licenses and industry qualifications |
| Retry count | 3 times | Addresses temporary fluctuations in external interfaces, reduces the failure rate of single-application audits |

## Three common misconfigurations
- The interface continuously returns connection failure prompts and cannot obtain qualification verification results. Cause: The `Authorization` parameter is not configured correctly, or the interface address does not point to the correct ad platform backend address.
- After calling, `responseData` only returns basic application information and lacks the correction prompt field, so the list of materials requiring correction cannot be displayed in the customer service interface. Cause: The correction prompt field to be returned is not specified in the configuration, so the interface returns simplified data by default.
- The system reports an out-of-memory error. Cause: No file upload size limit is set, and qualification scanned copies over 100 MB are received, exceeding the interface's carrying capacity.

## How to confirm the configuration is correct
- Call the test interface, check that the returned `responseData` includes the three core fields: application ID, audit status, and correction prompt, to verify that the parameter configuration takes effect.
- Upload a test qualification file under 100 MB, confirm that the interface receives it normally and returns an upload success flag, to verify the file size limit configuration.
- Simulate a call for a single application, check that the interface returns results within 300 seconds, to verify that the timeout threshold configuration meets requirements.
- Check the system logs, confirm that the `Authorization` parameter is carried correctly, and there are no unauthorized access error records.
