# Customer Technical Support and Pre-sales Q&A for Ad Account Opening Audit: Knowledge Base Retrieval and Recall

## What the data for this category looks like
The data for this category primarily comes from ad platform backends, the National Enterprise Credit Information Publicity System, customer-submitted account opening application materials, and industry access rule documents. Daily processed documents include account opening application forms, business license scans, industry qualification certificates, and account opening audit records. Data update frequency is daily or synchronized with each account opening application. Document fields include main entity name, affiliated industry category, qualification validity period, audit status, and others. Some are structured forms, while others are unstructured scanned documents.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
Data for this category is scattered across multiple systems and customer-submitted materials. This requires knowledge base retrieval to support cross-data source associated recall, covering content such as ad platform rules and qualification verification standards. Mixed structured and unstructured documents require the retrieval module to adapt to text from different formats and scanned document parsing results. Real-time data updates tied to account opening applications require knowledge base recall indexes to maintain an update frequency synchronized with business operations. Fields focus on main entity qualifications and industry access requirements, so retrieval must accurately match relevant fields to avoid irrelevant results interfering with audit judgments.

## How to set the configurations
This document is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches qualification and rule text related to ad account opening. This range filters low-relevance results while retaining core audit basis |
| `limit` | Top 10 entries | Controls the number of results recalled per query, adapting to the scenario where auditors review quickly and avoiding excessive information interfering with judgments |
| `searchMode` | semantic | Uses semantic retrieval mode, adapting to unstructured qualification documents and rule text to improve accuracy of cross-semantic matching |
| `usingReRank` | Enabled | Re-ranks recalled results, prioritizing content strongly related to account opening qualification verification to reduce misjudgment risks |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands query terms, adding synonyms and rule expressions related to industry access to cover more potential audit basis |
| `collectionIds` | Collection ID corresponding to the ad account opening audit knowledge base | Limits retrieval scope exclusively to the dataset for this category, avoiding irrelevant knowledge base content interfering with audit workflows |

## Three common mistakes
- Phenomenon: Knowledge base API calls return authentication failure or no permission access results. Cause: The exclusive authentication key for the ad account opening audit knowledge base is not used, and a general key is mistakenly used, leading to mismatched permission scope.
- Phenomenon: In locally deployed FastGPT, the number of recalled results from the knowledge base search module cannot be adjusted. Cause: The `limit` parameter is not configured correctly, or other unrelated settings are modified accidentally, causing the parameter to fail to take effect.
- Phenomenon: An error indicating incorrect format is prompted when importing a modified knowledge base CSV file. Cause: The field order and format are not adjusted according to the CSV template for the corresponding FastGPT version, so the system cannot recognize document metadata related to account opening audits.

## How to confirm the configuration is complete
- Run a typical query related to account opening audits, such as "What qualifications are required for game industry account opening", check the relevance and quantity of returned results, and adjust the `similarity` and `limit` parameters to match business requirements.
- View the knowledge base retrieval log to confirm that data is only recalled from the specified `collectionIds` collection, with no irrelevant knowledge base content returned.
- Compare the result ranking when `usingReRank` is enabled versus disabled, to confirm that the re-ranking function works correctly and prioritizes displaying core audit basis.
- Initiate a test call using the exclusive authentication key, confirm that knowledge base content related to account opening audits can be obtained normally, with no permission error reported.
