# Customer Technical Support and Pre-sales Q&A for Performance Testing and Capacity Evaluation: Sharing and Embedding

## What data for this category includes
Data sources for performance testing and capacity evaluation include stress testing platforms, APM monitoring tools, database slow logs, and production traffic baselines. Data update frequency is typically monthly or with each major version. Daily produced documents include stress testing plans, capacity evaluation reports, stress testing data records, and optimization suggestion sheets. Data fields include peak concurrent count, average response time, resource utilization, bottleneck indicators, etc. Units are concurrent count, milliseconds, percentage, and standard units for corresponding indicators respectively.

## Constraints imposed by these characteristics on sharing and embedding
The data update cycle for performance testing and capacity evaluation is not fixed and relies on multi-source collection. When sharing and embedding, the update rhythm of documents must be matched to avoid displaying outdated content. Category data includes professional technical indicators. Sharing and embedding must support custom display of core fields to avoid redundant information interfering with customer technical support and pre-sales Q&A. Different customers’ business scenarios have different focus areas for indicators. Embedding configuration must support flexible adjustment of display fields and sorting rules. Multi-source data query takes a long time. Request timeout settings for external calls to shared links must adapt to data loading requirements.

## Three common misconfigurations
- Sharing entry for performance testing and capacity evaluation fails to open. First verify the full system-generated link and its validity period, then check browser request status. Do not manually replace `shareId`.
- The visible scope of performance testing and capacity evaluation data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately. The sharing entry identifier itself does not provide business authorization.
- The same performance testing and capacity evaluation question and answer is not visible on another device. In anonymous scenarios, first check device, browser, and local identity status. Retention is not guaranteed across devices or after cache clearance; do not judge service anomalies solely based on this phenomenon.

## How to confirm configuration is complete
- Copy the shared link or corresponding embedding code generated from the application details - release channel - non-login window, insert it into an external test page, and check if stress testing-related documents and data content are displayed normally.
- Call the shared link generated from the non-login window, pass in test pre-sales questions, and verify that the returned results include stress testing data retrievable in the debug page.
- Modify the stress testing plan document in the external knowledge base, confirm that the external data source has completed updating, then check if the content on the embedded page matches the latest data.
- Simulate requests containing multi-indicator queries, confirm that no timeout errors occur, and that the returned result fields conform to preset custom display rules.
