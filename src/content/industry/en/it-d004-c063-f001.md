# Customer Technical Support and Pre-sales Q&A for Campaign Setup: HTTP APIs and External Systems

## What this category's data looks like
The core data for campaign setup comes from four sources: advertising platforms, user profile databases, budget scheduling tables, and attribution tools. Updates occur daily or when triggered by a single campaign. Daily generated documents include four types of structures: campaign setup outlines, audience targeting rules, budget allocation tables, and conversion tracking configuration items. Fields include targeted audience tags, budget amount thresholds, conversion event codes, and more. Each field must match the format requirements of the corresponding external system.

## What constraints do these characteristics impose on the HTTP API and external systems workflow
Data sources for this category are scattered and have strict format requirements. HTTP APIs must connect to APIs of multiple external system types simultaneously, adapting to different authentication and parameter formats. Data updates occur at a high frequency, so APIs must support high-frequency calls or scheduled synchronization configurations. Core fields must strictly match the business structure of campaign setup, otherwise configuration verification will fail. Additionally, configuration errors before campaign launch can lead to subsequent delivery risks, requiring clear and specific error feedback from the API to facilitate troubleshooting.

## How to configure
The following configurations are based on the specification requirements of FastGPT v4.17.0:

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | `Application API Key (not AI Proxy Admin Token)` | Complies with FastGPT official authentication rules; external calls to application APIs require authentication credentials issued by the application |
| `variables` | `Bind 10-20 core configuration variables` | Matches core fields of campaign setup such as targeting, budget, and conversion tracking, and passes valid business parameters |
| `responseData` | `Return configuration verification results of 200-800 characters` | Carries feedback such as delivery configuration status and error details, adapting to the parsing needs of external systems |
| Request timeout | `30-60 seconds` | Adapts to the average response delay of most advertising platform APIs, avoiding configuration process interruptions due to timeouts |
| Response format | `JSON format` | Compatible with interface specifications of mainstream external advertising systems, simplifying the parsing steps of configuration results |

## Three common mistakes
- API calls return 400 permission denied or request failure errors. Troubleshooting: Check if AI Proxy Admin Token is used as the authentication credential for the application API. External calls to application APIs require authentication credentials issued by the application.
- The configuration results returned by the API lack core fields. Troubleshooting: Check if required parameters for campaign setup are bound in `variables`, ensuring external systems can recognize valid configurations.
- API calls frequently trigger timeouts. Troubleshooting: Check if the request timeout setting is too short and does not adapt to the actual response delay of the advertising platform API.

## How to confirm the configuration is complete
- Call the test API, check that the returned authentication status is normal, and there are no permission-related error messages.
- Pass preset campaign configuration parameters, check that the verification results returned by `responseData` have no format errors or field missing prompts.
- Check the FastGPT server startup logs, confirm there are no verification errors indicating missing `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN`.
- Connect to the external advertising platform API, verify that the passed configuration parameters can be correctly recognized and return valid feedback.
