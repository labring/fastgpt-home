# Customer Technical Support and Pre-Sales Q&A for Interface Integration and Data Docking: Knowledge Base Retrieval and Recall

## What this category of data looks like
Data for this category is generated from interface interaction scenarios between systems. Sources include customer-side system interface definitions, external API documentation, integration test data, and operation logs. Daily produced documents include interface lists, integration records, field mapping tables, and issue tracking sheets. Data update frequency is daily or synchronized per project phase. The data structure primarily uses structured fields, including clear technical identifiers such as interface addresses, request parameters, return codes, and field types. It also includes unstructured integration problem descriptions and troubleshooting records.

## What constraints do these characteristics impose on knowledge base retrieval and recall
These data characteristics create multiple constraints for the retrieval and recall process. First, data sources rely on customer-side interfaces and API documentation. Retrieval must accurately match structured identifiers such as interface fields and exception codes to avoid generalized searches. Second, update frequency is daily or per-phase synchronization. The knowledge base must support regular incremental updates to ensure the latest integration configurations and exception descriptions are included in a timely manner. Third, daily documents primarily consist of interface lists and field mapping tables. Retrieval must balance structured field matching and semantic association of natural language questions. Fourth, the core time-consuming link is aligning field definitions and exception codes. Recalled results must prioritize high-priority interface content to reduce troubleshooting costs.

## How to configure settings
The following configurations are based on the knowledge base retrieval module of FastGPT v4.17.0:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | `0.72–0.88` | Matches the need for precise matching of interface fields and exception codes, filtering low-relevance non-target content |
| `limit` | `Top 6–12 results` | Matches the volume of associated content per scenario for interface integration issues, avoiding excessive redundant information that disrupts troubleshooting |
| `searchMode` | `Semantic + keyword hybrid` | Balances structured fields in interface documentation and natural language descriptions of integration problems |
| `usingReRank` | `Enabled` | Re-sorts recalled results by relevance to prioritize associated content for core interfaces or high-frequency exceptions |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Automatically expands questions into interface-related synonyms to cover different engineers’ expression habits |
| `collectionIds` | `Specify dedicated integration dataset IDs` | Limits the retrieval scope to exclude irrelevant general knowledge base content |

## Three common configuration mistakes
- A specified error message is returned after triggering retrieval via the knowledge base, and the console shows a parameter verification failure. The cause is that `collectionIds` was not configured correctly, and the parameter for limiting the retrieval scope was not passed in or was entered incorrectly.
- The knowledge base response delay is significant, exceeding the time threshold allowed by the business. The cause is that the `limit` parameter was not restricted and `usingReRank` was not enabled, resulting in the recall of excessive redundant historical integration log data, which increases retrieval and sorting overhead.
- Recalled results include a large number of irrelevant general technical documents and do not match the target interface’s fields or exception codes. The cause is that the `similarity` threshold was set too low, mixing in low-match non-target content.

## How to confirm correct configuration
- Perform a test retrieval for a single interface integration problem, and check whether the recalled results include the corresponding interface’s field mapping and exception code description content.
- View the retrieval time, and adjust the `limit` and `usingReRank` configurations based on the real-time response requirements of the integration scenario.
- Check the relevance ranking of retrieval results to confirm that high-match interface documents are displayed first.
- Initiate a retrieval by simulating an exception scenario, and verify that a troubleshooting guide for the corresponding exception code can be returned quickly.

The values listed are common starting points and should be evaluated against the relevant user’s own samples.
