# Customer Technical Support and Pre-sales Q&A for Search Ad Keyword Management: HTTP Interfaces and External Systems

## What the Data for This Category Looks Like
Data for this category primarily comes from search ad backends, search term reports, bidding ranking data, and landing page data. Daily produced documents include keyword lists, negative keyword tables, bid records, and search term reports. Core fields include keyword text, match type, single bid amount, average daily search volume, conversion paths, and more. Units include yuan, times, characters, and others. Data updates occur daily or weekly. Synced real-time or periodic data from multiple sources supports core operations such as keyword expansion and negative keyword screening.

## Constraints Imposed on HTTP Interfaces and External Systems
Data for this category comes from multiple sources and has inconsistent formats. HTTP interfaces must support multiple return structures and field validation rules. High-frequency or periodic updated data requires interfaces to use reasonable timeout and retry mechanisms. This avoids keyword adjustment efficiency being impacted by data synchronization delays. Batch import and export of keyword lists, negative keyword tables, and other documents requires interfaces to support specified format file transfer and encoding validation. This prevents garbled text or format errors. Interface errors may directly lead to increased invalid clicks, brand terms being outbid, and other negative outcomes. Complete failure alert and rollback mechanisms must be configured. Independent data for different ad accounts requires interfaces to support dynamic parameter binding. This ensures exclusive data for different customers is not mixed.

## Configuration Settings
| Configuration Item | Recommended Approach | Basis for This Approach |
| ---|---|--- |
| `Authorization` | `Bearer {API_KEY}` | Complies with FastGPT v4.17.0 interface authentication specifications, matches the authentication requirements of search ad backends, and ensures requests are legal and valid |
| Timeout Duration | `600 seconds` | Meets batch data synchronization time requirements for this category, covers transmission time for large keyword lists and search term reports in a single request |
| `responseData` | Extract keyword, bid, and match type fields via field mapping | Core data fields for this category are fixed. Direct extraction reduces subsequent data cleaning steps and improves processing efficiency |
| Encoding Format | `UTF-8` | Matches the default encoding of daily produced CSV documents such as keyword lists and negative keyword tables, prevents garbled text during import |
| Retry Count | `2–3 times` | Addresses temporary request failures caused by network fluctuations, ensures stability of batch data synchronization |
| `variables` | Bind ad account ID and time range parameters | Supports filtering data by different customer accounts and periods, improves interface reusability and targeting |

## Three Common Mistakes
- The error `Host '10.100.3.144' is not allowed to connect` occurs because the IP address or domain name of the target search ad backend has not been added to the interface whitelist, resulting in request interception.
- HTTP requests fail to execute because the `Authorization` parameter is not configured correctly, or the bound API key has insufficient permissions to complete the interface call.
- Garbled text appears when importing CSV files because the `UTF-8` encoding format is not specified. This does not match the encoding rules of locally exported keyword lists and negative keyword tables, leading to abnormal character parsing.

## How to Verify Proper Configuration
- Call the test interface. Returned data includes the `responseData` field as expected, and fields match core category data such as keywords, bids, and match types.
- Initiate a batch data request. The response completes within the set timeout duration, with no timeout errors or connection exception prompts.
- Import a test CSV file. The file parses correctly into formats such as keyword lists and negative keyword tables, with no garbled text or missing fields.
- Check the ad account ID and time range bound to the `variables` parameter. Corresponding cycle search term report data filters correctly.
