# Customer Technical Support and Pre-sales Q&A for Database Cloud Service Operations: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
The business data for database cloud service operations mainly comes from four sources: cloud database consoles, slow logs, monitoring metrics, and ticket systems. Update frequency is daily or after each instance change. Daily produced documents include instance change orders, backup and recovery records, performance diagnosis reports, and parameter adjustment records. Fields include instance ID, backup timestamp, slow SQL execution time (milliseconds), values before and after parameter adjustment, and some documents are associated with multi-tenant identifiers and cloud service boundary configurations.

## What Constraints These Characteristics Impose on the Knowledge Base Retrieval and Recall Link
The multi-source nature of business data requires retrieval to cover documents in different formats, including structured monitoring metrics and unstructured slow SQL analysis text. Fields such as instance ID and tenant identifier have strong business correlation, so retrieval must support filtering by metadata to avoid returning irrelevant results across tenants or instances. The frequent update rhythm of changes requires indexes to be synchronized in real time, ensuring retrieval results include the latest parameter adjustments and backup records. Core time-consuming links such as slow SQL positioning and backup and recovery drills require recall results to accurately match business scenarios and avoid interference from redundant information.

## How to Set the Configurations
This chapter’s configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---|---|--- |
| `similarity` | 0.75–0.85 | Matches the precise retrieval needs of database operation and maintenance scenarios, filtering low-relevance monitoring metrics and backup records |
| `limit` | Top 8 entries | Balances context length and information coverage, adapting to the recall of multiple types of business documents such as instance changes and backup and recovery |
| `searchMode` | Semantic Retrieval | Adapts to semantic matching requirements for unstructured text such as slow SQL analysis and parameter risk assessment |
| `usingReRank` | Enabled | Performs secondary ranking on initial recall results, optimizing the display priority of slow SQL and performance diagnosis results |
| `datasetSearchUsingExtensionQuery` | Enabled | Optimizes user questions in pre-sales Q&A scenarios, converting colloquial queries into retrieval terms that match business documents |
| `collectionIds` | Bind to the dedicated collection for cloud database operations | Only retrieves knowledge base content of this category, avoiding mixing documents from other business segments |

## Three Common Misconfigurations
- Phenomenon: Retrieval results include database instance documents from non-target tenants, or fail to filter content for the specified instance. Cause: Failed to correctly configure `collectionIds` to bind the dedicated business collection, or failed to set filtering rules based on metadata fields such as tenant and instance ID.
- Phenomenon: After enabling internet-connected AI models, the application only retrieves knowledge base content and cannot supplement the latest cloud service announcement information. Cause: The knowledge base retrieval priority was not adjusted, or the cross-source retrieval configuration was not correctly enabled, causing the internet connection function to be overridden by knowledge base retrieval.
- Phenomenon: Retrieval based on collection tags fails to return expected results, or the tag function malfunctions. Cause: Business tags such as instance ID and tenant ID were not correctly added to the knowledge base collection, or the tag filtering logic was configured incorrectly.

## How to Verify Proper Configuration
- Submit a test question that includes a specific instance ID, and check whether the returned results only include documents related to that instance.
- After enabling `usingReRank`, check whether the order of retrieval results conforms to business relevance, such as returning performance diagnosis reports first for slow SQL issues.
- Switch to an unrelated non-database operation and maintenance question, and confirm that retrieval results do not mix knowledge base content from other categories.
- Test the scenario with internet connection enabled, and confirm that when the knowledge base has no corresponding content, the application will trigger internet retrieval.

The values provided are common starting points and should be measured against the reader's own samples.
