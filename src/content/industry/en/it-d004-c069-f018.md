# Customer Technical Support and Pre-sales Q&A for Database Operations: Reranking and Hybrid Retrieval

## What this category of data looks like
Data for this category primarily originates from database monitoring, audit logs, SQL execution plans, and ticketing systems. Daily associated documents include database change orders, slow SQL reports, backup records, and permission application forms. Individual document fields cover instance ID, execution duration, permission level, change time, and additional metrics. Units include milliseconds, count, GB, and others.
Data updates occur daily or are triggered by individual database changes. Overall data is generated from daily operations, changes, and permission actions for database instances. The data structure includes both structured metrics and semi-structured text characteristics.

## Constraints on reranking and hybrid retrieval from these characteristics
Retrieval data for database operation scenarios includes both structured monitoring metrics and semi-structured ticketing text, plus sensitive or high-priority fields such as permission level and execution duration. Hybrid retrieval must first distinguish between different data types to prevent low-relevance content from interfering with core queries.
Data updates are triggered by individual changes, so incremental retrieval logic must be supported. This avoids reloading full historical data and improves efficiency.
Slow SQL reports and permission application forms have significant field differences. The reranking link must support multi-field weight configuration to ensure high-priority content related to problem location and permission verification is returned first.
As data volume grows with the number of database instances, the number of returned entries per retrieval must be limited to control overall response time.

## How to set configurations
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| Similarity Threshold | 0.65–0.75 | Filter low-relevance monitoring logs and non-target ticket content, adapt to field differences in operation and maintenance data |
| Maximum Search Results per Request | Top 10–15 entries | Control the number of returned entries, avoid response timeouts, and match the operation and maintenance need for quick problem location |
| Search Mode | Hybrid Retrieval | Combine vector retrieval and keyword retrieval, adapt to the mixed data characteristics of structured metrics and semi-structured documents |
| Reranking Toggle | Enabled | Reorder initial retrieval results, prioritize displaying high-priority business content such as slow SQL and permission applications |
| Reranking Request Timeout | 30 seconds | Adapt to response times of locally deployed or third-party reranking models, avoid blocking the overall retrieval process |

## Three common configuration errors
- Phenomenon: The reranking model returns empty content, or retrieval results have no matching entries. Cause: The reranking model request address is not configured correctly, or the similarity threshold is set too high, filtering all valid operation and maintenance data.
- Phenomenon: Retrieval responses time out, or page loading stalls. Cause: The maximum search results per request is set too high, and the number of entries participating in reranking is not limited. This leads to a large volume of data entering the reranking process.
- Phenomenon: Core content such as permission application forms and slow SQL reports is not displayed first. Cause: The reranking function is not enabled, or retrieval and reranking weight configurations are not adjusted for the database operation and maintenance scenario.

## How to verify successful configuration
- Access the scenario configuration page of FastGPT v4.17.0. Confirm the reranking toggle is enabled and the search mode is set to hybrid retrieval.
- Submit a test query, for example "View recent slow SQL reports". Check whether the number and order of returned results match expectations.
- View retrieval logs. Confirm the reranking model request was sent normally with no error returns.
- Adjust the similarity threshold to below 0.6. Verify that low-relevance content is filtered correctly.
