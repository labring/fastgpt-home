# Customer Technical Support and Pre-sales Q&A for Data Cleaning and Quality Inspection: Sharing and Embedding

## What Data for This Category Looks Like
Service subjects for this category include data engineers, quality inspectors, and project managers. Daily output documents include cleaning rules, quality inspection sampling sheets, abnormal data lists, and delivery reports. Data sources cover raw datasets, ETL logs, annotation platforms, and sampling results. Update frequency is daily or after each batch of data is delivered. Core daily processing steps include duplicate data identification, outlier handling, and sampling quality inspection. Data quality issues directly lead to unusable delivered data, distorted business metrics, or even customer rejection. The core difference from data collection tasks is that only acquired stock data is processed.

## Constraints Imposed on Sharing and Embedding
Since data for this category updates daily or per batch, and most documents are batch-specific cleaning rules and abnormal data lists, the sharing and embedding workflow must align with the data's update rhythm and unique attributes. If the sharing link validity period is too long, embedded content will fall out of sync with the latest abnormal data lists and cleaning rules. If recall scope is not restricted, irrelevant cross-batch data may be retrieved, which reduces the accuracy of pre-sales Q&A and technical support. Daily documents also include sensitive cleaning rules and delivery reports, so embedding permissions must be strictly controlled to prevent unauthorized access to core data. Data loading relies on stock resources such as ETL logs and sampling results, so the timeout setting for embedding calls must match the actual time required for data loading.

## How to Configure Settings
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| Sharing entry `shareId` | Full system-generated sharing links are copied; manual replacement of the identifier is not permitted | Identifies the sharing entry; data cleaning and quality inspection business records and data permissions must still be handled by external systems |
| Sharing link validity period | Test starting point: 7 days; adjust based on actual testing of data cleaning and quality inspection collaboration cycles and revocation requirements | Verify availability within the set validity period and access behavior after expiration; this value is not an official default or industry statistic |
| QPM | Test starting point: 20 requests per user per minute; adjust based on actual load | Limits the access frequency of a single user; must be verified combined with request logs and actual load |
| Identity verification | When identity permission requirements exist, commercial version capabilities and the uid returned by the third-party identity service are first verified | Holding a sharing link does not equate to having business data permissions; third-party identity and data scope must be verified separately |
| Quoted content display | Display configurations for snippets, full text, and original text are selected based on the sensitivity of data cleaning and quality inspection materials | Check displayed content within authorized data ranges; do not use hidden interfaces as a substitute for data permission control |
| Conversation record verification | Test example: Prepare 10 data cleaning and quality inspection Q&A samples, check on the same browser and another device respectively | Anonymous records rely on browser local identity; retention cannot be guaranteed across devices or after cache clearing |

## Three Common Errors
- Sharing entry for data cleaning and quality inspection fails to open. Full system-generated links and their validity periods are first verified, followed by browser request status checks; manual replacement of `shareId` is not permitted.
- The visible scope of data cleaning and quality inspection data does not match expectations. Third-party identity verification results, workflow request parameters, and external system data permissions are verified separately; the sharing entry identifier itself does not provide business authorization.
- The same data cleaning and quality inspection Q&A is not visible on another device. In anonymous scenarios, device, browser, and local identity status are first checked; retention cannot be guaranteed across devices or after cache clearing, so service abnormalities are not judged solely based on this phenomenon.

## How to Confirm Proper Configuration
- The generated sharing link is copied, opened in an incognito browser, and verified to load associated documents such as cleaning rules and abnormal data lists normally.
- The interface corresponding to the sharing link is called with a test question, and the document sources included in the returned results are verified to match the current project's cleaning and quality inspection data.
- The corresponding external component is embedded into a test web page, a test question containing an image is sent, and image scaling is verified to meet expected behavior.
- The extracted `shareId` is checked to confirm it is the system-generated identifier for the corresponding sharing link, ensuring correct association with the sharing configuration.

The values provided are common starting points and should be measured against the reader's own samples.
