# Customer Technical Support and Pre-sales Q&A for Data Masking: Sharing and Embedding

## What data in this category looks like
Teams source data for this category from databases, data dictionaries, masking tools, and access approval systems. Updates happen per batch or per project. Four core document types generate daily: masking plans, field mapping tables, masking validation reports, and approval records. The field mapping table tracks the link between sensitive fields and masking rules. The masking validation report confirms masking effectiveness. Core data processing steps include sensitive field identification, masking rule configuration, and availability validation. Errors in these steps may cause personal information leaks, data unavailability, or failed compliance audits. The key difference from data cleaning and quality inspection services is that the entire process focuses only on reducing exposure risks for sensitive information.

## What constraints these characteristics impose on the sharing and embedding workflow
Since data updates per project or batch and ties to specific business scenarios, external business systems must link shared and embedded content to the corresponding project’s masking configuration. This prevents mismatched masking rules from cross-project use. Documents such as sensitive field mapping tables contain unmasked original field information. Embedded interfaces must strictly restrict access permissions to block unauthorized parties from obtaining original sensitive data. The multi-data-source feature requires embedded configurations to link to the masking rules of the corresponding data source. External business systems must implement this linking logic; otherwise, masking effectiveness will fail. Additionally, errors in this data have severe consequences. Shared links must include identity verification mechanisms to block unauthorized access to sensitive data. Most users of embedded scenarios are technical support and pre-sales personnel. External business systems must complete interface language adaptation to fit Simplified Chinese usage scenarios and reduce operational barriers.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Sharing entry `shareId` | Copy the full sharing link generated by the system; do not manually replace the identifier | Identifies the sharing entry; data masking processing business records and data permissions still require processing by external systems |
| Sharing link validity period | Test starting point: 7 days; adjust based on actual testing of data masking processing collaboration cycles and revocation requirements | Validates availability during the validity period and access behavior after expiration; this value is not an official default or industry statistic |
| QPM | Test starting point: 20 requests per user per minute; adjust based on actual load | Limits access frequency for a single user; requires validation combined with request logs and actual load |
| Identity verification | When identity permission requirements apply, first verify commercial edition capabilities and the uid returned by third-party identity services | Holding a sharing link does not equal having business data permissions; third-party identity and data scope must be verified separately |
| Referenced content display | Select display configurations for snippets, full text, or original text based on the sensitivity of data masking processing materials | Checks displayed content within authorized data ranges; do not use hidden interfaces as a substitute for data permission controls |
| Conversation record validation | Test example: Prepare 10 data masking processing Q&A samples; check on the same browser and another device respectively | Anonymous records rely on browser local identity; retention cannot be guaranteed across devices or after cache clearance |

## Three common errors
- Sharing entries for data masking processing fail to open. First verify the full system-generated link and its validity period, then check browser request statuses. Do not manually replace `shareId`.
- Visibility range of data masking processing data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately. The sharing entry identifier itself does not provide business authorization.
- The same data masking processing Q&A is not visible on another device. For anonymous scenarios, first verify device, browser, and local identity status. Retention cannot be guaranteed across devices or after cache clearance; do not use this phenomenon alone to judge service anomalies.

## How to confirm configurations are complete
- Copy the generated sharing link and open it in an unlogged browser to check if the identity verification process is triggered.
- Confirm that the external business system has completed language adaptation, or check the basic configuration items of the sharing link to verify that the interface display matches expectations.
- Embed using an external domain site not added to the whitelist, confirm that the page cannot load masked data content, and verify that domain restrictions are in effect.
- View the `shareId` parameter in the sharing link to confirm that it is the system-generated identifier for this non-login sharing link.

The values provided here are common starting points and should be measured against the reader's own samples.
