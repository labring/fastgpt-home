# Customer Technical Support and Pre-sales Q&A for Text Annotation Projects: Sharing and Embedding

## What data for this category looks like
The data for text annotation projects is typically generated from the daily work of annotation teams, NLP algorithm teams, and quality inspectors. Daily documents include annotation specifications, sample packages, quality inspection reports, and problem feedback forms. Data sources include customer corpora, annotation platforms, vocabularies, and quality inspection sampling results. Data updates usually occur daily or after each batch of annotation tasks is completed. Core fields include annotated text, tag boundary descriptions, entity annotation results, and quality inspection scores. No extra non-annotation redundant content is included. Unlike image annotation projects, this category of data focuses on text content related to semantic boundaries, entity recognition, and intent recognition.

## What constraints these characteristics impose on the sharing and embedding link
The characteristics of this category of data directly restrict the configuration logic of the sharing and embedding link. First, data sources are scattered and linked to customer-specific corpora. The scope of shared and embedded content must be limited to prevent unauthorized users from accessing irrelevant or sensitive data. Second, data updates occur frequently. An external business system must set a cache refresh policy to ensure that Q&A content remains consistent with the latest annotation specifications and sample packages. Third, core work revolves around scenarios such as tag boundary explanations and difficult sample arbitration. The content shared and embedded must prioritize these high-value documents to avoid distracting customers with irrelevant information during Q&A. Finally, data errors can lead to model training deviations or delivery delays. Embedding permission controls must be used to ensure the security of data access.

## How to set the configurations
The following configurations and external associated settings apply to the sharing and embedding link for text annotation projects.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Sharing entry `shareId` | The full share link generated by the system is copied; manual replacement of the identifier is not permitted | Identifies the sharing entry; business records and data permissions for text annotation project services still need to be handled by external systems |
| Share link validity period | A test starting point of 7 days is used; adjust based on the collaboration cycle and revocation requirements of text annotation projects through actual testing | Availability within the validity period and access behavior after expiration are verified; this value is not an official default or industry statistic |
| QPM | A test starting point of 20 requests per user per minute is used; adjust based on actual load | The access frequency of a single user is limited; verification must be performed combined with request logs and actual load |
| Identity verification | When identity permission requirements exist, commercial version capabilities and the uid returned by the third-party identity service are first verified | Holding a share link does not equate to having business data permissions; third-party identity and data scope must be verified separately |
| Referenced content display | Display configurations for reference fragments, full text, and original text are selected based on the sensitivity of text annotation project materials | Displayed content is checked within the authorized data scope; hidden interfaces are not to be used as a substitute for data permission controls |
| Conversation record verification | A test example is used: 10 text annotation project Q&A samples are prepared, and checked in the same browser and another device respectively | Anonymous records rely on browser local identity; retention cannot be guaranteed across devices or after cache clearing |

## Three common mistakes
Sharing entries associated with text annotation projects fail to open. The full system-generated link and its validity period are first verified, followed by cross-checking browser request statuses. Manual replacement of `shareId` is not permitted.
The visible scope of text annotation project data does not match expectations. Third-party identity verification results, workflow request parameters, and external system data permissions are cross-checked separately. The sharing entry identifier itself does not grant business authorization.
The same text annotation project Q&A cannot be viewed on another device. In anonymous scenarios, the device, browser, and local identity status are first verified. Record retention cannot be guaranteed across devices or after cache clearing. Judging service abnormalities solely based on this phenomenon is not permitted.

## How to confirm the configuration is complete
The project's share link is opened, and the visual effect of the embedded window is checked for consistency with the business system's visual style.
The login-free URL of the embedded window is opened using IE browser, and the page is confirmed to load normally without rendering errors.
A request carrying a user identifier is initiated from the external business system, and the returned Q&A content is confirmed to only be associated with documents of the current annotation project.
The external business system is waited on to trigger content updates, then the share link is reopened, and the content is confirmed to have been updated to the latest annotation specifications or sample packages.

The values provided here are common starting points and should be evaluated against the relevant samples for the target deployment.
