# Customer Technical Support and Pre-Sales Q&A for Logging Platforms and Observability: Knowledge Base Retrieval and Recall

## What this category of data looks like
Data for this category primarily comes from logging systems, Trace platforms, Metrics systems, and application SDKs. Routinely maintained documents include logging collection specifications, link tracing instructions, metric dictionaries, and dashboard configuration records.
Data is updated daily or when a new version is released. Most document structures include field definitions, collection rules, troubleshooting workflows, and configuration examples. Fields mostly relate to log levels, Trace IDs, metric names, and threshold ranges. There are no uniform mandatory units, and matching must be done based on specific collection scenarios.

## What constraints do these characteristics impose on knowledge base retrieval and recall
The data characteristics of this category impose multiple constraints on retrieval and recall.
Multi-source data sources require retrieval to support integrated recall of documents across logging, link tracing, and metric systems.
The high-frequency update rhythm requires configuration to adapt to daily or version-level data synchronization, to avoid recalling outdated collection specifications or troubleshooting workflows.
Documents include technical fields and configuration examples, requiring retrieval to accurately match professional keywords such as log levels and Trace IDs.
High-time-consuming link troubleshooting scenarios require recall results to include complete contextual evidence to support efficient fault location.

## How to configure settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.72–0.85` | Match the precision of professional terms for logging and link troubleshooting, avoid overly strict settings that lead to insufficient recall, or overly loose settings that introduce irrelevant content |
| `limit` | `Top 8–12 entries` | Cover the contextual fragments required for a single troubleshooting session, while controlling the context window length |
| `searchMode` | `vector + fulltext` | Balance semantic matching for professional terms and exact recall for keywords, to adapt to retrieval needs for logging fields and link IDs |
| `usingReRank` | `Enabled` | Perform secondary ranking on recalled multi-source documents to improve result relevance in link troubleshooting scenarios |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Automatically expand search terms to cover field aliases and common troubleshooting phrases defined in collection specifications |
| `collectionIds` | `Bind specified collection IDs by business domain` | Isolate logging and observability documents across different business lines to avoid cross-domain recall interference |

## Three common configuration mistakes
- The knowledge base upload status remains in indexing for a long time. Cause: No chunking parameters adapted to logging and observability documents are configured, and large dashboard configuration records or link tracing documents cause excessively long indexing times.
- Embedded images are not displayed correctly when calling the knowledge base. Cause: Image association retrieval configuration is not enabled, or no path parameters for image resources are carried during retrieval, resulting in only text content being returned in responses.
- Retrieval fails due to incorrect variable reference format configuration. Cause: Non-standard variable wrapping formats are used, and the variable reference rules required by FastGPT are not matched, causing the system to fail to parse field variables in collection specifications.

## How to confirm the configuration is correct
- Upload a single logging collection specification document, check whether the indexing completion status updates within a reasonable time, to confirm that the chunking parameters adapt to the document size.
- Initiate a search containing the Trace ID keyword, check whether the recall results include link tracing instructions and corresponding dashboard configuration records, to verify the multi-source document integration function.
- Configure test variable references, initiate a search containing custom fields, confirm that the system can correctly parse and match field definitions in documents.
- Enable the re-ranking function, initiate a search, and compare the result ranking before and after enabling to verify that the re-ranking configuration takes effect.
