# Customer Technical Support and Pre-sales Q&A for Computer Room Inspection and Environmental Monitoring: Knowledge Base Retrieval and Recall

## What this category of data looks like
Data for this category primarily comes from motion environment monitoring systems, access control systems, UPS monitoring equipment, and video inspection terminals. Daily generated documents include inspection records, temperature and humidity operation logs, equipment alarm logs, and duty handover logs. Data update rhythms fall into two categories: real-time and daily. Real-time data includes temperature and humidity readings and alarm trigger status. Daily archived data consists of bulk inspection summary records. Data fields include unique device identifiers, operating parameter values, alarm levels, and collection timestamps. Some parameters have dedicated units: degrees Celsius for temperature and humidity, and percentage for relative humidity.

## Constraints imposed by this category’s characteristics on knowledge base retrieval and recall
This category’s data characteristics impose multiple constraints on the retrieval and recall process. Real-time motion environment and alarm data requires retrieval responses to align with operation and maintenance emergency scenarios, preventing delays that impact abnormal alarm confirmation and handling. Heterogeneous multi-source data includes distinct fields such as unique device identifiers, temperature and humidity parameters, and alarm levels. Unified field mapping rules are necessary to ensure accurate matching of user query intent during retrieval. Inspection records and duty logs have significant differences in document structure, requiring tailored chunking strategies to preserve context integrity. High-priority alarm data must have a higher recall priority than regular inspection records, ensuring core operation and maintenance needs are addressed first. Daily archived bulk inspection data requires regular index updates to avoid returning outdated historical records in retrieval results.

## How to set configurations
These configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the semantic similarity between device parameters, alarm descriptions in computer room inspection scenarios and user queries, balancing recall rate and accuracy |
| `limit` | Top 8 entries | Covers the volume of associated data in a single round of inspection or alarm scenario, avoiding context overload that affects operation and maintenance judgment |
| `usingReRank` | Enabled | Re-ranks recalled inspection and alarm data, prioritizing high-priority alarms and core device parameters |
| `datasetSearchUsingExtensionQuery` | Enabled | Performs semantic expansion on user inspection or alarm queries, adding associated vocabulary such as device models and operation and maintenance terminology |
| `searchMode` | Hybrid retrieval | Combines keyword matching and semantic retrieval, adapting to inspection documents that have both structured parameters and natural language descriptions |
| `collectionIds` | Bind the exclusive dataset ID for computer room inspection | Restrict the retrieval scope to only the knowledge base for computer room inspection and environmental monitoring, avoiding mixing irrelevant documents from other categories |

## Three common errors
- Phenomenon: API interface responses do not include the configured computer room inspection knowledge base content, only returning general Q&A content. Cause: The correct `collectionIds` is not specified in the request parameters, or the knowledge base is not associated with the current conversation application.
- Phenomenon: Retrieval results from the platform test interface and API calls are inconsistent. Cause: Knowledge base index configurations between the test environment and production environment are not synchronized, or the API request does not include correct retrieval parameters.
- Phenomenon: Index parameters cannot be adjusted directly through the retrieval test interface. Cause: Configuration was not completed on the content management page of the corresponding knowledge base, and the retrieval test interface in the current version does not have an independent editing entry.

## How to confirm the configuration is successful
- Access the knowledge base management page, verify whether `collectionIds` is bound to the exclusive dataset for the current computer room inspection.
- Submit a simulated inspection query, such as "Abnormal computer room temperature and humidity", and check whether returned results include temperature and humidity records, alarm logs and other category-specific documents.
- Call the API interface, and compare whether retrieval results from the platform test and the API match.
- View the retrieval log to confirm that configuration parameters such as `similarity` and `usingReRank` have taken effect.
