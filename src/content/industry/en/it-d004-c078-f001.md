# Customer Technical Support and Pre-sales Q&A for Rack Installation and Cabling: HTTP Interfaces and External Systems

## What data for this category looks like
Data for this category primarily comes from DCIM systems, enterprise asset systems, network topology diagrams, and customer service tickets. Daily produced documents include rack installation application forms, rack cabling topology diagrams, port label comparison tables, and on-site construction records. Data is updated synchronously upon completion of each construction order. Fields include rack position number, cable specification, port mapping relationship, construction acceptance status, and other items. Data volume adjusts based on construction scale.

## Constraints imposed by these characteristics in the HTTP Interfaces and External Systems link
Because data sources are scattered and include multiple types of structured documents, HTTP interfaces must support pulling business data in different formats across systems, while adapting to multi-field verification logic. Data updates are performed per single construction order. The synchronization frequency of interfaces must match the construction rhythm to avoid excessive system resource usage from high-frequency calls. Since errors such as incorrect port connections or abnormal heat dissipation directly impact customer business launch, interfaces must perform mandatory verification on core fields including rack position number, cable specification, and port mapping to prevent invalid data from flowing to subsequent links.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Carry a Bearer token with a 7-day validity period | Matches the permission verification cycle of customer tickets and DCIM systems, avoids frequent token refreshes that impact interface calls |
| `variables` | Bind two core business variables: rack position number and port label | Adapts to field mapping requirements of installation application forms and cabling diagrams, reduces hardcoded configurations |
| `responseData` | Return only two core fields: rack position status and port mapping results | Reduces interface response payload size, adapts to low-bandwidth on-site calls during construction scenarios |
| Timeout period | Set to 300 seconds | Matches the average operation duration of rack installation construction, avoids interrupted calls mid-process |
| Retry count | Set to 2 times | Addresses single call failures caused by on-site network fluctuations, does not increase ticket processing delay |

## Three common mistakes
- 404 Invalid URL (POST /api/rack/deploy) returned when calling the interface: The cause is mistakenly configuring the internal test address of the DCIM system as the production call address, which cannot match the legitimate service path of the external system.
- `responseData` returned by the interface lacks the port label field: The cause is failing to bind the corresponding field of the port label table in `variables`, which prevents the external system from transmitting correct business parameters and completing the label verification link.
- External system synchronization function configured previously stops working after upgrading to FastGPT v4.17.0: The cause is an adjustment to the verification rules for `Authorization` tokens after the version update, failing to regenerate tokens that comply with the new rules, resulting in interface authentication failure.

## How to confirm configuration is complete
- Call the configured HTTP interface, pass test installation application form parameters, and check if the returned `responseData` includes the expected rack position number and port mapping fields.
- View the access logs of the external system, confirm that the `Authorization` token verification for interface calls passes, with no authentication failure errors.
- Simulate a complete construction process, trigger interface data synchronization, and check if the DCIM system receives correct construction record data.
- Adjust the interface call frequency to no more than 1 time per construction cycle, verify that no frequent errors or rate limiting triggers occur.
