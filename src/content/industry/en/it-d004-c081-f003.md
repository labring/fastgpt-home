# Customer Technical Support and Pre-Sales Q&A for Penetration Testing Services: Sharing and Embedding

## What this type of data looks like
Penetration testing service data primarily originates from target system scan results, public vulnerability databases, manual verification records, and scanner outputs. Daily deliverable documents include test authorization letters, penetration test reports, vulnerability reproduction records, and rectification suggestions. Each document typically includes fields such as authorization scope, vulnerability ID, risk level, reproduction steps, and repair solutions. Data updates are synchronized per project or major version iteration. Data within a single project cycle updates dynamically as testing proceeds.

## What constraints these characteristics impose on the sharing and embedding workflow
Penetration testing service data characteristics create multiple constraints for sharing and embedding workflows.
Data contains sensitive authorization scope and undisclosed vulnerability details, so sharing links must rely on access permission controls configured via FastGPT's no-login window, or integrate with external third-party permission systems.
Project-specific data updates dynamically as testing progresses. Embedded content must sync with external systems per project cycles to avoid displaying outdated test results.
Document structures vary significantly across different projects. Embedded content must retain the original field display logic from external systems. FastGPT sharing links only provide basic content hosting, and cannot enforce uniform formatting.
Data also involves business interruption and legal authorization risks. Embedding scenarios typically restrict unauthorized external calls.

## Three Common Misconfigurations
- Sharing entry links for penetration testing services fail to open. First verify the full system-generated link and its validity period, then check browser request statuses. Do not manually replace `shareId`.
- The visible scope of penetration testing service data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately. The sharing entry identifier itself does not provide business authorization.
- Original conversation content for a penetration testing service Q&A is not visible on another device. For anonymous scenarios, first check device, browser, and local identity status. Record retention cannot be guaranteed across devices or after cache clearance. Do not use this phenomenon alone to judge service anomalies.

## How to Confirm Proper Configuration
- Access an unauthorized embedded link, confirm that a permission intercept prompt is returned.
- Trigger an AI reply, click the referenced content, confirm that the original test document is accessible via the linked content.
- Wait for the share link to expire, then access it, confirm that data cannot be loaded normally.
- Use the corresponding share link to access, confirm that only matching project test data is displayed.
