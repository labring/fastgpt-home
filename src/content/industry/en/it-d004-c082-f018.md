# Customer Technical Support and Pre-sales Q&A for Channel Attribution and Lead Distribution: Reranking and Hybrid Retrieval

## What the Data for This Category Looks Like
The core business data for this category comes from advertising platforms, customer relationship management systems, attribution SDKs, and user form submission systems. Daily maintained documents include standardized attribution rule documents, daily updated lead distribution tables, channel effect reports, and abnormal lead checklists. Data fields include channel identifiers, lead unique IDs, conversion timestamps, assigned sales accounts, budget consumption amounts, and more. Update frequencies are mostly daily or weekly.

## What Constraints These Characteristics Impose on Reranking and Hybrid Retrieval
Multi-source data access requires hybrid retrieval to support field integration across advertising platforms, CRM systems, and attribution SDKs. Recall logic adapted to multiple data sources must be configured. Document structures include text rules, tabular reports, and structured forms. The reranking link must support input content in different formats. Data update frequency is daily or weekly. Retrieval indexes must sync with the update rhythm to avoid returning outdated attribution rules or lead data. Fields are closely linked. Reranking weights must be adjusted based on the business priority of fields such as channel identifiers and conversion times, to avoid irrelevant leads being included in the result set.

## Three Common Mistakes
- Symptom: After the rerank model is deployed, it can pass independent tests, but the rerank mark in retrieval results is false, and the returned results are not sorted by reranking. Cause: The call configuration for the rerank model is not associated with the current retrieval task, or the rerank switch is not enabled correctly.
- Symptom: When the length of knowledge base retrieval content exceeds the threshold, the rerank model is not automatically called. Cause: The rerank trigger length threshold is set too low, and the threshold parameter is not adjusted for long-text attribution rules and channel reports in this category.
- Symptom: The rerank model cannot function normally in large model dialogue scenarios, but runs normally in separate knowledge base tests. Cause: The rerank switch is not enabled in the retrieval configuration for large model dialogues, or the retrieval scope does not cover the core data sources of this category.
