# Customer Technical Support and Pre-sales Q&A for Game Client Performance Optimization: Sharing and Embedding

## What Data for This Category Looks Like
Data for this category originates from engine Profiler tools, crash reporting platforms, real-device test queues, and frame rate collection systems. Updates are released daily or per software version cycle.
Daily deliverables include performance test reports, device compatibility lists, optimization iteration logs, and crash analysis records.
Data fields cover frame rate fluctuation ranges, peak resource usage, package size increments, loading duration, crash trigger counts, and similar metrics. Units include fps, MB, seconds, counts, and others.
No fixed unified format exists. Configurations are adjusted based on the specific test scenario.

## Constraints for the Sharing and Embedding Workflow
This category’s data updates frequently and lacks a unified format. External business systems must support incremental synchronization and custom parsing rules to avoid passing outdated or incorrectly formatted performance data. The FastGPT sharing component only handles content transmission.
Additionally, the data includes scenario-specific real-device test information. The Q&A component must connect to external systems to bind specified document sets and scenario tags. The FastGPT sharing component only supports receiving associated parameters passed from external systems to accurately link performance data for specific device models.
