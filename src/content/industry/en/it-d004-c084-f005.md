# Customer Technical Support and Pre-sales Q&A for Game Client Performance Optimization: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Business data for game client performance optimization typically comes from engine Profiler tools, crash analysis platforms, real-device test records, and frame rate collection systems. Daily maintenance documents include performance test reports, device adaptation lists, version optimization records, and crash log archives. Data updates occur daily or per version release cycle. Core fields include frame rate (fps), memory usage (MB), resource loading duration (seconds), device model, and crash stack information. Multiple associated dimensions exist across data types. Analysis must combine device model and scene trigger conditions.

## Constraints for Multi-turn Dialogue and Prompt Engineering
Fast data updates and multiple data dimensions require limiting the context window of multi-turn dialogue to a reasonable range. This prevents interference from outdated or non-current version performance data during analysis. Documents are scattered across types, so prompts must guide the model to prioritize extracting core fields from the current conversation. These fields include device model, jank scenarios, and corresponding performance metrics. Low-end device reproduction and resource analysis take a long time. Set sufficient dialogue timeout to prevent mid-session interruptions. Performance thresholds vary widely across different device models. Inject dedicated business data via variables to avoid generating generalized optimization suggestions.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind unique identifier for player device and session | Ensure multi-turn dialogue context is linked to the corresponding player's problem scenario, avoiding session confusion |
| `messages` | Retain the most recent 20 rounds of dialogue content | Cover the full interaction from the player's problem description to supplementary test details, while avoiding context overload |
| `variables` | Inject device model parameters, frame rate thresholds, and crash log templates | Enable the model to generate targeted recommendations based on game client-specific business data |
| Maximum context window | 8000 token | Adapt to the text length of performance reports and logs, preventing truncation of critical analysis information |
| Dialogue timeout | 300 seconds | Cover waiting requirements for time-consuming processes such as low-end device reproduction and resource usage analysis |
