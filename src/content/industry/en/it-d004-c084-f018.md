# Customer Technical Support and Pre-sales Q&A for Game Client Performance Optimization: Reranking and Hybrid Retrieval

## What This Category of Data Looks Like
Data for this category typically originates from engine Profiler, crash analysis platforms, real-device test clusters, and frame rate collection tools. Daily output documents include performance test reports, device compatibility lists, optimization iteration records, and crash root cause analysis reports.
Data updates follow a daily sync schedule or full update prior to each version release. Core fields include frame rate values, resource loading latency, crash stack information, and device compatibility tags. Fields and units adjust dynamically based on test scenarios, with no fixed unified format.

## Constraints on Reranking and Hybrid Retrieval Imposed by These Data Characteristics
First, data sources cover structured frame rate data, unstructured crash analysis reports, and device compatibility lists. Hybrid retrieval must support unified recall of multi-source heterogeneous data to avoid missing key information.
Second, data updates occur daily or per version. The retrieval system must support incremental synchronization mechanisms to ensure technical support accesses the latest optimization records and test results.
Additionally, core fields have no fixed unified format. The reranking link requires configurable field weight rules, such as separate adjustment of relevance weight for frame rate values.
Queries in technical support scenarios often target performance issues on specific devices. Retrieval must prioritize recalling compatibility data for matching devices to improve matching accuracy.

## Three Common Misconfigurations
- Symptom: Reranking-related fields in conversation details are empty or show an unconfigured status. Cause: The reranking toggle was not enabled in system configurations, or configuration parameters were not properly synced to service nodes. This corresponds to a common reranking configuration error.
- Symptom: Retrieval results only return a single highest-similarity entry. Cause: The reranking recall count was set to 1, which does not align with the need for referencing multiple solutions in technical support scenarios.
- Symptom: The reranking link does not filter low-relevance data as expected. Cause: The similarity threshold was set too high or too low, and does not match the document field characteristics of this category.

## How to Verify Configurations Are Correct
- Navigate to the FastGPT knowledge base configuration page, confirm that the reranking toggle is enabled and the retrieval mode is set to hybrid retrieval.
- Submit a test query, such as "How to optimize frame rate lag on a specific device", check if the number of retrieved results matches the configured single recall limit.
- View the retrieval log in the conversation details, confirm that the reranking link has executed and results are sorted by relevance.
- Adjust the similarity threshold and submit another test, confirm that the relevance of retrieval results changes accordingly.
