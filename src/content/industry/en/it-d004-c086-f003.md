# Customer Technical Support and Pre-sales Q&A for Game Publication License and Publishing Declaration: Sharing and Embedding

## What the data for this category looks like
Data for this category is generated around the publishing declaration process for a single game. Daily documents include four core types: declaration request files, game application forms, copyright certificates, and review reports.
Data sources include the National Press and Publication Administration’s service platform, copyright registration system, game package files, and qualification materials submitted by operating institutions.
The update cycle aligns with each game’s declaration period, with no fixed unified update frequency.
Data fields cover declaration subject information, game content descriptions, copyright numbers, review opinions, and other relevant details. All content must strictly match official service requirements.

## What constraints these characteristics impose on the "Sharing and Embedding" link
Declaration materials for this category must strictly match official requirements. Each game’s declaration data is independent and exclusive. As a result, the sharing and embedding link must meet three constraints.
First, share links only identify access entrances. Exclusive declaration data for a single game is managed by the corresponding external knowledge base configuration. Cross-project call avoidance is implemented through external knowledge base permission configuration.
Second, declaration document structures are fixed and must accurately correspond to approval stages. The knowledge base must be configured with filtering rules based on declaration stages to reduce irrelevant information interference. The sharing and embedding link is only responsible for passing entrance parameters.
Third, errors in the declaration process have serious consequences. Embedded interactions must ensure accurate data calls and traceable returned content. The setup must also support rapid troubleshooting of abnormal situations.

## Three Common Mistakes
- Failure to open the share entrance related to game publication license and publishing declaration. First verify the complete system-generated link and its validity period, then check the browser request status. Do not manually replace `shareId`.
- Mismatch between the visible range of game publication license and publishing declaration data and expected results. Verify the third-party identity verification result, workflow request parameters, and external system data permissions separately. The share entrance identifier itself does not provide business authorization.
- Inability to view original conversations for the same game publication license and publishing declaration Q&A on another device. For anonymous scenarios, first check the device, browser, and local identity status. Retention is not guaranteed across devices or after cache clearing. Do not use this phenomenon alone to judge service abnormalities.

## How to Confirm Proper Configuration
- Verify the link name and complete URL recorded in the release channel. The name is only used for management records. The title and business identifier of the externally embedded page must be verified separately on the external page.
- Call the share link corresponding to `shareId`, confirm that only the knowledge base content for the current game declaration project is displayed, with no cross-project data mixed in.
- Submit a test question, check whether the external business system can normally receive and process interaction data. Data consistency must be verified through the business system.
- Simulate an abnormal timeout scenario, check whether the external business system can normally trigger the exception handling process. Call records are retained by the corresponding business system.
