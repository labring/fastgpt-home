# Client Technical Support and Pre-sales Q&A for Game License and Publication Declaration: Multi-turn Dialogue and Prompts

## What data for this category looks like
This category’s data primarily comes from the National Press and Publication Administration’s service platform, copyright registration documents, game package materials, and filing materials submitted by operating institutions. Data updates follow an irregular schedule based on individual game declaration workflows. The core documents processed daily include four types: declaration request files, game application forms, copyright certificates, and review reports. The entities associated with the data are publishing units, game distribution legal staff, and project managers. All content is generated around the full publication declaration process for a single game.

## What constraints do these characteristics impose on multi-turn dialogue and prompt configuration
The data characteristics of this category impose clear constraints on multi-turn dialogue and prompt configuration. First, declaration data for a single game is updated independently according to workflow. Multi-turn dialogue must bind the unique identifier of a single game via `chatId` to avoid cross-project context confusion. Second, core documents are mostly structured declaration materials. `messages` must fully retain the historical records of each round of verification to prevent loss of key material information. In addition, data sources are scattered and have varying formats. Prompts must guide the dialogue system to accurately extract exclusive fields from different documents, such as copyright certificate numbers, review report modification opinions, and other relevant fields, to ensure multi-turn dialogue content aligns with declaration requirements.

## How to set configurations
The following configurations are written for FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Session ID Binding | Bind the unique identifier of a single game | Based on the characteristic that declaration work is managed independently for each game, to avoid cross-game context confusion, corresponding to the `chatId` configuration |
| Context Window Length | 8000–12000 characters | Covers the multi-turn dialogue content of the full declaration process for a single game, matching the total length range of daily declaration documents |
| Variable Binding | Bind core fields of the current declaration project | Ensure that `variables` transmits exclusive information such as game name and declaration phase, improving dialogue accuracy |
| Single Search Limit | Top 3 matching results | Based on the uniqueness requirement of declaration materials, to avoid redundant results interfering with material verification work |
| Timeout Threshold | 60 seconds | Matches the response rhythm of declaration business, avoiding excessively long waits that reduce communication efficiency |
| Question Optimization Switch | Enabled | Adapt to possible ambiguity in user expressions during multi-turn dialogue, improving knowledge base recall accuracy after optimization |

## Three common configuration mistakes
- Line breaks in dialogue responses cause JSON request failures: The phenomenon is an `Unexpected end of JSON input` error returned by the interface. The cause is failure to escape line breaks in dialogue response content, and non-compliance with JSON format specifications.
- Uploading declaration files triggers errors but text dialogue operates normally: The phenomenon is a system error during the file upload stage, with no abnormalities in text input. The cause is failure to configure parsing rules adapted to declaration file formats, or failure to set a reasonable file size threshold.
- Slow multi-turn dialogue response speed: The phenomenon is a dialogue interval exceeding 10 seconds. The cause is failure to limit the number of results retrieved from the knowledge base in a single run, or failure to optimize the context window loading logic.

## How to confirm configurations are correctly set
- Initiate a multi-round verification dialogue for a single game. Check that the session ID is bound to the unique identifier of that game, ensuring the context does not mix with other declaration projects.
- Input a declaration text fragment containing line breaks. Confirm that the interface request does not trigger a JSON format error, and the returned content is parsed normally.
- Upload a single declaration document. Confirm that the file can be parsed normally and associated with the current dialogue context, with no error prompts.
- Initiate three consecutive rounds of material verification requests. Check that the response speed meets the preset threshold, with no obvious delays.
