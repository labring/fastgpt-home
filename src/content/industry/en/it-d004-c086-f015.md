# Customer Technical Support and Pre-Sales Q&A for Game License and Publication Declaration: Knowledge Base Retrieval and Recall

## Data Profile for This Category
Core data for this category comes from daily declaration materials of publishing units, game distribution legal teams, and project leads. It includes four document types: declaration request files, game application forms, copyright certificates, and review reports.
Data sources include official government service platforms, copyright registration systems, game packages, and operator materials. Update frequency is irregular, aligned with the declaration progress of individual games. Each game has a dedicated set of declaration materials.
Documents exist in two formats: structured tables and unstructured reports. Fields include declaration subject information, game qualification information, and audit status flags. There is no universal template, so retrieval must match individual projects.

## Constraints on Knowledge Base Retrieval and Recall
Dispersed data sources require retrieval systems to sync across multiple platforms and adapt to different document formats.
Irregular updates require retrieval systems to support incremental synchronization and periodic validation, to avoid recalling expired declaration materials.
Diverse document formats require support for both structured table field matching and unstructured report semantic retrieval.
Dedicated materials per game require retrieval systems to narrow scope using declaration subject or game name, preventing cross-project document confusion.
Material consistency verification requires retrieval results to meet a high relevance standard, ensuring returned content directly aligns with current declaration needs.

## Configuration Recommendations
This configuration applies to FastGPT v4.17.0, adapted for game license and publication declaration scenarios:

| Config Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the high density of specialized terminology in declaration materials, filters irrelevant general documents, ensures recalled content aligns closely with current declaration needs |
| `limit` | Top 10 entries | Controls the number of single-recall results, avoids context overload, matches the volume characteristics of individual game declaration materials |
| `usingReRank` | Enabled | Performs secondary ranking on initial recall results, optimizes ranking of specialized documents, improves efficiency of material verification |
| `collectionIds` | Configured by declaration project group | Restricts retrieval scope to only the knowledge base set for the current project, avoids cross-project document interference |
| `datasetSearchUsingExtensionQuery` | Enabled | Performs semantic expansion on user queries, adapts to specialized terminology related to declarations, expands recall coverage |

## Three Common Misconfigurations
- When reference variables are filled in the `collectionIds` configuration, retrieval returns "invalid parameter" or "no matching results" errors. The cause is incorrect binding of the variable context scope, so the retrieval process cannot obtain valid knowledge base set identifiers.
- After importing an Excel-formatted table dataset, retrieval cannot match the field correspondence in the table, and returned results do not include declaration information from the table. The cause is failure to enable structured data field matching mode, or incorrect association between retrieval fields and business declaration fields during import.
- Initial recall results contain a large number of non-specialized general documents, and professional review reports rank low, failing to meet material consistency verification requirements. The cause is failure to enable the `usingReRank` configuration, or setting the `similarity` threshold too high, causing relevant specialized documents to be missed.

## How to Verify Successful Configuration
- Submit a test query that includes a specific game name and declaration material keywords, check if returned results only include dedicated documents for the current project, with no cross-project irrelevant content.
- Import a test Excel declaration table, verify that retrieval can correctly match field information in the table and return corresponding structured declaration content.
- Check retrieval logs, confirm that the `similarity` score of recalled results falls within the preset range of 0.75–0.85, and the number of returned results does not exceed 10.
- Compare retrieval result rankings before and after enabling `usingReRank`, confirm that the ranking of specialized documents is optimized to meet business verification needs.

The values provided are common starting points and should be measured against the user's own samples.
