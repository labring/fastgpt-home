# Customer Technical Support and Pre-sales Q&A for Game Design and Numeric Design: Multi-turn Dialogue and Prompts

## What data for this category looks like
Daily documents for this category include gameplay design docs, numeric tables, version requirement sheets, and balance test records. Data sources include player behavior data, public competitor materials, battle logs, and version feedback. Data updates occur weekly or per version cycle. Document fields mostly cover numeric parameters such as damage coefficients, growth curve slope, retention thresholds, and more. Units include percentage, seconds, damage points and other specialized game numeric units. Field rules vary across different projects.

## What constraints these characteristics impose on multi-turn dialogue and prompts
Gameplay design docs and numeric tables have high structural complexity but tightly linked fields. Multi-turn dialogue must retain cross-field contextual associations to avoid losing numeric linkage logic when split. Data updates happen frequently, so prompts need to adapt to rapidly iterated version requirements, and support dynamic loading of the latest version requirement sheets and balance test records. Numeric parameters have strict precision requirements: the context length of multi-turn dialogue must be limited to a range that can carry accurate numeric transmission, while avoiding numeric calculation deviations caused by overly long contexts. The unstructured nature of player behavior data and battle logs requires prompts to support automatic extraction of structured information, adapting to the need for breaking down gameplay rules during pre-sales Q&A.

## How to set configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the exclusive ID of the game project | Distinguish contextual data across different game projects, avoid confusion of numeric logic across projects |
| `messages` | Retain the most recent 5–7 turns of dialogue + 2 version fragments of numeric documents | Match the multi-turn derivation needs of numeric simulation and rule breakdown, while controlling the computational overhead of single-turn dialogue |
| `variables` | Inject the current version's damage coefficients, growth curve parameters | Ensure that the numeric values used in pre-sales Q&A and technical support are consistent with the latest version |
| Maximum context length | 8000–12000 token | Adapt to the content volume of game numeric documents, avoid truncating critical numeric logic |
| Prompt template update frequency | Update once per version | Match the data update rhythm of the category, ensure prompts adapt to the latest version requirements |

## Three common misconfigurations
- Phenomenon: When calling an API to initiate a dialogue or workflow, logs show the token field is incorrectly populated with the fixed value `fastgpt`. Cause: The exclusive project token parameter in `variables` is not correctly bound, resulting in incorrect authentication information not being passed during the call.
- Phenomenon: When accessing the same project ID multiple times, context turns become chaotic, and prior numeric logic is overwritten. Cause: The project exclusive identifier is not correctly bound using `chatId`, causing different requests to share contextual data and triggering numeric derivation conflicts.
- Phenomenon: Numeric calculation deviations occur during multi-turn dialogue, and results do not match the numeric tables of the current version. Cause: The latest `variables` parameters are not dynamically injected, and derivation uses outdated numeric configurations.

## How to confirm the configuration is correct
- Initiate a test dialogue using the project-exclusive `chatId`, check if the context only retains the historical dialogue data of this project.
- Inject test `variables` parameters, initiate a numeric simulation request, verify if returned results match the preset numeric logic.
- Trigger a workflow call, check if logs carry the correct project-exclusive token, with no abnormal fields filled with fixed values.
- View prompt template update records, confirm the template has been synchronized to the requirements of the current version's version requirement sheet.
