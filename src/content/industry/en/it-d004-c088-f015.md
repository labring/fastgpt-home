# Customer Technical Support and Pre-sales Q&A for Game Operation Activity Configuration: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Daily documents for this category include activity plans, reward configuration tables, launch checklists, and activity review materials. Data sources are game operation backends, player segmentation systems, paid data reports, and activity operation logs. Update rhythms are mostly weekly adjustments or temporary changes before holiday events. Reward configuration tables include fields such as activity ID, reward prop ID, distribution threshold, effective time period, etc. Units involve prop counts, distribution duration, calendar days, etc.

## What Constraints Do These Characteristics Impose on the Knowledge Base Retrieval and Recall Link
The data characteristics of this category impose multiple constraints on retrieval and recall. First, data update rhythms are flexible, mostly weekly adjustments or temporary changes before holiday events. Incremental synchronization must be supported to avoid the time cost of fully rebuilding the knowledge base. Second, documents include structured reward configuration tables and unstructured activity plans. Precise matching for both unstructured text and structured fields must be supported. Third, reward value verification is a core time-consuming step, and errors will trigger player complaints and revenue fluctuations. Retrieval and recall results must precisely match key fields such as activity ID and reward props to avoid interference from irrelevant content.

## How to Configure
The following configurations are based on FastGPT v4.17.0, adapted for the game operation activity configuration business scenario:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Match precise fields in reward configuration tables, avoid interference from low-similarity irrelevant activity content |
| `limit` | Top 6 entries | Cover common associated content for single activity inquiries, while controlling context length |
| `searchMode` | Precise matching | Adapt to structured field retrieval needs for reward configuration tables, avoid incorrect associations caused by fuzzy matching |
| `usingReRank` | Enabled | Perform secondary sorting on recall results, improve priority of content related to reward values |
| `datasetSearchUsingExtensionQuery` | Disabled | Activity configuration queries are mostly clear rule-based inquiries, no need to expand query terms to avoid deviating from the topic |
| `collectionIds` | Bind activity-specific knowledge base collections | Limit retrieval scope, avoid recalling irrelevant data across activities |

## Three Common Misconfigurations
- Phenomenon: Retrieval returns all rows of the full reward configuration table, without filtering content related to the currently inquired activity. Cause: The `limit` parameter is not configured, or the number of recalled entries is set too large, and the dedicated knowledge base collection is not limited via `collectionIds`.
- Phenomenon: Responses are not strictly based on knowledge base content, and information outside documents is introduced. Cause: The `similarity` threshold is set too low, irrelevant content is recalled, or `usingReRank` is not enabled for secondary sorting.
- Phenomenon: Cross-activity reward configuration content appears in retrieval results, causing responses to mix up activity rules. Cause: `searchMode` is set to fuzzy matching, or the `similarity` threshold is lower than 0.7, recalling low-similarity non-associated data.

## How to Confirm Configurations Are Properly Set
- Test questions related to current activity reward configurations are submitted, and retrieval results are checked to confirm they only include content within the bound knowledge base collection.
- The value range of the `similarity` parameter is adjusted, the relevance of returned results is verified to meet expectations, and the threshold setting is confirmed to be adapted to current business needs.
- An incremental synchronization operation is triggered, updated activity configuration content is verified to be quickly retrievable, and the synchronization logic is confirmed to be working properly.
- Test questions including structured fields, such as "What is the distribution threshold of props for activity A", are submitted, and retrieval results are verified to precisely hit the configuration content for the corresponding activity.

The values provided are common starting points and should be measured against the reader's own samples.
