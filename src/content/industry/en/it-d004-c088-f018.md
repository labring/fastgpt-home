# Customer Technical Support and Pre-sales Q&A for Game Operation Activity Configuration: Reranking and Hybrid Retrieval

## What this category of data looks like
This type of data primarily comes from game operation backends, player segment tag libraries, paid behavior data, and activity execution logs. Daily produced documents include activity execution plans, reward configuration tables, pre-launch checklists, and activity review reports. Data update cycles are usually weekly or temporary adjustments before holiday events. Document fields include activity time ranges, reward types and quantities, trigger conditions, player tiering rules, and more. Units are mostly specific numerical values or time units. Structural differences across documents are significant, with a mix of structured tables and free-form text.

## What constraints do these characteristics impose on the reranking and hybrid retrieval workflow
Activity configuration data fields are mostly rule-based and numerical. Hybrid retrieval must match both text rules and structured numerical thresholds, so it needs to balance semantic recall and precise field matching capabilities. Weekly or temporarily updated data requires the retrieval pipeline to support near-real-time synchronization, to avoid recalling expired activity configuration content. Activity documents have large structural differences: reward configuration tables are standardized tables, while activity plans are free-form text. The reranking link must adapt to inputs of different formats, and prioritize reward values and time configurations that are strongly relevant to the current consultation question. Additionally, errors in activity configuration can trigger player complaints and revenue fluctuations. The accuracy of retrieval results requires the reranking model to filter low-relevance content, and avoid misleading technical support and pre-sales staff.

## How to set the configurations
These configurations are based on FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches activity configuration rule text with player consultation questions. This range filters irrelevant historical activity configurations while retaining core matching items |
| `limit` | Top 8 entries | Limits the number of initially recalled results, adapts to the single-batch update volume of activity configuration documents, and avoids result overload that affects troubleshooting efficiency |
| `usingReRank` | Enabled | Targets the structured features of reward values and time configurations. Reranking adjusts the priority of results, prioritizing content strongly relevant to the current consultation activity |
| `searchMode` | Hybrid retrieval mode | Covers both free-form text activity plans and structured reward configuration tables, balancing the dual needs of semantic recall and field matching |

## Three common mistakes
-  The interface displays "result reranking unresponsive", and logs return an architecture incompatibility error. Cause: Using a reranking model image adapted for AMD architecture without switching to an ARM-compatible image package.
-  Hybrid retrieval returns fewer than 3 results. Cause: The `limit` parameter is set too low, or the `similarity` threshold is set too high, filtering out a large number of eligible activity configuration contents.
-  Reranked results are irrelevant to the consultation question. Cause: Not adjusting the reranking weight for structured fields, only relying on basic semantic matching, and not prioritizing core content related to reward values and activity time.

## How to confirm the configuration is complete
-  Navigate to the FastGPT retrieval configuration page, confirm that the `usingReRank` toggle is enabled, and `searchMode` is set to hybrid retrieval mode.
-  Enter a typical activity configuration consultation question, check the number of initially recalled results, and confirm it aligns with the `limit` parameter setting logic.
-  Compare the result order before and after reranking, verify that highly relevant activity time and reward configuration items are displayed first.
-  Check whether expired activity configurations are included in the retrieval results, and confirm that the data synchronization link matches the current update frequency requirements.
