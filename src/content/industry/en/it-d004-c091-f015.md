# Customer Technical Support and Pre-sales Q&A for Player Customer Service and Public Opinion Processing: Knowledge Base Retrieval and Recall
This document is written based on FastGPT v4.17.0.

## What this category of data looks like
Data for this category primarily comes from game customer service systems, community forums, app store reviews, and game logs. Daily processed documents include player tickets, compensation application materials, public opinion daily reports, and standardized response scripts. Data updates occur daily or in real time, synced with player feedback and community trends. Each data entry typically includes player account identifiers, feedback content, and processing progress fields. Some public opinion data also includes associated interaction metrics. Overall data is generated across the full workflow of player feedback and operational responses.

## What constraints these characteristics impose on knowledge base retrieval and recall
Dispersed data sources and real-time updates require the retrieval link to support multi-channel data synchronization. It avoids response deviations caused by data lag.
Player tickets and public opinion data contain large amounts of personalized account information and scenario-based rules. Precise matching of keywords and context is needed to avoid generic recall.
Documents such as compensation applications and response scripts have relatively fixed structures. Targeted retrieval by business modules must be supported. Redundancy of recall results must be controlled to prevent excessive irrelevant content from interfering with customer service judgments.
Real-time updated public opinion data requires the retrieval link to have low latency characteristics. It ensures the timeliness of problem responses.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Balances precision and recall coverage. It adapts to the colloquial and personalized question scenarios in player feedback. |
| `limit` | Top 6–8 entries | Controls the number of recall results per round. It avoids excessive content exceeding the information load that customer service can handle. |
| `searchMode` | hybrid | Combines keyword and semantic retrieval. It adapts to content in player tickets that includes both fixed rules and personalized descriptions. |
| `usingReRank` | Enabled | Re-ranks initial recall results. It optimizes the display order of highly relevant content and improves customer service judgment efficiency. |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands synonymous expressions of player questions. It covers different phrasing that players may use and improves recall completeness. |
| `collectionIds` | Configured by business module groups | Targets retrieval of exclusive knowledge base collections for player customer service and public opinion processing. It avoids irrelevant data interfering with retrieval results. |

## Three common errors
- An error related to entry limits occurs when deploying the open-source knowledge base locally. The backend log displays cannot fetch internal url. The root cause is one of two issues: the intranet access whitelist is not configured correctly, or the network policy of the knowledge base synchronization task blocks internal resource requests.
- After creating a Feishu knowledge base via URL, documents in PPT and PDF formats cannot be synchronized. The root cause is one of two issues: the parsing module for the corresponding document format is not enabled, or the resource corresponding to the target URL does not have sufficient access permissions.
- When clicking chunk preview for some PDF files in the knowledge base, a prompt indicates that the file content cannot be read. The root cause is one of three issues: the PDF file is encrypted, the file is a scanned image-based format, or a character encoding exception is triggered during the parsing process.

## How to confirm the configuration is complete
- Submit a simulated player ticket query. Check whether the retrieval results cover the exclusive document content corresponding to the business scenario.
- View the retrieval configuration page. Confirm that switches such as `usingReRank` and `datasetSearchUsingExtensionQuery` are enabled.
- View the data source synchronization logs. Confirm that player data from channels such as customer service systems and community forums has been successfully synchronized to the retrieval collection.
- Check the number of retrieval results returned. Confirm that it matches the quantity range set by the configured `limit` parameter.

The values provided here are common starting points. They should be validated against samples relevant to the specific deployment.
