# Customer Technical Support and Pre-sales Q&A for On-site Deployment Implementation: Sharing and Embedding

## What This Category’s Data Looks Like
This category’s data is primarily collected from customer data center environments, equipment inventories, software packages, and network topologies. Daily associated documents include deployment manuals, installation records, configuration lists, and on-site check-in forms. Data updates occur per order or per implementation phase. Data fields include deployment node IP addresses, software version numbers, configuration parameter values, on-site check-in times, and more. No unified standardized statistical framework exists. Data only updates in sync with on-site implementation progress, and all data ties exclusively to the scenario of the corresponding implementation order.

## Constraints Imposed on "Sharing and Embedding" Workflows
Since data comes from a customer’s exclusive on-site environment, embedded configurations must adapt to the customer’s local network restrictions. Public network generic parameters cannot be used directly. Data updates per implementation phase. Sharing links (including `shareId`) must match the single-phase implementation scenario, and cannot be reused across implementation orders. Most associated documents are on-site operation materials. The embedded Q&A module must associate and call locally deployed document fragments from the corresponding knowledge base. It must also adapt to the high-frequency question bank for on-site environment checks. On-site deployment errors can cause system unavailability. The embedded module must link to an external deployment document system, providing a quick jump entry to reduce on-site troubleshooting costs.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Sharing entry `shareId` | Copy the full sharing link generated by the system; do not manually replace the identifier | Identifies the sharing entry; on-site deployment implementation business records and data permissions still require handling by external systems |
| Sharing link validity period | Test starting point: 7 days; adjust based on actual on-site deployment implementation collaboration cycles and revocation requirements | Verify availability within the validity period and access behavior after expiration; this value is not an official default or industry statistic |

| Conversation record verification | Test example: Prepare 10 on-site deployment implementation Q&A samples, check them on the same browser and another device respectively | Anonymous records rely on browser local identity; retention cannot be guaranteed across devices or after cache clearance |

## Three Common Mistakes
- Sharing entries related to on-site deployment implementation fail to open. First verify the full system-generated link and its validity period, then check browser request statuses; do not manually replace `shareId`.
- The visible scope of on-site deployment implementation data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately; the sharing entry identifier itself does not provide business authorization.
- The same on-site deployment implementation Q&A cannot be viewed on another device. For anonymous scenarios, first check device, browser, and local identity status; retention cannot be guaranteed across devices or after cache clearance, and service abnormalities cannot be judged solely based on this phenomenon.

## How to Confirm Configuration Is Complete
- Copy the generated iframe code and embed it into a local test page, then check if the FastGPT application interface loads normally.
- Simulate common on-site environment check questions, then test if the Q&A module can return corresponding deployment document content.
- Open the browser console, check for any error messages, and confirm that cross-domain and cookie configurations are normal.
- Trigger a simulated deployment abnormality, then check if the module can link to the corresponding entry in the external deployment document system.
