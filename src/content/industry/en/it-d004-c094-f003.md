# Customer Technical Support and Pre-sales Q&A for User Acceptance Testing Support: Sharing and Embedding

## What Data for This Category Looks Like
Data for this category is generated around the full user acceptance testing process. Sources include requirement specification documents, test environment configurations, customer business sample data, and defect tracking system records. Daily produced documents include UAT test cases, acceptance issue tickets, acceptance reports, and signed confirmation forms. Fields cover test scenarios, execution results, defect descriptions, acceptance conclusions, and more. Data is updated once per test phase or version iteration, with updates synchronized alongside business requirement adjustments or defect fixes. Data is tied to actual customer business scenarios, and requires validation aligned with customer business logic. This differs from technical-level validation used in integration testing and interface testing.

## Constraints Imposed by These Characteristics on the Sharing and Embedding Workflow
Data for this category must align with actual customer business scenarios. As such, sharing and embedding configurations must support customizing content by business scenario. Data update frequency is once per phase or version, so external systems must implement data synchronization logic separately. The FastGPT sharing entry only provides access to content at the time of configuration, to avoid using expired data that disrupts acceptance progress. Daily documents include formal files such as signed confirmation forms. Embedded content must ensure access permissions are controlled, and only be available to authorized customer business representatives and implementation teams. Data sources include customer business samples, so language configuration for sharing links must be associated with usage scenarios as needed. FastGPT only provides a configuration entry for language settings, and does not include built-in business scenario association logic. Additionally, issue reproduction data during the acceptance process must be synchronized in real time. Session context is supported by local storage, and is only retained in the same device and browser environment. Retention cannot be guaranteed across devices or after cache clearing. If association with test process context is required, external systems must implement this separately.

## Three Common Misconfigurations
- Sharing entries related to user acceptance testing support fail to open. First verify the full system-generated link and its expiry date, then cross-check browser request statuses; do not manually replace `shareId`.
- Visibility scope of user acceptance testing support data does not match expectations. Cross-check third-party identity verification results, workflow request parameters, and external system data permissions separately; the sharing entry identifier itself does not provide business authorization.
- The same user acceptance testing support Q&A is not visible on another device. For anonymous scenarios, first verify device, browser, and local identity status; retention cannot be guaranteed across devices or after cache clearing, and service anomalies cannot be judged solely based on this phenomenon.

## How to Confirm Configuration Is Complete
- Open the page embedded with FastGPT, check if the chat window loads normally with no error prompts.
- Use authorized identity credentials to test if the sharing link language matches the usage scenario requirements.
- Check if the chat window prompt text is exclusive to UAT testing, with no default generic prompts.
- Verify that embedded pages from different domains can access the chat window normally, and permission configurations take effect.
