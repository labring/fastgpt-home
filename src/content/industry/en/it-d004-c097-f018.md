# Customer Technical Support and Pre-sales Q&A for Community Events and Developer Relations: Reranking and Hybrid Retrieval

## What the data for this category looks like
Typical subjects for this category are DevRel teams, community operations staff, and project maintainers. They regularly create four types of documents: activity plans, speaking scripts, registration lists, and post-activity reviews. Data sources include community forums, registration systems, social media platforms, and project roadmaps. Update frequency follows monthly cycles or each activity cycle. Document fields may include activity topic, speaker information, registration period, feedback evaluations, and other details. There is no unified standardized field structure. Single document lengths vary significantly. This category supports communication, Q&A, and user connection work. It is distinct from community contributor governance tasks.

## What constraints these characteristics impose on reranking and hybrid retrieval
Multi-source, scattered data sources require the retrieval process to integrate diverse content types, including forum Q&A, registration records, and activity scripts. Hybrid retrieval configuration must support cross-data source semantic matching logic. Non-standardized document structures make basic semantic retrieval unable to accurately distinguish priority levels between different documents. The reranking link must adjust sorting weights. Monthly or per-activity update cycles require retrieval indexes to update in line with these cycles, preventing outdated data. The most time-consuming tasks include topic planning, speaker coordination, and feedback organization. These tasks require the retrieval process to quickly locate relevant historical data, boosting work efficiency. Potential negative outcomes include low event turnout, uncollected community issues, and damaged brand reputation. These require retrieval results to accurately match user technical support or pre-sales consultation needs, cutting down redundant content.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.65–0.75 | Matches semantic matching accuracy for multi-source community text, balances recall rate and precision |
| `limit` | Top 10 entries | Matches single-round retrieval volume for community activity data, avoids excessive results interfering with user judgment |
| `searchMode` | Hybrid Retrieval | Integrates multi-source data from community forums, registration systems, and other platforms, covering all scenarios for pre-sales and technical support |
| `usingReRank` | Enabled | Optimizes sorting priority for different document types, elevates the display position of highly relevant content |
| Reranking result filter threshold | Keep top 3 entries | Focuses on core activity-related content, fits the fast, concise consultation needs in community scenarios |

## Three common mistakes
- Phenomenon: Custom reranking channel configuration triggers a call error, with the interface showing service connection failure. Cause: The reranking service input parameters were not adjusted for community activity document formats, causing the service to fail to parse multi-source mixed retrieval content.
- Phenomenon: Hybrid retrieval results include large volumes of irrelevant post-activity review documents, with no way to filter redundant content. Cause: Matching weights were not set for different fields of community documents, causing non-core content to be prioritized for recall.
- Phenomenon: Semantic retrieval results have higher accuracy than hybrid retrieval results. Cause: The reranking link was not enabled. Only basic semantic matching was used, and multi-source associated data from community forums and registration systems was not integrated. Cross-document associated information cannot be supplemented.

## How to confirm the configuration is complete
- Upload one activity plan and one registration list, run a preset pre-sales consultation retrieval, check if the returned results include relevant content from both document types.
- After enabling the reranking function, compare result rankings before and after activation, confirm whether highly relevant activity topic content is moved to a higher position.
- Check the reranking service call logs, confirm there are no errors and the number of returned results matches the configured `limit` value.
- Adjust the `similarity` parameter range, verify whether the matching accuracy of retrieval results meets scene requirements.

The values provided here are common starting points. They should be evaluated against the samples used in the specific deployment.
