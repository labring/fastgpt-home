# Customer Technical Support and Pre-sales Q&A for Community Contributor Governance: Knowledge Base Retrieval and Recall

## What data does this category include
Core data for community contributor governance comes from code repository commit records, community forum discussion posts, contribution statistics reports, and governance meeting minutes.
Daily maintained documents include contribution guidelines, community code of conduct, maintainer lists, and governance meeting minutes.
Data updates follow a monthly or quarterly schedule.
Core fields include contributor identity identifiers, permission levels, rule clause versions, and meeting resolution content.
No fixed statistical values exist. Data updates only occur dynamically as community governance actions take place.

## What constraints do these characteristics impose on knowledge base retrieval and recall
Community contributor governance data has diverse sources. These include structured code repository commit records, unstructured community forum discussions, and semi-structured meeting minutes and contribution statistics. The retrieval system must support multi-format data recall.
Data updates follow a monthly or quarterly schedule. High-frequency incremental synchronization is not required, but fast switching of rule versions must be supported.
Document content focuses on role permissions, governance rules, and contributor promotion processes. Retrieval must accurately match business scenarios to avoid returning irrelevant content. It must also support fine-grained recall related to permissions, ensuring that consultation results for different roles align with their permission scopes.
Unlike general document site retrieval, this scenario focuses on matching between personnel roles and governance rules.

## How to set the configurations
This configuration guide is written for FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Matches professional text such as community governance rules and permission descriptions, balancing recall accuracy and coverage |
| `limit` | `Top 8–12 results` | Community governance document entries are relatively fixed. A small number of precise recall results per query covers common consultation scenarios |
| `searchMode` | `vector` | Most community governance content consists of rules and process text. Vector retrieval better fits semantic matching needs |
| `usingReRank` | `Enabled` | Governance rules use similar phrasing. Reranking improves result sorting accuracy |
| `datasetSearchUsingExtensionQuery` | `Disabled` | Community governance documents do not require additional query expansion. Direct matching of original queries works |
| `collectionIds` | `Specify dedicated community governance knowledge base ID` | Isolates business data to avoid recalling documents from other categories |

## Three common configuration errors
- Symptom: Retrieval for community governance-related documents returns empty results, or all governance documents become unavailable after a period of deployment. Cause: Failed to bind the dedicated knowledge base collection via `collectionIds`, or failed to synchronize governance documents per the monthly update schedule, leading to accidental data overwrites or failed data loading.
- Symptom: Non-governance business documents appear in retrieval results. Cause: Failed to isolate the dedicated knowledge base, leading to recall of document data from other categories.
- Symptom: Sorting of retrieval results related to contributor permissions is chaotic. Cause: `usingReRank` is not enabled, or the `similarity` threshold is set outside the 0.75–0.85 range, leading to insufficient semantic matching accuracy.

## How to confirm correct configuration
- The `collectionIds` configuration item is checked to confirm only the dedicated community governance knowledge base ID is bound.
- A test query using the phrase "contributor promotion process" is run, and all returned results are verified to originate from governance-related documents.
- The `similarity` threshold is adjusted, and the matching accuracy of recall results is verified to meet business requirements.
- After `usingReRank` is enabled, the reranked result sorting is verified to align with business priority ordering.

The values provided in this guide are common starting points. They should be evaluated against the user’s own sample data.
