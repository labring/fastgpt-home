# Customer Technical Support and Pre-sales Q&A for Community Contributor Governance: Reranking and Hybrid Retrieval

## What data for this category looks like
This category of data centers on personnel and rules related to community contributor governance. Daily documents include contribution guidelines, code of conduct, maintainer lists, and governance meeting minutes. Data sources cover contribution submission records from code repositories, discussion content from community forums, contribution statistics reports, and minutes from offline and online governance meetings. Data is updated monthly or quarterly. Some temporary rule adjustments are synced immediately via meeting minutes. Data fields include contributor ID, role permissions, rule clauses, meeting resolution content, and more. There are no unified fixed units, with adjustments made flexibly based on document type.

## What constraints do these characteristics impose on the reranking and hybrid retrieval link
Community contributor governance data has scattered sources, including both structured contribution statistics and permission lists, as well as unstructured meeting minutes and forum discussions. Hybrid retrieval must adapt to text structures of different formats. Overall data update frequency is low, but some temporary rule adjustments require quick synchronization. The reranking link needs to support index adaptation for incremental updates. Most data fields are professional content related to roles and rules, with strong semantic relevance but a large number of industry-specific terms. The reranking model must adapt to terms specific to the community governance scenario. In addition, the data volume is relatively vertical, so the recall range for a single retrieval should not be too large. It is necessary to balance retrieval efficiency and recall accuracy to avoid invalid computing overhead.

## How to set configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Similarity threshold | 0.75–0.85 | Adapt to the professional semantic relevance of community governance documents, and avoid recalling irrelevant rule clauses |
| Single search limit | Top 10 results | Match the volume of vertical community data, control the number of returned results per retrieval to balance efficiency |
| Search mode | Hybrid retrieval | Adapt to mixed-source structured and unstructured data, balancing keyword and semantic recall |
| Rerank toggle | Enabled | Improve the sorting priority of highly relevant results for governance documents dense with professional terms |
| Maximum context length | 8000–12000 token | Adapt to the average length of community governance documents, and avoid exceeding the input limits of reranking models |

## Three common configuration mistakes
- Phenomenon: Retrieval response delay is noticeable, with single call duration exceeding 8 seconds. Cause: No reasonable single search limit is configured. When reranking is enabled, too many initial recall results are processed, increasing computing load.
- Phenomenon: System alerts that video memory usage exceeds the limit when running the reranking link, and the process is forcibly terminated. Cause: Reranking input parameters are not adjusted for the average length of community governance documents. The total text length of a single input exceeds the video memory capacity limit.
- Phenomenon: No configuration entry for the rerank model is found, and the rerank function cannot be enabled. Cause: The search mode is not set to hybrid retrieval, so rerank-related configuration items are not displayed in the interface.

## How to confirm configurations are set correctly
- View the knowledge base retrieval configuration panel, confirm that the rerank toggle is enabled, and the search mode is set to hybrid retrieval.
- Submit a test query related to community governance, check whether the sorting of returned results conforms to rule relevance, and prioritize displaying highly relevant governance rules and permission descriptions.
- View the system monitoring panel, confirm that the video memory usage of the reranking link is within a reasonable range, with no continuous over-limit situations.
- Verify that the retrieval response time meets business expectations, and adjust the single search limit to balance response speed and the number of recalled results.

The values provided are common starting points and should be measured against the reader's own samples.
