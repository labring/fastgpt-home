# Customer Technical Support and Pre-sales Q&A for Mobile Development: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Data related to customer technical support and pre-sales Q&A for mobile development comes primarily from daily work outputs and platform backends of iOS engineers, Android engineers, and cross-platform development teams.
Daily documents include end version release notes, device adaptation lists, crash analysis reports, app store review materials, and similar items.
Data sources cover code repositories, app store backends, crash monitoring platforms, and device coverage statistics platforms.
Updates occur either daily or when a new version is released.
Documents organize by device and version number. They include structured fields such as device version and permission configuration items, plus unstructured content like crash stacks and review material explanations.

## Constraints on knowledge base retrieval and recall
Dispersed data sources and frequent updates require the knowledge base to support multi-platform scheduled synchronization. This blocks retrieval of outdated version information.
Documents organize by device and version. Retrieval filters results using device parameters from the current session. This avoids returning mismatched adaptation content.
Documents include both structured and unstructured content. Retrieval modes balance keyword and vector matching. This covers all types of technical content.
App store material updates align with version release cycles. The knowledge base updates at the same frequency as version releases. This ensures material timeliness during pre-sales Q&A.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Mobile development documents have many technical details. Filter out low-match irrelevant adaptation content |
| `limit` | Top 8 entries | Mobile adaptation items are numerous. Too many retrieval results exceed context window limits |
| `searchMode` | Hybrid vector and keyword retrieval | Balance structured device parameters and unstructured crash log text. Improve recall accuracy |
| `usingReRank` | Enabled | Mobile documents have many similar terms. Rerank to select results most relevant to the current query |
| `datasetSearchUsingExtensionQuery` | Enabled | Add supplementary expanded queries for common developer terms. Cover synonyms and abbreviations used in cross-platform development |
| `collectionIds` | Mobile development exclusive knowledge base ID | Limit retrieval scope. Prevent interference from documents of other categories |

## Three common mistakes
- Symptom: When uploading an adaptation list document larger than 500MB, the FastGPT v4.17.0 interface shows a timeout, but the backend completes the upload. Cause: Administrators do not adjust the large file upload timeout threshold. The default timeout duration cannot cover parsing and uploading large documents.
- Symptom: After importing a crash analysis report, the knowledge base shows as ready but no retrieval results appear. Cause: Administrators do not enable structured data field mapping. They do not include fields such as crash log ID and device version in the retrieval index.
- Symptom: When a user asks two adaptation questions about different device models consecutively, the second retrieval still uses the knowledge base collection from the first query. Cause: Administrators do not configure the knowledge base switching logic for session context. The system retains the first selected knowledge base ID by default.

## How to verify proper configuration
- Upload a test document containing specified device adaptation requirements. Submit a query that includes the device name. Check if the retrieval result hits the corresponding paragraph of the test document.
- Adjust the `similarity` parameter. Confirm low thresholds recall irrelevant development documents, and high thresholds filter valid content.
- Upload a crash analysis report larger than 1GB. Confirm the upload progress works normally, with no interface timeout prompts.
- Submit two consecutive adaptation questions about different device models. Confirm the second retrieval switches to the knowledge base collection for the corresponding device model.

The values provided are common starting points. They should be evaluated against samples relevant to the specific deployment.
