# Customer Technical Support and Pre-Sales Q&A for Mobile Development: Reranking and Hybrid Retrieval

## What data looks like for this category
Data for this category primarily comes from code repositories, app store backends, crash monitoring platforms, and device coverage data. Daily produced documents include device version release notes, device compatibility lists, crash analysis reports, app store review materials, and similar items. Data updates run daily or trigger when a new version is released. Fields cover device models, system versions, code commit records, review statuses, crash stack information, and more. Some documents are structured tables, others are plain text logs, with no unified fixed format.

## What constraints these characteristics impose on reranking and hybrid retrieval
Data for this category includes both structured tables (such as compatibility lists) and unstructured text (such as crash logs). Update frequency fluctuates with version releases. Some data has strict timeliness requirements. Hybrid retrieval must support both structured field matching and full-text search. The reranking step must prioritize core business fields like device model, system version, and crash type. This prevents search results from straying from mobile development technical support scenarios. Data volume grows gradually with version iterations. Retrieval recall range must be controlled reasonably to avoid result overload and ensure search response speed.

## Three common mistakes
- Symptom: No search results appear after enabling the reranking function in the application, but tests work normally in the knowledge base alone. Troubleshooting: Check if the App/Admin server has correctly configured `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service, no additional path suffixes allowed) and `AIPROXY_API_TOKEN` (AI Proxy admin token, must match the AI Proxy server configuration and cannot be empty) environment variables. Confirm no required configuration is missing.
- Symptom: After Docker offline deployment, clicking the reranking model test prompts a request error. Troubleshooting: Check if the model vendor key was mistakenly entered into the `AIPROXY_API_TOKEN` environment variable. Confirm that upstream model channel configurations and AI Proxy service environment variables are not mixed up.
- Symptom: Search results include a large number of general IT documents, with no mobile development device compatibility content linked. Troubleshooting: Check the similarity threshold configuration. Confirm the threshold was not set too low, which would recall content from non-target scenarios.

## How to confirm configuration is complete
- Check the environment variables of the App/Admin server. Confirm `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are correctly configured, not empty, and no additional path suffixes are added.
- Check the App/Admin server startup logs. Confirm there are no startup verification errors related to missing environment variables.
- Enter mobile development related keywords in the application's technical support search entry. Check if the returned results include core documents such as device compatibility and crash analysis.
- Adjust the similarity threshold. Verify whether the relevance of search results meets business expectations.
