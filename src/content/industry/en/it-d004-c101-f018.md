# Customer Technical Support and Pre-sales Q&A for Renewal Health Management: Re-ranking and Hybrid Retrieval

## What the Data for This Category Looks Like
The data for this category typically comes from CRM systems, product usage data platforms, ticket statistics tools, and contract ledgers. Daily processed documents include customer health reports, renewal forecast sheets, high-risk customer lists, and cross-role communication minutes. Most fields include customer identifiers, contract cycle milestones, product usage frequency, ticket response times, and risk ratings. Data update frequencies are mostly weekly or monthly. The field dimensions of a single document cover core indicators related to the full customer lifecycle renewal process.

## Constraints for Re-ranking and Hybrid Retrieval
Multiple scattered data sources require hybrid retrieval to connect both structured ledgers and unstructured communication records, to avoid disjointed retrieval results.
Weekly or monthly update frequencies mean retrieval does not need to rely on real-time streaming data, reducing reliance on low-latency retrieval.
Document types cover structured reports and unstructured minutes. The re-ranking link must adapt to text features of different formats, and prioritize matching core fields related to renewal risk.
Multi-dimensional fields in a single document require retrieval and re-ranking to focus on indicators related to customer renewal, to avoid irrelevant interference with result ranking.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.62–0.78 | Focus on semantic matching related to renewal, filter low-match results unrelated to customer health and renewal risk |
| `limit` | Top 6–10 entries | Adapt to the scale of weekly or monthly updated documents, control the total number of returns per retrieval round |
| `searchMode` | hybrid | Integrate multi-source structured and unstructured data, cover different types of documents such as contract ledgers and communication minutes |
| `usingReRank` | Enabled | For documents with multi-dimensional fields, optimize the sorting priority of results related to core renewal indicators through re-ranking |

## Three Common Misconfigurations
- Persistent unreleased video memory usage after enabling `usingReRank`: The symptom is gradual increase in memory usage during model operation until an overflow error is triggered. The cause is failure to set the batch processing limit for the re-ranking model, and failure to enable the video memory automatic recycling mechanism.
- Failure to locate the API configuration entry for the re-ranking model: The symptom is that no rerank-related settings are found on the system configuration page. The cause is using a FastGPT version lower than v4.17.0; this function was not available in older versions.
- Retrieval results containing a large number of documents unrelated to renewal health: The symptom is returned results mixed with non-target documents such as product usage manuals and internal notifications. The cause is an unreasonable `similarity` threshold, failing to accurately match renewal-related semantics.

## How to Verify Proper Configuration
- Enter the retrieval test page, input keywords including "high-risk renewal customer list" and "recent monthly renewal forecast", and verify whether returned results prioritize target documents such as risk customer lists and renewal forecast sheets.
- Check system operation logs to confirm that the re-ranking function is normally enabled, and there are no video memory overflow or connection timeout error reports.
- Adjust the `similarity` threshold, and verify whether the relevance of returned results shows reasonable matching degree fluctuations as the threshold changes.
- Check the retrieval coverage of multi-source data, and confirm that documents from different sources including CRM data and product usage data are included in the retrieval scope.

The values provided are common starting points and should be measured against the reader's own samples.
