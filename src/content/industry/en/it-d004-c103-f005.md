# Customer Technical Support and Pre-sales Q&A for Art Asset Production Management: Multi-turn Dialogue and Prompt Engineering

## What data looks like for this category
Data for this category typically originates from art asset libraries, project management systems, engine resource packages, and outsourced delivery packages. Update frequency usually falls to daily or weekly cycles. Commonly used documents include art requirement sheets, asset specification sheets, outsourced feedback sheets, and acceptance records. Document fields mostly cover resource type, delivery deadline, specification parameters, acceptance criteria, and other details. Units include pixels, polygon counts, file formats, delivery cycles, and more. Entities associated with the data include art PMs, original artists, 3D artists, and outsourced project managers. The core focus is end-to-end delivery management of character, scene, and special effects art resources.

## Constraints on multi-turn dialogue and prompt engineering
Art asset-related documents contain a large number of professional parameters. Multi-turn dialogue and prompt engineering must accurately match units such as pixels and polygon counts to avoid ambiguity. Data sources are scattered and updated frequently. Multi-turn dialogue must retain complete context to link outsourced feedback and acceptance records across different cycles, ensuring consistent communication. Outsourced delivery packages have diverse formats. The dialogue link must support calling resource library format verification rules to assist with engine import checks. Changes to asset specifications must be synchronized via multi-turn dialogue, and must be bound to project management system node information to avoid missing materials or resource mismatches in versions. Interaction logic for different roles must align with corresponding document fields to avoid confusing resource types and acceptance criteria.

## Configuration settings
The following configurations are based on the logic of FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind unique project identifiers | Ensure multi-turn dialogue context is linked to the corresponding art project, avoiding cross-project data confusion |
| `messages` | Retain the most recent 20 interaction entries | Art asset communication often involves multiple rounds of specification confirmation and rework feedback. Retaining sufficient context avoids repeating asset parameter explanations |
| `variables` | Bind field variables from art asset libraries and project management systems | Daily documents include fields such as asset specifications and delivery deadlines. Using variables directly calls corresponding data, reducing prompt redundancy |
| Context window length | 8000–12000 characters | Data updates occur daily or weekly. A longer window covers outsourced feedback and acceptance records within a single project cycle |
| Role settings | Preset roles of "Asset PM", "Outsourced Party", and "Engine Verification" based on art asset scenarios | Interaction logic for different roles must match corresponding document fields to avoid confusing resource types and acceptance criteria |
| Maximum context refresh interval | 24 hours | Data updates follow a daily cycle. Regular refresh ensures asset data used in dialogue is up to date |

## Three common misconfigurations
- Form input fields in the workflow do not display on the dialogue interface. The cause is failure to correctly bind form variables to the `variables` parameter, so dialogue context cannot read user-input asset specification content.
- Configured file links cannot be called during dialogue. The cause is failure to correctly associate the outsourced delivery package path from the art asset library with the resource call configuration of the dialogue module, so the prompt cannot obtain the corresponding file content.
- Dialogue role settings do not align with business logic. The cause is failure to preset roles based on art asset scenarios, leading to confusion between asset types and acceptance criteria during interaction, and inability to accurately match the field requirements of daily documents.

## How to verify successful configuration
- Trigger a test dialogue, input art asset specification parameters, and check if the dialogue context correctly reads and displays the corresponding content.
- After configuring file links, initiate a query that includes the asset library path, confirm that the dialogue can return format and specification information for the corresponding resource.
- View logs for the `chatId` parameter, confirm that multi-turn dialogue context content updates incrementally with interactions, and no historical information is lost.
- Verify variable binding, confirm that delivery deadline information synchronized from the project management system can automatically update in the dialogue, matching the daily or weekly update frequency requirement.
