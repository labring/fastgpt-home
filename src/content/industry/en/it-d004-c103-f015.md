# Customer Technical Support and Pre-Sales Q&A for Art Asset Production Management: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Core data for art asset production management comes from art asset libraries, project management systems, engine resource packages, and outsourced delivery packages. Daily circulating documents include art requirement sheets, asset specification sheets, outsourced feedback record sheets, and acceptance confirmation sheets. Document fields contain unique asset identifiers, specification parameters such as polygon count and resolution, delivery time, outsourcer information, acceptance status, and more. Data update frequency is mostly daily or weekly. Single document size ranges from several KB to tens of MB, with some 3D asset resource packages having larger sizes.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
Mixed multi-source data requires retrieval to support cross-system associated recall, avoiding siloed asset information. Daily and weekly update cycles require knowledge base synchronization tasks to match data update periods, preventing retrieval of expired asset specifications or acceptance records. Document fields contain numerous professional parameters and status identifiers, requiring retrieval to accurately match specification keywords and status conditions. Otherwise, mismatched resource content may be returned. If a single retrieval returns too many long documents, it will exceed the context window limit, affecting the accuracy of subsequent generation steps. Resource mismatches or missing versions will directly impact project progress, so retrieval result relevance must meet a high standard.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Art asset specification parameters are numerous and professional. This range filters low-match irrelevant results and avoids mismatched resources |
| `limit` | `Top 8 entries` | Single art asset documents have relatively long lengths. Limiting the number of returned entries controls the total context length, preventing exceeding model limits |
| `searchMode` | `Vector + keyword hybrid retrieval` | Balances the need for exact matching of asset IDs, file names and other fields, and semantic matching of specification parameters |
| `usingReRank` | `Enabled` | Semantic relevance of long texts such as outsourced feedback and acceptance records needs to be optimized via reranking to improve the priority of core results |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Descriptions on art requirement sheets may use colloquial language or abbreviations. Extended queries can cover synonymous expressions and improve recall coverage |
| `collectionIds` | `Specify the collection IDs corresponding to the art asset library and project management system` | Restrict the retrieval scope to only art asset-related data sources, avoiding mixing in non-target content |

## Three common errors
- Triggering knowledge base request frequency limits. The symptom is returning a 429 status code. The cause is failing to configure reasonable request current limiting rules based on the update rhythm of art asset data, or failing to adjust concurrent parameters for batch retrieval.
- Unable to retrieve art asset data from Feishu knowledge base. The symptom is returning empty results. The cause is failing to correctly configure the sync permissions for the Feishu data source, or failing to associate the Feishu knowledge base with the specified art asset retrieval collection.
- An error of `Validation failed: name: Path `name` is required.` occurs when generating a static link knowledge base. The symptom is immediate failure after submitting the task. The cause is failing to correctly fill in the resource name field corresponding to the static link, or the resource metadata pointed to by the link is missing.

## How to confirm the configuration is correct
- Initiate a query containing specific art asset specification keywords, check whether the matching degree of returned results meets the preset `similarity` threshold.
- View the source collection identifiers of retrieval results, confirm that only content from specified data sources such as art asset libraries and project management systems is included.
- Test queries containing synonymous expressions, confirm that the `datasetSearchUsingExtensionQuery` function works normally and can recall relevant documents that do not use the original keywords.
- After enabling `usingReRank`, check whether the sorted results place the most relevant asset specifications or acceptance records at the top.
- Initiate batch test queries, confirm that frequency limits are not triggered, and verify the rationality of the current limiting configuration.

The values given are common starting points and should be measured against the reader's own samples.
