# Customer Technical Support and Pre-Sales Q&A for License Compliance and Copyright Notices: Sharing and Embedding

## What the Data for This Category Looks Like
The data for this category primarily comes from code repositories, dependency lists, license texts, and contribution records. Officially maintained documents include LICENSE files, NOTICE files, dependency license lists, and copyright notices. Data updates trigger with each version release or every dependency change. Fields include license type, copyright holder, authorization scope, dependency name, and version number. No custom units are used. All documents use plain text or structured table formats, and are updated synchronously with project iterations.

## Constraints Imposed on Sharing and Embedding Workflows
Because data for this category updates frequently with versions and dependencies, shared and embedded content must ensure real-time synchronization of the latest license and copyright information. Outdated documents must be avoided to prevent compliance risks. Data sources are scattered and have diverse structures. Embedding requires adaptation to different formats of LICENSE and NOTICE files, so a unified fixed template cannot be used. Additionally, data fields include sensitive information such as copyright holders and authorization scopes. Strict access control must be implemented during embedded sharing to prevent unauthorized commercial use. The update frequency is high, so embedded content must support regular pull updates to avoid mismatches between compliance documents and the current project version.

## Three Common Mistakes
- Sharing entries related to license compliance and copyright notices fail to open. First verify the full system-generated link and its validity period, then check browser request statuses. Do not manually replace `shareId`.
- The visible scope of license compliance and copyright notice data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately. The sharing entry identifier itself does not provide business authorization.
- The same license compliance and copyright notice question-and-answer pair is not visible on another device. For anonymous scenarios, first verify device, browser, and local identity status. Retention is not guaranteed across devices or after cache clearance. Do not use this phenomenon alone to judge service anomalies.

## How to Confirm Configurations Are Set Correctly
- Access the generated share link, check that the page language matches the configured target language.
- Attempt voice interaction on the login-free page, confirm that timing works normally and content can be sent successfully.
- Compare the license text displayed on the embedded page with the latest LICENSE file in the code repository, confirm that the content matches.
- Initiate multi-turn interactions on the embedded page, confirm that conversation context is only retained on the same device and browser, and cannot be retained across devices or after cache clearance.
- Check the domain whitelist configuration in the embedded code, confirm that only specified legitimate domains are allowed to use the embedding function.
