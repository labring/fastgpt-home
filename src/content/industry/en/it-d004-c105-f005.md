# Customer Technical Support and Pre-Sales Q&A for License Compliance and Copyright Notices: Multi-turn Dialogue and Prompts

## What data for this category looks like
Data for this category comes from code repositories, dependency lists, license texts, and contribution records. It is updated with each version release or dependency change. Daily operation documents include LICENSE files, NOTICE files, dependency license lists, and copyright notice files. Fields covered include license type, copyright owner, dependency name, version number, and more. The processing entities are open source project offices, project maintainers, and legal staff. Core steps include license compatibility verification, copyright ownership confirmation, and NOTICE file updates. Consequences of errors include license violations, blocked commercial use, and project takedowns for remediation.

## What constraints do these characteristics impose on the "multi-turn dialogue and prompts" link
The update frequency and document structure of category data impose clear constraints on multi-turn dialogue configuration. First, multiple license and dependency documents must be accurately distinguished, so dialogue must support configuration for retrieving specific documents. Second, data updates are frequent, so context cache duration must match version iteration cycles to avoid calling outdated license information. Third, most inquiries are professional compliance questions, so irrelevant small talk must be filtered, and only valid inquiry content must be retained in the `messages` field. Finally, users may repeatedly ask about archiving and cleanup rules, so the dialogue archiving limit must be adapted to the project’s daily inquiry scale.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context turns | Previous 8–12 turns of dialogue | License compliance inquiries are mostly short-sequence questions; overly long contexts will include irrelevant dependency information |
| Context cache duration | 72 hours | Dependency lists are updated with each version; cache duration matches a single project iteration cycle |
| Single recall count | Previous 3–5 entries | License document content is relatively short; a single recall can cover core compliance information |
| Knowledge base recall filtering | Filter by knowledge base tags | Category data includes multiple license documents; filtering by tags enables precise retrieval of target files |
| `messages` field processing | Retain only valid inquiry messages | Most category data consists of professional compliance questions; filtering out invalid small talk improves answer accuracy |
| `variables` configuration | Bind the current project’s LICENSE file ID | Category data comes from code repository-hosted files; binding the ID enables precise calling of local documents |
| Dialogue archiving limit | 500 entries | Matches the daily inquiry scale of open source projects; 500 entries covers monthly compliance inquiry needs |

## Three common mistakes
- Symptom: Subsequent questions in multi-turn dialogue cannot associate context, and responses are unrelated to the current inquiry. Cause: Context retention rules are not configured, or the context turn setting is too low, resulting in incomplete loading of `messages` field content for historical conversations associated with `chatId`.
- Symptom: Specific license documents cannot be targeted for recall, and recall results mix content from multiple files. Cause: Knowledge base tag filtering rules are not configured, and retrieval scope is not limited via configuration items.
- Symptom: Dialogue archiving space is insufficient or automatic cleanup does not take effect. Cause: Dialogue archiving limit and cache duration are not set, or cache duration is set too long and exceeds the project’s storage quota.

## How to confirm the configuration is correct
- Initiate two consecutive license compliance-related inquiries, confirm that the second response associates context from the first inquiry.
- After configuring knowledge base tags, initiate a retrieval request targeting a specific document, confirm that recall results only include content from the target document.
- View the dialogue management interface in FastGPT v4.17.0, confirm that the number of archived entries does not exceed the set limit, and old conversations are automatically cleaned up.
- Check the `variables` binding configuration and `chatId` association rules, confirm that the current project’s LICENSE file path or ID has been associated.
