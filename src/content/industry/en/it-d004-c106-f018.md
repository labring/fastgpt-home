# Customer Technical Support and Pre-Sales Q&A for Speech Annotation and Transcription: Reranking and Hybrid Retrieval

## What data for this category looks like
Speech annotation and transcription data originates from audio files, annotation results exported from annotation platforms, industry-specific vocabularies, and random inspection and quality control samples. Daily maintained documents include transcription specifications, audio delivery lists, quality inspection reports, and speaker annotation forms. Data updates occur daily or per annotation batch. Data fields include audio identifiers, speaker tags, transcribed text, annotation confidence, quality inspection results, and additional relevant fields. This is a structured speech transcription and annotation associated dataset that requires matching transcribed text to original audio metadata.

## What constraints these characteristics impose on reranking and hybrid retrieval
Speech annotation and transcription data characteristics create three main constraints for reranking and hybrid retrieval.
First, the data includes both original audio metadata and structured transcribed text. Hybrid retrieval must cover both metadata fields such as audio identifiers and speaker tags, and transcribed semantic content. Multi-dimensional matching logic must be configured.
Second, data updates daily or per annotation batch. Retrieval indexes must adjust refresh frequency to match this update cadence. This prevents retrieval results from falling out of sync with the latest annotation data.
Third, daily maintained transcription specifications and industry-specific vocabularies must be used as retrieval weighting factors. Reranking models must raise matching priority for specialized terms and quality inspection markers. These models must also filter low-confidence transcribed content from noisy segments to avoid interfering with retrieval results.

## How to set configurations
This document is written for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `usingReRank` | Enabled | Speech transcribed text contains noisy segments. Reranking is required to filter low-confidence matching results |
| `similarity` | 0.72–0.88 | Matches the matching accuracy of industry-specific vocabularies, calibrated via actual testing |
| `limit` | Top 8–12 results | Controls the number of retrieval results, preventing excessive noisy data from slowing down retrieval speed |
| `searchMode` | Hybrid retrieval | Must match both transcribed text and audio metadata to cover multi-dimensional retrieval requirements |
| Retrieval timeout | 600 seconds | Adapts to retrieval latency for batch-updated datasets, preventing timeout errors |

## Three common mistakes
- Symptom: After deploying FastGPT via Docker offline, the reranking model test displays "request error". Cause: The deployment path of the offline reranking model is not correctly bound to the model directory inside the container, or the model version is incompatible with the FastGPT version.
- Symptom: Retrieval takes too long after enabling reranking for knowledge base QA. Cause: The `limit` value exceeds 12 entries, or the `similarity` threshold is set too low. This leads to an excessive number of retrieval results, slowing down the overall workflow.
- Symptom: Retrieval results still contain large amounts of noisy transcribed segments after enabling `usingReRank`. Cause: The `similarity` threshold is not set, or the threshold is set too high, failing to filter low-confidence transcribed matching results.

## How to confirm configurations are correctly set
- Access the FastGPT model management page, confirm the reranking model status is loaded.
- Run a reranking model test, receive normal responses with no errors.
- Initiate a retrieval query that includes industry-specific vocabularies, verify results are sorted according to reranking logic.
- Check retrieval logs, confirm the reranking step has been triggered.
