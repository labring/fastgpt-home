# Customer Technical Support and Pre-sales Q&A for Account Ban and Appeal Review: Sharing and Embedding

## What the data for this category looks like
Data for this category typically comes from risk control systems, audit records, user behavior logs, and report evidence. Daily processed documents include ban records, appeal materials, review opinions, and user notifications.
Ban records contain fields for account identifiers, violation types, disposal times, and disposal levels. Appeal materials include supporting content and written descriptions submitted by users. Review opinions contain audit identifiers, judgment results, and adjustment bases.
Data updates occur daily or in real time. Most fields use string, timestamp, and enumeration value types.

## What constraints these characteristics impose on sharing and embedding
Real-time data requirements limit data source synchronization cycles. Synchronization must match daily or real-time update rhythms. Expired ban and appeal data must not be used. Synchronization is controlled by external business systems.
Documents contain sensitive account identifiers and audit details. Field filtering rules must be configured when sharing via calls. Only compliant fields can be exposed for external access.
Document structures vary significantly across types. Corresponding document categories must be specified during embedding calls. This ensures retrieved content aligns with the current account ban and appeal scenario. Category rules are configured by the external knowledge base.
Data sources include user behavior logs. Embedding calls must comply with data usage standards. User privacy information must not be exposed.

## Three common mistakes
- Sharing entries related to account ban and appeal review fail to open. First verify the full system-generated link and its validity period. Then check browser request statuses. Do not manually replace `shareId`.
- The visible scope of account ban and appeal review data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately. The sharing entry identifier itself does not provide business authorization.
- The same account ban and appeal review Q&A is not visible on another device. In anonymous scenarios, first check device, browser, and local identity status. Record retention cannot be guaranteed across devices or after cache clearance. Do not use this phenomenon alone to judge service abnormalities.
