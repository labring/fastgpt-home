# Customer Technical Support and Pre-sales Q&A for Identity Account and Permission Management: Reranking and Hybrid Retrieval

## What This Category of Data Looks Like
Data for this category primarily comes from enterprise IAM systems, HR systems, business system logs, and approval systems. Update frequency is daily synchronization or real-time updates accompanying personnel onboarding, offboarding, transfers, and adjustments. Daily produced documents include account application forms, permission matrices, offboarded account recovery forms, and permission audit reports. Fields cover account ID, permission groups, approval status, audit cycles, and more. There are no unified fixed units of measurement. Data volume varies based on enterprise employee scale and number of business systems.

## Constraints for Reranking and Hybrid Retrieval
Cross-system data sources require hybrid retrieval to associate datasets from IAM, HR, and approval systems simultaneously, to avoid missing information from single data sources. Non-fixed update frequency requires retrieval indexes to support on-demand refreshing, to adapt to real-time synchronization needs for personnel changes. Document structures vary significantly: there are both structured permission matrix tables and unstructured ticket text. Reranking models must adapt to weight allocation for different fields. Additionally, errors in permission data can lead to unauthorized access risks. The relevance ranking of retrieval results must strictly match the priority of business scenarios.

## Configuration Settings
The following configurations are formulated for FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Similarity Threshold | 0.75–0.85 | Adapt to structured permission data, filter low-relevance cross-system retrieval results |
| Single Search Limit | Top 10 results | Control the number of results returned by basic retrieval, adapt to the single-batch data volume of IAM systems |
| Search Mode | Hybrid Retrieval | Associate multi-source system data, cover full-link information for accounts, permissions, and approvals |
| Reranking Toggle | Enabled | Correct ranking deviations between structured and unstructured documents |
| Reranking Recall Limit | Top 20 results | Provide sufficient candidate results for the reranking model, ensure ranking accuracy |
| Context Window | 8000–12000 token | Adapt to retrieval requirements for long texts such as permission audit reports |

## Three Common Misconfigurations
- Symptom: Reranking model fails to start, logs return "hardware architecture incompatible" error. Cause: Only the amd architecture reranking model image was loaded, and the arm architecture deployment environment was not adapted.
- Symptom: Reranking function does not take effect after configuration is completed, returned results are identical to basic retrieval. Cause: The reranking toggle configuration item was not enabled, or the reranking model was not bound to the hybrid retrieval workflow.
- Symptom: Relevance of permission-related results returned by hybrid retrieval is overly deviant, with irrelevant business log entries appearing. Cause: The similarity threshold was set too low, failing to filter low-match cross-system data.

## How to Confirm Successful Configuration
- Navigate to the retrieval configuration page of FastGPT v4.17.0, confirm that the search mode is set to Hybrid Retrieval.
- Check the toggle status of reranking-related configuration items, confirm that the reranking toggle is enabled.
- Submit a permission-related test query, compare the result ranking differences between basic retrieval and reranked results.
- View retrieval logs, confirm that multi-source datasets from IAM, HR, and approval systems have been associated.

The values provided are common starting points and should be measured against the reader's own samples.
