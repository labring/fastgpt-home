# Customer Technical Support and Pre-sales Q&A for Project Implementation Plan Management: Sharing and Embedding

## What the data for this category looks like
Daily documents for this category include project plans, milestone lists, weekly reports, and risk issue lists. Data sources are contracts, work breakdown structures (WBS), customer schedules, and project management systems. Data update cycles are typically weekly or per milestone. Fields include task number, responsible person, deadline, progress status, risk level, and others. Units involve days, percentages, and task priority levels. Different documents have distinct field focuses: weekly reports prioritize summaries and risk feedback, while project plans focus on task details and scheduling.

## What constraints these characteristics impose on the "Sharing and Embedding" workflow
Since data is updated weekly or per milestone, content cache for sharing and embedding must align with this cycle. Relevant cache configurations must be set via external deployments or FastGPT release channels to prevent display of outdated task progress or risk information. Daily documents contain multiple types of structured content. When embedding, content filtering rules must be configured by document type to ensure content returned during pre-sales Q&A matches the customer’s inquiry context, such as task breakdown or risk tracking. Data originates from multiple external systems. FastGPT embedding configurations must support associating fields from specified external data sources to avoid mixing irrelevant non-project plan content. Customer-facing sharing must control visible field ranges: only expose progress and schedule information that customers are authorized to view, and hide sensitive fields such as internal risk levels. Relevant field permission control must rely on external project management systems.

## Three Common Misconfigurations
- Sharing entries related to project implementation plan management fail to open. First verify the full system-generated link and its validity period, then check browser request statuses; do not manually replace `shareId`.
- The visible range of project implementation plan management data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately; the sharing entry identifier itself does not provide business authorization.
- The same project implementation plan management Q&A is not visible on another device. For anonymous scenarios, first check device, browser, and local identity status; record retention cannot be guaranteed across devices or after cache clearance, and service abnormalities cannot be judged solely based on this phenomenon.

## How to Confirm Configuration is Successful
- Generate a FastGPT login-free share link, check that the link includes the system-generated `shareId` parameter, verify the external project management system’s data source association configuration, and confirm that shared content matches target project data.
- Open the embedded page, check that reference links can be clicked to jump to the original documents in the external project management system, and confirm that the reference link rendering configuration is effective.
- Wait for the configured cache cycle (such as the 7-day test example) and refresh the embedded page, check that the content is updated to the latest project plan or weekly report data, and verify that the cache configuration is correct.
- Attempt to access an unauthorized share link, confirm that internal sensitive fields (such as risk level) cannot be viewed, and verify that the external system’s field permission control configuration is effective.
