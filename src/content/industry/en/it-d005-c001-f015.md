# Technical Documentation and API Q&A for CDN and Edge Acceleration Configuration: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
Core data for this category originates from CDN consoles, DNS resolution records, user access logs, and monitoring alerts. Updates occur daily or when configuration changes. Daily deliverables include domain name access forms, cache rule configuration documents, refresh and preheating records, and fault analysis reports. Domain name access forms include fields such as filing numbers, origin server IP addresses, and acceleration regions. Cache rule documents specify matching paths and cache duration, measured in seconds. Access logs record request time, status codes, and traffic volume, measured in MB. The data structure primarily mixes structured configuration items and unstructured fault descriptions.

## Constraints for Knowledge Base Retrieval and Recall
The mixed multi-source data structure requires retrieval to support both structured field matching and non-semantic text matching. High-frequency data updates require the knowledge base to support incremental synchronization, to avoid recalling expired cache rules or invalid filing information. Specific business fields such as filing numbers and cache duration require retrieval to prioritize precise field matching. Daily time-consuming tasks including filing verification and cache debugging require the knowledge base to prioritize documents for matching scenarios, improving retrieval targeting.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Threshold for professional term similarity matching for CDN configuration documents, to avoid recalling irrelevant general network content |
| `limit` | Top 8 entries | Adapts to the moderate length of individual CDN configuration documents, ensuring context does not overflow |
| `searchMode` | Semantic Retrieval | Meets semantic matching needs for unstructured text such as cache rules and fault reports |
| `usingReRank` | Enabled | Reorders recalled results by relevance, optimizing sorting for fault troubleshooting content |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands query terms to supplement matching for precise fields such as filing numbers and origin server IPs |
| `collectionIds` | Bound to dedicated CDN configuration knowledge base | Isolates CDN documents across different business lines, avoiding cross-category recall |

## Three Common Misconfigurations
- Symptom: Calling the API to query CDN configuration-related questions returns no relevant content. Cause: The application is not bound to a dedicated CDN configuration knowledge base, and cross-business line knowledge bases cannot locate target documents.
- Symptom: After importing a single QA-formatted Markdown document, question-and-answer matching accuracy is insufficient. Cause: The query term expansion configuration is not enabled, and the document title is not used as a supplementary retrieval term.
- Symptom: Recalled fragments of long cache rule documents are missing key cache duration parameters. Cause: A reasonable text block overlap length is not set, resulting in truncated fields.
