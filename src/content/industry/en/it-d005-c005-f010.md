# Issue Triage and Response Technical Documentation and Interface Q&A: Source Citation and Traceability

## What the data for this category looks like
Data for this category primarily comes from GitHub or Gitee Issues, code repository version logs, user-submitted environment information, and problem reproduction descriptions. Daily maintained documents include Issue classification templates, tag rule libraries, historical reply records, and problem responsibility module mapping tables. Data update frequencies are mostly daily or weekly. A single data entry contains fields such as Issue title, descriptive text, associated code snippets, user environment parameters, tags, and priority markers. No unified fixed units exist, as values vary based on the actual content of each Issue.

## Constraints on Source Citation and Traceability
Data for this category ties to specific code repositories and Issue entries. The citation and traceability link must associate metadata such as repository addresses and Issue numbers. This avoids citing content with no clear ownership. Use daily maintained classification templates and tag rules to require traceability results match the preset Issue classification system. This ensures cited sources correspond to the correct problem modules. Data update frequencies stay mostly daily or weekly. Set reasonable refresh cycles for traceability caches. This prevents citation of expired tags or reply records. A single data entry includes non-standardized user environment and reproduction information. Configure the traceability link to support parsing unstructured text content. Avoid blocking the issue triage process due to overly long parsing times.

## Configuration Settings
This configuration applies to FastGPT v4.17.0 and above.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `detail` | `true` | Returns full metadata for knowledge base calls, matching the reproduction information and associated code snippets required for issue triage |
| `quoteMaxToken` | `800–1200 token` | Covers the typical text length of a single Issue, ensuring complete citation of problem descriptions and reproduction steps |
| `responseData` | `Includes repository address, Issue number` | Binds the data source characteristics of this category, ensuring traceability results can be directly linked to corresponding GitHub/Gitee entries |
| Traceability cache refresh cycle | 1 time per day | Matches the daily or weekly data update frequency, avoiding citation of expired tags or reply records |
| Streaming return timeout threshold | 600 seconds | Prevents blocking of the issue triage process due to overly long traceability parsing times |
| Citation validation rules | Execute per preset tag rule library | Matches daily maintained classification templates and tag rules, ensuring cited sources correspond to correct problem modules |

## Three Common Misconfiguration Scenarios
- Scenario: Citation content is returned even when `detail` is set to `false`. Cause: The Issue traceability parameters for this category are not correctly bound, causing the system to enable forced citation logic by default.
- Scenario: Returned cited files do not match the actual Issue content. Cause: Traceability results are not validated against the preset tag rule library, resulting in citation of incorrect classification module documents.
- Scenario: Streaming return results do not include traceability metadata. Cause: The `responseData` configuration item is not enabled, and metadata such as repository addresses and Issue numbers are not included in returned content.

## How to Verify Proper Configuration
This verification process applies to FastGPT v4.17.0 and above.
- Pass specified configuration parameters when calling the FastGPT interface, then check whether returned results include complete metadata for the `detail` field.
- Compare returned cited content with the actual content of the corresponding GitHub/Gitee Issue, and confirm that the cited text and metadata match.
- Review system logs, confirm that the traceability cache refreshes at the set cycle, and no expired citation alerts appear.
- Adjust the value of `quoteMaxToken`, then verify that the length of returned cited content meets expectations.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
