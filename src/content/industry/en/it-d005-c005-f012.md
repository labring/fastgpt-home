# Technical Documentation and Interface Q&A for Issue Sorting and Response: Document Parsing and Chunking

## What the data for this category looks like
This category’s data primarily originates from Issues, release notes, user environment information, and code repositories on GitHub or Gitee. Commonly processed documents include Issue templates, label rules, response records, and problem reproduction instructions. Data updates occur daily or weekly. Each individual data entry includes structured fields such as problem description, reproduction steps, environment information, and associated tags. Bulk imported data uses table or batch-exported text formats.

## Constraints on Document Parsing and Chunking
This category’s data consists mainly of short problem-focused text and structured bulk data, with a high update frequency. This requires efficient parsing and chunking processes. Structured fields such as reproduction steps and environment information must retain contextual associations. Splitting must not break semantic integrity. Bulk imported table data must be split by row. This ensures each Issue record is independently retrievable. Large-volume release notes or bulk Issue files create parsing time pressure. Reasonable timeout and size limits must be implemented.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Ensures semantic integrity for Issue text, avoiding splits that break the link between problem descriptions and reproduction steps |
| `chunkSplitter` | Semantic splitting | Adapts to structured paragraphs in documents of this category, preserving contextual connections between different modules |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports large-volume release notes or bulk Issue export files, meeting daily import requirements |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Accommodates the time required for bulk Issue parsing, preventing parsing process interruptions due to timeouts |
| `chunkSettingMode` | Manual configuration | Adapts to the specific document structure of this category, enabling flexible adjustment of chunking rules and splitting logic |

## Three Common Configuration Mistakes
- Symptom: Bulk Issue data imported from Excel is merged into a single chunk, with individual records not split independently. Cause: The `chunkSplitter` is not configured for row-splitting mode, or custom delimiters adapted to table row formats are not enabled.
- Symptom: Parsing times out and fails for a single release note file larger than 10 MB. Cause: The value of `PARSE_FILE_TIMEOUT_SECONDS` is lower than actual parsing time, or `UPLOAD_FILE_MAX_SIZE` is not adjusted to support large files.
- Symptom: The reproduction steps of an Issue are split into multiple chunks, making complete retrieval of the reproduction process impossible. Cause: The value of `chunkSize` is too small, preventing a single chunk from covering the full reproduction step description.

## How to Verify Correct Configuration
- Upload a single test text in standard Issue format. Check if chunking results retain complete problem descriptions and reproduction steps.
- Upload a pre-configured large-volume test file. Confirm no timeout errors occur during parsing.
- Import bulk Issue data in Excel format. Verify each record is split into an independent chunk unit.
- View backend parsing logs for FastGPT v4.17.0. Confirm configuration item values match preset values.
