# Technical Documentation and API Q&A for SLA and Service Reports: Citation Sources and Traceability

## What data for this category looks like
Data sources for this category include monitoring systems, ticket systems, contract documents, and customer communication records. Update cycles are monthly or quarterly. Daily produced documents include SLA clause text, monthly service reports, availability statistics reports, and customer review minutes. Core fields include SLA indicator items, event occurrence time, statistical cycle, number of service responses, and abnormal event details. No percentage-based statistical units are used. The text length of single documents varies widely, ranging from hundreds of characters for indicator entries to thousands of characters for review minutes.

## What constraints do these characteristics impose on the citation sources and traceability link
Since data sources are scattered and involve original records from multiple systems, the traceability link must associate identifiers across multiple data sources to ensure matching accuracy between SLA indicators and their corresponding original data. Update cycles are monthly or quarterly, so real-time data pulling is unnecessary. Statistical calibers must be aligned per cycle to avoid cross-cycle data confusion. Document structures and fields vary significantly, so different matching rules must be configured for each document type to maintain clear links between cited content and original sources. Errors here can easily lead to compensation disputes, so the traceability link must ensure cited content is complete and accurate, with no omissions or misplacements.

## How to configure
This configuration logic is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | Adapts to the single-paragraph text length of monthly service reports and SLA clauses, fully preserving cited content |
| `responseData` | Enabled | Used to associate traceability identifiers for original data, matching SLA statistical data from multiple sources |
| `detail` | Full | Displays the full content of original documents, meeting the needs of abnormal event attribution |
| Single traceability limit | Top 5 entries | Controls the number of returned traceability entries, avoiding content overload that affects readability |
| Traceability matching threshold | Calibrated via actual testing | Adapts to field matching accuracy for documents from different sources, ensuring accurate association |

## Three common configuration mistakes
- Symptom: Returned traceability results do not include links or unique identifiers for original documents. Cause: The `responseData` configuration is not enabled, and key identifiers for data sources are not associated.
- Symptom: Cited SLA clauses or service report text are truncated, with core content not fully displayed. Cause: The `quoteMaxToken` value is too small, failing to cover the length of the target text.
- Symptom: When calling an interface via a workflow, internal stored SLA documents cannot be associated using local variables, and only external resource links are supported. Cause: Variable binding rules for traceability parameters are not configured, and only directly passed external addresses are recognized.

## How to confirm correct configuration
- Initiate an API Q&A for SLA indicator calculation, and check if returned results include traceable original data identifiers such as document IDs or source links.
- Test cited long-text SLA clauses, and confirm returned cited content is not truncated and fully covers the target text.
- Call the workflow interface, and verify that internal stored SLA document data can be associated via variable binding.
- Check the number of returned traceability entries, confirming it meets the configured single traceability limit requirement.

The values provided are common starting points and should be evaluated against the reader's own samples.
