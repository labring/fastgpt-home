# Technical Documentation and API Q&A for Personal Information Protection Compliance: Citation Sources and Traceability

## What data in this category consists of
Data for this category originates from business systems, App permission lists, privacy policies, and user request records. Updates are triggered either quarterly or whenever product functions are modified. Daily generated documents include personal information lists, processing rules, impact assessment reports, and user authorization texts. Core fields include information type, processing purpose, legal basis, storage duration, and other relevant fields. Different document types have distinct formats, so citations must use corresponding fields matched to the document type.

## What constraints do these characteristics impose on citation sources and traceability
Dispersed data sources require association across multiple systems and document types to complete traceability, creating high requirements for citation scope precision. Update cycles are inconsistent, so regular synchronization of the latest compliance document versions is necessary to avoid compliance risks from citing outdated content. There is no unified document structure, so matching corresponding fields for different document types increases the difficulty of accurately locating citation snippets. Additionally, errors in this category lead to complaints or administrative penalties. Traceability results must be accurate and traceable; vague or incorrect citation sources are not acceptable.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | `1200–1800 token` | Matches the average length of core snippets in compliance documents, preventing truncation of key compliance fields |
| `responseData` | Only include core compliance document fields | Filters non-compliance-related data to simplify traceability workflows |
| `detail` | Include source file name + field name + original text snippet | Meets full traceability requirements for compliance audits |
| Data source synchronization frequency | Triggered by product changes + full synchronization every quarter | Matches the update cycle of this category to ensure cited content uses the latest version |
| Citation source identifier configuration | Automatically attach document ID and update time | Quickly locate data source versions to facilitate compliance traceback |

## Three common configuration errors
- Citation results include non-compliance document content. This occurs when the citation scope of `responseData` is not restricted, leading to the inclusion of unrelated data sources.
- Compliance fields are truncated and cannot be fully displayed. This occurs when `quoteMaxToken` is set too low, failing to match the length of core compliance document snippets.
- Workflow calls only support uploading compliance documents via external links, and cannot associate documents bound to local variables. This occurs when binding rules between citation sources and workflow parameters are not configured correctly.
