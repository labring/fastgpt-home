# Technical Documentation and API Q&A for Personal Information Protection Compliance: Knowledge Base Retrieval and Recall

## What data in this category looks like
Data for this category comes from business systems, App permission lists, privacy policies, and user request records. Daily documents include personal information inventories, processing rules, impact assessment reports, and user authorization texts. Each document focuses on personal information processing for a specific product or business scenario, and includes core fields such as processing purpose, storage period, and receiving entities. Update frequency follows a quarterly schedule, or is synchronized each time a product function is changed. All data is generated around personal information processing links that can identify natural persons.

## What constraints do these characteristics impose on knowledge base retrieval and recall
The update rhythm of data in this category is strongly tied to product changes, and all content revolves around personal information processing that can identify natural persons. This creates multiple constraints for retrieval and recall. First, data updates must be synchronized with product function changes. The recall link must support incremental synchronization configuration to prevent expired personal information processing rules from being retrieved. Second, the range of document types is wide: from itemized personal information inventories to long-text impact assessment reports. The retrieval mode must adapt to documents with different structures. Third, the data involves compliance-sensitive content. Retrieval results must be strictly linked to compliance scenarios to avoid returning irrelevant or incorrect compliance information that affects audit efficiency.

## How to set configurations
This document is written based on FastGPT v4.17.0. The following are configuration recommendations for this category:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | `0.85–0.92` | Matches the semantic association strength of compliance documents in this category, filters low-relevance non-compliance content |
| `limit` | `Top 8 entries` | Controls the number of results returned in a single recall, avoiding excessive entries that increase compliance audit burden |
| `searchMode` | `semantic + fulltext` | Adapts to the document structure of this category, which includes both itemized inventories and long-text reports |
| `usingReRank` | `Enabled` | Improves retrieval ranking accuracy for long-text compliance reports, filters results with inflated semantic scores |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Supplementally expands retrieval keywords related to compliance, covering all scenarios of personal information processing |
| `collectionIds` | `Specify a dedicated collection for compliance documents` | Isolates compliance data from other business data, preventing irrelevant content from being recalled |

## Three common mistakes
- Phenomenon: The interface displays "No matching results found" or the knowledge base has no synchronized data. Cause: `collectionIds` is not correctly configured to point to the dedicated compliance document collection, or the database synchronization task is not triggered quarterly or after product changes.
- Phenomenon: Retrieval results with a semantic score below 0.9 and unqualified full-text retrieval scores are returned. Cause: No `similarity` threshold is set, or `usingReRank` is not enabled, failing to filter low-quality compliance-related results.
- Phenomenon: The interface continuously displays the "Retrieving" status with no response. Cause: The `limit` value is set too high, or dual-mode `searchMode` is enabled at the same time, causing excessive system resource occupation and timeout.

## How to confirm configurations are correct
- Perform a single retrieval test, input "personal information processing rules", and verify that all returned results come from the dedicated compliance document collection.
- Adjust the `similarity` threshold, confirm that results below the threshold are not returned, and verify that the filtering logic takes effect.
- Trigger a data synchronization after a product change, check whether newly added document entries in the knowledge base are correctly recalled.
- View the system retrieval logs, confirm that the `usingReRank` and `datasetSearchUsingExtensionQuery` configuration parameters are loaded normally.

The values given are common starting points and should be measured against the reader's own samples.
