# Technical Documentation and API Q&A for Cloud Host Provisioning and Resource Activation: Vector Models and Indexes

## What this category of data looks like
Data for this category primarily comes from cloud management platforms, order systems, IAM permission systems, and billing systems. Daily processed documents include resource activation forms, instance configuration sheets, account permission forms, and delivery confirmation forms. These documents contain fields such as instance specifications, network security group configurations, account permission scopes, and billing-related items. Units include vCPU cores, memory in GB, bandwidth in Mbps, and others. Data updates follow a real-time per-order rhythm. The system updates corresponding documents and system data immediately each time a resource is activated or configuration is changed.

## What constraints these characteristics impose on the vector models and indexes link
Multi-source data sources require indexes to support cross-system data association, to avoid siloed business information. Real-time, per-order update rhythms require indexes to support incremental synchronization, so new activated resource data can be covered without full index reconstruction. Diverse document structures require chunking logic to adapt to field combinations of different documents, to avoid splitting that breaks business semantics. Clear fields and units require retaining business identifiers during vector modeling, to ensure recall results match actual resource configurations. Additionally, the time-consuming specification verification link requires indexes to first recall high-match resource specifications and configuration items, to reduce subsequent manual verification costs.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the field lengths of resource activation forms and instance configuration sheets, to avoid splitting that breaks business semantics |
| Overlap Length | 100–200 characters | Covers cross-chunk configuration association information, such as descriptions of security group rules spanning chunks |
| Similarity Threshold | 0.75–0.85 | Meets the precise matching requirements for resource configurations, to avoid recalling unmatched specifications or permission items |
| Single Search Limit | Top 10 entries | Controls the number of recall results, to adapt to the scenario where operation and maintenance staff perform quick verification |
| maxToken | 4096 token | Adapts to the context length of cloud host configuration documents, to ensure complete transmission of business information |
| defaultToken | Calibrated via actual testing | Adapts to resource data scale across different private deployments, balancing recall efficiency and accuracy |

## Three common mistakes
- Symptom: Vector recall results include unmatched cloud host specifications, and account permission information cannot be correctly associated. Cause: Chunking logic is not configured for the exclusive business fields of resource activation forms and instance configuration sheets, leading to chunk splitting that breaks the association semantics between specifications and permissions.
- Symptom: After deploying FastGPT v4.17.0 locally, externally configured index models cannot be loaded, and a model loading failure prompt appears in the interface. Cause: Network permissions and addresses for model access are not correctly configured, and model input adaptation is not completed to match the field format of cloud host data.
- Symptom: Data recall anomalies occur after vector storage migration, and newly activated cloud host resources cannot be retrieved. Cause: Update rules for incremental synchronization indexes are not configured, and full reconstruction logic is still used, leading to new data not being properly indexed.

## How to confirm configurations are set correctly
- Upload a real resource activation form document, initiate a keyword search, and check whether the recall results include the corresponding instance specifications and configuration items.
- Simulate a new resource activation operation, wait for index synchronization to complete, then initiate a search to confirm that new resource information can be recalled normally.
- Adjust the similarity threshold or single search limit, and verify whether the number and matching degree of recall results meet business verification requirements.
- View the index monitoring panel to confirm that the execution status of incremental synchronization tasks and data update frequency match the real-time, per-order rhythm.
