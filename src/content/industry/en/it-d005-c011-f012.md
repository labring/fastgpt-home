# Technical Documentation and API Q&A for Cloud Host Provisioning and Resource Activation: Document Parsing and Chunking

## What Data for This Category Looks Like
Data for this category primarily originates from cloud management platforms, order systems, IAM permission systems, and billing systems. Commonly processed documents include resource activation forms, instance configuration tables, account permission application forms, and delivery confirmation forms. Most of these documents are structured Excel files, standardized PDFs, or work order forms.
Data updates follow the pace of individual orders: one single delivery corresponds to a separate set of documents. Core fields include instance specifications, deployment regions, image IDs, security group configuration items, and billing rules. Relevant units include vCPU cores, GB memory, billing cycles, and similar metrics.

## Constraints on Document Parsing and Chunking
The characteristics of this category of data impose multiple constraints on document parsing and chunking.
First, heterogeneous document formats from multiple system sources require support for structured Excel, standardized PDF, and free-form work orders. Parsing logic must adapt to the field structures of different formats.
Second, the real-time delivery update rhythm requires parsing processes to avoid excessive delays. Excessive delays will slow resource activation progress.
Third, core content focuses on resource configuration items. Chunking must retain field relevance, and avoid splitting a single configuration item into multiple independent chunks.
Fourth, some offline delivery documents use scanned formats. OCR support for text content extraction is required. Excel documents often include multiple sheets, so support for extracting sheet names as a chunking basis is needed.

## Configuration Settings
The following configurations are based on the FastGPT v4.17.0 parameter system:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | This category of documents focuses on resource configuration items. This length retains complete relevance of a single configuration item and avoids splitting across fields |
| `chunkSplitter` | Split by title + paragraph | Adapts to the structured title format of resource activation forms, and binds descriptions and parameters of the same configuration item into one chunk |
| `customPdfParse` | Enable OCR mode | Supports text recognition for scanned delivery confirmation forms, and resolves the issue of unable to extract content from scanned documents |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Covers the upload requirements of multi-instance configuration tables in a single batch, and prevents interception due to oversized files |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time of large-volume Excel configuration tables, and prevents parsing failure due to timeout |
| `chunkSettingMode` | Manual configuration | Allows adjustment of chunking rules for different document types (such as activation forms, permission forms) to adapt to multi-scenario requirements |

## Three Common Mistakes
- Scanned delivery confirmation forms only return image links after parsing, with no valid text content. The cause is that OCR mode for `customPdfParse` is not enabled, and only the PDF image layer is identified without extracting text.
- Parsed results for Excel resource configuration tables do not display sheet names, and only contain global content. The cause is that `chunkSplitter` is not configured to split by sheet dimension. Default global splitting leads to loss of sheet information.
- Parsing large-volume Excel configuration tables returns status code 504 with a request timeout prompt. The cause is that the value set for `PARSE_FILE_TIMEOUT_SECONDS` is lower than the actual parsing time, leading to early termination of the process.

## How to Verify Configuration Success
- Upload an Excel instance configuration table with multiple sheets, and check if parsed results include each sheet’s name.
- Upload a scanned offline delivery confirmation form, and check if parsed results extract text content from the scanned pages.
- Upload a test file under 1000 MB, confirm that upload and parsing processes are not intercepted, and that parsing time meets expectations.
- Adjust `chunkSize` to 600 characters and 1200 characters, and check if chunked results retain complete content for a single configuration item.

The values listed above are common starting points, and should be evaluated against samples from the actual deployment.
