# Technical Documentation and API Q&A for Cloud Billing and Cost Accounting: Document Parsing and Chunking

## What the data for this category looks like
The core data for this category comes from cloud billing systems, tag data, order systems, and resource monitoring tools. Commonly processed documents include billing details, cost allocation tables, resource utilization reports, and optimization suggestion sheets. Data updates occur daily or monthly. Most document structures include fields such as resource identifiers, cost values, timestamps, and associated tags. Field units include yuan, hours, GB, and others. Some reports include multi-level nested allocation details.

## Constraints on document parsing and chunking
Documents in this category often include structured fields and nested details. Preserve field associations when chunking to avoid losing the ability to restore cost allocation logic after splitting. Data sources include tags and resource monitoring data. The parsing process must fully retain contextual information for tag values and resource identifiers. Data updates occur daily or monthly, so support is needed for documents of varying sizes. Daily billing details may grow longer as resource volume increases. Balance chunk length and contextual completeness. Support parsing logic for multi-level nested reports to avoid losing allocation hierarchy information.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Documents in this category often include nested details and structured fields. This range preserves complete contextual information for a single cost or allocation entry, avoiding broken associations after splitting |
| `chunkSplitter` | Separate by paragraphs and page headers/footers | Billing documents often include fixed page headers and multi-level allocation paragraphs. Separating by paragraphs preserves the integrity of individual allocation logic |
| `customPdfParse` | Enable structured parsing mode | Cloud billing PDFs are often standardized report formats. Enabling this mode accurately extracts fields and nested hierarchies, avoiding loss of detailed data |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Monthly summary bills may include large numbers of detailed entries. This upper limit supports full billing document upload requirements for most enterprises |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large monthly bills take longer to parse. This duration prevents parsing interruptions due to timeout |
| `chunkSettingMode` | Manual configuration | Adjust chunking parameters for different types of billing documents. Manual configuration adapts to the unique needs of structured reports and detailed lists |

## Three Common Configuration Errors
- Symptom: After uploading a monthly billing PDF, the chunk preview returns an error that the file content cannot be read. Cause: The structured parsing mode for `customPdfParse` was not enabled. The default general parsing cannot adapt to the format of standardized billing reports.
- Symptom: When deploying FastGPT v4.8.12 locally, parsing cost formulas in bills fails to return results normally. The online v4.9.0 version can parse normally. Cause: Some versions of FastGPT up to and including v4.17.0 have inconsistent compatibility logic for PDF structured formulas, leading to failure to correctly extract complex cost calculation formulas.
- Symptom: After configuring a Feishu knowledge base, PPT and PDF format billing documents cannot be synced. Cause: The document sync permission scope of the Feishu knowledge base was not confirmed, or parsing support for the corresponding file formats was not enabled.

## How to Verify Successful Configuration
- Upload a standard monthly billing PDF. Check if the chunk preview fully extracts cost details and allocation hierarchies, with no missing fields or broken splits.
- Adjust the `chunkSize` parameter, then re-upload the same document. Compare the contextual completeness of the chunk results to confirm the parameter takes effect.
- Upload a large billing document under 1000 MB. Wait for parsing to complete, then check for timeout errors to confirm the `PARSE_FILE_TIMEOUT_SECONDS` setting is appropriate.
- Try uploading a PPT format cost optimization suggestion sheet. Confirm it can be synced normally and chunked content is generated, to verify file format support.

The values provided are common starting points and should be evaluated against the reader's own samples.
