# Technical Documentation and API Q&A for Cloud Resource Compliance Audit: Citation Sources and Traceability

## What this category of data looks like
This category draws data from cloud audit logs, IAM permission systems, CMDB resource inventories, and security baseline scan results. Daily output documents include compliance checklists, permission audit reports, resource inventory lists, and rectification tracking forms. Data updates occur monthly or quarterly. Document fields include resource ID, permission configuration items, compliance status, scan time, and rectification responsible person. Most units are non-quantified, or labeled by resource type. The overall structure centers on compliance items to link resources and operation records.

## What constraints do these characteristics impose on the "citation sources and traceability" link
Data sources for this category are scattered across multiple cloud service systems. Link unique identifiers from different systems for citation and traceability to avoid resource confusion. Data updates occur monthly or quarterly. Clearly mark the source data’s update cycle when citing to ensure timeliness aligns with compliance audit requirements. Daily documents are structured around compliance items. Bind resource information, permission configurations, and scan records corresponding to specific compliance items for traceability. The rectification evidence verification process takes significant time. Quickly locate original scan or log data via citation traceability to support audit result traceability. Consequences of audit failure or unauthorized access are severe. Ensure accurate data matching in the traceability link to avoid cross-cycle data confusion.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average content length of compliance documents in this category, avoids truncating key compliance items and resource identifiers |
| `responseData` | Return only resource ID, compliance status, and scan time fields | Streamlines traceability content, adapts to internal audit teams' need to quickly verify rectification evidence |
| `detail` | Enabled | Adds associated fields from original cloud audit logs, supports traceability needs for permission anomaly identification |
| Single citation count | Top 3 entries | Matches the standard data volume of monthly compliance audits, avoids information overload |
| Citation source update cycle marking | Fill in according to the actual update cycle of the source data | Clarifies data timeliness, meets documentation requirements for compliance audits |

This configuration applies to FastGPT v4.17.0.

## Three common configuration errors
- Phenomenon: After workflow invocation, the answer displays the input and response content from knowledge base search. Cause: Non-essential traceability fields were not disabled in the configuration, resulting in redundant information being included in the answer.
- Phenomenon: The reference variable dropdown box for the knowledge base search node is empty, making it impossible to select a dynamically specified knowledge base. Cause: A variable for the corresponding knowledge base ID was not created in global variable configuration, or the variable scope does not cover the current workflow node.
- Phenomenon: Cited traceability data does not match the current audit cycle, with cross-quarter old data appearing. Cause: A source data update cycle filter condition was not specified in the configuration, resulting in cross-cycle data being retrieved.

## How to confirm the configuration is correct
- Initiate an API Q&A related to compliance audits, check that the answer only contains necessary traceability information, with no redundant input or response content.
- Test selecting variable references in the knowledge base search node of the workflow, confirm that the target variable appears in the dropdown options.
- View the update time mark of traceability data, confirm that it matches the update frequency of the current audit cycle.
- Trigger a Q&A for abnormal permission identification, check that the resource ID and permission configuration items included in the traceability data correspond correctly.
