# Technical Documentation and Interface Q&A for Enterprise Software License Management: Citation Sources and Traceability

## What the data for this category looks like
The data for this category comes from software asset management systems, procurement systems, terminal scan results, and vendor authorization documents. Daily maintained documents include license ledgers, software usage lists, procurement contracts, and compliance audit reports.
Data update frequency is monthly or quarterly. Structured data is stored in table format, including fields such as license number, authorized quantity, effective date, expiration date, and number of associated terminals. Unstructured data includes scanned authorization documents and PDF-format procurement contracts. There are no universal standard units for fields. Match corresponding identifiers based on document type.

## What constraints do these characteristics impose on citation and traceability
The data characteristics of this category impose four constraints on the citation and traceability process:
1.  The data includes structured ledgers and unstructured scanned documents. Support for both structured field matching and unstructured text indexing is required.
2.  The update frequency is monthly or quarterly. Real-time synchronization configuration is unnecessary. Batch import update methods can be adopted.
3.  There are no universal standard units for fields. Retain the original field structure during citation to avoid traceability errors caused by unit mismatches.
4.  Compliance audit requirements demand precise traceability. Citation content must be bound to specific entries in the original files.

## Configuration Settings
This document is written based on FastGPT v4.17.0. Specific configuration items and recommendations are as follows:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average content length of enterprise software license-related documents, ensuring complete citation content |
| `responseData` | Enabled | Retains complete data from the original citation source, supporting traceability requirements for compliance audits |
| `detail` | Display fields and source path | Clearly shows specific fields and file sources of citation entries, meeting compliance requirements |
| Number of citation recall entries | Top 3–5 entries | Data entries for this category are relatively concentrated. Excessive recall will interfere with core answer generation |
| Batch import frequency | Executed monthly | Matches the monthly update rhythm of data for this category |

## Three Common Misconfigurations
- Phenomenon: After setting citation association, the returned results do not display license-related content in the knowledge base. Cause: The structured ledger fields exported from the software asset management system are not mapped to the index fields of the knowledge base. This causes the question answering system to fail to match corresponding entries.
- Phenomenon: Only text-format ledgers in the knowledge base are cited. Scanned vendor authorization documents are not recalled. Cause: OCR indexing configuration for unstructured files is not enabled. The system cannot recognize text content in scanned documents.
- Phenomenon: The interface shows that knowledge base content is cited, but the generated answer has no connection to the cited content. Cause: `quoteMaxToken` is set too small. The cited content is not loaded into the model context. This prevents the model from generating matching answers based on the cited content.

## How to Confirm Proper Configuration
- Upload a test license ledger entry. Initiate a query that includes the license number. Check if the citation source of this entry is included in the returned results.
- Click the citation details in the returned results. Confirm that the displayed field information matches the original ledger, and the source path points to the correct imported file.
- Upload a scanned vendor authorization document. Initiate a query that includes the authorization number. Verify that the authorization information in the scanned document is correctly cited.
- Adjust the value of `quoteMaxToken`. Confirm that the length of the returned citation content changes with the configuration. Verify that the configuration takes effect.

The values provided are common starting points. They should be evaluated against the reader's own samples.
