# Technical Documentation and API Q&A for Crowdsourced Annotator Management: Source Citation and Traceability

## Data Profile for This Category
The data for this category originates from crowdsourcing platforms, annotation quality records, training exam logs, and financial systems. Daily documentation covers personnel access rules, training materials, performance sheets, and settlement lists. Data updates occur either daily or monthly. Included fields are unique personnel identifiers, access review status, training assessment scores, quality ratings, settlement amounts, and additional relevant fields. There is no unified mandatory format, and adjustments are made based on individual project requirements.

## Constraints on Source Citation and Traceability
These data characteristics create multiple constraints for source citation and traceability. First, data sources are dispersed. Personnel information from crowdsourcing platforms, quality inspection results from annotation data, training records, and financial settlement data must be associated. Traceability requires matching unique identifier fields across multiple systems. Second, update frequencies vary. Real-time association is required for daily updated performance data. Regular synchronization is needed for monthly updated settlement data. Missing cross-source synchronization rules lead to delayed referenced data. Third, document structures are inconsistent. Differences exist in personnel information fields across projects. Field mapping rules must be configured to accurately link referenced sources. Fourth, settlement data includes sensitive fields. Traceability requires ensuring permission verification and data consistency to prevent citation errors.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 token` | Adapts to the typical length of personnel documents and performance sheets for this category, retains sufficient context for traceability |
| `responseData` | Enabled | Must return specific fields and data locations of referenced sources to meet quality inspection and settlement verification requirements |
| `detail` | Full | Must display full content of referenced data to facilitate verification of personnel performance ratings or settlement amounts |
| Cross-source field mapping | Match actual fields per project | Adapts to field differences across multi-system data for this category, ensures accurate association of multi-source data |
| Data update synchronization cycle | Adjust based on data source: set 1-hour sync for daily data, 24-hour sync for monthly data | Matches update frequencies of data for this category, avoids delayed referenced data, aligns with FastGPT v4.17.0 data source management logic |
| Maximum number of recalled entries | Top 5 entries | Controls the number of data sources returned in traceability, avoids information overload that impacts verification efficiency |

## Three Common Configuration Errors
- The interface shows citation markers, but returned content has no relation to the personnel management knowledge base. This occurs when correct data source association rules are not configured, leading to recall of irrelevant general data.
- Only text-based personnel documents are successfully cited. Performance and settlement data do not appear in traceability results. This happens when corresponding embedding and recall rules are not configured for non-text data sources.
- When calling an API to trigger a workflow, specified personnel management knowledge bases cannot be cited. Returned results lack expected traceability data. This is caused by failure to correctly pass the knowledge base ID to the workflow's context parameters.

## How to Confirm Proper Configuration
- Trigger a query related to personnel performance. Check if returned results include configured referenced source fields to confirm association rules are active.
- Open the citation traceability panel. Confirm all configured data source types are correctly recalled with no omissions.
- Compare returned referenced data with original knowledge base documents. Confirm content matching meets expected standards.
- Call the API interface. Check if the `responseData` field contains complete referenced source information.
