# Technical Documentation and API Q&A for Crowdsourced Annotator Management: Knowledge Base Retrieval and Recall

## What this category of data looks like
The data for this category mainly comes from crowdsourcing platforms, annotation quality statistics systems, annotator training and assessment records, and financial settlement systems.
Daily maintained documents include personnel access rules, pre-job training materials, monthly performance statistics tables, and settlement lists.
Data update cycles are mostly daily or monthly. Annotation quality data is updated daily along with task completion status. Settlement-related data is updated monthly per project batch.
Document fields include personnel qualification numbers, task completion volumes, assessment scores, settlement amounts, and others. There is no unified standardized format, and some documents contain nested fields.

## What constraints do these characteristics impose on the knowledge base retrieval and recall process
Multi-source data sources require retrieval to support associating multiple datasets. This avoids information silos.
Non-standardized document fields and nested structures require query logic optimization before retrieval. This adapts to field matching across different formats.
Mixed daily and monthly update cycles require the recall phase to support filtering results by update time. This ensures the latest access rules and settlement data are returned.
Sensitive fields related to personnel qualifications and settlement amounts require precise keyword matching during recall. This reduces irrelevant results.
Mixed retrieval of multiple document types requires proper setup of recalled entry counts and reranking rules. This ensures core business documents are displayed first.

## Configuration Settings
All following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.72–0.80` | Adapts to non-standardized document fields, balances precise matching and recall coverage, and avoids missing low-similarity key information related to personnel qualifications |
| `limit` | `Top 8 entries` | Covers multiple types of personnel management documents including access rules, performance tables, and settlement lists. Prevents too few results from failing to cover business scenarios |
| `searchMode` | `vector+keyword` | Balances semantic retrieval and keyword matching to meet retrieval needs for nested fields and non-standardized documents |
| `usingReRank` | `Enabled` | Reranks recalled multiple types of documents to prioritize high-priority results related to personnel qualifications and settlement rules |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Expands query terms and adds synonyms related to personnel management to adapt to qualification and performance keywords expressed in different ways |
| `collectionIds` | `Configured for exclusive annotator management datasets` | Limits retrieval to the exclusive dataset to avoid mixing irrelevant documents from other categories |

## Three Common Mistakes
- Retrieval result document links prompt `Only support .txt, .m` when clicked. The cause is that the uploaded document format is not supported. Only text formats are allowed for annotation rules and performance documents.
- After local deployment, personnel access rule documents from external sites cannot be synchronized. The cause is that the external data source synchronization parameters for the dataset were not configured correctly. The corresponding synchronization function was not enabled.
- When `similarity` is set to above `0.9`, some low-similarity but critical settlement list entries cannot be retrieved. The cause is that the threshold is set too high, filtering out weakly matched results that meet business requirements.

## How to Confirm Proper Configuration
- Run a retrieval targeting "personnel access rules". Verify that returned results include exclusive documents of this category and do not mix content from other categories.
- Adjust the `similarity` parameter range. Compare the number of retrieval results under different thresholds to confirm that all document types required for business are covered.
- After enabling `usingReRank`, check whether reranked results prioritize displaying high-priority performance and settlement-related documents.
- Verify the external data source synchronization function. Confirm that daily updated annotation quality data can be retrieved normally.

The values provided are common starting points and should be measured against the reader's own samples.
