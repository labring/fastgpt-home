# Technical Documentation and API Q&A for Trusted Innovation Replacement Adaptation: Citation Sources and Traceability

## What Data This Category Contains
This category’s data primarily comes from existing system inventories, domestic software and hardware directories, test environment data, and vendor public materials. Daily produced documents include adaptation inventories, compatibility test reports, migration plans, and issue logs. Fields cover software and hardware models, version numbers, compatibility status, test conclusions, and additional relevant details. Data updates follow individual project cycles or quarterly intervals. It is synchronized and refreshed after each adaptation task is completed or a directory is updated, to ensure coverage of currently deployed software and hardware stacks.

## Constraints Imposed on Citation Sources and Traceability
Data sources for this category are scattered, and update rhythms are inconsistent. This causes cited knowledge base entries to have timing discrepancies. The traceability link must clarify version matching rules, to ensure cited content aligns with the software and hardware versions of the current adaptation scenario. Daily document structures vary, and field weights differ across documents. The scope of cited content must be limited, to avoid introducing irrelevant information that interferes with Q&A results. Incorrect adaptation scenarios can lead to business system unavailability, migration delays, or unnecessary procurement costs. The traceability link must accurately link to original test or plan documents, to prevent adaptation risks caused by citing expired or invalid content.

## How to Set Configurations
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| Similarity Threshold | 0.75–0.85 | Documents in adaptation scenarios are highly specialized, requiring filtering of low-relevance redundant entries |
| Single Search Limit | Top 10 entries | Adaptation inventories and test reports have a limited number of entries, to avoid introducing irrelevant content |
| Maximum Context | 3000–4000 characters | Single blocks of adaptation documentation are lengthy, requiring retention of sufficient traceability information |
| `quoteMaxToken` | 1500–2000 token | Control the total length of cited content, to ensure responses are clear and traceability is complete |
| Citation Source Display | Full path plus version number | Adaptation scenarios require clear software and hardware versions to facilitate subsequent verification |
| Version Field Extraction | Enabled | In FastGPT v4.17.0, this configuration accurately extracts version information from documents |

## Three Common Misconfigurations
- Symptom: When associating a knowledge base with a configured application variable, directly filling in the knowledge base ID returns the same result as calling via a variable, but directly binding the ID triggers a parameter validation error. Cause: The permission scope of the variable was not configured correctly, causing the variable to fail to properly map to the traceability rules of the target knowledge base.
- Symptom: Mixed retrieval returns citation entries that include non-adaptation documents, and the number of results exceeds the preset limit. Cause: No targeted similarity threshold was set, and content unrelated to trusted innovation adaptation was not filtered.
- Symptom: Cited traceability information does not label software and hardware versions, making it impossible to confirm the adaptation validity of the corresponding content. Cause: The version field extraction configuration was not enabled, and core verification information was omitted.

## How to Verify Proper Configuration
- Initiate a technical Q&A related to adaptation, and check whether cited sources in returned results match the current project’s adaptation inventory and test reports.
- Review whether cited content fields include core information such as software and hardware models and version numbers, to confirm traceability information is complete and meets requirements.
- Adjust the similarity threshold and run another test, then observe whether the number of returned citation entries matches expected values for the current scenario.
- Verify the scenario where an application variable binds a knowledge base, and confirm citation results are consistent with direct binding results and no error messages appear.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
