# Technical Documentation and API Q&A for In-Feed Ad Creative Testing: Citation Sources and Traceability

## Data Overview
Daily documentation for in-feed ad creative testing includes creative scripts, material test sheets, delivery data reports, and iteration checklists.
Data sources cover ad platform APIs, internal material libraries, user interaction data, and conversion data.
Update frequencies are divided into daily and weekly updates.
Document fields include material ID, copy content, delivery time slot, click-through rate, conversion cost, test group number, and other items.
The structure of different documents varies significantly.
Creative scripts focus on variable combinations.
Test sheets focus on quantified test results.
Delivery reports focus on overall delivery performance.

## Constraints for Citation and Traceability
Multi-source data and differentiated document structures require traceability systems to associate different types of document identifiers, to avoid confusing the sources of creative scripts and delivery data.
Daily and weekly update frequencies require the knowledge base to perform regular incremental synchronization, to ensure that traceability content matches the latest test results.
The time-consuming links of creative variable design and fatigue judgment require traceability to quickly locate corresponding document fragments, to reduce repeated search costs.
The serious consequences of material violations and increased conversion costs require traceability results to accurately match the question topic, to avoid returning irrelevant content that affects decision-making.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | Matches the total length of in-feed ad creative copy and test data, to avoid truncating critical information required for traceability |
| `responseData` | Return only document title, fragment text, source path | Adapts to the workflow needs of creative teams to quickly locate material documents |
| `detail` | Enabled | Retains complete document traceability fields, to facilitate troubleshooting of specific basis for material fatigue judgment |
| Single search limit | Top 5 entries | Filters redundant historical test data, focuses on content related to the current core creative test |
| Document chunk overlap length | 50–80 characters | Retains contextual connections between creative scripts and test sheets, to avoid losing variable combination information during traceability |
| Recall matching threshold | Calibrated based on actual testing | Filters non-creative related delivery data, accurately matches the topic of in-feed ad creative testing |

## Common Configuration Errors
- The knowledge base returns content unrelated to the query. This occurs when a reasonable recall matching threshold is not set, resulting in recall of non-creative related delivery data or general documents.
- Traceability information lacks document source paths. This occurs when the return fields of `responseData` are not configured correctly, only returning text fragments without associating source identifiers.
- Traceability content is truncated and cannot fully match creative variables. This occurs when the value of `quoteMaxToken` is set too small, truncating key fields such as conversion cost or test group number in the test sheet.

## How to Verify Correct Configuration
- Submit a query that includes specific creative variables, and verify that returned results are associated with the corresponding creative script or test sheet document.
- Review the traceability module located below the answer, and confirm that it includes complete information of document title, source path, and fragment text.
- Test a query unrelated to creative testing, and confirm that no matching results are returned.
- In FastGPT v4.17.0, confirm that the `detail` parameter is enabled to ensure complete traceability fields.
