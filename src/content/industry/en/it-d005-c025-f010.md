# Technical Documentation and Interface Q&A for Shift Scheduling and Handover: Source Citation and Traceability

## What This Category of Data Looks Like
Core data for this category comes from scheduling systems, fault work orders, monitoring alerts, and organizational contact directories. Daily documents include standardized shift schedules, cross-shift handover records, escalation contact lists, and daily shift reports. Fields cover shift time periods, pending items, emergency contacts, alert response paths, and additional relevant details. Data updates occur on a daily or weekly basis, with real-time or scheduled information refreshes triggered by shift rotations, fault changes, or personnel adjustments.

## What Constraints Do These Characteristics Impose on Source Citation and Traceability
Data for this category originates from multiple sources and has flexible update rhythms. Source citation and traceability require clear labeling of data source types to avoid mixing alert information from fault work orders with shift scheduling arrangements from shift schedules. Fixed document structures require matching corresponding document types during retrieval to ensure cited fields such as shift time periods and handover items are accurately aligned. Frequently or regularly updated data requires synchronized refreshes of knowledge base data source versions to prevent use of outdated shift schedules or contact information. Failure to do so may lead to business issues including unassigned responses or missed handovers.

## Configuration Settings
All configuration settings below are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Core documents for this category (shift schedules, handover records) have moderate per-document length. This range covers complete shift scheduling and handover content for a single shift, avoiding truncation of critical information |
| `responseData` | Return data source type, document ID, update time | This category of data comes from multiple sources and requires traceability. Explicitly returning these fields enables quick location of the source and timeliness of cited content |
| `detail` | Enable full field display | Documents in this category include key fields such as shift time periods and pending items. Full field display ensures accuracy of handover and scheduling information |
| Similarity Threshold | `0.6–0.7` | Retrieval content for this category mostly consists of structured scheduling data. This range filters low-relevance non-scheduling documents and improves matching accuracy |
| Single Search Limit | Top 3 results | Core information for this category is concentrated in a single shift schedule or handover record. Too many results increase model filtering costs and may introduce irrelevant content |
| Maximum Context | `1500–2000 token` | Shift schedules, handover records, and escalation contact information must be loaded simultaneously. This range covers complete associated information and ensures completeness of model responses |

## Three Common Configuration Mistakes
- Phenomenon: Retrieval fails to match the target shift schedule and returns irrelevant fault work order content. Cause: No document type filtering is configured, and no reasonable similarity threshold is set, causing non-scheduling data to be recalled first.
- Phenomenon: Cited shift information is outdated and fails to match the current shift schedule. Cause: Knowledge base data source versions are not refreshed regularly, and shift schedules updated weeks prior are cited.
- Phenomenon: Cited content is truncated after configuring `quoteMaxToken`, and pending handover items are lost. Cause: The set token range is too small and fails to cover the complete length of a single handover record.

## How to Verify Proper Configuration
- Initiate a retrieval for the current shift schedule, and check that the returned result data source types are shift schedules or handover records.
- Review the update time of cited content, and confirm that it matches the current system's shift schedule update time.
- Adjust the values of configuration items, and verify that the returned cited content fully covers required fields such as shift time periods and handover items.
- Test multi-source data retrieval, and confirm that different types of documents (such as shift schedules, alert records) are correctly distinguished and not confused during citation.

The values provided are common starting points and should be evaluated against relevant samples for the target deployment.
