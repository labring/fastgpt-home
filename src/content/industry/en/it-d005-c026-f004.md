# Technical Documentation and Interface Q&A for Level Content Creation: Vector Models and Indexes

## What data looks like for this category
Level content creation data typically comes from level editors, art resource libraries, player test data, and defect tracking systems. Daily output documents include level design drafts, resource requirement lists, test feedback sheets, and version submission records. Common fields include level ID, resource path, test time, defect severity, and submitter information.
Data updates occur weekly or per version iteration. The volume of a single update varies based on level scale. Some large-level design drafts exceed 10,000 characters.

## Constraints on vector models and indexes
Scattered data sources and fixed update schedules for level content creation require index systems to support incremental updates for weekly or per-version iterations. Different document types have wide structural differences. Chunking strategies must accommodate content ranging from short test feedback sheets to long level design drafts.
Data fields contain many game-specific paths, IDs, and test tags. Vector models must accurately recognize semantic connections for these domain-specific terms. Level content errors directly impact player experience, so index recall accuracy must be prioritized. Low-relevance results must be avoided to prevent interference with planner debugging work.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the single-page content length of level design drafts, prevents overly long single chunks from losing semantic coherence |
| Overlap Length | 100–200 characters | Covers continuous content across chunks such as level paths and resource placements, prevents semantic breaks that harm retrieval performance |
| Similarity Threshold | 0.75–0.85, calibrated via actual testing | Filters low-relevance content in test feedback sheets and defect records, accurately matches core information related to levels |
| `maxToken` | 4096 token | Adapts to the input limit of general embedding models, prevents long text level design drafts from being truncated and losing key rules |
| Single Search Limit | Top 10 results | Controls the number of returned level-related resources, avoids context overload that reduces debugging efficiency |
| `defaultToken` | 1024 token | Sets the default single-segment index text length, unifies basic configuration standards, and reduces configuration complexity for new users |

## Three common configuration errors
- Phenomenon: Retrieval similarity values are abnormally high after replacing the embedding model. Cause: The similarity threshold matching logic is not adjusted. The original model's score calculation benchmark is retained, so the new model's score range does not match the original configuration.
- Phenomenon: No index progress is displayed after uploading level data to the knowledge base, or index failure is reported upon completion. Cause: Vector database connection parameters are not configured correctly, or resource path fields in level data contain invalid characters that cause parsing failures.
- Phenomenon: Valid indexes cannot be generated after source code deployment. Cause: MongoDB, vector database, and sandbox services are not started simultaneously, so index storage and execution environments cannot link properly.

## How to verify proper configuration
- Upload a typical level design draft, confirm FastGPT v4.17.0 completes index progress within 1 minute with no error logs output.
- Enter a query term related to level resources, check that returned results include matching resource paths, test feedback sheets, and other associated content.
- Adjust the similarity threshold, verify that low-relevance test records are filtered correctly, and high-relevance level design content is retained.
- Log in to the vector database management interface, confirm that vector entries for the uploaded level data exist, and the entry count matches the number of uploaded documents.
