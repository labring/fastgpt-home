# Technical Documentation and API Q&A for Level Content Creation: Source Citation and Traceability

## What This Category of Data Looks Like
Level content creation data typically comes from four sources: level editors, art resource libraries, player test data, and defect systems. Daily produced documents include level design drafts, resource requirement sheets, test feedback forms, and version submission records.
Level design drafts contain fields such as path node coordinates and trigger conditions. Resource requirement sheets mark resource types and delivery milestones. Test feedback forms record BUG locations and reproduction steps. Version submission records include submitter information, modification times, and change details.
Data updates follow a weekly or per-version rhythm. Content structure is adjusted continuously as levels are iterated.

## Constraints on Source Citation and Traceability
Data for level content creation is spread across multiple types of systems. Traceability configurations must support association and matching of multi-source data to prevent cross-system information misalignment.
Data updates follow a weekly or per-version rhythm. Incremental synchronization mechanisms must be configured to ensure cited content uses the most recently submitted version.
Document fields include structured information such as coordinates and resource IDs. Precise field identification matching is required during traceability to avoid confusing resources and paths across different levels.
Test feedback forms and version submission records have strong connections. Associated query logic must be configured to ensure cited feedback corresponds to the correct level modification records.

## Configuration Settings
These configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 900–1100 token | Adapts to the average content length of a single level design draft, avoids truncating critical information such as path nodes and trigger conditions |
| `responseData` | Return only specified fields | Filters non-core test log data, retains only traceability-required fields such as resource IDs, level coordinates, and submission version numbers |
| `detail` | Enable full traceability | Displays the source system and update time of data, meets version traceability requirements for content creation |
| Number of citations returned | Top 4 entries | Matches the upper limit of resources associated with a single level, avoids excessive citations that confuse level logic |
| Incremental synchronization cycle | Every 24 hours | Adapts to weekly or per-version update rhythms, ensures traceability data uses the most recently submitted version |

## Common Configuration Errors
- A POST request succeeds, but no content is returned: The cause is incorrect configuration of the `responseData` parameter. Core content fields are filtered, resulting in only an empty response body.
- Cited thought processes have messy formatting and garbled text: The cause is that formatted output for the `detail` parameter is not enabled, and correct character encoding adaptation rules are not configured. Traceability information is directly concatenated, leading to encoding errors.
- Knowledge base original links cannot be accessed normally: The cause is incorrect configuration of nginx proxy for knowledge base path mapping. Traceability links point to the wrong local storage location, making original content inaccessible.

## How to Verify Correct Configuration
- Send a test request, check if returned results include the configured core traceability fields. This confirms the `responseData` parameter is active.
- View the citation module in the response, check if complete source information is displayed. This verifies the `detail` parameter configuration is correct.
- Click the cited original link, confirm normal navigation to the corresponding knowledge base content. This verifies the proxy configuration is correct.
- Adjust the `quoteMaxToken` parameter, check if critical level path information is truncated in the response. This confirms the setting adapts to the current content length.
