# Technical Documentation and API Q&A for Content Copyright and Authorization Management: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
The core data sources for this category are contract systems, copyright registration databases, official content libraries, and infringement complaint inboxes. Daily processed documents include authorization contracts, copyright ledgers, removal notices, and infringement complaint materials. Authorization contracts contain fields such as authorization scope, validity period, and authorized entities. Copyright ledgers record file authorization status and associated entities by entry. The size of a single authorization contract typically ranges from 500 to 2000 characters. Data updates follow per-business or monthly cycles. Significant differences in data volume exist across different document types.

## Constraints on Knowledge Base Retrieval and Recall
Scattered data sources require the retrieval process to support cross-system associated calls. This prevents fragmented knowledge bases from failing to cover core documents such as authorization contracts and copyright ledgers. Unlike content review scenarios, this category focuses on retrieval of rights sources and authorization scopes. It does not need to cover large volumes of review rule text. Data updates follow per-business or monthly cycles. This means the knowledge base incremental update rhythm must align with the business cycle. This avoids resource consumption from frequent updates or authorization scope verification errors caused by delayed data. Differences across multiple document types require retrieval strategies to adapt to varying text lengths. Core fields such as authorization scope must be assigned higher retrieval weights. This ensures retrieval accuracy for core information and reduces error risks for infringement investigations or authorization verifications.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | The core retrieval field for this category is authorization scope. Low-match results must be filtered to avoid interference from irrelevant infringement materials or expired contracts |
| `limit` | `Top 8–12 entries` | Authorization-related documents involved in a single round of business typically fall within this range. Too many results increase subsequent verification time |
| `searchMode` | `Semantic retrieval + keyword hybrid` | Both structured fields in authorization contracts and unstructured text in infringement complaints must be covered. Hybrid mode balances accuracy and recall rate |
| `usingReRank` | `Enabled` | This category has high matching accuracy requirements for authorization scope. Reranking optimizes the sorting logic of retrieval results and improves the display priority of core information |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Extended queries can cover synonyms and industry terms for authorization scope, adapting to professional expressions in the copyright field |
| `collectionIds` | `Specify copyright management exclusive collection` | Isolate business data from knowledge bases of other categories. This avoids retrieval of irrelevant content and ensures retrieval efficiency and data security |

## Three Common Misconfigurations
- Phenomenon: Semantic retrieval returns scores outside the 0–1 range, with values reaching thousands. Cause: The normalization logic for the `similarity` parameter is not configured correctly, or non-normalized similarity calculation methods are mixed, resulting in abnormal scores.
- Phenomenon: No file information associated with the current retrieval is obtained after calling the API. Cause: Result traceability configuration is not enabled, or the `collectionIds` parameter is not specified to limit the retrieval scope. This causes the system to fail to match the metadata of the corresponding file.
- Phenomenon: Expired information from old authorization contracts is still retrieved after knowledge base incremental updates. Cause: The knowledge base synchronization frequency is not adjusted according to the business update cycle, or expired authorization status fields are not filtered during retrieval.

## How to Verify Correct Configuration
- Run a test retrieval, enter authorization scope keywords, and check if the `similarity` scores of returned results meet business requirements. Adjust the value range as needed.
- Call the API interface, verify that returned results include metadata information for associated files. Confirm that the result traceability configuration is active.
- Simulate a monthly update operation, check if the knowledge base synchronizes the latest copyright ledger and authorization contract data according to the 30-day business cycle.
- Test the hybrid retrieval mode, verify that retrieval results combining semantics and keywords cover documents related to authorization scope and infringement complaints.

The values provided here are common starting points. They should be evaluated against the reader's own samples.
