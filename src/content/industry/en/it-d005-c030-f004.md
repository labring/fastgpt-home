# Technical Documentation and Interface Q&A for Internal Network and WiFi Operations: Vector Models and Indexes

## What the data for this category looks like
The core users of this category are network administrators, desktop support staff, and on-site outsourced operations personnel. Data originates primarily from switch consoles, wireless controllers, network monitoring systems, and frontline user trouble reporting channels. Daily produced documents include network topology diagrams, change approval forms, fault troubleshooting records, wireless coverage inspection forms, and similar materials. Data updates occur either daily or immediately following network changes. Most fields include device port numbers, VLAN configurations, signal strength values, inspection timestamps, and other relevant data. Units of measurement include Mbps, dBm, port numbers, dates, and others.

## Constraints imposed on vector models and indexes by these characteristics
Documents such as network topology diagrams and change forms have significant structural differences. Some contain both visual graphic descriptions and plain text configuration items. When splitting text chunks, balance the integrity of graphic descriptions and text fields to avoid losing key configuration associations after splitting. Fields like device ports and VLANs have strict accuracy requirements. Vector indexes must preserve relationships between fields to prevent incomplete configuration restoration after splitting. The daily or immediate update frequency requires index update mechanisms to adapt to high-frequency changes. At the same time, limit the processing scale of single-batch indexes to avoid excessive consumption of operations resources. Fault records and inspection forms have wide text length variation, ranging from short user trouble reports to detailed troubleshooting steps. This necessitates adaptive chunking rules for different text lengths.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the average length of texts such as network topology diagram descriptions and fault records, avoiding loss of configuration associations after splitting |
| Overlap Length | 100–200 characters | Retains contextual associations of key configurations such as VLANs and ports between adjacent chunks |
| Similarity Threshold | 0.75–0.85 | Filters low-match irrelevant operations documents, ensuring the accuracy of fault location and port verification results |
| Single Search Limit | Top 10 entries | Covers the number of documents for common operations scenarios, avoiding excessive redundant data returning that affects troubleshooting efficiency |
| `maxToken` | 8192 | Adapts to the input length limit of mainstream vector models, compatible with vectorization processing of long texts such as network topology diagrams |
| `defaultToken` | Calibrated based on actual measurements | Adapts to exclusive vector model call permissions for internal network operations scenarios, preventing token permission errors |

## Three Common Misconfigurations
- An interface returns the error "This token does not have permission to use the model". The cause is failure to configure a vector model channel adapted to internal network operations scenarios, or failure to correctly bind channel permissions to the current FastGPT instance.
- Knowledge base search takes longer than expected. The cause is excessively large chunk length or excessively high single search limit, failure to adapt to the hardware configuration of 8 cores, 64 GB memory, and RTX2070 graphics card, or failure to select a lightweight vector model.
- Key configuration fields are lost after chunk splitting. The cause is failure to adjust chunking rules for the structured characteristics of network operations documents, leading to key information such as ports and VLANs being split across different chunks.

## How to Confirm Configurations Are Correct
- Upload a typical network topology diagram document, and verify whether key configuration contexts such as ports and VLANs are retained after chunk splitting.
- Initiate a query related to fault records, and check whether the similarity of returned results falls within the preset threshold range.
- View model call logs in FastGPT v4.17.0, and confirm that no permission errors appear in vector model channel call requests.
- Simulate an index update after a network change, and verify whether update time meets the real-time requirements of operations scenarios.
