# Technical Documentation and Interface Q&A for Internal Network and WiFi Operations: Citation Sources and Traceability

This document is written based on the configuration rules of FastGPT v4.17.0.

## What the Data for This Use Case Looks Like
Core data for internal network and WiFi operations comes from switch consoles, wireless controllers, monitoring systems, and user trouble reporting channels. Daily produced documents include network topology diagrams, change orders, fault records, and wireless coverage inspection forms.

Topology diagrams annotate port numbers, VLAN IDs, and AP deployment locations. Change orders log change times and operators. Fault records mark fault durations and impact scopes. Inspection forms record signal strength values.

Data is updated daily or whenever a network change is completed. Fields include specific operational unit identifiers. Signal strength uses dBm as the unit. Ports use numbers as identifiers. There are no universal statistical percentage fields.

## Constraints on Citation Sources and Traceability
Data sources are scattered and heterogeneous. The traceability process must associate document entries from multiple systems. Recalling content from only a single data source will fail to cover complete operational basis.

Document structures vary widely. They include structured tables and mixed text and image content. Match chunking rules for different documents to ensure the integrity of cited passages. This prevents key port information from being missing in cited topology image passages.

Update frequency is high. Index updates must be synchronized with data changes. Citing outdated operational records may lead to incorrect fault localization.

Specific fields have strict precision requirements. Matching errors for VLAN IDs or port numbers will cause traceability failures. Lock retrieval rules for corresponding fields during the recall phase.

## How to Configure the Settings
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the length of valid single content items in operational documents, avoids recalled passages that are too short or too long |
| `responseData` | Includes fault records, change order data | Covers the most commonly used traceable document types in operational scenarios, meets fault localization and change traceability needs |
| `detail` | Enabled | Displays specific field information of cited documents, such as AP locations and port numbers, improving traceability credibility |
| Maximum number of citations | Top 3–5 entries | Avoids excessive citations interfering with conversation logic, focuses on core operational basis |
| Context association duration | 24 hours | Matches daily operational change and fault handling cycles, associates related records from the same time period |

## Three Common Configuration Errors
- Symptom: Unconfigured citation file links are automatically appended to the bottom of responses. Cause: The default setting for automatically displaying citation sources was not disabled, leading to redundant information interfering with operational conversations.
- Symptom: Citations from previous round fault records or inspection records cannot be associated in multi-turn operational conversations. Cause: Correct context association parameters were not configured, leading to lost conversation context and inability to link operational data from the same scenario.
- Symptom: Cited document passages fail to match the field requirements of the current query, such as failing to find records for a specific VLAN ID. Cause: The `quoteMaxToken` value is too small, causing recalled document passages to not contain key operational fields.

## How to Verify Correct Configuration
- Initiate a troubleshooting query for a specific network fault. Check if the cited sources in the response point to the corresponding fault records or change orders, and include required operational fields such as port numbers or VLAN IDs.
- Initiate consecutive multi-turn operational queries, such as first querying the inspection record for a specific AP, then querying the fault history for that AP. Check if citations in each round are linked to context data from that round.
- Check for the presence of unconfigured redundant citation links in responses. Confirm that unnecessary citations have been disabled.
- Adjust the `quoteMaxToken` value. Verify that the length of cited passages meets expectations, and ensure that key operational information is covered.
