# Technical Documentation and Interface Q&A for Creator Incentive Settlement: Vector Models and Indexes

## What This Category’s Data Looks Like
FastGPT v4.17.0 data for this category typically originates from content data, advertising revenue sharing systems, financial systems, and account backends. Update cycles follow monthly or single campaign periods. Daily processed documents include incentive rules, settlement details, appeal records, and payment lists.
Settlement details include standardized fields such as creator ID, revenue amount, and settlement cycle. Incentive rules consist mostly of clause-based text. Appeal records include appeal reasons and processing results. Data fields and units follow general financial formats, with no custom units added.

## Constraints on Vector Models and Indexing
Monthly or campaign-level update cycles require indexes to support batch updates and incremental synchronization. This avoids resource consumption from full index rebuilds.
Mixed structured and unstructured data from multiple sources requires distinct chunking logic to preserve field associations. For example, row data in settlement details must fully retain creator IDs and corresponding revenue amounts.
Sensitive financial fields must not be truncated or split during vectorization. Search results must accurately match revenue calculation standards, to avoid incorrect associations across cycles or creators.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Matches the length of single-segment information in settlement details and incentive rules, avoids splitting cross-field content |
| Overlap Length | 100–200 characters | Preserves contextual association between chunks, avoids splitting consecutive clauses of incentive rules |
| Similarity Threshold | 0.75–0.85 | Enables accurate matching of revenue calculation standards, reduces probability of incorrect associations |
| `maxToken` | 4096 token | Adapts to long-text vectorization of incentive rule documents, avoids truncation of critical clauses |
| Single Search Limit | Top 10 entries | Covers query needs for multiple settlement details within a single settlement cycle |
| `defaultToken` | Calibrated via actual testing | Adapts to settlement detail formats exported from financial systems, ensures vectorization consistency |

## Three Common Configuration Errors
- After uploading settlement details in Excel format, vectorization completes but index results match records from unrelated creators. The cause is failure to unify document header fields. For example, writing "creator ID" as "ID" causes loss of field associations.
- After enabling the knowledge base search reference merge function, duplicate entries appear in results. The cause is overlap length configuration exceeding the reasonable range of chunk length, leading to repeated chunk merging.
- The knowledge base remains in indexing status after upload. The cause is failure to adjust `maxToken` to adapt to long documents, leading to timeout and stuck vectorization tasks.

## How to Verify Successful Configuration
- Upload a single standardized settlement details Excel file, check that vectorized chunks include complete creator ID, revenue amount, and settlement cycle fields.
- Submit a query request for revenue calculation standard verification, confirm that search result similarity matches meet the preset threshold, with no incorrect matches across creators or cycles.
- Upload a complete incentive rule document, check that no text truncation errors occur during vectorization, and confirm that the `maxToken` configuration takes effect.
- Wait for the indexing task to complete, confirm that the status changes from indexing to completed, with no timeout or format error prompts.

The values provided are common starting points and should be evaluated against local sample data.
