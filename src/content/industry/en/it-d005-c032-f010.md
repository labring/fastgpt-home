# Technical Documentation and API Q&A for Creator Incentive Settlement: Citation Sources and Traceability

## What the Data for This Category Looks Like
Daily documents for the creator incentive settlement scenario include four core content types: incentive rules, settlement details, appeal records, and payment lists. Data sources cover content data, advertising revenue sharing systems, financial systems, and account backends. Common data fields include creator identifiers, revenue accounting standards, settlement cycles, payment status, and more. Update rhythms vary with monthly settlement cycles or exclusive activities. Document structures mostly combine structured detailed entries and rule descriptions.

## Constraints on Citation Sources and Traceability
Field differences across multiple system sources require the traceability link to unify matching rules for creator identifiers and settlement cycles, to avoid cross-system data misalignment. Monthly or activity-level update rhythms require the knowledge base to synchronize update frequencies, to prevent referencing expired incentive rules or outdated settlement details. Documents are split into two categories: rules and details. Separate general traceability for basic rules from precise traceability for individual creator settlement data. Settlement dispute error consequences also require traceability information to be fully associated with specific batches and individuals, to ensure full traceability.

## How to Configure Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Similarity Threshold | 0.6–0.7 | Precisely match exclusive fields of creator settlement details, filter interference from general incentive rules |
| Single Recall Count | Top 3–5 entries | Corresponds to the number of settlement-related documents associated with a single creator, avoid redundant citations |
| `quoteMaxToken` | 800–1200 token | Cover the complete field content of a single settlement detail, ensure no missing traceability information |
| `responseData` | Enable structured return | Retain identification fields of original data, facilitate association between creators and settlement batches |
| `detail` | Enable detailed traceability | Display associated information of appeal records and payment lists, support abnormal fraud investigation |
| Knowledge Base Update Frequency | Synchronize with settlement cycle | Match data update rhythm, avoid referencing expired rules or details |

## Three Common Configuration Errors
- Phenomenon: The configured single recall count does not take effect, and returned traceability entries exceed the set value. Cause: The setting was only modified in the frontend interface, and the corresponding parameters were not synchronized in the API call parameters, resulting in the frontend modification not actually taking effect.
- Phenomenon: When obtaining corpus only through API calls, the answer source cannot be displayed. Cause: Structured return for the `responseData` parameter was not enabled, and the source identification of the original data was not included, making it impossible to associate with specific settlement documents.
- Phenomenon: The similarity threshold is set too low, and required settlement details cannot be recalled. Cause: When the threshold is lower than 0.5, a large number of irrelevant general incentive rules will be matched, making it impossible to accurately locate the exclusive settlement data of the target creator.

## How to Verify Proper Configuration
- Initiate a test call for the creator incentive settlement scenario, check whether the returned results include traceability information of exclusive fields such as creator ID and settlement cycle.
- Check the number of traceability entries in the returned results, confirm that it matches the set single recall count.
- Verify that the `quoteMaxToken` parameter takes effect, check that the token length of the traceability content does not exceed the set range.
- Manually adjust the similarity threshold, observe whether the recalled document list changes correspondingly with the threshold adjustment.

The values provided are common starting points and should be measured against the reader's own samples.
