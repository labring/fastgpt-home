# Technical Documentation and API Q&A for Frontend Application Development: Knowledge Base Retrieval and Recall

## What this category of data looks like
The data for this category primarily comes from code repositories, API management platforms, design draft systems, and browser compatibility databases. Daily produced documents include API definitions, component parameter descriptions, joint debugging logs, and version release lists. Content covers structured API fields, component attributes, compatibility adaptation rules, and unstructured joint debugging problem records.
Data update frequency is mostly daily or upon each version release. Common fields include API paths, request methods, parameter types, and compatible terminal versions. Common units include characters, version numbers, and terminal model identifiers.

## Constraints for knowledge base retrieval and recall
This category’s data has high update frequency and scattered sources. Knowledge base retrieval and recall must support incremental synchronization and multi-source data access. This prevents outdated API documents or joint debugging logs from being retrieved.
The data includes structured API fields and unstructured joint debugging logs. The system must support content splitting and vector generation for different formats. This ensures key information such as API parameters and compatibility rules is retrieved accurately.
Frontend developers focus heavily on terminal compatibility. Retrieved results must prioritize content adapted to specific browsers and mini-program versions. This avoids returning configuration information that is incompatible across versions.

## Configuration Settings
These configurations apply to FastGPT v4.17.0, optimized for frontend application development scenarios:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the precise matching needs of API parameters and compatibility rules in frontend documents. Filters low-relevance joint debugging log content |
| `limit` | Top 8–12 results | Balances result density for joint debugging and component query scenarios in frontend development. Avoids excessive results that increase screening costs |
| `searchMode` | Semantic + keyword hybrid retrieval | Adapts to mixed content scenarios in frontend documents, which include both structured API parameters and unstructured joint debugging logs |
| `usingReRank` | Enabled, re-rank and take top 4–6 results | Performs secondary sorting on initial retrieval results. Prioritizes content matching high-frequency query keywords such as API paths and component names |
| `datasetSearchUsingExtensionQuery` | Enabled | Supplements scenario-specific terms frequently used in frontend development. Improves the accuracy of query retrieval |
| `collectionIds` | Bind frontend-exclusive knowledge base ID | Isolates frontend team API documents and compatibility data from knowledge base content of other categories |

## Three Common Mistakes
- Phenomenon: Chinese file names display garbled characters when calling the API to upload knowledge base files. Cause: The `Content-Type` request header is not configured as `multipart/form-data` with UTF-8 encoding. This causes the file name encoding to fail correct parsing.
- Phenomenon: Retrieved results include backend service document content after enabling `datasetSearchUsingExtensionQuery`. Cause: The retrieval knowledge base scope is not limited via `collectionIds`. This leads to cross-category data being retrieved.
- Phenomenon: Notion-linked documents cannot be indexed successfully. Cause: Team access permissions for Notion documents are not enabled, or the corresponding data source synchronization key is not configured in FastGPT. This prevents document content from being crawled.

## How to Confirm Configurations Are Correct
- Upload a test file with a Chinese file name. Call the FastGPT file upload API. Check the knowledge base file list to confirm the file name displays correctly.
- Submit a query that includes "browser compatibility" or "component parameters". Verify that retrieved results prioritize frontend-related API documents or compatibility data.
- Temporarily adjust the `similarity` threshold below 0.7. Confirm that low-relevance joint debugging log content appears in the result list.
- Confirm that after binding `collectionIds`, documents from non-frontend categories do not appear in retrieved results.

The values listed here are common starting points. They should be evaluated against the reader’s own samples.
