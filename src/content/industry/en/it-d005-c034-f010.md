# Technical Documentation and Interface Q&A for Office System Process Configuration: Citation Sources and Traceability

## What this category of data looks like
Data for this category originates primarily from enterprise OA systems, organizational structure repositories, internal policy documents, and user feedback. Regularly produced documents include process configuration sheets, approval node tables, form field descriptions, and change records.
Data updates in real time when process configurations change. Monthly update volumes fluctuate based on business adjustments.
Data fields include approval node permission rules, form associated fields, change approver information, and other relevant details. No unified fixed units apply; values vary based on the specific configuration item type.

## Constraints on citation and traceability workflows
This category’s data sources are scattered and have diverse structures. Citation traceability must cover multiple data types including OA system configuration data and internal policy texts.
Data updates in real time as process configurations change. Traceability content must match the currently active configuration.
Field logic varies significantly across different documents. Precise matching between configuration items and corresponding source paragraphs is required.
Incorrect traceability may lead to approval permission deviations or process execution issues. Strict association between configuration change records and cited content is necessary to avoid execution deviations.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the average length of single documents such as process configuration sheets and approval node tables, ensuring complete citation of configuration rules |
| `responseData` | Enabled | Used to return citation source metadata, matching the traceability requirements of office system process configurations |
| `detail` | Full | Displays the full context of cited content, facilitating verification of approval node permissions and form field rules |
| Citation Display Position | End of answer paragraph | Aligns with enterprise administrator habits for viewing traceability, and matches the default display logic of FastGPT v4.17.0 |

## Three common configuration errors
- Only returning citation metadata without core response content: This occurs when `quoteMaxToken` is set too small, truncating the core content of the configuration description and only retaining source identifiers.
- Failure to associate process configuration context across multi-turn conversations: This occurs when conversation context recall configuration is not enabled, and historical query process configuration information is not included in the current retrieval scope.
- Citation function not working or not displayed at the end of paragraphs under guest share links: This occurs because FastGPT v4.9.6 and earlier versions disable guest citation functionality by default. For versions v4.9.7 and later, the end-of-paragraph citation display toggle must be manually enabled.

## How to verify successful configuration
- Initiate a query related to process configuration, check if citation source entries are displayed at the end of the answer.
- Verify that cited content matches currently active process configuration sheets, approval node tables, and other documents.
- Test the guest share link, confirm that the citation function displays correctly and can jump to the corresponding original text.
- Adjust the `quoteMaxToken` value, verify that the length of cited content meets expectations.

The values provided are common starting points and should be measured against the reader's own samples.
