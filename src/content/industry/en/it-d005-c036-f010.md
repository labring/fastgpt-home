# Technical Documentation and Interface Q&A for Prototyping and Interaction Design: Source Citation and Traceability

## What Data for This Category Looks Like
Usually, business data for prototyping and interaction design comes from Figma or Axure files, internal team design systems, user feedback records, and usability test documents. Daily output documents include interactive prototypes, page flowcharts, component descriptions, and review records. Data updates happen weekly or per version iteration. Common document fields include prototype version numbers, component unique identifiers, operation path nodes, review modification opinions, and associated page IDs. Some content exists as visual layers.

## Constraints on Source Citation and Traceability
These data characteristics create multiple constraints for the source citation and traceability process. First, data is scattered across multiple design tools and document types. Traceability requires precise matching of content relationships across sources to prevent cross-document information confusion. Second, update frequency is high. Traceability information must be tied to specific version numbers and update times to ensure referenced content is currently active. Third, content length varies widely across interactive prototypes and operation path documents. Excessively long content may exceed the model context window. Limit the token count for single citations. Bind review records and abnormal scenario supplementary content to corresponding prototype nodes to avoid developer understanding gaps.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Matches the average content length of a single interactive prototype or component description, to avoid truncating critical operation paths |
| `responseData` | Enable source field return | Ensures that returned results carry traceability information such as prototype file paths, component IDs, and review record numbers |
| `detail` | `Top 3 recall results` | Focuses citations on core interactive processes, filters non-critical review details, and improves answer accuracy |
| Maximum context | `15000 characters` | Accommodates content from multiple associated prototype files, supports complete traceability for cross-page processes |
| Single search limit | `Top 6 recall results` | Covers complete supplementary content for abnormal scenarios, avoiding omission of critical operation path descriptions |

## Three Common Misconfigurations
- Phenomenon: After increasing `quoteMaxToken` to above 2000, the large model response does not show any citation sources. Reason: The set token value exceeds the context window threshold of FastGPT v4.17.0, and the system cannot extract metadata from the citation fragment.
- Phenomenon: After calling the knowledge base via an external API, the returned result has no traceability fields. Reason: The source return configuration for `responseData` is not enabled, or the API request does not correctly include the knowledge base association parameters.
- Phenomenon: Expired prototype version content appears in citation results. Reason: The data synchronization cycle is not configured to match the design document update frequency, resulting in recall of outdated prototype files.

## How to Verify Proper Configuration
- Log in to the FastGPT v4.17.0 knowledge base management page, and check whether the configurations of `quoteMaxToken`, `responseData`, and `detail` match the preset values.
- Submit a test query, view the system log, and confirm that the returned result includes traceability fields such as prototype file paths and component IDs.
- Adjust the value of `quoteMaxToken`, verify that the length of the recall result matches the configuration, and that the citation source is not truncated.
- Call the knowledge base via an external API, check whether the returned JSON structure includes traceability information corresponding to the `detail` field.

The values provided are common starting points and should be measured against the reader's own samples.
