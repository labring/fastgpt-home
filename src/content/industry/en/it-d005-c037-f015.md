# Technical Documentation and Interface Q&A for Release Management and Version Acceptance: Knowledge Base Retrieval and Recall

## What the data for this category looks like
The core users of this category are release managers, R&D and operations teams, and product owners. Daily produced documents include release plans, launch checklists, acceptance reports, and rollback plans. Data sources include CI pipelines, change management systems, test reports, and monitoring dashboards. Update frequency is weekly or per version. Documents typically include fields such as version identifiers, change item lists, rollback trigger conditions, and acceptance thresholds. No unified fixed format exists, and documents are updated incrementally with version iterations.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
Documents in this category are updated with version iterations. Retrieval must accurately match version identifiers to avoid invalid cross-version results. Most data sources are automated systems. Document structures are flexible with no fixed format. Retrieval must balance semantic matching and keyword matching. Update frequency is weekly or per version. The knowledge base must support incremental synchronization to align with release rhythms. Single-batch retrieval context quotas are limited. The number and length of recalled documents must be strictly controlled to prevent exceeding system limits.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches core fields of documents such as release plans and rollback plans, filters low-relevance redundant results |
| `limit` | Top 10 entries | Release-related documents for a single version typically do not exceed 8 entries. Limiting the number of entries avoids context overflow, and aligns with the single-batch context quota of FastGPT v4.17.0 |
| `searchMode` | Hybrid vector search + keyword search | Balances semantic matching and accurate matching of keyword fields such as version numbers and change items |
| `usingReRank` | Enabled | Performs secondary sorting on recalled results, prioritizes returning key documents containing rollback conditions and acceptance thresholds |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands retrieval keywords. For example, when entering "rollback conditions", adds related scenario terms such as "launch failure" and "version exception" |

## Three common mistakes
- Phenomenon: Insufficient number of retrieval results returned, or the system returns a maxLength-related error. Cause: The recall scope is not filtered by version identifiers. Irrelevant documents occupy context quotas, exceeding the single-batch limit of FastGPT v4.17.0.
- Phenomenon: Launch checklists for the corresponding version cannot be retrieved, and empty results are returned. Cause: Exclusive tags are not bound to documents of different versions, or the corresponding tag parameters are not specified during retrieval.
- Phenomenon: Single retrieval takes more than 30 seconds. Cause: The knowledge base collection scope for retrieval is not limited, including redundant documents not related to release management, leading to an overly large recall scope.

## How to confirm configurations are set correctly
- Release plan and rollback plan documents for a single version are uploaded. The query "rollback conditions for this version" is executed, and target documents are confirmed to be included in returned results.
- The `similarity` parameter is adjusted to 0.70, and non-relevant documents with low similarity are verified to no longer be recalled.
- 100 documents of the same category are batch imported. The number of returned results is confirmed to match the configured `limit` value after retrieval.
- `usingReRank` is enabled, and documents containing rollback conditions are confirmed to rank in the top 3 of retrieval results.

The values provided are common starting points and should be measured against samples relevant to the specific use case.
