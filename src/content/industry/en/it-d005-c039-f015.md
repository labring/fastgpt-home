# Technical Documentation and Interface Q&A for Backend Service Development: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Data for this category originates primarily from code repositories, API gateway logs, databases, and configuration centers. Update frequency follows either a daily schedule or per-release cycle. Commonly referenced documents include interface design specifications, database change tickets, code review records, and service release notes. Data fields typically include interface paths, request parameters, response formats, change effective timestamps, review comments, and similar details. No unified fixed units apply, and some fields are linked to version numbers or environment identifiers.

## What Constraints These Characteristics Impose on Knowledge Base Retrieval and Recall
Dispersed data sources and varied data types require retrieval configurations to support unified adaptation across multiple sources, preventing cross-source matching deviations. High update frequency demands incremental synchronization configurations to keep indexes and source data up to date, avoiding retrieval of outdated interfaces or modified content. Fields tied to version and environment identifiers require filtering conditions during retrieval, to prevent calling incorrect interfaces across versions or accessing configuration data from non-current environments. Core time-intensive tasks in backend scenarios focus on interface contract validation and exception troubleshooting, so retrieval results must accurately match key details such as interface parameters and transaction boundaries, reducing interference from irrelevant information.

## How to Configure

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Aligns with the precise matching requirements of backend interface documents, filtering low-relevance non-interface content |
| `limit` | Top 10 entries | Balances the comprehensiveness of retrieval results and system resource usage, adapting to scenarios where backend teams view interface information in batches |
| `searchMode` | hybrid | Combines keyword and semantic retrieval to cover different types of retrieval needs such as interface paths, parameter descriptions, and change records |
| `usingReRank` | Enabled | Performs re-ranking on initial retrieval results, improving the display priority of highly relevant interface documents and change tickets |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands retrieval terms to supplement extended content such as logs and review records associated with interfaces |
| `collectionIds` | Specified by business environment | Limits the retrieval scope to the knowledge base collection of the current environment, avoiding invalid cross-environment retrieval |

## Three Common Misconfigurations
- Symptom: After forcibly disabling the knowledge base retrieval switch, the returned results still include document fragments outside the configured scope. Cause: The `collectionIds` parameter was not correctly specified, so the retrieval scope was not limited, and the full knowledge base content was retrieved by default.
- Symptom: Retrieval results do not incorporate the interface version context of the current session, returning outdated database change tickets or release notes. Cause: `datasetSearchUsingExtensionQuery` was not enabled, or version information from the context was not used as a retrieval filtering condition.
- Symptom: In versions prior to FastGPT v4.17.0, page crashes or request timeouts occur during batch retrieval. Cause: The `limit` parameter was set too high, or the `similarity` threshold was too low, causing the number of returned results to exceed the system's processing limits.

## How to Confirm the Configuration Is Valid
- View retrieval logs to confirm that the associated collection of returned results matches the configured `collectionIds`, verifying that the scope restriction takes effect.
- Enter a retrieval term that includes an interface path and version number, check whether the relevance of the returned results meets expectations, verifying that the `similarity` and `searchMode` configurations take effect.
- Perform a batch retrieval operation, confirm that the system does not show abnormal errors or excessive resource usage, verifying that the `limit` and `usingReRank` configurations are reasonable.
- Disable the knowledge base retrieval switch, confirm that no document fragments outside the configured scope are included in the returned results, verifying that the retrieval scope restriction logic takes effect.
