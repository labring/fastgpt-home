# Technical Documentation and API Q&A for Pre-sales Technical Proposals: Citation Sources and Traceability

## What the data for this category looks like
This category of data primarily comes from customer interviews, bidding documents, vendor product materials, and historical project plans. The update frequency is per order or weekly. Daily produced documents include technical proposal books, customer requirement survey forms, quotation lists, and demo scripts. Data fields mostly revolve around technical routes, implementation boundaries, quotation configurations, and customer requirements. There are no unified fixed units, and requirements must be matched to the specific needs of the customer and project on a per-order basis.

## What constraints do these characteristics impose on the "citation sources and traceability" link
The data sources for this category are scattered and updated per order. This requires the citation traceability link to accurately bind the exclusive data source of the corresponding project, to avoid cross-order data confusion. Daily document structures are flexible with no fixed chunking rules. This requires ensuring that cited content fully matches the current project’s technical proposals, quotation lists, and other documents. The high update frequency requires the traceability link to support quick synchronization of the latest vendor materials and customer requirements. It also requires strict alignment with technical routes and committed scopes, to prevent issues such as lost bidding points or over-range commitments.

## How to set the configurations
The following configurations are formulated based on FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Matches the average content length of a single pre-sales technical proposal document, to ensure complete citation of the original Q&A pair responses in the knowledge base |
| `responseData` | Enabled | Forces return of the original Q&A pair data matched by the knowledge base, to prevent the system from calling general generation logic to overwrite original content |
| `detail` | Enabled | Retains complete metadata of cited content, to facilitate traceability of the project’s data sources, update times, and document sources |
| Single search limit | Top 3 entries | Matches the narrow-scope requirements of pre-sales projects, to avoid introducing irrelevant historical project or non-current project knowledge base data |
| Timeout threshold | `60 seconds` | Adapts to the workflow rhythm of rapid pre-sales proposal generation, to avoid prolonged waiting that impacts delivery efficiency |

## Three common mistakes
- The `responseData` configuration is not enabled. Responses only display AI-generated content, and do not cite the original Q&A pair responses from the knowledge base. This occurs because the switch for forcing return of original matched data is not enabled, causing the system to default to calling general generation logic.
- Knowledge base citation variables cannot be selected in workflow nodes, and the first search result cannot be output. This occurs because the knowledge base retrieval node is not correctly configured in the workflow, or the node parameters are not associated with the exclusive data source of the corresponding project.
- Cited content does not match the current project’s document format, and traceability information is unclear. This occurs because the citation template is not adapted to the delivery specifications of pre-sales technical proposals, and is not bound to the metadata fields of the corresponding project.

## How to confirm configurations are set correctly
- Initiate a test Q&A, check if the response content fully matches the original response of the Q&A pair imported into the knowledge base, with no additional generated content.
- View the traceability information in the response, confirm that it includes metadata such as the corresponding knowledge base entry, project data source, and update time.
- Test variable calls in the workflow, confirm that relevant fields of knowledge base retrieval results can be selected, such as the content of the first search result.
- Simulate binding of a single project’s data source, check if cited content is only associated with the current project’s knowledge base data, with no cross-order confusion.
