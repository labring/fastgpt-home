# Technical Documentation and API Q&A for Backup Recovery and Disaster Recovery Drills: Vector Models and Indexes

## What data falls under this category
Data for this category primarily comes from backup systems, database logs, object storage, and disaster recovery platforms. It covers four core types of documents: backup policies, recovery drill reports, disaster recovery switchover plans, and data validation records.

Data update frequencies are divided into three categories: daily, monthly, and quarterly. Backup policies and database logs are mostly updated daily. Recovery drill reports and data validation records are mostly archived monthly or quarterly.

Each individual document includes fields such as execution time, backup node path, recovery time elapsed, and validation result. Common units are timestamps, seconds, and file paths.

## What constraints do these characteristics impose on the vector model and indexing workflow
Multi-source heterogeneous data formats require index construction to support parsing different structured content, such as configuration text from backup policies and tabular data from drill reports.

Differences in update frequencies mean incremental indexing workflows must be configured for daily-updated log data. Batch full indexing is used for monthly/quarterly archived report data to reduce unnecessary computations.

Structured fields like execution time and node path in documents must be associated with metadata in the vector index. This allows results to be filtered by time range during subsequent retrieval.

Numeric values such as recovery time elapsed and validation results must be converted to standardized text formats. This ensures embedded vectors accurately match semantically related query requests.

Data scale grows dynamically with drill frequency. Index sharding must reserve space for future scaling to prevent declines in retrieval performance.

## How to configure settings
In FastGPT v4.17.0, the following configurations can be completed via the vector model and indexing module:

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Matches the text density per block of backup policies and drill reports, avoids semantic breaks within blocks |
| Overlap Length | 100–200 characters | Preserves cross-block contextual connections, ensures complete semantics of recovery steps |
| Similarity Threshold | 0.75–0.85 | Filters low-match irrelevant disaster recovery documents, reduces invalid recall |
| Single Search Limit | Top 10 results | Matches the single retrieval needs of operations teams, controls vector database query overhead |
| `maxToken` | 4000 token | Accommodates long text input from disaster recovery plans, avoids truncation of core configuration content |
| `defaultToken` | 200 token | Serves as the default query context length, balances retrieval efficiency and recall completeness |

## Three common configuration mistakes
- Uploading a backup policy document results in an empty index status with no matching retrieval results. The cause is that the incremental index switch for the corresponding data source was not enabled, so daily-updated backup logs were not synchronized to the vector database.
- Calling the API to query disaster recovery drill-related content returns a timeout error. The cause is that the single search limit was set too high, exceeding the response threshold of the vector database, causing query execution time to exceed preset limits.
- Using the m3e model prompts that no available channel is found. The cause is that model channel binding and authorization configuration were not completed, and access channel settings were not configured according to official guidelines.

## How to confirm configuration is complete
- Upload a backup policy document, wait for index generation to complete, enter keywords in the retrieval interface to verify that corresponding content is recalled, and match degree must comply with preset similarity threshold rules.
- Initiate a recovery drill-related query, check that the number of results returned by the API does not exceed the set single search limit, and results include core fields of documents in this category.
- View the vector database monitoring panel, confirm that index update frequency matches the data source's update rhythm, with no backlogged unindexed data.
- Test generating embedding vectors using the m3e model, confirm no channel-related error prompts are displayed, verify that model access configuration is active.
