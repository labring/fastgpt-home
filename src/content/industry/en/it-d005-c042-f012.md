# Technical Documentation and API Q&A for Backup Recovery and Disaster Recovery Drills: Document Parsing and Chunking

## What data looks like for this category
Data for this category originates from backup systems, database logs, object storage, and disaster recovery platforms. Daily documents include backup policies, recovery drill reports, disaster recovery switchover plans, and data verification records. Most documents include modules such as execution steps, parameter configurations, and verification results. Some systems generate operation and maintenance logs daily, update recovery drill reports monthly, and revise disaster recovery switchover plans quarterly. Fields include recovery point objective, recovery time objective, drill execution status, and other metrics. There is no unified fixed format, and formats vary slightly based on the output of the affiliated system.

## What constraints do these characteristics impose on document parsing and chunking
Documents from different sources have large format differences. General parsing rules cannot adapt to all files. Parsing logic must be adjusted specifically to match structures such as backup system logs and disaster recovery platform reports. The daily, monthly, and quarterly update frequencies require the parsing service to handle batch documents across different cycles, to avoid excessive load during single parsing. Documents contain professional operation and maintenance parameters such as recovery point objective and recovery time objective. When chunking, the association between parameters and their context must be retained, to avoid losing key configuration information after splitting. Unstructured data from multiple sources requires chunking logic to balance the coherence of long texts and the integrity of short parameters.

## How to configure settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `customPdfParse` | Enabled | Adapts custom parsing for PDF documents such as disaster recovery drill reports and backup policies, matches the table and parameter block structure of operation and maintenance documents |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large log files exported from backup systems take longer to parse. 600 seconds covers parsing requirements for most single files |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Quarterly drill reports exported from disaster recovery platforms may contain multi-page charts and data. 1000 MB meets file upload requirements for most scenarios |
| `chunkSize` | 800–1200 characters | Backup policy documents contain continuous configuration steps and parameters. 800–1200 characters retains the context of a complete single policy |
| `chunkSplitter` | Split by paragraph and heading | Disaster recovery switchover plans divide execution steps by chapter. Splitting by paragraph and heading retains the logical coherence of drill workflows |
| `chunkSettingMode` | Manual configuration | Operation and maintenance documents have large format differences. Manual configuration allows targeted adjustment of chunking rules to adapt to document structures from different sources |

## Three common mistakes
- Symptom: Parsing fails after uploading a backup policy PDF file, with status code 413 returned. Cause: The `UPLOAD_FILE_MAX_SIZE` parameter was not adjusted. The file was blocked because it exceeded the default limit.
- Symptom: After connecting a custom PDF parsing service, table content in recovery drill reports is not extracted correctly. Cause: The `customPdfParse` configuration was not enabled. The default parsing rules cannot adapt to the special table structure of operation and maintenance documents.
- Symptom: Timeout interruptions occur when parsing large disaster recovery switchover plans. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter was not set. The default timeout duration cannot cover long text parsing requirements.

## How to confirm configuration is complete
- Upload a single disaster recovery drill report PDF file under 1000 MB, check if the parsing status shows success.
- Review the chunking results, confirm that configuration parameters in backup policy documents are not split into different chunks.
- Submit batch documents from daily, monthly, and quarterly cycles, confirm there are no interruptions caused by excessive load on the parsing service.
- After connecting a custom PDF parsing service, verify the extraction completeness of tables and parameter blocks.

The values listed here are common starting points. They should be evaluated against the specific samples of the target deployment.
