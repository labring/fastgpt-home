# Technical Documentation and API Q&A for Security Incident Emergency Response: Source Citation and Traceability
This document is compatible with FastGPT v4.17.0.

## What this category of data looks like
Data for this category primarily comes from SIEM, EDR, firewall logs, and host images. Updates occur in real time or are triggered per individual incident. Daily produced documents include emergency response reports, forensic records, disposal plans, and notification materials. Fields cover incident identifiers, timestamps, attack chains, disposal steps, and evidence association information. Data is measured in units of entries, items, or documents. The content of a single document varies widely based on incident complexity.

## What constraints these characteristics impose on source citation and traceability
Dispersed data sources and real-time updates require citation and traceability processes to accurately match original logs and documents associated with the target incident, to avoid mixing information across events. The content of a single document varies widely based on incident complexity. Citation length limits for different scenarios must be accommodated to prevent token overflow from compromising answer completeness. Forensic records and disposal plans must be tied to unique incident identifiers for traceability, so citation sources must carry traceable incident association fields. Real-time updated security data requires synchronized updates to knowledge base indexes, to ensure traceability data matches the current incident’s timeliness. Failure to do so leads to deviations in attack path restoration and evidence chain organization, creating subsequent disposal risks.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | First 8–15 entries | Security incident-related logs and documents typically fall within this range, avoiding token limit exceedance |
| `responseData` | Only match current incident ID | Prevent unrelated data from other events from being included in traceability results, ensuring evidence chain accuracy |
| `detail` | Enable full fields | Display information such as incident identifiers, timestamps, and log sources, meeting compliance and forensic requirements |
| Context window reserve | 200–300 tokens | Reserve space for integrating cited content and emergency response instructions, avoiding answer truncation |
| Source citation sorting method | Sorted by incident time in descending order | Prioritize displaying the latest logs and disposal records, adapting to the timing requirements of attack path restoration |

## Three common misconfigurations
- Symptom: Setting `quoteMaxToken` to 2000 triggers a token limit exceedance error even for short responses. Cause: Single-segment content of security incident documents is generally long. The token calculation rules for long forensic records and disposal plans are not accommodated, leading to higher actual consumption than expected.
- Symptom: Prompt text when citing the knowledge base is in Chinese, which cannot adapt to English-language emergency response requirements. Cause: The knowledge base search prompt template is not adjusted. English expressions adapted to security operation scenarios are not substituted.
- Symptom: Cited entries in responses are not the top-ranked results from knowledge base searches, and data from other events is included. Cause: The incident association filtering rule for `responseData` is not configured correctly. Logs and documents from unrelated historical events are recalled.

## How to confirm proper configuration
- Submit an emergency response query for a single incident. Check if the returned citation sources only include logs and documents associated with that incident.
- Review the metadata of cited entries. Confirm that traceability-required fields such as incident identifiers and timestamps are included.
- Adjust the `quoteMaxToken` parameter. Verify that the token consumption of the response meets expectations, with no truncation or limit exceedance errors.
- Switch the query language. Confirm that the prompt text and citation display format adapt to the current usage scenario.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
