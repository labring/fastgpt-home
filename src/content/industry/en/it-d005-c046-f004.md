# Technical Documentation and Interface Q&A for Security Baseline Checks: Vector Models and Indexes

## What data for this category looks like
This category of data primarily comes from server configurations, middleware configurations, security device policies, and content exported by baseline tools. Daily documents include baseline checklists, configuration verification records, rectification suggestions, and exception approval forms. The data update frequency is monthly or quarterly. Each individual document contains fields such as baseline item identifiers, configuration parameter values, compliance verification results, and exception approval numbers. There are no fixed unit bindings, but configuration parameter values must match the standard format requirements of the corresponding device.

## What constraints these characteristics impose on the vector models and indexes stage
The data for this category comes from scattered sources and has significant format differences, including structured configuration parameters and unstructured policy descriptions. This requires vector models to adapt to encoding mixed-format text. The monthly/quarterly update frequency means indexes do not need frequent incremental refreshes, and a regular full update strategy can be used. At the same time, the data is associated with compliance verification results, which has clear requirements for the confidence of retrieval results. Low-similarity result recall must be restricted, and the association fields between configuration items and compliance status must be retained to avoid losing key business association information in retrieval results, which would affect the accuracy of subsequent compliance verification.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapt to the text length of single configuration items in baseline checklists, avoid destroying the integrity of configuration items during chunking |
| Overlap Length | 50–100 characters | Retain associated context from adjacent configuration items, avoid losing association information for compliance verification across chunks |
| Similarity Threshold | 0.75–0.85 | Filter low-match irrelevant configuration items, ensure retrieval results meet the strictness requirements of security baselines |
| `maxToken` | 4096 | Adapt to the context length limit of large language models, accommodate associated information from multiple configuration verification records |
| `defaultToken` | 2048 | Balance the precision of vector encoding and computing resource consumption, adapt to the average text length of baseline data |
| Single Search Limit | Top 10 entries | Control the number of retrieval results, avoid context overflow, and cover common compliance verification scenarios |

## Three common mistakes
- Phenomenon: Knowledge base retrieval takes more than 30 seconds, exceeding normal waiting ranges. Cause: Chunk length is set to more than 1500 characters, leading to a significant increase in the computational load for single-block text vector encoding, which slows down overall retrieval speed.
- Phenomenon: The dataset status remains "indexing" for a long time and cannot enter the ready state. Cause: The index task cycle is not adjusted according to the monthly/quarterly update frequency, and high-frequency full indexing leads to task backlog, which prevents index construction from being completed.
- Phenomenon: Index tasks get stuck after configuring `text-embedding-3-large`, and the issue persists after restarting the service with the model commented out. Cause: Old vector cache files are not cleaned, and residual abnormal index processes occupy system resources, preventing new tasks from starting normally.

## How to confirm configurations are set correctly
- Randomly select 10 baseline configuration items to initiate a retrieval request, verify that the similarity values of the returned results fall within the preset 0.75–0.85 range.
- Manually trigger a full index task, check that the task completion time meets expectations, and there is no prolonged backlog.
- Check the index list of the dataset, confirm that there are no duplicate index entries, and the deduplication logic is working properly.
- View the vector service logs for FastGPT v4.17.0, confirm that the `maxToken` and `defaultToken` configuration parameters have been loaded correctly, and there are no error messages.

The values provided are common starting points and should be measured against the reader's own samples.
