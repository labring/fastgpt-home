# Technical Documentation and API Q&A for Security Baseline Inspection: Document Parsing and Chunking

## What the data for this category looks like
This category serves security operations specialists, security consultants, and internal audit professionals. The documents they handle daily include baseline checklists, configuration verification records, rectification suggestions, and exception approval forms. Data comes from exported snapshots of server configurations, middleware configurations, and security device policies, as well as inspection reports generated by baseline tools. Update frequency is monthly or quarterly. Most documents are in structured formats, with fixed fields including configuration item ID, inspection item description, current configuration value, and compliance status. Some documents include configuration screenshots or compliance description attachments.

## What constraints do these characteristics impose on the "document parsing and chunking" link
Structured baseline documents require that chunking preserves the association between configuration items, and avoid splitting grouped inspection items and compliance descriptions. Configuration snapshots from multiple sources may include multiple formats such as Word, Excel, and exported text. The parsing link must support multi-format compatibility and retain table and field structures. The monthly or quarterly update frequency means chunking does not need to be overly fine-grained, but must retain sufficient context to support configuration verification. The most time-consuming configuration item verification link requires chunking to aggregate configuration items of the same category, improving retrieval and matching efficiency. The serious consequences of errors require that the parsing and chunking links do not miss key configuration items, ensuring that retrieval results fully cover compliance inspection content.

## How to set the configurations
The following configurations are formulated based on the parameter logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Matches the typical length of a single set of baseline inspection items plus compliance descriptions, avoiding splitting associated content of the same group of configurations |
| `chunkSplitter` | Split by title + paragraph | Adapts to the structure of baseline documents classified by inspection items, retaining the complete semantics of each inspection item |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time required for large baseline verification records exported in batches, avoiding interruptions during large file parsing |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Meets the file volume requirements for batch importing multiple quarterly baseline reports |
| `customPdfParse` | Enabled | Retains the table structure and field identifiers in PDF baseline checklists, avoiding format confusion after parsing |

## Three common mistakes
- Phenomenon: After importing images from a baseline checklist, images fail to load in conversations, and image links only retain relative paths. Cause: The image path completion configuration for custom document parsing is not enabled. The domain name is only processed during Word conversion, and the full domain name is not completed when importing in Markdown format.
- Phenomenon: Timeout errors occur when parsing large baseline configuration files, and logs show request timeout. Cause: The value set for `PARSE_FILE_TIMEOUT_SECONDS` is lower than the actual time required for parsing, causing interruption before parsing is completed.
- Phenomenon: Incomplete chunked content is returned when searching for a specific configuration item, with the compliance status field missing. Cause: The value set for `chunkSize` is too small, splitting a single configuration item into multiple chunks, resulting in failure to obtain complete content during retrieval.

## How to confirm that configurations are properly set
- A user uploads a typical baseline checklist document, reviews the parsed chunk preview, and confirms that grouped inspection items and compliance descriptions are not split into different chunks.
- A user checks the parsing log of the uploaded file, and confirms that the parsing time does not exceed the threshold set by `PARSE_FILE_TIMEOUT_SECONDS`.
- A user tests searching for the compliance status of a specific configuration item, and confirms that the returned chunked content includes complete inspection item description and current configuration value.
- A user uploads a baseline document containing images, and checks whether the image links displayed in the conversation have been completed with a full domain name prefix.

The values provided are common starting points and should be measured against the user’s own samples.
