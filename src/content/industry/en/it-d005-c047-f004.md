# Technical Documentation and Interface Q&A for Security Vulnerability Disclosure Handling: Vector Models and Indexes

## What this category of data looks like
This category covers technical documentation and interface Q&A data for security vulnerability disclosure handling scenarios. It originates from daily outputs of project security response teams, maintainers, and security researchers, plus external channels. It includes documents such as security advisories, vulnerability reports, fix patches, and CVE application materials. Data sources include private vulnerability reports, code repositories, official CVE number issuing authorities, and project public channels. Updates are tied to individual vulnerability events. Each entry contains structured fields like vulnerability ID, affected scope, fix version, disclosure time, and patch link, plus unstructured text content.

## What constraints these characteristics impose on vector models and indexing
Data for this category is updated per individual vulnerability event, with no fixed batch cycle. It includes two permission levels: private vulnerability reports and public documents. The data also contains both structured fields (such as CVE ID, fix version) and unstructured text (such as vulnerability descriptions, patch notes). Text length varies widely across individual entries. These characteristics require vector models and indexes to support layered permission control. They must adapt to encoding of mixed unstructured and semi-structured data. They must also flexibly respond to sudden single-event data updates, and avoid delays caused by fixed batch indexing.

## How to Configure Settings
| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Adapts to natural paragraph breaks in vulnerability descriptions and patch notes |
| Overlap Length | 100–200 characters | Preserves contextual connections across chunks, prevents loss of vulnerability details due to splitting |
| Similarity Threshold | 0.75–0.85 | Filters low-relevance historical vulnerability reports, focuses on information related to the current event |
| Single Search Limit | Top 10 entries | Controls the volume of retrieval results, avoids exceeding the model context window |
| `maxToken` | 8000 token | Adapts to long-text encoding for CVE application materials and complete security advisories |
| `defaultToken` | 2000 token | Serves as the default context length for single vector encoding, balances accuracy and performance |

## Three Common Misconfigurations
- After upgrading to FastGPT v4.17.0, calling the index interface returns a 400 status code with no response body. The cause is failure to adapt to the new version's index permission verification rules, and failure to configure corresponding access permissions for private vulnerability report data.
- Local deployment leads to server resource exhaustion from vector read and write operations. The cause is failure to limit the number and size of files per indexing batch, and failure to set a reasonable upper limit for `defaultToken`. This leads to simultaneous encoding of a large number of long texts, which occupies excessive resources.
- Knowledge base file uploads occasionally get stuck during 1 or 2 indexing groups. The cause is a mismatch between the chunk length setting and the text length of vulnerability reports, leading to failure to complete vector encoding for some chunks, and failure to enable the failure retry mechanism.

## How to Confirm Configurations Are Correct
- Upload a test vulnerability report document, check the vector generation logs to confirm that the chunk length and overlap length configurations take effect.
- Initiate a vulnerability impact assessment retrieval request, check the number of returned results and similarity scores to confirm that the threshold and single search limit configurations take effect.
- Export the current knowledge base configuration information, verify that the values of `maxToken` and `defaultToken` match the preset configurations.
- Simulate the upload and retrieval of private vulnerability reports, confirm that the permission control configurations take effect, and no unauthorized access prompts appear.

The values provided are common starting points and should be measured against the reader's own samples.
