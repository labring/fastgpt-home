# Technical Documentation and API Q&A for Customer Onboarding and Tenant Initialization: HTTP Interfaces and External Systems

## What the data for this category looks like
The core data for this category comes from CRM systems, contract orders, identity management systems, and the FastGPT product backend. Daily maintained documents include onboarding application forms, tenant configuration tables, administrator account lists, and delivery confirmation forms.
The data update rhythm is per order or daily. A single data batch covers fields such as customer basic information, tenant unique identifier, permission scope, and onboarding status. Field formats must strictly match FastGPT interface requirements, with no extra redundant content, to ensure accurate parameter passing during interface calls.

## What constraints these characteristics impose on HTTP Interfaces and External Systems
Since data sources involve multiple external systems, HTTP interfaces must support cross-system data pulling and synchronization. Unified authentication rules must be configured to ensure data security.
The data update rhythm can be triggered on demand or synced daily. The interface must support two trigger modes: single call and scheduled tasks.
Fixed field requirements in daily documents mandate that interface input parameters strictly match specified field names, with no missing items or non-agreed fields used.
Errors may result in customer login failures or delivery delays. The interface must be configured with a retry mechanism and result verification logic to ensure call success rate and data consistency.

This document is written based on FastGPT v4.17.0.

## How to configure settings
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| Authentication Method | Select Bearer token, enter the FastGPT administrator API key | Complies with FastGPT official interface authentication specifications, ensures interface call permissions are legitimate |
| Request Variable Mapping | Map customer ID, tenant identifier, and permission scope to interface input parameters | Matches the fixed field requirements of daily documents, ensures complete and accurate transmitted information |
| Return Result Verification | Verify that the return status code is 200 and the onboarding status field is completed | Quickly confirms that the tenant initialization operation was executed successfully |
| Retry Count | Set to 3 times, with a 10-second interval | Addresses call failures caused by temporary network fluctuations, improves interface call stability |
| Timeout Period | Set to 60 seconds | Matches the typical processing duration of tenant initialization, prevents task interruptions due to excessive waiting time |

## Three Common Mistakes
- Scenario: A 401 Unauthorized status code is returned after calling the interface, and the tenant is not initialized. Cause: The `Authorization` parameter is not configured correctly, resulting in authentication failure that prevents calling the FastGPT interface.
- Scenario: The interface call returns a 504 Gateway Timeout error. Cause: The timeout period is set too short, which does not match the actual processing duration of tenant initialization, causing the task to be interrupted before completion.
- Scenario: The interface return result has missing fields, making it impossible to confirm the onboarding status. Cause: Required fields in `responseData` are not mapped correctly, causing the verification logic to fail to trigger normally.

## How to Confirm the Configuration is Complete
- The test interface is invoked, and the returned result is checked to confirm it includes the expected tenant initialization status field.
- The FastGPT product backend is logged into, and the tenant list is reviewed to confirm the new tenant has been created and the permission configuration meets requirements.
- The customer login process is simulated, and access to corresponding resources is verified for the account.
- Interface call logs are reviewed to confirm there are no abnormalities in authentication, parameter passing, and result verification.
