# Technical Documentation and API Q&A for Customer Onboarding and Tenant Initialization: Document Parsing and Chunking

## What the data for this category looks like
Data for this category primarily comes from contract orders, CRM systems, identity management systems, and product backends. Commonly processed documents include onboarding application forms, tenant configuration sheets, administrator account lists, and delivery confirmation documents. Data updates take place per order or daily. Core fields include customer unique identifiers, tenant IDs, permission configuration items, onboarding status, and administrator account information. Document formats vary: some are structured forms, others are unstructured application descriptions.

## What constraints these characteristics impose on document parsing and chunking
Because data sources are scattered and document formats vary, the parsing process must support both structured forms and unstructured application text. The per-order or daily update frequency means the parsing workflow must run with low latency, to avoid delaying customer onboarding timelines. The uniqueness requirement for core fields means chunking must retain key identifiers like customer IDs and tenant IDs, to prevent loss of associated information after chunking. Additionally, configuration items vary widely across different customers. Chunking must avoid excessive splitting that breaks configuration logic, and must retain contextual associations for configuration items.

## How to configure settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the text length of onboarding application forms and tenant configuration sheets, avoids breaking contextual associations for key configuration items after splitting |
| `chunkSplitter` | Split by paragraph and semantic meaning | Supports both structured forms and unstructured application text, retains associations between configuration items and customer information |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Matches the per-order or daily update rhythm, prevents interruptions to the onboarding workflow due to timeouts |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapts to document scenarios with attached files such as delivery confirmation documents, meets single upload requirements |
| `chunkSettingMode` | Manual configuration mode | Flexibly adjusts chunking rules for differences in document formats across customers, adapts to diverse onboarding documents |

## Three common configuration errors
- A successful API call to parse a file returns no parsing results: This is typically caused by incorrect configuration of the `customPdfParse` parameter or failure to enable the corresponding parsing module, so no parsed results are returned to the interface after file parsing.
- Split-related error logs appear: This mostly happens when the `chunkSize` value does not match the document format. For example, using an overly long chunk length for short text causes the chunking logic to fail to run normally.
- Slow parsing speed: This may stem from an overly short `PARSE_FILE_TIMEOUT_SECONDS` setting, or failure to optimize chunking rules for structured forms, so parsing process time exceeds expected values.

## How to verify correct configuration
- Upload a single onboarding application form document, confirm parsed chunks retain key fields such as customer ID and tenant ID, with no broken contextual associations.
- Call the file parsing API, verify that the returned results include parsed text chunks and corresponding metadata, confirm normal interface return.
- Upload a document at the maximum allowed size, check if the upload and parsing process completes within the preset timeout period, with no timeout errors.
- View parsing module logs in FastGPT v4.17.0, confirm that chunking rules take effect as configured, with no parameter conflict prompts.
