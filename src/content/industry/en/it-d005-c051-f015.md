# Technical Documentation and API Q&A for Customer Data Import Migration: Knowledge Base Retrieval and Recall

## Data Profile for This Category
Teams source core data for this category from customer historical business systems, CSV/Excel templates, database export files, and product import logs. Personnel produce data migration templates, field mapping tables, migration execution plans, and migration verification reports regularly. Data update frequency follows custom per-project schedules, with no fixed cycle. The data structure includes structured business fields, non-standardized migration instruction documents, and import logs with operation traces. Fields must align with the business definitions of the customer’s original system, with no unified fixed units.

## Constraints for Knowledge Base Retrieval and Recall
Diverse data sources and inconsistent structures require retrieval systems to cover both structured fields and unstructured documents. This prevents missing key content from migration plans or field mapping tables. Irregular data update cycles require recall mechanisms to flexibly adapt to exclusive datasets for single imports. Global scheduled cache updates cannot support these needs. Fields must align with original customer system definitions, so retrieval systems must associate context from field mapping tables. This stops mistakenly recalling content from unrelated fields. Import logs contain operation traces, so retrieval systems must filter invalid dirty data entries. This improves result accuracy.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | Matches the field association accuracy of customer imported data, to avoid mistakenly recalling irrelevant migration logs or non-target customer data |
| `limit` | `Top 8–12 results per batch` | Large per-batch imported data volume, controls the context length of retrieval results to avoid exceeding model input limits |
| `searchMode` | `vector + fulltext` | Covers retrieval needs for structured business fields and unstructured migration documents, adapts to multi-type data characteristics |
| `usingReRank` | `Enabled` | Filters dirty data and low-match import log entries, improves relevance of retrieval results |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Combines context from field mapping tables to optimize search terms, ensures matching to correct business field definitions |
| `collectionIds` | `Bound to exclusive IDs of corresponding customer imported datasets` | Isolates imported migration data across different customers, to avoid recalling unrelated content across projects |

## Three Common Configuration Mistakes
- Scenario: When calling the knowledge base tool module in a workflow, the system returns empty results or fails to associate target customer imported data. Cause: Failed to bind `collectionIds` for the corresponding customer imported dataset, leading the retrieval scope to cover unrelated knowledge base content.
- Scenario: Some fields from uploaded CSV/Excel migration template data are missing in the knowledge base. Cause: `datasetSearchUsingExtensionQuery` was not enabled, and context from field mapping tables was not associated, leading the system to mistakenly filter non-standard formatted field data.
- Scenario: After configuring knowledge base retrieval, the tool call module fails to trigger normally. Cause: The `limit` parameter was not set appropriately, with retrieval results occupying all model context and leaving no parameter space for tool calls.

## How to Verify Correct Configuration
- Import a single batch of test data, perform a retrieval action, and verify that returned results include core content from the corresponding field mapping table and migration plan.
- Adjust the `similarity` threshold, verify that field association accuracy of matching results meets expectations, avoiding thresholds that are too high or too low which cause mistaken or missed recalls.
- View the operation logs of the knowledge base dataset, confirm that uploaded table data has not been filtered or had fields lost.
- Test simultaneous calls to the knowledge base and tool modules in a workflow, verify that their context parameter configurations are compatible with no conflicting resource occupation.

The values provided are common starting points and should be measured against the reader's own samples.
