# Technical Documentation and API Q&A for Customer Requirement Pool Management: Source Citation and Traceability

## Data Overview for This Category
Customer requirement pool management data typically comes from multiple sources including ticket systems, customer interview records, CRM customer profiles, and product roadmaps. The update frequency is weekly or per product release cycle. Daily maintained documents include requirement pool lists, requirement evaluation forms, customer feedback summaries, and version planning descriptions. Common data fields include requirement unique identifiers, associated customer information, priority tags, requirement descriptions, and version association items. There is no unified fixed format, and the field structure must be adjusted for different business scenarios.

## Constraints Imposed on Source Citation and Traceability Workflow
Multi-source data requires the traceability workflow to support cross-system metadata association. This ensures cited sources accurately match original customer feedback or requirement records. The relatively high update frequency means the traceability logic must adapt to the latest requirement pool data in real time. This avoids using outdated requirement content in citations. Inconsistent document structures require traceability configuration to support flexible field mapping rules. This adapts to requirement document formats across different businesses. Unlike other requirement management categories, this category prioritizes filtering and sorting feedback from multiple customers. The traceability workflow must clearly distinguish requirement sources from different customers to avoid cross-customer requirement confusion.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Return Traceability Detail Toggle | Enabled | Used to obtain complete response content including cited source metadata |
| Maximum Cited Content Length | 800–1200 characters | Adapts to the average content length of requirement pool documents, avoiding overly long cited content that disrupts conversation logic |
| Maximum Number of Traceability Results per Request | Top 5 entries | Controls the number of returned cited sources, preventing excessive redundant data from reducing requirement evaluation efficiency |
| Full Response Data Toggle | Enabled | Used to obtain detailed responses including knowledge base citation IDs, facilitating subsequent traceability verification |
| Context Concatenation Length | 6000 characters | Adapts to the splicing needs of multiple requirement documents, ensuring conversation context contains sufficient requirement information |

## Three Common Configuration Errors
- Failure to return knowledge base IDs when calling the chat API: The API response does not include traceability-related metadata fields. This occurs when either the Return Traceability Detail Toggle is not enabled, or the required FastGPT server environment variables `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service, for example http://aiproxy:3000; do not append paths such as /v1 or /chat/completions) and `AIPROXY_API_TOKEN` (AI Proxy administrator token, consistent with the AI Proxy server configuration and cannot be empty) are not correctly configured. Incorrect configuration triggers startup verification failures.
- Malfunctioning knowledge base citation merging function: Cited sources for multiple similar requirements are not correctly grouped. This happens when a reasonable maximum number of traceability results per request is not set, leading to unfiltered duplicate requirement records.
- Incorrect cited source files: Returned cited sources do not match actual requirement records. This occurs when metadata mapping rules between requirement pool data and the knowledge base are not correctly configured, leading to deviations in traceability matching.

## How to Verify Correct Configuration
- Initiate a test conversation, and verify whether the response includes traceability-related metadata fields such as cited source identifiers and associated customer information.
- View FastGPT Admin service startup logs, and confirm that `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service, for example http://aiproxy:3000; do not append paths such as /v1 or /chat/completions) and `AIPROXY_API_TOKEN` (AI Proxy administrator token, consistent with the AI Proxy server configuration and cannot be empty) are configured correctly, with no startup verification failure prompts.
- Adjust the value of Maximum Number of Traceability Results per Request, and verify that the number of cited sources returned in the response matches expected values.
- Compare actual requirement pool document content with returned cited sources, and confirm that the matching relationship is accurate.

This configuration applies to FastGPT v4.17.0 and later versions.
