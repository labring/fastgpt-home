# Technical Documentation and API Q&A for Customer Requirement Pool Management: Knowledge Base Retrieval and Recall

## What the data for this category looks like
The data for this category primarily comes from ticketing systems, customer interview records, CRM systems, and product roadmaps. The update frequency is weekly or per release cycle. Daily produced documents include requirement pool lists, requirement evaluation forms, customer feedback records, and version planning descriptions. Common document fields include unique requirement identifiers, associated customer information, priority tags, submission times, current statuses, and evaluation dimensions. Most of the overall data is structured text, with some unstructured original customer feedback included.

## What constraints these characteristics impose on knowledge base retrieval and recall
Decentralized data sources create differences in field formats across systems. Unified field mapping rules are required during retrieval to avoid matching deviations. A high update frequency means the knowledge base must regularly sync the latest requirement pool and version planning content. Otherwise, recall results will lag behind business changes. Requirement pool data includes customer association information. Retrieval must balance requirement ownership and business relevance. This prevents unrelated cross-customer requirements from being recalled. A notable share of unstructured original customer feedback exists. Processing must adapt to text fragments of varying lengths to ensure recall accuracy meets business requirements.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the core semantics of customer requirements. Avoids irrelevant results when set too low, and misses relevant requirements when set too high |
| `limit` | Top 10 entries | Adapts to the reasonable result volume for a single requirement pool retrieval. Prevents context overload that degrades conversation experience |
| `usingReRank` | Enabled | Performs secondary ranking on retrieved requirement-related documents. Optimizes the display position of high-priority requirements |
| `datasetSearchUsingExtensionQuery` | Enabled | Generates extended queries based on original questions. Covers synonyms and variant expressions in requirement descriptions |
| `collectionIds` | Bind to the exclusive knowledge base collection for the requirement pool | Ensures the retrieval scope only covers documents related to the current customer requirement pool. Prevents interference from cross-category data |

## Three Common Misconfigurations
- Uploaded files in conversations cannot be read. This occurs when files are uploaded only to the global knowledge base and not associated with the exclusive requirement pool collection. Retrieval cannot match the corresponding business data.
- Retrieval results are occasionally empty. The knowledge base sync frequency does not match the weekly or per-version update rhythm of the requirement pool. Outdated data is not updated in time, leading to matching failures.
- Retrieval returns irrelevant requirement content. This happens when the `similarity` threshold is set too low, or when `datasetSearchUsingExtensionQuery` is not enabled. This results in matching semantic fragments from non-target requirements.

## How to Confirm Configurations Are Set Correctly
- Access the application configuration page in FastGPT v4.17.0. Confirm that the retrieval configuration has bound the collection ID of the exclusive requirement pool knowledge base.
- Enter a typical requirement description. Verify that the similarity scores of retrieval results fall within the preset 0.75–0.85 range, and that all results are requirement pool-related documents.
- Simulate a requirement pool update operation. Trigger knowledge base synchronization. Verify that newly submitted requirement evaluation forms can be recalled normally.
- After enabling the reranking function, verify that the sorting position of high-priority requirements meets business expectations.
