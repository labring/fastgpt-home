# Technical Documentation and API Q&A for Container Platform Operations: Citation Sources and Traceability

## What the data for this category looks like
Core data for container platform operations comes from Kubernetes API, image registries, monitoring systems, and CI pipelines. Update frequency is daily or on each cluster change.
Commonly used documents include cluster change tickets, namespace quota tables, deployment records, and incident reports. Data fields include cluster ID, namespace, Pod status, image version, resource quota thresholds, and more. Units include cores, GiB, timestamps, and operator identifiers. Single data entry lengths vary widely, from hundreds to thousands of characters.

## Constraints on Citation Sources and Traceability
Multi-source heterogeneous data requires the traceability process to accurately match the original source identifiers of data, to avoid mixing data across clusters or repositories.
High-frequency data updates require traceability information to include accurate timestamps and version numbers, to ensure citations reference the most recently active configurations and records.
Documents with fixed field structures need to associate specific fields such as namespace and Pod name during traceability, to enable quick location of abnormal sources.
Wide variation in data length requires controlling the total volume of citations. This prevents context overflow that impacts large model responses, while also avoiding missing troubleshooting basis from insufficient citations.

## Configuration Settings
| Configuration Item | Recommended Practice | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 8000–12000 token | Single data entries for container platform operations typically occupy 300-800 tokens. This value covers stitching needs for 5 to 10 typical data entries, and adapts to multi-source data integration scenarios |
| `responseData` | with_source_meta | Core traceability fields such as resource version and update time returned by the Kubernetes API must be retained, to ensure citations can be traced back to original cluster resources |
| `detail` | true | Complete metadata of cited data must be returned, for quick location of problem roots during manual verification and incident troubleshooting |
| Single recall count | Top 10 entries | Container platform operations have a large number of data entries. This value controls context length, while covering major incident troubleshooting and quota adjustment scenarios |
| File encoding | UTF-8 | Configuration files and logs for container platform operations default to UTF-8 encoding, to avoid garbled characters during import |

## Three Common Mistakes
- Uploading CSV-format operation documents results in garbled display, and exceptions occur when calling related APIs. Cause: The file encoding is not specified as UTF-8. Configuration files and logs for container platform operations default to UTF-8 encoding. Incorrect configuration causes parsing failures.
- Setting `quoteMaxToken` to 3000 results in the large model not receiving context data. Cause: The configured token upper limit is too low. The total token count after stitching multi-source data for container platform operations exceeds the set value, causing the context to be completely truncated.
- Configuring HTTP response data as a citation has no effect. Cause: The response data is not converted to a structured format. API responses for container platform operations typically use JSON format. Specified fields must be extracted before importing into the knowledge base.
