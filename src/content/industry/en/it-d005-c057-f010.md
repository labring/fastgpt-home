# Technical Documentation and API Q&A for Ticket Handling and Issue Tiering: Source Citation and Traceability

This document is written based on FastGPT v4.17.0.

## What the data for this category looks like
Core data for this category comes from ticketing systems, chat logs, product logs, and customer contract SLAs. Updates occur daily or in real time. Daily generated documents include customer tickets, issue tiering tables, processing records, and service reports. Fields include ticket unique identifiers, issue types, tiering levels, handlers, associated SLA clauses, and more. There are no custom statistical units. The minimum storage unit is a single customer feedback or service event.

## What constraints do these characteristics impose on the "source citation and traceability" link
Mixed multi-source data access requires traceability links to bind unique identifiers to distinguish content from different sources. Real-time update features require configuring synchronization mechanisms to ensure the timeliness of referenced data. A ticket-centric document structure requires traceability to link to specific ticket IDs and processing records, to avoid generalized citations. The high time cost of issue reproduction and impact scope assessment requires traceability links to quickly locate original data, reducing manual verification costs. Consequences of SLA violations require referenced content to fully match original records. Forged associated information is prohibited.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | Matches the typical length of referenced content for tickets and processing records, avoiding truncation of key traceability information |
| `responseData` | Return only associated ticket IDs, processing records, and SLA clauses | Focuses on core data for this category, reducing redundant content that interferes with traceability judgments |
| `detail` | Full | Retains all fields of original data, supporting precise traceability to specific processing links |
| Maximum number of single recall entries | Top 5 entries | Matches the information density of ticket issue tiering, avoiding excessive irrelevant content occupying context space |
| Knowledge base dynamic binding | Match by the customer to which the ticket belongs | Adapts to the storage rule that ticket data is isolated by customer, enabling precise calling of the corresponding knowledge base |
| Citation mark filtering | Enabled | Removes redundant mark formats to comply with output specifications |

## Three common mistakes
- Blank reference variables when dynamically specifying a knowledge base: No variable binding trigger rules are configured in the knowledge base search node interface, resulting in the optional variable list not loading.
- Unable to distinguish referenced content from different sources in logs: Source identifier return for the `responseData` configuration is not enabled, making it impossible to locate the original data source via log fields.
- Large model forges reference IDs: Original data association verification in `detail` mode is not enabled, resulting in generated reference IDs that do not match the actually retrieved ticket records.

## How to confirm the configuration is complete
- Submit a test ticket, check whether the large model return results are associated with the corresponding ticket ID and processing records, and verify that the traceability information is accurate.
- View system logs, confirm that each referenced content carries a unique source identifier, allowing quick location of the original ticket or processing record.
- Configure variable binding in the knowledge base search node, verify that the optional variable list for dynamically specifying the knowledge base loads normally.
- Generate a test reply, confirm that the output content does not include redundant citation mark formats, and only retains core referenced content.

The values provided are common starting points and should be measured against the reader's own samples.
