# Technical Documentation and API Q&A for Advertising Compliance Audit Trails: Citation Sources and Traceability

## What the data for this category looks like
This data originates from advertising platform backends, customer qualification records, contract systems, and publicly available regulatory guidelines. Daily documents include advertising review forms, qualification attachments, delivery logs, and rectification notices. Data updates are completed per individual advertising campaigns or monthly cycles. Individual documents typically contain fields such as approval numbers, delivery periods, qualification validity windows, and rectification items. No unified fixed format exists, so documents must be archived and stored based on business scenarios. The core requirement is a fully traceable evidence chain.

## What constraints do these characteristics impose on the "citation sources and traceability" workflow?
Data sources are dispersed and formats are inconsistent, requiring precise matching of document source identifiers during traceability to prevent cross-system confusion. Update frequencies vary by campaign or monthly cycle, so support is needed to quickly retrieve compliance evidence for the corresponding time range. Individual documents cover broad content ranges, so citation length must be controlled during retrieval to avoid exceeding storage and display limits for compliance audit trails. Compliance audit trail requirements also mandate that traceability results can be directly linked to the original delivery or approval process. Cited content must align consistently with the fields of the original document, and cannot return only fragments without a complete source chain.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 1000–1500 token | Matches the average length of single-block content in advertising compliance documents to avoid truncating key compliance information |
| Single search limit | Top 3–5 entries | Focuses on core compliance evidence, reducing the archiving and review burden of non-essential content |
| `responseData` | Includes source path, document type, update time | Meets regulatory traceability requirements for source chains, enabling direct linking to original systems and archived records |
| `detail` | Enable full field display | Retains compliance-required fields such as qualification numbers and delivery periods to facilitate subsequent audit verification |
| Knowledge base chunk length | Calibrated via actual testing | Adapts to compliance documents of varying lengths, avoiding damage to key fields such as approval numbers and rectification items when chunking |

## Three Common Configuration Errors
- Phenomenon: Retrieved knowledge base chunks exceed the configured `quoteMaxToken` limit, and returned content is truncated or key compliance fields are missing. Cause: The knowledge base chunk length is not matched with the `quoteMaxToken` parameter. When a knowledge base chunk is larger than the citation limit, truncation triggers even if the chunk is recalled, resulting in incomplete compliance evidence.
- Phenomenon: The number of citations returned by knowledge base search exceeds expectations, and no configurable limit value can be identified. Cause: The single search limit is not set, or the set value does not align with archiving requirements for compliance audit trails, leading to the return of too many non-core compliance document fragments and increasing audit difficulty.
- Phenomenon: The sorting results of the knowledge base search citation merging module do not meet compliance priorities, and key rectification notices or qualification documents are not displayed first. Cause: The sorting basis is not clearly defined as the compliance level or update time of the source system, and only basic similarity sorting is used, which cannot meet the priority requirements of compliance audits.

## How to Confirm Proper Configuration
- Upload a standard advertising review form, set `quoteMaxToken` to 1200 token, and verify that the token count of returned content does not exceed the set value after retrieval.
- Review the returned search result fields to confirm that they include content from the `responseData` configuration, such as source path, document type, and update time.
- Trigger a multi-knowledge base search workflow, and confirm that results from all connected knowledge bases apply unified citation processing logic.
- Test documents with varying chunk lengths, and confirm that complete compliance field information displays when the `detail` configuration is enabled.

The values provided here are common starting points and should be evaluated against the reader's own samples.
