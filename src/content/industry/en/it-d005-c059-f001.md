# Technical Documentation and API Q&A for Advertising Material Review: HTTP Interfaces and External Systems

## What the Data for This Category Looks Like
The core data for this category includes advertising material copy, landing page screenshots, review opinions and modification records. Data sources cover advertising placement platforms, landing page servers, product qualification systems and advertising law compliance clause databases. Data updates occur daily or in real time. Real-time updated materials must be pulled synchronously with placement plans. The document structure includes fields such as material unique identifier, copy content, image binary stream, review status and violation point details. Units are mostly characters, pixels and timestamps, with no complex nested levels. A single material’s data size typically ranges from hundreds of KB to several MB. Mixed transmission of multi-format files and structured text must be supported.

## What Constraints These Characteristics Impose on the HTTP Interfaces and External Systems Link
Multiple data sources require the interface to pull data across systems including advertising platforms and landing page servers, or receive batch material files pushed by external systems. Real-time or daily data update rhythms require the interface to support incremental synchronization, avoiding excessive system resource occupation from full pull requests. Multi-format mixed document structures require the interface to support transmission of both structured text and binary file streams. Large single-material data sizes require the interface to set reasonable timeout thresholds and alternative chunked upload solutions. High error risk requires the interface to return clear status codes and detailed error information, enabling quick problem location. Material review must be bound to a unique placement identifier, so the interface must support passing business context parameters to ensure accurate binding of review results to corresponding materials.

## How to Set Configurations
| Configuration Item | Recommended Approach | Basis for This Approach |
| ---- | ---- | ---- |
| Authentication Method | Use the `Authorization` header to carry a Bearer token | Complies with FastGPT v4.17.0 security authentication specifications, avoids plaintext transmission of secrets |
| API Request Timeout | 600 seconds | Adapts to the full processing duration of a single material review, avoids timeout interruptions caused by lengthy review processes |
| Request Body Format | multipart/form-data | Supports simultaneous upload of multiple advertising material images and structured review parameters, meets multi-file transmission requirements |
| Response Data Format | Configure `responseData` as a JSON structure | Facilitates external systems to parse review results, violation point details and task status |
| Business Context Parameters | Pass advertising material ID and placement plan identifier via `variables` | Ensures review results are bound to corresponding advertising placement materials, facilitating subsequent compliance traceability and data association |
| Maximum Number of Files per Request | First 5 | Balances transmission efficiency and interface load, avoids timeouts caused by too many files in a single request |

## Three Common Misconfigurations
- Phenomenon: A 400 Bad Request error is returned when calling the interface to upload multiple advertising material images. Cause: The multipart/form-data request header is not correctly configured, or image files are not submitted as independent form fields.
- Phenomenon: Streamed review responses cannot be obtained when connecting a FastGPT application via Langchain. Cause: FastGPT's streamed output configuration is not enabled, or the interface's returned response stream is not processed in Server-Sent Events format.
- Phenomenon: A field missing error is returned when calling the dataset collection creation interface. Cause: Business parameters associated with the advertising material are not passed via `variables`, or the parameter format does not meet interface requirements.

## How to Confirm Configurations Are Properly Set Up
- Call the interface to upload a single advertising material image, check that the returned status code is 200 and `responseData` contains the review task ID.
- Call the interface after configuring the `Authorization` header, check that no 401 Unauthorized unauthorized error occurs.
- After enabling the streamed response configuration, connect the interface via an external tool, check that review result fragments can be received segment by segment.
- After uploading a landing page screenshot, check that the violation point annotation field returned by the interface is not empty and contains review details for the corresponding material.

The values provided are common starting points and should be measured against the user’s own samples.
