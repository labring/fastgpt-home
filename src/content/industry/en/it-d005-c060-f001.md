# Technical Documentation and API Q&A for Ad Account Opening Audit: HTTP Interfaces and External Systems

## What this category of data looks like
Data for this category primarily comes from the ad platform backend, the national enterprise credit information public disclosure system, account opening application materials and industry qualification documents submitted by clients, and public industry access rules. Data updates follow the progress of the account opening application flow, with one update triggered per single application. Daily documents include account opening application forms, scanned business licenses, corresponding industry qualification certificates, audit operation records, and other materials. Fields include the main body's unified social credit code, industry license number, application submission time, audit status, and more. There are no unified fixed units; corresponding formats are matched based on individual field attributes.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
Multiple data sources require the interface to support different authorization methods and data formats, to avoid request failures caused by relying on a single data source in a single call. The update rhythm triggered by applications requires the interface to support on-demand calls, to avoid invalid polling that occupies system resources. The inclusion of unstructured data such as scanned documents requires the interface to support file upload and binary data transmission, to meet the submission requirements of qualification materials. Time-consuming links such as main body qualification verification require the interface to be configured with a reasonable timeout period, to prevent request interruptions from blocking the audit process.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {ad platform API key}` | Ad platform interfaces typically use Bearer token authentication to ensure request legitimacy |
| Single call timeout | `600 seconds` | Links such as main body qualification verification take a long time; this value covers the single request duration of the complete audit process |
| `variables` | `Includes main body ID, industry type, application batch number` | Pass core business parameters as variables to the interface, to adapt to personalized verification requirements for different account opening applications |
| Request retry count | `3 times` | Address temporary fluctuations in ad platform interfaces that cause call failures, to avoid interrupting the audit process with a single failed request |
| `responseData` | `Only extract audit status, correction prompt fields` | Filter redundant return content, reduce interface transmission load, and improve parsing efficiency |
| File upload size limit | `1000 MB` | Cover the maximum storage requirements for scanned copies of business licenses and industry qualifications; the upload limit for some special industry qualifications is calibrated based on actual measurements |

## Three common mistakes
- Phenomenon: The interface call returns a 401 unauthorized error. Cause: The `Authorization` parameter format is not configured correctly, the Bearer token prefix is missing, or the key is filled incorrectly.
- Phenomenon: The interface returns empty audit correction prompts. Cause: Core `variables` such as the application main body ID and industry type are not passed to the interface, so the rule base corresponding to the audit process cannot be matched.
- Phenomenon: Qualification file upload fails. Cause: A reasonable file upload size limit is not set, exceeding the maximum transmission capacity allowed by the interface.

## How to confirm the configuration is correct
- Use the interface debugging tool of FastGPT v4.17.0, pass known valid account opening application `variables`, and check that the returned `responseData` includes the expected audit status field.
- Upload qualification files of conventional size, confirm that the interface returns an upload success status, then adjust the file upload limit according to actual business needs.
- Simulate a time-consuming scenario for qualification verification, verify that the interface does not interrupt the request within the preset duration, and adjust the timeout period based on actual time consumption.
- Check that the `Authorization` parameter format in the interface request header is correct, with no extra spaces or format errors.
