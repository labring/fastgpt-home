# Technical Documentation and API Q&A for Ad Account Opening Audit: Citation Sources and Traceability

## What Data for This Category Looks Like
Data centers on the full ad account opening process. Daily documents include account opening application forms, business license scans, industry access qualification documents, and audit records. Data sources include application ledgers from ad platform backends, entity verification data from the national enterprise credit information public disclosure system, paper and electronic materials submitted by customers, and industry access rule documents. Update frequency occurs after each account opening application is completed or via daily synchronization. Each data entry includes fields such as entity name, qualification ID, submission time, and audit status. There is no unified fixed unit, and fields adjust dynamically based on material type.

## Constraints on Citation Sources and Traceability
Mixed use of multi-source data requires traceability systems to distinguish entries from different sources, including ad platform backends, external public disclosure systems, and customer-submitted materials, to avoid cross-source confusion. The dynamic update rhythm of single applications requires traceability information to be bound to the unique identifier and submission time of a specific application, ensuring that referenced materials match the corresponding audit stage. The characteristic of dynamically adjusting fields based on material type requires traceability configuration to support custom field mapping, adapting to field differences across documents such as business licenses and industry qualifications. Additionally, the potential consequences of failed account openings require traceability information to be retrievable, enabling location of root causes of audit process issues and ensuring compliance of the audit workflow.

## Configuration Settings
| Configuration Item | Suggested Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Matches the average text length of single account opening audit materials, avoids truncating critical traceability information |
| `responseData` | `Include source fields, submission time, audit status` | Covers core traceability fields of business data, ensuring complete reference information that meets audit scenario requirements |
| `detail` | `Enabled` | Enables detailed traceability mode, displaying specific source paths of materials to help auditors quickly locate information origins |
| Maximum Context | `Top 3 associated application records` | Limits the traceability context scope, preventing irrelevant historical application data from interfering with current audit judgments |
| Single Recall Limit | `Top 5` | Matches the number of materials requiring verification for a single account opening audit, avoiding excessive redundant information occupying context space |

## Three Common Misconfigurations
- Referenced plugins cannot be found in imported workflows, with the interface displaying the prompt "Plugin not found". Cause: When exporting the workflow, associated plugin configuration and permission binding information was not synced, only the basic workflow structure was exported.
- The end of a response paragraph displays "No permission to operate this conversation record" as a citation prompt. Cause: The conversation traceability permission verification switch was not disabled, or the configured traceability data source did not grant access permissions to the current conversation role.
- Input `\n` characters are output as plain text in the response, without producing a line break effect. Cause: Text formatting parsing configuration was not enabled, or incoming line break characters were not escaped, resulting in them being treated as ordinary text.

## How to Confirm Proper Configuration
- Initiate a simulated account opening audit Q&A, check if correct source fields and submission time are displayed at the end of the response.
- Export the current workflow and import it to a test environment, confirm that associated plugins and traceability configurations are loaded correctly.
- Input test text containing `\n`, check if the response is properly segmented according to line breaks.
- Access the FastGPT v4.17.0 backend configuration panel, confirm that the values of `quoteMaxToken` and `responseData` match the preset settings.
