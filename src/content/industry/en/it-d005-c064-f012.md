# Technical Documentation and Interface Q&A for Tender Document Preparation: Document Parsing and Chunking

## What this category of data looks like
The data sources for this category are tender announcements, tender documents, enterprise qualification databases, and supplier quotations. The update rhythm is tied to each individual order. Commonly processed documents include tender documents, qualification certificates, business deviation tables, and technical deviation tables. The overall structure strictly follows the format specified by the tenderer, including fixed fields such as qualification response clauses, business quotation items, and technical parameter items. There is no unified fixed unit, and specific units are dynamically adjusted according to tender requirements.

## What constraints do these characteristics impose on the document parsing and chunking link
Since tender documents strictly follow the format specified by the tenderer, document parsing and chunking must match the chapter structure to avoid cross-chapter cutting that causes breaks in subsequent clause response verification. The data update rhythm is once per order with scattered order volumes, so the system must support fast batch parsing of tender documents and qualification documents in different formats. Documents such as qualification certificates and business deviation tables contain a large number of structured tables and fixed fields. Parsing must retain the original format association relationships, otherwise the accuracy of qualification material verification will be affected. A single tender project may include multiple types of documents, so the system must automatically identify different document types and adapt corresponding chunking rules.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | The response content for a single clause in tender documents is usually several hundred characters. This range can fully retain the logic of a single response and avoid cutting critical clauses |
| `chunkSplitter` | Split by paragraph + title | Matches the chapter-title-based structure of tender documents, and retains the contextual association of clauses |
| `customPdfParse` | Enabled | Retains original typesetting information for the large number of tables and formatted content in tender documents, facilitating subsequent verification |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapts to the upload requirements of multi-page tender documents and batch qualification files, preventing large files from being blocked |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large single tender documents require sufficient parsing time to avoid parsing failures due to timeout |
| `chunkSettingMode` | Manual configuration | Allows adjustment of chunking rules for different types of tender documents, such as qualification certificates and deviation tables, to adapt to structured content |

## Three common mistakes
- Parsing qualification certificate files in JSON format returns an error indicating a format error. The cause is that custom parsing rules are not enabled for structured documents, and the default chunking logic cannot correctly identify nested fields within JSON.
- FastGPT v4.17.0 deployed locally cannot enable the file parsing function. The cause is that environment variables for parsing-dependent services are not configured correctly, or local resources are insufficient to support the parsing process.
- Calling doc2x to parse a hundreds-page tender document fails, while small-page files parse normally. The cause is that the `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted. The parsing time for large files exceeds the default threshold, triggering a timeout interruption.

## How to confirm the configuration is correct
- Upload a typical tender document that includes chapter titles and response clauses, check the parsed chunk results, and confirm that each chunk contains a complete single response logic with no cross-chapter cutting.
- Upload a maximum test file that matches the `UPLOAD_FILE_MAX_SIZE` setting, confirm that the upload and parsing process completes normally with no blocking or timeout prompts.
- After enabling `customPdfParse`, upload a qualification certificate file that includes tables, confirm that the parsed result retains the row and column association relationships of the tables, with no critical content lost.
- After adjusting the `chunkSize` parameter, compare the number of chunks under different values, and confirm that the chunk length adapts to the content integrity requirements of the currently processed documents.

The values provided are common starting points and should be measured against the reader's own samples.
