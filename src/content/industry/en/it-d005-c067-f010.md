# Technical Documentation and API Q&A for Data Security Classification and Grading: Citation Sources and Traceability

## What this category of data looks like
This category of data includes four core document types: data catalogs, classification and grading rules, important data identification tables, and review minutes. Data sources include data asset inventory results, database metadata, business system description documents, and public compliance requirements. Update frequency is quarterly updates or synchronized updates after a single business system change. Each individual document contains fixed fields such as data asset name, classification level, sensitive field identifier, owning system, and update date. There is no dynamically changing business indicator content.

## What constraints do these characteristics impose on the citation source and traceability link
The multi-source attribute of this category of data requires that the citation traceability link clearly mark the original data source type of each citation, and distinguish between metadata, business documents, and compliance documents. The quarterly update frequency means that the traceability link must support quick location of historical versions, to avoid citing outdated old version classification rules. The structured document feature with fixed fields requires precise matching of core fields such as data asset name and classification level during traceability, to avoid misjudging unstructured temporary comments as valid citation sources. Citations of review minute documents must be associated with corresponding data asset change records, to ensure that traceability results meet compliance audit requirements.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | The core citation content of this category includes fixed fields such as classification level and sensitive field identifier. This range covers complete single citations and avoids truncating compliance-critical information |
| `responseData` | `only return structured citation sources` | This category of data is mainly structured documents, and unstructured temporary comments have no compliance reference value. Filtering them improves traceability accuracy |
| `detail` | `display original data source type and update date` | This category of data must meet compliance audit requirements. Clearly marking data source type and update date allows quick verification of the validity and timeliness of cited content |
| Citation source sorting rule | sort in descending order of data source update time | The update frequency of this category of data is quarterly or synchronized after changes. Sorting by update time prioritizes displaying the currently effective classification and grading rules, avoiding citing outdated invalid content |

## Three common misconfigurations
- Symptom: The citation sorting returned by knowledge base search does not meet expectations, and is not arranged according to the intended logic. Cause: The rule for sorting by data source update time is not configured, and the general sorting logic is mistakenly applied to this category of structured data, causing outdated invalid classification rules to be displayed first.
- Symptom: Citation content not associated with the local knowledge base appears in conversations. Cause: Structured filtering for `responseData` is not enabled, unassociated compliance document fragments are mistakenly identified as valid citation sources, or the matching relationship between citation sources and current data assets is not verified.
- Symptom: Citation content is truncated, and complete classification levels or sensitive field identifiers cannot be displayed. Cause: The value of `quoteMaxToken` is too small, and does not cover the core field length of single citations in this category, resulting in loss of compliance-critical information.

## How to confirm that the configuration is correct
- Initiate an API Q&A targeting classification and grading rule documents, and check whether the returned citation content includes the original data source type and update date fields.
- Trigger a query containing outdated classification rules, and confirm whether the returned citation source is the latest currently effective version.
- Test a long-text classification and grading rule query, and confirm that the citation content is not truncated and displays core fields completely.
- Initiate a query not associated with local data assets, and confirm that unrelated citation content is not returned.
