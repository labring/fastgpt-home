# Technical Documentation and API Q&A for Database Cloud Service Operations: Document Parsing and Chunking

## What the data for this category looks like
The data for this category originates primarily from cloud database consoles, slow logs, monitoring metrics, and ticket systems. Commonly processed documents include instance change orders, backup and recovery records, performance diagnosis reports, and parameter adjustment records. Data updates occur daily or after each completed change operation. Documents contain both structured fields and unstructured text. Structured fields include instance ID, change time, and backup path. Unstructured content includes slow SQL statements and performance analysis descriptions. Some fields include specific units.

## Constraints on the Document Parsing and Chunking Link
Documents in this category have significant structural differences. They include structured parameter adjustment records and unstructured slow log text. Chunking rules must balance field association and context integrity. Data is updated at a high frequency. The parsing link must support batch rapid processing to avoid delaying operational response speeds. Document sources include multi-tenant consoles and ticket data. Chunking must avoid splicing cross-tenant information to maintain data isolation. Large archived logs and PDF-format diagnosis reports make up a large share of content. The parsing link must support large files and complex layout content extraction, while preserving the correspondence between fields and text.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | `800–1200 characters` | This category includes slow SQL statements and parameter adjustment content of varying lengths. This range balances context integrity and chunk retrieval efficiency |
| `chunkSplitter` | By paragraph + heading | Documents in this category have clear heading hierarchies, such as change items in instance change orders and backup steps. Splitting by paragraph + heading preserves business context association |
| `customPdfParse` | Enabled | Backup and recovery records and performance diagnosis reports in this category are mostly in PDF format. Enabling custom parsing extracts form fields and code block content |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | The size range of single slow log archived files uploaded in this category is broad. This upper limit covers the storage and parsing needs of standard archived files |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Parsing large PDF or structured log files requires extended processing time. This duration prevents timeout interruptions during standard file parsing |
| `chunkSettingMode` | Manual configuration | Documents in this category have significant structural differences. Manual configuration allows adaptation of chunking rules for different document types |

## Three Common Misconfigurations
- Symptom: An "offset out of range" error appears when the upload progress reaches approximately 90% for large PDF or log archived files. Cause: The `UPLOAD_FILE_MAX_SIZE` and `PARSE_FILE_TIMEOUT_SECONDS` configurations are not adjusted. File parsing times out or exceeds the upload limit.
- Symptom: Chunking results differ between files uploaded via API and those uploaded directly through the platform. Cause: The `chunkSettingMode` and `chunkSplitter` configurations are not unified. Default chunking rules vary between the two upload paths.
- Symptom: Direct chunking fails to identify slow SQL statements or parameter adjustment records in PDFs. Cause: `customPdfParse` is not enabled. The default PDF parser does not extract structured forms and code block content.

## How to Verify Configurations
- View the knowledge base upload configuration page to confirm that values for parameters including `chunkSize` and `chunkSplitter` match the preset configurations.
- Upload a single archived log file under 1000 MB, and confirm that the upload progress completes without interruption or offset errors.
- Upload a mixed document containing instance change orders and slow SQL, and check that chunking results retain the context association between headings and corresponding content.
- Call the create file collection API to upload a test file, and compare the chunking results with those from direct platform uploads to confirm that both use consistent chunking rules.

The configuration values provided here are common starting points. They should be evaluated against the reader's own samples.
