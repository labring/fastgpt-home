# Technical Documentation and Interface Q&A for Text Annotation Projects: Source Citation and Traceability

## What Data for This Category Looks Like
Text annotation project data covers daily documents including annotation specifications, sample packages, quality inspection reports, and feedback forms. Data sources include customer-provided corpora, annotation results from annotation platforms, industry standard vocabularies, and verification results from quality inspection sampling. Data updates run daily or per annotation batch. Single entries mostly contain fields like text content, corresponding tags, annotator, quality inspection status, and no additional image attachments. The core focus is on semantic entities, intent boundaries, and tag associations.

## Constraints Imposed by These Data Characteristics on Source Citation and Traceability
The data characteristics of text annotation projects create multiple constraints for the traceability process. Data sources are scattered and updated per batch. Traceability must accurately link annotation batches to original corpora to avoid cross-batch confusion. Most daily documents are semi-structured text. Traceability needs to match tag fields to referenced fragments, and cannot rely on image metadata for association. The high update frequency requires limiting the historical data scope for single traceability runs to prevent overloading retrieval resources. Additionally, the core annotation logic focuses on semantic boundaries and intent. Traceability must retain tag explanations and sampling verification association information. Missing traceability will lead to ambiguous tag boundary explanations, which can cause model training deviations, rework, or delayed deliveries.

## Configuration Settings
This page’s configuration instructions are based on FastGPT v4.17.0. The specific configuration items are as follows:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Text annotation data mostly consists of short text fragments. This range matches the average length of annotation samples to avoid truncating valid traceability information |
| `responseData` | Return only annotation-related fields | Traceability for text annotation projects only needs to link tags, annotation batches, and corpora. No redundant extra data is required |
| `detail` | Enable full traceability | Association details between quality inspection sampling results and annotation specifications must be retained to meet arbitration and sampling inspection traceability requirements |
| Single traceability entry limit | `Top 3 entries` | Core samples for annotation projects are concentrated. Too many traceability entries will interfere with annotation logic and reading experience |
| Traceability data scope | Current batch + previous 1 batch | Data updated daily or per batch. Cross-batch traceability easily causes confusion. Limiting the scope improves accuracy |

## Three Common Misconfigurations
- Accidentally disabling all source citation displays, which prevents tracing annotation basis. This occurs when the traceability configuration display switch is turned off by mistake, which does not meet the quality inspection and arbitration requirements of annotation projects.
- Empty source citation fields, which fail to link tags and batch information. This happens when the return fields for `responseData` are not correctly configured, and annotation-related metadata to be returned is not specified.
- Traceability results truncating tag boundary explanation content from annotation specifications. This occurs when the value of `quoteMaxToken` is set too small, which truncates valid traceability text.

## How to Verify Successful Configuration
- A query including tag boundary explanations can be executed, and returned source citations checked for fragments from the corresponding annotation specifications.
- Retrieval logs can be reviewed to confirm that only annotation data from the current batch or specified scope is retrieved.
- The status of the `detail` configuration item can be checked to confirm that association information for quality inspection sampling is retained.
- Source citation fields can be verified to include necessary identifiers such as annotator and batch number.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
