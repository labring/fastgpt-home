# Technical Documentation and API Q&A for Computer Room Inspection and Environmental Monitoring: Knowledge Base Retrieval and Recall

## What this category of data looks like
Data for this category primarily comes from environmental monitoring, access control systems, UPS monitoring, and video inspection equipment. Daily generated documents include inspection reports, temperature and humidity records, alarm records, and duty logs. Common fields across these documents include device ID, inspection point, temperature and humidity value, alarm level, and timestamp. Temperature and humidity values use units of ℃ and %RH. Data is updated in real time or daily, and is entered or synced directly by operations staff or monitoring systems.

## What constraints these characteristics impose on the knowledge base retrieval and recall stage
Multi-source heterogeneous data sources require the retrieval system to support mixed recall across devices and document types, and to adapt to mixed matching of structured fields (such as device ID, timestamp) and unstructured text. Real-time updated temperature and humidity and alarm data require that recall results prioritize the latest data, and avoid using expired vectors. The semi-structured nature of inspection reports and duty logs requires retrieval to support both semantic matching and exact field matching, enabling operations staff to quickly locate inspection results for specific points. The high timeliness requirement of alarm records requires support for filtering recall results by time range, to prevent redundant historical data from interfering with judgment.

## Configuration Settings
These configurations are adapted for FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches highly relevant content such as alarms and temperature and humidity readings, and avoids recalling irrelevant inspection records |
| `limit` | Top 10 entries | Adapts to the amount of information viewed by operations staff in a single session, and avoids excessive results interfering with the location of core alarms |
| `searchMode` | hybrid | Balances structured field matching and semantic recall, adapting to the mixed data structure of inspection reports and alarm records |
| `usingReRank` | Enabled | Re-sorts recall results by relevance, prioritizing high-priority alarms and the latest inspection results |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands query terms, supplements common operations terms such as device models and inspection points, and improves recall accuracy |
| `collectionIds` | Configured by computer room group | Limits the retrieval scope to the dataset of the target computer room, avoiding cross-room data interfering with operational judgment |

## Three Common Misconfigurations
- Phenomenon: An error indicating format failure is prompted when importing Markdown files of temperature and humidity records. Cause: Structured fields of inspection reports (such as device ID, temperature and humidity value) are not formatted according to standard Markdown table specifications, causing system parsing failure.
- Phenomenon: Recall results work normally during debug preview, but cannot be searched after embedding into a self-owned page. Cause: The `collectionIds` parameter is not configured correctly, and the retrieval scope is not limited to the dataset of the target computer room, resulting in cross-room data range conflicts.
- Phenomenon: Attached images in alarm records in the knowledge base cannot be displayed normally, with a high error rate in cloud environments. Cause: Image resources are not uploaded to the associated cloud storage bucket, or the index configuration for image metadata is not enabled, causing vector retrieval to fail to associate image content.

## How to Confirm the Configuration is Complete
- Manually enter a known alarm record keyword, check whether the recall result includes the record and the sorting meets expectations.
- View the retrieval log, confirm that `searchMode` is set to hybrid mode, and the `similarity` value falls within the preset 0.75–0.85 range.
- Test filtering queries by time range, confirm that only alarm and inspection data within the specified time period is recalled.
- Check the dataset update log, confirm that real-time synchronized environmental monitoring data has been correctly indexed.

The values provided are common starting points and should be evaluated against samples from the target deployment environment.
