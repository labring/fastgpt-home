# Technical Documentation and API Q&A for Cabinet Rack Installation and Cabling: Source Citation and Traceability

## What this category of data includes
This category of data is primarily sourced from DCIM systems, asset management systems, network topology diagrams, and customer construction work orders. It is updated per individual work order or once daily.
Daily generated documents include cabinet rack installation application forms, cabling topology diagrams, port label comparison tables, and on-site construction records.
Data fields include rack unit number, cable port identifier, construction date, device model, and customer-related information. Data is only associated via single construction work orders, with no fixed batch statistics unit.

## Constraints on citation and traceability workflows
This category of data is updated per order and sourced across multiple systems. Citation traceability must accurately bind exclusive information such as rack units and ports for a single construction work order, to avoid mixing data across orders.
Diverse document types require matching different traceability display formats. For example, topology diagrams must mark the vector position of the corresponding rack unit. Construction records must be linked to specific construction personnel and dates.
The high-frequency update feature requires the traceability system to pull the latest DCIM and work order data in real time. This prevents the use of outdated port labels or rack planning information, which can cause errors during the acceptance phase.

The following configurations apply to FastGPT v4.17.0.

## How to Set Configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Core documents for cabinet rack installation and cabling typically contain port labels and rack planning information. This range covers a complete construction record or topology diagram annotation |
| `responseData` | Return only DCIM and work order-associated data | Data for this category must be bound to a single construction work order and asset information. Returning only specified source data avoids irrelevant content interfering with traceability |
| `detail` | Enabled | Subfields such as port number and rack unit location need to be displayed. Enabling this setting returns complete citation source details |
| Single search limit | Top 3 results | The number of cabinets and ports involved in a single construction is limited. The top 3 results cover core citation needs and avoid redundant data |
| Citation source display format | Classified by work order ID + rack unit number | Matches the per-order association feature of this category of data, allowing operation and maintenance personnel to quickly locate corresponding construction records |

## Three Common Configuration Mistakes
- Symptom: The citation source field returned by the API is empty, or the displayed content is unrelated to the current construction work order. Cause: `responseData` is not configured to return only DCIM and work order-associated data, resulting in redundant data from other categories being mixed in.
- Symptom: Knowledge base search fails to match the target port label or rack planning content, with insufficient citation entries. Cause: The `quoteMaxToken` value is not adjusted according to the per-order update feature of this category of data, or the single search limit is set too high, causing redundant data to dilute accurate matching results.
- Symptom: The citation source displayed in the AI response does not mark specific rack units or port numbers. Cause: The `detail` configuration is not enabled, only simplified document titles are returned, and subfield information is not included.

## How to Confirm Configuration is Correct
- Initiate an API call targeting a specific cabinet rack installation work order, check if the returned `responseData` field only contains DCIM and work order-associated content.
- Review the citation source in the AI response, confirm that it is classified by work order ID and rack unit number, and includes subfields such as port numbers.
- Adjust the `quoteMaxToken` value, verify that the search results cover the complete content of the target construction record, with no truncation or redundancy.
- Simulate multiple calls for queries from different work orders, confirm that the returned citation source is only bound to the information of the corresponding work order, with no cross-order mixing.
