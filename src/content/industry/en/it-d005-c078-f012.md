# Technical Documentation and Interface Q&A for Cabinet Installation and Cabling: Document Parsing and Chunking

## What Data for This Category Looks Like
Data for this category primarily comes from DCIM systems, asset management systems, network topology diagrams, and customer work orders. Documents processed daily include installation application forms, cabinet cabling diagrams, port label sheets, and construction records. Document fields include cabinet position number, cable length, port identifier, construction date, and more. Units include cabinet height U, cable length in meters, port number, and others. Data update frequency is per order or daily, synced with construction progress or work order circulation.

## What Constraints These Characteristics Impose on the Document Parsing and Chunking Link
The multi-source mixed document structure of this category requires parsing and chunking to adapt to multiple formats including plain text work orders, structured port tables, and vector cabling diagrams. It also requires avoiding splitting key associated fields and units. The high-frequency update feature requires the parsing process to support incremental synchronization. It also requires limiting the reasonable volume of a single parsed document to avoid timeouts. Specific business fields such as cabinet positions and cables require retaining the binding relationship between fields and corresponding business identifiers during chunking. This ensures accurate association of cabinet position and cable information during retrieval.

## How to Configure Settings
These configurations are formulated based on FastGPT v4.17.0 logic.

| Configuration Item | Recommended Value Range | Rationale |

| `chunkSize` | 800–1200 characters | This category of documents includes structured port tables and long-text construction records. This range preserves key business associated context such as cabinet positions and cables |
| `chunkSplitter` | Split by paragraph + title | Construction records accompanying cabinet cabling have clear chapter divisions. Splitting by title preserves business module integrity |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Single cabinet cabling drawing sets or bulk construction record documents have large volume. This value covers most business scenarios |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large vector cabling diagrams require long processing time. This avoids interrupting the parsing process due to timeout |
| `customPdfParse` | Enable external parser | Some hand-drawn cabling diagram PDFs require specialized tools to adapt vector graphic content. External parsers improve parsing accuracy |
| `chunkSettingMode` | Manual configuration | This category of documents has large format differences. Manual configuration accurately matches business field splitting requirements |

## Three Common Mistakes
- Uploading files triggers a 413 error. The cause is that the `UPLOAD_FILE_MAX_SIZE` configuration value is smaller than the actual file size of the uploaded file, exceeding the system's allowed upload limit.
- The external pdf-maker parser fails to call normally. The cause is that the corresponding parser's key information is not configured in environment variables in docker deployment mode, causing the parsing service to fail authentication.
- Feishu multi-level directory documents only allow retrieval of first-level content. The cause is that the default chunk configuration does not enable multi-level directory pulling function, and does not associate complete directory permissions of Feishu documents, resulting in incomplete parsing of deep directory content.

## How to Confirm Configurations Are Set Correctly
- Upload the maximum volume single document that fits the business scenario. Verify the upload request is received normally, with no 413 errors.
- After configuring the external PDF parser, upload a hand-drawn cabling diagram PDF. Verify the parsed text includes cabinet position markings and cable identification information from the drawing.
- Import a Feishu multi-level directory document. Search for construction record keywords in deep directories, confirm the corresponding content is retrieved.
- Call the API to upload a test document. Verify the returned result includes parsed chunked text, with no empty results or timeout prompts.
