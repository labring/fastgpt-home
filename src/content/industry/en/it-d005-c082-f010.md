# Technical Documentation and Interface Q&A for Channel Attribution and Lead Distribution: Source Citation and Traceability

## What Data for This Category Looks Like
Data for this category primarily comes from advertising platforms, CRM systems, attribution SDKs, and form systems. Daily maintained documents include attribution rule configuration tables, lead distribution tables, channel effect reports, and exception checklists. Data update cycles are mostly daily or weekly. Fields include channel identifiers, lead unique IDs, assigned sales accounts, conversion times, conversion amounts, and more. It is necessary to match the output field specifications of each system, and there is no unified mandatory format.

## Constraints on Source Citation and Traceability from These Characteristics
Format differences across multiple data sources require that unique identifiers from each system be unified during citation traceability to avoid duplicate lead statistics across systems. Daily or weekly update cycles mean traceability data must be synchronized on a regular basis, and real-time full data pulling cannot be relied upon. Different types of business documents must be individually linked to their corresponding data sources to ensure that specific configuration or report entries can be located during traceability. Additionally, the controversial nature of lead assignment requires that traceability results be traceable back to original data nodes, to support subsequent exception checks and responsibility determination.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the length of single records in channel attribution data, to avoid truncating critical channel identifiers and lead information |
| `responseData` | Return only core associated fields | Reduces invalid data transmission, and focuses on core traceability fields such as channel ID and lead assignment |
| `detail` | Enable full detailed display | Supports viewing original attribution SDK logs and form submission records during exception checks |
| Traceability data synchronization cycle | Calibrated to business update cycles (1 day / 7 days) | Matches the daily or weekly update frequency of advertising platforms and CRM systems |
| Source citation display limit | Top 3 valid records | Controls interface display length, while covering major channel conversion paths |
| Multi-source association switch | Enable cross-system association | Adapts to traceability requirements for dual data sources of advertising platforms and CRM |

## Three Common Misconfigurations
- Symptom: After configuring citation traceability, only the original question text is returned when connecting to WeChat Work, with no corresponding answer. Cause: The return range of `responseData` is not correctly configured, only traceability data is pulled and the model answer logic is not loaded.
- Symptom: Some workflow nodes cannot independently control the visibility of viewing source text. Cause: The switch state of the `detail` parameter is not set individually for different nodes, resulting in uniform permission configurations taking effect.
- Symptom: Some attribution documents do not generate traceable question-answer pairs, and original text is written directly. Cause: Block matching with `quoteMaxToken` is not enabled for structured attribution rules and exception checklist documents, resulting in key traceability fields not being extracted during splitting.

## How to Verify Successful Configuration
- Navigate to the workflow configuration page of FastGPT v4.17.0, and check whether the parameters in the source citation module match the preset configurations.
- Enter a test lead query, and check whether the returned results include matching channel identifiers and original data source identifiers.
- Switch between different workflow nodes, and verify that the switch for viewing source text can be controlled independently.
- After simulating a daily data update, check whether traceability results have synchronized the latest channel report data.
