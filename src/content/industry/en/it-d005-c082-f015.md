# Technical Documentation and Interface Q&A for Channel Attribution and Lead Distribution: Knowledge Base Retrieval and Recall

## What the data for this category looks like
The core users of this category are growth operations, sales operations, and data analysts. Daily documents used include attribution rules, lead distribution tables, channel reports, and exception checklists. Data mainly comes from advertising platforms, CRM systems, attribution SDKs, and form systems. Data update cycles are mostly daily or weekly. Each document or dataset includes fields such as channel identifiers, lead source parameters, conversion times, and assigned sales accounts. There are no unified fixed units, and some fields need to match corresponding coding rules based on business scenarios.

## What constraints these characteristics impose on knowledge base retrieval and recall
The data sources for this category are scattered, and field attributes are clear. This requires knowledge base retrieval to support precise recall across multiple data sources, to avoid confusing parameter identifiers of different channels. Daily documents include both structured lead distribution tables and unstructured attribution rules, so retrieval logic needs to adapt to content in different formats. Data is updated daily or weekly, so flexible configuration of incremental sync or full sync is required to ensure retrieval results match the latest business data. At the same time, fields must strictly correspond to key business items such as channel IDs and lead assignments. Retrieval logic must avoid incorrect matching caused by field misalignment, which would affect subsequent attribution and distribution results.

## How to Set Up Configurations
This document is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches strongly correlated fields such as channel IDs and lead assignments, requires ensuring the accuracy of retrieval results to avoid irrelevant low-similarity content being included |
| `limit` | Top 8–12 entries | A single round of retrieval for this category needs to cover multiple key documents, while avoiding excessive context that causes redundancy, balancing recall volume and inference efficiency |
| `searchMode` | Hybrid semantic retrieval + keyword retrieval mode | Balances keyword matching for structured reports and semantic understanding for unstructured rules, adapting to multiple types of business documents |
| `usingReRank` | Enabled | Performs secondary ranking on recall results to filter out content with similar semantics but low business relevance, improving the recall priority of key leads |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically optimizes query terms, supplements exclusive fields such as channel parameters and business codes, improving retrieval matching accuracy |
| `collectionIds` | Bind corresponding collections by business module | Only retrieves knowledge base collections related to channel attribution and lead distribution, avoiding irrelevant documents interfering with retrieval results |

## Three Common Mistakes
- Symptom: Unable to automatically sync Feishu knowledge base data, only manual file upload is supported. Cause: Authorization configuration for the Feishu data source has not been completed, or the scheduled trigger rule for automatic sync has not been enabled.
- Symptom: Unable to select multiple files at once in the knowledge base interface to limit the retrieval scope. Cause: The function switch for batch document selection has not been enabled, or the interface path for batch operations has not been mastered.
- Symptom: Timeout or frequency restriction errors occur when calling knowledge base interfaces. Cause: The retrieval frequency threshold has not been adjusted based on the business data update cycle, or a reasonable request timeout duration has not been configured, leading to platform restrictions being triggered by high-frequency requests.

## How to Verify the Configuration is Correct
- Precise retrieval targeting channel IDs may be performed, to confirm returned results only include business documents within bound collections, with no irrelevant content.
- Knowledge base sync task logs may be reviewed, to confirm daily or weekly update processes trigger normally with no failed records.
- The `similarity` threshold may be adjusted for multiple rounds of testing, to verify retrieval result accuracy meets business matching requirements.
- High-frequency retrieval requests may be simulated, to confirm interface returns are normal and no platform frequency restrictions are triggered.

The configuration values provided above are common starting points, and should be evaluated against applicable samples.
