# Technical Documentation and API Q&A for Game Content Compliance Self-Check: Citation Sources and Traceability

## What data for this category looks like
Data sources for game content compliance self-check include game text, art resource descriptions, plot scripts, and public regulatory requirements. Daily maintained documents include content self-check lists, sensitive content modification records, user agreements, and compliance review minutes.
Data updates occur per version or per activity cycle. Fields include content subject identifier, version information, compliance check tags, and other relevant fields. Documents are categorized and stored by version and business module. Compliance association information for a single data entry must be bound to the corresponding version and modification traces to ensure the complete compliance processing chain can be linked during traceability.

## What constraints do these characteristics impose on the citation sources and traceability link
Since data is updated per version or activity, the traceability link must bind version identifiers to distinguish compliance content across different cycles, avoiding cross-version confusion. The storage structure of multiple data types requires traceability to associate corresponding documents by data type. For example, game text must be linked to self-check lists, and art resources must be linked to modification records.
The closed-loop nature of daily documents requires traceability to cover the full process from check to modification, ensuring that compliance reviews can trace the complete processing flow. The severity of potential errors also requires that traceability information must accurately match the content subject, with no mismatches or omissions.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Aligns with the typical text length for game compliance scenarios in FastGPT v4.17.0, preventing truncation of critical content required for traceability |
| `responseData` | Includes source file path, version identifier, modification record | Matches the versioned, traceable characteristics of game compliance data to meet review and traceability requirements |
| `detail` | Full | Displays original basis details of compliance checks to facilitate verification of content compliance |
| Maximum context entries | Top 5 entries | Reference materials for game compliance self-checks are usually concentrated in documents from the current version and adjacent activities, avoiding interference from redundant information |
| Retrieval matching threshold | 0.72–0.88 | Balances recall precision and coverage for compliance content, reducing invalid matching results |

## Three common misconfigurations
- Phenomenon: After calling the knowledge base tool in a workflow, the output result does not include any citation information. Cause: The `responseData` configuration item is not enabled, or the configuration does not include the source file path and version identifier fields.
- Phenomenon: Garbled citation markers appear at the end of dialogue outputs, which automatically convert to normal quotation marks afterward. Cause: The `detail` configuration is not properly adapted to the output format, resulting in citation symbols not being properly escaped.
- Phenomenon: When asking compliance questions that do not exist in the knowledge base, irrelevant document citations are still returned. Cause: The retrieval matching threshold is set too low, or the empty citation logic for no matching results is not configured, leading to accidental recall of irrelevant compliance content.

## How to confirm proper configuration
- Initiate a test query with clear compliance keywords, check whether the output result includes traceability information such as source file path and version identifier.
- View the dialogue log, confirm that the token length of the cited content does not exceed the configured `quoteMaxToken` range.
- Enter a compliance question that does not exist in the knowledge base, verify that no irrelevant citations are returned, or that a correct no-match prompt is displayed.
- Adjust the retrieval matching threshold, check whether the number of recall results changes as expected.

The values provided here are common starting points and should be measured against the reader's own samples.
