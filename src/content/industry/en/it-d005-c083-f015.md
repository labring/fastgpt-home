# Technical Documentation and API Q&A for Game Content Compliance Self-Check: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
The data for this category mainly comes from game text, story scripts, art resources during game development, and compliance requirement documents publicly released by regulators. Maintained documents include content self-check lists, sensitive content modification records, user agreements, and compliance review minutes. Data updates occur synchronously per version or per event. Story scripts, art resources, and compliance requirements differ across versions. The data structure primarily uses structured checklists and unstructured text scripts, with no unified fixed fields. It is adjusted based on specific compliance scenarios.

## Constraints Imposed on Knowledge Base Retrieval and Recall
The data for this category updates frequently and adjusts with version iterations. This requires knowledge base retrieval to support synchronization per version cycle, to avoid recalling outdated compliance requirements. The data includes structured self-check lists and unstructured story scripts and art descriptions. Retrieval must support recall matching across multiple formats. There are many similar compliance judgment logic scenarios, leading to semantically similar retrieval requests. This requires avoiding redundant recall results. Compliance self-check has strict timeliness requirements. Retrieval results must be returned within business process nodes, otherwise audit delays will occur.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches semantic matching accuracy for game compliance text, balancing missed detection and false recall risks |
| `limit` | Top 8 entries | Covers the number of compliance items to reference for a single self-check, avoiding result overload |
| `searchMode` | hybrid | Balances keyword matching and semantic recall, adapting to structured self-check lists and unstructured story scripts |
| `usingReRank` | Enabled | Reorders recall results by relevance, prioritizing content related to high-sensitivity compliance matters |
| `datasetSearchUsingExtensionQuery` | Enabled | Performs semantic extension on user self-check questions to match similar compliance scenarios |
| `collectionIds` | Exclusive compliance self-check collection ID | Isolates business data to avoid interference from irrelevant knowledge base content on retrieval |

## Three Common Configuration Mistakes
- Phenomenon: A large number of irrelevant non-compliance documents appear in retrieval results. Cause: `collectionIds` is not specified, and the exclusive knowledge base collection is not isolated, leading to retrieval scope covering irrelevant business data.
- Phenomenon: Retrieval results for similar self-check questions vary significantly. For example, "story violence self-check" and "story fight self-check" return unrelated results. Cause: `datasetSearchUsingExtensionQuery` is not enabled, and no semantic extension is performed on the question, so semantically similar compliance judgment logic cannot be matched.
- Phenomenon: Outdated compliance requirements are included in retrieval results. Cause: The knowledge base is not updated per version cycle, leading to recall of outdated regulatory requirements or old version self-check list content.

## How to Verify Proper Configuration
- Execute a single compliance self-check question, and check whether retrieval results only come from the specified compliance knowledge base collection.
- Input multiple sets of semantically similar self-check questions, and verify whether the relevance of retrieval results meets business expectations.
- Simulate data synchronization after a version update, and check whether the knowledge base can properly load new compliance documents.
- View the retrieval configuration panel, and confirm that switches such as `usingReRank` and `datasetSearchUsingExtensionQuery` are enabled as required.

The configuration values provided here are common starting points. They should be evaluated against the reader's own samples.
