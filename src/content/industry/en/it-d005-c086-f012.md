# Technical Documentation and Interface Q&A for Game Publication License and Publishing Declaration: Document Parsing and Chunking

## What Data for This Category Consists Of
This category’s data mainly comes from the national press and publication administration’s official service platform, copyright registration system, game package files, and materials submitted by operating institutions. Daily processed documents include declaration request files, game application forms, copyright certification documents, and content review reports. Each game corresponds to a separate set of declaration materials, with update schedules adjusted irregularly according to project progress. Most document structures include fixed declaration fields, structured tables, and long explanatory texts. Some materials contain specific formatted content required for compliance verification.

## Constraints on Document Parsing and Chunking
Dispersed data sources lead to inconsistent document formats. Some materials use fixed templates from official platforms, while others are custom-submitted files, requiring higher parsing compatibility. Each game’s materials are independent and updated irregularly, making it impossible to adapt all scenarios through fixed batch rules. Documents include structured tables and long compliance explanations. When chunking, the integrity of table structures must be preserved to avoid splitting key verification fields. Some materials contain sensitive compliance content. Parsing must ensure that sensitive information is not accidentally split, while meeting context coherence requirements for subsequent review and verification.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `customPdfParse` | Configure with the actual deployed custom parsing service address, or disable it to use the built-in parser | The declaration materials for this category include official template PDFs and custom-submitted files, requiring compatibility with multiple format parsing |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 seconds | Most declaration materials are multi-page PDFs or contain large tables, which take longer to parse, avoiding timeout interruptions |
| `chunkSize` | 800–1200 characters | Declaration materials include long review explanations and structured fields. This length preserves context coherence and avoids splitting key compliance information |
| `chunkSplitter` | Split by paragraph and heading | Documents include fixed declaration chapters and explanatory texts. Splitting by heading preserves chapter integrity, facilitating subsequent consistent verification |
| `UPLOAD_FILE_MAX_SIZE` | 500–1000 MB | Some declaration materials attached to game packages have large sizes, requiring adaptation to large file upload requirements |
| `chunkSettingMode` | Manual configuration | The format of declaration materials varies per game. Manual configuration allows flexible adjustment of chunking rules |

## Three Common Misconfigurations
- Symptom: After uploading a declaration PDF file, parsing fails or empty content is returned. Cause: The `customPdfParse` parameter is not configured correctly, or the custom parsing service does not support official template formats.
- Symptom: After uploading a large declaration material, there is no response for a long time, and a timeout error is finally returned. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted, and the default value causes parsing time to exceed the limit.
- Symptom: After importing declaration CSV table data, only the first two columns of content are displayed. Cause: Table parsing rules are not explicitly configured. The default setting only extracts the first two columns of fields, which does not adapt to the multi-column structured format of declaration materials.

## How to Verify Correct Configuration
- Upload a standard game declaration PDF file, and check whether the parsed chunk results preserve the integrity of chapter headings and paragraphs.
- Upload a single declaration material with a size not exceeding 1000 MB, and confirm that the upload and parsing processes do not have timeout errors.
- Import a declaration CSV file with multiple columns, and confirm that all preset fields are correctly extracted.
- In FastGPT v4.17.0, adjust the `chunkSize` parameter and re-parse the same document to verify that the chunk length matches the expected setting.

The values listed are common starting points and should be evaluated against samples appropriate for the specific use case.
