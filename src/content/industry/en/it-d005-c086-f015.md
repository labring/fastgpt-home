# Technical Documentation and API Q&A for Game Publication License and Publishing Declaration: Knowledge Base Retrieval and Recall

## What the data for this category looks like
The data sources for this category include national press and publication administration service documents, copyright registration certificates, game packages, and operator information. Document types include declaration request files, game application forms, copyright certificates, review reports, and more. The declaration materials for a single game include fixed fields such as the declaration entity, game name, copyright number, and review opinions. The data update frequency is irregular per game declaration cycle. The scale of the material collection for a single declaration varies by project complexity, with no fixed batch update rhythm.

## What constraints these characteristics impose on knowledge base retrieval and recall
Dispersed data sources lead to differences in document formats, requiring a unified retrieval logic adapted to multi-source data. Irregular updates require configuring incremental synchronization mechanisms to avoid overwriting old data or missing new data. Declaration materials for a single game have cross-document associations. Retrieval must accurately match the exclusive materials of the current project to prevent interference from irrelevant results across games. Error consequences are directly linked to approval progress and operational qualifications. Retrieval results must have high confidence, while retrieval time must be controlled to adapt to the high-frequency business scenario of material verification.

## How to set configurations
This document is written based on FastGPT v4.17.0. Specific configuration items and recommendations are as follows:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Government documents have strict semantic requirements. Filter low-related results to avoid mistakenly recalling declaration materials for non-corresponding games |
| `limit` | Top 10 entries | The number of declaration materials for a single game is limited. Excessive results increase the context processing burden, adapting to the document scale of the business scenario |
| `usingReRank` | Enabled | Government documents contain a large number of similar expressions. Reranking improves the sorting priority of highly relevant results, adapting to semantic matching for long texts such as review reports |
| `datasetSearchUsingExtensionQuery` | Enabled | Declaration documents often use both short names and official full names. Extended queries cover more synonymous expressions, improving recall completeness |
| `collectionIds` | Bind the exclusive dataset for the corresponding game declaration | Avoid interference from cross-category data, ensuring the retrieval scope only covers the declaration materials of the current project |
| `searchMode` | Semantic retrieval mode | Keyword matching for government documents is easily disrupted by formatting. Semantic retrieval accurately matches the core semantics of declaration requirements |

## Three common mistakes
- Phenomenon: Retrieval of a single declaration material takes over 30 seconds. Cause: `collectionIds` is not specified. The retrieval scope covers the full dataset, resulting in an excessively large volume of recalled data.
- Phenomenon: Only results from a single knowledge base are returned after multiple knowledge bases are bound. Cause: Multi-result merging logic is not configured, or multi-knowledge base weight allocation rules are not enabled.
- Phenomenon: A large number of declaration materials unrelated to the current game appear in retrieval results. Cause: The `similarity` threshold is set too low, leading to the recall of low-related results, which violates the strictness requirements of government documents.

## How to confirm the configuration is correct
- Submit a test query containing the game name and review keywords. Verify that retrieval time meets business expectations, and confirm that `collectionIds` limits the correct exclusive dataset.
- Test the scenario where two or more knowledge bases are bound. Confirm that relevant results from multiple knowledge bases are returned, and that sorting follows preset weight rules.
- Adjust the `similarity` parameter. Verify changes in the sorting priority of high-related results, and confirm that the `usingReRank` function works properly.
- Submit a query containing the game's short name. Verify that `datasetSearchUsingExtensionQuery` covers recall results for synonymous expressions.

The values provided are common starting points and should be measured against the reader's own samples.
