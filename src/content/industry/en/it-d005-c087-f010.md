# Technical Documentation and API Q&A for Game Planning and Numerical Design: Source Citation and Traceability

## What data looks like for this category
Daily documents for game planning and numerical design include gameplay design documents, numerical tables, version requirement sheets, and balance test records. Data comes from player behavior data, publicly available competitor materials, battle logs, and version feedback. Update frequency is usually weekly or per version iteration. Document structures typically include rule descriptions, parameter tables, and iteration records. Most fields have clear units, such as damage coefficient, growth level, and cooldown time. Numerical tables also separate exclusive parameters for different characters or gameplay modes.

## Constraints on source citation and traceability
Game planning and numerical design documents have high update frequency. Citation traceability must quickly locate the latest version of content, and avoid using outdated values or rules. Parameters in documents have clear units and segmented fields. Traceability must accurately match specific paragraphs or cells, and avoid using general document titles. Data sources are diverse, and credibility varies across sources. Traceability must label source types to facilitate verification. Numerical imbalance or rule errors directly impact gameplay experience and retention. The traceability link must ensure cited content fully matches answers, and avoid irrelevant information interfering with decision-making.

## Configuration settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the content length of a single gameplay design document or numerical table, and avoids truncating critical growth curve parameters |
| `detail` | Enabled | Displays specific fields and units of cited original text, matching the precision requirements of numerical design parameters |
| `responseData` | Includes source document path and update time | Links iteration records from version requirement sheets, facilitating traceability of revision basis |
| Single search limit | Top 3 results | Prevents excessive citations from disrupting numerical simulation logic |
| Maximum context | 4000–6000 token | Adapts to context requirements for long-form gameplay design documents |
| Question optimization model | Aligned with knowledge base embedding model | Matches semantic matching accuracy for game numerical rules |

## Three common configuration errors
- Symptom: Returned answers have no connection to cited sources. Cited entries are empty or randomly matched. Cause: Misalignment between the question optimization model and knowledge base embedding model, leading to semantic matching deviation.
- Symptom: Enabling `detail` does not display specific fields, only document titles. Cause: Original text field extraction configuration is not enabled, so critical parameters such as damage coefficients in numerical tables cannot be located.
- Symptom: Number of cited entries exceeds the expected limit, and irrelevant sources are included. Cause: The range of knowledge base entries recalled in a single search is not restricted, leading to redundant information interfering with matching logic.

## How to verify proper configuration
- Submit a query that includes numerical parameters, and check if cited documents in returned results correspond to the correct version of numerical tables or design documents.
- View system logs to confirm that cited sources carry identifiers for document path and update time.
- After configuring citation visibility, switch between different collaboration roles to verify that visibility settings take effect.
- Adjust the `quoteMaxToken` parameter, and test whether citations from long-form gameplay design documents are fully retained or reasonably truncated.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
