# Technical Documentation and Interface Q&A for Game Planning and Numerical Design: Document Parsing and Chunking

## What Data for This Category Looks Like
The daily documents used for game planning and numerical design include gameplay design plans, numerical tables, version requirement sheets, and balance test records. Data sources include player behavior data, publicly available competitor materials, battle logs, and version feedback. Documents are updated weekly or per version iteration. Most document structures include structured numerical tables, rule description text, and version change records. Fields and units cover game-specific parameters such as damage coefficients, level-up experience, and unit thresholds. Individual document lengths vary widely, ranging from single-page numerical tables to dozens of pages of version requirement sheets.

## Constraints Imposed by These Characteristics on Document Parsing and Chunking
The coexistence of structured tables and long rule text in category documents, combined with high update frequency, imposes multiple constraints on the document parsing and chunking workflow. First, chunking must not damage the integrity of table cells or the contextual connection of rule paragraphs. Otherwise, subsequent rule decomposition and numerical simulation work will be disrupted. Second, individual document lengths vary widely, from single-page numerical tables to dozens of pages of version requirement sheets. Chunking configurations must support flexible adjustments to match documents of different sizes. In addition, numerical parameters in documents directly relate to game gameplay balance. Insufficient chunking accuracy may lead to gameplay imbalance or version rework.

## How to Configure Settings
The following configurations are based on FastGPT v4.17.0, and are adapted to the document characteristics of game planning and numerical design:

| Configuration Item | Recommended Setting | Rationale |
| ---|---|--- |
| `chunkSize` | 800–1200 characters | Adapts to the common length of rule paragraphs and numerical table blocks in this category, avoiding splitting critical numerical values or complete rules |
| `chunkSplitter` | Paragraph + table boundary | Preserves the integrity of structured numerical table cells, avoiding splitting associated parameters across cells |
| `customPdfParse` | Enabled | Adapts to design doc PDFs commonly found in this category that contain embedded tables, formulas, and images, preserving document formatting and content structure |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 seconds | Matches the parsing time required for large version requirement sheets or multi-page numerical tables, avoiding parsing failures due to timeout |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports uploading batches of documents or large version packages, meeting the needs of bulk document processing for this category |
| `chunkSettingMode` | Manual configuration | Adapts to the wide variation in document structure across this category, allowing separate adjustment of chunking rules for different document types |

## Three Common Mistakes
- Symptom: After uploading a design document PDF with embedded images or tables, parsed results lack numerical text from images or table formatting. Cause: The `customPdfParse` configuration is not enabled, and the default parsing logic does not support extraction of embedded non-text elements.
- Symptom: After uploading an Excel-format numerical table, queries cannot associate damage coefficients and level-up experience parameters from the same table. Cause: `chunkSplitter` is not configured to split by table boundaries, and default character-based splitting breaks the cell association of the table.
- Symptom: After uploading a large version requirement sheet, a timeout error is returned shortly after the parsing task is triggered. Cause: `PARSE_FILE_TIMEOUT_SECONDS` is set too low, failing to match the parsing time required for large documents.

## How to Confirm Your Configuration is Correct
- Users upload a typical numerical table PDF, and check if the parsed result retains complete cell content and formatting.
- Users upload a long rule text, adjust the `chunkSize` configuration, and confirm that no complete rule paragraphs or critical numerical values are split during chunking.
- Users upload a large version requirement document, and verify that no timeout exception occurs during the parsing task.
- Users upload an Excel-format numerical table, and confirm that specified cell values and associated parameters can be accurately retrieved via queries.

The values given are common starting points and should be measured against the reader's own samples.
