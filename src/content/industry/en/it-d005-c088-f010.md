# Technical Documentation and API Q&A for Game Operation Activity Configuration: Source Citation and Traceability

## What the data for this category looks like
Core data for game operation activity configuration typically comes from operation backends, player segments, payment data, and activity logs. Daily produced documentation includes activity plans, reward configuration tables, launch checklists, and activity post-mortems. Data update frequency is mostly weekly or aligned with holiday cycles. Individual data entries include fields such as activity ID, reward value, effective time, and trigger conditions, with units including yuan, person-times, hours, and others. Each activity’s configuration data has a unique identifier, and must be distinguished using the activity ID.

## What constraints do these characteristics impose on the source citation and traceability link
Data for this category comes from multiple dispersed sources and has flexible update rhythms. The traceability link must bind specific activity IDs to distinguish configuration and logs for different activities. There are diverse document types, so citation verification must cover multiple data sources including activity plans and reward tables. Reward values and activity times are the core points of errors. The traceability link must ensure cited content exactly matches the original data. Errors directly affect player experience and business revenue, so traceability information must allow quick location of the original data’s storage location and update time.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average length of single paragraphs in activity configuration documents, to avoid truncating key traceability content such as reward values and activity times |
| Citation variable source scope | Operation backend datasets, activity logs, player segment data | Covers the core data sources for this category, ensuring completeness of cited content |
| `responseData` filtering rules | Only return entries matching the current activity ID | Avoid mixing in configuration data from other activities, narrowing the traceability scope |
| `detail` display level | Full field display | Retain key traceability fields such as activity ID, reward configuration, and effective time |
| Variable update frequency | Synchronized with activity configuration (weekly/holiday cycles) | Adapts to the data update rhythm of this category, preventing citation of outdated content |
| Dynamic knowledge base binding | Associate corresponding knowledge bases by activity ID | Matches periodically updated activity configurations, ensuring accuracy of citation sources |

## Three common misconfigurations
- The citation variable dropdown in the knowledge base search node is empty. This occurs because corresponding variables such as activity ID and operation backend data sources have not been configured in global variables, or the citation permission for variables has not been enabled.
- The citation ID returned by the large language model does not match the actual activity log identifier. This occurs because source verification for `responseData` has not been enabled, and the unique identifier field for activity logs has not been bound, resulting in generated fake citation IDs.
- Different activity configuration data cannot be distinguished in MongoDB logs. This occurs because no activity ID filtering rule has been configured for the `detail` level, causing log content from different activities to be mixed together.

## How to confirm the configuration is complete
- In FastGPT v4.17.0, initiate a query that includes an activity ID, and check if the returned results include clear identifiers such as activity ID and data source.
- Test the citation variables in the knowledge base search node, confirm that the configured operation backend and activity log variables can be selected normally.
- Adjust the `quoteMaxToken` parameter, verify that the answer fully displays the key fields of the reward configuration without truncation.
- Submit queries for different activities, confirm that the returned results only include configuration data for the corresponding activity, with no cross-activity mixing.
