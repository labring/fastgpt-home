# Technical Documentation and API Q&A for Game Operation Activity Configuration: Document Parsing and Chunking

## What This Type of Data Looks Like
Game operation activity configuration data typically originates from operation backends, player segmentation systems, payment data platforms, and activity log systems. Daily produced documents include activity plans, reward configuration tables, launch checklists, and activity review reports. Data update cycles are mostly weekly or temporary adjustments made before holiday events. Most document structures include structured configuration fields and unstructured explanatory text. Reward configuration tables contain fields such as item ID, issuance quantity, effective time, etc. Activity cycles are marked in days.

## Constraints for Document Parsing and Chunking
Structured configuration fields follow fixed formats. Chunking must avoid breaking field associations, and ensure reward values are bound to corresponding descriptions. Documents updated weekly or temporarily require fast parsing. Single-file parsing duration and resource usage must be controlled. Numeric fields in reward configuration tables must be extracted accurately. Chunking must not split values from their corresponding configuration items. Activity review documents contain time-series data. Chunking must retain timeline coherence. Documents may embed images and tables. Multi-format parsing support is required.

## Configuration Rules
This article is based on FastGPT v4.17.0 configuration rules.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the text length of activity plans and configuration tables, avoids splitting associated configuration items |
| `chunkSplitter` | Markdown chunker | Preserves the structure of tables and headings in documents, adapts to structured content in activity configuration tables |
| `customPdfParse` | Enabled | Adapts to embedded images and tables in activity plans, improves structured extraction accuracy |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Accommodates multi-page activity review reports and batch reward configuration tables |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to parsing duration of large activity documents, avoids timeout interruptions |
| `chunkSettingMode` | Manual mode | Customizes chunking rules for the special document structure of operation activity configurations |

## Three Common Misconfigurations
- Uploading a DOCX file containing images returns invalid image identifiers. The cause is that the `customPdfParse` configuration is not enabled, resulting in failure to correctly extract and associate image resources.
- Single-file parsing triggers a timeout error. The cause is that `PARSE_FILE_TIMEOUT_SECONDS` is not adjusted to a value suitable for large activity documents, or `chunkSize` is set too small, leading to an excessive number of chunks.
- Uploading an Excel reward configuration table results in missing parsed fields. The cause is that `chunkSplitter` adapted to structured tables is not used, leading to incorrect splitting of tables into independent text chunks.

## How to Confirm Successful Configuration
- Upload a single reward configuration table DOCX file. Check whether structured fields such as item ID and issuance quantity are fully extracted in the parsing result.
- Upload an activity plan PDF file containing embedded images. Confirm that the parsing result includes the associated explanatory text for the images.
- Upload an activity review report of around 100 MB. Check that the parsing process does not trigger a timeout error.
- Adjust `chunkSize` to 800 characters. Verify that the chunking result does not split associated rows of the same reward configuration.
