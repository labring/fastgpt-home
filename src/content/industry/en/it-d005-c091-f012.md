# Technical Documentation and Interface Q&A for Player Customer Service and Public Opinion Handling: Document Parsing and Chunking

## What the data for this category looks like
The daily data for this category includes four types of documents: player tickets, compensation requests, public opinion daily reports, and response scripts. Data sources cover customer service systems, community forums, app store reviews, and game logs. Data update cycles are mostly daily or real-time. Document structures include structured identification fields such as ticket numbers and player accounts, short-text feedback content, and long-text aggregated reports. There are no unified fixed units for fields. Some documents include hierarchical titles and segmented content, which support daily verification, rule judgment, and feedback classification needs.

## What constraints these characteristics impose on document parsing and chunking
Dispersed data sources and real-time updates require the document parsing link to support high-concurrency and low-latency processing, to avoid slowing real-time ticket response workflows. Daily documents include short-text player feedback, long-text public opinion daily reports, and structured response scripts. Chunking strategies must adapt to different text lengths and hierarchical structures to avoid context breaks or matching deviations. Frequently updated ticket data requires the parsing link to avoid excessive timeouts, to ensure data can be synchronized to the knowledge base in a timely manner. Some documents include identification fields such as player accounts. Context associations must be retained during chunking to ensure accurate matching of associated content during retrieval.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the text length of player tickets and public opinion daily reports, avoids overly fragmented chunks causing context breaks, or overly long chunks affecting matching accuracy |
| `chunkSplitter` | Split by paragraph + title | Adapts to public opinion daily reports and response script documents that include hierarchical titles, retains content hierarchical associations, and improves retrieval accuracy |
| `customPdfParse` | Enable structured parsing | For PDF-format public opinion daily report documents, extracts main text and chapter titles, avoids losing structural information with plain text parsing |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Meets the upload requirements for single long-text public opinion daily reports or batched packaged ticket files, avoids parsing failures for large files |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 seconds | Matches the processing rhythm of real-time updated ticket data, avoids interruptions from long document parsing timeouts |
| `chunkSettingMode` | Manual configuration | Adjusts chunking parameters for different document types including tickets, daily reports, and scripts to adapt to the diverse document structures within this category |

## Three Common Configuration Mistakes
- Phenomenon: After uploading a docx-format document, RAG retrieval results do not include chapter titles. Cause: The structured parsing configuration of `customPdfParse` is not enabled, only plain text content is extracted, and the document hierarchical structure is lost.
- Phenomenon: When uploading files in a server environment, the document parsing node returns a 404 error. Cause: The server storage path configuration does not match the local environment, and the parsing node cannot read the actual storage address of the uploaded file.
- Phenomenon: When deploying a specified large model using Vllm 0.10, preset fields cannot be extracted from PDF parsing results. Cause: Different large models have differences in adaptation to parsing result field formats, and the parsing output rules are not adjusted for the currently deployed model.

## How to Verify Correct Configuration
- Upload a single docx-format public opinion daily report document, check whether the parsing results of FastGPT v4.17.0 include chapter titles and main text content.
- Upload a batched packaged ticket file within 100 MB, confirm that no timeout errors occur during the upload and parsing stages.
- After setting `PARSE_FILE_TIMEOUT_SECONDS` to 300 seconds, upload a long-text public opinion daily report, verify that no interruption prompts appear during parsing.
- After adjusting the `chunkSize` parameter, check whether the text length of the chunked results falls within the preset range.
