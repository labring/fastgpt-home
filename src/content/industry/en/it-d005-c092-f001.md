# Technical Documentation and API Q&A for On-Site Deployment: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
On-site deployment data originates from customer on-premises data center environments, equipment lists, software packages, and network topologies. Updates follow a per-order or per-phase schedule. Daily documentation covers deployment manuals, installation records, configuration checklists, and on-site sign-in logs. Data fields include deployment node IP addresses, software versions, configuration parameters, network connectivity status, and additional metrics. Units include units, instances, seconds, characters, and others. All data is created and updated incrementally during on-site deployment. Full data is only finalized after the corresponding implementation phase is complete.

## Constraints for HTTP Interfaces and External Systems
On-site deployment data relies on customer on-premises data center environments. HTTP interfaces must adapt to internal networks. Forcing public network addresses is prohibited. Data updates adjust per order or phase. Interface configurations must support parameter modifications per implementation order. Daily documentation uses structured deployment manuals and configuration checklists. Interface return formats must align with documentation fields to support on-site troubleshooting. Data generation follows a tight timeline. Interfaces must include clear error return and timeout mechanisms to avoid delaying on-site project timelines. On-site deployment errors directly impact system availability. Interface authentication must follow strict specifications to prevent unauthorized access from disrupting customer business operations.

## Configuration Guidelines
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `AIPROXY_API_TOKEN` | Non-empty admin token matching the AI Proxy server configuration | Aligns with AI Proxy dependency requirements for FastGPT v4.17.0 and later. Required environment variable for the App/Admin server |
| `variables` | Value range of 10–30 entries | Matches configuration checklist fields for on-site deployment. Adapts to parameter transfer volume for single-batch implementation tasks |
| `responseData` | Only return structured results of 200–500 characters | Fits the document format of on-site deployment manuals. Enables on-site engineers to quickly read and troubleshoot |
| `AIPROXY_API_ENDPOINT` | `http://customer internal IP:3000` | Root address for the AI Proxy service. Aligns with AI Proxy dependency requirements for FastGPT v4.17.0 and later. Required environment variable for the App/Admin server. Do not append `/v1` or model service paths |
| Workflow API timeout | 600 seconds | Covers average time for on-site deployment environment checks and software installation. Prevents mid-process timeout interruptions |

## Three Common Implementation Mistakes
- Symptom: Workflow API calls return a 401 Unauthorized error. Troubleshooting steps: Check if authentication parameters match the corresponding interface specifications. Confirm that credentials required for the target interface are not misused. Verify that the App/Admin server has correctly configured the non-empty `AIPROXY_API_TOKEN` environment variable.
- Symptom: API calls time out and return a 504 status code. Cause: Timeout settings are not adjusted to match actual on-site deployment durations. Short setting values fail to cover the full implementation workflow.
- Symptom: After uploading files via the API, the agent backend does not respond. Cause: An internally accessible file storage address is not configured. External systems cannot access uploaded files.

## How to Verify Successful Configuration
- Check the App/Admin service startup logs. Confirm there are no validation failure prompts for missing `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN`.
- Initiate a test API call. Verify that returned result fields match the on-site deployment configuration checklist.
- Simulate the customer's on-site network environment. Test interface connectivity and response duration to confirm they meet expectations.
- Review workflow execution logs. Confirm that interface calls complete authentication and parameter transfer normally, with no abnormal errors.
