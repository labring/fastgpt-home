# Technical Documentation and API Q&A for User Growth and Retention Operations: Source Citation and Traceability

## What Data Looks Like for This Category
Typical roles for this category include growth operations, user operations, and data analysts. Daily documents produced include growth experiment plans, user segmentation tables, outreach copy, and retention analysis reports. Primary data sources are user behavior logs, push systems, experiment platforms, and CRM systems. Most updates occur on a daily or weekly basis. Document fields typically include user identifiers, outreach channels, experiment groups, and retention metrics. There is no unified mandatory format, so matching the original data structure of each system is required.

## Constraints on Source Citation and Traceability
Data sources for this category are scattered, and update cycles are fixed. This requires the traceability link to associate original data identifiers across multiple systems, ensuring attribution results are traceable. There is no unified document format, so flexible matching of field structures across different documents must be supported to avoid information loss from forced conversion. Differences in update frequencies require traceability configurations to adapt to daily or weekly data source synchronization rhythms, ensuring the timeliness of cited content. Errors can lead to user dissatisfaction, reduced retention, or wasted budget, so strict accuracy and completeness of cited content must be maintained.

## How to Configure Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the typical content length of growth experiment plans and retention analysis reports, avoiding truncation of core attribution fields |
| `responseData` | Enable full return | Associates original data identifiers from user behavior logs and CRM systems, supporting cross-data-source traceability |
| `detail` | Enable detailed mode | Displays original content of outreach copy and user segmentation tables, enabling operations personnel to verify result accuracy |
| Source citation display location | Separate block at the end of the answer | Aligns with the reading habits of operations personnel during daily reviews, without interfering with the main analysis logic |
| Traceability data update matching | Synchronize with data sources (daily/weekly) | Matches the update rhythm of category data, ensuring the timeliness of cited content |

## Three Common Configuration Mistakes
- The thought process cited in the answer has messy formatting and no clear source identifiers. Cause: The `detail` parameter is not configured, only simplified Q&A results are returned, and structured markers for original citations are not retained.
- Garbled characters appear in returned content, and original CSV-formatted data displays abnormally. Cause: The `responseData` configuration does not adapt to cross-system character encoding rules, and encoding differences across data sources are not handled.
- When calling the `/api/core/dataset/colle` related interface, the returned cited data fields are empty. Cause: The list of required cited fields is not specified in the `responseData` configuration, causing the interface to not return original data identifiers required for traceability.

## How to Verify Successful Configuration
- Submit a growth experiment plan as a test document, initiate relevant Q&A, and check whether a separate source citation display block appears at the end of the answer.
- Upload CSV-formatted user behavior logs containing Chinese and special characters, initiate relevant Q&A, and check that the returned content has no garbled characters.
- Call the corresponding interface, view the `responseData` field, and confirm that it includes original data identifiers such as user identifiers and experiment groups required for traceability.
- Adjust the value of `quoteMaxToken`, test citations of long-text outreach copy or retention analysis reports, and check that content is fully displayed without truncation.
