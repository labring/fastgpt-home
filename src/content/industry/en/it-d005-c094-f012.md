# Technical Documentation and API Q&A for User Acceptance Testing Support: Document Parsing and Chunking

## What the data for this category looks like
Core data for this category comes from requirement specification documents, test environment outputs, customer business samples, and defect management systems. Update frequency follows each phase or version release. Commonly processed documents include UAT test cases, acceptance issue tickets, acceptance reports, and signature confirmation forms.
UAT test cases contain structured fields such as test steps, expected results, and actual results. Acceptance issue tickets include fields such as defect ID, reproduction steps, and severity level. Signature confirmation forms contain unstructured signature dates and business confirmation information.

## Constraints imposed on document parsing and chunking
Differences in document formats across multiple sources require the parsing process to support multiple formats including PDF, images, and plain text. The per-phase or per-version update feature requires chunking rules to be flexibly adjusted to adapt to document structures across different versions.
Structured UAT test cases and acceptance issue tickets require chunking to retain field relevance, to avoid splitting that breaks business logic. Unstructured signature confirmation forms require the parsing process to support text extraction from scanned documents.
Additionally, the time-sensitive nature of the acceptance process requires that parsing and chunking workflows do not experience timeouts or errors. Failures here will directly impact acceptance progress, and may even trigger scope disputes.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0, as detailed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the overall length of a single test step and expected result in UAT test cases, avoiding splitting that breaks business logic relevance |
| `chunkSplitter` | Split by paragraph | Matches the paragraph segmentation rules for defect reproduction steps in acceptance issue tickets, enabling accurate recall of context for corresponding defects |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Covers the full parsing time for large acceptance reports, preventing document parsing failures due to timeouts |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapts to batch-uploaded combined packages of multiple acceptance reports, meeting document submission requirements for phase-based acceptance |
| `customPdfParse` | Enabled | Adapts to unstructured PDF formats of scanned signature confirmation forms, improving text extraction accuracy |
| `chunkSettingMode` | Manual configuration | Flexibly adjust chunking parameters for different types of UAT documents, balancing parsing performance for both structured and unstructured documents |

## Three Common Misconfigurations
- Symptom: The file parsing API returns a `413 Request Entity Too Large` error. Cause: The `UPLOAD_FILE_MAX_SIZE` configuration was not adjusted, and large acceptance reports failed to upload due to exceeding the default limit.
- Symptom: Chunked parsed UAT test cases lose test step sequence numbers. Cause: The `chunkSplitter` was set to split by character instead of by paragraph, causing sequence numbers to separate from their corresponding steps and preventing complete restoration of test case logic.
- Symptom: Workflows calling the image parsing API return empty results. Cause: VLM parsing capability was not enabled in the API configuration, causing uploaded test environment screenshots to fail to parse correctly.

## How to Verify Proper Configuration
- Upload a single standard UAT test case PDF, and check parsed chunks for complete retention of test steps and expected results without broken field splits.
- Call the file upload API, upload an acceptance report combined package larger than the default size, and confirm the API returns normally without timeout or size limit errors.
- Enable `customPdfParse`, upload a scanned signature confirmation form, and confirm the parsed text can correctly retrieve signature date and confirmer information.
- Adjust `chunkSize` to the 800–1200 character range, compare the parsed chunk results, and confirm they meet the structural splitting requirements of the currently processed documents.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
