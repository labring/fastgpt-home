# Technical Documentation and Interface Q&A for Monitoring Alert Configuration: Document Parsing and Chunking

## What the data for this category looks like
The main data for this category comes from daily work documents of operations engineers and SRE teams, including monitoring metric lists, alert rule configurations, on-duty manuals, alert change records, and more. Data sources include export files from monitoring tools such as Prometheus and Zabbix, cloud monitoring platform logs, application operation logs, and CMDB configuration data. Documents are updated daily or whenever an alert rule is modified. A single document includes fields such as metric name, threshold range, alert level, notification target, and corresponding units like percentage, millisecond, and number of alert triggers.

## What constraints do these characteristics impose on the "document parsing and chunking" link
Since data sources include export files and log texts in multiple formats, document parsing must adapt to different encodings and structures. Alert rules and metric lists have strongly associated field combinations. During chunking, the contextual association between metrics and their corresponding thresholds, as well as notification logic, must be retained to avoid splitting that breaks business logic. Frequently updated documents require the parsing process to quickly adapt to structural changes. Overly long CMDB export files may exceed standard parsing durations, so a reasonable timeout threshold must be set. Scanned alert manuals must also support text extraction to prevent parsing failures caused by format issues.

## How to set the configurations
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Matches the length of single entries in alert rules and metric lists, avoids splitting associated fields |
| `chunkSplitter` | Semantic chunking | Adapts to the binding relationship between metrics and thresholds, rules and trigger conditions in alert documents |
| `customPdfParse` | Enabled | Supports text extraction for scanned alert manuals and CMDB export PDFs with tables |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts parsing duration for large monitoring export files of 10–20 MB |
| `chunkSettingMode` | Manual mode | Allows adjustment of chunking logic for specific structures of alert documents, retaining business field associations |
| `UPLOAD_FILE_MAX_SIZE` | 20 MB | Limits the size of a single imported file to avoid exceeding server parsing capabilities |

## Three common mistakes
- No parsing result after importing a Java interface document with a modified file extension. The cause is that `customPdfParse` is not enabled, and parsing rules for non-standard document formats are not adapted.
- Some uploaded PDF files display empty content. The cause is that `customPdfParse` is not enabled, or the uploaded PDF is a pure scanned version with no embedded text.
- Parsing tasks time out and fail. The cause is that `PARSE_FILE_TIMEOUT_SECONDS` is set too small, or the uploaded file exceeds the `UPLOAD_FILE_MAX_SIZE` limit.

## How to confirm the configuration is set correctly
- Upload a test alert rule PDF document, check the parsed chunking results, and confirm that a single chunk contains a complete combination of metrics and their corresponding thresholds.
- Modify `chunkSize` to 1000 characters, upload a monitoring metric list document, and verify that chunked paragraphs do not split associated metric names and unit fields.
- Set `PARSE_FILE_TIMEOUT_SECONDS` to 600 seconds, upload a 15 MB CMDB export file, and confirm that the parsing task completes normally with no timeout errors.
- Call the FastGPT parsing interface via code to obtain chunked text data, verify that the data format conforms to the field structure of alert documents and can be used to generate configuration reports.
