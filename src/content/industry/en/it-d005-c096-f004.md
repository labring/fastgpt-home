# Technical Documentation and Interface Q&A for Community Report Handling: Vector Models and Indexes

## What This Category's Data Looks Like
Data for this category originates from community report systems, pending review content details, user historical report records, and official review rules. Daily processed documents include report tickets, disposal records, appeal documents, and user notification templates. Data fields include report identifiers, content association IDs, report types, review statuses, and other related items. Data updates follow a daily or real-time push schedule. Individual data entries have a small size, but single-batch processing volume fluctuates based on community activity. This requires adaptation to high-frequency index update demands.

## Constraints Imposed on Vector Models and Indexes by These Characteristics
Data for community report handling comes from multiple dispersed sources. Connect to multiple system interfaces to pull report tickets, pending review content details, user historical records, and review rules. Vector indexes must support unified access across multiple data sources.
Data updates occur daily or in real time. Accommodate high-frequency index synchronization demands to avoid resource consumption from full index rebuilds.
Individual data entries have a small size, but single-batch processing volume fluctuates significantly. Control index shard size to improve retrieval efficiency.
Report content and review rules involve sensitive information. Vector storage must meet privacy encryption requirements.
Semantic characteristics vary widely across different report types. Judgment of report validity relies on semantic matching results. Split indexes by category to optimize recall accuracy and reduce invalid retrieval time.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Matches the valid single-paragraph information length of report tickets and content details, preventing breakage of report reasons and evidence within chunks |
| Overlap Length | 100–200 characters | Preserves contextual association between chunks, preventing split loss of cross-chunk report-related content |
| `maxToken` | 4000–6000 token | Adapts to multi-field concatenated context for report processing, avoiding truncation of critical review rules and appeal content |
| Similarity Threshold | 0.75–0.85 | Balances false positives and false negatives, meeting the semantic matching accuracy requirements for report content |
| Single Search Limit | Top 10 entries | Controls the number of returned historical reports and review records, avoiding context overload that impacts judgment efficiency |
| `defaultToken` | Calibrated via actual testing | Adapts to input limits of private deployment reranking models, compatible with token carrying capacity across different hardware environments |

## Three Common Misconfigurations
- Phenomenon: A "reranking model parameter incompatible" error is returned when calling an interface, with a status code of 400. Cause: The adapted value of `defaultToken` is not specified in the configuration, or the length limit of `maxToken` is not matched, causing the private deployment reranking model to fail to receive input data normally.
- Phenomenon: The returned historical report records have extremely low relevance to the current pending review content, and the number of results does not meet expectations. Cause: The similarity threshold is set too high or too low, failing to adapt to semantic characteristic differences across different report types.
- Phenomenon: Index update delay exceeds 1 hour, and the latest review rules cannot be synchronized in real time. Cause: Incremental index mode is not enabled, and a full index update process is still used, resulting in excessive resource occupation that cannot meet real-time update demands.

## How to Confirm Configuration Is Successful
- View the vector index management page in the FastGPT v4.17.0 backend, confirming that the chunk length and overlap length settings match the configured values.
- Enter keywords from a test report content, retrieve historical report records, and verify that the number and relevance of returned results meet the threshold requirements.
- Submit a temporary review rule update, check whether the index update log shows that incremental synchronization is complete.
- Call the test interface for the private deployment reranking model, confirming that it can normally receive vector recall results and complete sorting.
