# Technical Documentation and Interface Q&A for Community Report Handling: Citation Sources and Traceability

## What the data for this category looks like
Data sources for this category include report systems, content details, user historical records, and audit rules. Update frequency is daily or real-time. Documents produced daily include report tickets, processing records, appeal forms, and user notification templates. Report tickets contain fields such as report ID, associated content ID, report type, processing status, and disposal result. Appeal forms contain fields such as appeal reason and supporting material ID. All document fields are tightly bound to the single report processing workflow. Unlike content audit rule operations, this category processes specific user-submitted report content on a per-ticket basis.

## What constraints these characteristics impose on the "citation sources and traceability" workflow
Data sources are scattered and bound to individual report workflows. This requires the traceability workflow to accurately associate with the specific content and audit rules of the corresponding report, to avoid cross-ticket data confusion. Traceability failure may lead to user complaints, retention of non-compliant content, or escalation of community conflicts. Real-time update frequency requires traceability to support real-time pulling of the latest user historical records and audit rules, to avoid using expired data that impacts judgment. The tight binding of document structures requires citation sources to match the unique ID of the report ticket, ensuring every traceability result can be traced back to the original report and processing link. At the same time, field differences across multiple document types require traceability configurations to adapt to the field formats of different documents, to avoid parsing errors that cause traceability failure.

## How to configure the settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average character length of report tickets and associated content, ensuring complete citation of core supporting information |
| `responseData` | Return only report ID, associated content URL, audit rule version | Aligns with the requirement to bind to individual report workflows for this category, avoiding interference from redundant data |
| `detail` | Enabled | Used to pull complete supporting materials from report processing records, meeting the detail requirements of traceability |
| Single recall limit | Top 3 entries | Adapts to the volume of data associated with a single ticket for community report handling, avoiding mixing of irrelevant information |
| Context window | Historical data within 600 seconds | Matches the real-time update rhythm of report workflows, ensuring traceability data is synchronized with the current processing link |

## Three common configuration errors
- Phenomenon: The returned citation ID does not match the actual submitted report ticket, and forged citation IDs appear. Cause: Traceability is not bound to the unique ID of the report ticket, and general-purpose data is called directly, leading to association errors.
- Phenomenon: The text "Citation marker: [1]" appears in the output content. Cause: Automatic rendering of citation markers is not disabled, or markers in user notification templates are not filtered.
- Phenomenon: Log data from different sources cannot be distinguished. Cause: No association rule for content ID and source field is added in the traceability configuration, resulting in log data that cannot be categorized by report source.

## How to confirm the configuration is valid
- Submit a test report ticket to trigger the interface Q&A process, and check if the returned citation sources match the associated content and processing records of this ticket.
- View the `responseData` field returned by the interface, confirm that only necessary information such as report ID, associated content URL, and audit rule version is included, with no redundant data.
- Simulate real-time updates to audit rules, and check if the traceability workflow can pull the latest rule content.
- Verify that the "Citation marker" text does not appear in the output content, confirming that the filtering configuration is active.
