# Technical Documentation and API Q&A for Community Report Handling: Knowledge Base Retrieval and Recall

## What the data for this category looks like
The data for this category primarily comes from community report systems, content details pages awaiting review, user historical report records, and official review rules. Daily processing documents include report work orders, disposal progress records, user appeal forms, and standardized notification templates. Core data revolves around the full workflow of individual report events. Data update frequency is mostly real-time or daily batch synchronization, with updates only for associated content triggered by business events. There are no fixed batch update cycle restrictions.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
Since data revolves around individual report events, retrieval must accurately match content associated with the report, historical disposal records, and review rules to avoid retrieving irrelevant community content. Real-time or daily updated data requires the knowledge base to support incremental synchronization and incremental indexing, preventing expired rules or unsynchronized report records from appearing. The field characteristics of structured documents such as work orders and appeal forms require retrieval to filter recall results by field dimensions, ensuring returned content is strongly relevant to the current report scenario. Additionally, the timeliness requirements of report processing dictate that retrieval response times must be controlled within a reasonable range to avoid delaying subsequent disposal progress.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Filter low-relevance review rules and historical work orders to avoid invalid recalls |
| `limit` | Top 8 entries | Associated information for individual reports is limited; excessive recalls will increase the burden of context processing |
| `usingReRank` | Enabled | Perform secondary sorting on initial recall results by report scenario relevance to improve accurate matching |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expand report descriptions into violation type keywords to cover more associated rules |
| `collectionIds` | Specify collection IDs for the report rule base and historical work order base | Limit retrieval scope, exclude irrelevant community content, and improve retrieval efficiency |

## Three common mistakes
- Phenomenon: When uploading files larger than 10MB, background logs show that some chunks fail vectorization, and normal status is not restored after repeatedly clicking the upload retry button. Cause: No chunking strategy adapted for large files is configured, or the batch upload task does not enable the breakpoint resume mechanism, resulting in incomplete transmission of some chunks and abnormal vectorization processes.
- Phenomenon: The number of knowledge base retrieval return results does not match the configured `limit` parameter, with missing or redundant results. Cause: The `collectionIds` scope is not correctly limited, or the `similarity` threshold is set unreasonably, leading to an unexpected retrieval scope.
- Phenomenon: After server restart, batch-imported knowledge bases do not complete indexing automatically and remain stuck, requiring manual triggering of indexing operations. Cause: The automatic index recovery configuration for the knowledge base is not enabled, or batch import tasks are not marked as restartable and resumable, resulting in lost task status after restart.

## How to confirm configurations are correct
- Upload a single report work order document, check the relevance of returned results after retrieval to confirm whether they meet the business requirements of the current report scenario.
- View the knowledge base retrieval logs, confirm that the number of returned results matches the configured `limit` parameter, and that results filtered by the `similarity` threshold meet expectations.
- Simulate a server restart scenario, confirm that batch-imported knowledge bases complete indexing automatically without requiring manual triggering of operations.
- Upload a document containing images, confirm that text content associated with images can be retrieved normally without missing or abnormal results.

The values provided are common starting points and should be measured against the reader's own samples.
