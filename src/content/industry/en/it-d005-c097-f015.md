# Technical Documentation and API Q&A for Community Events and Developer Relations: Knowledge Base Retrieval and Recall

## What This Category of Data Looks Like
This category of data primarily comes from community forums, event registration systems, social media updates, and project roadmaps. The update cadence is monthly or aligned with the timeline of individual events. Daily produced documents include event planning proposals, on-site speeches, participant lists, and event post-mortem records. Common fields include event theme, holding time, agenda content, feedback opinions, and similar details. There is no fixed unified format, with adjustments made flexibly based on event type.

## What Constraints Do These Characteristics Impose on Knowledge Base Retrieval and Recall
The characteristics of this category of data impose multiple constraints on the retrieval and recall process. Dispersed multi-channel data sources with format differences increase the difficulty of unified text processing and vectorization. The non-fixed update cadence requires support for incremental updates to accommodate temporarily generated event documents. Diverse document fields require differentiated retrieval adaptation logic for structured and unstructured content. Most event post-mortem documents are produced after the event, so support for quick recall of associated content by event theme or time dimension is needed.

## How to Configure Settings
These configurations apply to FastGPT v4.17.0 and later versions.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.7–0.85` | Matches semantic similarity for event documents, filters low-relevance non-event content |
| `limit` | `Top 3–5 entries` | The number of recalled event documents per request should not be too large, to avoid overloading the context and affecting answer coherence |
| `searchMode` | `embedding` | Most event documents are unstructured text; vector retrieval mode is prioritized to improve matching accuracy |
| `usingReRank` | `Enabled` | Reranks recall results to improve the ranking priority of content related to event themes |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Automatically expands retrieval terms related to events, covering event agendas and participant-related content expressed in different ways |
| `collectionIds` | `Specify event-specific knowledge base collections` | Isolates event-related data from other community content to avoid irrelevant recall interfering with core results |

## Three Common Misconfigurations
- Troubleshooting item: Returns "AI Proxy configuration missing" error during conversation. Troubleshooting steps: Check if `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service) and `AIPROXY_API_TOKEN` (AI Proxy administrator token) on the App/Admin server are correctly configured and not empty, and confirm if there is a startup verification failure.
- Troubleshooting item: AI responses only return the first part of knowledge base content, omitting subsequent event-related entries. Troubleshooting steps: Check if the `limit` parameter is set too low, or the `similarity` threshold is set too high.
- Troubleshooting item: Added third-party model channels do not appear in the knowledge base configuration interface. Troubleshooting steps: Confirm if the configuration logic for model channel settings and AI Proxy environment variables is confused, and if vendor credentials were correctly configured via the model management page.

## How to Confirm Configurations Are Correct
- Check the environment variables on the App/Admin server, confirm that `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service) and `AIPROXY_API_TOKEN` (AI Proxy administrator token) are correctly configured and not empty, meeting the deployment requirements of FastGPT v4.17.0 and later versions.
- Initiate a test retrieval, enter event-related keywords, and verify whether the number and relevance of recall results meet expectations.
- View the source information of retrieval results, confirm that they are correctly associated with the corresponding event documents, meeting the requirements for displaying knowledge base citation sources.
- Simulate incremental updates of event documents, verify whether the retrieval function can properly load newly added event content.

The values provided are common starting points and should be measured against the reader's own samples.
