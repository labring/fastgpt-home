# Technical Documentation and API Q&A for Cybersecurity Level Protection Assessment Consulting: Document Parsing and Chunking

## What this category of data looks like
Data for this category comes from daily work outputs of cybersecurity level protection assessment institutions, security consulting firms, and enterprise security leaders. The core daily documents include four types: level determination reports, gap analysis reports, rectification plans, and assessment reports. Data sources include content exported from assessment tools, on-site interview records, system inventories, and security device logs. Data is updated on a per-assessment-project cycle, with one update cycle completed after each project is finished. Most document structures include fixed fields such as standardized control item entries, rectification requirements, and evidence lists. There are no unified fixed units of measurement. Fields are adjusted slightly based on the industry and scale of the assessment project.

## What constraints do these characteristics impose on the "document parsing and chunking" stage
Because daily documents include standardized control item entries and unstructured rectification evidence, the chunking stage must balance the integrity of structured fields and the coherence of unstructured content. Data sources include structured tables exported from tools and free text generated from interviews. The parsing stage must support input content in different formats. The annual update per project feature requires that chunking configurations can flexibly adapt to the document volume of a single project, avoiding chunk redundancy or missing content caused by fixed configurations. Control item gap verification and rectification evidence collection are core time-consuming links. Chunking must ensure that associated content for each control item is fully collected, preventing incorrect splitting of content across control items, which would harm subsequent question-and-answer matching and verification efficiency.

## How to configure settings
This document applies to FastGPT v4.17.0 configuration scenarios.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Aligns with the average length of control item entries and rectification requirements in level protection reports, avoiding splitting the full description of a single control item |
| `chunkSplitter` | Custom delimiter + paragraph line breaks | Matches the inherent format of level protection reports segmented by control items, preserving document structure integrity |
| `customPdfParse` | Enabled | Adapts to embedded tables and security device log screenshots in assessment reports, improving parsing accuracy for structured content |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports the need to upload multiple packaged assessment reports for a single project, preventing large file upload failures |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time required for large rectification plan documents, preventing mid-parsing timeouts for long documents |
| `chunkSettingMode` | Manual configuration | Allows adjustment of chunking parameters for different types of level protection documents such as level determination reports and rectification plans to adapt to project differences |

## Three common misconfigurations
- Uploading a 3 MB PDF assessment report triggers a parsing error. This occurs because the default `UPLOAD_FILE_MAX_SIZE` configuration was not adjusted, or the parsing timeout threshold was not adapted to the parsing time required for large PDF documents.
- After configuring a custom delimiter, chunking results still show paragraph merging or splitting errors. This occurs because the `chunkSize` value does not match the actual paragraph length of the document, and parameters were not adjusted in conjunction with the chunking logic of `chunkSplitter`.
- Parsing fails when attempting to import an Excel-format system inventory file via the API. This occurs because the corresponding format parsing plugin was not enabled, or `trainingType` was not configured to adapt to parsing rules for non-PDF documents.
- An error occurs when processing PDF documents after deploying Marker. This occurs because the associated environment variables for `customPdfParse` were not configured correctly, or the parsing timeout period did not cover Marker's preprocessing time.

## How to confirm successful configuration
- Upload a single typical level protection document, review the parsed chunking results, and confirm that content for each control item is not split across chunks.
- Upload a test file of a preset size, verify that the upload and parsing processes do not trigger errors, and confirm that the configuration has taken effect.
- For different types of level protection documents such as level determination reports and rectification plans, adjust chunking parameters separately and verify parsing results.
- Review parsing logs to confirm that configuration items such as `customPdfParse` and `chunkSize` were loaded correctly, with no parameter conflicts.

The values provided here are common starting points, and should be evaluated against local sample documents.
