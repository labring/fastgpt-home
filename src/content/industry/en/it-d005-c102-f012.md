# Technical Documentation and Interface Q&A for Defect Management and Regression Testing: Document Parsing and Chunking

## What Data for This Category Looks Like
Data for the defect management and regression testing category originates from defect management systems, test reports, code commit records, and user feedback. Update frequency is daily or per release cycle. Daily produced documents include defect tickets, regression test checklists, repair verification records, and defect statistical reports. Defect tickets contain fields such as defect ID, reproduction steps, priority, and associated version number. Regression checklists mark test case IDs, associated requirements items, and verification results. Statistical reports count defect distribution and repair rates by version and module. The data structure follows the functional defect lifecycle, with most fields tied to specific versions and test nodes.

## Constraints on Document Parsing and Chunking
Since data revolves around the defect lifecycle and is tied to version numbers, parsing must retain full context of version-associated fields. Chunking that breaks the binding between versions and defects will prevent Q&A from associating defects with repair information for their corresponding versions. High update frequency requires adapting to high-frequency incremental processing during batch document parsing, to avoid re-parsing already processed historical data and reduce system load. Diverse document types range from structured defect tickets to semi-structured regression checklists and statistical reports. This requires adapting field extraction logic for different formats, to avoid generic chunking breaking the association of structured fields. Defect reproduction steps and verification records contain detailed operation details. Chunking must retain step continuity, otherwise subsequent Q&A will fail to associate reproduction logic and cannot support defect reproduction queries.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Core fields and step descriptions for defect tickets and regression checklists are mostly within 1000 characters, matching the completeness of single-block content and avoiding cutting off reproduction steps or test case associations |
| `chunkSplitter` | Split by semantic paragraphs | Adapts to the segmentation logic of defect ticket reproduction steps and verification records, retaining contextual association between operations and results |
| `customPdfParse` | Enable structured extraction mode | Defect statistical reports are mostly in PDF format; enabling this extracts table fields and version-bound information, avoiding loss of structured data from plain text parsing |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | When batch processing test reports and defect tickets within a release cycle, prevents parsing timeouts due to large numbers of documents |
| `chunkSettingMode` | Manual configuration mode | Adjust chunking parameters for different document types (defect tickets, regression checklists) to adapt to structural differences across multiple document types in this category |

## Three Common Configuration Mistakes
- Parsing Playwright-related interface documents returns parsing failure. Cause: Custom parsing rules for `customPdfParse` were not configured for MCP format documents, leading to failure to correctly recognize non-standard protocol formats.
- Defect tickets containing image links in the knowledge base cannot have their image content associated during Q&A. Cause: Only the text parsing module was enabled, and image parsing binding was not configured, resulting in image links not being included in the chunked context.
- Parsing timeouts occur when batch processing regression checklists within a release cycle. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` setting is lower than the average processing duration for batch documents, leading to interruption of parsing for some large documents.

## How to Verify Correct Configuration
- Upload a typical defect ticket PDF, verify that the parsed text retains complete context of defect ID, reproduction steps, and associated version number.
- Execute a Q&A test for a defect ticket containing image links, confirm that the system returns associated content corresponding to the image links.
- Batch upload 5 regression checklists from the same version, check that parsing tasks complete within the duration specified by `PARSE_FILE_TIMEOUT_SECONDS`.
- Access the knowledge base configuration page of FastGPT v4.17.0, confirm that `chunkSettingMode` is set to manual configuration mode, and `chunkSize` is configured as 800–1200 characters.
