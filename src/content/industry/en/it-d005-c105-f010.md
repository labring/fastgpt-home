# Technical Documentation and API Q&A for License Compliance and Copyright Notices: Source Citation and Traceability

## What the data for this category looks like
Data sources for this category include code repositories, dependency manifests, license texts, and contribution records. Maintained documentation includes LICENSE files, NOTICE files, dependency license lists, and copyright notices. Data updates trigger with each version release or each dependency change. Document structures include core fields such as license type, copyright attribution statements, and dependency authorization terms. Content exists only in structured or plain text format, with no fixed quantitative units. This page applies to the configuration logic of FastGPT v4.17.0.

## What constraints do these characteristics impose on the "source citation and traceability" workflow?
Data sources are scattered and associated with multiple file types. Traceability requires linking multi-source information such as code repository commit records and dependency package metadata. This avoids authorization bias from single-source data. Update frequency fluctuates with project versions and dependency changes. Traceability results must sync with the latest data of the current project version. This prevents referencing expired license texts. Documents exist in plain text or structured list format, with no unified field format. Matching must adapt to text structures from different sources. Traceability must also cover multiple file types such as LICENSE and NOTICE. This ensures complete correspondence between copyright notices and authorization terms.

## How to Configure Settings
The following configurations are based on the interface and parameter logic of FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | `1200–1800 token` | Covers complete license texts and dependency authorization content, avoiding truncation of critical compliance information |
| `responseData` | Includes source file path, update time, and copyright notice snippets | Meets full compliance information verification requirements during traceability |
| `detail` | Enabled | Returns detailed license types and associated contribution records, facilitating copyright attribution confirmation |
| Single traceability return limit | Top 5 entries | Controls model input context length, preventing exceeding processing thresholds |
| Traceability data version verification | Match current project version | Ensures traceability results align with the latest dependency and license versions of the current project |

## Three Common Misconfigurations
- Phenomenon: The license compliance result returned by the conversation API does not include an entry or path for viewing the original source. Cause: The `responseData` parameter is not correctly configured, and the source information return switch is not enabled.
- Phenomenon: Expired license texts or outdated copyright notices appear in traceability results. Cause: The traceability data version verification configuration is not enabled, and the latest dependency and license versions of the current project are not linked.
- Phenomenon: License content returned by traceability is truncated, with critical authorization terms or copyright attribution information missing. Cause: The `quoteMaxToken` value is too small to cover the full length of the license text.

## How to Confirm Correct Configuration
- Submit a test request that includes a dependency license query, and check whether returned results include source file paths and update times.
- Adjust the `quoteMaxToken` parameter to a reasonable range, and verify that returned license text is not truncated.
- Switch to different project versions, and confirm that traceability results automatically match license and dependency data of the current version.
- Test the number of entries returned by a single traceability request, and confirm that it does not exceed the preset limit.

The values provided are common starting points and should be evaluated against applicable project samples.
