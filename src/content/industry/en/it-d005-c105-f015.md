# Technical Documentation and API Q&A for License Compliance and Copyright Notices: Knowledge Base Retrieval and Recall

## What This Category’s Data Looks Like
This category’s core data comes from open-source code repositories, third-party dependency lists, official license texts, and project contribution records.
Maintained documentation includes the project root directory’s LICENSE file, NOTICE statement file, batch-generated dependency license lists, and copyright ownership records tied to individual contributors.
Data updates trigger when project versions iterate or third-party dependencies change. No fixed update cycle exists.
Each single data entry includes fields such as license type, copyright holder, version number, and dependency package identifier. Some contribution records also include commit hashes and authorization scope.

## Constraints Imposed on Knowledge Base Retrieval and Recall
Data for this category is scattered across multiple sources including code repositories, dependency lists, and contribution records. Retrieval workflows must support cross-data-source recall logic to avoid missing scattered license and copyright information.
Data updates trigger without a fixed cycle, tied to version or dependency changes. Knowledge base synchronization mechanisms must adapt to this dynamic update rhythm. This ensures retrieval results align with the latest compliance documents.
Each single data entry includes multi-dimensional fields. Retrieval must match associated information such as license type and copyright holder. A single keyword cannot cover all retrieval requirements.
Compliance scenarios have strict requirements for recall accuracy. Missing critical licensed content directly creates compliance risks.

## Configuration Parameters
| Configuration Item | Recommended Value | Rationale |
| ---|---|--- |
| `similarity` | 0.75–0.85 | Matches the precision requirement for technical terms in license texts and copyright statements, prevents low-relevance generic text from appearing in retrieval results |
| `limit` | Top 10 entries | Covers the recall volume for common license types and dependency items, balances retrieval efficiency and completeness of compliance content |
| `usingReRank` | Enabled | Optimizes result ranking after multi-field matching, raises the priority of compliance-related content, and enhances display of critical information |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands retrieval terms to cover variants such as license aliases and common dependency package names, avoids missing similar compliance content |
| `collectionIds` | Specified per exclusive compliance document collection | Limits retrieval scope to compliance-related documents such as LICENSE and NOTICE files, excludes unrelated project code or test content |
| `searchMode` | Hybrid retrieval | Combines keyword matching and semantic matching, adapts to retrieval needs for technical terms in license texts and dependency package names |

## Three Common Configuration Errors
- Enabling `usingReRank` causes retrieval tasks to return a 500 status code or empty re-ranked results. Root cause: The deployment path and access permissions for the re-ranking model are not configured correctly, resulting in model loading failure.
- Retrieval results have insufficient entries to cover all relevant licenses and copyright statements. Root cause: The `limit` value is set too low, or `datasetSearchUsingExtensionQuery` is not enabled. This leads to missed detection of license aliases, dependency package variant names, and other related keywords.
- Non-compliance-related document content is included in retrieval results. Root cause: `collectionIds` is not specified to limit the retrieval scope. This allows retrieval to cover unrelated project code or test documents.

## How to Verify Successful Configuration
- In the FastGPT v4.17.0 backend configuration interface, manually enter a license text keyword. Check if retrieval results include the corresponding LICENSE or NOTICE file content.
- View retrieval logs to confirm that the `usingReRank` parameter is active. Ensure re-ranked results follow the priority of compliance-related content.
- Cross-check the `collectionIds` parameter. Confirm that the retrieval scope only includes compliance-related document collections, with no unrelated content included.
- Trigger a dependency list synchronization task. Check if the knowledge base automatically pulls new dependency license information.

The values provided here are common starting points. They should be evaluated against the samples used in the specific deployment.
