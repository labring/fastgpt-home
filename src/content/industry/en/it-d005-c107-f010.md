# Technical Documentation and API Q&A for Account Ban and Appeal Review: Source Citation and Traceability

## What the Data for This Category Looks Like
The core data for this category comes from four sources: risk control systems, audit records, user behavior logs, and report evidence. Update frequency is daily or real-time synchronization. Daily produced documents include four structures: ban records, appeal materials, review opinions, and user notifications. Fields typically include account unique identifier, violation type code, disposal timestamp, appeal status, associated evidence ID, and more. There is no unified fixed unit system. Each field is identified only by characters, timestamps, or numbers.

## What Constraints Do These Characteristics Impose on the Source Citation and Traceability Link
Associating multi-source data requires the traceability link to accurately match unique identifiers such as account IDs and evidence IDs. This prevents incorrect cross-account associations. The real-time or daily update frequency requires traceability APIs to support dynamic pulling of the latest data. Static caching cannot be relied on. The diversity of document structures requires traceability configurations to adapt to different types of business documents. A unified chunking rule cannot be used. The most time-consuming violation evidence verification step requires traceability results to directly link to original evidence. This reduces secondary processing steps for the large language model. Additionally, error consequences such as false bans and returned violation accounts require traceability results to have traceable original data sources. This ensures every citation can be verified.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Single Search Limit | Top 3 entries | Matches the number of core evidence entries in account ban scenarios, avoids redundant information interfering with review judgments |
| Maximum Context Length | 800–1200 characters | Adapts to the typical length of single documents such as ban records and appeal materials |
| `quoteMaxToken` | 4000 token | Controls token consumption per traceability request, avoids exceeding the large language model's input limit |
| Source Citation Switch | Enabled | Forces linking to original data sources such as risk control systems and audit records, prevents the large language model from generating false content |
| `detail` | Full Mode | Displays core business fields including account ID, violation time, and disposal status, meets review requirements |
| `responseData` | Raw Format | Retains the original document's layout and fields, ensures traceability results can be directly verified |

## Three Common Misconfigurations
- Phenomenon: The knowledge base original text output by the AI has added decorative content, and the original format is not retained. Cause: The configuration item for forcing reference to original content is not enabled, and the large language model's summary optimization logic is enabled by default.
- Phenomenon: The number of traceability result entries does not match the configured single search limit. Entries are too few or too many. Cause: The actual system recall threshold is not considered, and the set limit exceeds the range of data that the data source can return.
- Phenomenon: Interface returns timeout errors. Cause: `quoteMaxToken` is set too large, causing the large language model's processing time to exceed system limits.

## How to Verify Successful Configuration
- Initiate a ban appeal query for a specific account. Check if the returned results include the full content of the original document, with no additional modifications or rewrites.
- Check the number of traceability result entries. Confirm it matches the configured single search limit, with no abnormal deviations in entry count.
- Check if the returned results include core business fields such as account ID and violation type. Match the preset business data structure.
- Check the `responseData` and `detail` fields returned by the interface. Confirm they include linked information from original data sources and complete business fields.
- In the debug panel of FastGPT v4.17.0, a test query is initiated. Verify the source citation popup correctly displays the original document link and content.
