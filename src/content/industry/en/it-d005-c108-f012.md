# Technical Documentation and Interface Q&A for Warranty Period Defect Response: Document Parsing and Chunking

## What the Data for This Category Looks Like
The data for this category primarily comes from customer-submitted warranty work orders, system operation logs, contract warranty clauses, and project version records. Commonly processed documents include standardized defect confirmation sheets, repair execution records, customer confirmation receipts, and similar items. These documents contain fields such as work order number, defect description, responsibility boundary markers, repair time limits, and customer signature status. Data is updated via daily batch synchronization or triggered per individual order. Each document corresponds to the full process information for a single warranty defect.

## Constraints for Document Parsing and Chunking
Documents in this category are mostly semi-structured warranty process forms, mixed with unstructured defect descriptions and contract clauses. Some forms also include embedded images, tables, or handwritten confirmation marks. Data is updated either per order or on a daily basis. Individual documents are typically small in size, but all associated information must be fully preserved. If chunks are truncated at responsibility boundaries or contract warranty clauses, subsequent Q&A will not accurately determine responsibility attribution. If embedded images and table content are not correctly extracted, key customer confirmation credentials may be lost, which impacts subsequent closed-loop judgment.

## How to Set the Configurations
| Configuration Item | Recommended Setting | Rationale |
| ---|---|--- |
| `chunkSize` | `800–1200 characters` | This category’s documents include semi-structured forms and unstructured descriptions. This range balances context integrity and chunk granularity, and prevents key clauses from being truncated |
| `chunkSplitter` | Split by paragraph + title | Warranty documents are mostly divided into paragraphs by process nodes. Splitting by title preserves the contextual association of responsibility boundaries and clause items, and adapts to the structure of standardized forms |
| `customPdfParse` | `Enabled` | PDF documents in this category often contain embedded images and tables. Enabling this setting fully extracts text and image associated information, and avoids losing customer confirmation credentials |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120 seconds` | Individual warranty documents are usually small in size. This duration covers standard parsing time, and prevents parsing failures due to timeout |
| `UPLOAD_FILE_MAX_SIZE` | `50 MB` | Individual documents in this category are mostly work orders and record files. This upper limit covers most scenarios and avoids resource waste |
| `chunkSettingMode` | Manual configuration | The document structure of this category is relatively fixed. Manual configuration accurately matches chunking rules, and adapts to different types of warranty forms |

## Three Common Configuration Errors
- Only plain text is extracted during parsing, with no associated descriptions for tables and embedded images. This happens when the `customPdfParse` configuration is not enabled, causing the parsing tool to ignore non-text media information.
- Chunk results truncate key content from contract warranty clauses, making it impossible for subsequent Q&A to identify complete responsibility boundaries. This happens when the `chunkSize` setting is too small, splitting complete responsibility boundary clauses into multiple independent chunks and losing contextual association.
- Parsing tasks take an extended period with no return results, and the interface displays a timeout status code. This happens when the `PARSE_FILE_TIMEOUT_SECONDS` setting is too low, exceeding the standard parsing time for individual documents and triggering a timeout failure.

## How to Confirm Configuration Is Correct
Based on the parsing logic of FastGPT v4.17.0, use the following actions to verify that configurations are active:
- Upload a PDF warranty confirmation sheet that contains embedded images, and check if the parsing result includes associated descriptions or annotation information for the images. This confirms the `customPdfParse` configuration is enabled.
- Import a complete contract warranty clause document, and check if chunked results retain full paragraphs of the clauses. This confirms the `chunkSize` and `chunkSplitter` configurations match the document structure.
- Upload a test document of the maximum individual size, and check if the parsing task completes within the preset duration. This confirms the `PARSE_FILE_TIMEOUT_SECONDS` setting is reasonable.
- Export chunked text fragments, and verify that core fields such as work order number and responsible party are included. This confirms that chunks have not truncated key information.
