# Technical Documentation and API Q&A for Identity Account and Permission Management: Document Parsing and Chunking

This document applies to FastGPT v4.17.0.

## What Data in This Category Looks Like
Data for this category primarily comes from enterprise identity and access management (IAM) systems, HR systems, business system logs, and approval systems. Updates occur either daily or in real time when personnel changes happen. Common processed documents include account application forms, permission matrices, offboarding recovery forms, and audit reports. Most document structures include fields such as account ID, permission scope, effective or expiration time, and approval status. Common data units are individual accounts, permission entries, approval process nodes, and similar items.

## Constraints for Document Parsing and Chunking
Dispersed data sources create diverse document formats. Parsing modules must support multiple formats including PDF and structured table documents. Frequent updates triggered by personnel changes require parsing processes to have low latency. Permission matrices and audit reports hold sensitive permission information. Parsing processes must prevent data leakage. Account ID and time fields in documents must keep their associated relationships. Chunking must not break the matching logic between permissions and effective times. This prevents ambiguous permission scope issues in subsequent Q&A.

## Configuration Settings

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Matches the text length of single permission entries or approval nodes in documents such as permission matrices and audit reports, avoiding disruption of permission association logic |
| `chunkSplitter` | Split by tables, paragraphs, line breaks | Adapts to documents with structured tables including account application forms and permission matrices, retaining permission correspondence within tables |
| `customPdfParse` | Enable local parsing mode | Prevents sensitive document content leakage caused by online parsing, meeting security requirements for internal enterprise permission documents |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Meets upload requirements for large-volume documents such as audit reports and batch permission matrices, supporting enterprise batch document processing scenarios |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Covers full parsing duration for large-volume audit reports and multi-page permission documents, avoiding parsing failure due to timeout |
| `chunkSettingMode` | Manual configuration | Flexibly adjusts chunking rules based on the structured characteristics of IAM documents, adapting to different types of permission-related documents |

## Three Common Misconfigurations
- Uploading a permission matrix PDF results in misaligned table content, with disordered column widths and permission entries displayed across chunks. This occurs when the table is not configured as a chunk separator, causing the chunking logic to break the structured table layout.
- Uploading an offboarding recovery form fails during parsing, returning a parsing timeout status code. This happens when the `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted to a sufficient duration. Even small, single-page documents may experience parsing timeout due to system load.
- Enabling online parsing mode creates a risk of sensitive permission information leakage. This is caused by not enabling the `customPdfParse` local parsing configuration, resulting in document content being transmitted to external nodes during online parsing.

## How to Verify Proper Configuration
- Upload a permission matrix PDF document, check if the parsed text blocks retain the correspondence between accounts and permissions within the table, confirming that chunking does not break structured content.
- Upload an audit report document under 1000 MB, verify that parsing completes within 600 seconds with no timeout errors.
- Check parsing service logs, confirm that all document parsing processes are completed locally, with no external network request records.
- Adjust the `chunkSize` parameter to 800 characters, upload a document with a single permission entry of approximately 1000 characters in length, confirm that chunking does not split a single permission entry into multiple blocks.

The values provided here are common starting points. They should be evaluated against the user's own samples.
