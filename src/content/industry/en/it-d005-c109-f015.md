# Technical Documentation and API Q&A for Identity Account and Permission Management: Knowledge Base Retrieval and Recall

## What the data for this category looks like
This category of data mainly comes from IAM systems, HR systems, business system logs, and approval systems. Daily produced documents include account application forms, permission matrices, offboarding recovery forms, and audit reports. Data updates occur either daily or in real time following personnel changes. Most document structures include fields such as account identifiers, permission scopes, effective and expiration times, approval nodes, and review results. There is no universal external standardized format, and some documents are offline forms or structured tables.

## How These Characteristics Impose Constraints on Knowledge Base Retrieval and Recall
Multi-source and heterogeneous data formats require compatibility with semantic mapping of different fields during retrieval, and general standardized field matching logic cannot be used directly. Real-time data updates following personnel changes require that knowledge base recall results be synchronized with the latest permission status to avoid recalling permission information for disabled offboarded accounts. Internal documents such as permission matrices and audit reports contain sensitive permission details, so retrieval must strictly match access permissions, and only return corresponding results to authorized users. Most daily documents are structured tables or offline forms, so retrieval must perform precise matching on fields such as permission scopes and account IDs within tables, adapting to the retrieval logic for structured documents.

## How to Configure Settings
This configuration explanation is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---|---|--- |
| `similarity` | 0.75–0.85 | Matches precise fields such as permission descriptions and account IDs related to IAM, avoiding low-relevance permission documents from appearing in results |
| `limit` | Top 10 entries | Internal IAM document volume is manageable, returns sufficient reference content such as permission matrices and application forms, while controlling context length |
| `searchMode` | vector + keyword | Balances semantic matching and precise recall of keywords such as account IDs and permission codes, adapting to multi-format internal documents |
| `usingReRank` | Enabled | Performs secondary ranking on initially recalled permission-related documents to correct semantic matching deviations, such as distinguishing permission configurations for different account types |
| `datasetSearchUsingExtensionQuery` | Enabled | Generates extended terms based on the user's permission retrieval query, for example, matching "offboarded account recovery" to internal document keywords such as "offboarding recovery form" |
| `collectionIds` | Bind dedicated IAM knowledge base collections | Only retrieves documents related to identity account and permission management, avoiding irrelevant content from other business systems |

## Three Common Misconfigurations
- Phenomenon: The exported knowledge base file size is only hundreds of KB, and the content is incomplete. Cause: Not all dedicated identity account and permission management knowledge base collections are bound, only some fragmented permission configuration snippets are exported.
- Phenomenon: Retrieving permission-related questions returns a large amount of irrelevant business log content. Cause: The retrieval scope is not limited via `collectionIds`, or the `similarity` threshold is set too low, causing low-match non-IAM documents to be recalled.
- Phenomenon: After importing a Markdown account application form containing local image links, the permission description associated with the images cannot be retrieved. Cause: The knowledge base's local resource association logic is not configured, only text content is imported, and image links are not included in the retrieval context.

## How to Confirm the Configuration Is Correct
- Initiate a retrieval containing "offboarded account recovery", check whether the returned results cover corresponding documents such as permission matrices and offboarding recovery forms, with no irrelevant business content.
- Export the currently bound knowledge base collection, confirm that the exported file size matches the actual total volume of IAM documents, with no missing content.
- Simulate a personnel change, trigger a knowledge base incremental update, and verify that subsequent retrievals can recall the latest permission configuration information.
- Check the retrieval configuration panel, confirm that the enabled status and values of parameters such as `similarity` and `limit` meet the current retrieval requirements for IAM documents. Adjust to the desired matching effect via multiple tests.

The values provided here are common starting points and should be evaluated against the reader's own samples.
