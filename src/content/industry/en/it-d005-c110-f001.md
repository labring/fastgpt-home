# Technical Documentation and Interface Q&A for On-site Outsourced Operations Services: HTTP Interfaces and External Systems

## What data for this category looks like
The data for this category typically originates from the customer’s ITSM system, monitoring platforms, asset inventories, and on-duty records. Update cycles are mostly daily or monthly. Daily produced documents include on-site daily reports, service desk tickets, inspection reports, and SLA monthly reports. Fields cover ticket numbers, inspection items, SLA compliance status, on-duty personnel information, and more. There is no unified mandatory format, so configurations must match the customer’s field specifications. On-site engineers synchronize on-site data daily, while service managers aggregate SLA-related reports monthly. Data flow requires docking across multiple systems.

## Constraints Imposed on HTTP Interfaces and External Systems
Data sources are scattered and formats are inconsistent, so HTTP interfaces must support custom field mapping to adapt to the data structures of different customers’ ITSM and monitoring platforms. The daily or monthly update cycle requires that interface polling intervals match the business scenario, to avoid excessive calls or data lag. On-site network environments may experience fluctuations, so interfaces must be configured with reasonable timeout parameters. At the same time, the accuracy of SLA monthly reports and ticket data directly affects service delivery. Interface authentication and return verification must strictly align with the customer’s security requirements to prevent sensitive data leaks or data tampering.

## How to Configure Settings
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| `Authorization` | Carry the application API Key assigned by the customer | Adapt to the authentication requirements of the customer’s system, avoid authentication failures, and comply with FastGPT v4.17.0 interface call specifications |
| `variables` | Configure business variables such as ticket numbers, inspection cycles, and on-duty personnel | Match the dynamic field requirements of on-site service documents to achieve flexible data filling |
| `responseData` | Extract core fields such as ticket status, SLA compliance rate, and inspection completion rate | Filter redundant data and adapt to the organization format of on-site daily and monthly reports |
| Interface timeout period | 300–600 seconds | Adapt to on-site network fluctuations and the time consumption of pulling data from multiple systems, and avoid call failures due to network delays |
| Data synchronization frequency | Set according to the business scenario | Match the daily/monthly update cycle, balance data timeliness and system resource usage |

## Three Common Misconfigurations
- Symptom: The interface returns the error `Key is error. You need to use the app key rather than the account key`. Troubleshooting steps: Confirm that the authentication key used for application calls is the application API Key assigned by the customer, and the AI Proxy administrator Token is not used.
- Symptom: The data fields pulled by the interface do not match the format of the on-site daily report. Troubleshooting steps: Confirm that `responseData` has been configured to extract target fields to adapt to the customer’s document field specifications.
- Symptom: Interface calls frequently trigger timeouts or are blocked by the customer’s system. Troubleshooting steps: Confirm that the timeout parameters and synchronization frequency have been adjusted according to the on-site network environment and the customer’s system access restrictions.

## How to Verify Successful Configuration
- Call the test interface and check whether the returned `Authorization` header carries the application API Key assigned by the customer, with no additional sensitive information leaked.
- Trigger the data synchronization task and check whether the fields extracted by `responseData` match the required items of the on-site daily report.
- Simulate on-site network fluctuations to verify that the interface can normally return valid data within the set timeout threshold.
- Confirm that FastGPT is running on v4.17.0 or a later version, and that `AIPROXY_API_ENDPOINT` (the root address of the AI Proxy service, do not append paths such as /v1 or /chat/completions) and `AIPROXY_API_TOKEN` (the AI Proxy administrator Token, consistent with the AI Proxy server configuration and not empty) have been correctly configured as server environment variables, with no startup verification failure prompts.
