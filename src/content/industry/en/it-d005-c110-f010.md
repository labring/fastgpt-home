# Technical Documentation and Interface Q&A for On-site Outsourced Operations Maintenance Services: Source Citation and Traceability

## What this category of data looks like

Core data for on-site outsourced operations maintenance services comes from customer ITSM systems, monitoring platforms, asset inventories, and on-duty records. Four standard document types are produced regularly: on-site daily reports, service desk tickets, inspection reports, and SLA monthly reports.

Most data updates occur daily. Some SLA monthly reports are updated once per month.

Document fields include ticket numbers, inspection points, on-duty time periods, SLA compliance rates, and other items. No unified mandatory format exists. Field specifications must align with the customer’s existing systems.

## Constraints for Source Citation and Traceability

Data sources for this category are scattered, covering multiple systems including customer ITSM and monitoring platforms. When citing content for traceability, clearly mark the original system for each piece of information to avoid mixing data from different sources.

Update rhythms vary widely across document types. Daily updated on-site daily reports and on-duty records require real-time traceability support. Monthly updated SLA monthly reports need to lock historical versions for their respective periods.

No unified mandatory field specification exists for documents. When citing, retain the original fields and format of the source document. This ensures traced content matches original records exactly.

On-site ticket processing and inspection report compilation are the most time-consuming tasks. Citation and traceability must link directly to original data entries. This reduces errors caused by manual organization.

## How to Configure

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the typical single-document length of on-site daily reports and inspection reports, to avoid truncating critical traceability information |
| `responseData` | Enabled | Returns the source system and path of original data, to meet customer traceability verification requirements for tickets and SLA reports |
| `detail` | Top 3 entries | Corresponds to high-frequency on-site ticket processing scenarios, prioritizing the most relevant original records |
| Data source filtering rules | Only include customer ITSM, monitoring platforms, and asset inventories | Matches core data sources for this category, excluding unrelated non-on-site service data |
| Version locking configuration | Bind by update cycle | Adapts to differences between daily updated on-site daily reports and monthly updated SLA monthly reports, ensuring traceability uses historical data for the corresponding period |

## Three Common Configuration Errors

- Phenomenon: Non-on-site service monitoring alert data is included in cited content for generated inspection reports. Filtering for specified source content fails. Cause: Data source filtering rules are not configured, leading to recall of data outside the category scope.
- Phenomenon: When calling the interface to generate SLA monthly report Q&A, returned citation content fields do not match original documents. Missing fields or garbled formats appear. Cause: Original source document field structures are not retained. Returned content field formats are adjusted without authorization.
- Phenomenon: Cited content for generated on-site daily reports is automatically truncated. Complete on-duty record information cannot be displayed. Cause: The `quoteMaxToken` setting value is too small. Traceability content exceeding the threshold is automatically cropped by the system.

## How to Verify Successful Configuration

- Initiate a query related to an on-site ticket. Check if the returned result marks the corresponding original data source system and path via the `responseData` field.
- Generate Q&A content for a monthly SLA report. Confirm returned cited data uses the historical version for the corresponding period, and that the `detail` level matches configuration requirements.
- Adjust the `quoteMaxToken` parameter. Verify that cited content length meets expected display standards.
- Test citing on-site daily reports and inspection reports. Confirm returned fields match original documents exactly.

The values given are common starting points and should be measured against the reader's own samples.
