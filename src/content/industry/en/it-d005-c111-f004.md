# Technical Documentation and Interface Q&A for Configuration Management and CMDB Maintenance: Vector Models and Indexes

## What the data for this category looks like
Core data for this category comes from CMDB, cloud resource inventories, auto-discovery tools, and procurement ledgers. It covers four types of documents: configuration item lists, service component relationship topologies, change records, and asset inventory sheets. Data update frequency is daily or weekly. Fields include configuration item unique identifiers, dependency relationships, affiliated business lines, latest change times, and more. Only actual states of assets and configurations are recorded, with no additional statistical values.

## What constraints these characteristics impose on the "vector models and indexes" link
Configuration management and CMDB maintenance data includes strongly dependent relationship fields and frequently updated change records. When performing vector modeling, associated semantics between configuration items must be retained, so single configuration item text must not be vectorized individually. The daily or weekly update frequency requires the index update strategy to adapt to incremental synchronization, avoiding performance loss caused by full reconstruction. The risk of asset account-actual mismatch requires vector search results to accurately match the actual state of configuration items, so the index must be bound to the unique identifier field of configuration items to prevent search results from being disconnected from actual assets.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Adapts to the text length of configuration item lists and relationship topologies, avoids semantic breakage in single chunks |
| Overlap Length | 50–100 characters | Retains contextual coherence for dependency relationships between configuration items, prevents loss of associated semantics across chunks |
| Similarity Threshold | 0.75–0.85 | Filters low-match non-associated configuration items, avoids mixing irrelevant assets in search results |
| Single Search Limit | Top 10 entries | Matches common retrieval volumes during operational troubleshooting, balances recall precision and query efficiency |
| `defaultToken` | 4096 | Adapts to the total text length of CMDB documents, ensures complete loading of configuration items and associated relationships |
| `maxToken` | 8192 | Covers the total context length during batch retrieval, supports integration of associated semantics across multiple configuration items |

## Three common mistakes
- Phenomenon: Vector service call logs show that only a single text slice is passed per request, and batch processing is not triggered. Cause: Batch vectorization configuration was not enabled in FastGPT v4.17.0, the default setting calls the service with single text entries, which does not adapt to the batch input requirements of vectorization services.
- Phenomenon: Search results cannot be associated with original configuration items, and chunked index content is empty. Cause: The unique identifier field of configuration items was not bound in the vector index configuration, resulting in loss of the mapping relationship between chunked text and actual assets.
- Phenomenon: After adding the Alibaba multimodal-embedding-v1 vector model, the search results have no valid content. Cause: The input format of the multimodal model was not correctly adapted in FastGPT's model configuration, only text fields were passed without matching the multimodal data requirements.

## How to confirm that configurations are correctly set
- View the vector service call logs to confirm that the number of slices per request meets the batch configuration requirements.
- Retrieve the dependency relationship of a test configuration item, check that the configuration item identifiers in the returned results match the original CMDB data.
- Test the model update trigger logic, confirm that newly added change records can be synchronized to the vector index within the specified update cycle.
- Verify the deduplication effect of multi-index retrieval, confirm that multiple chunks of the same configuration item only return one valid result.

The values provided are common starting points and should be measured against the reader's own samples.
