# Technical Documentation and Interface Q&A for Integration Testing and Interface Testing: Document Parsing and Chunking

## What this category of data looks like
Typical data for this category comes from daily work outputs of test engineers and test development teams. It includes interface test cases, joint debugging issue tickets, environment description documents, and test reports. Data sources cover interface management platforms, test environment logs, databases, and message queues. Data is updated daily or after each version iteration. Interface test cases contain interface addresses, request methods, parameter lists, and expected response fields. Joint debugging issue tickets record problem symptoms, troubleshooting steps, and resolution results. Environment description documents include service deployment addresses and dependency configurations. Test reports summarize test pass rates and exception statistics.

## What Constraints Do These Characteristics Impose on Document Parsing and Chunking
Diverse data sources require parsing tools to support structured parameters, semi-structured logs, and unstructured issue tickets. This prevents key fields from being lost. High-frequency updates require lightweight parsing workflows. This avoids slowing test iteration efficiency due to long processing times. Interface test cases and joint debugging issue tickets have strongly linked contextual content. Chunking must preserve the full correlation of parameters and steps. Do not split core information from a single test case. Test reports and log files vary widely in size. Parsing processes must adapt to documents of different sizes.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the parameter block length of interface test cases and contextual length of joint debugging steps, avoids splitting complete information from a single test case |
| `chunkSplitter` | Separate by line breaks and Markdown headings | Matches test case titles, parameter blocks in interface cases, and step sections in issue tickets. Preserves the logical structure of documents |
| `PARSE_FILE_TIMEOUT_SECONDS` | 60–120 seconds | Adapts to batch parsing durations for test reports and log files. Prevents timeout errors when parsing large logs or multiple documents |
| `customPdfParse` | Enabled | Adapts to exported PDF-format test reports and interface documents. Preserves table and parameter layout from the original document |
| `chunkSettingMode` | Manual mode | Allows adjusting chunking rules separately for interface test cases and joint debugging issue tickets. Adapts to structural differences across document types |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Adapts to batch-uploaded test reports and log files. Prevents files from being blocked due to excessive size |

## Three Common Mistakes
- Document chunks created in different environments cannot be reused: The symptom is empty or incorrect search results after uploading to the server. The cause is inconsistent `chunkSplitter` rules between local and server environments. This leads to misaligned chunk boundaries and mismatched vector embedding results.
- No document content appears after parsing a link: The symptom is that the knowledge base parsing status shows success, but no text content is returned after passing an interface document link. The cause is failing to configure `customPdfParse` to adapt to embedded formats in online documents, or setting `PARSE_FILE_TIMEOUT_SECONDS` too short, which interrupts parsing.
- Context references do not render Markdown formatting: The symptom is that interface parameter lists display as plain text in search results. The cause is failing to preserve headings and list markers from the original document during chunking, or not enabling format retention configurations during parsing.

## How to Verify Configurations Are Correct
- Upload a single interface test case document. Check if chunked results retain complete parameters and expected responses for a single test case, with no split breaks.
- Pass a link to an online joint debugging issue ticket. Confirm that parsed text content is complete, with no missing troubleshooting step fields.
- Adjust the `chunkSize` parameter. Compare chunk lengths across different values to confirm they fall within the preset 800–1200 character range.
- View parsing logs for FastGPT v4.17.0. Confirm that `PARSE_FILE_TIMEOUT_SECONDS` does not trigger timeout errors.

The configuration values listed above are common starting points. Adjust them based on your own sample documents and use cases.
