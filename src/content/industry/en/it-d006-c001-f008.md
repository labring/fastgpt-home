# Test Cases and Defect Analysis for CDN and Edge Acceleration Configuration: Workflow Orchestration

This page applies to the workflow orchestration feature of FastGPT v4.17.0.

## What This Category of Data Looks Like
Data for this category primarily comes from CDN consoles, DNS resolution records, public network access logs, and edge node monitoring alerts. Daily associated documents include domain access forms, cache rule configuration tables, refresh and preheating operation records, and fault analysis reports.
Update frequency is daily synchronization or real-time updates with configuration changes. Fields include domain identifiers, cache policy parameters, node IP addresses, access response codes, preheating task statuses, and more. No mandatory additional statistical units are used; only records generated corresponding to operations are retained.

## What Constraints Do These Characteristics Impose on the "Workflow Orchestration" Link
Scattered data sources require workflows to connect to multiple data sources. Cross-source data pull nodes must be configured to integrate console configurations, DNS resolution results, and access logs.
Differences in update frequencies require workflows to set dynamic trigger rules, avoiding fixed-period pulls of expired data.
Varying structural degrees of daily documents require workflows to adapt to input and output of different formats, such as parsing text fields from domain access forms and JSON configurations of cache rules.
The distributed nature of edge nodes requires workflows to support multi-node status verification, while compatibility with differences in access log formats across regions to ensure consistent process execution.

## How to Set the Configuration
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| Variable Definition | Bind `variables` to domain name, cache rule ID, node IP | Match core business fields in CDN scenarios, facilitating parameter transfer and reuse within workflows |
| Trigger Rule | Trigger by configuration change events | Align with data update frequencies, avoiding invalid cyclic execution |
| Timeout Threshold | 600 seconds | Cover typical time consumption of CDN console API calls and log pulling |
| Node Verification | Access edge node status check corresponding to `nodeId` | Verify access validity of edge nodes, matching the distributed deployment characteristics of CDN |
| Result Output | Save to fault analysis report template | Adapt to archiving and review requirements of daily documents |

## Three Common Errors
- Workflow execution prompts "undefined" is not valid JSON. The symptom is that channel link calls fail. The cause is failure to bind JSON fields returned by CDN APIs in `variables`, resulting in empty parameter transfer.
- Workflow node execution times out. The symptom is no execution result returned for a long time after triggering. The cause is failure to set a reasonable timeout threshold, or failure to filter invalid edge node requests.
- Unable to display content corresponding to image URLs in the workflow. The symptom is that an image pull node is configured but no preview output is available. The cause is failure to add an image resource verification link in the workflow, and failure to adapt to anti-hotlinking configuration for CDN image access.

## How to Confirm the Configuration Is Correct
- Manually trigger the workflow, check if `variables` parameters correctly load cache rule configurations for the test domain name.
- View workflow logs, confirm that the edge node status check corresponding to `nodeId` returns normal results.
- Generate test cases, call channel links, verify that the output format meets the preset requirements of the fault analysis report template.
- Simulate a domain name configuration change event, confirm that the workflow automatically triggers and updates the verification record for the corresponding cache rule.

The values provided are common starting points and should be measured against the reader's own samples.
