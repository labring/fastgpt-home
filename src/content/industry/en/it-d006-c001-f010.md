# Test Cases and Defect Analysis for CDN and Edge Acceleration Configuration: Citation Sources and Traceability

## What data for this category looks like
Data for this category primarily comes from CDN consoles, DNS resolution records, user access logs, and edge node monitoring alerts. Daily associated documents include domain access forms, cache rule configuration tables, refresh and preheating task records, and fault analysis reports. Common data fields include node IP, cache hit rate, HTTP request status codes, and refresh task IDs. Update frequency is either daily sync or real-time updates when configuration changes occur. This page is compatible with FastGPT v4.17.0.

## Constraints Imposed by These Characteristics on Citation Sources and Traceability
The multi-source nature of CDN-related data requires associating console configurations, DNS resolution logs, and corresponding fields from access logs during traceability, to avoid bias from a single data source. The update rhythm of daily updates or real-time updates when configurations change requires matching data generation time with configuration effective time, to prevent cross-time data misalignment. The binding relationship between documents and data requires clearly marking the version or task ID of the corresponding document when citing, to ensure a complete traceability chain. The public network distribution feature requires traceability data to cover the bidirectional link between edge nodes and origin servers, and cannot rely solely on records from a single link.

## How to set the configuration
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average character length of single CDN log records, to avoid truncating critical traceability information |
| `responseData` | Full set including node IP, cache status code, and refresh task ID | Covers core fields required for CDN traceability, ensuring a complete traceability chain |
| `detail` | Enable full display | Meets complete traceability needs during fault analysis, avoiding omission of key node information |
| Citation data source range | Top 5 matching logs | Aligns with the conventional return volume of CDN access logs, balancing traceability accuracy and response speed |
| Query timeout threshold | 30 seconds | Adapts to the response delay range of CDN nodes, preventing traceability requests from timing out |
| Line break handling | Automatic escaping | Adapts to the storage format of line breaks in CDN logs, avoiding issues with raw output |

## Three common mistakes
- After importing to another environment, CDN-related plugins cannot be found. The symptom is an error "Plugin configuration does not exist" when the workflow runs. The cause is that the exported configuration does not include the permission binding information of the CDN console, and permission verification fails after cross-environment import.
- "No permission to operate this conversation record" is displayed at the end of knowledge base replies. The symptom is a permission error pop-up when citing traceability data. The cause is that the permission verification switch for citation sources is not enabled, or the conversation role has not been granted permission to view CDN logs.
- Raw `\n` is displayed without line breaks in replies. The symptom is that line breaks in traceability logs are directly shown. The cause is that the automatic escaping configuration is not enabled, and the storage format of CDN logs is not adapted.

## How to confirm the configuration is set correctly
- Export the CDN workflow configuration of the current environment, import it to another environment, and check whether the plugin configuration items are fully displayed to confirm that the permission binding information has been synchronized.
- Initiate a CDN cache refresh task, check whether the traceability citation at the end of the reply is normally displayed, with no permission error messages.
- Enter a CDN log query instruction containing line breaks, confirm that the line breaks in the reply are correctly rendered as line breaks.
- Switch to a role without permissions, check whether traceability data cannot be viewed, to confirm that the permission verification logic is effective.
