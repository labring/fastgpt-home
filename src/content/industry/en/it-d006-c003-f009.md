# Test Cases and Defect Analysis for IT Asset Inventory: Tool Calling and Plugins

## What data for this category looks like
Data for this category comes from asset management systems, procurement systems, financial fixed asset modules, and terminal management platforms. Core documents include asset ledgers, inventory sheets, loan and return forms, and scrap applications. The data update cycle is monthly, quarterly, or annually. Core fields cover asset number, ownership information, storage location, user, and status. Units are mostly physical measurements such as units, sets, and pieces. The corresponding relationship between ownership, location, and user must be matched. This differs from CMDB maintenance scenarios focused on configuration item management.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
Multi-source and heterogeneous data sources require plugins to support integration with multiple independent systems such as asset management, procurement, and finance, to avoid data silos. The low-frequency update cycle means tool calls do not need to be triggered frequently. Full or incremental data can be set to be pulled at fixed intervals. Core fields must strictly match asset number, ownership, location, and user. Plugin parameters must use fixed field mapping rules, and field names or formats cannot be adjusted arbitrarily. The core requirement of account-physical verification requires tools to support data comparison across multiple data sources, with built-in field consistency verification logic to reduce error risks. This document applies to FastGPT v4.17.0.

## How to configure
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool call trigger timing | Scheduled daily/weekly | Matches the monthly/quarterly/annual asset data update cycle, avoids unnecessary high-frequency calls |
| Plugin data source mapping rules | Fixed mapping of asset number, user, storage location fields | Meets the core field requirements of this category, ensures consistent data matching |
| Single pull data volume | Top 1000 entries / calibrated via actual testing | Adapts to the single-batch data return limit of terminal management platforms, avoids interface timeouts |
| Timeout retry count | 2–3 times | Addresses occasional fluctuations in multi-source interfaces, reduces single-call failure rate |
| `toolChoice` | Set to `auto` | Supports automatic selection of tool calling logic suitable for asset inventory |
| `functionCall` | Enable parameter format verification | Ensures returned results comply with the field format requirements of asset ledgers |

## Three common configuration errors
- A field empty error occurs after configuring a database connection plugin. The cause is failure to configure plugin parameters according to the asset ledger field mapping rules, resulting in a mismatch between fields returned by the plugin and the asset number and user fields required by the system.
- Model call time reaches over 600 seconds, but only 1 group of call consumption is displayed. The cause is failure to set the trigger timing according to the low-frequency update cycle of asset data, with high-frequency triggers causing backlog of interface resource occupancy, leading to longer-than-expected return content delay.
- Asset data pull fails when trying to call a third-party large model plugin. The cause is failure to configure the data source mapping between the plugin and the asset management system, resulting in the plugin being unable to obtain core data of this category.

## How to confirm configuration is complete
- Manually trigger a tool call, check whether the returned results include core fields such as asset number, user, and storage location, and that the field format matches the asset ledger.
- Check the scheduled task logs to confirm that tool calls are triggered according to the set daily/weekly cycle, with no records of high-frequency unnecessary calls.
- Verify the configuration parameters of `toolChoice` and `functionCall`, confirm that the plugin calling logic is normally enabled, and no parameter verification errors occur.
- Compare the data pulled by the plugin with the local asset ledger, confirm that the data matching degree complies with the preset verification rules.
