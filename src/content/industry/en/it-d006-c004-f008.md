# Test Cases and Defect Analysis for IT Procurement and Supplier Management: Workflow Orchestration

## What the data for this category looks like
Business data for IT procurement and supplier management typically comes from procurement systems, supplier quotation documents, budget spreadsheets, and contract management systems. Daily generated documents include procurement requisitions, price comparison records, formal contracts, and acceptance documents. Core fields include procurement ID number, supplier name, budget amount, and acceptance date, among others. Data updates are performed per individual procurement process: corresponding data is updated once a purchase order is completed. Monthly summary data is updated at a lower frequency.

## What constraints these characteristics impose on the workflow orchestration link
Since business data sources are dispersed, the workflow must connect to multiple system nodes to obtain procurement applications, price comparison records, and other information. It cannot trigger a process using only a single data source.
Data is updated per individual purchase order, so the workflow must trigger per order to support full-link processing of a single procurement process. There are many document fields with obvious structural differences, so text classification and extraction nodes must adapt to the field characteristics of procurement documents to avoid misclassification or extraction failures.
Process errors may lead to procurement delays, budget overruns, or contract risks. Failure alert and rollback nodes must be configured.

## How to set the configurations
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Parallel process concurrency | 2 | Matches the number of parallel links typically split for IT purchase orders, avoids system overload |
| `variables` bound fields | Purchase order number, supplier name | Matches core identification fields of procurement documents, facilitates process traceability and data association |
| Question classification node trigger rule | Match by keywords in input text | Adapts to the classification logic of procurement applications and price comparison records |
| Text classification extraction accuracy | Calibrated based on actual testing | Adapts to the field complexity of procurement documents |
| Workflow timeout threshold | 600 seconds | Matches the average processing duration of a single purchase order |
| `nodeId` association rule | Bind according to the business logic of process nodes | Ensures correct branch process jump |

## Three common misconfigurations
- Configuring parallel processes without observing speed improvements: The phenomenon is that process execution time does not decrease as expected. The cause is that the system's allowed concurrent resource quota was not adjusted, so process scheduling does not actually execute in parallel.
- Empty text classification extraction results: The phenomenon is that all extracted procurement fields are blank. The cause is that the procurement document fields corresponding to `variables` were not bound, so the node cannot locate valid extraction targets.
- Abnormal node jumps after workflow import: The phenomenon is that branch processes do not execute as configured. The cause is that the old version node configuration associated with `nodeId` was not updated after an upgrade, leading to incorrect node matching.

## How to confirm the configuration is correct
- Trigger a test procurement order process, check the process log to confirm that the two branches of the parallel process start execution at the same time.
- Submit test data after classification, confirm that the AI dialogue node terminates the process and does not return to the classification node.
- After importing an older version workflow, verify whether the business nodes associated with `nodeId` match the current process logic.
- Submit a test document containing procurement fields, confirm that the text classification extraction results include correct procurement order numbers and supplier name information.

Note: The values listed above are common starting points and should be evaluated against your own samples.
