# Test Case and Defect Analysis for IT Procurement and Supplier Management: Source Citation and Traceability

## What data looks like for this category
Data for this category typically comes from procurement systems, supplier quotes, budget sheets, and contract systems. Daily processed documents include purchase requests, price comparison records, contracts, and acceptance reports. Each document contains fields such as purchase order number, supplier name, quoted amount, contract terms, and acceptance date, with units including yuan and days.
Update frequency follows per-order or monthly cycles. The structure of individual procurement-related data is relatively fixed, but associative relationships between multi-source data are complex. Association across different documents relies on unified identifiers such as purchase order numbers. This category serves internal long-term procurement and supplier relationship management, with a different focus than supplier and equipment arrival management.

## Constraints on source citation and traceability
The multi-source nature of data requires traceability to link documents from different sources such as procurement systems and supplier quotes. This means configuration that returns metadata is necessary. The per-order or monthly update frequency requires citation timeliness to align with the data update cycle, avoiding use of expired price comparison records or contract content. Field differences across documents require distinguishing the weight of purchase requests versus contract terms during traceability, to ensure citation accuracy. Additionally, errors in procurement scenarios directly tie to enterprise budget and compliance risks, so traceability accuracy requirements are high. Incorrect source association or truncated key content must be avoided.

## How to set configurations
This guidance is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Single procurement-related document content typically falls within this token range, preventing truncation of critical contract terms or quote details |
| `responseData` | `Include source document metadata` | Must return metadata such as purchase order number and supplier name to enable associative traceability across multi-source data |
| `detail` | `Enabled` | Needs to display specific details like price comparison records and contract terms to match the traceability requirements of procurement scenarios |
| Single search limit | `Top 6 results` | Associated data for IT procurement typically does not exceed 6 entries; excess results will disrupt context understanding |
| Citation marker format | `Display only source identifiers` | Avoid redundant marker text in outputs, aligning with output requirements for the business scenario |

## Three Common Mistakes
- Output content includes the phrase "Citation Marker: [1]". This occurs when the explicit citation marker output configuration is not adjusted, and the system default marker format is directly included in the main text.
- Traceability results cannot be linked to specific purchase contracts or acceptance reports. This happens when the `responseData` parameter is not configured to return metadata. Returning only text content cannot match the unique identifier of source documents.
- Generated citation content truncates critical procurement terms. This is caused by a too-small `quoteMaxToken` value, which cannot accommodate complete procurement terms or quote details.

## How to Verify Proper Configuration
- Initiate a test query covering purchase requests and price comparison records, check that outputs include clear source identifiers and no redundant marker text.
- Review metadata fields in traceability results, confirm they include key information such as purchase order number and supplier name.
- Cross-check the length of cited content, confirm it fully covers procurement terms or quote details with no truncation.
- Simulate a query for a single purchase order, confirm the number of returned traceability results matches the configured single search limit.

The values provided are common starting points and should be measured against the reader's own samples.
