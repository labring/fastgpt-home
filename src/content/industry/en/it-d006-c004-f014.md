# IT Procurement and Supplier Management Test Cases and Defect Analysis: Model Access and Configuration

## What this category of data looks like
The data for this category primarily comes from internal enterprise procurement systems, supplier quotation documents, budget sheets, and contract systems. Daily processed documents include purchase requisitions, price comparison records, formal contracts, and acceptance documents. Common fields include purchase order numbers, supplier entity names, quotation amounts, contract clause entries, acceptance milestones, and more. Data updates follow each purchase order cycle, with monthly summary updates for the overall supplier and procurement ledger.

## What constraints do these characteristics impose during model access and configuration
Data sources are scattered across multiple internal systems, so models must support access to different format data sources. Unified parsing logic for multi-source data must be considered during configuration. Data updates follow individual order cycles, so the model context window must adapt to the total length of multiple documents associated with a single purchase order, to avoid exceeding processing limits. Daily documents include long texts such as contract clauses, so model context processing parameters must be adjusted to cover complete content. Additionally, procurement data involves sensitive information such as amounts and clauses, so data security and call efficiency must be balanced during configuration to prevent sensitive information leaks.

## How to set configurations
The following configurations are formulated based on the logic of FastGPT v4.17.0:

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the total length of multiple documents associated with a single purchase order, such as purchase requisitions, price comparison records, and contracts, to avoid context overflow |
| `maxTokens` | 2000–3000 token | Meets output length requirements for contract clause verification and supplier price comparison analysis, balancing generation quality and call latency |
| `quoteMaxToken` | 1000 token | Supports segmented processing of individual supplier quotation documents, adapting to the typical length of single quotations for this category |
| `toolChoice` | auto | Automatically selects tool calls to process structured procurement data comparison, adapting to multi-source data analysis requirements |
| `temperature` | 0.3–0.5 | Reduces random generation probability, ensuring rigorous and accurate results for procurement clause verification and price comparison analysis |
| `AIPROXY_API_TOKEN` | Fill in a non-empty administrator token consistent with the AI Proxy server configuration | Serves as the AI Proxy identity verification credential for the FastGPT App/Admin server, unrelated to model service provider API keys |

## Three common configuration mistakes
- Symptom: `Cannot read properties of null (reading 'q')` error occurs during calls. Troubleshooting steps: Check if the FastGPT App/Admin server has been configured with a non-empty `AIPROXY_API_TOKEN` and correct `AIPROXY_API_ENDPOINT` root address. Missing or incorrect configuration will cause startup verification failure.
- Symptom: Generated results time out when batch processing multiple supplier quotations. Troubleshooting steps: Check if the `maxContext` parameter value adapts to the total length of multiple documents associated with a single purchase order, to avoid exceeding the model's context processing limit.
- Symptom: Model-generated contract clause verification results deviate from actual documents. Troubleshooting steps: Check if the `temperature` parameter value meets scene requirements. A currently too-high value may cause random fluctuations in generated results.

## How to confirm successful configuration
- Upload a single purchase requisition and corresponding supplier quotation, trigger model analysis, and verify that price comparison results are returned normally.
- View model call logs to confirm that the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` configuration values match the corresponding values set on the AI Proxy server.
- Adjust the `temperature` parameter to 0.3, call the same contract text multiple times, and verify that generated clause verification results are consistent.
- Upload a purchase order package containing multiple associated documents, confirm that the model can read all documents completely and complete analysis.

The values provided are common starting points and should be measured against the reader's own samples.
