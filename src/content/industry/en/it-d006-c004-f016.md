# Test Cases and Defect Analysis for IT Procurement and Supplier Management: Forms and Interactions

## What Data for This Category Looks Like
This category's data primarily comes from enterprise procurement systems, supplier quotation documents, budget sheets, and contract systems. Daily circulating documents include purchase requisitions, price comparison records, formal contracts, and acceptance documents. Data is updated per individual procurement process, when a purchase is completed or during monthly reconciliations. Each document includes fields such as procurement category, budget amount, supplier qualifications, contract terms, and acceptance criteria. Some cross-system fields have inconsistent formatting.

## How These Characteristics Impose Constraints on Forms and Interactions
Data for this category comes from multiple sources and is updated per individual process. It must connect to external procurement systems and supplier quotation libraries to enable linked field population. This avoids manual duplicate entry of information such as procurement category and budget amount. Because document fields change based on process stage, external systems must implement logic to dynamically load custom field groups. This adapts form structures for different stages including purchase requisition, price comparison confirmation, and contract review. The FastGPT `formInput` node is responsible for collecting user input fields for the corresponding stage. Data updates occur infrequently but carry high associated risks. The interaction flow must embed field validity check logic provided by external business systems. For example, matching budget amounts to corresponding budget sheets. This reduces the risk of subsequent procurement delays or overspending.

## Three Common Configuration Mistakes
- Phenomenon: The AI does not trigger preset tools during the tool call link, and directly generates natural language responses. Verification steps: Check whether the tool call trigger conditions are configured correctly. Verify whether the tool call timeout setting matches the time required for cross-system data pulling.
- Phenomenon: The knowledge base reference count cannot select values in the 100-900 range, only fixed preset options. Verification steps: Check the knowledge base reference count configuration item for the current FastGPT version. If custom value range 100-900 is needed, it must be implemented by external systems to restrict the range.
- Phenomenon: The judge node matching rule trigger logic is abnormal. "Equal to" and "Starts with" rules trigger the ELSE branch, while "Contains" and "Ends with" trigger the IF branch. Verification steps: Check whether the judge's branch configuration order matches the business verification logic. Adjust matching priority.

## How to Confirm Proper Configuration
- Submit a simulated purchase requisition. Check whether the `formInput` fields connect to external systems as configured to complete data association. Verify that rules trigger correct prompts.
- Trigger tool calls. Confirm that external data sources are connected as configured to pull supplier qualification data. Verify that tool calls do not time out.
- Configure the judge to verify contract terms. Verify that different matching rules trigger corresponding branches as expected.
- View knowledge base reference results. Confirm that the number of returned documents matches the preset value range.

The values provided are common starting points and should be measured against the reader's own samples.
