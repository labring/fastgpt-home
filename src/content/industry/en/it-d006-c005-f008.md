# Test Cases and Defect Analysis for Issue Triage and Response: Workflow Orchestration

## What the Data for This Category Looks Like
This category’s data primarily originates from GitHub or Gitee Issues, release notes, user environment information, and code repositories. The update frequency is daily or weekly. Daily maintained documents include Issue templates, label rules, response records, and problem reproduction instructions. Data fields include Issue number, labels, priority, reproduction steps, associated code modules, submission time, and more, following the standard Issue structure of open-source communities, with no additional custom statistical fields.

## Constraints Imposed by These Characteristics on Workflow Orchestration
The data source relies on open-source repository APIs, requiring the workflow to support integration with GitHub or Gitee event triggering and polling mechanisms. The daily or weekly update frequency means the workflow trigger interval should not be too short, to avoid exceeding API call limits. Preset label rules and Issue templates require the workflow to include built-in unified classification standard nodes. For the most time-consuming links: problem classification, reproduction information completion, and responsibility module marking, embed sub-nodes for automatic classification and information completion prompts to prevent problem backlogs.

## How to Configure Settings
The following configurations are based on the interface and functional logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Mode | Trigger via GitHub Issue update events, poll every 6 hours | Matches daily data update frequency, balances API call frequency and real-time performance |
| `variables` | Preset enumeration values for Issue labels, priority, and associated code modules | Unifies classification standards, aligns with preset label rule documents |
| AI Conversation Node | Maximum 8000 characters per input, retain the first 3 rounds of conversation context | Adapts to the length of Issue descriptions and response records, avoids exceeding model context limits |
| File Upload Node | Allow uploading .md, .txt, .jpg format reproduction documents, maximum 100 MB per file | Matches the document types and sizes of daily problem reproduction instructions |
| Timeout Alert Threshold | Trigger alert when unprocessed Issues exceed 30 entries | Prevents problem backlogs, aligns with business error consequence constraints |

## Three Common Misconfigurations
- Configuring query merge nodes without specifying associated fields leads to disordered Issue classification results. The same type of problem is assigned to different responsibility modules. This occurs because matching and merging are not performed using the Issue’s code repository and label fields, violating preset label rules.
- Adding `variables` to the knowledge base without clarifying the data type causes workflow runtime errors. A "variable type incompatible" prompt appears on the interface. This happens because the enumeration type is not selected as instructed in the interface, which does not meet the configuration requirements for global variables.
- Enabling the file upload node without configuring corresponding permissions causes document upload failures in the contract review workflow. The upload button is grayed out or an "insufficient permissions" error is triggered. This occurs because the file upload permission configuration for the workflow node is not confirmed, and function permissions are mistakenly bound to paid features.

## How to Verify a Correct Configuration
- Manually trigger the workflow once, and check if the pulled Issue data matches the latest data from the corresponding GitHub repository.
- Submit a test Issue to verify that automatic classification and responsibility module marking align with preset label rules.
- Upload a document that matches the configured format, and confirm that the node can receive and process the file normally.
- Simulate a scenario where unprocessed Issues exceed the threshold, and confirm that the alert node triggers normally.
