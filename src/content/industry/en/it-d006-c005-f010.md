# Test Cases and Defect Analysis for Issue Triage and Response: Source Citation and Traceability

## What This Category of Data Looks Like
The data for this category primarily originates from GitHub or Gitee Issues, code repository version logs, user-submitted environment information, and problem reproduction descriptions. Daily maintenance documents include Issue templates, tag rules, historical reply records, and a list of marked modules responsible for issues. Data updates follow a daily or weekly schedule. Core fields include unique Issue identifiers, problem classification tags, associated code snippets, reproduction steps, and priority markers. No additional statistical numeric fields are included.

## Constraints on Source Citation and Traceability
Data sources for this category are scattered across Issue platforms and code repositories. Citation traceability requires linking both Issue numbers and commit identifiers of corresponding code snippets to prevent traceability deviations. The data update rhythm aligns with Issue processing cycles, so citation source synchronization frequency must not lag behind daily problem handling workflows. Core fields include classification tags and responsible module markers. Citation configurations must bind to corresponding tag rules to ensure traceability content matches problem classifications. Additionally, the effective information length associated with a single Issue is limited. Traceability returned content must adapt to the display scenario of Issue replies to avoid redundant information interfering with issue triage.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 1000–1500 token | Adapts to the average length of effective information for a single Issue, avoiding exceeding reply display limits |
| `responseData` | Return only associated Issues and code snippets | Matches the traceability requirements of this category, focuses on core problem-associated sources, and reduces irrelevant information |
| `detail` | Enable full traceability information | Includes Issue tags, reproduction steps, and associated commits, meeting the field requirements for issue triage and defect analysis |
| Citation source synchronization frequency | Synchronize daily | Matches the daily/weekly update rhythm of this category’s data, ensuring the timeliness of traceability content |
| Variable reference format validation | Bind to Issue data source type | Adapts to the data source structure of this category, avoiding format mismatch errors |

## Three Common Configuration Mistakes
- A `quote type error` error is returned when configuring variable references. This occurs because the reference source type is not correctly specified, and the data source format for GitHub/Gitee Issues or code repositories is not matched.
- Redundant citation source information is always displayed in replies, and irrelevant content cannot be hidden. This happens because the non-core field display configuration for `responseData` is not disabled.
- Excessively long reference content still appears after setting `quoteMaxToken`. This is because the knowledge base chunk size does not match `quoteMaxToken`, and reference content is not validated against the configured token limit.

## How to Verify Successful Configuration
- A test Issue is submitted under FastGPT v4.17.0, and the reply is checked for the associated Issue number and code commit identifier to verify traceability content accuracy.
- The `quoteMaxToken` configuration value is adjusted, a test Issue containing long text is submitted, and the returned reference content length is confirmed to not exceed the set token limit.
- The `detail` configuration is disabled, and the reply is checked to confirm only core traceability information is present, without redundant tags or reproduction step details.
- The variable reference configuration is tested, the absence of a `quote type error` error is confirmed, and the reference format is verified to match the data source type.

The configuration values listed here are common starting points. They should be evaluated against the reader’s own samples.
