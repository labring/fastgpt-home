# Test Cases and Defect Analysis for Pull Request Reviews: Tool Calling and Plugins

## What the Data for This Category Looks Like
Core data for this category comes from code repositories, CI pipelines, Issue links, and contributor submission records. It is generated and maintained by project maintainers, module owners, and contributors. Daily associated documents include PR descriptions, code review comments, CI results, and merge records. Data fields include PR numbers, lists of changed files, test case association IDs, defect tags, and CI execution status. Data updates run on daily or weekly cycles. Synchronization happens in real time or on a scheduled basis following PR submissions, CI executions, or defect tracking status changes.

## Constraints for Tool Calling and Plugins Workflows
Multi-source data requires tool calling to support pulling and associating data across code repositories, CI pipelines, and Issues. Single-data-source-only calls must be avoided. Unlike Issue triaging and response, PR reviews require association with specific code change context. Tool calling must bind to the unique PR identifier and change scope. The daily or weekly update cycle means tool triggering timing must align with standard PR submission, CI execution, or merge process nodes. Invalid calls must be avoided. PR-associated documents use a mix of structured and semi-structured formats. Tools must adapt to parsing rules for code snippets, CI logs, and Issue descriptions. Errors affect main branch code stability. Tool calling must verify test case coverage and defect association to reduce regression defect risk.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to multi-step tool calling needs for PR reviews, automatically selects associated test and defect analysis tools |
| `functionCall` | Set based on actual measurements | Matches structured parsing requirements for PR-associated code changes and CI results |
| Tool calling trigger timing | When the PR status changes to "awaiting review" or the CI pipeline completes | Aligns with standard PR review process nodes to avoid invalid calls |
| Test case association matching rule | Match the top 3 entries of PR changed file paths and test case association tags | Accurately associates corresponding test cases based on PR change scope |
| Defect association threshold | Similarity score ≥ 0.7 | Aligns with association matching standards for code changes and existing defects |
| Single tool call timeout | 600 seconds | Adapts to standard time ranges for CI pipeline and code repository pulls |

## Three Common Misconfigurations
- Symptom: Returned results are mixed after triggering two tool calls simultaneously. Cause: No context isolation rules for parallel calls configured via `toolChoice`
- Symptom: Calls to time-related plugins to retrieve CI trigger times return empty values. Cause: No plugin repository permission scope and time pull interval configured
- Symptom: Multimodal tools fail to recognize test case screenshots. Cause: No match between plugin input format requirements and model-supported image resolution

## How to Confirm Correct Configuration
- Submit a test PR to trigger tool calls, then check if test cases for the corresponding changed files are automatically associated
- View FastGPT v4.17.0 tool call logs to confirm trigger timing aligns with PR status change nodes
- Verify that uploading test case screenshots returns normal recognition results when calling multimodal tools
- Manually trigger parallel tool calls to confirm no parameter conflicts or mixed results
