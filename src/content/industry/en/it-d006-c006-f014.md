# Pull Request Review Test Cases and Defect Analysis: Model Access and Configuration

## What the data for this category looks like
This category's data primarily comes from code repositories, CI pipelines, Issue links, and change content submitted by contributors. Daily associated documents include PR descriptions, code review comments, CI execution results, and merge records. Data fields include PR numbers, changed file lists, CI pass rates, number of review comments, merge status, and more, with no unified standardized format. Update frequency is usually daily or weekly, updating dynamically based on the rhythm of PR submissions and merges.

## What constraints these characteristics impose on the "model access and configuration" link
PR review data sources are scattered and have inconsistent formats, so model access configuration must support format adaptation for multi-source data. `AIPROXY_API_ENDPOINT` (the root address of the AI Proxy service) must be configured as a required environment variable for the App/Admin server to connect to the model service. Data update rhythm changes dynamically with PR submissions, so the model context length must match the total scale of documents associated with the PR to avoid loss of key review information due to an overly small `maxContext` setting. The core links of PR review are change intent confirmation and defect analysis, which have high requirements for model output accuracy, so the `temperature` parameter must be set within a reasonable range. In addition, some PRs include changes such as code screenshots, so the `vision` parameter must be enabled to support visual analysis.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `10000–15000 token` | Adapts to the total length of code changes, review comments, and CI results associated with the PR |
| `temperature` | `0.2–0.4` | Ensures the accuracy of defect analysis and review comment output, avoids randomization bias |
| `maxTokens` | `8000 token` | Matches the single-output limit of mainstream code analysis models, prevents result truncation |
| `toolChoice` | `auto` | Allows the model to independently choose whether to call code analysis or visual analysis tools |
| `AIPROXY_API_ENDPOINT` | `Root address of the AI Proxy service, for example http://aiproxy:3000` | Required environment variable for the App/Admin server, configures the access root address of the AI Proxy service |
| `AIPROXY_API_TOKEN` | `Admin token consistent with the AI Proxy server configuration, cannot be empty` | Required environment variable for the App/Admin server, completes identity verification with the AI Proxy service |

## Three common configuration mistakes
- Symptom: After enabling the `vision` parameter, visual analysis for PRs with code screenshots is not triggered, and the model output does not include analysis results for code screenshots. Cause: The `toolChoice` parameter was not set to `auto`, so the model cannot independently call the visual analysis tool.
- Symptom: The actual token count during model calls does not match the `maxContext` configured on the page, resulting in context truncation or out-of-limit errors. Cause: The value range of the `maxTokens` parameter was not adjusted synchronously with `maxContext`, leading to configuration conflicts.
- Symptom: Model calls prompt authentication failure. Troubleshooting steps: Check whether `AIPROXY_API_ENDPOINT` is the correct root address of the AI Proxy service, whether `AIPROXY_API_TOKEN` is consistent with the AI Proxy server configuration and non-empty, and whether the variables have been configured as server-side environment variables for the App/Admin server.

## How to confirm the configuration is complete
- Check whether the App/Admin server startup verification passes, confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` have been correctly configured as server-side environment variables.
- Trigger a model call for a PR review, check whether the values of `maxContext` and `maxTokens` in the request parameters match the configured values.
- Test PR review tasks with different `temperature` parameters, confirm that the randomness of the output results meets expectations.
- Upload a PR containing code screenshots, confirm that after enabling the `vision` parameter, the model can output review opinions related to visual analysis.

The values provided here are common starting points and should be evaluated against the reader's own samples.
