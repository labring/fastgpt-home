# Test Cases and Defect Analysis for SLA and Service Reports: Citation Sources and Traceability

## What data for this category looks like
This category of data primarily comes from monitoring systems, ticketing systems, contract documents, and customer communication records. The update cycle is monthly or quarterly. Daily produced documents include original SLA clauses, monthly/quarterly service reports, availability statistics reports, and customer review minutes. Core fields include SLA agreed indicator items, unique event identifiers, customer entity information, report cycle range, and statistical calculation results. The data format is tightly bound to business contracts and service processes, with no additional non-standard custom fields.

## What constraints do these characteristics impose on the citation sources and traceability link
Because data sources for this category are scattered and update cycles are long, the citation sources and traceability link must use fixed unique identifiers corresponding to each data source to avoid cross-cycle data confusion. The document structure is tightly bound to business contracts. When citing, fields such as clause number and report cycle must be clearly matched to ensure traceability points to accurate business nodes. Since errors may lead to compensation disputes, the traceability link must retain the complete data source call chain, and citation records for intermediate calculation links cannot be omitted. Otherwise, abnormal event attribution cannot be completed.

## How to configure
This configuration is based on the interface and parameter logic of FastGPT v4.17.0, as detailed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average text length of monthly service reports, to avoid truncation of core SLA clause content |
| Citation source display toggle | Enabled | Complies with business specifications requiring transparent display of data sources in service reports |
| Single citation source limit | Top 6 entries | Balances report readability and traceability completeness, to avoid information overload on the page |
| `responseData` traceability binding | Enabled | Ensures association with original response data from ticketing and monitoring systems, supporting abnormal event attribution |
| `detail` level configuration | Retain full link | Retains full link citation records from original data to report indicators, meeting compliance requirements |
| Data source verification toggle | Enabled | Only allows calls to filed contract, ticketing, and monitoring system data sources, to avoid invalid citations |

## Three common configuration errors
- Phenomenon: The generated service report embeds a large number of irrelevant citation sources, and the display cannot be turned off. Cause: The citation source display toggle is not configured correctly, or the `quoteMaxToken` setting is too small, resulting in forced splicing of redundant data sources.
- Phenomenon: A red error message appears when generating a report, prompting that the citation source is invalid. Cause: The data source verification toggle is not enabled, an unfiled non-business data source is called, or the `responseData` binding configuration is incorrect, resulting in failure to call original data.
- Phenomenon: Only the first generated report in multi-round testing has citation sources, and subsequent rounds have no citation records. Cause: The traceability data cache duration is not configured, or the cache duration is set to 7 days, resulting in cross-cycle data not being refreshed, and the data source for the current report cycle cannot be matched.

## How to confirm the configuration is complete
- Manually trigger a monthly service report generation, check whether matching data source entries are displayed at the end of the report, and the number of entries does not exceed the set single citation limit.
- View system logs to confirm that all called data sources are filed monitoring, ticketing, and contract systems, with no abnormal data source call records.
- Adjust the `quoteMaxToken` parameter and regenerate the report, check that core SLA clauses are not truncated, and the cited content is complete.
- Trigger multi-round testing, verify that each generated report has citation source records corresponding to the cycle, with no missing cases.
