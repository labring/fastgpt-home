# Test Cases and Defect Analysis for SLA and Service Reports: Model Integration and Configuration

## What data for this category looks like
This category of data comes from monitoring systems, ticketing systems, contract documents, and customer communication records. The update cycle is monthly or quarterly. Daily produced documents include SLA clauses, monthly service reports, availability statistics reports, and customer review minutes. Data fields include indicator compliance during the service cycle, abnormal event records, and service thresholds agreed in contracts. There are no fixed unified units; the corresponding measurement standards are matched to specific service items.

## What constraints do these characteristics impose on model integration and configuration
Multi-source heterogeneous data sources require model access rules that support multi-format data parsing. The monthly or quarterly update rhythm allows model calls to trigger summary tasks on a periodic basis, without requiring high-frequency operation. Documents include structured clauses and unstructured minutes, so parsing parameters adapted to mixed text must be configured. SLA indicator calculation and abnormal attribution rely on precise logical alignment, so the randomness of model generation must be limited. At the same time, the context must cover complete cycle data to avoid calculation deviations caused by missing information.

## Configuration settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | Enter the root address of the AI Proxy service, for example http://aiproxy:3000. Do not append paths such as /v1 or /chat/completions | Set as an environment variable for the App/Admin server to configure the unified access path of the AI Proxy service, avoiding cross-system configuration conflicts |
| `AIPROXY_API_TOKEN` | Enter the administrator token consistent with the AI Proxy server configuration, and it cannot be empty | Set as an environment variable for the App/Admin server to ensure identity verification for AI Proxy service calls, complying with sensitive access requirements for SLA data |
| `temperature` | 0.1–0.3 | Reduce generation randomness to ensure consistency of SLA indicator calculation and attribution results |
| `maxContext` | 8000–12000 token | Cover the full context content of monthly service reports, ensuring the model can associate complete cycle data |
| `maxTokens` | 2000–3000 characters | Adapt to the single-section output length of SLA reports, avoiding exceeding format limits of downstream document processing |
| `toolChoice` | auto | Allow the model to call tools as needed to process structured data, improving the accuracy of SLA indicator calculation |

## Three common mistakes
- The interface prompts "No available channel for model gpt-4o-mini under current group default". The cause is that the access credential for this model is not configured in the corresponding model group, or the model channel is not bound to the default group.
- The model call returns an empty result or abnormal format. The cause is that the `maxContext` and `maxTokens` parameters are not adjusted according to the document structure of the SLA report, causing the context to be truncated due to exceeding limits.
- The generated SLA indicator calculation result does not match the actual value. The cause is that `temperature` is set too high, causing random deviations in the attribution logic generated by the model.

## How to confirm the configuration is complete
This document applies to FastGPT v4.17.0.
- Call the test interface, check whether the content returned by the model includes the basic calculation logic of SLA indicators, and verify whether the format of the returned result matches the import requirements of downstream documents.
- View the model call log, confirm that there are no format errors in the configuration of `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`, and that the call status code is 200.
- Adjust the `temperature` parameter, compare the SLA attribution results generated twice, and confirm that the consistency of the results meets business expectations.
- Import a sample of monthly service report data, verify whether the model can correctly associate SLA clauses in the contract with actual service records.

The values provided are common starting points and should be measured against the reader's own samples.
