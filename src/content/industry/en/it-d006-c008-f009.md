# Test Cases and Defect Analysis for Special Event Operations: Tool Calling and Plugins

## Data profile for this category
Data for this category primarily comes from daily documents such as event plans, resource slot schedules, event page copy, and post-event review reports. It also comes from content libraries, event backends, traffic data, and user feedback.
Update frequency is mostly weekly, or adjusted to match holiday event cycles.
Document structures include fields like event cycle, resource slot configuration, copy content, and traffic metrics. There are no uniform fixed units. Some metrics require matching statistical specifications based on the event scenario.

## Constraints on the tool calling and plugins workflow
Since data sources are scattered and updated alongside event cycles, tool calling must support linkage across multiple data sources. It must adapt to temporary data changes during event cycles.
Event documents include clear resource slot and cycle fields. Tool calling must precisely match field ranges to avoid pulling data across events.
Errors can lead to low event participation, wasted resources, or missed content audits. For this reason, tool calling must add pre-validation steps. It must also support historical data retrospective queries for event post-event review needs. Plugins must support the ability to filter data by event ID.

## Configuration settings
This configuration reference is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports flexible calling needs across event operation scenarios, no manual specification of specific tools required |
| `functionCall` | Use only when a fixed tool must be specified | Adapts to scenarios where a specific type of tool is called consistently during event operations |
| Tool calling timeout duration | 600 seconds | Event data pulling typically includes multi-dimensional metrics, sufficient time must be reserved for data aggregation |
| Variable replacement toggle | Enabled | Dynamic content such as event copy and resource slot IDs requires variable replacement to ensure accuracy |
| Maximum variable replacement length | 1000 characters | Adapts to standard length requirements for event copy |
| Data source filter scope | Limited by event ID | Avoids pulling irrelevant data across events, aligns with the independent cycle characteristics of special events |
| Number of returned entries per tool call | First 10 entries | Balances data display volume and calling time, adapts to the quick review needs of event operations |
| Failure retry count | 2 times | Balances data pulling success rate and operation time, adapts to the rapid iteration needs of event operations |

## Three common configuration errors
- A `400` status code error appears, with a prompt message indicating abnormal role formatting. The cause is incorrect handling of message role spaces or null values during tool calling, resulting in non-compliant parameter formatting.
- No output from database connection tool calls. The cause is failure to configure the data source filter scope by event ID. Pulling full event data results in timeout or platform filtering.
- Unable to connect when calling a text embedding model. Channel tests show abnormal request URL. The cause is incorrect configuration of the model’s request address parameter, failing to match model calling specifications for event operation scenarios.

## How to verify correct configuration
- Run a tool calling test. Confirm returned results only include data related to the current event, to verify the data source filter scope configuration is active.
- Submit a test case containing dynamic variables. Confirm the tool’s returned execution result correctly replaces variable content, to verify the variable replacement toggle is enabled and correctly bound.
- Review tool calling logs. Confirm the timeout duration configuration matches current data source pulling time, and no frequent timeouts occur.
- When calling a text embedding model, confirm the request URL matches official configuration documents, to verify model parameter configuration meets requirements.

The values listed here are common starting points. They should be evaluated against the reader’s own samples.
