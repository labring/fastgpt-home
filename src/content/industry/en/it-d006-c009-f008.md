# Test Cases and Defect Analysis for Personal Information Protection Compliance: Workflow Orchestration

## What data for this category looks like
Data covers the full lifecycle of processing personal information that can identify natural persons. Sources include business system operation logs, App permission configuration lists, public privacy policy texts, and user authorization and request records.
Daily generated documents include personal information processing lists, compliance processing rules, impact assessment reports, and user authorization texts.
Data updates occur quarterly or synchronously with product function changes. Common document fields include core items such as information type, processing purpose, legal basis, and storage period.

## What constraints these characteristics impose on workflow orchestration
Multi-source data requires workflows to support pulling heterogeneous data including permission lists and privacy policies across systems. Configure rules for parallel pulling across multiple nodes.
Quarterly updates or updates tied to product changes require workflows to support scheduled triggering or execution triggered by product change events, eliminating manual repeated configuration.
Diverse daily document types and inconsistent fields require format adaptation nodes to automatically extract core fields such as personal information type and processing purpose.
Compliance scenario sorting and legal confirmation take significant time. Workflows must include standardized scenario nodes to reduce manual repeated operations.
Non-compliance carries severe consequences. Configure failure retry and full-link log collection nodes to enable issue traceability.

## How to set configurations
All configurations below are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Multi-source data pull node | Connect to business system, App permission list, and privacy policy data sources separately | Covers the multi-source data characteristics of this category |
| Trigger rule | Trigger on a quarterly cycle or product change event | Matches the quarterly update or product-aligned update rhythm of data |
| Document format adaptation node | Support txt, pdf, docx format parsing | Covers common document types such as personal information lists and assessment reports |
| Global variable configuration | Store personal information type, processing purpose, and legal basis fields | Facilitates reuse of core compliance data across workflow nodes |
| Failure retry configuration | Retry 3 times with 60-second intervals | Addresses temporary exceptions during data pull or parsing |
| Log collection configuration | Bind to a dedicated compliance audit storage directory | Facilitates subsequent traceability of compliance issues |

## Three common misconfigurations
- Phenomenon: Empty fields or parameter transfer failures occur when calling APIs to pull knowledge base documents. Cause: Core parameters such as document ID and request path are not configured in `variables`, causing the node to fail to match the target resource correctly.
- Phenomenon: The backend returns a format error after an HTTP request node transmits a TXT file. Cause: Correct request header parameters are not configured, and the file stream is not converted to a compliant binary transmission format, causing the backend to fail to parse the content.
- Phenomenon: The workflow cannot be nested in a Bot and can only run independently. Cause: The workflow node is not bound to the Bot's function module, and `nodeId` is not correctly set to associate with the Bot's interaction flow.

## How to confirm proper configuration
- Run a test trigger to check if the multi-source data pull node successfully obtains document content from the corresponding data sources.
- Review the fields stored in global variables to confirm they include core compliance items such as personal information type and processing purpose, verifying correct parameter configuration.
- Trigger the failure retry logic to verify that nodes perform retry operations as configured during temporary exceptions.
- Bind the workflow to a Bot test scenario to confirm that the Bot can normally call the workflow to complete compliance test case generation.
