# Personal Information Protection Compliance Test Cases and Defect Analysis: Tool Calling and Plugins

## What Data Looks Like for This Category
Data for this category mainly comes from business systems, App permission lists, privacy policies, and user request records. Update frequency is quarterly or upon each product version change. Daily associated documents include personal information lists, processing rules, impact assessment reports, and user authorization texts. Core fields cover information type, processing purpose, legal basis, storage period, and user authorization status. There is no unified fixed unit, adjusted based on document type. Unlike the data security classification and grading category, data for this category focuses specifically on identifiable natural person information processing links. It must cover the full processing link, and support the construction of compliance test cases, defect location, and rectification plan organization.

## What Constraints Do These Characteristics Impose on the Tool Calling and Plugins Link
Data sources are scattered and formats are inconsistent. Tool calling must adapt to multi-type data source parsing, and multi-source data access plugins must be configured. Update frequency is not fixed. Tools must support on-demand triggering or triggering upon product change nodes, with no requirement for fixed periodic pulling. Core fields include compliance-specific fields such as legal basis and user authorization status. Tool calling must accurately match field definitions to avoid compliance deviations caused by generalized extraction. Document volume grows with product scale. A single-call document processing limit must be set to prevent context overflow that affects calling stability. Errors in compliance data can trigger serious consequences such as complaints and administrative penalties. Tool calling must add a result verification link to ensure extracted fields meet compliance requirements.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` and bound to compliance-specific functions | Adapts to the tool calling logic of FastGPT v4.17.0, automatically triggers the compliance test workflow |
| Single-call document limit | Top 10 documents | Prevents single context overload, matches the document volume characteristics of this category |
| Single-call character limit | 8000 characters | Adapts to the context limit of FastGPT v4.17.0, avoids content truncation |
| Call timeout | 300 seconds | Adapts to the time consumption requirements of multi-source data parsing, avoids timeout interruptions |
| Field extraction rules | Classified by legal basis and user authorization status | Matches the compliance attributes of the core fields of this category, avoids generalized extraction |
| `functionCall` | Only allow calling privacy compliance verification plugins | Restricts the scope of tool calling, prevents unauthorized access to sensitive compliance data |
| Result output switch | Hide tool calling process logs | Meets the confidentiality requirements of compliance data, avoids sensitive information leakage |

## Three Common Misconfigurations
- Phenomenon: Raw parsed logs are output directly after tool calling, without filtering sensitive compliance data. Cause: No result output filtering rule is configured, leading to leakage of sensitive document content such as personal information lists.
- Phenomenon: After calling the compliance verification plugin, the legal basis field cannot be extracted, and a null value is returned. Cause: The field extraction rule does not match the definition of the legal basis field exclusive to this category, and only adapts to general text extraction logic.
- Phenomenon: After sending a termination command to an ongoing tool call, the process does not stop and continues to run. Cause: No forced termination trigger logic for tool calling is configured, only a normal end node is set, and multi-source data parsing tasks being executed cannot be interrupted.

## How to Confirm Configuration is Correct
- Trigger a tool call, verify that the call parameters are bound to compliance-specific functions, and meet the configuration requirements of `toolChoice`.
- Import a test personal information list document, verify that the extracted fields include the core compliance attribute fields of this category.
- Initiate a timeout test, verify that the call completes within the configured timeout period.
- Test the termination command trigger, verify that ongoing tool calls can be interrupted normally.
