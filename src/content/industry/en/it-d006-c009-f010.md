# Test Cases and Defect Analysis for Personal Information Protection Compliance: Citation Sources and Traceability

## What Data for This Category Looks Like
This category of data centers on identifiable natural person information processing. Sources include business systems, App permission lists, privacy policies, and user request records. Daily produced documents include personal information inventories, processing rules, impact assessment reports, and user authorization texts. Data fields include information identification tags, processing links, legal basis association items, storage periods, and more. The data updates quarterly or with product version changes. After each product adjustment or update to compliance requirements, associated compliance document content must be refreshed synchronously.

## Constraints Imposed by These Characteristics on the "Citation Sources and Traceability" Link
Data sources for this category are scattered and linked to multiple document types. The traceability link must accurately match information tags from different sources to avoid incorrect association of cross-category documents. Data update frequency is fixed, so regular verification of citation source version validity is required to prevent use of expired compliance basis. Daily document structures are fixed, so specific fields must be matched when citing to ensure traceability content meets compliance audit format requirements. Consequences of errors include complaints and administrative penalties, so traceability link accuracy must meet traceable standards, and cited content must not mismatch actual compliance documents.

## Configuration Settings
| Configuration Item | Recommended Approach | Basis for This Setting |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Personal information compliance documents have moderate per-block length; this range avoids truncating key compliance basis |
| `responseData` | Return only compliance document fields | Focus on category-specific documents such as personal information inventories and processing rules, filter out irrelevant content |
| `detail` | Enabled | Display specific associated fields of compliance documents to meet detailed audit traceability requirements |
| Citation source filtering rules | Only match personal information-related documents | This category of data centers on identifiable natural person information; filtering non-compliance documents improves retrieval accuracy |
| Maximum number of citations | Top 3–5 entries | Compliance analysis needs to focus on core basis; excessive citations increase analysis complexity |

## Three Common Defects and Their Causes
- Phenomenon: Returns citations of unassociated non-compliance documents. Cause: Citation source filtering rules are not configured, leading the retrieval scope to cover irrelevant documents.
- Phenomenon: Cited content is truncated and cannot display complete compliance basis. Cause: `quoteMaxToken` is set too small, truncating key content from personal information inventories.
- Phenomenon: An error is triggered when applying variables to the knowledge base. Cause: The ID of the exclusive compliance knowledge base is not correctly bound, resulting in citation source matching failure.

- Trigger a defect analysis task, and check that the traceability result displays document tags and associated fields such as legal basis and storage period.
- Adjust the maximum number of citations parameter to confirm that the number of returned citations matches the set range.
