# Test Cases and Defect Analysis for Cloud Host Provisioning and Resource Activation: Tool Calling and Plugins

## What the Data for This Category Looks Like
The data for this category primarily comes from cloud management platforms, order systems, IAM permission systems, and billing systems. It is synced in real time for each individual order. Associated daily documents include resource activation tickets, instance configuration sheets, account permission application forms, and delivery confirmation forms. Core fields include compute specifications, network security group configurations, account permission scopes, billing items, and delivery status. The data structure changes dynamically with the order process, and there is no unified batch update cycle.

## What Constraints These Characteristics Impose on the Tool Calling and Plugins Workflow
Decentralized data sources require tool calling to interface with multiple systems, and separate adaptation to the authentication rules of different platforms such as cloud management platforms and order systems. The real-time update feature requires tool calling to use short-cycle polling or event listening mechanisms to avoid data lag. Field differences across multiple document types require plugins to support dynamic field mapping for different tickets, and fixed field templates cannot be used directly. The update logic unique to each order requires tool calling to bind the order ID as a unique identifier to prevent data confusion across orders. In addition, tool calling for core links such as specification verification and security group configuration must strictly match ticket fields. Otherwise, issues including customer deployment failure, misallocated resources, or billing disputes may occur.

## Configuration Options
FastGPT v4.17.0 supports the following tool calling and plugin configuration items, as detailed in the table below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to dynamic calling requirements across multiple cloud service interfaces, no manual tool type specification needed |
| `functionCall` | Enabled | Supports explicit passing of business parameters such as cloud host specifications and security group configurations |
| Tool Call Timeout Threshold | 300–600 seconds | Adapts to the typical time range for cloud host creation, avoids interrupting normal provisioning processes due to short timeouts |
| Field Mapping Rules | Dynamically match by order type | Adapts to field differences across documents such as resource activation tickets and instance configuration sheets |
| Order ID Binding Switch | Enabled | Ensures tool call data is uniquely associated with the corresponding order, avoiding data confusion across orders |

## Three Common Misconfigurations
- Phenomenon: A cloud management platform interface call returns a 403 permission error. Cause: Authentication parameters for the IAM system were not configured correctly, resulting in the tool call lacking required resource operation permissions.
- Phenomenon: The instance status returned after tool calling is empty. Cause: No real-time data listening mechanism was set up, and fixed-interval polling was used with a cycle longer than the cloud host provisioning time, so the latest status was not retrieved.
- Phenomenon: The formatted delivery result does not match the fields on the resource activation ticket. Cause: No dynamic field mapping rules were configured, and a fixed field template was used for all ticket types, ignoring field differences across different orders.

## How to Verify Proper Configuration
- Initiate a simulated tool call for a resource activation order, and confirm that corresponding data from the cloud management platform and order system can be correctly retrieved.
- Review tool call logs to verify that authentication parameters were passed correctly, with no permission-related errors.
- Compare the instance data returned by the tool with the preset fields on the resource activation ticket, to confirm that the mapping rules are active.
- Adjust the tool call timeout threshold to verify that the final status of cloud host creation can be obtained within a reasonable time range.

The values provided are common starting points and should be measured against the reader's own samples.
