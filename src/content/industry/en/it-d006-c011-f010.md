# Test Cases and Defect Analysis for Cloud Host Provisioning and Resource Activation: Citation Sources and Traceability

## What Data for This Category Looks Like
This category of data primarily originates from cloud management platforms, order systems, IAM permission systems, and billing systems. Daily generated documents include resource activation sheets, instance configuration tables, account permission sheets, and delivery confirmation sheets. Data updates occur in real time per order or at delivery process nodes. Data fields include instance unique identifiers, compute specifications, deployment regions, associated account permissions, billing nodes, delivery confirmation status, and more. There are no unified fixed units, and some fields must align with the resource identifier specifications of the corresponding cloud service provider.

## Constraints for Citation and Traceability Workflows
The multi-system data source characteristic requires the traceability link to establish cross-system association and matching rules. This ensures resource data from different sources can be mapped to the same delivery instance. The real-time or per-order update rhythm requires traceability queries to be limited to the time window of the corresponding delivery order. This prevents matching resource data from other time periods. Differences in structure and fields across different documents require mapping exclusive fields from each document to a unified traceability identification system during configuration. This avoids traceability failures caused by field mismatches. Additionally, errors can lead to customer deployment anomalies or billing disputes. This requires traceability results to have verifiable uniqueness, ensuring cited resource information fully matches actual delivered content.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the core content length of a single cloud host provisioning document. Ensures cited resource configuration and permission information is complete without exceeding context thresholds |
| Single Recall Limit | Top 3 entries | The number of core documents for cloud host provisioning is limited. Excessive recall will interfere with core information extraction |
| `responseData` | Return only matched resource fields | Avoid returning redundant data from unrelated systems. Focus on core traceability fields such as instance ID, specifications, and region |
| Traceability Time Window | Corresponding delivery order creation to completion period | Matches the real-time data update rhythm. Prevents matching resource data from other delivery processes |
| `detail` | Enable full field traceability | Ensures all critical fields such as instance unique identifier, permission configuration, and billing node are included during citation. Meets traceability verification requirements |

## Three Common Configuration Errors
- Phenomenon: After a workflow node executes a database query, the returned response does not include the queried resource activation sheet content. Cause: Traceability association configuration is not enabled, so the query results are not bound to the citation sources of the response.
- Phenomenon: In the variable selection panel of the code execution node, the resource field options referenced by the knowledge base cannot be found. Cause: The knowledge base data source is not mapped to the exclusive fields for the cloud host provisioning scenario, so the corresponding resource identifiers are not loaded into the variable pool.
- Phenomenon: Long unresponsive lag occurs when configuring citation traceability for the cloud host provisioning scenario. Cause: The traceability time window and data source range are not limited, so the model loads excessive irrelevant cloud resource data, causing timeout lag.

## How to Verify Successful Configuration
- Manually create a simulated resource activation sheet. After submitting the test, check if the document fields cited in the response match the simulated content. This test must be executed in the FastGPT v4.17.0 environment.
- Adjust the value of `quoteMaxToken`, observe changes in the length of cited content to confirm the configuration takes effect.
- Simulate time nodes of the delivery process, query resource data from different time periods, confirm that traceability results only match documents from the corresponding time period.
- Check the variable selection panel of the workflow node, confirm that fields related to cloud host resources appear in the optional list.

The values provided are common starting points and should be measured against the reader's own samples.
