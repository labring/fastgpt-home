# Test Cases and Defect Analysis for Cloud Host Provisioning and Resource Activation: Forms and Interactions

## What Data for This Category Includes
Data for this category comes primarily from cloud management platforms, order systems, IAM permission systems, and billing systems. Update frequency is per order or real-time.
Daily associated documents include resource activation orders, instance configuration sheets, account permission orders, and delivery confirmation sheets.
Fields include instance vCPU core count, memory capacity, security group rule entries, permission scope, delivery confirmation status, and more. Common units are cores, GB, entries, and individual units.
There is no fixed unified format. Fields must match the corresponding order dimensions.

## Constraints Imposed on Forms and Interactions
Multiple system data sources require forms to connect to order, IAM, billing, and other interfaces for real-time data pulling.
External business systems or subsequent nodes implement relevant verification logic separately to avoid manual entry errors.
Real-time update frequency requires form fields to sync with order status changes. External business systems or subsequent nodes implement this sync logic separately to avoid expired configurations.
Teams must display complex fields associated with multiple documents in blocks according to business logic to avoid interface overload.
Inconsistent unit requirements mean forms must add unit prompts. External business systems or subsequent nodes implement relevant conversion logic separately to lower entry barriers.
Teams must verify core fields in advance to prevent customers from being unable to deploy resources, misallocate resources, or encounter billing disputes due to configuration errors.

## Three Common Mistakes
- Phenomenon: An InvalidParameter error is returned after submitting the form, prompting that the parameter is empty or has an incorrect format. Cause: External business systems or subsequent nodes do not implement null value verification for the `userSelect` option pulled from the IAM system. When the IAM system interface returns an empty list, empty submissions are not intercepted.
- Phenomenon: Resource specifications after form submission do not match records in the order system. Cause: External business systems or subsequent nodes do not implement verification logic for real-time comparison with available specifications of the cloud management platform. Manually entered specifications are not compared in real time with available specifications of the cloud management platform.
- Phenomenon: Custom prompt text does not update when switching form blocks. Cause: External business systems do not configure the interaction logic of form blocks, and prompt text is not bound to the field status of the corresponding block.

## How to Confirm Configuration is Complete
- Call the IAM system interface to pull the permission list, verify whether the options of `userSelect` match the content returned by the interface.
- Manually enter content that does not comply with unit specifications, verify whether the form pops up unit prompts. External business systems or subsequent nodes implement relevant conversion logic.
- Simulate submitting a form with empty required fields, verify whether pre-submission verification triggers an intercept.
- Pause the cloud management platform interface, verify whether the form input verification logic triggers after input is paused. External business systems or subsequent nodes implement this verification logic.
