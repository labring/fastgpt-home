# Test Cases and Defect Analysis for Cloud Billing and Cost Accounting: Tool Calling and Plugins

## What This Category of Data Looks Like
Cloud billing and cost accounting core data originates from cloud billing systems, tag data, order systems, and resource monitoring platforms. Update cycles are typically daily or monthly. Regularly produced documents include billing details, cost allocation tables, resource utilization reports, and optimization suggestion sheets. Fields include billing item codes, resource attribution tags, allocation ratios, resource IDs, billing cycles, and amount units. The order of data fields and supplementary items varies across different business scenarios.

## Constraints on Tool Calling and Plugins Workflows
Data sources for cloud billing and cost accounting are scattered. Tool calling requires connecting to permission interfaces from multiple systems at the same time. Cross-data source linkage logic must be configured. Data update cycles are split into daily and monthly tiers. Scheduled tasks for tool calling must match the corresponding update cycle to avoid pulling outdated, unupdated data. Fields have no unified fixed format. Field validation logic must be added during tool calling to filter invalid or abnormal billing data. This category focuses on explaining resource consumption from a cost caliber perspective. Tool calling must strictly follow business rules for cost accounting. Errors may trigger customer billing disputes, budget overruns, or resource waste. Failure alerts and retry mechanisms must be configured.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Call timeout | 300–600 seconds | Cloud billing data pulling and cost allocation calculations typically take a long time |
| Retry attempts | 2–3 times | Address temporary call fluctuations in cloud billing interfaces |
| `toolChoice` | auto | Automatically adapt to the tool calling logic for the current scenario |
| `functionCall` | enabled | Force structured format calls for cost accounting-related tools |
| Workflow routing rules | Match by resource attribution tags | Precisely call cost allocation workflows for the corresponding business line |
| Parameter validation switch | enabled | Filter invalid billing detail fields to prevent abnormal data from entering the system |

## Three Common Mistakes
- API calls to cloud billing tools return results that differ from in-platform test results, with some fields empty. Incorrect binding of data source permissions for the cloud billing system causes incomplete billing detail data to be pulled during API calls.
- When calling multiple workflows, all requests trigger the same cost allocation workflow, and routing by business line is not possible. Workflow routing rules matching resource attribution tags are not configured, and trigger conditions for different workflows are not differentiated.
- Uploading local billing documents during API calls results in no response, while in-platform testing can parse documents normally. The document upload plugin configuration for the API endpoint is not enabled, or the parameter range for document parsing is not set correctly.

## How to Confirm Configuration Is Complete
- Initiate a test call, check if the returned results include complete billing detail fields, and verify consistency with in-platform test results.
- Pass resource IDs with different attribution tags to confirm that the corresponding cost allocation workflow is triggered.
- Upload a test billing document to confirm that the API returns parsed structured data.
- View the tool calling logs in FastGPT v4.17.0 to confirm that the `toolChoice` and `functionCall` parameters take effect as configured.
