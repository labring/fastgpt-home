# Test Cases and Defect Analysis for Cloud Billing and Cost Accounting: Citation Sources and Traceability

## What data looks like for this category
The data for this category primarily comes from cloud billing systems, tag data, order systems, and resource monitoring tools. Regularly produced documents include billing details, cost allocation tables, resource utilization reports, and optimization suggestion sheets. Data update cycles are typically daily or monthly. Billing detail fields include billing items, resource IDs, billing cycles, and actual settlement amounts. Cost allocation tables associate project tags with expense proportions, with units mostly being yuan, billing hours, and similar units.

## Constraints on citation sources and traceability from these characteristics
Data sources for this category are scattered. Unique identifiers across multiple systems including cloud billing, tags, and orders must be linked to complete full traceability. Data update cycles are tied to business cycles, so citation timeliness must align with the daily or monthly business report generation rhythm. Field structures vary significantly across different documents: core retrieval fields for billing details and cost allocation tables differ, so targeted chunking and retrieval rules must be configured. Additionally, traceability errors in expense-related data can directly lead to customer disputes or budget overruns, raising requirements for citation accuracy and traceability.

The following configurations are compatible with FastGPT v4.17.0.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum Context | 8000–12000 token | Adapts to the single-document length of billing details and cost allocation tables, avoiding truncation of critical billing fields |
| Single Search Limit | Top 5 results | Covers core associated data for a single report, avoiding redundant information interfering with retrieval results |
| `quoteMaxToken` | 1200–1800 characters | Limits the length of a single citation, adapting to detailed descriptions of individual billing items |
| Citation Source Matching Rule | Associate by resource ID and billing cycle | Ensures that unique identifiers from multiple systems such as cloud billing and tags are linked during traceability |
| `responseData` | Include resource ID, settlement amount | Extracts core traceable fields to facilitate subsequent defect troubleshooting and verification |
| `detail` | Enable full field return | Retains original billing item information from billing details, supporting traceability analysis for abnormal expenses |

## Three common misconfigurations
- Phenomenon: When specifying a knowledge base dynamically, no options appear in the citation variable dropdown menu. Cause: The knowledge base association variable was not defined in advance in the workflow, or the variable type does not match the requirements of the knowledge base selection component.
- Phenomenon: Residual "Citation Marker: [1]" text appears in the model output. Cause: No citation marker filtering rule was configured, or the filtering rule does not cover the prefix identifier of retrieval results.
- Phenomenon: Logs cannot distinguish billing data from different sources. Cause: Multi-system identifier association extraction was not enabled in the retrieval configuration, resulting in confusion of billing data from different cloud accounts and billing cycles.

## How to verify successful configuration
- Perform a retrieval test for a single billing detail, verify that the returned results include core traceable fields such as resource ID and settlement amount.
- Trigger the citation generation process, check that the output only retains business descriptions with no extra citation marker text.
- View workflow logs, confirm that the system identifiers associated with retrieval results match the billing source, with no cross-source data confusion.
- Adjust the retrieval limit parameter, verify that the number of returned results matches the preset configuration value.

The values provided are common starting points and should be measured against the reader's own samples.
