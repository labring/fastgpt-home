# Test Cases and Defect Analysis for Cloud Billing and Cost Accounting: Model Integration and Configuration

## What this category of data looks like
Data for this category primarily comes from cloud billing systems, tag data, order systems, and resource monitoring tools. Four types of documents are regularly produced: billing details, cost allocation tables, resource utilization reports, and optimization suggestion sheets. Data is updated daily or monthly. Fields include billing item identifiers, associated resource IDs, cost amounts, allocation ratios, resource utilization rates, and more. Units cover yuan, hours, GB, and others. The core focus is linking cost metrics to resource consumption.

## What constraints this category’s characteristics impose on model integration and configuration
The update rhythm and document structure of this category’s data impose multiple constraints on model integration and configuration. Daily or monthly bulk billing data has a large volume, so context parameters adapted for long-text processing must be configured. Fields linked across multiple systems require the model to accurately match resource and cost information, so model parameters related to association and matching need adjustment. Format differences across different documents call for flexible context splitting rules. Additionally, the sensitivity of cost data requires strict adherence to server environment variable configurations, to avoid leaking sensitive credentials. Do not mix model channel configurations with AI Proxy environment variable settings.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | Root address where the AI Proxy service is deployed, such as `http://aiproxy:3000` | Complies with server environment variable requirements starting from FastGPT v4.17.0. Do not append `/v1` or other path suffixes. |
| `AIPROXY_API_TOKEN` | Admin token consistent with the AI Proxy server configuration | Required server environment variable. Do not use application API keys or model vendor keys at the application layer instead. |
| `maxTokens` | 8000–12000 token | Adapts to processing requirements for long-text data such as billing details and cost allocation tables, to avoid truncating critical cost-related information. |
| `temperature` | 0.1–0.3 | Reduces randomness in model output, ensuring consistent output for cost calculation and cost allocation logic. |
| `maxContext` | 10–15 historical conversation turns | Adapts to multi-turn anomaly troubleshooting and cost explanation needs in cloud billing scenarios, avoiding context overload that impacts response speed. |
| `toolChoice` | auto | Allows the model to call tools as needed to complete tasks such as locating anomalous costs and explaining cost allocations. |

## Three common mistakes
- Scenario: FastGPT service startup fails with a validation error indicating missing required environment variables. Cause: `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN` is not configured on the App/Admin server, or the configured value is empty.
- Scenario: Model output includes redundant thinking tags, but the thinking output function is not enabled in the configuration. Cause: The setting locations for model channel configurations and AI Proxy environment variables are confused, and the model’s thinking output switch is not configured correctly.
- Scenario: Model calls fail to extract complete billing detail information, with missing fields in returned results. Cause: The `maxTokens` parameter adapted for long text is not configured, resulting in truncation of bulk billing data and failure to extract complete associated resource and cost information.

## How to confirm the configuration is correct
- Check the environment variable configuration file or deployment parameters on the App/Admin server, confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are correctly set and not empty.
- Initiate a test call, input a query instruction for a single billing detail, confirm that the model correctly returns associated resource information and cost details.
- Review the model call logs, confirm that the authentication information carried in the request is the AI Proxy admin token, not an application API key or other type of key.
- Adjust the `temperature` parameter to 0.2, initiate three identical queries, confirm that the output results remain consistent with no significant random deviations.

The values provided are common starting points and should be measured against the reader's own samples.
