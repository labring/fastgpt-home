# Test Cases and Defect Analysis for Cloud Billing and Cost Accounting: Forms and Interactions

## What the data for this category looks like
Data for this category typically comes from cloud billing systems, tag data, order systems, and resource monitoring tools. Outputs include billing details, cost allocation tables, resource utilization reports, and optimization suggestion sheets, updated daily or monthly. Document fields include resource ID, billing cycle, cost amount, allocation ratio, and tag attribution information. Common units are yuan, GB, hours, and similar. Core processing steps include tag attribution verification, abnormal cost troubleshooting, and cost allocation explanations. Issues often arise due to inconsistent data definitions.

## Constraints on Forms and Interactions
Decentralized data sources require external business systems or downstream nodes to implement multi-source data import and verification logic.
Differences in update frequencies require external business systems or downstream nodes to run data synchronization on a daily or monthly cycle.
Fields include multiple types of content, such as resource ID and cost amount. External business systems or downstream nodes must configure format verification rules for the `formInput` node. This prevents non-numeric content from entering the cost calculation phase.
The tag attribution verification step requires external business systems or downstream workflows to support batch selection of tag-associated resources.
Abnormal cost troubleshooting requires external business systems or downstream nodes to filter data quickly by keywords and time ranges.
Cost allocation explanations require downstream workflow nodes to output traceable field association relationships. This avoids accounting errors caused by ambiguous interactions.

## Three Common Mistakes
- Phenomenon: No return results after submitting the bill verification form for the first time. Data loads only after a second submission. Verification steps: Check if the external submission logic has debounce delay configured. Confirm if multi-source cloud billing data synchronization completes after the first submission time.
- Phenomenon: After configuring the model input token length, long-text cost allocation descriptions cannot be fully displayed. Verification steps: Check if the length of cloud billing detail fields matches the currently configured model token limit.
- Phenomenon: The workflow classify module cannot select an AI model in edit mode, but works normally after publishing. Verification steps: Check the model configuration edit mode verification rules for the workflow classify module. Verify if the publishing process bypasses front-end verification.

## How to Confirm Correct Configuration
- Import a simulated billing detail file. Verify that the `formInput` node's format rules block non-numeric cost fields.
- Adjust the data synchronization cycle. Verify that the external system triggers cloud billing data pulling and transmission to the form according to the set cycle.
- Initiate a tag resource batch selection request via an external business system. Confirm that the selection limit of the corresponding logic takes effect, with no operational lag.
- Submit an abnormal cost filtering form. Verify that matching results are returned according to the set threshold range.
