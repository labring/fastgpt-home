# Test Cases and Defect Analysis for Cloud Resource Compliance Audit: Tool Calling and Plugins

## What the data for this category looks like
This category of data is sourced from cloud audit logs, IAM permission systems, CMDB resource inventories, and security baseline scan results. The update cycle is monthly or quarterly. Daily produced documents include compliance checklists, permission audit reports, resource inventories, and rectification tracking sheets. Document fields cover resource ID, permission configuration items, compliance status, rectification progress, and more. Data is stored in a structured format only using actual collected resource and permission information, with no additional statistical values. Field formats remain consistent with the native output of each data source.

## What constraints these characteristics impose on the tool calling and plugins workflow
Data sources are scattered and update cycles are long. Tool calling must support batch pulling from multiple data sources to avoid resource occupancy caused by single-request overload. Document structures are fixed and fields are clearly defined. Plugins must adapt to standardized field mapping rules to reduce additional costs from format conversion. The most time-consuming resource inventory and permission anomaly identification links require tools to support incremental synchronization. Only updated resource data is pulled to improve efficiency. The error consequences of compliance auditing are directly linked to business risks. Tool calling must retain complete calling logs and result traceability fields to facilitate subsequent audit verification.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `functionCall` | Mandatory enabled | Adapts to the structured field requirements of compliance audit documents, ensures unified format of tool return results, and complies with FastGPT v4.17.0 tool calling specifications |
| `toolChoice` | Limited to compliance audit-specific tools | Prevents calling unrelated tools from affecting audit accuracy, and focuses on the business needs of this category |
| Data source pull frequency | Calibrated via actual testing (7–15 days) | Matches the monthly or quarterly update cycle of this category, reduces cloud resource occupancy from frequent requests |
| Result return limit | Top 20 entries | Covers core abnormal resources in a single audit, avoids result overload that impairs analysis efficiency |
| Log retention duration | 30 days | Meets evidence retention requirements for compliance audits, facilitates subsequent traceability and verification |
| Timeout threshold | 600 seconds | Adapts to the time requirements of batch pulling from multiple data sources, prevents request interruptions mid-process |

## Three common misconfigurations
- Tool calling returns an incorrect format, with a prompt that the returned content cannot be parsed. The cause is that the `functionCall` parameter is not configured correctly, resulting in the system failing to properly recognize the structured data returned by the tool.
- After locally deploying an MCP Server, normal calling fails, with a connection timeout prompt. The cause is that the proxy endpoint configuration item is not filled in correctly, and the local address is mistakenly written as a public domain name or the correct port is not specified.
- The number of returned results after tool calling does not match expectations, with only a small number of abnormal resources returned. The cause is that a reasonable result return limit is not set, or the field mapping rules for the resource inventory of this category are not adapted.

## How to confirm correct configuration
- Initiate a test call, and check whether the format of the returned results meets the field requirements of the compliance checklist.
- View the tool calling logs, and confirm that the `toolChoice` parameter is limited to compliance audit-specific tools.
- Simulate a request to pull data from multiple data sources in batch, and verify that the configured timeout threshold does not cause request interruptions.
- Check the log retention function, and confirm that calling records have been retained for the set duration.
