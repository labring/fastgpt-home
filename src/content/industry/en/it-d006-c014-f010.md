# Test Cases and Defect Analysis for Cloud Resource Compliance Audit: Citation Sources and Traceability

## What the data for this category looks like
Core data for this category comes from cloud audit logs, IAM permission systems, CMDB resource inventories, and security baseline scan results. Daily produced documents include compliance checklists, permission audit reports, resource inventory lists, and rectification tracking forms. Core fields include resource ID, owning account, configuration status, abnormal permission flag, and log timestamp. Data update frequency is monthly or quarterly. There is no fixed upper limit for resource entries per single update. All fields follow cloud-native standard specifications, with no custom extended fields.

## What constraints do these characteristics impose on the "citation sources and traceability" link
Three core constraints are imposed on the citation traceability link by the data characteristics of this category. First, data sources are scattered across multiple cloud service systems. Traceability must rely on unique identifiers such as resource IDs, and matching cannot be completed solely through text keywords. Second, the data update cycle is relatively long. Traceability must be associated with the generation cycle of the corresponding audit report to ensure that the cited fragments align with the audit cycle. Third, daily documents have a multi-table associated structure. Traceability must match both the resource ID and the report entry number to avoid confusion between similar cloud resources. Additionally, the consequences of errors directly affect audit compliance. The traceability link must ensure that citation sources are complete and verifiable, with no empty citations or invalid sources.

## How to configure the settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the single-entry content length of cloud resource compliance documents, avoids truncating compliance clauses or permission rules |
| `responseData` | Enable resource ID and report generation time fields | Ensures that traceability can associate unique identifiers and audit cycles from rectification tracking forms |
| `detail` | Enable full citation fragments | Retains clause numbers and specific configuration details from compliance checklists, facilitating manual verification |
| Reranking switch | Enabled | Filters irrelevant cloud resource entries during hybrid retrieval, improves citation accuracy |
| Similarity threshold | 0.75–0.85 | Defines the text matching boundary between compliant configurations and abnormal permissions |
| Single search limit | Top 10 entries | Adapts to the number of entries in a single resource inventory, avoids redundant citations |

## Three common configuration mistakes
- Phenomenon: After enabling the reranking function, the citation fragments for compliance audits are empty, and no matching entries appear in search results. Cause: The reranking filter threshold is set too high, excluding abnormal permission entries that meet compliance requirements but have low initial matching scores.
- Phenomenon: The `quoteMaxToken` setting is too small, and the returned citation fragments are truncated, preventing full display of compliance clause content. Cause: The field length of cloud resource compliance documents is not considered, leading to loss of key information.
- Phenomenon: Citation sources are not associated with unique identifiers, making it impossible to match corresponding entries in rectification tracking forms. Cause: The resource ID field in `responseData` is not enabled, and only returning text content prevents precise traceability.

## How to verify that the configuration is correct
- Initiate a permission audit query, check whether the citation sources in the returned results include cloud audit log timestamps and resource IDs, to verify that the `responseData` configuration is effective.
- Adjust the `quoteMaxToken` parameter, verify whether the returned citation fragments fully include the clause numbers from compliance checklists, confirming that the parameter configuration is effective.
- Compare search results after disabling the reranking function, confirm that the reranking function does not filter eligible compliance entries, verifying that the threshold setting is reasonable.
- Check the single search limit setting, confirm that the number of returned citation entries meets the actual needs of a single resource inventory.

The values provided are common starting points and should be measured against the reader's own samples.
