# Test Cases and Defect Analysis for Cloud Resource Compliance Audit: Model Integration and Configuration

## What Data This Category Includes
Data for this category comes from cloud audit logs, IAM permission configurations, CMDB resource inventories, and security baseline scan results. It updates monthly or quarterly. Daily processed documents include compliance checklists, permission audit reports, resource inventories, and rectification tracking sheets. All use structured formats. Core fields include resource unique identifiers, permission configuration items, compliance baseline matching status, and rectification completion markers. Data exists as batch-exported files or time-series logs. Individual document lengths vary widely, from hundreds to thousands of characters, with no fixed standard length.

## What Constraints These Characteristics Impose on Model Integration and Configuration
The monthly or quarterly update frequency means an overly long context window is unnecessary. It prevents redundant historical data from consuming model resources. Multi-source structured data requires clear field mapping rules during configuration. This ensures the model can accurately extract core information such as permissions and compliance status. Batch document processing needs require model integration to support multi-document context concatenation. Audit errors may lead to compliance failures, unauthorized access, and other consequences. Stable error retry and status verification mechanisms must be configured to guarantee call reliability. This category focuses on permission and configuration compliance. The model must be able to identify IAM policies and baseline rules. It has clear requirements for tool call support.

## How to Set Configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the context of batch compliance documents updated monthly or quarterly, avoids redundant data overflow |
| `maxTokens` | 2000–3000 token | Meets output length requirements for compliance rule parsing and permission anomaly detection |
| `quoteMaxToken` | 500–800 token | Limits the reference length of a single compliance document, prevents context overload |
| `toolChoice` | auto | Supports automatic calls to compliance rule matching and field extraction tools, adapts to multiple types of audit documents |
| `temperature` | 0.1–0.3 | Reduces output randomness, ensures consistency of compliance judgments |
| `AIPROXY_API_ENDPOINT` | Enter the root address of the AI Proxy service, for example http://aiproxy:3000 | Configures the AI Proxy service access address for the FastGPT App/Admin server. Do not append /v1 or /chat/completions paths |
| `AIPROXY_API_TOKEN` | Enter the administrator token matching the AI Proxy server configuration, cannot be empty | Configures the AI Proxy service authentication credential for the FastGPT App/Admin server. Do not use application API keys, model vendor keys, or other business tokens |

## Three Common Misconfigurations
- Model calls return a string of red numeric errors. Troubleshooting: Verify that the FastGPT App/Admin server has correctly configured the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` environment variables. Missing required variables causes startup verification failure, or the service cannot connect to the AI Proxy service. This issue often stems from incorrect configuration of these two environment variables. Keys from third-party API transit services must not be used as this credential.
- Multimodal model calls fail to recognize resource configuration information in images. Cause: The `vision` parameter is not enabled, or the appropriate visual model call path is not configured. Image content parsing cannot be completed.
- The compliance judgment result returned by the model does not match the actual audit document fields. Cause: The `maxContext` parameter is not set appropriately, leading to context overflow and loss of key field information. Field mapping rules may also be configured incorrectly.

## How to Verify Proper Configuration
- A single standard compliance checklist document is input into the system. A model call is executed, and the output is verified to include core fields such as permission status and compliance matching results.
- The environment variable configuration on the FastGPT App/Admin server is checked. The values of `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are confirmed to have no spelling errors and match the deployment environment.
- A simulated abnormal call is triggered. The error handling process is verified to start normally, including retry mechanisms and clear error prompts.
- The context length parameter is adjusted. Key information of the input document is verified to be fully loaded, with no truncation or loss.

The values listed above are common starting points. They should be evaluated against samples relevant to the specific use case.
