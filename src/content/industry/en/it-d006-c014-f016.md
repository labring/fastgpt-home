# Test Cases and Defect Analysis for Cloud Resource Compliance Audit: Forms and Interactions

## What Cloud Resource Compliance Audit Data Looks Like
Data for cloud resource compliance audit originates from cloud audit logs, IAM permission systems, CMDB resource management repositories, and security baseline scanning tools. Daily produced documents include compliance checklists, permission audit reports, resource lists, and rectification tracking forms. The data update cycle is monthly or quarterly. Document fields include resource unique identifiers, permission configuration items, compliance check results, rectification statuses, and associated responsible persons. No additional custom units are used; all fields follow standard general formats for cloud resource and compliance management. The content on this page is compatible with FastGPT v4.17.0.

## Constraints Imposed on Forms and Interactions
The cloud resource compliance audit data update cycle is monthly or quarterly, so no real-time synchronization logic is required for the forms and interactions link. The logic for batch importing local documents must be implemented separately by external business systems or subsequent workflow branches and interfaces. The FastGPT `formInput` node only collects information entered by users.
Document fields are fixed and cover multiple categories including resources, permissions, and compliance statuses. The form grouping display logic must be implemented separately by external business systems or subsequent workflow branches and interfaces, to avoid operational errors caused by information overload.
Data sources are scattered, so mapping rule configuration for multi-source data must be supported. This configuration must be implemented separately by external business systems or subsequent workflow branches and interfaces. The `userSelect` interaction node is used to associate rectification responsible persons, ensuring that the tracking process is traceable.
In addition, the volume of data processed in a single operation is large. The limits on batch import file size and number of entries must be implemented separately by external business systems or subsequent workflow branches and interfaces, to prevent system overload.

## Three Common Configuration Errors
- Phenomenon: The configured `formInput` node in the workflow does not display interactive content in the conversation interface. Cause: The workflow did not correctly trigger the `formInput` node, or subsequent workflow nodes did not correctly configure field mapping logic.
- Phenomenon: An upload failure prompt is returned when batch importing resource lists, with status code 413. Cause: The single import file size exceeds the configured 500 MB limit, or the number of entries exceeds the 1000–2000 entry range.
- Manually select configured options one by one in the `userSelect` node, verify whether the workflow enters the corresponding branch. For cloud resource compliance audit record filtering, additionally verify the input, permissions, and return values of the external interface.

## How to Verify Proper Configuration
- Upload a compliance checklist that conforms to the format, check whether the `formInput` node correctly parses file fields and displays the import entry.
- Trigger the `userSelect` interaction node, confirm that compliance team members can be selected from the user list provided by the external system.
- Simulate batch importing a resource list with fewer than 1000 entries, confirm that the system has no timeout or parsing error prompts.
- Check the form grouping configuration, confirm that fields of different business categories are correctly divided into corresponding modules.
