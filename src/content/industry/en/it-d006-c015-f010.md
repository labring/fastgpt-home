# Test Cases and Defect Analysis for Product Usage Data Analysis: Quote Sources and Traceability

## What Data for This Category Looks Like
This category of data primarily comes from tracking systems, data warehouses, CRM systems, and ticket systems. Update cycles are typically daily or weekly. Daily produced documents include usage analysis reports, tracking plans, indicator caliber tables, and dashboard requirement sheets. Data fields include user identifiers, function modules, operation trigger times, behavior types, and associated customer information. Field units are mostly common formats such as counts, minutes, and event identifiers, with no unified mandatory fixed units.

## What Constraints Do These Characteristics Impose on the "Quote Sources and Traceability" Link
Decentralized data sources require traceability logic to connect with verification rules across multiple systems, ensuring consistency of cross-source data. Differences in update frequencies require traceability information to match the refresh cycle of corresponding data, avoiding generation of analysis results using expired data. Diverse document types mean adaptation to source annotation rules for different formats, preventing indicator caliber conflicts. The non-standardized nature of fields requires binding the original data’s field definitions during traceability, avoiding indicator misjudgments. In test cases and defect analysis scenarios, it is necessary to quickly locate the original nodes of traceability data to ensure the traceability of analysis results.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the length of single analysis content for product usage data analysis, avoiding context overflow |
| `responseData` | Return only associated source fields | Adapts to lightweight traceability verification for tracking, CRM, and ticket systems, reducing data transmission overhead |
| `detail` | Enable full traceability mode | Used for full-link defect troubleshooting in test cases, matching the detailed annotation requirements of dashboard requirement sheets |
| Single search limit | Top 5 entries | Controls the number of returned cross-system references, avoiding redundant analysis results |
| Maximum context | 6000 token (calibrated via actual testing) | Adapts to traceability requirements for cross-source data integration, supporting batch verification of daily updated data |

## Three Common Configuration Mistakes
- Phenomenon: Reference document sources are not displayed on the official chat page, but are displayed normally on the debug page. Cause: The `detail` mode is not enabled in the configuration, only simplified response data is returned, and traceability fields are not included.
- Phenomenon: The number of returned references exceeds expectations, and cannot be limited to the specified quantity. Cause: The single search limit parameter is not configured, and full cross-source data is returned by default, which does not meet the quantity verification requirements of test cases.
- Phenomenon: Traceability markers for long-text analysis are misaligned and cannot match the positions of original data. Cause: `quoteMaxToken` is not set to adapt to long-text splitting rules, resulting in traceability markers that do not correspond to original data fragments.

## How to Confirm the Configuration Is Correct
- Perform a traceability test for single tracking data, check whether the returned results include the source identifier and field definition of the original data.
- Trigger a reference request for batch cross-system data, verify whether the number of returned entries matches the preset single search limit configuration.
- Import long-text analysis test cases, verify whether traceability markers match the positions of original data fragments.
- In FastGPT v4.17.0, switch between the debug and official environments, confirm that traceability information is displayed consistently in both scenarios.
