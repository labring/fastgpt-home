# Test Cases and Defect Analysis for Product Usage Data Analysis: Model Integration and Configuration

This page content is compatible with the model integration and configuration logic of FastGPT v4.17.0.

## What data in this category looks like
Data sources for this category include tracking systems, data warehouses, CRM systems, and ticket systems. Data update frequency is daily or weekly. Daily produced documents include usage analysis reports, tracking plans, metric definition tables, and dashboard requirement forms.
Data fields typically include customer unique identifiers, function module names, operation trigger counts, single operation durations, associated ticket IDs, and more. Field units are mostly basic statistical units such as times, minutes, and entries. No pre-calculation of complex aggregated derived fields is performed.

## What constraints these characteristics impose on the model integration and configuration link
Multi-source data access requires models to support compatible batch data import in different formats, to avoid parsing failures due to field format mismatches.
Daily or weekly update cycles require model configurations to adapt to batch task scheduling periods, to avoid timeouts caused by excessive single-processing data volume.
Unified metric definitions require models to align with preset field definitions during analysis, to avoid misjudgments due to caliber deviations.
Cross-customer behavior insight requirements require models to support aggregation analysis by customer dimension, to ensure analysis result granularity meets business requirements.

## How to set configurations
| Config Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to multi-field associated context of product usage data, avoids truncation of core metric definitions and customer behavior association information |
| `maxTokens` | 4000 token | Matches the conventional output length of a single usage analysis report, ensures complete presentation of metric explanations and grouping results |
| `temperature` | 0.1–0.3 | Ensures consistency of metric alignment and defect troubleshooting conclusions, avoids random deviations |
| `AIPROXY_API_ENDPOINT` | Root address of the AI Proxy service, for example http://aiproxy:3000 | Access address for the AI Proxy service. Do not append /v1 or /chat/completions paths. Do not configure as a single model service address |
| `AIPROXY_API_TOKEN` | Admin token consistent with the AI Proxy server configuration | Used for identity verification between the FastGPT server and the AI Proxy service. Cannot be empty |

## Three common misconfigurations
- When configuring `AIPROXY_API_ENDPOINT`, fill in a single model service address or append paths such as /v1. This causes FastGPT server startup verification failure or model call failure. The root cause is failure to correctly use the AI Proxy service root address as the configuration value.
- Adjust the `temperature` parameter without re-verifying the metric alignment results, leading to metric misjudgment. The root cause is failure to adjust the verification logic in combination with the high consistency requirements of product usage data.
- Misconfigure `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN` in config.json, workflow global variables, or the model management interface. This causes the server to fail to load the configuration correctly. The root cause is failure to configure them as server environment variables.

## How to confirm configuration is complete
- Check the FastGPT server startup verification log to confirm there are no missing configuration errors related to AI Proxy.
- View system operation logs to confirm that model call response times fall within the preset range, with no timeout or connection failure errors.
- Confirm that the FastGPT server has correctly loaded the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` environment variables.
- Import a weekly usage analysis report sample, check whether the defect analysis results generated by the model cover common abnormal data scenarios.

The values provided are common starting points and should be measured against the reader's own samples.
