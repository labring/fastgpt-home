# Test Cases and Defect Analysis for Product Usage Data Analysis: Forms and Interactions

## What the data for this category looks like
Data for this category typically comes from tracking systems, data warehouses, CRM systems, and ticket systems. Update cycles are mostly daily or weekly. Daily associated documents include usage analysis reports, tracking plans, indicator caliber tables, and dashboard requirement forms. Common data fields include user ID, function module identifier, interaction duration, operation count, customer attribution identifier, and more. Units are mostly counts, seconds, and calendar days. Some fields require aggregate statistics combined with customer dimensions.

## What constraints these characteristics impose on the forms and interactions link
Dispersed data sources require external business systems or subsequent workflow nodes to support multi-data source association configuration. Differences in update frequencies require external business systems or subsequent workflow nodes to support custom refresh cycles. Aggregation requirements for multi-dimensional fields mean external business systems or subsequent workflow nodes must provide flexible field mapping and unit conversion options. Unified indicator caliber requires caliber verification logic linked to the external business system in the interaction link, to avoid caliber deviations across documents. The need for explanations of customer grouping requires external business systems or subsequent workflow nodes to support adding comment fields for recording the basis of grouping rules.

## Three common configuration mistakes
- Phenomenon: After a front-end embedded interaction component is submitted, the backend does not receive interaction data. Verification action: Check whether the `formInput` node has been configured with logic to pass collected data to the specified backend interface.
- Phenomenon: Workflow AI nodes cannot accurately identify incomplete procurement input information. Verification action: Check whether the multi-field linkage verification logic of the external business system has been associated with the input data of the `formInput` node.
- Select the configured options one by one in the user selection node `userSelect`, verify whether the workflow enters the corresponding branch; filtering of product usage data analysis records must additionally verify the input, permissions, and return values of the external interface.

## How to confirm the configuration is complete
- Submit test form data, check whether the backend can receive complete interaction parameters.
- Trigger the workflow AI node, verify that the system prompt can correctly verify the completeness of input content.
- Select the configured options one by one in the user selection node `userSelect`, verify whether the workflow enters the corresponding branch; filtering of product usage data analysis records must additionally verify the input, permissions, and return values of the external interface.
- Adjust the data source refresh cycle configuration, verify whether the external data dashboard obtains updated data from the external system according to the set cycle.
