# Test Case and Defect Analysis for Code Review and Merge Management: Source Citation and Traceability

## What the Data for This Category Looks Like
The data for this category primarily originates from Git repositories, CI pipelines, static scanning reports, and defect databases. Daily generated documents include merge requests, code review comments, commit records, and branch strategy descriptions. Data update frequency is daily or triggered by code commits. Data fields include merge request identifiers, changed file lists, reviewer information, associated defect numbers, branch affiliations, and more. There is no unified standardized format, and specific fields vary based on repository configuration.

## Constraints on Source Citation and Traceability
Data for this category is scattered across multiple heterogeneous systems. Implementing citation and traceability requires simultaneous association of code changes from Git repositories, build results from CI pipelines, compliance records from static scanning reports, and issue entries from defect databases. Data update frequency is high, so real-time synchronization of traceability information upon commit must be supported to avoid outdated associated data. Since daily document formats are inconsistent, traceability logic must adapt to metadata fields of different documents such as merge requests and review comments, and cannot rely on a single fixed format for parsing. Additionally, change impact assessment relies on precise traceability; failed associations will directly reduce review efficiency and defect detection rate.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | 800–1200 characters | Adapts to the average length of documents such as merge requests and review comments, avoiding truncation of critical associated information |
| Single Recall Limit | Top 10 entries | Matches the number of associated entries in code review scenarios, avoiding excessive redundant information that interferes with judgment |
| `quoteMaxToken` | 2000 token | Controls the total token count of cited content, aligning with the context carrying capacity of code review scenarios |
| `responseData` | Return only associated entry metadata | Focuses on associated identifiers and paths required for code review and defect analysis, reducing irrelevant content |
| `detail` | Include associated file and defect links | Provides direct traceability entry points for code review, enabling quick jumps to view original content |
| Similarity Threshold | 0.75–0.85, calibrated via actual testing | Adapts to the matching accuracy of code semantics and defect descriptions, filtering results with low relevance |

## Three Common Misconfiguration Mistakes
- Phenomenon: After configuration, defect database entries in Git repositories still cannot be associated, and the returned result is empty. Cause: Multi-data source association rules are not configured correctly, only code data from a single repository is pulled, and defect database metadata is not associated.
- Phenomenon: Returned cited content is unrelated to the current merge request changes, with extremely low matching accuracy. Cause: The similarity threshold is set too low, resulting in recall of a large number of low-relevance test cases and defects.
- Phenomenon: Cited content exceeds display limits, causing review interface lag. Cause: `quoteMaxToken` is set too high, introducing excessive redundant code fragments and historical review records.

## How to Verify Proper Configuration
- Manually submit a test merge request, check whether associated test cases and defects are correctly recalled.
- View traceability logs to confirm that all configured data sources are normally pulled and associated.
- After adjusting configuration items, compare recall results under different parameters to confirm that matching accuracy meets expectations.
- Verify that cited jump links can directly point to the original Git repository, defect database, or CI pipeline pages.

The values provided are common starting points and should be evaluated against the reader's own samples.
