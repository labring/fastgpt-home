# Test Cases and Defect Analysis for Enterprise Software License Management: Workflow Orchestration

## What the data for this category looks like
Data for enterprise software license management comes from software asset management systems, procurement systems, terminal scanning tools, and vendor authorization documents. Core daily output documents include license ledgers, software usage lists, procurement contracts, and compliance audit reports. Data update frequency is monthly or quarterly, aligned with ledger update and compliance audit cycles. Core fields include license number, authorized quantity, terminal installation count, expiration date, and others. It requires matching authorized and actual installed usage quantities, which differs from general IT asset inventory that only tracks hardware or software installations.

## What constraints these characteristics impose on workflow orchestration
The need for multi-source data access requires workflows to support parsing of different file formats and cross-system data pull nodes, eliminating repetitive manual data organization work. The data update cycle is monthly or quarterly, so workflows must be configured with matching scheduled trigger rules, removing the need for frequent manual startup. The uniqueness and relevance of core fields require that `variables` in workflows be bound to accurate field parameters, ensuring correct logic for tasks such as authorized quantity verification and over-installation identification. Diverse document types require separate parsing rule configurations for ledgers, contracts, and scanning reports to adapt to different field extraction logic. FastGPT v4.17.0 workflow nodes can support these configuration requirements.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Scheduled Trigger Cycle | Follow business update frequency: monthly/quarterly | Aligns with the update rhythm of license ledgers and compliance audit reports |
| File Parsing Node | Enable full field extraction | Covers core business fields such as license number, authorized quantity, and expiration date |
| `variables` | Bind license number, authorized quantity, terminal installation count | Used for parameter transfer and comparison logic between nodes within the workflow |
| Node Timeout Setting | 600 seconds | Provides sufficient processing time for parsing large vendor authorization files or pulling data across systems |
| Exception Alert Trigger | Over-installation quantity > 0, expiration date < 30 days | Matches the most time-consuming business links of over-installation identification and renewal expiration reminders |
| `nodeId` | Bind file upload and data comparison node IDs | Configures trigger dependencies and parameter flow between nodes |

## Three common misconfigurations
- Phenomenon: A Load file error prompt appears when uploading vendor authorization files, and the interface shows file parsing failure. Cause: The file parsing node for the corresponding format is not configured, or `variables` are not correctly bound to the output parameters of the file upload node.
- Phenomenon: In a local deployment environment, after uploading a license ledger, the workflow parsing node has no execution logs. Cause: The automatic trigger switch for the workflow is not enabled, or the trigger dependency configuration between nodes is incorrect.
- Phenomenon: The code running node fails to execute the authorized quantity verification logic and cannot output comparison results. Cause: The field parameters bound to `variables` are not correctly referenced in the code node, or the corresponding data format is not matched.

## How to confirm the configuration is complete
- Upload a test vendor authorization file, check the workflow execution logs in FastGPT v4.17.0, and confirm that the file parsing node successfully extracts core fields.
- Manually trigger the workflow, review the output results of the data comparison node, and confirm that the over-installation identification logic runs normally.
- Configure a scheduled trigger task, wait for the matching update cycle, and check the workflow execution records to confirm that the automatic trigger takes effect.
- Simulate an over-installation scenario, verify that the exception alert node triggers prompts as expected.
