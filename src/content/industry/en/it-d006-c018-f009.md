# Test Cases and Defect Analysis for Enterprise Software License Management: Tool Calling and Plugins

## What data for this category includes
Data for this category comes from software asset management systems, procurement systems, terminal scan results, and vendor authorization files. Update cycles run monthly or quarterly. Daily associated documents include license ledgers, software usage lists, procurement contracts, and compliance audit reports. Data fields include software name, authorization type, authorized quantity, installed terminal count, and expiration date. Common units are devices, copies, and days. No fictional statistical values are included.

## Constraints on tool calling and plugin workflows
Data sources for this category are scattered. Multiple tools must be called to pull ledgers, scan results, and authorization files from different systems. Different interface formats must be adapted to complete data integration. Update cycles are monthly or quarterly. Fields are fixed and do not change frequently. Tool calls must lock corresponding field mappings to avoid cross-cycle data confusion. Authorized quantity and installed terminal count are core verification fields. Tool parameters must exactly match field names. Otherwise, over-installation identification errors will occur. Compliance audits must link procurement contracts and authorization files. Plugins must support multi-document context linkage. Single calls must cover all associated data to avoid context breaks.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to different tool calling scenarios such as authorized quantity verification, over-installation identification, and renewal reminders. Automatically selects matching tools |
| `functionCall` | `enabled` | This configuration is supported in FastGPT v4.17.0 and later versions. Forces structured tool calling to ensure precise matching of parameters with fields from license ledgers and terminal scan data |
| Tool call timeout period | 300–600 seconds | Data must be pulled from multiple source systems. The timeout period covers the reasonable duration for full data pulling and verification |
| Associated document recall limit | Top 3 entries | Compliance audits must link procurement contracts, authorization files, and software usage lists. Avoids redundant data interfering with verification logic |
| Context retention length | 1200–1500 characters | Must cover context for multi-document linkage. Prevents loss of core field information if tool calls are interrupted |

## Three common mistakes
- Phenomenon: After each tool call, the model-generated response cannot continue the previous license ledger context. Context breaks occur. Cause: `functionCall` is not set to forced mode. Associated contexts of procurement contracts and authorization files are not retained after tool calls.
- Phenomenon: After tool calls complete, the model response time exceeds the preset threshold. Timeout errors occur. Cause: The tool call timeout period is set too short. It does not cover the full process of multi-source data pulling and verification.
- Phenomenon: When calling the license verification tool, an error reporting empty fields is returned. Over-installation identification cannot be completed. Cause: No parameter supplement step is configured in the workflow. Required fields including authorized quantity and installed terminal count have no entered values.

## How to verify proper configuration
- Trigger a tool call. Check if returned fields exactly match those from license ledgers and terminal scan data. Matching logic must be calibrated according to actual business scenarios.
- Simulate a multi-source data pulling scenario. Verify if tool calls complete within the preset duration. Timeout thresholds must be calibrated according to actual pulling time.
- After testing tool calls, confirm if the model can continue the previous context to generate compliance verification conclusions. Context retention length must be calibrated according to the total character count of associated documents.
- Trigger over-installation identification verification. Check if authorized quantity from procurement contracts and installed quantity from terminal scans are correctly linked. Linkage rules must be set according to business requirements.
