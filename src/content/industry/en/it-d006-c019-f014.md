# Test Cases and Defect Analysis for Crowdsourced Annotator Management: Model Access and Configuration

## What the Data for This Category Looks Like
Data for this category primarily comes from crowdsourcing platforms, annotation quality collection systems, annotator training assessment records, and financial settlement systems. Daily associated documents include personnel access rules, annotation training materials, performance ranking tables, and settlement detail lists.
Data update frequency is typically daily or monthly. Core fields cover personnel qualification information, annotation task completion volume, quality pass rate, settlement amount, and more. Annotation rules and settlement standards differ across projects.

## Constraints Imposed on Model Access and Configuration
Data sources for this category are scattered and have varied formats. Model access workflows must support connecting to multi-source heterogeneous data. They must adapt to document formats including personnel access rules, performance tables, and settlement lists.
Differences in data update frequencies require configurations to support flexible switching between daily and monthly synchronization strategies.
Core fields have strong project-specific customization needs. Models must flexibly map exclusive fields for each project.
Settlement-related data has strict rigor requirements. Model configurations must match the field rules of financial systems. This avoids risks of incorrect or missed payments caused by field mismatches.
Test cases must cover compatibility for multi-source data access. Defect analysis must prioritize issues such as field mapping errors and data truncation.

## How to Set Configurations
The following server environment variables and model parameters are formulated based on the configuration logic of FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | `http://172.17.0.1:8000` (Intranet Docker deployment scenario, root address of the AI Proxy service; do not append paths such as /v1 or /chat/completions) | Adapts to AI Proxy service call requirements for intranet-deployed crowdsourced annotation management platforms, avoids public network access restrictions |
| `AIPROXY_API_TOKEN` | Non-empty administrator token consistent with the AI Proxy server configuration | Ensures identity legitimacy for AI Proxy service calls, prevents unauthorized access |
| `maxContext` | 8000–12000 token | Adapts to context length requirements for splicing multiple documents such as personnel access rules, performance tables, and settlement lists, avoids content truncation |
| `temperature` | 0.2–0.4 | Ensures consistency of field mapping and data synchronization results, reduces random deviations |
| `toolChoice` | `none` | This scenario does not require calling external tools, only completes data format conversion and field mapping |
| `maxTokens` | 2000–3000 token | Adapts to processing length for single settlement details or performance records, avoids exceeding model limits in a single request |

## Three Common Mistakes
- Phenomenon: Service calls return connection timeout errors with a 500 status code in Docker intranet deployment scenarios. Cause: The `AIPROXY_API_ENDPOINT` environment variable of the App/Admin server is not correctly configured. The value must be the root address of the AI Proxy service, and paths such as /v1 must not be appended. This causes the service to fail to connect to the AI Proxy service.
- Phenomenon: After configuring model parameters in Config.json, the model still returns results in streaming mode, and cannot switch to non-streaming mode. Cause: Related parameters for non-streaming control are not correctly configured. This causes the configuration items to not be recognized and take effect by the system.
- Phenomenon: After accessing the Whisper speech model, speech input annotation tasks fail to generate valid transcription results, and return empty content. Cause: Related parameters for the multimodal model are not correctly configured. This causes speech data to not be properly parsed and processed by the model.

## How to Verify Successful Configuration
- Use the curl command in the intranet environment to call the configured `AIPROXY_API_ENDPOINT` address, verify whether the AI Proxy service responds normally.
- Import a personnel performance table containing custom fields, check whether the field mapping results output by the model cover all custom fields without omissions.
- Adjust model parameters to different ranges, compare result consistency of multiple settlement data synchronizations, confirm that parameter values meet business requirements.
- View model call logs, confirm that no content truncation warnings are triggered when processing long documents, and that related parameter configurations have taken effect.
