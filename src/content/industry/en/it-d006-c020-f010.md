# Test Cases and Defect Analysis for Supplier and Equipment Arrival Management: Source Citation and Traceability

## What Data for This Category Looks Like
Daily documents for this category typically include purchase orders, arrival acceptance slips, serial number lists, and invoice materials. Data usually originates from ERP systems, supplier shipping documents, logistics information, and device manufacturer backends, with an update frequency of per order or weekly. Document fields often include purchaser information, supplier information, device model, serial number, arrival time, acceptance results, and similar details. Units are primarily physical units such as sets, pieces, and units. Data is linked to delivery nodes of specific integration projects, and updates dynamically alongside procurement and arrival processes.

## Constraints on Source Citation and Traceability
Data for this category is multi-source and scattered, updated per order or weekly, and core fields focus on precise identifiers such as device models and serial numbers. This creates multiple constraints during the source citation and traceability process. Unique identifiers including purchase order numbers and serial numbers must be associated to complete cross-document traceability and avoid mixing data across batches. Each procurement or arrival node must be bound to prevent use of expired or mismatched documents. Precise matching of device model and serial number fields is required to avoid mismatches caused by broad keyword searches. Specific project information must also be linked to ensure traceability results correspond to delivery nodes and avoid project delay risks.

## How to Configure Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 900–1100 token | Adapts to the content length of a single arrival acceptance slip or serial number list, and fully retains key traceability information such as device model and serial number |
| `responseData` | Includes source file name and storage path | Meets business requirements for tracing back to specific documents, and facilitates relevant personnel to verify procurement and arrival information |
| `detail` | Enable field-level matching | Precisely matches unique identifiers such as purchase order numbers and device serial numbers, avoiding mismatches caused by broad keyword searches |
| Single search recall limit | Top 5 entries | Covers the number of core documents linked to a single procurement batch, avoiding interference from redundant data during analysis |
| Retrieval filter condition | Bind purchase order number | Limits the retrieval scope to documents of this procurement batch, preventing cross-cycle data from being included |
| Context window size | 2000–2500 characters | Accommodates the content of multiple linked documents, supporting cross-document traceability analysis |

## Three Common Mistakes
- Phenomenon: The returned cited documents include invoice materials not from the current procurement batch. Cause: No purchase order number is bound as a retrieval filter condition, and redundant cross-cycle data is recalled, which easily leads to defects such as inconsistent asset book and physical records.
- Phenomenon: The device serial number field in the cited content is truncated and cannot be displayed. Cause: `quoteMaxToken` is set too low, truncating key traceability information that includes the serial number.
- Phenomenon: Test case execution prompts that there is no valid citation source. Cause: Field-level matching is not enabled, so the precise association between device models and serial numbers cannot be identified, resulting in no matching documents being retrieved.

## How to Confirm Proper Configuration
- Submit a test case linked to a single purchase order, check whether the returned citation list only includes documents from this procurement batch, and adjust the retrieval filter condition until the match is correct.
- View the returned citation content to confirm that fields such as device model and serial number are fully displayed, and adjust the value of `quoteMaxToken` until no truncation occurs.
- Trigger the defect analysis scenario, enter a question describing a device mismatch, and check whether the returned citations accurately point to the purchase order or shipping document of the corresponding model.
- Call the API interface to confirm that the returned response data includes the source file name and storage path, which meets traceability requirements.
