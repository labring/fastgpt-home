# Test Cases and Defect Analysis for Supplier and Equipment Arrival Management: Model Access and Configuration

## What data for this category looks like
This category of data typically comes from ERP systems, supplier shipping invoices, logistics tracking information, and equipment manufacturer backends. Core documents in daily circulation include purchase orders, arrival acceptance slips, serial number lists, and invoice materials. Purchase orders contain fields such as supplier number, equipment model, purchase quantity, and agreed arrival date. Serial number lists record the unique identifier of each individual device and the corresponding purchase order number. Data updates follow a per-order cycle. Some bulk arrival scenarios are synchronized weekly.

## What constraints these characteristics impose on the model access and configuration link
The multi-source data and per-order update characteristics of this category require the model access link to adapt to multiple unstructured document formats. These include scanned arrival acceptance slips and structured serial number lists. Single-order data volume is limited, but field correlation is high. Context windows must be restricted to avoid interference from irrelevant data. The need for accurate verification of equipment models and serial numbers requires the model’s recall and generation logic to align with strict matching rules for business fields. Generalized processing must be avoided. Bulk arrival scenarios use weekly data synchronization. This requires configuring a stable data source update trigger mechanism.

## How to configure settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Adapts to the total length of multiple documents associated with a single order, including purchase, acceptance, and serial number lists. Prevents truncation of critical business fields |
| `maxTokens` | `2000–3000 token` | Limits the output length of defect analysis or test cases generated per round. Matches the length of field descriptions in business documents |
| `quoteMaxToken` | `1500 token` | Restricts the total length of recalled knowledge base text blocks. Ensures only content related to equipment model and serial number verification is retained |
| `temperature` | `0.1–0.3` | Reduces generation randomness. Ensures accurate matching of fields such as equipment models and serial numbers. Avoids generalized output |
| `AIPROXY_API_ENDPOINT` | Enter the root address of the AI Proxy service, for example http://aiproxy:3000. Do not append paths such as /v1 or /chat/completions. Do not enter single-model service addresses | Required environment variable for the FastGPT server. Used to connect to the AI Proxy service and ensure data link connectivity |
| `AIPROXY_API_TOKEN` | Enter the administrator token consistent with the AI Proxy server configuration. Must not be empty | Required environment variable for the FastGPT server. Used for identity verification with the AI Proxy service. Prevents unauthorized access. Do not use application API keys, model supplier keys, or application-issued tokens as substitutes |

## Three common configuration mistakes
- Symptom: The model cannot read uploaded serial number lists or arrival acceptance slips. Returns empty results or prompts that the file cannot be parsed. Cause: The `vision` parameter for enabling multimodal parsing is not configured, or the uploaded document format exceeds the preset supported range.
- Symptom: Only 1 knowledge base matching text block is returned. Cannot comprehensively output multi-source equipment verification information. Cause: The `quoteMaxToken` parameter is not adjusted, or the recall logic does not have a multi-block merging rule configured.
- Symptom: Locally deployed model calls time out. The chat window is unresponsive. Cause: The `maxContext` parameter is set too large, exceeding the inference capacity of local hardware, or the AI Proxy service network path corresponding to `AIPROXY_API_ENDPOINT` has access restrictions.

## How to confirm configurations are correct
- Upload a single purchase order document. Verify that the equipment model output by the model exactly matches the fields in the document.
- Call the model to generate test cases. Confirm that the returned result length complies with the preset `maxTokens` parameter limit.
- View the FastGPT service startup logs. Confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` configurations are compliant, with no startup verification errors. View model call logs. Confirm that the AI Proxy service identity verification is normal, with no related errors.
- Test the multi-document upload scenario. Confirm that the model can simultaneously associate content from purchase orders and serial number lists.

The values provided are common starting points and should be measured against the reader's own samples.
