# Test Cases and Defect Analysis for Trusted Innovation Replacement Adaptation: Tool Calling and Plugins

## What Data Looks Like for This Category
Data for this category primarily comes from existing system inventories, domestic software and hardware directories, test environments, and publicly available manufacturer materials. Daily produced documents include adaptation inventories, compatibility test reports, migration plans, and issue ledgers. Fields cover software and hardware models, adaptation status, defect severity, test environment versions, and more. Data update cycles follow individual projects or quarterly cycles, and are dynamically adjusted alongside domestic adaptation progress and manufacturer version iterations.

## What Constraints Do These Characteristics Impose on the Tool Calling and Plugins Workflow
Data sources for this category are scattered but have relatively fixed formats. This requires tool calling to support integration with multiple heterogeneous data sources, while also adapting to parsing rules for structured documents such as adaptation inventories and test reports. Data update cycles follow project or quarterly units. Plugins must support regular synchronization of the latest domestic software and hardware directories and adaptation status data to avoid calling outdated information. Additionally, differences in the fields of issue ledgers require tool calling to support custom mapping rules to ensure the accuracy of retrieval and analysis.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Auto | For adaptation test scenarios, multiple types of tools need to be called dynamically. Auto mode can select tools such as adaptation inventories and issue ledgers based on context |
| `functionCall` | Enabled | Supports structured calls to defect analysis tools, facilitating automatic generation of test reports and migration suggestions |
| Stream Response Enable | Enabled | Test cases and defect analysis require real-time result returns. Enabling this setting allows synchronous display of test progress and defect localization processes |
| MCP Access Protocol | SSE | Complies with the MCP standard generated by FastGPT, and adapts to the integration requirements of third-party IDE tools |
| Knowledge Base Retrieval Scope | Only Trusted Innovation Adaptation Documents | Limits retrieval scope to documents related to trusted innovation replacement adaptation, avoiding interference from irrelevant information during analysis |
| Tool Call Timeout Threshold | 300 seconds | Adapts to the execution cycle of compatibility tests, preventing process blocking caused by overly long single tool calls |

Note: This configuration applies to FastGPT v4.17.0.

## Three Common Misconfigurations
- Symptom: Tool activation status shows as temporary, and continuous calling is not possible. Cause: Persistent synchronization rules for tool calling are not configured, and only adaptation inventory data for a single session is loaded.
- Symptom: Third-party IDE tools cannot connect to the generated MCP service. Cause: The MCP access protocol was incorrectly set to NPX mode, and the FastGPT-standard SSE protocol was not used.
- Symptom: No streaming response results are returned after calling the defect analysis tool. Cause: The stream response enable configuration is not turned on, and tool calls only return final static results, making real-time display of the defect localization process impossible.

## How to Confirm Successful Configuration
- Review tool calling logs to confirm that `toolChoice` auto mode can match the corresponding tool based on context.
- Test MCP service access to confirm that third-party tools can connect via the SSE protocol and obtain adaptation inventory data.
- Submit a defect analysis request to confirm that when stream response is enabled, segmented test progress information is returned in real time.
- Verify the knowledge base retrieval scope to confirm that only retrieval results for trusted innovation adaptation documents are returned.
