# Test Case and Defect Analysis for Informatization Budget and Project Portfolio Management: Tool Calling and Plugins

## What this category of data looks like
This category of data primarily comes from financial systems, project management systems, contract ledgers, and business department requirements. Daily generated documents include annual budget sheets, project proposal documents, project portfolio dashboards, and investment review reports. Fields include budget amount (unit: ten thousand yuan), project cycle (unit: month), priority level, revenue forecast, and more. Data update frequencies are mostly monthly, quarterly, or annual. Single batch data volume is large, and document formats exported from different systems vary: some are structured tables, others are plain text reports.

## What constraints these characteristics impose on the tool calling and plugins workflow
Decentralized data sources require tool calling to support docking with multiple system interfaces, to avoid errors caused by manual data aggregation. The need to process large batch data requires plugin configuration to support incremental pulling and segmented parsing, to prevent timeouts or context overflow. Different document formats require tool calling parameters to be compatible with multiple data structures, ensuring consistency in field parsing. Fixed update frequencies require the tool triggering logic to match the data update cycle, to avoid repeatedly pulling outdated data or missing the latest budget and project information, which would affect the accuracy of test cases and defect analysis.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| ---|---|--- |
| `toolChoice` | Set to `auto` or specify `budget_query, project_analysis` | Adapt to automatic selection of multiple tools or targeted calling of category-related data needs |
| `functionCall` | Enable parameter validation, limit incoming fields to budget amount, project cycle, and similar items | Ensure incoming business fields comply with the format and unit requirements of category data |
| Tool calling timeout duration | 300–600 seconds | Adapt to the time required for batch pulling of financial and project data, avoid timeouts caused by excessive data volume |
| Streaming return parsing switch | Enabled | Support incremental processing of large-volume budget and project documents, improve parsing efficiency |
| Knowledge base recall upper limit | Top 3–5 entries | Avoid excessive data exceeding the context window, adapt to the overall volume of category data |
| FastGPT version | v4.17.0 | Ensure compatibility with tool calling and plugin functions, adapt to the parameter rules of the current version |

## Three common configuration mistakes
- Unable to specify the target knowledge base when calling the conversation interface, and the returned results are not associated with preset budget and project data. Cause: The knowledge base association rule was not correctly configured in the request parameters, causing the tool to fail to call category-related datasets targetedly, affecting the accuracy of test cases.
- Fields in the parsed streaming return detail field are empty or formatted chaotically. Cause: Structured parsing configuration for streaming returns was not enabled, and data was split directly from raw text, failing to adapt to the multi-field structure and unit requirements of category data.
- Tool calling triggering logic is abnormal, and some project data fails to trigger tool calls. Cause: The scheduling interval of tool triggering was not adjusted based on the update frequency of category data, leading to delayed data pulling or repeated invalid calls, causing deviations in defect analysis.

## How to confirm the configuration is correct
- Initiate a simulated test call, pass in test data including budget amount and project cycle, confirm that the tool automatically calls the corresponding system interface to pull relevant data.
- View the streaming return results, confirm that the detail field is correctly parsed into structured budget and project fields, with no missing values or formatting errors.
- Check the tool calling logs, confirm that the `functionCall` parameter is correctly identified and the preset parameter validation rules are executed.
- Adjust the knowledge base recall upper limit parameter, verify that the number of returned results matches the preset value range, ensuring the context window is appropriately sized.
