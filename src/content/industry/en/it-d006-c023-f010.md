# Test Case and Defect Analysis for IT Budget and Project Portfolio Management: Citation Source and Traceability

## What Data Looks Like for This Category
The data for this category primarily comes from financial systems, project management systems, contract ledgers, and business department requirements. Test case documents and defect reports are also included as auxiliary data in the system to verify alignment between budget allocation and project requirements. Daily produced documents include annual budget sheets, project proposal documents, project portfolio dashboards, and investment review reports. Fields include budget amount, project ID, priority tags, expected revenue, and more. Data update cycles are typically monthly, quarterly, or annually. The volume of documents involved in a single update varies based on the cycle span. Core fields are mostly structured numerical values and project identifier text.

## Constraints for Citation Source and Traceability
As data sources are scattered across multiple business systems, citation traceability requires establishing cross-system metadata association rules. This ensures every cited item can be traced back to the original ledger, test case, or defect report. Since data updates follow monthly, quarterly, or annual cycles, cited source timeliness must match the business cycle. This avoids calling temporary data that has not completed updating. There are significant structural differences between document types: structured budget sheets, visual project dashboards, long-text review reports, and test case entries. The traceability link must adapt metadata extraction logic for multiple document formats to ensure accurate field matching.

## Configuration Settings
This configuration is based on the interface logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---|---|--- |
| `quoteMaxToken` | 800–1200 token | Core documents for this category include structured budget data, long-text review content, and test case entries. 800–1200 tokens cover the full context of a single key citation |
| `responseData` | Return original source metadata | Traceability for this category requires associating structured fields from financial and project management systems. Returning original metadata enables direct matching with business ledgers and test case records |
| `detail` | Enabled | Documents in this category require clear labeling of source update cycles and project IDs. Detailed traceability extracts these key details for defect and budget matching verification |
| Single search limit | Top 5 entries | Project portfolio and budget data for this category are closely linked. The top 5 high-match results cover major business association items, avoiding redundant information that interferes with test case verification |
| Context timeout | 60 seconds | Data update cycles for this category are long. A 60-second timeout accommodates response delays from cross-system association queries |
| Reranking | Calibrated via actual testing | Business terms for this category are mostly exclusive fields such as project IDs and budget codes. Reranking logic must be adjusted for these exclusive terms to improve matching accuracy |

## Three Common Misconfigurations
- Phenomenon: An unconfigured citation link list is automatically appended to the end of returned results. Cause: The default citation source display switch was not disabled, causing background logs from financial and project management systems to be output as redundant citations.
- Phenomenon: Traceability results cannot match project ID or budget amount fields. Cause: Exclusive field matching rules were not configured for structured documents of this category, and only general full-text search logic was used.
- Phenomenon: Cited content is truncated beyond the context length. Cause: The `quoteMaxToken` parameter value is smaller than the token count of a single core citation for this category, resulting in loss of key budget or test case information.

## How to Verify Successful Configuration
- Initiate a query that includes a project ID or budget amount, and check if returned results include the update time and source path of the corresponding documents.
- Review the sorting of citation results to confirm high-match project-related content is displayed first.
- Adjust the `quoteMaxToken` parameter value, and verify returned cited content covers complete business fields and test case identifiers.
- Disable the citation display switch, and confirm no redundant citation link lists are appended to the end of results.

The values provided here are common starting points and should be evaluated against the reader's own samples.
