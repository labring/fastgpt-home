# Test Case and Defect Analysis for IT Budget and Project Portfolio Management: Model Access and Configuration

## What the data for this category looks like
The core data for this category comes from financial systems, project management systems, contract ledgers, and business department requirements. Update frequencies are typically monthly, quarterly, or annually. Commonly processed documents include annual budget sheets, project proposal documents, project portfolio dashboards, and investment review reports. Document fields usually include budget amounts, project IDs, priority scores, revenue forecasts, and more. Some documents contain structured tables and multi-paragraph analysis text, with no fixed unified format template.

## What constraints do these characteristics impose on model access and configuration
Multi-source heterogeneous data sources require model access to support import and parsing of data sources in different formats. Monthly, quarterly, or annual update cycles require the knowledge base synchronization frequency to match the business update cycle, to avoid using outdated data. The mix of long text and structured documents requires the model's context capacity and segment interception rules to adapt to input content of varying lengths. Additionally, the rigor requirements of test case and defect analysis require the model's output to align with the field precision of the original data, to avoid deviations such as budget mismatches or duplicate project construction.

## How to set configurations
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | This category’s documents are mostly long-text budget sheets and review reports, which need to accommodate multiple project and budget-related data source contents to avoid context truncation |
| `maxTokens` | 2000–3000 token | The output length requirement for test case and defect analysis results is moderate, balancing output completeness and call costs |
| `quoteMaxToken` | 4000 token | Sufficient original document fragments must be retained for traceability, matching the single-page content length of budget sheets and review reports |
| `toolChoice` | auto | Allow the model to independently determine whether to call tools to supplement the latest project budget or project portfolio data |
| `temperature` | 0.3–0.5 | Test scenarios require rigorous results, to avoid deviations in budget priority judgment caused by excessive divergence |
| `AIPROXY_API_ENDPOINT` | Root address of the AI Proxy service, for example http://aiproxy:3000; do not append paths such as /v1 | Required environment variable for the App/Admin server, must match the AI Proxy server configuration |

## Three common mistakes
- Troubleshooting item: Check whether the App/Admin server has configured `AIPROXY_API_TOKEN` (AI Proxy admin token, consistent with the AI Proxy server configuration and non-empty) and `AIPROXY_API_ENDPOINT`. Missing or incorrect configuration will cause service startup verification failure or abnormal model calls.
- Symptom: A model that supports internet access is configured, but the generated test cases do not include the latest project budget data. Cause: `toolChoice` is not set to allow calling search tools, and the knowledge base update frequency does not match the monthly update rhythm of the data source.
- Symptom: Associated fragments returned when retrieving project proposal documents do not match test requirements. Cause: The `quoteMaxToken` value is not adjusted based on the document’s field length, resulting in too long or too short fragment interception.

## How to confirm the configuration is correct
- Check the environment variables deployed on the App/Admin server, confirm that `AIPROXY_API_ENDPOINT` is the root address of the AI Proxy service, and `AIPROXY_API_TOKEN` is a non-empty admin token consistent with the AI Proxy server configuration.
- Initiate a test case generation request for an annual budget sheet, and check whether the returned result contains accurate budget amount and project ID field information.
- Verify that the trigger frequency of the knowledge base update task matches the update rhythm of the data source, to ensure that the latest project portfolio data has been synchronized to the knowledge base.
- View the model call logs, confirm that the `maxContext` and `maxTokens` parameters do not trigger over-limit errors, and the call link is normal.
