# Test Case and Defect Analysis for IT Budget and Project Portfolio Management: Forms and Interactions

## What the data for this category looks like
This category's data primarily comes from financial systems, project management systems, contract ledgers, and business department requirements. Daily associated documents include annual budget sheets, project approval documents, project portfolio dashboards, and investment review reports. Data update cycles are mostly monthly, quarterly, or annual. Core fields include project number, budget amount, priority flag, revenue calculation value, and others. Units are mostly CNY, project cycle in days, and priority level. The data structure adjusts with project phases, and there is no unified fixed format.

## What constraints these characteristics impose on the "forms and interactions" link
Because data sources are scattered and document structures are inconsistent, the forms and interactions link is only responsible for collecting field inputs. Pulling fields from multiple data sources and custom mapping must be implemented separately by external business systems or subsequent nodes to adapt to format differences from submissions by different departments. Data update cycles are flexible. External business systems or subsequent nodes must be linked to dynamically load the latest budget and project information to avoid using expired data. Core business links take a long time. The form only accepts interactive inputs for priority adjustments. Preset logic for common sorting rules must be implemented separately by external business systems or subsequent nodes to simplify priority adjustment operations. At the same time, external business systems or subsequent nodes must be linked to configure field verification logic to prevent issues such as abnormal budget amounts and incorrect project number formats, reducing the risk of subsequent errors.

## Three common mistakes
- Symptom: After switching data sources, the prompt "common:core.chat | Data source connection failed" appears. Verification steps: Check whether the role permission configuration for the corresponding financial system and project management system is correct, and check whether the connection configuration for the external caching logic is valid.
- Symptom: The priority field displays empty after form submission. Verification steps: Check whether subsequent workflow nodes or external business systems have configured field mapping rules, and confirm that a corresponding relationship has been established between the fields submitted by the business department and the system's preset fields.
- Symptom: The budget amount entered in the form exceeds the reasonable range but no error prompt is triggered. Verification steps: Check whether external business systems or subsequent nodes have configured field verification logic, and confirm that the verification rules (such as the amount being a positive integer) are set correctly.

## How to confirm the configuration is complete
- Manually switch the permission scope of different roles, check whether the accessible data source list matches the configuration, and confirm that the permission configuration takes effect.
- Submit test budget data that includes abnormal amounts and incorrectly formatted project numbers, and check whether corresponding verification prompts are triggered.
- Wait for the external caching logic to expire, then refresh the page, and check whether the latest financial and project data is loaded.
- Adjust the priority sorting rules of the external system or subsequent nodes and save them, and check whether the form correctly passes the adjusted sorting results.
