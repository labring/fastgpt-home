# Test Cases and Defect Analysis for Duty Scheduling and Handover: Model Access and Configuration

## What This Category of Data Looks Like
Typical data for this category originates from SRE team scheduling systems, fault tickets, monitoring alerts, and organizational contact directories. Update frequency is daily or weekly. Daily produced documents include fixed-format duty schedules, handover records, escalation contact lists, and daily duty reports. Fields cover duty time periods, handover items, contact information, alert severity levels, and response time requirements. No additional statistical percentage data is included.

## Constraints for Model Access and Configuration
Because data sources are scattered and include multiple types of structured and unstructured documents, support for vector ingestion and context concatenation of multi-source data is required. The daily or weekly update frequency requires model configuration to adapt to the rhythm of batch data synchronization. The fixed field structure of documents such as duty schedules and handover records requires precise matching of corresponding fields for analysis when the model is called. At the same time, errors such as scheduling conflicts and missed handovers will affect business continuity, so the stability and result rigor of model calls must be ensured.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Duty-related documents include multi-day handover records, escalation paths, and complete scheduling information, requiring full context to support coherent analysis |
| `maxTokens` | `2000–3000 token` | Output length requirements for single scheduling conflict analysis or handover item sorting, to avoid truncation of critical information |
| `quoteMaxToken` | `1500–2000 token` | Need to reference complete duty schedule fragments, escalation contact lists, or historical handover records to ensure referenced content is intact |
| `toolChoice` | `auto` | Need to automatically determine whether to call tools to complete tasks such as scheduling coordination and pending item verification, adapting to multi-scenario requirements |
| `temperature` | `0.1–0.3` | Duty and handover scenarios require rigorous results, avoiding random deviations that may cause scheduling conflicts or missed handovers |
| `AIPROXY_API_ENDPOINT` | Fill in the root address of the deployed AI Proxy service, for example http://aiproxy:3000. Do not append /v1 or /chat/completions paths, and do not use it as a single-model service address | Configure as an App/Admin server environment variable, set the access root address for the AI Proxy service |
| `AIPROXY_API_TOKEN` | Configure a non-empty administrator token consistent with the AI Proxy server | Configure as an App/Admin server environment variable to complete identity verification for the AI Proxy service and ensure legitimate call permissions. Do not use application API keys, model vendor keys, or other types of tokens |

## Three Common Mistakes
- Symptom: Empty results or significantly mismatched content are returned when retrieving duty schedules or handover records. Cause: Different vector models are used locally and on the server, with mismatched embedding dimensions, resulting in misaligned vector conversion results.
- Symptom: A 400 status code is returned when calling the model, or a prompt indicates that the model does not support the current task. Cause: Model redirection rules are not configured correctly, and the actual called model cannot handle scenario tasks such as scheduling conflict analysis and handover item sorting.
- Symptom: The core process fails to start normally after updating the FastGPT service password. Cause: Corresponding modules were not restarted by service group, resulting in ineffective configuration or port conflicts.

## How to Verify Correct Configuration
- Upload a standard duty schedule document, perform vector ingestion operations, and check whether the ingestion logs of FastGPT v4.17.0 show successful embedding and matching dimensions.
- Send a test request for scheduling conflict detection, and check whether the returned result includes information about the corresponding duty personnel and coordination suggestions.
- Check the environment variable configuration on the App/Admin server, confirm that `AIPROXY_API_ENDPOINT` (AI Proxy service root address) and `AIPROXY_API_TOKEN` (AI Proxy administrator token) are correctly configured and non-empty.
- Trigger an automatic handover record sorting task, and check whether the output result includes complete pending items and escalation path information.

The values provided here are common starting points and should be evaluated against matching local samples.
