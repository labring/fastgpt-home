# Test Cases and Defect Analysis for Duty Scheduling and Handover: Forms and Interactions

## What Core Data for This Category Consists Of
Core data for this category comes from scheduling systems, fault work orders, monitoring alerts, and organizational contact lists. Update frequency is daily or weekly. Daily produced documents include duty schedules, handover records, escalation contact lists, and daily duty reports. Duty schedules contain fields for duty time slots, duty personnel, and contact information. Handover records include fields for unfinished tasks, pending escalation items, and current alert status. Escalation contact lists contain fields for job title, name, and emergency contact information. All data must align with team operational workflows to ensure fields cover all duty scheduling and item handover steps.

## What Constraints These Characteristics Impose on Forms and Interactions
Since data sources cover multiple systems and have fixed update frequencies, forms must support connecting to external data sources and synchronizing data on a scheduled basis. Different business documents correspond to different form modules. Field linkage between modules must be implemented via external business systems. The most time-consuming core links are scheduling conflict coordination, unfinished item handover, and escalation path confirmation. Therefore, verification rules must be implemented via external business systems or subsequent workflow branches to block non-compliant submissions. At the same time, data is directly linked to operational response timeliness. Form node configuration must ensure key fields are required to avoid handover omissions or response delays caused by missing information.

## Three Common Errors
- Issue: "Duplicate input information" error occurs when submitting a duty schedule form. Cause: No deduplication rules configured via external business systems or subsequent workflows, leading to duplicate submissions of the same scheduling application or handover record.
- Issue: An input error occurs during the execution of a code node after referencing the `formInput` node in a workflow. Cause: The output fields of the `formInput` node are not correctly mapped to the input parameters of the code node, resulting in missing parameters or format mismatches.
- When selecting configured options one by one in the `userSelect` node, verify whether the workflow enters the corresponding branch. For filtering duty scheduling and handover records, additionally verify the input, permissions, and return values of the external interface.

## How to Verify Correct Configuration
- Import the team's organizational contact list via the external system, and check whether the duty personnel pool in the `userSelect` node only includes internal team members.
- Submit a scheduling application with overlapping time slots, and confirm that the external business system or subsequent workflow pops up a conflict prompt and blocks the submission.
- Clear the required field for unfinished tasks after filling out the duty schedule form corresponding to the `formInput` node, and confirm that the `formInput` node blocks form submission and displays a field missing prompt.
- Fill out and submit the duty schedule form corresponding to the `formInput` node, and check whether the subsequent workflow can normally obtain all field data collected by the `formInput` node.
