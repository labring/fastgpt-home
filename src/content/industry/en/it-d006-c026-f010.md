# Test Cases and Defect Analysis for Level Content Creation: Citation Sources and Traceability

## What the Data for This Category Looks Like
The daily data sources for level content creation teams include level editors, art resource libraries, player test data, and defect systems. Daily produced documents include level design drafts, resource requirement sheets, test feedback forms, and version submission records. Level design drafts contain fields such as path nodes, trigger conditions, and resource IDs. Test feedback forms record defect severity and reproduction steps. Data is updated weekly or with each version iteration, and content is dynamically adjusted based on level debugging progress.

## Constraints on Citation Sources and Traceability
Dispersed data sources require associating reference information across multiple systems, to ensure traceability covers the full workflow of level design, resource calls, and test feedback. Frequent update cycles require traceability logic to match the latest version submission records, to avoid referencing outdated content. Diverse document structures require support for identifying and associating source files in different formats. Errors in level content directly affect launch timelines, so traceability must ensure the accuracy and completeness of citations, and avoid missing key test basis.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Matches the length of single entries in level design drafts and test feedback forms, to avoid truncating critical citation information |
| `responseData` | `Enabled` | Must return original citation file paths and version numbers, to meet the traceability requirements of defect systems |
| `detail` | `true` | Fully returns reproduced steps and resource IDs of citations, to support defect localization for test cases |
| Citation source sorting rule | Sorted in descending order of version submission time | Aligns with the version iteration logic of level content creation, prioritizing the most recently submitted citation content |
| Single search limit | `Top 3 entries` | Avoids excessive citations cluttering core information for level debugging, meeting the focused needs of test cases |

## Three Common Configuration Errors
- Issue: FastGPT v4.17.0 returns citation content without the citation switch enabled. Cause: This version enables citation logic for some scenarios by default, and does not separately turn off redundant citation configuration for test case scenarios.
- Issue: The citation files output by the knowledge base do not match the actual test cases. Cause: The version submission records of the level editor are not associated as traceability basis, leading to matching outdated versions of resources or design drafts.
- Issue: Streaming responses cannot parse call parameters and citation content simultaneously. Cause: The `responseData` parameter is not correctly bound, and call parameters are not associated with the citation traceability workflow.

## How to Confirm Successful Configuration
- Submit a test case query containing level path nodes, and verify that returned results include the file name and version number of the corresponding level design draft
- Enable the `detail` parameter, and check that returned content includes the reproduction steps of the defect and the corresponding resource ID
- Adjust the value of `quoteMaxToken`, and verify that critical defect descriptions in test feedback forms are not truncated
- Confirm that the citation switch for FastGPT v4.17.0 is only enabled in test scenarios, to avoid unnecessary citations cluttering output

The values provided are common starting points and should be measured against the reader's own samples.
