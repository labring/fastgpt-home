# Test Cases and Defect Analysis for Level Content Creation: Model Access and Configuration

## What Data Looks Like for This Category
Data for this category primarily comes from level editors, art resource libraries, player test data, and defect systems. Daily produced documents include level design drafts, resource requirement sheets, test feedback forms, and version submission records. Fields cover level ID, resource path, test case number, defect severity level, submission time, and more. Data updates follow weekly or per-version cycles. Updates occur in real time or in batches alongside level iterations, test feedback, and version submissions. Data formats vary across different sources.

## Constraints Imposed on Model Access and Configuration
The data for this category is scattered across multiple systems and documents. Format differences between sources increase format adaptation difficulty during model access. Weekly or per-version update cycles require flexible adjustment of the configured context window. This adjustment matches test data volumes across different cycles. Multi-field association logic in documents and data requires enabling corresponding association retrieval capabilities in model configurations. This ensures test case generation and defect analysis match key information such as level ID and resource path. Real-time requirements for test feedback forms and defect systems also demand configuring reasonable request frequencies. This avoids exceeding interface limits and ensures timely data processing.

## How to Configure Settings
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `AIPROXY_API_ENDPOINT` | Configure as the root address of the AI Proxy service, including the full protocol and port. Do not append `/v1` or model interface paths | Required environment variable for the App/Admin server. Ensures model requests are properly forwarded to the AI Proxy service |
| `AIPROXY_API_TOKEN` | Configure as the administrator token matching the AI Proxy server. Cannot be empty | Required environment variable for the App/Admin server. Ensures access authentication security for the AI Proxy service |
| `maxContext` | 8000–12000 token | Adapts to the context length of multiple documents such as weekly or per-version test feedback forms and level design drafts. Prevents truncation of critical test information |
| `maxTokens` | 2000–3000 token | Controls the output length of single-round test case generation or defect analysis. Adapts to detailed description requirements for level content |
| `temperature` | 0.3–0.6 | Balances standardization and flexibility of test cases. Prevents generation of overly divergent or overly rigid level test content |
| `toolChoice` | auto | Automatically selects whether to call retrieval tools. Adapts to association analysis requirements for multi-source data |

## Three Common Configuration Mistakes
- Symptom: The model output does not include the thought process, and only returns the final test case. Cause: The model's thought process display configuration is not enabled, or the output format does not include requirements for intermediate steps.
- Symptom: The deployment fails to connect to the AI Proxy service. Logs show address resolution failure or authentication failure. Cause: The server environment variable `AIPROXY_API_ENDPOINT` is not correctly configured, or the `AIPROXY_API_TOKEN` configuration is incorrect.
- Symptom: Rerank model call fails, returning a model incompatibility prompt. Cause: The adapted rerank model is not specified in the configuration, or an unsupported model type such as gte-rerank-v2 uses an incorrectly configured call path.

## How to Verify a Successful Configuration
- Send a test request, input a segment of a level design draft. Check if corresponding test cases can be generated, and if the output style matches the performance corresponding to the configured temperature parameter.
- View server startup logs and model call logs. Confirm that the AI Proxy connection is normal, with no prompts for authentication or address errors.
- Submit test data containing multi-field association information. Check if the model can correctly associate level IDs with corresponding defects and resource information, and generate targeted analysis results.
- Test input of long context. Confirm that the `maxContext` configuration does not trigger content truncation, and that the output is complete and covers critical test information.

The values provided are common starting points and should be measured against the reader's own samples.
