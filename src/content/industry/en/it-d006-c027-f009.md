# Test Cases and Defect Analysis for Content Review Rule Operations: Tool Calling and Plugins

## What Data for This Category Looks Like
Data for this category originates from the content review backend, user reporting channels, public regulations and policies, and internal sample libraries.
Daily maintained documents include review rules, disposal guidelines, appeal records, and quality inspection reports.
Review rule documents contain fields for rule ID, trigger threshold, matching logic, and effective time.
Appeal records contain fields for appeal ID, involved content, original review result, and review opinion.
Data is updated daily, or immediately when industry regulations or platform policies change.

## Constraints Imposed on the Tool Calling and Plugins Workflow
The data sources for this category are scattered, with flexible update schedules. This requires tool calling to support real-time pulling of the latest review rules and policy documents, to avoid using expired configurations.
Documents include both structured fields and unstructured sample text. Plugins must support structured parameter queries and compliance text analysis.
Appeal records and quality inspection reports contain sensitive content. Tool calling must include a permission isolation mechanism.
The high-frequency daily update requirement means the local cache period for tool calling must not exceed 24 hours, to ensure rules take effect immediately after being updated.
Additionally, the time-intensive nature of rule interpretation and difficult sample judgment requires tool calling response times to align with the work rhythm of the operations team.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` or bound to the review rule query plugin | Adapts to automatic tool selection and specified rule calling requirements in content review scenarios. FastGPT v4.17.0 supports this parameter configuration |
| `functionCall` | Enable structured output | Facilitates direct parsing of structured fields from review rules into executable parameters, improving the efficiency of rule matching and defect localization |
| Tool call timeout | `15–30 seconds` | Matches the typical response time for review rule queries and difficult sample analysis, preventing operational process freezes |
| Plugin cache period | `24 hours` | Aligns with the daily update frequency of data in this category, ensuring rule changes are synchronized and take effect promptly |
| Concurrent call limit | `3` | Controls the call pressure on the content review backend interface, avoiding triggering platform rate limits |

## Three Common Mistakes
- Phenomenon: When calling models other than the Tongyi Qianwen series, the interface returns the `invalid function call format` error. Cause: Some models do not fully comply with the `functionCall` format requirements, and the model's support for structured output of this parameter was not confirmed before configuration.
- Phenomenon: No intermediate thought process output is generated after calling a custom review rule query plugin. Cause: The thought log switch for tool calling was not enabled, or the plugin was not configured to return intermediate step fields.
- Phenomenon: Review rule document content cannot be retrieved when calling a document reading plugin. Cause: The plugin's document permission scope was not configured, or the document path parameter does not match the actual storage path.

## How to Confirm Configuration Is Complete
- Submit test content containing violation keywords, call the review rule query plugin, and verify whether the returned result hits the currently effective trigger threshold.
- View the tool call log, confirm that the `toolChoice` parameter automatically selects the corresponding plugin according to the configuration, or that the specified plugin was successfully called.
- Check the plugin cache refresh record, confirm that the time since the last update does not exceed 24 hours, ensuring that rule changes have been synchronized.
- Initiate more than 2 concurrent calls, confirm that no interface rate limit error is triggered.

The values provided here are common starting points and should be measured against the reader's own samples.
