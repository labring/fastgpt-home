# Test Cases and Defect Analysis for Content Moderation Rule Operations: Citation Sources and Traceability

## What This Category of Data Looks Like
Data in this category primarily comes from content moderation backends, user reporting channels, public regulatory policies, and compliance sample libraries. Daily produced documents include moderation rules, disposal guidelines, appeal records, and quality inspection reports. Document fields include rule identifiers, trigger conditions, processing workflows, appeal statuses, and other related items. Data update frequency is either daily synchronization or immediate updates when policies change. The size of individual data entries varies based on the complexity of moderation scenarios, with no fixed statistical standard.

## What Constraints Do These Characteristics Impose on the Citation Sources and Traceability Workflow
This category’s data characteristics impose multiple constraints on the citation sources and traceability workflow.
First, data sources are scattered across multiple channels including moderation backends, user reports, and policy documents. Unique identifiers for corresponding sources must be linked during citation to enable rapid location of original data nodes during traceability.
Second, update frequency is not fixed: either daily synchronization or immediate updates when policies change. Effective timestamps for data must be included in traceability information to prevent use of expired moderation rules.
Third, daily document types are diverse, including moderation rules, disposal guidelines, appeal records, and more. Citation formats must be differentiated for different document types to ensure traceability information can be quickly recognized.
Fourth, individual data entry size fluctuates based on scenario complexity. Character length of single citations must be limited to avoid exceeding the context capacity limits of large language models.

## How to Configure
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | Aligns with the typical character length of individual moderation rules and appeal records in this category, avoiding exceeding large language model context thresholds |
| `responseData` | Includes source identifier and effective time fields | Meets the requirement to link original data nodes and effective timestamps during traceability |
| `detail` | Enable full field return | Ensures complete information such as moderation rule trigger conditions and appeal record processing results can be obtained during citation |
| Single search limit | Top 10 entries | Covers typical sample volumes for daily moderation scenarios, avoiding interference from redundant data |

## Three Common Misconfigurations
- Symptom: When `quoteMaxToken` is set to 3000, large language models cannot access context content. Cause: Individual data entry size in this category fluctuates significantly, and 3000 tokens exceeds the context capacity limits of most large language models, causing the system to truncate citation content.
- Symptom: Returned citation content does not include source identifiers and effective timestamps. Cause: The `responseData` configuration is not enabled, and required source-related fields are not specified, resulting in missing original data metadata during citation.
- Symptom: Using HTTP response data as a knowledge base citation has no effect. Cause: Response data is not converted to a structured format compliant with platform requirements, and no corresponding source identifier is linked, resulting in the system being unable to recognize valid citation content.

## How to Verify Successful Configuration
- Submit a query related to moderation rules, and check whether the returned results include source identifier and effective time fields.
- Adjust the value of `quoteMaxToken` to verify whether large language models can normally receive and use citation content.
- Upload a test moderation rule document, and confirm that complete trigger conditions and applicable scenario information from the document can be obtained during citation.
- Call the specified interface to verify that the returned `responseData` field includes preset source and metadata information.

The values provided are common starting points and should be evaluated against the reader’s own samples.
