# Test Cases and Defect Analysis for Content Recommendation Operations: Citation Sources and Traceability

## What the data for this category looks like
The core data for content recommendation operations mainly comes from the content tag library, user behavior logs, the recommendation experiment platform, and the recommendation backend. Daily produced documents include recommendation strategy records, content pool lists, experiment reports, and operation reviews. The data update frequency is usually daily or weekly. The content pool list includes content unique identifiers, classification tags, and distribution weight fields. Experiment reports record experiment groups, changes in core metrics, and user feedback data.

## What constraints these characteristics impose on the "citation sources and traceability" link
The content pool list is updated daily or weekly. Citation traceability must match the latest content identifiers and classifications to avoid citing expired content. The field structures of experiment reports and operation reviews are fixed. During traceability, the original data sources corresponding to the experiment groups must be associated. User behavior logs and content tag data have large volumes. When citing, scope must be limited to avoid exceeding context carrying capacity. Data formats from different sources vary. They must be uniformly converted to a traceable standard format to ensure cited content can be quickly verified.

## How to set the configurations
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the length of single entries in content pool lists and experiment reports |
| `responseData` | Includes source file path and content classification fields | Ensures returned results carry traceable content identifiers and source paths |
| `detail` | Enabled | Displays complete citation source information, including content tags and experiment groups |
| Single search limit | Top 8 entries | Adapts to the daily updated content pool data volume, avoids query overload |
| Maximum context | 6000 characters | Accommodates associated data from multiple experiment reports and operation reviews |

## Three common mistakes
- Phenomenon: Returned cited content cannot be downloaded directly, and the interface displays the "Resource Unavailable" error. Cause: The source file path mapping in the `responseData` configuration is not enabled, causing traceability links to point to invalid temporary addresses.
- Phenomenon: Exported traceability data only includes knowledge base dimensions, and cannot be split by content classification or business tags. Cause: The configuration does not associate the classification fields of the content pool, and only exports the overall knowledge base data by default.
- Phenomenon: No citation source is returned after calling the online tool, and the corresponding field in the interface return is empty. Cause: The `detail` configuration item is not enabled, causing associated experiment platform and user behavior log data to not be loaded.

## How to confirm the configuration is correct
- Initiate a test question and answer based on the recommendation strategy, check whether the returned results include clear citation source identifiers.
- Call the interface to obtain the question and answer results, verify whether the `responseData` field carries complete source content paths and classification information.
- Trigger a traceability query for content pool data, confirm that the returned results can be filtered by business tags or experiment groups.
- Test the download function of cited content, confirm that source data files can be accessed normally.

The values provided here are common starting points and should be evaluated against the reader's own samples.
