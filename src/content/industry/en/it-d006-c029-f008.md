# Test Cases and Defect Analysis for Content Copyright and Authorization Management: Workflow Orchestration

## What This Category of Data Looks Like
This category of data mainly comes from contract systems, copyright registration databases, content material libraries, and infringement complaint inboxes. Daily processed documents include authorization contracts, copyright ledgers, removal notices, and infringement complaint materials. Data updates follow single-order or monthly cycles. Each individual data entry contains fields such as authorized subject, authorization scope, valid period, and infringement-related content. Most fields use text or date format. Individual data entries are small in size but have complex association relationships, requiring reliance on multi-source data for association and verification.

## Constraints Imposed by These Characteristics on the Workflow Orchestration Link
Data sources for this category are scattered, so workflow configuration needs to include pull nodes across multiple sources including contract systems and copyright registration databases. Update cycles are primarily single-order or monthly, so two operation modes must be supported: on-demand triggering and scheduled scheduling. Daily documents are mostly semi-structured text, so workflow nodes must adapt to text parsing and field extraction operations. Fields such as authorization scope and valid period are directly linked to compliance risks, so a compliance verification link must be embedded. Infringement complaint materials must be associated with corresponding content library materials, so a mapping link between content and complaint information must be configured to avoid compliance issues caused by incorrect associations.

## How to Configure Settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Global variable initialization | Preset `variables` using core fields from authorization contracts and copyright ledgers | Covers the core data fields of this category, avoiding missing key information during runtime |
| Node trigger condition | Trigger upon completion of a single order or on the 1st day of each month | Matches the single-order or monthly update frequency of this category, reducing invalid runs |
| Variable splicing rule | Only retain the output content of the current node, do not overlay historical variable results | Avoids anomalies caused by overlaying multiple rounds of output content, aligns with business data splicing logic |
| Exception alert node | Set trigger threshold to authorization scope verification failure and timeout of `600 seconds` | Covers core error scenarios of this category, timely intercepting compliance risks |
| Workflow timeout setting | Set timeout period to `300–600 seconds`, calibrated based on actual testing | Adapts to the time consumption requirements of multi-source data pulling and text parsing |
| Content association mapping | Associate content library material IDs with infringement identifiers from complaint inboxes | Meets the association requirement between infringement materials and corresponding content |

## Three Common Misconfigurations
- Phenomenon: After the workflow runs, the last variable value in the output overlays the content of previous variables. The `output` field displayed in the interface contains duplicate historical text. Cause: The splicing rule for `variables` was not configured correctly, and the historical variable overlay logic was enabled by default.
- Phenomenon: An insufficient permissions prompt appears when exporting the workflow, and the configuration file cannot be downloaded. Cause: The export permission for the workflow was not enabled, or the access permission for the export node was not configured.
- Phenomenon: After passing parameters via the API access link, the global variables are not updated, or the interaction node does not respond. Cause: The modifiable permission for global variables was not configured in the workflow, or the correct `nodeId` parameter was not carried.

## How to Verify Correct Configuration
- Run a test workflow, check that the `variables` field in the output only contains valid content from the current node, with no historical variable overlay.
- Attempt to export the workflow configuration file, confirm that it can be downloaded normally and contains complete nodes and parameter configurations.
- Pass test parameters via the API access link, confirm that the global variables are correctly updated to the passed values.
- Add an interaction node in the MCP configuration, run the workflow, confirm that a user input prompt box pops up in the interface to verify that the node is active.

The values provided are common starting points and should be measured against the reader's own samples.
