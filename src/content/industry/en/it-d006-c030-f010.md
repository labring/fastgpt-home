# Test Cases and Defect Analysis for Internal Network and WiFi Operations: Source Citation and Traceability

## What data for this category looks like
The data for this category primarily comes from switch consoles, wireless controllers, office network monitoring systems, and frontline user trouble reports. Daily maintenance documents include network topology diagrams, change tickets, fault records, and wireless coverage inspection forms. Fields cover port numbers, VLAN identifiers, signal strength, fault occurrence times, and disposal results. Data is updated daily or after each network change. Individual document sizes range from hundreds of characters to tens of megabytes.

## Constraints imposed by these characteristics on source citation and traceability
Data sources are scattered and mostly in native formats of operation and maintenance tools. Citation and traceability must support metadata extraction from both structured and unstructured documents. Uncertain update frequencies require traceability logic to dynamically match latest change records and inspection data. Wide variations in document size demand chunking strategies that adapt to both long topology diagrams and short fault tickets, while accurately associating fault records with configuration data from corresponding network nodes. Additionally, traceability in operation and maintenance scenarios requires strict matching of precise fields such as ports and VLANs, to avoid traceability deviations caused by generalized matching.

## How to configure settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 characters | Adapts to the single-block content length of operation and maintenance documents, avoids truncating critical port configurations or fault details |
| `responseData` | Enable citation detail mode | Ensures returned traceability data includes document source paths and metadata fields |
| Similarity threshold | 0.75–0.85 | Meets the need for precise field matching in operation and maintenance scenarios, avoids interference from low-correlation network data |
| Single search limit | Top 3 results | Focuses on core fault records and topology data, reduces redundant information |
| `detail` | Enable full metadata return | Extracts key fields such as VLAN and port numbers from documents for precise traceability |

## Three common configuration errors
- Symptom: API call responses do not include citation details, and no citation module is displayed in terminal output. Cause: The `responseData` citation detail configuration is not enabled, or the knowledge base variable is not correctly bound to the corresponding operation and maintenance document library.
- Symptom: Search results match irrelevant historical fault records, and cannot accurately locate current network nodes. Cause: The similarity threshold is set too low, leading to generalized matching of documents with non-target fields.
- Symptom: Chunked content of long network topology diagrams is incorrectly truncated, and critical VLAN configuration information is lost during traceability. Cause: Chunking strategies are not adjusted based on the structure of operation and maintenance documents, and general title separators cause topology blocks to be split.

## How to verify correct configuration
- Initiate a test API call, check whether the returned results include citation source information under the `responseData` field.
- Manually enter known fault record keywords, verify that matching fields in search results include precise identifiers such as ports and VLANs.
- View the preview content of chunked knowledge base documents, confirm that long documents are not incorrectly split and key configuration information is not lost.
- Compare the `detail` field returned by the API with metadata from original documents, ensure extracted fields match those in operation and maintenance documents.

The values provided are common starting points and should be measured against the reader's own samples.
