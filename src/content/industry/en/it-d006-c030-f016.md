# Test Cases and Defect Analysis for Internal Network and WiFi Operations: Forms and Interactions

## What this category of data looks like
Data for this category primarily comes from switch consoles, wireless controllers, office monitoring systems, and frontline user trouble ticket channels. Daily produced documents include network topology diagrams, network change orders, incident records, and wireless coverage inspection forms. Fields cover device port numbers, VLAN configurations, signal strength, trouble report time and location, with units including ports, dBm, hours, counts, and others. Data update frequency is daily updates or immediate synchronization upon network changes.

## What constraints do these characteristics impose on the forms and interactions stage
Scattered data sources, diverse document types, and flexible update cycles create multiple constraints for the forms and interactions stage.
Multi-channel data sources require cross-system import functionality via external business systems or subsequent workflows, to support file formats exported by different devices.
Wide variation in fields across document types requires external business systems or subsequent workflows to support custom field groups, to match entry requirements for different documents such as topology diagrams, change orders, and inspection forms.
High-frequency updates require external business systems or subsequent workflows to have real-time validation capabilities, to prevent entry of expired or conflicting configuration information.
Long fault localization time requires external business systems or subsequent workflows to preconfigure common tags, to reduce manual entry costs.

## Three Common Mistakes
- Phenomenon: After importing or entering data, the number of returned analysis results does not match the preset value. Cause: Data filtering range parameters are not configured in the external business system or subsequent workflow, causing processed raw data to exceed expected bounds.
- Phenomenon: After importing a CSV file exported from a switch, some fields cannot be recognized normally. Cause: Field mapping rules are not configured in the external business system or subsequent workflow, making it impossible to match imported data with non-standard column names.
- Phenomenon: The signal strength field in the wireless coverage inspection form cannot accept dBm units. Cause: Unit entry rules are not configured in the external business system or subsequent workflow, only allowing the default pure numeric field format.

## How to Confirm Configurations Are Correct
- Import a standard wireless coverage inspection form CSV file, check whether fields are displayed correctly according to preset groups, and confirm that the custom field group configuration takes effect.
- Enter a common fault trouble report, select a preset tag, check whether the external business system receives and processes the selected device tag, and confirm that the interaction trigger logic of the user select node (`userSelect`) works normally.
- Submit a test form, check whether the defect analysis results returned by the external business system cover the preset fault types, and confirm that the data processing rule configuration meets expectations.
- Try to import more documents than the preset batch size, check whether the external business system triggers a reasonable intercept prompt, and confirm that the import restriction configuration takes effect.
