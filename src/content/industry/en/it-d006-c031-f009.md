# Test Cases and Defect Analysis for Creator Onboarding and Certification: Tool Calling and Plugins

## What this category of data looks like
Data for this category centers around creator onboarding and identity verification. Daily documents include onboarding applications, identity qualification materials, certification audit records, and cooperation agreements. Data sources cover creator backends, enterprise credit information platforms, account history databases, and contract systems. Update frequency is daily or triggered upon submission of individual applications. Fields include application identifiers, qualification types, audit statuses, cooperation binding information, and more. There are no unified fixed units; values adjust according to the field rules of corresponding documents.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
This category of data is multi-source, scattered, and updated per individual application. This requires tool calling to support integration with multiple types of data sources such as creator backends and enterprise credit information platforms, and adapt to on-demand triggered execution rhythms. Core links including qualification verification and account risk judgment rely on multi-field combined verification. Tool calling must integrate multi-dimensional data inputs to avoid verification failure caused by single-source data deviation. Data is associated with cooperation agreements and benefit distribution, so the output of tool calling must strictly match the document field format to prevent errors such as benefit misalignment. Additionally, since error consequences involve false certifications and cooperation disputes, tool calling must add pre-verification and failure fallback mechanisms.

## Configuration Settings
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapt to different types of onboarding applications, automatically select corresponding tools such as qualification verification and account risk judgment |
| `functionCall` | Enable and restrict tool scope | Only allow calling qualification verification and credit query tools to avoid unauthorized call risks |
| Single tool call timeout | 300-600 seconds | Qualification verification requires connecting to multiple data sources, and time consumption fluctuates; this interval covers most normal scenarios |
| Tool call result cache duration | 1 day | Match the update frequency of daily data or per application, to avoid discrepancies between cached data and latest qualification information |
| Tool call failure retry count | 2-3 times | Avoid call failures caused by temporary network fluctuations or temporary unavailability of data sources |
| Input field mapping rules | One-to-one correspondence with onboarding application document fields | Strictly match the field formats of onboarding applications and qualification materials to ensure accurate input data for tool calls |

## Three Common Mistakes
- Phenomenon: When cyclic AI sessions are used to process qualification material arrays, tool call input fields are empty or have abnormal formats. Cause: The qualification material array in the onboarding application is not correctly mapped to cyclic input parameters, causing the loop body to fail to read corresponding data.
- Phenomenon: Integrated plugins cannot link normally with chat applications, and tool calls have no response. Cause: No parameter mapping rules between chat applications and tool calls are configured, causing application data to fail to be correctly passed to plugins.
- Phenomenon: Tool calls return errors such as "Failed to get the VQD". Cause: No pre-verification is performed on query parameters, and unprocessed creator account names are directly used as query terms, triggering tool interface exceptions.

## How to Verify Correct Configuration
- A test onboarding application is submitted, and tool calls are verified to automatically trigger the corresponding process without abnormal interruptions.
- Tool call logs are reviewed to confirm that only authorized configured tools are called, with no records of unauthorized tool calls.
- A scenario where data sources are temporarily unavailable is simulated, and tool calls are verified to trigger the retry mechanism and execute normally after recovery.
- Fields in tool output are compared to onboarding application document fields to confirm full matching, with no missing items or format deviations.

The values provided are common starting points and should be measured against corresponding local samples.
