# Test Cases and Defect Analysis for Creator Onboarding and Verification: Citation Sources and Traceability

## What the Data for This Category Looks Like
Core data for this category centers on creator access and identity verification. Daily documentation includes onboarding application forms, identity qualification document scans, certification audit logs, cooperation framework agreements, and related materials. Data originates from information submitted via creator backends, third-party enterprise credit query APIs, account historical behavior records, and enterprise contract management systems. Data update frequency is triggered by the application process: full-link data updates for a single application occur daily or sync in real time. A single data entry includes applicant identity fields, qualification numbers, audit status, associated contract numbers, and other fields. Fields adjust based on the application category, with no unified fixed unit.

## Constraints on Citation Sources and Traceability
Citation traceability for this category requires binding multi-source heterogeneous data. Variations in data formats across sources mean the traceability chain must support two data types: unstructured qualification documents and structured audit records. Per the update schedule tied to application submissions, traceability queries must pull the latest audit status and qualification materials in real time, to prevent expired data from impacting audit results. The multi-field association structure demands that traceability parameters accurately match association keys such as applicant ID and contract number, to avoid qualification verification errors caused by misaligned traceability results. Additionally, the risks of false certification require the traceability chain to retain complete call logs and source credentials, to support subsequent compliance verification and dispute resolution.

## How to Set the Configuration
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| Maximum Citation Source Token Count | 800–1200 token | Adapts to the content length of multiple document types including qualification materials and audit records |
| Returned Data Included Fields | Only return associated application ID, qualification number, audit status | Avoids redundant data occupying context space |
| Detail Return Toggle | Enabled | Used to parse complete traceability source information |
| Traceability Log Storage | Retain for 7 days | Meets the basic cycle requirement for audit review |
| Association Matching Fields | Applicant ID, contract number | Accurately binds the association relationship between multi-source data |
| Request Timeout | 30–60 seconds | Adapts to response delays from cross-system queries |

## Three Common Mistakes
- Phenomenon: In FastGPT v4.17.0, traceability source content is still returned when the citation return configuration is not enabled. Cause: The logic of the detail return toggle is not correctly bound, and the configuration is not synchronized to the streaming return link.
- Phenomenon: The traceable reference files output by the knowledge base do not match the actually submitted creator qualification materials. Cause: The association matching field configuration is incorrect; applicant ID is not used as the association key, resulting in data misalignment.
- Phenomenon: When calling the knowledge base API, the traceability data structure returned after the configuration is enabled cannot be parsed correctly. Cause: Associated information is not extracted according to the returned data format fields specified in the configuration, and nested source fields are omitted.

## How to Confirm the Configuration Is Correctly Set
- Submit a test creator onboarding application, check whether the expected traceability source fields are included in the returned results, and verify that the association matching fields take effect.
- Check the system logs to confirm that the traceability request carries the correct configuration parameters, with no omissions or incorrect values.
- Toggle the state of the detail return switch, and verify whether the returned traceability content changes synchronously with the configuration.
- Simulate cross-system data query, and confirm that the returned qualification materials match the submitted application information.
