# Test Cases and Defect Analysis for Creator Incentive Settlement: Tool Calling and Plugins

## What the data for this category looks like
Core data for creator incentive settlement comes from content production data, the advertising revenue sharing system, the financial accounting system, and the creator account backend. Daily archived documents include incentive rules, settlement detail ledgers, appeal processing records, and payment lists.
Data updates are triggered by monthly settlement cycles or single activities. Each settlement batch corresponds to an independent data set.
Fields include creator unique identifier, content production volume, revenue sharing coefficient, payable amount, appeal number, and payment status. There is no unified cross-system field format. Adaptation is required for each connected system.

## What constraints these characteristics impose on the tool calling and plugins workflow
Since data sources cover multiple heterogeneous systems, tool calling must adapt to the authentication rules and return formats of different interfaces. A single universal calling logic cannot be used.
Data updates occur monthly or per activity cycle. Context caching for tool calling must be reset per batch to avoid cross-batch data confusion.
Settlement documents contain sensitive personal revenue information. Tool calling output must include field desensitization processing to prevent sensitive data leaks.
Settlement detail fields are closely related. Tool calling parameters must precisely match the field names of the corresponding system to avoid settlement errors caused by parameter misalignment.

| --- | --- | --- |
| `toolChoice` | Specify the corresponding tool according to the settlement scenario | Adapt to tool calling requirements for different settlement stages. | `functionCall` | Force specification of settlement detail fields as calling parameters | Ensure tool calling accurately matches the field structure of settlement data, and avoid result abnormalities caused by parameter misalignment |
| Stream output control | Disable stream output | Ensure settlement results are returned in a single batch, and avoid variable superposition issues caused by segmented output |
| MCP tool connection timeout | Calibrate based on actual testing (120-180 seconds) | Adapt to the response duration of slow interfaces such as financial systems, and avoid settlement verification interruptions caused by timeouts |
| Tool calling log switch | Enable only in debug mode | Reduce redundant log output in production environments, and improve result viewing efficiency |

## Three common mistakes
- Phenomenon: The payable amount field returned by tool calling superposes historical results from previous calls. Cause: Stream output function is not disabled. Segmented returned content is spliced into a single variable, leading to residual historical data.
- Phenomenon: The tool calling module continuously outputs runtime logs. Cause: The log switch for the production environment is not turned off, resulting in redundant records generated for each call.
- Phenomenon: The MCP tool cannot establish a connection, and returns a connection timeout error. Cause: Authentication rules for different systems are not adapted, or the timeout setting is too short, making it incompatible with slow-response interfaces such as financial systems.

## How to confirm correct configuration
- Initiate a single tool calling request, and check that the returned result only includes detailed data for the target settlement batch, with no redundant logs or residual historical data.
- Check the output content of the tool calling, and confirm that only the settlement result after tool execution is returned, with no splicing issues from segmented stream output.
- Call the MCP tool to connect to the financial system interface, wait 150 seconds, and confirm that the connection is successful and correct settlement data is returned.
- Verify that the `toolChoice` parameter matches the tool for the current settlement scenario, and ensure that the interface of the corresponding system is called.
