# Test Cases and Defect Analysis for Creator Incentive Settlement: Model Access and Configuration

## What the data for this category looks like
Core data for creator incentive settlement comes from content data, advertising revenue sharing systems, financial systems, and creator account backends. Daily associated documents include incentive rules, settlement details, appeal records, and payment lists.
Data updates occur monthly or per single activity cycle. Fields include creator unique identifier, revenue calculation standards, settlement cycle, appeal status, payment amount, and more. Units include yuan, items, days, and others.
Data structure changes as activity rules are adjusted. Batch data volume fluctuates with the scale of participating creators. Cross-system field alignment and format verification requirements must be addressed.

## What constraints these characteristics impose on model access and configuration
Data sources for this category are scattered, and structures are flexible. Model access configuration must support cross-system field identification and alignment to avoid settlement standard deviations.
Data update rhythms are inconsistent. Configuration must adapt to one-time batch data processing and periodic verification scenarios.
Fields for settlement details and appeal records must strictly match business rules. The format and field completeness of model output directly impact subsequent settlement processes.
Abnormal fraud investigation and payment material verification have high accuracy requirements for models. The randomness of model generation must be limited to prevent settlement disputes or incorrect/missed payments.

## How to set the configuration
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Adapts to context capacity needs for multi-system aggregated data such as batch settlement details and appeal records, prevents field loss from long text truncation |
| `maxTokens` | `2000–3000 token` | Meets output length requirements for single-settlement analysis and fraud investigation, covers display of all required business fields |
| `quoteMaxToken` | `1500 token` | Retains core fragments of reference documents including incentive rules and payment lists, ensures models can access complete rule details during verification |
| `toolChoice` | `auto` | Enables models to independently determine whether to call tools for cross-system data alignment, adapts to flexible needs of different settlement scenarios |
| `temperature` | `0.1–0.3` | Reduces randomness of model generation, ensures output accuracy for revenue standard verification and payment verification steps, avoids deviations in rule interpretation |
| `AIPROXY_API_ENDPOINT` | `Root address of AI Proxy service, for example http://aiproxy:3000` | Root address of the AI Proxy service. Do not append /v1 or /chat/completions paths. This is a non-single-model service address |

## Three common mistakes
- Phenomenon: Multimodal model calls return format errors, with prompts indicating images do not meet requirements. Cause: The `vision` parameter is not configured to adapt to input verification for settlement voucher images, so the model cannot correctly identify image information in payment materials.
- Phenomenon: No fallback mechanism triggers after a model call fails, and batch settlement tasks stop immediately. Cause: Multi-model switching configuration is not enabled, so standby models cannot be automatically called to complete tasks when the primary model is unstable.
- Phenomenon: Deviations appear in revenue verification results generated by the model, leading to creator appeals. Cause: The `temperature` parameter is set too high, causing random deviations in the model's interpretation of incentive rules and incorrect calculation of revenue standards.

## How to confirm the configuration is correct
- Import a single standard settlement detail data set, run a model verification task, and check if the output includes required business fields such as creator ID, revenue amount, and settlement cycle.
- Simulate a batch data interface call, observe response duration and return status, and confirm no obvious timeouts or format errors occur.
- Adjust the `temperature` parameter to 0.1 and 0.3 respectively to run rule verification tasks, compare consistency between the two output results, and verify accuracy control effects.
- Check server startup logs, confirm no startup verification failures are triggered by missing or invalid `AIPROXY_API_TOKEN`.

The values provided are common starting points and should be evaluated against the reader's own samples.
