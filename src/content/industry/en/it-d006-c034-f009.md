# Test Cases and Defect Analysis for Office System Workflow Configuration: Tool Calling and Plugins

## What this category of data looks like
This category of data typically originates from internal enterprise OA systems, organizational directories, existing system documents, and frontline business user feedback. Regularly produced documents include workflow configuration sheets, approval node tables, form field descriptions, and change records.
Workflow configuration sheets record approval node order, trigger conditions, and permission binding rules. Approval node tables list responsible persons and transfer requirements for each node. Change records retain modification timestamps and operator information. Data updates are triggered by workflow configuration changes, with an average of multiple adjustments per month.

## Constraints on tool calling and plugins
Multi-source data sources require that tool calling supports connecting to multiple interfaces such as OA and organizational directories, to avoid incomplete configuration verification caused by a single data source.
Data updates are triggered by configuration changes, so tools must support real-time pulling of the latest configuration data to prevent test cases from failing due to expired caches.
Document structures include subdivided items such as approval nodes and permission fields. Tool calling parameters must match the naming rules of these fields, otherwise parsing failures will occur.
The test verification process takes a long time, so tools must support batch test case generation to reduce manual sorting workload.

## How to set configurations
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to multi-step tool calling scenarios for office workflow configuration, automatically schedules corresponding tools to complete tasks such as configuration verification and test case generation |
| `functionCall` | `enabled` | Supports structured parsing of field data in workflow configuration sheets and approval node tables, facilitating automatic generation of standardized test cases |
| Tool call timeout threshold | `300 seconds` | Office workflow configuration data has a moderate volume; 300 seconds covers the conventional time required for multi-source OA data pulling and permission verification |
| Batch test case generation limit | `Top 20 entries` | Matches the conventional number of entries in daily approval node tables, avoiding generation of redundant test data |
| Stream response switch | Enabled | Supports real-time return of progress for test case generation and defect troubleshooting, facilitating real-time monitoring of the configuration verification process |
| Data cache duration | `1 day` | Matches the update frequency of workflow configurations, avoiding use of expired approval node and form field data |

## Three common misconfigurations
- Phenomenon: The tool activation status shows as temporary, and workflow configuration data cannot be pulled continuously. Cause: Persistent authentication parameters are not configured, and only temporary session mode is enabled.
- Phenomenon: A timeout error is returned when calling the tool to generate test cases. Cause: The tool call timeout threshold is set too short, and does not adapt to the time required for multi-source OA data pulling.
- Phenomenon: Applications created based on the knowledge base cannot retrieve the latest workflow configuration data. Cause: Real-time data pulling rules for tool calling are not configured, and only static knowledge base caching is used.

## How to confirm the configuration is correct
- Manually trigger tool calling, and check whether the latest approval node tables, form field descriptions and other data can be pulled.
- View the tool call logs, and confirm that the tasks automatically scheduled by the `toolChoice` parameter match the current workflow configuration verification requirements.
- Generate batch test cases, and check whether the cases include core fields such as approval rules and permission configurations.
- Enable the stream response switch, and verify whether progress feedback for test case generation can be received in real time.
