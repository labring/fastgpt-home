# Test Cases and Defect Analysis for Unit and Component Testing: Source Citation and Traceability

## What Data for This Category Entails
This category’s data primarily comes from code repositories, test framework reports, requirement specifications, and interface definitions. Update frequency is daily or after each code commit.
Daily produced documents include test cases, coverage reports, Mock instructions, and defect tickets. Data fields include case ID, execution status, defect associated ID, code coverage value, and similar items. No custom units are used. Data structure adjusts slightly based on the test framework and team standards.

## Constraints Imposed on Source Citation and Traceability
Scattered data sources and frequent commit-based updates require traceability systems to quickly link code commit records and test results.
Test cases and defect tickets have strong field correlation. Unique identifiers like case IDs and defect IDs must be precisely matched to complete traceability.
High-frequency data updates demand that traceability configurations support real-time or near-real-time data synchronization, to avoid referencing outdated test data.
Differences in document structures across teams require traceability systems to have flexible field mapping capabilities, to adapt to varying team test document specifications.
Additionally, constructing test data and completing boundary condition checks takes significant time. Precise traceability reduces repeated troubleshooting costs, and prevents increased regression costs and build blockages caused by missed local logic defects.

## How to Configure Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the typical content length of test cases and defect tickets, ensuring complete citation of key information |
| `responseData` | First 3 entries | Focuses on core test data and defect records, aligning with engineers' needs for quick problem location |
| `detail` | Enabled | Displays full execution status of test cases and defect association information |
| Single search limit | First 10 entries | Matches the number of associations between test cases and defect tickets, avoiding excessive redundant data interfering with traceability |
| Field mapping rules | Calibrated based on actual testing | Adapts to differences in field naming across team test documents, ensuring precise matching of identifiers like case IDs and defect IDs |
| Data synchronization frequency | Every 15 minutes | Aligns with the update rhythm of code commits and test executions, balancing real-time performance and system load |

## Three Common Configuration Errors
- Phenomenon: After importing a workflow, the traceability function for test cases and defect analysis cannot link to the original data source. Cause: The mapping rules for the test data source were not included when exporting the configuration, and the data source configuration of the import environment does not match the original environment.
- Phenomenon: When displaying test report citations, an error pop-up appears stating "No permission to operate this conversation record". Cause: The access permission mapping for cited data has not been configured, or the permission scope of the test documents has not been opened to the current conversation role.
- Phenomenon: When searching for associated test cases, the number of returned results is far lower than expected. Cause: The single search limit is set too low, failing to cover the actual number of associations between test cases and defect tickets.

## How to Verify Successful Configuration
- A test case traceability query can be executed, and returned cited data can be checked to confirm inclusion of core identifiers such as test case IDs and defect IDs.
- After importing and exporting configurations, the traceability function can be verified to normally link to the test data source in the target environment.
- After adjusting configuration items, the number and content length of cited data can be observed to confirm alignment with expected settings.
- Permission configurations can be checked to ensure conversation roles can access relevant data for test cases and defect tickets.
