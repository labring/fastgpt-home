# Test Cases and Defect Analysis for Prototype and Interaction Design: Tool Calling and Plugins

## What data for this category looks like
Typical users of this category are product designers, interaction designers, and front-end product teams. Daily deliverables typically include interactive prototypes, page flowcharts, component descriptions, and review records. Data sources typically include Figma or Axure files, internal team design systems, user feedback, and usability test records. Update frequency is typically weekly or per version iteration. Core daily processing content focuses on page structure and operation paths. Teams must sort out state transitions, complete missing abnormal scenarios, and finalize design review revisions. Improper handling can lead to R&D misunderstanding, post-launch operation path failures, or rework problems.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
The data sources for this category are mostly structured or semi-structured design files. Plugins are required to parse exported Figma or Axure formats, so plugin configurations must adapt to parsing rules for specific file types. Data updates occur weekly or per version iteration, so tool calling trigger timing must align with this rhythm to avoid excessive triggering and resource waste. Daily document fields mostly relate to page nodes and interaction logic. Tool input parameters must accurately map to specific elements in prototypes to avoid generalized content extraction. Errors directly impact R&D and launch workflows, so failure retry and verification mechanisms must be configured to reduce processing risk in abnormal scenarios.

## Three common mistakes
- Phenomenon: Configured plugins cannot be found in the tool list, and the interface displays "No matching plugin configuration found". Cause: The plugin file was not placed in the FastGPT-specified plugin storage directory, or the configured path does not match the system's default plugin loading path.
- Phenomenon: Tool calls return empty results or missing core fields. Cause: Parameter mapping rules were not correctly configured, and fields such as page IDs and interaction nodes in prototype files were not accurately mapped to tool input parameters.
- Phenomenon: Plugin calls time out, returning status code 504. Cause: A reasonable timeout threshold was not set. For large prototype files, parsing time exceeds the system's default limit, and no retry mechanism was configured.

## How to confirm configurations are correct
- Upload a simplified Axure prototype test file, trigger plugin calls, and check if the configured target plugin appears in the tool list.
- View FastGPT plugin call logs to confirm whether input parameters correctly extract core information such as page IDs and interaction nodes from prototype files.
- Verify that plugin return result formats match the preset test case and defect analysis template, and that all fields are complete.
- Simulate an abnormal scenario by uploading a corrupted prototype file, check if the preset failure handling logic is triggered and a friendly prompt is returned.
