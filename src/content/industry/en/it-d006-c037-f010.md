# Test Cases and Defect Analysis for Release Management and Version Acceptance: Citation Sources and Traceability

## What this category of data looks like
This category of data is maintained by release managers, research and development operations teams, and product owners. Daily associated documents include release plans, launch checklists, acceptance reports, and rollback plans.
Data sources cover CI pipelines, change management systems, test reports, and monitoring dashboards. Update frequency is weekly or per version cycle.
Data fields include release version numbers, change items, test pass rates, and rollback trigger conditions. There are no unified mandatory units. Adjustments follow the field rules of corresponding documents.

## Constraints on citation sources and traceability
This category of data has scattered sources, and most are automatically generated system records. The traceability link must associate unique identifiers from original data sources such as CI pipelines and change management systems. This avoids missing traceability information.
Update frequency is tied to version release cycles. Cited context must be limited to the effective scope of the corresponding version. This prevents cross-version citation failures.
Daily associated document types are diverse. Traceability paths must be established based on categories such as release plans and launch checklists. This ensures cited content matches the version of corresponding documents.
Fields have no unified mandatory units. Original document field mapping rules must be retained. This avoids information distortion.

## Configuration settings
The following configurations are based on FastGPT v4.17.0

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `1500–2500 token` | Adapts to the average content length of single-version documents such as release plans and launch checklists |
| `responseData` | Only return datasets associated with the current version | Avoid traceability confusion caused by cross-version citations |
| `detail` | Return all original document fields | Retain key traceability information such as release data version numbers and change items |
| Maximum context length | `8000–12000 characters` | Cover combined content of multiple release-related documents |
| Citation time validity range | Match the current version update cycle | Align with weekly or per-version data update frequency |
| Traceability identifier binding | Associate CI pipeline and change system IDs | Meet traceability requirements for multiple data sources |

## Three common configuration errors
- Phenomenon: The number of context items displayed on the page does not match the number actually sent to the caller. For example, 30 items are displayed but 310 are actually sent. Cause: The `quoteMaxToken` configuration is not set correctly, and it does not match the token counting rules of the actual document, leading to abnormal truncation logic.
- Phenomenon: After setting a citation upper limit, blocks in the knowledge base that exceed this length are still cited. Cause: The `responseData` configuration is not set to filter datasets by version, leading to accidental recall of ultra-long blocks across versions.
- Phenomenon: Cited traceability information lacks original system identifiers. For example, it is impossible to associate with the corresponding CI pipeline record. Cause: The `detail` configuration item is not enabled, only simplified content is returned, and key traceability fields such as CI pipeline IDs are not retained.

## How to verify correct configuration
- View cited traceability associated identifiers. Confirm they include fields such as CI pipeline ID and version number. Check whether the `detail` configuration item is enabled.
- Test cross-version document citations. Confirm only datasets of the current version are recalled. Check whether the `responseData` configuration is correct.
- Test release documents of different lengths. Confirm the number of cited tokens falls within the set `quoteMaxToken` range.
- Check whether the citation time validity range matches the current version's update cycle.

The values given are common starting points and should be measured against the reader's own samples.
