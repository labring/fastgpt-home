# Test Cases and Defect Analysis for Pre-Sales Technical Solutions: Citation Sources and Traceability

## What This Category’s Data Looks Like
Core data for this category comes from customer interview records, public tender documents, official vendor product materials, and historical delivery project plans. Daily output documents include technical proposal documents, customer requirement research forms, quotation lists, and demo scripts. Core fields include technical roadmap, implementation boundaries, quotation configurations, customer requirement points, and other key content. Data is updated per order or per week, with updates synchronized alongside customer requirement adjustments or project phase progress.

## Constraints Imposed by These Characteristics on Citation Sources and Traceability
Core data sources are scattered across multiple types of public and internal documents. Citation traceability requires precise matching of the original source for each content fragment, to avoid mixing proposal content from different vendors or projects. Data is updated per order or per week, so traceability indexes must be refreshed synchronously when documents are modified. This prevents use of outdated content via citations. Differences in fields across different documents require traceability rules to adapt to specific fields such as technical roadmap and implementation boundaries, so adaptive matching logic must be used. Additionally, the tight delivery timelines for pre-sales proposals mean the traceability link cannot excessively slow down the proposal generation process.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 1000–1500 token | Matches the average length of single-segment content in pre-sales proposals, avoids truncating key traceability information, and adapts to the parameter logic of FastGPT v4.17.0 |
| Maximum Context Length | 8000–10000 characters | Carries multi-source proposal document fragments, ensuring coverage of complete technical roadmap and boundary descriptions |
| `responseData` | Enable traceability field return | Forces output of document IDs and source links for citation sources, to meet compliance verification requirements for pre-sales proposals |
| Single Recall Limit | Top 6 entries | Adapts to the number of core reference documents for pre-sales proposals, avoiding redundant information interfering with proposal boundary judgment |
| `detail` | Enable detailed traceability mode | Displays the original context of cited fragments, facilitating pre-sales consultants to verify consistency of proposal commitments |

## Three Common Misconfigurations
- Phenomenon: Empty citation fields are returned when calling an external API to reference knowledge base content. Cause: The `responseData` configuration item is not enabled, so the returned result does not include traceability information.
- Phenomenon: No citation markers appear in content generated by the large language model after increasing `quoteMaxToken` to above 2000. Cause: When exceeding the context carrying threshold, the system automatically truncates traceability-related information, making it impossible to match citation rules.
- Phenomenon: Traceability works normally during local testing, but cannot be referenced via external release channels. Cause: The knowledge base permission whitelist for external access is not configured, so external requests cannot read traceability-related data.

## How to Verify Correct Configuration
- Generate pre-sales proposal test content, and check whether the output result includes clear citation source annotations.
- Call the external API interface, and verify whether the returned `responseData` field includes document sources and fragment information.
- Modify the test case document, regenerate the proposal, and confirm that the traceability information is synchronized to the latest version.
- Adjust the `quoteMaxToken` parameter, and verify whether the length of the cited fragment conforms to the configured threshold range.

The values listed here are common starting points, and should be evaluated against local test samples.
