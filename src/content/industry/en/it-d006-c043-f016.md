# Test Cases and Defect Analysis for Security Incident Response: Forms and Interactions

This document applies to FastGPT v4.17.0.

## What This Category of Data Looks Like
This category of data originates from SIEM, EDR, firewall logs, and host images. Update frequency is real-time or per-event trigger. Daily produced documents include incident response reports, forensics records, disposal plans, and notification materials. Core fields include unique incident identifier, attack source IP address, disposal execution time, evidence chain number, and impact scope level. Data structure adjusts dynamically based on incident complexity. There is no fixed upper limit on the volume of data associated with a single incident. Adaptation is required for multi-source heterogeneous log and document formats.

## What Constraints Do These Characteristics Impose on Forms and Interactions
Multi-source heterogeneous log and document formats require external business systems to separately implement custom field groups and input type adaptations to cover structural differences across documents such as incident response reports and forensics records. The `formInput` node only collects user input information for corresponding fields and passes it to subsequent workflow nodes. The real-time event update rhythm requires data synchronization and association to be implemented by external business systems or subsequent workflow nodes to avoid data lag. Mandatory requirements for core fields such as incident identifiers require the `formInput` node to be configured with mandatory validation rules to ensure the integrity of emergency response data. For time-consuming links such as attack path restoration and evidence chain organization, external business systems or subsequent workflow nodes must implement batch import of associated logs to reduce manual entry workload. The `userSelect` node only passes selected user information. Permission scope division and validation must be implemented by external business systems to distinguish operational boundaries between incident response engineers and security leads.

## Three Common Mistakes
- Continuous page refresh when importing forensics logs prevents selecting target files: Check whether the batch import upper limit configuration of the external business system matches the current log import scale
- Fields are empty and cannot be saved after submitting an emergency disposal form: Check whether mandatory field validation configuration for the `formInput` node is enabled
- Invalid username displayed when adding team members: Check whether the user matching range configuration of the external business system includes the current operating account scope

## How to Confirm Proper Configuration
- Import a single batch of 100 SIEM logs via the external business system, check that the page loads without abnormal refresh
- Attempt to submit a form without filling in the incident ID, confirm that the system pops up a mandatory field prompt
- Switch between different role accounts, check that the editable form field range matches the permission configuration of the external business system
- Simulate a form submission failure scenario, confirm that the external business system or subsequent workflow nodes automatically initiate retries within 30 seconds

The values given are common starting points and should be measured against the reader's own samples.
