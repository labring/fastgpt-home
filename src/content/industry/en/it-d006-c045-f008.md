# Test Case and Defect Analysis for Security Training and Phishing Drills: Workflow Orchestration

## What data for this category looks like
Core documents for this category include training courseware, drill plans, phishing email templates, and drill result reports. Data sources include employee contact lists, email gateways, internal training platforms, and user click statistics systems.
Data update frequency is typically quarterly or annually. Core fields include drill audience scope, email delivery records, click behavior data, and rectification feedback items.
Daily data accumulation covers the entire process of employee security awareness training and phishing drills.

## What constraints do these characteristics impose on workflow orchestration
This category’s data characteristics create multiple constraints for workflow orchestration.
Data sources are scattered. Configure multi-source data pull nodes in workflows to connect to systems such as employee contact lists and email gateways, and obtain drill audience and delivery data.
Update frequency is low. Workflows do not need frequent triggering, but must support syncing the latest basic data on a quarterly or annual basis.
Core documents include templates and review reports. Build template generation and result export nodes into workflows.
Core time-consuming steps focus on audience screening and review. Use workflow automation to complete tag matching and data aggregation.
Errors may trigger security compliance risks. Add exception verification nodes to block invalid data flows.

## Configuration Specifications
This document applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Preset global variables according to the drill cycle, including audience scope and email subject keywords | Matches the quarterly/annual updated basic data of this category, reduces repeated configuration |
| User selection node trigger rule | Trigger after the upstream node specified by `nodeId` completes | Avoids workflow interruptions, supports multi-node series and nested call scenarios |
| Variable clearing configuration | When the upstream output is empty, update the corresponding field in `variables` to a null value | Resolves result abnormalities caused by residual variables |
| External data sync cycle | Sync employee contact list and email gateway data on a quarterly basis | Matches the data update frequency of this category, reduces sync overhead |
| Application parameter passing configuration | Support passing global `variables` via URL query parameters | Meets the parameter passing requirements for external systems to call workflows |
| Workflow nested trigger | Configure the parent workflow to return results after the child workflow specified by `nodeId` finishes executing | Resolves node execution interruptions during cross-workflow calls |

## Three common mistakes
- Scenario: After workflow A calls child workflow B, nodes after the user selection node in the child workflow no longer execute. Cause: The trigger rule associated with `nodeId` is not configured, causing the upstream node completion signal to not be passed correctly.
- Scenario: AI model output results cannot be cleared via variable updates, and fields retain residual values. Cause: The clearing logic for the corresponding field in `variables` is not bound to the empty output trigger condition of the upstream node.
- Scenario: External passed parameters cannot be written to global variables, and variables are not updated after workflow startup. Cause: The global variable binding configuration for URL query parameters is not enabled, or the parameter format does not meet system requirements.

## How to confirm the configuration is complete
- Check if the global `variables` match the basic data fields of the drill cycle. Use the preview node to verify if variable values load correctly.
- Verify the trigger rule for the user selection node. Manually trigger the upstream node, then confirm if subsequent nodes execute normally.
- Test the URL parameter passing function. Start the workflow with the specified query parameters, then check if global variables update synchronously.
- Trigger workflow nested calls. Confirm if the parent workflow continues executing subsequent nodes after the child workflow finishes.
