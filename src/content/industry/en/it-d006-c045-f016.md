# Test Case and Defect Analysis for Security Training and Phishing Drills: Forms and Interactions

## What this category of data looks like
Daily documents for this category include training slides, drill plans, phishing email templates, and drill result reports. Data sources include employee contact lists, email gateways, training platforms, and click statistics. Update frequency is typically quarterly or annually. Core data fields include drill audience scope, email template parameters, click behavior tags, rectification records, and more. The most time-consuming steps are concentrated in drill audience screening, template design, and result review. Configuration oversights may lead to employee data leakage risks, audit gaps, or lack of evidence for rectification.

## Constraints Imposed on Forms and Interactions
This category’s data characteristics impose multiple constraints on forms and interactions workflows. Data is synced from multiple systems, so bulk import of employee contact list data must be implemented via external systems or downstream nodes. `userSelect` is a user interaction node type used to collect personnel selection information and pass it to downstream nodes. Historical template reuse and version retention functions must be implemented by external business systems.

The drill audience screening step is time-consuming. Grouping screening and tag matching interaction controls must be implemented via the interface of external business systems. Email template design relies on precise variable insertion. Standardized training object and time variable insertion entry points must be provided by external business systems.

To avoid risks caused by configuration oversights, required field validation and exception status prompts must be configured via external business systems. `formInput` is a user interaction node type used to collect input information and pass it to downstream nodes. Data association for external click statistics interfaces must be implemented separately via external systems or downstream nodes.

## Three Common Misconfigurations
- Symptom: No upload button appears for the attachment upload input box in phishing email templates. Verification steps: Check whether the external business system has configured the attachment upload control, confirm whether the fields collected by the `formInput` node match the parameters of the external upload interface.
- Symptom: The `userSelect` module for drill audience screening cannot automatically sync options when employee contact lists are updated. Verification steps: Check whether the external system has configured automatic sync logic for employee contact list data, confirm whether the `userSelect` node calls the latest external personnel data interface.
- Symptom: Uploaded test images are not correctly passed when calling an external Python script via a workflow. Verification steps: Confirm whether the file upload fields collected by the `formInput` node match the interface parameters of the external Python script.

## How to Verify Successful Configuration
- Upload a test employee contact list CSV file to the external system, confirm that the `userSelect` node can load department/post grouping tags synced from the external system.
- Insert preset variables into the email template form in the external business system, confirm that the system can automatically replace them with test employee names and drill dates.
- Upload a test file with incorrect format to the external system, confirm that the system pops up clear error prompts including specific error fields and correction suggestions.
- Call the external script interface bound to the workflow, upload a test image, confirm that the script can normally receive and return analysis results.
