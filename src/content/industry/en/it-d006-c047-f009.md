# Test Cases and Defect Analysis for Security Vulnerability Disclosure Handling: Tool Invocation and Plugins

This document applies to FastGPT v4.17.0. It covers configuration, issue resolution, and validation methods for tool invocation and plugins during the test case and defect analysis phase of security vulnerability disclosure handling scenarios.

## What Data for This Category Looks Like
Data comes from private vulnerability reports, code repositories, CVE numbering authorities, and official release channels. Four core document types are regularly generated: security advisories, vulnerability reports, repair patches, and CVE application materials. Data updates follow single vulnerability event cycles. Each document includes fixed fields such as vulnerability ID, affected scope, repair steps, and disclosure time. Most field types are text, date, and enumeration types. There are no unified quantitative statistical units. Data transfer must strictly comply with privacy protection requirements.

## Constraints on Tool Invocation and Plugins
Data sources include private content and public institutional information. Tool invocation must distinguish permission scopes to avoid leaking undisclosed vulnerability details. Document structures mostly mix structured fields and free text. Plugins must support multi-format parsing and precise field extraction to ensure output results meet format requirements for official documents such as CVE applications. Update frequency is event-driven. Tool invocation must adapt to context length limits for single tasks to avoid redundant loading of historical data. Additionally, due to time coordination involved in vulnerability disclosure, tool invocation must support state synchronization and timing control to ensure accurate process handoff between links such as vulnerability impact assessment and patch preparation.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to multi-tool scheduling needs for vulnerability analysis, automatically matches tools such as vulnerability verification, patch scanning, and CVE query |
| `functionCall` | Calibrated based on actual testing | Adapts to structured document field extraction needs, ensures compliant information output format for CVE application materials and vulnerability reports |
| Timeout threshold | 300–600 seconds | Matches the analysis cycle of a single vulnerability event, prevents task interruption due to delays in code repository or CVE authority interfaces |
| Plugin access scope | Only open permissions for public code repositories and CVE official interfaces | Protects the privacy of private vulnerability reports, complies with security requirements for data sources |
| Single invocation result limit | Top 20 entries | Matches the information density of vulnerability analysis, avoids excessive redundant data occupying context space |

## Three Common Misconfigurations
- When invoking a plugin, MongoServerError: The dollar ($) p error is returned, and vulnerability data storage cannot be completed. The cause is that the database connection parameters configured for the plugin did not properly escape special characters, conflicting with MongoDB syntax rules.
- Calling an MCP tool for enterprise patent query returns "Enterprise has no patent information records", but direct testing of the tool set returns normal results. The cause is that the tool invocation component did not properly pass the enterprise name parameter, leading to missing query conditions.
- Using the official Markdown to file plugin, the interface shows "File upload failed". The cause is that the file storage directory configured for the plugin does not have write permissions, or the temporary file path exceeds system limits.

## How to Confirm Configuration is Correct
- Manually trigger a vulnerability scanning tool invocation, check if `toolChoice` automatically matches the corresponding plugin, and that the returned result includes vulnerability affected scope information.
- Run a field extraction task for CVE application materials, verify if the output of `functionCall` includes preset fields such as vulnerability ID and repair steps.
- Upload a security advisory document to the Markdown to file plugin, confirm that the generated file can be downloaded normally and has a compliant format.
- View plugin operation logs, confirm that all tasks set with the timeout threshold complete within 300–600 seconds, with no timeout errors.

The values provided are common starting points and should be measured against the reader's own samples.
