# Test Cases and Defect Analysis for Security Monitoring and SOC Duty: Forms and Interactions
FastGPT v4.17.0

## What data for this category looks like
Data for this category originates from SIEM, EDR, NDR, and threat intelligence sources. Update cadence has two categories: real-time and daily. Routine output documents include alarm disposal sheets, duty logs, threat intelligence notifications, daily and weekly reports. Data fields include alarm unique identifier, disposal status, associated threat intelligence number, duty period, submission time, and others. These fields support core workflows: alarm analysis, false positive elimination, and escalation dispatch. No additional custom units are used. All fields follow standard operations and security operation formats.

## Constraints Imposed by These Characteristics on Forms and Interactions
Real-time updated alarm data requires external systems or downstream nodes to load new fields in real time. This prevents data lag from reducing analysis efficiency. Daily updated weekly reports require external systems to support bulk import or scheduled synchronization configurations. This aligns with fixed-cycle document generation requirements. Field differences across multi-source data require external systems to support custom field mapping. This reduces manual sorting work by adapting to format variations across data sources. False positive markers and escalation dispatch fields in alarm disposal sheets need interactive linkage logic in external business systems. For example, selecting a false positive marker automatically populates preset disposal results. This cuts down the time needed for false positive elimination. Time period fields in duty logs require external systems to support filtering and entry by time range. This fits SOC duty shift scenarios and simplifies the reporting process.

## Three Common Errors
- Symptom: Field mismatch error is prompted when bulk importing alarm disposal sheets via an external system. Verification steps: Check if a standard field template adapted to this category is used. Check if core fields such as alarm ID and disposal status have been mapped.
- Symptom: Some fields are empty after form submission, and duty logs cannot be generated. Verification steps: Check if the `userSelect` node has user interaction trigger logic configured. Check if required field validation configurations have been completed.
- Symptom: Real-time alarm data loading delay exceeds 5 minutes, leading to alarm analysis timeout. Verification steps: Check the real-time synchronization interval parameter set by the external system or downstream nodes.

## How to Confirm Configuration is Complete
- A test alarm data entry is submitted, the `userSelect` node interaction is triggered, and the input information collected by the form is verified to be passed to downstream nodes. Configuration effectiveness is confirmed.
- A test document matching the standard format is uploaded, and full field mapping after import is verified via the external system. Bulk import configuration effectiveness is confirmed.
- The real-time synchronization interval set by the external system or downstream nodes is adjusted, and alarm data updates within the configured interval are observed. Synchronization configuration effectiveness is confirmed.
- A test data entry missing a disposal result is submitted, and a validation prompt is verified to be triggered. Field validation rule effectiveness is confirmed.
