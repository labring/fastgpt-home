# Test Cases and Defect Analysis for Customer Training and Usage Manuals: Tool Calling and Plugins

## What this category of data looks like
Typical data sources for this category include product help centers, customer organizational structures, training recordings, and ticket systems. Data is updated per order or per version. Daily generated documents include training slides, user manuals, training attendance sheets, and Q&A lists. Document structures cover three categories: standardized operation instructions, non-standard training materials, and user feedback records. Data fields include operation steps, permission configuration, Q&A keywords, and training attendance status. There are no fixed unified unit requirements, and adaptation must be flexible based on document type. Core users of this category are customer success managers, training instructors, and product operations. The most time-consuming daily tasks are role permission explanations, operation step demonstrations, and post-class question organization. Improper handling leads to customers being unable to use the product, reduced launch conversion rates, and a sharp increase in ticket volume.

## What constraints these characteristics impose on tool calling and plugin workflows
Scattered data sources and frequent updates require tool calling and plugins to support real-time pulling of the latest user manual and ticket data. They must adapt to different document formats, and avoid generating test cases based on outdated content. Diverse document structures require plugins to have multi-format parsing capabilities. They must handle both standardized user manuals and non-standard training materials, and cover all types of training materials. Data fields covering core content such as operation steps and permission configuration require tool calling to accurately extract corresponding fields. This avoids redundant information interfering with defect analysis and test case design. Meanwhile, the core time-consuming tasks and potential error consequences of this category require tool calling to prioritize parsing role permissions and operation steps. This reduces recall of irrelevant content and improves analysis efficiency.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to automatic tool calling requirements for different training documents, no manual specification of call type needed |
| `functionCall` | `enabled` | Supports extracting operation steps and permission configurations from user manuals as function call parameters |
| Tool call timeout | `300–600 seconds` | Training slides and user manuals are often long texts, sufficient time must be reserved for parsing and calling |
| Maximum tokens per single call | `8000–12000 token` | Single chapter content of user manuals usually falls within this range, avoiding exceeding model context limits |
| Maximum number of recalled documents | `Top 8 entries` | The number of common questions in training Q&A lists is limited, avoiding redundant data interfering with test case generation |
| Document parsing priority | User manuals first, then training slides | User manuals are standard operation documents, with higher priority than non-standard training slides |

## Three common errors
- Phenomenon: Document parsing tool returns a 400 status code with no response body. Cause: Pre-check steps for tool calling are not configured, and pre-requests are not triggered as required by the document.
- Phenomenon: Operation steps extracted via function call do not match the latest user manual. Cause: Version-matched recall rules are not set, and outdated training slide content is called.
- Phenomenon: Number of results returned by tool calling exceeds expectations. Cause: Maximum number of recalled documents per single call is not limited, leading to redundant data interfering with defect analysis.

## How to confirm correct configuration
- Upload the latest user manual for FastGPT v4.17.0, trigger tool calling, and verify that extracted operation steps match the original document text.
- Import a single training Q&A question, and verify that matching content returned after tool calling comes from the corresponding document type.
- Check tool calling logs, and confirm there are no error records of 400 status code with no response body.
- Enable the `functionCall` parameter, and verify that function calls can correctly map permission configuration content from user manuals.

The values provided are common starting points and should be measured against the reader's own samples.
