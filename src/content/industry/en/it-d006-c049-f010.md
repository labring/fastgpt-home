# Test Cases and Defect Analysis for Customer Training and Usage Manuals: Citation Sources and Traceability

## What the data for this category looks like
This category’s core documents include training slides, user manuals, training attendance sheets, and Q&A lists. The system sources data primarily from the product help center, customer organizational structures, training recording videos, and ticket systems. The system adjusts update frequency based on customer orders or product version iterations. Document fields typically include operation steps, role permission descriptions, Q&A scripts, and similar content. There are no uniform mandatory units; values depend on the content attributes of individual documents.

## What constraints do these characteristics impose on the citation sources and traceability link
Since data sources include multiple types of systems and recording content, citation traceability must support cross-data source association and matching. Document update frequency adjusts with orders and versions, so traceability configuration must adapt to dynamically updated content versions. Field differences across document types are significant, so the system must support precise recall for different content modules such as operation steps and permission descriptions. The post-class question organization step relies on associations with ticket systems and Q&A lists, so traceability must directly link to original Q&A records and training recording video nodes to avoid traceability deviations caused by fuzzy matching.

## How to configure settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 characters | Adapts to the single-paragraph content length of training slides and user manuals |
| `responseData` | Product help center, ticket system only | Matches the core data sources for this category |
| `detail` | Enabled | Ensures complete original document fragments are returned during traceability |
| Single recall limit | Top 3 entries | Prevents excessive redundant information from interfering with traceability judgments |
| Version matching switch | Bound to product version | Adapts to the document iteration rhythm updated with each version |
| Traceability verification threshold | 0.85–0.90 | Accurately matches semantic associations between operation steps and Q&A content |

## Three Common Configuration Mistakes
- Phenomenon: A "no matching source found" error is returned when calling the traceability function. Cause: Core data sources such as the product help center and ticket system have not been configured as recall scopes, making it impossible to associate original documents and records for this category.
- Phenomenon: Returned traceability fragments exceed the reasonable length of a single document and include irrelevant content. Cause: The `quoteMaxToken` setting exceeds the single-paragraph standard length of documents in this category, resulting in recall of redundant adjacent document chunks.
- Phenomenon: Traceability results are linked to outdated training content that does not match the product version currently used by the customer. Cause: The version matching switch has not been enabled, and the data source update rhythm for traceability has not been bound to the product version.

## How to verify the configuration is correct
- A test user manual fragment is uploaded, a conversation requiring traceability is triggered, and returned source fragments are verified to match the uploaded content.
- The configuration scope of `responseData` is adjusted to test whether only content from the specified data sources is recalled.
- Product versions are switched for simulated testing to confirm that documents of different versions can be correctly linked to corresponding traceability records.
- System logs are checked to confirm that the parameters of traceability requests match the configured `detail` switch status.

The values provided are common starting points and should be measured against the reader's own samples.
