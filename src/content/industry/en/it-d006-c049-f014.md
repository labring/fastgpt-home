# Test Cases and Defect Analysis for Customer Training and Usage Manuals: Model Integration and Configuration

## What data for this category looks like
This category’s daily documents include training slides, user manuals, training attendance sheets, and question-and-answer lists. Typical users include customer success managers, training instructors, and product operations teams. Data comes primarily from the product help center, customer organizational structures, training recording transcripts, and ticket systems. Updates occur once per order or per version. Document structures cover operation step instructions, permission configuration guidelines, frequently asked questions, and other types. Fields include operation nodes, permission roles, question-and-answer scenarios, and more. There are no fixed unified units. Values adjust dynamically based on document type.

## What constraints these characteristics impose on model integration and configuration workflows
Data sources include multiple formats: recording transcripts, ticket records, help center articles, and more. Models must adapt to input content of varying lengths and structures. The high update frequency requires configurations to support quick synchronization of latest training content. This prevents models from using outdated document information. Documents focus on operation steps and permission explanations. This creates high accuracy requirements for generated content. Incorrect configuration can lead to generated content deviating from actual training standards. This causes customer usage obstacles and a surge in support tickets. Mixed input of multiple document types also requires model integration configurations to adapt to the unique characteristics of each document type.

## How to set configurations
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | `4000–8000 token` | Single-section reference content from training slides and user manuals is usually long. Sufficient original document information must be covered to ensure generation accuracy |
| `maxTokens` | `1000–1500 token` | Responses about operation steps should not be too long. They must be kept within a range users can quickly read |
| `temperature` | `0.3–0.5` | Generated content must strictly match the accurate wording in training documents. Excessive divergence must be avoided |
| `toolChoice` | `auto` | Can automatically call tools to organize tickets and question-and-answer lists. This adapts to the post-session question organization workflow for this category |
| `AIPROXY_API_ENDPOINT` | Fill in the root address of the actually deployed AI Proxy service, for example http://aiproxy:3000. Do not append /v1 or /chat/completions | Required environment variable for the App/Admin server. This is the access root address for the AI Proxy service |
| `AIPROXY_API_TOKEN` | Fill in the administrator token consistent with the AI Proxy server configuration. This field cannot be empty | Required environment variable for the App/Admin server. Used for access authentication with the AI Proxy service |

## Three common mistakes
- Symptom: The same model returns inconsistent results between the FastGPT web debug interface and external access scenarios. Troubleshooting step: Check whether the `maxContext` parameter configuration is consistent between web debug and external calls.
- Symptom: Model testing fails after being added, with a missing configuration error popup. Troubleshooting step: Check whether the App/Admin server has configured the required `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` parameters, and whether the AI Proxy service root address format meets requirements.
- Symptom: Generated operation steps do not match the content in training slides, with extra irrelevant statements added. Troubleshooting step: Check whether the `temperature` parameter setting exceeds the reasonable range of `0.3–0.5`.

## How to confirm successful configuration
- Navigate to the model testing page in FastGPT v4.17.0. Input a typical operation-related question. Verify that returned content accurately references step instructions from training slides.
- Call the external access interface. Send a request using the same test question. Compare returned results with those from the web debug interface. Confirm that configuration parameters are fully consistent.
- View the model running logs. Confirm that there are no authentication failure or address error prompts related to `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN`.
- Adjust the `temperature` parameter to the reasonable range. Observe the degree of divergence in the generated content. Confirm that it meets the accuracy requirements for this category.

The values listed above are common starting points. They should be evaluated against the specific samples of the relevant deployment.
