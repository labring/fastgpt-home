# Test Cases and Defect Analysis for Customer Provisioning and Tenant Initialization: Model Access and Configuration

## What Data Looks Like for This Category
Core data for this category comes from CRM systems, contract order databases, identity management systems, and product backends. Daily maintenance documents include provisioning request forms, tenant configuration tables, administrator account lists, and delivery confirmation sheets.
Data updates follow per-order workflows. Full data synchronization completes after a single provisioning process finishes. Daily operations synchronize and update tenant permissions and account statuses each day.
Data fields include customer identity identifiers, permission scopes, resource quotas, and other information. No unified standardized format exists. Field mapping rules must be adjusted based on each customer’s contract terms.

## Constraints Imposed on Model Access and Configuration
Multi-source heterogeneous data sources require model access configurations to adapt to different document structures. Configurations must support custom field mapping rules.
Per-order update rhythms mean configurations must support rapid iterative adjustments. Changes take effect without a full global restart.
Sensitive fields require permission verification logic during model access. This prevents unauthorized reading and modification of configurations.
Errors in this link directly block customer logins, delay deliveries, or halt contract acceptance. Configurations must include pre-verification steps. These steps ensure parameter validity and alignment with permission scopes.

## How to Configure Settings
This configuration is based on FastGPT v4.17.0. Specific parameters are listed below:

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `maxTokens` | 8000–16000 token | Adapts to long-text processing needs for batch account creation and permission configuration during tenant initialization |
| `temperature` | 0.1–0.3 | Ensures consistency of configuration results such as permission allocation and account generation, avoids deviations |
| `AIPROXY_API_ENDPOINT` | Fill in the root address of the AI Proxy service according to the deployment environment, for example http://aiproxy:3000. Do not append /v1 or /chat/completions paths | Valid root address for the AI Proxy service, ensures the App/Admin service can connect to the AI Proxy service |
| `AIPROXY_API_TOKEN` | Match the administrator token configured on the AI Proxy server, and cannot be empty | Ensures valid identity verification between the App/Admin service and the AI Proxy service |
| `toolChoice` | auto | Automatically selects tools to handle field extraction and mapping in provisioning request forms |
| `quoteMaxToken` | 2000 token | Limits the length of referenced configuration documents, avoids context overflow that impacts processing efficiency |

## Three Common Configuration Mistakes
- Symptom: Unable to connect to local Ollama after Docker private deployment. The interface returns a 404 error. Cause: Failed to correctly set `AIPROXY_API_ENDPOINT` as the AI Proxy service root address, or failed to use a matching `AIPROXY_API_TOKEN` for identity verification with the AI Proxy server.
- Symptom: Configuration items fail to load normally after embedding the tenant initialization page in an iframe. Cause: Cross-domain access permissions for the corresponding domain were not enabled in the FastGPT backend, or iframe sandbox parameters were not configured correctly.
- Symptom: Subsequent requests are blocked and cannot be interrupted after sending batch provisioning requests. Cause: A reasonable `maxContext` limit for single-request context length was not configured, or the streaming response interrupt mechanism was not enabled. This leads to request backlogs that cannot be canceled.

## How to Verify Successful Configuration
- Run connectivity verification to confirm the AI Proxy service linked to `AIPROXY_API_ENDPOINT` can respond to requests normally.
- Submit a test provisioning request form. Check if the model correctly extracts customer information and permission configuration fields from the document. Confirm it generates compliant tenant configuration items.
- Trigger a batch provisioning process. Verify that active requests can be interrupted or canceled normally. This prevents resource backlogs.
- Review the administrator account list and delivery confirmation sheet. Confirm generated account information aligns with the configured mapping rules.

The values provided here are common starting points. They should be evaluated against the reader’s own samples.
