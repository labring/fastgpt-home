# Test Cases and Defect Analysis for Customer Data Import Migration: Workflow Orchestration

## Data Profile for This Category
Data for this category mainly comes from customer legacy systems, CSV or Excel templates, database export files, and product import logs. Data update frequency is per order or irregular, adjusted dynamically as migration projects progress. Daily associated documents include data templates, migration plans, field mapping tables, and migration validation reports. Core fields include customer identifiers, business data fields, and validation rule fields. There are no unified fixed units; matching must align with the customer’s business scenario. Implementation consultants, data implementation engineers, and customer IT liaisons typically handle this data. Core processes include field mapping confirmation, dirty data cleaning, and post-import sampling verification. Errors may lead to historical data loss, field misalignment, or customer rejection.

## Constraints for Workflow Orchestration
Decentralized data sources require workflows to include multi-format adaptation nodes that support CSV, Excel, and database export formats. Irregular update frequencies require workflows to support on-demand triggering, without binding fixed scheduling cycles. Multiple associated documents require embedding field mapping table call links in workflows to ensure real-time synchronization of migration rules. Core time-consuming links require workflows to split parallel processing nodes to reduce single-node runtime. Severe error consequences require workflows to include failure rollback and alert nodes, covering abnormal scenarios such as data misalignment and loss.

## Configuration Recommendations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Define a Number-type global counter, set the initial value to 0. Call the variable update node to increment the value each time execution completes | Matches the execution count statistics requirement for customer data import migration, complies with FastGPT v4.17.0 variable rules |
| Workflow Trigger Method | Trigger manually on demand or via import file upload event | Adapts to the irregular, on-demand update frequency characteristics of this category |
| Format Verification Node | Configure CSV/Excel format verification and database connection verification, set verification timeout to 600 seconds | Covers format validity checks for multi-source data, prevents invalid data from entering the workflow |
| Field Mapping Call | Link preset field mapping table nodes, load the latest mapping rules when called | Matches the core field mapping confirmation link requirement of this category, ensures correct data field correspondence |
| Failure Rollback Configuration | Set a pre-import data backup node, set backup storage capacity to 1000 MB, automatically roll back to the backup state upon failure | Reduces the risk of historical data loss after errors in this category |
| Alert Trigger Node | Configure alerts to trigger when failure status code ≥400 or field exceptions occur, set alert push interval to 300 seconds | Notifies relevant personnel of abnormalities in a timely manner, prevents customer rejection |

## Three Common Misconfigurations
- Symptom: The global Number-type counter cannot automatically increment after execution completes. The variable update plugin cannot trigger a change to its own value. Cause: The trigger logic for the variable update node is not configured in the workflow. Only the basic variable definition is bound, and the callback step after execution completion is not linked.
- Symptom: In the workflow orchestration debug panel of FastGPT v4.17.0, the code run node does not display execution details. Cause: The full node display filter rule of the debug panel is not enabled, or the debug log switch for the current workflow is not turned on.
- Symptom: After configuring a call to an external workflow, intermediate results do not match expectations, only the final output meets expectations. Cause: The imported external workflow configuration is not synchronously linked to the field mapping table, or the node execution order was accidentally adjusted, resulting in missing intermediate verification links.

## How to Verify Correct Configuration
- Manually trigger a test import process, check if the global counter increments correctly, and verify that the variable configuration takes effect.
- Upload a test file with an invalid format, confirm that the format verification node triggers interception and returns a corresponding prompt, and verify that the verification configuration takes effect.
- Simulate test data with field misalignment, confirm that the failure rollback node triggers backup recovery, and verify that the exception handling configuration takes effect.
- Trigger a preset abnormal scenario, check whether alert messages are pushed normally, and verify that the alert configuration takes effect.
