# Test Cases and Defect Analysis for Customer Data Import and Migration: Tool Calling and Plugins

## What This Category of Data Looks Like
Data sources for this category include CSV/Excel files exported from the customer’s existing business systems, database backup files, data exported via custom interfaces, and standard data templates provided by the customer. Data update frequency is adjusted irregularly alongside migration projects. Multiple updates may be conducted within a single project after adjusting field mappings based on customer requirements. Four core daily supporting documents are used: data templates, migration plans, field mapping tables, and migration verification reports. Fields fall into three categories: business identifiers, business attributes, and association relationships. There are no fixed unified units, and matching must be done based on specific business scenarios.

## Constraints on the "Tool Calling and Plugins" Workflow
Data sources for this category are scattered and have inconsistent formats. Tool calling plugins must support multiple data source access methods, including CSV/Excel templates, direct database connections, and data exported via custom interfaces. Data update frequency is adjusted flexibly for each project, so plugins must support dynamic modification of field mapping rules without rebuilding the entire migration workflow. Core documents rely on field mapping rules, so plugin configurations must bind mapping table parameters to ensure execution logic aligns with the documents. Logs generated during the migration process must be capturable by plugins for subsequent defect tracing and analysis.

## Configuration Recommendations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Bind to the preset customer data migration tool | Ensure tool calling aligns with the preset migration workflow and avoid parameter conflicts |
| `functionCall` | Process no more than 1000 data entries per single call | Adapt to the conventional data volume of CSV/Excel templates and reduce memory usage of single calls |
| Timeout threshold | 600 seconds | Align with the database plugin timeout configuration rules of FastGPT v4.17.0, adapt to long connection scenarios for direct database connections, and avoid timeout interruptions caused by bulk data imports |
| Log capture level | Record full execution logs | Facilitate subsequent defect tracing and migration verification report generation |
| Field mapping binding | Associate with the preset field mapping table | Ensure tool calling logic aligns with the mapping rules in business documents |

## Three Common Misconfigurations
- Phenomenon: Database connection plugin call duration increases significantly compared to older versions, with single-batch import time exceeding expectations. Cause: The new version of the plugin enables full data validation logic by default, and the optimized configuration for single-batch data volume is not applied.
- Phenomenon: Interface calls return a 413 error. Cause: The data volume transmitted in a single tool call exceeds the platform's preset limit, and batch processing is not implemented.
- Phenomenon: Tool calling processes are not hidden as expected, and sensitive fields are exposed in execution logs. Cause: Log desensitization rules are not configured correctly, or the output parameters of `toolChoice` are not adjusted based on project requirements.

## How to Verify Correct Configuration
- Perform a single-batch import test with a small data volume, and check whether the tool call logs align with the preset mapping rules.
- View the plugin configuration page to confirm that the migration tool bound to `toolChoice` matches the project documents.
- Trigger a timeout test to verify whether the timeout threshold takes effect as required for the project.
- Check whether the log capture switch is enabled, and confirm that complete import execution records can be obtained.
