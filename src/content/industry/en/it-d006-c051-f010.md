# Test Cases and Defect Analysis for Customer Data Import and Migration: Citation Sources and Traceability

## What this category of data looks like
This category of data primarily originates from customers’ historical business systems, CSV/Excel templates, database export files, and FastGPT product import operation logs. Daily supporting documents include data templates, migration plans, field mapping tables, and migration verification reports, with update cycles per individual project or on an irregular basis. Data fields mostly include customer identifiers, business attributes, timestamps, and similar items, with no unified fixed units, and require adjustment and adaptation based on the customer’s actual business scenario.

## Constraints on Citation Sources and Traceability
The data sources for this category are scattered and lack unified formatting, requiring citation traceability to be bound to a unique import batch identifier to prevent confusion across batches. The irregular update cycle means traceability configuration must support flexible adjustments to adapt to the timelines of different migration projects. The accompanying field mapping tables and migration verification reports require the traceability link to associate original data fields with imported business fields, ensuring cited content corresponds to actual migrated data. Import operation logs, as the core verification basis, must be directly bound to source information referenced by the knowledge base to facilitate troubleshooting of deviations between import and citation processes.

## Configuration Settings
The following configurations are documented for FastGPT v4.17.0:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 characters | Matches the length of single business blocks in imported data to avoid truncation of critical traceability information |
| Citation Source Display Toggle | Set based on actual testing | Adapts to different customers’ requirements for traceability visibility |
| Citation Matching Threshold | 0.75–0.85 | Balances field matching accuracy and recall efficiency for imported data |
| Maximum Citations Per Response | Top 3 entries | Aligns with the sampling verification logic of migration verification, avoiding answer redundancy |
| `detail` | Enabled | Displays field mapping relationships of original imported data to facilitate traceability troubleshooting |
| `responseData` | Bound to Import Batch ID | Directly binds import logs to citation sources to ensure accurate traceability |

## Three Common Misconfigurations
- Phenomenon: Returned answers do not associate with actual imported customer data, and citation sources point to unrelated historical migration batches. Cause: `responseData` is not bound to the import batch ID, resulting in traceability being linked to data from non-current projects.
- Phenomenon: Misaligned imported fields are incorrectly cited, and the fields displayed in traceability do not match the actual migrated fields. Cause: `detail` mode is not enabled, so field mapping relationships are not displayed, making it impossible to match original data with imported fields.
- Phenomenon: Citation source display does not meet configuration requirements; some migration projects force source display while others do not take effect. Cause: The citation source display toggle is not dynamically adjusted for each migration project, and the global default configuration is used instead.

## How to Verify Correct Configuration
- View import operation logs to confirm that the import batch ID associated with the citation source matches the current migration project.
- Trigger a test query to check whether the citation sources in the returned content match the actual imported field mapping relationships.
- Adjust the citation source display toggle to verify whether the interface display effects under different configurations meet expectations.
- Check the value of `quoteMaxToken` to confirm that the returned citation content has not had critical information truncated.

The values provided here are common starting points and should be evaluated against the reader’s own samples.
