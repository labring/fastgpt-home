# Test Cases and Defect Analysis for Customer Permission and Organizational Structure Configuration: Tool Calling and Plugins

## What the data for this category looks like
The core data for customer permission and organizational structure configuration comes from customer HR systems, identity directories, product backends, and audit logs. Update frequency occurs per order or irregularly. Daily maintained documents include permission matrices, organizational structure tables, role configuration records, and permission change forms. Data fields include department ID, role name, permission scope, change time, and others. No unified fixed unit exists; values adjust based on document type. Data processing subjects include implementation consultants, customer administrators, and technical support. These subjects must synchronize with and match enterprise internal identity management processes to ensure permission configurations align with actual organizational structures. This document applies to FastGPT v4.17.0.

## What constraints these characteristics impose on tool calling and plugin workflows
Decentralized data sources mean tool calling must interface with multiple sets of identity authentication systems to avoid cross-system permission conflicts. Irregular update frequencies require plugins to support both on-demand synchronization and scheduled incremental pull modes, adapting to temporary permission changes and routine maintenance scenarios. Fixed document structures require tool calling parameters to match the field formats of permission matrices and organizational structure tables; otherwise, data cannot be parsed correctly. The most time-consuming organization hierarchy verification and role mapping links require tools to support batch verification capabilities to reduce manual verification costs. Dependence on audit logs requires plugins to have the ability to pull and retain change records to meet subsequent audit requirements.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to automatic calling requirements for different permission scenarios, and matches the tool scheduling logic of FastGPT v4.17.0 |
| Permission data source synchronization frequency | Every 12 hours | Matches the per-order or irregular update rhythm, balances data timeliness and system load |
| Role permission mapping matching upper limit | Top 10 matching results | Covers the number of common role and department combinations in permission matrices, avoids redundant verification |
| Audit log pull scope | Last 7 days | Adapts to the audit cycle of routine permission changes, meets daily verification needs |
| `functionCall` | Strict mode | Ensures tool calling parameters comply with permission configuration rules, prevents unauthorized operations |
| Change impact preview switch | Enabled | Matches the verification process of permission change forms, identifies configuration risks in advance |

## Three Common Configuration Mistakes
- The permission synchronization tool call returns `Failed to fetch`. The cause is that authentication parameters for the identity directory system are not configured, preventing organizational structure data from being pulled.
- Role permission mapping results are empty. The cause is that department ID and role ID fields in the permission matrix are not matched, preventing the tool from associating corresponding configuration data.
- DingTalk webhook fails to push permission change notifications. The cause is that the correct organizational structure node ID is not bound in the tool configuration, causing the push scope to differ from expected values.

## How to Confirm Successful Configuration
- Run a permission data source synchronization task, verify that the number of pulled organizational structure entries matches the actual number of entries in the identity directory system.
- Trigger a role permission mapping verification, check that returned matching results cover all role and department combinations in the permission matrix.
- Submit a simulated permission change, confirm via the audit log tool pull interface that change records are correctly written to the product backend.
- Call the test interface for `toolChoice` automatic mode, verify that the tool automatically filters operable configuration items based on current role permissions.
