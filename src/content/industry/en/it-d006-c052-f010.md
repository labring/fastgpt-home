# Test Cases and Defect Analysis for Customer Permission and Organization Architecture Configuration: Quote Sources and Traceability

## What data for this category looks like
This category of data typically comes from customer HR systems, identity directories, product backends, and audit logs. Daily generated documents include permission matrices, organization architecture tables, role configuration records, and permission change forms. Fields cover department hierarchies, role permission items, personnel binding relationships, and change trails. Data updates have no fixed cycle. They trigger when customer permissions are adjusted or organization architecture changes. Each change corresponds to an independent configuration record and approval document.

## Constraints on quote sources and traceability
Decentralized data sources and irregular update cycles require traceability to link original records across multiple systems. A complete traceability chain cannot be built using only one data source. Diverse document types and inconsistent field standards require matching the field rules of the target document when quoting. This prevents field misalignment during cross-document quotes. Randomly triggered changes create time gaps in traceability data. Configurations must clearly define association time limits for change records. This ensures quoted permission configurations match the current active state. Additionally, configuration logic detailed for roles and departments requires traceability to link three layers of relationships: personnel, roles, and departments. Quote verification cannot be completed using only a single dimension.

## How to set configurations
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 8000–12000 token | Matches the average length of permission configuration documents, avoids truncating critical role permission mapping content |
| `responseData` | Return only fields associated with permission matrices and organization architecture tables | Filters redundant irrelevant audit log data, narrows the scope of traceability quotes |
| `detail` | Enable full field return | Retains core traceability fields such as department hierarchies and personnel binding relationships, meets cross-dimensional verification requirements |
| Single quote source limit | Top 6 entries | Adapts to the number of batch associations for permission configuration documents, avoids context overload |
| Traceability association time limit | Last 30 days | Matches the standard approval cycle for permission changes, covers all change records for the most recent valid configuration |

## Three common configuration mistakes
- Setting `quoteMaxToken` to 50000 token causes excessive permission configuration data to load on each quote. This slows down knowledge base query speed. The root cause is failing to match the actual length of documents in this category, and blindly expanding the token threshold.
- Failing to associate the exclusive permission configuration data source when calling the knowledge base module in a workflow. This prevents quoting content from organization architecture tables and permission matrices. The root cause is not specifying the exclusive data source for this category, so the general knowledge base is called by default.
- Failing to filter redundant fields when enabling the `detail` configuration. This introduces large numbers of irrelevant audit log quote markers into AI output. This causes garbled end-of-sentence quote markers. The root cause is not filtering returned data, so redundant markers are mixed into the output.

## How to verify correct configuration
- Initiate a query related to permission configuration. Check if returned quote sources include category-exclusive documents such as permission matrices and organization architecture tables.
- Check token consumption for quoted data. Confirm it does not exceed the preset `quoteMaxToken` threshold.
- Verify the association time limit for change records. Confirm only permission change content from the last 30 days is returned.
- Trigger a workflow call. Check if quoted data for organization architecture and role permissions can be returned normally.

The values provided are common starting points and should be measured against the reader's own samples.
