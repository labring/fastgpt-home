# Test Cases and Defect Analysis for Client Permissions and Organizational Structure Configuration: Model Integration and Configuration

## What this category of data looks like
This category of data primarily comes from client HR systems, identity directories, product backends, and audit logs. Updates occur per order or on an irregular basis. Daily deliverables include permission matrices, organizational structure tables, role configuration records, and permission change tickets. Core fields include department hierarchy, role permission items, change effective time, and operator information. Data must match the client’s existing organizational structure and permission rules. There are no fixed statistical thresholds. Updates are only triggered by client business adjustments or permission changes.

## What constraints these characteristics impose on model integration and configuration
Scattered data sources, irregular update frequencies, and diverse document formats impose multiple constraints on model integration and configuration. The system must support integration with multi-source identity directories and audit logs to ensure real-time synchronization of permission data. It must adapt to multiple document formats such as permission matrices and organizational structure tables to complete role permission mapping and organizational hierarchy verification. It must support dynamic pulling of updated permission data to adapt to irregular update schedules. It must also strictly verify permission mapping logic to avoid unauthorized access or audit failures caused by configuration errors.

## How to set configurations
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Adapts to context storage for multiple documents such as permission matrices and organizational structure tables, prevents permission mapping logic from interrupting due to context overflow, and complies with FastGPT v4.17.0 configuration specifications |
| `maxTokens` | `2000–3000 token` | Controls the length of permission analysis results output by the model in a single round, ensures results can fully match organizational structure fields, and avoids information truncation |
| `quoteMaxToken` | `1000–1500 token` | Limits the length of referenced permission document fragments, focuses on core permission rules and organizational hierarchy information, and improves analysis accuracy |
| `toolChoice` | `auto` | Automatically selects appropriate tools to complete permission data extraction and mapping, adapts to parsing requirements for multi-source documents |
| `temperature` | `0.1–0.3` | Reduces output randomness, ensures permission configuration analysis results align with actual rules, and avoids unauthorized access risks |
| `AIPROXY_API_ENDPOINT` | Root address of the AI Proxy service, for example http://aiproxy:3000 | Required environment variable for the App/Admin backend, serves as the access root address for the AI Proxy service. Do not append paths such as /v1 or /chat/completions |
| `AIPROXY_API_TOKEN` | Non-empty admin token matching the AI Proxy backend configuration | Required environment variable for the App/Admin backend, used for identity verification with the AI Proxy service. Do not use as an application API key or model vendor secret |

## Three common configuration errors
- When configuring a large model that only supports stream mode, the call returns empty results and logs show an error about failed data acquisition. Cause: Stream mode support is not enabled in the model configuration, making it impossible to parse the model’s streaming response format.
- When deploying FastGPT in an intranet environment and calling a model, service startup verification fails or the model cannot be called normally. Cause: `AIPROXY_API_ENDPOINT` is not correctly set to the root address of the AI Proxy service, or `AIPROXY_API_TOKEN` matching the backend configuration is not set, preventing normal access to the AI Proxy service.
- When importing a permission change ticket, the model fails to correctly identify the role permission mapping relationship and generates incorrect permission configuration suggestions. Cause: The value of `maxContext` is too small, failing to fully load all content of the permission change ticket and resulting in missing context information.

## How to confirm the configuration is correct
- Check whether the FastGPT service startup verification passes, and confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are correctly configured as backend environment variables.
- Import a permission matrix document, check whether the permission mapping results output by the model match the role permission items in the document, and confirm that the values of `temperature` and `maxContext` meet requirements.
- Test a call to a large model that only supports stream mode, check whether streaming responses can be received normally, and confirm that stream mode configuration is enabled.
- View the system audit logs, confirm that there are no unauthorized access-related abnormal prompts in the permission configuration suggestions generated by the model, and verify the effectiveness of the configuration.
