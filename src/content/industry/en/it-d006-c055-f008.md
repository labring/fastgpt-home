# Test Cases and Defect Analysis for Capacity Planning and Resource Scaling: Workflow Orchestration

## What data looks like for this category
Typical users of this category include SREs, cloud platform operations staff, and architects. Data is sourced from cloud bills, monitoring systems, business forecasts, and stress test reports. It is typically updated weekly or monthly.
Daily deliverables include capacity planning reports, scaling applications, resource utilization reports, and budget calculation sheets. Data fields include quantitative items such as resource utilization, peak traffic, and resource allocation limits, with corresponding units including cores, GB, Mbps, and others.
Data sources are dispersed, and document structures are fixed. Accurate matching of field requirements across each workflow link is required.

## What constraints these characteristics impose on workflow orchestration
Dispersed data sources require the workflow to configure multiple nodes to pull content from different data sources such as cloud bills and monitoring systems. This avoids timeout or missing data from a single pull node.
The weekly or monthly data update frequency requires the workflow trigger cycle to match the regular report output rhythm. This prevents excessive frequent execution that wastes resources.
Fixed document structures require the workflow to process data in a preset field order. This ensures parameter matching for subsequent workflow links.
Errors in this category can lead to peak service failures or resource waste. The workflow must configure failure retry and alert notification nodes to handle abnormal scenarios in a timely manner.

## How to set configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Map and configure fields from capacity planning reports and resource utilization reports | Documents in this category have fixed field structures, requiring accurate binding of corresponding data fields |
| `nodeId` | Configure based on the actual IDs of data source nodes and execution nodes | Workflow nodes require unique identifiers to ensure correct execution order |
| Workflow trigger cycle | Every Monday 00:00 | This category has a weekly or monthly data update frequency, matching regular report output rhythms |
| Failure retry count | 3 times | Addresses temporary network fluctuations during data pulling from monitoring systems |
| Timeout threshold | 300 seconds | Adapts to the average time range for pulling data from multiple sources |
| Data source pull limit | Top 5 historical data entries | Adapts to the regular data volume of weekly reports |

## Three common mistakes
- The `variables` reference in the workflow has no selectable values, and global variables cannot be called normally. The cause is that the global variable mapping permission is not enabled in the system configuration, or capacity planning-related fields are not registered as available variables in advance.
- An axioserror is returned when calling the workflow. The cause is that the timeout threshold of the workflow node is set too short, or the data source interface response delay exceeds the configured range.
- Workflow ID format verification fails. The cause is that non-24-bit hexadecimal characters are mistakenly passed as `nodeId`, not following the ID format specifications required by the platform.

## How to confirm successful configuration
- Manually trigger the workflow once, review execution logs for each node, and confirm successful pulling of content from corresponding data sources.
- Enter the `variables` binding page, check that mapped fields fully match those in capacity planning documents, with no omissions or incorrect bindings.
- Verify that the format of `nodeId` is 24-bit hexadecimal characters, ensuring no format errors occur during calls.
- Simulate an abnormal scenario where a data source is temporarily disconnected, confirm that the workflow triggers failure retry and pushes alert notifications to preset recipients.
