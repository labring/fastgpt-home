# Test Cases and Defect Analysis for Object Storage and Backup Services: Citation Sources and Traceability

## What Data for This Category Looks Like
Core data for object storage and backup services comes from object storage consoles, backup systems, access logs, and customer policy tables. Daily maintained documents include bucket configuration files, backup policy documents, recovery record ledgers, and lifecycle rule tables. Data update frequency is usually daily synchronization or real-time updates triggered by policy changes. Fields include bucket names, backup task IDs, recovery durations, permission policy content, file access paths, and more. There is no unified fixed statistical unit; values vary based on specific document types.

## Constraints on Citation Sources and Traceability Posed by These Characteristics
Data sources are scattered across multiple independent systems. Citation traceability requires associating corresponding entries from console configurations, backup logs, and customer policies to avoid cross-system data misalignment. Data updates trigger with policy changes. Traceability links must match the latest bucket or backup rules in real time. Static caching cannot be relied on. Daily document types are diverse. Citations must accurately correspond to specific file paths or task IDs. Broad association with large-category data is not permitted. Error consequences are directly linked to data leaks or recovery failures. Traceability accuracy must strictly match the field formats of business data.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Matches the average length of documents such as bucket configurations and backup policies. Prevents truncation of critical permission policy or recovery path content |
| `responseData` | Return only associated source data | Filters irrelevant information. Focuses on core traceability fields from object storage consoles and backup systems |
| `detail` | Show source file paths and modification times | Corresponds to standard fields in recovery records and access logs. Facilitates quick location of citation sources |
| Maximum number of citation sources per reference | Top 3 entries | Matches the typical number of associated access log entries for a single backup task. Prevents result overload |
| Citation source time verification range | Last 30 days | Matches the typical update cycle of lifecycle rules and backup policies. Ensures timeliness of cited data |
| Citation matching threshold | 0.75–0.85 | Differentiates between different versions of bucket configurations. Prevents incorrect association of similar but non-matching policy content |

## Three Common Configuration Mistakes
- Phenomenon: A `quote type error` error message is returned when calling the interface. Cause: The input variable format does not meet requirements. For example, a numeric backup task ID is mistakenly passed in a non-string format. The field specifications for bucket names and policy IDs are not matched.
- Phenomenon: The generated reply does not display the cited file name or storage path. Cause: The `responseData` configuration item is not enabled. The file path field from the object storage console is not associated. This leads to missing traceability information.
- Phenomenon: Multiple variables cannot be cited simultaneously. For example, results are abnormal when calling both bucket names and backup task IDs at the same time. Cause: Parameters supporting multi-variable association are not configured. Only the single-variable matching logic is enabled by default. This does not cover the association requirements for multi-source data in this category.
