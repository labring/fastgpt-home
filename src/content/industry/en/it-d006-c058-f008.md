# Test Cases and Defect Analysis for Advertising Compliance Recordkeeping: Workflow Orchestration

## What the Data for This Category Looks Like
The data sources for advertising compliance recordkeeping include advertising platform backends, customer qualification documents, contract systems, and publicly available regulatory rules. The update frequency is once per activity per month. Daily processed documents include advertising review forms, qualification attachments, delivery records, and rectification notices. Delivery records must be linked to activity identifiers, qualification attachments must be marked with expiration dates, and rectification notices must be bound to identifiers of corresponding review stages. The data structure adjusts dynamically with the compliance workflow of advertising activities, with no fixed, unified single-scenario format.

## What Constraints These Characteristics Impose on Workflow Orchestration
Pulling data from multiple sources requires that workflows be configured with cross-system connection nodes. This ensures compliance-related documents can be retrieved from different entry points such as advertising platform backends and contract systems. The update frequency tied to activity cycles requires that workflow trigger timing be bound to advertising activity nodes to match activity execution rhythms. The variety of document types requires workflows to handle compliance files in different formats, avoiding data extraction failures caused by format incompatibility. Since errors can lead to regulatory inspections, customer accountability, and account penalties, workflows must be configured with failure retry and exception alert nodes. This ensures the integrity of compliance record retention.

## Configuration Settings
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| `variables` | Include activity ID, compliance status, qualification expiration date | Match the core data fields of advertising compliance recordkeeping to ensure accurate parameters are passed during tool calls |
| `nodeId` | Bind the unique identifier of the compliance data archiving node | Ensure accurate workflow node calls and avoid data confusion across activities |
| Trigger Condition | Trigger within 24 hours after activity completion | Match the update frequency of once per activity per month to avoid unnecessary execution |
| Loop Termination Condition | Terminate when a rectification completion marker is detected | Align with the closed-loop rectification process of compliance recordkeeping and conform to business logic |
| Tool Call Parameters | Only pass compliance data fragments for the current activity | Avoid tool call exceptions caused by redundant parameters and improve execution efficiency |
| Timeout Setting | 600 seconds | Reserve sufficient time to pull data from multiple systems and process documents |

## Three Common Mistakes
- Symptom: The workflow runs normally in preview, but the tool call returns an error after publishing the workflow for unauthenticated access. Cause: Activity-specific compliance data was not correctly bound to the `variables` parameter, causing the parameters received by the tool to not match expected values.
- Symptom: The loop body cannot terminate according to the specified condition, and only executes a fixed number of times. Cause: Conditional judgment logic matching the rectification completion marker was not configured, and the closed-loop node of the compliance process was not correctly linked.
- Symptom: An error occurs when processing qualification attachments in PDF format. Cause: No preprocessing node adapted to multi-format documents was added to the workflow, making it impossible to parse the content of compliance attachments.

## How to Confirm Proper Configuration
- Run the workflow preview in FastGPT v4.17.0, check whether the `variables` parameter includes the compliance data fields of the current activity
- Trigger a simulated activity completion event to confirm that the workflow starts as expected and pulls compliance documents from the corresponding data source
- Inject test data for rectification completion into the loop body to confirm that the loop body terminates normally and proceeds to the subsequent process
- View the workflow run logs to confirm that the tool call parameters match the configured values, with no missing or redundant parameters
