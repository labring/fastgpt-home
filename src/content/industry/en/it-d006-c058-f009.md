# Test Cases and Defect Analysis for Advertising Compliance Logging: Tool Calling and Plugins

## What Data for This Category Looks Like
Data for this category primarily originates from advertising platform backends, customer qualification documents, contract systems, and publicly released regulatory rules. Four core document types are processed daily: advertising review forms, qualification attachments, delivery records, and rectification notices. Data updates follow cycles of single advertising campaigns or calendar months. Advertising review forms include delivery time period and compliance review marker fields. Qualification attachments mark validity periods and issuing authorities. Delivery records retain delivery channels and trigger nodes. Rectification notices link corresponding violation items and rectification requirements.

## Constraints Imposed by These Characteristics for Tool Calling and Plugin Workflows
Data sources for this category are scattered, and update cycles are inconsistent. Tool calling must adapt to multi-source heterogeneous data docking logic to avoid excessive resource usage from frequent full data pulls. The four core document types have fixed formats. Plugins must pre-set extraction rules for corresponding fields to ensure accurate identification of key information such as compliance markers on advertising review forms and validity periods of qualification attachments. Cross-document association needs are prominent. Plugins must bind delivery records and rectification notices to avoid data silos. Regulatory rules update irregularly. Plugins must support dynamic loading of the latest verification logic without requiring reconfiguration each time.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---|---|--- |
| `toolChoice` | `auto` or a specified compliance verification plugin | Adapts to fixed verification scenarios for advertising compliance logging, automatically selecting the appropriate tool to complete verification |
| `functionCall` | `enabled` | Forces the model to call the compliance verification plugin, ensuring key business fields are accurately extracted |
| Plugin data source configuration | Link to three data sources: advertising platform backend, customer qualification library, and contract system | Matches the actual data source paths for this category, covering all core data entry points |
| Field extraction rules | Configure corresponding extraction fields separately for the four document types | Covers the fixed field structure of the core documents for this category, avoiding missing key information |
| Single call data limit | `500 MB` | Adapts to the total document size per campaign cycle for this category, preventing memory overflow |
| Call timeout setting | `300 seconds` | Adapts to the average time required for multi-source data pulls, avoiding call failures due to fluctuations in data volume |

## Three Common Misconfigurations
- Symptom: After calling the compliance verification plugin, the returned result is always `false`, but the plugin starts normally. Cause: The exclusive identifier of the compliance verification plugin is not specified in the `toolChoice` configuration, leading to incorrect tool call matching.
- Symptom: In FastGPT v4.17.0, after saving the plugin editing page, the "Unsaved" prompt continues to display at the top of the page. Cause: Local cache and backend storage of plugin configurations are not synchronized, and the save confirmation status update is not triggered.
- Symptom: When calling the interface to generate a compliance verification index model, the returned model does not match the preset model. Cause: The index model parameter is not fixed in the plugin configuration, causing the default updated model to be used instead.

## How to Verify a Correct Configuration
- Manually trigger a plugin call, and verify whether the returned result includes the compliance identification field of the advertising review form.
- Check the plugin data source configuration page to confirm that the three data sources (advertising platform backend, customer qualification library, and contract system) are linked.
- View plugin call logs in FastGPT v4.17.0 to confirm that frequent timeout errors do not occur.
- Simulate the trigger process after an advertising campaign ends, and verify whether the plugin automatically performs verification according to the preset cycle.
