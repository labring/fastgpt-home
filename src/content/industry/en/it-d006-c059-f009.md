# Test Cases and Defect Analysis for Ad Creative Review: Tool Calling and Plugins

## What Data Looks Like for This Category
Data for this category primarily comes from advertising platforms, landing pages, product qualifications, and advertising law provisions. Update frequency is daily or real-time. Commonly processed documents include ad creative files, landing page screenshots, review opinion forms, and creative modification records. Data fields include creative unique identifiers, violation type tags, review status, modification timestamps, and more. There are no standardized fixed units; values adjust based on the format of the source creative material.

## Constraints on Tool Calling and Plugins
Multi-source real-time data sources require tool calling to adapt to the pull logic of different interfaces such as advertising platforms, landing pages, and product qualifications. It also requires support for low-latency responses to match the real-time update rhythm of reviews. Diverse document types require plugins to support parsing inputs in different formats, including ad creative text, landing page screenshots, and review opinion forms. The one-by-one review business scenario limits the batch size of tool calls, to avoid excessive resource usage from single requests. Errors directly relate to ad account risks, so tool calling must add parameter verification and failure retry mechanisms to reduce misjudgments or missed reviews.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `"auto"` or a specified compliance check tool name | Adapts to the multi-tool collaboration needs of ad creative review, enabling flexible invocation of different types of review plugins |
| Single Request Creative Limit | `Top 10 entries` | Matches the one-by-one review business rhythm, avoids excessive resource usage or timeouts from single requests |
| Failure Retry Count | `2–3 times` | Mitigates temporary fluctuations in third-party interfaces, reduces review process interruptions |
| Timeout Duration | `600 seconds` | Covers time-consuming steps such as landing page pulling and screenshot OCR parsing |
| Result Verification Switch | Enabled | Ensures that violations returned by tools match advertising law provisions, reduces misjudgment or missed review risks |
| `functionCall` | Configure function parameters according to review rules | Accurately triggers dedicated tool functions such as landing page consistency comparison and qualification verification |

## Three Common Configuration Mistakes
- A `connect ECONNREFUSED` error occurs. The cause is that the third-party review tool address configured in the plugin is not correctly mapped, or container network policies restrict port access.
- Tool calling fails for the Qwen2.5 model deployed via Ollama. The cause is that tool calling permissions are not enabled in the model configuration, or tool nodes are not correctly bound to model outputs in the workflow.
- Custom channel Jina rerank service calls fail. The cause is that request headers and interface addresses for the custom channel are not correctly configured, or service authentication rules are not matched.

## How to Verify Successful Configuration
- A single test creative is submitted. Tool calling logs in FastGPT v4.17.0 are reviewed to confirm request parameters match configured items.
- A temporary exception in a third-party interface is simulated. The failure retry mechanism is verified to confirm it triggers as configured.
- Tool return results are compared with manual review opinions. The result verification switch is verified to confirm it is active.
- The plugin monitoring panel is reviewed. Request success rates are confirmed to meet expected business thresholds.

The values listed are common starting points and should be validated against the specific samples used in the target deployment.
