# Test Cases and Defect Analysis for Ad Account Opening Audit: Workflow Orchestration
This document is written for FastGPT v4.17.0.

## What the data for this category looks like
Data for this category primarily comes from ad platform backends, the National Enterprise Credit Information Publicity System, customer-submitted account opening application materials, and industry access rules. Data updates occur daily, or trigger for each account opening application. Daily associated documents include account opening application forms, scanned business licenses, corresponding industry operation qualification documents, and historical account opening audit records. Data fields include the main body's unified social credit code, qualification validity period, application submission time, audit node status, and others. There are no unified fixed units, and some fields must match the format requirements of corresponding qualification documents.

## Constraints Imposed on the Workflow Orchestration Link
Decentralized data sources require the workflow to connect to multiple external interfaces. Configure multiple parallel or serial nodes to call different data sources. Application-triggered updates require the workflow to support on-demand startup. Do not use fixed-period triggering. Mixed processing of multiple document types requires the workflow to include a format verification node. Adapt parsing rules for different qualification documents. The lack of unified unit requirements for fields requires adding a field standardization link during orchestration. This prevents audit logic errors caused by format differences. Historical audit records used as reference data require configuring context association nodes. This ensures audit judgments rely on past compliance cases.

## How to Set Configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Number of data source nodes | No more than 4 | Data sources for this category are decentralized; excessive nodes increase overall call latency |
| Trigger method | Triggered by account opening application submission events | Data updates trigger with each application; fixed-period triggering cannot match real-time requirements |
| Node timeout period | 600 seconds | External data source interfaces typically respond within 10 minutes; 600 seconds covers most abnormal latency scenarios |
| Format verification rules | Set verification items by qualification type | Different industry qualifications have different format requirements; separate rules improve verification accuracy |
| `variables` | Configure the main body's unified social credit code and qualification validity period as global variables | Multiple nodes need to reuse these core fields; global variables reduce repeated configuration |
| `nodeId` | Assign a unique identifier to each data source node | Facilitates tracking node execution status during workflow orchestration and rapid localization during exception troubleshooting |

## Three Common Misconfigurations
- Phenomenon: Form input fields configured in the workflow do not appear during the conversation stage, and the interactive content is empty. Cause: The form fields are not bound to the global `variables`, so the node cannot read user-submitted account opening application information.
- Phenomenon: The advanced orchestration tool cannot automatically select subsequent execution nodes when called. Cause: The trigger logic associated with `nodeId` is not configured, so the workflow cannot identify node execution status to jump to subsequent steps.
- Phenomenon: The file links configured in the AI conversation module and user question items do not take effect, and historical audit records cannot be retrieved. Cause: The file path of the corresponding data source and the historical audit query conditions are not bound to the configuration items, so the module cannot read the target data.

## How to Confirm the Configuration is Correct
- Trigger test: Submit a simulated account opening application. Confirm that the workflow starts and executes all configured nodes according to the submission event.
- Variable verification: View the workflow running log. Confirm that the core fields configured in `variables` have correctly loaded the user-submitted information.
- Node tracking: Check the identifier of each data source node. Confirm that the execution status can be displayed normally in the orchestration interface.
- Interactive verification: Initiate a simulated conversation. Confirm that the form input fields and configuration items of the AI conversation module can be displayed and called normally.
