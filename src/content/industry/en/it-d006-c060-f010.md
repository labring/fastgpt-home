# Test Cases and Defect Analysis for Ad Account Opening Audit: Citation Sources and Traceability

This document is written based on the configuration logic of FastGPT v4.17.0.

## What the data for this category looks like
The core data for ad account opening audit includes account opening applications submitted by customers, business licenses, industry qualification documents, as well as audit records and industry access rules from the advertising platform backend and the National Enterprise Credit Information Publicity System. Data is updated daily or triggered by each account opening application. The document structure includes fields such as subject identification, qualification number, audit status, and there is no unified fixed format, so it needs to be stored classified by submitted material type.

## Constraints imposed by these characteristics on citation sources and traceability
Mixed storage of multi-source data requires the traceability process to accurately match data source types and subject information, to avoid qualification confusion across customers. The high-frequency update feature requires traceability queries to adapt to real-time or near-real-time data source synchronization, to ensure that returned audit records are the latest version. The non-standardized document structure requires traceability displays to retain complete fragments of the original document, to support manual verification. At the same time, the error consequences of this category are directly related to account opening compliance, so the accuracy of traceability must strictly match business rules.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Matches the average length of account opening audit documents, retains complete qualification and audit record fragments |
| `responseData` | `Enabled` | Required to return meta-information of the original data source, including submission channel and update time |
| `detail` | `Complete original document fragment` | Supports viewing the original document content before slicing, for manual qualification verification |
| Data source matching threshold | `0.85–0.90` | Distinguishes qualification materials of different customers, avoids cross-subject matching errors |
| Query timeout setting | `600 seconds` | Adapts to the time consumption of multi-data source queries, avoids interruption of the audit process |

## Three Common Mistakes
- A red numeric error string is returned when initiating a citation query. The cause is that the `responseData` parameter is not correctly configured, resulting in failure to identify the verification identifier of the original data source and generate a compliant traceability link.
- The original document details before slicing cannot be viewed, only simplified content of knowledge base slices can be seen. The cause is that the `detail` configuration item is not enabled, and only the fragment information processed by vectorization is returned.
- The traceability result matches qualification materials of unrelated customers. The cause is that a reasonable data source matching threshold is not set, leading to deviation in similarity calculation and confusing association of qualification files of different subjects.

## How to Confirm the Configuration is Correct
- Initiate a simulated account opening audit query, check whether the returned results include meta-information of the original data source, such as submission source and material type.
- Click the returned traceability link, confirm that the link directs to the original document details page before slicing, to verify that the `detail` configuration takes effect.
- Adjust the data source matching threshold and initiate a query, observe the change in the number of matching results, to verify that the threshold configuration takes effect.
- Test the timeout scenario, confirm that the query is completed within the set 600 seconds or returns a reasonable timeout prompt, to verify that the timeout setting takes effect.

The values provided are common starting points and should be measured against samples from the specific deployment.
