# Test Case and Defect Analysis for Performance Testing and Capacity Evaluation: Tool Calling and Plugins

## What Data for This Category Looks Like
Data sources for performance testing and capacity evaluation include pressure testing platforms, APM monitoring tools, database slow logs, and production traffic baselines. Data update frequency is monthly or upon major version releases. Daily generated documents include pressure testing plans, capacity evaluation reports, pressure testing data records, and optimization suggestion sheets. Data fields include throughput (unit: requests/second), request latency (unit: milliseconds), resource consumption (unit: cores/GB), and peak concurrent count (unit: count). There is no fixed unified format template, and the template must match the pressure testing specifications of the corresponding business.

## What Constraints Do These Characteristics Impose on the Tool Calling and Plugin Link
The dispersed nature of data sources requires plugins to support integration with multiple external tools, and to configure pull permissions and format adaptation rules for different data sources.
The low update frequency but high impact of changes requires plugins to prioritize incremental synchronization mode, to avoid full pull of duplicate data that occupies resources.
The ununified document structure requires plugins to include built-in field mapping logic, to convert raw data returned by external tools into a unified analysis input format.
The most time-consuming step of pressure testing model design and bottleneck identification requires tool calling to support batch processing of pressure testing data, to reduce manual sorting workload and improve analysis efficiency.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | Set to `auto` | Adapt to multi-tool calling scenarios, automatically select tools for pressure testing data pull, APM analysis, and similar tasks |
| Multi-source data pull trigger timing | Trigger after pressure testing task completion | Match the generation rhythm of pressure testing data, avoid pulling data from unfinished tasks |
| Incremental synchronization interval | Every 6 hours | Adapt to monthly update frequency, balance data timeliness and resource consumption |
| Field mapping rules | Directly map by pressure testing data field names | Match the field structure of existing pressure testing documents, reduce conversion costs |
| `functionCall` | Enable parameter verification mode | Ensure fields passed to analysis tools meet requirements, avoid invalid analysis |
| Data verification threshold | Calibrate based on actual measurements | Adapt to pressure testing data standards of different businesses, avoid misjudging abnormal data |

## Three Common Mistakes
- Phenomenon: Analysis results returned by plugin calls do not match original pressure testing data. Cause: The configuration parameters exposed by the plugin are limited, and custom field mapping rules cannot be set, causing the large model to use incorrect fields for analysis.
- Phenomenon: Timeout error occurs after plugin trigger, with duration exceeding 300 seconds. Cause: Incremental synchronization mode is not enabled, full pull of monthly pressure testing data causes excessive request load.
- Phenomenon: Large model calls prompt payment overdue, but API balance is sufficient. Cause: The external tool API key bound to the plugin is configured incorrectly, leading the third-party service to misjudge the scenario as payment overdue.

## How to Confirm Correct Configuration
- Manually trigger a plugin call, check if the returned result includes core performance indicator fields such as throughput and request latency.
- View the plugin logs of FastGPT v4.17.0, confirm that data pull is only triggered after pressure testing tasks are completed, and there are no duplicate request records.
- Submit a simulated pressure testing data set, verify that field mapping is correct, with no missing or misaligned fields.
- Check the API key configuration bound to the plugin, ensure that external tools can normally pull data from pressure testing platforms and APM monitoring tools.
