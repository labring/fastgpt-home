# Test Case and Defect Analysis for Performance Testing and Capacity Evaluation: Model Access and Configuration

## What the Data for This Category Looks Like
The data for this category mainly comes from concurrent request data collected by pressure testing platforms, interface latency and resource occupancy metrics monitored by APM, slow query records from database slow logs, and traffic baseline data from production environments. Daily deliverables include pressure testing plans, capacity evaluation reports, pressure testing data records, and optimization suggestion sheets. Common fields include throughput rate, average latency, peak concurrent count, CPU and memory usage, etc. The update frequency is once per month or after each major software version release.

## What Constraints These Characteristics Impose on the Model Access and Configuration Link
Data sources for this category are scattered and have inconsistent formats. Models must support multiple data types including structured metrics and semi-structured logs. Therefore, model access logic must be adapted to parse multi-source data. Data update rhythms shift with version iterations. Configurations must support dynamic adjustment of the context window to fit pressure testing data from different periods. Performance test results directly relate to production stability. The latency and accuracy of model calls must match the timeliness requirements of pressure testing analysis. Delays in model responses will cause analysis lag.

## How to Set Configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the combined length of pressure testing reports and multi-source logs, avoids truncation of critical metric data |
| `maxTokens` | 4000 token | Controls the output length of single-round analysis, ensures complete defect location conclusions without exceeding interface limits |
| `quoteMaxToken` | 1000 token | Limits the length of referenced pressure testing log fragments, avoids redundant data interfering with analysis |
| `toolChoice` | auto | Allows the model to independently choose whether to call tools to analyze bottleneck metrics, adapts to analysis requirements for different pressure testing scenarios |
| `temperature` | 0.2–0.4 | Reduces output randomness, ensures consistency and accuracy of defect analysis conclusions |
| `AIPROXY_API_ENDPOINT` | Fill in the root address of the AI Proxy service according to the deployment environment, for example http://aiproxy:3000. Do not append /v1 or /chat/completions. Do not fill in single-model service addresses | Required environment variable for the App/Admin server, ensures requests are properly routed to the AI Proxy service |
| `AIPROXY_API_TOKEN` | Non-empty administrator token consistent with the AI Proxy server configuration. Do not use application API keys, model vendor keys, etc. | Required environment variable for the App/Admin server, completes identity verification for the AI Proxy service, prevents unauthorized access |

## Three Common Misconfigurations
- A `400 Bad Request` response is returned during a call, with a prompt indicating context length exceeded. The cause is failure to adjust the `maxContext` parameter based on the actual combined length of pressure testing data, causing the request to exceed the maximum context threshold supported by the model.
- The locally deployed large model cannot be called, and the tool call function fails. The cause is failure to correctly set the `toolChoice` parameter to `auto`, or failure to enable function call support in the proxy service, preventing the model from triggering tool calls for bottleneck location.
- The analysis result deviates significantly from actual pressure testing data. The cause is setting the `temperature` parameter too high, causing excessive randomness in the model's defect conclusions, which cannot match real performance bottlenecks.

## How to Verify That Configurations Are Correct
- Submit an analysis request for small-scale pressure testing data. Check if the interface returns a 200 response code. Confirm that the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` environment variables are correctly configured on the server.
- Review model call logs. Confirm that the `maxContext` and `maxTokens` parameters are correctly included in request parameters, with no truncation or over-limit prompts.
- Submit two analysis tasks with different `temperature` configurations. Compare the consistency of analysis results. Confirm that parameter values meet expectations.
- Trigger an analysis task that includes multi-source data. Check if the model can automatically call tools to complete bottleneck metric location. Confirm that the `toolChoice` configuration takes effect.

The values provided are common starting points and should be evaluated against the reader's own samples.
