# Test Cases and Defect Analysis for Delivery Effect Optimization: Tool Calling and Plugins

## What data for this category looks like
Data for this category mainly comes from advertising platform backends, attribution analysis systems, CRM lead databases, and landing page data terminals. Update cycles are mostly daily or real-time. Daily associated documents include delivery daily and weekly reports, daily price adjustment records, material A/B test tables, and optimization review ledgers. Data fields include impressions, clicks, conversion cost, valid lead count, and more. Units include times, yuan, entries, and others. Each individual data entry is bound to a specific advertising plan, material, and delivery time slot.

## What constraints these characteristics impose on the "tool calling and plugins" link
The scattered data sources and varied formats of this category require the tool calling link to support integration with multiple types of data source plugins, and adapt to the permissions and return formats of different interfaces. The real-time or daily update cycle requires the trigger frequency of plugin calls to match the business adjustment cycle, to avoid redundant calls or data lag. The large differences in daily document structures require tool calling to support parsing inputs in different formats such as text and tables. The specificity of fields and units requires plugin output to complete standardized field mapping, ensuring that data from different sources can be uniformly used for test cases and defect analysis.

## How to set the configurations
For FastGPT v4.17.0, the following configuration items can be set directly in the workflow plugin module:

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Tool call trigger timing | Trigger according to advertising data update nodes | Match the daily/real-time business update cycle, avoid invalid calls |
| `toolChoice` | Auto mode | Adapt to multi-tool linkage scenarios, automatically select the corresponding data source plugin |
| Plugin timeout threshold | 60-120 seconds | Cover the conventional response duration of advertising platform interfaces, avoid process interruption due to network fluctuations |
| Output field mapping rules | Match according to business ledger fields | Align with standard fields of daily reports and price adjustment records, simplify subsequent analysis |
| `functionCall` | Enable mandatory parameter verification | Ensure that the formats of fields such as impressions and conversion cost in plugin inputs are compliant, reduce parsing errors |
| Plugin call retry count | 2-3 times | Respond to temporary fluctuations in advertising platform interfaces, reduce the probability of single call failure |

## Three common mistakes
- Phenomenon: A read exception error is returned when calling the document parsing tool. Cause: The table format of the material test table is not adapted, and the plugin cannot recognize custom fields or merged cell structures.
- Phenomenon: Variables spliced via text do not appear in the return result when calling the workflow via API. Cause: Standardized field mapping rules are not configured, and the format of variable fields does not meet plugin call requirements, resulting in parsing loss.
- Phenomenon: Process interruption occurs when calling plugins in batches. Cause: Reasonable retry times and timeout thresholds are not set, and temporary fluctuations in advertising platform interfaces cannot be handled.

## How to confirm the configuration is complete
- Manually trigger a tool call, check whether the fields in the return result align with the standard fields of the business ledger.
- Call the API interface, verify whether the spliced text contains preset variable content.
- Simulate multiple rounds of calls, observe the success rate of plugin calls and process stability, adjust the configuration to meet business requirements.
- View the tool call log, confirm that the trigger timing matches the business data update node.
