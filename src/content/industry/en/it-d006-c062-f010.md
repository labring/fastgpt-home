# Test Cases and Defect Analysis for Delivery Effect Optimization: Citation Sources and Traceability

## What Data Looks Like for This Category
Data for this category primarily comes from ad platform backends, attribution tracking systems, CRM customer management systems, and landing page analytics tools. Update frequency is typically daily or real-time. Core fields include delivery time periods, cost amounts, conversion volumes, lead IDs, and landing page bounce rates. Units include yuan, counts, percentages, and others. Daily produced documents include daily and weekly delivery reports, price adjustment operation records, material AB test data tables, and optimization review notes. Most documents use a format of structured tables paired with brief text explanations. Some review notes include unstructured adjustment ideas, but core traceability information remains primarily structured fields.

## Constraints on Citation and Traceability
Data sources for this category are scattered and linked to unique identifiers across multiple systems. The traceability link must associate identifiers from different data sources such as ad platforms and attribution systems, to avoid cross-system data confusion. Data update frequency is flexible. Real-time data citations must match the latest status of the current delivery cycle. Daily-level data must clearly mark the statistical time period. Daily documents are mostly structured tables. Traceability requires precise matching of field dimensions in the tables, otherwise corresponding delivery operations or material test results cannot be located. The core goal of delivery effect optimization is to control customer acquisition cost. The accuracy of the traceability link directly determines the effectiveness of adjustment strategies. Therefore, configuration must balance information completeness and retrieval efficiency.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 characters | Matches the single-page structured content length of delivery daily reports and material test sheets, avoids truncating key traceability fields |
| `responseData` | Includes ad platform ID, attribution lead ID, landing page URL | Adapts to the traceability requirements of multiple data sources for this category, ensures citations can associate cross-system unique identifiers |
| `detail` | Enabled | Used to display specific parameters of price adjustment records and material AB tests, matches the viewing logic of optimization review documents |
| Maximum context length | 3000–5000 characters | Adapts to the total content volume of real-time data and daily-level reports, avoids exceeding model processing limits |
| Single search limit | Top 3–5 entries | Controls redundancy of traceability results, focuses on the most relevant delivery adjustments or data records |

## Three Common Misconfigurations
- After connecting the knowledge base via the tool call module, no citation information is output, or the dialogue request interface does not return a cite reference ID. The cause is that the return of citation identifiers and ID fields is not enabled in the `responseData` configuration, resulting in traceability-related data not being passed through the call chain.
- Citation numbers in dialogue outputs appear garbled and are automatically converted to quotation marks. The cause is that the `detail` configuration does not correctly match the document's format encoding, leading to abnormal rendering of special characters.
- When searching for delivery-related questions that do not exist in the knowledge base, file citations are still returned. The cause is that the `quoteMaxToken` configuration value is too large, causing the model to forcibly call unmatched traceability data during content generation, without triggering the empty result filtering logic.

## How to Verify Proper Configuration
- Initiate a query containing delivery consumption or material test content, check whether the returned results include traceability identifiers such as ad platform ID and attribution lead ID.
- Review the citation format in dialogue outputs, confirm there is no garbled text or format abnormalities, and match the enabled status of the `detail` configuration.
- Input a delivery-related question that does not exist in the knowledge base, verify that irrelevant file citations are not returned, and the empty result logic is triggered.
- Call the dialogue request interface, check whether the returned data contains cite-related fields, confirm that the current FastGPT version is v4.17.0 to ensure configuration compatibility.
