# Test Cases and Defect Analysis for Campaign Setup: Tool Calling and Plugins

## What the Data for This Use Case Looks Like
Data for this use case primarily comes from ad platform APIs, enterprise user profile databases, internal budget scheduling sheets, and attribution tools. Core daily deliverables include campaign plans, targeting setting guidelines, budget scheduling sheets, and conversion tracking configuration files.
Data updates occur daily or are triggered per individual campaign. Document fields include targeting dimension parameters, budget amount and cycle, conversion event codes, and more. Some fields must match the required validation rules of the connected ad platform. There is no unified standard format, so adjustments must be made based on the specific ad platform being integrated.
This page is written based on the Tool Calling module of FastGPT v4.17.0.

## What Constraints Do These Characteristics Impose on the Tool Calling and Plugins Workflow?
Dispersed data sources and inconsistent formats require multi-source data format alignment before tool calling can proceed. Parameters must be configured to adapt to the interface specifications of different ad platforms.
Uncertain update frequencies require tool calling to support either on-demand triggering or scheduled pulling of the latest data.
Document fields must match ad platform validation rules. Tool calling input parameters must strictly correspond to the required items of the campaign plan, otherwise interface errors will be triggered.
Differences in conversion tracking configuration fields require plugins to support dynamic field mapping. This prevents campaign plans from failing to start due to field mismatches.
Configuration changes to campaign plans must be synchronized to the tool calling link in real time, to ensure each call uses the latest configuration data.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to scenarios of parallel tool calling in campaign setup, automatically selects tools matching ad platform interface requirements |
| `functionCall` | Enabled | Forces conversion of campaign plan configuration parameters to a standardized function call format to meet ad platform API requirements |
| Session context binding | Bind campaign plan ID | Ensures each API call is associated with configuration data for the same campaign project, preventing session confusion |
| Request timeout | 30–60 seconds | Adapts to the response delay range of ad platform interfaces, avoiding configuration process interruptions due to timeouts |
| Field mapping rules | Set based on actual testing | Matches differences in campaign plan fields across different ad platforms, ensuring input parameter format compliance |
| Retry trigger condition | Trigger only when a 5xx status code is returned | Avoids repeated calls due to temporary interface fluctuations, reducing invalid requests in budget validation steps |

## Three Common Mistakes
1.  Phenomenon: The output of the tool calling module is returned directly to the front-end interface without being hidden according to configuration.
    Cause: The automatic return switch for tool calling results was not disabled, or output filtering rules for `functionCall` were not configured.
2.  Phenomenon: Input text "share" is converted to "fend" when passed to tool calling.
    Cause: Input text encoding validation was not enabled, or the plugin does not adapt to input truncation issues from Chinese input methods.
3.  Phenomenon: The HTTP request component cannot receive numeric parameters passed by the plugin, triggering errors of the form `{"error": {"message": "Request failed with`.
    Cause: Parameter type conversion rules were not configured. Numeric values were passed as strings directly to the interface, causing ad platform interface validation failures.

## How to Confirm Proper Configuration
- Execute a single simulated campaign plan call, and check if the tool calling input parameters fully match the preset budget and targeting configuration.
- After triggering tool calling, verify that the front-end output only returns configuration results, with no redundant tool execution logs.
- Initiate multiple calls for the same campaign plan, confirm that the session context is always bound to the same campaign ID, with no parameter loss.
- Simulate a scenario where the interface returns a 5xx status code, and check if automatic retry is triggered according to the configured rules.

The values provided are common starting points and should be measured against the reader's own samples.
