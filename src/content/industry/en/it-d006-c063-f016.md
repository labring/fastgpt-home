# Test Cases and Defect Analysis for Campaign Setup: Forms and Interactions

## What this category of data looks like
Data for this category comes primarily from ad platform APIs, internal user profile libraries, budget scheduling tables, and attribution tools.
Core daily deliverables include campaign plans, targeting setting rules, budget scheduling tables, and conversion tracking configuration items.
Data updates occur daily, or when a single campaign is launched.
Core fields include target audience dimensions, daily budget amount, conversion event code, and delivery time slot parameters.
Common units are yuan, impressions, hours, and similar.

## What constraints do these characteristics impose on forms and interactions
Scattered data sources require cross-tool synchronization. Forms must support field linkage validation across multiple data sources. This prevents format errors from manual data entry.
Flexible update rhythms require forms to support switching between temporary editing and batch saving. This fits update needs for single campaigns or daily syncs.
Core fields include three strongly linked sets: target audience, budget amount, and conversion event. Any abnormal field will prevent campaign launch. So interactions must include dependency validation rules between fields.
Document structures are layered. Forms must match the document hierarchy. This avoids confusing field levels and reduces filling efficiency.

The following configurations apply to the campaign setup scenario. Some functions must be implemented by external business systems or downstream nodes.

## Three common configuration mistakes
- External business systems or downstream nodes configure file format and size limits for FastGPT's `formInput` node. Uploading non-table files causes parsing failure, with a file format mismatch prompt. The root cause is that supporting documents for campaign plans are mostly budget tables and targeting rule files. Unrestricted formats allow invalid files to consume resources.
- External business systems or downstream nodes configure tag validation logic for FastGPT's `userSelect` node. Manually entered target audience dimensions do not comply with ad platform specifications. This causes campaign launch failure after submission. The root cause is failure to match the ad platform's preset tag library, leading to abnormal field formats.
- After adding a custom plugin node in a FastGPT workflow, external business systems or downstream nodes do not configure input and output parameters. During campaign setup testing, the plugin cannot be called to complete conversion event validation. The interface shows no parameters and no error logs.

## How to verify correct configuration
- Upload a test budget scheduling table. After FastGPT's `formInput` node collects the file, external business systems or downstream nodes check if file content is correctly identified and passed to corresponding downstream nodes.
- Select preset targeting tags. After FastGPT's `userSelect` node receives the selection, external business systems or downstream nodes verify if the budget amount validation rule is updated accordingly.
- Edit the form and wait 300 seconds. External business systems or downstream nodes check if edited content is saved per the configured auto-save logic.
- Add a custom plugin node in a FastGPT workflow. External business systems or downstream nodes configure input and output parameters. Confirm that parameters are correctly displayed in the configuration interface.
