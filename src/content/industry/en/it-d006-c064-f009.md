# Test Cases and Defect Analysis for Tender Document Preparation: Tool Calling and Plugins

## What this category of data looks like
Data for this category is generated around a single tender task. Daily documents include tender documents, qualification certificates, commercial deviation tables, and technical deviation tables. Data sources include tender announcements, tender documents, enterprise qualification databases, and supplier quotations. The update cycle ends when the single task is completed. Documents must strictly match the format requirements of the tenderer, and include qualification response clauses, quotation details, and fields corresponding to scanned qualification documents. There is no universal fixed structure. Content and field order must be adjusted for each round of tender announcements.

## What constraints these characteristics impose on the tool calling and plugins workflow
The data source and format requirements for each single task are not fixed. Tool calling must support dynamically pulling the latest tender announcement and tender document content to adapt to the customized needs of a single task. Documents must strictly match the tenderer’s format requirements. Plugins must support field integrity and format compliance checks for commercial deviation tables and technical deviation tables. Errors directly lead to bid invalidation or margin loss. Tool calling must be embedded in the defect analysis link to perform real-time checks on clause responses and qualification verification results. The differentiated needs of single tasks require plugin configuration to support parameter adjustments per task, without requiring globally fixed settings.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---|---|--- |
| `toolChoice` | `auto` | Adapts to the tool calling logic of FastGPT v4.17.0, supports automatic selection of qualification verification and format check tools |
| Function call trigger timing | After generating 1000 characters of document | Matches the phased writing rhythm of tender documents, prevents excessive content in a single call from causing timeouts |
| Format check plugin call scope | First 3 core deviation table entries | Prioritizes checking key response clauses for commercial and technical aspects, aligns with the review priority of tender documents |
| Tool call timeout threshold | 600 seconds | Covers the average time required from pulling tender announcements to completing qualification verification, determined based on actual testing |
| `functionCall` | Enable mandatory verification mode | Ensures tool call results are directly included in the defect analysis link, prevents unverified content from being added to the final document |

## Three Common Mistakes
- Symptom: A 401 status code is returned when calling the enterprise qualification database tool. Cause: Tool authentication parameters are not configured correctly, and valid access credentials for the corresponding data source are not bound.
- Symptom: Generated technical deviation table fields are empty. Cause: The `functionCall` mandatory verification mode is not enabled, and tool call results are not correctly captured and written to the corresponding document fields.
- Symptom: A plugin call timeout alert is triggered. Cause: A single call pulls all tender announcement content, and the segmented pull configuration is not used, resulting in time exceeding the preset threshold.

## How to Confirm Correct Configuration
- Initiate a small-scale single tender document generation task, check whether the tool call logs include execution records for qualification verification and format checks.
- Manually enter a deviation table entry that does not comply with the tender format, verify whether the plugin triggers a defect alert.
- Check that the tool authentication configuration items are bound to access credentials for the corresponding data source, confirm there are no empty values or invalid keys.
- Adjust the single call content length to 500 characters, verify whether the tool call time is within the preset 600-second range.

The values provided here are common starting points and should be measured against the reader's own samples.
