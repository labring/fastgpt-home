# Test Cases and Defect Analysis for Tender Document Preparation: Source Citation and Traceability

## What the data for this category looks like
The core data for this category is generated around tender-related documents. Four types of documents are routinely produced: tender documents, qualification certificates, business deviation tables, and technical deviation tables.
Data sources include tender announcements, bidding documents, enterprise qualification databases, and supplier quotations. The update frequency is once per order.
Document structures must strictly match the format requirements of the tenderer. Fields include qualification response clauses, quotation details, qualification certificate attachments, and more. These fields must correspond one-to-one with specific requirements in the tender announcement, to ensure no redundant or missing content.

## Constraints on the "source citation and traceability" link
Data sources are scattered and updated per order. Traceability requires precise association with the exclusive data source for the current tender, to avoid mixing data across orders.
Documents must strictly match the tender’s required format. Cited content must correspond to specific clauses in the tender announcement, and sources cannot be replaced arbitrarily.
The consequences of errors are significant. Cited qualification, quotation, and other content must be directly traceable to the original database, to ensure the authenticity of response materials.
When processing multiple documents in parallel, data sources for different tender projects must be distinguished, to avoid cross-project citation errors that affect tender compliance.

## Configuration Settings
This chapter’s configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 characters | Tender document response clauses typically include multiple paragraphs of original text. Sufficient length must be reserved to fully present the original content, and avoid truncating key qualification or quotation information. |
| `responseData` | Return only knowledge base original text | Tender documents must strictly match the original source content. AI-generated decorative content must be avoided, as it can disrupt the format and accuracy required by the tender. |
| Single search limit | Top 5 results | Covers response needs for multiple clauses in the tender announcement. It also controls redundancy in search results, and improves traceability efficiency. |
| `detail` | Enabled | Full display of the citation source’s entry number and original document path is required, to help business personnel verify the compliance of response content. |
| Data source binding rules | Dynamically configured per current tender project | Each tender order corresponds to exclusive tender announcement and enterprise qualification data. This prevents content errors caused by cross-project citation. |

## Three Common Configuration Errors
- When running a workflow test, only the first question node associates with knowledge base citations. Subsequent nodes show no citation results. Cause: The datasetid for the current tender project is not synchronously configured for subsequent retrieval nodes in the workflow’s global variable binding step. This prevents subsequent nodes from calling the correct data source.
- The knowledge base retrieval node cannot reference the pre-configured global datasetid variable. Cause: The node’s variable reference switch is not enabled, or the variable’s scope does not cover the current workflow’s retrieval node. This prevents the variable from being read normally.
- Retrieved content returned includes decorative statements added by AI, which does not meet the strict format requirements of tender documents. Cause: `responseData` is not set to return only knowledge base original text. This leads the AI to perform secondary processing on retrieved content.

## How to Verify Successful Configuration
- Run a response test for a single tender clause. Check if the returned content includes the corresponding original source annotation, to confirm the `detail` configuration is active.
- Call the global datasetid variable. Verify that the retrieval node correctly associates with the exclusive data source for the current tender project, to confirm variable binding is correct.
- Generate a test tender response snippet. Check if the returned content is the original knowledge base text, with no additional decorative content added, to confirm the `responseData` configuration is correct.
- Adjust the value of `quoteMaxToken`. Verify that the length of the returned content matches the needs of the current tender clause, to confirm the parameter configuration aligns with the business scenario.

The values provided here are common starting points. They should be evaluated against the reader’s own samples.
