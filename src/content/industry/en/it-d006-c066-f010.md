# Test Case and Defect Analysis for Search Ad Keyword Management: Citation Sources and Traceability

## What This Category’s Data Looks Like
Core data for search ad keyword management comes from search ad backends, search term reports, bidding ranking data, and landing page data. Daily produced documents include keyword lists, negative keyword tables, bid records, and search term reports. Data update frequencies are mostly daily or weekly. Each document contains fields such as keyword text, bid amount, matching mode, negative keyword status, and search volume. Units include yuan per click, character count, click count, and others. Data centers on user-initiated search terms, and requires linking delivered keywords to actual search behavior. Unique identifiers from different data sources must be uniformly aligned.

## What Constraints Do These Characteristics Impose on Citation and Traceability?
The data characteristics of search ad keyword management impose multiple constraints on the citation traceability process. First, differences in update rhythms across multiple data sources require the traceability system to filter recalled content by data update time, to avoid citing outdated bid records or negative keyword tables. Second, document fields are numerous and association logic is complex. Core fields such as keywords, search terms, and bids must be accurately matched, otherwise traceability results will be disconnected from actual delivery behavior. In addition, data centers on user-initiated search terms, so the correspondence between delivered keywords and actual user search terms must be clearly distinguished, to prevent confusion of delivery configurations across different ad groups. Finally, format differences across documents require the traceability link to retain original typesetting, to facilitate operational staff to verify original data.

## How to Configure Settings
The following configurations are based on the interface and parameter rules of FastGPT v4.17.0, as detailed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Search ad-related documents contain multiple fields, requiring sufficient tokens to carry core information such as keywords, bids, and search term reports, to avoid truncation of critical data |
| `responseData` | Return only associated fields | Focus on core fields such as keywords, bids, matching modes, and negative keyword status, filter out irrelevant system log fields, and improve traceability efficiency |
| `detail` | Enabled | Display matching details between search terms and delivered keywords, to facilitate verification of the correspondence between actual search behavior and delivery configurations |
| Maximum number of context recall entries | Top 6 entries | Search ad keyword lists are usually manageable in scale, and the top 6 entries can cover core associated data, avoiding interference from redundant information |
| Citation source format | Retain original document formatting | Accurately display original typesetting of negative keyword tables and bid records, to facilitate operational staff to verify the integrity of original data |

## Three Common Misconfigurations
- The symptom is unrendered Markdown symbols appearing in context citations. The cause is that the `detail` configuration is not enabled, only raw unprocessed text content is returned, and document formatting is not parsed and rendered.
- The symptom is failure to associate with the specified search term report file. The cause is that the association filtering rule for `responseData` is not configured, irrelevant historical keyword list data is recalled, and the unique identifier of the target document cannot be matched.
- The symptom is failure to hide non-core citation source entries. The cause is that irrelevant fields are not filtered via the `responseData` configuration, resulting in all associated data being forcibly returned, and only core keyword and bid information cannot be displayed.

## How to Verify Correct Configuration
- Upload a keyword list and search term report that include keyword and bid fields, initiate a test query such as "View the corresponding search term report for the current delivered keywords", and check whether the context citations display accurate content of the corresponding fields.
- View the citation source display area, confirm that Markdown format elements such as tables and lists are correctly rendered, and no unprocessed symbols appear.
- Verify the number of citation sources, confirm that it does not exceed the preset maximum number of context recall entries, and there is no redundant irrelevant data.
- After the test query, confirm that the display scope of citation sources can be adjusted via configuration, and only core associated data is retained.

The values given are common starting points and should be measured against the reader's own samples.
