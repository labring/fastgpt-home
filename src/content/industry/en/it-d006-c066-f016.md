# Test Cases and Defect Analysis for Search Ad Keyword Management: Forms and Interactions

## What the Data for This Category Looks Like
Data for this category originates from search ad backends, search term reports, bidding ranking data, and landing page data. Update cycles follow daily and weekly schedules. Daily production creates documents including keyword lists, negative keyword tables, bid records, and search term reports. Core fields include keyword text, match type, single bid amount, negative keyword effective scope, average daily search volume, and conversion cost. Supported units include yuan, occurrences, characters, and others. The data centers on user-initiated search trigger terms, and forms a complete workflow around keyword expansion, filtering, and adjustment.

## Constraints Imposed on Forms and Interactions
This category’s data comes from multiple sources and has scattered fields. FastGPT form input nodes accept input data processed by external business systems. External business systems handle batch import of multiple document types and field mapping logic. External business systems implement specific import processing and field association logic. External business systems manage synchronization triggers, real-time validation, and scheduled pull logic for data with different update frequencies. FastGPT form input nodes only collect input and pass it to subsequent nodes.
Since core data centers on user-initiated search terms, FastGPT form input nodes support relevant interaction configurations. External business systems implement exclusive interaction control logic for keyword match types and negative keyword rules, preventing subsequent ad delivery exceptions caused by incorrect field formats.
External business systems simplify interaction paths for high-frequency operations during the most time-consuming keyword expansion, negative keyword filtering, and bid adjustment processes. External business systems provide operation logs and version rollback entries, facilitating tracing of operation records during defect troubleshooting.

## Three Common Mistakes
- After a form related to search ad keyword management is submitted, subsequent nodes do not receive complete fields. Compare required items, actual submitted content, and node output mapping one by one, then check subsequent interface returns. Existing symptoms alone cannot determine the root cause.
- Configured negative keyword rules do not take effect, and matching results displayed in the backend do not match expectations. The cause is that the selected match type does not match the standard configuration of the ad backend; broad match is mistakenly selected as exact match, resulting in the negative keyword scope not covering target search terms.
- After batch importing bid records, some fields are empty and cannot be saved. The cause is that the form mapping is not configured according to the document field order of the external business system, resulting in the bid amount field not being correctly associated with the data source column.

## How to Confirm Proper Configuration
- Upload a test keyword list, verify that the imported field mapping matches the document classification logic of the external business system.
- Submit a test keyword containing special characters, check whether the format validation prompt from the external business system is triggered.
- Switch the data source sync interval, check whether the synchronization task logs of the external business system execute according to the configured cycle.
- Select different match type options, check whether the matching logic of the ad backend preview interface meets expectations. This verification is based on the form node interaction logic of FastGPT v4.17.0. Business validation and synchronization configuration are implemented by external business systems.
