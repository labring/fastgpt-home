# Test Case and Defect Analysis for Database Cloud Service Operations: Citation Source and Traceability

## What data for this category looks like
Core data for database cloud service operations comes from cloud database consoles, slow logs, monitoring metrics, and ticketing systems. Updates occur daily or when instance changes are triggered. Daily generated documents include instance change orders, backup and recovery records, performance diagnosis reports, and parameter adjustment records. Common data fields include instance identifiers, operation times, operation content, and associated ticket numbers. The overall structure adjusts based on cloud vendor service boundaries, and must align with the export field specifications of the corresponding console.

## What constraints apply to citation source and traceability
Data for database cloud service operations comes from multiple dispersed systems. Cross-source data association rules must be configured for citation traceability, to bind operation records from different systems to the same instance’s change workflow. Data updates occur daily or when instance changes are triggered. Traceability processes must match the latest change timestamps, to avoid citing outdated parameter adjustment or backup and recovery records. Daily documents have no unified mandatory format. The original document’s field mapping logic must be retained, to ensure traceability information directly corresponds to instance identifiers and operation content. Multi-tenant service boundaries also require strictly limiting citation scope, to avoid cross-tenant data confusion.

## How to set configurations
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| `quoteMaxToken` | 1000–1500 token | Matches the average length of database cloud service operation documents such as slow logs and instance change orders, to avoid truncating critical traceability information |
| `responseData` | Enable original document field return | Facilitates direct association with original operation documents including instance change orders and slow logs, to meet traceability query requirements |
| `detail` | Enable full traceability display | Retains complete context of backup and recovery records and parameter adjustment records, to ensure full operation workflows can be viewed |
| Single search limit | Top 8 results | Balances traceability efficiency and data integrity for slow SQL troubleshooting and backup and recovery drills |
| Similarity threshold | 0.75–0.85 | Filters low-match non-target instance data, to avoid unrelated documents being included in the traceability scope |

## Three common misconfigurations
- Phenomenon: Empty traceability information is returned when calling the service, or only partial document fragments are displayed. Cause: The `responseData` configuration item is not correctly enabled, and the original document field return logic is not activated. This prevents extraction of associated instance change orders or slow log content.
- Phenomenon: The AI in the workflow does not reference query results after querying the database. Cause: The `detail` item is not configured to enable full traceability display, or query results are not associated and bound with knowledge base documents. This prevents query data from being included in the citation scope.
- Phenomenon: Timeout and lag occur when calling the service. Cause: The value of `quoteMaxToken` is too large, exceeding the system processing limit. It also does not match the actual length of database cloud service operation documents, leading to context assembly timeout.

## How to verify correct configuration
- Initiate a query for an instance change order. Check if the returned results include associated instance identifiers and operation time fields, to confirm that the `responseData` configuration is effective. This verification process is based on FastGPT v4.17.0.
- Trigger a slow SQL troubleshooting test process. Check if the returned results display the full slow log text, to confirm that the `detail` configuration is enabled.
- Adjust the value range of `quoteMaxToken`, verify that the returned traceability text is not truncated, and matches the actual length of database documents.
- Submit a query request that includes multi-tenant instances. Confirm that the returned results only include document data for the target tenant, to verify that the scope limiting configuration is effective.
