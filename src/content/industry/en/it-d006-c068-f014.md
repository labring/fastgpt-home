# Test Cases and Defect Analysis for Database Cloud Service Operations: Model Integration and Configuration

## What this category's data looks like
Data sources for database cloud service operations typically include cloud database consoles, slow query logs, monitoring metric dashboards, and internal ticket systems. Data updates occur daily or upon each instance change. Daily produced documents include instance change orders, backup and recovery records, performance diagnosis reports, and parameter adjustment records. Data fields include execution duration, error codes, request parameters, CPU usage, connection counts, multi-tenant resource identifiers, and more. Units include milliseconds, percentage, count, and others.

## What constraints these characteristics impose on model integration and configuration
Scattered data sources and multi-tenant identifiers require model integration configuration to support parameter configuration for multiple data source access and tenant permission isolation. Fixed daily document structures and clear fields require model prompts to match field mapping rules for documents such as instance change orders and backup and recovery records. Daily batch or single change-triggered data updates require configuring `maxContext` to adapt to different context windows and cover full update processing scopes. Real-time requirements for slow query logs and performance metrics require setting `maxTokens` to match the maximum length of single log processing. Multi-tenant data isolation requirements require configuring corresponding parameters to distinguish model call permissions for different tenants.

## How to set the configuration
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | Root address of the AI Proxy service, for example http://aiproxy:3000. Do not append /v1 or /chat/completions paths | Required environment variable for FastGPT server to connect to the AI Proxy service |
| `AIPROXY_API_TOKEN` | AI Proxy administrator Token, consistent with the AI Proxy server configuration and cannot be empty | Required environment variable for FastGPT server to connect to the AI Proxy service |
| `maxContext` | 8000–12000 characters | Adapts to the context length of daily updated full operation and maintenance documents and full parameter records for single changes |
| `maxTokens` | 2000–3000 tokens | Matches the single processing length of slow query logs and performance diagnosis reports, avoiding exceeding the model's processing limit |
| `quoteMaxToken` | 500–800 characters | Matches the reference length of a single operation and maintenance document, avoiding redundant references |
| `temperature` | 0.3–0.5 | Used for the rigor of test cases and defect analysis, preventing generated analysis results from deviating from operation and maintenance scenarios |
| `toolChoice` | auto | Adapts to tool call requirements for multiple scenarios, automatically selecting tool calls for operation and maintenance scenarios such as instance changes and backup recovery |

## Three common configuration errors
- A `cannot read properties of undefined (reading)` error appears when creating a new model integration channel. This occurs when required AI Proxy environment variables are not configured, or variable configurations do not meet requirements. The FastGPT server cannot connect to the AI Proxy service normally, and cannot read necessary configuration parameters during interface calls.
- The `vision` parameter is mistakenly enabled for pure-text test case and defect analysis scenarios. This results in no valid model call results or errors. Daily database cloud service operation documents are all in text format, so visual models do not need to be enabled.
- Values set for `maxContext` or `maxTokens` exceed the model's processing limit. This causes context truncation or call timeouts. Values are not set based on average operation and maintenance document length and processing requirements, and excessively large parameter values are used blindly.

## How to confirm the configuration is complete
- Verify that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` configurations match the AI Proxy server settings and are not empty.
- Initiate an analysis test for an instance change order, and confirm that model output analysis results conform to operation and maintenance scenario logic.
- View model call logs, and confirm that `maxContext`, `maxTokens` and `quoteMaxToken` values do not trigger context truncation or redundant prompts.
- Confirm that the `vision` parameter is disabled, or enabled on demand only for scenarios with visual operation and maintenance documents.

The values provided are common starting points and should be measured against the reader's own samples.
