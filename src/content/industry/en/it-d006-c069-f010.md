# Test Case and Defect Analysis for Database Operations: Citation Source and Traceability

## What Data Belongs to This Category
The data in this category mainly comes from database monitoring, audit logs, SQL execution plans, and ticketing systems. It routinely generates documents such as database change orders, slow SQL reports, backup records, and permission application forms. Data is updated either through daily synchronization or in real time as database changes occur. Document fields include change time, affected instances, execution statements, permission scope, backup paths, and more. There is no unified standardized format, and some fields are dynamically adjusted based on operation and maintenance scenarios.

## How These Characteristics Impact Citation Source and Traceability
Database operation and maintenance data sources are mostly structured operation logs and tickets, and document formats are inconsistent. Adapting to multiple data structures is required when performing citation traceability, and general text chunking rules cannot be used directly. The update frequencies of change orders and slow SQL reports vary greatly, so the traceability time range matching mechanism must be dynamically adjusted. Permission application forms involve sensitive data, so additional verification of data desensitization status is required during citation to avoid leakage of permission information. At the same time, database operation and maintenance data has strong field correlation. Ensuring that traceability can associate the complete change chain of the corresponding instance is necessary, as extracting a single text fragment is insufficient to cover complete information.

## Configuration Settings
This page adapts to the configuration logic of FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Maximum Citation Token Count | 800–1200 token | Corresponds to `quoteMaxToken`, matches the single-chunk content length of database operation and maintenance documents to avoid truncating key change statements or SQL execution plans |
| Response Data Format | Structured Traceability Mode | Corresponds to `responseData`, adapts to field association across multiple types of operation and maintenance documents, facilitating extraction of instance, time, and permission information |
| Detail Display Toggle | Enabled | Corresponds to `detail`, displays complete traceable document paths and execution times to meet slow query troubleshooting and change review requirements |
| Single Search Limit | Top 5 entries | Matches the number of core changes and slow SQL queries in daily operations, avoiding redundant results that interfere with analysis |
| Context Cache Duration | 12–24 hours | Adapts to different update rhythms of daily synchronization and real-time changes, balancing response speed and data freshness |
| Sensitive Data Verification | Enabled | Filters sensitive account and path information in permission application forms, complying with operation and maintenance data security specifications |

## Three Common Misconfigurations
- Phenomenon: The returned result shows that knowledge base content is cited, but the actual content is unrelated to professional operation and maintenance documents. Cause: The knowledge base search scope is not limited to database operation and maintenance exclusive data sources, and the general knowledge module covers some professional content.
- Phenomenon: Cited slow SQL statements are truncated, making complete execution logic unviewable. Cause: `quoteMaxToken` is set too low, truncating key parts of long text.
- Phenomenon: After dynamically binding knowledge base search via parameters, the AI response does not display any cited content. Cause: Dynamic parameters are not correctly associated with the data source configuration for knowledge base search, resulting in an empty search scope.

## How to Verify Proper Configuration
- Upload a test slow SQL report, submit a query including "Find the cause of slow SQL for this instance", and check if the returned result associates the corresponding document path and execution time.
- Submit a query including "View details of a certain permission application form", and check if the returned content filters sensitive permission accounts and server path information.
- Adjust the value of the single search limit, and observe if the number of cited results in the returned response matches the set range.
- Trigger a simulated database change query, and check if the traceable content covers the complete chain of change orders, audit logs, and execution plans.

The values provided are common starting points and should be measured against the reader's own samples.
