# Test Cases and Defect Analysis for Data Cleaning and Quality Inspection: Citation Sources and Traceability

## What data in this category looks like
Data for this category comes from raw datasets, ETL logs, annotation platforms, and sampling results, with an update frequency of daily or per batch. Daily produced documents include cleaning rules, quality inspection sampling tables, abnormal data lists, and delivery reports. Raw datasets contain data IDs, field values, and source identifiers. ETL logs record execution times and the number of processed rows. Quality inspection sampling tables label sampling batch numbers and abnormal entries. Abnormal data lists record anomaly types and processing results.

## What constraints do these characteristics impose on the citation sources and traceability workflow
Multi-source data requirements mean the traceability system must associate four types of identifiers: raw datasets, ETL logs, annotation platforms, and sampling results, to avoid fragmented traceability information. The daily or per-batch update rhythm requires traceability to bind batch numbers or timestamps as association bases, ensuring traceability consistency for data from the same batch. The structured nature of daily documents requires traceability to match document versions and processing stages, covering records of key stages such as cleaning rules and exception handling, to ensure defect analysis can be traced back to specific processing actions.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| ---|---|--- |
| `quoteMaxToken` | `800–1200 token` | The typical length of documents such as cleaning rules and abnormal data lists falls within this range, which can fully cover the context required for traceability |
| `responseData` | Includes raw dataset ID, ETL execution timestamp | Business data sources include raw datasets and ETL logs, and both types of identifiers must be associated to complete full traceability |
| `detail` | Enable full traceability | Detailed information from annotation platforms and sampling results must be covered to ensure a complete traceability chain for defect analysis |
| Single traceability upper limit | Top 6 entries | Based on the daily or per-batch update frequency, the number of traceability documents associated with a single batch typically falls within this range, avoiding overload |
| Association matching rule | Match by batch number | Data is updated by batch, and batch numbers are the most clear association identifiers, which can reduce matching errors |
| Traceability timeout threshold | `600 seconds` | The typical time required for single-batch data processing falls within this range, avoiding task failure due to excessive waiting time |

## Three common configuration errors
- Phenomenon: A "parameter not bound" error occurs when triggering traceability. Cause: Local variables were mistakenly used as the upload source for traceability references, and publicly accessible links were not used.
- Phenomenon: Traceability results return empty. Cause: The association matching rule between batch numbers and ETL logs was not configured correctly, resulting in failure to match the corresponding data source.
- Phenomenon: Key content returned by traceability is truncated. Cause: The value set for `quoteMaxToken` is too small, truncating core information from cleaning rules or abnormal data lists.

## How to confirm the configuration is complete
- Upload a cleaning rule document, trigger a traceability test, and check whether the returned results include the document's original source identifier and batch information.
- Check the value of the configuration item `quoteMaxToken` to confirm it falls within the preset range.
- Import an abnormal data list, and verify that traceability can associate the corresponding ETL processing logs and sampling results.
- In FastGPT v4.17.0, test using a batch number as the search condition to confirm that all associated data from the same batch can be matched.

The values provided here are common starting points and should be evaluated against the reader's own samples.
