# Test Cases and Defect Analysis for Data Masking Processing: Citation Sources and Traceability

## What Data in This Category Looks Like
Data for this category primarily comes from enterprise business databases, data dictionaries, data masking execution tools, and access approval systems. Data is updated per project batch or single task. Supporting documents include masking plans, field mapping tables, masking validation reports, and approval records. Data fields include sensitive field identifiers, masking rule codes, validation result statuses, approval workflow nodes, and similar items. No unified fixed units apply; values adjust based on specific business scenarios.

## Constraints on Citation Sources and Traceability
The per-project-batch update pattern of this category of data requires that citation traceability links bind the corresponding project identifier, to prevent data confusion from cross-project citation. The presence of supporting approval records and validation reports requires traceability to synchronously associate compliance approval statuses and masking validation results, to ensure the compliance of cited data. The field design for sensitive field identifiers and masking rule codes requires that only masked data identifiers are displayed during traceability, to avoid leaking original sensitive information. The need to integrate data from multiple sources requires that the traceability entrance uniformly aggregates associated data produced by different tools, to improve traceability efficiency.

## Configuration Settings
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Masked data is typically compressed, so balance between context length and completeness of traceability information |
| `responseData` | `Return only masked citation content and traceability ID` | Avoid leaking original sensitive information in responses, while retaining unique identifiers required for traceability |
| `detail` | `Enable traceability detail display` | Traceability of masked data needs to associate validation reports and approval records; detail display improves compliance check efficiency |
| Citation source display scope | `Filter by project dimension` | This category of data is updated per project batch; filtering by project avoids cross-project data confusion |
| Traceability ID binding rule | `Associate masking task ID and file ID` | The core identifiers of this category of data are masking tasks and corresponding files; binding allows accurate tracing of the original masking process |

## Three Common Misconfigurations
- After batch uploading masked files, some files fail training and duplicate content appears during citation. The cause is failure to group data by project batch during upload, and failure to configure traceability rules for deduplication by task ID.
- Masking validation reports and approval records are not displayed during citation traceability. The cause is failure to enable the detail display configuration for the `detail` parameter, resulting in traceability only returning masked content without associating compliance check data.
- No truncation prompt appears when citation content exceeds the configured length, and the truncated part cannot be traced. The cause is failure to correctly configure boundary checks for `quoteMaxToken`, resulting in truncated content being unable to associate with the original traceability identifier.

## How to Verify Proper Configuration
- Initiate a query containing sensitive field keywords, check that returned content only displays masked identifiers and no original sensitive information.
- View the citation traceability panel, confirm that approval records and masking validation reports for the corresponding project are displayed.
- Adjust the value of `quoteMaxToken`, check that the length of returned citation content changes with the configuration.
- Batch upload masked files from the same project, check that no duplicate content appears during citation.

The values provided are common starting points and should be measured against the reader's own samples.
