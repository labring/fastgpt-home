# Test Cases and Defect Analysis for Data Collection Task Design: Workflow Orchestration

## What This Category of Data Looks Like
This category of data is generated across the full workflow of data collection tasks. Sources include customer requirements, public data sources, collection tool outputs, and internal sample libraries.
Daily deliverable documents include collection plans, sample specification documents, authorization compliance files, and task scheduling tables.
Data update cadence follows project cycles or weekly iterations. Core fields include sample scope definition, collection field specifications, legality verification rules, and task execution nodes.
Data units vary by collection type: text uses character counts, while images use pixel or file size counts for labeling.

## What Constraints Do These Characteristics Impose on Workflow Orchestration
The core data characteristics of collection task design directly restrict workflow orchestration node logic.
Multi-source data requires matching pre-check nodes to ensure uniform formatting across customer requirements, public data sources, and tool outputs.
Data updated per project or weekly needs workflows that support dynamic node parameter adjustments, preventing adaptation failures from fixed configurations.
Repeated confirmation steps for sample scope and field specifications need manual approval nodes inserted into the workflow to reduce subsequent rework risks.
Authorization compliance file checks must be embedded in the pre-flow link to avoid infringement risks.
Unit differences across collection types require workflows to support custom field unit mapping rules.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Preset basic variables by collection type, with support for custom extensions | Adapt dynamic parameter passing for multi-source data, match iteration needs during project cycles |
| Global variable initialization timing | Complete loading 30 seconds before workflow starts | Ensure variables are fully assigned before node calls, avoid null value issues |
| Node timeout threshold | 600 seconds | Adapt long-duration collection legality check links, prevent workflow interruptions from single-node stalls |
| Maximum collection file size | 1000 MB | Match common single-file limits for public data sources, avoid upload failure due to exceeding limits |
| `nodeId` | Bind unique identifiers by node function | Facilitate workflow debugging and log tracing, quickly locate abnormal nodes |
| Manual approval trigger conditions | Trigger when sample scope changes or field specifications are adjusted | Match the most time-consuming confirmation steps, reduce rework probability |

## Three Common Mistakes
- Workflow component custom parameter changes do not take effect, and the default configuration is still displayed after saving and refreshing the page. This happens because the custom parameter is not registered in `variables`, so the configuration is not written to the workflow template.
- The global variable obtained when clicking the button in the data panel component is empty. This happens because the global variable initialization timing is set after node execution, so the variable has not been assigned when called.
- Workflow debugging triggers a "Dangerous behavior" error. FastGPT v4.17.0 and later versions added cross-source data call verification. This error usually occurs when the node configuration contains unauthorized cross-source data calls, or `variables` contains unvalidated sensitive parameters.

## How to Confirm Proper Configuration
- Trigger workflow startup, check whether the parameters defined in `variables` are passed normally across node calls.
- Trigger the approval node for sample scope changes, confirm that the workflow automatically pauses and pushes an approval request.
- Run a timeout threshold test, verify that nodes exceeding the set duration will trigger a workflow interruption prompt.
- View workflow logs, confirm that abnormal nodes bound to `nodeId` will output corresponding error messages accurately.

The values provided are common starting points and should be measured against the reader's own samples.
