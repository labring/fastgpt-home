# Test Cases and Defect Analysis for Data Collection Task Design: Citation Sources and Traceability

## What this category of data looks like
It is typically maintained by data service project managers, collection teams, and customer algorithm teams. Daily documents include four core types of files: collection plans, sample specifications, authorization descriptions, and task schedules. Data sources cover four channels: customer requirements, public data sources, collection tool outputs, and internal sample libraries. Update frequency follows the project cycle or once per week. A single data set includes fields such as sample scope definition, field specifications, collection legality verification records, and task schedules. Field units are dynamically adjusted based on the specific requirements of the collection task.

## What constraints do these characteristics impose on the citation sources and traceability workflow?
The diversity of data sources requires the traceability workflow to accurately mark the original channel of each citation, to avoid confusion between customer requirements, public data, and content produced by collection tools. The update frequency based on project cycles or weekly intervals requires traceability information to be bound to the unique identifier of the corresponding task, ensuring that citations can be traced back to the collection results of the corresponding period. Structural differences across multiple document types require traceability configurations to support association with different types of metadata such as collection plans and authorization descriptions. The high time consumption of collection legality verification requires the traceability workflow to directly link to verification records, reducing the cost of subsequent compliance checks. The risk of sample unavailability and infringement requires traceability information to include clear source and authorization statuses.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Matches the common document fragment length in collection tasks, avoiding truncation of critical traceability information |
| `responseData` | Includes original text links, source document names, and collection times | Covers core traceability and compliance verification requirements in collection tasks |
| `detail` | Enabled | Displays metadata such as collection task authorization descriptions and sample specifications, optimizing citation display effects |
| Maximum number of traceability entries | `Top 3` | Avoids redundant output, aligning with the single-task citation limit for collection tasks |
| Traceability request timeout threshold | `600 seconds` | Matches the document loading duration of collection tasks, preventing premature request termination |
| Traceability link proxy configuration | Synchronized with the project's nginx proxy rules | Ensures traceability links can normally access the collected original documents |

## Three Common Configuration Errors
- A POST request is initiated, the interface connects but no content return value is provided: The cause is that the `responseData` parameter is not correctly configured, and original text fields related to traceability are not specified for return.
- Citation display format is messy and garbled characters appear: The cause is that the output encoding of the collection tool is not matched, and the corresponding encoding rules are not synchronized in the configuration, resulting in abnormal parsing of traceability metadata.
- Traceability links cannot normally download the original text: The cause is that the project's nginx proxy rules are not synchronized to the traceability link generation logic, causing the link to point to an unproxied original address.

## How to Verify a Correct Configuration
- Initiate a test request, check whether the returned content includes fields such as original text links, source document names, and collection times specified by the `responseData` parameter.
- View the displayed citation section, confirm that metadata such as collection task authorization descriptions and sample specifications are displayed, with a clear format and no messy or redundant content.
- Click the traceability link to verify that the corresponding collected original document can be accessed normally.
- Adjust the value of the `quoteMaxToken` parameter, check whether the length of the returned traceability fragment meets the expected configuration requirements.

The values provided are common starting points and should be evaluated against the samples relevant to the specific use case.
