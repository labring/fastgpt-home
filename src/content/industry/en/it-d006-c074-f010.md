# Test Cases and Defect Analysis for Text Annotation Projects: Citation Sources and Traceability

## What the data for this use case looks like
Text annotation project data primarily comes from raw corpora provided by clients, annotation results produced by annotation platforms, supporting vocabularies, and verification results from quality inspection sampling. Core daily deliverables include annotation specification details, sample packages to be annotated, quality inspection reports, and issue feedback forms.
Data update cycles are typically daily updates or synchronized per annotation batch. Core fields include annotated text content, entity tags, intent classification results, quality inspection markers, and traceability IDs. Unlike image annotation projects, this data focuses on semantic-level entity and intent associations.

## Constraints on citation sources and traceability workflows
Data sources are scattered and updated in multiple batches. When traceability is required, raw corpora, annotation operation records, and quality inspection results must be linked. This requires defining unique identification rules for each source of data.
Daily document formats are inconsistent. Field differences between annotation specifications and quality inspection reports increase matching difficulty during traceability.
Uncertain update frequencies require traceability mechanisms to quickly locate data versions by batch or time window, preventing test case failures or defect analysis biases caused by mixed data versions.
The nature of semantic data requires traceability information to retain details of entity and intent associations. Storing only text content cannot meet full traceability requirements.

## Configuration Settings
This guide applies to FastGPT v4.17.0. All configurations follow the interface and parameter rules of this version.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average length of single samples in text annotation projects, avoids truncating core semantic information |
| Citation Matching Threshold | 0.75–0.85 | Aligns with the conventional range of text semantic similarity, reduces false matches or missed matches |
| Single Recall Limit | Top 6 entries | Corresponds to the conventional sampling quantity for quality inspection, avoids introducing excessive irrelevant annotation data |
| Return Traceability Fields | `responseData` includes annotation ID, quality inspection marker | Covers core identification and verification information required for traceability |
| Detail Display Toggle | Enabled | Facilitates viewing full context of annotation sources, supports defect analysis |
| `detail` | Enabled | Supplementally returns timestamp and operator information for annotation operations, enhances traceability accuracy |

## Three Common Misconfigurations
1. Setting `quoteMaxToken` too small causes truncated cited annotation text and empty field errors. This occurs when the value does not match the average length of single samples in the text annotation project, resulting in truncation of core semantic information.
2. Failing to configure `responseData` to return the annotation ID field prevents linking original samples to annotation results during test case execution, leading to traceability failure errors. This happens when core identification information required for traceability is not covered.
3. Failing to bind the dedicated data source for the annotation project causes unavailable options when configuring variable references. This occurs when the annotation platform’s data source is not configured as a citation source, so the system cannot recognize the corresponding variables.

## How to Confirm Successful Configuration
1. Execute a test case for a single annotation sample, check if the returned cited content includes complete annotation text and associated quality inspection markers.
2. Trigger a defect analysis task, verify that traceability IDs can be used to link to original client corpora, annotation operation records, and quality inspection reports.
3. Adjust the value of `quoteMaxToken`, observe the truncation status of cited content, confirm that the value matches the length range of current annotation samples.
4. View the configuration details page, confirm that the required traceability information items for `responseData` and `detail` return fields have been selected.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
