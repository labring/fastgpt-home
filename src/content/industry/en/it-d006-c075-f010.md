# Test Cases and Defect Analysis for Documentation Site Maintenance: Citation Sources and Traceability

## What the data for this category looks like
This category of data primarily comes from code repository commit records, documentation site build logs, end-user feedback, and version release records. Daily produced documents include installation guides, API interface descriptions, version migration manuals, and frequently asked questions. A single document typically includes version identifiers, update times, sample code blocks, and configuration parameter descriptions. The data updates follow weekly iterations or synchronized updates alongside software version releases. Core fields include document version numbers, associated code branches, verification pass markers, and expiration time identifiers.

## What constraints these characteristics impose on citation sources and traceability
Data for this category has scattered sources and frequent updates. Citation traceability must be bound to document version identifiers to prevent configuration misuse from cross-version citations. Daily documents include code examples and interface parameters. The traceability workflow must accurately match the associated branch and parameter version of sample code to prevent sample validation failures. Data updates are synchronized with version releases. The system must automatically pull the latest document content for the current version when generating citations, while retaining the traceability chain for historical versions to meet query needs of users on different versions. User-reported issues must be linked to specific sections of the corresponding document. The traceability workflow must support quickly locating the position of the associated document using problem keywords.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `2000–3000 token` | Matches the average character count of a single document, ensuring cited content fully covers core document explanations |
| `responseData` | Enabled | Returns metadata for cited documents, binding version and update time to meet traceability requirements |
| `detail` | Enabled | Displays the specific section position of the cited document, helping locate the source of issues |
| Number of citation sources displayed | Top 3–5 | Avoids redundant output while covering major reference documents |
| Traceability data cache duration | 7 days | Matches the weekly update rhythm of documents, balancing query efficiency and content timeliness |

## Three Common Mistakes
- Phenomenon: In non-tool call mode, the generated response does not display citation entries for associated documents, only showing a fixed generic citation module at the bottom. Cause: The `responseData` configuration is not enabled, so the system does not grab metadata for associated documents for traceability display.
- Phenomenon: The cited document content does not match the currently used FastGPT version, resulting in errors in interface parameters or installation steps. Cause: Document version identifiers are not bound, and the traceability workflow directly pulls the latest version content without supporting query needs of users on historical versions.
- Phenomenon: Cited document content is truncated and cannot cover complete API descriptions or installation steps. Cause: The `quoteMaxToken` setting value is too small, exceeding the length limit of core content for a single document.

## How to Verify Configurations Are Correctly Set
- Access the knowledge base configuration page for FastGPT v4.17.0, check whether the values for the `quoteMaxToken`, `responseData`, and `detail` configurations meet preset standards.
- Upload a test installation document, initiate an associated query, and verify whether the version, section, and associated information of the corresponding document are displayed at the bottom of the response.
- Switch between different versions of associated knowledge bases to confirm that traceability content automatically matches the currently bound version identifier.
- Adjust the setting for the number of citation sources displayed, verifying that the number of returned citation entries meets configuration requirements.

The values provided are common starting points and should be measured against the reader's own samples.
