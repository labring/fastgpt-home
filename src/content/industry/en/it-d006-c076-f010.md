# Test Case and Defect Analysis for Log Platform and Observability: Citation Sources and Traceability

## What this category of data looks like
Data for this category primarily comes from logging systems, Trace platforms, Metrics systems, and application SDKs. Daily supporting documents include logging collection specifications, link tracing instructions, metric dictionaries, and dashboard configuration records. Data update frequency is typically daily or when a version is released. Log fields include timestamps, request IDs, error codes, and context content. Trace fields include link IDs, node latency, and call relationships. Metrics fields include metric names, sampled values, and statistical dimensions. There are no unified mandatory units for each field, and configurations must match the standards of the corresponding system.

## What constraints do these characteristics impose on the citation sources and traceability link
Dispersed data sources require integrating cross-system associated identifiers such as request IDs and link IDs to complete full traceability, which increases the complexity of cross-system association configuration. Differences in data update frequencies require matching the latest versions of corresponding data during traceability, to avoid referencing outdated collection specifications or dashboard configurations. The existence of multiple types of documents and fields requires clearly specifying the system type of the data source when citing, to prevent confusion between different dimensions of logs, links, and metric data. Additionally, the lack of unified units for fields requires attaching field descriptions from the corresponding system during traceability, to ensure that the referenced context can be accurately verified.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 characters` | Adapts to the model context processing limit of FastGPT v4.17.0, and matches the single context length of log and link data |
| `responseData` | `Fields including link ID, request ID, and file path` | Matches the associated identifiers of multi-system data, ensuring quick correlation of corresponding logs, links, and stored files during traceability |
| `detail` | `Enabled` | Supplements the collection time and source node information of logs, enhancing the credibility of citation traceability |
| Citation Source Classification | `Divided by logging system, Trace platform, and Metrics system` | Distinguishes different types of observability data, avoiding confusion of citation content across different dimensions |
| Version Binding | `Bound to the currently active collection specification version` | Adapts to data update frequencies, ensuring that referenced documents and configurations match the current system version |

## Three common mistakes
- Phenomenon: The dropdown menu only shows a single variable option, and multiple associated log and link variables cannot be selected. Cause: The multi-source data association configuration switch is not enabled, causing the system to only load the variable list for a single type of data.
- Phenomenon: A `quote type error` error message appears in the response. Cause: The format requirements of the corresponding field are not met when citing, for example, passing a string parameter for a link ID to a configuration validation rule that expects a numeric type.
- Phenomenon: The referenced log file address is not displayed in the response. Cause: The `responseData` configuration is not set to include the file path field, or the storage path metadata mapping of the logging system is not associated.

## How to confirm the configuration is complete
- Initiate a test query that includes a known request ID, and check whether the response includes logs, link data, and stored file addresses associated with the corresponding request ID.
- Enter a variable parameter with an incorrect format, and check whether the expected error prompt is triggered to verify that the configuration's validation logic is working.
- View the citation traceability module in the response, and confirm that the displayed document type matches the configured source system type.
- Adjust the value of `quoteMaxToken`, and check whether the length of the context content in the response matches the configured value range.

The values provided are common starting points and should be measured against the reader's own samples.
