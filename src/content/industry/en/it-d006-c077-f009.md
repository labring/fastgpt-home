# Test Cases and Defect Analysis for Computer Room Inspection and Environmental Monitoring: Tool Calling and Plugins

## What Data for This Category Looks Like
Data for this category primarily comes from computer room power and environment monitoring systems, access control platforms, UPS power monitoring devices, and video inspection terminals. Daily generated documents include inspection records, temperature and humidity statistical ledgers, alarm event logs, shift handover logs, and similar materials.
Data update cycles are mostly real-time or daily archiving. Fields include device numbers, monitoring values (such as temperature and humidity in ℃, voltage in V), alarm levels, trigger times, and more. The core focus is on the physical environment of computer rooms and the operating status of on-site facilities.

## What Constraints These Characteristics Impose on Tool Calling and Plugins
Multi-source data access requires tool calling to support integration with different types of third-party monitoring plugins. Authentication parameters for corresponding data sources must be configured in advance.
Real-time updated monitoring data requires tool calling timeout thresholds to be adapted to short-latency scenarios. This avoids losing the latest alarm information due to waiting timeouts.
Structured environment and facility fields require clear mapping rules. This ensures that AI can accurately extract corresponding values when calling tools.
Unstructured content from inspection documents must be paired with document parsing plugins to complete field extraction and anomaly judgment.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to dynamic tool calling requirements in computer room inspection scenarios, automatically selects the plugin matching the current alarm or inspection task |
| Tool Call Timeout | `30 seconds` | The delay tolerance for real-time monitoring data in computer rooms is low. An overly long timeout will cause delayed alarm responses |
| `functionCall` | `enabled` | Forces enabled structured tool calling, to prevent AI from directly generating unstructured responses that lead to missed inspection information |
| Tool Call Retry Count | `1–2 times` | Temporary network fluctuations are common in computer room inspection scenarios. A small number of retries can improve call success rates, while too many retries will delay alarm processing |
| Plugin Authentication Timeout | `60 seconds` | The authentication process for some older monitoring devices takes a long time. Reasonably extending the authentication timeout can avoid normal calls being incorrectly marked as failed |
| Maximum Context Size | `4000 token` | Adapts to the multi-source data splicing requirements related to computer room inspections, to avoid tool call failures caused by context overflow |

## Three Common Misconfigurations
- Symptom: The AI does not trigger tool calls, and directly generates inspection reports or alarm analysis content without real-time data support. Cause: The `functionCall` parameter or tool call switch is not enabled, so the AI cannot recognize scenarios that require calling plugins to pull real-time computer room data.
- Symptom: Tool calls fail, and the interface returns a "call timeout" prompt or empty monitoring data results. Cause: The timeout threshold is not adjusted based on the type of computer room monitoring equipment, and the set timeout period is too short to complete the pulling and parsing of multi-source data.
- Symptom: Fields returned after calling plugins do not match inspection forms, with incorrect numerical units or missing key fields. Cause: No field mapping rules are configured between plugins and computer room monitoring data, and the plugin is called directly using default parameters, resulting in data format incompatibility with inspection documents.

## How to Confirm Configuration Is Complete
- Manually trigger a simulated computer room alarm scenario, and check whether the AI automatically calls the corresponding monitoring plugin to pull real-time data.
- Enter the FastGPT plugin configuration page, confirm that all authentication parameters for computer room data sources have been correctly filled in and have no format errors.
- View the tool call logs, confirm that each triggered tool call returns results that comply with the specifications of computer room monitoring fields.
- Simulate a temporary network fluctuation scenario, verify whether the tool call retry mechanism triggers normally and completes the call.
