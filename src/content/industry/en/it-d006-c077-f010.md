# Test Cases and Defect Analysis for Computer Room Inspection and Environmental Monitoring: Citation Sources and Traceability

## What Data for This Category Looks Like
This category’s data primarily originates from environment and power monitoring systems, access control controllers, UPS monitoring devices, and video inspection terminals. Most updates happen in real time or via daily archiving. Daily generated documents include inspection records, temperature and humidity statistics ledgers, alarm event logs, and shift handover logs. Common data fields include device ID, collection time, temperature and humidity values (units: ℃ and %RH), alarm level, and access record ID. Single record size is small. Total batch data volume grows as computer room scale expands.

## Constraints on Citation Sources and Traceability From These Characteristics
This category has scattered data sources and flexible update rhythms. The citation and traceability link must support cross-system data association and matching. Daily documents are mostly structured tables and time-series logs. Precise retrieval by fields such as device ID and collection time must be supported, without full-text fuzzy matching. High-timeliness real-time data requires time range restrictions during traceability, to avoid citing expired historical records. Single record size is small but total batch volume is large. The number of results per recall must be limited, to prevent redundant information from interfering with analysis. Inspection and alarm data have strong correlations. Traceability must link device status and event timelines simultaneously, to ensure citation completeness.

## How to Configure Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Single computer room inspection and alarm record size is small. Batch recall requires controlling total token usage to avoid exceeding model context limits |
| `responseData` | Enabled | Source data such as inspection logs and temperature and humidity records must be fully displayed to support traceability verification for defect analysis |
| `detail` | Enabled | Details of structured fields such as device ID and collection time must be recalled, to ensure cited information can be accurately verified |
| Single search upper limit | Top 6 entries | Associated records for a single abnormal computer room event usually do not exceed 6 entries. Too many results will interfere with analysis logic |
| Time range restriction | Last 7 days | Aligns with daily inspection and alarm review cycles, to avoid citing expired historical data |
| Chunk separator | Split by title hierarchy | Adapts to the document structure of inspection tables and alarm logs, improving retrieval accuracy |

## Three Common Misconfigurations
- Phenomenon: Embedded pages do not display cited content, or API call results contain no citation fields. Cause: The `responseData` configuration item is not enabled, or configuration parameters are not correctly synchronized to the embedding or API call chain.
- Phenomenon: After dynamically passing knowledge base search parameters, corresponding inspection or alarm data is not recalled. Cause: Retrieval matching rules are not configured according to the structured fields of inspection data, resulting in a search scope that does not match target data.
- Phenomenon: Recalled cited content includes a large number of irrelevant temperature and humidity records. Cause: Reasonable time range restrictions or single search upper limit are not set, resulting in recall of expired or redundant data.

## How to Confirm Configuration Is Correct
- Initiate a query for a known computer room alarm event, and check whether returned results include corresponding alarm logs and inspection records.
- View embedded pages or API returned content, and confirm whether detailed citation source information is displayed.
- Adjust the retrieval time range, and verify whether recall results update correctly with parameter changes.
- Test scenarios with dynamically passed knowledge base parameters, and confirm that relevant data of corresponding computer room devices can be accurately recalled.
