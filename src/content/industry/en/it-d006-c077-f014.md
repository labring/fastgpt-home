# Test Cases and Defect Analysis for Computer Room Inspection and Environmental Monitoring: Model Access and Configuration

## What this category of data looks like
Data sources for computer room inspection and environmental monitoring include power and environment monitoring systems, access control systems, UPS monitoring equipment, and video inspection cameras.
Data update cycles are split into real-time and daily levels.
Real-time data includes immediate alerts and temperature and humidity readings.
Daily level data includes complete inspection reports, duty logs, and archived alert records.
Daily documents primarily use structured tables, with fields such as device ID, temperature and humidity values (units: ℃ and %RH), alert level, and inspection timestamp.
Unstructured video inspection image files are also included alongside these tables.
Data users are IDC on-duty operation and maintenance staff and facility engineers.
The core use case is monitoring continuous operating status and handling abnormalities.

## Constraints Imposed on Model Access and Configuration
The data includes both structured logs and unstructured video images. Model access must therefore support both text reasoning and visual analysis capabilities.
Real-time or daily update cycles require context window configurations adapted to short-cycle incremental data processing. This avoids excessive resource usage from redundant historical data.
Structured documents with multiple fields require clear input field mapping rules for the model. This prevents field confusion or unit recognition errors during parsing.
The high timeliness requirement for exception handling means model call delay must match operation and maintenance response time standards. A failure retry mechanism must also be configured to handle network fluctuations.

## Configuration Settings
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the context length of real-time alerts and historical records for computer room inspections, avoiding truncation of critical operation and maintenance data |
| `vision` | Enabled | Supports parsing abnormal states in video inspection images, covering the reasoning requirements for unstructured data |
| `toolChoice` | auto | Automatically selects appropriate tools to process structured logs and unstructured videos, adapting to multiple types of data sources |
| `temperature` | 0.2–0.4 | Reduces random output, ensuring accurate and stable alert analysis results, matching the strict requirements of operation and maintenance scenarios |
| `quoteMaxToken` | 1000 token | Retains the length of key reference fragments, avoiding redundant references from occupying the context window |
| `AIPROXY_API_ENDPOINT` | Fill in the root address of the AI Proxy service (e.g., http://aiproxy:3000, do not append paths such as /v1 or /chat/completions) | Environment variable configured for FastGPT App/Admin services, used to connect to the AI Proxy service, ensuring service startup and model call connectivity |
| `AIPROXY_API_TOKEN` | Fill in the non-empty administrator token consistent with the AI Proxy server configuration | Environment variable configured for FastGPT App/Admin services, used for identity verification of the AI Proxy service, preventing unauthorized access |
| `maxTokens` | 2000 token | Limits the length of single-round model output, avoiding lengthy analysis that affects operation and maintenance response efficiency |

## Three Common Configuration Mistakes
- Model call fails, with background prompts for connection timeout or service startup verification failure. Troubleshooting steps: Incorrect configuration of server environment variables `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN`, or computer room network restrictions blocking access to the proxy address.
- Model output alert analysis results do not match actual inspection data, with field parsing confusion. This occurs when calling rules for `toolChoice` are not clearly defined, causing the model to not process structured inspection logs per specified field mappings.
- Video inspection images cannot be correctly parsed by the model. This happens when the `vision` parameter is not enabled, or a model interface supporting visual reasoning is not configured.

## How to Verify Successful Configuration
- Access the configured `AIPROXY_API_ENDPOINT` address to verify interface connectivity.
- Upload a structured temperature and humidity alert record and a video inspection image, initiate a model call, and check if the output includes analysis of the corresponding alert and annotations for image abnormal points.
- View model call logs to confirm `maxContext` and `maxTokens` parameter values match the configured settings, with no abnormal truncation.
- Simulate an exception scenario trigger, check that the alert level output by the model matches actual data, and confirm the `temperature` parameter is functioning as intended.

The values provided are common starting points and should be measured against the reader's own samples.
