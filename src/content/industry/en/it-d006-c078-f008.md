# Test Cases and Defect Analysis for Cabinet Installation and Cabling: Workflow Orchestration

## What this category of data entails
This data comes primarily from daily IDC maintenance operations and system logs. Typical users include IDC maintenance engineers, network engineers, and equipment deployment staff. Daily documents include installation application forms, cabinet cabling diagrams, port label sheets, and construction records. Data sources include DCIM systems, asset systems, network topology tools, and customer work orders. Update frequency is once per order or daily. Data fields include cabinet position numbers, port identifiers, cable lengths, customer access requirements, and no unified fixed quantitative statistical metrics.

## Constraints imposed on workflow orchestration by these characteristics
Scattered data sources and high update frequency require workflow orchestration to support multi-data-source `variables` binding, so each node can pull the latest data from its corresponding system. Diverse daily document types require dedicated parsing nodes for each document type to prevent format incompatibility. The most time-consuming steps—cabinet position planning, cable label verification, and installation acceptance—must be split into separate workflow nodes to enable independent debugging and failed retry. Errors directly impact physical connection accuracy, so verification nodes must be embedded in workflows to proactively block risks such as incorrect port connections and blocked heat dissipation.

## Configuration Settings
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Variable Binding | Bind the `variables` fields from DCIM systems, asset systems, and customer work orders | Covers the core data sources for this category, ensuring each workflow node can access the latest cabinet position, port, and work order information |
| Node Trigger Condition | Bind the installation application submission event by `nodeId` | Matches the order-based update frequency of this category, ensuring tasks start immediately after a work order is submitted |
| Failed Retry Configuration | Retry 2 times, with a 60-second interval | Adapts to steps that may experience temporary data delays, such as cable label verification and position verification |
| Task Timeout Threshold | 1200 seconds | Covers time-consuming daily operations such as cabinet position planning and multi-port label verification |
| Verification Threshold | Port label matching degree ≥ 90% | Ensures label verification for physical connections meets business requirements, blocking obviously incorrect wiring operations |

## Three Common Mistakes
- Symptom: Workflow debugging returns content unrelated to cabinet parameters. Cause: `variables` data source binding was not configured correctly, resulting in empty or incorrect incoming variables.
- Symptom: Advanced orchestration node call fails, prompting no valid input. Cause: Node dependencies were not configured in `nodeId` order, causing subsequent operations to trigger before preceding nodes finish generating data.
- Symptom: Workflow cannot pull data from DCIM systems. Cause: Data source environment variables were not configured correctly, resulting in connection failure.

## How to Confirm Proper Configuration
- Trigger a test installation application work order, check whether the `variables`-bound fields in the workflow correctly pull cabinet position numbers, port identifiers, and other information.
- Run the workflow in debug mode, verify that each node executes sequentially in `nodeId` order, with no skipped steps or blockages.
- Simulate a test scenario with mismatched port labels, verify that the failed retry configuration triggers, and that verification completes normally after retries.
- Check task run logs, confirm that the timeout threshold does not trigger unnecessary task termination, and aligns with the time range of daily operations.

The values provided here are common starting points and should be evaluated against the reader's own samples.
