# Test Cases and Defect Analysis for Cabinet Rack Installation and Cabling: Citation Sources and Traceability

## What this category’s data looks like
Typical users are IDC operations engineers, network engineers, and equipment implementation specialists. Daily deliverables include rack installation applications, cabinet cabling diagrams, port label sheets, and construction records. Data sources cover DCIM systems, asset management systems, network topology diagrams, and customer service tickets. Data updates occur per order or daily. Core fields include cabinet slot number, cable type, port correspondence, and construction date. Some fields are text labels with no unified standardized units.

## Constraints for citation sources and traceability
Business data for cabinet rack installation and cabling is dispersed across multiple heterogeneous systems including DCIM and asset management systems. Citation traceability must link to unique work order numbers or device serial numbers to enable cross-verification of references from different sources. Daily documents include structured tables and unstructured drawings. The traceability process must support both structured field matching and position anchoring for drawing fragments. Data updates happen in real time with construction orders. Excessively long historical context may contain expired data. Reference time ranges and total token counts must be limited to avoid introducing outdated slot planning or cabling information. Additionally, core fields have no unified units. Traceability must retain original text labels for fields, and forced standardization conversion is not allowed.

## Configuration settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Similarity Threshold | 0.7–0.85 | Matches structured port fields in cabinet cabling diagrams and defect descriptions in test cases, avoids interference from low-relevance historical work orders |
| `quoteMaxToken` | 800–1200 token | Limits total context per citation round, adapts to single-page drawing or table length of cabinet cabling documents. FastGPT v4.17.0 default value is 1000 token, can be calibrated based on actual testing |
| Single Search Limit | Top 6 entries | Matches core device count for cabinet rack installation, avoids introducing irrelevant data from other cabinets |
| `responseData` | Retain cabinet slot number, port number, construction date fields | Maps core fields of port label sheets, ensures traceability information can be directly linked to original construction records |
| `detail` | Enabled | Displays specific position of cited fragments, such as page 3, paragraph 2 of a cabinet cabling diagram, to help locate defect sources |

## Three common configuration errors
- Symptom: After setting the minimum relevance threshold to 1, search results still contain large volumes of low-relevance non-target cabinet data. Cause: No secondary filtering is performed using structured fields such as cabinet number and port number. Only global semantic similarity matching is used, which cannot distinguish cabling information for different cabinets.
- Symptom: Citation sources appear blank or have no valid links. Cause: The `responseData` parameter is not configured to map core fields of port label sheets, so valid associated information cannot be extracted during traceability.
- Symptom: Search response times out or returns truncated content. Cause: The `quoteMaxToken` value is not limited, causing context length to exceed system limits and triggering timeout or truncation logic.

## How to verify correct configuration
- Generate a simulated port misconnection defect test case, check if the response links to cited fragments of the corresponding cabinet’s cabling diagram and port label sheet.
- Check if traceability information in the response includes core fields such as cabinet slot number and construction date, and can be directly linked to original construction records.
- Adjust the similarity threshold to 0.7, verify that low-relevance non-target cabinet data is filtered out.
- Check token consumption for single-round responses, confirm it does not exceed the `quoteMaxToken` configuration value, and no timeout or truncation occurs.

The values provided are common starting points and should be measured against the reader's own samples.
