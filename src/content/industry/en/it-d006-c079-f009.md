# Test Cases and Defect Analysis for Architecture Design and Technical Solutions: Tool Calling and Plugins

## What Data for This Category Looks Like
Core data for this category originates from historical traffic data, service topology, monitoring metrics, and business growth plans. Regularly produced documents include technical solutions, architecture diagrams, capacity assessment reports, and technical review minutes.
Data is updated once per month, or synchronized with major business requirements.
Document structure includes fields such as dependency descriptions, resource constraint items, and evolution route planning. Architecture diagrams contain structured fields including node IP addresses and port mappings. Technical solution text records constraints and trade-off logic in paragraph form.

## Constraints Imposed by These Characteristics on the Tool Calling and Plugins Link
Since data sources include operation and maintenance metadata such as service topology and monitoring metrics, tool calling must adapt to cross-system metadata pulling permissions. This prevents failure to obtain core test data due to insufficient permissions.
Data updates follow a monthly or on-demand rhythm. Plugin caching strategies must align with this cycle to avoid two issues: frequent pulling increasing system load, or overly long caching causing test cases to use outdated architecture data.
Documents contain mixed-format content: structured architecture diagrams and unstructured review minutes. Tool calling must support multi-format parsing, while reserving sufficient context windows to hold complete solution content.
Additionally, test cases for architecture solutions must verify constraint conditions. Tool calling must be able to associate historical review conclusions with current test logic.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to scenarios requiring multi-tool calls for architecture solutions, automatically selects matching tools to handle tasks such as topology queries and capacity assessments |
| `functionCall` | `[{"name":"query_arch_topology","parameters":{}}]` | Specifies calling the topology query tool for scenarios where architecture design data comes from service topology |
| Tool call timeout | `300 seconds` | Matches the pulling and parsing complexity of architecture solution data, avoids interrupting the test process due to slow queries |
| Plugin cache validity period | `7 days` | Aligns with the monthly statistical cycle of historical traffic data, reduces resource consumption from repeated pulling |
| Multi-format parsing switch | `Enabled` | Adapts to mixed input scenarios of architecture diagrams and technical solution documents, supports parsing vector graphics and text content |
| Context window size | `8000–12000 token` | Accommodates complete architecture review minutes and capacity assessment data, avoids truncating key constraint conditions |

## Three Common Misconfigurations
- Empty service topology data returned after tool call: The cause is failing to correctly specify the query cluster range parameter in the `functionCall` parameter, causing the tool to fail to match the corresponding architecture data.
- Tool call timeout with 504 status code returned: The cause is setting the tool call timeout period too short, failing to adapt to the complex calculation scenario of architecture diagram parsing.
- Test cases failing to reuse historical review constraint conditions: The cause is not configuring context association parameters, causing the tool to fail to obtain the previous round of test conclusions as input prompts.

## How to Confirm Proper Configuration
- View the tool call logs in FastGPT v4.17.0, confirm that the `toolChoice` parameter is `auto` or that the specified `functionCall` name correctly matches the business scenario.
- Trigger an architecture solution test case execution, check whether service topology, monitoring metrics and other data source content can be pulled normally.
- Simulate a slow query scenario, verify whether the tool call timeout configuration takes effect, confirm that the process will not be interrupted prematurely.
- Submit a test case containing an architecture diagram and text solution, confirm that the plugin can correctly parse mixed-format input content.
