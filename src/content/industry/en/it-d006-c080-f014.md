# Test Cases and Defect Analysis for Desktop Terminal Support: Model Access and Configuration

## What this category's data looks like
This category's data primarily comes from terminal management platforms, asset systems, user support channels, and software repositories. Commonly processed documents include terminal trouble tickets, inventory lists, software installation records, and remote assistance records. Each record contains fields such as device ID, fault symptom, operation steps, and resolution result.
Data updates occur via daily batch sync or real-time sync with each terminal maintenance request. There is no fixed statistical cycle; new data is only generated alongside actual maintenance operations. Most data uses unstructured text formats, with some fields being standardized device IDs and operation identifiers.

## Constraints on model access and configuration
Dispersed data sources and varied formats require unified field mapping rules during model access. This integrates terminal data from different systems into input recognizable by the model.
Flexible update frequencies and high real-time requirements demand adaptation to dynamic context lengths, preventing excessive single-request data from exceeding the model's processing limits.
Most daily documents are unstructured text, so appropriate context truncation parameters must be configured to avoid losing key information such as fault symptoms and troubleshooting steps.
The desktop terminal support workflow relies on fast response times. Model call configuration must match the time efficiency requirements of maintenance work, preventing work order backlog caused by excessive waiting periods.

## How to set configurations
In FastGPT v4.17.0, the following configuration items can be set directly on the model access page. `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` must be configured as App/Admin server environment variables, and must not be entered on the model access page.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the typical text length of desktop terminal trouble tickets and remote assistance records, avoiding analysis interruptions caused by context overflow |
| `maxTokens` | 2000 token | Controls the length of single-round replies, matching the information needs of maintenance engineers for quick access to troubleshooting conclusions |
| `quoteMaxToken` | 1000 token | Limits the maximum length of referenced documents such as terminal logs and inventory lists, preventing redundant information from interfering with core analysis |
| `toolChoice` | auto | Allows the model to independently choose whether to call tools, adapting to terminal operation verification scenarios that may be required during fault troubleshooting |
| `temperature` | 0.3–0.5 | Reduces reply randomness, ensuring the accuracy and consistency of fault analysis conclusions |
| `AIPROXY_API_TOKEN` | Fill in the non-empty administrator token consistent with the AI Proxy server configuration | As an App/Admin server environment variable, completes identity verification for the AI Proxy service, preventing request failures caused by unauthorized access |
| `AIPROXY_API_ENDPOINT` | Fill in the root address of the AI Proxy service, for example http://aiproxy:3000. Do not append /v1 or /chat/completions paths | As an App/Admin server environment variable, completes basic access configuration for the AI Proxy service, ensuring correct request routing |

## Three common misconfigurations
- When a model call returns an empty result or does not include expected chain-of-thought intermediate steps, check if the `maxContext` parameter matches the text length of the current processing task.
- When a proxy request returns a 401 Unauthorized error, confirm that `AIPROXY_API_TOKEN` is a non-empty administrator token consistent with the AI Proxy server configuration, and has been set as an App/Admin server environment variable.
- When a proxy request fails to forward normally, confirm that `AIPROXY_API_ENDPOINT` is the root address of the AI Proxy service, with no /v1 or /chat/completions paths appended, and has been set as an App/Admin server environment variable.

## How to confirm correct configuration
- Run a test request, check the field integrity of the returned result, and confirm that key fault information has not been truncated by the context parameter.
- Verify the proxy connection status by using the specified API call tool to initiate a request. Confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` configured as App/Admin server environment variables work normally.
- Adjust the `temperature` parameter and run multiple rounds of tests, confirming that the randomness of replies meets the preset analysis rigor requirements.
- Switch between different model channels, check that the configuration takes effect, and confirm that tool call settings align with fault troubleshooting scenarios.

The values provided are common starting points and should be measured against the reader's own samples.
