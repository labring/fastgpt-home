# Test Cases and Defect Analysis for Channel Attribution and Lead Distribution: Tool Calling and Plugins

## What this category of data looks like
The data for this category mainly comes from advertising platforms, CRM systems, attribution SDKs, and form systems. Daily maintained documents include attribution rule configuration tables, lead distribution tables, channel effect reports, and exception checklists. Common data fields include channel identifiers, lead unique IDs, sales owners, conversion times, budget consumption amounts, and the like. The update frequency is mostly daily or weekly. Data transfer requires matching parameter formats across multiple systems to avoid analysis deviations caused by cross-system field mismatches.

## What constraints these characteristics impose on the tool calling and plugins link
Multi-data source access requires tool calling to be compatible with parameter formats of different systems to avoid cross-system field parsing failures. The daily or weekly data update frequency requires plugin calls to adapt to the execution duration of batch tasks to avoid timeout interruptions. The fixed field structure of attribution rules and lead distribution tables requires plugins to accurately extract specified fields, and cannot flexibly adapt to any non-standard documents. The manual verification requirement in the sales ownership confirmation link requires tool calling to retain complete calling logs for subsequent exception tracing and problem troubleshooting.

## How to Configure
This document is written based on FastGPT v4.17.0. The configuration items and recommendations are as follows:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to the parameter verification requirements of multiple data sources, automatically match the corresponding tool calling logic |
| `functionCall` | `enabled` | Enable structured output to facilitate accurate parsing of specified fields in attribution rules and lead distribution tables |
| Single call data limit | Top 1000 lead records | Match the daily or weekly data update scale, avoid single call timeout |
| Timeout duration | 600 seconds | Adapt to the average response duration of multi-system interface calls, cover batch data processing cycles |
| Number of chat context calls | Top 6 historical records | Retain complete interaction context for attribution and lead distribution, facilitate exception troubleshooting |
| Plugin trigger condition | Trigger based on channel parameter matching | Match channel identifiers in attribution rules, avoid invalid calls |

## Three Common Mistakes
- Phenomenon: Tool calling returns unstructured text, unable to extract channel parameters and sales ownership fields. Cause: The `functionCall` configuration is not enabled, and the output format does not meet field parsing requirements.
- Phenomenon: A plugin node configured with 6 chat history entries in the workflow only returns the first 3 records when triggered. Cause: The context configuration of the plugin node conflicts with the global workflow settings, or the parameter threshold for context calls is not correctly matched.
- Phenomenon: A 504 timeout error occurs during multi-channel parameter verification. Cause: The single call data volume exceeds 1000 records, and the interface response times out due to failure to split batch tasks.

## How to Confirm the Configuration Is Correct
- Trigger a tool call, check if the returned result is in structured JSON format, and verify that the `functionCall` configuration is effective.
- Manually enter a test case containing 6 historical chat records, confirm that the plugin node can fully extract all historical content, and verify that the number of chat context calls configuration is correct.
- Submit a batch call task with 1200 lead records, check if the task is completed within 600 seconds without timeout errors, and verify that the single call data limit and timeout duration configurations are reasonable.
- View the calling logs, confirm that the tool only triggers when channel parameter identifiers are matched, and verify that the plugin trigger condition configuration is correct.
