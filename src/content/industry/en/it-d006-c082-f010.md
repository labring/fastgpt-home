# Test Cases and Defect Analysis for Channel Attribution and Lead Distribution: Citation Sources and Traceability

## What Data for This Category Looks Like
Core data for this category originates from advertising platforms, CRM systems, attribution SDKs, and form systems. Most updates run on a daily or weekly schedule. Daily deliverables include attribution rule documents, lead distribution lists, channel performance reports, and abnormal lead checklists. Data fields include channel ID, lead unique identifier, assigned sales account, conversion timestamp, budget consumption amount, and additional relevant fields. Common units include pieces, yuan, seconds, and others. The data structure centers on two core dimensions: lead source and sales assignment. Field formats differ across various data sources.

## Constraints on Citation Sources and Traceability
Variations in fields across multiple data sources require the traceability process to implement unified format validation rules. This prevents cross-platform data misalignment. Daily or weekly update cycles require the traceability time range to align with the data refresh cycle. Mismatched cycles lead to delayed or invalid data. The core document structure focused on lead source and assignment requires traceability to accurately bind key fields such as channel parameters and sales assignment. This supports abnormal checks and rule validation. The most time-consuming steps, including channel parameter verification and duplicate lead deduplication, require traceability information to include sufficient associated identifiers. This reduces manual verification workload.

## Configuration Guidelines
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `6000–10000 token` | Attribution and lead data includes multi-dimensional fields, requiring sufficient context to carry complete traceability information |
| `responseData` | Return only matching fields | Filter redundant fields from advertising platforms, CRM systems, and other data sources, and focus on core traceability fields such as channel ID and lead assignment |
| `detail` | Enable full-field traceability | Fully retain key information such as channel parameters, conversion time, and budget consumption, to support abnormal checks |
| Single recall count | Top 10 entries | Match the single-batch data volume of daily abnormal checklists, to avoid interference from excessive irrelevant information |
| Context refresh cycle | Match data update rhythm | Adapt to daily or weekly data refresh frequencies, to ensure the timeliness of traceability information |

## Three Common Configuration Errors
- An input error occurs when referencing and executing code in other workflows after creating a plugin. The root cause is incorrect configuration of the `responseData` parameter, resulting in a returned data source format that does not match the expected fields of the workflow code.
- A value between 100 and 900 cannot be selected when setting the citation upper limit. Only the 100 or 900 tier options are available. The root cause is that the system only exposes fixed-tier citation quota configurations by default, and does not support custom interval settings.
- Channel ROI is distorted, but specific attribution rules cannot be traced. The root cause is that full-field traceability via the `detail` parameter is not enabled, resulting in lost associated information that binds channel parameters and attribution rules.

## How to Verify Proper Configuration
- Import a single test lead data entry, and check if the referenced traceability information includes core fields such as channel ID and assigned sales ID.
- Run a test task for a weekly attribution report, and confirm that no critical information truncation appears in the returned context.
- Simulate an abnormal lead scenario, and verify if the error message points to the specific data source and attribution rule.
- Adjust the `quoteMaxToken` parameter, and check if the number of fields carried in the context matches expected values.
