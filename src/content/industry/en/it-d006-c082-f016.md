# Test Cases and Defect Analysis for Channel Attribution and Lead Distribution: Forms and Interactions

## What the data for this category looks like
This category’s data primarily comes from advertising platforms, CRM systems, attribution SDKs, and form systems. Most updates occur on a daily or weekly basis. Daily associated documents include attribution rule configuration tables, lead distribution tables, channel effect reports, and exception checklists. Core fields include channel identifiers, lead source identifiers, conversion timestamps, sales attribution subjects, budget allocation amounts, and more. Fields require flexible configuration based on business scenarios, with no unified fixed length limit.

## What Constraints These Characteristics Impose on the Forms and Interactions Link
Because data sources are numerous and fields are scattered, form input nodes cooperate with external business systems to complete field mapping configuration for multiple data sources, avoiding parameter misalignment. Since update frequencies are fixed, interactions cooperate with external scheduled task systems to complete synchronization task configuration and status display. The accuracy of core fields directly affects business outcomes. Form input nodes cooperate with external verification logic to complete required field verification and exception data interception rule configuration. At the same time, flexible selection of sales attribution rules is supported to reduce manual check time and lower error rates.

## Three Common Mistakes
- Symptom: A field empty error occurs after configuring the `formInput` node in the workflow, and no attribution results are generated after importing test data. Cause: The required channel ID field is not added to the `formInput` node configuration, and verification configuration is not completed with external verification logic, resulting in data failing to flow normally to subsequent nodes.
- Symptom: Duplicate leads appear after lead distribution, triggering sales ownership disputes. Cause: Duplicate verification rules for lead identification fields are not configured with external business systems, resulting in duplicate data being distributed multiple times.
- Symptom: External scheduled synchronization tasks time out, and channel reports are not generated daily. Cause: A reasonable synchronization waiting duration is not set with the external scheduled task system, or the data source interface response time exceeds the externally configured threshold, resulting in task interruption.

## How to Verify Proper Configuration
- After configuring the `formInput` node in the workflow, cooperate with external verification logic to check verification results, and confirm that all required fields pass verification.
- Import a small amount of test data, check whether the `formInput` node displays fields according to the externally configured grouping rules, and whether abnormal data is correctly intercepted by external verification logic.
- Manually trigger a synchronization task with the external scheduled task system, check whether channel reports are generated according to the configured update frequency, and whether abnormal data triggers an alarm via the external alarm system.
- Test the matching logic of sales attribution rules. The matching logic is provided by an external business system, and confirm that the results comply with preset business rules.
