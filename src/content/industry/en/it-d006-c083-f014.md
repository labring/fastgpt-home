# Test Cases and Defect Analysis for Game Content Compliance Self-Check: Model Integration and Configuration

## What Data for This Category Looks Like
Data for this category primarily comes from game text assets such as plot scripts, character lines, and popup copy during game development, as well as art resources including character illustrations and scene art. Content self-check lists, sensitive content modification records, user agreements, compliance review minutes and other documents are generated based on publicly available regulatory compliance requirements.
Data updates follow game version iterations or event launch cycles, with one update per version or event. Structured fields include compliance check tags, modification version numbers, review comments and more.

## What Constraints These Characteristics Impose on Model Integration and Configuration
Data is updated frequently with versions or events, so the system must adapt to variable-length context inputs to avoid check interruptions caused by context overflow. Data includes both text and art resources, so support for both text and vision model integration is required.
Daily documents are mostly structured self-check lists and review minutes, so contextual association of key check fields must be retained. Compliance checks have high accuracy requirements, so balance must be struck between model generation flexibility and the rigor of check results. Stable API integration parameters must also be configured to avoid check process interruptions that disrupt version launch timelines.

## How to Set Configuration
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the context length of game plot text and compliance review minutes, avoiding loss of key historical check records during validation |
| `maxTokens` | 2000–3000 token | Covers single-round compliance check output requirements, ensuring complete return of modification suggestions and defect markers |
| `vision` | Enabled | Supports compliance checks for resources such as character illustrations and scene art, covering art data types beyond text |
| `temperature` | 0.2–0.4 | Reduces randomness of generation results, improving consistency and accuracy of compliance check results |
| `AIPROXY_API_ENDPOINT` | Fill in the root address of the AI Proxy service, for example http://aiproxy:3000. Do not append /v1 or /chat/completions paths. Do not use single-model service addresses such as VLLM/Ollama/Xinference | Root address of the AI Proxy service, ensuring normal connection between the App/Admin service and the AI Proxy service |
| `AIPROXY_API_TOKEN` | Fill in the administrator token consistent with the AI Proxy server configuration. Cannot be empty | Acts as an identity verification credential for the AI Proxy service, ensuring communication security between the App/Admin service and the AI Proxy service |

## Three Common Misconfigurations
- Phenomenon: Redundant text of the model's internal thought process appears in returned results, reducing the readability of compliance reports. Cause: The configuration item that forces output of thought processes in the model system prompt is not disabled.
- Phenomenon: Garbled characters or format errors appear in returned results, making it impossible to properly identify special characters in game text. Cause: The correct character set is not specified in API calls, or non-standard encoding formats of game art resources are not adapted.
- Phenomenon: No compliance check results are returned after uploading images or DOC-format plot scripts. Cause: The `vision` parameter for visual resource parsing is not enabled, or the associated parsing plugin for file uploads is not configured.

## How to Confirm Proper Configuration
- Run a compliance check on a single plot line. Verify that the returned result includes complete defect markers and modification suggestions, with no redundant thought process text.
- Upload a test character illustration image. Confirm that the model returns the corresponding compliance check conclusion, with no garbled characters or missing results.
- Check the App/Admin service startup logs. Confirm that the environment variables for `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are correctly configured, with no startup check failure errors.
- Adjust the `temperature` parameter to 0.3. Run multiple rounds of checks on the same text segment. Confirm that results have no obvious deviations, meeting basic compliance check requirements.

Note: The configuration values listed above are common starting points. Adjust them based on your own specific samples and use cases.
