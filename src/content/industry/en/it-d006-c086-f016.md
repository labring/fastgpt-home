# Test Cases and Defect Analysis for Game License and Publication Declaration: Forms and Interactions

## What Data for This Category Looks Like
Data for this category comes from official administrative service and copyright registration systems, game package files, and operating institution materials. Daily submitted documents include four core types: declaration request files, game application forms, copyright certificates, and review reports. Fields cover declaration subject qualifications, game names and classifications, copyright numbers, review content matching items, and more. Data updates occur once per game declaration, and are adjusted and supplemented irregularly alongside provincial preliminary review feedback. There is no fixed batch update cycle.

## Constraints on Forms and Interactions
Multi-source data means external business systems must implement cross-system field association verification separately after FastGPT’s `formInput` node collects input, to avoid inconsistent materials. The four core documents have differentiated structures, so external business systems must implement template switching and custom field expansion separately to adapt to information submission for different declaration scenarios. Irregular data updates require external business systems to reserve adjustable form field space, without modifying FastGPT node underlying configurations during every iteration. Severe approval failure consequences require external business systems to complete real-time key field verification during the filling stage, to avoid errors in advance.

## Three Common Mistakes
- A "field format mismatch" error appears after submitting the declaration form collected by FastGPT’s `formInput` node. This occurs because the external business system has not configured the corresponding field format verification rules, or the copyright certificate number has not been filled in the format required by the official authority.
- The account of the provincial preliminary review liaison position cannot edit the preliminary review opinion field of the declaration form. This occurs because the external business system has not configured the corresponding job permission group, and the corresponding role has not been granted the corresponding editing permission.
- Request timeout occurs when importing multiple declaration materials in batches. This occurs because the external business system has not set a reasonable timeout retry configuration, and the request duration exceeds the system limit, resulting in failed data import.

## How to Confirm Configuration Is Complete
- Fill in the fields marked as required in FastGPT’s `formInput` node, and no error prompt appears after triggering the external business system’s field verification. This confirms the required field configuration and format verification rules are effective.
- Switch to the account of the legal review position, and confirm only the review report and compliance fields associated with FastGPT’s `formInput` node can be edited. This verifies the external business system’s job permission configuration is correct.
- Import a declaration template file that meets the format requirements, and confirm the data can be normally loaded into FastGPT’s `formInput` node and match the corresponding fields. This verifies the external business system’s cross-data source association configuration is effective.
- Simulate the submission process and wait for 600 seconds, and confirm no timeout error appears. This verifies the external business system’s timeout retry configuration is effective.
