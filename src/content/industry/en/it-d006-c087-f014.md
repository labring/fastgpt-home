# Game Design and Numerical Tuning Test Cases and Defect Analysis: Model Integration and Configuration

## What the data for this category looks like
Daily documents for this category include gameplay design documents, numerical tables, version requirement sheets, and balance test records. Data sources include player behavior data, public competitor materials, battle logs, and version feedback. Update frequency is weekly or per version cycle. Most data fields include rule descriptions, numerical parameters, trigger conditions, effective ranges, and similar content. Units involve damage values, growth coefficients, retention rates, and other metrics. The document structure centers on rule breakdown and numerical correlation, with overall characteristics of both semi-structured text and structured numerical data.

## What constraints these characteristics impose on the model integration and configuration phase
Daily documents for this category primarily consist of semi-structured gameplay rules and numerical tables, with data updated weekly or per version cycle. This requires models to support long-context parsing and dynamic content synchronization when integrated. Multi-source data including player behavior data and battle logs contains timed trigger conditions and effective parameters. Models must support context integration across multiple data sources. Significant differences exist in the unit specifications of numerical table fields. Models must accurately identify and verify the compliance of numerical parameters. Additionally, test case and defect analysis results directly relate to version launch risk. The traceability and accuracy of model outputs must align with business strictness requirements.

## How to set the configurations
This document applies to FastGPT v4.17.0. The following are configuration recommendations for this category:

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to context requirements for long documents such as gameplay design documents and balance test records |
| `maxTokens` | 2000–3000 token | Meets output length requirements for numerical simulation and rule breakdown |
| `vision` | Enabled | Used to parse image-format numerical tables, battle log screenshots, and similar assets |
| `temperature` | 0.2–0.4 | Reduces random output to ensure accuracy of numerical calculations and rule descriptions |
| `toolChoice` | auto | Automatically calls tools to complete numerical simulation and aggregation of version feedback data |
| `AIPROXY_API_TOKEN` (server environment variable, not a model configuration item) | AI Proxy administrator token, consistent with AI Proxy server configuration and not empty | Used for identity verification between the App/Admin server and AI Proxy service. This is a required item; missing configuration will cause startup verification failure |

## Three common configuration mistakes
- 400 format errors returned when calling a vision model, even when using PNG format images. Verifiable troubleshooting items: Check if the `vision` parameter is not enabled, or if the latest platform image format verification rules are not followed.
- Empty streaming response when calling tools with a deployed open-source model. Verifiable troubleshooting items: Check if the `toolChoice` parameter is not configured as auto, or if tool call support is not enabled during model deployment.
- Large deviations in numerical analysis results after configuring model parameters. Verifiable troubleshooting items: Check if the `temperature` parameter value is too high, causing random deviations in rule breakdown and numerical calculations.

## How to confirm successful configuration
- Upload a typical numerical table or gameplay design document, and verify that the model can correctly parse the fields and numerical units contained within.
- Call tools to complete one numerical simulation test, and confirm that the model can normally return structured simulation results.
- View the model call logs, and confirm that the actual call values of parameters such as `maxContext` and `maxTokens` match the configured values.
- Test the vision input function, upload a PNG-format battle log screenshot, and confirm that the model can correctly extract the text content contained within.
