# Test Cases and Defect Analysis for Game Operation Activity Configuration: Tool Calling and Plugins

## What Data for This Category Looks Like
This type of data typically comes from game operation backends, player segmentation systems, paid data platforms, and activity log systems. Daily produced documents include activity plans, reward configuration tables, launch checklists, and activity review reports. Document fields include activity ID, effective time period, reward type and value, trigger rules, and more. Common units are times, yuan, minutes, and percentage. Data update frequency is usually weekly, or adjusted temporarily before holiday activities. A single configuration involves many fields and connects upstream and downstream processes. Errors in any field may affect activity execution results.

## What Constraints Do These Characteristics Impose on the Tool Calling and Plugins Link
Decentralized data sources require tool calling to integrate with multiple types of interfaces. Teams must configure call order and permissions for multiple tools. The large number of closely linked document fields requires parameter validation during tool calling to cover all fields. This avoids configuration failures caused by format errors. Unfixed update frequencies require avoiding fixed caching of old data, and supporting dynamic loading of the latest activity configuration data. Error consequences affect player experience and revenue. Tool calling must include failure retry, exception capture, and alert mechanisms to ensure the accuracy of configuration verification. In addition, game operation activities have strong timeliness. Tool calling must be completed before the activity goes live, which imposes clear requirements for call duration and response speed.

## How to Set the Configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to the multi-tool automatic scheduling workflow for operation activity configuration |
| Maximum number of tools called in a single run | First 3 | Match the number of core links involved in operation activity configuration |
| Tool call timeout period | 600 seconds | Cover the time required to pull and verify data from multiple data sources |
| Parameter validation trigger method | Automatic validation before call | Intercept field format errors in advance |
| Number of failure retries | 2 | Address temporary network fluctuations and interface jitter |
| `functionCall` | Bind activity configuration table fields | Ensure tool call parameters are consistent with the format of operation data |

These configurations apply to FastGPT v4.17.0.

## Three Common Misconfigurations
- Returned fields are empty after calling an MCP tool. This occurs because the corresponding fields in the activity configuration table are not bound, preventing the tool from obtaining correct operation data.
- The LLM cannot call multiple MCP tools in sequence. This occurs because `toolChoice` is not set to auto mode, or the dependency order of tool calls is not explicitly configured.
- The platform fails to start after upgrading FastGPT-MCP-Server. This occurs because compatible configuration for the FastGPT core version is not updated synchronously, resulting in service port conflicts or dependent version mismatches.

## How to Confirm the Configuration Is Correct
- Initiate a single tool call test, verify whether the returned results match the fields in the activity configuration table, and adjust parameter matching rules until they align.
- Simulate a multi-tool call workflow, verify whether tools execute in the preset order, and check whether the input and output of each step meet the requirements of the operation document.
- Trigger a tool call timeout scenario, verify whether the failure retry mechanism works, and confirm that the configured retry times and timeout period meet actual needs.
- After upgrading the MCP service, check platform logs for port conflicts or dependency errors, and confirm that the version compatible configuration is correct.

The values listed here are common starting points and should be evaluated against the reader's own samples.
