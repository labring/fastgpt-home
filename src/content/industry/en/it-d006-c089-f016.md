# Test Case and Defect Analysis for Vulnerability Scanning Services: Forms and Interactions

## What data for this category includes
Vulnerability scanning service data primarily comes from vulnerability scanners, asset inventories, CVE databases, and patch bulletins. Daily produced documents include scan plans, vulnerability lists, remediation tickets, and rescan reports. Core fields include asset scope, CVE ID, vulnerability severity, remediation status, and rescan time.
Data update frequency is weekly or monthly. Sync rhythms differ across asset and vulnerability databases. Fields in documents must strictly align with requirements of scanning tools and security operations workflows to ensure data consistency and traceability.

## Constraints on forms and interactions workflows
Data sources are scattered, and multiple security document formats must be matched. Forms must receive asset inventory data imported from external asset systems, and receive vulnerability filtering criteria output by external filtering logic.
The weekly or monthly data update rhythm requires scan triggering logic to run via an external scheduled scheduling system. This avoids frequent scans impacting business peak hours.
The strong correlation between core fields requires external business systems to group and display form-collected content per security operations workflows. For example, configure scan scope before setting vulnerability filtering rules.
High-severity vulnerability exposure risks require mandatory field and data validity checks in subsequent nodes. This prevents security risks caused by missing critical configuration.

## Three Common Configuration Errors
- Symptom: Vulnerability scanning form displays "No valid vulnerability library associated" after submission. Verification steps: Confirm subsequent retrieval nodes use a valid CVE library source, confirm the form correctly passes vulnerability library association parameters
- Symptom: Scheduled scan task does not run at the scheduled time. Verification steps: Check trigger time settings in the external scheduled scheduling system, confirm the form correctly passes triggering configuration parameters
- Symptom: Rescan result vulnerability count does not match initial scan results. Verification steps: Check external asset scope filtering logic configuration, confirm classification rules in subsequent data comparison nodes are correct

## How to Verify Correct Configuration
- Submit a test small asset inventory via the external asset import interface. Confirm the selected asset scope is normally received and displayed after form submission.
- Call the external scanning service interface to trigger a single scan task. Confirm the task starts normally and generates an initial scan plan document.
- View the external vulnerability retrieval node. Confirm the correct CVE library source is associated, and preset test vulnerability information can be retrieved.
- Check configuration items in the external scheduled scheduling system. Confirm trigger times are set per business requirements and do not conflict with peak business hours.
