# Test Cases and Defect Analysis for Player Customer Service and Public Opinion Processing: Tool Calling and Plugins

## Data structure and sources for this category
The data for this category comes mainly from game customer service systems, community forums, app store reviews, and game runtime logs. Daily processed documents include player tickets, compensation requests, public opinion daily reports, and standardized response scripts. Most data updates run daily or in real time, with immediate updates triggered by player feedback. Each individual feedback forms the basic document unit, including fields such as feedback subject, problem type, associated account information, and processing progress. No fixed unified format exists, and field dimensions must be adjusted based on the feedback scenario.

## Constraints imposed on tool calling and plugins
Decentralized data sources and inconsistent formats require tool calling to support multi-source data pulling and adaptation, and avoid hard-coded fixed fields. Real-time updated public opinion and tickets require tool calling to deliver low-latency responses, with timeout thresholds adapted to real-time scenarios. Mixed processing of multiple document types requires plugin configurations to flexibly switch parsing rules for different documents, and avoid using a single parsing logic for all scenarios. The immediacy of player feedback requires tool calling triggers to bind to input keywords or feedback types, and ensure problem responses match the pace of player demands.

## How to set the configuration
This configuration uses FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports automatic tool selection for multiple feedback types including player tickets and public opinion |
| `functionCall` | Allow active invocation | Enables triggering custom interface responses based on input keywords |
| Plugin call timeout | 10-15 seconds | Matches low-latency response requirements for player customer service scenarios |
| Multi-source data pull interval | 30-60 seconds | Adapts to mixed daily and real-time data update rhythms |
| Keyword matching rules | Calibrated via actual testing | Adapts to keyword recognition for different player feedback scenarios |
| Tool calling trigger condition | Bound to player feedback type tags | Aligns with ticket and public opinion classification logic for this category |

## Three common misconfigurations
- Phenomenon: After configuring `functionCall`, specified keywords do not trigger the custom interface, and a default response is returned instead. Cause: Keywords are not bound to the tool calling trigger rule, only the global switch is enabled.
- Phenomenon: Plugin calls return timeout errors with no valid processing results. Cause: The plugin call timeout is set too short, unable to adapt to the response delay of the associated interface.
- Phenomenon: Pulled customer service ticket data has missing fields, making account verification or compensation rule judgment impossible. Cause: Multi-source data field differences are not adapted, and dynamic field mapping rules are not configured for the plugin.

## How to confirm correct configuration
- Input preset player feedback keywords, check if the bound custom plugin interface triggers, and verify that `toolChoice` and `functionCall` configurations take effect.
- Simulate delayed requests, check if the plugin call timeout meets the preset threshold, with no timeout errors.
- Pull test data from different sources, confirm that the plugin adapts to multi-source document field structures with no missing fields.
- View tool calling logs, confirm that trigger logic matches configured keywords or feedback type tags.
