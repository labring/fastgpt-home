# Test Cases and Defect Analysis for On-Site Deployment: Workflow Orchestration

## What the data for this category looks like
Data for this category primarily originates from customer on-site machine room environments, equipment inventories, software installation packages, and network topology diagrams. Daily supporting documentation includes deployment manuals, installation records, configuration lists, and on-site check-in logs. Data is updated once per completed phase or order. Core fields include environment inspection items, software version numbers, configuration parameter values, and problem troubleshooting records. No fixed unified format exists, and adjustments are made based on differences in individual customer on-site environments.

## How These Characteristics Impact Workflow Orchestration
Data for this category relies on real-time on-site environment collection, and supporting documents have no fixed unified format. As a result, workflow orchestration must adapt to dynamically input environment parameters.
The data update rhythm varies by phase or order, requiring the workflow to support on-demand node updates and parameter synchronization.
On-site problem troubleshooting is the most time-consuming core link. Workflows must include preset standardized troubleshooting nodes, while retaining flexible adjustment options to accommodate different customers’ equipment and software combinations.
The non-standard nature of supporting documents requires workflows to associate multiple document types as input sources, avoiding hard-coded fixed fields.

## Configuration Settings
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| Variable Reference Scope | Only bind customer environment documents associated with the current order | Data for this category only comes from the environment and documents of the current on-site order, preventing cross-order data contamination |
| Node Trigger Condition | Trigger based on environment inspection results in `variables` | Node execution order must be dynamically adjusted based on real-time on-site environment parameters, and `variables` can carry dynamically collected environment data |
| Single Troubleshooting Node Timeout | 300–600 seconds | Conventional time range for on-site environment inspection and software installation configuration, calibrated based on actual measurements |
| Knowledge Base Association Scope | Only select deployment manuals and configuration lists bound to the current order | Data for this category only associates exclusive documents of the current on-site order, avoiding interference from irrelevant knowledge bases |
| Node ID Binding Rule | Bind the on-site deployment node `nodeId` of the current order | Must accurately associate the specific node of the current on-site deployment to avoid cross-node confusion |
| Workflow Status Synchronization Frequency | Synchronize once per completed node | Must record each step of on-site deployment progress in real time to facilitate subsequent problem tracing |

## Three Common Misconfigurations
- Phenomenon: Dynamically bound customer documents cannot be referenced using `variables` when selecting a knowledge base, requiring manual knowledge base switching for each deployment. Cause: The permission to bind knowledge bases with variables in FastGPT v4.17.0 workflow configuration is not enabled, and only fixed selection of preset knowledge bases is supported.
- Phenomenon: Responses from multiple AI chat nodes in the workflow are all aggregated in the final chat conversation, making it impossible to distinguish the execution results of each individual node. Cause: Independent output context isolation is not configured for each AI chat node, causing responses from all nodes to be unifiedly aggregated.
- Phenomenon: Timeout errors with status code 504 occur during workflow execution. Cause: The timeout setting for a single troubleshooting node is too short, not matching the actual time required for on-site environment inspection or software installation.

## How to Verify Proper Configuration
- Trigger a workflow test, input simulated customer environment parameters, and confirm whether the knowledge base is only bound to documents of the current test order.
- Execute multiple AI chat nodes, check that each reply is displayed independently with no cross-node result aggregation.
- Simulate a timeout scenario to verify that the workflow completes node execution within the set timeout period.
- View workflow logs to confirm whether parameters in `variables` and `nodeId` are correctly passed to each configuration node.

The values provided are common starting points and should be evaluated against the reader's own samples.
