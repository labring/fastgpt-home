# Test Cases and Defect Analysis for On-Site Deployment: Tool Calling and Plugins

## What this category of data looks like
This category of data originates from customer data center environments, device inventories, software packages, and network topologies. Structured documentation is compiled daily using deployment manuals, installation records, configuration lists, and on-site check-in logs. Data is updated per order or phase, synchronized with the progression of on-site deployment workflows. Core fields include device identifiers, software versions, configuration parameters, and network connectivity status. No unified standardized field template exists; adjustments must be made based on the customer’s on-site environment.

## Constraints on tool calling and plugins workflows
Data sources are scattered and rely on the customer’s real-time on-site environment. Tool calling must support pulling and parsing multi-source heterogeneous data, and cannot rely on fixed global data source templates. The per-order or per-phase data update requirement means plugin configurations must support single-instance customization. This avoids global rules overriding different customers’ deployment needs. The non-standardized structure of daily documentation requires tools to support content extraction from deployment manuals and configuration lists in various formats. The high time consumption of on-site problem troubleshooting requires plugins to integrate automated environment verification and log parsing capabilities. This reduces manual troubleshooting costs.

## How to set configurations

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to dynamically changing tool calling requirements during on-site deployment, no manual tool type specification needed, matches the default calling logic of FastGPT v4.17.0 |
| `functionCall` | `enabled` | Supports structured parameter transfer for test cases and defect analysis scenarios, matches the field format of deployment documents |
| Plugin authentication configuration | Based on customer data center IP whitelists, validity period bound to a single deployment phase | Matches temporary access needs of on-site deployment, avoids security risks from global authentication |
| MCP format adaptation | Map to the field structure of the deployment manual, set timeout threshold to 300 seconds | Adapts to the structured format of customer on-site device inventories, timeout threshold covers conventional network delay ranges |
| Code execution trigger | Only trigger after configuration list verification passes, single execution duration no more than 600 seconds | Prevents code execution when environment configuration is incomplete, limits execution duration to avoid excessive resource usage |
| Plugin call frequency limit | No more than 20 calls per 10 minutes | Matches the per-phase operation rhythm of on-site deployment, avoids triggering platform call restrictions |

## Three common errors
- Phenomenon: Calling the MCP format interface returns a 403 status code. Cause: The customer data center IP was not added to the FastGPT plugin whitelist configuration, and the authentication rules do not match the temporary access needs of on-site deployment.
- Phenomenon: Tool calling returns an empty result. Cause: MCP format parameters were not mapped according to the field structure of the deployment manual, causing the plugin to fail to recognize valid fields in the configuration list.
- Phenomenon: Automatically executed code does not produce expected results. Cause: Code execution was not triggered after configuration list verification passed, early execution caused dependent environment configuration to be incomplete.

## How to verify correct configuration
- Run a plugin authentication test, initiate a call using the test IP of the customer data center, confirm a 200 status code is returned.
- Import a structured snippet of a local deployment manual, call the MCP format adaptation plugin, confirm that device version and network topology fields can be extracted correctly.
- Trigger a code execution test, confirm that execution starts only after configuration list verification passes, and execution duration does not exceed the preset threshold.
- Check the FastGPT v4.17.0 plugin logs, confirm that tool calling parameters fully match the configuration items.

The values provided above are common starting points, and should be evaluated against the reader’s own samples.
