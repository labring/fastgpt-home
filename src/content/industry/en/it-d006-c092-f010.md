# On-site Deployment Implementation Test Cases and Defect Analysis: Citation Sources and Traceability

## What This Category of Data Looks Like
Data for this category originates primarily from customer data center environments, equipment inventories, software packages, and network topologies. Four types of documents are routinely generated: deployment manuals, installation records, configuration lists, and site check-in sheets.
Update frequency is once per order or implementation phase. Core fields include equipment model, software version, installation time, and network topology nodes.
The most time-consuming steps in the implementation process are environment checks, software installation and configuration, and on-site problem troubleshooting. Data abnormalities will directly lead to system unavailability, project delays, or increased return costs.

## Constraints Imposed on Citation Sources and Traceability
The data sources for on-site deployment implementation are scattered and updated per order. Traceability configuration must support associated matching across multiple source documents.
Document types are fixed as deployment-specific materials, so traceability scope must be limited to avoid mixing irrelevant data.
Each document’s fields focus on on-site implementation details, so precise field matching is required for citations.
Data abnormalities can cause serious consequences, so traceability configuration must include fast problem locating capabilities.
Since each order’s data is independent, the configuration must support single-instance customization without requiring unified global rules.

## Configuration Specifications
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Max Citation Token Count | 800–1200 token | Matches the average page length of on-site deployment documents, avoids truncating critical installation steps |
| Return Data Scope | Only associated deployment manuals, installation records | Limits traceability data sources, prevents mixing irrelevant customer data center environment data |
| Detail Display Toggle | Enabled | Displays specific fields of citation sources, such as software package version, network topology nodes |
| Citation Content Template | Includes variables for deployment manuals, installation records, configuration lists | Adapts to deployment-specific document types for on-site implementation |
| Citation Template Prompt | Prioritize matching software package versions in equipment inventories | Aligns with core verification links for on-site deployment |
| Single Citation Limit | Top 3 entries | Controls the amount of traceability results returned per round, avoids information overload |

## Three Common Misconfigurations
- Phenomenon: No optional values appear when selecting variable references during knowledge base search. Cause: Variables such as deployment manuals and installation records have not been registered in the on-site deployment-specific document configuration.
- Phenomenon: A `Cannot redefine property: toString at Object.defineProperty` error occurs when executing traceability in a production environment. Cause: Duplicate definitions of the same-named attribute for citation data sources exist in the configuration.
- Phenomenon: Irrelevant customer data center environment data is mixed into traceability results. Cause: The return data scope has not been limited to on-site deployment-specific documents.

## How to Confirm Proper Configuration
- Upload an on-site deployment installation record document, trigger citation traceability, and check if the returned results only include the specified deployment-related documents.
- Check the Max Citation Token Count configuration item, confirm that the value falls within the average length range of on-site documents.
- Enable the Detail Display Toggle, check if the citation results display dedicated fields such as software package version, network topology nodes.
- Test the variable reference function, confirm that variables such as deployment manuals, installation records appear in the optional list.
