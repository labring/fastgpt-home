# Test Cases and Defect Analysis for User Growth and Retention Operations: Tool Calling and Plugins

## What the data for this category looks like
This category's data primarily comes from user behavior logs, push systems, experiment platforms, and CRM systems. Daily produced documents include growth experiment plans, user segmentation tables, outreach copy, and retention analysis reports. Data update frequency is mainly daily or weekly. Fields typically include user identifiers, outreach actions, conversion results, segmentation tags, and similar items. There is no unified mandatory format, and adjustments must be made to fit specific operational scenarios.

## What constraints these characteristics impose on the tool calling and plugins workflow
Since data sources are scattered and update rhythms vary, tool calling must adapt to the synchronization cycles of multiple data sources to avoid reading temporary data that has not completed updating. Daily documents are mostly unstructured or semi-structured operational documents, so tool calling must support precise parsing of outreach copy and segmentation tables. At the same time, data fields are flexible with no fixed format, so tools must support custom field mapping and avoid interrupting operational logic due to missing fields. In addition, batch processing of retention analysis reports requires controlling resource usage per call to prevent disruption to normal business system operations.

## How to set the configuration
This document is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool calling trigger timing | Trigger after outreach copy generation and user segmentation table update | Match the update rhythm of daily documents to ensure data has completed updating before calling |
| Single call data volume limit | Top 1000 user segmentation data entries | Adapt to daily update data scale and avoid single call timeouts |
| Context window length | 800–1200 characters | Cover core content of outreach copy and experiment plans to avoid information truncation |
| `toolChoice` | Force calling specified tools | Ensure tool calling focuses on user segmentation and outreach effect analysis, avoiding irrelevant results |
| Failure retry count | 3 times, 60-second interval | Respond to temporary fluctuations in push systems or CRM to reduce call failure rate |
| Plugin call permission scope | Only open plugins related to user segmentation and retention analysis | Fit the category's business scenario and prevent unauthorized calls to unrelated tools |

## Three Common Mistakes
- Knowledge base content is accidentally introduced during tool calls. The cause is that the `toolChoice` parameter is not configured correctly, causing the knowledge base recall logic to be enabled by default.
- API calls return a 514 status code. The cause is that the single call data volume exceeds the system preset limit, and call tasks are not split according to the business update rhythm.
- Plugin calls return an empty result. The cause is that custom fields are not mapped correctly, causing the tool to fail to recognize user segmentation tags.

## How to Confirm the Configuration is Correct
- Manually trigger a tool call, and check if returned results only contain content related to user segmentation and outreach analysis, with no irrelevant knowledge base information.
- View call logs to confirm that the number of data entries per call meets the preset limit, with no overloading.
- Simulate a call failure scenario to check if the system executes the retry logic according to the configuration, and the retry interval matches the set value.
- Call the custom field mapping plugin to confirm that the tool can correctly recognize and parse user segmentation tags.

The values provided are common starting points and should be evaluated using samples from the actual operational context.
