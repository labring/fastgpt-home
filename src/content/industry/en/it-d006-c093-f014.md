# Test Cases and Defect Analysis for User Growth and Retention Operations: Model Integration and Configuration

## What the data for this category looks like
This category's data mainly comes from user behavior logs, push systems, experiment platforms, and CRM systems. Daily produced documents include growth experiment plans, user segmentation tables, outreach copy, and retention analysis reports. Data update frequencies are mostly daily or weekly. Core fields include user identifiers, behavior trigger times, outreach content codes, and experiment group identifiers. Information is only recorded per original behavior and business node, with no additional custom statistical units.

## What constraints these characteristics impose on model integration and configuration
Decentralized data sources and uneven update rhythms require model integration to support asynchronous pulling and aggregation of multiple data sources, to avoid single-request timeouts. Diverse daily document formats require configuring models to support mixed input of structured tables such as user segmentation tables and unstructured text such as outreach copy. The user segmentation and experiment attribution links take a long time. Models must adapt to fast inference for small batch samples, and also support parameter adjustment requirements across different business scenarios. This avoids analysis result deviations caused by mismatched configurations, which would otherwise affect the effectiveness of user outreach strategies.

## How to set configurations
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the context length requirements of multiple documents such as user segmentation tables and retention analysis reports, avoiding truncation of core business information |
| `temperature` | 0.3–0.5 | Used for outreach copy optimization and experiment attribution analysis, maintaining output stability and rationality, avoiding excessive divergence |
| `maxTokens` | 1500–2000 token | Adapts to the single-round output length requirements of a single outreach copy or experiment attribution |
| `AIPROXY_API_ENDPOINT` | Root address of the AI Proxy service, for example `http://aiproxy:3000` (do not append paths such as `/v1` or `/chat/completions`, not a single-model address) | Environment variable for the App/Admin server, ensuring the correct model request flow |
| `AIPROXY_API_TOKEN` | Non-empty administrator token matching the AI Proxy server configuration | Environment variable for the App/Admin server, ensuring proxy service authentication security and preventing unauthorized access |
| Single request data volume | Top 500 user behavior records | Balances inference speed and data integrity, adapting to daily batch analysis business scenarios |

## Three common misconfigurations
- When configuring a local model, the entry is not enabled in the corresponding menu of FastGPT v4.17.0, resulting in inability to find the local model integration option. The cause is failure to correctly access the local deployment page of model configuration.
- In the SaaS version, the corresponding overseas large model entry is not filtered, resulting in inability to call Claude or ChatGPT models. The cause is failure to select the corresponding overseas available model list on the model configuration page.
- The `maxContext` parameter is not adjusted to adapt to long documents, resulting in truncation of core fields of the user segmentation table, and the output analysis results lack key segmentation information.

## How to confirm configuration is complete
- Initiate a test inference for the user segmentation table, and check whether the output result contains complete segmentation labels and analysis logic.
- Check whether the App/Admin server has correctly configured `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`, and troubleshoot AI Proxy service connectivity and authentication validity.
- Configure test cases covering the pulling logic of different data sources, and check whether data aggregation meets the daily update rhythm requirements.
- Adjust the `temperature` parameter and compare two output results, and confirm that output stability meets business requirements.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
