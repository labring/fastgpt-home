# Test Cases and Defect Analysis for User Acceptance Testing Support: Tool Calling and Plugins

## What the data for this category looks like
Data for this category comes from requirement specification documents, test environment configurations, customer business sample materials, and defect management systems. Core daily deliverables include UAT test cases, acceptance issue tickets, acceptance reports, and signed confirmation forms. Data is updated per project phase or software version. UAT test cases include scenario steps and expected result fields. Acceptance issue tickets record reproduction paths and associated case numbers. Defects are graded by severity, archived by business scenario, and have no fixed statistical unit.

## What constraints these characteristics impose on tool calling and plugins
Data for this category comes from scattered sources. It requires integration with multiple business systems. Tool calling must support cross-data source format adaptation. Documents are updated per project phase or version. Tool calling must support triggering latest data pulls by node. A strong association exists between UAT test cases and defect tickets. Tool calling must support automatic matching and synchronization of associated fields. Additionally, data is customized based on customer business samples. Plugins must support custom business field mapping to adapt to differences in document structures across customers. This avoids format incompatibility issues with generic tool calls. The most time-consuming steps in this category are test case preparation and defect classification. Tool calling must automatically pull test cases and match associated defects. This reduces manual operation costs.

## How to configure settings
The following configuration items are adapted for FastGPT v4.17.0. Specific values may be adjusted based on actual project conditions:

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` or `specified tool name` | Adapt to requirements for automatically calling defect query tools or case synchronization tools in UAT scenarios |
| `functionCall` | Enabled | Support generating call parameters based on UAT test case fields, and automatically populate defect ticket association information |
| Tool call timeout period | 300–600 seconds | UAT data pulling requires integration with multiple business systems, reserve sufficient time for synchronization and data processing |
| Plugin field mapping rules | Map according to native fields of UAT test cases/defect tickets | Ensure data returned by tool calls directly matches local document field formats, no additional conversion required |
| Scheduled sync trigger timing | Trigger per project acceptance phase nodes, or sync once every 24 hours | Adapt to the rhythm of phase-based data updates for this category, avoid data lag impacting test progress |
| Number of items returned per call | Top 15–20 items | Reduce invalid data volume and improve efficiency of defect classification and case matching |

## Three common configuration errors
- Phenomenon: Tool calls return empty results, or logs show call parameter field mismatches. Cause: Plugin mapping rules are not configured per the document fields of this category, causing the tool to fail to recognize native fields of UAT test cases or defect tickets.
- Phenomenon: Tool calls time out, or return incomplete results. Cause: The set timeout period is too short, failing to adapt to delays from multi-system integration, or the number of items returned per call is set too high.
- Phenomenon: UAT data cannot be pulled normally when calling tools with a custom API key. Cause: The permission scope for tool calls is not configured, or the service bound to the key does not cover the data source interfaces of this category.

## How to verify correct configuration
- Manually trigger a tool call, check whether returned data includes test case or defect information for the current UAT project, and that fields match local document formats.
- View execution logs for scheduled sync tasks, confirm data has been pulled per preset phase nodes or cycles, with no failed records.
- Call the `functionCall` function, verify that call parameters conforming to UAT document formats can be automatically generated without manual field adjustments.
- In FastGPT v4.17.0, view detailed execution records for tool calls through the system log module, confirm there are no permission errors or format errors.
