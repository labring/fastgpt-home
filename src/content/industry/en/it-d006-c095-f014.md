# Test Cases and Defect Analysis for Monitoring Alert Configuration: Model Integration and Configuration

## What data for this category looks like
Data for this category comes from Prometheus, Zabbix, cloud monitoring, application logs, and CMDB platforms. Update frequency is daily or after each alert rule change. Daily maintenance documents include a monitoring metric list, alert rule configuration, on-call manual, and alert change records. The metric list includes fields such as metric name, scraping interval, and threshold range. Alert rules include fields such as trigger conditions, notification targets, and link paths. Most field units are percentage, millisecond, count, and similar units.

## What constraints these characteristics impose on model integration and configuration
As data sources are scattered and updates trigger on alert rule changes, model integration must support dynamic pulling of the latest alert rules and metric data to avoid using expired configurations. Alert rule fields have high complexity. The model must accurately identify associated fields such as trigger conditions and notification links, and adapt to differences in field formats across different sources. Additionally, alert configuration changes occur frequently. Model calls must support real-time synchronization of the latest configurations, and call frequency must be controlled to stay within the API rate limit thresholds of monitoring platforms. Configuration validation must cover core check points such as notification links and threshold rationality.

## How to set configurations
The following configuration items are based on the effective logic of FastGPT v4.17.0:
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the context length requirements of multiple documents including alert rules and metric lists, preventing truncation of critical configuration information |
| `temperature` | 0.1–0.3 | Alert configuration requires strict accuracy. Lower temperature ensures generated configuration rules are precise and unambiguous |
| `toolChoice` | auto | Allows the model to independently decide whether to call tools to pull the latest alert metric data, adapting to dynamic configuration scenarios |
| `AIPROXY_API_ENDPOINT` | http://aiproxy:3000 | Root address of the AI Proxy service. Do not append paths such as /v1 or /chat/completions. This is not a single-model service address |
| `maxTokens` | 2000–3000 characters | Controls the length of alert configuration documents generated per model round, preventing exceeding the reading threshold of on-call manuals |

## Three common mistakes
- Phenomenon: The timestamp of alert configurations generated by the model does not match the actual system time, or fields are empty or have incorrect formatting. Verifiable troubleshooting items: Failure to correctly call the system time variable provided by the platform, failure to explicitly require the use of the current date in the model prompt.
- Phenomenon: Alert configurations generated by the model do not include the current session ID, making it impossible to associate alert change records with operation logs. Verifiable troubleshooting items: Failure to explicitly require passing the session ID parameter in the model prompt, failure to configure the session ID passing logic.
- Phenomenon: Alert configurations generated by the model include forged non-existent reference IDs, causing the configuration to fail to be applied. Verifiable troubleshooting items: Failure to disable the model's forced reference generation logic, or failure to restrict the model to only use data source fields from the current alert configuration.

## How to confirm successful configuration
- Manually trigger a model call test, check whether the timestamp of the generated alert configuration matches the current system time.
- View the FastGPT model call logs, confirm that the actual effective values of the `maxTokens` and `maxContext` parameters match the preset configuration.
- Simulate an alert rule change, check whether the model can pull the latest metric data and generate compliant configurations.
- Verify that the generated configuration contains no forged reference IDs, and all references come from the data source fields of the current configuration.

The values listed above are common starting points and should be measured against the reader's own samples.
