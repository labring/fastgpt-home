# Test Cases and Defect Analysis for Monitoring Alert Configuration: Forms and Interactions

## What the data for this category looks like
Data sources for this category include Prometheus, Zabbix, cloud monitoring, application logs, and CMDB systems. Update frequency is daily or real-time when configuration changes. Daily produced documents include monitoring indicator lists, alert rule documents, on-duty manuals, and alert change records. Fields cover indicator names, threshold ranges, notification channels, effective time periods, trigger conditions, and more. Some fields have clear units, such as percentage for indicator thresholds and seconds for trigger delay.

## What constraints these characteristics impose on the "forms and interactions" link
The need to access multi-source data requires forms to support the `userSelect` component for selecting data source types, to avoid configuration errors. The high-frequency update feature requires input content verification logic to be implemented via external business systems or subsequent workflows, to prevent invalid configuration submissions. The rich set of field types requires forms to be split into multiple modules—indicator configuration, threshold setting, notification link, test verification—by external business systems or subsequent workflows, to reduce operational complexity. Additionally, since configurations are directly linked to pre-failure alert mechanisms, interaction entrances for test cases must be reserved via external business systems or subsequent workflows, to support pre-verification of configuration validity and avoid online configuration oversights.

## Three common errors
- Symptom: Drop-down options do not update when selecting alert indicators. Verification action: Check whether the external data source synchronization interface has been configured, and confirm that the interface can normally pull the indicator list.
- Symptom: Parameter format error prompt appears after configuration submission. Verification action: Check whether the input threshold matches the unit requirements of the corresponding indicator, for example, confirm whether the percentage threshold includes the % symbol.
- Symptom: No file upload entrance in the form, unable to upload monitoring logs or indicator data files. Verification action: Check whether external business systems or subsequent workflows have configured file upload related interaction logic.

## How to confirm the configuration is complete
- Manually trigger the configured alert rule, verify whether a notification is received via the corresponding channel.
- Select each configured option one by one in the user selection node `userSelect`, check whether the workflow enters the corresponding branch; filtering monitoring alert configuration records must additionally verify the input, permissions, and return values of the external interface.
- Check whether the thresholds configured in `formInput` match the normal fluctuation range of the corresponding monitoring indicators.
- After submitting a configuration change, confirm that the external business system or subsequent node generates the corresponding alert change record.

The values provided are common starting points and should be measured against the reader's own samples.
