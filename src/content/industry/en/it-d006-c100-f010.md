# Test Cases and Defect Analysis for Cybersecurity Level Protection Assessment Consulting: Citation Sources and Traceability

## What This Category of Data Looks Like
This category of data is generated across the full lifecycle of cybersecurity level protection assessments. Core daily documents include four types: classification determination reports, gap analysis reports, rectification plans, and assessment reports.
Data sources include assessment tool output results, on-site interview records, asset system inventories, and security device operation logs.
Data updates follow individual assessment project cycles. Full archiving is completed after a project ends. Partial updates are triggered during subsequent rectification or annual reviews.
Document fields include control item numbers, compliance requirements, gap item descriptions, rectification evidence links, and more. There is no unified fixed unit, and formats adjust based on project document requirements.

## Constraints Imposed on Citation Sources and Traceability
Multi-source, heterogeneous data sources require the traceability process to support field matching across document formats. It cannot rely on a single parsing rule.
Project-based update rhythms require traceability to be bound to project context. This avoids compliance risks from cross-project data confusion.
Core documents have compliance attributes, so traceability information must fully retain key fields such as control item numbers and rectification evidence. Association relationships cannot be lost.
Non-fixed document unit structures require traceability configurations to support flexible field mapping rules. It cannot rely on a unified unit verification logic.

## Configuration Settings
The following configurations are formulated for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Single Search Limit | Top 8 entries | Matches the average number of core documents under a single project to avoid redundant data interfering with responses |
| Maximum Citation Token Count | 1200–1500 tokens | Adapts to the content length of long documents such as assessment reports to ensure complete citation |
| Citation Source Display Toggle | Enabled | Meets compliance traceability requirements for cybersecurity level protection assessments, enabling tracing back to original documents |
| Context Association Scope | Bound to project | Matches the project-based data update rhythm to avoid cross-project data confusion |
| Field Matching Rule | Match by control item number | Adapts to the fixed field structure of core documents to ensure traceability accuracy |

## Three Common Misconfigurations
- Phenomenon: Matching knowledge base content is not included in the main response body. Citation entries are only displayed in the sidebar or footer.
  Cause: The configuration to automatically embed cited content into the response body is not enabled. Only citation list display is retained.
- Phenomenon: Search results return document data that does not belong to the current assessment project.
  Cause: The project-bound context association scope is not configured. Cross-project historical data is recalled.
- Phenomenon: Missing fields or messy formatting appear in cited content.
  Cause: The field matching rule based on control item number is not configured. Key traceability information from the original document is lost.

## How to Verify Correct Configuration
- Upload a single assessment report document. Initiate a query that includes control items from the report. Check if corresponding document fragments are embedded in the response body.
- Switch to different assessment project contexts. Initiate the same query. Confirm only document data from the current project is returned.
- View the citation source list. Confirm each citation includes key traceability fields such as control item number and document type.
- Adjust the maximum citation token count value. Verify that the length of cited content changes with the configuration.

The values provided are common starting points and should be measured against the reader's own samples.
