# Test Case and Defect Analysis for Level Protection Evaluation Consulting: Forms and Interactions

## What this type of data looks like
Core data for level protection evaluation consulting comes from evaluation tools, interview records, system inventories, and security device logs. Update frequency is per project or annually. Daily deliverable documents include classification reports, gap analysis reports, rectification plans, and evaluation reports. These documents have both structured fields and semi-structured descriptive content. Typical users include level protection evaluation institutions, security consulting firms, and enterprise security leaders. The most time-consuming work steps are organizing classification materials, checking control item gaps, and collecting rectification evidence. Data errors can lead to evaluation failure, delayed rectification, or regulatory inspection risks.

## What constraints do these characteristics place on forms and interactions
Since documents have both structured and semi-structured attributes, forms must support combined entry of multiple field types, including components like text boxes and selectors. Attachment upload must be implemented via external business systems or subsequent nodes. Per project or annual update requirements mean single-project data isolation and version management must be implemented via external business systems or subsequent nodes, to avoid mixing data from different projects. Multi-source data import needs require batch import and field auto-matching interaction capabilities via external business systems or subsequent nodes, to reduce manual entry workload. For the most time-consuming checking step, configure verification rules via external business systems or subsequent nodes to intercept non-compliant input early, and support batch export of check results. Severe error consequences require operation log recording via external business systems or subsequent nodes, to enable full traceability of data submission and modification processes.

## Three common misconfigurations
- Phenomenon: Global variables throw null input errors during cross-node calls. Cause: Global variable persistence rules were not configured via external business systems or subsequent nodes; the `formInput` node only collects input information and passes it to subsequent nodes.
- Phenomenon: After selecting the qwen-plus model and enabling thought output, the result does not include the thought process. Cause: The thought output option was not enabled in the model configuration's interaction switch, resulting in incorrect parameter passing.
- Phenomenon: Question and answer pair extraction execution order is opposite to expected. Cause: The execution timing of the `userSelect` node was not set correctly, resulting in the workflow not following the expected process.

## How to confirm correct configuration
- Submit a test case, intentionally leave the required fields of the `formInput` node blank, check if the external business system or subsequent node triggers an intercept prompt.
- Manually set a global variable and pass it to the next node, confirm there are no null value errors during the call.
- Select the qwen-plus model and enable the thought output switch, generate evaluation-related content, confirm the result includes the thought process.
- Configure workflow processing nodes, adjust the execution timing of the `userSelect` node, verify the workflow execution order matches expectations.
