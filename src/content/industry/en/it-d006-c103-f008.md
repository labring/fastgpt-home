# Test Case and Defect Analysis for Art Asset Production Management: Workflow Orchestration

## What this category of data looks like
The data for this category primarily comes from art asset libraries, project management systems, engine resource packages, and outsourced delivery files. Daily associated documents include art requirement sheets, asset specification sheets, outsourced feedback sheets, and acceptance records. Fields cover asset unique identifiers, polygon counts, resolution, delivery timelines, acceptance status, and more. Units include pixels, triangle counts, MB, and others. Data updates follow daily or weekly cycles. The resource volume of single delivery packages varies widely, ranging from single texture maps to batches of 3D model files.

## What constraints do these characteristics impose on workflow orchestration
The data characteristics of art asset production management impose clear constraints on workflow orchestration. Multi-source heterogeneous associated documents and resource packages require configuring cross-system data pulling and format conversion nodes in the workflow to adapt to data formats from different sources. Daily or weekly update cycles require the workflow to support both scheduled and manual trigger modes, to accommodate both periodic verification and temporary acceptance needs. The wide variation in resource volume requires workflow nodes to support dynamic adjustment of processing thresholds, to adapt to verification scenarios for single files and batch resources. Additionally, the non-standard nature of outsourced delivery files requires adding pre-verification nodes during orchestration to filter delivery content that does not meet format requirements. At the same time, art asset acceptance records must be tied to task progress in the project management system, so a data synchronization node must be configured in the workflow to ensure test results are synced to the project management system.

## How to set configurations
The following configurations are based on FastGPT v4.17.0

| Configuration Item | Recommended Value | Rationale |
| ---|---|--- |
| Trigger Mode | Scheduled + manual dual trigger mode | Adapts to daily or weekly data update cycles, and accommodates temporary verification needs |
| `variables` configuration | Includes asset polygon count thresholds, resolution standards, and acceptance rule sets | Uniformly manages verification standards for multiple types of art assets, and adapts to field differences between art requirement sheets and asset specification sheets |
| `nodeId` configuration | Binds cross-system pulling nodes, format verification nodes, and defect marking nodes | Accurately locates key links in the workflow, facilitating subsequent troubleshooting and process adjustments |
| Batch processing limit | 800–1200 resource files per run | Adapts to the wide variation in resource volume of outsourced delivery packages, and avoids node resource overload |
| Timeout threshold | 600 seconds | Adapts to verification durations for large-volume 3D models, and prevents abnormal task interruptions |
| Number of exception retries | 2–3 times | Addresses temporary network fluctuations or format parsing failures, and reduces manual intervention |

## Three common mistakes
- Phenomenon: The locally deployed workflow configuration interface experiences text input lag when there are many nodes. Cause: No pagination rendering configuration is applied to interface nodes, and a large number of DOM nodes loading simultaneously occupies main thread resources.
- Phenomenon: An axioserror error is returned when a code node executes. Cause: Valid interface request addresses and timeout thresholds are not configured in `variables`, causing requests to fail to complete normally.
- Phenomenon: A parameter verification failure is returned when calling a specified workflow. Cause: The workflow ID does not use 24-bit hexadecimal characters, which does not meet the FastGPT interface parameter format requirements.

## How to confirm the configuration is correct
- Manually trigger a small test workflow, check whether test data from the art asset library can be pulled normally and format verification completed.
- View the workflow log panel, confirm that nodes bound to `nodeId` all execute normally with no error messages.
- Call the workflow interface, pass a workflow ID in 24-bit hexadecimal format and a valid API key, confirm the interface returns normal results.
- Adjust the batch processing limit to 500 resource files, test whether the verification process for batch delivery packages runs normally.

The values provided are common starting points and should be measured against the reader's own samples.
