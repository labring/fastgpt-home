# Test Case and Defect Analysis for Art Asset Production Management: Tool Calling and Plugins

## What this category of data looks like
This category of data primarily comes from art asset libraries, project management systems, engine resource packages, and outsourced delivery packages. Daily associated documents include art requirement sheets, asset specification sheets, outsourced feedback sheets, and acceptance records. Fields cover asset unique identifiers, resolution, triangle count, delivery cycle, acceptance status, and more. Data update frequency is daily or weekly, with single update volume fluctuating based on project phase. Core data focuses on delivery standards and quality verification for art resources.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
Since data is scattered across multiple systems and delivery packages, tool calling must adapt to multi-source data access plugins to retrieve asset specifications and acceptance records in a unified format. Fields in daily associated documents have inconsistencies, so tool calling parameters must match the field mapping rules of different documents to avoid verification failures. The file structure of outsourced delivery packages is not fixed, so plugins must support custom parsing rules to adapt to delivery formats from different outsourcers. High-frequency daily or weekly updates also require tool calling to support real-time triggering to adapt to project schedule changes. ## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to the automatic generation needs of art asset test cases, no manual specification of tool types is required |
| `functionCall` | Enable mandatory parameter verification | Ensures core fields such as asset ID and specification parameters are required when calling tools, avoiding invalid calls |
| User confirmation before tool calling | Bind asset specification verification node | Prevents plugin execution from triggering when parameters do not meet art asset standards |
| Plugin timeout threshold | `300 seconds` | Adapts to typical time required for art asset package parsing and engine resource checks, avoiding early termination of processes |
| Single tool call trigger frequency | `Every 10 minutes` | Adapts to the daily update rhythm of art asset production, avoiding resource occupation from overly frequent calls |
| Context window length | `800–1200 characters` | Adapts to typical field length of art requirement sheets and asset specification sheets, avoiding truncation of key verification information |

## Three common mistakes
- The AI response during intermediate steps after tool calling cannot be hidden. This occurs when tool calling result display rules are not configured correctly, and intermediate execution results are mistakenly set to mandatory display.
- A prompt indicating missing core parameters appears when the plugin runs. This occurs when mandatory parameter verification for `functionCall` is not enabled, resulting in required fields such as asset ID and specification parameters not being passed.
- Frequent timeout errors occur during tool calling. This occurs when the plugin timeout threshold is set to a value lower than the actual required time, without adapting to the typical runtime duration of art asset package parsing.

## How to confirm the configuration is correct
- Start the FastGPT service, check that server logs have no startup verification failure errors related to AI Proxy. Confirm that `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service, do not append paths such as /v1, not a single model address) and `AIPROXY_API_TOKEN` (AI Proxy administrator token, consistent with server configuration and non-empty) have been configured according to official requirements.
- Create a new art asset test case workflow, trigger tool calling, and check whether the corresponding tool is automatically called according to the configured `toolChoice`, or whether parameter verification is completed according to the `functionCall` rules.
- Simulate a tool call with parameters that do not meet asset specifications, and confirm whether the preset verification interception or user confirmation process is triggered.
- Wait for the plugin execution to complete, check that the execution duration is within the configured timeout threshold, and no early termination occurs.
