# Test Cases and Defect Analysis for Art Asset Production Management: Citation Sources and Traceability

## What This Category’s Data Looks Like
Core data for this category comes from art asset libraries, project management systems, engine resource packages, and outsourced delivery packages. Update frequency is typically daily or weekly.
Daily produced business documents include art requirement sheets, asset specification sheets, outsourced feedback forms, and acceptance records. Data fields include asset unique identifiers, version numbers, delivery times, polygon/pixel specifications, acceptance results, rework requirements, and more. Some outsourced delivery packages also include original source files and compressed package information.

## Constraints on Citation Sources and Traceability
Data sources are scattered, including local private libraries, third-party outsourced delivery packages, and engine-built resources. The traceability link must correlate information across multiple data sources to prevent asset version mismatches.
Data updates occur daily or weekly. The traceability system must support scheduled incremental data synchronization to ensure cited asset information is up to date.
Business document fields are mostly non-standard, project-specific fields. Matching rules must be configured to bind cited content to specific assets. For art asset performance parameters such as polygon count and file size, accurate linking to corresponding specification documents is required. This supports precise positioning during defect analysis.

## Configuration Recommendations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `8000-12000 token` | Art asset-related documents usually include detailed specifications, acceptance records, and rework feedback, which are lengthy. This range covers complete cited content |
| `responseData` | Return detailed citation source information | Asset IDs, version numbers, and other unique identifiers must be linked to support precise traceability for defect analysis |
| `detail` | Enabled | Specific performance parameters and acceptance results of assets must be displayed to help locate the root cause of defects |
| Knowledge base synchronization frequency | Automatic synchronization at daily midnight | Matches the daily or weekly data update rhythm, ensuring cited information is up to date |
| Number of recalled citations | Top 6 entries | A single query must cover multiple acceptance and feedback documents to meet information needs for defect analysis |

## Three Common Configuration Mistakes
- Phenomenon: The conversation interface does not return the cited knowledge base ID. Cause: The detailed information return configuration corresponding to `responseData` is not enabled. Only text content is returned, and no source data identifiers are included.
- Phenomenon: Cited content is not linked to a specific asset version. Cause: No field matching rules are configured. No unique identifiers such as asset IDs and version numbers are extracted. Only document titles are displayed.
- Phenomenon: No data from outsourced delivery packages is cited. Cause: Outsourced delivery packages are not included in the knowledge base synchronization scope. Traceability cannot cover defect information from the outsourced process.

## How to Verify Correct Configuration
- Initiate a test conversation that includes art asset specification queries. Check if the response content includes fields such as asset ID and version number of the citation source.
- View the FastGPT v4.17.0 knowledge base synchronization logs. Confirm that art asset libraries, outsourced delivery packages, and engine resource data are automatically synchronized at daily midnight.
- Test queries related to defects. Check that the number of returned citations matches the preset recall limit.
- Adjust the `quoteMaxToken` parameter to a smaller value. Verify whether long document citations are properly truncated or retained.

The values provided are common starting points and should be measured against the reader's own samples.
