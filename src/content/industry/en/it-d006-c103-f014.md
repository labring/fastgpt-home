# Test Case and Defect Analysis for Art Asset Production Management: Model Access and Configuration

## What the Data for This Category Looks Like
Typical stakeholders in art asset production management include art PMs, concept artists, 3D artists, and outsourcing managers. Daily generated documents include art requirement sheets, asset specification sheets, outsourcing feedback forms, and acceptance records. Data mainly comes from art asset libraries, project management systems, engine resource packages, and outsourcing delivery packages. Update frequency is mostly daily or weekly. Core fields include resource ID, version number, specification parameters, outsourcing status, and acceptance results. This category focuses on delivery management for character, scene, and special effect resources, and differs from level content creation. The most time-consuming steps are specification confirmation, outsourcing rework communication, and engine import checks. Errors can trigger issues such as resource mismatches, performance overages, or missing version assets.

## Constraints Imposed on "Model Access and Configuration" by These Characteristics
Art asset production management uses multi-source data, so model access configuration must adapt to asset documents and outsourcing feedback data in different formats. Set a reasonable context window to accommodate multiple related documents. The daily or weekly update rhythm requires the `maxContext` value to match the data update cycle, to avoid introducing expired invalid information. Core fields have specific requirements, so configuration must support precise extraction and verification of fields such as resource ID and specification parameters. Balance the model's rigor and flexibility to meet defect analysis needs for scenarios including outsourcing rework and engine import.

## How to Configure the Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | `7-14 days` | Matches the daily/weekly update rhythm of art asset data, avoids redundant old data interfering with defect analysis |
| `temperature` | `0.2-0.4` | Art asset verification requires rigor, reduces randomly generated vague judgments, improves the accuracy of defect identification |
| `maxTokens` | `8000-12000 token` | Needs to handle concatenation of multiple documents including art requirement sheets, asset specifications, and outsourcing feedback, ensures complete context input |
| `quoteMaxToken` | `2000-3000 token` | Prioritizes referencing core asset specifications and acceptance records as key basis for defect analysis |
| `toolChoice` | `auto` | Automatically adapts to tool calling needs for different tasks such as asset verification and outsourcing communication record organization |
| `AIPROXY_API_TOKEN` | AI Proxy server environment variable, must match the AI Proxy server configuration and cannot be empty | This variable is the AI Proxy administrator token, a required deployment configuration for the App/Admin server, not an application call credential or user-level secret |

## Three Common Mistakes
- Phenomenon: After adding model configuration in the FastGPT interface, the configured model option cannot be seen, and the issue persists after restarting the service. Cause: The model configuration file was not placed in the model access directory specified by FastGPT v4.17.0, or the configuration file format does not meet the platform's verification rules.
- Phenomenon: The model test run returns the error "[] is too short - 'messages'". Cause: The necessary context message field was not filled in the model call configuration, or the test input is an empty message array.
- Phenomenon: After configuring multi-user authentication, cross-account conversation record sharing occurs. Cause: Application call credentials for different users were not properly isolated, or correct application API authentication parameters were not configured.

## How to Verify Successful Configuration
- Enter the FastGPT model management interface, confirm that the configured model appears in the available model list.
- Submit test text containing art asset specification fields, run the model test, confirm that no "messages"-related error messages are returned.
- Verify the user authentication configuration on the application side, ensure that call credentials for different test accounts are effectively isolated, and conversation records will not be shared between accounts.
- View the model call logs, confirm that the values of configuration parameters such as `maxContext` and `temperature` match the preset configuration.
