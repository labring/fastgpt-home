# Test Cases and Defect Analysis for Art Asset Production Management: Forms and Interactions

## What This Category of Data Looks Like
Data for this category primarily comes from art asset libraries, project management systems, engine resources, and outsourced delivery packages. Update frequency is typically daily or weekly. Commonly used documents include art requirement sheets, asset specifications, outsourced feedback forms, and acceptance records. Fields usually include asset unique identifiers, delivery formats, resolution requirements, polygon count limits, acceptance status, and some documents include binary-format outsourced delivery files. Business participants include art PMs, 2D artists, 3D artists, and outsourced liaison staff. Data flows follow the full asset delivery workflow.

## What Constraints These Characteristics Impose on Forms and Interactions
Multiple data sources require cross-system data association logic implemented by external business systems. FastGPT's `formInput` node only collects input information and passes it to subsequent nodes, to avoid manual repeated entry of asset IDs, specification parameters, and other content. Daily or weekly update frequency requires incremental submission and version tracing functions implemented by external business systems, to adapt to the rhythm of asset iterations. Diverse document types require field association rules implemented by external business systems, to match the filling logic of different documents such as art requirement sheets and acceptance records. The most time-consuming specification confirmation and outsourced rework links require simplified repetitive operations implemented by external business systems, to reduce invalid clicks for business personnel. Consequences of errors such as resource mismatches and missing version materials require field verification logic implemented by external business systems, or a verification link configured in the FastGPT workflow, to intercept non-compliant submissions in advance.

## Three Common Mistakes
- Asset data from external business systems associated with FastGPT's `formInput` node fails to load correctly, shown as empty asset acceptance status fields. Verify whether the data reference rules of the external business system are properly configured. FastGPT nodes only pass collected information and cannot directly pull data from external business systems.
- The dropdown menu of the user selection node (`userSelect`) contains a large number of duplicate entries, shown as multiple identical outsourced liaison staff options in the dropdown box. Verify whether the option set of the `userSelect` node is configured by role groups, and confirm that uncategorized full staff data is not used.
- Uploading an oversized delivery package triggers an upload failure prompt returned by the external business system, shown as a file size limit exceeded error. Verify whether the single submission file limit configuration of the external business system is reasonable, and confirm that low-threshold configurations for general scenarios are not reused.

## How to Confirm Proper Configuration
- Verify that the currently used FastGPT version is v4.17.0, to ensure configuration items are compatible with the current system version.
- Fill out a test art specification requirement, check whether the form input node (`formInput`) pops up a prompt when the input length limit is reached.
- Select a business role option, check whether the user selection node (`userSelect`) displays options grouped by art PM, 2D artist, and outsourced liaison staff.
- Upload a test delivery package that complies with external system limits, confirm that the submission process completes normally without file size limit exceeded errors.
- Associate a test asset ID, check whether asset data from the external business system can be correctly pulled and passed to the subsequent workflow corresponding to FastGPT's `formInput` node.
