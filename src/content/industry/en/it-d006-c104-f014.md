# Test Cases and Defect Analysis for Landing Page Conversion Optimization: Model Integration and Configuration

## What the Data for This Category Looks Like
The core data for this category comes from four types: landing page access logs, heatmaps, form submission data, and ad source parameters. Daily associated documents include landing page design plans, event tracking requirement lists, AB test reports, and form field configuration tables. Data update frequency is weekly or per single campaign cycle. Fields include page path, dwell time, form submission status, ad utm parameters, etc. There are no unified fixed units; values adjust dynamically based on analysis dimensions.

## Constraints on Model Integration and Configuration
FastGPT v4.17.0 model integration configuration must adapt to the data characteristics of this category. Multi-source heterogeneous data sources require model integration to support cross-data source context association, to avoid fragmented analysis results. Weekly or campaign-level update cycles mean model context windows should not be too large, otherwise expired data will be introduced. The diversity of document structures requires configuration items to adapt to analysis materials in different formats. At the same time, errors will directly lead to lead loss or attribution failure, so complete failure retry and permission isolation mechanisms are required.

## Configuration Settings
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 6000–10000 token | Matches the total length of landing page data within a single campaign cycle, to avoid truncation of critical path and event tracking information |
| `temperature` | 0.2–0.4 | Reduces randomness of analysis results, ensuring consistency of test case and defect troubleshooting conclusions |
| `AIPROXY_API_TOKEN` | Non-empty value matching the AI Proxy server configuration | This variable is an App/Admin server environment variable. It is the AI Proxy administrator token used to establish a legitimate connection with the AI Proxy service, and is unrelated to model API keys |
| `toolChoice` | auto | Automatically calls built-in tools to extract core fields such as form blockages and path jump abnormalities |
| `maxTokens` | 1500–2000 characters | Controls the output length of single-round analysis, adapting to the conventional reading length of AB test reports |

## Three Common Misconfigurations
- Model addition fails for any model, with interface prompts of connection timeout or insufficient permissions. Troubleshooting steps: Incorrect access address configuration for `AIPROXY_API_ENDPOINT`, or incorrect configuration of `AIPROXY_API_TOKEN`.
- Models with identical names but different keys cannot be distinguished, leading to data confusion during multi-account analysis. Troubleshooting steps: Upstream model channel configurations do not isolate keys by account, or the server environment variable `AIPROXY_API_TOKEN` is not configured correctly.
- Workflow node output mixes irrelevant data from the global context. The cause is failure to restrict the context range of the current node, resulting in direct calls to the full campaign dataset.

## How to Confirm Successful Configuration
- Enter the model integration management page, select a single model instance to initiate a test call, confirm that the returned results include core fields for landing page analysis.
- Submit preset test cases, check that the analysis results only include data related to the current campaign, with no redundant cross-campaign information.
- Adjust the `temperature` parameter to values within the 0.1 to 0.4 range, verify that the difference between the two analysis results falls within the expected range.
- Check system logs, confirm that there are no abnormal records such as model call timeouts or permission errors.
- Enter the custom model management page, confirm that the FunASR speech recognition model configuration information has been correctly saved and displayed in the list.

The values listed above are common starting points. They should be evaluated against the samples relevant to the target deployment.
