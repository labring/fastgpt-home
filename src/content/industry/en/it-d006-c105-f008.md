# Test Cases and Defect Analysis for License Compliance and Copyright Notices: Workflow Orchestration

## What This Category of Data Looks Like
This category of data primarily comes from code repository commit records, third-party dependency lists, official license texts, and project contributor attribution records. Daily produced documents include LICENSE files, NOTICE files, project dependency license summary lists, and copyright notice texts. Updates occur when software versions iterate or third-party dependencies change, with no fixed cycle. Core fields include license type identifiers, copyright attribution entities, dependency package version numbers, and distribution permission descriptions. No unified mandatory units exist, and labeling follows only document specifications.

## What Constraints Do These Characteristics Impose on Workflow Orchestration
The data characteristics of this category impose multiple constraints on workflow orchestration. Data sources are scattered, so configure multiple nodes to pull code repositories, dependency lists, license texts, and contribution records separately. Updates have no fixed cycle, so set trigger-based execution rules bound to code commit or dependency list change events. Core fields have no unified units, so configure field mapping logic in nodes to unify license identifiers and copyright attribution information from different sources into standard formats. Error consequences are severe, so embed error capture branches in the workflow and pair them with alert nodes to handle validation failure scenarios. In FastGPT v4.17.0, workflow trigger configuration and variable passing functions have been adapted for such scenarios. Pass cross-node copyright entity IDs and dependency version numbers via `variables`, and associate node states of different validation links via `nodeId`.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Condition | Bind code commit and dependency list change events | Matches the characteristic that data in this category updates with version or dependency changes |
| Single Validation Timeout | 600 seconds | Accommodates time-consuming steps such as license compatibility checks and copyright attribution confirmation |
| Retry Interval | 300 seconds | Avoids frequent triggering of dependency interface rate limits |
| Field Standardization Mapping | Map by license type and copyright entity classification | Resolves the issue that core fields in this category have no unified units |
| Cross-node Variable Passing | Use `variables` to pass dependency version numbers | Supports passing core validation data across links |
| Node State Association | Configure `nodeId` to mark validation links | Distinguishes execution states of different validation steps |

## Three Common Misconfigurations
- Phenomenon: The dependency license list fields generated after workflow execution are empty. Cause: The association between the data source node and field mapping node is not configured, and the dependency package name parameter is not passed via `variables`.
- Phenomenon: The workflow cannot read custom environment variables set during docker deployment. Cause: Environment variable call permissions are not enabled in the workflow configuration, and environment variables are not mapped to workflow nodes via `variables`.
- Phenomenon: User-selectable validation skip branches cannot be configured in the workflow. Cause: The `variables` option is not set at the workflow entry, and optional trigger nodes are not associated.

## How to Confirm Proper Configuration
- Manually trigger a simulated code commit event to check whether the workflow starts normally and pulls the corresponding data source.
- View workflow logs to confirm that parameters such as dependency version numbers and copyright entity IDs passed via `variables` are not missing.
- Trigger a validation failure scenario to check whether preset alert notifications and retry logic are triggered.
- Check the output of the field mapping node to confirm that license information from different sources has been unified into standard formats.
