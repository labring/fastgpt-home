# Test Cases and Defect Analysis for License Compliance and Copyright Notices: Model Integration and Configuration

## What this category of data looks like
This category of data primarily comes from code repositories, dependency lists, license texts, and contribution records. Maintained documentation includes LICENSE files, NOTICE files, dependency license lists, and copyright notices. Data is updated with each version release or each dependency change. Document fields include license type, copyright holder name, dependency name, version number, and authorization scope. There are no additional statistical fields. This data is only used for compliance verification and copyright notice generation.

## What constraints these characteristics impose on the model integration and configuration workflow
Data sources are scattered across code repositories and dependency lists. When integrating a model, pull permissions and paths across multiple data sources must be configured. Update frequency aligns with version and dependency changes. The model must support incremental synchronization to avoid reprocessing old data and improve processing efficiency. The document structure is fixed to four types of files. The model must recognize the field rules for different files: LICENSE files require extracting authorization terms, and NOTICE files require organizing copyright notice content. There are no additional statistical dimensions for fields. The model does not need to perform additional aggregation statistics during processing, only matching compliance rules based on fields.

The following configurations apply to FastGPT v4.17.0.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | Root address of the AI Proxy service, for example http://aiproxy:3000. Do not append /v1 or /chat/completions paths, and do not point to single-model service addresses such as VLLM/Ollama/Xinference | Required environment variable for the App/Admin server, used to connect to the AI Proxy service |
| `AIPROXY_API_TOKEN` | Administrator Token for the AI Proxy service. Must match the Token configured on the AI Proxy server and cannot be empty | Required environment variable for the App/Admin server, used for AI Proxy service authentication |
| `maxContext` | 8000–12000 token | Adapts to the context length after multiple documents are spliced, avoiding truncation of critical compliance terms |
| `maxTokens` | 4000 token | Limits the length of a single model output to ensure compliance conclusions are concise and clear |
| `temperature` | 0.1–0.3 | Maintains consistency in compliance judgments, avoiding generation of vague compliance conclusions |
| `quoteMaxToken` | 2000 token | Limits the length of quoted license texts to ensure quoted output content is clear |

## Three common misconfigurations
- Check item: Verify that the `maxContext` parameter value matches the context length after the current multiple documents are spliced
- Check item: Verify that the model channel configuration is correct, ensuring that data related to contribution records can be retrieved normally
- Check item: Verify that `AIPROXY_API_ENDPOINT` is the correct root address of the AI Proxy service, with no additional paths such as /v1 or /chat/completions appended

## How to confirm the configuration is complete
- Check the App/Admin server startup logs to confirm there are no startup verification failure prompts related to `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN`
- Upload a single LICENSE file and a single NOTICE file, and verify that the compliance conclusions output by the model match the file content
- Trigger an incremental synchronization task to confirm that only recently updated dependencies are reprocessed
- Adjust the `temperature` parameter to 0.2, and verify that the compliance conclusions output remain consistent with previous results

The values provided are common starting points and should be measured against the reader's own samples.
