# Test Cases and Defect Analysis for Speech Annotation and Transcription: Workflow Orchestration

## What Data for This Category Looks Like
Data for this category primarily originates from uploaded audio files, task lists exported from annotation platforms, industry-specific vocabularies, and random inspection quality control samples. Daily synchronized documents include transcription specifications, audio batch lists, quality inspection reports, and speaker annotation tables, with updates performed daily or per delivery batch. Structured text must be generated after initial audio transcription. Core processing steps include noise segment identification, speaker differentiation, and specialized vocabulary proofreading; these steps have relatively high time overhead.

## What Constraints These Data Characteristics Impose on Workflow Orchestration
The data characteristics of this category create multiple constraints for workflow orchestration. The multi-source, batch-update nature requires workflows to support batch task access and batch status validation. Dependence on industry-specific vocabularies must be integrated into pre-check nodes to prevent specialized vocabulary errors in transcription outputs. Core processing steps have long runtimes, so node timeout thresholds and exception retry logic must be configured. Structured text output requires fixed field formats that align with the statistical dimensions of quality inspection reports. Unlike text annotation workflows, audio transcription must be executed first. Workflows must clearly separate the node order for audio processing and text annotation.

## How to Set Configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Global variable initialization | Import initial values per transcription specifications, set to `{ "special_words": [], "noise_threshold": 0.8 }` | Matches initial configuration for specialized vocabularies and noise judgment, resolves issues where variable initial values do not take effect, and adapts to the global variable logic of FastGPT v4.17.0 |
| Node ID binding | Bind the unique `nodeId` of the audio transcription node and quality inspection node | Ensures correct processing links are targeted when workflow nodes are called, avoiding node confusion |
| Variable reference configuration | Reference the specialized vocabulary and noise threshold from `variables` into the transcription node body | Enables unified calling of global configurations, avoiding repeated parameter entry |
| Retry count setting | Set to 2–3 times | Covers scenarios of temporary network fluctuations or audio parsing exceptions, reducing invalid error reports |
| Timeout threshold setting | Set to 600 seconds | Matches the upper limit of average time consumption for single-batch audio transcription and quality inspection, avoiding long periods of no response |
| Batch verification switch | Enable verification matching batch lists and audio file quantities | Prevents task abnormalities caused by missing or extra audio file uploads |

## Three Common Misconfigurations
- Symptom: An error occurs directly in the tool call phase after the workflow initiates a query. Logs show that variable fields are empty. Cause: Variable references are not correctly configured for the node body, causing the transcription node to fail to obtain specialized vocabulary or noise threshold parameters.
- Symptom: Global variables do not take effect after being set, and default values are used during node calls. Cause: Global variable initialization is not triggered when the workflow starts, or the initialization configuration is not bound to the corresponding node.
- Symptom: Workflow nodes time out without triggering the retry mechanism. Cause: The timeout threshold is set too short and does not match the actual time consumption of single-batch audio processing, or the retry configuration is not associated with the abnormal node.

## How to Verify a Correct Configuration
- Manually import transcription specifications into global variables, check if the corresponding `variables` fields are correctly referenced in the node body.
- Submit a single batch of test audio, check if the workflow logs show that global variable initialization was successful, with no missing variable error reports.
- Simulate an audio parsing exception scenario, verify if the node triggers the retry mechanism, and confirm that the timeout threshold matches the preset duration.
- Compare the batch list with the number of uploaded audio files, confirm whether mismatched tasks are blocked after the batch verification switch is enabled.

The values provided are common starting points and should be measured against the reader's own samples.
