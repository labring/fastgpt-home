# Test Cases and Defect Analysis for Speech Annotation and Transcription: Tool Calling and Plugins

## What Data for This Category Looks Like
This category’s data primarily comes from audio files, annotation platforms, proprietary term lists, and spot-check samples. Updates follow a daily or batch-based schedule. Associated daily documents include transcription specifications, audio lists, quality inspection reports, and speaker annotation forms. Core data fields include audio duration, speaker identifiers, transcribed text segments, quality inspection scores, and proprietary term verification results.
Compared to text annotation projects, this category requires converting unstructured audio to structured text before conducting annotation and quality inspection work. Core time-consuming steps focus on noise segment judgment, speaker differentiation, and proprietary term proofreading.

## What Constraints These Characteristics Impose on Tool Calling and Plugins
The unstructured nature of audio files requires tool calling to support audio preprocessing steps, and to adapt to batch audio retrieval and shard processing logic. Daily or batch-updated data scales require plugin configurations to support batch task scheduling and breakpoint resumption, to avoid single-call timeouts.
Fixed verification requirements for proprietary term lists and spot-check samples require tool calling to bind specified term lists and sample libraries, ensuring consistency in proprietary term recognition and quality inspection logic.
Structured requirements for speaker annotation forms require plugins to support field mapping for multi-speaker differentiation results, ensuring field alignment between annotation data and quality inspection reports. Misalignment can lead to recognition training bias, transcription rework, or delivery delays.

## How to Set Configurations
The following configurations are based on the interface and parameter logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto`, or specify the audio preprocessing tool name | Supports automatic tool scheduling for speech annotation and transcription scenarios, matching batch audio processing workflow requirements |
| Single batch audio limit | 100–200 items | Matches batch-updated data scales, avoids exceeding platform resource limits in single calls |
| Plugin timeout setting | 600 seconds | Covers processing durations of core time-consuming steps such as noise segment judgment and speaker differentiation |
| Proprietary term list binding | Bind a dedicated proprietary term list | Ensures recognition accuracy of proprietary terms during transcription, aligning with transcription specification requirements |
| Speaker field mapping | Align with fields from the speaker annotation form | Ensures consistent field formatting between annotation results and quality inspection reports, simplifying downstream data analysis |
| `functionCall` | Enable structured output mode | Forces conversion of code, transcription, and quality inspection results generated by plugins into standardized field formats, facilitating downstream processing |

## Three Common Misconfigurations
- Calling a code generation plugin returns empty code snippets or no execution results. Cause: Structured output mode for `functionCall` is not enabled correctly, preventing the platform from properly parsing and returning plugin-generated code.
- Batch audio transcription tasks have partial nodes that time out and fail, with a 504 status code. Cause: The number of single batch audio items exceeds a reasonable range, and breakpoint resumption logic is not configured.
- Speaker annotation fields in quality inspection reports do not match the original annotation form. Cause: Speaker field mapping is not configured, so the plugin does not align results with the field rules of the original annotation form.

## How to Verify Configurations Are Properly Applied
- Submit a single audio test task, check if the tool automatically calls the preset audio preprocessing and transcription workflow, and confirm the `toolChoice` configuration is active.
- Submit a batch test task, verify that processing duration covers core time-consuming steps, and confirm the timeout setting meets actual requirements.
- Review transcription results, check if proprietary terms have been verified against the bound term list, and confirm the proprietary term list binding configuration is active.
- Export a quality inspection report, verify that speaker annotation field formatting matches the original annotation form, and confirm the mapping configuration is correct.

The values provided are common starting points and should be measured against the reader's own samples.
