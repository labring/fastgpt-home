# Test Cases and Defect Analysis for Speech Annotation and Transcription: Citation Sources and Traceability

## What the Data for This Category Looks Like
The data sources for this category include raw audio files, annotation results from annotation platforms, proprietary vocabularies, and spot-check quality control samples. Daily maintained documents include transcription specifications, batch audio lists, quality inspection reports, and speaker annotation tables. Update frequency is adjusted daily or per batch task cycle. The data structure centers on structured transcribed text, with accompanying fields such as audio duration, speaker identifiers, and annotation timestamps. Common units are seconds, characters, and item counts. Unlike text annotation projects, speech annotation and transcription require first converting audio to structured text before conducting subsequent quality inspection and analysis.

## What Constraints These Characteristics Impose on the Citation Sources and Traceability Workflow
The unstructured nature of audio sources means traceability must bind timestamps of original audio segments, and cannot rely solely on text keyword matching. Data updated daily or per batch requires a traceability chain that lets users quickly locate associated documents by task batch, preventing cross-batch data confusion. The presence of proprietary vocabularies and quality control samples means traceability results must also link to annotation specifications and spot-check bases. This ensures traceability for transcription errors covers two high-risk areas: proprietary vocabulary verification and speaker differentiation. Additionally, the completeness of fields in structured transcribed text requires traceability information to include detailed dimensions such as speaker identifiers and annotator information, enabling precise positioning for defect analysis.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the single-batch length of speech transcribed text, avoids truncating critical traceability information, and adapts to the token allocation rules of FastGPT v4.17.0 |
| `responseData` | Includes timestamps and speaker identifiers | Adapts to the structured characteristics of speech data, supports defect traceability for noisy segments and speaker differentiation |
| `detail` | Enabled | Displays complete audio segment citation information, facilitating matching against spot-check samples in quality inspection reports |
| Citation Recall Limit | Top 6 entries | Covers the main annotation sources for a single-batch task, avoids redundant information interfering with analysis |
| Chunk Matching Granularity | Per audio second-level segment | Corresponds to the timestamp characteristics of speech data, accurately locating erroneous audio segments |
| Task Batch Association | Bind knowledge base by batch ID | Adapts to the daily or batch-based data update rhythm, quickly filtering traceability documents for the corresponding task |

## Three Common Misconfigurations
- Failing to specify structured fields when configuring `responseData` will result in returned results only containing text fragments, with no way to associate audio timestamps and speaker identifiers. This prevents locating the source of noisy segments or speaker differentiation errors.
- Failing to bind task batch IDs when dynamically passing knowledge base variables will expand the search scope to cover the full knowledge base. This prevents matching the current batch's audio list and transcription specifications, leading to situations where no citation results are returned.
- Failing to enable the `detail` configuration will only return concise answers, missing associated citations for quality inspection reports and vocabularies. This makes it impossible to trace the basis for proprietary vocabulary verification errors.

## How to Verify the Configuration Is Correct
- Initiate a test request covering scenarios of proprietary vocabulary verification and speaker differentiation. Check whether the returned results include fields such as audio timestamps and speaker identifiers.
- Dynamically pass knowledge base variables for a specified task batch. Verify whether the returned citation sources only associate with the current batch's audio list and transcription specifications.
- View the answer detail page. Confirm whether complete information of associated traceability documents such as quality inspection reports and vocabularies is displayed.
- Test queries for transcribed text containing noisy segments. Verify whether the recalled citations can match the corresponding original audio segment information.

The values provided are common starting points and should be measured against the reader's own samples.
