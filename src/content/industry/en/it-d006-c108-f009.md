# Test Cases and Defect Analysis for Warranty Period Defect Response: Tool Calling and Plugins

## What the Data for This Category Looks Like
Data sources for this category include customer-submitted warranty work orders, system operation logs, contract warranty clauses, and project version update records. Daily circulating documents include warranty work orders, defect confirmation sheets, repair records, and customer confirmation sheets. Each document corresponds to work order number, defect description, trigger time, responsibility determination result, repair version, and customer closed-loop confirmation identifier respectively. Data update frequency is daily or triggered per order, and core fields are updated in real time alongside defect processing progress.

## What Constraints These Characteristics Impose on the Tool Calling and Plugins Link
Dispersed data sources and unstructured, semi-structured formats require the tool calling chain to support automatic pulling of multi-source documents and field mapping. The high update frequency requires tool triggering timing to match the rhythm of single-order processing or daily batch synchronization, to avoid delayed or repeated calls. Field differences across multiple documents require the tool calling to preset clear parameter rules, ensuring data from different sources can be uniformly used for defect analysis. The consequences of errors in defect processing directly relate to customer rights, requiring tool calling results to be traceable, and combining warranty clauses to assist in determining responsibility boundaries.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapt to automatic tool calling requirements for different defect work orders, no need to manually specify call type |
| `functionCall` | `[{"name":"query_quality_clause","parameters":{}}]` | Preset call to the warranty clause query tool to assist in quickly completing responsibility boundary judgment, configured based on the plugin calling rules of FastGPT v4.17.0 |
| Single recall result limit | Top 3 entries | Avoid excessive redundant information interfering with defect analysis, focus on core warranty clauses and defect records |
| Maximum context length | 8000–12000 token | Accommodate content from multiple documents including work orders, logs, contract clauses, etc., to ensure complete analysis dimensions |
| Question optimization switch | Enabled | Convert vague defect descriptions into standard query statements recognizable by tools, improving tool calling accuracy |

## Three Common Misconfigurations
- When debugging tool calling nodes, two separate large model thinking logs appear in the logs. Cause: The tool calling mode is not set to forced via the `toolChoice` configuration. The large model first attempts to generate natural language replies, then triggers the tool calling process.
- Unable to retrieve knowledge base content after enabling tool calling. Cause: The tool calling configuration prioritizes calling external interfaces, and does not retain the plugin calling chain for knowledge base retrieval, or does not include the knowledge base as an optional tool in the configuration.
- Parameter format errors occur when calling a locally deployed large model. Cause: Confusing the parameter verification logic of online APIs and local deployments, and failing to adapt to the input format constraints of the local model.

## How to Confirm Proper Configuration
- Submit a test warranty work order, check the tool calling logs to confirm whether the warranty clause query plugin is triggered as configured.
- Check whether the large model reply includes warranty clause content pulled from the knowledge base, with no redundant or missing key clause information.
- Verify that when calling a local large model, differences in input parameters between online API configurations have been adapted, with no format-related errors.
- Check whether the tool calling return results are correctly mapped to the responsibility determination field of the defect confirmation sheet, with no field misalignment issues.
