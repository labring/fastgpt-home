# Test Cases and Defect Analysis for Warranty Defect Response: Quote Sourcing and Traceability

## What Data for This Category Looks Like
This category's data primarily comes from customer-submitted warranty work orders, system operation logs, project contract warranty clauses, and software version update records.
Daily generated documents include warranty work orders, defect confirmation sheets, repair records, and customer confirmation sheets.
Data updates occur daily or as each individual business order progresses.
Data fields include work order number, defect description, liability determination basis, repair version, customer confirmation status, and more.
There is no unified standardized format. Association and matching must be completed according to business document type.

## Constraints on Quote Sourcing and Traceability
Scattered data sources and lack of a unified format require traceability to link multiple types of business documents. This prevents deviations in liability boundary judgments.
The high update frequency means the traceability process must pull real-time latest data. Static caching cannot be used.
Field differences across different documents require matching exclusive fields for each document type. For example, do not mix the defect description field from warranty work orders with the version field from repair records.
Traceability results directly impact warranty dispute decisions. Every quoted reference must accurately map to the original business document. Vague association with unrelated data is not permitted.

## Configuration Settings
These configurations follow the parameter rules for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---|---|--- |
| `quoteMaxToken` | `800–1200 token` | Covers the core content of a single complete warranty work order or defect confirmation sheet |
| `responseData` | Enabled | Retains original text snippets of business data, supports direct reference to raw content from databases or knowledge bases |
| `detail` | Enabled | Retains original field information for data, making it easier to match exclusive fields across different documents such as warranty work orders and repair records |
| Single recall limit | Top 3–5 entries | Prevents excessive redundant data from interfering with the large model's judgment of defect liability |
| Data source filtering rules | Classify by warranty work order and defect confirmation sheet | Matches the unique document structure of this category, avoids linking unrelated business data |

## Three Common Misconfigurations
- Issue: The large model's response does not link to the original text snippets of specific business documents, only providing general conclusions. Cause: The `responseData` configuration is not enabled, and no data source filtering rules are configured. Raw business data cannot be pulled.
- Issue: The number of references returned by the search exceeds expectations, and cannot be adjusted via configuration. Cause: `quoteMaxToken` or the single recall limit is not set correctly, and data sources are not filtered by the category's document structure.
- Issue: After switching the embedding model, traceability results cannot match the exclusive fields of warranty work orders. Cause: No adjustment to the embedding model adaptation rules for the category's unique data structure, and no verification of data source consistency.

## How to Verify Proper Configuration
- Submit a test query targeting a specific warranty defect. Check if the returned results include field snippets from original business documents, such as work order numbers or repair versions.
- Review the current values of configuration items. Confirm that the settings for `quoteMaxToken`, `responseData`, and `detail` align with preset rules.
- Submit a test query after switching the embedding model. Verify that traceability results still match the category's unique data structure.
- Adjust the single recall limit value. Confirm that the number of returned references falls within the set range.

The values provided here are common starting points. They should be evaluated against the reader's own samples.
