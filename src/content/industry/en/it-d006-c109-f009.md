# Test Cases and Defect Analysis for Identity, Account, and Permission Management: Tool Calling and Plugins

## What this category of data looks like
This category of data primarily originates from enterprise IAM systems, HR systems, business system operation logs, and approval systems. Data updates trigger in real time alongside personnel changes. The routine batch synchronization runs once per day. Core documents include account application forms, permission matrix tables, deactivated account recovery forms, and compliance audit reports. Fields cover account unique identifiers, employee affiliated departments, permission group configurations, effective and expiration times, approval node status, and no additional custom statistical fields.

## How these characteristics constrain tool calling and plugin workflows
Decentralized data sources require tool calling plugins to support multi-source authentication docking with IAM, HR, business log, and approval systems, to prevent cross-system permission leaks. The combination of real-time updates and daily batch synchronization requires plugins to support both event-triggered and scheduled pull invocation modes. This supports immediate synchronization for personnel changes and daily batch verification. Fixed document structures require plugin input and output fields to match the standard formats of account application forms and permission matrices, with no flexible support for non-standard fields. Plugins must also include built-in pre-check logic for unauthorized access and residual accounts, to reduce the impact of error consequences.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to dynamic selection needs for parallel multi-system calls |
| `functionCall` | Enabled | Support structured returns of standardized fields, matching the fixed format of permission documents |
| Plugin call timeout | 300 seconds | Adapt to the typical response duration of IAM system interfaces |
| Batch sync trigger cycle | Daily at 00:00 | Match the batch processing rhythm of routine permission reviews |
| Abnormal permission data cache | 1000 MB | Meet temporary storage needs for daily permission logs and application forms |
| Multi-source authentication retry count | 3 times | Balance call success rate and system resource consumption |

## Three common mistakes
- An internal server error displays when installing the database connection plugin. The root cause is missing cross-system authentication keys for the IAM system, which prevents the plugin from pulling permission matrix data.
- The `dataId` field cannot be retrieved when calling the API to fetch permission data. The root cause is that `functionCall` is not enabled in the plugin configuration, resulting in non-standard structured data output.
- Permission data fields returned by the plugin are empty. The root cause is failure to match the standard field format of account application forms, leading to data parsing failure.

## How to confirm successful configuration
- Manually trigger a synchronization call for an account application form. Verify that the returned data includes required fields such as account ID and permission groups, and confirm that the corresponding `dataId` can be obtained.
- Access the MinIO storage bucket, confirm that permission logs and deactivated account recovery form data have been stored per the configured path, and verify that MinIO is operating correctly.
- Simulate an employee departure event, and verify whether the plugin triggers real-time synchronization and updates the deactivated account recovery status.
- Check the FastGPT v4.17.0 plugin call logs, and confirm that no internal server errors or field parsing exceptions occur.
