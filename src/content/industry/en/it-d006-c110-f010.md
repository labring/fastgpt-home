# Test Case and Defect Analysis for On-site Outsourced Operations Services: Source Citation and Traceability

## What the data for this category looks like
The typical entities in this category are on-site outsourced engineers, service managers, and customer IT departments. Data typically originates from customer ITSM systems, monitoring platforms, asset inventories, and on-duty logs. Update cycles are split into daily and monthly. Daily deliverable documents include on-site daily reports, service desk tickets, inspection reports, and SLA monthly reports. Relevant fields include ticket numbers, inspection items, SLA compliance rates, on-site staff on-duty windows, and more. The data covers the full delivery workflow of on-site services, with no unified mandatory format requirements.

## What constraints do these characteristics impose on the "source citation and traceability" workflow
The scattered distribution of data sources means the traceability workflow must associate unique identifiers across multiple systems to prevent cross-data-source citation conflicts. Differences in update cycles require separate traceability logic for daily inspection data and monthly SLA reports, to align with varying update frequencies. The diversity of document structures means traceability tools must support field extraction across formats including on-site daily reports and tickets. Additionally, errors in this category can directly impact service contracts, so traceability accuracy must meet delivery compliance standards, with no missing citations or incorrect identifiers allowed.

## How to set up the configuration
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | Adapts to the average length of documents such as on-site daily reports and inspection reports, ensuring complete citation content |
| `responseData` | Return only associated fields | Reduces redundant data, focusing on core traceability fields such as ticket numbers and inspection items |
| `detail` | Enable full-field traceability | Meets traceability requirements requiring multi-dimensional association such as SLA monthly reports |
| Single search limit | Top 8 entries | Covers the average volume of tickets and inspection records generated daily for on-site services |
| Data source association rule | Configure according to customer ITSM identifier format | Adapts to differences in system field naming across different customers |
| Traceability update frequency | Daily/Monthly tiered matching | Matches the daily and monthly update cycles of data in this category |

## Three common configuration errors
- The conversation request API does not return the cite citation ID. This occurs when full-field traceability for the `detail` configuration item is not enabled, so the citation identifier field is not included in the returned data.
- Variable references fail after selecting a knowledge base in the knowledge base search card. This occurs when the data source association rule is not configured, preventing matching of unique identifiers for on-site tickets and inspection reports.
- A field empty error appears when viewing knowledge base citations in chat responses. This occurs when `quoteMaxToken` is set too small, causing cited content to be truncated and unable to match source data.

## How to verify the configuration is complete
- Initiate a test request, check if the returned result includes the cite citation ID, and confirm the configured `quoteMaxToken` matches the length of the current test document.
- Launch a search using the target knowledge base, verify that variable references can correctly associate source data for on-site tickets or inspection reports.
- View the citation module in chat responses, confirm there are no field format errors or missing fields, and adjust validation rules to match the target customer’s system format.
- Switch between daily and monthly data sources, verify that the traceability logic automatically adapts to the configured update frequency.
