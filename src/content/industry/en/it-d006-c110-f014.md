# Test Case and Defect Analysis for On-site Outsourced Operations Services: Model Integration and Configuration

## What Data for This Category Looks Like
Data related to test case and defect analysis for on-site outsourced operations services primarily comes from customer ITSM systems, monitoring platforms, asset inventories, and on-duty logs. Daily produced documents include on-duty daily reports, service desk tickets, inspection reports, and SLA monthly reports. Data update frequencies fall into two categories: daily and monthly.
On-duty daily reports include fields such as on-duty timeframes, ticket processing entries, and inspection completion status. SLA monthly reports track service compliance and related records. The field structures and update cycles of all documents align with the contracted delivery requirements of on-site services.

## What Constraints These Characteristics Impose on Model Integration and Configuration
Dispersed data sources covering multiple systems require model integration to support unified pulling and parsing of multi-source data. Diverse document structures and varying update cycles require configuring prompt templates and context windows adapted to different fields.
The contracted nature of on-site operations services requires model calls to isolate customer data. It also requires retaining complete call logs to meet audit requirements.
The rigor of defect analysis requires model parameters to align with the business logic of on-site scenarios. This avoids generating conclusions that do not comply with operations specifications.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | Root address of the AI Proxy service, for example http://aiproxy:3000. Do not append /v1 or /chat/completions, and do not use single-model addresses such as VLLM/Ollama/Xinference | This variable is a required environment variable for the App/Admin server, and must match the deployment address of the AI Proxy server |
| `AIPROXY_API_TOKEN` | AI Proxy administrator token. Must match the configuration of the AI Proxy server and cannot be empty | This variable is a required environment variable for the App/Admin server, and must not be an application API key, model vendor secret, or token issued per application |
| `maxContext` | `8000–12000 token` | Covers content from multiple documents such as on-site tickets and inspection reports over 1-3 days, avoiding context truncation |
| `maxTokens` | `2000–3000 token` | Ensures that the output of test case and defect analysis includes complete troubleshooting suggestions and rectification plans, meeting the delivery requirements of on-site services |
| `toolChoice` | `auto` | Automatically calls document parsing and log query tools to adapt to the processing needs of multi-source data |
| `temperature` | `0.3–0.5` | Maintains the rigor of defect analysis conclusions, avoiding overly divergent troubleshooting directions |

## Three Common Misconfigurations
- Adding the `avatar` field in the model configuration file and using a web link causes model startup failure. The dedicated model for outsourced on-site operations services does not support custom avatar configuration, so this field is not required.
- Attempting to use an unauthorized speech recognition model results in a permission denied error during calls. Model integration for on-site services must use contracted models agreed upon in the contract, and unauthorized models cannot pass permission verification.
- Unable to find corresponding records when viewing OneAPI call logs. The log retention configuration for model calls is not enabled. The audit requirements for on-site services require enabling complete log recording.

## How to Confirm Successful Configuration
- In FastGPT v4.17.0, initiate a test case generation request, and check whether the returned result includes associated information from on-site tickets.
- Check the App/Admin server startup logs to confirm there are no startup verification failures caused by missing `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN`.
- Adjust the `temperature` parameter, and check whether the rigor of the analysis results meets expectations.
- Verify the multi-source data pulling function, and confirm that documents from sources such as ITSM and monitoring platforms can be properly parsed by the model.
