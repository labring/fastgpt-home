# Test Cases and Defect Analysis for Configuration Management and CMDB Maintenance: Tool Calling and Plugins

## What This Category's Data Entails
Data for this category is generated around the configuration and association relationships of IT service components. Daily maintenance documents include configuration item lists, service component relationship topologies, change records, and asset inventory tables. Data sources include enterprise-owned CMDB systems, cloud resource lists, automated asset discovery tools, and procurement ledgers. Data update frequency is daily or weekly. Core fields include configuration item unique identifiers, component types, dependency relationships, and change timestamps. No unified quantitative units are used, and fields are adjusted based on asset categories. In daily work, configuration item collection, cross-component relationship verification, and post-change synchronization are the most time-consuming steps. Data deviations directly affect fault location and impact scope analysis. The core difference from general IT asset inventory is the focus on dependency relationships between service components.

## Constraints Imposed on Tool Calling and Plugins
Because data sources are scattered and have different update rhythms, tool calling must adapt to the timing requirements of multi-source data pulling. The pulling cycle for different data sources must be clearly specified. The field structures of configuration items and relationship topologies are complex and adjusted based on asset categories. Tool calling must preset field mapping rules to avoid data parsing failures caused by mismatched field names. Change records have high real-time requirements. Batch execution tools must support filtering entries to be processed by change timestamp. At the same time, data deviations directly affect analysis results. Tool calling must include built-in verification logic to mark abnormal configuration items that do not match actual assets. Compared with general IT asset inventory scenarios, this category requires additional processing of dependency relationships between service components. Plugins must support recursive pulling and verification of topology relationships.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0.
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapt to dynamic calling requirements for multi-source data pulling, no need to manually specify a fixed tool |
| Batch execution concurrency | `2–4` | Adapt to the call limits of CMDB and cloud resource interfaces, avoid triggering rate limiting |
| Parameter priority rule | Prioritize workflow variables, then plugin default values | Match dynamic configuration update needs in operation and maintenance scenarios, support temporary parameter adjustments |
| Data verification switch | Enabled | Prevent configuration items that do not match actual assets from entering subsequent analysis processes, reduce error risks |
| Timeout setting | `600 seconds` | Adapt to the time requirements of multi-source data pulling, avoid workflow interruptions caused by overly long single calls |
| `functionCall` | Enable batch mode | Support pulling associated data for multiple configuration items at the same time, improve processing efficiency |

## Three Common Misconfigurations
- When a CMDB data pulling tool is called in a workflow, a parameter mismatch error is returned. This manifests as empty interface return fields or format errors. The cause is failure to map tool input parameters according to the field names in the configuration item list, leading to parsing failure.
- The plugin fails to obtain parameter values according to the preset priority. This manifests as failing to automatically use the default value when the specified workflow variable is not read, and directly throwing a parameter missing error. The cause is failure to enable the parameter priority verification configuration.
- The number of results returned by the batch execution tool does not match expectations. This manifests as the number of results being less than or more than the number of entries to be processed. The cause is failure to set the correct change timestamp filtering condition, leading to pulling historical data outside the intended range.

## How to Verify Correct Configuration
- Initiate a tool call for a single configuration item, verify that the fields in the returned result fully match those in the configuration item list.
- Manually remove the configured workflow variable, confirm that the plugin automatically uses the preset default parameter values without throwing a parameter missing error.
- Submit a batch execution task, check that the task log marks abnormal configuration items that do not match actual assets, with no abnormal error messages present.
- Wait longer than the `600 seconds` timeout setting, confirm that the workflow is not interrupted due to call timeout and that a complete data set is returned.
