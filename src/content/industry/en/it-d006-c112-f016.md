# Test Case and Defect Analysis for Issue Management and Root Cause Analysis: Forms and Interactions

This page is compatible with FastGPT v4.17.0.

## What Data for This Category Looks Like
Data for this category comes from fault timelines, operation logs, monitoring metrics, and code commit records. Update frequency is every major outage or once per month. Daily produced documents include RCA reports, issue tickets, post-incident review minutes, and rectification tracking sheets. Fields include fault occurrence time, root cause type, rectification measures, and tracking status. There are no uniform mandatory units. Some fields need to be linked to original log timestamps and code commit hashes.

## What Constraints These Characteristics Impose on Form and Interaction Workflows
Data sources are scattered and rely on original logs and code records. Fast association and entry of multi-source data is handled by external business systems or downstream nodes. Update frequency is not fixed, so temporary retroactive entry must be supported. Batch import is handled by external business systems or downstream nodes. Daily documents have diverse structures, so the system must support pasting content in different formats. Structured editing is handled by external business systems or downstream nodes. Root cause analysis requires repeated verification, so multi-round draft saving and version rollback are handled by external workflows or the host platform. Rectification tracking requires closed-loop management, so the system must bind status fields and assignees. Association logic is handled by external business systems. Because the consequences of errors are severe, the form must have mandatory key fields to avoid missing core information that leads to ineffective rectification or repeated outages.

## Three Common Misconfigurations
- Phenomenon: An upload failure prompt pops up when uploading RCA reports or log files, while text input in conversations works normally. Cause: The file format whitelist supported by the external business system is not configured, or the file size exceeds the limit set by the external business system.
- Phenomenon: After importing a markdown-format post-incident review minutes, the title hierarchy and subordinate category relationships are lost. Cause: External structured parsing logic is not configured, and content is only processed as plain text segments.
- Phenomenon: After submitting the rectification tracking sheet, the associated incident ticket status is not automatically updated. Cause: Field linkage rules between the external business system and the existing issue management system are not configured, resulting in data desynchronization.

## How to Verify Proper Configuration
- Enter a long text segment, verify that the `formInput` node supports full entry and format pasting.
- Attempt to select an assignee, confirm that the `userSelect` node can normally retrieve the preset team member list provided by the external business system.
- Import a test markdown file, check if the external structured parsing logic correctly parses title and category relationships into independent fields.
- After submitting the information collected by the `formInput` node, check if field linkage between the external business system and the existing issue management system takes effect, and if data is synchronized and updated.
