# Integration Testing and API Testing Test Case and Defect Analysis: Forms and Interactions

## What this category of data includes
Data for this category originates from API management platforms, test environment logs, databases, and message queues. Data is updated daily or per version release cycle. Daily generated documents include API test cases, joint debugging issue tickets, environment descriptions, and test reports. API test cases contain fields such as API addresses, request parameters, expected responses, and test preconditions. Joint debugging issue tickets record trigger scenarios and troubleshooting processes for link anomalies. Data fields must align with cross-module interaction verification requirements. This page is compatible with FastGPT v4.17.0.

## Constraints for forms and interactions
Cross-module interaction verification requirements require that parameters collected by forms match existing parameter formats from API management platforms and abnormal fields from test environment logs. Parameter linkage logic is handled by external systems or downstream nodes. The daily or per-version update nature of data requires rapid reuse of historical test cases via external systems. Version tracing is managed by external document management systems. The need to associate multiple document types requires configuring external document jump entrances via external systems, with entrance directions provided by external business systems. Fields must strictly match the standard structure of API test cases to prevent test data from being unusable due to field incompatibility.

## Three common configuration errors
- Phenomenon: After submitting an API test case, the admission ticket field is not fully filled but still passes validation, triggering subsequent test exceptions. Cause: Required field validation rules are not configured in external verification logic, and core parameters such as admission tickets are not covered.
- After submitting a form related to integration testing and API testing, downstream nodes do not receive complete fields. Compare required items, actual submitted content, and node output mappings one by one, then check downstream API responses. Existing symptoms alone cannot determine the root cause.
- Phenomenon: After submitting a joint debugging issue ticket, it is not synchronized to test logs, and abnormal trigger scenarios cannot be directly traced via the form. Cause: External system linkage rules are not configured, and external document jump entrances are not added.

## How to verify successful configuration
- Submit a test case with incomplete parameters, confirm that the external verification logic pops up a prompt for missing required fields.
- Call externally defined variables in the JSON input box, confirm that variables can be inserted normally and generate valid JSON format.
- Import the test case template exported from the API management platform via the external system, confirm that fields match the form structure without manual adjustment required.
- After submitting the test case, confirm that the external system automatically generates a jump link for the corresponding test log.
