# Test Case and Defect Analysis for Requirements Analysis and PRD Management: Workflow Orchestration

## What Data for This Category Looks Like
Daily documents for this category include requirement research notes, PRDs, user story lists, and requirement change forms. Data sources are mostly customer interview records, ticketing systems, competitor public pages, and analytics dashboards. Update frequency is usually weekly or per version release cycle. Document structures vary widely. Notes focus on interview key points. PRDs include business objectives and acceptance criteria. Change forms record details of requirement adjustments. There are no unified mandatory standards for fields. Core fields include requirement ID, business scenario, acceptance condition, and change time. The most time-consuming steps are classifying interview information, confirming boundary conditions, and synchronizing requirement changes. Improper handling can lead to development rework, schedule delays, or acceptance disputes.

## Constraints on Workflow Orchestration From These Characteristics
Multi-source, heterogeneous document structures for this category require workflows to support multi-format input adaptation. Configure variable binding rules to filter irrelevant data. Weekly or version-level update frequencies require workflows to support regular synchronization of the latest requirement change forms and PRD versions. This prevents expired documents from being used to generate test cases. High manual costs for core time-consuming steps require workflows to include AI-assisted classification and verification nodes. This reduces manual classification workloads. The severity of potential errors requires workflows to add an acceptance criterion verification link. This ensures generated test cases fully match PRD acceptance conditions. Configure an exception alert node to notify relevant personnel promptly when a process error occurs.

## How to Configure Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| AI Session Node Temperature Setting | Disabled | Requirement analysis documents require strict accuracy. This prevents AI-generated content from diverging from business objectives. It also avoids issues with inconsistent effects of temperature parameters. |
| `variables` Binding Scope | Only associate with current PRD and associated change forms | Avoid introducing irrelevant historical requirement data. Ensure test cases match current requirements. |
| Question Classification Node Match Result Limit | Top 3 entries | Requirement documents have few fields. Too many match results increase manual screening costs and reduce node processing speed. |
| Context Window Length | 8000 characters | Adapt to the standard length of most PRD documents. Ensure complete reading of core business information. |
| nodeId | Bind to test case generation node | Enable automatic linkage between the requirement analysis phase and the test phase. Synchronize acceptance conditions to test cases. |
| Timeout Threshold | 60 seconds | Prevent workflow blocking caused by prolonged document loading or AI processing. |

## Three Common Configuration Mistakes
- Symptom: The AI session output appends the fixed prompt "FastGPT is a knowledge base question answering system based on large language models (LLM)" at the end. Cause: Failed to disable the default brand prompt in system settings, or the workflow did not include a prompt rewriting step.
- Symptom: Workflow execution times out. Cause: No reasonable timeout threshold is set, or too many non-associated requirement document data are bound, leading to excessive processing load.
- Symptom: Consecutive multi-line line breaks do not display correctly. Cause: Native line break parsing is not enabled in the text output node, or input variables do not retain original line break formatting.

## How to Verify Correct Configuration
- Run a test workflow. Import a test PRD document. Check that the output does not include extra brand prompt text. Confirm that default prompts are disabled.
- View the workflow's variable binding configuration. Verify that only the current PRD and associated change forms are associated. No irrelevant historical requirement data is included.
- Trigger the question classification node. Check that the number of returned match results matches the preset top 3 configuration. No redundant results are present.
- Input test text containing multiple line breaks in the text output node. Confirm that line break formatting displays correctly.

The values provided are common starting points and should be measured against the reader's own samples.
