# Test Case and Defect Analysis for Project Implementation Plan Management: Quote Source and Traceability

## What the Data for This Category Looks Like
This category of data primarily comes from contracts, work breakdown structures (WBS), client schedules, and project management systems. Core daily documents include project plans, milestone lists, weekly reports, and risk issue lists.
Data updates are triggered weekly or per individual milestone node. Fields include task breakdown items, responsible persons, scheduling nodes, risk levels, and rectification requirements. There is no unified mandatory format, and adjustments are made based on project scale and client requirements.

## Constraints Imposed by These Characteristics on the "Quote Source and Traceability" Link
Dispersed data sources and inconsistent update frequencies require clear matching of the document version corresponding to the project cycle when quoting, to avoid using expired content.
There is no unified document structure, so traceability tagging for multi-source heterogeneous content must be supported. Association cannot rely on fixed field formats.
Core fields are linked to project progress and costs. During traceability, tasks, schedules, and risk items must be accurately bound, and associated data from different projects must not be confused.
After data updates, the quote link must be synchronized to ensure traceability information matches the current project status. For cross-party collaboration sources, both internal and external document identifiers must be marked.

## Configuration Settings
Note: This configuration applies to FastGPT v4.17.0 and above.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 1200–1800 token | Matches single-paragraph quote lengths for documents such as project plans and weekly reports, avoiding truncation of core scheduling and responsible person information |
| Reordering | Enabled | Adapts to multi-source heterogeneous project documents, improves sorting accuracy of relevant fragments, and reduces invalid quotes |
| Single Search Limit | Top 6 entries | Corresponds to retrieval volume for multi-field documents such as WBS and risk lists, covering core tasks and risk items |
| Similarity Threshold | 0.75–0.85 | Filters low-relevance non-project documents, focusing on valid sources such as contracts and client schedules |
| `detail` | Enabled | Retains complete field information for quote fragments, making it easy to verify task responsible persons and scheduling nodes during traceability |
| `responseData` | Return only quote source markers | Focuses on traceability requirements for project data, avoiding redundant content that interferes with core information |

## Three Common Misconfigurations
- Symptom: Empty quote fragments after enabling reordering, with no matching content in search results. Cause: Failure to adjust the similarity threshold. Reordering filters valid project documents that originally met the basic threshold, resulting in no available sources for traceability.
- Symptom: Quote timeout, with complete traceability information unable to be returned. Cause: Failure to adjust the `quoteMaxToken` parameter. Excessively long quote fragments exceed the system processing limit, triggering timeout restrictions.
- Symptom: Quote content inconsistent with the current project cycle, with traceability pointing to expired weekly reports or historical milestone documents. Cause: Failure to bind document versions to project milestone nodes, directly quoting historically updated document content.

## How to Confirm Proper Configuration
- Import a single project plan document, trigger a search, and verify that returned quote fragments include core fields such as tasks, responsible persons, and scheduling.
- After enabling reordering, compare the number of quote results before and after to confirm the sorting logic is active.
- Check that quote markers are associated with the source path and update time of the corresponding document, ensuring complete traceability information.
- Test cross-source retrieval (contracts, client schedules, WBS) to confirm that quote markers from multiple sources can be displayed normally.

The values provided are common starting points and should be measured against the reader's own samples.
