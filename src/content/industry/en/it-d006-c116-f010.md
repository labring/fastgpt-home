# Test Case and Defect Analysis for Project Document Handover and Archiving: Citation Sources and Traceability

## What this category’s data looks like
This category of data primarily comes from project document libraries, configuration lists, meeting minutes, and test reports. Daily produced documents include completion documents, configuration manuals, training records, and acceptance certificates. Data is updated synchronously at the end of each project phase or when the overall project wraps up. Documents typically contain fields such as document version number, associated project identifier, signature status, test case number, and defect record number. There are no fixed unified unit fields, and the content is mainly text-based descriptions.

## What constraints do these characteristics impose on the "citation sources and traceability" link
Project document handover and archiving data is mostly updated in phases. When citing, it is necessary to match the version corresponding to the project cycle to avoid citing expired documents across phases. Document fields include identifiers related to test cases and defects. During traceability, precise association with records of the corresponding test links is required. Since the data update frequency is not fixed, it is necessary to verify the latest version status of the document when citing, to prevent citing draft documents that have not completed signature or archiving. Additionally, most documents are text-based content, so it is necessary to ensure that the specific chapters and entries of the original document can be accurately matched during citation, to facilitate subsequent acceptance checks and operational traceability.

## How to configure it
This configuration applies to FastGPT v4.17.0 and above. The specific parameter settings are as follows:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the single-paragraph text length of project documents to avoid truncating key descriptions of test cases and defects |
| `responseData` | Include citation source metadata | Ensure that the returned results carry traceability fields such as document version number and associated project ID |
| `detail` | Enable full traceability mode | Display the specific chapter location of the original document to facilitate checking the association between test cases and defects |
| Single search limit | Top 3 matching results | Focus on the most relevant project documents to avoid redundant information interfering with test case analysis |
| Version verification switch | Enabled | Ensure that only the latest version of documents from the current project phase is cited |

## Three common errors
- Interface calls succeed but return no valid content, only empty fields. The cause is that the `responseData` parameter is not correctly configured, and the return switch for citation source metadata is not enabled, causing the system to fail to associate valid data from the project document library.
- The cited document version does not match the current test phase, and expired test case content appears. The cause is that the version verification switch is not enabled, allowing citation of unarchived draft documents from historical phases.
- Cited content has formatting confusion or truncation exceptions. The cause is that a reasonable `quoteMaxToken` parameter is not set, causing abnormal splicing after long text is truncated, or the `detail` mode is not enabled, resulting in loss of chapter information from the original document.

## How to confirm the configuration is correct
- Initiate a test request containing test case keywords, check whether the returned results include metadata fields such as document version number and associated project ID, to confirm that the `responseData` configuration is effective.
- Submit a test case query containing historical version identifiers, verify whether the system only returns the latest documents of the current project phase, to confirm that the version verification switch is effective.
- View the details of the returned citation source, confirm whether the specific chapter location of the original document is displayed, to confirm that the `detail` mode is enabled.
- Adjust the `quoteMaxToken` parameter to different ranges, submit a defect query containing long text descriptions, and verify that the returned content is not excessively truncated or abnormally spliced.

The values provided are common starting points and should be measured against the reader's own samples.
