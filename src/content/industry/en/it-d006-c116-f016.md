# Test Cases and Defect Analysis for Project Document Handover and Archiving: Forms and Interactions

## What the Data for This Category Looks Like
The service subjects for this category are project managers, implementation consultants, and customer archive administrators. Daily delivered documents include four types: completion documents, configuration manuals, training records, and acceptance certificates. Data sources cover project document libraries, configuration lists, meeting minutes, and test reports. Updates follow cycles tied to project phase milestones or project completion. Each individual document includes fixed fields such as project number, version number, signature information, and acceptance date. Core data requires cross-source verification before archiving. Missing or inconsistent core data can lead to failed acceptance, lack of materials for subsequent operations, delayed final payment, and other issues.

## What Constraints These Characteristics Impose on the "Forms and Interactions" Link
Data sources for this category are scattered and require cross-source verification. Split forms by document category and display them via the external business system interface, to avoid verification errors caused by mixed fields. Enable mandatory validation for the form due to the presence of fixed fields, to prevent acceptance issues caused by missing core information. Use the external system to limit form data scope to content associated with the current project, to match the phase-based update rhythm and avoid confusion across project data. Implement cross-source data consistency verification via external business systems or subsequent workflow branches, to enable linkage verification of cross-document fields and ensure version information consistency between configuration lists and test reports.

## Three Common Mistakes
- Phenomenon: After submitting the form, a prompt "Core field is empty" appears, but the page shows that the field has been filled in. Cause: No linkage verification rules are configured for cross-document associated fields (such as acceptance date and project number) via external business systems or subsequent workflows, resulting in the form failing to correctly identify the mandatory field status when submitted.
- Phenomenon: Only part of available knowledge bases are displayed when selecting a document library, and the exclusive document library for the current project cannot be found. Cause: The optional scope configured via the FastGPT user selection node is not limited to document libraries associated with the current project; pulling all knowledge bases by default causes screening confusion.
- Phenomenon: Submission of JSON-format attachment metadata fails, and the system pops up a format error prompt. Cause: No JSON format input verification rules are configured via external business systems; metadata submitted by the FastGPT form input node is blocked because the format does not meet requirements.

## How to Confirm Proper Configuration
- Submit a simulated project document handover form, check whether the external business system pops up a clear verification prompt when mandatory fields are empty.
- Switch between different project-associated document libraries, confirm that the optional scope of the FastGPT user selection node only includes document libraries for the current project.
- Upload JSON metadata that meets standard formats, confirm that the FastGPT form input node can submit content normally, and that external business systems or subsequent nodes can receive and process it normally.
- Wait for the test example: verification process of more than 120 seconds, confirm that the external verification logic will not interrupt execution actions due to timeout.
