# Online Troubleshooting and Retrospective for IT Asset Inventory: Deployment and Upgrade

## What Data for This Category Looks Like
Data for IT asset inventory is sourced from asset management systems, procurement systems, financial fixed asset ledgers, and terminal management platforms. Update frequency is monthly, quarterly, or annually. Core documents include asset ledgers, inventory sheets, loan and return forms, and scrap applications. Fields include asset ID, name, owner, storage location, usage status, purchase date, scrap status, and more. Core focus areas are asset ownership, actual storage location, and current user. The difference from configuration management data is that it does not prioritize device configuration parameters, only focusing on physical asset ownership and circulation records.

## What Constraints These Characteristics Impose on Deployment and Upgrade
The need to integrate multiple data sources requires configuring interface adaptation rules compatible with different systems during deployment, to avoid format conflicts during data synchronization. The low-frequency but bulk update rhythm requires adjusting concurrent read/write thresholds for storage, to prevent connection exhaustion during bulk imports. Core fields focus on ownership, location, and user, requiring clear data mapping rules during deployment to ensure imported asset data includes corresponding fields. Errors can lead to asset loss and audit risks, so startup verification and failure alert configurations must be enabled during deployment to maintain data consistency.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 100–200 connections | Adapts to concurrent read/write demands for bulk asset ledgers and inventory records, preventing database connection exhaustion |
| `MONGODB_URI` | MongoDB instance address with authentication credentials | Stores structured and semi-structured data such as asset ledgers, inventory records, and scrap applications |
| `REDIS_URL` | redis://:authentication password@host address:port/database number | Caches frequently accessed asset ownership and location information to speed up queries during account-physical verification |
| `STORAGE_S3_ENDPOINT` | Fill in according to the deployed object storage service endpoint, such as `http://minio:9000` | Stores file resources such as asset inventory attachments and scrap application materials |
| `FE_DOMAIN` | Frontend access domain name of the deployment environment | Configures the validity of jump links for asset-related pages, ensuring download links are accessible normally |
| `FILE_TOKEN_KEY` | Randomly generated string of 32 or more characters | Encrypts asset file download links to prevent unauthorized access to sensitive asset materials |

## Three Common Misconfigurations
- Symptom: Asset file download links return 404 or fail to load normally. Cause: `FE_DOMAIN` and file storage mapping rules are not configured correctly, leading to a mismatch between the generated link domain name and the actual access domain name.
- Symptom: FastGPT service fails to start, with logs indicating missing required environment variables. Troubleshooting: FastGPT v4.17.0+ has a startup verification failure issue when `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service, example: http://aiproxy:3000; do not append /v1 or /chat/completions paths, do not use single-model addresses such as VLLM/Ollama/Xinference) or non-empty `AIPROXY_API_TOKEN` (AI Proxy administrator token, must match the AI Proxy server configuration; do not use application API keys, model vendor keys, or other credentials) are not configured on the App/Admin server. Do not use workflow global variables, application API request headers, or the general model management page to set these variables instead of server-side deployment configurations.
- Symptom: Bulk asset data import tasks are interrupted. Cause: `DB_MAX_LINK` value is not adjusted, leading to insufficient concurrent connections to handle bulk data import requests.

## How to Verify Successful Configuration
- Start the FastGPT service, check that the console logs do not show error prompts for missing required environment variables.
- Submit an asset ledger query request, verify that the returned data includes core fields such as asset ID, owner, and storage location.
- Generate a download link for a single asset file, test access in a browser to confirm the corresponding file can be retrieved normally.
- Execute a bulk asset data import task, confirm the task does not terminate early due to connection exhaustion or configuration errors.
