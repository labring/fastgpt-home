# Online Troubleshooting and Post-Mortem for IT Procurement and Supplier Management: Deployment and Upgrade

## What the data for this category looks like
Data sources for this category typically include internal enterprise procurement systems, supplier quotation documents, budget sheets, and contract systems. Daily generated documents include procurement request forms, comparison records, formal contracts, and acceptance documents. Data updates follow the rhythm of each procurement order or monthly cycles. Data fields typically include procurement requirement details, supplier qualifications, quotation amounts, contract terms, and acceptance results. No unified mandatory format exists, and the format adjusts with the enterprise’s internal procurement workflow. Data volume fluctuates with the number of orders.

## What constraints these characteristics impose on deployment and upgrade
Data for this category mostly comes from internal heterogeneous systems, and no unified document format standard exists. During deployment, configure multiple source data access adaptation items to prevent data synchronization failures caused by format incompatibility. Data updates follow single order or monthly cycles, leading to significant traffic fluctuations. Reserve sufficient resource buffers during deployment, and configure reasonable database connection parameters to handle peak requests. Procurement-related data is subject to internal compliance requirements. During the upgrade phase, ensure configurations do not disrupt original data storage and access permissions, to avoid affecting normal operation of existing procurement processes.

## How to set configurations
This document is written based on FastGPT v4.17.0, and all following configuration items are adapted to the deployment logic of this version.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `20–50 connections` | The data update frequency for this category is per order or monthly, with peak requests concentrated during the procurement approval phase. This value balances resource usage and connection response speed |
| `MONGODB_URI` | Points to a dedicated database instance for the enterprise’s internal procurement contract system | Core data for this category includes contracts, acceptance documents, etc. Storing this data on a dedicated MongoDB instance ensures data isolation and access security |
| `REDIS_URL` | Configured as an internal network dedicated cache node | Used to cache temporary verification data for procurement requests and comparison records. Internal deployment reduces external access risks |
| `STORAGE_S3_ENDPOINT` | Internal network address of the enterprise’s internal object storage service | Used to store original procurement documents. Internal access improves upload and download speeds and ensures data security |
| `FE_DOMAIN` | Secondary domain name of the enterprise’s internal procurement system | Adapted to internal access scenarios, avoiding cross-domain or access permission issues caused by external domain names |
| `FILE_TOKEN_KEY` | `32-character random string` | Used to generate access tokens for procurement documents, ensuring unauthorized users cannot directly access sensitive procurement files |

## Three common errors
- Symptom: Docker deployment fails to start, with a database connection timeout prompt. Cause: `MONGODB_URI` is not configured to the database address corresponding to the enterprise’s internal procurement system, and a public test database address is used by mistake.
- Symptom: After internal network deployment, external access cannot load procurement document previews. Cause: `STORAGE_S3_ENDPOINT` is configured as an external network address, and the internal network cannot access external storage nodes.
- Symptom: Runtime logs show database connection count exceeds the limit. Cause: The value of `DB_MAX_LINK` is too low, failing to adapt to concurrent connection requests during procurement approval peak periods.

## How to confirm configurations are correct
- Run the database connection test script to verify connectivity for configurations including `MONGODB_URI` and `REDIS_URL`, and adjust parameter values based on test results.
- Upload a test procurement request form document to verify whether the storage and reading functions of `STORAGE_S3_ENDPOINT` operate normally.
- Access the frontend page corresponding to `FE_DOMAIN` to confirm that internal users can log in normally and access procurement-related knowledge base content.
- Check runtime logs to confirm no connection count limit exceeded or storage access failure errors are triggered, and adjust corresponding configuration items based on exception information in the logs.
