# Online Troubleshooting and Retrospective for Cloud Resource Compliance Auditing: Scheduled Tasks and Automation

## What the data for this category looks like
This category's data primarily originates from cloud audit logs, IAM permission systems, CMDB resource inventory libraries, and security baseline scanning tools. Daily produced documents include compliance checklists, permission audit reports, resource inventories, and rectification tracking forms. Data update frequency is monthly or quarterly. Fields cover resource unique identifiers, permission configuration items, compliance check status, rectification progress, and more. Only native system fields and standard document formats are retained, with no additional custom statistical units.

## What constraints do these characteristics impose on the scheduled tasks and automation workflow
Data in this category is scattered across multiple sources, has a long update cycle but large single-processing volume, and has a relatively high degree of document format standardization. Therefore, scheduled tasks must support parallel pulling of multiple data sources to avoid single-source blocking slowing the overall process. Since the update frequency is monthly or quarterly, high-frequency scheduling is unnecessary. A single task must process full compliance data, so reasonable timeout thresholds and retry strategies must be configured. At the same time, the automated workflow must adapt to parsing and field verification of standardized documents such as compliance checklists and rectification tracking forms. This ensures the accuracy of data extraction, prevents abnormal audit results caused by format deviations, and triggers clear alerts after task failure for timely intervention.

## How to set configurations
The following configurations apply to the scheduled tasks and automation module of FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Task Trigger Cycle | Monthly or quarterly | Matches the monthly/quarterly update frequency of data in this category, avoids invalid scheduling |
| Maximum Single Task Execution Duration | 1800 seconds | Adapts to the processing time required for full compliance data, prevents task interruptions caused by timeouts |
| Parallel Data Source Pull Count | First 3 | Balances system resource usage and data pulling efficiency, avoids cloud API rate limiting risks |
| Failed Retry Count | 3 times | Addresses temporary network fluctuations or cloud API rate limiting, reduces task failure probability |
| Document Format Validation Switch | Enabled | Ensures accurate field extraction from compliance checklists and rectification tracking forms, filters invalid data |
| Task Failure Alert | Push immediately upon trigger | Notifies the compliance team in a timely manner, avoids delays in the audit cycle |

## Three common misconfigurations
- Symptom: The scheduled task automatically interrupts after running for more than 180 seconds, failing to complete the full compliance data audit process. Cause: The maximum single task execution duration configuration was not adjusted, and the default threshold was retained, which cannot cover the processing time required for full data.
- Symptom: A large number of empty fields appear in the automated compliance audit report, resulting in invalid audit results. Cause: The document format validation switch was not enabled, and format-abnormal compliance checklists and rectification tracking forms were not filtered, leading to invalid data being included in the audit.
- Symptom: Permission data for some cloud resources is not synchronized to the audit process, resulting in missed compliance checks. Cause: The parallel data source pull count was set too high, triggering cloud API rate limiting, and no retry mechanism was configured, leading to failed pulls for some data sources.

## How to confirm the configuration is correct
- Trigger a scheduled task manually, and verify that the task execution duration matches the configured maximum single task execution threshold.
- Extract a compliance checklist and rectification tracking form, and verify that the fields extracted by the automated workflow match the original document content.
- Simulate temporary network fluctuations or cloud API rate limiting scenarios, and confirm that the task can complete execution normally after the retry mechanism is triggered.
- Check the alert configuration, and confirm that a corresponding notification is pushed to the specified receiving channel when the task fails.
