# Online Troubleshooting and Retrospective for Cloud Resource Compliance Auditing: Deployment and Upgrade

## What the Data for This Category Looks Like
The data for this category comes from cloud audit logs, IAM permission systems, CMDB resource inventories, and security baseline scan results. Daily produced documents include compliance checklists, permission audit reports, resource inventory lists, and rectification tracking forms. The data update cycle is monthly or quarterly. Data fields include resource ID, permission configuration items, compliance status, rectification progress, and similar items, with no additional statistical percentage fields. Core processing steps focus on resource inventory, abnormal permission identification, and rectification evidence verification, requiring complete retention of operation and verification traces.

## Constraints on Deployment and Upgrade
Scattered data sources and long update cycles require persistent connections for multi-source data synchronization during deployment, to avoid missing audit data due to data source interruptions. Daily document structures are fixed, so original field mapping rules must be retained during upgrades; otherwise, historical audit report formats will be corrupted. The resource inventory process takes a long time, so database connection pool parameters must be adjusted during deployment to adapt to batch data processing. Strict rectification evidence retention requirements mandate configuring compliant storage paths to ensure data cannot be tampered with. Additionally, compatibility must be maintained with IAM and CMDB interfaces of different cloud service providers, to avoid increased deployment adaptation costs when cloud service providers change.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `10–15 connections` | Adapt to concurrent connection requirements for batch resource inventory and permission scans, avoid connection pool exhaustion |
| `MONGODB_URI` | Point to a dedicated replica set address for compliance auditing data | Isolate business data and audit data to prevent accidental modification of compliance data |
| `REDIS_URL` | Configure an independent cache instance, set an expiration time of `3600 seconds` | Cache frequently accessed compliance baseline rules and resource snapshots to reduce inventory time |
| `STORAGE_S3_ENDPOINT` | Select an object storage endpoint that meets compliance requirements | Retain rectification evidence and audit logs to ensure stored data is traceable |
| `FILE_TOKEN_KEY` | Set the key length based on actual testing | Generate access tokens for compliance reports to prevent unauthorized access to sensitive audit documents |
| `ROOT_KEY` | Only configure for dedicated administrators of the compliance team | Restrict modification permissions for core configurations to meet internal audit permission control requirements |

## Three Common Mistakes
- Symptom: After upgrading the version, the resource list field in the compliance audit report is empty, and the backend logs show database connection timeout. Cause: The original `DB_MAX_LINK` configuration was not retained during the upgrade, causing the connection pool to be exhausted during batch data synchronization.
- Symptom: A 403 status code is returned when calling the compliance audit interface, and permission audit reports cannot be obtained. Cause: The `ROOT_KEY` permission was not configured correctly, causing ordinary users to be unable to access core audit data.
- Symptom: Rectification evidence cannot be displayed in the compliance report after being uploaded. Cause: The storage endpoint configured in `STORAGE_S3_ENDPOINT` has insufficient permissions to read the uploaded evidence files.

## How to Confirm the Configuration Is Correct
- Run a batch resource inventory task, check whether the active connection count of the database connection pool falls within the range configured for `DB_MAX_LINK`, and confirm that the connection pool is not exhausted.
- Access the download link of the compliance audit report, verify that the token generated by `FILE_TOKEN_KEY` can be accessed normally, and unauthorized users cannot obtain the report.
- Upload a rectification evidence file, confirm that the file can be displayed normally in the rectification tracking form and associated with the corresponding compliance item.
- Restart the service, check whether the multi-source data synchronization task starts normally, and there are no data source connection error logs.

The values provided are common starting points and should be evaluated against sample data from the specific deployment environment.
