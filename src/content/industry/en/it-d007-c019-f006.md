# Online Troubleshooting and Retrospective for Crowdsourced Annotator Management: Scheduled Tasks and Automation

## What data for this category looks like
Data for this category primarily originates from crowdsourcing platform backends, annotation quality spot-check records, personnel training exam results, and financial settlement systems. Daily maintained documents include personnel access rules, on-the-job training materials, monthly performance sheets, and quarterly settlement statements. Data update frequencies are primarily daily and monthly. Core fields include unique personnel identifiers, access review status, training assessment scores, daily annotation pass rates, and monthly settlement amounts. No additional custom statistical metrics are used.

## What constraints these characteristics impose on scheduled tasks and automation
Data sources for this category are scattered, requiring integration with multiple interface types including crowdsourcing platforms, quality inspection systems, and financial systems. Scheduled tasks must adapt to the timing requirements of multi-source data pulling. Data update frequencies are primarily daily and monthly, so corresponding tasks must be configured with daily and monthly triggering scheduling rules respectively. Core documents such as access rules and settlement statements must be refreshed synchronously with data updates to prevent expired configurations from being used during task execution. Task failures will directly cause quality fluctuations or settlement errors, so failure alerts and retry mechanisms must be configured to ensure execution stability.

## How to configure settings
These configurations are based on the FastGPT v4.17.0 user interface settings:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Task Trigger Cycle | Daily tasks set to `2:00-4:00 daily`, monthly tasks set to `0:00 on the 1st of each month` | Matches daily and monthly data update rhythms, avoids peak business hours |
| Multi-source Data Pull Timeout | `300 seconds` | Adapts to average cross-system interface response times, prevents single-task timeout interruptions |
| Failure Retry Count | `2 times` | Balances task execution success rate and system resource consumption, avoids duplicate data caused by repeated triggers |
| Task Log Retention Period | `30 days` | Meets log tracing requirements for troubleshooting, while controlling storage resource usage |
| Task Trigger Condition | Trigger based on data update time | Prevents empty runs caused by fixed-cycle triggering, only executes tasks when new data is available |

## Three common misconfigurations
- Symptom: A form input node nested within another workflow still displays a dialog box during execution. Cause: The context isolation parameter for nested workflows is not configured, causing the parent workflow's dialog rendering rules to override the child node's settings.
- Symptom: The default index of a manually inserted general knowledge base automatically disappears after several hours. Cause: The scheduled index synchronization task does not have a retention rule configured for manually inserted data, triggering the automatic cleanup logic.
- Symptom: The root user password modified after upgrading the version automatically reverts to the initial value the next day. Cause: The built-in system initialization scheduled task is not disabled, resetting configuration parameters daily.

## How to confirm the configuration is complete
- Access the FastGPT task management panel, verify that the scheduled task's trigger cycle, retry count, and other configuration items match the set values.
- Manually trigger a test task, check that there are no timeout exceptions in the cross-system data pulling logs.
- Verify task execution results, confirm that tasks only trigger when new data is available, with no empty runs.
- View retained task logs, confirm that retries are performed according to the configured number of attempts when execution fails.

The values provided are common starting points and should be measured against the reader's own samples.
