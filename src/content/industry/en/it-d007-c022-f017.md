# Online Troubleshooting and Retrospective for Independent Innovation Replacement Adaptation: Deployment and Upgrade

## What data for this category looks like
Relevant data for independent innovation replacement adaptation usually comes from existing system inventories, domestic software and hardware directories, test environments, and publicly available manufacturer materials. Daily produced documents include adaptation lists, compatibility test reports, migration plans, and issue ledgers. Fields generally cover software and hardware models, compatibility status, test results, migration steps, etc. There are no uniform mandatory units, and labeling must be done according to the actual situation of the project. The data update frequency is usually once per project or per quarter. It must be updated in a timely manner along with the version iteration of domestic software and hardware and adjustments to business systems to ensure that adaptation configurations match the current environment.

## What constraints these characteristics impose on the deployment and upgrade link
Since data sources are scattered and update rhythms are inconsistent, the latest domestic software and hardware adaptation list corresponding to the current project must be pulled before deployment to ensure that configuration items match the current compatible versions, and avoid using non-adapted general configurations. Daily produced documents are subdivided and numerous. The deployment and upgrade link must one by one check the parameter requirements in the adaptation list, compatibility test report, and migration plan, and must not mix configuration templates from different projects. Independent innovation replacement adaptation focuses on software and hardware stack replacement and compatibility verification. The deployment and upgrade link must additionally adapt to the connection formats and permission rules of domestic basic software and hardware. At the same time, pre-tests must be completed in advance to avoid risks such as business system unavailability, migration delays, and procurement waste.

## How to set the configuration
The configuration items in this section apply to the independent innovation deployment scenario of FastGPT v4.17.0.

| Configuration Item | Recommended Value | Basis for This Value |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–200` | Adapt to the connection pool limit of domestic databases to avoid connection exhaustion caused by excessive concurrency |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.100:9000` (fill in according to the actual domestic object storage address) | Need to connect to domestic object storage services in an independent innovation environment, and use the legal access address provided by the manufacturer |
| `REDIS_URL` | `redis://:custom password@host address:6379/0` | Adapt to the standard connection format of domestic cache middleware to ensure normal calling of cache services |
| `FE_DOMAIN` | `https://fastgit.project-domain.com` | Ensure domain name consistency for front-end callbacks and interface calls, avoid cross-domain or token verification failures |
| `FILE_TOKEN_KEY` | `Random key with a length of no less than 32 characters` | Ensure the security of the file upload interface and avoid token conflicts across projects |

## Three common mistakes
- Symptom: When uploading files in an execution workflow after upgrading the version, `Failed to create post presigned url` is returned. The cause is that `STORAGE_S3_ENDPOINT` is not correctly configured to point to the domestic object storage service, or the object storage write permission for the corresponding key is not granted.
- Symptom: Unable to pull ARM architecture runtime images during deployment. The cause is that the image tag corresponding to the architecture is not specified, or the domestic image acceleration source is not configured to adapt to the network requirements of the independent innovation environment.
- Symptom: Compatibility test fails after pure source code deployment. The cause is that the software and hardware versions in the adaptation list are not sorted out in advance, and default dependency packages are directly used, resulting in incompatibility with domestic basic software.

## How to confirm that the configuration is correct
- Log in to the storage configuration page of the management backend, check whether the address configured for `STORAGE_S3_ENDPOINT` can be accessed normally, and there is no connection timeout prompt.
- Execute a database connection test to verify that the connection pool parameter configured by `DB_MAX_LINK` meets the concurrency estimation requirements of the current business.
- Upload a small test file to check whether the file upload link in the workflow can normally generate a pre-signed URL without error prompts.
- Check the system operation logs to confirm that there are no alarm messages about missing configuration items, format errors, or insufficient permissions.
