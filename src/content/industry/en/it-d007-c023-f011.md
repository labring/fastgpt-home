# Online Troubleshooting and Retrospective for IT Budget and Project Portfolio Management: Database and Operations
This document applies to FastGPT v4.17.0

## Data Profile for This Category
Data for this category comes primarily from financial systems, project management systems, contract ledgers, and business department requirements. Regular output documents include annual budget sheets, project initiation documents, project portfolio dashboards, and investment retrospective reports. Fields include budget amount, project cycle, priority identifier, expected revenue, and responsible department. Data updates run on monthly, quarterly, or annual cycles. Data formats vary across sources, so unified mapping to a standardized storage structure is required.

## Constraints for Database and Operations Workflows
Multi-source heterogeneous data input requires the database to support cross-system data synchronization and format conversion, to avoid import failures caused by incompatible data formats. Low-frequency but bulk update rhythms require database connection pool configurations to balance resource utilization and concurrent processing capabilities, preventing connection exhaustion during bulk writes. Standardized document output requires the database storage structure to match the field rules of project portfolio dashboards and investment retrospective reports, while supporting flexible field expansion for new business needs. Data errors directly lead to risks such as budget mismatches and duplicate project construction, so the database must include complete backup and rollback mechanisms to ensure data consistency.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://[username]:[password]@[host]:[port]/fastgpt?authSource=admin` | Adapts to unstructured and semi-structured data storage needs for multi-system data synchronization in this category |
| `PG_URL` | `postgresql://user:pass@[host]:5432/fastgpt` | Stores structured business data such as project initiation documents and budget sheets |
| `DB_MAX_LINK` | `20–30 connections` | This category’s data updates follow monthly or quarterly cycles. Limit connection count during bulk writes to avoid exhausting database resources |
| `REDIS_URL` | `redis://[password]@[host]:6379/0` | Caches temporary calculation results for budget priority sorting and project revenue retrospectives to improve query efficiency |
| Database bulk query switch | Enabled | Supports multi-line query statements, adapting to bulk budget verification and data checking scenarios for this category |

## Three Common Configuration Mistakes
1. Symptom: Error during MySQL multi-line query execution, with a syntax error prompt returned. Cause: The database bulk query configuration is not enabled, or the plugin has not been granted multi-line execution permission.
2. Symptom: Knowledge base and intelligent agent data missing after restoring a backed-up project file. Cause: The backup only exported the project configuration file, and did not synchronize knowledge base vector and session data stored in the database.
3. Symptom: Database connection timeout, with a `504` status code returned. Cause: `DB_MAX_LINK` and connection timeout thresholds were not adjusted based on the category’s data update frequency, leading to backlogged bulk requests that cannot be processed in a timely manner.

## How to Verify Configuration Success
- Log in to the database management tool, use the connection addresses for `MONGODB_URI` and `PG_URL` to confirm normal read and write access to business data.
- Run a bulk budget data import script, check for connection exhaustion errors in the connection pool, and confirm the `DB_MAX_LINK` configuration takes effect.
- Trigger a budget priority sorting calculation, inspect the cache instance corresponding to `REDIS_URL`, and confirm temporary calculation results can be stored and read normally.
- Perform a backup and restore test, import the backed-up project configuration file, and confirm knowledge base and intelligent agent data in the database can be loaded correctly.
