# Online Troubleshooting and Retrospective for Informatization Budget and Project Portfolio Management: Deployment and Upgrade

## What data for this category looks like
Data for this category primarily comes from financial systems, project management systems, contract ledgers, and business department requirements. Daily produced documents include annual budget sheets, project proposal documents, project portfolio dashboards, and investment retrospective reports. Data update cycles follow monthly, quarterly, or annual schedules. Core fields include budget amount, project cycle, priority ranking, expected revenue, and more. Units are mostly CNY, natural days, numeric units, etc. Formatting varies based on business department needs, requiring adaptation for multi-source data integration.

## What constraints these characteristics impose on the deployment and upgrade phase
Multi-source and heterogeneous data sources require adaptive cross-system data synchronization parameters during deployment. This avoids data format conflicts between different systems.
Monthly, quarterly, or annual update cycles require upgrade windows to be scheduled outside business data settlement periods. This prevents interruption of data synchronization processes.
Differing structures across multiple document types require preconfigured parsing rules for each template during deployment. This ensures accurate extraction of core fields such as budget amounts and project cycles.
Non-standardized field formats require compatibility configurations for legacy data imports to be retained during upgrades. This prevents historical business data from failing to load normally.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–50` | Adapts to concurrent requirements for multi-source data synchronization, prevents connection pool exhaustion from impacting task execution |
| `MONGODB_URI` | Fill in the database connection address of the enterprise project management system, enable SSL encryption | Ensures transmission security for sensitive data such as project proposal documents and investment retrospective reports |
| `REDIS_URL` | Configure as a dedicated cache instance, set an expiration time of `3600 seconds` | Caches real-time data for the project portfolio dashboard, adapts to the monthly update business rhythm |
| `FE_DOMAIN` | Fill in the secondary domain name for internal enterprise access | Adapts to access rules of internal business systems, prevents cross-origin verification failures |
| `STORAGE_S3_ENDPOINT` | Point to the access address of the enterprise self-built object storage | Stores large-volume documents such as annual budget sheets, adapts to large-scale data storage requirements |
| `FILE_TOKEN_KEY` | Generate a random 32-character string | Ensures access permissions for uploaded document files, prevents unauthorized access |

## Three common mistakes
- Accessing the internally deployed project portfolio dashboard page results in a `403 Forbidden` error. The cause is incorrect configuration of the `FE_DOMAIN` parameter, leading to mismatched cross-origin verification rules.
- Historical budget data fails to load after an upgrade. The cause is failure to retain compatible configurations for the legacy `PG_URL` parameter, resulting in inability to read historical project ledgers after the database connection string is changed.
- Runtime logs cannot be viewed after service startup. The cause is failure to configure administrator permissions corresponding to `ROOT_KEY`, or failure to specify the correct log storage path, preventing normal generation of log files.

## How to confirm the configuration is correct
- Run the `curl internal deployment domain/health` command, check that the returned status code is `200 OK` to confirm that the basic service has started normally.
- Import a standard-format annual budget sheet document, check whether core fields are correctly parsed and synchronized to the system to confirm that the data extraction configuration is effective.
- View the cache instance corresponding to `REDIS_URL`, confirm that cached data for the project portfolio dashboard exists to confirm that the cache configuration is operating normally.
- Log in to the administrator backend, check that the version number displays `FastGPT v4.17.0` to confirm that the upgraded version matches the deployment package.
