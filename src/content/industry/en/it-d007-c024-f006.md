# Online Troubleshooting and Retrospective for In-Feed Ad Creative Testing: Scheduled Tasks and Automation

## What the data for this category looks like
Data related to in-feed ad creative testing typically comes from ad delivery platforms, internal material libraries, user interaction data, and conversion data. Updates follow daily or weekly cycles. Daily produced documents include creative scripts, material test sheets, delivery data reports, and iteration checklists. Fields cover creative variable combinations, material fatigue markers, click-through rates, conversion costs, and more. Material IDs and delivery plan IDs are required to match data across different documents.

## What constraints these characteristics impose on scheduled tasks and automation
Dispersed data sources that require cross-document matching mean scheduled tasks must pull data from multiple sources and complete field matching. The daily or weekly update cycle requires scheduled task trigger frequencies to align with data update rhythms, to avoid repeated pulls or missed cycle data. Errors in creative testing directly impact delivery effectiveness, so automated workflows must set clear exception trigger conditions and alert rules. They must also accommodate the batch processing time required for material libraries and delivery data.

## How to configure settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Scheduled Trigger Cycle | 1 day / 7 days | Aligns with the daily/weekly update rhythm of delivery data and material updates |
| Data Source Pull Scope | Ad platform data from the past 7 days | Covers valid sample sizes for complete test cycles |
| Failure Retry Count | 3 times | Avoids task interruptions caused by single network fluctuations or temporary interface errors |
| Exception Alert Threshold | 10% drop in click-through rate (calibrated via actual testing) | Identifies delivery anomalies caused by creative fatigue or material policy violations in a timely manner |
| Task Execution Timeout | 1800 seconds | Accommodates total time for pulling multiple data sources and AI creative recognition |

## Three common configuration errors
- Tasks do not auto-trigger and can only be started manually. This occurs because the scheduled task trigger for FastGPT v4.17.0 is not configured, and the workflow relies on manual triggering.
- Image recognition results are not synced to material test sheets. This occurs because the trigger rule for automatically uploading materials to the knowledge base is not configured, and only manual upload of local files is supported.
- Test sheet fields are empty after task execution. This occurs because the association rule for material IDs and delivery plan IDs is not configured, so pulled data cannot match existing test checklists.

## How to confirm configurations are correct
- View the task management panel in FastGPT v4.17.0, confirm the target scheduled task status is enabled.
- Manually trigger a test task, check if it automatically pulls ad platform data and material library files from the specified cycle.
- Simulate a temporary network outage scenario, check if preset failure retries and alert notifications are triggered.
- Cross-check the generated iteration checklist, confirm automatically summarized test conclusions and creative variable fields are complete.

The values listed here are common starting points, and should be evaluated against local test samples.
