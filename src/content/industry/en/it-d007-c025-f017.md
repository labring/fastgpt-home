# Online Fault Troubleshooting and Review for Duty Scheduling and Handover: Deployment and Upgrade

## What the data for this category looks like
Core data for this category comes from scheduling systems, fault tickets, monitoring alerts, and organizational contact lists. Daily maintenance documents include duty rosters, handover records, escalation contact lists, and daily duty reports. Data updates occur daily or weekly. Fields include duty date, duty personnel, contact information, unresolved fault items, escalation chain priority, and other relevant fields. Document structures primarily use structured tables and plain text records. Support is provided for synchronization and storage of multiple data types.

## What constraints these characteristics impose on the deployment and upgrade phase
Deployments must support configuration items for connecting to multiple external systems to meet multiple data synchronization needs. Scheduled synchronization task parameters must be configured to match daily or weekly update frequencies and avoid data lag. Storage configurations must support both unstructured and structured data to accommodate multiple document types. Permission controls and conflict verification logic must be configured to prevent unauthorized modifications and missed information for high-risk scenarios such as scheduling conflicts and missed handovers. Caching mechanisms must be configured to reduce core data query latency and ensure escalation chain reliability.

## How to set the configurations
These configurations apply to FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 10–20 connections | Adapts to daily or weekly updated scheduling and ticket data volumes, avoids exhausting database connections |
| `MONGODB_URI` | Fill in the cluster connection string according to the deployment environment | Stores multiple document types including duty rosters and handover records, requires support for read and write permission configuration |
| `REDIS_URL` | Local Redis instance or managed service connection string | Caches duty personnel contact information and escalation chain information, reduces database query frequency |
| `FE_DOMAIN` | Fixed public network access domain name | Used to generate sharing links for duty reminders and handover records, ensures link stability after restart |
| `ROOT_KEY` | Randomly generated 32-character string | Configures exclusive administrator permissions to prevent unauthorized personnel from modifying scheduling and handover configurations |

## Three common configuration mistakes
- Duty handover records cannot be stored properly. This occurs when read and write permissions for `MONGODB_URI` are not configured correctly, resulting in failure to write documents to the database.
- After restarting deployment nodes, sharing links for duty records cannot be accessed. This happens when `FE_DOMAIN` is not fixed to a public domain name, using temporary container addresses causes links to fail after restart.
- Scheduling conflicts do not trigger automatic alerts. This takes place when `REDIS_URL` is not configured to cache escalation contact information, leading to repeated database reads for each verification, with response delays causing missed conflicts.

## How to confirm configurations are correctly applied
A database connection test is run to verify that the number of connections set in `DB_MAX_LINK` matches the configured range, with no connection timeout errors.
A standard duty roster template is manually imported, then checked to confirm `MONGODB_URI` can store the imported documents normally, with no storage failure prompts.
A sharing link for a duty record is generated, the deployment node is restarted, then the link is accessed to confirm the domain name configured in `FE_DOMAIN` has not changed, and the link opens normally.
A non-administrator account is used to attempt modifying scheduling configurations, then verification confirms the permission control from `ROOT_KEY` takes effect, and the modification operation cannot be completed.

The values provided are common starting points and should be measured against the reader's own samples.
