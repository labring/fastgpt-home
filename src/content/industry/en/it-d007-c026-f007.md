# Online Troubleshooting and Retrospective for Level Content Creation: Conversation Logs and Auditing

## Data Profile for This Category
The data for this category originates primarily from level editors, art resource libraries, player test datasets, and defect tracking systems. Daily associated documents include level design drafts, resource requirement sheets, test feedback forms, and version submission records. Common data fields include level ID, resource path, test feedback timestamp, defect severity, submission version number, and similar entries. Data updates occur weekly or per version release. A single update includes a large volume of resource and level configuration entries, which are continually added or adjusted across version iterations.

## Constraints Imposed on Conversation Logs and Auditing
Dispersed data sources linked to multiple types of business documents require conversation logs to associate with version submission records and defect tickets for the corresponding level to fully trace fault root causes. Weekly or per-version update frequency means logs must support bulk filtering by version number or time range to avoid loading excessive data in a single request. Fields include resource paths and level IDs, so log audits must allow quick location of associated art resources and level configurations via resource paths, while supporting fields from different test feedback form formats. Additionally, fault troubleshooting for level content creation often requires reviewing multiple rounds of test conversations retroactively. Logs must fully retain context interaction details without truncating key configuration conversations.

## Configuration Guidelines
The following configuration scheme is compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Conversation log export scope | Filter single-round sessions by `chatId` or bulk export by version number | Matches the level content creation need for troubleshooting by version, supports bulk tracing of multiple rounds of test conversations |
| Log detail display | Enable full display of the `detail` field | Fully retains resource paths and level configuration parameters in test conversations, avoids loss of critical information |
| Session association binding | Bind `responseChatItemId` to corresponding defect tickets | Quickly link conversation logs to fault records in the defect tracking system |
| Single retrieval limit | Return the first 100 records per single retrieval | Adapts to weekly or version-level data volume, avoids loading timeouts |
| Log retention period | Retain conversation logs from the last 30 days | Aligns with version iteration cycles, covers complete test cycles |
| Log export size limit | Do not exceed 1000 MB | Adapts to local storage and export transfer requirements |

## Three Common Misconfigurations
- Symptom: Unable to export full conversation records, or the number of retrieved results is far lower than the actual number of sessions. Cause: Export scope for bulk filtering by version number or `chatId` is not configured, and only default single-session retrieval is used.
- Symptom: Conversation logs do not display complete context interactions, only showing single-round Q&A content. Cause: Full display of the `detail` field is not enabled, and only basic session metadata is loaded, resulting in loss of critical conversation details related to resource paths and level configurations.
- Symptom: Timeout errors occur when retrieving conversation logs. Cause: No single retrieval limit is set, and full session data for weekly or version-level scopes is loaded, exceeding system processing thresholds.

## How to Verify Correct Configuration
- Run a log export filtered by version number, confirm the exported file includes all test conversation records for the target version.
- Open the details of a single session, confirm the `detail` field contains complete conversation content including resource paths and level configuration parameters.
- Check defect ticket association items, confirm conversation logs bound with `responseChatItemId` can directly jump to the corresponding session.
- Initiate a bulk retrieval request, confirm the system does not throw timeout errors and the number of returned records matches the preset single retrieval limit.

The values provided here are common starting points and should be evaluated against the user’s own samples.
