# Online Troubleshooting and Retrospective for Level Content Creation: Database and Operations

## Data Overview for This Category
Data for this category comes primarily from level editors, art resource libraries, player test data, and defect tracking systems. Daily deliverables include level design documents, resource requirement sheets, test feedback forms, and version submission records.
Level design documents include path node coordinates, resource mount IDs, and trigger condition parameters. Test feedback forms log level node numbers and issue types.
Data updates typically occur weekly or per version. Each update includes bulk submission of multiple related documents.

## Constraints for Database and Operations Workflows
The data characteristics of this category create multiple constraints for database and operations workflows.
Multi-source data access requires support for heterogeneous database connections. Separate storage is needed for semi-structured level configurations, transactional test records, and cached real-time preview data.
The weekly or per-version bulk update rhythm requires databases to support high-concurrency writes and version rollback. This prevents level locks or launch delays caused by failed updates.
Data fields include spatial coordinates and resource association IDs. This requires databases to support spatial indexing and associated queries to meet level content deployment needs.

## Configuration Guidelines
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://game_level:pass123@db-host:27017/fastgpt_level?authSource=admin` | Level data includes semi-structured coordinates and resource association information. MongoDB supports storage for non-fixed format data like this. |
| `PG_URL` | `postgresql://level_admin:pass456@db-host:5432/level_test?sslmode=require` | Test feedback forms and version submission records require transactional associated queries. PostgreSQL supports consistency validation for complex data sets. |
| `DB_MAX_LINK` | `20–30` | The typical number of concurrent online editors for a level production team is 5-10. Reserved redundant connections handle bulk version submission scenarios. |
| `REDIS_URL` | `redis://redis-pass@redis-host:6379/0` | Cache real-time preview data for the level editor to reduce high-frequency query pressure on the primary database. |

## Three Common Misconfiguration Issues
- Symptom: A syntax error is triggered when passing database connection parameters via variables. Manual SQL execution shows no errors. Cause: Special characters in level data such as commas in coordinates and slashes in resource paths are not escaped. Variables do not use correct escaping rules.
- Symptom: Database tool calls in FastGPT v4.17.0 workflows return connection timeouts. Cause: `DB_MAX_LINK` is set too low. Bulk level update requests submitted simultaneously exhaust the database connection pool. New requests cannot acquire available connections.
- Symptom: MongoDB connection validation fails, with a prompt that the specified database does not exist. Cause: The correct target database name is not configured in `MONGODB_URI`. The default connected database has no collections created for level-related data.

## How to Verify Correct Configuration
- Run a manual SQL query to confirm the database configured via `PG_URL` can read associated level design document data. Cross-check query results against actual documents.
- View the database connection pool monitoring dashboard. Confirm current active connections do not exceed the `DB_MAX_LINK` setting, with no connection exhaustion alerts.
- Submit a single bulk level resource update request. Confirm `MONGODB_URI` can correctly write new version records. Review logs to check write results.
- Open the real-time preview function of the level editor. Confirm cached data from `REDIS_URL` updates in a timely manner, and preview content matches the latest edited results.

The values provided are common starting points. They should be validated against local sample data and operational workloads.
