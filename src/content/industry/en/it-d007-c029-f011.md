# Online Troubleshooting and Retrospective for Content Copyright and Authorization Management: Database and Operations

## What the data for this category looks like
This category of data primarily comes from four sources: contract systems, copyright registration information, content libraries, and complaint inboxes. Daily generated documents include authorization contracts, copyright ledgers, removal notices, and infringement complaint materials. Authorization contracts contain fields such as authorization scope, authorization period, and authorized subject. Copyright ledgers are updated per individual entry. Infringement complaint materials are mostly in attachment form. The data update frequency is once per order or once per month, and the volume of data updated in a single instance fluctuates with the number of business orders. Core time-consuming steps involve authorization scope verification, expiration reminders, and organization of infringement materials. Data fields must cover key information such as rights source, authorization boundary, and processing status.

## What constraints these characteristics impose on the database and operations link
The data characteristics of this category directly restrict database and operations configurations. First, data sources are scattered and require cross-system synchronization, so fault-tolerant mechanisms for cross-source data synchronization must be configured to avoid loss of copyright data caused by single-system failures. Second, authorization scope verification is a high-frequency query scenario, so indexes must be created for the authorized subject and authorization period fields to reduce query latency. Third, infringement complaint materials are mostly large-volume attachments, so database components that support large field storage must be selected to avoid data truncation. Fourth, data errors can lead to serious consequences such as infringement compensation and content removal, so full backups and audit logs must be configured to ensure data traceability and recovery.

## How to Set Configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Exclusive replica set address pointing to the copyright contract and ledger collections | Isolate business data to avoid interference with other business databases, and ensure the read/write security of core copyright data |
| `PG_URL` | Read-only replica address for infringement complaint material metadata | Share high-frequency query pressure to ensure response speed for core operations such as authorization scope verification |
| `DB_MAX_LINK` | 100–150 | Adapt to the monthly update volume per order, avoid request rejection caused by connection pool exhaustion |
| `REDIS_URL` | Configure cache expiration time as 30 days | Cache high-frequency queried authorization scope data to reduce the number of direct database accesses |

## Three Common Misconfigurations
- Concurrency calls to the workflow return none, and the logs show database connection timeout. The cause is failure to adjust the `DB_MAX_LINK` configuration for high-frequency authorization scope queries, so the connection pool cannot allocate new connections in time to process requests.
- Unable to connect to the remote database during local debugging, returning a connection refused error. The cause is failure to correctly configure `MONGODB_URI` to point to the target service address, and using the local default database address by mistake, resulting in inability to access remote resources.
- The permission module returns no data, and the interface shows abnormal authorization relationships. The cause is failure to correctly configure database association relationships, and failing to map the table association relationships of authorized subjects, contracts, and complaint materials to the FastGPT permission module.

## How to Confirm Proper Configuration
- Run the high-frequency query script for authorization scope verification, check the database connection number monitoring, and confirm that the connection number does not exceed the `DB_MAX_LINK` configuration value.
- Submit a test authorization contract, check whether the data is synchronized to the collection specified by `MONGODB_URI`, and verify normal data writing.
- Trigger an infringement complaint material upload process, confirm that metadata is correctly written to the database corresponding to `PG_URL`, and that the attachment storage path is configured correctly.
- View the database relationship diagram in the FastGPT permission module, confirm that the association relationships of authorized subjects, contracts, and complaint materials are configured correctly, and verify normal permission logic.
- This verification process applies to FastGPT v4.17.0.
