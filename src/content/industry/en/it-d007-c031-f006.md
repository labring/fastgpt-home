# Online Troubleshooting and Retrospective for Creator Onboarding and Verification: Scheduled Tasks and Automation

## What Data for This Category Looks Like
This category's data primarily comes from creator backends, enterprise credit information query APIs, account historical behavior databases, and contract management systems. Daily processed documents include onboarding application forms, identity qualification scan copies, audit verification records, and cooperation agreement files. Data updates are mostly triggered by individual applications, with some batch verification tasks updated daily. Core fields include creator account ID, qualification verification status, audit node records, and agreement effective date. Data volume fluctuates with the complexity of application materials.

## Constraints Imposed on Scheduled Tasks and Automation
Since data sources include external APIs and non-standard materials uploaded by users, scheduled tasks must adapt to external API call rate limits and uncertainty in material parsing. Real-time verification for individual applications must avoid repeated triggers. Batch tasks must be scheduled daily and run outside business peak hours. Association verification between audit records and agreement files requires scheduled tasks to retain context association relationships, preventing missed associated items during single-item data verification. The manual intervention trigger condition for the qualification verification link must align with scheduled automatic verification nodes, to prevent repeated verification or missed detections.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Batch Task Scheduling Interval | 14400 seconds (4 hours) | Adapts to the daily update business rhythm of this category, avoids triggering rate limits by high-frequency calls to external credit APIs |
| Maximum Parallel Tasks per Job | First 20 applications | Balances system resource usage and batch verification efficiency, matches the reasonable processing volume of a single batch task |
| Timeout Retry Threshold | 3 retries | Addresses temporary fluctuations in external APIs, prevents a single failed API call from interrupting the entire task |
| Alarm Trigger Condition for Verification Failures | Single application verification failure rate ≥10% | Detects common anomalies in batch tasks promptly, enabling rapid troubleshooting |
| Task Log Retention Period | 30 days | Meets log query requirements for fault retrospective, aligns with the retention requirements for audit records in this category |

*Note: This configuration is based on FastGPT v4.17.0*

## Three Common Misconfigurations
- Phenomenon: After switching different verification workflow configurations, the scheduled task still retains the mandatory global variable verification rules of the old workflow, triggering parameter missing errors. Cause: The associated global variable template was not cleared or updated in the task configuration, resulting in residual old configurations.
- Phenomenon: The qualification verification scheduled task repeatedly triggers the same application form, causing duplicate verification nodes to appear in audit records. Cause: The trigger condition for task scheduling was not bound to the audit status of the application form, and applications that have completed verification were not filtered out.
- Phenomenon: After setting a specified audit result reply, the tool still automatically generates AI reply content. Cause: The automatic AI reply switch in the task was not turned off, resulting in simultaneous activation of the specified reply and automatic reply.

## How to Confirm Proper Configuration
- View the task scheduling log to confirm that batch tasks trigger at the preset 14400-second interval, with no abnormal repeated executions.
- Manually trigger the verification task for a single application, simulate a failed external API call scenario, and verify that the system automatically retries 3 times before triggering an alarm.
- Check the alarm configuration to confirm that a specified alarm notification channel is triggered when the single application verification failure rate reaches 10%.
- View the task log storage directory to confirm that verification records from the past 30 days can be queried and exported normally.

*The configuration values provided are common starting points and should be evaluated against your own specific samples.*
