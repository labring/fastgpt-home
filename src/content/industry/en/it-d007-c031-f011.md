# Online Troubleshooting and Retrospective for Creator Onboarding and Certification: Database and Operations

## Data Structure of This Category
The core data for this category includes four types of core documents: onboarding application forms, identity qualification materials, certification audit records, and cooperation agreements. Data sources cover account information submitted via the creator backend, enterprise credit information query interfaces, account historical behavior data, and cooperation files archived in the contract system. Data update follows full updates for single applications as the primary rhythm, with incremental data synchronized daily for daily audit scenarios. Single data entries include application unique identifier, creator account ID, qualification file storage path, audit node status, and associated cooperation agreement number. The main data types are text, binary files, and enumeration values. No unified business unit field exists.

## Constraints Imposed on Database and Operations
The data characteristics of this category impose multiple constraints on the database and operations link. Multi-source data access requires configuring connection pools compatible with different interface protocols to avoid performance loss from frequent connection creation and destruction. Single data entry size varies significantly; qualification files may contain large-capacity binary files, so reasonable storage sharding must be configured to balance read and write efficiency. Frequent audit status changes require creating a secondary index for the status field to speed up node query and filtering. Long-term data retention archiving requirements demand configuring a tiered storage strategy to distinguish hot data and cold archived data.

## Common Misconfigurations
Three common misconfigurations are as follows:
- Symptom: Database connection is refused, returning the `ECONNREFUSED` status code. Cause: The external request IP of the platform was not added to the database whitelist, causing external connections to be blocked.
- Symptom: Unable to query associated SQL database data via the built-in tool, returning empty results. Cause: SQL database connection parameters were not configured, and query permissions for the corresponding business database were not mapped.
- Symptom: During local development environment deployment, the database initialization step is skipped, and the process directly jumps to the Docker Compose deployment flow. Cause: Local database connection parameters were not configured in advance, and the deployment script automatically calls Docker Compose to pull containers instead of performing local initialization.

## How to Verify Successful Configuration
The following steps confirm proper configuration:
- The built-in database testing tool of FastGPT v4.17.0 verifies the connectivity of `MONGODB_URI` and `PG_URL`, confirming no permission or timeout errors occur.
- The Redis cache monitoring panel is checked to confirm the cache node configured via `REDIS_URL` normally receives and returns account historical data, and the cache hit rate meets expectations.
- A simulated onboarding application is initiated to trigger an audit status change query, confirming the database secondary index takes effect and the query time meets the preset threshold.
- A backup operation is triggered to verify that the export granularity can be split by onboarding application form dimension, matching the business data structure.

The values provided are common starting points and should be evaluated against sample data tailored to the specific deployment.
