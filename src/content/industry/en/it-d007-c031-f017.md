# Online Troubleshooting and Retrospective for Creator Onboarding and Verification: Deployment and Upgrade

## What the data for this category looks like
Data for the creator onboarding and verification process originates primarily from the creator backend, enterprise credit information systems, account history databases, and contract management systems. Daily processed documents include onboarding application forms, scanned identity qualification materials, verification audit records, cooperation agreements, and similar items. Data update frequency is daily or triggered by each individual application. Fields include identity identifiers, qualification numbers, audit statuses, contract terms, and similar items. There is no unified fixed statistical standard. Data flows only according to the application process.

## What constraints these characteristics impose on the deployment and upgrade phase
Starting with FastGPT v4.17.0, data for this category is dispersed across multiple sources and requires high real-time updates. Maintain stable connections between multiple systems. Therefore, configure reasonable database and cache connection parameters during deployment. The document structure includes unstructured qualification files and structured audit records, which impose clear requirements on storage service compatibility and read/write performance. Since errors directly affect the credibility of account access, strictly verify mandatory configuration items during deployment and upgrade. Prevent process interruptions caused by missing parameters. Additionally, separate AI Proxy-related configurations from model channel configurations. Prevent security risks caused by confusion of authentication information.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:27017/fastgpt?authSource=admin` | Stores structured business data such as creator qualifications and audit records. Requires correct configuration of authentication information and target database |
| `REDIS_URL` | `redis://:redispassword@host:6379/0` | Caches account risk judgment results and temporary session data. Ensures response speed in high-frequency application scenarios |
| `DB_MAX_LINK` | `50–100 connections` | Matches the concurrent processing scale of creator onboarding applications. Prevents service interruptions caused by exhausted connection pools |
| `STORAGE_S3_ENDPOINT` | Enter based on the actual storage service provider address, for example `https://oss-cn-beijing.aliyuncs.com` | Stores unstructured data such as creator-uploaded qualification files. Must match the access endpoint of the storage service |
| `FILE_TOKEN_KEY` | Random string of 32 or more characters | Authentication credential for signed file uploads. Prevents unauthorized users from accessing sensitive qualification materials |
| `ROOT_KEY` | Strongly random 64-bit string | Authentication key for highest-privilege operations in the management backend. Ensures security of configuration modifications |

## Three common configuration errors
- Symptom: The FastGPT service throws a validation failure error on startup, indicating missing `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN`. Cause: These two mandatory environment variables are not configured in the App/Admin backend. `AIPROXY_API_ENDPOINT` is the root address of the AI Proxy service. `AIPROXY_API_TOKEN` is the AI Proxy administrator token. Alternatively, the two values are incorrectly entered in the model management page, workflow global variables, or application API request headers instead of service deployment configurations.
- Symptom: A storage connection timeout error is returned when uploading creator qualification files. Cause: `STORAGE_S3_ENDPOINT` is configured incorrectly, or storage service access keys and permissions are not properly configured.
- Symptom: The server experiences read/write resource exhaustion, with service lag occurring during fixed daily periods. Cause: `DB_MAX_LINK` is set too small, and does not match the concurrent peak of creator onboarding applications. This leads to exhaustion of the database connection pool.

## How to confirm configurations are correct
- Initiate the FastGPT App/Admin service. Review startup logs to confirm no startup failure errors related to databases, storage services, or AI Proxy.
- Invoke test interfaces related to creator onboarding. Submit a simulated application to confirm normal completion of the file upload and qualification verification processes, and generation of audit records.
- Review monitoring metrics for Redis and MongoDB. Confirm that connection counts remain within the configured range, with no frequent disconnections and reconnections or connection overflow incidents.
- Access the management backend. Use the permissions linked to `ROOT_KEY` to execute configuration modification operations, and confirm the operations take effect normally.

The values provided are common starting points and should be measured against the reader's own samples.
