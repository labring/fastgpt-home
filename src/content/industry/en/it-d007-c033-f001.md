## How to set configurations
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Format as `Bearer {platform-issued secret}` | Complies with mainstream interface authentication specifications and adapts to authentication requirements for frontend cross-origin requests |
| Request timeout duration | 10–30 seconds | Adapts to the general threshold for browser request timeouts, avoiding prolonged page blocking |
| `responseData` parsing rules | Extract fields according to the path specified in the interface documentation | Ensures frontends can correctly obtain business data returned by interfaces |
| External system call retry count | First 2 attempts | Balances interface stability and frontend page loading speed |
| `variables` binding rules | Extract dynamic parameters from local storage or URL parameters | Adapts to dynamic request requirements across frontend scenarios |
| Cross-origin preflight request cache | 600 seconds | Reduces the frequency of repeated preflight requests initiated by browsers, optimizing page loading performance |

## Three common mistakes
- Symptom: Calls to external interfaces return 401 or 403 errors, and frontend pages cannot load business data. Cause: The format of the `Authorization` field is not configured correctly, or the secret has expired and not been updated, failing to meet interface authentication requirements.
- Symptom: Interface calls return empty data, and frontend pages display abnormally. Cause: The `responseData` field is not parsed according to the rules specified in the interface documentation, and outer wrapper fields are mistakenly extracted as business data.
- Symptom: The page initiates a large number of repeated preflight requests, slowing loading speed. Cause: The cache duration for cross-origin requests is not configured correctly, causing browsers to repeatedly initiate preflight requests.

## How to confirm configurations are correct
- Initiate a simulated request, and verify whether the returned `responseData` field matches the interface documentation.
- Check whether the format of the `Authorization` field meets interface requirements via the network panel in browser developer tools.
- Verify that cross-origin requests can be initiated normally, with no preflight request interception or timeout errors.
- Adjust dynamic `variables` parameters, and confirm that request parameters update correctly alongside page state.

The values listed above are common starting points, and should be evaluated against the reader's own samples.
