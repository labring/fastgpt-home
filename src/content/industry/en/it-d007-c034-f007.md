# Online Troubleshooting and Retrospective for Office System Process Configuration: Conversation Logs and Auditing

## What This Type of Data Looks Like
Normally, data related to office system process configuration comes from OA systems, organization directories, internal policy documents, and frontline user feedback. Daily maintained documents include process configuration sheets, approval node tables, form field descriptions, and change records. Data updates are triggered by process configuration changes, with no fixed cycle. All associated configuration items are fully updated after a single change. Data fields include unique process identifiers, approval node permission rules, form binding logic, change times, and operator information. There are no unified fixed units, and fields are adjusted based on specific business scenarios.

## What Constraints These Characteristics Impose on Conversation Logs and Auditing
Since data sources cover multiple systems and manual operations, conversation logs and auditing must associate cross-system configuration change records and user operation trails to ensure complete traceability of the entire link during troubleshooting. Data updates have no fixed cycle, so audit logs must synchronize the latest process configuration versions in real time to prevent mismatches between configuration and log versions. There are various types of daily documents, so audit logs must support multi-dimensional filtering by process configuration sheets, approval nodes, and other criteria to fit different troubleshooting scenarios. Errors directly impact business approvals, so logs must fully record the trigger conditions and execution results of each conversation step to help locate the root causes of issues such as stuck approvals and permission errors.

## How to Configure Settings
The following configurations are formulated for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Session Association Identifier | Bind `chatId` to the process configuration sheet ID | Matches the unique process identifier field of office system process configurations, ensuring logs are bound to the corresponding process |
| Module Output Logging | Enable the `detail` parameter | Captures console.log output from workflow code modules, covering detailed logs of process execution |
| Session Isolation Rule | Generate independent `chatId` based on user identity | Matches user identifiers from the organization directory, ensuring different users can only view their own sessions |
| Response Content Binding | Pass `responseChatItemId` | Associates user input with AI response content, avoiding cases where the Human field is empty |
| Log Storage Period | 7 days, adjustable based on actual testing | Balances storage costs and troubleshooting needs, adapting to the monthly change update frequency |
| Single Batch Export Limit | Top 100 entries | Adapts to the single query volume for daily troubleshooting, avoiding overly large exported data sets |
| Log Storage Cap | 1000 MB | Adapts to internal enterprise storage quotas, avoiding excessive resource consumption |

## Three Common Configuration Errors
- Symptom: Session records associated with approval processes are lost after clearing conversation logs. Cause: Failed to filter logs bound to process configuration sheet IDs using `chatId`, and accidentally deleted cross-process associated data.
- Symptom: console.log logs from workflow code modules do not appear in the audit panel. Cause: Failed to enable the `detail` parameter to record module runtime output, only retaining basic conversation content.
- Symptom: Multiple users cannot view their own historical conversations when using the application. Cause: No session isolation rule configured, and no unique session identifier generated by associating `chatId` with user identity.

## How to Confirm Configurations Are Correctly Applied
- Initiate a test conversation related to process configuration, check whether `chatId` in the logs is bound to the unique identifier of the current process configuration sheet.
- Run a workflow code module that includes console.log, check whether the corresponding output content appears in the audit panel to confirm the `detail` parameter is enabled.
- Switch between different test accounts to initiate conversations, confirm that each account can only view its own initiated session records to verify that the session isolation rule is effective.
- Call the FastGPT API to create a conversation, check whether the response content includes a complete Human field to confirm that `responseChatItemId` is passed correctly.
