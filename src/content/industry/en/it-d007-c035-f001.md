# Online Troubleshooting and Retrospective for Unit and Component Testing: HTTP Interfaces and External Systems

## What data for this category looks like
Data sources for this category include code repositories, test framework reports, requirement specifications, and interface definitions. Update frequency is daily or per commit. Daily output documents include test cases, coverage reports, Mock instructions, and defect tickets. Test cases contain interface paths, request methods, request headers, and response assertion fields. Coverage reports include code line and branch coverage statistics. Mock instructions mark simulation rules and return parameters for external interfaces.

## What constraints these characteristics impose on the HTTP Interfaces and External Systems workflow
Since data updates daily or per commit, HTTP interface configurations must adapt to rapidly iterating interface definition changes and support quick synchronization of the latest interface parameters. Documents such as test cases and Mock instructions are tied to actual code, so configurations must be linked to test scripts and Mock rules in code repositories to ensure test logic matches online interfaces. Coverage reports rely on real request data from interface calls, so correct authentication and request parameters must be configured to collect accurate coverage results. Defect tickets are associated with failed test cases, so complete request and response logs must be retained to enable subsequent retrospective problem localization.

## How to configure settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Extract authentication information including Basic Auth or Bearer tokens from test cases in the code repository | Match authentication configurations in test scripts, ensure requests pass external system authentication checks, and adapt to FastGPT v4.17.0 plugin invocation rules |
| `variables` | Configure mandatory parameters per interface definitions, with values determined via actual testing | Match interface parameter rules in requirement specifications, ensure request formats meet external system receiving requirements |
| `responseData` | Extract assertion fields from test cases, covering both normal and abnormal return formats | Ensure component tests can verify external system response content matches expectations, facilitating failed case localization |
| Mock timeout threshold | 10-30 seconds | Adapt to normal response durations of external systems, avoid test blocking due to short delays |
| External interface address | Test environment addresses extracted from interface definition documents | Remain consistent with interface paths in requirement specifications, ensure tests point to the correct external systems |

## Three common misconfigurations
- Phenomenon: External interface calls return 401 Unauthorized error. Cause: Correct `Authorization` parameter was not extracted from test cases, and default empty authentication information was used.
- Phenomenon: Response fields are empty after test case execution. Cause: Mandatory parameters in `variables` were not configured per interface definitions, resulting in external systems returning no valid data.
- Phenomenon: Unit test builds are blocked. Cause: Mock timeout threshold was set too short, and normal external system response delays exceeded the configured threshold, causing test failures.

## How to confirm configurations are correct
- Review interface call logs in test framework reports to confirm the `Authorization` parameter is correctly included in requests.
- Execute a single test case to verify that assertion fields in `responseData` match expected return content.
- Simulate a 15-second delay for the external system, check if tests complete normally, and confirm the timeout threshold fits actual scenarios.
- Compare interface definitions in the code repository with configured request parameters to ensure they match completely.

The values provided are common starting points and should be measured against the reader's own samples.
