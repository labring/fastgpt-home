# Online Troubleshooting and Retrospective for Change Management and Release Windows: Chat Logs and Auditing

## What data for this category looks like
This category of data originates from change management systems, CI pipelines, monitoring data, and business calendars. Update frequency is weekly or each time a change is executed. Daily associated documents include change requests, risk assessment reports, launch window plans, and rollback schemes. Data fields include change number, execution time, approval status, associated service ID, window time period, and rollback trigger conditions. All content covers the full workflow of production environment changes.

## What constraints these characteristics impose on the chat logs and auditing workflow
Decentralized data sources require log collection to interface with multiple systems, and unified identification of session data linked to changes is necessary. Update frequency is not fixed, so on-demand log synchronization must be supported instead of fixed-period pulling. There are many associated documents, so auditing requires linking chat records across the entire change chain, and retrieval by change number must be supported. Fields include approval status and rollback conditions, so auditing must verify that chat records for approval steps are complete, ensure that risk rating and approval coordination processes are traceable, and avoid audit gaps caused by missing approvals.

## How to configure settings
Configuration items under FastGPT v4.17.0 are as follows:

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind the change number from the change management system as a prefix | The change number is a unique identifier in change management scenarios, making it easy to quickly associate sessions with corresponding change events |
| `responseChatItemId` | Store the first and last IDs of the conversation chain | Enables quick backtracking of the complete conversation flow, covering all chain records from request to rollback |
| `detail` | Include all fields for approval records and rollback operations | Covers audit requirements for the most time-consuming steps such as risk rating and approval coordination |
| Log storage period | 180–365 days | Meets cycle requirements for compliance auditing and fault retrospective, calibrated based on actual testing |
| Retrieval return limit | Top 20 entries | In change management scenarios, associated sessions need to be located quickly; limiting return entries improves retrieval efficiency |
| Field filtering switch | Only collect conversation content related to changes | Reduces invalid log storage and lowers retrieval costs during auditing |

## Three common configuration mistakes
- Symptom: After running an interface call workflow, the running data in the chat logs is empty. Cause: The `detail` field for collecting workflow return content is not configured, resulting in missing key running information in audit logs.
- Symptom: Cannot associate the corresponding change number when searching for sessions. Cause: `chatId` is not bound to the change number from the change management system, so there is no associated identifier between sessions and change events.
- Symptom: The number of log search results exceeds expectations. Cause: No exact match rule for change numbers is set, resulting in irrelevant session logs being retrieved.

## How to confirm configuration is complete
- View the session details page, confirm that the `chatId` field contains the change number from the change management system.
- Export audit log samples, confirm that the `detail` field includes all associated content such as approval records and rollback operations.
- Initiate a simulated change process, search for sessions using the corresponding change number, confirm that the search results meet expectations.
- Check the log storage period configuration, confirm that it meets the cycle requirements for business compliance and retrospective.

The values provided are common starting points and should be measured against the reader's own samples.
