# Online Troubleshooting and Retrospective for Pre-Sales Technical Solutions: Conversation Logs and Auditing

## What the data for this category looks like
Data for this category comes primarily from customer interviews, bidding documents, vendor product materials, and historical project plans. Update frequency is per order or weekly. Daily deliverables include technical proposal documents, customer requirement survey forms, quotation lists, and demo scripts. Common data fields include proposal version number, requirement items, configuration parameters, quotation details, and demo script nodes. There is no unified mandatory format, and adjustments are made per order. Unlike bidding document preparation categories, the core work of this category revolves around early communication of technical routes and implementation boundaries. The relevance of data directly affects the accuracy and compliance of proposals.

## What constraints these characteristics impose on conversation logs and auditing
Data for this category is scattered and customized per order, with core focus on early communication of technical routes and implementation boundaries. This requires conversation logs to be bound to the corresponding project’s proposal identifier, to ensure logs are linked to technical proposals, requirement surveys, and other documents for that single project. Update frequency is per order or weekly, so the auditing workflow must retain logs according to the project cycle to avoid cross-project data confusion. Daily document formats are inconsistent, so logs must support fields linked to different document types, and be compatible with non-standard data formats from historical projects. Additionally, boundary design and quotation configuration for pre-sales proposals are the most time-consuming and error-prone steps. The auditing workflow must fully record the entire process of requirement clarification and proposal adjustment, to provide traceable evidence for subsequent troubleshooting and retrospective.

## How to configure settings
The following configurations are written for FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Conversation log retention period | 30–90 days | Matches the cycle length of most pre-sales projects |
| Log linked document fields | Use project proposal number and requirement survey form ID | Matches core identifier fields for documents in this category |
| Audit log trigger conditions | Proposal boundary adjustment, requirement clarification, quotation verification steps | Covers the most time-consuming and error-prone steps for this category |
| Log export format | JSON, PDF | Compatible with common document formats used for pre-sales proposals |
| Log retrieval scope | Filter by `chatId` | Quickly locate full-process conversation logs for a single project |
| `detail` field toggle | Enabled | Fully record detailed conversation content to meet auditing requirements |

## Three common configuration mistakes
- Symptom: Historical conversation records fail to load during workflow optimization, making it impossible to trace earlier requirement clarification content. Cause: The `chatId` parameter is not bound in the conversation configuration, so logs cannot be linked to the session identifier for the corresponding project.
- Symptom: After accidental deletion of conversation logs, it is impossible to retrospectively review the decision basis for proposal boundary adjustments. Cause: No audit log locking mechanism is configured, or the retention period is set shorter than the project cycle.
- Symptom: Downloaded conversation logs from knowledge base source documents do not include the `responseChatItemId` identifier, making it impossible to trace the original materials referenced by the proposal. Cause: Document linked field recording is not enabled in the conversation configuration, and the `responseChatItemId` parameter is not bound.

## How to confirm configurations are correctly set
- Access the conversation interface for a single project, check if the log list displays the proposal number identifier for that project.
- Trigger a conversation about proposal boundary adjustment, verify that the log fully records all content in the `detail` field.
- Attempt to delete a single log entry, confirm that a permission intercept prompt or deletion failure message is triggered.
- Search for sessions with a specified `chatId`, confirm that full-process conversation logs for the corresponding project can be quickly located.
