# Online Troubleshooting and Retrospective for Image Annotation Projects: Deployment and Upgrade

## What the Data for Image Annotation Projects Looks Like
Image annotation project data typically originates from image samples produced by annotation platforms, bounding box coordinate data, preset category dictionaries, and spot check results and rework lists generated during quality inspection.
Daily produced documents include annotation specification documents, bounding box reference sample files, official quality inspection reports, and rework follow-up lists.
Data updates occur daily or per annotation batch. Core fields include pixel-level target bounding box coordinates, category labels, annotator identifiers, and rework counts. Common units are pixels and times.

## What Constraints These Characteristics Impose on Deployment and Upgrade
Image annotation project data includes large-volume content such as pixel-level bounding boxes and image samples. Sufficient local or cloud storage capacity must be reserved during deployment to prevent service interruptions caused by data write overflow.
Data updates occur daily or per batch. A gray release strategy must be used during upgrades to ensure ongoing annotation batches are not affected.
Many core documents and data fields exist. Deployment configurations must support integration with multiple data sources. Additional network access rules must be configured in intranet environments to avoid data synchronization exceptions caused by failed interface calls.
Annotation tasks have high real-time interaction requirements. Database and cache service connections must be configured for low latency during deployment to avoid impacting annotator operations such as bounding box drawing and quality inspection.

## How to Set Configurations
This configuration is adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `200–300 connections` | Adapts to concurrent demands of multiple annotators submitting bounding box data and generating quality inspection reports |
| `REDIS_URL` | `redis://:custom password@intranet Redis address:6379/0` | Caches annotation task status and temporary bounding box data to ensure real-time interactive response latency does not exceed 500 milliseconds |
| `STORAGE_S3_ENDPOINT` | `Intranet object storage node address` | Connects to local storage services to store large-volume files such as image samples and bounding box results |
| `FE_DOMAIN` | `Intranet access domain name of the annotation project` | Configures the access root domain name for the frontend service to comply with intranet deployment access rules |
| `FILE_TOKEN_KEY` | `32-character random string` | Encrypts access tokens for annotation files to prevent unauthorized users from directly accessing annotation data |

## Three Common Misconfiguration Issues
1.  Symptom: An `ERROR: failed to solve: archive/tar: unknown file mod` error occurs when running the `docker build` command. Cause: No local image cache or proxy is configured in the intranet environment, which prevents correct recognition of file permission attributes during the packaging process and causes archive exceptions.
2.  Symptom: The page remains unresponsive for a long time after submitting an annotation task, and the interface returns a timeout status code. Cause: The `DB_MAX_LINK` parameter has not been adjusted to a value suitable for concurrent demands, causing the database connection pool to be exhausted and unable to process bounding box data submitted by multiple users simultaneously.
3.  Symptom: The annotation platform cannot connect to local storage after deployment using the official `docker-compose.yml` file. Cause: The `STORAGE_S3_ENDPOINT` parameter in the official configuration file has not been updated, and the default public storage configuration is retained, which cannot comply with intranet deployment storage rules.

## How to Verify Proper Configuration
1.  Run the `docker ps` command to confirm that all containers for the annotation project are running and there are no abnormal exit records.
2.  Access the configured `FE_DOMAIN` address, attempt to upload a test image and generate a bounding box sample, and verify that file storage and interface calls function normally.
3.  Check database connection logs to confirm that the `DB_MAX_LINK` parameter is in effect and the number of connections does not exceed the set upper limit.
4.  Trigger an update task for an annotation batch to verify that the data synchronization process to the quality inspection report is completed normally.

The values given are common starting points and should be measured against the reader's own samples.
