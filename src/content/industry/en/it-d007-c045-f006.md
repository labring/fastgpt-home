# Online Troubleshooting and Retrospective for Security Training and Phishing Drills: Scheduled Tasks and Automation

## What the data for this category looks like
The core data for this category comes from employee directories, email gateways, internal training platforms, and user click statistics systems. Four types of documents are routinely produced: training courseware, phishing email templates, drill plans, and retrospective reports. Data update frequency is typically quarterly or annual. Core fields include drill participant lists, email sending records, click behavior data, and retrospective scoring items. Data volume fluctuates with enterprise scale and drill frequency, with no fixed quantitative standard.

## What Constraints These Characteristics Impose on Scheduled Tasks and Automation
Data sources are scattered, and update frequency is typically quarterly or annual. Scheduled task trigger cycles must align with the full drill workflow rhythm, and should not be set too short.
Drill participant screening and result retrospective steps take significant time. Automated processes must reserve sufficient processing duration to avoid task interruptions.
Personalized configuration of phishing email templates must bind employee directory fields. Accurate field mapping must be ensured when calling these fields automatically, otherwise sending failures will occur.
Retrospective report generation requires associating multi-source data. Scheduled tasks must pull data in a fixed order to avoid splicing errors.
Additionally, tasks involving employee privacy must comply with security and compliance requirements. This ensures data processing legality.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Scheduled task trigger cycle | 15–60 minutes | Aligns with the pull and processing rhythm of drill data, avoids frequent interface calls that consume resources |
| Task execution timeout threshold | 300 seconds | Covers the average processing duration for participant screening and data splicing, prevents premature task termination |
| Data pull batch size | First 200 entries | Adapts to the single pull limit of employee directories, avoids interface overload |
| Field mapping verification switch | Enabled | Ensures no missing fields when phishing email templates call employee directory fields, reduces sending failure probability |
| Email sending concurrency | 10–20 concurrent | Matches the rate limiting rules of email gateways, avoids triggering sending restrictions |
| Retrospective report generation trigger time | 23:00 daily | Aggregates that day's click data by natural day, ensures timeliness of retrospective data, and is compatible with FastGPT v4.17.0 scheduled task scheduling logic |

## Three Common Misconfigurations
- Symptom: Scheduled task trigger interval is set to 3000MS. Frequent pulling of `webhook` messages causes interface rate limiting. Cause: The trigger cycle was set too short, failing to match the category data's update rhythm and exceeding system resource carrying capacity.
- Symptom: POST /api/admin/initv4818 404 error is returned when executing the upgrade script. Cause: The interface path of the upgrade script does not match the current FastGPT version's API path, and the initialization interface for the corresponding version was not utilized.
- Symptom: When a custom plugin is added, input and output parameters fail to appear in workflow tasks, and no error logs are generated. Cause: The custom plugin's parameter configuration was not correctly bound in the workflow node, or the plugin metadata failed to correctly declare input and output fields.

## How to Confirm Proper Configuration
- View scheduled task running logs to confirm that tasks trigger at the preset cycle, with no frequent startup or stagnation.
- Manually trigger a task once, check that the pulled employee directory fields match the placeholders in the template, with no null values or misalignment.
- Verify the email sending process, send a phishing email template to a test account to confirm that recipient information and email content are correct.
- Check the retrospective report generation results, confirm that associated click statistics data and training platform data have been correctly spliced.
