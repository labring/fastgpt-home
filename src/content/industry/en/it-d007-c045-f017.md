# Online Troubleshooting and Retrospective for Security Training and Phishing Drills: Deployment and Upgrade

## What the data for this category looks like
Daily documents for this category include training slides, drill plans, phishing email templates, and drill result reports. Data sources typically include employee contact lists, email gateways, training platforms, and click statistics. Update frequency is mostly quarterly or annual. The most time-consuming steps focus on drill audience filtering, email template design, and result retrospection. Errors here may lead to employee data leakage risks, audit gaps, or lack of evidence for rectification. Unlike security baseline check services, this category focuses on training and drills for personnel security awareness and behavior.

## What constraints these characteristics impose on the deployment and upgrade phase
Because data sources include internal enterprise systems such as employee contact lists and email gateways, deployments must adapt to different identity authentication and data synchronization rules to avoid permission leaks. Storage of drill result reports and templates must align with existing enterprise document management compliance requirements. Upgrades must maintain compatibility with historical data. Audience filtering and retrospection rely on precise field matching. Deployment phases must pre-configure corresponding data mapping rules to prevent subsequent drill data misalignment. The quarterly or annual update rhythm requires lightweight upgrade processes after deployment to reduce business downtime.

## How to configure settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Dedicated cluster connection string within a private network; configure access whitelists | Stores sensitive business data such as drill templates and reports, complies with sensitive data storage specifications for FastGPT v4.17.0 |
| `REDIS_URL` | Dedicated caching service with single-instance memory no less than 2048 MB | Caches temporary data for drill audience filtering and click statistics results, reduces database load |
| `FILE_TOKEN_KEY` | Randomly generated string of 32 or more characters | Encrypts access tokens for phishing email templates and drill reports, prevents unauthorized downloads |
| `STORAGE_S3_ENDPOINT` | Access address of the enterprise’s own object storage service | Aligns with existing enterprise document storage compliance requirements, unifies data management paths |
| `DB_MAX_LINK` | 100–200 connections | Balances concurrent demand for drill data queries and database resource usage |
| `FE_DOMAIN` | Enterprise internal domain or dedicated subdomain | Isolates external access, maintains internal use attributes of the training and drill platform |

## Three common misconfigurations
- After upgrading the version, the drill report detail page displays the `Invalid dataset file key` error. This occurs because the upgrade process did not synchronize the updated `FILE_TOKEN_KEY` configuration value, causing the original file token verification to fail.
- Database connection timeouts occur when deploying the community edition. This happens because no reasonable value was configured for `DB_MAX_LINK`, and concurrent requests exceed the database connection limit.
- No correct configuration is applied for the duration and usage count limits of non-commercial API keys. This stems from not enabling verification rules in the corresponding configuration items, leading to risks of key abuse.

## How to confirm proper configuration
- Run the built-in database connectivity test script to verify connectivity for `MONGODB_URI` and `REDIS_URL`, confirm there are no access permission or connection timeout issues.
- Upload a test phishing email template, generate an access link via `FILE_TOKEN_KEY`, verify the link opens normally and has no unauthorized access anomalies.
- Check the frontend page loading status, confirm the `FE_DOMAIN` configuration matches the actual access address, with no cross-domain or domain resolution errors.
- Simulate a small-scale drill audience filtering operation, verify that the data mapping rules take effect and the filtering results match employee contact list data.
