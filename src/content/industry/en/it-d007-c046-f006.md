# Online Fault Troubleshooting and Retrospective for Security Baseline Checks: Scheduled Tasks and Automation

## What the data for this category looks like
Security baseline check data is sourced from server configurations, middleware configurations, security device policies, and baseline tools. The update cycle is monthly or quarterly. Daily produced documents include baseline checklists, configuration verification records, rectification suggestions, and exception approval forms. Fields cover configuration item identifiers, compliance verification results, rectification execution status, exception approval opinions, and no preset additional statistical values.

## What constraints these characteristics impose on the scheduled tasks and automation link
Multi-source data pulling requires scheduled tasks to adapt to the interface permissions of different data sources. Monthly or quarterly update cycles limit task trigger frequency to avoid excessive computing resource waste. Dispersed document types require automated workflows to automatically synchronize multiple document types such as checklists and verification records, ensuring data consistency. The manual nature of exception approval forms requires setting manual review nodes in tasks, as the compliance of exception configurations cannot be fully automatically determined. The high time-consuming nature of configuration verification requires automated workflows to prioritize batch compliance checks, reducing manual repetitive labor.

## How to configure the settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Task trigger cycle | `30 days` | Matches the monthly data update rhythm, adapts to the security baseline check cycle |
| Data pull scope | Server, middleware, and security device three types of data sources | Covers all data sources to ensure no missed compliance checks |
| Compliance check threshold | `100% match baseline standards` | Meets the core requirements of security baseline checks, weak configurations require rectification |
| Abnormal alert trigger condition | `compliance check failure rate ≥5%` | Identifies batch configuration abnormalities in a timely manner, avoids long-term risk accumulation |
| Manual review node trigger rule | When detecting configuration items associated with exception approval forms | Exception configurations require manual confirmation, cannot be automatically determined as compliant |
| Log retention duration | `180 days` | Meets internal control audit requirements for retention of compliance verification records |

## Three Common Configuration Mistakes
- Phenomenon: Scheduled task trigger frequency does not match the preset, for example, a monthly task is triggered daily. Cause: Incorrect selection of task cycle unit, or configuration parameters not saved in the interface.
- Phenomenon: Compliance check result is empty, unable to obtain configuration item data. Cause: Incorrect configuration of data pull scope, missing pull permissions for some data sources.
- Phenomenon: Scheduled task function does not take effect, unable to perform baseline checks as scheduled. Cause: Relevant permissions of the scheduled task module are not enabled in the FastGPT v4.17.0 SaaS version, or configuration parameters do not take effect.

## How to Confirm the Configuration Is Successful
- Enter the scheduled task management interface, check that the trigger cycle, data pull scope and other parameters of the created baseline check task match the configured items, confirm that the configuration has been saved and takes effect.
- Manually trigger a baseline check task, check whether compliance check results for all configuration items can be obtained, confirm that the data source coverage meets the required scope.
- Simulate a scenario with weak configurations, verify whether the abnormal alert triggers according to the preset rules, confirm the validity of the alert configuration.
- View task execution logs, confirm that the log retention duration meets the requirements of organizational internal control audits.
