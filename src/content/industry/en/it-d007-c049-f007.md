# Online Troubleshooting and Retrospective for Customer Training and Usage Manual: Conversation Logs and Auditing

## What This Category’s Data Looks Like
This data typically originates from product help centers, customer organizational structures, training recording videos, and ticket systems. It updates per order or per version. Daily documents include training slides, user manuals, training attendance sheets, and question-and-answer lists. Data fields cover training topics, participant IDs, operation step screenshots, ticket feedback numbers, and question-and-answer record timestamps. Common units are person-times, minutes, and character counts. Documents are archived by training batches and customer groups. This category focuses on building first-time usage capabilities. Its core difference from renewal health management categories is that it prioritizes first-use operation guidance and problem resolution.

## Constraints Imposed on Conversation Logs and Auditing
This category’s data characteristics impose multiple constraints on the conversation logs and auditing workflow. Data sources are scattered across product help centers, training recording videos, and ticket systems. Auditing tools must connect to multiple entry points to collect complete interaction data. Update frequency is per order or per version. Tools must support associating logs with training batches and customer versions. Documents are archived by training groups. Logs must be stored classified by role and operation step. Fields include question-and-answer records and permission explanation content. Full interaction links must be retained. This covers operation traces from the most time-consuming segments, such as role permission explanations and operation step demonstrations. Omitting these traces will make post-session problem organization difficult and lead to a surge in follow-up tickets.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind the session ID associated with the training batch | This category’s data is archived by training batch. `chatId` can associate all user interaction logs within a single batch, enabling auditing by batch |
| `responseChatItemId` | Associate the unique ID of user questions and customer service responses | Full recording of the question and response link during the Q&A segment is required. `responseChatItemId` can accurately locate the complete flow of a single interaction |
| `detail` | `true` | This category requires retaining full details of operation step demonstrations and permission explanations. Full logs cover operation traces from role permission explanation segments |
| Log Storage Period | 180–365 days | Training data must be retained until the next version update, to support subsequent retrospectives and ticket traceability requirements |
| Auditing Filter Dimensions | Classify by role, training batch, and operation step | This category’s documents are archived by training groups. Filtering by these dimensions allows rapid location of abnormal points during post-session problem organization |
| Real-Time Sync Switch | Enabled, calibrated based on actual testing | Update frequency is per order or per version. Real-time sync ensures association between the latest training data and logs |

## Three Common Configuration Errors
- Symptom: The session interface displays image upload success, but interaction buttons remain disabled. Logs only record upload requests with no subsequent response fields. Cause: Full log collection with `detail` is not enabled. Abnormal nodes during image parsing cannot be captured, making it impossible to identify the root cause of disabled buttons.
- Symptom: User Q&A records for a specified training batch cannot be retrieved. Filtered results are empty. Cause: The association between `chatId` and the training batch is not established. Logs are not archived by batch, leading to missing filter dimensions.
- Symptom: Knowledge base search node returns results unrelated to historical context. Reference resolution fails. Cause: Configuration to associate historical interactions using `responseChatItemId` is missing. Complete session links are not retained, leading to lost context.

## How to Verify Successful Configuration
- Access the FastGPT backend, view the session log list, and confirm that logs can be filtered by training batch and user role.
- Trigger a training Q&A interaction, and verify that logs include the `chatId`, `responseChatItemId` fields, and full `detail` content.
- Simulate a ticket submission scenario, and verify that logs can associate ticket numbers with Q&A records.
- Verify the log storage period configuration, ensuring retention duration can be adjusted based on business requirements.

The values provided are common starting points and should be measured against the reader's own samples.
