# Online Troubleshooting and Retrospective for Customer Training and Usage Manuals: Database and Operations

## What the data for this category looks like
The output creators for this category are customer success managers, training instructors, and product operations teams. Daily documents include training slides, user manuals, training attendance sheets, and question-and-answer lists. Data is primarily collected from the product help center, customer organizational structures, training recordings, and ticket systems. Updates follow a per-order or per-version cycle. Each document includes fields such as role permission descriptions, operation step demonstrations, and post-class question-and-answer records. Training data for different customers must be archived and differentiated by organizational structure. Training recordings and question-and-answer lists must be linked to corresponding slide versions and ticket records.

## What constraints these characteristics impose on database and operations workflows
Data for this category originates from scattered sources and connects to multiple business processes. This requires database and operations workflows to support structured import of multi-source data and cross-table associated storage. Data update cycles are inconsistent, so on-demand adjustment of storage capacity and indexing strategies must be supported to avoid resource idle or shortage. Training data for different customers must be isolated by organizational structure, requiring tenant-level data permission controls. Documents include multimedia content such as text and recordings, so support for both text indexing and binary storage is required. Core fields such as operation steps and permission descriptions need dedicated indexing to ensure retrieval efficiency and prevent response delays during fault troubleshooting.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://[username]:[password]@host:port/database?authSource=admin` | Adapts to multi-tenant data isolation and cross-table associated storage requirements, and supports mixed storage of text and binary data |
| `PG_URL` | `postgresql://[username]:[password]@host:port/dbname?sslmode=require` | Used to store structured training document metadata, ensuring accurate querying of permission fields |
| `DB_MAX_LINK` | `20–30` | Matches the concurrency of single-batch data import for this category, avoiding connection pool exhaustion |
| `REDIS_URL` | `redis://[password]@host:port` | Used to cache training document indexes for high-frequency queries, accelerating retrieval speed during fault troubleshooting |
| Database connection timeout | `300 seconds` | Adapts to the writing and reading processes of large files such as training recordings, avoiding mid-process interruptions |

## Three Common Misconfigurations
- Database connection plugin installation fails, with internal server error prompts. The cause is that the authentication source parameter is not correctly filled in the `MONGODB_URI` configuration, or the database port is not granted external network access permissions.
- FastGPT new version fails to start, with mongo error prompts in the console. The cause is that `DB_MAX_LINK` is set too low, leading to connection pool exhaustion, or the database version is incompatible with FastGPT v4.17.0.
- Exported knowledge base content after training returns empty results. The cause is that `REDIS_URL` is not configured as a task caching queue, causing export requests to fail normal scheduling.

## How to Confirm Configurations Are Properly Set
- Run the built-in database connection test tool to verify connectivity for `MONGODB_URI` and `PG_URL`, and confirm there are no authentication or permission errors.
- Import a test training slide document, and check that data is stored correctly by tenant dimension with no cross-tenant data leakage risks.
- Initiate a small-scale export test, and confirm that export tasks generate files normally with no timeouts or interruptions.
- View the operations and maintenance monitoring panel, and confirm that database connection counts stay within the `DB_MAX_LINK` value range with no abnormal fluctuations.

The values provided are common starting points and should be measured against the reader's own samples.
