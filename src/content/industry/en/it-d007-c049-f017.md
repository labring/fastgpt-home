# Online Troubleshooting and Retrospective for Customer Training and Usage Manuals: Deployment and Upgrade

## What the data for this category looks like
Core data for this category typically comes from product help centers, customer organizational structures, training recording videos, and ticket systems. Daily produced documents include training courseware, user manuals, training attendance sheets, and problem Q&A lists. Data update frequency follows per order or per version. The most time-consuming steps focus on role permission explanations, operation step demonstrations, and post-class question organization. Document structures usually include audience segmentation, operation steps, and common question modules. Fields include document version, update time, associated customer identifier, audience group tags, and more. There are no fixed mandatory unit requirements.

## What constraints these characteristics impose on deployment and upgrade workflows
Because data sources are scattered and updates are frequent, the deployment workflow must support fast integration with multi-source document synchronization tools. This prevents inconsistent content after deployment caused by document updates. Because documents contain role permission-related content, preset permission configuration templates must be deployed. These templates adapt to the access scope of different training audiences, such as permission differences between regular customers, administrators, and other roles. Because update frequency follows per order or per version, the upgrade workflow must be compatible with old document structures. This prevents existing training materials from failing to load normally after upgrade, while retaining customer historical training records. At the same time, because core data is associated with customer identifiers, independent storage and access permissions must be configured during deployment. This prevents confusion of training data across different customers, and ensures data security.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale for This Setting |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@host:27017/training_db?authSource=admin` | Persistently stores core category data such as training courseware and ticket records |
| `REDIS_URL` | `redis://:your_redis_password@host:6379/0` | Caches training recording video access tokens, user sessions, and retrieval caches |
| `FE_DOMAIN` | `https://your-training-platform.com` | Binds the official access domain for training manuals, ensuring front-end resources load normally |
| `ROOT_KEY` | `Randomly generated string of 32 or more characters with no special symbols` | Configures the system's highest privilege management entry, used for batch updates of training content |
| `DB_MAX_LINK` | `10–20 connections` | Limits database connection count to adapt to daily concurrent access demands for training documents |
| `STORAGE_S3_ENDPOINT` | `Set based on actual testing` | Adapts to storage and access demands for large files such as training recording videos and courseware |

## Three Common Configuration Mistakes
- Running `docker-compose up` results in a failed startup, with an error indicating database connection timeout. The cause is incorrect access permissions for `MONGODB_URI` or `PG_URL`, or the database service did not start normally.
- Training manual pages fail to load, and the front end displays a 404 error. The cause is the domain configured in `FE_DOMAIN` not being bound to the public IP of the deployment server, or the front-end resource packaging path being incorrect.
- Uploaded training courseware cannot be retrieved, or training recording videos cannot play normally. The cause is missing `STORAGE_S3_ENDPOINT` configuration, resulting in an incorrect file storage path, or the access permissions for the storage service not being enabled.

## How to Verify Configurations Are Correct
- Run the `docker-compose config` command. Check that all configuration items follow the FastGPT v4.17.0 specification, with no syntax errors.
- Access the domain corresponding to `FE_DOMAIN`. Confirm that the training manual homepage loads normally, with no blank pages or error prompts.
- Use the `ROOT_KEY` to call the system's built-in permission verification interface. Verify that the highest privilege configuration takes effect, and that batch document update operations can be performed normally.
- Upload a test training courseware under 10MB. Confirm that the file can be uploaded and stored normally, and can be found normally via the retrieval function.
