# Online Troubleshooting and Retrospective for Customer Onboarding and Tenant Initialization: HTTP Interfaces and External Systems

This guide applies to FastGPT v4.17.0.

## What data for this category looks like
Data for this category typically originates from CRM systems, contract orders, identity management systems, and product backends. Daily documents include onboarding application forms, tenant configuration tables, admin account lists, and delivery confirmation slips. Core fields cover basic customer information, tenant ID, permission configuration scope, admin account lists, and more. Data update frequency is once per order or daily. Single update volume is completed gradually as the customer onboarding process advances.

## Constraints on HTTP interfaces and external systems
Since data sources involve multiple external systems, HTTP interfaces must support integration with different external services such as identity management and CRM. This ensures consistent data synchronization. Data update frequency is low, but single processes involve multiple field checks. Interfaces must have complete parameter verification capabilities to prevent initialization failures caused by missing fields. Field requirements from daily documents must be synchronized to interface parameters. This ensures returned data can be directly used for document verification, reducing manual verification costs. Additionally, the most time-consuming steps focus on customer information verification, permission initialization, and result confirmation. Interfaces must support status query capabilities to handle abnormal interruptions in long-running processes.

## Configuration Settings
Configuration focuses on three core dimensions: `Authorization` authentication, `variables` business parameters, and `responseData` return fields. Specific configuration items are listed below:
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Interface authentication method | Bearer {tenant_admin_token} | Complies with identity authentication standards, ensuring only authorized tenant administrators can call the interface |
| Business parameter configuration | {"customer_name": "", "tenant_quota": "1000 MB", "expire_days": 7} | Matches field requirements from onboarding application forms and tenant configuration tables, covers customer information and basic permission configurations |
| Return field filtering | ["tenant_id", "admin_account", "status"] | Matches core verification fields on delivery confirmation slips, enabling automatic completion of onboarding result confirmation |
| Interface timeout period | 600 seconds | Covers the maximum time required for customer information verification and permission initialization, preventing mid-process interruptions |
| Call frequency limit | 1 time per order, peak not exceeding 10 times per minute | Adapts to the data update rhythm of once per order or daily, avoiding overload of external systems |

## Three Common Configuration Mistakes
- Phenomenon: Front-end access address cannot be switched to HTTPS, browser displays an insecure connection warning. Cause: SSL certificate is not bound in the external system reverse proxy configuration, or HTTPS forwarding rules for the interface are not correctly configured.
- Phenomenon: Customers cannot log in after tenant initialization. Cause: The `variables` parameter does not include the correct identity management system user identification field, resulting in failed account synchronization.
- Phenomenon: Onboarding result confirmation times out, delivery process gets stuck. Cause: The `responseData` parameter is not correctly configured, resulting in failure to retrieve the onboarding status field returned by the interface, preventing automatic completion of result confirmation.

## How to Confirm Configuration is Correct
- Call the test interface, check if returned fields match parameters in the tenant configuration table.
- View the user list in the identity management system, confirm that the newly created tenant admin account has been successfully synchronized.
- Trigger a complete tenant initialization process, check if the status of the onboarding application form in the CRM system has updated to completed.
- Verify the call logs of external systems, confirm that interface call frequency meets the set threshold.

The values provided are common starting points and should be evaluated against the reader's own samples.
