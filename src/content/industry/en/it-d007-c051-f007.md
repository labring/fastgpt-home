# Online Troubleshooting and Retrospective for Customer Data Import Migration: Conversation Logs and Auditing

## What This Category of Data Looks Like
This category of data primarily comes from customer legacy systems, CSV or Excel templates, database exports, and product import logs. Supporting daily documents include data templates, migration plans, field mapping tables, and migration validation reports. Data update cadence is per order or irregular. Core processing steps include field mapping confirmation, dirty data cleaning, and post-import sampling verification. Common error consequences include historical data loss, field misalignment, and customer rejection. Associated core roles include implementation consultants, data implementation engineers, and customer IT liaisons.

## Constraints Imposed on Conversation Logs and Auditing
This category of data characteristics imposes multiple constraints on the conversation logs and auditing link. Multi-source data import scenarios require logs to cover all trigger paths including template uploads, direct database connections, and API calls. The irregular update business characteristic requires auditing to support order-by-order tracing, with archiving cadence adjustable based on individual task requirements. Supporting documents are strongly bound to imported data, so field mapping rules and dirty data cleaning logic must be fully recorded. The high error risk in core processing steps requires logs to retain pre- and post-import data comparisons, failure node details, and operation timelines. Severe error consequences require full-link operation logs to be fully exportable for problem retrospectives and responsibility clarification.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Session Binding Identifier | `chatId` | Links the full process conversation of a single import task to enable order-by-order tracing |
| Response Item Record Identifier | `responseChatItemId` | Binds the processing response for a single imported data entry to accurately locate failure causes for individual data entries |
| Detailed Operation Logs | `detail` | Records specific parameters and execution results of field mapping and data cleaning to support retrospectives |
| Log Retention Period | 180 days | Covers the time window for regular problem troubleshooting to meet retrospective requirements |
| Exception Trigger Threshold | Calibrated via actual testing | Adapts to differences in dirty data proportions across different customers, allowing flexible adjustment of judgment criteria |
| Log Export Format | CSV format | Matches the editing habits of migration validation reports to facilitate subsequent associated analysis |

## Three Common Misconfigurations
- Phenomenon: The `detail` field is empty in import task logs, making specific data processing steps unviewable. Cause: The detailed operation log collection switch is not enabled, and only basic session identifiers are recorded.
- Phenomenon: Import progress is stuck on the frontend interface, with no errors shown in logs, and task status updates after refreshing. Cause: A delay exists in synchronization between frontend and backend logs, and real-time synchronization rules for session status polling are not configured.
- Phenomenon: Field misalignment is found during post-import sampling verification, but no field mapping modification records appear in audit logs. Cause: Field mapping configuration operations are not included in the scope of audit logs, and only the final import result is recorded.

## How to Verify Proper Configuration
- A single test import is executed, and whether the logs include the `chatId`, `responseChatItemId`, and `detail` fields is checked to confirm core log items have been collected.
- An abnormal import is triggered, such as a CSV file with incorrect formatting, and whether corresponding exception logs are generated and include detailed error information is verified.
- Logs for a specified import task are exported, and compatibility between the export format and daily document processing tools is confirmed.
- The log retention duration configuration is reviewed to confirm it meets the retrospective cycle requirements of the current business.

The values provided are common starting points and should be measured against available local samples.
