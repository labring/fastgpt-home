# Online Troubleshooting and Retrospective for Customer Permission and Organizational Structure Configuration: Database and Operations

## What the data for this category looks like
This category of data primarily comes from customer HR systems, identity directories, product backends, and audit logs. Updates occur per single request or on an irregular schedule. Daily produced documents include permission matrices, organizational structure tables, role configuration records, and permission change tickets. Fields cover department identifiers, role identifiers, associated user accounts, permission coverage ranges, change timestamps, and operator information. The data structure changes dynamically with customer organizational adjustments. There is no fixed batch update cycle.

## What constraints these characteristics impose on the database and operations link
Decentralized data sources require integration with multiple sets of identity synchronization interfaces. Differences in data formats across systems must be addressed. The irregular update feature requires the database to support flexible write and query modes. Fixed batch tasks cannot be relied upon. Complete audit trails must be retained for permission matrices and change records. Non-tamperable storage fields must be configured. The association between organizational hierarchies and role mappings is complex. Reasonable index structures must be designed to avoid query delays. Data must also adapt to custom organizational rules for different customers. Sufficient field expansion space must be reserved to prevent table structure conflicts during subsequent adjustments.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | Configure cluster addresses with read-write separation suffixes, enable connection pool reuse | Adapt to scattered query and write requests from multiple customers, reduce single-connection overhead |
| `PG_URL` | Configure dedicated read-only replica addresses for permission queries | Separate query and change traffic for permission data, avoid business writes blocking permission verification requests |
| `DB_MAX_LINK` | 100–150 connections | Match the maximum connection limit for a single instance, prevent service unavailability caused by exhausted connections |
| `REDIS_URL` | Configure cluster addresses with password authentication, enable RDB persistence | Cache permission mapping results from high-frequency queries, reduce database query pressure |

## Three Common Misconfigurations
- A `429 Too Many Requests` error occurs, and permission verification requests have a latency exceeding 5 seconds. The cause is that a reasonable value for `DB_MAX_LINK` is not configured, leading to exhausted database connections and an inability to handle concurrent permission verification requests.
- Some users cannot access corresponding resources after a permission change, and query results return empty fields. The cause is that mandatory field validation for audit logs is not enabled, leading to missing user identifier fields in permission change tickets, and an exception occurs during database writing.
- Organizational structure synchronization fails when connecting to Feishu, and imported file content cannot be recognized. The cause is that a compatible document format whitelist is not configured. Only standard identity directory formats are supported, and special format files exported from Feishu are not adapted.

## How to Confirm Proper Configuration
- View the database connection pool monitoring panel, confirm that the current active connection count does not reach the configured `DB_MAX_LINK` value.
- Initiate a batch permission change request, check whether the audit log completely records all change fields and operator information.
- Simulate permission queries for users at different organizational levels, confirm that query response times meet preset thresholds.
- Test importing identity directory files exported from Feishu, confirm that the organizational structure table can be synchronized and updated normally.
