# Online Troubleshooting and Post-Incident Review for Advertising Compliance Logging: HTTP Interfaces and External Systems

## What the data for this use case looks like
Service stakeholders in the advertising compliance logging scenario include advertising platform compliance teams, agency legal departments, and brand marketing teams. Data comes from four sources: advertising platform backend, customer qualifications, contract systems, and publicly available regulatory rules. Core daily documents include four key types: advertising review forms, qualification attachments, delivery records, and rectification notices.

Data update frequency aligns with single advertising campaigns or monthly cycles. Core fields include campaign ID, compliance review status, qualification validity period, and rectification completion status. Common units are items, copies, and days. The most time-consuming steps focus on qualification archiving, delivery record storage, and rectification evidence organization. Data must be retained until the end of the regulatory inspection cycle.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
This use case requires integration with multiple external systems. HTTP interfaces must support concurrent calls and format adaptation for data from multiple sources such as advertising platforms and contract systems.

Data update cycles are flexible. Interfaces must support call logic triggered by single advertising campaigns. Scheduled polling cannot match the random update rhythm of campaigns.

Large-volume qualification attachments and structured delivery records coexist. Interfaces must support chunked transfer or batch submission.

Data retention requirements are strict. Interfaces must fully record all request and response content. This avoids situations where no evidence is available during regulatory inspections, customer liability claims, or account penalties.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Updated per campaign | Matches the requirement for data to update at the frequency of single advertising campaigns |
| `variables` | Bound to core compliance fields | Associates key information from advertising review forms and rectification notices |
| `responseData` | Stored in full | Meets the requirement for complete evidence retention for regulatory inspections |
| Interface timeout | 600 seconds | Accommodates transfer of large-volume data such as qualification attachments and delivery records |
| Request retries | 3 times | Addresses temporary service fluctuations in advertising platform backends |
| Batch processing threshold | First 50 items | Balances archiving efficiency and system resource usage |

## Three Common Misconfigurations
- Symptom: Workflow validation fails with the prompt "Missing, missing values, or abnormal connections". Cause: Required fields from advertising review forms and qualification attachments are not correctly bound to `variables`.
- Symptom: The Human field in API conversation response records is null. Cause: User input parameters for compliance queries are not correctly passed to `variables` in interface requests.
- Symptom: Interface calls time out with a 504 status code. Cause: An insufficiently long timeout period is set, preventing transfer of large-volume qualification attachments.

## How to Confirm Proper Configuration
- Verify that the `Authorization` credential is automatically updated each time an advertising campaign is triggered.
- Initiate a mock interface call to confirm that `responseData` contains complete fields from advertising review forms, delivery records, and rectification notices.
- Submit test data within the batch processing threshold to confirm that the interface can complete archiving and logging operations normally.
- Run workflow validation to confirm that there are no prompts for missing fields or abnormal connections.

The values provided are common starting points and should be measured against the reader's own samples.
