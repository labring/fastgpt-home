# Online Troubleshooting and Post-Mortem for Ad Creative Review: HTTP Interfaces and External Systems

## What the Data for This Category Looks Like
Ad creative review data sources include advertising platforms, landing pages, product qualifications, and advertising law clauses. Update frequency is daily or real-time. Daily associated documents include ad creative files, landing page screenshots, review opinion sheets, and modification records. Core fields cover creative unique identifiers, review status, violation type tags, landing page URLs, and qualification numbers. Data primarily exists in two formats: structured text and binary images, and is updated in real time alongside delivery plans or review actions.

## Constraints Imposed by These Characteristics on HTTP Interfaces and External Systems
The need to access multi-source data requires interfaces to adapt to the authentication and return formats of different advertising platforms, and standardized request and parsing logic must be implemented. The real-time update feature requires interfaces to support low-latency calls to avoid blocking the review process. Transmission of multiple data types requires interfaces to support both text and binary streams, with chunked upload support required in some scenarios. The need for standardized parsing of core fields requires that interface return results can be uniformly extracted and associated, facilitating subsequent traceability and post-mortem of review records. Additionally, the serious consequences of review errors require interfaces to be configured with retry and alert mechanisms to reduce the impact of failures on ad delivery.

## How to Set the Configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` authentication header | Bearer token format, set token validity period to 7 days | Matches the standard authentication specifications of most advertising platform open APIs, ensuring request legitimacy |
| Interface timeout | 60 seconds | Matches the single-item processing time limit for ad creative review, preventing process interruptions caused by request backlogs |
| Maximum retry count | First 3 attempts | Addresses temporary jitter in advertising platform interfaces, reducing the probability of single review failure |
| Response data parsing | Extract violation fields from `responseData` | Standardizes parsing of return structures from different advertising platforms, simplifying subsequent review logic and troubleshooting |
| Context variable passing | Carry creative ID and landing page URL via `variables` | Associates external interface requests with local review records, facilitating quick location of specific creatives associated with faults |

## Three Common Misconfigurations
- Symptom: Interface returns 401 Unauthorized error, review process interrupts. Cause: No automatic token refresh logic configured for the `Authorization` header, and no new token is obtained after the existing token expires.
- Symptom: A large number of duplicate creative review requests are initiated in a short period, triggering rate limiting interception by the advertising platform. Cause: No unique request identifier is passed via `variables` to implement deduplication, leading to repeated submission of the same review task.
- Symptom: The `responseData` field is empty, making it impossible to extract violation point information. Cause: The nested return structure of the target advertising platform is not adapted to, and deep fields are not parsed correctly.

## How to Confirm the Configuration Is Correct
- Initiate a review request for a single test creative, check whether the request header carries a valid `Authorization` token, and confirm that the interface returns a 200 status code.
- Parse the `responseData` returned by the interface, verify whether core review fields such as violation type and landing page matching degree can be extracted.
- Simulate a temporary interface failure scenario, check whether the preset retry mechanism and alert notifications are triggered.
- Pass a test creative ID via `variables`, and verify that the association between local review records and external interface requests is correct.

The values provided are common starting points and should be measured against local samples.
