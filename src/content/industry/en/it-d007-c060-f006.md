# Online Troubleshooting and Retrospective for Ad Account Opening Audit: Scheduled Tasks and Automation

## Data Overview for This Scenario
Data for the ad account opening audit scenario comes from ad platform backends, the national enterprise credit information public disclosure system, customer-submitted account opening application materials, and industry access rules. Daily associated documents include account opening application forms, scanned business licenses, industry operation qualification documents, and historical account opening audit records. Data updates trigger once per application submission, or via a full daily sync. Core fields include subject name, unified social credit code, applied industry category, audit status, and correction notice content. No unified fixed unit field exists. Format requirements align only with the associated document type.

## Constraints for Scheduled Tasks and Automation
Scattered data sources require scheduled pulls of ad platform APIs, enterprise credit system APIs, and customer-submitted local materials. Interface call frequencies and permission requirements differ across sources, so targeted task trigger rule configurations are needed. Data updates use two modes: per application submission and full daily sync. Both application event-triggered and scheduled batch verification execution modes must be supported. Core fields require cross-source consistency checks across ad platforms, enterprise credit systems, and other sources. A single task handles many fields, so execution duration must be controlled to avoid timeout interruptions. Audit results directly affect delivery compliance. Task failures must quickly trigger alert and retry mechanisms to avoid disrupting the account opening process.

## How to Set Configurations

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Task trigger timing | Triggered once per application submission; perform full verification at 00:00 daily | Matches the two data update frequencies: per application submission and full daily sync |
| Single task execution duration | Within 1200 seconds | Avoids task timeout interruptions, and accommodates the time requirements of cross-source consistency checks for multiple fields |
| Failure retry count | 2 retries, with a 300-second interval | Addresses temporary API fluctuations, and reduces audit delays caused by occasional failures |
| Variable update mechanism | Automatically update global variables when the audit status changes | Synchronizes the latest audit progress, and avoids variable lag caused by relying solely on scheduled pulls |
| Alert trigger threshold | Trigger an alert when 3 consecutive task failures occur | Quickly identifies persistent failures, and ensures the stability of the audit process |
| Log retention period | 30 days | Meets log query requirements for online troubleshooting and retrospective analysis |

## Three Common Misconfiguration Issues
- Symptom: API request returns 404 - Resource Not Found. Cause: The ad platform API path configured for the scheduled task is incorrect, and does not match the official API address for the current environment.
- Symptom: Global variable values are not automatically updated. Cause: No variable update hook is configured for audit status changes, and only scheduled pulls are used to synchronize audit progress, which may result in status lag.
- Symptom: Scheduled task execution times out and is interrupted. Cause: A single task processes too many account opening application batches, and no batch splitting is performed, exceeding the preset execution duration limit.

## How to Verify Successful Configuration
- Manually trigger a scheduled task, and check for a successful execution record in the task log module of FastGPT v4.17.0.
- Submit a test account opening application, simulate an audit status change, and check whether the global variable is updated to the latest audit result.
- Simulate an API call failure to trigger the alert condition for 3 consecutive failures, and check whether the preset alert notification is received.
- Check the log retention directory to confirm that task execution logs for the corresponding period have been properly generated and archived.
