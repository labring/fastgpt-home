# Online Troubleshooting and Post-Mortem for Ad Account Opening Audit: Database and Operations

## What the Data for This Category Looks Like
The data for this category primarily comes from the advertising platform backend, the National Enterprise Credit Information Publicity System, account opening application materials and industry qualification documents submitted by clients, and public industry access rules. Data synchronization runs daily or is triggered with each account opening application. Common documents involved include account opening application forms, scanned business licenses, industry operation qualification certificates, and account opening audit record ledgers. Data fields include full subject name, unified social credit code, applied advertising industry, audit status, correction communication record number, and others. There is no unified fixed unit, as values vary by field attributes. Unlike the advertising material audit category, the core of this category’s audit is pre-confirmation of the advertising subject and industry qualifications.

## What Constraints Do These Characteristics Impose on the Database and Operations Link
Mixed multi-source data storage requires the database to support both structured field storage and unstructured file metadata management. The uncertain data update rhythm requires the operations link to configure an elastic connection pool to adapt to sudden batch application requests. Frequent external data source calls require adding a caching mechanism to reduce repeated query overhead. The strong consistency requirement for data association verification requires configuring transactions to ensure synchronized updates of audit records and qualification data. The most time-consuming link is subject qualification verification and industry access judgment. Therefore, database query index configuration must be optimized to reduce single-request response time and support time control for the audit process.

## How to Configure the Settings
This configuration is adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `PG_URL` | `postgresql://user:pass@host:5432/ad_audit` | Stores structured audit records and subject qualification fields; PostgreSQL is suitable for complex associated queries |
| `MONGODB_URI` | `mongodb://user:pass@host:27017/ad_audit_files` | Stores metadata of unstructured files such as business licenses and industry qualifications; adapted for semi-structured data storage |
| `DB_MAX_LINK` | `20–30` | Adapts to mixed requests of daily batch applications and real-time submissions; avoids connection exhaustion |
| `REDIS_URL` | `redis://:pass@host:6379/0` | Caches query results from the National Enterprise Credit Information Publicity System to reduce repeated external calls |
| Redis cache expiration time | `1 day` | Balances cache hit rate and timeliness of qualification information |
| Database connection timeout | `30 seconds` | Matches the typical response time of external qualification queries; prevents audit process blocking |

## Three Common Misconfigurations
- Symptom: The same SQL statement sometimes returns data correctly and sometimes fails. Cause: No reasonable value is configured for `DB_MAX_LINK`. The connection pool exhausts connections during high-concurrency application periods, leaving some SQL requests without available connections.
- Symptom: Tool call nodes stall directly when executing database queries. Cause: No Redis cache is configured. Frequent calls to the National Enterprise Credit Information Publicity System trigger external interface rate limiting, and requests time out without triggering a retry mechanism.
- Symptom: Storage exceptions occur for unstructured qualification file metadata, and query responses are slow. Cause: A relational database is misused to store large-field file information, which cannot adapt to high-concurrency query requirements for batch qualification verification.

## How to Confirm the Configuration Is Valid
- Execute batch simulated account opening application requests, observe the database connection pool usage rate, and adjust the `DB_MAX_LINK` value to match the current business peak interval.
- Trigger multiple identical qualification query requests, check the Redis cache hit count, and confirm that the cache configuration is active.
- Import a batch of unstructured qualification files, verify that the storage and query processes for file metadata work normally.
- Simulate an external interface rate limiting scenario, check whether the database query node triggers a reasonable timeout retry logic.

The values provided are common starting points and should be measured against the reader's own samples.
