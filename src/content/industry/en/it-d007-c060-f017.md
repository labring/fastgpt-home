# Online Troubleshooting and Post-Mortem for Ad Account Opening Audit: Deployment and Upgrade

## Data Overview for This Category
The data for this category typically comes from advertising platform backends, the National Enterprise Credit Information Public Disclosure System, customer-submitted materials, and industry access rules. Daily associated documents include account opening application forms, scanned business licenses, industry qualification certificates, and audit records. The data update rhythm follows either per-application or daily cycles. Fields include subject name, qualification number, audit status, submission time, and additional relevant fields. There is no fixed unified standardized format, and some fields require cross-data source association verification.

## Constraints on Deployment and Upgrade
Dependence on multiple data sources requires configuring stable cross-system access permissions during deployment, to avoid qualification verification failures caused by insufficient permissions. Unstructured document storage demands a storage solution adapted to flexible fields; during upgrades, the field structure of legacy audit records must be compatible. The high-frequency real-time verification and update rhythm requires a caching service that supports high-frequency queries, to avoid delays from repeated calls to external interfaces. Since audit results are directly linked to the account opening process, the deployment and upgrade phase must include complete failure retry and alert mechanisms, to prevent account opening failures or non-compliant ad placements.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---|---|--- |
| `MONGODB_URI` | `mongodb://[username]:[password]@[host]:[port]/fastgpt?authSource=admin` | This category requires storing flexible qualification materials and audit records; MongoDB is suited for unstructured document storage and querying |
| `DB_MAX_LINK` | `20–30 connections` | The database connection demand for a single audit task is stable; this value avoids connection pool exhaustion and adapts to daily concurrent volume |
| `REDIS_URL` | `redis://:[password]@[host]:[port]/0` | High-frequency queries of industry access rules and subject verification results need to be cached, reducing the overhead of repeated calls to external interfaces |
| `STORAGE_S3_ENDPOINT` | `https://s3.[region].[service provider domain]` | High-definition qualification scan files submitted by customers need to be stored, adapting to large file upload and download requirements |
| `FILE_TOKEN_KEY` | `32-character random string` | Secure file access tokens must be generated to prevent unauthorized downloading of sensitive qualification materials submitted by customers |
| `PG_URL` | `postgresql://[username]:[password]@[host]:[port]/fastgpt` | Can be used as an alternative storage solution to MongoDB, for storing structured audit process logs |
| `ROOT_KEY` | Generate a strong random string based on the deployment environment | Platform highest-privilege operations must be controlled, to prevent unauthorized modification of audit processes or data tampering |

## Three Common Misconfigurations
- The symptom is an audit process error "connection timeout" with status code 504. The cause is failure to configure a reasonable `DB_MAX_LINK` for multiple data sources, leading to database connection pool exhaustion and inability to respond to qualification verification requests in a timely manner.
- The symptom is that qualification materials submitted by customers cannot be stored normally, with "file upload failed" displayed on the interface. The cause is incorrect configuration of `STORAGE_S3_ENDPOINT`, leading to an incorrect storage service address and inability to complete large file uploads.
- The symptom is missing audit record fields, such as empty qualification numbers. The cause is failure to verify the read/write permissions of `MONGODB_URI` during deployment, leading to inability to write complete audit data fields.

## How to Verify Correct Configuration
- Execute the version query command to confirm that the currently running FastGPT version is v4.17.0, and verify that the deployment package matches the officially released version.
- Submit a test account opening application, check whether a complete audit record is generated in the database, and verify that the read/write permissions of `MONGODB_URI` are functional.
- Upload a test qualification scan file, check whether it can be stored normally and an access link is generated, and verify that the `STORAGE_S3_ENDPOINT` configuration is correct.
- Check connection pool monitoring metrics to confirm that the current database connection count does not exceed the configured `DB_MAX_LINK` threshold, and verify that the connection pool configuration is effective.
