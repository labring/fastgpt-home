# Online Troubleshooting and Retrospective for Ad Performance Optimization: Deployment and Upgrade

## Data Profile for This Category
The data for this category primarily comes from advertising platform APIs, attribution systems, CRM lead databases, and landing page event tracking data. The update rhythm is daily or real-time. Regularly produced documents include daily and weekly performance reports, keyword or material price adjustment records, material A/B test sheets, and performance optimization retrospective reports. Data fields include impressions, clicks, conversions, customer acquisition cost, budget balance, etc., with units such as counts, yuan, etc. Field formats vary across advertising platforms, so extraction must follow the corresponding API specifications.

## Constraints for Deployment and Upgrade
The data sources for this category are scattered and update flexibly. When deploying, stable connection parameters for multiple data sources must be configured to avoid connection interruptions during real-time synchronization. Daily documents have inconsistent formats. When upgrading, the parsing logic for legacy price adjustment records and retrospective reports must be compatible to prevent data import failures. The real-time update feature requires verifying the latency of indicator synchronization after deployment. A configuration entry for exception alerts must also be reserved to avoid increased customer acquisition costs or early budget exhaustion due to undetected indicator anomalies.

## Configuration Guidelines
The following configuration items are formulated based on the deployment specifications of FastGPT v4.17.0:

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://aduser:adpass@mongodb-host:27017/ad_optimize` | Stores ad performance data, price adjustment records, and retrospective reports; supports bulk data write requirements |
| `REDIS_URL` | `redis://default:redispass@redis-host:6379/1` | Caches real-time synchronized ad indicator data; reduces repeated call frequency of advertising platform APIs |
| `DB_MAX_LINK` | `200–300 concurrent connections` | Supports concurrent access demands from multiple data sources; prevents connection exhaustion during real-time synchronization |
| `STORAGE_S3_ENDPOINT` | `https://s3-ad-optimize.yourprovider.com` | Stores document files such as material test sheets and retrospective reports; complies with object storage specifications of advertising platforms |
| `ROOT_KEY` | `Customized per the security policy of the deployment environment` | Controls access permissions for internal system configuration interfaces; prevents unauthorized configuration modifications |

## Three Common Misconfigurations
- Symptoms include failure to obtain the global variable token when calling an MCP tool in a workflow, with an error returned indicating an empty field. The root cause is that the storage and delivery chain of global variables was not configured during deployment, and the workflow context was not correctly associated with tool call parameters.
- Symptoms include an incompatible hardware architecture error when starting the service, making it impossible to load model inference components. The root cause is that the compilation dependencies for Ascend 910B were not adapted during upgrade, and the hardware-accelerated runtime environment was not correctly configured.
- Symptoms include timeout errors with 408 status code when calling advertising platform APIs after switching from oneapi to aiproxy. The root cause is that the timeout parameters of the proxy configuration were not updated per the deployment process, and connectivity between the proxy and each advertising platform was not verified.

## How to Verify Successful Configuration
- Run a connectivity test for `MONGODB_URI`, write a test price adjustment record, and verify that data can be stored and read normally.
- Trigger a real-time indicator synchronization task, check the cache hit rate of `REDIS_URL`, and confirm that real-time data caching is active.
- Upload a legacy material test sheet, verify that the document parsing process can correctly extract core fields such as impressions and conversions.
- Call the internal configuration interface, send a request using an unauthorized key, and confirm that the interface returns an insufficient permissions error.

The values provided are common starting points and should be measured against the reader's own samples.
