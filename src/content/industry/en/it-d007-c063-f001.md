# Online Troubleshooting and Retrospective for Campaign Setup: HTTP Interfaces and External Systems

## What This Category of Data Looks Like
The data for this category mainly comes from advertising platform APIs, user profile datasets, internal budget scheduling tables, and attribution tools. Daily produced documents include campaign setup plans, targeting setting rules, budget scheduling tables, and conversion tracking configuration items. Data updates occur daily or when a single campaign starts. Fields include targeted audience tags, budget amounts, conversion event IDs, delivery time periods, and other metrics. Units involve yuan, visits, hours, and others. There is no fixed unified format specification. The field requirements of the connected external advertising system must be matched.

## Constraints for HTTP Interfaces and External Systems
The data sources for this category are scattered. Formats are inconsistent. HTTP interfaces must support field mapping and format conversion for multi-source data. This prevents configuration failures caused by field mismatches. Data updates occur daily or when a single campaign starts. Interface call frequency must match the data update rhythm. This avoids triggering external system rate limits from high-frequency calls. Daily configuration documents include multiple independent modules. Interfaces must support submission by module or full plan synchronization. This reduces single-request complexity. Configuration errors will directly cause budget waste or failed campaign launches. Interfaces must include basic verification logic. This intercepts invalid parameters in advance.

## How to Configure Settings
| Configuration Item | Recommended Approach | Basis for This Approach |
| ---|---|--- |
| `Authorization` | Token in the format `Bearer {API_KEY}` | Complies with the identity verification specification of the official FastGPT v4.17.0 interface, ensuring legitimate interface call permissions |
| `variables` | Pass grouped by campaign setup module, for example `{"targeting": [], "budget": {}}` | Matches the structure of daily campaign setup documents, reduces field mapping complexity, and simplifies error troubleshooting |
| `responseData` | Include a three-level structure of `code`, `message`, `data` | Unifies external system return formats, enabling quick identification of call results and error causes |
| Single request data volume | 10–20 delivery configuration items | Matches the single submission limit of advertising platform APIs, preventing rate limits from overly large requests |
| Timeout period | 30–60 seconds | Covers runtime for routine operations such as budget verification and audience tag pulling, avoiding semi-successful configurations caused by timeouts |

## Three Common Misconfigurations
- An interface call returns `{"code":514,"statusText":"invalid api key"}`. Cause: The `Authorization` parameter is not configured correctly, and the token format or permissions do not meet the requirements of the connected system.
- The interface returns only structured data with no text format content. Cause: No text parsing rule for `responseData` is specified in the request, and the readable output format required for campaign setup is not matched.
- Some targeting settings fail to take effect after submitting batch delivery configurations. Cause: The single request data volume exceeds the single submission limit of the external advertising system, resulting in truncated and unprocessed configuration items.

## How to Confirm a Successful Configuration
- Verify that the `Authorization` parameter matches the token provided by the connected system before calling the interface, to ensure identity verification passes.
- After submitting a test configuration, check whether the returned `responseData` structure meets the preset campaign setup field requirements, to confirm data format compatibility.
- Initiate a small-batch configuration request, observe the return logs of the external advertising system, and confirm that configuration items have been correctly synchronized.
- Simulate a campaign setup update scenario, verify that the interface retry mechanism triggers correctly after a timeout, and avoid semi-successful configurations.
