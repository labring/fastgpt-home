# Online Troubleshooting and Retrospective for Campaign Setup: Scheduled Tasks and Automation

## What the data for this category looks like
Data sources for the campaign setup phase include advertising platform APIs, budget scheduling sheets, attribution tool reports, and user profile tag libraries. Regularly produced structured documents include campaign plans, audience targeting settings, budget allocation rules, and conversion tracking configurations.
Data updates occur either on a daily schedule or when campaign activities are triggered. Core fields include targeted audience tag codes, daily budget amounts, conversion event IDs, and delivery time window parameters. Supported units include yuan, impressions, hours, and other relevant units.

## Constraints Imposed on Scheduled Tasks and Automation
Structured campaign plan documents require automated configurations to precisely match field mapping rules, to prevent misconfigured campaign settings caused by field misalignment. Data sources rely on external advertising platform APIs, so the scheduled task trigger rhythm must align with the API call limits and data update cycles of the advertising platform.
The accuracy of conversion tracking configurations directly impacts subsequent campaign performance. Automated workflows must complete field validity checks before task execution.
Timeliness of budget allocation requires that tasks do not experience excessive delays, as this could lead to budget waste or delayed campaign startup.

## How to Configure Settings
The following configurations are based on the interface and functional logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Scheduled task trigger frequency | Every 4 hours / 1 hour before campaign activation | Matches the update cadence of daily or campaign-specific campaign plans, and aligns with the platform's task scheduling limits |
| API timeout threshold | 180–300 seconds | Covers execution durations of non-streaming API requests and complex workflows, to prevent mid-task disconnects |
| File parameter validation switch | Enabled | Ensures uploaded file links can be correctly passed as parameters to workflows, and filters invalid link formats |
| Automatic knowledge base ID retrieval | Bound to project context for automatic fetching | Reduces manual configuration errors, and aligns with the association logic between campaign projects and knowledge bases |
| Failure retry count | 2–3 retries | Addresses temporary network fluctuations or short-term advertising API jitter, to improve task success rates |
| Alert trigger rules | Task failure / timeout / field validation failure | Notifies relevant personnel of exceptions promptly, to prevent escalation of campaign incidents |

## Three Common Misconfigurations
- Symptom: Uploaded test files cannot pass their links as parameters to bound workflows, and the workflows receive empty parameters. Cause: The file parameter validation switch is not enabled, so the system automatically filters non-predefined link formats.
- Symptom: Non-streaming tasks initiated via API are forcibly disconnected after exceeding 180 seconds, failing to complete the full campaign setup process. Cause: The API timeout threshold was not adjusted, and the default short timeout setting was retained.
- Symptom: Workflows cannot automatically retrieve the knowledge base ID for the corresponding project, and configured fields show empty values. Cause: The campaign project context was not bound, so the system cannot pull associated knowledge base configuration information.

## How to Verify Proper Configuration
- Manually trigger a scheduled task, check the task logs, and confirm that the pulled campaign plan fields match the locally configured document content.
- Upload a test file, and verify that the workflow can correctly receive and use the file link as an execution parameter.
- Simulate a task failure scenario, and confirm that the configured alert notifications trigger normally and are pushed to the specified channel.
- Check the workflow's knowledge base association configuration, and confirm that the system can automatically retrieve the knowledge base ID for the corresponding campaign project.

The values given are common starting points and should be measured against the reader's own samples.
