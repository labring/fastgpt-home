# Online Troubleshooting and Retrospective for Campaign Setup: Conversation Logs and Auditing

## What this type of data looks like
Daily documentation for campaign setup includes campaign plans, targeting settings, budget scheduling, and conversion tracking configurations. Data sources include advertising platforms, user profiles, budget spreadsheets, and attribution tools. Update frequency follows a daily cadence or updates per individual campaign activity.

Data fields include unique plan identifiers, targeting audience parameters, budget amounts, conversion event IDs, and additional relevant fields. Units involve yuan, entries, days, and other standard units. The volume of associated interaction data for a single campaign plan changes based on configuration complexity.

## What constraints do these characteristics impose on conversation logs and auditing
The multi-source data characteristics of campaign setup require conversation logs to link business identifiers such as campaign plan ID and targeting configuration ID. This prevents cross-activity log confusion.

Following the per-activity or daily data update rhythm, audit logs must support archiving and filtering by activity dimension. This aligns with standard retrospective cycles.

Full-process interactions cover core links including targeting, budget, and conversion. Logs must retain complete conversation chains to enable tracing of configuration errors.

Additionally, the security requirements of advertising account data mandate that log access be bound to corresponding permission roles. This prevents leakage of sensitive configuration information.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind campaign plan ID as prefix | Quickly filter conversation logs for the corresponding campaign activity |
| `responseChatItemId` | Associate interaction ID of targeting configuration nodes | Precisely locate conversation interactions in the audience targeting link |
| `detail` | Store complete interaction chains, maximum 8000 characters of storage | Cover full-process conversations for targeting, budget, and conversion configurations |
| Context recall count | First 8 historical conversations | Match the short-link interaction characteristics of campaign setup |
| Single export limit | 1000 entries | Adapt to batch export business scenarios |
| Log retention period | 30 days after campaign ends | Align with time requirements for standard campaign retrospectives |

This page applies to FastGPT v4.17.0.

## Three Common Misconfigurations
- Symptom: Conversation log displayed context count does not match configured settings, and some historical interactions are not included. Cause: The context recall range is bound to the knowledge base search threshold during configuration, and the independent conversation log filtering rule does not take effect.
- Symptom: Unable to export full conversation logs, or exported results lack interaction content from the targeting configuration link. Cause: The activity-dimensional log archiving switch is not enabled, and only temporary logs for the current session are retained.
- Symptom: In the campaign setup workflow, after the AI replies with budget configuration suggestions, the workflow automatically returns to the question classification node. Cause: No branch termination node is configured for the workflow, causing the process to loop and trigger classification verification logic.

## How to Verify Correct Configuration
- Enter a test campaign plan ID, filter conversation logs, and confirm that only interaction records for the corresponding activity are displayed.
- Export logs for a specified campaign activity, and check that complete interaction content for targeting settings, budget allocation, and conversion tracking is included.
- Verify the return fields of the log export interface, and confirm that complete information for `chatId`, `responseChatItemId`, and `detail` is included.
- Check log retention duration, and confirm that corresponding logs can still be retrieved within 30 days after the campaign ends.

The values provided are common starting points and should be measured against the reader's own samples.
