# Online Troubleshooting and Retrospective for Campaign Setup: Deployment and Upgrade

## What the data for this category looks like
Daily documents for campaign setup include campaign setup templates, audience targeting configuration sheets, budget scheduling tables, and conversion tracking configuration items. Data primarily comes from advertising platform APIs, user profile tag libraries, offline budget approval forms, and attribution analysis tools. Data update cycles typically follow daily synchronization or full updates when a single campaign launches. Fields include targeted audience package IDs, budget thresholds, conversion event codes, and the like. There are no unified standardized units, and some fields must match the enumeration value format of the advertising platform.

## What constraints these characteristics impose on deployment and upgrade workflows
Data for campaign setup comes from multiple heterogeneous sources. During deployment, parameters for multi-source data integration must be configured, and enumeration value verification logic must be built in to prevent configuration failures caused by mismatched data formats. Data updates occur on a daily or campaign level. During upgrades, stability of data synchronization tasks must be maintained to prevent failed campaign launches after interruptions. The most time-consuming steps include audience targeting, budget allocation, and conversion event verification. These steps require built-in field validity checks during deployment to reduce manual troubleshooting costs. Failures may result in wasted budget or failed campaign launches. Quick rollback parameters must be configured before upgrades to ensure fast service recovery during outages. FastGPT v4.17.0 added a retry mechanism for multi-source data synchronization, which is compatible with the update cycles of this category.

## How to set configurations
| Configuration Item | Recommended Configuration Value | Rationale |
| ---|---|--- |
| `MONGODB_URI` | `mongodb://[username]:[password]@host:port/dbname?authSource=admin` | Targeted audience packages and historical configuration data for campaign setup require persistent storage, and must match the enumeration value format returned by advertising platforms |
| `REDIS_URL` | `redis://:password@host:port/0` | Real-time budget verification results and temporary data for targeted audience packages must be cached. Cache expiration time is recommended to be set to 3600 seconds |
| `PG_URL` | `postgresql://username:password@host:port/dbname` | Historical versions of budget schedules and associated records of attribution data must be stored, and multi-tenant permission isolation must be supported |
| `DB_MAX_LINK` | `100–150` | Concurrent request volume for campaign setup typically stays below 100, preventing connection pool exhaustion from impacting service stability |
| `ROOT_KEY` | `Randomly generated string of 32 or more characters` | Used for signature verification when connecting to advertising platform APIs, preventing unauthorized configuration modifications |
| `FE_DOMAIN` | `https://your-deploy-domain.com` | Configures the access domain for the frontend service, used for cross-origin request verification and callback address setup |

## Three common mistakes
- Symptom: A 401 unauthorized error is returned when calling the advertising platform API, and targeted audience package data cannot be loaded. Cause: Authentication parameters in `ROOT_KEY` or `MONGODB_URI` are not configured correctly, causing signature verification to fail.
- Symptom: When using OneAPI deployed via Sealos to call a large model, function call tools cannot be triggered, and conversion event verification for campaign setup fails. Cause: The API gateway address deployed via Sealos was not added to the `FE_DOMAIN` configuration, causing cross-origin requests to be blocked and tool call parameters to fail to pass correctly.
- Symptom: An error indicating failed dependency package retrieval is displayed when building a Docker image, and the local debugging environment cannot be started. Cause: A correct dependency source image was not specified, or the local network cannot access the official package management repository, causing the build process to interrupt.

## How to confirm configurations are correct
- Run the `docker ps` command to confirm that all dependent service containers (MongoDB, Redis, PostgreSQL) are running.
- Call the configured advertising platform API interface to verify that targeted audience package data stored in `MONGODB_URI` can be read normally and matches enumeration values.
- Modify the budget configuration for one campaign setup to observe whether the cache in `REDIS_URL` is updated synchronously within the set expiration time.
- Run the upgrade rollback script to verify that the permission verification logic of `ROOT_KEY` can normally block unauthorized configuration modifications.

The values provided are common starting points and should be evaluated against the reader's own samples.
