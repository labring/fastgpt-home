# Online Troubleshooting and Retrospective for Bid Document Preparation: Scheduled Tasks and Automation

## What this category of data looks like
This category of data is generated around the full bid lifecycle. Sources include tender announcements, tender documents, enterprise qualification libraries, and supplier quotes. Daily processed documents include bid documents, qualification certificates, business deviation tables, and technical deviation tables. Most have fixed-format tables and clause text, with fields corresponding to qualification, quotation, and response items required by tenders. Each business order corresponds to one data update, with no fixed universal cycle.

## What constraints these characteristics impose on scheduled tasks and automation
Data sources are scattered and updated per order. Scheduled pulls of the latest tender announcements and qualification library information are required to avoid using expired qualifications that make responses non-compliant with tender requirements. Document structures are fixed but have significant format differences; bid document formats vary between tenderers, so splitting and validation rules must be adjusted for each individual file, making universal template batch processing impossible. Single-task data volume varies with bid order scale; large bid documents may contain large amounts of qualification and clause content, requiring flexible execution pacing to avoid excessive resource usage. Task failure directly relates to bid rejection risk, so strict accuracy and completeness of task execution must be ensured. A fast retry and notification process must be triggered after failure to reduce the probability of bid rejection.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Scheduled Trigger Cycle | Pre-pull period is 2:00 AM to 4:00 AM daily, single task trigger delay is 24 hours before bid submission | Matches the business rhythm of per-order updates, pre-pulls the latest tender information to avoid temporary waiting, ensuring response timeliness |
| Document Splitting Rules | Split by line + custom delimiter set to line break | Adapts to the line-by-line format of qualification entries and clauses in bid documents, prevents cross-line content from being merged into a single row during Excel import |
| Task Retry Count | 3 times | Balances task success rate and resource consumption, adapts to fault tolerance requirements under bid rejection risk, prevents single failure from directly causing task invalidation |
| Task Timeout Threshold | 1800 seconds | Covers processing duration for large bid documents, avoids mid-run interruptions that lead to bid rejection risk |
| Exception Notification Configuration | Triggered when task fails or result field is empty | Synchronizes exception information to relevant personnel in a timely manner, reducing the probability of bid rejection caused by delayed handling |

## Three Common Misconfigurations
- Scenario: After importing a bid qualification Excel file, multiple originally line-separated qualification entries are merged into a single row. Cause: Custom line delimiter is not configured, using the default general splitting rule causes cross-line content to not be properly split.
- Scenario: Image links in the bid document generated by the scheduled task are not replaced with the specified server address. Cause: File content parsing and external link replacement configuration is not enabled, and the target file server is not bound.
- Scenario: After nesting a knowledge base assistant in a workflow, the API call returns an empty value. Cause: The workflow's context transfer parameter is not configured in `FastGPT v4.17.0` or later, resulting in no valid input for knowledge base calls.

## How to Verify Proper Configuration
- Upload a test Excel file containing multiple line-separated qualification entries, check if each split entry occupies a separate row to verify that the custom delimiter configuration is effective.
- Trigger a scheduled task for a small bid document, check if the task log contains a successful record of image external link replacement to verify that the file server binding configuration is effective.
- Call the API interface of the corresponding workflow, pass test tender text and qualification data, check if the returned result contains complete response content to verify that the context transfer configuration is effective.
- Simulate a task failure scenario, such as manually setting the timeout threshold lower than the actual processing duration, check if the preset notification reminder is triggered to verify that the exception trigger configuration is effective.

The values provided are common starting points and should be measured against the reader's own samples.
