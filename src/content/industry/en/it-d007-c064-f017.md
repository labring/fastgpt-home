# Online Troubleshooting and Retrospective for Tender Document Preparation: Deployment and Upgrade

## What the data for this category looks like
Core data for tender document preparation is generated around individual tender projects. Daily documents include tender documents, qualification certificates, commercial deviation tables, and technical deviation tables. Data sources include public tender announcements, tender documents, internal enterprise qualification databases, and external supplier quotation information. The update frequency is once per project. Each individual tender document includes structured response clauses, qualification certificate numbers, quotation details and other fields, as well as unstructured content such as stamped scanned copies. The total size is typically between 100–500 MB, and is updated dynamically as the project progresses.

## What constraints these characteristics impose on deployment and upgrade
Project data for tender document preparation has strict isolation requirements. Documents and configurations from different projects cannot be shared across instances, so deployments must support storage and cache configurations that enable multi-project isolation. Individual files are large and contain multiple format types, so deployment processes must optimize timeout settings for large file uploads and parsing to avoid parsing interruptions. Additionally, errors in tender projects can lead to bid rejection and earnest money losses. Upgrade processes must maintain service availability and must not interrupt ongoing document processing tasks. Data sources also include external public tender documents, so deployments must support flexible connection to temporary import interfaces for external data sources. This guide is based on the configuration specifications for FastGPT v4.17.0.

## How to set configuration values
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `300 seconds` | Tender document parsing requires loading multiple associated documents. Extend the database connection timeout to avoid parsing interruptions |
| `REDIS_URL` | Address of a dedicated instance with no less than 2048 MB of memory | Tender project data requires strict isolation. Use a dedicated Redis instance to store sessions and temporary document caches, ensuring read and write speed |
| `STORAGE_S3_ENDPOINT` | Endpoint address adapted to the enterprise’s internal object storage | Tender documents include large scanned copies. Use enterprise internal object storage to ensure data storage compliance and access speed, supporting the 100–500 MB file upload requirement |
| `FILE_TOKEN_KEY` | Randomly generated 32-character string | Prevent unauthorized tampering of access tokens for tender documents, protecting access permissions for project documents |
| `ROOT_KEY` | Key known only to internal operations staff | Restrict access to backend configurations, preventing unauthorized personnel from modifying parsing configurations for tender documents |

## Three common misconfigurations
- Symptom: An `embed ding error` error occurs when uploading tender-related documents to build a knowledge base. Cause: `STORAGE_S3_ENDPOINT` is not configured correctly, causing large qualification scanned copies to fail to upload to the storage medium, triggering a failure in the embedding task.
- Symptom: After deployment using docker-compose, knowledge base operations fail, with system logs displaying `Exception: 'usage' Keye`. Cause: `ROOT_KEY` or database connection parameters are not configured correctly, causing the system to fail to call the permission verification field for the large model interface, triggering a key exception error.
- Symptom: Full tender document clause content fails to load after creating a knowledge base. Cause: The `DB_MAX_LINK` parameter is not adjusted to a value suitable for multi-document association, causing the database connection to disconnect early during parsing of multiple associated tender documents, resulting in incomplete content loading.

## How to verify the configuration is correct
- Upload a tender file not exceeding 500 MB, confirm whether the corresponding file is generated in the storage medium, verifying that the `STORAGE_S3_ENDPOINT` configuration takes effect.
- Run a database connection test, confirm whether the connection timeout matches the preset `DB_MAX_LINK` value, verifying database connection stability.
- Attempt to create two isolated knowledge bases for tender projects, confirm whether document data from different projects cannot access each other, verifying that the isolation configuration for `REDIS_URL` takes effect.
- Check backend logs to confirm there are no permission-related errors, verifying that the `ROOT_KEY` and `FILE_TOKEN_KEY` configurations are correct.

The values provided are common starting points and should be evaluated against the specific samples of the deployment environment.
