# Online Troubleshooting and Review for Data Security Classification and Grading: Deployment and Upgrade

## What This Category of Data Looks Like
Data for this category originates from data asset inventories, database metadata, business system descriptions, and compliance regulatory documents. Update frequency is quarterly, or when the corresponding business system changes. Daily produced documents include data catalogs, classification and grading rules, important data identification tables, and review minutes. Fields cover data asset identifiers, sensitivity levels, affiliated businesses, compliance requirements, and more. There is no unified fixed unit, and adjustments are made based on specific data asset types.

## Constraints for Deployment and Upgrade Processes
Data sources for this category are scattered, with significant structural differences between datasets. Extended configuration to support multi-source metadata import must be reserved during deployment.
Update frequency is adjusted flexibly based on business system changes. The upgrade process must support smooth migration of old-version classification and grading rules and review minutes. For FastGPT v4.17.0 and later versions, additional adaptation to the new storage permission verification rules is required.
Various document types require separate configuration of compliant storage paths to retain all types of compliance documents. Data governance scenarios have high requirements for deployment stability. The upgrade process must support configuration items for zero-downtime or gray switching to avoid disrupting compliance review work for business systems.

## How to Set Configuration Values
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–150 concurrent connections` | Adapts to concurrent query needs of multi-source data assets, avoids deployment exceptions caused by connection pool exhaustion |
| `MONGODB_URI` | `Authenticated cluster connection address` | Stores classification and grading rules and review minutes, requires highly reliable persistent storage and compliance with data security access requirements |
| `REDIS_URL` | `Local cache instance, memory configuration no less than 2048 MB, expiration time set to 300 seconds` | Caches frequently accessed classification and grading rules, reduces database query pressure and improves deployment response speed |
| `FE_DOMAIN` | `Compliant public or intranet domain name for service deployment, port 80 or 443` | Configures the front-end access entry, ensures data governance teams can access the system through compliant paths |
| `STORAGE_S3_ENDPOINT` | `Compliant object storage endpoint` | Stores compliance documents such as data catalogs and identification tables, must meet data retention and access audit requirements |
| `ROOT_KEY` | `Strong key generated according to enterprise security policies` | Configures the system's highest privilege access credential, prevents unauthorized access to sensitive configurations |

## Three Common Configuration Mistakes
- Phenomenon: Local Ollama service access fails after Docker private deployment, with model connection failure displayed in the interface. Cause: The network mode of the deployment container is not set to host, or port mapping for local Ollama access is not added, preventing the container from accessing the Ollama port of the host machine.
- Phenomenon: When upgrading from 4.8.17 to 4.9.0, the `curl --location` command executed in the upgrade script returns a 404 status code. Cause: The target address in the upgrade script does not adapt to the new FastGPT release path, or the local network cannot access the official image repository.
- Phenomenon: A `failed to solve: failed to checksum fi` error occurs when building an image with `docker build`. Cause: The checksum of locally cached dependency packages is abnormal during the build process, or dependency file downloads are incomplete due to network interruptions.

## How to Verify Proper Configuration
- Run the `docker ps` command, confirm all deployment containers are in running state, with no abnormally exited logs.
- Access the configured `FE_DOMAIN` address, log in to the system and view the classification and grading rule list, confirm that imported rules have no missing or formatting errors.
- Connect to the configured `MONGODB_URI` and `REDIS_URL`, perform basic read-write tests, confirm that storage and cache services are connected normally.
- Upload a test review minutes document, confirm that it can be normally stored in the storage service corresponding to the configured `STORAGE_S3_ENDPOINT`.

The values provided are common starting points and should be measured against the reader's own samples.
