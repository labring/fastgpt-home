# Online Troubleshooting and Retrospective for Database Cloud Service Operations: Conversation Logs and Auditing

## What the data for this category looks like
The data for this category mainly comes from cloud database consoles, slow query logs, performance monitoring metrics, and operation ticket systems. Daily produced documents include instance change orders, backup and recovery records, performance diagnosis reports, and parameter adjustment records. Data updates occur daily or in real time when configuration changes are made. Fields include instance ID, operation time, operation content, associated ticket number, performance thresholds, and more. Some slow log data records SQL execution details at millisecond granularity.

## What constraints these characteristics impose on the conversation logs and auditing link
Conversation logs for cloud database operations must be associated with instance IDs and ticket numbers to match the complete fault troubleshooting chain. High-granularity slow log data requires audit logs to retain sufficient field details to avoid missing key execution information during troubleshooting. For updates triggered by configuration changes, the audit system must support quick retrieval of corresponding sessions by change order ID. Multi-tenant cloud service boundaries require conversation logs to be stored isolated by tenant to prevent cross-tenant data leakage. Sessions related to backup and recovery must retain complete operation links to ensure recovery processes can be traced.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Session ID binding rule | Bind cloud database instance ID as session ID prefix | Match the requirement of retrieving sessions by instance in operation scenarios, and comply with the instance association requirements of data sources |
| Log detail retention item | Retain complete operation and execution log fields | Cover full chain details for slow SQL troubleshooting and parameter adjustment, and meet audit requirements of business scenarios |
| Ticket association configuration | Bind operation ticket ID to session records | Enable quick association between sessions and operation tickets, facilitating traceability of complete processes during fault retrospective |
| Log retention duration | 30–90 days | Comply with general cloud service operation audit compliance requirements, and balance storage costs and troubleshooting needs |
| Session retrieval limit | Top 20 sessions | Avoid excessive retrieval results affecting troubleshooting efficiency, and adapt to daily batch troubleshooting scenarios for DBAs |

## Three Common Misconfigurations
- Phenomenon: Calling the historical record API with customUid specified via API returns sessions that include records for non-target instances or users. Cause: customUid is not used as a binding field for session IDs, only the default session identifier is relied on, and instance-level session isolation is not implemented.
- Phenomenon: Unable to obtain historical records when calling the conversation log interface from a workflow node. Cause: No association rule between session ID and workflow instance is configured, resulting in failure to match the context of the corresponding session during retrieval.
- Phenomenon: Conversation log download links cannot be accessed normally after configuring a proxy. Cause: No path rewrite or permission rules for the conversation log interface are added in the proxy configuration, causing the frontend to fail to correctly pull log files.

## How to Confirm Configuration is Correct
- Call the historical record API, pass the bound instance ID or customUid, and verify that the returned sessions only include records for the target instance or user.
- View the details of a single session, confirm that the operation ticket ID or instance change order number is associated, and the link information is complete.
- Check the log retention duration configuration, confirm that it meets the audit requirements of the business scenario, and that the retention period is not set too short or too long.
- Use FastGPT v4.17.0 to test the conversation log download or viewing function, and confirm that there are no access errors.
