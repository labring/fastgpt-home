# Database Operations Online Fault Troubleshooting and Retrospective: Scheduled Tasks and Automation

## What This Category of Data Looks Like
Database operations scenario data originates from database monitoring systems, operation audit logs, SQL execution plan files, and ticketing systems. Daily documents include database change orders, slow SQL performance reports, backup and recovery records, and permission application approval forms. Data updates follow two rhythms: real-time generation during single database changes, or daily batch statistical report generation. Data fields include execution duration (milliseconds), backup file size (GB), and permission application approval status. Data formats and structures vary across different sources.

## Constraints Imposed on Scheduled Tasks and Automation
Decentralized, varied data sources require scheduled tasks to support multi-data source pulling logic and format parsing rules, preventing data loss from format incompatibility. Differences in update rhythms require task cycles to match corresponding data generation frequencies. For example, use trigger-based execution for change orders, and daily execution for slow SQL reports. Data-associated business risks are high. Task failures or execution exceptions can cause data permission oversteps or query timeouts. Configure complete failure retry and alert mechanisms to ensure exceptions are detected and handled promptly.

## Recommended Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Scheduled task trigger cycle | `1 day` or `on change trigger` | Matches the regular update rhythm of slow SQL reports and database change orders, avoids duplicate processing or missing critical data |
| Task execution timeout threshold | `300 seconds` | Adapts to the typical time consumption of single-instance slow SQL analysis and log pulling, prevents long task blocking that occupies resources |
| Number of failure retries | `2 times` | Addresses temporary monitoring interface fluctuations or network jitter, reduces the probability of task failure caused by single exceptions |
| Knowledge base binding scope | Bind the dedicated knowledge base of the corresponding business database | Limits the retrieval scope, avoids cross-database data interfering with fault troubleshooting results |
| Exception alert trigger condition | When a task fails or the retrieval result is empty | Notifies operation and maintenance personnel in a timely manner to handle exceptions, meeting the timeliness requirements of fault troubleshooting |

## Three Common Mistakes
- Symptom: Scheduled tasks return empty slow SQL analysis results after execution. Cause: The database monitoring data source address configured for task pulling is incorrect, so valid log data cannot be retrieved.
- Symptom: An error occurs when configuring automatic knowledge base switching. Cause: The knowledge base is not bound to the corresponding database instance identifier, so the task cannot identify the target retrieval scope.
- Symptom: Task startup verification fails, prompting missing required configuration. Troubleshooting steps: Verify whether the required environment variables `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service, for example http://aiproxy:3000, no path suffix allowed, not a single model address such as VLLM/Ollama/Xinference) and `AIPROXY_API_TOKEN` (AI Proxy administrator token, consistent with AI Proxy server configuration and cannot be empty, not an application API key or model vendor key) are missing from the App/Admin server. Also check whether these variables were incorrectly filled in application API request headers, workflow global variables, or other locations, which violates FastGPT v4.17.0 deployment requirements.

## How to Confirm Proper Configuration
- Check environment variables on the App/Admin server, confirm that `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service, for example http://aiproxy:3000, no path suffix allowed, not a single model address such as VLLM/Ollama/Xinference) and `AIPROXY_API_TOKEN` (AI Proxy administrator token, consistent with AI Proxy server configuration and cannot be empty, not an application API key or model vendor key) are correctly configured and not empty.
- Manually trigger a scheduled task, review the task execution log, and confirm no abnormal errors occur during data source pulling and knowledge base retrieval.
- Simulate a database change ticket, verify that the automated review process triggers normally and generates corresponding results.
- Configure a failure alert, simulate a task exception scenario, and confirm that alert notifications are sent normally.
