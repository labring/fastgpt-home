# Online Troubleshooting and Retrospective for Data Collection Task Design: Conversation Logs and Auditing

## What the data for this category looks like
Data for this category primarily comes from customer requirements, public data sources, collection tools, and internal sample libraries. It is managed daily through four types of documents: collection plans, sample specifications, authorization instructions, and task schedules. Data updates are performed per project or weekly. Core fields include sample scope, collection fields, compliance verification identifiers, and task schedule nodes. Common units are sample count, data volume in MB, and time in days. This step determines how raw data is obtained. The core difference from the subsequent data cleaning and quality inspection step is that it does not process collected data, only defines data acquisition rules.

## What constraints these characteristics impose on the conversation logs and auditing link
Decentralized data sources mean logs must cover multi-channel collection actions, and must be associated with documents such as collection plans and authorization instructions for compliance auditing. The requirement for project-by-project or weekly data updates means logs must be archived by project to avoid cross-project data confusion. The verification logic for core fields must be embedded in logs to ensure that sample scope and field specifications match the collection task. The compliance status of authorization instructions must have audit nodes recorded in logs to avoid infringement risks. Additionally, in scenarios with multiple collaborating parties, logs must record operation nodes for different roles to facilitate tracing the causes of task schedule delays.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Session Association ID | Bind `chatId` and `responseChatItemId` | Used to track the full process of collection tasks within a single session, matching project-level log archiving rules |
| Detailed Log Switch | Enable the `detail` parameter | Retain complete configuration of collection actions, including core verification content such as sample scope and field specifications |
| Log Storage Period | 30–90 days | Adapt to the data archiving requirements of project-by-project or weekly updates, facilitating cross-cycle retrospectives |
| Audit Trigger Node | Match the collection legitimacy verification step | Trigger audit logs when collection actions deviate from preset compliance rules |
| Log Query Scope | Restrict to collection tasks within the current project | Match the permission boundaries of data service project managers, collection teams, and customer algorithm teams |

## Three common mistakes
- Symptom: When consecutive collection task requests are initiated within the same session, the response time exceeds 600 seconds. New session requests return to normal. Cause: `chatId` and `responseChatItemId` are not bound for session isolation, causing logs to not be archived by session, and backlogged historical collection task data occupies retrieval resources.
- Symptom: After starting a collection task, there are no compliance verification records in the logs, and the sample scope does not match the preset collection plan. Cause: The `detail` parameter is not enabled, so the configuration details of the collection action are not retained, making it impossible to trace abnormalities in the compliance verification step.
- Symptom: After deploying FastGPT v4.8.10 locally, port 3000 is inaccessible, and logs only display database connection-related prompts. Cause: Parameter verification during the container startup step is not configured in the audit logs, resulting in incomplete recording of database connection configurations, making it impossible to locate link abnormalities.

## How to confirm configurations are set correctly
- Initiate consecutive collection tasks within a single session, check if logs are associated with `chatId` and `responseChatItemId`, and confirm that session isolation configuration is active.
- Trigger a compliance verification abnormality, check if a complete log with the `detail` parameter is generated, and confirm that the detailed collection switch is enabled.
- Filter logs by project dimension, confirm that the storage period covers the full cycle of the current project, and confirm that the archiving rules match requirements.
- Switch between different role accounts, confirm that only collection task logs within the current project are visible, and confirm that permission configurations adapt to the permission logic of FastGPT v4.17.0.
