# Online Troubleshooting and Retrospective for Dataset Delivery and Version Management: Database and Operations

## What this category of data looks like
Typically, this category of data is maintained by data project managers, data engineers, and customer algorithm teams. Daily documents include dataset descriptions, version records, delivery checklists, and acceptance reports. Data sources cover object storage, data warehouses, annotation platforms, and customer acceptance feedback. Update frequencies align with each batch or version release. Data fields usually include dataset identifiers, version numbers, source paths, sample counts, acceptance statuses, and similar items. Units are commonly entries, GB, days, and other standard units. The core focus is on the completeness of delivery packages and version traceability, which differentiates this service from similar offerings focused on data cleaning. This content is compatible with FastGPT v4.17.0.

## What constraints these characteristics impose on database and operations
This category of data is scattered across multiple sources, update frequencies fluctuate with versions, and core documents require structured storage and fast querying. These factors create multiple constraints for database operations.
Multi-data source access requirements demand configuration of connection parameters compatible with different storage types. Core metadata such as version numbers and sample count differences must be persistently stored to prevent loss that would make training unreproducible. Delivery completeness verification requires support for complex conditional queries, which places demands on database index optimization. Frequent version updates and delivery operations require limiting concurrent connection counts to avoid service overload.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@host:27017/fastgpt_dataset` | Used to store unstructured version records and delivery checklists, supports flexible storage for multi-source data |
| `PG_URL` | `postgresql://user:pass@host:5432/fastgpt_metadata` | Stores structured dataset description and acceptance report fields, supports complex conditional queries |
| `DB_MAX_LINK` | `20–30 connections` | Prevents database connection exhaustion, adapts to concurrent requests from multiple batch dataset deliveries |
| `REDIS_URL` | `redis://:password@host:6379/0` | Caches frequently accessed version metadata to reduce database query load |
| Cache expiration time | `300 seconds` | Reduces the number of database queries for frequently accessed version metadata |
| Dataset export granularity | By business classification dimension | Adapts to split export requirements for multiple types of knowledge bases, meets refined delivery requirements |

## Three common misconfigurations
- Phenomenon: When exporting a dataset, only the knowledge base dimension can be selected, and splitting by business classification or data type is not available. Cause: The export granularity parameter configured by business dimension is not set, and only knowledge base-level granularity is enabled by default.
- Phenomenon: A database connection error is reported during local deployment, prompting that the host name cannot be resolved or permissions are insufficient. Cause: The host address in `PG_URL` or `MONGODB_URI` is not filled in correctly, or the service IP is not added to the database whitelist.
- Phenomenon: A syntax error is returned when executing multiple SQL statements. Cause: Multi-line query support for the database connection plugin is not enabled, and only single-statement execution is allowed by default.

## How to confirm that configurations are correct
- Access the database management panel, check for the presence of corresponding table structures including dataset version records and delivery checklists, and confirm that fields match daily document structures.
- Initiate a small-scale dataset export test, verify that the export granularity matches the business classification configuration, and confirm that exported file completeness aligns with the delivery checklist.
- Execute two or more SQL statements for testing, confirm that no syntax errors occur, and that the statements can execute normally to completion.
- Access the database connection monitoring panel, confirm that the current active connection count does not exceed the `DB_MAX_LINK` configuration value.

The values given are common starting points and should be measured against the reader's own samples.
