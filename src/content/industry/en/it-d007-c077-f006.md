# Online Fault Troubleshooting and Retrospective for Computer Room Inspection and Environmental Monitoring: Scheduled Tasks and Automation

## What data for this category looks like
This category's data mostly comes from four sources: environmental monitoring, access control systems, UPS monitoring, and video inspection. Update rhythms are split into real-time and daily. Daily retained documents include inspection reports, temperature and humidity records, alarm records, and duty logs. Fields cover device numbers, temperature and humidity values, alarm levels, inspection times, access control records, UPS voltage values, and more. Units include degrees Celsius, volts, entries, and others. The data focuses on the continuous operating status of existing computer rooms, and does not include operation records for hardware installation and cabling.

## What constraints these characteristics impose on scheduled tasks and automation
The data characteristics of this category create multiple constraints for scheduled task and automation configuration. First, update rhythms vary widely across multi-source data. Synchronization tasks for real-time data sources require high-frequency scheduling, while processing tasks for daily documents must match daily cycles to avoid data lag or resource waste. Second, daily documents have diverse fields and units. Automated processing needs pre-configured field mapping rules to ensure uniform formatting for inspection records and alarm information. In addition, abnormal alarm confirmation, on-site inspection records, and facility status handover are the most time-consuming steps. Automation must cover automatic flow for these steps to reduce manual operations. Finally, abnormalities can cause device downtime and customer SLA impact. A real-time alarm and retry mechanism must trigger after task failure to ensure stable data synchronization and processing.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Scheduled task scheduling cycle | Group by data source: set `10 seconds` for environmental monitoring, set `86400 seconds` for daily temperature and humidity inspection reports | Matches the real-time update rhythm of environmental monitoring and daily generation of daily reports, implemented using FastGPT v4.17.0 scheduling capabilities |
| Automation exception threshold | Temperature and humidity exceed `28 degrees Celsius`, UPS voltage deviates from `220±10 volts` | Complies with general standards for computer room environmental operation to avoid false triggers |
| Alarm trigger delay | More than `30 seconds` | Filters false alarms from instantaneous fluctuations to ensure alarm effectiveness |
| Task failure retry count | `3 times` | Balances resource consumption and task success rate, avoids invalid retries occupying system resources |
| Data synchronization batch size | Process the first `20 entries` of data per batch | Reduces single-task load and adapts to the interface bearing capacity of multiple data sources |
| Retrospective log retention period | `30 days` | Matches the industry-general retrospective document archiving period to meet fault troubleshooting needs |

## Three common mistakes
- Phenomenon: Empty records or connection timeouts return when calling environmental monitoring or UPS monitoring tools. Cause: The scheduled task scheduling cycle is set too long, exceeding the data source's update interval, resulting in failure to pull the latest data or connection timeout.
- Phenomenon: Automated inspection task status remains "pending" after execution. Cause: No retry mechanism is configured after task failure, and the task does not automatically restart after a single execution failure.
- Phenomenon: System lag occurs when batch synchronizing video inspection data. Cause: Per-batch synchronization data volume is set too large, exceeding the platform's interface processing limit.

## How to confirm the configuration is correct
- The platform's scheduled task logs are reviewed to confirm that each data source's synchronization frequency matches the configured scheduling cycle.
- A scenario where temperature and humidity exceed thresholds is simulated to verify normal triggering of the automated alarm and retry mechanism.
- Retrospective documents are exported to check whether fields match records from the original data sources.
- Task failure retry records are reviewed to confirm that the retry count meets the configured `3 times` requirement.
