# Online Fault Troubleshooting and Retrospective for Computer Room Inspection and Environmental Monitoring: Deployment and Upgrade

## What this category’s data looks like
The data for this category mainly comes from environmental and power monitoring systems, access control management systems, UPS monitoring equipment, and video inspection terminals. Four types of documents are produced regularly: inspection reports, temperature and humidity records, alarm records, and duty logs. Data is updated either in real time or once daily. Fields include device ID, monitoring values (such as ℃ for temperature and humidity, V for voltage), alarm level, timestamp, and operations staff identifier. No additional statistical quantitative indicators are included.

## What constraints these characteristics impose during deployment and upgrade
Data sources for this category are scattered and heterogeneous. During deployment, adaptation rules for multi-source data docking must be configured, and sufficient storage and cache resources must be reserved. Scenarios with real-time data updates require cache connection parameters adapted to high-frequency read and write operations. The connection pool upper limit corresponding to `REDIS_URL` must be set appropriately. The fixed document field structure requires strict adherence to preset field mapping logic during deployment, to avoid data loss caused by field incompatibility. During the upgrade process, the availability of core monitoring links must be prioritized, to avoid false alarm triggers or data interruptions caused by configuration changes.

## How to Configure Settings
These configuration items apply to the deployment of the computer room inspection and environmental monitoring module for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30 connections` | Connects to databases for multiple environmental and power monitoring devices, prevents connection exhaustion from affecting real-time data collection |
| `MONGODB_URI` | `mongodb://[username]:[password]@[host address]:[port]/fastgpt_monitor?authSource=admin` | Stores alarm records and inspection logs, requires specifying an authentication source and dedicated database to ensure data isolation |
| `REDIS_URL` | `redis://:[password]@[host address]:[port]/0` | Caches high-frequency data such as real-time temperature and humidity, access control status, to reduce query pressure on the primary database |
| `STORAGE_S3_ENDPOINT` | `Fill in according to the access endpoint provided by the local storage or cloud storage service provider` | Stores video inspection clips and historical alarm files, matches the access path of the storage medium |
| `FILE_TOKEN_KEY` | `32-bit random string calibrated through actual testing` | Encrypts access tokens for inspection files, prevents unauthorized access to sensitive monitoring data |
| `ROOT_KEY` | `Only used for internal operations configuration, not exposed externally` | Manages global deployment permissions, prevents unauthorized modification of core monitoring link configurations |

## Three Common Misconfigurations
- After deploying version v2, logs show `ocr error`, and device identifiers in video inspection frames cannot be parsed. The OCR recognition dependency library for video streams is not configured, or `FILE_TOKEN_KEY` is configured incorrectly, preventing the recognition model from loading.
- A database connection failure prompt appears after starting a newly deployed environment. The host address, port, or authentication information in `MONGODB_URI` or `REDIS_URL` is not filled in correctly.
- Temperature and humidity fields in inspection reports are empty after an upgrade. The field mapping rules are not updated, causing the newly deployed configuration to not match the field format of existing inspection documents.

## How to Verify a Successful Configuration
- Run container log query commands to confirm there are no error logs related to database connections.
- Submit a simulated inspection record, and check whether the corresponding file is generated in the specified storage path.
- Access the monitoring panel to check whether real-time data such as temperature and humidity, access control status is updated normally.
- Trigger a simulated alarm, and confirm that the alarm record is correctly written to the specified database.

The values provided are common starting points and should be measured against local deployment samples.
