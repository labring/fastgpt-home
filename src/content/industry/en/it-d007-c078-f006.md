# Cabinet Rack Installation and Cabling Online Fault Troubleshooting and Retrospective: Scheduled Tasks and Automation

## What the data for this category looks like
Data sources for this category include DCIM systems, asset management systems, network topology diagrams, and customer service work orders. Daily generated documents include cabinet rack installation application forms, cabling topology diagrams, port label comparison tables, and on-site construction records. Data is updated once per completed work order or synced daily. Fields include rack unit number, cable port number, device model, construction time, and others. Units are mostly physical position units (such as U positions), port numbers, length units, and similar. This covers physical access for new or modified devices, and differs from routine data center patrol work.

## What constraints these characteristics impose on scheduled tasks and automation
Due to scattered data sources covering multiple platforms such as DCIM and asset management systems, scheduled tasks require configured cross-system data pull logic. Pull intervals must be adjusted based on system response speeds to avoid excessive resource consumption. There are diverse document types, including tabular port label sheets and topological cabling diagrams, so automation workflows must adapt to parsing rules for different document types. Data updates change in real time as work orders are completed, so scheduled tasks need flexible scheduling triggered by work orders. The accuracy of physical fields directly determines troubleshooting results; automated verification links must strictly match unambiguous fields such as rack unit numbers and port numbers, and cannot tolerate approximate matching.

## How to set the configuration
This configuration is based on FastGPT v4.17.0

| Config Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Cross-system data pull interval | 300–600 seconds | Balances daily data updates and work order timeliness, avoids frequent pulls from consuming system resources |
| Task execution timeout | 120 seconds | Prevents single tasks from occupying queue resources for too long, ensures tasks complete on schedule |
| Document parsing trigger timing | Triggered after rack installation work order submission | Aligns with data update rhythm, ensures parsed data is synchronized with work order status |
| Port label verification rule | Exact match of port numbers | Physical access links have high requirements for field accuracy, fuzzy matching is not acceptable |
| Task failure retry count | 2–3 times | Addresses pull failures caused by temporary network fluctuations, avoids excessive resource usage from repeated executions |
| Abnormal alert trigger threshold | 2 consecutive verification failures | Notifies operation and maintenance personnel in a timely manner to handle exceptions, prevents delays in installation progress |

## Three common configuration mistakes
- Symptom: After a scheduled verification task runs, the port label matching result is empty, with no error logs. Cause: Permissions for cross-system DCIM data pulls are not configured, so the task cannot obtain the latest port number data.
- Symptom: After a scheduled task runs repeatedly multiple times, the parsing result of the cabinet cabling diagram contains duplicate entries. Cause: No task deduplication logic is set, so documents from the same work order are pulled and parsed multiple times.
- Symptom: After automated verification is triggered during the rack acceptance phase, the work order status is not updated synchronously, causing subsequent processes to block. Cause: No callback logic is configured to link to the asset system to update the work order status after the task completes.

## How to confirm the configuration is properly set up
- Manually trigger a scheduled task, and check if the pulled data includes all associated documents and system data for the current test work order.
- Submit a test rack installation work order to trigger the corresponding scheduled task, and confirm that the verification rule executes according to the preset exact matching logic.
- Simulate a data pull failure scenario, and confirm that the preset alert notification is triggered and the retry logic executes as configured.
- View task execution logs, and confirm that calls to all associated systems complete normally according to the configured interval and permissions.
