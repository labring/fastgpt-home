# Online Troubleshooting and Retrospective for Desktop Terminal Support: Deployment and Upgrade

## What the data for this category looks like
This data primarily comes from terminal management platforms, enterprise asset systems, frontline user trouble reports, and internal software repositories. Routinely stored documents include terminal trouble tickets, installation manifests, software installation records, and remote assistance session logs. Data is updated via daily batch synchronization or real-time updates per individual request. Fields include terminal unique identifiers, fault classifications, associated software versions, peripheral models, and processing statuses. Entries are only stored in accordance with operational workflows, with no fixed statistical thresholds.

## What constraints these characteristics impose on deployment and upgrade
Documents such as terminal trouble tickets and installation manifests are mostly tied to the local configuration of a single terminal. During deployment, ensure the service can pull a single terminal’s software version and peripheral information on demand, to avoid excessive resource usage from full synchronization. Scenarios with real-time data updates require deployed services to have low-latency response capabilities. During upgrades, reserve rolling update windows to avoid interrupting frontline operational workflows. The privacy of terminal asset data requires configuring strict access permissions during deployment to prevent sensitive information leaks. Additionally, differences in data formats from multiple sources require configuring unified data parsing rules during deployment to adapt to document structures exported by different systems.

## How to set the configurations
This configuration applies to FastGPT v4.17.0 and later.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:port/dbname?authSource=admin` | Adapts to persistent storage requirements for structured data such as terminal assets and trouble tickets |
| `REDIS_URL` | `redis://:password@host:port/0` | Used to cache real-time status and session data for single terminals, reducing repeated query overhead |
| `FE_DOMAIN` | `https://your-fastgpt-frontend-domain.com` | Configures the frontend access domain name to ensure that remote assistance session jump links can be accessed normally |
| `FILE_TOKEN_KEY` | `Randomly generated string of 32 or more characters` | Used to encrypt access tokens for files such as trouble tickets and installation manifests uploaded by terminals |
| `STORAGE_S3_ENDPOINT` | `http://your-s3-endpoint:port` | Stores file resources such as logs and installation packages generated during terminal operations |
| `DB_MAX_LINK` | `20–30 connections` | Adapts to concurrent query requirements in terminal operation scenarios, avoiding connection pool exhaustion |

## Three common mistakes
- Symptom: Installation manifests and trouble tickets uploaded by terminals cannot be parsed normally. Cause: `FILE_TOKEN_KEY` is not configured, or the key length is insufficient, causing file access token verification to fail.
- Symptom: Database connection failure error logs appear when the service starts. Cause: `MONGODB_URI` is configured incorrectly, with no correct authentication source or connection address specified.
- Symptom: Access exceptions occur after jumping to remote assistance sessions. Cause: `FE_DOMAIN` is configured as an internal network address, and the access domain name for external operation and maintenance personnel is not adapted.

## How to confirm the configuration is correct
- The FastGPT service startup script is executed, and the console output is checked for connection success logs for the database and cache service.
- A test installation manifest file is uploaded, and the terminal identifiers and software version information within the file are verified to be readable and parsable.
- The `FE_DOMAIN` configured for the frontend is accessed, and the remote assistance jump link is verified to open normally and load the corresponding page.
- The specified storage bucket is viewed, and operation logs, installation packages and other files are confirmed to have been successfully uploaded to the storage path corresponding to `STORAGE_S3_ENDPOINT`.

The values given are common starting points and should be measured against the reader's own samples.
