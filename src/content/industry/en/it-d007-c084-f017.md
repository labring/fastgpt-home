# Online Troubleshooting and Retrospective for Game Client Performance Optimization: Deployment and Upgrade
This page is compatible with FastGPT v4.17.0.

## What Data for This Category Looks Like
Data for this category primarily comes from game engine Profiler tools, online crash collection platforms, real-device test data, and frame rate statistics systems. Daily maintained documents include performance test reports, device model adaptation lists, optimization iteration records, and crash analysis reports. The data update frequency is daily or per version release cycle. Core fields include frame rate (fps), resource package size, resource loading time, device model identifiers, and crash stack information. Adaptation scope and performance indicators must be updated synchronously with version iterations.

## Constraints Imposed on Deployment and Upgrade
Data sources for this category are scattered and rely on real-device test environments. The deployment link must support multi-device performance data collection pipelines to avoid data collection failures due to environment differences. The data update frequency is daily or per version. During deployment, configure highly available storage and query pipelines to support high-frequency data writes. During upgrades, ensure data migration is uninterrupted and compatible with historical collection formats. Daily documents are strongly bound to performance data. During deployment, synchronously configure document association fields. During upgrades, ensure that old documents and newly deployed collection data logic are consistent to avoid disconnect between data and documents.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–200 connections` | Adapts to the high-frequency performance data write and query requirements of this category per daily/version cycle, prevents service interruptions caused by connection pool exhaustion |
| `MONGODB_URI` | Configure cluster address with read-write separation | Performance data for this category includes large volumes of time-series frame rate and crash logs. Read-write separation balances read and write loads and improves query efficiency |
| `REDIS_URL` | `1000 MB memory instance` | Temporarily caches real-device test data and optimization record association keys, avoids repeated database queries and reduces storage link pressure |
| `STORAGE_S3_ENDPOINT` | Configure storage endpoint in the nearest region | Real-device collected performance data needs to be quickly uploaded to storage nodes. Nearest nodes reduce upload latency and ensure data timeliness |
| `FILE_TOKEN_KEY` | Encryption key calibrated via actual testing | Protects upload permissions for performance test reports and crash logs, prevents unauthorized access leading to data leaks or tampering |
| `ROOT_KEY` | Configure independent administrator permission key | Deployment for this category requires strict separation of data collection and management permissions, prevents misoperations from affecting online performance data collection and analysis |

## Three Common Misconfigurations
- Symptom: Performance data reporting interface returns 403 Forbidden status code. Cause: `FILE_TOKEN_KEY` is not configured correctly, leading to failed upload permission verification.
- Symptom: Frame rate statistics query time exceeds expectations. Cause: `DB_MAX_LINK` is set too small, connection pool is exhausted and cannot handle concurrent query requests.
- Symptom: Crash analysis reports cannot be associated with the corresponding device model adaptation list. Cause: The management configuration corresponding to `ROOT_KEY` is not enabled, causing the document association logic to fail to load properly.

## How to Verify Proper Configuration
- Run a simulated real-device performance data upload test, confirm the interface returns a 200 status code, and verify that the `FILE_TOKEN_KEY` configuration matches the upload rules.
- Check the database connection pool monitoring dashboard, confirm that the active connection count does not exceed the `DB_MAX_LINK` setting, and verify the validity of the connection configuration.
- Attempt to associate an uploaded performance report with a device model adaptation list, confirm that the association logic triggers normally, and verify that the `ROOT_KEY` configuration is effective.
- Upload test performance data to the configured storage endpoint, confirm that the file can be read and downloaded normally, and verify that the `STORAGE_S3_ENDPOINT` configuration is correct.

The values provided are common starting points and should be measured against the reader's own samples.
