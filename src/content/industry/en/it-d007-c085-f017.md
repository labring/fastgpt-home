# Online Troubleshooting and Retrospective for Game Server Development and Operations: Deployment and Upgrade

## What this category’s data looks like
Daily documents for this category include server architecture descriptions, server launch plans, server merge plans, and fault reports. Data comes primarily from game runtime logs, online player count monitoring, player asset databases, and player feedback tickets. Data update frequency is typically daily or after major in-game events. Data fields include player unique identifiers, session latency, online peak counts, asset change records, and more. Units include milliseconds, concurrent player sessions, timestamps, and others.

## Constraints imposed on deployment and upgrade by these characteristics
Complex daily documentation requires traceable deployment configurations, to enable verification of deployment parameters during subsequent fault retrospectives. Integrating multiple data sources requires configuring connection parameters for multiple external services during deployment, to prevent data synchronization errors. Frequently updated business data requires upgrade processes to support gray release and rapid rollback, to reduce impact on online players. Player data errors can cause serious issues such as login failures and data rollbacks. During deployment, configure authentication parameters to secure interfaces, and reserve sufficient database connection resources to handle concurrent requests.

## How to set the configurations
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 100–200 connections | High concurrent request volume in game server operation and maintenance scenarios requires sufficient database connections to avoid timeouts |
| `MONGODB_URI` | Assemble according to the MongoDB instance address of the game server cluster, including read-write separation configuration and authentication information | Storing player save data and event data requires a highly available MongoDB cluster. The corresponding cluster address must be configured to ensure read-write performance |
| `REDIS_URL` | Configure the local area network Redis instance address, set a dedicated connection password | Cache online sessions and temporary server merge data. Low-latency network is required to ensure data read-write speed |
| `FE_DOMAIN` | Fill in the gateway domain name or local area network IP exposed by the game server | Front-end resource loading and interface requests must match the external access address to prevent cross-domain request blocking |
| `ROOT_KEY` | Generate a 32-bit random string | Used for background management interface authentication, to eliminate default weak password risks after deployment |

## Three common mistakes
- Connection failure for the 192.168 network segment, page fails to load. Cause: `FE_DOMAIN` is not configured to a locally accessible IP or domain name, or the inbound rules for the corresponding server port are not opened.
- A default promotion QR code appears at the bottom of the page after deployment, and cannot be hidden via the interface. Cause: Default static resource configuration is not replaced, or the built-in promotion component is not disabled.
- Database connection limit alarms occur during cluster deployment, and player login requests time out. Cause: The `DB_MAX_LINK` configuration value is not adjusted based on the number of cluster nodes, resulting in insufficient connections per node.

## How to confirm the configuration is correct
- Run a local curl command to access `127.0.0.1:3000` and the configured local area network IP, confirm the page loads normally with no cross-domain error prompts.
- Use the generated `ROOT_KEY` to call the background management interface, confirm authentication is successful and the configuration page can be accessed.
- Check database connection logs, confirm the current connection count does not reach the `DB_MAX_LINK` configuration threshold.
- Inspect the front-end static resource directory, confirm the default promotion QR code file has been replaced or removed.

The values provided are common starting points and should be measured against the reader's own samples.
