# Online Troubleshooting and Post-Mortem for Game License and Publication Declaration: Database and Operations

## What the data for this category looks like
Daily data for this category includes declaration request documents, game application forms, copyright certificates, review reports, and more. Data sources cover official government service platforms, copyright registration systems, game installation packages, and operator materials. Data is generated per individual game declaration project, with an irregular update frequency adjusted dynamically alongside preliminary review modification workflows. A single set of declaration data includes structured fields such as declaration ID and copyright registration number, plus unstructured review report text. The overall data structure improves gradually as the declaration process advances.

## What constraints these characteristics create for database and operations work
Multi-source data access requires the database to support cross-system synchronization and compatible mixed structured and unstructured storage modes. Single-project data grows dynamically with workflows and has no fixed update cycle, so a dynamically adaptable connection pool must be configured to avoid resource exhaustion. The material consistency check step has strict real-time data requirements, so query response speed must be maintained. Data errors will directly lead to approval rejection, so strict data consistency must be enforced, and dirty data must be blocked from entering the workflow.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| ---|---|--- |
| `PG_URL` | `postgresql://username:password@host:5432/fastgpt_game_approval` | Stores structured declaration forms and approval records, leverages PostgreSQL's transaction consistency features, and is compatible with FastGPT v4.17.0 database integration logic |
| `MONGODB_URI` | `mongodb://username:password@host:27017/fastgpt_game_docs` | Stores unstructured documents such as review reports and copyright certificates, supports flexible document schemas |
| `DB_MAX_LINK` | `15–25 connections` | Adapts to the resource limit of an 8-core 16-gigabyte host, avoids exhausting memory from too many connections, and is calibrated via actual testing |
| `REDIS_URL` | `redis://:password@host:6379/0` | Caches declaration status and retrieval results to speed up cross-process data queries |
| Reranking | `Top 3–5 results` | The number of declaration-related documents is limited; excessive reranking increases response latency |
| Query Optimization | Calibrated via actual testing | Must match the semantic characteristics of declaration documents, avoid over-optimization that deviates from business content |

## Three Common Misconfigurations
- Symptom: Knowledge base index creation fails when PostgreSQL is deployed via Docker, with connection timeout errors in logs. Cause: The `PG_URL` configuration does not point to the game declaration dedicated database, and `DB_MAX_LINK` is set too low, causing the connection pool to be exhausted.
- Symptom: The service fails to start after changing the database password, with an authentication failure error. Cause: The password parameters in `PG_URL` and `MONGODB_URI` were not updated synchronously.
- Symptom: Single-query response time exceeds 30 seconds after enabling query optimization and reranking. Cause: The reranking configuration is set to `Top 10+ results`, and `DB_MAX_LINK` was not adjusted to accommodate high-concurrency retrieval requests.

## How to Verify the Configuration is Correct
- Run a database connection test script to verify that `PG_URL` and `MONGODB_URI` can establish normal connections, with no authentication or network errors.
- Submit a test declaration document, monitor the index creation progress, and confirm there are no timeout or failure logs.
- Enable query optimization and reranking functions, test single-query response time, and confirm it meets the expected business threshold.
- After adjusting the `DB_MAX_LINK` parameter, check host memory and CPU usage to confirm the number of connections does not exceed the resource limit.

The values provided are common starting points and should be measured against the reader's own samples.
