# Online Troubleshooting and Post-Incident Review for Game License and Publication Declaration: Deployment and Upgrade

## What this category’s data looks like
Data for this category is generated around the publication approval process for a single game. Core sources include the national press and publication administration work service platform, copyright registration systems, game package files, and business materials submitted by operating institutions. Daily generated documents include declaration request files, game application forms, copyright certification documents, and review reports. Data update rhythm is adjusted irregularly alongside the declaration process for a single game, with one full round of data updates completed once the entire declaration process for a game is finished. Data fields include game name, copyright holder information, declaration subject qualification, review conclusion, and other items. There is no unified fixed batch update cycle requirement.

## What constraints do these characteristics impose on deployment and upgrade
Data sources for this category are scattered, and update rhythms advance irregularly alongside single-game declaration processes. The deployment link must configure a stable cross-source data storage and caching link to avoid synchronization interruptions that impact real-time access to declaration materials. Daily document formats are diverse, and fields must strictly match approval requirements. Deployment must reserve configuration space for custom document verification to adapt to material specifications for different declaration stages. Approval errors for a single game will directly cause launch delays. The upgrade link must ensure data read-write consistency and rapid fault rollback capabilities to avoid declaration material data anomalies caused by configuration changes. Additionally, since data updates have no fixed cycle, post-deployment support is required for on-demand triggered incremental data synchronization to avoid excessive system resource usage from full updates.

## How to set configurations
This document is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:port/dbname?authSource=admin` | Stores metadata for declaration documents and review reports. Requires correct authentication information and database name to ensure persistent storage of multi-source data |
| `REDIS_URL` | `redis://:password@host:port/0`, set cache expiration time to `600 seconds` | Caches real-time synchronized game packages and operating institution materials, adapts to irregular data update rhythms, and avoids delays from frequent reads of external systems |
| `DB_MAX_LINK` | `20–30 connections` | Limits the maximum number of connections in the database connection pool, avoids excessive server resource usage when multiple declaration projects send requests simultaneously, and sets the connection upper limit based on actual measurements |
| `STORAGE_S3_ENDPOINT` | `Fill in according to the object storage service provider address of the deployment environment`, set single file maximum size to `1000 MB` | Stores game packages and large-volume review report files. Must match the endpoint address of the storage service provider to ensure secure upload and download of large-volume files |
| `FE_DOMAIN` | `https://your-deployment-domain.com` | Configures the frontend access domain name, used to generate preview links for declaration documents, ensuring approval departments can normally access material files |
| `FILE_TOKEN_KEY` | `Randomly generated string of 32 or more characters` | Used to generate temporary tokens for file access, ensures access permission security for declaration documents, and avoids unauthorized access |

## Three common misconfigurations
- Symptom: A "database connection failed" error pops up when creating a new declaration application after deployment. Cause: The `MONGODB_URI` parameter is not correctly configured, with incorrect database authentication information or database name filled in.
- Symptom: After enabling the incremental data synchronization switch, updated game package content is not displayed normally. Cause: The `REDIS_URL` parameter is not correctly configured, causing the synchronization task status cache to be lost, and the configuration item does not actually take effect.
- Symptom: After deployment and upgrade, the custom field verification function for declaration documents does not work. Cause: No verification configuration items adapted to the approval requirements of this category are reserved, and no verification rule configuration is performed for the fixed fields of declaration documents.

## How to confirm configurations are correct
- Execute the database connection test command to verify whether the `MONGODB_URI` configuration is correct, and confirm normal read and write access to declaration document metadata.
- Upload a test game package file to verify whether the `STORAGE_S3_ENDPOINT` configuration functions normally, and confirm normal file upload and download.
- Access the address configured for `FE_DOMAIN`, confirm normal loading of the frontend page, and confirm that valid preview links for declaration documents can be generated.
- Initiate a simulated incremental data synchronization task to verify whether the `REDIS_URL` cache configuration functions normally, and confirm that synchronization task statuses can be correctly recorded.
