# On-site Deployment Implementation: Online Troubleshooting and Retrospective — Conversation Logs and Auditing

## What this category of data looks like
This data primarily originates from customer data center environments, device inventories, software packages, and network topologies. Daily associated documents include deployment manuals, installation records, configuration lists, and on-site check-in sheets. These documents are updated per deployment or phase by implementation engineers, system engineers, and customer IT staff during on-site deployment.

Data is generated around the execution process of a single on-site deployment. It includes configuration information of deployment nodes, installation step records, on-site environment verification results, and associated identifiers for corresponding work orders. There are no additional derived statistical fields. Data is retained only in accordance with the execution rhythm of a single deployment.

## What constraints these characteristics impose on the conversation logs and auditing workflow
Data sources are scattered across multiple on-site customer entities and documents. Conversation logs must be associated with the unique identifier of the corresponding deployment work order to avoid cross-work order log confusion.

Update frequency aligns with the single deployment cycle. Log retention must match the nodes of the deployment phase; archiving cannot be done early or delayed.

The binding relationship between daily documents and logs requires the auditing workflow to quickly retrieve associated files such as deployment manuals and installation records. Log fields must include basic information such as deployment nodes, operators, and execution times to adapt to the small-batch, multi-work order scenario of on-site deployment.

Additionally, there are no standardized statistical fields for the data. The auditing workflow must retain the complete link of original operations, and log content cannot be arbitrarily deleted.

## How to configure parameters
For the conversation logs and auditing workflow of on-site deployment implementation, configure the following parameters based on the characteristics of this category of data. This guidance is formulated for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique identifier of the on-site deployment work order | Matches the per-order update data characteristic to achieve precise association between logs and corresponding deployment work orders |
| `responseChatItemId` | Store the log entry ID for single-step deployment operations | Adapts to the phased execution logic of on-site deployment, facilitating fault backtracking by step |
| `detail` | Fully record the original output content of on-site environment verification and software installation | Aligns with the characteristic that on-site deployment data has no standardized fields, retaining complete auditing basis |
| Log retention period | Deployment duration + 30 days | Matches the update frequency per order/phase, meeting the audit traceability requirements of on-site deployment |
| Associated document index | Bind file paths of deployment manuals and installation records | Aligns with the business requirement of binding daily documents and logs, enabling quick retrieval of associated materials |

## Three common configuration mistakes
- Symptom: When calling the API, conversation logs only display title content, with no complete operation records. Cause: The full output switch for the `detail` parameter is not configured, only the log summary field is retained, which does not meet the requirement of fully retaining original output for on-site deployment.
- Symptom: Logs across deployment work orders cannot be distinguished, and log entries from unrelated work orders appear during retrieval. Cause: The `chatId` is not bound to the unique identifier of the deployment work order, leading to chaotic log association, which does not conform to the data characteristic of order-based management.
- Symptom: Conversation logs cannot be associated with the corresponding deployment manual or installation record. Cause: The binding logic for the associated document index is not configured, and no corresponding relationship is established between logs and daily documents, failing to meet the audit traceability requirements of on-site deployment.

## How to confirm correct configuration
- Retrieve logs for a specified `chatId`, confirm that all associated deployment operation records are correctly included.
- View single-step deployment log entries, confirm that the `detail` field contains complete original output of on-site environment verification and software installation.
- Verify the binding relationship between logs and deployment manuals, installation records, confirm that corresponding documents can be quickly retrieved via logs.
- Validate that the log retention period matches the set value of deployment duration plus a reasonable buffer period.

The values listed above are common starting points, and should be evaluated against the reader's own operational samples.
