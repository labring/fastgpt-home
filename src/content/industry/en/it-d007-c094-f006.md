# Online Troubleshooting and Retrospective for User Acceptance Testing Support: Scheduled Tasks and Automation

## What the data for this category looks like
The data sources for this category are requirement specifications, test environments, customer business samples, and defect systems. The update frequency is per phase or per version. Daily produced documents include UAT test cases, acceptance issue tickets, acceptance reports, and signed confirmation documents. UAT test cases contain fields for test scenarios, expected results, and actual results. Acceptance issue tickets include fields for issue number, reproduction steps, and severity. Data formats are maintained jointly by implementation consultants, test managers, and customer business representatives based on business scenarios.

## What constraints do these characteristics impose on scheduled tasks and automation?
The data characteristics of this category impose multiple constraints on the scheduled tasks and automation link. First, fixed data sources require that the data source configuration for scheduled tasks strictly corresponds to requirement specifications, test environments, customer business samples, and defect systems. Non-business-related data sources must not be arbitrarily introduced. Second, the update frequency per phase or per version requires that the scheduled task trigger cycle matches version releases or UAT phase nodes. Avoid overly frequent or delayed triggers. Third, the most time-consuming links: test case preparation, issue reproduction, and classification require that the data volume processed by a single scheduled task is controlled within a reasonable range. Excessive resource occupation must be avoided. Finally, the consequences of errors include acceptance delays, delayed final payments, and scope disputes. This requires that scheduled tasks are configured with failure retry and alert mechanisms to ensure that exceptions are identified in a timely manner.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Task trigger cycle | 1 day before version release, or 2 hours before UAT phase end | Matches the update rhythm per phase or per version, reserves time for test case preparation and issue reproduction |
| Synchronized data source scope | Only include requirement specifications, test environments, customer business samples, and defect systems | Strictly corresponds to the fixed data sources of the category |
| Single processed data entry count | Top 200 UAT test case entries | Adapts to the time limit of the test case preparation link, avoids resource overload |
| Failure retry count | 3 retries, 600-second interval | Addresses temporary unavailability of defect systems, ensures data synchronization success rate |
| AI dialogue node output rule | Only return execution results, hide debug output | Adapts to the requirement of only needing results in UAT acceptance scenarios, avoids output interfering with the acceptance process |
| Nested workflow popup rule | Show popups only when triggered by an independent workflow | Adapts to the independent operation scenario of UAT acceptance, avoids popup interference during nesting |

## Three common misconfigurations
- Phenomenon: When debugging the AI dialogue node for UAT acceptance, output content is written to the dialogue return panel. Cause: The AI dialogue node output hiding rule is not configured, so results are not blocked.
- Phenomenon: Manually inserted knowledge base indexes are lost after scheduled task execution. Cause: The rule for regularly cleaning expired temporary indexes is not configured. The system automatically overwrites manually inserted indexes.
- Phenomenon: Popups are not hidden for UAT acceptance nodes nested in other workflows. Cause: The popup hiding rule for nested workflows is not configured. The popup trigger logic does not distinguish between independent and nested scenarios.

## How to confirm the configuration is correct
- Log in to the FastGPT v4.17.0 scheduled task management page, check whether the task trigger cycle matches 1 day before version release or 2 hours before UAT phase end.
- Manually trigger a test synchronization task, check whether the generated UAT test case document fields completely match the configured data source fields.
- After configuring the AI dialogue node output hiding rule, trigger debugging, check whether only execution results are retained in the output.
- Simulate a nested workflow triggering the UAT acceptance node, check whether popups are hidden.
