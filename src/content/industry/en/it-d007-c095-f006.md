# Online Fault Troubleshooting and Retrospective for Monitoring Alert Configuration: Scheduled Tasks and Automation

## What the data for this category looks like
Data sources for this category include Prometheus, Zabbix, cloud monitoring, application logs, and CMDB. Update frequency is daily or after each alert rule change. Daily maintenance documents include monitoring metric lists, alert rules, on-duty manuals, and alert change records. Data fields include metric name, threshold range, alert trigger condition, notification recipient, change time, and associated resource ID. Units include seconds, entries, characters, and other common units. Field formats vary slightly across different data sources.

## What constraints these characteristics impose on scheduled tasks and automation workflows
Diverse data sources and inconsistent formatting mean scheduled tasks must standardize parsing rules for multi-source data. This prevents field mismatch issues.
Alert data updates daily or after each rule change. Scheduled task execution cycles must align with this update rhythm. Do not run tasks too frequently to waste compute resources, and do not run them too slowly to avoid outdated alert information.
Additionally, configuration validation must trigger after alert rule changes. This ensures updated rules function correctly. Noise cleanup and notification link verification must run regularly via scheduled tasks. This maintains stability of the overall alert system.

## How to configure settings
This guide is compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Scheduled task execution cycle | 300 seconds-3600 seconds | Match alert data update frequency, balance data timeliness and resource consumption |
| Alert data pull scope | Records from the previous 1 change cycle | Cover the latest alert rule changes and metric data, reduce loading of invalid historical data |
| Alert noise filtering threshold | 3 consecutive triggers | Filter false positives from temporary fluctuations, avoid disrupting on-duty personnel |
| Notification link verification frequency | Once daily | Ensure alert notification reachability, detect link failures promptly |
| Configuration validation trigger timing | After each alert rule change | Validate updated configurations in a timely manner, avoid potential fault risks |

## Three common configuration errors
- Auto-marking of conflicting fields across multi-source alert data is disabled. Symptoms: Field inconsistencies appear when comparing alert rules from different sources, but no highlighting is displayed. Cause: Scheduled document conflict analysis tasks are not enabled.
- Active message sending to WeChat Work external groups fails. Symptoms: Calling the send API returns a permission error. Cause: Message sending whitelist verification for external groups is not configured.
- Alert noise cleanup configuration does not take effect. Symptoms: Redundant alerts continue to be pushed. Cause: The scheduled task execution cycle is set too long, failing to clean up new noise alerts in a timely manner.

## How to confirm successful configuration
- View scheduled task execution logs to confirm the number of recently pulled alert data falls within the expected range.
- Manually modify one alert rule, wait for the validation task to trigger, then check if a corresponding change validation record is generated.
- Simulate triggering an alert metric that meets the threshold, verify that alert notifications are sent normally to the specified link.
- Check the output of the conflict analysis task, confirm that conflicting fields across multi-source alert data are correctly marked.
