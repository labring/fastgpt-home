# Online Troubleshooting and Retrospective for Cybersecurity Level Protection Assessment Consulting: HTTP Interfaces and External Systems

## What this category of data looks like
Core data for cybersecurity level protection assessment consulting comes from assessment tools, interview records, system inventories, and security device logs. The update frequency is once per project. Daily produced documents include classification determination reports, gap analysis reports, rectification plans, and assessment reports. Data fields revolve around level protection control items, rectification evidence, and system assets. There are no unified global fields, and data must be sorted out individually for each single project. The core work links of this category are classification determination material sorting, control item gap verification, and rectification evidence collection. Data correlation carries high risks. Any data deviation may lead to assessment failure or regulatory inspection risks.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
Since data is updated independently per project and carries regulatory risks, interfaces must support data isolation by project dimension to prevent cross-project data leaks. Multi-source data sources require interfaces to adapt to logs and system inventories in different formats, and provide flexible field filtering and parsing rules. Core documents rely on structured control item and rectification data. Interface responses must only include fields necessary for business purposes to reduce redundant data transmission. High-risk attributes require interfaces to have stable failure handling mechanisms to lower manual intervention costs, while also adapting to custom configurations of internal assessment tools.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {Exclusive Assessment Project Token}` | Cybersecurity level protection assessment data involves sensitive regulatory information. Using project-exclusive authentication tokens enables data isolation and prevents cross-project permission leaks |
| Request Timeout | `300-600 seconds` | A single request may retrieve large volumes of system inventory or log entries. Allowing sufficient response time accommodates large-volume data transfers |
| `responseData` | Only return fields containing control item ID, rectification status, and asset number | Matches the core field requirements of daily documents, filters redundant content to reduce transmission costs, and improves data organization efficiency |
| `variables` | Bind two global variables: project number and assessment cycle | Automatically adapts interface request paths and return parsing rules for different projects, eliminating the need to configure interface parameters individually for each project |
| Retry Policy | Retry 2 times after failure, with a 60-second interval | Addresses request failures caused by temporary collection delays from assessment tools, reducing the workload of manual troubleshooting and intervention |

## Three common mistakes
- An interface request returns a `self-signed certificate` error. This occurs when the custom SSL certificate of the internal assessment tool has not been imported into FastGPT. Most internal tools in level protection scenarios use self-signed certificates. Failure to add these certificates to trusted lists will block data retrieval.
- An interface request returns a `404 page not found` error. This occurs when the project number variable in `variables` is not bound. Using a fixed global path to send requests will not match the exclusive interface address for different projects.
- Interface response data includes redundant fields. This occurs when the filtering rule configured in `responseData` is not applied, and log detail fields unused in daily documents are returned. This requires additional data cleaning when organizing subsequent classification determination reports.

## How to confirm configurations are correct
- A single interface request is sent to verify that `Authorization` authentication takes effect, and the returned data only includes the core fields specified in the configuration.
- The custom SSL certificate is imported, then the request is resent to confirm that the `self-signed certificate` error no longer appears.
- The project number variable bound in `variables` is switched to verify that the interface request path updates automatically, and the returned data adapts to the new project rules.
- A request failure scenario is simulated to verify that the system automatically retries after a 60-second interval, and the request succeeds after 2 retries.
- Current usage of FastGPT v4.17.0 is confirmed, to ensure that the parsing logic for configuration items is compatible with the current version.
