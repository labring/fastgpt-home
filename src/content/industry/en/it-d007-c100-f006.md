# Online Troubleshooting and Retrospective for Classified Protection Assessment Consulting: Scheduled Tasks and Automation

## What the data for this category looks like
The core data for classified protection assessment consulting is generated across the full lifecycle of classified protection assessments. Sources include system asset data collected by assessment tools, interview records, manually compiled system inventories, and security device logs. Daily deliverable documents include classification reports, gap analysis reports, rectification plans, and assessment reports. Data updates follow individual project cycles; annual projects require full data retrospective updates. Data fields include control item matching results, rectification evidence numbers, system compliance status, and other related items. There are no unified fixed units, with values adjusting dynamically based on document type.

## What constraints do these characteristics impose on scheduled tasks and automation
The data characteristics of this category impose three constraints on the scheduled tasks and automation link: First, data sources include mixed formats from manual entry and tool collection, so multi-source data pulling and format adaptation must be supported to prevent task interruptions due to format incompatibility. Second, data updates follow individual project cycles; annual projects only require annual retrospective updates, so the scheduled task trigger frequency must match the project rhythm and avoid excessive resource occupation from overly frequent runs. Third, core time-consuming links require automated assistance; scheduled tasks must cover batch processing of classification material compilation, control item gap verification, and rectification evidence collection to reduce manual repetitive operations.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Task trigger interval | `every 12-24 hours` | Data updates follow project cycles. Frequent triggers generate redundant data, while lower frequency aligns with the retrospective rhythm of annual projects |
| Data source pull scope | Current project-associated system inventories and security device logs | Data for this category is only generated around the current assessment project, so there is no need to pull all historical data |
| Task retry count | `2-3 times` | Data sources may experience temporary network fluctuations; a small number of retries prevents task interruptions from single failed runs |
| Alert trigger threshold | 2 consecutive execution failures | Errors in this category of data can lead to assessment failure, so responsible parties must be notified promptly for troubleshooting |
| Task execution window | Non-working hours (such as 22:00–6:00 the next day) | Daily assessment work occupies working hours, so avoiding task execution during this period prevents system resource contention that disrupts manual operations |
| Field mapping rule | Match rectification evidence fields by control item number | Daily documents must be organized by classified protection control item categories; unified field mapping simplifies subsequent retrospective work |

## Three common misconfigurations
- Symptom: After adding a custom classified protection data pull plugin, no input or output parameters are displayed in the workflow task, and no error logs are generated. Cause: The field structure of the assessment document was not correctly mapped in the plugin configuration, causing the system to fail to recognize parameter definitions.
- Symptom: Executing the scheduled upgrade script returns the `POST /api/admin/initv4818 404` error. Cause: The FastGPT version does not match the upgrade script, and the upgrade command was not executed in the deployment directory corresponding to the correct version.
- Symptom: Setting an overly short trigger interval (such as 3000 milliseconds) when creating a scheduled task, leading to excessive system resource occupation. Cause: The update rhythm of this category of data was not matched; overly short intervals generate large amounts of redundant data and repetitive operations.

## How to confirm the configuration is correct
- For FastGPT v4.17.0, manually trigger a scheduled task, view the workflow execution logs, and confirm that no errors occur during the data source pull, format adaptation, and field mapping stages.
- Check the task trigger records to confirm that document fragments meeting the current project requirements were automatically generated within the set execution window.
- Verify the alert function: manually simulate a task execution failure, and confirm that the corresponding responsible party receives a notification.
- Cross-check the document fields output by the task to confirm that they correspond one-to-one with the control items and rectification evidence of the current assessment project.
