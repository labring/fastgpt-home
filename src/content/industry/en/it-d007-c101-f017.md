# Online Troubleshooting and Retrospective for Renewal Health Management: Deployment and Upgrade

## What the data for this category looks like
Core data for renewal health management originates from CRM systems, product usage logs, service ticket statistics, and contract ledgers. Daily generated documents include customer health reports, renewal forecast sheets, high-risk customer lists, and communication minutes. Data is updated weekly or monthly.
Data fields include customer unique identifiers, contract cycle milestones, monthly active counts, ticket response times, and renewal intent ratings. There are no unified fixed units, and configurations must be adapted to specific business scenarios.

## What constraints these characteristics impose on deployment and upgrades
Since data sources are scattered and updates are not real-time, configure retry mechanisms for multi-data-source synchronization during deployment to avoid single-pull timeouts.
During upgrades, retain compatible configurations for old data synchronization rules to prevent core report loss from weekly or monthly task interruptions.
Field differences across multiple document types require dynamic field mapping rules during deployment to adapt to output formats for different business scenarios.
Additionally, since risk identification errors directly impact customer retention and revenue plans, configure pre-checks for data validation before upgrades to ensure field completeness and format compliance.

## How to configure settings
The following configurations apply to the renewal health management module deployment and upgrade for FastGPT v4.17.0:

| Config Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–200 connections` | Adapt to concurrent connection requirements for multi-data-source synchronization, avoid connection pool exhaustion |
| `MONGODB_URI` | Assemble standard connection string per business cluster nodes | Non-relational database storing customer contract and ticket data, must point to a dedicated business cluster |
| `REDIS_URL` | Bind dedicated network segment on internal port 6379 | Cache intermediate results of customer health calculation, must ensure low latency and access security |
| `STORAGE_S3_ENDPOINT` | Use endpoint address provided by regional storage service provider, bind 1000–2000 GB storage quota | Store exported files of customer health reports and historical ticket attachments, adapt to cross-region backup requirements |
| `FE_DOMAIN` | Bind dedicated business secondary domain | Provide front-end visualization interface for renewal health management, must isolate from internal system domains to ensure access security |
| `ROOT_KEY` | Configure prefix string for model service provider authorization keys | Authenticate third-party service requests such as Reranker models, prevent unauthorized calls |

## Three Common Mistakes
- Phenomenon: After deployment, the SaaS FLUX plugin fails to operate normally, parameter configuration is correct but no return results are generated. Cause: The plugin-specific access key is not bound in the `FILE_TOKEN_KEY` configuration, causing authentication failure.
- Phenomenon: After importing the knowledge base, the system does not automatically select the knowledge base in the target JSON file, and the dropdown menu is empty. Cause: The knowledge base metadata storage address is not associated via `PG_URL`, causing metadata loading failure.
- Phenomenon: When pulling the Reranker model, a prompt indicates the ACCESS Token is invalid or not found. Cause: The model service provider's authorization key is not configured in the `ROOT_KEY` configuration, causing the request to be blocked.

## How to Confirm Configuration is Complete
- Run the multi-data-source synchronization scheduled task, check that the task log has no connection exceptions or data pull failure records.
- Access the front-end page bound to `FE_DOMAIN`, confirm that the interface display language matches business configuration requirements.
- Import a test knowledge base file, check that the knowledge base selection dropdown menu loads normally with no null values.
- Call the FLUX plugin and Reranker model test interfaces, confirm that returned results meet expectations, with no authentication failure or parameter mismatch errors.
