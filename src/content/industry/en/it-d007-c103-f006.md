# Online Troubleshooting and Retrospective for Art Asset Production Management: Scheduled Tasks and Automation

## What data for this category looks like
Data for this category primarily comes from art asset libraries, project management systems, engine resource packages, and outsourced delivery packages. Daily produced documents include art requirement sheets, asset specification sheets, outsourced feedback sheets, and acceptance records. Fields include asset unique identifiers, version numbers, delivery times, specification parameters, acceptance status, and more. Data update frequency is typically daily or weekly, and single asset package sizes range from tens of MB to several GB.

## What constraints these characteristics impose on scheduled tasks and automation
Multi-source data sources require tasks to support cross-system data pulling and unified formatting to avoid data silos. Daily or weekly update frequencies require task scheduling to align with business rhythms, avoiding excessive system resource usage. Field differences across document types require differentiated validation rules to be configured per document type. The large size of asset packages requires controlling resource consumption per single processing operation during chunked handling, to prevent performance issues or task timeouts.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Task trigger cycle | 2 AM daily, or set according to project update rhythms | Aligns with the daily or weekly update frequency of art assets, avoids frequent data pulling that consumes system resources |
| Data source pull scope | Only data from art asset libraries and project management systems associated with the current project team | Filters irrelevant data to reduce task processing volume |
| Data chunk size | `800–1200 characters` | Adapts to the single-row column content length of Excel source data, avoids excessive chunk sizes that lead to high resource consumption |
| Resource matching validation threshold | `Resource matching degree ≥95%` | Meets the strict requirements for asset specifications, prevents resource mismatch issues |
| Failure retry configuration | Retry 2 times, interval `600 seconds` | Addresses task failures caused by temporary network fluctuations or high system load |
| Alert trigger condition | 2 consecutive task failures | Notifies relevant personnel in a timely manner to handle exceptions |

*Note: This configuration applies to FastGPT v4.17.0*

## Three common misconfigurations
- Symptom: After a scheduled task runs, the knowledge base does not sync updated content, and when the corresponding conversation is reopened, historical reply content is empty. Cause: Task result persistent storage is not configured, or the conversation record saving action is not bound.
- Symptom: Tasks time out when processing Excel-format asset specification sheets. Cause: The data chunk size is set to more than `1500 characters`, exceeding the system's single-processing resource limit.
- Symptom: Automated validation is not triggered after an outsourced delivery resource package is uploaded. Cause: Only fixed-time task triggers are configured, and rules for triggering based on resource package suffixes are not added.

## How to confirm proper configuration
- Manually trigger a scheduled task, check whether there are pull and processing records for the corresponding data source in the task logs.
- Upload a test art requirement sheet document, confirm that the task generates corresponding validation results and syncs them to the knowledge base after execution.
- Simulate a task failure scenario, such as disconnecting a temporary data source connection, check whether the preset alert notification is triggered.
- Check the split asset specification content in the knowledge base, confirm that it meets the preset chunk size requirements.

The values provided here are common starting points, and should be evaluated against your own specific samples.
