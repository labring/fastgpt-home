# Online Troubleshooting and Retrospective for Speech Annotation and Transcription: Deployment and Upgrade

## What Data Looks Like for This Category
The data for this category primarily comes from audio files awaiting annotation, annotation job platforms, custom vocabularies, and sampling inspection samples. Daily associated documents include transcription specifications, audio delivery lists, quality inspection reports, and speaker annotation tables.
Data updates follow per-batch tasks or daily synchronization. Fields include audio duration, transcribed text, annotator ID, quality inspection results, and speaker differentiation tags. No unified fixed units exist. Values adjust flexibly based on annotation task types.

## What Constraints These Characteristics Impose During Deployment and Upgrade
This category’s data relies on multi-source inputs. Stable external storage and database connections must be configured during deployment. This ensures uninterrupted synchronized pulling of audio files, annotation platform data, and vocabularies.
The daily or per-batch data update rhythm requires upgrade processes to support incremental synchronization and gray release. This avoids service interruptions and delivery delays caused by full data migration.
Diverse associated documents and flexible annotation fields require deployments to configure adjustable metadata storage rules. These rules adapt to field changes across different annotation tasks.
Incorrect annotation data causes training deviations and rework. Upgrade processes must reserve configuration space for rapid rollback. This ensures the scope of fault impact remains controllable.
Additional adaptation for multi-source data batch pulling logic is required for the FastGPT v4.17.0 deployment package.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `200–300` | Speech annotation tasks require frequent read/write operations for annotation data and quality inspection reports. A reasonable connection pool upper limit prevents database connection exhaustion. |
| `STORAGE_S3_ENDPOINT` | The dedicated endpoint provided by the object storage service provider | Audio files and annotation documents are stored via object storage. Correct endpoints ensure stable upload and download of large files. |
| `REDIS_URL` | A dedicated cache instance address, with connection timeout set to `300 seconds` | Used to cache vocabularies and real-time annotation progress. The timeout setting prevents cache requests from blocking the main service. |
| `FE_DOMAIN` | The frontend access domain name for the deployed service | Used to generate time-limited file access links. This ensures annotators can normally access audio and document resources. |
| `FILE_TOKEN_KEY` | A randomly generated key with 32 or more characters | Used to encrypt file access tokens. This prevents unauthorized users from accessing annotation-related audio and documents. |
| `PG_URL` | A PostgreSQL instance address that supports large field storage | Used to store long-text transcribed content and complex speaker annotation metadata. |

## Three Common Mistakes
- Symptom: Calling associated plugins only outputs XML or JSON code blocks, and does not render visual charts. Cause: Cross-origin access permissions are not enabled in the `FE_DOMAIN` configuration. This prevents the frontend from loading static resources required for chart rendering.
- Symptom: Unable to retrieve arm64 architecture version packages when pulling deployment images. Cause: The architecture parameter is not specified in the pull command, and the image repository does not support the FastGPT v4.17.0 arm64 architecture image.
- Symptom: The version number displayed on the frontend page after upgrade does not match the actual deployed version. Cause: Frontend static resources are not synchronized for update. Only the backend service package is replaced.

## How to Confirm Proper Configuration
A database connection test script is run. The connection pool configured via `DB_MAX_LINK` is verified to handle concurrent annotation data read/write requests normally.
A test audio file is uploaded. Upload and download operations are completed via the storage service configured with `STORAGE_S3_ENDPOINT`. Confirmation that the file access link works correctly is obtained.
The frontend service is started. The access address configured via `FE_DOMAIN` is accessed. Verification that annotation documents and audio resources load and display normally is completed.
An incremental data synchronization task is triggered. Confirmation that the cache service configured via `REDIS_URL` can normally cache vocabulary and real-time annotation progress data is obtained.

The values given are common starting points and should be measured against the reader's own samples.
