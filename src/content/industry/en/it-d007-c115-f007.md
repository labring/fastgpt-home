# Online Troubleshooting and Retrospective for Project Implementation Plan Management: Conversation Logs and Auditing

## What this category of data looks like
The data for this category primarily originates from project contracts, work breakdown structures (WBS), client schedules, and enterprise project management systems. Daily generated documents include project plans, milestone lists, weekly reports, and risk issue lists. Data updates occur weekly or are triggered per individual project milestone. Common data fields include task number, responsible person, scheduled completion time, actual progress status, and risk level. There is no unified mandatory format, and adjustments are made flexibly based on project management workflows.

## Constraints imposed on the conversation logs and auditing link
This category of data is scattered and has flexible formatting. The conversation logs and auditing link must support binding project-specific identifiers, and associate multi-source data such as contracts and WBS. Data update cycles change with project phases, so log retention strategies must adapt to on-demand update frequencies to prevent invalid data accumulation. There is no unified standard for document structures, so log fields must support custom mapping to adapt to the document formats of different projects. Conversations generated through cross-party coordination must fully retain the interaction chain to ensure multi-party communication details can be traced during audits. The system must also be compatible with custom field rules for different projects to avoid missing audit data.

## How to configure the settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind project-specific identifiers, such as project WBS numbers | Used to associate conversation logs with plan, risk list, and other data for the corresponding project, ensuring audit trails can be traced to specific projects |
| `responseChatItemId` | Associate the unique identifier of a single round of conversation | Used to locate specific interaction nodes during fault troubleshooting, and quickly locate the context of abnormal errors |
| `detail` | Enable full log recording | Retain complete content of user input, AI replies, and system error reports, adapting to the full-chain tracing requirements of project audits |
| Log retention period | Set to twice the project milestone cycle, such as 180 days | Adapt to the full-cycle audit requirements of projects from initiation to acceptance, preventing key data from expiring prematurely |
| Custom field mapping | Bind task ID and responsible person fields from the project management system | Adapt to the flexible document structure characteristics of this category, enabling automatic association between logs and project data |

## Three common misconfigurations
- Symptom: After an online fault troubleshooting triggers an abnormal error, no error details are displayed in the logs. Cause: The `detail` full log configuration is not enabled, only basic interaction content is recorded, and system error messages are not captured.
- Symptom: When calling the conversation record interface, the context of the last AI reply cannot be located via `responseChatItemId`. Cause: The project-specific `chatId` is not bound during conversation initialization, causing logs and project data to fail to associate, and the interface cannot perform precise matching.
- Symptom: After configuring custom field mapping, the project responsible person field does not appear in the logs. Cause: Fields from the project management system are not correctly mapped to FastGPT log fields, and the flexible document structure characteristics of this category are ignored.

## How to confirm the configuration is complete
- View the conversation log list, confirm that each log carries the `chatId` field, and the field value matches the WBS number of the corresponding project.
- Trigger a simulated fault error, check whether the logs contain complete `detail` content, including system error information.
- Call the conversation record interface, verify that the `responseChatItemId` field returns normally, and that single-round interaction details can be located via this ID.
- Check the log retention period, confirm that the retention duration covers the current project plan cycle, and there is no risk of premature expiration.

The configuration values listed here are common starting points, and should be evaluated against actual operational samples.
