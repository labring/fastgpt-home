# Online Troubleshooting and Retrospective for Project Document Handover Archiving: Database and Operations

## What the data for this category looks like
Data for this category originates primarily from project document libraries, configuration lists, meeting minutes, and test reports generated across the full project lifecycle. Updates typically occur at project phase milestones or when a full project concludes. Daily delivered documents include completion documents, configuration manuals, training records, and acceptance certificates. Common data fields include project unique identifier, document version number, archiving verification code, associated operations node ID, and signature status. Storage units are based on individual files or structured entries. Most common formats are PDF, structured tables, or JSON archive packages.

## What constraints these characteristics impose on the database and operations link
Data sources for this category are scattered, and updates are intermittent. This requires databases to support batch import and version verification of multi-source heterogeneous data. Update frequency is not high, so the operations link does not need continuous high-concurrency writes. It must, however, support staged batch archiving verification. Daily documents include critical deliverables such as acceptance certificates. Indexes must be created for fields including signature status and project identifier to enable fast retrieval during troubleshooting. Additionally, data is tied to project uniqueness. Data must be isolated by project to avoid mixing archived documents from different projects. Data integrity must also be ensured to prevent acceptance failures caused by missing archives.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://[username:password@]host1:27017/project_docs?maxPoolSize=10` | Adapts to unstructured archiving storage for project documents, specifies connection pool size to match batch import scenarios |
| `PG_URL` | `postgresql://admin:pass@db-host:5432/acceptance?sslmode=prefer` | Stores structured data such as acceptance certificates and configuration manuals, supports multi-condition retrieval of archive records |
| `DB_MAX_LINK` | `10–15` | Balances concurrency requirements for batch archiving and server resource usage, prevents connection exhaustion |
| `REDIS_URL` | `redis://:auth@redis-host:6379/0` | Caches intermediate verification results for document integrity checks, speeds up multi-stage archiving verification workflows |

## Three common misconfigurations
- Symptom: Different project archived document sources cannot be distinguished in MongoDB logs. Cause: No dedicated database or project identifier tag is specified in the `MONGODB_URI` connection string. This causes documents from different projects to be stored in the same collection, making rapid filtering impossible.
- Symptom: Database connection plugin execution time increases significantly compared to older versions, with single connection time exceeding 1 second. Cause: The `DB_MAX_LINK` parameter is not configured properly. Insufficient connection pools cause request queuing, or the `REDIS_URL` cache is not enabled, leading to repeated execution of document verification logic.
- Symptom: Database connection in workflows prompts `connect ETIMEDOUT`, but local access works normally. Cause: Correct network access rules are not configured in the `PG_URL` or `MONGODB_URI` connection strings, or the deployment node has not opened the corresponding ports for the database service.

## How to confirm configurations are correct
- Run a test task to batch import 10 completion documents. Check that the database connection log has no connection exhaustion errors, to verify the connection pool configuration is reasonable.
- Retrieve acceptance certificates for a specified project. Confirm that matching results can be returned quickly via associated database queries, to verify structured retrieval configuration is active.
- Check cache monitoring data. Confirm that the cache hit rate for intermediate results of archiving verification meets standards, to verify the `REDIS_URL` configuration is valid.
- Verify workflow plugin parameters for FastGPT v4.17.0. Confirm that all database connection string formats comply with specifications.
