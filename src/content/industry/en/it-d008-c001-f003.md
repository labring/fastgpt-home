# CDN and Edge Acceleration Configuration Operations On-Call and Internal Ticket Q&A: Sharing and Embedding
This document is based on FastGPT v4.17.0.

## What this category of data looks like
This category typically includes four core document types: domain access tickets, cache rule configurations, refresh and preheating records, and fault analysis reports.
Data is sourced from CDN consoles, DNS resolution records, public network access logs, and node monitoring alerts.
Update frequency is either daily sync or real-time updates when configurations change.
Most fields include domain identifiers, cache policy parameters, node IPs, access latency thresholds, and similar items.
There is no unified standard format, so adjustments must be made to match the console format of different CDN vendors.
Operations staff regularly verify filing information and debug cache rules. Records generated by these actions are included in the aforementioned data sources.

## What Constraints Do These Characteristics Impose on Sharing and Embedding?
CDN-related data contains sensitive information such as domain identifiers and node IPs. Access permissions must be restricted during sharing to prevent unauthorized personnel from obtaining public resource configuration details.
Data updates in real time when configurations change. Embedded external knowledge bases must be configured with automatic sync mechanisms to ensure shared content matches the latest console data.
Document formats vary widely across different CDN vendors. Embedding workflows must adapt to the field structures of multiple data sources to avoid parsing errors.
Ticket Q&A for on-call operations scenarios must link to historical records for specific domains. External business systems must support filtering context by domain dimension, otherwise accurate matching of ticket scenarios is not possible.
Additionally, the sharing cycle for sensitive configurations must align with the measured operational ticket processing cycle range to avoid long-term exposure of outdated configurations.

## Three Common Mistakes
- CDN and edge acceleration configuration-related share links fail to open. First verify the full system-generated link and its validity period, then check browser request status. Do not manually replace `shareId`.
- The visible scope of CDN and edge acceleration configuration data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately. The share entry identifier itself does not provide business authorization.
- The same CDN and edge acceleration configuration Q&A cannot be viewed on another device. For anonymous scenarios, first check device, browser, and local identity status. Retention is not guaranteed across devices or after cache clearance, and service abnormalities cannot be judged solely based on this phenomenon.

## How to Confirm Configuration Is Complete
- Call the share link via an external business system such as an internal ticket system to check if identity verification takes effect. Unauthorized access returns permission denied results. FastGPT share links do not have built-in permission verification functions.
- Enter the CDN console to modify a cache rule, wait for the external data synchronization system to complete synchronization, then check if the content on the embedded page updates. FastGPT shared content does not have built-in automatic CDN data synchronization functions.
- Call the embedded iframe interface via an external business system to check that the returned conversation context only includes configuration context associated with the current ticket identifier, with no cross-ticket data. FastGPT does not have a built-in function to isolate sessions by `shareId`.
- Test the text display of the front-end page hosting the embedded content, confirm that Markdown code blocks only display original configuration content with no additional rendering formatting. FastGPT shared content does not have built-in Markdown rendering control functions.
