# IT Asset Inventory Operations Duty and Internal Ticket Q&A: Sharing and Embedding

## What data for this category looks like
IT asset inventory data comes from asset management systems, procurement systems, financial fixed asset modules, and terminal management platforms. Daily generated documents include asset ledgers, inventory sheets, requisition and return forms, and scrap applications. Core fields include asset number, device name, storage location, responsible user, asset status, purchase amount, and others. The data update frequency is mostly monthly, quarterly, or annually. A single update covers full asset status and ownership changes.

## What constraints these characteristics impose on sharing and embedding
Since asset data comes from multiple systems and has a long update cycle, embedding scenarios must adapt to cross-data source permission verification to prevent unauthorized access to sensitive asset information. The fixed document structure requires embedded chat sessions to preset business guidance logic to match query needs for fixed fields such as asset ledgers and inventory sheets. At the same time, links related to asset data physical verification, scrap review and other links involve compliance requirements. Embedded sharing links must verify operations duty permissions through the connected third-party identity verification system. The knowledge base synchronization rhythm is determined by the update cycle of the external asset management system to ensure that the returned asset information timeliness meets business requirements.

## Three common errors
- IT asset inventory-related sharing links fail to open. First check the complete link generated by the system and its validity period, then cross-check the browser request status; do not manually replace `shareId`.
- The visible scope of IT asset inventory data does not match expectations. Cross-check the third-party identity verification results, workflow request parameters, and data permissions of the external system; the sharing entry identifier itself does not provide business authorization.
- The same IT asset inventory Q&A cannot be viewed on another device. In anonymous scenarios, first check the device, browser, and local identity status; record retention cannot be guaranteed across devices or after cache clearing; do not use this phenomenon alone to judge service abnormalities.

## How to confirm the configuration is properly set
- Open the internal page configured with iframe embedding, check whether the chat window loads normally and displays the preset custom session prompt.
- Create sharing links in Simplified Chinese and English respectively, confirm that the interface text matches the specified language after opening, and is not affected by the console main interface settings.
- Verify that idle session processing complies with the configuration through the FastGPT backend session management page.
- Verify permissions through the connected third-party identity verification system, confirm that unauthorized accounts cannot access asset-related information.
- Cross-check that the `shareId` in the embedded code matches the identifier generated on the sharing configuration page, ensuring that it is bound to the asset inventory-specific knowledge base session.
