# IT Asset Inventory: Operations On-Duty and Internal Ticket Q&A: Permission and Data Isolation

## What data for this category looks like
Data for this category comes from asset management systems, procurement systems, financial fixed asset modules, and terminal management platforms. Core documents include asset ledgers, inventory sheets, loan and return forms, and scrap applications.
Data update frequency is monthly, quarterly, or annually. Each single data entry includes fields such as asset number, affiliated unit, physical location, user, and financial original value. Units include units, unit sets, yuan, and others.
Data is linked to multiple business systems, involves financial and ownership information, and requires strict control of access scope.

## What constraints do these characteristics impose on permission and data isolation
Data for this category is scattered across multiple business systems, with long update cycles. Permission configuration stability and consistency must be ensured.
Data includes sensitive information such as financial original value and asset ownership, which meets audit and compliance requirements. It cannot be opened to all internal users without differentiation.
Access scope varies significantly across roles: IT asset administrators can view full asset data, desktop support staff can only access assigned terminal assets, and finance personnel can only view finance-related fields.
In internal ticket Q&A scenarios, cross-team asset data leaks must be avoided.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Team data scope binding | Associate corresponding asset ledger via `teamId` | Match the managed asset scope of different IT teams |
| Sensitive field desensitization rule | Hide 80% of the characters in the financial original value field | Prevent leakage of asset financial sensitive information during internal ticket Q&A |
| Single-round return record limit | Return the first 15 matching asset data entries | Control the volume of data returned per Q&A session |
| Role permission binding | Bind desktop support/finance roles via `tmbId` | Only display asset tickets that the corresponding role can process |
| Data synchronization cycle | Synchronize latest inventory data every `7 days` | Match the monthly/quarterly/annual update rhythm of asset data |
| Authentication verification switch | Enable enterprise authentication binding | Restrict access to asset-related content by unauthorized users |

## Three common mistakes
- Symptom: After adding a custom asset inventory plugin to a workflow, input and output parameters are not displayed. Cause: The plugin is not associated with the asset data scope bound to `teamId`, resulting in missing parameter rendering.
- Symptom: A TypeError related to bootstrap-legacy-autofill-overlay.js appears in the console. Cause: The permission verification script for the asset inventory module of FastGPT v4.17.0 is not loaded correctly, leading to abnormal front-end parameter rendering.
- Symptom: After multiple accounts log in to the same team, cross-department asset tickets cannot be viewed. Cause: The binding rule between `tmbId` and roles is not configured, so the permission verification logic does not take effect.

## How to confirm the configuration is complete
- Log in with an unauthorized role account, attempt to access cross-team asset ledger tickets, and confirm that access to this type of content is denied.
- After configuring `teamId` binding for the corresponding team, view the internal ticket list of that team, and confirm that only asset-related tickets within the team's managed scope are displayed.
- After enabling the sensitive field desensitization rule, search for asset financial information in internal ticket Q&A, and confirm that the financial original value field is hidden.
- Test the workflow configuration of the custom asset inventory plugin, and confirm that input and output parameters are displayed normally in the configuration interface.
