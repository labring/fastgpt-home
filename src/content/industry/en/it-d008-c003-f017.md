# IT Asset Inventory: Operation and Maintenance On-Duty and Internal Work Order Query – Deployment and Upgrade

## What this type of data looks like
IT asset inventory data primarily comes from asset management systems, procurement systems, financial fixed asset modules, and terminal management platforms. Daily generated documents include asset ledgers, inventory lists, loan and return forms, and scrap applications. Fields include asset number, asset name, storage location, user, asset status, and more. Units are mostly units, sets, or pieces. Data update frequency is typically monthly, quarterly, or annually. The number of entries updated per single operation varies with the enterprise’s asset scale, with no fixed proportion.

## What constraints do these characteristics impose on deployment and upgrades
Since asset inventory data has a low update frequency, high-frequency real-time vector update configuration is not required, which can reduce service computing resource consumption. Since data sources involve multiple internal enterprise systems, deployment must adapt to the database connection formats of different systems to ensure compatibility of data synchronization. Since daily document formats are diverse, upgrades must ensure that the file storage module supports common spreadsheet and document formats to prevent inventory-related documents from failing to upload normally. Since asset ledgers involve internal enterprise management compliance, the deployment link must ensure the security of data storage and avoid configuration leakage risks.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `10–20 connections` | Asset inventory data has a low update frequency, so connection count does not need to be high, avoiding idle resource occupation |
| `MONGODB_URI` | `Private deployment dedicated MongoDB instance connection string` | Asset ledger data requires persistent storage; dedicated instances ensure data isolation and security, meeting hardware resource requirements for commercial deployments |
| `REDIS_URL` | `Intranet address of local cache service, memory configuration no less than 1000 MB` | Cache query results during high-frequency asset information retrieval to reduce access pressure on the primary database |
| `STORAGE_S3_ENDPOINT` | `Enterprise object storage service endpoint, bandwidth no less than 100 Mbps` | Adapt to the enterprise’s existing storage architecture and uniformly manage asset documents such as inventory lists and loan forms |
| `ROOT_KEY` | `32-character random encrypted string` | Ensure access permissions for backend management interfaces and prevent unauthorized operations |
| `FILE_TOKEN_KEY` | `64-character random encrypted string matching the storage service` | Verify the legitimacy of asset document upload and download requests to prevent unauthorized requests |

## Three common mistakes
- Asset search results are empty after upgrading to a new version. The cause is that structured asset ledger data was not reindexed, or the vector database connection configuration was accidentally modified during the upgrade, making it impossible to match existing asset information.
- Container startup fails after Docker packaging and deployment. The cause is that `MONGODB_URI` or `REDIS_URL` parameters were not filled correctly, causing the service to fail to connect to dependent databases and cache services, resulting in failed container health checks.
- Internal work order response is abnormal after enabling the mineru function. The cause is that access permissions for the corresponding module were not enabled in the configuration, or the `FILE_TOKEN_KEY` configuration does not match the storage service, causing work order data to fail to circulate normally.

## How to confirm the configuration is correct
- Log in to the FastGPT v4.17.0 backend management interface, use `ROOT_KEY` to verify interface permissions, and confirm normal access to the asset management module without permission errors.
- Upload a standard XLSX-format asset inventory list, confirm that the file is properly stored via the storage service corresponding to `STORAGE_S3_ENDPOINT`, and that the complete file can be downloaded via the interface with no file corruption prompts.
- Perform an asset keyword search, enter a known asset number, and confirm that the returned results include detailed information of the corresponding asset, with the number of result entries matching the actual number of entries in the existing asset ledger.
- Restart the service and check system logs, confirm that there are no database connection timeout or refused connection errors, the cache service connection is normal, and no abnormal error messages are present.
