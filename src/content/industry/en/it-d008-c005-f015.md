# Operations on-duty and internal work order question answering for issue sorting and response: Knowledge base retrieval and recall

## What this category of data looks like
Typical subjects include open source maintainers, community operators, and core contributors. Data sources mainly include GitHub or Gitee Issues, release notes, user environment information, and code repositories. Update frequency is daily or weekly. Daily maintained documents cover Issue templates, label rules, response records, and problem reproduction instructions. Data fields include problem descriptions, classification labels, reproduction steps, and responsible modules. The overall content primarily consists of structured rules and semi-structured problem records.

## Constraints on knowledge base retrieval and recall
The data mainly includes natural language questions related to Issues and rule documents. Retrieval and recall must match core information such as problem descriptions and label rules. Use a retrieval mode adapted to natural language.
Data updates happen daily or weekly. Set up a regular synchronization mechanism to keep the knowledge base consistent with the latest label rules and response templates.
Most daily documents are classification rule content. Ensure recalled fragments accurately match problem classifications and response standards. Prevent irrelevant content from disrupting the sorting process.
Data volume changes with community activity. Limit the number of single recall entries to control context length. Maintain response efficiency in on-duty operations scenarios.

## Configuration recommendations
This configuration applies to FastGPT v4.17.0. Specific configuration items and recommendations are listed below:

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `similarity` | 0.72–0.85 | Semantic similarity threshold for matching Issue-related questions, covers common work order and problem classification scenarios in operations, calibrated based on actual testing |
| `limit` | Top 6 entries | Limits the number of single recall results, adapts to the short context processing requirements of on-duty operations scenarios and avoids information overload |
| `searchMode` | Semantic retrieval | Matches natural language descriptions of Issue problems, adapts to non-standard work order content submitted by operations staff |
| `usingReRank` | Enabled | Performs secondary sorting on recall results, corrects deviations from semantic retrieval and improves the accuracy of Issue classification |
| `collectionIds` | Bind Issue-related knowledge base collections | Restricts the retrieval scope, only calls preset knowledge bases for operations work orders, Issue rules, and response templates |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands problem keywords, supplements high-frequency labels and module names related to Issues, and improves recall matching accuracy for specific problems in operations work orders |

## Three common configuration errors
- All `similarity` scores in retrieved results exceed 0.9, and large volumes of historical Issue content unrelated to the current work order are included. This occurs when a reasonable `similarity` threshold is not set, or `usingReRank` is not enabled for secondary result sorting. Low-relevance content is then incorrectly recalled.
- When configuring the `collectionIds` parameter in a workflow, referencing a global variable triggers a configuration error, or retrieval results do not match the specified knowledge base. This happens when the `collectionIds` reference format is not configured per FastGPT v4.17.0 variable binding rules, or the variable scope does not cover the current workflow.
- After importing Issue template data in Excel format, retrieval results do not match the label rules in the table. This stems from incorrect mapping between Excel table column names and knowledge base retrieval fields, or failure to enable the field matching mode for the table dataset.

## How to verify successful configuration
- Manually submit a typical operations work order question. Check if the `similarity` scores of retrieval results fall within the preset interval. Adjust the threshold to meet business requirements.
- Check the `collectionIds` parameter configuration in the workflow. Verify that the specified knowledge base collections include the Issue rules and response template data needed for the current retrieval.
- Trigger a complete Issue sorting process. Confirm that the number of recall results matches the `limit` parameter setting, and no extra irrelevant content is included.
- Import a test Excel dataset. Verify that retrieval results match fields such as labels and reproduction steps in the table. Confirm that the mapping relationship takes effect.

The values provided are common starting points and should be measured against the reader’s own samples.
