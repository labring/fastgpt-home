# Operations On-Duty and Internal Ticket Q&A for Issue Triage and Response: Deployment and Upgrade

## What This Category of Data Looks Like
This category of data originates primarily from GitHub or Gitee Issues, release notes, user environment information, and code repositories. Daily maintained documents include Issue templates, label rules, response records, and problem reproduction instructions. Data updates occur daily or weekly. Typical fields include Issue numbers, classification labels, priority levels, reproduction steps, associated code repositories, and version information. This data is maintained daily by open-source maintainers, community operators, and core contributors, and is used for issue classification, response, and closed-loop processing.

## What Constraints These Characteristics Impose on Deployment and Upgrade
The data sources for this category are scattered, including external code repositories and local user environment information. During deployment, parameters adapted for multi-source data access must be configured to ensure normal synchronization of Issues and environmental data from all channels. Data updates occur daily or weekly. The upgrade process must support incremental synchronization logic to avoid excessive resource usage caused by full data pulls. Daily documents include fixed-format Issue templates and label rules. During deployment and upgrade, a configuration entry for custom label mapping must be retained to maintain compatibility with existing maintenance workflows. This data is manually maintained by community personnel. Post-upgrade functions must support adaptive adjustments for automatic label classification, without forcing changes to established maintenance habits.

## Configuration Recommendations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@host:port/database?authSource=admin` | Issue data and user environment information for this category rely on MongoDB storage. The standard connection format adapts to public cloud and local deployment scenarios |
| `REDIS_URL` | `redis://:password@host:port/0` | Used to cache Issue label rules and response records. The default database 0 adapts to resource allocation for single-instance deployments |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-beijing.aliyuncs.com` (or a local MinIO custom address) | Stores Issue attachments and problem reproduction logs. Must match the endpoint address of the object storage service in use |
| `DB_MAX_LINK` | `100–200 connections` | The daily/weekly updated data volume for this category is moderate. This connection count balances concurrent requests and server resource usage, and is calibrated based on actual testing |
| `FE_DOMAIN` | `https://your-fastgpt-domain.com` | Used to generate jump links in Issue responses. Must match the domain name of the deployed front-end service |

## Three Common Configuration Mistakes
- Symptom: After deploying FastGPT v4.17.0 locally, the Issue attachment parsing function fails to trigger normally, and the interface displays a file parsing failure error. Cause: `STORAGE_S3_ENDPOINT` or associated storage keys are not configured correctly, preventing access to uploaded Issue attachment data.
- Symptom: After deploying the SaaS version, the basic chart plugin outputs `none` and cannot generate the expected chart URL. Cause: The configured `FE_DOMAIN` value does not match the actual domain name of the SaaS platform, causing links generated by the plugin to fail normal parsing.
- Symptom: After an upgrade, Issue classification labels cannot be synchronized automatically, and manually configured label rules become invalid. Cause: The original `REDIS_URL` cache configuration was not retained during the upgrade process, resulting in the label cache being cleared or reset.

## How to Confirm Configuration Is Complete
- Run the database connection test script to verify that the configurations for `MONGODB_URI` and `REDIS_URL` can establish normal connections, and the connection status must align with the resource limits of the deployment environment.
- Upload a test Issue attachment, and confirm that the attachment can be accessed normally via the storage address specified in `STORAGE_S3_ENDPOINT`, with no permission or path errors.
- Trigger a simulated Issue synchronization task, and check whether the label mapping and response record generation logic follow the preset configuration rules.
- View the jump links on the front-end page, confirm that the configured `FE_DOMAIN` value matches the actual accessed domain name, with no cross-domain or path errors.
