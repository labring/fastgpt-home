# Pull Request Review Operations On-Call and Internal Ticket Q&A: Sharing and Embedding

## What the Data for This Category Looks Like
Typically, core data for Pull Request reviews comes from code repositories, CI pipelines, Issue links, and contributor submission records. Daily generated documents include PR descriptions, code review comments, CI results, and merge records. Data update frequency is mostly daily or weekly, matching the rhythm of code commits and pipeline runs. Data fields include change intent descriptions, code change scope, test pass rates, conflict status, and more. There is no unified standardized field format, with slight differences based on project configuration.

## What Constraints These Characteristics Impose on the Sharing and Embedding Workflow
Since data sources involve private content from code repositories and CI pipelines, the sharing and embedding workflow must strictly control access permissions to prevent unauthorized personnel from accessing sensitive code information. Data update frequency is daily or weekly, so the associated PR review knowledge base must synchronize source data regularly to ensure embedded content matches the latest review status. PR review data structure focuses primarily on code change-related information, so retrieval scope must be limited to PR-specific documents to avoid mixing in irrelevant Issue content. Some data includes code snippets and CI result screenshots; display and interaction of this content must be implemented by the frontend of the embedded page.

## Three Common Misconfigurations
- Pull Request review-related sharing links fail to open. First verify the full system-generated link and its expiration period, then check browser request status; do not manually replace `shareId`.
- The visible scope of Pull Request review data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately; the sharing entry identifier itself does not provide business authorization.
- The same Pull Request review Q&A is not visible on another device. In anonymous scenarios, first check device, browser, and local identity status; retention cannot be guaranteed across devices or after cache clearing, so do not use this phenomenon alone to judge service anomalies.

## How to Confirm Proper Configuration
- Copy the `shareId` parameter of the share link, and verify that it matches the system-generated identifier of the corresponding sharing entry generated by the FastGPT non-login window.
- Use an API tool to call the sharing interface, pass a test question, and verify that the returned results include preset PR review-related content.
- Send a test question containing code snippets or CI screenshots on the embedded page, and click the image to confirm that it can jump to the original image for viewing.
- Wait for the preset external data synchronization cycle, then check if the embedded page can pull the latest PR merge records or CI results.
