# Operational On-Call and Internal Ticket Q&A for SLA and Service Reports: Deployment and Upgrade

## What this type of data looks like
Data sources include monitoring systems, ticketing systems, contract documents, and customer communication records. The update frequency is monthly or quarterly. Daily output documents include SLA clauses, monthly service reports, availability statistics documents, and customer review minutes. Data fields include service cycle identifier, abnormal event classification, contractually agreed service thresholds, event attribution results, and other related items. All data must be summarized and aligned per individual customer contract cycle to ensure consistency with contract terms.

## What constraints do these characteristics impose on the Deployment and Upgrade phase
Since data must be summarized and archived per individual customer contract cycle, configure storage parameters for multi-tenant data isolation during deployment to avoid cross-customer data confusion.
Since data sources include multiple external systems, adapt deployment to interface formats and permission rules of different systems.
Since the update frequency is fixed as monthly or quarterly, configure task parameters for scheduled synchronization and summarization during deployment.
During upgrade, retain the archive structure of historical data to avoid damaging generated service reports and review minutes. Also, retain the original cross-system data pulling logic to prevent interruption of periodic data processing workflows.
Additionally, since data is associated with customer contract service thresholds, ensure the integrity of data verification logic during deployment and upgrade to avoid disputes caused by missing fields or calculation errors.

## Configuration Parameters
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://[username]:[password]@[host]:[port]/fastgpt_sla?authSource=admin` | Stores SLA cycle data and ticket association records, adapts to multi-tenant data isolation requirements |
| `PG_URL` | `postgresql://[username]:[password]@[host]:[port]/fastgpt_report` | Stores structured metadata for monthly service reports, supports fast querying by contract cycle |
| `REDIS_URL` | `redis://:[password]@[host]:[port]/0` | Caches status and temporary calculation results of scheduled summarization tasks, reduces repeated pulls from external systems |
| `DB_MAX_LINK` | `20–30 concurrent connections` | Adapts to multi-customer concurrent SLA data query requests, avoids exhausting database connections |
| `STORAGE_S3_ENDPOINT` | Calibrated based on actual testing | Stores attachments and archive files for monthly service reports, adapts to existing enterprise object storage configurations |
| `ROOT_KEY` | Randomly generated 32-character string | Manages permission verification for SLA configurations and scheduled tasks, prevents unauthorized modifications |

## Three Common Mistakes
- Symptom: After upgrading the platform version, the scheduled SLA report generation task fails to trigger, with an error indicating database connection failure. Cause: The `MONGODB_URI` configuration was not updated correctly during the upgrade, preventing access to the database storing SLA cycle data.
- Symptom: Multiple associated fields in SLA reports cannot be aggregated correctly, resulting in missing report content. Cause: Multi-node data synchronization logic was not configured properly during deployment, causing variable updates to fail to integrate uniformly into the data aggregation process.
- Symptom: The specified large language model cannot be invoked in the commercial version, only the reranking model is available. Cause: Association parameters between the `FE_DOMAIN` configuration and model interfaces were not set correctly during deployment, leading to failed permission verification for channel models.

## How to Verify Configuration Completion
- In FastGPT v4.17.0, run a database connection pool status query to check if the number of connections configured for `DB_MAX_LINK` falls within the specified range.
- Trigger a manual monthly SLA report generation task, confirm that data from the corresponding cycle can be pulled from the ticketing system and monitoring system, and that a structured report document is generated.
- Access the frontend address configured in `FE_DOMAIN`, navigate to the SLA configuration page, and verify that the `ROOT_KEY` permission verification logic takes effect to prevent unauthorized access.
- Check the object storage archive directory to confirm that generated monthly service reports have been uploaded in accordance with the `STORAGE_S3_ENDPOINT` configuration.
