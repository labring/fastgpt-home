# Operations on-duty and internal ticket Q&A for special event campaigns: Sharing and embedding

## What data looks like for this use case
Typically, data sources for special event campaign operations include content libraries, event backends, traffic metrics, and user feedback. Daily produced documents include event plans, resource slot schedules, event page copy, and post-event review reports. Fields are mostly event-specific IDs, resource slot numbers, copy versions, traffic metrics, and user feedback tags. Units are mostly pieces, times, and characters. Data update cycles follow a weekly rhythm. Holiday periods may adjust update frequency based on event schedules, and some temporary events follow a daily update cycle.

## What constraints do these characteristics impose on the sharing and embedding workflow
Special event campaigns have clear cycles and resource slot requirements. Therefore, sharing and embedding configurations must use system-generated unique share entry identifiers to avoid mixing content across events. Data updates follow a weekly cycle, with some temporary events switching to a daily rhythm. The caching strategy for embedded pages must be set by external systems such as CDNs and page services to match the data update rhythm, preventing expired event copy or ticket data from being displayed. Daily documents include multiple structured fields, which must be passed to the FastGPT application by external systems. The FastGPT application itself does not pull business data; data pulling is handled by corresponding external systems or knowledge bases. Additionally, event pages have fixed resource slot dimensions. The specifications of embedded containers must adapt to page layout standards to ensure overall coordination after embedding.

## Three common mistakes
- Share entries related to special event campaigns fail to open. First verify the full system-generated link and its validity period, then check browser request statuses. Do not manually replace `shareId`.
- The visible scope of special event campaign data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately. The share entry identifier itself does not provide business authorization.
- The same special event campaign Q&A is not visible on another device. For anonymous scenarios, first check device, browser, and local identity status. Retention of records is not guaranteed across devices or after cache clearance; do not use this phenomenon alone to judge service anomalies.

## How to confirm configuration is complete
- Open the embedded event page, check that the top title matches the event name in the event plan.
- Enter a test ticket question, such as "Today's on-duty operations staff list", confirm that the conversation correctly returns matching on-duty operations and internal ticket content.
- Copy the share link, add parameters that comply with external system rules, then open the link to confirm that the parameters are recognized by the corresponding system and that content for the corresponding theme is applied.
- Check that the dimensions of the embedded container match the reserved space for resource slots on the event page, with no layout overflow or content truncation.
