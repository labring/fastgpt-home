# Operations on Duty and Internal Ticket Q&A for Special Event Campaigns: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
Typical users of this category include content operations, event operations, design, and R&D support staff. Daily processed documents include event plans, resource slot schedules, event page copy, and review reports. Data sources cover content libraries, event backends, traffic data, and user feedback. Update frequency follows a weekly cycle, with temporary increases around holidays. Document structures include structured schedule fields, unstructured copy content, and multi-paragraph review reports. Some documents contain varied content such as resource slot IDs and traffic values, with no unified fixed field units.

## Constraints on Knowledge Base Retrieval and Recall
Multi-source event-related data leads to dispersed knowledge base entries. This requires limiting the retrieval scope to avoid mixing non-event content. Non-fixed update frequencies require the retrieval system to support incremental synchronization and temporary updates, to match temporary event needs during holiday periods. The diversity of document types and fields requires the retrieval system to support mixed matching of structured and unstructured content, plus filtering by fields such as resource slot IDs and event cycles. Clear event cycles require retrieval results to tie to currently ongoing or upcoming events. This avoids returning expired event content, reducing resource waste and audit omission risks.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0, as shown in the table below.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Semantic similarity matching for event copy, schedules and similar content requires a stable threshold to avoid returning irrelevant general operation documents |
| `limit` | `Top 6–10 entries` | Knowledge base entries for special events are usually grouped by event cycle. Excessive results will exceed the carrying capacity of the conversation context |
| `usingReRank` | Enabled | Topic similarity of event-related documents can easily be disrupted by fields such as event names and resource slot IDs. Reranking filters low-relevance results |
| `datasetSearchUsingExtensionQuery` | Enabled | Event operation questions often include situational modifiers, such as "resource slot schedule for Double 11 event". Extended queries can cover more relevant documents |
| `collectionIds` | Bind corresponding knowledge base collections by event cycle | Special events have clear cycle ranges. Limiting collections reduces retrieval results from irrelevant historical events or non-event content |

## Three Common Misconfigurations
- Symptom: Retrieval results are empty during debugging, or fail to match event-related documents. Cause: Not binding `collectionIds` by event cycle, leading the retrieval scope to cover irrelevant non-event knowledge bases. Or not enabling `datasetSearchUsingExtensionQuery`, which prevents recognition of situational question phrasing.
- Symptom: Garbled characters appear after importing the knowledge base online, but work normally locally. Cause: The online deployment environment’s character encoding differs from the local environment. Event copy includes multilingual or special format characters without unified encoding processing.
- Symptom: The knowledge base search entry is forcibly displayed in answer content. Cause: The search result display switch in conversation configuration is not disabled. This causes the retrieval module to display by default, which does not meet the concise needs of internal ticket Q&A.

## How to Confirm Successful Configuration
- Upload a single current event plan document, initiate a query that includes the event theme, and verify that returned results include relevant fragments of this document.
- View the retrieval log to confirm only knowledge base entries corresponding to `collectionIds` bound to the current event cycle are returned, with no irrelevant content.
- Initiate a query with situational modifiers, such as "resource slot schedule for National Day event", and confirm result ranking aligns with semantic relevance after `usingReRank` is enabled.
- Upload an event copy document containing special characters, confirm no garbled characters appear after online import, and that the encoding format is uniformly UTF-8.

The values provided are common starting points and should be measured against the reader's own samples.
