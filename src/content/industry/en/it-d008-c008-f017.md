# Operations on Duty and Internal Ticket Q&A for Special Event Operations: Deployment and Upgrade

## What the data for this category looks like
Typical entities include content operations, event operations, design, and R&D support. Daily documents include event plans, resource slot schedules, event page copy, and review reports. Data sources are content libraries, event backends, traffic data, and user feedback. Update frequency is weekly or during holiday cycles. Documents include fields such as event cycle, resource slot ID, traffic metrics, and review status. There are no fixed unified units, as they vary by document type.

## What constraints these characteristics impose on the deployment and upgrade workflow
Event plans and resource slot schedules have clear time window constraints. Deployment and upgrade must avoid active event periods to prevent disruption to business workflows. In the deployment process for FastGPT v4.17.0, special attention must be paid to the upgrade window settings during the event cycle. Documents include multiple types of structured and unstructured content. Database and cache configurations must adapt to concurrent demands for batch document uploads and real-time traffic queries. User feedback data must be synchronized to the ticket system in a timely manner. A stable external service connection must be configured during deployment. Historical data during the event cycle must be retained during upgrades to prevent data loss from configuration changes.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@host:27017/fastgpt?authSource=admin` | Stores structured documents such as event plans and review reports, adapting to storage needs for multiple types of event data |
| `REDIS_URL` | `redis://:password@host:6379/0` | Caches real-time event traffic data and ticket session information, supporting fast internal Q&A queries |
| `DB_MAX_LINK` | `20–30 connections` | Supports concurrent connections for weekly batch uploads of event plans, preventing database connection exhaustion |
| `ROOT_KEY` | `32-character random string` | Manages root permissions for the internal ticket system, ensuring the security of configuration modifications |
| `FILE_TOKEN_KEY` | `Calibrated via actual testing` | Protects download permissions for event page copy, preventing unauthorized access |

## Three Common Misconfigurations
- Phenomenon: After removing `networks - fastgpt` from docker-compose.yml, communication between components fails. The interface returns a 500 status code and prompts a connection timeout. Cause: FastGPT isolates component communication via a specified network by default. Removing this setting prevents resolution of internal service addresses.
- Phenomenon: After upgrading to FastGPT v4.9.8, modifying the root user password results in it being automatically reset to the initial value the next day. Cause: The `ROOT_KEY` configuration was not persisted in environment variables, or persistent storage volumes for saving configurations were not mounted during deployment.
- Phenomenon: After integrating qwen3-embedding-8b with FastGPT v4.9.11, the file status consistently displays "Indexing" with no progress updates. Cause: FastGPT has not adapted to the interface compatibility of this embedding model version, or the request timeout parameter configuration is insufficient.

## How to Verify Proper Configuration
- Run the docker-compose ps command to confirm all components have a status of Up and no continuous restart records.
- Log in to the FastGPT backend, enter the internal ticket module, create and submit a test ticket, and confirm the ticket can be properly routed to the corresponding responsible party.
- Upload an event plan document to trigger the indexing process, and confirm that the indexing status updates within a reasonable time frame.
- View the cache service corresponding to `REDIS_URL` and confirm there are cached records of event traffic data.

The values provided are common starting points and should be measured against the reader's own samples.
