# Cloud Billing and Cost Calculation: Operations On-Call and Internal Ticket Q&A - Permission and Data Isolation

## What data in this category looks like
This document is written based on FastGPT v4.17.0. Daily data for cloud billing and cost calculation includes four types of documents: billing details, cost allocation tables, resource utilization reports, and optimization suggestion sheets.

Data sources include cloud billing systems, tag data systems, order systems, and resource monitoring platforms. Update frequency is typically daily or monthly.

Billing details aggregate billing information by resource dimension. Cost allocation tables link business projects and resource tags. Resource utilization reports record resource usage status. Optimization suggestion sheets flag resource configurations that need adjustment.

Data fields include billing cycle, resource ID, cost amount, tag values, and no pre-built additional statistical values.

## What constraints do these characteristics impose on permission and data isolation?
Cloud billing data from multiple sources with varying update frequencies includes sensitive cost information. Different roles such as cloud finance operations, FinOps teams, and account managers require access to different data scopes. Permissions must be isolated by business boundaries.

Daily and monthly bulk data updates require permission configurations that support bulk synchronization. This avoids repetitive operations.

Tag data is tied to resource ownership. Permissions must be bound to tag dimensions to precisely control access scopes and prevent cross-team data leaks.

Accurate permissions are required for abnormal cost troubleshooting and cost allocation explanations. Unauthorized personnel cannot access sensitive billing content.

In operations on-call and internal ticket Q&A scenarios, different ticket roles can only call Q&A capabilities for their corresponding business lines. They cannot access data from other teams without authorization.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `teamId` | Divide by business team, use the unique identifier of the corresponding team | Match the team ownership tags of cloud billing data, to isolate data by team |
| `tmbId` | Divide by ticket scenario, use the template ID for scenarios such as operations on-call and cost calculation | Restrict different ticket roles to only call Q&A models for their corresponding scenarios |
| Data access scope | Bind to resource tag dimensions, use the tag values of the corresponding business line | Match the tag association rules of cost allocation tables, to limit access to only data from the user's own business line |
| Bulk authorization limit | Calibrate based on actual testing, use 10–20 teams per day | Adapt to the bulk data synchronization rhythm of daily updates, to avoid overloading permission configurations |
| Session timeout duration | Set to 1800 seconds | Adapt to the long session requirements of operations on-call, while avoiding idle sessions consuming resources |
| Permission audit switch | Enabled | Record access logs for ticket Q&A, for traceability during abnormal cost troubleshooting |

## Three common misconfigurations
- Phenomenon: The ticket assistant returns a no permission access error message, or returns empty billing data. Cause: `teamId` and resource tags are not correctly bound, resulting in roles being assigned cross-business line access scopes.
- Phenomenon: Team members do not receive permission notifications after logging in, or cannot view their team's cost allocation tables. Cause: The bulk authorization limit is set too low, permission synchronization for all teams is not completed, or the `tmbId` configuration does not match the current ticket scenario.
- Phenomenon: Sessions are forcibly interrupted during operations on-call. Cause: The session timeout duration is set too short, which does not adapt to long-duration abnormal cost troubleshooting scenarios.

## How to confirm the configuration is correct
- Submit an internal operations on-call ticket, verify that the Q&A results only include billing details and cost allocation data for the user's own team.
- Switch to another team's account, confirm that resource utilization reports and optimization suggestion sheets for the corresponding business line cannot be accessed.
- Check the permission audit logs, confirm that all access records for ticket Q&A are associated with the correct `teamId` and `tmbId`.
- Wait one daily update cycle, verify that the bulk authorization configuration does not experience abnormal interruptions, and newly added teams can obtain permissions normally.
