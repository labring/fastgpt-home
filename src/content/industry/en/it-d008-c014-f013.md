# Cloud Resource Compliance Audit Operations Duty and Internal Ticket Q&A: Permission and Data Isolation

## What this category of data looks like
Data for the cloud resource compliance audit category comes from cloud audit logs, IAM permission systems, CMDB resource inventories, and security baseline scan results. Data is updated monthly or quarterly. Daily output documents include compliance checklists, permission audit reports, resource inventories, and rectification tracking forms. Each document contains fields such as resource identifiers, permission configuration items, audit timestamps, and rectification status. No additional statistical values are included.

## What constraints do these characteristics impose on permission and data isolation
Data for cloud resource compliance audit includes sensitive compliance information such as permission configurations and resource inventories. The update frequency is low, but the content must meet compliance requirements. This requires strict limits on data access. Audit data for different teams must be isolated by team, to prevent unauthorized cross-team access to compliance documents. In operations duty and internal ticket Q&A scenarios, chat records and audit data storage must be tied to the corresponding operating subject, to avoid leakage of sensitive audit content. Edit permissions for rectification tracking forms must match the responsible team, to ensure only authorized personnel can modify data.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `teamId` binding | Bind the exclusive `teamId` of the corresponding compliance audit team, only allow members of this team to access | Ensure audit data is only accessible to authorized teams, aligns with core permission isolation requirements |
| `tmbId` association | Associate with the internal ticket’s `tmbId`, only allow the ticket initiator and handler to view related Q&A content | Match the permission chain of internal tickets, prevent unauthorized cross-ticket access to sensitive audit data |
| Session data storage path | Local encrypted storage directory `/var/fastgpt/audit-data` | Meet local deployment data retention requirements, avoid third-party storage leakage risks |
| Chat record retention period | `90 days` | Align with monthly audit compliance retention cycles, meet evidence requirements for rectification tracking |
| Access permission check interval | `600 seconds` | Balance access efficiency and permission check security, prevent continued access after permission changes due to long intervals without checks |

## Three common misconfigurations
- Symptom: After generating a publicly accessible link, unauthorized users can view internal compliance audit chat records. Cause: Access permission checks were not configured via `teamId`, and access was not restricted to only authorized team members.
- Symptom: After configuring a model related to compliance audit, a connection error prompt appears during testing. Ignoring the error allows generating responses, but internal ticket calls fail to load compliance data. Cause: The `tmbId` was not associated with the internal ticket’s permission chain, leading to failed data access permission checks.
- Symptom: Team members cannot view their team’s rectification tracking forms. Cause: The `teamId` was incorrectly bound to a non-corresponding team, resulting in overly narrow permission scope that prevents access to the team’s compliance documents.

## How to confirm the configuration is complete
- Generate an access link bound to the exclusive `teamId`, use an unauthorized account to attempt access, confirm that compliance audit-related content cannot be loaded.
- Initiate an internal ticket, call the compliance audit Q&A function, confirm that the team’s resource inventories and permission audit reports can be loaded.
- Check the local encrypted storage directory, confirm that chat records are only stored in the exclusive subdirectory bound to the `teamId`.
- Test model calls, confirm there are no permission check error reports, and that response content only includes the team’s compliance audit data.
