# Operations On-Duty and Internal Ticket Q&A for IT Budget and Project Portfolio Management: Permission and Data Isolation

## What This Category of Data Looks Like
This category’s data primarily comes from financial systems, project management systems, contract ledgers, and business department requirements. Daily outputs include annual budget sheets, project proposal documents, project portfolio dashboards, investment review reports, and similar documents.
Data update cycles are mostly monthly, quarterly, or annual. Core fields include project number, budget amount, project initiation time, revenue forecast, and more. Units include ten thousand yuan, person-days, project cycle (months), and others.
Data structures revolve around the full project lifecycle and budget allocation. There is no unified standard format. Most data is exported from various business systems and then organized.

## What Constraints These Characteristics Impose on Permission and Data Isolation
Data sources are scattered across multiple business systems. Different departments hold data with distinct permission scopes. Isolation rules must define clear access boundaries based on department and role.
Data update frequency is low, but single data volume may be large. Frequent changes to permission configurations must be avoided to prevent permission confusion.
Document structures are non-standard. Field-level permissions must be configured for different document types. This prevents sensitive content such as investment review reports and budget sheets from being accessed by unauthorized members.
Cross-team operation tickets and agent calls must also be strictly isolated. This avoids leakage of budget data from different project teams.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `teamId` | Bound to the exclusive teamId of the corresponding business department | Distinguish access scope for project and budget data across different business departments |
| `tmbId` | Assign tmbId groups by role, such as financial BP group, PMO group | Limit operating permissions for different roles. Only allow corresponding groups to modify authorized data |
| Team Data Scope | Associate specified data sources from financial systems and project management systems | Match the data isolation requirements for multi-system sourced data in this category |
| Single Query Limit | Top 5 entries | Limit the number of data entries returned per query round to avoid cross-team data leakage |
| Context Isolation Duration | 600 seconds | Limit the retention time of cross-team context to avoid data leakage |
| Permission Verification Rules | Configure field-level permissions by document type | Adapt to the non-standard document structure of this category |
| Interface Call Permissions | Only allowed to be configured by team administrators | Prevent unauthorized personnel from modifying isolation rules |

## Three Common Mistakes
- Phenomenon: Cross-team applications return no relevant content when calling the knowledge base. Cause: The binding relationship between `teamId` and the knowledge base is not configured, leading to failure to correctly isolate cross-team data.
- Phenomenon: Unauthorized members can view model usage records within the team. Cause: `tmbId` groups are not assigned by role, leading to ineffective permission verification.
- Phenomenon: Members can create unauthorized agents. Cause: Interface call permissions are not configured to only allow administrator operations, leading to unauthorized personnel modifying permission rules.

## How to Confirm Configuration is Complete
- Log in to the FastGPT v4.17.0 backend, switch to the corresponding team, and check if the data source bound to `teamId` matches the actual business department’s systems.
- Use an unauthorized member account to attempt to access the annual budget sheet or investment review report within the team, and confirm that the corresponding content cannot be viewed or operated.
- Test the cross-team agent’s function of calling the knowledge base, and confirm that no relevant content is returned or a prompt for insufficient permissions pops up.
- Check the member permission group configuration, and confirm that only team administrators can modify permission isolation-related setting items.
