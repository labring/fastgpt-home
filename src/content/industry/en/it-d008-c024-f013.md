# Operations On-Duty and Internal Ticket Q&A for Information Feed Ad Creative Testing: Permission and Data Isolation

## What This Category of Data Looks Like
Core data for information feed ad creative testing comes from advertising delivery platforms, internal material libraries, user interaction data, and conversion data. Update frequency is mostly daily or weekly. Common associated documents include creative scripts, material test sheets, delivery data reports, and iteration checklists. Data fields include material ID, creative type, test cycle, click-through rate, conversion cost, material compliance status, and more. There are no unified fixed units; some fields must be defined per the interface specifications of the corresponding advertising platform.

## What Constraints Do These Characteristics Impose on Permission and Data Isolation
Multi-source cross-system data from information feed ad creative testing needs to match access boundaries for different business roles: optimizers, creative teams, and growth teams. This prevents cross-team unauthorized access to sensitive delivery data. Test data and iteration checklists updated daily or weekly have time sensitivity. Permission configurations must take effect in real time with project changes to prevent data leaks caused by leftover old permissions. Errors in creative testing directly affect delivery effectiveness. Permission isolation must prevent unauthorized personnel from modifying officially delivered creative configurations or test conclusions, and avoid cross-mixing of material data from different test projects. Internal ticket workflows must be bound to the permissions of the corresponding test project, ensuring tickets are only approved and processed within authorized scope.

## How to Configure Settings
The following configurations are implemented using the permission and data isolation module of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---|---|--- |
| Team permission binding | Bind `teamId` to advertising account ownership | Matches the account ownership logic of advertising platforms, ensuring only team members can access corresponding creative test data |
| Material permission binding | Bind `tmbId` to material library groups | Restricts material access to only material resources of the current test project, preventing cross-project material leaks |
| Global variable isolation | Enable `teamId`-based variable isolation | Resolves conflicts where global variables with the same name from different teams overwrite each other, matching the variable usage scenarios of business roles |
| Ticket permission scope | Limit to test tickets under the current `teamId` | Narrows the permission boundary for ticket approval, ensuring approvals can only process internal tickets for the corresponding team |
| Access time control | Limit to test data from the last 7 days with a maximum size of 1000 MB per file | Reduces permission coverage, lowers the risk of historical data leaks, and matches the volume of daily test data |
| Log audit configuration | Only record operation logs for the current `teamId` | Simplifies troubleshooting scope while meeting internal compliance audit requirements |

## Three Common Configuration Mistakes
- Symptom: Cross-team material data is displayed when optimizers from different teams view test reports. Cause: `teamId` is not bound to advertising account ownership, and permissions are not isolated by team, leading to chaotic cross-team data permissions.
- Symptom: Variable values from different users overwrite each other after configuring global variables with the same name. Cause: `teamId`-based variable isolation is not enabled, and variable scopes are not isolated by team or user ID, causing configuration conflicts.
- Symptom: Operations on-duty staff cannot view ticket details for the corresponding test project. Cause: The ticket approval role is not bound to the corresponding `tmbId` or `teamId`, and the permission scope does not cover associated data for the target test project.

## How to Confirm the Configuration Is Correct
- Switch test accounts from different teams, verify that only creative test data and tickets bound to the corresponding `teamId` can be accessed.
- Configure global variables with the same name, launch tests using accounts from different teams, confirm that variable values do not interfere with each other.
- Submit an internal ticket, verify that approval roles can only view tickets and associated test data under the current `teamId`.
- View operation logs, confirm that only operation behaviors belonging to the account’s current team are recorded, with no cross-team operation records.
