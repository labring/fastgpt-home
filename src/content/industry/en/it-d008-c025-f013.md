# Duty Scheduling and Handover: Operational Duty Management and Internal Work Order Q&A - Permission and Data Isolation

## What This Category of Data Looks Like
This category of data primarily comes from scheduling systems, fault work orders, monitoring alerts, and organizational contact lists. Daily maintained documents include duty rosters, handover records, escalation contact lists, and daily duty reports. Data is updated daily or weekly. Each individual data entry contains fields such as duty time period, duty personnel, pending items, and escalation paths. It only records objectively relevant operational duty content, with no additional statistical percentage data.

## Constraints Imposed on Permission and Data Isolation
Data sources include sensitive operational information such as organizational contact lists and fault work orders, so access scope must be isolated by team or duty group. The daily/weekly update frequency requires that permission configurations support real-time synchronization with personnel changes and scheduling adjustments. Documents such as duty rosters and handover records contain sensitive content like pending items and escalation paths, so access must be restricted to only corresponding duty personnel and management personnel. Specific duty time period data associated with the scheduling system must be bound to `teamId` and `tmbId` to implement fine-grained permission control, preventing cross-group viewing of unauthorized duty schedules and handover records.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `teamId` | Bind to the unique identifier of the operational team | Isolate duty scheduling and internal work order data by operational team, matching team-level permission management requirements |
| `tmbId` | Bind to the unique identifier of the duty group | Segment permissions by specific duty group, preventing cross-group viewing of unauthorized duty schedules and handover records |
| Permission synchronization cycle | Synchronize once every 12 hours | Match the daily/weekly update frequency of this category of data, ensuring permissions stay consistent with the latest scheduling and personnel changes |
| Sensitive document access scope | Only visible to duty personnel and direct management personnel | Duty rosters and handover records contain sensitive content such as pending items and escalation paths, so access permissions must be strictly controlled |
| Cross-team data masking | Mask unauthorized team data by default | Prevent unrelated operational teams from viewing unauthorized scheduling and work order information, meeting security requirements for operational scenarios |
| Single data entry access validity period | Valid within 24 hours | Match the daily update frequency of this category of data, ensuring expired duty scheduling data cannot be accessed |

## Three Common Misconfigurations
- An SQL permission error occurs after restarting the deployment service, and duty scheduling data fails to load. The cause is failing to re-sync permission association configurations after restarting, which causes the database access permission binding to become invalid.
- Cross-operational-team viewing of duty rosters and handover records from non-associated teams. The cause is not enabling the permission filtering rules bound to `teamId`, or setting an overly long permission synchronization cycle that fails to update personnel and team association relationships in a timely manner.
- Duty personnel cannot view pending work orders for their assigned time periods. The cause is failing to bind the duty personnel account to the `tmbId` of the corresponding duty group, resulting in failed permission verification.

## How to Confirm the Configuration Is Correct
- Use an unauthorized operational team account to access the system, confirm that duty rosters and handover records from the corresponding team cannot be viewed.
- Check the permission synchronization logs, confirm that the permission synchronization cycle has been executed as configured, with no abnormal errors.
- Log in with a duty personnel account, confirm that pending work orders and escalation contact lists for their assigned time periods can be viewed.
- After restarting the deployment service, check whether duty scheduling data loads normally, with no permission-related errors.
