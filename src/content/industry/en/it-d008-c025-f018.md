# On-Duty Scheduling and Handover: Operations On-Duty and Internal Work Order Q&A — Reranking and Hybrid Retrieval

## What this category of data looks like
Data for this category comes from scheduling systems, fault work orders, monitoring alerts, and organizational contact lists. Data updates occur daily or weekly. Daily documents include on-duty schedules, handover records, escalation contact lists, and on-duty daily reports. On-duty schedules contain fields for on-duty date, on-duty personnel, and contact information. Handover records document open work orders, pending follow-up items, and escalation paths. Escalation contact lists identify secondary contacts for each operations team.

## What constraints do these characteristics impose on the reranking and hybrid retrieval link
Data sources are scattered and have different update rhythms. Scheduling system data updates daily, while organizational contact lists update weekly. Hybrid retrieval must adapt to timeliness weighting across different data sources. Daily document structures vary significantly: on-duty schedules are structured field data, while handover records are mostly unstructured text. The reranking link must adjust matching priorities for different document types. The core scenarios for this category focus on scheduling conflict coordination, pending item handover, and escalation path confirmation. Retrieval must prioritize recalling corresponding high-value fields to avoid irrelevant results interfering with core decision-making.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Similarity Threshold | `0.72–0.85` | Matches the precision requirements of structured fields in on-duty schedules, avoids recalling irrelevant scheduling records |
| Single Recall Limit | `Top 8 entries` | Covers core handover and scheduling data within a single on-duty cycle, avoids excessive results disrupting retrieval |
| Search Mode | Hybrid Retrieval | Combines keyword matching and semantic retrieval to meet hybrid retrieval needs for structured and unstructured documents |
| Reranking Toggle | Enabled | For unstructured text in handover records, uses reranking to improve the recall ranking accuracy of pending items and escalation paths |
| Retrieval Timeout Threshold | `60 seconds` | Adapts to response times for multi-data-source retrieval, prevents retrieval failures due to delays in scheduling system interfaces |

## Three Common Mistakes
- The locally deployed reranking model does not display in the interface. Cause: The access address and security credentials for the reranking model were not correctly configured in the FastGPT configuration file, causing the platform to fail to recognize the locally deployed service.
- Retrieval result ranking does not align with business priorities, with pending items not appearing at the top. Cause: The reranking toggle was not enabled, or the similarity threshold was set incorrectly, leading to incorrect ranking of unstructured handover records.
- The number of retrieval results is lower than expected. Cause: The single recall limit was set too low, or some interfaces timed out during multi-data-source retrieval, leading to failure to recall complete data.

## How to Confirm Proper Configuration
- Navigate to the knowledge base configuration page in FastGPT v4.17.0 or later, confirm that the reranking toggle is enabled.
- Initiate a test retrieval that includes keywords for on-duty dates and open work orders, verify that the returned results are ranked in line with business priorities.
- Check the retrieval logs to confirm that recalled data from all multi-data sources has been loaded normally, with no timeout or connection errors.
- After adjusting the similarity threshold, verify that the number and relevance of recalled results meet business requirements.
