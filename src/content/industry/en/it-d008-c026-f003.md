# Operations on-duty and internal work order Q&A for level content creation: Sharing and embedding

## What data looks like for this category
Usually, data sources for this category are level editors, art resource libraries, player test data, and defect tracking systems. Update cycles are weekly or per version iteration. Daily produced documents include level design drafts, resource requirement sheets, test feedback forms, and version submission records. Level design drafts contain path node coordinates and resource mounting tags. Test feedback forms mark defect severity and repair status. Version submission records track submission times and change details. All documents are associated with a unique project identifier.

## What constraints these characteristics impose on the sharing and embedding workflow
Since data originates from multiple tools and is tied to project-unique identifiers, the sharing and embedding workflow must use external identity verification systems to enforce access permission controls at the project level, to avoid cross-project data leaks.
Document types cover multi-format content such as design drafts and feedback forms. Embedding configurations must support parsing rules for multiple unstructured text formats.
The weekly or per-version update cycle requires that associated external business systems or knowledge bases can flexibly configure synchronization update cycles to adapt to project content iteration needs.
Errors in level content directly lead to level blocks or launch delays. Associated external business systems or knowledge bases must link to the original data’s version identifier to ensure returned content matches the current project version.

## Three common mistakes
- Sharing entries related to level content creation fail to open. First verify the full system-generated link and its validity period, then check browser request statuses; do not manually replace `shareId`.
- The visible scope of level content creation data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately; the sharing entry identifier itself does not provide business authorization.
- The same level content creation Q&A is not visible on another device. For anonymous scenarios, first check device, browser, and local identity status; retention is not guaranteed across devices or after cache clearing; do not judge service anomalies solely based on this phenomenon.

## How to confirm configurations are set correctly
- Access the embedded generated share link, enter test keywords for the corresponding project, and verify that returned results include level design-related content for that project.
- View embedded service logs to confirm that the `shareId` of the share link has been properly parsed by the system, with no invalid sharing entry or permission error prompts.
- Manually update resource submission records within the project, wait for the synchronization cycle of the associated external business system or knowledge base to end, and verify that Q&A results include the latest change details.
- Invite unauthorized external personnel to access the share link, confirm that they cannot query level design content for that project.
