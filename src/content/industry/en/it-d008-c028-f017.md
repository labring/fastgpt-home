# Operations on-duty and internal ticket answering for content recommendation operations: Deployment and Upgrade

## What this category of data looks like
Data for this category typically comes from content tag libraries, user behavior logs, online experiment platforms, and recommendation backends. Daily produced documents include recommendation strategy records, content pool lists, experiment reports, and operational reviews.
Data update cycles are daily or weekly. Core fields include content classification tags, user interaction metrics, experiment group identifiers, and recommendation exposure volumes. Statistical dimensions must be adjusted based on specific operational scenarios; there is no fixed unified standard.

## What constraints do these characteristics impose on the deployment and upgrade phase
Data sources for content recommendation operations are scattered and updated frequently. Deployment must support access configuration for multiple data sources, to avoid content pool synchronization interruptions caused by insufficient storage capacity.
Daily documents include structured strategy records and unstructured experiment reports. Deployment must configure parsing parameters compatible with mixed formats.
Data is linked to core operational metrics. The upgrade phase must ensure seamless service switching, to avoid downtime that interrupts recommendation strategies.
Additionally, operations on-duty and ticket answering require real-time association with data status. Post-deployment link verification must be completed quickly to ensure timely response for exception troubleshooting.

## How to set configurations
This configuration applies to FastGPT v4.17.0, adapted for content recommendation operation scenarios.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150 connections` | Adapts to the large number of daily new data connection requests from the content pool, avoiding connection pool exhaustion that disrupts content synchronization |
| `MONGODB_URI` | `mongodb://mongo:27017/fastgpt` | Standard container address for storing unstructured data such as content tags and experiment reports |
| `REDIS_URL` | `redis://redis:6379/0` | Caches user behavior logs and recommendation strategies, reducing pressure from high-frequency database queries |
| `FE_DOMAIN` | `https://internal-ops.your-domain.com` | Configures the frontend access address for operations on-duty and internal ticket answering, ensuring notifications reach operations personnel normally |
| `FILE_TOKEN_KEY` | `32-character random string` | Encrypts access tokens for sensitive documents such as content pool lists, preventing unauthorized access to core operational data |
| `AIPROXY_API_ENDPOINT` | `http://aiproxy:3000` | Root address of the AI Proxy service, used to connect to AI Proxy dependent services |
| `AIPROXY_API_TOKEN` | `Non-empty string matching the AI Proxy server configuration` | AI Proxy admin token, used for authentication when the App/Admin service connects to AI Proxy |

## Three common mistakes
- Symptom: Service fails to start after launching with docker-compose, with logs indicating missing environment variables. Cause: Required `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` environment variables are not configured, and the container is not recreated to load new configurations, resulting in startup verification failure.
- Symptom: Interface calls report errors after offline deployment, indicating the cl100k.tiktoken file cannot be found. Cause: Local tokenizer model dependencies are not configured, and the service attempts to pull files from the public internet by default, which does not meet offline deployment requirements.
- Symptom: Internal ticket answering cannot respond to queries related to recommendation strategies. Cause: The AI Proxy admin token is incorrectly filled with the application API key, resulting in interface authentication failure and inability to access content pool and experiment report data in the knowledge base.

## How to confirm configurations are correct
- Run `docker logs fastgpt-app` to view startup logs, confirm there are no error messages about missing environment variables or authentication failures.
- Call the internal operations interface, pass a valid `AIPROXY_API_TOKEN`, verify that the ticket answering module can normally return data related to content pool lists.
- Access the configured `FE_DOMAIN` address, confirm that the operations on-duty panel loads normally and displays service running status.
- Test the tokenizer function in an offline deployment scenario, confirm that local dependent files can be loaded normally without an internet connection.

The values provided are common starting points and should be measured against the reader's own samples.
