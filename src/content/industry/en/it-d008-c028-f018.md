# Operations on-duty and internal ticket Q&A for content recommendation operations: Reranking and Hybrid Retrieval

## What data looks like for this category
Content recommendation operations teams create daily documents including recommendation strategy records, content pool lists, experiment reports, and operation reviews. They source data from content tags, user behavior logs, experiment platforms, and recommendation backends. The content pool list includes fields such as content identifiers, classification tags, and release times. Recommendation strategy records document recall rules and threshold configurations. Experiment reports cover A/B test metrics and user feedback data. Most content pools update daily, while strategy reviews update weekly. Individual document character counts vary widely, with no fixed standard length.

## What constraints these characteristics impose on the reranking and hybrid retrieval link
Content recommendation operations data pulls from multiple business systems. Teams must use hybrid retrieval to integrate multi-source data and match content tags and user behavior characteristics. Documents mix strategy configurations and business review content, so the reranking link must prioritize relevance matching for core business fields. Data updates happen daily or weekly, so teams must synchronize retrieval indexes regularly to keep content fresh. Individual documents have widely varying character counts, so reranking calculations must adapt to different content lengths. This prevents resource waste or incomplete recall. Errors in this workflow directly impact core business metrics, so teams must align reranking configuration strictly with content pool filtering rules. This stops low-quality content from being amplified.

## How to set configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Enable reranking | Enabled | Content recommendation operations need to filter low-quality recall results to meet the quality requirements of business distribution |
| Similarity threshold | 0.65–0.75 | Match the matching accuracy requirements for content tags, avoid missing high-quality content within the valid content pool |
| Single recall limit | Top 10 entries | Align with the conventional display limit for content distribution, control computing resource consumption during the reranking link |
| Search mode | Hybrid recall | Integrate multi-source data including content tags and user behavior logs, improve the comprehensiveness of recall results |
| Number of entries retained after reranking | Top 5 entries | Focus on high-quality content in the core content pool, reduce the screening workload for operation reviews |

## Three common mistakes
- Phenomenon: No search results appear in the application after enabling reranking, but the knowledge base test works normally. Cause: Multi-source data association rules for hybrid retrieval are not configured, causing the application layer’s recall pool to differ from the knowledge base test pool.
- Phenomenon: The number of results after reranking does not match the configured single recall limit. Cause: The result truncation threshold after reranking is not set correctly, causing some eligible content to be filtered out additionally.
- Phenomenon: Reranking results do not meet business expectations, and core content is not ranked first. Cause: Content tag weights are not configured in the reranking model’s calculation rules.

## How to confirm proper configuration
- In the FastGPT v4.17.0 knowledge base test interface, enable the reranking function, enter a test question, and verify that returned results sort according to content tag priority.
- Check the application’s retrieval logs to confirm that reranking model call counts match the configured single recall limit parameter.
- Compare retrieval results when reranking is enabled and disabled to confirm that low-quality content proportion meets business expectations.
- Review multi-source data synchronization status to confirm that content pool list and user behavior log update frequencies match configured update rules.
