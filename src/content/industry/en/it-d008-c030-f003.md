# Internal Network and WiFi Operations: On-Duty Support and Internal Ticket Q&A - Sharing and Embedding

## What data for this category includes
Data sources for this category include switch consoles, wireless controllers, office area monitoring systems, and frontline user trouble reporting channels. Data updates occur daily or immediately when network changes are made. Daily associated documents include network topology diagrams, change orders, fault records, and wireless coverage inspection forms. Data fields include port numbers, VLAN identifiers, wireless signal strength, workstation locations, trouble reporting times, and other relevant fields. Some fields use standardized units, such as dBm for signal strength.

## What constraints do these characteristics impose on sharing and embedding?
Data sources are scattered across multiple types of devices and trouble reporting channels. When embedding, trigger rules must be configured via an external multi-source data synchronization system to ensure embedded Q&A can call the latest device status and fault records. Data updates are synchronized immediately upon network changes. The knowledge base connected via embedding must be synchronized by the external data synchronization system to match the data update rhythm. FastGPT only supports connecting to knowledge bases that have completed synchronization, to avoid returning outdated network configuration information. Documents include materials with structured fields. When embedding, specify the retrieval weight for corresponding fields to ensure quick matching of key information such as ports and VLANs during fault location. In addition, for sensitive configurations related to office networks, sharing and embedding permissions must be bound to the enterprise's internal access scope via an external access control system, to prevent unauthorized access.

## Three common configuration errors
- Failure to open the sharing entry related to internal network and WiFi operations. First verify the full link generated by the system and its validity period, then cross-check browser request statuses; do not manually replace `shareId`.
- Visibility range of internal network and WiFi operation data does not match expectations. Cross-check third-party identity verification results, workflow request parameters, and data permissions of external systems; the sharing entry identifier itself does not provide business authorization.
- The same internal network and WiFi operation Q&A is not visible on another device. For anonymous scenarios, first verify device, browser, and local identity status; retention is not guaranteed across devices or after cache clearance, and service anomalies cannot be judged solely based on this phenomenon.

## How to confirm successful configuration
- The office page with the embedded function is accessed, a troubleshooting question including a specific port number or workstation location is entered, and returned results are verified for corresponding operation and maintenance information.
- The browser console for the embedded code is checked, loading errors are confirmed absent, and page loading speed is verified to meet daily office usage standards.
- The embedded page is accessed after the share link validity period has expired, successful loading of Q&A content is confirmed to be blocked, and permission control effectiveness is verified.
- A fault record is modified, external data synchronization is triggered, the same query is initiated again, and returned results are confirmed to include the updated record content.
