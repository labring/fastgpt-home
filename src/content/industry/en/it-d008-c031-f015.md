# Operations on-call and internal ticket Q&A for creator onboarding and verification: Knowledge base retrieval and recall

## What the data for this category looks like
Typically, business data for creator onboarding and verification originates from creator backends, enterprise credit information query APIs, account history systems, and partner contract management systems. Daily processed documents include onboarding application forms, identity qualification scans, audit review workflow records, and cooperation framework agreements.
Data updates are triggered per individual application or synced in daily batches. Fields include account unique identifiers, qualification numbers, audit statuses, cooperation periods, and more. Some fields are structured, while others are free text with no unified fixed format.

## Constraints on knowledge base retrieval and recall
Dispersed data sources and varied field formats require knowledge base retrieval to support cross-data-source associated matching, to avoid missing cross-system related information.
Updates triggered per application require the knowledge base to support incremental sync, ensuring the latest qualification audit records can be retrieved in a timely manner.
Varied document structures require retrieval strategies to balance matching accuracy for both structured fields and free text.
The most time-consuming qualification verification step requires recall results to have high precision, to avoid irrelevant content interfering with audit judgments. Otherwise, issues such as false certifications or mismatched account entitlements may occur.

| Configuration Item | Recommended Setting | Rationale |

| `limit` | Top 8 entries | Balances context length for internal ticket processing and recall comprehensiveness, avoiding processing overload from excessive results |
| `usingReRank` | Enabled | Text related to onboarding has significant format differences; reranking improves precise matching accuracy and optimizes recall effects for qualification verification |
| `datasetSearchUsingExtensionQuery` | Enabled | For structured fields such as account IDs and qualification numbers, optimize queries to expand retrieval scope and improve recall rates for structured data |
| `collectionIds` | Bound to the dedicated knowledge base collection for creator onboarding and verification | Isolates business data to avoid interference with knowledge base content from other categories |

## Three common configuration errors
- `quote type error`: The symptom is a format error prompt returned when referencing configuration variables. The cause is failing to pass variables according to the format requirements of knowledge base fields, such as using incorrect wrapping symbols or mismatched formats for qualification number fields.
- Fully matched chunks cannot be recalled: The symptom is that text blocks identical to a query are not recalled under a specific knowledge base, but a newly created knowledge base with the same content can recall them normally. The cause is that the chunking parameters of the old knowledge base do not match the current retrieval configuration, or the `searchMode` configuration is not unified.
- No source annotation for retrieval results: The symptom is that retrieved results do not display knowledge base reference information. The cause is failing to enable the reference display switch, or failing to retain source association information for original chunks after reranking operations.

## How to verify correct configuration
- Submit a test query containing qualification numbers and account IDs, check if the similarity of returned results falls within the 0.75–0.85 range, to verify that the `similarity` configuration is active.
- Check the number of returned retrieval results, confirm it does not exceed 8 entries, to verify that the `limit` configuration value matches the set value.
- Pass a qualification number variable with correct formatting, confirm no `quote type error` is returned, to verify that variable reference configuration is correct.
- Compare retrieval results from old and new knowledge bases, confirm that after unifying the `searchMode` configuration, the recall logic for identical content is consistent, to verify that the collection binding configuration is active.
