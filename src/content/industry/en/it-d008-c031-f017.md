# Operations On-Call and Internal Ticket Q&A for Creator Onboarding and Certification: Deployment and Upgrade

## What This Category of Data Looks Like
This category of data typically originates from creator backends, enterprise credit information query APIs, account historical behavior repositories, and contract systems. Daily processed documents include onboarding application forms, identity qualification scan copies, certification audit records, and cooperation agreement texts. Data updates are triggered by creator applications, with one complete set of associated data per single application. Fields include application number, qualification type, audit status, bound account information, and other relevant details. No fixed batch update cycle exists.

## Constraints Imposed by These Characteristics on Deployment and Upgrade
Data for this category is multi-source, decentralized, and updated only when applications are submitted. Deployment must meet stability requirements for connecting to multiple data sources. Daily processed qualification documents and contract texts vary widely in size, so sufficient storage and file parsing resources must be reserved. Audit records have relatively high real-time requirements. The deployment phase must configure appropriate cache and database connection limits to prevent service interruptions during application peaks. During upgrades, compatibility logic for original data fields must be retained to avoid mismatches in certification status and cooperation agreement association relationships.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 80–120 connections | Adapts to database connection peaks during bulk creator applications in a single day, preventing connection exhaustion |
| `MONGODB_URI` | Cluster address with read-write separation suffix | Stores audit records and account historical data; cluster deployment ensures read-write stability for concurrent application requests |
| `REDIS_URL` | Standalone instance with no less than 2000 MB of memory | Caches qualification verification results and temporary application data, reducing repeated calls to multi-source APIs |
| `STORAGE_S3_ENDPOINT` | Configured according to service provider access standards | Stores qualification scan copies and cooperation agreement files, adapting to file upload bandwidth requirements of different scales |
| `FILE_TOKEN_KEY` | Randomly generated 32-character string | Encrypts file download links, preventing unauthorized access to sensitive qualification materials |

## Three Common Misconfigurations
- Database connection timeout errors occur during local Docker deployment: The cause is incorrect configuration of the `DB_MAX_LINK` parameter, or the `MONGODB_URI` not specifying the correct database instance port, leading to connection exhaustion during application peaks.
- Qualification file upload fails with a permission error: The cause is the storage endpoint configured in `STORAGE_S3_ENDPOINT` not being granted read-write permissions, or incorrect configuration of `FILE_TOKEN_KEY` leading to failed encryption verification.
- Certification status association anomalies appear after upgrade: The cause is failure to maintain compatibility with the field format of original account historical data, leading to broken binding relationships between onboarding applications and certification audit records.

## How to Verify Proper Configuration
- The official deployment script for FastGPT v4.17.0 is used to run basic configuration verification, confirming that all configuration items have no syntax errors.
- 100 concurrent simulated onboarding application requests are initiated, verifying that database connection and cache configurations can stably support concurrent traffic.
- A test qualification file is uploaded, confirming that it can be stored normally and an accessible download link is generated using `FILE_TOKEN_KEY`.
- The audit record query API is checked, confirming that no anomalies exist in the fields and association relationships of original historical data.
