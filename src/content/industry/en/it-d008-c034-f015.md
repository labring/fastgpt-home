# Operational Duty and Internal Work Order Q&A for Office System Process Configuration: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Core data for this category comes from enterprise OA systems, organizational structure databases, internal policy documents, and user feedback work orders. Daily produced documents include process configuration sheets, approval node tables, form field descriptions, and change records.
Process changes trigger data updates, with a regular update frequency of once per month. The core data structure centers on approval paths, permission rules, and form fields. No unified fixed unit exists; values adjust based on specific configuration items.

## What Constraints These Characteristics Impose on Knowledge Base Retrieval and Recall
Data for this category is scattered across multiple internal systems and documents. Retrieval must support cross-source associated recall to avoid siloed knowledge base results.
Process configuration documents primarily use structured rules. Retrieval must accurately match approval nodes, permission fields, and form configurations. Fuzzy matching can produce incorrect results.
Process changes trigger data updates, with a regular monthly update frequency. The knowledge base synchronization mechanism must adapt to non-fixed-cycle incremental updates.
Approval exceptions directly result from incorrect retrieval returns. Retrieval and recall accuracy must be prioritized to avoid returning irrelevant configuration rules that cause approval exceptions.

## How to Set Configurations
The following configurations are based on the knowledge base retrieval logic of FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | Matches structured office process configuration rules, prevents irrelevant results from too low a threshold, and prevents valid configurations from being missed with too high a threshold |
| `limit` | Top 8 entries | Covers common approval node and permission combination configurations, prevents excessive redundant data from hindering troubleshooting |
| `searchMode` | Exact Match | Adapts to structured process configuration fields, prioritizes exact matches for approval rules, node names, and similar content |
| `usingReRank` | Enabled | Re-ranks recall results by relevance, optimizes display order for approval rule-related content |
| `datasetSearchUsingExtensionQuery` | Enabled | Associates organizational structure data, supplements approval permission configurations corresponding to the user’s department |

## Three Common Misconfigurations
- Phenomenon: Knowledge base retrieval takes longer than 40 seconds, with noticeable result delay. Cause: Recall parameters have not been adjusted for structured process configuration data, and cross-source retrieval association logic has not been optimized.
- Phenomenon: When importing CSV-format QA data, submission fails because the Q field exceeds the length limit. Cause: The knowledge base single-text length threshold has not been adjusted; the default limit does not match the long text in process configuration sheets.
- Phenomenon: Retrieval results do not include the latest process change records. Cause: Incremental synchronization triggered by changes has not been configured, and fixed-cycle full updates are still used.

## How to Confirm Configuration is Complete
- Submit a simulated operational work order, retrieve the configuration content for a specified approval node, and verify that the returned results include the corresponding approval rules and permission descriptions.
- Trigger a knowledge base synchronization task after a process change, and verify that the newly added configuration sheet can be accurately retrieved.
- Adjust retrieval parameters, compare the number of returned results and latency before and after the adjustment, and confirm that the parameter changes take effect.
- Check cross-source associated organizational structure data, and confirm that the retrieval results include approval permission configurations corresponding to the current user’s department.
