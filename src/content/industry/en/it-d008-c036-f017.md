# Prototype and Interaction Design for Operations On-Call and Internal Ticket Q&A: Deployment and Upgrade

## What this category of data looks like
Typically, work data for prototype and interaction design comes from Figma or Axure files, internal design systems, user feedback, and usability test records. Daily output documents include interactive prototypes, page flowcharts, component descriptions, and review records. Data update frequency is mostly weekly or per version iteration. The document structure centers on page paths, operation steps, and component attributes as core fields. Some files contain embedded interaction logic and associated resources, with no unified standardized format.

## What constraints do these characteristics impose on deployment and upgrade
Prototype and interaction design documents often contain large-volume design files and frequently accessed component information. During deployment, sufficient storage and cache resources must be configured to avoid file upload or preview failures. Due to the high frequency of data updates, the database connection configuration must adapt to concurrent demands for batch document import during upgrades, to prevent service interruptions. The internal operations and ticket Q&A scenario requires the service to be accessible only to internal teams. Correct access domain name and token encryption parameters must be configured to prevent unauthorized access. At the same time, the required environment variables `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service; do not append paths such as /v1 or /chat/completions, and do not use single-model service addresses such as VLLM/Ollama/Xinference) and non-empty `AIPROXY_API_TOKEN` (administrator token consistent with the AI Proxy server configuration) must be configured on the App/Admin server. Otherwise, service startup verification will fail, and AI capabilities cannot be properly called to handle queries related to tickets and design documents.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale for this setting |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://admin:secure_pass@mongodb:27017/fastgpt?authSource=admin` | Stores prototype metadata, ticket records, and design review information; must specify authentication information and target database |
| `REDIS_URL` | `redis://:redis_secure_pass@redis:6379/0` | Caches frequently accessed design system components and ticket sessions to reduce database concurrency pressure |
| `DB_MAX_LINK` | `20–30` | Adapts to concurrent database connection demands during batch prototype file import, avoiding service exceptions caused by exhausted connections |
| `FE_DOMAIN` | `http://internal-design-ops:8080` | Configures the access domain name for internal operations and design teams, ensuring normal redirection of ticket notifications and prototype preview links |
| `FILE_TOKEN_KEY` | `Randomly generated 32-bit hexadecimal string` | Encrypts access tokens for design files to prevent unauthorized access to internal prototype resources |
| `STORAGE_S3_ENDPOINT` | `http://minio.internal:9000` | Stores Axure and Figma exported prototype files, matching the root address of the internal object storage service |

## Three common mistakes
- Symptom: A verification failure error appears when starting the FastGPT service, prompting that `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN` is missing. Cause: The required environment variables `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service) and non-empty `AIPROXY_API_TOKEN` (administrator token consistent with the AI Proxy server configuration) were not configured on the App/Admin server. They were mistakenly filled into workflow global variables, application API request headers, or the common model management page. External calling of application APIs must not use the AI Proxy administrator token instead of the application API Key.
- Symptom: After upgrading to FastGPT v4.17.0, file processing plugins fail to load, and background logs prompt abnormal file access permissions. Cause: `FILE_TOKEN_KEY` was not configured correctly, causing access token verification for design files to fail, and the plugin cannot load normally.
- Symptom: Database connection timeout errors occur during batch import of prototype files. Cause: The value of `DB_MAX_LINK` is too low, exhausting the database connection pool when concurrently processing document imports.

## How to confirm the configuration is correct
- Start the App/Admin service, check the startup logs, and confirm there are no prompts for missing required environment variables or verification failures.
- Upload a small Axure prototype file, confirm that the file can be stored normally and previewed on the front-end page.
- Submit an internal operations ticket, test that the ticket status transition can be updated normally and pushed to relevant personnel.
- Access the internal address configured in `FE_DOMAIN`, confirm that the front-end page can load normally, and that AI capabilities can be called to handle design-related queries.

The values provided are common starting points and should be measured against the reader's own samples.
