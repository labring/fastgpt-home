# Operations on-duty and internal work order Q&A for prototyping and interaction design: Re-ranking and hybrid retrieval

## What data looks like for this category
The data for this category primarily comes from Figma or Axure files, internal team design systems, user feedback records, and usability test archives. Daily produced documents include interactive prototypes, page flowcharts, component specification descriptions, and design review records. Data update cycles are mostly weekly synchronization or aligned with product version iterations. Document fields typically include page hierarchy identifiers, component interaction logic, review opinion status, and test feedback entries. Some prototype files will mark pixel dimensions or interaction trigger conditions, with no unified mandatory measurement standards.

## What constraints these characteristics impose on re-ranking and hybrid retrieval
Since most data in this category consists of nested interactive prototypes and review records, the re-ranking link must first identify page hierarchies and component association relationships to avoid retrieving irrelevant isolated fields. Data update frequency is relatively high, so the retrieval range for hybrid retrieval must adapt to weekly or version-level update cycles to avoid retrieving expired prototype versions. Documents contain two types of content: interaction logic and review opinions, so hybrid retrieval must distinguish the weight of different document types to prevent confusion between review modification opinions and prototype design logic. Additionally, the proportion of supplementary documents for abnormal scenarios is not fixed, so the re-ranking retrieval threshold must adapt to unstructured design text features.

## Three Common Mistakes
- Phenomenon: Re-ranking service calls return a 500 status code or no valid results. Cause: Custom channel parameters for the re-ranking service are not configured correctly, or channel access permissions have not been fully enabled.
- Phenomenon: A large number of irrelevant expired prototype versions or non-design documents are mixed into hybrid retrieval results. Cause: A reasonable similarity threshold is not set, or differentiated recall rules are not configured for different document types.
- Phenomenon: The number of single-round retrieval results exceeds expectations, causing model context overflow. Cause: The retrieval upper limit parameter is not set to a value range adapted to the length of design documents, or the actual number of returned retrieval results is not verified.

## How to Confirm Proper Configuration
- Perform a single-round retrieval test related to on-duty work orders, check whether the returned document types cover interactive prototypes and design review records.
- View the re-ranking service call logs, confirm that the service request format and return status are normal.
- Compare the recall results of semantic retrieval and hybrid retrieval, confirm that the hybrid retrieval range meets the retrieval requirements for design documents.
- Adjust the similarity parameter range, verify whether the relevance of returned results shows a reasonable adjustment trend as the parameters change.

The values provided are common starting points and should be measured against the reader's own samples.
