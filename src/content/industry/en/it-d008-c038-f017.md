# Operations On-Call and Internal Ticket Q&A for Change Management and Release Windows: Deployment and Upgrade

## Data Characteristics of This Category
Data sources include change management systems, CI pipelines, monitoring data, and business calendars. Data updates occur weekly or after each change. Associated documents consist of change request forms, risk assessment reports, release window schedule plans, and rollback plan documents. Core fields include change unique identifier, effective window time period, risk rating level, approval node status, and rollback trigger threshold. Only workflow node status and time node information are recorded. No additional custom statistical values are included.

## Constraints During Deployment and Upgrade
Data sources involve integration with multiple systems. Cross-system synchronization parameters must be configured during deployment to ensure real-time pulling of change data. Update frequency fluctuates with change frequency. A configuration item for dynamically adjusting synchronization intervals must be reserved after deployment. Associated documents have inconsistent formats. Multiple document parsing rules must be adapted during deployment to support extraction of specified fields. Core fields must strictly match required items of the change workflow. Field integrity must be verified during deployment to avoid workflow interruptions. Time configuration for change windows must align with business calendars. Check logic for window time periods must be preset during deployment to prevent change operations from being triggered outside valid windows.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0, optimized for the operations on-call and internal ticket Q&A scenario for change management and release windows.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `80–120 connections` | Limits the maximum number of database connection pool connections, adapts to high-frequency data queries in change management scenarios |
| `MONGODB_URI` | `mongodb://admin:securepass@db-host:27017/fastgpt?authSource=admin` | Stores full workflow business data including change requests, risk assessments, and related records |
| `REDIS_URL` | `redis://:redispass@cache-host:6379/0` | Caches change window check rules and ticket Q&A context. Set cache validity period to 300 seconds |
| `FE_DOMAIN` | `https://ops-fastgpt.your-company.com` | Configures the domain for internal operations access, ensures normal loading of the change management module |
| `STORAGE_S3_ENDPOINT` | Calibrated based on actual testing | Connects to enterprise object storage service, stores change-related documents and rollback plan attachments |
| `FILE_TOKEN_KEY` | Random 32-character encrypted string | Generates access tokens for ticket attachments, ensures access security for change documents |

## Three Common Configuration Mistakes
- Symptom: Attachments in the change management module fail to download normally. The interface displays "Invalid access token". Cause: The `FILE_TOKEN_KEY` configuration value does not match the secret key used to generate attachment access tokens, causing verification failure.
- Symptom: The operations interface displays in English, and cannot be switched to Chinese. Cause: The localization resource loading path is not configured correctly, or the Chinese language pack file is omitted when deploying the image.
- Symptom: Approval status of change tickets cannot be synchronized and updated. The workflow gets stuck with no progress. Cause: The database permissions configured in `MONGODB_URI` are insufficient, making it impossible to write approval status data, leading to workflow interruption.

## Verify Successful Configuration
- Run the database connection test script to verify that the `MONGODB_URI` and `REDIS_URL` configurations can establish normal connections.
- Upload a change request document, initiate a download request through the internal ticket Q&A module, and confirm that attachments load normally.
- Access the configured `FE_DOMAIN` address, confirm that the operations interface loads normally, and no obvious configuration error prompts are displayed.
- Simulate submitting a test change request, check whether the approval status can be written to storage normally, and verify that the connection pool configuration does not trigger exceptions.

The values provided are common starting points and should be evaluated against the operator’s own test samples.
