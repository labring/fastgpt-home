# Operations On-Duty and Internal Ticket Q&A for Security Training and Phishing Drills: Permission and Data Isolation

## What the Data for This Category Looks Like
The core data for this category includes four types: training courseware, drill plans, phishing email templates, and drill result reports. Data sources typically include employee contact lists, enterprise email gateways, internal training platforms, and user click statistics systems. Data updates occur mostly quarterly or annually. Individual document structures include fields such as scenario classification, operation steps, risk level, and statistical results. No unified fixed units apply, and some documents include user behavior data tags.

## Constraints Imposed on Permission and Data Isolation by These Characteristics
Employee contact list data contains private information. Restrict full dataset access to only the security operations team. Phishing email templates count as high-risk content. Divide access permissions by job level to prevent unauthorized personnel from accessing sensitive drill materials. Drill result reports serve as internal audit basis. Retain access logs for different roles. Data updates happen infrequently, so permission rules do not need frequent adjustments. Ensure permission configurations for historical versions take effect synchronously. Different document types have widely varying sensitivity levels. Set differentiated permission granularity separately for courseware, templates, and reports.

## How to Configure Settings
The following configurations are based on FastGPT v4.17.0. Adjust specific parameters based on actual business needs:

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `teamId` | Bind the ID of the corresponding business team, value range 1-5000 | Achieve physical isolation of knowledge base and session data across teams |
| Role permission groups | Divide by job role, such as security operations, internal training, intern | Match permission difference requirements for this category |
| Document access granularity | Set by document type, for example, phishing templates are only accessible to the security team | Adapt to sensitivity levels of different documents |
| Session validity period | 1800 seconds | Control access duration for unauthorized sessions |
| Data storage path | Divide by category, such as /training, /phishing-template, /report | Achieve storage isolation by document type |

## Three Common Misconfigurations
- Symptom: A permission error appears when testing a locally deployed model, with the interface displaying "No access permission". Cause: The team ID for the model deployment is not bound via `teamId`, so cross-team calls to model resources fail.
- Symptom: Intern accounts can view phishing email template documents. Cause: Differentiated access granularity is not set based on document sensitivity, so high-risk documents are configured to be visible to all users.
- Symptom: Some team members cannot view their exclusive drill result reports. Cause: Permission filtering rules based on the user's department are not configured, leading to incorrect data access scope.

## How to Confirm the Configuration Is Correct
- Log in to accounts with different roles, and verify that only documents within the corresponding permission range are accessible.
- View session logs to confirm that only authorized users can initiate security training-related session requests.
- Check whether the `teamId` configuration item matches the ID of the current business team to ensure data isolation works as expected.
- Verify that highly sensitive documents, such as phishing email templates, can only be accessed by specified roles.
