# Operation Duty and Internal Ticket Q&A for Customer Training and Usage Manuals: Deployment and Upgrade

## What the data for this category looks like
This category of data primarily comes from product help centers, customer organizational structures, training recording videos, and ticket systems. Four types of documents are regularly produced: training courseware, user manuals, training attendance sheets, and problem resolution lists. Data updates are triggered by each customer training order or product version iteration. A single data entry includes fields such as customer identifier, corresponding product version, courseware chapter, and Q&A entry. The document structure is split by customer scenario, with each document bound to a specific customer and version range. No universal default configurations span multiple customers.

## What constraints these characteristics impose on deployment and upgrade
Because data for this category is bound to specific customers and product versions, the deployment phase must support isolating data and permission configurations by customer to prevent cross-customer document disclosure. Data updates are triggered by orders and version iterations, so a stable data synchronization interface must be configured during deployment to connect with product help centers and ticket systems, ensuring real-time synchronization of training content and Q&A data. Document types include multi-format content such as recorded video transcripts, courseware, and lists, so deployment must reserve extended space for adapting to multi-source document parsing. During upgrades, compatibility with old version document binding rules must be maintained to avoid invalidation of existing customer training data.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `80–150` | Document and ticket data for this category is updated frequently, so the database connection pool size must be maintained to support multiple concurrent requests |
| `REDIS_URL` | `redis://<deployment host>:6379/1` | Used to cache customer permissions and training document metadata, isolating the cache database to avoid conflicts with other businesses |
| `FE_DOMAIN` | `https://<custom domain>` | Used to generate access links for training documents, ensuring customers can normally access bound training resources |
| `FILE_TOKEN_KEY` | `Randomly generated 32-bit string` | Used to encrypt access tokens for training documents, preventing unauthorized access to customer-specific training content |
| `STORAGE_S3_ENDPOINT` | `Configured per local storage or cloud storage service provider` | Used to store large-volume documents such as training recording videos and courseware, adapting to multi-source storage requirements |
| `ROOT_KEY` | `Strong key configured only during initial deployment` | Used to initialize system administrator permissions, ensuring secure permission configuration during the initial deployment phase |

## Three common mistakes
- Phenomenon: After deploying associated services, accessing the bound link for a training document returns a 405 Method Not Allowed error. Cause: The cross-origin rules for the storage service corresponding to `STORAGE_S3_ENDPOINT` were not correctly configured, or the frontend `FE_DOMAIN` does not match the allowed domain names of the storage service.
- Phenomenon: A database connection exhaustion error occurs after starting the service. Cause: The value of `DB_MAX_LINK` was not adjusted based on the high update frequency of this category, resulting in a connection pool size insufficient to support concurrent requests.
- Phenomenon: After upgrading to FastGPT v4.17.0, the training document permission configuration from the old version becomes invalid. Cause: Existing `FILE_TOKEN_KEY` related configurations were not exported and migrated before the upgrade, causing access tokens to fail to generate normally.

## How to confirm configurations are correct
- Run the database connection test script to verify that the connection pool size configured via `DB_MAX_LINK` can normally handle multiple concurrent requests.
- Access the custom domain bound to `FE_DOMAIN`, generate a test training document access token, and confirm that the token can be properly parsed and points to the corresponding resource.
- Upload a test training courseware to verify that the storage service corresponding to `STORAGE_S3_ENDPOINT` can complete file upload and reading normally.
- Restart the service, then check system logs to confirm there are no connection failure errors related to `REDIS_URL` or `MONGODB_URI`.

The values given are common starting points and should be measured against the reader's own samples.
