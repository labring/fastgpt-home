# Operations on-call and internal work order Q&A for customer onboarding and tenant initialization: Knowledge base retrieval and recall

## What this category of data looks like
Core data for this category is maintained daily by SaaS implementation consultants, customer success managers, and operations onboarding staff. Daily documents include onboarding application forms, tenant configuration sheets, administrator account lists, and delivery confirmation documents.
Data sources cover CRM systems, contract order databases, identity management systems, and product backends. Update frequency is per order or daily.
Core fields include customer identifiers, tenant domain names, permission configuration items, and administrator account information. The number and structure of fields per document are relatively fixed. There is no high-frequency reliance on multi-modal unstructured content.

## Constraints on knowledge base retrieval and recall from these characteristics
Multi-source data association requires customer identifiers to be bound as core matching fields during retrieval. This prevents cross-customer configuration information from being confused.
Fixed document structures require retrieval modes to prioritize matching structured fields. This reduces invalid recalls.
Per-order or daily update frequency requires retrieval to support incremental recall logic. This avoids loading expired tenant configuration content.
Recall results directly affect the accuracy of customer onboarding and permission configuration. The proportion of irrelevant documents mixed in must be strictly controlled.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches structured fields related to customer onboarding, filters irrelevant content with low matching scores |
| `limit` | Top 10 entries | Covers all document entries required for a single onboarding process, avoids missing key configuration items |
| `searchMode` | Exact match | Prioritizes retrieval of core structured documents such as tenant configuration sheets and onboarding application forms |
| `usingReRank` | Enabled | Sorts recall results by customer identifier and tenant domain name, improves the priority of key information |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically supplements extended retrieval terms related to customer identifiers, associates identity data across systems |
| `collectionIds` | Bound to exclusive customer onboarding knowledge base collections | Isolates business data, avoids recalling knowledge base content from other categories |

## Three common mistakes
- Phenomenon: Non-customer onboarding operations work order documents are mixed in retrieval results. Cause: Exclusive `collectionIds` are not bound, leading to recall of knowledge base content from other business lines.
- Phenomenon: Uploaded doc-format onboarding application forms cannot be retrieved normally. Cause: The FastGPT v4.17.0 version’s knowledge base does not have parsing adaptation configured for doc-format documents. Format conversion must be completed before upload.
- Phenomenon: Embedded images in retrieved tenant configuration sheets cannot be displayed normally. Cause: The multi-modal document parsing switch is not enabled, and only text content is parsed by default.

## How to verify correct configuration
- Upload a test onboarding application form, perform retrieval with the specified search term, confirm that only documents related to this category are returned.
- Adjust the value range of the `similarity` parameter, verify that the matching degree of retrieval results meets the expected settings.
- Trigger an incremental update task, confirm that newly added tenant configuration sheets can be retrieved normally without expired content mixed in.
- Check the sorting of retrieval results, confirm that after `usingReRank` is enabled, core fields such as customer identifier and tenant domain name are displayed first.

The values provided here are common starting points and should be measured against the reader's own samples.
