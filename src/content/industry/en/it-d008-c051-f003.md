# Customer Data Import and Migration: Operations On-Call and Internal Ticket Q&A, Sharing and Embedding

## What This Category of Data Looks Like
The core data for customer data import and migration includes business data exported from the customer’s legacy systems, import templates in CSV/Excel format, field mapping tables, migration plan documents, and import validation reports. Data sources cover the customer’s original business systems, database export files, standardized import templates, and other channels. Update frequency is customized per order, with no fixed cycle. Daily maintained documents focus on structured field mappings, migration step descriptions, and validation result records. These documents include details such as business field correspondence and data validation rules. Errors may cause business data misalignment or loss.

## Constraints Imposed by These Characteristics on the "Sharing and Embedding" Link
This category of data contains sensitive customer business information. When sharing and embedding, access scope must be strictly limited. Only internal operations and ticket systems are allowed to call the data. Data updates have no fixed cycle. External knowledge bases or business systems must be used to dynamically synchronize the latest migration plans, field mapping tables, and other documents. The FastGPT sharing component does not have built-in scheduled refresh capabilities. Outdated content that causes migration errors must be avoided. Structured field mappings and validation reports must be retrieved via external system connections. This assists on-call operations staff in quickly checking migration details and reduces time spent manually searching documents. Import logs serve as core validation basis. They must be quickly pulled from the external ticket system for corresponding batch import records to improve problem troubleshooting efficiency.

## Three Common Misconfigurations
- Sharing entries related to customer data import and migration fail to open. First check the complete system-generated link and its validity period. Then compare browser request statuses. Do not replace `shareId` yourself.
- The visible scope of customer data import and migration data does not match expectations. Check third-party identity verification results, workflow request parameters, and external system data permissions separately. The sharing entry identifier itself does not provide business authorization.
- The same customer data import and migration Q&A cannot be seen on another device. For anonymous scenarios, check device, browser, and local identity status first. Record retention cannot be guaranteed across devices or after cache clearing. Service abnormalities cannot be judged solely based on this phenomenon.

## How to Confirm the Configuration Is Complete
- Copy the embedding code to the test page of the internal operations system. Verify that the exclusive Q&A interface for customer data import and migration loads normally.
- Submit a test question related to field mapping or dirty data cleaning. Confirm that the system can retrieve the corresponding document fragments and provide accurate responses.
- Check the corresponding external system logs. Confirm that conversation records have been correctly retrieved.
- Embed the page in the mini-program test environment. Verify that it loads normally and there are no cross-domain errors.
