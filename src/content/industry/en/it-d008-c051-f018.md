# Operations on-duty and internal ticket Q&A for customer data import migration: Reranking and hybrid retrieval

## What this category of data looks like
This category of data primarily comes from customer legacy systems, CSV or Excel templates, database export files, and product import logs. Updates occur per order or irregularly. Daily associated documents include data import templates, migration execution plans, field mapping comparison tables, and migration verification reports. Implementation consultants, data implementation engineers, and customer IT liaisons are the service subjects. Data includes business fields, mapping rules, import verification results, and similar content. No unified fixed units exist. Determine values based on the customer’s original system fields and import template requirements.

## What constraints do these characteristics impose on the reranking and hybrid retrieval link
This category has diverse data sources and inconsistent formats. During hybrid retrieval, adapt field structures of different format data sources such as CSV and database exports to avoid field misalignment in retrieval results. Data updates follow no fixed cycle, so support dynamic matching of the latest migration plans, import logs, and verification reports to ensure retrieval results cover the latest configurations. Daily documents are scattered across templates, mapping tables, and reports. The reranking link must integrate associated content, prioritize displaying field mapping rules and exception records related to the current ticket, and meet the need for quick problem location during on-duty operations.

## How to set the configuration
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Similarity threshold | 0.75–0.85 | Filter migration logs and mapping content unrelated to the current ticket, and adapt to the field matching accuracy requirements of imported data |
| Single retrieval limit | Top 10 entries | Limit the number of results returned by a single retrieval to avoid overload during on-duty operations, and meet the needs of quick ticket issue location |
| Search mode | Hybrid retrieval | Integrate vector retrieval and keyword retrieval to adapt to diverse data source formats |
| Reranking switch | Enabled | Rearrange initial retrieval results by field matching degree and exception level, prioritize displaying high-risk records such as field misalignment and data loss |
| Retrieval data source scope | Migration logs, field mapping tables, import templates | Limit retrieval scope to documents exclusive to this category to avoid interference from unrelated content |

## Three common misconfigurations
- Phenomenon: The reranking switch is displayed as false, and retrieval results are not sorted by priority. Cause: The reranking model is not correctly associated with the retrieval task, or the reranking configuration is not bound to the current import migration ticket scenario.
- Phenomenon: Multiple variables after an HTTP request cannot correspond to the specified knowledge base, and retrieval results mix migration data from different customers. Cause: An independent retrieval data source scope is not configured for each variable, leading to cross-customer data confusion.
- Phenomenon: The reranking function fails to load properly on arm architecture systems, and there is no reranking logic in retrieval results. Cause: A reranking model image that only supports amd architecture is used, and the system architecture is not adapted.

## How to confirm the configuration is complete
- View the retrieval configuration interface, confirm that the similarity threshold, single retrieval limit, search mode, and reranking switch settings match the expected values.
- Submit a test ticket, retrieve associated migration logs and mapping tables, and check whether the results are sorted by priority.
- Check that the retrieval data source scope is limited to the exclusive templates, mapping tables, and log documents of this category, to exclude interference from unrelated content.
- View the system logs, confirm that the reranking model has loaded normally, and there are no architecture incompatibility or configuration error prompts.
