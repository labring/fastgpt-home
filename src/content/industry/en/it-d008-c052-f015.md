# Operations on-call and internal ticket query for customer permission and organizational structure configuration: Knowledge base retrieval and recall

## What this category of data looks like
Service targets include implementation consultants, customer administrators, and technical support staff. Data primarily comes from customer HR systems, identity directories, product backends, and audit logs. Daily generated documents include permission matrices, organizational structure tables, role configuration records, and permission change tickets. Data updates are triggered by single permission changes or organizational adjustments, with no fixed cycle. Data fields include department hierarchy paths, role names, associated permission items, user accounts, and effective end times. There are no uniform mandatory units. Some fields require supplementary explanations based on business scenarios. For example, permission items must be marked with their affiliated business module.

## What constraints these characteristics impose on knowledge base retrieval and recall
Data sources are scattered and updates have no fixed cycle. Knowledge base recall must prioritize the latest permission change records to avoid returning expired configurations. Permission matrices and organizational structure tables have hierarchical associations. Retrieval must match both department paths and role permissions, otherwise cross-level unauthorized recall results may occur. Single change ticket data volume is small but fields are closely associated. Retrieval must limit the association scope of returned results to avoid mixing irrelevant historical permission configurations. Audit logs contain operation traces. Recall must filter unauthorized configuration operation records to ensure retrieval results meet compliance requirements.

## How to set configurations
This document applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Permission configuration data has high precision requirements. Low-similarity irrelevant configuration items must be filtered to avoid returning incorrect permission mapping relationships |
| `limit` | `Top 8 entries` | Permission-related document fields are closely associated. Too many results will increase the context processing burden, while this number covers all associated records of a single change |
| `searchMode` | `Hybrid vector and keyword search` | Permission configurations include structured fields and text descriptions. Hybrid retrieval can match both role name keywords and vector semantic associations |
| `usingReRank` | `Enabled` | Semantic association of permission data requires precise sorting. Reranking corrects result deviations from vector retrieval, ensuring highly relevant permission configurations are ranked first |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Permission configurations often include abbreviation and full-name mappings. Extended queries can supplement matching alias-like permission descriptions, improving recall completeness |
| `collectionIds` | `Specify a dedicated collection for permission configurations` | Avoid mixing knowledge base data from other categories, ensuring the retrieval scope only covers documents related to customer permissions and organizational structures |

## Three common configuration mistakes
- The number of retrieval results is far lower than the expected number of permission documents. This occurs when the `similarity` threshold is incorrectly configured, filtering out eligible permission configuration entries.
- Permission documents in the specified collection cannot be retrieved. This occurs when the `collectionIds` parameter is filled incorrectly, causing the retrieval scope to cover other business knowledge bases.
- Recall results include expired permission change records. This occurs when the latest configuration data is not prioritized for matching, and the effective time field in audit logs is not associated for filtering.

## How to verify successful configuration
- Upload a single permission matrix document, run a retrieval test, and check whether the returned result fields match the original document.
- Adjust the `similarity` threshold to 0.6, observe changes in the number of returned results, and verify the threshold's impact on recall scope.
- Fill `collectionIds` with values for non-permission-type knowledge bases, run a retrieval, confirm no irrelevant results are returned, and verify that the collection filtering function is active.
- Compare sorting results after enabling `usingReRank`, confirm that highly relevant permission configuration entries are ranked first.

The values provided are common starting points and should be measured against the reader's own samples.
