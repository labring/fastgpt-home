# Operations Duty and Internal Ticket Q&A for Customer Permission & Organizational Structure Configuration: Reranking and Hybrid Retrieval

## What this category of data looks like
Data for this category typically comes from customer HR systems, identity directories, product backends, and audit logs. Updates occur per ticket or irregularly, with no fixed batch update cycle. Daily maintained documents include permission matrices, organizational structure tables, role configuration records, and permission change tickets. Common data fields include department hierarchy paths, role permission mapping rules, permission change operation timestamps, associated customer IDs, and more. Some fields use enumeration values or boolean values, with no unified fixed unit.

## What constraints do these characteristics impose on the "reranking and hybrid retrieval" link
This category of data is scattered across multiple sources and has no fixed update cycle. The hybrid retrieval link must support connecting to multiple data sources. This ensures full coverage of all configuration documents such as permission matrices and organizational structure tables. There are many data fields and complex association relationships. The reranking link must sort results based on field relevance. It must prioritize results directly related to permission issues. Operations duty scenarios require rapid location of abnormal configurations. The timeliness and relevance weight of retrieval results must be higher than in general scenarios. Adjust reranking and retrieval parameters to fit this business requirement. Errors in permission configuration data can cause serious consequences such as unauthorized access. The retrieval link must strictly limit the data source scope. This avoids interference from irrelevant data during troubleshooting.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `usingReRank` | Enabled | This scenario requires sorting retrieval results by permission relevance to improve the accuracy of operations troubleshooting |
| `similarity` | 0.75–0.85 | Filter low-similarity results unrelated to permission configurations and organizational structures, focusing on core business data |
| `limit` | Top 10 entries | Adapt to the needs of rapid problem location during operations duty, avoiding excessive redundant results that interfere with judgment |
| `searchMode` | Hybrid retrieval mode | Support simultaneous retrieval of multiple source documents such as permission matrices, organizational structure tables, and permission change records |
| Reranking model matching threshold | 0.6–0.7 | Calibrated based on actual measurements, filter low-relevance candidate results during the reranking phase |
| Retrieval data source scope | Permission configuration document library | Limit the retrieval scope to avoid interference from irrelevant business data during troubleshooting of permission-related issues |

## Three Common Misconfigurations
- Symptom: The reranking function shows false, and retrieval results are not sorted by relevance. Cause: The `usingReRank` configuration item was not enabled correctly, or the reranking model was not deployed and adapted.
- Symptom: The reranking function fails to load normally in an ARM architecture deployment environment. Cause: A reranking model image that only supports AMD architecture was used. The deployment package adapted for ARM architecture was not selected.
- Symptom: The number of retrieval results does not match expectations after configuration is completed. Cause: The `limit` parameter value was set incorrectly, or the retrieval data source scope was not limited to the permission configuration document library.

## How to Confirm Configuration Completion
- Access the corresponding configuration page in FastGPT v4.17.0. Check whether the `usingReRank` switch is enabled.

- Check whether the retrieval data source scope only includes target documents such as permission matrices and organizational structure tables. Eliminate interference from irrelevant data.
- Review system operation logs. Confirm that there are no errors in reranking model calls, and that retrieval parameters match the preset configuration.
