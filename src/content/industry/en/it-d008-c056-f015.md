# Object Storage and Backup Service Operations Duty and Internal Ticket Q&A: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
Daily documents for this category typically include bucket configurations, backup policies, recovery records, lifecycle rules, and similar content. Data originates primarily from object storage consoles, backup systems, access logs, and customer policy tables. Update frequency is daily or when policies are modified. Fields commonly include bucket identifiers, backup task numbers, recovery timestamps, permission policy entries, and similar items. There are no uniform fixed units; values vary based on specific configuration items and business requirements.

## What Constraints These Characteristics Impose on Knowledge Base Retrieval and Recall
Data from this category is dispersed across multiple sources and has diverse formats, including structured configuration documents, time-series operation logs, and policy entries. During knowledge base retrieval and recall, format differences across multiple data sources must be adapted to avoid mixed and disordered retrieval results. Data updates are triggered by policy changes, so the knowledge base incremental update mechanism must flexibly match non-fixed-cycle synchronization rhythms to avoid outdated configuration information. Additionally, the business scenario focuses on high-risk maintenance operations. The accuracy and relevance of retrieval results directly impact maintenance efficiency and data security, so the precision of recall results must be enhanced.

## How to Configure Settings
The following configurations are based on the interface and parameter logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | This category’s maintenance documents are mostly structured policy-related content. This range filters low-correlation non-policy results to meet the precise retrieval needs of maintenance scenarios |
| `limit` | Top 6–8 results | For maintenance duty and ticket scenarios, a single retrieval does not require excessive results. This range balances information completeness and reading efficiency |
| `usingReRank` | Enabled | Maintenance documents contain a large number of similar policy configuration entries. Reranking optimizes result sorting logic to prioritize content that better matches maintenance issues |
| `datasetSearchUsingExtensionQuery` | Enabled | Converts colloquial questions from maintenance personnel into standardized retrieval terms, adapting to retrieval needs for professional terminology such as storage buckets and backup policies |
| `searchMode` | Semantic Retrieval | Documents in this category are mostly non-natural language configuration entries. Semantic retrieval better matches the intent of maintenance personnel’s questions, rather than being limited to keyword matching |
| `collectionIds` | Bind the knowledge base collection ID corresponding to the storage bucket/backup system by business domain | Limits the retrieval scope to avoid recalling irrelevant documents across business domains, improving retrieval efficiency |

## Three Common Misconfigurations
- Phenomenon: Knowledge base retrieval returns normal results during debugging, but does not reference knowledge base content in formal AI conversations, only returning generic responses. Cause: The configured knowledge base collection is not bound to the conversation node of the corresponding workflow, or the retrieval configuration of the conversation node does not inherit the parameters from the debugging phase.
- Phenomenon: Attempting to limit the number of retrieval results via the similarity threshold, but the actual number of returned results still fluctuates with the threshold and cannot be fixed to a specified quantity. Cause: Confused the configuration logic between the similarity threshold and the number of recalled entries, and did not use the `limit` parameter to set a fixed number of recalled results.
- Phenomenon: After uploading a text file with embedded images, the knowledge base cannot retrieve the text content in the images. Cause: The OCR text extraction configuration for the knowledge base was not enabled, and the image content was not converted into retrievable text fragments.

## How to Verify Proper Configuration
- Navigate to the retrieval debugging page of the corresponding knowledge base, enter a typical maintenance question, and check whether the returned results include exclusive document content for this category.
- Review the conversation node configuration of the workflow, confirm that the correct knowledge base collection ID is bound, and that all retrieval parameters match the preset configuration.
- Upload a test text file with embedded images, initiate a retrieval, and confirm that the text in the images can be retrieved normally.
- Trigger a simulated maintenance ticket conversation flow, and check whether the returned results comply with the preset retrieval rules and no irrelevant cross-domain documents appear.
