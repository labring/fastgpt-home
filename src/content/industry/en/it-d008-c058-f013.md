# Ad Compliance Logging Operations Duty and Internal Ticket Q&A: Permission and Data Isolation

## What This Category of Data Looks Like
This category of data originates from advertising platform backends, customer qualification records, contract systems, and publicly released regulatory rules. Update frequency is once per campaign or monthly. Daily processed documents include ad review forms, qualification attachments, delivery logs, and rectification notices. Each document includes fields such as subject information, review stages, delivery time windows, and rectification requirements. Qualification attachments are mostly scanned documents or encrypted files. Delivery logs contain standardized fields including delivery channels, content, and duration.

## How These Characteristics Create Constraints for Permission and Data Isolation
Data sources are scattered and include customer-sensitive qualification information and regulatory evidence. Access scopes for different entities must be strictly separated. Update frequencies are variable and tied to business campaigns, so permission scopes need to be dynamically synchronized based on campaign cycles. Documents contain sensitive compliance information, so tiered permissions must be configured for different roles including compliance specialists, operations and maintenance staff, and legal personnel. Qualification attachments are mostly encrypted or scanned documents, so matching storage permissions and access links are required. Delivery logs and rectification notices for different entities must be stored in isolation to prevent cross-team or cross-customer data leaks.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `teamId` binding | Assign a unique `teamId` for each customer entity | Aligns with customer data isolation requirements for ad compliance logging |
| Member permission groups | Divide into three tiered roles: compliance review, operations duty, legal archiving | Matches compliant data access scopes for different job functions |
| Data filtering rules | Automatically filter non-associated compliance documents using `teamId` | Prevents cross-customer data leaks |
| Team invitation configuration | Enable invitation binding to `teamId`, set invitation notification delay to no more than 300 seconds | Resolves cases where no notifications are sent after invitations are dispatched |
| Storage quota | Allocate 800–1200 MB of storage per `teamId` | Fits the volume of compliance documents updated monthly |
| Permission synchronization latency | Configure to sync permission changes within 600 seconds | Matches the response timeline of business activities |

## Three Common Configuration Errors
- Issue: When a team invitation is sent, the invited member receives no interface or system notifications. Cause: The `teamId`-bound invitation trigger configuration is not enabled, and the invitation is not linked to the corresponding team's permission scope.
- Issue: Operations and maintenance staff on duty can view ad review forms and delivery records that do not belong to their assigned customer during internal ticket Q&A. Cause: Data filtering rules based on `teamId` are not configured, and permission groups are not bound to the corresponding team identifier.
- Issue: After adjusting member permission groups, the access scope for compliance documents is not updated promptly. Cause: Permission synchronization latency is not set to 600 seconds, so the system cache does not refresh permission configurations in a timely manner.

## How to Verify Successful Configuration
- A compliance document access request is sent to an account not bound to the target `teamId`, confirming that the corresponding content cannot be viewed.
- A team invitation is sent, confirming that the invited account receives a notification within the preset time limit.
- A member permission group is adjusted, and after waiting for the preset synchronization duration, the access scope is verified for updates.
- The storage usage of a single `teamId` is checked, confirming that it falls within the pre-configured storage quota range.
