# Operations Shift and Internal Ticket Q&A for Ad Account Opening Audit: Knowledge Base Retrieval and Recall

## What Data Looks Like for This Category
The core data for this category comes from the advertising platform backend, the national enterprise credit information public disclosure system, customer-submitted application materials, and industry access rules. Daily processed documents include account opening application forms, scanned copies of enterprise business licenses, operating qualification documents for corresponding industries, and historical account opening audit records.

Data is updated via daily batch synchronization or real-time updates submitted with individual orders. Most documents are a mix of structured forms and unstructured text and image formats, with fields including subject name, unified social credit code, advertising industry classification, audit node status, and additional relevant fields.

## Constraints Imposed on Knowledge Base Retrieval and Recall
Decentralized data sources and mixed formats require the retrieval link to support both structured field matching and unstructured text and image semantic recall.

Real-time update requirements for individually submitted orders require the recall pipeline to support low-latency incremental synchronization.

The need for associated verification of multiple qualification documents requires recall results to be aggregated by application order, returning a full set of associated materials.

A high proportion of historical audit record data requires recall operations to prioritize matching the latest access rules and historical compliance cases.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | Semantic similarity threshold for matching qualification documents, balances precision and recall for standard audit scenarios |
| `limit` | Top 8 entries | Limits the number of documents retrieved per request, adapts to the total volume of associated materials for a single account opening application |
| `searchMode` | hybrid | Hybrid retrieval mode, supports both structured field matching and unstructured semantic recall |
| `usingReRank` | Enabled, take top 5 entries after reranking | Reranks retrieved results to prioritize documents strongly related to audit rules |
| `datasetSearchUsingExtensionQuery` | Enabled | Expands query terms based on the original question to supplement potential matching items related to industry access |
| `collectionIds` | Specify audit-exclusive dataset ID | Restricts retrieval scope, excludes unrelated business documents |

## Three Common Misconfigurations
- Issue: An upload failure prompt appears when uploading business licenses, account opening applications, or other files; a 400 status code is returned in some scenarios. Cause: The allowed upload file formats and single-file size thresholds for the dataset have not been configured, or the file uses an unsupported encoding format.
- Issue: When querying industry access rules, retrieved document content is incomplete, with core audit clauses missing. Cause: Segmentation enhancement processing is not enabled, or the segmentation length is set incorrectly, causing long documents to be truncated and key information to be lost.
- Issue: Retrieval response times out when processing account opening applications in bulk; server hard disk IO usage remains consistently high. Cause: The retrieval dataset scope has not been restricted, resulting in retrieval of a large volume of unrelated historical audit records, or the reranking step is not enabled, leading to excessive redundant results.

## How to Verify Proper Configuration
- Upload a test business license and account opening application form, confirm that the files can be uploaded normally and stored in the specified dataset.
- Enter a simulated audit query, check that the number of retrieved results matches the preset `limit` value, and that the similarity score falls within the 0.72–0.80 range.
- After enabling the reranking function, confirm that the retrieved results are sorted to prioritize documents strongly related to the current audit scenario.
- View the dataset configuration page, confirm that `collectionIds` is bound to the current audit-exclusive dataset and does not include unrelated business documents.

The values provided here are common starting points and should be measured against the reader's own samples.
