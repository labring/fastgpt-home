# Operations on-duty and Internal Ticket Q&A for Ad Account Opening Review: Deployment and Upgrade

## What the data for this category looks like
Core data for this category is generated during the ad account opening review process. Daily documents include account opening application forms, business license scans, corresponding industry operation qualification documents, and account opening review record ledgers. Data sources include ad platform backend account data, public information from the national enterprise credit information publicity system, paper or electronic materials submitted by customers, and industry access rule documents. Data updates are triggered by account opening applications. Each single application corresponds to one complete data update. Fields include subject identification information, industry category, qualification validity period, review node status, and other relevant details.

## Constraints imposed by these characteristics on deployment and upgrade
The data characteristics of this category create multiple constraints for the deployment and upgrade process. Multi-source and heterogeneous data sources require configuring data source access modules adapted to different interface formats during deployment, to avoid data pull failures caused by interface differences. The update rhythm triggered by single applications requires setting a reasonable concurrency upper limit, to prevent excessive concurrent requests from exhausting system resources. The diverse formats of qualification documents require compatibility with new document types during upgrades, to ensure the storage module operates normally. The requirement to bind internal tickets and account opening data requires configuring association rules between tickets and data during deployment, to ensure ticket circulation and review data synchronization during operations on-duty work.

## How to configure settings
The following configuration items are designed for FastGPT v4.17.0:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 100–200 connections | Matches the concurrency request scale of ad account opening review, covers regular business peaks, and avoids exhausting database connection pools |
| `MONGODB_URI` | Local or cloud-hosted MongoDB address with authentication information | Stores unstructured data such as account opening applications and review records, and adapts to the storage needs of this category's data |
| `REDIS_URL` | Cache address configured with a 600-second expiration time | Caches frequently pulled industry access rules and publicity system data, balancing real-time performance and request efficiency |
| `FE_DOMAIN` | Domain name of the internal operations on-duty system | Binds the front-end interaction domain name between the internal ticket system and FastGPT, ensuring normal ticket circulation for operations staff |
| `FILE_TOKEN_KEY` | Randomly generated 32-character string key | Encrypts access tokens for stored qualification documents, ensuring the security of materials submitted by customers |
| `STORAGE_S3_ENDPOINT` | Object storage endpoint adapted to single file storage under 1000 MB | Stores scans of business licenses and industry qualifications, aligning with the conventional scale of this category's file storage |

## Three common configuration mistakes
- Symptom: The front-end interface becomes unresponsive or freezes when processing multiple account opening review tickets concurrently. Cause: The `DB_MAX_LINK` parameter is not configured reasonably, leading to exhaustion of the database connection pool and inability to respond to subsequent requests.
- Symptom: A connection failure error appears when attempting to connect to MongoDB started via local Docker Desktop. Cause: The `MONGODB_URI` parameter is not configured correctly, and the correct port and authentication information for MongoDB inside the Docker container are not included.
- Symptom: After redeploying the reranking model, an Invalid URL (POST /v1/rerank) error is returned when calling it. Cause: The interface address of the reranking model is not configured correctly in FastGPT, leading to a mismatch in request paths.

## How to confirm proper configuration
- Run a database connection test to verify whether the connection number configured in `DB_MAX_LINK` can cover regular concurrent requests, and adjust based on business peaks.
- Submit a test account opening application, check whether qualification files can be uploaded and stored normally, and verify whether the `STORAGE_S3_ENDPOINT` configuration takes effect.
- Initiate a test internal ticket circulation, confirm that the association between tickets and account opening application data is normal, and verify whether the `FE_DOMAIN` configuration is correct.
- Trigger a high-frequency data pull, check whether the cache is updated normally, and verify whether the expiration time configuration of `REDIS_URL` meets requirements.
