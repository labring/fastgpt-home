# Operations Duty and Internal Ticket Q&A for Performance Testing and Capacity Evaluation: Sharing and Embedding

## What this category’s data looks like
This category of data typically comes from pressure testing platforms, APM monitoring tools, database slow logs, and production traffic baselines. Daily produced documents include pressure testing plans, capacity evaluation reports, pressure testing data records, and optimization suggestion sheets. Document fields usually include throughput metrics, latency thresholds, resource occupancy rates, and traffic baseline values. Corresponding units are requests per second, milliseconds, percent, GB, and others. Data updates occur once per month, or when major software versions are released. Core documents must be reviewed and confirmed by the architecture team and operations team before being archived.

## What constraints these characteristics impose on the sharing and embedding workflow
Data from this category involves production environment resource margins and traffic baselines, which are internal sensitive information. Therefore, the sharing and embedding workflow must strictly restrict access scope. Only internal operations and testing teams may access this data. Data updates happen infrequently, so frequent refreshes of shared content are unnecessary. However, the cache validity period must match the data update rhythm to avoid displaying expired pressure testing results. Daily documents have diverse structures. When embedding, external systems must support loading content in chunks by document type. This adapts to the panel layout of the operations workbench. In the operations duty scenario, FastGPT’s no-login sharing link simplifies the access process. This avoids repeated verification that impacts duty efficiency. Access permissions are controlled by the access range set in FastGPT sharing configurations to prevent data leaks.

## Three common configuration errors
- Sharing entries related to performance testing and capacity evaluation fail to open. First verify the full system-generated link and its validity period, then check browser request status. Do not manually replace `shareId`.
- The visible scope of performance testing and capacity evaluation data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately. The sharing entry identifier itself does not provide business authorization.
- The same performance testing and capacity evaluation Q&A cannot be viewed on another device. In anonymous scenarios, first check the device, browser, and local identity status. Retention cannot be guaranteed across devices or after cache clearance. Do not use this phenomenon alone to judge service abnormalities.

## How to confirm the configuration is complete
- Open the operations workbench page with embedded FastGPT shared content, check that performance testing data loads normally with no error prompts.
- Attempt to access via the copied FastGPT no-login sharing link. Internal operation accounts can successfully view the content. External unauthorized accounts cannot access and receive a permission insufficient prompt.
- Check the FastGPT no-login sharing link configuration, confirm that the sharing validity period (if configured) matches the data update rhythm.
- Wait for external data updates or cache validity period expiration, refresh the external operations workbench page, confirm that the latest pressure testing data and capacity evaluation reports are displayed synchronously.
