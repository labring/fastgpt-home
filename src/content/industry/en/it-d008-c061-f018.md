# Operations On-Duty and Internal Ticket Query for Performance Testing and Capacity Assessment: Reranking and Hybrid Retrieval

## What Data in This Category Looks Like
Data for this category comes primarily from stress testing platforms, APM monitoring systems, database slow logs, and production traffic baselines. Daily produced documents include stress testing plans, capacity assessment reports, stress testing data records, and optimization suggestion sheets. Common fields include throughput (unit: TPS), latency (unit: milliseconds), resource usage rate, and resource surplus (unit: GB). The data update frequency is typically once per month, or synchronized after major system version iterations.

## Constraints Imposed by These Characteristics on Reranking and Hybrid Retrieval
Data in this category includes both structured metrics and unstructured documents. Hybrid retrieval must match both semantic content and structured fields. Since data update frequency is low, high-frequency incremental synchronization during retrieval is not required. Precise filtering rules must be set for the units of stress testing metrics, such as TPS and milliseconds. Data from multiple sources has format differences. The reranking link must first associate metric records and corresponding assessment reports from the same stress test batch, to avoid mixing data across batches. Tickets in operations on-duty scenarios mostly focus on specific stress testing tasks or capacity issues. Retrieval must first recall stress testing data directly bound to ticket keywords, to avoid generic historical records interfering with core results.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale for This Approach |
| --- | --- | --- |
| Similarity threshold | `0.7–0.85` | Filter stress testing metrics and documents with overly low semantic matching, to avoid irrelevant content entering retrieval results |
| Single retrieval limit | `Top 10–15 entries` | Match the conventional information requirement scope of operations tickets, to avoid excessive results increasing manual screening costs |
| Retrieval mode | Hybrid retrieval | Meet the retrieval needs of both structured stress testing metrics and unstructured reports, adapting to the multi-format data characteristics of this category |
| Reranking toggle | Enabled, take top 5 entries for reranking | Address format differences across multiple source data, optimize the association order of same-batch stress testing content through reranking, improving retrieval accuracy |
| Context window length | `8000–12000 token` | Adapt to the total content length of stress testing reports and metric data, avoid truncating key stress testing metrics and conclusions |

## Three Common Misconfigurations
- Phenomenon: Irrelevant documents not associated with a stress testing batch appear in hybrid retrieval results. Cause: No keyword filtering rules are configured, leading to recall of historical data across batches.
- Phenomenon: After the reranking toggle is set to disabled, retrieval results are not sorted by relevance, and core stress testing bottleneck data focused on by tickets appears late. Cause: The reranking configuration item was mistakenly set to disabled, and reranking to optimize result order was not enabled.
- Phenomenon: After binding a knowledge base in a workflow, only a single entry is returned, and no corresponding stress testing report is associated. Cause: The retrieval scope is not limited to the data source of the specified stress testing batch in the retrieval configuration, leading to mixing of multi-batch data.

## How to Confirm Configuration Is Properly Set
- Enter the retrieval configuration page of FastGPT v4.17.0, confirm that the retrieval mode is set to hybrid retrieval, and the reranking toggle is enabled.
- Submit a test ticket, enter keywords that include stress testing metric units, and check whether the returned results include structured data with corresponding units and associated reports.
- Check the number of retrieval results, confirm that the returned quantity matches the configured single retrieval limit.
- Check the result sorting, confirm that metrics and report content from the same stress testing batch are arranged in the top positions.

The values provided are common starting points and should be measured against the reader's own samples.
