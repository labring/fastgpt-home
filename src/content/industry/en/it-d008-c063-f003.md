# Operations on Duty and Internal Ticket Q&A for Campaign Setup: Sharing and Embedding

## What the data for this use case looks like
Core data for campaign setup use cases comes from advertising platforms, user profile databases, budget scheduling sheets, and attribution tools. Daily produced documents include campaign setup templates, audience targeting rules, budget allocation plans, and conversion tracking configuration items. Data update frequency is typically once daily or triggered by campaign activity adjustments. Core fields include targeted audience package ID, daily budget amount, conversion event type, and account structure hierarchy identifier. Units are business-specific, such as yuan, users, and occurrences.

## What constraints do these characteristics impose on the sharing and embedding workflow
The structured documents and multi-source data characteristics of campaign setup impose multiple constraints on the sharing and embedding workflow. First, multi-source data has high real-time requirements. Embedded sharing sessions must sync the latest budget and targeting configurations from external business systems. It is recommended that external embedding systems limit the cache duration of sharing pages. Second, core fields involve sensitive configurations of advertising accounts. Sharing and embedding must use external permission systems to control the access scope of user roles, preventing unauthorized personnel from viewing budgets or targeting rules. Third, the structured nature of documents requires external systems to retain field association logic for embedded conversation windows. This ensures that Q&A can accurately link to structured fields for the corresponding campaign. Finally, language requirements vary significantly across use cases. Sharing page language must be configurable independently by external embedding systems, separate from the main FastGPT console language. This page is written for FastGPT v4.17.0.

## Configuration Settings

| --- | --- | --- |
| `shareId` (Sharing Portal) | Copy the full sharing link generated by the system, do not replace the identifier manually | Identifies the sharing portal; campaign setup business records and data permissions must still be handled by external systems |
| Sharing Link Expiry Duration | Test starting point: 7 days; adjust based on actual campaign setup collaboration cycles and revocation requirements | Verify availability within the valid period and access behavior after expiry. This value is not an official default or industry statistic |
| QPM | Test starting point: 20 requests per user per minute; adjust based on actual load | Limits access frequency for a single user. Must be validated with request logs and actual load |

| Conversation Record Validation | Test example: Prepare 10 campaign setup Q&A samples, check on the same browser and another device respectively | Anonymous records rely on browser local identity. Retention is not guaranteed across devices or after cache clearance |

## Three Common Mistakes
- Sharing portals related to campaign setup fail to open. First verify the full system-generated link and its expiry period, then check browser request status. Do not manually replace `shareId`.
- The visible scope of campaign setup data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately. The sharing portal identifier itself does not provide business authorization.
- The same campaign setup Q&A is not visible on another device. For anonymous scenarios, first check device, browser, and local identity status. Retention is not guaranteed across devices or after cache clearance. Do not use this phenomenon alone to judge service anomalies.

## How to Confirm Proper Configuration
- Generate a sharing link for the corresponding campaign, switch to different language environments to access, and confirm that the interface language matches the configured requirements.
- Access the sharing link, check that the passed prompt text is displayed correctly or hidden, with no redundant default copy.
- Use the configured non-login link to initiate a test Q&A, check external log storage systems or the FastGPT commercial edition backend session logs, confirm that records have been generated and match the configured storage duration.
- Deploy the embedded code to the internal ticket system, verify that the conversation window can normally initiate Q&A related to campaigns, with no loading exceptions.

The values provided are common starting points and should be measured against the reader's own samples.
