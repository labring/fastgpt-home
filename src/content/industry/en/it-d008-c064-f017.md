# Bid Document Preparation: Operations On-Duty and Internal Ticket Q&A — Deployment and Upgrade

## What the Data for This Category Looks Like
Core data for this category is generated and circulated around individual bid projects. Daily documents include bid documents, qualification certificates, commercial deviation tables, and technical deviation tables. Data sources include tender announcements, bidding documents, enterprise qualification databases, and supplier quotations. Updates are performed independently for each project. The document structure for each bid project is fixed, including strictly formatted response clauses, qualification verification fields, and quotation details. Single document size fluctuates with project complexity. Deployments must support multi-source heterogeneous unstructured and semi-structured data processing.

## Constraints on Deployment and Upgrade
Since data is updated independently per project and uses a fixed format, deployments must support rapid interface integration with external data sources such as tender announcements and qualification databases. Single documents have large file sizes, so sufficient storage and connection pool resources must be provisioned. Format verification and clause response for bid documents must accurately match tender requirements, so parsing rules for the required format must be preset during deployment. Errors directly carry the risk of bid invalidation, so upgrade processes must retain backups of existing configurations to avoid business interruptions caused by parameter changes. Internal tickets and on-duty notifications must be sent exclusively to bid specialists, so a dedicated push link must be configured. When upgrading to FastGPT v4.17.0, adjust database connection pool configurations for compatibility. Default parameter changes may disrupt batch document processing, so these adjustments must be made carefully.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–150 connections` | Matches batch processing requirements for associated documents such as qualifications and quotations linked to a single bid file, and avoids exhaustion of connection pool resources |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.100:9000` or the endpoint provided by the corresponding object storage service provider | Adapts to storage requirements for single documents such as bid files and qualification certificates, which can reach hundreds of MB in size |
| `FILE_TOKEN_KEY` | Randomly generated 32-bit hexadecimal string | Ensures access authentication security for uploaded bid-related files, and prevents unauthorized access |
| `REDIS_URL` | `redis://:custom password@deployment host:6379/1` | Caches frequently queried tender announcements and qualification database entries to reduce repeated parsing and call overhead |
| `FE_DOMAIN` | `https://bid-support.example.com` | Ensures that internal ticket push and bid file download links can be generated and accessed normally, and adapts to domain name rules for internal office networks |

## Three Common Mistakes
- Symptom: Using a general account key as the configuration value for `STORAGE_S3_ENDPOINT`, resulting in authentication failure when uploading bid files. Cause: The general account key is only used for model call authentication, and cannot be used as an access credential for the storage module. Configuration permissions for different functional modules are confused.
- Symptom: No output content is displayed on the frontend after a Q&A session ends, and messages can only be viewed by entering the details page. Cause: `REDIS_URL` is not configured, causing session cache failure. Messages are not synchronized to the frontend rendering chain, and cannot be displayed on the session homepage.
- Symptom: After enabling the workflow file upload function, an error is returned when using the document parsing tool to parse the file address. Cause: `FILE_TOKEN_KEY` or `STORAGE_S3_ENDPOINT` is not configured, causing files to not be stored and parsed correctly, and valid access paths cannot be generated.

## How to Confirm Correct Configuration
- Upload a test qualification certificate document, confirm that the upload progress bar completes normally, and that a file with the same name can be found in the corresponding storage directory.
- Initiate a simulated internal ticket, confirm that the ticket push notification can be sent normally to the preset receiving channel.
- Call the model to generate a bid clause response, confirm that the generated result can be viewed directly on the frontend session page without entering the details page.
- View the database connection pool monitoring panel, confirm that the current active connection count does not exceed the configured value of `DB_MAX_LINK`.

The values provided here are common starting points, and should be measured against the reader's own samples.
