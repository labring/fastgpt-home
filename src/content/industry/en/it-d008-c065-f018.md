# Operations on-call and internal ticket query for interface integration and data docking: Re-ranking and hybrid retrieval

## What the data for this category looks like
The data for this category mainly comes from customer system interfaces, API documentation, test data, and integration logs. Daily produced documents include interface lists, integration records, field mapping tables, and issue tracking sheets. Data updates follow a daily cadence or proceed per project phase. Individual documents typically contain structured content such as interface addresses, request parameters, return fields, and error code definitions. Some real-time integration logs record call chains and error details. Fields mostly use interface protocol field names and business codes as identifiers, with no unified standardized format.

## What constraints do these characteristics impose on re-ranking and hybrid retrieval
Documents in this category are mostly structured interface definitions and semi-structured integration logs. Data update frequencies fluctuate widely. Some integration logs have strict real-time requirements. Hybrid retrieval must recall both static interface lists and dynamic integration logs. This requires distinguishing the weights of different data sources. Inconsistent field standards cause deviations in retrieval keyword matching. Use a re-ranking model to correct semantic matching results. Long-text integration logs occupy more context space. Limit retrieval result length to avoid exceeding the model context window. Adjust retrieval trigger timing to adapt to the update cadence of different data sources.

## How to Configure
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `usingReRank` | Enabled, bound to a deployed bge-reranker series model | This category of data has large semantic differences. Re-ranking corrects matching deviations from basic recall |
| `similarity` | `0.65–0.75` | Interface fields mostly require precise matching. A too-low threshold introduces irrelevant interface documents. A too-high threshold misses valid integration logs |
| `limit` | Top 8 entries | This category of single-round retrieval covers two data sources: interface lists and integration logs. 8 entries balances recall volume and context usage |
| `searchMode` | Hybrid retrieval | Recall both static interface metadata and dynamic integration log data. Adapts to multi-source data characteristics |
| Re-ranking input length limit | `800–1200 characters` | Adapts to the common length of integration logs. Avoids exceeding the input window of the re-ranking model |

## Three Common Mistakes
- Phenomenon: The re-ranking model passes local tests, but the retrieval result re-ranking flag is set to false. Cause: The `usingReRank` parameter is not enabled in the FastGPT v4.17.0 retrieval configuration, or the deployed re-ranking model is not bound.
- Phenomenon: The re-ranking model is not called when knowledge base retrieval content is too long. Cause: No retrieval result truncation threshold is set. Long-text integration logs exceed the maximum input length supported by the re-ranking model. The system automatically skips the re-ranking step.
- Phenomenon: The re-ranking model cannot be used in large model calls, but works normally in knowledge base search tests. Cause: The large model call link does not enable hybrid retrieval and re-ranking configurations. It only uses basic vector recall logic.

## How to Confirm the Configuration Is Complete
- Enter the knowledge base configuration page of FastGPT v4.17.0. Check whether the `usingReRank` parameter is enabled and a deployed re-ranking model is bound.
- Submit a test retrieval request containing interface fields and integration error keywords. Check whether the returned results include a re-ranking score field. Check whether the result order differs from the basic recall order.
- Upload a single integration log with a length exceeding 1000 characters. Initiate a retrieval. Confirm that the re-ranking model normally participates in the sorting process.
- View the retrieval log. Confirm that `searchMode` is set to hybrid retrieval mode. Confirm that the number of returned results matches the configured `limit` value.
