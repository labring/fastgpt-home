# Search Ad Keyword Management Operations On-Call and Internal Ticket Q&A: Deployment and Upgrade

## What the data for this category looks like
Daily business data for search ad keyword management typically includes fields such as keyword text, matching mode, bid threshold, historical search volume, negative keyword rule entries, and landing page links. Data is primarily sourced from search ad delivery backends, search term reports, ranking bidding data interfaces, and landing page monitoring tools. Structured documents are generated at a daily or weekly update frequency. Core documents requiring synchronization during daily operations include keyword lists, negative keyword tables, bid records, and search term reports. Data read and write frequencies fluctuate alongside ad delivery cycles.

## What constraints these characteristics impose on deployment and upgrade
Since data sources rely on ad platform interfaces and structured business documents, deployments must configure local storage and database connections that support offline scenarios. Frequent keyword read/write operations and scheduled data synchronization tasks require database connection pool and cache configurations to align with business load. Cross-version upgrades must maintain compatibility with the keyword field structure of older database versions to avoid business data loss due to field mismatches. Additionally, operations on-call and internal ticket workflows must be linked to data synchronization pipelines. Deployments must reserve integration interfaces to enable on-call personnel to trigger keyword change reviews and data synchronization verification via tickets.

## How to set the configurations
The following configurations apply to FastGPT v4.17.0, and are adapted for both offline and online deployment scenarios for search ad keyword management:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 10–15 connections | Adapts to the high-frequency database read/write operations of search ad keyword management, prevents synchronization task interruptions caused by exhausted connections |
| `MONGODB_URI` | Cluster intranet address with local authentication | Stores structured business data such as keyword lists and negative keyword tables, adapts to offline deployment scenarios without external network access |
| `REDIS_URL` | Local Redis instance address, timeout set to 300 seconds | Caches search term reports and ranking bidding data, reduces repeated calls to ad interfaces |
| `FE_DOMAIN` | Intranet domain of the internal operations on-call system | Associates jump links for internal ticket Q&A, ensures on-call personnel can directly access ticket approval workflows |
| `STORAGE_S3_ENDPOINT` | Intranet access address of local object storage | Stores attached files such as search term reports and landing page data, meets storage requirements for offline deployments |

## Three common errors
- Symptom: Keyword list fields are empty or matching modes are abnormal after cross-version upgrade. Cause: Failed to export keyword business fields from the older database before offline upgrade, failed to run version-compatible database script updates.
- Symptom: Keyword synchronization tasks frequently time out, and internal ticket submissions have no response. Cause: Set `DB_MAX_LINK` to a value lower than 5, causing the database connection pool to be exhausted and unable to handle concurrent requests.
- Symptom: Upgrade operations cannot be performed after commercial edition deployment. Cause: Misunderstood the commercial edition initialization process, incorrectly disabled database write permissions, causing failure to write version metadata during upgrades.

## How to confirm configurations are set correctly
- A database connection test is run, and the active connection count for the connection pool corresponding to `DB_MAX_LINK` is checked to confirm it stays within the configured range.
- A manual synchronization task is triggered, and the cache hit logs for `REDIS_URL` are reviewed to confirm there are no timeout errors or data loss.
- The internal ticket system corresponding to `FE_DOMAIN` is accessed, and the jump link is confirmed to open normally, with ticket submission and approval workflows functioning without issues.
- The storage permissions for `STORAGE_S3_ENDPOINT` are checked, and business files such as search term reports are confirmed to be uploadable and downloadable normally.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
