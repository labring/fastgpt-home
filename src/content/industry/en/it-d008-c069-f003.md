# Database Operations: On-Duty Support and Internal Ticket Q&A: Sharing and Embedding

This document is compatible with FastGPT v4.17.0.

## What this category of data looks like
Database operations scenarios typically source data from database monitoring, audit logs, SQL execution plans, and internal ticket systems. Daily produced documents include database change orders, slow SQL reports, backup records, and permission application forms. Common data fields include instance ID, SQL execution duration, change time, and permission level. Units include milliseconds, GB, and days. Data updates occur either daily or when individual database changes take place. Content is updated in real time or on a schedule alongside operations and maintenance activities.

## What constraints these characteristics impose on sharing and embedding
Database operations scenario data has scattered sources and flexible update cycles. When embedding or sharing content, external operations and maintenance systems must pass matching context parameters to align with the current scenario. This prevents loading irrelevant cross-category data. External systems must pass filtering parameters when calling FastGPT sharing and embedding, due to structured documents and field requirements. FastGPT sharing and embedding only displays the passed context content. The real-time or scheduled update feature requires embedded content cache duration to match the specific data update rhythm. This prevents displaying outdated content that could reduce the accuracy of operations and maintenance decisions.

## How to set the configurations
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| Sharing Entry `shareId` | Copy the full share link generated by the system, do not manually replace the identifier | Identifies the sharing entry; database operations business records and data permissions must still be handled by external systems |
| Share Link Validity Period | Test starting point: 7 days; adjust based on database operations collaboration cycles and revocation requirements through actual testing | Verify availability within the validity period and access behavior after expiration; this value is not an official default or industry statistic |
| QPM | Test starting point: 20 requests per user per minute; adjust based on actual load | Limits the access frequency of a single user; requires verification combined with request logs and actual load |
| Identity Verification | When identity permission requirements exist, first verify commercial edition capabilities and the uid returned by third-party identity services | Holding a share link does not equate to having business data permissions; third-party identity and data scope must be verified separately |
| Referenced Content Display | Select display configurations for reference fragments, full text, and original source based on the sensitivity of database operations materials | Check displayed content within authorized data ranges; do not use hidden interfaces as a substitute for data permission controls |
| Conversation Record Verification | Test example: Prepare 10 database operations Q&A samples, check them in the same browser and another device respectively | Anonymous records rely on browser local identity; retention is not guaranteed across devices or after cache clearance |

## Three common mistakes
- Failed to open database operations-related sharing entries. First verify the full system-generated link and its validity period, then check browser request status; do not manually replace `shareId`.
- The visible scope of database operations data does not match expected values. Verify third-party identity verification results, workflow request parameters, and external system data permissions separately; the sharing entry identifier itself does not provide business authorization.
- The same database operations Q&A content is unavailable on another device. In anonymous scenarios, first check device, browser, and local identity status; record retention is not guaranteed across devices or after cache clearance, do not use this phenomenon alone to judge service abnormalities.
