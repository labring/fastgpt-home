# Database Operations and Maintenance On-Call & Internal Ticket Q&A: Permission and Data Isolation

## What this category of data looks like
This category of data primarily originates from database monitoring, audit logs, SQL execution plans, and internal ticket systems. Daily generated documents include database change orders, slow SQL reports, backup records, and permission application forms. Data updates are triggered by database changes or occur on a daily basis. Each document includes fields such as instance ID, operation type, execution time, and permission scope. There is no unified fixed unit, and fields are dynamically adjusted based on ticket type and database instance attributes.

## What constraints do these characteristics impose on the permission and data isolation link?
Data in this category involves sensitive content such as database instance operations and permission application details. Data from multiple sources requires clear permission boundaries. Database instances managed by different DBAs or operations and maintenance teams have clear isolation requirements to prevent cross-instance permission breaches. Daily documents include permission application records and execution logs, which must ensure that only authorized personnel can view corresponding tickets and reports. Data is updated in real time alongside database changes, so permission configurations must sync with the latest status of instances and tickets to avoid security risks from outdated permissions.

## How to set the configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `teamId` | Bind to the team that owns the database instance | Ensure only team members can access operation and maintenance data for the corresponding instance |
| `tmbId` | Associate with the member ID of the ticket submitter | Limit access to the ticket to only the submitter and authorized administrators |
| Permission scope grouping | Divide by instance cluster and operation type | Isolate operation and maintenance access permissions for different clusters to avoid cross-cluster privilege escalation |
| Login-free link validity period | 15 minutes | Limit the validity period of temporary access to prevent long-term abuse if the link is leaked |
| Team member collaboration limit | Set according to the actual number of operation and maintenance personnel in the team | Match the team size to avoid permission chaos caused by unrestricted access |
| Team invitation permission configuration | Only administrators can initiate invitations | Restrict team invitation permissions to prevent unauthorized personnel from adding operation and maintenance members |
| Conversation content export permission | Only administrators can configure | Prevent sensitive operation and maintenance data from being exported without authorization |

## Three common mistakes
- Phenomenon: The team invitation entry cannot be found in the local deployment environment, and new operation and maintenance members cannot be added. Cause: The administrator-level team invitation permission configuration is not enabled, or the relevant switches for the team function are not activated.
- Phenomenon: Unauthorized users can access full database operation and maintenance data via login-free links. Cause: The instance and access permissions are not bound via `teamId`, only the link ID is used for verification without associating the team permission scope.
- Phenomenon: New members applying to join the operation and maintenance team receive an error indicating the number limit is exceeded. Cause: The configuration value for the collaboration limit was not adjusted based on the actual team size, causing new members to be unable to be added after the preset limit is exceeded.

## How to confirm the configuration is correct
This verification applies to FastGPT v4.17.0.
- Use an account that is not a team member to attempt to access the ticket page for the specified database instance, confirm that the corresponding content cannot be viewed.
- Generate a login-free link, wait 16 minutes, then attempt to access it, confirm that the link cannot load normally.
- Submit a database change ticket, confirm that only the submitter and administrators can view the detailed information of this ticket.
- Attempt to export operation and maintenance conversation content, confirm that non-administrator accounts cannot trigger the export operation.
