# Database Operations Maintenance Duty and Internal Ticket Q&A: Re-Ranking and Hybrid Retrieval

## What the data for this category looks like
The data for this category mainly comes from database monitoring, audit logs, SQL execution plans, and internal ticket systems. Daily processed documents include database change orders, slow SQL reports, backup records, and permission application forms. Each document contains fields such as instance ID, execution time, permission level, and change content. Data update frequency is triggered by database changes or updated daily. The size of individual data entries varies widely. Some slow SQL reports include detailed structured information such as execution time consumption and lock waits.

## What constraints do these characteristics impose on the "re-ranking and hybrid retrieval" link
This category of data is multi-source and heterogeneous. Hybrid retrieval must integrate structured monitoring metrics, semi-structured SQL execution plans, and unstructured ticket text at the same time. Retrieval logic adapted to multi-format data must be configured. Data updates are triggered by database changes. Retrieval results must prioritize the latest change records and permission application forms to avoid returning outdated configuration information. Documents contain precise matching fields such as instance ID and permission level. The re-ranking link must prioritize associating instance information in the query to avoid mixing irrelevant results. The size of individual data entries varies widely, so the single length of retrieval results must be limited to adapt to the system's context window restrictions.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.85 | Matches the precise query requirements of database operation and maintenance scenarios, and avoids mixing low-correlation slow SQL or tickets into results |
| `limit` | Top 10 entries | Adapts to the quick browsing needs of operation and maintenance duty scenarios, and avoids excessive results occupying the context window |
| `searchMode` | hybrid | Corresponds to the hybrid retrieval mode, integrating vector retrieval and keyword retrieval to cover structured and unstructured data |
| `usingReRank` | Enabled | Optimizes sorting priority for multi-source heterogeneous data, and prioritizes results matching instance IDs and permission-related content |
| Single search upper limit | 2000 characters | Adapts to the text length of slow SQL reports and change orders, and avoids truncating key execution information |
| Re-ranking model call threshold | Top 8 recalled results | Balances retrieval efficiency and sorting accuracy, and meets the query response requirements of database operation and maintenance scenarios |

## Three Common Mistakes
- Phenomenon: Retrieval results are not sorted by business priority, and irrelevant historical backup records appear at the top of slow SQL query results. Cause: The `usingReRank` configuration is not enabled, only basic vector similarity sorting is used, and precise matching fields such as instance ID are not associated.
- Phenomenon: The number of hybrid retrieval return results is far lower than expected, and there is no clear error message. Cause: The `limit` parameter value is too small, and the `similarity` parameter threshold range is not adjusted, causing some qualified low-similarity results to be filtered out in advance.
- Phenomenon: The re-ranking link fails to trigger, and the interface displays a model call failure prompt. Cause: The re-ranking model call key and address are not configured on the FastGPT platform, or the total character count of the recalled results exceeds the model's input limit.

## How to Confirm the Configuration Is Complete
- Submit a query that includes the database instance ID, and check whether the retrieval results prioritize returning change orders and slow SQL reports for the corresponding instance.
- View the retrieval log to confirm that `searchMode` is set to hybrid mode and the `usingReRank` configuration is enabled.
- Adjust the query keywords to verify that the number of results changes reasonably with adjustments to the `similarity` parameter.
- Trigger a query for a database change ticket, and confirm that the updated content appears in the retrieval results within a reasonable time frame.

The values provided are common starting points and should be measured against the reader's own samples.
