# Operations Duty and Internal Ticket Q&A for Text Annotation Projects: Sharing and Embedding

## What the data for this category looks like
Text annotation project data typically comes from client-provided corpora, annotation results from internal annotation platforms, custom vocabularies, and feedback results from quality inspection sampling. Daily maintained documents include annotation specification documents, batch sample packages, quality inspection reports, and problem feedback forms. Data updates occur daily or synchronized per annotation batch. Document structures use primarily structured fields: text content, entity tags, intent classification, quality inspection markers, and more. All content focuses exclusively on semantics, entities, and intent, with no image-related fields.

## What constraints these characteristics impose on sharing and embedding
The core data of text annotation projects centers on semantic tags, entities, and intent, with high update frequency. Sharing and embedding must therefore ensure data synchronization timeliness, to prevent embedded content from lagging behind latest annotation results. Documents include internal sensitive content such as annotation specifications, so access permissions must be restricted during sharing to stop unauthorized personnel from viewing annotation rules and sample details. Most fields for annotation projects are text-based. After embedding, adapt text display lengths for different scenarios to avoid content overflow or truncation that harms readability. Batch sample packages may have large data volumes, so loading performance must be considered during embedding. Limit content scale loaded in a single instance to prevent page freezes.

## Three common errors
- Sharing entries related to text annotation projects fail to open. First verify the full system-generated link and its validity period, then cross-check browser request statuses; do not manually replace `shareId`.
- The visible scope of text annotation project data does not match expectations. Cross-check third-party identity verification results, workflow request parameters, and external system data permissions separately; the sharing entry identifier itself does not provide business authorization.
- The same text annotation project Q&A is not visible on another device. In anonymous scenarios, first verify device, browser, and local identity status; record retention cannot be guaranteed across devices or after cache clearance, do not use this phenomenon alone to judge service abnormalities.

## How to confirm proper configuration
- Open the embedded page, initiate a conversation related to operations tickets, refresh the page on the same device and browser, then check if previous conversation content and context are retained.
- Use an account that has not passed identity verification to access the share link, confirm that annotation-related content cannot be viewed normally (identity verification is only supported in the commercial edition).
- Wait for the cache duration matching the data update frequency to expire, refresh the page to check if the latest annotation data or updated specification content loads.
- View the browser console logs of the embedded page, confirm there are no loading timeout error messages.
