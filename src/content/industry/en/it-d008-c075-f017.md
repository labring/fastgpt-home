# Operations On-Duty and Internal Ticket Q&A for Documentation Site Maintenance: Deployment and Upgrade

## What Data for This Category Looks Like
This category of data typically originates from code repositories, documentation site build logs, user feedback, and version release records. Daily maintenance documents include installation guides, API documentation, migration guides, and FAQs. Common content fields include version numbers, API paths, configuration parameter names, error messages, and operational steps. Data update frequency is usually weekly or synchronized with version releases. Core document content is adjusted alongside feature iterations. Expired content must be cleaned regularly to prevent misleading users.

## Constraints Imposed by These Characteristics on Deployment and Upgrade
The data characteristics of this category create multiple constraints during deployment and upgrade. First, data sources include version release records. During deployment, strictly match configuration parameters for the corresponding version to avoid using outdated fields from older version documents. Second, update frequency adjusts with version iterations. Before upgrading, consult the migration guide to confirm configuration changes introduced by version differences. Additionally, daily documents include API documentation and FAQs. After deployment, verify API call logic to align with documentation instructions. Regularly clean expired content to prevent users from referencing incorrect information and creating support tickets.

## How to Set Configuration Values
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | Full connection string with authentication information, formatted as `mongodb://[username:password@]host:port/database_name` | Matches the database connection format required in the documentation site installation guide to ensure normal data storage |
| `REDIS_URL` | `redis://[username:password@]host:port/database_number` | Used for caching documentation site static resources and session data, must match the Redis instance in the deployment environment |
| `DB_MAX_LINK` | `100–200 concurrent connections` | Limits the number of database connections to avoid exceeding resource limits of the deployment environment |
| `FE_DOMAIN` | External access domain name of the documentation site, such as `https://docs.fastgpt.example.com` | Used to generate correct resource links and callback addresses to avoid cross-domain or link errors |
| `ROOT_KEY` | Randomly generated string of 32 or more characters, calibrated based on actual testing | Used for highest privilege verification of the management backend, must comply with the key length specification required in the documentation |
| `STORAGE_S3_ENDPOINT` | Access address of the corresponding object storage service, such as `https://s3.example.com` | Used to store documentation site build logs and static resources, must match the access address provided by the storage service provider |

## Three Common Misconfigurations
- Symptom: After deployment, calling internal interfaces returns certificate verification failure, and documentation site resources fail to load normally. Cause: The deployment environment machine cannot directly request interfaces via HTTPS, and relevant settings to skip certificate verification are not configured.
- Symptom: After upgrading to FastGPT v4.17.0, the document reference function does not work as expected, but still displays referenced content. Cause: The configuration switch for the reference function was not adjusted according to the version migration guide, resulting in failure to correctly load configuration parameters.
- Symptom: After creating a tool call application, some models cannot trigger the preset tool call logic. Cause: The tool call parameter format required in the documentation site API documentation was not matched, resulting in failure to meet the logical judgment conditions.

## How to Verify Configurations Are Correct
- Run connection test commands for the database and cache services to verify that `MONGODB_URI` and `REDIS_URL` configurations match the actual deployment environment.
- Access the external domain name of the documentation site to check whether static resources and interface return content conform to the documentation instructions, confirming that `FE_DOMAIN` is configured correctly.
- View the documentation site build logs to confirm that the latest update content has been synchronized and expired content has been cleaned up.
- Test the tool call trigger process, compare the parameter requirements in the API documentation, and confirm that the configuration complies with the specifications of the corresponding version.
