# Operations On-Call and Internal Ticket Q&A for Logging Platforms and Observability: Sharing and Embedding

## What this category of data looks like
Data for logging platforms and observability originates from logging systems, distributed tracing (Trace) platforms, Metrics indicator systems, and business application SDKs.
Data updates occur daily or when a version is released.
Daily supporting materials include logging collection specifications, tracing guidelines, indicator dictionaries, and dashboard configuration records.
Data fields include log levels, trace IDs, timestamps, indicator values, and other entries.
Some fields use fixed units: timestamps use milliseconds, indicator values use percentages or bytes.

## Constraints on Sharing and Embedding
Since data sources include multiple types of operations and maintenance tools, align permissions between external data sources and FastGPT application access permissions during embedding. This prevents unauthorized access to logs or indicator data.
Relevant permission configuration must be implemented by the external system or the identity authentication module of the FastGPT application.
Data has a high update frequency. External systems must implement separate refresh or synchronization logic. The FastGPT shared application only acts as an access entry. Ensure on-call personnel retrieve the latest information through the shared entry.
There are many supporting documents with a fixed structure. External systems must configure knowledge base association rules separately. The FastGPT shared entry only provides the application access path and cannot include built-in document association configurations.
Operations on-call and ticket scenarios require that different users only view their own conversations. Implement permission isolation through the FastGPT application’s user isolation configuration or by connecting to a third-party identity authentication system.
Some scenarios require hiding non-essential operation buttons such as the Markdown export function. Configure this through the FastGPT application’s release settings.
Associate exclusive data sources through separate external system configuration to improve configuration accuracy.
This configuration is based on FastGPT v4.17.0.

## Three Common Configuration Mistakes
- Shared entries for logging platform and observability fail to open. First verify the full system-generated link and its validity period, then check browser request statuses. Do not manually replace `shareId`.
- The visible scope of logging platform and observability data does not match expected results. Verify third-party identity authentication results, workflow request parameters, and external system data permissions separately. The shared entry identifier itself does not provide business authorization.
- The same logging platform and observability Q&A cannot be viewed on another device. For anonymous scenarios, first check the device, browser, and local identity status. Retention cannot be guaranteed across devices or after cache clearance. Do not use this phenomenon alone to judge service anomalies.

## How to Verify Configuration Completion
- Open the embedded iframe page, confirm the Markdown export button is not present to verify the configuration takes effect. Also check that the FastGPT application release configuration’s associated data source matches the target. Data source association must be configured separately by the external system.
- Use two different accounts to access the embedded application separately. Verify that each account can only view its own initiated conversation history. Commercial editions must implement this isolation by connecting to a third-party identity authentication system.
- Adjust the iframe size to an adaptive value. Confirm the logging dashboard and conversation area are fully displayed without content truncation.
- Test whether the shared link becomes inaccessible after the 7-day sample validity period to verify the validity period configuration is correct.

All provided configuration values are common starting points. Adjust them based on your own specific samples and requirements.
