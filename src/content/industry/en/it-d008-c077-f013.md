# Operational Duty and Internal Ticket Q&A for Computer Room Inspection and Environmental Monitoring: Permission and Data Isolation

## What data this category includes
Daily data for this use case includes four categories: inspection forms, temperature and humidity records, alarm records, and duty logs. Data sources include dynamic environment monitoring systems, access control systems, UPS monitoring devices, and video inspection tools. Data update frequencies are split into real-time and daily. Real-time data such as alarm information and temperature and humidity readings are pushed directly by collection devices. Duty logs and inspection forms are updated during each daily shift handover cycle. Data fields include device ID, temperature and humidity values (units: ℃ and %RH), alarm level, physical device location, duty personnel ID, and timestamp. Data fields from different sources have clear classification boundaries.

## What constraints these characteristics impose on permission and data isolation
Multi-source heterogeneous data sources require permission isolation to match the ownership scope of each system, preventing cross-system unauthorized access. Real-time updated alarm and temperature and humidity data require permission configurations to take effect immediately, otherwise exceptions may not be handled promptly by the relevant team. Inspection records and duty logs contain sensitive physical location and personnel information, so fine-grained permission control based on responsible areas and shifts is required. Internal tickets must be linked to the operation and maintenance team for the corresponding computer room, ensuring tickets only circulate among personnel assigned to that area.

## How to configure settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `teamId` binding rule | Assign a unique `teamId` to each computer room area, such as A Computer Room Group, B Computer Room Group | Matches the classification storage of inspection data by area, ensuring operation and maintenance teams for different areas only access corresponding data |
| `tmbId` permission grouping | Assign a `tmbId` to each duty shift, such as morning shift group, evening shift group | Adapts to the shift-based classification of duty logs, ensuring personnel from different shifts only access logs for their own shift |
| Data field filtering | Only expose temperature and humidity (℃), alarm level, and device ID fields | Meets sensitive field control requirements for inspection records, hiding non-essential information such as physical device location |
| Real-time data source permissions | Bind `teamId` to data sources from dynamic environment monitoring and UPS monitoring | Adapts to the real-time update characteristics of this data, ensuring permission configurations take effect immediately |
| Ticket permission association | Link the `tmbId` of duty logs to the corresponding operation and maintenance team | Ensures internal tickets are only visible to personnel responsible for the corresponding computer room and shift |
| Permission effective latency | No more than 600 seconds | Adapts to the processing rhythm of real-time alarm data, preventing delayed response to exceptions caused by permission lag |

## Three common configuration errors
- Symptom: After configuring `teamId` binding for data sources, some inspection data cannot be accessed by the corresponding team. Cause: Data sources for dynamic environment monitoring and UPS monitoring are not correctly associated with `teamId`, leading to failed permission mapping.
- Symptom: After adding a custom data source, input parameters for corresponding inspection data do not appear in the workflow. Cause: The binding relationship between `teamId` and the data source is not configured, so permission verification fails and parameters fail to load.
- Symptom: Cross-shift operation and maintenance personnel can view duty logs from other shifts. Cause: Shift permissions are not assigned based on `tmbId`, leading to disorganized permission grouping.

## How to confirm configurations are correct
- Log in to the account associated with the target `teamId`, verify that you can only view temperature and humidity records and alarm logs for your assigned computer room, and cannot access data from other areas.
- Log in to the account associated with the target `tmbId`, verify that you can only view duty logs for your assigned shift, and cannot access records from other shifts.
- Trigger a test alarm, confirm that only operation and maintenance personnel responsible for the corresponding computer room and shift receive internal ticket notifications.
- After modifying permission configurations, wait no more than 600 seconds for the change to take effect, then verify that data access permissions are updated as expected.
- View data source binding logs in FastGPT v4.17.0, confirm that the association between `teamId` and `tmbId` with dynamic environment monitoring and access control systems is functioning normally.
