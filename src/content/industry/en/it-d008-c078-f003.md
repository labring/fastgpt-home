# Cabinet Rack Installation and Cabling Operations Duty and Internal Work Order Q&A: Sharing and Embedding

## What data for this category looks like
The typical users of this category are IDC operations engineers, network engineers, and equipment implementation staff. Daily processed data includes rack installation applications, cabinet cabling diagrams, port label sheets, construction records, and more. Data sources are usually DCIM systems, internal asset systems, network topology diagrams, and customer-submitted work orders. Update frequency is per order per day. Each single data entry includes structured fields such as rack position number, cable length, port identifier, construction date, equipment model, and others. Some entries come with visual cabling drawing attachments.

## What constraints these characteristics impose on the "sharing and embedding" workflow
Since data originates from internal systems and customer work orders, access permissions for embedding scenarios must be strictly controlled to avoid unauthorized disclosure of cabinet and equipment information. The data update frequency is per order per day. External business systems implement knowledge base synchronization separately. Corresponding knowledge base nodes handle FastGPT knowledge base updates, to prevent returning outdated cabling and port information. Each single data entry includes structured fields and visual attachments. FastGPT knowledge base retrieval supports associating structured fields and attachment content, and external systems must provide corresponding knowledge base data. Since the results of cabinet rack installation and cabling directly affect equipment operation and customer delivery, external business systems pass the current work order unique identifier. FastGPT uses this identifier to filter the retrieval scope, establish context association between the conversation and the corresponding work order, ensure that Q&A only relates to the currently operated cabinet and work order, and avoid irrelevant data interfering with on-site operations.

## Three common mistakes
- Sharing entry for cabinet rack installation and cabling fails to open. First verify the complete system-generated link and its validity period, then check browser request status; do not manually replace `shareId`.
- The visible scope of cabinet rack installation and cabling data does not match expectations. Verify third-party identity verification results, workflow request parameters, and external system data permissions respectively; the sharing entry identifier itself does not provide business authorization.
- The same cabinet rack installation and cabling Q&A cannot be viewed on another device. For anonymous scenarios, first check device, browser, and local identity status; record retention cannot be guaranteed across devices or after clearing cache, do not judge service abnormalities solely based on this phenomenon.
