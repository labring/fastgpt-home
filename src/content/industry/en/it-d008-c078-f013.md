# Cabinet Deployment and Cabling: Operations On-Duty and Internal Ticket Q&A: Permission and Data Isolation

## What this category of data looks like
Typically includes four core document types: deployment application forms, cabinet cabling diagrams, port label sheets, and construction records. Data sources include DCIM systems, asset management systems, network topology diagrams, and customer-submitted tickets. Data update frequency is per ticket or daily. Core fields include cabinet position number, device model, cable number, port correspondence, construction time, etc. Asset data for different cabinets is mutually independent and belongs to a clear data center room or customer.

## What constraints do these characteristics impose on permission and data isolation
This type of data involves physical data center assets and customer tickets. Data with different ownership requires strict isolation. Use unified permission verification logic for multi-source data to prevent cross-system data leaks. Follow the per-ticket or daily update feature requirements to ensure permission changes take effect promptly, preventing unauthorized access caused by old permission caches. Operations staff in different roles only access the cabinet data they are responsible for, and do not view asset information from other customers or data center rooms. Align permission divisions with daily operations role divisions.

## How to configure

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `teamId` team isolation identifier | Bind to the `teamId` of the corresponding IDC data center room | Matches the data center room ownership in the DCIM system, ensuring that tickets for the same data center room are only visible to authorized teams |
| Permission group configuration | Divided by role: deployment applicants only view the tickets they submitted, implementation engineers only view cabling data for responsible cabinets | Matches daily operations role divisions, preventing access to unrelated data |
| Single-round Q&A return count | Top 5 entries | Limits the amount of cabinet data returned in a single query, avoiding exposure of unrelated sensitive information |
| Context cache duration | 600 seconds | Matches the daily ticket update frequency, ensuring that caches are refreshed promptly after permission changes |
| `tmbId` asset association identifier | Bind to the `tmbId` of the corresponding device asset | Associates device ownership in the DCIM system, preventing unauthorized cross-device data access |

## Three common configuration errors
- After configuring `teamId`, the workflow node does not display the input parameters for corresponding cabinet data. Cause: `teamId` was not bound to the data source configuration of the DCIM system, resulting in the permission identifier not taking effect.
- Engineers within the same team cannot view construction records for a specified cabinet. Cause: Permission group configuration was not refined to cabinet ownership, and all data center room data was mistakenly opened to the entire team.
- Cabling diagram data returned by Q&A exceeds the expected range. Cause: Single-round Q&A return count was not limited, resulting in sensitive data from unauthorized cabinets being returned.

## How to verify correct configuration
- Switch test accounts for different teams, verify that only deployment application tickets for the corresponding data center room are visible.
- Submit a test deployment application, confirm that only the submitter and authorized implementation engineers can view the detailed information of this ticket.
- Trigger a workflow task bound with `teamId`, confirm that only cabinet-related data for the corresponding data center room is returned.
- Modify the permission configuration and wait 600 seconds, verify that the new permissions take effect in Q&A interactions.
