# Cabinet Installation and Cabling Operations Duty and Internal Work Order Q&A: Knowledge Base Retrieval and Recall

## What data for this category looks like
This category of data mainly comes from DCIM systems, internal asset ledgers, network topology diagrams, and work orders submitted by customers. Daily processed documents include cabinet installation application forms, physical cabling diagrams, port correspondence label tables, and one-time installation construction records. Data updates trigger per work order or update daily. Fields include cabinet position number, cable specification, port identifier, construction time, customer access requirements, and more. The number and format of fields in a single data entry vary slightly based on work order type.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link
The data characteristics of this category create multiple constraints for knowledge base retrieval and recall. First, data originates from multiple heterogeneous systems, with differing field formats. Retrieval requires precise matching of specific fields such as cabinet position number and port identifier to avoid recalling irrelevant content. Second, data updates trigger per work order or daily. The knowledge base must maintain real-time synchronization to ensure recalled content aligns with latest construction records and asset ledgers. Additionally, daily documents include tabular cabling diagrams and text-based work order applications. Different content formats require adapted chunking and recall logic. Work order questions mostly focus on cabling planning and verification for specific cabinet positions, demanding more targeted recall results.

## Three common errors
- Phenomenon: After setting custom delimiters and manual line breaks, chunking results either merge multiple cabling paragraphs or split individual port label entries. Cause: Chunking parameters were not adjusted to match the structured format of documents in this category. Relying solely on fixed delimiters cannot meet chunking requirements for tabular cabling diagrams and fixed-format label tables.
- Phenomenon: Chinese questions cannot recall cabinet-related documents in the knowledge base. Cause: `datasetSearchUsingExtensionQuery` was not enabled, and colloquial maintenance questions were not converted to standard format, leading to failure to match structured fields such as cabinet position number and port identifier.
- Phenomenon: Retrieval results include cabling information from non-target cabinet positions. Cause: The `similarity` threshold was not set, or the threshold was set too low, resulting in recall of content that does not meet similarity standards.

## How to verify correct configuration
- Upload a cabinet installation application form and cabling diagram, perform a simulated retrieval, and check whether returned results include key fragments of the corresponding documents.
- Check the knowledge base synchronization log to confirm that latest data from DCIM systems and work order systems has synchronized to the bound `collectionIds` collection.
- Adjust the `similarity` threshold to verify whether recall results under different thresholds meet the accuracy requirements for cabinet position matching.
- Submit a test work order question containing a specific cabinet position number to confirm whether returned results focus on cabling information for that cabinet position.
