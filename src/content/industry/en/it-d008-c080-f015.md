# Desktop Terminal Support for Operations On-Call and Internal Ticket Q&A: Knowledge Base Retrieval and Recall

## What data for this category includes
Data for this category primarily comes from terminal management platforms, enterprise asset systems, user trouble ticket systems, and software repositories. Daily processed documents include terminal trouble tickets, installation manifests, software installation records, and remote assistance operation logs. Data is updated either daily or in real time when a ticket is created. Individual documents typically contain fields such as device serial number, fault symptom, troubleshooting steps, and software version number. Field structures vary based on document type, and there are no fixed mandatory units.

## Constraints on knowledge base retrieval and recall from these characteristics
Dispersed data sources lead to inconsistent document formats. The retrieval module must adapt to field structures from different sources to avoid retrieving irrelevant asset ledger content. Flexible update frequencies require the retrieval module to support real-time or on-demand refresh of the knowledge base index, to prevent retrieving outdated installation records. The flexible field structure of individual documents means retrieval must use keywords to precisely match core fields such as fault type and device identifier, to avoid overly broad retrieval of irrelevant content. Additionally, ticket response time requirements for desktop terminal support demand controlling retrieval latency to avoid impacting the efficiency of on-call engineers.

## Configuration guidelines
The following configuration items apply to FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the precision requirement for terminal trouble tickets, filters low-relevance general operations and maintenance content |
| `limit` | Top 5–8 results | Adapts to the needs of on-call engineers for quick review, avoids excessive results that distract attention |
| `searchMode` | Keyword matching priority | Adapts to retrieval of clearly defined fields such as device serial number and fault symptom in terminal trouble tickets |
| `usingReRank` | Enabled | Re-ranks retrieval results by relevance to improve the display priority of core troubleshooting documents |
| `datasetSearchUsingExtensionQuery` | Enabled | Generates extended query terms to cover common variant expressions for terminal faults |
| `collectionIds` | Bind dedicated knowledge base collections for desktop terminal support | Limits the retrieval scope to avoid retrieving operations and maintenance documents from other categories |

## Three common configuration errors
- Symptom: Retrieval results include non-desktop terminal-related installation manifests with empty fields. Cause: `collectionIds` is not correctly configured, and no dedicated knowledge base collection is bound, leading to retrieval scope covering the entire platform’s knowledge base.
- Symptom: `worker terminated due to reaching memory limit` error, common in FastGPT v4.13.2. Cause: The `limit` parameter value is not restricted, retrieving too many documents causing memory usage to exceed thresholds.
- Symptom: No matching content is returned after variable reference. Cause: The user-reported device serial number is not correctly passed as a retrieval variable, or variable matching logic is not enabled in the retrieval configuration.

## How to verify correct configuration
- Manually input a known terminal trouble ticket keyword, confirm retrieval results only include desktop terminal support-related documents.
- View logs from the knowledge base retrieval module to confirm no memory limit exceeded errors occur, and retrieval latency meets expectations.
- Pass a device serial number as a retrieval variable to verify that the corresponding device’s installation manifests and software installation records are retrieved.
- After enabling `usingReRank`, check if the order of retrieval results matches the core needs of fault troubleshooting.

The values provided are common starting points and should be validated against samples from the target deployment.
