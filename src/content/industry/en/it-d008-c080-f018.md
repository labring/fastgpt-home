# Desktop Terminal Support for Operations On-Duty and Internal Ticket Q&A: Re-Ranking and Hybrid Retrieval

## What this category’s data looks like
This category of data primarily comes from terminal management platforms, asset systems, user reporting channels, and software repositories. The primary processing stakeholders are desktop operations and maintenance staff, IT support engineers, and on-site outsourced personnel. Daily processed documents include terminal fault tickets, installation checklists, software installation records, and remote assistance logs. Each document contains fields such as device unique identifier, fault phenomenon description, hardware model, software version, processing time, and user employee ID. Data updates occur either via daily batch synchronization or real-time updates triggered by user requests.

## What constraints these characteristics impose on re-ranking and hybrid retrieval
Data sources for this category are scattered and have inconsistent formats. The hybrid retrieval process must first complete unified mapping of cross-system fields to prevent missing fields or format inconsistencies in retrieval results. Different data sources have varying update schedules: real-time fault reporting data must take priority in retrieval, while batch-synced asset data requires sorting weights adjusted based on update time. Multiple document types cover scenarios including fault troubleshooting and hardware configuration. The re-ranking process must distinguish business relevance across document types, and prioritize returning fault reproduction steps or software installation records that closely match the current ticket. Desktop terminal operations and maintenance have strict timeliness requirements, so re-ranking must prioritize valid processing records from the past 7 days.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.65–0.75 | Filter low-match irrelevant terminal fault records, retain core matching fault troubleshooting content |
| `limit` | Top 10 entries | Adapt to the information processing volume of a single desktop operations and maintenance ticket, avoid excessive redundant results interfering with troubleshooting |
| `searchMode` | hybrid | Combine keyword retrieval and semantic retrieval to cover multi-dimensional retrieval needs such as hardware models and fault phenomena |
| `usingReRank` | Enabled | For hybrid retrieval results of multiple document types, re-rank to prioritize returning core content matching the current ticket |

## Three Common Misconfigurations
- Symptom: Retrieval result order does not change after enabling `usingReRank`. Cause: The re-ranking model’s API key or model call chain is not configured correctly, or the re-ranking model’s recall threshold does not match the base retrieval threshold.
- Symptom: Re-ranking related configuration items cannot be selected when creating an application. Cause: Re-ranking functionality is not enabled in system configuration, or the current FastGPT v4.17.0 version does not support the re-ranking module.
- Symptom: Re-ranking model call returns a timeout error. Cause: A reasonable upper limit for retrieved results is not set, causing the re-ranking model to process an excessively large data volume that exceeds the 30-second call time limit.

## How to confirm the configuration is complete
- Check the re-ranking switch status on the application configuration page, confirm that `usingReRank` is enabled.
- Submit a simulated terminal fault ticket, compare the sorting differences of retrieval results before and after enabling re-ranking to verify that the re-ranking function is active.
- Check system logs to confirm that there are no error fields or status codes in the re-ranking model’s call requests and returned results.
- Adjust the `similarity` parameter value, observe changes in the number of retrieved results to confirm that the parameter configuration has taken effect.

The values provided here are common starting points and should be evaluated against the reader’s own samples.
