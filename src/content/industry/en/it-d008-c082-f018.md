# Operational On-Call and Internal Ticket Q&A for Channel Attribution and Lead Distribution: Reranking and Hybrid Retrieval

## What the Data for This Category Looks Like
The data for this category primarily comes from advertising platforms, customer relationship management systems, attribution SDKs, and online form systems. Core documents for daily maintenance include attribution rule configuration tables, lead distribution tables, daily channel conversion reports, and abnormal lead checklists. Data update frequencies are mostly daily or weekly. Fields include channel unique identifiers, lead source parameters, conversion timestamps, sales attribution accounts, and more. Units include timestamps, count units, currency units, and others. Data formats vary across different sources.

## What Constraints Do These Characteristics Impose on Reranking and Hybrid Retrieval?
The multi-source, heterogeneous data characteristics of this category require the hybrid retrieval link to be compatible with field mapping rules for different data sources, and to set dedicated retrieval fields for different document types such as attribution rules and lead distribution tables. The daily or weekly update frequency requires that retrieval prioritizes the latest channel reports and abnormal checklists, so a weight adjustment mechanism based on update time must be configured. Structured daily documents require the reranking link to perform precise matching on key fields such as lead IDs and channel parameters, to avoid interference from non-key fields on retrieval results. The accuracy of sales attribution-related data directly affects retrieval priority, so a weight factor for attribution credibility must be added to the reranking link to ensure that ticket Q&A results align with business logic.

## Three Common Configuration Mistakes
- Symptom: The rerank marker field in retrieval results returns false, and the sorted results after reranking are not displayed in the interface. Cause: The reranking toggle is not enabled, or the reranking model configuration is not bound to the corresponding data source.
- Symptom: When adding a reranking model with the same name, the existing model configuration with the same name is automatically overwritten. Cause: The system only supports a single reranking model configuration per name. Configure model names with unique identifiers for different data sources.
- Symptom: Calling the reranking model returns empty content with no valid sorting results. Cause: The input parameter format of the reranking model does not match the data source fields, or the model call timed out without returning a result.
