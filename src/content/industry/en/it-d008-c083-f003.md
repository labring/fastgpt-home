# Operations on-duty and internal ticket Q&A for game content compliance self-audit: Sharing and embedding

## What this category of data looks like
Game content compliance self-audit data comes from game text, art assets, plot scripts, and public regulatory requirements, with an update cadence of per version or per event. Daily used documents include content self-audit checklists, sensitive content modification records, user agreements, and compliance review minutes. Service targets include game release compliance officers, content review officers, and producers. Data fields cover text sensitive words, art compliance tags, plot compliance nodes, and review opinions. There are no additional custom statistical units; compliance verification content for corresponding versions or events is stored only by document category.

## Constraints on the sharing and embedding workflow
Since the data source includes multiple types of game content and has a high update frequency, the associated knowledge base must support regular synchronization of the latest compliance verification data to avoid returning outdated self-audit results. Daily documents are scattered across categories such as self-audit checklists and modification records, so the associated knowledge base must support filtering compliance data for specified categories. This configuration is completed by the external business system or the corresponding knowledge base; the FastGPT sharing entry only calls data that meets the filter criteria.

Additionally, compliance data involves sensitive content, so embedded access must restrict internal permissions to prevent external leaks. In the operations on-duty scenario, the embedded interface must maintain stable loading speed to avoid affecting the real-time response efficiency of on-duty personnel. The interface must adapt to the layout dimensions of internal ticket systems and review pages to ensure seamless integration with existing workflows.

## Three common configuration mistakes
- Failure to open the sharing entry related to game content compliance self-audit. First verify the complete system-generated link and its validity period, then check the browser request status; do not replace `shareId` independently.
- Mismatch between the visible scope of game content compliance self-audit data and expected results. Verify the third-party identity verification result, workflow request parameters, and external system data permissions separately; the sharing entry identifier itself does not provide business authorization.
- Unable to view the original conversation of the same game content compliance self-audit Q&A on another device. For anonymous scenarios, first check the device, browser, and local identity status; record retention cannot be guaranteed across devices or after clearing cache, do not judge the service as abnormal based solely on this phenomenon.
