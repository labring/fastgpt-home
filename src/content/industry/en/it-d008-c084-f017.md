# Operations on-duty and internal ticket Q&A for game client performance optimization: Deployment and upgrade

## What data for this category looks like
Data for this category typically originates from engine Profiler, crash analysis platforms, real-device test equipment, and frame rate collection tools. Updates follow a daily or per-version release cycle. Daily output documents include performance test reports, device compatibility lists, optimization iteration records, and crash analysis reports. Common fields include device model, frame rate value, resource occupancy ratio, crash stack information, and pre- and post-optimization comparison items. There is no unified mandatory format, and configurations must be adapted to the daily collaboration habits of the R&D team.

## Constraints imposed by these characteristics on the deployment and upgrade workflow
Data sources for this category are scattered and update frequency is high. The deployment link must support batch access to multi-source logs and test data, while adapting to high-frequency knowledge base incremental updates. Daily document formats are inconsistent. Knowledge base index rules that support custom field mapping must be configured to avoid retrieval failures caused by format differences. The low-end device reproduction and resource occupancy analysis links generate large volumes of structured and unstructured data. Sufficient storage and computing resources must be reserved during deployment to support storage and real-time retrieval of massive performance logs. Optimization iteration records must be linked with internal ticket systems. Association fields between tickets and documents must be configured during deployment to quickly locate tickets and historical records corresponding to optimization issues.

## Configuration settings
These configurations apply to FastGPT v4.17.0.

| `FILE_TOKEN_KEY` | `Randomly generated 32-bit string` | Encrypts download links for performance reports to prevent unauthorized internal personnel from accessing sensitive optimization data |
| `ROOT_KEY` | `Configured as a dedicated key for the internal operations team` | Restricts only authorized personnel from performing batch knowledge base updates and system upgrade operations |

## Three common configuration mistakes
- The symptom is that when running the `docker-compose up` command, pulling official images times out, and the process takes multiple hours to complete. The cause is that no domestic image acceleration address is configured, resulting in slow pulling of images related to large-volume game performance log storage.
- The symptom is significant delays in returned results when retrieving frame rate data or device compatibility lists in the knowledge base. The cause is that the database connection count configuration is not adjusted, and index threads become blocked during batch import of performance test reports, making it impossible to respond to retrieval requests in a timely manner.
- The symptom is that after deploying multiple replicas in a K8s cluster, the same performance optimization ticket is processed repeatedly by multiple nodes. The cause is that no Redis distributed lock is configured, causing multiple replicas to simultaneously read and process the same ticket data.

## How to verify successful configuration
1.  Under FastGPT v4.17.0, execute the `docker ps` command to confirm that all service containers are running and there are no abnormally exited logs.
2.  Upload a small performance test report, perform a retrieval operation, and confirm that the index generation process completes normally.
3.  After configuring the internal operations team's dedicated key, attempt to access the system configuration page using an unauthorized key, and confirm that access is denied.
4.  Simulate batch import of performance logs, check the database connection count monitoring panel, and confirm that the connection count does not exceed the preset configuration value.

The values provided are common starting points and should be measured against the reader's own samples.
