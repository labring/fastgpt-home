# Operations Duty and Internal Ticket Q&A for Game Server Development and Operations: Permission and Data Isolation

## What the Data for This Category Looks Like
Common data sources include game operation logs, real-time online player count monitoring, business databases, and player feedback tickets. Update frequency is daily or adjusted alongside large-scale game events. Daily operation and maintenance documents include server architecture descriptions, server launch capacity plans, server merging data verification processes, and fault troubleshooting reports. Data fields cover server node identifiers, peak online counts, player account ranges, fault trigger times, and more. Units include person-times, GB, timestamps, and other standard units.

## What Constraints These Characteristics Impose on Permission and Data Isolation
Game server operation data involves sensitive information such as player accounts and online status. Daily documents include core operation plans like server launches and merges. Therefore, permission isolation must divide access boundaries based on operation and maintenance roles and project teams. Frequently updated real-time monitoring data and server merging data tied to event cycles require isolation configurations that can be quickly adjusted alongside business rhythms. Documents and data for different operation and maintenance scenarios, such as duty troubleshooting and server launch preparation, must be strictly isolated. This prevents unauthorized personnel from accessing core operation processes and player private data. Operation tickets involve cross-team collaboration, so access ranges must be divided by shift periods. This ensures on-duty personnel can handle issues promptly, while off-duty personnel cannot interfere with tickets for the current shift.

## How to Set Configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Team Permission Groups | Divide into launch teams, duty teams, and SRE teams | Matches standard game server operation and maintenance division, clarifies access boundaries for each role |
| Data Isolation Scope | Bind `teamId` to corresponding server nodes | Matches game server node attribution rules, ensures data is only visible to authorized teams |
| Ticket Access Permissions | Only allow duty operation and maintenance teams to view tickets from their shift | Aligns with operation and maintenance shift rotation processes, prevents off-duty personnel from taking actions |
| Global Variable Isolation | Isolate identically-named variables by user ID | Adapts to exclusive configuration needs of different operation and maintenance personnel, avoids parameter conflicts |
| Permission Activation Latency | Synchronize updates within 10 minutes | Matches real-time adjustment requirements for game server configurations |
| SSO Integration Configuration | Bind to enterprise identity sources | Supports enterprise-level unified identity management, compatible with FastGPT v4.17.0 |

## Three Common Misconfigurations
- Phenomenon: An operation and maintenance personnel cannot view specified server architecture documents and logs after logging in. A no access permission prompt appears on the interface. Cause: The operation and maintenance personnel's account is not bound to the corresponding `teamId`, so the system cannot match the authorized access scope.
- Phenomenon: Operation and maintenance personnel from different shifts see ticket data from non-current shifts. Cause: Ticket access permissions are not configured according to shift cycles, and full ticket view permissions are enabled by default.
- Phenomenon: Parameter conflicts occur in global variables. Identically-named variables modified by different operation and maintenance personnel overwrite each other. Cause: The configuration to isolate global variables by user ID is not enabled, so variable scopes are not divided by user.

## How to Confirm the Configuration Is Properly Set
- Log in to the account assigned to the target operation and maintenance role. Confirm that only server architecture documents and log data for their team are visible.
- Submit a test ticket. Confirm that only the duty operation and maintenance team can view the ticket, while other teams cannot access it.
- Modify a global variable. Check that variables used by other operation and maintenance personnel are not affected, confirming that isolation is active.
- Test the SSO login process. Confirm that identity verification can be completed via the enterprise identity source, and corresponding permissions are obtained.
