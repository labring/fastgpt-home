# Operations Duty and Internal Ticket Q&A for Game Planning and Numerical Design: Sharing and Embedding

## What Data for This Category Looks Like
Daily documents for game planning and numerical design include gameplay design proposals, numerical tables, version requirement sheets, and balance test records. Data sources are player behavior data, public competitor materials, battle logs, and version feedback. Update frequency is weekly or per game version. Document structures contain structured numerical thresholds, gameplay rule parameters, and version iteration identifiers. Most fields fall into rule, numerical, and feedback categories. There is no unified lightweight format, and some content includes lengthy text descriptions.

## Constraints Imposed by These Characteristics on Sharing and Embedding
Because most documents are long-text gameplay rules and structured numerical tables, sharing and embedding require accurate content association to avoid logical breaks when content is split. Since data updates occur weekly or per game version, documents linked via shared links must be updated to the latest version by the external knowledge base system to prevent outdated content. Internal operations duty and ticket Q&A involve sensitive player data and planning documents, so access permissions must be strictly limited to only internal authorized personnel. Additionally, support for user identifier passing is required to align with the permission tracking needs of internal systems.

## Three Common Errors
- Sharing entries for game planning and numerical design fail to open. First verify the full system-generated link and its validity period, then check browser request status. Manual replacement of `shareId` is prohibited.
- The visible scope of game planning and numerical design data does not match expectations. Third-party identity verification results, workflow request parameters, and external system data permissions are verified separately. The sharing entry identifier itself does not grant business authorization.
- The same game planning and numerical design Q&A is not visible on another device. For anonymous scenarios, device, browser, and local identity status are checked first. Retention is not guaranteed across devices or after cache clearance. Service anomalies cannot be judged solely based on this phenomenon.

## How to Verify Proper Configuration
- The shared link is opened, and displayed content is confirmed to exactly match the current version gameplay design proposals and numerical tables updated by the external knowledge base system.
- A non-internal account attempts to access the shared link, and loading fails or an access denied prompt is shown.
- The document linked via the shared link is verified to be the latest current version gameplay design proposals and numerical tables updated by the external knowledge base system.
- User identifier passing is verified to work correctly through the internal permission system.
