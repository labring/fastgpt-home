# Operations On-Duty and Internal Ticket Q&A for Player Customer Support and Public Opinion Management: Permission and Data Isolation

## What the data for this category looks like
Daily data for this category primarily comes from customer support systems, community forums, app store reviews, and game logs. Update frequency is daily or real-time. Daily documents include player tickets, compensation requests, public opinion daily reports, and standardized response scripts. Data fields typically include unique ticket identifiers, player account identifiers, feedback types, processing progress, and associated log numbers. There are no unified fixed units, and values are adjusted based on specific business scenarios.

## What constraints do these characteristics impose on permission and data isolation?
Data sources for this category are scattered and updated in real time. Isolation of player tickets and public opinion data across different game partitions is required to prevent cross-project data mixing. Documents contain sensitive player account information, so access to private content must be restricted for unauthorized roles. Different business roles — customer support, public opinion specialists, publishing operations — have distinct scope of responsibilities. Differentiated access permissions must be configured to ensure only corresponding roles can process matching types of business data. Additionally, real-time updated data requires that permission configuration changes take effect quickly, to avoid data leaks or access anomalies caused by delayed permissions.

## How to set the configurations
The following configurations were completed based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `teamId` | Bind the team ID corresponding to the target game partition | Player tickets are grouped by game partition, so customer support for different partitions only accesses ticket and public opinion data under the corresponding `teamId` |
| `tmbId` | Assign exclusive IDs by role group | Customer support, public opinion specialists, and publishing operations use different `tmbId`s to restrict cross-role access to unauthorized documents |
| Team document permissions | Only allow access to business documents bound to the current team | Determined through actual testing | Isolate sensitive player data and public opinion information across different game projects |
| Sensitive field access | Only authorized roles can view player account and compensation request details | Determined through actual testing | Prevent non-essential roles from accessing player private information |
| Permission activation time | Permission changes take effect within 10 minutes | 10 minutes | Match the real-time update rhythm of data in this category to ensure permissions take effect promptly |
| Session context isolation | Isolate context per single ticket session | First 5 historical interactions | Avoid mixing contexts from different tickets, which could affect processing accuracy |

## Three Common Mistakes
- Symptom: An error indicating no permission to access the knowledge base is displayed when calling a team application as a tool. Cause: The application was not bound to the corresponding `teamId`, so it cannot call player ticket or public opinion documents within the team.
- Symptom: Team members do not receive permission invitation notifications and cannot join the authorized group. Cause: No channels other than in-site notifications were configured, and reliance on the system's default notifications led to delayed viewing.
- Symptom: Public opinion data from different game partitions is accessed across roles. Cause: `teamId` isolation was not configured per partition, resulting in mixed access to business data from different partitions.

## How to Confirm the Configuration Is Complete
- Switch the `tmbId` of different roles to confirm that only player tickets and public opinion documents within the corresponding role's permission scope are accessible.
- Submit a test ticket to confirm that only authorized operations roles can view game log data associated with the ticket.
- Modify the permission configuration, wait 10 minutes, and verify that the new permissions take effect for real-time updated public opinion data.
- Attempt to call business documents outside the team to confirm that a permission block prompt is triggered and normal access is blocked.
