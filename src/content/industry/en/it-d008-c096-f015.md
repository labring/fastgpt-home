# Operations Duty and Internal Ticket Q&A for Community Report Handling: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
This category processes individual user-submitted report content. Core data comes from the community report system, pending review content detail pages, user historical report records, and official review rule documents. Daily processed documents include individual report tickets, disposal progress records, user appeal forms, and standardized notification templates.
Data updates run in real time or via daily synchronization. Each record includes a unique report identifier, associated content ID, report type tag, submitting user information, and disposal status fields. No additional statistical aggregation fields are included.

## Constraints Imposed on Knowledge Base Retrieval and Recall
Individual report ticket data volume is small. Associated content may include multi-format materials. Real-time updated review rules must be synchronized to the knowledge base vector library. This prevents recalling outdated judgment criteria.
Retrieval needs differ sharply across report types. Corresponding knowledge base sets must be matched accurately using ticket fields. This avoids recalling irrelevant violation judgment standards.
Intercepting violation evidence and verifying its validity takes the most time in this scenario. Retrieval prioritizes matching core fields. This reduces invalid recall results and improves overall processing efficiency.

## Configuration Settings
This configuration applies to FastGPT v4.17.0 and later versions. The following are retrieval and recall configuration items tailored for the community report handling scenario:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Matches the accuracy of report types and review rules. Avoids too low a threshold that recalls irrelevant rules, or too high a threshold that misses valid judgment criteria |
| `limit` | `Top 8 entries` | Associated information for individual report tickets is limited. Too many recall results exceed the model context window limit |
| `searchMode` | `Keyword + vector hybrid retrieval` | Balances text keyword matching for report content and semantic matching for review rules |
| `usingReRank` | `Enabled` | Reorders recall results by relevance to improve the accuracy of violation judgments |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Generates extended query terms based on the original report question. This covers synonyms and scenario-specific phrasing |
| `collectionIds` | `Bind corresponding knowledge base sets by report type` | Only recalls review rules and disposal templates associated with the current report type. This reduces invalid retrieval |

## Three Common Configuration Mistakes
- Extra spaces between numbers and text in retrieval results: Undisplayed spaces added during input appear between numbers and adjacent text in recalled review rules or ticket text from the knowledge base. Troubleshooting step: Check if hidden format spaces are cleaned from chunked knowledge base text.
- Failure to recall content from specified knowledge bases: Expected review rules or disposal templates are not returned after submitting a report ticket. Troubleshooting step: Confirm the `collectionIds` parameter is bound to the correct knowledge base set ID.
- Retrieval result count exceeds expectations: Returned recall results exceed the configured `limit` value. Troubleshooting step: Confirm the `limit` parameter is locked to the configured value in the retrieval node.

## How to Verify Proper Configuration
- Server environment variables are checked. Confirm `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service, for example http://aiproxy:3000; do not append paths such as /v1 or /chat/completions) and `AIPROXY_API_TOKEN` (AI Proxy administrator token, consistent with the AI Proxy server configuration and not empty) are set correctly. No empty values or incorrect formats are permitted.
- A test report ticket is submitted. The relevance and count of returned retrieval results are checked against the configured `similarity` and `limit` requirements.
- Knowledge base vector update logs are viewed. Confirm the knowledge base sets associated with the report type have completed real-time synchronization.
- The extended query function is tested. Confirm retrieval results cover synonyms and scenario-specific phrasing from the original report question.

The values provided are common starting points. They should be evaluated against the specific deployment samples in use.
