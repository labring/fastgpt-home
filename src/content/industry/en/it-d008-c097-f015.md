# Operations on-call and internal ticket question answering for community events and developer relations: Knowledge base retrieval and recall

## What this category of data looks like
This category of data primarily comes from community forums, registration systems, social media, and project roadmaps. Daily documents include event plans, speaking scripts, registration lists, and event post-mortems. Event plans contain fields for event theme, execution process, and budget. Registration lists include fields for applicant information and registration time. Speaking scripts include fields for agenda key points and interactive session design. Data updates are usually triggered monthly or at individual event milestones, with no fixed high-frequency update rhythm. The length of individual documents varies widely, ranging from a few hundred characters of event notifications to several thousand characters of event post-mortem reports.

## Constraints on knowledge base retrieval and recall
Significant differences exist in data formats across sources. Unstructured question-and-answer content from community forums, structured form data from registration systems, and short text content from social media require the retrieval link to support mixed recall of multi-format data. Data updates have no fixed high-frequency rhythm, with concentrated updates only during event preparation or post-mortem phases. This requires support for on-demand incremental recall to avoid excessive computing resource usage. The span of individual document lengths is large, from short notifications to long post-mortem reports. This requires adapting text chunking rules for different lengths to ensure semantic integrity of recalled segments. Internal tickets mostly focus on event execution issues, requiring association between event documents and operation and maintenance logs. This requires the retrieval link to support cross-data source associated recall.

## Recommended configuration parameters
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.85 | Aligns with the semantic similarity distribution of community event documents, filters low-relevance forum casual chat content |
| `limit` | Top 8–12 results | Balances recall coverage and context length, adapts to the short question scenario of internal tickets |
| `searchMode` | hybrid | Combines keyword and semantic retrieval to cover retrieval needs for structured registration data and unstructured event documents |
| `usingReRank` | Enabled | Improves ranking accuracy of high-relevance recall results, adapts to semantic matching for long documents such as event post-mortems |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands relevant keywords for questions, covers synonyms for event themes and industry terminology |
| `collectionIds` | Configured by event theme group | Targets recall of exclusive documents for corresponding events, avoids interference from irrelevant data in retrieval results |

## Three common misconfiguration issues
- Rate limit errors occur during vectorization. This happens when the number of vectorization threads is not limited, or vectorization tasks are not batched according to document update frequency, leading to concurrent requests exceeding interface quotas.
- Knowledge base retrieval takes too long. This happens when `searchMode` is not set to hybrid retrieval, or the number of recalled entries is set too high, leading to a large number of low-relevance documents participating in sorting calculations.
- Workflow call errors prompt that the model was not triggered. This happens when the knowledge base collection for the corresponding event is not associated, or the `collectionIds` configuration is empty, leading to the retrieval link being unable to obtain valid context.

## How to confirm configuration is successful
- Check vectorization task logs in FastGPT v4.17.0 to confirm thread count limits are active, with no consecutive rate limit errors.
- Submit an internal ticket question related to an event, and verify that the retrieval results include the corresponding event plan or post-mortem document.
- Test recall results for different questions to confirm that the `similarity` threshold filters out low-relevance casual chat content.
- Check that the `collectionIds` configured in the knowledge base match the current event theme, to ensure targeted recall is active.

The values given are common starting points and should be measured against the reader's own samples.
