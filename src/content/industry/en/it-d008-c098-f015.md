# Operations On-Call and Internal Ticket Q&A for Community Contributor Governance: Knowledge Base Retrieval and Recall

## What this category of data looks like
This category of data centers on the personnel and rule system for community contributor governance. Daily documents include contribution guidelines, code of conduct, maintainer lists, and governance meeting minutes. Data sources include code repository commit records, community forum discussions, contribution statistics, and offline or online governance meeting notes. Update frequency is monthly or quarterly. Data fields include role permission descriptions, promotion rules, contributor qualification records, and meeting resolution content. Most content is text-based descriptions, with no unified numerical units.

## What constraints do these characteristics impose on the "knowledge base retrieval and recall" link
First, most data is unstructured text with low update frequency, so high-frequency incremental recall is not required, which can reduce the configuration overhead of real-time synchronization. Second, the data contains sensitive content such as role permissions and promotion rules. Access scope must be strictly limited during retrieval to avoid unauthorized content being recalled. Third, data sources are scattered across different platforms such as code repositories and forums. The collection ID of the corresponding dataset must be specified during recall to ensure that the retrieval scope covers all governance-related documents. In addition, the length of individual documents varies greatly, and meeting minutes may be long. The total length of recall results must be reasonably controlled to avoid exceeding the model context window, adapting to the retrieval logic of FastGPT v4.17.0.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Match the text features of community governance documents, avoid recalling irrelevant business ticket content |
| `limit` | Top 8 entries | Cover the total volume of governance documents updated monthly, avoid excessive results exceeding context limits |
| `searchMode` | hybrid | Combine keyword and semantic retrieval, adapt to different types of governance documents such as contribution guidelines and meeting minutes, compatible with the hybrid retrieval logic of FastGPT v4.17.0 |
| `usingReRank` | Enabled | Perform secondary ranking on recall results, improve the ranking position of high-priority content such as promotion rules and permission descriptions |
| `datasetSearchUsingExtensionQuery` | Disabled | Governance documents have low update frequency, no need to extend query terms additionally, avoid introducing irrelevant content |
| `collectionIds` | Fill in according to the community governance exclusive collection | Limit the retrieval scope to only governance-related datasets such as contribution guidelines and maintainer lists, avoid recalling other business data |

## Three common mistakes
- Retrieval returns the error `invalid configuration parameter name "hnsw.max_scan_tuples"`: Non-standard configuration parameters not in the official specified list are used incorrectly, and FastGPT configuration specifications are not followed.
- Recall results include non-governance business ticket content: The `collectionIds` configuration to limit the retrieval scope is not set, causing the retrieval to cover irrelevant business datasets.
- An empty knowledge base prompt appears during conversations after an upgrade: The collection ID configuration for governance documents was not synchronized during migration, or the verification process for the retrieval scope was not re-triggered.

## How to confirm the configuration is correct
- View the retrieval configuration page, confirm that all used configuration items are from the official specified list, with no additional custom parameters.
- Initiate a test retrieval, enter a question related to contributor promotion, check that the recall results only include governance-related documents.
- Trigger a knowledge base synchronization task, confirm that updated governance documents appear normally in retrieval results.
- Check the context window settings, ensure that the total content length of a single recall meets the model's limit requirements.

The values provided are common starting points and should be measured against the reader's own samples.
