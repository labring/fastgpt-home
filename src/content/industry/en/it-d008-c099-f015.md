# Mobile Development Operations On-Call and Internal Work Order Q&A: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
Mobile development operations and work order data mainly comes from code repositories, app store backends, crash monitoring platforms, and device coverage data. The update frequency is daily or per version release cycle. Daily used documents include client version release notes, adaptation lists, crash analysis reports, and app store review materials.
Client version release notes contain fields such as version number and compatible device range. Adaptation lists mark system versions and permission configuration items. Crash analysis reports record abnormal data by device and system version. App store review materials include review requirements and version description fields.

## Constraints Imposed on Knowledge Base Retrieval and Recall by These Characteristics
Dispersed data sources require cross-system associated retrieval, with priority given to matching core fields such as device model and system version.
High update frequency requires retrieval to support real-time or near-real-time document update synchronization.
Diverse document structures include both structured list-style documents and unstructured analysis reports, so retrieval must support content recall across different formats.
Work order issues mostly focus on specific scenarios such as permission troubleshooting, device adaptation, and review rules. Retrieval must avoid interference from irrelevant category documents.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Mobile development documents mostly contain technical details. This range balances retrieval precision and coverage, and is compatible with the semantic matching logic of FastGPT v4.17.0 |
| `limit` | Top 8 entries | Mobile development work orders usually focus on single scenarios. Too many results will interfere with engineers' ability to quickly locate issues |
| `searchMode` | Semantic retrieval | Development issues often involve vague technical troubleshooting. Semantic matching is better than keyword matching for matching implicit technical scenarios |
| `usingReRank` | Enabled | Documents related to multi-device adaptation often have similar similarity scores. Reranking can improve the sorting priority of key content |
| `datasetSearchUsingExtensionQuery` | Enabled | Development questions often include abbreviations or industry terminology. Extended queries can cover more relevant documents |
| `collectionIds` | Bind exclusive knowledge base collections for mobile development | Isolate data from other categories to avoid interference from irrelevant content in retrieval results |

## Three Common Misconfigurations
- Symptom: Knowledge base retrieval is triggered occasionally but not consistently. Cause: Global retrieval configuration is not permanently enabled, or `datasetSearchUsingExtensionQuery` is not enabled, causing some inputs to not trigger the extended retrieval logic.
- Symptom: Retrieval latency increases significantly after multiple rounds of conversation in the same window, but returns to normal in a new window. Cause: The context window length is not limited. Cumulative historical conversations occupy retrieval resources, causing the actual effective range of the `limit` parameter to be compressed.
- Symptom: Hybrid retrieval performs worse than semantic retrieval. Cause: `searchMode` is not adjusted for mobile development technical documents. Keyword weighting in hybrid retrieval will interfere with the precision of semantic matching.

## How to Verify Proper Configuration
- Initiate a query containing device adaptation keywords, and check whether the returned results include core fields of the adaptation list document.
- Initiate 3 consecutive similar queries, and observe whether retrieval latency fluctuations meet expectations.
- Switch `searchMode` to hybrid retrieval, compare the precision of returned results, and confirm that semantic retrieval is more suitable for the current scenario.
- Check the `collectionIds` configuration, and confirm that non-mobile development knowledge base collections are not included.

The values provided are common starting points and should be measured against the reader's own samples.
