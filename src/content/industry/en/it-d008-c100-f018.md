# Operations On-Duty and Internal Work Order Q&A for Cybersecurity Rating Protection Assessment Consulting: Reranking and Hybrid Retrieval

## What Data for This Category Looks Like
Data for this category primarily comes from project deliverables and process records of cybersecurity rating protection assessment services. Core daily documents include four types of core documents: classification reports, gap analysis reports, rectification plans, and assessment reports. Data sources include scan results exported from assessment tools, on-site interview records, asset system inventories, and security device operation logs. Each project’s data is updated once per project or per year. Core fields include control item number, gap description, rectification measures, verification evidence, and other related items. There is no unified fixed unit; values adjust based on specific project requirements.

## What Constraints Do These Characteristics Impose on Reranking and Hybrid Retrieval
Document types are diverse and structures are inconsistent. Reranking models must adapt to semantic associations across different fields, to avoid mismatches between control item numbers and rectification descriptions. Data is updated independently per project. Retrieval scope must be limited to the current project’s dataset, to avoid irrelevant cross-project content interfering with retrieval results. Core business processes involve control item gap verification. Hybrid retrieval must combine semantic similarity and structured field matching, to ensure retrieval results accurately correspond to cybersecurity rating protection requirements. Data volume fluctuates with project scale. Retrieval upper limits must be adjusted based on total data volume for a single project, to avoid excessive resource usage.

## Three Common Misconfigurations
- Calling a private reranking model returns a 401 unauthorized error. Symptoms include authentication failure prompts in the interface, and logs showing status code 401. Causes include failing to configure the correct access key for the reranking model in FastGPT, or failing to open access permissions for the deployed container to the network where FastGPT runs.
- Failing to enable the reranking function. Retrieval results cannot filter low-match content, and the number of results exceeds expectations. Symptoms include retrieval results containing large numbers of document fragments unrelated to control items. Causes include confusing the basic similarity of vector retrieval with precise relevance after reranking, and failing to enable the secondary screening step.
- Setting the single retrieval upper limit too large, causing context to exceed model input limits. Symptoms include model prompts that the context is too long when generating responses. Causes include failing to adjust the retrieval result upper limit based on average length of documents per project, and blindly expanding the retrieval scope.
