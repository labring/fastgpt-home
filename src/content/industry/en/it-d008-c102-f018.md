# Operations On-Duty and Internal Ticket Q&A for Defect Management and Regression Testing: Reranking and Hybrid Retrieval

## What Data for This Category Looks Like
This category’s data originates from defect management systems, test reports, code commit records, and user feedback. Daily generated documents include defect tickets, regression checklists, repair verification records, and defect statistical reports. Defect tickets contain fields including defect ID, priority, reproduction steps, associated code commits, and current status. Regression checklists include test case ID, associated defect number, and verification results. Data updates occur daily or per version release cycle, and accumulate gradually through R&D iterations.

## What Constraints These Characteristics Impose on Reranking and Hybrid Retrieval
Data sources for this category are scattered and update frequently. Hybrid retrieval must support recall and integration across cross-system data sources. Fields such as defect ticket priority and associated code commits are core business identifiers. The reranking step must prioritize matching these high-weight fields. This prevents high-priority defects from being overshadowed by low-correlation entries. The association between regression checklists and defect tickets is clearly defined. Retrieval must accurately link corresponding entries to ensure correct matching between regression test cases and their associated defects. Data volume grows gradually with each version iteration. The number of recalled entries per single request must be limited to avoid excessive retrieval load that slows internal ticket Q&A response times. Some fields, such as reproduction steps, contain unstructured text. Hybrid retrieval multi-modal matching logic must be adapted to improve recall accuracy.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Reranking Toggle | Enabled | This category’s data includes unstructured reproduction steps and structured business fields. Reranking improves recall accuracy for high-priority defects |
| Single Recall Limit | Top 10 entries | The data volume per version for this category is manageable. Limiting recalled entries optimizes retrieval response speed to meet real-time Q&A needs for operations on-duty |
| Retrieval Mode | Hybrid Retrieval | Supports structured field association and unstructured text matching, adapting to cross-document association requirements for defect tickets and regression checklists |
| Similarity Threshold | 0.75–0.85 | Calibrated via actual testing, balances high-priority defect recall rate and low-correlation entry filtering performance |
| Reranking Model Request Timeout | 30 seconds | Adapts to response delays of locally deployed or cloud-based reranking models, preventing blocking in internal ticket Q&A workflows |

## Three Common Configuration Errors
- Symptom: The reranking model returns empty content, or no reranked results appear in internal ticket Q&A. Cause: The custom request address for the reranking model was not configured correctly, or the timeout period was set too short, preventing the model response from completing.
- Symptom: Low-priority defects make up an overly large share of retrieval results, and high-priority defects are not displayed first. Cause: The reranking function was not enabled, or the similarity threshold was set unreasonably, failing to filter low-correlation entries.
- Symptom: Hybrid retrieval cannot associate defect tickets with regression checklist entries. Cause: The retrieval mode was not set to hybrid retrieval mode, and only plain text retrieval was used, without matching structured association fields.

## How to Confirm the Configuration Is Complete
This configuration process is compatible with FastGPT v4.17.0.
- Access the knowledge base configuration page, check the reranking toggle status, and confirm it is enabled.
- Submit a test ticket, enter defect-related keywords, review the sorting logic of retrieval results, and confirm high-priority entries are displayed first.
- Review the reranking model request logs, confirm the request address and timeout time match the expected configuration, and verify there are no connection timeout or empty response records.
- Switch the retrieval mode to plain text mode, compare differences in retrieval results, and confirm hybrid retrieval mode is active.
