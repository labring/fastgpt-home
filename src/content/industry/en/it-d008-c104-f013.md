# Landing Page Conversion Optimization On-Call Operations and Internal Ticket Q&A: Permission and Data Isolation

## What This Category’s Data Looks Like
Business data for landing page conversion optimization primarily comes from landing page access logs, heatmaps, form data, and advertising source parameters. Update frequency is weekly or within a single campaign cycle. Daily associated documents include landing page plans, event tracking requirements, AB test reports, and form field lists. Data fields include page path, dwell time, form submission status, advertising channel identifiers, and more. Data is aggregated by campaign dimension, and the volume of data for a single campaign varies with campaign scale.

## Constraints Imposed on Permission and Data Isolation
Since data is aggregated in association with advertising campaigns and business teams, individual optimizers can only view landing page data for the channels they manage. In on-call operations scenarios, staff need to quickly locate form blocking issues for a single campaign, so permission boundaries must be divided by team and campaign dimensions. The binding between documents and data is tight; unauthorized access may lead to campaign plan leaks or disordered attribution data. Data updated weekly or per campaign cycle requires permission configurations to take effect alongside campaign adjustments, without repeated reconfiguration. Form data and user behavior logs involve sensitive business information, so viewing and export permissions for unauthorized personnel must be strictly restricted.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `teamId` | Exclusive identifier bound to the current landing page campaign | Matches the data aggregation characteristic of landing pages by campaign, preventing cross-campaign data leakage |
| `tmbId` | Limit member range for the current team | Aligns with business divisions for growth products and advertising optimizers, preventing cross-team access |
| Single campaign data storage quota | 1000 MB per campaign | Adapts to log and form data volume for a single campaign, avoiding cross-campaign data accumulation |
| Context call limit | Top 3 associated log data entries | Controls returned data scope, meeting quick query needs during on-call operations scenarios |
| Permission activation latency | Synchronized within 600 seconds | Adapts to response rhythm for temporary campaign adjustments, meeting real-time requirements for operations scenarios |

## Three Common Configuration Mistakes
- Binding the incorrect campaign ID when configuring `teamId`: A permission error pop-up appears during test calls. Forcing dismissal allows execution but returns cross-campaign form data. The root cause is failure to bind the exclusive identifier by campaign dimension, resulting in permission scope not matching business data attribution.
- Unable to locate the team invitation entry after local deployment, making member permission range configuration impossible. The root cause is failure to enable the default configuration for the team permission module in FastGPT v4.17.0, so the basic permission isolation function does not load.
- Not configuring concurrency limits for members associated with `tmbId`, leading to unauthorized team members accessing data simultaneously, exceeding business-planned collaboration limits. The root cause is failure to enable concurrency limit configuration for member permissions; the default setting does not restrict concurrent callers.

## How to Confirm Successful Configuration
- Log in to the permission management panel corresponding to `teamId`, confirm only current team and associated project members can view configuration items.
- Initiate a test call, verify returned data only includes landing page logs, form data, and associated documents for the current campaign.
- Use an unauthorized account to attempt access, confirm cross-campaign event tracking requirements and AB test reports cannot be viewed.
- Verify the conversation export function, confirm only analysis data associated with the current campaign can be exported, with no access to business information from other campaigns.
