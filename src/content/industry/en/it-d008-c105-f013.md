# Operations On-Duty and Internal Ticket Q&A for License Compliance and Copyright Notices: Permission and Data Isolation

## What Data This Category Includes
This category’s data comes primarily from code repositories, dependency lists, license texts, and contribution records. Daily documents include LICENSE files, NOTICE files, dependency license lists, and copyright statements.
Data is updated per project version or dependency change frequency. Fields include license type, copyright holder, dependency package name, version number, and update time.
Compliance data for different projects is independent, with no default cross-project associations.

## Constraints Imposed by These Characteristics on Permission and Data Isolation
Decentralized, frequently updated data sources require permission configurations to align with data ownership dimensions, to prevent cross-project data leaks.
Compliance documents for different projects have no default associations. Data must be bound via team dimensions to stop unauthorized personnel from accessing another project’s license and copyright information.
The high update frequency means permission configurations must support real-time or scheduled synchronization, to ensure permission rules for compliance data apply promptly.
Errors can lead to license violations and blocked commercial use. Access to edit or view sensitive compliance data must be strictly limited.

## Configuration Recommendations

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `teamId` | Bind the unique identifier of the team that owns the project | Match the owning team of compliance data, compatible with FastGPT v4.17.0 team permission logic |
| `tmbId` | Associate the team membership identifier for a member | Verify if a member has permission to operate compliance data for the corresponding project |
| Data synchronization interval | Every 12 hours | Match the update frequency of dependency changes and version releases |
| Maximum number of dependencies per synchronization | First 500 entries | Control API request load to avoid synchronization timeouts |
| Maximum storage limit for compliance data per project | 1000 MB | Limit storage size of compliance documents per project to avoid excessive resource usage |
| Sensitive data visibility scope | Only visible to team maintainers | Prevent unauthorized personnel from accessing copyright statements and license compatibility information |

## Three Common Misconfigurations
- Symptom: Calls to interfaces linked to license data return no relevant content. Cause: The data owning team was not bound via `teamId`, and non-project-specific dependency lists and copyright statements were not filtered during cross-team requests.
- Symptom: Team maintainer accounts cannot edit NOTICE files. Cause: The sensitive data visibility scope was not set to allow only maintainer access, and full team edit permissions were mistakenly enabled.
- Symptom: Unauthorized members can view license texts from other projects. Cause: The maximum number of dependencies per synchronization was not configured, and cross-project data was not filtered and displayed by team dimensions.

## How to Verify Correct Configuration
- Log in with a non-team maintainer account, attempt to access the compliance documents page, and confirm that access to LICENSE and NOTICE files for the corresponding project is denied.
- Submit a cross-team compliance data query request, and confirm returned results only include the dependency license list and copyright statements for the current project.
- Modify the project’s license data, trigger a manual synchronization, and confirm the data updates within the configured synchronization cycle.
- Access the team management page, and confirm only maintainer accounts can configure permission rules and view member usage records.
