# License Compliance and Copyright Statement for Operations On-Call and Internal Ticket Q&A: Deployment and Upgrade

## What This Category of Data Includes
This category of data originates from open source project code repositories, third-party dependency lists, official license texts, and contributor records. Core documents include the LICENSE file in the project root directory, the NOTICE copyright statement file, an auto-generated dependency license list, and incrementally updated copyright ownership confirmation records.
Data update cadence syncs with project version releases and third-party dependency changes. Full verification and updates are required for each version iteration or dependency introduction.
Data fields include license type, copyright owner, dependency package name, and distribution restriction terms. No unified fixed units apply; information is recorded per document specifications.

## Constraints on Deployment and Upgrade
The characteristics of this category of data impose clear constraints on the deployment and upgrade phase.
Data sources are scattered across code repositories and third-party dependency lists. During deployment, configure an integration path that automatically pulls the latest dependency lists and license files to ensure real-time synchronization of compliant data.
Data updates trigger alongside version iterations and dependency changes. The upgrade phase must automatically initiate the license compliance check process to avoid missing copyright statements and license information for new dependencies.
Multiple structured documents require a unified storage path to allow the operations ticket system to quickly retrieve corresponding files. Configure document parsing rule matching fields to prevent verification failures caused by differences in field formats.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:27017/fastgpt?authSource=admin` | Official recommended connection format for storing license verification records and dependency lists |
| `REDIS_URL` | `redis://:password@host:6379/0` | Caches frequently accessed license document metadata; default port 6379 is an industry-standard configuration |
| `STORAGE_S3_ENDPOINT` | Set based on actual testing | Object storage endpoint for storing license documents and dependency lists; must match the cloud service provider configuration of the deployment environment |
| `FE_DOMAIN` | `https://your-domain.com` | Specifies the access domain name of the operations ticket system, used to generate sharing links for compliance documents |
| `DB_MAX_LINK` | `50–100 connections` | Limits the maximum number of connections in the database connection pool to avoid resource exhaustion caused by concurrent compliance checks |
| `FILE_TOKEN_KEY` | Random 32-character string | Used to encrypt sharing tokens for compliance documents, ensuring access security for sensitive copyright information |

## Three Common Configuration Mistakes
- Symptom: After restarting the server, sharing links for license compliance documents cannot be accessed, with a 403 status code returned. Cause: Persistent storage for `FILE_TOKEN_KEY` is not configured. The token key resets after restart, causing sharing links to expire.
- Symptom: After upgrading to FastGPT v4.17.0 or later, the automatic dependency license list generation function cannot be triggered. Cause: The trigger path for dependency scanning is not correctly specified in the deployment configuration. The legacy local configuration file no longer takes effect.
- Symptom: The ticket system returns empty results when searching for license documents. Cause: The correct storage path for `STORAGE_S3_ENDPOINT` is not configured, causing compliance documents to not be properly mounted or uploaded.

## How to Verify Proper Configuration
- Run the dependency scanning command to check if third-party dependency lists can be pulled normally and a license verification report can be generated. Confirm that the report's generation path matches the configured storage path.
- Manually generate a sharing link for a compliance document. Access the link to confirm that the document content loads normally and the token verification logic functions correctly.
- Check the database connection logs to confirm that the number of connections in the database connection pool does not exceed the configured threshold, and that no connection timeout errors occur.
- Restart the deployment container to confirm that services related to license compliance do not display startup failure errors, and that all configuration parameters load normally.
