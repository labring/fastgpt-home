# Operations Duty and Internal Ticket Q&A for License Compliance and Copyright Notices: Reranking and Hybrid Retrieval

## What this category of data looks like
This category of data primarily originates from code repositories, dependency lists, license texts, and contribution records. Daily produced documents include LICENSE files, NOTICE files, dependency license lists, and copyright notices. Data updates trigger with each version release or dependency change. Individual documents contain fields such as license type, copyright ownership, authorization terms, and dependency association information. There is no unified fixed unit, and field content varies slightly based on document type.

## What constraints do these characteristics impose on the reranking and hybrid retrieval workflow
The multi-source heterogeneous nature of this category of data requires hybrid retrieval to cover license texts within code repositories, external dependency lists, and historical contribution records simultaneously. Data update frequency is inconsistent, so incremental retrieval must support adaptation to change rhythms. Individual documents have large field differences, so the reranking model must adapt to semantic weights of different fields to avoid retrieval result deviations caused by field mismatches. Compliance data has extremely high accuracy requirements, so hybrid retrieval must prioritize recalling high-confidence official license texts, rely on accurate matching logic, and reduce false recall risks.

## Three common mistakes
- Phenomenon: The order of knowledge base retrieval results does not change, and no reranking effect is visible. Cause: The rerank function toggle is not enabled, or the rerank model is not correctly associated with the current application.
- Phenomenon: The rerank model configuration option cannot be selected when creating an application. Cause: Rerank model parameters are not configured in config.js as required, or the configuration parameters have format errors.
- Phenomenon: The rerank model call returns a timeout or connection failure. Cause: A valid model access key is not configured, or the locally deployed rerank model is not started normally.

## How to confirm the configuration is complete
- The application configuration page of FastGPT v4.17.0 is accessed, and the rerank toggle is confirmed to be enabled.
- A test query containing license-related keywords is submitted, and the sorting logic of the returned retrieval results is checked against expectations, with official license texts displayed first.
- The config.js configuration file is reviewed, and rerank model parameters are confirmed to be correctly filled with valid formatting.
- Application running logs are inspected, and rerank model call requests are confirmed to have been normally initiated with no error messages.
