# Operations on-duty and internal work order Q&A for speech annotation and transcription: Deployment and upgrade

## What this category of data looks like
Data for this category primarily comes from audio files, annotation platforms, specialized vocabulary lists, and spot-check samples. Updates occur daily or in sync with annotation batches. Daily produced documents include transcription specifications, audio inventory lists, quality inspection reports, and speaker annotation tables. Data fields cover audio duration, annotator ID, transcribed text, confidence tags, and quality inspection results. Compared to text annotation projects, speech annotation and transcription first require converting audio content into structured text. Core time-consuming steps focus on noise segment identification, speaker differentiation, and specialized vocabulary proofreading.

## What constraints do these characteristics impose on the deployment and upgrade phase
The data characteristics of this category impose multiple constraints on the deployment and upgrade phase. Audio and annotation data volume updates frequently with annotation batches. Configure high-throughput storage and concurrent processing capabilities to avoid data write blocking. Daily documents include multiple types of structured tables. During deployment, adapt parsing and storage formats for structured data to ensure accurate field mapping. Specialized vocabulary proofreading relies on specialized vocabulary lists. During upgrades, synchronize updates to vocabulary list loading logic to prevent recognition training bias. Noise segment identification and speaker differentiation require calling audio processing models. During deployment, reserve sufficient memory and computing resources to avoid operational lag.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `80–120` | Adapts to daily high-frequency annotation data write and query requirements, avoids exhausting database connections |
| `REDIS_URL` | `Local cluster deployment, single node memory no less than 16 GB` | Caches audio processing results, annotation progress, and internal work order status to reduce duplicate computation overhead |
| `STORAGE_S3_ENDPOINT` | `Object storage endpoint supporting large file multipart upload` | Hosts large-volume data such as audio files and quality inspection reports, adapts to batch annotation read and write requirements |
| `ROOT_KEY` | `32-bit randomly generated security key` | Secures access permissions for internal operation and maintenance interfaces and configuration pages, prevents unauthorized operations |
| `PG_URL` | `Configure connection timeout threshold to 600 seconds` | Handles long-duration audio transcription parsing and structured data queries, avoids connection interruptions |

## Three common mistakes
- Scenario: When deploying related components via Docker, the service fails to load the specialized vocabulary list after startup. Cause: Failed to correctly configure data loading-related parameters under the environment field in docker-compose.yml, causing the service to fail to read local vocabulary list files.
- Scenario: After deploying on an 8-core 32GB machine, workflow operation response speed is slow. Cause: Failed to adjust `DB_MAX_LINK` and Redis memory configurations, leading to insufficient database connection pools or low cache hit rates, slowing down data reading speed.
- Scenario: After modifying FastGPT configurations, access to port 3005 throws abnormal errors, while access to port 3000 works normally. Cause: Failed to correctly distinguish configurations for internal operation and maintenance interfaces and external service interfaces, causing the service bound to port 3005 to fail to load correct private deployment parameters.

## How to confirm configurations are properly set
For FastGPT v4.17.0, the following verification actions can be completed:
- Review database connection logs to confirm connection counts do not continuously reach the configured limit. Adjust the value of `DB_MAX_LINK` to adapt to current business volume.
- Upload a single audio file and trigger the transcription process, then check if cache results return within a reasonable time frame. Adjust Redis memory configurations to optimize cache hit rates.
- Access the internal operation and maintenance interface, complete authentication using `ROOT_KEY`, then confirm that specialized vocabulary lists and configuration parameters can be loaded normally.
- Review object storage access logs to confirm audio files and documents can be uploaded and read normally. Adjust the configuration of `STORAGE_S3_ENDPOINT` to adapt to the storage service.

The values provided are common starting points and should be measured against the reader's own samples.
