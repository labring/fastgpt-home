# Operations Duty and Internal Ticket Q&A for Identity Account and Permission Management: Knowledge Base Retrieval and Recall

## What this category of data looks like
This category of data comes from enterprise IAM systems, HR systems, business system logs, and approval systems. Updates occur either on a daily schedule or when triggered by personnel changes. Daily operation and maintenance documents include standardized account application forms, permission matrix tables, offboarding account recovery forms, and compliance audit reports. Document fields include account ID, permission scope, effective time, approval status, associated business systems, and more. The length of individual documents varies widely, ranging from approval sheets with dozens of lines to permission matrix tables with hundreds of lines.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link?
Decentralized data sources create significant format differences across different documents. Retrieval must support mixed input of structured tables and unstructured text. Update frequencies are flexible and triggers have no fixed cycle, so support for switching between incremental recall and full reindexing is required. Documents contain sensitive permission fields, so the visibility of retrieval results must be strictly controlled to avoid unauthorized access risks. The length of individual documents varies greatly, so chunking rules of different lengths must be adapted to prevent long text truncation from losing key permission information. Additionally, the operations duty scenario requires fast retrieval response times, so a balance must be struck between the number of recalled results and query latency.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | Adapt to the semantic matching accuracy of permission-related documents, avoid mixing low-relevance results while retaining enough recall candidates |
| `limit` | Top 10 entries | Balance information density and retrieval speed for operations duty scenarios, prevent excessive results from delaying quick location of needed information by duty personnel |
| `searchMode` | Semantic recall | Adapt to the retrieval needs of semi-structured and unstructured documents such as permission matrices and audit reports, matching both keywords and semantic associations |
| `usingReRank` | Enabled | Perform secondary sorting on recalled results, prioritize documents containing the latest permission changes to meet the timeliness requirements of operations scenarios |
| `datasetSearchUsingExtensionQuery` | Enabled | Generate extended query terms based on the original question, cover retrieval of professional terms such as account ID and permission scope, and improve recall rate |
| `collectionIds` | Bind dedicated knowledge base collections for IAM and approval systems | Limit the retrieval scope, avoid interference from irrelevant documents, and ensure only content related to identity account and permission management is returned |

## Three common configuration errors
- No retrieval result updates after performing a full index rebuild. The cause is failing to correctly specify the `collectionIds` parameter to bind the target knowledge base collection, so the rebuild operation does not apply to the dedicated permission management dataset.
- Homogeneous permission matrix documents in retrieval results are sorted randomly. The cause is not enabling `usingReRank`, so no weight adjustment is performed based on document update time or associated personnel change time.
- Retrieval results include unauthorized sensitive permission fields. The cause is not configuring permission filtering rules for retrieval results, directly returning the full content of the original documents.

## How to confirm the configuration is correct
- Perform a test retrieval by entering "offboarding account recovery process", check whether the returned results only include documents related to identity account and permission management, with no irrelevant content from other business systems.
- Upload a new permission matrix document, wait 1 hour, then perform a retrieval to confirm the new document can be recalled normally.
- Check the retrieval logs in FastGPT v4.17.0, confirm that the `usingReRank` and `datasetSearchUsingExtensionQuery` parameters are active with no error records.
- Adjust the `similarity` parameter to 0.8, perform a retrieval for "account unauthorized access investigation", check whether the relevance of the returned results meets expectations.

The values listed above are common starting points, and should be evaluated against your own specific samples.
