# Identity Account and Permission Management for Operations Duty and Internal Ticket Q&A: Re-Ranking and Hybrid Retrieval

## What this category of data looks like
This category of data originates from IAM systems, HR systems, business system logs, and approval systems. Its update frequency is daily, or triggered by personnel changes.
Daily operations and ticket-related documents include account application forms, permission matrices, offboarding recovery forms, and audit reports. Account application forms contain fields for applicant identification, applied permission scope, and approval status. Permission matrices contain fields for system name, bound account, and permission level. Offboarding recovery forms contain fields for offboarding time and list of recovered accounts. Audit reports contain fields for permission compliance items and abnormal permission records.
Documents cover two categories: structured forms and unstructured reports. All fields are directly related to accounts, permissions, and personnel changes.

## What constraints these characteristics impose on re-ranking and hybrid retrieval
Multi-source heterogeneous data sources require hybrid retrieval to support both keyword matching and semantic recall, to cover distinct retrieval needs for structured forms and unstructured reports.
Data update frequency is triggered by personnel changes, so retrieval results must be timely. The re-ranking link must prioritize matching the latest personnel changes and permission change scenarios.
Document fields are highly focused on account and permission-related content. Irrelevant non-permission data must be excluded during retrieval. Thus, the hybrid retrieval recall scope must be limited to IAM-specific data sources. The re-ranking model must also calibrate result priorities based on business scenarios.

## How to configure the settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Identity account and permission management data has strong field correlation. A threshold that is too low will introduce irrelevant business system log entries. A threshold that is too high will miss associated permission application forms and audit reports |
| `limit` | `Top 12–18 entries` | IAM-related documents have short individual content. A sufficient recall volume is needed to cover different ticket scenarios, while avoiding context overload that reduces retrieval efficiency |
| `searchMode` | Hybrid Retrieval | Must support matching both keywords (such as account ID, offboarding time) and semantics (such as permission overrun descriptions) to adapt to multi-source heterogeneous IAM-specific data |
| `usingReRank` | Enabled | Basic vector similarity for multi-source data cannot fully align with business scenario priorities. The re-ranking model can secondarily adjust result order, prioritizing documents directly related to operations duty tickets |

## Three Common Misconfigurations
- Symptom: The re-ranking model test returns a call failure error, and the interface shows model connection abnormality. Cause: The private deployment model interface address and authentication key were not filled in the re-ranking model configuration of FastGPT v4.17.0, interrupting the model call link.
- Symptom: When `usingReRank` is disabled, the relevance field of retrieval results cannot reflect business priorities, and the sorting of permission application forms and audit reports has no clear rules. Cause: Basic retrieval only uses vector similarity calculation, and does not incorporate the business association logic of IAM data, so it cannot distinguish the importance of different document types.
- Symptom: When the hybrid retrieval configuration `similarity` is set to 0.8, the returned results include a large number of non-permission-related system operation logs. Cause: The retrieval data source range is not limited, and recall filtering rules are not adjusted for IAM-specific data, leading to irrelevant logs being recalled.

## How to Confirm the Configuration is Successful
- Retrieve the ticket keyword "offboarding account recovery", and check if offboarding recovery forms and permission matrix documents are returned first in the results.
- Run the same retrieval after disabling `usingReRank`, and compare the sorting differences between the two results to confirm that the re-ranking link has taken effect.
- Check the retrieval log to confirm that `searchMode` is set to hybrid retrieval mode, and that the `similarity` and `limit` configuration parameters have been correctly loaded.
- Simulate submitting a ticket related to permission abnormalities, and verify that the retrieval results include the corresponding audit reports and permission abnormality records.

The values provided are common starting points and should be validated against the target deployment’s own samples.
