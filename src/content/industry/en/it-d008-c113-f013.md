# Operations On-Duty and Internal Ticket Q&A for Integration and Interface Testing: Permission and Data Isolation

## Data profile for this category
Core users of this category are test engineers, test development teams, and interface platform maintenance staff. Daily documents produced and maintained include interface test cases, joint debugging issue tickets, test environment descriptions, and test reports. Data sources include interface management platforms, test environment logs, test databases, and message queues. Data is updated daily or upon each version release. Individual documents contain fields such as interface addresses, parameter lists, test results, and issue localization records. There are no unified fixed units, and values vary based on document type and specific test scenario.

## Constraints on permission and data isolation
Cross-system data from multiple sources creates cross-use risks for test data across different teams. Strict separation of permissions for interface documents, logs, and tickets across test groups is required. High-frequency updates daily or per version demand that permission configurations take effect in real time. Delayed permission updates can lead to data leaks or accidental operations. Joint debugging issue tickets and test reports involve cross-module collaboration. Access must be restricted to only relevant participating personnel. This prevents unrelated teams from accessing undisclosed test progress and interface details. Interface test cases contain sensitive parameters and environment information. Generalized permissions must be avoided to prevent unauthorized access to core test data.

## Configuration guidelines
This configuration guide is based on FastGPT v4.17.0, and is tailored for the operations scenario of integration and interface testing.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Team permission group binding | Bind `teamId` to business test groups | Data sources include team-specific data from interface management platforms, ensuring permissions align one-to-one with business groups |
| Member permission scope | Only view test cases and joint debugging issue tickets belonging to their own team | Daily documents are team-specific test-related content, preventing cross-team data leaks |
| Data isolation scope | Restrict to test data updated daily or per version | Data update frequency is daily or per version, ensuring only valid data from the current cycle is loaded |
| Log access permission | Only open to maintenance personnel of the corresponding test environment | Data sources include test environment logs, which are sensitive operational data |
| Ticket creation permission | Grant corresponding permissions via binding `tmbId` | Internal ticket Q&A must be linked to the business permissions of test teams, ensuring creation permissions are only granted to legitimate members |
| Reference document display limit | Only display the first 3 reference documents belonging to the current team | Avoids irrelevant data interfering with test personnel's issue location, meeting the rapid response needs of operations on-duty |

## Three common configuration errors
- Symptom: Non-team members can still view this team's interface test cases. Cause: The member's `teamId` was not bound to the corresponding test group's permission configuration.
- Symptom: Team members granted write permissions cannot create internal tickets. Cause: The permission scope for ticket creation was not configured for `tmbId`.
- Symptom: Responses only display the bottommost knowledge base document entry. Cause: The reference document display limit was not linked to the current team's test data scope.

## How to verify successful configuration
- Switch to a test account from a different team, and confirm that this team's interface test cases and joint debugging issue tickets cannot be viewed.
- Use a member account granted write permissions, attempt to create an internal ticket, and confirm the operation completes normally.
- Initiate a query related to test issues, and confirm that the returned reference documents only include this team's test reports and joint debugging issue tickets.
- Check the SSO login entry for enterprise edition users, and confirm that only enterprise edition users can use this login method.
