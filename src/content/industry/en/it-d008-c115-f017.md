# IT operations on-duty and internal work order Q&A for project implementation plan management: Deployment and upgrade

## What this category of data consists of
This data is generated across the full project lifecycle. Daily documents include project plans, milestone lists, weekly reports, and risk issue lists. Data sources include contracts, work breakdown structure (WBS), client schedules, and project management systems. Update frequency is weekly or after completing a milestone node. Data fields include task identifier, responsible person, deadline, risk level, budget-related items, and more. Data is stored as structured text and tables, with no unified fixed unit format. Some fields must match the client’s project management specifications.

## What constraints these characteristics impose on deployment and upgrade
Data sources are scattered and rely on external project management systems. During deployment, configure adaptation parameters for cross-system data synchronization to ensure compatibility of field formats from different sources. Update frequencies are uneven and tied to milestone nodes. During upgrade, reserve a time window for incremental synchronization to avoid service interruptions at critical project nodes. Data is linked to core project progress and costs. During deployment, strictly isolate test and production environments to prevent configuration changes from affecting ongoing projects. Daily document formats vary. Support custom field mapping to adapt to different clients’ project management document structures, avoiding data import failures caused by format incompatibility.

## How to configure settings
This page applies to the FastGPT v4.17.0 deployment process.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30 connections` | Adapts to medium data volume for project implementation plan management, prevents database connection exhaustion that causes work order Q&A response failures |
| `MONGODB_URI` | Points to a dedicated MongoDB instance storing project plans and risk lists | Isolates business data from general Q&A data, ensures access permissions for project-sensitive information |
| `REDIS_URL` | Configured as a local cache instance, with cache validity set to `3600 seconds` | Caches frequently queried project progress data, reduces overhead from repeated database reads |
| `FE_DOMAIN` | Fill in the domain name of the enterprise’s internal project management portal | Enables jump linkage between on-duty work orders and the project portal, allowing on-duty personnel to quickly locate issues |
| `STORAGE_S3_ENDPOINT` | Configured as the access address of the enterprise’s internal object storage | Stores project document attachments and work order interaction records, meets compliance storage requirements |
| `ROOT_KEY` | Generate a random key in accordance with enterprise internal permission specifications | Controls system highest permissions, prevents unauthorized access to core project data |

## Three common misconfigurations
- Phenomenon: A newly deployed Docker version cannot insert project data, and the interface displays a database connection timeout prompt. Cause: The `DB_MAX_LINK` parameter is not configured correctly, exhausting the database connection pool and preventing new data write requests from being processed.
- Phenomenon: The custom voice playback function for on-duty work orders cannot connect to chat TTS, and oneAPI returns a 400 status code. Cause: The internal domain name of the TTS service is not bound in the `FE_DOMAIN` configuration, blocking cross-domain requests and preventing service calls from completing.
- Phenomenon: Project weekly report Q&A results are empty after an upgrade. Cause: The permission configuration for `MONGODB_URI` was not updated, preventing the new service instance from accessing the old data storage instance and unable to read historical project data.

## How to confirm the configuration is complete
- Run the database connection test script to verify that the number of connections configured for `DB_MAX_LINK` can be created and reused normally, with no connection timeout errors.
- Submit a test project work order, check that it can correctly associate with the project portal link specified by `FE_DOMAIN`, and that the jump functions without issues.
- Trigger frequent project progress queries, confirm that within the cache validity period set for `REDIS_URL`, query results can be retrieved directly from the cache without repeated database reads.
- Upload a project plan document to the system, verify that the storage service configured via `STORAGE_S3_ENDPOINT` can normally receive and store the file.
