# Operations Duty and Internal Work Order Q&A for Project Document Handover and Archiving: Deployment and Upgrade

## What this category of data looks like
Data for this category primarily comes from project document libraries, configuration lists, meeting minutes, and test reports. The update cadence occurs at the end of a project phase or the completion of the overall project.
Daily included documents include completion documents, configuration manuals, training records, and acceptance certificates. Common data fields include project ID, document version number, archiving time, and seal status.
Data is grouped by individual project. Single document sizes range from tens of KB to several MB. Single project archive package sizes can reach around 1000 MB.

## Constraints on deployment and upgrade workflow
This category of data is scattered and has diverse formats. During deployment, support for batch import of multi-source documents is required. Support for uploading and parsing files in different formats, such as completion documents and acceptance certificates, must be included.
Since data update cadence fluctuates with project phases, the upgrade process must support lossless migration of historical archived data. This prevents loss of document records during version upgrades.
Additionally, data must be associated with project IDs and seal status. During deployment, corresponding permission verification and storage paths must be configured. This ensures traceability of archived data, supporting accurate information for subsequent operations duty and internal work order Q&A.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| ---|---|--- |
| `DB_MAX_LINK` | `100–200 connections` | Single project archive package for this category can reach 1000 MB. Concurrent reading of multiple documents and document queries for internal work orders require sufficient connection count |
| `STORAGE_S3_ENDPOINT` | Fill in the address of the private object storage service provider used for deployment | Completion documents, acceptance certificates and other materials for this category must be stored in a private environment to prevent unauthorized access to archived data |
| `FILE_TOKEN_KEY` | `32-character random string` | Access permissions for archived documents and conversation records must be secured to avoid leakage of sensitive operations documents |
| `REDIS_URL` | `Local Redis service address` | Operations duty and work order Q&A for this category require caching of session records and document indexes. Local deployment reduces access latency |
| `FE_DOMAIN` | Public network domain name or internal IP address of the deployment server | Operations duty personnel must be able to access the conversation page via the specified address to view historical work orders and archived documents |
| `ROOT_KEY` | Administrator key calibrated through actual testing | Only authorized personnel may configure archiving rules and system parameters to ensure data security |

## Three common configuration errors
- After upgrading FastGPT v4.17.0, refreshing the conversation page displays empty conversation records, with only new conversations shown. The root cause is failure to properly migrate the session cache configuration corresponding to `REDIS_URL` during the upgrade, leading to historical session data not being loaded.
- Partial file upload failures occur during batch import of completion documents, with a storage path error prompt. The root cause is incorrect configuration of access permissions for `STORAGE_S3_ENDPOINT`, preventing writing to the archived storage directory.
- After configuring a TTS model, voice broadcast for archived documents cannot be generated normally. The root cause is failure to synchronize `FILE_TOKEN_KEY` to the TTS service configuration items, blocking normal invocation of document audio.

## How to verify correct configuration
- Log in to the system backend, confirm the `DB_MAX_LINK` configuration value matches the preset connection count, and test that no connection timeout errors occur during concurrent import of multiple documents.
- Upload a completion document, verify it can be stored normally in the directory corresponding to the specified `STORAGE_S3_ENDPOINT`, and that it can be accessed via the configured `FE_DOMAIN` address.
- Submit an internal operations work order, confirm session records are saved normally, and that historical conversations are not lost after refreshing the page.
- Test TTS model invocation, confirm voice broadcast content for the corresponding archived documents can be generated.
