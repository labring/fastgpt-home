# Requirements and Design Document Drafting for CDN and Edge Acceleration Configuration: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Daily documents for CDN and edge acceleration configuration include domain access forms, cache rules, refresh and preload records, and fault analysis reports.
Data sources are CDN consoles, DNS resolution records, user access logs, and node monitoring alerts.
Update frequency is daily, or whenever a configuration change is made.
Document fields include filing number, origin server IP address, cache TTL value, task execution status, and more.
Some fields must comply with filing-related regulations.
There are no uniform fixed units. Fields vary significantly across different document types.

## Constraints on Multi-turn Dialogue and Prompt Engineering
Document types for CDN and edge acceleration configuration are scattered, with notable field differences.
Multi-turn dialogue must first clarify the current document category being processed. This prevents confusion in verification logic for core fields such as filing number and cache TTL.
Data sources are scattered, and update frequencies are flexible. Prompts must guide users to provide the latest configuration change information. This ensures generated documents match current system status.
Filing verification and cache rule debugging are the most time-consuming steps. Multi-turn dialogue must prioritize collecting core fields to reduce ineffective interactions.
Public network access-related error consequences require prompts to include field verification logic. This ensures document parameters are compliant.

## How to Set Configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Maximum context window | First 20 conversation turns or 8000 characters | Matches multi-link fields of CDN documents, prevents information loss from context overflow |
| Variable mapping rules | Bind filing number and origin server address fields in `variables` | Corresponds to required fields in domain access forms, ensures complete fields in generated documents |
| Session reset threshold | Group by `chatId`, reset context every 600 seconds | Avoids context confusion across work orders, aligns with independent processing logic for CDN work orders |
| Prompt update frequency | Sync latest cache rule library once daily | Matches daily data update frequency, ensures prompts cover latest configuration items |
| Conversation role distinction | Distinguish user input and system prompts by `messages` role | Separates requirement collection and document verification links, avoids confusion in interaction logic |

## Three Common Misconfigurations
- Empty results are returned when calling workflows concurrently. Reviewing workflow logs reveals runtime limits have been triggered. The cause is failure to adjust runtime thresholds for the high-frequency CDN work order submission scenario. High-frequency calls trigger current limiting.
- Variable results in AI replies show content overlap. The variable A result from the previous round is included in the current variable B output. The cause is failure to correctly configure context isolation rules for `variables`, and failure to reset session variables by `chatId`.
- Expected guide questions do not appear in the conversation interface after enabling input guidance and thesaurus. The cause is failure to synchronize CDN-specific terms such as cache rules and filing verification to input guidance configurations, leading to matching failures.

## How to Confirm Correct Configuration
- Test calls to prompts that include filing number and origin server address fields in `variables`. Check if returned document fragments include corresponding fields.
- Simulate high-frequency call scenarios. Review workflow logs for current-limiting related status codes. Confirm threshold configurations align with actual usage needs.
- Enable input guidance function. Manually input CDN-specific terms. Check if matching logic for the corresponding thesaurus is triggered.
- View session logs grouped by `chatId`. Confirm that context from different work orders is not mixed.
