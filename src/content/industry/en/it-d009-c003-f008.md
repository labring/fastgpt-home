# Drafting Requirements and Design Documents for IT Asset Inventory: Workflow Orchestration

## What Data for This Category Looks Like
Data for this category comes from asset management systems, procurement systems, financial fixed asset modules, and terminal management platforms. Update frequency is monthly, quarterly, or annually. Daily produced documents include asset ledgers, inventory sheets, loan and return forms, and scrap applications. Document fields include asset number, name, specification model, user, location, usage status, and similar items. Corresponding units include unit, set, piece, and similar terms. Associated stakeholders are IT asset administrators, financial asset staff, and desktop support personnel. The core focus is on asset ownership, location, and user information.

## Constraints Imposed by These Characteristics on Workflow Orchestration
This explanation uses the workflow function logic of FastGPT v4.17.0. Data sources for this category are scattered, and update cycles are fixed. Workflow orchestration must adapt to multi-system interface call logic. It must trigger inventory tasks on a monthly, quarterly, or annual cycle. Document fields must strictly match core information such as asset ownership, location, and user. Workflow nodes must include required field verification rules to prevent missing key information. Different business scenarios use different document templates. Workflows must support branch jump logic to adapt to links such as ledger updates, inventory checks, and scrap applications. Data errors can lead to asset loss or audit issues. Workflows must add exception alert nodes to block non-compliant process submissions.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger node settings | Trigger based on asset update cycle, supports monthly/quarterly/annual cycles | This category of data is updated monthly, quarterly, or annually, matching business execution rhythm |
| Variable verification rules | Pre-set asset number, user, and location as required variables | Document core fields must cover asset ownership, location, and user to avoid missing key information |
| Branch node configuration | Set 3 parallel branches based on asset status (in use/loaned/scrapped) | Different business scenarios correspond to different document templates and process logic |
| Node ID configuration | Assign a unique `nodeId` to each business branch | Ensure workflow nodes can be accurately identified and jumped to |
| Exception alert configuration | Trigger system alerts within 120 seconds when field verification fails | Data errors may lead to asset loss or audit issues, requiring timely blocking of abnormal processes |
| Single node timeout setting | Set single system interface call timeout to 600 seconds | Multi-system data pulling must adapt to response time ranges of different interfaces |

## Three Common Errors
- Phenomenon: New context and reply content from AI conversation nodes are incorrectly bound to the same document field, resulting in missing user information in generated inventory sheets. Cause: Binding rules for the two types of output are not clearly configured, and context is not used to fill in historical asset data, while reply content is only used for adding new fields.
- Phenomenon: Timeout errors occur during workflow execution, with the interface displaying request timeout. Cause: Timeout thresholds adapted to multi-system calls are not set, and single node call duration exceeds system preset limits.
- Phenomenon: Calling the workflow API interface returns empty results, and asset ledger data cannot be pulled. Cause: Correct asset screening parameters are not configured in `variables`, causing the interface to fail to match corresponding business data.

## How to Confirm Configuration Completion
- Manually trigger a workflow, check whether the generated asset ledger includes preset core fields, and confirm that field matching rules take effect.
- Call the workflow API interface, check whether returned asset data matches the configured screening range, and confirm that interface call logic is correct.
- Simulate a scenario with missing fields, confirm whether preset alert rules are triggered, and verify that exception interception logic takes effect.
- View workflow node logs, confirm that branch jump logic executes correctly based on asset status, and verify that branch configuration is accurate.
