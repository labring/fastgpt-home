# Drafting Requirements and Design Documentation for Issue Triage and Response: Context and Token

## What the data for this category looks like
This category’s data mainly comes from GitHub or Gitee Issues, code repository version logs, user-submitted environment information, and problem reproduction descriptions.
Daily maintained documents include Issue templates, tag rules, historical response records, and responsible module mapping tables.
Data updates occur daily or weekly.
Each single data entry includes fields such as problem title, description, associated code snippets, submission time, and user tags.
The content is primarily text and label-style content, with no fixed quantitative unit fields.

## Constraints imposed by these characteristics on context and token handling
This category’s data is mostly unstructured text, including code snippets, environment logs, and detailed reproduction steps. Token usage varies significantly across single data entries.
Issue submission frequency fluctuates with project popularity. High-volume periods can generate large amounts of new data in a single day. This requires controlling the total token count processed per round during context recall, to avoid exceeding model limits.
Additionally, data must be linked to responsible module information from the code repository. If the context recall range is too large, irrelevant content will be introduced, reducing triage accuracy.
Failure to configure minimal context for short Issues, or to restrict the value of `quoteMaxToken`, will waste token quotas and prevent complete recall of valid information from long Issues.

## How to set configurations
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| Similarity Threshold | 0.35–0.45 | Matches the relevance between Issue text for this category and knowledge base content, to avoid recalling irrelevant historical responses or tag rules |
| `quoteMaxToken` | 8000–12000 token | Adapts to the average token usage of single Issues in this category, while reserving space for the model’s triage logic |
| `maxContext` | 14000–16000 token | Matches the base context limit of FastGPT v4.17.0, to avoid exceeding the model’s total token limit |
| Single Recall Count | Top 3–5 entries | Controls the total token usage of per-round context, to avoid introducing excessive irrelevant historical Issue data |
| Context Truncation Strategy | Truncate by content importance | Prioritizes retaining core information such as Issue reproduction steps and responsible module tags, discards non-critical redundant content |

## Three common configuration mistakes
- Phenomenon: After setting the similarity threshold to 0.4, required tag rules or historical response records still cannot be recalled. Cause: The threshold was not adjusted to match the Issue text characteristics of this category. A threshold that is too low will recall irrelevant content, while a threshold that is too high will miss relevant matches.
- Phenomenon: Model output is truncated at 12288 tokens, and the interface displays a reply limit exceeded error. Cause: `maxContext` was not configured to match the model’s total token limit, and `quoteMaxToken` was not restricted. This causes total context usage to exceed the model’s supported range.
- Phenomenon: Too many associated Issues are returned during single-round processing, leading to increased processing time. Cause: Single recall count was not restricted, introducing a large volume of unnecessary historical data and consuming excessive token quotas.

## How to confirm correct configuration
- Review token usage logs for single Issues, confirm that the `maxContext` configuration does not exceed the model’s total token limit.
- Submit test Issues of varying lengths, check that context recall results include core reproduction steps and responsible module information.
- Compare recall results before and after adjusting configurations, confirm that the similarity threshold value matches the content characteristics of the current knowledge base.
- Check output logs, confirm that no token limit exceeded error prompts appear.

The values provided are common starting points and should be measured against the reader's own samples.
