# Pull Request Review Requirements and Design Document Drafting: Document Parsing and Chunking

## What the data for this category looks like
Data related to Pull Request reviews comes primarily from code repositories, CI pipelines, Issue links, and contributor submissions. Update frequency is daily or weekly. Daily processed documents include PR descriptions, code review comments, CI results, and merge records. These documents typically include fields such as change scope, dependencies, test steps, and review comments. Metadata includes character counts, submission counts, CI run durations, and similar units.

## Constraints Imposed by These Characteristics on Document Parsing and Chunking
This category’s data sources include multi-format files, such as docx PR templates and pdf CI logs. High-frequency updates require the parsing process to be efficient. Structured fields in PR documents—such as change scope and review comments—require chunking to preserve logical connections, and avoid splitting complete review logic across fields. Long text fragments from CI results and merge records require reasonable chunk length control to balance retrieval accuracy and context completeness. Some documents include embedded tables and code blocks. Chunking strategies must adapt to these special formats to prevent loss of data associations.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | PR review documents include long paragraphs such as change descriptions and test steps. This range preserves the complete context of a single review logic |
| `chunkSplitter` | Split by heading + paragraph | PR documents have clear heading levels for change scope, review comments, and similar sections. Splitting by heading preserves logical connections |
| `customPdfParse` | Enable MinerU adaptation mode | Adapts to open-source PDF-to-Markdown services, resolving issues with parsing some complex tables |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Some large PRs include long CI log documents. Sufficient timeout time is required to complete parsing |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports upload of large merge records and CI log files, adapting to team-level PR review data volumes |
| `chunkSettingMode` | Manual configuration | For the specific structure of PR documents, manually adjusting chunk parameters better fits business needs than automatic mode |

## Three Common Misconfigurations
- Some docx documents fail to parse, and a parsing failure prompt appears in the interface. The cause is that `customPdfParse` is not enabled to adapt to complex embedded format PR document templates, resulting in failure to recognize some custom fields.
- Some tables are not chunked correctly, and chunking results lose table column association information. The cause is that `chunkSplitter` is configured to split only by line breaks, without adapting to the structure where table titles and content are bound in PR documents.
- Out-of-vRAM error occurs after container deployment, and GPUs cannot be detected. The cause is that CUDA environment variables are not mounted correctly, and `PARSE_FILE_TIMEOUT_SECONDS` is set too short, causing parsing processes to retry repeatedly and consume VRAM.

## How to Verify Configurations Are Correct
- Upload a sample PR review document that includes tables and long paragraphs. Confirm the parsed Markdown retains table structure and paragraph logic.
- Upload a CI log file of approximately 100 MB. Confirm the parsing task completes within 600 seconds with no timeout errors.
- Adjust the `chunkSize` parameter. Verify chunked text fragments completely contain a single review comment or change description.
- Check the FastGPT v4.17.0 system GPU monitoring panel. Confirm parsing processes call the configured CUDA environment, with no abnormal VRAM usage.

The values provided here are common starting points. They should be evaluated against the reader’s own samples.
