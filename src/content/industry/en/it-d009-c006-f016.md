# Pull Request Review Requirement and Design Document Drafting: Forms and Interactions

## What the data for this category looks like
Data for this category primarily comes from code repositories, CI pipelines, Issue links, and contributor submissions. Daily generated documents include PR descriptions, code review comments, CI results, and merge records. Data updates occur daily or weekly. Core fields include change scope, associated Issue numbers, test status, merge prerequisites, and reviewer information. Typical users are project maintainers, module owners, and contributors. Data flows around mergeable code changes, which differs from Issue triage and response tasks.

## Constraints on forms and interactions
Decentralized data sources require forms to cover multiple types of information, including code change scope, associated Issues, and test results. This prevents missing core review basis. Missing core fields directly causes review delays or merge errors, so set mandatory validation rules. Typical review participants have clear roles, so limit the selectable user range for the `userSelect` node to ensure review professionalism. The change intent confirmation step is the most time-consuming. Add guiding copy to forms to unify information collection standards and reduce cross-role communication costs.

| External implementation: Form submission timeout control | Implement separately via external systems; set test example value to 600 seconds, implemented via external workflow environment | Adapt to CI pipeline execution cycles to prevent form submission from blocking external workflows |
| External implementation: Mandatory item validation | Implement separately via external systems; mark associated Issue numbers and test result links as mandatory fields | Avoid error consequences such as merge conflicts and regression defects |

## Three common configuration errors
- A `quote type error` appears during debug preview: Verify that the variable reference syntax for form fields matches the preset format, and that correct quoting rules are used.
- Guiding copy fails to display normally in the form: Confirm that external guiding content is correctly configured, and that form node configuration changes have been saved.
- Cross-branch calls to form nodes fail: Check that external workflow branch associations are correctly configured, and that node parameters are properly passed to subsequent nodes.

## How to confirm configuration is complete
- Submit a test form, and verify that the associated Issue number and code change scope information collected by the `formInput` node are correctly passed to subsequent nodes.
- Attempt to submit a form without filling in the associated Issue number, and confirm that the system triggers mandatory validation prompts.
- When the `userSelect` node is triggered, confirm that the selectable user range provided by the external permission management system only includes project maintainers and module owners.
- Enter debug preview mode, and verify that the input guiding copy is displayed normally at the top of the form.
