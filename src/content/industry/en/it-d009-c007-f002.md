# Requirements and Design Document Drafting for SLA and Service Reports: Context and Token

## What data for this category looks like
This category of data comes from monitoring systems, ticketing systems, service contracts, and customer communication records. The update cadence is monthly or quarterly. Daily produced documents include SLA clauses, monthly service reports, availability statistics reports, and customer review minutes. Core fields include service indicators bound to contracts, event occurrence time, service response duration, ticket processing results, and customer feedback ratings. Fixed percentage statistical fields are not included. Data is stored in structured text and numerical formats. Some historical records are unstructured communication minutes. Data volume increases gradually as the statistical period lengthens.

## What constraints do these characteristics impose on the context and token link
Since data sources are scattered and update cycles are fixed, the context must cover all service events and contract terms for the full monthly or quarterly period. Single-context token consumption will increase significantly as the cycle lengthens. Unstructured content exists in SLA clauses and review minutes, requiring more precise context retrieval to avoid irrelevant data occupying tokens. Service report fields must strictly match contract agreements. Context-retrieved content must include accurate contract numbers and indicator definitions, otherwise invalid token consumption or calculation errors will occur. Format differences across multiple data sources increase the complexity of context splicing. The volume of non-essential retrieved data must be limited to control the token cap and avoid exceeding the model's context window limit.

## How to set configurations
These configurations apply to FastGPT v4.17.0, as detailed below:

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Matches the core data volume of monthly service reports, and adapts to the context window cap of general large models |
| `quoteMaxToken` | `2000–3000 token` | Limits the token share of retrieved unstructured customer communication minutes, avoiding excessive occupation of context space |
| Maximum number of context retrieval entries | Top 6 entries | Controls the number of service events retrieved in a single call, adapting to the scale of core events in monthly statistics |
| Context retrieval similarity threshold | 0.75–0.85 | Filters low-relevance historical records to reduce invalid token consumption |
| Context synchronization frequency | Daily | Matches the real-time data update cadence of monitoring systems, ensuring the accuracy of service report calculations |

## Three common mistakes
- Symptom: When calling the model to query associated service data, the token consumption displayed by the platform does not match third-party API billing results. Cause: The `maxContext` configuration does not filter redundant historical communication records, resulting in a large amount of non-core data being included in the context, causing invalid token consumption.
- Symptom: The context content output by the AI conversation node is empty and cannot be used for SLA indicator calculation. Cause: No association rule between data sources and contract numbers is configured, so SLA clauses and service event data for the corresponding contract cannot be retrieved.
- Symptom: The SLA indicator calculation in the generated service report is incorrect and does not match the contract agreement. Cause: `quoteMaxToken` is set too low, resulting in key SLA clause content being truncated, making it impossible to match correct indicator definitions and calculation rules.

## How to confirm the configuration is correct
- View the context retrieval log, check that the number of retrieved service events matches the configured number of retrieval entries, and confirm that the token cap of `maxContext` is not triggered frequently.
- Compare the token consumption of model calls with the sum of the configured `quoteMaxToken` and `maxContext`, confirming that overall token usage meets expectations.
- Randomly select a monthly service report, check that the retrieved SLA clause content matches the original contract, confirming the accuracy of context retrieval.
- Test cross-month data retrieval, confirming that service data from different cycles can be correctly associated with the corresponding contract, avoiding confusion across cycle data.

The values provided here are common starting points and should be measured against the reader's own samples.
