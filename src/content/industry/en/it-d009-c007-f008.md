# Drafting Requirements and Design Documents for SLA and Service Reports: Workflow Orchestration

## What the data for this category looks like
This category's data originates from monitoring systems, ticket systems, contract documents, and customer communication records, with a monthly or quarterly update cycle. Daily output documents include SLA clause text, monthly service reports, availability statistics reports, and customer review minutes. Data fields include service indicators bound to contracts, event occurrence times, statistical cycle ranges, and service compliance flags. Only service-related quantitative and text information is recorded in industry-standard formats, with no additional custom units.

## What constraints do these characteristics impose on the workflow orchestration link
As data sources are scattered and update cycles are fixed, the workflow must support scheduled monthly or quarterly triggering, and automatically pull data for the target cycle from multiple systems. As document fields follow clear specifications, the workflow must include a field verification link to ensure pulled fields such as contract numbers and service indicators meet format requirements. As core time-intensive steps include SLA indicator calculation and caliber alignment, the workflow must integrate standardized calculation logic to reduce manual adjustment steps. It must also configure caliber-consistent nodes to prevent statistical caliber differences across reports from different cycles.

## Configuration Guidelines
The following configurations are written for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Scheduled Trigger Settings | Monthly/Quarterly | Matches the update frequency of this category's data, ensuring the workflow runs according to the contract cycle |
| `variables` Configuration | Bind contract number, statistical cycle | Reuse core business identifiers, avoid duplicate data entry, and align with the global variable use case for `variables` |
| Node Output Filtering | Hide intermediate AI conversation node content | Prevent unnecessary intermediate step results from appearing in the final service report |
| Coreference Resolution | Enable historical context association | Resolve coreference issues during knowledge base searches, and improve search result accuracy |
| Single Search Result Limit | Top 5 entries | Control the number of returned results, and avoid redundant content in service reports |
| Workflow Version Management | Calibrate based on actual testing | Adapt to adjustment needs for different cycle reports, and retain historical configuration versions |

## Three Common Misconfigurations
- Phenomenon: After the workflow runs, content from intermediate AI conversation nodes appears in the final service report. Cause: No node output filtering rules are configured, and unnecessary intermediate step output is not hidden.
- Phenomenon: Global variables do not function across all workflow links, and some nodes cannot call preset contract numbers or statistical cycles. Cause: `variables` parameters are not correctly bound, or global variable calling is not enabled in the corresponding nodes.
- Phenomenon: Knowledge base search results cannot properly handle referential questions, such as identifying "this service" as unknown content. Cause: Historical context association configuration is not enabled, and user historical conversation records are not used to optimize search queries.

## How to Verify a Correct Configuration
- Manually trigger the workflow once. Check that the final output document only includes content required for the service report, with no redundant intermediate AI conversation information.
- Open the global variable configuration page. Confirm that identifiers such as contract numbers and statistical cycles bound in `variables` are correctly associated with all nodes in the workflow.
- Test the knowledge base search node. Enter a question containing referential content, and check that returned results associate with historical context to resolve coreference issues.
- Verify the scheduled trigger function. Set a temporary test cycle, and confirm that the workflow automatically starts according to the preset monthly or quarterly cycle.
