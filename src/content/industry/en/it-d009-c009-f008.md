# Drafting Requirements and Design Documents for Personal Information Protection Compliance: Workflow Orchestration

## What Data in This Category Looks Like
Data for this category comes from business systems, App permission lists, privacy policies, and user request records. The update frequency is quarterly or each time a product version is updated. Daily produced documents include personal information lists, personal information processing rules, personal information impact assessment reports, user authorization texts, and more. Document fields must cover core items such as information processing scenarios, legal bases, data subject scope, and storage periods. Each document corresponds to the compliance requirements of a single product or business module.

## What Constraints These Characteristics Impose on the "Workflow Orchestration" Link
Dispersed data sources require the workflow to be configured with multi-source data pull links, covering different entry points such as business systems and permission lists. There are various document types, so input and output nodes for different formats must be adapted. The update frequency must be flexibly adjusted with product changes. Fixed timed triggers are not suitable, and the workflow must be bound to product version change events. Core time-consuming links must be split into independent nodes to facilitate step-by-step verification and adjustment. A compliance verification node must also be configured to avoid oversights in processing scenario sorting and legal basis confirmation steps.

## Configuration Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Contains preset values for product version, data subject scope, and storage period | Matches the core fields of personal information compliance documents, facilitating the transfer of fixed compliance parameters between nodes |
| Workflow timeout duration | `600 seconds` | Covers the typical time range for multi-source data pulling, scenario sorting, and legality verification |
| Multi-source data pull node | Binds three data sources simultaneously: business system, App permission list, and privacy policy | Covers all source channels of data in this category |
| `nodeId` | Assigns a unique identifier to each compliance verification sub-node | Facilitates troubleshooting of exceptions in the legal basis confirmation link within the workflow |
| Document export format | Supports PDF and Markdown formats | Matches standard submission and archiving formats for compliance documents |
| Form input node maximum character count | `8000 characters` | Covers the typical entry length of personal information lists |

## Three Common Mistakes
- Phenomenon: The branching logic for tool calls and MCP calls fails, and the number of results does not match expectations. Cause: No judgment condition based on request type is configured in the branch node.
- Phenomenon: The default value of the form input node is empty, and the product version parameter in `variables` cannot be read. Cause: The reference path of the corresponding global variable is not bound in the node configuration.
- Phenomenon: The document upload node in the workflow reports an error and cannot read the privacy policy file. Cause: No upload verification rule supporting PDF and Word formats is configured.

## How to Confirm the Configuration Is Correct
- Trigger the workflow, and check whether the multi-source data pull node successfully pulls the corresponding data from the business system and App permission list.
- View the default value of the form input node, and confirm whether the preset parameters in `variables` are read correctly.
- Run the compliance verification node, and verify whether the logic of the legal basis confirmation link is triggered normally.
- Export the workflow file, and confirm that all configured nodes and parameters are included.
