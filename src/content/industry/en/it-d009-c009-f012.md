# Requirements and Design Document Drafting for Personal Information Protection Compliance: Document Parsing and Chunking

## Data Characteristics for This Category
Data for this category comes from business systems, App permission lists, privacy policies, and user request records. Update cycles follow quarterly intervals or each product version change. Daily processed documents include personal information inventories, processing rules, impact assessment reports, and user authorization texts. Most documents contain core fields such as natural person identification information, processing purposes, and legal bases. There is no unified fixed unit, and corresponding fields must be extracted based on document type. The main stakeholders are privacy compliance teams, security consulting institutions, and legal departments. Core work focuses on the entire process of processing information that can identify natural persons.

## Constraints Imposed on Document Parsing and Chunking
Documents contain sensitive natural person information, so parsing must avoid information leakage. Corresponding rules must be configured to filter or desensitize sensitive content. Document update frequency follows product changes, so chunking logic must adapt to structural changes in different documents to avoid parsing failure due to format differences. Core compliance fields such as legal bases and processing purposes must be fully retained within a single chunk. Chunk length must cover complete semantic units to prevent field splitting from disrupting compliance logic. There are diverse document types, so parsing rules must adapt to inventory, report, text, and table documents to avoid content loss due to format incompatibility. Compliance scenarios have extremely high requirements for document integrity. Chunking failure or content missing may directly affect subsequent compliance assessments, so reasonable timeout and retry mechanisms must be set.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | `800–1200 characters` | Covers the core semantic units of personal information inventories and impact assessment reports, avoids splitting compliance fields such as legal bases |
| `chunkSplitter` | Split by paragraph + heading | Compliance documents mostly contain hierarchical headings and structured content. Splitting by headings preserves the integrity of compliance logic |
| `customPdfParse` | Enable sensitive field filtering | Documents contain natural person identification information. Sensitive content must be removed or desensitized during the parsing phase to meet compliance requirements |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | Compliance documents are mostly batch reports or long texts. Large file upload support is required to avoid parsing interruption due to oversized files |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Long document parsing takes a long time. Set a reasonable timeout to prevent task termination ahead of schedule |
| `chunkSettingMode` | Manual configuration | Compliance documents have diverse formats. Manual configuration adapts to the chunking needs of different document types and ensures core fields are complete |

## Three Common Configuration Mistakes
- Phenomenon: After Docker deployment, processing compliance PDF documents returns an error message in the format `{"detail":"error message"}`. Cause: Sensitive field filtering rules for `customPdfParse` are not configured correctly, or environment variables are not loaded properly, leading to sensitive content verification failure during parsing.
- Phenomenon: Core compliance fields such as legal bases are empty or split across multiple chunks after chunking. Cause: The `chunkSize` setting is too small, splitting complete compliance logic units into multiple chunks, resulting in incomplete field information that cannot support subsequent compliance assessments.
- Phenomenon: When uploading XLSX-format user authorization texts, the parsing result misses multiple lines of table content. Cause: The `chunkSplitter` rules are not adjusted for table documents. The default chunking logic does not adapt to the structured content of multi-line tables, leading to truncated table data.

## How to Verify Correct Configuration
- Upload a typical personal information inventory document, verify that the parsed text contains preset core compliance fields, and no desensitized natural person identification information appears.
- Adjust chunking configuration parameters to verify that chunked content units cover complete compliance logic, with no key fields split across chunks.
- Upload the maximum size document that matches the business scenario, confirm that the parsing task does not trigger timeout termination and successfully generates chunked data.
- Upload XLSX-format compliance documents, verify that table content is fully extracted and correctly included in chunked units.

The values given are common starting points and should be measured against the reader's own samples.
