# Requirements and Design Document Drafting for Cloud Host Provisioning and Resource Activation: Context and Token

## What the data for this category looks like
Data for this category typically originates from cloud management platforms, order systems, IAM, and billing systems. Update frequency is per order or real-time. Daily produced documents include resource activation forms, instance configuration sheets, account permission forms, and delivery confirmation sheets. Most structures combine structured fields, including core fields such as instance specifications (unit: vCPU cores, GB memory), region, image ID, permission group ID, and billing cycle. The content length of a single document usually ranges from hundreds to thousands of characters.

## What constraints these characteristics impose on the "context and token" workflow
Integrating multi-source data requires context recall to cover associated fields from different sources such as cloud management platforms and order systems. This prevents missing core configuration information.
The real-time update feature requires context configuration to adapt to dynamically changing resource states. This stops outdated order or permission data from being recalled.
The structured document structure requires chunking and recall logic to match field boundaries. This avoids splitting that breaks the integrity of core configuration items such as instance specifications and regions.
The single-document content length range requires context and token configuration to balance recall scope and resource usage. This prevents token overflow or truncation of key information.

## How to set the configurations
| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | The core content of a single delivery document for this category usually does not exceed 10,000 characters. The corresponding token count falls within the context bearing range of FastGPT v4.17.0 |
| `quoteMaxToken` | `2000–3000 token` | The core field content of a single resource activation form is approximately 1500-2500 characters. This matches the document content scale of this category |
| Chunk overlap length | `100–200 characters` | Documents in this category use structured field combinations. A small amount of overlap ensures context coherence and avoids field splitting breaks |
| Recall matching threshold | `0.75–0.85` | Precise matching of core fields such as instance specifications and regions is required. This prevents irrelevant historical data from being mixed into the context |
| Single recall count | Top 3–5 entries | The amount of data associated with a single delivery document for this category is limited. Excessive recall will consume too many token resources |

## Three common configuration mistakes
- Failing to set `maxContext` appropriately. A value that is too small may cause core fields such as instance specifications and regions to be missing after context truncation. This leads to resource configuration errors.
- Failing to configure `quoteMaxToken` correctly. This may cause the referenced source data chunk to be too large. It consumes too many tokens and causes context overflow or result truncation errors.
- Failing to match the recall logic to the permission field structure of the IAM system. This may trigger an E11000 duplicate key error when adding a new account. This causes database conflicts.

## How to verify correct configuration
- Upload a single resource activation form document. Check the FastGPT context preview panel. Confirm that core fields such as instance specifications, region, and permission group are fully recalled.
- Initiate a resource configuration verification request. Check the token consumption statistics. Confirm that the values of `maxContext` and `quoteMaxToken` are not exceeded.
- Check the server environment variables `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service, for example http://aiproxy:3000. Do not append /v1 or single model service address paths) and `AIPROXY_API_TOKEN` (AI Proxy administrator token. Must match the AI Proxy server configuration and cannot be empty. Do not use this as an application API key, model vendor key, etc. Do not replace service deployment configuration with this variable in workflow global variables, application API request headers, or general model management pages). Confirm that the configuration values match the actual AI Proxy service information.
- Simulate an add account permission operation. Check the system logs. Confirm that no abnormal prompts related to E11000 duplicate key errors appear.

The values provided here are common starting points. They should be validated against the reader’s own samples.
