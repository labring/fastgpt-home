# Drafting Requirements and Design Documents for Cloud Host Provisioning and Resource Activation: Multi-turn Dialogue and Prompt Engineering

This document provides configuration instructions based on FastGPT v4.17.0.

## What Data for This Category Looks Like
Data for this category typically comes from cloud management platforms, order systems, IAM, and billing systems. Data updates occur per order or in real time. Daily output documents include resource activation forms, instance configuration sheets, account permission forms, and delivery confirmation sheets. Document structures generally include fields such as instance specification parameters, network configuration, permission configuration, and billing information. Field units follow standard specifications for each parameter: vCPU uses cores as the unit, memory uses GB, and delivery time is recorded in a standard format.

## Constraints on Multi-turn Dialogue and Prompt Engineering Link
The multi-turn dialogue and prompt engineering link for cloud host provisioning must adapt to the characteristics of scattered data sources, real-time updates, and numerous document fields.
First, data comes from multiple systems, so prompts must explicitly specify integration of parameters from different systems to avoid missing key information.
Second, the real-time update feature requires the dialogue link to pull the latest data in real time, and cannot rely on cached old parameters.
Third, multiple document types and rich fields require multi-turn dialogue to gradually guide users to supplement required parameters, avoiding errors caused by submitting too much content at once.
Fourth, configuration errors directly affect customer deployment, so the dialogue link must add basic parameter verification logic to ensure configurations comply with general cloud platform specifications.

## How to Set Configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique identifier of each delivery order | Ensure multi-turn dialogue associates all documents and parameters for the same order |
| `messages` | Concatenate in the order of system prompts, user input, and AI replies; retain the first 8 rounds of dialogue | Cloud host provisioning requires multi-step confirmation. Retaining recent context avoids repeated inquiries about required fields |
| `variables` | Bind to real-time available parameters from cloud management platforms and order systems | Must obtain the latest instance specifications, regions, permission lists, and other data in real time |
| Maximum tokens per single dialogue | 7000–9000 tokens | Accommodate complete delivery document fields and detailed configuration information entered by users |
| Multi-turn dialogue trigger condition | Triggered when more than 2 required document fields are detected as missing from user input | Guide users to gradually supplement necessary parameters to improve interaction efficiency |

## Three Common Mistakes
- Phenomenon: After calling the dialogue interface, a 200 status code is returned but the response body is empty, with no valid delivery configuration information. Cause: `variables` is not correctly bound to the real-time data interface of the order system or cloud management platform, so the AI cannot obtain necessary parameters.
- Phenomenon: For a brief cloud host configuration inquiry, the AI first returns the complete result at once before switching to streaming output mode. Cause: The dialogue context window retains too much historical dialogue content, so the AI must first integrate all context information before generating a reply.
- Phenomenon: The output content of code execution in the workflow cannot be passed to the dialogue link, and the dialogue cannot read this data. Cause: The output result of the code execution is not correctly mounted to the `variables` parameter, so the dialogue link cannot access this data.

## How to Verify Proper Configuration
- Initiate a simulated cloud host resource activation request, check whether the dialogue can gradually guide users to supplement required fields such as region, instance specification, and permission scope.
- Review the data source configuration bound to `variables`, confirm that the latest data such as available instance specifications of the cloud management platform and permission lists of IAM can be pulled in real time.
- Call the dialogue interface, check that the response body contains the unique identifier `chatId` corresponding to the simulated order.
- Test a brief configuration inquiry, confirm that the AI replies use streaming output and have no obvious context integration delay.
