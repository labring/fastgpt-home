# Drafting Requirements and Design Documents for Cloud Host Provisioning and Resource Activation: Forms and Interactions

## What the data for this category looks like
Data for this category comes from cloud management platforms, order systems, IAM, and billing systems. Update frequency is per order or real-time. Daily produced documents include resource activation forms, instance configuration sheets, account permission forms, and delivery confirmation forms. Core fields include instance specifications, deployment regions, system images, security group rules, IAM permission configurations, billing modes, and more. Document structure follows the application-review-delivery workflow in layers. Each field must match the parameter format of the corresponding system.

## What constraints these characteristics impose on forms and interactions
Multiple systems providing data requires real-time options to be fetched via external business system linkage. FastGPT’s `formInput` and `userSelect` interaction nodes receive these options and display them to users. This prevents parameter mismatches caused by manual input.
The real-time update frequency requires that after a form is submitted, external business systems or subsequent workflow nodes quickly complete verification and synchronization. FastGPT’s interaction nodes pass user input information to support this process. This prevents resource misalignment or billing anomalies.
Multiple types of business documents require external business systems to separately implement dynamic field configuration logic for documents. FastGPT’s `formInput` and `userSelect` interaction nodes collect user input information and pass it to subsequent nodes. This matches required fields and format requirements for different scenarios.
The most time-consuming specification verification link requires external business systems or subsequent workflow nodes to implement automatic verification logic. FastGPT’s interaction nodes pass user input information to support this verification. This reduces manual verification costs and error rates.

## Three common mistakes
- Phenomenon: Forms built using FastGPT interaction nodes allow submission or initiation of subsequent operations without completing required field verification. Cause: Required field verification logic for external business systems or subsequent workflow nodes is not configured. Pre-submission verification links are not set up.
- Phenomenon: Drop-down options in forms built using FastGPT interaction nodes do not match actually activatable resources. Invalid optional values appear. Cause: External business system linkage to pull real-time options is not implemented. Options are not updated in a timely manner.
- Phenomenon: Instance deployment fails or billing anomalies occur after submitting a form built using FastGPT interaction nodes. Cause: Linkage verification rules configured via external business systems or subsequent workflow nodes are missing. Matching between instance specifications, regions, and images is not verified. Data is not synchronized to the billing system.

## How to confirm configuration is complete
- Open the corresponding business document form built using FastGPT interaction nodes. Check whether required fields are configured according to document type. Attempt to submit with incomplete fields to verify whether external verification logic triggers prompts.
- View the drop-down option list in the form built using FastGPT interaction nodes. Confirm that options are pulled by external business systems from cloud management platforms, IAM, and other business systems. Switch regions to check whether options are synchronized and updated.
- Simulate submitting a test form built using FastGPT interaction nodes. Check whether data is synchronized to order systems and billing systems. Verify whether external callback logic takes effect.
- Trigger field verification. Enter an invalid instance specification. Check whether FastGPT interaction nodes display precise error messages generated by external business systems or subsequent workflow nodes. Verify whether external verification prompt configuration takes effect.
