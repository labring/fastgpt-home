# Drafting Requirements and Design Documents for Cloud Network and Load Balancer Configuration: Workflow Orchestration
This page is written for FastGPT v4.17.0.

## What Data for This Category Looks Like
Daily documents for this category include VPC planning, security group rules, load balancer configurations, and change tickets. Data sources include cloud platform consoles, network topologies, traffic monitoring, and customer architecture diagrams. Update frequency is per ticket or per change. Document fields include subnet mask, port range, health check interval, backend server weight, and more. Corresponding units include /24, 80/443, seconds, percentage, and others. Format varies by cloud vendor, and configuration rules for the corresponding platform must be followed.

## What Constraints Do These Characteristics Impose on the Workflow Orchestration Link
Data for this category is mostly structured, but configuration formats vary across cloud vendors, and update frequency is high. Workflows must support direct reading of structured data returned by cloud APIs, without relying on general-purpose text parsing. Units and validation rules for document fields must strictly match the requirements of the corresponding cloud platform. Therefore, workflows must include a dedicated field validation step to prevent configuration failure from unit errors or rule mismatches. At the same time, workflows triggered by change tickets must be synchronized with business processes to ensure corresponding design documents are generated immediately after configuration updates.

## How to Set Configurations
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| Input Source Type | Cloud API structured data | Data for this category comes from structured sources such as cloud consoles, eliminating the need for general-purpose text parsing |
| Node Trigger Timing | After change ticket submission | Matches the per-ticket or per-change update frequency of this category, and synchronizes with business process nodes |
| `variables` binding scope | Current workflow context | Accurately associates dedicated document fields such as VPC planning and load balancer configurations |
| Failed Retry Count | 3 times | Addresses temporary network fluctuations during cloud API calls, preventing workflow interruptions from a single failed call |
| `nodeId` association rules | Only associate with cloud network nodes | Limits workflow scope to avoid interference from unrelated configurations |
| Validation Rule Threshold | Calibrated based on actual testing | Adapts to the complexity of network configuration validation across different cloud vendors |

## Three Common Mistakes
- When a workflow node calls a large language model, text parsing is enabled by default, and structured documents are not passed directly. This prevents accurate identification of fields such as subnet masks and port ranges, leading to format errors in the final generated configuration documents.
- When multiple code running components are added to a workflow, no node execution order is set. This reverses the execution logic of configuration validation and change ticket generation, causing configuration conflicts.
- When configuring the problem optimization link, environment variable binding is not enabled. This prevents access to preset network compliance verification rule libraries, and automatic troubleshooting of security group rule exposure risks cannot be completed.

## How to Confirm the Configuration Is Complete
- View the workflow configuration panel, confirm that the input source type has been selected as cloud API structured data.
- Trigger a test change ticket, check whether the node execution log contains correct field content such as subnet and port.
- View the `variables` binding list, confirm that dedicated document fields such as VPC planning and load balancer configurations for the current workflow have been associated.
- Simulate a cloud API call failure scenario, confirm that the workflow automatically re-executes after triggering the failed retry mechanism.
