# Requirements and Design Document Drafting for Cloud Network and Load Balancer Configuration: Document Parsing and Chunking

## What the data for this category looks like
Daily documents for this category include VPC planning, security group rules, load balancer configurations, change tickets, and similar content. Data sources are configuration files exported from cloud platform consoles, network topology diagrams, traffic monitoring reports, and customer architecture diagrams. Documents follow a structure based on change tickets and configuration item chapters, and include fields such as network segment range, port mapping, health check thresholds, and backend server groups. Common units include Class C network segments, milliseconds, and server units. Update frequency aligns with each completed configuration change.

## Constraints imposed by these characteristics on the document parsing and chunking link
Structured chapter documents for this category require chunking to retain chapter titles to maintain context association. Frequent change updates require the parsing process to adapt to rapidly iterating document content. The precision requirements for fields such as network segments and ports mean chunking must not split individual key configuration items. Exported files from cloud platforms may have format compatibility issues, so the parsing process must adapt to non-standard document structures. The length of individual change ticket documents varies; some large topology documents have substantial content. Chunking parameters must be flexibly adjusted to avoid overly fine or overly coarse chunking results that reduce subsequent retrieval accuracy.

## How to set configurations
These configurations are written for FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale for This Setting |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the chapter length of cloud network configuration documents, avoiding splitting individual configuration items |
| `chunkSplitter` | Split by title + paragraph | Retains the chapter hierarchy of documents, improving context accuracy during retrieval |
| `customPdfParse` | Enabled | Adapts to PDF configuration files exported from cloud platforms, restoring table and chapter structures |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Accommodates batch configuration documents for single changes, adapting to large network topology files |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Prevents timeout during parsing of large documents, adapting to the processing duration of complex change tickets |
| `chunkSettingMode` | Manual mode | Flexibly adjusts chunking parameters for different types of network documents, adapting to diverse configuration formats |

## Three common errors
- Symptom: A 404 error is returned by the parsing node after uploading a file in the server environment, while the local environment operates normally. Cause: The static resource access path for server-side file uploads is not configured, so the parsing node cannot retrieve uploaded document files.
- Symptom: When deploying with Qwen3-14B, response fields cannot be extracted from PDF parsing results. Extraction works normally when using Qwen2.5-14B. Cause: `customPdfParse` optimization for parsing structure is not enabled, so the large language model cannot recognize structured configuration content.
- Symptom: RAG retrieval results only return body content, without chapter title information. Cause: The chunking configuration does not retain title hierarchies, only splitting paragraph content, leading to loss of context association.

## How to confirm configurations are correctly set
- Upload a standard load balancer configuration docx document, and check whether the parsed chunking results include chapter titles and corresponding configuration paragraphs.
- Upload a change ticket document of approximately 100 MB, and confirm that the parsing process does not trigger a timeout error, with the parsing status showing completed.
- Adjust the `chunkSize` parameter to different ranges, compare the content length after chunking, and verify that the parameter takes effect.
- Upload a PDF format configuration file exported from a cloud platform, and check whether the table and chapter structures are fully restored.

The values provided are common starting points and should be evaluated against the reader's own samples.
