# Drafting Requirements and Design Documents for Cloud Billing and Cost Accounting: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Data for this category typically originates from cloud billing systems, tag data, order systems, and resource monitoring tools. Daily produced documents include billing details, cost allocation tables, resource utilization reports, and optimization suggestion sheets. Billing details contain fields such as resource identifiers, billing items, settlement amounts, and usage duration. Units are mostly yuan and hours. Cost allocation tables mark allocation ratios and affiliated departments. Data update frequencies are divided into daily and monthly categories. Different documents use distinct update schedules.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
The diversity of data sources requires clear specification of the current data source type during multi-turn dialogue, to avoid confusion between field definitions across different systems. Differences in document structures require prompts to first confirm the current document type, then match corresponding field extraction rules. Differences in update frequencies require clear specification of the data time range during dialogue, such as daily bills or monthly allocation tables. The time-consuming nature of tag ownership verification requires multi-turn dialogue to gradually guide confirmation of the resource tag’s owning entity, to avoid confusion caused by inputting excessive information at once. Troubleshooting abnormal expenses relies on resource monitoring data. Prompts must guide users to provide specific characteristics and time ranges of abnormal bills.

## Configuration Settings
The following configurations are formulated for FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context window | 8000–12000 token | Covers the typical length of documents such as billing details and cost allocation tables, and fully loads historical dialogue and document content |
| Number of multi-turn history entries to retain | First 20 entries | Adapts to historical needs of multi-turn interactions such as tag verification and exception troubleshooting, and avoids context overflow |
| `variables` parameter configuration | Bind cloud billing field variables | Supports dynamic calling of preset fields such as billing items and resource identifiers, and simplifies prompt writing |
| Single reply token limit | 2000 token | Limits the length of single-round replies, to avoid response timeouts or redundant content |
| Question optimization switch | Calibrate based on actual testing | Optimizes question breakdown for cloud billing terminology, improving response speed and accuracy |
| `messages` parameter configuration | Retain system prompts and user historical interactions | Ensures consistency of context during multi-turn dialogue, and maintains prior document processing logic |
| `chatId` parameter configuration | Bind exclusive dialogue identifiers | Distinguishes dialogue contexts for different cloud billing projects, avoiding confusion between configurations of different projects |

## Three Common Configuration Mistakes
- The symptom is slow response to requests for explanations of cost allocation. The cause is failure to enable the question optimization switch, or failure to limit the number of document fragments processed in a single round.
- The symptom is lost context during multi-turn dialogue, making it impossible to continue the prior abnormal expense troubleshooting workflow. The cause is failure to correctly configure the number of multi-turn history entries to retain, or failure to enable the context association logic of the `messages` parameter.
- The symptom is preset cost accounting document templates not triggering when using dialogue opening shortcut buttons. The cause is failure to bind preset templates to shortcut buttons, or failure to load variables of the corresponding template in the prompt.

## How to Verify Correct Configuration
- A test request containing billing detail fields may be initiated, and correct extraction of preset fields such as resource identifiers and settlement amounts in the response may be confirmed.
- Consecutive multi-round interactions may be initiated, and historical dialogue content may be verified as correctly retained and used for subsequent tag ownership verification or exception troubleshooting requests.
- The preset dialogue opening shortcut button may be triggered, and loading of the template and variables for the corresponding cloud billing document may be confirmed.
- The configuration panel may be viewed, and configuration items such as the `variables` parameter and maximum context window may be verified as matching current business requirements.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
