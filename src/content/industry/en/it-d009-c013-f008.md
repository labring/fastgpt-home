# Requirements and Design Document Drafting for Cloud Billing and Cost Accounting: Workflow Orchestration

## What the data for this category looks like
The data for this category primarily comes from cloud billing systems, tag data, order systems, and resource monitoring tools. Regularly produced documents include billing details, cost allocation tables, resource utilization reports, and optimization suggestion sheets. Data fields cover resource identifiers, billing items, expense amounts, tag ownership, allocation ratios, and other relevant fields. Units include yuan, hours, percentages, and additional standard units. Data update frequencies are split into daily and monthly updates, with different report types matched to appropriate update schedules.

## What constraints these characteristics impose on workflow orchestration
The data sources for this category are scattered but closely interconnected. Workflow orchestration must support synchronization and verification logic across multiple data sources. This prevents cost allocation errors caused by inconsistent cross-system data. Different documents have distinct update frequencies. For example, billing details are updated daily, while annual cost reports are updated monthly. Workflows must therefore support trigger nodes configured for daily or monthly runs. Data fields include specialized financial fields such as billing items and allocation ratios. Workflows must bind corresponding variables to complete field mapping. They must also reserve branch nodes for abnormal expense troubleshooting. These nodes handle exceptions in time-consuming steps like tag ownership verification and abnormal expense identification, reducing the risk of billing disputes and resource waste.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Mode | Scheduled trigger by day / by month | Matches the update frequencies of billing details and cost allocation tables, and complies with the scheduled task rules of FastGPT v4.17.0 |
| Variable Binding | Bind resource ID, expense amount, and tag ownership fields in `variables` | Corresponds to the core fields of category data, and completes field mapping for requirements and design documents |
| Node Timeout | 600-1200 seconds | Covers time-consuming scenarios such as tag ownership verification and abnormal expense troubleshooting, preventing premature task termination |
| Abnormal Branch Trigger | Triggered by empty fields or abnormal HTTP status codes | Addresses data missing or system error situations, reducing the risk of billing disputes |
| Output Format | Generate HTML using a preset billing template | Adapts to the output requirements of requirement documents, ensuring content complies with financial document specifications |
| Tool Call Switch | Enabled only during the cost allocation phase | Reduces unnecessary API calls and optimizes workflow operation efficiency |

## Three Common Mistakes
- HTML output generated during workflow runs is not displayed, and the workflow proceeds directly to the next branch. This happens when format validation for the output node is not configured, or the HTML content field bound to `variables` is not correctly linked to the output node, causing the node to skip the rendering step.
- Workflows run at slow speeds. This occurs when a reasonable node timeout threshold is not set, or parallel processing is not used for multi-data source requests, leading to excessive time spent on steps such as tag ownership verification and abnormal expense troubleshooting.
- Knowledge base search input and response references remain visible after tool calls. This happens when the output log switch for the knowledge base search node in the workflow is not disabled, or reference markers are not filtered during document generation, leaving redundant content in the final output.

## How to Verify Proper Configuration
- Trigger the scheduled workflow, and check if the generated cost allocation table includes core fields such as the bound resource ID and expense amount.
- Simulate a data missing scenario, such as deleting tag data for a specific resource, and confirm whether the abnormal branch is triggered and a corresponding error prompt is generated.
- Run the tool call node, and check if the output HTML code matches the preset billing detail template format.
- Review the workflow run logs, confirm that the node timeout setting does not trigger unnecessary task interruptions, and that tool calls are only enabled in the specified phase.
