# Requirements and Design Document Drafting for Cloud Resource Compliance Audit: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data for this category comes from cloud audit logs, IAM systems, CMDB databases, and security baseline scan results, with an update frequency of monthly or quarterly. Daily produced documents include compliance checklists, permission audit reports, resource lists, and rectification tracking forms. The fields of each document cover resource ID, permission configuration items, compliance status, rectification responsible person, etc. There is no unified fixed unit, and it is necessary to match the resource identifiers and compliance item definitions of the corresponding cloud service provider.

## What constraints do these characteristics impose on the multi-turn dialogue and prompt engineering link
Data sources are scattered and require cross-system data pulling. Multi-turn dialogue must support batch calls to different data source interfaces to avoid overloading single requests. The update frequency is fixed as monthly or quarterly, so prompts must be adapted to batch data processing logic, and real-time result refresh should not be required. There is no unified standard for document fields, so multi-turn dialogue must support dynamic field mapping to avoid hard-coded field names. Processes such as resource inventory checking and permission anomaly identification take a long time, so dialogue must support context retention and breakpoint resumption to ensure task continuity across turns.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum context length | `8000–12000 characters` | Single batch data volume for cloud resource compliance audit is large, so it is necessary to accommodate resource lists, permission data and other content of multi-turn dialogues to avoid context overflow |
| Maximum single dialogue turns | `8–12 turns` | Cross-data-source pulling requires multiple rounds of confirmation of fields and data scope; too many turns will easily cause context confusion and affect the accuracy of compliance document generation |
| `variables` configuration | Bind cloud resource ID and compliance status fields | Daily documents need to be associated with specific resources and compliance items, so corresponding field variables must be dynamically passed in to ensure that the generated document fields match business requirements |
| `messages` context splicing rule | Splice historical dialogues in sequence according to conversation turns | Ensure that the context logic of multi-turn dialogues is coherent, which meets the step-by-step data pulling requirements of cloud resource compliance audit |
| Context recall count | `last 6–10 historical dialogues` | It is necessary to retain cross-turn data source pulling instructions and result feedback to avoid loss of key context |
| Prompt template update frequency | Updated quarterly | Match the monthly or quarterly update frequency of this category of data to ensure that the template is adapted to batch data processing logic |

## Three common mistakes
- The symptom is a `401 No auth credentials found` error. The cause is that the cloud service provider's access key variable is not configured in `variables`, making it impossible to pull data sources such as cloud audit logs.
- The symptom is missing or misaligned fields in the generated compliance documents. The cause is that the field variables of the corresponding cloud resources are not bound, and the prompt does not explicitly require mapping document fields to data source results.
- The symptom is lost multi-turn dialogue context. The cause is that no `chatId` persistent session identifier is specified, causing the context to reset each dialogue and making it impossible to continue cross-turn data source pulling tasks.

## How to confirm that the configuration is correct
- Initiate a test dialogue requesting to pull the resource list of a specified cloud account, and check whether the returned results include data source fields from CMDB and IAM.
- Initiate a multi-turn dialogue, call the data source interface 3–5 times consecutively, and check whether `chatId` remains consistent and whether the context continues the previous round's instructions and results.
- Check whether necessary variables related to cloud service provider access have been configured in `variables` to ensure no null values or incorrect configurations.
- Use the FastGPT v4.17.0 configuration interface to trigger a compliance document generation task, and check whether the generated content matches the preset document structures such as compliance checklists and permission audit reports.
