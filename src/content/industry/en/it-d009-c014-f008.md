# Requirements and Design Document Drafting for Cloud Resource Compliance Audit: Workflow Orchestration

## What the data for this category looks like
The data for this category is sourced from cloud audit logs, IAM permission systems, CMDB resource inventory libraries, and security baseline scanning tools.
Daily generated documents include compliance checklists, permission audit reports, resource inventory lists, and rectification tracking forms.
Included fields are resource unique identifiers, permission binding relationships, compliance baseline matching results, and rectification progress markers.
Data update frequency is monthly or quarterly.
Single batch data scale fluctuates with the scale of enterprise cloud resource deployment.
There is no fixed unified threshold.

## Constraints on workflow orchestration from these data characteristics
Data sources for this category are scattered and have inconsistent formats. Configure format conversion rules for multi-source data pull nodes during workflow orchestration.
Monthly or quarterly batch data updates have large scale. Limit the number of concurrent requests per node to avoid triggering cloud service API rate limits.
Document fields are closely related. Use the `variables` parameter to bind field mapping relationships in the workflow. This ensures field alignment for compliance checklists and permission audit reports.
Set time-consuming links such as resource inventory and permission identification as independent nodes. This prevents overall workflow timeout.
Bind the status flow of rectification tracking forms to the output of permission exception identification nodes. Configure dependency trigger rules between nodes.
Specify a unique `nodeId` for each independent node to facilitate subsequent debugging.
Reuse existing configurations by nesting calls to independent compliance check plugins.

## Configuration Settings
The following configurations reference the FastGPT v4.17.0 workflow orchestration interface.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Scheduled trigger cycle | Once per month | Matches the monthly data synchronization rhythm of this category |
| Batch request concurrency | 2-3 | Avoids exceeding rate limit thresholds of mainstream cloud service APIs |
| `variables` parameter configuration | Bind resource ID and compliance status fields | Ensures field alignment during multi-source data import |
| Node timeout duration | 600 seconds | Covers processing duration of time-consuming links such as resource inventory and permission identification |
| Node ID configuration | Specify a unique `nodeId` for each link node | Facilitates subsequent log correlation and process debugging |
| Log recording toggle | Enable full-node logging | Facilitates subsequent verification and traceability of rectification evidence |

## Three Common Configuration Mistakes
- Symptom: After nesting a compliance check plugin call, the main workflow does not record logs from the permission audit link. Cause: Log synchronization configuration for nested nodes is not enabled. Logs from cross-application calls are not synced to the main workflow.
- Symptom: When processing resource inventory in batches, the loop node terminates after executing a fixed number of times. Cause: The upper limit parameter of the loop node is not adjusted. The default upper limit restricts the processing scale of batch resources.
- Symptom: Some fields in the compliance checklist are empty after workflow execution. Cause: The `variables` parameter or `nodeId` is not configured correctly. The field mapping between source data and target documents does not take effect.

## How to Confirm the Configuration Is Correct
- Trigger a test execution. Check the output results of each workflow node. Confirm that the complete fields of the compliance checklist and permission audit report are included.
- Check the scheduled trigger configuration. Confirm that the trigger cycle matches the update rhythm of business data.
- View the log toggle for nested call nodes. Confirm that cross-node logs have been synced to the main workflow's log panel.
- Simulate batch resource input. Verify that the number of executions of the loop node covers all test resources.
