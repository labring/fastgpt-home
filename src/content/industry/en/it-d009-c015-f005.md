# Drafting Requirements and Design Documents for Product Usage Data Analysis: Multi-turn Dialogues and Prompt Words

## What Data for This Category Looks Like
Data for this category primarily comes from tracking systems, data warehouses, CRM systems, and ticket systems. Most updates run on a daily or weekly schedule. Daily output documents include usage analysis reports, tracking plans, indicator definition tables, and dashboard requirement sheets.
Common data fields include user identifiers, function modules, access duration, operation counts, and customer tiers. Some associated data includes business units: for example, access duration is measured in minutes, and stored data is measured in GB.
There are notable structural differences across document types. Indicator definition tables require unified field definitions. Tracking plans need clear collection rules. Dashboard requirement sheets must specify display dimensions.

## How These Characteristics Impact Multi-turn Dialogues and Prompt Words
The diversity of fields from multi-source data collection requires prompt words for multi-turn dialogues to clearly distinguish field definitions across different data sources. This avoids confusion over indicator definitions.
The daily or weekly update rhythm requires `variables` used in dialogues to support caching global default values per update cycle. This prevents repeated pulls of basic indicator definitions during each dialogue.
Significant structural differences across documents require prompt words to adapt to format requirements for different document types. For example, when processing tracking plans, clarify the priority of collection rules. When processing dashboard requirement sheets, specify constraints for display dimensions.
The need for cross-customer behavior insights also requires `messages` to retain dialogue context. This associates layered data across different customers, avoiding analysis bias caused by lost context.

## Configuration Settings
This configuration is based on FastGPT v4.17.0. Specific configuration items and their rationales are listed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `messages` context retention count | First 10-15 dialogue turns | Adapts to context association needs for multi-turn analysis, avoids excessive computational load from overly long context |
| `variables` global cache switch and cycle | Enabled, set cache cycle to 7 days | Matches daily/weekly data update frequencies, reduces repeated pulls of basic data such as indicator definitions |
| `chatId` session binding rule | Bind to corresponding customer analysis tasks | Ensures isolation of analysis contexts across different customers, avoids confusion between cross-customer data |
| Single knowledge base retrieval limit | Top 8 matching results | Adapts to the number of fields from multi-source data, avoids redundant information interfering with analysis logic |
| Prompt template length | 800-1200 characters | Adapts to differences in document structures, ensures coverage of requirements for different document types such as tracking plans and indicator definition tables |

## Three Common Misconfigurations
- Issue: An error occurs when setting `variables`, and preset parameters cannot be passed normally. Cause: The variable scope was not configured correctly, so the variable is not bound to the current dialogue context.
- Issue: Global variables reset after the dialogue ends, and preset values cannot be retained. Cause: The `variables` global cache switch was not enabled, or the cache cycle was set too short, so variables are cleared after the dialogue ends.
- Issue: Knowledge base retrieval sometimes triggers and sometimes does not, or response speed slows after multiple dialogue turns. Cause: The number of retained `messages` context entries was not limited, leading to overly long context, or retrieval trigger conditions were not explicitly set, so prompt words do not enforce association with knowledge base data.

## How to Verify Successful Configuration
- Pass preset `variables` parameters, and check that the interface variable panel displays correct values with no error prompts.
- Launch multiple related dialogue turns, and check that each response associates with indicator definitions or tracking data from the knowledge base.
- Wait for one full data update cycle, then launch a dialogue again, and check that global `variables` retain the default values set in the previous session.
- Launch more than 10 consecutive dialogue turns, and check that response speed remains stable with no obvious timeouts.

The values provided here are common starting points and should be evaluated against the reader's own samples.
