# Requirements and Design Document Drafting for Code Review and Merge Management: Context and Token

## What the data for this category looks like
This category's data originates from Git repositories, CI pipelines, static scanning reports, and defect repositories. Update frequency is daily or after each code commit. Core documents include merge requests, code review comments, commit records, and branch strategy descriptions. Merge requests contain a list of changed files, commit hashes, a reviewer list, and change descriptions. Commit records include commit messages, change timestamps, and author information. Static scanning reports include code violations and their severity levels. Data structure updates in real time with each commit. The volume of associated data for a single change varies based on project scale.

## What constraints these characteristics impose on the context and token workflow
Multi-source heterogeneous data requires association and matching. The context must cover code changes, review comments, and scanning results simultaneously. Token consumption increases with the volume of associated data. Real-time updates for each commit require the context to load the latest data quickly. An overly long context can cause processing timeouts. The scope of changes in merge requests varies widely. Small changes require only a small amount of associated data, while large changes need more context. Irrelevant data must be prevented from occupying token quotas. Review comments and commit records have a strong association. The context must retain this association, otherwise deviations will occur in change judgment.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Calibrated via actual testing to fit the total token volume of change records and review comments associated with merge requests in code review scenarios |
| `quoteMaxToken` | 2000 token | Limits the maximum truncated length of a single review comment or commit record, prevents a single entry from occupying excessive context quota |
| Chunk Length | 1500 characters | Fits the typical content length of Git commit records and review comments, balances context completeness and token consumption |
| Overlap Length | 200 characters | Retains contextual association between chunks, prevents key change descriptions from being truncated |
| Single Recall Limit | Top 6 associated records | Matches the core change sources of merge requests, reduces irrelevant data occupying token quota |
| Compatible Version | FastGPT v4.17.0 | Fits the context processing logic of the current version, ensures configuration takes effect |

## Three Common Misconfigurations
- An "invalid api key" or "endpoint not found" error may be returned during calls. Troubleshooting includes verifying incorrect configuration of `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service) or `AIPROXY_API_TOKEN` (AI Proxy admin token). Issues include extra spaces in variable values, format errors, or using the AI Proxy admin token as the application API key. Missing required variables will cause startup verification failures.
- A token exhaustion error may occur when processing merge requests. The cause is failure to limit the value of `maxContext`, resulting in full Git repository history or unrelated commit records being included in the context.
- Timeouts or truncated results may occur when processing large review comment documents. The cause is an excessively large chunk length, leading to single-chunk token consumption exceeding system thresholds.

## How to Confirm Configuration Is Successful
- System runtime logs can be checked to confirm that token consumption during context calls falls within the range set by the `maxContext` configuration, with no abnormal overflow.
- A test merge request can be submitted to verify that associated change records and review comments are correctly truncated and recalled, with no redundancy or loss of critical information.
- The loading status of server environment variables `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service) and `AIPROXY_API_TOKEN` (AI Proxy admin token) can be verified to confirm no format errors and that the variables have taken effect.
- A complete code review process can be triggered to check that the returned change impact judgment results include core change information and meet expectations.

The values provided are common starting points and should be measured against the reader's own samples.
