# Requirements and Design Document Drafting for Code Review and Merge Management: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Looks Like
This category of data primarily originates from team Git repositories, CI pipelines, static code scanning reports, and defect tracking repositories. Core daily documents include merge requests, code review comments, commit records, and branch strategy descriptions. Each data entry includes fields such as changed code snippets, reviewer feedback, commit time, associated branch information, and more. Data updates are triggered by code commits, typically occurring daily or per commit cycle. Document structures vary slightly across different projects; some projects additionally associate test cases and deployment records.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering by These Characteristics
Since data is updated frequently alongside code commits, multi-turn dialogue must limit the effective duration of context history to avoid loading outdated review records and change data. Document structures vary slightly across different projects, so prompt engineering must adapt to extraction logic for different fields such as merge requests and review comments; generic templates cannot be directly applied. Data sources are tied to Git repositories and CI pipelines, so dialogue must associate context with specific projects to prevent cross-project data confusion. Additionally, change impact assessment and conflict resolution are core time-consuming steps, so multi-turn dialogue prompt engineering must focus on code change scope and review comment conflict points to avoid interference from irrelevant content.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Context history count limit | Top 20 entries | Matches the high-frequency update characteristic of code review data, avoids loading outdated review records and change data |
| `messages` array length limit | 1000–1500 characters | Matches the typical content scale of merge request documents, prevents dialogue context overflow |
| `chatId` binding rule | Bind to a single Git repository | Prevents cross-project data confusion, aligns with the binding characteristic of data sources for this category |
| Dialogue authentication switch | Enabled | Protects the privacy of merge requests and review records, meets permission requirements of development teams |
| Knowledge base reference switch | Disabled per project | Avoids introducing irrelevant knowledge base content, focuses on native data for code review and merge management |
| `variables` injection rule | Inject current repository branch information | Adapts to document characteristics of branch strategy descriptions, helps prompt engineering accurately locate change scope |

## Three Common Misconfigurations
- Symptom: Outdated merge request review records load in dialogue, affecting impact assessment for current changes. Cause: No context history cleanup rule configured, causing old `messages` data to load continuously.
- Symptom: Dialogue links can be accessed by unauthorized personnel, leaking sensitive content of merge requests. Cause: Dialogue authentication switch not enabled, no access permission verification configured.
- Symptom: Irrelevant knowledge base content appears in dialogue results, interfering with code change scope assessment. Cause: Knowledge base reference switch not disabled, or `variables` not correctly configured to limit context to the current project.

## How to Verify Proper Configuration
- Initiate a simulated code review dialogue, confirm that loaded context only includes merge requests and review records for the current project, with no cross-project data.
- Test access permissions for the dialogue link, confirm that unauthorized users cannot view dialogue content.
- Check that dialogue results do not include irrelevant knowledge base content, and only focus on information related to code review.
- Trigger multiple code commits, confirm that dialogue context automatically cleans up outdated historical records, retaining only content within the valid scope.
