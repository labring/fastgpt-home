# Requirements and Design Document Drafting for Code Review and Merge Management: Forms and Interactions

This document is compatible with FastGPT v4.17.0.

## What this category of data looks like
Data for this category primarily comes from Git repositories, CI pipelines, static scanning reports, and defect databases. Daily produced documents include merge requests, code review comments, commit records, and branch policy descriptions. Data updates occur daily or upon each code commit. Typical fields include source and target branch names, commit hashes, reviewer lists, changed file lists, review comment entries, and associated defect IDs. There are no unified fixed units; units adapt to individual field properties.

## What constraints these characteristics impose on forms and interactions
Git repository branch data is updated in real time. Branch selection options must pull the latest branch list via external systems or subsequent workflow interfaces to avoid selecting deleted or non-existent branches. Commit records and review comments associated with merge requests iterate alongside the review process. The logic for dynamically appending review comment fields and associating them with commit hashes must be implemented by external business systems or subsequent workflows. Static scanning report results are automatically synced to the defect prompt area. Data pulling and rendering capabilities must be implemented by external business systems or subsequent workflows. Fields for branch policy descriptions must follow team specifications. Restrictions on the association logic of input content must be implemented by external business systems or subsequent workflows to avoid non-compliant configurations. For multi-reviewer scenarios, batch assignment of review tasks and real-time synchronization of review status logic must be implemented by external business systems or subsequent workflows.

## Three common mistakes
- Phenomenon: When invoking a published workflow via API, no interaction popup for the `formInput` or `userSelect` component appears. Cause: External systems or subsequent workflows did not correctly return interaction instructions, causing FastGPT to fail to trigger the popup.
- Phenomenon: Deleted invalid branches appear in the branch selection dropdown list. Cause: External systems or subsequent workflows did not correctly pull real-time Git repository branch data, using only static cached data leading to data desynchronization.
- Phenomenon: Review comments cannot be associated with the corresponding commit hash. Cause: External systems or subsequent workflows did not correctly configure the data binding logic between the commit hash field and the review comment input box, causing commit record data to fail to sync to the review form.

## How to confirm correct configuration
- Trigger the Git repository branch pull action via external systems or subsequent workflows, check whether the branch selection dropdown list includes currently existing valid branches.
- Call the API interface to confirm that the returned content includes configuration information for the `formInput` or `userSelect` component.
- Submit a test review comment, check whether it can correctly associate with the corresponding commit hash.
- Configure the CI status refresh interval via external systems or subsequent workflows, wait for the CI pipeline to complete execution, and check whether the form automatically updates its status.
