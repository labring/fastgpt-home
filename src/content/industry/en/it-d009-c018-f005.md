# Requirements and Design Document Drafting for Enterprise Software License Management: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Data for this category comes from software asset management systems, procurement systems, terminal scan results, and vendor authorization documents. Update frequency is monthly or quarterly.
Daily produced documents include license ledgers, software usage lists, procurement contracts, and compliance audit reports. Fields cover software name, authorized quantity, installed node count, authorization validity period, vendor information, and more.
Units are mostly units, sets, and calendar days. No additional statistical percentage data is included.

## What Constraints Do These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering
Decentralized data sources require multi-turn dialogue to first integrate fields across different systems. For example, match installed lists from terminal scans with authorization ledgers from procurement systems. This prevents discrepancies between authorized and installed quantities.
Low update frequency means dialogue must support long-term calls to historical data. No frequent data source refreshes are needed. Therefore, limit the length of the `messages` array in multi-turn dialogue. This stops redundant data from occupying model context.
Diverse document types require prompts to distinguish field requirements for different scenarios. Scenarios include ledger verification, over-installation identification, renewal reminders, and more. Each dialogue only processes the business logic of the current scenario.
Fields include precise numerical values such as authorized quantity and installed node count. Prompts must strictly limit units and verification logic. This avoids confusing authorized and installed quantities. It also adapts to the most time-consuming business links, including authorized quantity verification and over-installation identification.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Only bind license ledger fields for the current session | Based on decentralized data sources, limit variables to call only business data associated with the current session. This avoids interference from unrelated fields |
| Maximum context per dialogue | First 8 turns of historical dialogue + current prompt | Based on the monthly update frequency of license management documents, historical dialogue does not need to be too long. This prevents exceeding the model's supported context length |
| Question optimization switch | Enabled | Based on the need to clarify discrepancies multiple times for authorized quantity verification, optimized prompts can more accurately extract verification logic. This reduces invalid output |
| Maximum search times per query | Top 5 matching documents | Based on compliance audit reports needing priority access to the latest authorization files. This avoids excessive old data interfering with core verification results |
| Maximum response tokens | Calibrated based on actual testing | Based on differences in output length across scenarios. Renewal reminders only require short prompts, while over-installation identification needs detailed difference listings |
| `chatId` | Bind current session ID | Based on the need for multi-turn dialogue to maintain session consistency. This ensures verification logic for different scenarios only takes effect within the current session |

## Three Common Misconfigurations
- Symptom: Knowledge base responses are truncated, only partial authorization verification results are output. Cause: Maximum context per dialogue is not configured correctly. Splicing historical dialogue and current prompt exceeds the model's supported context length.
- Symptom: A 500 error is triggered when importing compliance audit reports. Cause: The binding scope of `variables` is not limited correctly. Attempting to call data fields from unauthorized external systems causes data parsing failure.
- Symptom: Multi-turn authorization quantity verification outputs irrelevant historical dialogue content. Cause: The question optimization switch is not enabled. The prompt does not limit only the core verification logic of the current session.

## How to Verify Successful Configuration
- Manually enter a prompt for the over-installation identification scenario. Check if the output only includes the difference between installed software count and authorized count associated with the current session.
- Initiate a dialogue related to renewal expiration reminders. Confirm the output only includes software names and validity periods that are pending renewal in the current session.
- View the dialogue log. Confirm that only the first 8 turns of historical dialogue are retained, with no redundant data loaded.
- Import different types of business documents. Confirm that only business fields for the current session are bound, with no unrelated data called.
