# Drafting Requirements and Design Documents for Enterprise Software License Management: Workflow Orchestration

## What Data for This Category Looks Like
Core data for this category comes from software asset management systems, procurement systems, terminal scan results, and vendor authorization documents. Key daily deliverables include license ledgers, software usage lists, procurement contracts, and compliance audit reports.
Data is updated monthly or quarterly. Fields include software name, authorization type, authorized quantity, installed terminal count, expiration date, vendor information, and more. Fields must match the measurement standards of the corresponding vendor; there is no unified mandatory unit.

## What Constraints Do These Characteristics Impose on Workflow Orchestration
Decentralized data sources require workflows to be configured with cross-system integration nodes to pull stock data from multiple sources. Low update frequencies require workflow trigger mechanisms to support scheduled batch synchronization, which fits non-real-time batch processing scenarios.
Document fields must strictly match the measurement rules set by vendor authorizations to avoid field mapping errors. Compliance audit documents require complete traceability nodes in the workflow to ensure auditability for future reviews.
The authorization quantity verification link takes up a large share of total time. Workflows must include built-in automatic verification nodes to reduce manual intervention steps.

## Configuration Settings
| Configuration Item | Recommended Practice | Basis for This Practice |
| --- | --- | --- |
| Global variable binding | Associate with license ledger and software usage list data sources | Aligns with FastGPT v4.17.0 global variable calling rules, directly calls stock data based on core data sources of this category |
| Scheduled trigger configuration | Execute every 30 days | Matches the monthly data update frequency of this category, reduces invalid run times |
| Knowledge base association node | Bind to the dedicated knowledge base for compliance audit reports | Meets document calling requirements for the compliance verification link |
| `variables` parameter configuration | Pass dynamic knowledge base ID | Supports workflows in calling a specified compliance knowledge base, adapts to multiple audit scenarios |
| `nodeId` configuration | Set as the unique identifier of the authorization verification node | Ensures no conflicts in workflow node calls, avoids link interruptions |
| File upload size limit | No more than 100 MB | Matches typical size ranges of vendor authorization documents, avoids storage overload |
| Authorization verification threshold | Maximum 100 records per single verification | Matches data update scale of this category, avoids overload during single processing |

## Three Common Misconfigurations
- Workflows return no matching documents when calling a knowledge base, and the interface shows the knowledge base ID field is empty. The cause is failure to pass the dynamic knowledge base ID via the `variables` parameter; only the global variable was bound, but the parameter was not referenced in the workflow node.
- After configuring a document upload trigger node, subsequent analysis processes cannot be triggered. The cause is failure to limit the file format range, so uploads of non-vendor authorization documents or compliance audit reports do not trigger node startup.
- Authorization quantity verification errors occur after workflow execution, with results that do not match the actual ledger. The cause is failure to match vendor authorization measurement fields, using default fields from the software asset management system directly for verification, leading to mismatched units or counting rules.

## How to Confirm the Configuration Is Correct
- Manually trigger the workflow once, check whether the license ledger data source fields are correctly loaded in the run logs.
- Pass a preset test knowledge base ID, verify whether the workflow can call document content from the corresponding knowledge base.
- Upload a simulated vendor authorization document, confirm whether the workflow triggers the subsequent verification node.
- Check the scheduled trigger configuration, confirm that the system will automatically start the workflow according to the set monthly cycle.
