# Requirements and Design Document Drafting for Enterprise Software License Management: Document Parsing and Chunking

## What the data for this category looks like
Data sources for this category include software asset management systems, procurement systems, terminal scanning tools, and vendor authorization documents. Regularly processed documents include license ledgers, software usage lists, procurement contracts, and compliance audit reports. Update frequency is monthly or quarterly. Most document structures include fields such as authorization number, number of compatible devices, validity period, and vendor name. Units include set, unit, day, and other relevant units.

## Constraints on the document parsing and chunking process
This category’s data sources include structured ledgers, unstructured contracts, and audit reports. Document formats vary widely across different sources. Parsing tools must support multi-format input. Monthly or quarterly update cycles create demand for batch document processing. The chunking process must support processing multiple identical-type documents in a single run. Documents include highly compliance-related fields such as authorization quantity and validity period. During chunking, associations between fields must be preserved. Key compliance information must not be split across fields. Parsed data must be matched to the corresponding authorization subject to avoid association errors.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the length of authorization entries and contract clauses in documents of this category, avoids splitting single authorization information |
| `chunkSplitter` | Separate by paragraph + heading | Matches the entry structure of license ledgers and chapter divisions of contracts, preserves content logic |
| `customPdfParse` | Enabled | Adapts to the PDF format of vendor authorization documents, preserves structured information of form fields |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch upload of quarterly compliance audit reports and large-volume contract files |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Prevents parsing timeouts for large-volume contracts or multi-page ledgers |
| `chunkSettingMode` | Manual configuration | Adapts to the fixed structure of documents in this category, no need for automatic adaptation to general scenarios |

## Three Common Errors
- Phenomenon: After passing in a vendor authorization document link, the parsing result is empty or only returns page metadata. Cause: Web parsing adaptation for `customPdfParse` is not enabled, or the document linked does not have direct crawling permissions enabled.
- Phenomenon: A single authorization information entry is split into two chunks, leading to omissions in subsequent compliance checks. Cause: The value of `chunkSize` is too small, or `chunkSplitter` is not configured to separate by entry headings.
- Phenomenon: After locally split documents are uploaded to the server, the results do not match the server’s vector model recall results, or Markdown formatting is not rendered correctly in context references. Cause: Chunking configuration does not match the server, or parsing steps removed text formatting markers.

## How to Confirm Proper Configuration
- Upload a single license ledger document, check if parsed chunks fully retain all field information for a single authorization entry.
- Upload a batch of quarterly audit reports, confirm that parsing time does not exceed the configured timeout threshold.
- Pass in a vendor authorization document link, verify that the parsing result includes core fields such as authorization number and validity period.
- Compare local and server chunking configuration parameters, ensure values for core configuration items are consistent.

The values provided are common starting points and should be evaluated against the reader’s own samples.
