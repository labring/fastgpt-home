# Drafting Requirements and Design Documents for Crowdsourced Annotator Management: Context and Token

## What the Data for This Category Looks Like
Core data for crowdsourced annotator management comes from crowdsourcing platforms, annotation quality data, training exam records, and financial systems. Daily associated documents include personnel access rules, training materials, performance sheets, and settlement lists. Most data is updated daily or monthly. This category focuses on workforce organization and performance settlement. Data includes structured personnel performance and financial settlement entries, plus unstructured training and rule text. The most time-consuming steps are personnel screening, quality ranking, and settlement verification.

## How These Characteristics Impose Constraints on Context and Token Handling
This category has diverse data types. It includes structured performance and settlement entries, plus long-form rule and training materials. Document lengths vary widely. The daily or monthly data update rhythm requires context caching to align with update schedules, to avoid using expired personnel performance or settlement data. The most time-consuming screening, ranking, and settlement verification steps rely on complete context information. Incorrect token configuration may truncate critical access conditions, performance scores, or settlement amounts, leading to quality fluctuations, incorrect or missed payments, or project delays. Unlike text annotation projects, this category’s context must cover multiple document types, which places higher demands on total token volume and single reference length.

## How to Configure the Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Maximum context token count | 8000–12000 token | Must cover the total length of personnel access rules, training materials, multiple performance sheets, and settlement lists, to avoid truncating core management information |
| `quoteMaxToken` | 1500–2000 token as an untested configuration example | This is the total token budget for cited knowledge-base content, not a separate length limit for each sheet or citation |
| Single search reference limit | Top 6 entries | Corresponds to the number of personnel screening and quality ranking data entries that need daily synchronization, to avoid context overload |
| External business-cache policy | 24 hours as a test example, adjusted to actual update needs | If an integration caches business results, implement expiration and invalidation there; this is not a native FastGPT context-cache duration switch |
| `maxContext` | Calibrated via actual testing | Adapts to the personnel scale and total document volume of different projects, to avoid exceeding the model’s context window limit |

## Three Common Mistakes
- Observation: After setting `quoteMaxToken` to 2000, settlement list content returned by search is truncated, exceeding the set token limit. Check the total citation token budget, the retrieved chunks, and the model window. The total citation budget is not the chunk length of an individual document.
- Observation: Conversation context is lost, and continuous conversations cannot be resumed. Check the conversation history actually sent in the request, retrieved content, and total token usage separately. `maxContext` is the LLM maximum context length; it does not automatically store or restore a conversation.
- Observation: Entered personnel access rule text is forcibly split. Inspect the actual import and chunking settings in the deployed version, then compare parsed records with the source. Do not assume a universal automatic-chunking switch exists.

## How to Verify the Configuration Is Correct
- Import a single settlement list, search in the knowledge base, and check that referenced content is fully displayed with no truncation prompts.
- Initiate a continuous conversation, verify that historical interaction content and associated personnel management document fragments are correctly included in the current context.
- Import the full text of personnel access rules, confirm that no paragraph breaks occur due to automatic splitting.
- Check the knowledge base dataset in FastGPT v4.17.0 to confirm the target text is not forcibly split.
- If an external business cache is used, verify its invalidation policy and test whether retrieval obtains current content after a source record changes.

The values provided are common starting points and should be measured against the reader's own samples.
