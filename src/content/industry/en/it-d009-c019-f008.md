# Drafting Requirements and Design Documents for Crowdsourced Annotator Management: Workflow Orchestration

## What Data for This Category Looks Like
Data for this category primarily comes from crowdsourcing platform backends, annotation quality spot-check records, annotator training exam results, and enterprise financial settlement systems. Data update frequencies are divided into daily and monthly updates.
Daily update data includes same-day annotation quality feedback and real-time staff attendance status. Monthly update data includes monthly performance rankings and settlement lists.
Daily produced documents include staff access rules, standardized training materials, monthly performance reports, and settlement details. Fields covered include unique staff identifier, review status, training exam score, task completion volume, compliance rating, settlement amount, and more.

## What Constraints Do These Characteristics Impose on Workflow Orchestration
Decentralized data sources require workflows to configure cross-system data pull nodes, connecting different data sources from crowdsourcing platforms, quality systems, and financial systems.
Differing update frequencies require workflows to distinguish scheduled trigger cycles: set daily synchronization for annotation quality data, and monthly triggers for performance calculation and settlement processes.
Multiple document types require workflows to adapt to different node logic, such as access rule review nodes, training result verification nodes, and performance calculation nodes.
Errors can cause quality fluctuations or settlement mistakes, so data verification steps must be configured at key links to prevent abnormal data from entering subsequent processes.

## How to Set Configurations
These configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Include unique staff identifier, settlement cycle, qualified quality inspection score | Cover core business fields of crowdsourced annotation management, enabling precise association and transfer of cross-system data |
| `nodeId` | Assign values by node function category, e.g., access review node is node_001, performance calculation node is node_002 | Facilitate workflow debugging and abnormal node location, matching the orchestration logic of multi-link parallel or serial operations |
| Data verification switch | Enable quality data verification and settlement amount verification | Prevent unqualified annotation data or abnormal settlement values from entering subsequent processes, reducing error risks |
| Scheduled trigger cycle | Daily level (synchronize every 600 seconds), monthly level (trigger on the last working day of each month) | Match the daily and monthly update frequencies of data, ensuring timely data synchronization |
| Settlement trigger condition | Trigger when quality inspection pass rate ≥ 90% and performance meets standards | Align with business settlement rules, ensuring only eligible staff enter the settlement process |

## Three Common Mistakes
- Issue: When creating a workflow via API, node configuration cannot be saved, and status code 400 is returned. Cause: Required business fields of the `variables` parameter were not passed correctly, causing workflow node verification to fail.
- Issue: In code running nodes, the dropdown menu does not display configured knowledge base references, and the variable field is empty. Cause: The `variables` parameter associated with the knowledge base was not bound in the global workflow configuration, causing the node to fail to read the corresponding resource.
- Issue: When configuring question classification for a large number of annotation knowledge points, the trigger node returns no matching results, with a result count of 0. Cause: Question classification nodes were not split according to business scenarios, leading to incomplete coverage of classification rules and inability to match user input.

## How to Confirm the Configuration Is Complete
- Trigger the scheduled synchronization task, check whether cross-system pulled data matches the latest records of the data source.
- Manually trigger the settlement node, verify that only staff meeting preset conditions enter the settlement process.
- View workflow logs, confirm that the `variables` parameter is passed in the correct format with no missing fields.
- Simulate abnormal data input, verify that the data verification node can intercept non-compliant content.
