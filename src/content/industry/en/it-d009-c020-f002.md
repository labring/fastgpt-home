# Requirements and Design Document Drafting for Supplier and Equipment Delivery Management: Context and Token

## What this category of data looks like
Daily documents for supplier and equipment delivery management include purchase orders, delivery acceptance forms, serial number lists, and invoice materials. Data sources cover ERP systems, supplier shipping documents, logistics information platforms, and equipment manufacturer backends. Within a single project execution cycle, data is updated per order. Latest logistics and acceptance information is also synchronized weekly. Document fields include purchase order number, equipment model, serial number, supplier name, delivery date, acceptance result, and other relevant fields. Units are typically physical measurement units such as sets, pieces, and individual units.

## Constraints on context and token processing
Multi-source heterogeneous data sources require context integration of formats and fields across different systems. Core identifiers such as equipment models and serial numbers must be matched precisely to avoid cross-system data misalignment. The weekly or per-order update rhythm requires context processing timeliness to align with business circulation cycles. Expired logistics or acceptance data must not be used. Many document fields are strongly bound to physical objects, so context recall must prioritize retaining core business fields. Failure to do so may lead to equipment mismatches, project delays, and other issues. The total token count of a single document must fit the model's context window to prevent inference failure from token overflow.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Maximum Context | 8000–12000 token | Adapts to the total token length of multiple documents (purchase orders, acceptance forms, etc.) under a single project, and aligns with the default window range of FastGPT v4.17.0 |
| `maxContext` | 8000–12000 token | Limits the total token upper limit of global context to prevent inference timeout caused by overly long model input |
| `quoteMaxToken` | 2000–3000 token | Restricts the token upper limit of a single quoted document, prioritizes retaining core business fields such as equipment model and serial number |
| Single Recall Upper Limit | Top 6 entries | Matches the number of suppliers and equipment involved in a single project, avoids redundant data occupying context space |
| Context Recall Threshold | Calibrated via actual testing | Adapts to field matching accuracy of multi-source data such as ERP and logistics information, ensures relevance of recalled data |
| Question Optimization Switch | Enabled | Optimizes context extraction logic for professional documents such as procurement and acceptance, improves recall accuracy of core fields |

## Three common configuration mistakes
- The interface shows the v2 model version is selected, but call logs show old version token quota is still consumed. The cause is that the model version is only configured in the global config, and the specified model is not bound in the context configuration of the corresponding knowledge base.
- Enabling knowledge base search and question optimization functions results in platform deduction fees, even if a custom openapi token has been set. The cause is that the call links of these two functions are not bound to the custom token, and the platform's default billing token is still used.
- A token overflow error occurs when processing context containing multiple serial number lists. The cause is that the `quoteMaxToken` parameter is not set to limit the token upper limit of a single quoted document, resulting in truncation of core business fields.

## How to verify proper configuration
- Log in to the FastGPT v4.17.0 backend, enter the context configuration page of the corresponding knowledge base, confirm that the values of `maxContext` and `quoteMaxToken` match the preset configuration.
- Call the openapi interface to test the knowledge base search function, check whether the token in the request header matches the custom configured token, and view the token consumption statistics in the return result.
- Upload a single purchase order and delivery acceptance form, verify that the recalled context fields include core business information such as equipment model and serial number.
- In the intranet deployment environment, check system logs to confirm that the oneapi process has not restarted, and that context processing time meets expectations.

The values provided here are common starting points and should be measured against the reader's own samples.
