# Requirements and Design Document Drafting for Supplier and Equipment Arrival Management: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
This category of data typically comes from ERP systems, supplier shipping invoices, logistics tracking information, and equipment manufacturer backends. The core documents produced daily include purchase orders, arrival acceptance forms, serial number lists, and invoice materials. The fields of each document cover supplier numbers, equipment models, purchase quantities, arrival dates, equipment serial numbers, acceptance status, and more. Data updates follow a single-project cycle: single purchases or weekly synchronization of logistics and acceptance information. The character count of a single core document typically ranges from hundreds to thousands.

## Constraints imposed by these characteristics on multi-turn dialogue and prompt engineering
There are significant differences in data formats across sources. Purchase orders exported from ERP are mostly structured tables, while supplier shipping invoices may contain non-standard remark fields. This requires multi-turn dialogue to first identify the data source type corresponding to the current interaction, then call the corresponding field extraction rules. The update rhythm of single-project data requires dialogue to support on-demand data pulling, to avoid using expired arrival or serial number information. The existence of multiple associated documents requires dialogue context to track the currently processed document type and associated project ID, preventing cross-order data confusion. The strong associative attribute between equipment models and serial numbers requires prompts to clarify field matching logic, reducing mismatch risks.

## How to configure settings
The following configurations are based on FastGPT v4.17.0, and are adapted for the requirements and design document drafting scenario for supplier and equipment arrival management:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind the current project ID as a fixed value | Ensure multi-turn dialogue context for the same project does not share across orders, complying with single-project data isolation rules |
| `messages` | Retain the first 10 dialogue context entries | Cover the full process interaction from purchase order placement to arrival acceptance for a single project, avoiding loss of critical context |
| `variables` | Preset three core variables: supplier number, equipment model, project ID | Quickly call structured data from the corresponding data source, reducing repeated input and field errors |
| Maximum context length | 800–1200 characters | Adapt to the core field length of a single purchase order or acceptance form, avoiding interaction interruptions caused by context overflow |
| Single dialogue data pull limit | Top 5 matching records | Control the amount of data returned per dialogue round, preventing interface loading overload and information chaos |
| Timeout threshold | 60 seconds | Adapt to the standard response duration of ERP and logistics interfaces, avoiding dialogue interruptions caused by waiting for external data timeouts |

## Three common misconfigurations
- A 401 No auth credentials found error is returned during dialogue. The cause is that correct authorization parameters are not configured in the external data node, leading to permission verification failure when multi-turn dialogue calls ERP or supplier interfaces.
- Clickable downloadable BLOB format document links cannot be generated in dialogue. The cause is that the document storage path variable is not configured in `variables`, and the BLOB object is not mapped to a downloadable file field.
- The equipment model referenced by the knowledge base does not match the actual arrival model. The cause is that the field rules for associating project IDs and corresponding documents are not clarified in the prompt, leading to the context calling expired purchase order data.

## How to verify configurations are correctly set
- Initiate a test dialogue containing the specified project ID, check whether the context automatically associates the field data of the corresponding purchase order.
- Call the ERP interface to pull purchase order data, confirm that the returned result has no 401 error, and the fields match the preset variables.
- Generate an arrival acceptance form file in BLOB format, check whether a clickable download link appears in the dialogue interface.
- Switch the document type in the dialogue, verify that the context is correctly updated to the currently processed document field extraction rules.
