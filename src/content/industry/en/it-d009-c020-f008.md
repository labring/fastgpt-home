# Drafting Requirements and Design Documents for Supplier and Equipment Arrival Management: Workflow Orchestration

## What the data for this category looks like
Data for this category primarily comes from ERP systems, supplier shipping documents, logistics tracking information, and equipment manufacturer backends. Daily produced documents include purchase orders, arrival acceptance forms, serial number lists, and invoice materials. Purchase orders contain fields such as supplier number, equipment model, purchase quantity, and agreed arrival date. The serial number list records the association between unique equipment identifiers and corresponding purchase items. Data updates follow a per-order cycle, with some bulk procurement projects synchronized weekly.

## What constraints these characteristics impose on the "workflow orchestration" link
Dispersed data sources require the workflow to connect multiple external data source nodes. Corresponding input rules must be configured to adapt to different formats of shipping documents and logistics information. Cross-document field association requires binding `variables` to enable field linkage between purchase orders, serial number lists, and acceptance forms, to avoid manual entry errors. Data update cycles vary flexibly per order. Startup rules triggered by individual order submissions must be set up. Some bulk projects need to adapt to weekly synchronization logic. The requirement for unique device serial numbers requires adding a verification link in the workflow to block duplicate or mismatched identifier information, preventing equipment mismatches or inconsistencies between book records and actual assets.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| ---|---|--- |
| `variables` | Bind three core fields: purchase order ID, equipment SN code, and project number | Match the cross-document field association requirements of this category, enabling multi-document data linkage |
| Trigger Node Settings | Trigger per individual order submission, support weekly batch task triggering | Adapt to the update frequency of individual orders or weekly cycles for this category, align with business execution rhythm |
| Input Node Configuration | Connect three data sources: ERP, supplier shipping documents, and logistics information, set field mapping rules | Cover all data sources for this category, reduce manual entry steps |

| Output Node Configuration | Generate purchase order attachments and arrival acceptance form templates, support exporting as PDF documents not exceeding 500 MB | Match the daily document output requirements of this category, facilitate archiving and internal circulation |

## Three common configuration mistakes
- Workflow runtime errors display "Cannot convert undefined or null to object". The cause is that `variables` binding for core fields is not configured, resulting in empty values for fields called in the workflow.
- AI chat node output is displayed directly on the page, and cannot be specified for output after splicing via subsequent components. The cause is that the automatic output switch of the AI node is not turned off, and `nodeId` for association with subsequent text splicing nodes is not configured.
- Historical records in the workflow cannot be used as cross-node variable calls. The cause is that the output fields of the historical record node are not bound in `variables`, resulting in inability to transfer data.

## How to confirm proper configuration
- Submit a test order, check whether the workflow automatically triggers and pulls corresponding ERP, shipping document, and logistics information data.
- Enter a simulated duplicate serial number, check whether the verification node blocks abnormal data and returns clear prompts.
- After configuring the AI chat node, turn off the automatic output switch, run the workflow, and check whether results are only output after the text splicing component completes.
- View the workflow logs in FastGPT v4.17.0, confirm that all fields bound in `variables` have valid values, and no null value errors occur.
