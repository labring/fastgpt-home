# Requirements and Design Document Drafting for Independent Innovation Replacement Adaptation: Workflow Orchestration

## What the data for this category looks like
Daily documents for this category include four types: adaptation inventory, compatibility test reports, migration plans, and issue ledgers. They typically contain fields such as system identification, original software and hardware versions, alternative candidate lists, compatibility verification results, and risk assessment items. Data sources cover existing enterprise system inventories, official directories of domestic software and hardware, test environment records, and manufacturer public materials. The update rhythm proceeds per individual project or is synchronized once per quarter. There are no fixed unified field units, and adjustments must be made based on specific verification scenarios.

## What constraints these characteristics impose on workflow orchestration
Data sources for this category are scattered and have diverse structures. Workflows must support parallel pulling of information from different data sources across multiple nodes, while adapting to different input and output formats of the four document types. The update rhythm per project or quarter requires workflows to flexibly adjust parameters and node order to adapt to phased adaptation tasks. Since errors may cause business systems to become unavailable, workflows must be configured with clear failure handling nodes and verification logic to avoid overall adaptation progress being affected by abnormalities in a single link. Additionally, the lack of fixed unified field units requires workflows to support custom field mapping to adapt to document specifications for different projects.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow trigger mode | Trigger upon completion of project nodes | Adapt to the document rhythm updated in project phases |
| Variable call scope | Project parameters within `variables` and App/Admin server deployment environment variables | Complies with official configuration requirements. AI Proxy administrator Token must not be used as an application authentication key, and AI Proxy-related environment variables must not be configured in workflow global variables |
| Node timeout threshold | 600–1200 seconds | Adapts to the reasonable time interval for multi-source data pulling and compatibility verification |
| Failure retry count | 2–3 times | Addresses occasional connection fluctuations and data pulling delays in test environments |
| Node ID binding | Bind `nodeId` to exclusive workflow nodes | Facilitates locating specific workflow links corresponding to adaptation documents |
| Document field verification | Enable required item verification based on preset document structure | Ensures generated adaptation documents comply with enterprise specifications |

## Three common mistakes
- Symptom: Workflow nodes return "Missing parameter" error. Troubleshooting items: Failed to correctly bind project-specific parameters within `variables`; or misused AI Proxy administrator Token as an application authentication key; or failed to configure required AI Proxy-related environment variables on the App/Admin server, resulting in startup verification issues
- Symptom: Workflow execution times out with no results. Troubleshooting items: Failed to set a reasonable timeout threshold, failed to configure failure retry nodes
- Symptom: Generated adaptation documents have missing fields or disorganized formatting. Troubleshooting items: Failed to configure node input and output based on preset document structure, failed to enable required field verification logic

## How to confirm the configuration is correct
- Check the environment variable configuration on the App/Admin server, confirm that `AIPROXY_API_ENDPOINT` (AI Proxy service root address) and `AIPROXY_API_TOKEN` (AI Proxy administrator Token) are correctly set and non-empty, and meet the deployment requirements for FastGPT v4.17.0 and later versions.
- Trigger the workflow test node to verify that project parameters within `variables` can be called normally.
- View workflow node logs to confirm that the timeout threshold and retry count match the preset configuration.
- Export the draft adaptation document generated by the workflow and check that the fields match the preset document structure.
