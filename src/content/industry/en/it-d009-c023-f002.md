# Drafting Requirements and Design Documents for IT Budget and Project Portfolio Management: Context and Token

This document is based on the configuration logic of FastGPT v4.17.0.

## Data profile for this category
Data for this category typically comes from financial systems, project management systems, contract ledgers, and requirements submitted by business departments. Daily produced documents include annual budget statements, project proposal forms, project portfolio dashboards, and investment review reports. Document fields mostly cover budget amounts, project cycles, resource allocation ratios, priority rankings, and similar items. Units include ten thousand yuan, days, man-months, and others. Data update cycles are mostly monthly, quarterly, or annually. The size of a single document varies with the scale of the enterprise’s project portfolio. Core content focuses on project initiation, budget allocation, and investment review.

## Constraints imposed on context and token processing
Heterogeneous data formats from multiple systems are inconsistent, which increases token consumption during context organization. Batch documents updated monthly or quarterly cause fluctuations in total context token count per single input, so a per-round input token cap must be set in advance. If structured fields in documents are not trimmed, non-core content will occupy excessive tokens, squeezing out space for critical priority information. Multi-turn interactions during requirement finalization accumulate context tokens. If token usage of historical conversations is not restricted, the total will quickly exceed the model’s supported range. Multi-dimensional data from project portfolio dashboards lengthens context length, so clear token truncation rules must be defined to avoid loss of core decision-making information.

## How to set configurations
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Matches the typical document size of annual budget statements and project portfolio dashboards, prevents token overflow |
| `quoteMaxToken` | 2000–3000 token | Adapts to the core content length of a single project proposal or investment review report |
| Historical session token cap | 5000 token | Controls context accumulation during multi-turn interactions in requirement finalization |
| Context truncation threshold | Calibrated via actual testing | Filters non-core redundant fields for structured data imported from heterogeneous systems |
| Single recall count | Top 3 entries | Matches the number of core reference documents for project priority ranking |

## Three common configuration mistakes
- An InternalError.Algo.InvalidParameter error with 400 status code is thrown, prompting that the token range is invalid. This occurs because the `maxContext` or `quoteMaxToken` parameters are not configured, so the system cannot limit the per-round input token cap, triggering a parameter validation failure.
- An error requesting external network resources occurs in an offline deployment environment. This occurs because the local tokenizer file path is not configured, and the system attempts to pull the public cl100k.tiktoken file by default, causing a request failure in the offline environment.
- Content truncation due to context overflow occurs after multiple rounds of requirement communication. This occurs because the historical session token cap is not set, and accumulated interaction content exceeds the token range supported by the model, resulting in loss of earlier budget priority information.

## How to confirm configurations are properly set
- Upload a typical annual budget statement, check the context token consumption value displayed by the system, and confirm it falls within the configured `maxContext` range.
- Trigger simulated multi-turn interactions for requirement finalization, check the token usage of historical conversations, and confirm it does not exceed the set historical session cap.
- Test document import in an offline deployment environment, confirm there are no error logs related to external network requests.
- Adjust the token cap for quoted content, verify whether the core content of a single project proposal is fully included in the context.

The values provided here are common starting points and should be measured against the reader's own samples.
