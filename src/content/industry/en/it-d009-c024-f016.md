# Requirements and Design Document Drafting for In-Feed Ad Creative Testing: Forms and Interactions

## What This Category’s Data Looks Like
The data used for in-feed ad creative testing typically comes from ad delivery platforms, internal asset libraries, user interaction data, and conversion data. Daily deliverable documents include creative scripts, asset test sheets, delivery data reports, and iteration checklists. Fields covered include asset type, copy length, delivery time slot, click-through rate, conversion cost, and more. Units include impressions, yuan, characters, hours, and others. Data update cycles follow daily or weekly schedules. Core test data is synced daily. Iteration records are summarized and archived weekly.

## Constraints Imposed on Forms and Interactions by These Characteristics
Since data sources are scattered and update cycles are short, connect to external business systems (such as asset libraries, ad delivery platforms) to obtain the latest data. Form nodes only collect input information to avoid using outdated test assets. Split and display multiple document types via external business systems or subsequent workflow nodes. Organize displays into chunks: creative scripts, asset configuration, test variables, and data reporting. This reduces filling complexity. Implement targeted validation rules via external business systems or subsequent workflow nodes. Examples include validating copy length and asset format compliance. Test results directly affect delivery effectiveness. Submission validation and exception handling logic must be implemented via external business systems or subsequent workflow nodes. Cover common issues such as empty fields and format errors to reduce subsequent delivery risks.
