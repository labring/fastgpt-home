# Requirements and Design Document Drafting for Duty Scheduling and Handover: Context and Token

## What the data for this category looks like
Core data for this category originates from scheduling systems, fault work orders, monitoring alerts, and organizational contact lists. Updates occur daily or weekly. Regularly produced documents include duty schedules, handover records, escalation contact lists, and daily duty reports. Fields cover duty time periods, unresolved pending tasks, escalation chain contacts, alert response status, and additional relevant details. Core associated information centers on duty personnel responsibilities and fault handling workflows.

## What constraints these characteristics impose on the "context and token" link
Data updates happen daily or weekly, and core information shifts dynamically with duty rotations. Context recall must first filter expired data. This prevents the introduction of outdated duty arrangements or inactive escalation chains. Document fields span multiple dimensions including time periods, pending tasks, and contacts. Precise matching to query scenario scopes is required to stop irrelevant information from occupying token quotas. Handover records and daily duty reports have lengthy single-call content. Total context token volume must be limited to avoid truncation or errors caused by exceeding model support limits.

## How to set the configuration
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Maximum total context token | 8000–12000 token | Adapts to the average content size of documents in this category, ensuring complete recall of key duty and handover information |
| `maxContext` | Calibrated at 1.2x the total length of business documents (FastGPT v4.17.0) | Matches the platform's context processing limits to avoid forced content truncation |
| Context recall token limit | 2000–3000 token | Focuses on core duty arrangements and handover items, filtering redundant historical alert information |
| `quoteMaxToken` | 1500 token | Limits token consumption for single recalled documents, preventing single overly long entries from occupying overall context space |
| Number of single recall entries | Top 3 entries | Matches the number of documents updated daily or weekly, avoiding excessive entries from occupying token quotas |

## Three common errors
- Phenomenon: "context length exceeded" errors appear in logs, and the interface shows token consumption exceeding preset thresholds. Cause: Context recall rules are not adjusted for this category's frequently updated documents, leading to recall of redundant duty records and handover content across multiple cycles.
- Phenomenon: Returned escalation contacts do not match current duty rotation personnel, making them unsuitable for direct use in fault response. Cause: Context time filtering configuration is not enabled, leading to recall of outdated escalation contact lists across cycles.
- Phenomenon: Calls return empty context-related content, with no duty-related documents loaded. Cause: `quoteMaxToken` is incorrectly set to 0, preventing recall of any eligible associated documents.

## How to confirm the configuration is correct
- Upload duty schedules, handover records, and escalation contact lists from the past 7 days. Trigger a duty arrangement query, and check if recalled documents are from the past 7 days.
- View token consumption statistics in call logs, confirm that single-call token volume does not exceed the configured maximum total context token value.
- Test queries for different duty time periods, confirm that returned escalation contacts match the responsibility scope of current duty personnel.
- Check the private deployment access path configuration, confirm that the application access path complies with preset context rules.

The values provided are common starting points and should be measured against the reader's own samples.
