# Requirements and Design Document Drafting for Level Content Creation: Context and Token

## What the data for this category looks like
The core data for level content creation typically comes from level editors, art resource libraries, player test data, and defect tracking systems. Common daily deliverable documents include level design drafts, resource requirement lists, test feedback sheets, and version submission records. Their structures cover fields such as level numbering, path nodes, resource locations, task trigger conditions, and test results. Data is updated weekly or per version iteration. The content length of a single document grows with the scale of the level, with many closely linked core fields.

## What constraints these characteristics impose on the context and token workflow
Frequent, closely linked updates to level content creation data require the context window to sync the latest level editing and test feedback content in a timely manner. This prevents the use of outdated resource requirements or test results. The complex document structure and large number of fields mean core information such as level paths and resource locations must be prioritized. As a result, token allocation must balance content completeness and model call efficiency. The weekly or version-level update rhythm requires context recall to match the data update cycle. This prevents redundant old data from being included. Errors in level content can lead to level blocks or launch delays. The total token count of the context must be strictly controlled to avoid exceeding the model's capacity limits.

## How to set the configurations
| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Matches the total content length of level design drafts and resource requirement lists |
| `quoteMaxToken` | 1500–2000 token | Aligns with the content scale of a single test feedback sheet or resource requirement entry |
| Context recall limit | Top 6 entries | Balances the volume of recalled content and token consumption, avoiding exceeding model thresholds |
| Context overlap length | 200–300 characters | Prevents core information such as level paths and resource locations from being truncated across chunks |
| Maximum model output token | 4000 token | Supports the detailed description requirements for level gameplay rules |

## Three common misconfigurations
-  Setting the context recall limit to 3000 prevents the large language model from receiving complete context. Verifiable troubleshooting steps: Check whether the token limit configurations for single references and total context match. Confirm that threshold settings are reasonable.
-  External network request errors for cl100k.tiktoken occur in offline deployment environments. Verifiable troubleshooting steps: Check whether the offline deployment environment can access the external network to obtain tokenizer dependency files, or confirm that local tokenizer files have been deployed correctly.
-  Model response timeouts occur during high-concurrency calls. This happens when the concurrency threshold for context processing is not adjusted based on hardware configuration, exceeding the system's carrying capacity.

## How to confirm configurations are correct
-  Check the server environment variables of the FastGPT v4.17.0 deployment environment. Confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` have been configured correctly, with no extra path suffixes.
-  Send a test request targeting level design documents. Check whether the context preview module includes the latest core information such as level paths and resource locations.
-  After adjusting context-related configurations, verify that the model output covers complete level gameplay rules and resource requirement descriptions.
-  Check system logs. Confirm there are no external network request errors related to token statistics, and no context truncation prompts.
