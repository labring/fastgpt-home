# Drafting Requirements and Design Documentation for Content Copyright and Authorization Management: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
This category's data mainly comes from contract systems, copyright registration databases, content material libraries, and complaint inboxes. Daily produced documents include authorization contracts, copyright ledgers, removal notices, and infringement complaint materials. Each individual authorization contract contains fields such as authorized subject, authorization scope, validity period, and payment terms. The copyright ledger must bind corresponding authorization information to each individual piece of content. Data updates follow a per-order or monthly rhythm. After the authorization status of a single piece of content changes, the ledger and contract association information must be updated synchronously.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Data sources are scattered and associated with individual pieces of content. Multi-turn dialogue must accurately bind the authorization information of the currently processed content. The context must be limited to only authorization-related data from the current session to avoid cross-content information interference. Document fields include professional terms such as rights ownership and authorization scope. The prompt must clearly limit the processing scope, focusing only on authorization-related fields. Update frequency fluctuates with business order volume. The dialogue must support resetting the context per individual piece of content to prevent historical data confusion. Infringement complaint materials require quick matching of corresponding authorization records. Multi-turn dialogue must support calling ledger data from specified sources to ensure the accuracy of verification.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context | Last 20 turns of dialogue + associated document fragments | This category needs to focus on authorization information for a single piece of content. Excessive historical dialogue will interfere with current matching. Limiting the number of turns reduces context redundancy |
| Single Search Limit | Top 6 entries | Authorization-related ledger and contract data volume is relatively fixed. Excessive search results increase prompt load. 6 entries can cover common authorization association items |
| Question Optimization | Enabled | This category of documents contains professional rights terminology. Optimized prompts can more accurately identify core fields such as authorization scope and validity period |
| `chatId` | Bind to the currently processed content ID | Ensure multi-turn dialogue only associates authorization data for the current content, avoiding cross-content context confusion |
| `variables` | Preset authorization subject and content ID variables | Quickly call ledger information from corresponding data sources, reducing repeated input |
| `messages` | Only retain authorization-related messages from the current session | Filter irrelevant conversation content, focusing on the current copyright authorization processing workflow |

## Three common mistakes
- Phenomenon: The workflow terminates directly after reaching the multi-turn dialogue link, without completing the subsequent authorization verification process, and the interface displays that the session has ended. Cause: `chatId` is not bound to the current content ID, resulting in lost context and the dialogue triggering the end condition early.
- Phenomenon: The dialogue returns a timeout prompt or no response for more than 120 seconds. Cause: The single search limit is not set, and ledger data from too many sources is called, exceeding the system response threshold.
- Phenomenon: When calling the standard dialogue function, global content library data is automatically introduced, exceeding the preset authorization-related processing scope. Cause: The global knowledge base call switch is not turned off, or the prompt does not explicitly limit only using data from the preset `variables` parameter.

## How to confirm proper configuration
- Manually trigger an authorization document drafting dialogue for a single piece of content, check that the context only contains authorization ledger data for the current content, with no irrelevant historical dialogue content.
- Verify that the `chatId` configuration item is bound to the currently processed content ID, ensuring each dialogue only associates authorization information for a single piece of content.
- Test calling the standard dialogue function, confirm that global content library data is not automatically introduced, and only content from the preset `variables` parameter is used.
- Simulate a long-duration dialogue scenario, check that dialogue responses are completed within 120 seconds on FastGPT v4.17.0, with no unresponsive situations.
