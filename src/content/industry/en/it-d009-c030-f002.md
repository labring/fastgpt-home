# Drafting Requirements and Design Documents for Internal Network and WiFi Operations: Context and Token

## What Data for This Category Looks Like
Data for this category comes primarily from switch consoles, wireless controllers, office monitoring systems, and frontline user trouble reporting channels. Daily generated documents include network topology diagrams, network change orders, equipment fault records, and wireless coverage inspection forms. Fields include device port numbers, VLAN configurations, signal strength values, inspection timestamps, and more. Units include dBm, port numbers, VLAN IDs, and others.
Data update frequency is adjusted based on operational activities. Daily inspection data is updated once per day. Relevant documents are updated immediately after network changes or fault handling.

## Constraints Imposed on Context and Token Processing
Data sources for this category are scattered, including switch console logs, wireless controller configurations, inspection form values, and user trouble reports. Context formats vary widely across sources. Unified cleaning is required before data can be added to the token processing workflow.
Daily document update frequency shifts with operational activity. Bulk data additions occur during network changes or fault handling. Insufficient context token quota can lead to loss of critical information such as key port and VLAN configurations.
Units and formats of fields like signal strength and port numbers in inspection forms are inconsistent. Without preprocessing, these inconsistencies consume extra tokens and reduce context matching accuracy.
Operation scenarios require coverage of change and inspection data from the past 7 days. This imposes clear constraints on effective token allocation and window settings.

## Configuration Settings
The following configurations are based on the interface and parameter logic of FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | This category must cover core operational data such as network topology, change orders, and inspection forms from the past 7 days. This range accommodates complete operational information while avoiding global token overflow |
| `quoteMaxToken` | 1000–1500 characters | The core content of a single operational document typically does not exceed this range. This ensures referenced information is complete without consuming excessive context quota |
| Context recall upper limit | Top 6–8 entries | The volume of valid operational data for this category is moderate. Excessive recall consumes additional tokens, while insufficient recall misses key fault records or change information |
| Context update trigger rule | Daily scheduled + operational change trigger | Daily inspection data is updated once per day. Updates trigger immediately after network changes or fault handling, ensuring context data timeliness |
| Context cleaning threshold | Calibrated based on actual testing | Data formats for this category include multiple field types such as port numbers, VLAN IDs, and signal strength. Cleaning rules must be adjusted based on actual connected data sources to prevent invalid information from consuming tokens |

## Three Common Misconfigurations
- Symptom: An error stating `AIPROXY_API_ENDPOINT` is not configured or `AIPROXY_API_TOKEN` is invalid appears after startup, or a 401 status code is returned when making a model request. Cause: The `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` environment variables for the App/Admin server are not configured, or the format of the entered `AIPROXY_API_ENDPOINT` is incorrect (such as omitting the http/https prefix). `AIPROXY_API_ENDPOINT` is the root address of the AI Proxy service. `AIPROXY_API_TOKEN` is the AI Proxy administrator token, and is unrelated to the model interface address and model authorization token.
- Symptom: Generated requirements and design documents lack recent network change order content, or fault records are not fully matched. Cause: The `maxContext` configuration value is too small to accommodate all core operational data from the past 7 days, resulting in critical context being truncated.
- Symptom: The content of a single referenced operational document is incomplete, only showing the opening section. Cause: The `quoteMaxToken` configuration value is smaller than the core content length of the target document, resulting in referenced content being truncated early.

## How to Confirm Configurations Are Valid
- View the real-time occupancy of the context window, confirm that the configured `maxContext` value matches the total volume of connected operational data. Adjustments must be made based on recent data update frequency and new data volume.
- Manually import a complete change order or fault record, check the completeness of the referenced content, and confirm that the `quoteMaxToken` configuration value matches the core content length of this document.
- Trigger a recall test for operational documents, verify that the number of returned recall entries matches the configured context recall upper limit, and confirm that the recall rule is active.
- Check the configuration values of the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` environment variables on the App/Admin server, confirm that the format is correct and consistent with the AI Proxy server configuration.

The values provided are common starting points and should be evaluated against sample data relevant to the specific deployment.
