# Requirements and Design Documentation for Creator Onboarding and Certification: Context and Token

## What the data for this category looks like
Daily documents for creator onboarding and certification include onboarding applications, identity qualification materials, certification audit records, and cooperation agreements. Data is sourced from creator backends, enterprise credit information systems, account history databases, and contract management systems. Updates occur daily or when each application is submitted. Common document fields include account ID, qualification number, audit status, cooperation period, and others. Individual materials range in length from hundreds to thousands of characters. Multi-source data must be integrated to support audit judgment.

## What constraints these characteristics impose on the context and token link
The multi-source data structure of this category requires the context to cover multiple content types including creator backend records, enterprise credit information, historical audit results, and more, leading to high total token consumption. Updates occur daily or when each application is triggered, so the context must pull the latest qualification and audit data in real time. All key fields must remain untruncated during the most time-consuming qualification verification and account risk judgment steps. Otherwise, false certifications or mismatched rights and interests may occur. Additionally, the wide variation in individual material lengths requires limiting the token count of single citations to avoid context overflow, which would compromise the integrity of audit logic.

## How to configure the settings
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| maxContext | 8000–12000 token | The total token consumption of full onboarding application materials and historical audit records for creator onboarding and certification typically falls within this range, ensuring all key fields are not truncated |
| quoteMaxToken | 1500–2000 token | The length of individual qualification materials or cooperation agreement fragments typically does not exceed this value, preventing single citations from overflowing the context |
| Context recall count | Top 6 entries | Historical account records and qualification verification results related to a creator typically number 6 or fewer. Excessive entries will add unnecessary token consumption |
| Single request timeout | 600 seconds | Qualification verification and risk judgment steps take a long time, so this value must match actual processing durations |
| Recall relevance threshold | 0.75 | Ensure that the relevance of recalled account history and enterprise credit information to the current application meets audit requirements |

## Three common misconfigurations
- If the context fails to associate historical audit records as expected after calling `/api/core/dataset/collection/create` or `/api/core/dataset/create`, check whether the `maxContext` configuration does not cover the total token amount of historical records and the current application, resulting in truncation of critical historical data.
- If qualification verification results are not included in the context and only the current application content is returned, check whether `quoteMaxToken` is set too small, causing individual qualification material tokens to exceed the limit and be filtered out.
- If the audit request returns a 504 timeout status code, check whether `maxContext` is set too large, causing model processing time to exceed the preset threshold, and the timeout configuration has not been adjusted to match actual processing durations.

## How to confirm the configuration is correct
- Upload a complete creator onboarding application material, and verify that all uploaded qualifications, historical records, and agreement fragments appear in the context preview.
- Submit a simulated audit request, and confirm that the returned results include recalled associated account historical data and enterprise credit information.
- Check the server startup logs for FastGPT v4.17.0 to confirm that no validation errors for missing `AIPROXY_API_ENDPOINT` (AI Proxy service root address) or `AIPROXY_API_TOKEN` (AI Proxy administrator Token) are present.
- Adjust the value of `maxContext`, and verify that the total token count of the context preview changes in line with the new configuration.
