# Requirements and Design Documentation for Creator Onboarding and Certification: Forms and Interactions

## What Data for This Category Looks Like
Data for this category originates from creator backends, corporate credit information query platforms, account history records, and contract systems. Regularly produced documents include onboarding application forms, scanned identity qualification documents, certification audit flow records, and cooperation agreement texts. Data updates occur either via daily synchronization or when triggered by individual applications. Core fields include creator account identifiers, qualification document numbers, audit status identifiers, and cooperation binding identifiers. Field units align with corresponding business types, with no unified fixed format.

## Constraints Imposed on Forms and Interactions
Decentralized data sources require the `formInput` node to support collecting creator information from multiple channels. The `formInput` node must be configured to collect qualification document information. Qualification verification via external corporate credit information interfaces is handled by external business systems. Updates are triggered per individual application. After the `formInput` node submits input information, audit status synchronization logic is implemented by external business systems or subsequent nodes, to prevent duplicate submission operations. Core fields include qualification document numbers. Document format verification and account risk verification are handled by external business systems or subsequent nodes; the `formInput` node is responsible for collecting relevant input information. Audit records and cooperation agreements must be bound to application entries. A unique association identifier is generated by the external business system, and input information collected by the `formInput` node is linked to this identifier to ensure full-link data traceability.

## Three Common Configuration Errors
- Phenomenon: A "qualification information format error" error message is returned when submitting an onboarding application. Cause: No document type matching rules configured for implementation by external business systems or subsequent nodes, resulting in non-standard qualification numbers failing verification.
- Phenomenon: Two duplicate audit records appear in the audit system after the same creator submits two onboarding applications. Cause: No duplicate submission interception logic configured for implementation by external business systems or subsequent nodes using application entry unique identifiers, resulting in unblocked duplicate submission data.
- Phenomenon: Creators do not see audit status updates within the preset duration after submitting an application. Cause: The external business system's audit status synchronization trigger logic is incorrectly configured as fixed-period execution, which does not match the update rhythm of individual applications, resulting in delayed status updates.

## How to Confirm Proper Configuration
- Input different types of qualification document numbers, verify whether external business systems or subsequent nodes trigger format verification.
- Submit a test onboarding application, confirm whether the external corporate credit information interface is called, and qualification verification is completed by the external system.
- After submitting a test application, check whether the audit status of the external business system is updated according to the configured logic.
- Switch creator subject types, verify whether external business systems or subsequent nodes dynamically adjust the required rules of the `formInput` node according to the configuration.
