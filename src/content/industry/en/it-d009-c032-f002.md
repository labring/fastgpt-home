# Drafting Requirements and Design Documents for Creator Incentive Settlement: Context and Token

## What the Data for This Category Looks Like
The core data for creator incentive settlement comes from content data, advertising revenue sharing systems, financial systems, and account backends. Updates follow a monthly or single operational activity cycle. Daily generated documents include incentive rules, settlement details, appeal records, and payment lists. Fields include creator identifiers, content association identifiers, revenue accounting items, settlement cycle identifiers, appeal statuses, and payment voucher identifiers. There is no fixed uniform document length. Multi-source data must be integrated across systems before use.

## What Constraints Do These Characteristics Impose on Context and Token Processing
The requirement to integrate multi-source data means the context must load associated content from different systems at the same time. Combined with the most time-consuming revenue caliber verification step, this directly increases token consumption. Document update schedules are irregular, so the context must be dynamically refreshed to avoid using outdated data. Token lengths vary widely across different documents. Settlement details and appeal records may contain long text, which easily exceeds the model's context window. When splicing fields across systems, both completeness and token limits must be balanced. Otherwise, core accounting information may be lost, leading to settlement disputes or incorrect payment risks.

## How to Configure Settings
This document is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum context window | `8000–12000 token` | Adapts to the average token length of creator settlement-related documents, with reasonable redundant space reserved |
| Context reference token limit | `2000–3000 token` | Matches the typical token length of a single settlement detail or appeal record, preventing a single data entry from occupying excessive window space |
| Context refresh timing | Triggered per settlement cycle | Aligns with the business characteristic where data updates occur monthly or per activity cycle |
| Multi-source associated data limit | Top 3 entries | Focuses on core associated content for a single settlement, avoiding excessive data that slows context loading |
| Long text truncation threshold | Calibrated via actual testing | Adapts to appeal records and payment list documents of varying lengths |

## Three Common Misconfigurations
- Symptom: The interface returns a context token limit exceeded error, and logs show the `maxContext` threshold has been breached. Cause: Configurations are not adjusted based on the average token length of creator settlement-related documents, and parameters from general question-and-answer scenarios are used directly.
- Symptom: Settlement verification results do not match the latest payment list. Cause: Context refresh timing is not set based on data update frequency, and outdated settlement data continues to be used.
- Symptom: Information from some appeal records is excluded when merging results across consecutive questions. Cause: The `quoteMaxToken` limit for single referenced data length is not set, resulting in long text being truncated.

## How to Verify Correct Configuration
- Upload a single complete settlement detail document, test context loading, and confirm no token limit exceeded error is triggered.
- Update the incentive rule document, manually trigger a context refresh, and verify that the loaded content is the latest version.
- Initiate a consecutive question that includes multi-source data, and check that the returned results cover the core fields of incentive rules, settlement details, and appeal records.
- Adjust the `quoteMaxToken` parameter, upload a long appeal record, and verify that no critical information is lost from the referenced content.

The values provided are common starting points and should be measured against the reader's own samples.
