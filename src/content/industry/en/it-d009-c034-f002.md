# Drafting Requirements and Design Documents for Office System Process Configuration: Context and Token

## Data Profile for This Category
Data for this category primarily comes from enterprise OA systems, organizational structure repositories, internal policy documents, and frontline user feedback. Documents produced daily include process configuration sheets, approval node tables, form field descriptions, and change records. Data updates are triggered by process changes, with a full sync completed at least once per month. Fields cover approval node permissions, form validation rules, routing path parameters, and more. There is no unified fixed unit, and values vary based on configuration item type.

## Constraints Imposed on Context and Token Processing
Fields in process configuration documents are mostly structured content related to permissions and routing, and must be associated with organizational hierarchy information. The context must cover the complete approval node chain and associated permission rules to avoid permission omissions. Data updates are triggered by changes, so the context window must support dynamic adaptation to new configuration items. This prevents configuration deviations caused by overwriting old data. The token count of a single configuration document increases with process complexity. Exceeding the token limit will cause the generated requirement document to miss key routing rules. Knowledge base retrieval must accurately match node permissions and form fields to avoid retrieving irrelevant historical change records.

## How to Configure Settings
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| Max Context Window | 8000–12000 token | Adapt to the structured content volume of process configuration documents, cover complete approval chains and associated permission data, and align with the context processing logic of FastGPT v4.17.0 |
| `quoteMaxToken` | 2000–3000 token | Limit the token upper limit of a single retrieved document, avoid excessive single data occupying context space, and prevent large model response timeouts |
| Single Retrieval Count | Top 6 entries | Match the range of process configuration node counts, ensure complete retrieval of approval rules and form fields |
| Context Overlap Length | 200–300 characters | Retain approval node association information across chunks, prevent rule breaks caused by chunking |
| `maxContext` | Calibrated based on actual testing | Adapt to the complexity of enterprise-specific processes, avoid generation failures caused by exceeding context limits |

## Three Common Misconfigurations
- Phenomenon: Large model response timeout or incomplete returned content, with token limit exceeded error displayed in logs. Cause: The `quoteMaxToken` value is set to 50000 token, and the total token of single retrieved documents exceeds the large model support limit, occupying context space.
- Phenomenon: Generated requirement documents miss some approval node rules. Cause: The context overlap length is set too small, and node association information across chunks is truncated, making it impossible to fully restore the approval chain.
- Phenomenon: Unable to retain context session information when calling the API. Cause: The persistence parameter of the context window is not configured correctly, resulting in session context reset for each request.

## How to Verify Successful Configuration
- Review max context window and `quoteMaxToken` values on the configuration page, confirm alignment with average token counts of process documents. Token statistics for a single process configuration document can be used for verification.
- Initiate a simulated process configuration requirement drafting request, check if the returned document includes complete approval nodes, permission rules, and form fields.
- View retrieval logs, confirm that the number of retrieved documents and token volume match the preset configuration, with no excessive retrieval.
- Test multiple consecutive API calls, confirm that context session information is correctly retained, with no session reset.

The values provided are common starting points and should be measured against the reader's own samples.
