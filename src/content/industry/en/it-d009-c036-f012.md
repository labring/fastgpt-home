# Requirements and Design Document Drafting for Prototyping and Interaction Design: Document Parsing and Chunking

## What Data for This Category Looks Like
Data for this category typically originates from Figma or Axure files, internal team design systems, user feedback records, and usability test results. Daily produced documents include interactive prototypes, page flowcharts, component descriptions, and design review records. Update cycles follow weekly intervals or align with product version iterations. This data is primarily maintained by product designers, interaction designers, and front-end product teams. Most document structures include page hierarchies, operation paths, interaction rules, and comment fields. No unified fixed units or format requirements apply. Some documents embed visual components and interaction descriptions. This guide is compatible with FastGPT v4.17.0.

## What Constraints These Characteristics Impose on the "Document Parsing and Chunking" Link
Documents in this category often include hierarchical page structures, interactive operation paths, and embedded visual components. Parsing processes must retain the logical connections between pages to avoid breaking the context of operation flows. Most documents originate from specific formats exported by structured design tools such as Figma and Axure. Custom parsing rules must be adapted to extract complete interaction descriptions and comment content. The high update frequency of these documents requires chunking logic to support incremental updates to document fragments. It is also necessary to handle the binding relationship between scattered review comments and prototype pages to prevent loss of corresponding associations after chunking. Some documents lack unified formats. Chunking processes must avoid forcibly splitting cross-field interaction rule descriptions.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Documents in this category often include page hierarchies and operation paths. This range preserves the complete context of single-page interaction logic, avoiding overly fine or overly coarse splitting |
| `chunkSplitter` | Split by page and component | Prototyping and interaction design documents take pages and components as core units. Splitting by this method retains complete interaction descriptions for individual modules |
| `customPdfParse` | Enabled | Some design documents are exported as scanned PDFs or PDFs with embedded elements. Enabling this setting adapts custom parsing rules to extract text and embedded content |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Packaged files exported from Axure and Figma usually do not exceed this size, covering the upload needs of most teams |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 seconds | Large design system documents take longer to parse. This duration prevents parsing failures due to timeout |
| `chunkSettingMode` | Manual configuration | Document structures vary significantly across teams. Manual configuration allows flexible adaptation to the splitting needs of page hierarchies and interaction descriptions |

## Three Common Mistakes
- Issue: After uploading Excel-format review records exported from Axure, index results only include headers with no content. Cause: Parsing rules adapted for structured tables are not configured. The default parsing logic does not extract comments and review opinions within cells.
- Issue: After uploading scanned PDFs exported from Figma, parsing results are empty or only contain a small amount of garbled text. Cause: The OCR adaptation switch for `customPdfParse` is not enabled. The system cannot recognize text content within scanned images.
- Issue: Chunked content includes cross-page interaction logic, preventing development teams from retrieving complete associated operation paths. Cause: `chunkSize` is set too large or too small. Chunking is not performed by page units, breaking the contextual connections between pages.

## How to Confirm Configurations Are Correct
- Upload a single typical interactive prototype document. Check whether the number of parsed chunks matches the number of pages. Adjust chunking rules until each chunk corresponds to a single page or component unit.
- Upload a scanned design document. Verify that the parsed result includes complete text content. Confirm that the `customPdfParse` configuration takes effect.
- Upload the largest specification design file. Check whether the upload and parsing processes complete within the preset duration. Verify that the `UPLOAD_FILE_MAX_SIZE` and `PARSE_FILE_TIMEOUT_SECONDS` configurations are suitable.
- Upload a document with embedded components. Check whether chunked content retains associated descriptions of components. Confirm that the `chunkSplitter` configuration aligns with the document structure.

The values provided here are common starting points. They should be evaluated against the reader's own samples.
