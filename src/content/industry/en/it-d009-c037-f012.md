# Requirements and Design Document Drafting for Release Management and Version Acceptance: Document Parsing and Chunking

## What the data for this category looks like
This category’s core data originates from CI pipelines, change management systems, test reports, and monitoring dashboards. Daily produced documents include release plans, launch checklists, acceptance reports, and rollback plans.
Document structures are mostly mixed formats. Some documents from automated systems are plain unformatted text. Manually created documents include section headings, tables, and structured fields such as version identifiers, change association IDs, acceptance pass markers, and rollback trigger conditions.
Update frequency is weekly or per release cycle. Typical users include release managers, R&D and operations teams, and product owners. Core workflows focus on launch window coordination, release item verification, and rollback condition confirmation.

## What constraints do these characteristics impose on the document parsing and chunking link
Mixed-format data sources include automated system outputs and manually created documents. The parsing link must adapt to multiple file types including unformatted text, tables, and PDFs, and avoid losing structured fields.
Documents update weekly or per release cycle. Parsing tasks must adapt to fast-paced release rhythms, and must not block launch processes due to timeouts.
Release-related documents contain key metadata such as version associations and launch times. During chunking, adjacent context must be retained to ensure complete release items and acceptance statuses can be associated during retrieval. Key information must not be lost due to overly fine or overly coarse chunking.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the paragraph length of release plans and acceptance reports, retains context for key metadata such as version associations and launch times |
| `chunkSplitter` | Split by heading + paragraph | Matches the section structure of launch checklists and rollback plans, avoids splitting that disrupts the integrity of acceptance status and rollback condition content |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the average parsing duration of a single release document, prevents timeouts that block release workflows |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch uploading of multiple launch checklists and test reports, matches the document package scale used by R&D teams |
| `chunkSettingMode` | Manual configuration | Allows release managers to adjust chunking parameters based on different release types (emergency launch / regular iteration) to adapt to business scenarios |

## Three common mistakes
- Symptom: When searching Excel documents for launch checklists, only some matching entries are returned. Cause: Chunking did not retain full row data, or automatic chunking truncated complete cell content containing "acceptance status" or "rollback trigger conditions".
- Symptom: After uploading a PDF rollback plan document, key trigger conditions are missing from the parsed chunks. Cause: The `customPdfParse` configuration was not enabled, and the default PDF parsing did not recognize hierarchical headings and conditional text within the document.
- Symptom: When searching doc or docx format acceptance reports, body content associated with section headings is not returned. Cause: Chunking did not retain adjacent section headings as context, resulting in missing associated acceptance node information in search results.

## How to confirm configurations are set correctly
- Upload a standard release plan document, check if the parsed chunks include metadata such as version number and launch time. This verification process applies to FastGPT v4.17.0.
- Upload a single launch checklist with a size not exceeding 1000 MB, confirm that the parsing task completes within 600 seconds with no timeout errors.
- Adjust the `chunkSize` parameter, then search test report documents, confirm that the returned chunk lengths match the expected configuration.
- Enable the `customPdfParse` configuration, upload a PDF rollback plan, check if the chunks retain section headings and trigger conditions.

Note: The values provided here are common starting points, and should be evaluated against the reader's own samples.
