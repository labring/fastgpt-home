# Requirements and Design Document Drafting for Change Management and Release Windows: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Data for this category comes from internal enterprise change management systems, CI pipelines, production environment monitoring data, and business calendars. Daily produced documents include change request forms, risk assessment reports, launch window schedules, and rollback plan documents. Data update frequency is once per change cycle or once per week. Document structure includes fields such as change subject, impact scope, risk level, window time period, rollback trigger conditions, with no additional unmentioned statistics or field content.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
Change management and release window documents are mostly structured content, and must be associated with real-time change status and business calendar windows. Multi-turn dialogue must retain context to associate past change records. Data updates are triggered per single change. Dialogue context must filter non-change-related history to avoid interference from redundant information. Field formats vary widely across different documents. Prompt engineering must clearly specify field extraction rules for corresponding documents, while also limiting dialogue context length to adapt to short-cycle, high-frequency interactions in this scenario.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Context window length | First 10 turns of dialogue or 8000 characters | Change management documents have moderate length, avoid overly long context causing the model to mix up change plans across different cycles |
| Historical message filtering rule | Only retain `messages` related to the change topic | Filter non-change-related historical dialogue to reduce interference from redundant information on the model |
| Variable binding scope | Bind change ID and window time period parameters from `variables` | Ensure the model only uses exclusive data for the current change when called, avoiding cross-session data confusion |
| Output format constraint | Enforce Markdown format, single segment content no longer than 1500 characters | Adapt to FastGPT v4.17.0's dialogue rendering rules, avoid content truncation |
| Maximum interaction turns | No more than 15 turns per single session | Match the single change approval cycle in change management scenarios, avoid resource consumption from invalid long conversations |

## Three Common Misconfigurations
- The phenomenon is that the LLM returns unbound external knowledge base content. The cause is that the prompt does not clearly limit use of only change management-related bound document data.
- The phenomenon is that Markdown table output is truncated, showing only partial content. The cause is that the maximum character limit for output content is not configured, exceeding the default threshold of FastGPT's dialogue rendering.
- The phenomenon is that the model mixes up change plans across different cycles. The cause is that historical message filtering rules are not configured, retaining irrelevant historical dialogue context.

## How to Verify Proper Configuration
- Initiate a multi-turn dialogue for drafting a change request form, check that returned content only includes bound change management document fields, with no irrelevant external content appearing.
- Input historical content containing multi-turn change discussions, confirm that the model only retains context information from the specified turns, and does not mix up change plans across different cycles.
- Trigger output of a risk assessment report in Markdown format, check that the content is fully displayed with no truncation or hidden characters.
- Verify that session context bound to `chatId` can restore saved change discussion records when re-entering the session.

The values provided are common starting points and should be measured against the reader's own samples.
