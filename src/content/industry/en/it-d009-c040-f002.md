# Drafting Requirements and Design Documents for Pre-Sales Technical Solutions: Context and Token

## What the data for this category looks like
Core users of this category are system integrator pre-sales consultants, solution architects, and sales teams. Daily deliverables include technical proposal documents, customer requirement survey forms, quotation lists, and demo scripts. Data sources cover customer interview records, public bidding documents, vendor product materials, and historical project proposals. Document update frequency follows individual project cycles, typically once per project or weekly. The most time-consuming steps in core business processes are requirement clarification, solution boundary design, and quotation configuration verification. Configuration errors may lead to lost bidding points, over-range commitments, or project losses. Documents in this category use business chapters as their core structure, including clear fields such as technical route, implementation scope, and resource allocation. There are no unified mandatory format requirements.

## What constraints these characteristics impose on the context and token workflow
Data sources for this category are scattered and have varying formats. Integrating multi-source information to draft requirements and design documents causes large fluctuations in token consumption for context content. Single pre-sales technical proposals have large content volumes, and their multi-chapter structure easily introduces context overflow risks. The requirement clarification process requires repeated calls to historical project proposals, customer requirement data, and similar resources. Improper context management will result in redundant information occupying token resources, or key historical records being truncated. Business error consequences are severe, so context and token configurations must accurately match business scenarios. This avoids incomplete or over-range solution generation caused by configuration errors.

## How to set the configurations
| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Adapts to the average content length of single pre-sales technical proposal documents, matches the default context window range of FastGPT v4.17.0 |
| `quoteMaxToken` | 2000–4000 token | Limits token consumption for single quoted content, prevents context overflow caused by overly long segments of vendor materials or customer interview content |
| Maximum Context Retention Rounds | First 10 rounds | Matches the multi-round requirement clarification scenario for pre-sales proposal drafting, retains key interaction records and historical proposal references |
| Context Splicing Threshold | Calibrated via actual testing | Adapts to the needs of multi-source data integration, avoids redundant information occupying excessive token resources |

## Three common configuration mistakes
- Symptom: `maxContext` is set to 10000 token, but context truncation occurs during actual proposal generation. Troubleshooting: Confirm that the `maxContext` configuration value matches the business scenario and does not exceed the FastGPT context window upper limit.
- Symptom: The number of context entries displayed on the interface does not match the number actually sent to the upstream model. Troubleshooting: Confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are environment variables set on the App/Admin server side. They must not be filled in the application configuration page or workflow global variables, and `AIPROXY_API_TOKEN` must not be used as the application API Key.
- Symptom: Context association still deviates after manually adjusting document segments. Cause: The segment logic is not optimized for the chapter structure of pre-sales proposals, causing segment boundaries to destroy the integrity of business context.

## How to confirm the configuration is correct
- Check the environment variables on the App/Admin server. Confirm that `AIPROXY_API_ENDPOINT` (AI Proxy service root address) and `AIPROXY_API_TOKEN` (AI Proxy administrator Token) are correctly configured and not empty.
- View the context and token related configuration items on the FastGPT application configuration page, confirm that their values match the preset plan.
- Initiate a test call, check whether the context token count reported in the log matches the configured value.
- Import a typical pre-sales technical proposal document, verify that the generated proposal content does not have unnecessary truncation or redundancy.

The values provided are common starting points and should be measured against the reader's own samples.
