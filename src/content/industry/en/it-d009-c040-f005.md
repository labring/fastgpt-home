# Drafting Requirements and Design Documents for Pre-Sales Technical Solutions: Multi-Turn Dialogue and Prompt Engineering

## Data Profile for This Category
This category of data primarily comes from customer interview records, public bidding documents, official manufacturer product materials, and past historical project plans. Updates occur once per order or per week. Typical document structures include modules for customer requirement breakdown, technical roadmap planning, implementation boundary clarification, quotation configuration list, and demo script framework. Core fields include customer requirement items, technical selection items, implementation cycle estimates, quotation detail items, and some documents include project risk reminder items.

## Constraints Imposed on Multi-Turn Dialogue and Prompt Engineering
The data sources for this category are scattered and updated frequently. Multi-turn dialogue must support switching context by data source type to avoid referencing expired or mismatched content. There are numerous document modules, with core fields covering requirements, technical roadmaps, quotations, and implementation boundaries. Multi-turn dialogue must guide interactions step-by-step by module to prevent cross-module information confusion. Additionally, pre-sales solutions are directly linked to bidding outcomes, so dialogue must strictly align with the current project’s exclusive data, cannot mix configuration information from other projects, and must clearly verify core field compliance in each interaction.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | 8000–12000 characters | A single pre-sales solution document is typically 5000–10000 characters long, and full historical dialogue and reference document fragments must be retained |
| Single Recall Result Limit | Top 6 entries | Core reference data for pre-sales solutions is concentrated in a small number of authoritative data sources; excessive recalls will distract from the context |
| Dialogue Context Retention Period | 90 days | Most pre-sales project cycles do not exceed 90 days, so multi-turn interaction records must be fully retained for subsequent verification |
| `chatId` | Generated using the project's unique identifier | Must strictly distinguish dialogue contexts for different pre-sales projects to avoid cross-project data confusion |
| `messages` | Retain the most recent 10 rounds of interaction content | Multi-turn dialogue for pre-sales solutions typically requires no more than 10 rounds to complete requirement clarification and plan confirmation |
| `variables` | Bound to the current project's exclusive fields | Must automatically insert information such as customer name and bidding number to ensure generated content matches the current project’s requirements |

## Three Common Misconfigurations
- Symptom: A prompt reading "No available index model detected" appears after page refresh, and reference documents for the current dialogue cannot be loaded. Cause: The exclusive data source of the current pre-sales project is not bound to the corresponding index configuration, or the index model update frequency does not match the project’s weekly update cadence.
- Symptom: Results returned by the dialogue interface do not include an entry to view the original source material. Cause: The source reference switch for the dialogue is not enabled, or the metadata of the data source is not correctly embedded into the `messages` parameter.
- Symptom: Historical conversations older than 2 months cannot be accessed. Cause: The dialogue context retention period configuration is shorter than the current pre-sales project’s cycle, or the `chatId` of historical conversations does not retain the project’s unique identifier, resulting in automatic context cleanup.

## How to Verify Configurations Are Properly Set
- Initiate a test dialogue targeting the current project’s bidding documents, and verify that returned results can correctly reference bound data source content.
- Confirm that the `chatId` matches the current pre-sales project’s unique identifier, ensuring that dialogue contexts for different projects do not interfere with each other.
- Review the dialogue context retention period configuration, confirming that it covers the current project’s estimated cycle.
- After enabling the question optimization switch, input a vague requirement statement, and verify that the dialogue can automatically extract core requirement points.

The values provided here are common starting points and should be measured against the reader's own samples.
