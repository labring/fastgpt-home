# Drafting Requirements and Design Documents for Pre-sales Technical Solutions: Workflow Orchestration

## What the Data for This Category Looks Like
The data for pre-sales technical solutions primarily comes from customer interviews, bidding documents, vendor product materials, and historical project plans. Daily deliverable documents include four categories: technical proposal documents, customer requirement research forms, quotation lists, and demo scripts. Fields cover customer business scenarios, technical routes, implementation boundaries, and quotation details. Some fields include units, such as project duration (days) and quotation amount (yuan). Data is updated per order or weekly. The document volume of a single plan varies based on project complexity.

## What Constraints These Characteristics Impose on the "Workflow Orchestration" Link
Multi-source data input requires workflows to pull and integrate data across sources, to avoid errors from manual copy-pasting. Multiple document structures and fields require workflows to split into dedicated nodes for separate processing, ensuring accurate field mapping for different document types. The per-order or weekly update rhythm allows workflows to reuse temporary variables for single tasks, without reconfiguring basic parameters. Fields with units require workflows to include built-in basic validation rules, to prevent solution errors caused by unit mismatches.

## How to Set Configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Configured to customer business scenario, technical route, and quotation detail fields | Matches the multi-field data structure of pre-sales technical solutions |
| `nodeId` | Assign unique identifiers to requirement extraction, solution boundary, and quotation verification nodes | Adapts to the workflow orchestration logic of multi-node serial/parallel execution |
| Context window configuration | 8000–12000 characters | Accommodates the full content of multiple associated pre-sales documents |
| Timeout threshold setting | 600 seconds | Adapts to the processing duration of complex technical proposal documents |
| Variable validation rules | Validate required items by field type | Avoids missing fields or unit errors in pre-sales solutions |

## Three Common Mistakes
- Workflow page input text lags, triggered when there are many nodes. The cause is missing node grouping and folding configuration, which leads to excessive page rendering load.
- Links in workflow reply components display as "Click to Ask Immediately". The cause is incorrect configuration of reply content format parameters, with links not output as plain text directly.
- Workflow input instructions lack trigger rules set for business scenarios. The cause is unbound data source trigger conditions for corresponding pre-sales documents, leading to mismatched instruction execution timing and business processes.
