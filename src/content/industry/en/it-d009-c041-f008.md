# Requirements and Design Document Drafting for Image Annotation Projects: Workflow Orchestration

## What data looks like for this category
Core data for image annotation projects comes from image samples, category dictionaries, and inspection results produced by annotation platforms. Associated daily documents include annotation specifications, bounding box examples, quality inspection reports, and rework lists. Data is updated daily or per single batch. Fields include target bounding box coordinates, category labels, occlusion determination results, quality inspection scores, and more. Units are typically pixels or percentages, determined by the annotation team’s actual rules. The core data revolves around the position and category information of visual targets, differing from semantic processing scenarios for text annotation.

## What constraints these characteristics impose on workflow orchestration
Data sources for image annotation projects are scattered. These include independent image samples, annotation data exported from annotation platforms, category dictionaries, and inspection results. Workflow orchestration must support access to multi-source data and format verification. Data is updated daily or per single batch, so trigger conditions must be configured to match the update rhythm. Multiple types of associated daily documents require different parsing logic. Workflows must distinguish processing rules for nodes such as annotation specifications and bounding box examples. Fields for visual data, such as bounding box coordinates and occlusion determination results, must retain mapping relationships in the workflow to avoid field loss. Cross-team rework list circulation requires configured variable transfer rules to adapt to document collaboration needs of different teams.

## How to set configurations
This guide adapts to FastGPT v4.17.0 workflow orchestration features.

| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| Global variable verification rules | Enable verification only for nodes that depend on global variables | Avoid triggering redundant errors when switching nodes that do not require global variables |
| Workflow trigger conditions | Daily at 2:00 AM / after single batch data upload is complete | Match the daily or batch update rhythm of data for image annotation projects |
| `variables` parameter configuration | Only pass fields required by the current node (such as bounding box coordinates, category labels) | Reduce cross-node variable conflicts and adapt to the field characteristics of visual data |
| `nodeId` configuration rules | Assign unique identifiers based on node functions | Ensure unique identification of workflow nodes, avoid node confusion and configuration errors |
| Multi-source data access nodes | Configure access rules for image samples, annotation data, and category dictionaries separately | Adapt to scattered data sources and ensure accurate format verification for each data source |
| Document parsing node configuration | Set parsing logic separately for annotation specifications, bounding box examples, and quality inspection reports | Match the diverse types of daily associated documents and ensure parsing accuracy |

## Three common misconfigurations
- Phenomenon: When switching workflow nodes, even if the target node does not require global variables, a mandatory variable verification error from the previous node is triggered. Cause: The global variable verification rules for non-essential nodes are not turned off, leaving cross-node verification logic intact.
- Phenomenon: After the workflow is saved successfully, the configuration content is lost after refreshing the page. Cause: The save status was not confirmed after configuration was completed, or network fluctuations caused the save request to not fully synchronize to the server.
- Phenomenon: Global variables required for image annotation, such as category dictionary ID, cannot be passed correctly during API calls. Cause: The `variables` parameter was not configured as required, or the corresponding fields were not included in the request.

## How to confirm correct configuration
- Manually trigger the workflow once, check whether variable transfer between each node meets expectations, and confirm there are no redundant variable errors.
- Refresh the page after saving the configuration, check whether the configuration content matches the content during editing, and confirm the save logic is working properly.
- Call the corresponding API interface, check whether the request parameters include the global variables required by the current node, and confirm the transfer rules are effective.
- View the workflow trigger logs, confirm that the trigger conditions match the data update rhythm, and there are no abnormal trigger situations.

The values provided here are common starting points and should be measured against the reader's own samples.
