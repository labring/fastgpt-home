# Requirements and Design Document Drafting for Security Training and Phishing Drills: Workflow Orchestration

## What the data for this category looks like
The daily documents for this category include training courseware, drill plans, phishing email templates, and drill result reports. Data sources are employee contact lists, email gateways, internal training platforms, and user click statistics systems. The data update cycle is usually quarterly or annually. Document fields include drill audience scope, email trigger rules, click behavior data, rectification records, and more. Fields vary significantly across different documents, and some reports require combining data from multiple sources to generate.

## What constraints these characteristics impose on the workflow orchestration link
Since data sources are scattered and update cycles are long, workflow orchestration must support pulling static variables across data sources to avoid delays caused by frequent external interface calls. There is no unified standard for document fields, so dynamic field mapping nodes need to be configured to adapt to different templates and report formats. Drill audience screening relies on employee contact list data, so the workflow must support batch data reading and filter rule configuration. Incorrect node configuration may lead to missed audience selection and cause data leakage risks. The result review link needs to associate click statistics data, so the workflow must connect data aggregation and verification nodes to ensure review data is complete and traceable.

## Three Common Mistakes
- Workflows can only execute the first conversation node, with subsequent nodes unresponsive. The cause is that context variables for cross-node data transfer are not configured in `variables`, leading to interrupted data links between nodes.
- Unable to read the contents of uploaded Excel files. The cause is that no file format verification rules are configured for the data reading node, and only the default format is supported, leading to reading failures.
- Workflow execution times out, with the task status showing abnormal. The cause is that the timeout threshold is set too low and does not adapt to the time required for multi-data-source associated document generation.

## How to Confirm the Configuration Is Correct
- Manually trigger the workflow, check if the variable output of each node includes the corresponding data from employee contact lists and email gateways.
- Switch between different document types, confirm that the field mapping rules can automatically adapt to template formats.
- Simulate abnormal data input, check if the result verification node triggers corresponding prompts.
- Connect to external call channels, verify that the workflow can execute the full process as expected.
