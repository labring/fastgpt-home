# Requirements and Design Document Drafting for Security Training and Phishing Simulations: Forms and Interactions

## What the data for this category looks like
Core data sources for this category include employee directories, email gateways, internal training platforms, and phishing simulation click statistics systems. Daily delivered documents include standardized internal security training slides, quarterly phishing simulation plans, customized phishing email templates, and post-simulation review reports. Common document fields include simulation audience scope, email trigger rules, click behavior tags, rectification follow-up items, and more. Data update frequency is typically quarterly or annually, with the overall simulation framework adjusted alongside annual security planning. Temporary data from individual simulations is archived once the review is completed.

## What constraints these characteristics impose on forms and interactions
Dispersed data sources requiring cross-system pulling require integration with external business systems to enable multi-data source linked configuration, avoiding manual entry of duplicate information. Diverse document types with significant field differences require integration with external business systems to enable dynamic switching of form modules, adapting to the input requirements of different documents such as training slides, templates, and reports. Low overall update frequency but wide single adjustment scope requires integration with external business systems to retain historical version comparison functionality, allowing internal training teams to retroactively review adjustment records. Audience screening is the most time-consuming step, requiring integration with external user management systems to provide bulk selection and tagged user grouping functions, reducing manual workload. Phishing email template compliance requires verification, requiring integration with external verification systems to implement basic format verification rules, preventing accidental input of sensitive content.

## Three common mistakes
- Select configured options one by one in the user selection node `userSelect` and verify whether the workflow enters the corresponding branch; filtering records related to security training and phishing simulations must additionally verify the input, permissions, and return values of the external interface.
- The `formInput` module for phishing email templates does not set length limits, causing submitted body text to exceed the delivery limits of email service providers, resulting in send failure errors. The symptom is a system return message stating that the content is too long to deliver, which can be troubleshooted by comparing the submitted body length with the restriction rules of the connected external verification system.
- The form does not integrate an external file upload interaction entry, making it impossible to directly import existing content from training slides. The symptom is no file upload entry in the input box area, requiring manual copy-pasting of slide text, which can be troubleshooted by checking whether the form integrates an external file upload interaction entry.

## How to confirm configurations are complete
- Select configured options one by one in the user selection node `userSelect` and verify whether the workflow enters the corresponding branch; filtering records related to security training and phishing simulations must additionally verify the input, permissions, and return values of the external interface.
- Attempt to submit phishing email body text that exceeds the recommended length, check whether the connected external verification system pops up a corresponding prompt, and confirm that the format verification rules are active.
- Check whether the form integrates an external file upload interaction entry, and confirm that local document content can be imported directly.
- Simulate submitting a simulation configuration once, check whether the connected external business system can normally pull test data, and confirm that cross-data source linkage is working properly.
