# Requirements and Design Document Drafting for Security Baseline Checking: Forms and Interactions
This document is written based on FastGPT v4.17.0.

## What Data for This Category Looks Like
Data comes from server configurations, middleware configurations, security device policies, and baseline tool output results. Update frequency is monthly or quarterly.
Daily produced documents include baseline checklists, configuration verification records, rectification suggestions, and exception approval forms. Common document fields include configuration item names, compliance status, verification time, rectification measures, and exception approval opinions. No unified mandatory units apply. Some fields must match the configuration parameter format of corresponding devices.
Service subjects include security operation and maintenance personnel, security consultants, and internal control auditors. Core work focuses on verifying the compliance of configuration items.

## What Constraints These Characteristics Impose on Forms and Interactions
Dispersed data sources that require matching multiple device configurations mean external business system forms must support batch import of multi-source data and field mapping.
Low update frequency but need to retain historical versions. The interaction workflow requires external business systems to support version rollback and archiving.
Many daily document fields with no unified units require external business system forms to support custom fields and unit adaptation.
The most time-consuming configuration item verification process requires external business systems to provide batch selection and quick retrieval of configuration items.
The associated filling requirement for exception approval forms requires external business system forms to support cross-document field linkage.
Compliance status determination must strictly match baseline rules. External business systems must configure fixed enumeration verification to prevent invalid data entry.

## Three Common Mistakes
- Phenomenon: A "Field format mismatch" error pops up after form submission. Cause: No verification rules for the corresponding field are configured, and non-enumeration values are entered into the compliance status field.
- Phenomenon: Only some entries are successfully parsed when importing configuration data in batches. Cause: The field separator of the imported file does not match the preset format of the form.
- Phenomenon: AI-generated rectification suggestions displayed on the front end after embedding the form must be implemented by the external business system. The reason the backend cannot obtain complete suggestion content is that no callback interface after form submission is configured, and the generated answer data is not synchronized to the backend storage system.

## How to Confirm Configuration Is Complete
- Implement field verification rules via the external business system, manually enter a configuration item data that conforms to the enumeration rules, check whether a verification error is triggered after submission, and confirm that the field verification rules take effect.
- Implement the batch data import function via the external business system, upload a test CSV file that conforms to the format, check that the number of imported entries matches the expected value, and confirm that the batch import configuration is correct.
- Implement the exception approval association function via the external business system, associate a test exception approval form, check whether the form automatically fills in the approval number field, and confirm that the association configuration takes effect.
- Implement the version rollback function via the external business system, check the top navigation bar of the form, confirm that there is a version rollback entry, and check that the number of accessible historical versions meets the update frequency requirements.
