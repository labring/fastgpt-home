# Requirements and Design Document Drafting for Security Vulnerability Disclosure Handling: Forms and Interactions

This document provides configuration instructions based on FastGPT v4.17.0.

## What data for this category looks like
Data sources for this category include private vulnerability reports, code repositories, CVE numbering authorities, and public disclosure channels. Daily produced documents include security advisories, vulnerability reports, fix patches, and CVE application materials. Core fields cover vulnerability ID, impact scope, patched version, disclosure time, and impact assessment results. Each data update follows a single vulnerability event cycle. Each completed vulnerability disclosure process triggers one data update. The entire process involves sensitive information transfer across multiple collaborating roles.

## What constraints do these characteristics impose on the forms and interactions link
Since data sources include private vulnerability reports, forms must strictly restrict access permissions. Only authorized roles may view and edit content. Data updates follow single event cycles, so general templates do not need to be reused. The system must support full field entry for a single event’s end-to-end process. Core fields must align with specifications from code repositories and CVE authorities to avoid process blockages from missing fields. Sensitive information transfer must match permission divisions for multi-role collaboration. The role selection function of interactive components must link to the collaboration role list from external business systems. Permission control is implemented by the external business system or subsequent nodes.

## Three Common Mistakes
- Copy operations may fail to copy, or generated Markdown content lacks line breaks. Verification steps: Confirm whether the external copy logic has automatic line break rules configured. Confirm whether the output of the `formInput` node is correctly bound to the copy process.
- The `userSelect` component is not configured with the role permission scope of the external business system, allowing unauthorized users to view private vulnerability reports. Verification steps: Confirm whether the selectable range of the `userSelect` component only links to authorized roles from the external business system. Confirm whether the form permission settings are only open to project members.
- The vulnerability ID field is empty after form submission, making the CVE application process impossible to complete. Verification steps: Confirm whether the required validation rules include the vulnerability ID field. Confirm whether the required validation logic is triggered when the form is submitted.

## How to Confirm Configuration is Complete
- Log in to the system with a non-project member account, attempt to access the vulnerability disclosure processing form, and confirm that content cannot be viewed or submitted.
- Attempt to submit after filling in some required fields, and confirm that the system prompts that required fields are incomplete.
- Trigger the external copy operation, and confirm that the generated content includes correct line breaks.
- Select a role option from the `userSelect` component, and confirm that the form can correctly reference the selected role variable.
