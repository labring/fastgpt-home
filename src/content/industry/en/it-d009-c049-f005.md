# Requirements and Design Document Drafting for Customer Training and Usage Manuals: Multi-turn Dialogue and Prompts

## What data for this category looks like
Data for customer training and usage manuals is created by customer success managers, training instructors, and product operations teams. Daily documents include training slides, user manuals, training attendance sheets, and question and answer lists. Data sources include product help centers, customer organizational structures, training recording videos, and ticket systems. Update frequency is adjusted based on customer orders or product versions, with one update per order or version. The most time-consuming document writing tasks focus on role permission explanations, operation step demonstrations, and post-class question organization. This content must be adjusted to match the customer’s actual organizational structure and the latest product version details.

## Constraints Imposed on Multi-turn Dialogue and Prompt Configuration
The data characteristics of this category impose multiple constraints on multi-turn dialogue and prompt configuration. Data sources cover multiple types including text, audio and video, and structured data. As a result, multi-turn dialogue must support recall and integration of cross-source data to avoid limitations from a single data source. Update frequency is adjusted based on orders or product versions, so prompts must support dynamic injection of the latest version documents and customer-specific data to prevent lagging generated content. The most time-consuming tasks focus on permission explanations and step demonstrations, so multi-turn dialogue must prioritize recalling document content from these tasks to reduce interference from irrelevant information. Document types are diverse, including slides, manuals, attendance sheets, and others. This means the system must adapt to the field structures of different documents to ensure generated content conforms to the format requirements of the corresponding document.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `messages` | Retain the last 15 rounds of dialogue context, with no more than 800 characters per round | Adapts to the frequently updated document characteristics of this category, and avoids request timeouts caused by overly long context |
| `variables` | Enable customer-specific data injection, including organizational structure and ticket keywords | Matches the characteristic that data sources for this category include customer organizational structures, and ensures generated content aligns with actual customer scenarios |
| `chatId` | Bind the session ID corresponding to the target customer, with a single session valid for 7 days | Adapts to the session management rules of FastGPT v4.17.0, and ensures data isolation for training documents across different customers |
| Multi-turn context token limit | No more than 12000 tokens, calibrated based on actual testing | Matches the requirement for multi-source data integration in this category, and avoids exceeding platform processing thresholds |
| Document recall priority | Prioritize recalling documents related to role permissions and operation steps | Matches the characteristic of the most time-consuming tasks in this category, and focuses generation on core content |

## Three Common Misconfigurations
- Dialogue pages crash with a 500 status code. The cause is failure to limit the context length of `messages`, resulting in request payloads exceeding platform load thresholds.
- Knowledge base pages fail to load, with associated training slide metadata empty. The cause is incorrect configuration of `variables` for injecting customer organizational structure department information, resulting in failed document matching.
- Guidance prompts do not take effect, with generated operation steps inconsistent with actual manuals. The cause is failure to pass the latest content from the product help center as dialogue context, resulting in generated content lagging behind version updates.

## How to Confirm Correct Configuration
- Initiate a test dialogue, enter a question related to role permissions, and check if the returned content includes permission explanations from training slides.
- Trigger a multi-turn dialogue, verify that the context retains the last 10 rounds of interaction content, and confirm that the `messages` configuration is active.
- Call the session associated with the `chatId` parameter, and check if variable data has been correctly injected with customer-specific organizational structure information.
- Update one version document, submit a generation request, and check if the generated manual content includes the latest version details.

The values provided here are common starting points, and should be evaluated against local test samples.
