# Requirements and Design Document Drafting for Customer Training and Usage Manuals: Workflow Orchestration

## What the data for this category looks like
The core data for this category includes four types of documents: training courseware, user manuals, training attendance sheets, and question and answer lists. Data sources are mainly the product help center, customer organizational structure, training recording videos, and ticket system. Update frequency is per order or per version, synchronized with customer requirements or product version iterations. Document fields include role permission descriptions, operation step entries, and question and answer pairs. The length of a single document is adjusted based on customer scale and training content, with no mandatory fixed unit.

## What constraints do these characteristics impose on the "workflow orchestration" link
The data sources for this category are scattered and updated frequently, so the workflow must support automatic pulling and integration of multi-source data to avoid errors caused by manual copy-pasting. The structure of different types of documents varies greatly, so the workflow must adapt to the input and output formats of different nodes, and separately handle the generation logic for courseware, manuals, and attendance sheets. The most time-consuming links of role permission explanations and operation step demonstrations must be split and optimized via the workflow to automate repetitive verification and generation actions. At the same time, document quality directly affects customer user experience, so the workflow must add a content verification link to avoid incorrect permission descriptions or operation steps.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow trigger rule | Triggered by customer version updates or training plan milestones | Matches the update frequency of this category per order or per version |
| Context window configuration | 800–1200 characters | Adapts to the single-paragraph content length of user manuals and training courseware |
| Tool call switch | Enabled only during knowledge base retrieval | Avoids redundant knowledge base reference output |
| Timeout threshold | 600 seconds | Covers the processing duration of multi-source data integration |
| Variable binding setting | Bind customer organizational structure fields in `variables` | Adapts to role permission configuration for training courseware |
| Node ID verification | Fix `nodeId` as the training document generation node | Ensures uniqueness of workflow links |

## Three common mistakes
- Workflow runtime timeout: The symptom is that the node status shows timeout, with a 504 status code returned. The cause is that a reasonable timeout threshold is not set, and the multi-source data integration link is not split.
- Redundant knowledge base references in output: The symptom is that reference content of `input` and `response` appears in the generated training documents. The cause is that the unnecessary knowledge base search reference switch is not turned off during the tool call link.
- Incorrect variable binding: The symptom is that role permission configuration is missing in the generated documents. The cause is that the customer organizational structure fields in `variables` are not bound correctly, or the `nodeId` configuration is incorrect, causing abnormal link execution.

## How to confirm the configuration is correct
- Check that the AI Proxy-related environment variables of the App/Admin server have been correctly configured, and ensure that FastGPT v4.17.0 passes startup verification.
- Trigger a test workflow, and check whether the output content only includes the training document body, with no redundant `input` and `response` reference fields.
- Verify that variable binding takes effect, and the generated document includes the corresponding customer's role permission description content.
- Confirm that the workflow trigger rule matches the current version update or training plan milestone, and manual trigger test runs are available.

The values provided are common starting points and should be measured against the reader's own samples.
