# Requirements and Design Document Drafting for Customer Onboarding and Tenant Initialization: Context and Token

## What the data for this category looks like
Core data for this category comes from four systems: CRM, contract order, identity management, and product backend. Update frequency is per order or daily. Daily deliverable documents include onboarding application forms, tenant configuration sheets, administrator account lists, and delivery confirmation forms. Data fields include customer ID, tenant identifier, administrator account list, permission configuration items, and onboarding status. Units include number of accounts, number of configuration entries, and timestamps. This data is generated around a single customer onboarding and tenant initialization workflow. Associated stakeholders include SaaS implementation consultants, customer success managers, and operations onboarding personnel.

## What constraints do these characteristics impose on the context and token workflow
Multiple data sources require context to integrate fields from four systems including CRM and contract orders. Improper data trimming will lead to excessive token usage. The per-order or daily update frequency requires context to bind exclusive data for a single workflow, to avoid loading redundant information across cycles. The fixed document structure requires context to extract and match document field priorities, prioritizing core content such as administrator accounts and tenant configurations to reduce invalid token consumption. The most time-consuming customer information verification step requires context to prioritize loaded verified valid data, avoiding repeated processing of unconfirmed information and improving token usage efficiency.

## How to set the configuration
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| Max Context Window | 8000–12000 token | Matches the multi-source data integration needs of tenant initialization scenarios, avoids token overflow |
| Max Reference Token Count | 2000–3000 token | Prioritizes loading key fields of core documents, controls token consumption for a single context |
| Context Refresh Trigger Condition | Triggered after onboarding application submission | Matches the per-order or daily data update frequency, avoids invalid refreshes |
| Context Loading Priority | Load in the order of administrator account list, tenant configuration sheet | Aligns with the priority of core fields in daily deliverable documents, reduces invalid token usage |
| Context Filter Threshold | Calibrated via actual testing | Onboarding data fields vary widely across customers, requires adaptation to actual scenarios |

## Three common misconfigurations
- Symptom: The FastGPT workflow API returns an empty context, even when context is configured for the workflow. Cause: No exclusive data source for the tenant initialization scenario is bound in the workflow, so the system cannot match the corresponding customer's onboarding data.
- Symptom: Token consumption shows abnormal fluctuations, exceeding expected limits. Cause: No upper limit is set for context loading token count, leading to token consumption exceeding billing standards during multi-source data integration.
- Symptom: Team data returned by team switch API is not updated synchronously. Cause: Context does not real-time associate the latest team data from the identity management system, so old data carried by tokens is not refreshed.

## How to confirm correct configuration
- Submit a test onboarding application form, check if the automatically loaded context includes the corresponding customer's CRM information and contract order data.
- Call the workflow API related to tenant initialization, confirm that the context carried in the returned result does not contain irrelevant redundant fields.
- View token consumption records in the product backend, confirm that token consumption for a single initialization workflow falls within the preset configuration range.
- Verify that the context loading order of the administrator account list matches the configured priority.

The values provided are common starting points and should be measured against the reader's own samples.
