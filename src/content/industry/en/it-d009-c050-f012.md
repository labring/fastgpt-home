# Requirements and Design Document Drafting for Customer Onboarding and Tenant Initialization: Document Parsing and Chunking

## What the data for this category looks like
This category’s core data is sourced from CRM systems, contract orders, identity management systems, and product backends. Daily involved documents include customer onboarding application forms, tenant configuration sheets, administrator account lists, and delivery confirmation documents. Data updates occur once per order or per day. Each document contains fixed-format field groups, such as customer main body information, permission configuration items, and account list details. No free-form large blocks of text are present. The overall structure is orderly, and field boundaries are clearly defined.

## Constraints on Document Parsing and Chunking
The structured nature of category documents requires that parsing and chunking strictly preserve field boundaries, to avoid splitting cross-field configuration items. Data sources are scattered, and individual document sizes vary widely, so the system must adapt to format differences across documents from different sources. The update frequency of once per order or per day means the parsing process must support rapid processing of individual, independently delivered documents, to avoid resource preemption by batch tasks. Sensitive fields such as permission configurations and account information in documents must be accurately extracted, and chunking logic must match the field association relationships of the business scenario.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale for This Setting |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Category documents are mostly structured forms; each chunk must cover a complete field group to avoid splitting critical configuration items |
| `chunkSplitter` | Split by paragraph + fixed characters | Category documents include fixed-format application forms and configuration sheets; paragraph separation preserves the logical integrity of fields |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Individual delivery documents may include multiple attachments, requiring adaptation to long-duration parsing scenarios |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Category documents may include bulk administrator account lists or large configuration sheets |
| `customPdfParse` | Enabled | Category documents mostly consist of standardized PDF-format onboarding application forms; custom parsing enables accurate field extraction |
| `chunkSettingMode` | Manual configuration | Document formats vary across delivery orders; manual configuration allows adaptation to specific scenarios |

## Three Common Misconfigurations
- Phenomenon: FastGPT reports a PDF parsing timeout, but the PDF parsing service shows success. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` configuration value is lower than the actual required parsing duration, and does not adapt to the bulk attachment scenario of category documents.
- Phenomenon: After uploading a file, the large language model does not trigger file parsing. Cause: The `chunkSettingMode` is set to automatic mode, which does not match the fixed-format trigger conditions for category documents.
- Phenomenon: After uploading an Excel-format tenant configuration sheet, the parsing result cannot read table content. Cause: The `chunkSplitter` configuration is not adjusted for structured table documents, and the default chunking logic does not preserve table row and column association relationships.

## How to Confirm Proper Configuration
- Upload a standard customer onboarding application form PDF, and check if the parsed chunks include complete customer information and permission configuration fields.
- Upload a single document under 1000 MB, and confirm that no timeout error is triggered during the parsing process.
- Adjust `chunkSettingMode` to automatic mode, and verify that the chunking logic can automatically adapt based on document format.
- View the file parsing log in the FastGPT v4.17.0 product backend, and confirm that the parsing duration falls within the range configured by `PARSE_FILE_TIMEOUT_SECONDS`.

The values provided are common starting points and should be evaluated against samples from the target deployment environment.
