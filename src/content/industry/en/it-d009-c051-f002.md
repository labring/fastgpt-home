# Requirements and Design Document Drafting for Customer Data Import Migration: Context and Token

## What this type of data looks like
This type of data mainly comes from customer legacy systems, CSV or Excel templates, database exports, and product import logs. Update frequency is per order or irregular. Daily deliverables include data templates, migration plans, field mapping tables, and migration validation reports. Core fields include source system field names, target system mapping rules, data validation rules, import batch numbers, etc. Data volume fluctuates with customer business scale, with no fixed unit standard.

## What constraints do these characteristics impose on the context and token workflow
Diverse data sources lead to inconsistent formats. Context processing must support field mapping logic for multi-source data to avoid token overflow. Irregular update frequencies mean that the context of import batches must be managed separately, and fixed context templates cannot be reused. Mapping rules for core fields must be embedded in the context to ensure that token statistics cover mapping logic and validation rules, preventing import failures caused by field misalignment. Fluctuating data volume requires that context and token configurations adapt to the import scale of different batches, preventing single processing from exceeding system thresholds.

## How to set configurations
The configuration items for FastGPT v4.17.0 are as follows:
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–15000 token | Adapts to field mapping and validation logic for multi-source import data, avoids context overflow |
| `quoteMaxToken` | 1000–2000 token | Covers field mapping rules and validation descriptions for a single import batch, ensures complete context |
| Maximum context cache duration | 3600 seconds | Matches the irregular import batch cycle, prevents mapping errors caused by expired context |
| Import field mapping context switch | Enabled | Ensures token statistics cover field mapping logic, prevents field misalignment caused by missing rules |
| Single import token limit | Calibrated based on actual testing | Adapts to the business data volume of different customers, avoids system overload |

## Three common misconfigurations
- Phenomenon: Import tasks trigger a "token limit exceeded" error, but the import log does not show the specific overflowed context content. Cause: Detailed token statistics configuration for context is not enabled, making it impossible to locate the overflowed field mapping or validation rule.
- Phenomenon: Import tasks deployed on cloud instances cannot find the token-related settings entry. Cause: FastGPT cloud instance versions hide advanced configuration items by default. Configuration permissions must be obtained via permission application or by switching to the standard edition.
- Phenomenon: After an import batch is completed, historical context is not cleared, leading to field mapping misalignment in subsequent batches. Cause: No automatic context clearing rule is configured after import tasks complete, and the context cache is not updated with the batch.

## How to confirm configurations are correct
- View the context logs of import tasks to confirm that field mapping rules are included in the token statistics scope.
- Test a small-scale import batch, check whether token consumption matches the configured `maxContext` and `quoteMaxToken` values.
- Check the configuration entry for cloud instance versions, confirm that token-related setting items are displayed and can be modified.
- Complete a single import batch, verify that the context cache is automatically cleared to avoid affecting subsequent batches.

The values provided here are common starting points and should be evaluated against the reader's own samples.
