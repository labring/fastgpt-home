# Requirements and Design Document Drafting for Customer Data Import Migration: Document Parsing and Chunking

## What This Category of Data Looks Like
This category of data mostly originates from customer legacy systems, CSV or Excel templates, database export results, and product import logs. Daily produced documents include data templates, migration plans, field mapping tables, and migration validation reports. Update cycles are adjusted irregularly for individual projects. Document structure is split according to migration workflows. Field mapping tables contain content such as business field names, target system field names, data formats, and validation rules. The number of fields per single document varies widely based on customer business complexity.

## What Constraints Do These Characteristics Impose on the "Document Parsing and Chunking" Link
This category of data includes structured tables and unstructured plan documents. Parsing must support content extraction for both formats. Field mapping tables have tight field association relationships. Chunking must retain the full context of a single mapping rule, and avoid splitting cross-field mapping logic. Some documents are PDF-format field mapping tables and migration plans. Custom parsing rules must be adapted to preserve original typesetting information. Document scale varies significantly across different projects. The system must support full migration logs ranging from single-page templates to hundreds of pages.

## How to Configure the Settings
These configuration items are based on official settings for FastGPT v4.17.0, as detailed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the length of single rules in field mapping tables, avoids splitting complete field association logic |
| `chunkSplitter` | Split by paragraph + heading | Matches the structured chapter divisions of migration plans and validation reports, retains document logical structure |
| `customPdfParse` | Enabled | Adapts to PDF-format migration documents and field mapping tables, supports specifying custom parsing parameters via API |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports single bulk exported database logs or large customer data templates |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Meets full parsing time requirements for large migration plan documents, avoids mid-process interruptions |
| `chunkSettingMode` | Manual configuration | Adapts to document format differences across projects, allows flexible adjustment of chunking and parsing parameters |

## Three Common Mistakes
- Failing to enable the `customPdfParse` configuration, which causes uploaded PDF-format field mapping tables to fail to extract embedded fields correctly, resulting in empty field parsing results. The default parsing rules do not adapt to PDF embedded form structures, and recent default rule updates break compatibility with older document formats.
- Setting `PARSE_FILE_TIMEOUT_SECONDS` to less than 300 seconds, which triggers a timeout error and returns a 504 status code when processing migration plan documents with more than 500 pages. Large document parsing times exceed the preset threshold.
- Selecting `chunkSplitter` as character-based splitting, which causes cross-row mapping rules in field mapping tables to be truncated, resulting in misaligned field parsing results. Full context association of mapping rules is not retained.

## How to Confirm Proper Configuration
- Upload a single PDF-format field mapping table, check that the parsing result contains complete field names and mapping rules, with no truncated or missing content.
- Check the system upload file limit prompt, confirm that the `UPLOAD_FILE_MAX_SIZE` configuration value matches the actual maximum uploadable file size.
- Submit a migration plan document with more than 100 pages, wait for parsing to complete, confirm no timeout error logs are generated.
- Switch `chunkSettingMode` to manual configuration, modify `chunkSize` to 1000 characters, verify that chunking result lengths match the preset value.

The values provided are common starting points and should be measured against the reader's own samples.
