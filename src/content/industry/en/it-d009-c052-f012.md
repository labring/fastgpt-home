# Requirements and Design Document Drafting for Customer Permission and Organization Architecture Configuration: Document Parsing and Chunking

## What the data for this category looks like
Documents in this category typically include permission matrices, organization architecture tables, role configuration records, and permission change forms. Data sources include customer HR systems, identity directories, product backends, and audit logs. Update frequency is per request or irregular. Most document structures have hierarchical fields such as departments, roles, and permission items. Some documents present permission mapping relationships in table form. There are no unified fixed units for fields. Values are adjusted flexibly based on the customer’s actual business scenarios.

## Constraints Imposed on Document Parsing and Chunking
Format differences across multiple data sources require the parsing link to adapt to both structured table and unstructured text inputs. This prevents loss of critical permission association information. Irregular update frequencies mean the parsing link must support incremental processing logic. This reduces resource consumption from repeated full-data parsing. Hierarchical document structures require the chunking link to preserve contextual associations. This prevents damage to department and role permission mapping relationships after splitting. The chunking link must also support custom field configurations from different customers. This prevents generic chunking rules from truncating critical content.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapt to the field density of permission matrices and organization architecture tables. Avoid including cross-hierarchy permission association information in a single chunk |
| `chunkSplitter` | Split by title hierarchy | Match the title hierarchy structure of daily documents. Preserve association relationships between departments and roles |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Address parsing time consumption for large files exported from identity directories. Avoid interrupting the parsing process mid-run |
| `customPdfParse` | Enabled | Adapt to PDF format documents such as permission change forms. Preserve field alignment effects from original typesetting |
| `chunkSettingMode` | Manual configuration | Adapt to differences in document formats across customers. Avoid automatic chunking from damaging permission mapping logic |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Support batch-imported organization architecture tables and audit log files. Meet multi-customer data import requirements |

## Three Common Configuration Mistakes
- Only partial fields are returned after uploading a permission matrix table. This occurs because the `customPdfParse` configuration is not enabled, or the `chunkSize` value is too small, truncating cross-page permission mapping content.
- Parsing nodes become unresponsive after local deployment. This occurs because the `PARSE_FILE_TIMEOUT_SECONDS` value is too low, or the `UPLOAD_FILE_MAX_SIZE` limit blocks large file uploads. This prevents identity directory export files from completing parsing.
- Multi-account same-team configuration cannot be created. This occurs because hierarchical fields in the organization architecture table are not correctly extracted during chunking. This prevents the system from recognizing association relationships between departments and roles.

## How to Verify Successful Configuration
- Upload a test permission matrix table. Check if parsed chunks include complete combinations of department, role, and permission fields.
- Upload a single test file of maximum allowed size. Confirm the parsing progress bar completes without timeout errors.
- Import batch data exported from an identity directory. Verify that the number of organizational layers in the parsed results matches the source file.
- Check FastGPT v4.17.0 system logs. Confirm there are no error records for chunking failures or field loss.
