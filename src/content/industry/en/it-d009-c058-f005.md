# Drafting Requirements and Design Documents for Advertising Compliance Traceability: Multi-turn Dialogue and Prompt Words

## What the Data for This Category Looks Like
This category's data comes from advertising platform backends, customer qualification documents, contract systems, and publicly available regulatory rules. The update frequency is once per campaign or monthly. Daily processed documents include advertising review forms, qualification attachments, delivery records, and rectification notices. Most document fields include campaign ID, delivery period, qualification number, compliance status, rectification requirements, and similar items. The length of individual documents varies widely. Documents must be archived and stored by campaign batch.

## Constraints on Multi-turn Dialogue and Prompt Word Workflows
Decentralized data sources require integrating input content across systems. Multi-turn dialogue must support context linking across data sources. Update frequencies are not fixed. Prompt words must adapt to full-process documents for a single campaign. Document fields are diverse and must strictly match compliance requirements. Multi-turn dialogue context must retain field association information. The consequences of errors are severe. The dialogue process must ensure complete evidence retention, and avoid context loss or field omissions. Scenarios often require linking multiple qualification documents and delivery records. Clear context length limits for dialogue and knowledge base association upper limits must be set to avoid input exceeding limits.

## Configuration Guidelines
This document is based on FastGPT v4.17.0 configuration instructions.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Generate a unique value per campaign batch | Ensure dialogue context in the same scenario is bound to the corresponding advertising campaign, and avoid confusion across campaigns |
| `messages` | Retain the most recent 20 rounds of dialogue content | Cover the full process of dialogue from review to rectification for a single advertising campaign, and avoid context truncation that loses key compliance evidence |
| `variables` | Bind three types of variables: campaign ID, delivery platform, and compliance type | Automatically fill document fields, and ensure generated requirement document fields fully match business requirements |
| Maximum context length | 8000–12000 characters | Adapt to the total character count of a single advertising review form and multiple qualification attachments, and avoid input exceeding limit errors |
| Knowledge base association upper limit | Calibrate based on actual testing | Cover three data source types: regulatory rules, customer qualifications, and delivery records, and meet full information requirements for compliance traceability |
| Auto-trigger default questions | Load during dialogue initialization | Automatically push compliance review points for the current campaign, and reduce manual input steps |

## Three Common Configuration Mistakes
- Phenomenon: Dialogue prompts that input character count exceeds the limit. Compliance documents cannot be submitted. Cause: The maximum context configuration is not adjusted based on the character span of category documents. Using default values directly causes single campaign documents to exceed the limit.
- Phenomenon: Preview works normally after linking the knowledge base, but an error occurs during formal dialogue. Cause: Knowledge base association parameters are not synchronized in the corresponding environment. Cross-environment configurations do not take effect synchronously.
- Phenomenon: Default questions are not loaded after dialogue initialization, and manual input is required. Cause: The configuration for auto-triggering default questions during dialogue is not enabled, or the default questions are not bound to compliance variables for the current campaign.

## How to Verify Successful Configuration
- Submit a typical advertising campaign document package. Check whether the dialogue can normally receive and generate corresponding content. Confirm there are no character exceeding limit errors.
- Check whether `chatId` is automatically generated per campaign batch. Ensure dialogue context for the same campaign is bound correctly.
- Verify that `variables` automatically fill fields such as campaign ID and delivery platform. Confirm there are no null values or incorrect fields.
- Enable dialogue initialization testing. Confirm whether default questions are automatically loaded. Confirm they match the compliance points of the current campaign.

The values provided are common starting points and should be measured against the reader's own samples.
