# Drafting Requirements and Design Documents for Advertising Compliance Logging: Workflow Orchestration

## What This Category of Data Looks Like
This category of data primarily comes from advertising platform backends, customer qualification documents, contract systems, and publicly released regulatory rules. Key daily deliverables include advertising review forms, qualification attachments, delivery records, and rectification notices. Data updates align with individual advertising campaigns or natural monthly cycles. Each data entry includes fields such as advertising delivery subject, compliance review number, qualification validity period, delivery period, and rectification records. No fixed uniform upper limit exists for the size of a single data entry; it fluctuates based on the scale of the advertising campaign.

## Constraints Imposed on Workflow Orchestration
Decentralized data sources require the workflow to interface with multiple system APIs, and cross-source data pull nodes must be configured to adapt to the format requirements of different data sources. Diverse document types require the workflow to support multi-format input, including text parsing and attachment extraction sub-nodes to process unstructured data such as qualification attachments. Fluctuating update frequencies tied to campaigns require support for both on-demand and scheduled triggering modes to avoid unnecessary execution. The strong evidence requirement for compliance logging mandates full workflow traceability: bind `variables` to record the execution status and results of each operation node, and bind `nodeId` to mark node identities for subsequent audits. Fluctuating single data entry sizes based on campaign scale require sufficient context processing space to avoid context overflow errors.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Single Search Limit | Top 3-5 entries | The number of compliance items in a single delivery record data entry typically ranges from 3 to 5, matching the compliance check scope of a single campaign |
| Maximum Context | 8000-12000 token | The text length of advertising review forms and rectification notices varies widely, so sufficient space is reserved to accommodate multi-document concatenation |
| Variable Storage | Enable full-link recording | Compliance logging requires retaining execution results for each step; bind `variables` and `nodeId` nodes to record execution status and node identities |
| Trigger Mode | On-demand triggering + scheduled triggering | Data updates fluctuate with campaigns and monthly cycles; on-demand triggering adapts to temporary campaigns, while scheduled triggering adapts to monthly archiving |
| Attachment Parsing Rules | Auto-adapt by file format | Data includes multi-format files such as qualification attachments; auto-adapting parsing rules covers common compliance document formats |

## Three Common Misconfigurations
- The workflow only supports single-node calls, and nested multi-workflows in the main Bot are not supported. The symptom is that no matching options appear when searching for sub-workflow nodes in the node library of the Bot configuration panel. The cause is that workflow nesting permissions are not enabled, or the target workflow is not set as a publicly callable external node.
- The text processing module is missing after importing a third-party JSON workflow. The symptom is that the imported workflow configuration includes text processing nodes, but the module cannot be found in the local editor's node library. The cause is that the local FastGPT version is lower than v4.17.0; this module was added in v4.17.0 and later versions.
- Workflow export fails or exported content is incomplete. The symptom is that no download response occurs after clicking the export JSON button, or the exported JSON file lacks configuration parameters for some nodes. The cause is that there are unsaved draft nodes in the workflow, or the node configuration includes unauthorized external reference links.

## How to Verify Successful Configuration
- After triggering the workflow, review the execution logs recorded by the `variables` node to confirm that all cross-source data pull nodes have successfully retrieved corresponding documents with no error messages.
- Run the workflow and input a single advertising campaign data entry, then check that the output includes all required document fragments such as advertising review forms and delivery records, with complete fields.
- Attempt to add this workflow node in the main Bot's node library, confirm that it can be normally selected and configured with call parameters, with no abnormal prompts.
- Export the workflow as a JSON file, decompress the file and verify that it contains all configuration nodes and parameters with no missing content, and that it can be re-imported normally.

The values listed above are common starting points and should be evaluated against your own samples.
