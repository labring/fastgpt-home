# Requirements and Design Documentation for Ad Creative Review: Forms and Interactions

## What data for this category looks like
This category's data comes from ad delivery platforms, landing page hosting services, product qualification filing systems, and advertising law compliance clause libraries, with a daily or real-time update frequency. Daily processed documents include single ad creative files, landing page screenshots, review opinion sheets, and modification record ledgers. Data fields include creative copy content, landing page URLs, product qualification numbers, violation type tags, and review statuses. There are no unified fixed units, and the length of single creative copy varies widely, ranging from tens to thousands of characters.

## What constraints these characteristics impose on forms and interactions
Data sources are scattered and updates are real-time. Batch import of multi-source data and business verification logic are implemented separately by external business systems. The form is responsible for collecting input to avoid errors from manual entry. There are diverse document types, so the form must support uploading materials and screenshots in different formats. The interaction link must distinguish verification rules for text and image inputs; this verification logic is implemented separately by external business systems to prevent unsupported formats from being submitted. The length of single creative copy varies widely, so an external business system must implement a self-adapting height text input box. The `formInput` node is responsible for collecting input information, and the timing of automatic violation content recognition must be limited to avoid resource waste. The multi-stage circulation of the review process requires the form to retain operation log fields for subsequent traceability of modification records. The review status synchronization logic is implemented separately by external business systems to ensure information consistency.

## Three common mistakes
- Phenomenon: The backend returns empty results or an error after submitting a txt file. Verification steps: Check whether the file upload parsing configuration of the external business system is correct, and confirm whether the `formInput` node correctly passes file data to subsequent nodes.
- Phenomenon: When reviewing materials in batch, subsequent workflow nodes cannot obtain previously generated review results. Cause: The data transfer logic between workflow nodes is not configured correctly, resulting in input data from the `userSelect` node not being passed to subsequent workflow nodes.
- Phenomenon: After setting a high reference limit, the returned results exceed the token limit. Cause: The workflow's context accommodation configuration is not adjusted based on the length of the creative copy, and the token consumption for a single review is not limited.

## How to confirm the configuration is complete
- Upload test ad creative files, verify whether the external business system's format verification logic works normally, and confirm whether the `formInput` node correctly passes file data to subsequent nodes.
- Trigger the review process and check whether data is transferred between each node as expected.
- Adjust configuration items, and verify whether the review information synchronization logic between external business systems works normally.
- Simulate batch submissions, and confirm that the submission limit of the `formInput` node matches actual processing capabilities.
