# Drafting Requirements and Design Documentation for Ad Account Opening Audit: Context and Token

## What data for this category looks like
This category of data typically comes from ad platform backends, the National Enterprise Credit Information Publicity System, customer-submitted account opening application materials, and industry access rules. Commonly processed documents include account opening application forms, business license scans, industry-specific operation qualification documents, and historical account opening audit records. Data updates follow a rhythm of daily synchronization or on-submission updates. Document structures include fields such as main identity information, industry category, qualification validity period, and audit node records. There is no unified fixed unit, as details vary by material type.

## What constraints do these characteristics impose on the context and token workflow
Multi-source heterogeneous data formats include structured forms, text descriptions, and scanned document transcriptions. This typically requires context processing to adapt to token allocation rules for different formats. High-frequency small-batch on-submission updates typically require flexible adjustment of the context window to avoid redundant token usage. Time-sensitive content such as qualification validity periods and industry access rules typically requires limiting the context time range to prevent expired data from interfering with audit judgments. The volume of historical audit record data increases with application forms, so total context token volume must be strictly controlled to avoid exceeding model processing limits.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context window | 8000–12000 token | Matches the total token count of a single account opening audit material plus 3 historical audit records from the past 30 days, aligning with standard processing thresholds for FastGPT v4.17.0 |
| Quote maximum token limit | 1500–2000 token | Ensures valid qualification information extracted from multi-source materials does not exceed model processing limits, avoiding truncation of key fields |
| Context time range | Past 30 days | Filters expired industry rules and historical audit records, reducing invalid token usage |
| Context chunk length | 800 characters | Matches the typical paragraph length of account opening materials, reducing token fragmentation after chunking |
| `maxContext` | Calibrated via actual testing | Adapts to the data return volume of different ad platform backend APIs, avoiding errors caused by exceeding data limits |
| `quoteMaxToken` | Calibrated via actual testing | Adapts to the token length of transcribed qualification materials in different formats, optimizing extraction accuracy |

## Three common configuration mistakes
- Phenomenon: ACCESS_TOKEN-related errors occur when configuring ad platform APIs. Cause: API keys from other platforms were incorrectly entered into the token field of the ad platform interface, and the authorized token for the target ad platform was not used.
- Phenomenon: Token usage exceeds the single-run limit in a multi-model orchestrated audit workflow, resulting in truncated audit results. Cause: Independent context parameters were not set for each model node, and the combined context data of multiple models exceeds the window limit.
- Phenomenon: An excessively large context window causes service processing timeouts. Cause: The context time range was not limited, and excessive historical audit records were retrieved, occupying too many tokens and causing processing delays.

## How to confirm the configuration is correct
- Import a single complete account opening application and qualification material, check that all fields are displayed after context loading, with no truncation prompts.
- Run a test workflow with multi-model orchestration, view the token consumption statistics for each node, and confirm that the context parameters for each node take effect independently.
- After configuring `quoteMaxToken`, extract key fields from qualification materials, and verify that transcribed content is not truncated prematurely.
- Perform a local test in a network-free environment, confirm that no `maxContext`-related data source errors occur when the service starts.

The values provided are common starting points and should be measured against the reader's own samples.
