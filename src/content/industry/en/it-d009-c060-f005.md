# Drafting Requirements and Design Documentation for Ad Account Opening Audits: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
The data for this category primarily comes from ad platform backends, the National Enterprise Credit Information Publicity System, customer-submitted account opening application materials, and industry access rules. Data updates occur daily or are triggered by each individual account opening application. Daily processed documents include account opening application forms, scanned business licenses, corresponding industry qualification documents, and audit records. Data fields include subject name, unified social credit code, advertising industry category, audit node status, and others. There are no unified fixed units, as values vary based on document type.

## Constraints Imposed on the Multi-turn Dialogue and Prompt Engineering Link
Decentralized data sources including both structured and unstructured content require multi-turn dialogue to support cross-data-source information retrieval and integration. Update frequency triggered per application requires that dialogue contexts be isolated per single application session to avoid mixing data across applications. Diverse document types require prompt engineering to adapt to field extraction rules for different documents, such as extracting the unified social credit code from business licenses and matching categories for industry qualification documents. Subject qualification verification and industry judgment are time-consuming steps, requiring multi-turn dialogue to trigger step-by-step verification prompts to reduce repeated communication. Additionally, potential consequences of errors include account opening failure, non-compliant advertising, and customer complaints. The dialogue flow must ensure the accuracy of information extraction to avoid compliance risks caused by incorrect judgments.

## Configuration Settings
The following configurations are based on the functional logic of FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique business number of a single account opening application | Ensure each audit session is tied to its corresponding application to avoid mixing data across applications |
| `messages` | Retain all interactive content within the current application session, with a 12,000-character limit | Cover the full qualification verification and communication process, support retrospective review of historical audit nodes |
| `variables` | Preload variables for unified social credit code, advertising industry category, and customer qualification status | Quickly call existing structured data to reduce repeated queries |
| Session timeout threshold | 600 seconds | Match the typical processing duration of a single ad account opening audit, preventing premature session termination |
| Context overlap length | 200 characters | Adapt to content coherence of qualification documents, reducing information gaps |
| Automatic question optimization | Enabled | Convert vague verification requests into clear field extraction instructions, adapting to extraction rules for multiple types of qualification documents |

## Three Common Configuration Errors
- Failure to bind `chatId` to the unique identifier of the account opening application, resulting in mixed audit session contexts across different applications and incorrect cross-application information display. This occurs because the session isolation logic is not linked to specific business applications, and contexts are not isolated per application.
- Setting the conversation timeout threshold too low, triggering premature session termination and clearing incomplete qualification verification content stored in `messages`. This occurs because the timeout value does not match the actual duration of the audit process and fails to cover the full material correction communication phase.
- Receiving empty results when calling associated tools to generate qualification verification progress charts, unable to display the audit node distribution for the corresponding application. This occurs because the pre-defined audit status fields in `variables` are not correctly mapped to the tool's data source parameters, and field matching rules are missing.

## How to Verify Correct Configuration
- Initiate a simulated account opening application session, check that `chatId` is bound to the unique application identifier, and that interactive content within the session does not appear in other application sessions.
- Simulate a process including multi-round qualification verification and communication, confirm that the session does not terminate prematurely within the preset timeout threshold, and that all interactive content is fully recorded.
- Call associated tools with the pre-defined fields from `variables`, check that the tool can correctly read and generate corresponding content with no empty returns or missing fields.
- After enabling the automatic question optimization feature, input a vague qualification verification request, check that the dialogue automatically converts the request into a clear field extraction instruction.
