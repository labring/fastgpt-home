# Requirements and Design Document Drafting for Delivery Effect Optimization: Workflow Orchestration

## Data Profile for This Category
Data for this category comes from ad delivery platforms, attribution systems, CRM lead systems, and landing page data. Update cycles fall into two categories: real-time and daily. Regularly produced documents include delivery daily reports, delivery weekly reports, price adjustment records, material test sheets, and optimization review documents. Most document structures use table formats grouped by delivery plans, with fields such as impressions, clicks, conversion cost, and budget balance. The units for these fields are times, times, yuan/conversion, and yuan respectively.

## Constraints on Workflow Orchestration
Business data for delivery effect optimization comes from multiple systems with flexible update cycles. Workflows must support multi-data source field mapping and trigger rules for real-time or daily updates.
Diverse daily document types including daily reports, weekly reports, and price adjustment records require workflows to support variable writing for different document structures. This avoids format chaos caused by field mismatches.
Delivery optimization relies on historical data comparison and adjustment. Workflows must bind corresponding delivery task identifiers to ensure accurate data association.
Frequent operations for anomaly location and budget allocation require workflow components to support quick reuse, improving document drafting efficiency.

## Configuration Specifications
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Map fields from ad platforms and attribution systems to corresponding business document fields | Match the business data structure of delivery effect optimization, ensure accurate variable reading |
| Trigger Timing | Real-time trigger (after ad data updates) or daily trigger (daily 00:00) | Adapt to daily or real-time data update frequencies, align with business adjustment rhythms |
| Context Window | First 12000 tokens | Cover complete content of a single daily report plus price adjustment records, avoid context truncation |
| `nodeId` | Bind the node ID of the corresponding delivery plan | Associate already running delivery task data, avoid data confusion across plans |
| Result Output Method | Only write to document variables, do not output to conversation flow | Meet requirement and design document drafting scenarios, no additional conversation responses needed |
| Retry Strategy | Retry 3 times, 60 seconds interval between each attempt | Address occasional fluctuations in ad platform APIs, reduce probability of single call failure |

## Three Common Misconfigurations
- Phenomenon: The output content of the AI conversation node is written to the return area of the requirement document and synchronized to the conversation flow. Cause: The result output method is not configured correctly. The node output is synchronized to the conversation return channel by default, which does not meet the scenario requirements of document drafting.
- Phenomenon: Workflow components cannot be copied and pasted. Drag-and-drop or shortcut key operations have no response. Cause: Component copy permission is not enabled in the workflow settings of FastGPT v4.17.0, or the target component is not selected correctly.
- Phenomenon: Workflow loses historical context, and cannot associate past price adjustment records with current optimization requirements. Cause: The `variables` binding context fields of historical documents are not configured correctly, causing the node to fail to read previous business data.

## How to Confirm Correct Configuration
- Trigger the workflow once, check the generated requirement and design document, confirm that it only contains delivery business data fields, with no additional conversation response content.
- Check the mapping relationship of `variables`, confirm that all data source fields and business document fields are in one-to-one correspondence, with no omissions or mismatches.
- Select the target workflow component, use the copy shortcut key and paste it into other workflows, confirm that the component configuration is fully retained.
- View the workflow running logs, confirm that the node trigger timing matches the data update rhythm, with no abnormal errors.
