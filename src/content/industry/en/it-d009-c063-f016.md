# Requirements and Design Document Drafting for Campaign Setup: Forms and Interactions

## What the data for this category looks like
The core data for this category comes from advertising platform APIs, user profile databases, internal budget sheets, and attribution tools. The four core types of documents produced daily include campaign plans, targeting settings, budget scheduling, and conversion tracking configurations. Data update frequency is daily or per individual campaign cycle. Core fields include audience targeting tags, budget amounts, conversion event IDs, and others, which must match the field formats and unit requirements of the advertising platform. The most time-consuming configuration steps focus on audience targeting combinations, budget allocation ratios, and conversion event verification. Errors may lead to budget waste, missing conversion data, or failed campaign launch.

## What constraints these characteristics impose on forms and interactions
These data characteristics directly constrain form and interaction design: Multi-source data import requirements require associating data sources with batch configuration items through external business systems; The high-frequency update feature requires connecting to external business systems to implement real-time verification logic, avoiding invalid configuration submissions; Field differences across multiple document types require forms to support dynamic switching of configuration groups; High-risk error consequences require connecting to external business systems to add strict verification links, performing format and legibility checks on core fields such as budget amounts and targeting tags; Hierarchical configuration logic requires linked loading of options through external business systems or subsequent workflows, simplifying complex targeting setup processes.

## How to set configurations
The following configurations are based on FastGPT v4.17.0, as detailed below:
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Form input node `formInput` | Test example: Select 3 fields from campaign setup fields as required inputs; actual fields are determined per task | This node collects user input; when required items are missing, interaction status must be checked to avoid subsequent nodes failing to receive complete input |
| User selection node `userSelect` | Test example: Set 2 business options, check corresponding branches one by one | This node handles user selection; querying and filtering records related to campaign setup must be implemented by subsequent APIs or external systems |
| Field passing after submission | Test example: Prepare 10 campaign setup input samples, covering complete filling, missing required items, and canceled operations | Compare inputs and node outputs to verify whether subsequent nodes receive corresponding fields; result thresholds are determined per actual task |
| External implementation item: Text input field | Must be implemented separately by external systems; multi-line text input, maximum 2000 characters per single field | Matches the long text description requirements of campaign plan documents |
| External implementation item: Selection input field | Must be implemented separately by external systems; multi-select mode, maximum 50 items per option group | Adapts to multi-combination configuration scenarios for audience targeting tags |
| External implementation item: Numeric input field | Must be implemented separately by external systems; numeric input, unit verification logic is implemented by external business systems or subsequent nodes, with the example unit being yuan/day | Matches the field unit and format requirements of budget allocation |

## Three common misconfigurations
- No interaction prompts when calling via API after deployment. Cause: The interaction trigger logic between the form input and user selection nodes in the workflow was not configured correctly, resulting in the interface not returning interaction fields.
- The form does not have unit verification rules configured, and submissions succeed after entering non-numeric or invalid unit budget values. Cause: The numeric and unit verification logic of external business systems or subsequent nodes was not configured, leading to invalid configurations entering subsequent processes.
- Linked options are not correctly associated with data sources, and sub-options do not update after selecting a parent targeting tag. Cause: The linkage trigger conditions were not configured via external business systems or subsequent workflows, resulting in hierarchical configurations failing to load properly.

## How to confirm the configuration is complete
- Import test data in standard campaign plan format, check whether the fields loaded by the form match the core configuration items of targeting, budget, and conversion tracking.
- Call the FastGPT API interface, confirm that the returned interaction fields include relevant configurations for the form input and user selection nodes.
- Enter a budget value with an invalid unit, check whether the external business system triggers a format verification error prompt.
- Select a parent audience targeting tag, confirm whether the external business system loads and displays child subdivision tags.

The values given are common starting points and should be measured against the reader's own samples.
