# Tendering Document Preparation: Requirement and Design Document Drafting - Workflow Orchestration

## What the data for this category looks like
The data for this category mainly comes from tender announcements, tender documents, enterprise qualification databases, and supplier quotations. The update frequency is once per project. Daily processed documents include overall tender document templates, qualification certificates, business deviation tables, and technical deviation tables. Core fields include response clauses required by the tenderer, qualification certificate numbers, and quotation detail items. All documents must strictly match the format requirements specified by the tenderer, and there is no universal fixed field structure.

## What constraints these characteristics impose on the "workflow orchestration" link
Since data sources are scattered and updated per project, the workflow must support dynamically pulling files and fields from different sources. Document structures change with tender requirements, so flexible variables must be bound to implement field mapping. The most time-consuming tasks of responding to clauses item by item and verifying qualification materials must be split into independent nodes to avoid excessive load on a single node. Errors directly lead to the risk of bid invalidation, so verification steps must be added at key links to ensure data accuracy and format compliance.

## How to set the configurations
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| `variables` | Bind three types of variables: tender clauses, qualification documents, and quotation data | Match the core data sources and document types of this category |
| `nodeId` | Assign consecutive nodeIds in the order of qualification verification, clause response, and packaging check | Align with the business execution order of tender document preparation |
| File upload node size limit | Single file no larger than 1000 MB | Adapt to the common file size in enterprise qualification databases |
| Node timeout setting | 600 seconds | Match the average time consumption of a single round of qualification verification |
| Variable mapping rule | Automatically match according to the field names in the tender documents | Address the feature of large differences in document formats per project |

## Three common mistakes
- Phenomenon: An error "Failed to create post presigned url" is prompted when uploading files by calling the workflow via API. Cause: The permission to generate pre-signed URLs for file storage nodes is not enabled in the FastGPT v4.17.0 workflow configuration, or the storage rules of v4.14.0 and above are not adapted.
- Phenomenon: The business deviation table fields are empty after the workflow is executed. Cause: The deviation requirements in the tender documents are not bound to the corresponding variables in `variables`, resulting in the deviation content required by the tenderer not being correctly pulled and filled.
- Phenomenon: The workflow terminates early during the qualification verification link. Cause: A reasonable node timeout duration is not set, or multiple rounds of qualification verification nodes are not split, resulting in the single-node processing time exceeding the threshold.

## How to confirm the configuration is complete
- Trigger a workflow test, upload the corresponding tender announcement and qualification documents, and check whether the `variables` automatically fill in the tender clauses and qualification information.
- Call the API to pass the file type parameter, verify that there are no errors in the file upload link, and the returned result contains the correct file storage path.
- Simulate a scenario where qualification items are omitted, check whether the workflow triggers a verification prompt and intercepts the execution process that does not meet the requirements.
- View the workflow execution log, confirm that the `nodeId` order is consistent with the business process of qualification verification, clause response, and packaging check, and there is no error in node execution order.
