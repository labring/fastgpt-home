# Requirements and Design Document Drafting for Tender Document Preparation: Document Parsing and Chunking

## What the data for this category looks like
Core data for this category comes from tender notices, bidding documents, enterprise qualification databases, and supplier quotations. Updates are completed independently for each individual order. Commonly processed documents include tender document main text, qualification certificates, business deviation tables, and technical deviation tables. Most document structures follow fixed formats provided by the tenderer, and contain fields such as tender requirements, qualification numbers, quotation amounts, and response clauses. No unified general field template exists, and matching must align with the specific requirements of the tenderer. The content scale of each document varies based on the complexity of the tender project, and the number of attachments ranges from 1 to dozens.

## Constraints imposed on document parsing and chunking
The data characteristics of this category create three constraints for document parsing and chunking. First, the independent update per order requirement means parsing tasks require one-time adaptive processing. General chunking rules cannot be reused, and parameters must be adjusted for each tender document. Second, documents must strictly match the tender format. Chunking must retain the corresponding relationship between clauses and response content. Splitting that breaks the link between tender requirements and supplier responses will cause errors in subsequent response verification work. Third, documents contain large volumes of tabular qualification materials and structured deviation tables. Chunking must preserve original format and field associations. Failure to do so will impact subsequent clause response verification and seal packaging inspection work.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Tender document clause response paragraphs mostly fall within this range, to avoid splitting tender requirements and corresponding response content |
| `chunkSplitter` | Split by headings and paragraphs | Match the chapter structure of tender documents, ensure deviation tables and qualification pages are chunked logically |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Single tender documents include multiple attachments, sufficient parsing time must be reserved |
| `customPdfParse` | Enabled | Retain format information such as tables and page numbers in tender documents, avoid loss of qualification certificate fields, and adapt to the PDF parsing optimization of FastGPT v4.17.0 |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Adapt to the common size of single tender project file packages |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules for the fixed format of tender documents |

## Three Common Misconfigurations
- Chunked content after parsing lacks corresponding tender clauses, with split-related errors in logs. This occurs when `chunkSplitter` is configured to split by fixed characters, without adapting to the heading hierarchy of tender documents, leading to cross-chapter splitting.
- Parsing tasks take longer than expected. This happens when `PARSE_FILE_TIMEOUT_SECONDS` is set too low, or when `customPdfParse` is not enabled, resulting in repeated parsing of formatted content.
- Document enhanced parsing shows no effect after being enabled, and normal functionality returns after switching to an older version. This is caused by a version incompatibility between the deployed environment and the enhanced parsing configuration, or failure to correctly enable commercial version exclusive parsing permissions.

## How to Verify Correct Configuration
- Upload a standard tender document sample, review the parsed chunk list, and confirm each chunk corresponds to an independent tender clause or qualification content.
- Check the parsing task running logs, confirm no timeout errors are triggered, and that the elapsed time matches the set value of `PARSE_FILE_TIMEOUT_SECONDS`.
- Open the parsed PDF result, confirm that format information such as tables and page numbers is not lost, and that all qualification certificate fields are fully retained.
- Check the size of the uploaded file, confirm it does not exceed the `UPLOAD_FILE_MAX_SIZE` limit to avoid system interception.

The values provided are common starting points and should be measured against the reader's own samples.
