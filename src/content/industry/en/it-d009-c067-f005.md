# Drafting Requirements and Design Documents for Data Security Classification and Grading: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data for this category primarily comes from data asset inventory results, database metadata, business system documentation, and public regulatory documents.
Daily produced documents fall into four categories: data catalogs, classification and grading rules, important data identification tables, and review minutes.
Data is updated quarterly, or synchronized whenever the corresponding business system changes.
Core document fields include data asset name, affiliated business domain, sensitivity level identifier, and classification grade.
There is no unified fixed unit. Matching must be done based on specific business scenarios.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
Data sources are scattered and require cross-system data pulling. Multi-turn dialogue must gradually align metadata and business descriptions from different sources. It must sequentially confirm data asset scope and rule basis during dialogue.
Document types are diverse and have inconsistent structures. Prompts must adapt to the field formats of different documents, avoiding confusion between data catalog and grading rule identification logic.
Update frequencies are triggered by business changes. Dialogue context must support temporary supplementation of the latest updated system information, preventing expired rules from being used to generate documents.
Sensitive field identification and grading review take a long time. Multi-turn dialogue must split complex tasks into sub-steps, avoiding exceeding context limits with a single input.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Maximum Context | 1500–2000 characters | Adapts to the concatenated length of multiple classification and grading documents, avoiding exceeding model context limits with a single input |
| Maximum Single Dialogue Turns | First 6 turns | Matches the step-by-step dialogue requirements for data sorting and rule review, preventing context overload |
| `variables` | Bind to data catalog templates | Automatically populate existing data asset information, reducing repeated input |
| Question Optimization | Enabled | Converts vague document drafting requirements into structured generation instructions, improving output matching |
| `chatId` | Bind to dedicated sessions | Retains classification rules and asset sorting context for a single team, avoiding cross-session confusion |
| `messages` | Calibrated based on actual testing | Adapts to business system asset counts of different scales, flexibly adjusting dialogue history length |

## Three Common Mistakes
- Embedded explanatory images in generated documents are not fully displayed. This occurs because image context storage rules are not adapted in dialogue configurations, causing image resources to fail to load properly.
- Compliance rule trace symbols appear at the end of dialogue outputs. This occurs because the rule display switch is not turned off in the dialogue settings of FastGPT v4.17.0.
- Request failures occur during concurrent calls of multi-turn dialogue. This occurs because a reasonable context upper limit is not set, causing a single request to exceed system carrying capacity.

## How to Verify Proper Configuration
- Import a test data catalog and classification and grading rule document, initiate a multi-turn dialogue, and confirm that the output document includes all required core fields.
- Initiate a test dialogue containing a rule trace symbol, and check that the symbol is not displayed in the output.
- Test the context coherence of multi-turn dialogue, confirm that subsequent questions can continue generating documents based on previous asset sorting results.
- Initiate a test dialogue requiring embedded images, and confirm that image display in the generated content meets expectations.

The values provided are common starting points and should be measured against the reader's own samples.
