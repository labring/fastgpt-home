# Requirements and Design Document Drafting for Data Security Classification and Grading: Workflow Orchestration

## What this category of data looks like
Data for this category is created and maintained daily by data governance teams, security consultants, and legal compliance teams. Core daily documents include data catalogs, classification and grading rules, important data identification tables, and review minutes. Data sources include data asset inventory results, database metadata, business system description documents, and public regulatory documents. Data is updated on a quarterly cycle, or triggered each time a business system is modified. Document fields include data asset number, sensitive field identifier, classification level, review comments, and similar items. There is no unified fixed unit, and adjustments are made based on business scenarios.

## Constraints imposed on the workflow orchestration link
Multiple-source data access requires workflows to support parallel pulling of different types of data sources across multiple nodes, to avoid overloading a single node. The quarterly or on-demand update feature requires workflow configurations to support flexible triggering, with both scheduled run and manual trigger modes. Processing multiple types of documents requires built-in variable storage nodes in the workflow, to carry the content and fields of different documents respectively. The multi-round verification in the review link requires setting serial approval nodes in the workflow, to ensure that classification rules and identification results pass compliance confirmation before entering the next stage. Errors may lead to compliance risks, so workflow configurations must include error alerts and rollback mechanisms.

## How to set configurations
| Configuration Item | Recommended Approach | Basis for This Approach |
| ---- | ---- | ---- |
| Issue Optimization | Enable after the sensitive field identification node | Used to clean original asset inventory data and optimize sensitive field matching rules |
| Maximum Context | 8000–12000 characters | Must carry multiple document contents such as classification and grading rules and data catalogs, calibrated according to actual tests |
| `variables` Binding | Map according to the metadata fields of uploaded files | Must pass multiple types of data sources such as data asset inventory tables and business system descriptions into the workflow |
| Timeout Threshold | 600 seconds | Covers multi-round verification processes such as classification rule review and sensitive field identification, to avoid mid-run interruptions |
| `nodeId` Association | Bind to the unique ID of the main classification and grading node | Ensure the workflow executes in the order of asset inventory → sensitive identification → rule review |

## Three common configuration errors
- Phenomenon: After the workflow runs, the sensitive field identification result is empty, and the interface shows that `variables` has not finished loading. Cause: The metadata fields of the data asset inventory table are not bound to the workflow variables, resulting in the data source not being passed correctly.
- Phenomenon: After configuring the issue optimization component, a timeout error occurs in the classification rule review link. Cause: The issue optimization component is placed after the review node, which consumes context quota in advance and prevents the subsequent process from completing.
- Phenomenon: When calling this workflow as a tool in a simple application, the uploaded file cannot pass parameters. Cause: The file link mapping switch is not enabled in the workflow's `variables` configuration, causing the upload parameters from the simple application to fail to be passed to the workflow.

## How to confirm the configuration is correct
- Enter the workflow editing page of FastGPT v4.17.0, check whether the `variables` configuration includes field mappings for data sources such as data catalogs and classification and grading rules.
- Trigger a test run of the workflow, and check whether the output of the sensitive field identification node includes the sensitive field information from the uploaded asset inventory table.
- Call the tool bound to this workflow, upload a test file, and confirm that the file link can be correctly passed to the workflow parameters.
- View the workflow run logs, and confirm that no timeout errors occur in the review link after the timeout threshold is set.
