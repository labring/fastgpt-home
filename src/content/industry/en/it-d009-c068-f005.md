# Requirements and Design Document Drafting for Database Cloud Service Operations: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Daily data for database cloud service operations comes from cloud database consoles, slow logs, monitoring metrics, and ticketing systems. Data updates occur daily or when an instance change is completed. Common documents include instance change orders, backup and restore records, performance diagnosis reports, and parameter adjustment records. Each document has distinct field structures:
- Instance change orders include operation time and parameter values before and after changes
- Slow logs include SQL statements, execution duration, and originating IP addresses
- Backup records include storage paths and restore success rates
Field units include milliseconds, GB, and other standard units. Data formats vary across different sources.

## Constraints for Multi-turn Dialogue and Prompt Engineering
Dispersed data sources, frequent update cycles, and varied document structures for database cloud operations create clear constraints for multi-turn dialogue and prompt configuration. First, data from different sources must be isolated using key identifiers. Pass parameters such as tenant ID and instance ID via `variables` to prevent cross-tenant data confusion. Second, frequently updated operations data can overload conversation contexts. Limit the retained length of `messages` to avoid exceeding model context windows. Third, varying field structures across documents require prompts to adapt to specific document parsing rules, ensuring extracted information aligns with operations requirements. In FastGPT v4.17.0, these constraints must be implemented via standardized configurations to prevent invalid model retrieval or information mixing.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Session Identifier Binding | Bind `chatId` to instance ID | Matches the business boundaries of multi-tenant services, ensuring each session maps to exactly one cloud database instance |
| Conversation History Retention Limit | Top 20 conversations | Aligns with the daily update or instance change trigger rhythm of database cloud operations documents, preventing `messages` context overload |
| Variable Passing Rules | Only pass tenant ID and instance ID within `variables` | Strictly isolates operations data across different customers, preventing cross-tenant queries |
| Question Optimization Switch | Enabled | Automatically optimizes question accuracy for time-consuming tasks such as slow SQL troubleshooting and parameter risk assessment |
| Context Truncation Threshold | 8000 characters | Matches the average length of single operations documents, and aligns with context windows of common large language models |
| Single Search Result Limit | Top 5 results | Matches the per-query volume of data such as slow logs and monitoring metrics, reducing redundant information interference |

## Three Common Misconfiguration Scenarios
- Scenario: After upgrading to FastGPT v4.17.0, an interface error occurs when uploading cloud operations dataset files. The status code returned is 400, and the template import function works normally. Cause: `variables` does not have correctly configured S3 storage bucket permission variables, leading to authentication failure during cross-storage migration.
- Scenario: Multiple slow SQL logs from unrelated cloud database instances are returned during multi-turn dialogue, making it impossible to locate the target instance. Cause: Instance ID parameters are not correctly passed in `messages`, so the retrieval scope is not limited to the specified instance.
- Scenario: The conversation window returns an error stating "context length exceeds limit", and subsequent questions cannot be completed. Cause: No conversation history retention limit is set, leading to excessive accumulated `messages` content exceeding the model context window.

## How to Verify Successful Configuration
- Upload a test cloud database instance change order, and check if the instance ID and change time fields are correctly extracted in the conversation history.
- Trigger a query for slow SQL troubleshooting, and confirm that returned results are limited to the current tenant’s cloud database instances.
- Access the FastGPT v4.17.0 configuration panel, and confirm that conversation history retention limit and variable passing rules are active as configured.
- Test file upload after S3 storage migration, and confirm no authentication or timeout errors occur.
