# Drafting Requirements and Design Documents for Database Operations: Multi-turn Dialogue and Prompts

## What This Category's Data Looks Like
Data for database operations scenarios primarily comes from database monitoring, audit logs, SQL execution plans, and ticketing systems. Four core document types are regularly produced: database change orders, slow SQL reports, backup records, and permission application forms. Data is updated daily or triggered by individual database changes. Each document includes fields such as instance ID, change time, SQL statement, execution duration, and permission scope. Field structures vary significantly across different document types, and most data formats combine structured and semi-structured data.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompts
The multi-source and heterogeneous nature of database operation data requires multi-turn dialogue to gradually align field definitions across different documents, to avoid confusion over critical information such as instance ID and permission level. Frequently updated operation data means overly long dialogue history introduces redundant interference, so context length must be limited to ensure response accuracy. Processing logic varies greatly across different types of operation documents, so prompts must be adapted for scenarios such as change review and slow query troubleshooting. The `variables` parameter must be used to isolate context data for different tickets, to prevent variable contamination. In addition, errors in operation actions directly relate to data security, so multi-turn dialogue must include a verification step to confirm the accuracy of operation instructions.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context length | 8000–12000 characters | Matches the average length of a single core operation document, to avoid context overload affecting responses |
| `messages` array limit | Keep the first 10 rounds of dialogue history | Filters redundant historical data, focusing on the core context of the current operation task |
| `variables` parameter binding rules | Bind exclusive variables by ticket type | Isolates context data for different operation tickets, avoiding variable superposition contamination |
| Multi-turn dialogue session identifier | Associate session context by `chatId` | Ensures context consistency for operation actions within the same session |
| Workflow concurrency threshold | 1 call per second | Matches the conventional operation frequency of database operations, avoiding execution exceptions caused by high concurrency |

## Three Common Misconfigurations
- Symptom: Workflow calls return `none` when invoked concurrently, and no valid execution records are found in logs. Cause: Concurrency volume exceeds the preset threshold, and workflow execution is forcibly terminated.
- Symptom: The large model's thinking process is not displayed in dialogue outputs. Cause: No thinking process generation instruction is included in the prompt, or the corresponding switch in configuration settings is not enabled.
- Symptom: Variable superposition appears in AI reply results, where result A from a previous dialogue is carried over to the current result B. Cause: The `variables` parameter does not implement session isolation, and historical session variables are not cleared.

## How to Verify Proper Configuration
- A test call for a simulated operation ticket is executed. The returned result is checked to confirm it includes the required document fields and no redundant historical variables remain.
- Concurrent calls at 1 to 2 calls per second are simulated. Workflow return results are confirmed to be non-empty, and no timeout-related error messages are present.
- The FastGPT v4.17.0 configuration interface is accessed. The `messages` array length limit and `variables` scope rules are confirmed to be correctly set.
- A prompt including a thinking process requirement is input. The large model is confirmed to output intermediate thinking steps if this function is enabled.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
