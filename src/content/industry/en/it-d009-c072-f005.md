# Requirements and Design Document Drafting for Data Collection Task Design: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Data for this category primarily comes from customer requirement documents, public data sources, collection tool logs, and internal sample libraries.
Daily deliverable documents include collection plans, sample specification sheets, authorization instructions, and task scheduling sheets.
Data update cycles follow individual project timelines. For cross-project reuse, updates can be synchronized on a weekly basis.
Document fields include sample scope, collection fields, compliance check items, and scheduling nodes. Units typically include sample counts, time cycles, and permission identifiers. There is no unified standardized unit system.

## Constraints on Multi-turn Dialogue and Prompt Engineering
Data sources for this category are scattered, and document structures are inconsistent. The most time-consuming steps—defining sample scope and confirming field specifications—require gradual clarification of vague customer needs through multi-turn dialogue.
Prompts must preset basic compliance verification rules to avoid missing core clauses of authorization instructions. Since data updates follow single-project cycles, dialogue context must retain project-specific collection requirements. The length of retained historical messages must be limited to ensure interaction efficiency.
Different projects have no unified standards for document fields. Prompts must clearly guide the extraction of standardized collection parameters to avoid generating task design content that does not meet project requirements.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `messages` historical message retention limit | First 3–5 turns of dialogue content | Adapts to the context length of single-project collection tasks, avoids redundant information interfering with prompt logic |
| `variables` preset collection field template | Structured variables including sample scope and compliance check items | Unifies document field extraction rules across different projects, aligns with the standard structure of daily collection plans |
| Single dialogue timeout threshold | 600 seconds | Adapts to the interaction duration required for complex compliance checks and multi-turn clarifications, prevents timeouts due to numerous task details |
| `chatId` binding to project-specific context | Binds to the unique identifier of the current project | Ensures multi-turn dialogue only retains collection requirements for the current project, avoids cross-project data confusion |
| Question optimization switch | Enabled | Automatically optimizes vague user demand statements, assists in clarifying sample scope and field specifications |
| Maximum context token count | 8000 tokens | Adapts to prompt input for long documents such as collection plans and authorization instructions, ensures complete information |

## Three Common Configuration Errors
In FastGPT v4.17.0, three common configuration errors are as follows:
- A "context parsing failed" error appears in the dialogue window. The cause is failing to limit the historical turns of `messages`. Redundant content accumulated across multi-turn dialogue exceeds the configured maximum context token count, preventing the system from fully loading the context.
- File and text dataset uploads fail, but template import functions operate normally. The cause is failing to configure data source verification rules in `variables`. The system fails to correctly recognize non-template upload request formats.
- The dialogue opening screen only displays a single preset question, and multiple optional questions cannot be generated. The cause is failing to explicitly require the generation of multi-option opening questions in the prompt, and failing to write the preset question list into the initial dialogue variables of `variables`.

## How to Verify Correct Configuration
- Launch a simulated dialogue, input vague collection requirements, and check if the system can gradually clarify sample scope and field specifications to confirm that the `messages` historical turn limit is active.
- Upload a non-template collection plan document, check if the upload function works normally, and confirm that the `variables` data source verification rules are configured correctly.
- View the initial dialogue interface, confirm that multiple preset optional questions are displayed, and check if the `variables` initial variables include the preset question list.
- Launch a dialogue containing compliance check items, check if the system can automatically associate relevant clauses of the authorization instructions, and confirm that the preset rules of the prompt are active.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
