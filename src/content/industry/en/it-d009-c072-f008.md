# Requirements and Design Document Drafting for Data Collection Task Design: Workflow Orchestration

## What this category of data looks like
Data for this category primarily comes from customer requirements, public data sources, collection tools, and internal sample libraries. Four types of documents are produced regularly: collection plans, sample specifications, authorization descriptions, and task schedules. Update frequency follows per project or weekly cycles. Common data fields include sample scope, collection fields, compliance check items, and schedule nodes. Sample volume is measured in units of items, time nodes in units of days. Compliance check items must clearly specify authorization coverage ranges.

## What constraints these characteristics impose on the "workflow orchestration" link
Data sources for this category are scattered. Document structures vary, and update rhythms are inconsistent. Workflows must support multi-source data access adaptation, and be compatible with collection tools of different formats and output content from public data sources. Document nodes must be split by type such as collection plans and sample specifications. This ensures each link corresponds to exclusive check logic. Fields must match unit and specification requirements. Pre-check nodes must be configured to block non-compliant fields. Failure rollback and alert nodes must also be embedded, to avoid project rework caused by sample definition errors or compliance oversights. The workflow module of FastGPT v4.17.0 can adapt to these constraints through node grouping and variable management.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Configure a global default variable group that includes fixed collection cycles and compliance thresholds | Store globally unchanged variables, to prevent variables from being reset during workflow execution |
| `nodeId` | Assign unique identifiers to collection plan nodes and compliance check nodes separately | Distinguish different workflow nodes, to facilitate log troubleshooting and status tracking |
| Multi-source data format conversion | Match conversion rules by data source type, such as CSV to JSON, API interface data standardization | Adapt to data formats from different sources, to ensure unified processing logic |
| Field check node | Check sample volume unit (items) and time node unit (days), block collection ranges without valid compliance authorization | Match units and specification requirements of data fields, to prevent non-compliant data from entering the workflow |
| Failure alert trigger | Trigger system notifications when a node status is failed | Address workflow abnormalities promptly, to reduce project rework risk |
| Trigger mode setup | Trigger by project schedule nodes, or manually trigger on-demand collection | Match the update rhythm of task schedules, to flexibly adapt to different project requirements |

## Three Common Misconfigurations
- Extraction of output variables fails after workflow runs, and the corresponding fields display empty on the interface. The cause is failure to configure the `variables` global variable group to store fixed parameters, or incorrect binding of target node input parameters during variable transfer between nodes.
- Knowledge base search nodes return empty results. The cause is failure to configure the correct associated knowledge base ID, or the search scope not covering sample specifications and authorization description documents required for the collection task.
- Global default variables are overwritten during workflow execution. The cause is failure to categorize variables into the `variables` global variable group; temporary variables are cleared after a single workflow run.

## How to Confirm Configurations Are Correct
- Check the `variables` global variable group configuration, confirm all unchanged parameters have been stored in the group and are not overwritten by temporary nodes.
- Import test data from different sources, verify that the output format of multi-source data format conversion nodes is unified and meets collection plan requirements.
- Manually trigger node exception scenarios, confirm that failure alert notifications are sent normally, to promptly detect workflow issues.
- Review trigger mode settings, match project schedule node or manual trigger logic, confirm that the workflow starts as expected.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
