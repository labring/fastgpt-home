# Requirements and Design Document Drafting for Data Collection Task Design: Document Parsing and Chunking
This document is written based on FastGPT v4.17.0.

## What Data in This Category Entails
Data for this category primarily originates from customer requirements, public data sources, collection tools, and sample libraries. Four types of documents are routinely produced: collection plans, sample specifications, authorization statements, and task schedules. The primary users are data service project managers, collection teams, and customer algorithm teams.

Document update frequency aligns with project cycles or occurs weekly. Typical document structures include collection goals, sample field lists, compliance clauses, schedule nodes, and similar content. Fields cover sample scope, data format, authorization requirements, and other relevant aspects. There is no fixed unified unit standard, as details shift based on specific collection requirements.

## Constraints Imposed on the Document Parsing and Chunking Link
Documents from multiple sources have significant format variations, including structured tables, unstructured paragraphs, PDF export files, and more. The parsing link must support adaptation to multiple formats. Update frequencies adjust flexibly with projects, so support is required for both full parsing for single projects and incremental parsing for weekly updates.

Documents contain compliance-related content, so the parsing process must preserve the integrity of sensitive fields to avoid truncation that creates compliance risks. Fields and content change based on requirements, so chunking rules must match the document’s logical chapters. Failure to do so will compromise the configuration integrity of the collection task.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapt to the paragraph length of documents such as collection plans and sample specifications, avoid splitting content blocks that span multiple fields |
| `chunkSplitter` | Split by headings | Match the chapter structure of the document, retain logically complete chapters such as "sample scope" and "field requirements" |
| `customPdfParse` | Enabled | Adapt to non-standard PDF documents exported by collection tools, preserve the original typesetting of tables and lists |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Address parsing time for large collection schedule documents, avoid interrupting the parsing process due to mid-process timeout |
| `chunkSettingMode` | Auto-adapt by document type | Automatically adjust chunking rules for documents with different structures such as authorization statements and task schedules |

## Three Common Misconfigurations
- After uploading a locally deployed document, the parsing node displays no work progress. The cause is that `customPdfParse` is not enabled to adapt to non-standard export formats, or `UPLOAD_FILE_MAX_SIZE` is set lower than the actual size of the uploaded file.
- When fetching table data from a database, only partial fields or row content are returned. The cause is that `chunkSize` is set too small, truncating complete table blocks during splitting.
- The Markdown table output by the model fails to render completely, with content truncated. The cause is that `chunkSplitter` is not configured to split by table structure, causing the table to be split across multiple chunks.

## How to Verify Proper Configuration
- Upload a single collection plan document under 100 MB, check that the parsing progress bar completes without errors.
- Import a sample specification document containing multi-field tables, confirm that parsed chunks retain complete table content.
- Adjust `chunkSize` to different values, compare the number of parsed chunks to confirm the chunking logic aligns with the document structure.
- View the parsing log to confirm that `PARSE_FILE_TIMEOUT_SECONDS` does not trigger timeout errors.

The values provided are common starting points and should be measured against the reader's own samples.
