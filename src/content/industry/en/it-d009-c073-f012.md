# Requirements and Design Document Drafting for Dataset Delivery and Version Management: Document Parsing and Chunking

## What data for this category looks like
The core data for this category is produced by data project managers, data engineers, and customer algorithm teams. Daily documents include dataset descriptions, version records, delivery checklists, and acceptance reports. Data sources cover object storage, data warehouses, annotation platforms, and customer acceptance feedback. Updates are rolled out per batch or version. Documents typically include fields such as version number, sample count, delivery scope, and difference descriptions. There are no uniform mandatory units, and adjustments must be made to match delivery scenarios.

## What constraints do these characteristics impose on the document parsing and chunking link
Documents from multiple sources have significant format differences. Parsing rules for different data sources must be adapted to avoid loss of critical information due to format incompatibility. The characteristic of updates per batch or version requires that chunking results be strongly bound to the corresponding version to prevent mixing of data across versions. Documents contain key associated fields such as version numbers and sample difference descriptions. Context associations must be retained during chunking to avoid splitting critical information. Documents such as delivery checklists and acceptance reports have non-fixed structures. Flexible delimiter configuration must be supported, and chunking must avoid being too fine or too coarse due to delivery integrity verification requirements.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the field density of delivery documents, avoids including too many unrelated version records and sample descriptions in a single chunk, and complies with the parsing engine rules of FastGPT v4.17.0 |
| `chunkSplitter` | Segment by headings and line breaks | Matches the structured layout of delivery checklists and version records, retains the association between version numbers and corresponding content |
| `customPdfParse` | Enabled | Adapts to table and paragraph parsing for PDF format documents such as acceptance reports, avoiding loss of table content |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapts to large-volume dataset description packages for single-batch delivery, avoiding upload interruptions |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Covers the parsing duration of long version records and multi-page acceptance reports, preventing timeout failures |
| `chunkSettingMode` | Manual configuration | Adjusts parameters for different delivery document types to meet parsing requirements for version tracing and sample difference descriptions |

## Three common mistakes
- Symptom: Uploaded delivery checklist tables display abnormally in the knowledge base, and table content cannot be viewed after export. Cause: The `customPdfParse` configuration is not enabled, causing tables in PDF-format delivery checklists to be parsed as plain text and losing table structure.
- Symptom: Version numbers and corresponding sample descriptions are separated in retrieval results, making association and verification impossible. Cause: The `chunkSplitter` configuration only uses line breaks for segmentation, without matching heading hierarchies, causing key associated information to be split into different chunks.
- Symptom: Parsing tasks remain in a waiting state for a long time and eventually return a timeout error. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted, and the parsing duration of long version records or multi-page acceptance reports exceeds the default threshold.

## How to confirm that configurations are correctly set
- Upload a single typical delivery document, view the parsed chunked content, and confirm that key fields such as version number and sample count are not split.
- Upload an acceptance report containing tables, and check whether the row and column structure and content of the table are retained in the knowledge base.
- Upload a large-volume delivery package, and verify that the upload and parsing processes do not show interruptions or timeout prompts.
- Adjust the `chunkSize` parameter, compare chunking results under different configurations, and ensure that chunk length meets document layout requirements.

The values provided are common starting points and should be measured against the reader's own samples.
