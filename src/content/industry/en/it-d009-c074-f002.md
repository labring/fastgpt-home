# Requirements and Design Document Drafting for Text Annotation Projects: Context and Token

## What Data for This Category Looks Like
Data for text annotation projects primarily comes from original corpora provided by clients, annotation results generated by internal annotation platforms, specialized vocabularies, and results from quality inspection sampling. Daily maintained documents include annotation specification manuals, batch sample packages, quality inspection reports, and issue feedback forms. Updates occur daily or per batch of annotation tasks. Data fields include original text, annotation tags, annotator information, quality inspection results, and additional relevant fields. Common units are characters, tag categories, and batch numbers. This category focuses on semantic boundaries, entity recognition, and intent classification, differing from image annotation projects which prioritize visual feature processing.

## What Constraints These Characteristics Impose on the Context and Token Workflow
The multi-source data and high-frequency update characteristics of text annotation projects directly impact context and token usage logic. Original corpora vary widely in length, and the total character count of batch sample packages far exceeds the single-model context limit, easily triggering token overflow or result truncation. Semantic details from annotation specifications and quality inspection reports must be fully retained to ensure alignment of annotation logic. Improper context interception can lead to deviations in the interpretation of tag boundaries. Additionally, the daily or per-batch update rhythm requires context configurations to adapt to dynamically changing corpus scales, avoiding abnormal token consumption or response delays caused by fixed parameters.

## How to Configure the Settings
| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Adapts to the corpus scale of batch text annotation, avoids single-round context overflow, and aligns with FastGPT v4.17.0 context processing logic |
| `quoteMaxToken` | 2000–3000 characters | Retains complete semantics of key reference texts such as annotation specifications and quality inspection reports, ensuring alignment of annotation logic |
| Maximum context refresh interval | Every 6 hours | Adapts to daily or per-batch update frequencies, enabling timely loading of the latest annotation specifications and sample data |
| Single-batch sample context limit | First 100 samples | Controls single-round token consumption, avoiding response delays during batch processing |
| Semantic alignment threshold | Calibrated via actual testing | Matches the semantic boundary accuracy requirements of annotation tasks, avoiding excessive interception of key tag explanation content |

## Three Common Misconfiguration Issues
- Issue: Text truncation still occurs after configuring `maxContext`, with logs showing `[hide X char]`. Cause: The `quoteMaxToken` parameter was not adjusted synchronously, causing referenced annotation specification text to be truncated early, failing to fully convey semantic boundary requirements.
- Issue: Response timeout occurs during batch annotation tasks, with the interface returning status code 504. Cause: The number of context-loaded samples per batch was not limited, causing token consumption to exceed the model's carrying limit and triggering a timeout.
- Issue: An error `failed to get gpt-3.5-turbo token encoder` is reported when starting the associated model service. Cause: Context parameters were not adjusted for the corpus characteristics of text annotation projects, causing the model encoder to fail to adapt to the token statistics logic of batch text.

## How to Verify Proper Configuration
- Run a test task for 100 samples per batch, check that the context fully loads annotation specifications and historical quality inspection reports, with no truncation or hidden characters.
- Review token consumption statistics, confirm that single-round task token usage falls within the configured `maxContext` range, with no abnormal spikes.
- Associate the latest annotation specification update, verify that the context configuration can automatically load the latest version of document content.
- Test the response speed of batch tasks, confirm that it aligns with the daily processing rhythm of the annotation team.

The values provided are common starting points and should be measured against the reader's own samples.
