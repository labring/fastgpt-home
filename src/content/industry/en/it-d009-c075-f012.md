# Requirements and Design Document Drafting for Documentation Site Maintenance: Document Parsing and Chunking

## What the data for this category looks like
The data for this category mainly comes from code repositories, documentation site build logs, user feedback, and version release records. Daily maintained documents include installation guides, API specifications, migration manuals, and frequently asked questions. These documents are produced by technical writers, maintainers, or developer relations teams.
Data updates follow a weekly cadence or sync with version releases. Documents are typically divided into chapters by functional modules, and contain fixed fields such as command line examples and interface parameter descriptions. There is no unified mandatory format requirement, but documents must match the documentation site’s rendering specifications.

## What constraints do these characteristics impose on the document parsing and chunking link
Since document sources include comments from code repositories and error messages from build logs, the parsing process must support Markdown, plain text, and a small number of embedded code block formats. The high-frequency update feature requires the chunking workflow to adapt to rapidly iterating documents, avoiding repeated parsing of full content.
Daily documents include long paragraphs of API specifications and step-by-step installation guides. Excessively long single segments will exceed the model’s context limit, so rule-based splitting is necessary. Most parsing failure cases from user feedback come from docx files with complex formats or oversized PDFs. This means the chunking link must have fault tolerance handling capabilities.

## How to set the configurations
The following configuration items apply to FastGPT v4.17.0, and can be directly used to adjust the document parsing and chunking workflow for documentation site maintenance scenarios:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the chapter length of daily documents, avoids single chunks exceeding the model’s context limit, and reduces the total number of chunks |
| `chunkSplitter` | Split by Markdown headings + paragraphs | Matches the chapter structure of documentation sites, preserves the logical hierarchy of installation guides and API documents |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing duration of 10–20 MB documents, avoids parsing timeouts for oversized PDFs or docx files |
| `UPLOAD_FILE_MAX_SIZE` | 2000 MB | Meets the demand for batch document uploads in a single operation, matches batch document update scenarios during version releases |
| `customPdfParse` | Enabled | Optimizes text extraction effects for PDF documents, reduces garbled text or missing content after parsing |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for different document types such as API documents and FAQs, to adapt to scenario-specific needs |

## Three common misconfigurations
- Symptom: A timeout error is prompted when uploading a 10+ MB PDF. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter was not adjusted, and the default timeout duration is insufficient for parsing large-volume documents.
- Symptom: Garbled text or missing content appears after parsing individual docx documents. Cause: The `customPdfParse` configuration was not enabled, and the default parsing logic has insufficient compatibility with docx files with complex embedded formats.
- Symptom: Ultra-long paragraphs are not split a second time after chunking, causing single chunks to exceed the model’s processing limit. Cause: Documents were only split by fixed delimiters, no secondary splitting logic was implemented for ultra-long segments, and the configuration requirements of `chunkSize` were not matched.

## How to confirm configurations are correctly set
- Upload a test PDF of approximately 15 MB, check that there are no timeout errors in the parsing log, confirming that the `PARSE_FILE_TIMEOUT_SECONDS` configuration is active.
- Upload a docx document with a complex format, check that the parsed text retains the original chapter titles and paragraph structure, confirming that the `customPdfParse` configuration is enabled.
- Import a segment of API description text exceeding 1500 characters, check whether the chunking results are split into multiple chunks conforming to the `chunkSize` rule.
- Upload a batch document package, confirm that the total upload size does not exceed the `UPLOAD_FILE_MAX_SIZE` limit, and no upload failure prompts appear.

The values provided here are common starting points and should be measured against the reader's own samples.
