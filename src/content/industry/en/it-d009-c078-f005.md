# Drafting Requirements and Design Documents for Cabinet Rack Installation and Cabling: Multi-turn Dialogue and Prompt Words

## What Data This Category Includes
Data for this category comes primarily from DCIM systems, asset management systems, network topology diagrams, and customer work orders. Daily produced documents include cabinet rack installation application forms, cabinet cabling diagrams, port label tables, and construction records. Installation application forms include fields such as slot number, device model, and number of access ports. Cabling diagrams mark cable identifiers, start positions, and end positions. Port label tables include port numbers and corresponding device information. Data updates occur once per order or daily, with adjustments synchronized to construction progress.

## Constraints for Multi-turn Dialogue and Prompt Words Workflows
Data sources for this category are scattered, and fields are clearly subdivided. Multi-turn dialogue must first confirm the currently called data source type to avoid confusion between field information from different systems. Daily documents have many fields, so multi-turn questioning gradually confirms complete information. For example, first confirm the target cabinet slot number, then verify the number of device access ports. Data updates happen frequently, so dialogue must support real-time pulling of the latest DCIM and asset system data to avoid using outdated information. Errors directly affect business delivery, so dialogue must verify field matching in each interaction. This prevents situations where port numbers do not match actual devices. Associated calls for multiple documents must retain complete interaction context. This ensures generated cabling diagrams and label tables match the requirements of the same work order.

## Configuration Settings
This configuration is based on FastGPT v4.17.0. The specific configuration items are listed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context length | 800–1200 characters | Adapts to the text length of cabinet cabling diagrams and port label tables, avoiding truncation of key field information |
| `messages` context retention rounds | Previous 10 rounds | Covers the complete interaction flow from requirement confirmation to document generation for a single rack installation application |
| `variables` storage fields | Slot number, device model, port quantity | Matches the core fields of daily documents, facilitating subsequent calls to generate standardized documents |
| Single dialogue timeout | 600 seconds | Prevents session interruption due to waiting for DCIM data pulling |
| `chatId` session isolation rule | Isolate by work order number | Prevents context interference between different cabinet rack installation work orders |
| Prompt word trigger timing | Trigger after core fields are completed | Ensures generated documents include all required information |

## Three Common Misconfigurations
- Phenomenon: After increasing the context length in dialogue, complete interaction memory is still not retained, and the generated document omits the previously confirmed slot number. Cause: The context retention range of `messages` is not configured correctly, and only the most recent 2 rounds of dialogue are retained.
- Phenomenon: No return data appears after calling the online dialogue interface, and the frontend displays a blank screen. Cause: Core fields stored in `variables` are not correctly bound, so the prompt word template cannot obtain necessary parameters to generate documents.
- Phenomenon: Duplicate port numbers appear in the generated port label table. Cause: Port data pulled from DCIM is not verified in dialogue, and old data from historical work orders is used directly.

## How to Verify Proper Configuration
- Initiate a simulated work order dialogue, confirm slot number, device model, and number of access ports in sequence, and check whether `variables` correctly stores the entered field values during the dialogue.
- Adjust the context length to 1000 characters, send test content containing the text of a cabinet cabling diagram, and confirm that no text truncation occurs.
- Initiate simulated dialogues for two different work orders, check whether `chatId` is isolated by work order number, and that the contexts of the two dialogues do not interfere with each other.
- Call the online interface, pass simulated work order parameters, and check whether a properly formatted rack installation application document can be returned normally.
