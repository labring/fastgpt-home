# Drafting Requirements and Design Documents for Cabinet Rack Installation and Cabling: Document Parsing and Chunking

## What the Data for This Category Looks Like
Core data for this category comes from DCIM systems, asset management systems, network topology diagrams, and customer work orders. The update frequency is per order or daily. Commonly processed documents include rack installation applications, cabinet cabling diagrams, port label sheets, and on-site construction records. Most document structures include fields such as rack unit number, port identifier, cable specification, and construction node. Some drawing documents include vector annotations and point coordinates. Common units include rack units (U) and cable length in meters.

## Constraints Imposed on Document Parsing and Chunking
Heterogeneous document formats require parsing adaptation, as structured forms, vector cabling diagrams, and plain text construction records must be processed simultaneously. Frequently updated data sources require real-time performance in the parsing stage. Professional fields and units must be retained to avoid breaking the logical association between rack positions, ports, and cables during chunking. Embedded image content in drawings must be extracted separately to ensure large language models can access point annotation information. Multi-source data splicing must retain the original document attribution association to avoid confusion between construction content from different work orders.

## Configuration Guidelines
This configuration is based on FastGPT v4.17.0 feature parameters:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Documents in this category mostly include professional fields and associated information. This range retains contextual associations for rack positions and ports, avoiding logical breaks after chunking |
| `chunkSplitter` | Split by paragraph + title | Rack installation applications and construction records have clear title and paragraph hierarchies, which can retain the logical structure of documents |
| `customPdfParse` | Enabled | Cabinet cabling diagrams are PDF files with embedded vector images. Enabling this setting extracts embedded image content for use by large language models |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Meets the size requirements for large cabinet topology PDF files or batches of construction record packages, avoiding upload failures |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large drawing parsing requires longer processing time, avoiding timeout interruptions |
| `chunkSettingMode` | Manual configuration | Documents in this category have heterogeneous formats. Manual configuration adapts to the chunking needs of different document types |

## Three Common Misconfigurations
- Symptom: After parsing a PDF cabling diagram, embedded images are not extracted, and the large language model cannot access point annotations. Cause: The `customPdfParse` configuration is not enabled, so only text content is extracted, and embedded vector drawings are ignored.
- Symptom: Uploading a public Yuque link results in a parsing failure with a 400 status code returned. Cause: The Yuque link is not confirmed to be a publicly accessible, permission-free page. FastGPT only supports static web pages that can be directly crawled as data sources.
- Symptom: After chunking, fields in port label sheets are split sporadically, with rack unit numbers and port numbers separated. Cause: The `chunkSize` value is too small, breaking the contextual association logic of professional fields.

## How to Verify Correct Configuration
- Upload a cabinet cabling diagram PDF, check if the parsed result includes embedded drawing images, and confirm that the `customPdfParse` configuration is enabled.
- Upload a public Yuque link, verify that the parsed result includes all page text and images, and confirm that the link meets crawlable requirements.
- Extract a segment of text containing rack unit numbers and port numbers, test whether the chunking result retains the association between the two, and confirm that the `chunkSize` value adapts to the document structure.
- Upload a batch of construction record packages under 1000 MB, verify that the upload and parsing process does not experience timeouts or interruptions, and confirm that the `UPLOAD_FILE_MAX_SIZE` and `PARSE_FILE_TIMEOUT_SECONDS` configurations are reasonable.
