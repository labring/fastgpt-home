# Drafting Requirements and Design Documents for Cabinet Rack Installation and Cabling: Forms and Interactions

## What the Data for This Category Looks Like
Core data for this category comes from DCIM systems, enterprise asset systems, network topology diagrams, and customer service tickets. Daily produced documents include cabinet rack installation application forms, cabling diagrams, port label sheets, and construction record forms. Common fields include rack unit number, cable type, port identifier, device model, and construction time. Units are mostly U (rack unit), meters (cable length), and units (port count). Data updates follow the cycle of a single device rack installation or single cabling construction, with synchronization per order or daily. Unfinished plans and construction records are temporarily saved for later completion.

## What Constraints These Characteristics Impose on Forms and Interactions
Decentralized data sources require external business systems or downstream nodes to support cross-system variable pulling, to avoid duplicate data entry. Professional fields with units require external business systems or downstream nodes to pre-set unit suffixes, to reduce input errors. The per-order update rhythm requires forms to support temporary saving and batch-by-batch submission, to adapt to the fragmented operations of construction personnel. Errors have serious consequences, so FastGPT's built-in required field validation must be configured. Cross-field business logic validation must be implemented by external business systems or downstream workflow branches, such as matching verification between rack unit numbers and port labels. Global variable reference support is also required, to meet the demand for dynamic default value retrieval.

## Three Common Mistakes
- Observable symptom: After configuring variable references in the form input node, default values fail to load normally, and fields display as empty. Verification steps: Check the global variable scope configuration, confirm that the variable source is bound to the current workflow's data source.
- Observable symptom: Batch submission of construction records triggers external interface errors, or data is truncated. Verification steps: Verify whether the number of data submitted in a single time meets the single data write limit of the external DCIM system, and check the batch submission validation configuration of the external interface.
- Observable symptom: When filling out the form in non-logged-in state, form input content is not synchronized to the external business system, or data upload is delayed. Verification steps: Check the authorization status of the non-logged-in real-time synchronization interface of the external business system, and troubleshoot network transmission delays.

## How to Verify Proper Configuration
- Submit a test ticket to verify whether the form default values correctly load the values of the corresponding global variables.
- Intentionally omit required fields to confirm that the system triggers corresponding validation prompts.
- Submit batch test data to confirm whether the external interface performs verification and data processing according to preset thresholds.
- Switch to the non-logged-in state to test whether the form synchronization function of the external business system works normally.
