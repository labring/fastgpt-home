# Requirements and Design Document Drafting for Architecture Design and Technical Solutions: Document Parsing and Chunking

## What the Data for This Category Looks Like
Documents in this category are mostly technical solutions, architecture diagrams, capacity assessment reports, and technical review minutes. Data sources include historical traffic data, service topologies, monitoring metrics, and business growth plans. Documents are updated monthly or when major requirements are triggered. Their structures include clear chapter hierarchies, architecture node descriptions, quantitative indicators, and review comment fields. Some documents contain embedded visual elements and structured tables.

## Constraints Imposed on the Document Parsing and Chunking Link
The characteristics of these documents impose multiple constraints on the parsing and chunking process. Embedded non-pure text elements such as architecture diagrams and structured tables require the parsing process to retain content associations, and avoid losing descriptive text linked to visual elements. The clear chapter hierarchy requires chunking to follow document logic, ensuring each chunk contains complete technical descriptions and context. The feature of low update frequency but high content complexity requires flexible configuration to adapt to architecture documents of different sizes. For content concentrated with professional terms and quantitative indicators, terms must be kept in the same chunk as associated capacity and boundary descriptions.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Category documents are mostly structured technical content. Each chunk must cover complete architecture node descriptions and associated explanations to avoid splitting critical technical logic |
| `chunkSplitter` | Split by heading hierarchy | Technical solution documents have clear chapter and sub-chapter structures. Splitting by heading hierarchy retains context association and aligns with the reading logic of architecture documents |
| `customPdfParse` | Enabled | Architecture design documents often contain embedded architecture diagrams and mathematical formulas. Custom parsing retains the correspondence between text and visual elements |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large technical solution documents may contain multi-page topology diagrams and data tables. Sufficient time is required to complete full parsing and avoid mid-process timeout errors |
| `chunkSettingMode` | Manual configuration | Architecture documents for different projects vary widely in complexity. Manual configuration adapts to chunking requirements for specific scenarios, such as adjusting rules for long-chapter documents |

## Three Common Mistakes
- Symptom: Uploaded Word or Excel documents are parsed successfully, but no matching results appear in knowledge base searches. Cause: Custom parsing rules for structured tables are not enabled, leading to incorrect splitting or direct loss of table content.
- Symptom: Large model outputs do not include architecture diagram content from the documents. Cause: The `customPdfParse` configuration is not enabled. The default parsing only extracts pure text and does not retain associated descriptions of visual elements.
- Symptom: After setting chunk length, document splitting results in cross-chapter content. Cause: The `chunkSplitter` configuration is not set to split by heading hierarchy. Splitting only by fixed character length breaks the logical structure of the document.

## How to Confirm Configuration Is Complete
- Upload a technical solution document containing architecture diagrams and structured tables, and check that the parsed text includes associated descriptions or alt text for the diagrams.
- Manually adjust the `chunkSize` parameter, upload the same document, and compare the number of split chunks and content integrity to confirm chunking meets expectations.
- Perform a knowledge base search test, enter the names of core architecture nodes from the document, and confirm that the corresponding chunked content is returned.
- Upload the maximum size document supported by FastGPT v4.17.0, and check that parsing completes within `PARSE_FILE_TIMEOUT_SECONDS` without timeout errors.
