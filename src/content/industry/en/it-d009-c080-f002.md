# Requirements and Design Documentation for Desktop Terminal Support: Context and Token

## What data looks like for this category
Daily data for desktop terminal support comes from terminal management platforms, asset systems, user trouble reporting portals, and software repositories. Daily generated documents include terminal trouble tickets, installation checklists, software installation records, and remote assistance records. Fields cover device model, software version, trouble reporting time, trouble severity, operation records, and more. Units include units, times, days, and similar. Data update frequency is daily or per service request. Token consumption per single record fluctuates with document complexity.

## What constraints these characteristics impose on the context and token workflow
The data sources for desktop terminal support are scattered and updated frequently. The context for a single session may include historical records for multiple devices. Total context token volume must be limited to avoid exceeding model limits. Daily documents have diverse fields, and token consumption rises quickly when concatenated. The number of knowledge base snippet tokens referenced must be controlled. Troubleshooting scenarios have high accuracy requirements for recall results. Insufficient context leads to missing troubleshooting logic, while excessive context increases token costs and response delays. Additionally, frequently updated terminal data may have timeliness differences. Expired context must be cleaned regularly to ensure accuracy.

## How to set configurations
| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | Context for desktop terminal support mostly consists of single-device trouble, installation, and remote assistance records. Token consumption per session is moderate. This range covers typical scenarios |
| `quoteMaxToken` | `1200–1800 token` | Knowledge base chunks are typically 5000 tokens. Referenced snippets must be controlled within a reasonable range to suit desktop terminal support troubleshooting scenarios |
| Context history retention count | First 8–12 conversation turns | Sessions for desktop terminal support usually revolve around a single type of issue for one device. Excessive history adds unnecessary token consumption |
| Context auto-cleanup trigger threshold | Trigger at 75% of `maxContext` | Prevents token consumption from exceeding the preset limit, and suits frequently updated terminal data |
| Single retrieval recall limit | Top 3–5 matching results | Troubleshooting issues for desktop terminals often have typical characteristics. Too many recall results increase context token consumption |

## Three common configuration mistakes
- Issue: After setting `quoteMaxToken` to 1500 tokens, knowledge base snippets exceeding this threshold are still retrieved. Cause: Only the final referenced token limit was set, and no pre-truncation was applied to the raw chunks returned by initial retrieval. Unprocessed raw chunks still consume token resources.
- Issue: Single question-and-answer token usage statistics cannot be viewed. Cause: Global token statistics configuration is not enabled, or log display functionality is not turned on for the corresponding session page. Some versions require manual enabling of the corresponding debug switch.
- Issue: Session context cannot be automatically cleared by device or trouble type. Cause: Associated fields for context cleanup are not configured, and session context is not bound to the currently processed device identifier. This prevents recognition of cleanup trigger conditions.

## How to verify correct configuration
- Initiate a simulated desktop terminal troubleshooting question-and-answer session. Check whether the length of knowledge base snippets referenced in the returned results matches the `quoteMaxToken` configuration requirements.
- View the global statistics page of FastGPT v4.17.0 to confirm that token consumption data for each question-and-answer session is displayed normally, with no missing or abnormal values.
- Manually construct a session context that exceeds the `maxContext` threshold, and verify whether the cleanup logic is automatically triggered and valid historical records are retained.
- Configure context cleanup rules based on device identifiers, initiate a cross-device question-and-answer session, and verify whether eligible context is cleared.

All recommended values listed here are common starting points. Adjustments should be made based on the reader's own specific samples and use cases.
