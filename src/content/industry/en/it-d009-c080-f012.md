# Requirements and Design Documentation for Desktop Terminal Support: Document Parsing and Chunking

## What data looks like for this category
Daily documents for desktop terminal support include terminal trouble tickets, installation checklists, software installation records, and remote assistance records. Data originates from terminal management platforms, asset systems, user reporting channels, and software repositories. Document update frequency is daily or triggered by requests. Typical structures include fields such as terminal unique identifier, fault type, operation steps, software version, and timestamp. Content length varies widely, ranging from a few hundred characters of fault descriptions to thousands of characters of bulk installation records.

## What constraints do these characteristics impose on document parsing and chunking
The format and content range of desktop terminal documents requires parsing and chunking to adapt to different text lengths and multi-source formats, while avoiding truncation of key troubleshooting information. Frequently updated documents must be parsed quickly, otherwise work order backlogs or employee downtime may result. Document formats vary significantly across sources, such as CSV installation checklists, PDF fault reports, and plain-text remote assistance records. Targeted format compatibility handling is required for these differences. Additionally, chunking results must align with vector model input rules to ensure the accuracy of subsequent retrieval.

## How to set configurations
This guide is written based on FastGPT v4.17.0 configuration rules. Below are document parsing and chunking configuration recommendations for desktop terminal support scenarios:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the content span of desktop terminal documents, retains complete context for fault troubleshooting while complying with the input length limits of most vector models |
| `chunkSplitter` | Split by paragraph + line break | Matches the natural segmentation logic of terminal documents, such as problem description sections and troubleshooting steps sections of trouble tickets, retaining the correlation between each segment |
| `PARSE_FILE_TIMEOUT_SECONDS` | 60–120 seconds | Covers time consumption fluctuations during bulk work order parsing, avoids work order processing interruptions caused by single parsing timeouts |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapts to the upload and parsing needs of large bulk installation checklists and multi-page remote assistance records |
| `customPdfParse` | Enabled | Preserves the original typesetting and field information of PDF-format terminal documents, avoiding loss of key content after parsing |

## Three common errors
- Symptom: Chunking results differ between local and server environments, leading to failed vector retrieval matching. Cause: `chunkSplitter` and `chunkSize` configurations are not unified, and chunking rules differ between local and server environments, resulting in mismatched indexes and queries.
- Symptom: Only raw Markdown tags are displayed in context references, and formatting cannot be rendered normally. Cause: `customPdfParse` is not enabled, or parsing configuration does not retain format tags, leading to loss of typesetting information after chunking.
- Symptom: Timeout errors are returned when uploading bulk desktop terminal trouble tickets. Cause: `PARSE_FILE_TIMEOUT_SECONDS` is set too low, failing to adapt to the parsing time requirements of bulk documents.

## How to verify correct configuration
- Check the environment variables of the App/Admin server, confirm that `AIPROXY_API_ENDPOINT` (root address of the AI Proxy service, for example http://aiproxy:3000, do not append /v1 or /chat/completions, do not configure as single-model addresses such as VLLM/Ollama/Xinference) and `AIPROXY_API_TOKEN` (AI Proxy administrator token, consistent with the AI Proxy server configuration and not empty, do not use for application API call authentication) are correctly configured and have no empty values.
- Upload a typical terminal installation checklist PDF, view the parsed chunked content, and confirm that paragraph segmentation conforms to the natural segmentation logic of the document.
- Upload a bulk remote assistance record file within 1000 MB, and verify that no timeout errors occur during the parsing process.
- Compare core configuration parameters such as `chunkSize` and `chunkSplitter` between local and server environments, and confirm that they are completely consistent.

The values provided are common starting points and should be measured against the reader's own samples.
