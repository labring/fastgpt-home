# Drafting Requirements and Design Documents for Game Content Compliance Self-Check: Multi-turn Dialogue and Prompt Words

## What the data for this category looks like
This category’s data originates from in-game text, plot scripts, art annotation files, and public regulatory requirements. Daily generated documents include content self-checklists, sensitive content modification records, user agreements, and compliance review minutes. Document fields cover content types, compliance check items, modification traces, review opinions, and other relevant fields. The data update rhythm follows game version or operational activity timelines. A round of compliance self-check must be completed before each version update or event launch. Data volume changes dynamically based on content scale.

## Constraints imposed by these characteristics on the multi-turn dialogue and prompt words link
Since data sources include multiple types of game content and public regulatory requirements, multi-turn dialogue must support cross-modal context association, and adapt to distinct check logic for text and art annotations. As updates follow version or activity timelines, dialogue context must support quick reset and scene binding to prevent confusion between different batches of self-check data. Daily document structures are fixed but contain many fields, so prompt words must accurately match self-check items and document fields to ensure generated content aligns with compliance requirements. Compliance requirements are adjusted dynamically, so multiple rounds of iteration and calibration of prompt words are needed to adapt to the latest rules, while retaining historical review traces for closed-loop verification. Content compliance errors can lead to launch delays or public opinion risks, so the dialogue link must perform real-time checks on the consistency between output and self-checklists.

## How to configure settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Maximum Context | First 12000–15000 characters | Adapts to the typical content length of game plot scripts and self-checklists |
| `variables` | Inject current version number, activity name, compliance self-checklist ID | Associates the update rhythm of related data with fixed document structure |
| `messages` | Splice context in the historical order of compliance review minutes | Retains review traces and modification records for multi-round verification |
| Prompt Template | Embed game content types and compliance check dimensions | Matches the fields and business logic of daily documents |
| Question Optimization | Calibrate based on actual testing | Adapts to compliance check requirements for different types of game content |
| `chatId` | Bind compliance tasks for a single version or single activity | Isolates self-check data and context from different batches |

## Three common misconfigurations
- Phenomenon: An uncaught exception occurs when calling the AI dialogue component, and a configuration error prompt is returned. Cause: Model connection parameters are not correctly configured during private deployment, leading to failed context calls for multi-turn dialogue.
- Phenomenon: After uploading game content files in the workflow, the document parsing tool returns an error. Cause: Parsing rules for multiple game content formats (such as plot scripts, art annotation files) are not adapted, or the file storage path is not correctly configured.
- Phenomenon: Compliance self-check results generated by multi-turn dialogue are inconsistent with historical review records. Cause: The `messages` from historical review minutes are not spliced in order, leading to missing context association.

## How to verify successful configuration
- Upload a single game plot script, and confirm that the self-check items generated by the prompt words match the preset compliance checklist.
- Trigger two rounds of dialogue, and verify that `variables` correctly inject the version and activity information of the current task.
- View the dialogue context storage, and confirm that the task bound by `chatId` is not confused with context from other batches.
- Run a test workflow, and check that compliance self-check results can be generated normally after file upload.
