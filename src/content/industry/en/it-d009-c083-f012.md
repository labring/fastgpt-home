# Requirements and Design Document Drafting for Game Content Compliance Self-Check: Document Parsing and Chunking

## What Data in This Category Looks Like
Data for this category primarily originates from game text, art resource descriptions, plot scripts, and public regulatory requirements. Commonly used documents include content self-check lists, sensitive content modification records, user agreements, and compliance review minutes. Most document structures include hierarchical headings, table fields, and status markers. For example, self-check lists contain compliance items, corresponding text snippets, and modification status fields. Modification records include operation time, modification content, and reviewer fields. Data updates occur once per version or event.

## Constraints Imposed on Document Parsing and Chunking
Document types in this category are diverse. They include plain-text plot scripts, as well as self-check lists and review minutes with tables. Single-document length varies widely. Frequent version updates require parsing processes to be efficient and stable, to avoid delaying version launches. Associated fields in documents (such as compliance items and their corresponding text snippets) must retain contextual connections during chunking. Otherwise, compliance check logic breaks. Some regulatory document formats are inconsistent. Parsing tools must adapt to multiple layout styles to ensure key information is not lost.

## How to Set Configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the single-paragraph text length of game plot scripts and compliance self-check lists, avoids splitting that breaks the connection between compliance items and their corresponding text |
| `chunkSplitter` | Split by paragraph + heading | Matches the hierarchical structure of compliance review minutes and self-check lists, retains contextual logic between different compliance items |
| `customPdfParse` | Enabled | Adapts to PDF formats of art resource descriptions and compliance documents, retains original document table layouts and text hierarchies |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch submission of plot script packages and compliance document collections for each version, meets bulk self-check requirements |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to time consumption requirements for long document parsing, avoids interrupting the parsing process due to timeout |
| `chunkSettingMode` | Manual configuration | Flexibly adjusts chunking rules for different document types (such as table-based self-check lists and plain-text plots) |

## Three Common Misconfigurations
- A 413 error is returned when uploading a compliance document collection. The cause is failure to adjust the `UPLOAD_FILE_MAX_SIZE` parameter to a suitable threshold.
- Only the first two columns are read when importing sensitive content modification records in CSV format. The cause is failure to configure table parsing rules during chunking; the default setting only extracts the first two table columns.
- The external pdf-maker parser fails to operate after being enabled. The cause is failure to correctly set the corresponding parser's key parameters in the system configuration.

## How to Confirm Configurations Are Properly Set
- Upload a single compliance self-check list CSV file, check that all preset fields are included in the parsed content, with no missing or misaligned fields.
- Upload a plot script PDF under 100 MB, verify that parsing completes within 600 seconds with no timeout errors.
- Navigate to the chunk configuration page, confirm that the `chunkSize` value matches the document length of the current category.
- After enabling `customPdfParse`, upload an art resource description PDF, check that the original document's table layouts and text hierarchies are retained.

The values listed above are common starting points. Adjust them based on your own specific samples.
