# Requirements and Design Document Drafting for Game Content Compliance Self-Check: Forms and Interactions

## What this category’s data looks like
This category of data originates from game text, story scripts, and art assets during game development and publishing, plus public regulatory compliance requirements. Four types of documents are regularly produced: content self-check lists, sensitive content modification records, user agreements, and compliance review minutes. Fields include content type, compliance risk level, modification suggestions, review status, and more. There are no unified fixed units. Data update frequency is triggered by game versions or single operational activities, covering the entire self-check process before version updates and during iterations.

## What constraints these characteristics impose on forms and interactions
Multi-source data sources require forms to support two interaction types: text input and file upload, to adapt to different submission formats for game text, story scripts, and art assets. Four fixed document structures require external systems to configure corresponding field groups for forms, to ensure no self-check items are missed. Following the update rhythm of versions or activities, external systems must separately implement functions for rapid reuse of form templates and version association binding. The FastGPT form node only collects input information. High-risk consequences require docking with external compliance verification logic or subsequent workflow branches to implement compliance verification prompts, and block obviously non-compliant submissions. The closed-loop review process must dock with external business systems or subsequent workflow branches to implement status transfer and opinion collection, ensuring modification records are traceable.

## Three common mistakes
- Symptom: In a login-free compliance self-check form, text submitted via voice input is not displayed, and the timer always shows 00:00 when long-pressing for input. Verification steps: Check whether the external voice input system has been docked, and confirm whether the parameter configuration of the external input system is normal.
- Symptom: After configuring the compliance risk word bank and input guidance rules, the expected compliance prompt does not pop up in the form. Verification steps: Check whether the external compliance verification logic has been docked, and confirm whether the association configuration between the word bank and text input fields is normal.
- Symptom: After submitting the self-check form, the associated review record is not automatically updated. Verification steps: Check whether the status synchronization logic of the external business system or subsequent workflow has been configured, and confirm whether data transmission after form submission is normal.

## How to confirm the configuration is complete
- Import a test game story script, confirm whether the external system or subsequent workflow has been configured with chunking rules, and verify whether the input content is automatically split according to the rules.
- Call the docked external voice input function, record a compliance self-check text, verify that the input timer works normally and the content is displayed correctly after submission.
- Dock with external compliance verification logic, configure the compliance word bank and input guidance, enter sensitive content in the test text, and verify that the corresponding prompt pops up.
- Call the external template configuration function, select a preset self-check template, and verify that the form fields automatically match the structure of the corresponding document.
