# Requirements and Design Document Drafting for Game License and Publication Declaration: Context and Token

## What This Category of Data Looks Like
This data is sourced from official press and publication administration services, copyright registration records, game package files, and operating institution materials. Daily documents include declaration request submissions, game application forms, copyright certificates, and review reports. Publishing units, game distribution legal teams, and project leads maintain these materials. Update frequency is irregular for each individual game. Each game’s declaration package includes fixed-format application fields and accompanying supporting documents. Fields across different documents have a high level of correlation.

## Constraints Imposed on Context and Token Handling
Documents from multiple sources have varying formats. When concatenating context, distinguish between different types of declaration material fields to avoid invalid content consuming token quota. Updates for individual game declaration materials do not follow a fixed schedule. Align knowledge base synchronization timing with declaration progress, otherwise outdated context content or abnormal token consumption may occur. Individual declaration materials include a large number of fields. The total token count of core content approaches the standard context upper limit. Strictly control the scope of recalled documents and token usage to avoid exceeding the configuration limits of `maxContext` and `quoteMaxToken`. The approval process requires verifying consistency across multiple documents. Context must accurately recall corresponding fields. Redundant context increases review and modification costs.

The following configuration recommendations apply to FastGPT v4.17.0.

## How to Set the Configuration
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Core documents for a single game’s declaration materials total approximately 6000–10000 token when concatenated, with reasonable redundant space reserved |
| `quoteMaxToken` | `3000–5000 token` | Effective content of core declaration documents such as review reports and game application forms accounts for approximately 60%, controlling total token quota for single-round citations |
| Single search limit | Top 4 results | Core declaration documents for this category fall into 4 categories. Excessive recall increases invalid token consumption and context redundancy |
| Query optimization | Split queries by declaration fields | Fields across different source documents have a high degree of correlation. Optimizing query statements improves accurate recall and reduces invalid context |
| Reranking | Enabled | Perform relevance sorting on recalled multi-source documents, prioritize content with high matching degree to declaration requirements, and reduce token waste |
| Context update trigger | Follow individual game declaration cycles | Update frequency for this category is irregular per game. Triggering synchronization based on individual game declaration progress avoids invalid token quota usage |

## Three Common Misconfigurations
- Symptom: Calling the FastGPT application API returns an empty context, or fails to include associated content from historical declaration materials. Cause: The value range of the `maxContext` parameter is not configured correctly, or the automatic context concatenation synchronization switch is not enabled, resulting in historical documents not being included in the context pool.
- Symptom: Single-round query token consumption far exceeds the preset value, leading to interface timeouts or truncated returned content. Cause: The `quoteMaxToken` parameter is not set, or its value is too large, causing all documents recalled by the knowledge base to be directly concatenated into the context, exceeding token limits.
- Symptom: When calling an MCP tool in a workflow, the declaration token in global variables cannot be retrieved. Cause: Global variables are not bound to the context transfer link, or the context reference permission for global variables is not enabled in the configuration, resulting in tokens failing to transfer with the context.

## How to Verify Proper Configuration
- Review the application’s context logs to confirm that the recalled document types and quantities match the preset single search limit.
- Call the API to retrieve context content, verify that the total concatenated token count does not exceed the `maxContext` configuration value.
- Simulate a complete declaration document query, check that returned content only includes fields relevant to the current declaration requirements, with no redundant content.
- Test global variable transfer in the workflow, confirm that the MCP tool can normally retrieve the bound context token.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
