# Drafting Requirements and Design Documents for Game Publication License and Publishing Declaration: Multi-turn Dialogue and Prompt Engineering

## Data Structure for This Category
The data sources for this category include official government service requirements for publishing declaration workflows, copyright registration documents, game package materials, and operational institution filing materials. Data updates occur irregularly during each game’s declaration cycle, with dynamic adjustments based on supplementary materials submitted during approval stages. Core daily documents include declaration request files, game content application forms, copyright ownership certificates, and content review reports. Fields cover declaration subject qualifications, game genre classification, copyright registration numbers, review modification opinions, and more. There is no unified fixed format template, and adjustments must be made to match the specific requirements of each declaration.

## Constraints for Multi-turn Dialogue and Prompt Engineering
Dispersed data sources that update dynamically with approval stages require multi-turn dialogue to track supplementary materials across different stages, preventing context loss. Documents have no fixed format, so prompt engineering must adapt to diverse document structures and guide dialogue to generate structured content that meets declaration requirements. Each game’s declaration data is independent, so `chatId` must be used to distinguish different conversation contexts and prevent information confusion across declarations. Fields in review reports and application forms must strictly correspond; multi-turn dialogue must repeatedly verify field consistency to avoid information discrepancies that lead to approval rejection. Additionally, declaration materials have strong professional specificity, so prompt engineering must include guidance for industry-specific terminology to ensure generated content complies with official review standards.

## Three Common Mistakes to Avoid
- Line breaks in conversation responses cause JSON request failures. The symptom is an interface error prompt containing content related to format abnormalities. The cause is failure to escape returned content, where line breaks break the grammatical structure of JSON format.
- An error is triggered when uploading declaration material files, while text conversations operate normally. The symptom is an error popup appearing after a file upload operation. The cause is failure to configure parsing rules for the corresponding file type, or the uploaded file size exceeding the allowed range.
- An `Unexpected end of JSON input` error appears during dialogue when using the ChatGLM2 model. The symptom is dialogue interruption mid-process with this error message. The cause is incomplete model returned content, or context length exceeding the model’s supported threshold leading to truncation.

## How to Verify Proper Configuration
- Initiate a new declaration conversation for a single game, verify that `chatId` is bound to the unique identifier of the corresponding declaration to prevent confusion with other projects.
- Input a fragment of a declaration document, test whether the conversation response includes correct fields, and confirm that subject information injected via `variables` takes effect.
- Upload a small declaration material file, confirm that file upload operates normally with no error prompts.
- Launch multi-turn queries, check that `messages` retains prior rounds of declaration information without context loss.

The values provided are common starting points and should be evaluated against individual deployment samples.
