# Requirements and Design Document Drafting for Game License and Publication Declaration: Document Parsing and Chunking

## What the data for this category looks like
Core data for this category originates from official and internal materials throughout the full game declaration workflow. This includes four core document types: declaration request documents, game application forms, copyright certificates, and review reports.
Data sources cover the National Press and Publication Administration service platform, copyright registration documents, game packages, and supplementary materials submitted by operating institutions.
Update frequency is irregular, aligned with each game’s declaration cycle. Fields within a single declaration package have strong correlations. For example, declaration subject information must fully match the right holder information listed in the copyright certificate.

## What constraints do these characteristics impose on the document parsing and chunking workflow
This category’s document characteristics impose multiple constraints on the parsing and chunking workflow.
First, core documents have clear title hierarchies and field binding relationships. Chunking must retain the association between titles and their corresponding content, to avoid splitting that breaks matching of required declaration field information.
Second, declaration materials include scanned copyright certificates and formatted PDFs exported from Word. The workflow must support both text extraction and scanned document parsing.
Additionally, a single game’s declaration package may include multiple attachments. Parsing time can vary, so the workflow must adapt to processing needs for materials of different sizes.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Declaration documents contain both long paragraphs of review comments and short-field application items. This range balances semantic completeness and chunk granularity. |
| `chunkSplitter` | By paragraph + title | Declaration documents have clear title hierarchies. Chunking by title preserves the binding relationship between fields and their corresponding content. |
| `customPdfParse` | Enabled | Declaration materials include scanned copyright certificates and formatted PDFs. Custom parsing enables extraction of complete text and metadata. |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Large game declaration packages may include multiple attachments. This duration covers most parsing scenarios. |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Combined declaration materials for a single game typically do not exceed this threshold, adapting to most declaration scenarios. |

## Three common mistakes
- When uploading a game application form with nested tables, chunking results lose the association between table cells and their corresponding field information. This occurs because chunking rules are not configured to follow title + table structure, and splitting is only done by character length.
- When parsing a scanned copyright certificate PDF, the extracted text contains extensive garbled characters or missing content. This occurs because the scanned document parsing mode under `customPdfParse` is not enabled, and only the default text extraction logic is used.
- When testing a review report that includes images, the knowledge base can recognize image links, but the question-and-answer workflow cannot call the image content. This occurs because the image metadata extraction function in custom PDF parsing is not enabled, and image information is not associated during chunking.

## How to confirm configurations are correctly set
- Upload a standard game application form PDF, and check that chunking results split content into independent blocks using titles such as "Declaration Subject Information" and "Game Basic Information", with each block containing its complete corresponding content.
- Upload a scanned copyright certificate PDF, and confirm that extracted text is complete, with no garbled characters or missing key fields.
- Upload a combined game declaration package under 500 MB, and confirm that the parsing task completes within 600 seconds with no timeout interruptions.
- Upload a review report that includes images, and check that chunking results include metadata links for images, to ensure subsequent question-and-answer workflows can access the relevant content.
