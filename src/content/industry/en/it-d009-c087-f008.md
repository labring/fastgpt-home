# Requirements and Design Document Drafting for Game Design and Numerical Design: Workflow Orchestration

## What Data Looks Like for This Category
Core documents for this category include gameplay design documents, numerical tables, version requirement sheets, and balance test records. Data is primarily sourced from player behavior data, publicly available competitor materials, battle logs, and version feedback. Update frequency is weekly or per version cycle. Most document fields include rule trigger conditions, character attribute values, growth coefficients, damage multipliers, and similar items. Some fields require attached units such as percentage, seconds, and points.

## Constraints on Workflow Orchestration from These Characteristics
Data sources for this category are scattered, including multiple types of unstructured and semi-structured content such as player behavior and battle logs. Workflows must support parallel pulling and integration of data from different sources across multiple nodes. Document formats vary significantly. Numerical tables require precise parsing of numerical fields. Gameplay design documents require retention of natural language rule descriptions. This imposes clear requirements on the format adaptation capabilities of input nodes. High update frequency means workflows must support scheduled triggering and incremental synchronization. Errors can lead to gameplay imbalance or version rework. Workflows must include pre-validation and exception rollback configurations.

## Three Common Mistakes
- When global historical records are included in code run node input, a validation failure prompt appears in the interface, and the workflow cannot start. The cause is that the node's input rules only allow structured data for the current node, and direct passing of global historical variables is not supported.
- Global variable initial values do not take effect after setup, and variable values do not change after updates. The cause is that the update trigger node for the corresponding document is not bound, so variables do not synchronize with document updates.
- Variables cannot be correctly referenced to the body field of document editing. The cause is that the target variable is not bound via the `variables` parameter, and unparsed global variables are referenced directly.

## How to Verify Proper Configuration
- Manually trigger the workflow once, check that the code run node executes normally with no validation failure errors.
- View the global variable panel, confirm that variable values synchronize with updates to the version requirement sheet.
- Check the context reference node, confirm that only the specified number of balance test records are pulled.
- Verify that variables are correctly populated into the corresponding fields of generated design documents or numerical tables.
