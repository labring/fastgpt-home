# Drafting Requirements and Design Documents for Game Operation Activity Configuration: Multi-turn Dialogue and Prompt Words

## What the data for this category looks like
The core data for game operation activity configuration comes from the game operation backend, player segment system, payment data platform, and activity log system. Daily produced documents include activity plans, reward configuration tables, launch checklists, and activity post-event review reports. Document fields typically include activity ID, effective time period, reward type and value, trigger conditions, and other items. Update frequency is usually weekly, or temporary adjustments made ahead of holiday events.

## What constraints these characteristics impose on the multi-turn dialogue and prompt words link
Decentralized data sources require dialogue to pull information across multiple systems. Clearly define the range of callable data sources. Many document fields and inconsistent formats require prompt words to use fixed field extraction rules to avoid ambiguity. Fluctuating update frequencies require dialogue context to support temporarily adjusted activity parameters. High-risk attributes of reward values and time configurations require multi-turn verification steps to confirm parameter compliance. Activity configuration documents must be associated with specific activity IDs and player segment data. Dialogue context must retain the complete discussion chain to prevent loss of key configuration information.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `chatId` | Bind to activity-specific ID | Ensure conversation context for one activity is not confused with other activities |
| `messages` | Retain the first 10 rounds of conversation content | Cover the full discussion cycle for a single activity configuration, avoid loss of key parameters |
| `variables` | Limit calls to two data sources: operation backend and player segments | Restrict the data range accessible to dialogue, prevent unauthorized access to irrelevant information |
| Context memory limit | 8000 characters | Adapt to communication needs for multi-turn verification of activity configurations, avoid context overflow |
| Prompt word template | Fixed extraction requirements for activity ID, effective time period, and reward fields | Unify the format of generated documents, reduce missing fields |

## Three common errors
- Empty fields returned by dialogue interface calls. The symptom is generated documents missing reward configuration values. The cause is failure to correctly bind the data source parameters corresponding to `variables`, making it impossible to pull reward data from the operation backend.
- Lost dialogue context. The symptom is subsequent questions during multi-turn configuration cannot associate previously mentioned activity IDs. The cause is failure to correctly set `chatId`, resulting in independent context generated for each dialogue.
- Prompt words failing to correctly generate documents in English format. The symptom is generated activity post-event review reports containing Chinese field names. The cause is failure to adapt prompt words to field naming rules for English business scenarios.

## How to confirm configuration is complete
The following verification actions are based on the configuration logic of FastGPT v4.17.0.
- Initiate a test dialogue, input an activity ID and reward configuration requirements, check if the generated document contains complete activity fields, and verify that the `variables` parameter is configured correctly.
- Initiate two or more consecutive dialogues, confirm that subsequent questions can associate previously mentioned activity parameters, and verify that the context memory function works properly.
- Call the dialogue interface to upload a reward configuration table file and activity screenshots, check if the interface can correctly parse file content and include it in the dialogue context, and verify that the file upload configuration is effective.
- Switch the prompt word language to English, input activity configuration requirements, check if the generated document fields conform to English naming rules, and verify that the Chinese and English prompt word configuration is effective.
