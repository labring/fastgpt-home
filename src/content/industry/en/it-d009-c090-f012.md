# Requirements and Design Document Drafting for Version Releases and Release Notes: Document Parsing and Chunking

## What this category’s data looks like
Core data for this category comes from Git tags, merge commit records, CI artifacts, and Issue milestones. Updates occur once per version. Daily deliverables include Release Notes, change logs, version tag descriptions, and release checklists. Primary users are open source maintainers, release managers, and document maintainers. Typical document structures include fields such as version number headers, change category entries, breaking change markers, and artifact verification information. No unified mandatory format exists, but most documents are produced as Markdown or plain text.

## Constraints imposed by these characteristics on document parsing and chunking
The once-per-version update frequency requires parsing processes to support repeatability and accuracy. It prevents version information misalignment caused by fluctuating chunking logic.
Data sources are scattered and have diverse formats. They include structured Git commit logs and unstructured manually written change descriptions. Chunking tools must adapt to multiple text structures.
Change categorization and breaking change descriptions are the most time-consuming steps. Chunking must split content by change type and version node to facilitate subsequent categorization and organization. It must also avoid cross-version chunking errors that could cause community confusion or version rollback issues.

## How to configure settings
The following configurations are optimized for FastGPT v4.17.0. Specific parameters are listed below:

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | `800–1200 characters` | Single change entries in release documents typically span hundreds of characters. This value ensures each chunk contains complete change descriptions and associated information |
| `chunkSplitter` | Split by Markdown headings | Release documents mostly use version numbers and change categories as heading levels. Splitting by headings ensures each chunk corresponds to an independent change group |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Log documents generated by CI artifacts are often lengthy. This value covers parsing durations for most documents, preventing mid-process timeout interruptions |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | Artifact packages and log files related to version releases typically do not exceed this threshold. It prevents invalid large files from occupying parsing resources |
| `customPdfParse` | Enabled | Some CI artifacts export release notes as PDF files. Enabling custom parsing accurately extracts text and associated artifact information |
| `chunkSettingMode` | Manual configuration | Release document formats vary across versions. Manual configuration allows flexible adaptation to specific version document structures |

## Three common configuration errors
The first error symptom is a copy prompt stating "Browser automatic copy is unavailable, please manually copy the content below". The cause is that parsed document text is not correctly bound to the same-origin page context, leading to failure of browser copy permission verification.
The second error symptom is that some MCP services fail to parse correctly. The cause is that the configured `chunkSplitter` does not adapt to the log output format of the corresponding service, leading to loss of key service identification information during chunking.
The third error symptom is that image links in the knowledge base cannot be called during question answering. The cause is that only text content is extracted during chunking, and the association between image links and their context is not retained. This leads to loss of associated information during embedding.

## How to verify correct configuration
Upload a typical version release document. Check if parsed chunks are split by version number and change category. Ensure each chunk contains complete change information.
Run a large-volume CI artifact parsing task. Confirm that no timeout errors occur during parsing. Verify the appropriateness of the `PARSE_FILE_TIMEOUT_SECONDS` value.
Trigger the copy function. Confirm that parsed text can be successfully copied to the clipboard. Verify the correctness of the same-origin context configuration.
Upload a release document that includes image links. Check if chunked text retains the association between image links and corresponding change entries.

The values listed above are common starting points. They should be evaluated against the samples associated with the actual deployment.
