# Requirements and Design Document Drafting for Version Releases and Release Notes: Forms and Interactions

## What the data for this category looks like
Data for this category corresponds to daily work outputs of open-source maintainers, release managers, and documentation maintainers. Core documents include Release Notes, change logs, version tags, and release checklists.
Data sources generally include Git tags, merged commit records, CI artifact packages, and Issue milestones. The update frequency is once per version.
The data structure usually includes fields such as version number, change category, breaking change description, and artifact links. There is no unified mandatory unit, but version numbers must follow semantic versioning format, and change entries must be categorized by module.

## Constraints on Forms and Interactions
Data for this category relies on Git, CI, and Issue systems.
Forms must support entering version tags, artifact links, and Issue number fields. External business systems or subsequent nodes implement field association logic.
Bind form trigger timing to version release nodes to match the once-per-version update frequency, avoiding invalid triggers.
Add preset classification options to the most time-consuming change categorization step, to reduce manual input costs.
Highlight breaking change descriptions separately to prevent omissions.
Errors may cause user upgrade failures or community misunderstandings. Implement required field validation and format validation via external business systems or subsequent nodes to reduce filling error rates.

## Three Common Implementation Mistakes
- Phenomenon: The `formInput` dialog box remains visible when nested in other workflows, and only hides when triggered by a single workflow. Cause: The dialog box display logic must be controlled by external workflow scheduling rules, and there is no FastGPT built-in configuration parameter for "display only when the current workflow is triggered".
- Phenomenon: The prompt configuration interface only displays two global variable options, while older versions displayed more. Cause: This phenomenon is caused by adjustments to the global variable entry in the prompt configuration interface. Refer to the official documentation of the corresponding platform for specific adjustment logic.
- Phenomenon: After enabling the speech recognition model, clicking the voice input prompt shows that the browser is not supported. Cause: The browser has not enabled voice input permissions or the corresponding speech recognition script has not been loaded. This function is provided by the browser and is not a FastGPT built-in configuration.
