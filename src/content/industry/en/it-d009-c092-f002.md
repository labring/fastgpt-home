# Drafting Requirements and Design Documents for On-Site Deployment Implementation: Context and Token

## What the data for this category looks like
Core data for on-site deployment implementation comes from on-site collected information such as customer computer room environments, equipment lists, software packages, and network topologies. Routinely produced documents include deployment manuals, installation records, configuration lists, on-site check-in sheets, and similar materials. Data is updated once per order or per stage. Document fields include equipment model, IP address, software version, installation time, on-site operation records, and more. Units include units, pieces, hours, and others. The total length of documents per stage fluctuates with deployment scale. Core content includes both structured configuration items and unstructured on-site records.

## What constraints these characteristics impose on the "context and token" workflow
Data from on-site deployment implementation is scattered and updated frequently. Multiple types of documents and on-site information must be integrated, which easily causes total context token consumption to exceed limits. The total length of documents per stage has a wide fluctuation range. If the context configuration does not match this characteristic, core information is likely to be truncated. On-site records are mostly unstructured text with inconsistent formats, requiring additional processing for context format consistency. This increases the complexity of token processing. In addition, on-site deployment documents must be strongly bound to the actual customer on-site environment. If the context is not refreshed in a timely manner, the configuration may not match the actual situation, leading to subsequent deployment errors.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Matches the average total length of on-site deployment implementation documents per stage, covers core content such as deployment manuals, configuration lists, network topology descriptions, and adapts to the global token limit of FastGPT v4.17.0 |
| `quoteMaxToken` | `2000–3000 token` | Adapts to the content length of a single core document such as an equipment list or installation record, preventing single reference content from overflowing the context window |
| Context refresh cycle | After each order stage | Matches the document update frequency of on-site deployment implementation, ensuring the context synchronizes with the latest installation records and on-site check-in data |
| Context recall count | Top 5 entries | Covers core document types per stage, avoids excessive content occupying tokens while retaining key configuration information |
| File path token attachment toggle | Disabled | Prevents uploaded file paths from carrying additional tokens, adapting to business scenarios where files are processed via HTTP requests |

## Three common configuration errors
- Setting `maxContext` too low, triggering "content exceeds length limit" error popups or logs. This occurs because general default values are used without referencing the per-stage document length of on-site deployment implementation.
- Context being interrupted after calling an MCP tool, manifested as the context window losing core configuration information after the tool call completes. This occurs because context persistence configuration is not enabled, or the configured context retention duration is shorter than the tool call cycle.
- Uploaded file paths carrying tokens, causing HTTP requests to return parameter errors or 404 status codes. This occurs because the file path token attachment toggle is not disabled, and temporary tokens are mistakenly used as part of the file path.

## How to confirm the configuration is correct
- Enter the FastGPT context preview interface, confirm that single-stage documents such as deployment manuals and configuration lists are fully included in the context window.
- Initiate a simulated deployment process call, check that the output content is not truncated, and no "content exceeds length limit" type errors appear.
- After uploading on-site deployment documents, view the file storage path, confirm that the path does not include additional token parameters.
- After completing an MCP tool call, check that the context still retains the previous deployment configuration information, with no context loss occurring.

The values provided are common starting points and should be measured against the reader's own samples.
