# Requirements and Design Document Drafting for User Growth and Retention Operations: Workflow Orchestration

## What the data for this category looks like
Data for this category typically comes from user behavior logs, push systems, experiment platforms, and CRM systems. Daily produced documents include growth experiment plans, user segmentation tables, outreach copy, and retention analysis reports. Data update frequencies are mostly daily or weekly. User segmentation tables contain fields such as user ID, outreach frequency, and retention cycle. Outreach copy must adapt to tag parameters for different user groups. Retention analysis reports summarize core indicator data on a weekly basis.

## What constraints these characteristics impose on the workflow orchestration link
Multiple data sources with inconsistent synchronization rhythms require workflows to adapt to each data source’s sync cycle. This prevents segmentation result deviations caused by data lag.
Diverse document types and dynamic field needs require workflows to support binding custom variables for different operation scenarios.
User segmentation, outreach rhythm design, and experiment result attribution are the most time-consuming steps. Workflows must split these steps into independent, reusable nodes.
Errors may cause user dissatisfaction and budget waste. Workflows must include pre-check and exception capture configurations.

## Configuration Settings
This guidance is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Knowledge base reference scope | Full accessible | Supports users to freely access any existing files, meets accurate extraction needs |
| `variables` | Bind user segmentation tags and outreach cycle variables | Adapts to dynamic fields of operation documents, enables personalized outreach |
| Single search limit | Top 8 entries | Balances the precision of recalled content and context length, avoids exceeding processing thresholds |
| Referenced content template | Retain original core sentences, remove redundant annotations | Streamlines available content, adapts to the length limits of outreach copy |
| `nodeId` | Bind experiment node and attribution node IDs | Associates workflow links with experiment data, facilitates subsequent attribution analysis |
| Maximum context length | 8000 characters | Adapts to the conventional length of retention analysis reports, avoids content truncation |

## Three Common Misconfigurations
- Phenomenon: Knowledge base recall results during workflow debugging do not match actual front-end test results. Cause: No scenario-specific variable filtering rules were bound during debugging, and front-end tests used actual running user segmentation parameters.
- Phenomenon: Custom variables in guest links do not display. Cause: Variables were not configured as publicly transmissible parameters in the workflow, and were only enabled in the debugging environment.
- Phenomenon: Referenced content returned by the AI chat node does not match the configured template. Cause: The configuration logic of the referenced content template and the reference template prompt was confused. The former formats recalled raw content, while the latter guides the AI to integrate content.

## How to Confirm the Configuration Is Correct
- Manually generate a guest link, check whether custom variables are properly passed in the link parameters and displayed on the front-end page.
- Switch different user segmentation tags, verify whether the content recalled by the knowledge base matches the file scope corresponding to the tags.
- Compare the debug output of the AI chat node with the return content of actual front-end calls, confirm that the reference template format is consistent.
- View the status logs of workflow nodes, confirm that the links bound to `nodeId` do not have execution timeouts or data loss.
