# Drafting Requirements and Design Documents for User Growth and Retention Operations: Forms and Interactions

## What Data for This Category Looks Like
This category's data mainly comes from user behavior logs, push systems, experiment platforms, and CRM systems. Daily produced documents include growth experiment plans, user segmentation tables, outreach copy, and retention analysis reports. Data update frequencies are mostly daily or weekly. Documents will include fields such as user segmentation tags, outreach rhythm configuration, and experiment grouping rules. Field units are mostly operation-related units such as natural days, number of outreaches, and sample proportion.

## What Constraints These Characteristics Impose on Forms and Interactions
The data sources for this category are scattered and update frequently. This requires the forms and interactions link to support quick reference and real-time synchronization of multi-data source fields. There are diverse daily document types, so interactions need to adapt to the exclusive field structures of different documents. Examples include tag configuration for user segmentation tables and grouping rules for growth experiment plans. Since user segmentation and outreach rhythm design are the most time-consuming steps, common configuration template functions must be implemented separately by external business systems to reduce manual data entry. The FastGPT form input node only collects entered information. At the same time, since errors will directly affect user experience and retention, field validity verification must be implemented separately by external business systems or subsequent nodes to avoid submission of unreasonable configurations.

## Three Common Mistakes
- Select configured options one by one in the User Selection Node `userSelect`, and verify whether the workflow enters the corresponding branch. Filtering of user growth and retention operation records must also be verified separately against the input, permissions, and return values of external interfaces.
- Phenomenon: Front-end test results for outreach configuration do not match workflow debugging results. Verification steps: Check the data source update frequency configuration referenced by the interaction node, and confirm whether the latest user behavior log data has been synchronized by checking external data source synchronization logs.
- Phenomenon: No validity prompt appears for the submitted segmentation rule form. Verification steps: Check whether external business systems or subsequent nodes have configured field validity verification logic, and confirm whether the outreach frequency upper limit threshold rule has been configured.

## How to Confirm Proper Configuration
- Open the variable reference configuration interface of the corresponding interaction node, and confirm that the configured user segmentation and outreach rule variables can be selected normally.
- Enter the same configuration parameters in the external workflow debugging environment and the front-end test interface respectively, and verify whether the returned results are consistent.
- Submit an ultra-high-frequency outreach configuration, and confirm that the corresponding validity verification prompt pops up from the external business system or subsequent nodes.
- View the external data source synchronization logs, and confirm that the user behavior data referenced by the interaction node has been updated to the latest version.
