# Requirements and Design Document Drafting for User Acceptance Testing Support: Multi-turn Dialogue and Prompt Words

## What the Data for This Category Looks Like
This category’s data comes from requirement specification documents, test environment configurations, customer business sample materials, and defect management systems. Data updates occur once per delivery phase or version iteration. Core daily deliverable documents include UAT test cases, acceptance issue tickets, acceptance reports, and signed confirmation forms. Each UAT test case includes fields for test scenario, preconditions, operation steps, and expected results. Acceptance issue tickets include fields linked to defect numbers, reproduction steps, and impact scope. The overall data structure is built around customer business confirmation logic.

## Constraints Imposed on Multi-turn Dialogue and Prompt Words by These Characteristics
Dispersed data sources linked to customer business scenarios require multi-turn dialogue to anchor to the test scope of the current phase, and avoid mixing cross-phase data. The phase-based update feature requires dialogue context to support isolating test data for different versions via `chatId`, to prevent context overflow. The field attributes of core documents require prompt words to clearly limit calls only to UAT test cases and issue ticket data from the corresponding phase, while adapting to the formatted output requirements of signed confirmation forms, and avoid mixing irrelevant fields in responses. Associated data from defect systems must be accurately matched during dialogue, to prevent retrieval of defect records from non-current acceptance batches.

The following configurations are optimized for FastGPT v4.17.0.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Context window size | First 8 turns of dialogue + 1000–1500 characters | Adapts to the length of individual UAT test case documents, and avoids exceeding model context limits |
| `chatId` isolation rule | Bind a unique `chatId` to each delivery phase | Prevents mixing of cross-phase test data, and matches the phase-based data update feature |
| `variables` bound fields | Bind the defect number prefix of the current acceptance batch | Accurately retrieves acceptance issue ticket data for the corresponding batch |
| Single retrieval limit | Top 3 matching results | Avoids excessive redundant data interfering with acceptance conclusion confirmation |
| Prompt template | Clearly limit usage only to UAT document content linked to the current `messages` | Prevents calling external data from non-current phases |

## Three Common Mistakes
- Symptom: Retrieved UAT test case paragraphs include hidden paragraph number fields, which are directly written into acceptance reports. Cause: Failure to explicitly require filtering non-business fields in prompt words leads to redundant information being mixed into outputs.
- Symptom: Test environment screenshot materials cannot be displayed in the dialogue window. Cause: Failure to configure supported image formats and size limits for the dialogue environment, leading to failed material rendering.
- Symptom: Custom-deployed models return inconsistent results between dialogue and workspace. Cause: Failure to uniformly bind batch parameters for `variables`, leading to deviations in retrieval scope across the two environments.

## How to Confirm Proper Configuration
- Initiate a test case query for the corresponding delivery phase, and verify that returned results only include UAT document content from the current phase.
- Submit an acceptance issue ticket including image materials, and confirm that materials render correctly in the dialogue window.
- Switch `chatId` values for different delivery phases, and verify that context does not mix data across phases.
- Enter a query with a defined scope, and confirm that returned results do not exceed associated data from the current acceptance batch.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
