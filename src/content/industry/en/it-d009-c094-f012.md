# Requirements and Design Document Drafting for User Acceptance Testing Support: Document Parsing and Chunking

## Data Characteristics for This Category
Data for this category originates from requirement specification documents, test environment configuration records, client business sample materials, and defect tracking systems. Daily output documents include UAT use cases, acceptance issue tickets, acceptance reports, and signed confirmation sheets. These documents are collaboratively maintained by implementation consultants, test managers, and client business representatives, with updates scheduled per project phase or version iteration. Most document structures contain fields such as business scenario, operation steps, expected results, issue description, and closed-loop status. No unified fixed format template exists, and adjustments are made based on client business requirements.

## Constraints Imposed on the Document Parsing and Chunking Link
Since document sources include multiple types of heterogeneous materials and no unified format is used, the parsing link must support Word, Excel, and PDF files with different layouts to avoid content loss caused by format incompatibility. Daily documents include detailed business fields. When chunking, the association logic between business scenarios and acceptance results must be retained to avoid splitting that damages business integrity.

The update frequency is per phase or version, so chunking configurations must adapt to batch processing of phase-based documents, and support precise splitting for acceptance-specific documents. This avoids retrieval matching failure caused by overly large chunks, or context loss caused by overly small chunks. At the same time, the core content length of documents is concentrated in a fixed range, so reasonable chunking parameters must be used to balance retrieval accuracy and context integrity.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | The core content length of documents such as UAT use cases and acceptance issue tickets falls within the range that a single chunk can carry, avoiding including too many unrelated business scenarios in one chunk |
| `chunkSplitter` | Split by paragraph + title | Daily documents mostly include business titles and corresponding operation steps. Splitting by paragraph retains the integrity of a single business scenario |
| `customPdfParse` | Enabled | Acceptance-specific PDF documents often include scanned copies or complex layouts. Enabling custom parsing improves OCR recognition and structure extraction accuracy |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | This is the common maximum size limit for single-phase acceptance document collections, to avoid upload failure caused by overly large files |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | This aligns with the time required to parse large acceptance reports or multi-page PDF documents, ensuring complete parsing of complex files |
| `chunkSettingMode` | Manual configuration | Adjustments to chunking rules are required for different types of acceptance documents. Manual mode adapts to the differentiated needs of multi-source heterogeneous documents |

This configuration applies to FastGPT v4.17.0.

## Three Common Configuration Mistakes
- No search results are returned after uploading a Word or Excel file, and only an error prompt is displayed. Cause: Office document parsing adaptation is not enabled, or `UPLOAD_FILE_MAX_SIZE` is set too small, resulting in file upload being blocked.
- An OCR Error error occurs when parsing a PDF file. Cause: The resolution of the scanned PDF does not meet requirements, or `PARSE_FILE_TIMEOUT_SECONDS` is set too short, resulting in parsing interruption.
- The document parsing configuration entry cannot be found after updating the version. Cause: Some parsing functions have been integrated into the general upload process, and operations must be performed through the file parsing settings entry in the knowledge base editing page.

## How to Verify Successful Configuration
- Upload a single UAT use case document, check the number of parsed chunks, and confirm that the chunk length falls within the preset `chunkSize` range.
- Upload a scanned acceptance report, check that the parsed result includes complete text content with no obvious recognition gaps.
- Upload an acceptance document collection larger than 50 MB, confirm that the upload and parsing processes complete normally, with no timeout or file size prompt.
- Search for specific acceptance issue keywords in the document, confirm that the search results match the corresponding chunk content, with no context loss.

The values provided are common starting points and should be measured against the reader's own samples.
