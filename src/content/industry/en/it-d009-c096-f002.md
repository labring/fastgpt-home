# Requirements and Design Document Drafting for Community Report Handling: Context and Token

## What this type of data looks like
Community report handling data mainly comes from report systems, involved content details, user historical behavior records, and official review rules. The update rhythm is daily or real-time. Daily produced documents include report tickets, report handling records, user appeal forms, and standardized user notification templates. Common data fields include unique report ID, involved content ID, reporting user ID, report type tag, disposal status, and associated content snapshot. There are no fixed additional statistical fields.

## Constraints on Context and Token Configuration from These Data Characteristics
Community report handling data characteristics impose multiple constraints on context and token configuration. The real-time update property of report tickets and handling records requires the context to pull the latest disposal status synchronously, to avoid disposal deviations caused by referencing expired data. The length of involved content snapshots varies widely, covering short-text reports to long image-text details, so the context loading logic must adapt to different lengths. A single report data is associated with multi-dimensional sources, so the total context token amount must be strictly limited to prevent exceeding the model's processing upper limit. The reusability of user notification templates requires the context to accurately match the variables of the current report scenario, to avoid redundant token consumption. In FastGPT v4.17.0, these constraints directly affect the parameter settings for retrieval recall and context splicing.

## How to Set Configurations
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Community report data includes multi-dimensional content such as tickets, involved content, historical records, so total token consumption must adapt to the model's window upper limit |
| `quoteMaxToken` | `1500–2000 token` | The core evidence fragment length of a single report usually falls within this range, which can accurately cover key review rules and involved content |
| Number of single retrieval recall entries | Top 3–5 entries | Valid associated data for community reports is concentrated in a small number of entries; too many recalls will increase unnecessary token consumption |
| Context synchronization frequency | Real-time | The update of report disposal status has high real-time requirements, so the context must always load the latest tickets and handling records |
| Knowledge base chunk length | 4000–5000 token | The content length of community review rules and report tickets varies widely; this chunk range can balance recall accuracy and token usage |
| Context history retention duration | 24 hours | Community report historical data is usually archived daily; retaining for 24 hours can cover the full process context of a single report disposal |

## Three Common Misconfigurations
- Phenomenon: The `quoteMaxToken` is set to 1500 token, but the loaded knowledge base content still exceeds this upper limit. Cause: The retrieved and recalled chunked content is not truncated a second time according to `quoteMaxToken`, and the complete chunk is directly included in the context, causing the referenced token to exceed the preset value.
- Phenomenon: The context history cannot be cleared in the report handling workflow. Cause: The trigger condition for clearing in the workflow node is not bound to the report scenario, or the trigger logic is not associated with specific report statuses such as appeal submission and disposal completion.
- Phenomenon: The token usage details of a single report handling Q&A cannot be viewed. Cause: The FastGPT token log collection function is not enabled, or the log collection configuration does not cover Q&A requests related to report handling.

## How to Verify Correct Configuration
- Submit a test report ticket to trigger a Q&A request, and check whether the loaded context includes the latest report disposal status and involved content snapshot.
- After adjusting the `quoteMaxToken` parameter, verify whether the length of the retrieved and recalled content meets the preset token upper limit requirement.
- Enable the token log collection function, and check whether the token consumption of a single Q&A matches the configured `maxContext` and `quoteMaxToken` parameters.
- Trigger the workflow node for report disposal completion, and verify whether the context history is automatically cleared or retained according to the configured retention duration.

The values listed above are common starting points and should be evaluated against samples appropriate to the specific use case.
