# Requirements and Design Document Drafting for Community Contributor Governance: Context and Tokens
This page is compatible with FastGPT v4.17.0.

## What this category of data looks like
Data for this category centers on community contributor governance personnel and rules. Core daily documents include four types: contribution guidelines, code of conduct, maintainer lists, and governance meeting minutes. Data sources include code repository commit records, community forum interaction data, contribution statistics reports, and offline and online governance meeting records. Update frequency is monthly or quarterly. Document fields include role permission details, contributor promotion criteria, and governance decision processes. There are no unified quantitative units. Entries are divided based on specific governance scenarios.

## What constraints do these characteristics impose on context and token handling
Data sources for this category are scattered, including unstructured meeting minutes and forum discussion content. Limit the scope of context recall to avoid mixing irrelevant code commit logs. Document update frequency is low, but content is time-sensitive. Control the retention duration of context cache to prevent calling outdated governance rules. Document fields focus on roles and rules. Prioritize context recall matching keywords related to permissions and promotions, and focus on core governance content. Additionally, errors in governance scenarios have serious consequences. Limit token consumption per call to avoid governance disputes caused by invocation failures due to overly long context.

## How to set configurations
| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| Maximum context length | 8000–12000 token | Covers the average total length of community governance documents, adapts to the context limit of general large models |
| `quoteMaxToken` | 1500–2000 token | Limits the length of a single recalled document fragment, ensures core governance rule content is complete without consuming too many tokens |
| Context recall count | Top 5–7 entries | Matches the common governance scenario requirements of this category, avoids context overload from redundant data |
| Context cache duration | 7–30 days | Matches the monthly or quarterly document update frequency, balances rule timeliness and cache efficiency |
| `maxContext` | Calibrated at 70%–80% of the total token count of the community document library | Reserves processing space to avoid invocation failures caused by overly long context |
| Context recall similarity threshold | ≥0.75 | Prioritizes recalling rule documents strongly related to current governance issues, filters irrelevant community forum casual chat content |

## Three common misconfigurations
- Phenomenon: Token limit exceeded error is triggered during invocation. Logs show the total context length exceeds the model limit. Cause: The `maxContext` configuration is not adjusted based on the actual total length of community governance documents. Using default values directly leads to context overload.
- Phenomenon: Returned governance rule content is incomplete. Key permission clauses are truncated. Cause: The set `quoteMaxToken` value is too small, which truncates core document fragments prematurely.
- Phenomenon: Old version contributor promotion rules are returned after invocation. Updated governance document content is not synchronized. Cause: Context cache duration is set too long, and does not match the monthly or quarterly document update rhythm.

## How to confirm the configuration is correct
- Upload all community governance documents, perform a single context recall test, and verify that the number of recalled documents matches the configured recall count.
- Check invocation logs to confirm that the total context length does not exceed the preset `maxContext` limit, with no token limit exceeded errors.
- Wait for document updates, trigger a context invocation, and verify that the returned content is the latest version of governance rules. Confirm that the cache duration configuration takes effect.
- Test governance questions of different lengths, and confirm that the length of recalled document fragments matches the `quoteMaxToken` setting.

The values provided are common starting points and should be measured against the reader's own samples.
