# Requirements and Design Document Drafting for Community Contributor Governance: Document Parsing and Chunking

## What the data for this category looks like
Core data for this category comes from community code repositories, forum sections, contribution statistics systems, and online or offline governance meeting minutes. Common processed documents include contribution guidelines, community code of conduct, maintainer lists, and governance meeting minutes. Maintainer lists use structured table formats, with fields such as role, permission scope, and term of office. Meeting minutes and contribution guidelines are mostly unstructured text or markdown formats. Data updates occur monthly or quarterly, with no high-frequency real-time update requirements. Document formats and content structures are relatively fixed, but include minor personalized adjustments.

## What constraints do these characteristics impose on the document parsing and chunking link
The data characteristics of this category create multiple constraints for the parsing and chunking process. First, document sources are diverse and have large format differences, so adaptation to multiple formats such as structured tables, markdown, and long-text meeting minutes is required. Second, update frequency is low, but parsing result stability must be maintained to prevent historical documents from becoming unusable due to changes in parsing rules. Third, core content focuses on role permissions and governance rules, so chunking must retain semantic integrity and must not split cross-paragraph rule descriptions. Finally, parsing results must support subsequent time-consuming processes such as role permission confirmation and rule explanation, and must enable quick location of target content.

## How to set configurations
| Configuration Item | Recommended Value | Rationale for This Value |
| --- | --- | --- |
| `chunkSize` | `800–1200 characters` | Documents in this category are mostly rule descriptions, role lists, and meeting minutes. This length retains semantic unit integrity and avoids splitting role permission descriptions or meeting topics |
| `chunkSplitter` | Split by headings and paragraphs | Daily documents mostly have hierarchical heading structures. Splitting by headings retains the logical hierarchy of documents, facilitating subsequent location of governance rules and role information |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300–600 seconds` | Some governance meeting minutes have long transcribed text. This duration reserves sufficient parsing time to prevent parsing failures due to timeouts |
| `UPLOAD_FILE_MAX_SIZE` | `100–200 MB` | Community governance documents may include batch contribution statistics data or long meeting records. This configuration adapts to large file upload and parsing requirements |
| `chunkSettingMode` | Custom mode | Document formats in this category have large differences. Custom mode allows flexible adjustment of chunking rules to adapt to different parsing needs for structured lists and unstructured minutes |

## Three common errors
- Phenomenon: After upgrading to FastGPT v4.17.0, contributor list CSV files that previously parsed normally throw errors, returning field mismatch prompts. Cause: The new version optimizes column name verification rules for structured documents and does not support non-standard column name formats from older documents.
- Phenomenon: After uploading a PDF file of governance meeting minutes, the parsing result loses the original document's chapter heading hierarchy. Cause: The `customPdfParse` configuration is not enabled, and the system's default general PDF parsing logic is used, which does not adapt to the structured typesetting of governance documents.
- Phenomenon: When calling the knowledge base file collection creation API, parsing parameters are not specified, causing the default parsing method to fail to correctly extract role and permission fields from the maintainer list. Cause: Corresponding parsing rules are not configured in the API request, and the system's default general chunking logic is relied upon.

## How to confirm configurations are properly set
- Upload a test maintainer list CSV file, and check whether the parsed chunks retain the integrity of core fields such as role and term of office.
- View the parsing task's running logs to confirm that parsing time does not exceed the duration set by the `PARSE_FILE_TIMEOUT_SECONDS` configuration, and there are no timeout error records.
- Call the knowledge base file collection creation API interface, specify `chunkSplitter` as split by headings in the request parameters, and verify whether the returned chunk results are divided according to document chapters.
- Upload a PDF format governance meeting minutes, and confirm that the parsed text retains the original document's heading hierarchy and paragraph logic.

The values given are common starting points and should be measured against the reader's own samples.
