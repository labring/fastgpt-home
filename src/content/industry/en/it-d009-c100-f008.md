# Drafting Requirements and Design Documents for Cybersecurity Level Protection Assessment Consulting: Workflow Orchestration

## What Data Looks Like for This Category
The daily documents for cybersecurity level protection assessment consulting include four types: level determination reports, gap analysis reports, rectification plans, and assessment reports. Data sources include assessment tool outputs, interview records, system inventories, and security device logs. Data updates follow a single project cycle, with all document iterations completed within that cycle. Document structures are organized around control items from cybersecurity level protection assessment standards, with fixed fields including control item number, compliance requirements, current status description, rectification measures, and more. There is no unified maximum length limit for a single document.

## Constraints Imposed on Workflow Orchestration
The multi-source data, multiple document types, and project-level update frequency of this category require workflows to support isolated configuration per project to prevent parameter confusion across different projects. The four fixed-structure documents must correspond to independent processing nodes to ensure accurate extraction of control item fields. The need to integrate multi-source data requires workflows to include cross-data source aggregation nodes. Time-consuming steps such as sorting out level determination materials and verifying control item gaps must include built-in automated verification steps to reduce manual verification error risks. The serious consequences of failed assessments require workflows to add pre-verification nodes to proactively identify issues including missing documents or incorrect fields.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context | 12000 tokens | The longest single cybersecurity level protection document is approximately 3000 characters, and the total length of the four types of documents is compatible with this setting to avoid context truncation |
| Single Search Limit | Top 8 results | The number of control items in a typical cybersecurity level protection project is approximately 6-10, so 8 results can cover the matching needs of all assessment items |
| `variables` | Bind project number and assessment level fields | Each project is updated independently, and project-specific parameters need to be passed to ensure targeted document processing |
| `nodeId` | Bind corresponding processing nodes by document type | The four types of documents need to trigger matching field extraction and verification processes separately to avoid node confusion |
| Question Optimization | Enabled | General search questions need to be converted into cybersecurity level protection standard terminology to improve matching accuracy with control item content |
| Response Timeout Threshold | 600 seconds | Adapt to the processing duration of multi-source data aggregation to avoid workflow interruption due to excessive data volume |

## Three Common Configuration Mistakes
- Phenomenon: Workflow nodes lag for more than 3 seconds when dragged, and the status is abnormal after saving. Cause: FastGPT v4.17.0 has not been upgraded. The legacy version’s node rendering logic is unoptimized, and loading multiple document nodes consumes excessive system resources.
- Phenomenon: Search results do not incorporate project context, only returning scattered assessment item content. Cause: `variables` have not been configured to bind project-specific system inventory or interview record data, and the search query is not linked to project background.
- Phenomenon: Some models return invalid content when executing workflow nodes and cannot trigger subsequent steps. Cause: A fallback node compatible with non-function call models has not been configured, and only function-call-only node types are used directly.

## How to Confirm Correct Configuration
- The workflow canvas is opened, any node is dragged, the response time is monitored, and alignment with the current version’s performance metrics is verified.
- A level determination report and system inventory are uploaded as test data, the search node is triggered, and the returned results are confirmed to be associated with project-specific parameter content.
- An attempt is made to export the current workflow configuration, the pop-up window is confirmed to open normally, and no missing parameter prompts are displayed.
- The model’s thought output switch is disabled, the workflow node is executed, and no content wrapped in `<think>` tags is confirmed to appear in the returned results.
