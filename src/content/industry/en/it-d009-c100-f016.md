# Requirements and Design Document Drafting for Classified Protection Evaluation Consulting: Forms and Interactions

## What Data for This Category Looks Like
Data for this category centers on the full workflow of classified protection evaluation. Sources include system lists exported from evaluation tools, interview records, security device logs, and on-site verification materials. Four types of documents are routinely produced: classification rating reports, gap analysis reports, rectification plans, and evaluation reports. Each document maps to one independent evaluation project. Updates follow a project-based schedule, with full updates completed within a single project cycle. Data fields revolve around evaluation control items, compliance status, rectification measures, and evidence materials. No unified fixed units apply; values adjust based on the requirements of individual evaluation items.

## Constraints Imposed by These Features on the Forms and Interactions Link
Data sources are scattered and include unstructured logs and interview content. This requires forms to support an interaction mode that combines multi-type attachment uploads and structured field entry. Single-project data updates occur frequently. Independent form entry groups must be created by external business systems per project to avoid cross-project data confusion. The FastGPT `formInput` node is responsible for collecting input data for corresponding groups. Document types are fixed and field boundaries are clear. External business systems must preset field groups for the four document types to reduce redundant entry operations. The control item gap verification process takes significant time. Support must be added for integration with external business systems to enable bulk import and data verification, reducing manual verification costs. Evaluation results directly relate to compliance risks. Forms must include required field validation and exception prompts to ensure the integrity of core data.

## Three Common Misconfigurations
- Phenomenon: No response after submitting the form, and the interface displays timeout status code 504. Cause: No reasonable timeout threshold configured in the external business system for large security device log uploads, resulting in transmission timeout.
- Phenomenon: Attachment fields in the form cannot recognize system list files. Cause: No upload whitelist preset in the external business system for corresponding file formats, causing legitimate system list files to be blocked.
- Phenomenon: A large number of empty fields appear after bulk importing control item data. Cause: No field mapping rules matched between the evaluation documents and the external business system, resulting in mismatched column names of imported data and preset form fields.

## How to Verify Successful Configuration
- Manually enter core fields for a single classification rating report, skip non-required items and submit. Verify whether the FastGPT `formInput` node triggers required field prompts to confirm that validation rules are active.
- Upload a single 500 MB security device log file. Confirm that upload progress works normally and no format block prompts appear, verifying the external business system’s upload configuration.
- Switch preset project role options. Confirm that only personnel lists corresponding to permissions are displayed, verifying the external business system’s role option configuration.
- Import a simulated control item data set. Check whether imported fields match the preset form items in the external business system, verifying data mapping rules.
