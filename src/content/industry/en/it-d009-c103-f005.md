# Drafting Requirements and Design Documents for Art Asset Production Management: Multi-turn Dialogue and Prompt Words

## What Data for This Category Looks Like
Data for this category typically originates from art asset libraries, project management systems, engine resource packages, and outsourced delivery files. Daily deliverable documents include art requirement sheets, asset specification sheets, outsourced feedback forms, and acceptance records. Most fields cover resource type, dimensions, polygon count, delivery cycle, and similar attributes. Units include pixels, triangle counts, days, and others. Data updates follow a daily or weekly cycle, with adjustments synced as projects advance. Document versions for different project stages must be linked to their corresponding conversation contexts.

## Constraints for Multi-turn Dialogue and Prompt Word Workflows
Decentralized data sources require dialogues to be bound to `variables` to call compliant cross-system data sources, eliminating information bias from manual input. Documents include numerous fields with specific units, so prompt words must preset field verification rules to ensure generated specification descriptions align with standard units such as pixels and triangle counts. Non-standard formats of outsourced delivery packages require multi-turn dialogue to gradually align on format requirements. Differences in data update frequencies require linking conversation contexts via `chatId` to prevent mixing data across projects or cycles. High resource matching standards require embedding engine resource verification logic within dialogues to proactively avoid issues like exceeded performance limits or resource mismatches.

## Configuration Settings
These configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind to project unique identifier | Ensure multi-turn dialogue contexts are linked to corresponding art projects, avoiding cross-project data mixing |
| `messages` | Retain the most recent 30 rounds of conversation content | Adapt to multi-round communication scenarios for art requirement iterations, balancing context completeness and response speed |
| `variables` | Bind read-only permission variables for art asset libraries and project management systems | Allow dialogues to directly call compliant data sources without manually re-entering resource information |
| Context length limit | 8000–12000 token | Cover the complete content length of a single art requirement sheet plus multi-round feedback, calibrated based on actual testing |
| Model switching permission | Only accessible to project administrators | Prevent format or precision mismatches caused by ordinary art personnel accidentally switching models |

## Three Common Mistakes
- Symptom: An unauthorized error message appears when calling an external art asset library plugin. Cause: The API key permission scope for the target data source was not configured in `variables`, preventing the session from pulling compliant data.
- Symptom: Asset specifications generated after switching models during a dialogue do not comply with required unit standards. Cause: Unit verification rules were not preset in the prompt words, so field constraints in the conversation context are lost after model switching.
- Symptom: Long-form asset descriptions are truncated during streaming output. Cause: The number of retained `messages` rounds and output length threshold were not adjusted, preventing complete output of long specification descriptions.

## How to Verify Successful Configuration
- Initiate a test dialogue containing fields from an art requirement sheet, and check if `variables` automatically pulls asset specification data for the corresponding project.
- Attempt to switch models, and verify that generated documents comply with preset field unit rules.
- Test the streaming output function, and confirm that long-form asset descriptions are not arbitrarily truncated.
- Call the bound plugin interface, and check if delivery verification information for outsourced packages can be pulled normally.
