# Requirements and Design Document Drafting for Landing Page Conversion Optimization: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Includes
Teams source data for this category from landing page access logs, heatmaps, form submission data, and advertising source parameters. Regular document outputs include landing page plans, buried point requirement lists, AB test reports, and form field configuration tables. Teams update these documents weekly or adjust them per individual marketing campaign.
Document fields typically include page paths, dwell time, form field validation rules, experiment group identifiers, and other relevant items. Units include seconds, entries, characters, and others. Teams must correlate and align core data with advertising delivery source parameters.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
Dispersed data sources require cross-system correlation. Multi-turn dialogue must gradually guide users to supplement data information across different dimensions, to avoid context confusion caused by inputting too many fields at once.
Document structures vary and need to match business scenarios. Prompts must adapt to field rules for different document types such as landing page plans and buried point requirements.
Update frequency adjusts with campaigns. Dialogue context must support archiving by campaign cycle, to avoid mixing data across campaigns.
Time-consuming tasks like page path analysis require linking historical data. Prompts must support filtering data by time range, to reduce manual investigation costs.

## How to Set Configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Context window length | First 8 turns of dialogue + latest 1200 characters | Adapts to the document length of weekly updates, avoids context overflow affecting subsequent questions |
| Knowledge base recall limit | Top 6 entries | Matches the conventional upper limit of field counts for documents such as form fields and buried point requirements |
| Variable binding rule | Bind `variables` by campaign dimension | Differentiates landing page data for different marketing campaigns, avoids parameter confusion |
| Dialogue timeout threshold | 600 seconds | Covers processing duration for time-consuming tasks such as page path analysis and experiment result judgment |
| Historical message retention rule | Retain latest 10 `messages` | Adapts to context coherence for multi-turn dialogue, avoids interference from redundant information |
| Question optimization switch | Enabled | Automatically simplifies complex questions about buried point requirements and AB test analysis, improves understanding efficiency |

## Three Common Misconfigurations
- Symptom: A "no knowledge base selected" prompt is returned when calling the dialogue interface, but the function works normally in debug preview. Cause: `chatId` is not passed in the request parameters to bind the knowledge base configuration for the corresponding campaign, or the knowledge base ID is not specified in `variables`.
- Symptom: Dialogue logs are not automatically cleaned by cycle, occupying storage space. Cause: Rules for archiving dialogue records by campaign cycle are not configured, and full historical data is retained by default.
- Symptom: Historical document fragments are lost during multi-turn dialogue, causing subsequent questions to fail to link to previously provided landing page plan content. Cause: The context window length is set too short, retaining insufficient historical interactions and document information.

## How to Confirm Configurations Are Properly Set
- Initiate a question that includes buried point requirement fields, check if the reply links to preset landing page document content.
- Pass the `chatId` parameter when calling the dialogue interface, confirm that context for the same conversation is correctly retained.
- View the dialogue log archiving rules, confirm that the configuration for automatically cleaning expired data by campaign cycle is active.
- Test inputting long-form AB test report content, confirm that the context window can load complete information normally.
