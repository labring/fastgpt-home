# Requirements and Design Document Drafting for License Compliance and Copyright Notices: Context and Token

## What data for this category looks like
This category of data mainly comes from code repositories, dependency lists, license texts, and contribution records. Daily output documents include LICENSE files, NOTICE files, dependency license lists, and copyright notices. Data updates occur with each version release or each dependency change. Document structures include plain-text license terms, structured dependency lists, contribution records with attribution information, and more. Fields and lengths vary significantly across different documents. The content scale of a single batch of processing fluctuates based on the number of project dependencies.

## Constraints on context and token processing
The characteristics of this category of data directly restrict context and token processing logic. First, scattered data from multiple sources and fluctuating content scale cause unstable token consumption for single-batch processing. This easily exceeds model context limits. Second, format differences across documents make unified token counting and chunking strategies difficult to adapt to all scenarios. This may result in partial content being truncated or redundant tokens occupying excessive space. Finally, frequently updated data requires frequent compliance checks. This increases resource consumption for context management and token calculation. Improper parameter configuration can trigger processing timeouts or overflow issues.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8192–16384 token` | Adapts to the total token requirements for single-batch compliance processing of most open-source projects. FastGPT v4.17.0 supports configuration in this range |
| `quoteMaxToken` | `2048 token per entry` | The license text for a single dependency typically does not exceed this length, preventing a single entry from occupying excessive context space |
| Context chunk length | `1000–1500 characters` | Matches the natural paragraph length of license texts, balancing token calculation accuracy and chunking processing efficiency |
| Single recall limit | Top 10 entries | Most compliance checks only require license data for core dependencies. Too many entries will easily exceed context limits |
| Maximum response token | `4096–8192 token` | Meets the output length requirements for generating complete dependency license lists or copyright notices |

## Three common configuration errors
- Scenario: Context overflow errors still occur after configuring `maxContext`. Cause: The cumulative token count of multi-dependency license texts is not pre-calculated. Actual processing content exceeds the set context upper limit.
- Scenario: `get tiktoken` errors occur during offline deployment. Cause: Local token calculation dependencies are not loaded correctly. The system cannot accurately count context tokens, triggering process interruption.
- Scenario: GPU memory utilization meets standards, but context length is limited. Cause: The model's native context window is not aligned with the `maxContext` configuration. Adjusting only GPU memory utilization without limiting the actual processing token upper limit causes this issue.

## How to confirm configurations are correctly set
- Upload a license list containing 10 core dependencies. Check whether the system’s displayed context token count falls within the configured `maxContext` range.
- Start the offline deployment service. Confirm there are no errors in logs related to token calculation, and that local token dependencies are loaded normally.
- Adjust `maxContext` to a smaller value. Trigger a context overflow prompt to verify the configuration is effective.
- Generate a copyright notice document. Check whether the output content length matches the configured maximum response token range.

The values provided here are common starting points. They should be evaluated against samples from the target deployment environment.
