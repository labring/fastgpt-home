# Requirements and Design Document Drafting for License Compliance and Copyright Notices: Multi-turn Dialogues and Prompts

## What Data for This Category Looks Like
This category’s data is generated around right statements and compliance documents for open-source projects. Core documents include LICENSE files, NOTICE files, dependency license lists, and copyright notice text. Data sources include code repositories, third-party dependency lists, official license texts, and project contribution records. Updates are triggered by project version iterations or dependency changes. Document fields include license type, copyright attribution entity, dependency name, and compliance check results. Only matching open-source protocol standard formats are required; no custom units are needed.

## Constraints Imposed on Multi-turn Dialogues and Prompts by These Data Characteristics
Data for this category is scattered and updated frequently. This requires multi-turn dialogues to pull the latest content from code repositories and dependency lists in real time, ensuring compliance checks are based on the latest versions. Document fields must strictly match open-source protocol standards. Prompts must use a fixed output format to generate compliant LICENSE and NOTICE files. Multi-turn dialogues must cover time-consuming steps such as license compatibility checks and copyright attribution confirmation. It is necessary to progressively ask for supplementary dependency information and contribution record details, while avoiding generating non-compliant content to prevent subsequent compliance risks.

## How to Configure
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `messages` | Append 1000–1500 characters of context per dialogue turn | This category requires retaining the latest dependency lists and copyright records. Excessively long context increases check latency. This range balances information completeness and processing efficiency |
| `variables` | Preset 3 fixed variables: project name, dependency list path, and license type template | Standardized variables reduce repeated input and ensure uniform formatting for generated LICENSE and NOTICE files |
| `chatId` | Bind to a project-specific ID | Isolates compliance dialogue contexts for different open-source projects, preventing cross-project data confusion |
| Maximum context length | 8000–12000 tokens | Must cover dependency lists and contribution records for a single version. This range fully carries the information required for core compliance checks |
| Question optimization | Enabled | Converts vague compliance requirements into clear check items, improving dialogue efficiency and accuracy |

## Three Common Misconfigurations
- Symptom: When using streaming output for dialogue API calls, generated license links only work on the current page and cannot open new pages. Cause: No link jump trigger rules for streaming output are configured, leading to front-end rendering logic not properly handling external links.
- Symptom: In FastGPT v4.17.0, dialogue log details do not match the actually generated copyright notice text. After multiple dialogues, logs still display old content. Cause: No project-specific `chatId` is bound, leading to mixed contexts across different dialogues and incorrect log cache session differentiation.
- Symptom: Generated NOTICE files omit license statements for some third-party dependencies. Cause: Latest dependency list data is not appended to multi-turn dialogues, only the initially loaded old dependency list is used.

## How to Verify Correct Configuration
- Initiate a compliance check dialogue that includes multiple third-party dependencies, and verify that the generated dependency license list includes all input dependency items.
- View dialogue logs to confirm that the `chatId` of each session matches the corresponding project ID, and that log content matches the actually generated document content.
- Trigger streaming output, click a generated license link, and confirm that it redirects to the official page for the corresponding protocol.
- Update the dependency list and initiate a new dialogue, and verify that the generated NOTICE file includes the updated dependency information.
