# Requirements and Design Document Drafting for License Compliance and Copyright Notices: Workflow Orchestration

## What the data for this category looks like
The data for this category comes from code repositories, dependency lists, license texts, and contribution records. Regularly produced documents include LICENSE files, NOTICE files, dependency license lists, and copyright notices. LICENSE files mark license types and authorization scope. NOTICE files record third-party dependencies used by the project and their corresponding licenses. Dependency license lists note the name, version, and compliance information of each dependency package. Copyright notices clarify the project's copyright ownership and contributor information. Data updates are triggered with each version release or each dependency change.

## What constraints these characteristics impose on the "workflow orchestration" link
Data sources are scattered and require cross-channel retrieval. The workflow needs multiple nodes to connect to code repositories, dependency lists, and other data sources individually. Data updates have no fixed cycle and flexible trigger conditions. The workflow needs to support event triggering instead of fixed-cycle execution. Document fields are numerous and compliance verification logic is complex. The workflow needs parameter binding to accurately match parsing and verification nodes for different documents. Errors have serious consequences. The workflow needs verification and alert links to intercept compliance risks in a timely manner.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Method | Triggered by code repository commit events, bound to the commit identifier in `variables` | Data updates are triggered with each version or dependency change. Commit events can accurately trigger the workflow, and comply with the event node rules of FastGPT v4.17.0 |
| Data Source Nodes | Associated code repository and dependency list retrieval nodes | Data sources cover multiple types of compliance data sources such as code repositories and dependency lists |
| Parameter Mapping Rules | Bind `nodeId` to the LICENSE file parsing node | Accurately associate parsing nodes for different documents to extract core fields such as copyright and license type |
| Document Parsing Character Limit | 800–1200 characters | Adapts to the typical length of license texts and copyright notices |
| Verification Timeout Duration | 600 seconds | Ensures sufficient runtime for complex license compatibility checks and copyright ownership confirmation |
| Alert Trigger Condition | Triggered when verification fails or data is empty | Errors can lead to license violations and blocked commercial use, so project maintainers must be notified in a timely manner |
| Dependency List Retrieval Limit | Top 1000 dependency items | Matches the typical scale of daily project dependencies to avoid node overload |

## Three common mistakes
- Scenario: The workflow returns a log stating "dependency license list field is empty". Cause: The data source node ID of the dependency list is not correctly bound via `variables`, so corresponding compliance data cannot be retrieved.
- Scenario: The workflow does not generate an updated NOTICE file after triggering. Cause: Accurate trigger rules for code commits or dependency changes are not configured, and fixed-cycle execution leads to outdated data.
- Scenario: The workflow times out and throws an exception error. Cause: A reasonable timeout duration is not set, and the complex logic of license compatibility checks exceeds the preset duration.

## How to confirm the configuration is correct
- Trigger a simulated code repository commit event manually, and check whether the latest LICENSE file and dependency list are retrieved.
- Review the `variables` configuration items of the workflow, and confirm that parameters such as commit hash and dependency list ID are correctly bound.
- Simulate a dependency change scenario, and check whether the license compatibility verification link triggers and generates a corresponding compliance report.
- Trigger a verification failure scenario manually, and verify that the alert configuration pushes notifications to the specified channel correctly.
