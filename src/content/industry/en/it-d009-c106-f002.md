# Drafting Requirements and Design Documents for Speech Annotation and Transcription: Context and Token

This document is written for FastGPT v4.17.0. It targets the requirements and design document drafting phase for speech annotation and transcription scenarios, with a focus on context and token configuration and implementation.

## What the Data for This Category Looks Like

Data for this category primarily comes from audio files, annotation records exported from annotation platforms, proprietary vocabularies, and spot-check samples. Daily associated documents include transcription specifications, audio task lists, quality inspection reports, and speaker annotation forms. Data updates follow daily or single-batch task cycles. Single-batch data volume fluctuates with task scale. Data fields include audio duration, speaker identifiers, transcribed text segments, annotation confidence, noise interval markers, and other fields. No unified fixed units exist; adjustments are required based on specific task configurations.

## What Constraints Do These Characteristics Impose on the Context and Token Link?

Structured text segments generated by speech annotation and transcription vary widely in length. The full transcription result of a single long audio file may exceed the single-round AI context limit, leading to truncation of key content. Auxiliary data such as proprietary vocabularies and spot-check samples must be included in the context reference range alongside the task, increasing total context token consumption. Data updated daily or in batches must load the corresponding dataset each time a task starts. If context token quotas are not reasonably controlled, task startup delays or excessive resource usage may occur. Annotation rule documents for speaker differentiation, noise judgment, and other links must be used as context references, further increasing context token occupancy requirements.

## How to Set the Configurations

| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | The context for speech annotation and transcription must include transcription specifications, audio task lists, and historical annotation samples. This range covers the total volume of documents and data for most single-batch tasks, avoiding content truncation |
| `quoteMaxToken` | 2000–3000 token | Reference data such as proprietary vocabularies and spot-check samples must independently control token consumption, avoiding occupation of the main context quota and ensuring normal operation of core task logic |
| Single transcribed text segment length | Determined via actual measurement | The transcription result of a single long audio file must be properly segmented to adapt to the `maxContext` quota setting, preventing a single segment from exceeding the context limit |
| Number of historically referenced documents loaded | Top 3 | Historical quality inspection reports can serve as reference standards for current tasks. Too many batches increase context token consumption, while too few fail to cover typical quality inspection rules |
| Context update trigger rule | Updated per task batch | Data is updated daily or in batches. Triggering updates per batch avoids resource waste caused by frequent data loading |

## Three Common Mistakes

- Phenomenon: A task prompts that the context length is exceeded during operation, and the returned result truncates part of the transcribed text. Cause: The `maxContext` configuration is not adjusted based on the total token volume of single-batch speech annotation data, resulting in exceeding the context carrying limit of the AI model.
- Phenomenon: An Ai proxy error occurs in an offline deployment environment, prompting get tiktoken dial tcp lookup failure. Cause: Local tiktoken resources are not configured, or network policies restrict access to external token calculation services, resulting in failed context token statistics.
- Phenomenon: Resource preemption occurs during concurrent task execution, and some tasks respond with a timeout. Cause: The concurrent quota for context loading is not reasonably set, resulting in excessive resource occupation in the token statistics and context matching link when multiple tasks load a large amount of audio transcription data simultaneously.

## How to Verify Correct Configuration

- View context-related parameters on the task configuration page, confirm that the values of configuration items such as `maxContext` and `quoteMaxToken` match the data scale of the current task.
- Submit a small-batch test task, check whether the transcription result is complete without truncation, and verify that the context configuration adapts to the current data volume.
- View the running logs of the offline deployment environment, confirm that there are no network errors related to tiktoken, and verify that the token statistics function operates normally.
- Simulate concurrent submission of multiple tasks, check that there are no abnormalities in the context loading and processing links of each task, and verify the adaptability of the concurrent configuration.

The values provided are common starting points and should be measured against the reader's own samples.
