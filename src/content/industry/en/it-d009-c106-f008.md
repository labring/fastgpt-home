# Drafting Requirements and Design Documents for Speech Annotation and Transcription: Workflow Orchestration

## What data for this category looks like
Speech annotation and transcription scenario data comes from four main sources: audio files, annotation platforms, proprietary vocabularies and spot-check samples.
Data updates follow daily or per-project batch cycles.
Daily produced documents include transcription specifications, audio lists, quality inspection reports and speaker annotation tables.
The core of the data structure is structured audio metadata, transcribed text and annotation tags.
Unlike text annotation projects, this category first converts audio content to structured text before carrying out subsequent processing.
Core time-consuming links focus on noise segment judgment, speaker differentiation and proprietary vocabulary proofreading.

## Constraints these characteristics impose on workflow orchestration
This category’s data characteristics impose multiple constraints on workflow orchestration.
First, data sources are scattered and updated in batches. Workflows must support batch pulling of audio and associated annotation metadata. They must also configure scheduled trigger rules to match the update rhythm.
Second, core links take a long time. Split these links into independent nodes to avoid single-node timeouts.
Third, annotation result accuracy directly affects subsequent algorithm training. Workflows must embed quality inspection nodes and failure retry mechanisms. They must also match the output format requirements of daily documents.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Mode | Batch trigger, no more than 50 audio files per batch | Matches the daily or per-batch data update rhythm, avoids overloading single processing runs |
| `variables` | Bind audio path, speaker annotation table ID | Associates audio files and annotation metadata from data sources, ensures the workflow can read corresponding annotation rules |
| Node Timeout | 600 seconds | Covers processing duration of core time-consuming links such as noise judgment, speaker differentiation |
| Retry Count | 2 times | Addresses execution failures caused by temporary interface fluctuations on annotation platforms |
| `nodeId` | Orchestrate in the order: audio import → transcription → quality inspection → export | Matches the standard business process sequence for speech annotation, ensures coherent node execution logic |
| Batch Output Format | Match transcription specifications and quality inspection report templates | Meets daily document output requirements, enables teams to directly reuse results |

## Three Common Mistakes
- Issue: After the workflow is imported into another environment, the associated annotation platform plugin cannot be called. Cause: The plugin configuration was not exported with the workflow, only the process JSON file was exported.
- Issue: A timeout error occurs during workflow execution. Cause: The node timeout was not adjusted based on core time-consuming links, and the set timeout duration is insufficient.
- Issue: Speaker annotations in the transcription result do not match the source table. Cause: The `variables` parameter for the speaker annotation table was not bound in the workflow, resulting in incorrect metadata association.

## How to Confirm Proper Configuration
- Check the workflow's trigger node configuration, confirm the trigger rule matches the daily or per-batch data update rhythm.
- Verify the data source bound to the `variables` parameter, confirm that audio files and annotation metadata can be pulled correctly.
- Run a single test case, check whether the node execution duration falls within the preset timeout range.
- Export the workflow configuration, confirm that associated plugins and metadata configurations have been exported synchronously.

The values provided are common starting points and should be measured against the reader's own samples.
