# Requirements and Design Document Drafting for Warranty Period Defect Response: Document Parsing and Chunking

## What the Data for This Category Looks Like
Data for this category primarily comes from customer-submitted warranty work orders, on-site defect confirmation sheets, R&D team repair records, and end-customer confirmation sheets. Data updates follow a per-single-work-order cycle, synced daily or alongside the processing progress of each order. There is no unified fixed document structure. Common formats include Word, PDF, or scanned documents. Core fields include defect ID, occurrence scenario, reproduction steps, associated version, responsibility judgment items, and closed-loop status, among others.

## What Constraints Do These Characteristics Impose on the "Document Parsing and Chunking" Link
Diverse data sources and inconsistent formats require the parsing link to support multiple file formats. This avoids losing key information such as defect reproduction steps due to format parsing failures. Single work order data has a small volume but frequent updates. Chunking must adapt to the rhythm of short-text high-frequency processing to avoid timeouts. Sensitive fields including responsibility judgments and customer feedback in documents must retain contextual associations during chunking. This prevents loss of complete information required for responsibility boundary judgment after splitting. Some documents include scanned copies or embedded images. Parsing must extract associated image information simultaneously. This avoids missing key scenario descriptions caused by only extracting text.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapts to the core content length of a single warranty work order, avoiding loss of complete context for defect reproduction after splitting |
| `chunkSplitter` | Split by paragraph + heading | Matches the natural structure of warranty documents divided by defect scenarios and processing steps, retaining business logic relevance |
| `customPdfParse` | Enabled | Improves parsing accuracy for scanned PDFs or warranty documents with complex embedded formats |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to time consumption requirements for batch parsing of multiple work orders per batch, avoiding parsing failures due to timeouts |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Compatible with batch packaged warranty document submissions, meeting scenarios of centralized processing by project teams |
| `chunkSettingMode` | Manual configuration | Allows adjustment of chunking rules for different types of warranty documents, adapting to diverse business document structures |

## Three Common Misconfigurations
- Phenomenon: After uploading a PDF or Word format warranty document, the parsing result has no associated image information, or the image link does not carry a preset domain name. Cause: The `customPdfParse` configuration is not enabled, or the image extraction rule is not configured, resulting in only plain text content being extracted.
- Phenomenon: After chunking, the responsibility judgment field of some work orders is separated from its context, making it impossible to associate complete judgment basis during subsequent retrieval. Cause: `chunkSplitter` is configured to split by fixed characters, not matching the natural paragraph structure of the document.
- Phenomenon: Parsing timeout errors occur when uploading multiple warranty documents in batches, returning status codes similar to `net::ERR_INCOMP`. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` configuration value is too low, not adapting to the parsing time consumption of batch documents.

## How to Confirm the Configuration Is Correct
This verification process applies to FastGPT v4.17.0.
- Upload a warranty PDF document that includes scanned copies and embedded images, and verify whether the parsing result includes image links and corresponding descriptions.
- Import a Word format work order that includes multiple sections of defect descriptions, and check whether the chunking result is divided by paragraphs, with no cross-paragraph splitting.
- Upload more than 5 warranty documents in batches, wait for parsing to complete, and check whether timeout errors occur. Confirm that the parsing time consumption meets expectations.
- View the chunked text fragments, and confirm that the responsibility judgment items and associated defect reproduction steps are included in the same chunked content.

The values provided are common starting points and should be measured against the reader's own samples.
