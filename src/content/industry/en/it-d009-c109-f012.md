# Requirements and Design Document Drafting for Identity, Account, and Permission Management: Document Parsing and Chunking

## What the Data for This Category Looks Like
Core users of this category include IAM administrators, information security specialists, and business system administrators. Daily processed documents include account application forms, permission matrices, offboarding recovery forms, and internal audit reports. Data sources are enterprise IAM systems, HR systems, business system logs, and approval systems. Update frequency aligns with personnel changes or daily synchronization. Most documents are structured forms and tables, with fields including account identifiers, permission allocation scopes, effective and expiration times, approval node information, and more. Single document sizes range from several KB to tens of MB. This page applies to FastGPT v4.17.0.

## Constraints Imposed by These Characteristics on the Document Parsing and Chunking Link
Most core documents are structured forms and permission matrix tables. Parsing must retain field association relationships, and avoid splitting content blocks that cross permission bindings. Data updates follow personnel changes or daily synchronization. The parsing link must support rapid response to upload requests, and avoid caching old data. Documents contain sensitive fields such as account identifiers and permission scopes. Chunking must ensure that single blocks do not break critical permission association logic. Single documents have limited size but dense fields. Chunking parameters must adapt to the smallest reasonable unit of structured content, and avoid semantic breaks caused by splitting.

## How to Configure the Parameters
| Configuration Item | Recommended Value Range | Rationale |
| ---|---|--- |
| `chunkSize` | 800–1200 characters | Adapts to the field density of structured documents such as permission matrices, and avoids splitting content blocks with cross-permission associations |
| `chunkSplitter` | Split by paragraphs and tables | Retains the form structure of account application forms and offboarding recovery forms, and avoids damaging field associations |
| `customPdfParse` | Enabled | Adapts to scanned documents or complex-format audit reports, and retains original layout and field positions |
| `UPLOAD_FILE_MAX_SIZE` | 50 MB | Matches the maximum common size of single documents such as IAM audit reports, and avoids parsing timeouts for large files |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses batch parsing requirements after merging data from multiple systems, and avoids failures for medium and small documents due to wait timeouts |
| `chunkSettingMode` | Manual configuration | Adapts to the structured characteristics of IAM documents, and avoids damaging permission association logic via automatic chunking |

## Three Common Configuration Mistakes
- Setting `UPLOAD_FILE_MAX_SIZE` too small triggers upload failures when uploading permission matrix Excel files. The root cause is failure to match the common single-file size of IAM documents.
- Not enabling `customPdfParse` results in missing fields and layout errors when parsing scanned offboarding recovery forms. The root cause is that the default parser cannot recognize structured content in scanned documents.
- Failing to adjust `PARSE_FILE_TIMEOUT_SECONDS` to a reasonable range leads to request failures when uploading audit reports for locally deployed large model versions, even after restarting the server. The root cause is that the default timeout duration is insufficient to complete merged parsing of multiple log datasets.

## How to Verify Successful Configuration
- Upload a standard permission matrix Excel file, and check if the parsed content retains complete table structure and field associations.
- Upload an audit report file with a size of approximately 40 MB, and confirm that the upload and parsing processes do not produce errors.
- Submit an offboarding recovery form document, wait for parsing to complete, and check that chunked content does not split the binding relationship between accounts and permissions.
- View system logs, and confirm that parsing time does not exceed the configured value of `PARSE_FILE_TIMEOUT_SECONDS`.

The values provided are common starting points and should be measured against the reader's own samples.
