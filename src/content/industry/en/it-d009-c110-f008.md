# Requirements and Design Document Drafting for On-site Outsourced Operations Services: Workflow Orchestration

## What the data for this category looks like
The data for this category primarily comes from the customer's ITSM system, monitoring platform, asset inventory, and on-duty records. Update cycles are divided into daily and monthly. Daily produced documents include on-site daily reports, service desk tickets, inspection reports, and SLA monthly reports. Data fields include on-site staff identifiers, ticket numbers, inspection item content, SLA statistics items, etc. There is no unified mandatory format, and it needs to adapt to the customer's document specifications.

## What constraints these characteristics impose on the "workflow orchestration" link
Decentralized data sources require the workflow to integrate multi-system pulling capabilities to avoid errors caused by manual copy-pasting. Differences in update cycles require the workflow to support both scheduled triggering and manual triggering modes, adapting to daily on-site daily reports and inspection reports, as well as monthly SLA reports. The inconsistent document format requires the workflow configuration text to adapt to nodes processing input content of different structures. At the same time, on-site tickets, inspection records, and SLA statistics are strongly correlated, so the workflow must clarify variable transfer rules between nodes to avoid data association errors.

## How to configure settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Scheduled Trigger Settings | Set daily trigger time to `09:00`, monthly trigger time to `08:30` on the 1st of each month | Matches the standard submission rhythm for on-site daily reports and SLA monthly reports |
| Variables Binding | Enable variable binding, specify the output of the upstream `nodeId` as the input for downstream nodes | Adapts to strongly correlated data transfer between on-site tickets and inspection records |
| Cross-Source Data Pull Configuration | Configure the pull scope according to the interface permissions of the customer's ITSM and monitoring platforms | Ensure only on-site related data within the compliant scope is retrieved |
| Text Format Adaptation | Process input content according to rules calibrated through actual testing | Adapt to differences in document formats across different customers |
| Single Node Timeout Setting | Set to `600 seconds` | Prevent workflow interruptions caused by slow responses from customer systems |

## Three Common Misconfigurations
- Symptom: When calling an external model via the code run module, streaming output cannot be implemented. Cause: The streaming output switch for the node is not configured, or the data flow from the upstream node is not correctly bound.
- Symptom: When calling a workflow via API, the variable parts in the spliced text are not returned. Cause: The API output switch for variables is not enabled in the workflow configuration, or the variable output from the upstream node is not correctly bound.
- Symptom: The text splice node outputs normally, but the AI question answering node cannot receive its input. Cause: The `nodeId` of the text splice node is not specified as the input source for the AI question answering node, resulting in interrupted data flow between nodes.

## How to Confirm Proper Configuration
- Manually trigger the workflow and check if the output of each node matches the corresponding fields of on-site daily reports and tickets.
- Configure a scheduled trigger task and verify whether the workflow starts automatically at the preset time.
- Call the API interface and check if the returned results include all configured variable content.
- Simulate concurrent calls, observe system resource usage, and adjust concurrency restriction parameters to a reasonable range.

The values given are common starting points and should be measured against the reader's own samples.
