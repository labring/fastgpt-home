# Requirements and Design Document Drafting for On-site Outsourced Operations and Maintenance Services: Document Parsing and Chunking

## What This Category of Data Looks Like
Daily documents for on-site outsourced operations and maintenance services mainly include daily on-site reports, helpdesk tickets, inspection reports, and SLA monthly reports. Data comes from the customer's ITSM system, monitoring platform, asset inventory, and duty records. Document update frequencies are divided into daily and monthly updates. Daily update documents contain fields such as ticket number, on-site problem description, and rectification measures. Monthly update documents include content such as inspection item statistics and SLA compliance rate. Some documents are attached in table, image, or scanned file formats.

## What Constraints These Characteristics Bring to the Document Parsing and Chunking Link
Documents in this category have diverse formats, including spreadsheets, image-and-text PDFs, scanned files, and other types. Some Excel documents contain multiple sheet tabs. Some PDF documents include original images that do not require secondary parsing. Daily update tickets have strong content relevance. When splitting chunks, retain the complete context of a single ticket. Statistical fields in monthly update reports must be fully preserved to avoid data fragmentation caused by splitting. Additionally, there is high demand for batch import of on-site documents. The parsing link must support multi-format batch processing. Avoid redundant OCR operations on images with already clear text to prevent damage to existing typesetting or loss of original image information.

## How to Set the Configuration
This configuration is formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | `800–1200 characters` | Adapts to the content length of daily on-site reports and tickets, retains business context while avoiding excessively long chunks that impact retrieval |
| `customPdfParse` | `Enable as needed, disable automatic OCR` | Most on-site documents are in electronic format, no need for secondary OCR of image content, preserves original image typesetting |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | Adapts to the parsing duration of batch documents such as SLA monthly reports, avoids parsing failures caused by timeouts |
| `chunkSplitter` | `Split by paragraph + heading` | Matches the chapter structure of operations and maintenance documents, retains business logical association after splitting |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | Supports batch import of large-volume documents such as inspection reports |

## Three Common Misconfigurations
- Symptom: Sheet names are not extracted after parsing an Excel document, and the corresponding fields are empty. Cause: The default parsing rule only reads the first sheet tab, and multi-sheet extraction parameters are not configured.
- Symptom: Images in PDF documents are automatically converted to plain text via OCR, and original image typesetting is lost. Cause: The global PDF enhanced OCR function is enabled, and the automatic OCR switch is not disabled for on-site documents.
- Symptom: No parsing results are returned after importing a PPT or DOC document, and the content is empty. Cause: The PDF enhanced function only adapts to PDF format documents, and general document parsing rules are not configured.

## How to Confirm the Configuration Is Properly Set
- Upload a single daily on-site report PDF, check whether the parsing result retains the original image and does not perform OCR conversion on the image content.
- Upload an Excel ticket template containing multiple sheet tabs, check whether the parsing result includes all sheet names and corresponding content.
- Upload a single SLA monthly report DOC document, check whether the parsing result fully extracts the text content.
- View the parsing task log to confirm that no timeout-related error messages are triggered.

The values provided are common starting points and should be measured against the reader's own samples.
