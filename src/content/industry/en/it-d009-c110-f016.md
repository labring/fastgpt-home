# Drafting Requirements and Design Documents for On-site Outsourced Operations and Maintenance Services: Forms and Interactions

## What this category’s data looks like
Core data for on-site outsourced operations and maintenance services comes from customer ITSM, monitoring platforms, asset inventory, and on-duty records. Update cycles fall into two categories: daily updates (such as on-site daily reports, service desk tickets) and monthly updates (such as SLA monthly reports). Daily produced documents include on-site daily reports, service desk tickets, inspection reports, and SLA monthly reports. Document fields cover duty periods, inspection equipment numbers, ticket numbers, service completion status, and more. Some fields must match standardized formats filed by the customer. The overall data structure is built around on-site service delivery and contract performance requirements.

## What constraints these characteristics impose on forms and interactions
The diversity of data sources requires external business systems to implement data source association and automatic backfill logic. The `formInput`/`userSelect` nodes only collect and pass user input or selection information to reduce duplicate data entry. The classification of daily and monthly updated documents requires external business systems or subsequent workflows to configure field grouping logic. The `formInput` node only collects input information for corresponding fields, adapting to different entry scenarios for daily inspection records and monthly SLA statistics. The completeness of core business fields directly affects service performance evaluation. External business systems or subsequent workflows must configure mandatory verification rules to avoid missed entries. The `formInput` node only collects input information for corresponding fields. The requirement to associate on-site personnel with service records requires external business systems to provide standardized option data sources. The `userSelect` node only loads and displays corresponding options, ensuring entered information matches customer-filed data and avoids discrepancies.

## Three Common Configuration Mistakes
- Phenomenon: When configuring form docking for notification channels, the system prompts "Receiving message address verification failed (please ensure the address is accessible via public network)". Verification steps: Check whether the form callback address is configured as a publicly accessible path, and check whether external docking parameters related to SSL certificate verification are configured correctly.
- Phenomenon: The `formInput` node does not display any prompt when input content exceeds the preset length. Verification steps: Check whether text input length verification logic is configured in the external business system or subsequent workflows.
- Select configured options item by item in the User Selection Node `userSelect`, verify whether the workflow enters the corresponding branch; filtering records related to on-site outsourced operations and maintenance services must additionally verify the input, permissions, and return values of the external interface.
