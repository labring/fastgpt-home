# Requirements Analysis and PRD Management: Requirements and Design Document Drafting — Document Parsing and Chunking

## What data falls under this category
Data for this category primarily comes from daily deliverables of internet product teams, business analysts, and product managers. These deliverables include requirement research notes, PRD documents, user story lists, and requirement change forms.
Data sources cover customer interview records, ticketing systems, public competitor pages, and event tracking dashboards. Update frequency is weekly or per version iteration.
Documents typically include business goal definitions, acceptance criterion descriptions, functional boundaries, and change tracking fields. There is no unified mandatory format, but requirement scope and execution standards must be clearly defined.

## What constraints do these characteristics impose on document parsing and chunking
Daily produced documents have inconsistent formats. They include unstructured interview notes, structured PRD tables, and change forms. The parsing process must adapt to multiple types of content structures.
The weekly or per-version update frequency requires the parsing workflow to quickly respond to document changes. It must avoid redundant repeated processing.
Clearly defined business goal and acceptance criterion fields in documents must be fully retained. Chunking must not split critical logic. Split critical logic will disrupt subsequent requirement alignment and development verification.
Additionally, batch uploading multiple documents is a common scenario. The parsing process must support unified processing of single or multiple requirement documents.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the average length of functional modules in PRD documents, avoids splitting critical logic such as acceptance criteria |
| `chunkSplitter` | Split by paragraph + heading | Matches the chapter- and feature-point-based structure of requirement documents, preserves contextual associations |
| `customPdfParse` | Enabled | Adapts to tables and heading hierarchies in exported PRD PDF documents, restores original document structure |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch uploading multiple requirement documents, adapts to team version iteration batch document processing needs |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Matches the parsing duration of large PRD documents or combined multiple documents, avoids mid-process interruptions |
| `chunkSettingMode` | Manual configuration | Allows adjustment of chunking rules for different types of requirement documents, such as research notes and change forms |

FastGPT v4.17.0 supports custom adjustment of the above configuration items.

## Three common configuration mistakes
1.  Calling the workflow API to upload images or documents returns a parameter error with status code 400. The cause is failure to pass the correct field format or field names as required by the interface documentation, and failure to match the parameter specifications for document parsing.
2.  Setting `chunkSize` to an excessively small value, resulting in complete acceptance criteria being split into multiple chunks after processing. The cause is failure to adjust parameters based on the content structure of requirement documents, and blind use of generic small chunk configurations.
3.  Parsing tasks time out and fail when batch uploading multiple requirement change forms. The cause is failure to adjust the `PARSE_FILE_TIMEOUT_SECONDS` parameter; the default duration is insufficient for the parsing process after combining multiple documents.

## How to confirm configuration is applied correctly
- Upload a typical PRD document, review the parsed chunk results, and confirm each chunk contains complete functional modules or acceptance criterion content.
- Call the file upload interface, pass a test requirement document, and verify that the returned parsing status and chunk information match the expected configuration rules.
- Adjust the specified chunking configuration items, re-upload the same document, and compare changes in chunk length or structure to confirm the configuration has taken effect.
- Upload a test file larger than the standard single-document size, verify that the parsing process does not trigger a timeout error, and confirm the timeout parameter configuration meets actual needs.

The values provided are common starting points and should be measured against the user's own samples.
