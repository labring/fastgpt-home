# Requirements and Design Document Drafting for Project Implementation Plan Management: Context and Token

## What data for this category looks like
Data for this category typically originates from project contracts, work breakdown structures (WBS), client-confirmed schedules, and enterprise project management systems. Daily deliverable documents include overall project plans, milestone node lists, weekly progress reports, and risk and issue tracking lists. Data update frequency is typically once per week or triggered by individual milestone nodes. Core fields include task breakdown items, responsible person assignments, scheduling nodes, risk levels, and response measures. There is no fixed unified standard format, and content is dynamically adjusted based on project phase.

## Constraints on context and token handling from these characteristics
Data for this category is scattered and has inconsistent formatting. Cross-source information requires complete contextual association to accurately restore the full project overview, which creates a requirement for complete context recall. Data is updated weekly or per milestone, and incrementally updated content must be included in the context scope to avoid missing latest progress adjustments and risk records. Core documents include multiple types of project-related entries, and single documents have high token usage. If reasonable limits are not set for context and reference token caps, model output truncation or call timeouts are likely to occur. Additionally, project scheduling and task breakdown rely on preceding and subsequent related information. Context truncation will break scheduling logic, reducing the accuracy of requirement and design documents.

## Configuration settings
This document is written based on the configuration logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–10000 token | Covers associated information across multiple core documents including project plans, weekly reports, and risk lists, to avoid truncation of key scheduling and task content |
| `quoteMaxToken` | Single reference no more than 1200 token, total references no more than 3000 token | Project documents have long single-item content, limit single and total reference length to avoid context overload |
| Maximum response tokens | 2000–2500 token | Requirement and design document drafting requires outputting complete task breakdowns and scheduling descriptions, with sufficient response length to cover full document content |
| Context update trigger timing | Triggered weekly or after individual milestone nodes are completed | Matches the regular update rhythm of this category of data, ensuring the context includes the latest progress and risk records |
| Similarity matching threshold | 0.75–0.85 | Filters low-relevance non-project core documents to avoid irrelevant information interfering with requirement document drafting logic |

## Three common configuration mistakes
- Some project scheduling logic in generated requirement documents is broken, and historical task information recalled by the context is incomplete. This occurs because the `maxContext` value is set too low, truncating scheduling associated information from prior milestones and preventing the model from restoring the complete project progress context.
- Generated document output is truncated halfway, or some image reference addresses fail to display normally. This occurs because the `quoteMaxToken` or maximum response tokens value is set too high, causing the context to occupy too many model token quotas or resulting in truncated resource path information.
- Model calls fail, with a prompt that the specified model interface cannot be connected. This occurs because the address and key for `ai proxy api` are not configured correctly, or model call parameters are not properly set in environment variables.

## How to verify your configuration
- Import typical project documents for this category, including project plans, weekly reports, and risk lists, test generating requirement and design documents, and check whether core content is fully covered.
- View model call logs to confirm that the total length of recalled context documents does not exceed the preset `maxContext` value, and single reference lengths comply with `quoteMaxToken` limits.
- Adjust the context update trigger timing, compare document content generated before and after the update, and confirm that the latest project progress and risk records have been included in the context.
- Test generating documents containing image references, check that image addresses are complete and not truncated, and confirm that knowledge base resource reference logic complies with configuration requirements.
