# Requirements and Design Document Drafting for Project Archive Handover: Workflow Orchestration

## What this category of data looks like
Data for this category primarily originates from project document libraries, configuration lists, meeting minutes, and test reports. Regularly produced documents include completion documents, configuration manuals, training records, and acceptance certificates. Data is updated synchronously at the end of each project phase or when the overall project concludes. Each individual document includes fields such as project number, document version number, signatory information, archive date, and associated project ID. Some acceptance-related documents also include a scanned copy of the client’s official seal and an acceptance result identifier.

## What constraints these characteristics impose on the workflow orchestration link
Scattered data sources and flexible update rhythms require the workflow to support multi-source data pull nodes. These nodes can connect to data sources stored in different paths, including project document libraries and configuration lists. Document types cover multiple categories such as completion, training, and acceptance documents. Verification rules differ across document types, so categorized verification branches must be configured in the workflow. Each individual document includes multi-dimensional fields, and version consistency checks and integrity checks are core time-consuming steps. The workflow must include built-in automated verification nodes that trigger exception flags for documents with missing fields or version mismatches. Operation traces must be retained during the archiving process to support subsequent operation and maintenance traceability.

## How to configure settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Trigger Node Settings | Trigger upon project phase completion marker, or manual trigger | Adapts to the rhythm of phase or wrap-up data updates for this category |
| Multi-source Data Pull Configuration | Associate preset project ID parameters in `variables` | Accurately pull document library and configuration list data for the corresponding project |
| Pull Timeout Threshold | 300 seconds | Adapts to the time-consuming requirements of multi-source document pulling |
| Document Verification Node | Match classification rules for completion documents, acceptance certificates, and similar items | Differentiate verification logic for different document types |
| Exception Alert Configuration | Push alert information within 5 minutes after triggering | Ensure timely response to identified issues |
| Archive Storage Path | Configure in the format `/project_archive/{nodeId}/v{version}` | Store files categorized by project ID and version number |

## Three Common Misconfigurations
- Symptom: The running result of a code node cannot be passed to an AI chat node, triggering the `chat:ai_input_is_e` error. Cause: No result storage variable is configured in `variables`, and the code node output is not bound to the input parameters of the AI node.
- Symptom: When using the database connection plugin to connect to PostgreSQL, the interface prompts "Workflow verification failed, please check for missing or empty values, and whether connections are normal", and configuration verification cannot be completed. Cause: No address, port, account, and password parameters required for database connection are configured in `variables`, or the connection does not correctly associate the database node with subsequent processing nodes.
- Symptom: When referencing fields of project documents in the workflow, using the `[{datasetId: xxx}]` format fails to read data normally. Cause: The FastGPT standard `{{variables.xxx}}` variable reference format is not used, and the syntax of knowledge base variables is incorrectly applied.

## How to Confirm Configuration is Complete
- Manually trigger the workflow once, review the running logs of each node, and confirm that the multi-source data pull node successfully obtains document data for the corresponding project.
- Submit a test document with missing fields, and confirm that the verification node correctly marks exceptions and triggers alerts.
- Check the storage path of the archive node, and confirm that generated archive files are stored categorized by project ID and version number.
- View the variable binding configuration of the workflow, and confirm that `variables` and `nodeId` parameters are correctly associated with corresponding nodes.
