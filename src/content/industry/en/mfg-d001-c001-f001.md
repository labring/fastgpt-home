# Supplier and Process Quality Audit for PCB Manufacturing: HTTP Interfaces and External Systems

## What data looks like for this category
This category of data primarily comes from Gerber files, drill files, BOM lists provided by customers, as well as factory internal CAM system data, production equipment parameters, bath solution test results, AOI inspection reports, electrical testing reports, and laboratory slice reports. Data updates cover continuous collection per production batch or each shift. Daily documents include engineering production instructions, drilling and lamination parameters, chemical solution analysis records, and more. Data fields cover graphic parameters, hole position information, inspection results, process parameters, and other categories. Units are adjusted based on inspection items and process requirements.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
Data sources for this category are scattered and update frequently. Interfaces must support batch pulling and real-time synchronization of multiple data sources. Daily documents include structured and unstructured content such as Gerber analysis records and AOI reports. Interfaces must support file upload and field extraction capabilities. Data is associated with production batches and process parameters. Interfaces must support associating data by production batch identifiers to avoid data misalignment. The consequences of errors are severe. Interfaces must be configured with complete failure retry and status verification mechanisms to ensure data transmission accuracy.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer ${工厂系统API密钥}` | Complies with HTTP standard authentication formats and adapts to authentication rules for most industrial systems |
| `variables` | `{"batch_no": "${当前生产批编号}", "gerber_path": "${上传的Gerber文件路径}"}` | Matches the business logic of PCB manufacturing data management by production batch, and passes core business identifiers and core file parameters |
| `responseData` | `Extracted fields: [{"defect_type": "检测报告.缺陷类型"}, {"pass_rate": "检测报告.合格率"}]` | Quickly extracts key indicators required for supplier audits from the return results of AOI and electrical testing reports |
| Timeout period | `300–600 seconds` | Process parameters and inspection report generation for PCB manufacturing take a certain amount of time; this avoids interrupting normal requests due to short timeouts |
| File transfer method | `multipart/form-data` | Adapts to the upload requirements of unstructured files such as Gerber files and AOI reports, and complies with interface requirements of most industrial equipment |

## Three common mistakes
- Scenario: When the stream parameter is set to true when calling the interface, only segmented data is received and the final result cannot be obtained. Cause: The result aggregation logic is not configured. Only the sharded data returned by the stream is received, and it is not merged into a complete output.
- Scenario: An interface error occurs when uploading a Gerber file or AOI report, and parameter transfer fails. Cause: The request body in multipart/form-data format is not correctly configured, or the file parameters are not mapped to the field names required by the interface.
- Scenario: The interface call succeeds but the required audit fields cannot be extracted, and the returned fields are empty. Cause: The `responseData` extraction rules are not configured according to the actual data structure returned by the interface, and the field path matching is incorrect.

## How to confirm the configuration is correct
- Call the test interface and check the returned authentication status code to confirm that the `Authorization` configuration is correct.
- Upload a small test Gerber file, check the file analysis results returned by the interface, and confirm that the `variables` and file parameter configurations match the business logic.
- After configuring the `responseData` extraction rules, check the field extraction results of the returned data to confirm that the field paths match the interface return structure.
- Simulate a long-running production batch audit request to confirm that the interface does not trigger a timeout, and adjust the timeout threshold according to actual process time consumption.

The values provided here are common starting points and should be measured against the reader's own samples.
