# Supplier and Process Quality Audit for PCB Manufacturing: Workflow Orchestration

## What the data for this category looks like
This category’s data covers all process stages of printed circuit board factories. Daily documents include engineering production instructions, Gerber analysis records, drilling and lamination parameters, chemical solution analysis, AOI reports, electrical test reports, and sectioning reports.
Data sources include Gerber, drill tape, and BOM files provided by customers. Additional sources are CAM system data, production equipment parameters, bath solution test results, AOI and electrical test equipment data, and laboratory test records.
Data updates run per production batch and on a shift-by-shift basis. Some equipment parameters and bath solution data are collected continuously.

## What constraints these characteristics impose on workflow orchestration
Data sources for this category are scattered, and update rhythms vary widely. Workflow orchestration must adapt to the order of multi-source data pulling and verification nodes.
Multiple types of daily documents require dedicated format parsing nodes for each document type.
Key processes such as engineering data conversion, lamination and drilling control must be embedded as core verification links in the workflow. This ensures each step of data meets electrical connectivity and manufacturing accuracy requirements.
Continuously collected real-time data needs trigger-based nodes. This avoids production delays caused by batch processing lag.
Strict cross-batch data isolation rules prevent cross-contamination of parameters and test data across different production batches.

## Configuration settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` initialization rule | Load and bind when triggered by a production batch | Data updates per production batch. This ensures variables for each batch match customer documents and parameters |
| Node execution order | Execute serially in `nodeId` order | Aligns with the sequential logic of PCB manufacturing processes. This avoids cross-process data confusion |
| Debug timeout setting | 600 seconds | Covers time-consuming steps such as complex Gerber analysis and AOI data verification |
| Variable transfer scope | Only the current workflow instance | Prevents cross-contamination of `variables` data across different production batches |
| Workflow export configuration | Package and archive by production batch | Matches archiving and audit requirements for daily production documents |

## Three common misconfigurations
- A button click in the workflow returns an empty `variables` value. This happens because global variables are not initialized and assigned in the workflow startup node. Variable values are only written after subsequent nodes run.
- Workflow debugging returns an error message containing "Dangerous behavior". This happens because the execution scope of `nodeId` is not restricted. This leads to cyclic triggers or invalid node calls.
- The workflow returns a base64-formatted AOI report that cannot be displayed as an image. This happens because no image decoding node is configured in the workflow. The base64 string is passed directly to the display link.

## How to verify the configuration is properly set up
- Start a simulated production batch workflow. Check whether `variables` loads bound data such as the Gerber number and drilling parameters for the corresponding batch.
- Manually trigger the node with the specified `nodeId`. Confirm the workflow executes in the preset order, with no cycles or invalid calls.
- Import base64-formatted AOI report data. Verify the workflow can properly decode the data and generate viewable images.
- Export the current workflow configuration. Confirm the exported file structure matches archiving requirements for daily production documents.

The values provided here are common starting points and should be measured against the reader's own samples.
