# Supplier and Process Quality Audit for SMT Placement and Electronic Assembly: HTTP Interfaces and External Systems

## What Data Looks Like for This Category
Data for this category primarily originates from customer-provided BOMs, Gerber files, component coordinate files, MES systems, solder paste and component batch ledgers, placement machines, SPI/AOI inspection equipment, and reflow oven temperature collection systems. Daily documents include BOMs and coordinate files, line change sheets, stencil parameters, furnace temperature records, first article confirmation sheets, SPI/AOI defect reports, maintenance records, and traceability labels.
Data updates trigger in real time with work orders and line changes. Fields include part numbers, reference designators, component batch numbers, defect coordinates, temperature curve parameters, and more. Some parameters use millimeters and degrees Celsius as units.

## Constraints Imposed by These Characteristics on HTTP Interfaces and External Systems
This category’s data has high real-time requirements, with updates triggered in real time by work orders and line changes. HTTP interfaces must support high-frequency calls and real-time data synchronization.
Document types include structured BOMs, semi-structured inspection reports, and plain text records. Interfaces must adapt to receiving and parsing multi-format data.
Fields include precise coordinates, temperature values, and component batch parameters. Interfaces must strictly validate field formats and unit consistency.
First article confirmation and defect reports must be quickly synced to audit workflows. Interface latency must meet production cycle requirements.
Traceability labels are linked to work order information. Interface calls must include work order identifiers as context parameters to ensure accurate data binding.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Interface Timeout | 600 seconds | Matches the average processing cycle of production work orders to avoid workflow interruptions caused by device response delays |
| Single Request Data Limit | 50 records | Adapts to the single line change or batch data volume of SMT work orders to prevent request overload |
| `Authorization` Authentication Method | Bearer Token Format | Complies with FastGPT v4.17.0 official interface security specifications to secure external system call permissions |
| Knowledge Base Import Batches | Split batches by work order | Corresponds to the independent data scope of SMT work orders to facilitate subsequent audit traceability |
| `variables` Context Binding | Bind work order ID and component batch number | Matches the associated attributes of this category’s data to ensure accurate data context during audits |
| Response Data Extraction Rule | Extract the `responseData` field | Complies with FastGPT interface return standard formats to facilitate external system parsing of audit results |

## Three Common Misconfigurations
- Interface calls return null values, and the return results of workflows nested with knowledge base assistants are empty. Cause: Correct work order context variables are not included in interface requests, causing the knowledge base to fail to match the corresponding batch of SMT data.
- Uploaded CSV files are not split into QA pairs as expected, resulting in slow retrieval speed after import. Cause: Data batches are not split by work order dimension, causing the knowledge base index to include redundant cross-work order data and increasing retrieval overhead.
- Interface requests return a 401 Unauthorized error. Cause: The Token format of the `Authorization` parameter is not configured correctly, causing FastGPT to fail to verify the calling identity.

## How to Confirm Configuration Is Complete
- Initiate an interface call with simulated work order data, check that the returned response body includes the correct `responseData` field content.
- Upload BOM and SPI report files for the corresponding work order, verify that the documents generated in the knowledge base match the original data fields.
- Simulate an interface synchronization request after a line change, confirm that the system completes data reception and indexing within the preset timeout period.
- Call the interface to trigger knowledge base retrieval, verify that the returned results are associated with matching component batches and work order IDs.

The values provided are common starting points and should be measured against the reader's own samples.
