# Supplier and Process Quality Audit for SMT Mounting and Electronic Assembly: Workflow Orchestration

## What Data Looks Like for This Category
Core data for SMT mounting and electronic assembly comes from customer-provided BOM, Gerber, and coordinate files, as well as on-site equipment including MES systems, mounters, SPI/AOI inspection devices, and reflow oven temperature recorders. Daily documents include changeover sheets, stencil usage records, first article confirmation reports, repair records, and traceability labels.
Data is updated in real time per work order and each changeover. Core fields include part number, reference designator, component batch number, reflow temperature curve parameters, and defect type.

## Constraints Imposed on Workflow Orchestration by These Characteristics
The data for this category is highly dynamic. New data is generated for every work order and changeover. This requires workflows to support dynamic variable binding to avoid adaptation issues caused by hardcoding.
Multi-source heterogeneous data collection needs require workflows to integrate multiple types of nodes such as form inputs and API calls. This adapts to device logs and document formats from different sources.
Cross-device and cross-system data association needs require workflows to bind output data from different stages via node IDs. This enables automatic association between first article reports and defect records.
Strict data validation requirements mean field validation steps must be added to workflows. This prevents batch quality risks such as wrong components and dry joints.

## Configuration Settings
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Bind work order ID, component batch number, reflow temperature threshold | Match dynamic data requirements per work order, associate node data from corresponding stages |
| Form input node | Configure three required fields: part number, reference designator, component batch number | Align with core field requirements for SMT work order documents |
| User selection node | Pre-set five options: First article qualified, solder paste defect, placement offset, solder joint short circuit | Align with defect classification standards from SPI/AOI reports |
| API call node | Set request timeout to `30 seconds` | Adapt to real-time data return rhythm of mounters and SPI devices, avoid process blocking |
| `nodeId` | Associate first article verification node and defect record node | Bind output data from the two nodes to enable automatic association of defect records with corresponding first article reports |

## Three Common Misconfiguration Scenarios
- Scenario: After importing a workflow from version v4.6.7 into version v4.8.10, some node configurations fail. The cause is that the `variables` binding format of the old workflow does not adapt to the new version rules.
- Scenario: When publishing a workflow via API call, interactive prompts for user selection or form input are not triggered. The cause is that the pass-through logic for interactive nodes is not enabled in the API trigger configuration.
- Scenario: A parameter error is triggered when configuring a knowledge base ID as a workflow variable. The cause is that the `variables` item is not correctly bound, and unvalidated field values are passed directly.

## How to Verify Proper Configuration
- Upload a single test work order BOM file, check whether the workflow automatically extracts and binds the corresponding `variables` fields.
- Call the published workflow via API, confirm whether the preset interactive node prompts are triggered.
- Simulate a changeover operation, verify whether the workflow starts execution according to the set trigger rules.
- Pass a test knowledge base ID parameter, confirm that no parameter error is triggered by the workflow.

The values provided are common starting points and should be measured against the reader's own samples.
