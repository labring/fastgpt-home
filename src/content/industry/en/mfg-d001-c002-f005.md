# Supplier and Process Quality Audit for SMT Placement and Electronic Assembly: Tool Calls and Plugins

## What the data for this category looks like
This category's data comes from BOMs, Gerber files, component coordinate tables provided by customers, plus real-time collected data from workshop MES systems, placement machines, SPI/AOI testing equipment, and reflow ovens. Documents processed daily include changeover sheets, stencil usage records, furnace temperature curve logs, first article confirmation sheets, SPI/AOI defect reports, maintenance ledgers, and product traceability labels. Data updates take effect in real time with production work orders and changeover operations. Some batch-specific data such as solder paste and component batch numbers are synchronized according to inbound batches. Document fields include part numbers, reference designators, component coordinates, testing thresholds, furnace temperature parameters, etc. There is no unified universal format, and archiving must be done per work order.

## What constraints these characteristics impose on the "tool calls and plugins" workflow
The real-time nature, heterogeneous format, and binding to work order and batch attributes of this category's data impose multiple constraints on tool calls and plugins. First, the ability to update in real time with work orders and changeovers requires tool calls to support dynamic passing of work order-specific parameters, with no reusable fixed configurations. Second, multi-source heterogeneous documents such as CSV-formatted BOMs and PDF-formatted SPI reports have significant differences, requiring plugins to adapt parsing rules for different document types. Third, traceability data must be bound to work order IDs and component batch numbers, requiring associated fields to be carried during tool calls to complete data verification. Fourth, real-time collected furnace temperature and testing data requires plugin request latency to match workshop production rhythms, to avoid disrupting production line processes.

## How to set up configurations
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | Must automatically select whether to trigger external tools based on tool call requirements returned by plugins, to adapt to multi-scenario quality audit workflows |
| Workflow/API function-call configuration | `Allow passing work order IDs, component batch numbers` | Must bind associated fields for production data to complete cross-verification of supplier materials and production process data |
| File parsing type | Auto-detect, supports CSV, PDF, TXT | Documents in this category include multiple heterogeneous formats such as CSV-formatted BOMs and PDF-formatted SPI/AOI reports |
| Request timeout | `30–60 seconds` | Real-time production data must be returned within a short time to avoid blocking workshop production line processes |
| Environment variable call permission | Enabled, bound to work order-specific secret keys | Must securely call exclusive interfaces of workshop MES systems to avoid leakage of production data |
| Single tool call limit | `Top 3 entries` | Must limit the number of defect reports returned per call to avoid overloading workflow nodes |

## Three common misconfigurations
- The symptom is a tool interface call returning a 200 status code, but workflow node output fields are empty. The cause is failing to enable the result return switch in plugin configuration, or failing to correctly bind the automatic trigger rule for `toolChoice`, resulting in tool call results not being captured.
- The symptom is an error "Unable to parse file format" when tool calls are made with a CSV file of component coordinates or a PDF SPI report. The cause is failing to configure auto-detected file parsing types, or failing to adapt to the specific layout format of documents in this category.
- The symptom is an empty value returned when calling custom environment variables in a workflow. The cause is failing to mount environment variables such as workshop MES interface secrets to the container during FastGPT deployment, or failing to enable environment variable call permission.

## How to verify a correct configuration
- Submit a test work order to trigger the tool call plugin, and check if the workflow node returns parsing results for the corresponding work order's BOM and SPI reports.
- Manually pass a document with an abnormal format to verify if the plugin automatically identifies and completes parsing without errors.
- View FastGPT runtime logs to confirm whether associated fields such as work order IDs and component batch numbers are correctly carried during tool calls.
- Call the environment variable test node to verify that parameters such as workshop interface secrets configured during deployment can be correctly read.

The values provided are common starting points and should be measured against the reader's own samples.
