# Supplier and Process Quality Audit for SMT Mounting and Electronic Assembly: Document Parsing and Chunking

## What this category’s data looks like
The typical entities in this category are EMS factories, consumer electronics, industrial control, and automotive electronics factories. Daily documents include BOMs and coordinate files, changeover sheets, stencil and reflow oven temperature records, first article inspections, SPI/AOI reports, maintenance records, traceability labels, and more. Data sources include customer BOMs, Gerber files, coordinate data, MES systems, solder paste and component batch records, placement machines, SPI/AOI equipment, and reflow oven temperature data. Update frequency is per work order, each changeover, and real-time updates. Documents contain structured bill of materials entries and unstructured detection report paragraphs. Fields include part numbers, reference designators, alternative parts, reflow oven temperature parameters, and other dedicated information.

## What constraints do these characteristics impose on the document parsing and chunking process
The mixed multi-format documents, high-frequency update characteristics, and dedicated field requirements of this category create multiple constraints for the document parsing and chunking process. Structured BOM files and long PDF detection reports exist side by side. This requires the parsing engine to support both structured data extraction and long text processing. Real-time updated work order documents require batch parallel processing capabilities. This avoids excessive single-file processing delays that impact audit efficiency. Intranet-deployed Confluence pages are a common source of internal audit documents. This requires the parsing service to adapt to intranet access environments. The association relationships of dedicated fields such as part numbers and reference designators require retaining contextual semantics during chunking. This avoids losing material association information after splitting.

## How to Configure Settings
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the information density of BOM entries and AOI report paragraphs in SMT documents, avoiding single chunks containing excessive cross-work order data |
| `chunkSplitter` | Mixed paragraph + fixed length | Balances semantic integrity for structured documents such as BOMs and chunking efficiency for long PDFs such as 1000-page reflow oven temperature records |
| `customPdfParse` | Enabled | Preserves key metadata such as work order numbers and component batches from page headers and footers for long PDF documents, avoiding loss during parsing |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time required for 1000-page level PDF documents, avoiding timeout during long file processing |
| `UPLOAD_FILE_MAX_SIZE` | 2000 MB | Supports uploading multiple large-volume documents in a single batch, meeting file upload requirements for batch work order audits |
| `chunkSettingMode` | Manual configuration | Adjusts chunking parameters for different document types such as structured BOMs and unstructured AOI reports to adapt to mixed multi-format scenarios |

## Three Common Configuration Errors
- Phenomenon: Batch upload of PDF documents with more than 500 pages results in timeout failure for some parsing tasks. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted. The default timeout duration is insufficient for processing large, long documents.
- Phenomenon: Importing an intranet-deployed Confluence page results in no valid text content being extracted in the knowledge base. Cause: No parsing node for intranet access is configured. A publicly deployed parsing service cannot connect to intranet resources.
- Phenomenon: Enabling parent-child chunking results in lost association information between BOM entries and corresponding SPI reports. Cause: No association rules are set for dedicated SMT document fields such as part numbers and reference designators for parent-child chunking. The chunk matching logic fails as a result.

## How to Verify Proper Configuration
- Upload a 1000-page reflow oven temperature record PDF document. Review parsing task status to confirm no timeout errors occur.
- Import an intranet-deployed Confluence first article inspection document. Check the knowledge base to confirm extraction of key content such as part numbers and reference designators from the document.
- Upload a structured BOM document. Review chunking results to confirm each chunk contains only single or associated BOM entry information.
- Switch `chunkSettingMode` to manual configuration. Adjust the `chunkSize` parameter for different document types such as AOI reports and changeover sheets. Verify that chunk length adapts to document content density.

The values provided are common starting points and should be measured against appropriate samples.
