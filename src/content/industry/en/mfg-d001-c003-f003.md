# Supplier and Process Quality Audit for Dairy Processing: Multi-turn Dialogue and Prompting

## What Data for This Category Looks Like
This category covers the entire production process for liquid milk, yogurt, milk powder and dairy ingredients. Daily documents include raw milk acceptance records, standardized ingredient lists, pasteurization or UHT heat treatment records, CIP cleaning records, filling operation records, and retained sample and microbial test reports.
Data is sourced from milk source testing equipment, production MES systems, homogenization and heat treatment online sensors, real-time temperature and flow collection systems, CIP cleaning systems, and LIMS laboratory management platforms.
Updates sync in real time for each milk tank and production batch.
Fields include test values, operation parameters, timestamps, and batch numbers.
Units include professional measurement standards such as degrees Celsius, cubic meters per hour, total bacterial count CFU/mL, and others.

## Constraints for Multi-turn Dialogue and Prompting
The real-time, batch-based data characteristics of dairy processing require multi-turn dialogue to bind `chatId` and batch identifiers. This ensures context only associates with the current production tank or batch.
Frequently updated raw milk and heat treatment data limit the dialogue context window. This prevents response delays from loading redundant history.
Differences in fields across documents—such as raw milk antibiotic indicators and filling cleanliness parameters—require prompts to trigger by process classification. This avoids cross-document field confusion.
The timeliness of real-time data requires dialogue responses to match production rhythms. It cannot tolerate overly long model call cycles.
Historical data calls for retained sample microbial test reports need clear batch ranges. This prevents cross-batch data from interfering with audit results.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique identifier of the production batch | Ensure that dialogue context is only associated with raw milk, production and testing data for the current batch, avoiding interference from cross-batch data |
| `messages` | Retain the first 3 rounds of dialogue for the current batch + real-time detection snapshot | Balance context completeness and response speed, adapting to the real-time production rhythm of dairy processing |
| `variables` | Preset batch numbers and compliance indicator thresholds | Quickly call documents and verification standards for corresponding links, reducing repeated input |
| Maximum context length | 800–1200 characters | Adapt to the average data volume of documents for a single batch, avoiding delays caused by loading redundant content |
| Response timeout threshold | 600 seconds | Match the processing cycle of real-time production data, preventing interruption of the production process |
| Prompt triggering rules | Load documents classified by production link | Accurately match exclusive documents for different audit scenarios such as raw milk acceptance, heat treatment, and filling |

## Three Common Misconfigurations
- Phenomenon: The system prompts that the batch ID field is empty when calling the `variables` parameter. Cause: The association between `chatId` and the production batch is not bound, so the necessary batch identifier parameter is not included in the context.
- Phenomenon: Dialogue responses time out, returning status code 504. Cause: The set response timeout threshold is lower than the processing cycle for real-time data collection, and does not match the real-time production rhythm of dairy processing.
- Phenomenon: Historical dialogue records for the current application cannot be retrieved for audit tracing. Cause: Persistent storage for `chatId` is not correctly configured, so dialogue context cannot be retained across sessions.

## How to Verify Correct Configuration
- Enter raw milk acceptance record data for a specific batch, and confirm the dialogue only returns associated detection data for that batch with no cross-batch content.
- Trigger an audit request for the heat treatment link, and confirm the prompt automatically loads the corresponding pasteurization or UHT record documents.
- Simulate real-time data input, and check that the response time meets production rhythm requirements.
- Call the `variables` parameter, and confirm preset compliance indicator thresholds can be quickly retrieved.

The values provided are common starting points and should be measured against the reader's own samples.
