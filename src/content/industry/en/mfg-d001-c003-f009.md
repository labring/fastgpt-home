# Supplier and Process Quality Audit for Dairy Processing: Model Connection and Configuration

## What Data for This Category Looks Like
This category covers full-process production data for enterprises producing liquid milk, yogurt, milk powder, and dairy ingredients. Daily documents include raw milk acceptance records, standardized ingredient lists, pasteurization or UHT heat treatment records, CIP cleaning records, filling records, sample retention and microbial test reports. Data comes from milk source testing equipment, MES systems, homogenization and heat treatment equipment, online temperature and flow collection devices, CIP systems, and LIMS laboratory management systems. Data updates in real time for each milk tank and each batch. Each individual record includes process parameters, test indicators, and batch information for the corresponding production link.

## Constraints for Model Connection and Configuration
The real-time, batch-based data characteristics of this category require model connection configuration to support incremental index refresh. This avoids delays caused by full data synchronization. Multi-source heterogeneous data sources covering equipment, production systems, and laboratory records require configuration to support mixed access to structured process parameters and unstructured test reports. Each individual batch record includes clear process parameters and test indicators. This requires the model’s retrieval logic to match field-based judgment rules. Additionally, raw materials are perishable, and errors lead to serious consequences. The configured model response speed must match the verification window of the production link to avoid delays disrupting the process.

## How to Set Up Configurations
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Matches the total length of full-process documents for raw milk acceptance, heat treatment, and filling for a single batch, to avoid truncating key process parameters |
| `maxTokens` | `4000 token` | Limits the length of single-round generated output, adapts to the concise judgment needs of production verification, and avoids timeout from overly long responses |
| `quoteMaxToken` | `3000 token` | Defines the total token limit for recalled documents, ensuring only test and process records related to the current batch are returned |
| Workflow/API tool selection | `auto` | Allows the model to independently choose whether to call the retrieval tool, adapting to mixed query scenarios for structured parameters and unstructured reports |
| `temperature` | `0.1–0.3` | Reduces generation randomness, ensuring consistent results for raw milk antibiotic judgment and heat treatment compliance verification |
| `AIPROXY_API_ENDPOINT` | Specify a dedicated endpoint based on the deployment region | Adapts to domestic access requirements, reducing cross-region network delay impacts on real-time verification |

## Three Common Configuration Mistakes
- Symptom: Continuous connection errors occur when accessing a third-party aggregated embedding service. Cause: A dedicated index model access endpoint is not configured separately. Using the global aggregated interface leads to permission or routing conflicts.
- Symptom: A request error is returned when uploading a raw milk acceptance PDF report with multi-page tables. The marker service calls normally. Cause: The structured table parsing configuration for dairy documents is not adapted, leading to abnormal data format after parsing.
- Symptom: Error log fragments containing abnormal IDs and node IDs are returned during chat verification. Cause: The `maxContext` configuration value exceeds the token limit of the deployment environment, leading to context processing failure.

## How to Confirm Proper Configuration
- Run a retrieval test for single-batch raw milk data, and verify that recalled results only include acceptance, process, and test records for the current batch.
- Initiate a simulated query for raw milk antibiotic judgment, and verify that the judgment logic of the generated result matches the test indicators in the documents.
- Check deployment logs to confirm that the request delay of the model access endpoint meets the real-time verification window requirements of the production link.
- Test the multi-format document upload process, and confirm that no fields are missing from the parsed results of raw milk acceptance records and CIP cleaning records.

The values provided are common starting points and should be assessed against samples relevant to the specific use case.
