# Supplier and Process Quality Audit for Warehousing, Lot Tracking, and In-Plant Logistics: Multi-Turn Dialogue and Prompt Engineering

## What Data Looks Like for This Category
This category covers material management for raw material warehouses, line-side warehouses, finished product warehouses, and material control departments. Daily documents include receiving slips, putaway slips, material picking and return slips, inventory transfer slips, inventory checklists, lot ledgers, and expiration date records. Data sources include ERP/WMS systems, barcode or RFID equipment, purchase work orders, storage location information, AGV transport systems, and weighing data. Update frequencies include real-time synchronization, daily summaries, and monthly inventory counts. Document fields typically include material codes, lot numbers, storage location numbers, inspection statuses, and expiration dates.

## Constraints on Multi-Turn Dialogue and Prompt Engineering
Differences in fields across heterogeneous data sources require prompts to clearly define query scopes, preventing cross-system field confusion. Multiple update frequencies require dialogues to separate real-time storage location data from historical inventory records, avoiding use of expired information during audits. Multiple document types and fields require multi-turn dialogues to guide users to supplement key parameters such as lot numbers and storage locations step-by-step, preventing invalid verification logic from being generated. Strict verification requirements for lots and expiration dates require prompts to include fixed verification rules, ensuring audit results align with business requirements.

## Configuration Settings
Under FastGPT v4.17.0, adjust settings using the following reference configurations:

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Bind material codes, lot numbers, and expiration thresholds | Quickly call real-time material data from WMS/ERP to adapt to lot audit scenarios |
| `messages` | Split structure by system prompts, business rules, and user questions | Clearly distinguish audit standards and specific verification requests, reducing the probability of context confusion |
| Maximum context window | First 10 turns of dialogue or 8000 characters | Warehousing documents have many fields, requiring retention of key audit context such as lots and storage locations |
| Historical session binding | Associate dialogue context via `chatId` | Support cross-turn tracing of lot ledgers and historical verification records |
| Number of returned entries per query | Top 3 matching documents | Reduce redundant information interference, focusing on the material lot for the current audit |

## Three Common Misconfiguration Issues
- Phenomenon: Deleting the login-free dialogue link simultaneously clears background operation logs. Cause: No independent log storage rules are configured, binding dialogue context and operation logs.
- Phenomenon: Workflows cannot load global variables saved in historical sessions in new dialogues. Cause: Variables for historical lot ledgers or storage location information are not bound via the `variables` parameter.
- Phenomenon: Calling the MySQL database tool returns a 400 status code with no response body. Cause: The prompt does not clearly specify the query field scope, leading to SQL statements with invalid fields or syntax errors.

## How to Verify Successful Configuration
- Initiate a test dialogue that includes specified material codes and lot numbers, confirming returned results contain verification information for the corresponding documents.
- Trigger a dialogue deletion operation, checking whether background logs retain dialogue records to validate log persistence configuration.
- Start the associated workflow, confirming new dialogues can load global variables for lot ledgers saved in historical sessions.
- Call the MySQL tool to execute material queries, confirming returned results match preset field and filtering rules.
