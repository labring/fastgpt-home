# Supplier and Process Quality Audit for Warehousing, Lot Tracking and In-Plant Logistics: Tool Calling and Plugins

## What the Data for This Category Looks Like
Daily documents for this category include receiving slips, putaway slips, material picking and return slips, inventory transfer slips, inventory count sheets, lot ledgers, first-in first-out (FIFO) and expiration date records. Core fields cover material code, lot number, storage location number, expiration date, inspection status, and quantity unit. Data sources include ERP/WMS systems, barcode or RFID devices, procurement and work orders, storage location information, AGV or conveyor systems, and weighing data. Update frequencies are divided into three categories: real-time, daily, and monthly inventory counts.

## What Constraints Do These Characteristics Impose on the "Tool Calling and Plugins" Link
Heterogeneous data from multiple sources requires tool calling to support integration with systems using different protocols. Document structures with multiple fields such as lot numbers and expiration dates require plugins to accurately extract specified fields. Mixed update rhythms of real-time and periodic updates require calling strategies to distinguish between real-time data and static data. Business goals of inventory-actual consistency and lot traceability require tool calling to strictly verify field completeness, to avoid risks such as incorrect material allocation or production line downtime caused by missing data.

## How to Set Up Configurations
This configuration guide applies to FastGPT v4.17.0:

| Configuration Item | Suggested Value | Rationale for This Value |
| ---- | ---- | ---- |
| Workflow/API tool selection | auto | Allows the model to autonomously match tool types related to warehousing and lot tracking |
| Tool call timeout | 600–1200 seconds | Adapts to bulk data pull delays from ERP/WMS systems |
| Plugin request retry count | 2–3 times | Addresses temporary connection fluctuations from barcode and RFID devices |
| Workflow/API function-call configuration | Specify by document type | Calls dedicated tools for fixed-format documents such as receiving slips and inventory count sheets |
| Number of data items returned per request | First 10 items | Matches the single query data volume of lot ledgers |
| Parameter validation switch | Enabled | Validates required fields such as material code and lot number |

## Three Common Misconfigurations
- Tool calls return the `400 InternalError.Algo.InvalidParameter` error. The cause is failure to validate required fields such as lot numbers and expiration dates, resulting in parameter formats that do not meet system requirements.
- Initial tool call has high latency, while subsequent requests return to normal. The cause is failure to pre-warm connections to internal network ERP/WMS systems. The initial request requires establishing a network channel or pulling full basic configuration data.
- HTTP plugin calls to internal network systems fail. The cause is failure to configure a proxy to adapt to internal network access restrictions, making it impossible to bypass external network isolation.

## How to Confirm Configuration Is Complete
- Submit a test document containing material code and lot number, check whether the tool can correctly pull associated data from the corresponding ERP/WMS system.
- Simulate initial call and consecutive calls, verify whether initial latency and subsequent latency meet business expectations.
- Create a test case missing the lot number, confirm whether the parameter validation error prompt is triggered.
- After configuring the proxy, test whether plugin calls to the internal network WMS system can be completed normally.
