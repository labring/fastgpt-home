# Supplier and Process Quality Audit for Photovoltaic Wafer Manufacturing: Vector Models and Indexes

This configuration applies to FastGPT v4.17.0.

## What data looks like for this category
Photovoltaic wafer manufacturing enterprises’ process, equipment, quality control, and production teams generate multiple types of business data. Data sources include silicon wafer incoming material records, MES production management systems, operating parameters of diffusion furnaces, coating equipment, and printing presses, EL defect detection images, IV electrical performance test data, and laboratory yield reports.

Data updates occur per incoming batch, per product inspection, and daily summary statistics. Daily documents include fixed-format process cards, segmented diffusion and coating parameter tables, real-time printed sintering records, EL detection images with pixel annotations, IV data sorted by electrical performance, and periodic yield statistical reports.

## What constraints these characteristics impose on vector models and indexes
The data includes structured parameter tables, numerical test data, and unstructured image documents. Vector models must support embedding of multimodal data and association with structured metadata.

High-frequency batch-by-batch and piece-by-piece update requirements mean indexes must support incremental updates, avoiding performance loss from full reconstruction. Piece-level and batch-level traceability needs require retrieval results to bind corresponding equipment IDs, production batches, and incoming batch information, preventing invalid cross-batch data from being recalled.

Associated analysis of process parameters and defect detection requires vector index dimensions and fields to match the granularity of business data, ensuring retrieval accuracy.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum chunk length | 800–1200 characters | Matches the typical paragraph length of single documents such as photovoltaic wafer manufacturing process cards and sintering records |
| Maximum paragraph depth | 3 | Adapts to the document structure of layered annotations for EL detection images and graded IV data |
| `maxToken` | 1024 token | Matches the input length limit of multimodal embedding models and adapts to the embedding requirements of EL detection images |
| Index dimension | 128 | Balances vector retrieval accuracy and storage costs for the business scenario |
| `defaultToken` | 512 token | Sets the default token quota for chunks, adapting to the typical length of structured parameter tables |
| Incremental update trigger rule | Triggered by production batch | Adapts to the update rhythm of photovoltaic wafer manufacturing per incoming batch and per production batch |

## Three common configuration errors
- Invalid format errors when accessing multimodal embedding models: No adaptation rules for multimodal embedding are configured for EL detection images and IV graded data, or unstructured input data fails format validation.
- Failure to retrieve old vector database data after upgrading to a new version: Chunk parameters and index dimension configurations are not updated synchronously, leading to inconsistent spatial mapping between old and new vectors, causing retrieval matching to fail.
- Full index reconstruction task execution failure or timeout: Expired production batch data is not cleaned in advance, causing index storage to exceed quota, or chunk parameter settings exceed system limits.

## How to confirm the configuration is correct
- In FastGPT v4.17.0, upload a single process card and EL detection image, check if the chunk results match the preset maximum paragraph depth and chunk length.
- Call the API to initiate a retrieval for a specific batch of production data, verify that the returned results are associated with the correct production batch and equipment metadata.
- Perform a vector database migration operation, check if the migrated index can normally recall relevant data from historical production batches.
- Trigger a full index reconstruction task, confirm that the task completes normally with no error prompts.

The values provided are common starting points and should be measured against the reader's own samples.
