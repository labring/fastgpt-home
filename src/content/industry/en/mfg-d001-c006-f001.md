# Supplier and In-Process Quality Audit for Photovoltaic Module Encapsulation: HTTP Interfaces and External Systems

This page is compatible with FastGPT v4.17.0.

## What data for this category includes
Data for this category comes from battery cell grading records, glass adhesive film backplane batch ledgers, factory MES systems, string welding and lamination production equipment, EL defect detectors, and IV power testers. Daily documentation includes module layout diagrams, material batch records, lamination process parameter records, EL defect images, IV test reports, insulation withstand voltage test records, and finished product packing lists.

Data is updated per individual module and per material batch. Fields include battery cell current gear values, lamination temperature and duration, EL crack coordinates, IV test power values, and more. Units include watts, degrees Celsius, seconds, and others.

## Constraints imposed by these characteristics on HTTP interfaces and external systems
The high-frequency, small-batch update rhythm requires interfaces to support low-latency requests to avoid production wait timeouts.
Multiple heterogeneous data sources (equipment, MES, ledgers) require interfaces to support varying field names and formats, with pre-configured mapping required.
Transmission of unstructured data including EL images and IV test reports requires interfaces to set sufficient request body size limits and timeout thresholds.
The strong association between modules and material batches requires interfaces to carry unique identifier fields to ensure accurate data matching.

## Configuration guidelines
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Carry a Bearer token with a validity period of 7200 seconds | Adapts to internal factory system identity verification rules to prevent unauthorized requests from being blocked |
| `variables` | Bind three types of variables: component ID, batch number, and test time | Matches exclusive data for each module to ensure the interface pulls material and test records for the corresponding batch |
| `responseData` | Filter out current gear, lamination parameters, and EL defect fields | Only return core data required for audits to reduce transmission load |
| Request timeout duration | 300–600 seconds | Adapts to large file transmission durations for EL images and IV reports to avoid request failures due to transmission timeouts |
| Retry mechanism | Retry 2 times after failure, with a 60-second interval | Addresses scenarios such as temporary production equipment disconnection or network fluctuations to ensure successful data pull rates |

## Three common misconfigurations
- The interface returns `500 do request failed: Post "https://xxx tls: failed to verify certificate"`. No trusted certificate verification rules are configured, or self-signed certificates are not imported into the system trust list, causing HTTPS connection establishment to fail.
- The interface is called at high frequency during non-working hours, leading to unexpected resource consumption. No request frequency limit rules are configured, or scheduled tasks do not correctly set call time windows, causing invalid requests to occupy quota.
- Pulled EL defect images cannot be parsed normally. The receiving format for binary data is not specified in the interface configuration, causing unstructured EL images to be truncated or damaged after transmission.

## How to confirm proper configuration
- Initiate a test request for a single module, and verify whether the returned `responseData` includes preset core business fields.
- View interface call logs to confirm that request trigger times match production operation times, with no call records from abnormal time periods.
- After importing trusted certificates from the corresponding system, initiate an HTTPS request to confirm there are no certificate verification-related errors.
- Bind test component ID and batch number variables, initiate a request, and verify that the pulled data matches locally stored ledger records.

The values provided are common starting points and should be measured against the reader's own samples.
