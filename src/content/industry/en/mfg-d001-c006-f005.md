# Supplier and Process Quality Audit for Photovoltaic Module Encapsulation: Tool Calling and Plugins

## What the Data for This Category Looks Like
Photovoltaic module encapsulation business data comes from cell grading records, adhesive film and backsheet batch ledgers, production MES systems, string welding and lamination equipment logs, EL defect detectors, and IV power testers. Data update frequency follows that each module generates a dedicated test record, and raw material batches are synchronized with batch ledgers. Daily produced documents include layout drawings, material batch records, lamination process parameter sheets, EL defect images, IV power test reports, insulation voltage withstand records, and packing lists. Core fields include cell current grade, lamination temperature, pressure, and duration, EL crack location coordinates, and IV power value, with units including degrees Celsius, pascals, watts, millimeters, and others.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins
Multi-source heterogeneous real-time data requires tool calling to support integration with different types of device interfaces and system APIs, to avoid relying solely on offline knowledge bases. High-frequency updated per-module data requires that the context for tool calling be limited to the current batch and single module, to avoid interference from redundant data. Structured professional fields require that input and output for tool calling use JSON format, to ensure accuracy of parameter matching. Additionally, business errors directly lead to customer claims, so tool calling must be configured with failure retry and exception alert mechanisms to ensure stability of data queries.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `functionCall` | Enabled forcibly | Dedicated interfaces of EL testers and IV power meters must be called to obtain real-time test data. Structured business data cannot be obtained in non-tool calling modes |
| Maximum number of tool calls per single run | First 3 entries | Test data volume for a single batch of modules is limited. Excessive returned content will exceed the context capacity and affect response accuracy |
| Tool call timeout period | 120 seconds | Device communication and data parsing are required to pull EL and IV test data. 120 seconds covers response durations of most conventional devices |
| `toolChoice` | auto | Can automatically select between calling tools or generating responses directly based on user queries, balancing business query efficiency and general question answering capabilities |
| JSON input variable binding | Enabled | Business variables such as component ID and material batch number must be bound to ensure accurate matching of production data for the corresponding batch during tool calling |

## Three Common Misconfigurations
- The symptom is that preset business variables cannot be selected in the JSON input box. The cause is that variable binding configuration for the plugin was not enabled, and fields such as component ID and batch number were not mapped as callable variables.
- The symptom is that web search node content is not referenced in non-tool calling mode. The cause is that tool calling permissions were not enabled in system configuration, so the large model cannot trigger external interface calls.
- The symptom is that the plugin cannot be found in the community after publication. The cause is that correct plugin classification tags were not filled in, and the community indexing mechanism was not synchronized.

## How to Confirm the Configuration Is Complete
- Initiate a test query including "query the EL crack situation of a specified component" to verify that the tool call successfully returns structured defect data.
- In the plugin configuration interface, check whether the JSON input box can bind preset variables such as component ID and material batch number.
- Go to the FastGPT v4.17.0 system configuration page to confirm that the `functionCall` and `toolChoice` parameters have been configured according to the preset values.
- Submit the plugin publication application, wait for indexing synchronization to complete, and confirm that the corresponding entry can be found in the community plugin library.

The values provided here are common starting points and should be measured against the reader's own samples.
