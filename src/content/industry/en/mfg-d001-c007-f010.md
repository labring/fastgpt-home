# Supplier and Process Quality Audit for Stamping and Sheet Forming: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Data for this category originates from stamping workshops at automotive panel, household appliance sheet metal, and hardware component enterprises. It includes documents such as stamping operation instructions, material utilization rate tables, mold inspection checklists, first and last piece records, dimensional inspection reports, and mold change records.
Data sources include steel coil labels and quality certificates, stamping press and feeder operation data, mold management systems, MES systems, and coordinate measuring machine or fixture inspection data.
Data updates trigger with each steel coil batch, each production task, and each mold change operation. Documents include fields like material number, mold number, inspection dimensions, and mold change time. Some fields use standardized units; for example, mold clearance is measured in millimeters.

## Constraints on Knowledge Base Retrieval and Recall
Data updates for this category occur with each steel coil batch, each production task, and each mold change, at a high frequency. This requires the knowledge base retrieval system to support incremental recall and rapid updates, avoiding excessive computing resource consumption from full index rebuilding.
Data sources cover equipment operation data, system management data, and paper inspection records, with significant format differences. This requires the retrieval module to support unified parsing and matching across multi-source data.
Documents focus primarily on mold parameters, material utilization rates, and quality inspection results. Retrieval must accurately match the process parameters and quality indicators of the current production batch, avoiding recall of irrelevant historical batch data. This ensures the timeliness and accuracy of supplier and process quality audits.

## Configuration Recommendations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the precision requirements for stamping process parameters and quality indicators, filters low-relevance historical data |
| `limit` | Top 6 entries | Covers multiple types of data (mold, material, inspection, etc.) required for a single audit, avoids excessive results that interfere with judgment |
| `usingReRank` | Enabled | Stamping scenarios have tightly linked parameters; re-ranking filters surface-similar but process-mismatched recall results |
| `datasetSearchUsingExtensionQuery` | Enabled | Supplements extended process-related query phrasing, adapts to auditors' precise spoken questions |
| `collectionIds` | Bound to the exclusive knowledge base collection for the current stamping workshop | Isolates production data across different workshops, avoids recalling irrelevant documents from other production lines |

## Three Common Configuration Mistakes
- Issue: After importing mold inspection checklists and dimensional inspection reports from a stamping workshop, the data status remains displayed as "Indexing in progress" for more than 4 hours. Cause: No incremental index update strategy is configured. Full index rebuilding processes multiple batches of mold change and inspection data, consuming substantial computing resources.
- Issue: Retrieval results only return stamping operation instructions, and do not match material utilization rate data for the current batch. Cause: `datasetSearchUsingExtensionQuery` is not enabled. No extended query terms related to material utilization rates are added, so the system cannot adapt to auditors' precise questions about the current batch.
- Issue: Retrieval results include mold change records from other workshops. Cause: `collectionIds` is not configured correctly. Cross-workshop knowledge base collections are bound, leading to recall of irrelevant production data.

## How to Verify Successful Configuration
- Upload a single mold inspection checklist. After indexing completes, check whether the data status displays as "Ready".
- Input the query "Current batch material utilization rate parameters", and verify that retrieval results include the material utilization rate table data for the current workshop.
- Access the retrieval configuration panel in FastGPT v4.17.0, and confirm that both `usingReRank` and `datasetSearchUsingExtensionQuery` are enabled.
- Validate the return count for the `limit` parameter, confirming that the number of results per retrieval matches the preset value.

The values given are common starting points and should be measured against the reader's own samples.
