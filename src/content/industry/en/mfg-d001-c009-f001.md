# Supplier and Process Quality Audit for Pharmaceutical Dosage Form Manufacturing: HTTP Interfaces and External Systems

## What this category's data looks like
Data for this category comes from approved formulation processes, material batches, MES/electronic batch records, equipment and environmental monitoring systems, LIMS, and quality management systems. Daily documents include master production documents, batch production/packaging/cleaning records, inspection records, deviation/CAPA/change documents, and batch release audit forms. Fields cover material batch numbers, process parameters, test results, deviation details, and more. Update frequency follows per production batch, each key process step, and fixed monitoring plans. Data must be stored synchronously with production operations.

## What constraints these characteristics impose on HTTP interfaces and external systems
Data in this category is linked to multiple systems and bound to production batches. HTTP interfaces must support pulling corresponding data by production batch to avoid cross-batch data confusion. Data must be synchronized with production operations, so interfaces must support request idempotency to prevent data inconsistency caused by repeated submissions. Fields cover compliance items such as material batch numbers, process parameters, and test results. Interfaces must strictly match field formats and must not omit key information. In scenarios with multiple data source connections, unified data verification logic is required to ensure incoming data meets GMP-related document requirements. Additionally, since error consequences are severe, interfaces must be configured with complete exception capture and reporting mechanisms to ensure reliable data synchronization.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer ${predefined_qms_token}` | Follow industry-standard authentication formats when connecting to quality management systems, ensure interface access security, and adapt to the authentication configuration logic of FastGPT v4.17.0 |
| `variables` | `{"target_batch": "${current_batch}"}` | Dynamically pass the current production batch parameter to accurately pull inspection and deviation data for the corresponding batch, matching the batch-based update data characteristics of this category |
| `responseData` | Only return batch_no, test_result, deviation_desc fields | Reduce invalid data transmission, and comply with streamlined data storage requirements under GMP |
| Request timeout | 30–60 seconds | Pulling data for this category involves interactions with multiple systems, so sufficient time must be reserved for data verification and transmission to avoid interrupting batch data synchronization due to timeout |
| Retry strategy | Up to 2 times, 10-second interval | Address temporary network fluctuations while avoiding GMP compliance risks caused by repeated submissions |
| Field mapping rules | Align with batch production record fields | Ensure interface return data fully matches internal document fields, meeting data integrity requirements |

## Three common mistakes
- An interface call returns a 401 Unauthorized error. Checking the request header reveals an extra automatically added Bearer prefix. The cause is failing to disable the system's default automatic Bearer addition function, resulting in an authentication format that does not meet external system requirements.
- Interface return data includes cross-batch inspection records, making accurate matching of the current audit batch impossible. The cause is not configuring dynamic parameter binding, with each call retrieving fixed-range data without filtering by production batch.
- Interface return fields include redundant information not required for audits, leading to deviations in alignment with internal documents. The cause is not enabling the response data filtering configuration, directly returning full data from the external system, which does not meet the precise data requirements of GMP audits.

## How to confirm the configuration is complete
- Manually trigger an interface call, view the returned response data, and confirm only preset audit-required fields are included.
- Pass simulated production batch parameters, check whether the interface only returns relevant data for the corresponding batch, with no cross-batch data mixed in.
- Simulate a scenario where the authentication token is incorrect, confirm the interface returns a clear unauthorized prompt without other abnormal error messages.
- Configure exception capture rules, disconnect the simulated network, and check whether the preset retry and reporting mechanism is triggered to ensure data synchronization is not interrupted.
