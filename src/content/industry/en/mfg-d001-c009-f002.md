# Supplier and Process Quality Audit for Pharmaceutical Dosage Form Manufacturing: Vector Models and Indexes

## What Data Looks Like for This Category
Relevant entities for pharmaceutical dosage form manufacturing include production, quality assurance, quality control, and warehouse departments. Daily documents include master production files, batch production records, batch packaging records, cleaning records, test records, deviation/CAPA/change documents, and batch release review forms. Data sources include approved formulation processes, material batch information, MES/electronic batch records, equipment and environmental monitoring data, LIMS systems, and quality management systems. Data update frequency follows each production batch, each key process step, and as implemented per established monitoring plans.

## Constraints for Vector Models and Indexing
Documents and data for this category must comply with regulatory requirements and are tightly bound to production workflows. Vector models and indexing must therefore support mixed input from multiple structured and semi-structured data sources. Document volume per batch varies based on process complexity, so incremental index updates must be supported to avoid reprocessing full historical datasets. Additionally, audit-related documents such as deviations and CAPAs require precise matching, which sets clear requirements for vector recall accuracy. Data traceability links must also be retained to meet audit needs.

## Configuration Settings
This page is written for FastGPT v4.17.0. The following is the vector model and indexing configuration plan for this scenario:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Matches the length of single-process descriptions in batch production records, avoids splitting that disrupts process logic and material association information |
| `maxToken` | 4096 token | Adapts to the total text volume of a single batch’s batch record, ensures complete embedding within the input range of the selected embedding model |
| Overlap Length | 50–100 characters | Retains process transition content between adjacent chunks, prevents audit logic from breaking due to split key steps |
| Similarity Threshold | Calibrated via actual testing | Adjusted based on deviation matching accuracy required by compliance regulations, ensures recall results align with audit judgment standards |
| Single Search Limit | Top 10 results | Covers historical records, material data, and deviation reports related to the same batch, meets information requirements for audit scenarios |
| `defaultToken` | Set from representative sample documents | `defaultToken` is the default token count for direct text chunking; tune it on representative source documents. See the [v4.17.2 model-field reference](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx). It is not a vector dimension, embedding-model input cap, or retrieval/LLM context. |

## Three Common Misconfigurations
- Index creation fails, with a database connection timeout logged. Cause: Docker mount volumes and port mapping for the PostgreSQL database were not configured correctly, preventing the FastGPT container from accessing the host’s PostgreSQL instance.
- Embedding model invocation fails with an error indicating no available channels. Cause: The embedding model was not configured separately, and the default OneAPI channel was used without adding available nodes for the corresponding model.
- A 503 status code appears after startup, indicating no available models in the group. Cause: The API key and invocation address for the embedding model were not set correctly, causing the model channel to fail to activate normally.

## How to Confirm Configurations Are Valid
For FastGPT v4.17.0, use the following actionable steps to verify configuration effectiveness:
- Upload a typical batch production record, check whether the chunked text retains complete process steps and material batch information.
- Initiate a supplier quality audit query, verify whether the number of returned vector search results matches the configured single search limit.
- Check system logs to confirm that token consumption during embedding model invocation does not exceed the `maxToken` setting.
- Verify that vector data for the uploaded document is generated in the PostgreSQL database’s index table.

The values provided are common starting points and should be measured against the reader's own samples.
