# Supplier and Process Quality Audit for Pharmaceutical Dosage Form Manufacturing: Tool Calling and Plugins

## What the data for this category looks like
Data for pharmaceutical dosage form manufacturing originates from approved formulation processes, material batches, MES/electronic batch records, equipment and environmental monitoring systems, LIMS, and quality management systems. Daily documents include master production files, batch production records, batch packaging records, cleaning validation records, inspection records, deviation/CAPA/change documents, and batch release review forms. Data updates occur per production batch, each critical process step, and as per established monitoring plans. Data fields include material batch numbers, process parameters, test results, deviation details, environmental monitoring values, etc., and must strictly comply with required formats and completeness for regulatory compliance.

## What constraints these characteristics impose on the tool calling and plugins workflow
This category has scattered data sources that require strict compliance. Tool calling workflows must connect to multiple internal systems, and ensure each tool’s access permissions meet compliant data access requirements. Data updates happen frequently and tie to production batches, so tool calling must accurately match production nodes and batches to avoid pulling expired or irrelevant data. Daily document structures have fixed, strict field requirements, so tool return results must directly map to corresponding document fields without arbitrary format adjustments. The most time-consuming review and summary step relies on multi-source data integration, so tool calling must automatically pull data across systems to reduce manual operation time and error risks.

## How to set up the configuration
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `toolChoice` | Specify three types of tools: supplier qualification review, batch record query, and deviation summary | Matches the core business scenarios of pharmaceutical dosage form manufacturing audits, reduces unnecessary tool calls |
| `functionCall` | Force tool call triggering | Ensures audit processes rely on real system data, meeting compliance requirements for data integrity |
| Tool call timeout setting | 120 seconds | Average time to pull data from LIMS and MES across systems is 60-100 seconds, with reasonable buffer reserved |
| HTTP toolset configuration | Configure Oracle database connection parameters | Adapts to mainstream storage systems for enterprise material batch data, enabling direct data pulling |
| Number of tool result returns | Top 8 entries | Core data items required for single-batch review typically do not exceed 8, avoiding information overload |
| Batch data sync trigger | Triggered upon completion of each production batch | Matches data update frequency, ensuring audits use the latest batch production and test data |

## Three common configuration mistakes
- Phenomenon: After manually triggering tool calls, irrelevant data not included in the audit scope is returned, and the interface shows that an unauthorized tool was called. Cause: The `toolChoice` parameter was not used to specify a tool set suitable for the business scenario, and non-compliant tools were mistakenly included in the call range.
- Phenomenon: A 504 timeout error is returned when configuring the HTTP toolset to connect to an Oracle database. Cause: Correct database port, enterprise internal network access whitelist, or timeout threshold was not configured, and the actual time required for cross-system data pulling was not accommodated.
- Phenomenon: After the tool call node finishes executing, the interface returns empty reply content with no tool return data. Cause: The `functionCall` forced mode was not enabled, the large language model did not trigger tool calls and directly generated empty content, or the correct mapping relationship between tool results and review fields was not configured.

## How to confirm the configuration is complete
- Manually trigger the preset three types of tool calls, check that the returned data comes from the specified MES, LIMS, or Oracle systems, and includes core audit fields such as batch production records and deviation details.
- Simulate a completed production batch scenario, verify that the tool automatically pulls data for the corresponding batch according to the configured trigger conditions, with no additional irrelevant tool calls.
- View the tool call logs, confirm that the timeout setting meets business time requirements, and there are no frequent timeout errors.
- Check the configuration of the `functionCall` parameter, ensure that tool call results are correctly mapped to the corresponding fields of the batch release review form, with no missing fields or format errors.

The values provided are common starting points and should be evaluated against the samples relevant to the actual deployment.
