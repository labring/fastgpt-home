# Supplier and Process Quality Audit for Finished Chemical Pharmaceutical Manufacturing: Citation Sourcing and Traceability

## What this category of data looks like
This category of data is generated by production, quality assurance, quality control, and warehousing departments of finished pharmaceutical manufacturers. Daily documents include master production files, batch production/packaging/cleaning records, test records, deviation/CAPA/change documents, and batch release review forms. Data sources include approved formulation processes, material batches, MES electronic batch records, equipment and environmental monitoring data, LIMS, and quality management systems. Updates are triggered per production batch, with key process steps executed in line with monitoring plans. Core fields include material batch numbers, process parameter values, test results, and deviation numbers. Corresponding units include ℃, hours, batch codes, and similar units.

## What constraints these characteristics impose on citation sourcing and traceability
Each batch’s associated documents and data have strict batch-specific correlation. They must be accurately linked to the corresponding batch’s materials, processes, and test records to avoid cross-batch confusion. Data is archived independently per batch and updated frequently. During traceability, the context range must be strictly limited to the target batch’s dataset to prevent irrelevant data from being included. Per GMP compliance requirements, all citations must correspond to approved original documents. Traceability results must be matched to specific document entries and data nodes; vague associations are not sufficient. Data from multiple systems must be uniformly aligned with batch identifiers to avoid traceability failures caused by data inconsistencies.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the total character count of core documents for a single batch, avoiding exceeding the system context limit |
| `responseData` | Return only data associated with the target batch | Restricts retrieval scope to the production batch being audited, preventing irrelevant cross-batch information from being retrieved |
| `detail` | Full fields and source path | Outputs specific entries of original documents and data storage locations, complying with GMP traceability compliance requirements |
| Single search limit | Top 6 retrieved results | Covers the main associated data within a single batch, avoiding redundant information interfering with audit judgments |
| Maximum context | 4000–6000 characters | Adapts to the total length of a single batch’s batch record, ensuring all associated data can be fully loaded |

These configurations are adapted for FastGPT v4.17.0.

## Three common configuration errors
- Issue: Traceability results include documents not from the current batch, or batch identifier fields are empty or do not match. Cause: The retrieval scope for `responseData` is not limited to the target production batch, leading to cross-batch data being retrieved.
- Issue: Chinese queries cannot be linked to English original test records in the knowledge base. Cause: Association matching rules for multilingual documents are not configured, and only data sources matching the query language are retrieved.
- Issue: Context timeout errors occur during the audit process. Cause: `quoteMaxToken` or maximum context parameters are not set appropriately, causing the total volume of loaded documents to exceed the system’s capacity limit.

## How to verify correct configuration
- Import the complete batch record and associated data for a single batch, submit a targeted audit query, and check that returned results only include document entries for that batch.
- Test the association effect between Chinese queries and English original test records, confirming that corresponding English data sources can be correctly matched.
- Review system logs to confirm that no context overflow or timeout errors occur during retrieval, and that all configuration parameter values fall within their specified ranges.
- Check that traceability results include storage paths and field details for original documents, verifying that the `detail` parameter configuration is active.

The values provided here are common starting points and should be evaluated against the reader’s own samples.
