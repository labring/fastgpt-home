# Supplier and Process Quality Audit for Pharmaceutical Dosage Form Manufacturing: Deployment and Upgrade

## What the Data for This Category Looks Like
Relevant data for pharmaceutical dosage form manufacturing is generated by production, quality assurance, quality control, and warehouse departments. Daily documents include master production files, batch production records, batch packaging records, cleaning records, inspection records, deviation/CAPA/change documents, and batch release review forms. Data sources include approved formulation processes, material batch information, MES/electronic batch record systems, equipment and environmental monitoring data, LIMS laboratory information management systems, and quality management systems. Data updates occur per production batch, each critical process step, and per fixed monitoring plans. It includes clear fields such as material batch numbers, process parameter values, deviation types, and inspection results.

## Constraints Imposed on Deployment and Upgrade
Since data sources cover multiple internal systems, the deployment phase requires configuring multi-data source connection adapters to ensure uniform formatting across different systems. High-frequency bulk data updates require setting a sufficient database connection pool during deployment to avoid concurrent query blocking. Storage of compliance documents must meet internal enterprise security requirements, and a specified internal storage service must be used. Frequent associated queries for batch records, deviations, and inspection data require configuring a reasonable indexing strategy in advance to ensure retrieval efficiency. System upgrades must also ensure data integrity to avoid impacting ongoing batch review processes.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `MONGODB_URI` | `mongodb://qa_user:pass123@internal-mongo:27017/pharma_qms?authSource=admin` | Connects to the enterprise internal quality management database to store core business information such as batch records and deviation data. Requires specifying the business database and authentication source |
| `DB_MAX_LINK` | `200–300 connections` | Each production batch generates a large amount of associated data. High-concurrency query scenarios require sufficient database connection pool support |
| `REDIS_URL` | `redis://redis_pass@internal-redis:6379/0` | Caches frequently accessed business data such as material batches and process parameters to reduce query pressure on the backend database |
| `STORAGE_S3_ENDPOINT` | `http://internal-s3-endpoint:9000` | Stores compliance documents such as batch production records and inspection reports. Uses enterprise internal object storage to ensure data security |
| `FILE_TOKEN_KEY` | `32-character random secure string` | Generates secure tokens for access to compliance documents to prevent unauthorized access to sensitive business files |
| `ROOT_KEY` | `Custom strong password string` | Configures the initial authentication key for system administrators to secure background management permissions |

## Three Common Configuration Errors
- After starting the Docker container, MongoDB connection fails, and the login interface cannot be accessed. The cause is that the authentication information in `MONGODB_URI` is not configured correctly, or the corresponding port of the database instance is not open, preventing FastGPT from establishing a data connection.
- After configuring the model, clicking test prompts an error, but the reference runs normally after forcibly ignoring it. The cause is that the timeout threshold of the test interface is set too short, while the actual call has a longer context length, triggering the timeout limit.
- Offline deployment fails to load dependent images, causing deployment failure. The cause is that all dependent Docker images were not exported in advance, only the FastGPT main image was downloaded, and necessary middleware image files are missing.

## How to Verify Successful Configuration
- Run the `docker ps` command to confirm that all relevant containers for FastGPT v4.17.0 and the dependent MongoDB and Redis containers are in normal running status.
- Access the domain specified by `FE_DOMAIN`, enter the administrator account corresponding to `ROOT_KEY` to log in to the system background, and verify that the configuration interface can be accessed normally.
- Upload a simulated batch production record document, perform a keyword search operation, and confirm that matching document content can be returned correctly.
- Check the corresponding directory in the internal object storage to confirm that the uploaded compliance document has been stored correctly, and the file can be downloaded normally using the generated access token.

The values provided are common starting points and should be measured against the reader's own samples.
