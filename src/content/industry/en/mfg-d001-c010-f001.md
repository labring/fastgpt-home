# Supplier and Process Quality Audit for Medical Device Assembly and Clean Production: HTTP Interfaces and External Systems

## What Data for This Category Entails
This category covers production-related documents for manufacturers of single-use consumables, implanted and interventional devices, diagnostic equipment, and active medical devices. These documents include production process specifications, batch production records, clean zone records, sterilization batch records, test reports, software version records, adverse event and traceability materials.
Data sources include design history files, device and material lots, MES systems, clean environment monitoring equipment, sterilization equipment, testing and calibration systems.
Data updates run per product batch, per device, or per clean environment monitoring plan. Fields include unique identifiers, batch numbers, sterilization parameters, clean environment metrics, software versions, with units adjusted alongside corresponding document fields.

## Constraints Imposed on HTTP Interfaces and External Systems
Data sources are dispersed and linked to batches and unique device identifiers. Interfaces must support pulling data by batch number and unique identifier, while compatible with field formats from different systems.
Update frequency shifts with production batches or environment monitoring plans. Interfaces must support on-demand triggering to adapt to non-fixed update rhythms.
Documents involve high-risk production and compliance data. Interfaces must carry the `Authorization` parameter for identity verification to prevent unauthorized access.
Multi-dimensional data such as sterilization and clean environment metrics must be processed synchronously. Interface response structures must support batch extraction of multiple fields to reduce invalid transmission traffic.

| --- | --- | --- |
| `Authorization` | `Bearer {Medical Device Manufacturer Exclusive API Key}` | This category’s data involves high-risk production and compliance information, requiring standard Bearer tokens for identity verification to meet data security requirements |
| `variables` | `{"batchNo": "", "deviceUniqueId": ""}` | Batch number and unique device identifier must be passed as retrieval conditions for data pulling, to match the associated fields of this category’s data |
| `responseData` | `Only return production process specification, sterilization batch record, and clean zone monitoring fields` | This category’s audit only requires specific high-value data, reducing invalid transmission traffic and aligning with process quality audit information needs |
| Interface timeout setting | `600 seconds` | Must accommodate data pull delays from sterilization equipment and clean environment monitoring systems, to avoid interrupting audit processes due to timeout |
| Retry trigger rule | `Only trigger retries when 5xx status codes are returned` | Adapts to occasional offline or data synchronization delays of production equipment, avoiding repeated requests for compliance data |

## Three Common Misconfigurations
- A `404 page not found` status code is returned when calling the interface. Causes: Incorrect configuration of the `Authorization` parameter, or the retrieved batch number and unique identifier do not exist in the associated systems, resulting in the interface being unable to match corresponding data.
- Empty fields are returned after calling the interface. Causes: Incorrect retrieval parameters are not configured in `variables`, or fields returned by the external system do not match the extraction rules set in `responseData`.
- Interface calls time out. Causes: The interface timeout setting is not adjusted to accommodate delays from production equipment, or data synchronization blocking occurs in the external system.

## How to Verify Correct Configuration
- A test interface call with an `Authorization` parameter meeting security requirements is executed, to confirm returned status codes match expectations.
- A known valid production batch number is passed as the `variables` parameter, to confirm returned fields match the audit-required data set in the configuration.
- A temporary delay scenario from the external system is simulated, to confirm the interface’s retry and timeout settings align with production rhythms.
- Interface returned data is cross-checked against the required fields specified in this category’s production audit documents, to confirm the match level meets audit needs.
