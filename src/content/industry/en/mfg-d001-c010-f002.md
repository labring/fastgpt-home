# Supplier and Process Quality Audit for Medical Device Assembly and Cleanroom Production: Vector Models and Indexes

## What Data for This Category Looks Like
Typical data for this category comes from design history files, device and material lots, MES systems, clean environment monitoring equipment, sterilization equipment, inspection and calibration systems. Daily documents include production process specifications, batch production records, clean zone records, sterilization batch records, inspection reports, software version records, adverse event and traceability materials. Fields include unique identifiers, batch numbers, temperature and humidity parameters, sterilization duration, inspection results, and more. Update frequency follows per batch or per product, or aligns with clean environment monitoring plans.

## What Constraints These Characteristics Impose on Vector Models and Indexing Workflows
Data for this category is linked to product batches and the entire production process. When chunking, context associations of key parameters must be retained to avoid cutting off process steps or unique identifiers. Update rhythms vary across different documents, so incremental indexing trigger rules must be matched to avoid full duplicate indexing. Data involves sterile control and traceability requirements, so vector retrieval must accurately recall documents corresponding to the target batch, while controlling the number of retrieval results to fit the information processing volume of audit scenarios.

## Configuration Settings
These configurations apply to FastGPT v4.17.0:
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Chunk length | 800–1200 characters | Matches the typical length of a single batch production record, retains complete context of process steps |
| Overlap length | 100–150 characters | Prevents chunking from cutting off key audit parameters such as sterilization duration and unique identifiers |
| `maxToken` | 8192 token | Adapts to the input upper limit of text-embedding-3-large, covers the content length of complete batch records |
| Single search limit | Top 8 entries | Balances recall scope and information density during audits, avoids excessive redundant content interfering with judgment |
| `defaultToken` | Calibrated based on actual measurements | Adapts to video memory limits of locally deployed vector models, prevents memory overflow |
| Maximum context | 4000–6000 characters | Matches the total document length associated with a single query in supplier audit scenarios |

## Three Common Misconfigurations
- Symptom: Knowledge base retrieval takes longer than 30 seconds, with a timeout status displayed on the interface. Cause: The chunk length setting for this category was not matched, leading to an excessive number of chunks and a longer vector retrieval recall chain.
- Symptom: Indexing tasks remain stuck in the "Indexing" state and cannot enter the ready status. Cause: A reasonable `maxToken` value was not set, and individual data exceeds the model's input upper limit, causing parsing to freeze.
- Symptom: Index entries in the dataset automatically increase repeatedly, with multiple sets of indexes generated for the same batch production record. Cause: Incremental indexing was not triggered according to batch update rules, and full indexing was executed on a fixed cycle instead, leading to multiple index entries being generated for the same document.

## How to Confirm Proper Configuration
- Upload a single typical batch production record, check that chunked fragments retain key parameters including sterilization batch number and clean zone temperature and humidity.
- Trigger an incremental indexing task, wait for completion, verify that the number of index entries matches the count of product batches in the source data.
- Input a query related to supplier audits, confirm that retrieved documents include sterilization records and inspection reports corresponding to the target batch.
- Review the vector model’s running logs, confirm no error messages related to video memory overflow or token limit exceedance are present.

The values provided are common starting points and should be measured against the reader's own samples.
