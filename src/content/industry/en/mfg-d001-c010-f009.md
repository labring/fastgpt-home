# Supplier and Process Quality Audit for Medical Device Assembly and Clean Production: Model Access and Configuration

## What data for this category looks like
Data sources for this category include design history files, device and material batch records, MES systems, clean environment monitoring data, sterilization equipment logs, inspection and calibration systems, and more. Daily documentation covers production process specifications, batch production records, clean zone records, sterilization batch records, inspection reports, software version records, adverse event and traceability materials. Data is updated when corresponding records are generated per batch or product unit, or at regular intervals per clean environment monitoring plans. Document fields include exclusive content such as unique identifiers, process parameters, cleanliness indicators, sterilization parameters, and inspection results. It does not include general statistical percentage fields.

## What constraints these characteristics impose on the model access and configuration workflow
Data for this category involves highly compliant batch records and real-time monitoring data. Models must accurately match unique identifiers and process parameters. This means model access must support long context processing. Data is updated frequently, and single data volume varies with production batches. Parameters must be configured to adapt to dynamic data scales. Document fields include exclusive industry terms such as biocompatibility and cleanliness. Models must be able to recognize content in this specialized field. At the same time, output formats must meet compliance requirements to avoid format errors that block subsequent processes. Data traceability requirements are high. Model calls must retain complete context association information to prevent broken links. FastGPT v4.17.0 must be used to adapt to these constraints.

## How to set configuration
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the long context requirements of multi-batch associated documents for this category, covering complete associated information for process specifications and batch records |
| `maxTokens` | 4000 token | Matches the output length of single-batch inspection reports and sterilization records, avoiding truncation of critical compliance data |
| `toolChoice` | auto | Supports automatic selection of corresponding tools for different tasks such as supplier audit and quality verification, adapting to multi-link audit scenarios |
| `temperature` | 0.1–0.3 | Reduces random output, ensuring the accuracy of output for compliance fields such as unique identifiers and sterilization parameters |
| `AIPROXY_API_ENDPOINT` | Configure per deployment environment | Adapts to internal corporate network access restrictions, ensuring compliance and stability of model calls |

## Three common errors
- Knowledge base search return results cannot be recognized as valid JSON format, and "invalid json" errors appear in logs. The cause is that model output does not strictly follow preset structured format constraints, and does not adapt to the nested field structure of documents for this category.
- Tool calls in advanced orchestration cannot automatically select specified tools for execution, and task execution results deviate from expectations. The cause is that `toolChoice` is not configured to auto mode, or trigger rules for corresponding tasks are not bound.
- Rearrangement of model returns results in abnormal errors, and matching results do not conform to business logic. The cause is that rearrangement matching logic is not adjusted for exclusive fields such as cleanliness and sterilization parameters for this category, leading to field matching failures.

## How to confirm successful configuration
- Launch a supplier audit task, check whether the format of model return results conforms to preset structured requirements, and confirm there are no format errors.
- After configuring tool call rules, trigger the corresponding task, and verify whether the model automatically selects matching tools for execution.
- Input a query containing cleanliness parameters and sterilization records, check whether semantic matching results prioritize returning exclusive documents for this category.
- View model call logs, confirm that actual call values for parameters such as `maxContext` and `maxTokens` match configured values.

The values provided are common starting points and should be measured against the reader's own samples.
