# Supplier and Process Quality Audit for Printing and Packaging Processing: Model Access and Configuration

## What the data for this category looks like
Business data for printing and packaging processing comes primarily from customer manuscripts, color management systems, printing press data, ink and substrate batch records, spectrometers, barcode detectors, and similar sources. Daily documents include pre-press files, imposition sheets, printing process sheets, ink color matching records, first article approval samples, barcode inspection reports, die-cutting and lamination records, and more.
Data updates occur per order, per batch, and each time a plate is changed. Fields include plate number, batch number, color parameters, barcode check digits, die-cutting accuracy, and others. Units adjust flexibly based on specific process parameters.

## What constraints these characteristics impose on the "model access and configuration" workflow
Business data for printing and packaging processing includes both text and image types. Update frequency follows per order, per batch, and per plate change cycles. Single-batch data volume shifts based on order scale. Multi-type documents require models to support both text parsing and image recognition, so multi-modal related parameters must be configured.
The high-frequency update feature requires context length to adapt to batch audit scenarios, preventing loss of historical verification information. Business fields lack unified units, so models need flexible parameter recognition capabilities. Output token length and temperature parameters must be set reasonably to ensure consistent judgment.
Cross-system data pulling requirements mean models must support plugin calls, so corresponding access parameters need configuration.

The following configurations are based on FastGPT v4.17.0.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the total token volume of multiple documents per single batch, meeting context requirements for batch audits |
| `maxTokens` | 2000–3000 token | Matches the output length of a single audit result, avoiding truncation of key verification information |
| `vision` | Enabled | Supports parsing image documents such as first article approval samples and barcode inspection reports, adapting to the multi-modal audit scenario of printing and packaging |
| `temperature` | 0.1–0.3 | Ensures stability of audit judgments, reduces random deviations, and meets the rigor requirements of quality audits |
| Workflow/API tool selection | auto | Allows the model to independently choose whether to call plugins, adapting to cross-system data verification needs |
| `AIPROXY_API_ENDPOINT` | Fill in the locally deployed model access address | Connects to locally deployed models such as chatglm2, meeting data privacy requirements |

## Three common configuration errors
- Phenomenon: When creating a knowledge base, locally deployed chatglm2 models cannot be selected, or model interface calls return a 401 error. Cause: `AIPROXY_API_TOKEN` is not configured correctly, or the token is not granted access permissions for the corresponding model.
- Phenomenon: CosyVoice2-0.5B cannot be used normally, while whisper-large-v3-turbo runs normally. Cause: The `vision` parameter is not enabled, or the configured model does not support multi-modal input, resulting in failure to correctly parse image documents.
- Phenomenon: The model cannot call DingTalk robot plugins to complete task push. Cause: `toolChoice` is not configured to a mode that allows plugin calls, or the plugin has not completed permission binding, resulting in the model being unable to trigger plugin calls.

## How to confirm configuration is complete
- Run a local model connectivity test to verify that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are configured correctly, and can return the list of deployed models.
- Upload a single pre-press file and first article approval sample image to verify that the `vision` parameter takes effect, and the model can recognize text and color deviation information in the image.
- Initiate a single-batch audit task to verify that the `maxTokens` configuration is reasonable, and the output audit results are not truncated.
- Configure the DingTalk robot plugin and initiate a test call to verify that the `toolChoice` parameter takes effect, and the model can normally trigger plugin pushes.

The values provided are common starting points and should be measured against the reader's own samples.
