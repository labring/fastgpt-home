# Supplier and Process Quality Audit for Active Pharmaceutical Ingredient and Pharmaceutical Intermediate Manufacturing: HTTP Interfaces and External Systems

## What data for this category looks like
Data for this category comes from registered process documents, raw material batch ledgers, DCS control systems, weighing systems, LIMS laboratory information management systems, chromatography data systems, and QMS quality management systems. Daily generated documents include batch production records, material balance sheets, reaction and purification step records, cleaning validation records, impurity profile reports, deviation and change documents. Data is updated per production batch and process step. Fields include batch number, reaction temperature, yield, impurity content, solvent residue, change approval status, with no additional preset statistical values.

## What constraints these characteristics impose on HTTP interfaces and external systems
Data for this category is scattered across multiple sources and requires integration with multiple external systems such as DCS, LIMS, and QMS. HTTP interfaces must support parallel calls to multiple endpoints and data aggregation. Data is updated per batch and process step, so interfaces must support precise data pulling using batch number and step node as query parameters to avoid returning invalid data. Professional fields such as impurity content and solvent residue must be returned in a structured format, and interfaces must support custom field mapping. Errors in production links have severe consequences, so interfaces must be configured with timeout retry and exception alert mechanisms to ensure the reliability and timeliness of data synchronization.

## Configuration Settings
The following configurations are formulated based on the standard specifications of FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Bearer ${bound authentication token} | Complies with standard interface authentication specifications to ensure permission security for external system calls |
| `variables` | {"target_batch": "{{batch_number}}", "process_step": "{{step_id}}"} | Supports dynamically passing query parameters by production batch and process step to accurately pull data for the corresponding link |
| `responseData` | Retain only batch number, impurity profile data, yield, and solvent residue fields | Filters non-essential fields to reduce data transmission volume and adapts to the core data requirements of quality audit scenarios |
| Interface timeout period | 600 seconds | Reserves sufficient time to complete multi-endpoint data aggregation and return for single-batch data that needs integration with multiple external systems |
| Retry trigger threshold | Trigger retry after 2 consecutive failed calls | Addresses occasional network fluctuations in production environments to ensure the reliability of data synchronization |
| Maximum call frequency | 1 call per production batch | Matches the rhythm of data updated per batch to avoid pulling redundant data repeatedly |

## Three Common Misconfigurations
- Scenario: Interface returns 401 Unauthorized status code, unable to pull impurity profile data from the LIMS system. Cause: The `Authorization` parameter is not configured correctly, or the bound authentication token has expired or has insufficient permissions.
- Scenario: After restarting the Docker container under Ubuntu, interface calls associated with external systems throw SQL permission errors. Cause: Local mounted database configuration file permissions are reset after container restart, preventing the FastGPT process from accessing the associated local database cache.
- Scenario: Models configured in OneAPI cannot be called normally on the FastGPT page, and the interface displays that the model does not exist. Cause: The proxy address and corresponding model identifier of OneAPI are not correctly entered in the FastGPT model configuration, and the configured model service is not matched.

## How to Verify a Successful Configuration
- Manually pass a known production batch number, call the configured HTTP interface, and check if the returned fields include preset core data such as impurity profiles and yield.
- Simulate a network fluctuation scenario to trigger an interface call, and confirm that retries are completed according to the configured number of times and valid data is returned.
- View the FastGPT system logs to confirm that authentication parameters for interface calls are correctly carried, and there are no permission-related error messages.
- Compare the original data from external systems with the structured data returned by the interface to confirm that field mapping relationships meet configuration requirements.

The values provided are common starting points and should be measured against the reader's own samples.
