# Supplier and Process Quality Audit for Active Pharmaceutical Ingredient and Pharmaceutical Intermediate Manufacturing: Workflow Orchestration

## What the Data for This Category Looks Like
Core data for this category comes from daily production and quality documents of active pharmaceutical ingredient synthesis, fermentation, purification, quality and registration support departments. These documents include batch production records, material balance sheets, reaction and purification records, cleaning records, impurity profile reports, deviation and change documents.
Data sources cover registered process documents, raw material batch ledgers, DCS production control systems, weighing systems, LIMS laboratory information management systems, chromatography data systems, and QMS quality management systems.
Update frequency is once per production batch and per process step.
Data fields include reaction yield, solvent residue levels, impurity profile peak values, batch compliance status, and other fields. These fields vary with testing items and process parameters, with no unified fixed units.

## Constraints Imposed on Workflow Orchestration
Data sources for this category are scattered and have high update frequency. Workflows must support connecting structured and unstructured data from multiple systems to avoid synchronization delays and omissions.
Core document types are diverse and closely linked. Workflows must adapt to parsing files in different formats, such as batch production records and impurity profile reports.
Compliance risks and error consequences in the production process are directly tied to batch scrapping. Workflows must be configured with clear failure handling and verification nodes to ensure compliance of every audit step.
Multi-step reaction and intermediate transfer processes have high complexity. Workflows must support splitting nodes by process steps to enable step-by-step audits and data linkage.

## Configuration Settings
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| `variables` configuration | Bind batch ID with corresponding impurity profile and yield data, set storage scope to current session | Match the independent update requirements of each batch of data, ensure accurate cross-node data transfer |
| File parameter transfer | Limit incoming file size to no more than 1000 MB, only allow uploading batch production records and impurity profile report documents | Adapt to the volume and type range of core documents for this category |
| `nodeId` mapping | Bind DCS data collection nodes and quality audit nodes, set trigger interval to 300 seconds after each production batch is completed | Match the update rhythm of production steps, avoid repeated triggers and data redundancy |
| Failure retry strategy | Retry 2 times after failure, set retry interval to 60 seconds | Address common scenarios of temporary response delays in LIMS systems |
| Global variable debugging | Enable debug logs, retain input and output fields | Facilitate troubleshooting of runtime issues with empty parameters |
| Workflow trigger rule | Trigger based on the completion status of raw material batches | Match the node sequence of the production process, ensure audit timing is synchronized with production progress |

## Three Common Misconfigurations
- Phenomenon: The `variables` field is empty when the workflow runs. Cause: Associated parameters corresponding to the batch ID are not bound in the configuration, resulting in interrupted cross-node data transfer.
- Phenomenon: Files uploaded via simple tasks cannot be passed as parameters to workflow nodes. Cause: External link transfer permission is not enabled in the file parameter configuration, only local file streams are allowed, resulting in inability to read the uploaded file's link.
- Phenomenon: After modifying the global variable value, the next node debug prompt shows empty input. Cause: The variable scope is not locked to the current conversation session in the `variables` configuration of FastGPT v4.17.0, resulting in the variable value not being updated correctly.

## How to Verify Correct Configuration
- Trigger a simulated active pharmaceutical ingredient batch production workflow, check whether the batch ID field configured in `variables` correctly loads corresponding data.
- Upload an impurity profile report, verify that the file link can be smoothly passed to the corresponding workflow node.
- Simulate a scenario where the LIMS system has a response delay, confirm whether the failure retry strategy takes effect.
- After modifying the global variable value, check whether the input log of the next node displays the updated content.

The values provided are common starting points and should be measured against the reader's own samples.
