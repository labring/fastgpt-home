# Supplier and Process Quality Audit for Transformer and High-Voltage Electrical Manufacturing: HTTP Interfaces and External Systems

## What data looks like for this category
Daily documents for this category include winding and core assembly records, vacuum drying records, insulating oil reports, partial discharge and withstand voltage test reports, and nameplate parameter tables. Data sources include design BOM, silicon steel sheet and insulating material data, vacuum and drying equipment, oil testing equipment, and test stations. Data is updated once per device and once per batch of materials. Complete audit data for a single device includes exclusive fields such as insulation structure parameters, partial discharge values, withstand voltage values, and nameplate rated voltage (unit kV).

## What constraints these characteristics impose on HTTP interfaces and external systems
Each device and batch of materials in this category has a unique identifier, and data requires single-unit traceability. Interface requests must carry identification parameters such as batch numbers and device serial numbers. Multiple types of audit documents require interfaces to support multi-format data retrieval. Consequences of failures such as insulation breakdown and grid site faults are severe, so interfaces must be configured with reasonable timeout and retry mechanisms. Single-device test data has high precision requirements. Original returned data cannot be arbitrarily truncated or modified, and the original meaning of business fields must be retained.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {third-party system API key}` | External interfaces for suppliers and test equipment typically use Bearer token authentication, which conforms to industrial system security access specifications |
| `variables` | `{"batchId": "actual batch number", "deviceSerial": "device serial number"}` | Each device and batch of materials in transformer manufacturing has a unique identifier, used for the interface to accurately match audit data for the corresponding batch |
| `responseData` | `Retain original fields, do not rename` | Fields in insulating oil reports and partial discharge test reports have fixed business meanings. Renaming these fields will prevent subsequent audit links from matching correctly |
| Single request timeout duration | `600 seconds` | High-voltage test report generation takes a long time. This setting avoids interrupting data retrieval due to early timeout |
| Streaming return shard interval | `Calibrated based on actual measurements` | Test data volume varies across batches. The interval must match front-end display rhythm requirements |

## Three Common Mistakes
- Phenomenon: After the chat API streams output, clicking external links only overwrites the current page and does not jump. Cause: The correct jump protocol field is not configured in `responseData`, so the front end cannot recognize the external link jump rules.
- Phenomenon: Chat log details do not match the actual answer content. Cause: The correct device batch ID is not bound in `variables`, so each request calls cached old data.
- Phenomenon: API call return speed is fixed at 4 seconds per call and cannot be adjusted. Cause: The interface return shard configuration is not adjusted based on test report data volume. The default shard interval does not adapt to the single-batch data scale of transformer manufacturing.

## How to Confirm Configuration is Correct
- Call the test interface, check if the returned `responseData` includes category-specific fields such as insulating oil moisture content and partial discharge values, and that field names match the external system's documentation.
- Initiate a request carrying the batch ID defined in `variables`, and verify that the returned data matches the corresponding batch's test records.
- Enable streaming output testing, observe whether front-end link jump behavior meets business requirements, and adjust configuration items until expectations are met.
- Check the FastGPT v4.17.0 chat log to confirm that log content matches the actual content returned by the interface.
