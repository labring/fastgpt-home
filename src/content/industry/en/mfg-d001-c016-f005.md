# Supplier and Process Quality Audit for Transformer and High-Voltage Electrical Equipment Manufacturing: Tool Calling and Plugins

## What this category of data looks like
This category of data originates from design BOM, silicon steel sheet and insulating material ledgers, vacuum drying equipment logs, oil test reports, high-voltage test records from the test station, and nameplate parameter tables. Data is updated per single product or per batch of raw materials. Core documents include winding and core assembly records, vacuum drying records, insulating oil test reports, and partial discharge and withstand voltage test reports. Fields include insulating oil moisture content, partial discharge amplitude, rated voltage, tap position, and others. Some fields use dedicated units: picocoulombs (pC) for partial discharge, kilovolts (kV) for voltage.

## Constraints on tool calling and plugin workflows
Data for this category is updated per single product or per batch of raw materials. Tool calling must bind to the exclusive context of the corresponding batch or single equipment. This prevents cross-batch data mixing. Core documents include structured test data and dedicated unit fields. Plugins must support unit verification and structured field extraction. This ensures accurate parameter matching. Multi-source data comes from production equipment and test stations. Tool calling must be compatible with interface formats of different data sources. This reduces data adaptation costs. Quality audit errors carry severe consequences. A pre-verification step must be added before tool calling. This stops invalid parameters from triggering incorrect processes.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Force tool calling | This category requires fixed calls to two tool types: test data parsing and material verification. This prevents the model from selecting options that deviate from business scenarios |
| Single tool call timeout | 600 seconds | Structured parsing of high-voltage test reports requires a long processing cycle. This avoids mid-interruption that stalls the audit workflow |
| `functionCall` | Enable strict format validation | Fields in this category must strictly match dedicated units and value ranges. This prevents the model from generating non-compliant call parameters |
| Number of retained tool call context entries | First 8 entries | The volume of historical operation data for single product audits is manageable. Excessive entries will interfere with parameter matching for the current batch |
| Single knowledge base recall limit | First 6 entries | Reference documents for insulating oil tests and assembly records are concentrated. Excessive recalls will increase context load |

## Three Common Misconfigurations
- Symptom: Knowledge base search response times out, with slow operation prompts in logs. Cause: Retrieval strategy was not adjusted for structured test reports of this category. This leads to longer-than-expected parsing time for single batch data.
- Symptom: Tool calling fails to pull insulating oil report data for the corresponding batch. Cause: Tool calling context was not bound to the current product’s BOM number. This expands the retrieval scope beyond the target batch.
- Symptom: Parameters generated by tool calling do not meet the dedicated unit requirements of this category. This results in significant result deviations. Cause: Strict format validation for `functionCall` was not enabled. The model did not adapt to the field rules of this category.

## How to Verify Correct Configuration
- Submit a simulated quality audit request for a single transformer. Check that tool calling only triggers the preset test data parsing and material verification tools.
- Review tool call return results. Confirm that the units of structured fields match the dedicated units of this category.
- Verify that documents recalled by the knowledge base belong to the current batch’s insulating oil, assembly records, or other relevant types.
- Check system logs. Confirm that no timeout errors occurred during tool calling.
