# Supplier and Process Quality Audit for Spraying and Coating: Model Access and Configuration

This document applies to model access configuration for FastGPT v4.17.0.

## What the Data for This Category Looks Like
Daily documents for this category include coating process cards, coating batch sheets, paint mixing records, film thickness and color difference reports, oven curves, defect repair sheets, and VOCs ledgers. Data sources cover coating supplier TDS/SDS, real-time collected data from spray booths and ovens, colorimeters, film thickness gauges, environmental monitoring equipment, and MES systems.

Update rhythm adjusts with production flow. Ledgers are generated per coating batch and per shift. Oven and color difference detection data are collected continuously. Document fields include coating batch number, film thickness values, oven temperature curve nodes, VOCs concentrations, and other business content. Formats include structured system data and unstructured electronic or paper documents.

## What Constraints These Characteristics Impose on the Model Access and Configuration Phase
Multiple heterogeneous data sources require the model access link to support unified format conversion for structured sensor data, semi-structured process documents, and unstructured inspection reports, to avoid data parsing errors.

High-frequency continuously collected oven and color difference data require model call response delay to match production tempo, to avoid audit delays caused by excessive latency.

Field differences across different documents require the model to accurately identify and associate corresponding business fields, to ensure the accuracy of audit basis.

Batch-level updates require knowledge base synchronization frequency to match the update rhythm of coating batches and shifts, to avoid data lag affecting cross-batch quality correlation analysis.

## How to Set the Configurations

| Configuration Item | Recommended Value Range | Rationale |
|---|---|---|
| `maxContext` | `8000–12000 token` | Requires associating content from coating process cards, coating batch sheets, and multiple inspection reports, covering multi-document context to support complete audit logic |
| `maxTokens` | `2000–3000 token` | Adapts to the output length requirement for coating quality audit conclusions, avoiding truncation of critical defect analysis or rectification suggestions |
| `quoteMaxToken` | `1500–2000 token` | Retains sufficient reference content for associating specific inspection data such as film thickness and color difference as audit basis |
| `temperature` | `0.2–0.4` | Ensures stability of audit conclusions, avoiding random fluctuations that affect consistency of quality judgments |
| `AIPROXY_API_ENDPOINT` | Fill in according to the deployed proxy address, such as `https://xxx/v1` | Adapts to the model call path of the proxy platform to ensure requests are correctly routed to the target model |
| `AIPROXY_API_TOKEN` | Fill in with the valid key generated by the proxy platform | Completes identity verification for model calls, ensuring security of the access link |

## Three Common Mistakes
- The symptom is a knowledge base search error `invalid configuration parameter name "hnsw.max_scan_tuple"`. The cause is mistakenly entering parameters not supported by FastGPT into configuration items, without using the specified configuration parameter list.
- The symptom is no thought process displayed after enabling the output thought function for the large model. The cause is incorrect configuration of the model's preset output format, or an excessively high `temperature` value leading to random deviations in generation logic.
- The symptom is an empty model list returned during proxy calls. The cause is incorrect use of the `/v1/models` path for the proxy address, without matching the proxy-required `/v1/model/list` path.

## How to Verify Successful Configuration
- Call the model test interface, input test questions related to coating quality audit, and check whether returned results include correct inspection data or references to process documents.
- View proxy call logs to confirm that requests for `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` have no authentication failures or path errors.
- After adjusting the `temperature` parameter, test the same audit question multiple times, and check whether results remain relatively stable, meeting low-randomness audit requirements.
- Upload single-batch coating documents and inspection data, test whether knowledge base recalled content matches the corresponding information of that batch, and verify accuracy of data association.

The values provided are common starting points and should be measured against the reader's own samples.
