# Supplier and Process Quality Audit for Coating and Painting: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
This category covers materials related to coating lines for automotive, home appliances, construction machinery, and metal furniture. Daily documents include coating process cards, paint batch sheets, paint mixing records, film thickness and color difference reports, oven curves, defect repair sheets, and VOCs logs. Data comes from paint supplier TDS/SDS documents, spray booth and oven operation data, colorimeters, film thickness gauges, environmental monitoring equipment, and MES systems. Updates follow this schedule: batch sheets and paint mixing records are updated for each paint batch, process execution data is synchronized per shift, and key parameters are collected continuously. Document fields include film thickness values, color difference deviation values, oven temperature curves, and VOC emission concentrations. Some documents include batch numbers and production team identifiers.

## Constraints on Knowledge Base Retrieval and Recall
Data in this category has high update frequency, diverse types, and scattered sources, which creates multiple constraints for knowledge base retrieval and recall. High-frequency updated paint batch data and per-shift process data require the retrieval pipeline to support incremental synchronization and real-time association, to avoid using expired parameters. Multiple document types include structured film thickness and color difference reports, curve-style oven data, and text-based process cards. These require chunking rules adapted to different formats, to ensure semantic matching covers all scenarios. Field naming varies across different sources. For example, film thickness parameters collected by equipment and coating thickness descriptions in supplier documents need unified mapping, to avoid retrieval bias. The key process matching step relies on accurate parameter recall, so interference from irrelevant results must be limited, to ensure audit efficiency and accuracy.

## Configuration Settings
The following configurations are adapted for FastGPT v4.17.0:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Matches semantic relevance for coating process parameters and defect analysis, filters low-correlation results, and meets the precise audit needs of painting scenarios |
| `limit` | `Top 8–12 results` | Controls the number of results returned per recall, avoids context overload, and adapts to the multi-parameter verification scenario of coating audits |
| `searchMode` | `Semantic retrieval + keyword hybrid` | Balances precise matching of process parameters and quick location of document keywords, covering structured data and text content |
| `usingReRank` | `Enabled` | Performs secondary sorting on recall results, prioritizes high-value content related to coating defects and process windows |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Automatically expands query terms, supplements synonyms for paint models and process parameters, and adapts to professional term matching in the coating field |
| `collectionIds` | `Bind dedicated knowledge base collections for coating processes and quality inspection reports` | Isolates non-coating data, avoids interference from irrelevant documents on retrieval results, and ensures audit professionalism |

## Three Common Mistakes
- Issue: Knowledge base search tests return 0 results, or match documents unrelated to the current coating audit. Cause: Dedicated knowledge base collections are not bound, so the retrieval scope covers non-coating data, or the `similarity` threshold is set too high, leading to over-precision and missing relevant content.
- Issue: Some coating documents show training exceptions, and duplicate references appear even after re-uploading. Cause: The knowledge base deduplication mechanism is not enabled, or uploaded files include duplicate paint batch sheets and paint mixing records, and the system does not automatically identify duplicate content, leading to training exceptions and redundant references.
- Issue: Retrieval results exceed the preset reference limit, resulting in overly long audit context. Cause: The `limit` parameter is not configured correctly, or `usingReRank` is not enabled to filter low-value results, leading to too many recall results beyond the scope required for audits.

## How to Verify Proper Configuration
- Access the FastGPT knowledge base test page, enter query terms related to coating processes, and confirm that the source of returned results is the bound dedicated knowledge base collection.
- Upload a test coating defect repair sheet, trigger knowledge base training, retrieve the document's keywords, and confirm that the result returns normally without abnormal errors.
- Adjust the `similarity` threshold, observe changes in the relevance of retrieval results, and confirm that the threshold setting meets the needs of the current audit scenario.
- After enabling `usingReRank`, compare the sorting of recall results before and after enabling, and confirm that the re-ranking function works correctly.

The values provided are common starting points and should be measured against the reader's own samples.
