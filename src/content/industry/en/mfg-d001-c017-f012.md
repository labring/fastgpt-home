# Supplier and Process Quality Audit for Spraying and Coating: Deployment and Upgrade

## Data Profile for This Category
This category’s data comes from coating supplier TDS/SDS, spray booth and oven operating data, colorimeters, film thickness gauges, environmental monitoring equipment, and MES systems. Daily documents include coating process cards, coating batch sheets, paint mixing records, film thickness and color difference reports, oven curves, defect repair sheets, and VOCs logs. Data update frequency follows batch-specific schedules for each coating batch, with shift-level records generated per shift. Spray booth and oven data is collected continuously. Core document fields include film thickness, color difference ΔE, oven temperature range, VOCs concentration, coating viscosity, and other key parameters.

## Constraints Imposed on Deployment and Upgrade
The multi-source heterogeneous data sources, high-frequency update cadence, and specialized document structure of this category create clear constraints for deployment and upgrade.
Multi-format data access requirements demand configuring parsing rules adapted to industrial documents, time-series device data, and instrument reports during deployment.
High-frequency batch and continuous collection data requires adjusting batch synchronization intervals during upgrades to avoid overload during single synchronization operations.
Structured storage requirements for specialized parameters demand retaining field mapping configurations to ensure core indicators such as film thickness and color difference can be indexed correctly.
Cross-document associated audit requirements demand retaining cross-data source associated storage configurations during upgrades to prevent data silos between VOCs logs and defect repair sheets.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Connection string pointing to an independent sharded cluster | Adapts to multi-source heterogeneous time-series and document data storage requirements, ensures read/write performance for batch data synchronization |
| `REDIS_URL` | Instance with 1000 MB or more memory | Supports high-frequency device data caching and session state management, adapts to the update frequency of continuous shift-level collection |
| `STORAGE_S3_ENDPOINT` | Bound to an industrial-grade object storage service node | Meets large-file storage requirements for coating-related documents such as oven curves and batch sheets |
| `DB_MAX_LINK` | Set to 200–300 | Balances concurrent connection count for multi-source data access and server resource usage, adapts to the basic 2-core 8G server configuration |
| `PG_URL` | Points to a lightweight relational database instance | Stores audit workflow task status and associated records, separated from time-series data storage |
| `FILE_TOKEN_KEY` | Random string calibrated through actual testing | Ensures access permission security for coating documents, prevents unauthorized access to sensitive process data |

## Three Common Misconfigurations
- Container restarts continuously, with logs showing out-of-memory errors. The cause is failure to adjust the `DB_MAX_LINK` parameter according to the storage requirements of coating data. Excessive server memory is occupied by concurrent connections, and connection count is not restricted when adapting to the 2-core 8G server configuration.
- Images in coating documents within the knowledge base cannot be displayed in conversations. The cause is failure to correctly configure `FILE_TOKEN_KEY` or `STORAGE_S3_ENDPOINT`, leading to failed image access permission verification and inability to generate valid access links.
- Abnormal inter-component communication occurs when not using docker compose for deployment. The cause is failure to configure correct `REDIS_URL` and `MONGODB_URI` connection strings when starting individual containers manually, leading to failed normal connectivity between the database and cache service.

## How to Verify Proper Configuration
- Run the docker ps command to confirm all relevant containers are in a running state with no abnormal exit records.
- Upload a coating process card document to verify that the file can be stored normally and generate an accessible link.
- Initiate a batch synchronization test to confirm that multi-source data such as film thickness reports and oven curves can be indexed correctly.
- Check system logs to confirm that the database connection count does not exceed the threshold set by `DB_MAX_LINK`.

The values provided are common starting points and should be measured against the reader's own samples.
