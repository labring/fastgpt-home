# Supplier and Process Quality Audit for Continuous Basic Chemical Production: Multi-turn Dialogue and Prompts

## Data Profile for This Category
Typical data sources for continuous basic chemical production include DCS/SIS systems, online analyzers, LIMS laboratory management systems, equipment condition monitoring tools, energy metering devices, and raw material tank data. Data update frequencies fall into three categories: real-time, per shift, and daily. Daily documents cover operating procedures, process index cards, DCS trend charts, laboratory reports, interlock bypass records, special work permits, and shift logs. Data fields include reaction temperature (℃), system pressure (MPa), material flow rate (m³/h), interlock number, work permit number, and others. Units comply with general metrology standards for chemical production.

## Constraints on Multi-turn Dialogue and Prompt Workflows
Real-time updated production data requires that conversation context does not include overly outdated redundant information. The time range for retrieval and dialogue must be limited. Multiple types of documents require prompts to clearly distinguish retrieval scenarios. For example, prioritize calling process index cards to verify parameters, or retrieve interlock bypass records to confirm compliance. The need to associate multiple data sources requires configuring exclusive identifiers bound to corresponding production units. This avoids mixing audit data from different devices. Fixed fields and units require prompts to uniformly verify formats. This ensures returned audit results comply with metrology specifications for chemical production.

## Configuration Settings
This configuration is based on FastGPT v4.17.0. Specific parameters are listed below:

| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Matches the content length of a single page of process index cards or a single DCS trend record, to avoid truncating critical parameters |
| Overlap Length | 150–200 characters | Covers continuous descriptions of process parameters across chunks, ensuring complete retrieval of interlock logic |
| Single Search Limit | Top 6 entries | Matches the number of single-batch entries in shift reports and laboratory reports generated per shift, to avoid interference from redundant data |
| Maximum Context | Top 3 turns of dialogue + real-time data snapshot | Adapts to the timeliness of real-time data, reducing the impact of old data on current audits |
| `chatId` Configuration | Bind to device number | Associates exclusive data for the corresponding production unit, isolating audit information from different devices |
| `variables` Configuration | Inject current shift and raw material batch | Matches real-time updated production parameters, accurately matching the current audit scenario |

## Three Common Configuration Mistakes
-  When configuring `messages`, only passing historical text without binding `chatId`, which causes audit conversation contexts from different production devices to interfere with each other, resulting in cross-device data mixing.
-  Configuring the AI reply annotation of the dialogue component to trigger only after stream reply completion, which prevents real-time calls to DCS real-time data during the audit process, leading to returned annotation content lagging behind current production status.
-  After migrating the knowledge base, all text content is visible on the knowledge base page, but the model indicates the knowledge base is empty during dialogue. The cause is failure to configure `variables` to bind current associated raw material tank data, resulting in the retrieval scope not matching the migrated corresponding documents.

## How to Verify Correct Configuration
-  Initiate a test dialogue that includes the current shift and raw material batch, check whether the returned content includes real-time process parameters for the corresponding device.
-  Import migrated historical laboratory reports, initiate corresponding audit queries, confirm that the model can correctly retrieve document content.
-  Upload interlock bypass records in XLSX format, initiate a retrieval request, check whether content corresponding to the target interlock number can be extracted.
-  View the device number bound to `chatId`, confirm that conversation contexts from different devices do not interfere with each other.

The values provided are common starting points and should be measured against the reader's own samples.
