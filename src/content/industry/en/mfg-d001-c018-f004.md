# Supplier and Process Quality Audit for Continuous Basic Chemical Production: Workflow Orchestration

## What the data for this category looks like
Data sources for this category include DCS/SIS systems, online analyzers, LIMS laboratory management systems, equipment condition monitoring modules, energy metering devices, and raw material tank monitoring terminals. Data update rhythms are divided into real-time (such as reactor pressure and flow), shift-based (such as shift reports and special work tickets), and daily (such as lab reports and energy metering reports). Daily documents cover operating procedures, process index cards, DCS trend charts, lab test records, interlock bypass logs, special work permits, and shift operation daily reports. Fields include process parameters (units: MPa, ℃, m³/h), equipment runtime (unit: hours), tank liquid level (unit: meters), and more.

## What constraints do these characteristics impose on workflow orchestration
The data characteristics of this category impose clear constraints on workflow orchestration. Real-time process parameters require workflows to support high-frequency triggering to avoid node delays that affect abnormal response speed. Multi-source, multi-update frequency data must be accessed by category to prevent low-frequency data from repeatedly triggering processes and consuming resources. Documents with approval attributes such as interlock bypass records and special work tickets must have manual review nodes embedded to match on-site operation processes. Significant differences in field formats across different documents require a unified format conversion step to be configured in the workflow to adapt to subsequent quality audit logic. The steady-state maintenance requirement of continuous production requires workflows to link multiple process nodes to achieve automatic early warning and disposal linkage when parameters are abnormal.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Define groups by data source, including real-time parameter group, shift report parameter group, and lab test parameter group | Match the multi-update frequency data classification of this category, making it easy for workflows to trigger processes by group |
| Node timeout threshold | 300–600 seconds | Adapt to the response window requirements of real-time process parameters in this category, avoiding delays affecting abnormal disposal |
| `nodeId` | Assign a unique identifier to each process link node, categorized by reaction, separation, and circulation systems | Facilitate quick location of abnormal nodes and achieve precise interlock linkage control |
| Manual review node trigger condition | Trigger when interlock bypass records or special work tickets are detected | Match the approval process of on-site operations to ensure compliance |
| Variable mapping rule | Map DCS data to standardized process parameter fields, map LIMS data to test value fields | Unify the format of data from different sources to adapt to subsequent quality audit logic |

## Three Common Mistakes
- When text is concatenated with configured `variables` in a workflow, variable fields are empty in API call return results. The cause is that the parameter mapping of the corresponding data source is not correctly bound in the workflow's `variables` configuration, resulting in no valid variable values being passed during the call.
- When calling workflows concurrently, the front-end interface does not respond even though system resource usage is not exceeded. The cause is that no node concurrency limit is configured for the workflow, and a large number of parallel requests cause background task queue blocking.
- When configuring external interface calls in a workflow, interface calls fail due to incorrect passing of token parameters. The cause is that the corresponding variable is not defined in `variables` and bound to the external interface node, resulting in no valid identity credentials being carried during the call.

## How to Confirm the Configuration is Complete
- Trigger a workflow test to check whether real-time process parameters are correctly loaded according to the configured `variables` groups.
- Simulate abnormal parameter triggers to confirm whether the workflow node timeout threshold triggers interruptions or early warnings as preset.
- Submit interlock bypass record documents to confirm whether the manual review node is correctly triggered.
- Call the external interface for testing to confirm whether the parameters defined in `variables` are correctly passed to the target interface.

The values provided are common starting points and should be measured against the reader's own samples.
