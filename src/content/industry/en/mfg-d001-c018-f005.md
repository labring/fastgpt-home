# Supplier and Process Quality Audit for Basic Chemical Continuous Production: Tool Calling and Plugins

## What this category's data looks like
Data for this category primarily comes from DCS/SIS control systems, online process analyzers, LIMS laboratory information management systems, equipment condition monitoring systems, energy metering devices, and raw material tank data nodes. Daily supporting documents include process operation procedures, key process indicator cards, DCS real-time trend charts, raw material and finished product test reports, interlock bypass operation records, special work permits, and shift operation daily reports.

Data update frequencies cover real-time (such as DCS parameters), per-shift (such as shift reports, work permits), and daily (such as aggregated test data). Document fields include process control parameters, material component content, equipment operating status, work approval status, and more. Some parameters use industry-specific units including MPa, ℃, t/h, and ppm.

## What constraints these characteristics impose on tool calling and plugins
Data sources for this category are scattered, and update frequencies vary significantly. This requires tool calling to adapt to interface specifications for multiple types of data sources. Real-time data requires adaptation to short-cycle polling. Batch documents need support for scheduled pulling.

Daily documents in multiple formats require plugins to have targeted parsing capabilities. Examples include parsing approval fields in interlock bypass records and component content data in test reports. The business characteristic of strong interlock control requires tool calling results to have high confidence. This avoids impacting device stability due to parameter extraction errors.

The continuous operating nature of continuous production requires tool calling links to have low latency. This avoids interrupting quality audit processes due to call timeouts.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |

| Workflow/API tool selection | `required` | Force tool calling to trigger, ensure the audit process must obtain real-time process and supplier data, and comply with parameter rules for FastGPT v4.17.0 |
| Workflow/API function-call configuration | `enabled` | Enable function calling capabilities to support parsing of structured business documents and data |
| Plugin call timeout | `30 seconds` | Match the update cycle of real-time data for this category, avoid timeouts affecting stable operation of continuous production |
| Tool call retry count | `2 times` | Balance network fluctuation fault tolerance and call duration, avoid process interruptions caused by overly long retries |
| Real-time data pull interval | `60 seconds` | Cover the normal change cycle of key process parameters while controlling system load |
| Batch document parsing limit | `First 10 items` | Focus on core documents for this audit, avoid excessive data slowing down the calling link |

## Three common configuration mistakes
- Symptom: A parameter verification failure error is returned when calling the FastGPT OpenAPI chat interface. Cause: The `toolChoice` or `functionCall` parameters are not configured correctly, or the parameter values do not meet the mandatory requirements for tool calling in this category.
- Symptom: The content extraction node cannot connect to a self-built model interface. Cause: The custom model adaptation switch is not enabled in the system configuration, or the interface address of the self-built model is not added to the optional list of the corresponding node.
- Symptom: The internet plugin cannot pull external supplier qualification data normally. Cause: A domestically available proxy service is not configured, or the plugin's network request rules do not adapt to the domestic network environment.

## How to confirm the configuration is complete
- Initiate a tool calling test for a single batch of raw material supplier qualifications, check whether the preset tool calling output fields are included in the returned results.
- View system logs to confirm that the `toolChoice` and `functionCall` parameters have been correctly loaded, and there are no parameter verification failure records.
- Simulate a real-time process data pull request, check that the response duration of the tool call falls within the preset control range.
- Test the batch document parsing function, confirm that the parsed result fields cover the core business parameters required for this audit.
