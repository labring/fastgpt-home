# Supplier and Process Quality Audit for Basic Chemical Continuous Production: Citation Sources and Traceability

## What data for this category looks like
Typical enterprises in basic chemical continuous production include chlor-alkali, synthetic ammonia, methanol, and soda ash manufacturers. Daily documents cover operating procedures, process indicator cards, DCS trends, laboratory reports, interlock bypass records, special work permits, and shift logs. Data sources include DCS/SIS, online analyzers, LIMS, equipment status, energy metering, and raw material storage tanks. Update frequencies include real-time, per shift, and daily. Data fields include pressure, temperature, and flow units for process parameters, concentration and purity units for test results, and equipment operation status codes.

## What constraints these characteristics impose on the citation sources and traceability link
Multi-source real-time data and time-staged updated documents require the traceability system to accurately match citations by data collection time. This prevents invalid cross-timeframe associations.
The business characteristics of strong interlocks and hazardous media require that cited documents such as interlock bypass records and special work permits must precisely correspond to the audit period. No unrelated records may be included.
Structural differences across multiple document types require the traceability display to adapt to fields of different formats. For example, structured DCS trends must show timestamps and parameter values. Semi-structured work permits must show approvers and work times.
The characteristics of large-scale continuous production require the traceability data coverage to match the full process flow nodes. This avoids missing citations for critical links.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context | 8000–12000 token | The total length of process documents and real-time data for basic chemical production is long. This setting must cover the complete reaction, separation, and circulation system logic |
| `quoteMaxToken` | 1500–2000 token | A single traceability data entry must retain sufficient process parameter details. This prevents truncation of critical indicators and interlock information |
| Maximum Knowledge Base Citations | Top 6 entries | The core data sources for this category are concentrated in 6 types of systems including DCS and LIMS. Excessive citations will exceed context limits |
| Maximum Response Tokens | 3000–4000 token | Audit reports must include traceability information and process analysis. This setting reserves enough space to display complete content |
| `responseData` | Enabled | Full citation source metadata must be returned, including data collection time, affiliated system, and document type |
| `detail` | Enabled | Specific fields of traceability data must be displayed, such as concentration values from test results and real-time pressure values from DCS |

## Three Common Misconfigurations
- Issue: Red error markers appear in generated audit reports, and citation sources cannot be displayed normally. Cause: The `quoteMaxToken` parameter is not configured correctly. This causes the citation data to exceed token limits, triggering format verification failure.
- Issue: The returned citation list includes non-process-related documents such as administrative notices. Cause: Variables are not used to limit the data source scope of knowledge base searches. Documents from core systems such as DCS and LIMS are not filtered.
- Issue: Citation source information is not included in the response results after calling the interface. Cause: The `responseData` parameter is not enabled. The traceability data return function is not activated.
