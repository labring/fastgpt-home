# Supplier and Process Quality Audit for Basic Chemical Continuous Production: Knowledge Base Retrieval and Recall

## What data for this category looks like
Typical entities in basic chemical continuous production include chlor-alkali, synthetic ammonia, methanol, soda ash and other enterprises. Daily documents cover operating procedures, process index cards, DCS trends, laboratory reports, interlock bypass records, special work permits, and shift logs. Data sources include DCS/SIS, online analyzers, LIMS, equipment status, energy metering, and raw material storage tanks. Update frequencies range from real-time, per-shift, to daily. Documents include structured and unstructured content with diverse formats. Fields cover process parameters, laboratory concentrations, interlock trigger thresholds, and some fields have clear units.

## What constraints these characteristics impose on knowledge base retrieval and recall
This category’s data originates from multiple sources with widely varying update frequencies. Real-time generated DCS trends and daily updated laboratory reports must adapt to different index update rhythms, otherwise data lag or redundancy may occur. Document types are mixed and highly specialized, so retrieval logic must match both structured parameters and unstructured text. A single retrieval mode cannot cover all document types. Operation requirements for strong interlocks and process parameters demand high accuracy, so the relevance threshold for retrieval results must be strictly set. Low-relevance recalls may lead to misoperations. Additionally, data coverage is wide, and unrestricted retrieval can introduce irrelevant documents, increasing the screening workload for audit personnel.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Basic chemical processes and interlock parameters require high relevance. This range filters low-match irrelevant documents and avoids operational risks |
| `limit` | `Top 6–8 results` | Covers multiple core document types including process indicators, interlock records, and laboratory reports, while controlling the total context length |
| `searchMode` | `Hybrid retrieval` | Adapts to the dual needs of structured parameter matching and unstructured text retrieval, covering all document types |
| `usingReRank` | `Enabled` | Semantic differences between professional documents are large. Reranking further filters low-relevance results and improves the recall accuracy of key content |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Can expand professional terms such as process numbers and interlock codes into associated retrieval terms, covering more relevant documents |
| `collectionIds` | `Collection IDs grouped by document type` | Group DCS trends, laboratory reports, interlock records and other documents into separate collections to accurately limit the retrieval scope and avoid cross-type interference |

## Three Common Mistakes
- No return results when calling the knowledge base online, with the interface prompting that the retrieval scope is empty. The cause is incorrect configuration of `collectionIds`: the document collection for retrieval is not limited, so the system cannot find matching datasets.
- Newly uploaded DCS trend charts or real-time laboratory data cannot be retrieved. The cause is not using FastGPT v4.17.0 or a later version. Older versions only support full index updates and cannot synchronize real-time generated production data.
- Retrieval results have high deviation even though the knowledge base model is configured, with a large number of irrelevant documents appearing. The cause is that `usingReRank` is not enabled, the `similarity` threshold is set too low, and `datasetSearchUsingExtensionQuery` is not enabled, making it impossible to accurately match professional content.

## How to Confirm the Configuration Is Correct
- View the collection configuration of the dataset, confirm that `collectionIds` are grouped by document type and cover core documents required for the current audit, such as operating procedures and interlock records.
- Test retrieval of professional terms such as a specific interlock number or process parameter value, check whether the returned results include the corresponding interlock bypass record or process index card, and verify whether `searchMode` and `datasetSearchUsingExtensionQuery` are effective.
- Upload a new process index card, wait for the index to update, then retrieve the parameters on this card, confirm that the new data has been recalled, and verify that the real-time update configuration is correct.
- View the retrieval log, confirm that the `similarity` threshold and `limit` parameters have been applied, and the number of returned results matches the preset range.

The values provided here are common starting points and should be measured against the reader's own samples.
