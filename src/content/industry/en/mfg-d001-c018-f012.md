# Supplier and Process Quality Audit for Basic Chemical Continuous Production: Deployment and Upgrade

## What the data for this category looks like
Typical organizations are basic chemical enterprises including chlor-alkali, synthetic ammonia, methanol, and soda ash producers. Daily documents include operating procedures, process indicator cards, DCS trends, laboratory reports, interlock bypass records, special work permits, and shift reports. Data sources include DCS/SIS systems, online analyzers, LIMS systems, equipment condition monitoring, energy metering devices, and raw material storage tanks. Data update frequencies include real-time, per-shift, and daily. Document fields include pressure, temperature, concentration, interlock number, bypass time, and similar items, with corresponding units mostly being MPa, ℃, %, hours, and similar units.

## Constraints on deployment and upgrade processes
Multi-source real-time data and multiple types of business documents from basic chemical continuous production impose multiple constraints on deployment and upgrade work. Real-time DCS and online analyzer data require high-frequency synchronization. During the upgrade, the data link must remain uninterrupted to avoid disrupting stable device operation. Multi-data source docking must be compatible with proprietary protocols of existing enterprise LIMS and DCS systems. After the upgrade, each data source connection must be verified to function normally. Differences in the formats of multiple document types require re-adapting indexing rules after the upgrade to ensure all business documents can be correctly retrieved. In addition, storage permissions for documents related to hazardous media must retain their original configurations during the upgrade to avoid abnormal permission settings.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `STORAGE_S3_ENDPOINT` | `http://10.10.10.10:9000` (replace with the enterprise intranet S3-compatible storage address) | Adapt to industrial-grade S3 storage commonly used by basic chemical enterprises, ensuring stable upload of large files such as laboratory reports and DCS trends |
| `REDIS_URL` | `redis://:custom password@10.10.10.11:6379/0` | Cache real-time process indicator data to reduce high-frequency query pressure on DCS/SIS data sources |
| `DB_MAX_LINK` | `20–30` | Match concurrent connection requirements for multiple data sources, avoiding data synchronization interruptions caused by connection pool exhaustion |
| File upload timeout | 600 seconds | Adapt to upload durations of large DCS trend files and shift report archive packages, avoiding upload failures caused by large file sizes |
| Document chunk length | 800–1200 characters | Adapt to business documents of varying lengths such as process indicator cards and interlock bypass records |
| Number of retrieval context entries | Top 10 | Match retrieval requirements for batch documents such as shift reports and special work permits generated per shift |

## Three common misconfigurations
- After upgrading to FastGPT v4.17.0, the error `fail to create post presigned url` appears when uploading attachments. The cause is an incorrect `STORAGE_S3_ENDPOINT` configuration, or the S3 storage access permission configuration was not synchronized and updated after the upgrade.
- When calling the MCP tool, an error prompts that only stdio processes are supported, and connections encapsulated with the sse protocol cannot be recognized. The cause is that the default protocol configuration of MCP was reset to stdio mode after the upgrade, and the original sse configuration was not retained.
- After migrating the S3 storage, an error occurs when RAG uploads files, and the files cannot be stored normally. The cause is that the `FILE_TOKEN_KEY` configuration does not match the signature key of the S3 storage, or the `DB_MAX_LINK` setting is too low, causing connection pool overflow.

## How to confirm the configuration is correct
- Upload a simulated DCS trend CSV file, verify successful storage in S3 storage and generation of a retrieval index.
- Use the built-in data source testing tool to connect to the DCS/SIS system, verify real-time process data synchronization update frequency meets requirements.
- Check background logs to confirm no connection pool overflow errors related to `DB_MAX_LINK`, and no permission errors related to file uploads.
- Retrieve an uploaded interlock bypass record, confirm that fields in the search results match the original document, with no missing fields or format errors.

The values provided are common starting points and should be measured against the reader's own samples.
