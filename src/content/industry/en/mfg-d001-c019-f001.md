# Supplier and Process Quality Audit for Plastic Injection Molding: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
Data sources include resin batch property sheets, injection molding machine operating parameters, mold temperature controller monitoring data, workshop MES systems, and dimensional and appearance inspection equipment.
Data update points occur when each batch of raw materials enters the workshop, each mold and material change is completed, and at the end of each shift’s patrol inspection.
Daily documents include injection molding process cards, raw material drying records, mold history logs, first article inspection reports, production patrol inspection forms, and material change and machine cleaning records.
Fields include resin moisture content, mold cavity temperature (℃), filling duration (s), mold number, production batch number, and others. Data structures vary based on document type.

## What Constraints These Characteristics Impose on HTTP Interfaces and External Systems
High-frequency, clearly timed data updates require interfaces to support calls triggered by production nodes, to avoid invalid repeated requests.
Multi-source heterogeneous data formats require interfaces to support flexible field filtering and format parsing, to adapt to differences in return structures from injection molding machines, mold temperature controllers, MES systems, and other equipment.
Bulk quality inspection and process data require interfaces to support pagination or bulk data pulling, to reduce data transmission volume per request.
Strict quality control requirements mean interfaces must include exception retry and alert capabilities, to handle request failures caused by workshop network fluctuations or device offline status.
Production data sensitivity requires interface authentication configurations to comply with workshop industrial network security specifications, to prevent unauthorized access.

## How to Configure Settings

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| Authentication Method | `Authorization` header carrying Bearer token | Complies with general authentication specifications for industrial device interfaces, and adapts to the device access security requirements of injection molding workshops |
| Request Timeout | 30–60 seconds | Covers the average time required to pull injection molding process parameters and synchronize single-batch quality inspection data |
| Return Field Filtering | Only specify fields required for business purposes | Reduces data transmission volume, adapting to the limited network bandwidth of workshops |
| `variables` Parameter Binding | Bind production batch number and mold number variables | Accurately pull raw material, process, and quality inspection data for the corresponding production scenario |
| `responseData` Parsing Rule | Parse according to JSON array format | Adapts to the bulk data structure returned by most workshop MES systems |
| Retry Mechanism | Retry 2 times after failure, with a 5-second interval | Addresses temporary request interruptions caused by workshop network fluctuations |

## Three Common Configuration Mistakes
- Phenomenon: A 504 timeout status code displays on the interface when calling an external interface. Cause: The timeout period was not adjusted based on the volume of injection molding data being pulled, and the default timeout duration is insufficient to cover the transmission time of bulk quality inspection data.
- Phenomenon: The interface returns fields that do not match expectations, with redundant data. Cause: No return field filtering rules were configured, and full device log data was pulled directly, exceeding the scope required for business purposes.
- Phenomenon: The curl call to the interface responds quickly, but latency is noticeable when calling within FastGPT. Cause: No local caching rules were configured for the interface, and repeated pulling of the same injection molding process card data occupies request resources. At the same time, the request concurrency number was not adjusted, leading to queuing during high-frequency workshop requests.

## How to Confirm the Configuration Is Correct
- Execute a local curl command, carry the `Authorization` header to call the target interface, and confirm that the returned fields match the configured filtering rules.
- In the FastGPT test panel, bind the production batch number and mold number variables to initiate an interface call, and confirm that the returned data includes the raw material drying records corresponding to that batch.
- Simulate 10 high-frequency calls, observe that the interface response duration does not show significant fluctuations, and confirm that the retry and concurrency configurations are effective.
- Check the FastGPT v4.17.0 system logs, confirm that the `Authorization` authentication parameter for interface requests is correctly carried, and there are no parsing errors.
