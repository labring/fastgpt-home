# Supplier and Process Quality Audit for Plastic Injection Molding: Workflow Orchestration
This page is compatible with FastGPT v4.17.0

## Data Profile for This Category
Data sources for this category include resin batches and property sheets, injection molding machine parameters, mold temperature controller data, MES system records, and dimensional and appearance inspection results. Daily documents include injection molding process cards, raw material drying records, mold history logs, first article inspection reports, patrol inspection forms, and material change and machine cleaning records. Data is updated every production batch, each mold change or material change operation, and during shift handover. Document fields include resin batch number, mold temperature setpoint, injection pressure parameters, cooling duration, and others. Units include ℃, MPa, seconds, and others.

## Constraints Imposed on Workflow Orchestration
The high update frequency and scattered trigger scenarios of this category’s data require workflows to support triggering based on production batches, mold change operations, and shift handover nodes. The multi-source and heterogeneous data structure requires workflows to support `variables` configuration for custom field mapping, to adapt to specific fields such as resin batch number and mold temperature parameters. High-frequency data submissions during mass production require setting reasonable concurrency thresholds for workflow nodes to avoid single-node overload. Additionally, associated verification of quality inspection data and process parameters requires workflows to connect nodes from different data sources to ensure the continuity of audit logic.

## How to Configure
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Mode | Trigger based on production batches, mold change operations, and shift handover nodes | Matches the update rhythm of this category’s data |
| `variables` Configuration | Map resin batch number, mold temperature setpoint, and cooling duration fields | Adapts to specific data fields for injection molding processes |
| Concurrency Limit | 20–30 concurrent/ node | Matches the hardware carrying capacity of a single node |
| Node Timeout | 600 seconds | Covers the full cycle of a single injection molding process |
| JSON Input Box Variable Binding | Enable variable selection mode | Supports entry of audit parameters combining multiple fields |

## Three Common Misconfigurations
- Workflows return parameter errors when accessed via API. The cause is that required fields such as injection batch number and mold temperature parameters needed for API requests are not configured in `variables`, resulting in missing necessary parameters in the request body.
- Single nodes experience process crashes in high-concurrency scenarios. The cause is that a reasonable concurrency limit is not set, exceeding the carrying threshold of a 4c16g single node, leading to resource exhaustion.
- Variables cannot be selected in the JSON input box. The cause is that the variable binding switch for the JSON input box is not enabled, only supporting static JSON entry and unable to dynamically associate data source fields in the workflow.

## How to Verify Proper Configuration
- Manually trigger a workflow, check if documents such as the injection molding process card and raw material drying records for the corresponding batch are pulled.
- Adjust the concurrency parameters, use simulated traffic to test the node’s carrying capacity, and confirm that the single node runs stably.
- After configuring the JSON input box, attempt to select `variables` fields from the workflow, confirm that variables can be bound normally.
- Call the API interface, check if the returned results include the output of the preset audit verification logic.
