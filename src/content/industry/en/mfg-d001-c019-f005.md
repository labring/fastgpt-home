# Supplier and Process Quality Audit for Plastic Injection Molding: Tool Calling and Plugins

## What This Category’s Data Looks Like
Data sources for this category include resin batches and property sheets, injection molding machine operating parameters, mold temperature controller data, workshop MES systems, and dimensional and appearance inspection results. Updates occur every production batch, each mold or material change, and at the end of each shift. Daily documents include injection molding process cards, raw material drying records, mold history logs, first-piece inspection forms, production patrol forms, and material change and machine cleaning records. Fields covered include resin batch number, mold temperature (degrees Celsius), injection molding speed, dimensional tolerance (millimeters), production cycle (seconds), and more.

## Constraints Imposed on Tool Calling and Plugins
Data for this category updates frequently and is triggered by production nodes. This requires tool calling to be bound to specific production batches and mold or material change events, to avoid calling expired or unrelated production data. The presence of multiple types of daily documents requires plugins to support parsing files in different formats such as structured tables and log records. Dispersed data sources require plugins to implement multi-API docking to integrate data from injection molding machines, mold temperature controllers, MES systems, and other platforms. Specific unit requirements for fields mean plugins must include built-in format verification rules to ensure parameters passed to tools conform to standard injection molding industry formats. At the same time, quality audit errors can lead to batch defects or safety issues, so tool calling must be configured with failure retry and exception alert logic.

## Three Common Misconfigurations
- Phenomenon: The tool calling node returns the `Invalid JSON: Bad control character` error. Cause: When splicing parameters passed to the tool, control characters such as line breaks and tabs in injection molding process cards and drying records are not escaped, resulting in invalid JSON format.
- Phenomenon: The tool calling node cannot create connection lines, and no small circle controls for connection are displayed on the interface. Cause: The basic configuration of the tool calling node is not completed, or the edit activation state of the workflow is not enabled, causing interactive controls to be hidden.
- Phenomenon: The MCP-assisted model takes too long to process injection molding audit tasks, or detailed call logs for the MCP service cannot be viewed. Cause: The maximum thinking token count for the model is not limited, only the injection molding-related tool group is not called, or the log output level is not configured as detailed, causing the model to retrieve irrelevant content or lack log information.

## How to Confirm Configuration Is Complete
- Perform a tool calling test, check whether the returned JSON format is valid, with no parsing errors caused by control characters.
- Manually trigger tool calling, verify that it can correctly associate resin, mold, and injection molding machine data for the current production batch, and that returned fields include standard injection molding industry parameters.
- Simulate a network fluctuation, check whether the tool calling automatically retries according to the configured retry count, with no abnormal errors.
- View the workflow log panel, confirm that detailed parameters and return results of tool calls have been fully recorded.
