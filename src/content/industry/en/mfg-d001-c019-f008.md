# Supplier and Process Quality Audits for Plastic Injection Molding: Document Parsing and Chunking

This page is compatible with FastGPT v4.17.0.

## What the data for this category looks like
Typical documents for this category include injection molding process cards, raw material drying records, mold history logs, first-piece inspection reports, patrol inspection forms, and material change and machine cleaning records. Data sources include resin batch sheets and material property sheets, injection molding machine parameters, mold temperature controllers, MES systems, and dimensional and appearance inspection equipment. Data update frequency aligns with each production batch, each mold or material change, and each shift patrol inspection node. Documents include specific fields and units, such as mold temperature (℃), holding time (seconds), raw material moisture content, and mold usage count (times). Structured forms and process description text coexist within documents.

## What constraints do these characteristics impose on the "document parsing and chunking" step?
The mixed structure of documents requires parsing tools to support both structured forms and long-form process descriptions, and avoid splitting critical parameter groups. The presence of fixed fields and units requires chunking to retain the association between parameters and their units, preventing numerical values from being separated from their units after parsing. High-frequency data updates require chunking rules to match the length of different documents: short documents such as material change and machine cleaning records should not be over-split, while long documents such as cross-shift patrol inspection forms require reasonable chunk intervals. Differences in data formats across multiple sources require parsing tools to support multiple formats such as scanned PDFs and MES-exported CSV files, ensuring accurate content extraction from documents from different channels.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | Adapts to the field spacing of injection molding process cards and patrol inspection forms, avoiding splitting critical parameter groups such as filling, holding, and cooling windows |
| `chunkSplitter` | By paragraph + fixed character boundary | Balances structured form paragraphs and process description text, retaining complete batch information from raw material drying records |
| `customPdfParse` | Enabled | Adapts to text extraction from scanned mold history logs and first-piece inspection PDFs, restoring form fields and their corresponding values |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Accommodates single-batch resin property sheets and summary files of multiple sets of injection molding machine parameters |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time required for large mold history logs and cross-shift patrol summary files |
| `chunkSettingMode` | Manual configuration | Adjusts chunking parameters for different document types such as short forms and long process descriptions, matching data update frequencies |

## Three common configuration errors
- An error occurs during file upload and parsing after configuring the `CUSTOM_READ_FILE_URL` environment variable. The cause is that the variable is not configured in the correct format in config.json, preventing the parsing tool from reading local file paths.
- Some PDF files cannot be recognized. The cause is that `customPdfParse` is not enabled, text from scanned PDFs is not extracted correctly, or the document uses an encrypted format.
- The parsing result is empty after enabling file upload in a workflow. The cause is that document chunking rules are not matched, and long patrol inspection forms are over-split, leading to loss of key fields.

## How to confirm the configuration is complete
- Check the configured values of `UPLOAD_FILE_MAX_SIZE` and `PARSE_FILE_TIMEOUT_SECONDS` in config.json to ensure they match the local deployment's file storage capacity and parsing time.
- Upload a typical injection molding process card PDF, and verify that the parsed text retains parameters such as filling, holding, and cooling windows along with their corresponding units.
- Test uploading a scanned mold history log, and confirm that fields such as mold usage count and maintenance date can be extracted after `customPdfParse` is enabled.
- Verify multi-account team configurations, confirming that users can access shared injection molding document knowledge bases through a unified team entry.

The values provided are common starting points and should be measured against the reader's own samples.
