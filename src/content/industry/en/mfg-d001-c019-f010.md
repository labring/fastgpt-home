# Supplier and Process Quality Audit for Plastic Injection Molding: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Data for this category comes from resin batch property sheets, injection molding machine operating parameters, mold temperature collector data, production MES systems, and dimensional and appearance inspection reports. Daily documents include injection molding process cards, raw material drying records, mold history logs, first article inspection forms, patrol inspection forms, and material change and machine cleaning records. Data updates occur per production batch, each mold change or material swap, and at the end of each shift. Document fields include packing pressure (unit: megapascals), holding time (unit: seconds), mold temperature (unit: degrees Celsius), drying temperature, cumulative mold runs, and more. Fields across different documents have high correlation, requiring cross-document matching and verification to ensure production process consistency.

## Constraints on Knowledge Base Retrieval and Recall
Frequently updated production data requires the retrieval system to support near-real-time incremental indexing to avoid retrieving outdated data. Mixed storage of multiple document types requires the retrieval model to adapt to semantic matching across different formats, such as accurately associating defect descriptions in patrol inspection forms with adjustment methods in process cards. Fields with specific units require matching unit information during retrieval to prevent invalid results with mismatched mold temperature or pressure units. Cross-data source field association requires the retrieval system to support cross-document information integration, such as binding raw material drying records to parameters from injection molding process cards. Additionally, retrieval related to injection molding defects requires precise matching of process adjustment logic, without generalized retrieval of irrelevant content.

## Three Common Configuration Mistakes
- Model-related errors occur during search: the interface returns "model call timed out" or logs show "embedding request failed". The cause is failure to configure incremental synchronization for high-frequency updated injection molding data, leading to an overly large knowledge base index that triggers model resource overload.
- Retrieval results include irrelevant process documents, such as cross-linking and curing related content. The cause is failure to enable category-specific retrieval filtering, and failure to distinguish document features between injection molding and other categories.
- Retrieval results lack raw material drying records for the current batch, returning old data from 3 days prior. The cause is failure to configure a retrieval rule sorted by update time, and failure to enable the real-time update mechanism for incremental synchronization.

## How to Verify Proper Configuration
- An injection molding process card and a raw material drying record are uploaded, a query for "adjustment methods for shrinkage defects" is initiated, and retrieval results are confirmed to include the corresponding process parameters.
- The knowledge base's incremental synchronization logs are reviewed to confirm that index updates are completed within 10 minutes after each material change or batch production.
- A retrieval test is conducted by entering the query "injection molding process with mold temperature of 60 degrees Celsius", and retrieval results are confirmed to have mold temperature fields matching this unit.
- The FastGPT knowledge base configuration panel is accessed to confirm that `usingReRank` and `datasetSearchUsingExtensionQuery` are enabled.
