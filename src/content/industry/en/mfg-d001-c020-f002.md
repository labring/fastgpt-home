# Supplier and Process Quality Audit for Safety, Environmental Protection and Special Work Management: Vector Models and Indexes

## What Data Looks Like for This Category
This category of data comes from EHS departments and production inspection and maintenance teams of manufacturing enterprises in chemical, metallurgical, machinery and other industries. It covers documents including risk identification records, work permits for hot work, confined space work, hoisting and other operations, environmental monitoring records, hazardous waste ledgers, accident and hidden danger rectification reports. Data sources include industry regulations and standards, online environmental monitoring systems, gas detectors, personnel qualification files, equipment isolation lists and supervision platforms. Updates are triggered by work events, run in real time or per monitoring requirements, with regular inspections and ledger updates completed on a scheduled basis.

## What Constraints These Characteristics Impose on Vector Models and Indexing
Data sources for this category cover structured files, real-time monitoring data streams and unstructured operation documents. This requires vector indexes to support mixed retrieval of multiple data types. High-frequency update demands that indexes support incremental synchronization, avoiding the time cost of full reindexing. Highly compliance-focused documents such as work permits and rectification reports require precise matching during vector recall, so low-confidence result returns must be restricted. Operation-related documents include multi-dimensional fields such as operation type, personnel qualifications and monitoring values. Indexes must retain field-level associations to support precise filtering.

## How to Configure Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the average length of single documents such as work permits and monitoring records, avoiding splitting business logic across chunks |
| Overlap Length | 100–150 characters | Compensates for context breaks caused by chunking, ensuring semantic coherence of operation process text |
| Similarity Threshold | 0.75–0.85 | Matches the strong compliance retrieval requirements of this category, filtering low-confidence irrelevant risk records |
| Single Search Limit | Top 10 results | Limits the number of returned results, avoiding redundant information interfering with pre-operation risk identification |
| `maxToken` | 4096 token | Adapts to the average length of industry documents, ensuring complete recall of long texts such as rectification reports and regulatory citations |
| `defaultToken` | Set from representative sample documents | `defaultToken` is the default token count for direct text chunking; tune it on representative source documents. See the [v4.17.2 model-field reference](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx). It is not a vector dimension, embedding-model input cap, or retrieval/LLM context. |

## Three Common Configuration Mistakes
- Symptom: After manually inserted work permit documents generate a default index, the index disappears automatically after several hours. Cause: Incremental indexing persistent storage configuration is not enabled, causing temporarily cached index data to be automatically cleaned up.
- Symptom: Testing returns a 404 status code after configuring the embedding model API. Cause: The complete interface path for model calls is not filled correctly, or the corresponding API access permission is not enabled in platform permissions.
- Symptom: After replacing the embedding model, batch re-embedding is not performed on existing knowledge base documents, leading to a decline in recall rate for multilingual documents. Cause: The full reindexing process for the existing knowledge base is not triggered, and old embedding vectors are not replaced.

## How to Confirm Configuration Is Complete
- Upload a single work permit document, check whether the correct embedding model call information is displayed in the vector generation log.
- Perform a retrieval test for risk records, verify that the number of returned results matches the configured single search limit.
- Add a new hazardous waste ledger document, wait for the update to complete and verify that the index is retained normally.
- Adjust the similarity threshold, test whether the filtering effect of retrieval results meets business requirements.

The values provided are common starting points and should be measured against the reader's own samples.
