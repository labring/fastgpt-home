# Supplier and Process Quality Audit for Safety, Environmental Protection and Special Operations Management: Workflow Orchestration

## What data this category includes
Data sources for this category include regulatory standards, online environmental monitoring equipment, gas detectors, personnel qualification files, equipment isolation lists, and supervision platforms. Daily documents cover risk identification records, work permits for hot work, confined space work, lifting operations and similar tasks, on-site monitoring records, hazardous waste ledgers, emission monitoring reports, and accident and hidden danger rectification reports.
Update frequency follows three patterns: updated upon completion of each operation, updated in real time or per monitoring requirements, and updated via regular inspections.
Document fields include operation type, operation time, guardian qualification number, gas detection value, hazardous waste category, generation volume and more. Some fields use specific units, such as ppm or %LEL for gas detection values.

## What constraints these characteristics impose on workflow orchestration
Dispersed data sources and inconsistent update rhythms require workflows to support multiple trigger methods. This adaptation covers single operations, real-time monitoring, regular inspections and other update scenarios.
Many document fields have dedicated validation rules. Field validation nodes must be configured in workflows to ensure data such as qualifications and detection values meet requirements.
High-risk operation characteristics require workflows to set mandatory approval and exception reporting branches. This prevents non-compliant operations from being executed.
Cross-departmental collaboration needs require configuring node permissions. This limits the operating scope for different roles.

## How to configure
This document applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Trigger Method | Trigger by operation node event, or by operation ID passed via `variables` | Matches the single or real-time update characteristics of operations, avoids invalid polling |
| Node Timeout | 600 seconds | Fits the reasonable time required for on-site operations such as gas detection and qualification verification |
| Variable Binding Rule | Directly bind `variables` using operation document field names | Simplifies operation data flow and reduces format conversion errors |
| Exception Branch Configuration | Jump to approval node when detection value exceeds threshold | Aligns with high-risk rejection requirements in safety and environmental scenarios |
| Node ID Identification | Configure unique `nodeId` by operation type | Facilitates debugging and log tracing, distinguishes workflows for different operation scenarios |
| Permission Configuration | Only EHS departments can modify approval node status | Complies with permission control requirements for operation management |

## Three common misconfigurations
- Phenomenon: Code execution node returns execution failure logs, or node status is set to abnormal. Cause: Failed to pass on-site equipment interface keys, detection thresholds and other operation-required parameters via `variables`, or node timeout setting does not match on-site operation duration.
- Phenomenon: HTTP request node body parameter is empty, or operation-related data fails to load correctly. Cause: Failed to bind fields from work permits and monitoring records to `variables`, or failed to correctly reference variable names in request configurations.
- Phenomenon: Workflow cannot distinguish uploaded images from other file formats, causing subsequent validation nodes to trigger incorrectly. Cause: No file type validation logic configured, or failed to extract file suffix names via `variables` for branch jumping.

## How to verify successful configuration
- Trigger test: Manually submit a simulated work permit. Check if the workflow starts corresponding nodes per the configured trigger rules.
- Variable validation: View the `variables` in the workflow debugging panel. Confirm they correctly load operation-related fields, and verify the variable reference format for the HTTP request body is correct.
- Exception branch verification: Simulate a high-risk scenario, such as gas detection value exceeding thresholds. Check if the workflow jumps to the preset approval or reporting node.
- Permission verification: Use an account from a non-EHS department to attempt modifying approval node status. Confirm the permission configuration takes effect.

The values provided are common starting points and should be measured against the reader's own samples.
