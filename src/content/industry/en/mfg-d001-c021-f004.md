# Supplier and Process Quality Audit for Furniture and Wood Product Manufacturing: Workflow Orchestration

## What Data Looks Like for This Category
This category primarily covers panel furniture, solid wood furniture, custom home and door manufacturers. Core daily documents include order breakdown drawings, cutting lists, edge banding and drilling programs, coating process documents, hardware bill of materials, and assembly and packaging records. Data is mainly sourced from order design systems, panel and wood batch ledgers, CNC cutting/drilling equipment, ERP/MES systems, and moisture content testing equipment. Update frequencies vary with business nodes, including three rhythms: per order, daily, and per material batch. Fields include panel size, material color code, hardware model, moisture content indicators, and some documents require association with on-site installation space parameters.

## Constraints These Characteristics Impose on Workflow Orchestration
Custom order-driven business models require workflows to support flexible binding and updating of multi-dimensional variables. Dispersed multi-source data from numerous panels requires workflows to integrate multi-node data validation and transfer logic. High-frequency data update cycles require workflow triggers to match actual business node rhythms, avoiding delayed or duplicate execution. High precision requirements for fields such as panel size and color code require workflows to have strict parameter validation rules to prevent erroneous data from entering subsequent processes. Additionally, the requirement to associate on-site installation space means workflows must synchronously extract space parameters from design and production ends for verification.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger node timing | Within 10 minutes after order creation | Matches the rapid audit needs of custom furniture orders, avoiding process delays that impact production scheduling |
| Variable mapping rules | Bind order ID and panel batch number from `variables` | Enables traceability correlation between order design, production data and quality inspection data, ensuring accurate audit basis |
| Node timeout period | 600 seconds | Covers processing duration requirements for parsing multiple types of documents including order breakdown drawings, cutting lists, and edge banding programs |
| File upload parameters | Support local file upload, maximum 1000 MB | Adapts to upload needs for large-volume documents such as order breakdown drawings and process documents |
| Number of documents parsed per run | First 200 | Adapts to the number of documents for multiple panels in a single custom order, avoiding node overload |
| Variable update synchronization rule | Execute updates in `nodeId` order | Prevents data conflicts caused by parallel updates across multiple nodes, ensuring consistent variable status |

## Three Common Mistakes
- Phenomenon: Unable to select a configured production quality audit model in the workflow editor; the model list is empty. Cause: The model is not bound to the permission scope of the corresponding workflow, or the workflow version does not match the model configuration version.
- Phenomenon: When calling an upload file via a custom tool, local file paths from `variables` cannot be referenced, only external links are supported. Cause: Local file upload permission for the workflow is not enabled, or the tool parameters are not configured to support variable binding.
- Phenomenon: After a multi-variable update node is executed, the AI reply does not include all updated field data. Cause: The variable update node did not execute in order, or the updated variables were not connected to the context of the AI reply node.

## How to Confirm Proper Configuration
- Trigger a test order under FastGPT v4.17.0, check the workflow log to confirm all nodes start as expected and complete data transfer.
- Upload test order breakdown drawings and cutting lists, verify that the file parsing node can correctly extract core fields such as panel size and material color code.
- Call a custom tool to upload a local test file, confirm that the order number parameter from `variables` can be referenced to complete binding.
- Configure and execute a multi-variable update node, check the AI reply content to confirm all updated fields are fully included.
