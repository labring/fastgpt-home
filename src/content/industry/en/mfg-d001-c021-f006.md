# Supplier and Process Quality Audit for Furniture and Wood Product Manufacturing: Citation Sources and Traceability

## What the Data for This Category Looks Like
This category covers panel furniture, solid wood furniture, custom home and door manufacturers. Core daily documents include personalized order disassembly drawings, CNC cutting lists, edge banding and drilling programs, coating process specifications, hardware bill of materials, and assembly and packaging records. Data originates from order design systems, sheet and wood batch ledgers, CNC processing equipment, ERP/MES systems, and moisture content test records. Update schedules adjust in real time alongside order generation, daily inspections, and material batch deliveries.

## Constraints on Citation Sources and Traceability
This category includes multiple types of structured and semi-structured documents. These documents contain fields such as size parameters and batch numbers. The traceability link must accurately match exclusive information. Frequently updated order and batch data requires the traceability link to support real-time synchronization of the latest sheet moisture content, cutting programs, and other details. The custom order-driven multi-part production mode means knowledge base recall entries must cover full link data for a single order. This prevents missing key associated content. It also ensures citations directly correspond to specific nodes in the production chain.

## How to Configure
The following configuration items apply to FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the total character count of single-order disassembly drawings and cutting lists, to avoid truncating critical size and batch information |
| Single search limit | Top 8–12 entries | Covers core production documents for a single order, to avoid redundant data interfering with model judgment |
| Recall similarity threshold | 0.75–0.85 | Accurately matches exclusive fields in disassembly drawings and cutting lists, filters irrelevant documents |
| Data sync trigger rule | Triggered by order/batch | Matches the rhythm of frequently updated production data for this category |
| `detail` | Enabled | Displays full fields of traceable documents, such as material moisture content, cutting program version |
| `responseData` | Enabled | Outputs metadata of traceable documents, to facilitate associating production nodes during audit |

## Three Common Configuration Errors
1. Phenomenon: After increasing the `quoteMaxToken` parameter, the model’s generated response does not include any citation content. System logs show normal recall entries. Cause: The parameter value exceeds the actual carrying limit of the model’s context window, causing citation fragments to be automatically filtered.
2. Phenomenon: Local testing shows normal citation, but traceability content cannot be returned via external API calls. Cause: The `responseData` switch is not enabled, or the release channel has not been configured with metadata output permissions.
3. Phenomenon: Citation content does not match the fields of actual production documents. Size deviations or batch number errors appear. Cause: The recall similarity threshold is set too low, introducing irrelevant document fragments, or the knowledge base is not divided by order dimensions.

## How to Confirm Proper Configuration
- Initiate a quality audit query related to a single order. Check the traceability list at the end of the response, and confirm that corresponding documents such as disassembly drawings and cutting lists are included.
- Enter the system log page. Check whether full metadata of traceable documents is output, such as material batch numbers, cutting program versions.
- Adjust the `quoteMaxToken` parameter. Verify that the length of content cited in the response matches the set value range, with no truncation.
- Switch to an external API call channel. Confirm that the returned results include traceability-related fields, consistent with local test results.

The values provided are common starting points and should be evaluated against the sample data relevant to the specific use case.
