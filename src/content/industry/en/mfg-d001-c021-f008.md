# Supplier and Process Quality Audit for Furniture and Wood Product Manufacturing: Document Parsing and Chunking

## What Data Looks Like for This Category
It typically covers production-related data for panel furniture, solid wood furniture, custom home goods, and wooden door enterprises. Daily documents include order breakdown drawings, cutting lists, edge banding and drilling programs, coating process documents, hardware material lists, trial assembly and packaging records. Data sources include order design systems, sheet and wood batch ledgers, CNC machining equipment, ERP/MES systems, and moisture content testing equipment. Update frequency aligns with orders, daily cycles, or per batch of materials. Document structures include structured parameter lists, drawings with vector layers, and step-by-step process descriptions. Fields include panel specification dimensions, material batch numbers, process parameters, test results, and additional relevant details.

## What Constraints These Characteristics Impose on the Document Parsing and Chunking Link
Personalized order-driven document formats are inconsistent. The structure of order breakdown drawings and cutting lists varies per order. This requires chunking rules with flexible adaptability to avoid fixed templates that cannot accommodate custom content. Heterogeneous document types coexist: plain text lists and PDF drawings with vector layers. Different parsing logic must be supported to retain key information. Frequently updated documents need support for batch rapid processing to match per-order, daily, or per-batch update rhythms. Associated fields such as panel dimensions and hardware lists must be fully retained in the same chunk. Splitting these fields would break the connection between panels and corresponding processes or test results, harming traceability for subsequent quality audits.

## How to Set the Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the typical length of panel lists and process steps in furniture documents, avoiding splitting content that links panel specifications and corresponding parameters |
| `chunkSplitter` | Custom separator based on paragraphs + `[Panel ID]` | Adapts to the structured layout of order breakdown drawings and cutting lists, ensuring complete information for each panel is retained in the same chunk |
| `customPdfParse` | Enabled | Used to parse PDF drawings with vector layers such as order breakdown drawings and edge banding programs, retaining layer hierarchy and annotation information |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing time required for large multi-page cutting lists and batch process documents, avoiding parsing failures due to timeout |
| `chunkSettingMode` | Manual configuration | For customized order documents, prevents automatic chunking from breaking the association of key traceability fields such as order numbers and material batch numbers |

## Three Common Mistakes
- Phenomenon: Parsing fails after enabling `customPdfParse`, returning status code 500. Cause: The vector layer format of furniture PDFs is not adapted, and the default parsing rules cannot recognize panel ID annotations in breakdown drawings.
- Phenomenon: Panel dimensions and corresponding hole position programs are split into different chunks in the chunking result. Cause: `chunkSplitter` is not configured with `[Panel ID]` as the custom separator, and only uses the default paragraph-based splitting rules.
- Phenomenon: Timeout is triggered when batch parsing synchronous documents. Cause: The value set for `PARSE_FILE_TIMEOUT_SECONDS` is lower than the actual parsing time required for multi-page process documents, and does not match the pressure of batch processing.

## How to Confirm the Configuration Is Correct
- Upload a single custom order's order breakdown drawing PDF, check if the parsed chunks include complete panel IDs, dimensions, and corresponding hole position program content.
- Check the parsing logs in FastGPT v4.17.0, confirm that the `customPdfParse` parameter has taken effect, and there are no error messages about failed vector layer parsing.
- Batch upload cutting lists from the same batch, check that the number of chunks matches the number of order panels, with no duplicate or missing chunked content.
- Call the API interface to pull the uploaded document library, confirm that the returned chunked content includes key traceability fields such as order numbers and material batch numbers.
