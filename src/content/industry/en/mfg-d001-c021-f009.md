# Supplier and Process Quality Audit for Furniture and Wood Products Manufacturing: Model Integration and Configuration

## What data for this category looks like
Data for this category primarily comes from order design systems, sheet material and wood batch ledgers, CNC cutting and drilling equipment logs, ERP/MES systems, and moisture content testing equipment. Daily documents include custom cut lists, cutting lists, edge banding and drilling programs, coating process documents, hardware bill of materials, assembly and packaging records.
Data update cadence changes with orders, daily, or per material batch. Each order links to a large volume of panel data, with fields including dimensions, material batch, moisture content, hole position parameters, etc. These data typically do not have a unified, fixed standardized BOM structure.

## What constraints these characteristics impose on model integration and configuration
The personalized order-driven nature of this category requires model integration to adapt to non-standard cut lists, cutting documents, and similar materials. Multi-source batch data update cadence requires associating data timestamps during configuration to avoid calling expired parameters. The large volume of panel data linked to a single order requires limiting the token limit per request to prevent model processing overload. High-frequency log data from on-site equipment requires configuring a reasonable context window length to ensure only the latest production parameters are loaded during calls. For FastGPT v4.17.0, additional attention must be paid to adapting to enterprise internal data isolation requirements to prevent sensitive production parameters from being leaked.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `maxContext` | 800–1200 characters | Adapts to the total volume of documents for single orders with multiple panels in this category, prevents context overflow |
| `maxTokens` | 4000–8000 token | Matches the multi-document parsing requirements of custom furniture orders, balances processing speed and content completeness |
| `quoteMaxToken` | 1500–2000 token | Limits the total token count of recalled documents, ensures core cutting and hardware parameters are prioritized for model reading |
| `temperature` | 0.2–0.4 | Maintains consistency of audit results, avoids random deviations in process parameters or dimensions |
| `AIPROXY_API_ENDPOINT` | Enter the locally deployed proxy address | Adapts to enterprise internal data isolation requirements, prevents sensitive production data from being leaked |
| `AIPROXY_API_TOKEN` | Use an enterprise-specific authentication key | Ensures security of model calls, restricts unauthorized access |

## Three common configuration errors
- Phenomenon: After deploying FastGPT v4.17.0 locally, the configured external model does not appear in the available model list. Cause: `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are not filled correctly, or the proxy service fails to respond to authentication requests.
- Phenomenon: When multiple model nodes are orchestrated in a workflow, audit results for different orders show parameter confusion. Cause: The single-order context range is not limited via `maxContext`, leading to cross-order production data being loaded together.
- Phenomenon: Model calls return timeout prompts, and logs show request duration exceeds 300 seconds. Cause: `maxTokens` value exceeds the processing limit of the model service, or a reasonable request timeout policy is not configured.

## How to confirm configuration is complete
- Access the model channel management page in the FastGPT backend, confirm that the filled `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` match the proxy service deployed internally within the enterprise.
- Upload the cut list, cutting list, and hardware list for a single custom furniture order, trigger model audit, check if the returned results cover all core production parameters for that order.
- Orchestrate two independent model audit nodes in a workflow, associate each with different material batches, confirm that the audit results for the two nodes do not show parameter confusion.
- View detailed model call logs, confirm that the context length and token limit for each request match the preset configuration, with no error messages indicating exceeded limits.

The values provided are common starting points and should be evaluated against local deployment samples.
