# Supplier and Process Quality Audit for Household Appliance Finished Goods Manufacturing: Multi-turn Dialogue and Prompt Words

## What the data for this category looks like
The main entities in this category are air conditioner, refrigerator, washing machine, and small household appliance manufacturers. Daily documents include bill of materials (BOM), assembly work instructions, refrigerant charging records, electrical safety test reports, performance spot check reports, and rework records. Data sources cover ERP/MES systems, component batch ledgers, tightening and charging equipment, safety compliance testers, performance laboratories, and after-sales fault databases. Update frequencies follow per single device, per shift, and per spot check plan. Document fields include material code, batch number, charging pressure, test voltage, rework number, and others. Corresponding units include megapascals, volts, hours, and additional standard units.

## What constraints these characteristics impose on the multi-turn dialogue and prompt words link
Multiple heterogeneous data sources and differentiated update frequencies require dialogue context to accurately carry audit-related information for a single device or single batch, to avoid mixing cross-batch data. Multi-dimensional audit scenarios (safety compliance, performance, rework) require prompt words to clearly distinguish field rules for different documents, ensuring the dialogue matches the BOM and assembly requirements for the corresponding model. Mixed-line assembly production modes require the dialogue to dynamically associate component batch information for the current workstation, to prevent incorrect or missing installations. Frequently updated equipment and test data require limiting invalid history in the context window, to avoid redundant information interfering with current audit judgments.

## How to configure the setup
This configuration is based on FastGPT v4.17.0. Specific configuration items are listed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `messages` | Limit context to 800–1200 preceding characters | Adapt to the length of multi-stage documents for single-device audits, avoid context overload |
| `variables` | Bind the component batch number for the current workstation | Associate batch data in ERP/MES systems, ensure audits match corresponding component information |
| `chatId` | Bind the session ID for the current audit batch | Differentiate audit dialogues for different workstations, avoid session confusion |
| Maximum single dialogue turns | Top 6 turns | Cover the full process from supplier qualification audit to on-site process spot check |
| Historical message filtering | Only retain dialogue logs from the last 24 hours | Adapt to per-shift update frequency, exclude expired non-current-day audit data |
| Prompt word template configuration | Split by audit type (safety compliance/performance/rework) | Match document field rules for multi-dimensional audits, clarify judgment standards for different scenarios |

## Three common misconfigurations
- Phenomenon: Current auditor identity identification is missing from dialogue logs, with empty fields. Cause: User identity information is not bound via the `variables` parameter, resulting in inability to record the audit subject in logs.
- Phenomenon: Response lag occurs after multiple turns of dialogue, with no results returned after more than 10 seconds. Cause: Maximum single dialogue turns are not limited, leading to the context window loading excessive redundant historical audit data.
- Phenomenon: The dialogue fails to correctly match BOM data for the current model, resulting in incorrect installation suggestions. Cause: Prompt word templates are not split by audit type, confusing assembly rules for different household appliance models.

## How to verify successful configuration
- Launch a supplier qualification audit dialogue, check if the component batch information for the current workstation is automatically associated in the dialogue, verify that the `variables` parameter binding takes effect.
- View the dialogue context window, confirm that only historical logs from the last 24 hours are retained, with no expired cross-batch audit data.
- Launch multiple consecutive audit dialogues, check if response times meet expectations, with no obvious lag.
- Call the safety compliance audit prompt word template, confirm that the dialogue can correctly extract voltage parameters from electrical safety test reports.
