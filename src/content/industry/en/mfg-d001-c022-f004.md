# Supplier and Process Quality Audit for Complete Home Appliance Manufacturing: Workflow Orchestration

## What the data for this category looks like
Daily documents for complete home appliance manufacturing include configuration BOM, assembly work instructions, refrigerant charging records, electrical safety test reports, performance sampling inspection reports, and rework records. Data sources cover ERP/MES systems, component batch ledgers, tightening and charging equipment, safety compliance testers, performance laboratory equipment, and after-sales fault databases. Data updates follow the cadence of single product, shift production batch, or sampling plan. Data related to a single product includes fields such as component batch number, tightening torque value, charging volume, safety test voltage value, and performance test noise value. The unit of each field varies by test item, with no unified fixed standard.

## What constraints these characteristics impose on workflow orchestration
Multi-source heterogeneous data sources for this category require workflows to configure different access nodes based on data type. This avoids format conflicts between data collected by different equipment. High-frequency update cadence requires workflows to support event triggering. This adapts to real-time trigger scenarios such as completion of a single product or end of a shift batch, without relying on fixed periodic polling. The mixed-line assembly production mode for multiple models requires workflow variables to be isolated by task. This prevents confusion of production parameters for different models. The verification priority of key test data such as safety compliance and performance requires workflows to configure pre-verification nodes. This ensures unqualified data cannot enter subsequent audit links and reduces batch risks.

## How to set the configuration

| --- | --- | --- |
| `variables` | Isolate scope per single audit task and supplier ID | Adapt to the variable isolation requirement for mixed-line production of multiple models, avoid parameter confusion between different users or batches |
| Node Trigger Timing | Trigger on component batch completion event | Match the update cadence of data per single product or shift, ensure the audit process syncs with production beat |
| Knowledge Base Association Configuration | Bind safety compliance and performance sampling inspection data sets for the corresponding model | Match the characteristic that daily documents include electrical safety test and performance sampling inspection reports, ensure accurate retrieved data |
| `nodeId` | Specify the IDs of the three core nodes: safety compliance verification, charging verification, and performance test verification | Prioritize high-risk links, ensure the verification priority of key processes |
| Global Variable Binding | Bind datasetid to the `variables` parameter of the corresponding retrieval node | Solve the problem that global variables cannot be referenced in retrieval nodes, adapt to the switching requirement of multiple model data sets |
| Timeout Threshold | 600 seconds | Match the return cycle of safety compliance test data, avoid workflow interruption due to equipment response delay |

## Three Common Mistakes
- Phenomenon: Value confusion occurs when different user IDs use the same `variables` name in the workflow. Cause: The variable scope is not configured as a single audit task, causing variables to be shared globally.
- Phenomenon: When testing a workflow based on question classification, only the first question triggers knowledge base retrieval, and subsequent questions have no results. Cause: Context variables are not reset after the classification node, causing subsequent retrieval to fail to match the corresponding data set.
- Phenomenon: The global variable datasetid is set but cannot be referenced by the knowledge base retrieval node. Cause: The global variable is not bound to the `variables` parameter of the retrieval node, causing the variable to not be passed to the target node.

## How to Confirm the Configuration is Correct
- Submit audit tasks for complete home appliances of different models, check whether the `variables` parameters are isolated per task, and no cross-confusion of variable values between different tasks occurs.
- Trigger multi-round classification questions, check whether the knowledge base retrieval of the corresponding model is correctly triggered after each classification node, and confirm that the retrieval results match the questions.
- View node logs, confirm that the global variable datasetid has been correctly passed to the knowledge base retrieval node, with no null or incorrect values.
- Simulate the upload of safety compliance test data, check whether the pre-verification node is triggered as configured, and whether unqualified data is intercepted.
