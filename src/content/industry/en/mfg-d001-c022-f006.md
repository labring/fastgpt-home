# Supplier and Process Quality Audit for Complete Household Appliance Manufacturing: Citation Sources and Traceability
## What the Data for This Category Looks Like
This category covers complete unit manufacturing of air conditioners, refrigerators, washing machines, and small home appliances. Daily documents include configured BOMs, assembly work instructions, refrigerant charging records, electrical safety test reports, performance spot check reports, and rework records. Data sources cover ERP/MES systems, component batch ledgers, tightening and charging equipment logs, safety tester data, performance lab test results, and after-sales fault records. Data updates follow per-unit product, shift production batch, or spot check schedule. Each data entry includes fields such as component number, process parameters, test results, and batch identifier.

## Constraints on Citation Sources and Traceability
The mixed-model mixed-line assembly production mode requires precise binding of component batches, process parameters, and test results to individual products during traceability, to avoid mixing data from different models. High-frequency updated per-unit and shift production data requires the traceability chain to quickly locate all records for the corresponding production batch, preventing cross-batch data from interfering with audit judgments. Multi-source data covering equipment logs, system ledgers, and after-sales records requires unified citation rules to ensure traceability can reversely link full-link data from production to after-sales. Strict compliance requirements for safety and performance testing mean the traceability link must clearly identify the credibility of citation sources, to avoid invalid or incorrect data being included in audit judgments.

## Three Common Configuration Errors
- Symptom: When configuring citation traceability, no optional values are available for variable references after selecting the target knowledge base. Cause: Core business fields such as component batches and equipment numbers have not been configured as referenceable metadata for the knowledge base, or metadata has not been correctly bound to uploaded documents such as BOMs and test reports.
- Symptom: A `Cannot redefine property: toString` error occurs during online operation. Cause: The `toString` method has been repeatedly defined in a custom traceability node, or an introduced external dependency conflicts with the built-in tool method of FastGPT v4.17.0.
- Symptom: Cited traceability data includes document content from non-target models. Cause: No filtering rules based on product model and production batch have been set, resulting in simultaneous retrieval and return of multi-model data in mixed-line assembly scenarios.

## How to Verify Successful Configuration
- Upload the assembly work instruction and refrigerant charging record for a single home appliance, trigger a traceability request, and check if the returned citation sources include the document's metadata fields.
- Enter search keywords for a specified component batch, verify that the returned cited data only links to production and test records for that batch, with no cross-model data included.
- View the system-generated citation log, confirm that each cited entry includes the document path, generation time, and equipment number, matching the configured requirements.
- Run a traceability process that pulls multi-source data, confirm that the request does not time out, and that the number of returned citations complies with the preset single search limit rule.
