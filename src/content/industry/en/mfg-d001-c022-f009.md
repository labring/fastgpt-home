# Supplier and Process Quality Audit for Complete Home Appliance Manufacturing: Model Access and Configuration

## What the data for this product category looks like
Data for this category covers configuration BOMs, assembly work instructions, refrigerant charging records, electrical safety test reports, performance spot check reports, and rework records related to the production of air conditioners, refrigerators, washing machines, and small home appliances.
Data sources include ERP/MES systems, component batch ledgers, tightening and charging equipment logs, safety compliance testers, performance laboratory data, and after-sales fault archives.
Updates are performed per single product, per shift operation, or per spot check plan.
Each individual data entry includes fields such as component model, process parameters, test results, and batch number. The number and length of fields vary by document type.

## What constraints do these characteristics impose on model access and configuration
The mixed-line assembly of multiple product models requires the model to support rapid identification of multiple batches and heterogeneous documents of multiple models. Model access must therefore support compatibility with data sources in different formats.
High-frequency updated real-time process and test data requires the context window to adapt to short-term, high-frequency content synchronization, preventing audit failure caused by context overflow.
Strict compliance requirements for safety and performance tests require the model to accurately match specific fields in documents, such as refrigerant charging volume and insulation resistance value. Model configuration must therefore prioritize field recall accuracy.
The intranet deployment scenario restricts external interface calls. Local model access parameters must be configured, and a fault tolerance mechanism for database connection exceptions must be implemented.

## How to set the configuration
This configuration is based on FastGPT v4.17.0. Details are listed below:

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the multi-document context requirements of mixed-line assembly for multiple product batches, covering the BOM, process, and test data required for a single audit |
| `maxTokens` | 2000–3000 token | Controls the output length of a single audit result, adapting to the structured judgment requirements for safety and performance anomalies |
| `quoteMaxToken` | 1500–2000 characters | Limits the total length of referenced documents, to avoid model inference timeouts caused by overly long references |
| `temperature` | 0.1–0.3 | Reduces randomness, ensures consistency of safety and performance judgments, and meets the rigor requirements of compliance audits |
| `AIPROXY_API_ENDPOINT` | Intranet-deployed FastGPT proxy address | Adapts to model calls in an intranet environment, avoiding external network restrictions |
| `AIPROXY_API_TOKEN` | Token generated according to intranet authentication rules | Ensures access permission security for intranet model calls |

## Three common configuration mistakes
- The symptom is a model call returning a database connection refused error, with logs showing port unresponsiveness. The cause is failure to specify the correct intranet MySQL address and port in the configuration, preventing retrieval of supplier ledger data.
- The symptom is incorrect judgment of mixed-model assembly in audit results. The cause is that `maxContext` is set too small, failing to cover all BOM and process documents for the current batch, leaving the model unable to distinguish component model requirements for different products.
- The symptom is empty field matches for safety compliance test results. The cause is that `quoteMaxToken` is set too large, preventing the model from accurately locating specific test parameters in documents, leading to failed compliance judgments.

## How to confirm the configuration is correct
- Call the test interface, input the BOM and safety compliance test data for a single home appliance, and check whether the returned audit result includes matching content for the corresponding fields.
- View system logs to confirm there are no timeout or refused error messages for model call database connections, verifying interface connectivity in the intranet environment.
- Import test documents for mixed-line assembly of multiple product models, and check whether the model can correctly distinguish components and process requirements for different batches.
- Adjust the `temperature` parameter, compare the consistency of two audit results, and confirm the stability of compliance judgments.

The values given are common starting points and should be measured against the reader's own samples.
