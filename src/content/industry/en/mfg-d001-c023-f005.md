# Supplier and Process Quality Audit for Industrial Instrument Manufacturing and Calibration: Tool Calling and Plugins

## What the Data for This Category Looks Like
Core data for industrial instrument manufacturing and calibration is generated across the full calibration lifecycle of a single tested device. Data sources include design documents, standard instrument monitoring data, calibration software outputs, laboratory information system records, and customer range requirement documents. Data is updated once per calibration for each device. Daily generated documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, calibration certificates, and software version logs. Fields include tested part number, standard instrument number, ambient temperature (℃), error value (ppm), traceability number, calibration date, and expiration date. Some documents include visualized error curve data.

## How These Characteristics Impact Tool Calling and Plugins
Data sources for this category are distributed across multiple independent systems. Tool calling must support integration with multiple data sources such as calibration software and laboratory information systems to eliminate data silos. Data updates are tied to one calibration run per device. Tool calling must support on-demand triggering to ensure access to the most recent calibration data. Documents contain both structured fields and visualized curves. Plugins must support parsing unstructured PDF calibration certificates and error curves to extract key traceability information. Fields must adhere to metrology specifications. Tool calling must validate unit formats and field completeness to prevent failed audits caused by data errors.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | Auto-match or specify calibration audit tools | Must automatically select data parsing and error validation tools based on audit scenarios, or fixed call preset calibration audit plugins |
| Maximum document parsing character count | `8000–12000 characters` | Calibration certificates and error curve documents typically fall within this length range, preventing truncation of core information such as key traceability numbers and error values |
| Workflow/API function-call configuration | Enable forced function calling | Audit processes require fixed calls to calibration data validation and traceability chain query tools, preventing the model from freely generating results that do not meet metrology specifications |
| Number of results returned | `Top 3–5 entries` | Audit processes only require core calibration record data. Excessive data increases model processing load |
| Call timeout | `600 seconds` | The process of establishing connections between standard instruments and tested devices and collecting multiple-point error data takes a long time. Sufficient interface call time must be reserved |
| Result validation rules | Validate traceability numbers and error value units | Data for this category must meet metrological traceability requirements. Incorrect field formats will invalidate calibration certificates and cause audit failures |

## Three Common Errors
- Symptom: A parameter error prompt appears when calling a multimodal model, and interface logs show format incompatibility. Cause: Protocol adaptation rules for tool calling are not correctly configured, and the input parameter format of the multimodal model is not aligned with the calling requirements of FastGPT plugins.
- Symptom: The "Unsaved" prompt remains displayed in the upper right corner of the plugin editing page, and a prompt of no changes appears after clicking the save button. Cause: A known issue with delayed plugin save status synchronization exists in FastGPT v4.17.0. Subsequent operations are performed without waiting for page status to refresh.
- Symptom: The reranker plugin returns a result of false, with no valid parsed content. Cause: The input text length threshold for the reranker is not configured. Long documents such as complete error curves exceed the model's supported range, resulting in empty return results.

## How to Confirm Proper Configuration
- Trigger a calibration audit tool call manually for a single device, and verify that returned results include required fields such as tested part number and traceability number.
- Allow the plugin editing page to finish loading, confirm that the save prompt in the upper right corner has disappeared, and verify version compatibility.
- Pass a standard text snippet of a calibration certificate to the reranker plugin, and check that the number of returned results matches the preset configuration.
- Review tool calling logs to confirm that interface request parameters match the configured `toolChoice` and `functionCall` rules.

The values provided are common starting points and should be measured against the reader's own samples.
