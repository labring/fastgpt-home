# Supplier and Process Quality Audit for Industrial Instrument Manufacturing and Calibration: Model Integration and Configuration

## What Data for This Category Looks Like
Data for this category comes from design documents, standard instrument and environmental monitoring data, calibration software, laboratory information systems, and customer range requirements.
Each individual instrument generates documents after each calibration. These documents include assembly and commissioning forms, calibration procedures, original calibration records, error curves, metrology certificates, and software version records.
Fields include traceability numbers, range limits, error values (units such as Pa, ℃, kPa, etc.), calibration dates, and environmental parameters.
Data is updated after each calibration for each instrument. The length of a single document varies based on the number of calibration points and the complexity of the error curve.

## Constraints on Model Integration and Configuration
Calibration records and metrology certificates are core deliverables for this category. Data must be strictly traceable and free of deviations.
The mix of multiple document types requires the model to handle both structured fields and unstructured chart data.
The update rhythm of one calibration per instrument per cycle requires context to be limited to full-process materials for a single calibration. This avoids mixing cross-batch data.
The most time-consuming audit steps involve multi-point error calculation and traceability chain verification. The model must automatically call tools to retrieve data scattered across different systems.
Output content must exactly match original records, with no unfounded content generated.
Additionally, the risk of measurement deviation transfer requires configuration to strictly control the model's generation freedom. This prevents irrelevant content from interfering with audit results.

## How to Set the Configuration
| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Covers all document content for a single instrument's single calibration, including calibration records, error curves, and metrology certificates |
| `quoteMaxToken` | 2000–3000 token per quote | Fully retains traceability information in metrology certificates and key data from error curves, to avoid truncating core audit basis |
| Workflow/API tool selection | auto | Automatically calls tools to query calibration records and standard instrument data in the laboratory information system, adapting to audit processes with multi-system collaboration |
| `temperature` | 0.1–0.3 | Controls the rigor of model-generated content, avoiding deviations that do not match original calibration data |
| `AIPROXY_API_ENDPOINT` | Fill in according to the deployed proxy service | Securely forwards large model requests, avoiding direct exposure of interface keys |
| `AIPROXY_API_TOKEN` | Generated according to FastGPT v4.17.0 configuration rules | Completes interface identity verification, ensuring requests are legal and valid |

## Three Common Errors
- Phenomenon: The model outputs without citing original calibration records, and directly generates general audit conclusions. Cause: `quoteMaxToken` is not configured, or its value is too small. This prevents complete calibration data from loading, triggering the model to directly generate content.
- Phenomenon: The database table structure corresponding to calibration records cannot be viewed. Cause: The data table mapping tool is not enabled in the configuration, or the table definition file of the laboratory information system is not imported. This prevents recognition of fields and associated relationships for calibration data.
- Phenomenon: The model configuration page or question-and-answer interface fails to load properly in some browsers. Cause: The browser version is not compatible with supported FastGPT versions, or the browser's privacy blocking rules block interface requests. This causes configuration to fail to save normally, or question-and-answer requests to fail to initiate.

## How to Verify a Successful Configuration
- Submit a simulated supplier audit request, and check whether the model automatically calls tools to obtain calibration records and metrology certificate data for the corresponding instrument.
- Review the citation markers in the output content, and confirm that all core audit basis comes from original calibration documents, with no unfounded generated content.
- Verify the connection status of the local large model service, and confirm that interface requests can normally return responses matching the calibration data format.
- Switch to different browsers to open the configuration page, and confirm that page loading and interface requests have no blocking or errors, and adapt to the target browser versions.

The values provided are common starting points, and should be evaluated against the reader's own samples.
