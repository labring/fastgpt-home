# Supplier and Process Quality Audit for Industrial Instrument Manufacturing and Calibration: Deployment and Upgrade

## What the data for this category looks like
Data for this category originates from design documents, standard instrument environmental monitoring data, calibration software outputs, laboratory information systems, and customer range requirements. Data is updated per individual device and each calibration workflow. Daily documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version logs. Data fields cover measured values, error calculation results, calibration dates, standard instrument serial numbers, customer range thresholds. Units align with standard metrological traceability requirements, including pressure, temperature, current, and similar units.

## What constraints these characteristics impose during deployment and upgrade
Data for this category is updated per individual device and each calibration workflow, and includes documents with strict metrological traceability requirements such as metrology certificates and error curves. Deployments must support incremental indexing and device-level data management. Data sources include external systems such as standard instrument monitoring and laboratory information systems. Deployments must include standardized interface integration capabilities. Calibration records are core deliverables, so upgrade processes must ensure complete retention and traceability of historical data. Data verification rules must be configured to prevent non-compliant calibration documents from entering the system. Additionally, data fields must strictly match metrological traceability requirements. Deployments must predefine field mapping rules to avoid errors during subsequent data imports.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://your_mongo_user:your_mongo_password@your_mongo_host:27017/fastgpt?authSource=admin` | Stores unstructured documents such as calibration records and metrology certificates, requires persistence and support for multi-document queries |
| `REDIS_URL` | `redis://:your_redis_password@your_redis_host:6379/0` | Caches temporary calculation results and session information for calibration data, reduces database load |
| `DB_MAX_LINK` | `20–30` | Matches concurrent request volume for single calibration tasks, prevents database connection exhaustion |
| `STORAGE_S3_ENDPOINT` | Fill in according to the actual address of the enterprise’s internal object storage | Stores large files such as error curves and original calibration records, adapts to storage needs for batch calibration data |
| `FE_DOMAIN` | Public IP of the deployment server or bound domain name | Configures the frontend access address, ensures normal preview and download links for calibration documents |
| `FILE_TOKEN_KEY` | Randomly generated 32-bit string | Encrypts access tokens for calibration files, prevents unauthorized access to metrologically sensitive data |

## Three Common Misconfigurations
- Symptom: The deployment address loads a blank page for an extended period, with no error messages. Cause: `FE_DOMAIN` is not correctly configured to the actual access address of the deployment server, causing abnormal frontend resource loading links.
- Symptom: Large files such as error curves are missing after calibration records are imported. Cause: `STORAGE_S3_ENDPOINT` is not configured or is configured incorrectly, preventing normal file storage.
- Symptom: A database connection error appears after container startup, and the service cannot start normally. Cause: `MONGODB_URI` or `REDIS_URL` is configured incorrectly, and does not correctly point to available database and cache services.

## How to Confirm Proper Configuration
After completing initialization using the FastGPT v4.17.0 deployment package, perform the following verification steps:
- View container runtime logs, confirm there are no error logs for database and cache service connections, and verify that `MONGODB_URI` and `REDIS_URL` configurations are valid.
- Upload a standard calibration procedure document, check that the file upload and parsing process works normally, and confirm that `STORAGE_S3_ENDPOINT` can store files correctly.
- Access the configured `FE_DOMAIN` address, confirm that the frontend page loads normally, with no resource loading failure prompts.
- Generate a temporary access token, verify it using the encryption rule corresponding to `FILE_TOKEN_KEY`, and confirm that access permission configuration for sensitive calibration files is valid.

The values provided are common starting points and should be measured against the reader's own samples.
