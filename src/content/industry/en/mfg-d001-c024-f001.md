# Supplier and Process Quality Audit for Process Change and Engineering Change: HTTP Interfaces and External Systems

## What this category of data looks like
This category of data comes from manufacturing enterprise PLM, ERP, MES, supplier records, validation tests, and customer-specific requirements. Daily documents include ECN/ECR, change assessment reports, drawings and BOM version files, process validation reports, transition plans, inventory disposal documents, and customer approval documents. Data updates have no fixed cycle; each change triggers one update. Documents center on change identifiers, and are associated with multi-dimensional information such as materials, processes, and inspections. Fields include change number, version number, effective date, approval status, and some fields use standard units corresponding to their respective business documents.

## What constraints do these characteristics impose on the HTTP Interfaces and External Systems link
Data sources for this category are scattered, involving multiple heterogeneous enterprise systems. HTTP interfaces must be compatible with the authentication rules and data formats of different systems. There are various document types, including text reports, drawings, BOM files, etc. Interfaces must support multi-format data transmission and verification. Data updates have no fixed cycle. Interfaces must support on-demand triggering to adapt to temporary change trigger requirements. Changes are associated with cross-department collaborative processes. Interfaces must pass core associated fields to ensure that change data between external systems and FastGPT remains consistent, and avoid version confusion and data inconsistency.

## How to set configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Bearer Token format, valid for 7 days | General authentication standard for connecting enterprise-level systems, avoiding frequent token refreshes |
| `variables` | Includes three core fields: change number, version number, change type | Matches core identifiers of change management documents to ensure accurate data association |
| `responseData` | Only returns verified change data, filters invalid fields | Reduces redundant data processing overhead for external systems |
| Single request file limit | 800–1200 characters (text type), 100 MB (attachment type) | Adapts to the conventional size of change documents, avoiding triggering transmission restrictions |
| Timeout threshold | 600 seconds | Covers the time required for data retrieval and verification across multiple systems |
| Call trigger timing | Triggered after change approval is completed | Ensures synchronized data is the final effective version |

## Three common mistakes
- Scenario: A maxLength error is triggered when calling the interface, returning a 413 status code. Cause: The total document size of a single request is not restricted, exceeding the transmission limit of FastGPT or external systems.
- Scenario: Associated fields returned by the interface are empty, failing to match the business logic of change documents. Cause: Core identifier fields are not configured in `variables`, resulting in missing passed parameters.
- Scenario: Interface calls frequently time out, returning a 504 status code. Cause: A reasonable timeout threshold is not set, failing to cover the full time required for cross-system data retrieval.

## How to confirm the configuration is complete
- Send a test request carrying the change number and version number, check whether the content returned by `responseData` includes the expected core field information.
- Upload a single change document that meets the size limit, confirm that the interface can complete data synchronization normally without returning errors.
- Call the interface to pull change data, verify that the authentication information is valid, and no 401 or 403 errors are returned.
- Adjust the timeout threshold, simulate a long-time data retrieval scenario, and confirm that the interface does not interrupt the connection in advance.

The values given are common starting points and should be measured against the reader's own samples.
