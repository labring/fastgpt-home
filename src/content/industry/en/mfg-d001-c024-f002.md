# Supplier and Process Quality Audit for Process and Engineering Changes: Vector Models and Indexes

## What the data for this category looks like
Data for this category is generated and used by change management teams made up of R&D, process, quality, production, and procurement staff at manufacturing enterprises. Core data sources include PLM, ERP, and MES systems, supplier materials, process validation test records, and customer special requirement documents. Daily generated documents include ECN/ECR forms, change assessment reports, drawings and BOM version files, process validation reports, production switching plans, inventory disposal documents, and customer approval documents. Data updates follow no fixed cycle. New content is generated each time a process or engineering change is triggered. A single change will link to multiple cross-system document types.

## Constraints on Vector Models and Indexing Workflows
This category’s data connects multiple systems and includes cross-document attributes. Each change triggers batch updates to linked documents, creating multiple constraints for the vector model and indexing workflow.
First, cross-system documents have wide format differences, including structured fields and unstructured text. The system must support vectorization of mixed-type content.
Second, irregular incremental updates require indexes to support lightweight synchronization. This prevents full reindexing from consuming excessive computing resources.
Third, chain effects from change associations require cross-document matching during retrieval. Indexes must retain the association relationships between documents.
Fourth, long-text change assessment and validation reports require vectorization to preserve complete logical chains. This avoids truncating critical decision-making information during chunking.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to long-text documents such as ECN and change assessment reports, and preserves complete change logic and approval node information |
| Overlap Length | 100–200 characters | Prevents cross-chunk change association information from being truncated, and ensures retrieval can match complete change chains |
| Similarity Threshold | 0.75–0.85 | Filters low-relevance historical change documents, and focuses on valid content linked to the current change |
| Single Search Limit | Top 20 entries | Covers key linked change documents, and avoids excessive redundant results impacting subsequent processing |
| `maxToken` | 8192 | Adapts to long-text process validation reports and BOM version files, and ensures core content is not truncated during vectorization |
| `defaultToken` | 256 | Sets a base vectorization length for short-text change forms, balancing computing efficiency and information integrity |

## Three Common Misconfigurations
- Vectorization task error prompts "embedding rate limit exceeded": No concurrent thread limits are configured. Batch vectorization requests exceed interface call quotas, triggering rate limiting.
- Knowledge base retrieval is slow: Chunk length is set too large, increasing vector calculation time for single-block text. Retrieval recall range is not optimized, leading to loading a large number of irrelevant documents.
- Dataset automatically generates multiple indexes: No incremental index trigger rules are configured. The system generates a new index each time data sources such as PLM are synchronized by default, leading to accumulation of duplicate index data.

## How to Verify Proper Configuration
- Upload a complete ECN document, check the progress status of the vectorization task, and confirm the task completes within a reasonable time frame with no error prompts.
- Enter keywords related to change assessment for retrieval, check the relevance and number of returned results, and confirm they meet the single search limit configuration requirements.
- View the index record list of the dataset, confirm new indexes are only generated when manually triggered or during configured change events, with no automatic repeated generation.
- Import a long-text process validation report, check the vectorized text fragments, and confirm no critical logic is truncated, matching the `maxToken` configuration range.
- View the current FastGPT version information, confirm use of FastGPT v4.17.0 to ensure configuration item compatibility.
