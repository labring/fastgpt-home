# Supplier and Process Quality Audit for Process Change and Engineering Change: Multi-turn Dialogue and Prompting

## What this category’s data looks like
Data sources for this category include PLM, ERP, MES, supplier materials, validation tests, and customer-specific requirements. Updates occur irregularly, only triggered by individual changes. Daily documents include ECN/ECR forms, change assessment reports, drawings and BOM version files, process validation reports, transition plans, inventory disposal documents, and customer approval documents. Data fields include change number, version number, effective date, affected bill of materials, validation results, and more. The version number has no unit, dates use the YYYY-MM-DD format, and material quantities are measured in pieces or sets.

## What constraints these characteristics impose on multi-turn dialogue and prompting
Data is distributed across multiple heterogeneous systems, so multi-turn dialogue must dynamically call the latest data from corresponding data sources and avoid using expired versions. Document structures are complex with strong field correlations, so prompts must clearly guide the model to extract core change information and identify cross-departmental chain impacts. Change triggers have no fixed cycle, so context must support on-demand loading of the latest change records and validation files. The audit process involves cross-team collaboration across R&D, process, quality, and other departments, so multi-turn dialogue must split question steps by role to ensure accurate information transfer.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Maximum context length | 1200–1800 characters | Matches the average single-page length of ECN/ECR documents to avoid truncating critical change content |
| Single dialogue turn limit | First 8 turns | Matches the standard communication steps for change audits to avoid ineffective loops |
| Variable injection rule | Bind the `variables` parameter to pass the latest BOM version | Ensures material data used in dialogue is the currently active version |
| Context recall scope | Associate PLM change records from the past 30 days | Covers the traceability period for chain impacts of current changes |
| Initial system prompt | Preset by process/engineering change category | Matches audit priorities for different change scenarios to reduce model divergence |

## Three common misconfigurations
- Phenomenon: The BOM version referenced in the dialogue does not match the currently active version exported from PLM. Cause: The `variables` parameter is not used to pass the latest material data synchronized from ERP in real time, so the model uses cached old version information.
- Phenomenon: Dialogue output is empty or generates content unrelated to change audits. Cause: The initial system prompt for the `messages` parameter is not configured, so the model cannot recognize the current supplier and process quality audit scenario and cannot generate valid responses.
- Phenomenon: Dialogue triggers timeout interruptions. Cause: The cross-system query scope for single dialogue is not limited, and multiple data sources including PLM, MES, and supplier materials are called simultaneously, exceeding response time limits.

## How to verify the configuration is correct
- Initiate a simulated change request dialogue, check that the material version referenced in the dialogue matches the latest version exported from PLM.
- Submit a change request missing customer approval documents, check if the model prompts for supplementary corresponding audit materials.
- Initiate more than 8 consecutive rounds of change impact traceability dialogues, check if the turn limit is triggered.
- View the dialogue logs in FastGPT v4.17.0, confirm that the `chatId` parameter is correctly bound to ensure context continuity for the same scenario.
