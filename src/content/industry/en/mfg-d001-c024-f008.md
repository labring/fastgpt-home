# Supplier and Process Quality Audits for Engineering and Process Changes: Document Parsing and Chunking

## What this category’s data looks like
This category’s data is generated by a change management team composed of R&D, process, quality, production, and procurement teams from manufacturing enterprises. Core documents include ECN/ECR, change assessment forms, drawings and BOM version files, process validation reports, transition plans, inventory disposal documents, and customer approval documents. Data sources cover PLM, ERP, MES systems, supplier materials, validation test records, and customer-specific requirements. Updates are triggered irregularly with each change. Documents contain fields such as design parameters, material codes, process steps, and inspection standards. Some drawing documents include non-standard units and version identifiers.

## What constraints do these characteristics impose on the document parsing and chunking process
This category includes diverse document types: plain text change files, parameterized tables, drawings and BOM files with version identifiers. Parsing must support mixed-format content. The system must distinguish new and old documents using version identifiers to avoid version confusion during parsing. Documents contain structured fields such as material codes, process steps, and inspection standards. Chunking must retain relational links between fields to avoid breaking business logic when splitting content. Some documents are linked to customer-specific requirements and validation records. Chunking must retain contextual connections to ensure complete traceability of supporting evidence during audits.

## How to configure
This document is written based on the configuration logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the paragraph length of ECN/ECR documents and the information density of process parameter blocks in this category, avoiding overloaded or overly fragmented single chunks |
| `chunkSplitter` | Semantic paragraph + fixed length hybrid | Adapts to mixed-format change documents in this category, retains business associations such as material codes and process steps, while controlling the information density of single chunks |
| `customPdfParse` | Enabled | Adapts to drawing and table PDF documents in this category, retains original typesetting and field positions, avoiding loss of structure during parsing |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Addresses parsing time for large BOMs or multi-page validation reports in this category, avoiding timeout interruptions |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Compatible with batch-imported multi-page drawings and change document packages in this category, meeting the bulk document needs of change management |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules for different document types in this category, adapting to diverse document structures |

## Three common misconfigurations
- Phenomenon: After uploading a drawing-type PDF, the system fails to parse image and table content, returning empty text results. Cause: The `customPdfParse` configuration is not enabled. The default parsing only processes the plain text layer and does not trigger the parsing logic adapted for graphics and tables.
- Phenomenon: After importing an Excel-format BOM document, the chunking result loses the corresponding relationship between material codes and quantities. Cause: Splitting is only done by fixed length without configuring semantic paragraph splitting, which breaks the field association logic within the table.
- Phenomenon: A timeout error occurs when parsing a multi-page change validation report. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted. The default timeout duration is insufficient for processing large multi-page documents.

## How to confirm the configuration is correctly applied
- Upload a single PDF drawing document with tables and graphics. Verify the parsing result includes graphic annotations and table fields to confirm the `customPdfParse` configuration is active.
- Import an Excel BOM document containing multiple structured fields. Verify the chunking result retains the corresponding relationship between fields such as material codes and quantities to confirm the chunking rules are adapted to structured data.
- Upload a change validation report with more than 200 pages. Verify the parsing process completes within the duration set by `PARSE_FILE_TIMEOUT_SECONDS` without timeout errors.
- Test the single-document PDF query function. Confirm search results only target the content of the target document with no redundant cross-document information to confirm chunking did not break document boundaries.
