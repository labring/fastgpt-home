# Supplier and Process Quality Audit for Engineering Change and Process Change: Model Access and Configuration

## What this category of data looks like
This category of data is generated by the change management team composed of R&D, process, quality, production and procurement departments of manufacturing enterprises. Daily documents include ECN/ECR, change assessment reports, drawing and BOM versions, process verification reports, switching plans, inventory disposal documents, customer approval documents, etc. Data sources cover PLM, ERP, MES, supplier materials, verification test records and customer special requirements. Updates are triggered irregularly with each change. Documents contain fields such as change number, effective node, involved materials and process items, with no unified fixed update cycle.

## What constraints do these characteristics impose on the model access and configuration link
Multi-source heterogeneous data sources require adapting to the interface formats and data structures of different systems when accessing the model. Configure a unified parsing rule to process cross-system change-related data. Irregular change triggering rhythm leads to large fluctuations in context length. Reserve sufficient context and response token space to avoid processing failures caused by sudden increases in data volume. Configure mixed-format input processing logic to ensure that all types of change-related documents can be parsed correctly. Changes involve multiple types of documents for cross-department collaboration. Define clear recall rules for associated documents to avoid missing key verification or customer approval documents, and prevent issues that do not meet quality control requirements.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0, and are adapted to the audit scenario of process change and engineering change for manufacturing enterprises:

| Configuration Item | Recommended Value Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | The total token count of change-related documents fluctuates with complexity. Reserve sufficient space to accommodate the content of ECN, BOM version comparison and multiple verification reports |
| `maxTokens` | `4000–6000 token` | The response length of a single round of change audit needs to cover core content such as change impact analysis and switching node confirmation, to avoid truncation of key conclusions |
| `quoteMaxToken` | `2000–3000 token` | Sufficient supplier materials, verification reports and customer approval documents must be recalled as audit basis, to ensure that the referenced content is complete |
| `temperature` | `0.2–0.4` | Change audit requires maintaining rigor, reduce randomness in generated results to ensure conclusions meet enterprise quality control requirements |
| `AIPROXY_API_ENDPOINT` | Fill in the corresponding interface address according to the deployment environment | Adapt to the access requirements of the enterprise internal network environment, ensure that the model interface can be called normally |
| Workflow/API tool selection | `auto` | Automatically call the document parsing tool to process mixed-format change files, no need to manually specify processing logic |

## Three common configuration mistakes
- Symptom: The interface returns `model not supported` error. The cause is that the access permission of the target model is not added in the proxy configuration corresponding to `AIPROXY_API_ENDPOINT`.
- Symptom: The generated change audit conclusion is truncated. The cause is that the value of `maxTokens` is too small, which does not cover the token amount required for a single round of response, leading to loss of key content.
- Symptom: Recalled associated documents are missing customer approval files. The cause is that the value of `quoteMaxToken` is too low, which does not cover the total token length of the required referenced documents, leading to failure to recall some key files.

## How to confirm that the configuration is complete
- Submit a complete ECN document and associated BOM version data, check whether the model can correctly parse the change content and generate audit results.
- Check the context length statistics returned by the interface, confirm that the value of `maxContext` is greater than the total token amount of the current test data.
- Trigger a change audit task, check whether the recalled referenced documents include supplier materials, verification reports and customer approval files.
- Adjust the value of `temperature` to 0.5, compare the differences between the two audit results, and confirm that the parameter configuration takes effect.

The values provided are common starting points and should be measured against the reader's own samples.
