# Supplier and Process Quality Audit for Tooling, Fixture and Gauge Manufacturing: Vector Models and Indexes

## What the data for this category looks like
Business data for tooling, fixture and gauge manufacturing comes from tooling departments of automotive, aerospace and mechanical assembly enterprises, as well as dedicated tooling suppliers. Daily documents include tooling requirement documents, positioning datum schemes, fixture drawings, gauge operation manuals, acceptance reports, calibration records and change histories. Data sources cover product 3D models and GD&T parameters, process routes, coordinate measuring machine data, on-site trial feedback and metrology system data. Updates follow project delivery, product change and periodic calibration schedules. Documents contain professional engineering terms, geometric tolerance parameters, metrology values and operation steps. The text length of single documents varies widely.

## Constraints imposed on vector models and indexing by this category's characteristics
The category’s data includes professional engineering terms, multiple document formats and widely varying text lengths. This requires vector models to adapt to industry-specific terminology semantics. The update rhythm tied to projects and changes requires indexes to support incremental updates and versioned management, to avoid time-consuming full rebuilds. Professional content in documents such as engineering drawings and calibration records is prone to being truncated during chunking. This requires properly configured chunking and overlap parameters. Multi-modal data embedding needs require configuring model parameters adapted to multi-modal input, to avoid format compatibility errors. Additionally, the audit scenario for this category has high retrieval precision requirements. Incorrect index configuration may lead to serious consequences such as clamping deviation or gauge misjudgment.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `maxToken` | 8192 | Adapts to the total token length of engineering drawing text, GD&T parameters and calibration records included in tooling and fixture documents |
| `defaultToken` | 4096 | Meets the embedding requirements for multi-modal embedding processing of fixture drawing text descriptions and coordinate measuring machine data |
| Chunk Length | 800–1200 characters | Matches the single-paragraph text length of fixture drawing descriptions and acceptance reports, preventing professional terms from being split |
| Overlap Length | 100–150 characters | Retains professional term context across chunks, preventing semantic loss caused by chunk truncation |
| Similarity Threshold | 0.72–0.85 | Adapts to the professional term matching precision of industrial documents, filtering low-correlation historical data |
| Single Search Limit | Top 10 entries | Focuses on the most relevant historical acceptance and calibration records, meeting the precise retrieval needs of audit scenarios |

## Three common configuration mistakes
- Symptom: Returns an Invalid parameter error when connecting a multi-modal embedding model. Cause: Fails to adapt to the token format of GD&T terms and engineering drawing text in tooling and fixture documents, and fails to enable industrial document embedding optimization in FastGPT v4.17.0.
- Symptom: Voyage indexes become unavailable after upgrading to a new version, returning a 400 status code with no response body. Cause: Fails to update index configuration parameters to adapt to the new version’s vector protocol, and fails to regenerate embedding vectors for historical data.
- Symptom: Historical calibration records cannot be retrieved correctly after rebuilding the knowledge base index. Cause: Chunk overlap length is set too small, leading to truncated professional terms that cannot match query requests.

## How to confirm proper configuration
- Upload a typical tooling and fixture acceptance report, and check if the generated embedding vector includes core fields such as GD&T parameters and calibration dates.
- Initiate a retrieval for historical change records, and confirm that the similarity of returned results falls within the preset threshold range.
- Perform a vector database migration test, and verify that old version data can be loaded normally into the new index structure.
- Call the multi-modal embedding interface to upload text descriptions of a fixture drawing, and confirm that the returned embedding vector has no errors and uses the correct format.

The values provided here are common starting points, and should be validated against the samples relevant to the actual deployment scenario.
