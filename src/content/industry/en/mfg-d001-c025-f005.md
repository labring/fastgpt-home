# Supplier and Process Quality Audit for Tooling, Fixture and Gauge Manufacturing: Tool Calling and Plugins

## What the data for this category looks like
Data for this category comes from product digital models and GD&T, process routes, coordinate measuring machine data, on-site trial feedback, and metrology systems. Daily documents include tooling requirement documents, positioning datum schemes, fixture drawings, gauge operation manuals, acceptance reports, calibration records, and change histories. Data updates run per project milestones, each product change, or regular calibration. Documents include fields such as datum parameters, tolerance values, calibration cycles, and change version numbers. Most units follow standard measurements like millimeters, newtons, and hours.

## What constraints these characteristics impose on the tool calling and plugins workflow
Data for this category is multi-source and heterogeneous, including both unstructured and structured content such as engineering digital models and metrology reports. Tool calling must support parsing documents in multiple formats to ensure accurate extraction of specialized fields like datum parameters and tolerance values. Data updates have no fixed cycle. Plugins must support triggering based on project milestones, product changes, or calibration cycles to avoid unnecessary calls. Documents include traceable content such as calibration records and change histories. Tool calling must link to the correct version of data sources to ensure consistency during the audit process. Errors such as out-of-tolerance batch machining or gauge misjudgment have severe consequences. Plugin calls must include a validation step to intercept abnormal inputs or results.

## How to set up the configuration
These configurations are developed based on FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | This scenario requires the model to independently determine whether to call plugins to process engineering data, so no forced plugin specification is needed |
| Workflow/API function-call configuration | Calibrate based on actual testing | For specialized fields like GD&T tolerances and calibration records in this category, the plugin input parameter format must be precisely matched to avoid parameter incompatibility |
| Plugin timeout | 600 seconds | Digital model parsing and coordinate measuring data processing for this category usually take a long time. Reserve sufficient time to ensure complete data acquisition |
| File parsing format restrictions | Only allow .dwg, .pdf, .xlsx | Filter non-business-related files to reduce unnecessary calls and improve tool calling efficiency |
| Call retry count | 2 times | Respond to network fluctuations or temporary external interface exceptions, and avoid interrupting the audit process due to a single failed call |
| Result validation switch | Enabled | Perform format and reasonableness checks on positioning schemes and deviation data returned by plugins, to prevent incorrect results from entering the audit workflow |

## Three common configuration mistakes
- Scenario: A custom plugin is configured but never triggers a call, and logs show no tool calling request. Cause: `toolChoice` is not correctly set to `auto` mode, or plugin input parameters do not match the specialized field format of tooling documents for this category.
- Scenario: The model does not read uploaded fixture drawings or calibration records, and directly generates audit conclusions. Cause: The automatic tool calling trigger logic in simple mode is not enabled, or the association rules between file parsing and plugins are not configured.
- Scenario: Calling an external metrology system interface returns empty results or a 500 status code. Cause: The plugin timeout threshold is not set, or the request headers and parameter formats of the external interface are not adapted, and the field integrity of returned data is not verified.

## How to confirm the configuration is correct
- Manually trigger tool calling, upload typical tooling requirement documents and fixture drawings, and check whether plugins are called as expected and return parsing results.
- Simulate a product change scenario, trigger plugin calls, and check whether the corresponding version of change history data is linked.
- View tool calling logs to confirm that the `toolChoice` parameter has taken effect, and that plugin call timeout and retry configurations match preset rules.
- Input documents with abnormal formats, and check whether plugins trigger filtering logic to intercept invalid inputs.

The values provided here are common starting points and should be measured against the reader's own samples.
