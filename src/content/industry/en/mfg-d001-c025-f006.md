# Supplier and Process Quality Audit for Tooling, Fixture and Gauge Manufacturing: Citation Sources and Traceability

## What this category of data looks like
This category of data comes from daily work outputs of tooling departments and dedicated tooling suppliers at automotive, aerospace, and mechanical assembly enterprises. It includes tooling requirement documents, positioning datum schemes, fixture drawings, gauge operation manuals, acceptance reports, calibration records, and change histories. Data sources include product digital models and GD&T, process routes, coordinate measuring machine data, on-site trial feedback, and metrology systems. Updates follow project milestones, product changes, or regular calibration schedules. Individual documents hold structured fields such as positioning datums, dimensional tolerances, and calibration parameters, plus unstructured drawing content.

## Constraints on citation sources and traceability for this category
The multi-source mixed structure of this category’s data requires traceability processes to cover both structured parameters and unstructured drawing content. This prevents missing key information such as geometric tolerances when only text searches are used. Following the update rhythm tied to projects and changes, traceability links must include version identifiers. This ensures referenced fixture drawings and calibration records match the current production batch. Professional fields such as GD&T tolerances and coordinate measuring machine readings must retain their original units and precision. Generalized conversion of these fields is not allowed. Cross-verification across multiple data sources requires traceability chains to reach original metrology systems or on-site trial records. Relying solely on intermediate documents cannot support accurate traceability.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale for This Setting |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 token` | This category’s documents include drawing metadata and coordinate measuring machine data. Sufficient tokens are needed to hold complete traceability information, and this setting aligns with FastGPT v4.17.0’s token allocation rules. |
| `detail` | Enabled | Full metadata of traceability documents must be returned, including calibration dates and change version numbers, to support detailed parameter extraction. |
| Single search limit | Top 6 entries | The number of documents linked to a single project in this category is limited. Too many results will disrupt accurate matching. |
| Maximum context | `4000–6000 characters` | This setting must hold associated content from multiple traceability documents, to avoid truncating critical change histories. |
| `responseData` | Return only structured fields and original source identifiers | This category requires precise association of original data from acceptance reports and calibration records. Redundant unstructured content must be excluded. |
| Timeout threshold | `300 seconds` | Retrieval of individual documents in this category takes extended time. This setting aligns with FastGPT v4.17.0’s timeout handling logic. |

## Three common configuration errors
- Search results return old-version fixture drawings that are unrelated to the current tooling project. This happens when traceability is not linked to version identifiers, only keyword matching is used, and no filtering based on project batches is applied.
- Accurate reference to x-axis and y-axis measurement values from coordinate measuring machine data is not possible. This occurs when the `detail` configuration is not enabled, so detailed parameters of structured fields are not returned.
- Traceability results do not link to change histories, leading to reference of expired positioning datum schemes. This happens when version filtering logic is not enabled, and documents of the latest version are not selected.

## How to confirm correct configuration
- Initiate a query for a specific tooling project, and check if returned results include specified documents such as the project’s acceptance report and calibration records.
- Review metadata from traceability results, and confirm that fields such as change version numbers and calibration dates are included.
- Verify that the `quoteMaxToken` configuration fully displays all content of coordinate measuring machine data without truncation.
- Test that only documents related to the current project are returned after triggering a search, with no unrelated content included.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
