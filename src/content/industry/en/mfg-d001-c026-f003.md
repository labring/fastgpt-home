# Supplier and Process Quality Audit for Non-Ferrous Metal Smelting and Electrolysis: Multi-turn Dialogue and Prompt Engineering

## What Data Looks Like for This Category
Daily documents for this category include batching lists, smelting records, electrolyzer condition records, laboratory test reports, anode and cathode quality records, and environmental protection ledgers. Data sources cover concentrate and auxiliary material analysis reports, DCS system data, electrolyzer voltage and current monitoring values, laboratory test results, and energy and environmental protection monitoring data.

Data update frequency aligns with raw material batches, smelting heats, or electrolyzer condition changes. Some monitoring data is synchronized in real time. Document fields include raw material composition values, furnace temperature parameters, cell voltage, metal recovery volumes, pollutant emission values, and similar. Common units are degrees Celsius, volts, tons, milligrams per cubic meter, and other standard units.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
Real-time cell condition and furnace temperature data, paired with batched raw material batching lists and laboratory reports, require accurate association of batches and operating condition nodes in dialogue context. This prevents cross-batch data mixing.

Field differences across multi-source heterogeneous data require prompts to explicitly specify data sources and corresponding document types. Without this, data extraction deviations are likely to occur.

The update frequency of high-volume real-time data requires the multi-turn dialogue context window to adapt to short-cycle data timeliness. Overly long historical context may introduce outdated data that interferes with current audits.

Associated queries for batched documents require prompts to explicitly bind unique identifiers such as raw material batch numbers, furnace numbers, or cell numbers. Without these, supplier incoming materials and process quality data cannot be accurately matched.

## Configuration Specifications
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Max Context Window | Keep the last 10 dialogue history entries | Matches short-cycle batch audit requirements in the smelting industry, avoids outdated data from overly long history |
| Single Search Limit | Keep the top 8 matched documents | Covers associated data volume for single-batch raw materials and multiple smelting heats, meets information needs for process audits |
| Variable Population | Bind the `variables` parameter to specify furnace/cell numbers | Accurately associates smelting and electrolyzer condition records for corresponding operating conditions, prevents cross-batch data mixing |
| Dialogue Identifier | Bind the `chatId` parameter to link a single audit task | Ensures multi-turn dialogue context only belongs to the current supplier or process audit, isolates data across different tasks |
| Prompt Optimization | Enable, calibrate based on actual testing | Adapts to professional terminology and field formats for non-ferrous metal smelting, improves data extraction accuracy |

## Three Common Configuration Errors
- Phenomenon: No target audit data is returned after starting a multi-turn dialogue. The interface shows empty results or incorrect matches. Cause: Unique identifiers such as raw material batch numbers, furnace numbers, or cell numbers are not bound in the prompt. This prevents the context from accurately associating corresponding documents.
- Phenomenon: No smelting-related data for the current year or month can be extracted after configuring the prompt. Cause: The data time range field and document type are not explicitly specified. The timestamp format and field naming rules for non-ferrous metal smelting documents are not adapted.
- Phenomenon: The dialogue fails to load preset audit guidance rules after setting the context count to 0 in the workflow. Cause: The scope of the `messages` parameter is misunderstood. This parameter includes initial prompts and system guidance content. Setting it to 0 will lose core audit logic.

## How to Verify Proper Configuration
- Manually enter a query that includes a known furnace number or batch number. Confirm that returned results are associated with smelting records and laboratory reports for the corresponding furnace number.
- Adjust the context count parameter. Test that historical context in multi-turn dialogue loads according to the set quantity, with no redundant irrelevant data.
- View workflow run logs. Confirm that the `chatId` and `variables` parameters are correctly bound to the unique identifier of the current audit task.
- Enter a query that does not specify identifiers. Confirm that results do not show incorrect cross-batch or cross-furnace number data, to verify the constraint effect of the configuration.

The values provided are common starting points and should be evaluated against the reader's own samples.
