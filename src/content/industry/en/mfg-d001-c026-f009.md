# Supplier and Process Quality Audit for Non-Ferrous Metal Smelting and Electrolysis: Model Access and Configuration

## Data Characteristics for This Category
Core data for this category comes from smelting, electrolysis, laboratory testing, and scheduling departments of copper, aluminum, lead-zinc, and other smelting enterprises. Daily documents include batching lists, smelting records, electrolytic cell status records, laboratory reports, anode and cathode quality records, and environmental protection ledgers.
Data sources cover concentrate and auxiliary material analysis, DCS systems, cell voltage and current monitoring, laboratory testing, and energy and environmental protection monitoring equipment. Update frequency changes in real time based on raw material batches, furnace heats, or electrolytic cell operating status. Some ledger data is archived per production cycle.
Fields include smelting-specific parameters such as concentrate grade, impurity content, cell voltage, current value, and metal recovery rate. No unified format exists across general industry standards.

## Constraints for Model Access and Configuration
Multi-source heterogeneous data sources require the model access link to support documents in multiple formats and real-time data streams. Sufficient context capacity must be configured to cover batch historical production data.
Frequently updated production data means model calls must adapt to real-time requirements, and cannot rely on outdated context caches. Smelting scenarios have high precision requirements for impurity analysis and metal balance calculations. Random deviations in model output must be limited.
This category relies on specific numerical parameters to judge furnace status and electrolytic cell status. The model must have the ability to process structured production data, and cannot rely solely on unstructured text analysis.
Domestic demand for large model access is widespread. Support must be provided for configuring non-OpenAI models via a transit API, to adapt to deployment scenarios without native OpenAI API keys.

## Configuration Parameter Recommendations
| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Covers the stitching needs of multiple historical batching lists and electrolytic cell status records, avoids context truncation that loses critical production data |
| `temperature` | 0.2–0.4 | Reduces random deviations in impurity component analysis and metal balance calculations, meets precision control requirements for smelting scenarios |
| `AIPROXY_API_ENDPOINT` | Fill in the corresponding transit endpoint according to the deployment environment | Adapts to domestic large model access scenarios, addresses configuration needs without official OpenAI API keys |
| `maxTokens` | 2000–3000 token | Balances the completeness of single audit results and call latency, adapts to the timeliness requirements of real-time furnace status judgment |
| Workflow/API tool selection | auto | Allows the model to independently choose whether to call tools for structured calculation tasks such as component accounting and cell status analysis |

## Common Configuration Mistakes
- Model calls return an "invalid token" error. The cause is filling the platform's native API key into `AIPROXY_API_TOKEN`, instead of using a valid token generated by the transit service.
- Cannot properly connect to a Docker-deployed FastGPT instance. The cause is not configuring `AIPROXY_API_ENDPOINT` to the container's internal or mapped API port address.
- Model output missing core production parameters. The cause is setting `maxContext` too small, failing to load sufficient historical production data for comparative analysis.

## How to Verify Successful Configuration
- Check whether `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` match the deployed transit service or large model platform. Verify connectivity via the FastGPT built-in model test interface.
- Upload a single batching list and electrolytic cell status record, trigger a supplier and process quality audit task, and confirm whether the output includes core fields such as concentrate grade and cell voltage.
- Adjust the `temperature` parameter, trigger the same audit task multiple times, and observe whether the consistency of output results meets the precision control requirements of the scenario.
- View the model call logs in FastGPT v4.17.0, confirm that the context length does not trigger the threshold limits of `maxContext` or `maxTokens`.

The values provided here are common starting points. They should be evaluated against the reader's own production samples.
