# Supplier and Process Quality Audit for Garment Cutting and Sewing: Tool Calling and Plugins

## What the Data for This Category Looks Like
Core data for this category comes from orders and size charts, CAD patterns, fabric and accessory inspection records, hanging system data, needle detector output records, and customer sealed samples.
Daily generated documents include process sheets, layout plans, cutting lists, first article sealed samples, process quality sheets, and packaging and size matching lists. Fields include size specifications, fabric dye lots, cut piece quantities, and process quality inspection items, among others.
Data updates occur per order, per style, and per batch. Cut piece-related data is irreversible. Process records are synced in real time with production milestones.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins
Cut piece data for this category is irreversible and processing is labor-intensive. Tool calling must accurately match pattern and process requirements to avoid using incorrect historical data.
In scenarios with parallel production across multiple orders, data context must be isolated by order and batch to prevent cross-order data confusion.
Fields such as fabric dye lots and size specifications have strict precision requirements. Tool calling must first retrieve category-exclusive document fields, including process sheets and layout plans.
The large volume of seasonal styles requires plugins to support quick switching of knowledge base data for the current production batch.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `auto` | This category's quality inspection scenarios cover multiple needs including process verification and size verification. Automatic tool selection adapts to dynamic business scenarios |
| `functionCall` | Allow all configured tools | Garment cutting and sewing audits involve multiple tools including fabric and accessory inspection and process quality inspection, requiring full coverage of business processes |
| Tool call timeout | 600 seconds | Document parsing for this category's layout plans, process sheets and other materials requires a long processing cycle, to avoid interrupting the audit process midway |
| Single tool call result limit | Top 10 entries | Single batch production data volume is moderate; excessive results will increase the model's context processing load |
| Knowledge base data filtering rule | Match by production batch tag | Data must be isolated by order and batch to prevent cross-order data confusion from affecting audit accuracy |

## Three Common Misconfigurations
- Phenomenon: The workflow interrupts when reaching the tool calling node, with no error logs or empty results returned. Cause: Knowledge base data filtering rules are not configured by production batch, leading to retrieval of redundant cross-order data during tool calling, triggering context overflow.
- Phenomenon: Tool call results do not include field details of category-exclusive documents such as process sheets and layout plans. Cause: Exclusive knowledge base retrieval fields are not configured; default retrieval of general business fields cannot match key information such as this category's size specifications and fabric dye lots.
- Phenomenon: Intermediate execution steps of tool calls are repeatedly displayed in the chat window. Cause: The intermediate step display switch for tool calls is not turned off, causing logs from the plugin execution process to be synchronized to the conversation interface.

## How to Confirm Proper Configuration
- Manually trigger tool calling, check that returned results only include document data such as the current production batch's process sheets and size charts, to confirm the filtering rule is active.
- View tool call logs, confirm that the `toolChoice` parameter is automatically set to `auto`, and all called tools are configured quality inspection-related tools.
- Send a test request, check that intermediate steps of the tool call process are not displayed in the conversation interface, to confirm the hidden output configuration is active.
- Simulate a cross-batch retrieval request, confirm that the tool cannot retrieve document data from other orders, to verify the data isolation rule is active.

The values provided are common starting points and should be measured against the reader's own samples.
