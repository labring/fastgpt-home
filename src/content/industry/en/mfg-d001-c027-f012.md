# Supplier and Process Quality Audit for Garment Cutting and Sewing: Deployment and Upgrade

## What the data for this category looks like
Core data for this category comes from garment OEM/ODM factories and cutting and sewing workshops on brand supply chains. Daily circulated documents include process sheets, CAD patterns, layout plans, cutting orders, first sample seals, process quality sheets, packaging size matching sheets, and more. Data sources cover order and size charts, surface and accessory inspection records, hanging system production data, needle detector test results, and customer sealed sample information. Updates follow cycles per order, per style, and per batch. Core fields include pattern parameters, fabric batches, process quality inspection items, packaging ratios, and more. Cutting piece-related data is irreversible, and manual labor accounts for a high share of process links.

## What constraints these characteristics impose on the deployment and upgrade phase
The high-frequency, small-batch, multi-document nature of this category requires deployment to adapt to parsing of multiple types of unstructured documents. The irreversible attribute of cutting piece data requires knowledge base storage to have tamper-proof permission control. The update cycle per order, per style, per batch requires configuring scheduling logic adapted to batch data synchronization. The dense manual process feature requires reserving sufficient document parsing computing power during deployment to handle embedding processing of long texts such as process quality sheets. At the same time, format differences across data sources require configuring unified document preprocessing rules during deployment to avoid format conflicts in quality inspection data from different sources.

## How to set the configurations
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://fastgpt:securepass@mongodb:27017/fastgpt?authSource=admin` | Adapts to structured quality inspection data storage for multiple batch orders, supports high-concurrency read and write operations |
| `REDIS_URL` | `redis://:redispass@redis:6379/0` | Caches frequently accessed pattern parameters and process rules to reduce database load |
| `STORAGE_S3_ENDPOINT` | `http://minio:9000` | Stores large-volume unstructured documents such as CAD patterns and first sample seals, supports batch uploads |
| `DB_MAX_LINK` | `150–250` | Handles concurrent requests for multiple documents per order to avoid connection exhaustion |
| `FE_DOMAIN` | `https://fabric-audit.your-domain.com` | Configures a dedicated access domain name to distinguish production and test environments |
| `FILE_TOKEN_KEY` | `Randomly generated 32-bit hexadecimal string` | Ensures permission verification for file upload and access, prevents unauthorized file access |

## Three common errors
- Running `docker-compose up` results in failed service startup, with container logs indicating database connection timeout. The cause is failure to correctly fill in database account and password information in `MONGODB_URI` or `PG_URL`, resulting in inability to establish a persistent connection.
- After local deployment, the maximum number of createable knowledge bases is fixed at 30 and cannot be adjusted. The cause is failure to modify the default value of the corresponding configuration item, failing to adapt to the document storage requirements of multiple orders and batches for this category.
- After connecting to OneAPI, the platform does not display available models, and the front-end console prompts that cross-origin requests are blocked. The cause is failure to add the OneAPI access address to the cross-origin allow list of `FE_DOMAIN`, resulting in blocked interface requests.

## How to confirm the configuration is complete
- Run the `docker ps` command to confirm that all FastGPT-related containers are in running status, with no abnormal exit records.
- Upload a CAD pattern file to confirm that the file can be stored normally and retrieved in the document list of the knowledge base.
- Initiate a document parsing request for a process quality sheet to confirm that the parsing result includes complete process quality inspection fields and fabric batch information.
- Access the background management address corresponding to `FE_DOMAIN` to confirm that you can log in normally and view the connection status of the database and cache.

The values provided are common starting points and should be evaluated against the reader's own samples.
