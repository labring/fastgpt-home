# Supplier and Process Quality Audits for Incoming Material Inspection and Supplier Quality: Tool Calling and Plugins

## What the data for this category looks like
The data for this category comes from purchase orders, drawings and specifications, supplier quality certificates, inspection equipment, historical quality data, and supplier portals. Daily associated documents include inspection specifications, sampling plans, incoming material reports, supplier audit reports, exception contact sheets, 8D reports, and concession acceptance approval documents. Data updates are triggered with each batch of incoming materials, monthly or quarterly supplier evaluations, and irregular audits. Core fields include incoming material batch number, supplier code, inspection items, qualified judgment results, sampling quantity, and deviation values. Units vary by inspection item type, and there is no unified fixed format.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
Data sources are scattered and connected to multiple external systems. Tool calling must support docking with multiple data source interfaces to avoid data fragmentation. Update frequency fluctuates with production batches. Tool calling must adapt to batch trigger logic to support fast inspection processes for single batches of incoming materials. There are diverse document types and inconsistent formats. Plugins must adapt to parsing rules for different documents and extract core inspection fields. Quality results are directly linked to production links. Tool calling must configure failure retry and verification mechanisms to reduce the risk of defective materials entering production. The collaborative nature of external suppliers requires tool calling to be compatible with interface current limiting rules of supplier portals.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to tool calling matching requirements for multiple types of quality documents |
| Batch execution node timeout | 600–1200 seconds | Cover the entire process processing time for single-batch incoming material inspection |
| Maximum parallel calls | First 3 | Match the interface current limiting threshold of the supplier portal to avoid triggering call restrictions |
| Plugin input parameter validation | Enable required validation for batch numbers and inspection items | Align with core field requirements for incoming material inspection and reduce invalid calls |
| `functionCall` | Trigger subsequent nodes based on tool return results | Adapt to the process logic for generating exception contact sheets |
| Tool calling retry count | 2 times | Respond to temporary fluctuations in supplier interfaces |

## Three Common Mistakes
- When calling the large model in a loop within a batch execution node, online debug can complete the entire process, but API calls cannot execute all steps. The reason is that online debug uses local temporary resources, and the concurrency limit of the batch node is not configured during API calls, exceeding the supplier interface current limit.
- After calling the workflow via the interface, running data in the conversation log is empty. The reason is that the workflow's log collection switch is not enabled, or tool calling does not correctly map data source fields.
- After the custom plugin runs, the output download address keeps jumping before finally returning the result. The reason is that the plugin contains asynchronous requests that are not waited for to complete, resulting in abnormal result return timing.

## How to Confirm Proper Configuration
- Initiate a test call for a single batch of incoming materials, check whether the tool correctly pulls the corresponding supplier's quality certificate and historical quality data.
- Trigger the batch execution node, check whether the FastGPT v4.17.0 workflow log displays the execution results of all loop steps.
- Verify whether the plugin call generates an exception contact sheet or 8D report template that conforms to the required format.
- Simulate a temporary interface fluctuation scenario, check whether the tool calling triggers the preset retry mechanism.

The values provided are common starting points and should be measured against the reader's own samples.
