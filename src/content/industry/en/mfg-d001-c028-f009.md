# Supplier and Process Quality Audits for Incoming Material Inspection and Supplier Quality: Model Access and Configuration

## What data looks like for this category
Data sources for this category include purchase orders, drawings and specifications, supplier quality certificates, data collected by inspection equipment, historical quality records, and supplier portals. Daily processed documents cover inspection specifications, sampling plans, incoming material reports, supplier audit reports, exception contact sheets, 8D reports, and concession acceptance approval documents. Data update cadence is synchronized with each incoming material batch. Overall supplier evaluations are completed monthly or quarterly, and special quality audits are conducted irregularly. Data fields include incoming material batch numbers, inspection item parameters, non-conformity judgment results, supplier numbers, and inspection dates. Some fields have physical units or standardized number formats.

## What constraints these characteristics impose on model access and configuration
The multi-source and scattered data sources require access configuration to adapt to documents and system data in different formats, to avoid loss of key fields. The frequently updated incoming material batch data requires that the context window retains associated metadata such as suppliers and batches, and must not truncate excessively to break audit logic. Diverse document structures require configuring appropriate context and reference lengths to ensure that original inspection basis can be fully called during audits. At the same time, quality audits require rigorous and unified judgment logic, which has clear requirements for the stability of model output, so the value range of random parameters must be limited.

## How to set configurations
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | This category requires retaining associated metadata such as incoming material batches, supplier information, and historical quality records to avoid truncating key audit basis |
| `maxTokens` | `2000–3000 token` | Single-round audit replies need to include judgment conclusions, rectification suggestions, and reference basis to avoid truncation of output content |
| `quoteMaxToken` | `1500 token` | Original document fragments such as inspection specifications and sampling plans need to be fully referenced as audit support, controlling the total length of referenced content |
| `temperature` | `0.2–0.4` | Quality audits need to maintain consistency of judgment logic, reducing random fluctuations in output results |
| `AIPROXY_API_ENDPOINT` | Fill in the private proxy address deployed in actual use | Adapt to the internal enterprise model call link to ensure data does not leave the private network |
| `AIPROXY_API_TOKEN` | Configure enterprise-specific verification tokens | Ensure the identity legitimacy of model calls and prevent unauthorized access |

## Three common mistakes
- Model calls return a 401 unauthorized error, caused by incorrect configuration of `AIPROXY_API_TOKEN`, or a mismatch between the token and the proxy address.
- Audit results lack incoming material batch or supplier associated information, caused by an excessively small `maxContext` value that truncates key metadata content.
- Service experiences abnormal restarts or infinite retries, caused by `maxTokens` exceeding the response limit of the model interface, leading to repeated failures in the call link.

## How to confirm the configuration is correct
- Enter a typical audit query that includes incoming material batch and supplier information, check whether the reply fully associates the corresponding fields to confirm that the context parameters take effect.
- Initiate a test call, check whether the token consumption value of the returned result is within the configured `maxTokens` range to confirm that the output truncation logic is correct.
- Initiate a call with an invalid token, confirm that an unauthorized error is returned to verify that the identity verification configuration takes effect.
- Enter the same audit query twice, compare the logical consistency of the two replies to confirm that the temperature parameter configuration meets expectations.

The values provided are common starting points and should be measured against the reader's own samples.
