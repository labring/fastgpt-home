# Supplier and Process Quality Audits for Incoming Material Inspection and Supplier Quality: Deployment and Upgrade

## What this category of data looks like
This category of data mainly comes from purchase orders, drawing specifications, supplier quality certificates, inspection equipment, historical quality data, and supplier portals. Daily documents include inspection specifications, sampling plans, incoming material reports, supplier audit reports, exception contact sheets, 8D reports, and concession acceptance approval forms. Data updates occur with each incoming batch, monthly or quarterly supplier evaluations, and ad-hoc special audits. Data fields include incoming batch identifiers, inspection parameters, non-conformity judgment results, supplier ratings, and some fields are associated with units such as physical dimensions and quantities.

## What constraints these characteristics impose during deployment and upgrade
Since this category of data originates from multiple internal and external systems including purchase orders, supplier portals, and inspection equipment, permission and synchronization rules for cross-system integration must be configured during deployment. Because data updates occur with each incoming batch, monthly or quarterly supplier evaluations, deployment parameters must support high-frequency incremental synchronization to avoid synchronization delays that disrupt audit workflows. Multiple types of quality documents require matching parsing and storage configurations to ensure normal indexing of files in different formats such as inspection specifications and 8D reports. Fields associated with data such as batch identifiers and inspection parameters must strictly align with business definitions. Field mapping rules must be preset during deployment to prevent data misalignment that leads to audit errors.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `STORAGE_S3_ENDPOINT` | `http://minio-service:9000` (intranet environments can use private domain names) | Adapt to the storage needs of multi-source quality documents for this category; intranet environments can complete local storage integration without public network exposure |
| `REDIS_URL` | `redis://:password@redis-host:6379/0` | Support high-frequency incoming inspection data caching and real-time synchronization; 6379 is the default Redis port |
| `DB_MAX_LINK` | `20–30` | Adapt to high-frequency data writes generated by each incoming batch to avoid connection pool exhaustion |
| `MONGODB_URI` | `mongodb://user:pass@mongodb-host:27017/iqc_db?authSource=admin` | Store historical quality data and supplier audit reports; adapt to storage needs for unstructured documents |
| `ROOT_KEY` | `Custom strong key string` | Ensure permission security for system backend operations; must comply with internal enterprise key management specifications |
| `FILE_TOKEN_KEY` | `Custom encryption key` | Encrypt access tokens for files such as incoming material reports and supplier quality certificates to prevent unauthorized access |

## Three common mistakes
- Phenomenon: After deployment, files such as supplier quality certificates and incoming material reports fail to load, and a storage connection failure prompt appears on the interface. Cause: The `STORAGE_S3_ENDPOINT` was incorrectly configured as a public network access address, the private deployment requirements of the intranet environment were not addressed, and storage configuration adjustments were not made by referring to the FastGPT v4.17.0 plugin system update notes.
- Phenomenon: When configuring the supplier data synchronization interface, no oneapi-related configuration items can be found, and the interface call returns parameter errors. Cause: The oneapi docking environment variables were not added to the docker compose configuration file, and correct parameter names and values were not configured by referring to official documentation.
- Phenomenon: When pushing incoming inspection data in batches, some fields are parsed as empty, and supplier rating calculations cannot be completed. Cause: No multi-field mapping rules for incoming material reports were preset, resulting in parsed fields that do not match business definitions, and configuration was not completed based on the document structure of this category.

## How to confirm the configuration is complete
- Log in to the system backend, upload a standard incoming material report, check whether the file can be stored and previewed normally, and verify that the `STORAGE_S3_ENDPOINT` configuration matches the actual storage address.
- Run a simulated incoming data synchronization task, check whether the `REDIS_URL` and database connections are normal, and confirm that data can be written to the corresponding storage repository.
- Configure a webhook push rule, trigger an exception contact sheet push, check whether the callback data includes the required business fields, and confirm that the field mapping rules are in effect.
- Verify backend operation permissions, use the account corresponding to `ROOT_KEY` to perform configuration modifications, and confirm that permission verification works normally.

The values provided are common starting points and should be measured against the reader's own samples.
