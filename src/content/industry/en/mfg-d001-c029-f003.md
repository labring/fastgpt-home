# Supplier and Process Quality Audit for Mold Design and Manufacturing: Multi-turn Dialogue and Prompt Engineering

## Data Structure for This Category
Data for this category revolves around the full lifecycle of molds. It typically comes from customer product models, mold flow or forming simulation files, CAD/CAM design source files, machining and coordinate measuring machine data, and sample part inspection records. Daily generated documents include mold design task sheets, DFM reports, part drawings, machining process cards, mold trial reports, mold modification notices, and mold history logs. Data updates follow a per-project workflow, with new version files created after each mold trial or modification operation.

## Constraints on Multi-turn Dialogue and Prompt Engineering
The data characteristics of this category create clear constraints for multi-turn dialogue and prompt engineering configurations.
Diverse, heterogeneous document types (CAD source files, simulation reports, measurement data) require dialogue support for recognizing uploaded attachments in different formats, and prompts must adapt to the dedicated field logic of each document type.
Project-driven update cycles require dialogue contexts to be bound to project identifiers, to prevent cross-project data confusion.
High-frequency mold trial and modification iterations require multi-turn dialogue to retain historical modification records as reference material, and prompts must prioritize calling the latest version of associated documents.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique identifier of a single mold project | Prevent cross-project dialogue context confusion, ensure multi-turn dialogue only associates documents and historical records for the current project |
| `messages` | Retain the first 20 turns of dialogue content, with each turn not exceeding 1500 characters | Adapt to the dialogue length required for multi-turn mold project reviews, avoid information loss caused by context overflow |
| `variables` | Pre-set three variables: project number, mold type, current mold trial stage | Quickly call project-specific data, reduce repeated entry of project information in prompts |
| Maximum context length | 8000–12000 token | Cover dialogue and document content across the full mold design, mold trial, and modification process |
| Single retrieval limit | Top 8 matching results | Adapt to the multi-dimensional associated attributes of mold documents, avoid excessive redundant information interfering with audit judgments |

## Three Common Misconfigurations
- Phenomenon: A 503 error appears when uploading mold design files in STEP or STP format, but no error occurs when uploading knowledge base text files. Cause: The attachment parsing configuration for the dialogue scenario does not support mold-specific CAD formats, leading to parsing request timeouts that trigger the error.
- Phenomenon: When using a strict question-answering template to retrieve the knowledge base, if an image address for a sample part is matched, the system prompts that no answer was found. Cause: The strict question-answering template only matches structured text fields, with no associated parsing rules configured for image content, so it cannot convert image addresses into retrievable information.
- Phenomenon: When sending consecutive AI dialogue requests, subsequent requests must wait for the previous generation to complete, and the current generation process cannot be interrupted. Cause: No streaming output or session isolation rules are configured for the dialogue, causing requests with the same `chatId` to be processed serially.

## How to Verify Proper Configuration
- Upload mold design files in STEP or STP format, confirm no errors occur and key document information can be extracted in the dialogue.
- Initiate a multi-turn dialogue after configuring project-specific variables, confirm that preset project parameters are automatically included in the prompt.
- Send two dialogue requests with a very short interval, confirm support for interrupting the current generation and processing the new request.
- Switch the question-answering template to retrieve knowledge base entries containing sample part image addresses, confirm that the return logic of different templates meets expected behavior.

The values provided are common starting points and should be measured against the reader's own samples.
