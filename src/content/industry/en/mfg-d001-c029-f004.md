# Supplier and Process Quality Audit for Mold Design and Manufacturing: Workflow Orchestration

## What the data for this category looks like
This category's data primarily comes from product models, mold flow or forming simulation files, CAD/CAM design files, machining and measurement data delivered by customers, plus inspection records of trial-molded samples. Daily associated documents include mold design task sheets, DFM reports, part drawings, machining process cards, mold trial reports, mold modification notices, and mold history logs. Data updates are carried out on a per-project basis, with new versions and records generated after each mold trial or modification operation. Documents typically include dedicated fields such as mold number, part tolerances, and defect descriptions.

## What constraints these characteristics impose on workflow orchestration
The data characteristics of this category impose multiple constraints on workflow orchestration. Multi-source heterogeneous data formats require workflows to support parsing and adaptation of multiple file types, to avoid node execution failures caused by format incompatibility. The project-triggered update rhythm requires workflows to bind project-level variables, ensuring that each mold project runs its process independently. The presence of dedicated document fields requires workflows to be configured with customizable variable capture rules, to accurately extract key information such as mold numbers and mold trial defects. Additionally, the iterative mold trial and modification process requires workflows to support branch jumps and loop execution, to adapt to the needs of multiple rounds of review and adjustment.

## How to set the configuration
This configuration is designed based on the workflow orchestration feature of FastGPT v4.17.0. The specific configuration items are as follows:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Variable Configuration | Preset `variables` per project template, including fields such as mold number, mold trial defect items, and mold modification times | This category of documents contains dedicated business fields, which need to be bound to project-level custom variables |
| Node Trigger Rule | Bind upstream node execution results for triggering via `nodeId` | Workflows need to trigger subsequent processes based on the upload nodes of different documents such as mold trial reports and mold modification notices |
| File Upload Size Limit | `1000 MB` | Adapt to the large-volume storage requirements of CAD assembly files and mold flow simulation data |
| Loop Execution Count | `0–20 times` | Match the number of multi-round mold trial and modification iterations typically required for this category |
| Node Timeout Setting | `1200 seconds` | Meet the time requirements for CAD file parsing and complex mold flow data processing |
| Knowledge Base Association Rule | Select the corresponding knowledge base based on the mold type of the project | Call dedicated design specifications and defect handling experience bases to support the audit process |

## Three common mistakes
- Phenomenon: After the tool call node executes, the results are directly displayed in the workflow final output panel and cannot be hidden. Cause: No output filtering rule is set in the `variables` configuration, and the raw data returned by the tool is mistakenly bound to the global output variable.
- Phenomenon: CAD, mold trial report and other files uploaded in the local environment can be read normally by the parsing node, but a 404 error is triggered when the same files are uploaded after server deployment. Cause: No static file storage path mapping is configured on the server side, causing the parsing node to fail to access the uploaded file address.
- Phenomenon: After the workflow executes, the mold trial defect information extracted by the review node is empty, and it cannot enter the subsequent mold modification branch. Cause: The output of the upstream document parsing node is not bound via `nodeId`, causing key business fields to not be correctly captured.

## How to confirm the configuration is correct
- Upload a test mold design task sheet, check whether the document parsing node can correctly extract fields such as mold number and project name, and verify whether the extraction result matches the field mapping of the preset `variables`.
- Trigger a complete workflow process, check whether the node trigger rule correctly jumps based on the upstream node execution result bound via `nodeId`, and verify whether the loop execution count meets the project iteration requirements.
- After configuring the file upload size limit, upload a CAD file that exceeds the preset threshold, and check whether the node can correctly intercept and prompt an exception.
- Adjust the knowledge base association rule, switch between different types of mold projects, and check whether the workflow can automatically match the content of the corresponding knowledge base.

The values given are common starting points and should be measured against the reader's own samples.
