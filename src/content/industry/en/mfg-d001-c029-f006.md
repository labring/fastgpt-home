# Supplier and Process Quality Audits for Mold Design and Manufacturing: Source Citation and Traceability

## What data for this category looks like
Daily documents for this category include mold design task sheets, DFM reports, part drawings, machining process cards, trial mold reports, mold modification notices, and mold history records. Data sources include customer product models, mold flow or forming simulation files, CAD/CAM design files, machining and measurement data, and trial mold sample inspection records. Data updates follow individual project cycles. New version files are generated after each trial mold or mold modification. Documents include both structured and unstructured fields such as part dimension parameters, machining tolerances, trial mold defect records, and mold modification plans.

## What constraints do these characteristics impose on the source citation and traceability link
Documents for mold design and manufacturing are mostly engineering files with precise dimensions and tolerances, and are updated iteratively per project and trial mold/modification cycles. Source citation and traceability must match content across different file versions. CAD files and simulation data from different sources have significant format differences. Traceability must link back to the original generation tool and submission time. Multiple rounds of mold modifications during a project cycle create a large number of version files. Traceability must accurately distinguish documents from different stages of the same project, to avoid confusing content created before trial mold and after mold modification. Supplier audits require linking machining data to trial mold reports. The traceability link must cover multiple types of data generated across departments and tools, to ensure the sources of audit basis are traceable.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `quoteMaxToken` | `800–1200 token` | Mold design documents are mostly engineering drawings and reports, with moderate effective content length per document. This setting avoids truncating critical dimensions or mold modification records, and adapts to the context processing rules of FastGPT v4.17.0 |
| `responseData` | Return only matching document metadata and snippets | Supplier audits require clear citation of document type and version number of the source, without redundant raw file binary content |
| `detail` | Enable full field display | Details such as dimensions on mold part drawings and defect descriptions in trial mold reports must be extracted to support audit judgments |
| Single search limit | Top 6 results | The number of related documents for mold projects is moderate. Too many results will increase context redundancy, while too few may miss critical mold modification records |
| Maximum context length | `4000–6000 characters` | Must accommodate key content from multiple trial mold reports and mold modification notices, while avoiding exceeding model processing limits |

## Three Common Misconfigurations
- Phenomenon: When applying variables in the knowledge base search node, there are no selectable options in the reference variable dropdown menu. Cause: The variable binding rules for the corresponding knowledge base have not been configured in advance, or the variable scope does not cover the current audit workflow.
- Phenomenon: It is impossible to distinguish the source of mold machining data submitted by different suppliers in system logs. Cause: No supplier identification field has been configured in the document metadata, or source field extraction has not been enabled in the traceability configuration.
- Phenomenon: Fake citation IDs that do not match actual documents appear in answers generated by the large model. Cause: Unique identifier verification for document metadata has not been enabled, or recalled documents and citation IDs have not been bound and associated.

## How to Confirm Correct Configuration
- Initiate a supplier audit request for a mold project, and check whether the output content includes the source name, version number and generation time of the corresponding document.
- View system logs to confirm that each recalled document has a unique source identifier, and that it corresponds one-to-one with the citation IDs in the answer.
- Test the dynamic knowledge base specification function, and confirm that the reference variable dropdown menu displays configured knowledge base variables after variable application.
- Enter a query containing trial mold defect descriptions, and check that automatically spliced citation marker text does not appear in the output.

The values provided here are common starting points, and should be measured against the reader’s own samples.
