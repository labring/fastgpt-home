# Supplier and Process Quality Audit for Mold Design and Manufacturing: Model Access and Configuration

## What the data for this category looks like
The daily documents for this category include mold design task sheets, DFM reports, part drawings, processing technology cards, trial mold reports, mold modification notices, and mold records. Data mainly comes from customer product models, mold flow or forming simulations, CAD/CAM, machining and measurement data, and trial mold samples. Data updates are carried out according to projects, and are synchronized each time a mold is trial-produced or modified. The document structure and fields vary across different projects, and some documents include subdivided fields such as the number of mold cavities, draft angle, material grade, and machining accuracy requirements.

## What constraints these characteristics impose on the model access and configuration link
The diverse daily document types and inconsistent structures require that model access must support multi-format document parsing and field extraction adaptation. The frequency of data updates increases with project iterations, so access logic that supports incremental synchronization must be configured to avoid full-volume repeated loading. The subdivided fields vary greatly across different projects, so configuration space for custom field mapping must be reserved. Real-time data generated from mold trials and modifications must be accessed quickly, which places certain requirements on the real-time performance of model responses. Mold-related data involves the accuracy requirements of production tooling, and the audit results output by the model must have high accuracy. Therefore, the configuration of parameters such as context length and token limits must match the business scenario.

## How to set the configurations
| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Matches the average length of mold design documents, ensuring that context information related to DFM reports and part drawings can be fully loaded during audits |
| `maxTokens` | 4000–6000 token | Limits the output length of a single reply, avoiding reduced audit efficiency caused by overly long content, and adapts to the concise needs of process quality audits |
| `quoteMaxToken` | 2000–3000 token | Limits the total token count of referenced documents, ensuring that retrieved content such as trial mold reports and processing technology cards can be fully included in the audit logic |
| `temperature` | 0.2–0.4 | Reduces output randomness, ensuring consistency of audit conclusions such as mold accuracy and demolding feasibility |
| `AIPROXY_API_ENDPOINT` | Proxy address deployed according to business needs | Adapts to the internal corporate network environment, ensuring the stability and data security of model calls |
| `AIPROXY_API_TOKEN` | Calibrated through actual testing | Matches the authentication requirements of the proxy service, ensuring the legality of access |

## Three common mistakes
- Phenomenon: After upgrading FastGPT v4.17.0, the retrieval time of the same knowledge base and embedding model increases significantly, and the conversation response time exceeds 10 seconds. Cause: The `maxContext` parameter is not adjusted according to the length of mold design documents, resulting in excessive redundant context data being loaded each time a call is made.
- Phenomenon: Configuration cannot be completed when attempting to access an enterprise messaging robot, and no officially supported alternative solution is found. Cause: A custom API access channel is not configured through the workflow module, and only the officially built-in access template is used.
- Phenomenon: After publishing a workflow as a personal WeChat channel, only a single person can scan the code to use it, and multi-person collaborative access cannot be implemented. Cause: The access permission of the workflow is not configured as team shared mode, and only a personal temporary access link is opened.

## How to confirm the configuration is correct
- Upload a complete mold design task sheet and trial mold report, test whether the model can correctly extract key audit items, and check whether the output content covers the core information of the documents.
- Simulate multiple mold trial and modification scenarios, trigger the data synchronization process, and confirm that newly uploaded mold modification notices can be normally retrieved and referenced by the model.
- Adjust the `temperature` parameter, compare the output results of two identical audit requests, and confirm that the result consistency meets business requirements.
- Call the test interface to verify the configuration validity of `AIPROXY_API_TOKEN` and `AIPROXY_API_ENDPOINT`, and confirm that there are no authentication or connection errors.

The values provided here are common starting points and should be evaluated against the actual samples relevant to the deployment context.
