# Supplier and Process Quality Audit for Rubber Compounding and Product Vulcanization: Vector Models and Indexes

## What Data Looks Like for This Category
Typical entities in this category are tire, seal, hose, and rubber product manufacturers. Daily produced documents include formula sheets, weighing records, mixing curves, rubber quick test reports, vulcanization process cards, mold records, and finished product performance reports.
Data sources cover formula management systems, raw material batch ledgers, internal mixers, Mooney viscometers, rheometers, vulcanizers, and laboratory testing equipment. Updates occur per raw material batch, per mixed rubber batch, and per vulcanized product per mold.
Each document includes fields such as batch number, equipment number, process parameter values, and test results. Some documents include visual curves or tabular data.

## Constraints Imposed on Vector Models and Indexing
Indexes must support incremental synchronization for high-frequency batch data, to avoid performance loss from full reconstruction.
Mixed multi-source document formats include structured numerical fields and unstructured curve screenshots. Vector encoding must adapt to mixed data types, rather than relying solely on plain text encoding.
Audit requirements demand precise matching, so retrieval results must be filtered by business dimensions and only return compliant records within the associated scope.
Small per-batch data volume with frequent updates requires index chunking and retrieval logic to adapt to small-batch high-frequency synchronization scenarios, balancing retrieval speed and data integrity.

## Configuration Settings
This page’s configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Values | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the semantic integrity of single segments of documents such as mixing curves and complete process cards, avoiding splitting critical formula parameters |
| Overlap Length | 100–150 characters | Retains associated information such as batch numbers and equipment numbers across chunks, preventing retrieval matching deviations caused by semantic breaks |
| Similarity Threshold | 0.75–0.85 | Meets the precise audit requirements for mixing process parameters and formula ratios, filtering irrelevant retrieval results |
| Single Search Limit | Top 10 entries | Covers associated historical records for single-batch mixing and vulcanization, avoiding redundant data interfering with audit judgments |
| `maxToken` | 4096 | Adapts context passing for long documents such as complete mixing curve logs, avoiding truncation of critical temperature and torque parameters |
| `defaultToken` | 150 | Controls the encoding length of a single vector, balancing retrieval accuracy and system resource usage |

## Three Common Mistakes
- Retrieval results include rubber compound data from non-current batches. Search results show mixing records unrelated to the audit batch. The cause is missing index filtering rules based on raw material batch and equipment number, with irrelevant data mixed in due to reliance only on semantic matching.
- Vector encoding fails. The interface displays an encoding error prompt. Logs show field format errors. The cause is missing preprocessing for structured numerical fields in mixing curves and vulcanization process cards, with encoding applied directly to original binary or unformatted text.
- Retrieval requests time out. The system returns a loading timeout prompt box. The cause is excessively large chunk length settings, causing vector generation and retrieval for single-batch data to occupy excessive memory and computing resources.

## How to Confirm Proper Configuration
- Import a single batch of mixing records and corresponding formula sheets, initiate a retrieval request for "verify if the current batch's feeding meets formula requirements", and check if returned results only include associated data for this batch.
- Upload a complete mixing curve document, check if the number of chunks after vector encoding matches the set chunk length, with no obvious parameter truncation.
- Adjust the similarity threshold to 0.8, retrieve historical records of the same type of process parameters, and confirm that the relevance of returned results meets business audit needs.
- Run a batch incremental synchronization test, check if the system can complete index updates for new batch data without abnormal error prompts.

The values provided are common starting points and should be measured against the reader's own samples.
