# Supplier and Process Quality Audit for Complete Vehicle Final Assembly: HTTP Interfaces and External Systems

## What the data for this category looks like
The typical entities for this category are passenger vehicle, commercial vehicle, and new energy vehicle complete vehicle manufacturers. Core daily documents include production orders, VIN lists, assembly work instructions, tightening data, off-line inspection reports, rework records, and consistency and release documents. Data sources cover ERP/MES, VIN and configuration systems, supplier batch management systems, tightening tools, EOL inspection lines, and quality traceability systems. Update frequencies include per vehicle, real-time, and per shift. In core business workflows, matching hundreds of configuration and part items by VIN is the most time-consuming step, while key connection torque must be controlled and cross-station off-line defects must be addressed.

## What constraints do these characteristics impose on the "HTTP Interfaces and External Systems" link
The business characteristics of this category impose multiple constraints on interface calls. First, the mixed-line production model centered on VIN as the main vehicle thread requires interfaces to support precise query of corresponding configurations, parts, supplier batches and other data by VIN. Second, real-time updated tightening data and off-line inspection reports require low-latency interface responses to avoid blocking production line beat. Third, multi-source heterogeneous system data (ERP, MES, inspection equipment) needs to adapt to different interface formats and verification rules. Finally, the consequences of errors directly relate to vehicle off-line, line stop, or even recall risks, requiring interfaces to have reliable fault tolerance mechanisms to avoid production interruptions caused by interface anomalies.

## How to set the configurations
| Configuration Item | Recommended Practice | Rationale |
| ---- | ---- | ---- |
| Identity Verification Configuration | Bearer {Enterprise-specific API Key} | Complies with identity verification requirements of supplier systems and internal production systems, preventing unauthorized access to core production data |
| Global Variable Binding | Bind VIN codes and supplier batch numbers as global variables | Adapts to audit requirements for individual vehicles or batches, reduces repeated parameter passing, and lowers the probability of interface call errors |
| Response Field Filtering | Only return VIN matching results, tightening torque qualified values, and off-line inspection status fields | Filters redundant data, reduces interface transmission load, and meets the low-latency requirements of real-time audits |
| Timeout Threshold | 30–60 seconds | Adapts to the real-time response requirements of tightening data and off-line inspections, avoiding blocking production line beat |
| Retry Strategy | Retry 2 times after failure, with a 5-second interval | Addresses temporary network fluctuations or short-term system unavailability, ensuring uninterrupted production line data synchronization |

## Three Common Mistakes
- Request returns a 400 status code, caused by failure to correctly pass required fields such as VIN codes and batch numbers, which does not meet the verification rules of the supplier system.
- The getaddrinfo EAI_AGAIN error occurs, caused by the proxy configuration not correctly pointing to the internal system domain name, or network policies restricting access permissions for the specified interface.
- Audit data lacks key fields, caused by not configuring response field filtering rules, which causes the system to filter out key audit information such as tightening torque and VIN matching results.

## How to confirm the configuration is correct
- Call the test interface, pass a known compliant VIN code, and check that the returned results include core fields such as expected configuration matching and tightening data.
- Simulate network fluctuations to trigger interface call failures, and check whether the system automatically executes the retry strategy and resumes data synchronization.
- Check the FastGPT v4.17.0 system logs to confirm that the identity verification configuration has passed, and there are no unauthorized access related errors.
- Compare the interface returned data with the original production data from the ERP system to confirm that the field matching logic meets business requirements.
