# Supplier and Process Quality Audit for Complete Vehicle Final Assembly: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
The core thread of data for this category is individual vehicle VINs. Daily documents include production orders, VIN lists, assembly work instructions, tightening data, off-line inspection reports, rework records, and consistency release documents.
Data sources cover ERP/MES systems, VIN and configuration systems, supplier batch ledgers, tightening tools, EOL inspection lines, and quality traceability systems.
Updates are generated in real time per vehicle and summarized and archived per shift.
Core fields include VIN codes, assembly torque values, part batch numbers, inspection qualification status, and some data requires matching hundreds of vehicle configuration and part information.

## What Constraints This Category Imposes on Multi-turn Dialogue and Prompt Engineering Processes
The single-vehicle data structure centered on VINs creates multiple constraints for multi-turn dialogue and prompt engineering workflows.
Bind the current VIN parameter during dialogue initialization to avoid confusion across vehicle configurations.
Real-time generated tightening data and off-line inspection reports require the dialogue to quickly recall the latest documents, so redundant historical data in the context window must be limited.
The need to match hundreds of vehicle configurations requires prompts to explicitly limit the context scope, only calling assembly work instructions and part lists related to the current VIN.
The shift-based data summarization feature requires the dialogue to filter supplier batch data by time range, and also handle repeated quality audit requests across multi-turn conversations.

## How to Configure Settings
These configurations are adapted for FastGPT v4.17.0:
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `variables` | Bind current VIN code, production shift ID | Ensure the dialogue only processes audit requests related to the current vehicle and production shift, avoiding cross-vehicle data confusion |
| `chatId` | Bind unique workstation identifier and VIN suffix | Differentiate sessions across workstations and vehicles, enabling isolation of multi-user chat records |
| `messages` | Retain the most recent 15–20 dialogue messages | Adapt to the multi-turn interaction rhythm of mixed-line production, reducing redundant context usage |
| Maximum context length | 8000–12000 token | Cover the text length requirements of hundreds of vehicle configurations, avoiding exceeding system processing limits |
| Timeout setting | 600 seconds | Match the waiting period for retrieving real-time tightening data and off-line inspection reports |

## Three Common Misconfigurations
- Symptom: Failed to parse documents such as assembly work instructions and tightening data when calling external tools, with a tool call failure prompt displayed. Cause: The current VIN parameter was not bound in `variables`, so the tool could not match the retrieval conditions for the corresponding documents.
- Symptom: Specified reply plugin logs from historical conversations are carried over into the current audit process, interfering with result judgment. Cause: No historical message filtering rules were configured, leaving non-audit-related plugin operation records intact.
- Symptom: Chat records from different users are cross-contaminated when multiple workstations initiate audits simultaneously. Cause: No unique identifier for workstations and VIN was bound using `chatId`, so session isolation configuration is missing.

## How to Verify Proper Configuration
- Initiate a test dialogue bound to a known VIN, verify that the dialogue context only displays assembly document retrieval results related to that VIN.
- Simulate session initiation from multiple workstations, check that sessions with different `chatId` have independent chat records with no cross-contamination.
- Trigger a tool call request, verify that the tightening data documents for the corresponding VIN can be parsed normally, with no tool call failure prompts.
- Insert historical plugin call logs into the dialogue, verify that the system automatically filters out non-audit-related historical records.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
