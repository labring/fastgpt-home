# Supplier and Process Quality Audit for Complete Vehicle Final Assembly: Tool Calling and Plugins

## What the data for this category looks like
The core of the data for this category is the single Vehicle Identification Number (VIN). Daily documents include production orders, VIN lists, assembly work instructions, tightening data, off-line inspection reports, rework records, consistency and release documents. Data sources cover ERP/MES systems, VIN and configuration systems, supplier batch ledgers, tightening tools, EOL inspection lines, and quality traceability systems. Updates trigger per vehicle, in real time, or per shift. Fields include VIN codes, tightening torque values, inspection item results, and other relevant data. The data has multi-dimensional association characteristics for mixed-line production.

## What constraints these characteristics impose on the tool calling and plugins workflow
Single-vehicle data association centered on VIN requires tool calls to accurately match the configuration and parts list corresponding to the target VIN, to avoid mixing data across vehicles. Real-time updated tightening data and off-line inspection reports require tool calls to support low-latency real-time data pulling, to ensure audit links obtain the latest status. For mixed-line production scenarios with parallel workstations, plugins must support filtering documents and data for the corresponding workstation by VIN. Strict validation of call parameters is also required, to prevent incorrect quality judgments caused by parameter errors and avoid subsequent production line downtime or recall risks.

This document is written for FastGPT v4.17.0.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Automatically match quality audit tools | Adapt to VIN-based audit workflows, automatically select the appropriate tool to process different types of quality documents such as tightening data and off-line inspection reports |
| Tool call timeout period | 600-900 seconds, calibrated via actual testing | Cover the full process of pulling all quality data associated with a single VIN from multiple systems, avoid call interruptions caused by large data volumes |
| Number of items returned per tool call | First 10 items | Match the limited number of assembly and inspection records corresponding to a single VIN, avoid redundant data interfering with audit logic |
| `functionCall` | Trigger per audit node | Ensure that corresponding tools are called at key nodes such as supplier batch verification, workstation tightening verification, and off-line inspection verification, to accurately process quality data for the corresponding link |
| Cross-domain access configuration | Bind no more than 3 production system domain names | Support third-party production systems to call FastGPT interfaces via browsers, comply with security access specifications for industrial scenarios |

## Three Common Configuration Mistakes
- Symptom: Cross-domain error returned when calling third-party quality system interfaces, with status code 403 or CORS verification failure. Cause: FastGPT cross-domain access whitelist is not configured, and legitimate domain names of production systems are not bound.
- Symptom: Tool calls do not filter data by VIN, returning quality records for the entire workshop. Cause: Automatic matching rules for `toolChoice` are not configured, or VIN is not passed as a filter condition in call parameters.
- Symptom: Tool calls return empty results, and tightening torque data cannot be obtained. Cause: Timeout period is set too short, failing to cover the full duration of pulling associated data from multiple systems, or access permissions for the corresponding data source are not configured.

## How to Verify Successful Configuration
- Submit a quality audit request for a single VIN, check whether tool calls automatically trigger the processing logic for the corresponding link, and confirm that the matching rules for `toolChoice` are active.
- View interface call logs, confirm that cross-domain access only allows the configured production system domain names, with no illegal access blocked.
- Simulate a timeout scenario, verify whether the tool call timeout period meets the actual data pulling duration requirements, and confirm there are no frequent timeout errors.
- Pass a test VIN, check whether the returned quality data only includes tightening and inspection records for the corresponding vehicle, with no redundant cross-vehicle data.
