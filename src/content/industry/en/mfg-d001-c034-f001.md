# Supplier and Process Quality Audit for Baked Goods and Convenience Foods: HTTP Interfaces and External Systems

## What data looks like for this category
Production entities include bread and pastry, biscuit, instant noodle, and frozen pastry factories. Daily documents cover formulas and feeding lists, production records, baking or steaming curves, metal detection records, cleaning and disinfection records, and factory inspection reports. Data sources include raw and auxiliary material qualification certificates, ERP/MES systems, weighing systems, ovens or frying lines, laboratory testing equipment, and food traceability ledgers. Update frequency is per batch, per shift, or daily. Core time-consuming steps include reviewing formulas and allergen materials, controlling proofing, baking, or frying windows, verifying foreign matter control and packaging dates. Consequences of errors may include unqualified taste and moisture, incorrect allergen labeling, or product recalls. This category has more prominent control needs for allergens and cleaning switching due to multiple formulas, frequent line changes, and direct-edible products.

## What constraints these characteristics impose on HTTP interfaces and external systems
Multi-batch, high-frequency production data for this category requires HTTP interfaces to support a mixed invocation mode of batch pulling and real-time callbacks. Data from multiple sources requires interfaces to adapt to the authentication formats and field structures of different systems, especially the mapping of core fields such as allergens, shelf life, and test results. Dynamic formula requirements brought by frequent product line changes require interfaces to flexibly adapt to the audit rules of different products through variable passing. Production documents and test records named in Chinese require interfaces to support correct encoding formats to avoid garbled characters in file names or field content. The strict compliance requirements of audit scenarios require that only core audit fields are retained in data transmitted by the interface, and redundant logs and non-essential information are filtered out.

## How to set up the configuration
This setup is based on FastGPT v4.17.0.

| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| `Authorization` configuration | Fixed prefix with factory-specific secret key, formatted as `Bearer {secretKey}` | Matches the authentication format of most industrial ERP/MES systems, avoids authentication field errors |
| `variables` mapping configuration | Map field names of raw and auxiliary materials and production records, cover allergen lists and baking temperature ranges | Adapts to multi-formula, multi-field document structures, and flexibly adapts to different product audits |
| `responseData` verification configuration | Only retain allergen, shelf life, and test result fields, filter redundant data | Reduces interface transmission load and focuses on core audit requirements |
| Batch request interval | `10–30 seconds` | Adapts to the update frequency of per-batch production data, avoids triggering system rate limits |
| Single request file size limit | `1000 MB` | Adapts to the needs of batch uploading production records and test reports |
| Timeout setting | `600 seconds` | Covers the longest cycle from pulling data from production equipment to transmitting laboratory results |

## Three common mistakes
- Receiving two requests when calling the file interpretation interface, with the second request having an incorrect `Authorization` field format. Cause: No idempotency check is configured, or dynamic splicing of authentication parameters during interface callbacks causes format exceptions.
- Receiving an unauthorized error when calling the conversation guidance interface, even after filling in the API key. Cause: The API key is not bound to the corresponding factory's dedicated authentication configuration, or the key prefix does not meet industrial system requirements.
- Garbled Chinese file names when uploading knowledge base files via API. Cause: No correct encoding format is specified in the HTTP request header, leading to character set mismatch during transmission.

## How to confirm the configuration is correct
- Send a test request carrying a production record file named in Chinese, check that the file name displays normally in the response result.
- View interface logs to confirm that the `Authorization` field format of each request is consistent, with no errors caused by dynamic changes.
- Trigger batch data pulling, check that the returned `responseData` only contains core fields required for audit, with no redundant data.
- Pass an abnormal value of the allergen field to the interface via simulation, confirm that the system can correctly identify and trigger the corresponding verification logic.

The values provided are common starting points and should be measured against the reader's own samples.
