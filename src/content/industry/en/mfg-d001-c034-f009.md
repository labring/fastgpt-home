# Supplier and Process Quality Audit for Baking and Convenience Foods: Model Integration and Configuration

## What this category's data looks like
This category covers bread, pastry, biscuit, instant noodle and frozen pastry factories. Daily data includes formula and feeding lists, production records, baking/steaming curves, metal detection records, cleaning and disinfection records, and factory inspection reports. Data sources cover raw and auxiliary material qualification certificates, ERP/MES systems, weighing equipment, production lines, laboratory testing systems, and food traceability ledgers. Update frequency is per batch, per shift, or daily. Single-batch data includes fields such as allergen labels, production temperature, and time thresholds. Units include degrees Celsius, seconds, kilograms, and others. Frequent product line changes mean document types and field combinations vary within the same batch.

## What constraints do these characteristics impose on model integration and configuration
The frequent line changes and multi-source data features of this category require model access configuration to adapt to short-cycle, multi-type document processing needs. The high-frequency update requirement per batch or shift requires model call response speed to match production rhythm, to avoid data processing delays caused by improper configuration. Allergen verification and production window control are core audit links, requiring configuration to support accurate field extraction and rule matching, avoiding fuzzy processing. Multi-source data docking requirements require configuration to be compatible with API interfaces of different systems, ensuring stability of data synchronization. In addition, the ready-to-eat product attribute requires high rigor of audit results, putting forward higher requirements for the controllability of model output.

## How to set the configuration
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | The total length of single-batch formula, production records and test records usually falls within this range, which can avoid truncation of key allergen information and production parameters |
| `maxTokens` | 1500–2000 token | Matches the standard output length of quality audit reports, avoiding call timeouts or resource waste caused by excessive length |
| `temperature` | 0.1–0.3 | Quality audit requires rigorous conclusion output. This temperature range reduces the randomness of generated content and improves result credibility |
| Workflow/API tool selection | auto | Can automatically select applicable tools such as allergen verification and production curve analysis based on the input document type, adapting to multi-type audit scenarios |
| `AIPROXY_API_ENDPOINT` | Fill in according to the actually deployed data source interface | Used to connect multi-source data such as ERP/MES and testing equipment, ensuring the correctness of data synchronization |
| `AIPROXY_API_TOKEN` | Fill in according to the authentication requirements of the corresponding interface | Ensures the security of multi-source data docking and avoids unauthorized access |

## Three common mistakes
- Phenomenon: Unable to tick the configured reranking model when creating an application, or an error "No available channel for model gpt-4o under current group default" appears. Cause: The dedicated API endpoint for the reranking model is not configured in `AIPROXY_API_ENDPOINT`, or the configured token does not cover the call permission of the reranking model.
- Phenomenon: Failed to load when trying to import a local LLaMA 3 model to process knowledge base files. Cause: `AIPROXY_API_ENDPOINT` is not correctly configured to point to the locally deployed LLaMA 3 interface, or the configured token does not authorize access to this model.
- Phenomenon: Search results only return fuzzy matching content, and cannot trigger AI supplementary audit conclusions. Cause: `toolChoice` is not correctly set to the mode adapted to the audit scenario, or `maxContext` is configured too small to load complete production records and formula data.

## How to confirm the configuration is complete
- Enter the application configuration page of FastGPT v4.17.0, check if the configured model list includes the target model, and confirm there are no "no available channel" errors.
- Upload a single-batch baking production record document, initiate an audit request, wait 10–30 seconds to view the output result, and check whether it includes core audit content such as allergen verification and production window check.
- Call the test interface to verify that the configuration of `maxContext` and `maxTokens` meets expectations, with no content truncation or call timeout.
- View the data source docking log to confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are configured correctly, with no connection failure or permission error.
