# Supplier and Process Quality Audit for Baked Goods and Convenience Foods: Deployment and Upgrade

## What the data for this category looks like
Data for supplier and process quality audits in the baked goods and convenience foods industry comes from raw material compliance certificates, ERP/MES systems, weighing systems, oven or fryer equipment, laboratory test results, and food traceability logs. Update frequency is per batch, per shift, or daily.

Daily documents include formulas and feeding lists, production records, baking or steaming curves, metal detection records, cleaning and disinfection records, and factory inspection reports. Fields cover allergen labels, baking/frying parameters, shelf life, foreign matter detection results, packaging dates, and additional relevant details. The data includes both structured feeding parameters and unstructured curves and test records. Frequent product line changes result in varying document fields across different batches.

## Constraints these characteristics impose on deployment and upgrade
High data update frequency and frequent line changes require support for high-frequency incremental synchronization and quick switching between different product knowledge bases. Multiple data sources require configuration of connections and permission settings for multiple sources.

Mixed structured and unstructured document types need field extraction rules tailored to baked goods and convenience foods. This ensures accurate extraction of key fields such as allergens and baking parameters. Ready-to-eat product characteristics require audit parameter configurations to strictly match food contact, foreign matter, and microbial control requirements. Allergen management checks must be precise to avoid mislabeling. Frequent line changes also require quick updates to knowledge base configurations to adapt to audit rules for different products.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 100–200 connections | Adapts to high-frequency read/write demands for multiple data sources, supports concurrent access to systems including ERP, MES, weighing systems, and laboratory test systems, and meets high-frequency data updates per batch or shift |
| `REDIS_URL` | Local port 6379, with a dedicated password | Caches frequently accessed data such as formulas and allergens, reduces latency from repeated queries, and adapts to scenarios with frequent line changes |
| `STORAGE_S3_ENDPOINT` | Local object storage endpoint | Stores unstructured documents including baking curves and test records, ensuring fast reading and storage of documents |
| `FILE_TOKEN_KEY` | 32-bit random string | Used for token verification during file upload, ensuring access permissions for sensitive documents such as raw material compliance certificates and test records |
| `PG_URL` | Local PostgreSQL connection address | Stores structured data including audit process records and allergen logs, enabling subsequent audit traceability |

## Three common configuration mistakes
- Issue: After uploading a baking curve document, parsed baking temperature and time fields are empty. Cause: No document parsing field mapping rules were configured, and no document field extraction logic tailored to baked goods and convenience foods was specified. This prevents recognition of structured parameters.
- Issue: When calling the MCP service, the custom parameter `type` is fixed to `string`, and numeric baking temperature parameters cannot be passed. Cause: The parameter type configuration for the MCP service was not adjusted during deployment, so the parameter validation logic does not support numeric parameters.
- Issue: In FastGPT v4.17.0, after uploading a raw material compliance certificate, the request fails after 2 minutes of parsing. Cause: No reasonable value was configured for `DB_MAX_LINK`, leading to exhausted database connections, which prevents normal data reading during file parsing.

## How to confirm proper configuration
- Run a database connection test to verify the connection status of `MONGODB_URI`, `PG_URL`, and `REDIS_URL`, and confirm that production records and test data can be read and written normally.
- Upload a bread formula document, confirm that fields including allergens and feeding volume are extracted after parsing, and that field content matches the original document.
- Call the MCP service, pass a numeric baking temperature parameter, and confirm that the parameter can be passed normally and recognized.
- Upload a metal detection record document, confirm that the file can be parsed normally and stored in the storage location corresponding to `STORAGE_S3_ENDPOINT`.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
