# Supplier and Process Quality Audit for Production Planning and Shop Scheduling: Tool Calling and Plugins

## What this category of data looks like
The typical entities for this category are manufacturing enterprise PMC, planning, shop scheduling, and material control departments. Daily processed documents include sales orders, master production plans, material requirement plans, weekly and daily production schedules, work orders, material shortage lists, and delivery change notices. Data sources cover ERP orders and inventory, BOMs and process routes, equipment capacity, staff shifts, work-in-progress, and supplier arrivals. Update frequencies fall into three categories: daily, weekly, upon order placement, or when an exception occurs. Core fields include order numbers, process codes, equipment IDs, capacity thresholds, material codes, and delivery requirements.

## What constraints do these characteristics impose on the tool calling and plugins workflow
Because data sources for this category are scattered and update rhythms shift in real time with orders and exceptions, tool calling must adapt to real-time pulling logic for multiple data sources to avoid scheduling deviations caused by delayed data. At the same time, core documents contain multi-dimensional constraint conditions. Tool calling parameters must accurately match exclusive fields such as work orders, capacity, and materials, and cannot use generalized calls for general data. Additionally, scheduling adjustments directly affect delivery dates and work-in-progress status. Plugin calling must be paired with an exception handling mechanism to address scenarios where data pulling fails or scheduling calculations encounter errors.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| ------ | -------- | ------------ |
| Workflow/API tool selection | `auto` | Adapts to automatic tool matching requirements in scheduling scenarios, no need to manually specify tool types |
| Tool calling timeout | 600 seconds | Scheduling data processing involves multi-dimensional resource constraint calculations, sufficient execution time must be reserved |
| Single call data limit | First 20 work order records | Prevents system overload from pulling too much data in a single call, while covering core business needs for a single scheduling run |
| Exception retry count | 3 times | Addresses temporary network fluctuations or brief data source unavailability scenarios, reducing the probability of call failures |
| Workflow/API function-call configuration | Force binding scheduling-related tools | Ensures calls only target exclusive tools for production planning and shop scheduling, avoiding triggering unrelated functional modules |

## Three common mistakes
- A tool call returns a 401 status code. The cause is failure to correctly configure identity authentication parameters for tool calling, resulting in identity verification failure.
- No valid scheduling result is returned after plugin calling. The cause is failure to specify field filtering rules matching work orders and material requirement plans, leading the tool to pull irrelevant non-production data.
- Tool call trigger frequency is too high. The cause is failure to set call frequency limits, matching the frequently updated scheduling data trigger logic, which triggers system request interception.

## How to confirm the configuration is correct
- Simulate submitting a new sales order, check whether the system automatically triggers tool calls related to scheduling.
- Review tool call logs, confirm that the returned results include exclusive data fields for this category such as work orders, material requirement plans, and equipment capacity.
- Simulate triggering an exception scenario where a material shortage list is updated, check whether the plugin correctly executes the scheduling recalculation logic.
- Initiate a test API call, confirm that the returned results have no identity verification-related errors, and comply with FastGPT v4.17.0 interface specifications.
