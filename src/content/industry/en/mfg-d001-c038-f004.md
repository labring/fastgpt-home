# Supplier and Process Quality Audit for Biologics and Aseptic Manufacturing: Workflow Orchestration

## What this category's data looks like
The typical data for this category includes cell bank or seed lot records, culture and purification records, aseptic filling records, environmental monitoring data, media fill simulation results, sterility test reports, and batch release documents. Data sources cover cell bank and seed lot systems, process analysis equipment, clean zone monitoring systems, MES, LIMS, and equipment integrity testing tools. Data update frequencies fall into three categories: per batch, real-time, and per monitoring plan. Fields include batch number, culture temperature, sedimentation bacteria concentration, test pass rate, and others.

## What constraints these characteristics impose on the workflow orchestration link
Data sources for this category are scattered, and update rhythms vary significantly. Workflows must support scheduled pulling from multiple data sources, real-time triggering, and batch processing. Fields in batch record documents require precise association; workflows must bind fixed fields via variables to avoid data misalignment. Since errors in aseptic manufacturing have severe consequences, workflows must set clear exception branches and alert triggering rules. They must also comply with the output format requirements of compliance documents to ensure audit processes are traceable. This category differs from chemical formulations in that it relies more on process control and environmental monitoring, so workflows must strengthen the comprehensive verification link for multi-source data.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Variable Binding | Bind the batch number, culture temperature, and sedimentation bacteria value fields in `variables` | Ensures precise association of batch record fields per category documentation, enabling full data traceability |
| Trigger Node Configuration | Bind the MES batch release trigger signal by `nodeId` | Matches real-time production signals from MES as a data source, aligning with real-time update rhythms |
| Single Pull Data Volume | Top 50 entries | Prevents process delays caused by pulling too much data in a single operation |
| Timeout Threshold | 600 seconds | Aligns with the typical time range for batch record processing, avoiding process interruptions due to data pull delays |
| Branch Judgment Rule | Match the sterility test pass rate field in `variables` | Triggers release or exception handling branches based on test results |
| Retrieval Content Filtering | Only retain tool call results, hide the input and response from knowledge base retrieval | Ensures compliance audit documents are output, avoiding redundant information |

## Three common mistakes
- HTML code output mid-workflow without display, proceeding directly to the next branch. The symptom is no HTML rendered content in the interface, with the node status showing execution complete but no corresponding output. The cause is failure to configure the rendering trigger condition for the HTML node, or failure to match the trigger variable for HTML output in branch judgment.
- Workflow runtime is too slow. The symptom is node execution time exceeding the preset threshold, with significant overall process delay. The cause is failure to properly configure parallel nodes for multi-data source pulling, or failure to limit the single pull data volume.
- Knowledge base retrieval input and response references still appear after tool calls. The symptom is redundant retrieval input and output content included in the output results. The cause is failure to enable the retrieval content filtering configuration item, or failure to correctly bind the tool call output rules.

## How to confirm correct configuration
- Trigger a simulated batch production signal, check that the workflow executes in the preset node order, and that the field values bound in `variables` match the test data.
- Simulate abnormal data such as exceeding standard sedimentation bacteria values, confirm that the workflow enters the corresponding exception branch and triggers an alert.
- Run the tool call node, check that the output results only retain audit conclusions, with no redundant retrieval input and output content.
- View the node execution logs in FastGPT v4.17.0, confirm that all steps complete within the preset timeout threshold.
