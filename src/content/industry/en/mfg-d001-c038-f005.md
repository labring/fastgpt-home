# Supplier and Process Quality Audits for Biologics and Aseptic Manufacturing: Tool Calling and Plugins

## What data looks like for this category
This category's data comes from cell banks and seed lots, process analytics, cleanroom monitoring, MES, LIMS, and equipment integrity testing. Data update frequencies include per-batch, real-time, and per monitoring plan. Daily documents include cell bank or seed lot records, culture and purification records, aseptic filling records, environmental monitoring, media fill simulation, sterility testing, and batch release documentation. Fields include seed lot number, culture temperature, settleable microbial count in filling environment, batch release test results, and others, with corresponding units such as ℃, cfu/㎡, batch number, and more.

## What constraints these characteristics impose on tool calling and plugins
Data sources for this category are scattered and have varied formats. Tool calling must support connecting to multiple data source plugins to pull data across systems. Data update frequencies vary widely. Tool calling must adapt to both on-demand triggering and batch scheduling scenarios. Document structures are complex and field requirements are strict. Tool calling parameters must precisely match business fields to avoid information bias from generic calls. Audit errors have severe consequences. Tool calling must include built-in validation and failure retry mechanisms to ensure the accuracy and stability of data calls.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Workflow/API tool selection | `auto` | Adapts to the multi-tool needs of biologic audits, automatically selects the appropriate plugin for supplier and process quality audits |
| Workflow/API function-call configuration | `strict: true` | Enforces matching of key audit fields such as seed lot numbers and culture parameters to avoid missing core information |
| Plugin timeout setting | 300 seconds | Adapts to the time requirements of complex batch release data queries and cross-system calls |
| Batch trigger threshold | 1 time per batch | Matches the per-batch update data rhythm of this category, avoids resource waste from repeated triggering |
| Tool retry count | 2 times | Balances call stability and resource usage, addresses temporary interface fluctuations |
| Context window | 8000–12000 token | Accommodates the full content of multiple audit documents, supports comprehensive cross-document audit analysis |

## Three Common Configuration Mistakes
- When calling Bedrock tools, errors starting with software.amazon.awssdk.services.bedrockruntime.model are returned. The cause is that the tool permission scope for biologic audit scenarios is not properly configured, preventing access to specified data interfaces for LIMS or cleanroom monitoring.
- Interface calls return aiPointsNotEnough. The cause is that tool calls are not triggered at the per-batch or real-time update rhythm, leading to insufficient valid data points for audits.
- Multimodal plugins fail to correctly parse image data from aseptic filling records. The cause is that image preprocessing parameters matching biologic document formats are not configured, making it impossible to identify key fields such as settleable microbial count labels.

## How to Verify Correct Configuration
- Submit a simulated supplier audit request, check if tools automatically call corresponding data source plugins to pull required data.
- Trigger a batch release audit workflow, confirm that tool call timing matches the per-batch update business rhythm.
- Review tool call logs in FastGPT v4.17.0, confirm that function call parameters strictly match required fields for biologic audits.
- Simulate abnormal data input, check if tools trigger preset failure handling and retry mechanisms.
