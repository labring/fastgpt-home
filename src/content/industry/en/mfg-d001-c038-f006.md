# Supplier and Process Quality Audit for Biologics and Aseptic Manufacturing: Source Citation and Traceability

## What the data for this category looks like
The primary entities in this category are manufacturers of vaccines, antibodies, blood products, and sterile injectables. Daily generated documents include cell bank or seed lot records, culture and purification records, aseptic filling records, clean zone environmental monitoring data, media fill simulation results, sterility test reports, and batch release documents. Data sources include cell bank and seed lot systems, process analytical sensors, clean zone monitoring equipment, MES manufacturing execution systems, LIMS laboratory information management systems, and equipment integrity testing tools. Data update frequencies fall into three categories: per batch, real-time, and according to established monitoring plans. Core fields include batch number, culture duration, environmental temperature and humidity, colony count, equipment operating parameters, and some records require matching personnel and material path information for aseptic operations.

## What constraints these characteristics impose on the source citation and traceability link
Multi-source and scattered data in this category requires the traceability system to accurately match unique identifiers such as batch numbers and equipment IDs. This prevents cross-batch or unrelated data from being retrieved. Data with different update frequencies needs to support dynamic index updates. Real-time monitoring data must be pulled in real time during audits. Environment monitoring data updated according to plans must retain complete time series. Complex document structures include long text records and structured parameters. This requires support for field-based filtering and precise context citation. It ensures that compliance data for key links can be quickly located during quality audits. Aseptic manufacturing cannot fully guarantee quality through finished product sampling alone. Referenced process data must cover the entire workflow of culture, filling, testing, and other stages. Missing any key data will result in audit failure. Traceability results must be bound to the specific location of the original document, enabling quick verification of original records during audits.

## How to set up the configuration
The following configurations are based on the source citation and traceability logic of FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context | Top 12000 tokens | Adapts to the total length of single-batch production records, avoids truncating core compliance data |
| `quoteMaxToken` | 800–1200 characters | Matches the information length of a single core process record, ensures referenced content is complete and does not overflow the context |
| `responseData` | Return only batch number, test result, and equipment parameter fields | Focuses on key data required for quality audits, reduces interference from redundant information |
| `detail` | High | Retains complete details of original records, meets the rigor requirements for audit verification |
| Single Search Limit | Top 8 entries | Covers key citations from multiple data sources, avoids irrelevant records affecting audit judgments |

## Three common configuration errors
- Phenomenon: Non-current production batch records appear in referenced traceability data. Cause: Batch number fields are not configured as search filtering conditions, leading to cross-batch data being retrieved.
- Phenomenon: Model temperature parameters cannot be set in variable citation mode. The temperature setting button in the configuration interface disappears. Cause: The model parameter setting module is not loaded synchronously on the variable citation configuration page for some versions. The parameter panel must be manually enabled.
- Phenomenon: Unique identifier fields for referenced data are empty, making traceability binding impossible. Cause: Unique identifier fields are not configured for data returned by `responseData`, making it impossible to match the specific location of original documents.

## How to confirm the configuration is correct
- Upload a complete single batch release document, initiate a quality audit query, and check if the reference results include all core test items and process parameters.
- Simulate a query request for a specified batch, confirm that the retrieved data sources only come from cell bank, production, and test records corresponding to that batch.
- Adjust the value of the `quoteMaxToken` parameter, verify that the length of referenced content meets expectations, with no excessive truncation or redundant content.
- View the traceability log, confirm that each referenced data item is bound to the corresponding original document path and field information, allowing quick jumps to original records.

The values provided are common starting points and should be measured against the reader's own samples.
