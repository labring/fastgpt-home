# Supplier and Process Quality Audits for Biologics and Aseptic Manufacturing: Document Parsing and Chunking

## What the Data for This Category Looks Like
Core data for this category comes from cell banks and seed lots, process analysis systems, clean zone monitoring records, MES, LIMS, and equipment integrity test results. Daily documents include cell bank or seed lot records, culture and purification records, aseptic filling records, environmental monitoring reports, media fill simulation data, sterility test reports, and batch release documents. Data update cycles cover each production batch, real-time monitoring, and fixed-period planned monitoring. Most documents contain process parameters, test values, batch identifiers, and compliance annotations. Fields often include measurable items with clear units such as temperature, duration, and colony count.

## What Constraints These Characteristics Impose on the Document Parsing and Chunking Process
The multi-source heterogeneous document formats, batch-based and real-time update characteristics, and high compliance requirements of this category impose multiple constraints on the document parsing and chunking process. Documents exported from different systems come in multiple formats including PDF reports, Excel process parameter tables, and structured monitoring records, requiring adaptive mixed-format parsing. Documents with batch identifiers must be split and chunked by production batch to avoid mixing data across batches. Time-series data from real-time monitoring must retain continuous context to ensure complete association logic for parameters. High-risk attributes require the parsing process to fully extract measurable fields and compliance annotations to avoid loss of critical information.

## How to Configure the System
The following configurations are based on the functional logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Documents in this category include long-form process records and structured test data. This range preserves complete context for a single process step or single test report |
| `chunkSplitter` | Split by paragraph + title | Documents contain batch titles and process node titles. Splitting by title ensures content from the same process segment is grouped together, avoiding scattered data across nodes |
| `customPdfParse` | Enabled | PDF documents in this category often contain embedded tables and vector graphics. Enabling custom parsing fully extracts table data and vector text, avoiding OCR omissions or formatting errors |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Parsing large batch release documents and multi-page environmental monitoring reports takes significant time. This duration covers parsing needs for most complex documents |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Complete batch record sets for this category may include multi-page reports and attachments. This threshold covers upload requirements for most production documents |
| `chunkSettingMode` | Manual configuration | Document structures vary widely across this category. Manual configuration allows adjusting chunking rules for different document types, adapting to the different format requirements of cell bank records and filling records |

## Three Common Mistakes
- Issue: After importing an Excel spreadsheet dataset, some cell fields are empty or their corresponding relationships fail. Cause: Custom table parsing configuration was not enabled. The default parsing does not adapt to the nested headers and merged cell formats of structured tables in this category.
- Issue: Chinese garbled characters or missing characters appear after parsing a scanned sterility test report. Cause: Parsing engine parameters adapted to Chinese were not configured, or the scanned document has insufficient resolution leading to OCR recognition failure.
- Issue: Parsing tasks for large batch release documents show timeout failures. Cause: `PARSE_FILE_TIMEOUT_SECONDS` was not adjusted to a reasonable duration, or the uploaded file exceeds the `UPLOAD_FILE_MAX_SIZE` limit.

## How to Verify Proper Configuration
- A single typical document such as an aseptic filling record may be uploaded, and the parsed chunks may be verified to be grouped by process node with no cross-node splitting.
- A structured table document such as a cell bank record may be imported, and the parsed fields may be checked to correspond one-to-one with the headers and cell content of the original document.
- A document at the preset maximum allowed size may be uploaded, and the parsing task may be verified to complete within the preset duration with no errors.
- A scanned environmental monitoring report may be used to confirm that the parsed text has no garbled characters or loss of critical parameters.

The values provided are common starting points and should be measured against the reader's own samples.
