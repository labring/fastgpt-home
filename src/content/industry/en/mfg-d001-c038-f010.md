# Supplier and Process Quality Audit for Biologics and Aseptic Manufacturing: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Typical entities in this category are vaccine, antibody, blood product, and sterile injectable manufacturers. Daily documents include cell bank or seed lot records, culture and purification records, aseptic filling records, environmental monitoring data, media fill simulation results, sterility test reports, and batch release documents.
Data sources cover cell bank and seed lot systems, process analysis equipment, clean zone monitoring systems, MES, LIMS, and equipment integrity testing tools. Data updates are performed per batch, monitoring results are synced in real time, or follow established monitoring plans.
Document fields include batch number, operation time, parameter values, test results, and operator identifiers. Some records must be linked to equipment serial numbers and environmental temperature and humidity values. Some parameters must match industry-specific metrology standards.

## Constraints on Knowledge Base Retrieval and Recall
The data characteristics of this category create multiple constraints for the retrieval and recall process.
Documents updated per batch and strongly linked to batch numbers require retrieval to be accurately bound to batch context, to avoid mixing data across batches. Dispersed multi-source system data requires retrieval to cover associated content across multiple datasets, to ensure full-chain data required for audits can be recalled.
A large number of specialized process parameters, test results, and dedicated metrology fields require retrieval strategies to retain field associations, to avoid breaking parameter logic by splitting fields. Real-time monitoring data’s immediate update requirement requires the retrieval link to have low-latency response capabilities, to adapt to the immediate judgment needs of process audits.
The high compliance requirements for aseptic manufacturing records require filtering irrelevant redundant content, to ensure retrieval results only relate to documents related to quality audits.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `similarity` | 0.85–0.92 | Matches the precision requirement for aseptic manufacturing process parameters and test results, avoids low-relevance results interfering with quality audits |
| `limit` | Top 8 entries | Balances information completeness and context length for retrieval and recall, adapts to multi-field associated content in batch records, avoids exceeding model processing limits |
| `searchMode` | Full-text search | Covers full-dimensional retrieval needs for process parameters, test results, and batch information, meets full-chain data calls for supplier and process audits |
| `usingReRank` | Enabled | Performs secondary ranking on initially recalled multi-source data, strengthens matching between specialized terminology and audit scenarios, improves result accuracy |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands retrieval keywords to cover synonyms and industry-specific expressions for process parameters, adapts to the specialized terminology system for biologic manufacturing |
| `collectionIds` | Configured by business dataset grouping | Distinguishes independent datasets such as batch data, environmental monitoring data, and test reports, avoids mixing cross-category data, ensures business relevance of retrieval results |

## Three Common Errors
- Index building gets stuck, with no progress updates or timeout prompts displayed in the interface. Cause: `collectionIds` is not configured by business dataset grouping, and all multi-source data is imported at once, leading to excessive index building resource usage that prevents completion.
- Search tests trigger errors, returning field parsing failure prompts. Cause: `datasetSearchUsingExtensionQuery` is not enabled, cannot adapt to specialized terminology expansion for biologic manufacturing, leading to retrieval keywords failing to match document fields.
- Retrieval results include content not from this category, not strictly matching aseptic manufacturing-related documents. Cause: `collectionIds` configuration includes datasets from other categories, leading to recall of irrelevant document content.

## How to Confirm Proper Configuration
- Review index building logs, confirm that index progress for each business dataset is completed normally, with no timeout or error records.
- Enter specialized process parameters or batch number keywords for retrieval, verify that recalled results include document content from the corresponding business scenario.
- After enabling `usingReRank`, compare initially recalled results with reranked results, confirm that specialized terminology matching is improved.
- Check `collectionIds` configuration, confirm that only business dataset IDs for this category are included, with no cross-category datasets mixed in.

The values provided here are common starting points and should be measured against the reader's own samples.
