# Supplier and Process Quality Audit for Electric Motor and Generator Manufacturing: Vector Models and Indexes

## What the Data for This Category Looks Like
This category of data originates from winding, insulation, final assembly, and testing departments of electric motor factories and power equipment enterprises. It covers documents including winding process cards, insulation treatment records, dynamic balance reports, voltage withstand insulation test reports, and type and factory test reports.
Data is sourced from electromagnetic design data, copper wire and insulation material batch records, winding equipment, balancing machines, electrical test bench data, and ERP/MES systems. New data is generated for each produced product, each batch of materials, or each type change, so update frequency aligns with these events.

## What Constraints This Category’s Data Imposes on Vector Models and Indexing
This category of data includes structured batch numbers, electromagnetic parameters, and test values, as well as semi-structured process step records. Update frequency is high, individual data entry size is small, but overall data volume grows quickly.
Large differences exist in unit standards across fields from multiple data sources. For example, turns, temperature rise, and voltage withstand values use different measurement standards. This requires vector models to adapt to semantic and numerical associations across mixed fields.
Frequent incremental update requirements exist, so support for fast synchronization of new data by batch or device ID is needed.
At the same time, core audit scenarios require precise matching of associations between winding processes, test results, and anomaly analysis, which places high demands on index recall accuracy.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the single-page content length of winding process cards and test reports, avoids semantic breaks within chunks |
| Overlap Length | 100–150 characters | Retains cross-chunk process step and test data associations, prevents key information from being split |
| Similarity Threshold | 0.75–0.85 | Matches precise process parameter and anomaly result associations in motor manufacturing, filters low-relevance search results |
| `maxToken` | 8192 token | Adapts to the long text content of type test reports, ensures complete loading of test data and process descriptions |
| Maximum Search Results per Request | Top 8 entries | Covers the volume of associated data for core audit scenarios, avoids redundant information interfering with audit judgments |
| `defaultToken` | Calibrated based on actual measurements | Adapts to resource usage of locally or privately deployed vector models, balances retrieval speed and recall effect |

## Three Common Mistakes
- Phenomenon: The knowledge base displays an unindexed status after upload, and no corresponding data entries appear in the vector database. Cause: No incremental synchronization trigger rules are set per batch of materials or device ID, resulting in newly generated test reports not being automatically included in the index.
- Phenomenon: The interface prompts that no available channels are found for m3e, and vector embedding cannot be generated. Cause: No deployment address and key for m3e are added in the private model configuration page of FastGPT v4.17.0, or channel quota has been exhausted.
- Phenomenon: System response delay is high when repeatedly initiating the same process parameter retrieval request. Cause: No cache optimization mechanism is configured, so each request directly accesses the vector database without reusing previously retrieved results.

## How to Verify Proper Configuration
- Upload a latest winding process card, check the knowledge base index status page, confirm that entries have been generated and associated with the corresponding batch number.
- Enter the search term "winding turns verification", check whether the returned results include associated entries for dynamic balance reports and voltage withstand test data, to verify that the recall logic matches audit scenarios.
- Check the operating metrics of the vector model, confirm that the `defaultToken` configuration adapts to current deployment resource limits.
- Initiate two identical retrieval requests, compare response times, to verify whether the cache mechanism takes effect as configured.

The values provided here are common starting points, and should be evaluated against corresponding samples.
