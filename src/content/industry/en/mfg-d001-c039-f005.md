# Supplier and Process Quality Audit for Electric Motor and Generator Manufacturing: Tool Calling and Plugins

## What the data for this category looks like
Core audit data for electric motor and generator manufacturing comes from electromagnetic design databases, copper wire and insulation material batch ledgers, winding equipment, balancing machines, electrical test benches, as well as ERP and MES systems.
Daily generated documents include winding process cards, insulation treatment records, dynamic balance reports, dielectric strength test reports, and type and factory inspection reports.
Data is updated per motor or per batch of materials, and synchronized whenever a formal design change occurs.
Core fields to verify include winding turns, insulation system parameters, dynamic balance values, temperature rise and dielectric strength test results. Dual constraints of electromagnetic and rotating machinery balance must also be considered.

## What constraints these characteristics impose on tool calling and plugins
Data sources for this category cover equipment, systems and paper documents. Tool calling must connect to multiple data types, and support batch parameter verification.
Data updates happen frequently, and single changes have wide impact ranges. Tool calling must adapt to real-time or near-real-time data pull requirements.
Core document fields are numerous and have professional constraints. Tool calling must support step-by-step collection of multiple parameters and strict format matching.
In addition, special data requirements for high-voltage and temperature rise tests require tool calling to retain context associations, to avoid logical breaks caused by parameter splitting.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Workflow/API tool selection | auto | Adapt to multi-parameter, multi-step tool calling requirements in motor manufacturing scenarios, automatically trigger parameter supplementation and data pulling |
| Single tool call timeout | 600 seconds | Cover time-consuming motor-specific detection links such as dielectric strength tests and dynamic balance analysis |
| Workflow/API function-call configuration | strict | Strictly match fixed field formats of winding process cards and test reports, avoid parameter misalignment |
| Multi-parameter supplementation trigger | Workflow node interception | Step-by-step collection of motor-manufacturing-specific required fields such as copper wire batch numbers and winding equipment serial numbers |
| Tool result cache duration | 3600 seconds | Match batch update frequency of batch data, avoid repeated pulling of historical test data |
| Context retention count | First 8 entries | Balance context completeness and calling speed, avoid overload affecting response efficiency |

## Three common mistakes
- Phenomenon: When calling MCP tools, the model context is interrupted, the output is unrelated to the current motor audit, and historical winding parameters are not retained. Cause: `toolChoice` is not configured as auto, forced tool calling directly interrupts context flow, and the historical parameter association of winding process cards is not retained.
- Phenomenon: Required fields are empty during multi-parameter MCP calls, resulting in tool call failure. Cause: No parameter supplementation link is set via workflow nodes, and motor-manufacturing-specific required parameters such as copper wire batch numbers and insulation material models are not collected.
- Phenomenon: Model response delay exceeds the threshold after tool calling, with slow response. Cause: The number of result return entries per tool call is not limited, or the cache duration is set too long, resulting in repeated loading of large amounts of historical test data.

## How to confirm the configuration is complete
- Import a complete winding process card and dynamic balance report, trigger tool calling, and check whether core fields such as winding turns and insulation thickness are automatically extracted.
- Simulate an audit request missing copper wire batch parameters, and check whether a parameter supplementation link or workflow interception node is triggered.
- Initiate 3 consecutive test data queries for the same motor batch, and check whether the response time remains stable.
- View the FastGPT v4.17.0 tool call log, confirm that `functionCall` is configured as strict mode, and the returned results match the field formats of test reports.
