# Supplier and Process Quality Audit for Electric Motor and Generator Manufacturing: Document Parsing and Chunking

## What the data for this category looks like
Data for this category originates from winding, insulation, final assembly, and testing departments of electric motor factories and power equipment enterprises. Core documents include winding process cards, insulation treatment records, dynamic balance reports, dielectric strength test reports, and type and factory inspection test reports. Data is collected from electromagnetic design data, copper wire and insulating material batches, winding equipment, balancing machines, electrical test benches, and ERP/MES systems. Updates occur per manufactured unit, per production batch, or upon each type change. Document fields include winding turns, paint dipping and drying parameters, vibration values, temperature rise data, and other similar entries, with corresponding professional units such as turns, millimeters, micrometers, and kelvins.

## Constraints imposed by these characteristics on document parsing and chunking
Documents such as winding process cards and test reports contain fixed professional fields and numerical content. When creating chunks, the link between fields and their corresponding values must be preserved to avoid losing context after splitting. The high update frequency for multiple batches and units requires chunking to align with the document granularity of a single batch or unit, preventing cross-batch content from being mixed. Professional terms related to electromagnetism, insulation, and testing must be accurately identified. Chunk boundaries must not truncate professional terms mid-word. Different document types have significant structural differences, so different chunking logic must be used to ensure key audit-related information is not split.

## Configuration settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the length of professional paragraphs and fields in winding process cards and test reports, avoiding splitting of key technical parameters |
| `chunkSplitter` | Split by paragraph + title | Matches the segment logic of process steps and test items in documents, retaining the contextual association required for audits |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Addresses the parsing time required for large type test reports, avoiding timeout interruptions of the parsing process |
| `customPdfParse` | Enable Marker parsing mode | Adapts to embedded test data tables and professional charts in PDF documents, improving the accuracy of structured content extraction |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports uploading multiple batch documents in a single operation, adapting to the scenario requirements of batch audits |
| `chunkSettingMode` | Manual configuration mode | Customizes chunking rules for different document types (process cards, test reports) to meet the requirement of retaining professional fields |

## Three common configuration mistakes
- Issue: File enhanced parsing functionality fails in some versions. Normal operation resumes after switching to Marker parsing mode, as the default parsing engine does not adapt to embedded professional charts and table structures in motor manufacturing documents.
- Issue: The file parsing tool cannot be invoked during conversations. The cause is that associated parameters between the file parsing service and the conversation flow were not configured correctly.
- Issue: The Marker image fails to start when deployed via Docker. The cause is that GPU resources were not mounted correctly, or port mapping parameters were configured incorrectly, such as not using port 7231.

## How to verify correct configuration
- Upload a winding process card PDF, and check if core fields such as winding turns and paint dipping parameters are fully retained in the parsed content.
- View the running logs of the parsing task, and confirm that timeout errors related to `PARSE_FILE_TIMEOUT_SECONDS` are not triggered.
- Compare parsing results with and without `customPdfParse` enabled, and confirm that the extraction accuracy of structured tables and charts has improved.
- Upload a type test report under 1000 MB in size, and confirm that the upload and parsing processes complete normally.

The values provided are common starting points and should be evaluated against the reader's own samples.
