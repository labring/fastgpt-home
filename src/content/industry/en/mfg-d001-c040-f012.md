# Supplier and Process Quality Audit for Battery PACK and Energy Storage System Integration: Deployment and Upgrade

## What Data Looks Like for This Category
The core data for this category originates from industrial terminals and systems including cell grading and capacity testing equipment, production MES systems, welding torque tools, BMS software, and EOL test benches. Daily processed documents cover grouping rules, BOM lists, welding and torque records, BMS flashing logs, insulation and voltage withstand reports, EOL test reports, and system configuration lists. These include structured parameters and unstructured test records. Data updates occur once per produced battery pack or energy storage cabinet, with configuration data synchronized each time the BMS software version changes. Fields include cell gear, welding torque value, insulation resistance value, BMS version number, and more. There is no unified universal document format.

## Constraints Imposed on Deployment and Upgrade by These Characteristics
Multi-source heterogeneous data sources require adaptation to different interface protocols and data formats during deployment. Access permissions and conversion rules for data sources must be configured in advance. The high-frequency update rhythm requires retaining an incremental synchronization mechanism during upgrades, to avoid excessive production system resource usage from full synchronization. Diverse document structures require knowledge base splitting configurations to support differentiated processing of structured and unstructured documents, preventing loss of core parameter fields. Severe error consequences require configuring a rollback plan during upgrades, to ensure rapid recovery of the original audit process when anomalies occur. Additionally, compatibility of all dependent images must be verified in advance for offline deployment scenarios, to avoid startup failures.

## Three Common Misconfigurations
- Phenomenon: After upgrading to FastGPT v4.17.0, the independent text processing function entry disappears, and existing audit workflows based on this function are interrupted. Cause: This version integrates the text processing module into the knowledge base configuration process, and does not retain the independent function entry. Configuration must be completed on the knowledge base editing page.
- Phenomenon: During offline deployment, `PG_URL` is configured correctly, but the aiproxy_pg image fails to start, and the log shows a database connection timeout. Cause: The container network policy is not configured in the offline environment, causing the aiproxy_pg container to fail to connect to the internal PostgreSQL instance.
- Phenomenon: When splitting grouping rule documents in paragraph-first mode, the cell gear parameter is lost after splitting. Cause: The dedicated splitting mode for structured parameter documents is not enabled, causing nested fields to not be fully extracted.

## How to Verify Successful Configuration
- Upload a standard BOM document to the knowledge base, and verify that the split paragraphs contain complete material codes and specification parameter fields.
- Call the API to create a text collection, pass in the grouping rule document, and confirm that the interface returns a status code of 200 and generates a valid collection ID.
- Start the aiproxy_pg container, check that the container logs have no database connection-related errors, and confirm that the `PG_URL` configuration takes effect.
- Trigger an incremental synchronization of an insulation report, and check that the file storage path matches the `STORAGE_S3_ENDPOINT` configuration.

The values provided are common starting points and should be measured against the reader's own samples.
