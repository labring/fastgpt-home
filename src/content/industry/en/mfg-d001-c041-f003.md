# Supplier and Process Quality Audit for Electroplating and Chemical Surface Treatment: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
The primary data subjects for this category are electroplating plants, electronic connector surface treatment workshops, and hardware component surface treatment workshops. Daily documents include bath solution analysis records, process parameter cards, fixture usage records, film thickness and adhesion test reports, hazardous waste management ledgers, and wastewater monitoring records. Data sources include customer surface treatment specifications, bath solution test results, rectifier operation data, online water quality monitoring data, and hazardous waste management ledgers. Data is updated per single bath cycle, per shift, or generated in accordance with special monitoring requirements.

## Constraints imposed on multi-turn dialogue and prompt configuration by these category characteristics
This category has high-frequency data updates, clearly segmented document fields, and associated compliance requirements, which impose constraints on multi-turn dialogue and prompt configuration. First, data is updated per single bath cycle or per shift. Multi-turn dialogue must limit the context scope to avoid loading expired bath solution or monitoring data. Second, documents include segmented fields such as bath solution parameters, film thickness indicators, and hazardous waste ledgers. Prompts must clearly specify the query logic and field units for corresponding documents. In addition, data is linked to compliance monitoring requirements. Dialogue must associate corresponding compliance records, and exclusive fields must be bound to ensure audit accuracy. Differences in documents across different processes must also be noted: data from the pre-treatment and plating tank links must be associated separately to prevent context confusion from affecting audit results.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind the unique identifier of a single bath cycle, set session validity period to 600-1200 seconds | Single bath cycle operation duration ranges from 10 to 20 minutes, matching the category's operation cycle |
| `messages` | Retain the 3 most recent bath cycle-related conversations and document snippets | The category has high-frequency data updates, and overly long context will introduce expired bath solution or monitoring data |
| `variables` | Bind exclusive fields including bath solution pH value, film thickness (μm), wastewater discharge limits, etc. | The category has clearly segmented document fields, requiring precise association of business parameters and compliance indicators |
| Question Optimization | Enabled, with optimization direction limited to bath solution parameters, compliance records, and process quality indicators | Core business focuses on supplier audit and process quality control, focusing on core query scenarios |
| Maximum Context | 800-1200 characters | The total number of core document fields for the category is moderate; overly long context will cause response delays |

This configuration is based on FastGPT v4.17.0.

## Three Common Misconfigurations
- Symptom: Images of bath solution analysis records in conversation history fail to load, the interface displays a blank screen or resource error. Cause: The slot identifier associated with the image is not bound via `variables`, so the corresponding document attachment for the current session cannot be matched.
- Symptom: After the workflow calls the compliance check plugin, no conversation logs for the current audit process are generated. Cause: The unique session identifier for a single bath cycle is not bound in `chatId`, and the plugin call is not associated with the current context, resulting in logs being unable to be attributed to the corresponding audit task.
- Symptom: The preset conversation opening quick button does not respond when clicked, and no category-specific quality audit prompt appears. Cause: Only general business prompts are configured, and no exclusive audit scenario parameters for electroplating and chemical surface treatment are bound, so business requirements cannot be matched.

## How to Verify Successful Configuration
- Initiate a simulated bath cycle audit conversation, check that the `messages` context only retains the 3 most recent bath cycle-related records with no expired data.
- Call the compliance query function, confirm that fields such as bath solution and film thickness bound via `variables` can correctly return corresponding document content.
- Trigger the workflow to call the plugin, check that session logs marked with `chatId` are generated and attributed to the current audit task.
- Click the preset opening quick button, confirm that the displayed prompt includes exclusive audit scenario parameters for electroplating and chemical surface treatment.
