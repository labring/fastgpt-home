# Supplier and Process Quality Audit for Electroplating and Chemical Surface Treatment: Tool Calling and Plugins

## What data looks like for this category
The data for this category primarily comes from customer surface treatment specifications, bath laboratory test records, rectifier operation data, online water quality monitoring systems, and hazardous waste management ledgers. Daily documents include bath analysis records, process parameter cards, fixture usage ledgers, film thickness and adhesion test reports, hazardous waste disposal ledgers, and daily wastewater monitoring reports. Data update frequency follows per bath batch, per shift, or fixed monitoring cycle requirements. Fields include parameters with clear units: bath concentration (g/L), plating bath temperature (℃), rectifier current (A), film thickness (μm), wastewater heavy metal concentration (mg/L), and other similar metrics.

## What constraints these characteristics impose on the tool calling and plugins workflow
The multi-source heterogeneous data structure and high-frequency update characteristics of this category require tool calling to adapt to the field formats of different documents such as bath analysis and water quality monitoring, to avoid parameter parsing errors. Real-time data such as bath temperature and rectifier current requires tool calling to be triggered in short cycles, and cannot rely on fixed-interval synchronization. Hazardous waste ledger and compliance-related data must be bound to audit processes to trigger tool calls, to avoid unnecessary calls consuming resources. Structured fields from test reports such as film thickness and adhesion must strictly match tool parameters, otherwise audit result deviations will occur. Cross-data-source tool calling must handle data format differences across different systems to ensure consistent parameter transfer.

## Three common configuration mistakes
- The phenomenon is that HTTP request parameters are parsed normally during tool calling, but the corresponding operation is not actually executed. The cause is that the permission verification rules for tool triggering are not bound, or the request parameters do not match the field formats of business documents such as bath and hazardous waste ledgers.
- The phenomenon is that when calling an embedding or inference model, the return value is `{"object":"error","message":"Only allowed now"}`. The cause is that the whitelist for model calling is not configured, or the locally deployed model has not completed startup loading.
- The phenomenon is that the multimodal image recognition tool call returns missing or incorrectly formatted parameters. The cause is that the test report image has not been converted to a standardized base64 encoding, or the content type is not correctly specified in the request.

## How to confirm the configuration is complete
- Trigger a supplier audit process, check whether the correct parameters and trigger node are displayed in the tool call log, and verify that the fields in the log match the business documents.
- Use the test tool to input simulated bath parameters, confirm that the tool return results conform to the preset verification rules, and have no format errors.
- View the system resource monitoring panel, confirm that the load of parallel tool calls is within a reasonable range, and there are no timeout errors.
- Verify the model calling function, input standard test text, confirm that the returned results have no permission-related errors and conform to the required format.
