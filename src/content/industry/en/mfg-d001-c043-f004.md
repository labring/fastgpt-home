# Supplier and Process Quality Audit for Batch Fine Chemical Synthesis: Workflow Orchestration

## What Data for This Category Looks Like
This category covers production entities for paints, resins, additives, agrochemical intermediates, and specialty chemicals. Daily documents include batch production instructions, feeding verification sheets, reaction process records, cleaning records, test reports, deviation and change orders.
Data is sourced from formula and process libraries, raw material batches, reactor DCS, weighing systems, LIMS, and warehouse systems, and updated per batch production or each key step.
Data fields include raw material batch numbers, reactor temperature parameters, feeding amounts, cleaning confirmation flags, and more. Some fields involve formula confidential content, so access permissions must be strictly controlled.

## What Constraints These Characteristics Impose on Workflow Orchestration
The multi-variety, batch-switching production mode requires workflows to trigger for each single batch production task, with node configuration matching the batch’s formula and process parameters.
Multi-source data access needs require workflows to integrate multiple tool nodes to retrieve real-time data from reactor DCS, weighing systems, and LIMS separately.
The per-batch updated data feature requires workflow node variables to not use cross-batch cached data, ensuring the accuracy of each batch audit.
Time-consuming steps such as feeding verification, reaction end judgment, and cleaning confirmation require workflows to be configured with conditional branches that trigger subsequent nodes based on the execution results of key steps.
The formula confidentiality requirement means that `variables` related to formulas in workflows can only be accessed by authorized nodes.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `variables` | Bind workflow global token variables to tool input parameters | Adapt to business requirements for passing global parameters, comply with FastGPT v4.17.0 global variable usage specifications |
| Tool auto-invocation trigger | Auto-trigger based on node execution results | Adapt to conditional judgment logic for multi-step audits, no manual intervention required for each step execution |
| DingTalk webhook | Configure audit result push address and trigger conditions | Implement synchronous notifications for deviation orders, test reports and other results, cover business collaboration requirements |
| Node timeout setting | 300–600 seconds | Cover average time intervals for operations such as reaction process data collection and LIMS query, calibrated based on actual measurements |
| `nodeId` | Bind to process nodes corresponding to the batch | Ensure that node parameters for each step match the process requirements of the current production batch |
| Variable access scope | Only authorized audit nodes can access | Protect the security of confidential formula data, avoid leakage of sensitive information |

## Three Common Mistakes in Configuration
- Phenomenon: Workflows cannot retrieve global tokens in `variables` during runtime, and tool calls return empty parameters. Cause: Global variables are not correctly bound to tool input parameter configurations, and the global variable passing switch is not enabled.
- Phenomenon: Workflows cannot automatically select and call tools, and always execute according to a fixed process. Cause: Trigger rules for node execution results are not configured, and the tool auto-invocation mode is not enabled.
- Phenomenon: DingTalk webhook pushes have no valid content or fail to send. Cause: Correct audit result trigger conditions are not configured, and output data from corresponding nodes is not bound to push content.

## How to Confirm Your Configuration Is Correct
- Run a test batch workflow, check the input parameter details of tool calls, and confirm that global token variables have been correctly passed to corresponding tools.
- Simulate a node execution result that does not meet preset conditions, check whether the workflow automatically triggers the corresponding branch or calls tools, and confirm that the auto-invocation logic is active.
- Configure a test DingTalk webhook address, check the push content after the audit node is triggered, and confirm that audit result data has been correctly synchronized.
- Check the access permission configuration of `variables`, confirm that non-authorized nodes cannot view variable content related to sensitive formulas, and confirm that permission control is effective.

The values provided are common starting points and should be measured against the reader's own samples.
