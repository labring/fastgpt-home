# Supplier and Process Quality Audit for Batch Fine Chemical Synthesis: Deployment and Upgrade

## What the data for this category looks like
The data for this category comes from formula and process libraries, raw material batch records, reactor DCS systems, weighing systems, LIMS laboratory management systems, and warehouse systems of specialty chemical enterprises including coatings, resins, additives, and agrochemical intermediates. Daily documents include batch production instructions, feeding review sheets, reaction process records, cleaning records, test reports, deviation and change orders. Data updates follow the rhythm of each batch production or each key process step. Fields include formula parameters, feeding quantities, reaction parameters, and test results. Field units change dynamically based on specific process items.

## What constraints these characteristics impose on deployment and upgrade
The high-frequency batch-level updates, multiple heterogeneous data sources, sensitive formula confidentiality, and multi-product switching characteristics of this category create multiple constraints for deployment and upgrade.
High-frequency small-batch data updates require support for incremental synchronization mechanisms during deployment. This avoids excessive storage and computing resource usage from full indexing.
Heterogeneous data from multiple sources requires compatibility with different databases and device interfaces. Data source access rules must be configured in advance.
Formula confidentiality requires configuration of document permissions and sensitive data desensitization strategies during deployment. This prevents leakage of core process information.
The upgrade process must ensure ongoing audit workflows are not interrupted. This avoids disrupting continuous production batch schedules.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `10–15` | Adapts to database connection requirements for high-frequency multi-batch access, prevents connection pool exhaustion |
| `MONGODB_URI` | `mongodb://[username]:[password]@[host]:[port]/[database name]?authSource=admin` | Stores unstructured data such as batch records and reaction process documents, configured per FastGPT v4.17.0 storage rules for secure connection addresses |
| `REDIS_URL` | `redis://:[password]@[host]:[port]/0` | Caches validation rules, user sessions, and bulk data indexes, uses a dedicated database to avoid conflicts with other business operations |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.100:9000` (on-premises deployment) or official public cloud S3 endpoints | Stores attached files such as cleaning records and test reports, adapts to the enterprise’s existing storage architecture |
| `ROOT_KEY` | 32-bit random string generated per enterprise confidentiality rules | Manages system backend permissions, prevents unauthorized access to core configuration interfaces |
| `FE_DOMAIN` | `https://fastgpt.chemical-manufacturer.com` | Configures the frontend access domain name, adapts to the enterprise’s internal domain management rules |

## Three common configuration errors
- Symptom: Database connection errors, prompt indicating connection limit exceeded, status code 500. Cause: `DB_MAX_LINK` is not configured or the value is too low, cannot support concurrent database query requests from multiple batches.
- Symptom: Knowledge base attachments cannot be updated. Latest cleaning records or test reports are missing from search results. Cause: Incremental synchronization tasks are not configured per batch update frequency, or `STORAGE_S3_ENDPOINT` is not correctly configured to point to the latest storage path.
- Symptom: Locally deployed large model calls to MCP query service fail, returns connection timeout error. Cause: `REDIS_URL` is not configured as the caching middleware for model calls, or the local deployment model port is not opened to the network where the MCP service resides, causing requests to fail to forward normally.

## How to confirm the configuration is properly set
- Navigate to the system data source management interface. Verify that configured connection information such as `MONGODB_URI` and `PG_URL` matches the enterprise’s existing systems. Confirm that the connection status displays as normal.
- Upload a latest feeding review sheet document to trigger the incremental synchronization task. Confirm that the complete content of the document can be loaded normally in search results.
- Initiate multiple concurrent audit query requests. Confirm that no connection limit exceeded errors occur in the database. Verify that the `DB_MAX_LINK` configuration meets current business requirements.
- Use an unauthorized account to attempt logging in to the system. Confirm that access to document directories containing core formula parameters is denied. Verify that permission configurations are effective.

The values provided are common starting points and should be evaluated against the deploying entity’s own samples.
