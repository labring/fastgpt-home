# Supplier and Process Quality Audit for Spinning and Weaving: Workflow Orchestration

## What the data for this category looks like
Core data for this category comes from raw fiber inspection reports, ERP systems, real-time collected data from spinning and weaving machines, results output by evenness testers and fabric inspection machines, and order specification documents. Daily generated documents include cotton blending or ingredient lists, process setup sheets, equipment operation records, yarn inspection sheets, gray fabric inspection sheets, and defect ledgers. Data updates synchronize with production batches, work shifts, and individual fabric pieces. Corresponding data is generated or updated each time a batch of raw materials is processed, a shift finishes production, or a single fabric piece is completed. Fields include fiber indicators, twist parameters, loom speed, defect types and locations, and other metrics. Some parameters require adjustment based on the equipment model of the corresponding production line.

## What constraints do these characteristics impose on workflow orchestration?
Data sources for this category are scattered, covering offline inspection reports, real-time equipment-collected data, and ERP business data. Workflow orchestration must support parallel pulling of multiple data source nodes and uniform formatting. Data updates synchronize with production batches, shifts, and individual fabric pieces. Workflows must adapt to high-frequency trigger scenarios to avoid waiting delays. Defect records and process parameter fields for individual fabric pieces have equipment-specific differences. Workflows must reserve `variables` configuration space to adapt to field mapping for different production lines. Additionally, audit data volumes for bulk raw materials and fabrics are large. Workflows must support batch processing nodes to prevent single calls from exceeding load limits.

## Configuration Settings
The following configurations are compatible with the workflow function of FastGPT v4.17.0:

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Map fiber indicator, twist parameter, and defect ledger fields | Adapt to field differences from equipment customization for this category |
| Single Trigger Limit | 10 fabric pieces per trigger | Match the number of fabric pieces in a single production batch to avoid excessive load |
| Timeout Threshold | 600 seconds | Cover the maximum time required for equipment data pulling and audit calculations |
| Context Window | 8000–12000 token | Adapt to long-text process and inspection reports |
| `nodeId` | Assign fixed identifiers based on production line data sources | Distinguish equipment data nodes for different production lines to prevent call confusion |
| Output Trigger Rule | Execute only after the text splicing node is completed | Display final results in the order of the audit workflow |

## Three Common Configuration Mistakes
- A runtime error `Cannot convert undefined or null to object` occurs. The cause is that field mapping for the corresponding data source is not configured in `variables`, causing empty values to be read during node calls.
- The workflow only displays the original output of the AI chat node, and cannot output processed results to the dialog box. The cause is that the trigger timing of the text splicing node is not configured, and the output node is not connected in the workflow order.
- Historical inspection records cannot be passed as variables into the workflow. The cause is that the global variable configuration entry for the workflow is not enabled, and variables are incorrectly bound only to a single chat node.

## How to Verify Proper Configuration
- Manually trigger a simulated single fabric piece audit process, and verify whether each data source node correctly pulls test data for the corresponding fields.
- Check whether the `variables` configuration covers the core inspection fields of the current production line, with no missing or incorrect mappings.
- Verify that the output node triggers only after the text splicing node is completed, and confirm that original AI chat content is not displayed directly.
- Simulate a high-frequency trigger scenario, and check whether the workflow completes all node executions within the preset timeout threshold.

The values provided are common starting points and should be measured against the reader's own samples.
