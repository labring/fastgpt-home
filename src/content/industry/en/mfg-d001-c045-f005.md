# Supplier and Process Quality Audit for Spinning and Weaving: Tool Calling and Plugins

## What Data Looks Like for This Category
Data for this category typically comes from raw fiber inspection reports, ERP systems, spinning and loom operation logs, data collected by evenness testers and fabric inspection machines, and order specification documents. Daily documents include cotton blending or ingredient lists, process setup sheets, equipment operation records, yarn inspection sheets, grey fabric inspection sheets, and defect ledgers. Data updates synchronize with each batch of raw materials, each shift’s production, and each piece of fabric produced. Fields include fiber indicators, spinning twist, weaving structure parameters, defect types and locations, and some indicators use dedicated units such as tex and meters.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins
Data for this category is multi-source, dispersed, and updates in sync with production cycles. Tool calling must support real-time retrieval of the latest data from different systems. For example, sync defect records to the audit process immediately after a piece of fabric is produced. Different data sources have significant format differences. Plugins must adapt to paper-to-electronic conversions of raw fiber inspection reports, dedicated output files from evenness testers, and structured ERP interfaces. The volume of production data for a single batch of raw materials or single piece of fabric is concentrated. The context for tool calling must be limited to the corresponding batch, shift, or fabric number to avoid redundant data interfering with audit logic. Defect records must be linked to specific production parameters. Tool calling must pass dedicated fields such as yarn twist and loom model to ensure audit results are traceable.

## Configuration Settings
This configuration is developed for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `auto` | Automatically matches tool calling needs for supplier audits and production workflows, adapts to multi-source calling logic |
| `functionCall` | `enabled` | Forces tool calling to ensure audit workflows depend on real-time production data, and only retrieves real-time production-related data |
| Tool calling timeout | `300–600 seconds` | Covers response delays across multi-source production systems, adjust the range based on actual measurements |
| Tool calling data scope | Current production batch | Limits retrieval to raw materials, equipment, and inspection data for the corresponding batch only, avoids interference across batches |
| Plugin data source whitelist | ERP, evenness tester, fabric inspection machine interfaces | Only allows calls to category-specific production data interfaces, ensures compliance with data access requirements |

## Three Common Misconfigurations
- Symptom: Tool calling returns empty results or a 500 status code. Cause: No category-specific data source whitelist is configured, so plugins cannot access dedicated interfaces such as evenness testers and fabric inspection machines.
- Symptom: Tool calling in advanced orchestration fails to trigger, the interface shows no errors but the audit workflow stalls. Cause: The `functionCall` configuration item is not enabled, so the system does not generate a tool calling request body.
- Symptom: Timeouts or format errors occur when calling a locally deployed large language model. Cause: The tool calling request body is not adapted to the input format of the local model, and a reasonable timeout range is not configured.

## How to Verify the Configuration Is Correct
- Manually trigger tool calling, check if the returned production data includes cotton blending indicators and equipment operation records for the current batch.
- Review plugin logs to confirm only configured data source interfaces are called, and no unauthorized access requests appear.
- Temporarily adjust the `toolChoice` configuration to `none`, verify that the system skips tool calling and directly generates a response.
- Simulate a single piece of grey fabric defect audit workflow, confirm that the defect data returned by tool calling matches the real-time records from the fabric inspection machine.

The values provided here are common starting points and should be evaluated against local samples.
