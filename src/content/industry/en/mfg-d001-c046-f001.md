# Supplier and Process Quality Audits for Meat Products and Slaughter Processing: HTTP Interfaces and External Systems

## What data looks like for this category
Core data for this category comes from daily production and compliance documents of slaughterhouses, cooked meat and frozen prepared food enterprises. This includes animal quarantine certificates, slaughter and cutting records, ingredient marinating records, thermal processing parameter records, cold chain temperature logs, and microbial test reports.
Data sources cover animal quarantine information systems, supplier batch ledgers, production traceability platforms, temperature collection terminals, metal detection equipment, and laboratory testing systems.
Data updates follow production batches and shift schedules. Cold chain temperature data must be collected and uploaded continuously. Single-batch data is linked to complete quarantine, processing, and circulation links.

## Constraints imposed on HTTP interfaces and external systems
Batch-linked data for this category requires interfaces to carry batch ID and quarantine number as core verification parameters. This prevents mixing of data from different batches.
Continuously collected cold chain temperature data has a large volume. Interfaces must support batch upload or chunked transmission to avoid single-request timeouts.
Document fields vary across different processing stages. For example, quarantine certificates include animal origin information, while temperature records only contain location points and values. Interfaces must adapt to request bodies with multiple field formats.
Compliance data must strictly align with traceability requirements. Interface-returned verification results must be clearly linked to corresponding batches to support subsequent audits.

## How to configure settings
The following configurations are based on the interface logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Request timeout | 600 seconds | Adapts to the request duration for multi-field batch uploads in this category, avoiding timeouts triggered by large data volumes |
| `Authorization` | Format is `Bearer {enterprise-specific API key}` | Verifies access permissions for external systems, meeting compliance and security requirements for the food processing industry |
| `variables` | Pre-set three variables: batch ID, quarantine certificate number, and cold chain point | Adapts to the dynamic filling needs of batch-linked data for this category, simplifying configuration for multi-scenario requests |
| `responseData` | Only return batch verification result and error code fields | Reduces invalid data transmission and improves interface response efficiency |
| Data chunked upload threshold | 1000 entries per request | Adapts to the volume of continuously collected cold chain temperature data, avoiding overload from single requests |
| Retry strategy | Retry 2 times after failure, 30-second interval | Addresses network fluctuations or temporary interface exceptions, ensuring data upload success rate |

## Three common configuration mistakes
- Phenomenon: Interface returns 401 unauthorized error, or requests are blocked by external systems. Cause: `Authorization` parameter is not configured correctly, token format is incorrect, or valid key is not carried.
- Phenomenon: Front end cannot receive streaming cold chain temperature data and cannot display it line by line. Cause: Streaming transmission configuration is not enabled, or the interface does not correctly return an SSE-format response body.
- Phenomenon: Uploaded batch data does not match the quarantine certificate, and empty fields appear. Cause: Batch ID and quarantine number variables in `variables` are not correctly bound, resulting in associated fields not being carried in the request body.

## How to confirm configurations are correct
- Call the test interface, check if the returned `responseData` only contains the preset verification result and error code fields, confirming that the data filtering configuration is effective.
- Simulate uploading 1000 cold chain temperature data entries in a single request, verify that the interface can normally receive and return a success status, confirming that the chunked upload threshold configuration is reasonable.
- Check if the format of the `Authorization` parameter complies with the Bearer token specification, use an invalid key to call the interface, confirm that a 401 error is returned, verifying that the permission verification is effective.
- Manually modify the batch ID variable in `variables`, initiate a request, check if the request body received by the external system carries the new batch ID, confirming that the dynamic variable configuration is effective.

The values provided are common starting points and should be measured against the reader's own samples.
