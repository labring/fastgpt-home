# Supplier and Process Quality Audit for Meat Products and Slaughter Processing: Vector Models and Indexes

## What the Data for This Category Looks Like
Data for this category comes primarily from daily production and compliance documents of slaughterhouses, cooked meat and frozen prepared food enterprises. These documents include animal quarantine certificates, slaughter and cutting records, ingredient marinating records, thermal processing records, cold chain temperature records, and microbial test reports.
Data sources cover animal quarantine information, supplier batch ledgers, production traceability systems, real-time temperature collection equipment, metal detection equipment, and laboratory test results.
Update frequency follows production batches and shifts. Cold chain temperature records are updated continuously in real time. Fields include batch number, quarantine number, temperature value (degrees Celsius), detection time, and partition identifier, among others.

## Constraints on Vector Models and Indexing
This category’s data characteristics impose three core constraints on vector models and indexing:
1. Continuous real-time cold chain temperature records have a high update frequency. An incremental indexing update strategy must be used to avoid performance losses from full index rebuilding.
2. The strong association between batches and quarantine certificates requires indexes to bind batch number metadata, preventing matching of irrelevant records across batches.
3. Document types vary widely in length, from short quarantine numbers to several pages of production records. Chunking strategies must be adjusted to fit the input length limits of vector models, while retaining key cross-chunk association information.

## Configuration Settings
| Configuration Item | Recommended Values | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Fits the average length of documents such as quarantine certificates and production records, avoids including excessive cross-batch association information in a single chunk |
| Overlap Length | 100–150 characters | Retains key cross-chunk metadata such as batch numbers and temperature values, prevents association information from being truncated by chunking |
| `maxToken` | 4096 token | Matches the input token limit of Qwen3-Embedding-8B, fits the total length of single-batch records |
| Similarity Threshold | 0.75–0.85 | Distinguishes vector matching accuracy for qualified and unqualified microbial test and temperature records |
| Single Search Limit | Top 10 results | Covers the number of associated records required for single-batch audits, avoids redundant data interfering with audit logic |
| Maximum Context | 8000 characters | Integrates multi-chunk associated quarantine, production, and cold chain data, meets context requirements for complete audit logic |

## Three Common Misconfigurations
- Setting a `maxToken` value greater than 4096 results in a 413 status code error from the API. This occurs because the input token limit of Qwen3-Embedding-8B is not matched, leading to the vectorization request being rejected by the model.
- Failing to configure metadata indexes to associate batch numbers results in cross-batch cold chain temperature records appearing in vector search results. This happens because batch numbers are not used as index association fields, and vector matching relies only on text content, unable to filter data from unrelated batches.
- Failing to adjust the index refresh cycle for high-frequency temperature control data results in temperature records stored in the knowledge base deviating from actual production data by more than one hour. This occurs because an index update interval consistent with static documents is used, without adapting to the continuously real-time updated temperature control data.

## How to Verify Proper Configuration
- Upload quarantine certificates and corresponding production records for a single batch, run a vector search, and confirm that returned results only include associated documents for that batch.
- Check the system disk usage statistics in FastGPT v4.17.0, and confirm that knowledge base storage includes three parts: original files, split text chunks, and embedded vectors.
- Call the locally deployed VLLM embedding interface, input test text, and confirm that the returned vector dimension matches the standard dimension of Qwen3-Embedding-8B.
- Trigger a batch vectorization task, observe that there are no `maxToken` overlimit errors in the task logs, and the task completion rate is 100%.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
