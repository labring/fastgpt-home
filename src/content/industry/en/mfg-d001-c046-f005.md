# Supplier and Process Quality Audit for Meat Products and Slaughter Processing: Tool Calling and Plugins

## What data for this category looks like
Typical entities in this category include slaughterhouses, cooked meat and frozen prepared food enterprises. Daily documents include quarantine certificates, slaughter and cutting records, ingredient marinating records, thermal processing records, cold chain temperature records, and microbial test reports. Data sources include animal quarantine information, supplier batches, production traceability systems, temperature collection equipment, metal detection equipment, and laboratory testing systems.

Data updates follow this rhythm: each batch of raw materials triggers one quarantine and batch record update. Processing link records are synchronized per shift. Cold chain temperature requires continuous collection and updates.

Fields include quarantine number, raw material batch number, processing temperature value, test time, microbial indicator value, and others. Some fields must match compliance formats related to biosafety.

## What constraints these characteristics impose on tool calling and plugins
Data is updated per batch and must be strictly linked to quarantine information. This requires tool calls to be bound to batch-level data sources to avoid cross-batch data confusion.

Cold chain temperature is collected continuously. Tool calls must support real-time pulling or fixed-interval synchronization of temperature data. Otherwise, temperature control abnormalities cannot be detected in time.

Documents related to biosafety and compliance must call dedicated verification tools. Tool triggers must match processing link nodes, and cannot be called arbitrarily.

Data fields include numerical temperature and microbial indicators. Tool calls must support numerical parameter passing and verification. Otherwise, accurate test result comparison cannot be completed.

If tool call configuration is incorrect, compliance risks may occur, such as diseased raw materials entering production, cross-contamination, or microbial over-standard recalls. Configuration must strictly match business requirements.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically match tools for quarantine verification, temperature detection, microbial detection, and other scenarios to adapt to multiple types of audit use cases |
| `functionCall` | `{"strict": true}` | Strictly match required fields such as batch number and temperature value to avoid invalid parameter calls |
| Tool call timeout | `600 seconds` | Match the synchronization requirements of cold chain temperature data to avoid delays in handling temperature control abnormalities |
| Number of results per tool call | `Top 5` | Cover recent test and temperature control data related to the batch, balancing information completeness and processing efficiency |
| Batch association trigger cache duration | `30 minutes` | Match the update rhythm of shift processing records to avoid repeated calls of expired data |
| Raw/cooked area separation detection trigger condition | Triggered by processing link nodes | Call the partition detection tool when switching between raw and cooked processing to control sterilization temperature compliance |

## Three common configuration errors
- Symptom: The tool call returns an empty batch field. Cause: The batch association trigger rule is not configured. Tool calls cannot be bound to the corresponding raw material batch, resulting in misaligned audit data.
- Symptom: The API call returns a 403 permission denied error. Cause: The access permission policy for tool calls is not configured in FastGPT, and the access permission for the corresponding supplier data source is not bound. External calls cannot obtain compliant data.
- Symptom: The MCP client fails to call numerical type parameters. Cause: The strict parameter verification of `functionCall` is not enabled, and numerical fields such as temperature and microbial indicators are not passed in the required format. The tool cannot recognize valid test data.

## How to confirm the configuration is correct
- Submit simulated slaughter batch data, check whether the tool automatically calls the corresponding quarantine verification tool and returns matching results.
- Trigger cold chain temperature data pulling, check whether the tool obtains temperature values according to the set rules and completes abnormality detection.
- Use the API testing tool provided by FastGPT v4.17.0, check whether the returned results contain correct batch association information and have no permission errors.
- Enter the workflow editing page, confirm that the trigger conditions of the external MCP plugin match the processing links, and there is no response delay after the test call.
