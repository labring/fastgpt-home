# Supplier and Process Quality Audit for Meat Products and Slaughter Processing: Deployment and Upgrade

## Data for this category
Daily data for this category includes animal quarantine certificates, slaughter and cutting records, ingredient marination ledgers, thermal processing parameter logs, cold chain temperature logs, microbial test reports, and more. Data sources include animal quarantine information systems, supplier batch ledgers, production traceability systems, online temperature collection devices, metal detection terminals, and laboratory testing systems. Updates follow production batches and each shift cycle. Continuous temperature control data is synchronized in real time. Fields include batch numbers, quarantine identifiers, temperature thresholds, test results, and some records require matching biosecurity-related identifiers.

## Constraints during deployment and upgrade
Data sources for this category are scattered, and update frequencies vary widely. During deployment, access formats for multi-source heterogeneous data must be adapted. This includes structured temperature logs and unstructured scanned copies of quarantine certificates. Real-time synchronized temperature control data requires a high-frequency index update mechanism. This prevents data lag that affects audit timeliness. The strong binding requirement between batch and quarantine information requires associated verification logic. This stops mismatched data from entering the audit workflow. During upgrades, existing multi-source data access configurations must be compatible. This avoids interrupting production-related audit operations. Data storage permission controls must also be strengthened to meet biosecurity management requirements.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 10–15 | Adapt to concurrent access from multiple sources of equipment and documents, and meet real-time data import requirements for each production batch |
| `STORAGE_S3_ENDPOINT` | Intranet access address of the enterprise’s self-built object storage | Store large files such as cold chain temperature logs and quarantine certificates, and ensure local compliant data storage |
| `REDIS_URL` | Intranet-deployed Redis instance with memory limit set to 1000 MB | Cache frequently accessed batch association information to reduce database query latency |
| `FILE_TOKEN_KEY` | Unified key string consistent with the enterprise document management system | Verify the legitimacy of uploaded files such as quarantine certificates and test reports, and prevent unauthorized file access |
| `ROOT_KEY` | Key generated in accordance with enterprise internal permission control rules | Restrict background configuration access scope for audit workflows, and meet food production safety and compliance requirements |

## Three common mistakes
- Symptom: Knowledge base index creation steps stall, and background logs return database connection timeout errors. Cause: The `DB_MAX_LINK` parameter is not configured reasonably, and the number of concurrent connections is insufficient to support batch import of multi-batch production data.
- Symptom: After switching audit applications, the page still triggers mandatory global variable validation errors from the original application. Cause: Front-end cache has not been updated to synchronize application configurations, and global variable binding rules have not been reset.
- Symptom: Uploaded files such as quarantine certificates and cold chain temperature logs cannot be read by the system, and search results are empty. Cause: The `FILE_TOKEN_KEY` parameter is not configured correctly, and file authentication verification failures block data access.

## How to confirm configurations are correct
- Run a batch import test for production batch simulation data, check that index construction progress is not stalled, and confirm that database connection configurations are effective.
- Upload compliant quarantine certificates and temperature log files, verify that files can be read normally and associated with corresponding production batches, and confirm that the `FILE_TOKEN_KEY` configuration is correct.
- Log in to the FastGPT v4.17.0 backend management interface, check that the parameter values of `DB_MAX_LINK` and `REDIS_URL` match the preset configurations, and confirm that basic storage and cache configurations are correct.
- Switch between different audit applications, verify that global variable validation rules are updated synchronously with the application, and no residual validation logic from old applications remains.
