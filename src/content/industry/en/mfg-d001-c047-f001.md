# Supplier and Process Quality Audit for Measuring Instruments and Laboratory Management: HTTP Interfaces and External Systems

## What This Category of Data Looks Like
This category of data covers daily business documents from enterprise metrology rooms and CNAS system laboratories, including gauge ledgers, calibration plans, calibration certificates, periodic verification records, original test records, reference material ledgers, and deviation handling documents. Data sources include internal metrology management systems, external calibration institution certificates, standard instruments, LIMS systems, and environmental monitoring equipment. Data updates are triggered by calibration cycles, completion of single tests, or abnormal events. Fields include unique instrument numbers, calibration dates, measurement uncertainties, traceability chain numbers, environmental parameters, and more. Units include metrology-specific units such as length, force, and temperature.

## What Constraints These Characteristics Impose on HTTP Interfaces and External Systems
The traceability, specialized fields, and strict update rhythm of data in this category impose multiple constraints on HTTP interfaces. Metrology data must meet traceability requirements. Interface requests must carry a valid `Authorization` parameter for authentication to prevent unauthorized tampering of metrology data. Specialized fields such as measurement uncertainty and traceability number must be transmitted in strict accordance with formatting rules. The request body must include complete definitions of corresponding fields. Sudden abnormal update scenarios require the interface to support temporary batch submissions. A timeout mechanism must be configured to prevent long-term resource occupation. Binary attachment transmission for documents such as calibration certificates must adapt to the interface's file upload specifications to ensure complete delivery of attachments.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Include a Bearer token with a 7-day validity period | Used to verify external system call permissions, aligning with the high security requirements of metrology data |
| `variables` | Bind business fields such as instrument number, calibration date, and measurement uncertainty | Enables dynamic filling of metrology business parameters, adapting to audit workflows for different instruments |
| `responseData` | Verify the completeness of returned calibration certificate number and measurement result fields | Ensures metrology data returned by external systems complies with business formatting requirements |
| Request timeout duration | 600 seconds | Adapts to processing times for large file uploads such as calibration certificates or complex calculations |
| Batch submission threshold | 50 items per request | Matches the volume of metrology data for a single audit, preventing interface overload |
| File upload size limit | 1000 MB | Meets transmission requirements for attachments such as calibration certificate PDFs and scanned original test records |

## Three Common Mistakes
- After calling the interface to upload metrology documents, the interface remains in an indexing state for a long time. The cause is that the batch submission threshold is not configured correctly, and the number of metrology documents submitted in a single request exceeds the interface's carrying limit, causing the indexing process to block.
- The interface returns a `401 Unauthorized` status code. The cause is that the `Authorization` parameter is not set correctly, or the token has expired, failing authentication checks.
- The calibration data received by the interface lacks the measurement uncertainty field. The cause is that the corresponding business field in `variables` is not bound to the request body, resulting in incomplete metrology data transmitted by the external system.

## How to Confirm Proper Configuration
- Initiate a test request carrying a valid `Authorization` parameter, and check that the returned status code is 200.
- Submit test variables including instrument number and calibration date, verifying that fields bound via `variables` are correctly filled into the request body.
- Upload a calibration certificate attachment, checking that the verification result of the attachment is correctly returned in `responseData`.
- Simulate batch submission of 50 metrology data items, confirming that no timeout or overload error messages are returned by the interface.

The values provided are common starting points and should be measured against the reader's own samples.
