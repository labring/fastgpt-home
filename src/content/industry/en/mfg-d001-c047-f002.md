# Supplier and Process Quality Audit for Measuring Instruments and Laboratory Management: Vector Models and Indexes

## What the Data for This Category Looks Like
Data for this category comes from enterprise metrology rooms, metrology management systems in CNAS-compliant laboratories, LIMS platforms, external calibration institution certificates, and environmental monitoring data. Daily documents include gauge ledgers, calibration plans, calibration certificates, periodic verification records, original test records, reference material ledgers, and deviation handling documents. Updates are initiated by calibration cycles, single test results, or abnormal events. Each document includes fields with clear units: instrument number, measurement range, accuracy grade, measured value, uncertainty, calibration date, and more.

## What Constraints Do These Characteristics Impose on the Vector Model and Indexing Link
Multi-source heterogeneous data sources require indexes to support associative retrieval across system documents. Non-batch update modes triggered by calibration cycles or abnormal events require indexes to support incremental updates to avoid time-consuming full computation. Document structures with clear units and traceability fields require retaining field associations during chunking to avoid breaking the traceability chain when splitting. High-confidence quality audit requirements demand that the matching accuracy of vector retrieval results strictly aligns with business scenarios, with no irrelevant results appearing. The long-text nature of calibration certificates and test records requires vector model context windows to adapt to the length requirements of single documents.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Adapts to the single-content length of calibration certificates and original test records, avoiding splitting that breaks the association of traceability fields such as instrument number and calibration date |
| Overlap Length | 50–100 characters | Retains contextual association between chunks, ensuring continuous information on calibration cycles and periodic verification is not truncated |
| `maxToken` | 8192 | Adapts to the context window upper limit of most public vector models, meeting the full vectorization requirements of long-text calibration certificates |
| Similarity Threshold | Calibrated based on actual measurements | This category has high requirements for retrieval confidence, and matching accuracy needs to be adjusted based on actual quality audit retrieval results |
| Single Search Limit | Top 10 results | Covers the retrieval needs of multiple associated documents, ensuring complete associated records can be obtained when tracing the product scope affected by inaccurate instruments |
| `defaultToken` | Set from representative sample documents | `defaultToken` is the default token count for direct text chunking; tune it on representative source documents. See the [v4.17.2 model-field reference](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx). It is not a vector dimension, embedding-model input cap, or retrieval/LLM context. |

## Three Common Misconfigurations
- Phenomenon: After importing data, the status continues to show Creating Index for several hours. Cause: The chunking configuration was not adjusted for long texts such as calibration certificates and test records, and the single chunk content is too long, resulting in excessive vector computing resource usage.
- Phenomenon: Vector calculation scores are abnormal, with excessively high scores and consistent scores across multiple results. Cause: Metadata fields such as instrument number and calibration date were not retained during chunking, resulting in similar retrieval matching irrelevant long-text content and failing to accurately associate traceability information.
- Phenomenon: Vectorization processing speed is too slow, unable to meet the update needs of batch calibration data. Cause: Incremental index mode was not configured, and all historical data was fully indexed each time, repeating calculations for old documents that had already been vectorized.

## How to Confirm Proper Configuration
- View the index creation logs in FastGPT v4.17.0, confirm that the single chunk length conforms to the preset chunking configuration, with no abnormally split traceability fields.
- Retrieve a known instrument number, confirm that the returned results include associated calibration certificates, periodic verification records, and original test records, and the sorting conforms to business association logic.
- Import batch calibration data, verify that index creation time conforms to the preset time interval, with no continuous stuck or abnormal termination.
- Adjust the similarity threshold, verify that the matching accuracy of retrieval results conforms to the confidence requirements of quality audits.

The values provided are common starting points and should be evaluated against the reader's own samples.
