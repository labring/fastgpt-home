# Supplier and Process Quality Audit for Measuring Instruments and Laboratory Management: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
This category's data is primarily sourced from enterprise metrology rooms, metrology management systems of CNAS-accredited laboratories, LIMS platforms, external calibration institution certificates, and standard instrument data. Daily documents include gauge ledgers, calibration plans, calibration certificates, interim verification records, original test records, reference material ledgers, deviation disposition forms, and others. Fields include traceability numbers, measured values, measurement uncertainties, calibration cycles, environmental parameters, and additional metrology-specific fields. Units include metrology-specific units such as length, mass, and temperature. Data updates are triggered by calibration cycles, individual tests, or abnormal events, with no fixed batch update schedule.

## What constraints do these characteristics impose on the multi-turn dialogue and prompt engineering workflow
Data in this category has strong traceability, standardized formatting, and high compliance requirements, which create three constraints for multi-turn dialogue and prompt configuration. First, complete conversation context must be retained to track traceability chain changes, and truncation of critical calibration certificate numbers or measurement uncertainty data must be avoided. Second, prompts must clearly specify field extraction rules to ensure accurate extraction of metrology-specific fields from multiple document types such as gauge ledgers and calibration certificates, and avoid generalized processing. Third, the dynamic update rhythm of data must be adapted, and the latest calibration plans or interim verification records must be called in real time during conversations to ensure audit results are based on currently valid data.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum context length | 8000–12000 characters | Covers complete conversation context for multi-turn calibration certificates and gauge ledgers, avoids truncation of critical traceability information |
| Single recall result limit | Top 5 entries | Data entries in this category are standardized and have high precision requirements; a small number of recalls can cover all relevant metrology records |
| `variables` bound fields | Traceability number, measurement uncertainty | Use the `variables` parameter to bind core business fields, ensuring direct access to verification during conversations |
| `chatId` persistence | Enabled | Use the `chatId` parameter to retain conversation context and track traceability chain changes across multi-turn audits |
| `messages` context organization | Concatenated in conversation order, retain core fields such as traceability number and measurement uncertainty | Use the `messages` parameter to standardize conversation context format, avoiding interference from redundant information on audits |
| Prompt forced injection | Enabled | Ensures the model follows preset metrology audit logic, avoids being overwritten by custom content |
| Context refresh interval | 24 hours | Adapts to the update rhythm of daily calibration plans, ensuring conversations call the latest data |

## Three common mistakes
- Unassociated knowledge base documents in conversation responses: After calling the API to initiate a conversation, the returned content does not reference calibration certificates or gauge ledgers from the knowledge base. The cause is failure to correctly bind the `variables` parameter to the metrology data index in the knowledge base, leading to retrieval scope deviating from the business scenario.
- Page load crash: When using FastGPT v4.8.20, the conversation page or knowledge base page fails to load. The cause is a memory overflow defect in older versions' handling of multi-turn metrology document context caching. It is recommended to upgrade to FastGPT v4.17.0.
- Preset prompts not taking effect: When using a model deployed via Ollama, the preset audit prompts are not executed by the model. The cause is failure to enable prompt forced injection in the conversation configuration, or the model's system prompt being overwritten by custom content.

## How to confirm correct configuration
- Initiate a test query containing a traceability number preset in the knowledge base, verify that the returned result includes content from the corresponding calibration certificate in the knowledge base.
- Enable multi-turn conversations, submit three different metrology data queries consecutively, verify that the conversation continues to retain context associations.
- After configuring custom audit prompts, trigger the model to generate audit results, verify that the output includes the preset verification logic.
- View conversation logs, confirm that the business fields bound by the `variables` parameter have been correctly extracted and called.

The values provided are common starting points and should be measured against the reader's own samples.
