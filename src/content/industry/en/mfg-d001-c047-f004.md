# Supplier and Process Quality Audit for Measuring Instruments and Laboratory Management: Workflow Orchestration

## What this category of data looks like
Data sources include enterprise metrology management systems, external calibration institution certificates, reference standards, LIMS, and environmental monitoring equipment.
Updates are triggered by calibration cycles, each test, or abnormal events.
Daily documents include gauge ledgers, calibration plans, calibration certificates, interim check records, test original records, reference material ledgers, and deviation disposal forms.
Fields include instrument numbers, calibration validity periods, measurement uncertainty, traceability chain numbers, and environmental temperature and humidity parameters.
Units are mostly metrology-specific units such as millimeters, newtons, and pascals.

## What constraints these characteristics impose on workflow orchestration
Data sources are scattered and rely on outputs from external institutions. Workflows must support multi-source data pulling and format verification.
Update frequencies are inconsistent. Trigger nodes must be configured to start processes based on calibration plans or abnormal events.
Daily document fields are mostly metrology-specific parameters. Preset field verification rules are required to prevent invalid data from entering the workflow.
Traceability chain and uncertainty reviews require connecting multiple sequential nodes to ensure the process complies with system requirements.
The consequences of errors directly relate to product quality judgments. Exception nodes must be configured to trigger alerts and process rollback mechanisms.

## Configuration guidelines
This configuration rule applies to FastGPT v4.17.0.

| Configuration Item | Recommended Practice | Rationale |
| ---- | ---- | ---- |
| Global Variables | Map to measuring instrument ledger fields | Support subsequent node calls for core information such as instrument traceability and calibration status |
| Node Trigger Rule | Trigger 7 days before calibration expiration | Match the update and reminder rhythm of calibration plans |
| Data Verification Threshold | Calibrate measurement uncertainty error based on actual measurements | Comply with metrology professional precision requirements |
| `variables` scope | Take effect globally | Ensure synchronization of instrument status and parameters across nodes |
| `nodeId` binding rule | Bind to calibration certificate upload node | Fix process links to avoid data confusion caused by node misalignment |

## Three common configuration mistakes
- Opening the workflow prompts "Cannot read properties of undefined (reading 'incl')". The cause is that the metrology instrument fields bound to `variables` are not correctly configured, causing the node to read a null object when called.
- After setting global variables, subsequent components cannot obtain the variable value. The cause is that the `variables` scope is not set to take effect globally, only node private variables are configured.
- Workflow execution fails calibration certificate verification. The cause is that no field verification rules are configured, and parameter inputs that do not meet measurement units are not filtered.

## How to confirm the configuration is complete
- Verify that the fields bound to `variables` cover the core parameters of the measuring instrument ledger, including instrument number, calibration validity period, and others.
- Test whether the trigger node starts the process according to the set calibration cycle schedule.
- Check that the data verification rules match metrology-specific units and precision requirements.
- View whether the `nodeId` of the process link corresponds one-to-one with the node IDs in the actual page.

The values given are common starting points and should be measured against the reader's own samples.
