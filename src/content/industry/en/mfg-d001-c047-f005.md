# Supplier and Process Quality Audit for Measuring Instruments and Laboratory Management: Tool Calling and Plugins

## What this type of data looks like
Typical entities include enterprise metrology rooms, quality laboratories, and CNAS accredited laboratories. Daily documents cover gauge ledgers, calibration plans, calibration certificates, interim check records, original test records, reference material ledgers, and deviation handling records. Data sources include metrology management systems, external calibration institution certificates, standard instruments, LIMS, and environmental monitoring equipment. Data update rhythms change with calibration cycles, each test, and abnormal events. Data fields include instrument number, calibration date, measurement uncertainty, traceability number, and others. Some documents require measured values with legal measurement units.

## What constraints do these characteristics impose on the tool calling and plugins link
When data sources are scattered, configure independent authentication for each system separately to prevent permission mixing. Since data update rhythms are inconsistent, enable on-demand trigger synchronization and pull data based on actual needs. Daily audits rely on specific fields such as calibration certificates and traceability chains, so build tools to support accurate extraction of specified fields. Some documents require legal measurement units, so adapt tools to perform unit consistency checks. Audits also need to associate out-of-calibration instruments with product ranges, so enable tools to support cross-system data association queries.

## How to set up the configuration
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| Authentication configuration | Configure independent Bearer Token authentication for metrology management systems and LIMS separately | Data sources are scattered, access permissions for different systems must be isolated |
| Tool call timeout | 300-600 seconds | Calibration certificate retrieval and traceability chain queries require longer processing times |
| Workflow/API tool selection | auto | Automatically select whether to call metrology-related tools based on user queries |
| Field extraction rules | Only extract the four core fields: instrument number, calibration date, measurement uncertainty, and traceability number | Daily supplier and process quality audits only require core compliance data |
| Number of data items returned per single call | Top 20 entries | Avoid returning too much data which causes timeouts |
| Data source sync trigger condition | Trigger when calibration cycle expires or abnormal records are generated | Data update rhythms change with calibration cycles, tests, and abnormal events |
| Workflow/API function-call configuration | Enable mandatory validation of returned field formats | Ensure audit data formats meet compliance requirements |

## Three common misconfigurations
- Symptom: Calling the metrology management system API returns a 401 Unauthorized status code. Cause: Independent authentication information was not configured for different data sources, and authentication credentials for different systems were mixed.
- Symptom: The measurement uncertainty field is empty in calibration certificate data extracted by the tool. Cause: Accurate field extraction rules were not configured, and this core audit field was accidentally filtered out.
- Symptom: Insufficient number of results returned when tracing the product ranges affected by out-of-calibration instruments. Cause: Data source synchronization was not triggered based on calibration cycles or abnormal events, so associated batch data for some instruments was not updated.

## How to confirm the configuration is properly set up
- Initiate a tool call for the gauge ledger, check that returned data includes preset core fields.
- Call the external calibration certificate API, verify that returned authentication information is valid and no unauthorized errors occur.
- Simulate generating a deviation handling record, trigger data source synchronization, and check that status data for the corresponding instrument has updated.
- After setting `toolChoice` to auto, send a request including a query for calibration uncertainty, verify that the tool automatically triggers the call.

The values provided are common starting points and should be evaluated against samples specific to each deployment.
