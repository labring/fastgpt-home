# Supplier and Process Quality Audit for Measuring Instruments and Laboratory Management: Document Parsing and Chunking

## What the Data for This Category Looks Like
Organizations in this category source typical data from metrology rooms, metrology management systems of CNAS-accredited laboratories, LIMS, external calibration institution certificates, and standard instrument data. Daily documents include gauge ledgers, calibration plans, calibration certificates, interim verification records, original test records, reference material ledgers, and more. Some calibration certificates are scanned PDFs. Data updates trigger on calibration cycles, single tests, or abnormal situations. Documents include fields such as instrument number, calibration result, measurement uncertainty, traceable standard instrument number, and use units including millimeters and newtons.

## Constraints Imposed on Document Parsing and Chunking
The data characteristics of this category impose multiple constraints on document parsing and chunking. First, a large volume of scanned PDF calibration certificates exists, so OCR text recognition workflows must be supported. Second, documents contain structured ledger tables and unstructured test records. Chunking rules must balance the integrity of structured fields and the coherence of unstructured text. Third, data update frequencies vary widely, from single-page records for individual tests to batches of calibration certificate collections. The system must adapt to different document lengths. Finally, traceability chain-related information must retain complete context, avoiding chunking that cuts off key associated fields such as instrument numbers and calibration institutions.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | This category of documents includes structured tables and long-text calibration records. This range preserves complete measurement items and traceability associated information for a single calibration certificate |
| `chunkSplitter` | markdown+ocr hybrid mode | Documents include parsable Markdown-format ledgers and scanned calibration certificates. The hybrid mode handles both structured and unstructured content |
| `customPdfParse` | enabled | This category contains a large number of scanned PDF calibration certificates. Enabling this triggers OCR parsing workflows to extract valid text content |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Multi-page scanned calibration certificates or batch document parsing takes a long time. This range avoids timeout failures |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Common size for bulk-uploaded gauge ledger Excel packages or collections of multiple calibration certificate PDFs |
| `chunkSettingMode` | manual | This category of documents has large structural differences. Manual configuration accurately matches the chunking needs of different document types |

## Three Common Misconfigurations
- Symptom: Uploading a scanned PDF calibration certificate results in empty or garbled parsed text. Cause: The `customPdfParse` configuration is not enabled, so the OCR parsing workflow is not triggered, and text content from scanned files cannot be extracted.
- Symptom: Uploading a gauge ledger Excel file results in missing measurement value fields in the vectorized index. Cause: Chunking rules adapted for structured tables are not configured. The default chunking logic breaks the row-column associations of the table, leading to incomplete field splitting.
- Symptom: Parsing times out when uploading a batch of multiple calibration certificate collections. Cause: The value of `PARSE_FILE_TIMEOUT_SECONDS` is too small, leaving insufficient time for OCR and parsing workflows for multi-page scanned documents.

## How to Verify Correct Configuration
- Upload a scanned calibration certificate PDF, check if the parsed text includes core fields such as calibration results and measurement uncertainty, to confirm the `customPdfParse` configuration is active.
- Upload a gauge ledger Excel file, review the vectorized chunking results to confirm that complete column information such as instrument number and calibration date is retained, to confirm the chunking rules adapt to table structures.
- Upload a calibration certificate collection larger than 200 MB, check if the upload and parsing processes complete normally, to confirm the `UPLOAD_FILE_MAX_SIZE` and `PARSE_FILE_TIMEOUT_SECONDS` configurations are reasonable.
- Adjust `chunkSize` to different ranges, compare the contextual integrity of the chunked results, to confirm the configuration matches the information density of this category of documents.

The values provided here are common starting points, and should be evaluated against the user’s own sample data.
