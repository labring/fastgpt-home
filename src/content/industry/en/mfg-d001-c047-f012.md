# Supplier and Process Quality Audit for Measuring Instruments and Laboratory Management: Deployment and Upgrade

## What the data for this category looks like
Data for this category comes from metrology management systems, external calibration institution certificates, reference standards, LIMS, and environmental monitoring equipment. Daily documents include gauge ledgers, calibration plans, calibration certificates, periodic verification records, original test records, reference material ledgers, and deviation handling documents. Data updates trigger based on calibration cycles, single test results, or abnormal situations. Fields include instrument number, calibration date, measurement uncertainty, traceability number, and other relevant fields. Units cover metrology-specific values such as length, force, and temperature.

## What constraints these characteristics impose during deployment and upgrade
Data sources for this category are scattered and have diverse formats. Formats include both structured ledger data and unstructured certificate files. Deployments must support access to multiple data sources and hybrid storage. Data updates follow no fixed cycle. Deployments must support both scheduled synchronization and real-time trigger update modes. Data must fully support traceability chains and quality judgments. Deployments must include data verification and permission isolation capabilities. These capabilities prevent traceability failure or permission escalation caused by configuration oversights. Errors in metrology data directly affect product quality judgments. Deployments must reserve sufficient debugging and verification space.

## How to set configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30 connections` | Adapts to high-frequency read/write demands for gauge ledgers and calibration records. Prevents database connection exhaustion. |
| `MONGODB_URI` | Fill in the intranet address of the locally deployed MongoDB instance | Stores unstructured large text data such as calibration certificates and original test records. |
| `REDIS_URL` | Configure to the local Redis service address. Set the timeout threshold to `300 seconds`. | Caches calibration cycle reminders and traceability chain query results. Reduces repeated calculation overhead. |
| `FE_DOMAIN` | Fill in the public or intranet access domain name of the deployment node | Supports session credential distribution and cross-node verification during multi-account login. |
| `STORAGE_S3_ENDPOINT` | Fill in the intranet access endpoint if using local object storage | Stores files such as batch-uploaded calibration certificates and reference material ledgers. |
| `ROOT_KEY` | Generate a random string based on the deployment environment | Initializes administrator permissions. Ensures permission isolation for multi-account systems. |

## Three common configuration errors
- Symptom: Multi-account login fails after local Docker deployment. A session verification failure prompt displays. Cause: `FE_DOMAIN` is not correctly matched to the deployment node’s actual access address. Session credentials cannot complete cross-node verification.
- Symptom: No results return after initiating a knowledge base query. The console shows a timeout error. Cause: The `REDIS_URL` timeout configuration is not adjusted. Batch calibration record queries exceed the default timeout threshold.
- Symptom: Calibration certificates cannot associate with the corresponding gauge ledger after upload. Cause: The correct storage path for `STORAGE_S3_ENDPOINT` is not configured. File metadata fails to match ledger fields.

## How to confirm the configuration is complete
- Access the login page corresponding to `FE_DOMAIN`. Log in using an administrator account and a regular account separately. Verify sessions remain normal.
- Upload a standard calibration certificate file. Confirm the file stores successfully. Check that corresponding content retrieves in the knowledge base.
- Execute a batch gauge ledger synchronization task. Verify the task completes within `300 seconds` with no error logs.
- Call the administrator interface linked to `ROOT_KEY`. Confirm regular accounts cannot access the administrator configuration page. Verify permission isolation takes effect.

The values provided are common starting points and should be measured against the reader's own samples.
