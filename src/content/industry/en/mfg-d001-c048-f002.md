# Supplier and Process Quality Audit for Equipment Inspection and Preventive Maintenance: Vector Models and Indexes

## What Data Looks Like for This Category
Data for this category comes from daily documents and system data held by manufacturing enterprise equipment departments, maintenance teams, and other relevant entities. It includes equipment ledgers, inspection checklists, maintenance plans, work orders, failure analysis reports, spare parts lists, special equipment inspection records, and other related types.
Data sources include EAM/CMMS systems, equipment sensor data, operator inspection logs, maintenance history, spare parts inventory, and statutory inspection information.
Updates occur per shift, daily, weekly, monthly, and in real time when faults are detected.
Fields include equipment identification numbers, inspection locations, measured parameters, fault symptoms, spare part models, inspection validity periods, and other relevant attributes.

## Constraints for Vector Models and Index Workflows
This category has diverse data types: structured inspection parameters, unstructured failure analysis text, and associated statutory records. Update frequencies span wide ranges.
Indexes must support vector mapping for multimodal data and incremental synchronization.
Equipment ledgers and inspection records link compliance fields. Index fields must maintain semantic consistency to avoid splitting critical associated information.
Failure descriptions in maintenance work orders often use colloquial industrial language. Select a vector model suited for industrial scenarios to ensure semantic matching accuracy.
Non-planned downtime risks are high. Index retrieval must deliver low-latency recall efficiency.

## Configuration Settings
| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Matches single-segment semantic integrity for equipment inspection checklists and maintenance work orders, prevents splitting associated information such as fault descriptions or spare part models |
| Overlap Length | 100–150 characters | Prevents chunk boundaries from breaking the correspondence between inspection items and measured values, ensures semantic coherence |
| `defaultToken` | Set from representative sample documents | `defaultToken` is the default token count for direct text chunking; tune it on representative source documents. See the [v4.17.2 model-field reference](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx). It is not a vector dimension, embedding-model input cap, or retrieval/LLM context. |
| `maxToken` | Set to the selected embedding model/service maximum supported input tokens | `maxToken` is the input-token maximum supported by the selected embedding model/service; verify it in that provider configuration. See the [v4.17.2 model-field reference](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx). It is not retrieval/LLM context or a FastGPT-wide fixed cap. |
| Similarity Threshold | 0.72–0.80 | Filters low-correlation equipment sensor data, retains historical records strongly associated with current fault troubleshooting |
| Single Search Limit | Top 10 entries | Controls the scale of retrieval results, fits the rapid query scenarios of workshop maintenance teams |

## Three Common Errors
- Symptom: Embedding model calls return 503 errors, with prompts indicating no available channels for the specified model. Cause: No separate embedding model is configured for the indexing workflow. Reusing the key and channel configuration from the conversation interface causes embedding requests to fail to match correct model resources.
- Symptom: After configuring the CHAT_API_KEY environment variable, the service does not load the new key information. Cause: The container is not rebuilt to load updated environment variable configurations, so old runtime configurations remain active.
- Symptom: Retrieved inspection records do not match fault descriptions, with significant deviation in result relevance. Cause: Incorrect chunk length settings split the associated semantics of inspection items and measured values, preventing the vector model from capturing complete business associations.

## How to Verify Proper Configuration
- Access the FastGPT index management page to confirm that the current embedding model configuration matches the dedicated indexing model.
- Upload a sample equipment inspection checklist or maintenance work order, run a retrieval test, and verify that returned result relevance meets the preset threshold.
- Review service runtime logs to confirm that there are no 503 errors or key-related error messages from embedding model calls.
- Adjust the chunk length parameter, re-upload the sample data, and verify that retrieval results retain semantic integrity without damage.

The values provided are common starting points and should be measured against the reader's own samples.
