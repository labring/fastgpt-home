# Supplier and Process Quality Audit for Equipment Inspection and Preventive Maintenance: Citation Sources and Traceability

## What This Category of Data Looks Like
This category of data covers structured and unstructured content related to the full lifecycle of equipment. Daily documents include equipment ledgers, inspection checklists, maintenance plans, work orders, fault analysis, spare parts lists, and special equipment inspection records. Data sources include EAM/CMMS systems, equipment sensor data, operator inspection records, maintenance history, spare parts inventory data, and statutory inspection information. Update frequencies cover shifts, daily/weekly/monthly cycles, and real-time updates when faults occur. Fields include equipment numbers, inspection points, operating parameter thresholds, maintenance man-hours, spare part models, and others, with units including millimeters, revolutions per minute, hours, and more.

## How These Data Characteristics Impact Citation and Traceability
The data characteristics of this category impose multiple constraints on the citation and traceability process. Dispersed multi-source data requires traceability tools to associate content from different systems such as EAM/CMMS, sensor data, and inspection records, to avoid information bias from single-source data. Differentiated update frequencies require traceability to support real-time matching of sensor data when faults occur, while also adapting to historical traceability for daily/weekly/monthly cycle inspection and maintenance plans. Diverse document structures require traceability to extract key fields such as equipment numbers and parameter thresholds from different format documents, and only display relevant content instead of the full document. Severe error consequences require traceability information to accurately associate corresponding equipment and time nodes, to avoid unplanned downtime or quality issues caused by mismatches.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 characters | Adapts to the length of single entries in equipment inspection checklists and work orders, to avoid truncating key parameters and equipment identifiers |
| `responseData` | Enabled | Attaches original structured data returned by MySQL calls, retaining traceability fields such as spare part models and inspection points |
| `detail` | Enabled | Displays metadata of source documents, including the uploading work team, update time, and document type |
| Single recalled citation count | Top 3–5 entries | Adapts to the volume of shift-based inspection records, to avoid context window overflow |
| FastGPT Version | v4.17.0 | Adapts to the parameter configuration logic of this version |

## Three Common Configuration Mistakes
- Symptom: The AI response only generates text, and does not include original equipment inspection snippets returned by MySQL calls. Cause: The `responseData` configuration is not enabled, and original structured data is not attached.
- Symptom: The number of traceable documents displayed in the response exceeds the preset limit. Cause: The `quoteMaxToken` parameter is not set correctly, or the single recalled citation entry limit is not enforced.
- Symptom: Key fields such as equipment numbers and inspection times are missing from traceability information. Cause: Specified fields in the original data are not extracted, and the full document content is displayed instead.

## How to Verify a Successful Configuration
- Initiate a query related to equipment inspection, and check whether metadata of source documents is displayed at the end of the response.
- Check whether the response includes original data snippets returned by MySQL calls.
- After adjusting the `quoteMaxToken` parameter, verify that the response fully displays inspection record content without truncation.
- Check whether the toggle switches for `responseData` and `detail` in the configuration interface are set to enabled.

The values provided are common starting points and should be measured against the reader's own samples.
