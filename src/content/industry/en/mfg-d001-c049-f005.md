# Supplier and Process Quality Audits for In-Process Quality and Final Product Release: Tool Calling and Plugins

## What the data for this category looks like
Daily audit documents for this category include control plans, patrol inspection records, SPC reports, final product inspection reports, nonconforming product reviews, release orders, and quality monthly reports. Data sources cover manufacturing execution systems (MES), testing equipment, laboratory systems, process parameter libraries, customer standard libraries, and historical defect libraries. Data updates trigger alongside production batches and patrol inspection nodes. Some online monitoring indicators are collected continuously. Data fields include inspection item numbers, batch identifiers, defect types, judgment results, release status, and other relevant items. The structure adjusts dynamically based on production scenarios, with no fixed unified statistical caliber.

## What constraints these characteristics impose on the tool calling and plugins workflow
Multi-source heterogeneous data sources require tool calling to adapt to the API formats and permission rules of different systems. This avoids audit process interruptions caused by failed data docking. The high-frequency updated production rhythm requires tool calling to be bound to production batch and patrol event triggers. This reduces invalid calls and resource consumption. The need to process multiple types of documents requires plugins to support structured parsing, text extraction, and field mapping. This adapts to audit materials in different formats such as control plans and inspection reports. Strict quality control requirements mean tool calling must include exception capture and retry mechanisms. This addresses issues such as occasional interruptions in testing equipment data transmission and system interface timeouts.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to dynamically occurring inspection item judgment scenarios in process quality audits, automatically selecting appropriate tools to complete data pulling and parsing |
| `functionCall` | Set based on actual measurements | Adapts to structured extraction requirements for multiple types of documents, matching audit materials in different formats such as control plans and inspection reports |
| Plugin Trigger Rules | Bound to production batch events | Matches the update frequency per batch and shift, avoiding invalid calls |
| Retry Count | 2–3 times | Addresses occasional interruptions in testing equipment data transmission scenarios |
| Timeout Threshold | 600 seconds | Adapts to the pulling duration of batch data such as SPC reports and quality monthly reports |
| Historical Context Window | First 10 historical inspection records | Matches the trend analysis needs of process quality audits |

## Three common mistakes
- A `Your model may not support tool_call SyntaxError` error occurs. The cause is that the tool calling configuration does not match the syntax support of the current model, or the model's tool calling permission is not correctly enabled on the platform.
- API interface calls for published tool flows fail, returning prompts of insufficient permissions or non-existent resources. The cause is that the permission scope of the API access key is not correctly configured, or the workflow-associated plugins are not synchronized to the target environment.
- Plugins referenced in imported workflows show as empty or unloaded. The cause is that local associated configuration information of the plugins was not carried when exporting the workflow, or the corresponding plugin version is not deployed in the target environment.

## How to confirm proper configuration
- Based on FastGPT v4.17.0, trigger a tool call bound to a production batch, and check whether batch information and inspection data from the corresponding MES system can be correctly pulled.
- View tool calling logs to confirm that no `toolChoice`-related syntax errors occur, and that the returned results include core audit fields such as inspection items, defect levels, and judgment results.
- Manually trigger a parsing task for a nonconforming product review document, and check whether the plugin can correctly extract the review conclusion and release recommendation for the nonconforming product.
- Simulate a data pulling delay scenario, and verify whether the tool will trigger a retry or throw clear exception information within the set timeout threshold.
