# Supplier and Process Quality Audits for In-Process Quality and Finished Product Release: Source Citation and Traceability

## What This Category of Data Looks Like
This category of data comes from MES systems, online testing equipment, laboratory instruments, process parameter logs, customer quality standards, and historical defect databases. Daily generated documents include control plans, patrol inspection records, SPC reports, finished product inspection reports, nonconforming product review records, release orders, and quality monthly reports.
Data is updated by production batch and shift frequency. Some process parameters and defect data are collected continuously. Document fields include inspection items, measured values, judgment results, operators, batch numbers, inspection times, and some data have units such as mm, MPa, ppm. FastGPT v4.17.0 supports the multi-source data association requirements for this category.

## Constraints Imposed on Source Citation and Traceability
Data sources are scattered and follow different update rhythms. During traceability, matching inspection records and process parameters for the corresponding batch is required to avoid mixing data across batches.
Multiple types of documents have significant field differences. Unique identifiers such as batch numbers and inspection items must be clearly associated to complete citation links.
Continuously collected real-time data requires setting a reasonable retrieval range to avoid introducing outdated or irrelevant process data.
For large production batches, citations must cover the full chain from work-in-progress to finished product. This ensures that release audits can trace back to original records such as patrol inspection and SPC reports.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Citation Token Count (`quoteMaxToken`) | 800–1200 token | Matches the typical text length of a single inspection report or SPC report, avoids truncating critical judgment information |
| Return Source Data Toggle (`responseData`) | Enabled | Meets the requirement to directly retrieve original inspection records during release audits, ensuring traceability is available |
| Detail Display Toggle (`detail`) | Enabled | Displays fields and batch information from original documents, making it easier for quality personnel to verify inspection items and measured values |
| Single Retrieval Limit | Top 6 entries | Covers the number of inspection and patrol records corresponding to a single production batch, avoids interference from redundant data |
| Citation Matching Threshold | 0.75–0.85 | Distinguishes the similarity boundary between qualified and unqualified inspection records, reduces incorrect associations |
| Context Window | Calibrated based on actual measurements | Adapts to complex audit scenarios with multi-document associations, avoids context overflow |

## Three Common Misconfigurations
- Symptom: After configuring citation traceability, a red error prompt pops up when generating audit conclusions, and output cannot be completed. Cause: Unique identifier fields such as batch numbers and inspection items in documents are not correctly associated, causing retrieval to fail to match original records for the corresponding production batch.
- Symptom: During workflow testing, only the first question node displays knowledge base citation results, and subsequent nodes have no relevant retrieval content. Cause: The dataset ID is not correctly bound in global variables, or subsequent nodes do not enable the variable reference configuration item.
- Symptom: The audit conclusion output by the AI includes non-original document decorative content, and unmodified original inspection record text cannot be directly obtained. Cause: The return source data toggle corresponding to `responseData` is not enabled, or additional content organization rules are configured to overwrite the original data.

## How to Verify Correct Configuration
- Upload a single finished product inspection report and the patrol inspection record for the corresponding batch, trigger retrieval, and verify that the returned source data includes the correct batch number and inspection item information.
- Enable the `detail` toggle, view the details page of the retrieval results, and confirm that complete fields and upload time of the original document are displayed.
- Test a multi-node workflow, initiate audit requests for different batches in sequence, and verify that the citation results of each node match the documents for the corresponding batch.
- Check the `quoteMaxToken` configuration, confirm that the retrieved source data is not truncated, and can fully display key information for inspection judgments.

The values provided are common starting points and should be measured against the reader's own samples.
