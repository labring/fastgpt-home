# Supplier and Process Quality Audit for General Mechanical Equipment Assembly: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Core data for the general mechanical equipment assembly scenario originates from end-to-end business operations of manufacturers of pumps, valves, compressors, reducers, machine tools, and custom equipment. Daily documents include assembly process cards, BOMs, torque records, clearance adjustment records, commissioning reports, factory inspection sheets, and packing lists. Data sources cover PLM/ERP systems, part inspection data, assembly tool collection terminals, test benches, MES systems, and customer technical agreements. Data updates are tied to individual equipment or each order. Corresponding documents are updated once an assembly step or order delivery is completed.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
Data for this category is scattered across multiple systems and updated independently for each piece of equipment. Multi-turn dialogue must retrieve documents from different sources gradually. This avoids loading too much content at once and exceeding context limits. Documents contain specific fields with clear units, such as torque values, clearance parameters, and coaxiality requirements. Prompts must clearly guide the extraction and verification of these fields. The audit process for a single piece of equipment covers multiple assembly steps. Multi-turn dialogue must proceed step by step by process. This prevents cross-step information from interfering with current judgments. BOMs and assembly records for each order are unique. Dialogue context must be bound to the current order identifier. This ensures accurate information association.

## Configuration Settings
This configuration is based on FastGPT v4.17.0, and is adapted for the general mechanical equipment assembly audit scenario.

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `chatId` | Unique identifier bound to the equipment serial number or order number | Each piece of equipment corresponds to a unique audit process, ensuring audit records can be accurately traced |
| `messages` | Retain the most recent 10 conversation turns, automatically truncate the earliest turns when exceeded | Audit conversations for this category focus on the current assembly step, excessive historical content will interfere with current judgments |
| `variables` | Automatically synchronize the current order BOM number and assembly process number from the ERP system | Ensure dialogue context is associated with exclusive documents for the current batch, avoiding cross-order confusion |
| Single recall limit | Top 6 entries | Documents for this category are categorized by process, the top 6 entries cover reference content for the current audit step |
| Maximum context length | 8000–12000 characters | Total length of assembly documents for a single piece of equipment typically falls within this range, avoiding exceeding model token limits |
| Conversation record retention period | 180 days | The industry typically requires retaining assembly audit records for six months after equipment delivery to meet traceability requirements |

## Three Common Mistakes
- Phenomenon: When executing a long-text audit task, the interface shows the task completed normally but throws the `The value of "offset" is out of range` error. Cause: No reasonable chunking parameters are set for long documents of this category, such as complete assembly process cards. This causes the offset to exceed the actual length of the document during chunking.
- Phenomenon: Specified order BOM documents cannot be retrieved during dialogue. Cause: The `variables` configuration is not correctly set to bind the current order's BOM identifier. This causes the knowledge base search to fail to match the corresponding exclusive documents.
- Phenomenon: Cross-team users can view assembly documents for processes they are not responsible for after logging in. Cause: Knowledge base permissions are not configured by assembly process. This allows the permission scope to cover non-current process document libraries.

## How to Confirm Configuration is Correct
- Initiate an audit conversation for a single reducer assembly. Check if `chatId` is bound to the equipment's serial number. This ensures accurate traceability of conversation records.
- Enter the query "Verify the BOM completeness status for the current batch". Confirm that the returned documents include the BOM content for the current order. This verifies that the `messages` and `variables` configurations are effective.
- Attempt to test with documents exceeding the configured length. Observe if a context truncation prompt is triggered. This verifies that the maximum context length configuration is reasonable.
- Switch between different test accounts. Check that only assembly documents for the corresponding process are accessible. This verifies that the knowledge base permission configuration is correct.
