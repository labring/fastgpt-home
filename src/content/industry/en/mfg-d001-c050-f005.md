# Supplier and Process Quality Audit for General Mechanical Equipment Assembly: Tool Calling and Plugins

## What Data Looks Like for This Category
Data for this category typically comes from PLM/ERP systems, part inspection databases, assembly tool collection terminals, test benches, MES systems, and customer technical agreements. Data updates occur once per equipment or order. Associated documents include assembly process cards, BOM lists, torque records, clearance adjustment records, commissioning reports, factory inspection certificates, and packing lists. Data fields include material codes, assembly torque values (unit N·m), clearance parameters (unit mm), temperature rise data (unit ℃), and cover full links including component matching, assembly processes, and delivery.

## What Constraints Do These Characteristics Impose on the Tool Calling and Plugins Link
The high update frequency for multiple orders and multiple units requires tool calling to support precise triggering for a single order or single equipment each time, to avoid pulling redundant full-volume data. There are many document types with specialized fields, so tools must adapt to parsing logic for different documents. For example, extract material codes from BOMs, and verify compliance thresholds from torque records. Data sources are scattered, so plugins must connect to multiple system interfaces, and unify parameter formats to accommodate return structures from different systems. Core parameters from the assembly process must be extracted accurately. The context of tool calling must be limited to the assembly data range of the corresponding equipment, to avoid interference from cross-order data.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Fixed as `function` | Clarifies the trigger type for tool calling, adapting to scenarios with multiple document parsing and multiple system connections |
| Workflow Binding Rule | Bind the corresponding audit workflow ID by equipment BOM | Matches the exclusive assembly audit process for each equipment, avoiding confusion from cross-order data |
| Interface Timeout Threshold | 600 seconds | Covers time requirements for multi-system data pulling, complex BOM verification, and assembly parameter verification, calibrated based on actual testing |
| Text Parsing Strategy | Split parsing by document type | Adapts to structures of different documents including assembly process cards, torque records, and clearance adjustment records |
| Result Return Format | Retain original fields and units | Facilitates subsequent front-end display of specialized assembly parameters, aligning with reading habits of audit personnel |

## Three Common Errors
- Calling a specified workflow returns a non-existent process. The symptom is an error message stating the specified workflow ID does not exist in the interface response. The cause is failure to correctly obtain the workflow ID for the corresponding assembly audit process, or binding an incorrect process identifier.
- Front-end parsing of returned text streams produces only unstructured full paragraphs. The symptom is that displayed assembly parameters cannot distinguish between torque, clearance and other fields. The cause is failure to configure the return rule to retain original fields and units, and failure to split and parse content by document type.
- Parameter format errors occur during API debugging. The symptom is a parameter verification failure prompt returned by the interface. The cause is failure to pass required parameters in accordance with the FastGPT v4.17.0 interface specification, such as failure to correctly set the `toolChoice` parameter.

## How to Confirm Configuration Is Correct
- Call the bound workflow ID, check if the workflow returned by the interface matches the assembly audit process of the corresponding equipment, confirming that the workflow binding rule is effective.
- Call the tool interface, check if the returned result contains the original document's fields and unit information, confirming that the text parsing strategy is configured correctly.
- Simulate a call for assembly data of a single equipment, check if the interface response time meets the preset threshold, confirming that the timeout threshold setting is reasonable.
- Check if the `toolChoice` parameter is fixed as `function`, confirming that the tool calling trigger type configuration is correct.

All provided configuration values are common starting points, and should be evaluated against the reader's own samples.
