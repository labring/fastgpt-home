# Supplier and Process Quality Audit for Metal Cutting Machining: HTTP Interfaces and External Systems

## What the data for this category looks like
The main entities for this category are machining factories, precision parts factories, and machining workshops of equipment enterprises. Data sources include product drawings and 3D models, CAPP/CAM systems, machine tool collection terminals, tool management systems, MES systems, and measuring tool data terminals. Daily documents cover process routes, operation cards, tool lists, CNC programs, first-piece inspection records, patrol inspection forms, and measuring tool calibration records. Data updates are triggered with each work order, each workpiece, random sampling, and tool changes. Document fields include cutting speed, feed rate, dimensional error values, calibration cycles, and others, with units including revolutions per minute, millimeters per minute, micrometers, days, and more.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
Data sources for this category are scattered and have diverse formats. When connecting to external systems, multiple sets of interface authentication rules must be adapted, so a global verification logic for the `Authorization` parameter must be unified. Data update triggers are irregular, so interfaces must support on-demand pull requests to avoid invalid polling occupying resources. Documents include large-volume CNC program code, so interfaces must adapt to single-file size limit requirements. Field units include differentiated units such as micrometers and revolutions per minute, so unit identifiers must be carried in the request's `variables` to ensure accurate data parsing.

## How to set the configurations
These configurations apply to FastGPT v4.17.0, and meet the interface connection requirements for metal cutting machining scenarios:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {global shared secret}` | Unified authentication format when connecting to multiple external systems, avoiding repeated configuration of authentication rules for different systems |
| `responseData` | Structured data filtered by work order ID | Matches the work order-associated data requirements of metal cutting machining, reduces invalid data returns, and improves parsing efficiency |
| Number of data items per single request | `Top 10` | Adapts to batch pull scenarios for patrol inspection forms and first-piece inspection records, avoiding timeouts caused by excessive returned data in a single request |
| Interface timeout period | `300-600 seconds` | Covers the time requirements for large file uploads such as CNC programs and batch data pulls, calibrated based on actual measurements |
| Single file upload limit | `1000 MB` | Adapts to the upload requirements of large CNC programs and 3D models, matching the document volume characteristics of this category |
| `variables` | Carry work order ID and unit identifier | Ensures that pulled data is accurately bound to the current processing work order, while retaining field unit information to avoid parsing errors |

## Three common mistakes
- Phenomenon: No response is returned after calling a multimodal interface, and the conversation log shows a 400 error related to images. Cause: Interface image upload parameters were not configured correctly, and visual screenshots of processed workpieces or 3D model thumbnails were not submitted in the required format, triggering format verification failure.
- Phenomenon: Knowledge base upload of tool lists or CNC program files fails, returning a parameter error. Cause: Work order-associated parameters configured in `variables` were not carried in the request, causing files to fail to bind to the corresponding processing task, leading to interface verification failure.
- Phenomenon: Calling a machine tool collection interface returns empty data. Cause: The correct authentication format for the `Authorization` parameter was not configured for the connected machine tool collection system, returning an empty response after interface authentication failure, making it impossible to obtain patrol inspection data or process parameters.

## How to confirm the configuration is complete
- Initiate a single work order data pull request, check if the returned `responseData` includes the first-piece inspection records and tool list fields corresponding to the work order.
- Upload a single CNC program file of approximately 100 MB, confirm that the interface returns an upload success status, with no file size limit exceeded prompt.
- Call a multimodal interface to submit a visual image of a processed workpiece, check that the interface returns no 400-level errors, and the content matches the process information associated with the image.
- Check that the `variables` parameter carries the unique identifier of the current work order, ensuring that pulled data is accurately bound to the current processing task.

The values provided here are common starting points, and should be validated against the reader's own samples.
