# Supplier and Process Quality Audit for Metal Cutting Machining: Tool Calling and Plugins

## What Data for This Category Looks Like
Data for this category comes from product drawings and 3D models, CAPP/CAM systems, machine tool collection terminals, tool management systems, MES systems, and measuring tool inspection data. Daily documents include process routes, operation cards, tool lists, CNC programs, first-piece inspection records, patrol inspection forms, and measuring tool calibration records. Data updates trigger with each work order, each workpiece, sampling batch, or tool change. Data fields include tool life (unit: hours), process dimension tolerances (unit: millimeters), CNC program line numbers, measuring tool calibration validity periods (unit: days), and more. Data structures tie to machining processes and workpiece batches.

## What Constraints These Characteristics Impose on Tool Calling and Plugins
Data for this category comes from multiple dispersed systems, and update frequency changes dynamically with work orders and batches. Tool calling must match real-time process node triggers to avoid calling outdated tool wear or quality inspection data. Diverse document types require plugins to support parsing formats such as CNC program G-code, operation card PDFs, and measuring tool calibration records, adapting to extraction logic for different fields. Fields include parameters with units, so plugins must automatically complete unit verification and conversion to prevent unit mismatch issues during audits. Machining quality audits require associating multi-dimensional data, so tool calling must support cross-system data linkage to ensure process parameters used during supplier audits match actual production data.

## How to Configure Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `auto` | Machining supplier audits require calling multiple types of tools. Automatically selecting the tool suited for the current task improves calling efficiency. |
| `functionCall` | Force enabled | This scenario requires calling multi-source data plugins. Forced function calling ensures the stability and accuracy of tool execution. |
| Number of items returned per single tool call | Top 5 entries | Machining audits only require the latest critical data. Excessive data increases processing and audit burden. |
| Tool trigger timing | Trigger by work order node | Data for this category updates dynamically with work orders and tool changes. Matching trigger timing to process nodes ensures data timeliness. |
| Context window size | 8000 token | Machining audits require associating multiple documents such as CNC programs and operation cards. Sufficient context ensures complete parameter association. |
| Question optimization | Enabled | Machining audits involve multi-dimensional process parameters. Optimization improves the accuracy of tool calling. |

## Three Common Mistakes
- Phenomenon: When calling the PDF to Markdown tool, G-code comments in CNC programs cannot be extracted correctly. Cause: The tool is not configured with parsing rules adapted to machining documents, resulting in failed format extraction.
- Phenomenon: After configuring a global numeric variable counter, the variable does not increase by 1 as expected after calling the answer plugin. Cause: The variable update plugin is not bound to the trigger node after answer generation, causing the variable update logic to not execute correctly.
- Phenomenon: After enabling question optimization in the knowledge base orchestration workflow, the optimization logic still executes even if the question optimization switch for the final AI answer plugin is turned off. Cause: The question optimization plugin in the workflow executes earlier than the switch control node, causing the switch setting to not take effect.

## How to Confirm the Configuration Is Correct
- Trigger a tool call bound to a work order node, and check whether the returned data is the tool, quality inspection, and process data associated with the current work order.
- Check the trigger timing of the variable update plugin, confirm that it is bound to the execution node after answer generation.
- Simulate passing parameters that do not meet unit requirements, and check whether the plugin triggers a unit verification prompt.
- View the workflow run log, confirm that the `toolChoice` and `functionCall` configuration parameters are loaded correctly.

The values given are common starting points and should be measured against the reader's own samples.
