# Supplier and Process Quality Audits for Metal Cutting Machining: Document Parsing and Chunking

## What the data for this category looks like
Data sources for supplier and process quality audits in metal cutting machining include product drawings and 3D models, CAPP/CAM systems, machine tool collection data, tool management systems, MES systems, and measurement and inspection tool data. Daily documents cover process routes, operation cards, tool lists, CNC programs, first-piece inspection records, patrol inspection forms, and measuring tool calibration records.
Data updates are triggered by work orders, single-piece machining, spot checks, or tool changes. Exclusive fields include process number, tool life (unit: minutes per piece), dimensional tolerance (unit: mm), and CNC program line numbers, among others.

## What constraints these characteristics impose on the "document parsing and chunking" link
Multi-source heterogeneous data formats require chunking rules to adapt to multiple document types including text, CNC code, and tables. High-frequency data updates require moderate chunk lengths to avoid loading excessive redundant data during retrieval.
The association between exclusive fields and their units requires chunking to retain contextual connections, preventing loss of key parameters after splitting. The business characteristic of severe error consequences requires chunking to not omit core information affecting machining quality, such as tolerances and tool compensation.
Priority associations between main content and auxiliary data within chunks must be clarified to avoid interference of auxiliary data with core parameter matching during retrieval.

## How to configure the settings
Current configuration rules adapted for FastGPT v4.17.0 are as follows:

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the single-paragraph context length of operation cards and CNC programs, retains key information such as tolerances and tool parameters |
| `chunkSplitter` | By paragraph + fixed delimiters | Adapts to the typesetting logic of structured documents, avoids splitting single CNC program instructions |
| `customPdfParse` | Enabled | Accurately extracts table and field association information from PDF-format product drawings and process documents |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 seconds | Adapts to the full parsing duration of large CNC programs and multi-page process documents |
| `chunkSettingMode` | Manual mode | Customizes chunking rules to adapt to different document types for the special formats of metal cutting machining documents |

## Three common configuration mistakes
- Unformatted raw text displayed in context references: The `customPdfParse` configuration is not enabled, causing tables and process parameters in PDFs to fail correct parsing into structured content.
- Abnormal retrieval results after switching vector models: Vector embeddings are not regenerated for chunked documents, and existing chunked data is directly processed with a different vector model, leading to semantic matching failure.
- Loss of key tolerance parameters after chunking: The `chunkSize` is set too small, splitting dimensional tolerances with units into independent segments, breaking the contextual association between parameters and their values.

## How to confirm the configuration is correctly applied
- Upload a typical operation card PDF, check if the parsed text retains the contextual association of fields such as process number, dimensional tolerance, and tool model.
- Upload a segment of CNC program text, confirm that chunks do not split single G-code instructions or tool compensation parameters.
- View the running logs of the parsing task, confirm that timeout errors corresponding to `PARSE_FILE_TIMEOUT_SECONDS` are not triggered.
- Switch the test vector model, confirm that chunked documents can be normally loaded and participate in semantic retrieval.

The values provided are common starting points and should be measured against the reader's own samples.
