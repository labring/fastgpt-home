# Supplier and Process Quality Audit for Metal Cutting Machining: Model Integration and Configuration

## What the data for this category looks like
Data for metal cutting machining scenarios comes from product drawings and 3D models, CAPP/CAM systems, machine tool collection terminals, tool management systems, MES systems, and measurement and inspection tool data. Daily documents include process routes, operation cards, tool lists, CNC programs, first-piece inspection records, patrol inspection forms, and measuring tool calibration records. Fields cover operation numbers, tool numbers, CNC program segments, measured dimension values, calibration cycles, and more. Data update frequency is triggered by work order execution, sampling inspection links, and tool replacement actions, with no fixed cycle. Single data entry length varies widely, from short dimension values to hundreds of lines of CNC programs.

## What constraints do these characteristics impose on model integration and configuration
Multi-heterogeneous data sources require unified format parsing rules. The rules must adapt to different structured data, such as G-code syntax for CNC programs and numerical output formats of measurement and inspection tools. Frequently updated data sources require the context window to quickly load the latest operation, tool, and inspection data. This avoids audit deviations caused by expired context. High accuracy requirements for precision dimension values and process parameters limit the randomness of model output. The configuration must also support reference and parsing of long text fragments. The scenario relies on associated logic for tooling, tools, and datum conversion. This requires the model configuration to associate cross-field information from multiple documents.

## How to set the configuration
| Configuration Item | Recommended Value | Basis for This Setting |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Process documents and inspection records for metal cutting machining have long single entries. Sufficient window size avoids truncation of key content when carrying context information associated with multiple operations |
| `temperature` | 0.1–0.3 | Quality audit requires strict matching of process parameters and inspection results. Low temperature reduces output randomness and improves accuracy of numerical parsing and rule matching |
| `quoteMaxToken` | 2000–3000 characters | Long text fragments such as CNC program segments and measuring tool calibration records need to be referenced. Ensures referenced content fully covers details required for audit |
| Workflow/API tool selection | auto | The audit process needs to call the knowledge base to query operation requirements and tool parameters. Automatic tool calling improves process efficiency |
| `AIPROXY_API_ENDPOINT` | `http://192.168.xxx.xxx:8080 (local proxy address)` | Adapts to data collection nodes in the workshop intranet, reducing cross-network segment transmission delay and ensuring stable data flow |
| `AIPROXY_API_TOKEN` | Calibrated based on actual testing | Must match the identity verification rules of the proxy service to avoid call failures caused by unauthorized access |

## Three common misconfigurations
- Phenomenon: A null stream response is prompted when calling the model, and the interface returns a 401 or timeout status code. Cause: `AIPROXY_API_TOKEN` is not configured correctly, or `AIPROXY_API_ENDPOINT` points to an incorrect intranet node.
- Phenomenon: System logs show that the actually called model does not match the model configured for the application. Cause: The configuration items for the application's global model and the knowledge base's parameter-optimized model are not distinguished, resulting in different models being bound to the two.
- Phenomenon: CNC program or operation card content cannot be fully loaded during the audit process. Cause: The value of `maxContext` is too small to carry long-text process documents, resulting in context truncation.

## How to confirm the configuration is correct
- Log in to the FastGPT v4.17.0 management backend, enter the model configuration page of the corresponding application, and check that the values of `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` match the proxy service configuration.
- Submit a test request containing a CNC program fragment, and check whether the context length returned in the log conforms to the configured value of `maxContext` with no truncation.
- Initiate a quality audit test to confirm that the called model matches the model configured for the application, with no mixed use of models across configuration items.
- Trigger an audit request for the tool replacement scenario to verify that the model can correctly associate the associated data between the tool list and the operation card.

The values provided are common starting points and should be measured against the reader's own samples.
