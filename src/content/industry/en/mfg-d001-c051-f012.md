# Supplier and Process Quality Audit for Metal Cutting Machining: Deployment and Upgrade

## What this category of data looks like
Data sources for this category include product drawings and 3D models, CAPP/CAM systems, machine tool collection terminals, tool management systems, MES systems, and measuring tool data. Data updates are triggered by work order execution, workpiece completion, sampling inspection, or tool replacement. Daily documents include process routes, operation cards, tool lists, CNC programs, first-piece inspection records, patrol inspection forms, and measuring tool calibration records. Fields include tool life (unit: hours), process dimension tolerances (unit: mm), CNC program version numbers, and others.

## What constraints this category's characteristics impose on the deployment and upgrade phase
The multi-source, heterogeneous nature of data in this category requires adapting parsing rules for specialized documents such as process routes and CNC programs during deployment, and reserving mapping capabilities for specialized fields such as tool life and dimension tolerances. The high-frequency update characteristic requires configuring data synchronization triggered by work orders or tool replacements, to avoid delays that disrupt audit processes. The need for cross-document association requires configuring cross-document associated retrieval capabilities during deployment, linking operation cards and first-piece inspection records to meet the requirements of linked process and inspection data for supplier audits. For intranet deployment scenarios, access restrictions of local systems such as machine tool collection and MES must be accommodated, while meeting local storage requirements for production data.

## Configuration Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30 connections` | This category of data is updated frequently with work orders, so a sufficient database connection pool is required to support concurrent queries |
| `REDIS_URL` | `Local intranet Redis service address` | Used to cache frequently accessed tool lists and process route data, to meet low-latency requirements for production scenarios |
| `STORAGE_S3_ENDPOINT` | `Enterprise intranet object storage address` | Used to store large-volume production documents such as CNC programs and first-piece inspection records, to comply with local deployment requirements |
| `FE_DOMAIN` | `Enterprise intranet domain name or local IP:8080` | Used to configure the frontend access address, to adapt to intranet deployment scenarios |
| `ROOT_KEY` | `Randomly generated 32-character string` | Used for system administrator permission verification, to ensure access security in production environments |

## Three Common Configuration Errors
- Phenomenon: The frontend page fails to load after deployment. The browser console displays 404 errors or resource loading failures. Cause: `FE_DOMAIN` is not correctly configured as the local deployment access address, leading to incorrect frontend resource paths.
- Phenomenon: The system logs prompt database connection failure after startup, and the audit configuration interface cannot be loaded. Cause: The address and port of the intranet MySQL service are not correctly filled in, or database permissions are not granted to the deployment node.
- Phenomenon: Audit interface calls time out, and logs show retrieval time exceeding 30 seconds. Cause: A reasonable connection number for `DB_MAX_LINK` is not configured, causing the database connection pool to be exhausted and unable to respond to concurrent queries from multiple work orders promptly.

## How to Confirm Proper Configuration
- Access the configured `FE_DOMAIN` address, and confirm that the frontend page loads normally with no resource loading failure prompts.
- Run a database connection test, and confirm that the connection number configured by `DB_MAX_LINK` supports at least 10 concurrent queries.
- Upload CNC programs and first-piece inspection records, and confirm that the documents are stored normally to the storage service corresponding to the configured `STORAGE_S3_ENDPOINT`.
- Log in to the system backend using `ROOT_KEY`, and confirm that administrator permission verification works correctly.

The values provided are common starting points and should be measured against the reader's own samples.
