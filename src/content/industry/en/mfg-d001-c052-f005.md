# Supplier and Process Quality Audit for Steel Rolling and Finishing: Tool Calling and Plugins

## What Data for This Category Looks Like
Data for this category comes from slab or billet batches, heating furnaces, mill automation control systems, online thickness and width measuring equipment, surface inspection devices, and manufacturing execution systems (MES). Daily documents include rolling plans, heating schedules, rolling specifications, shape and thickness records, surface quality reports, and quality certificates. Fields include coil number, furnace number, rolling thickness (unit: millimeters), flatness, surface defect level, and more. The data updates in real time for each coil or billet, and supports full-link traceability at the coil level. Unlike the steelmaking category which focuses on chemical composition control, this category focuses on control of geometric and microstructure parameters following continuous plastic deformation.

## Constraints Imposed on Tool Calling and Plugins by These Characteristics
The real-time coil-level data and strict field requirements for this category require tool calling to match the data source of the corresponding batch to avoid mixing data across coils. The high-frequency real-time updated inspection data requires tool calling to have low-latency response capabilities, and the timeout setting must adapt to the actual feedback rhythm of the equipment. The association between multiple types of documents and process parameters requires plugins to load corresponding tools classified by rolling process to reduce invalid calls. The requirement for coil-level traceability requires tool calling to carry the coil number as a required parameter to ensure that audit results are bound to the corresponding steel coil. The serious consequences of errors require tool calling to be configured with retry and alert mechanisms to avoid steel coil downgrading or equipment damage caused by a single failed call.

## Configuration Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically match the tool corresponding to the current rolling task, adapting to multi-process audit requirements |
| Tool call timeout | 300-600 seconds | Adapt to the real-time response delay of online inspection equipment, avoiding interrupting the audit process due to timeout |
| Tool call retry count | 2 times | Balance call success rate and system load to cope with temporary network fluctuations |
| Batch tool call limit | 5 tools per coil | Match the typical number of audit links for single-coil rolling, avoiding excessive tool calls from occupying resources |
| `functionCall` | Enforce parameter format verification | Ensure that incoming fields such as coil number and thickness comply with business specifications, reducing invalid execution |
| Stream response segment interval | 1000 milliseconds | Adapt to the push rhythm of real-time inspection data, avoiding data overload |

## Three Common Mistakes
- Phenomenon: Tool calling returns a permission error when temporarily activated. Cause: The temporarily activated tool is not bound to the access permissions corresponding to the rolling specification, and cannot read heating schedule and rolling specification documents.
- Phenomenon: Tool calling returns a 408 timeout status code. Cause: The timeout setting is too short, failing to adapt to the real-time response delay of online inspection equipment.
- Phenomenon: Tool execution fails due to missing `functionCall` parameter verification. Cause: The incoming rolling thickness parameter is of a non-numeric type, which does not meet the field format requirements of the mill automation control system.

## How to Confirm the Configuration Is Correct
- Initiate a tool call for a specified coil number, and check whether the returned result includes the shape and thickness records and surface defect level fields corresponding to that coil.
- View the tool call log to confirm that the `toolChoice` parameter automatically selects the tool matching the current rolling process.
- Simulate a network delay scenario to verify that the tool call will perform retry operations according to the configured retry count.
- Enable the stream response switch, and check whether the real-time inspection data returned by the tool is pushed to the audit interface in segments.

The values provided are common starting points and should be measured against the reader's own samples.
