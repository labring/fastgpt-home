# Supplier and Process Quality Audit for Sheet Metal Cutting and Bending: HTTP Interfaces and External Systems

## What the data for this category looks like
Data for this category primarily comes from CAD/CAM software, order BOMs, sheet metal inventory systems, laser cutters, bending machines, and production MES systems. Documents produced daily include unfolded drawings, CNC cutting programs, bending process cards, nesting diagrams, first-piece records, and process flow cards. Data updates are triggered by order creation, daily inventory checks, or each production changeover. Operations run in a multi-variety, small-batch mode, with core reliance on drawing-driven bending coefficient compensation and nesting planning.

## What constraints do these characteristics impose on the "HTTP Interfaces and External Systems" link
The multi-source, heterogeneous data sources of this category require HTTP interfaces to support files and parameters in different formats. These include vector drawings exported from CAD and production work orders synchronized from MES. The multi-variety, small-batch operating mode results in dynamically fluctuating call frequencies. Interfaces must adapt to sudden order-level interface requests. Data updates triggered by each changeover require interfaces to support low-latency real-time synchronization. The core bending coefficient compensation and nesting logic require interface-transmitted fields to include key parameters such as sheet thickness, bending radius, and unfolding allowance. This avoids subsequent assembly errors or sheet waste caused by missing data.

## How to set up the configuration
This configuration applies to FastGPT v4.17.0. Below are HTTP interface configuration recommendations for the sheet metal cutting and bending scenario:

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `Authorization` | `Bearer {API_KEY}, automatically refreshed after 1 hour of validity` | Industrial interfaces typically use Bearer token authentication to avoid transmitting sensitive production data keys in plain text |
| `variables` | Fixed key-value pairs containing sheet material, thickness, bending radius, and nesting priority | Process parameters for sheet metal cutting and bending are dynamically adjusted per work order. Passing parameters via variables simplifies interface configuration logic |
| `responseData` | Return only verified first-piece records and core process parameters. Filter redundant device logs | Audit scenarios only require key quality data. This reduces interface transmission load and parsing time |
| Timeout Duration | `30–60 seconds` | Parsing sheet metal process data requires a certain amount of processing time. An overly long timeout will block the audit process. An overly short timeout will cause normal requests to fail |
| Retry Count | `2–3 times` | Network fluctuations are common in industrial production scenarios. A small number of retries can reduce audit interruptions caused by temporary faults |

## Three Common Mistakes
- Phenomenon: Garbled characters are returned when calling the interface to upload sheet metal-related CSV files. Fields may also be empty after parsing. Cause: The `Content-Type` is not specified as `text/csv; charset=utf-8` in the request header. This causes a mismatch between the encoding of CSV files exported by industrial systems and the default encoding of the interface.
- Phenomenon: The interface call returns a 401 status code. Bending process data cannot be synchronized. Cause: The `Authorization` parameter does not carry a valid token, or the token expires without automatic refresh as configured.
- Phenomenon: Correct bending verification results cannot be generated after the audit process is triggered. Cause: Core process parameters such as bending coefficient and unfolding allowance are not configured in `variables`. This causes the interface to fail to pass necessary verification basis to the LLM.

## How to Confirm the Configuration is Complete
- Send a request carrying test sheet metal work order parameters. Check whether the fields returned in `responseData` include the core process information required by the order.
- Simulate temporary network fluctuations. Verify whether the interface retry mechanism triggers as configured, with no abnormal errors.
- View the interface authentication log. Confirm that the validity period and refresh logic of the `Authorization` token meet expectations.
- Upload a test unfolded drawing file. Check whether the interface correctly parses the drawing format and returns structured data available for audit.

The values provided are common starting points, and should be evaluated against sample data from the relevant deployment.
