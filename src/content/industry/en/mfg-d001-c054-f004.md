# Supplier and Process Quality Audit for Sheet Metal Cutting and Bending: Workflow Orchestration

## What the data for this category looks like
The core data for this category comes from CAD/CAM software, order BOMs, sheet metal inventory systems, laser cutters, bending machines, and workshop MES systems. Daily circulating documents include 3D part unfolding drawings, CNC cutting programs, bending process cards, nesting diagrams, first-piece inspection records, and process transfer cards. Data updates are triggered with production orders. Sheet metal inventory and equipment operation data are synced daily. Bending compensation parameters and nesting plans are updated each time molds are changed. Document fields include sheet metal grade, thickness, bending radius, unfolded dimensions, and process number. Units are mostly millimeters, kilograms, and square meters.

## What constraints these characteristics impose on the "workflow orchestration" link
Multi-source heterogeneous data comes from different business systems. Workflows must support cross-node calls to `variables` to store shared core information such as sheet metal parameters and order numbers, to avoid repeated data pulls. Daily circulating documents have diverse formats. Standardized parsing of unfolding drawings and process cards must be completed in preceding nodes to adapt to extraction rules for different fields. Data updates change with orders and mold changes. Workflows must support on-demand triggering to avoid redundant calculations from fixed cycles. Validation for multi-process transfers must match the bending parameters of the current process. Independent validation nodes must be configured for each process to ensure that bending sequences and compensation parameters match actual production.

## How to set the configurations
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Global variable configuration | Bind sheet metal grade and bending coefficient per order | Matches the feature that this category updates data per order and mold change, enabling cross-node parameter sharing |
| `variables` | Store qualified judgment results from first-piece inspection records | Enables reuse of validation results across process nodes, avoiding repeated calculations |
| `nodeId` | Bind unique identifiers for each bending process validation node | Differentiates validation logic for different processes, ensuring parameters match the current production stage |
| Question optimization configuration | Enable historical context association | Resolves reference resolution issues for process parameters, optimizing query intent for knowledge base searches |
| Single search limit | Top 6 entries | Process parameters and drawing entries for sheet metal cutting and bending are relatively few, avoiding redundant recall |
| Timeout threshold | 300-600 seconds | Parsing large unfolding drawings and nesting diagrams requires long processing time, calibrated based on actual measurements |

## Three common mistakes
- Phenomenon: After a workflow runs, results from intermediate bending parameter validation nodes are appended to the final audit output. Cause: Output hiding rules for intermediate nodes were not configured, and all node execution content is retained by default.
- Phenomenon: Process parameters returned by the knowledge base search node have unclear references, and cannot match the current production process. Cause: The historical context association configuration was not enabled, and recall is based only on the current single query.
- Phenomenon: `variables` parameters called across process nodes are empty, causing bending compensation validation to fail. Cause: The data source for global variables was not correctly bound in the process start node, and corresponding sheet metal parameters were not pulled from the order BOM or MES system.

## How to confirm the configuration is complete
- Trigger a workflow execution for a simulated production order, check that the final output only includes audit conclusions and final process results, with no redundant content from intermediate nodes.
- Submit a query containing historical process parameters, verify that knowledge base search results match the bending compensation requirements of the current process, and confirm that reference resolution is working.
- View the log records for `variables` parameters, confirm that shared cross-node parameters such as sheet metal grade and bending coefficient have been correctly loaded.
- Check the `nodeId` identifiers for each process validation node, confirm that validation logic for different processes has not been mixed up.

The values provided are common starting points and should be measured against the reader's own samples.
