# Supplier and Process Quality Audit for Sheet Metal Cutting and Bending: Tool Calling and Plugins

## What Data for This Category Looks Like
Data for this category typically comes from CAD/CAM software, order BOM systems, sheet metal inventory ledgers, laser cutter and bending machine device logs, and workshop MES systems. Daily generated documents include 3D part unfolding drawings, CNC cutting programs, bending process cards, nesting diagrams, first-piece inspection records, and work order transfer cards.
Data updates trigger on order placement, daily production inventory checks, and each equipment changeover adjustment. Most fields include part unfolding dimensions, bending compensation values, sheet metal specifications, work order transfer numbers, and equipment processing parameters. Common units are millimeters, square meters, and kilograms.

## Constraints on Tool Calling and Plugin Configuration
The multi-document type, high-frequency updates, and specialized field traits of this category create multiple constraints for tool calling and plugin configuration.
First, daily documents include structured and semi-structured files such as CAD unfolding drawings and CNC programs. Tool calling must adapt to multi-format parsing logic to accurately extract specialized fields like bending compensation values and unfolding dimensions.
Second, the multi-variety, small-batch production model requires tool calling to quickly adapt to drawing parameters for different orders, avoiding adaptation deviations from generic configurations.
Third, data updates in real time alongside orders and equipment changes. Tool calling must support real-time pulling of the latest sheet metal inventory and work order transfer data. This ensures parameters used in the audit link always match current production status.
Fourth, the accuracy of specialized processing parameters directly affects product quality. Field mapping for tool calling must strictly align with standard formats exported by CAD/CAM software. Misalignment will cause issues such as hole position misalignment and sheet metal waste.

## Three Common Mistakes
- Phenomenon: The unfolding drawing parameter fields returned by the pre-configured PDF parsing component are empty, and tool calling cannot extract bending compensation values. Cause: The field mapping of tool calling is not aligned with the fields in PDF documents exported by CAD, and exclusive parsing rules are not configured for specialized fields of the sheet metal category.
- Phenomenon: Execution logs and intermediate results of tool calls are directly displayed in the audit interface, even after adding a tool call end node, the setting does not take effect. Cause: Trigger conditions for tool result hiding are not correctly configured. Only adding the end node does not override the output rendering logic of tool calls.
- Phenomenon: After sending a termination instruction to the MCP server-side tool, the process continues to run and is not terminated normally. Cause: Corresponding abnormal status codes or preset termination instruction trigger rules are not bound, and the communication protocol format of MCP tools is not adapted.

## How to Confirm the Configuration Is Correct
- Upload a sheet metal unfolding drawing PDF document, trigger the tool calling process, and verify that extracted unfolding dimensions and bending compensation values match the parameters in the document.
- After triggering tool calling, check that the interface only displays the final audit conclusion, and does not show intermediate logs and results of tool execution.
- Simulate a tool execution timeout scenario, confirm that the preset termination instruction can be triggered normally, and terminate the abnormal process on the MCP server side.
- Switch between different large language models, confirm that the field extraction logic of tool calling is not affected by model version, and stably returns target parameters.
