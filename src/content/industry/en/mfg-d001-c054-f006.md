# Supplier and Process Quality Audit for Sheet Metal Cutting and Bending: Citation Source and Traceability

## What Data for This Category Looks Like
This category of data typically comes from CAD/CAM software, order BOMs, sheet metal inventory systems, laser cutter and bender equipment logs, and MES production management systems. Daily produced documents include part unfolding drawings, CNC cutting programs, bending process cards, nesting diagrams, first-piece inspection records, and process transfer cards.
The data update cadence follows these rules: Exclusive documents are generated for each individual order. Sheet metal inventory and equipment operation data are synced daily. Bending compensation parameters and nesting plans are updated each time production switches models.
Document fields include bending compensation coefficients, hole position coordinates, sheet metal thickness, cutting dimensions, process numbers, and more. Common units are millimeters, square meters, and pieces.

## Constraints on Citation and Traceability
Sheet metal cutting and bending uses a multi-variety, small-batch production model and is drawing-driven. This requires citation traceability to accurately match exclusive documents such as unfolding drawings and process cards for single orders.
Data updates happen frequently, and model changes are common. Traceability must prioritize retrieving the latest same-day model change parameters and exclusive files for the current order. This avoids calling outdated legacy process data.
There are many document types with clearly subdivided fields. Retrieval scope must be divided by document type and order to prevent accidental citation of unrelated documents across different orders.
Additionally, traceability for core fields such as bending compensation coefficients and hole position coordinates must be linked to equipment logs and first-piece records. This ensures cited content matches parameters from actual production steps.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average length of single content blocks for sheet metal cutting and bending documents, to avoid truncating core audit parameters such as bending compensation coefficients and hole position coordinates |
| `responseData` | Return file names, process numbers, order numbers | Meets traceability requirements for supplier and process quality audits, and accurately links documents to specific production links |
| `detail` | Enabled | Displays subdivided fields of cited content, making it easier for auditors to verify key information such as bending sequence and sheet metal specifications |
| Single search limit | Top 5 results | Adapts to the distribution of order documents for multi-variety, small-batch production, reducing interference from unrelated documents |
| Maximum context | Calibrated based on actual testing | Adapts to document sets of different order scales, preventing retrieval deviations caused by context overflow |
| Reranking | Enabled | Reorders results based on the relevance of cited content to audit questions, prioritizing results related to bending processes and cutting dimensions |

## Three Common Configuration Errors
- Issue: The number of returned cited documents is higher than expected, with more than 10 entries shown in the interface. Cause: The single search limit is not configured, and the retrieval scope covers all historical order documents. This returns too many unrelated legacy process files.
- Issue: API call results do not include cited file name fields. Cause: The `responseData` parameter is not configured correctly, and traceability-required fields such as file names and process numbers are not specified for return.
- Issue: Cited content contains incorrect hole positions or bending compensation values, but these issues are not flagged as unreasonable. Cause: The `detail` configuration is not enabled to display subdivided fields. First-piece records and equipment log data are not linked, making it impossible to verify the actual production matching degree of cited content.

## How to Verify Proper Configuration
- Submit a retrieval request for bending compensation coefficients. Check if the number of cited documents in the returned results matches the preset range.
- Call the API interface. Verify that the `responseData` field includes information such as file names and process numbers.
- After enabling the `detail` configuration, confirm that the returned cited content displays subdivided audit fields such as bending compensation coefficients and hole position coordinates.
- Submit a retrieval request after simulating a production model change. Confirm that the retrieval results prioritize displaying the latest model change process cards and nesting diagram documents.

The values provided here are common starting points, and should be evaluated against the user's own samples.
