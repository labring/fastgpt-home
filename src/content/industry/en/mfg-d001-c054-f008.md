# Supplier and Process Quality Audit for Sheet Metal Cutting and Bending: Document Parsing and Chunking

## What the data for this category looks like
This category serves manufacturers of cabinet chassis, ventilation equipment, electrical enclosures, and custom non-standard equipment. Daily generated documents include expansion drawings, CNC cutting programs, bending process cards, nesting diagrams, first-piece records, and process flow cards. Data mainly comes from CAD/CAM tools, order BOMs, sheet material inventory systems, laser cutters and bending machine equipment, and MES systems. Update frequency adjusts based on orders, daily operations, or each production line changeover. Most documents contain fields such as dimension parameters, process parameters, and equipment codes. Some documents embed CAD drawing objects or structured tables.

## What constraints these characteristics impose on the "document parsing and chunking" link
The multi-variety, small-batch business model leads to inconsistent document formats, requiring adaptation to multiple document structures including embedded CAD objects and structured tables. The drawing-driven business logic requires accurate extraction of key fields such as bending coefficients, expansion dimensions, and tolerance values after parsing, to avoid omissions that would affect quality audits. Frequently updated documents require the parsing process to have fast response speeds. Timeout settings must match the business rhythm. At the same time, the chunking logic must balance retrieval accuracy and content integrity, to prevent key process parameters from failing to be accurately recalled due to improper chunking, which could lead to subsequent assembly errors or sheet material waste.

## How to set the configurations
This guidance is based on FastGPT v4.17.0.
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Sheet metal cutting and bending documents contain compact process parameters and dimension information. This range ensures that a single chunk contains complete process parameters or a single table segment, balancing retrieval accuracy and contextual integrity |
| `chunkSplitter` | Split by tables and paragraphs | Nesting diagrams and bending process cards often contain structured tables. Splitting by tables and paragraphs avoids damaging table structures, ensuring that key information such as nesting layouts and bending sequences can be fully obtained during audits |
| `customPdfParse` | Enabled | Documents in this category often embed CAD drawing objects or complex vector graphics. Enabling custom parsing optimizes extraction of such content, solving the problem that standard parsing cannot recognize embedded drawings |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Parsing large-size expansion drawings or nesting diagrams takes a long time. 600 seconds covers the parsing cycle of most documents, avoiding document parsing failure due to timeout |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Some CAD program files exported from production lines have large sizes. This upper limit meets the upload requirements of conventional large documents |

## Three Common Misconfigurations
- Phenomenon: Some DOCX documents fail to display after upload, with parsing error logs returned. Cause: The `customPdfParse` configuration is not enabled. Sheet metal cutting expansion drawings often embed CAD drawing objects, and standard parsing logic cannot recognize such embedded content, leading to parsing failure.
- Phenomenon: Tables in some nesting diagrams or process cards in the knowledge base cannot be chunked correctly, with content truncated or merged across chunks. Cause: `chunkSplitter` is not set to split by tables and paragraphs. The default chunking logic will damage table structures, causing key information such as nesting dimensions and bending sequences to be scattered across multiple chunks.
- Phenomenon: A GPU out-of-memory error is reported when starting a parsing task after Docker deployment, and GPU information cannot be detected. Cause: The host machine's CUDA driver directory is not mounted correctly, and `PARSE_FILE_TIMEOUT_SECONDS` is set too long. This causes excessive memory usage when parsing PDFs exported from large-size CAD files, triggering an out-of-memory error.

## How to confirm that configurations are correctly set
- Upload a DOCX format expansion drawing containing embedded CAD drawings, check whether the parsed text contains key fields such as bending coefficients and expansion dimensions, and confirm that the parsing status shows success.
- Upload a nesting diagram PDF, view the knowledge base chunk list, and confirm that table content is not split, with a single chunk containing complete table rows and parameters.
- Check system operation logs, confirm that no timeout errors occur when uploading large-size documents within 1000 MB, and that the `PARSE_FILE_TIMEOUT_SECONDS` configuration value matches parsing time.
- Verify that after `customPdfParse` is enabled, documents with embedded complex vector graphics can normally generate parsed text content without missing fields.

Note: The configuration values listed above are common starting points. They should be measured against the reader's own samples.
