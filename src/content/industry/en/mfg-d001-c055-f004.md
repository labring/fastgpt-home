# Supplier and Process Quality Audit for Foundry (Sand Casting, Precision Casting, Die Casting): Workflow Orchestration

## What This Category of Data Looks Like
Daily documents for foundry applications include casting process cards, batching lists, heat records, mold history records, first article inspection records, material test reports, and nonconforming product review forms. Data sources cover ERP material master data, melting furnaces and thermometers, spectrometers, MES heat records, mold management systems, customer drawings, and technical specifications. Data updates occur per heat, per batch, or daily. Fields include alloy batching parameters, melting temperature, pouring time, heat number, mold cycle number, defect types, and more. The dataset includes a mix of structured and unstructured data.

## What Constraints These Characteristics Impose on Workflow Orchestration
Multi-source heterogeneous data sources require workflow nodes to support input adaptation for different formats. High-frequency update cycles require workflow trigger logic to match production tempo to avoid delays. Mixed document types require workflows to include branch nodes for structured data parsing and unstructured text processing. Defect traceability business requirements require establishing association bindings between heat numbers, mold cycle numbers, and quality data across nodes. High-risk error consequences require configuring failure alerts and pause mechanisms to enable timely intervention.

## Configuration Guidelines
This document applies to FastGPT v4.17.0 workflow orchestration features. The following are configuration recommendations for foundry applications:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Concurrent execution switch | Enable per production batch, set single-batch concurrency to `3–5 items` | Matches the production tempo of each heat or batch of castings, avoids overloading the system by processing too many tasks simultaneously |
| `variables` initialization | Pre-set heat number, mold cycle number, and alloy grade variables | Adapts to field mapping requirements for multi-source data, unifies basic workflow parameters |
| File upload node configuration | Set supported formats to `.txt`, `.pdf`, `.xlsx`, single upload limit to `1000 MB` | Covers common formats and sizes of foundry process cards, heat records, and nonconforming product review forms |
| Timeout threshold | Set to `600 seconds` | Matches typical processing durations for melting and spectral testing, prevents workflow interruptions caused by device response delays |
| `nodeId` association configuration | Bind corresponding defect detection nodes using the unique identifier of heat records | Enables precise traceability of defects to heat numbers and mold cycle numbers, meets traceability requirements for quality audits |
| Failure handling node | Trigger alerts and pause the current workflow instance | Matches high-risk scenarios where castings are scrapped due to nonconforming products, enables timely intervention |

## Three Common Misconfigurations
- After enabling concurrent execution for batch run nodes, only some heat tasks complete, while remaining tasks remain in waiting state. Cause: Did not adjust concurrent execution node parameters based on the number of heats per batch.
- Workflow model icons fail to display normally, and a network error prompt pops up during file upload. Cause: Did not configure an upload whitelist adapted to foundry multi-source document formats, or network bandwidth is insufficient to support transfer of large-volume heat record files.
- Workflow runtime returns an offset 17 error message. Cause: The heat number field bound by `nodeId` has format abnormalities, containing unescaped special characters that cause data transfer failures between nodes.

## How to Verify Proper Configuration
- Manually trigger a single-heat workflow instance, verify that preset heat number and alloy grade parameters in `variables` load correctly.
- Upload a standard foundry process card PDF file, confirm that the file can be parsed normally and proceeds to subsequent text processing nodes.
- Enable batch concurrency mode, submit 3 simulated heat tasks, confirm that all tasks start execution simultaneously.
- Simulate a node run failure, confirm that the failure handling node triggers alerts and pauses the current workflow instance.

The values provided are common starting points and should be measured against the reader's own samples.
