# Supplier and Process Quality Audit for Forging and Die Forging: HTTP Interfaces and External Systems

## What Data Looks Like for the Forging and Die Forging Category
Daily documents for the forging and die forging category include forging process specifications, cutting material cards, furnace heating records, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports.
Data sources include raw material quality certificates, furnace heating systems, press collection data, MES, non-destructive testing instruments, and customer forging drawings.
Data update frequency is per piece, per batch, or per furnace run.
Core fields include forging batch number, heating temperature range, forging ratio, mold number, and ultrasonic testing defect level.
Units include degrees Celsius, tons, millimeters, and other standard units.

## Constraints Imposed on HTTP Interfaces and External Systems by These Features
Data sources for the forging and die forging category are dispersed. They include multiple external systems such as furnace heating systems, press collection systems, non-destructive testing instruments, and MES.
Update cycles vary based on furnace runs or production batches.
This requires HTTP interfaces to support batch-triggered calls. It prevents invalid polling that consumes system resources.
Core audit fields must strictly match forging batch numbers, heating temperature ranges, and ultrasonic testing defect levels from external systems. Interfaces must accommodate format differences across multiple data sources.
Forging errors can lead to scrap or in-service fracture. Interface return data must include all necessary audit fields. It must also have basic verification mechanisms to ensure data accuracy.
Requirements to link daily documents to production batches mean interfaces can pull fields from multiple associated documents. This adapts to the full workflow needs of supplier and process quality audits.

## How to Configure Settings
This page’s configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Identity Verification Configuration | Use a Bearer token carried in the `Authorization` header, with a validity period of 7200 seconds | Matches the identity verification requirements of supplier audit systems, prevents unauthorized call failures |
| Variable Binding Configuration | Configure `variables` to bind forging batch numbers, heating temperature ranges, and ultrasonic defect levels | Corresponds to core audit fields for the forging category, ensures interface data matches audit workflows |
| Response Data Filtering | Only extract batch status, defect detection results, and material furnace batch numbers from `responseData` | Reduces invalid data transmission, improves data processing efficiency for audit workflows |
| Interface Timeout Configuration | Set to 600 seconds | Adapts to the batch data return rhythm of forging production, prevents data loss caused by timeouts |
| Trigger Frequency Control | Call once per furnace run | Matches the update frequency of forging production, avoids redundant calls that consume system resources |

## Three Common Configuration Errors
- Phenomenon: Interface calls return a 404 Invalid URL error, or logging in with the default root account prompts a password error. Cause: The full request path of the interface is not configured correctly, or the token generation rule for the `Authorization` header does not match the supplier audit system.
- Phenomenon: Interface return data has missing fields. It cannot complete the matching check between forging batches and material furnace batches. Cause: Not all core audit fields are bound in `variables`. This causes the interface to not return required forging batch numbers or raw material quality certificate information.
- Phenomenon: Interface calls time out and return a 504 error. Cause: A reasonable interface timeout period is not set, or multiple redundant data source interfaces are called simultaneously. This exceeds the system load limit.

## How to Confirm Configuration is Complete
- Call the configured interface, and check if returned data fields match preset audit parameters.
- Initiate a call using a test forging batch number. Confirm the interface return result matches production records from external systems.
- Check the identity verification configuration. Confirm the `Authorization` header token format meets the identity verification requirements of external systems.
- Simulate consecutive furnace run calls. Confirm the interface trigger frequency matches the set production rhythm.
