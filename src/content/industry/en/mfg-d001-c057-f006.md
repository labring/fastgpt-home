# Supplier and Process Quality Audit for Forging and Die Forging: Citation Sources and Traceability

## What Data for This Category Looks Like
Typical entities include forging plants, aerospace and automotive forging suppliers, and forging shops. Daily generated documents include forging process specifications, cutting lists, furnace logs, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports. Data sources cover raw material quality certificates, furnace systems, press collection data, MES systems, non-destructive testing equipment, and customer forging drawings. Update frequency is per forging part, per batch, or per furnace run. Core fields include heat number, forging ratio, mold life, testing defect type, and others. Some data is automatically collected from industrial systems, while some comes from manually filled paper or electronic forms.

## Constraints for Citation Sources and Traceability
Data sources for forging and die forging are scattered across industrial systems and manual documents, and updated per furnace run or batch. Traceability requires precise matching of unique identifiers such as heat numbers and forging batches to avoid cross-batch confusion. Core documents contain key quality information like process parameters and test results. Citations must accurately link all source data for the corresponding batch, and cannot rely solely on vague keyword matching. Data updates occur frequently with small per-update volumes, so traceability workflows must support real-time linking of latest furnace run data, and handle multi-source data integration. Incorrect traceability can allow non-conforming forgings to enter the market, leading to batch isolation or even safety incidents. Accuracy and completeness of traceability are core requirements.

## Configuration Settings
| Configuration Item | Recommended Value | Basis for This Setting |
| --- | --- | --- |
| `detail` | `true` | Forging scenarios require complete source traceability information, including matched document fields and batch information. Enable this parameter to obtain detailed data, which adapts to the standard configuration of FastGPT v4.17.0. |
| `responseData` | Includes knowledge base ID, source document path, matched fields | Forging data needs to link unique identifiers such as heat numbers and forging drawing numbers. This configuration returns the unique identifiers and specific source paths required for traceability. |
| `quoteMaxToken` | `1500–2000 token` | Forging-related documents contain long content such as process parameters and test reports. This value range accommodates complete citation information and avoids truncation of key quality data. |
| Single recall limit | Top 8 entries | The number of documents associated with a forging batch is limited. Excessive recall adds redundancy and reduces traceability efficiency. This value adapts to scenario requirements. |
| Citation source merging rule | Merge by heat number and forging batch | Forging data is updated per furnace run or batch. Merging citations from the same batch simplifies the traceability process for auditors and avoids interference from redundant information.

## Three Common Mistakes
- Phenomenon: The citation information returned when calling the chat interface does not include the knowledge base ID. Cause: The knowledge base ID return switch in the `responseData` configuration item was not enabled, resulting in missing unique identifiers required for traceability and inability to accurately locate source documents.
- Phenomenon: The documents cited in the knowledge base output answer do not match the actual forging batch. Cause: The citation merging rule based on heat number and forging batch was not set, causing documents from different batches to be incorrectly linked and leading to traceability confusion.
- Phenomenon: Citation source fields are empty in the streaming return result. Cause: The `detail` configuration item was not set to `true`. The default simplified result does not include detailed source information required for traceability and cannot meet audit requirements.

## How to Verify Correct Configuration
- Initiate a test query that includes forging heat numbers and ultrasonic testing report keywords, then check if the returned results include traceability information such as knowledge base ID and source document path.
- Review the citation sources in the returned results, confirm that documents with the same heat number are correctly merged, and there are no incorrect cross-batch associations.
- Enable streaming return testing, then check if each segment of output includes corresponding detailed citation sources.
- Call the non-streaming interface to obtain complete results, confirm that the `detail` field returns `true` and includes matched specific field information.

The values provided are common starting points and should be measured against the reader's own samples.
