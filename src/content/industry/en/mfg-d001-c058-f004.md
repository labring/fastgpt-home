# Supplier and Process Quality Audit for Precast Concrete Components: Workflow Orchestration

## What the Data for This Category Looks Like
Core data for precast concrete components comes from BIM detailed design documents, rebar and concrete batch ledgers, mold table and curing kiln operation logs, laboratory test reports, and product QR code traceability systems. Daily supporting documents include component detailed drawings, rebar cutting lists, mold inspection records, pouring and vibration records, curing cycle records, and demolding and factory inspection reports. Data updates trigger per individual component, per batch of materials, or per curing kiln batch. Fields include component unique ID, rebar specification and model, concrete strength grade, curing duration, demolding strength, and more. Each component must correspond one-to-one with on-site lifting positions. This differs from flowable ready-mixed concrete delivered by truck.

## Constraints on Workflow Orchestration
The multi-source data sources and update rhythm (per piece, batch, or curing kiln) for precast concrete components require workflows to precisely match trigger timing. This avoids duplicate or missed executions. The complex set of document types requires splitting workflows into independent nodes such as detailed drawing parsing, material verification, and production record verification. This adapts to processing logic for different document types. The one-to-one correspondence between individual components and on-site lifting positions requires adding a position matching verification link in the workflow. This ensures accurate data association. The high-frequency update feature also requires workflow nodes to support rapid iteration and failure rollback. This reduces rework costs after errors.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Trigger Timing | Triggered by component batch completion time + QR code scan event | Matches the data update rhythm of precast concrete components per batch and per piece |
| Variable Binding | Bind component detailed drawing ID, rebar batch number, curing kiln number via `variables` | Associates multi-source data sources to avoid confusion across data sources |
| Audit Indicator Configuration | Bind demolding strength ≥30MPa, curing cycle ≥48 hours via `variables` | Adapts to the quality verification standards for precast concrete components |
| Problem Classification Rules | Split processing nodes by document type | Adapts to audit documents of different types such as detailed drawings and cutting lists |
| Code Run Timeout | 600 seconds | Adapts to the calculation duration requirements for complex component verification |
| Failure Handling Node | Bind rollback verification link via `nodeId` | Quickly triggers error correction to reduce scrap risk |

## Three Common Configuration Mistakes
- Phenomenon: Problem classification node recognition prompts return results with large deviations. Cause: No classification rules configured for the exclusive document types of precast concrete components. This causes the model to fail to accurately match the audit scenario.
- Phenomenon: MCP plugin calls have no response after being connected. Cause: Did not bind the component batch parameters required by MCP via `variables` in the workflow. This causes the plugin to fail to obtain necessary context information.
- Phenomenon: Code run nodes continue to fail to execute. Cause: Did not adapt to the large-scale verification scenario of precast concrete components. The timeout threshold was set too low, causing the verification logic to be terminated before completion.

## How to Confirm Configuration Is Complete
- Trigger a simulated component QR code scan event. Verify that the workflow executes in sequence according to preset nodes.
- Verify that parameters bound via `variables` correctly associate corresponding data fields such as component detailed drawings and rebar batches.
- Call the test MCP plugin to confirm that the context parameters of the current workflow can be obtained.
- Simulate the code verification scenario for complex components. Verify that the execution duration does not exceed the preset threshold.
