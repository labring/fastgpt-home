# Supplier and Process Quality Audits for Beverage and Bottled Water: Multi-turn Dialogue and Prompt Engineering
This page is compatible with FastGPT v4.17.0

## What the Data for This Category Looks Like
This category primarily covers carbonated drink, juice, tea, functional beverage, and packaged drinking water factories. Daily documents include formula sheets, water treatment records, blending records, sterilization or aseptic filling records, packaging material inspection reports, and finished product inspection reports. Data sources include water source and raw material testing, formula systems, online sugar and acidity monitoring, filling equipment, visual inspection systems, and LIMS systems. Updates occur per batch, per shift, or via continuous collection. Compared to similar food categories, this category features high-speed liquid filling and synchronized formula and packaging execution. Water treatment and aseptic control links account for a larger share of operations. There is no raw milk acceptance step, but product switching frequency is higher.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
The multi-source, high-frequency batch data of this category requires multi-turn dialogue to bind `chatId` to a single batch audit chain, to avoid context confusion across different batches. Field differences in structured documents require prompts to explicitly specify exclusive fields for documents such as formula sheets and water treatment records. High-speed continuous collection of real-time data requires dialogue to support short-interval multi-turn follow-up questions, and to limit context length to avoid exceeding processing limits. Frequent product switching scenarios require prompts to dynamically adapt to the document template of the current audit category, to prevent field matching errors. The requirement for parallel auditing of multiple batches further requires that dialogue context be strictly bound to `chatId`, to avoid interference from cross-batch data.

## Three Common Misconfigurations
- Attempting to export all records via the dialogue log module only returns partial content. The cause is failure to bind the corresponding production batch via `chatId`. The system defaults to returning only the current session’s context, and does not associate full batch audit dialogue.
- After uploading packaging material inspection images, the system cannot complete interpretation. The cause is failure to specify image analysis rules in the prompt, and failure to configure associated fields for corresponding visual inspection data, making it impossible to match the packaging inspection standards for beverage categories.
- After enabling the guest login dialogue window, context memory does not take effect. The cause is failure to bind `chatId` to the dialogue chain, failure to enable the context memory switch, leading to context being cleared after the session ends. It also includes failure to limit the single search document range, with external knowledge interfering with batch-associated context.

## How to Verify Correct Configuration
- Initiate a multi-turn dialogue for single batch audit. After entering the batch number, check if the dialogue context automatically associates corresponding batch documents such as formula sheets and water treatment records.
- Call the dialogue export function, enter the corresponding `chatId`, confirm that complete dialogue records for that batch audit can be extracted.
- Upload packaging inspection images, check if the system can complete content interpretation according to preset prompts and match beverage category inspection standards.
- Enable the guest login dialogue window, initiate multi-round interaction, check if context persists throughout the session without loss.
