# Supplier and Process Quality Audit for Beverage and Bottled Water: Document Parsing and Chunking

## What the Data for This Category Looks Like
Typical entities in this category are carbonated beverage, juice, tea, functional beverage, and packaged drinking water factories. Daily documents include formula sheets, water treatment records, blending records, sterilization or aseptic filling records, packaging material inspection reports, and finished product inspection reports.
Data sources cover water source and raw material testing, formula systems, online sugar and acidity monitoring equipment, filling equipment, visual inspection systems, and LIMS systems.
Document update frequency follows production batches and shifts. Some continuously collected records update in real time.
Documents include dedicated fields such as raw material batch numbers, test values, operation times, and equipment numbers. Most documents combine structured tables and standardized text.

## Constraints Imposed on Document Parsing and Chunking
This category’s documents have high update frequency, diverse types, and include structured test data. This creates multiple constraints for parsing and chunking.
Multiple document types require adaptation to different structures. For example, text paragraphs in formula sheets and tabular data in water treatment records must not be split in a way that breaks logical integrity.
Continuously collected real-time records need to be split by operation period or batch. This prevents cross-batch content from being merged.
Accurate extraction of structured fields requires adaptation to dedicated formats. Otherwise, key information such as feeding amounts and test values may be lost, affecting subsequent audit processes.
Frequent product switches lead to increased document batches. Chunking logic must support quick location of content exclusive to a single batch.

## Configuration Settings
These configurations are adapted for FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the typical paragraph and table row length of single documents in this category, avoiding splitting cross-batch production records |
| `chunkSplitter` | Paragraph + semantic boundary | Adapts to the structure of multiple document types such as formula sheets and test records, preserving the logical integrity of content |
| `customPdfParse` | Enabled | Preserves table and field alignment effects for PDF format documents such as aseptic filling records and packaging material inspection reports |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Adapts to the parsing duration of single batch production documents, avoiding timeouts for large files collected continuously |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Accommodates collections of multiple documents associated with a single batch, such as packaged files of water treatment records and filling records |
| `chunkSettingMode` | Manual configuration | Adjust chunking parameters for different document types to adapt to the unique document structure differences of this category |

## Three Common Mistakes
- Symptom: The test value field is empty in the parsed result after uploading a PDF document. Cause: The `customPdfParse` configuration is not enabled, and the default parsing logic cannot recognize the structured test tables exclusive to this category.
- Symptom: When calling the knowledge base file collection creation interface, the dedicated doc2x PDF parsing process is not triggered. Cause: The `customPdfParse` parameter is not specified in the interface request, and the system default parsing rules are used.
- Symptom: The parsing task times out after uploading batch production documents. Cause: The value of `PARSE_FILE_TIMEOUT_SECONDS` is set too low, and does not adapt to the parsing time of single continuous collection documents in this category.

## How to Confirm the Configuration Is Correct
- Upload a single formula sheet PDF, check if the parsed result fully retains dedicated fields such as additive feeding amounts and batch numbers.
- Upload a single continuously collected water treatment record, check if the chunking results are split by operation period and do not merge content across batches.
- View the parsing task log to confirm that no timeout error is triggered, verifying that the parsing parameters take effect.
- Upload a batch document collection of a preset size, verify that the upload limit does not block legitimate upload requests.

The values provided are common starting points and should be measured against samples relevant to the intended use case.
