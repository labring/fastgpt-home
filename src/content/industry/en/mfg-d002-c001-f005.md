# Drafting Process Documents and Exception Reports for PCB Manufacturing: Tool Calling and Plugins

## What the Data for This Category Looks Like
PCB manufacturing process and exception data primarily comes from Gerber files, drill files, BOM lists provided by customers, as well as CAM analysis results, production equipment parameters, bath solution test records, AOI inspection reports, electrical testing reports, and laboratory slice reports.
Data is continuously collected in line with production batches and shifts. Multiple related documents are generated within a single production batch.
Documents include fields such as drill hole diameter, lamination temperature, chemical solution concentration, defect coordinates, test results. Some parameters carry units like millimeters, degrees Celsius, and grams per liter.

## Constraints for Tool Calling and Plugins Workflow
Data sources are scattered and updated in real time with production batches. Tool calling must support multi-source data pulling and batch parsing, and cannot rely on static datasets.
Field formats vary widely across different documents. For example, drill parameters and AOI defect reports have different field structures. Tools must adapt to heterogeneous data formats.
Continuously collected high-frequency data generates large volumes of input content. Tool calling must limit the context length of a single processing to avoid exceeding model limits.
Exception reports have strict timeliness requirements. Tool calling must support low-latency triggering to ensure exception information is synchronized to the drafting process in a timely manner.

## How to Set Up Configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to automatic parsing needs for multi-source heterogeneous data, no manual specification of a single tool required |
| Number of returns per single tool call | Top 3 entries | Matches the reasonable volume of core process and exception data within a single production batch |
| Context window limit | 8000 token | Adapts to the average content length of PCB process documents, avoids exceeding model processing limits |
| Timeout threshold | 120 seconds | Covers average time for multi-source data pulling and parsing, prevents process interruptions |
| Field mapping rules | Automatically match by document fields | Adapts to heterogeneous field structures across different documents, reduces manual configuration costs |

## Three Common Mistakes
- Scenario: Global variable parameters do not take effect after assignment when calling an interface, and returned result fields are empty. Cause: Variables are not correctly bound to the input parameter positions of tool calls, resulting in failed parameter transmission.
- Scenario: When a team application is called as a plugin, the tool call process cannot be triggered, and an error prompt indicating that the tool was not found is returned. Cause: Tool call permissions are not enabled in the plugin configuration, or the tool and application have not been successfully bound.
- Scenario: CSV file collections created via the interface do not match results generated via the user interface, and field order is scrambled. Cause: No column name mapping rules are specified for the CSV file, and the tool call does not parse data according to the preset field order.

## How to Confirm the Configuration Is Properly Set Up
- Run a production batch process data pulling test, and check whether the fields returned by the tool call match the fields in the source documents.
- Simulate an exception report triggering process, and check whether the tool call return results include preset exception types and corresponding parameters.
- View the tool call running logs, confirm that the timeout threshold has not been triggered, and that the number of returned entries complies with the preset top 3 rule.
- Test the scenario where a team application is called as a plugin, and confirm that the tool call function triggers normally and returns valid results.

The values provided are common starting points and should be measured against the reader's own samples.
