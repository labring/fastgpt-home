# PCB Manufacturing Process Document and Exception Report Drafting: Document Parsing and Chunking

## What this category's data looks like
This category's data comes from engineering, production, quality control, and laboratory departments of printed circuit board factories. It covers engineering production instructions, Gerber parsing records, drilling and lamination parameters, chemical solution analysis reports, AOI reports, electrical test reports, slice reports, and more. Data sources include customer Gerber files, drill tapes, BOM lists, CAM files, equipment operating parameters, bath solution test results, and various inspection data. Update frequency is per production batch, per shift, or continuous collection. Most documents contain precise numerical values, process steps, and inspection result fields.

## What constraints these characteristics impose on the "document parsing and chunking" link
Industrial formats such as Gerber files and drill tapes have varying levels of structural complexity. Some require dedicated parsing logic, and chunking rules must be adapted to different document structures. Continuously collected high-frequency data generates a large number of short single documents, so chunking granularity must be adjusted to avoid information fragmentation. Numerical values of process parameters and inspection results must retain their original units and precision, and associated fields must not be lost during chunking. Exception reports include fault location and rectification suggestions, so chunks must be split by process link to preserve contextual associations.

## How to set configurations
The following configurations are based on the standard settings of FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapts to the paragraph length of PCB process documents containing parameters and steps, avoiding splitting critical process logic |
| `chunkSplitter` | By paragraph + semantic boundary | Adapts to structured content such as Gerber parsing records and inspection reports, preserving the association between process steps and inspection results |
| `customPdfParse` | Enabled | For PDF documents exported from Gerber or CAM files, enabling custom parsing preserves original vector graphics and numerical fields |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Adapts to the file size of complete process packages for a single production batch, preventing large file upload failures |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Handles parsing requirements for multi-page inspection reports and complex Gerber files, preventing timeout interruptions |
| `chunkSettingMode` | Manual configuration | For the special fields of PCB documents, manually adjust chunking rules to preserve process parameters and associated descriptions |

## Three common mistakes
- Symptom: No drilling parameter fields appear in the parsing result after uploading a Gerber format PDF file. Cause: The `customPdfParse` configuration is not enabled; the default PDF parser cannot recognize structured parameters in industrial vector documents.
- Symptom: After calling a tool to send an HTTP request, the tool does not trigger execution but the parameter log shows normal status. Cause: The tool's trigger conditions and knowledge base binding relationship are not configured, or the timeout setting is too short causing the request to not complete.
- Symptom: After importing a Feishu multi-dimensional table, retrieval results cannot return complete table content. Cause: The table recognition mode for custom chunking is not enabled; the default parsing only extracts text content and loses table structure.

## How to confirm configurations are set correctly
- Upload a single typical process document, check the parsed chunk results, confirm that key parameters such as drilling aperture and lamination temperature are fully retained in the same chunk of content.
- Initiate a tool call test, check the tool execution log, confirm that the parameter transfer and execution trigger process is normal.
- Import Feishu spreadsheets and multi-dimensional documents, check the returned content after retrieval, confirm that the table structure and original data are consistent.
- Upload a process package file exceeding the preset size, confirm that no timeout or interruption prompts appear during the upload and parsing process.

The values provided here are common starting points and should be measured against the reader's own samples.
