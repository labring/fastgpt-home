# Drafting Process Documents and Exception Reports for SMT Mounting and Electronic Assembly: Model Access and Configuration

## What the data for this category looks like
Data for SMT mounting and electronic assembly scenarios comes from BOMs, Gerber files, and component coordinate tables provided by customers, plus real-time or work-order level data from MES systems, mounters, SPI/AOI inspection equipment, and reflow oven temperature recorders. Daily documents include changeover sheets, first article confirmation reports, maintenance records, and traceability labels. Fields cover part numbers, reference designators, component lot numbers, temperature curve parameters, defect locations and types, and more. Updates occur in real time per work order or each changeover.

## Constraints on model access and configuration
Multi-source heterogeneous real-time work-order data requires model access to support structured document parsing and real-time data calls. Frequent work-order level updates mean the context must stay strictly limited to the current work order to prevent cross-work-order data interference. Dense-field process and exception documents require model output to accurately match specific fields such as part numbers and reference designators. The system must also adapt to document format differences exported by different equipment to ensure consistent data extraction.

## Configuration Settings
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Matches the total data volume of process documents and exception reports for a single work order, and avoids exceeding the model's context window limit |
| `maxTokens` | 2000–3000 token | Meets the output length requirements for complete process document drafting and exception analysis reports, and prevents result truncation |
| `temperature` | 0.2–0.4 | Maintains accuracy of process descriptions and defect analysis, and reduces the impact of subjective bias on results |
| Workflow/API tool selection | auto | Automatically calls document parsing tools to extract key fields from structured data such as BOMs and coordinate files |
| `AIPROXY_API_ENDPOINT` | http://localhost:8080/v1 or corresponding cloud service provider access address | Adapts to low-latency data processing requirements for SMT scenarios, and ensures response speed for real-time work-order processing |
| `AIPROXY_API_TOKEN` | Exclusive access token generated by the platform | Ensures security of model access permissions, and prevents unauthorized calls from affecting production data |

## Three Common Misconfigurations
- After deploying a 14B model locally, adding work-order data calls for exception report drafting returns an error. The error returns a 500 status code or "context overflow" prompt. The root cause is failing to adjust the `maxContext` parameter to match the local model's context window limit.
- The system model dropdown list does not display configured local model options, and the target model cannot be selected. The root cause is failing to correctly configure `AIPROXY_API_TOKEN` or using an incorrect access address format.
- Process document drafting results omit key fields such as part numbers and reference designators. The root cause is failing to enable the `toolChoice` automatic parsing function, so core data from structured documents is not extracted.

## How to Verify Successful Configuration
- Upload the BOM and SPI report files for a single work order, call the drafting function, and check if the output includes corresponding fields such as part numbers and defect types.
- Check the FastGPT v4.17.0 model access logs to confirm that the request status codes for `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are 200.
- Adjust the `temperature` parameter value, compare two output results, and confirm that the impact of parameter adjustments on results matches expectations.
- Test cross-work-order context isolation: upload data from different work orders, call the function, and confirm the output does not include redundant data from other work orders.

The values provided here are common starting points and should be evaluated against local test samples.
