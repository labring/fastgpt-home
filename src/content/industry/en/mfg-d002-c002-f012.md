# Drafting Process Documents and Exception Reports for SMT Mounting and Electronic Assembly: Deployment and Upgrade

## What data looks like for this category
Data involved in drafting process documents and exception reports for SMT mounting and electronic assembly comes from multiple sources. These include customer-provided BOM, Gerber, and coordinate files, factory MES systems, solder paste and component batch records, and real-time operating data from placement machines, SPI/AOI inspection equipment, and reflow ovens. Daily documents include BOM and coordinate files, line change lists, stencil and furnace temperature records, first article confirmation reports, SPI/AOI inspection reports, maintenance records, and traceability labels. Data updates occur in real time per work order and each line change. Fields include part number, reference designator, component batch, furnace temperature curve parameters, inspection defect type, and more. Some documents include professional units such as millimeter-level coordinates and Celsius-level temperatures.

## Constraints during deployment and upgrade
The high-frequency real-time updates and multi-source heterogeneous data structure of this category require deployment to support incremental data synchronization and multi-format import adaptation. Frequent work order-level updates create high concurrent connection requirements, so stable database and cache clusters must be configured. Data from different sources, such as structured BOM and unstructured inspection reports, requires separate adaptation of storage and parsing rules. Upgrades must be compatible with existing field mapping logic to avoid interrupting the generation of line change-related process documents. Exception reports rely on real-time data docking with SPI/AOI equipment. Deployment must reserve configuration entrances for device APIs or log imports to ensure complete data links.

## Configuration settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–150 concurrent connections` | Adapt to high-frequency data writes per work order and line change, avoid database connection exhaustion |
| `MONGODB_URI` | `Replica set connection string with read-write permissions` | Store unstructured documents such as SPI/AOI reports and maintenance records, support large-volume file indexing |
| `PG_URL` | `Connection string with partition table configuration` | Store structured BOM, line change list, and component batch data, improve high-frequency query efficiency |
| `REDIS_URL` | `Primary-replica synchronization cluster connection string` | Cache real-time furnace temperature and placement status data, reduce real-time read-write pressure on the database |
| `STORAGE_S3_ENDPOINT` | `Object storage endpoint calibrated by vendor actual testing` | Store large-volume process documents such as stencil files and Gerber drawings |
| `FILE_TOKEN_KEY` | `32-bit randomly generated key` | Encrypt access tokens for process documents, prevent unauthorized document downloads |

## Three common misconfigurations
- Symptom: Part number and reference designator fields are empty when importing BOM files after deployment. Cause: Corresponding field mapping rules for the document type are not configured, and core fields of SMT process files are not matched.
- Symptom: Exception reports for some work orders cannot be retrieved after multi-node deployment. Cause: Primary-replica synchronization for `REDIS_URL` is not configured, so cached real-time device data is not synchronized to all nodes.
- Symptom: Locally deployed models cannot parse defect text in SPI/AOI inspection reports. Cause: Industrial inspection document parsing plugins are not enabled, or the model is not adapted to professional term formats for the SMT industry.

## How to confirm successful configuration
- Run an incremental synchronization test, import a new line change list data set, check whether corresponding records are generated in the database, and verify that the concurrent connection count for `DB_MAX_LINK` does not trigger alarm thresholds.
- Access the frontend domain configured via `FE_DOMAIN`, upload a stencil file, check whether a valid access link with an expiration date is generated normally, and verify that the `FILE_TOKEN_KEY` configuration is effective.
- View the storage bucket corresponding to `STORAGE_S3_ENDPOINT`, confirm that documents such as Gerber drawings and furnace temperature records are stored according to the preset path.
- Trigger an SPI/AOI report parsing task, check system logs, confirm that there are no database connection errors or format parsing failure prompts, and verify that read-write permissions for `MONGODB_URI` and `PG_URL` are normal.

The values provided are common starting points and should be measured against the reader's own samples.
