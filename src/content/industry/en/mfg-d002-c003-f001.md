# Drafting Process Documents and Exception Reports for Dairy Processing: HTTP Interfaces and External Systems

## What data for this category looks like
Core data for dairy processing comes from milk source testing, MES systems, homogenization and heat treatment equipment, online temperature and flow collection devices, CIP cleaning systems, and LIMS laboratory management systems. Daily produced documents include raw milk acceptance records, standardized batching sheets, pasteurization or UHT heat treatment records, CIP cleaning verification records, filling records, retained sample and microbial test reports. Data is synchronized in real time per milk tank and per batch. Fields include raw milk antibiotic and physicochemical indicators, heat treatment time and temperature, CIP residue levels, filling environment parameters, and more. Units include ℃, seconds, CFU/mL, mg/L, and others.

## What constraints these characteristics impose on HTTP interfaces and external systems
Real-time high-frequency data updates require interfaces to support low-latency calls, to avoid delays in drafting process documents caused by data lag. Multiple heterogeneous data sources require interfaces to support business documents in different formats, particularly docx format test and cleaning records. Perishable liquid raw materials have strong batch correlation, so interfaces must bind unique batch identifiers to ensure the correspondence between data and process documents. Error consequences include full-tank rejection or large-scale recalls, so interfaces must include failure retry and exception alert capabilities, and strictly control permissions to prevent unauthorized access.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
|---|---|---|
| `Authorization` | Bearer {{Internal Enterprise API Key}} | Used for identity verification when connecting to internal enterprise MES and LIMS systems, and complies with permission control requirements of dairy processing enterprises |
| `variables` | Bind raw milk batch numbers, heat treatment temperature thresholds, CIP residue standards | Adapt to real-time updated process data per batch, and match the field association rules of business documents |
| `responseData` | Parse into structured JSON format | Facilitate rapid extraction of core indicators for drafting exception reports, and adapt to FastGPT knowledge base call logic |
| Timeout Setting | 30 seconds | Matches the response requirements of real-time data collection, and avoids blocking production processes due to device delays |
| Document Parsing Mode | Only extract the main body content of docx files | Adapt to docx format reports that can be normally downloaded via browsers, and compatible with existing business data sources |
| Retry Count | 2 times | Address temporary call failures caused by network fluctuations, and reduce the probability of interruptions in exception report drafting |

## Three common mistakes
- Calling the content interface returns an unsupported format error. The symptom is the interface returns a 415 Unsupported Media Type status code. The cause is that the parsing adaptation for docx files is not configured correctly, and the Content-Type of the interface request header is not set to the corresponding format.
- The model cannot connect after upgrading FastGPT v4.17.0. The symptom is the interface returns a 500 Internal Error or connection timeout. The cause is that the model call key and proxy configuration in `variables` are not updated synchronously, and the API call rules of the new version are not adapted.
- The docx file provided in the URL cannot be accessed. The symptom is the interface returns a 404 Not Found status code or an empty content field. The cause is that the docx links stored in the internal enterprise storage are not added to the interface access whitelist, and the permission verification for file downloads is not configured.

## How to confirm the configuration is complete
- Initiate a curl request to call the target interface, pass the `variables` parameter of the test batch, and verify that the returned `responseData` includes core indicator fields of raw milk acceptance and microbial test reports.
- Check the validity of the `Authorization` parameter. Initiate a call with an invalid key, confirm that the interface returns a 401 Unauthorized status code, and verify that the identity verification logic takes effect.
- Simulate network fluctuations to trigger an interface call failure, verify that the system automatically triggers the retry mechanism, and the number of retries meets the configured 2 times requirement.
- Pass the URL of a docx file that can be normally downloaded via a browser, verify that the content returned by the interface matches the main body of the original document, and there are no format parsing errors.

The values provided here are common starting points and should be measured against the reader's own samples.
