# Process Document and Exception Report Drafting for Dairy Processing: Tool Calling and Plugins

## What the data for this category looks like
Daily documents for this category include raw milk acceptance records, standardized ingredient lists, pasteurization or UHT heat treatment records, CIP cleaning records, filling records, retained sample and microbial test reports. Data sources cover milk source testing equipment, production MES systems, online sensors for homogenization and heat treatment, real-time flow and temperature collection devices, CIP systems, and LIMS laboratory management systems. Data updates are synchronized in real time per milk tank and per production batch. Liquid biological raw materials are perishable and the production chain is continuous, with no batch-wise isolation buffer space.

## What constraints these characteristics impose on the "tool calling and plugins" link
Real-time, high-frequency production data updates require tool call response delays to match production rhythms, avoiding process deviations caused by delays. Multi-source heterogeneous data formats require plugins to support connections to data sources with different protocols and unify field formats to generate standardized process documents. Independent data identifiers per milk tank and per batch require `toolChoice` to be bound to a unique batch code, ensuring tool calls only pull data for the corresponding batch and avoid cross-batch data confusion. The characteristic that liquid raw materials have no batch-wise isolation buffer space requires exception report generation tools to trigger quickly, preventing problem escalation and expanded impact scope.

## How to set the configurations
This guide is written for FastGPT v4.17.0:
| Configuration Item | Recommended Setting | Rationale for This Setting |
| ------ | -------- | ------------ |
| Workflow/API tool selection | `auto` | Adapts to automatic tool calling logic for multi-source data, matching process and exception handling requirements across multiple dairy processing links |
| Workflow/API function-call configuration | Bind unique batch code | Ensure tool calls only pull data for the corresponding milk tank or production batch, avoiding cross-batch data confusion |
| Data source request timeout | 60 seconds | Match real-time data collection delay requirements for production links, preventing process document generation from being blocked by device data pull timeouts |
| Number of data items returned per single call | Top 10 entries | Control the volume of data returned by tool calls, avoiding context overload that slows exception report generation |
| Exception report trigger condition | Match microbial test exception thresholds | Align with dairy processing test judgment standards, automatically triggering the exception report drafting process |
| Tool call retry count | 2 times | Balance data pull success rates and production chain response speeds, avoiding repeated requests that occupy system resources |

## Three common errors
- A `The tool call is not supported` error appears in the interface. The cause is that the tool calling function is not enabled in the application configuration, or the corresponding tool plugin has not been bound and authorized.
- Process document data returned by tool calls does not match the current production batch. The cause is that the trigger rule for binding a unique batch code is not configured, causing the tool to pull cross-batch historical data.
- Tool calls continue to time out after deploying a model locally. The cause is that the configured data source request timeout threshold is too short, not matching the actual time taken by local model inference delay or device data pulling.

## How to confirm the configuration is correct
- Initiate a tool call for a simulated production batch, verify that returned data only includes records for the corresponding batch such as raw milk acceptance and heat treatment.
- Trigger the exception report drafting process, verify that the tool automatically pulls corresponding microbial test reports and equipment log data.
- View plugin call logs to confirm that tool call retry counts and timeout settings match the expected configuration.
- Test cross-batch tool call requests, verify that the system automatically intercepts call requests that do not match the batch code.
