# Drafting Process Documents and Exception Reports for Dairy Processing: Knowledge Base Retrieval and Recall

## What Data Looks Like for This Category
This category of data covers raw milk acceptance records, standardized ingredient lists, pasteurization or UHT heat treatment records, CIP cleaning records, filling operation records, sample retention and microbial test reports, and similar content. Data sources include milk source testing systems, production MES systems, homogenization and heat treatment equipment, online temperature and flow collection modules, CIP systems, and LIMS laboratory management systems. Updates occur in real time per milk tank and per batch. Some online parameters such as temperature and flow are updated every second. Document fields include raw milk antibiotic and physicochemical indicators, heat treatment time and temperature, CIP cleaning parameters, filling environment cleanliness, microbial test values, and more, with corresponding detection units such as ℃, seconds, and CFU/mL.

## What Constraints These Characteristics Impose on the Knowledge Base Retrieval and Recall Link
Real-time, high-frequency updated online equipment data requires the retrieval system to support low-latency recall. It prevents process parameter matching errors caused by data lag.
Multi-source heterogeneous data formats, including original device logs, laboratory reports, production documents, and others, require retrieval to adapt to different text structures. It must accurately match field-associated information.
Independent data attributes per milk tank and per batch require retrieval to filter recall results by batch. This prevents cross-batch parameter confusion.
The timeliness of perishable raw materials requires rapid recall of full-link data for the corresponding batch when drafting exception reports. This avoids delays that lead to full-tank rejection or large-scale recall risks.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Dairy processing parameters require precise matching to avoid recalling irrelevant cross-batch data |
| `limit` | Top 10 entries | Production documents per batch are limited in number; excessive results will exceed context window limits |
| `searchMode` | Hybrid retrieval mode | Balances recall accuracy for both structured device data and unstructured reports |
| `usingReRank` | Enabled | Optimizes sorting logic for multi-source heterogeneous data, prioritizes content strongly related to current processes or exceptions |
| `datasetSearchUsingExtensionQuery` | Enabled | Supplements dedicated fields such as raw milk batch and heat treatment parameters to improve retrieval matching accuracy |
| `collectionIds` | Dedicated dairy production knowledge base ID | Limits retrieval scope, excludes irrelevant knowledge base content from other product categories |

## Three Common Mistakes
- Phenomenon: A "database connection timeout" error appears during retrieval, or no results are returned. Cause: Data sources are not synchronized per the update rhythm of each milk tank or batch, causing the dataset used for retrieval to not match the current production batch.
- Phenomenon: Retrieval results include production documents from other categories, or field units display abnormally (such as ℃ shown as Pa). Cause: The `collectionIds` configuration for limiting retrieval scope is not set, or the `datasetSearchUsingExtensionQuery` for supplementary dedicated field matching logic is not enabled.
- Phenomenon: Retrieval returns too many redundant results, leading to extended time spent drafting exception reports. Cause: A reasonable `limit` parameter is not configured, or `usingReRank` for result reranking optimization is not enabled.

## How to Confirm the Configuration Is Correct
- A raw milk antibiotic test retrieval request is submitted, and returned results are verified to only include raw milk acceptance records for the corresponding batch.
- The FastGPT v4.17.0 retrieval log is checked, and confirmation is made that only the specified dairy production knowledge base collection is called.
- An exception scenario retrieval is tested, and returned results are verified to include associated heat treatment and CIP cleaning records.
- Retrieval parameters are adjusted, and the impact of similarity threshold changes on recall results is verified to match expected settings.

The values provided here are common starting points, and should be measured against the reader's own samples.
