# Drafting Process Documents and Exception Reports for Warehousing, Lot Tracking, and In-Plant Logistics: Tool Calling and Plugins

## What the data for this category looks like
The core data for this category comes from ERP and WMS systems, supplemented by barcode/RFID scanning data, AGV transport records, weighing logs, and production work order information. Daily generated and circulated documents include receiving slips, putaway slips, material picking and return slips, warehouse transfer slips, inventory counts, lot ledgers, first-in first-out (FIFO) control records, and expiration date control records. Data update frequencies are divided into three categories: real-time (location changes, scanning operations), daily (work order picking, cross-warehouse transfers), and monthly inventory (physical vs. book balance reconciliation). Document fields include material codes, lot numbers, location numbers, quantities, expiration dates, inspection statuses, and similar items. Common units include pieces, kilograms, cubic meters, and other standard units.

## What constraints these characteristics impose on tool calling and plugin workflows
Multi-source heterogeneous data sources and document formats require plugins to have flexible field mapping capabilities. This ensures that material data from different systems can be uniformly pulled and formatted. Real-time updated location and lot data requires tool calling to have low-latency response capabilities. This prevents the generation of outdated process documents. Monthly inventory-generated physical vs. book balance difference data requires plugins to support bulk pulling and structured organization. This data is used for drafting exception reports. Unstructured fragments from AGV and weighing data require plugins to complete format conversion before they can be embedded into standard process documents. At the same time, the complete traceability chain of lot ledgers requires tool calling to retain full calling context. This ensures that exception reports can trace back data sources and processing workflows.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts automatic calling logic for multiple data source types, matching plugin calling needs for multiple systems including ERP and WMS |
| Single tool call timeout | 15–30 seconds | Addresses network fluctuations when pulling real-time location data, preventing interruptions to process document generation due to timeouts |
| Tool call result caching | Enabled, cache duration 600 seconds | Reduces repeated requests for frequently pulled lot ledger data, aligning with daily updated business rhythms |
| `functionCall` | Mandatory compliance with specified schema | Ensures generated exception report fields align with standard formats for receiving slips and inventory counts |
| Plugin calling permission scope | Only authorized ERP, WMS, and AGV data interfaces | Prevents unauthorized access to data from non-production support systems |

## Three common configuration errors
- Calls return empty results, with logs showing no matching data source fields. The cause is failure to configure mapping rules corresponding to ERP/WMS fields, which prevents tools from pulling lot ledger data.
- Tool calls time out, with the interface displaying a request timeout status code. The cause is failure to adjust the timeout duration, as network latency exceeds the default threshold when pulling real-time AGV location data.
- Report fields are missing after configuring `functionCall`. The cause is failure to add mandatory fields unique to the warehousing category, such as expiration dates and inspection statuses, to the plugin schema.

## How to verify correct configuration
- Manually trigger a tool call, and check if returned data source data includes core fields such as material codes and lot numbers.
- Simulate a monthly inventory scenario, call the bulk data pulling plugin, and confirm that the number of returned records matches the number of entries in the current inventory count.
- In the plugin management interface of FastGPT v4.17.0, check if the configured plugin permission scope only includes ERP, WMS, and AGV data interfaces.
- Verify that when generating exception reports, unique warehousing category data fields such as expiration dates and locations are automatically embedded.
