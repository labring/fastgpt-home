# Drafting Process Documents and Exception Reports for Warehousing, Lot Tracking, and In-Plant Logistics: Deployment and Upgrade

## What data looks like for this category
Typical data sources include ERP, WMS systems, barcode/RFID devices, purchase work orders, storage location information, AGV transport systems, and weighing equipment. Daily generated documents include receiving slips, putaway slips, material picking and return slips, stock transfer slips, inventory checklists, lot ledgers, and expiration date records. Fields cover material codes, lot numbers, storage location numbers, inspection statuses, expiration dates, quantity units, and more. Data update frequencies are divided into real-time (storage location and lot status), daily (material picking/return and stock transfer data), and monthly inventory (total inventory and slow-moving material records).

## What constraints do these characteristics impose during deployment and upgrade
Multi-source heterogeneous data sources require interface connection configuration for multiple systems during the deployment phase to avoid data synchronization delays. High-frequency real-time updates of storage location and lot data require optimizing the vector database update frequency during the upgrade phase to prevent information deviation caused by cache expiration. Diverse document formats and dedicated field requirements require configuring precise document parsing rules during deployment to ensure that different types of warehousing documents can be correctly extracted as retrievable knowledge base content. Cross-warehousing unit data isolation requirements also require retaining permission isolation configuration items during upgrades to avoid data mixing across different storage groups.

## How to set configurations
All following configuration items are compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `DB_MAX_LINK` | `120–180 connections` | Connect multiple ERP, WMS, and AGV system instances to avoid connection pool exhaustion |
| `REDIS_URL` | `Cluster address with access control, 60-second timeout` | Cache real-time storage location and lot ledger data to ensure response speed for high-frequency queries |
| `STORAGE_S3_ENDPOINT` | `Intranet S3-compatible storage node` | Store large documents such as inventory checklists and RFID scan logs to reduce external network transmission latency |
| `FILE_TOKEN_KEY` | `Encryption key consistent with the in-plant logistics system` | Verify the source legitimacy of uploaded receiving slips, material picking/return slips, and prevent unauthorized document imports |
| `PG_URL` | `Read-only instance address` | Read static business data such as lot ledgers and expiration date records to avoid write operations interfering with business operations |
| `ROOT_KEY` | `Exclusive key generated per warehousing unit` | Isolate knowledge base data across different warehousing units such as raw material warehouses and finished product warehouses to ensure data isolation |

## Three common mistakes
- Symptom: Frequent timeout errors occur during bulk import of warehousing documents, and backend logs show database connection exhaustion. Cause: No reasonable value is configured for `DB_MAX_LINK`, and the connection pool cannot support concurrent requests from multiple ERP/WMS systems.
- Symptom: Some fields are empty in imported lot ledgers, making it impossible to generate complete process document fragments. Cause: The `FILE_TOKEN_KEY` consistent with the in-plant logistics system is not used, causing parsing failures for some encrypted RFID scan log documents.
- Symptom: Batch information query results are incomplete, only including material data for some storage locations. Cause: `PG_URL` is not configured as a read-only instance address, and business write operations occupy too many database resources, leading to incomplete data reads.

## How to confirm configurations are correct
- Perform a bulk import of 10 different types of warehousing documents, including receiving slips, inventory checklists, and lot ledgers, and check whether they can be parsed normally and generate corresponding knowledge base entries.
- Initiate 100 consecutive batch information query requests, confirm that the response time is stable within an acceptable range, and verify that the `REDIS_URL` cache configuration is effective.
- Attempt to import a test receiving slip from an unauthorized source, check whether it is intercepted by the system, and verify that the `FILE_TOKEN_KEY` encryption verification configuration is effective.
- View the backend connection pool monitoring dashboard, confirm that the active database connection count does not exceed the `DB_MAX_LINK` configuration value, and verify that the connection pool configuration is reasonable.

The values provided are common starting points and should be measured against the reader's own samples.
