# Process Document and Exception Report Drafting for Photovoltaic Module Encapsulation: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
This category of data comes from the wafer grading system, glass adhesive film backplane batch ledger, MES production management system, string welding and lamination equipment logs, and EL/IV tester output files. Daily documents include layout drawings, material batch records, lamination process records, EL crack diagrams, IV test reports, insulation voltage resistance records, and packing lists.
Data is updated in real time per individual module and per batch of materials. Each document includes fields such as batch number, current gear, process parameters, and test values. Some graphic and text documents must be linked to production records for the corresponding batch.

## Constraints on Knowledge Base Retrieval and Recall From This Category’s Characteristics
High-frequency real-time updated data requires knowledge base retrieval to align with production rhythms, and avoid recalling expired material batches or process parameters.
The coexistence of multiple document types requires retrieval to support cross-modal matching for graphics and text, numerical reports, and equipment logs. It must accurately associate EL crack diagrams with corresponding lamination process records.
Fixed fields such as batch number and current gear require retrieval to perform precise matching based on specific fields, reducing interference from irrelevant results.
The strong binding between production links and test data requires recalled results to link processes such as string welding and lamination with IV test values. This ensures logical coherence for drafted exception reports.

## How to Configure the Setup
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches precise fields such as batch number and current gear, filters low-relevance recall results |
| `limit` | Top 8–12 entries | The number of associated documents per batch is limited. Too many results will exceed the context capacity limit |
| `usingReRank` | Enabled | Differentiates relevance between graphic and text EL diagrams and numerical test reports. Prioritizes recalling content matching exception keywords |
| `datasetSearchUsingExtensionQuery` | Enabled | Supplements professional photovoltaic encapsulation terminology such as string welding temperature and lamination bubble threshold. Improves retrieval accuracy |
| `searchMode` | Precise matching | Performs targeted retrieval based on fields such as batch number and equipment number. Avoids interference from full-text fuzzy matching |

## Three Common Misconfigurations to Avoid
- A "Request failed with status code 400" error occurs when uploading Feishu-associated knowledge base documents. The cause is incorrect configuration of Feishu Open Platform application permissions, or uploaded documents containing fields the system cannot access. This triggers a parameter error during interface calls.
- Unreasonable values are set when customizing chunk length. This happens without accounting for the mixed graphic and text characteristics of photovoltaic encapsulation documents. Too short a chunk length splits EL crack diagrams and corresponding process parameters. Too long a chunk length causes context redundancy, reducing retrieval accuracy.
- Retrieval results include a large number of documents from non-current batches. This occurs when a reasonable value for the `limit` parameter is not set, or when precise matching mode is not enabled. Too many irrelevant historical batch data are recalled.

## How to Confirm the Configuration Is Complete
- Upload a current batch’s lamination process records and EL crack diagrams, initiate a retrieval request, and verify that the recalled results include the associated material batch ledger.
- Trigger a simulated request for exception report drafting, check the number of documents returned by retrieval, and confirm it matches the value range set by the `limit` parameter.
- Review the relevance of retrieval results, confirm that low-relevance irrelevant documents have been filtered by the `similarity` threshold.
- Validate the Feishu knowledge base document import process, confirm no 400 errors occur, and ensure documents are successfully synchronized to the knowledge base.

The values provided are common starting points and should be measured against the reader's own samples.
