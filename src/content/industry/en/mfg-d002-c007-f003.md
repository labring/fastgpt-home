# Stamping and Sheet Metal Forming Process Document and Abnormal Report Drafting: Multi-turn Dialogue and Prompt Words

## What the data for this category looks like
Stamping and sheet metal forming scenario data originates from stamping workshops at automobile panel, home appliance sheet metal, and hardware component enterprises. Data includes steel coil labels and quality certificates, stamping press and feeder operation data, mold management system records, MES production data, and dimensional inspection reports from coordinate measuring machines or inspection tools. Daily documents cover stamping operation instructions, material utilization rate sheets, mold inspection sheets, first and last piece records, and mold change records.
Data updates occur per coil of material, per production batch, or each time a mold is changed. Each document includes dedicated fields such as mold clearance parameters, blank holder force setting values, and material grades.

## What constraints these characteristics impose on multi-turn dialogue and prompt words
Data updates happen per coil of material, production batch, or mold change. Multi-turn dialogue must strictly limit context scope. Only the latest data within the current production cycle may be called. This avoids confusion from old data across batches or prior to mold changes.
Daily documents contain dedicated business fields. These include mold clearance parameters, blank holder force setting values, and material utilization rate calculation results. Prompt words must explicitly specify extracting these dedicated fields. Generic manufacturing document templates cannot be reused directly.
Multiple heterogeneous data sources require explicit association of corresponding data sources in dialogue configuration. This avoids calling irrelevant machining or assembly process data. Frequently updated data must sync latest records each time a dialogue is initiated. Real-time pull trigger rules must be configured for this purpose.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `messages` parameter configuration | Retain the first 3 rounds of dialogue content within the current mold change cycle + current user input, bind batch identification via `chatId` | Focus on valid data for the current production scenario, avoid interference from cross-cycle data, use `chatId` to distinguish dialogues for different production batches |
| `variables` variable binding | Bind the current batch’s steel coil grade, material utilization rate, and mold clearance parameters, no more than 8 fields | Accurately extract dedicated business variables for stamping scenarios, avoid excessive variables leading to delayed dialogue processing |
| Context window size | 1200–1800 characters | Adapt to the field length of stamping-related documents, avoid processing overflow |
| Dialogue timeout period | 600 seconds | Adapt to the pull duration of stamping data, avoid process interruptions caused by long waits |
| Data source association scope | Only call mold inspection sheets and MES data from the last 2 mold changes | Match the dedicated data sources for stamping scenarios, exclude irrelevant workshop data |
| Dialogue role setup | Preset as stamping process engineer | Align with industry terminology specifications, ensure prompt word logic conforms to the business scenario |

## Three Common Misconfigurations
- Form input fields configured in the workflow do not appear in dialogue interactions. The cause is that form variables are not correctly bound to the corresponding fields of the `variables` parameter, causing the dialogue module to fail to read incoming business parameters.
- The file link configuration of the AI dialogue module does not take effect, and the specified mold inspection sheet data cannot be called. The cause is that the data source path of the mold management system is not explicitly associated in the configuration, or the data update trigger condition is not specified.
- The dialogue role is set incorrectly, causing the prompt words to fail to match the business logic of the stamping scenario, and the generated process documents contain non-dedicated parameters. The cause is that the dialogue role is not preset as a stamping process engineer, and a generic manufacturing role template is used by mistake.

## How to Verify Correct Configuration
- Initiate a test dialogue, enter the current production batch number, check whether the `messages` parameter contains the first and last piece record data of the corresponding batch.
- Trigger the dialogue process, check whether the `variables` correctly extract dedicated business fields such as steel coil grade and material utilization rate.
- Review the generated process documents to confirm that they include stamping scenario-specific parameters such as mold clearance and blank holder force.
- Check the FastGPT v4.17.0 runtime logs to confirm that the context call scope does not include irrelevant data from non-stamping workshops.
