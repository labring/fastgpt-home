# Drafting Process Documents and Exception Reports for Stamping and Sheet Forming: Tool Calling and Plugins

## What the Data for This Category Looks Like
This category's data mainly comes from steel coil labels and quality certificates, press and feeder operation data, mold management systems, MES systems, coordinate measuring machine or fixture inspection data. Daily associated documents include stamping work instructions, material utilization rate sheets, mold inspection sheets, first and last piece records, dimensional inspection reports, and mold change records. Data updates trigger per coil of material, each production batch, and each mold change operation. Document fields include steel coil grade, sheet thickness and width, press pressure and stroke, mold number and wear amount, measured dimensions and tolerance values, etc. Corresponding units include millimeters, megapascals, kilonewtons, and others.

## Constraints for Tool Calling and Plugins
Data updates for this category trigger dynamically with production nodes. Tool calling must adapt to on-demand triggering logic to avoid pulling redundant or delayed data on fixed schedules. Multi-source heterogeneous data formats require plugins to support different system API return formats and complete field standardization conversions. Specialized document fields require tool calling to accurately match corresponding field names, preventing irrelevant data extraction from affecting report accuracy. The volume of documents for a single production batch or mold change operation fluctuates greatly. The data pull volume for a single tool call must be limited to avoid timeouts or excessive resource usage.

## Three Common Misconfigurations
- Failing to hide the original plugin execution return content after tool calling, only displaying the final drafted report. This occurs because the output parameters of `toolChoice` are not configured correctly, causing plugin execution results to be directly inserted into the conversation flow.
- When multiple tool calling nodes are configured in a workflow, only the results of preceding steps take effect, and subsequent tools cannot obtain correct input. This occurs because the step-by-step context retention setting is not enabled, and the processing results of intermediate steps are not properly cached.
- An authentication failure prompt appears when calling a custom production data plugin, making it impossible to pull mold or inspection data. This occurs because the plugin's API key and access permissions are not configured correctly, preventing the system from connecting to the corresponding data source.

## How to Confirm Successful Configuration
- Trigger a tool call at a mold change node, check whether the returned data includes the current mold change's mold number and inspection records, matching the configured field requirements.
- View the tool call logs to confirm that the timeout period and data pull count match the preset configuration, with no abnormal error reports.
- Start a multi-step workflow to confirm that the results of intermediate steps are correctly passed to subsequent tool calling nodes.
- Verify the plugin's trigger logic, ensuring that calls are only started when mold changes or production batch updates occur, with no redundant triggering.
