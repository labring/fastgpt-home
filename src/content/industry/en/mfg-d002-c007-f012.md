# Stamping and Sheet Metal Forming: Process Document and Exception Report Drafting - Deployment and Upgrade

## What data for this category consists of
This category of data mainly comes from steel coil labels and quality certificates, punch and feeder operation data, mold management systems, MES systems, coordinate measuring machine or fixture inspection data. Data updates are triggered with each coil of material, each batch of production parts, and each mold change. Daily documents include stamping work instructions, material utilization rate sheets, mold inspection sheets, first and last piece records, dimensional inspection reports, and mold change records. Document fields include steel coil grade, mold number, mold change time, processing dimensional parameters, inspection deviation values, and similar items. General statistical percentage data is not included.

## Constraints imposed on deployment and upgrade
The high-frequency, multi-source, production-node-bound data characteristics of this category impose multiple constraints on deployment and upgrade. High-frequency update demands database connection configurations adapted to stable long links to avoid synchronization interruptions. Some devices in workshop intranet environments cannot access interfaces via standard HTTPS requests, so connection methods that skip certificate verification must be supported. Multi-source heterogeneous data requires flexible reserved data source adaptation configurations to match interfaces of different formats such as mold management systems and MES. Customized document field requirements mean support is needed for custom parsing rules bound to stamping-related business fields. During upgrades, real-time production-related data synchronization must be maintained without interruption to avoid disrupting normal workshop operations.

## Configuration settings
The following configuration items apply to FastGPT v4.17.0:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:port/database?ssl=false` | Adapts to workshop intranet environments without valid HTTPS certificates, skips certificate verification to ensure normal data synchronization |
| `REDIS_URL` | `redis://:password@host:port?maxmemory-policy=allkeys-lru` | Supports caching of high-frequency production data. Set maxmemory-policy based on actual workshop data volume measurements |
| `DB_MAX_LINK` | `20–30` | Matches concurrent data synchronization requests from multiple workshop devices to avoid connection pool overflow |
| `STORAGE_S3_ENDPOINT` | Intranet object storage intranet address | Adapts to workshop intranet storage environments to reduce public network transmission latency |
| `FILE_TOKEN_KEY` | Key generated according to workshop document encryption rules | Protects access security of stamping process documents and inspection data |
| `ROOT_KEY` | Randomly generated 32-bit string | Ensures access permission security for the system backend management interface |

## Three common configuration mistakes
- Phenomenon: After deployment, unable to pull interface data from mold management systems or MES, returning an SSL certificate verification failure error. Cause: Connection parameters that skip certificate verification were not configured, and the workshop intranet environment without valid HTTPS certificates was not adapted.
- Phenomenon: In FastGPT v4.9.4, after enabling the citation function, the generated exception report still contains content for which citation was not enabled. Cause: There is a compatibility issue with the version's built-in citation verification logic, and the citation switch status in the application configuration was not read correctly.
- Phenomenon: In FastGPT v4.8.23 deployed via Docker, the tool call judgment logic is abnormal, and some models cannot trigger preset process document generation tools. Cause: Tool call trigger conditions were not configured according to stamping scenario business rules, or there is a version compatibility issue with the tool call module in the image version.

## How to confirm correct configuration
- Perform a data source connectivity test in the intranet environment, adjust connection parameters such as `MONGODB_URI` until no SSL verification errors occur.
- Upload a sample stamping work instruction document to test the document parsing function, confirm that preset business fields can be extracted.
- Start an incremental data synchronization task, observe the data update frequency, and adjust synchronization configuration until it matches the trigger rhythm of production nodes.
- Log in to the system backend, verify that the key configured via `ROOT_KEY` can normally access the management interface without permission errors.

The values provided are common starting points and should be measured against the reader's own samples.
