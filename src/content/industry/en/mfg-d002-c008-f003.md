# Drafting Process Documents and Exception Reports for Cosmetics Manufacturing: Multi-turn Dialogue and Prompt Engineering

## Data Profile for This Category
Cosmetics manufacturing data originates primarily from registered or filed formulas, raw material safety documentation, weighing and emulsification equipment, ERP/MES systems, laboratory test records, and packaging material version repositories. Daily production documents include formula process sheets, weighing and feeding records, emulsification or filling records, cleaning and site clearance records, semi-finished and finished product inspection reports, and label review forms. Data is updated with each production batch or each line change. Document fields include formula components, restricted substance content, production temperature, batch number, packaging material version, and other fields. Some fields must meet filing compliance requirements.

## Constraints for Multi-turn Dialogue and Prompt Engineering
The batch independence and compliance requirements of cosmetics manufacturing create clear constraints for multi-turn dialogue and prompt engineering configurations. First, data is updated per batch and must strictly align with filing rules. Dialogue contexts cannot share data across batches, as this will create inconsistencies between process documents and filings and introduce compliance risks. Second, document fields include highly compliance-sensitive content such as restricted substances and label claims. Prompts must only call compliance data for the current batch, to avoid generating content that fails to meet filing requirements. Finally, data from multiple systems must be accurately linked. Dialogues must trace feeding and test records for the current batch, to ensure exception reports are relevant and accurate, and avoid missing key production process information.

## Configuration Guidelines
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum Context Length | 10000–15000 characters | Covers the total character count of full-process documents for a single batch, to avoid truncating core compliance fields such as restricted substance content and batch numbers |
| `variables` Binding Rules | Map to exclusive data via the current production batch ID | Ensures each dialogue only loads feeding and test records for the corresponding batch, and does not read historical data across batches |
| `messages` Field Processing | Automatically filter historical messages not from the current batch | Avoids context pollution, and complies with batch control requirements for cosmetics manufacturing |
| Prompt Template Configuration | Embed filing formula verification logic | Ensures generated process documents remain consistent with filed data |
| `chatId` Binding Rules | Bind the unique production batch ID as the identifier | Distinguishes dialogue contexts for different production batches, to prevent data cross-interference |
| Response Preview Switch | Enable Human message preview | Facilitates troubleshooting of abnormal situations where the `messages` field is empty |

## Three Common Misconfigurations
- The Human value of the `messages` field is empty in API call response previews. The current batch’s user input is not correctly bound to the corresponding position in the `messages` array, so the system cannot recognize user question context.
- Generated process documents include formula data from non-current batches. The batch binding rule for `variables` is not configured, so the dialogue accesses document data from historical batches and violates batch control requirements.
- The dialogue interface has interaction lag and abnormal historical message loading. The batch binding for `chatId` is not correctly configured, so dialogue contexts from different batches are mixed and displayed, exceeding system processing limits.

## How to Confirm Proper Configuration
- Initiate a dialogue related to a single production batch, and check if the Human value in the `messages` field of the response preview includes the current user input.
- After generating a process document, confirm that the restricted substance content matches the filed formula data.
- Switch the `chatId` for different batches, and verify that dialogue contexts do not share data across batches.
- Trigger exception report generation, and check if it is linked to the current batch’s test records and feeding data.

The values provided are common starting points and should be measured against the reader's own samples.
