# Drafting Process Documents and Exception Reports for Cosmetics Production: Workflow Orchestration

This page provides explanations based on the workflow functionality of FastGPT v4.17.0.

## What the Data for This Category Looks Like
Data sources for cosmetics production include registered or archived formulations, raw material safety documents, MES/ERP systems, weighing and emulsification equipment, laboratory test records, and packaging material version archives. Daily produced documents include formulation process sheets, weighing and feeding records, emulsification or filling records, cleaning and site clearance records, semi-finished and finished product inspection reports, and label review documents.

Data updates are triggered per production batch or each line change. Fields include restricted substance content of raw materials, emulsification temperature parameters, batch number, packaging material version number, inspection results, and more. Units include degrees Celsius, kilograms, batch numbers, and others.

## What Constraints Do These Characteristics Impose on the "Workflow Orchestration" Link
The need for multi-source data access requires workflows to support integration with multiple independent data sources such as equipment, ERP, and laboratories, to avoid manual duplicate data entry.
The high-frequency update characteristic requires workflows to dynamically bind real-time production data, without adjusting configuration each time to adapt to new production batches.
Strict field compliance requirements require workflows to include built-in verification logic, to ensure generated process documents and exception reports are consistent with archived data.
Severe consequences of errors require workflows to set exception trigger branches, to automatically generate warning reports when data does not match or processes encounter exceptions, preventing unqualified products from entering the market.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| Variable Settings | Bind the three core `variables` of production batch, raw material list, and packaging material version | Matches exclusive data for each production batch, ensuring consistency between process documents and archived information for the corresponding batch |
| Node Trigger Rules | Trigger in the order of production nodes, with `nodeId` associated with three links: equipment data collection, verification, and report generation | Follows the process flow logic of cosmetics production, to avoid disordered links |
| Data Verification Rules | Set restricted substance content verification thresholds based on actual measurements, match the first 3 archived entries for packaging material versions | Meets compliance requirements for cosmetics archiving, avoiding incorrect use of packaging materials or non-compliant raw materials |
| Maximum Context Length | 1000-1500 characters | Covers core content of single-batch process documents, avoiding context overflow |
| Retry Count | 3 times | Addresses temporary fluctuations in equipment interfaces, reducing the probability of workflow interruptions |
| Timeout Limit | 60 seconds | Matches the return cycle of laboratory test data, avoiding long wait times |

## Three Common Mistakes
- Failure to bind the output fields of code nodes to `variables` in the workflow. The symptom is that the AI chat link cannot obtain device data results from code runs. The cause is that the output identifier of the code node was not associated during variable configuration.
- Incorrect configuration of data mapping rules, leading to HTTP-returned packaging material version information not being filled into the label review document. The symptom is that the generated label document lacks the packaging material version field. The cause is that the specified field from the HTTP response was not mapped to the document template variable.
- Failure to retain the original workflow's `nodeId` association relationship, leading to some nodes failing to trigger normally after import. The symptom is that node status shows configuration conflicts. The cause is that the configuration was not imported according to the original workflow's node dependency relationships.

## How to Confirm Proper Configuration
- Trigger a simulated production batch workflow, check whether each node executes in the preset order.
- Input abnormal test data, such as raw material content exceeding the archived range, confirm whether the verification node triggers an abnormal warning.
- Access the `variables` configuration page, confirm that all production-related fields are bound to corresponding data sources.
- Test HTTP interface calls, confirm that returned data can be correctly mapped to document template variables.

The values listed above are common starting points. They should be evaluated against the reader's own samples.
