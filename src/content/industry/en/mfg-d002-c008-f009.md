# Drafting Process Documents and Exception Reports for Cosmetics Production: Model Access and Configuration

## What the Data for This Category Looks Like
Cosmetics production process and exception data primarily originates from registered or filed formulas, raw material safety documents, weighing and emulsification equipment, ERP/MES systems, laboratory test records, and packaging material version information. Daily documents include formula process sheets, weighing and feeding records, emulsification or filling records, cleaning and site clearance records, semi-finished and finished product inspection reports, and label review documents.
Data updates are triggered with each production batch or each line change. Document fields include restricted substance content, process temperature parameters, batch number, packaging material specifications, and all data updates dynamically alongside the corresponding production batch.

## Constraints on Model Access and Configuration
Cosmetics production process and exception data updates dynamically with each production batch or line change. This requires model access configurations to support real-time association with the latest filed formulas, production records, and other data, to avoid using expired information.
Documents contain highly compliance-focused fields such as restricted substance content and label claims. Configurations must prioritize retrieving accurate filed data sources to reduce compliance risks in generated content.
The total volume of documents for a single production batch is moderate, but fields are highly targeted. Context length must be controlled to prevent irrelevant data from interfering with generation results. Additionally, errors carry compliance risks such as product removal and recall. Configurations must strengthen parameter stability and reduce generation errors.

## Configuration Settings
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Must accommodate all process documents and filed data for a single production batch, to avoid truncating critical restricted substance and formula compliance information |
| `maxTokens` | 3500–4500 token | Controls the generation length of a single process document or exception report, matching the typical length of cosmetics production documents |
| `quoteMaxToken` | 1800–2200 token | Limits the total length of retrieved knowledge base content, prioritizing retention of core compliance data such as filed formulas and raw material safety documents |
| `temperature` | 0.1–0.3 | Reduces generation randomness, ensuring accuracy of process parameters, batch numbers, compliance fields, and other content |
| `toolChoice` | auto | Automatically triggers knowledge base retrieval, adapting to the dynamic data update requirements of each production batch |
| `AIPROXY_API_ENDPOINT` | Fill in according to deployment environment | Adapts to on-premises or private cloud deployment API addresses, ensuring production data does not leave the domain |
| `AIPROXY_API_TOKEN` | Calibrated based on actual testing | Ensures interface call security, preventing unauthorized access |

## Three Common Configuration Mistakes
- Incorrect index model configuration: Calls return a 401 status code or empty results. This occurs when `AIPROXY_API_TOKEN` or `AIPROXY_API_ENDPOINT` are not filled correctly, or when parameter formats do not meet deployment requirements.
- Unintended retrieval with an empty knowledge base: Generated results include irrelevant general question-and-answer content. This happens when skip retrieval logic for empty knowledge bases is not configured, leading the model to use its general capabilities to generate non-production-related content.
- Failed model calls after version upgrade: Timeout or parameter verification failure prompts are returned. This occurs when non-standard configurations from versions prior to FastGPT v4.17.0 are retained, without adapting to the new version’s parameter verification rules.

## How to Verify a Correct Configuration
- Submit the formula process sheet for a single cosmetics production batch, and verify that the generated process document includes filed restricted substance information and correct process parameters.
- Simulate a scenario where the knowledge base is empty, trigger the exception report drafting workflow, and confirm that no irrelevant retrieval results are returned.
- Check interface call logs to confirm that actual call values for configuration parameters such as `maxContext` and `temperature` match preset values.
- Test document generation related to label review, and confirm that generated content complies with cosmetics label compliance requirements.

The values provided are common starting points and should be evaluated against the reader's own samples.
