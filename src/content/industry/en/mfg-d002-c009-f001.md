# Process Document and Exception Report Drafting for Pharmaceutical Preparations Production: HTTP Interfaces and External Systems

## What the data for this category looks like
Data sources for pharmaceutical preparations production include approved prescription processes, MES electronic batch records, equipment and environment monitoring systems, LIMS systems, and quality management systems.
Data updates occur per production batch, when each key process step runs, and per fixed monitoring plans.
Daily documents include master production files, batch production records, batch packaging records, cleaning records, inspection records, deviation/CAPA/change documents, and batch release review forms.
Core fields cover material batch numbers, process parameter values, inspection results, deviation descriptions, corrective actions, and more.

## Constraints on HTTP Interfaces and External Systems
Multi-system data sources, batch-level update frequency, and GMP compliance requirements create multiple constraints for HTTP interface and external system integration.
Connect to multiple data sources including MES, LIMS, and quality management systems.
Interface fields must strictly match each system’s output format. This avoids document generation errors from data mismatches.
Batch-level update frequency requires interfaces to support variable input parameters. This adapts to material, process parameter, and inspection data across different production batches.
GMP requirements for synchronous documents and operations demand real-time linkage between interface calls and production links.
Interfaces must also support real-time return of abnormal data. This ensures full traceability of deviation and correction records.

## Recommended Configuration Settings
| Configuration Item | Recommended Practice | Basis for This Practice |
| --- | --- | --- |
| Request timeout duration | 300–600 seconds | Adapt to multi-system data pulling delays, avoid process interruption from production link wait timeouts |
| Variable input parameter configuration | Support batch number, material batch, and process parameter fields | Match dynamic data requirements for each production batch, adapt to parameter differences across production batches |
| `Authorization` | Generate temporary tokens according to system permissions | Ensure interface call permission compliance, meet operational traceability requirements under GMP |
| Response data validation rules | Verify required field integrity | Ensure pulled MES and LIMS data contain core information required for batch records |
| Response extraction method | Calibrate based on actual measurements | Adapt to FastGPT v4.17.0 and later response formats, avoid incompatible extraction logic |
| Trigger timing configuration | Trigger via production step completion signals | Meet GMP requirements for synchronous documents and operations, ensure document generation aligns with production progress |

## Three Common Misconfigurations
- Phenomenon: Null values return when calling workflow interfaces integrated with external systems. Cause: The `variables` input parameter is not configured correctly. Core dynamic parameters such as production batch numbers are not passed. This prevents the external system from returning corresponding data.
- Phenomenon: Structured data or exception records returned by HTTP requests cannot be extracted normally. Cause: Updated response extraction rules in newer FastGPT versions are not adapted. For example, v4.8.12-beta and later versions have changed response extraction logic. This causes mismatches with preset extraction paths.
- Phenomenon: Dynamically adjusted input parameters cannot be passed during interface calls. Cause: Dynamic input parameter binding is not enabled in workflow configuration. This leaves input parameters fixed, so they cannot adapt to material and process data across different production batches.

## How to Confirm Proper Configuration
- Initiate a simulated call. Pass the material batch number of a test batch. Check if the interface returned fields include core information required for batch production records.
- Check the `Authorization` token generation logic. Confirm only authorized users can trigger interface calls. Confirm call records are traceable.
- Trigger a simulated production step completion signal. Confirm the workflow automatically calls the interface and generates corresponding process documents or exception reports.
- Simulate abnormal data return. Confirm deviation records can sync correctly to the quality management system’s interface.

The values provided here are common starting points and should be measured against the reader's own samples.
