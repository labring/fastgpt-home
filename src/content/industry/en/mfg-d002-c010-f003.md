# Drafting Process Documents and Exception Reports for Medical Device Assembly and Cleanroom Production: Multi-turn Dialogue and Prompt Engineering

## What data looks like for this category
Data for this category comes from design history files, device and material batch ledgers, MES systems, clean environment monitoring equipment, sterilization equipment, and inspection and calibration systems. Daily documents include production process specifications, batch production records, clean zone operation records, sterilization batch records, inspection reports, software version records, adverse event and traceability materials. Data is updated once per batch or per product unit. Clean environment data is updated per the established monitoring plan. Individual documents contain fields such as unique device identification, material batch number, environmental monitoring parameters, sterilization parameters, and inspection results. There are many fields, and they must meet compliance requirements for medical device production.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Because data sources are scattered across different systems, multi-turn dialogue must gradually retrieve MES data, clean environment records, and sterilization parameters for the corresponding batch, to avoid mixing data across batches. Data update frequency changes with production batches. Dialogue context must be limited to the scope of a single production batch, to prevent the introduction of expired or irrelevant data. Document fields must match compliance requirements. Prompts must clearly specify the required field types, to ensure that generated process documents and exception reports meet standard formats. Exception reports must be linked to traceability materials. Multi-turn dialogue must gradually guide the supplement of necessary information such as batch, time, and environmental abnormality details, to ensure a complete traceability chain.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique identifier of the current production batch | Ensure dialogue context only links to process and exception data for the corresponding batch, avoiding cross-batch confusion |
| `variables` | Preset the unique device identification and material batch number for the current batch | Reduce repeated input of basic information during multi-turn dialogue, improving interaction efficiency |
| `messages` | Organize per the historical dialogue records of the current batch | Ensure coherent context for multi-turn dialogue, preventing information loss |
| Maximum context | 1500-2000 preceding characters | Match the size of single-batch production documents, avoiding context overload that impacts generation quality |
| Exception report generation trigger | Trigger after collecting more than 3 abnormality details | Ensure the generated exception report contains sufficient traceability and analysis information |

## Three common mistakes
- A dialogue return result does not include uploaded clean zone monitoring image content. Checking the dialogue log shows no image parsing record, and the API call returns a 400 invalid image error. The cause is that the image processing configuration for multimodal dialogue is not enabled, or the uploaded image format does not meet system requirements, resulting in the image not being loaded into the dialogue context.
- Multi-turn dialogue response time exceeds 600 seconds. Checking system monitoring shows high model call load. The cause is that the scope of the dialogue context is not limited, and historical data from multiple batches is introduced, leading to excessive context size.
- The generated process document does not reference uploaded batch record data. Checking the input variable list shows it is empty. The cause is that the uploaded file identifier is not bound via `variables`, so the system does not treat the uploaded data as dialogue input.

## How to confirm configurations are set correctly
- Check if `chatId` is bound to the unique identifier of the current production batch, to ensure dialogue context only links to data for the corresponding batch.
- Verify that `variables` preset basic information such as the unique device identification and material batch number for the current batch.
- Test uploading a clean zone monitoring image that meets the format requirements, and confirm that the dialogue return result includes the text content parsed from the image.
- Confirm that the current FastGPT version is v4.17.0, to ensure compatibility of configuration items.

The values provided here are common starting points, and should be measured against one's own samples.
