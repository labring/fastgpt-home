# Drafting Process Documents and Exception Reports for Medical Device Assembly and Clean Production: Citation Sourcing and Traceability

## Data Profile for This Category
Typical entities are manufacturers of single-use consumables, implantable and interventional devices, diagnostic equipment, and active medical devices.
Daily documents include production process specifications, batch production records, clean zone records, sterilization batch records, inspection reports, software version records, and adverse event and traceability materials.
Data sources cover design history files, device and material batches, MES systems, clean environment monitoring equipment, sterilization equipment, and inspection and calibration systems.
Update frequency follows per batch, per device, or per clean environment monitoring plan.
Collected data includes device and material batch numbers, clean environment parameters, sterilization parameters, software version numbers, and adverse event traceability fields.
Each document corresponds to full production process information for a single batch or single device.

## Constraints on Citation Sourcing and Traceability
Data sources for this category are dispersed but tightly linked. Traceability workflows must correlate production and monitoring data across multiple systems, requiring precise matching of batch information across different data sources.
Update frequency shifts with production batches, so cited source documents must fully align with the current production batch. Generic historical data cannot be used.
Most documents are controlled production files. Cited content must be traceable back to original records, and must include key unique identifiers and risk control parameters.
Error severity is high: incorrect citations may lead to sterile product failure or traceability failure. As a result, traceability workflows have strict accuracy requirements, and must be strictly bound to a dedicated production knowledge base.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `detail` | `true` | Requires returning complete citation source details to match the strict traceability requirements of medical device manufacturing |
| `quoteMaxToken` | `800–1200 token` | Adapts to the total length of production documents related to a single batch, avoiding truncation of critical traceability information |
| `responseData` | Structure containing cited file paths, batch numbers, and update times | Accurately extracts key traceability fields from medical device production documents to facilitate subsequent verification |
| Maximum number of citations | Top 3–5 entries | Focuses on the most core process and record documents for a single batch, avoiding redundant information that interferes with analysis |
| Knowledge base binding parameter | `[{datasetId: Corresponding production knowledge base ID}]` | Precise calls to knowledge bases bound to dedicated medical device production documents, avoiding interference from cross-category data |
| Timeout threshold | 30–60 seconds | Adapts to query time for multi-system data association, preventing traceability process interruptions due to timeout |

## Three Common Configuration Errors
- Phenomenon: Returned cited files do not match the content of the actually called knowledge base, and some traceability fields are empty. Cause: The knowledge base binding parameter format was not configured correctly, or the passed ID is not bound to a dedicated medical device production document library.
- Phenomenon: After enabling `detail` as `true`, streamed cited content cannot be fully spliced. Cause: Parsing was not performed segment by segment according to the return structure when `detail` is `true`, and citation marker information in segments was omitted.
- Phenomenon: In FastGPT v4.17.0, additional cited content is still returned even after the citation display switch is turned off. Cause: The built-in traceability logic of this version is enabled by default. The global traceability switch setting must be adjusted additionally in the knowledge base configuration.

## How to Verify Proper Configuration
- Submit a process query instruction for a single batch, and confirm that cited files in the returned content belong to the production documents of that batch.
- Enable `detail` as `true`, and check that streamed return segments include complete cited source paths and batch information.
- Adjust the `quoteMaxToken` parameter, and verify that returned cited content is not forcibly truncated.
- Turn off the global citation display switch, and confirm that no additional citation fields are included in the returned results.

The values provided here are common starting points, and should be measured against the reader's own samples.
