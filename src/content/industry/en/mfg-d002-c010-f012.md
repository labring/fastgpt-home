# Drafting Process Documents and Exception Reports for Medical Device Assembly and Cleanroom Production: Deployment and Upgrade

## What this category's data looks like
Daily documents for this category include production process procedures, batch production records, clean zone records, sterilization batch records, inspection reports, software version records, adverse event and traceability materials. Data sources include design history files, device and material lots, MES systems, clean environment monitoring equipment, sterilization equipment, and inspection and calibration systems. Data updates are performed per batch or per product, with regular synchronization following clean environment monitoring plans. Document fields include unique device identification, sterilization parameters, clean zone temperature and humidity, batch number, software version number, and other relevant fields. Corresponding units include ℃, Pa, batch numbers, and others.

## What constraints these characteristics impose on the deployment and upgrade phase
Cross-source data correlation requires configuring cross-system permission mappings during deployment, to ensure accurate binding of process documents, production batches and environment monitoring data. The high-frequency update rhythm requires deploying scheduled synchronization tasks, to avoid data lag that impacts the timeliness of exception report drafting. Compliant storage of controlled documents requires configuring encrypted storage and version control, to prevent unauthorized access or data loss. Field compliance requirements demand strictly matching document fields and system parameters during deployment, to ensure drafted reports meet the category’s traceability and risk control requirements. During upgrades, historical configurations must be synchronized and migrated, to avoid data correlation interruptions caused by parameter changes.

| `FILE_TOKEN_KEY` | `32-bit randomly generated encrypted string` | Encrypts process document access tokens, preventing unauthorized access to controlled documents |
| `DB_MAX_LINK` | `50` | Limits database connection count, avoiding connection exhaustion caused by multi-source data synchronization |

## Three common mistakes
- After deployment, accessing the application returns 404 Not Found. The cause is incorrect configuration of the `FE_DOMAIN` parameter, leading to a mismatch between frontend routing and backend service addresses.
- After upgrading the version, `systemEnv` related configuration items cannot be found. The cause is failure to adjust the configuration file structure per the FastGPT v4.17.0 update notes, with legacy parameters not migrated to their corresponding locations in the new version.
- The view original text function for password-free shared links cannot be disabled normally. The cause is incorrect configuration of `FILE_TOKEN_KEY` or storage permissions, leading to failure of the document access verification logic.

## How to confirm the configuration is complete
- Run the database connection test command to verify that the `MONGODB_URI` configuration can successfully connect to the storage instance.
- Upload a sterilization batch record document, confirming that the document can be stored normally and accessed via the configured domain name.
- Generate a shared link for a process document, verifying that access permissions match the configured token rules.
- Check system operation logs to confirm there are no alarm messages for missing configuration items or incorrect parameter formats.
