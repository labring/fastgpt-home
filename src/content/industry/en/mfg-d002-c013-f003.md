# Drafting Process Documents and Exception Reports for Printing and Packaging Processing: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
The typical entities in this category are color printing, label, carton, flexible packaging, and pharmaceutical packaging processing enterprises. Core daily documents include pre-press files, imposition sheets, printing process sheets, ink color matching records, first-piece sample approvals, barcode inspection records, die-cutting and lamination records. Data sources include customer manuscripts, color management systems, printing press operation data, ink and substrate batch ledgers, spectrometer test results, and barcode detector readings. Documents are updated per order, per batch, and each plate change. Individual process documents include exclusive fields such as version number, CMYK color values, die-cutting tolerance (unit: mm), and ink batch number. Exception reports must link to corresponding batch inspection data and first-piece sample approval results.

## Constraints on Multi-turn Dialogue and Prompt Configuration
The data characteristics of this category impose three core constraints on multi-turn dialogue and prompt configuration. First, data updates occur frequently, and a single order links to multiple documents. The dialogue must retain the latest version and batch information to avoid calling outdated imposition or process sheet data. Second, data sources are scattered, covering equipment test data and manually entered ledgers. Prompts must explicitly specify prioritizing objective test data such as spectrometer color values and printing press operation parameters to reduce errors from manual entry. Third, the consequences of errors are severe. Misprinted plates or unreadable barcodes will lead to full batch scrapping. Multi-turn dialogue must cover three core dimensions in each round of verification: content version, color parameters, and packaging structure, to ensure the accuracy of exception reports.

| Session Binding Rule | Bind all linked documents of the current order by `chatId` | Ensures that process documents and exception report dialogues for the same order are independently linked, to avoid confusion of cross-order data |

## Three Common Misconfigurations
- Phenomenon: After enabling the file upload component in the workflow, an uncaught exception is returned when calling the document parsing tool. Cause: Parsing rules for category-exclusive documents such as AI-format imposition sheets and EPS pre-press files were not configured in advance, leading to failure to recognize exclusive file formats for the printing and packaging industry.
- Phenomenon: An empty value is returned when calling the ink batch field bound to `variables` in multi-turn dialogue. Cause: Exclusive variables such as the current order's ink batch and version number were not passed to the dialogue context during session initialization, leading to incorrect loading of variables.
- Phenomenon: Context loss frequently occurs during dialogue, and the dialogue cannot continue the previous round's version verification requirements. Cause: The dialogue context of the current order was not bound by `chatId`, leading to confusion and overwriting of parameters from different sessions.

## How to Verify Proper Configuration
- Upload a printing process sheet and imposition sheet for this category, and check whether the dialogue component can correctly extract exclusive fields such as version number and CMYK color values.
- Launch a multi-turn dialogue, sequentially ask about version verification, ink batch matching, and barcode readability requirements, and check whether the context can retain historical dialogue parameters and requirements.
- Trigger the exception report drafting process, and check whether it can automatically link the current order's first-piece sample approval data and printing press operation parameters.
- View the `chatId` identifier of the session, confirm that all dialogues for the same order are bound to the same session ID, to avoid cross-order data confusion.

The values provided are common starting points and should be measured against the reader's own samples.
