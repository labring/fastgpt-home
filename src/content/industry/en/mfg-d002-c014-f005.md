# Drafting Process Documents and Exception Reports for Dyeing and Finishing: Tool Calling and Plugins

## What data for this category looks like
Data for this category comes from customer color samples, formula libraries, dye chemical batch records, dye vat control systems, colorimeters, setting machines, and environmental monitoring equipment. Daily documents include dyeing formulas, chemical weighing records, dye vat temperature curves, proofing confirmation sheets, color difference reports, setting process sheets, and sewage ledgers. Data is updated per vat, batch, or shift. Single-batch data includes batch numbers, dye chemical parameters, process curves, test values, and emission indicators. Field units include professional industrial units such as ℃, g/L, mg/L, and others.

## What constraints do these characteristics impose on the tool calling and plugins workflow
High-frequency data updates require tool calls to match production batch rhythms and avoid pulling expired data. Multi-type document structures need plugins to parse business files in different formats, including tables, curves, and text. Professional fields and units require parameter verification during tool calls to prevent unit errors or missing fields in generated content. Severe error risks require configuring failure retry and exception reporting logic, so abnormal data triggers report generation promptly. Cross-device data sources need plugins to complete unified format conversion, ensuring consistency of generated content.

## How to set up the configuration
This configuration scheme applies to FastGPT v4.17.0.
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Automatically matches tool calling logic related to dyeing and finishing processes |
| `functionCall` | `enabled` | Supports calling professional tools to generate process documents and exception reports |
| Tool call timeout | `600 seconds` | Adapts to the processing cycle of processes such as dye vat heating and material addition |
| Number of returns per single tool call | `Top 3` | Avoids excessive historical batch data interfering with current generation |
| Plugin data pull trigger condition | Triggered by the current production batch | Matches the data update rhythm per vat or batch, and requires connecting to production equipment data sources via the MCP toolset |
| Abnormal result verification threshold | Calibrated based on actual measurements | Adapts to qualification standards for color difference, emissions, and other metrics across different orders |

## Three common mistakes
- Issue: The process document returned by the tool lacks the dye chemical batch field. Cause: The plugin was not configured to pull data sources from the dye chemical batch library, resulting in missing core business fields in generated content.
- Issue: A timeout error occurs after calling the tool. Cause: The set timeout period is shorter than the actual processing cycle of the dye vat process, making it impossible to complete full parameter pulling and calculation.
- Issue: The tool cannot pull real-time data from the dye vat equipment. Cause: The locally running MCP service was not correctly added to the toolset, resulting in data source connection failure.

## How to confirm the configuration is complete
- Trigger a test call simulating single-vat production, and check that the returned process document includes core document fields such as dyeing formulas and chemical weighing records.
- View the tool call log to confirm that the configurations for `functionCall` and `toolChoice` are correctly applied.
- Simulate a scenario where color difference exceeds standards, and check whether the exception report generation logic is triggered.
- Check the connection status of the MCP toolset to confirm that production equipment data can be pulled normally.

The values given are common starting points and should be measured against the reader's own samples.
