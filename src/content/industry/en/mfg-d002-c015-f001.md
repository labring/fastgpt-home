# Drafting Process Documents and Abnormal Reports for Active Pharmaceutical Ingredient and Pharmaceutical Intermediate Production: HTTP Interfaces and External Systems

## What data belongs to this category
This category of data is sourced from registered process documents, raw material batch ledgers, DCS control systems, weighing systems, LIMS laboratory information management systems, chromatography data systems, and QMS quality management systems. Data is updated for each production batch and each process step. Core documents include batch production records, material balance sheets, reaction and purification records, cleaning validation records, impurity profile reports, deviation and change documents. Data fields include batch numbers, reaction temperatures, yield ratios, impurity contents, solvent residue levels, and parameters for intermediates linked to multi-step chemical synthesis routes.

## What constraints these characteristics impose on HTTP interfaces and external systems
Multiple heterogeneous data sources require interfaces to support standardized data formats from different systems. Cross-system permission verification must be completed via the `Authorization` parameter. Updates occur per batch and per step, so interface calls must align with production batch trigger points to avoid redundant requests or data lag. Complex document structures and multiple field attributes require interface requests to carry precise parameters such as batch numbers, reaction steps, and impurity types to ensure correct data association. Large-volume impurity profile reports and batch records require interfaces to support chunked transfer and resumable upload capabilities.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum data per single request | 1000 MB | Matches the average volume of single-batch process documents to avoid transfer timeouts |
| Chunked transfer threshold | 500 MB | Enables chunked transfer when a single document exceeds this size, adapting to the large-volume nature of impurity profile reports |
| `Authorization` | Use enterprise internal OAuth2.0 verification | Complies with pharmaceutical industry data control requirements and FastGPT v4.17.0 interface specifications to ensure compliant interface access |
| `variables` | Bind core fields such as batch numbers and reaction steps | Accurately matches exclusive data for each production batch to avoid data confusion |
| `responseData` | Filter core fields such as yield, impurity content, and solvent residue | Reduces invalid data transfer and improves interface response speed |
| Timeout period | 600 seconds | Adapts to the pull and parsing duration of complex process data to avoid mid-transfer interruptions |

## Three common mistakes
- Symptom: Interface calls return format error prompts, and data synchronization with external systems cannot be completed. Cause: The FastGPT interface parameter specifications were not correctly adapted, and non-standard formats were used to initiate requests, causing the system to fail to parse request content.
- Symptom: After calling the interface, the knowledge base chunks do not add corresponding process data, and the returned result fields are empty. Cause: Core associated fields such as batch numbers and reaction steps were not bound via `variables`, causing the system to fail to match exclusive document data for the corresponding production batch.
- Symptom: After using the API to upload a PDF-format impurity profile report, the parsing result does not extract pharmaceutical professional fields such as impurity content and solvent residue. Cause: PDF enhanced parsing configuration was not enabled, and targeted processing was not performed for the professional structure of pharmaceutical documents, leading to loss of core business data.

## How to confirm configurations are correct
- Initiate a simulated interface request carrying `variables` parameters with a known batch number, and check if `responseData` returns core process fields for the corresponding batch.
- View interface logs to confirm that the `Authorization` parameter has passed enterprise internal permission verification, with no `401 Unauthorized` type errors.
- Upload a test impurity profile PDF document, and check if the knowledge base chunks include parsed professional fields after calling the interface.
- Adjust the single request data volume above the chunked transfer threshold, and confirm that the interface automatically enables chunked transfer with no transfer interruption errors.

The values provided are common starting points and should be measured against the reader's own samples.
