# Drafting Process Documents and Abnormal Reports for Transformer and High-Voltage Electrical Manufacturing: HTTP Interfaces and External Systems

## What Data for This Category Includes
Data for this category comes from design BOMs, silicon steel sheet and insulating material inventory data, vacuum drying equipment, oil test reports, and high-voltage test records from testing stations. Daily generated documents include winding and core assembly records, vacuum drying records, insulating oil test reports, partial discharge and withstand voltage test reports, and nameplate parameter tables.
Data is updated per single product or batch of raw materials. Detection and assembly data from each production stage must be synchronized in real time to process and abnormal report workflows. Fields include insulation distance parameters, moisture content test values, test voltage levels, and most units are millimeters, percent, and kilovolts.

## What Constraints These Characteristics Impose on HTTP Interfaces and External Systems
The multi-source, decentralized data sources for this category require HTTP interfaces to support data pulling and integration across devices and systems. Full workflow data for a single product must be bound to a unique code. Interface requests must include this code to associate complete process chain information.
The high-frequency update rhythm for single products or batches requires interface response times to match the wait thresholds of production stages. Special fields such as insulation distance and partial discharge values require predefined mapping rules for units and formats in interface configurations to avoid data parsing errors.

## How to Set Configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {Production System API Key}` | Test and assembly data for this category is production-sensitive information. Standard Bearer token authentication must be used to prevent unauthorized access |
| `variables` | `{"deviceCode": "${external.deviceId}", "testCategory": "highVoltageWithstand"}` | Bind the unique code of a single product and the corresponding test type to match the single product/batch data update rules |
| `responseData` | `{"insulationDistance": "mm", "moistureContent": "%", "partialDischarge": "pC"}` | Standardize units for fields returned by the interface to match the format requirements for special parameters of this category |
| Interface Timeout | `600 seconds` | Match production cycles of time-consuming stages such as high-voltage tests to prevent data synchronization interruptions from timeouts |
| Request Retry Count | `First 3 attempts` | Address interface call failures caused by workshop network fluctuations to ensure data synchronization success rates |

## Three Common Misconfiguration Scenarios
- Scenario: Abnormal report data is not written to the process database when the client disconnects after calling an HTTP interface. Cause: Persistent callback logic for the interface is not configured. Data is only written after the request completes, resulting in lost data from interrupted transfers.
- Scenario: The insulating oil moisture content field returned by the interface is empty. Cause: No field mapping for the corresponding data source is configured in `variables`, so raw data from external systems cannot be parsed correctly.
- Scenario: A 401 status code is returned after calling the interface. Cause: The `Authorization` parameter is not set correctly, and an expired or unauthorized API key is used.

## How to Confirm Proper Configuration
- Initiate a simulated interface request for a single transformer, and verify that the units of fields returned in `responseData` match the special parameter format requirements for this category.
- Check that the `Authorization` parameter carries valid authentication information. Simulate an unauthorized request to confirm that the returned status code matches expectations.
- Simulate a workshop network fluctuation scenario to verify that the request retry logic triggers, and confirm that the data synchronization success rate meets requirements.
- Initiate a request with a unique device code bound, and verify that the data returned by the interface is associated with the process records for the corresponding single product.

The values provided here are common starting points and should be evaluated against the reader's own samples.
