# Drafting Process Documents and Exception Reports for Transformer and High-Voltage Electrical Equipment Manufacturing: Workflow Orchestration

## What the Data for This Category Looks Like
Data for this category comes from design BOM, silicon steel sheet and insulating material inventory data, vacuum drying equipment logs, insulating oil test reports, and partial discharge and withstand voltage test records from high-voltage test stations. Documents include winding and core assembly records, vacuum drying records, insulating oil test reports, partial discharge and withstand voltage test reports, and product nameplate parameter tables.
Data is updated per individual product and per batch of raw materials. Fields include rated voltage, insulation distance, water content, partial discharge peak value, and others. Units include kV, mm, ppm, pC.

## What Constraints These Characteristics Impose on Workflow Orchestration
Data for this category is scattered across multiple sources, covering all process nodes from design, production to testing. Workflow orchestration must connect to multiple heterogeneous data sources.
Each individual product’s data is unique. The workflow must bind the product’s unique identifier to enable full-chain data traceability.
Document fields include specific metering parameters. Workflow variables must strictly match the corresponding field names and units.
High-voltage test abnormalities can cause serious production and safety consequences. The workflow must be configured with exception trigger branches, automatically generate exception reports, and route them to the review link.

## How to Set the Configuration
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Include product ID, insulating oil water content threshold (20ppm), partial discharge abnormality threshold (10pC) | Matches the core fields and validation rules of documents for this category |
| Trigger Node | Trigger upon completion of product batch upload | Matches the update rhythm of each batch of raw materials |
| `nodeId` | Bind the node ID for obtaining high-voltage test data | Accurately connect to partial discharge and withstand voltage test data sources from test stations |
| Timeout Setting | 600 seconds | Adapts to the collection duration of high-voltage test data |
| File Upload Parameters | Support multi-type document upload, upper limit calibrated through actual testing | Covers multiple document formats including insulating oil reports, assembly records, and others |
| Exception Branch Configuration | Trigger when the partial discharge value exceeds the threshold | Corresponds to high-risk error scenarios for this category |

## Three Common Mistakes
- The workflow runs normally on the run preview page, but has no output on the chat page. The cause is that the workflow is not configured with permission binding for shared nodes, or the product identification parameters required for the chat session are not passed in `variables`.
- When configuring the form-data type HTTP request in the workflow, the test report file cannot be sent correctly. The cause is that the file parameter is not bound to the document node within the workflow, or the MIME format matching the document type is not specified.
- An error prompt Load file error appears when uploading process documents. The cause is that the workflow node does not adapt to the formats of insulating oil reports and withstand voltage test reports, or the file size exceeds the limit configured for the node.

## How to Confirm the Configuration Is Correct
- Open the run preview page of the workflow, pass in the preset product ID and test data, and verify whether each node executes in the preset order.
- Configure the form-data type HTTP request node, upload a small insulating oil report file, and verify whether the request can be sent normally and return the expected result.
- Trigger the exception branch, enter a partial discharge value exceeding the threshold, and verify whether it automatically jumps to the exception report generation node.
- View the workflow log panel, confirm that the parameters in `variables` have been correctly passed to each associated node.

The values provided are common starting points and should be measured against the reader's own samples.
