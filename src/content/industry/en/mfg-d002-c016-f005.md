# Process Document and Abnormal Report Drafting for Transformer and High-Voltage Electrical Manufacturing: Tool Calling and Plugins

## What data looks like for this category
Daily documents for this category include winding and core assembly records, vacuum drying records, insulating oil reports, partial discharge and withstand voltage test reports, and nameplate parameter tables.
Data sources cover design BOM, silicon steel sheet and insulating material procurement data, vacuum and drying equipment operation data, oil test reports, and high-voltage test data from test stations.
Data updates follow the rhythm of single products or batches of materials. Each document includes professional fields such as insulation moisture content, partial discharge value, withstand voltage value, and tap position. Units include ppm, pC, kV, and others. Full-process data traceability for single products is required.

## What constraints do these characteristics impose on tool calling and plugins workflows
Data sources for this category are scattered and specialized. Tool calling must connect to multiple heterogeneous data source interfaces, including equipment sensor data and test station APIs.
Full-process traceability for single products requires binding a unique product identifier during tool calling to avoid data confusion. The accuracy of professional fields directly affects product quality. Tool calling must accurately extract corresponding fields and verify their formats.
The high-frequency update feature requires tool calling to support real-time pulling of the latest data. Expired caches should not be relied on.

## How to set configurations
These configurations are formulated based on FastGPT v4.17.0.

| Workflow/API tool selection | `auto` | Automatically match tools required for transformer process document drafting, and adapt to multi-source data calling needs |
| Workflow/API function-call configuration | `enabled` | Force tool calling to ensure that corresponding test data interfaces are called when generating process documents and abnormal reports |
| Tool call timeout | 600 seconds | High-voltage test data pulling and insulating oil report parsing usually require long processing times |
| Number of multi-source data pulled | First 5 entries | Associated data volume for a single transformer is limited, avoiding redundant information interfering with generation |
| Tool result verification switch | Enabled | Verify the legality of insulation parameters and test data to avoid serious quality risks |

## Three common errors
- When calling a third-party large model, the response returns `{"object":"error","message":"Only allowed now"}`. The cause is that third-party model calling permissions are not enabled in the system configuration. Only platform built-in models are permitted.
- When calling HTTP tools, parameter parsing completes normally, but the tool does not execute. Empty results or abnormal status codes are returned. The cause is that request header authentication information for the tool is not configured, or the request address does not match the access permissions of the enterprise internal interface.
- The generated abnormal report lacks insulation parameter fields or uses incorrect units. The cause is that the tool result verification switch is not enabled, and format verification is not performed on extracted test data.

## How to confirm the configuration is complete
- Initiate a simulated process document generation request for a single transformer. Verify whether the tool call log pulls corresponding design BOM and test station data.
- Trigger a partial discharge abnormal report generation request. Check whether the tool call result includes required fields such as insulation moisture content and partial discharge value.
- Test calling a third-party large model. Confirm that no permission-related error messages are returned.
- Simulate inputting incorrect test parameters. Check whether tool result verification interception is triggered.
