# Spraying and Coating: Drafting Process Documents and Exception Reports, HTTP Interfaces and External Systems

## What data for this category looks like
Data sources for this category include coating supplier TDS/SDS documents, real-time collected data from spray booths and ovens, test results from colorimeters and film thickness gauges, workshop environmental monitoring data, and MES system records. Daily documents include coating process cards, coating batch lists, paint mixing records, film thickness and color difference reports, oven curves, defect repair sheets, and VOCs ledgers. Data update cadence follows batch list updates for each coating batch, generation of paint mixing and process execution records per shift, and continuous collection of key test data. Fields include coating batch number, film thickness μm value, color difference ΔE, oven temperature, VOCs concentration, and other relevant items.

## What constraints these characteristics impose on the "HTTP interfaces and external systems" link
Multi-source data sources for this category require interfaces to support integration with different types of external systems, and compatibility with pull formats for TDS/SDS files, equipment test data, and MES system data. The high-frequency update cadence requires interface call intervals to align with batch, shift, and continuous collection rhythms to avoid data lag. Specific units and exclusive naming for document fields mean interface parameters must strictly match the format of fields such as coating batch number and film thickness μm value. The severity of potential exception consequences requires interfaces to be configured with failure retry and alert mechanisms to prevent interruptions to process document and exception report generation.

## How to configure settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Fixed Bearer plus the API key assigned by the platform | Used to verify access permissions for external systems, complies with FastGPT v4.17.0 interface security specifications |
| `variables` | Includes fields for coating batch number, film thickness test value, and oven temperature | Matches exclusive data fields for spraying scenarios to avoid parameter mismatches |
| `responseData` | Extracts fields for coating process card content, exception defect type, and rectification suggestions | Corresponds to core output content for spraying scenarios, covering business document requirements |
| Interface call timeout | 30–60 seconds | Adapts to transmission delays for coating equipment data, preventing call interruptions from network fluctuations |
| Retry count | 2 times | Addresses temporary transmission fluctuations for equipment data, ensuring stability of data pulling |
| Data pull frequency | Once every 10–15 minutes | Aligns with update cadences for shift-level process updates and continuous test data |

## Three common mistakes
- Phenomenon: The interface returns a `401 Unauthorized` status code. Cause: The `Authorization` parameter is not configured correctly, or the key format or permission scope does not meet requirements.
- Phenomenon: The `responseData` field returned by the interface is empty. Cause: Exclusive fields for spraying scenarios are not matched, general document fields are incorrectly extracted, and core content for coating processes and exception reports is not covered.
- Phenomenon: Pre-created process knowledge base content cannot be retrieved via external interfaces. Cause: An exclusive coating knowledge base is not bound in the interface configuration, resulting in inability to access preset process reference data.

## How to confirm proper configuration
- Call the test interface to check if the `Authorization` parameter passes permission verification and returns normal business responses.
- Verify that the `variables` field returned by the interface includes exclusive spraying scenario fields such as coating batch number and film thickness value, matching preset parameters.
- Confirm that the `responseData` field includes content such as coating process cards and exception defect types, complying with business document structure requirements.
- Simulate consecutive interface calls to confirm that timeout and retry mechanisms trigger normally, with no frequent abnormal error reports.
