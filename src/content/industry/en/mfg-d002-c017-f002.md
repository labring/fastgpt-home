# Spraying and Coating Process Document and Exception Report Drafting: Vector Models and Indexes

## What data for this category includes
This category covers production and compliance records from coating lines for automobiles, home appliances, construction machinery, and similar use cases. Daily documents include coating process cards, paint batch sheets, paint mixing records, film thickness and color difference reports, oven curves, defect repair orders, and VOCs ledgers. Data sources include TDS/SDS documents from paint suppliers, real-time collected data from spray booths and ovens, colorimeters, film thickness gauges, environmental monitoring equipment, and MES systems. Updates occur per paint batch, per production shift, and for continuous time-series collection. Document structures include fixed parameter sections and dynamic time-series data. Fields include oven temperature (℃), film thickness (μm), VOCs concentration (mg/m³), color difference ΔE value, and other items with specialized units.

## Constraints on vector models and indexes
The high-frequency updates and multi-source data characteristics of the coating category require indexes to support incremental updates to adapt to real-time production data. Long time-series documents such as oven curves and continuously collected spray booth data generate extremely long text blocks, which requires alignment with the input length limits of vector models. Precise matching of specialized terminology such as "sagging", "orange peel", and "VOCs control thresholds" requires vector encoding to adapt to semantic features in industrial scenarios. Massive data collected in parallel by multiple devices requires adjustments to index recall rules to cover enough relevant documents. Precise matching of compliance ledgers such as VOCs records requires similarity thresholds to meet the precision requirements of industrial scenarios.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the effective information length of single sections in documents such as coating process cards and oven curves, and avoids truncating core process parameters |
| Chunk Overlap Length | 100–200 characters | Prevents specialized terms such as "sagging defects" and "film thickness deviation" from being truncated during chunking, and improves the completeness of vector matching |
| `maxToken` | 1024 token | Complies with the input limits of industry-standard vector models, and adapts to the text length of chunks split from long documents |
| Similarity Threshold | 0.75–0.85 | Matches the specialized semantics of coating defect descriptions and process parameters, and balances recall precision and coverage |
| Single Search Limit | Top 8 results | Covers the multi-parameter association requirements of coating processes, and avoids missing key process window information |
| `defaultToken` | 512 token | Adapts to the context filling requirements during exception report drafting, and ensures the coherence of generated content |

## Three common configuration mistakes
- Issue: When uploading coating documents larger than 10MB, some chunks fail during vectorization, and repeated retries do not produce error prompts. Cause: No reasonable chunk overlap length is set, leading to truncation of specialized terms, which triggers a vector model input format verification failure.
- Issue: After locally deploying ollama on an Ubuntu system and restarting the server, unfinished index tasks become stuck and unresponsive, and the knowledge base remains unavailable. Cause: No automatic index recovery rules are configured, so unfinished chunking and vectorization processes are not automatically resumed after restart.
- Issue: When initiating an exception report drafting query, the number of returned results does not match expectations, and a token limit exceeded error appears. Cause: Chunk length is not adjusted according to the `maxToken` limit, causing chunked text to exceed the token limit supported by the model.

## How to verify successful configuration
- Use FastGPT v4.17.0 to upload a standard coating process card, check that the chunked list has no abnormal markers, and that chunk lengths fall within the preset range.
- Initiate a "oven temperature matching" query, verify that the number of returned results matches the single search limit setting.
- Upload long time-series documents such as oven curves, confirm that no token limit exceeded errors occur, and that the chunk overlap length takes effect.
- Restart the server, check whether unfinished index tasks are automatically recovered and progressing.
