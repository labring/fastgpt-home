# Drafting Process Documents and Exception Reports for Spraying and Coating: Tool Calling and Plugins

## What the data for this category looks like
Data sources for spraying and coating scenarios include coating supplier TDS/SDS, real-time data from spray booths and ovens, data collected by colorimeters and film thickness gauges, and MES system work order data. The update frequency is per coating batch, per shift, and continuous collection. Daily documents include coating process cards, coating batch sheets, paint mixing records, film thickness and color difference reports, oven curves, defect repair sheets, and VOCs ledgers. Fields include coating viscosity (Ford Cup seconds), film thickness (micrometers), oven temperature (degrees Celsius), workpiece model, batch number, and other related fields.

## What constraints these characteristics impose on tool calling and plugins
Multi-source, real-time data requires tool calls to connect to multiple data source plugins. This prevents timeouts caused by loading excessive historical data in a single call. Many document fields have industry-specific units. Tool call parameters must match the corresponding field formats, otherwise parameter validation errors will occur. The data volume per batch or per shift is limited. Limit the number of entries returned by a single tool call to avoid context overload. The association logic between exception reports and process documents is complex. Tool calls must accurately match historical data, otherwise analysis results will deviate.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports automatic tool selection for multi-source process and exception data |
| `functionCall` | Calibrated based on actual measurements | Matches the field structure of coating process cards and defect repair sheets |
| Number of entries returned per tool call | Top 3 | Matches the limited field volume of single-batch coating data |
| Tool call timeout period | 60–90 seconds | Matches the collection delay of oven curves and film thickness data |
| Context window length | 1000–1500 characters | Matches the text volume of single-shift coating records |
| Tool call retry count | 2 times | Addresses temporary communication exceptions for colorimeters and film thickness gauges |

## Three Common Configuration Mistakes
- A 400 error is returned when calling the MCP service connected to spray booth data. The log shows `InternalError.Algo.InvalidParameter: Range of i`. The cause is failure to match tool call parameters to the field range of coating data. For example, failing to specify the unit of viscosity test as Ford Cup seconds.
- After the large model calls the tool, empty exception report fields are returned. The cause is failure to configure the `functionCall` output format to align with the fields of the coating defect repair sheet, resulting in tool return data that cannot be parsed correctly.
- Tool calls cannot be triggered when configuring the Gemini model. The cause is failure to correctly set `toolChoice` to `auto`, or failure to bind tool definitions matching the coating process scenario to the model.

## How to Verify a Successful Configuration
- Upload a single batch of coating batch sheet and paint mixing records, trigger a tool call, and check whether the FastGPT v4.17.0 tool call logs contain matching fields.
- Simulate a temporary interruption scenario for colorimeter data, trigger a tool call, and check whether retry actions are performed according to the configured retry count.
- Manually set the data collection delay to exceed 90 seconds, trigger a tool call, and confirm whether the timeout processing logic is triggered.
- Switch between different models that support tool calls, and confirm that tool calls can all be triggered normally and return coating-related data.

The values listed here are common starting points and should be evaluated against samples relevant to the specific use case.
