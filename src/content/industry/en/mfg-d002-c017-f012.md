# Coating and Painting Process Document and Exception Report Drafting: Deployment and Upgrade

## What data for this category looks like
Data sources for this category include coating supplier TDS/SDS documents, real-time collected data from spray booths and ovens, test results from colorimeters and film thickness gauges, environmental monitoring data, and MES system records. Daily generated documents include coating process cards, coating batch lists, paint mixing records, film thickness and color difference reports, oven curves, defect repair orders, and VOCs logs. Fields include film thickness values, color difference ΔE values, oven temperatures, coating viscosity, and other metrics. Update frequencies are per coating batch, per work shift, and continuous real-time collection.

## What constraints these characteristics impose during deployment and upgrade
Multi-source heterogeneous data access requires reserving storage and parsing configurations compatible with unstructured documents and structured time-series data during deployment, to avoid data format mismatch issues. Frequently updated data such as coating batches and per-shift paint mixing records generates high volumes of read and write requests. The deployed storage service must have sufficient concurrent processing capacity to prevent data backlog or write failures. Coating-related documents include professional test parameters. Corresponding field extraction rules must be configured during deployment to ensure accurate association of business data when drafting process documents and exception reports. VOCs logs involve compliance data. Data permissions and audit configurations must be updated synchronously during upgrades to ensure data storage security and traceability.

## How to configure these settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 1000–1500 connections | Adapts to the upper limit of associated queries for multi-source documents and real-time data in coating scenarios, preventing database connection pool exhaustion |
| `MONGODB_URI` | Points to the replica set address storing oven curves and defect repair orders | Coating scenarios require storage of large volumes of time-series test data; replica set architecture ensures data high availability and disaster recovery capabilities |
| `REDIS_URL` | Configured as a local cache instance with 2048 MB of memory allocation | Caches frequently accessed coating TDS/SDS documents and process cards, reducing read/write load on the backend database |
| `STORAGE_S3_ENDPOINT` | Bound to the access address of the enterprise’s internal object storage | Stores large batches of coating test reports and VOCs logs, meeting large-file storage and bulk download requirements |
| `FILE_TOKEN_KEY` | 32-bit randomly generated string | Ensures the security of download tokens for documents such as coating test reports, preventing unauthorized access |
| `FE_DOMAIN` | Enter the public or internal domain name of the deployment node | Ensures normal access to the frontend page, avoiding frontend resource path errors after container restarts |

## Three common errors
- Containers restart continuously and the frontend cannot load pages. The cause is incorrect configuration of the `FE_DOMAIN` parameter, leading to a mismatch between frontend resource paths and backend service addresses, which triggers cross-origin or routing errors.
- Unable to set usage duration and request count limits for non-commercial version API keys. The cause is using a FastGPT version lower than v4.17.0; this function was officially added in v4.17.0 and later versions.
- Imported coating TDS files cannot correctly extract professional parameters. The cause is missing corresponding document parsing rules, resulting in failure to accurately identify structured fields, which affects the accuracy of process document drafting.

## How to confirm successful configuration
- Access the configured `FE_DOMAIN` address, verify that the frontend page loads normally and there are no resource loading failure prompts.
- Log in to the FastGPT backend storage management page, check that the services pointed to by `MONGODB_URI` and `REDIS_URL` both show normal connection status.
- Upload a sample coating process card document, verify that the system can correctly extract professional parameters such as film thickness and oven temperature, and generate formatted draft fragments.
- Enter the API key management page, confirm that you can configure usage duration and request count limits for keys, and verify that the function is enabled normally.

The values provided here are common starting points and should be evaluated against the user’s own samples.
