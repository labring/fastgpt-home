# Drafting Process Documents and Exception Reports for Continuous Basic Chemical Production: HTTP Interfaces and External Systems

## What the Data for This Category Looks Like
Data sources for continuous basic chemical production include DCS/SIS systems, online analyzers, LIMS laboratory management systems, equipment condition monitoring modules, energy metering systems, and raw material tank level monitoring modules.
Data update frequencies fall into three categories: real-time (reaction parameters, interlock alarms), shift-based (shift reports, special work permits), and daily (laboratory reports, energy consumption statistics).
Daily documents cover operating procedures, process index cards, DCS trend curves, laboratory reports, interlock bypass records, special work permit tickets, and production shift reports.
Fields include reactor temperature (℃), system pressure (MPa), material feed flow rate (m³/h), interlock trigger thresholds, and other parameters, with clearly defined chemical industry standard units.

## What Constraints These Characteristics Impose on HTTP Interface and External System Integration
The data characteristics of this category impose multiple constraints on HTTP interface and external system integration.
Multi-source real-time data requires interfaces to support high-frequency calls. Data delays must be avoided to prevent disruption of exception report generation.
Different update frequency data requires tailored request strategies. Use short polling for real-time parameters. Use scheduled triggers for daily summary documents.
Heterogeneous daily document formats require interfaces to support flexible request body structures. This adapts to return content from different external system types.
Chemical data involves hazardous medium control. Interface authentication and data transmission encryption must comply with industry safety specifications.
Field units and business scope must also be verified. This prevents invalid data from entering the process document generation workflow.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Interface Authentication Method | Use Bearer Token in the `Authorization` header, rotate the secret key every 7 days | Basic chemical production data involves hazardous medium control, requiring strict authentication and regular key rotation to prevent leaks |
| Request Timeout | 30–60 seconds | Covers the standard response duration for DCS data pulling and LIMS report queries |
| Data Format Validation Rules | Validate field units and business scope | Matches the fixed field formats of process index cards and DCS trends, preventing invalid data from being stored |
| Batch Request Batch Size | 10–20 entries | Adapts to shift-based shift report and exception record batch submission scenarios |
| Response Data Processing | Map the `responseData` field to local document fields | Unifies heterogeneous data formats returned by external systems, adapting to process document generation logic |
| Variable Parameter Configuration | Pass reactor numbers and material types via `variables` | Adapts to differentiated document generation requirements for different production units |

## Three Common Misconfigurations
- An interface returns a 401 Unauthorized status code. Incorrect configuration of the `Authorization` header, or failure to regularly rotate the authentication secret key, causes the external system to reject data transmission requests.
- Request timeouts occur during batch submission of exception reports. Setting the batch request size too large exceeds the interface's carrying capacity. This also fails to match the real-time data pulling rhythm of continuous basic chemical production.
- Key fields in generated process documents are empty. Failing to validate the `responseData` field mapping relationship, or failing to match the fixed field names in LIMS laboratory reports, prevents correct extraction of external data.

## How to Confirm Configuration Is Successful
- Call the configured interface with correct authentication information, and check if the returned HTTP status code matches expectations
- Submit simulated shift report test data, and check if the `responseData` field can be correctly extracted and mapped to the local document template
- Configure the `variables` parameter to pass a test reactor number, and verify if the generated process document includes parameters for the corresponding production unit
- Trigger a simulated exception event, and check if the external system can normally receive callback notifications
