# Drafting Process Documents and Exception Reports for Continuous Basic Chemical Production: Source Citation and Traceability

## What this category of data looks like
This category of data includes daily production documents and real-time monitoring data from basic chemical enterprises such as chlor-alkali, synthetic ammonia, methanol, and soda ash. Daily documents include operating procedures, process index cards, DCS trend charts, laboratory reports, interlock bypass records, special work permits, and shift logs. Data sources include DCS/SIS systems, online analyzers, LIMS systems, equipment condition monitoring devices, energy metering systems, and raw material tank sensors. Update frequencies cover real-time, per-shift, and daily. Document fields include timestamps, process parameter values, control thresholds, and work approval statuses. Parameter units use mostly industrial standard units such as MPa, ℃, t/h, m³.

## What constraints do these characteristics impose on the source citation and traceability link?
Multi-source heterogeneous data sources and differentiated update rhythms require the citation traceability link to distinguish recall priorities for different data types, giving priority to matching DCS/SIS data and shift logs with high real-time requirements. Diverse document structures and unit systems require automatic identification of parameter units during the recall phase to avoid invalid cross-unit matching. Real-time updated monitoring data and static work permit documents require a layered indexing strategy to adapt to citation needs for high-frequency queries and low-frequency archiving respectively. Documents related to strong interlock control require traceability results to be associated with precise time intervals, ensuring that citations in exception reports can be traced back to specific process periods and avoid associating process data from incorrect periods.

## How to configure the settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapt to the length of basic chemical process parameters and exception descriptions, avoid truncating critical interlock alarms or process fluctuation information |
| Number of recalled entries | Top 6 | Cover core documents such as shift DCS trends, laboratory reports, and shift logs, avoid redundant display |
| `responseData` | Include source document path, timestamp, parameter unit | Meet the format requirements for traceability information in exception reports, facilitate process personnel to verify the citation rationality |
| Chunk overlap rate | 15% | Balance the completeness of shard recall for real-time DCS data and the retrieval efficiency of static work permits |
| `detail` | Enabled | Display core parameter snippets of source documents to help confirm the accuracy of citations |

## Three common configuration mistakes
- Phenomenon: Empty citation fields with no associated source documents appear in generated exception reports. Cause: Required fields of the `responseData` parameter are not configured, leading to failure to correctly extract traceability information.
- Phenomenon: Citation sources are displayed repeatedly when querying data from the same process period in multi-turn interactions. Cause: No reasonable recall quantity threshold is set, leading to repeated recall of DCS trend data from the same period.
- Phenomenon: The parameter units cited in generated process documents do not match those in the source documents. Cause: The unit verification logic of the `detail` parameter is not enabled, leading to accidental recall of cross-unit parameter matches.

## How to verify correct configuration
- Submit an exception description containing specific process parameters, check whether the generated result includes the source document path and timestamp information.
- Trigger multi-turn interactions to query process data from the same period, confirm that citation sources are not displayed repeatedly and cover all relevant documents.
- View the generated process documents, confirm that the parameter units match the labels in the source documents, with no cross-unit incorrect matches.
- Log in to the FastGPT v4.17.0 backend configuration panel, confirm that the values of `quoteMaxToken`, `responseData`, and `detail` parameters match the preset configurations.

The values provided here are common starting points and should be measured against the reader's own samples.
