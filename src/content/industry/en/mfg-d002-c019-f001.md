# Drafting Process Documents and Exception Reports for Plastic Injection Molding: HTTP Interfaces and External Systems

## What this category of data looks like
Daily documents for this category include injection molding process cards, raw material drying records, mold histories, first-piece inspections, patrol inspection forms, and material change and machine cleaning records. Data is sourced from resin batch property sheets, injection molding machine operating parameters, mold temperature controller data, workshop MES systems, and dimensional and appearance inspection equipment. Data update frequency aligns with each production batch, each mold or material change, and the end of each shift. Document fields include specific unit parameters: drying temperature in degrees Celsius, filling pressure in megapascals, cooling time in seconds. Exception reports must associate batch numbers, mold numbers, and defect types.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
Data sources cover multiple types of workshop equipment and systems. Interfaces must support pulling and integrating data from multiple sources. High-frequency update business scenarios require interfaces to have low latency. This prevents data lag from affecting the generation of process documents and exception reports. Specific units and business association logic for document fields require request parameters to match corresponding field names and formats. Exception reports must associate data such as mold histories and resin batches. Interfaces must support queries based on conditions like batch numbers and mold numbers.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {workshop system API key}` | Complies with HTTP interface authentication standards, adapts to the identity verification rules of injection molding workshop systems. Can be directly configured as a request header in the FastGPT v4.17.0 HTTP node. |
| `variables` | `{"batchNo": "PXXXXXXXXX", "moldId": "M001", "defectType": "short shot"}` | Carries business fields including injection batch number, mold number, and defect type. Matches the query conditions for exception report drafting, enabling accurate data pulling. |
| Interface timeout period | `30–60 seconds` | Adapts to the latency range of injection equipment data pulling. Prevents request failures due to workshop network fluctuations. |
| `responseData` | `Extract process parameters, test results, batch association fields` | Only returns core data required for process documents and exception reports. Reduces network transmission overhead and improves generation efficiency. |
| Batch request limit | `Top 20 entries` | Matches the single submission quantity of each shift's patrol inspection form. Prevents interface overload from affecting workshop system operation. |

## Three common mistakes
- Symptom: The interface returns `401 Unauthorized`, and the returned `responseData` is empty. Cause: The `Authorization` parameter is not configured correctly. Authentication credentials required by the workshop system are not included.
- Symptom: The interface returns `504 Gateway Timeout`, and the generated exception report is missing some process parameters. Cause: The timeout period is set too short. It does not adapt to the actual latency of pulling data from injection equipment.
- Symptom: After the HTTP node returns a BLOB object, users cannot click to download in the dialog box. Cause: The correct response format is not configured. Binary streams are not converted into downloadable file links.

## How to confirm the configuration is correct
- A test call is initiated in the FastGPT v4.17.0 HTTP node. The returned `responseData` is checked for core injection molding process card parameters, such as filling pressure and holding time.
- The `Authorization` parameter format is verified against Bearer authentication rules. No spelling or format errors are present.
- A mold or material change scenario is simulated. An interface call is triggered. The update frequency of returned data is confirmed to align with requirements for each batch and each mold change.
- Automatic association of resin batch property sheets and test result data during exception report generation is verified.

All provided configuration values are common starting points. They should be evaluated against local operational samples and conditions.
