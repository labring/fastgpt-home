# Drafting Process Documents and Exception Reports for Plastic Injection Molding: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
This category’s data covers production and inspection records across the full injection molding workflow. Daily documents include injection molding process cards, raw material drying records, mold history logs, first-piece inspection forms, patrol inspection forms, and material change and machine cleaning records. Each document includes fields such as resin batch number, injection pressure, holding time, mold temperature, and raw material moisture content, with units including MPa, seconds, ℃, and others. Data sources include resin batch property sheets, real-time injection molding machine parameters, mold temperature controller data, MES systems, and dimensional and appearance inspection results. Data is updated with each production batch, each mold change or material swap, and each shift’s patrol inspection.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
This category’s data is updated frequently and linked to multi-dimensional business information. Multi-turn dialogue must limit context scope, only using valid data from the current batch and current mold change cycle to avoid mixing expired records. Document fields have clear professional units. Prompt engineering must explicitly require extracting parameter values with units, to prevent ambiguous results without units. Drafting exception reports requires linking raw material batches, mold history logs, and inspection data. Multi-turn dialogue must gradually guide users to supplement missing key information, such as confirming the raw material batch first before asking about abnormal phenomena. Additionally, due to the risk of material mixing, the dialogue flow must verify matching between input information and existing business data.

## Configuration Settings
This configuration is formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Maximum Context | Last 20 conversation history entries | Adapt to the frequently updated business data of this category, avoid context overload, ensure dialogue focuses on the current production batch |
| `variables` | Pre-set variables for resin batch, mold number, and inspection date | Automatically bind business data sources, reduce manual input errors, ensure parameters are linked to the current production link |
| `messages` | System prompt limits use of only current batch raw material drying records and injection molding machine parameters | Avoid interference from expired data, ensure accuracy of process documents and exception reports |
| Question Optimization | Calibrate based on actual measurements | Optimize standardized understanding of injection molding terminology, for example, unify descriptions of defects such as "shrinkage" and "flash" |
| `chatId` | Bind unique identifier of current production batch | Distinguish process and exception data across different batches, avoid cross-batch confusion |

## Three Common Misconfigurations
- Symptom: Unconfigured thought process fragments are included in dialogue outputs. Cause: The system prompt does not explicitly require hiding thought processes, or the agent configuration does not turn off intermediate step display.
- Symptom: The holding time field from the injection molding process card cannot be automatically extracted. Cause: The prompt does not explicitly specify extracting parameter values with units, or the process card data source is not configured in `variables`.
- Symptom: Abnormal analysis results returned by the dialogue do not match actual production data. Cause: The dialogue context is not limited to only current batch raw material and equipment data, and expired historical records are called.

## How to Verify Proper Configuration
- Initiate a test dialogue, enter "Please generate the current batch's injection molding process card", verify that the returned result includes preset business fields such as resin batch number and injection pressure parameters.
- Enter a description containing an abnormal phenomenon, such as "Flash appears on the plastic parts produced this time", verify that the dialogue prompts for necessary parameters for the corresponding production link before generating results.
- View the dialogue history record, verify that only the number of context entries that meet the configuration requirements is retained, with no redundant expired dialogue content.
- Test generating an exception report, verify that the result only links current batch raw material, equipment, and inspection data, and does not call information from other batches.

The values provided here are common starting points and should be evaluated against the user's own samples.
