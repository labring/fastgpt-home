# Process Document and Exception Report Drafting for Plastic Injection Molding: Deployment and Upgrade

## What this category’s data consists of
This category of data includes documents such as injection molding process cards, raw material drying records, mold histories, first-piece inspections, patrol inspection forms, and material change and machine cleaning records. Data sources include resin batch property sheets, injection molding machine operating parameters, mold temperature controller data, manufacturing execution systems (MES), and dimensional and appearance inspection results. Data updates are triggered with each production batch, each mold or material change, and each shift’s production cycle. Document fields include injection pressure, temperature, mold cycles, drying duration, and more. Corresponding units are megapascals, degrees Celsius, cycles, and seconds.

## What constraints do these characteristics impose on the deployment and upgrade phase?
The data characteristics of this category impose multiple constraints on the deployment and upgrade phase.
Multi-source heterogeneous data sources require configuring format-compatible access channels during deployment, to adapt to the data output formats of different systems such as injection molding machines, mold temperature controllers, and MES.
The high-frequency update rhythm requires supporting near-real-time synchronization mechanisms, to ensure that process documents and exception reports always use the latest production data.
The standardized field structure with fixed units requires presetting standardized field mapping rules, to avoid parameter matching errors during parsing.
During upgrades, it is necessary to support format changes for historical production data, to avoid interrupting the document processing flow of existing production links.

## How to set the configurations
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://injection_user:secure_pass@db-host:27017/injection_molding` | Stores unstructured historical documents such as injection molding process cards and mold histories, to meet industrial scenario document storage requirements |
| `REDIS_URL` | `redis://:redis_auth@cache-host:6379/0` | Caches frequently read raw material drying records and real-time injection molding machine parameters, to reduce load on the core database |
| `STORAGE_S3_ENDPOINT` | `https://s3-internal.manufacturing.example.com` | Stores large-capacity files such as uploaded inspection reports and material change and machine cleaning records, to adapt to industrial data storage scales |
| `DB_MAX_LINK` | `20–30 connections` | Matches the upper limit of concurrent connections for multiple devices in the injection molding workshop, to avoid data synchronization failures caused by exhausted connections |
| `ROOT_KEY` | Generated in accordance with internal enterprise security specifications | Configures platform administrator permissions, to ensure access security for production-related data |
| `PG_URL` | `postgresql://mes_user:db_pass@mes-host:5432/mes_sync_db` | Synchronizes production batch data from the MES system, to associate exception reports with specific production processes |

## Three common configuration mistakes
- A 404 status code is returned after startup, and uploaded injection molding inspection reports cannot be accessed. The cause is that `FILE_TOKEN_KEY` is not configured correctly, resulting in failed file access token verification.
- Only some patrol inspection forms can be read during production data synchronization, with remaining data failing to load. The cause is that the value of `DB_MAX_LINK` is lower than the concurrent connection count of workshop devices, resulting in partial database connections being released due to timeout.
- Corresponding batch injection molding machine parameters cannot be associated when generating exception reports. The cause is that `PG_URL` is not configured to point to the correct MES synchronization database, resulting in an unconnected data link.

## How to confirm the configuration is complete
- Access the platform address corresponding to `FE_DOMAIN`, confirm normal login and access to the process document management module.
- Upload a standard injection molding process card, confirm that preset fields such as pressure and temperature can be successfully parsed, with no parsing error prompts.
- Trigger a full data synchronization task, confirm whether the number of synchronized data entries matches the actual number of production documents.
- Submit an exception analysis request, confirm that corresponding batch injection molding machine operating parameters and inspection results can be automatically associated.

The values provided here are common starting points, and should be measured against the user’s own samples.
