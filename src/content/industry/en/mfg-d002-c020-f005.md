# Process Document and Abnormal Report Drafting for Safety, Environmental Protection and Special Work Management: Tool Calling and Plugins

## What this category of data looks like
This category of data comes from EHS departments and maintenance teams of manufacturing enterprises in chemical, metallurgical, machinery and other industries. Daily documents include risk identification records, work tickets for hot work, confined space work, lifting work and other operations, environmental monitoring records, hazardous waste ledgers, emission monitoring data, and accident and hidden danger rectification reports. Data sources cover regulatory standard libraries, online environmental monitoring systems, gas detectors, personnel qualification lists, equipment isolation lists, and supervision platforms. Data updates are triggered by individual work, synchronized in real time per monitoring requirements, or completed through regular inspections. Document structures use classified form templates, including fields such as work number, monitoring value, qualification number, and compliance requirements. Some fields have fixed units.

## What constraints these characteristics impose on tool calling and plugins
The scattered data sources and diverse formats in this category require tool calling plugins to support connection to and data extraction from multiple data source types. The real-time or work-triggered update rhythm requires plugins to support on-demand triggering, adapting to call timing for single work or real-time synchronization. The structured field requirements for form-based documents require that results returned by plugins must match preset field formats and compliance requirements, preventing unstructured data that cannot be directly filled into work tickets or abnormal reports. Additionally, this category has high compliance veto authority: the accuracy of tool calling results is directly linked to compliance risks, so legitimacy verification must be performed on data returned by plugins.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to multi-data-source calling scenarios, automatically match compliance data and monitoring results required for work |
| `functionCall` | Enable structured output | Ensure that returned abnormal reports and work ticket fields comply with preset compliance formats |
| Data source call timeout | 300 seconds | Match the data synchronization delay range of online monitoring and supervision platforms |
| Number of records returned per single interface call | First 20 records | Cover multiple types of monitoring records and qualification lists involved in a single work |
| Dynamic parameter passing | Pass according to work context | Adapt to dynamic parameter requirements such as tokens and work numbers for different work scenarios |
| Compliance field verification | Enable required field verification | Match the mandatory compliance field requirements of work tickets and abnormal reports |

This configuration is based on FastGPT v4.17.0.

## Three common misconfigurations
- Symptom: The data source plugin returns a database connection structure instead of structured data, and the log shows an `invalid output format` error. Cause: The `functionCall` configuration is not enabled, and the structured output requirement is not specified.
- Symptom: Dynamic tokens or work numbers cannot be passed in the workflow, and the interface call returns a 401 Unauthorized status code. Cause: Dynamic parameter passing according to work context is not configured, and fixed parameter values are used instead.
- Symptom: Tool calling times out, and the interface displays a 504 Request Timeout status code. Cause: The timeout parameter adapted to the delay of online monitoring platforms is not set, or the value is set too short.

## How to confirm the configuration is correct
- Trigger a simulated hot work process, and check whether the gas monitoring data returned by the plugin includes preset concentration fields and corresponding units.
- Manually pass a test work token, and confirm that the parameters carried during external interface calls match the test values.
- Simulate a scenario where compliance fields are missing, and check whether the system triggers a verification prompt.
- View the tool calling logs, and confirm that the returned result format complies with the preset work ticket template requirements.

The values provided here are common starting points and should be evaluated against the user's own samples.
