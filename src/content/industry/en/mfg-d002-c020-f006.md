# Process Document and Abnormal Report Drafting for Safety, Environmental Protection and Special Operation Management: Citation Source and Traceability

## What this category of data looks like
Typical documents for this category include risk identification lists, hot work and confined space work permits, online environmental monitoring records, hazardous waste ledgers, accident rectification reports, and more. Data sources include regulatory standard libraries, online environmental monitoring equipment, gas detectors, personnel qualification files, equipment isolation lists and supervision platforms. Update frequencies fall into three categories: work permits and risk records are updated immediately after a single operation is completed, monitoring data is refreshed in real time or daily, and compliance ledgers are updated quarterly on a regular basis. Document fields include work permit numbers, gas concentration values, hazardous waste generation volumes, regulatory feedback numbers, and other relevant fields.

## What constraints do these characteristics impose on the citation source and traceability link
Multi-source, heterogeneous data sources require traceability systems to differentiate recall priorities for static qualifications, real-time monitoring data and compliance documents. Multiple documents linked to a single operation must be accurately associated using the operation ID to prevent invalid cross-operation citations. Data with varying update frequencies must be matched to corresponding traceability verification logic to ensure the timeliness of real-time monitoring data. Since errors can result in personal safety risks and compliance penalties, traceability must guarantee the integrity and accuracy of cited content, with no key fields omitted. The traceability configuration of FastGPT v4.17.0 must accommodate these characteristics, otherwise compliance verification cannot be completed.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context | 16000–20000 token | Covers the complete context of regulatory standards, multiple work permits and monitoring reports |
| Maximum Knowledge Base Citations | Top 7 entries | Matches the total volume of qualifications, isolation and monitoring data associated with a single safety operation |
| Maximum Response Tokens | 1800–2200 characters | Meets requirements for complete explanations and traceability in abnormal report drafting |
| `quoteMaxToken` | 10000–14000 token | Limits the maximum length of a single citation to avoid interference from redundant data |
| `detail` | Enabled | Retains complete fields of citation sources, including detection time, qualification numbers and other relevant details |
| `responseData` | Includes update time and source type of cited documents | Facilitates verification of data timeliness and compliance |

## Three common misconfigurations
- Setting `quoteMaxToken` too small results in truncated cited monitoring report content, with truncation markers displayed in the interface. Full gas concentration values and detection times cannot be viewed. This occurs because the setting does not match the single-document length requirements of safety and environmental protection documents, truncating key traceability information.
- Failing to configure `responseData` to retain source document identifiers results in generated abnormal reports only displaying content. These reports cannot be linked to corresponding work permit numbers or supervision platform feedback records, making compliance verification impossible. This occurs because the citation traceability metadata output configuration is disabled.
- Failing to properly handle line break markers results in `\n` prompts being output as plain text in generated documents, preventing proper paragraph separation. This occurs because the response content format parsing switch is not enabled, treating line break instructions as ordinary text.

## How to confirm the configuration is correct
- A test query containing work permits and gas detection records is submitted, and returned cited content is checked for complete fields such as detection time and concentration values.
- Citation metadata is viewed, and confirmed to include the update time and source type of the corresponding document. This can be verified via the output field corresponding to `responseData`.
- The value of `quoteMaxToken` is adjusted, and cited content of different lengths is tested to confirm full return with no truncation markers.
- A test instruction containing line break prompts is input, and generated documents are checked to confirm line break markers are correctly parsed as paragraph separators.

The values provided here are common starting points, and should be evaluated against the reader's own samples and use cases.
