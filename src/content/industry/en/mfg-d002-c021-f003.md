# Drafting Process Documents and Exception Reports for Furniture and Wood Product Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
This category's data comes from order design systems, sheet and wood batch ledgers, CNC cutting and drilling equipment logs, ERP/MES systems, and moisture content test records. Daily documents include order disassembly drawings, cutting lists, edge banding and drilling programs, coating process specifications, hardware bill of materials, trial assembly and packaging records. Data updates are issued per individual order, daily production batch, and material batch. A single order can link to dozens of sheet part data entries, with fields including sheet part dimensions, material batch, process parameters, installation points, and more.

## What constraints these characteristics impose on the Multi-turn Dialogue and Prompt Engineering link
Customized order-driven multi-sheet part attributes require multi-turn dialogue to associate all sheet part data for a single order, to avoid missing individual pieces of information. Frequently updated sheet material batches and process parameters require the dialogue context to filter expired data, only retaining valid information for the current production batch. Precise fields such as sheet part dimensions and hole positions require prompts to clearly specify units and formats, to prevent non-standard expressions from being generated. When multiple documents are input together, the dialogue component must distinguish the field priority of different data sources such as order disassembly drawings and process documents, to ensure generated content complies with production specifications.

## How to set up the configuration
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the current production order ID | Ensure multi-turn dialogue for the same order shares context, avoiding cross-order data confusion |
| `messages` | Retain the first 10 dialogue history entries | Adapt to the context requirements of single-order sheet part data, avoiding model overload |
| `variables` | Pass the current sheet material batch and order disassembly drawing ID | Provide real-time production data for prompts, ensuring generated content matches current batch parameters |
| Maximum Context | 8000–12000 token | Calibrated based on actual testing, covers all process and exception data for a single order |
| Prompt Format Constraints | Require labeling sheet part numbers and dimension units, support space-separated multi-parameter input | Adapt to this category's requirement for precise fields, preventing non-standard expressions from being generated |

## Three common misconfigurations
- Only a small amount of context is displayed in dialogue details, making it impossible to associate historical process data. The cause is that `chatId` is not correctly bound, resulting in multi-turn dialogue context not being shared, only retaining information from the current single interaction.
- Loop processes cannot correctly judge exception report content and cannot trigger secondary generation. The cause is that judgment rules for category-specific exceptions such as sheet part dimensions and color differences are not configured in the question classification node, causing the classification logic to fail.
- Generated process documents cannot correctly recognize space-separated multi-sheet part parameters. The cause is that the prompt does not have recognition rules for space-separated fields configured, resulting in multi-sheet part information being processed as a single merged entry.

## How to confirm the configuration is correct
- Initiate the first round of dialogue, input the sheet part list for the current order, check the context list in the dialogue details, confirm that historical interactions and order-related data are included.
- Test passing the `variables` parameter, call sheet material batch information in the dialogue, verify whether the generated content matches the preset batch parameters.
- Configure the loop process, input non-standard sheet part dimension data, verify whether the secondary generation or exception report process can be triggered.
- Adjust the prompt to require generating process parameters with units, verify whether the output result includes clear dimension units and sheet part numbers.

The values provided here are common starting points and should be evaluated against the user's own samples.
