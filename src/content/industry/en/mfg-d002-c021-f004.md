# Drafting Process Documents and Exception Reports for Furniture and Wood Product Manufacturing: Workflow Orchestration

## What the data for this category looks like
Daily data for furniture and wood product manufacturing comes primarily from order design systems, sheet and lumber batch ledgers, CNC cutting and drilling equipment, ERP/MES systems, and moisture content testing equipment. Data update frequency shifts with business nodes. This includes order-specific split drawings and cutting lists generated per order, daily updated coating process parameters, and moisture content test records for each material batch. Typical documents include panel size parameters, hardware model lists, edge banding and drilling program codes, trial assembly and packaging records. Most fields relate to custom sizes, color codes, batch numbers, and moisture content values. No unified fixed BOM structure exists.

## What constraints these characteristics impose on workflow orchestration
This category is driven primarily by custom orders. The number of panels is large, and their sizes and color codes are adjusted per order to meet individual requirements. Workflows must support dynamic variable loading. Data sources are scattered and updated frequently. Workflows must automatically synchronize fields from different systems to workflow nodes, to avoid manual entry errors. Errors such as incorrect panel sizes or color code deviations directly impact installation progress. Workflows must include validation steps. Additionally, the non-standardized structure of custom orders requires workflows to adapt to associated calls across multiple document types. This differs from the mixed-line production model of standard home appliances with fixed BOMs.

## How to set up the configuration
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Global variable configuration | Bind fields from split drawings, sheet material batches, and hardware lists | Core sources of category data include order design and sheet material ledgers. Dynamic fields must be managed uniformly via the `variables` parameter |
| Node ID mapping | Bind CNC equipment nodes and ERP/MES nodes | Production data for this category comes from CNC equipment and ERP systems. Cross-system data synchronization is achieved via the `nodeId` parameter |
| Multi-knowledge base association | Associate cutting process libraries, coating process libraries, and hardware parameter libraries | Daily documents for this category cover multiple types of process files. Multiple knowledge bases must be called to cover complete business scenarios |
| Keyword extraction rules | Extract panel sizes, color codes, and moisture content values | Most errors in this category stem from incorrect field identification. Extraction logic must be configured for exclusive fields |
| Context window setting | 800–1200 characters, calibrated via actual testing | Document length related to single orders falls within this range. This balances recall accuracy and operational efficiency |

## Three common errors to avoid
- Running a workflow triggers an error that global variables are undefined. The cause is failure to correctly map fields from the order design system to the `variables` parameter.
- Workflow execution fails due to node data synchronization failure. The cause is failure to correctly configure the `nodeId` parameter to bind CNC equipment or ERP/MES nodes.
- Exception reports returned by the workflow lack color code or size fields. The cause is failure to associate the corresponding category's process knowledge base, or failure for keyword extraction rules to cover exclusive fields.

## How to confirm the configuration is complete
- Manually enter category-exclusive panel size and sheet material batch fields, check if the `variables` parameter loads and displays normally.
- Trigger the workflow, view node logs to confirm that data from CNC equipment and ERP systems bound via the `nodeId` parameter has been synchronized to the workflow.
- Submit test order data, verify that the keyword extraction function correctly identifies exclusive fields such as color codes and moisture content values.
- After associating multiple category-related knowledge bases, test if recall results cover full-process documents including cutting, coating, and hardware-related content.
