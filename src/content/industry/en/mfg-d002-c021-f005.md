# Drafting Process Documents and Exception Reports for Furniture and Wood Product Manufacturing: Tool Calling and Plugins

## What Data Looks Like for This Category
Data related to process documents and exception reports for furniture and wood product manufacturing typically comes from order design systems, sheet and wood batch ledgers, CNC cutting and drilling device logs, ERP/MES systems, and moisture content testing equipment.
Daily documents include order breakdown drawings, cutting lists, edge banding and drilling programs, coating process specifications, hardware bill of materials, trial assembly and packaging records.
Data update cadence: order-specific breakdown and cutting data is generated per order, coating process parameters are synced daily, and sheet moisture content and batch information is updated per material batch.
Document fields include board length, width and height dimensions, sheet color code and moisture content, hardware model and quantity, hole position coordinates, with units mostly millimeters, percentage, and count.

## Constraints on Tool Calling and Plugins Workflow
The mixed structured and semi-structured document types for this category require tool calling to support multiple format parsing. High-frequency data updated per order and batch requires tools to pull the latest sheet batches and device logs in real time. The custom-order driven production model leads to a large number of board parts associated with a single order, so tool calling must support batch retrieval and field matching. Additionally, the accuracy of process documents and exception reports directly impacts production delivery, so tool calling must include basic validation logic to avoid mismatched board part dimensions and color codes.

## Three Common Mistakes
- Symptom: Uploading an order breakdown drawing via the Doc2x plugin returns empty parsing results. Cause: The plugin-supported document format whitelist is not configured, so CAD-format order breakdown drawings are not included in the allowed parsing scope.
- Symptom: Submitting a query via the API does not return the list of knowledge base files associated with the current call. Cause: The knowledge base file traceability configuration is not enabled, and associated document metadata is not returned by default.
- Symptom: Streaming output suddenly stops with no subsequent content returned. Cause: The retry mechanism for `functionCall` is not configured, and no automatic retry is triggered after a single call times out, leading to workflow interruption.

## How to Verify Correct Configuration
- Upload a CAD order breakdown drawing for panel furniture, call the document parsing plugin, and verify that structured parsing results including board part dimensions and hole position coordinates are returned.
- Submit a query including "retrieve the cutting list for the current order", and verify that the returned results include the names and paths of associated knowledge base files.
- Submit a simple query of only a few words, and verify that results are streamed as expected, with no abnormal interruptions or empty returns.
- Modify the plugin format whitelist, upload a PDF process file that is not allowed, and verify that a clear error prompt indicating unsupported format is triggered.
