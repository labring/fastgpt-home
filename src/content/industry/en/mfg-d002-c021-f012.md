# Drafting Process Documents and Exception Reports for Furniture and Wood Product Manufacturing: Deployment and Upgrade

## What data for this category looks like
Business data for furniture and wood product manufacturing originates from order design systems, sheet material and wood batch ledgers, CNC cutting and drilling equipment, ERP/MES systems, and moisture content testing equipment. Update frequency aligns with business nodes. Data includes split drawings and cutting lists generated per order, daily updated coating process parameters, sheet moisture content and batch number for each material batch, and other relevant details. Daily documents cover edge banding and drilling programs, hardware lists, trial assembly and packaging records. Fields include panel size (millimeters), hardware model, coating color code, production batch, and more. No unified fixed BOM structure exists; configurations are adjusted for individual custom orders.

## Constraints during deployment and upgrade
The custom order-driven nature of this category requires deployment to support isolating process data and exception reports by order, to prevent cross-order data confusion. Dispersed data from multiple sources requires integration with multiple external systems. The deployment phase must configure stable database and cache connections to support high-frequency real-time data queries. Large-volume CNC programs and split drawing documents require sufficient storage capacity and bandwidth during deployment. Customized panel parameters and process requirements require retaining contextual associations of corresponding fields when upgrading the model, to ensure accurate exception report generation. Additionally, production errors directly impact installation and delivery; deployment must reserve audit and traceback interfaces for exception reports.

## Three common mistakes
- Symptom: After upgrading the FastGPT version, symbols tracing display rules appear at the end of model conversation response results. Cause: The prompt debugging flag switch was not disabled in the system configuration, resulting in the model output attaching built-in trace prompt content.
- Symptom: After uploading a video-format process record file, the system cannot recognize the file content. Cause: Multimodal function configuration was not enabled during deployment, or the FastGPT version used is lower than the version that supports video recognition.
- Symptom: Local deployed AIproxy returns authentication failure when calling the Gemini API. Cause: The API key and interface address were not configured correctly, or the local server did not open the corresponding port for accessing external API interfaces.

## How to confirm configurations are correctly set
- Access the frontend address configured in `FE_DOMAIN`, log in to the system, upload a split drawing, confirm that the file can be stored normally and displayed in the document list.
- Initiate an exception report generation request based on sheet material batch data, confirm that the returned result includes correct field information such as sheet moisture content and hardware model.
- Use a database connection tool to connect to the database configured in `MONGODB_URI`, verify that process file metadata and exception report records can be read and written normally.
- After upgrading to FastGPT v4.17.0, upload a video-format trial assembly record, confirm that the system can parse it normally and generate the corresponding text summary.

The values provided here are common starting points and should be measured against the reader's own samples.
