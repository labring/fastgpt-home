# Drafting Process Documents and Exception Reports for Complete Home Appliance Manufacturing: Multi-turn Dialogue and Prompt Engineering

## Data Profile for This Category
This category covers the full manufacturing lifecycle of complete home appliance units including air conditioners, refrigerators, washing machines and small household appliances. Daily documents include configured BOMs, assembly work instructions, refrigerant charging records, electrical safety test reports, performance sampling inspection reports and rework records. Data sources include ERP/MES systems, component batch ledgers, tightening and charging equipment logs, safety compliance tester data, performance laboratory test results and after-sales fault feedback. Data updates follow individual product units, shift production batches or sampling plans. Fields include component numbers, process parameter values, test results, rework reasons and additional relevant details.

## Constraints for Multi-turn Dialogue and Prompt Engineering
Data sources for this category are dispersed, and update frequency is high. Multi-turn dialogue must bind context for the current production batch to avoid mixing historical data across batches. Different types of process documents have distinct field requirements. Prompts must clearly define call rules and field formats for each document type. Process parameters for individual products must strictly match corresponding component batches and equipment logs. Multi-turn dialogue context must filter expired data. Exception reports must link after-sales faults and rework records. Prompts must include core field logic for exception determination to prevent generation of non-compliant safety content.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind the unique identifier of the current production work order | Ensure multi-turn dialogue links to process data for the corresponding batch, avoiding cross-work order confusion |
| `messages` | Retain the first 8 conversation history entries + device log fragments from the last 2 hours | Align with shift-based production updates, keeping context length within a reasonable range |
| `variables` | Pass the current component batch number and safety compliance test thresholds | Enable prompts to directly access on-site parameters, reducing manual input errors |
| Maximum context length | 12000–15000 token | Calibrated via real-world testing, covering complete process documents and exception data for a single product unit |
| Context filtering rules | Only retain documents associated with the current work order | Filter expired data based on the per-unit or per-shift data update pattern |
| Prompt template fields | Clearly specify call priority for BOMs, charging records and safety compliance reports | Accommodate structural differences across multiple document types, ensuring generated content meets process standards |

## Three Common Configuration Mistakes
- Symptom: The conversation interface does not separately display input token and output token statistical values. Cause: The conversation token statistics switch in FastGPT v4.17.0 is not enabled. By default, only total token consumption is shown.
- Symptom: After entering a production batch number and process drafting requirements, corresponding batch charging records cannot be retrieved. Cause: The batch number is not passed as a retrieval parameter via `variables`, and the context does not limit the document scope to the current work order.
- Symptom: The prompt attempts to extract process data from the current year or current month, but returns an empty result. Cause: The prompt does not clearly specify the data source document type and time field format, and does not limit the retrieval scope to historical data for the current work order.

## How to Verify Successful Configuration
- Launch a simulated conversation, enter the current production batch number and process drafting requirements, and verify that the work order identifier for the corresponding batch is automatically bound in the conversation history.
- View the conversation token statistics panel, confirm that input and output token values are displayed separately, matching the version characteristics of FastGPT v4.17.0.
- Enter a request to extract process data from the current year or current month, and verify that returned results are limited to documents associated with the current work order, with no cross-batch data included.
- Adjust the context filtering rule configuration, confirm that expired data is automatically excluded, and ensure generated process files only use valid data from the current production cycle.
