# Drafting Process Documents and Exception Reports for Complete Home Appliance Manufacturing: Workflow Orchestration

## What Data Looks Like for This Category
Core data for complete home appliance manufacturing comes from ERP systems, MES manufacturing execution systems, component batch scanning devices, refrigerant charging equipment, electrical safety testers, performance laboratory equipment, and after-sales fault feedback databases. Daily generated documents include configured BOMs, assembly work instructions, refrigerant charging records, electrical safety test reports, random performance inspection reports, and rework records.

Data updates occur after a single product is produced, after each shift ends, and according to fixed random inspection plans. Data fields include product model number, component batch number, charging volume, test voltage, rework reason, and others. Some fields have clear units: charging volume is measured in grams, test voltage in volts.

## What Constraints These Characteristics Impose on Workflow Orchestration
Multiple heterogeneous data sources require workflows to unify data formats across different devices and systems, to avoid parsing failures caused by field mismatches.
Mixed-line production mode requires workflows to trigger corresponding processes based on product model numbers, to prevent misassembly of mixed product models.
High-frequency data updates require workflows to support real-time or near-real-time data pulling, to ensure the timeliness of process documents and exception reports.
Strict requirements for key processes such as safety testing and refrigerant charging require workflows to include built-in verification rules to intercept and report abnormal data.
Mass production characteristics require workflows to process process data for individual products in batches, while also supporting batch generation and pushing of exception reports.

## How to Configure Settings
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| variables | Preset `{productModel, batchNumber, testDate}` by product model | Matches query conditions for configured BOMs and component batches, ensuring accurate data association |
| nodeId | Unique identifier bound to safety test nodes and charging record nodes | Accurately associates data sources for each process step, avoiding node confusion |
| Trigger Timing | After completion of a single process step, after each shift ends | Matches update cadence of single-unit and shift-level production data |
| Process Verification Thresholds | Refrigerant charging deviation ±5 grams, electrical safety test voltage deviation ±2% | Complies with process specification requirements for complete home appliance manufacturing |
| Node Timeout Setting | 600 seconds | Covers typical time required for device data upload and database queries |
| Exception Report Template | Binds product model number, rework reason, and test data fields | Automatically generates exception report documents that meet category requirements |

## Three Common Misconfigurations
- Symptom: The database node returns no data during workflow execution, with an error prompt indicating SQL statement matching failure and no configuration information found for the corresponding product model. Cause: The `variables` parameter was not correctly passed in the workflow, resulting in missing configuration BOM information for the target product model in the query conditions.
- Symptom: The HTTP node returns a getaddrinfo ENOTFOUND error when calling a Peanut Hull address. Cause: Network access permissions for the workflow were not configured, making it impossible to resolve the intranet penetration address.
- Symptom: Optional parameters for custom tools do not appear in the node configuration panel. Cause: Enumerated value ranges for the parameters were not defined in `variables`, causing the node to fail to load configuration items.

## How to Verify Configuration Is Complete
- Manually trigger the workflow for a single specified product model, verify that the `variables` parameter is correctly included in the SQL query conditions, and that configured BOM data for the target product model is returned.
- Call the HTTP node to access a preset internal test address, confirm that the returned status code is 200 and the data format matches the preset document structure.
- Simulate an abnormal scenario where the refrigerant charging volume exceeds the deviation threshold, check whether the workflow triggers the exception report generation process and pushes it to the specified node.
- View workflow logs in FastGPT v4.17.0, confirm that each process node bound to `nodeId` executes normally, with no timeout or error records.
