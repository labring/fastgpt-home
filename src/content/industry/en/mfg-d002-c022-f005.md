# Drafting Process Documents and Exception Reports for Complete Home Appliance Manufacturing: Tool Calling and Plugins

## What the Data for This Category Looks Like
Complete home appliance manufacturing process and exception data primarily comes from ERP/MES systems, component batch ledgers, tightening and refrigerant charging equipment, safety compliance testers, performance laboratories, and after-sales fault databases. Daily documents include configured BOMs, assembly work instructions, refrigerant charging records, electrical safety test reports, performance sampling inspection reports, and rework records. Data updates run at the individual product level, shift team level, or per sampling plan. Document fields include component batch numbers, tightening torque values, refrigerant charging volumes, test voltages, rework reasons, and fault codes.

## How These Characteristics Impact Tool Calling and Plugin Workflows
This category has scattered data sources spanning production equipment, laboratory systems, and after-sales databases. Tool calling must adapt to the interface formats of multiple data sources. Data update cadences range from individual product to shift team levels. Tools must support real-time or near-real-time pulling of on-site data such as latest tightening torque values and refrigerant charging volumes. Document types are diverse with distinct field differences. Tool calling must support custom parameter mapping to match the field requirements of different documents like configured BOMs and rework records. In mixed-line assembly scenarios, tools must support switching calling parameters by product model to avoid cross-model data confusion and ensure accuracy of process documents and exception reports.

## Three Common Misconfigurations
- Issue: MCP tool calls return errors indicating parameter format mismatch. Cause: Parameter mapping rules for the tool are not configured based on the document fields for complete home appliance manufacturing, such as component batch numbers and tightening torque values. This causes incoming fields to not match the format expected by the tool.
- Issue: API calls time out and interrupt, failing to complete process document drafting. Cause: Tool calling timeout values are not adjusted. The default timeout duration is insufficient to cover the time required to pull bulk production data from ERP/MES systems.
- Issue: Process documents uploaded via custom workflows cannot reference variables from configured BOMs. Cause: The workflow’s parameter reference switch is not enabled. This causes the upload component to only support static link uploads, and cannot dynamically extract document fields.

## How to Verify Correct Configuration
- Initiate a simulated tool call, input typical fields for complete home appliance manufacturing such as component batch numbers and refrigerant charging volumes, and check if returned data matches the format of corresponding documents.
- Adjust the tool calling timeout value, then initiate a test task to pull production device logs, and confirm the task completes within the preset duration.
- Enable the workflow parameter reference switch, upload a configured BOM document, and check if fields can be automatically extracted and populated into the drafting template.
- Start the locally deployed tool container, upload a safety compliance test report, and confirm the uploaded file size meets the preset limit without triggering truncation errors.

The values provided here are common starting points, and should be evaluated against the samples used in the actual deployment scenario.
