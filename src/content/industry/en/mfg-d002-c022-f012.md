# Drafting of Process Documents and Exception Reports for Complete Home Appliance Manufacturing: Deployment and Upgrade

## What the Data for This Category Looks Like
Daily documents for this category include configuration BOM, assembly work instructions, refrigerant charging records, electrical safety test reports, performance spot check reports, and repair records. Data originates from ERP/MES systems, component batch ledgers, tightening and charging equipment, safety compliance testers, performance laboratory data, and after-sales fault records. Update cadence follows per-single product, per work shift team, and scheduled spot check plans. Documents are linked to specific production batches, process parameters, and test results.

## Constraints Imposed by These Characteristics on Deployment and Upgrade
This category has scattered data sources across multiple terminals such as production equipment, laboratories, and after-sales systems. During deployment, configure multi-source data synchronization adaptation links to support access to device data using different protocols. The high-frequency, fine-grained update cadence requires adjusting database connection pool parameters for small-batch, high-frequency write scenarios to avoid connection exhaustion. For diverse document types and per-single-product or per-team update logic, add document routing rules linked to product models during upgrades to prevent document mismatches during mixed production of multiple models. Product attributes targeted at consumers require strict field validation for exception reports. Configure required field validation logic during deployment. ## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150 connections` | Adapts to high-frequency, small-batch production data write scenarios, avoids database connection exhaustion |
| `REDIS_URL` | `redis://:custom password@intranet IP:6379/0` | Stores temporary process document parsing cache and session data, meets high-frequency access requirements for home appliance production |
| `STORAGE_S3_ENDPOINT` | `Enterprise intranet object storage node address` | Stores large-capacity safety compliance test reports and repair records, reduces public network transmission latency |
| `FE_DOMAIN` | `https://enterprise intranet process platform domain` | Adapts to enterprise intranet access scenarios, avoids exposing production-related data over the public network |
| `FILE_TOKEN_KEY` | `Calibrated via actual testing` | Generates access tokens for process documents, adapts to document permission control for different product models |
| `ROOT_KEY` | `Enterprise-specific random string` | Ensures permission security for platform background configuration, prevents unauthorized access |

## Three Common Mistakes
- Symptom: After Docker deployment, the frontend access address cannot be switched to HTTPS, and the browser displays an insecure connection warning. Cause: The `FE_DOMAIN` parameter was not correctly configured for HTTPS format, and the SSL certificate was not mounted to the frontend service directory in the container.
- Symptom: After adding the Qwen3 model to the configuration, startup fails with an error stating the model only supports streaming mode. Cause: The streaming transmission switch was not enabled in the model configuration, and the model was called using non-streaming mode.
- Symptom: Field null exceptions occur during multi-source data synchronization, leading to failure of process document generation. Cause: No cache expiration time was configured for the `REDIS_URL` entry, resulting in loss of temporarily synchronized component batch data.

## How to Verify Successful Configuration
- Access the configured `FE_DOMAIN` address, confirm the frontend page loads normally and displays process documents and exception report templates.
- Trigger a multi-source data synchronization task, confirm data from ERP/MES, safety compliance testers, and other systems can be pulled and stored normally.
- Call a large language model to generate a simulated repair exception report, confirm the output includes preset process document fields.
- Check database connection pool monitoring data, confirm the current number of connections does not reach the configured upper limit.
