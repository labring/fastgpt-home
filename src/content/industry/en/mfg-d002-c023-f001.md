# Drafting Process Documents and Exception Reports for Industrial Instrument Manufacturing and Calibration: HTTP Interfaces and External Systems

## What data for this category looks like
The data for this category comes from design documents, standard instruments and environmental monitoring equipment, calibration software, laboratory information systems, and customer range requirements. Daily generated documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version records.
Data is generated after each calibration for each device. Fields include tested part number, calibration date, standard instrument traceability number, error calculation value, and range. Units include pressure units, temperature units, percentage precision identifiers, and similar.

## What constraints these characteristics impose on HTTP interfaces and external systems
Data sources for this category are scattered and have associated traceability requirements. HTTP interfaces must support synchronizing original calibration data and certificate information from multiple systems.
Documents generated from a single calibration have diverse formats, so interfaces must support transmission of both structured fields and unstructured curve files.
Data update frequency is high, so interface calls must adapt to high-frequency synchronization scenarios.
Additionally, calibration records are critical deliverables, so interfaces must include traceability verification fields to prevent invalid data circulation and stop measurement deviations from propagating to downstream links.

## How to set configurations
| Configuration Item | Recommended Value | Rationale for This Value |
| --- | --- | --- |
| `Authorization` | `Bearer {laboratory information system exclusive key}` | Calibration data for this category is stored in laboratory information systems. Using a Bearer token enables secure verification of interface access permissions |
| `variables` | `{"calibrationRange": "customer agreed range", "standardId": "standard instrument traceability number"}` | Dynamic parameters exclusive to calibration scenarios must be passed in to adapt to calibration requirements for different tested parts |
| `responseData` | ``Only extract structured calibration records and associated file identifiers within the `responseData` field`` | This category requires precise acquisition of core calibration data, filtering non-essential content to improve review efficiency |
| Request retry count | `3 times` | Calibration data transmission is susceptible to laboratory network fluctuations, so retries can ensure data synchronization success rate |
| Single request data volume | `No more than 800 kilobytes` | Calibration records and error curve files for a single device have limited size, so limiting request size can avoid interface overload |

## Three common mistakes
- An HTTP interface call returns a 200 status code but no valid content. The cause is failing to pass the customer agreed range or tested part number parameter in `variables`, so the system cannot locate the corresponding calibration record.
- An error indicating parsing failure is prompted when uploading calibration error curve files. The cause is failing to adapt to the unstructured curve file format for this category, so the system cannot recognize the binary data structure generated by the instrument.
- Synchronized calibration records lack the standard instrument traceability number field. The cause is failing to carry legitimate access permissions for the laboratory information system via `Authorization`, so the interface only returns some non-core data.

## How to confirm configurations are set correctly
- A request simulating calibration data is sent using the interface debugging tool based on FastGPT v4.17.0, and the `responseData` field is checked to confirm inclusion of core fields such as tested part number and calibration date.
- The calibration error curve file for a single device is uploaded, and the system is confirmed to parse it normally and generate corresponding process document fragments.
- A batch synchronization request for calibration records is sent, and the `variables` parameter returned by the interface is checked to confirm it matches the passed calibration scenario parameters.
- The interface call log is viewed, and the verification status of the `Authorization` token is confirmed as passed, with no permission error reports.

The values provided are common starting points and should be measured against the reader's own samples.
