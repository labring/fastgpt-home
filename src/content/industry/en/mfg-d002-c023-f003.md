# Drafting Process Documents and Exception Reports for Industrial Instrument Manufacturing and Calibration: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Entails
Data for this category originates from design documents, standard instrument monitoring data, calibration software outputs, laboratory information systems, and customer range requirements. Daily output includes assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version logs. Data updates each time a device undergoes calibration. Data fields include measured parameter values, calibration dates, traceability numbers, and environmental monitoring parameters. Units align with standard metrology units for flow, pressure, temperature, and other metrics. The data volume of a single calibration record varies based on the number of calibration points.

## Constraints for Multi-turn Dialogue and Prompt Engineering
This category’s data updates per device per calibration. Multi-turn dialogue must link historical calibration records and current calibration data for the target device, to avoid mixing parameters from different batches or devices. Documents include specialized metrology fields and units. Prompts must clearly define field extraction formats, to ensure accurate matching of key details such as error values and traceability numbers. The data volume of a single calibration record grows with the number of calibration points. Multi-turn dialogue context length must support loading multiple associated documents, while retaining device numbers and customer range requirements from earlier conversations. This ensures consistent context for follow-up questions.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Context window size | 8000–12000 token | Accommodates the total length of multiple calibration documents (original records, error curves, certificates) for a single device, avoiding truncation of key information such as traceability numbers |
| `variables` global variable | Bind to the calibration record ID and customer range requirements for a single device | Ensures multi-turn dialogue always associates with exclusive data for the corresponding device, avoiding cross-device parameter confusion |
| `messages` historical message retention rule | Retain the most recent 4 turns of dialogue and the initial device identifier input | Balances context completeness and call efficiency, retains device numbers and initial range requirements |
| Prompt template structure | Split in the order of "calibration data verification → error calculation → exception report generation" | Matches the fixed review and generation workflow for documents in this category, ensuring accurate extraction of professional fields |
| `chatId` session isolation rule | Create independent sessions per device per calibration | Ensures calibration data from different batches or devices does not interfere across sessions, aligning with the per-calibration data update characteristic of this category |
| Large model temperature setting | 0.1–0.3 | Ensures accurate generation of metrology-related values and traceability information, avoids arbitrary changes to professional parameters, and follows the parameter configuration logic of FastGPT v4.17.0 |

## Three Common Misconfigurations
- Phenomenon: After a global variable is passed for the first time, if the variable value is modified during the same dialogue, subsequent component calls still display the initial value. Cause: The in-session update logic for `variables` is not correctly bound, causing the variable to not refresh synchronously with dialogue turns.
- Phenomenon: When selecting a variable-referencing large model for the AI dialogue component, the temperature setting entry is not displayed in the interface, making it impossible to adjust generation parameters. Cause: The parameter display switch is not enabled in the advanced configuration page, causing the temperature setting item to be hidden.
- Phenomenon: When only the dialogue model is configured, the call is grouped as 1 group, but dialogue response time exceeds 600 seconds. Cause: The historical message retention turn limit for `messages` is not set, causing the context to be too long and resulting in large model processing timeout.

## How to Confirm Proper Configuration
- Initiate a test dialogue for a single device's calibration workflow, input initial calibration parameters, and verify that the global variables are correctly bound to the corresponding device ID and range requirements.
- Conduct 3 consecutive rounds of questions targeting different calibration data, verify that each round's original question can be correctly identified and associated.
- Check the large model call logs, confirm that no key document content is truncated in the context window, and that the session isolation rule is active.
- Adjust the large model temperature parameter, verify that the numerical precision of the generated metrology report meets expectations, with no arbitrary changes to professional fields.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
