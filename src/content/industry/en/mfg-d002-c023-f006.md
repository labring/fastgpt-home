# Drafting Process Documents and Exception Reports for Industrial Instrument Manufacturing and Calibration: Citation Sources and Traceability

## What this category of data includes
This category of data covers daily operations of flow, pressure, temperature, and analytical instrument manufacturers and metrology laboratories. Daily documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version logs. Data sources include design documents, standard instrument monitoring data, calibration software outputs, laboratory information systems, and customer range requirements. Updates occur after each calibration for every device. Document fields include calibration date, error value, metrology certificate number, software version number, and more. Most units use international standard measurement units.

## What constraints these characteristics impose on the citation sources and traceability link
The multi-source nature of this category of data, plus the requirement to update after each single calibration, requires the citation traceability process to accurately match individual calibration records for each device. This prevents mixing data across devices or batches. Clear priority must be established for data from different sources. Standard instrument monitoring data takes precedence as a traceability basis. Calibration software outputs must be linked to original collection records. There are diverse document types. Corresponding recall rules must be configured for different document types, such as assembly and commissioning sheets, calibration procedures, and metrology certificates. This ensures cited content aligns with business scenarios. Calibration records are core deliverables. When cited, their fields and units must be fully retained to avoid information distortion.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context | 8000–12000 token | Adapts to FastGPT v4.17.0 context processing capabilities, accommodates long text from multiple calibration documents and error curves |
| Single Search Limit | Top 6 entries | Covers core documents for a single device, including calibration procedures, original records, and metrology certificates. Prevents interference from irrelevant data |
| Reranking | Enabled | Prioritizes recall of content directly related to calibration traceability and exception causes, improving citation accuracy |
| `quoteMaxToken` | 1500–2000 characters | Limits the length of a single cited passage, ensuring cited content in process documents and exception reports is clear and not redundant |
| `responseData` | Retain original fields and units | Ensures cited calibration data, error values, and other content fully match business document formats |
| `detail` | Enabled | Requires the large language model to strictly retain original document fields, units, and numerical details, preventing information tampering |

## Three common errors
- Symptom: Cited fields are empty in generated exception reports, or metrology certificate numbers are not displayed. Cause: `responseData` is not configured correctly, and the large language model is not instructed to extract and retain key fields from original documents.
- Symptom: Recalled cited content spans device batches, and does not match the instrument for which the report is being drafted. Cause: Recall results are not filtered by device serial number and calibration date, leading to recall scope covering documents from unrelated devices.
- Symptom: Cited passages in large language model outputs use inconsistent units compared to original documents, such as writing kPa as bar. Cause: The `detail` configuration item is not enabled, and the large language model is not forced to strictly follow original document units and numerical formats.

## How to confirm the configuration is correct
- Upload calibration documents and metrology certificates for a single designated device, submit a test request to draft a process document, and check if the returned results include the calibration date and error value for that specific device.
- Review citation source metadata, confirm that each citation is labeled with document type and source path to meet traceability requirements.
- Adjust the single search limit value, test whether the number of recalled results matches expectations, and verify that filtering rules are active.
- Check that cited units in generated exception reports match original documents, confirming the `detail` configuration item is enabled.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
