# Process Document and Exception Report Drafting for Industrial Instrument Manufacturing and Calibration: Document Parsing and Chunking

## What Data for This Category Looks Like
Data for this category comes from instrument manufacturers’ design documents, standard device and environmental monitoring records, calibration software outputs, laboratory information systems, and customer range requirements. Daily documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version logs. Data is updated once per calibration for each device. Fields include traceability chain number, error value, environmental parameters, calibration date, and tested device range. Units include instrument-specific units such as pascals, degrees Celsius, and calibration counts.

## Constraints Imposed on the Document Parsing and Chunking Link
Documents generated from a single calibration have high update frequency. Chunking logic must adapt to the independent business attributes of individual documents, and prevent cross-device data mixing. Documents include structured tables and visualized error curves. Parsing tools must support extraction of embedded charts and table data. Fields include key metrology information such as traceability numbers and environmental parameters. Chunking must retain the association between fields and their corresponding content, to avoid information fragmentation from splitting. Multi-source data imports have format differences. Parsing logic must support both standardized formats exported by software and non-standardized formats filled manually.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the field density of individual calibration documents, avoids splitting key metrology information such as traceability chain numbers and error curve descriptions |
| `chunkSplitter` | Split by paragraph + heading hierarchy | Matches the structured heading hierarchy of calibration procedures and metrology certificates, retains the association between fields and their corresponding content |
| `customPdfParse` | Enable embedded data extraction | Adapts to chart data and embedded tables in error curves and metrology certificates, avoids losing visually linked information |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 seconds | Addresses original calibration record documents with multiple sets of error curves, avoids parsing timeouts |
| `chunkSettingMode` | Manual configuration | Targets individual calibration documents for a single device, prevents automatic chunking from breaking up key metadata such as traceability chains |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Adapts to the typical size of calibration-related documents, avoids upload failures due to oversized files |

## Three Common Mistakes
- The issue: After parsing a metrology certificate with error curve images, the chunking result only retains text content, and image links are not associated. Question-and-answer testing cannot extract error data related to the images. The cause is that the embedded data extraction configuration for `customPdfParse` is not enabled, and only plain text content is extracted.
- The issue: When uploading a document with multiple sets of original calibration records, the system prompts a parsing timeout error. The cause is that the default duration of `PARSE_FILE_TIMEOUT_SECONDS` is not adjusted, and the parsing time for multiple sets of data cannot be covered.
- The issue: When clicking the document copy function, the prompt "Cannot use browser automatic copy, please manually copy the content below" is displayed. The cause is a same-origin restriction between front-end deployment and back-end interfaces, and no cross-domain copy proxy is configured.

## How to Verify Correct Configuration
Based on the configuration logic of FastGPT v4.17.0, the configuration effect can be verified through the following actions:
- Upload a calibration certificate document for a single device, and check if the parsed chunks retain independent metadata blocks such as traceability chain numbers and calibration dates.
- Upload a metrology certificate containing error curves, and verify if the parsing result includes the association between image links and their corresponding descriptive text.
- Upload a document with three or more sets of original calibration records, and confirm that the parsing process does not trigger a timeout error.
- Retrieve the chunked document content, and confirm that key metrology fields such as error values and traceability chain numbers can be retrieved normally.

The values provided are common starting points and should be measured against the reader's own samples.
