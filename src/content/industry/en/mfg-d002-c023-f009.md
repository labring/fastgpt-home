# Drafting Process Documents and Exception Reports for Industrial Instrument Manufacturing and Calibration: Model Access and Configuration

## What the data for this category looks like
Typical entities in this category include flow, pressure, temperature, and analytical instrument manufacturers, plus metrology laboratories. Daily generated documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version logs. Data sources cover design documents, standard instrument and environmental monitoring data, calibration software, laboratory information systems, and customer range requirements. Updates occur per calibration for each instrument. Core documents contain traceable measurement data and metrology certificate information, with most fields having clear units. The key difference from general equipment documents is that calibration records are critical deliverables that directly impact customer production and metrology audit results.

## What constraints these characteristics impose on model access and configuration
The data for this category has three core characteristics: per-instrument single-calibration updates, fields with units, and core documents being calibration records and metrology certificates. These traits create multiple constraints for model access and configuration.
Short-cycle data loading for a single instrument per calibration must be supported, to ensure full context covers all documents for a single calibration batch. Recognition of professional metrology terminology and unit-bearing fields must be supported, to prevent unit errors in generated content. Rigor of generated content must be strictly controlled, to ensure that fields and traceability information in calibration reports and exception reports match original data. High-frequency document update scenarios must be supported, to ensure stability and timeliness of model call links.

## How to set the configuration
This configuration is based on FastGPT v4.17.0.

| `AIPROXY_API_ENDPOINT` | Enter the dedicated model access address for industrial metrology scenarios | Industrial instrument calibration involves sensitive traceability data; dedicated access addresses ensure stability of call links and permission isolation |
| `AIPROXY_API_TOKEN` | Enter a dedicated token that has passed permission verification | Calibration records include sensitive information such as customer range requirements and error data; dedicated tokens prevent unauthorized access |
| `maxContext` | `8000–12000 token` | The total length of documents such as calibration procedures, original records, and error curves for a single instrument falls within this range; fully loading the context ensures generated content matches original data |
| `maxTokens` | `4000–6000 token` | Limit the maximum number of tokens per generation round, to avoid generated content exceeding delivery requirements for process documents or exception reports |
| `temperature` | `0.1–0.3` | Metrology reports must strictly match standard data; lower temperature parameters reduce random expressions and ensure result consistency |
| `quoteMaxToken` | `2000–3000 characters` | Key fragments such as error values and traceability chains must be extracted from calibration records; limiting reference length avoids redundant information interfering with generation |

## Three common mistakes
- Symptom: The model configuration page shows an invalid token, while the OneAPI configuration has no issues. Cause: A dedicated token for industrial metrology scenarios was not used; general tokens cannot match the access control rules for this scenario.
- Symptom: After selecting the GPT-4o mini model, a 400 error is returned when entering a query containing metrology parameters such as "350"; switching to another model works normally. Cause: This model has strict input format validation for professional metrology scenarios; failure to adapt to unit context of instrument parameters leads to format exceptions.
- Symptom: After initiating a model call, results are only displayed after full content generation, with no streaming return of segmented content. Cause: The streaming output switch was not enabled in the model configuration, or the configured model does not support streaming return logic.

## How to confirm the configuration is complete
- Users log in to the FastGPT backend, navigate to the model configuration page, check the status of `AIPROXY_API_TOKEN`, and confirm it shows a valid status.
- Users import calibration record documents for a single instrument, enter the test query "Generate the calibration exception report for this instrument, and verify that no 400 error is returned in the result.
- Users initiate a test call, observe whether the interface returns generated content segmentally, and confirm that streaming output is enabled normally.
- Users view the generated process document or exception report, and verify that the content includes core fields such as error curves, traceability chains, and customer range requirements.
