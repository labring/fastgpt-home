# Drafting of Process Documents and Exception Reports for Industrial Instrument Manufacturing and Calibration: Deployment and Upgrade

## What Data for This Category Looks Like
Data for this category comes from multiple sources. These include design documents, standard instrument and environmental monitoring data, calibration software outputs, laboratory information systems, and customer range requirements.
Daily generated documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version records.
Data updates trigger once per calibration operation per device.
Data fields include calibration range, error calculation values, traceability numbers, environmental temperature and humidity parameters, and more.
Core deliverables are certificate documents with metrological traceability.

## Constraints Imposed on Deployment and Upgrade Processes
This category's data has three key characteristics: high-frequency per-device updates, multi-source access, and strict compliance requirements. These create clear constraints for deployment and upgrade workflows.
Support precise retrieval by device ID and calibration time.
Adapt to fixed field parsing rules for structured calibration documents.
Interface with data from multiple laboratory systems and calibration software.
Complete pre-deployment configuration for traceability chains and environmental condition checks of metrology certificates. This ensures generated documents meet metrological audit requirements.
Ensure data storage traceability. Adapt incremental storage logic for multiple calibration data entries per single device.

## How to Configure Settings
The following configurations are formulated based on the deployment specifications of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `15–25 connections` | Multiple documents are generated per calibration operation per device. This setting supports concurrent database connection requests and avoids connection exhaustion |
| `MONGODB_URI` | Private connection address with 3 replica sets | Calibration records and error curve data have large volumes and require incremental storage. Replica sets ensure read-write stability and data redundancy |
| `REDIS_URL` | Private instance with 1000 MB or more memory | Cache real-time calibration parameter and environmental monitoring data to reduce latency from repeated database queries |
| `FILE_TOKEN_KEY` | Encryption key based on traceability numbers | Restrict access to calibration documents only to authorized personnel, and meet metrological compliance requirements |
| `STORAGE_S3_ENDPOINT` | Service address compatible with metrological storage specifications | Metrology certificates are critical deliverables. This ensures storage reliability and traceability |
| `PG_URL` | Read-only access connection for laboratory information systems | Used to synchronize customer range requirements and calibration traceability information, and ensure compliance of data sources |

## Three Common Misconfigurations
1. Symptom: Failed login with the preset administrator account after deployment. The system prompts permission verification failure. Cause: Incorrect configuration of the `ROOT_KEY` parameter, or a mismatch between the parameter value and the initial key set in the deployment script.
2. Symptom: Database connection exhaustion error when batch importing calibration records for multiple devices. Cause: The `DB_MAX_LINK` configuration value is lower than the actual concurrent request count. This causes the connection pool to fail to support batch operations.
3. Symptom: Uploaded error curve files cannot be parsed normally. The generated exception report lacks core fields such as error values and traceability numbers. Cause: Failure to adapt to the fixed field structure of this category's documents. Parsing rules do not match the standard format of calibration records.

## How to Verify Successful Configuration
- Execute the database connection test tool. Confirm that the connection pool configured with `DB_MAX_LINK` can support the concurrent requests required by the business. Adjust the configuration to fit the actual load range.
- Log in to the system using the configured administrator account. Confirm that the permission verification process operates normally without error prompts.
- Upload a standard calibration record document for this category. Confirm that the system correctly identifies core fields in the document and generates required structured data.
- Perform read and write tests for the storage service. Confirm that the storage service configured with `STORAGE_S3_ENDPOINT` can normally save and retrieve calibration documents.

The values provided are common starting points and should be evaluated against the operator’s own samples.
