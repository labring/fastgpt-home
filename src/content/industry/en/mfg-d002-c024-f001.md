# Process Change and Engineering Change: Process Document and Abnormal Report Drafting, HTTP Interfaces and External Systems

## What This Type of Data Looks Like
Data for this category comes from PLM, ERP, MES, supplier materials, validation tests, and customer-specific requirements. Daily documents include ECN/ECR, change assessment reports, drawings and BOM versions, process validation reports, transition plans, inventory disposal forms, and customer approval documents. Data updates occur irregularly, triggered by each change event. Document fields include change number, version number, effective date, impact scope, approval status, and others. Version numbers use the vX.Y format, effective dates use the YYYY-MM-DD standard format, and impact scope marks specific workshops or product lines.

## Constraints Imposed on HTTP Interfaces and External Systems
Multiple data sources require interfaces to support format specifications from different systems, and must adapt to differentiated structures such as PLM ECN fields and ERP BOM version numbers. Irregular update rhythms require interfaces to avoid fixed polling, and support event triggering or on-demand pulling. Complex document structures containing text and large attachments require interfaces to support large file transfers or attachment upload validation. Strict business field formatting rules require interfaces to validate request parameters to prevent invalid calls. Severe consequences of change errors require interfaces to include failure retry and status synchronization mechanisms to ensure data consistency.

This document applies to FastGPT v4.17.0 configuration.

## How to Configure
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {corresponding external system API key}` | Complies with internal enterprise API identity verification specifications to ensure secure external system integration |
| `variables` | Includes change number, effective date, impact scope fields | Matches the core business field structure of ECN/ECR documents to deliver accurate change parameters |
| `responseData` | Returns only change status, approval result, effective date fields | Reduces invalid data transmission and focuses on the core query needs of change management teams |
| Request timeout | 600 seconds | Adapts to the pull and parsing time required for large process validation reports and BOM files |
| Retry count | 3 times | Addresses interface call failures caused by temporary network fluctuations to ensure request success rate |
| Attachment upload limit | 1000 MB | Supports transmission needs for large drawings and process documents, matching the size range of business documents |
| Interface call rate limit | No more than 20 times per minute | Adapts to the API rate limiting rules of external systems to avoid triggering interception |

## Three Common Configuration Mistakes
- Symptom: Interface call returns 401 Unauthorized error. Cause: The `Authorization` parameter is not configured correctly, an expired system key is used, or the Bearer prefix is not added.
- Symptom: Received change data fields are empty. Cause: Correct business field mappings are not specified in `variables`, and the structure of ECN documents returned by the external system is not matched.
- Symptom: Interface call times out and fails. Cause: The configured request timeout is too short, and does not adapt to the parsing and transmission time required for large process validation reports.

## How to Verify Successful Configuration
- Call the test interface and check if the returned `responseData` includes the preset core change fields.
- Simulate a change submission to verify that the `variables` parameter is correctly passed to the target external system.
- View the interface call log to confirm that the `Authorization` parameter is correctly carried and passes identity verification.
- Upload a test process drawing file to confirm that the attachment transmission does not trigger a size limit error.

The values provided here are common starting points and should be evaluated against the reader's own samples.
