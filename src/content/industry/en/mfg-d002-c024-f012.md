# Process Change and Engineering Change: Process Document and Exception Report Drafting - Deployment and Upgrade

## What This Category of Data Looks Like
This category of data is generated by manufacturing enterprise change management teams. It covers ECN/ECR, change assessment forms, drawings and BOM versions, process validation reports, transition plans, inventory disposal documents, and customer approval files. Data sources include PLM, ERP, MES systems, supplier materials, validation test records, and customer-specific requirements. Updates are triggered irregularly with each change. Each document includes fields such as change number, version identifier, effective node, and impact scope. It must link material, process, and quality data across multiple systems. This page is compatible with FastGPT v4.17.0.

## Constraints Imposed by These Characteristics During Deployment and Upgrade
This category of data links multiple systems and contains large-volume process documents. During deployment, cross-system permission mapping must be configured to ensure normal connection of data sources such as PLM and ERP. Large-volume drawings and BOM files require storage configuration adapted to large-capacity object storage to avoid upload failures. Irregular change triggers may cause temporary concurrent writes. Database connection pool parameters must be configured to support high concurrency requirements. At the same time, change data involves customer approval files. Role permission configuration must be refined to prevent unauthorized access. During the upgrade process, change workflows must be kept uninterrupted. A gray release strategy must be adopted to avoid data synchronization exceptions caused by full-scale upgrades.

## How to Configure These Settings
| Configuration Item | Suggested Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://user:pass@host:27017/fastgpt?maxPoolSize=60` | Adapts to write and query operations for cross-system linked change data, avoids connection exhaustion |
| `STORAGE_S3_ENDPOINT` | `http://minio.example.com:9000`, set single file limit for storage buckets to 1000 MB | Meets storage requirements for large-volume process documents such as drawings and BOM files |
| `REDIS_URL` | `redis://:pass@host:6379/0`, set connection timeout to 300 seconds | Supports real-time status synchronization and permission caching for change workflows |
| `DB_MAX_LINK` | `50–80` | Matches concurrent demand for multi-system data pulling, avoids database connection pool overflow |
| `ROOT_KEY` | Configure role mapping rules according to enterprise permission systems | Differentiates role permissions for R&D, process, quality and other teams in the change management team, ensures access security for customer approval files |
| `FILE_TOKEN_KEY` | Generate a random 32-bit string | Secures download links for process documents, prevents unauthorized access |

## Three Common Misconfigurations
- Symptom: After device restart, locally deployed change workflow configurations and model parameters are lost. Cause: The database associated with `MONGODB_URI` and cache configuration associated with `REDIS_URL` are not persistently stored, relying on local temporary in-memory storage for configurations.
- Symptom: Workflow debugging returns an error containing "Dangerous behavior". Cause: No security verification rules are configured for `FILE_TOKEN_KEY`, causing uploads of large-volume process documents to trigger platform security interception.
- Symptom: Embedding model calls time out or return empty results. Cause: Concurrency settings for `DB_MAX_LINK` are not adjusted based on the average length of change documents, causing resource competition during multi-data-source pulling that leads to timeouts.

## How to Verify Successful Configuration
- Upload a single process document that does not exceed the preset limit, confirm that the storage path matches the `STORAGE_S3_ENDPOINT` configuration, and that the download link can be accessed normally.
- Restart the deployment server, confirm that change configuration and role permission data stored in the database are not lost.
- Trigger a test node in the change workflow, confirm that the workflow runs without security interception errors.
- Call the embedding tool interface, pass in the text of a process validation report, confirm that the returned result matches the expected format.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
