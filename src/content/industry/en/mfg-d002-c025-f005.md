# Drafting Process Documents and Exception Reports for Fixture and Gauge Manufacturing: Tool Calling and Plugins

## What Data for This Category Looks Like
Data for this category comes from product 3D models and GD&T, process routes, coordinate measuring machine data, on-site trial feedback, and metrology systems.
Daily documents include fixture requirement documents, positioning benchmark schemes, fixture drawings, gauge operation manuals, acceptance reports, calibration records, and change histories.
Document fields include GD&T tolerance annotations, micrometer-level measurement values, calibration dates, deviation values, and more.
Updates occur as projects progress, products are modified, or regular calibrations are performed.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins
Data sources for this category are scattered and have inconsistent formats.
Plugins must connect to metrology systems, coordinate measuring equipment, and other data sources.
Tool calling must support parsing of multiple data formats.
Document lengths vary widely, from a few pages for requirement documents to dozens of pages for fixture drawings.
Tool calling must support variable-length context processing.
Update schedules are triggered by project progress and product changes.
Tools must pull the latest calibration records and change histories on demand to avoid using expired data.
Tool calling results must be linked to GD&T tolerances and measurement values to ensure the accuracy of process documents and exception reports.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to different plugin calling scenarios and automatically matches tool capabilities |
| `functionCall` | `enabled` | Enables explicit function calls to keep tool calling workflows controllable |
| Tool calling timeout | `300 seconds` | Coordinate measuring machine data retrieval and calibration record parsing typically require longer processing times |
| Maximum items returned per tool call | `Top 10 items` | Fixture and gauge documents have many entries to prevent context overload |
| Context reservation ratio | `20%` | Retain sufficient space to process measurement data and tolerance information returned by plugins |
| Plugin request retry count | `3 times` | Resolve temporary connection interruptions with metrology systems |

## Three Common Configuration Mistakes
- Symptom: An `unAuthChat` error appears when calling a plugin. This occurs when the plugin's access key is not configured correctly, or the interface address has a spelling error.
- Symptom: Key information is missing from exception reports generated by tools when processing long documents such as large fixture drawings. This happens when context window settings are not adjusted, leading to core GD&T tolerance data being truncated.
- Symptom: No entry for scheduled tool execution is found. This occurs when the scheduled task module is not enabled on the plugin management page, or the installed FastGPT version does not support this feature.

## How to Verify Correct Configuration
- On the plugin testing page of FastGPT v4.17.0, a sample fixture requirement document is entered, tool calling is initiated, and parsing results for the positioning benchmark scheme are verified.
- The access key and interface address on the plugin configuration page are checked. A test call is triggered to confirm no permission errors or connection timeout prompts appear.
- A gauge operation manual containing coordinate measuring machine data is uploaded, and the exception report generated after tool calling is verified to include micrometer-level measurement deviation values.
- The scheduled task configuration page is accessed, a plugin execution task triggered by project changes is created, and the corresponding configuration item is confirmed to display in the task list.

The values provided are common starting points and should be evaluated against the reader's own samples.
