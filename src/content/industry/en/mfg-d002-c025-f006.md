# Process Document and Exception Report Drafting for Fixture and Gauge Manufacturing: Source Citation and Traceability

## What this category of data looks like
The core documents for this category include tooling requirement documents, positioning datum schemes, fixture drawings, gauge operation manuals, acceptance reports, calibration records, and change histories. Data sources cover product digital models and GD&T, process routes, coordinate measuring machine data, on-site trial feedback, and metrology systems. Updates are carried out per individual project, triggered by product changes, with regular calibration record updates. Document fields include positioning datum coordinates, GD&T tolerance values, coordinate measuring machine measurement results, metrology equipment numbers, change version numbers, and some drawing documents include assembly dimension chain parameters.

## What constraints do these characteristics impose on the source citation and traceability link
Documents in this category are strongly bound to specific projects and product changes. Traceability requires precise matching of project IDs and version information to avoid cross-project citation confusion. Multi-source data includes structured fields such as professional tolerances and coordinates, so retrieval must match professional terminology and cannot rely on generalized keyword filtering. Frequently updated calibration records and change histories require traceability to be linked to the latest version data; otherwise, process documents will not match actual production status. Individual documents have high professional parameter density, so the citation context must cover core verification fields to prevent traceability failure.

## How to configure settings
| Configuration Item | Suggested Value | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | Tooling fixture and gauge documents contain a large number of structured parameters. This value range can cover the context of core verification fields |
| `responseData` | Return file names, change version numbers, metrology equipment numbers | Traceability for this category requires linking to change histories and calibration records. Clear metadata allows quick location of valid sources |
| `detail` | Include positioning datum coordinates, GD&T tolerance fields | Core verification of process documents for this category relies on professional parameters, so citation content must cover key fields |
| Single search limit | Top 6 entries | The number of associated documents per project is moderate. Too many entries will interfere with relevance judgment of core citations |
| Context window | Calibrated based on actual measurements | Document lengths vary widely across different projects. Adjust the window size based on actual document volume |

## Three common mistakes
- Phenomenon: The number of returned citation documents exceeds expectations, with redundant content displayed on the interface. Cause: The single search limit is not set, and the retrieval scope is not filtered by project ID, resulting in incorrect citation of cross-project documents.
- Phenomenon: The returned citations do not match the latest change history of the current project. Cause: Version-matching retrieval configuration is not enabled, and retrieval is not linked to the project ID, resulting in citation of outdated documents.
- Phenomenon: The citation file name field returned by the API call is empty. Cause: The file name return switch for `responseData` is not enabled, or the file name metadata field of the document library is not mapped correctly.

## How to confirm that the configuration is complete
- Submit a test request for drafting tooling process documents, and check whether the returned citation list includes the fixture drawings, gauge operation manuals, and calibration records corresponding to the current project.
- Call the FastGPT v4.17.0 API interface, and check whether the metadata such as file names and change version numbers under the `responseData` field are included in the returned results.
- Adjust the `quoteMaxToken` parameter to 600 tokens and 1400 tokens, and verify whether the returned citation context covers core fields such as GD&T tolerances and coordinate measuring machine measurement results.
- Simulate an exception report drafting request, and check whether citations are automatically linked to the latest change history and calibration records.
