# Process Document and Exception Report Drafting for Non-Ferrous Metal Smelting and Electrolysis: Source Citation and Traceability

## What This Category's Data Looks Like
Typical business entities for this category are smelting, electrolysis, testing, and scheduling departments of copper, aluminum, lead-zinc smelting enterprises. Daily generated documents include batching lists, smelting records, electrolytic cell status records, test reports, anode and cathode quality records, and environmental protection ledgers. Data sources cover concentrate and auxiliary material analysis, DCS systems, cell voltage and current monitoring, laboratory testing, energy and environmental monitoring, and other channels. Update frequencies vary by raw material batch, per furnace or cell, or in real time. Document fields include raw material composition ratios, equipment operating parameters, test result values, batch numbers, timestamps, and other items, with units matching the corresponding data type.

## Constraints on Source Citation and Traceability
Data for this category comes from multiple sources with highly varied update rhythms. Traceability requires precise matching of core identifiers: batch numbers, furnace or cell numbers, and timestamps. This avoids mixing data across batches or equipment. Field formats differ across multiple document types. Matching rules must be configured for the document structures of different data sources. This ensures cited original data aligns with the process document or exception report currently being drafted. For real-time data such as cell voltage and current, the traceability chain must quickly retrieve the latest monitoring records. This ensures data timeliness during exception troubleshooting. The business logic linking processes and exceptions for this category is complex. Traceability must cover all process data nodes from raw materials to finished products. This provides complete evidence for process adjustments or exception accountability.

## Three Common Mistakes
- Phenomenon: An error occurs when viewing knowledge base citations in chat responses. Cause: No field association rules between data sources and knowledge base are configured, making it impossible to match corresponding data entries during traceability.
- Phenomenon: Variable references fail to take effect after selecting a knowledge base in the knowledge base search card. Cause: The metadata return configuration for the `responseData` parameter is not enabled, making it impossible to extract variable fields from the citation source.
- Phenomenon: Process data cited in generated exception reports does not match the actual batch. Cause: The `quoteMaxToken` value is too small, truncating core associated fields such as batch numbers, leading to matching errors during traceability.

## How to Verify Proper Configuration
- Import single-batch test documents such as batching lists and smelting records, submit a process document drafting request, and check whether the returned results include complete source metadata.
- Simulate an exception scenario by entering a question about abnormal cell voltage, and verify that the cited traceability data is linked to the real-time operating records of the corresponding furnace or cell.
- Adjust the `quoteMaxToken` value to verify that documents of different lengths can be fully cited without truncation.
- Check that the configured data sources cover the four core categories: concentrate analysis, DCS operation, test reports, and environmental monitoring.
