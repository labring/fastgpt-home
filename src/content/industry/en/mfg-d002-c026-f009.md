# Drafting Process Documents and Exception Reports for Non-Ferrous Metal Smelting and Electrolysis: Model Access and Configuration

## What data for this category looks like
This category of data comes from concentrate and auxiliary material analysis reports, production DCS systems, electrolyzer voltage and current monitoring data, laboratory test results, and energy and environmental monitoring devices. Daily generated documents include batching lists, smelting records, electrolyzer condition records, test reports, anode and cathode quality records, and environmental protection ledgers. Data updates proceed in real time with production batches, single furnace, or single tank operations. Some monitoring indicators update every second or minute. Ledger-type documents are archived according to operation cycles.

## What constraints these characteristics impose on the model access and configuration link
Multi-source, scattered data sources require model access to support multi-format input. Adjust context window parameters to accommodate splicing of documents from different sources. High-frequency real-time updates lengthen context length. Limit the total number of tokens generated per call to avoid call timeouts. Industry-specific fields such as impurity proportion, tank voltage, and metal recovery rate require adjusting the rigor of model generation. Exception reports must match response requirements tied to operation cycles. Calibrate parameters to balance generation speed and content accuracy.

## How to set the configurations
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Covers complete multi-source data for a single batch of smelting or electrolysis operations, adapts to the need for splicing multiple documents such as batching lists and tank condition records |
| `maxTokens` | 1500–2000 token | Limits the length of generated content, matches the standard length of exception reports and process documents, and avoids call timeouts |
| `quoteMaxToken` | 2000–2500 characters | Retains sufficient source data fragments as generation references without exceeding the upper limit of the context window |
| `temperature` | 0.3–0.5 | Balances the accuracy of industry-specific terminology and generation fluency, avoiding generation of non-standard parameter content that does not comply with regulations |
| Workflow/API tool selection | auto | Automatically calls tools to integrate real-time monitoring data, adapting to the rapid generation requirements of exception reports |
| `AIPROXY_API_ENDPOINT` | Enterprise internal deployment node | Complies with data isolation requirements for industrial production, avoiding transmission of sensitive production data over external networks |

This content is written based on the model access configuration logic of FastGPT v4.17.0.

## Three common mistakes
- Symptom: The interface displays an API link verification failure, but local oneAPI testing works normally. Cause: The path parameter for `AIPROXY_API_ENDPOINT` is not configured correctly, or the enterprise internal deployment node is not added to the allowed access list.
- Symptom: Generated process documents include incorrect tank voltage units or impurity proportion values. Cause: The `temperature` parameter is set too high, leading the model to generate non-standard field content that does not comply with industry regulations.
- Symptom: Call returns an empty result or times out. Cause: The `maxContext` parameter is set too large, exceeding the context window upper limit supported by the model, or the `maxTokens` parameter fails to limit generation length, causing resource exhaustion.

## How to confirm the configuration is complete
- Input the batching list and tank condition records for a single smelting batch into the test interface. Verify that the generated process document includes industry-specific fields such as impurity proportion and anode and cathode quality parameters.
- View the model call log to confirm that the `maxContext` and `maxTokens` parameters do not exceed configured upper limits, and that no timeout or parameter error reports appear.
- Verify the response time for exception report generation to match the response requirements of the operation cycle.
- Check the API key configuration to confirm that only authorized specified accounts have access, complying with data security specifications.

The values given are common starting points and should be measured against the reader's own samples.
