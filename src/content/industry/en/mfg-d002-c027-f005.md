# Drafting Process Documents and Exception Reports for Garment Cutting and Sewing: Tool Calling and Plugins

This page's configuration instructions apply to FastGPT v4.17.0 and later versions.

## What Data for This Category Looks Like
Data for this category typically comes from orders and size charts, CAD patterns, fabric and accessory inspection records, hanging system data, needle detector test results, and customer sealed samples. Daily generated documents include work orders, patterns, layout plans, cutting lists, first article sealed samples, process quality sheets, packaging and size matching sheets, and others. Data update frequency is per order, per style, per batch. Due to the large number of styles and strong seasonality, single-style cut pieces are irreversible and manual processes are intensive. Data fields often include size parameters, fabric batch numbers, process nodes, packaging ratios, and other specific content.

## Constraints on Tool Calling and Plugins From These Characteristics
Since single-style cut pieces are irreversible and data updates per order batch, tool calling must bind the exclusive dataset for a specific order to avoid cross-order data confusion. The large number of styles and strong seasonality require frequent switching of associated data sources, so plugins must support fast switching of bound CAD patterns, layout plans, and other documents. Intensive manual processes mean exception reports must accurately match process node data, and tool calling must accurately extract defect records from process quality sheets. The field specificity of fabric batch numbers and size parameters requires plugins to identify and filter field information not belonging to the current order when called.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` or specify a specific tool name | Match the document parsing plugin bound to the current order automatically based on the specific scenario of drafting process documents, to prevent the model from selecting unrelated tools by mistake |
| Workflow/API function-call configuration | `enabled` | Force the model to call pre-configured plugins, to avoid directly generating process content that deviates from actual cut piece data |
| Plugin data source binding | Bind the CAD pattern, layout plan, and process quality sheet dataset corresponding to the current order ID | Since cut pieces are irreversible and data updates per order batch, restrict plugins to only call exclusive data from the current batch |
| Context window size | 8000–12000 token | Accommodate the full content of multiple documents such as work orders and packaging size matching sheets, to avoid truncating critical size and fabric batch parameters |
| Tool call timeout threshold | 300–600 seconds | Wait for backend processes such as CAD pattern parsing and hanging system data synchronization to complete, reserve sufficient processing time |
| Number of matching results returned | Top 3 entries | Drafting process documents only requires core process requirements, size ratios, and other data; excessive results will interfere with the model's generation of accurate content |

## Three Common Mistakes
- Symptom: The model does not trigger the bound plugin during tool calling, and directly generates general process content. Cause: `toolChoice` is not correctly configured for mandatory calling mode, or the exclusive dataset for the current order is not bound, causing the model to fail to match the corresponding tool.
- Symptom: The generated exception report includes fabric batch or size data from non-current orders. Cause: The plugin does not filter data sources by order ID, and calls historical data across orders, resulting in content that does not match the current batch.
- Symptom: Tool calling times out, returning empty results or error messages. Cause: The set timeout threshold is lower than the actual time required for backend data synchronization and CAD pattern parsing, and sufficient processing time is not reserved.

## How to Confirm Configuration Is Correct
- Submit a process document drafting request for a single order, check the backend tool call logs to confirm that the bound corresponding document parsing plugin was successfully triggered.
- Review the generated work order content to confirm that fields such as size and fabric batch match the current order's dataset exactly.
- Simulate a process exception scenario to trigger exception report generation, confirm that the plugin can extract corresponding defect records from the process quality sheet and integrate them into the report.
- Verify the tool call timeout setting by simulating delayed data synchronization steps, confirm that no timeout error occurs.

The values provided are common starting points and should be measured against the reader's own samples.
