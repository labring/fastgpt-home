# Drafting Process Documents and Exception Reports for Garment Cutting and Sewing: Source Citation and Traceability

## What Data Looks Like for This Category
Core data for this category comes from garment OEM/ODM workshops, order and size charts from brand supply chains, CAD patterns, fabric and accessory inspection records, hanging system data, needle detector results, and customer sealed samples. Daily generated documents include process sheets, layout plans, cutting lists, first article sealed samples, process quality sheets, packaging and size matching lists, and more. Fields cover size specifications, fabric dye batches, cutting piece matching requirements, packaging size matching rules, and other items. Data update rhythm adjusts with each order and production batch. Process documents and exception data for a single order only correspond to that batch’s production task.

## Constraints Imposed by These Characteristics on the "Source Citation and Traceability" Link
Since documents for this category are updated frequently with order batches, traceability must be tied to specific order numbers and style numbers to avoid mixing data across batches. The irreversible nature of cut pieces and dense workflow requirements mean cited exception report data must accurately correspond to inspection records for individual processes, and cannot be mixed across processes. Requirements for fabric dye batches and cutting piece matching fields mean traceability must extract exclusive fields such as fabric batch numbers and cutting piece IDs, and cannot rely solely on general text matching. Additionally, in multi-document collaboration scenarios, ensure citation sources for process sheets, layout plans, and exception reports do not overlap, to avoid data conflicts.

## How to Configure the Setup
This scenario’s configuration is based on the functional rules of FastGPT v4.17.0. Specific configuration items and recommendations are as follows:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | The text length of a single process sheet or exception report for this category falls within this range, preventing truncation of core fields such as cutting piece IDs and fabric dye batches |
| Similarity Threshold | 0.75–0.85 | Match precise fields such as fabric dye batches and cutting piece IDs, filtering redundant data from non-target batches |
| Single Search Limit | Top 6 entries | Cover multiple types of documents related to a single order, including process sheets, layout plans, and inspection records |
| `responseData` | Return only associated order fields | Ensure traceability data only includes exclusive information for the current batch, avoiding interference from cross-order data |
| `detail` | Enable full field display | Retain detailed fields such as cutting piece IDs and fabric dye batches, meeting precise traceability requirements |
| Maximum Context | 3000–4000 characters | Accommodate concatenation of multiple associated documents, preventing loss of prior process requirements |

## Three Common Misconfigurations
- Phenomenon: Retrieval results include documents not associated with the current production batch, and irrelevant citations are displayed in the interface. Cause: Order numbers and style numbers are not bound as retrieval filter conditions, leading to recall of cross-batch data.
- Phenomenon: Cited documents have too low relevance, or an unexpected number of entries. Cause: Threshold and single search limit parameters are not adjusted based on the matching needs of precise fields for this category.
- Phenomenon: After writing a knowledge base ID or custom citation variable in the configuration, a parameter format error is triggered during application. Cause: Built-in variable binding rules of the platform are not used, and hardcoding directly leads to format incompatibility.

## How to Confirm Proper Configuration
- Import test order data for a single batch, initiate a process document drafting request, and verify that the order numbers of cited documents match the current test order.
- Adjust the similarity threshold and single search limit, and check whether the number and relevance of returned citations meet the needs of the current scenario.
- After enabling the `detail` parameter, check whether cited documents include exclusive fields such as cutting piece IDs and fabric dye batches.
- Verify the binding logic of citation variables, initiate an exception report drafting request, and confirm that the citation source has a correct association with the current task.

The values provided are common starting points and should be measured against the reader's own samples.
