# Drafting Process Documents and Exception Reports for Mold Design and Manufacturing: Multi-turn Dialogue and Prompt Words

## What Data Looks Like for This Category
Daily documents for this category include mold design task sheets, DFM reports, part drawings, machining process cards, trial mold reports, mold modification notices, and mold records. Data sources include product models provided by customers, mold flow or forming simulation results, CAD/CAM files, machining and measurement data, and trial mold sample parameters. Data updates are carried out on a per-project basis, and relevant documents are updated synchronously after each trial mold or mold modification. Document fields usually include specific parameters such as demolding requirements, forming accuracy indicators, and mold modification times.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompt Words
The documents for this category have fixed structures and large quantities, with diverse data sources. Update frequencies change in real time with trial molds and mold modifications, and there are a large number of professional process parameters. This requires that multi-turn dialogue must split prompt words by document type, adapting to different scenarios such as design task sheets and trial mold reports respectively. At the same time, it is necessary to bind `variables` to associate the exclusive data source of the corresponding project, ensuring that the latest data of the current project is called. In addition, the dialogue context must be restricted to only retain the historical records of the current project, avoiding mixing old data from other projects to interfere with generation results. Prompt words must also embed proprietary terminology from the mold industry to ensure that generated content complies with industry specifications.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Context window size | First 800–1200 characters | Matches the typical length of a single page of mold-related documents, avoiding truncation of key demolding and accuracy parameters |
| Maximum retained historical dialogues | First 3 project-related dialogues | Focuses on the latest records of the current trial mold or mold modification, avoiding interference from redundant historical content on generation |
| `variables` binding rules | Bind the exclusive data source of the current project | Ensure generated content references exclusive information such as the DFM report and trial mold data of the corresponding project, in compliance with FastGPT v4.17.0 configuration specifications |
| Prompt template grouping | Split by document type | Adapt to different generation requirements for process documents and exception reports respectively |
| Chunk retrieval length | 600 characters | Matches the typical paragraph length of mold process cards and part drawing descriptions, improving retrieval matching accuracy |

## Three Common Misconfigurations
- Phenomenon: When configuring prompt words, content interpreting mold DFM reports is embedded. When calling to generate process documents, the system prompts that no files have been uploaded. Cause: Only document reference instructions are written in the prompt word text, and the corresponding documents are not bound to the `variables` parameter. The system cannot recognize the associated data source.
- Phenomenon: After upgrading, refreshing the dialogue page causes the historical dialogue records of the current mold project to disappear, and a brand new dialogue is displayed. Cause: Persistent storage for `chatId` is not configured. Session data is only saved in local temporary cache, which is cleared after the page is refreshed.
- Phenomenon: Attempting to switch the knowledge base of different mold projects during dialogue, and the generated content does not match the trial mold data of the corresponding project. Cause: The real-time switched knowledge base identifier is not passed through `messages`. The system still calls the default bound knowledge base.

## How to Confirm Proper Configuration
- Initiate a multi-turn dialogue, enter the trial mold defect description of the current mold project, and check whether the generated exception report references the trial mold data of this project.
- View the `variables` binding in the configuration items, and confirm that documents such as the current project's mold design task sheet and part drawing have been associated.
- Refresh the dialogue page, and check whether the historical dialogue records of mold modifications and trial molds are fully retained.
- Switch between different document type prompt templates, and confirm that the generated process documents or exception reports comply with the format requirements of the corresponding documents.
