# Process Document and Abnormal Report Drafting for Mold Design and Manufacturing: Document Parsing and Chunking

## What data for this category looks like
Core data for mold design and manufacturing scenarios typically comes from customer product models, mold flow or forming simulation files, CAD/CAM exported drawings, machining and measurement records, and inspection reports of trial mold samples. Daily generated documents include mold design task sheets, DFM reports, part machining process cards, trial mold reports, mold modification notices, and mold histories. Data update rhythm follows project progress, with new documents generated after each trial mold, mold modification, or process adjustment. Document structures include structured parameter fields such as number of mold cavities, material grade, and draft angle, semi-structured process steps, and free-form defect descriptions. Some documents include vector graphics and embedded tables.

## What constraints do these characteristics impose on the "document parsing and chunking" link
Mold design and manufacturing documents contain technical terminology, structured parameters, and semi-structured process logic. Chunking must retain semantic association, and avoid breaking the corresponding relationship between process steps and defect rectification. The structure varies significantly across different document types: CAD-exported PDFs include vector graphics and embedded tables, while Excel process cards have multi-row and multi-column parameter tables. General-purpose parsing engines struggle to support all formats. Data updates occur frequently and iterate with projects, so incremental parsing and batch processing of multiple document sets must be supported. Improper chunking can lead to loss of key process information, which may affect subsequent mold review and mold modification decisions. This differs significantly from the document requirements for regular part machining.

## How to set the configurations
The following configurations are formulated based on FastGPT v4.17.0:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Mold process documents contain continuous machining steps and defect analysis. Chunks that are too long will lose contextual association, while chunks that are too short will break process logic. This range adapts to the semantic integrity of professional documents. |
| `chunkSplitter` | Separate by paragraph + heading | Mold documents have clear section headings and paragraph structures. Separating this way preserves the complete logical chain of process steps and defect rectification. |
| `customPdfParse` | Enabled | Some CAD-exported PDFs contain vector graphics and embedded tables. Enabling custom parsing preserves the correspondence between tables and text. |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large mold project process documents include multi-page drawings and simulation data. Sufficient timeout time is required to complete full parsing. |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | A single project's mold document set usually includes multiple CAD attachments and reports. This upper limit covers the file size requirements of most projects. |

## Three common mistakes
- Symptom: After uploading a CAD-exported PDF, embedded part drawings cannot be displayed normally, and text blocks are misaligned. Cause: The `customPdfParse` configuration is not enabled. The default parsing engine cannot support vector format PDFs exported from CAD.
- Symptom: After uploading an Excel-format machining process card, the chunking result loses the association between process numbers and corresponding parameters. Cause: The `chunkSplitter` configuration is not adjusted for structured table documents. The default character-based chunking breaks the row association of tables.
- Symptom: After uploading a mold project document package larger than 100 MB, the parsing task times out and fails directly. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` configuration value is set too low, and does not adapt to the document size and parsing time of large mold projects.

## How to confirm the configuration is correct
- Upload a typical trial mold report PDF, and verify that the parsed text retains complete paragraphs of defect descriptions and rectification measures, with no obvious text misalignment.
- Upload an Excel-format machining process card, and verify that each process block in the chunking result includes the process name, parameters, and acceptance criteria, with no field splits or losses.
- Upload a mold project document package larger than 50 MB, and confirm that the parsing task completes within 10 minutes with no timeout errors.
- Test replacing the configuration items of the custom PDF parsing tool, and verify that the embedded annotation text can be normally parsed from the uploaded CAD drawing PDF.

The values provided are common starting points and should be measured against applicable samples.
