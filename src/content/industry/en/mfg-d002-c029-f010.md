# Drafting Process Documents and Exception Reports for Mold Design and Manufacturing: Knowledge Base Retrieval and Recall

## What this category of data looks like
Data for this category originates from injection molding, stamping, and die-casting mold enterprises, as well as mold centers within manufacturing enterprises. It includes documents such as mold design task sheets, DFM reports, part drawings, machining process cards, mold trial reports, mold modification notices, and mold history records.
Data sources include customer product models, mold flow/form simulation files, CAD/CAM output files, machining and measurement data, and mold trial sample records. Data is updated per individual project, with corresponding documents synchronized after each mold trial or modification.
Each document is bound to a unique mold number and part drawing number, and includes fields like demolding angle, machining tolerance, and mold trial defect type.

## What constraints do these characteristics impose on retrieval and recall?
The data characteristics of this category create three core constraints for the retrieval and recall process.
First, each document is tied to a unique mold number and part drawing number. Retrieval must accurately match these identifiers to avoid pulling irrelevant data from other projects.
Second, the data includes multiple file types: mold flow simulations, CAD drawings, machining measurement records, and more. Retrieval must support multi-format parsing, and must link time-stamped mold trial and modification records to prevent retrieving outdated process parameters or defect reports.
Third, data updates trigger dynamically after each mold trial or modification. Retrieval must support incremental synchronization to ensure only the latest versions of process documents and exception records are returned.
Additionally, documents contain professional numerical fields such as demolding angle and machining tolerance. Retrieval must support matching by numerical ranges, not just keyword matching.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | Matches professional terminology and numerical ranges for mold process parameters, avoiding retrieval of low-relevance mold trial reports |
| `limit` | Top 8 entries | The number of process documents and exception reports per project is typically limited. Restricting retrieved entries prevents context overload |
| `searchMode` | `embedding` | Supports semantic matching for professional terminology and numerical ranges, meeting the specialized retrieval needs of mold design |
| `usingReRank` | Enabled | Re-ranks retrieved results by their match score with mold ID and part drawing number to improve accuracy |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands search terms, adding retrieval dimensions for unique identifiers like mold numbers and part drawing numbers |
| `collectionIds` | Knowledge base collection IDs bound to the project | Restricts retrieval scope to only the mold documents for the current project, eliminating cross-project interference |

## Three Common Configuration Mistakes
- Symptom: Retrieval results only return a single matching entry, and cannot display multiple eligible process documents. Cause: The `limit` parameter was not configured correctly, or its value was mistakenly set to 1, resulting in only one entry being retrieved.
- Symptom: Non-text files such as mold flow simulations and CAD drawings cannot be retrieved. Cause: The document parsing capability for the corresponding file formats was not enabled, so non-text process data failed to generate embedding vectors.
- Symptom: Retrieval results include irrelevant mold documents from other projects, and cannot accurately match the current project's mold number. Cause: The `collectionIds` parameter was not configured to limit the retrieval knowledge base collection, allowing cross-project data to be retrieved.

## How to Verify Proper Configuration
- Retrieve process documents for a specified mold number, and confirm that returned results only include files associated with that mold to verify the `collectionIds` configuration works.
- Enter a search term with professional parameters such as demolding angle or machining tolerance, and confirm that returned results match the corresponding parameter ranges to verify the `similarity` and `searchMode` configurations are reasonable.
- Upload the latest mold modification notice, wait for synchronization to complete, then search for keywords related to the modification event, and confirm that updated documents are returned to verify the incremental synchronization configuration works.
- Test retrieval of non-text format simulation files, and confirm that the corresponding content can be retrieved and parsed normally to verify multi-format parsing configuration is complete.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
