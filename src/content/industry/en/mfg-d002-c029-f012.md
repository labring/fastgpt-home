# Drafting Process Documents and Exception Reports for Mold Design and Manufacturing: Deployment and Upgrade

## What the Data for This Category Looks Like
Typical users are injection molding, stamping, and die-casting mold enterprises, as well as mold centers within manufacturing enterprises. Daily documents include mold design task sheets, DFM reports, part drawings, machining process cards, mold trial reports, mold modification notices, and mold records.
Data sources include customer product models, mold flow or forming simulation files, CAD/CAM source files, machining and measurement data, and photos of trial-molded parts.
Data updates follow project cycles, with synchronization after each mold trial or modification.
Documents include fields such as mold number, part number, defect type, and number of mold modifications. Dimension fields use millimeters as the unit. Duration fields use hours as the unit.

## Constraints Imposed on Deployment and Upgrade
Business data for mold design and manufacturing has scattered sources and diverse formats. During deployment, systems must support parsing and storing unstructured data such as CAD files and simulation files.
Data is updated frequently based on projects and mold trials or modifications. Deployment configurations must support project-based data isolation to prevent mixing of process documents and exception reports across different projects.
Business errors directly affect mass production timelines. The deployment and upgrade phase must ensure stable connections for all services. During upgrades, historical mold modification and trial record data must be retained to prevent business interruptions.
Additionally, business document fields have custom requirements. Configurations must support custom field mapping rules.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `MONGODB_URI` | `mongodb://{username}:{password}@{host}:{port}/fastgpt?authSource=admin` | Unstructured data such as mold trial reports and mold modification records for mold design and manufacturing are compatible with MongoDB storage formats |
| `REDIS_URL` | `redis://:{password}@{host}:{port}/0` | Cache frequently accessed mold part drawings and DFM report preview data to reduce repeated read overhead |
| `STORAGE_S3_ENDPOINT` | `Fill in according to the actual address of the enterprise's self-built object storage` | Mold-related CAD files and photos of trial-molded parts have large sizes, compatible with the storage and reading requirements of object storage |
| `DB_MAX_LINK` | `20–30` | The volume of process document and exception report data accessed simultaneously for a single project is large, to avoid exhausting the database connection pool |
| `FE_DOMAIN` | `https://{enterprise mold business system domain name}` | Embed FastGPT into the existing mold design and manufacturing business interface to unify operation entry points |
| `FILE_TOKEN_KEY` | `Randomly generated 32-bit string` | Encrypt access tokens for mold documents to prevent unauthorized access to sensitive business data |

## Three Common Mistakes
- Symptom: The FastGPT interface displays a database connection failure. System logs show a "connection refused" error. Cause: `MONGODB_URI` is not set to an available database address, or database access permissions are not opened for the deployment node.
- Symptom: Content cannot be extracted after uploading a mold trial report or part drawing. The interface displays a document parsing failure. Cause: `FILE_TOKEN_KEY` is not configured, or the secret key does not match FastGPT's encryption rules, leading to insufficient file read permissions.
- Symptom: Testing a oneAPI call to generate an exception report returns no valid results. Background logs show a request timeout. Cause: The oneAPI service container port is not fixedly mapped to the host machine. The service address changes after each container restart, resulting in unsynchronized configuration updates.

## How to Confirm Successful Configuration
- Access the FastGPT v4.17.0 administrator interface, enter `ROOT_KEY` to complete login, and view the system status page. Confirm that the connection status of all databases, Redis, and object storage shows normal.
- Upload a standard mold part drawing CAD file. Confirm that the preview function loads normally, and document metadata such as part dimensions and material grade can be correctly identified and extracted.
- Call the oneAPI test interface, enter a preset prompt word for mold exception report drafting. Confirm that the returned content includes structured business fields such as mold defect analysis and mold modification suggestions.
- View the Redis monitoring panel. Confirm that the cache hit rate is in a reasonable range, with no frequent connection timeout or service disconnection errors.
