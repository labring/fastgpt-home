# Drafting Process Documents and Exception Reports for Rubber Mixing and Product Vulcanization: Workflow Orchestration

## What this category of data entails
This category supports tire, seal, rubber hose, and rubber product enterprises. Daily documents include formula sheets, weighing records, mixing curves, rubber compound quick tests, vulcanization process cards, mold records, and finished product performance reports. Data sources include formula systems, raw material batch management modules, internal mixers, Mooney viscometers, rheometers, vulcanizers, and laboratory testing equipment. Data updates occur per truckload of rubber, each batch of compound, and each vulcanization cycle. Document fields cover raw material feeding weight, mixing temperature and duration, vulcanization temperature and time, mold number, and finished product performance indicators. Associated units include kilograms, degrees Celsius, minutes, cycles, and similar units.

## Constraints Imposed on Workflow Orchestration by This Category’s Data Characteristics
This category’s data characteristics create multiple constraints for workflow orchestration. High-frequency production data requires workflows to trigger based on production nodes, matching the rhythm of per-truckload rubber, per-batch compound, and per-cycle vulcanization. Multi-source heterogeneous data inputs require workflows to connect to different data source nodes such as formula systems, production equipment, and laboratory equipment, to ensure accurate data matching. Diverse document types require workflows to support parsing and field extraction for different document formats. Strict process requirements and high consequences of errors require workflows to include built-in exception checks and trigger branches, to promptly handle issues such as feeding errors, temperature deviations, under-vulcanization, and over-vulcanization.

## How to Configure
This configuration logic is documented for FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Update in real time per vulcanization cycle or batch | Match the production update frequency of per-truckload rubber, per-batch compound, and per-cycle vulcanization, and sync the latest feeding and process parameters |
| `nodeId` | Bind to the device node ID corresponding to internal mixers and vulcanizers | Accurately connect to real-time data from target production equipment, and avoid data source confusion |
| Single trigger limit | 1 time per vulcanization cycle | Align with the production cycle rhythm, and prevent repeated triggers that cause data chaos |
| Exception branch trigger conditions | Mixing temperature deviation ±5 degrees Celsius, vulcanization time deviation ±10% | Based on process control requirements, promptly trigger the exception report generation workflow |
| Context window size | 1000–1500 characters | Adapt to the content length of single-batch process documents, and ensure complete information |
| Variable update trigger timing | Trigger upon completion of raw material feeding nodes | Align with production process nodes, and ensure that variables passed to the workflow are the latest valid data |

## Common Configuration Mistakes
- Symptom: Raw material feeding weight fields are empty in generated process documents. Cause: The output of the weighing record node is not bound to the `variables` configuration item, causing variables to not be correctly passed to the document generation node.
- Symptom: Workflow trigger frequency exceeds capacity limits, generating multiple duplicate exception reports. Cause: A reasonable single trigger limit is not configured, and multi-node deployment to improve QPS carrying capacity is not enabled.
- Symptom: Generated exception reports do not include contextually associated process parameter information. Cause: The AI conversation node’s context output and reply content are not correctly distinguished, causing associated data to not be correctly brought into the workflow.
- Symptom: Exception reports do not identify under-vulcanization or over-vulcanization situations. Cause: Vulcanization temperature and time deviation settings are not configured as exception branch trigger conditions, so the corresponding exception handling workflow cannot be triggered.

## How to Verify Successful Configuration
- Trigger one simulated vulcanization cycle production process, and check if the generated process document includes all required fields.
- Check workflow trigger logs to confirm that the workflow is only triggered once after the production node is completed.
- Simulate a mixing temperature outside the deviation range, and check if the exception report generation workflow is triggered.
- Call the workflow application interface test address to verify the correctness of the trigger logic.
- Check the correspondence between the device node ID bound in the workflow and actual production equipment.
