# Process Document and Exception Report Drafting for Cement Clinker and Grinding: Tool Calling and Plugins

## What this category’s data looks like
Daily documents include raw material batching plans, kiln operation logs, laboratory reports, quality control notices, equipment inspection records, and energy reports.
Data comes from online composition analysis systems, DCS control systems, laboratory data, kiln and mill equipment sensors, raw and fuel ledgers, and energy metering instruments.
Update frequencies are split into three categories: real-time (equipment status, composition data), shift-based (inspection records, operation logs), and daily (quality control notices, energy reports).
Document fields include material ratios, temperature parameters, strength indicators, and energy consumption values. Units include percentage, degrees Celsius, megajoules, megapascals, and others.

## What constraints these characteristics impose on tool calling and plugins workflows
Real-time data retrieval requirements mandate that tool calling response times stay within reasonable limits. Otherwise, instant drafting of exception reports cannot be supported.
Heterogeneous data from multiple sources must be unified in format via plugins. This prevents field mismatches that cause logical confusion in generated process documents and exception reports.
Batch documents generated per shift or daily require batch processing plugins. This reduces manual sorting time.
Exclusive fields for different document types—such as batching items in raw material batching plans, temperature parameters in kiln operation logs—require clear extraction rules during tool calling. Otherwise, generated content will not match business scenarios.
Additionally, thermal stability requirements for cement clinker and grinding mean tool calling must prioritize real-time core data from kiln and mill equipment. This ensures report accuracy.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |

| `toolChoice` | `auto` | Adapts to automatic tool calling needs for multiple document types, covering data extraction across scenarios including batching, inspection, and laboratory work |
| Batch processing limit | 100 documents per shift | Matches the number of inspection and operation record documents generated per shift, preventing overload from single calls |
| Field mapping rules | Preset by document type | Corresponds to exclusive fields such as batching items in raw material batching plans and temperature parameters in kiln operation logs |
| Tool calling timeout duration | 300 seconds | Adapts to standard response times for DCS system data retrieval, preventing generation failures caused by missing real-time data returns |

## Three common mistakes
- Issue: Tool calling continuously returns slow operation logs, with MongoDB response delays. Cause: No timeout time set to match real-time DCS data retrieval, leading to tool calling wait timeouts.
- Issue: Configuring deepseek-r1 for tool calling results in large deviations in generated output. Cause: No preset field mapping rules exclusive to cement clinker and grinding, leading to extracted ratio, temperature, and other data that do not conform to business logic.
- Issue: Global counter plugin cannot achieve auto-increment. Cause: No binding of trigger conditions for the corresponding business scenario in plugin configuration, only basic variable update logic is configured.

## How to confirm configuration is complete
- Upload a raw material batching plan document, trigger tool calling, and verify that extracted ratio fields match the original document.
- Simulate a scenario where equipment temperature deviation exceeds the threshold, and check if the exception report drafting process is automatically triggered.
- Review tool calling logs to confirm timeout settings meet business response requirements, with no frequent timeout errors.
- Test the batch processing function, upload documents generated per shift, and confirm that the plugin completes format conversion and data integration normally.
