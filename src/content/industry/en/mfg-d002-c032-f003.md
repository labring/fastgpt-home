# Process Document and Exception Report Drafting for Complete Vehicle Final Assembly: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
The core thread of data for this category is the individual vehicle VIN. Data sources include ERP/MES systems, VIN and configuration systems, tightening tools, end-of-line (EOL) inspection stations, and quality traceability systems. Daily documents include production orders, VIN lists, assembly work instructions, tightening torque data, offline inspection reports, rework records, and consistency release documents. Systems update data per vehicle, in real time, and per shift. Fields include VIN code, torque value, inspection item number, and supplier batch number. Units include newton meters, percentage, and station number, among others.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
The core single-vehicle thread tied to VIN requires multi-turn dialogue to bind context for the corresponding VIN, to avoid confusion across vehicle configurations. Real-time updated tightening data and offline inspection data require the dialogue system to quickly pull the latest individual vehicle data, to avoid using expired information. Shift-updated team and station configurations require prompt engineering to adapt to that day’s production schedule and station permissions. High configuration complexity from mixed-model production requires multi-turn dialogue to gradually clarify assembly requirements, to prevent mismatched or missed installations. Exception report drafting must link to rework records and historical inspection data for the corresponding VIN, to ensure complete traceability logic.

## Configuration Settings
This page’s configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `chatId` | Bind the session ID to the current VIN | Ensure multi-turn dialogue always links to the exclusive data for the corresponding vehicle, avoiding context confusion |
| `messages` | Retain the most recent 20 rounds of dialogue content | Cover the full workflow from assembly to exception handling for a single vehicle, preventing loss of critical configuration information |
| `variables` | Inject the current VIN, station number, and that day’s production shift | Allow prompt engineering to directly call exclusive parameters for the current production scenario, without repeated queries |
| Maximum context length | 8000–12000 token | Accommodate multiple assembly documents and inspection data for a single vehicle, meeting dialogue needs for complex scenarios |
| Dialogue timeout period | 600 seconds | Handle cross-station exception data queries and document splicing, avoiding timeouts caused by large data volumes |
| Attachment upload limit | Single file no larger than 50 MB, supports PDF and CSV formats | Adapt to the size and format of common documents such as assembly work instructions and tightening data reports |

## Three common misconfigurations
- Issue: Dialogue records cannot be exported, or VIN association information is missing after export. Cause: The current VIN parameter is not bound in `variables`, so the dialogue context is not linked to exclusive vehicle data, and corresponding documents cannot be matched during export.
- Issue: Uploaded assembly work instructions cannot be recognized by the dialogue system. Cause: The attachment upload limit adapted for PDF and CSV formats is not set, or the attachment parsing switch is not enabled.
- Issue: Knowledge base calls return configuration data for unrelated vehicles. Cause: The VIN context of the current dialogue is not passed via `messages`, so the knowledge base recall does not filter by vehicle dimension.

## How to verify correct configuration
- Initiate a dialogue bound to a known VIN, check whether the configuration information for the corresponding vehicle automatically appears during the dialogue, to confirm that parameter injection works correctly.
- Upload a standard tightening data CSV file, verify that the dialogue can correctly parse and reference the torque data in the file, to confirm that attachment upload and parsing configurations are set properly.
- Start a multi-turn dialogue, send more than 20 consecutive interaction messages, check that the dialogue context does not get lost or confused, to confirm that the context retention rule is active.
- Try to export the dialogue record, check that the exported file includes the current VIN and associated production data, to confirm that the session association logic works correctly.

The values provided here are common starting points, and should be measured against the reader's own samples.
