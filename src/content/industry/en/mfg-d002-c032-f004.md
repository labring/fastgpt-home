# Drafting Process Documents and Exception Reports for Complete Vehicle Final Assembly: Workflow Orchestration

## What the Data for This Category Looks Like
This category of data centers on the Vehicle Identification Number (VIN) of individual vehicles. Typical daily documents include production orders, VIN lists, assembly work instructions, tightening data, offline inspection reports, rework records, and consistency and release documents. Data mainly comes from ERP/MES systems, VIN and vehicle configuration systems, supplier batch management modules, workshop tightening tools, EOL offline inspection lines, and quality traceability systems. Data is updated in real time per vehicle, or batched and aggregated per shift. Fields include unique vehicle identification codes, torque parameters, inspection results, part batch numbers, and more. Some documents require matching hundreds of vehicle configurations and corresponding part information.

## What Constraints Do These Characteristics Impose on Workflow Orchestration
The data characteristics of this category impose multiple specific constraints on workflow orchestration. The single-vehicle data chain centered on VIN requires workflows to support dynamic matching of configuration-specific datasets, and adapt to parallel processing of multiple vehicle models in mixed-line production. Real-time updated tightening data and offline inspection results require workflow nodes to support low-latency synchronous calls to data sources. Cross-system data from multiple sources must be spliced according to assembly process sequences, requiring `variables` to be configured to associate output fields from different modules. Drafting exception reports requires associating rework records and inspection results, requiring workflows to support multi-node data aggregation and verification. Production data batched and aggregated per shift requires support for batch processing to avoid overloading single nodes.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Define global variables by VIN, torque threshold, and inspection acceptance criteria, including `VIN code, 10–500 N·m torque threshold, 95% offline inspection acceptance threshold` | Match individual vehicle-specific configurations and process parameters, ensuring targeted process documents and exception reports |
| Node Trigger Timing | Trigger subsequent nodes after VIN matching is completed | Adapt to dynamic data call logic in mixed-line production, and avoid invalid node execution |
| `nodeId` | Assign unique `nodeId` to tightening data query and exception record retrieval nodes, using values `query_torque_001, query_repair_002` | Facilitate workflow debugging and data transfer between nodes, and avoid node ID conflicts |
| External Call Variable Passing | When configuring external interface calls, pass the `variables` parameter with values `production order number, VIN code, current station ID` | Support external platforms to pass real-time business parameters, and adapt to the need for dynamically generating process documents |
| Node Timeout | Set to `300 seconds` | Adapt to data return delays from workshop equipment, and avoid unexpected workflow interruptions |
| Result Reference Rule | Force reference to database query results when generating text | Avoid AI-generated content without basis, and ensure the accuracy of process documents and exception reports |

The configurations on this page are based on FastGPT v4.17.0.

## Three Common Misconfigurations
- Phenomenon: After a workflow calls a database query node, the generated process document or exception report does not include the queried tightening data or rework records. Cause: The mandatory result reference rule is not configured, causing the AI to not bind the output data of the query node.
- Phenomenon: When an external platform calls the published workflow interface, the passed global parameters are not recognized by the workflow, and the generated file lacks the exclusive configuration information of the corresponding vehicle. Cause: The external transfer entry for the `variables` parameter is not configured in the workflow, causing the variables passed by the interface to not be loaded.
- Phenomenon: In a workflow configured with multi-layered question tree nodes, the spliced text does not match the format of stored process documents, and custom variables cannot be added. Cause: The `variables` field is not configured according to the document structure associated with the individual vehicle VIN, causing failure to match the paragraph structure of the corresponding document during splicing.

## How to Verify Successful Configuration
- Initiate a test call, pass a real VIN code, and check whether the workflow automatically pulls the configuration and process data of the corresponding vehicle.
- View the workflow operation log, confirm that the `variables` parameter and nodes corresponding to `nodeId` execute normally without timeout errors.
- Generate an exception report, and verify whether the tightening data and rework records in it match the database query results.
- Call the external interface with custom business parameters, and confirm whether the workflow correctly loads and uses the passed parameters to generate files.

The values provided are common starting points and should be measured against the reader's own samples.
