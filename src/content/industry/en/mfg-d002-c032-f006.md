# Drafting Process Documents and Exception Reports for Complete Vehicle Final Assembly: Quote Sourcing and Traceability

## What the data for this category looks like
Data sources for complete vehicle final assembly scenarios include ERP/MES systems, VIN and vehicle configuration systems, supplier batch management systems, tightening tool terminals, End-of-Line (EOL) off-line inspection lines, and quality traceability systems.
Daily documents include production orders, VIN lists, assembly work instructions, tightening torque data, off-line inspection reports, rework records, and consistency release documents.
Data is generated in real time per vehicle and summarized and archived per shift. Each vehicle has hundreds of associated configuration and inspection fields. Core fields include VIN code, torque value (unit: newton-meter), inspection item number, supplier batch number, and station code.

## What constraints do these characteristics impose on quote sourcing and traceability
Mixed-model production that uses VIN as the single vehicle master identifier requires quote traceability to accurately bind exclusive configuration and production data for each vehicle. This prevents document confusion across vehicles.
Real-time updated tightening data and off-line inspection reports require recall logic to dynamically match newly generated documents.
The large number of associated documents per single vehicle requires limiting recall scope and context length. This avoids irrelevant data that causes redundant generation results.
Additionally, compliance requirements in final assembly scenarios require retaining metadata associations for original documents. This ensures every quote can be traced back to specific production links and data sources.

## How to Configure Settings
This content is based on FastGPT v4.17.0 configuration guidelines.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | `8000–12000 token` | Final assembly process documents and exception reports include multiple sections of tightening data and VIN-associated configuration information. Sufficient context is needed to carry all full fields required for traceability, and avoid truncating critical traceability information |
| `responseData` | Return original document metadata | Drafted exception reports and process documents need to associate specific fields such as tightening tool number, inspection station number, and supplier batch number. Returning metadata ensures traceability of quoted content |
| `detail` | Enable full traceability mode | Full traceability mode retains all associated information from original documents. This meets traceability requirements for single-vehicle production data in final assembly scenarios |
| Number of documents recalled per single run | Top 8 entries | Mixed-model production limits the number of exclusive documents per vehicle. Too many recalled entries will introduce irrelevant data and reduce the accuracy of generation results |
| Context window | `16000–20000 token` | Need to carry both VIN-matched configuration documents, tightening data, and original exception report content. This avoids context overflow that causes generation interruptions |

## Three Common Configuration Errors
- When testing configured models, an error prompt appears. Forcing ignore and running generates content but has insufficient quote entries. Rules for filtering recall results by VIN tags are not configured, so the recall scope covers all knowledge base documents and only the first associated data is matched.
- The workspace knowledge base application only retrieves a single document each time. Vehicle-specific filter conditions are not bound, so only the default recall logic of the global knowledge base is triggered, and all associated documents corresponding to the VIN are not matched.
- Knowledge base quote limit is insufficient. `quoteMaxToken` or the number of single-recall documents are not adjusted, so the number of quoteable documents cannot meet the multi-field traceability requirements of final assembly scenarios.

## How to Confirm Configurations Are Correct
- Enter a specific VIN code. The returned document list includes assembly work instructions, tightening torque data, and off-line inspection reports corresponding to that VIN.
- Every quote in the generated process document or exception report includes metadata fields from the original document, such as station code and supplier batch number.
- No error prompts appear during test calls. Quote markers in generated content correspond one-to-one with original document numbers.
- After replacing the VIN code, the recalled document list automatically updates to exclusive production data corresponding to the new VIN. No redundant irrelevant documents are included.
