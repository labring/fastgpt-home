# Drafting Process Documents and Exception Reports for Complete Vehicle Final Assembly: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Data for the complete vehicle final assembly scenario is generated per individual vehicle VIN. Sources include ERP/MES systems, VIN and configuration systems, supplier batch libraries, tightening tools, EOL inspection lines, and quality traceability systems. Daily documents cover production orders, VIN lists, assembly work instructions, tightening torque data, offline inspection reports, rework records, and consistency release documents. Data updates follow two schedules: real-time synchronization per vehicle, and batch updates per shift. Core fields include VIN, vehicle model batch, torque parameters, inspection results, and more. The core focus is individual vehicles. In mixed-line production, exclusive configuration requirements for different vehicle models must be distinguished.

## What constraints these characteristics impose on knowledge base retrieval and recall
The property that a single vehicle VIN is associated with hundreds of configuration items requires retrieval to precisely match exclusive fields, and prevents irrelevant cross-model results from being returned. Real-time updated tightening data and offline inspection reports require the retrieval pipeline to support low-latency real-time data recall. Otherwise, real-time on-station process verification cannot be supported. Multi-source and heterogeneous document types require retrieval to adapt to matching logic for both structured parameters and unstructured text. In mixed-line production scenarios, the retrieval scope must be limited to the knowledge base for the vehicle model corresponding to the current station. This avoids context overload that slows down drafting efficiency, and ensures the confidence of retrieval results. It also prevents misassembly or missed assembly that could cause production line downtime or recall risks.

## How to set configurations
The following configurations are based on FastGPT v4.17.0:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the semantic similarity requirements for process parameters and VIN-associated configurations in vehicle final assembly scenarios, and balances recall completeness and accuracy |
| `limit` | Top 8 entries | Single-batch retrieval return limit, adapts to the retrieval volume of hundreds of configuration items per single VIN, and avoids context overload |
| `searchMode` | hybrid | Combines keyword and semantic retrieval, adapts to mixed structured and unstructured documents such as assembly work instructions and tightening data |
| `usingReRank` | Enabled | Reranks recall results, resolves redundant result issues, and prioritizes matches to current station process requirements |
| `datasetSearchUsingExtensionQuery` | Enabled | Expands exclusive fields such as VIN and vehicle model batch based on the original query, improving configuration matching accuracy |
| `collectionIds` | Specified by vehicle model batch | Limits retrieval scope to the process library and quality traceability library for the corresponding vehicle model, narrowing the retrieval range |

## Three Common Errors
- Retrieval returns a large number of redundant results, making it impossible to quickly locate the process requirements for the current station. The cause is that the `usingReRank` reranking function is not enabled, and the retrieval knowledge base scope is not limited via `collectionIds`.
- The interface shows a semantic retrieval score of 0.77, but the model prompts that relevant information cannot be found. The cause is that `datasetSearchUsingExtensionQuery` is not enabled to expand exclusive fields such as VIN and vehicle model batch, resulting in failure to match exclusive configuration data for individual vehicles.
- An error occurs when the workflow executes retrieval and fails to load multiple knowledge base contents. The cause is that multiple `collectionIds` parameters are not passed in the correct format, or access permissions for the corresponding knowledge bases are not configured.

## How to Confirm the Configuration Is Properly Set
- Enter a process query that includes a specific VIN, and check whether the retrieval results include exclusive content such as assembly work instructions and tightening parameters for the corresponding vehicle model.
- View the retrieval log, confirm that the `similarity` score falls within the preset range, and that the number of returned results matches the `limit` setting.
- Switch queries for different vehicle models, verify that `collectionIds` automatically limits the scope to the knowledge base for the corresponding vehicle model, and prevents irrelevant cross-model results from being returned.
- Compare the result ranking before and after enabling `usingReRank`, confirm that the reranking function is active, and prioritizes content relevant to the current station.

The values provided are common starting points, and should be measured against the reader's own samples.
