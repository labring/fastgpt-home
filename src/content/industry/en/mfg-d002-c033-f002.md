# Process Document and Exception Report Drafting for High-Volume Automotive Component Manufacturing: Vector Models and Indexes

## What the data for this category looks like
Data for this category comes from business documents of suppliers of automotive braking, steering, chassis, interior and exterior, and powertrain system components. These documents include control plans, process flow diagrams, work instructions, first article and inspection records, SPC reports, PPAP materials, and 8D reports. Data sources cover customer drawings and special characteristic lists, ERP/MES systems, measurement and inspection tool data, equipment process parameters, and supplier quality certificates. Updates occur per production batch, per shift, and through continuous real-time collection. Documents contain fixed business fields and dynamic parameters, and some require matching customer-specified formats.

## What constraints these characteristics impose on the vector models and indexes link
Multi-source heterogeneous data sources mean vector models must adapt to semantic encoding of both structured parameters and unstructured text. The high-frequency update cadence demands indexes support incremental writes and scheduled refreshes to avoid data lag. The requirement for documents to match customer-specific formats requires retaining field-level associations in vector indexes to prevent loss of key business identifiers such as special characteristics. Exception report documents include long text segments, so models must support sufficient input length to fully encode root cause analysis content. Combined with the local deployment environment of FastGPT v4.17.0, it is necessary to adapt to hardware resource limits and balance encoding accuracy and computational overhead.

## How to set the configurations
| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Ensures semantic integrity for long documents such as work instructions and 8D reports, avoids truncating key process steps across chunks |
| Overlap Length | 100–200 characters | Retains contextual association between adjacent chunks, prevents process parameters and exception causes from being split across chunks |
| `maxToken` | 4096 token | Supports long-text encoding for PPAP materials and complete SPC reports, aligns with the local model support scope of FastGPT v4.17.0 |
| `defaultToken` | 512 token | Used for efficient encoding of first article inspection records and short exception descriptions, balances computational resources and semantic accuracy |
| Single Search Limit | Top 10 results | Matches the high-frequency exception retrieval needs of high-volume manufacturing scenarios, avoids redundant results interfering with root cause analysis |
| Reranking | Enabled | Performs semantic reranking of retrieved process documents to meet the precise matching requirements of customer special characteristics |

## Three common errors
- Phenomenon: Retrieval error occurs after switching vector databases, returning a dimension mismatch prompt. Cause: Vector dimension parameters were not unified, the embedding dimensions of the original index and new database are inconsistent, and the unified encoding requirements for batch documents were not met.
- Phenomenon: Local vector model fails to load, displaying an out-of-memory error. Cause: A model lightweightly adapted to NVIDIA 1080ti hardware was not selected, system video memory was not reasonably allocated, and GPU resources were not correctly mapped when using the WSL deployment environment.
- Phenomenon: Retrieval results fail to match customer-specified special characteristic fields. Cause: Fixed field associations for special characteristics were not retained during chunking, resulting in loss of key business identifiers in the vector index and inability to accurately match retrieval requests.

## How to confirm the configuration is correct
- Upload a single complete 8D report, check if the chunked text fragments retain complete root cause analysis and containment measure paragraphs, with no critical content truncated.
- Submit a retrieval request containing customer special characteristics, verify that the returned results are sorted to prioritize matching the target characteristic fields.
- Batch upload 10 inspection records generated on the same day, check if the index update task completes within the preset time with no timeout errors.
- View the vector embedding logs, confirm that the `defaultToken` and `maxToken` parameters have taken effect as configured, with no parameter conflict prompts.

The values provided are common starting points and should be measured against the reader's own samples.
