# Drafting Process Documents and Exception Reports for High-Volume Automotive Component Manufacturing: Knowledge Base Retrieval and Recall

## What This Category's Data Looks Like
Data for this category comes from customer drawings and special characteristic lists, ERP systems, MES systems, measuring tools, equipment process parameters, and supplier quality certificates.
Daily documents include control plans, process flowcharts, work instructions, first article and patrol inspection records, SPC reports, PPAP materials, and 8D reports.
Data is updated per batch, per shift, and via continuous collection.
Documents include exclusive business fields such as special characteristic numbers, process parameter thresholds, and batch numbers.
The data structure covers process, record, and report types.

## Constraints on Knowledge Base Retrieval and Recall
Multi-source heterogeneous data sources require retrieval logic to support cross-knowledge base associated recall, and adapt to document formats exported from different systems.
High-frequency update cycles require recall mechanisms to support incremental synchronization, avoiding repeated processing of full datasets.
Diverse document types and exclusive business fields require retrieval rules to balance semantic matching and precise field matching. This ensures recalled content is strongly relevant to automotive component manufacturing professional scenarios.
High-volume manufacturing business characteristics require controlling the context length of retrieval results to avoid exceeding processing limits. It also requires associating compliance-related documents to meet quality system constraints from vehicle customers.

## Configuration Settings
This configuration is based on FastGPT v4.17.0. The specific parameter settings are as follows:

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | Matches the precision of automotive component terminology and exclusive fields, filters irrelevant general process content |
| `limit` | Top 8 entries | Controls the context length returned per retrieval round, adapts to multi-document associated processing in high-volume manufacturing scenarios |
| `searchMode` | `mixedRecall` | Combines semantic matching and keyword matching, covers precise business fields such as special characteristic numbers and equipment parameters |
| `usingReRank` | Enabled | Reorders recall results by business relevance, prioritizes core manufacturing documents such as first article records and PPAP materials |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands associated compliance verification and expert interpretation knowledge base content based on user queries |
| `collectionIds` | Configured in three groups: process, exception, compliance | Distinguishes document collections across different business domains, enabling targeted precise retrieval |

## Three Common Configuration Mistakes
- Retrieval results return a large number of irrelevant general machining documents. This occurs when the `similarity` threshold is not configured, or is set too low, and the special characteristic fields exclusive to automotive components are not matched.
- Large documents are not prioritized for processing after upload, and no manual pause or resume function is available. This occurs when the priority scheduling logic for the knowledge base upload queue is not enabled, and the asynchronous processing configuration for document segmentation is not connected.
- Business fields in retrieval results are empty or have mismatched units. This occurs when precise retrieval rules are not configured for exclusive automotive component fields such as ppm and process parameters, and metadata verification for the corresponding collection is not associated.

## How to Verify Correct Configuration
- Enter a query containing a specific special characteristic number, and check whether retrieval results prioritize returning corresponding control plans, PPAP materials, and other relevant documents.
- Upload one large document and multiple small documents, and check whether the upload queue prioritizes processing small documents and supports pause and resume operations.
- View the metadata of retrieval results, and confirm that the correct `collectionIds` grouped collection is associated.
- Trigger a query related to exception report drafting, and check whether associated business documents such as 8D reports and SPC reports are automatically recalled.

The values provided are common starting points and should be evaluated against the user’s own samples.
