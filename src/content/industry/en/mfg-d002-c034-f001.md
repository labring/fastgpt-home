# Drafting Process Documents and Exception Reports for Baking and Convenience Food Industries: HTTP Interfaces and External Systems

## What the Data for This Category Looks Like
Typical entities are factories producing bread, pastries, biscuits, instant noodles, and frozen steamed goods. Daily documents include formulas and feeding lists, production records, baking or steaming curves, metal detection records, cleaning and disinfection records, and factory inspection reports. Data sources include raw and auxiliary material qualification certificates, ERP/MES systems, weighing systems, oven or frying line equipment, laboratory test results, and food traceability ledgers. Update frequency is per batch, per shift, or daily. Fields include allergen material identifiers, baking temperature and duration, packaging date, shelf life, metal detection results, and more. Units are mostly degrees Celsius, minutes, grams, and standard date formats.

## Constraints Imposed on HTTP Interfaces and External Systems by These Characteristics
Because data sources are scattered and update frequencies vary, the interface must support concurrent pulling of different types of production data from multiple sources. Because formula line changes happen frequently, the interface must support dynamically passing variables such as batch numbers and production line IDs to accurately pull documents for the corresponding production cycle. Because high-risk scenarios such as allergen mislabeling and foreign matter recall are involved, the interface return must include complete traceability fields. Because document structures vary, the interface must adapt to extraction of text and numeric fields in different formats. Additionally, the update rhythm per batch or per shift requires that the interface call frequency can be flexibly adjusted to avoid triggering rate limiting rules of external systems.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Call timeout | 60–120 seconds | Accommodates latency requirements for pulling large text such as baking curves and feeding lists |
| Retry attempts | First 3 attempts | Addresses temporary fluctuations in interfaces for weighing systems and oven data |
| `Authorization` | Fixed Bearer token | Complies with identity verification specifications of external systems |
| `variables` | Pass batch number, production line ID | Accurately pull document data for the corresponding production cycle |
| `responseData` | Only return allergen, test result, and shelf life fields | Reduces invalid data transmission and improves interface efficiency |
| Request body format | application/json | Meets interface requirements of most ERP/MES systems |

## Three Common Mistakes
- Phenomenon: The allergen field returned by the interface is empty. Cause: The production line allergen configuration parameter was not passed in `variables`, causing the external system to not return the corresponding field, which in turn leads to the risk of allergen mislabeling.
- Phenomenon: The request returns status code 429, and calls fail frequently. Cause: The call interval was not adjusted according to the update frequency per batch or per shift, triggering the rate limiting mechanism of the external system.
- Phenomenon: The packaging date in the generated exception report does not match the actual value. Cause: Real-time data from the packaging machine was not pulled from `responseData`, and only fixed template fields were used, leading to failed traceability.

## How to Confirm the Configuration Is Correct
- Initiate a single interface call for one batch, and check whether the returned fields include preset content such as allergens and baking parameters.
- Simulate multiple high-frequency calls, observe whether the external system's rate limiting mechanism is triggered, and adjust the call interval to meet requirements.
- Check whether the `Authorization` token is valid, and verify that the identity verification process for interface calls works properly.
- Compare the interface returned data with the original records in the ERP/MES system to confirm consistency of field values.

The values provided are common starting points and should be measured against samples from the target deployment.
