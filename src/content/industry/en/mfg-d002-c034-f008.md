# Document Parsing and Chunking for Craft Document and Exception Report Drafting in Baking and Convenience Food Industry

## Data Profile for This Category
Baking and convenience food factories maintain daily documents including recipes and feeding lists, production records, baking or steaming curves, metal detection records, cleaning and disinfection records, and factory inspection reports. Data sources cover raw and auxiliary material qualification certificates, ERP/MES systems, weighing equipment, ovens and frying lines, laboratory testing systems, and food traceability ledgers. Updates occur per production batch, shift, or daily. Individual documents include fields such as feeding volume, baking temperature, time, allergen labels, packaging date, and shelf life. Some documents contain vector charts and table structures.

## Constraints for Document Parsing and Chunking
This category has frequent line changes, and single-batch document formats vary. Accurate matching of different document structures is required for chunking. Allergen and cleaning and disinfection records involve sensitive compliance information. Chunk boundaries must avoid crossing sensitive fields. Large baking curve PDFs and multi-batch production record files have large file sizes. Parsing durations often exceed default thresholds. Repeated production record templates and standardized feeding lists easily generate duplicate chunks. Deduplication logic must be controlled to avoid disrupting custom chunk order. Additionally, the ready-to-eat product attribute requires document parsing to retain original field integrity. Key compliance information must not be lost due to chunking.

## Configuration Guidelines
The following configurations are formulated for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the field density of baking recipes and production records, avoids chunking across feeding batch or allergen information |
| `chunkSplitter` | Split by paragraph + table | Matches line breaks and table structures in production records, retains complete units of feeding lists and inspection forms |
| `customPdfParse` | Enabled | Adapts to vector charts in baking curves and stamped formats in cleaning and disinfection records, retains original typesetting |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Addresses multi-batch production records uploaded in batches, avoids parsing timeout for large curve files |
| `chunkSettingMode` | Manual mode | Allows separate adjustment of chunk boundaries for allergen-related documents, avoids crossing sensitive information boundaries |

## Three Common Misconfigurations
- Phenomenon: Duplicate document chunks in the knowledge base are automatically deleted, and the index order of custom chunks is disrupted. Cause: The default duplicate chunk deduplication logic is not disabled, leading to a mismatch between the matched index after chunking and the preset order.
- Phenomenon: A timeout error is returned when parsing large baking curve PDFs. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted, and the default timeout duration is insufficient for vector chart parsing.
- Phenomenon: Chunked content includes cross-batch allergen and non-allergen information. Cause: The `chunkSettingMode` manual mode is not enabled, and default automatic chunking causes boundaries to cross sensitive fields.

## How to Validate Configuration
- Upload a single cleaning and disinfection record with allergen labels, and check if the chunking result treats the allergen field as a separate chunk unit.
- Upload a baking curve PDF larger than 10MB, and confirm that the parsing status completes within a reasonable duration with no timeout errors.
- Upload a standard feeding list table document, and check if the chunking result retains the complete row and column structure of the table with no content splitting errors.
- Call the parsing status query API, and confirm that the parsing status of the uploaded file correctly displays as ready, parsing, or failed, matching the actual progress.

The values given are common starting points and should be measured against the reader's own samples.
