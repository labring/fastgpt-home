# Drafting Process Documents and Exception Reports for Production Planning and Shop Scheduling: Workflow Orchestration

## Data Profile for This Category
Data for this category primarily comes from enterprise ERP systems, process BOM libraries, shop floor equipment monitoring modules, and supplier arrival ledgers. Daily processed documents include sales orders, master production schedules, material requirements plans, weekly and daily production schedules, work orders, material shortage lists, and delivery change notices.

Data update rhythms vary by business scenario: equipment capacity and staff shift data is synced daily, master production schedules are updated weekly, and documents such as work orders and material shortage lists are updated in real time when orders are released or exceptions occur.

Document fields include order numbers, material codes, process working hours, equipment numbers, inventory balances, delivery requirements, and more. Some documents require associated units: working hours are measured in hours, capacity in units per shift, and inventory in units.

## Constraints Imposed on Workflow Orchestration by These Characteristics
Decentralized data sources with inconsistent update rhythms require workflow orchestration to support scheduled pulling from multiple data sources and real-time triggers.

Multiple document types with significant field differences require configuring unified data parsing rules within the workflow to adapt to field mapping across different documents.

A wide range of exception trigger scenarios requires supporting branch orchestration for abnormal events such as emergency order additions, material shortages, and equipment failures.

High data association requirements require passing key parameters such as work order numbers and material codes across nodes via `variables` to ensure data consistency across all workflow links. It is also necessary to adapt to permission ranges of different departments, restricting access to specific nodes.

## Configuration Guidelines
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Global variable `variables` | Preset three core fields: work order number, material code, equipment capacity threshold | Adapt to parameter transfer needs for multi-document association, reduce repeated configuration between nodes |
| Node trigger rules | Trigger via three methods: order submission, exception report, scheduled task | Match different data update rhythms, cover daily scheduling and emergency handling scenarios |
| Tool call timeout | 600 seconds | Align with typical time required for ERP data pulling and process document generation, avoid interrupting the overall workflow due to single-node stall |
| Knowledge base recall limit | Top 5 entries | Match precise information needs in shop scheduling scenarios, avoid redundant data interfering with workflow execution |
| `nodeId` configuration | Assign a unique identifier to each data source node | Facilitate locating abnormal nodes during debugging, quickly troubleshoot data pulling or parsing issues |
| Generated document length limit | 800–1200 characters | Align with standard format requirements for shop floor process documents and exception reports, avoid reduced readability from overly long content |

## Three Common Configuration Errors
- Two separate thought process logs appear when debugging a tool call node. This occurs when the workflow's automatic thinking switch is not disabled, causing the node to execute both tool call and context completion logic simultaneously.
- Global variable fields are empty after workflow execution. This happens when variable mapping rules are not configured in the data source node, and order fields returned by the ERP are not correctly assigned to the preset `variables`.
- Unable to retrieve MCP tool execution results via API call. This is caused by not binding the MCP tool node in the workflow, and not using `nodeId` to identify the unique entry for the tool call.

## How to Confirm Configuration Completion
- Manually trigger a workflow triggered by order submission, verify that each data source node has pulled the correct ERP order data.
- Debug the tool call node, confirm that the timeout setting behaves as expected, with no early interruptions.
- Review the global variable assignment log, confirm that fields such as work order numbers and material codes have been correctly populated into `variables`.
- Generate a test exception report, check that the document length falls within the 800–1200 character range, and that content matches preset business fields.

The values provided are common starting points and should be measured against the reader's own samples.
