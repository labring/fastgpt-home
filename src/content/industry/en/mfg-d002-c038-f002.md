# Process Document and Exception Report Drafting for Biologics and Aseptic Manufacturing: Vector Models and Indexes

## What the data for this category looks like
Data for this category comes from cell banks and seed lots, process analysis systems, clean zone monitoring records, MES, LIMS, and equipment integrity test results. Daily documents include cell bank or seed lot records, culture and purification records, aseptic filling records, environmental monitoring data, media fill simulation reports, sterility test results, and batch release documents. Data updates occur per production batch, with real-time monitoring data uploads and updates following fixed monitoring plans. Document fields include batch identifiers, culture temperature, settleable microbial concentration, equipment runtime, and other fields. Some fields must match the compliance record format required for aseptic manufacturing.

## What constraints do these characteristics impose on the vector models and indexes workflow
This category’s data is multi-source and scattered, including structured compliance records and unstructured monitoring logs. This requires vector indexes to support associated retrieval across multiple data sources. The data update cadence includes both real-time and batch updates, so indexes must support incremental updates to avoid the time cost of full reconstruction. Document fields must align with aseptic manufacturing compliance requirements, with some fields having fixed format constraints. Vector models must adapt to mixed vectorization of long texts and structured fields. Additionally, retrieval results for process documents and exception reports are directly linked to production compliance, so retrieved results must have high confidence to prevent low-correlation content from interfering with judgment.

## How to set configurations
| Configuration Item | Recommended Setting Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the long compliance documents in this category, avoids splitting key process parameters across chunks |
| Overlap Length | 100–150 characters | Covers the association logic of process parameters across chunks, prevents critical steps from being truncated by chunking |
| Similarity Threshold | 0.75–0.85 | Matches the strict compliance requirements of aseptic manufacturing data, filters low-correlation non-compliance records |
| Single Search Limit | Top 10 results | Controls the scale of retrieval results, avoids excessive data interfering with rapid identification of exception reports |
| `defaultToken` | Set from representative sample documents | `defaultToken` is the default token count for direct text chunking; tune it on representative source documents. See the [v4.17.2 model-field reference](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx). It is not a vector dimension, embedding-model input cap, or retrieval/LLM context. |
| Maximum Context | 6000 tokens | Balances retrieval recall and model processing capability when paired with the `defaultToken` setting |

## Three common errors
- Phenomenon: Vector index construction fails, returning status code 500. Cause: Fails to adapt to format differences across multi-source data in this category. Directly applying general chunking rules to structured compliance records causes loss of key field associations during chunking.
- Phenomenon: Response latency is too long during repeated queries. Cause: No caching mechanism is configured. Each query directly accesses the vector database, with no reuse of previously retrieved results.
- Phenomenon: After calling the create training order interface, the knowledge base does not generate the corresponding index. Cause: Fails to clarify the difference between training orders and collection data addition. Training orders are used for batch vectorization processing of multi-source heterogeneous production data. Collection data addition only supports direct index creation for single or small volumes of text.

## How to confirm correct configuration
- Import a batch of typical documents for this category, verify that chunked text fully retains key process parameters and compliance fields.
- Initiate two identical queries, confirm that the second query’s response latency is significantly lower than the first, to validate that the caching mechanism is active.
- Retrieve keywords related to exception reports, check that the relevance of returned results meets the strict requirements of this category, and adjust the similarity threshold to an appropriate range as needed.
- Call the create training order interface, confirm that the corresponding index task starts normally and generates traceable task records, to validate that the interface function matches business needs.

All provided configuration values are common starting points, and should be evaluated against the reader’s own specific samples.
