# Process Document and Exception Report Drafting for Electric Motor and Generator Manufacturing: HTTP Interfaces and External Systems

## What this category’s data looks like
Core data for this category comes from electromagnetic design systems, copper wire and insulating material batch ledgers, winding equipment, balancing machines, electrical test benches, and ERP/MES systems. Daily produced documents include winding process cards, insulation treatment records, dynamic balance reports, withstand voltage insulation test reports, type and factory inspection reports. Fields cover winding turns, impregnation temperature, vibration amplitude, withstand voltage value, and other metrics, with some fields including clear units. Data is updated once per motor or per product batch, and all associated documents are fully updated synchronously when a type change occurs.

## What constraints do these characteristics impose on HTTP interfaces and external systems
Field names from multiple data sources vary, so standardized mapping must be completed before interface calls, otherwise field mismatches will occur during knowledge base retrieval. The volume of data pushed in a single request is limited by the production rhythm of each motor or product batch, and should not be too large, otherwise the risk of interface timeout increases. There are many numeric fields with units, so the interface must support structured transmission of numeric values bound to their units, to ensure that stored data can be retrieved by dimension. The generation of exception reports is strongly tied to equipment test results, and must be synchronized to the knowledge base in real time, so the interface response delay must align with the time required for the test process.

## Three common misconfigurations
- Calling the pushData interface returns "Request parameter exceeds limit" with status code 413. The cause is that the number of data groups pushed in a single request exceeds 200 sets, and data is not split into batches.
- When configuring the model response format, the json_object option cannot be found. The cause is that the custom response format switch in FastGPT's model configuration has not been enabled, or a model version that supports this format has not been bound.
- Unable to pass a withstand voltage test CSV file when using the HTTP tool. The cause is that the file input parameter support configuration for the HTTP tool has not been enabled, or file binary data has not been encapsulated as required.

## How to confirm the configuration is complete
- Call the batch push interface, pass 1 set of test data, check whether the corresponding entry is generated in the knowledge base, and adjust the field mapping rules to match the business document structure.
- View the `responseData` returned by the interface, confirm that it contains the status code and error information, and verify whether the exception troubleshooting link is available.
- Simulate a full data push for a single motor, check that the interface response time meets the business real-time requirements, and adjust the timeout configuration to a reasonable range.
- Test the file input parameter function, confirm that the withstand voltage test CSV file can be uploaded normally and synchronized to the knowledge base, and verify whether the file transmission configuration takes effect.
