# Process Document and Exception Report Drafting for Electric Motor and Generator Manufacturing: Vector Models and Indexes

## What data looks like for this category
Core data for this category comes from business systems and equipment used by winding, insulation, final assembly, and testing departments at motor factories. Daily documents include winding process cards, insulation treatment records, dynamic balance test reports, voltage withstand insulation test records, and type and factory inspection reports.
Data sources include electromagnetic design data, copper wire and insulation material batch ledgers, winding equipment operation logs, balancing machine test data, electrical test bench test results, and production work orders from ERP and MES systems.
Data is updated once per finished product or production batch. All associated documents are synced for updates when a product type is changed.
Document fields include technical parameters with defined units, such as winding turns, insulation class, test voltage, and temperature rise value.

## What constraints these characteristics impose on vector models and indexing
Data sources include multiple types of device logs, test reports, and production ledgers. This requires support for vector conversion of multimodal data, so multimodal vector models must be adapted.
High-frequency updates per unit or batch require indexes to support incremental updates. This avoids performance losses caused by full index reconstruction.
Documents include technical parameters strongly tied to units, such as winding turns and withstand voltage values. Vector indexes must retain semantic associations between fields to prevent matching deviations caused by unit confusion.
Minor adjustments to document structure from product type changes require flexible adjustment of indexing chunking rules. This adapts to the varying lengths of process cards and test reports.

## Configuration Settings
This document applies to FastGPT v4.17.0 vector model and index configurations.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Chunk Length | 800–1200 characters | Adapts to the length of single-segment technical parameters in winding process cards and test reports, prevents splitting of core parameters |
| Overlap Length | 100–150 characters | Retains semantic connections between adjacent chunks, prevents loss of cross-chunk content such as winding turns and wiring instructions |
| `maxToken` | 8192 | Matches the input length limit of multimodal vector models, covers the full content of type inspection reports |
| Similarity Threshold | 0.75–0.85 | Differentiates precise matching of technical parameters from fuzzy matching of general text, avoids false recalls of exception reports |
| Single Search Limit | Top 5 results | Limits the number of returned test reports and process cards, meets the quick lookup needs of engineers |
| `defaultToken` | Set from representative sample documents | `defaultToken` is the default token count for direct text chunking; tune it on representative source documents. See the [v4.17.2 model-field reference](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx). It is not a vector dimension, embedding-model input cap, or retrieval/LLM context. |

## Three common configuration errors
- Phenomenon: After deployment, calls to the vector model API return a 500 error, and the interface displays "Model configuration invalid". Cause: The call key and access domain name of the cloud vector model are not configured correctly, or the selected model does not support multimodal data parsing.
- Phenomenon: After index construction is complete, searches for winding turns return no results. Cause: Chunk length is set too large, splitting complete paragraphs containing turns into multiple chunks, and insufficient overlap length leads to semantic loss.
- Phenomenon: Index updates time out when uploading insulation treatment records in bulk. Cause: Incremental index mode is not enabled, and each upload triggers full index reconstruction, exceeding system processing limits.

## How to confirm successful configuration
- Upload a single winding process card, access the vector index preview page, and confirm that chunked text does not split core technical parameters such as winding turns and insulation class.
- Initiate a search request for a specific test parameter, and confirm that returned results include valid fragments of the corresponding document.
- Submit an incremental update task, and confirm that the index status changes from "Pending Update" to "Completed" with no timeout errors.
- Switch the vector model configuration, and verify that search result relevance aligns with preset matching rules.

The values given are common starting points and should be measured against the reader's own samples.
