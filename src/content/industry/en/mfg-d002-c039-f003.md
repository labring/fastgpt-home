# Motor and Generator Manufacturing: Process Document and Exception Report Drafting, Multi-turn Dialogue and Prompt Words

## What the data for this category looks like
Data sources include electromagnetic design data, copper wire and insulation material batches, winding equipment, balancing machines, electrical test benches, and ERP/MES systems. Update frequency is once per motor or per production batch, with synchronized updates for each design change. Daily documents include winding process cards, insulation treatment records, dynamic balancing reports, voltage withstand insulation test records, type test and factory inspection reports. Fields cover winding turns, insulation thickness, dynamic balancing value, voltage withstand value, temperature rise data, etc., with corresponding units: turns, millimeters, gram-centimeters, kilovolts, degrees Celsius.

## What constraints do these characteristics impose on the "multi-turn dialogue and prompt words" link
Category data is updated per batch or per single unit, requiring that dialogue contexts must be bound to the corresponding batch number to avoid mixing data from different batches. Fields and units for multiple types of professional documents have strict specifications, so prompt words must clearly specify field names and corresponding units to ensure generated process documents and exception reports meet standards. Multi-turn dialogue needs to connect documents from different stages such as winding, insulation, final assembly, and testing, and guide users to provide data step-by-step according to processes to avoid cross-stage information confusion. At the same time, exception data comes from multiple types of equipment and systems, so dialogue needs to gradually integrate information from different sources to ensure analysis accuracy.

## How to set the configuration
The configuration examples on this page are formulated based on the interface specifications of FastGPT v4.17.0.

## Three common misconfigurations
- LaTeX formatting renders correctly during debug preview, but only raw code is displayed after publishing. This occurs because the global LaTeX rendering configuration is not enabled, and the function is only enabled in the local debug environment.
- Custom prompt words do not trigger expected professional content generation. This occurs because category-specific fields such as winding turns and insulation thickness are not bound to the `variables` parameter, so the prompt words cannot call preset data templates.
- Dialogue experiences continuous lag and no response after Docker deployment. This occurs because the historical storage length of `messages` is not limited, resulting in excessive session context data volume for a single motor batch that occupies resources.

## How to confirm the configuration is correct
- Enter professional fields such as winding turns and insulation thickness, and check whether the `variables` parameter automatically fills in the corresponding preset values.
- Send test content containing LaTeX formulas, and confirm that the format renders correctly on the published dialogue interface.
- Create a session by binding the motor batch number, and check whether the `chatId` correctly associates the corresponding production data.
- Initiate a multi-turn dialogue to simulate the process connection from winding to insulation, and confirm that historical messages in `messages` are stored in segments according to process stages.
