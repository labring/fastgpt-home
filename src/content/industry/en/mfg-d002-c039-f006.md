# Process Document and Abnormal Report Drafting for Electric Motor and Generator Manufacturing: Source Citation and Traceability

## What This Category’s Data Looks Like
Data for this category originates from daily operational documents of motor factory winding, insulation, final assembly, and testing departments. Documents include winding process cards, insulation treatment records, dynamic balance reports, voltage withstand insulation test records, and type and factory acceptance test reports. Data sources cover electromagnetic design data, copper wire and insulating material batch information, winding equipment operation data, balancing machine test results, electrical test bench parameters, and ERP/MES system records. Updates are generated per unit or per production batch, and synchronized after each design change. Document fields include winding turns, wiring methods, paint dipping process parameters, vibration and temperature rise data, and test results. Documents are linked to material batches and equipment operation logs.

## Constraints for Source Citation and Traceability
Operational data for this category links to individual units or batches of materials and equipment logs. The traceability process must accurately match specific document blocks and original production data for individual batches, to avoid generalized citations. Document updates are triggered by batch production and design changes. The system must support incremental knowledge base synchronization, and prioritize matching the latest document versions during traceability. Professional fields such as winding turns and voltage withstand test results must link to field weights corresponding to their document types, to ensure citation relevance. Additionally, due to the serious consequences of abnormalities, traceability must fully display specific fields of the citation source and the source document, without omitting key information. The workflow must also support dynamic incoming knowledge base variable calls, and control the return format of the citation list.

## Recommended Configuration Settings
This configuration plan is adapted to this category, based on the FastGPT v4.17.0 version logic.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 characters` | Single blocks of process documents and test reports for this category are lengthy, and this range can accommodate complete process parameter or test result snippets |
| `responseData` | `Return citation source list + original text snippet` | The system must display specific fields and source documents of citations to process drafting personnel, to meet traceability requirements |
| `detail` | `Enabled` | Abnormal reports for this category must link to specific test data or equipment logs. Enabling this parameter displays more detailed citation context |
| Single search result limit | `Top 6 results` | This category has many document types. Filtering the top 6 most relevant documents for traceability avoids information overload |
| Citation display length | `300–500 characters` | Citations for process and abnormal reports must clearly display key parameters. Overly long fragments disrupt readability |
| Knowledge base incremental sync frequency | `Every 4 hours` | Document updates for this category trigger with batch production and design changes. Syncing every 4 hours balances real-time performance and system load |

## Three Common Configuration Errors
- Symptom: The returned citation list is empty or only includes irrelevant documents. Cause: Field weights are not configured for this category’s document types, so search does not prioritize core fields such as winding turns and test results.
- Symptom: Knowledge base variables passed during workflow calls do not take effect, and the document library for the corresponding batch cannot be switched. Cause: The knowledge base selection node is not configured to support dynamic variable references, and only a fixed knowledge base is bound.
- Symptom: Citation text fragments exceed expected lengths, causing formatting chaos in process documents. Cause: A reasonable value for `quoteMaxToken` is not set, and the default parameter is too long, not adapted to the single-block content length of this category’s documents.

## How to Verify Correct Configuration
- Submit a process drafting request for a single electric motor, and check if the returned results include citation sources for linked winding process cards and test reports.
- Call the workflow and pass a custom knowledge base variable, and confirm that the search node can read document content from the corresponding knowledge base.
- View the returned citation list, and confirm that the `detail` parameter is enabled, displaying specific field information for the citation text.
- Trigger an abnormal report drafting request, and check if the citation source is linked to corresponding vibration and temperature rise data or equipment logs.

The values provided above are common starting points, and should be evaluated against the reader’s own operational samples.
