# Process Document and Exception Report Drafting for Electric Motor and Generator Manufacturing: Document Parsing and Chunking

## What data for this category looks like
Data for this category comes from daily output of winding, insulation, final assembly, and testing departments at electric motor factories and power equipment enterprises. It includes winding process cards, insulation treatment records, dynamic balance reports, voltage withstand insulation test reports, and type and factory inspection test reports. Data sources cover electromagnetic design data, copper wire and insulating material batch records, winding equipment logs, balancing machine data, electrical test bench outputs, and ERP and MES systems. Documents are updated per production batch or single unit, and synced after each form change. Document fields include clear engineering units such as winding turns, wire diameter (mm), withstand voltage value (kV), temperature rise (K), and others. The structure is divided into fixed modules including process steps, test parameters, and result judgment.

## What constraints these characteristics impose on document parsing and chunking
Mixed parsing of multiple document types requires parsing rules to adapt to the linear step structure of process cards and the hierarchical parameter structure of test reports. Fields with engineering units must retain contextual associations during chunking, to avoid information loss caused by separation of parameters and units. Frequently updated production data requires the parsing process to have low latency, to prevent blocking batch processing tasks. Embedded charts such as dynamic balance vibration waveforms and voltage withstand test curves require parsing tools to support non-standard image formats generated by industrial equipment, and to bind charts to corresponding test data. The association between fault descriptions and test data in exception reports requires retaining the context of adjacent fields during chunking, to facilitate subsequent retrieval and analysis.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the parameter block length of winding process cards and test reports, retains complete context for key data |
| `chunkSplitter` | Split by paragraph + heading | Matches the hierarchical structure of process steps and test items in documents, avoids cross-module chunking |
| `customPdfParse` | Enabled | Identifies industrial-specific embedded image formats such as vibration charts in dynamic balance reports and waveform diagrams in voltage withstand tests |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 seconds | Covers the full parsing time of type test reports over 100 pages, prevents parsing timeout for large documents |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Supports batch upload requirements for multiple test reports per single batch |

This configuration logic is based on FastGPT v4.17.0.

## Three Common Misconfigurations
- After uploading a DOCX file containing embedded images, the image fields in returned results show invalid content. The cause is that the `customPdfParse` configuration is not enabled. Default parsing rules cannot recognize non-standard image formats generated by industrial equipment.
- Parsing timeout errors trigger after uploading large type test reports. The cause is that `PARSE_FILE_TIMEOUT_SECONDS` is not adjusted to the value range suitable for large documents. The default timeout duration is insufficient to complete full parsing.
- Images are separated from corresponding test parameters when parsing Excel test records containing images. The cause is that custom Excel parsing rules are not configured. The default chunking logic does not bind the association between images and adjacent fields.

## How to Verify Configurations Are Set Correctly
- Upload a DOCX process card file containing winding turns and wire diameter parameters, and check if parsed chunks retain complete context of parameters and units.
- Upload a 100-page PDF type test report, and check if parsing duration falls within the configured `PARSE_FILE_TIMEOUT_SECONDS` range, with no timeout error triggered.
- Upload a DOCX report containing dynamic balance vibration images, and check if images are correctly displayed in parsing results, with no invalid image prompts appearing.
- Upload a packaged test report file with a single size of 450 MB, and confirm that upload and parsing processes do not trigger file size limit errors.

The values provided are common starting points, and should be evaluated against samples from the specific deployment context.
