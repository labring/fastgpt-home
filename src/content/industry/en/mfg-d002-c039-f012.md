# Drafting Process Documents and Exception Reports for Electric Motor and Generator Manufacturing: Deployment and Upgrade

## What Data Looks Like for This Category
Core data for this category comes from electromagnetic design systems, copper wire and insulation material batch records, winding equipment, balancing machines, electrical test benches, and ERP/MES systems. Daily generated documents include winding process cards, insulation treatment records, dynamic balance reports, voltage withstand insulation test results, and type and factory inspection reports. Document fields include clear numerical values and unique identification information such as winding turns, paint dipping process parameters, vibration detection values, and voltage withstand thresholds. Data is updated once per product or per batch. All associated documents are updated synchronously whenever the product type is changed.

## Constraints on Deployment and Upgrade Posed by These Characteristics
Data sources for this category cover multiple industrial systems and equipment, including structured test values and unstructured reports with charts. Update frequency is high, and single-batch data volume grows with production scale.
During deployment, meet stability requirements for multi-source data access to avoid interrupting production link process document and exception report generation.
During upgrade, maintain compatibility with configurations for connecting existing industrial equipment, to ensure existing data synchronization logic is not affected.
Additionally, documents include many test reports with visual charts. Configure modules that support image parsing and indexing to ensure complete reading of process documents and exception reports.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `DB_MAX_LINK` | `20–30 connections` | This category involves multiple process documents and test reports per production batch. Frequent calls generate a large number of database connections. Setting 20–30 balances performance and resource usage |
| `STORAGE_S3_ENDPOINT` | `internal enterprise object storage node address` | This category’s test reports and process cards are industrial documents with images. Storing them on internal object services ensures data security and access speed |
| `REDIS_URL` | `local Redis cluster address, cache validity period set to 3600 seconds` | Frequent queries for data such as winding turns and material batches reduce database pressure with caching, adapting to real-time document generation needs in production links |
| `MONGODB_URI` | `MongoDB instance bound to ERP/MES data synchronization interface, memory no less than 4096 MB` | Data sources for this category include ERP and production equipment. This configuration connects to existing business data. Sufficient memory ensures stability of multi-source data synchronization |
| `FILE_TOKEN_KEY` | `32-character random string` | Used to generate access tokens for process documents, ensuring access security for internal documents |
| `FE_DOMAIN` | `internal enterprise access domain` | This system is only used internally by the production department. Configuring an internal domain ensures access security |

## Three Common Misconfigurations
- Issue: After local deployment, images in process documents cannot be automatically indexed, and previews fail to display in the knowledge base after upload. Cause: `STORAGE_S3_ENDPOINT` is not correctly configured to point to the internal enterprise object storage service, interrupting the image parsing and indexing workflow.
- Issue: After Docker deployment completes, accessing the configured `FE_DOMAIN` returns no response, with connection timeout or 503 status code. Cause: Container port mapping parameters are misconfigured, or the cache service referenced by `REDIS_URL` is not running normally, preventing the frontend from connecting to the backend service.
- Issue: A FastGPT v4.17.0 version update notification pop-up appears every time a new conversation session is opened. Cause: The parameter to disable update prompts was not configured during deployment, triggering the update prompt logic each time a session initializes.

## How to Confirm Successful Configuration
- Upload a dynamic balance report with images, search for keywords from the report in the knowledge base, and confirm normal retrieval and image preview functionality.
- Access the configured `FE_DOMAIN`, verify that the frontend page loads normally without connection timeout or status code errors.
- Submit a process document generation request, confirm that the returned document includes category-specific field information such as winding turns and voltage withstand test values.
- Check the connection count monitor for `DB_MAX_LINK`, confirm that connection exhaustion does not occur during high-frequency requests.

The values provided are common starting points and should be measured against the reader's own samples.
