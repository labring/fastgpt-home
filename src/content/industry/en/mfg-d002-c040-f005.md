# Drafting Process Documents and Exception Reports for Battery PACK and Energy Storage System Integration: Tool Calling and Plugins

## What Data for This Category Looks Like
The typical entities in this category are manufacturers of power battery packs, energy storage cabinets, and BMS systems. Daily produced documents include grouping rules, BOM lists, welding and torque records, BMS flashing records, insulation and voltage withstand reports, EOL test data, system configuration lists, and other related materials. Data sources cover cell capacity grading equipment, MES systems, welding station equipment, torque tools, BMS software version repositories, EOL test benches, and additional equipment. Data updates occur once per manufactured PACK or energy storage cabinet, or synchronously each time the BMS software version is updated. Document fields include cell model, capacity difference threshold, material code, station number, test voltage, internal resistance parameters, and some fields require accompanying unit identifiers.

## What Constraints Do These Characteristics Impose on the Tool Calling and Plugins Workflow
Multi-source heterogeneous data sources require tool calling to adapt to device export files and system interfaces in different formats. Unified parsing rules must be configured.
Single-task data volume is small, but update frequency is high. Single-task processing duration and resource usage must be limited. This avoids disrupting real-time production line processes.
Professional document fields and unit requirements demand precise extraction of corresponding fields during tool calling. This prevents report errors caused by format mistakes.
Exception reports must link multi-source data. Plugins must integrate interface permissions across different systems. This ensures data integrity and accuracy.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Tool calling timeout duration | 300–600 seconds | Matches the processing cycle for a single cabinet process document on a single PACK production line |
| Single file upload limit | 800–1200 MB | Fits the typical size of energy storage cabinet system configuration lists and EOL test reports |
| `toolChoice` | auto | Supports automatic switching between tools for parsing grouping rules and generating exception reports |
| `functionCall` | enabled | Fixed call to plugins to complete field validation for BMS flashing records |
| Variable reference switch | Enabled | Supports referencing dynamic variables of cell capacity grading data in upload parameters |

## Three Common Mistakes
- When calling the MinerU plugin, a "File size exceeds limit" error is returned, and local welding torque records cannot be uploaded. Cause: No custom file size threshold is configured in container startup parameters. The default 2 MB limit is used instead.
- When uploading process documents in a custom workflow, dynamic variables of cell capacity grading data cannot be referenced. Only fixed links are supported. Cause: Variable reference configuration for the workflow is not enabled. Parameters are not bound to variable fields of the corresponding data source.
- Insulation and voltage withstand data fields are empty in generated exception reports. Cause: The EOL test data interface of the MES system is not linked. Corresponding fields are not correctly extracted during tool calling.

## How to Verify Proper Configuration
- Start the MinerU plugin container in a FastGPT v4.17.0 environment. Upload a single 1000 MB process document. Verify that no size limit error occurs.
- Configure upload parameters in a custom workflow. Reference a preset cell capacity grading data variable. Upload a test file. Verify that the variable is correctly parsed into tool calling parameters.
- Call the plugin configured via `functionCall`. Pass simulated BMS flashing record data. Verify that the plugin returns field validation results that match preset rules.
- View upload logs in the MinIO storage bucket. Confirm that upload records for process documents and exception reports have been generated. No storage failure prompts are present.

The values provided are common starting points and should be evaluated against the reader's own samples.
