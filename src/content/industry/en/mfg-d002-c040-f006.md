# Process Document and Abnormal Report Drafting for Battery PACK and Energy Storage System Integration: Source Citation and Traceability

## What data for this category looks like
Data for this category includes cell capacity grading data, MES production records, welding equipment logs, torque tool readings, BMS software versions, and EOL test bench test results. Daily generated documents cover grouping rules, BOM lists, welding and torque records, BMS flashing records, insulation and voltage withstand reports, EOL test reports, and system configuration lists.
Data updates occur once per produced battery pack or energy storage cabinet, and are synchronized each time the BMS software version changes. Document fields include cell capacity, internal resistance, material code, torque value, insulation resistance value, and more. Corresponding equipment numbers and test timestamps are attached to each entry.

## What constraints these characteristics impose on source citation and traceability
Multiple scattered data sources require the citation and traceability process to bind unique identifiers such as equipment numbers and test timestamps. This prevents mixing of data from different batches.
High-frequency data updates require the traceability system to associate the latest BMS version and production batches. This ensures cited process documents and abnormal reports match current production status.
The professional field and fixed-unit document structure require retaining complete original parameter expressions during traceability. Random simplification is not permitted.
Abnormal scenarios may lead to serious system failure. Each citation must be traceable to original production or test records. This avoids system faults caused by configuration deviations.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 1200–1500 token | Matches the average length of a single process document or abnormal report. Ensures complete citation of core parameters |
| Source citation display | Enabled | Retains traceability identifiers such as original document equipment numbers and test timestamps. Meets compliance requirements for production scenarios |
| Result rearrangement | Enabled | Prioritizes search results strongly related to grouping rules and insulation tests. Adapts to core business links of this category |
| Single search limit | Top 6–10 entries | Covers multiple data sources involved in a single process document. Avoids missing key grouping or test records |
| `responseData` | Includes original document path and fields | Supports direct jumps to original production records for fast traceability |
| `detail` | Enabled | Retains complete original document fields and units. Prevents loss of key parameter information after simplification |

## Three common configuration errors
1. After enabling result rearrangement, search returns no results or citation source fields appear empty. Cause: The rearrangement threshold is set too high. This filters out low-relevance but business-compliant historical test records. No valid traceability data can be matched.
2. Setting an excessively large value for `quoteMaxToken` causes context overflow. Cause: The parameter is not adjusted based on the average length of a single document. It exceeds the system context window limit, leading to retrieval failure.
3. After exporting a workflow and importing it to another environment, the cited traceability plugin fails to load. Cause: The configuration information of the corresponding data source was not synchronized during workflow export. Only process nodes were exported. The data source mapping relationship required for traceability was not retained.

## How to confirm correct configuration
- In FastGPT v4.17.0, generate a simulated abnormal report. Check if the cited traceability information includes unique identifiers such as equipment numbers and test timestamps.
- Adjust the `quoteMaxToken` parameter. Verify citation integrity across different values. Ensure core fields are not truncated.
- Trigger a process document drafting process. Confirm that search results are sorted according to the priority of core businesses such as grouping rules and insulation tests.
- Export the currently configured workflow. Import it to a test environment. Verify that all traceability-related nodes can load data sources normally.
