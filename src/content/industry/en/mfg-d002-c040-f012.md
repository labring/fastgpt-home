# Drafting Process Documents and Exception Reports for Battery PACK and Energy Storage System Integration: Deployment and Upgrade

## What this category of data looks like
Daily documents for this category include grouping rules, BOM lists, welding and torque records, BMS flashing records, insulation and pressure resistance reports, EOL test results, and system configuration lists. Data sources include cell capacity separation data, MES systems, welding equipment, torque tools, BMS software version records, and EOL test benches. A new record is generated each time a battery pack or energy storage cabinet is produced. Associated documents are updated synchronously each time the BMS software version changes. Data fields cover core production information such as cell parameters, equipment operating parameters, test results, and software versions.

## What constraints do these characteristics impose on the Deployment and Upgrade phase
The data sources for this category cover production equipment, test systems, and software records. The need to access multi-source heterogeneous data increases interface adaptation complexity during the deployment phase. The high update frequency requires deployment configurations to support fast indexing of small individual documents, to avoid resource overload from batch tasks. Diverse document types and dedicated fields require preset data parsing and verification rules during deployment, to ensure fields in subsequently drafted process documents and exception reports comply with requirements. Production data is directly linked to system operating safety. A data verification link must be configured during deployment to prevent incorrect parameters from entering subsequent processes.

## How to set configurations
The following configurations are adapted to the production scenario of this category for FastGPT v4.17.0:

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://username:password@host:5432/pack_manufacture` | Production data for this category is mostly stored in PostgreSQL databases. The connection address of the dedicated business database must be matched |
| `REDIS_URL` | `redis://:password@host:6379/0` | Used to cache frequently accessed data such as cell capacity separation and BMS configurations. The default database 0 can isolate business cache from other services |
| `DB_MAX_LINK` | `20–30` | The single-batch production data volume of this category is moderate. 20-30 connections balance resource usage and concurrent indexing requirements. Adjust based on actual measurements |
| `STORAGE_S3_ENDPOINT` | `http://minio.example.com:9000` | Test reports, BOMs and other documents for this category are mostly stored in object storage services. The access address of the corresponding storage node must be matched |
| `FE_DOMAIN` | `https://pack-manufacture.example.com` | Used to configure the platform frontend access domain name, matching the business system domain name rules for this category |
| `FILE_TOKEN_KEY` | `Randomly generated 32-bit string` | Used to encrypt document access tokens, ensuring access security for production documents and preventing unauthorized access |

## Three common configuration errors
- Knowledge base indexing tasks fail, with logs showing "file read failed". Cause: `STORAGE_S3_ENDPOINT` is not configured or is configured incorrectly, making it impossible to access stored documents such as welding records and EOL test reports.
- Database connection timeouts occur, and indexing tasks cannot be completed. Cause: `DB_MAX_LINK` is not adjusted to a value adapted to the data volume of this category, exhausting the connection pool and failing to handle concurrent indexing requests.
- Embedding model calls return exceptions, and document vectors cannot be generated. Cause: `REDIS_URL` is not configured correctly, causing cached model call parameters to be lost and triggering service verification failures.

## How to verify a successful configuration
- Run an indexing task for a single cell capacity separation data set, confirm the task status is successful. Adjust the indexing concurrency based on the number of documents for this category.
- Access the frontend domain name `FE_DOMAIN`, confirm that the platform can be logged into normally, and uploaded BOM lists, insulation and pressure resistance reports and other documents can be viewed.
- Call the database connection test interface, confirm that the number of available connections in the database connection pool matches the preset `DB_MAX_LINK` value.
- Upload a document with dedicated fields, such as a welding torque record, confirm that the parsed fields are complete and can be used normally for drafting process documents.

The values provided are common starting points and should be measured against the reader's own samples.
