# Drafting Process Documents and Exception Reports for Electroplating and Chemical Surface Treatment: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
This category of data comes from customer surface treatment specifications, bath solution test results, rectifier operation data, online water quality monitoring records, and hazardous waste management ledgers. Daily documents include bath solution analysis records, process parameter cards, fixture usage records, film thickness and adhesion reports, hazardous waste ledgers, and wastewater monitoring records.
Data updates occur per bath run, per shift, or per fixed monitoring requirements. Fields cover bath solution component concentration, operating temperature, current value, film thickness metrics, discharge concentration, and more. Common associated units are g/L, ℃, A, μm, mg/L.

## Constraints Imposed on HTTP Interfaces and External Systems
The update frequency of data in this category is inconsistent. It is linked to multiple types of business and compliance documents. Interfaces must support on-demand triggering or flexible scheduled data pulling.
Core fields have specific units. Interface requests require standardized field mapping rules to ensure accurate data filling into report templates.
Some data must be pulled across multiple systems. Interfaces must adapt to cross-source data integration logic, while securing access to sensitive production and compliance data.
Single-batch data volume is small, but there are many batches. Interfaces must support small-batch submissions or precise single-item calls to avoid excessive load.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0, and are suitable for HTTP interface and external system docking for electroplating and chemical surface treatment scenarios:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {custom service key}` | Data in this category involves production compliance and sensitive parameters. Standard authentication is required to ensure interface access security. |
| `variables` | `{"batchId": "", "slurryContent": "", "filmThickness": ""}` | Matches core fields of bath solution analysis, film thickness reports, and other documents to enable automatic data mapping to drafting templates. |
| `responseData` | `Only retain specified business fields` | Filters unnecessary system logs and redundant data, focusing on content required for process and exception reports. |
| Interface timeout setting | 600 seconds | Sufficient response time must be reserved when pulling bath solution test and online monitoring data across systems. |
| Bulk submission limit | First 20 entries | Adapts to the small-batch data submission rhythm per shift or per bath run for this category, avoiding excessive interface load. |

## Three Common Errors
- Symptom: Interface calls return a 401 unauthorized error. Cause: The `Authorization` parameter is not configured correctly, or the service key does not match the external system’s authentication rules.
- Symptom: Generated process reports contain empty fields. Cause: Core business fields for this category are not configured in `variables`, so externally pulled data cannot be correctly mapped to the report template.
- Symptom: The external interface does not trigger after a specified keyword is entered, and a preset reply is returned directly. Cause: Keyword verification rules are not bound in the interface trigger configuration, so the custom interface call logic does not take effect.

## How to Verify Successful Configuration
- Initiate a simulated interface call, and confirm that the returned `responseData` only includes preset business fields such as process parameters and exception metrics.
- Submit test data containing batch numbers and bath solution concentrations, and confirm that fields configured in `variables` are correctly linked to the report drafting template.
- Adjust the trigger keyword, and verify that the external system interface is successfully called and corresponding data content is retrieved after the specified input.
- Simulate a cross-system data pulling scenario, and confirm that no unauthorized or timeout errors occur in the interface.
