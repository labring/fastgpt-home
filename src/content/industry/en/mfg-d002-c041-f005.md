# Drafting Process Documents and Exception Reports for Electroplating and Chemical Surface Treatment: Tool Calling and Plugins

## What the data for this category looks like
Data for this category comes from daily production records of electroplating plants, electronic connector workshops, and hardware surface treatment facilities.
Core documents include bath solution analysis records, process parameter cards, fixture records, film thickness and adhesion reports, hazardous waste ledgers, and wastewater monitoring records.
Data updates occur per bath cycle, shift, or according to fixed monitoring requirements.
Most documents are structured tables or forms. Fields include bath number, analysis time, metal ion concentration (g/L), pH value, coating thickness (μm), workpiece number, discharge indicators and other professional parameters.
The format is unified, and field boundaries are clearly defined.

## Constraints on Tool Calling and Plugin Workflows
This category has high data update frequency and scattered data sources.
Tool calling must adapt to trigger rhythms based on bath cycles and shifts. This avoids delayed or repeated pulling of real-time production data.
Professional field units and value ranges are fixed. Function parameters for tool calling must strictly match dedicated fields such as bath solution concentration and film thickness. Generic parameter templates cannot be used.
Hazardous waste and wastewater data require association with compliance verification logic. Plugins must be embedded in corresponding detection links.
Exception reports must quickly associate multi-source data to generate rectification suggestions. This places clear requirements on the context carrying capacity of tool calling.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | Automatically matches calling requirements for multi-source production data, adapts to update rhythms based on bath cycles and shifts |
| Workflow/API function-call configuration | Enabled | Supports passing structured parameters for professional fields such as bath solution concentration and film thickness |
| Tool call trigger condition | Within 10 minutes after a bath cycle is completed | Matches the data update frequency of this category per bath cycle |
| Function parameter mapping rules | Bind dedicated fields such as bath number, ion concentration, and film thickness | Corresponds to the document structure and data fields of this category |
| Single tool call return limit | Top 10 records | Balances data loading volume and process processing efficiency |
| Context window size | 4000 token | Carries field information and associated data from multiple production documents |

## Three Common Misconfigurations
- Some browsers cannot display application images and avatars embedded in tool calls. Only a small number of browsers such as Quark can load them normally. The cause is that cross-origin whitelist rules adapted for general browsers are not configured, resulting in blocked cross-origin resource requests.
- In two-layer workflow tool calls, the content returned by the first-layer AI is automatically printed. The cause is that the output switch for intermediate steps is not turned off, resulting in unnecessary intermediate data being exposed during process execution.
- Tool call functionality when using the Qwen2.5 model returns an error, prompting that function calls are not supported. The cause is that the `functionCall` parameter is not enabled in the model configuration of FastGPT v4.17.0, and the tool call format for this model is not adapted.

## How to Verify Successful Configuration
- Submit a simulated single bath cycle process document drafting request. Check whether the tool automatically pulls bath solution analysis data and process parameters for the corresponding bath number.
- Trigger an exception report generation process. Check whether the compliance check plugin is called to associate wastewater and hazardous waste ledger data.
- Configure a tool call task for the Qwen2.5 model. Submit a test request. Confirm that the returned result conforms to the preset parameter mapping rules.
- View the workflow execution log. Confirm that the intermediate output of the first layer in the two-layer process is not printed, and that the execution order conforms to the dependency settings.

The values provided are common starting points and should be evaluated against the reader's own samples.
