# Process Document and Exception Report Drafting for Electroplating and Chemical Surface Treatment: Source Citation and Traceability

## What Data Looks Like for This Category
Typical entities in this category are electroplating factories and hardware surface treatment workshops. Daily documents include bath solution analysis records, process parameter cards, fixture records, film thickness and adhesion reports, hazardous waste ledgers, and wastewater monitoring records. Data sources include customer surface treatment specifications, bath solution test results, rectifier operation data, online water quality monitoring data, and hazardous waste management ledgers. Data update frequency is per bath cycle, per shift, or as required by monitoring standards. Individual documents contain specific parameters and units, such as bath solution pH value, current density (A/dm²), film thickness (μm), and more. Fields and update rhythms vary significantly across different documents.

## Constraints Imposed on Source Citation and Traceability
High-frequency updated multi-type documents require matching the latest production cycle data during traceability, to avoid citing expired bath solution or monitoring records. Differentiated fields across multiple document types require the traceability system to distinguish document categories, ensuring that cited parameters correspond to the current production scenario. Mixed sources of online monitoring data and offline ledgers require marking data acquisition methods and update times during traceability, to guarantee the accuracy of exception analysis. The high-stakes business nature requires traceability to precisely correspond to specific bath cycles or monitoring periods, preventing batch rework or environmental penalties caused by citation errors.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 1500–2000 token | Matches the average length of a single process document or monitoring record for this category, to avoid truncating critical parameters and units |
| `responseData` | Enabled | Requires returning metadata for cited sources, including document type, update time, and bath cycle number |
| Single search limit | Top 6 results | Covers the quantity of reference documents required for exception report drafting, including bath solution, process, and fixture records |
| Reranking | Enabled | Sorts cited sources by relevance, prioritizing records most relevant to current process adjustments or exception issues |
| `detail` | Full | Returns complete fragments of cited text, including all detection parameters and unit information |
| Maximum context | 8000 characters | Accommodates content from multiple associated documents, ensuring contextual completeness during exception analysis |

## Three Common Configuration Mistakes
- Phenomenon: Returned cited sources do not include document update time or bath cycle number. Cause: The `responseData` configuration is not enabled, and metadata fields are not requested, making it impossible to trace records corresponding to the production cycle.
- Phenomenon: Insufficient number of cited references returned by searches, failing to cover all process parameters required for exception reports. Cause: The single search limit is set too low, not matching the reference needs for multiple types of documents in this category.
- Phenomenon: Cited bath solution data does not match the current production bath cycle, leading to incorrect exception analysis conclusions. Cause: No filtering based on document update time (per bath cycle/shift) is performed, and historical bath cycle records are incorrectly cited, which may cause coating blistering or batch rework.

## How to Verify Correct Configuration
- Submit a test request that includes a query for bath solution parameters, and check whether the returned results include the document type and update time of the cited sources.
- Trigger the exception report drafting workflow, and check whether the number of returned citation lists matches the preset single search limit.
- Import an expired bath solution analysis record, and verify that the search results prioritize the latest monitoring data.
- Check the `responseData` field returned by the interface, and confirm that it includes complete cited text fragments and metadata.

The values provided are common starting points and should be measured against the reader's own samples.
