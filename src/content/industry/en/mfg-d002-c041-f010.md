# Drafting Process Documents and Exception Reports for Electroplating and Chemical Surface Treatment: Knowledge Base Retrieval and Recall

## What data for this category looks like
Data sources include customer surface treatment specifications, bath test results, rectifier operation data, online water quality monitoring data, and hazardous waste management ledgers. Daily produced documents include bath analysis records, process parameter cards, hanger usage logs, film thickness and adhesion reports, hazardous waste ledgers, and wastewater monitoring records.
Update cadence follows per bath run, per shift, or fixed monitoring requirements. Most documents are forms or records with structured fields, including bath component concentrations, process current and temperature, coating performance parameters, emission indicators, and similar details.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link
The high-frequency incremental update nature of this category requires the retrieval system to support low-latency data source synchronization, to avoid computational load pressure from full re-indexing. Documents with many structured fields need targeted field recall rules, to avoid full-text retrieval matching irrelevant general content.
Retrieval for hazardous waste and emission-related data must prioritize matching compliance-required fields, to ensure drafted reports meet standards. As the knowledge base scale expands with production batches, retrieval time and token consumption will increase, so recall strategies need optimization.
Documents of different types have large field differences, so knowledge base collections should be divided by document category, to avoid mixing irrelevant cross-category results.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Matching electroplating process parameters and exception reports requires high confidence, to avoid low-relevance results causing drafting errors |
| `limit` | `Top 8–12 results` | Documents in this category are mostly structured records; a small number of precise results are sufficient to support drafting, and too many results will increase token consumption |
| `searchMode` | `vector+keyword` | Balances structured field matching and full-text semantic recall, adapting to different types of documents such as bath parameters and film thickness data |
| `usingReRank` | `Enabled` | Filters irrelevant content through re-ranking after multiple recall results, improving matching accuracy when drafting exception reports |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Expands user-provided exception descriptions into professional terms, such as "blistering" expanded to "coating blistering defects", to match bath exception records in the knowledge base |
| `collectionIds` | `Collection IDs grouped by document type` | Manages bath records, process cards, and hazardous waste ledgers in separate databases, to avoid recalling irrelevant cross-category results |

## Three Common Misconfigurations
- Symptom: An `insufficient_quota Current group upstream load is saturated, please try again later` error is returned during retrieval. Cause: Incremental synchronization rules are not configured based on document update frequency, causing excessive data source loading pressure during full retrieval, or the number of recall results per retrieval is not limited, consuming too many computing resources.
- Symptom: Retrieval recall results are irrelevant to the content of the drafted process documents or exception reports, and most matching results are general documents unrelated to electroplating. Cause: The `collectionIds` configuration is not used to group collections by category, recalling knowledge base content from other categories, or `datasetSearchUsingExtensionQuery` is not enabled, leading to insufficient professional term matching.
- Symptom: As the knowledge base content increases, retrieval time increases, and token consumption is too high when generating exception reports. Cause: The number of recall results specified by `limit` is not limited, or `usingReRank` is not enabled to filter invalid results, leading to overly long context passed to the large model.

## How to Confirm the Configuration is Correct
- Upload a recent bath analysis record and process parameter card, initiate a retrieval, and check whether the recall results include the exclusive document fields of this category.
- Simulate drafting an exception report, enter a description such as "coating blistering", and check whether the recall results include corresponding bath exception records and treatment solutions.
- View the retrieval log to confirm that the number of returned results matches the value range specified by the configured `limit`.
- Test incremental update of a hazardous waste ledger, confirm that the knowledge base can quickly synchronize new data, without load errors triggered by full loading.

The values listed above are common starting points, and should be evaluated against the reader's own samples.
