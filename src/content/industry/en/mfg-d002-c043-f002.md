# Drafting Process Documents and Exception Reports for Batch Fine Chemical Synthesis: Vector Models and Indexes

## What Data Looks Like for This Category
Typical entities in this category are coating, resin, additive, agrochemical intermediate, and specialty chemical enterprises. Daily generated documents include batch production instructions, feeding review sheets, reaction process records, cleaning records, inspection reports, deviation and change orders. Data sources cover formula and process libraries, raw material batch data, reactor DCS systems, weighing systems, LIMS systems, and warehouse systems. Data updates occur once per batch production or each key process step. Core time-consuming steps in business processes include reviewing multiple feedings in sequence and by conditions, judging reaction endpoints to switch to post-processing, and preventing residual cross-contamination during product change cleaning.

## What Constraints These Characteristics Impose on Vector Models and Indexes
Multi-batch, multi-step document updates require indexes to support incremental synchronization. This avoids performance losses from full reindexing. Single-batch documents contain multiple structured and semi-structured fields, such as feeding volume, reaction temperature, reaction duration, etc. Vector models must adapt to semantic extraction for mixed fields. Adjust `defaultToken` to adjust the semantic coverage of individual chunks. Frequent batch-level updates create index write pressure. Limit the document scale for a single indexing operation. Process parameters vary across batches. Index recall logic must balance batch specificity and cross-batch reference value. Process documents involve confidential formula content. Index access permissions must bind to production system permissions.

## How to Set Configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Adapts to the content length of a single step in a single process document, avoids semantic breaks across steps within a chunk |
| Overlap Length | 100–200 characters | Retains associated semantics for adjacent feeding and reaction steps, prevents loss of critical context after chunking |
| Similarity Threshold | 0.75–0.85 | Matches semantic similarity between process parameters and exception scenarios, avoids recalling documents from unrelated batches |
| Single Search Limit | Top 10 results | Balances reference coverage and retrieval efficiency when drafting exception reports |
| Maximum Context | 4000 tokens | Adapts to batch reference requirements for process documents, complies with input limits of mainstream vector models |
| `defaultToken` | 1000 | Adapts to the basic reference length of a single exception report |
| `maxToken` | 16000 | Supports complete indexing of long documents, covers full process records for a single batch |

## Three Common Misconfigurations
- The symptom is excessively long indexing times when calling the knowledge base interface. The interface displays queue wait times exceeding 300 seconds. The cause is failure to configure chunking rules for batch-level incremental updates. This leads to full scanning of multi-batch documents.
- The symptom is that imported knowledge bases cannot generate new indexes after switching vector models. Re-import attempts trigger duplicate file errors. The cause is failure to enable version marking for incremental indexing. The system cannot recognize that vectors generated by the old model do not match the new model.
- The symptom is that knowledge base search results are sorted inconsistently with semantic similarity. Exception report drafting prioritizes low-correlation historical documents. The cause is failure to configure a reranking step. The system only sorts based on initial recall similarity, and does not adjust order based on step priority of process documents.

## How to Confirm Configurations Are Correct
- Review index generation logs to confirm that the number of chunked document blocks matches the number of steps in the original document.
- Manually upload a single exception report template to test whether search recall results include reference documents from the same process step.
- Check index update records to confirm that newly generated batch documents can be incrementally synchronized to the index.
- Verify vector model call logs to confirm that the used model matches the configured settings.

All provided configuration values are common starting points. They should be evaluated against the relevant samples.
