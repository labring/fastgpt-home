# Drafting Process Documents and Exception Reports for Batch Synthesis in Fine Chemicals: Tool Calling and Plugins

## What Data Looks Like for This Category
Core data for batch synthesis in fine chemicals comes from formula and process libraries, raw material batch records, reactor DCS systems, weighing systems, LIMS laboratory information management systems, and warehouse systems. Data is updated once per production batch and each key reaction step. Daily documents include batch production instructions, feeding verification sheets, reaction process records, cleaning records, inspection reports, deviation and change orders. Fields include feeding amount (kilograms/liters), reaction temperature (degrees Celsius), batch number, raw material batch identifier, cleaning confirmation records, and other relevant items. The content involves confidential formula information, so data access scope must be strictly controlled.

## What Constraints These Characteristics Bring to the Tool Calling and Plugins Workflow
The multi-batch switching production mode requires tool calls to be strictly linked to batch numbers to avoid cross-batch data mixing. Data updated per key step requires tool triggering timing to align with production nodes, preventing the use of outdated data. The confidential formula attribute requires tool calls to only return fields within authorized scope, and must not disclose core process parameters. Scenarios where a single batch is associated with data from multiple systems require tool calls to support simultaneous connection to multiple interfaces such as DCS and LIMS, and filter results by batch to avoid redundant data interfering with process document and exception report generation.

## Configuration Settings
This configuration is based on the tool calling logic of FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | Adapts to the automatic matching requirements of multi-system interfaces, no need to manually specify each calling tool |
| Workflow/API function-call configuration | Enabled | Enables precise calling of corresponding business system interfaces, avoiding fuzzy matching from general question answering |
| Single tool call timeout | 300-600 seconds | Operations such as reactor DCS data collection and LIMS queries require long response cycles |
| Context window limit | 8000-12000 token | Covers the content length of complete process documents and exception reports for a single batch |
| Number of tool call results returned | Top 3-5 entries | The volume of system data associated with a single batch is limited, and too many entries will interfere with content generation |
| Batch association matching rule | Filter by current session batch number | Prevent cross-batch data from being mixed into process documents and exception reports |

## Three Common Configuration Mistakes
- Calling the `apiCollection` interface returns `Invalid URL, code: 500`: The valid API address of the corresponding fine chemical business system is not configured, or special characters contained in the address have not been properly escaped.
- The tool calling module output cannot be canceled, and redundant replies are displayed on the interface: The automatic return switch for tool execution results is not turned off, and interface calling logs are mistakenly spliced directly into the generation context.
- Inputting "share" is converted to an incorrect term: The word segmentation whitelist for fine chemical professional terms is not configured, and the general word segmentation model cannot recognize near-homophones in professional scenarios, resulting in incorrect conversion of input content.

## How to Verify the Configuration Is Correct
- Upload the batch production instruction document for a single batch, trigger tool calling, and verify whether the returned API data matches the raw material batch information of that batch.
- Simulate an exception scenario input, and check whether the results returned by tool calling only include deviation and change order data for the current batch, with no cross-batch redundant content.
- Set `toolChoice` to `auto`, input a process verification question, and confirm whether the tool automatically calls the corresponding LIMS interface to return feeding verification data.
- Adjust the single tool call timeout to a reasonable range, simulate a slow interface request, and confirm that the system does not trigger a timeout error.

The values provided are common starting points and should be measured against the reader's own samples.
