# Drafting Process Documents and Exception Reports for Batch Fine Chemical Synthesis: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Business data for batch fine chemical synthesis comes from formula and process libraries, raw material batch records, reactor DCS systems, weighing systems, LIMS laboratory management systems, and warehouse systems.
Daily documents include batch production instructions, feeding review sheets, reaction process records, cleaning validation records, test reports, deviation and change orders.
Data is updated per production batch or each critical step. Document fields include batch number, feeding amount (kilograms/liters), reaction temperature (degrees Celsius), cleaning validation results, and some formula-related fields require confidentiality.

## Constraints Imposed on Knowledge Base Retrieval and Recall
The multi-batch, multi-step document structure requires retrieval to associate batch number and process step fields. This avoids invalid recall across batches or products.
Frequent updates per batch or critical step require the knowledge base to support incremental synchronization and real-time update verification. This ensures retrieved data matches the current production batch.
Documents contain a large number of precise process parameters with units. Retrieval must retain unit matching logic to prevent incorrect recall caused by parameter mismatches.
Some sensitive fields require confidentiality. Retrieval results must automatically filter unauthorized content, while ensuring compliant historical data can be called when drafting exception reports.
The business characteristic of multi-product switching requires retrieval to isolate data by product category. This prevents confusion of process data related to cross-contamination.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `similarity` | 0.75–0.85 | Fine chemical process parameters require precise matching. A value too low will introduce irrelevant non-target batch data, while a value too high will miss abnormal references from similar processes |
| `limit` | Top 8 entries | The number of process-related documents per single batch is moderate. Too many entries will exceed the context window, while too few will fail to cover the complete reaction process and feeding records |
| `searchMode` | `vector` | Documents in this category contain a large number of process parameters with units. Vector retrieval can accurately match numerical and step association relationships, which is better than keyword fuzzy matching |
| `usingReRank` | Enabled | Documents for multi-step reactions have similar content. Re-ranking can prioritize recall of cleaning validation and deviation records most relevant to the current abnormal scenario |
| `datasetSearchUsingExtensionQuery` | Enabled | Process exception reports often need to associate feeding and DCS data. Extended queries can automatically supplement associated fields such as batch number and raw material batch, improving recall breadth |
| `collectionIds` | Bound by product category | Multi-product switching in fine chemical manufacturing. Binding knowledge base collections corresponding to specific products avoids confusion of cross-product process data, and meets cleaning and confidentiality requirements |

## Three Common Configuration Errors
- Symptom: Knowledge base retrieval results fail to recall feeding review sheets for the specified batch, or results include a large number of documents from non-target batches. Cause: `datasetSearchUsingExtensionQuery` is not configured, so batch number association queries are not automatically supplemented. Only matching keywords cannot associate the target batch.
- Symptom: After switching the vector model, the system displays no progress prompt, and the original model binding configuration cannot be restored. Cause: The original model configuration was not saved in the knowledge base management interface. Forcing a direct switch causes context association interruption, and no rollback path is reserved.
- Symptom: After calling the knowledge base in the workflow tool call module, the returned result is empty or has missing fields. Cause: The corresponding product's `collectionIds` are not bound, so the tool call only retrieves the global default collection, and does not cover the exclusive process documents for the current batch.

## How to Verify Correct Configuration
A test query including the current production batch number and reaction temperature is submitted. The relevance of the recall results is verified, and the `similarity` value is adjusted to a range appropriate for the business scenario.
The knowledge base synchronization log is reviewed. Confirmation that the latest batch production record has been incrementally synchronized to the knowledge base meets the per-batch update requirement.
The knowledge base tool module is called in the workflow. Keywords for the abnormal scenario are passed in, the returned results are checked for coverage of required document types, and `collectionIds` binding is confirmed as correct.
A vector model switch is attempted. The interface is checked for the ability to restore the original configuration, confirming that the model switching logic meets expectations.

The values given are common starting points and should be measured against the reader's own samples.
