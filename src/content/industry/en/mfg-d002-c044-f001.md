# Pulp and Papermaking: Process Document and Exception Report Drafting - HTTP Interfaces and External Systems

## What the data for this category looks like
Data sources for pulp and papermaking scenarios include wood pulp and waste paper batch ledgers, DCS/QCS control systems, paper machine online measurement equipment, laboratory testing systems, and energy and water treatment systems. Daily documents include stock preparation sheets, beating records, paper machine operation logs, online quality curves, laboratory test reports, and sheet break and product change records.
Data updates follow three rhythms: real-time, per shift, and per roll. Online quality data updates in real time. Shift reports sync per shift. Single roll production records update when the roll completes.
Document fields include stock ratio, grammage, moisture content, thickness, paper defect type, and more. Corresponding units are percentage, grams per square meter, percentage, millimeters, and type identifier.

## What constraints do these characteristics impose on the "HTTP Interfaces and External Systems" link
The multi-source heterogeneous data characteristics of pulp and papermaking scenarios impose multiple constraints on HTTP interface and external system integration.
Real-time online data requires interfaces to support low-latency polling or active push, to avoid data lag affecting process adjustments.
Data sources with multiple update frequencies require interfaces to support different synchronization cycle configurations, to adapt to the synchronization needs of real-time data, shift reports, and roll-level records respectively.
The coexistence of structured documents and curve files requires interfaces to support parameter transfer in multiple formats. It also requires verification of field units and value ranges, to prevent non-compliant data from entering the system.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Authorization Configuration | Enable `Authorization` header verification, use Bearer tokens | Adapt to the security integration requirements of internal enterprise APIs, comply with general interface security specifications |
| Variable Transfer Configuration | Use `variables` to pass business identifiers such as paper machine number, batch number | Achieve precise association between process documents and exception reports for different production units |
| Response Data Validation | Enable `responseData` field validation, configure core field whitelists | Filter invalid data, ensure that content imported into the knowledge base complies with process document standards |
| Data Synchronization Cycle | Pull real-time data every 30 seconds, sync shift reports every 8 hours | Correspond to the update rhythm of DCS/QCS online data and shift reports |
| Batch Request Limit | Sync no more than 1000 records per single request | Avoid interface timeouts, adapt to batch synchronization needs of paper machine operation records |
| File Upload Format | Support CSV, PNG, and JSON format documents | Match the document structure of pulp and papermaking scenarios such as stock preparation sheets and quality curves |

## Three common errors
- Phenomenon: Invalid content cannot be parsed after uploading HTML-format interface documents. Cause: Structured parsing rules are not configured, only plain text, CSV, or specified structured file formats are supported, and HTML tags are not correctly converted.
- Phenomenon: Process files cannot be uploaded via the conversation interface, and the returned knowledge base search results are empty. Cause: The parameter name for file upload is not configured in `variables`, or the file stream forwarding permission of the external system is not enabled.
- Phenomenon: Ambiguous references appear when drafting exception reports, such as "this batch" cannot be associated with specific paper machine production records. Cause: Historical record optimization configuration is not enabled, and context variables are not passed into interface requests.

## How to verify the configuration is correct
- Send a test request with an `Authorization` token, check that the returned `responseData` includes the core fields of the stock preparation sheet, with no missing or incorrect formats.

- Enable historical record optimization, send two consecutive related questions, confirm that the second question can correctly associate the paper machine number mentioned in the first question.
