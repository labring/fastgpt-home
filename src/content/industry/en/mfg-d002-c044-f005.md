# Pulp and Papermaking: Process Document and Exception Report Drafting - Tool Calling and Plugins

## What the data for this category looks like
Core data for pulp and papermaking scenarios comes from wood pulp and waste paper batches, DCS/QCS systems, on-paper-machine measurement equipment, laboratory testing, and energy and water treatment systems. Documents generated daily include pulp preparation sheets, beating records, paper machine operation records, online quality curves, laboratory reports, and sheet break and product change records.

Data update frequencies include real-time (such as on-paper-machine measurement data), per shift (such as team operation records), and per roll (such as finished paper quality reports). Document fields include stock consistency, machine speed, grammage, moisture content, thickness, and more. Corresponding units are %, m/min, g/㎡, %, mm, and others.

## Constraints Imposed on Tool Calling and Plugin Workflows
Multiple heterogeneous data sources and varied update frequencies require tool calling to adapt to different data source retrieval logic and synchronization frequencies.

Diverse document formats, including text tables and curve charts, require plugins to support parsing non-general document formats exclusive to pulp and papermaking scenarios, such as quality curves and pulp preparation sheets.

Industry-specific fields and units require tool calling to include built-in unit verification and format conversion logic to prevent parameter mismatches.

Massive real-time data generated by high-speed continuous production requires tool calling to support batch data processing and reasonable timeout settings.

## How to Configure the System
This configuration applies to FastGPT v4.17.0

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | Adapt to on-demand triggering of multiple tools in pulp and papermaking scenarios, no manual tool specification required |
| Workflow/API function-call configuration | Enabled | Support calling dedicated tools for parsing paper machine operation curves and pulp preparation sheets |
| Maximum data per single tool call | 800–1200 characters | Match the average data length of single-roll paper machine operation records |
| Data retrieval timeout | 600 seconds | Adapt to data retrieval latency across multiple pulp and papermaking systems (DCS, laboratory) |
| Tool retry count | 2 times | Address call failures caused by temporary data fluctuations in papermaking systems |
| Data source filtering rules | Match current production batch | Accurately retrieve wood pulp, waste paper, and paper machine operation data for the corresponding batch |

## Three Common Configuration Mistakes
- Cannot find the function call configuration entry in the interface, and the tool module list is empty. The cause is that the tool calling permission for the corresponding large model is not enabled, or the tool calling switch is not activated in the application configuration.
- Returns empty fields after calling the tool that retrieves DCS data. The cause is that no papermaking-scenario-specific data source filtering conditions are specified, resulting in retrieval of irrelevant historical data.
- Tool call times out with a 504 status code error. The cause is that the data retrieval latency for multiple papermaking data sources is not accounted for, and the timeout setting is too short to complete full data retrieval and parsing.

## How to Verify Correct Configuration
- Enter the application's tool configuration interface, confirm that the `functionCall` switch is enabled, and `toolChoice` is set to `auto`.
- Initiate a simulated call, enter "Generate the pulp preparation sheet for the current shift", and check whether the tool successfully retrieves slurry data from the corresponding data source.
- View the tool call logs, confirm that the returned fields include papermaking-scenario-specific parameters such as grammage and moisture content.
- Trigger an exception report generation task, verify that the tool can parse the sheet break record field in the paper machine operation record.

The values provided are common starting points and should be measured against the reader's own samples.
