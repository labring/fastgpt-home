# Drafting Process Documents and Exception Reports for Spinning and Weaving: Workflow Orchestration

## What the data for this category looks like
Core data for the spinning and weaving category comes from raw fiber inspection, ERP inventory systems, real-time data from spinning machines and looms, evenness testers, fabric inspection machines, and order specification documents. Daily generated documents include cotton blending or ingredient lists, process setup sheets, equipment operation records, yarn inspection reports, grey fabric inspection reports, and defect records. Data update frequency is adjusted according to production rhythm. New data is generated for each batch of raw materials, each production shift, and each piece of fabric produced. Document fields include fiber fineness, cotton blending ratio, spinning twist, weaving structure parameters, defect type and location, and more. Some equipment-collected data has clear numerical units.

## What constraints these characteristics impose on workflow orchestration
The data for this category is multi-source, heterogeneous, and updated at high frequency. Workflow orchestration must support real-time synchronous calls across multiple data sources, to avoid errors in process documents and exception reports caused by data lag. Core documents contain professional process parameters and defect records. The workflow must preset variable rules for corresponding fields, to ensure extracted information conforms to industry-standard expressions. There are many pieces of equipment, and defects are prone to continuous spread. The workflow must arrange nodes in the order of production processes: first complete raw material blending and process parameter verification, then handle exception record generation, to prevent incorrect parameters from flowing to subsequent processes.

The following configurations are based on FastGPT v4.17.0, and are adapted to the workflow orchestration needs of the spinning and weaving category.

## Three common mistakes
- Symptom: The process document generated after the workflow runs lacks the cotton blending ratio field. Cause: The corresponding global variable was not configured in `variables`, so subsequent nodes cannot call this data.
- Symptom: Global variables cannot be used in subsequent modules under the specified `nodeId`. Cause: The global scope was not enabled on the variable configuration page, or the preceding node did not complete variable assignment.
- Symptom: Extracted defect type keywords are inaccurate, causing the generated exception report to fail to match the corresponding reference documents. Cause: Keyword extraction rules were not optimized for professional terms such as insufficient yarn strength and fabric hole defects, leading to insufficient matching of recalled reference documents.

## How to confirm the configuration is correct
- Manually trigger a test workflow, check whether the generated process setup sheet includes preset fields such as fiber fineness and cotton blending ratio.
- Enter the variable configuration page, confirm that all core business variables preset in `variables` have been enabled and their scope is set to global.
- Simulate a shift-end equipment data synchronization event, verify whether the workflow starts automatically and completes the execution of corresponding nodes.
- View the node call log, confirm that execution follows the order of cotton blending data extraction, process parameter verification, and exception report generation.
