# Spinning and Weaving: Process Document and Exception Report Drafting - Citation Sourcing and Traceability

## What Data for This Category Looks Like
The main entities in this category are cotton spinning, chemical fiber spinning, woven fabric, and knitted fabric enterprises. Daily generated documents include cotton blending or ingredient lists, process setup sheets, equipment operation records, yarn inspection sheets, gray fabric inspection sheets, and defect records. Data sources include raw fiber inspection reports, ERP systems, real-time data from spinning and looms, evenness tester test results, fabric inspection machine output data, and order specification documents. Data update frequency adjusts based on raw material batches, production shifts, and finished fabric lots. Each document includes fields such as fiber length, impurity rate, twist, weaving width, defect type, and fabric length. Corresponding units are millimeters, %, twists per meter, centimeters, count, and meters.

## What Constraints Do These Characteristics Impose on Citation Sourcing and Traceability
Multi-source data, high-frequency update rhythms, and diverse document structures for this category require the citation traceability link to accurately match identifiers such as batch, equipment, and inspection time. This prevents invalid cross-batch data from being cited. Mixed calls for multiple document types need unified retrieval logic for tabular cotton blending lists and sequential defect records. High-frequency updated data requires the traceability link to quickly locate the latest production and inspection records. It also needs to associate data sources from different systems. Original test data and process parameters can be traced when drafting exception reports. Subsequent issues such as unqualified yarn strength and continuous fabric defects are avoided.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `8000–12000 token` | Spinning and weaving process documents and exception reports need to carry citation content from multiple equipment records and inspection sheets. This value range covers all fully associated documents for a single production batch. |
| `responseData` | Enable document metadata display | Traceability requires matching key identifiers such as specific cotton blending batches, loom numbers, and inspection times. Metadata provides these core positioning details. |
| `detail` | Enable | Exception report drafting needs to trace specific test values for defects and process adjustment records. Detail mode returns more complete citation fragments. |
| Single search limit | `Top 8 recall results` | A single batch of raw materials corresponds to multiple inspection and equipment records. 8 results cover the main associated data, avoiding redundant content that disrupts drafting. |
| Knowledge base incremental update cycle | `Every 6 hours` | Data updates occur per shift and per fabric lot. A 6-hour cycle covers shift-based updates, ensuring the timeliness of cited data. |

## Three Common Misconfigurations
- Symptom: Only 1 citation result is returned when calling the knowledge base. The interface displays "Knowledge Base Citation (1 entry)". This fails to meet the need for multi-document citations. Cause: The single search limit configuration was not adjusted. The default value is too low, so it cannot recall multiple associated production and inspection documents.
- Symptom: After importing a designated spinning and weaving knowledge base, the data source selection is empty. The target library must be manually reselected. Cause: No default binding rule was configured for the knowledge base. The dedicated spinning and weaving document library was not set as the default call source.
- Symptom: The test data cited in the generated exception report cannot be traced. Clicking the link fails to redirect. Cause: Metadata persistence configuration for `responseData` was not enabled. The cited document fragments were not bound to traceable storage addresses.

## How to Verify Proper Configuration
- Initiate a query that includes "the third cotton blending list from May 2024". Check if the number of citation results in the returned content matches the configured single search limit.
- Review the attached information for each returned result. Confirm that it includes metadata such as document name, batch number, and loom number.
- Try clicking the cited traceability link. Confirm that it redirects to the original fragment of the corresponding document.
- Import a new batch of defect records. Wait for the configured incremental update cycle. Verify that the new data can be recalled normally.

The values provided here are common starting points. They should be evaluated against the reader's own samples.
