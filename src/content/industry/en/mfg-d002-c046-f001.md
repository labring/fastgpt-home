# Process Document and Exception Report Drafting for Meat Products and Slaughter Processing: HTTP Interfaces and External Systems

## What the data for this category looks like
Core data for this category originates from the full production process of slaughterhouses, cooked meat and frozen prepared food enterprises. Daily documents include animal quarantine certificates, slaughter and cutting records, ingredient marinating records, thermal processing records, cold chain temperature records, and microbial test reports.
Data sources cover animal quarantine information, supplier batch ledgers, production traceability systems, temperature collection equipment, metal detection equipment, and laboratory test results. Update frequency follows production batches and shift schedules. Cold chain temperature records are updated continuously.
Data fields include batch number, quarantine number, temperature value (℃), test time, microbial test indicators, and more. Strict alignment with production traceability association requirements is mandatory.

## What constraints these characteristics impose on HTTP interfaces and external systems
This category’s data characteristics impose clear constraints on HTTP interface configuration.
Data is updated per production batch and shift, so interfaces must support triggering document upload and synchronization via batch identifiers.
The data includes sensitive compliance data such as animal quarantine and microbial test reports, so the `Authorization` parameter must use an enterprise-specific permission key to prevent unauthorized access.
Cold chain temperature records are continuously collected bulk data, so the number of records submitted in a single request must be limited to a reasonable range to avoid interface timeouts.
Data fields include exclusive identifiers such as batch number and temperature unit, so interfaces must support custom variable binding to ensure accurate association between knowledge base documents and production batches.
The rapid synchronization requirement for exception reports requires that interface response delay be controlled within an acceptable range to avoid impacting production processes.

| `variables` | Bind batch number, quarantine number, production shift | Match the batch traceability requirements of meat product processing, and enable accurate association between knowledge base documents and specific production links |
| `responseData` | Return batch ID, upload status, indexing progress | Facilitate external systems to track document upload results and synchronize the processing status of exception reports |
| Single upload limit | `500–1000 records` | Avoid interface timeouts caused by submitting bulk temperature control data in a single request, and adapt to the upload rhythm of continuously collected temperature data |
| Timeout period | `600 seconds` | Handle the upload requirements of large documents such as batch quarantine certificates and test reports, and ensure complete data submission |
| Model selection | Set based on actual testing | Adapt to different text extraction and exception analysis requirements, such as dedicated analysis scenarios for microbial test reports |

## Three common configuration mistakes
- Calling the chunk-mode pushdata API to upload documents results in persistent indexing status: The production batch identifier is not correctly bound via the `variables` parameter, causing the knowledge base to fail to associate documents by batch, and indexing progress stalls.
- An error is returned when calling the knowledge base query interface with an application key: The enterprise-specific API key is not used for `Authorization` verification, and an application-level access key is used incorrectly, so permission verification fails.
- Only GPT series models are displayed in text content extraction model selection: The supported model identifier is not passed via `variables` in the external system configuration, so only default model options are loaded in the FastGPT interface.

## How to confirm proper configuration
- Submit a slaughter record document with a unique quarantine number, and check that the upload status returned by `responseData` is successful.
- Call the knowledge base query interface, pass the bound batch number variable, and confirm that the returned results are associated with production documents of the corresponding batch.
- In the FastGPT v4.17.0 model selection list, confirm that the configured non-GPT models are visible and available.
- Submit bulk temperature control data, and check that the interface response does not exceed the preset timeout period, with no timeout errors.
