# Process Document and Abnormal Report Drafting for Meat Products and Slaughter Processing: Workflow Orchestration

## What This Category's Data Looks Like
Daily documents for this category include animal quarantine certificates, slaughter and cutting records, ingredient marinating records, thermal processing records, cold chain temperature records, and microbial test reports. Data sources include animal quarantine information, supplier batch ledgers, production traceability systems, on-site temperature collection devices, metal detection equipment, and laboratory test results.

Data updates are performed per production batch and each shift’s operating cycle. Cold chain temperature data is collected continuously. Document fields include batch number, quarantine identifier, temperature threshold, test values, and others. Temperature records use degrees Celsius as the unit. Microbial test results use colony-forming units as the statistical reference.

## Constraints Imposed on Workflow Orchestration
Data for this category is updated per production batch and each shift cycle, and cold chain temperature data is collected continuously. Workflow orchestration must bind batch variables in `variables` to associate corresponding documents, preventing cross-batch data confusion.

Continuously collected temperature data has a large volume. Workflows must limit the range of files read in a single operation to avoid node overload. Quarantine certificates and production records must be one-to-one matched. Workflows must configure association verification links to ensure batch information matches.

Control requirements for raw/cooked zoning and sterilization temperature require embedding parameter checks in workflows, triggering alerts for abnormal temperatures or non-compliant zoning. Documents related to biological risks must be stored strictly in accordance with traceability requirements. Workflows must clarify the storage node permissions corresponding to `nodeId` to prevent data leakage or tampering.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Bind batch number and quarantine number as required fields | Ensure each process document and abnormal report is associated with the corresponding production batch to avoid data misalignment |
| Single read file limit | Top 20 entries | Matches the document scale updated per batch for this category, prevents node lag |
| Storage node permissions | Bind traceability-specific nodes via `nodeId` | Complies with traceable storage requirements for biological risk documents, restricts unauthorized access |
| Abnormal verification threshold | Trigger when temperature deviates from set value by ±2℃ | Aligns with cold chain temperature control standards, intercepts abnormal data in a timely manner |
| Timeout setting | 600 seconds | Adapts to the upload and parsing duration of laboratory test reports, avoids process interruption |
| File chunk size | 800–1200 characters | Adapts to the text length of individual production records, improves parsing efficiency |

## Three Common Configuration Mistakes
- Phenomenon: Drag-and-drop lag or operational delay appears in the front-end interface when selecting batch variables in `variables`. Cause: The number of files read in a single operation is not limited, and excessive batch data loading simultaneously causes excessive node resource usage.
- Phenomenon: The abnormal report generated after the workflow runs lacks the quarantine number field. Cause: Required field verification is not configured in `variables`, and batch information from quarantine certificates is not associated.
- Phenomenon: Uploaded cold chain temperature records cannot be automatically associated with the corresponding production batch by the workflow. Cause: The storage node corresponding to `nodeId` is not bound to batch variables, and the file storage path does not include batch identifiers.

## How to Verify Proper Configuration
- Manually bind batch variables in `variables`, verify whether the workflow can automatically associate documents for the corresponding batch.
- Upload a cold chain temperature record that deviates from the set value, confirm whether the workflow triggers the preset verification link.
- Check the workflow storage node, confirm that uploaded production records are classified and stored according to the traceability node bound via `nodeId`.
- Run the workflow for a test batch, confirm that the generated process documents include all required document fields.
