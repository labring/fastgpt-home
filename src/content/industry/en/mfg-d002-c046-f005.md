# Drafting Process Documents and Exception Reports for Meat Products and Slaughter Processing: Tool Calling and Plugins

## What Data Looks Like for This Category
The data for this category comes primarily from animal quarantine information, supplier batches, production traceability systems, temperature collection devices, metal detection devices, and laboratory test results. Daily documents include quarantine certificates, slaughter and cutting records, ingredient marinating records, thermal processing records, cold chain temperature logs, and microbial test reports. Data updates align with production batches and shifts. Cold chain temperatures require continuous collection and recording. Each document includes clear fields for batch numbers, quarantine identifiers, temperature values, test indicators, and similar items. Units include degrees Celsius, batch numbers, qualified judgment identifiers, and more.

## Constraints for Tool Calling and Plugins From This Category’s Characteristics
This category requires binding batches to quarantine information. Tool calls must accurately associate corresponding numbers to avoid mixing cross-batch data. Continuously collected cold chain temperature data has large volume. Tool calls must support filtering valid data by time ranges. Raw and cooked zone separation and biological risk control require tool calls to distinguish data access permissions by production area. This prevents sensitive data leaks. Exception reports need rapid integration of multi-source production and test data. Tool call response delays must match production rhythms to avoid risk spread.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Mandatorily set to `functionCall` | Ensures tool calls strictly follow the preset process document and exception report generation workflow |
| Tool call trigger condition | Triggered after a production batch completes | Matches the batch-based production and test management logic for this category |
| Single tool call return count | Top 3 entries | Adapts to core data reading needs for a single batch |
| Tool call timeout threshold | 120 seconds | Matches real-time requirements for cold chain data collection and test results |
| Data association rule | Bind batch numbers and quarantine identifiers | Ensures generated documents and reports accurately correspond to production batches |
| Plugin data scope | Only current production shift data | Complies with data isolation control requirements for raw and cooked zone separation |

## Three Common Misconfigurations
- The tool call module returns empty fields after connecting to the knowledge base. The symptom is that generated process documents lack quarantine information for the corresponding batch. The cause is that the data association rule binding batch numbers and quarantine identifiers was not configured.
- The tool call module fails to respond. The symptom is that the module status shows a timeout. The cause is that the timeout threshold was set lower than the actual time required for data reading.
- The tool call continuously returns streaming output fragments. The symptom is that exception reports are returned in multiple segments. The cause is that `toolChoice` was not correctly configured for mandatory `functionCall` mode.

## How to Confirm Successful Configuration
- Submit simulated production batch data, and check if the tool call returns quarantine and production records for the corresponding batch.
- Trigger exception report generation, and check if the result correctly binds the batch number and quarantine identifier.
- View the tool call log, and confirm that the `functionCall` parameter has been correctly enabled with no segmented streaming output.
- Confirm that the FastGPT v4.17.0 tool call module has loaded normally.

All listed configuration values are common starting points. Adjust them based on your own specific samples and operational requirements.
