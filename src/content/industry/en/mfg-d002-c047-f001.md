# Drafting of Process Documents and Exception Reports for Measuring Instruments and Laboratory Management: HTTP Interfaces and External Systems

## What data for this category looks like
Data for this category comes from metrology management systems, external calibration institution certificates, LIMS systems, and environmental monitoring equipment. Daily documents include gauge ledgers, calibration plans, calibration certificates, periodic verification records, original test records, reference material ledgers, and deviation handling documents. Data fields include unique instrument numbers, calibration validity periods, measurement uncertainties, traceability numbers, and other relevant fields. Units include commonly used metrology units such as length, force, and temperature. Data update timing follows calibration cycles, completion of single tests, or triggering of abnormal events, with no fixed batch update cycle.

## What constraints do these characteristics impose on HTTP interfaces and external systems workflows
Multiple scattered data sources require interfaces to support multi-system authentication and cross-source data aggregation. Non-fixed update rhythms require interfaces to support both on-demand calls and scheduled triggering modes. Complex document structures require interfaces to adapt to field mapping for different types of business data. Strict traceability requirements require interfaces to retain complete call logs and associated identifiers. Data errors can lead to quality judgment deviations, so interfaces must return clear error messages and structured results.

## How to configure settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Carry a Bearer token with the interface key assigned by the platform | Verify external system call permissions and ensure access security for sensitive metrology data |
| `variables` | Pass key-value pair parameters such as instrument numbers, calibration cycles, and exception types | Adapt to field mapping for multiple types of documents and support customized drafting of process documents and exception reports |
| `responseData` | Configure a structured field set containing calibration results and traceability information | Facilitate external systems to directly extract core metrology data and support automatic document generation |
| Scheduled triggering configuration | Set the trigger interval according to the calibration cycle, with values of 7 days, 30 days, or 90 days | Match the calibration update rhythm of measuring instruments and ensure the timeliness of process documents |
| Exception triggering configuration | Bind to abnormal alarm events from the LIMS system | Trigger the drafting process for exception reports in real time and meet rapid disposal requirements |

## Three common configuration mistakes
- When calling the interface to connect to a MySQL database, metrology ledger data cannot be extracted. The cause is that the field mapping between database fields and process document templates is not configured via the `variables` parameter.
- After uploading a calibration certificate via the API, the generated process document sections do not match those of documents uploaded directly through the platform. The cause is that the field extraction rules for `responseData` are not correctly configured, leading to differences in metadata processing logic between upload paths.
- When calling the interface on a scheduled basis to send exception reports, the external system does not receive the request. The cause is that the `Authorization` parameter is not correctly set, or the token permissions do not cover the access scope of the target external system.

## How to confirm the configuration is complete
- Call the interface with a known instrument number, and check whether the fields returned in `responseData` include core metrology data such as calibration dates and measurement uncertainties.
- Trigger the scheduled task and check whether the external system receives request parameters that conform to metrology document formats.
- Simulate an abnormal event and verify whether the interface automatically generates exception report content containing deviation handling information.
- View the interface call logs and confirm that the business fields passed via the `variables` parameter fully match the preset template.
