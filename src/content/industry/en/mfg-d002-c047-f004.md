# Drafting of Process Documents and Exception Reports for Measuring Instruments and Laboratory Management: Workflow Orchestration

## What data for this category looks like
This category of data originates from daily operations of enterprise metrology rooms and CNAS system laboratories. It includes gauge ledgers, calibration plans, calibration certificates, interim verification records, test raw records, reference material ledgers, and deviation handling documents. Data sources include metrology management systems, external calibration institution certificates, standard instruments, LIMS systems, and environmental monitoring equipment. Updates are triggered by calibration cycles, completion of individual tests, or exception events. Document fields include unique instrument numbers, calibration validity periods, measurement results, and traceability chain information. Units include metrology-related professional units such as length, force, and concentration.

## How these characteristics impact workflow orchestration
Multi-source data access for this category requires workflows to integrate with external data sources such as metrology management systems and LIMS. Unified variable management is needed to standardize field formats across different systems. Non-fixed update rhythms require workflows to support mixed trigger configurations: event-triggered, scheduled, and manual. Professional fields and measurement units require workflow node parameters to match exclusive fields like instrument numbers and calibration validity periods, to avoid mismatches from generic parameters. Exception-triggered update scenarios need built-in exception branch handling to quickly generate emergency documents such as deviation reports. The data traceability chain requirement also means workflows must retain complete invocation and data source logs.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Prioritize obtaining parameters from specified business variables; use plugin preset default values if not obtained | Data sources for this category are scattered, so latest data from metrology management systems and LIMS should be used first |
| Batch execution node | Generate calibration plans and interim verification records in batches according to calibration cycles | Calibration plans and interim verification records for this category are updated on fixed cycles, and batch execution improves processing efficiency |
| Ultra-long text generation limit | 800–1200 characters | Standard professional length of calibration certificates and test raw records usually falls within this range, adapting to document display and storage requirements |
| `nodeId` | Bind exclusive node ID for metering instrument traceability chain | This category requires complete data traceability logs, and binding exclusive node ID enables precise tracking of data sources and invocation links |
| Variable update counting rule | Count by exception type, with a single counting interval of 1000 milliseconds | Exception events for this category need classified statistics, and the interval setting avoids duplicate counting |
| Timeout retry count | 2 times, with a 60-second interval | Temporary network fluctuations may occur when downloading external calibration institution certificates, and retries reduce workflow failure rates |

## Three common configuration errors
- Phenomenon: Calibration certificates generated by workflows lack the measurement uncertainty field. Cause: No source variable for measurement uncertainty is configured in `variables`, and no default value is set. This leaves the field empty of valid data.
- Phenomenon: Duplicate entries appear in interim verification records generated by batch execution nodes. Cause: No deduplication rule is set for batch execution, leading to repeated generation of test data for the same instrument.
- Phenomenon: The exception count recorded by the variable update counting node does not match actual occurrence numbers. Cause: No counting trigger conditions or intervals are configured, causing multiple counts for the same exception event.

## How to verify correct configuration
- Trigger a calibration certificate generation workflow on the FastGPT v4.17.0 platform, and verify the generated document includes the latest measurement results and traceability chain information exported from the metrology management system.
- Run the batch execution node, and verify the number of generated interim verification records matches the count of currently valid metering instruments.
- Simulate an exception event to trigger the workflow, and verify the variable update counting node correctly records one exception occurrence.
- Generate an exception report, and confirm the generated text length falls within the preset range.
