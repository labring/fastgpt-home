# Drafting of Process Documents and Exception Reports for Measuring Instruments and Laboratory Management: Knowledge Base Retrieval and Recall

## What this category of data looks like
Data for this category comes from enterprise metrology rooms, metrology management systems in CNAS-accredited laboratories, LIMS platforms, external calibration institution certificates, and standard instrument data. Daily documents include gauge ledgers, calibration plans, calibration certificates, interim verification records, original test records, reference material ledgers, deviation handling records, and more. Fields include unique instrument numbers, calibration dates, measured values, measurement uncertainty, traceability chain associated information, and others. Units include millimeters, newtons, percentages, milligrams per liter, and other specialized metrology units. Data updates are triggered by calibration cycles, each test, or exception situations, with no fixed batch update schedule.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
Data sources are scattered and have diverse formats, requiring connection of multiple data sources. During recall, core metrology fields from different documents must be consistently identified. Documents contain high-precision numerical values and strict traceability information, so retrieval results must match original data to meet metrology confidence requirements. Update cycles are not fixed, so systems must support incremental recall to avoid repeated processing of already calibrated instrument data. Process documents and exception reports require linkage to full-cycle metrology data for specific instruments. Retrieval must prioritize matching strongly related fields, otherwise process parameter errors or invalid exception judgments occur.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `similarity` | 0.75-0.85 | Metrology data requires guaranteed confidence, to avoid recalling low-matching non-corresponding calibration records |
| `limit` | Top 5 entries | Control the number of documents recalled per round, to avoid excessive historical records interfering with drafting work |
| `searchMode` | Exact match | Prioritize matching core fields such as instrument number and calibration date, which meets the rigor requirements of metrology data |
| `usingReRank` | Enabled | Reorder recall results based on traceability chain completeness and measurement uncertainty precision, to improve visibility of key information |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically supplement context keywords related to instrument traceability, to strengthen cross-document associated recall |
| `collectionIds` | Specify dedicated collection IDs for measuring instruments | Isolate business data, to avoid recalling documents from other categories that cause interference |

This configuration is based on the parameter logic of FastGPT v4.17.0.

## Three Common Mistakes
- No parsing completion prompt after uploading calibration certificate PDFs, and search test results are empty. The cause is that batch parsing status notifications are not enabled, and documents are not imported into the dedicated measuring instrument collection.
- Knowledge base content is not called during exception report drafting, and the generated content does not match actual metrology data. The cause is that the `similarity` threshold is set too high, resulting in no qualifying recall results.
- Knowledge base information extraction returns empty values in the workflow. The cause is that document chunking does not cover the traceability chain fields of calibration certificates, leading to key associated information not being vectorized.

## How to Confirm the Configuration Is Set Correctly
- Upload a single calibration certificate, check the platform’s parsing status, and confirm there are no format errors and parsed fields include core content such as instrument numbers, measured values, and traceability information.
- Initiate a search test, enter the unique number of a specified instrument, and verify that corresponding ledgers, calibration plans, historical calibration certificates, and other documents are recalled.
- Adjust the `similarity` threshold to 0.8, initiate an exception report drafting test, and confirm that results include the measurement uncertainty information from the calibration certificate.
- Check workflow logs, and confirm that the number of documents returned by the knowledge base retrieval step matches the value set in the `limit` configuration.

The configuration values provided here are common starting points, and should be evaluated against samples relevant to the specific deployment.
