# Drafting Process Documents and Exception Reports for Measuring Instruments and Laboratory Management: Deployment and Upgrade

This page is written based on FastGPT v4.17.0.

## What the Data for This Category Looks Like

Core data for this category comes from metrology management systems, external calibration institution certificates, reference standards, LIMS systems, and environmental monitoring equipment. Daily generated documents include gauge ledgers, calibration plans, calibration certificates, interim check records, original test records, reference material ledgers, and deviation disposition forms.

Data update frequency is not fixed. It triggers based on calibration cycles, single test results, or abnormal events. Documents include fixed fields and custom fields. Fixed fields include instrument number, calibration value, measurement uncertainty, and traceability chain number. Units cover metrology-specific units such as length, force, and temperature. Custom fields must match the special requirements of the enterprise’s metrology system.

## Constraints Imposed by These Characteristics on Deployment and Upgrade

The data characteristics of this category impose multiple constraints on deployment and upgrade.
Multi-source heterogeneous data sources require adapting to different systems’ API interfaces and data formats during deployment. This prevents data synchronization failures.
Non-fixed update frequencies require configuring incremental synchronization mechanisms. This reduces system resource usage.
Rich document fields and specialized units require support for custom field mapping and unit verification. This ensures the accuracy of process documents and exception reports.
Severe consequences of errors require adding a data verification link during deployment. Conduct legality checks on key fields such as traceability chains and measurement uncertainty. This stops invalid data from entering the system.
The traceability of metrology data requires retaining a complete data link during deployment. This supports subsequent audits.

## Configuration Settings

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://<username>:<password>@<host>:<port>/fastgpt_meter?authSource=admin` | Stores large-volume unstructured documents such as calibration certificates and original test records |
| `REDIS_URL` | `redis://:<password>@<host>:<port>/0` | Caches calibration cycle reminders and exception report task queues to reduce database access pressure |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.100:9000` | Adapts to self-built object storage addresses, used to store large-capacity calibration certificates and reference material ledgers |
| `DB_MAX_LINK` | `20–30` | Adapts to concurrent connection requirements for multi-source data synchronization, avoiding connection pool exhaustion |
| `PG_URL` | `postgresql://<user>:<pass>@<host>:<port>/fastgpt_meter` | Stores structured business data such as measuring instrument status and traceability chains |
| Team Management Toggle | Enable in the system settings interface | Restricts document access and configuration permissions for metrology room personnel, complying with permission control requirements of the metrology system |

## Three Common Misconfigurations

- Accessing the deployed URL returns 405 Method Not Allowed. Cross-origin rules for `FE_DOMAIN` and the backend service address are not correctly configured. Requests get blocked.
- The team management function cannot be enabled normally. `ROOT_KEY` is not configured in the environment variables and bound to an administrator account. The permission control module fails to load.
- A timeout error occurs when generating an exception report. `DB_MAX_LINK` is set too low. The connection pool is exhausted during multi-source data synchronization. Real-time data from the metrology system cannot be read in a timely manner.

## How to Verify Successful Configuration

- Access the domain specified by `FE_DOMAIN`. Confirm the page loads normally and no cross-domain error prompts appear.
- Upload a standard calibration certificate. Confirm fields such as instrument number, calibration value, and uncertainty in the document are correctly extracted and stored in the database corresponding to `PG_URL`.
- Trigger an exception report generation task. Confirm the task queue is scheduled normally through `REDIS_URL`, with no task backlog prompts.
- Log in to the system with an administrator account. Confirm the team management function can properly configure personnel permissions and access scope.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
