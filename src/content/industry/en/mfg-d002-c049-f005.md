# Process Quality and Finished Product Release: Drafting Process Documents and Exception Reports via Tool Calls and Plugins

## What Data for This Category Looks Like
This category of data originates from MES systems, online testing equipment, laboratory systems, process parameter libraries, customer quality standards, and historical defect databases. The system updates data per production batch, per shift rotation, and via continuous collection. Daily produced documents include control plans, patrol inspection records, SPC reports, finished product inspection reports, nonconforming product review forms, release forms, and quality monthly reports. Fields cover inspection item parameters, deviation values, judgment results, responsible teams, release permission identifiers, and similar items. No fictional statistical values are included.

## Constraints Imposed on Tool Calls and Plugin Workflows
Multi-source heterogeneous data sources require tool calls to support integration with different external interface types including MES and testing equipment. Return data in varying formats must be processed uniformly.
Frequently updated business data requires tool calls to bind fixed session contexts. Each call associates with current batch production information, avoiding retrieval of expired inspection records or process parameters.
Fine-grained document fields require tool call parameters to match dedicated fields such as inspection items, deviation values, and release permissions. General-purpose parameter templates cannot be used.
The risk of accidental release of nonconforming products requires tool calls to add permission verification steps. Non-authorized users are restricted from triggering plugin operations related to releases.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to process document content across different production batches, automatically trigger tool calls for corresponding data sources |
| `functionCall` | Set a maximum of 3 tool functions per call based on actual testing | Match the call requirements for multiple document fields in this category, avoid overload from single calls |
| Session context binding | Bind the current production batch ID | Associate with corresponding batch data in the MES system, ensure called data matches current business needs |
| Session retention duration | 8 hours | Cover the full workflow of a single shift, ensure multiple tool calls use the same session |
| HTTP request timeout | 300 seconds | Adapt to latency when retrieving data from testing equipment, avoid call failures due to unreturned data |
| Tool call result filtering | Return only structured report content, truncate redundant logs to under 2000 characters | Prevent unnecessary intermediate steps from being included in final exception reports |

This configuration set applies to FastGPT v4.17.0

## Three Common Misconfigurations
- Symptom: Tool call module output in the workflow is directly displayed in the final report and cannot be hidden. Cause: `toolChoice` is not configured to call only tools without returning intermediate responses, causing intermediate tool logs to be included in finished product reports.
- Symptom: The term "share" in input text is incorrectly converted to garbled or mistranslated text when passed to tool calls. Cause: Text standardization verification within the session is not enabled, or the encoding format of the plugin-connected interface does not match the current session, leading to character translation errors.
- Symptom: The HTTP request component cannot receive numeric parameters passed by the plugin, triggering a `Request failed with` error. Cause: Plugin parameters are not mapped to query or body fields of the HTTP request, or parameter formats do not match the interface-required types, leading to request parsing failures.

## How to Verify Successful Configuration
- Trigger a single tool call for finished product inspection of one batch. Verify that the called interface is associated with the current production batch ID, confirming matching data sources.
- Review the tool call return results. Confirm that only structured inspection data or exception report content is included, with no redundant logs from intermediate steps.
- Initiate two consecutive tool calls. Verify that both calls bind the same production batch in their session contexts, ensuring session consistency.
- Simulate a scenario with incorrect parameter passing. Confirm that the system triggers corresponding error messages and blocks unauthorized requests, verifying that permission and parameter verification configurations are active.

All provided configuration values are common starting points. They should be evaluated against the reader's own samples.
