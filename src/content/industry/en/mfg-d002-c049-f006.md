# Process Quality and Finished Product Release: Drafting Process Documents and Exception Reports – Citation Sources and Traceability

## Data Profile for This Category
Data for this category comes from manufacturing enterprise MES systems, online testing equipment, laboratory systems, process parameter libraries, customer standards, and historical defect databases. Daily generated documents include control plans, patrol inspection records, SPC reports, finished product inspection reports, nonconforming product review forms, release forms, and quality monthly reports. Single documents contain fields such as batch number, inspection item, test value, and review conclusion. Update frequency follows per production batch, per shift, or continuous collection. Data structures vary significantly by document type. Some documents include real-time collected process parameters, while others are batch-aggregated statistical reports.

## Constraints on the Citation Sources and Traceability Link
Multi-source, heterogeneous data structures require the traceability link to accurately associate document types with corresponding fields. This avoids confusion between inspection data and review conclusions from different sources. High-frequency data updates require the citation system to retrieve latest test results and review records in real time. This ensures the timeliness of release basis. Differences in fields across documents—for example, SPC reports include statistical parameters, while nonconforming product review forms include responsibility determinations—require traceability information to retain original document metadata. This supports quality personnel in verification work. Consequences of errors in this category directly relate to production line shutdowns and customer recalls. Therefore, the traceability link must ensure cited content fully matches original data, with no omissions or tampering.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| Maximum Citation Token Count | Set `quoteMaxToken` to 1200–1800 tokens | Adapts to the average length of single documents in this category, avoids truncating key test values and review conclusions |
| Response Data Format | Select "With Metadata" for `responseData` | Retains fields such as document source, batch number, and update time, meeting the requirements for accurate traceability association |
| Detail Return Level | Set `detail` to "Full Fragment" | Retains the original document's field information, facilitating quality personnel to verify the authenticity of cited content |
| Single Recall Limit | Top 6–10 entries | Covers associated data from multiple sources in this category, avoids omitting key process or exception records |
| Block Length Validation | Enabled | Ensures knowledge base blocks exceeding `quoteMaxToken` are truncated, prevents cited content from exceeding the set range |

## Three Common Configuration Mistakes
- Symptom: After setting `quoteMaxToken` to 1500 tokens, knowledge base blocks exceeding the length are still cited. Cause: The block length validation function is not enabled. The system only selects fragments according to recall rules, and does not automatically truncate content beyond the threshold.
- Symptom: After the knowledge base retrieval results are passed to an HTTP request in a workflow, the AI conversation cannot generate valid citation traceability information. Cause: The metadata fields in `responseData` are not correctly passed, preventing the AI from associating document sources and batch information.
- Symptom: Matching knowledge base content is retrieved, but only citation identifiers are returned, with no specific document fragments. Cause: `detail` is set to "Only Identifiers", and full fragment return is not enabled, making it impossible to display specific traceability basis.

Run a complete workflow including knowledge base retrieval, HTTP request processing, and AI conversation. Check if AI replies include complete traceability information and metadata.
Import document fragments exceeding the set `quoteMaxToken` length, and confirm the system automatically truncates excess content, retaining only content within the threshold.
