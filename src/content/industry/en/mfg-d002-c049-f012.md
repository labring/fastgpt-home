# Process Quality and Finished Product Release: Process Document and Exception Report Drafting - Deployment and Upgrade

## What Data for This Category Looks Like
Data for this category comes from MES systems, production testing equipment, laboratory systems, process parameter libraries, customer quality standards, and historical defect libraries.
Daily generated documents include control plans, patrol inspection records, SPC reports, finished product inspection reports, nonconforming product review forms, release forms, and quality monthly reports.
Data is collected continuously per production batch and each shift. Some historical data is synchronized on demand.
Document fields include batch identifiers, inspection parameter thresholds, defect types, review opinions, and release identifiers.
Corresponding units cover standard production and inspection scenario units such as number of produced parts, inspection duration, and nonconformance grades.

## What Constraints These Characteristics Impose During Deployment and Upgrade
Multiple data sources and real-time updates require configuring multiple storage connections during deployment. This supports bulk data writes and high-frequency queries.
Access to multi-format documents requires adapting different parsing rules. This avoids format parsing failures.
The complexity of data fields requires accurate mapping of business fields during vector database import. This ensures retrieval accuracy.
Core data related to finished product release must remain consistent. Configuration changes during deployment and upgrades must not cause data synchronization interruptions. Such interruptions would disrupt production workflows.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–200 records/minute` | Adapts to bulk data write cadence per batch and shift, prevents database connection pool exhaustion |
| `MONGODB_URI` | `Exclusive connection string for production quality database` | Stores unstructured documents such as SPC reports, nonconforming product review forms, and historical defect libraries |
| `REDIS_URL` | `Intranet access address for local Redis instance` | Caches query results for real-time patrol inspection records and release forms, reduces query pressure on the primary database |
| `STORAGE_S3_ENDPOINT` | `Access endpoint for enterprise internal object storage` | Stores large-volume documents such as finished product inspection reports and control plans, supports bulk storage requirements |
| `FE_DOMAIN` | `Public or intranet domain for deployed services` | Matches the correct access path when generating process document download links, prevents link failure |
| `FILE_TOKEN_KEY` | `Randomly generated 32-character encrypted string` | Encrypts knowledge base original document download links, prevents unauthorized access to core quality documents |

These configurations apply to FastGPT v4.17.0.

## Three Common Misconfigurations
- Knowledge base original document download links fail to load, returning 403 or 404 errors: `FE_DOMAIN` and nginx proxy rules are not configured correctly, causing generated download links to not match actual access paths.
- Quality data synchronization tasks interrupt after container restart: Core configurations such as `MONGODB_URI` and `REDIS_URL` are only passed as temporary startup parameters instead of being written to persistent environment variables, resulting in lost configurations after restart.
- Connection timeout occurs when bulk importing nonconforming product review records: `DB_MAX_LINK` value is not adjusted based on data write frequency, so the connection pool cannot support bulk write requests.

## How to Confirm Configurations Are Properly Set Up
- Access the download link corresponding to the configured `FE_DOMAIN` to verify that process documents and exception report originals can be downloaded normally.
- Run environment variable query commands in the deployment container to confirm that configuration parameters such as `MONGODB_URI` and `REDIS_URL` have been loaded correctly.
- Submit a test patrol inspection record, wait 1 minute, then query the corresponding storage to confirm that data has been written successfully.
- Generate a preview link for an exception report, verify that the encrypted parameter `FILE_TOKEN_KEY` has not been tampered with, and that the link can be accessed normally.

The values provided are common starting points and should be measured against the reader's own samples.
