# Drafting Process Documents and Exception Reports for General Mechanical Equipment Assembly: Workflow Orchestration

## What this category's data looks like
Data for general mechanical equipment assembly scenarios mainly comes from PLM, ERP, parts inspection systems, assembly tool collection terminals, test benches, MES, and customer technical agreements. Daily documents include assembly process cards, multi-level BOMs, torque records, clearance adjustment records, commissioning reports, factory inspection sheets, and packing lists. Data is updated per single device or per order. Document fields include part numbers, torque values, clearance parameters, test results, and other details. Some documents need to match physical serial numbers and inspection values.

## What constraints these characteristics impose on the workflow orchestration link
Multi-level BOMs require tier-by-tier verification, which requires workflows to support nested variable calls. Data updated per single device or order needs to be bound to unique identifiers to avoid cross-order confusion. Multi-source data has significant format differences, so unified field mapping rules need to be configured. Exception reports need to be linked to original records of corresponding assembly steps, requiring workflows to retain data traceability links. Document fields for different orders have custom differences, so dynamic variable adaptation needs to be supported.

## How to set the configuration
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Variable Reference | Bind the single device serial number and BOM level from `variables` | Adapt to the data characteristics updated per single device or order |
| Knowledge Base Selection | Link to the exclusive document library for the corresponding order | Ensure the called process documents match the current assembly task |
| Session Submit Button | Configure after the exception report filling node | Trigger archiving of exception data and process flow |
| Mermaid Flowchart Generation | Call MCP Server and pass assembly process parameters | Generate standardized process flowchart links |
| Timeout Threshold | 600–1200 seconds | Adapt to delay fluctuations in multi-source data collection |
| Single Recall Limit | Top 10 entries | Adapt to the recall coverage range of multi-source documents |

## Three common mistakes
- Workflows return empty process document fields, shown as blank pages or missing torque and clearance parameters. The cause is that the device serial number in `variables` is not bound to the knowledge base search conditions, resulting in no matching documents for the current order.
- The session submit button does not trigger the process normally, shown as no log updates or process stagnation after clicking. The cause is that the `nodeId` of the button node is not configured as the trigger source for the subsequent archiving node.
- The generated Mermaid flowchart does not match the actual assembly process, shown as missing key debugging steps in the flowchart. The cause is that the BOM level parameters for the corresponding process are not passed, resulting in an incomplete generated process.

## How to confirm the configuration is correct
- Enter the serial number of a single device, verify whether the workflow can automatically pull the assembly process card and BOM data for the corresponding order.
- Click the submit button at the exception report filling node, check whether the process triggers archiving of exception data and circulation logs.
- Pass parameters for the specified assembly process, verify whether a compliant Mermaid flowchart link can be generated and accessed normally.
- Adjust the value range of the timeout threshold, simulate multi-source data delay scenarios, and confirm that no timeout errors occur in the process.

The values provided are common starting points and should be measured against the reader's own samples.
