# Drafting Process Documents and Exception Reports for General Mechanical Equipment Assembly: Tool Calling and Plugins

## What This Category of Data Looks Like
Daily documents for general mechanical equipment assembly include assembly process cards, multi-level BOMs, torque records, clearance adjustment records, commissioning reports, factory inspection sheets, and packing lists. Data sources typically include PLM/ERP systems, part inspection data, assembly tool collection terminals, test benches, MES systems, and customer technical agreements. Data is updated once per device or per order, and includes fields such as equipment model, order number, assembly date, torque value (unit: N·m), clearance value (unit: mm), coaxiality tolerance (unit: μm), and others.

## What Constraints Do These Data Characteristics Impose on the Tool Calling and Plugin Workflow
These data characteristics impose multiple constraints on the tool calling and plugin workflow. Multi-source and heterogeneous data sources require plugins to support interfacing with different systems, and adapt to return data in varying formats such as PLM and MES. The per-device or per-order update rhythm requires each tool call to accurately pull the latest data for the corresponding batch, to avoid using expired content. The nested structure of multi-level BOMs requires plugins to support nested data parsing, to enable layer-by-layer verification of material availability. Fields with specific units require plugins to include built-in unit validation logic, to prevent process document errors caused by unit mismatches.

## How to Set the Configuration
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to the automatic calling logic of multi-data-source plugins, no need to manually specify each plugin |
| Single Search Limit | Top 8 entries | Matches the typical content length of a single page of assembly process cards, avoids interference from redundant data |
| Timeout Period | 300 seconds | Adapts to the interface response cycle across PLM and MES systems, prevents call failures caused by network delays |
| `functionCall` | Enabled | Supports calling external MCP plugins to parse multi-level BOM and torque record data |
| Context Window Limit | 16000 token | Adapts to the long-text parsing requirements of complete assembly process cards |

All of the above configurations apply to FastGPT v4.17.0.

## Three Common Mistakes
- API calls return a 403 permission denied error: This occurs because the access scope of the corresponding API key has not been configured on the FastGPT platform, and the call permissions for the required plugins have not been bound.
- Workflow calls to MCP plugins display "service not found": This occurs because the MCP service was not registered in the plugin management module before directly calling the plugin node in the workflow.
- Tool call timeout errors occur: This occurs because a reasonable timeout period was not set, and the response delay of cross-system interfaces was not accounted for, leading to interruptions in the call process.

## How to Verify That the Configuration Is Properly Set
- Pass a test order number to call the API, and check whether the returned BOM data matches the order bill of materials in the corresponding PLM system.
- Add an MCP plugin node to the workflow, select the registered assembly data parsing plugin, run the test node, and check whether parsed results for clearance adjustment records can be returned.
- After configuring the timeout period, simulate a cross-system call, and check whether valid results are returned within the set time.
- Check whether the `functionCall` switch is enabled, and confirm that the parameter format for plugin calls meets the parsing requirements of assembly process documents.

The values provided are common starting points and should be evaluated against the reader's own samples.
