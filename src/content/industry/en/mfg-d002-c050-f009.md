# Drafting Process Documents and Exception Reports for General Mechanical Equipment Assembly: Model Access and Configuration

## What Data for This Category Looks Like
Data for general mechanical equipment assembly scenarios primarily comes from PLM/ERP systems, parts inspection data, assembly tool collection terminals, test benches, MES systems, and customer technical agreements. Daily generated documents include assembly process cards, BOM lists, torque records, gap adjustment records, trial run reports, factory inspection certificates, and packing lists. Data is updated once per equipment or per order. Document fields include standardized assembly parameters, inspection results, and delivery information. Most units use precision measurement units such as Newton meters, millimeters, and micrometers.

## What Constraints These Characteristics Impose on Model Access and Configuration
Data sources for this category are scattered, and include precision measurement data collected from multiple systems. Model access configuration must support unified connection of multiple data sources, and avoid data synchronization delays. Document update frequency is per single equipment or per order, which requires adaptation to frequent content changes. Context window configuration must support dynamic adjustment to accommodate the latest assembly and inspection records. There are diverse document types, including step-by-step process cards and list-style BOMs. Configuration must support multi-format text parsing rules. Verification of precision parameters must limit token usage to ensure content accuracy.

## How to Set Configuration
| Configuration Item | Recommended Value | Rationale for This Value
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Fits the total length of multiple documents related to single-equipment assembly, covers full content of process cards, BOMs, and inspection records, avoids context overflow
| `maxTokens` | 2000–3000 token | Limits the output length of documents per drafting session, ensures process documents and exception reports comply with standard formats for assembly scenarios
| `quoteMaxToken` | 1500 token | Limits the maximum length of referenced source data, ensures accurate and non-redundant reference of precision data such as torque values and gap parameters
| `temperature` | 0.2–0.4 | Reduces randomness of generated content, ensures consistency of assembly parameters and inspection results, meets the rigor requirements of the scenario
| `AIPROXY_API_ENDPOINT` | Fill in according to the enterprise's internal proxy address | Adapts to the enterprise's internal network environment, resolves access issues when there is no network connectivity
| Workflow/API tool selection | auto | Automatically selects tool calls, adapts to needs of multi-data-source parameter verification and document splicing

## Three Common Misconfigurations
- An error occurs when starting the model access container, showing a no-network error, or prompting that API resources cannot be obtained. Cause: The enterprise's internal network proxy address is not configured, or the container deployment environment does not have external access permissions enabled.
- Generated exception reports or process documents contain a large number of meaningless punctuation marks. Cause: The `temperature` parameter is not adjusted to a reasonable range, resulting in redundant format errors in generated content, or context filtering rules are not configured to clear invalid markers.
- The model cannot be called normally after configuring the API key. Cause: The `AIPROXY_API_TOKEN` parameter is not filled in correctly, or the key permissions do not cover the interface call scope for the current scenario.
