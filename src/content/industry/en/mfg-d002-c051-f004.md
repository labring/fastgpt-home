# Process Document and Exception Report Drafting for Metal Cutting Machining: Workflow Orchestration

## What this category's data looks like
Data sources for this category include product drawings and 3D models, CAPP/CAM systems, machine tool collection data, tool management systems, MES, and measurement and inspection tool records. Daily documents cover process routes, operation cards, tool lists, CNC programs, first-piece inspection records, patrol inspection forms, and measuring tool calibration records. Data updates are triggered with each work order, each workpiece, sampling batch, or tool change. Core fields include benchmark parameters, clamping schemes, tool life, dimensional deviation values, and surface roughness indicators, with millimeters, revolutions per minute, and meters per minute as the main units.

## What constraints these characteristics impose on the "workflow orchestration" link
Dispersed data sources and diverse update trigger conditions require workflows to support scheduled pulling from multiple data sources and linkage with event-triggered nodes. Large differences in the structure of multiple types of documents require configuring nodes to adapt to parsing and mapping rules for different fields. The high error risk in core process links requires embedding exception judgment logic in workflows, linking machine tool alarms and process parameter thresholds. Dynamic changes in tools and benchmarks require real-time synchronization of parameters such as tool life and clamping benchmark offset values via global variables to avoid data inconsistency across nodes. At the same time, fields in process documents and exception reports must strictly match business delivery formats, requiring workflows to support custom field mapping and output template configuration.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `variables` | String array containing tool number, process dimension, and exception type | Covers core fields of metal cutting machining process documents and exception reports |
| `nodeId` | Bound to machine tool collection nodes and exception judgment nodes | Enables event-triggered workflow linkage |
| Global variable assignment | Use work order ID as the association key to pass the `variables` parameter | Matches the business rhythm of data updates per work order |
| API access assignment | Use the API link of the release channel to carry parameters | Supports external systems to inject real-time data into workflows |
| Exception trigger threshold | Calibrated based on actual measurements of ±0.02 millimeters and 0.8 micrometers | Adapts to the precision requirements of precision component machining |
| Workflow export | Package documents and reports by work order dimension | Matches the document delivery requirements of business deliveries |

## Three common mistakes
- Phenomenon: Incorrect array parameter format when calling an API to assign values to global variables, resulting in failed field parsing. Cause: Did not follow the array structure requirements of the `variables` parameter, and did not use the correct key-value pair format to transfer process and exception data.
- Phenomenon: Results from the previous work order are superimposed into the variables of the current work order in the exported exception report. Cause: Did not reset the `variables` array before node execution, resulting in global variables not being cleared and retaining residual data from the previous run.
- Phenomenon: The exported workflow cannot correctly associate the data source collected by the machine tool. Cause: Did not bind the corresponding data source node when configuring `nodeId`, resulting in the exported workflow lacking data linkage logic.

## How to confirm the configuration is complete
- Trigger a test work order, check whether the output of the global variable includes expected fields such as tool number and process dimension.
- Call the API link of the release channel to pass test parameters, confirm that the workflow node can correctly receive and use the passed variable values.
- Export the workflow configuration file, check whether all configured nodes and parameter settings are included.
- Simulate scenarios of dimensional deviation and tool wear exceptions, confirm that the workflow can correctly jump to the exception report generation node.

The values provided here are common starting points and should be evaluated against the reader's own samples.
