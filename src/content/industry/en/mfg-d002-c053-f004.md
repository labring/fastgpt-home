# Drafting Process Documents and Exception Reports for Iron and Steel Smelting and Continuous Casting: Workflow Orchestration
This page is written for FastGPT v4.17.0.

## What the data for this category looks like
Business data for this category comes from hot metal and scrap charging data, L2 process control system, laboratory test results, manufacturing execution system (MES), energy medium monitoring system, and equipment status collection terminals. Daily generated business documents include heat plans, batching lists, converter smelting records, composition reports, continuous casting process records, and slab judgment sheets. Fields covered include hot metal temperature, carbon, silicon, manganese content, converter end point temperature, continuous casting pulling speed, slab thickness, and more. Update frequencies cover per heat, real-time, and shift-based cycles.

## What constraints these characteristics impose on workflow orchestration
Multiple heterogeneous data sources and varied update rhythms require workflow nodes to match the trigger timing of their corresponding data sources, to avoid reading data that has not completed updating.
The strongly coupled nature of heats and casting sequences in high-temperature continuous processes requires workflows to support breakpoint resumption and automatic retry of failed nodes, to prevent process interruptions from disrupting continuous casting operations.
Industry-specific document fields and units require workflow `variables` to bind value validation rules for corresponding fields, to ensure drafted process documents and exception reports meet format compliance requirements.
The need for cross-link data collaboration requires workflows to associate output results from different data nodes by `nodeId`, to integrate all information from smelting and continuous casting links.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Global variable `variables` | Bind core fields of documents including heat plans, composition reports, etc., set value ranges based on actual calibration | Cover core data items required for process documents and exception reports, meet multi-link data collaboration needs |
| Node trigger timing | Set according to the update frequency of the data source associated with `nodeId`; set L2 process data nodes to real-time trigger, laboratory data nodes to shift-based trigger | Match update rhythms of different data sources, avoid reading business data that has not completed updating |
| Exception retry configuration | 3 retry attempts, 60-second retry interval | Address temporary equipment fluctuations or network blips, ensure processes do not disrupt continuous casting operations |
| Debug timeout threshold | Set to 300 seconds | Adapt to time required for multi-source data pulling, avoid early termination of processes during debugging |
| Variable value validation | Bind industry standard thresholds, set converter end point temperature to 1600–1700℃ | Ensure drafted process parameters comply with smelting specifications, reduce abnormal situations |

## Three Common Mistakes
- Attempting to modify parameters of built-in components results in failed saves. The cause is that the parameter range of built-in components is not open for custom modification. Use global `variables` binding instead of custom configuration.
- Button trigger nodes obtain unassigned global variables. The cause is that the variable assignment node is not orchestrated before the button trigger node, so variables have not completed updating when read.
- Workflow debugging triggers a `Dangerous behavior` error. The cause is that the workflow contains circular references or empty nodes not bound to data sources, leading the system to identify the operation as high-risk.

## How to Confirm Proper Configuration
- Verify that global `variables` are bound to all core fields required for process documents and exception reports, and that value rules match industry document specifications.
- Confirm that the trigger timing of each data node matches the update frequency of its corresponding data source, ensuring only fully updated business data is read.
- Trigger the exception node retry process, confirm that the workflow can automatically recover and no interruption prompts appear.
- Initiate a button trigger test, confirm that assigned global variables can be obtained, and that output content conforms to industry document formats.
