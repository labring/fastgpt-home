# Process Document and Exception Report Drafting for Sheet Metal Cutting and Bending: Model Access and Configuration

## What Data for This Category Looks Like
Daily data for this category comes primarily from CAD/CAM software, order BOMs, sheet metal inventory systems, laser cutters, bending machines, and MES systems. Daily documents include sheet metal unfolding drawings, CNC cutting programs, bending process cards, nesting diagrams, first-piece records, and process flow cards. Core fields include bending compensation, sheet thickness, hole size, cutting specification, bending sequence, and more. Most units are millimeters, square meters, and kilograms. Data updates trigger when orders are created, daily inventory checks are performed, or production changeovers occur. Bending coefficients and nesting plans must be synchronized each time a changeover takes place.

## What Constraints These Characteristics Impose on Model Access and Configuration
The multi-variety, small-batch nature of sheet metal cutting and bending requires model access and configuration to support flexible context calls and dynamic parameter adaptation. The drawing-driven business model requires enabling visual parsing capabilities in the configuration to read CAD drawings and process card content. The high-frequency data update feature requires the model to quickly associate the latest order BOMs and inventory data. Core time-consuming steps focus on unfolding calculations and nesting management. The configuration must allow the model to call specialized tools to complete these complex tasks. Error consequences include sheet material waste and assembly errors. The configuration must strengthen result verification logic to avoid generating incorrect process parameters.

## How to Configure the System
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting/Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Sheet metal unfolding drawings, process cards and other long documents require full context retention to accurately extract parameters |
| `temperature` | 0.2–0.4 | Process documents and exception reports must maintain rigor, to avoid arbitrary or non-standard generated content |
| `vision` | Enabled | Parse visual documents such as CAD drawings and nesting diagrams to extract graphic dimensions and bending parameters |
| `toolChoice` | auto | Automatically call tools to complete complex business logic such as bending coefficient calculation and nesting planning |
| `AIPROXY_API_ENDPOINT` | Fill in the proxy address for enterprise private deployment | Protect production data from leaks and comply with enterprise data security requirements |
| `AIPROXY_API_TOKEN` | Fill in the enterprise-specific access key | Verify access permissions for model services and prevent unauthorized calls |

## Three Common Configuration Mistakes
- Phenomenon: Testing fails after adding a model, returning connection timeout or 401 error. Cause: `AIPROXY_API_TOKEN` or `AIPROXY_API_ENDPOINT` parameters are not configured correctly, preventing connection to the target model service.
- Phenomenon: Garbled text or messy formatting appears in generated process documents. Cause: The `vision` configuration is not enabled, so table content in DOC documents or vector graphic information of CAD drawings cannot be parsed correctly.
- Phenomenon: No parsing result is returned after uploading an unfolding drawing or bending process card. Cause: `maxContext` is not set to a sufficiently large value, causing uploaded document content to be truncated and core parameters in the drawing cannot be fully read.

## How to Confirm Successful Configuration
- Manually upload a standard sheet metal unfolding drawing, and check if the model correctly extracts core fields such as sheet thickness and bending coefficient.
- Run an exception report drafting test, and confirm the model automatically associates preset order BOMs and sheet metal inventory data to generate report content that conforms to business logic.
- View the model call log, and confirm the `toolChoice` configuration takes effect and automatically triggers tool calls related to unfolding calculations or nesting analysis.
- Test uploading documents in different formats, including nesting diagrams in image format and process cards in DOC format, and confirm the `vision` configuration correctly recognizes all types of document content.

The values provided are common starting points and should be measured against the reader's own samples.
