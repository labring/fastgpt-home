# Drafting Process Documents and Exception Reports for Sheet Metal Cutting and Bending: Deployment and Upgrade

## What data for this category looks like
Data for this category is primarily sourced from CAD/CAM software, order BOMs, sheet metal inventory systems, laser cutters, bending machines, and workshop MES systems. Daily outputs include development drawings, CNC cutting programs, bending process cards, nesting diagrams, first-piece records, process flow cards, and similar documents. Fields include sheet metal specifications, bending coefficients, process sequences, part numbers, and more. Common units are millimeters, kilograms, and square meters. Data updates synchronize with order generation, daily inventory changes, and each production line changeover. The core characteristic of this category is a drawing-driven workflow.

## What constraints these characteristics impose on deployment and upgrade
Since this category is drawing-driven and features multiple product varieties with small batch sizes, deployments must support parsing entry points for multi-format CAD/CAM files. Upgrades must be compatible with data reporting formats from different production line devices. The high-frequency update feature requires configuration items to support real-time data synchronization, preventing process document deviations caused by expired caches. Mixed calls of multiple document types require optimizing knowledge base retrieval logic to ensure that the retrieval priority of different documents such as development drawings and process cards matches business workflows. Temporary data changes caused by production line changeovers must support quick adjustment of the data source range associated with the knowledge base, to avoid errors in exception report generation.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `STORAGE_S3_ENDPOINT` | Fill in using the address of the enterprise's self-built object storage node | Adapt to storage needs for large quantities of CAD drawings and process documents in sheet metal cutting and bending scenarios, ensuring stable reading of large-volume files |
| `REDIS_URL` | Configure as the address of an independent cache cluster, set cache validity period to 3600 seconds | Cache frequently called sheet metal inventory and bending coefficient data, matching daily and per-order update rhythms to reduce repeated query overhead |
| `DB_MAX_LINK` | Set to 20–30 | Adapt to concurrent scenarios where multiple devices (laser cutters, bending machines) report data simultaneously, avoiding database connection exhaustion |
| `FILE_TOKEN_KEY` | Configure as a randomly generated 32-bit string | Encrypt access tokens for process documents, ensuring access security for sensitive production documents such as sheet metal drawings |
| `MONGODB_URI` | Bind to an independent business database instance | Store structured business data such as order BOMs and process flow cards, physically isolating it from general knowledge base data |

## Three common misconfigurations
- Workflow nested knowledge base assistant calls return empty values. The cause is that in FastGPT v4.8.10 and later versions, the API call link between the workflow and the knowledge base is not correctly bound to the data source permission, resulting in insufficient retrieval permissions.
- Docker-deployed reranker component calls succeed but return false. The cause is that the input format of the reranker model does not match long text from sheet metal cutting scenarios (such as text content parsed from development drawings), or the environment variable for the model access address is not correctly configured.
- Cannot find update notes after upgrading to a specified version. The cause is that version update logs were not pulled from the official designated channel, and the upgrade was performed directly via an image tag, resulting in missing version documents.

## How to confirm the configuration is properly set
- Upload a sheet metal development drawing supported by FastGPT v4.17.0 to the knowledge base, perform a retrieval test, and confirm that the returned documents include target fields such as bending coefficients and process sequences.
- Simulate data reporting after a production line changeover, and check whether the knowledge base can update the associated process file data source in real time.
- Call the workflow interface, pass in the BOM data of a test order, and confirm that the returned exception report draft includes correct sheet metal specifications and cutting program numbers.
- View the cache monitoring panel, confirm that the cache hit count for high-frequency business data meets business expectations, and there are no frequent database query logs.

The values provided here are common starting points. They should be evaluated against the reader's own samples.
