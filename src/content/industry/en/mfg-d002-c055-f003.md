# Drafting Process Documents and Exception Reports for Foundry (Sand Casting, Precision Casting, Die Casting): Multi-turn Dialogue and Prompt Engineering

## What Data Looks Like for This Foundry Category
This category’s data includes foundry process cards, batching lists, heat records, mold history logs, first-piece inspection records, material test reports, nonconforming product review forms, and similar documents. Data sources cover ERP material master data, melting furnace thermometers, spectrometers, MES heat records, mold management systems, customer drawings, and technical specifications. Updates occur per heat, per batch, or daily. A single heat record includes fields such as alloy composition, pouring temperature, and mold cycle number. Units include kilograms, degrees Celsius, millimeters, and other standard measurement units.

## Constraints on Multi-turn Dialogue and Prompt Engineering Workflows
Data sources for this category are scattered, updates are frequent, and document fields follow specific formats. This requires multi-turn dialogue to call data step-by-step in line with the data generation rhythm. Heat records updated per heat must be accurately matched by mold cycle and heat number during dialogue. Prompts must clearly specify units for fields such as alloy batching and pouring temperature. Time-consuming steps such as batching ratio verification and defect tracing must be broken down. Associated data such as mold history logs and material test reports must be retrieved step-by-step via multi-turn dialogue, to avoid context overflow caused by inputting too many fields at once. Corresponding data synchronization timing must be set for different document update frequencies, to ensure all data used in dialogue is the latest heat and mold data.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique identifier of the current heat/mold cycle | Used to associate all dialogue context for a single heat, preventing cross-heat data confusion |
| `messages` | Retain the first 10 rounds of dialogue content | Aligns with the dialogue round requirements for single-heat processing in foundry scenarios, avoiding overly long context |
| `variables` | Preset variables for heat number, mold cycle number, and alloy grade | Used to quickly retrieve corresponding mold history and heat record data |
| Maximum context length | 8000–12000 token | Aligns with the field splicing requirements for multiple foundry documents, calibrated via actual testing |
| Single tool call limit | Top 3 recall results | Prevents excessive redundant data from interfering with batching ratio verification |
| Timeout duration | 600 seconds | Accommodates retrieval delays for melting data and spectral test results |

## Three Common Misconfigurations
1.  Phenomenon: Tool call results are not displayed in the dialogue box, and only become visible after reloading the page, with no tool return identifier. Cause: `chatId` is not correctly bound to the current session, leading to failed context association.
2.  Phenomenon: The iframe-embedded dialogue interface displays in English. Cause: No interface language parameter is configured, and the default English language pack is used.
3.  Phenomenon: Frequent request timeout errors occur in the local deployment environment. Cause: No reasonable timeout duration is set, failing to accommodate retrieval delays from equipment such as melting furnaces and spectrometers.

## How to Verify Proper Configuration
- Initiate a dialogue that includes a heat number query, check if the session log shows the bound `chatId` as the unique identifier for the current heat.
- Call a tool to retrieve batching list data, confirm that the returned results include field content corresponding to the preset `variables`.
- Initiate more than two rounds of dialogue, check if the dialogue history retains the preset `messages` round limit.
- Simulate a melting data retrieval request, confirm that no persistent timeout errors occur.

The values provided here are common starting points, and should be evaluated against the user’s own samples.
