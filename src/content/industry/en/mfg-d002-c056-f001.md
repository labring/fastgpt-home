# Process Document and Exception Report Drafting for Lithium-Ion Cell Manufacturing: HTTP Interfaces and External Systems

## What the data for this category looks like
This category’s daily documents include batching records, coating and rolling parameters, winding or lamination records, liquid injection records, formation and grading data, OCV and safety test reports. Data sources cover raw material batch ledgers, MES systems, slurry and coating testing equipment, dew point monitoring devices, formation and grading cabinets, and laboratory test data. Data is synced in real time per batch and per individual cell. Fields include batch numbers, test parameter values, timestamps, and some parameters have specific units such as roll gap, temperature, milliampere-hour, etc. The document structure is layered by production process, with independent data entries corresponding to each process to enable batch-based traceability and analysis.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
This category has scattered data sources with real-time updates, requiring HTTP interfaces to support multi-source data pulling and high-frequency calls. There are many document fields with specific units, so interface request parameters must strictly match the field names and formats of upstream systems to avoid data misalignment. Electrochemical production has extremely high requirements for data accuracy, and exception reports must be synced to the management system in real time, so interfaces must have low latency characteristics. Each batch of cells corresponds to a large amount of detailed data, so interfaces must support batch data transmission while filtering redundant content to improve transmission efficiency. In addition, exception reports must be associated with full-process data for a specific batch, so the interface return structure must adapt to structured storage requirements.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Request timeout | 60-120 seconds | Adapts to the real-time data reporting delay of formation and grading cabinets, prevents premature request termination. This configuration applies to FastGPT v4.17.0 |
| Data encoding | UTF-8 | Matches the universal encoding format of MES systems and laboratory equipment, prevents text garbling |
| Batch request threshold | 50 entries per request | Adapts to the number of documents per cell batch, balances interface load and transmission efficiency |
| Field mapping rules | Match by cell batch number and test parameter name | Corresponds to the fixed field structure of process documents, ensures data is correctly written to process document templates |
| Retry trigger condition | Status code ≥500 or timeout | Adapts to temporary network fluctuations of industrial equipment, ensures the success rate of exception report synchronization |
| `Authorization` parameter configuration | Bearer {custom service key} | Used to verify the identity of external systems and FastGPT, prevents unauthorized access |

## Three common mistakes
- Phenomenon: Permission error returned when initiating application management requests via API. Cause: The `Authorization` parameter is not configured correctly, or the bound key does not have application management operation permissions enabled.
- Phenomenon: Garbled characters appear when uploading process document text, regardless of whether uploading via web page, local file, or API parameters. Cause: The data encoding is not uniformly configured as UTF-8, which does not match the encoding format of upstream equipment.
- Phenomenon: Exception reports are not generated as expected after a workflow loops calls to HTTP interfaces. Cause: The `variables` parameter is not correctly set to bind the cell batch number, causing the interface to fail to obtain process data for the corresponding batch.

## How to confirm the configuration is complete
- Initiate a single HTTP interface request, check if the returned `responseData` contains the expected process document fields with no redundant content.
- Upload a piece of process text containing special characters, confirm that the returned data set content has no garbled characters.
- Trigger a workflow to loop calls to HTTP interfaces, observe that all interface status codes are within the normal range, with no continuous timeouts or errors.
- Initiate an application management request using the configured key, confirm that the corresponding operation can be performed normally.
