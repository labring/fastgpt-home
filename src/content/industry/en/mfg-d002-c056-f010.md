# Process Document and Exception Report Drafting for Lithium-Ion Cell Manufacturing: Knowledge Base Retrieval and Recall

## What this category of data looks like
Daily documents for lithium-ion cell manufacturing include batching records, coating and rolling parameters, winding or lamination records, liquid injection records, formation and grading data, and OCV and safety test reports. Data sources cover raw material batches, MES systems, slurry and coating testing equipment, dew point monitoring devices, formation and grading cabinets, and laboratory data. Updates refresh in real time alongside production batches and single-cell test results. Most documents are structured tables and time-series parameter records, with fields including equipment number, batch number, test values, and operating conditions.

## What constraints do these characteristics impose on knowledge base retrieval and recall
This category has real-time high-frequency updates and strong batch-associated structured data traits. These traits impose constraints on retrieval and recall workflows:
Retrieval and recall must bind production batches and operating parameters as retrieval conditions. This prevents interference from irrelevant cross-batch data.
Structured parameter documents cannot rely on general full-text retrieval matching. Precise recall for field-level keywords is required.
High-frequency updated datasets need incremental synchronization mechanisms. This stops retrieval from calling old data.
Exception report drafting must associate the latest test results. Recall scope must be limited to recent data from the corresponding production link. This avoids redundant information occupying context.

## How to set configurations
These configurations are based on FastGPT v4.17.0.

Choose a retrieval mode through representative-query testing; configure category, batch, or entity filters separately because the mode itself does not enforce those boundaries.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the high-precision parameter requirements of cell manufacturing, filters low-correlation non-batch data |
| `limit` | Top 100–200 entries | Covers typical parameter entries for a single production batch, avoids context overload |
| `usingReRank` | Enabled | Performs secondary sorting on recall results by batch and operating conditions, optimizes relevance |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically supplements extended retrieval terms such as batch numbers and equipment numbers, strengthens precise matching |
| `collectionIds` | Bind dedicated datasets for corresponding production links | Limits retrieval scope to exclusive datasets for batching, coating, formation and grading, and other production stages |

## Three common misconfigurations
- Retrieved content has a large discrepancy from the target document. The cause is failure to enable the extended retrieval term function, and failure to automatically supplement exclusive retrieval conditions such as batch numbers and equipment numbers. This results in generalized matching of irrelevant data.
- Retrieval time exceeds 10 seconds. The cause is failure to limit the retrieval scope via `collectionIds`, performing full retrieval across multiple production link datasets, and failure to enable the re-ranking mechanism to filter low-correlation entries in advance.
- Low-correlation reference content is still output after setting the minimum similarity threshold to 1. The cause is failure to correctly bind the dedicated dataset for the corresponding production link, or failure to enable the re-ranking function to perform secondary filtering on recall results. This results in some low-matching entries being included in the context.

## How to confirm configurations are correctly set
- View the retrieval configuration panel. Confirm that the `similarity` threshold is set in the 0.75–0.85 range, and that the `usingReRank` function is enabled.
- Check whether `collectionIds` is bound to the dedicated dataset for the corresponding production link. This avoids cross-link retrieval.
- Initiate a test retrieval. Enter a query term that includes a batch number and equipment number. Verify whether the recall results only include process documents from the corresponding batch.
- View the retrieval time logs. Confirm that single retrieval time is within a reasonable range, with no obvious timeouts.

The values provided are common starting points and should be measured against the reader's own samples.
