# Forging and Die Forging Process Document and Abnormal Report Drafting: Multi-turn Dialogue and Prompt Engineering
This document is written based on FastGPT v4.17.0.

## What This Category of Data Looks Like
Data sources for this category include raw material quality certificates, heating furnace systems, press collection data, MES systems, non-destructive testing equipment, and customer forging drawings. Data updates occur per individual forging, each production batch, or each furnace heat. Daily documents cover forging process specifications, cutting cards, heating furnace records, forging process cards, mold life records, heat treatment entrustment slips, and ultrasonic testing reports. These documents include fields such as forging ratio, fiber direction, furnace batch number, forging dimensions, and testing results. Units include millimeters, degrees Celsius, tons, and others.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
This category’s data updates frequently and is generated per batch or furnace heat. Multi-turn dialogue contexts must be accurately bound to the original data of the corresponding production batch to avoid mixing cross-batch data.
Multi-source heterogeneous data sources require prompts to clearly define exclusive field rules for each document. This ensures correct matching of key items such as forging ratio and furnace batch number when data is called.
Large individual document sizes and specialized field content require limiting context extraction during dialogue. This prevents redundant information from interfering with generation results.
Abnormal report drafting requires rapid association of real-time parameters from heating and press systems. Prompts must use fixed retrieval dimensions to shorten response times.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the length of single-paragraph specialized content in forging process specifications, avoiding information fragmentation within chunks |
| Chunk Overlap Length | 100–200 characters | Retains key fields such as furnace batch number and forging ratio across adjacent chunks, preventing missed retrieval between chunks |
| Single Search Limit | Top 5 results | Matches the number of documents associated with a single furnace heat production run, avoiding introduction of irrelevant batch data |
| Query Optimization | Enabled | Optimizes user-submitted process query expressions for forging scenarios with many specialized terms, to match standard documents in the knowledge base |
| Maximum Context | 6000 token | Limits the total volume of documents loaded per dialogue turn, adapting to the specialized content density of forging-related documents |
| `chatId` | Bind to current production batch ID | Ensures multi-turn dialogue always links to the original data of the corresponding batch, avoiding context confusion |

## Three Common Misconfigurations
- Dialogue return results include document content from unrelated furnace heats: The cause is failure to bind `chatId` to the current production batch ID. Retrieval does not limit the batch scope, resulting in inclusion of data from other furnace heats.
- Excessively long parsing time for large Word documents: The cause is an excessively large chunk length, which exceeds the reasonable range for single-chunk parsing. This creates concentrated processing pressure on individual chunks.
- Incorrect forging ratio values in generated abnormal reports: The cause is failure to explicitly specify in the prompt to extract data from the raw material quality certificate of the corresponding furnace heat. Parameters from other batches are used instead.

## How to Verify Proper Configuration
- Initiate a dialogue based on the heating record of a specific furnace heat. Confirm the context only includes associated documents for that furnace heat, with no data from other batches.
- Upload a single forging process specification of approximately 10MB. Check that parsing time meets expectations, with no obvious lag.
- Submit a query containing specialized forging terms. Confirm the system correctly identifies fields such as forging ratio and fiber direction, and matches the corresponding documents.
- View the `messages` parameter of the dialogue. Confirm the context of each session is bound to the exclusive identifier of the current production batch.

The values provided are common starting points and should be evaluated against the user’s own sample data.
