# Drafting Process Documents and Exception Reports for Forging and Die Forging: Workflow Orchestration

## What the Data for This Category Looks Like
Daily documents for forging and die forging include forging process specifications, cutting lists, heating furnace logs, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports. Data sources cover raw material quality certificates, heating furnace systems, press collection data, MES systems, non-destructive testing equipment, and customer forging drawings. Data update frequency is per piece, per batch, or per furnace run. Core fields include heat batch number, forging ratio, fiber direction, forging dimensions, and defect type. Units include millimeters, degrees Celsius, tons, and others.

## Constraints Imposed by These Characteristics on Workflow Orchestration
Data comes from multiple industrial systems. Workflows must support cross-system data pulling and field mapping to avoid errors from manual entry. Data updates frequently per piece, batch, or furnace run. Workflows must support one-time trigger document generation to ensure each generated file matches the latest production data. Daily document structures vary. Corresponding field combinations must be called for different document types. For example, process specifications must bind forging ratio and heating range. Exception reports must link to non-destructive testing defect data. Error consequences directly relate to forging scrap and service safety. Workflows must add exception verification steps to ensure key fields are complete.

## Configuration Settings
| Configuration Item | Recommended Approach | Basis for This Approach |
| ---- | ---- | ---- |
| Global variable binding rules | Associate `variables` by heat batch number and forging batch | Data updates by heat batch and batch, so precise matching of data sources for corresponding production links is required |
| Node trigger condition | Receive completion signal from upstream node with `nodeId` 3 | Wait for upstream data collection nodes to finish before starting document generation workflows |
| Timeout threshold | 600 seconds | Reserve sufficient processing time for cross-system data collection and document generation |
| Exception trigger rule | Trigger when defect fields in `variables` are not empty | Automatically jump to the exception report generation link |
| Template field mapping | Bind cutting weight from cutting lists and heating temperature range from heating furnaces | Match the required field requirements of forging process specifications |

## Three Common Errors
- Phenomenon: When calling the published workflow interface, global variables do not take effect, and returned fields are empty. Cause: The permission to externally pass global variables was not enabled in the workflow configuration, and `variables` was not bound to the parameter entry of the corresponding node.
- Phenomenon: The text splicing result does not match the preset document format, and custom variables are not correctly replaced. Cause: `variables` were not configured according to the field naming rules of forging documents, and variable names do not match placeholders in document templates.
- Phenomenon: Multi-layer exception branch logic is interrupted, and the exception handling process cannot proceed according to the problem tree. Cause: `nodeId` was not bound according to the branch node sequence, and the upstream node did not correctly pass the trigger signal to downstream branch nodes.

## How to Verify a Successful Configuration
- Trigger a single furnace forging process, check whether the workflow automatically pulls fields from the corresponding heating furnace log and raw material quality certificate into the process document template.
- Simulate an exception scenario, such as detecting folding defects, confirm whether the system automatically jumps to the exception report generation node and generates an ultrasonic testing report containing the corresponding defect information.
- Call the external published interface, pass preset `variables` parameters such as forging batch number and defect type, check whether the returned document correctly replaces placeholders.
- View the workflow logs in FastGPT v4.17.0, confirm that the `nodeId` trigger sequence matches the preset process steps, and there are no timeouts or unexecuted nodes.
