# Forging and Die Forging Process Document and Abnormal Report Drafting: Source Citation and Traceability

## What Data for This Category Looks Like
Core data for forging and die forging comes from raw material quality certificates, furnace heating systems, press collection data, MES systems, non-destructive testing equipment, and customer forging drawings.
Daily documents include forging process specifications, cutting lists, furnace heating records, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports.
Data is updated per individual forging, batch of materials, or furnace heat. Fields include heat batch number, forging ratio, heating temperature, press tonnage, detected defect type, and other specialized metrics. Units include degrees Celsius, tons, counts, and other industry-specific parameters.

## Constraints on Source Citation and Traceability
Data for forging and die forging is tied to heat batch numbers and production batches. Source citation and traceability require precise matching of associated data for a single furnace heat or single batch, to avoid cross-batch confusion.
There are many types of daily documents, and specialized fields are complex. It is necessary to accurately identify exclusive identifiers for different document types such as process specifications and testing reports.
Unlike casting’s solidification defect control, forging requires strict control of metal flow lines and forging ratio. Therefore, traceability must link full-lifecycle data from raw materials through all processing steps.
Compiling deformation steps, defining heating intervals, and verifying furnace batch numbers are the most time-consuming daily tasks. The traceability logic must support fast retrieval of associated data sources.
If traceability errors occur, it may lead to forging scrap, insufficient fatigue life, or service fracture of critical load-bearing components. Therefore, complete citation links and metadata must be retained.

## Three Common Configuration Errors
- Symptom: No selectable values appear for variables after selecting a knowledge base. Cause: Fields such as heat batch numbers and batch numbers from data sources have not been configured as referenceable variables, or the field mapping rules for the corresponding knowledge base have not been bound.
- Symptom: Console error `Cannot redefine property: toString`. Cause: Custom citation logic conflicts with the platform’s built-in `toString` method, and function execution context is not properly isolated.
- Symptom: Citation results include data sources from unrelated batches. Cause: Heat batch numbers are not used as the core retrieval keyword, and only general text matching is used, leading to mixed results.

## How to Verify Correct Configuration
- Users input the heat batch number of a specified forging, and verify that the retrieved data sources only include heating furnace records, press data, and testing reports for that furnace heat.
- Users review the process document or abnormal report generated in the conversation, and confirm that each citation is labeled with the source document type, number, and corresponding batch information.
- Users run a test case to trigger the abnormal report drafting process, and check that no `Cannot redefine property` type errors occur.
- Users adjust the citation parameters, and verify that the `quoteMaxToken` value affects the completeness of cited content.

The values provided here are common starting points, and should be measured against the reader’s own samples.
