# Drafting Process Documents and Exception Reports for Forging and Die Forging: Document Parsing and Chunking

## What data for this category looks like
Daily documents for forging and die forging scenarios include forging process specifications, cutting lists, furnace heating records, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports. Data sources are raw material quality certificates, furnace heating systems, press collection data, MES systems, non-destructive testing equipment, and customer forging drawings. Document update frequency is per part, per batch, or per furnace run. Core fields include heat lot number, forging ratio, heating temperature, pressure parameters, defect type, and others. Some documents have clear unit identifiers such as degrees Celsius, megapascals, millimeters, and others. Document structures vary significantly across different types.

## Constraints on document parsing and chunking
This category has diverse document types with significant structural differences. Some are long-text forging process specifications, while others are cutting lists and ultrasonic testing reports with dense tables. Chunking rules must adapt to different document structures to avoid splitting that breaks relational links of core fields such as heat lot number and forging ratio. Data updates are performed per production batch or furnace run, with concentrated document volume per single batch. Bulk parsing support is required, and batch identifiers must be preserved. Data sources cover export formats from multiple systems, so compatibility with common file types such as Excel and PDF is needed. Parsing duration must align with production cycles to avoid timeouts that disrupt on-site workflows.

## Configuration Settings
This deployment uses FastGPT v4.17.0 configuration. Specific parameters are listed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the paragraph length of forging process specifications, preserves key information such as heating ranges and deformation steps |
| `chunkSplitter` | Split by paragraph + table | Adapts to the table structure of cutting lists and ultrasonic testing reports, avoids splitting that breaks cell relational links |
| `customPdfParse` | Enabled | Adapts to structured PDFs from non-destructive testing reports, accurately extracts fields such as defect location and testing results, loads the corresponding parsing model to complete format conversion |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to the parsing duration of large furnace heating records and multi-batch process documents, avoids timeout failures |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports bundled uploads of multiple documents per furnace run, matches the document submission requirements of mass production |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for different document types, adapts to the diversity of documents in forging scenarios |

## Three Common Configuration Mistakes
- Parsing results show empty fields after uploading an Excel-format cutting list. Cause: Table document chunking rules are not enabled, and the default chunking method fails to recognize relational links of Excel cells.
- Uploading a single-furnace-run furnace heating record PDF results in a request failure prompt, as parsing time exceeds the preset threshold. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted, and the default parsing duration is insufficient for large documents.
- Core identification fields such as forging ratio and heat lot number are lost after chunking. Cause: The `chunkSize` value is too small, splitting complete paragraphs containing core fields into different chunks, leading to broken contextual links.

## How to Verify Proper Configuration
- Upload a typical cutting list Excel file, check that parsed chunks retain complete fields such as material grade and cutting dimensions.
- Upload a single-furnace-run furnace heating record PDF, confirm that parsing time does not exceed the preset `PARSE_FILE_TIMEOUT_SECONDS` threshold.
- Upload a structured PDF containing ultrasonic testing data, check that `customPdfParse` is enabled and defect location and testing results are correctly extracted.
- View the system upload file limit, confirm that single file size does not exceed the `UPLOAD_FILE_MAX_SIZE` configuration.

The values provided are common starting points and should be assessed against the specific samples of the intended deployment.
