# Precast Concrete Component Process Document and Abnormal Report Drafting: Multi-turn Dialogue and Prompt Words

## What the data for this category looks like
Data for precast concrete components comes from BIM or detailed design documents, rebar and concrete batch ledgers, mold table and curing kiln operation logs, laboratory test records, and QR code traceability systems. Daily documents include component detailed drawings, rebar cutting lists, mold inspection forms, pouring and vibration records, curing records, and demolding and factory inspection reports. Data is updated per individual component, each batch of materials, and each curing batch in a kiln. Fields include component number, rebar specification, curing temperature, demolding strength, and others. Units include millimeters, megapascals, degrees Celsius, days, and others.

## What constraints these characteristics impose on the "multi-turn dialogue and prompt words" link
Data sources for precast concrete components are scattered and updated frequently. Multi-turn dialogue must gradually align fields across multiple systems such as BIM detailed drawings, material ledgers, and production logs to avoid information deviation across data sources. Field differences across different documents are significant. Prompt words must clearly distinguish format requirements for different documents such as rebar cutting lists and curing records. Production data for individual components must be linked in real time. Dialogue must support dynamic retrieval of the latest batch information such as concrete strength and mold table number to ensure timeliness of process documents and abnormal reports. Errors may lead to component scrap or project delay. Multi-turn dialogue must include a verification step to confirm that key information such as embedded position and strength parameters is correct.

## Three Common Mistakes
- Phenomenon: The model's output language does not match the preset English prompt requirements, and only returns Chinese content. Cause: The language parameter is not explicitly bound in the prompt words, or the `variables` configuration does not associate a language variable, causing the model to fail to follow the English output requirements.
- Phenomenon: An error occurs in the parsing process after uploading documents such as component detailed drawings and rebar cutting lists. Cause: No document splitting rule adapted to large-scale engineering drawings is configured, or the knowledge base recall limit is set too low to load complete drawing text content.
- Phenomenon: The application's internal variable calls and knowledge base recall records are not displayed on the dialogue details page. Cause: The detailed recording switch for session logs is not enabled, or the `chatId` binding is not synchronized to the log storage module, causing key dialogue information to not be captured.

## How to Confirm Proper Configuration
- Initiate a dialogue with a clear English output requirement, verify whether the language of the model's returned content meets the preset requirements.
- Upload a single component detailed drawing document, check whether the parsed text fully covers the key parameters of the drawing.
- Initiate a dialogue that includes a component number, verify whether `variables` successfully call the production ledger data of the corresponding batch.
- View the session details page, confirm that the session log bound to `chatId` includes complete dialogue and parameter call records.
