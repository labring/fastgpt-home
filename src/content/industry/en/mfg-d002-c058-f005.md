# Drafting Process Documents and Exception Reports for Precast Concrete Components: Tool Calling and Plugins

## What the data for this category looks like
Precast concrete component production data originates from BIM or detailed design documents, steel bar and concrete batch ledgers, mold table and curing kiln operation records, laboratory test reports, and component QR code traceability systems. Daily generated documents include component detailed drawings, steel bar cutting lists, mold inspection forms, pouring and vibration records, curing records, and demolding and factory inspection reports. Data is updated in real time per individual piece, each batch, and each kiln. Core fields include component ID, steel bar specification and model, concrete strength grade, curing temperature, demolding strength value, and other related fields. Units include MPa, cubic meters, hours, and other standard units.

## What constraints these characteristics impose on the tool calling and plugins workflow
Precast concrete component data is updated in real time per individual piece, each batch, and each kiln. This requires tool calls to pull the latest batch and inspection data in real time, to prevent process documents from using expired information. Multiple types of production documents require plugins to adapt to parsing and field extraction for different formats, to ensure accurate core parameters such as steel sleeve positions and curing strength. The one-to-one correspondence between components and on-site lifting positions requires tool calls to associate component unique IDs with on-site installation information, to prevent installation misalignment. The consequences of errors are severe, so field verification logic must be added to the tool calling link, to avoid component scrap or construction delays caused by parameter errors.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |

| Workflow/API tool selection | `auto` | Adapts to FastGPT v4.17.0 automatic tool selection logic, automatically matches the dedicated tool set for precast concrete component scenarios |
| Workflow/API function-call configuration | `Limit calls to document parsing and data verification tools` | Process documents and exception reports require verification of core fields such as steel bar specifications, sleeve embedded positions, and curing strength |
| Tool call timeout | `600 seconds` | Processing detailed drawing parsing for large bridge components requires a long calculation cycle, to avoid process interruption due to timeout |
| Tool trigger timing | `Pull latest batch data before generating component list` | Precast component data is updated in real time per piece and batch, so process documents must use the latest steel bar and concrete batch information |
| Knowledge base association rule | `Trigger only when tool calls return exceptions` | Avoid redundant retrieval, focus on exception scenarios that tools cannot automatically handle |
| Number of tool returns per single call | `Top 5 entries` | Focus on core pouring, curing, and demolding inspection records, avoid information overload that affects drafting efficiency |

## Three common configuration mistakes
- Symptom: After enabling the tool call node, knowledge base retrieval returns no results. Cause: The trigger priority between tool calls and knowledge base retrieval is not configured, and tool call logic overrides knowledge base retrieval by default.
- Symptom: Two separate thinking processes appear when debugging the tool call node. Cause: Both automatic thinking and tool call trigger rules are configured in the workflow, leading to repeated triggering of the thinking link.
- Symptom: Attempts to call local office software to generate documents fail, returning a connection timeout error. Cause: Remote call permissions are not configured via FastGPT's MCP plugin, only local path triggers are set, so execution cannot be performed on the server.

## How to confirm the configuration is complete
- Trigger a complete process document generation workflow, check the workflow log, and confirm that the automatically matched tool set includes document parsing and data verification items.
- Simulate a steel bar batch data update, check whether the tool call automatically pulls the latest data and updates the corresponding fields in the process document.
- Manually construct an abnormal data scenario, confirm that after the tool call fails, knowledge base retrieval automatically starts and returns relevant exception handling documents.
- View the workflow debugging interface, confirm that only one tool call thinking process appears, with no repeated triggering links.
