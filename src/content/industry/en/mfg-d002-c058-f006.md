# Drafting Process Documents and Exception Reports for Precast Concrete Components: Source Citation and Traceability

## What Data for This Category Looks Like
Precast concrete component daily data sources include BIM detailed design documents, rebar and concrete batch ledgers, mold table and curing kiln operation records, laboratory test reports, and outgoing QR code traceability data.
Data update frequency aligns with individual components, each batch of materials, and each curing kiln cycle.
Typical documents include component detailed drawings, rebar cutting lists, mold inspection records, pouring and vibration records, curing records, demolding and factory inspection reports.
Fields include component number, rebar diameter, concrete strength grade, curing duration, mold table number, and others. Common units are millimeters, cubic meters, hours, and megapascals.

## Constraints Imposed by These Characteristics on Source Citation and Traceability
The individual uniqueness and batch correlation of precast concrete components require traceability information to be precise down to individual components or single batches, to avoid cross-batch confusion.
Heterogeneous document types, ranging from drawings to ledgers, require traceability systems to link the same component numbers and material batches across different documents.
The high-frequency update feature requires traceability data to match the latest curing and inspection records in real time. This ensures that the latest valid data is used when drafting exception reports.
Additionally, the business characteristic of severe error consequences requires traceability information to fully cover the entire process from design to factory delivery. This ensures that all key links can be traced.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `quoteMaxToken` | 1200–1800 token | Precast concrete component process documents and traceability data have lengthy content, requiring coverage of complete batch and inspection information |
| `responseData` | Include file path and component number | Need to clearly mark the storage location of traceability documents and the unique identifier of the corresponding component |
| `detail` | Enabled | Need to display complete fields of traceability documents, such as rebar batch number, curing kiln number, demolding strength value |
| Chunk Length | 4000–5000 characters | Precast concrete component documents contain a large number of drawing parameters and batch information, requiring complete single-chunk content |
| Single Recalled Entries | Top 6–8 entries | Traceability data for precast concrete components is scattered across multiple records, requiring coverage of the entire design, production, and inspection process |
| Timeout Wait Duration | 30–60 seconds | Precast concrete component documents contain a large amount of drawing data, requiring sufficient retrieval time |

## Three Common Configuration Mistakes
- Phenomenon: Knowledge base chunks are retrieved, but returned results do not include file source addresses. Cause: The `responseData` configuration item is not enabled, and the associated field for returning traceability information is not specified.
- Phenomenon: Cited content is truncated, with critical information such as curing duration or strength level missing. Cause: The `quoteMaxToken` value is not adjusted based on the length of precast concrete component documents, and a smaller general-scenario threshold is used.
- Phenomenon: After searching multiple knowledge bases, traceability data from different sources cannot be linked to the same component. Cause: A unified component number is not specified as the associated field in the configuration, leading to mismatched retrieval results across different knowledge bases.

## How to Verify Proper Configuration
- Initiate a query that includes a specific component number, and check whether the returned results contain the path and field information of the corresponding document.
- Adjust `quoteMaxToken` to a test threshold, and verify that the length of the returned cited content matches the expected setting.
- Simulate an exception report drafting scenario, and confirm that the retrieval results include multiple types of traceability documents such as pouring records and curing records.
