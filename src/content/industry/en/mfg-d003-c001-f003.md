# PCB Manufacturing Process Specifications and Technical Standards Q&A: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
The data linked to PCB manufacturing process and standard Q&A includes Gerber files, drill files, and BOM lists provided by clients, plus in-house factory CAM system data, equipment operating parameters, bath solution test results, AOI and electrical test reports, and slice analysis records. Daily documents cover production work instructions, drilling and lamination process parameters, chemical solution mixing records, and quality inspection reports. Data is collected in real time or continuously alongside production batches and team shifts. Different business roles use business data fields of varying dimensions. There is no unified, fixed general document structure. Corresponding data items must be matched based on specific business links.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
PCB manufacturing data sources are scattered and cover multiple business links. Multi-turn dialogue must associate business data from different roles based on context. Prompts must clearly specify the production module associated with the queried data. Data updates alongside production batches and shifts. Prompts must include batch-specific parameter verification logic to prevent referencing expired records. There is no unified document structure. Multi-turn dialogue must guide users to clarify the process and batch linked to the data step by step, to avoid mixing up parameters from different links. Continuously collected real-time data requires the dialogue system to support dynamic loading of the latest records. Prompts must limit the query time range to avoid returning redundant information.

## Configuration Guidelines
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | 8000–12000 token | Adapts to the context length of multi-process associated data for PCB manufacturing, avoids exceeding model processing limits |
| Single Recall Count | Top 6 entries | Matches the typical number of entries for single-process data, reduces redundant information interference |
| `variables` | Predefined by production batch and process type | Used to bind batch and process parameters in dialogue, ensures queries point to accurate business data |
| Dialogue History Truncation Threshold | Last 20 turns of dialogue | Focuses on the context of the current production link, avoids confusing current queries with historical data |
| `messages` | Spliced in the order of business links | Ensures multi-turn dialogue context is organized according to PCB manufacturing process logic, improves information matching accuracy |
| `chatId` | Bound to production batch number | Isolates dialogue contexts from different production batches, avoids confusing data across batches |

## Three Common Misconfigurations
- Format symbols that cannot be closed via standard operations appear at the end of dialogue response results. The cause is that result closing rules are not configured in the prompt. The default output logic of FastGPT v4.17.0 will append system verification identifiers.
- Process parameters or inspection report content queried during multi-turn dialogue are incomplete. The cause is that the prompt does not limit the production batch and process range of the query, causing the model to call redundant data across batches and exceeding the context processing limit.
- Dialogue requests have no response for a long time and return a timeout status code. The cause is that `chatId` is not bound according to production batches, causing a single dialogue to load too much historical PCB manufacturing data and exceeding system processing time limits.

## How to Confirm Proper Configuration
- Initiate a multi-turn dialogue containing production batch and process keywords, check whether the returned results only relate to process parameters and inspection data of the corresponding batch.
- Review the dialogue context truncation logic, confirm that only the specified number of recent dialogue entries are retained, with no redundant historical information interfering with the current query.
- Verify that the `variables` parameter can correctly bind batch and process variables in the dialogue, ensuring each query points to accurate business data.
- Check the prompt configuration, confirm that no undefined format rules are included, and no additional system verification symbols appear at the end of results.
