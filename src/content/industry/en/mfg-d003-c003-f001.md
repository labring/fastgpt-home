# Process Specification and Technical Standard Q&A for Dairy Processing: HTTP Interfaces and External Systems

## What this category’s data looks like
Data is sourced from milk source detection systems, MES production execution systems, homogenization and heat treatment equipment, online temperature and flow monitoring modules, CIP cleaning systems, and LIMS laboratory information management systems. Daily documentation includes raw milk acceptance records, standardized batching sheets, pasteurization or UHT heat treatment records, CIP cleaning records, filling operation records, and sample retention and microbial test reports.
Data updates occur in real time per milk tank and production batch. Included fields are raw milk antibiotic and physicochemical index values, heat treatment time and temperature parameters, CIP cleaning cycle and chemical agent concentrations, filling environment cleanliness data, and additional relevant metrics. Supported units include degrees Celsius, seconds, milligrams per liter, and other standard production units.

## What constraints these characteristics impose on HTTP interfaces and external systems
Real-time data updates per milk tank and production batch require HTTP interfaces to support precise retrieval of single-batch data via batch numbers and milk tank IDs. This prevents excessive bandwidth usage from full synchronization.
Fields include specialized production parameters, so interfaces must support specifying a return field list to reduce invalid data transmission.
Production safety-related data requires interfaces to implement authentication mechanisms to verify request legitimacy.
High update frequencies require interface timeout settings to align with production cycles. This avoids data synchronization interruptions caused by timeouts.

## How to configure the integration
For FastGPT v4.17.0, interface integration with external production systems can be completed using the following configuration items:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {internal production system API key}` | Complies with production system security authentication specifications to prevent unauthorized access to sensitive production data |
| `variables` | `{"targetBatch": "", "milkTankSerial": ""}` | Matches the need for precise data retrieval per production batch and milk tank in dairy processing, to locate single-batch production documentation |
| `responseData` | `Only return raw milk physicochemical indicators, heat treatment time and temperature, and CIP cleaning parameters` | Filters redundant fields, reduces invalid data transmission, and improves interface call efficiency |
| Timeout duration | `30–60 seconds` | Aligns with the synchronization rhythm of real-time production data, avoiding timeout interruptions caused by fast production cycles |
| Number of records returned per request | `First 1 record` | Adapts to single-batch or single-milk-tank data retrieval scenarios, preventing confusion across multiple batches of data |

## Three common configuration errors
- Symptom: Interface calls return a 401 unauthorized error, or fail to retrieve process data for the corresponding production batch. Cause: The `Authorization` header is not configured correctly, or an expired production system API key is used.
- Symptom: Interface calls time out, or return empty results. Cause: The timeout duration is set too short and does not match the synchronization rhythm of real-time dairy production, or the correct production batch number is not specified via the `variables` parameter.
- Symptom: Returned response data includes a large number of irrelevant production parameters. Cause: The required return fields are not specified via the `responseData` configuration, resulting in retrieval of redundant non-process standard data.

## How to confirm correct configuration
- Interface calls with a correctly formatted `Authorization` header return a 200 status code, with no authentication-related errors.
- A preset production batch number passed to the `variables` parameter results in returned data matching the field values of the corresponding batch’s process documentation.
- Waiting 30 seconds before calling the same interface again returns the latest real-time production data, with no delays or missing entries.
- The `responseData` field of the interface response only includes preset process specification-related parameters, with no redundant content.
