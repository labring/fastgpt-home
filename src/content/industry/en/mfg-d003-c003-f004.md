# Process Specification and Technical Standard Q&A for Dairy Processing: Workflow Orchestration

## What Data Looks Like for This Category
This category covers manufacturers of liquid milk, yogurt, milk powder and dairy ingredients. Daily stored business documents include raw milk acceptance records, standardized ingredient lists, pasteurization or UHT heat treatment records, CIP cleaning records, filling records, sample retention reports and microbial inspection reports. Data sources cover raw milk testing equipment, MES systems, homogenization and heat treatment equipment, online temperature and flow collection systems, CIP systems and LIMS laboratory management systems. Updates occur in real time per milk tank and per production batch. Documents are archived by production batch, and include fields for physical and chemical indicators, process parameters and test results for the corresponding batch.

## What Constraints These Characteristics Impose on Workflow Orchestration
Since this category’s data updates in real time per milk tank and batch and is independently associated, workflows must accurately bind batch-level variables to avoid cross-batch data confusion. Multi-source heterogeneous data sources require workflow nodes to call data by type to avoid interface conflicts. Severe error consequences require workflows to have strict context isolation and exception retry mechanisms. Bulk running nodes must adapt to resource limits for multi-batch parallel processing to prevent single-batch exceptions from affecting all tasks.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Context Scope | Exclusive context for the current node | Dairy processing batch data is independent, avoiding interference from cross-batch process documents and test data |
| Batch Concurrent Execution Count | 3-5 | Single batch business data volume is moderate, avoiding server resource overload |
| Node Error Retry Count | 2 | Equipment collected data has occasional fluctuations, retries can restore normal data pulling |
| `variables` Binding Fields | Batch number, milk tank number | Accurately match exclusive process documents and test records for the corresponding batch |
| Node Timeout Threshold | 600 seconds | Matches the actual business duration of the CIP cleaning process, avoiding early task interruption |
| Model Call Context Length | 8000 token | Covers the total character range of single-batch process documents and test data, calibrated via actual testing |

## Three Common Mistakes
- Phenomenon: Workflow model icons do not display, and file upload prompts network errors. Cause: FastGPT has not been updated to v4.17.0, and local cache has not synced the latest component resources.
- Phenomenon: Large model node returns 500 Gateway forwarding error because service is disconnected. Cause: Data sources such as bound LIMS and CIP systems have not completed connectivity configuration, or network policies restrict cross-system access.
- Phenomenon: Workflow nodes only call global context data, and do not use current batch exclusive data. Cause: Batch number, milk tank number and other exclusive parameters are not bound via `variables` configuration, and global knowledge base is incorrectly associated.

## How to Confirm Proper Configuration
- Manually trigger a single-batch workflow, check that the documents returned by the node only include the current milk tank's raw milk acceptance and heat treatment records, with no data from other batches.
- Configure a bulk running task, check that the number of concurrently executing nodes matches the preset 3-5 threshold, with no node accumulation or errors.
- Simulate a data source disconnection scenario, check that nodes automatically trigger 2 retries before normally recovering or triggering preset alerts.
- View the workflow node's configuration panel, confirm that `variables` has bound exclusive fields such as batch number and milk tank number.

The values listed above are common starting points, and should be evaluated against the reader's own samples.
