# Q&A for Workflow Procedures and Technical Standards for Warehousing, Lot Tracking, and In-Plant Logistics: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
This category of data primarily comes from ERP/WMS systems, barcode or RFID collection devices, procurement and work order documents, warehouse location archives, AGV transport systems, and weighing equipment. Daily documents include receiving slips, putaway slips, material picking and return slips, warehouse transfer slips, inventory count sheets, lot ledgers, first-in first-out (FIFO) and expiration date records. Data update frequencies cover real-time (such as scanned warehouse receipts), daily (such as daily inventory summaries), and monthly (such as full warehouse inventory counts). Core fields include lot number, warehouse location code, expiration date, material code, and corresponding quantity and unit.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering segment
Data for this category has large variations in real-time performance. Some scenarios require retrieving the latest scanned warehouse receipt data. Multi-turn dialogue must support fast context refreshing. Core business operations revolve around lot and warehouse location management. Prompts must explicitly limit extraction to exclusive fields such as lot numbers and warehouse location codes, to avoid confusion with general material fields. There are many types of documents. Multi-turn dialogue must guide users to gradually specify document types and associated work orders, to reduce vague queries. Handling discrepancies between book and physical inventory requires linking inventory records and work order data. Prompts must pre-set cross-document association logic for verification.

The following configurations are based on FastGPT v4.17.0.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context | 8000–10000 preceding characters | Covers complete fields of lot ledgers and 3 to 5 core warehouse documents, avoids truncating critical lot and expiration date information |
| Single Search Limit | Top 6 results | Matches multiple documents associated with the same work order, avoids redundant inventory data interfering with core queries |
| `variables` | Pre-set lot number and warehouse location code as required variables | Quickly locates data for specific warehouse scenarios from user queries, reduces fuzzy matching errors |
| `chatId` | Bind the session to the current work order number | Retains multi-turn dialogue context within the same scenario, continues lot tracking and material availability verification logic |
| Question Optimization | Enabled | Automatically supplements fields such as lot numbers and warehouse locations for vague queries like "find materials", to guide precise searches |
| Chunk Overlap Length | 150–200 characters | Retains contextual association between lot numbers and warehouse location codes, avoids losing critical matching information after chunking |

## Three common mistakes
- Scenario: Failed to upload warehouse document attachments when calling the dialogue interface, returns an error with empty fields. Cause: Failed to correctly configure attachment upload associated fields in the `messages` parameter, and failed to bind the context between the session and file uploads.
- Scenario: Insufficient accuracy of multi-turn dialogue prompts, unable to accurately distinguish query logic for lots and warehouse locations. Cause: Failed to clearly distinguish field rules between System prompts and Human inputs, and failed to pre-set required query conditions via `variables`.
- Scenario: Multi-turn dialogue return results mix information from multiple warehouse documents, unable to split and display by module. Cause: Failed to bind output modules to corresponding document types via `variables`, and failed to clarify output rules in the `messages` parameter.

## How to confirm the configuration is complete
- A test dialogue may be initiated, with the input "Query the warehouse location of lot A001 for work order 123". The returned result may be verified to confirm it links to the material picking/return slip and warehouse location archive for the corresponding work order.
- The `chatId` parameter may be passed when calling the dialogue interface, and 3 consecutive queries about the same lot may be initiated. The context may be verified to confirm it is not reset.
- After configuring `variables`, a vague query like "find materials" may be tested. The system may be verified to automatically prompt for supplementary lot number and warehouse location code.
- After uploading warehouse document attachments, the document parsing result returned by the dialogue interface may be verified to confirm it includes the lot and expiration date fields from the documents.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
