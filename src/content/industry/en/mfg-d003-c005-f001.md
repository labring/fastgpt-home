# Process Specification and Technical Standard Q&A for Photovoltaic Cell Manufacturing: HTTP Interfaces and External Systems

## What data for this category looks like
Normally, business data for photovoltaic cell manufacturing scenarios comes from silicon wafer incoming materials, MES systems, diffusion furnaces, coating equipment, printing presses, EL and IV testing equipment, and laboratories. Daily documents include process cards, diffusion and coating parameter tables, printing and sintering records, EL detection images, IV grading data, and yield reports. Data update cycles cover each production batch, per-wafer test results, and daily summaries. Fields include diffusion temperature (℃), printing paste thickness (μm), photoelectric conversion efficiency (%), yield rate, and others. The volume of single test data fluctuates with batch scale.

## What constraints do these characteristics impose on HTTP interfaces and external systems
Data in this scenario is multi-source heterogeneous and updated frequently. HTTP interfaces must support integration with multiple types of external systems, including equipment PLCs, MES systems, and testing instruments. The high-frequency data upload requirement for single production batches places demands on the interface's concurrent processing capability. Differences in fields across different document types—such as structured parameter tables and unstructured detection images—require interfaces to adapt to different request body formats. The business also has high requirements for data accuracy. Interfaces must support parameter verification and exception capture to prevent incorrect process parameters from entering production links.

## How to set up configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Carry an enterprise-specific token in the format `Bearer {token}` | Identity verification when connecting to external systems, to prevent unauthorized access |
| Single request timeout | 600 seconds | Adapt to the delay of photovoltaic production equipment data uploads, to avoid request interruptions caused by slow device responses |
| `variables` | Bind process fields such as diffusion temperature and printing paste thickness | Enable dynamic parameter replacement during process specification Q&A, to match real-time production data |
| `responseData` | Filter return fields, only retain process standards and compliance judgment results | Simplify returned content, to adapt to the receiving format of external systems |
| External system callback address | Fill in the interface path specified by the MES system | Enable automatic synchronization of Q&A results with production systems |
| Request body format | Set JSON/binary separately according to document type | Adapt to the transmission requirements of structured parameter tables and unstructured detection images |

## Three common configuration mistakes
- Phenomenon: The interface returns a `401 Unauthorized` status code. Cause: The `Authorization` parameter is not configured correctly, or the token format or permissions do not meet the requirements of the external system.
- Phenomenon: The Q&A result fields returned by the interface are missing. Cause: The `responseData` configuration is not used correctly to filter returned content, or real-time production parameters in `variables` are not bound.
- Phenomenon: The interface request times out. Cause: The single request timeout is set too short, and does not adapt to the data upload delay of photovoltaic production equipment.

## How to verify a complete configuration
- Call the interface with a properly formatted `Authorization` parameter, and check that the returned HTTP status code is `200 OK`.
- Pass simulated process parameter data, and check that `variables` successfully bind and replace dynamic fields in the Q&A content.
- After configuring the callback address, send a test request, and check that the external system receives the correct Q&A results.
- Simulate a delay scenario for equipment data uploads, and confirm that the interface does not interrupt requests due to timeout.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
