# Process Specification and Technical Standard Q&A for Photovoltaic Cell Manufacturing: Workflow Orchestration

## What this category of data looks like
This category of data mainly comes from the process, equipment, quality control, and production departments of crystalline silicon cell enterprises. It covers documents such as process cards, diffusion and coating parameters, printing and sintering records, EL detection images, IV grading data, and yield reports. Data sources include silicon wafer incoming material ledgers, MES systems, operation data of diffusion furnaces, coating equipment, and printing presses, EL and IV test results, and laboratory test records. Update cycles cover each production batch, individual test results, and daily summaries. Documents include fields such as process parameters, detection indicators, and grading results. Units involve professional parameters such as temperature, current, and conversion efficiency.

## What constraints these characteristics impose on the "workflow orchestration" link
Photovoltaic cell manufacturing data has a high update frequency and fine granularity. Each piece of test data needs to be synchronized in real time, so the workflow must support high-frequency triggers and small-batch data processing. Mixed calls of multiple types of documents require the workflow to distinguish the retrieval logic of process parameter data and detection data to avoid confusion between cross-type data. The update rhythm based on batches and daily summaries requires the workflow to associate data sources of corresponding periods to ensure that the retrieved process specifications match the current production batch. The sensitivity of piece-level test data requires the workflow's `variables` to be bound to the production batch ID to prevent data misuse, and restrict non-authorized nodes from accessing original test data.

## How to set the configuration
The following configurations are formulated based on the logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Variable Binding | Bind the production batch ID and the `variables` field | Ensure the workflow only retrieves process specifications and test data corresponding to the current batch, avoiding confusion between cross-batch data |
| Knowledge Base Association | Associate dedicated knowledge bases for process cards and parameter ledgers | Match the professional document types of photovoltaic cell manufacturing, narrowing the retrieval scope |
| Tool Call Branching | Divide knowledge base and MCP call paths by document type | Distinguish the call logic between process parameter queries and equipment operation data queries |
| Form Input Node | Use the global production batch variable as the default value | Reduce manual input frequency, adapting to high-frequency production scenarios |
| Timeout Threshold | 600 seconds | Cover the time requirements of multi-device data pulling and multi-document retrieval |
| Node Permission Configuration | Divide `nodeId` access scopes by department | Restrict process, equipment, and quality control departments to only access workflow nodes with corresponding permissions |

## Three Common Mistakes
- Phenomenon: Workflow nodes cannot add input parameters for HTTP responses, and the form fields are empty. Cause: The binding rules for input parameters are not declared in the `variables` configuration, causing the system to fail to recognize the incoming parameter fields.
- Phenomenon: No file is generated after clicking the workflow export button, and the interface prompts a parameter error. Cause: The `nodeId` associated path of the workflow is not configured, causing the export logic to fail to locate the complete node configuration.
- Phenomenon: The default value of the form input node cannot read the global production batch variable and displays as empty. Cause: The global variable is not correctly bound to the `variables` configuration of the form node, causing the system context value to fail to be obtained.

## How to Confirm the Configuration is Correct
- Trigger the workflow once, check whether the returned results only include process specifications and test data corresponding to the current production batch.
- Submit the form input, confirm that the default value automatically loads the global production batch variable without manual input.
- Test different types of query requests, confirm that they are routed to the knowledge base or MCP call nodes according to the configuration.
- Export the workflow configuration file, check whether the file contains the complete configuration information of all nodes.
