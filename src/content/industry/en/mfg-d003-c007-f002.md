# Process Specification and Technical Standard Q&A for Stamping and Sheet Forming: Vector Models and Indexes

## What Data Looks Like for This Category
The data for this category mainly comes from steel coil labels and quality certificates, press and feeder operation data, mold management systems, MES systems, coordinate measuring machine or fixture inspection data. Daily documents include stamping work instructions, material utilization rate sheets, mold inspection sheets, first and last piece records, dimensional inspection reports, and mold change records. Data updates trigger per coil of material, each production batch, and every mold change operation. Document fields include material grade, material thickness specification, mold model, mold change time, inspection deviation value, and more. Some documents include on-site photos of process parameters and actual measurement records.

## Constraints Imposed on Vector Models and Indexes
This category of data is updated frequently alongside production batches and mold change operations. Indexes must support incremental updates to reduce resource consumption from full reconstruction. Multi-source, heterogeneous document formats—including tabular inspection sheets and step-by-step work instructions—require chunking strategies tailored to different document structures. This prevents splitting that breaks the complete association of process parameters. Process parameters in production links have strong interdependencies, so indexes must bind metadata such as material, mold, and batch information for precise filtering. Because errors in this context lead to serious consequences, the proportion of low-confidence recall results must be limited to avoid invalid results disrupting on-site decision-making.

## How to Set Configurations
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxToken` | `8000–12000 token` | Stamping process documents include multiple sets of continuous parameters, so complete context must be retained to avoid truncating critical process steps |
| `defaultToken` | `2000–3000 token` | Single-round process Q&A must cover the core parameters of a single work instruction to avoid context overflow impacting recall |
| Chunk Length | `500–800 characters` | Adapted to the step-by-step structure of stamping work instructions, retaining complete logic and parameter associations for a single process step |
| Overlap Length | `50–100 characters` | Retains connecting content when process parameters span chunks, avoiding logical breaks in recall results |
| Similarity Threshold | `0.75–0.85` | Stamping process parameter matching has high precision requirements, filtering out low-confidence invalid recall results |
| Single Search Limit | `Top 8 entries` | Production scenarios require quick location of core process solutions; too many results increase on-site decision-making costs |

## Three Common Mistakes
- Phenomenon: Retrieval fails to prioritize calling the specified knowledge base index, resulting in cross-knowledge base invalid recall. Cause: No knowledge base priority filtering rules are configured, leading to mixed output of retrieval results from multiple knowledge bases.
- Phenomenon: Retrieval requests return a 60-second timeout error. Cause: Incremental indexing is not enabled, and full index scanning covers a large volume of historical mold change and batch data, causing retrieval time to exceed system thresholds.
- Phenomenon: The interface returns a parameter verification failure when adding collection block indexes in bulk. Cause: Metadata fields such as material grade and mold model are not included as required, preventing indexes from associating core production scenario information.

## How to Confirm Proper Configuration
- Check the incremental update switch status in the index management interface, confirm that incremental synchronization has been enabled for mold change and batch data.
- Submit a simulated retrieval request, enter a stamping process-related question, and verify that the metadata of the recall results includes the specified material and mold information.
- Test the bulk index addition interface request, confirm that the return status code is 200 and there are no parameter verification errors.
- View the retrieval logs, confirm that single retrieval time does not exceed the preset threshold, and there are no timeout error records.

The values provided are common starting points and should be measured against the reader's own samples.
