# Stamping and Sheet Metal Forming Process Specification and Technical Standard Q&A: Multi-turn Dialogue and Prompt Words

## What this category of data looks like
This category of data comes from daily production documents and equipment data from stamping workshops of automobile panel, household appliance sheet metal, and hardware component enterprises. It includes stamping operation instructions, material utilization rate tables, mold inspection forms, first and last piece records, dimensional inspection reports, mold change records, and other materials. Data sources cover steel coil labels and quality certificates, punch and feeder data, mold management systems, MES systems, coordinate measuring machine or fixture inspection data. Update frequency adjusts with each coil of material, each batch of workpieces, or each mold change. Document fields contain specific production parameters including material grade, mold number, blank holder force parameters, dimensional tolerances, mold change time, and additional relevant details.

## Constraints Imposed on Multi-turn Dialogue and Prompt Words
The data for this category updates frequently with coils, batches, or mold changes. Multi-turn dialogue must bind to the context of the current production batch to avoid referencing expired mold parameters or material data. Field differences across documents are significant. Prompt words must explicitly specify exclusive fields for the corresponding document, such as blank holder force and springback correction calculation rules. Changes to mold setup and material batches have a major impact on production stability. The context window for multi-turn dialogue must be limited to the current batch cycle to prevent cross-batch parameter confusion. Errors in process Q&A directly affect batch production quality. The conclusion of each dialogue must be traceable back to the original data in the corresponding production document.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Maximum context entries | First 3–5 current batch dialogues | This category of data updates frequently with batches and mold changes. Limiting context avoids cross-batch parameter confusion |
| `chatId` | Bind to the session ID of the current production batch | Multi-turn dialogue must be tied to production data for a specific batch to ensure context consistency |
| `variables` | Embed current steel coil grade and mold number variables | Dynamic calls to process documents and equipment data for the corresponding batch are required |
| `messages` | Include fixed prompt words for current batch process rules | Explicitly specify exclusive stamping process rules to avoid ambiguity from generic prompt words |
| Prompt template | Calibrate based on actual testing | This category of documents includes exclusive parameters such as blank holder force and springback correction. The format must match the specific operation instructions |
| Context verification switch | Enable current batch data verification | Prevent reference to expired mold inspection or mold change record data |

## Three Common Misconfigurations
- Symptom: Only 2 context entries appear in the dialogue details, but 30 context window entries are configured. Cause: The `chatId` for the current production batch is not bound. Session context is shared globally, and old cross-batch dialogues are loaded preferentially.
- Symptom: The completion reason field of the AI dialogue node is empty, and subsequent components cannot reference the field value. Cause: The prompt template does not explicitly require outputting a structured completion reason field, and the output permission for this field is not configured via `variables`.
- Symptom: Loop logic fails to trigger secondary AI dialogue to generate revised content. Cause: Batch variables such as current steel coil grade and mold number are not passed to the loop node, so the revision logic cannot match the current production process parameters.

## How to Confirm Proper Configuration
- Check if the session `chatId` is bound to the current production batch number, and confirm that only dialogue content from the current batch is loaded as context.
- Trigger a process Q&A, and verify that the output results include variable values configured via `variables` such as the current batch steel coil grade and mold number.
- Test multi-turn dialogue, and confirm that the conclusion of each round is associated with the process document data of the current batch, and no expired mold change or inspection record data is referenced.
- Trigger multi-turn dialogue and loop logic tests, and confirm that the conclusion of the previous round can be used as an input parameter for the next round of prompt words.

The values provided here are common starting points and should be measured against the reader's own samples.
