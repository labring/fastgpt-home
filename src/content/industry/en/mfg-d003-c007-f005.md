# Stamping and Sheet Forming Process Specification and Technical Standard Q&A: Tool Calling and Plugins

## What Data for This Category Looks Like
This category of data originates from steel coil labels and quality certificates, punch and feeder operation data, mold management systems, MES systems, and coordinate measuring machine or fixture inspection data. Daily produced documents include stamping work instructions, material utilization rate tables, mold inspection checklists, first and last piece records, dimensional inspection reports, and mold change records. Data updates trigger per coil of material, per batch of materials, or each mold change. Document fields include material batch numbers, mold numbers, blank holder force parameters, dimensional tolerance values, and additional relevant fields. Units include MPa, mm, pieces, and other standard production units.

## Constraints on Tool Calling and Plugins From These Characteristics
High update frequency and scattered trigger nodes require tool calling to support on-demand pulling of the latest batch data, and avoid use of expired historical documents. Diverse document types and inconsistent field units require plugins to configure multi-source data parsing rules, adapting to the text format of work instructions and the numerical format of fixture data. Stamping scenarios carry severe error consequences. Tool calling must add matching logic for mold numbers and material batch numbers during parameter verification, to prevent batch production issues caused by calling incorrect data. Additionally, high mold change frequency requires tool calling response speed to adapt to workshop rapid process adjustment needs, avoiding delays that disrupt production schedules.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | Adapts to the need for dynamically calling different tools such as material utilization rate calculation and mold parameter query in stamping process Q&A |
| Workflow/API function-call configuration | `Enabled` | Forces the model to output tool call results in structured format, ensuring that process parameter query outputs can be parsed by workshop production systems |
| Tool call timeout | 300–600 seconds | Adapts to the time required to pull mold change records and coordinate measuring machine inspection data from MES systems, avoiding call failures caused by slow responses from workshop systems |
| Tool call retry count | 2 times | Adapts to rapid recovery after workshop data pulling failures, avoiding process interruptions caused by a single failed call |
| Tool call result filtering | Retain only core process fields | Filters redundant equipment operation logs from daily documents, focusing on key content in stamping work instructions and material utilization rate tables |
| Context window size | 8000–12000 token | Accommodates context information of mold change records and first and last piece inspection data for multiple batches of materials, ensuring Q&A coherence |

## Three Common Misconfigurations
- Symptom: Workflows return "incorrect API Key used" or a 401 status code. Cause: The global universal API Key is mistakenly used for calling the application conversation interface, instead of the application-specific API key.
- Symptom: Tool call responses include knowledge base search input and response fields, with excessive redundant information. Cause: Rules to block knowledge base reference content are not configured, or configuration items are not correctly linked to the tool calling workflow.
- Symptom: Tool call returns process parameters that do not match the current batch of materials. Cause: Matching logic for material batch numbers and mold numbers is not added to the tool call configuration, leading to calls of expired or incorrect mold change record data.

## How to Verify Proper Configuration
- In the FastGPT v4.17.0 workflow debugging interface, enter stamping process-related questions to trigger tool calls. Confirm that `toolChoice` automatically matches the corresponding tool type.
- Review tool call return results. Confirm that only core process fields from stamping work instructions and material utilization rate tables are included, with no redundant information.
- Verify that the `functionCall` configuration takes effect. Tool call results return in structured format, and can be directly parsed by downstream production systems.
- Enter query questions for different batches of materials. Confirm that tool calls pull the latest data for the corresponding batch, and no expired content is returned.

The values provided here are common starting points, and should be evaluated against local operational samples.
