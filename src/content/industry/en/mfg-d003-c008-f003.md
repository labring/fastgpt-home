# Cosmetics Manufacturing Process Procedures and Technical Standards Q&A: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
This category of data is sourced from multiple document types across skin care, hair care, makeup, and special cosmetics manufacturing enterprises. These documents include formula process sheets, weighing and feeding records, emulsification and filling records, site cleaning and clearance records, semi-finished and finished product inspection reports, and label review documents.
Data sources cover registered or filed formulas, raw material safety materials, production equipment logs, ERP/MES systems, laboratory test results, and packaging material version documents. Updates trigger per production batch or each line change.
Data fields include formula components, restricted substance content, emulsification temperature, homogenization parameters, batch number, packaging material version, and other items. Each field corresponds to exclusive formats and units tied to different documents.

## Constraints for Multi-turn Dialogue and Prompt Engineering
The high-frequency update requirement for each production batch or line change requires multi-turn dialogue to quickly bind exclusive data for the current batch. This prevents calling expired formula and filing information from older batches.
The varied formats of multiple document types require prompts to clearly define reading priorities for different documents. This ensures priority matching of documents aligned with the current production link.
Strict compliance constraints for restricted substances and formula filings require all content returned by dialogue to strictly match officially registered and filed data. No deviations are permitted.
Cross-link data association needs demand full retention of context information from feeding, inspection, and other links during multi-round interaction. The context window must therefore cover complete associated content for all multi-turn questions and corresponding replies.

## Configuration Setup
This configuration is based on the functional logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind the unique identifier of the current production batch | Ensure multi-turn dialogue only associates production data for the current batch. Avoid confusion of formulas and filing information across batches, and comply with batch-based management requirements for cosmetics manufacturing |
| `messages` | Retain the last 10 rounds of interaction and corresponding production document fragments | Cover core production link context from feeding, emulsification to inspection. Meet the needs of production personnel for cross-link questions, and adapt to the multi-step process requirements of cosmetics manufacturing |
| `variables` | Preset raw material safety limits and filed formula numbers for the current batch | Quickly call exclusive production parameters for the current batch. Reduce repeated input operations by production personnel, and improve Q&A efficiency |
| Maximum context length | 800–1200 characters | Adapt to the typical length of single segments of cosmetics production documents. Avoid reduced matching accuracy caused by context overload |
| Question Optimization | Enabled | Convert colloquial questions from production personnel into standardized process procedure query statements. Improve matching accuracy with filing documents and production records |

## Three Common Misconfigurations
- Phenomenon: The returned reply content does not match the process procedures of the current production batch when calling dialogue record-related interfaces. Cause: `chatId` is not correctly bound as the unique identifier of the current batch. This causes the system to call context data from other batches.
- Phenomenon: Non-current users can view other users' dialogue content in the shared application. Cause: Session isolation is not implemented based on `chatId`, and binding rules between users and dialogues are not configured.
- Phenomenon: When using the "Get Dialogue Record List" interface, user questions and AI replies in the returned results cannot be matched. Cause: Complete context association information of the `messages` parameter is not carried in the request. This causes the interface to fail to correctly match the corresponding relationship.

## How to Verify Proper Configuration
- Initiate a question about the current batch formula. Check if the returned result includes the filed formula number for the current batch. Confirm that the `variables` parameter has correctly loaded preset values.
- Initiate multi-round cross-link questions. For example, first ask about feeding requirements, then ask about emulsification parameters. Check if the system can associate the feeding information from the previous round. Confirm that the `messages` parameter retains context.
- Call the "Get Dialogue Record List" interface. Check if each returned record can match the corresponding user question and AI reply. Confirm that `chatId` binding is correct.
- After sharing the application, initiate dialogues using different accounts. Check that each account can only view its own dialogue content. Confirm that the session isolation configuration takes effect.

The values provided here are common starting points. They should be evaluated against the reader's own samples.
