# Cosmetics Manufacturing Process Procedures and Technical Standards Q&A: Model Connection and Configuration

## What this category's data looks like
Data comes from registered and filed formulas, raw material safety materials, production equipment logs, ERP/MES systems, laboratory test records, and packaging material version archives from skincare, haircare, makeup, and special cosmetics manufacturers. Daily documents include formula process sheets, weighing and feeding records, emulsification or filling records, site cleaning records, semi-finished and finished product test reports, and label review documents.
Data updates trigger with each production batch or line change operation. Core fields include raw material restricted substance content, process parameter thresholds, packaging material claim content, and batch numbers.

## What constraints these characteristics impose on model connection and configuration
Data updates occur frequently and change with production batches. Model connections must support dynamic data synchronization, and avoid using static cached expired formulas or records.
Significant field differences exist across multiple document types. Corresponding data parsing rules must be configured to ensure raw material and process data from different sources can be uniformly identified.
Compliance verification of raw material restricted substances relies on precise matching of filed data. Model calls must link to the latest registered and filed information, and avoid using outdated data.
Real-time process parameters during production must be quickly passed to the model. The connected API response delay must meet real-time interaction requirements.

## How to set the configuration
This configuration applies to FastGPT v4.17.0 and later versions.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Matches the average length of single-batch documents for cosmetics manufacturing, covering complete process and test data |
| `maxTokens` | 4000 token | Limits the output length of single-round Q&A, avoiding overly long content that impacts interaction efficiency |
| `temperature` | 0.1–0.3 | Reduces random output probability, ensuring consistent and accurate responses for process parameters and compliance requirements |
| `AIPROXY_API_ENDPOINT` | Fill in the dedicated access address according to the deployment environment | Adapts to the access path of enterprise internal networks or cloud services, ensuring data transmission security |
| `quoteMaxToken` | 1500 characters | Limits the length of quoted document fragments, focusing on core process or compliance content related to the current question |

## Three common errors
- Symptom: Model calls return a 401 unauthorized error. Cause: The `AIPROXY_API_TOKEN` parameter is not filled correctly, or the token permissions do not cover the compliance data access scope required for cosmetics manufacturing.
- Symptom: Signature time fields are empty in workflows. Cause: System time variables are not bound correctly, or the standard calling syntax of `{{platform time variable}}` is not used.
- Symptom: Process parameters output by the model do not match the latest filed data. Cause: The `maxContext` parameter is not configured to limit the context range, resulting in the introduction of expired pre-line-change production data.

## How to confirm the configuration is complete
- Conduct a single formula compliance verification test. Check that the raw material restricted substance results returned by the model match the filed documents, confirming normal data association.
- Trigger a process Q&A for line change scenarios. Verify that the document update time referenced by the model matches the current production batch, confirming that dynamic data synchronization is effective.
- Submit a workflow test that includes time variables. Confirm that the signature time field automatically fills in the current date, confirming correct variable binding.
- View the model call log. Confirm that the `AIPROXY_API_TOKEN` verification passes, with no permission-related errors, confirming normal access permissions.

The values provided are common starting points and should be evaluated against the reader's own samples.
