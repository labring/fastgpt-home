# Process Specification and Technical Standard Q&A for Pharmaceutical Preparations Manufacturing: HTTP Interfaces and External Systems

## What this category of data looks like
The main entities of data related to pharmaceutical preparations manufacturing are production, quality assurance, quality control, and warehousing departments. Daily documents include master production files, batch production records, batch packaging records, cleaning records, inspection records, deviations/CAPA/change requests, and batch release approval forms. Data sources include approved prescription processes, material batches, MES/electronic batch records, equipment and environmental monitoring, LIMS, and quality management systems. Update frequency follows per batch, per critical step, and per monitoring plan. Data fields include batch numbers, material information, process parameters, test results, and more, and must strictly align with compliance requirements.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
Data sources for pharmaceutical preparations manufacturing are scattered across multiple independent systems. Interfaces must adapt to the data formats and permission rules of different systems. Data update frequency is high and strongly tied to production batches. Interface trigger timing must match the critical steps of single-batch production to ensure real-time and accurate Q&A content. Restricted by compliance requirements, interfaces must strictly verify access identities. Returned documents must be traceable. Single-batch production data volume is large, so interfaces must limit the scale of returned content to avoid excessive load affecting response speed in production links.

## How to set configurations
This document is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `Authorization` | Bearer {encrypted compliant access token} | Process specifications and batch records are regulated data. This parameter completes strict identity verification to meet compliance data security requirements |
| `variables` | Bind batch number, material batch, and test result fields | Must accurately match the associated parameters of a single batch production to ensure Q&A returned process and standard content aligns with the current batch |
| `responseData` | Include document title, effective version, and associated batch record number | Enables production and quality departments to quickly locate compliant documents, meeting traceability requirements |
| Number of documents returned per request | Top 5 entries | Batch records and process documents for pharmaceutical preparations manufacturing have large data volumes per batch. Limiting returned entries reduces interface load while meeting quick access needs |
| Timeout threshold | 600 seconds | When integrating multiple systems (MES, LIMS, quality management systems), data pulling takes a long time. Sufficient time must be reserved for data synchronization |
| Context window size | 8000–12000 token | Calibrated through actual testing, this range covers the complete content of a single batch process specification and associated inspection records |

## Three Common Misconfigurations
- Symptom: The interface returns `Api response error: undefined`. Cause: The `variables` parameter is not correctly configured to pass associated fields such as batch number, so the system cannot match the corresponding process and batch record data.
- Symptom: The file collection creation API interface does not specify PDF parsing configuration, so process specification PDF documents cannot be parsed correctly, and empty document fragments are returned. Cause: The corresponding parsing rules are not bound in the interface configuration, so the default parsing logic cannot adapt to the PDF document format used in pharmaceutical preparations manufacturing.
- Symptom: Using an incorrect port when calling the proxy service results in failure to connect to the LLM service. Cause: The correct service port is not configured according to the requirements of the integrated system, and the port rules of different proxy services are confused.

## How to Confirm Proper Configuration
- Call the interface with the `variables` parameter using a known compliant batch number, and check if `responseData` returns the process specification and batch record associated content for the corresponding batch.
- After configuring the `Authorization` parameter, send a request using an invalid token to confirm that an identity verification failure error prompt is returned.
- Send a file collection creation request with PDF parsing related configuration, and check if the interface returns a normal document parsing status.
- Monitor the response duration after sending an interface request, and confirm that it does not exceed the preset timeout threshold.
