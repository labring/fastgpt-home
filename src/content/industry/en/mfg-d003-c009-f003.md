# Q&A for Process Procedures and Technical Standards of Chemical Pharmaceutical Preparations Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What data for this category looks like
Daily documents for this category include master production documents, batch production records, batch packaging records, cleaning records, inspection records, deviation/CAPA/change documents, and batch release review forms. Data comes from approved prescription processes, material batch information, MES systems, electronic batch records, equipment and environmental monitoring data, LIMS, and quality management systems. Data updates trigger with each batch production, execution of key process steps, and progress of monitoring plans. Fields include process parameter ranges, material batch numbers, test results, deviation descriptions, and more. No unified fixed units exist; values adjust based on corresponding document fields.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
Data for this category updates dynamically with each batch production. Multi-turn dialogue must use `chatId` to bind exclusive context for the current batch, to avoid mixing data across batches. Document fields have no unified units and include sensitive information such as process parameters and material batch numbers. Prompts must explicitly specify extraction of fields corresponding to the current batch, to prevent invalid or non-compliant output. Since error consequences directly relate to batch release and regulatory compliance, dialogue processes must retain historical interaction records to ensure traceability during review. Complex summary and review tasks require step-by-step disassembly via multi-turn dialogue, to avoid exceeding model processing limits in a single request.

## Three Common Misconfigurations
- Symptom: After a rerank model is configured, the external network can ping the model, but reranked sorting results do not appear in the conversation details. Cause: The rerank configuration is not bound to the retrieval link for this process Q&A, or the system prompt does not specify using rerank results to generate responses.
- Symptom: After the `variables` parameter is passed, prompt placeholders are not replaced, and returned content is unrelated to the target batch. Cause: The placeholder format is not correctly declared in the prompt, or the `variables` parameter is not bound to the conversation request during API calls, leading to ineffective variables.
- Symptom: After user input, the text content extraction node does not return expected fields, and the process stalls after triggering a specified response. Cause: No backtracking guidance mechanism for multi-turn dialogue is configured, and users are not prompted to supplement missing batch information or process parameters, leading to stalled process progression.

## How to Verify Correct Configuration
- A test request containing current production batch information is sent using FastGPT v4.17.0. Returned content is verified to accurately link to process parameters and records for the corresponding batch.
- The conversation details page is reviewed to confirm the `messages` parameter fully retains historical interaction system prompts and user messages, with no accidental truncation.
- Preset `variables` parameters are passed, and prompt placeholders are verified to be correctly replaced with corresponding field values.
- A text extraction failure scenario is simulated. The process is confirmed to trigger a specified response and prompt users to supplement necessary information.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
