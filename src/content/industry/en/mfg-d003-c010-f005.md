# Q&A for Process Specifications and Technical Standards for Medical Device Assembly and Clean Production: Tool Calling and Plugins

## What this category's data looks like
This category's data primarily comes from design history files, device and material batches, MES systems, clean environment monitoring equipment, sterilization equipment, and inspection and calibration systems. Daily documents include production process specifications, batch production records, clean zone records, sterilization batch records, inspection reports, software version records, adverse event and traceability materials. Data update frequency follows per batch or per product, or as specified in the clean environment monitoring plan. Document fields include core content such as unique device identification, material batch number, sterilization parameters, clean zone temperature and humidity values, and software version number.

## What constraints these characteristics impose on tool calling and plugins
Data for this category is updated frequently and is strongly tied to production batches. Tool calling must be associated with a unique device identification to avoid cross-batch calling errors. Documents include controlled process specifications and traceability materials. Tool calling must strictly follow access controls, allowing only authorized nodes to access sensitive data. Data fields include professional content such as sterilization parameters and clean environment indicators. Plugins must support loading dedicated field mappings for this category, and cannot directly reuse field rules from general categories. Additionally, data update frequency changes with production batches. The context cache for tool calling must be refreshed regularly to avoid using expired batch record data.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | Set to `auto` | Adapt to multi-batch data matching requirements, automatically associate process data corresponding to the unique device identification |
| Workflow/API function-call configuration | Enable | Force calling of batch-bound tools to ensure that Q&A only returns compliant data for the current production batch |
| Single tool call wait duration | Set to `60 seconds` | Adapt to the response requirements of professional data queries for this category, avoid timeouts caused by large data volumes |
| Context refresh cycle | Set to `15 minutes` | Adapt to the data update rhythm of this category per batch or as planned, avoid using expired batch records |
| Field mapping rules | Bind unique device identification, sterilization parameters, and clean zone temperature and humidity fields | Correspond to the dedicated field structure of documents in this category, ensure Q&A returns accurate process and standard content |

## Three Common Mistakes
- The symptom is that the conversation window icon is not customized as required for the production environment. The cause is that no custom icon file was uploaded in the FastGPT v4.17.0 plugin configuration, and only the default style was used.
- The symptom is that the Chrome plugin cannot pull local production data after deployment. The cause is that cross-domain access permissions for the plugin and the internal MES system were not configured, resulting in data requests being blocked.
- The symptom is that the workflow name returned by tool calling is empty. The cause is that the workflow unique identification parameter was not correctly included in the call request, making it impossible to match the process specification data for the corresponding batch.

## How to Confirm Configuration is Valid
- After uploading the custom icon file, check in the platform preview interface whether the conversation window icon matches the production environment identifiers.
- Initiate a query request with a unique device identification, check whether the returned results include sterilization parameters and clean zone record data for the corresponding batch.
- View the tool calling logs to confirm that the `functionCall` parameter has taken effect, and only workflows bound to the current batch are called.
- Check the plugin permission configuration to confirm that the access scope of different production roles meets the security requirements of controlled documents.
