# Q&A for Process Specifications and Technical Standards for Medical Device Assembly and Clean Production: Source Citation and Traceability

## What data looks like for this category
Data for this category comes from end-to-end production workflows of manufacturers of single-use consumables, implantable and interventional devices, diagnostic equipment, and active medical devices. It includes documents such as production process specifications, batch production records, clean zone environment records, sterilization batch records, test reports, and software version records. Data sources cover design history files, device and material batch ledgers, MES systems, clean environment monitoring equipment, sterilization equipment, and test and calibration systems. Data updates are performed per product batch or per piece of equipment. Clean environment monitoring data is updated on a scheduled plan. Each individual document includes structured fields such as unique device identifier, batch number, process parameters, and test results, plus detailed operating requirements for the corresponding production stage.

## What constraints these characteristics impose on source citation and traceability
Data for this category is tied to specific batches and production stages. When citing, precise matching of unique device identifiers and batch numbers is required to avoid mixing process requirements across batches. Multi-source data associations must clearly label source systems and update times to ensure traceability. Data updates occur at a relatively high frequency, so retrieved results must be the latest valid records. Individual data entries have a large volume, so citations must balance content completeness and context length limits to prevent loss of critical compliance parameters due to truncation. Errors may lead to serious outcomes such as sterile failure or failed traceability, so accuracy and completeness of traceability information are core constraints.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 8000–12000 token | This category’s individual batch record data has a large volume, so full process steps and batch parameters must be covered to avoid truncation of critical information |
| `responseData` | Return batch number, source system, and update time fields | This category requires binding of unique identifiers and traceability information to facilitate tracing of production stages and data validity |
| `detail` | Enabled | Full process specification clauses and test report details must be displayed to meet compliance requirements |
| Single search limit | Top 10 results | Data for this category is categorized by batch, and too many results may cause confusion between process requirements of different batches |
| Result reordering | Sorted in descending order by source update time | The latest batch records and environment monitoring data serve as reference for current assembly processes |
| FastGPT version | v4.17.0 | This version optimizes field mapping logic for multi-source data traceability |

## Three common mistakes
- Phenomenon: The context window displayed in the interface only shows 30 results, but the actual number of retrieved documents is 310, and the results sent to the calling end are also 310. Reason: The front-end rendering field for `responseData` was not configured in FastGPT v4.17.0, causing the front end to only load and display partial results.
- Phenomenon: After setting `quoteMaxToken` to 1500 token, document chunks in the knowledge base that exceed this length are still successfully cited. Reason: `quoteMaxToken` only limits the token limit for a single retrieved document chunk, and does not combine with the single search limit to restrict total context length, resulting in ultra-long chunks being included in the context individually.
- Phenomenon: After passing knowledge base retrieval results into an HTTP request, the AI chat stage cannot correctly associate citation sources. Reason: Source fields were not passed in the `responseData` format required by FastGPT, causing the chat module to fail to recognize traceability information.

## How to confirm correct configuration
- Submit a process query for a specific batch, and check whether the reply includes the corresponding batch number, source system name, and update time.
- Adjust the value of `quoteMaxToken`, and observe whether the total context length changes accordingly.
- After enabling the `detail` configuration, confirm that the reply includes complete process specification clauses and test details.
- Simulate multi-batch data retrieval, and check whether results are sorted in descending order by update time and there is no cross-batch content confusion.

The values given are common starting points and should be measured against the reader's own samples.
