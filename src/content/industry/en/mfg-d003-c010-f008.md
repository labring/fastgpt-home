# Process Specification and Technical Standard Q&A for Medical Device Assembly and Clean Production: Document Parsing and Chunking

## What the data for this industry category looks like
The typical subjects of this category are manufacturers of single-use consumables, implantable and interventional devices, diagnostic equipment, and active medical devices. Daily production and management documents include production process specifications, batch production records, clean zone records, sterilization batch records, test reports, software version records, adverse event and traceability materials. Data sources include design history files, device and material batch ledgers, MES systems, clean environment monitoring equipment, sterilization equipment, testing and calibration systems. Documents are updated per batch or per device, or at regular intervals per clean environment monitoring plans. Most documents have fixed-format batch identifiers, process parameters, and test data. Fields include sterilization batch numbers, clean zone temperature and humidity thresholds, biocompatibility test indicators, and more. Units mostly involve professional measurement parameters such as temperature, pressure, and time.

## What constraints these characteristics impose on document parsing and chunking
Documents in this category are mostly batch-based, highly correlated production and test records. Parsing and chunking must retain the complete logical chain within a single batch, and avoid splitting critical parameters and their corresponding identifiers. Otherwise, the accuracy of subsequent process Q&A will be affected. Frequently updated documents require the parsing process to support fast import needs, and avoid duplicate work caused by timeouts or format incompatibility. A high proportion of documents contain embedded images, such as clean zone monitoring reports and sterilization parameter curves. Parsing tools must be able to extract non-text data. The fixed document structure requires chunking rules to adapt to metadata such as headers and batch identifiers, and avoid breaking cross-field association relationships.

## How to Set Configuration
This article is compatible with FastGPT v4.17.0. The following configuration items are formulated based on the document characteristics of this category:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | This category’s documents contain continuous process steps and parameter combinations. This range retains complete information for a single process or batch, and avoids excessive splitting |
| `chunkSplitter` | Split by paragraph + header | Most documents include header metadata such as batch numbers and document types. Splitting by paragraph preserves the complete logic of a single record |
| `customPdfParse` | Enabled | Embedded non-text data such as sterilization parameter reports and clean zone monitoring images must be extracted, to ensure the large language model can access complete data sources |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Parsing a collection of multiple documents for a single batch takes a long time. This duration covers the parsing needs of most large files |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Collections of sterilization batch records and test reports for a single batch may reach a large volume. This upper limit supports complete document imports |
| `chunkSettingMode` | Manual configuration | Chunking parameters must be adjusted for different document types such as process specifications and batch records, to adapt to the category-specific document structure |

## Three Common Mistakes
- Symptom: After uploading a Yuque publicly shared document link, the system prompts that the data source type is unsupported, and parsing fails. Cause: The Yuque link was not confirmed to be a fully public share page without permission restrictions. Controlled internal documents for this category require adjusted sharing permissions before import.
- Symptom: Embedded clean zone temperature and humidity record images are not extracted from the parsed document, and this type of data cannot be obtained during Q&A. Cause: The `customPdfParse` configuration was not enabled. The default parsing only extracts plain text content, and does not process embedded image resources.
- Symptom: The chunking result splits sterilization temperature and duration parameters for the same sterilization batch into different chunks. Complete parameters cannot be queried together during Q&A. Cause: The `chunkSize` setting is too small, and the batch number in the header was not used as a chunking boundary, breaking the association of batch data.

## How to Confirm the Configuration Is Correct
- Upload a typical batch production record PDF, check that the parsing result includes all text content and embedded images, and confirm that the `customPdfParse` configuration is active.
- Review the chunked document fragments, confirm that critical parameters for the same process or batch are not split across different chunks, and verify the rationality of the `chunkSize` and `chunkSplitter` configurations.
- Upload a single large collection of sterilization batch records, confirm that upload and parsing do not produce timeout errors, and verify that the `UPLOAD_FILE_MAX_SIZE` and `PARSE_FILE_TIMEOUT_SECONDS` configurations adapt to the current document scale.
- Import a controlled document link shared publicly on Yuque, confirm that parsing succeeds and the content is complete, and verify the correctness of the data source configuration.
