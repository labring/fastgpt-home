# Q&A for Process Procedures and Technical Standards for Active Pharmaceutical Ingredient and Pharmaceutical Intermediate Production: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
This category of data comes from daily documents of active pharmaceutical ingredient production departments including synthesis, fermentation, purification, quality control, and registration support. Documents include batch production records, material balance sheets, reaction and purification records, cleaning validation records, impurity profile reports, deviation and change documents. Data sources cover registered process documents, raw material batch ledgers, DCS systems, weighing systems, LIMS, chromatography data systems, and QMS. Update frequency is once per production batch and once per process step. Documents include clear fields for process parameters, material information, test data, and compliance records. Units include temperature, pressure, reaction time, purity percentage, and similar metrics.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
The high-frequency update requirement for each production batch and process step means multi-turn dialogue must quickly sync the latest batch data. It must avoid referencing expired process parameters or test results. The heterogeneous multi-source data requirement means prompt engineering must clearly specify data priority and source systems. It must prevent confusion between test data and process records from different systems. The core business need for impurity profiles and multi-step chemical routes means multi-turn dialogue must retain full reaction step context. It must ensure traceability of intermediate data for each step during process change evaluation. The compliance-related deviation and change document requirement means prompt engineering must clearly label the version and batch information of referenced documents. It must mitigate compliance risks.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0, and are adapted for the process Q&A scenario of active pharmaceutical ingredient and pharmaceutical intermediate production.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the current production batch ID | Ensures each dialogue round is associated with exclusive data for the corresponding batch, avoiding cross-batch parameter confusion |
| `messages` | Retain the last 20 rounds of dialogue context | Covers the complete process chain of multi-step reactions, supporting traceability queries for intermediate handover |
| `variables` | Inject the current batch's raw material lot number and process version number | Automatically fills batch-specific parameters required for dialogue, reducing manual input errors |
| Maximum context length | 8000–12000 characters | Adapts to complete process documents for multi-step reactions and multi-turn dialogue history, avoiding content truncation |
| Question optimization toggle | Enabled | Automatically breaks down complex process questions, adapting to query needs linked to multiple steps in active pharmaceutical ingredient production |

## Three Common Misconfigurations
- Dialogue return results include unspecified Markdown formatting. This occurs because the prompt does not clearly limit output formats, and does not cover the need for plain text display of test data and parameter tables in active pharmaceutical ingredient process documents.
- One-to-many dialogue scenarios cannot distinguish query requests from different production batches. This occurs because `chatId` is not bound to the batch ID, leading to context confusion between process data from different batches.
- Workflows cannot exit the question classification node after AI dialogue completes. This occurs because no output branch binding is configured for dialogue results, causing the process to loop back to the question classification node.

## How to Verify Proper Configuration
- Initiate a query for process parameters of the current production batch. Verify that the dialogue context automatically associates the batch's raw material lot number and process version.
- Input a complex question covering multiple reaction steps. Confirm that the dialogue retains the intermediate data from the previous round, without losing context association.
- Trigger a workflow that includes a question classification node. Submit a compliance-related query. Confirm that the workflow jumps to the preset output node after AI dialogue completes.
- Test Q&A output. Confirm that no unspecified Markdown formatting appears, meeting document display requirements.

The values provided are common starting points, and should be evaluated against the reader's own samples.
