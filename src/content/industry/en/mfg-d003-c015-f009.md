# Q&A for Process Procedures and Technical Standards for Active Pharmaceutical Ingredient and Pharmaceutical Intermediate Production: Model Access and Configuration

## What Data for This Category Looks Like
Daily documents for this category include batch production records, material balance sheets, reaction and purification records, cleaning validation records, impurity profile reports, deviation and change documents. Data sources include registered process documents, raw material batch ledgers, DCS production control systems, LIMS laboratory information management systems, chromatography data systems, and QMS quality management systems. Data updates are triggered with each batch production and completion of each process operation. Fields include batch numbers, reaction parameters, yield, impurity content, solvent residue levels, change approval status, and more. Some data is exported from automated systems, while some are scanned paper documents.

## Constraints Imposed on Model Access and Configuration by These Data Characteristics
The data characteristics of this category impose multiple constraints on model access and configuration. First, multi-source heterogeneous data formats require the configuration link to support cross-system data integration and unstructured document parsing, to avoid loss of key process information due to format incompatibility. Second, high-frequency batch-level updates require model call frequency to match the data update rhythm, to prevent question and answer content from lagging behind production progress. Third, the accuracy of professional fields such as impurity profiles and yields requires model output to strictly match industry terminology. At the same time, compliance Q&A for deviation and change documents requires the model to have context association capabilities, to ensure logical consistency in change evaluations. Finally, the compliance requirements of pharmaceutical production require the configuration link to retain complete call logs and data traceability paths.

## Three Common Configuration Mistakes
- Phenomenon: Interface calls frequently trigger QPS limit errors, with status code 429 returned. Cause: The call frequency is not adjusted for the high-frequency batch data updates of pharmaceutical production, and a reasonable request interval is not set.
- Phenomenon: The process names and impurity values output by the large model have inconsistent Markdown formatting, resulting in messy typesetting. Cause: The `temperature` parameter is not adjusted to a reasonable range, or the prompt does not clearly require compliance with the formatting specifications of pharmaceutical documents.
- Phenomenon: Calls fail after configuring the OneAPI Kimi key, with prompts indicating invalid key or no interface permission. Cause: `AIPROXY_API_ENDPOINT` is not pointed to the corresponding transit address of OneAPI, or the call permission scope of the key is not confirmed.

## How to Verify Successful Configuration
- Send a test query of "View the batch production record of batch XX", check whether accurate fragments and source markers of the corresponding document are returned.
- Initiate a multi-step process Q&A, such as "What are the reaction parameters and yield requirements for the third step in the synthesis of XX intermediate", check whether the output includes professional terminology and has standardized formatting.
- Simulate high-frequency calls, observe whether QPS limits are triggered, confirm that the call frequency configuration matches actual business rhythm.
- Verify the key and interface address configuration, check whether the response status code returned by the interface is 200, with no authentication error prompts.

The values provided are common starting points and should be measured against the reader's own samples.
