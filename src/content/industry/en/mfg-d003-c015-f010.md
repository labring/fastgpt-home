# Q&A on Process Procedures and Technical Standards for Active Pharmaceutical Ingredient and Pharmaceutical Intermediate Production: Knowledge Base Retrieval and Recall

## What This Category's Data Looks Like
Data for this category comes from registered process documents, raw material batch ledgers, DCS systems, weighing systems, LIMS, chromatography data systems, and QMS. Daily documents include batch production records, material balance sheets, reaction and purification records, cleaning validation records, impurity profile reports, deviation and change documents. Core data consists of impurity profiles and records related to multi-step chemical processes. Each document is associated with fields such as batch number, reaction parameters, impurity content, and operation time, covering units including molar ratio, retention time, and batch number. Data updates occur once per production batch or per process step, with real-time synchronization along the production flow.

## Constraints Imposed on Knowledge Base Retrieval and Recall
The multi-source heterogeneous data sources of this category require the retrieval link to support cross-system data associated recall. The high-frequency real-time update feature requires the retrieval link to support incremental synchronization and version verification to avoid calling expired process parameters. Professional documents contain precise chemical parameters, requiring retrieval matching accuracy higher than general scenarios. Fields such as batch and step associated with a single document must be used as retrieval anchors to narrow the recall scope. Production scenarios cover multi-step reaction association, intermediate transfer and yield tracking, requiring the retrieval link to support multi-document association. Errors in the production link directly lead to batch scrap and compliance risks, requiring recall results to be accompanied by data source and update time for verification.

## How to Configure

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | This category requires matching precise process parameters and impurity data. A threshold that is too low will introduce irrelevant batch records, while a threshold that is too high may miss valid compliant documents. |
| `limit` | Top 8 entries | The number of documents associated with a single batch process is limited. Too many results will exceed the context window, while too few will fail to cover multi-step reaction associated data. |
| `searchMode` | Exact Match | Process procedures and technical standards must strictly match registered and filed parameters. Fuzzy matching may introduce non-compliant temporary adjustment records. |
| `usingReRank` | Enabled | Semantic similarity of professional documents requires secondary verification to avoid interference from results that only match keywords but do not match parameters. |
| `datasetSearchUsingExtensionQuery` | Enabled | Can automatically expand synonyms related to processes to cover terminology differences across departments, such as associating "purification step" with "purification operation". |
| `collectionIds` | Bind corresponding knowledge base collections by department | Narrow the retrieval scope, avoid interference from cross-department documents, and improve retrieval efficiency. |

## Three Common Misconfigurations
- Symptom: A provider-related error pops up after clicking to add a new folder in the knowledge base. Cause: The collection permissions of the corresponding knowledge base are not correctly bound, or the configured `collectionIds` parameter contains non-existent collection IDs.
- Symptom: The number of retrieval results is far lower than expected. Cause: The `limit` parameter is set too low, or `datasetSearchUsingExtensionQuery` is not enabled after `searchMode` is set to exact match, resulting in documents with mismatched terminology being filtered out.
- Symptom: An authentication failure is returned when calling the API to synchronize the knowledge base collection. Cause: The correct secret key parameter is not carried in the API request, or the secret key permissions do not cover the target knowledge base collection.

## How to Verify Successful Configuration
- Retrieve the process parameters of a specified batch, and check whether the returned results include the corresponding batch's batch production records and impurity profile reports.
- Adjust the `similarity` parameter range, observe the correlation changes of the returned results, and confirm that the matching logic meets business requirements.
- Simulate adding a new process step document, and verify whether the retrieval link can recall the updated content in real time.
- Check the API call logs to confirm that the `collectionIds` parameter only contains authorized knowledge base collection IDs, with no invalid values.

The values given are common starting points and should be measured against the reader's own samples.
