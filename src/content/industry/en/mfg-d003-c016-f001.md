# Process Specification and Technical Standard Q&A for Transformer and High-Voltage Electrical Equipment Manufacturing: HTTP Interfaces and External Systems

## What the data for this category looks like
Data for this category comes from design BOMs, silicon steel sheet and insulating material ledgers, vacuum drying equipment logs, oil test reports, and test station partial discharge and withstand voltage records. Updates are triggered by single products or per batch of materials. Daily documents include winding and core assembly records, vacuum drying logs, insulating oil test reports, partial discharge and withstand voltage test reports, and nameplate parameter tables. Core fields include insulation structure parameters, lead connection positions, partial discharge values, withstand voltage thresholds, and rated voltage. Units include kV, pC, m, and others. Documents for single products require full traceability. Data update frequency is higher than that of batch production categories.

## What constraints do these characteristics impose on HTTP interfaces and external systems?
The data characteristics of this category impose multiple constraints on HTTP interface and external system configuration. The requirement for full-process traceability of single products requires interfaces to support precise query by unique device ID, to avoid cross-device data confusion. High-frequency updated single product and batch data requires interfaces to support real-time pulling, and long cache cycles should not be used. The requirement for unit consistency across multiple types of documents and core fields requires interfaces to complete format and unit verification during data pulling, to prevent parameter confusion. In addition, the high-risk consequences of errors such as insulation breakdown and grid fault require interfaces to be configured with strict permission verification rules, only allowing authorized accounts to access sensitive process and test data.

## Three common configuration errors
- Phenomenon: The partial discharge value field returned by the interface is empty. Cause: The correct test station device ID was not specified in `variables`, resulting in failure to match corresponding test data.
- Phenomenon: Interface request times out, returning status code 504. Cause: A reasonable timeout threshold was not adjusted. The test report data volume of this category is large, exceeding the default interface response duration.
- Phenomenon: The insulation parameter units returned by Q&A are mixed, including both kV and V. Cause: No unit unified verification rule was configured in `responseData`, and the units of multi-source data pulled were not aligned.

## How to verify the configuration is correct
- Initiate an interface request with a valid device ID, check whether the returned fields include preset insulation parameters and test results.
- Simulate an unauthorized request, confirm that the corresponding permission error status code is returned, verifying that the `Authorization` configuration takes effect.
- Adjust the test type parameter in `variables`, confirm that the returned results change dynamically with the filter conditions.
- Check the interface response duration, adjust the timeout threshold to a range that meets business requirements.
