# Process Specification and Technical Standard Q&A for Transformer and High-Voltage Electrical Equipment Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
The data for this category comes from design BOM, silicon steel sheet and insulating material procurement data, vacuum drying equipment operation logs, oil test reports, partial discharge and withstand voltage test records from the test station, and product nameplate parameter tables. Data updates synchronize with the completion of each finished product and each batch of raw materials. Daily documents include winding and core assembly records, vacuum drying process records, insulating oil performance reports, partial discharge and withstand voltage test reports, and product nameplate parameter tables. Core fields include insulation distance, water content, and test voltage value. Products are tracked for their full life cycle on a per-unit basis.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
The per-unit tracking requirement mandates that dialogues be bound to `chatId` to retain exclusive context for each product. Pass historical interaction content via the `messages` parameter to ensure coherent context. Frequent queries of test reports and insulation parameters require prompts to explicitly limit calls to process documents for transformer and high-voltage electrical equipment manufacturing, preventing inclusion of process content from unrelated categories. The update frequency of each unit or batch requires that dialogues trigger real-time knowledge base retrieval, ensuring returned test data is the latest for the current batch. Complex partial discharge anomaly analysis requires multi-turn dialogue to gradually decompose parameters. Prompts must guide engineers to supplement specific test point and voltage level information, avoiding vague responses.

## Three Common Misconfigurations
- The symptom is that after migrating the knowledge base, the dialogue interface prompts that the knowledge base is empty, but all document content can be viewed on the knowledge base management page. The cause is that the knowledge base association configuration bound to the dialogue was not synchronized for update, or the dialogue context cache retains old knowledge base association information.
- The symptom is an error occurs after the number of concurrent multi-turn dialogue requests exceeds the expected limit in FastGPT v4.9.14. The cause is that a reasonable concurrent upper limit threshold was not configured for this version, and the number of dialogue concurrency per node was not restricted.
- The symptom is a significant difference in returned results when stream is set to false versus true. The cause is that the prompt did not explicitly limit the return format and content scope, causing inconsistent retrieval logic triggered by different streaming configurations.

## How to Verify Correct Configuration
- Initiate a process query for a single product, check whether the returned documents include the insulating oil report and withstand voltage test records corresponding to that product.
- Switch between stream and non-stream modes, verify that the result range and format returned twice are consistent.
- View the `chatId` parameter of the dialogue, confirm that dialogue sessions for each product are independent and there is no context mixing.
