# Process Specification and Technical Standard Q&A for Transformer and High-Voltage Electrical Equipment Manufacturing: Model Access and Configuration

## What this category of data includes
The core data for transformer and high-voltage electrical equipment manufacturing comes from design BOM, silicon steel sheet and insulating material ledgers, vacuum drying equipment operation logs, insulating oil test reports, high-voltage test station records, and single-unit product nameplate parameter tables. Daily documents include winding and core assembly records, vacuum drying process records, insulating oil test reports, partial discharge and withstand voltage test reports, and product nameplate parameter tables. Data is updated per individual product or raw material batch. Full traceability is required for all records of insulation structure, cleanliness, lead connection and other links for each single product.

## What constraints these characteristics impose on model access and configuration
Full traceability data for single products requires the model to associate multi-source heterogeneous documents. The total context length must be limited to avoid exceeding the model's capacity limit. The update frequency per product or batch requires configuration to support incremental data synchronization. This avoids repeated loading of full historical data and reduces resource usage. Professional fields such as insulating oil and partial discharge tests have specific units and numerical precision requirements. The model must accurately recognize professional terms and numerical ranges, so appropriate context matching rules need to be configured. The scenario of high-voltage test abnormality analysis requires tool calls to quickly associate test report data. The priority and association scope of tool triggers must be clearly defined.

## Three common configuration mistakes
- Phenomenon: When creating a new AI conversation, the default model for tool calls does not appear in the optional list, or a model call failure prompt is returned after the conversation is initiated. Cause: The correct model deployment node is not configured in `AIPROXY_API_ENDPOINT`, so the platform cannot pull the available model list.
- Phenomenon: Search works normally in the knowledge base, but the reranking model cannot be called when initiating an AI conversation, and empty association results are returned. Cause: The `AIPROXY_API_TOKEN` of the reranking model is not bound in the model access configuration, or the deployment node of the reranking model is not correctly associated with the current workspace.
- Phenomenon: When deploying a 16b model using 4070ti, the response time of a single process Q&A exceeds 5 minutes, and the video memory usage remains high. Cause: The `maxContext` configuration value is too large, exceeding the video memory limit of the deployed hardware, leading to excessive time for the model to load the context.

## How to confirm successful configuration
- View the connected model list on the platform's model management page, and confirm that the target model and version are displayed normally.
- Initiate a test conversation containing a query on insulating oil density or withstand voltage value, and verify that the tool call can correctly associate and return the corresponding data in the test report.
- Enter a query for partial discharge abnormality analysis, and check whether the content returned by the model includes compliant process specification references.
- View the model call log, and confirm that configuration parameters such as `maxContext` and `temperature` have taken effect according to the set values.
