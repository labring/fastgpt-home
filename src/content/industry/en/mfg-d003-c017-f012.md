# Q&A for Coating and Painting Process Procedures and Technical Standards: Deployment and Upgrade

## What the data for this category looks like
Business data for coating and painting scenarios includes documents such as coating process cards, paint batch sheets, paint mixing records, film thickness and color difference reports, oven curves, defect repair orders, and VOCs ledgers. Data sources include TDS/SDS documents from paint suppliers, real-time collected data from spray booths and ovens, test results from colorimeters and film thickness gauges, environmental monitoring data, and MES system work orders. Data update cadence is as follows: batch sheets are updated per paint batch, paint mixing and process execution records are updated per shift, and oven and environmental monitoring data are collected continuously. Document fields include professional parameters such as spraying temperature (unit: ℃), curing time (unit: minutes), paint viscosity (unit: seconds, Ford cup 4), film thickness (unit: μm), and VOCs concentration (unit: mg/m³).

## What constraints these characteristics impose on the deployment and upgrade phase
Data for this scenario is multi-source and has highly variable update frequencies. During deployment, support for multiple formats including PDF process cards, CSV test reports, and JSON real-time data must be provided, so storage configuration must support uploading and indexing multiple types of files. High-frequency continuous collection of oven and environmental data requires the vector database to support incremental updates to avoid performance loss caused by full synchronization. The presence of professional fields and units requires that knowledge base chunks retain complete parameter information without arbitrary content truncation. At the same time, incorrect coating processes can lead to batch repairs or compliance risks, so the deployment and upgrade phase must ensure service stability and avoid reduced retrieval accuracy caused by configuration changes.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `STORAGE_S3_ENDPOINT` | Consistent with the intranet access address of the enterprise object storage service | Most process documents and test reports for coating scenarios are large files; intranet access reduces pull latency |
| `MONGODB_URI` | Configured as the replica set address for storing process documents and vector data | High-frequency read/write test data and retrieval records require highly available storage to ensure business continuity |
| `REDIS_URL` | Address of an instance allocated with 2000 MB or more of memory | Cache frequently retrieved process parameters and paint mixing records to reduce database load |
| Single search limit | Top 8 entries | Coating process matching needs to cover pre-treatment, spraying, and curing stages; limited candidate results improve retrieval accuracy |
| Maximum context length | 800–1200 characters | Adapts to the length of single-segment professional content on coating process cards, avoiding truncation of critical parameters |
| Question optimization switch | Enabled | Maps colloquial questions from on-site operators to standard process parameters, improving retrieval matching accuracy |

## Three common misconfigurations
- Symptom: Image pull failure, with interface prompts of pull timeout or status code 504. Cause: Enterprise intranet image acceleration address is not configured; public network pull is limited by egress bandwidth and access policies.
- Symptom: After upgrading to FastGPT v4.8.14-fix, voice playback function malfunctions, while voice recognition function operates normally. Cause: The image version required by the voice service dependency in the upgrade package was not updated synchronously, and is incompatible with the base components of the existing deployment environment.
- Symptom: Knowledge base question answering can only use the GPT-3.5 model, and cannot switch to other available models. Cause: Environment variables for model services were not configured correctly; only the default GPT-3.5 interface is exposed, and access configurations for other models were not added.

## How to confirm configuration is correct
- Execute the `docker ps` command to confirm that all configured service containers for FastGPT v4.17.0 are in running state.
- Upload a coating process card PDF document to the knowledge base, retrieve questions containing professional parameters, and verify that returned results include complete parameters and their corresponding units from the document.
- Trigger an incremental synchronization task, and confirm that newly uploaded paint mixing records can be retrieved within the time frame consistent with the business update cadence.
- Access the domain configured via `FE_DOMAIN`, and verify that the knowledge base configuration page loads normally and can save modified parameters.
