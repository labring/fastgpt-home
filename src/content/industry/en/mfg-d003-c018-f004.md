# Process Specification and Technical Standard Q&A for Basic Chemical Continuous Production: Workflow Orchestration

## What Data for This Category Looks Like
This category of data covers scenarios including chlor-alkali and synthetic ammonia basic chemical continuous production. Daily documents include operation procedures, process index cards, DCS trends, laboratory reports, interlock bypass records, special work permits, and shift reports. Data sources include DCS/SIS systems, online analyzers, LIMS systems, equipment condition monitoring modules, energy metering devices, and raw material storage tank data platforms. Update frequencies are split into real-time (such as DCS trends), per shift (such as shift reports), and daily (such as laboratory reports). Document fields include process parameter values, interlock logic, work approval status, and metering data, with common industry units attached.

## Constraints on Workflow Orchestration
The multi-source, multi-update-frequency, and multi-document-type nature of this category’s data creates multiple constraints for workflow orchestration. First, real-time data such as DCS trends must be prioritized in workflow calls. Trigger conditions must be configured to match real-time data update nodes. Second, different document types require corresponding retrieval rules. Structured process parameters need precise field matching, while unstructured special work permits rely on semantic recall. Additionally, data volume grows with production scale. The number of returned entries per single retrieval must be limited to avoid exceeding the input limit of AI dialogue nodes. Finally, critical data such as interlock bypass records requires separate permission checks to prevent unauthorized content from entering the Q&A process.

## Configuration Settings
Configuration settings are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context | 8000–12000 characters | Matches the single-section content length of basic chemical process specifications and index cards, avoids exceeding the input limit of AI dialogue nodes |
| Single Search Limit | Top 6 entries | Controls the total length of retrieval results, adapts to the scale of basic chemical continuous production data |
| Variable Reference | Bind device number via the `variables` parameter | Accurately matches exclusive process documents for the corresponding production device |
| Node Trigger Condition | Bind real-time data nodes via the `nodeId` parameter | Ensures real-time data from DCS/SIS systems triggers corresponding knowledge base calls |
| Result Verification Threshold | 0.85–0.90 | Filters low-match irrelevant documents, ensures accuracy of process data |
| Node Timeout | 600 seconds | Adapts to retrieval response requirements for basic chemical real-time data |

## Three Common Configuration Mistakes
- Phenomenon: The interface returns an "input context too long" error, and the dialogue node has no valid reply content. Cause: No maximum context limit is configured, and the total length of documents returned by a single retrieval exceeds the input limit of the AI model.
- Phenomenon: Knowledge base search results match process specifications or index cards from unrelated production devices. Cause: No device number variable for the corresponding device is bound via the `variables` parameter, resulting in retrieval scope covering all documents.
- Phenomenon: No submit button appears in workflow sessions, and subsequent workflow nodes cannot be triggered. Cause: No user interaction node is configured in the workflow, and no `nodeId` binding logic for button triggering is set.

## How to Confirm Correct Configuration
- Upload a single process index card for the corresponding production device, trigger the workflow, and check if retrieval results only match exclusive documents for that device.
- Simulate an input that exceeds the preset maximum context length, check if the workflow intercepts the over-limit request and returns a clear prompt.
- Insert a user interaction node into the workflow, confirm that a submit button appears in the session, and that clicking it triggers subsequent workflow steps.
- Trigger a simulated real-time DCS data update, check if the workflow automatically calls the retrieval process for the corresponding knowledge base.

The values provided are common starting points and should be measured against the reader's own samples.
