# Q&A for Process Procedures and Technical Standards in Basic Chemical Continuous Production: Knowledge Base Retrieval and Recall

## What this category of data looks like
Data sources cover DCS/SIS control systems, online process analyzers, LIMS laboratory management systems, equipment condition monitoring tools, energy metering systems, and raw material tank data. Daily documents include operating procedures, process index cards, DCS trend charts, laboratory reports, interlock bypass records, special work permits, and shift daily reports.
Data updates occur in real time, per shift, and daily. Documents include clear process parameter fields and units. Examples include standard ranges for temperature, pressure, and flow, plus interlock action trigger thresholds.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
The combination of multi-source real-time data and multi-type documents requires the retrieval and recall pipeline to support cross-data-source content aggregation. It must also adapt to mixed retrieval of structured process parameters and unstructured operation records.
Frequently updated real-time data, such as DCS trends, requires the retrieval pipeline to support short-cycle data synchronization. This avoids delayed recall results.
The strong interlock control business characteristic requires recall results to accurately match key thresholds and disposal processes. This prevents missing high-risk operation guidance.
Differences in fields across documents require configuring chunking and indexing rules for multi-format content. This ensures accurate recall of process indicators and work permit content.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the precision requirements for basic chemical process parameters, and avoids recalling irrelevant historical operation records |
| `limit` | Top 8 entries | Covers process indicators, interlock rules, and operational requirements involved in a single shift operation, and avoids excessive context load |
| `searchMode` | `mixedRecall` | Adapts to mixed content of structured parameters and unstructured work permits, balancing precision and recall scope |
| `usingReRank` | Enabled | Performs secondary sorting on recall results, prioritizing high-priority interlock disposal and process procedure content |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands process-related keywords based on user questions, adapting to scenario-based retrieval needs |
| `collectionIds` | Bound by business domain | Only retrieves process procedures and interlock data for the corresponding production unit, narrowing the recall scope to improve efficiency |

*This configuration is based on FastGPT v4.17.0*

## Three common misconfigurations
- Symptom: A 413 status code error for parameter limit exceeded is returned when calling the `pushData` interface. Cause: Batched pushes do not follow the maximum limit of 200 data groups per batch. The number of data groups pushed in a single operation exceeds this upper limit.
- Symptom: The knowledge base cannot parse intranet Confluence page content, and retrieval returns no results. Cause: Access permissions and parsing adaptation rules for intranet data sources are not configured. Only publicly accessible external web links are supported.
- Symptom: No matching retrieval results appear after uploading a DOC format document. Cause: The parsing plugin for DOC format documents is not configured, or DOC content is not correctly imported into the knowledge base dataset.

## How to confirm configurations are correct
- Initiate a retrieval for core process parameters. Verify that the `similarity` scores of returned results fall within the preset range. Confirm retrieval relevance meets requirements.
- Check the number of retrieval results. Confirm the returned count does not exceed the configured `limit` value. Confirm results cover content from the target business domain.
- Test the import and retrieval process for intranet data sources and DOC format documents. Confirm parsing and recall work normally.
- Trigger the re-ranking function. Confirm content related to high-risk interlocks is displayed first. Verify the sorting logic takes effect.
