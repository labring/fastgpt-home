# Process Specification and Technical Standard Q&A for Safety, Environmental Protection and Special Operation Management: Workflow Orchestration

## What data for this category includes
This category covers risk identification records, work permits for hot work, confined space work, lifting work and similar operations, monitoring records, hazardous waste ledgers, emission monitoring data, and accident and hidden danger rectification reports.
Data sources include regulatory standard documents, online environmental monitoring equipment, gas detectors, personnel qualification files, equipment isolation lists, and supervision platform data.
Data updates occur upon completion of individual operations, per monitoring cycles, or during regular inspections.
A single work permit includes fields such as work type, guardian qualification information, and gas detection parameters. The hazardous waste ledger records hazardous waste categories and disposal-related information.

## What constraints these characteristics impose on workflow orchestration
Data sources are scattered, and update nodes are not unified. Workflows must support synchronous pulling of multi-source data and format adaptation.
Documents such as work permits and monitoring records have widely varying structures. Workflows must pre-set parsing rules for multiple document types, and adapt field extraction logic for different work types.
Data update frequencies range from real-time to scheduled. Workflows must be configured with both on-demand and scheduled trigger modes to ensure the latest data is included in the Q&A context.
Work-related data is tied to personal and environmental safety. Workflows must strictly verify data integrity to prevent Q&A failures caused by missing key information such as qualifications and detection values.

## Configuration settings
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| `variables` | Define numeric counters and work identification variables. Set the initial counter value to 0 | Used to track the number of workflow node executions for work orders, meeting the closed-loop traceability requirements of safe operations |
| `nodeId` | Assign unique identifiers to multi-source data pulling nodes, and configure them grouped by work type | Distinguish data sources for different work scenarios such as hot work and confined space work, and avoid node call conflicts |
| Global variable update rules | Only trigger the counter increment operation after the AI generates a valid response | Ensure the counter is updated only after compliant Q&A, meeting traceability requirements for safe operations |
| Debug display configuration | Enable the debug panel for code execution nodes | Adapt to interface adjustments in FastGPT v4.17.0, and facilitate troubleshooting of workflow exceptions |
| Context length setting | 800–1200 characters | Match the typical single-paragraph text length of documents such as work permits and monitoring records, and avoid context overflow |
| Workflow import validation | Enable field consistency validation | Prevent field mismatch issues when importing external workflows, and ensure normal process operation |

## Three common misconfigurations
- Symptom: The global Number type counter fails to automatically increment after an AI response, and the value does not change after the variable update plugin is executed. Cause: The rule to trigger variable updates only after a valid response is not configured, causing the plugin to incorrectly update variables during invalid workflow node execution.
- Symptom: In FastGPT v4.17.0, the workflow orchestration debug panel does not display code execution nodes. Cause: The code execution node switch in the debug display configuration is not enabled, causing node debug information to be hidden.
- Symptom: After importing an external workflow configuration, the process can output normally but intermediate results do not meet expectations. Cause: The workflow import validation function is not enabled, causing the imported configuration's field mapping relationship to mismatch the current environment, leading to data reading exceptions.

## How to confirm the configuration is properly set
- Manually trigger workflow execution, and check if the counter defined by `variables` increments as expected after a valid response.
- Enter the workflow debug panel, and confirm that debug information for code execution nodes is displayed normally.
- Import an external workflow configuration, run the validation tool to confirm there are no field matching exceptions, then execute the workflow.
- Adjust the context length parameter, and check if the intercepted length of the Q&A context falls within the preset configuration range.
