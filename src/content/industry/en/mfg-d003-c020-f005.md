# Process Specification and Technical Standard Q&A for Safety, Environmental Protection and Special Operation Management: Tool Calling and Plugins

## What this category of data looks like
Data for this category comes from daily operational documents of EHS departments and production maintenance teams in manufacturing enterprises such as chemical, metallurgical, machinery, and light industry. The documents include risk identification records, work permits for hot work, confined space operations, lifting operations and other tasks, environmental monitoring records, hazardous waste ledgers, emission monitoring data, and accident and hidden danger rectification reports.
Data sources cover statutory compliance standards, online environmental monitoring equipment, gas detectors, operator qualification files, equipment isolation lists, and local supervision platforms.
Data updates follow the completion of individual operations, real-time monitoring requirements, or regular inspection schedules.

## What constraints do these characteristics impose on the "tool calling and plugins" workflow
The multi-source and heterogeneous characteristics of data in this category require tool calling to adapt to different data formats of structured work permits, qualification files, and unstructured monitoring reports. Corresponding calling rules for each data source must be configured separately.
Frequently updated operational data requires tool calling to set a reasonable cache duration, to avoid using expired work permits or monitoring results.
Risk identification and qualification verification before operations require precise matching of specific fields. Tool calling must support filtering results based on conditions such as operation type and operator qualification validity period.
The severe consequences of errors require tool calling to be configured with clear fallback and alert mechanisms for failures, to ensure operational safety in abnormal scenarios.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` or the tool corresponding to the specified operation type | Adapt to tool calling requirements in different operation scenarios, ensure accurate triggering of corresponding compliance checks or data queries, and comply with the tool calling logic of FastGPT v4.17.0 |
| Tool calling timeout | `60–120 seconds` | Data in this category mostly comes from real-time monitoring or online supervision platforms, and calls must be completed within the time limit of the operation workflow |
| `functionCall` parameter validation | Enable required field validation | Scenarios such as work permits and qualification verification require strict matching of required items such as operation type and operator qualification number, to avoid invalid calls |
| Plugin data source binding rules | Bind the compliance standard library and real-time monitoring interface corresponding to the operation type | Data in this category is stored classified by operation type, and must be accurately associated with the corresponding data source |
| Number of results returned per call | `Top 3–5 entries` | Core compliance basis or monitoring results must be obtained quickly, to avoid excessive information interfering with operation judgment |
| Number of failure retries | `2 times` | Balance call success rate and operation workflow time, to avoid delaying operations due to temporary network delays |

## Three common mistakes
- Symptom: After importing a workflow from another environment, plugin calls prompt that the corresponding plugin cannot be found. Cause: When exporting the workflow, only the workflow JSON configuration was saved, and the data source permissions and instance information of the bound plugin were not synchronized, so the new environment cannot recognize the associated plugin.
- Symptom: Unparsed Human <Instruction> tags appear in tool calling logs, and the specified tool cannot be triggered. Cause: Uncleaned system prompt tags remain in the conversation context, interfering with the parsing of tool calling instruction formats.
- Symptom: Missing parameter errors occur when using the query tool, and compliance data for the corresponding operation cannot be obtained. Cause: `functionCall` parameter validation is not enabled, and required fields such as operation type and operator qualification number are not mandatory for input, resulting in incomplete call parameters.

## How to confirm the configuration is complete
- Manually trigger tool calling for the corresponding operation type, check whether matching compliance standards, monitoring data, or qualification verification results are returned.
- Export the current workflow and import it to a test environment, verify that there are no missing prompts for plugin data source binding configurations.
- Simulate an interface delay scenario, check whether tool calling completes within the configured timeout period or triggers the retry mechanism.
- Verify that the parameters of tool calling include required fields, and ensure there are no null or invalid parameters.
