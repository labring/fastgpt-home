# Furniture and Wood Products Manufacturing: Process Specification and Technical Standard Q&A — Document Parsing and Chunking

## What this category of data looks like
Daily documents for furniture and wood products manufacturing include order breakdown drawings, cutting lists, edge banding and drilling programs, coating processes, hardware parts lists, trial assembly and packaging records. Data comes from order design systems, sheet and lumber batch records, CNC cutting and drilling equipment, ERP/MES systems, and moisture content testing equipment. Update frequencies are adjusted per order, daily, or per material batch. Each document includes structured fields such as panel dimensions, sheet parameters, process steps, and hardware model numbers. Some documents also include CNC code and chart information.

## What constraints these characteristics impose on the document parsing and chunking stage
The custom order-driven business model leads to significant individual differences between each document. Chunking must retain the associated logic between panels and their corresponding processes, to avoid splitting that breaks business context. Documents contain precise fields such as CNC code and dimensional values, so parsing must preserve the semantic integrity of these fields to prevent loss of critical information. Documents from multiple systems have inconsistent formats, so parsing must adapt to content with different structures. Frequently updated business data requires the parsing process to have sufficient response speed, to avoid delays that impact production links. A single document may contain a large number of panels and have lengthy content, so chunk size must be controlled reasonably to prevent too many chunks or overloaded single chunks.

## How to set the configuration
This page is written based on FastGPT v4.17.0 configuration rules. The specific configurations are as follows:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Furniture documents include associated content such as panel dimensions and process steps. This range preserves business association logic within a single chunk, avoiding splits that break the correspondence between processes and panels |
| `chunkSplitter` | By paragraph + semantic boundary | Furniture documents have independent process paragraphs such as coating and edge banding. Splitting by semantic boundaries preserves the integrity of process descriptions, preventing cross-paragraph process information from being fragmented |
| `customPdfParse` | Enable structured parsing | Furniture documents include content with tables and fields such as order breakdown drawings and cutting lists. Enabling this setting extracts structured fields such as panel numbers and dimensions, improving question-and-answer matching accuracy |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 seconds | A single cutting list or order breakdown drawing may contain a large amount of panel data. Reserving sufficient time for parsing and chunking prevents task failure due to timeout |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Large order breakdown drawings or multi-batch sheet record documents have large file sizes. This configuration allows uploading documents matching business scale, preventing upload interception |
| `chunkSettingMode` | Manual configuration | Custom furniture order documents have large individual differences. Manual configuration allows adjusting chunking rules for different types of documents such as breakdown drawings and process files, adapting to diverse document formats |

## Three common mistakes
- When enabling `customPdfParse`, failing to configure MinerU API related parameters causes parsing tasks to fail. Cause: The third-party parsing service is not bound as required by the documentation, preventing structured parsing from triggering normally.
- When a conditional judgment component processes boolean data obtained from parsing, the field becomes empty. Cause: The type information of the original boolean field was not retained during parsing, or the field content was accidentally truncated during chunking, leading to information loss.
- An error "Cannot redefine property: toString" occurs after uploading a large cutting list. Cause: An illegal property redefinition operation was performed on an overly large text block during parsing, exceeding runtime limits.

## How to confirm the configuration is correct
- Upload a single typical furniture process document, view the parsed chunk list, and confirm that each chunk contains complete process steps or panel information, with no obvious content fragmentation.
- Trigger a parsing task, check the background logs, and confirm that the `PARSE_FILE_TIMEOUT_SECONDS` configuration does not trigger timeout errors.
- Extract the parsed structured fields, and verify whether key information such as panel numbers and dimensions has been correctly extracted and retained.
- Upload a large document estimated to have more than 3000 chunks, check whether the corresponding prompt is triggered, and confirm that the chunking rules adapt to the document scale.
