# Q&A for Process Specifications and Technical Standards for Complete Home Appliance Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
This category covers the entire production process for air conditioners, refrigerators, washing machines, and small home appliances. Daily documentation includes bill of materials (BOM) configurations, assembly work instructions, refrigerant charging records, electrical safety test reports, performance sampling inspection reports, and rework records. Data comes from ERP/MES systems, component batch ledgers, tightening and charging equipment, safety compliance testers, performance laboratory data, and after-sales fault records. Updates run per individual product unit, per shift production batch, or per sampling inspection plan. Document fields include component model numbers, process parameters, test results, batch numbers, and compliance identifiers.

## Constraints Imposed by These Characteristics for Multi-turn Dialogue and Prompt Engineering
Mixed-model mixed-line assembly scenarios require dialogue to accurately distinguish process parameters for different models, and limit context association scope to avoid cross-model confusion. Data updated per unit or batch requires dialogue to bind records for specific batches, and support filtering associated documents by batch ID. Compliance-focused documents such as safety and energy efficiency records require strict matching of content for the relevant process link. Prompts must explicitly limit retrieval scope to assembly and test data for the target model. For tightening and charging process queries with high real-time requirements, ensure dialogue context update delays align with production beat. Retain context for key process nodes via the `messages` parameter to avoid interference from redundant data.

## Three Common Configuration Errors
- Symptom: Single dialogue response time exceeds 10 seconds, and the interface displays a loading timeout prompt. Cause: Retrieval result count is not limited, leading to excessive safety compliance and performance test documents loading and slowing response.
- Symptom: Previous dialogue flow cannot be resumed across sessions, and historical dialogue content is lost. Cause: `chatId` for session binding is not configured correctly, or session persistence settings are not enabled.
- Symptom: Dialogue logs cannot be automatically cleaned up within the specified period, occupying storage space. Cause: Session retention duration parameter is not configured correctly, or the update rule for the corresponding storage path is not associated.

## How to Verify Correct Configuration
- Initiate a query targeting the assembly process of a specific model, and confirm the response only includes assembly work instructions and BOM data for that model.
- Initiate multi-turn progressive queries to verify the dialogue context retains model and batch information from prior questions.
- View the session management interface to confirm log retention period matches the preset configuration.
- Simulate rapid on-site production queries to check if response times align with acceptable on-site operation ranges.

The values provided are common starting points and should be measured against the reader's own samples.
