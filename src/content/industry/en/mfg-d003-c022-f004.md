# Q&A for Process Specifications and Technical Standards for Complete Household Appliance Manufacturing: Workflow Orchestration

## What data looks like for this category
Daily documents for this category include configuration BOM, assembly work instructions, refrigerant charging records, electrical safety test reports, performance sampling inspection reports, and rework records. Data comes from ERP/MES systems, component batch ledgers, tightening and charging equipment, safety compliance testers, performance laboratory data, and after-sales fault databases. Updates are performed per single product, per shift production batch, and per sampling inspection plan. Document fields include component batch number, process parameter values, test results, rework reasons, and other relevant information.

## What constraints do these characteristics impose on workflow orchestration
Multiple heterogeneous data sources require the workflow to configure multiple data access nodes to pull documents from different systems and equipment separately. High update frequency requires that document synchronization nodes in the workflow be triggered according to production shifts or sampling inspection plans, to ensure retrieved process documents use the latest versions. The mixed-line assembly production mode requires the workflow to dynamically filter process documents for the corresponding model using bound parameters, to avoid misassembly. Strict compliance requirements require the workflow to add a verification link for retrieval results, to prevent invocation of risk parameters such as electric leakage and refrigerant leakage.

## How to set up the configuration

| `variables` | Bind two global variables: product model and component batch | Adapt to mixed-line assembly scenarios, dynamically match process specifications and standard documents for the corresponding model |
| Data source synchronization trigger rule | Trigger according to production shifts and sampling inspection plan nodes | Match the update rhythm of data per shift and sampling inspection plan |
| Knowledge base retrieval scope | Limit to the process document subset for the current model | Avoid calling incorrect documents during mixed-line production of multiple models |
| Code running node timeout setting | 600 seconds | Cover the time required for equipment data pulling and document parsing |
| Single knowledge base retrieval limit | Top 10 results | Balance retrieval efficiency and document coverage |
| `nodeId` | Bind the return result of the safety compliance verification node | Ensure retrieval results meet electrical safety requirements before proceeding to the next link |

## Three common misconfigurations
- Phenomenon: The code running node shows execution success but does not return expected process parameter verification results, or throws an execution error. Cause: The code logic was not adjusted for fields such as component batch and torque parameters for this category, resulting in failure to correctly read the `variables` data passed into the workflow.
- Phenomenon: No optional values appear in the variable dropdown menu of the knowledge base retrieval node, or global variables cannot be referenced in node configuration. Cause: Global variables were not registered on the workflow management page, or the target variable was not bound to the `variables` parameter of the current workflow.
- Phenomenon: The workflow's external service call node is unresponsive, and external MCP plugins cannot be called to complete process compliance verification. Cause: Interface parameters of the external service were not mapped to fields such as safety compliance testing and performance sampling inspection for this category, resulting in mismatched parameter passing.

## How to confirm the configuration is complete
- Trigger a simulated production process, pass in test product model and batch number, check whether the workflow automatically matches the process documents for the corresponding model.
- View the logs of the data source synchronization node, confirm whether document updates were completed according to the preset shift or sampling inspection plan.
- Call the code running node, pass in preset process parameters, check whether verification results meeting the requirements of this category are returned.
- Check the global variable reference configuration, confirm that all parameters that need to be passed have been bound to the `variables` parameter and can be called in each node.
