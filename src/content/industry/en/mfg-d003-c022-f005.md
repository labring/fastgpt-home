# Q&A for Process Specifications and Technical Standards for Complete Home Appliance Manufacturing: Tool Calling and Plugins

## What the Data for This Category Entails
Core data revolves around the end-to-end production process of complete home appliances. This includes bill of materials (BOM) configurations, assembly work instructions, refrigerant charging records, electrical safety test reports, performance sampling inspection reports, and rework records.
Data sources cover ERP/MES systems, component batch ledgers, tightening and charging equipment logs, safety compliance tester data, performance laboratory test results, and after-sales fault databases.
Data update cycles follow individual product units, shift production batches, and sampling inspection schedules.
Individual records include fields such as component model, process parameters, test results, and rework status. Some records include physical quantity units such as pressure values and torque values.

## What Constraints These Characteristics Impose on Tool Calling and Plugin Workflows
Most data for this category consists of structured process records and structured test reports, with high update frequencies. Individual records link to specific production batches, so tool calling must accurately match batch information and process standards.
In mixed-line assembly scenarios, assembly work instructions for different appliance models must be quickly distinguished. Tool calling must support filtering and retrieving documents by product model.
Safety compliance test and performance data directly link to compliance requirements. Tool calling must prioritize retrieving the latest versions of technical standard documents.
After-sales rework data must link to corresponding production batches. Tool calling must support cross-data-source associated queries to avoid data disconnection across production links.
Process records for individual products must be cross-verified with sampling inspection reports. The retrieval scope of tool calling must cover end-to-end production process data.

## How to Configure the Setup
This guide is written for FastGPT v4.17.0. The following are tool calling configuration recommendations for this category:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to dynamic tool calling requirements for process specification Q&A, no manual function type specification needed |
| Maximum number of retrieved documents per call | Top 8 entries | Home appliance production documents are moderately lengthy per piece; 8 entries cover the complete process and test requirements for a single product |
| `functionCall` | `enabled` | Supports calling document parsing tools to extract structured content such as charging records and safety compliance test data |
| Tool calling timeout period | 300 seconds | Queries across ERP and laboratory data sources require sufficient time to avoid timeouts due to large data volumes |
| Document retrieval similarity threshold | 0.75-0.85 | Balances matching accuracy between process standards and production records, avoids incorrectly retrieving documents for non-matching product models |

## Three Common Misconfigurations
- Symptom: Slow response speed when calling the document parsing interface. Cause: No reasonable document retrieval filtering rules are configured, or no limit is set on the number of retrieved documents per call, resulting in excessive data to parse.
- Symptom: Connection failure occurs when calling a locally deployed large model in a Linux deployment environment. Cause: The listening port of the local model is not opened, or the FastGPT container network is not in the same network segment as the local model network.
- Symptom: Tool calling fails to trigger the document parsing function after upgrading the version. Cause: Automatic triggering rules for tool calling are not enabled in system settings, or the model configuration is not adapted to the function calling logic of the new version.

## How to Confirm Successful Configuration
- Initiate a process specification Q&A for a single home appliance, check whether the tool calling automatically triggers the document parsing operation.
- View the tool calling log, confirm that all retrieved documents are data such as assembly work instructions and test reports for the corresponding product model.
- Initiate a Q&A that includes safety compliance test parameters, check whether the tool can correctly extract numerical content for the corresponding fields.
- Test cross-data-source queries, confirm that the tool can simultaneously link BOM data from ERP and after-sales rework records.

The values provided are common starting points and should be measured against the reader's own samples.
