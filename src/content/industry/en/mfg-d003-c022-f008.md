# Process Specification and Technical Standard Q&A for Complete Home Appliance Manufacturing: Document Parsing and Chunking

## What This Category’s Data Looks Like
Data sources for this category include ERP/MES systems, component batch ledgers, tightening and refrigerant charging equipment logs, safety tester data, performance laboratory reports, and after-sales fault records. Daily documents cover configuration BOMs, assembly work instructions, refrigerant charging records, electrical safety test reports, random performance inspection reports, and rework records. Data is updated at the individual product level, shift output level, or according to random inspection plans. Document fields include component numbers, process parameter values, test results, batch information, and more. Some parameters have dedicated units.

## What Constraints These Characteristics Impose on the "Document Parsing and Chunking" Link
Multi-source heterogeneous document formats and field structures require the parsing module to support mixed formats including PDF, CSV, and Excel, to avoid field misalignment. Frequently updated individual product or shift-level data requires retaining batch and individual product association information during chunking, to prevent cross-batch content confusion. Process parameters with dedicated units require retaining the association between parameters and units during chunking, to avoid errors where parameters and units are separated during process Q&A. Document features for mixed-model line assembly require splitting chunks by product model and process segment, to prevent mixing of process specifications for different models. High-risk safety and performance test documents require retaining complete test items and results during parsing, to avoid loss of critical information.

## How to Set Configurations
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Matches the length of single process steps or test items in assembly work instructions and test reports, to avoid splitting critical process steps |
| `chunkSplitter` | Split by paragraph + heading | Matches the heading structure of assembly processes and test items in documents, to retain process logical associations |
| `customPdfParse` | Enable structured parsing | Adapts to multi-format mixed safety and performance test PDF documents, extracting table and field information |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Covers parsing time for large-capacity random inspection reports and rework records, to avoid timeout interruptions |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Adapts to batch upload requirements for multiple documents per batch, meeting parsing needs for shift output-level data |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules for this category's dedicated document structures, adapting to differences in multi-model documents for mixed-line assembly |

## Three Common Errors
- Symptom: Calling the FastGPT file parsing API shows a successful call, but the returned result is empty or contains no valid parsed content. Cause: The structured parsing switch for `customPdfParse` was not correctly enabled, resulting in incomplete text extraction from unstructured PDF documents.
- Symptom: Logs prompt split-related errors, and the file parsing process is interrupted. Cause: The `chunkSize` value exceeds the maximum length of a single document segment, or the split rule configured for `chunkSplitter` does not match the document structure, causing exceptions during chunking.
- Symptom: After batch uploading multiple documents, only some files generate parsed results. Cause: The `UPLOAD_FILE_MAX_SIZE` configuration value is too small, exceeding the total upload capacity limit per batch, resulting in some files failing to complete parsing.

## How to Confirm the Configuration Is Correct
- Upload a typical document for this category, such as an assembly work instruction, and confirm the parsed text fully extracts process steps, parameters, and unit information.
- Call the file parsing API, and confirm the returned result contains complete parsed text and chunk data, with no null values or truncation.
- Adjust chunking-related configurations, and compare chunking results for documents of different product models to confirm the chunking logic matches the process structure of the corresponding product.
- Upload a large-capacity random inspection report document, and confirm the parsing process does not experience timeout interruptions, aligning with the preset timeout configuration.
