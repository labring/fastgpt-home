# Process Specification and Technical Standard Q&A for Industrial Instrument Manufacturing and Calibration: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
Data for this category comes from design documents, standard instruments, environmental monitoring data, calibration software, laboratory information systems, and customer range requirements. Daily documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version logs. Data is updated once per instrument per calibration. A single calibration record includes fields such as the measured device’s range, calibration environment temperature and humidity, multi-point error values, and metrology certificate number, with fields accompanied by corresponding engineering units such as Pa, m³/h, ℃, etc.

## Constraints on HTTP Interfaces and External Systems
Three constraints apply to HTTP interface and external system configuration based on the data characteristics of this category. First, data is updated per instrument per calibration, so interfaces must support precise matching of target data using device ID and calibration batch to avoid cross-device data confusion. Second, calibration records include both structured and unstructured content such as metrology certificates and error curves, so interfaces must support returning both text and file-type data, or extracting structured fields for question answering. Third, data sources involve laboratory information systems and calibration software, so interfaces must comply with standard authentication methods to ensure secure transmission of calibration data.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer ${oneapi_api_key}` | Integrates with oneapi authentication to ensure secure transmission of calibration data |
| `variables` | `{"target_device": "", "calibration_batch": ""}` | Passes the measured instrument identifier and calibration batch to match the per-instrument per-calibration data update pattern |
| `responseData` | `Extract error curves, metrology certificate number, environmental temperature and humidity` | Focuses on core deliverable fields and filters non-essential content |
| Single Request Timeout | `600 seconds` | Adapts to the time required for multi-point calibration data collection and error calculation |
| Knowledge Base Recall Limit | `Top 8 entries` | Balances calibration procedure document coverage and interface response speed |
| Model Call Version | `FastGPT v4.17.0` | Complies with interface authentication and parameter transfer rules for the current version |

## Three Common Configuration Errors
- An interface returns a 401 status code, caused by an incorrectly configured `Authorization` parameter, or a oneapi API key not bound to the corresponding model permissions.
- The content extraction node cannot return results from custom models, caused by incorrectly configured `toolChoice` and `functionCall` parameters in config.json, or a model not associated with the corresponding knowledge base.
- The interface returns an empty result, caused by failure to pass the correct device ID and calibration batch via `variables`, making it impossible to match the corresponding calibration record data.

## How to Verify Successful Configuration
- Send a configured HTTP request using Postman, verify that the return status code is 200 and that the expected calibration error and metrology certificate number fields are included in the response.
- In the FastGPT console, initiate a question answering session using the preset `variables` parameter, check that returned results match the calibration procedures and records for the specified device.
- Simulate an abnormal request, such as using an incorrect `Authorization` parameter, confirm that the interface returns the corresponding error status code to verify that the authentication configuration is active.
- Adjust the knowledge base recall limit parameter, check that the number of returned documents matches the configured upper limit.

The values provided here are common starting points and should be evaluated against the reader's own samples.
