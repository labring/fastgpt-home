# Process Specification and Technical Standard Q&A for Industrial Instrument Manufacturing and Calibration: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Looks Like
This category of data originates from flow, pressure, temperature, and analytical instrument manufacturers and metrology laboratories. Daily documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version logs. Data is generated from design documents, standard instrument monitoring data, calibration software, laboratory information systems, and customer range requirements. Each device receives an update once per calibration. Document fields include calibration point values, error calculation results, traceability numbers, environmental monitoring parameters, with physical units such as pascals, degrees Celsius, and relative humidity percentages.

## What Constraints These Characteristics Impose on the Multi-turn Dialogue and Prompt Engineering Link
The high-frequency update nature of this category of data requires multi-turn dialogue to bind `chatId` and maintain the calibration context of the same device, preventing retrieval of expired records. Documents contain multiple types of professional fields with physical units. Prompts must explicitly specify extraction of specific content such as calibration errors, traceability numbers, and environmental parameters, to prevent generation of unsubstantiated results. A single calibration generates multiple associated documents. Multi-turn dialogue must recall relevant data sorted by device number and calibration time, pass context in order via `messages`, and limit context length to avoid exceeding processing limits.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| Maximum Context | 8000–12000 characters | The average length of calibration-related documents for a single device in this category is approximately 2000 characters. Multi-turn dialogue must retain context for 3 calibration records |
| Question Optimization | Enabled | Calibration-related questions contain specialized term abbreviations. Optimization improves recognition accuracy of these terms |
| Single Recall Limit | Top 6 entries | The number of calibration-associated documents for a single device typically does not exceed 5. Selecting 6 entries covers all relevant data |
| `variables` Binding | Pass device number, calibration time | Used to accurately recall calibration records for the corresponding device during multi-turn dialogue |
| `chatId` Binding | Enabled | Maintains context continuity for calibration conversations of the same device |
| Timeout Setting | 60 seconds | Sufficient processing time must be reserved for calibration data error calculations |

## Three Common Misconfigurations
- Missing traceability number field in dialogue return results: The cause is that the prompt fails to explicitly require extraction of the traceability number from the metrology certificate, and only broadly requests return of calibration information.
- Lost multi-turn dialogue context: The cause is that `chatId` binding is not enabled. Each dialogue resets context, making it impossible to associate previous calibration records.
- Insufficient number of available variables in the configuration interface: The cause is use of a FastGPT version below v4.17.0. The variable configuration entry location changed in older versions. Required fields must be added in the global variable module of application settings.

## How to Verify Configurations Are Set Correctly
- Initiate a first round of questions containing a device number, and verify that returned dialogue content includes the calibration error value and unit for the corresponding device.
- Initiate a second round of questions asking about environmental parameters from the last calibration, and verify that the dialogue can associate the device number mentioned in the first round and recall the corresponding record.
- Check that `variables` in the configuration items are bound to fields such as device number and calibration time, and that `chatId` is enabled.
- Initiate a multi-turn dialogue that exceeds the context length, and verify that the system does not display timeout errors or content truncation exceptions.
