# Process Specification and Technical Standard Q&A for Industrial Instrument Manufacturing and Calibration: Workflow Orchestration

## What Data Looks Like for This Category
This category’s data primarily comes from design documents, standard instrument and environmental monitoring data, calibration software, laboratory information systems, and customer range requirements. Daily documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version logs.
Data is generated once per device per calibration, with updates matching this cadence. Fields include device ID, calibration parameters, error values, metrology certificate number, range limits, and more. Most units are internationally recognized standards such as pascals, degrees Celsius, and milliliters per minute.

## What Constraints These Characteristics Impose on Workflow Orchestration
The high update frequency and single-generation per device per calibration requirement means workflows must support calling exclusive context for individual calibration tasks.
Document types include structured certificates, curve charts, and text procedures. Orchestration must support splitting and indexing multi-format documents.
The calibration process must strictly follow traceability chain requirements. Workflows must retain associated nodes for standard instruments, environmental data, and calibration records to avoid information gaps.
The most time-consuming steps — establishing standard instrument connections, multi-point error calculation, and review — must be split into separate orchestration nodes to reduce repeated manual operations.
Validation nodes must also be configured to block processes that do not meet traceability requirements, preventing measurement deviations from propagating to downstream production links.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `variables` | Bind device ID, calibration date, standard instrument ID | This category requires precise matching of exclusive data for individual calibration tasks, using variables to associate core business fields |
| Node trigger rules | Trigger based on calibration task status bound to `nodeId` | Calibration processes must execute in sequence per stage, using node IDs to lock the exclusive calibration workflow for a single device |
| Single search limit | Top 6 entries | Documents for this category are mostly exclusive to individual calibrations, so excessive redundant context is unnecessary and will interfere with accurate matching |
| Timeout threshold | 120 seconds | Typical time required for multi-point collection and error calculation, set as a reasonable wait time based on actual measurement calibration |
| Maximum context length | 8000–12000 characters | Documents for this category include error curves, metrology certificates, and other content, requiring space for substantial structured and chart description content |
| Image resource replacement | Replace with enterprise-owned domain name | Calibration certificates often include error curve images, so unifying resource access paths ensures documents load correctly |

## Three Common Mistakes
- Issue: After selecting `variables` to bind business fields, drag-and-drop lag and operational delay appear in the front-end interface. Cause: The `variables` configuration was not set up for lightweight binding, with excessive redundant variable nodes consuming front-end rendering resources.
- Issue: After enabling image upload functionality, returned image links use IP plus port format and cannot be accessed normally within the enterprise intranet. Cause: Image resource replacement rules were not configured, and default IP port links were not replaced with the enterprise-owned domain name.
- Issue: A `$schema`-related field error occurs during workflow execution, preventing the process from starting. Cause: The FastGPT v4.17.0 workflow node configuration specifications were not followed, with custom fields containing invalid metadata prefixes.

## How to Confirm Proper Configuration
- Trigger a simulated calibration task, check whether fields such as device ID and calibration date bound to `variables` are correctly passed to workflow nodes.
- Upload a calibration certificate including an error curve image, confirm that the image loads normally using the enterprise-owned domain name.
- Run the workflow, check whether nodes trigger sequentially in the order bound to `nodeId`, with no lag or delay.
- Submit the workflow execution log, confirm there are no `$schema`-related invalid field errors.
