# Process Specification and Technical Standard Q&A for Industrial Instrument Manufacturing and Calibration: Tool Calling and Plugins

## What data for this category looks like
Data for this category primarily comes from design documents, standard instrument monitoring data, calibration software, laboratory information systems, and customer range requirements. Daily generated documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version logs. Data updates follow the rhythm of each calibration for a single device. Fields include range units, error values, calibration dates, traceability numbers, and other relevant fields. Each record is bound to the unique identifier of the tested instrument.

## Constraints on Tool Calling and Plugins by This Category's Characteristics
The high-frequency update requirement of this category's data mandates that tool calling support real-time retrieval of the latest calibration records for a single device. It must avoid use of expired historical data. Data includes strongly correlated fields such as traceability numbers and error curves. Tool calling must preconfigure field matching rules to ensure extracted information is tied to the tested instrument. Calibration records are core deliverables. Tool calling must verify the integrity of the traceability chain. It must prevent calls to document content that lacks compliance checks. Error calculation logic for multi-point collection must be encapsulated via plugins. This eliminates repeated manual execution of calculation steps.

## Three Common Configuration Errors
- Tools repeatedly execute calibration record query tasks. The cause is incorrect configuration of the `toolChoice` parameter. The system fails to identify a valid termination condition, triggering repeated tool calls.
- Calibration procedure data fails to load when calling an indexing model. The cause is incorrect configuration of the model's data source binding. Category-specific documents were not imported into the indexing library.
- A 400 format error occurs when calling an image parsing tool. The cause is the absence of a PNG format validation rule in the plugin. It also fails to handle cache format conversion for temporary files.

## How to Verify Correct Configuration
- Initiate a calibration procedure query for a single instrument. Confirm the tool call triggers only once, with no repeated execution records.
- Review tool call logs. Verify extracted calibration records include category-specific fields such as ranges and error values, with correct units.
- Upload a PNG-format error curve image. Confirm the plugin parses the image normally and extracts key data, with no 400 errors.
- Submit a traceability chain review Q&A request. Confirm the tool automatically verifies the compliance of metrology certificate traceability numbers.
