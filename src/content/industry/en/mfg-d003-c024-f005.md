# Process Change and Engineering Change Process Specification and Technical Standard Q&A: Tool Calling and Plugins

## What this category of data looks like
Manufacturing enterprise change management teams generate change data from multiple systems and sources including PLM, ERP, MES, supplier materials, validation tests, and customer-specific requirements. The data includes documents such as ECN/ECR, change assessment forms, drawings and BOM versions, process validation reports, transition plans, inventory disposal documents, and customer approval files. Each change triggers an update, with no fixed update cycle. Documents contain fields including change number, version identifier, effective date, validation conclusion, and are linked to physical production processes and customer requirements.

## Constraints imposed by these characteristics on tool calling and plugin workflows
Change data is linked to multiple systems and document types. Tool calling must adapt to the interface formats and permission rules of different data sources. There is no fixed update cycle for the data, so plugin logic must support incremental synchronization and real-time pulling. Linkage impact identification, version transition point confirmation and other links involved in changes require tools to execute in order of association priority to avoid data inconsistency. The strong interconnections between documents require that tool calling results must undergo consistency checks to prevent errors such as mixing old and new versions. Additionally, the high-risk nature of change data requires that tool calling must include failure retry and exception alert mechanisms.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to multi-tool calling scenarios for change Q&A, automatically matches associated data sources and document types, compatible with FastGPT v4.17.0 |
| `functionCall` | `enabled` | Triggers function execution logic for tool calling, supports binding multiple types of document parsing tools related to changes |
| Tool execution order | Execute in order of change association priority | Change data has strong interconnections; first pull BOM version data from PLM, then synchronize inventory information from ERP to ensure coherent data logic |
| Plugin timeout threshold | `300 seconds` | Interface responses for multi-system integration have delays, reserve sufficient time for cross-system data pulling and synchronization |
| Tool calling retry count | `2 times` | Avoid call failures caused by temporary network fluctuations, while reducing unnecessary wait time |
| Context window size | `8000–12000 token` | Total length of change-related documents is large, retain sufficient context information to support logical judgment for tool calling |

## Three Common Misconfigurations
- Phenomenon: After configuring multiple tools, some tools do not execute or the execution order is chaotic. Cause: No clear tool execution order rule is set, calls are triggered only in the default random order, and the association priority of change data is not matched.
- Phenomenon: Abnormal streaming behavior occurs when calling Qwen3 series models. Cause: The streaming call switch is not enabled, or the switch configuration does not match the calling method supported by the model, causing a conflict in the tool calling logic of the agent node.
- Phenomenon: Tool calling interface errors occur after embedding into a frontend page. Cause: Cross-origin request permissions are not configured correctly, or the interface call token is not passed properly, making it impossible to normally call FastGPT's tool interface.

## How to Confirm Proper Configuration
- Submit a test query that includes a known change number, check the tool calling logs to confirm that all configured tools execute in the expected order.
- Switch to the Qwen3 series models, submit a test query to confirm that the tool calling return results are streamed output with no blocking.
- Manually adjust the plugin timeout threshold, submit a cross-system data pulling test to confirm that the call duration meets the configured threshold requirements.
- Check the document fields returned by the tool call to confirm that key information such as change number, BOM version, and effective date is included.

The values given are common starting points and should be measured against the reader's own samples.
