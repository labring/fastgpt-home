# Process Change and Engineering Change Process Specification and Technical Standard Q&A: Model Access and Configuration
This document adapts to the model access configuration workflow of FastGPT v4.17.0.

## What Data for This Category Looks Like
Data for this category comes from PLM, ERP, MES, supplier materials, validation tests, and customer special requirements. The update schedule is irregular, triggered by each process or engineering change. Daily documents include ECN/ECR, change assessment reports, drawings and BOM versions, process validation reports, switching plans, inventory disposal documents, and customer approval documents. Fields cover change order number, version number, effective date, material code, and more. Some documents include graphical parameters, with no unified fixed units, adapting to document types.

## What Constraints Do These Characteristics Impose on the "Model Access and Configuration" Link
Multi-source heterogeneous data sources require configuring document format parsing rules adapted to different systems. Irregular update schedules require incremental synchronization trigger logic to avoid redundant data loading. Mixed document structures containing drawings and text require models to support visual parsing capabilities. The feature of numerous highly associated documents requires configuring sufficient context capacity to prevent truncation of key change information. At the same time, data errors directly lead to production risks, so models must output high-accuracy version and parameter information.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Carry complete content of multiple associated documents such as ECN and BOM versions, avoid truncation of key change information |
| `maxTokens` | 2000–3000 token | Control single-round response length, ensure complete output of detailed process change steps, switching plans and other content |
| `quoteMaxToken` | 1500–2000 token | Limit the length of referenced source document fragments, match the common length of a single standard process specification entry |
| `vision` | Enabled | Process graphical process parameters and annotations in drawings and validation reports, adapt to non-text data in this category |
| `temperature` | 0.1–0.3 | Reduce response randomness, ensure accurate output of key information such as change order numbers, version numbers and effective dates |
| `AIPROXY_API_TOKEN` | Generate and limit length according to system authorization | Prevent token length from exceeding storage field limits, ensure access security |
| `AIPROXY_API_ENDPOINT` | Fill in the corresponding node according to the deployment environment | Adapt API paths for multi-system access, ensure normal data synchronization and calling |

## Three Common Mistakes
- Phenomenon: After saving the model configuration, chat automatically switches to another large model. Cause: `AIPROXY_API_TOKEN` is not bound to the specified model, or multiple sets of tokens are configured without clear effective scope.
- Phenomenon: Processing speed is too slow after uploading documents such as ECN and drawings. Cause: `maxContext` or `quoteMaxToken` parameters are not adjusted, leading to excessive long-text parsing load on the model.
- Phenomenon: Prompt "Data too long for column 'models'" when adding a token. Cause: Token length is not truncated according to system requirements, or the configured model list exceeds the field storage limit.

## How to Confirm Successful Configuration
- Initiate queries related to process specifications, check that returned document versions and change order numbers match source data.
- Upload validation reports containing drawings, confirm that the model can correctly identify process parameters and annotations in the drawings.
- Test multi-round change Q&A, confirm that there is no version confusion or key information truncation in the context.
- Check API call logs, confirm that token verification passes, and there are no length overrun or path error prompts.

The values provided are common starting points and should be measured against the reader's own samples.
