# Incoming Material Inspection and Supplier Quality Process Specification and Technical Standard Q&A: Tool Calling and Plugins

## What this category of data looks like
The data for this category comes from purchase orders, drawing specifications, supplier quality certificates, inspection equipment, historical quality data, and supplier portals. Daily involved documents include inspection specifications, sampling plans, incoming material reports, supplier audit reports, exception contact sheets, 8D reports, and concession acceptance approval forms. Data updates are synchronized with each batch of incoming materials, monthly or quarterly supplier evaluations, and irregular audits. Most document structures include fields such as batch number, inspection items, qualified judgment standards, supplier information, and historical exception records. Units involve batches, quantities, inspection item parameter thresholds, and similar items.

## What constraints do these characteristics impose on the "tool calling and plugins" link?
Data sources are scattered and update rhythms are inconsistent. Tool calling must support dynamic loading of the latest batch of incoming material inspection data and supplier documents, to avoid using expired inspection specifications or quality certificates. There are diverse document types and significant field differences. Plugins need to adapt to parsing logic for different documents, such as extracting sampling plans from inspection specifications, and extracting root cause correction information from 8D reports. Quality data must be bound to batches and supplier entities. Tool calling must accurately match corresponding identifiers to prevent incorrect matching across batches or suppliers. Non-relevant business data must also be isolated, ensuring that tool calling only accesses supplier quality-related documents and avoids interfering with other business processes.

## How to set the configurations
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically matches tool calling logic related to process specifications and quality standards |
| `functionCall` | `{"name": "query_quality_doc", "parameters": {"batch_id": ""}}` | Binds the incoming material batch number to accurately pull inspection specifications and sampling plans for the corresponding batch |
| Timeout Threshold | `300 seconds` | Adapts to the real-time response requirements of incoming material inspection, avoiding delays in production scheduling |
| Context Load Count | `Top 8 historical quality records` | Balances information completeness and retrieval efficiency, avoiding interference from redundant data in judgment |
| Plugin Data Scope | `Supplier Quality Document Library` | Isolates non-relevant business data, ensuring that tool calling only accesses compliant documents for this category |
| Retry Count | `3 times` | Addresses temporary fluctuations in data source connections, improving tool calling stability |

## Three common mistakes
- The developed supplier quality tool entry cannot be found in the plugin management interface of the FastGPT platform. The cause is that the plugin files were not placed in the path required by the platform, or the FastGPT service was not restarted to load the new plugin.
- The tool calling returns empty results or fails to match the target process specification. The cause is that the correct incoming material batch number was not passed in the `functionCall` parameter, resulting in failure to associate the inspection specification documents for the corresponding batch.
- A timeout error occurs after calling the tool, and the interface displays the request timeout status code. The cause is that the set timeout threshold is too short, failing to adapt to the pull delay of the supplier document library.

## How to confirm the configuration is complete
- Upload an incoming material report marked with a test batch number and the inspection specification for the corresponding batch, trigger tool calling, and check whether the returned documents are bound to the test batch number.
- Simulate a slow request scenario, adjust the timeout threshold, and confirm that the tool calling retry logic triggers normally according to the configuration.
- Check the plugin's data access permission configuration, confirm that only the supplier quality document library can be accessed, and business data of other categories cannot be viewed.
- View the platform operation logs, confirm that the `toolChoice` and `functionCall` parameters are executed correctly according to the configuration, and there are no parameter error prompts.

The values provided are common starting points and should be measured against the reader's own samples.
