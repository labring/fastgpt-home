# Incoming Material Inspection and Supplier Quality Process Specification and Technical Standard Q&A: Deployment and Upgrade

## What data for this category looks like
Data for this category comes from purchase orders, drawings and specification documents, supplier quality certificates, data collected by inspection equipment, historical quality records, and supplier portals. Update cycles include immediate records for each batch of incoming materials, monthly or quarterly supplier evaluations, and ad-hoc special audits. Daily documents include inspection specifications, sampling plans, incoming material inspection reports, supplier audit reports, exception contact sheets, 8D correction reports, and concession acceptance approval forms. Data fields include inspection batch numbers, AQL values, non-conformity item types, and supplier qualification numbers. Some documents include unit-bearing fields such as physical dimensions and load parameters.

## What constraints do these characteristics impose on deployment and upgrades
Data for this category consists primarily of batch-associated structured and semi-structured documents, with update frequencies that fluctuate based on incoming material batches. Deployment must accommodate high-frequency, small-volume data writes. Each batch of incoming materials uses exclusive inspection specifications and sampling plans. The knowledge base must support isolating or associating documents by batch dimension. During upgrades, ensure version iterations do not break existing batch-associated retrieval links. Supplier quality data involves cross-department collaboration. Deployment must support unified formatting for multi-source data. During upgrades, retain retrieval compatibility for historical quality data. The requirement to associate and retrieve non-conformity items and correction records requires configuring reasonable associated storage rules during deployment to avoid data redundancy or retrieval failure.

## How to set configurations
This document is written based on FastGPT v4.17.0. The following configuration items are optimized for the business characteristics of this category:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `150–250 records/minute` | Accommodates high-frequency data writes generated by each batch of incoming materials, and avoids exhausting database connection pools |
| `MONGODB_URI` | Points to a dedicated incoming material quality database instance | Isolates data for this category from other business data to ensure retrieval performance and data security |
| `REDIS_URL` | `redis://127.0.0.1:6379/1` | Caches frequently retrieved sampling plans and inspection specifications to shorten Q&A response times |
| `STORAGE_S3_ENDPOINT` | Connects to the internal enterprise object storage service address | Stores large-volume documents such as batch-uploaded supplier audit reports and 8D reports |
| `ROOT_KEY` | Generate an exclusive key based on team permissions | Restricts access to the corresponding knowledge base only to the incoming material inspection and supplier quality team |
| `FE_DOMAIN` | `https://iqc-sqe.internal.com` | Limits access scope of the Q&A tool to the internal office domain to ensure data security |

## Three common mistakes
- Q&A response time exceeds 3 minutes, and a timeout error is displayed on the interface. The cause is that `REDIS_URL` for caching frequent documents is not configured, or the `DB_MAX_LINK` value is set too low, causing database connection blocking.
- Workflow conversations show failure, but the model backend can receive response logs. The cause is that `FILE_TOKEN_KEY` is not configured correctly, causing uploaded inspection reports to fail to associate properly with Q&A contexts, or the `FE_DOMAIN` configuration is incorrect, causing cross-domain requests to be blocked.
- Historical incoming material inspection data is lost after upgrading from v4.9.3 to v4.12.2. The cause is that only the docker-compose file was updated and the service was restarted directly without backing up the corresponding database data in advance, resulting in data not being retained.

## How to confirm the configuration is complete
- Perform a bulk import of 10 supplier audit reports, and check whether the corresponding files are generated in the storage bucket corresponding to `STORAGE_S3_ENDPOINT`.
- Initiate a retrieval Q&A for incoming material inspection specifications, confirm that the response time meets expectations, and check whether the cache hit logs for `REDIS_URL` are generated normally.
- Log in to the management backend corresponding to the `ROOT_KEY`, and confirm that only authorized team members can access the knowledge base for this category.
- Perform a version upgrade operation, then query historical incoming material inspection records, and confirm that data is complete and not lost.

The values provided are common starting points and should be measured against the reader's own samples.
