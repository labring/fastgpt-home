# Process Specification and Technical Standard Q&A for Mold Design and Manufacturing: Workflow Orchestration

## What this category of data looks like
This category of data typically comes from customer product models, mold flow or forming simulations, CAD/CAM, machining and measurement data, and trial mold samples. Updates are driven by individual projects, with each mold trial or modification triggering a data update. Daily documents include mold design task sheets, DFM reports, part drawings, machining process cards, mold trial reports, modification notices, and mold records. Data fields include the number of mold cavities, draft angle, machining tolerance, mold trial batch number, and others, with corresponding units of millimeters, angles, times, and similar units.

## What constraints these characteristics impose on the "workflow orchestration" link
Since data is updated per individual project and changes are triggered by each mold trial or modification, workflows must be bound to the exclusive context of the corresponding project to avoid cross-project data confusion. There are significant differences in field formats across multiple types of documents, so workflows need to support structured extraction and field mapping for multi-source documents. Data is associated with specific mold batches and mold trial records, so workflows' `variables` must pass unique identification parameters such as project ID and mold number. Additionally, the core time-consuming and error-prone links for this category are concentrated in process review and iteration, so workflows need to cover the calling and exception trigger logic for corresponding nodes.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Context binding parameters | Pass project ID and mold number into `variables` | Matches the project-based data management characteristics of this category to avoid cross-project data confusion |
| Tool call timeout | 600 seconds | Adapts to the typical time required for process document retrieval and structured extraction |
| Result post-processing configuration | Enable custom code modules | Supports extraction of specific strings, adapting to format differences across multiple types of documents |
| History association rule | Bind `nodeId` and project ID | Ensures that workflow question optimization can retrieve historical records for the corresponding project |
| Identity association configuration | Pass business system user identifiers into `variables` | Enables identity association when embedded in a business system |

## Three common configuration mistakes
- Symptom: Tool call nodes return an abnormal number of results or specific fields are empty. Cause: The result post-processing module is not configured, making it impossible to adapt to format differences across multiple types of documents.
- Symptom: After the workflow is configured, the chat window cannot normally call the Q&A function. Cause: Necessary project parameters in `variables` are not bound, causing the context to fail to match the corresponding mold data.
- Symptom: The workflow question optimization link cannot retrieve historical conversation records. Cause: `nodeId` and project ID are not bound, causing the context association logic to fail.

## How to confirm the configuration is correct
- Submit a test request, pass the preset project ID and mold number, and check whether the `variables` parameters are correctly bound to the workflow context.
- Call the tool call node, verify that the returned results can complete specific string extraction through the custom code module.
- Trigger the question optimization link, confirm that historical conversation records for the corresponding project can be retrieved.
- After embedding in the business system, initiate a conversation and verify that the user identity identifier is correctly passed to the workflow parameters.
