# Q&A for Process Specifications and Technical Standards for Rubber Mixing and Product Vulcanization: Tool Calling and Plugins

## What Data Looks Like for This Category
Core data for this category comes from formula systems, raw material batch ledgers, internal mixer operation logs, Mooney viscometers, rheometers, vulcanizer records, and laboratory finished product performance reports.
Daily generated documents include formula sheets, weighing records, mixing curves, rubber compound quick test results, vulcanization process cards, mold usage records, and finished product performance test reports.
Data updates occur once per raw material batch, per rubber compound production run, and per vulcanization cycle.
Individual documents include clear fields such as mixing temperature, vulcanization time, and rubber compound Mooney value.
Record formats exported by different devices vary.

## Constraints on Tool Calling and Plugins From These Data Characteristics
Scattered data sources and high update frequencies require tool calling to support dynamic pulling of real-time or near-real-time logs from different devices. This prevents inaccurate process query results caused by delayed data.
Multi-format documents require plugins to adapt to parsing rules for multiple data sources. A single template cannot extract data from all sources.
Severe potential consequences require tool calling to include parameter verification and failure retry mechanisms. This prevents scrap rubber compound or failed products caused by incorrect process parameter calls.
Data updated per batch and vulcanization cycle requires tool calling query scopes to bind to the current production batch. This avoids mixing data across batches.

## How to Configure Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Automatically matches tools related to process specifications and technical standards, no manual specification of call targets required |
| `functionCall` | `enabled` | Enables function calling capabilities, supports calls to dedicated tools such as mixing curve queries and vulcanization parameter matching |
| Tool call timeout threshold | `300 seconds` | Adapts to loading and parsing time for internal mixer and vulcanizer logs, prevents request interruptions caused by large data volumes |
| Tool call retry count | `2 times` | Addresses temporary fluctuations in raw material batch data interfaces, reduces probability of single request failure |
| Context window size | `8000–12000 token` | Covers complete process specification documents and multi-batch data, ensures context integrity during queries |
| Maximum number of returned query results | `Top 5` | Avoids excessive historical data occupying the context window, ensures query efficiency |

## Three Common Mistakes
- Tool calls return {"code":514,"statusText":"unAuthApiKey"}. This occurs when the API key required for tool calling is not correctly bound, or the expired key has not been updated.
- Global variables updated during tool calling do not take effect in subsequent steps. This happens when the global variable synchronization switch is not enabled, so the variable scope does not cover the tool calling process.
- After configuring `toolChoice` as `auto`, the expected vulcanization process query tool is not triggered. This occurs when dedicated tools for this category are not bound in the system, so the automatically selected tool does not match the business scenario.

## How to Verify Successful Configuration
- Send a test request that includes "query the mixing temperature parameters for the current batch of rubber compound". Check if the tool returns operation log data from the corresponding internal mixer.
- Review tool call logs. Confirm there are no unAuthApiKey errors, and the API key status is normal.
- Manually update the global variable for the raw material batch, then send a vulcanization process query. Check if the results include corresponding parameters for the latest batch.
- After configuring `functionCall` as `enabled`, send a process query that includes multiple parameters. Check if the tool returns structured result data.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
