# Q&A on Process Specifications and Technical Standards for Cement Clinker and Grinding: Tool Calling and Plugins

## What the data for this category looks like
Business data for cement clinker and grinding scenarios covers multiple departments of cement enterprises. Daily documents include raw material batching plans, kiln operation records, laboratory reports, quality control notices, equipment inspection records, and energy reports. Data sources include online composition analysis devices, DCS control systems, laboratory management systems, kiln and mill equipment sensors, raw and fuel ledger systems, and energy metering devices. Update frequencies are divided into three categories: real-time (equipment operation data), shift-based (inspection records), and daily (laboratory reports, energy reports). Professional parameters include raw material ratios, temperatures, operation durations, energy consumption, and other relevant metrics.

## What constraints these characteristics impose on the tool calling and plugins workflow
Multiple heterogeneous data sources require tool calling to support integration with multiple data source interfaces, and avoid reliance on a single document library only. Different update frequencies require tool calling triggers to align with the update cycle of corresponding data. Real-time equipment data requires high-frequency trigger calls, while daily reports use daily triggers. Diverse document structures require plugins to adapt to parsing of process documents in different formats, retain original professional parameters and units, and prevent parameter matching errors. Severe process error consequences require tool calling to include failure retry and exception alert mechanisms, reducing fluctuations in clinker quality and kiln system shutdowns caused by abnormal data. Time-consuming tasks such as batching adjustments amid raw and fuel fluctuations and stabilizing the thermal regime of rotary kilns also require tool calling to quickly retrieve the latest professional data.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Workflow/API tool selection | `auto` | Automatically select tools matching process questions, adapting to process calling needs across multiple cement clinker and grinding scenarios |
| Workflow/API function-call configuration | `enabled` | Enable preset process parameter calculation plugins, supporting professional calculations such as clinker mineral composition and grinding fineness |
| Tool call timeout duration | 300 seconds | Match the time required to retrieve rotary kiln thermal data and online composition analysis data, preventing call interruptions due to timeout |
| Number of results returned per tool call | Top 8 entries | Balance context length and data coverage, covering core process specifications and real-time data |
| Tool call failure retry count | 2 times | Address temporary fluctuations in equipment data and network jitter, reducing invalid call attempts |

This document applies to FastGPT v4.17.0.

## Three common configuration mistakes
- Tool call returns empty results. This occurs when tools matching professional data for cement clinker and grinding are not configured, and only the general document library is called. Specialized data such as raw material batching and kiln operation records cannot be retrieved.
- Tool call triggers a timeout. This occurs when the set timeout duration is too short, and does not match the actual time required to retrieve rotary kiln data. This causes call interruptions before real-time thermal data is fully retrieved.
- Tool call format error, with status code 400 returned in the interface. This occurs when the `functionCall` parameter is not configured correctly. The parameter format when calling the plugin does not meet preset requirements, and the professional calculation function cannot be triggered.

## How to confirm the configuration is complete
- Submit a process question about raw material batching adjustment, check the tool call log, and confirm that the raw material ledger and laboratory data tools are automatically selected.
- Simulate data updates to trigger tool calls, confirm that the corresponding number of results are returned within the set time range.
- Check the `toolChoice` parameter in the configuration interface, confirm that it is set to auto mode.
- Trigger a tool call failure scenario, confirm that the 2-time retry mechanism is activated.
