# Process Specification and Technical Standard Q&A for Complete Vehicle Final Assembly: Workflow Orchestration
This page configuration guidance is based on FastGPT v4.17.0.

## What this category of data looks like
Data for the complete vehicle final assembly scenario is generated around individual vehicle VIN main lines. Daily documents include production orders, VIN lists, assembly work instructions, tightening data, offline inspection reports, rework records, and consistency release documents. Data sources include ERP/MES systems, VIN and configuration systems, tightening tools, EOL inspection lines, and quality traceability systems. Data update frequencies cover real-time generation per vehicle, real-time synchronization at the station level, and batch summary per shift. Core fields include VIN code, torque value, station number, and part batch number. Units include physical measurement standards such as newton meters and seconds.

## Constraints on Workflow Orchestration
Mixed-model production driven by individual vehicle VINs requires workflows to isolate variables per session, to avoid mixing process parameters from different vehicles. Real-time tightening data and offline inspection data require workflows to support low-latency real-time retrieval calls. Multi-station parallel operation scenarios require workflow nodes to bind exclusive retrieval rules for the corresponding station, to prevent mismatching of cross-station process documents. Batch-summarized shift team data updates require workflows to adapt to periodic knowledge base synchronization updates, ensuring retrieval content matches the latest standards.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | User-level variables isolated per session | Adapt to the isolation requirement of single VIN-specific process parameters, avoid mixing parameters from different vehicles |
| `nodeId` | Retrieval node bound to the corresponding assembly station | Match the exclusive work instructions for final assembly stations, ensure retrieval content matches the current station |
| Single retrieval limit | Top 10 entries | Cover core entries of single-station process specifications, avoid interference from redundant information |
| Timeout threshold | 600 seconds | Adapt to the synchronization rhythm of real-time tightening data acquisition, avoid station stagnation caused by long waits |
| Context length | 800–1200 characters | Carry complete process requirements for a single station, align with the typical length of final assembly documents |
| Knowledge base synchronization cycle | Once per shift | Match the summary rhythm of shift team data, ensure retrieval content matches the latest standards |

## Three Common Configuration Mistakes
- Only the first query in a workflow triggers knowledge base retrieval, with no knowledge base reference for subsequent queries. This occurs because the continuation trigger rule for session context is not configured, and only a single node trigger is set.
- Global variables datasetid cannot be referenced in a workflow. This occurs because the global scope dataset ID is not bound in `variables`, or the node configuration does not enable global variable reference permissions.
- Variables in workflows are not isolated by user ID. This occurs because global variables are used during configuration, and the session-level variable isolation rule is not enabled.

## How to Verify Correct Configuration
- Input different VIN codes to initiate queries, verify that the returned assembly work instructions match the configuration of the corresponding VIN.
- View workflow run logs, confirm that the `variables` parameter is isolated per session, with variable values from different test sessions not interfering with each other.
- Initiate multiple retrieval requests for different stations consecutively, confirm that each request correctly matches the process specifications of the corresponding station.
- Check node configurations, confirm that the retrieval node bound by `nodeId` matches the current station's business scenario.
