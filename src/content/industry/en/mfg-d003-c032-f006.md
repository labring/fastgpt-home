# Assembly Process Specifications and Technical Standards Q&A for Complete Vehicles: Citation Sources and Traceability

## What Data for This Category Looks Like
Core data for complete vehicle final assembly comes from ERP, MES systems, VIN and configuration systems, tightening tools, EOL inspection lines, and quality traceability systems. Daily documents include production orders, VIN lists, assembly work instructions, tightening torque data (unit: N·m), offline inspection reports, rework records, and consistency release documents.
Data updates follow a rhythm of real-time updates per vehicle and batch updates per shift. Fields include VIN code, torque threshold, station number, inspection batch number, and rework order number. A single work instruction typically covers 10 to 20 assembly steps.

## Constraints on Citation Sources and Traceability
Since final vehicle assembly uses mixed-line production with VIN as the unique identifier for each vehicle, citation traceability must be precisely bound to the configuration and assembly data of a single vehicle. Unrelated documents must not be recalled across VINs.
Real-time tightening data and offline inspection reports have strict timeliness requirements. Matching and tracing the latest data must be completed within the Q&A response window. A single vehicle involves hundreds of assembly configurations, so cited content must be kept within a reasonable range to avoid overloading and interfering with dialogue logic.
Incorrect citations may lead to mismatched missing parts, vehicle failure to pass final inspection, or even safety recalls. Therefore, traceability must specify exact stations, tools, and batches, with no vague citations.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 8000–12000 token | A single vehicle assembly work instruction typically exceeds 2000 characters. Sufficient token capacity is required to carry complete cited content and avoid truncating critical process steps |
| Single search limit | Top 8 results | Core process documents for a single vehicle assembly total approximately 6 to 7 items. Too many recalled results will introduce irrelevant supplier batch data and interfere with core Q&A logic |
| `responseData` | Enable VIN-associated filtering | In mixed-line production scenarios, only configuration, parts, and process documents matching the VIN bound to the current Q&A must be recalled, to avoid cross-vehicle citations |
| Similarity threshold | 0.72–0.78, calibrated via actual testing | Assembly documents use specialized terminology with high repetition. This range filters low-relevance general documents and retains precise station-level process content |
| `detail` | Enable full citation path display | Fields such as the data source's associated station, tightening tool ID, and inspection batch number must be displayed to meet vehicle assembly quality traceability requirements |
| Rearrangement rule | Sort by station timestamp | Assembly processes follow station sequence. Prioritizing process standards for current and preceding stations aligns with assembly personnel's usage habits |

This configuration logic is based on FastGPT v4.17.0.

## Three Common Misconfigurations
- Phenomenon: Cited content not included in the local knowledge base is displayed in the conversation. Cause: VIN-associated filtering for `responseData` is not configured, and historical documents across VINs are accidentally recalled during mixed-line production.
- Phenomenon: Knowledge base citation sorting does not follow process logic, and content from subsequent stations is displayed first. Cause: Sorting by station timestamp is not enabled, and only basic similarity sorting is used, leading to irrelevant later station documents being prioritized.
- Phenomenon: Cited content is truncated, and complete process steps cannot be viewed. Cause: `quoteMaxToken` is set below 8000 tokens, which does not match the character length of assembly documents, leading to critical torque parameters or steps being truncated.

## How to Verify Successful Configuration
- Initiate a Q&A about assembly processes bound to a known VIN, and confirm that cited content only includes assembly work instructions and inspection data corresponding to that VIN, with no cross-VIN unrelated documents.
- Check the sorting of the citation module, and confirm that process documents for preceding stations are prioritized over content for current and subsequent stations, aligning with vehicle assembly order.
- Verify that citation cards include complete data source paths, such as station numbers, tightening tool IDs, or inspection batch numbers, with no vague data source labels.
- Test the citation display toggle, and confirm that knowledge base cited content can be hidden or displayed as needed, with no forced display of redundant information.
