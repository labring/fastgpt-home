# Complete Vehicle Final Assembly Process Specification and Technical Standard Q&A: Knowledge Base Retrieval and Recall

## What the Category’s Data Looks Like
The core data for this category originates from ERP/MES systems, VIN and vehicle configuration systems, tightening tools, EOL inspection lines, and quality traceability systems. Daily documentation includes production orders, VIN lists, assembly work instructions, tightening torque data, offline inspection reports, rework records, and consistency release documents. Data update frequencies cover two scenarios: real-time updates per individual vehicle, and batch updates per shift. Documents are linked to corresponding configurations, parts lists, and full-process quality records using VIN as the unique identifier. Fields include torque units, inspection thresholds, part numbers, and other content directly related to vehicle assembly.

## Constraints Imposed on Knowledge Base Retrieval and Recall
Because data is tied to full-process information centered on VIN, retrieval must accurately match individual vehicle configurations. As a result, recall results must strictly align with the exclusive configuration requirements of the corresponding VIN. Real-time updated tightening data and offline inspection reports require the retrieval pipeline to support low-latency recall, to avoid disrupting assembly takt time. Process specification documents updated per shift must be regularly synchronized to the knowledge base, and valid versions must be differentiated during retrieval. The mixed-line production scenario with multiple concurrent configurations requires retrieval results to be sorted by assembly station priority, to prevent mismatching and missed installations. The consequences of errors include vehicles failing to complete final assembly or safety defects, so the confidence level of retrieval results must be traceable, and source documents must be clearly linked.

## Configuration Settings
This configuration is based on FastGPT v4.17.0. Specific parameter settings are listed below:
| Configuration Parameter | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Filters low-match non-exclusive configuration documents to avoid mismatching station requirements during mixed-line production |
| `limit` | `Top 8–12 results` | A single vehicle assembly requires matching many process items, so results must cover enough stations without exceeding the context window |
| `searchMode` | `vector + fulltext` | Combines semantic matching for VIN configurations and keyword matching for process parameters, balancing accuracy and recall completeness |
| `usingReRank` | `Enabled` | In mixed-line production scenarios with multiple configurations, reorder results by assembly station priority to reduce mismatch risks |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Automatically expands configuration keywords related to VIN to improve the matching rate between VIN and corresponding process documents |
| `collectionIds` | `Specify exclusive collection IDs for final assembly processes` | Avoids retrieving documents from non-final assembly links, narrowing the recall scope to improve efficiency |

## Three Common Misconfigurations
- Semantic retrieval scores fall outside the standard 0-1 range, with values exceeding 4000. This occurs when normalization logic for the `similarity` parameter is not properly configured, leaving raw similarity scores unscaled.
- Unable to retrieve source file information used by the knowledge base via API calls. This happens when source file tracking for the knowledge base is not enabled, or when the API parameters do not specify the field for returning source file details.
- Knowledge base capacity planning has deviations due to lack of clear basis for estimation. This is caused by not calculating based on average single-document size and total number of documents, and not accounting for storage space used by real-time updated incremental data.

## How to Verify Correct Configuration
- Submit a retrieval request with a specific VIN, verify that returned results only include assembly work instructions and configuration files associated with the corresponding VIN.
- Review the score distribution of retrieval results, confirm all scores fall within a reasonable range with no abnormally high values.
- Call the relevant API interface to confirm that returned results include the path and version information of source files.
- Simulate a mixed-line production scenario, submit retrieval requests for multiple stations, confirm results are correctly sorted by assembly station priority.

The values provided are common starting points and should be measured against the reader's own samples.
