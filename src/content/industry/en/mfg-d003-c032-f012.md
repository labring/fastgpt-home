# Complete Vehicle Final Assembly Process Specifications and Technical Standards Q&A: Deployment and Upgrade

## What Data for This Category Looks Like
Data sources for complete vehicle final assembly process and standard data cover ERP/MES systems, VIN and configuration systems, tightening tools, EOL inspection lines, and quality traceability systems. Data update frequencies include per-vehicle (such as tightening data and VIN configuration for individual vehicles), real-time (such as station work instructions), and per-shift (such as batch production plans). Daily documents include production orders, VIN lists, assembly work instructions, tightening torque data, offline inspection reports, rework records, and compliance release documents. Core fields include VIN code, part number, torque value, inspection results, and batch number. Corresponding units include newton meters, batch numbers, station numbers, and similar units.

## Constraints Imposed by These Characteristics on Deployment and Upgrade
This category’s multi-source scattered data and high-concurrency update requirements impose clear rules for deployment data integration. Deployments must connect both structured databases and unstructured document storage simultaneously.
Mixed-line production has high configuration complexity. Upgrade phases must retain compatibility with multiple sets of process templates. Version updates must not damage existing VIN matching logic.
Real-time updated tightening and inspection data require highly available storage connections during deployment. Data interruptions must not disrupt station Q&A services.
Errors affect vehicle offline operations and safety compliance. Deployments must configure complete operation logs and permission isolation rules. Misoperations must not cause production risks.

## How to Set Configurations
| Config Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 10–20 connections | Adapt to concurrent process data retrieval requests from multiple stations in the final assembly workshop, and avoid database connection exhaustion |
| `MONGODB_URI` | Configure as an unstructured data connection string with a replica set | Support high-concurrency read and write operations for unstructured process documents such as tightening data and rework records |
| `PG_URL` | Point to the structured data primary database address synchronized from ERP | Ensure the efficiency of structured queries for accurately matching assembly work instructions by VIN code |
| `REDIS_URL` | Configure as a local cache cluster, with the cache expiration time set to 300 seconds | Cache frequently accessed process templates and VIN configuration mappings, reducing database query pressure |
| `STORAGE_S3_ENDPOINT` | Bind to the enterprise's internal S3-compatible storage node | Store batch-uploaded offline inspection reports and compliance release documents |
| `FE_DOMAIN` | Fill in the enterprise's internal front-end access domain name | Limit the access scope of non-login links, meeting the security access requirements of the production environment |

## Three Common Errors
- Phenomenon: The open-source version v4.8.22 only allows adjustment of basic AI parameters. It cannot customize prompt words and reference templates. Reason: This version does not offer the advanced configuration module for process Q&A. Upgrades to FastGPT v4.17.0 or later are required.
- Phenomenon: After a user using a non-login link deletes a conversation, the background operation log is cleared synchronously. Reason: Permission rules linked to `ROOT_KEY` are not correctly configured during deployment. Isolation for log deletion permissions is not implemented.
- Phenomenon: When adding new process knowledge base documents, a prompt indicates the quantity exceeds the upper limit. Further additions are not possible. Reason: The default knowledge base quota limit of the open-source version is not adjusted. Configuration expansion for document storage requirements in final assembly scenarios is not completed.

## How to Confirm Configuration Is Complete
- Log in to the FastGPT management backend, check that the configured value of `DB_MAX_LINK` matches the preset value, initiate 15 concurrent retrieval requests, and confirm no connection timeouts or error messages occur.
- Upload a real VIN list and the corresponding station’s assembly work instructions, initiate process Q&A matching by VIN code, and confirm returned results include the station’s work requirements and torque parameters.
- Generate a non-login link and initiate a conversation, delete the conversation, check the background log, and confirm the original conversation record is retained and not synchronously cleared.
- Add more than 30 process knowledge base documents, confirm storage and retrieval functions operate normally, and no errors related to quota limits appear.
