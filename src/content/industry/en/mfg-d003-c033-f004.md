# Process Specification and Technical Standard Q&A for High-Volume Automotive Parts Manufacturing: Workflow Orchestration

## What data for this category looks like
This category of data primarily comes from customer drawings and special characteristic lists, ERP/MES systems, measurement and inspection tool data, equipment process parameters, and supplier quality certificates. Daily production-related documents include control plans, process flowcharts, work instructions, first-piece and patrol inspection records, SPC reports, PPAP materials, and 8D reports. Data updates occur per production batch, during each shift’s patrol inspections, and through continuous collection of equipment parameters. Document fields include part numbers, process parameters, quality characteristic values, anomaly records, and more. Units mostly use industry-standard measurements such as millimeters, newton-meters, and percentages.

## What constraints these characteristics impose on workflow orchestration
Data for this category is scattered and updated frequently. Workflow orchestration must support real-time synchronous calls across multiple data sources to avoid deviations in process Q&A caused by data lag. There are many types of daily documents, so the workflow must preset parsing rules for different documents: extract process requirements from control plans, and extract anomaly root causes from 8D reports. Vehicle customer quality systems impose restrictions, so the workflow must configure strict permission verification nodes. Only links bound with the `nodeId` permission tag can access confidential quality documents. High-volume production has strict real-time requirements, so the workflow must support high-frequency triggering to handle real-time anomaly data and patrol inspection records from MES.

## Three common misconfigurations
- The number of results returned after workflow execution does not match expectations. The symptom is that the number of retrieved documents is less than the configured value. The cause is that the knowledge base association quantity is not correctly configured, or the associated knowledge bases have not synchronized the latest process documents.
- Global variables cannot be called in subsequent nodes. The symptom is that the variable fields read by downstream modules are empty. The cause is that the cross-node passing configuration for global variables is not enabled, or the global scope was not selected when defining the variables.
- MCP tool calls fail. The symptom is that authentication errors or missing parameters are returned. The cause is that the token global variable in the workflow is not correctly bound to the request parameters of the MCP tool, causing the tool to fail to obtain valid authentication information.

## How to confirm the configuration is complete
- Trigger a test Q&A, input a question that includes a part number and batch number, and check whether the workflow automatically extracts the corresponding `variables` variables.
- Manually trigger the workflow, and check whether the logs of each node show that global variables have been correctly passed to downstream modules.
- Call the MCP tool, and check whether the authentication information passed in from the workflow is included in the tool's request parameters.
- Adjust the knowledge base association quantity, and verify whether the number of retrieval results matches the configured expectations.

The values provided are common starting points and should be measured against the reader's own samples.
