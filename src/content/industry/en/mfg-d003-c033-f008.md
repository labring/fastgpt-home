# Process Specification and Technical Standard Q&A for Mass Production of Automotive Parts: Document Parsing and Chunking

## What Data Looks Like for This Category
Daily documents for this category include control plans, process flowcharts, work instructions, first article and patrol inspection records, SPC reports, PPAP materials, and 8D reports. Data sources include customer drawings and special characteristic lists, ERP/MES systems, measuring tools, equipment process parameters, and supplier quality certificates. Data is updated per batch, per shift, or via continuous collection. Documents contain fields such as special characteristic numbers, process parameters, tolerance values, and batch numbers. Units include millimeters, newton-meters, hours, and other commonly used industrial measurement standards.

## Constraints on Document Parsing and Chunking
Mixed multi-source data formats require parsing tools to support structured tables, vector graphic PDFs, and plain text paragraphs. Frequently updated documents need fast parsing workflows to avoid delays that disrupt mass production scheduling. Structural differences across document types require chunking logic to balance paragraph integrity and retention of associated information. For example, do not separate special characteristics in a control plan from the operational requirements of their corresponding process. Business scenarios with strict vehicle customer constraints demand field accuracy and format consistency in parsing results, to prevent parameter deviations in subsequent Q&A links caused by chunking errors.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the length of single-process content in work instructions and control plans, avoiding splitting the association between critical parameters and operation instructions |
| `chunkSplitter` | Semantic-based chunking | Adapts to the mixed content structure of structured paragraphs and unstructured descriptions in PPAP materials and 8D reports |
| `customPdfParse` | Enable Marker parsing | Adapts to customer drawing PDFs with vector graphics and complex-format SPC reports, resolving format corruption issues from native parsing |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Accommodates large documents such as batched PPAP materials and process flowcharts packaged for mass production scenarios |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses parsing time for large SPC reports and multi-page process flowcharts, preventing parsing failures due to timeouts |
| `chunkSettingMode` | Manual configuration | Adjust chunking parameters for different document types, such as work instructions vs 8D reports, to optimize Q&A recall accuracy |

## Common Misconfigurations
- Symptom: FastGPT v4.17.0's built-in PDF parsing returns empty content or format corruption. Cause: `customPdfParse` configuration is not enabled, and Marker parsing is not called for vector graphic customer drawing PDFs.
- Symptom: File parsing tools fail to launch when calling large language models. Cause: `PARSE_FILE_TIMEOUT_SECONDS` timeout parameter is not configured correctly, or GPU resources are not mounted during container deployment, causing parsing processes to fail to start.
- Symptom: Associations between special characteristics and their corresponding processes are lost after chunking. Cause: `chunkSize` is set too small, splitting parameter requirements and operation instructions for the same process into separate chunks.

## How to Verify Correct Configuration
- Upload a single-page work instruction PDF, check if parsed chunked content retains key fields such as process numbers and tolerance values.
- Check container deployment logs to confirm Marker parsing processes start normally, with no timeout or format parsing errors.
- Upload an SPC report with more than 100 pages, verify that parsing time does not exceed the threshold set by `PARSE_FILE_TIMEOUT_SECONDS`.
- Upload packaged documents of a control plan and its corresponding work instructions, confirm that associated paragraphs of the two document types are not split after chunking.

The values listed are common starting points, and should be validated against the samples relevant to the deployment context.
