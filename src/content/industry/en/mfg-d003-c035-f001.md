# Heat Treatment Process Specifications and Technical Standards Q&A: HTTP Interfaces and External Systems

## What the data for this category looks like
This category of data comes from material grade standards, customer technical requirements, temperature control instruments, furnace temperature uniformity test results, testing data from hardness testers and metallographic equipment, and workshop MES systems. Daily documents include heat treatment process cards, furnace loading layout diagrams, furnace temperature curve records, hardness and metallographic inspection reports, equipment inspection sheets, and exception handling sheets. Data is updated per furnace load and per batch. Individual documents contain fields such as heating, holding, and cooling parameters, furnace loading positions, testing values, and exception handling records. Units include temperature (℃), time (hours/minutes), hardness (HV/HRC), and others.

## What constraints these characteristics impose on HTTP Interfaces and External Systems
This category of data is updated frequently per furnace load and per batch. HTTP interfaces must support high-frequency calls and bulk data import to avoid production process delays caused by synchronization latency. Data includes multiple types of documents and structured testing values, so interfaces must support both unstructured text and structured field inputs to adapt to formats from different sources. Since process abnormalities can cause all parts in a furnace load to be scrapped, interfaces must return clear status codes and error details to enable quick troubleshooting of configuration or data issues. The business attributes of multiple fields require interfaces to support custom variable mapping, matching raw data from temperature control instruments, hardness testers, and other sources to standard fields in the knowledge base. This configuration is formulated based on the interface specifications of FastGPT v4.17.0.

## How to Set the Configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Bearer workshop-specific access token | Follow HTTP authentication specifications to restrict unauthorized interface calls and protect production data security |
| `variables` | Pass the current furnace load's material grade and customer technical conditions | Supplement retrieval context to align process Q&A with the exclusive standards of the current production batch |
| Single bulk data import limit | 40–60 items per request | Adapt to the bulk data scale per furnace load and avoid overloading interface resources |
| Timeout period | 240–360 seconds | Cover the parsing and import time of multiple heat treatment documents to prevent mid-call interruptions |
| `responseData` | Structured content including status code, error information, and imported item count | Enable external systems to automatically parse interface results and quickly troubleshoot import or query abnormalities |
| Custom field mapping | Map furnace temperature curve data to the "furnace temperature curve" field | Match the standard data structure of heat treatment business and improve retrieval accuracy |

## Three Common Mistakes
- Phenomenon: A `401 Unauthorized` status code is returned after calling the interface, and data cannot be imported. Cause: The `Authorization` parameter is not configured correctly, or an expired or workshop-permission-unbound access key is used.
- Phenomenon: The results returned by the conversation interface do not include the source original text of furnace temperature curves and hardness reports. Cause: The source association configuration is not enabled in the `responseData` parameter, or original documents are not correctly uploaded to the knowledge base.
- Phenomenon: Some documents are not indexed during bulk data import, and the imported item count in the returned results is less than the submitted count. Cause: The single bulk data import limit is set too high, exceeding the interface's processing capacity, or some documents have formats that do not meet the knowledge base requirements.

## How to Confirm the Configuration Is Complete
- Call the test interface with simulated furnace load data. Confirm that the `Authorization` parameter passes authentication and returns a 200 OK status code.
- Initiate a process Q&A request. Confirm that the `responseData` return field includes source document association information, and that the retrieval results match the current furnace load's process requirements.
- Submit a bulk data import request. Verify that the returned imported item count matches the submitted count, and that all documents are correctly indexed.
- View the knowledge base data list in the FastGPT backend. Confirm that imported heat treatment process cards, furnace temperature curves, and other documents all exist and have matching fields.

The values given are common starting points and should be measured against the reader's own samples.
