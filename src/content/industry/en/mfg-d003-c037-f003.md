# Process Specification and Technical Standard Q&A for Production Planning and Shop Scheduling: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Looks Like
This category of data covers core business documents for manufacturing enterprise PMC, planning, shop scheduling, and material control departments. It includes sales orders, master production schedules, material requirement plans, weekly and daily production scheduling tables, work orders, material shortage lists, and delivery change notices. Data sources include ERP order and inventory systems, BOM and process routes, equipment capacity ledgers, staff shift schedules, work-in-progress inventory, and supplier arrival records. Data update frequency is adjusted according to business rhythm, including daily, weekly updates, and immediate updates when orders or exceptions occur. Data fields include order numbers, material codes, capacity values, scheduling dates, and standard production units such as pieces, hours, and days.

## Constraints on Multi-turn Dialogue and Prompt Engineering
Data sources for this category are scattered, and update rhythms are flexible. Multi-turn dialogue must simultaneously link multiple types of data such as ERP orders, process routes, and equipment capacity. It is therefore necessary to retain context associations for different business modules in the dialogue history. Daily document structures vary widely. Prompts must adapt to different types of business fields such as sales orders, work orders, and material shortage lists to avoid recognition errors. The immediacy of data updates requires multi-turn dialogue to call the latest scheduling and work-in-progress data in real time. The truncation threshold for dialogue context must therefore match the data update frequency to prevent expired information from being used to generate scheduling suggestions. In addition, cross-process and cross-shop scheduling logic requires prompts to clearly link resource constraints to avoid generating scheduling plans that do not comply with equipment or material restrictions.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context length | `8000–12000 characters` | Production planning documents have long individual lengths. Sufficient multi-turn dialogue history must be retained to adapt to the context processing limit of FastGPT v4.17.0. |
| Session ID binding rule | Bind workshop work order number + scheduling date | Distinguish independent scheduling dialogue contexts for different workshops, corresponding to the standardized binding logic of `chatId` |
| Number of retained multi-turn dialogue history entries | Top 10 entries | Production planning dialogue logic is compact. Excessive history will interfere with current scheduling judgments. This is designed based on the `messages` history truncation rule. |
| Variable mapping configuration | Bind work order number, equipment ID, current scheduling date | Match core business fields of this category to ensure `variables` are correctly replaced with real-time business data. |
| Prompt template configuration | Embed BOM fields, equipment capacity thresholds | Adapt to the process specifications and scheduling logic of this category to ensure dialogue results comply with production standards. |
| Knowledge base recall matching threshold | Calibrate based on actual testing | Adapt to the field characteristics of this category of documents to avoid recalling irrelevant process or scheduling data. |

## Three Common Misconfigurations
- Phenomenon: Interface calls return empty fields. Cause: Business variable binding for `variables` is not configured correctly, so core business parameters for production planning cannot be matched.
- Phenomenon: Raw output data from dialogue is unorganized and does not fit the reading habits of shop schedulers. Cause: The result organization logic for multi-turn dialogue is not enabled, and raw recalled data is returned directly.
- Phenomenon: Prompts cannot adapt to retrieval of English process documents. Cause: Prompt rules are not adjusted for the language of this category’s business documents, leading to a mismatch between recalled Chinese process data and English prompt logic.

## How to Verify Proper Configuration
- Test the interface call by passing the `chatId` bound to a work order number, and verify that the session context retains the historical dialogue content for the corresponding work order.
- Check the `variables` binding configuration, and verify that business parameters are correctly replaced into prompts and recall results after being passed in.
- Trigger a multi-turn dialogue, enter a request containing an abnormal scheduling scenario, and verify that the returned results are associated with corresponding material shortage lists or equipment capacity content.
- Adjust the configuration for retained multi-turn dialogue history, and verify that old dialogue content is automatically truncated after exceeding the set threshold.
