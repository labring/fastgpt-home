# Process Specification and Technical Standard Q&A for Production Planning and Shop Scheduling: Workflow Orchestration
This document is written based on FastGPT v4.17.0.

## What this category's data looks like
Data for this category comes from enterprise ERP order and inventory systems, BOM and process routes, equipment capacity ledgers, staff shift schedules, work-in-progress ledgers, and supplier arrival records. Daily associated documents include sales orders, master production schedules, material requirements plans, weekly scheduling sheets, work orders, material shortage lists, and delivery change notices. Data updates are triggered by orders or exception events, or follow a daily or weekly cycle. Document fields include order numbers, material codes, process numbers, capacity values, work-in-progress quantities, and have no unified fixed units, and are flexibly adjusted according to the field definitions of corresponding business modules.

## What constraints do these characteristics impose on the workflow orchestration link
Dispersed data sources and inconsistent update rhythms require workflow orchestration to support scheduled pulling and real-time trigger synchronization for multi-source data. Differences in fields across multiple types of business documents require workflows to be configured with unified field mapping rules to avoid scheduling errors caused by parameter mismatches. High-frequency updates triggered by orders and exceptions require workflow nodes to support dynamic parameter injection and rapid rescheduling logic. At the same time, it is necessary to adapt to cross-process and cross-resource constraint checks, ensure that workflow execution covers multiple restriction conditions of equipment, materials, and personnel, and ensure that scheduling results conform to actual production capacity.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Bind to session lifecycle, persistent variables retained for 7 days | Adapt to temporary and long-term storage needs of scheduling data, avoid cross-session data interfering with normal scheduling logic |
| `nodeId` | Bind to corresponding business nodes, such as work order decomposition nodes, scheduling recalculation nodes | Accurately locate the execution status and parameter transfer path of each link in the workflow, facilitating exception troubleshooting |
| Multi-parameter Q&A trigger configuration | Automatically trigger follow-up questions when missing parameters are detected | Adapt to the multi-parameter input requirements of MCP tools, supplement missing fields required for process specifications and scheduling |
| Timeout waiting duration | 300–600 seconds | Cover the conventional execution cycles of ERP data pulling and scheduling recalculation, avoid task failure from premature interruption |
| Context window size | 1000–1500 token | Carry core information of multiple documents such as orders and scheduling sheets, avoid exceeding the model's processing limit |
| Global variable persistence strategy | Archive by business cycle, such as weekly archiving to enterprise storage | Retain historical scheduling data for review, while controlling memory usage during workflow runtime |

## Three common errors
- Phenomenon: When calling an MCP tool in a workflow, a parameter missing error is returned, and process parameter supplementation cannot be completed. Cause: The multi-parameter Q&A trigger node is not configured, and the follow-up question logic for missing parameters is not set in the workflow, so users cannot be guided to supplement required fields.
- Phenomenon: When re-entering after a session ends, the stored value of global variables is not retained. Cause: The `variables` configuration is not set to session persistence mode, or the persistence duration is set too short, causing temporary variables to be cleared after the session ends.
- Phenomenon: Workflow node execution times out, returning status code 504. Cause: The timeout waiting duration is set lower than the actual execution time of ERP data pulling or scheduling recalculation, and the processing cycle of this category of data is not adapted.

## How to confirm the configuration is complete
- Trigger a work order decomposition workflow, check whether the corresponding ERP order and BOM data can be pulled automatically, and verify whether the `variables` parameters are correctly transferred to subsequent nodes.
- Simulate a parameter-missing MCP call scenario, confirm that the system automatically triggers follow-up questions to guide the supplementation of fields required for process specifications and scheduling.
- End the session and re-enter, check whether global variables are retained for the configured duration, and verify that the `variables` persistence settings take effect.
- Run a complete scheduling recalculation process, confirm that the execution duration does not exceed the set timeout threshold, and there are no interruption errors.

The values provided are common starting points and should be measured against the reader's own samples.
