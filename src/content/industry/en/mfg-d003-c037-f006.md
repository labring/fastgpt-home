# Process Specification and Technical Standard Q&A for Production Planning and Shop Scheduling: Citation Sources and Traceability

## What this category of data entails
It typically serves manufacturing enterprise PMC, planning, shop scheduling, and material control departments. Data sources include ERP orders and inventory, BOMs and process routes, equipment capacity, staff shifts, work in progress, and supplier deliveries. Daily processed documents include sales orders, master production schedules, material requirements plans, weekly and daily scheduling tables, work orders, material shortage lists, and delivery change notices. Data update frequency is daily, weekly, or real-time alongside orders or abnormal situations. Fields include order numbers, process numbers, equipment numbers, capacity units, and more. Citations must be matched according to associated relationships.

## What constraints do these characteristics impose on the citation sources and traceability link?
Multi-source, frequently updated data requires traceability to link to accurate document versions, and prevents use of expired scheduling parameters. Complex associated document structures, such as work orders linked to multiple process specifications, require traceability to accurately match association relationships between documents, and cannot rely solely on keyword matching. The characteristic that a single task involves multiple documents requires traceability to limit the number of returned results, avoiding information overload that impacts shop scheduling personnel’s judgment. The characteristic that data abnormalities directly lead to delivery delays or work in progress accumulation requires traceability to retain verifiable original data paths, supporting verification of scheduling results.

## How to configure the settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 900–1100 characters | Adapts to the valid single-paragraph content length of production planning and scheduling documents, avoiding truncation of core information such as work order numbers and capacity parameters |
| `responseData` | Enabled | Retains field information of associated documents, supporting cross-verification and traceability checks in the scheduling link |
| `detail` | Enabled | Displays the update time and complete source path of cited documents, adapting to scenarios of frequently updated production data |
| Single search limit | Top 6 entries | Covers process specifications and associated documents for multiple processes involved in a single scheduling task |
| Citation display location | End of conversation | Aligns with the reading habits of shop scheduling personnel, enabling quick verification of data sources |

*This configuration is based on FastGPT v4.17.0*

## Three common configuration mistakes
- No citation sources are displayed at the end of the conversation. This occurs because the `responseData` configuration item is accidentally disabled, and traceability data return is not enabled.
- Cited content truncates core scheduling parameters such as work order numbers and equipment capacity. This occurs because the value of `quoteMaxToken` is lower than the valid single-paragraph length of production planning documents.
- The displayed traceability documents are outdated versions from one week prior. This occurs because filtering citation sources by latest update time is not configured, resulting in use of expired data.

## How to confirm the configuration is properly set
- Launch a Q&A about process specifications that includes a specific work order number, check if the source path and update time of the corresponding document are displayed at the end of the reply.
- Submit a test question involving multi-process scheduling, verify that no critical parameters are truncated in the cited content, and confirm that the `quoteMaxToken` value adapts to the document length.
- Simulate a scenario with an abnormal order, check if traceability links to the latest delivery change notice or material shortage list data.
- View the module configuration panel in FastGPT v4.17.0, confirm that both `responseData` and `detail` are enabled.
