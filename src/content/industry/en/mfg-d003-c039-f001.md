# Process Specification and Technical Standard Q&A for Electric Motor and Generator Manufacturing: HTTP Interfaces and External Systems

## What data for this category looks like
Process specification and technical standard data for electric motor and generator manufacturing comes from electromagnetic design data, copper wire and insulating material batch records, winding equipment, balancing machines, electrical test benches, and ERP/MES systems. Daily generated documents include winding process cards, insulation treatment records, dynamic balance reports, withstand voltage insulation test reports, and type and factory test reports. These documents contain structured fields such as number of winding turns (unit: turns), insulation thickness (unit: millimeters), test voltage (unit: kilovolts), as well as supporting attachments like wiring diagrams and test waveform diagrams. Data updates occur once per product or per batch, and all associated documents are updated synchronously when a type change takes place.

## What constraints these characteristics impose on HTTP interfaces and external systems
Data sources cover multiple external systems including equipment and ERP. Interfaces must support cross-system data pulling and integration to avoid duplicate entry of process and test information. The characteristic of updating by batch and by process step requires interfaces to support precise parameter queries based on batch numbers, test types, and other criteria, to ensure returned process data matches current production tasks. Documents include structured numerical fields and image, PDF attachments. Interfaces must support both structured data transmission and multi-type file uploads, to meet the multimodal requirements of process Q&A. Process data is directly linked to product quality, so interfaces must have authentication and data verification capabilities to prevent unauthorized access or incorrect data from entering the Q&A system.

## Three common mistakes
- The phenomenon is that the interface returns a 400 status code, prompting that the file format is not supported. The cause is that the request body format supporting multi-type process documents such as PDFs and images is not correctly configured.
- The phenomenon is that no segmented streaming data is returned after calling the interface. The cause is that the streaming response parameters of the Q&A interface are not correctly configured, and only full-segment Q&A results are returned.
- The phenomenon is that the `responseData` field returned by the interface is empty. The cause is that the correct batch number or test type parameters are not passed, and the corresponding process specification and technical standard data cannot be matched.

## How to confirm the configuration is complete
- Call the authentication interface, verify the validity of the `Authorization` parameter, and confirm that a correct session token is returned.
- Pass a known valid batch number parameter, call the process Q&A interface, and check if `responseData` returns structured process data for the corresponding batch.
- Upload a single winding wiring diagram image or test report PDF, verify that the interface can correctly receive and associate the corresponding process information.
- Configure the streaming response parameters, check if the interface returns segmented Q&A results as expected.
