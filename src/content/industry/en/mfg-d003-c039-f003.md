# Process Specification and Technical Standard Q&A for Electric Motor and Generator Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Looks Like
This category of data originates from winding, insulation, final assembly, and testing departments of electric motor factories and power equipment enterprises. It includes winding process cards, insulation treatment records, dynamic balance reports, voltage withstand insulation test records, type test reports, and factory inspection reports. Data fields cover winding turns, copper wire specifications, insulation material batches, test voltage, temperature rise values, and additional metrics. Units include turns, millimeters, volts, degrees Celsius, and others. Data updates occur synchronously when a single unit or batch of products is produced, and when product type changes are implemented. Data sources include electromagnetic design data, raw material batch records, production equipment operation logs, and ERP/MES systems.

## Constraints on Multi-turn Dialogue and Prompt Engineering for This Category
Process and test data for this category must match the exclusive parameters of a single unit or batch of products. Multi-turn dialogue must retain context information such as winding turns and insulation batches for each product, to avoid mixing data across batches. Documents include professional content across electromagnetic, insulation, and mechanical balance domains. Prompts must explicitly limit retrieval scope to exclusive documents from the corresponding department, to prevent mixing in process data from other categories. Data updates occur frequently and change often. Dialogue must trigger real-time association with the latest type change records. Single-turn dialogue context length must be limited, to avoid response delays caused by loading too many old batch data. Users typically initiate multi-round parameter checks for a single product. The dialogue workflow must adapt to complete scenarios from process parameter queries to anomaly analysis.

## Three Common Configuration Mistakes
- Symptom: After upgrading to FastGPT v4.17.0, the dialogue window reports an error. Uploading files and text datasets fails. Only the template import function works normally. Cause: After the upgrade, the interface routing logic does not adapt to the upload path for non-template files. Requests fail to match the target dataset interface correctly.
- Symptom: Prompts cannot be used to specify a specific dataset for search. Retrieval results include process documents across the entire platform. Cause: The `variables` configuration is not used to bind the exclusive identifier of the target dataset. Prompts do not limit retrieval scope to exclusive motor manufacturing process documents.
- Symptom: The dialogue opening screen only displays a single preset guide question, and cannot provide multiple optional initial query directions. Cause: Multiple sets of preset questions are not configured in the `messages` initial parameters. The opening screen variable setting for multi-turn dialogue is not enabled.

## How to Verify Successful Configuration
- Upload a winding process card file, initiate a retrieval request, and confirm that returned results only include relevant content from this document, with no irrelevant documents from other categories.
- Initiate more than two rounds of parameter follow-up questions, and confirm that the dialogue context retains the previous round's winding turns or insulation batch information, with no context loss.
- View the dialogue opening screen, and confirm that multiple preset guide questions are displayed, covering core scenarios such as winding parameter queries and test standard checks.
- Upload a dynamic balance report file, confirm that the upload succeeds and retrieval can be initiated normally, with no interface errors or data loss.
