# Q&A for Motor and Generator Manufacturing Process Specifications and Technical Standards: Workflow Orchestration

## What the data for this category looks like
Process and standard data for motor and generator manufacturing comes from electromagnetic design databases, copper wire and insulation material batch ledgers, winding equipment logs, dynamic balancing machine data, electrical test bench records, and ERP and MES systems. Daily produced documents include winding process cards, insulation treatment records, dynamic balancing reports, voltage withstand insulation test reports, and type and factory inspection test reports. Data fields include winding turns, paint immersion temperature, dynamic balancing accuracy, voltage withstand value, and others. Update frequency is once per product unit or batch, with synchronization after each form change.

## What constraints these characteristics impose on workflow orchestration
Data sources are scattered across multiple types of equipment and systems. Workflows must support synchronous or real-time pulling from multiple data sources.
Data updates occur frequently and are tied to individual units or batches. Workflows must bind variables at the product batch level to avoid cross-batch data confusion.
Documents contain multiple types of professional fields. Workflows must preset field extraction rules to ensure only compliant process and test data is called during Q&A.
The most time-consuming tasks include checking winding turns and wiring, and controlling paint immersion and drying. Workflows must preset high-frequency Q&A nodes to reduce manual checking costs.
Errors can lead to serious issues such as winding burnout and insulation breakdown. Workflows must add anomaly verification nodes to trigger alerts for non-compliant results.

## How to configure
The following configuration examples are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Single search limit | Top 6 results | Single motor manufacturing process documents are lengthy. Too many results will exceed the context window and reduce Q&A accuracy |
| Maximum context | 8000–12000 token | Process documents associated with a single motor include winding, insulation, test and other content. Sufficient context is required for associated verification |
| `variables` | Bind winding turns and voltage withstand value fields | Core verification parameters for process specification and standard Q&A are winding turns and voltage withstand value. These must be used as core workflow variables |
| `nodeId` | Bind test result verification node | Data compliance verification must be triggered synchronously when the test data verification node runs, to ensure test data called during Q&A meets standards |
| Timeout setting | 300 seconds | Querying test data requires connecting to multiple types of equipment and systems. Sufficient response time must be reserved to avoid execution interruptions |
| Result display method | Group by document type | Process documents are divided into winding, insulation, test and other categories. Grouped display helps engineers quickly locate target content |

## Three common mistakes
- Symptom: After the workflow executes an SQL query successfully, no content is displayed in the AI dialog box. Cause: The workflow's output `variables` are not bound to the dialog display node, so results are not synchronized to the dialog context.
- Symptom: In a private deployment environment, an Application error is displayed when accessing the workflow editing interface. Cause: The cross-domain access whitelist for the local service is not configured, so the frontend cannot pull workflow configuration data.
- Symptom: After setting conditional judgment rules in the workflow, the dialog context history is not cleared. Cause: No context reset configuration is added after the conditional trigger node, or the node trigger logic is not correctly associated with the specified `nodeId`.

## How to confirm the configuration is complete
- Manually trigger the workflow to verify that SQL query results are correctly returned and displayed in the AI dialog box, grouped by document type.
- Check that the `variables` configuration is bound to core process fields such as winding turns and voltage withstand value, to ensure parameters called by the workflow meet category requirements.
- Test the conditional trigger logic to verify that context reset operations are triggered when input meets the specified judgment conditions.
- View the workflow node status logs to confirm that all nodes have executed successfully, with no timeout or error messages.
