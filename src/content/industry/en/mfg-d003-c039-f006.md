# Q&A for Motor and Generator Manufacturing Process Specifications and Technical Standards: Quote Source and Traceability

## What data for this category looks like
Data for this category primarily comes from electromagnetic design documents, copper wire and insulation material batch records, winding equipment parameters, balancing machine operation logs, electrical test bench test results, and ERP/MES systems. Data is updated per individual motor or production batch, and synced with every form modification. Daily produced documents include winding process cards, insulation treatment records, dynamic balance reports, voltage withstand insulation test reports, and type and factory test reports. Fields include winding turns, insulation class, test voltage, and batch number, with corresponding units of turns, class identifiers, volts, and batch numbers.

## What constraints do these characteristics impose on the "quote source and traceability" link
Data for this category is updated per unit or batch and linked to batch numbers. Quote traceability must bind to specific production batches and corresponding equipment operation records to avoid cross-batch confusion. Professional documents contain precise fields with units such as winding turns, insulation class, and test voltage, which must match the original text of process specifications and test reports, and cannot rely on general semantic matching. Long documents such as type test reports contain multi-stage test data. When chunking, the integrity of test nodes must be retained to avoid losing associated logic after splitting. The high-frequency update feature requires the knowledge base to support incremental indexing to ensure that quoted content is synchronized with the latest production data.

## How to set the configuration
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Motor manufacturing process documents contain long fields such as turns and test parameters, this range can hold a single core test report or process card content |
| `responseData` | Return the first 300 characters of the original text | Core parameters of process specifications and test reports are concentrated at the beginning or key nodes of the document. Truncating the first 300 characters can quickly display traceability basis |
| `detail` | Enable | It is necessary to display key identifiers such as the batch number and test date of the quoted document to facilitate verification by production personnel |
| Chunk length | `1000–1500 characters` | The length of a single process or test step in winding process cards and test reports is concentrated in this range, avoiding splitting across process nodes |
| Single search limit | Top 6 entries | Production documents for a single motor do not exceed 6 copies; too many quotes will exceed context limits |
| Reranking | Sort by matching degree in descending order | It is necessary to prioritize test reports or process cards with a high degree of matching to the current process question |

## Three common mistakes
- Phenomenon: Only text datasets are quoted, and no quoted content exists for other format datasets. Reason: The quote switch for the corresponding format dataset is not enabled, or uploaded non-text files have not completed OCR text indexing.
- Phenomenon: After configuring dynamic value passing for knowledge base search variables, the AI does not return quoted documents. Reason: The knowledge base variable is not bound to the current production batch, and the search scope is not limited to documents of the corresponding batch.
- Phenomenon: Quoted display content cannot be hidden after embedding the page via iframe. Reason: The quote display switch is not turned off in the embedding parameters, or the style override rules for the embedded page are not configured correctly.

## How to confirm the configuration is correct
- Initiate a process query about winding turns, and check whether the returned result includes the batch number and original text fragment of the quoted document.
- Simulate a query after a form modification, and confirm that the returned quoted content is the latest updated document.
- Upload a test process card, search for the corresponding keyword, and verify that the number of returned quotes matches the single search limit configuration.
- View the knowledge base index log, and confirm that incrementally updated documents have completed indexing with no failed records.

The values given are common starting points and should be measured against the reader's own samples.
