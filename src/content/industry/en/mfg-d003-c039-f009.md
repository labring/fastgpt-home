# Process Specification and Technical Standard Q&A for Electric Motor and Generator Manufacturing: Model Access and Configuration

## What this category of data looks like
This category of data originates from business systems and equipment used in the winding, insulation, final assembly, and testing departments of motor factories and power equipment enterprises. It includes documents such as winding process cards, insulation treatment records, dynamic balance reports, voltage withstand insulation test records, and type and factory test reports.
Data sources include electromagnetic design data, copper wire and insulation material batch information, winding equipment, balancing machines, electrical test benches, and ERP/MES systems. Updates occur when each product or batch of materials completes production, and are synchronized after each product type change. Documents contain both structured and unstructured fields, including equipment parameters, batch information, and test values.

## Constraints on model access and configuration from these characteristics
This category of data is multi-source and dispersed, including direct device-collected data, ERP/MES business data, and professional test reports. Model access configuration must support unified parsing of multi-format data sources.
The high-frequency update rhythm (per product, per batch production, and after each type change) requires configuration to support incremental synchronization trigger logic and update frequency.
Documents include professional fields such as winding turns, insulation system parameters, and vibration test values. Configuration must support recall rules adapted to motor manufacturing professional terminology, and support associative retrieval across multiple documents. This prevents disconnection between process and test data caused by isolated recall.

## How to set the configuration
These configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
|---|---|---|
| `maxContext` | 8000–12000 token | Adapts to the long-text context requirements of motor manufacturing process documents and test reports, avoiding truncation of core information such as winding turns and insulation parameters |
| `maxTokens` | 4000–6000 token | Limits the output length of single-round responses, ensuring that professional content such as process steps and test results is complete and not redundant, and adapting to the reading habits of engineering personnel |
| `quoteMaxToken` | 1500–2000 token | Limits the total length of recalled reference documents, prioritizing core document fragments such as winding process cards and dynamic balance reports, avoiding interference from irrelevant content in responses |
| `temperature` | 0.1–0.3 | Reduces the randomness of responses, ensuring that answers to process specifications and technical standards conform to the rigor of official documents, and avoiding incorrect content that does not match motor manufacturing specifications |
| `AIPROXY_API_ENDPOINT` | Fill in according to the actual address of the deployed proxy service | Adapts to unified proxy configuration for multi-source model access, facilitating unified management of model call permissions and traffic in motor manufacturing scenarios |
| `AIPROXY_API_TOKEN` | Fill in according to the exclusive token generated by the proxy service | Ensures the security of model calls, avoiding unauthorized access that could lead to leakage of sensitive process data |

## Three common configuration errors
-  Phenomenon: A 404 status code is returned when calling the model, and normal response results cannot be obtained. Cause: `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN` is not filled in correctly, or the proxy service is not connected to a model interface adapted for motor manufacturing scenarios.
-  Phenomenon: Recalled reference documents only include scattered test data, and do not link to corresponding winding process card content. Cause: Rules supporting associative retrieval across multiple documents are not configured, so process and test data for the same batch of products cannot be bound.
-  Phenomenon: Response content includes incorrect parameters that do not match motor manufacturing specifications, such as deviations in insulation thickness values. Cause: The `temperature` configuration value is too high, causing the model-generated content to deviate from official process specifications and technical standards.

## How to confirm the configuration is correct
-  Upload a winding process card and a dynamic balance report, submit the query "Does the winding turns of this batch of products meet the process requirements?", and verify that the recalled reference documents include corresponding document fragments.
-  Submit a query containing professional terminology, such as "Insulation treatment steps for stator windings", and verify that the response content matches the rigorous wording of official process specifications, with no obvious errors.
-  View the model call log to confirm that the configurations for `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` have been correctly read, with no connection timeouts or permission error messages.
-  Submit a query requiring cross-document associative retrieval, such as "Analyze the insulation performance of this product by combining insulation treatment records and voltage withstand test reports", and verify that the recalled content includes relevant fragments from both document types.
