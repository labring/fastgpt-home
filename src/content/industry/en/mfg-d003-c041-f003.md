# Electroplating and Chemical Surface Treatment Process Specification and Technical Standard Q&A: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Includes
This category covers multiple types of business documents from electroplating plants and hardware surface treatment workshops, including bath solution analysis records, process parameter cards, fixture usage records, film thickness and adhesion test reports, hazardous waste management ledgers, and wastewater monitoring records. Data sources include customer surface treatment specifications, bath solution test results, rectifier operation data, online water quality monitoring data, and hazardous waste management ledgers. Data is updated per bath cycle, per shift, or according to fixed monitoring cycles.

## Constraints for Multi-turn Dialogue and Prompt Engineering
Data for this category is updated frequently and has fine granularity. Multi-turn dialogue must accurately track real-time parameters of the current bath cycle to avoid interference from old data across different bath cycles. Documents include multiple content types such as process parameters, monitoring values, and hazardous waste records. Prompt engineering must clearly define retrieval scopes to prevent mixing in irrelevant compliance documents or documents from non-current bath cycles. Data sources include both online real-time monitoring and offline records, so multi-turn dialogue must support precise context binding and truncation. This ensures only information related to the current business is retained, avoiding response delays caused by retrieval overload.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind the unique identifier of the current electroplating bath | Distinguish dialogue contexts for different bath cycles, preventing cross-bath parameter confusion |
| `messages` | Retain the most recent 15–25 dialogue rounds | Cover the full process from fixture installation to finished product inspection for a single bath, matching the data update rhythm of each bath cycle |
| `variables` | Bind bath solution type and fixture specification variables | Limit retrieval scope to process parameter cards and monitoring records for the corresponding bath |
| Maximum context length | 7000–11000 characters | Adapt to the field length of documents such as bath solution analysis records and film thickness reports, avoiding truncation of critical values |
| Single retrieval limit | Top 5–7 matching documents | Control the number of retrieval results, preventing inclusion of excessive historical data from non-current bath cycles |
| Context truncation rule | Retain entries in reverse chronological order of dialogue time | Prioritize loading recent bath solution test and online monitoring data, aligning with per-shift and fixed-cycle update frequencies |

All configurations above are based on the interface and parameter logic of FastGPT v4.17.0.

## Three Common Configuration Mistakes
- Phenomenon: A "context does not exist" prompt appears when calling historical dialogue, or parameters from old bath cycles fail to load. Cause: The fixed bath cycle identifier is not bound via `chatId`, leading to incorrect categorization or automatic cleanup of historical dialogue.
- Phenomenon: Single-turn dialogue response time exceeds 10 seconds. Cause: The number of documents retrieved per request is not limited, or the retrieval scope is not restricted via `variables`, causing the system to scan all historical workshop documents.
- Phenomenon: Process parameters returned by the dialogue do not match the actual parameters of the current bath, with data from other bath cycles included. Cause: `variables` specifying the current bath number are not bound in the prompt engineering, so the retrieval scope fails to accurately match the current business scenario.

## How to Verify Correct Configuration
- Initiate a process query for the corresponding bath cycle, and confirm that returned parameters match the process parameter card of the current bath.
- Initiate a multi-turn dialogue, sequentially ask about bath solution concentration, fixture requirements, and film thickness standards, and confirm that each round of replies carries forward context from the previous round.
- Review the dialogue log storage record, and confirm that dialogue for the corresponding bath cycle has not been automatically cleaned up.
- Test the retrieval scope by entering keywords for other bath numbers, and confirm that the system does not return irrelevant document content.
