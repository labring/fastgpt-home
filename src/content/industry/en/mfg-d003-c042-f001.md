# Process Specification and Technical Standard Q&A for Petroleum Refining: HTTP Interfaces and External Systems

## What this category of data looks like
Data for process specifications and technical standards in petroleum refining scenarios comes from DCS/APC control systems, LIMS laboratory systems, tank farm metering systems, crude oil evaluation reports, equipment management systems, and energy management systems. Data update frequencies include three categories: real-time, shift-based, and daily. Document types cover operating procedures, production plans, material balance sheets, distillate export quality reports, interlock ledgers, shift handover records, and change management documents. Each individual document includes fields such as unit number, operating steps, material parameters, and interlock logic, with standardized units like pressure, temperature, and flow rate attached.

## What constraints these characteristics impose on HTTP Interfaces and External Systems
Since data sources include multiple industrial control systems and business systems, HTTP interfaces must support compatible authentication protocols and data formats for different systems to avoid cross-system call conflicts. Data update frequencies vary widely. Interfaces handling real-time data require short-cycle polling or event-triggered mechanisms. Documents updated daily can use batch synchronization tasks. Differences in document structure across types require interfaces to support parsing rules specified by document category. Interfaces must also reserve field expansion space to adapt to new process parameter items. In addition, timeliness requirements for process exception handling mean interface timeout settings must match the response windows of industrial systems, preventing production risks caused by delays.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {API key bound to industrial system}` | Complies with the interface authentication specification for FastGPT v4.17.0, and adapts to authentication requirements for multi-source industrial systems |
| `variables` | Includes unit number and document type tag | Used to targeted pull process specification and technical standard documents for the corresponding unit |
| `responseData` | Only return operating steps, parameter thresholds, and interlock logic | Filters redundant fields to reduce data transmission overhead |
| Request timeout | 30–60 seconds | Matches the conventional response cycle of petroleum refining industrial systems |
| Document synchronization batch limit | First 8 entries per batch | Avoids occupying too many system resources in a single request |
| Knowledge base upload threshold | Calibrated based on actual measurements | Adapts to document libraries of different scales of refinery enterprises |

## Three Common Misconfigurations
- A 401 Unauthorized error is returned when calling the interface. The cause is that the `Authorization` parameter is not configured correctly, and an invalid or expired API key is used.
- After offline deployment, calling the interface prompts that the cl100k.tiktoken file cannot be loaded. The cause is that offline word segmentation resources are not configured in the local deployment environment, and external network word segmentation files are relied on.
- After uploading documents, only titles are returned in the knowledge base with no content. The cause is that the extraction rules for `responseData` are not specified correctly, and the mapping relationship of content fields is not configured.

## How to Confirm Proper Configuration
- Execute an authentication interface call using FastGPT v4.17.0, verify that the return status code is 200 to confirm the `Authorization` configuration takes effect.
- Pass test unit numbers and document types, check whether the `variables` parameter correctly pulls the corresponding documents in a targeted manner.
- Upload a single test document, verify whether `responseData` correctly extracts the target field content.
- Initiate a batch synchronization request, confirm that the system does not trigger overload alarms and meets internal enterprise resource occupancy requirements.
