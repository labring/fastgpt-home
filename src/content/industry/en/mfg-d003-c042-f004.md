# Process Specification and Technical Standard Q&A for Petroleum Refining: Workflow Orchestration

## What data for this category looks like
Process and standard data for petroleum refining comes from DCS/APC, LIMS, tank farm metrology, crude oil evaluation, equipment management systems, and energy systems. Data update frequencies include real-time, shift-based, and daily. Daily documents include operating procedures, production plans, material balance reports, distillate outlet quality reports, interlock logs, shift handover records, and change management documents. Fields cover crude oil density, distillation range temperature, product octane number, interlock trigger values, and more. Units include degrees Celsius, kilograms per cubic meter, megapascals, and more. Individual document lengths vary widely.

## Constraints on workflow orchestration from these characteristics
Multi-source data with real-time, shift-based, and daily update rhythms requires workflows to support parallel pulling of process parameters from different systems. This avoids single-node blocking. The variety of document types and mixed field units requires workflows to configure variable mapping rules. These rules adapt to field extraction and unit conversion for different documents. Multiple continuous units coupled via material and hydrogen networks require workflows to associate process nodes across multiple units. This enables cross-unit parameter verification. Attributes with severe error consequences require workflows to include reference validity checks. These checks intercept non-compliant process calls in advance.

## Three common misconfigurations
- Phenomenon: Workflow returns empty reference verification results, and does not flag non-compliant process standard reference content. Cause: Reference verification trigger logic is not configured, and field mapping for `variables` is not correctly bound.
- Phenomenon: The dropdown menu only shows single variable options, and cannot reference multiple process parameters at the same time. Cause: Variable batch binding configuration is not enabled, and only single-field mapping binding is completed.
- Phenomenon: Debug nodes enter an unending loop, and the interface stop button does not respond. Cause: No timeout interruption node is configured in the workflow, and blocking occurs due to cycle dependence on real-time data from multiple systems.

## How to confirm proper configuration
- Submit a crude oil property verification request, and check whether the returned results mark whether the referenced distillate outlet quality report complies with process standards.
- Test the multi-variable binding operation, and confirm that multiple process parameter variables can be selected at the same time.
- Start node debugging, and verify that the process automatically terminates after the timeout period elapses.
- View workflow logs, and confirm that the timing of multi-source data pulling conforms to unit coupling logic.
