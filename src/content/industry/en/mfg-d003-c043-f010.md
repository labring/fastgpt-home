# Q&A for Batch Fine Chemical Synthesis Process Procedures and Technical Standards: Knowledge Base Retrieval and Recall

## What This Category's Data Looks Like
Daily documents for batch fine chemical synthesis include batch production orders, feeding material verification slips, reaction process logs, cleaning records, inspection reports, deviation and change orders. Data sources include the formula and process library, raw material batches, reactor DCS systems, weighing systems, LIMS, and warehouse management systems. Update frequency is once per production batch or each critical process step. Document fields include batch number, feeding quantity (kg or L), reaction temperature (℃), residence time (hours) and other specialized units of measurement. Some documents involve formula confidentiality and cleaning confirmation requirements.

## What Constraints Do These Characteristics Impose on Knowledge Base Retrieval and Recall
Multi-variety, multi-step batch switching business characteristics lead to large document volumes in the knowledge base and require precise batch filtering to avoid irrelevant cross-batch content recall. Batch-based update rhythms require retrieval systems to support incremental synchronization and version matching, ensuring that the latest documents for the current production batch are recalled. The presence of specialized units and sensitive content requires retrieval to support field matching and permission control, preventing unit ambiguity and sensitive information leakage. Deviation and change orders contain content that conflicts with original process documents, requiring retrieval systems to support conflict content marking and priority sorting.

## Configuration Settings
This guide is based on FastGPT v4.17.0. The following is the knowledge base retrieval and recall configuration plan for this category:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the specialized terminology density of fine chemical process documents, avoids recalling irrelevant general chemical content, calibrated via actual testing |
| `limit` | Top 8 entries | Balances context length and recall coverage, adapts to the total length of single-batch process documents, calibrated via actual testing |
| `searchMode` | Exact Match | Prioritizes recalling exact match results containing batch numbers and feeding quantity units, adapts to retrieval needs for multi-batch switching |
| `usingReRank` | Enabled | Re-ranks recall results by professional relevance, resolves sorting issues when content conflicts exist across multiple documents |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands technical term synonyms, such as expanding "feeding material verification" to "feeding material inspection", adapting to different expressions in process documents |
| `collectionIds` | Knowledge base collections bound to the target batch | Limits retrieval scope to only process, inspection, and deviation documents associated with the current production batch, avoiding irrelevant cross-batch content recall |

## Three Common Misconfigurations
- Scenario: After calling the API with knowledge base configuration, no corresponding content is retrieved, returning empty results or status code 400. Cause: The `collectionIds` parameter is not bound correctly, or the passed knowledge base collection ID does not match the document collection of the target production batch.
- Scenario: Recall results include process documents for other product varieties unrelated to the current batch, and the generated answer does not reference professional knowledge base content. Cause: Exact match `searchMode` is not enabled, or `collectionIds` is not limited to the knowledge base collection of the current batch, leading to overly broad retrieval scope.
- Scenario: Content conflicts exist between process documents and deviation orders in the knowledge base, but the recall results do not mark conflicting items and cannot quickly locate conflicting positions. Cause: `usingReRank` is not enabled to sort conflicting content by priority, and pre-rules for conflict detection are not configured.

## How to Verify Proper Configuration
- Log in to the FastGPT backend, check if the currently configured `collectionIds` are bound to document collections corresponding to the current production batch, including process, inspection, and cleaning records.
- Enter a test question such as "Feeding material verification requirements for batch XX", check if the `similarity` score of the recall results falls within the 0.75–0.85 range.
- Verify the re-ranking function: Enter a test question involving conflicting content, check if the returned results are sorted to prioritize the latest deviation or change documents.
- Call the API with the correct `collectionIds` parameter, check if the returned retrieval results only include documents relevant to the current batch.

The values provided here are common starting points, and should be validated against the reader's own samples.
