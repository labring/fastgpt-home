# Q&A for Batch Synthesis Process Specifications and Technical Standards in Fine Chemicals: Deployment and Upgrade

## What Data for This Category Looks Like
Daily documents for this category include batch production instructions, feeding verification sheets, reaction process records, cleaning records, inspection reports, deviation and change orders. Data sources include the formula and process library, raw material batches, reactor DCS, weighing systems, LIMS, and warehouse systems. Updates occur per batch production or each critical step. Data fields include feeding volume, reaction temperature, reaction duration, cleaning residue detection values, and others. Some formula fields require confidentiality, and full chain information of raw materials, equipment, and tests associated with the batch must be matched.

## Constraints Imposed by These Characteristics on Deployment and Upgrade
Data for this category consists mostly of batch-associated heterogeneous documents, and retrieval must be linked in production process order. Deployments must support bulk data ingestion from multiple source systems. Some formula fields require confidentiality, so fine-grained access permissions must be configured. High-frequency updates per batch or critical step require the knowledge base to support incremental updates without full re-scanning. The multi-product switching characteristic of batch production requires deployments to quickly switch between process document libraries for different categories. Upgrade processes must ensure batch data consistency, and prevent cross-version data loss or broken links.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 1000 | Adapts to the concurrent request limit for multi-source system access for this category, and prevents database connection exhaustion |
| `MONGODB_URI` | Points to a dedicated MongoDB instance storing batch documents and process libraries | Isolates sensitive formula data from other business data to protect data security |
| `REDIS_URL` | Configured as a local cache instance, with a cache duration set to 3600 seconds | Reduces database pressure during high-frequency retrieval of batch-associated data, and adapts to the high-frequency update requirements per batch |
| `STORAGE_S3_ENDPOINT` | Points to the enterprise internal object storage service | Stores documents with attachments such as feeding verification sheets and reaction process records, and adapts to multi-format document access |
| `ROOT_KEY` | Generates a dedicated key according to the enterprise permission system | Controls access to background configurations, and prevents unauthorized personnel from modifying process knowledge base configurations |

## Three Common Misconfigurations
- Symptom: The knowledge base fails to load image attachments in documents, and image links in retrieval results are invalid. Cause: `STORAGE_S3_ENDPOINT` is not configured to point to the enterprise internal object storage service, or object storage permissions are not granted to the FastGPT service.
- Symptom: Model interface calls return a 400 error, with FastGPT version v4.17.0. Cause: Model request parameters do not match the exclusive prompt format for fine chemical process Q&A, or the `REDIS_URL` configuration is incorrect, resulting in lost session context.
- Symptom: After deployment via docker-compose runs for a period of time, the knowledge base and workflow pages display blank content, but interface calls function normally. Cause: The MongoDB instance specified by `MONGODB_URI` has a connection timeout without automatic reconnection, or the cache configuration does not adapt to high-frequency updated batch data.

## How to Verify Configurations Are Correct
- Perform a bulk import of a set of typical batch production instruction documents, and verify that parsed document fields fully match core business requirement fields including feeding, reaction, and testing data.
- Call the model interface to initiate a process-related query, and confirm that returned results are associated with raw material and equipment information for the corresponding batch.
- Review database connection count monitoring, and confirm that the upper limit set by `DB_MAX_LINK` is not continuously exhausted.
- Upload a cleaning record document with image attachments, and confirm that images in retrieval results are accessible normally.
