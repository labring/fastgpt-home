# Spinning and Weaving Process Specifications and Technical Standards Q&A: Tool Calling and Plugins

## What this category of data looks like
This category of data comes from daily production documents and equipment-collected data from cotton spinning, chemical fiber spinning, woven fabric, and knitting enterprises. Daily documents include cotton blending or ingredient lists, process setup sheets, equipment operation records, yarn and grey fabric inspection records, and defect records. Data sources cover raw fiber inspection reports, ERP systems, real-time data from spinning and weaving machines, evenness testers, fabric inspection machine test results, and order specification requirements. Data update frequency changes with production batches, shifts, and fabric lot numbers. Individual documents typically include fields such as fiber type, process parameters, test values, and lot numbers, with some fields having clear physical units.

## What constraints these characteristics impose on tool calling and plugin workflows
Since data updates change with production batches, shifts, and fabric lot numbers, tool calling must adapt to data retrieval logic with high real-time requirements, and avoid using overly long cache cycles. Differences in fields across multiple data sources require tool calling configurations to support cross-system field mapping, ensuring process parameters and test data from different sources can be uniformly identified. The process parameters and test records in individual documents are moderately lengthy, but bulk data volume is large. Tool calling must limit the number of documents retrieved in a single request to avoid exceeding the context capacity limit. Additionally, defect records are strongly bound to fabric lot numbers, so tool calling must support precise association of corresponding test data by lot number.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to tool calling needs for two different scenarios: process parameter queries and defect analysis |
| `functionCall` | `enabled` | Supports calling external equipment data interfaces and custom model APIs |
| Single search limit | `Top 6 entries` | Individual spinning and weaving process documents are moderately lengthy; too many results will exceed the context window |
| Maximum context | `8000–12000 token` | Can accommodate complete content of multiple batches of cotton blending, setup parameters, and test records |
| Tool calling timeout | `300 seconds` | Adapts to the collection and return cycle of equipment data interfaces |
| Knowledge base matching threshold | `Calibrated via actual testing` | The accuracy of matching process parameters and test records needs to be adjusted based on production scenarios |

## Three common configuration mistakes
- A `400 <400> InternalError.Algo.InvalidParameter: messages with role` error is returned when starting the project, and the MongoDB visualization tool can connect normally. The cause is that the role parameter was not formatted correctly in the tool calling configuration, causing the model to fail to recognize the incoming context role.
- When using HTTP-returned equipment data for knowledge base analysis, the results have significant deviation. The cause is that the fields returned by HTTP were not mapped to the standard fields of spinning and weaving process documents via the tool calling configuration, leading to incorrect parameter matching.
- No response is received when calling an API not in the model list. The cause is that `toolChoice` was not correctly configured for custom calling mode, and the interface parameters and verification information for the corresponding model were not supplemented.

## How to verify correct configuration
- Initiate a single-batch cotton blending parameter query, and check whether the tool calling returns the fiber indicators and blending records for the corresponding batch.
- Trigger a defect analysis task for a specified fabric lot number, and confirm whether the tool calling can retrieve the test data from the corresponding fabric inspection machine.
- Test calling a custom model API, and check whether analysis results for process parameters can be returned normally.
- View the tool calling logs in FastGPT v4.17.0, and confirm that the timeout time and context configuration match the set values.

The values provided are common starting points and should be measured against the reader's own samples.
