# Process Specification and Technical Standard Q&A for Meat Products and Slaughter Processing: Workflow Orchestration

## What data for this category looks like
The data for this category covers daily production documents from slaughterhouses, cooked meat and frozen prepared food enterprises. Documents include quarantine certificates, slaughter and cutting records, ingredient pickling records, thermal processing records, cold chain temperature records, and microbial test reports.
Data sources include animal quarantine information, supplier batches, production traceability systems, temperature collection equipment, metal detection equipment, and laboratory test results.
Update frequency follows per production batch, per shift operation, and continuous temperature control collection.
Document fields include batch number, quarantine number, temperature value, test indicators and results. Units include degrees Celsius, batch numbers, and test qualification marks.

## Constraints imposed on workflow orchestration by these characteristics
Since data is updated per batch, per shift, and via continuous temperature control, workflows must support triggering nodes by batch to avoid mixing data across batches.
Requirements for separating raw and cooked zones and controlling sterilization temperatures require workflows to include parameter validation steps. These steps verify the legality of temperature values and zone identifiers.
Biological risk and quarantine association requirements require workflows to bind associated fields for batch and quarantine information. This ensures complete traceability links.
Continuous high-frequency updates of temperature control data require workflows to support real-time reading of the latest temperature records. This avoids using expired data to trigger Q&A logic.
The timeliness of microbial test results requires workflows to prioritize matching the latest test data for the current batch when calling standard Q&A.

## Configuration guidelines
The following configurations are designed for the workflow function of FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| `variables` | Bind batch number, quarantine number, cold chain temperature threshold | Based on batch traceability and quarantine association requirements for category data, to ensure Q&A matches accurate data for the corresponding production batch |
| `nodeId` | Assign unique identifiers to temperature control verification and quarantine matching nodes | Based on workflow node scheduling requirements, to avoid confusion in node calls |
| Global variable storage rules | Isolate temporary data by production batch | Based on the per-batch update frequency of data, to avoid cross-batch data contamination |
| Node call timeout | 600 seconds | Based on real-time requirements for continuous temperature control data, to ensure node calls are not delayed |
| Context call limit | Top 3 batch-related records | Based on raw/cooked zone separation and sterilization temperature control requirements, to prioritize matching the latest production data |

## Three common misconfigurations
- Phenomenon: When calling a workflow as a tool in a simple application, the uploaded production record file cannot pass its link to workflow nodes. Cause: No file link receiving parameter is added in the workflow's `variables` configuration, breaking the parameter transfer link.
- Phenomenon: A parameter verification failure error appears when running a process Q&A workflow. Cause: No associated variables for batch number and quarantine number are bound, making it impossible to match standard process data for the corresponding production batch.
- Phenomenon: The initially passed global variable value displays normally, but modified values in the same conversation do not take effect in subsequent components. Cause: No real-time update trigger rule is configured for global variables, so components use the initially stored value.

## How to verify successful configuration
- Check whether the `variables` configuration item includes category-specific fields such as batch number and quarantine number, and confirm the binding logic matches the production process.
- Trigger a test call simulating batch production, and verify that workflow nodes read the cold chain temperature data of the corresponding batch as expected.
- Upload a simulated production record file, and confirm that the file link is correctly passed to the workflow's tool nodes.
- Modify the test value of the global variable, and confirm that subsequent components can obtain the updated variable content.

The values provided are common starting points and should be measured against the reader's own samples.
