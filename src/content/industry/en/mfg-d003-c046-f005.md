# Process Specification and Technical Standard Q&A for Meat Products and Slaughter Processing: Tool Calling and Plugins

## What data looks like for this category
This category's data comes from animal quarantine information, supplier batch ledgers, production traceability systems, temperature collection devices, metal detection devices, and laboratory test reports. Daily documents include quarantine certificates, slaughter and cutting records, ingredient marinating records, thermal processing records, cold chain temperature records, and microbial test records. Quarantine certificates include batch numbers and quarantine identification numbers. Slaughter records note carcass weight and cutting station information. Cold chain temperature records use degrees Celsius as the unit. Microbial test results include colony count units. Data updates follow this cadence: Corresponding batch documents are generated for each product batch, station operation records are updated per shift, and collected data is generated in real time for continuous temperature control links.

## Constraints imposed by these characteristics on the tool calling and plugins workflow
The batch association feature of this category requires tool calls to bind corresponding production batch parameters, to avoid information misalignment caused by cross-batch retrieval. The real-time data requirement for continuous temperature control requires plugins to support high-frequency data pulling, and the response duration of a single call must be controlled. The existence of multiple document types requires tool calling plugins to be compatible with the parsing formats of structured ledgers and unstructured test reports. The rapid processing requirements of production links limit the maximum waiting time for tool calls, and excessive response delays are not acceptable. Biological risk and compliance requirements mean that tool call results must include traceable call logs and source identifiers. Compliance requirements for microbial test data mean that tool calls must filter unqualified test results to avoid returning non-standard content.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Workflow/API tool selection | Set to "auto" | Supports automatically selecting tools matching the business, adapting to retrieval needs for multiple document types |
| Workflow/API function-call configuration | Enabled | Supports parameterized tool calls, accurately passing query conditions such as production batches |
| Tool call timeout duration | 30 seconds | Matches the rhythm requirements of real-time pulling of continuous temperature control data and rapid processing |
| Single tool call limit | Top 3 entries | Avoids excessive data loading affecting response speed in production links |
| Context window size | 8000 token | Accommodates associated document data across multiple batches |
| Document parsing tool switching | Preset based on business document type | Supports replacement with custom parsing tools adapted to this category |

## Three Common Mistakes
- Symptom: Returns parameter errors or status code 400 when calling the OpenApi interface. Cause: Failed to correctly declare supported tool parameters in the `functionCall` configuration, or the `toolChoice` setting does not match the interface call parameters.
- Symptom: When entering a simple question of only a dozen characters, the tool call result is output all at once instead of using streaming return. Cause: Failed to correctly configure the streaming output trigger rule, or did not use FastGPT v4.17.0 or a later version.
- Symptom: The content extraction node cannot call the self-built model interface. Cause: Failed to enable custom model support for `functionCall` in the system configuration, or the node configuration did not check the option to allow calling external models.

## How to Verify Proper Configuration
- Initiate a query that includes a production batch, verify that the tool call return results only associate document data for the corresponding batch.
- Test high-frequency calls for continuous temperature control data, verify that the response duration meets the business rhythm requirements.
- Call the OpenApi interface, verify that the returned tool call parameters match the configured items.
- Switch the document parsing type, verify that the plugin can correctly adapt to the parsing of structured ledgers and unstructured test reports.

The values provided are common starting points and should be measured against the reader's own samples.
