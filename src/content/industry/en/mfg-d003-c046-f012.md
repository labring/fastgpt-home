# Q&A for Meat Products and Slaughter Processing Workflow Procedures and Technical Standards: Deployment and Upgrade

## What data looks like for this category
Data sources for this category include animal quarantine information, supplier batch records, production traceability ledgers, cold chain temperature collection data, metal detection results, and laboratory microbial test reports. Daily documents cover quarantine certificates, slaughter and cutting records, ingredient marinating records, thermal processing records, cold chain temperature control logs, and microbial test documents.
Data is updated by production batch and shift. Continuous temperature control data is collected in real time. Fields include batch number, quarantine qualification mark, temperature threshold, microbial test indicators, and others. Units include degrees Celsius, kilograms, total colony count limits, and others.

## What constraints these characteristics impose on deployment and upgrade
Real-time temperature control and batch-bound data requirements for this category require support for high-frequency, small-batch data writes during deployment, and adaptation to multi-source heterogeneous data access.
The strong association between batches and quarantine information requires the knowledge base index to accurately match batch numbers and quarantine identification fields, to avoid cross-batch data confusion.
Strict control of raw and cooked product separation and sterilization temperature requires the Q&A model to accurately call process parameters. Dedicated data isolation storage must be configured during deployment.
Continuously updated log-type data requires adaptation to incremental synchronization mechanisms, to avoid excessive resource usage from full synchronization.
Compliant storage of biological risk-related data requires configuring storage paths that meet industry data security requirements. Original data access permission configurations must be retained during upgrades.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://localhost:27017/fastgpt_meat` | Stores structured production data such as batches and quarantine records, matching the data storage needs of this category |
| `REDIS_URL` | `redis://:custompass@localhost:6379/0` | Caches real-time temperature control data and frequently queried process parameters, reducing database access latency |
| `DB_MAX_LINK` | `20–30 connections` | Adapts to the connection count requirements of high-frequency data writes across multiple batches for this category, avoiding connection exhaustion |
| `FE_DOMAIN` | `http://192.168.1.200:3000` or the enterprise's own secondary domain name | Configures local area network or public network access addresses, adapting to internal office network scenarios of slaughterhouses |
| `STORAGE_S3_ENDPOINT` | Set based on actual measurement | Stores unstructured documents such as cold chain temperature control logs and test reports, adapting to the enterprise's existing storage architecture |
| `ROOT_KEY` | Randomly generated 32-character string | Configures administrator access permissions, ensuring secure control of production data |

## Three common errors
- The symptom is that the login interface displays the container's internal IP, and the system cannot be accessed after replacing it with a local area network IP. The root cause is that the `FE_DOMAIN` configuration was not updated to the corresponding local area network or public network address, leading to incorrect front-end resource binding.
- The symptom is that the service fails to start normally after modifying the administrator password, and the Q&A module is unresponsive. The root cause is that the corresponding service process was not restarted to load the new configuration and permission information.
- The symptom is that the Q&A result returns quarantine or temperature control data that does not match the current batch. The root cause is that the knowledge base index was not configured with association rules for batch numbers and quarantine identification fields, leading to retrieval confusion.

## How to confirm the configuration is correct
- Access the configured `FE_DOMAIN` address, confirm that the front-end page loads normally and administrator login can be completed.
- Import quarantine and production data for a single batch, initiate queries such as "Sterilization temperature requirements for the current batch", confirm that the returned results match the process parameters of the corresponding batch.
- Check database connection monitoring, confirm that the connection count configured by `DB_MAX_LINK` does not experience exhaustion.
- Upload documents such as temperature control logs and test reports, confirm that they can be stored and read normally.
