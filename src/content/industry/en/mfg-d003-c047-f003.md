# Process Specification and Technical Standard Q&A for Measuring Instruments and Laboratory Management: Multi-turn Dialogue and Prompting

## What the Data for This Category Looks Like
This category covers daily business documents for enterprise measurement rooms, quality laboratories, and CNAS system laboratories. Included documents are measuring tool ledgers, calibration plans, calibration certificates, periodic verification records, original test records, reference material ledgers, and deviation handling documents.
Data sources include measurement management systems, external calibration institution certificates, standard instruments, LIMS systems, and environmental monitoring equipment.
Data updates occur based on calibration cycles, each test, or abnormal events. Documents contain structured fields such as instrument number, calibration date, measured value, uncertainty, and traceability chain. Some certificate documents carry legal metrology markings and unit specifications.

## Constraints for Multi-turn Dialogue and Prompting
The data structure for this category is scattered with strict association requirements. Multi-turn dialogue must pull the latest measurement data across multiple data sources. Prompts must explicitly specify that only structured document fields from this category are referenced, to avoid mixing irrelevant business content.
Since data updates have no fixed cycle, dialogue context must support dynamic filtering of expired information to prevent reference to invalid calibration certificates or instrument status data.
Additionally, the traceability requirement for measurement data means multi-turn dialogue must retain key identifiers. Prompts must explicitly pass context association information to ensure each response builds on the business scenario from the prior query.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Dialogue context window | Last 20 historical messages | Retain key information required for traceability such as instrument numbers and calibration cycles, to avoid loss of core data |
| `chatId` parameter | Enable and bind to a unique session identifier | Track multi-turn dialogue within the same scenario, to meet batch traceability and compliance review requirements for measuring instruments |
| Prompt template | Fixedly limit reference to measuring tool ledger and calibration certificate fields | Ensure responses only use compliant documents from this category, to avoid generating irrelevant content |
| `variables` variable | Inject the current query's instrument number | Enable precise data matching for single-instrument scenarios, to narrow search scope |
| Tool call result binding | Automatically sync to the next round of `messages` | Carry over measured uncertainty and traceability chain data from parsed calibration certificates, to support subsequent traceability queries |
| Single-round context character limit | 800–1200 characters | Avoid context overload, while ensuring complete transmission of key measurement data |

## Three Common Misconfigurations
- Custom prompt template editing is not available in the open source version, only a small number of basic parameters can be adjusted. Cause: Not upgraded to FastGPT v4.17.0 or later; early open source versions do not grant full prompt configuration permissions.
- Calibration certificate parsing results returned by tool calls cannot be reused in subsequent dialogue. Cause: Tool call results are not bound to the current session's `messages` parameter, leading to context loss.
- `chatId` association information is not displayed in dialogue logs, causing session traceability to fail. Cause: The `chatId` parameter was not correctly passed during API calls, or session identifier tracking was not enabled in system configuration.

## How to Verify Proper Configuration
- Initiate a query for calibration information of a specific instrument, check that returned results only include compliant documents such as measuring tool ledgers and calibration certificates from this category.
- Initiate multi-turn traceability queries, confirm that subsequent dialogue can build on key information from the prior query such as instrument numbers and calibration dates, to enable coherent business queries.
- View API call logs, confirm that the `chatId` parameter has been correctly recorded and associated with the current dialogue context.
- Test the tool call function, confirm that parsed calibration data can be automatically carried over to the next round of dialogue, without requiring manual re-entry.

The values provided are common starting points and should be evaluated against the reader's own samples.
