# Process Specification and Technical Standard Q&A for Measuring Instruments and Laboratory Management: Knowledge Base Retrieval and Recall

## What this category’s data looks like
Data for this category originates from daily documents of enterprise metrology rooms and CNAS system laboratories. It includes measuring instrument ledgers, calibration plans, calibration certificates, interim check records, original test records, reference material ledgers, and deviation handling documents. Data sources cover metrology management systems, external calibration institution certificates, standard instruments, LIMS systems, and environmental monitoring equipment. Updates are triggered by calibration cycles, single test results, or abnormal events. Document fields include instrument number, accuracy grade, calibration validity period, measured value, uncertainty, traceability number, and some documents include physical units such as millimeters, milligrams, and pascals.

## Constraints Imposed by These Characteristics on Knowledge Base Retrieval and Recall
Multi-source heterogeneous data sources require the retrieval system to support unified field mapping across system documents, to avoid retrieval failure due to format differences. Non-fixed update rhythms require the retrieval module to support incremental synchronization, with updates triggered by calibration cycles or abnormal events, to ensure the timeliness of retrieved data. Structured fields with accuracy and uncertainty values require retrieval to balance semantic matching and precise keyword matching, to avoid missing key parameters. Traceability chain association requirements require retrieved results to be linked to full-chain documents such as corresponding measuring instrument ledgers, calibration certificates, and test records; retrieving only single records cannot meet traceability needs.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Documents such as calibration certificates and traceability records require high-precision matching. A threshold that is too low will introduce irrelevant metrology data, while a threshold that is too high will miss valid associated items |
| `limit` | Top 8 entries | Balances the detail of individual calibration certificates and associated interim check and test records, and avoids excessive context exceeding model processing limits |
| `searchMode` | semantic+keyword | Balances semantic matching for process specifications and keyword matching for structured fields such as instrument numbers and calibration dates, to improve retrieval accuracy |
| `usingReRank` | Enabled | Re-sorts retrieved entries by relevance, to resolve issues where semantic retrieval may mix low-relevance measuring instrument ledgers |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands synonymous expressions of metrology terms, such as expanding "calibration validity period" to "validity deadline, calibration expiration time", to adapt to different question phrasing |
| `collectionIds` | `["metrology_001", "lims_002"]` | Limits the retrieval scope to only knowledge bases for measuring instruments and laboratory management, to avoid mixing irrelevant documents from other categories |

## Three Common Mistakes
- Phenomenon: Returns empty values when calling the knowledge base assistant workflow via API. Cause: Failed to correctly configure `collectionIds` to limit the retrieval scope, or set the `similarity` threshold too high, resulting in no valid documents being retrieved.
- Phenomenon: Triggers a `quote type error` error when referencing knowledge base variables. Cause: The passed parameter format does not meet requirements, and does not follow the standard passing methods for configuration items such as `limit` and `similarity`.
- Phenomenon: The output result cannot hide knowledge base reference fragments. Cause: Failed to disable the reference display option in workflow output configuration, or failed to correctly filter reference fields from retrieval results.

## How to Verify Proper Configuration

- Confirm that no format errors occur when referencing knowledge base variables, and that passed parameters meet the format requirements of configuration items such as `similarity` and `limit`.
