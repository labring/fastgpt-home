# Process Specification and Technical Standard Q&A for Measuring Instruments and Laboratory Management: Deployment and Upgrade

## What data for this category looks like
Data for this category originates from enterprise metrology rooms, metrology management systems and LIMS platforms in CNAS-accredited laboratories, external calibration institution certificates, standard instruments, and environmental monitoring equipment. Daily documents include gauge ledgers, calibration plans, calibration certificates, interim verification records, original test records, reference material ledgers, and deviation handling forms. Data fields include instrument number, calibration validity period, measurement uncertainty, traceability chain information, and others. Units include μm, mg/L, days, and more. Updates are triggered based on calibration cycles, single test results, or abnormal events, with no fixed batch update window.

## What constraints does this category impose on the deployment and upgrade workflow
Data for this category has heterogeneous sources and requires strict traceability. During deployment, connections to databases and file storage of multiple systems must be established, and stable cross-system connection parameters must be configured. Data updates have no fixed cycle, so both incremental synchronization and manual trigger modes must be supported to prevent excessive resource usage from full synchronization. Documents such as calibration certificates and test records contain large numbers of images and structured fields. File parsing and storage for different formats must be supported, while ensuring data consistency to avoid traceability chain breaks. FastGPT v4.17.0 deployment must align with the storage and database configuration requirements of this category. During upgrades, existing index associations for metrology data must be retained.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `10–20 connections` | Metrology data mostly uses structured queries, this avoids database connection exhaustion impacting business operations |
| `PG_URL` | `PostgreSQL connection string for the metrology management system` | Directly connects to structured gauge ledger and calibration plan data |
| `REDIS_URL` | `Local Redis instance, port 6379` | Caches calibration certificate metadata and traceability chain information to reduce database query load |
| `STORAGE_S3_ENDPOINT` | `Enterprise internal object storage endpoint` | Uniformly stores files such as calibration certificates and test records, meeting traceability management requirements |
| `FILE_TOKEN_KEY` | `32-character random string` | Secures file access permissions, preventing unauthorized access to metrology documents |

## Three Common Misconfigurations
- Insufficient video memory configured when deploying the marker document parsing container, leading to failure to parse large calibration certificate PDFs and inability to generate text indexes. This occurs because container video memory quotas are not adjusted based on document page count and image resolution.
- Knowledge base image indexes fail to update alongside calibration cycles, and the interface displays image loading failures. This occurs because `STORAGE_S3_ENDPOINT` is not configured correctly, making it impossible to access certificate image resources provided by external calibration institutions.
- Connection timeout errors occur when calling a locally privately deployed model. This occurs because a reasonable value for `DB_MAX_LINK` is not set, leading to database connection exhaustion and inability to read metrology data during model inference.

## How to Verify Proper Configuration
- Connect to the database specified by `PG_URL`, run a simple query statement to verify that gauge ledger data can be retrieved normally.
- Call the cache service corresponding to `REDIS_URL`, write and read a single calibration certificate metadata entry to verify that the cache function operates correctly.
- Upload a calibration certificate PDF, generate a temporary link via `FILE_TOKEN_KEY` to verify that the file can be accessed normally.
- Trigger an incremental synchronization task to check whether metrology data is automatically updated according to the preset calibration cycle.

The values provided here are common starting points and should be evaluated against the user's own samples.
