# Process Specification and Technical Standard Q&A for Equipment Inspection and Preventive Maintenance: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Includes
Data sources include EAM/CMMS systems, equipment sensor collection data, daily inspection records completed by operators, maintenance work order history, spare parts inventory lists, and legal inspection records for special equipment. Data updates follow shift-based inspection cycles, daily/weekly/monthly maintenance plan updates, and real-time records for sudden faults. Daily documents include structured inspection sheets and maintenance plans, as well as unstructured fault analysis reports. Fields covered include equipment numbers, inspection points, parameter thresholds, spare part models, inspection validity periods, and most fields have clear units such as millimeters, degrees Celsius, and operating hours.

## Constraints for Multi-turn Dialogue and Prompt Engineering
Multi-turn dialogue requires limiting context scope to avoid redundant cross-device historical information interfering with current queries. The mixed characteristics of structured and unstructured documents require prompts to distinguish call logic for different document types. For example, prioritize calling structured data from inspection sheets, with call logic different from that used for unstructured fault analysis descriptions. Fields with units require prompts to explicitly match units to prevent parameter confusion. Frequently updated data needs regular knowledge base refreshes. Dynamic variables such as current equipment numbers and inspection cycles can be passed via the `variables` parameter to improve dialogue relevance and avoid using outdated information.

## Configuration Settings
This configuration is based on FastGPT v4.17.0, and precise control of multi-turn dialogue can be achieved through three core parameters: `chatId`, `messages`, and `variables`.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context | 1200–1500 preceding characters | Matches the single-page document length of inspection sheets and maintenance work orders, and avoids exceeding model context limits |
| Single search limit | Top 6 results | Covers the number of documents commonly used by shift teams, such as inspection sheets and spare parts lists, balancing recall accuracy and response speed |
| Question optimization | Enabled | Automatically completes field unit prompts to meet the demand for matching inspection parameter units, improving reply accuracy |
| Knowledge base refresh frequency | 2:00 AM daily | Matches the daily/weekly inspection plan update cycle, ensuring conversations use the latest data |
| Context binding | Bind equipment number via `chatId` | Differentiates conversation contexts for different devices, avoiding interference from redundant cross-device information |

## Three Common Misconfigurations
- Outputting full multi-turn conversation history in workflows instead of only the latest round of results. This occurs because the `messages` parameter is not configured to retain only the current interaction context, causing all historical conversations to be included in the output.
- Receiving unrendered markdown markers such as # and * in replies when connecting to external conversation channels. This occurs because the native markdown format output switch for conversations is not disabled, causing format symbols to be returned directly.
- Failing to return referenced knowledge base information identifiers when calling the conversation interface. This occurs because knowledge base reference tracking configuration is not enabled, causing the interface to not return the corresponding field.

## How to Verify Proper Configuration
- Initiate a query for inspection parameters of a single device, confirm that the reply only includes the latest inspection thresholds for that device, with no irrelevant historical conversation content.
- Copy reply content to an external conversation channel, check that there are no unrendered markdown format symbols.
- Call the conversation interface, confirm that the returned results include the referenced knowledge base document identification field.
- Initiate a spare parts query request, confirm that the reply matches the current inventory spare part models and units, with no outdated data.
