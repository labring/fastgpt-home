# Q&A for Process Procedures and Technical Standards of General Mechanical Equipment Assembly: Multi-turn Dialogue and Prompt Engineering

## What data looks like for this category
Data for general mechanical equipment assembly scenarios typically originates from PLM/ERP, part inspection data, assembly tool collection systems, test benches, MES, and customer technical agreements. Daily generated documents include assembly process cards, BOM lists, torque records, clearance adjustment records, commissioning reports, factory inspection sheets, and packing lists. Data updates follow a per-equipment or per-order rhythm. Each document includes clear process steps, parameter values, inspection results, and responsible person fields. Some documents must align with physical assembly sequence and physical unit requirements such as clearance and coaxiality.

## What constraints do these characteristics impose on multi-turn dialogue and prompt engineering
The per-equipment or per-order data update rhythm requires multi-turn dialogue to bind to a specific order or equipment ID, to avoid mixing data across orders. Document types include multiple categories such as process cards and inspection records, and include physical parameters such as torque and clearance. Prompts must clearly distinguish between process steps, inspection results, and BOM matching logic. The assembly phase relies on accurate data for physical fits, so multi-turn dialogue must support step-by-step review of process records. It must also filter irrelevant parts processing documents. Data sources are scattered, so dialogue flows must guide users to clearly provide the PLM module or order number associated with the document, to reduce retrieval bias.

## How to configure settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `variables` | Bind order number and equipment model fields | Limit retrieval scope to assembly data for the corresponding order, avoid mixing data across orders |
| `messages` history message truncation threshold | Retain the most recent 20 dialogues | Filter redundant prior conversations, focus on issues in the current assembly phase, avoid context overload |
| Context window size | `8000–12000 token` | Cover complete assembly processes and inspection records for a single piece of equipment, avoid context truncation |
| Maximum number of recalled documents per query | Top 6 entries | Match retrieval needs for multiple associated documents (process cards, torque records, BOM) in assembly scenarios, avoid information redundancy |
| Dialogue timeout setting | `120 seconds` | Cover response latency for cross-system data retrieval from PLM and MES, avoid request timeout errors |
| Question optimization switch | Enabled | Convert vague user assembly questions into standardized retrieval instructions, match process step fields in process cards |

## Three common configuration mistakes
- Symptom: Request Time error occurs during dialogue. Cause: The dialogue timeout setting is not adjusted for cross-system PLM and MES data retrieval scenarios. The default timeout duration is insufficient to cover the data pull process.
- Symptom: The iframe-embedded dialog box displays an English interface. Cause: No corresponding language variable binding is configured, and the language parameter in `variables` is not set to Chinese.
- Symptom: Retrieval results include irrelevant parts processing documents that do not match the current assembly order. Cause: The prompt does not explicitly limit the retrieval scope to assembly-related documents, and `chatId` is not bound to associate context for the corresponding order.

## How to confirm correct configuration
- Initiate an assembly question that includes an order number, verify that the dialogue context automatically binds document fields for the corresponding order.
- Initiate a vague question such as "Adjust the clearance of the pump", verify that the system automatically converts it into a standardized retrieval instruction.
- Initiate a multi-step progressive question such as "First check the process card, then check the torque record", verify that the system retains context and associates the corresponding documents.
- Wait for the dialogue response, verify that no timeout errors occur, and that the response duration aligns with the preset timeout setting.
