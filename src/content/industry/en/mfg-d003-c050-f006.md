# Q&A for General Mechanical Equipment Assembly Process Procedures and Technical Standards: Citation Sources and Traceability

## What data for this category looks like
Daily documents for the general mechanical equipment assembly category include assembly process cards, BOMs, torque records, clearance adjustment records, commissioning reports, factory inspection certificates, and packing lists. Data mainly comes from PLM/ERP systems, part inspection data, assembly tool collection records, test bench data, MES systems, and customer technical agreements. Data is updated on a per-equipment or per-order cycle. Each document contains clear fields such as assembly steps, parameter thresholds, and inspection records. Some documents include quantitative indicators such as torque units and clearance tolerances.

## What constraints do these characteristics impose on the "citation sources and traceability" link?
Since data is updated per single piece of equipment or single order, and contains a large number of personalized assembly parameters, citation traceability requires precise matching of exclusive documents for a single piece of equipment. It cannot rely on general batch knowledge bases. Multiple types of documents have large structural differences. Some documents contain multi-level BOMs, so it is necessary to distinguish component-level and complete machine-level documents during traceability. Data sources are scattered across multiple systems, so they must be uniformly associated with corresponding assembly tasks to avoid citing invalid data across orders. The units and tolerance ranges of quantitative parameters must strictly match the original text. Otherwise, traceability results will not match actual process requirements. FastGPT v4.17.0 configuration must be adapted to these characteristics to ensure traceability accuracy.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | This category of documents contains multi-level BOMs and assembly parameters. Sufficient context must be retained to accurately associate process requirements |
| Include traceability details in responses | Enabled | Cited document sources such as assembly process cards and inspection certificates must be clearly displayed to meet process audit requirements |
| Single recall source limit | Top 6 entries | Assembly-related documents for a single piece of equipment usually do not exceed 6 categories. Too many entries will interfere with core process information presentation |
| `detail` | Enabled | Specific parameters such as torque values and clearance tolerances must be extracted from documents to ensure traceability content matches actual process requirements |
| Knowledge base chunk length | `300–500 characters` | This category of documents contains structured parameters and step descriptions. The chunk length adapts to the information density of a single process segment or single inspection record |
| `responseData` | Include source identifiers and fields | Identifiers such as the number and generation time of traceable documents must be embedded in the response to facilitate subsequent verification |

## Three common mistakes
- Phenomenon: Q&A responses do not include assembly process content from the local knowledge base, and only return general model answers. Cause: Category-specific assembly process cards, BOMs and other documents are not correctly associated with the corresponding knowledge base, or the traceability association switch is not enabled in the configuration.
- Phenomenon: Traceability sources are displayed correctly, but specific parameters such as torque values are not extracted. Cause: The `detail` configuration is not enabled, or the knowledge base chunk length is too long, causing parameters to be truncated and unable to be recognized by the model.
- Phenomenon: Recalled traceable documents cross orders and do not match the single piece of equipment currently being queried. Cause: Knowledge base recall results are not filtered by order or equipment ID, resulting in references to assembly records from other batches.

## How to confirm the configuration is correct
- Initiate a query about the assembly process of a single piece of equipment, and check whether the response contains clear traceable document names and numbers.
- Verify whether the response extracts quantitative parameters from documents such as torque values and clearance tolerances, and confirm that the `detail` configuration is enabled.
- Import a single test document, initiate a corresponding query, and check that the recall result only includes this test document with no content from other irrelevant batches.
- View the `responseData` field in the response, and confirm that it includes identifying information such as the generation time of the source document and the associated order.

The values given are common starting points and should be measured against the reader's own samples.
