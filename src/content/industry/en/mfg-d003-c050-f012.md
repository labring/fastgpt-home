# Q&A for General Mechanical Equipment Assembly Process Procedures and Technical Standards: Deployment and Upgrade

## What the data for this category looks like
Business data for general mechanical equipment assembly scenarios mainly comes from PLM, ERP, MES systems, as well as torque records and gap adjustment records collected by assembly tools, factory inspection sheets, packing lists, and other documents. Daily documents include assembly process cards, multi-level BOMs, trial run reports, and other materials. Fields include component numbers, torque values, coaxiality parameters, gap tolerances, and other metrics. Common units are millimeters, newton meters, and revolutions per minute. Data updates are synchronized with each equipment assembly and each order delivery, with a single update covering the full assembly record for a single piece of equipment.

## What constraints do these characteristics impose on the deployment and upgrade phase
The multi-source mixed and per-order high-frequency update business characteristics of this category impose multiple constraints on the deployment and upgrade phase. Documents in multi-source formats require access rules compatible with structured BOMs, torque records and unstructured process cards to be configured during deployment. High-frequency updates per equipment or order require upgrades to support incremental synchronization without interrupting existing Q&A services. Fixed units for professional fields require retaining original field mappings during configuration to avoid retrieval deviations caused by unit conversions. A verification interface must also be reserved to ensure that core process parameter retrieval results match on-site assembly requirements.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `50–80` | Adapts to the data volume of a single order generated by one equipment’s assembly, and avoids connection pool exhaustion |
| `MONGODB_URI` | Points to the process document database synchronized from PLM | Stores unstructured business documents such as assembly process cards and trial run reports |
| `PG_URL` | Points to the structured parameter repository | Stores structured data with units such as torque records and gap adjustment records |
| `REDIS_URL` | Configured as a local cache node | Accelerates high-frequency retrieval queries for process parameters and reduces database load |
| `ROOT_KEY` | Generate a random string based on the deployment environment | Ensures access permission security for background configurations, and complies with internal enterprise deployment specifications |
| `FE_DOMAIN` | Configured as the enterprise internal access domain name | Adapts to the access path of internal engineers and avoids cross-domain access issues |

## Three common misconfigurations
- Symptom: After upgrading to FastGPT v4.17.0, the knowledge base can return retrieval results, but the model cannot output final content. Cause: The cache expiration time for `REDIS_URL` was not configured, causing retrieval results to be cleared before model invocation.
- Symptom: After Docker deployment, the page on port 3000 cannot be accessed, while the page on port 3001 opens normally. Cause: The deployment script did not correctly map port 3000 for the frontend service, or firewall rules restrict external access to port 3000.
- Symptom: After modifying the FastGPT configuration file inside a Docker container, the OpenAI API key or root password does not take effect. Cause: The container was not restarted to load the new configuration, or the modified configuration file path does not match the mounted path inside the container.

## How to confirm configurations are properly set
- Run a database connection test to verify that the repositories pointed to by `MONGODB_URI` and `PG_URL` can read and write assembly-related documents normally.
- Submit a process procedure retrieval request for a single piece of equipment, and confirm that the returned results include core fields such as the corresponding BOM and torque records.
- After restarting the deployment service, check that the frontend page loads normally and that no cross-domain errors appear for the access path configured in `FE_DOMAIN`.
- Trigger an incremental synchronization task to verify that newly uploaded assembly records can be correctly recognized by the retrieval system.

The values provided are common starting points and should be measured against the reader's own samples.
