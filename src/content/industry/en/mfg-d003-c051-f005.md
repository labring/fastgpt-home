# Process Specification and Technical Standard Q&A for Metal Cutting Machining: Tool Calling and Plugins

## What this category of data looks like
Typical data for this category includes process routes, operation cards, tool lists, CNC programs, first-piece inspection records, patrol inspection forms, measuring tool calibration records, and more. Data sources include product drawings and 3D models, CAPP/CAM systems, machine tool collection data, tool management systems, MES systems, and measuring and inspection tool data. Data updates are triggered with each work order, each workpiece production run, sampling inspection link, or tool change. Fields include operation number, tool model, cutting speed, feed rate, inspection dimensions, and more. Units include professional machining units such as millimeters, revolutions per minute, millimeters per minute.

## What constraints these characteristics impose on the tool calling and plugins workflow
Data sources for this category are scattered and diverse, requiring tool calling plugins to connect to multiple systems to pull data, which increases plugin configuration complexity. Data update frequency is high, requiring tool calling to support real-time or incremental synchronization to avoid returning outdated process information. Document structures vary widely, including both structured operation card parameters and unstructured CNC program text, requiring plugins to adapt to multiple format parsing scenarios. There are many professional fields and units, requiring tool calling to verify parameter legitimacy to prevent incorrect machining parameters from being referenced.

## How to set the configuration
The following configurations apply to FastGPT v4.17.0, and are adapted for the metal cutting machining process specification Q&A scenario.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | Metal cutting process Q&A requires automatic matching of tools for retrieving process specifications, tool lists, and similar content, with no manual specification needed |
| Tool call timeout | `600 seconds` | Data for this category must be pulled from multiple systems such as CAPP and MES, which takes a long time |
| Number of entries returned per tool call | `Top 3` | There are many process specification entries, to avoid context overload that reduces answer accuracy |
| Workflow/API function-call configuration | `Enable parameter verification` | Need to verify the units and value ranges of cutting parameters to ensure the legitimacy of process data |
| Plugin data source mapping | `Associate machine tools and tool systems by work order` | Data for this category is updated per work order, requiring binding of exclusive data sources for corresponding work orders |
| Context window limit | `8000 token` | Need to carry parsed content from multiple operation cards and CNC programs to avoid context overflow |

## Three common configuration mistakes
- Tool call fails to connect, caused by incorrect configuration of MCP service access parameters and failure to enable the adapted protocol.
- Unable to establish a non-tool call link after tool call termination, caused by incorrect setting of tool call termination trigger conditions, leading to incomplete reset of session context.
- Missing tool model field in returned process data, caused by failure to configure data source field mapping for the plugin and incomplete pulling of tool list data.

## How to confirm the configuration is correct
- Initiate a test request containing a cutting parameter query, confirm that the tool can automatically retrieve the content of the corresponding operation card.
- Check the tool call logs, confirm that the timeout configuration is in effect, and there are no frequent timeout errors.
- Verify the MCP service access configuration, confirm that real-time machining data collected by the machine tool can be pulled normally.
- Test the tool call termination operation, confirm that the session can switch to non-tool call Q&A mode.

The values listed here are common starting points and should be evaluated against the reader's own samples.
