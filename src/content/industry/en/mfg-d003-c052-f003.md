# Process Specification and Technical Standard Q&A for Steel Rolling and Finishing: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Business data for steel rolling and finishing originates from slab or billet batches, heating furnaces, mill automatic control systems, online thickness and width measuring equipment, surface inspection devices, and MES systems. Daily documentation includes rolling plans, heating schedules, rolling specifications, shape and thickness records, surface quality reports, and quality certificates. Fields include thickness (unit: mm), temperature (unit: ℃), rolling speed (unit: m/s), and surface defect level, among other metrics. Data updates in real time per coil or individual steel product. Each single batch of data links to a unique traceability identifier, with a fixed structure.

## Constraints on Multi-turn Dialogue and Prompt Engineering
Data for this category updates in real time per coil or batch, and ties to a unique batch identifier. Multi-turn dialogue must bind to the batch identifier to avoid context confusion. Documents primarily use structured parameters. Prompts must clearly define the scope of rolling and finishing processes, and exclude irrelevant content from the steelmaking stage. Single batches have limited data but frequent updates. Limit the context window size to prevent loading expired or redundant data. Support fast recall of corresponding documents by batch to ensure Q&A results match the currently processed steel product.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Context window size | Previous 10 turns of dialogue or 8000 characters | Matches the volume of single-batch rolling data to avoid context overload |
| `chatId` | Bind to the current steel coil batch ID | Establishes association between dialogue context and batch, supporting coil-level traceability |
| `messages` | Append by dialogue turn, no more than 12 turns | Controls the volume of historical messages loaded to prevent processing timeouts |
| `variables` | Fill in the current steel coil’s batch number and specification parameters | Accurately matches rolling specifications and quality reports for the corresponding batch |
| Single recall limit | Top 6 matching results | Core parameter entries for rolling and finishing are limited; excessive results will interfere with judgment |
| Dialogue timeout | 600 seconds | Adapts to the time required for retrieval and organization of complex rolling parameters |

## Three Common Configuration Errors
- Phenomenon: Dialogue returns results unlinked to the current steel coil batch, only providing general rolling specifications. Cause: The `chatId` parameter is not passed, and the session context is not bound to the batch identifier, leading to recalled documents that do not match the currently processed product.
- Phenomenon: Structured data is returned directly after calling the interface, without being formatted into natural language Q&A. Cause: The dialogue generation link is not configured; only the knowledge base recall interface is called, and final AI dialogue organization is not completed.
- Phenomenon: Prompts and knowledge base recall results are only in Chinese, and cannot respond to English queries. Cause: No language type is specified in the prompt template, and `variables` are not configured to support multilingual scenarios.

## How to Verify Correct Configuration
- A test dialogue may be initiated, with the batch number of a specific steel coil entered. Confirm returned results include the heating schedule and rolling specifications for that batch.
- Three consecutive rounds of questions about different parameters for the same steel coil may be launched. Confirm the batch context is retained in the dialogue, and no re-entry of batch information is required.
- The number of knowledge base recall results may be checked. Confirm it does not exceed the configured single recall limit, with no redundant or irrelevant content.
- An English query may be submitted. Confirm prompts and returned results can adapt to the English scenario.

The values provided are common starting points and should be measured against the reader's own samples.
