# Process Specification and Technical Standard Q&A for Steel Rolling and Finishing: Tool Calling and Plugins

## What this category of data looks like
This category of data comes from slab or billet batches, heating furnaces, mill automatic control systems, online thickness and width measurement equipment, surface inspection devices, and MES systems. Daily documents include rolling plans, heating schedules, rolling specifications, shape and thickness records, surface quality reports, and quality certificates. Data is updated per coil or per individual steel product. Some parameters such as rolling speed and shape deviation are updated in real time. Document fields include batch number, heating temperature, reduction rate, thickness tolerance, and surface defect level. Units include degrees Celsius, millimeters, meters per second, and others.

## What constraints do these characteristics impose on the "tool calling and plugins" link
The multi-source real-time, coil-level updated data characteristics of this category require tool calling to support precise filtering of search results by steel coil batch to avoid cross-batch data confusion. Multiple types of process documents require plugins to adapt to parsing formats including rolling plan PDF files, CSVs exported from MES, and Word format quality certificates. Since errors directly correlate with production losses, tool calling results must include clear batch matching verification logic. Real-time updated rolling parameters require plugins to support short-cycle data pulling, and limit the amount of data returned per call to avoid timeouts. Coil-level traceability requirements require plugins to associate multiple data sources, such as online thickness measurement data and corresponding rolling specifications.

## Three common mistakes
- Phenomenon: The plugin configuration and testing are normal, but the returned results only contain XML or JSON code blocks without rendering visual charts. Cause: The result rendering switch is not enabled in the tool calling configuration, or the plugin is not correctly bound to the rendering context.
- Phenomenon: For the same user input, prompt, and knowledge base, the results of online chat and API calls differ significantly. Cause: The `toolChoice` parameter consistent with the web version is not configured in the API call, or the context settings are not synchronized.
- Phenomenon: The process data returned by tool calling does not match the actual steel coil batch. Cause: The steel coil batch number is not bound as a filter condition in the retrieval parameters, leading to cross-batch data confusion.

## How to confirm the configuration is correct
- Initiate a process query that includes a clear steel coil batch number, and check whether the corresponding batch filter parameter is included in the tool calling request.
- View the tool calling log to confirm that the returned result format meets the plugin requirements, with no pure code blocks or format errors.
- Compare the tool calling parameters of online chat and API calls to ensure that the `toolChoice` and context settings are consistent between the two.
- Trigger a test case to verify whether the plugin can correctly render visual charts corresponding to rolling parameters.

The values provided are common starting points and should be measured against the reader's own samples.
