# Forging and Die Forging Process Specification and Technical Standard Q&A: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
This category of data includes forging process specifications, cutting stock cards, heating furnace records, forging process logs, mold life records, heat treatment work orders, ultrasonic testing reports, and more. Data is sourced from raw material quality certificates, heating furnace systems, press collection data, MES systems, non-destructive testing instruments, and customer forging drawings. It is updated per individual forging, batch, or furnace charge. Fields include forging ratio, metal fiber direction, furnace batch number, heating temperature, mold usage count, detected defect type, and additional relevant metrics. Units include degrees Celsius, megapascals, millimeters, and other standard industrial units.

## Constraints for Multi-turn Dialogue and Prompt Engineering
Data is updated per single batch or furnace charge. Multi-turn dialogue should retain session context such as furnace batch number and forging batch number to avoid repeated basic information queries. Professional fields like forging ratio and metal fiber direction should be clearly defined in prompts to prevent model confusion with similar process parameters. Multi-source data association logic should be fixed in prompts to ensure accurate recall of corresponding heating furnace records or ultrasonic testing reports during dialogue. Because errors directly result in forging scrap, dialogue should prompt users to provide specific document numbers or batch information to narrow recall scope.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind the unique identifier of the current forging batch | Ensure multi-turn dialogue is associated with process and testing data for the same batch |
| `messages` | Retain the last 10 rounds of dialogue content | Cover full process traceability requirements for a single furnace charge |
| `variables` | Inject the furnace batch number and customer drawing number of the current forging | Narrow the scope of recalled data |
| Single search limit | Top 8 entries | Match the typical number of documents related to a single batch |
| Maximum context length | 8000 characters | Accommodate heating records and process card content for a single furnace charge |
| Document chunk length | 1200–1500 characters | Adapt to the information density of a single page of forging process cards |

## Three Common Misconfigurations
- Refreshing the page displays the prompt "No available index model detected". This occurs when forging-specific documents are not linked to the current session’s index library, or when the index library update is incomplete.
- Dialogue results do not include source document links. This occurs when the source document association binding logic is not enabled in the configuration, and document paths or batch identifiers are not injected via `variables`.
- Calling the dialogue interface returns a 404 status code with no response body. This occurs when `chatId` is not bound to a valid batch identifier, or when the session context exceeds the configured retention rounds, leading to cache invalidation.

## How to Verify Correct Configuration
- Create a new session and inject the `variables` parameter with a known furnace batch number. Check if the dialogue automatically recalls heating furnace records and forging process logs for the corresponding batch.
- Initiate more than 10 consecutive dialogue rounds. Check if the `messages` parameter retains historical context, with no context loss observed.
- Pass a valid `chatId` when calling the interface. Check if returned results include the bound batch information, with no 404 status code appearing.
- View the index library’s associated documents. Confirm that the library includes forging process specifications, ultrasonic testing reports, and other documents exclusive to this category.
