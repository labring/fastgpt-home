# Forging and Die Forging Process Specification and Technical Standard Q&A: Tool Calling and Plugins

## What This Category’s Data Looks Like
Daily data for forging and die forging scenarios includes documents such as forging process specifications, cutting cards, heating furnace records, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports.
Data sources include raw material quality certificates, heating furnace systems, press collection data, MES systems, non-destructive testing instruments, and customer forging drawings.
Update frequency follows per piece, per batch, or per furnace load.
Data fields include forging ratio, fiber direction, heating temperature range, furnace batch number, forging batch number, and others. Units include professional measurement standards such as degrees Celsius, tons, and millimeters.

## Constraints Imposed on Tool Calling and Plugins
This category’s data has high update frequency and is scattered across multiple sources. Tool calling must pull the latest MES, heating furnace, and non-destructive testing data in real time to avoid using expired information.
Multiple document types have structured and semi-structured features. Plugins must support parsing professional documents in different formats, and accurately extract specific fields such as forging ratio and furnace batch number.
Professional terminology has strict uniqueness requirements. Tool calling must be bound to forging domain-specific plugins to avoid generic models calling irrelevant tools.
Data association verification is necessary. Tool calling must integrate verification logic such as batch matching and defect analysis to ensure consistency between processes and standards.

## Configuration Settings
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `functionCall` | Accurately call the specified forging process query plugin, prevent the model from autonomously selecting irrelevant tools |
| Single tool call timeout | `300 seconds` | Forging process data queries pull data from multiple source systems, which takes a long time |
| Maximum number of tool return results | `Top 8 entries` | The number of related entries in forging process specifications should be limited to avoid context overflow |
| Tool call context truncation length | `1200–1500 characters` | Single records of forging professional documents have long lengths, requiring adaptation to long-text processing |
| Plugin call concurrency limit | `2 times/second` | Prevent excessive system load caused by pulling data from multiple sources |
| Plugin call permission scope | Only allow data sources for process specifications and test reports | Avoid calling irrelevant system data to ensure data security |

## Three Common Misconfigurations
- Phenomenon: Multiple incompatible large model APIs are requested simultaneously during tool calling, resulting in interface error returns. Cause: Routing rules that trigger corresponding models based on input data types are not configured, and multimodal ultrasonic testing images are incorrectly handed to plain text processing models.
- Phenomenon: The search tool returns empty results, and public process reference information cannot be obtained. Cause: A search plugin that requires overseas access is used, and it is not replaced with a local search tool adapted to the domestic environment.
- Phenomenon: The raw material quality certificate data returned by the tool does not match the current forging batch, and no verification prompt is triggered. Cause: Tool call steps for batch verification are not configured, and the batch matching interface of the MES system is not bound.

## How to Confirm Proper Configuration
- Submit a query containing ultrasonic testing images. Confirm that the tool automatically calls a multimodal-capable model, and the `functionCall` parameter is enabled.
- Submit a plain text query for process parameters. Confirm that the tool automatically calls a plain text processing model, and returned results come from forging process specification documents.
- Trigger tool calling. Check whether returned results include matching verification information for the current forging batch and furnace batch number.
- Check plugin call logs. Confirm that only authorized forging-related data sources are accessed, and no irrelevant external interfaces are called.

The values provided are common starting points and should be measured against the reader's own samples.
