# Precast Concrete Component Process Procedure and Technical Standard Q&A: Citation Sources and Traceability

## Data for This Category
The core data for precast concrete components comes from BIM detailed design, rebar and concrete batch ledgers, mold table and curing kiln operation records, laboratory test reports, and component QR code traceability systems. Daily documents include component detailed drawings, rebar cutting lists, mold inspection records, pouring and vibration logs, curing cycle records, and demolding and factory inspection reports. Data is updated on a per-component, per-batch, per-kiln basis. Each document corresponds to a dedicated component or production batch, with fields including parameters with clear units such as rebar specification, curing age, strength grade, and mold table number.

## Constraints for Citation Sources and Traceability
Since each data entry corresponds to a dedicated component or production batch, citation traceability requires precise matching of the association between component IDs and documents to avoid cross-batch citation of incorrect documents. Frequently updated pouring and curing records require the traceability system to associate the latest version of data in real time, and cannot rely on static cached old documents. Multiple types of business documents must be indexed by production stage, ensuring that process procedure Q&A can quickly locate documents corresponding to the relevant process. Attributes with high consequence of error require traceability information to include clear fields such as batch and inspection item, and cannot only return vague document names.

## Configuration Settings
This page’s configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the typical paragraph length of a single document for precast components, ensuring cited content fully covers process parameters |
| Single search limit | Top 6 results | Covers multiple associated documents corresponding to a single component, such as detailed drawings, cutting lists, and curing records |
| `responseData` | Enabled | Enables detailed data return for citation sources, supporting display of core fields such as document batch and inspection item |
| Reranking | Enabled | Prioritizes documents strongly associated with the current component ID, improving traceability accuracy |
| `detail` | Enabled | Outputs complete metadata for citation sources, including document type, generation time, and other information |
| Maximum context | 3500–4500 characters | Carries the complete context of precast concrete component process procedures, avoiding loss of key parameters |

## Three Common Configuration Errors
- Phenomenon: Only 1 citation is returned per query in simple workspace knowledge base applications. Cause: The single search limit is configured too low, failing to match all associated documents for the target component.
- Phenomenon: A test prompt error occurs after model configuration, and the system runs after forced bypass but the citation traceability field is empty. Cause: The `responseData` configuration item is not enabled, so citation data return is not activated.
- Phenomenon: After importing the precast concrete component knowledge base, the system default document selection box is empty, requiring manual selection of each document. Cause: Documents are not classified and indexed by component ID, so dedicated documents for the category cannot be automatically matched.

## How to Verify Successful Configuration
- Enter a question related to precast component rebar cutting lists, and check if the returned result includes traceability information such as the corresponding document name and batch number.
- Adjust the `quoteMaxToken` parameter, and test if long document citation splitting behaves as expected.
- Import multiple precast component curing record documents, and verify that retrieval matches documents corresponding to the correct batch.
- Check if the `detail` configuration item is enabled, and confirm the returned result includes complete citation metadata.

The values provided are common starting points and should be evaluated against the reader’s own samples.
