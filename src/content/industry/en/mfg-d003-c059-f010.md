# Q&A for Ready-Mixed Concrete Production Process Specifications and Technical Standards: Knowledge Base Retrieval and Recall

## What this category of data looks like
This category of data originates from commercial concrete batching plant control systems, project laboratories, quality and scheduling departments, engineering orders, sand, gravel, cement and admixture inspection records, and moisture content measurement data. Daily documents include mix proportion notices, opening identifications, production and transportation orders, raw material inspection reports, test block records, and strength reports. Fields include measured aggregate moisture content, material usage per cubic meter, slump, strength grade, and other related items. Units include kilograms, millimeters, and megapascals. Data updates occur per vehicle production task, per batch of raw materials entering the site, and during daily laboratory testing cycles.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link?
The high-frequency update characteristic of this data category requires knowledge base retrieval to support an incremental synchronization mechanism, to avoid resource consumption from full refresh operations. The multi-source, heterogeneous document structure requires retrieval to classify and recall documents by type, such as mix proportion notices and strength reports, while associating core fields like aggregate moisture content and slump for precise matching. The fact that a single data entry spans the entire production process requires recall results to cover full process links: raw material inspection, batching, transportation, and pouring. This avoids fragmented information. The lagging verification attribute of test block strength reports requires retrieval to support associating historical data from the same batch for cross-reference.

## How to Set Configurations
These configurations are adapted for FastGPT v4.17.0

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `similarity` | `0.75–0.85` | Matches the precision requirements for ready-mixed concrete process parameters, and avoids recalling irrelevant raw material inspection or test block records |
| `limit` | `Top 8 entries` | Covers process information across multiple links including mix proportion, transportation, and strength, while controlling context length |
| `searchMode` | `embedding` | Prioritizes vector retrieval to meet the demand for precise matching of numerical process fields such as aggregate moisture content and slump |
| `usingReRank` | `Enabled` | Performs secondary ranking on recalled process specification content, and prioritizes matching the correction requirements of the current production batch |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Automatically expands user process questions, and associates related documents such as mix proportion notices and opening identifications |
| `collectionIds` | `Specify the dedicated knowledge base collection for the batching plant` | Isolates production data of different engineering projects, and avoids interference from cross-project information |

## Three common mistakes
- Phenomenon: When calling the `/api/v1/chat/completions` interface, no knowledge base content is recalled after specifying the appId, and the returned result is only a general large model response. Cause: The `collectionIds` configuration item is not included in the interface parameters, or the passed collection ID does not match the target knowledge base.
- Phenomenon: A large number of irrelevant test block strength reports appear in the retrieval results, and the number of recalled entries exceeds expectations. Cause: The `similarity` value is lower than 0.7, or `usingReRank` is not enabled, causing low-relevance content to be recalled first.
- Phenomenon: The retrieval results do not include the process steps for adjusting water use based on aggregate moisture content. Cause: `datasetSearchUsingExtensionQuery` is not enabled, so it cannot automatically associate the measured moisture content data in mix proportion notices with water use adjustment specifications.

## How to Confirm the Configuration Is Properly Set
- Check whether the request parameters include `collectionIds` before calling the interface, and that the corresponding collection ID matches the ready-mixed concrete production knowledge base.
- Review the number of retrieval return results to confirm it matches the value set in the `limit` configuration.
- Verify that the retrieval results include core process fields for the current production batch, such as aggregate moisture content and mix proportion.
- Compare the recall ranking when `usingReRank` is enabled and disabled, to confirm the reranking function is active.

The values provided are common starting points and should be measured against the reader's own samples.
