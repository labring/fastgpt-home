# Beverage and Bottled Water Process Specification and Technical Standard Q&A: Workflow Orchestration

## What This Category’s Data Looks Like
Core data for this category comes from water source and raw material testing, formula systems, online sugar and acidity monitoring, filling equipment, visual inspection systems, and LIMS systems. Daily retained documents include formula sheets, water treatment records, blending records, sterilization or aseptic filling records, packaging material inspection reports, and finished product inspection reports.
Data updates follow each production batch, shift schedule adjustments, and continuous collection. Documents are archived by production batch, with fields including raw material parameters, process parameters, test results, and equipment operating status. Some fields have exclusive identifiers and format requirements.

## What Constraints These Characteristics Impose on Workflow Orchestration
This category has high-frequency data updates and strong batch association. Workflow orchestration must support triggering nodes by production batch to avoid cross-batch data confusion.
Multi-source data is scattered across different systems. Workflows must be configured with cross-data source access nodes to integrate scattered process and inspection data.
Document types are diverse and require precise matching. Workflows must support calling corresponding parsing rules by document type to ensure accurate field extraction for different documents.
Continuously collected real-time data requires workflow nodes to have low-latency processing capabilities to avoid data lag in production links.
Error consequences must be strictly controlled. Workflows must be configured with exception verification nodes to intercept risks such as formula over-limits and microbial abnormalities in advance.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Node Configuration | Trigger by production batch | Matches the data archiving feature of this category to avoid cross-batch data confusion |
| Maximum Context Length | 8000–12000 token | Covers the full content of process documents for a single batch to ensure complete question-and-answer context |
| Number of Recalled Results | Top 6 | Balances recall accuracy and response speed, adapting to retrieval needs for multi-source data |
| `variables` Binding | Bind production batch number variable | Accurately filters process and inspection data for the corresponding batch, aligning with data archiving logic |
| Node Timeout Threshold | 300 seconds | Adapts to retrieval response requirements for real-time production data, avoiding waiting timeouts in production links |
| Node Visibility Configuration | Enable based on node function | Meets the requirement where some nodes need to display sources and others do not |

## Three Common Mistakes
- Phenomenon: File parsing nodes show idle status with no tasks, and logs return format mismatch prompts. Cause: Exclusive parsing rules are not configured for this category’s document types, and the same parsing template is used for filling records and formula sheets, leading to failed field extraction.
- Phenomenon: Code running nodes fail to execute, returning permission error reports. Cause: The node execution permission corresponding to `nodeId` is not configured, preventing calls to the preset operating environment.
- Phenomenon: Workflow template import shows success, but no nodes are present in the workflow. Cause: The data source configuration in the template does not adapt to this category’s system paths, and mismatched configuration items are automatically discarded after import.

## How to Confirm Configuration Is Complete
- Submit a process query request for a known production batch, check whether the returned results only include document data for that batch, and confirm that the `variables`-bound batch number variable is effective.
- Trigger workflow node operation, check whether the node logs return correct document parsing results, and confirm that the trigger node and data source configuration match.
- Adjust the visibility settings of different nodes, verify whether the source display status of the corresponding nodes meets the configuration requirements.
- Test the code running node by executing a simple script, confirm that the node timeout threshold and permission configuration are normal.
