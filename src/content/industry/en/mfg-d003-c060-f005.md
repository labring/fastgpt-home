# Beverage and Bottled Water Process Specification and Technical Standard Q&A: Tool Calling and Plugins

## What Data for This Category Looks Like
Data sources for this category include water source and raw material testing, formulation systems, online sugar and acidity monitoring, filling equipment, visual inspection, and LIMS systems.
Data update frequencies include batch-generated formulation sheets and packaging material inspection records, shift-updated blending records, and continuously collected real-time data for water treatment, sterilization, or aseptic filling.
Daily documents include formulation sheets, water treatment records, blending records, sterilization or aseptic filling records, packaging material inspection, and finished product inspection.
Fields cover raw material batch numbers, sugar content, acidity, filling liquid level, sealing parameters, label batch numbers, and other relevant items. Some data has fixed format requirements.

## Constraints on Tool Calling and Plugin Workflows
The multi-source real-time and mixed batch data characteristics of this category require tool calling plugins to support simultaneous connection to multiple data sources such as formulation systems, LIMS, and filling equipment.
Continuously collected real-time data requires tool calling to pull the latest monitoring values within a short time frame, and avoid use of expired historical data.
Fixed format requirements require tool calling parameters to match the type and format of corresponding fields, and prevent deviation of feeding parameters.
Batch-updated document data requires tool calling to support precise retrieval by batch number, and avoid confusion across batches.
Because the consequences of errors are severe, tool calling must include parameter verification logic to intercept over-limit feeding, liquid level, and other parameters in advance.

## How to Configure Settings
This configuration applies to FastGPT v4.17.0. Specific parameter settings are as follows:

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Adapts to multi-tool parallel calling scenarios, and matches the process data retrieval requirements of multiple data sources |
| `functionCall` | Calibrated based on actual testing | Adapts to process parameter queries of different complexity levels, and supports precise calling of specified tools |
| Single tool call timeout | 30 seconds | Matches the pull delay requirements of real-time filling and water treatment data |
| Tool call result cache duration | 5 minutes | Balances real-time performance and system load, and adapts to shift-updated blending record requirements |
| Batch number matching precision | Exact match | Avoids confusion across batches, and complies with the per-batch independent document update rules |
| Parameter verification switch | Enabled | Intercepts over-limit process parameters such as sugar content and liquid level in advance, and avoids production risks |

## Three Common Misconfigurations
- Scenario: When calling an MCP service, the parameter type is fixed to `string`, and cannot match non-string fields such as sugar content and filling liquid level. Cause: Custom parameter type mapping is not enabled in the plugin configuration, and the default setting forces string type transmission of process parameters.
- Scenario: Tool calling returns an empty response with no process data results. Cause: The data source is not matched precisely by batch number, or the timeout setting is too short to pull continuously collected real-time filling data.
- Scenario: The streaming output of tool calling cannot be turned off, resulting in redundant streaming fragments returned by workflow nodes. Cause: The streaming output switch is not turned off in the workflow's tool calling module, and the default streaming configuration is retained.

## How to Verify Correct Configuration
- Initiate a tool call request for sugar content parameters, and check whether the returned parameter type matches the format required by the field.
- Initiate a call with an over-limit feeding volume parameter, and confirm that the system triggers parameter verification interception and returns an exception prompt.
- Enter a specified batch number to initiate process record retrieval, and confirm that only document data of the corresponding batch is returned, with no cross-batch confusion.
- Turn off the streaming output switch of tool calling, run the workflow node, and confirm that complete non-streaming result content is returned.

All provided configuration values are common starting points, and should be evaluated against relevant on-site samples.
