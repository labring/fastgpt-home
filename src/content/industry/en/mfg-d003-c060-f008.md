# Beverage and Bottled Water Process Specification and Technical Standard Q&A: Document Parsing and Chunking

## What data for this category looks like
Data for this category mainly comes from water source and raw material testing, formula systems, online sugar and acidity monitoring equipment, filling equipment, visual inspection systems, and LIMS systems. Daily generated documents include formula sheets, water treatment records, blending records, sterilization or aseptic filling records, packaging material inspection reports, and finished product inspection reports.
Formula and inspection records are updated once per production batch. Real-time data from water treatment, filling and other links is collected continuously, and summarized and archived per shift. Most documents are structured records tied to batches, with fields including feeding amount, turbidity, filling liquid level, sealing qualification rate, batch number, and others. Some documents include numerical items for equipment operating parameters.

## What constraints do these characteristics impose on the "document parsing and chunking" link
Batch-tied documents for this category require chunking to retain complete associated information of a single batch’s process, to avoid splitting that breaks the contextual integrity of batch data.
Continuously collected real-time link data has dense entries. A single document may contain a large number of short numerical records, so chunk boundaries must be reasonably controlled to prevent unrelated data from multiple batches from being included in a single chunk.
Different document types have significant field differences. Formula sheets include feeding ratio parameters. Filling records include liquid level and sealing parameters. Chunking logic must adapt to parsing rules for structured and semi-structured documents, to avoid missing key process items.
Frequently updated batch documents require matching reasonable timeout thresholds, to prevent bulk parsing tasks from being interrupted due to large data volumes.
Inspection records related to aseptic control must retain compliance fields completely. Chunking must not truncate key inspection items.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0, and are formulated for the characteristics of process documents for the beverage and bottled water category.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to documents with multiple batches of short records in this category, avoids including too many unrelated batch data in a single chunk, while retaining complete context of a single process specification |
| `chunkSplitter` | Mixed paragraph and fixed-length splitting | Adapts to structured records and semi-structured process documents, first splits by paragraph to retain semantics, then uses fixed length to complete boundaries |
| `customPdfParse` | Enabled | Documents in this category mostly include standardized inspection reports and batch records; enabling custom PDF parsing can accurately extract table and field information |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports uploading full-process document packages for a single batch, adapting to the document archiving needs of factory bulk batches |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Matches the parsing duration of large-volume bulk documents in this category, preventing parsing interruptions due to excessive data volume |
| `chunkSettingMode` | Customized by document type | Sets differentiated chunking rules for different document types such as formula sheets and filling records, adapting to field differences |

## Three common configuration mistakes
- Phenomenon: An error "the argument ‘windows-1252’ is invalid encoding" appears when uploading PPT or Word documents. Cause: The multi-language mixed characters and non-standard encoding formats that may be included in documents of this category are not adapted, and the default parsing encoding does not cover the encoding types commonly used in factory documents.
- Phenomenon: After local deployment and enabling workflow file upload, calling the document parsing tool returns an address parsing failure. Cause: The `CUSTOM_READ_FILE_URL` environment variable is not configured correctly, or the file storage path is not aligned with the access path of the parsing tool, which cannot match the storage and parsing process of bulk documents in this category.
- Phenomenon: When bulk parsing multiple batches of filling records, some document parsing results are empty or have missing fields. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` setting value is too small, which does not match the parsing duration of large-volume bulk documents in this category, causing the task to terminate early.

## How to confirm the configuration is correct
- Upload a single typical document of this category, such as a single batch water treatment record, and check whether the parsing result completely extracts all fields and batch associated information.
- Adjust the `chunkSize` parameter, compare the chunking results under different values, and confirm that a single chunk does not include unrelated data from multiple batches.
- Verify that after `customPdfParse` is enabled, the PDF format inspection report can accurately extract numerical values and parameters in the table.
- Upload a bulk archived document package, confirm that the parsing task does not have a timeout interruption, and all documents have completed parsing.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
