# Cross-Review of Technical Documentation for PCB Manufacturing: Multi-Turn Dialogue and Prompt Engineering

## What the data for this category looks like
Engineering, production, quality control, and laboratory teams at printed circuit board factories use daily documents including manufacturing instructions, Gerber analysis records, drilling and lamination parameters, chemical solution analysis reports, AOI reports, electrical test reports, and sectioning reports.
Data sources include Gerber files, drill files, and BOMs provided by customers, processing files generated by CAM, equipment operating parameters, bath solution test results, detection data collected by AOI and electrical test equipment, and laboratory test records.
Data updates occur per production batch, per shift, or via continuous collection. Fields across different documents include parameters with clear units: drilling aperture, lamination temperature, chemical solution concentration, and defect location coordinates, among others.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Data sources are scattered and update frequently. Multi-turn dialogue must accurately associate specific documents for the current production batch to avoid mixing data across batches.
Documents contain many professional parameters with units, such as drilling aperture and lamination temperature. Prompts must clearly specify parameter matching rules to prevent irrelevant data from being retrieved.
High update frequency means dialogue context must load the latest detection and processing data in a timely manner. It also requires limiting context length to avoid excessive system load.
Errors can lead to severe consequences. Multi-turn dialogue must gradually verify parameter consistency. Each interaction must be based on valid data for the current production batch.

## How to Configure the Setup
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Generate a unique identifier per production batch | Distinguish dialogue contexts for different production batches, preventing cross-batch data reuse |
| `messages` | Retain the most recent 3 dialogue turns and the current query | Control context length to support bulk data loading for PCB documentation |
| `variables` | Pass the Gerber number and drill file version for the current production batch | Accurately link to the exclusive document set for the corresponding batch |
| Maximum context | Top 10000 tokens | Accommodate field information from multiple PCB documents, avoiding truncation of critical parameters |
| Single search limit | Top 8 retrieved results | Cover key information across multiple document types including manufacturing instructions, AOI reports, and electrical test reports |
| Question optimization | Enabled | Automatically supplement PCB manufacturing professional terminology, improving document matching accuracy |

## Three Common Misconfigurations
- Calling the dialogue interface returns "No knowledge base selected", but the function works normally in debug preview. This occurs when failing to pass the knowledge base association identifier for the current production batch via `variables`, so the context cannot match the corresponding document set.
- Dialogue context continues to accumulate without automatic cleanup. This happens when failing to limit the number of retained turns for `messages`, causing historical data from multiple production batches to occupy system resources.
- Drilling parameter matching deviations occur during multi-turn verification. This is caused by failing to explicitly require priority access to drill file data for the current batch in the prompt, resulting in retrieval of parameters from historical batches.

## How to Confirm Proper Configuration
- Initiate a test dialogue, enter "Query the drilling parameters for the current production batch", and verify that the returned results include the drill file data and parameters for the corresponding batch.
- Call the `chatId` generation interface, confirm that `chatId` values for different production batches do not share context data, avoiding cross-batch interference.
- Review dialogue logs, confirm that `messages` exceeding the retained number of turns are automatically cleaned up, with no historical data accumulation.
- Enter a query containing PCB professional terminology, and verify that the system can accurately match corresponding documents such as AOI reports and lamination parameters.

The values provided are common starting points and should be evaluated against the reader's own samples.
