# Cross-Review of Technical Documentation for PCB Manufacturing: Deployment and Upgrade

## What Data for This Category Looks Like
Data originates from customer-provided Gerber files, drill files, and BOMs. It also includes data from internal factory CAM systems, production equipment parameters, bath test records, AOI inspection reports, electrical testing reports, and laboratory sectioning reports. Daily documents cover engineering production instructions, Gerber analysis records, drilling and lamination process parameters, chemical analysis logs, and defect detection records.
Data updates trigger with production batches and shifts, or are collected continuously by equipment. Each batch of data includes process parameters, test results, and associated customer identification tags. Fields include drilling aperture, lamination temperature and pressure, defect coordinates, chemical concentration, and other specific process and test items.

## Constraints During Deployment and Upgrade
Data sources cover customer materials and multiple types of production and testing equipment. Updates occur frequently with production batches and shifts.
Deployment must support batch access and real-time synchronization of multi-source heterogeneous data. Upgrades must be compatible with document format parsing logic for new equipment.
Each batch of data contains large volumes of unstructured process parameters and test details. Deployment must reserve sufficient storage and computing resources. Upgrades must avoid breaking existing document association relationships.
Data association relies on customer tags and production batches. Deployment must configure unified tag mapping rules. Upgrades must retain association logic for historical data to ensure cross-version data traceability.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `REDIS_URL` | `redis://:your_password@localhost:6379/0` | Supports high-frequency real-time production data caching and synchronization, adapts to multi-batch concurrent document processing requests |
| `MONGODB_URI` | `mongodb://localhost:27017/fastgpt_pcb_docs` | Stores large volumes of unstructured Gerber files, inspection reports, and process parameter documents |
| `DB_MAX_LINK` | `200–300` | Adapts to simultaneous document cross-review requests from multiple workstations, prevents database connection exhaustion |
| `FE_DOMAIN` | `https://pcb-tech-review.your-factory.com` | Configures valid access and embedded domain names, resolves cross-domain access and iframe embedding blank screen issues |
| `FILE_TOKEN_KEY` | `32-bit randomly generated encrypted string` | Encrypts access tokens for sensitive customer Gerber files and inspection reports, ensures data security |
| `STORAGE_S3_ENDPOINT` | `Configured per the factory’s existing storage architecture` | Adapts to storage requirements for large-size Gerber files, compatible with the factory’s existing cloud storage or local storage solutions |

## Three Common Mistakes
- Symptom: FastGPT pages embedded via iframe display a blank screen, but direct access to the public network address works normally. Cause: The `FE_DOMAIN` parameter is not configured correctly, and the embedded page’s domain name is not added to the allowed access list.
- Symptom: No developed plugin configuration entry is visible after deployment, and corresponding paths cannot be located using public tutorials. Cause: The plugin module’s configuration file was not loaded during deployment, or the plugin function was not enabled in startup parameters.
- Symptom: After upgrading to FastGPT v4.17.0, calls to speech-to-text related interfaces return an error for `POST /v1/audio/transcriptions`. Cause: Original audio processing environment variable configurations were not retained during the upgrade, or the dependent service version is incompatible with the new interface call logic.

## How to Verify Successful Configuration
- Access the configured `FE_DOMAIN` address, confirm the page loads normally with no cross-domain related error prompts.
- Upload a test Gerber file and the corresponding production batch’s inspection report, confirm the file can be stored successfully and association relationships are established.
- Initiate multiple sets of document cross-review test requests, confirm the system can process multiple concurrent document comparison tasks normally.
- Call the interface to test the audio transcription function, confirm no errors related to `POST /v1/audio/transcriptions` are returned.

The values provided here are common starting points. They should be evaluated against applicable samples and use cases.
