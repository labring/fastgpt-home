# Cross-Review of Technical Documentation for SMT Mounting and Electronic Assembly: Workflow Orchestration

## What the data for this category looks like
Documents generated and circulated daily for this category include BOMs and coordinate files, line change lists, stencils and reflow oven temperature records, first article confirmation reports, SPI/AOI test reports, maintenance records, and traceability labels.
Data sources include customer-provided BOMs, Gerber files, coordinate files, MES systems, solder paste and component batch ledgers, mounters, SPI/AOI equipment, and reflow oven temperature collection systems.
Data updates take effect in real time with each work order and each line change.
Document fields associated with a single work order include part numbers, reference designators, component batches, reflow temperature curve parameters, test thresholds, and more. There are no unified fixed units. Measurement rules are matched based on field type.

## What constraints these characteristics impose on workflow orchestration
Data for this category updates in real time with work orders and line changes. Document types are diverse, and field associations are complex. Workflow orchestration must bind precise trigger timing to avoid redundant execution.
Multi-source heterogeneous data access requires setting format verification steps in workflow nodes. These steps match the field rules of different document types.
Real-time updated component batch and reflow temperature data require data transfers between workflow nodes to be timely. This prevents the use of expired data.
Cross-system collected test reports and BOM data require field comparison steps in the cross-review link. This ensures consistency of core information such as part numbers and reference designators.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
|---|---|---|
| Trigger Node | Triggered by work order creation / line change completion events | Matches the real-time data update rhythm of this category based on work orders and line changes, avoids redundant execution |
| `variables` configuration | Bind work order ID, component batch number | Used to pass core business identifiers across nodes, ensures accurate data association |
| Document verification rules | Configure field matching by document type | Covers field differences across multiple document types including BOMs and SPI reports, unifies cross-review benchmarks |
| Node timeout threshold | 600 seconds | Adapts to the calculation time required for multi-document comparison in this category, prevents task interruptions mid-execution |
| `nodeId` binding | Bind dedicated review nodes by document type | Ensures different documents enter corresponding verification processes, improves review accuracy |
| API file upload limit | Single upload no larger than 1000 MB | Matches the average size range of documents associated with a single work order in this category |

## Three Common Misconfigurations
1.  Phenomenon: The workflow does not complete all nodes after execution, and no error logs are generated. Cause: The trigger node is not bound to the work order/line change event for this category, and is only triggered on a fixed cycle. This causes some work order data to fail to be matched.
2.  Phenomenon: The historical records associated with the workflow exceed the set 1-item limit. Cause: The dedicated context identifier for the current work order is not bound in `variables`, causing historical records from different work orders to be confused and called.
3.  Phenomenon: Specified documents cannot be uploaded when calling the workflow via API. Cause: No file receiving node is configured in the workflow, or upload permissions for the corresponding file format are not enabled.

## How to Confirm Proper Configuration
1.  Manually trigger a simulated work order creation event. Check if the workflow in FastGPT v4.17.0 executes in the order of preset nodes. Verify that node logs include the bound `variables` and `nodeId` parameter values.
2.  Upload BOM and SPI report documents corresponding to this category. Check if the document verification rules match the corresponding fields by type, with no format errors.
3.  Call the API to upload a single test document. Confirm that the file can be received by the workflow and enter the review node.
4.  View the workflow timeout configuration. Confirm that the threshold setting matches the actual time consumption requirements of multi-document comparison for this category. Adjust to a reasonable range based on actual measurements.
