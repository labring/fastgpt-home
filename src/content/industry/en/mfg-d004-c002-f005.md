# Cross-Review of Technical Documents for SMT Mounting and Electronic Assembly: Tool Calling and Plugins

## What Data Looks Like for This Category
Data sources for this category include BOMs, Gerber files, component coordinates delivered by customers, factory MES system data, solder paste and component batch ledgers, mounters, SPI/AOI testing equipment, and reflow oven temperature records.
Daily generated documents include BOM and coordinate files for each work order, line change sheets, stencil parameters, furnace temperature records, first article confirmation reports, SPI/AOI test results, maintenance records, and traceability labels.
The system updates data in real time when a work order is created or when the production line changes over. Document fields include part numbers, reference designators, substitute materials, test parameters, and other content closely tied to electronic assembly processes.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins
Data sources for this category are scattered, including customer-provided design files and real-time equipment data collected from production lines. Tool calling must support multi-format input and output, and interface with different systems such as MES and testing equipment.
The system updates data in real time for each work order and production line changeover. The volume of data processed in a single call varies with work order scale. Tool calling must adapt to dynamic data volumes, avoiding resource waste or incomplete processing caused by fixed thresholds.
Document fields are tightly bound to electronic assembly processes. Tools must accurately identify exclusive fields such as part numbers and reference designators, and cannot use general field matching logic.
Errors on the production line directly affect overall product quality. Tool calling must add pre-check and post-validation steps to ensure the accuracy of review results.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically match the tools required for the current task, adapting to the cross-review logic for multi-source SMT documents |
| `functionCall` | Force call the specified tool set | Limit use to only tools related to electronic assembly document review, eliminating risks of unrelated calls |
| Single tool call timeout | 600–1200 seconds | Adapt to the processing duration of multiple documents included in a single work order, avoiding timeout interruptions caused by complex validation steps |
| Tool call retry count | 2 | Address temporary network fluctuations or temporary device interface exceptions, reducing the probability of processing failure |
| Tool call result caching rule | Cache by work order ID for 24 hours | Avoid repeated calls to external device interfaces for repeated reviews of the same work order, improving processing efficiency |

## Three Common Misconfigurations
- Phenomenon: Tool calls return timeout errors, or workflow status shows execution that has not completed after more than 1200 seconds. Cause: The timeout configuration was not adjusted to meet the multi-document processing needs of SMT work orders. General short timeout thresholds were used, which cannot accommodate the cross-check duration of batch BOMs and test reports.
- Phenomenon: Tool calls fail, with a prompt that the specified tool was not found or the interface cannot be accessed. Cause: Tools integrated with SMT equipment and document systems were not correctly imported into the FastGPT platform, or tool configuration parameters did not match the actual interface addresses of production line equipment.
- Phenomenon: Tool call results return incomplete fields, missing core information such as part numbers or reference designators. Cause: The call scope of `functionCall` was not limited. Tools called general tools that do not include electronic assembly document field recognition, and cannot accurately match exclusive process fields.

## How to Confirm Proper Configuration
- Access the FastGPT v4.17.0 platform, navigate to the configuration page of the target workflow, and check if the `toolChoice` parameter is set to `auto`. Confirm that the tool calling logic adapts to the current task.
- Upload a test SMT work order document, trigger a tool call, and verify that the timeout configuration falls within the 600–1200 second range. Confirm that the call duration meets expectations.
- Review the tool call results, confirm that returned fields include SMT-specific process information such as part numbers and reference designators. Verify that the `functionCall` tool set restriction takes effect.
- Simulate a temporary network interruption, trigger a tool call, confirm that the retry count is set to 2, and verify that review can be completed normally after the exception is resolved.
