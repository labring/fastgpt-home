# Cross-Review of Technical Documentation for SMT Mounting and Electronic Assembly: Deployment and Upgrade

## What data for this category looks like
Technical documents for SMT mounting and electronic assembly scenarios include BOM and coordinate files, line change lists, stencil and reflow oven temperature records, first article confirmation reports, SPI/AOI inspection reports, maintenance records, traceability labels, and more.
Data sources include customer-provided BOMs, Gerber files, component coordinates, as well as MES systems, mounters, SPI/AOI equipment, reflow oven temperature collection devices, and solder paste and component batch ledgers.
Data is synced in real time per work order and each line change.
Fields include part number, reference designator, substitute part, coordinate values, reflow oven temperature parameters, batch number, and more.
Units include millimeters, degrees Celsius, batch numbers, and more.

## What constraints these characteristics impose on deployment and upgrade
The scenario’s high-frequency real-time update requirements require the deployment phase to adapt to high-concurrency data access and index updates. Business disruption from connection exhaustion or synchronization delays must be avoided.
The need to access multiple document types and multi-source data requires configuring unified storage and docking logic. This ensures uniform retrieval of data from different sources such as BOMs and inspection reports.
Frequent line changes and work order updates require the upgrade phase to support rolling updates. This avoids interrupting ongoing document review tasks.
The need to accurately match core fields such as part number and reference designator requires index configuration to optimize these high-frequency query fields. This improves retrieval accuracy.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 15–25 connections | Adapt to concurrent database access from high-frequency work orders, avoid connection exhaustion |
| `REDIS_URL` | Local clustered address with password authentication | Cache frequent query results for part number and reference designator matches, reduce database load |
| `STORAGE_S3_ENDPOINT` | Enterprise self-built object storage node address | Store multiple types of original documents including BOMs and SPI/AOI reports, enable unified management |
| `PG_URL` | PostgreSQL instance address in the same network segment as the MES system | Dock with work order and line change data from the MES system, ensure low-latency access |
| `FILE_TOKEN_KEY` | Randomly generated 32-bit string | Encrypt document access tokens, prevent unauthorized access to technical documentation |

## Three common errors
- Symptom: After starting a local private deployment service, OOM errors or request timeouts occur when calling the large model. Cause: Sufficient GPU video memory is not reserved based on the scale of multi-dimensional data such as coordinate files and reflow oven temperature records processed in SMT scenarios.
- Symptom: Updated documents including BOMs and SPI/AOI reports do not appear in search results. Cause: The incremental index update mechanism of FastGPT v4.17.0 is not used, or storage path mapping is not configured correctly.
- Symptom: In multi-node deployments, some nodes cannot properly connect to the database or MCP service. Cause: The connection limit for `DB_MAX_LINK` is not set reasonably, or database access permissions for `PG_URL` are not configured uniformly.

## How to confirm proper configuration
- Run a database connection test to verify that configurations for `PG_URL` and `MONGODB_URI` can connect to their respective data sources normally.
- Upload a test BOM file to trigger a document update, confirm that matching content for the document is returned normally in search results.
- Start a multi-node deployment, check whether cached part number matching data is synchronized consistently across nodes via `REDIS_URL`.
- Call the large model interface with simulated SMT work order data, confirm that no OOM or timeout errors appear in the returned results.

The values provided are common starting points and should be measured against the reader's own samples.
