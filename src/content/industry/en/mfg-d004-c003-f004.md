# Cross-Review of Technical Documentation for Dairy Processing: Workflow Orchestration

## What this type of data looks like
Technical documents for dairy processing cover raw milk acceptance records, standardized ingredient lists, pasteurization or UHT heat treatment records, CIP cleaning records, filling records, and sample retention and microbial inspection reports. Data sources include milk source detection systems, MES production management systems, homogenization and heat treatment equipment, online temperature and flow monitoring devices, CIP systems, and LIMS laboratory information management systems. Data updates occur per milk tank, per batch, or in real time. Fields include clear units, such as raw milk antibiotic content (mg/kg), heat treatment temperature (℃), cleaning time (seconds), and others.

## What constraints these characteristics impose on workflow orchestration
Because data updates per milk tank or batch in real time, the workflow must support event triggering to ensure review starts immediately after data upload.
Because documents and equipment data for different batches are independent, the workflow must bind batch identifiers to prevent cross-batch data mixing.
Because document fields have clear units and numerical requirements, the workflow must include a built-in format check step to block invalid data from entering the review process.
Because dairy raw materials are perishable and errors carry serious consequences, the workflow must streamline steps to complete cross-review quickly and avoid delaying production timelines.

## How to Configure
The following configurations are written for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` binding | Pass the current batch's knowledge base ID and batch identifier | Based on dairy processing data management per tank or batch, dynamic association with the corresponding batch's document set is required |
| Trigger node type | Triggered by equipment data upload or document upload events | Based on real-time or per-tank/per-batch data updates, the workflow must start immediately |
| `nodeId` configuration | Bind the unique identifier of the knowledge base search node | Based on the need to accurately call the specified knowledge base retrieval node and avoid node confusion |
| Single search limit | Top 5 entries | Based on the need to complete cross-review quickly and avoid slowing the process with excessive results |
| Timeout setting | 600 seconds | Based on the need for rapid decision-making in dairy processing workflows and avoiding production delays |
| Export configuration | Generate Word download link | Based on the need to retain and archive workflow results and support quick export of compliant documentation |

## Three Common Configuration Mistakes
- Failing to retrieve target documents after passing the `variables` parameter via API: The symptom is that the returned result has no citation source. The cause is that the current batch's knowledge base ID was not correctly bound to the `variables` parameter.
- The workflow does not start analysis after uploading technical documents: The symptom is that the workflow node status remains pending. The cause is that the trigger node was not configured to trigger on document upload events, and a fixed periodic trigger mode is still used.
- No matching content is returned after configuring dynamic knowledge base search: The symptom is that the number of search results is 0. The cause is that the search scope was not limited to the current batch's document set, resulting in no corresponding data when searching the global knowledge base.

## How to Confirm Configuration Is Complete
- Upload the raw milk acceptance record for a single batch, and check whether the workflow starts automatically and enters the analysis node.
- Call the API with the current batch's `variables` parameter, and verify that the knowledge base search only returns documents for that batch.
- After running the workflow, check whether a Word download link is generated in the interface to confirm that the export configuration is active.
- View the workflow run logs to confirm that no format error alerts were triggered by the field check step.

The values provided are common starting points and should be measured against the reader's own samples.
