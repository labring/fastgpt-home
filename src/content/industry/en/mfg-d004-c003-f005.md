# Cross-Review of Technical Documentation for Dairy Processing: Tool Calling and Plugins

## What the Data for This Category Looks Like
Technical document data sources for dairy processing include raw milk testing, MES systems, homogenization and heat treatment equipment, online temperature and flow collection systems, CIP cleaning systems, and LIMS laboratory management systems. Data updates occur in real time for each milk tank and each product batch. Core daily documents include raw milk acceptance records, standardized ingredient lists, pasteurization or UHT heat treatment records, CIP cleaning records, filling records, sample retention reports, and microbial inspection reports. Document fields include raw milk antibiotic and physicochemical index values, heat treatment time and temperature, CIP cycle parameters, and filling aseptic status parameters. Units include ℃, seconds, cfu/mL, ppm, and others.

## What Constraints These Characteristics Impose on Tool Calling and Plugins
Real-time updated equipment and testing data requires tool calling to have low latency. This avoids missing the review window for raw milk or product batches due to wait timeouts. Multiple heterogeneous data sources require plugins to adapt to different systems' API formats. This ensures accurate pulling of technical documents for the corresponding fields. Exclusive documents per milk tank and per batch need dynamic binding to knowledge base groups. This prevents cross-batch data confusion. Perishable raw materials require fast cross-review completion. This avoids risks of entire milk tank raw milk rejection or product recall due to delays. Aseptic process verification requires precise matching of document fields. This ensures parameters meet specifications.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
|---|---|---|
| `toolChoice` | `auto` | Supports automatic tool selection for multiple types of technical documents in dairy processing, no manual plugin specification required |
| `functionCall` | `enabled` | Supports calling equipment data APIs and LIMS query plugins to complete cross-system document cross-verification |
| Maximum documents per single call | Top 6 entries | Matches the number of core technical documents for a single product batch, avoids context overload |
| Tool call timeout | 15–30 seconds | Adapts to the return delay of real-time equipment data, balances wait time and review efficiency |
| Knowledge base association rule | Dynamic binding by production batch | Matches the exclusive document group for each tank or batch of raw milk, avoids data confusion |

## Three Common Mistakes
- Symptom: A prompt stating the knowledge base ID does not exist appears during a call. Cause: Knowledge bases are not dynamically bound by production batch, and a global knowledge base ID is used directly, leading to matching failures.
- Symptom: Fields returned by tool calls are missing antibiotic or CIP parameters. Cause: Plugins do not correctly map the data source fields unique to dairy processing, and custom field configuration is not completed.
- Symptom: The workflow times out when uploading heat treatment records. Cause: No timeout interval adapted to real-time equipment data is set, and the default timeout is too short to retrieve complete temperature and time series data.

## How to Confirm the Configuration Is Complete
- In FastGPT v4.17.0, trigger the review process for a single batch of raw milk acceptance. Check the tool call logs, and confirm that `toolChoice` automatically matches the corresponding document query plugin.
- Upload the technical documents for a single product batch. Check the workflow run logs. Confirm there are no errors about missing knowledge base IDs, and that the bound knowledge base matches the current batch.
- Simulate document review for the CIP link. Confirm that the fields returned by tool calls include CIP cycle times and cleaning duration parameters, and that the data source is correct.
- Adjust the tool call timeout interval to 15–30 seconds. Simulate real-time equipment data pulling. Confirm there are no timeout errors and that the results are complete.
