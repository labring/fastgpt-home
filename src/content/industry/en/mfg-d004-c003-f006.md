# Cross-Review of Technical Documentation for Dairy Processing: Citation Sources and Traceability

## What the data for this category looks like
The main entities in this category are manufacturers of liquid milk, yogurt, milk powder, and dairy ingredients. Daily technical documents include raw milk acceptance records, standardized ingredient lists, pasteurization or UHT heat treatment records, CIP cleaning records, filling records, sample retention records, and microbiological test reports. Data sources cover raw milk testing equipment, production MES systems, homogenization and heat treatment online monitoring devices, CIP systems, and LIMS laboratory management platforms. Data is updated in real time for each milk tank and each production batch. Each document includes fields such as batch number, test values, operation time, and equipment number. Some records include measured data with units such as temperature and flow rate.

## What constraints these characteristics impose on the "citation sources and traceability" link
Real-time per-tank and per-batch data requires the traceability chain to be accurately bound to specific production batches to avoid cross-batch confusion. Multi-source heterogeneous data sources require unified association logic to ensure cited test values and operation records come from the original systems of the corresponding production links. The continuous production nature of perishable raw materials means abnormalities cannot be isolated per batch. If citation errors lead to compliance issues, wide-ranging risks will occur. Therefore, traceability must include complete document paths and field information. The dense field structure of single documents means key test parameters cannot be truncated during citation, and complete original record details must be retained.

## How to configure the settings
This configuration is optimized for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average length of single technical documents for dairy processing, avoids truncating key fields such as raw milk antibiotic test values and pasteurization heat treatment time |
| `responseData` | Enable and bind original document metadata | Supports tracing batch information from raw milk acceptance records, operation time from CIP cleaning logs, and other original data |
| `detail` | Return full context of matching fragments | Retains indispensable details such as aseptic parameters from filling records and colony count values from sample retention microbiological test reports |
| Single recall limit | Top 5 entries | Adapts to the number of documents associated with a single production batch, avoids excessive redundant information interfering with review logic |
| Document encoding verification | Enforce UTF-8 | Unifies document formats uploaded from multi-source systems, prevents garbled text issues |

## Three common configuration errors
- The cited knowledge base original document link cannot be downloaded normally, returning a 404 error or blank page. The cause is incorrect configuration of the nginx proxy's knowledge base file path mapping, which prevents the system from reading locally stored original documents.
- After sending a POST request to call a local large model, the interface returns a successful status code but no content field content. The cause is failure to enable the content output switch for `responseData`, or context parameter configuration exceeding the model's supported range.
- The cited document fragment display format is chaotic and contains garbled text. The cause is failure to enable document encoding verification configuration, or failure to set format sorting rules for the `detail` parameter, leading to inconsistent encoding across multi-source documents.

## How to verify successful configuration
- A standard raw milk acceptance record is uploaded to the knowledge base, an associated review request is initiated, and the returned results are confirmed to include exclusive fields such as raw milk batch number and antibiotic test values.
- The POST request interface is called, and the returned content is checked to include the original document path and metadata information bound by `responseData`.
- The displayed content of the cited fragment is viewed, and it is confirmed that there is no garbled text and the format is clear, matching the reading habits of business documents.
- A review request for multi-batch production data is simulated, and the number of recall results is verified to meet the single recall limit configuration requirements.

The values provided are common starting points and should be measured against the reader's own samples.
