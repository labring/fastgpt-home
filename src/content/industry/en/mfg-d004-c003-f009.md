# Cross-Review of Technical Documentation for Dairy Processing: Model Integration and Configuration

## Typical Data for Dairy Processing
Typical data for dairy processing originates from milk source testing, MES systems, homogenization and heat treatment equipment, online temperature and flow collection systems, CIP cleaning systems, and LIMS laboratory management systems. Daily documentation includes raw milk acceptance records, standardized ingredient lists, pasteurization or UHT heat treatment records, CIP cleaning records, filling records, sample retention and microbial test reports. Data updates occur per milk tank, per batch, or in real time. Core fields cover raw milk antibiotic and physicochemical indicator values, heat treatment parameters, cleaning parameters, and more, with units including ℃, seconds, CFU/mL, and other professional measurement standards.

## Constraints Imposed on Model Integration and Configuration
Cross-review of technical documentation for dairy processing requires frequent processing of real-time data for individual batches or tanks. Model calls must therefore adapt to a small-batch, low-latency request rhythm. Multi-source heterogeneous professional document fields require the model to accurately identify and associate parameters across different systems. This necessitates configuring appropriate context length and reference fragment length. Dairy production errors directly impact product safety, so model output must strictly match the fields and units of original documents. Adjust the rigor parameters for model generation, and avoid relying on default external API service configurations in offline deployment scenarios.

## Configuration Settings
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Covers the total token count of full-process documentation from raw milk acceptance to filling for a single tank, ensuring complete context for cross-review |
| `maxTokens` | 2000–3000 token | Meets the detailed output requirements for professional judgment, avoiding missing key review conclusions due to insufficient output length |
| `quoteMaxToken` | 1500–2000 token | Fully references core fields of a single device record or test report, ensuring traceability of review conclusions |
| `temperature` | 0.1–0.3 | Reduces randomness in model generation, ensuring rigor for professional document review and avoiding judgment results that deviate from original data |
| `AIPROXY_API_ENDPOINT` | Fill in according to the deployment environment, e.g. http://127.0.0.1:8080 | Adapts to offline or online deployment model service addresses, ensuring correct model call link |
| `AIPROXY_API_TOKEN` | Fill in with the key generated by the platform or a custom key | Ensures security of model integration, preventing unauthorized access requests |

## Three Common Misconfigurations
- Symptom: After upgrading to FastGPT v4.17.0, offline configured reranking models show request errors when the model test button is clicked. Cause: `AIPROXY_API_ENDPOINT` is not pointed to the container port address of the local reranking model, or a valid `AIPROXY_API_TOKEN` is not configured.
- Symptom: Custom model configuration does not disable one API service dependency, leading to incorrect request routing. Cause: The default enabled one API service configuration is not adjusted, and direct use of custom model integration causes link conflicts.
- Symptom: Cross-review results returned by the model lack document fields or professional units. Cause: `temperature` is not set to the 0.1–0.3 rigor range, resulting in model output that does not comply with dairy professional document specifications.

## How to Verify Successful Configuration
- Navigate to the model configuration page, click the model test button, and check if the returned result includes dairy professional document fragments such as raw milk acceptance records and heat treatment parameters.
- Check the configuration values of `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` to confirm they match the deployed model service address and key.
- Upload typical documents for a single dairy batch, run a cross-review task, and review the field completeness and professional matching of the returned results.
- View system logs to confirm there are no records of model call request timeouts or routing errors.

The values provided are common starting points and should be measured against the reader's own samples.
