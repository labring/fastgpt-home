# Cross-Review of Technical Documentation for Photovoltaic Module Encapsulation: Citation Sources and Traceability

## What Data for This Segment Looks Like
Photovoltaic module encapsulation data sources include battery cell grading ledgers, glass adhesive film and backsheet batch records, MES production management systems, string welding and lamination equipment operation logs, and output files from EL defect detectors and IV power testers.
The data update rhythm is that each module generates a dedicated document, and batch traceability records are synchronized for each batch of materials.
Daily documents include layout diagrams, material batch tables, lamination process parameter records, EL crack marking diagrams, IV power test reports, insulation withstand voltage test records, and finished product packing lists.
Core fields include battery cell current gear, lamination temperature and holding duration, EL crack location and area, IV test power value, and insulation resistance value. Units include amperes, degrees Celsius, seconds, watts, megohms, and others.

## What Constraints Do These Characteristics Impose on Citation Sources and Traceability
Each module’s document is independent and updated frequently. This requires the traceability system to accurately match all associated documents for a single module, to avoid incorrect cross-module associations.
Document types include images, text, tables, and test data. This requires the traceability system to support recall and display of multi-format content.
There are many core fields with clear business units. This requires precise matching of field keywords during retrieval, to avoid recalling irrelevant records.
Compliance reviews need to trace the association information between material batches and test equipment. This requires traceability results to include the original generation path of the document and equipment number.
Compared to the battery cell manufacturing segment, this category pays more attention to post-encapsulation lamination quality and power grading. Therefore, traceability must focus on encapsulation segment documents, and only cover the dedicated document library for photovoltaic module encapsulation.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | Adapts to the length of single records in photovoltaic encapsulation documents, to avoid truncating key parameters such as lamination temperature and EL crack area |
| `responseData` | Return only batch records, EL marking diagrams, and IV test values | Focuses on core business fields, reducing interference from irrelevant layout diagram content on retrieval results |
| `detail` | Enable full traceability | Displays the original upload path, generation time, and test equipment number of documents, to meet compliance review requirements |
| Single Recall Limit | Top 6 entries | Matches the number of associated documents for a single module, avoiding loading excessive redundant records from the same batch of materials |
| Context Window | 14000–16000 token | Accommodates multiple associated documents for a single module, such as material batch tables, lamination records, EL diagrams, and IV reports |

## Three Common Misconfigurations
- Phenomenon: A workflow runs an error after invoking the document retrieval plugin, with the input box displaying "parameter format error". The cause is failing to set the recall limit within the platform’s preset range, and entering a value outside the valid range.
- Phenomenon: The retrieval results return a large number of irrelevant battery cell manufacturing documents, without focusing on encapsulation segment content. The cause is failing to configure keyword filtering rules, and not limiting the retrieval scope to the dedicated photovoltaic module encapsulation document library.
- Phenomenon: The associated description text for EL diagrams is truncated, making complete crack marking information unviewable. The cause is failing to adjust the `quoteMaxToken` value, resulting in insufficient token quota and truncated key content.

## How to Confirm Correct Configuration
- In the FastGPT v4.17.0 environment, upload a complete document package containing single-module batch records, EL diagrams, and IV test reports, run a retrieval task, and verify that the returned results only include core business documents for that module.
- View the traceability details of the retrieval results, confirm that the upload path, generation time, and test equipment number of the documents are displayed.
- Adjust the `quoteMaxToken` value, verify that the returned EL diagram description text does not show truncation.
- Simulate a retrieval scenario with multiple module documents, confirm that no context overflow error prompt appears.

The values provided are common starting points and should be measured against the reader's own samples.
