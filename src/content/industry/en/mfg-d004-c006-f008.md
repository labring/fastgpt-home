# Cross-Review of Technical Documentation for Photovoltaic Module Encapsulation: Document Parsing and Chunking

## What this category of data looks like
Photovoltaic module encapsulation data sources include battery cell grading records, glass adhesive film and backsheet batch ledgers, MES system data, string welding and lamination equipment logs, EL tester images, IV test reports, insulation voltage withstand records, and packing lists.
Data is updated such that one record corresponds to each module, and batch ledgers are generated for each material batch.
Document structures include standardized process parameter tables, coordinate-bearing layout diagrams, and reports with test values.
Fields include current gear, lamination temperature, crack location, power value, and more. Professional units such as ampere, degree Celsius, and watt are used.

## What constraints do these characteristics impose on the document parsing and chunking workflow
Mixed document types require parsing tools to support structured extraction of text, tables, and image formats simultaneously.
High-frequency updated batch data requires parallel processing in parsing workflows to avoid single-file parsing timeouts.
Specific professional fields and units must retain their original formatting to prevent broken parameter associations after chunking.
MES and equipment log sources deployed on internal networks require parsing tools to support access to internal network resources.
Non-standard PDF formats from EL test images and IV reports require targeted parsing configuration adaptations.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Matches the single-section parameter length of photovoltaic process records and test reports, retains contextual association between adjacent fields |
| `chunkSplitter` | Split by paragraph + table boundaries | Adapts to mixed process text, parameter tables, and EL image descriptions in documents |
| `customPdfParse` | Enabled | Supports non-standard PDF formats generated by EL testers, retains original layout of images and tables |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 seconds | Adapts to parsing time for batch records and large EL image packages |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports uploading multiple batch ledgers and test report packages in a single operation |
| `chunkSettingMode` | Manual mode | Adjusts chunking rules separately for different document types to match extraction requirements for professional fields |

This configuration is based on FastGPT v4.17.0.

## Three Common Configuration Mistakes
- Parsing results produce unformatted full text, leading to poor readability after front-end rendering. The cause is failure to enable `customPdfParse` and configure `chunkSplitter` to split documents by boundaries.
- Valid content cannot be parsed from internal network Confluence pages. The cause is failure to configure an internal network access proxy, or `PARSE_FILE_TIMEOUT_SECONDS` being set too short, leading to timeouts.
- Battery cell current gear and corresponding lamination parameters cannot be associated after chunking. The cause is `chunkSize` being set too small, splitting associated parameters in the same segment into different chunks.

## How to Verify Proper Configuration
- A lamination process record PDF is uploaded, and parsed chunks are checked for retained table content and process parameter paragraphs.
- A link to a Confluence process document deployed on an internal network is uploaded, and parsing results are confirmed to include process descriptions and parameter tables on the page.
- 10 EL test reports from the same batch are uploaded in batch, and parsing tasks are confirmed to not trigger timeout errors.
- `chunkSize` is adjusted to 1000 characters, and chunked content is verified to fully cover associated content for a single group of battery cell gears and lamination parameters.

The values listed are common starting points and should be evaluated against the reader's own samples.
