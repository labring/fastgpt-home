# Cross-Review of Technical Documentation for Photovoltaic Module Encapsulation: Model Access and Configuration

## What data for this category looks like
In photovoltaic module encapsulation scenarios, data comes from cell grading systems, glass and adhesive film backplane batch ledgers, workshop MES systems, string welding and lamination equipment terminals, EL defect detectors, and IV power testers. Daily generated documents include layout diagrams, material batch records, lamination process parameter records, EL defect images, IV test reports, insulation withstand voltage test records, and finished product packing lists. The data update rhythm follows one set of test records per module, with batch ledgers generated synchronously for each batch of raw materials. Fields in individual documents include material specifications, equipment parameters, test values, batch numbers, and more. Formats vary based on production stage differences.

## What constraints these characteristics impose on the "model access and configuration" link
Data sources for this scenario are scattered and have large format differences, including multimodal images and structured reports. This requires model access configuration to support multimodal input capabilities. Each individual document corresponds to a single module, and data update frequency is high. Context parameters adapted for short-cycle batch document processing must be configured. Core verification links focus on cell current gear matching and lamination process compliance. The model must accurately associate material batches with equipment parameters, so configuration must strengthen context-related parameter settings to avoid cross-batch data confusion. Errors in the encapsulation link directly affect the long-term reliability of products. Parameters that balance accuracy and flexibility must be configured to ensure the rigor of review results.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale for This Setting |
| --- | --- | --- |
| `vision` | Enabled | This scenario requires processing multimodal documents such as EL defect images and IV test reports, so the model must have image recognition capabilities |
| `temperature` | 0.2–0.4 | Precise matching of standardized content such as cell gear positions and lamination process parameters is required, to avoid overly divergent output |
| `maxContext` | 8000–12000 token | The total length of material batch, equipment record, and test report associated with a single module fits this context range |
| `maxTokens` | 2000–3000 token | Length requirement for output content of single-round technical document cross-review |
| `AIPROXY_API_ENDPOINT` | Fill in the address provided by the deployment service provider | Access address requirements for connecting to third-party models |
| `AIPROXY_API_TOKEN` | Fill in the key allocated during deployment | Identity verification requirements for connecting to third-party models |

## Three common configuration mistakes
- Failure to load model vendor icons on the interface: The static resource path for the model vendor is not configured in FastGPT v4.17.0, causing icon resources to fail to load properly.
- Large model node returns 500 Gateway forwarding error: The model service fails to start normally or the connection with FastGPT is interrupted, and no health check mechanism is configured, resulting in failed request forwarding.
- Custom model encapsulated using the SSE protocol cannot be recognized: The model access is not configured according to the protocol format required by FastGPT, and the SSE mode is mistakenly bound to an unsupported node type, causing protocol verification to fail.

## How to confirm configuration validity
- Conduct multimodal input testing: Upload a single EL image and its corresponding IV test report, and verify whether the model correctly recognizes image content and associates structured data.
- Verify model response stability: Initiate continuous batch document review requests, and confirm no repeated errors or response interruptions occur.
- Verify interface key configuration: Compare deployment documentation with currently configured `AIPROXY_API_TOKEN` and `AIPROXY_API_ENDPOINT` to ensure parameter matching.
- Retest after adjusting parameters: Modify `temperature` or `maxContext` parameters, and verify whether review result consistency and accuracy meet expected standards.
