# Cross-Review of Technical Documentation for Photovoltaic Module Encapsulation: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Core data for this category comes from the battery cell grading system, glass adhesive film backplane batch ledger, workshop MES system, string welding and lamination production equipment, and EL and IV testers. Daily covered documents include module layout diagrams, material batch records, lamination process parameter records, EL defect images, IV power test reports, insulation voltage withstand test records, and finished product packing lists.
Data updates follow this rhythm: each produced component generates a dedicated test and record file, each batch of raw materials synchronously updates the batch ledger, and all data is bound to a unique production batch and component number.

## Constraints Imposed on Knowledge Base Retrieval and Recall
High data update frequency and each data entry bound to a unique production batch require precise matching of batches and component numbers during retrieval. This prevents calling incorrect process or test data across batches.
Document types include structured parameters and professional charts, so retrieval must support multi-modal content recall and structured field matching.
Single data entries are small in size, but total volume grows continuously with production scale. Retrieval links must adapt to high-concurrency, low-latency recall logic.
Matching battery cell current gears is a core time-consuming step. Retrieval must first recall documents highly relevant to the current batch’s battery cell parameters to reduce invalid matching overhead.

## Configuration Settings
These configurations follow the parameter rules for FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the precision requirements for photovoltaic module process parameters and test data; this interval filters low-relevance batch records and process documents |
| `limit` | Top 10 entries | The total number of documents associated with a single batch production is limited; recalling too many entries increases context stitching overhead; 10 entries cover core process and test reference needs |
| `searchMode` | `mixedRecall` | Balances matching of structured batch fields and unstructured process text, adapting to the retrieval needs of multiple document types in this category |
| `usingReRank` | Enabled | For professional documents such as EL images and IV test reports, reranking can improve the display priority of highly relevant results |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands retrieval keywords such as production batches and component numbers to match documents bound with corresponding identifiers |
| `collectionIds` | Bind corresponding knowledge base collections by production department | Documents from string welding, lamination, and testing departments are stored in separate databases; limiting retrieval scope by department scenarios reduces invalid recalls |

## Three Common Misconfigurations
- API calls for inserting documents return parameter verification failures. This occurs when a valid `collectionIds` parameter is not passed, and the target knowledge base collection ID is not specified.
- Retrieval of process documents or test reports takes longer than 30 seconds. This occurs when the retrieval scope is not limited, recalls are executed across multiple unclassified knowledge bases, and `usingReRank` is not enabled to optimize the retrieval link.
- Retrieval results only return matching content from a single knowledge base. This occurs when only a single `collectionIds` is bound, and the retrieval scope for multiple knowledge base collections is not configured, making cross-department associated documents unavailable for recall.

## How to Verify Correct Configuration
- Execute a retrieval request for a single batch of components, and confirm that the returned `collectionIds` match the knowledge base collections of the target department.
- Test retrieval using keywords that include battery cell current gears, and confirm that the sorting priority of returned results meets the relevance requirements for professional documents.
- Call the API to insert a test document, and confirm that the document is successfully synchronized to the specified knowledge base collection.
- Simulate a retrieval request in a production scenario, and confirm that the single retrieval time meets real-time requirements.

The values provided are common starting points and should be measured against the reader's own samples.
