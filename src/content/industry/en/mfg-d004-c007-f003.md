# Cross-Review of Technical Documentation for Stamping and Sheet Forming: Multi-Turn Dialogue and Prompt Engineering

## What data belongs to this category
The core entities in this category are stamping workshops of enterprises producing automobile body panels, household appliance sheet metal parts, and hardware components. Daily documents include stamping operation instructions, material utilization rate tables, mold inspection logs, first/last piece records, dimensional inspection reports, and mold change records. Data sources include steel coil labels and quality certificates, operation data of stamping presses and feeders, mold management systems, MES systems, and coordinate measuring machine or fixture inspection data. Data is updated synchronously for each coil of material, each production batch, and each mold change operation. Document fields include material grade, thickness, mold number, process parameters, dimensional tolerances, inspection results, and other relevant fields.

## Constraints for Multi-Turn Dialogue and Prompt Engineering
The high-frequency updates and multi-dimensional data characteristics of this category create multiple constraints for multi-turn dialogue and prompt configuration. Real-time data updates for each coil, batch, and mold change require multi-turn dialogue contexts to lock exclusive parameters for the current batch and mold, to avoid cross-batch confusion. Differentiated fields across multiple document types require prompts to clearly define review scope, and only call specified field information from corresponding documents. The real-time requirements of stamping processes require each interaction to synchronize the latest process data, to prevent reviews using outdated information. Additionally, the risk characteristics of mass production require the dialogue process to clearly distinguish the boundaries between context retention and reply content.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to a unique string tied to the current production batch and mold number | Ensure independent context for each batch review session, avoid cross-batch data confusion |
| `messages` | Retain 3 historical interactions and the latest process parameters for the current batch, with total length not exceeding 1000 tokens | Control context redundancy, adapt to the length of professional information for stamping processes; FastGPT v4.17.0 supports this configuration |
| `variables` | Inject global variables for the current steel coil grade, blank holder force parameters, and mold change time | Enable prompts to obtain real-time production data without manual entry |
| Maximum context length | 800–1200 characters | Adapt to the total information volume of single-batch stamping documents, avoid exceeding model processing limits |
| Prompt template | Limit review to only the current batch’s stamping operation instructions and dimensional inspection reports | Clarify review scope, avoid calling irrelevant data from mold inspection logs or mold change records |

## Three Common Misconfigurations
- Phenomenon: The AI reply is irrelevant to the current review question, and returns material utilization data from historical batches. Cause: The `chatId` is not used to bind the unique identifier for the current batch and mold, causing the session context to reuse historical data.
- Phenomenon: The prompt template fails to specify exclusive fields for stamping processes when configuring MCP, leading to returned parameters that do not match actual production. Cause: The prompt does not limit calls to specific fields from the mold management system and MES, such as blank holder force and drawbead parameters.
- Phenomenon: Global variables are not used correctly in multi-turn dialogue, leading to review results missing quality certificate information for the current steel coil. Cause: The `variables` configuration fails to inject parameters for the current steel coil’s grade and thickness, so the prompt cannot access the corresponding data.

## How to Verify Correct Configuration
- Manually trigger a review session, check if `chatId` is bound to the unique identifier for the current batch and mold number, and confirm that the session context does not reuse historical data.
- Input a query containing exclusive parameters for the current batch, verify that the AI reply only calls document data from the current batch, with no historical batch information included.
- Check the global variable configuration, confirm that parameters for the current steel coil and mold have been correctly injected, and that the prompt can call these variables normally.
- Test multi-turn interactions, confirm that each round of dialogue context only retains interaction records for the current batch, with no data from other batches mixed in.

The values provided here are common starting points, and should be evaluated against samples corresponding to the specific deployment scenario.
