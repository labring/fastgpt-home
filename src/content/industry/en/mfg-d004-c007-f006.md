# Cross-Review of Technical Documentation for Stamping and Sheet Forming: Citation Sources and Traceability

## What data for this category looks like
The data for this category comes from steel coil labels and quality certificates, press and feeder operation data, mold management systems, MES systems, coordinate measuring machine or fixture inspection reports. Daily documents include stamping work instructions, material utilization rate tables, mold inspection logs, first and last piece records, dimensional inspection reports, and mold change records. Data updates are triggered per coil of material, per production batch, and per mold change operation. Document fields include steel coil grade, sheet thickness, mold number, dimensional deviation values, etc., with corresponding units such as millimeters, newtons, tons, and others.

## What constraints do these characteristics impose on the "citation sources and traceability" link?
Multi-source and frequently updated data require precise matching of production batches and mold change nodes during traceability to avoid mixing data across batches. Document types cover long-text work instructions and structured tables, requiring chunking logic to adapt to content integrity across different formats. Fields include specific professional units, which must be associated with exact values of corresponding fields during traceability to ensure review accuracy. A large number of documents related to a single production run require controlling the recall scope to avoid redundant information interfering with the efficiency and accuracy of cross-review.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Chunk length | 800–1200 characters | Adapt to process paragraphs and structured table slices in stamping work instructions, avoid splitting complete instructions across mold changes |
| `quoteMaxToken` | 1500–2000 token | Retain complete field content of material utilization rate tables and dimensional inspection reports, avoid truncating key production data |
| Citation return toggle | Enabled | Corresponds to the `responseData` parameter configuration, ensures that returned results include original document information for citation snippets |
| Detail display | Enabled | Corresponds to the `detail` parameter, displays the path of the original document and the context content before slicing |
| Single recall limit | Top 6 entries | Match multiple types of documents related to a single stamping batch, avoid introducing irrelevant historical mold change records |

## Three common mistakes
- Terminal responses from API calls have no citation snippets: The cause is failure to enable the citation return toggle or incorrectly configure the `responseData` parameter, resulting in no citation metadata being returned.
- Unable to view the online preview of the original file corresponding to the citation snippet: The cause is failure to retain the path metadata of the original document during chunking, or the slicing logic not being associated with the original file before import.
- Recalled citation snippets do not match the current review question: The cause is an excessively long chunk length, causing the slice to include production data from other irrelevant batches, or setting the single recall limit too high, introducing redundant content.

## How to confirm the configuration is correct
- Upload a stamping work instruction and a material utilization rate table, initiate a test question that includes a specific production batch, and check whether the returned results include the original document name and path of the citation snippet.
- Call the FastGPT v4.17.0 corresponding API interface, verify whether the returned fields include content related to `detail` and `responseData`.
- Import a document containing a single mold change record, adjust the chunk length, view the knowledge base chunk preview, and confirm that the slice does not split the complete content of the mold change record.
- After enabling the citation display toggle in the knowledge base management interface, initiate a test question and answer, and confirm that the terminal reply displays detailed information about the citation source.

The values given are common starting points and should be measured against the reader's own samples.
