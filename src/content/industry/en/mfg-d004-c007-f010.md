# Cross-Review of Technical Documentation for Stamping and Sheet Metal Forming: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
Data for stamping and sheet metal forming scenarios comes from stamping workshops at automobile panel, household appliance sheet metal, and hardware component enterprises. Daily documents include stamping operation instructions, material utilization rate tables, mold inspection logs, first and last piece records, dimensional inspection reports, and mold change records. Data sources include steel coil labels and quality certificates, punch and feeder operation data, mold management systems, MES systems, and coordinate measuring machine or fixture inspection data. Documents contain fields with professional units: furnace number, yield strength (MPa), thickness (mm), drawbead clearance (mm), blank holder force (kN). The system updates data per material coil, per production batch, or each time a mold is changed.

## What Constraints These Characteristics Impose on Knowledge Base Retrieval and Recall
Multi-source heterogeneous data sources require retrieval to cover both structured numerical fields and unstructured text content. High-frequency data updates require the retrieval system to support incremental indexing and real-time recall, to avoid using outdated material or mold data. Strict matching requirements for professional units and parameters mean retrieval must balance semantic consistency and field format consistency, to prevent matching incorrect material specifications. Batch high-frequency document uploads require the system to support large file chunking and stable batch indexing, to prevent recall failure caused by overload in a single task.

## How to Configure the System
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `similarity` | `0.75–0.85` | Meets precision requirements for matching stamping professional parameters, filters low-relevance non-target documents |
| `limit` | `Top 8–12 entries` | Covers multi-parameter combination needs in stamping scenarios, while controlling context window usage |
| `searchMode` | `mixedRecall` | Balances dual needs of numerical parameter retrieval and text-based process retrieval |
| `usingReRank` | `Enabled` | Filters results with similar semantics but mismatched parameters, improves professional retrieval accuracy |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Supplements professional units omitted by users, matches document fields that include units |
| `collectionIds` | `Bind dedicated dataset ID for stamping workshops` | Isolates mold and material data across production lines, avoids invalid cross-scenario recall |

## Three Common Misconfigurations
- Symptom: After uploading files larger than 10 MB, some chunks fail vectorization, and recovery fails after repeated retry clicks. Cause: No breakpoint resume mechanism is configured for large file chunked uploads. Network fluctuations cause partial chunk upload failures that are not automatically retransmitted.
- Symptom: After batch uploading multiple documents, the server restarts, and the knowledge base does not automatically complete indexing, remaining in a stuck state. Cause: No automatic index trigger rule is enabled for the dataset, and no restart retry mechanism is configured for batch tasks. Manual index triggering is required.
- Symptom: Retrieval results from tool calls and MCP calls include documents outside the stamping scenario. Cause: No dedicated `collectionIds` are bound, leading to recall of content from datasets of other categories.

## How to Verify Successful Configuration
- View the dataset's indexing log panel, confirm that all chunks have a vectorization status marked as successful, with no abnormal errors.
- Enter a query with professional parameters, such as "Debugging steps for blank holder force of 0.8mm galvanized steel sheet", and verify the document type and field matching degree of the retrieval results.
- Test batch uploading more than 3 mold change records and material utilization rate tables, confirm that indexing tasks complete automatically, with no stuck or failure markers.
- After enabling `usingReRank`, compare sorting changes in retrieval results, confirm that highly relevant professional documents appear first.
