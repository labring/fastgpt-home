# Cross-Review of Technical Documentation for Cosmetics Production: HTTP Interfaces and External Systems

## What data for this category looks like
This category of data originates from daily production documents of skincare, haircare, makeup, and special cosmetics manufacturers. Documents include formula process sheets, weighing and feeding records, emulsification or filling records, cleaning and site clearance records, semi-finished and finished product inspection reports, and label review files.
Data sources cover registered and filed formulas, raw material safety materials, production equipment, ERP/MES systems, laboratory test results, and packaging material version documents. Updates occur with each production batch or each line change.
Document fields include raw material names and proportions, restricted substance content, production temperature parameters, batch numbers, packaging material specifications, and claimed content.

## Constraints imposed on HTTP interfaces and external systems
Data is updated in real time with each production batch or line change. HTTP interfaces must support high-frequency, small-batch data pulling and verification to avoid document version inconsistencies caused by expired caches.
Multiple data sources come from different systems. Interfaces must support field mapping for varying formats. Clear authentication rules must be defined for the `Authorization` parameter to connect to external systems such as ERP and MES.
Labels and formulas must match filed content. The `responseData` returned by the interface must include filing verification fields for real-time cross-review comparison.
Strong association with production batches requires interfaces to support queries by batch number. Variable transfer must bind global production batch information through the `variables` parameter to prevent mixing of data across batches.

## Configuration Settings
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| `Authorization` | Use a key format with the `Bearer` prefix, with a key length of no less than 32 characters | Complies with authentication specifications of external ERP and MES systems, prevents unauthorized access to production data |
| `variables` | Bind production batch numbers and line change identifiers as configurable parameters | Matches the update rhythm of each production batch, ensures cross-review data corresponds to the correct production batch |
| `responseData` | Require structured fields including raw material proportions, restricted substance content, and filing compliance identifiers | Facilitates direct data extraction for cross-verification of formulas and labels |
| Interface timeout setting | 30–60 seconds | Adapts to the average response duration of production data pulling, prevents blocking of production processes |
| Field mapping rules | Map production document standard field names to system verification fields | Compatibility with different data formats from multiple source systems, reduces field conversion errors |

## Three Common Configuration Mistakes
- Failing to add the `Bearer` prefix when configuring the `Authorization` parameter, which returns empty fields or prompts a null value error during calls. This occurs because the authentication format requirements of external systems are not followed, preventing the system from correctly parsing the key content.
- After releasing the workflow interface, external platforms cannot pass global production batch variables. This occurs because no externally passable variable identifier is configured in the `variables` parameter, so global variables cannot be bound.
- In versions prior to FastGPT v4.17.0, the dedicated configuration entry for external interfaces cannot be found, and a Cannot read property error is prompted during calls. This occurs because older versions do not support the connection requirements for multi-source production data, leading to parameter parsing failures.

## How to Confirm Configuration is Complete
- Call the test interface, check if the `responseData` returned includes core production document fields, and confirm field mapping matches configured settings.
- Pass a preset `variables` parameter, verify that the interface returns data bound to the corresponding production batch information.
- Verify the authentication effect of the `Authorization` parameter: use an invalid key to call the interface, and confirm the corresponding error status code is returned.
- Simulate batch data pulling, confirm the interface does not experience blocking or timeout errors, and adapts to real-time production scenario requirements.

The values provided are common starting points and should be measured against the reader's own samples.
