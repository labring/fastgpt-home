# Cross-Review of Technical Documentation for Cosmetics Production: Tool Calling and Plugins

## What Data for This Category Looks Like
Data for this category covers formula process sheets, weighing and feeding records, emulsification and filling records, cleaning and site clearance records, semi-finished and finished product inspection reports, label review documents, and other materials related to the production of skin care, hair care, makeup, and special cosmetics. Data sources include registered and filed formula databases, raw material safety materials, production equipment MES systems, ERP platforms, laboratory test data, and packaging material version management systems. Updates to data trigger with each batch production and each line change. Each individual document includes fields such as restricted substance content, process parameters, batch number, and packaging material specifications. Units include milligrams, degrees Celsius, batch numbers, and other standard units.

## Constraints on Tool Calling and Plugins From These Characteristics
Data updates trigger with each batch production and each line change. Tool calling must support real-time pulling of the latest batch production and filing data, and avoid using expired cached content. Plugins must be compatible with the interface formats of different systems and adapt to differences in field naming to support multi-source heterogeneous data sources. Each individual document includes specific professional fields such as restricted substance content and process parameters. Tool calling must accurately match target fields to avoid retrieving irrelevant content. Errors may trigger compliance risks such as off-shelf recalls. Tool calling must add a result verification link to ensure returned data aligns with filing requirements. The system must also handle requests for parallel review of multiple batches to avoid exceeding interface call frequency limits.

## How to Configure Settings
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `toolChoice` | `auto` | Allows the system to automatically match applicable tools, adapting to cross-review scenarios for multiple types of production documents |
| `functionCall` | `enabled` | Enables precise function calling, supporting extraction of specific professional fields such as restricted substance content and process parameters |
| Tool call timeout duration | `600 seconds` | Adapts to the time consumption of pulling multi-source production data, avoiding call interruptions due to large data volume |
| Number of data items returned by a single tool call | `Top 8 entries` | Controls the scale of returned data to avoid exceeding the model's context processing limit |
| Multi-source data synchronization frequency | `After each batch production is completed` | Updates data with each batch production to ensure that the latest filing and production records are used for review |
| Result verification trigger condition | `Automatically executed after call completion` | Performs consistency verification on returned review results to avoid compliance risks |

## Three Common Misconfigurations
- Phenomenon: Tool calls return empty results or missing fields. Cause: No field matching rules for multi-source data are configured, so the system cannot extract corresponding professional fields from MES and ERP systems.
- Phenomenon: Interface calls return a 429 status code, with concurrent requests restricted. Cause: No reasonable call frequency limit is set, and current limiting processing is not applied to parallel review requests for multiple production batches.
- Phenomenon: Tool calls time out, and tasks fail. Cause: No sufficiently long timeout duration is set, so the system cannot complete full pulling of multi-source production data.

## How to Verify Successful Configuration
- Initiate a simulated review request, and check whether the tool call automatically matches applicable data source interfaces.
- View the tool call return results to confirm that target fields such as restricted substance content and process parameters are included.
- Simulate multiple concurrent requests to verify that a reasonable current limiting mechanism triggers, with no interface errors.
- Submit real data from one production batch to check whether the result verification link activates normally and returns compliance prompts.
