# Cross-Review of Technical Documentation for Cosmetics Manufacturing: Deployment and Upgrade

## What Data for This Category Looks Like
Technical documentation for cosmetics manufacturing includes formula sheets, weighing and feeding records, emulsification and filling records, cleaning and site clearance records, semi-finished and finished product inspection reports, label review documents, and more. Data sources include registered and filed formula libraries, raw material safety materials, weighing and emulsification equipment, ERP/MES systems, laboratory testing systems, and packaging material version management systems.

Data updates are triggered by each production batch or each production line changeover. Individual documents include fields such as raw material CAS number, restricted substance content, production temperature, batch number, and packaging material version number. Units include degrees Celsius, kilograms, batch identifiers, and others.

## What Constraints These Characteristics Impose on Deployment and Upgrade
Multi-source heterogeneous data sources require configuring multi-format data access adaptation rules during deployment, to avoid synchronization failures caused by data format differences between equipment, ERP/MES, and filing systems.

High-frequency update triggers require configuring incremental synchronization trigger mechanisms during deployment, to support real-time synchronization needs for each production batch or production line changeover.

Compliance requirements for document fields require compatibility with the latest filed data formats during upgrades, to ensure that verification logic for formulas, labels, and other documents meets regulatory requirements.

The high-risk nature of the data requires configuring strict permission verification and storage encryption rules during deployment, to prevent leaks of sensitive raw material and formula data.

## How to Set the Configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `REDIS_URL` | `redis://<internal IP>:6379` | Cosmetics production data is updated frequently. Internal network deployment reduces cache latency, and meets the session and vector cache requirements of FastGPT v4.17.0 |
| `MONGODB_URI` | `mongodb://<user>:<pwd>@<host>:27017/cosmetic_docs?authSource=admin` | Stores multiple types of documents including formula sheets, inspection records, etc. Specifying the business database name isolates data, and authSource ensures effective permission verification |
| `ROOT_KEY` | Combination of letters, numbers, and special characters with a length of ≥16 characters | Avoids periodic reset issues for the default root account, complies with production environment security specifications, and addresses the abnormal reset scenario reported by the community |
| `DB_MAX_LINK` | 20–30 connections | Adapts to concurrent read requests from multi-source data access, and avoids database connection exhaustion |
| `STORAGE_S3_ENDPOINT` | `https://cos.<region>.tencentcs.com` | Connects to object storage to store cleaning records, packaging material scans, and other files, and adapts to domestic cloud storage access formats |

## Three Common Misconfigurations
- Symptom: After configuring qwen3-embedding-8b as the indexing model, retrieval results cannot generate valid vectors. Cause: The model's access address and parameters are not correctly specified in the configuration file, and the model format supported by FastGPT v4.17.0 is not matched.
- Symptom: Pulling the Redis image fails when executing the docker compose up command, returning "manifest not found" or network timeout errors. Cause: No domestic image acceleration source is configured, pulling the official image directly is restricted by network conditions, and the Alibaba Cloud image repository address is not specified.
- Symptom: The root account password is automatically reset to 123456 every 1 day. Cause: The default `ROOT_KEY` parameter is not modified during deployment. The default configuration of FastGPT v4.17.0 triggers a periodic password reset logic, and the default key is not replaced.

## How to Verify Proper Configuration
- Execute the docker compose ps command, confirm that all service containers are in the running state, and there are no abnormally exited logs.
- Upload a cosmetics formula sheet, check whether the system can correctly identify fields such as raw materials and restricted substances and complete indexing.
- Access the backend address corresponding to `FE_DOMAIN`, log in with the custom root account password, and confirm that the login status is stable without automatic reset.
- Trigger a synchronization task after a production line changeover, check whether relevant data from ERP and laboratory systems can be normally incrementally synchronized to the system.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
