# Cross-Review of Technical Documentation for Pharmaceutical Dosage Form Manufacturing: Vector Models and Indexes

## What Data for This Category Looks Like
This category’s data primarily originates from approved formulation processes, material batch information, MES/electronic batch records, equipment and environmental monitoring data, LIMS systems, and quality management systems. Daily documents include master production documents, batch production records, batch packaging records, cleaning validation records, inspection records, deviation, CAPA, and change documents, batch release review forms, and more. They contain fields such as material batch numbers, weighing values, process parameters, deviation descriptions, and use standardized units including kilograms, degrees Celsius, hours, and others. Data updates follow the rhythm of each production batch, each key process step, and established monitoring plans. Strongly related field dependencies exist across different documents.

## Constraints Imposed on Vector Models and Indexes by These Characteristics
The data characteristics of this category impose multiple constraints on the vector models and indexes link. First, data that is frequently updated by batch and key process steps requires indexes to support incremental updates and version management, to avoid resource consumption from full reindexing. Second, documents mix textual descriptions and structured process parameters, requiring vector models to adapt to embedding multiple types of content, ensuring that numerical and text-related information is not lost. Third, strong field dependencies exist across different documents—for example, batch records and deviation documents share material batch number fields—requiring that field context is preserved during chunking, to avoid breaking cross-document associations. Finally, compliance requirements mandate data traceability, so indexes must support immutable storage and audit trails.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the text length of a single process step or segment of a batch record, avoiding truncation of critical information across steps |
| Overlap Length | 100–150 characters | Preserves contextual associations between adjacent process steps, ensuring complete process logic can be identified after chunking |
| Similarity Threshold | 0.75–0.85 | Differentiates normal fluctuations in process parameters from compliance deviations, aligning with the rigor requirements of GMP reviews |
| Single Search Limit | Top 10 results | Covers the number of associated documents required for single-batch review, balancing recall efficiency and review comprehensiveness |
| `defaultToken` | 8000 | Adapts to the total text length of a typical single batch record, meeting the contextual input requirements for complete process steps |
| `maxToken` | 16000 | Accommodates review context across multiple associated documents, supporting deviation correlation analysis across records |

## Three Common Misconfigurations
- Symptom: Blank options appear when selecting an index model, or an error message reading "failed to load index model" is displayed. Cause: The vector model file adapted for pharmaceutical documents was not deployed to the FastGPT specified directory, or the model path was not correctly declared in the configuration file.
- Symptom: Associated documents returned by search fail to accurately match process parameters or deviation descriptions. Cause: Chunk length was set too small, truncating the complete context of a process step and causing key associated information to be lost during vector embedding.
- Symptom: Context timeout errors occur during batch record review. Cause: The `maxToken` setting does not cover the total text length of multiple associated documents, exceeding the model's input limit.
