# Cross-Review of Technical Documentation for Pharmaceutical Preparations Production: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data for this category comes from approved formulation processes, Manufacturing Execution System (MES) electronic batch records, Laboratory Information Management System (LIMS), quality management systems, and similar systems. Updates follow each production batch, each critical process step, and execution per environmental and equipment monitoring plans.

Daily documents include master production files, batch production records, batch packaging records, cleaning records, inspection records, deviation Corrective and Preventive Actions (CAPA) changes, and batch release review forms. Fields cover material batch identifiers, process execution parameter values, deviation descriptions, inspection result values, and units including mass units, temperature, time intervals, and more.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
Data for this category is scattered across multiple systems and updated at high frequency. Multi-turn dialogue must limit context scope to avoid loading redundant data from expired batches.

Document structures include multiple types of compliance files. Prompts must clearly specify the document types and corresponding fields to be reviewed, to ensure precise retrieval scope.

Reviews for each batch must link multi-dimensional data such as materials, processes, and inspections. Multi-turn dialogue must support associating context by batch ID to avoid mixing data across batches.

Additionally, reviews under compliance requirements must fully record the basis for each interaction. Prompts must guide the output of traceable review nodes.

## Configuration Settings
This configuration is adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Dialog context window | Top 10 interaction records | Avoid loading excessive redundant data from expired batches, and adapt to single-batch review scenarios |
| `variables` binding | Bind batch ID and document type variables | Associate corresponding data by production batch, avoid mixing data across batches |
| `chatId` association | Bind unique identifier of production batch | Ensure unified conversation history for reviews of the same batch, meet compliance traceability requirements |
| Retrieval scope limit | Limit to 800-1200 character document fragments of the current batch | Narrow retrieval scope, improve review accuracy, adapt to single-batch document length |
| Interaction timeout | 600 seconds | Adapt to the thinking time required for complex cross-document reviews |

## Three Common Misconfigurations
- When configuring conversation opening shortcut keys, fail to bind preset prompts for the corresponding review scenario. The root cause is failure to associate shortcut keys with batch variables bound via `variables`, leading to failure to load document context for the corresponding batch when triggered.
- When viewing conversation history without a login status, associated document screenshots fail to load. The root cause is failure to configure the binding logic between `chatId` and batch ID, leading to failure to match stored data for the corresponding batch in the context.
- When calling other applications or plugins in a workflow, conversation logs are not recorded. The root cause is failure to enable the log synchronization configuration for `messages`, leading to failure to archive interaction records.

## How to Verify Proper Configuration
- Enter a test batch ID, check if the conversation context only links to documents for that batch.
- Trigger a nested application scenario, confirm if the dialog box of the form input node is hidden as configured.
- Call the associated plugin, check if conversation logs are synchronized and recorded.
- Check if the values of configuration items meet preset compliance review requirements.

The values provided here are common starting points, and should be evaluated against the user's own samples.
