# Cross-Review of Technical Documentation for Pharmaceutical Dosage Form Manufacturing: Model Access and Configuration

## What Data Looks Like for This Category
Daily documents for this category include master production files, batch production records, batch packaging records, cleaning records, inspection records, deviation/CAPA/change control documents, and batch release approval forms. Data sources include approved formulation processes, material batches, MES/electronic batch records, equipment and environmental monitoring data, LIMS, and quality management systems. Data updates are triggered with each batch production, key process step, and monitoring plan execution. Core fields include material batch numbers, process parameters, test results, deviation descriptions, and release status. Units follow standard pharmaceutical manufacturing units such as mass, volume, and temperature.

## Constraints Imposed on Model Access and Configuration
Documents for this category are tightly bound to production operations and must comply with regulatory requirements. Model access must support accurate matching of structured and semi-structured documents. Data is updated dynamically with each batch production, so interfaces that support dynamic pulling of the latest batch data must be configured. For core compliance field verification, model outputs must link to original data sources, so context reference configuration must be enabled. Batch release decisions rely on multi-source data aggregation, so models must support cross-document correlation analysis. Call latency must align with real-time review rhythms to avoid disrupting production cycles.

## How to Set Configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Documents for this category are mostly multi-source batch record summaries, requiring sufficient context to hold complete batch data and avoid truncation of critical compliance information |
| `temperature` | 0.1–0.3 | Cross-review of technical documents must strictly follow established rules; low temperature ensures output consistency and compliance |
| `quoteMaxToken` | 2000 characters | Sufficient original document fragments must be retained for compliance tracing, matching the average single-page length of batch records |
| `toolChoice` | auto | The model must independently determine whether to call document retrieval tools to complete cross-verification, adapting to multi-source data correlation analysis needs |
| `AIPROXY_API_ENDPOINT` | Fill in the locally deployed model gateway address | Adapt to enterprise local deployment model call requirements, ensuring production data stays within the network to meet compliance rules |
| `AIPROXY_API_TOKEN` | Fill in the exclusive token generated by the gateway | Restrict unauthorized model calls and ensure access security for production data |

## Three Common Misconfigurations
- Phenomenon: Model calls return a connection refused error, and the interface displays model connection failure. Cause: `AIPROXY_API_ENDPOINT` is not correctly configured to the locally deployed model gateway address, or the gateway service is not running properly, or the port is not open, so a valid connection cannot be established.
- Phenomenon: Generated cross-review reports lack linked original document fragments. Cause: The `quoteMaxToken` parameter is not configured, or its value is too small, preventing the model from extracting and returning linked original document content.
- Phenomenon: Single-batch document review takes too long, triggering platform timeout limits. Cause: The `maxContext` parameter is set too large, exceeding the context window limit supported by the model, leading to increased model processing delay.

## How to Confirm Configurations Are Correct
- Manually trigger a cross-review task for a single batch of documents, check the model call logs to confirm the request address matches the `AIPROXY_API_ENDPOINT` configuration.
- After the review result is generated, verify that linked original document fragments are included, confirming the `quoteMaxToken` parameter configuration meets the current document's reference requirements.
- Submit 3 to 5 different batches of documents for review in bulk, confirm that no connection failures or timeout errors occur, and adjust parameters based on actual operating rhythms.
- Check the consistency of model output results, confirming the `temperature` value meets the rigor requirements for compliance reviews.

The values provided are common starting points and should be measured against the reader's own samples.
