# Cross-Review of Technical Documentation for Medical Device Assembly and Cleanroom Production: Vector Models and Indexes

## What data for this category looks like
Data for this category originates from design history files, device and material batch records, MES systems, clean environment monitoring equipment, sterilization equipment, and inspection and calibration systems. Daily documentation includes production process specifications, batch production records, clean zone records, sterilization batch records, inspection reports, software version records, adverse event and traceability materials.
Data updates follow a per-batch or per-product cycle, and also sync with clean environment monitoring plans. Documents contain fields such as controlled assembly requirements, unique material identifiers, sterilization parameters, and clean environment monitoring data. Some records require association with batch and device numbers.

## What constraints these characteristics impose on vector models and indexes
Data for this category is scattered across multiple systems, and includes structured batch records and unstructured process documents. Indexes must support vector association between structured metadata and unstructured text.
Data is updated frequently per batch or monitoring plan. Incremental indexing logic must be adapted to avoid excessive time spent on full reconstruction.
Documents must link specific fields such as unique device identifiers and sterilization parameters. Vector retrieval must retain metadata for accurate traceability.
Some records involve controlled compliance content. Indexes must support filtering retrieval results by document type and batch range.

## Configuration Settings
These configurations apply to FastGPT v4.17.0:

| Configuration Item | Recommended Value | Rationale |

| Chunk Length | 800–1200 characters | Aligns with the length of single-segment compliance text in this category’s process specifications and batch records, preventing split of associated information within chunks |
| Overlap Length | 120 characters | Preserves key cross-chunk associated fields such as batch unique identifiers and sterilization parameters, preventing loss of cross-batch association information during retrieval |
| Similarity Threshold | 0.78–0.82 | Matches the strict compliance review standards for this category, filtering low-relevance non-compliant documents and invalid records |
| Single Search Limit | Top 8 results | Controls the number of recalled results, adapts to the precision needs of batch-associated retrieval, and avoids redundant results interfering with compliance reviews |

## Three Common Misconfigurations
- Symptom: Embedding model calls to OneAPI return connection timeout or 404 errors. Cause: Field formats for this category’s documents are not adapted, leading to OneAPI verification failure, or the configured model name does not match the model mounted on OneAPI.
- Symptom: After enabling reranking configuration, online recall test results are not sorted by reranking. Cause: Reranking association settings are not enabled during index construction, or reranking model call parameters do not match the length requirements of this category’s documents.
- Symptom: After selecting an open-source index model, retrieval speed fails to meet the real-time needs of batch-based review. Cause: The incremental refresh cycle of the index is not adjusted based on the update frequency of this category’s data, leading to excessive system resource consumption from full index reconstruction.

## How to Confirm Proper Configuration
- Perform index construction for a single batch of documents, check if the index log contains the batch’s unique identifier and associated metadata.
- Submit a retrieval request for a specific sterilization parameter, verify that recalled results include the corresponding batch’s sterilization batch records.
- Trigger an incremental index update, check that the system only synchronizes updated batch records and environment monitoring data, and does not perform full reconstruction.
- Call the Embedding model interface, verify that the returned vector data format matches the system’s preset vector dimensions.

The values provided are common starting points, and should be evaluated against the reader’s own samples.
