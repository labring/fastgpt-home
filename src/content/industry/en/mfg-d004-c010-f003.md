# Cross-Review of Technical Documentation for Medical Device Assembly and Clean Production: Multi-Turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
This category’s core data includes production process specifications, batch production records, clean zone records, sterilization batch records, inspection reports, software version records, adverse event and traceability materials.
Data sources cover design history files, device and material batch records, MES systems, clean environment monitoring equipment, sterilization equipment, and inspection and calibration systems.
Data updates run per batch or per device. Clean environment monitoring data updates on a set regular schedule.
Single-batch documents include exclusive fields such as unique device identification, batch number, sterilization parameters, and clean zone temperature and humidity.

## What Constraints These Characteristics Impose on Multi-Turn Dialogue and Prompt Engineering
Data sources are scattered and tightly linked to the current batch. Multi-turn dialogue must accurately bind the exclusive dataset for the corresponding batch to avoid mixing cross-batch documents.
Documents contain strongly constrained fields like unique identification and sterilization parameters. Prompts must guide the system to prioritize extracting and verifying these fields.
Frequently updated real-time data requires dialogue context to retain recent batch information. This prevents expired data from being used during reviews.
Reviews for this category cover multiple document types. Recall results must be accurately filtered to avoid irrelevant information interfering with core judgments.

## Configuration Settings
These configurations are based on FastGPT v4.17.0:

| Configuration Item | Recommended Approach | Rationale |
|---|---|---|
| Dialogue context retention length | Previous 10 rounds of dialogue context, or 2000–3000 characters | Reviews for a single batch of this category require linking multiple documents. Retaining key batch information prevents context loss |
| Prompt variable configuration | Bind `variables` to current batch ID and clean zone number | Accurately locate exclusive documents for the current batch’s production, sterilization, and other processes. This narrows the recall scope |
| Knowledge base single-recall upper limit | Top 8 recall results | This category has multiple document types. Too many results will interfere with judgments on core review points |
| Dialogue opening preset | Preset 3 review questions linked to the current batch | Helps operators quickly focus on core links such as sterilization parameter verification and unique identification checks |
| Session identification configuration | Carry `chatId` parameter to bind the current session | Ensures context association for multi-turn dialogue, avoiding session confusion |
| Source return configuration | Enable returning original document paths | Meets the need to trace documents during reviews |

## Three Common Configuration Errors
- A 404 status code with no body occurs during dialogue. This happens when the exclusive knowledge base dataset for the current batch is not correctly bound, or the `chatId` parameter does not carry the current session’s unique identifier. The system cannot locate linked documents in this case.
- The dialogue opening does not generate targeted questions. This occurs when variables such as batch ID and clean zone number are not configured in `variables`. The opening cannot link to the specific batch under current review.
- Recall results do not display source original text. This stems from failing to enable the return source original text configuration item, or knowledge base chunks not correctly linking to the original documents’ storage paths.

## How to Confirm Configuration Is Successfully Applied
- Initiate a test dialogue, enter the current batch’s unique identifier. Check if the dialogue context retains this identifier, and if the `messages` parameter includes key review information from historical dialogues.
- Trigger a knowledge base recall. Verify that returned results only include documents linked to the current batch, such as production, sterilization, and clean zone documents. No irrelevant content from other batches should appear.
- Check if dialogue return results include the original source document’s path or number. Confirm the `variables` have been correctly passed to the prompt.
- Simulate a multi-turn review dialogue. Confirm the system can continue asking for verification details of exclusive fields like sterilization time and clean zone temperature and humidity based on the previous round of questions.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
