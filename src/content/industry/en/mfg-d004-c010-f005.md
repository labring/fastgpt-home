# Cross-Review of Technical Documentation for Medical Device Assembly and Clean Production: Tool Calling and Plugins

This configuration is formulated based on FastGPT v4.17.0.

## What data looks like for this category
Data sources for this category include design history files, device and material batch ledgers, manufacturing execution systems (MES), clean environment monitoring equipment, sterilization equipment, and inspection and calibration systems. Data is synchronized each production batch or when a single device is completed. Clean environment monitoring data is updated regularly per a set schedule.

Daily documentation includes production process specifications, batch production records, clean zone operation records, sterilization batch records, inspection reports, software version logs, adverse event and traceability archives. Fields include unique device identification, material batch numbers, clean environment parameters, sterilization parameters, inspection results, software version numbers, and additional relevant fields.

## What constraints do these characteristics impose on the "tool calling and plugins" workflow
Data for this category is scattered across multiple production and quality systems. Tool calling must support connecting to multiple data source interfaces to sync different types of documents.

Data updates per production batch or on a regular schedule. Tools must support filtering search results by batch number and time range. This prevents expired or mismatched production data from being included.

Documentation fields include dedicated medical device identification and clean environment parameters. Tool calling must recognize and verify the format of these dedicated fields. This ensures search results align with review requirements.

For traceability and compliance reviews, tool return results must include core fields such as associated batches and sterilization parameters. This supports cross-check logic.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports automatic tool selection for multiple document types in this category, covering different data sources such as production process specifications and clean zone records |
| Single search limit | Top 10 entries | Matches the core retrieval volume for single-batch production documents, avoids redundant data interfering with cross-review |
| Maximum context | 8000 token | Adapts to the total character size of single-batch documents, meets retrieval requirements for complete processes and batch records |
| Single retrieval data volume | 1000 MB | Adapts to the storage size of single-batch documents, avoids exceeding system memory limits |
| `functionCall` | Enable mandatory verification | Ensures tool call return results include mandatory compliance fields such as unique device identification and sterilization parameters |
| Timeout threshold | 600 seconds | Covers the time required for multi-data-source synchronization and complex document parsing, prevents mid-interruption of review processes |

## Three common mistakes
- Issue: Tool call return results lack mandatory fields such as unique device identification and sterilization parameters. Returned data cannot support traceability reviews. Cause: Mandatory verification for `functionCall` is not enabled. Retrieval field rules are not specified. This causes returned results to fail to meet compliance review requirements.
- Issue: Self-built front-end docking pages have abnormal styles and cannot match the platform's native interaction logic. Cause: Official recommended embedding solutions are not used. Direct interface calls do not adapt to the platform's interaction specifications.
- Issue: 401 unauthorized error is returned when calling the interface. Cause: Verification token calling rules are not configured correctly. Token format or validity period settings do not meet platform requirements.

## How to confirm the configuration is complete
- Manually initiate a tool call for a specified production batch. Check whether returned results include preset mandatory fields.
- Review tool call operation logs. Confirm that the timeout threshold setting matches the response duration of currently connected data sources, with no frequent timeout records.
- Compare search results with actual production batch document content. Confirm that only data within the current batch range is returned, with no expired historical content.
- Adjust the `toolChoice` parameter value. Verify that the automatic tool selection function can cover different types of documents such as production process specifications and clean zone records, with no call failure prompts.
