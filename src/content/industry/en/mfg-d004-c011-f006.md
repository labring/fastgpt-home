# Cross-Review of Technical Documents for Semiconductor Packaging and Testing: Citation Sources and Traceability

## What the data for this category looks like
Semiconductor packaging and testing technical documents include packaging process cards, bonding and molding parameters, wafer incoming material diagrams, test program versions, yield reports, and failure analysis reports.
Data sources cover wafer test diagrams, MES systems, bonding and molding equipment, ATE test machines, X-ray/SAM detection equipment, and customer specification requirements.
Data updates sync with production batches, single-chip testing, and daily operations.
Document fields include batch identifiers, process parameters, test results, equipment numbers, and other items, and must match the original field formats of corresponding equipment or systems.

## What constraints do these characteristics impose on citation sources and traceability
The multi-source, heterogeneous data characteristics of semiconductor packaging and testing require that citation traceability must accurately bind production batches, equipment numbers, and wafer identifiers to avoid cross-batch confusion.
Frequently updated single-chip test data and daily operation logs require traceability logic to support quick location of the latest associated documents by production node.
Field differences across document types—such as numeric fields in packaging parameter tables and text descriptions in failure analysis reports—require traceability to match the exclusive identifier fields of corresponding documents.
This link must also align the association between wafer diagrams and physical batches to provide a traceable original data chain for subsequent failure analysis.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | `800–1200 token` | Packaging and testing documents include long parameter tables and failure analysis reports, requiring complete retention of cited content |
| `responseData` | Return original source ID and batch number | Must bind production batches and equipment numbers to meet core traceability requirements |
| `detail` | Enabled | Need to display specific fields of cited documents, such as ATE test bin codes, molding temperature parameters |
| Single search limit | Top 6 entries | The number of associated documents per production batch is limited, avoiding redundant citations that interfere with results |
| Context window | `1500–2000 characters` | Need to integrate associated information from wafer incoming material diagrams and test programs to ensure complete contextual logic |

## Three common mistakes
- Symptom: When configuring the knowledge base search link, no optional values are available for variable references. Cause: The variable output node was not pre-configured in the conversation flow, or the variable was not bound to the input parameters of the search link.
- Symptom: A `Cannot redefine property: toString` error is triggered in the online environment. Cause: The `toString` global method was declared repeatedly in a custom code block, or an introduced extension conflicts with the built-in prototype method of FastGPT v4.17.0.
- Symptom: The returned citation traceability information only includes document body content, and does not associate production batches and equipment IDs. Cause: The extraction rule for source fields was not configured in the knowledge base citation template, and only the core document text was extracted.

## How to confirm the configuration is complete
- Submit a test query that includes production batch keywords, and check whether the returned results attach the batch number and equipment identifier of the original source.
- Adjust the value of `quoteMaxToken`, and verify whether the length of the returned cited content meets expectations.
- Trigger a test request in the online environment, and confirm that no `Cannot redefine property: toString` errors occur.
- Compare the prompt and the knowledge base citation template configuration, and confirm that their scope of action and format requirements are clearly distinguished.
