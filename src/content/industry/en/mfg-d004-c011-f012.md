# Cross-Review of Technical Documentation for Semiconductor Packaging and Testing: Deployment and Upgrade

## What the data for this category looks like
Data sources for this category include wafer test maps, MES production management systems, bonding and molding equipment logs, data collected by ATE test machines, X-ray/SAM inspection results, and customer specifications. Daily generated documents cover packaging process cards, bonding and molding parameter tables, incoming wafer maps, test program version files, yield reports, and failure analysis reports. Data update frequencies cover each production batch, each chip test cycle, and daily summary cycles. Documents include dedicated fields such as wafer ID, test bin value, parameter thresholds, and batch number. Units involve electronic manufacturing-specific metrology standards including voltage, time, and yield percentage.

## What constraints these characteristics impose on the deployment and upgrade phase
The data sources for this category cover industrial equipment, production systems, and customer documents. The high-frequency update feature requires the deployment phase to support low-latency data access and parsing. Multiple types of documents include dedicated fields and units, so document parsing rules adapted to electronic manufacturing scenarios must be configured during deployment. The time sensitivity of production links requires that core document processing processes not be interrupted during upgrades, so a rolling upgrade method must be used. At the same time, cross-system docking requirements require configuration items to be compatible with interface specifications of industrial systems such as MES and ATE test machines, to avoid production schedule impacts from data synchronization interruptions.

## Three common mistakes
- Symptom: Slow download speed when pulling the `fastgpt-minio` image, with download timeout errors displayed in the interface. Cause: No domestic mirror acceleration source is configured, and pulling the official image directly leads to excessive cross-network transmission delays.
- Symptom: Unable to add image datasets after private deployment, with the image upload button missing in the knowledge base page. Cause: `STORAGE_S3_ENDPOINT` and associated storage keys are not correctly configured, causing the file storage module to fail to load properly.
- Symptom: Low matching accuracy of cross-review results, with incoming wafer maps unable to be correctly associated with batch data. Cause: Document indexing rules are not configured based on the dedicated fields of this category (such as wafer ID and test bin value), leading to semantic matching deviations.

## How to confirm the configuration is complete
- Run the database connection test script to verify that configuration items such as `MONGODB_URI` and `REDIS_URL` can establish normal connections, and confirm that the connection pool quantity meets the `DB_MAX_LINK` configuration range.
- Upload two typical documents: packaging process card and wafer test map, check that files can be stored normally and retrieved in the knowledge base, to verify that the `STORAGE_S3_ENDPOINT` configuration takes effect.
- Access the intranet address corresponding to `FE_DOMAIN`, confirm that the FastGPT frontend page loads normally, and that the tag function of the knowledge base module can be enabled normally.
- Simulate high-frequency data writes, observe that the database connection count does not exceed the `DB_MAX_LINK` configuration value, and confirm that system load meets expectations.
