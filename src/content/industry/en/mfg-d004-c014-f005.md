# Cross-Review of Technical Documentation for Dyeing and Finishing: Tool Calling and Plugins

## What the data for this category looks like
This category of data originates from customer color swatches, formula libraries, dye chemical batch ledgers, dye vat operation records, colorimeter readings, setting machine parameters, and environmental monitoring data. Daily documents include dyeing formulas, chemical weighing records, dye vat temperature curves, proofing confirmation sheets, color difference reports, setting process sheets, and sewage discharge ledgers. Data is generated per vat, per batch, or per shift. Individual documents contain fields such as vat number, batch number, dye ratio (unit: g/L), heating rate (unit: ℃/minute), and holding duration (unit: hour).

## What constraints these characteristics impose on the "tool calling and plugins" workflow
The batched, frequently updated data characteristics of this category require tool calls to bind vat number and batch number as unique identification parameters, to avoid cross-batch data confusion. Multi-source and heterogeneous document formats (such as tabular dye vat curves and text-based color difference reports) require plugins to support parsing files with different structures, adapting to table extraction and text semantic recognition. Frequent generation of single-vat or single-batch data requires knowledge base synchronization frequency for tool calls to match production rhythms, preventing use of expired formulas or chemical data. The core links of color judgment and formula scaling require tools to simultaneously call the formula library, colorimeter data, and process sheets for cross-review.

## How to configure the settings
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `functionCall` | Enable and bind to a preset workflow | Explicitly specifying the called workflow tool ensures parameter transfer aligns with dyeing and finishing batch review logic |
| Knowledge base single recall limit | Top 5 entries | The number of documents related to a single batch in this category is limited; excessive recall will interfere with the accuracy of cross-review |
| Tool call timeout threshold | 600 seconds | Operations such as dye vat curve parsing and formula comparison require long processing times, matching the typical duration of production links |
| File association parameter | Bind to the vat number field | Data in this category is archived by vat number, so uploaded files must be accurately bound to the corresponding production batch to avoid data confusion |
| `toolChoice` | Fixed target workflow ID | Avoid calling unrelated tools that cause process errors, ensuring consistency of the review workflow |

## Three common configuration mistakes
- Phenomenon: Workflows receive empty file parameters, or file link fields uploaded via the interface contain no valid content. Cause: Uploaded files are not bound to production identifiers such as vat number and batch number, causing tools to fail to match review data for the corresponding batch.
- Phenomenon: Knowledge base recall results include dyeing formulas and color difference reports from non-current production batches, leading to deviations in cross-review results. Cause: No vat number filtering condition is added to query parameters, causing the recall range to exceed current review requirements.
- Phenomenon: Tool calls return timeout errors, or workflows execute without response. Cause: No timeout threshold matching dyeing and finishing data processing rhythms is set, or the target workflow is not specified via `toolChoice`, causing mismatched tools to be called.

## How to verify correct configuration
- Upload a test dye vat curve file, and check whether the vat number is automatically extracted as an association parameter during tool calling.
- Initiate a review request that includes a vat number, and verify that documents recalled by the knowledge base only include content such as dyeing formulas and color difference reports for the corresponding batch.
- Check tool call logs to confirm that the preset technical document cross-review workflow is called under the `functionCall` mode.
- Simulate a processing scenario that exceeds typical duration, and verify that the tool call triggers a reasonable timeout prompt or retry mechanism.

The values provided are common starting points and should be measured against the reader's own samples.
