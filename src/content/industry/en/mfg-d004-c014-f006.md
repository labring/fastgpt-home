# Cross-Review of Technical Documentation for Dyeing and Finishing: Citation Sources and Traceability

This configuration is built for FastGPT v4.17.0, and is tailored to meet technical document cross-review requirements for dyeing and finishing scenarios.

## What the data for this category looks like
Core data for dyeing and finishing scenarios comes from dyeing, setting, laboratory, and quality departments of dyeing and finishing plants. Daily documents include dyeing formulas, chemical weighing records, dye vat curves, sample confirmation reports, color difference reports, setting process sheets, and wastewater ledgers.

Data sources include customer color samples, formula libraries, dyestuff batch ledgers, dye vat control equipment, colorimeters, setting machines, and environmental monitoring devices. Update frequency is per vat, per batch, and per shift.

Individual documents contain fields such as dyestuff batch number, temperature points for heating curves, color difference ΔE values, and setting temperature. Units include degrees Celsius, grams per liter, and color difference units. The total length of multiple documents linked to a single vat is typically in the thousands of characters.

## What constraints these characteristics impose on citation sources and traceability
Production data for this category is tightly bound to individual vats and batches, with extremely high update frequencies. The traceability link must accurately match unique identifiers such as vat numbers and batch numbers to avoid cross-batch mixed calls.

Most daily documents are numerical records of wet chemical processes. Citations must retain key fields like dyestuff batches and color measurement results; effective recall cannot rely solely on text keywords. Errors directly lead to full-vat rework, orders failing color requirements, or excessive environmental emissions.

Therefore, the traceability link must strictly limit the citation scope, only calling the latest data related to the current production task, and must not use expired or mismatched historical documents. Additionally, the length of documents per vat is manageable, so excessive splitting is unnecessary, and matching and verification can be performed directly on full documents.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | First 2000 tokens | Fits the full length of documents such as single-vat dyeing formulas and dye vat curves, to avoid truncating key process parameters |
| `responseData` | Return only matching entry metadata | Only display necessary traceability fields such as vat numbers, dyestuff batches, and detection times, filtering redundant full original document content |
| `detail` | Enabled | Display the original document fields for each citation, to facilitate verification of process parameters and traceability information |
| Citation source display limit | First 6 entries | Covers multiple types of documents involved in single-vat production, avoiding excessive entries that confuse query logic |
| Context window size | 1500–2000 characters | Fits the full content length of single-batch process sheets, calibrated based on actual testing |

## Three common mistakes
- Phenomenon: After the workflow calls the knowledge base search, redundant knowledge base search input and response field content appears in the answer. Cause: The original citation display switch was not turned off in the knowledge base node of the workflow, and the input and output logs from the search phase are retained by default.
- Phenomenon: When selecting variable references in the knowledge base search node, the reference variable dropdown menu is empty, and preset parameters such as vat numbers and knowledge base IDs cannot be selected. Cause: Corresponding dynamic variables were not configured in global variables in advance, or the variable scope does not cover the current workflow node.
- Phenomenon: The cited traceability data does not match the current production vat number, and documents from historical batches are recalled. Cause: Dynamic parameters such as vat numbers and batch numbers were not bound in the search conditions, resulting in recall scope covering all historical data.

## How to confirm the configuration is complete
- Initiate a test query, enter a process question about a specific vat number, check that the answer only displays key fields of traceability documents, with no redundant search input and output content.
- View the citation source list below the answer, confirm that each citation includes unique fields such as vat numbers, dyestuff batches, and detection times, matching the production batch of the current query.
- Adjust the `quoteMaxToken` parameter value, verify that the cited document content in the answer is not truncated for key process parameters such as heating curve nodes or color difference ΔE values.
- Test the scenario of dynamically specifying the knowledge base, confirm that the reference variable dropdown menu can normally load preset global variable options, with no blank error messages.

The values provided here are common starting points, and should be measured against the reader's own samples.
