# Cross-Review of Technical Documentation for Dyeing and Finishing: Deployment and Upgrade

## What the data for this category looks like
Technical documentation for dyeing and finishing includes dyeing formulas, chemical dosing records, dye vat curves, sample confirmation reports, color difference reports, setting process sheets, and wastewater ledgers.
Data sources cover customer color samples, formula libraries, dye chemical batches, dye vat control systems, colorimeters, setting machines, and environmental monitoring equipment.
Update frequency follows per vat, per batch, or per shift cycles.
Single-vat data includes structured fields such as temperature curves, concentration parameters, and color difference values.
Units include degrees Celsius, grams per liter, milligrams per liter, and other industrial standard units.
Some unstructured documents are binary log files from dye vat operations.

## What constraints these characteristics impose on deployment and upgrade
The high-frequency updates and multi-source heterogeneous nature of this category’s data creates multiple constraints for deployment and upgrade workflows.
Multi-source device access requires storage configurations adapted to industrial intranet access, to avoid public network latency.
Batch vat-level data uploads require database connection count configurations matched to concurrent write requirements.
Coexistence of unstructured dye vat curves and structured formula data requires storage and parsing configurations to balance read and write performance across different formats.
The tightly linked data characteristic requires ensuring consistency between the formula library and dye vat data during upgrades, to avoid process deviations caused by synchronization interruptions.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `STORAGE_S3_ENDPOINT` | `http://192.168.xx.xx:9000` (intranet object storage address) | Category data includes large-volume dye vat curves and wastewater ledgers. Intranet access reduces transmission latency. |
| `REDIS_URL` | `redis://:custom password@intranet Redis address:6379/0`, memory quota no less than `2 GB` | High-frequency updated formula and color difference data require caching. This avoids repeated reads from industrial device interfaces. |
| `DB_MAX_LINK` | `200` | Batch uploads occur immediately after each vat data is generated. High-concurrency connections prevent write blocking. |
| `MONGODB_URI` | Replica set connection string with read-write separation | This category’s data has both real-time write and batch query requirements. Read-write separation improves overall performance. |
| `FILE_TOKEN_KEY` | Randomly generated 32-character string | Document uploads require signature verification. This prevents unauthorized access to sensitive process data. |

## Three common errors
- Phenomenon: Deleting a folder containing many dye vat curve files in the knowledge base triggers a `timeout of 60000ms exceeded` error.
  Cause: The `DB_MAX_LINK` configuration is not adjusted. Batch deletion exhausts database connections, leading to the timeout.
- Phenomenon: Local deployment packaging fails with an error about missing document parsing dependencies.
  Cause: Additional parsing plugins for dyeing industry documents are not installed. Default dependencies do not support the binary format of dye vat curves.
- Phenomenon: Formula library synchronization fails after an upgrade.
  Cause: The `STORAGE_S3_ENDPOINT` configuration is not updated. The new storage address is not authorized for the old service, so process data cannot be read normally.

## How to confirm configurations are set correctly
- Upload 10 dye vat curve files in a batch. Check the upload success rate. Adjust `DB_MAX_LINK` to a threshold that meets concurrent requirements.
- Access the address bound to `FE_DOMAIN`. Verify that the front-end page loads preview components for dyeing formulas and color difference reports normally.
- Use `ROOT_KEY` to call the interface and query the latest wastewater ledger data. Confirm that returned fields match the category document structure.
- Restart the FastGPT v4.17.0 service. Check logs for connection failure errors related to `REDIS_URL` or `STORAGE_S3_ENDPOINT`. None should appear.
