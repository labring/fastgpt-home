# Cross-Review of Technical Documentation for Active Pharmaceutical Ingredient and Pharmaceutical Intermediate Manufacturing: HTTP Interfaces and External Systems

## What data looks like for this category
Daily documents include batch production records, material balance records, reaction purification records, cleaning records, impurity profile reports, deviation and change documents. Data comes from registered process documents, raw material batch ledgers, DCS systems, weighing systems, LIMS, chromatography data systems, QMS. Data updates per production batch and process step. Fields include reaction temperature, feeding amount, impurity content, batch number, operation time, operator. Units include degrees Celsius, kilograms, milligrams per liter, and others.

## Constraints Imposed on HTTP Interfaces and External Systems
Daily documents have complex structures, including structured process parameters and unstructured report content. HTTP interfaces must support multi-format data interaction. Multi-source data synchronization requires handling response delays from different industrial systems. Request timeout and retry policies must be configured. Data volume updated per batch has peak loads. Interface concurrent processing capacity must match production rhythms. Data involves process and compliance information. Interface authentication and data encryption must meet production quality management requirements.

The following configurations are based on FastGPT v4.17.0.

## How to Set Configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Authentication Configuration | Configure the `Authorization` header as a Bearer token. Set token validity based on actual measurements | Adapts to authentication rules for industrial systems such as LIMS and chromatography data systems |
| Request Timeout | 600 seconds | Matches the response delay range of industrial equipment such as DCS and weighing systems |
| Single Request Data Volume | 800–1200 characters | Adapts to the length of single structured fields in batch production records |
| Variable Mapping Rule | Map batch numbers and impurity content to the `variables` parameter | Enables associated calls of cross-system data |
| Response Data Validation | Validate whether `responseData` contains batch number and impurity content fields | Ensures returned data meets business compliance requirements |

## Three Common Mistakes
- Symptom: A 400 Bad Request error is returned when performing cross-system multi-row data synchronization. Cause: Requests are not split by production batch. A single submission of multi-row cross-system query statements exceeds the interface's single data volume limit.
- Symptom: Returned process review results do not include document citation sources, and no corresponding fields exist in `responseData`. Cause: Extraction logic for citation source fields is not configured. Batch numbers, impurity profile reports, and other items are not mapped to the `variables` parameter.
- Symptom: Document content cannot be obtained after connecting to the Confluence knowledge base. Cause: Authentication information for the `Authorization` header is not correctly configured. The interface path rules for Confluence are not adapted.

## How to Confirm the Configuration Is Correct
- A synchronization request for a single batch production record is sent. The interface returns a 200 OK status code.
- An impurity content query request is sent. The `responseData` field contains preset business fields.
- A cross-system data associated call is sent. The batch number mapped in the `variables` parameter matches the source system ledger.
- Synchronization requests for five consecutive production batches are sent. No consecutive errors occur.

The values provided are common starting points and should be measured against the reader's own samples.
