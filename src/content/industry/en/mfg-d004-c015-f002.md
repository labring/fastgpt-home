# Cross-Review of Technical Documentation for Active Pharmaceutical Ingredient and Pharmaceutical Intermediate Production: Vector Models and Indexing

## What the Data for This Category Looks Like
This category’s data originates from synthesis, fermentation, purification, quality control, and regulatory support departments of active pharmaceutical ingredient enterprises. Daily documents include batch production records, material balance records, reaction and purification records, cleaning records, impurity profile reports, deviation documents, and change documents. Data sources cover registered process documents, raw material batch ledgers, DCS systems, weighing systems, LIMS, chromatography data systems, and QMS. Updates occur once per production batch and per process step. Documents include fields such as process parameters, impurity data, and batch information. Some content requires matching professional details like chemical molecular formulas and residual solvent units.

## Constraints Imposed on Vector Models and Indexing
The high-frequency, multi-source heterogeneous document characteristics of this category create multiple constraints for the vector indexing workflow. Updates for every batch and process step require indexing to support incremental synchronization. Full reconstruction would take excessive time and harm business efficiency, so this must be avoided. Multi-source data includes numeric process parameters, specialized chemical text, and compliance records. A unified vector mapping logic is required to retain field associations. This prevents loss of critical information such as batch numbers and impurity data. Professional terminology, including impurity profiles and reaction routes, makes up a large share of content. The vector model must be adapted to medical chemistry domain semantics to ensure accurate vectorization of specialized content. Cross-departmental document association needs mean indexing recall must match associated fields like batch numbers and process steps. This avoids compliance risks caused by recalling unrelated batch data.

## Configuration Recommendations
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the single-block text length of batch production records and impurity profile reports, avoids splitting professional terms across chunks |
| Overlap Length | 50–100 characters | Retains contextual continuity for process steps and impurity associations, prevents semantic breaks after splitting |
| `maxToken` | 8192 | Adapts to the input limit of mainstream medical domain embedding models, meets vectorization needs for long document files |
| Similarity Threshold | Calibrated via actual testing | Must match the semantic similarity judgment standards for impurities and process parameters, avoids incorrectly recalling low-relevance data |
| Single Search Limit | Top 10 results | Covers the number of associated documents for multi-step reactions, meets review needs for associating multiple batch documents during process changes |
| `defaultToken` | 1024 | Sets the default token length for general vectorization, adapts to the text length of most daily documents |

## Three Common Misconfigurations
- After configuring an embedding model with the same name, the old configuration is overwritten, and only the latest configuration item appears in the interface. The cause is that the platform uses the model name as the unique identifier by default, and the multi-instance configuration function is not enabled.
- After indexing, search results only return a small number of short texts, and cannot match complete process route documents. The cause is that the chunk length is set too short, which splits the associated semantic content of long documents. This prevents complete reaction step information from being recalled during retrieval.
- Search results include impurity profile reports from non-target batches. The cause is that batch fields are not configured as index association conditions, and recall is based solely on full-text similarity.

## How to Confirm Proper Configuration
- The model configuration page is accessed, and the added embedding model name and configuration parameters such as `defaultToken` and `maxToken` are confirmed to match the preset values, with no overwrites.
- A single impurity profile report is uploaded, an indexing test is run, and the chunked text fragments are checked for retention of complete chemical terms and batch information.
- Search terms related to process changes are entered, and the search results are confirmed to include batch production records and change documents for the corresponding batch, with the number of results matching the single search limit setting.
- The incremental indexing function is tested, a new batch production record is uploaded, and the indexing task is confirmed to complete normally, with the new data retrievable.

The values provided are common starting points and should be measured against the reader’s own samples.
