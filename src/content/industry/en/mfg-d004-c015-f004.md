# Cross-Review of Technical Documents for Active Pharmaceutical Ingredient and Pharmaceutical Intermediate Production: Workflow Orchestration

## What the data for this category looks like
Technical document data sources for active pharmaceutical ingredient and pharmaceutical intermediate production cover registered process documents, raw material batch ledgers, DCS production control systems, weighing systems, LIMS laboratory information management systems, chromatography data systems, and QMS quality management systems.
Daily documents include batch production records, material balance reports, reaction and purification step records, cleaning validation records, impurity profile reports, and deviation and change control documents.
Data updates trigger per production batch or per process step. Fields include batch identifiers, process parameter values, test results, compliance status, and similar items. No uniformly formatted bulk aggregated documents exist.

## What constraints these characteristics impose on workflow orchestration
Multi-source heterogeneous data sources require workflows to support cross-system data pulling and format adaptation. This prevents data format conflicts between different systems.
High-frequency batch-level updates require workflows to use dynamic parameter binding to adapt to each batch’s personalized needs. There is no need to repeatedly create independent workflows.
Compliance-related document verification requires mandatory associated checks between steps. This ensures parameter matching between reaction records and impurity profile reports. It also requires handling chain effects of change documents on subsequent process steps. Workflows must include branch judgment and associated verification nodes.
Batch data uniqueness requirements mean workflows must avoid cross-mixing of data during concurrent execution. Node call unique identifier rules must be configured.

## How to configure
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Bind batch numbers, reaction temperature ranges, impurity content thresholds | Adapt to dynamic process parameters for each batch, avoid workflow redundancy caused by hard-coded configurations |
| `nodeId` | Assign unique identifiers to data pulling, verification, and output nodes | Ensure correct workflow node call order, avoid node conflicts during multi-batch concurrency |
| Tool selection trigger rules | Trigger corresponding processing nodes based on data source type | Differentiate processing logic for DCS real-time production data and LIMS offline test reports |
| Timeout setting | 600 seconds | Cover pulling and processing duration of batch test data from chromatography data systems |
| Concurrency control | Limit concurrency count of a single workflow instance to 1 | Avoid verification errors caused by cross-association of multi-batch data |
| Branch judgment threshold | Calibrate based on actual measurements | Verification rules differ for different impurity profile reports, must adapt to actual business scenarios |

## Three common configuration mistakes
- Phenomenon: Tool selection nodes run concurrently, generating duplicate verification results. Cause: Unique `nodeId` is not assigned to nodes, leading to conflicting node calls across multiple batch workflows.
- Phenomenon: Workflows cannot correctly associate cross-system data, resulting in batch number mismatch errors. Cause: Batch numbers are not bound as association keys via `variables`, leading to mixing of raw material batches and DCS data from different batches.
- Phenomenon: Workflow execution times out and triggers errors. Cause: No reasonable timeout duration is set, and pulling batch test data from chromatography data systems exceeds the preset time limit.

## How to verify correct configuration
- Simulate a single batch production flow to trigger the workflow. Check that the call order of `nodeId` matches configured settings, with no skipped or duplicate node execution.
- Pass multiple sets of test data from different batches. Verify that batch parameters bound via `variables` are correctly called, with no cross-mixing of data.
- Simulate a timeout scenario. Verify that the workflow completes execution within 600 seconds or triggers the preset failure handling process.
- Configure tool selection branch rules. Verify that only nodes matching the corresponding data source type are called, with no concurrent execution.

The values given are common starting points and should be measured against the reader's own samples.
