# Cross-Review of Technical Documentation for Transformer and High-Voltage Electrical Equipment Manufacturing: HTTP Interfaces and External Systems

## What the Data for This Category Looks Like
Technical documents for transformer and high-voltage electrical equipment manufacturing include winding and core assembly records, vacuum drying records, insulating oil reports, partial discharge and withstand voltage test reports, and nameplate parameter tables. Data sources cover design BOM, silicon steel sheet and insulating material inventory data, vacuum and drying equipment operation data, oil test results, and test station test data.
Data is updated per product and raw material batch, and requires association with unique serial numbers for single-unit traceability. Core fields include insulation gap parameters, microcoulomb-level partial discharge values, drying temperature in degrees Celsius, and other fields, using industry-standard professional units.

## Constraints on HTTP Interfaces and External Systems
Document types for this category include structured reports and unstructured test photos, and must be bound to the unique serial number of a single product. This requires interfaces to support precise querying by serial number.
Data update frequency changes dynamically with product batches, so interfaces must adapt to batch request scenarios. Core data originates from multiple types of industrial equipment and management systems, so interfaces must be compatible with varying authentication mechanisms and data formats.
Transmission of unstructured data such as insulating oil reports and withstand voltage test photos requires interfaces to support multiple file upload types and format verification. The single-unit traceability requirement also mandates that returned data must be bound to a unique serial number to prevent cross-product data mixing.

## Configuration Guidelines
The following configurations are designed for the interface module of FastGPT v4.17.0:
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `Authorization` | Bearer {Internal Enterprise Unified Authentication Token} | Matches internal system authentication specifications for power transmission and distribution equipment manufacturers |
| `variables` | Pass `{"serialNumber":"","materialBatch":""}` | Adapts to query requirements for single products and batch materials |
| `responseData` | Only return the `reportType,serialNumber,testResult` fields | Reduces invalid data transmission and focuses on core information for technical document review |
| Timeout Period | 600 seconds | Covers the typical time range for high-voltage test report generation |
| Maximum Number of Documents per Request | Top 3 | Matches the upper limit of document quantity corresponding to each batch of raw materials |
| Retry Strategy | Calibrated based on actual measurements | Adapts to the unstable response characteristics of industrial equipment interfaces |

## Three Common Configuration Errors
- A `400 Bad Request` error occurs with the prompt "unsupported media type". This occurs because the allowed format range for insulating oil reports and withstand voltage test photos is not specified in the interface configuration, causing multimodal invocation failures.
- An empty `responseData` field is returned after interface invocation. This occurs because the field names of the transformer nameplate parameter table are not mapped correctly, making it impossible to extract valid review data from external systems.
- A retry is not executed after a global timeout is triggered during interface invocation. This occurs because the timeout threshold adapted to the response duration of test equipment is not set, and the request process is terminated directly.

## How to Verify Correct Configuration
- Invoke the test interface, pass the valid serial number of a single transformer, and check if the returned `responseData` contains the expected report type and serial number fields.
- View the system authentication log to confirm that the `Authorization` header is correctly carried and passes internal enterprise system verification.
- Simulate a batch document request and check if the number of documents returned by the interface matches the configured maximum number of documents per request.
- Trigger a simulated timeout scenario and confirm that the system executes retry operations according to the configured retry strategy.

The values provided are common starting points and should be measured against the reader's own samples.
