# Cross-Review of Technical Documentation for Transformer and High-Voltage Electrical Manufacturing: Tool Calling and Plugins

## What the data for this category looks like
Data for this category primarily comes from design BOMs of power transmission and distribution equipment enterprises, purchase ledgers for silicon steel sheets and insulating materials, vacuum drying equipment logs, insulating oil test reports, and partial discharge and withstand voltage test records from high-voltage test stations.
Daily generated documents include winding and core assembly records for single products, vacuum drying parameter records, insulating oil physical and chemical indicator reports, partial discharge and withstand voltage test reports, and product nameplate parameter tables.
Data is updated per product or batch of raw materials. Document fields include parameters with clear units such as insulation moisture content, partial discharge peak value, and test voltage value. Corresponding batch materials and equipment operation data must be associated.

## What constraints these characteristics impose on tool calling and plugins
The requirement for full-link traceability of single products requires tool calling to bind a unique product identifier to avoid cross-batch data confusion.
Multi-source and heterogeneous document formats, including scanned documents, structured tables, and test reports, require plugins to support multi-format reading and structured field extraction.
High-precision insulation and test parameter requirements limit the extraction accuracy of tool calls to prevent numerical or unit errors.
The data update characteristic of per-product or per-batch updates requires the plugin's context association logic to match the data update rhythm to avoid calling expired data.
External system docking requirements additionally require the API configuration for tool calling to support cross-domain permissions and response format adaptation.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | Force `functionCall` | Ensure tool calls only execute preset cross-review tasks for documentation, avoid unrelated calls |
| Document reading format adaptation | Switch based on document type: Enable field extraction mode for structured tables, enable OCR mode for scanned documents | Cover the multi-source and heterogeneous document types of this category |
| Maximum documents per single call | 3 | Match the number of core documents associated with a single transformer, avoid processing timeouts |
| Field extraction accuracy | Calibrate based on actual measurements | Meet the extraction requirements for high-precision parameters such as insulation moisture content and partial discharge values |
| API response timeout | 120 seconds | Match the reading and data processing duration for large high-voltage test reports |
| External call whitelist | Only bind enterprise internal system IP ranges | Ensure access security for test data and design BOMs |

## Three Common Mistakes
- Phenomenon: A 403 status code is returned when importing an insulating oil report via the HTTP plugin. Cause: The external system IP whitelist is not configured, resulting in API call permission being blocked.
- Phenomenon: Fields returned by tool calls have missing units or numerical deviations. Cause: The reading mode is not adapted based on document type, and structured tables do not enable accurate field extraction, leading to parameter parsing errors.
- Phenomenon: No response is returned after the workflow initiates an API call. Cause: The number of documents per single call exceeds the configured limit, resulting in processing timeout with no returned results.

## How to Confirm the Configuration is Complete
- Upload 3 core documents for a single transformer, trigger tool calling, and check whether the returned results include preset parameter fields such as insulation moisture content and test voltage value.
- After configuring the API call address and access key, initiate a call via an external test tool, confirm that the cross-review results processed by the tool can be obtained normally.
- Adjust the maximum documents per single call to 5, test the reading process for large high-voltage test reports, confirm that no timeout errors occur.
- Check that the currently used FastGPT version is v4.17.0, confirm that the `toolChoice` parameter is set to forced `functionCall` mode.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
