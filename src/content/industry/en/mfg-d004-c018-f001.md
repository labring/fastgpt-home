# Cross-Review of Technical Documentation for Continuous Basic Chemical Production: HTTP Interfaces and External Systems

This document applies to FastGPT v4.17.0.

## What Data for This Category Looks Like
Data for this category comes from DCS/SIS systems, online analyzers, LIMS systems, equipment condition monitoring modules, energy metering devices, and raw material storage tanks. Daily documentation includes operating procedures, process index cards, DCS trend charts, laboratory reports, interlock bypass records, special work permits, and shift logs.
Data update cycles fall into three categories: real-time, per-shift, and daily. Document fields include process parameter values, interlock logic numbers, laboratory result units, work permit validity periods, and more. Units cover standard chemical industry units such as pressure, temperature, flow rate, and concentration.

## Constraints Imposed on HTTP Interfaces and External Systems
Mixed, multi-source heterogeneous data types and update cycles require HTTP interfaces to support mixed requests for structured parameters and unstructured text.
Real-time collected DCS data, paired with shift logs and laboratory reports updated per shift, require interface timeout settings to match data collection cycles. Delays will cause cross-review failures.
Documents with strong associations, such as interlock bypass records and special work permits, require interface-passed parameters to carry unique identifiers. This ensures precise matching of corresponding process links during cross-review.
Bulk energy metering and raw material storage tank data require interfaces to support segmented data pulling. This prevents system stability issues caused by overload from single requests.

## How to Set Configurations
| Configuration Item | Recommended Setting | Basis for This Setting |
| --- | --- | --- |
| API Authentication Configuration | Use Bearer token authentication, token validity period 7200 seconds | Matches the `Authorization` header authentication requirements of basic chemical external systems, avoids frequent token refreshes that reduce review efficiency |
| Request Variable Settings | Pass process unit number, laboratory batch number, storage tank ID | Pass necessary identification fields via `variables` to ensure external systems can locate corresponding process documents and data |
| Response Data Filtering | Only return process parameter, interlock status, and work permit status fields | Only retain core data within the `responseData` rule, reduces invalid transmission and improves processing efficiency |
| Scheduled Pull Interval | 300 seconds | Matches per-shift data update cycles, balances real-time performance and interface load |
| Request Timeout Threshold | 60 seconds | Adapts to collection delays of real-time DCS data, prevents review interruptions caused by request timeouts |
| Trigger Rule Configuration | Trigger on interlock bypass record changes | Matches real-time review requirements for special work and interlock changes, optimizes data pull timing |

## Three Common Mistakes
- Symptom: External interface calls return a 403 Forbidden status code, or an authentication failure prompt. Cause: The `Authorization` parameter is not configured correctly, an expired token is used, or the authentication format does not match the external system's requirements.
- Symptom: Custom plugin calls to external interfaces return empty results, or core fields are missing. Cause: Necessary identification fields are not passed in `variables`, causing external systems to fail to locate corresponding documents and data.
- Symptom: Scheduled pull tasks trigger too frequently or time out and interrupt. Cause: A reasonable pull interval is not set based on data update cycles, or the timeout threshold does not match real-time data collection delays.

## How to Confirm Configuration Is Complete
- Call the test interface, check if the returned `responseData` only includes preset core fields with no redundant data.
- Simulate a process unit change or work permit submission to trigger an interface call. Verify that the corresponding document data returned by the external system matches the locally stored data.
- Check the interface call logs to confirm the `Authorization` parameter format is correct, with no expired or invalid tokens.
- Adjust the trigger rule or pull interval, verify that the interface call frequency matches the data update cycle, with no abnormal load.

The values provided here are common starting points. They should be evaluated against the reader's own samples.
