# Cross-Review of Technical Documentation for Furniture and Wood Product Manufacturing: Tool Calling and Plugins

## What the data for this category looks like
Core data for furniture and wood product manufacturing comes from order design systems, sheet material and wood batch records, CNC cutting and drilling equipment, ERP/MES systems, and moisture content testing equipment. Daily documentation includes order disassembly drawings, cutting lists, edge banding and drilling programs, coating process documents, hardware accessory lists, and assembly and packaging records. Data updates follow this cadence: order disassembly and cutting data is generated per order, coating process and inventory information is updated daily, and sheet material moisture content and batch information is updated when each batch of materials arrives. Document fields include panel size, hardware model, sheet batch number, moisture content value, and other fields. Some fields are adjusted based on custom order requirements.

## What constraints these characteristics impose on the tool calling and plugins workflow
Custom-order-driven production leads to a high number of panels per order and a high degree of personalization. Tool calling must adapt to dynamically changing document structures and fields. High-frequency data updates require tool calling to pull the latest sheet batch, cutting list, and equipment program data in real time. This avoids using expired information. Cross-review of panel size, hole positions, and hardware matching requires data from multiple sources. Tool calling must support retrieving information from multiple data sources at the same time. Complex production processes and strict error consequences require tool calling to include failure retry and exception alert mechanisms. This ensures the accuracy of review results.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale for This Setting |
|---|---|---|
| Workflow/API tool selection | `auto` | Adapts to diverse queries from custom orders, automatically selects whether to call tools or respond directly |
| Workflow/API function-call configuration | `enabled` | Supports calling external tools to obtain real-time production data such as cutting lists and sheet moisture content |
| Maximum number of single tool calls | First 3 attempts | Controls tool call frequency to avoid excessive system resource usage |
| Tool call timeout period | 15-25 seconds | Adapts to network latency fluctuations from CNC equipment and ERP systems, calibrated based on actual measurements |
| Context retention length | 800-1200 characters | Retains key information from order disassembly drawings and cutting lists, prevents overly long contexts from impairing logic |
| Tool call result cache duration | 30 minutes | Adapts to daily updated coating process and inventory data, reduces repeated calls |

## Three Common Misconfigurations
- The workflow runs repeated HTTP calls without a termination condition, returning duplicate cutting list data. This occurs when no termination rule for loop triggers is configured, and no order completion status verification field is bound.
- The tool call function does not return matching document results from the knowledge base, only returning generic responses. This occurs when the linked configuration between tool calling and knowledge base retrieval is not enabled, and no associated production document source is specified.
- The AntV Chart MCP plugin returns XML or JSON code blocks but does not render charts. This occurs when the result rendering switch is not enabled in the tool call configuration, or required fields such as panel size and batch data are not passed correctly.

## How to Confirm the Configuration Is Correct
- Initiate a query that includes "verify the panel size and cutting list for order XX", confirm the tool call returns the corresponding real-time cutting data.
- Trigger a test flow for repeated HTTP calls, input the order completion status identifier, confirm the loop terminates automatically.
- Call the AntV Chart MCP plugin, input test data such as panel size and hardware model, confirm the returned code block is correctly rendered as a visual chart.
- View the tool call logs in FastGPT v4.17.0, confirm the parameters for each call match the configured items.
