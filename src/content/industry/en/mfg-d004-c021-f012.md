# Cross-Review of Technical Documentation for Furniture and Wood Product Manufacturing: Deployment and Upgrade

## What the data for this category looks like
Technical documents for furniture and wood product manufacturing originate primarily from order design systems, sheet and wood batch ledgers, CNC cutting/drilling device logs, ERP/MES systems, and moisture content testing equipment. Daily documents include order disassembly drawings, cutting lists, edge banding and drilling programs, coating process documents, hardware bill of materials, and trial assembly and packaging records.
Data updates follow this rhythm: exclusive documents generated per order, production progress synced daily, and batch information updated per material batch.
Document fields include panel size (millimeters), sheet moisture content, hardware model, production batch number, and some documents include visual drawings and process parameters.

## Constraints imposed on deployment and upgrade
This category is driven primarily by customized orders. A single order corresponds to multiple panel documents. Data volume grows linearly with order count. High-performance storage and vector databases must be configured during deployment.
Frequently updated sheet batch and production data require real-time synchronization support after deployment. Cache and database connection parameters must be optimized.
Documents include visual drawings and text content, which have clear requirements for file storage compatibility and size limits.
Customized panel parameters and process requirements require the system to adapt to embedding and retrieval logic for multiple document types, to prevent retrieval results from mismatching actual production needs.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `PG_URL` | Intranet-accessible PostgreSQL connection address, formatted as `postgresql://user:pass@host:port/dbname` | Stores technical document metadata, review results, and user operation logs |
| `REDIS_URL` | Intranet Redis instance address, configure key expiration time to 600 seconds | Caches frequently queried document metadata and session information to reduce database load |
| `STORAGE_S3_ENDPOINT` | Intranet object storage endpoint, supports storing disassembly drawings and process files under 1000 MB | Stores all types of unstructured technical documents, supports multi-format file upload and reading |
| `FE_DOMAIN` | Intranet-accessible domain name or IP + port, for example `https://fastgpt.intranet:3000` | Adapts to access paths after Nginx reverse proxy, ensures normal communication between frontend and backend interfaces |
| `ROOT_KEY` | Custom high-strength random string with a minimum length of 32 characters | Protects highest-privilege access to the FastGPT management backend |

## Three common mistakes
- Symptom: After deployment, the model channel list only displays rearranged models, and other language models cannot be selected. Cause: `MONGODB_URI` is not configured correctly, so model metadata fails to sync to the system database.
- Symptom: File upload fails during intranet deployment, and the chat box shows a file storage exception alert. Cause: `FILE_TOKEN_KEY` or `STORAGE_S3_ENDPOINT` is not configured, leading to an invalid file upload path or missing read/write permissions.
- Symptom: FastGPT cannot connect to the local Ollama model after Docker deployment. Cause: The container is not configured with host network mode or mapped to the correct port, so the container cannot access the Ollama service running on the host machine.

## How to confirm configuration is complete
- Log in to the FastGPT v4.17.0 management backend, navigate to the system settings page, and check the database connection status. Confirm that the connection items corresponding to `PG_URL` and `REDIS_URL` show normal status.
- Upload a disassembly drawing or cutting list file. Wait for the upload to finish, then search for the file in the document library. Confirm that the file has been stored successfully and can be previewed normally.
- Navigate to the model channel configuration page, add an Ollama model channel, enter the local service address and port, and click the connection test. Confirm that a connection success prompt is returned.
- Check the Nginx reverse proxy logs. Verify that the access path corresponding to `FE_DOMAIN` returns a 200 status code, with no 404 or 502 errors.
