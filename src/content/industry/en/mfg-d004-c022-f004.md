# Cross-Review of Technical Documentation for Complete Household Appliance Manufacturing: Workflow Orchestration

## What Data for This Category Looks Like
Data for this category covers configuration BOMs, assembly work instructions, refrigerant charging records, electrical safety test reports, performance spot check reports, and rework records for complete units including air conditioners, refrigerators, washing machines, and small household appliances. Data sources include ERP/MES systems, parts batch ledgers, tightening and charging equipment, safety compliance testers, performance laboratory data, and after-sales fault records. Updates run per individual complete unit, per shift production batch, or per spot check plan. Most documents include associated fields for process parameters, test results, and parts batches.

## What Constraints These Characteristics Impose on Workflow Orchestration
Multi-source, heterogeneous data sources for this category require workflows to support connecting to data sources in different formats such as ERP/MES, device logs, and after-sales systems. Frequently updated data at the individual unit or batch level requires workflow trigger logic to bind to production nodes, to avoid data lag. The mixed-line assembly production mode requires workflows to filter corresponding documents by complete unit model and parts batch. Cross-check requirements for safety compliance, performance, and after-sales data require workflows to integrate field association rules across multiple document types, to avoid safety risks from incorrect assembly or process deviations. High-volume production also requires workflows to efficiently handle batch validation tasks for multiple complete units in a single batch.

## How to Set the Configuration
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Pass complete unit model, parts batch number, production shift ID | Match exclusive documents such as BOMs and assembly work instructions for the corresponding model, to avoid mixed-line misalignment |
| `nodeId` | Bind production station trigger node ID | Trigger the workflow according to production beat, to adapt to real-time update requirements for individual unit or batch level data |
| Single search limit | Top 8 entries | Cover multiple test reports, process records, and associated after-sales data for the same model |
| HTTP request timeout | 600 seconds | Adapt to the long data return cycle of equipment such as safety compliance tests and performance tests |
| Cycle nesting configuration | Execute per batch | Adapt to batch validation requirements for multiple production batches per shift |
| Knowledge base variable reference | Calibrate based on actual measurements | Adapt to cross-check logic for documents with multiple associated fields |

## Three Common Mistakes
- Phenomenon: Calling the workflow API returns a null value, or the knowledge base variable reference triggers a `quote type error` error. Cause: Variable transfer rules for nested knowledge bases are not correctly configured in FastGPT v4.17.0 or later, or input variables do not match the associated field format of documents.
- Phenomenon: The tool call module outputs both an AI reply and triggers execution of the next level branch. Cause: Trigger conditions for the branch are not correctly set, and the tool call output is bound to multi-path execution logic at the same time.
- Phenomenon: The HTTP request timeout cannot be adjusted to a duration that meets production requirements, or HTTP request nodes cannot be embedded in cycle nesting. Cause: The timeout parameter is not modified in the workflow's HTTP configuration panel, and it is not confirmed that the cycle module supports nested calls to external requests.

## How to Confirm the Configuration Is Correct
- Manually trigger the workflow, pass the specified complete unit model and batch number, and check whether returned associated documents only contain exclusive content for the corresponding model.
- View the workflow execution logs, confirm that the HTTP request timeout has been modified to a duration that meets production requirements, and that the cycle node triggers execution per batch.
- Simulate a variable reference operation, enter a test field, confirm that no `quote type error` error is triggered, and that the variable can correctly associate with the corresponding document.
- Test the tool call module, confirm that only the tool execution result is output or only the next level branch is triggered, with no parallel execution.

The values listed above are common starting points, and should be evaluated against the reader's own samples.
