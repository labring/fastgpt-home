# Cross-Review of Technical Documentation for Complete Home Appliance Manufacturing: Tool Calling and Plugins

## What the Data for This Category Looks Like
The daily documentation for this category includes configuration BOMs, assembly work instructions, refrigerant charging records, electrical safety test reports, performance spot check reports, and rework records. Data sources cover ERP/MES systems, component batch ledgers, tightening and charging equipment logs, safety compliance tester data, performance laboratory test results, and after-sales fault archives. Data updates follow per single product, per shift production batch, or spot check schedules. Each individual data entry includes fields such as component model, process parameters, test results, batch number, and other relevant fields.

## What Constraints These Characteristics Impose on the Tool Calling and Plugins Workflow
The mixed-line assembly of multiple product models in this category requires tool calling to precisely match the exclusive BOM and process parameters of each single product, to avoid mixing data across batches. Frequently updated equipment logs, spot check reports, and rework records require tool calling to support real-time pulling of the latest data sources, to avoid using outdated documentation. Data from multiple sources requires plugins to uniformly connect to ERP/MES, testing equipment, and after-sales archives, and to verify field consistency to ensure the accuracy of cross-review. Additionally, the need to cross-reference compliance, performance, and rework data across documents requires tool calling to specify an exclusive tool set via `toolChoice`, supporting parallel retrieval across multiple documents and field matching.

## Three Common Misconfigurations
- Phenomenon: Tool call return results include component data not from the current batch, with mismatched batch numbers or process parameters. Cause: The plugin rule triggered by product batch ID is not configured, leading to mixing of cross-batch data and creating a risk of mixed-line assembly errors.
- Phenomenon: No termination marker exists after the tool call node in the process orchestration, causing subsequent tool calls to be triggered continuously and leading to timeout. Cause: No tool call termination node is added at the end of the process, so the system calls tools in a loop according to the orchestration logic, exceeding the preset time threshold.
- Phenomenon: Custom cards cannot be displayed on the interface, and no content is returned after calling the plugin. Cause: The plugin is not configured with correct data source interface permissions, or is not bound to the tool call node, resulting in failure of normal data transmission.

## Verification of Successful Configuration
- The BOM and assembly work instructions for a single home appliance are uploaded, tool calling is triggered, and returned results are confirmed to only include documentation data from the current batch.
- Process orchestration nodes are reviewed, and a termination marker is confirmed to be added after the tool call node, with no risk of cyclic calls.
- The custom card plugin is enabled, tool calling is triggered, and the preset documentation review card is confirmed to be displayed on the interface.
- Timeout scenarios are tested, and tool calls are confirmed to complete and return within 300–600 seconds, with no prolonged suspension.

The values listed here are common starting points, and should be evaluated against local operational samples.
