# Cross-Review of Technical Documentation for Complete Home Appliance Manufacturing: Deployment and Upgrade

## What the Data for This Category Looks Like
This category covers complete unit manufacturing scenarios for air conditioners, refrigerators, washing machines, and small home appliances. Daily documents include bill of materials (BOM), assembly work instructions, refrigerant charging records, electrical safety test reports, performance sampling inspection reports, and repair records. Data sources include ERP/MES systems, component batch ledgers, tightening and charging equipment logs, safety compliance tester data, performance laboratory test results, and after-sales fault archives. Data updates follow per-unit product output, shift-level production volume, or sampling inspection schedules. Document structures include fields such as model identifiers, process parameters, test results, and batch numbers. Units include voltage, pressure, power, time, and other standard units used for industrial and consumer products.

## What Constraints These Characteristics Impose on Deployment and Upgrade
The multi-source, heterogeneous nature of this category’s data requires deployment to adapt to device logs, system export documents, and after-sales archives in varying formats. It must support bulk import of BOMs and work instructions with different structures. The high-frequency update rhythm requires configuring an automatic synchronization mechanism during deployment to avoid delays caused by manual imports. The mixed-line assembly business scenario requires upgrades to allow quick adjustment of document matching rules for different product models, without rebuilding the entire workflow. The association between data and batches or individual products requires retaining complete traceability field mapping relationships during deployment, to ensure review results can be traced back to specific production links. For products targeting end consumers, cross-review must strictly align with safety compliance, energy efficiency, and appearance requirements. Deployment must reserve entry points for validation rules for these corresponding fields.

| File access token secret | Generated per enterprise security policies | Secure access permissions for uploaded documents |

## Three Common Configuration Mistakes
- Issue: After local deployment, calling the model test returns 404 no body. Cause: `REDIS_URL` or `MONGODB_URI` is not configured correctly, causing the cache and database connections required by the service to fail.
- Issue: When importing images, base64 conversion and submission for visual model analysis cannot be completed directly. Cause: No image transcoding workflow node is added, and no associated rules for file format conversion are configured.
- Issue: The [Text Processing] module cannot be found after deployment. Cause: FastGPT v4.17.0 is not installed, or the corresponding function switch is not enabled in the deployment configuration.

## How to Confirm Configuration Is Complete
- Log in to the FastGPT backend, enter the data source configuration page, and confirm that synchronization paths for corresponding data sources such as ERP, MES, tightening equipment logs, and safety compliance tester data have been added.
- Upload an air conditioner configuration BOM and refrigerant charging record, trigger a manual synchronization task, and wait 10–30 minutes to check the document index status.
- Enter preset cross-review rules, such as model matching and process parameter verification, call the test interface, and confirm that the returned results include content from the corresponding review dimensions.
- View the service running logs, confirm that the connection status of `MONGODB_URI`, `REDIS_URL`, and `STORAGE_S3_ENDPOINT` is normal, with no error messages.
