# Cross-Review of Technical Documentation for Industrial Instrument Manufacturing and Calibration: HTTP Interfaces and External Systems

## What Data Looks Like for This Product Category
Daily documentation for this product category includes assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version logs. Data sources include design documents, standard instruments and environmental monitoring data, calibration software, laboratory information systems, and customer range requirements. Each document is updated once per calibration for each instrument. Core fields include tested instrument ID, calibration date, standard instrument parameters, ambient temperature and humidity, multi-point measurement values, error calculation results, and metrology certificate number. Measurement values must follow the statutory units of the corresponding physical quantities.

## What Constraints These Characteristics Impose on HTTP Interfaces and External Systems
Data sources for this category are scattered and have inconsistent formats. Multiple external systems such as calibration software and laboratory information systems must be integrated. HTTP interfaces must support format adaptation for multiple data sources. A single calibration data set includes multi-point measurement values and error curves. Interfaces must support large field transmission. Update frequency is once per calibration for each instrument. Interfaces must support on-demand trigger calls. In addition, calibration data is directly linked to measurement deviations in customer production. Interfaces must strictly validate required fields to prevent invalid data from entering subsequent processes.

## How to Configure Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Bearer {{SECRET_KEY}}, store the secret key in environment variables | Follow industrial interface authentication specifications to avoid secret key leakage caused by hardcoding |
| `variables` | Configure tested instrument ID and calibration batch number as modifiable global variables | Adapt to the need for pulling exclusive calibration data for a single instrument |
| `responseData` | Validate that returned fields include ambient temperature and humidity, error curve URL, and metrology certificate number | Ensure returned data covers required business fields |
| Single call timeout | 300–600 seconds | Calibration data collection and error calculation require long processing times |
| Retry strategy | Retry 2 times after failure, set interval based on actual measurements | Address temporary response anomalies from calibration software |

## Three Common Configuration Errors
- An empty `responseData` field is returned after calling the interface. This occurs because the `responseData` validation rule is not configured, and non-business fields returned by the interface are filtered out, leading to loss of critical data.
- No corresponding execution node appears after importing the workflow template. This occurs because the external system authentication parameters configured in the template are not adapted to the exclusive variables of industrial instruments, and the variables are not correctly bound after import.
- Text embedding status is not obtained after calling the openAPI. This occurs because the associated ID of the embedding task is not configured in `variables`, making it impossible to track status updates.
- Connection to the SQL data source of calibration software fails. This occurs because the database connection timeout parameter is not configured, or access permissions for the corresponding port are not enabled.

## How to Confirm Configuration Is Complete
- Trigger an interface call, then check if the returned `responseData` includes preset business fields, and if the field format matches calibration records.
- After importing the workflow template, check if the `variables` configuration has bound parameters such as tested instrument ID and calibration batch number.
- Test the connection to the external system, confirm that authentication information is valid, and there are no connection timeout or permission error messages.
- Run the workflow, then check if the task log includes a complete transfer record of calibration data.
