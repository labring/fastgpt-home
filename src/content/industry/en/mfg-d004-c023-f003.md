# Cross-Review of Technical Documentation for Industrial Instrument Manufacturing and Calibration: Multi-Turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
This category’s data comes from design documents of instrument manufacturers, calibration standards and environmental monitoring data, calibration software outputs, laboratory information systems, and range requirements proposed by customers. Daily generated documents include assembly and commissioning sheets for single equipment, calibration procedures, original calibration records, error curves, metrology certificates, and software version records. Data is updated after each calibration for each individual device. Document fields include equipment ID, calibration date, standard instrument ID, measuring point parameters, error value, and traceability number. Units include metrology-specific units such as pascals, degrees Celsius, milliliters per minute, and others.

## What Constraints These Characteristics Impose on the Multi-Turn Dialogue and Prompt Engineering Link
Data for this category is updated independently for each calibration of a single device. Multi-turn dialogue must bind `chatId` to associate all calibration documents of a single device, to avoid mixing data across devices. Documents contain metrology-specific fields and units. Prompts must explicitly require output content to match the format of fields such as traceability number and error value. Otherwise, metrology audits cannot pass. Calibration records are core deliverables. Multi-turn dialogue must support gradual retrieval of original records, error curves, and certificate information. Each dialogue round only focuses on cross-checking a single type of document, to avoid audit errors caused by information overload. Data sources are scattered. The dialogue must gradually guide users to provide document fragments from corresponding sources, to ensure the traceability of cross-review.

## Configuration Setup
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique calibration identifier of a single device. One independent `chatId` corresponds to each device | Data for each calibration of a single device is independent. This avoids mixing documents across devices and ensures precise review scope |
| Maximum context length | 800–1200 characters | Single calibration documents for this category are mostly 500–1000 characters long. This prevents information loss from context overflow |
| `messages` | Concatenate historical dialogue and associated document fragments in calibration process order. Only retain valid content for the current round each time | Calibration processes have fixed pre-check links. Concatenating in order improves logical consistency of cross-review |
| `variables` | Preset three variables: equipment ID, calibration date, and standard instrument ID. Auto-fill during invocation | Reduces repetitive input operations. Ensures accuracy and consistency of core field information |
| Maximum single document recall limit | Top 3 entries | Associated documents for this category are limited in number. Too many matching results will interfere with reviewers’ judgments |

## Three Common Misconfigurations
- Symptom: When calling the dialogue API, the database does not save the current round of dialogue content after the client interrupts the SSE connection. Cause: Dialogue records are only written after the full request returns. Temporary save logic before interruption is not supported.
- Symptom: When retrieving dialogue history, all dialogue across the entire application is returned. Filtering by single device or user is not supported. Cause: No association between `chatId` and device/user is configured. No dimension-based filtering parameters are set up.
- Symptom: After submitting a calibration document review request, the prompt cannot accurately extract metrology-specific field information. Cause: Core fields such as equipment ID and calibration date are not preset in `variables`, leading to insufficient prompt matching accuracy.

## How to Verify Proper Configuration
- Launch a calibration document review dialogue for a single device. Check that the associated `chatId` matches the device’s unique identifier. Confirm that dialogue records only relate to the current device.
- Call the dialogue history interface, pass the `chatId` parameter. Confirm that only dialogue content for the current device is returned. No cross-device data mixing occurs.
- Submit a test request containing calibration fields. Check that preset variables such as equipment ID and calibration date are auto-filled.
- Interrupt the SSE connection. Check that the database has saved the current round of dialogue fragments. Confirm that the auto-save logic is working correctly.
