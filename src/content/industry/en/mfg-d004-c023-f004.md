# Cross-Review of Technical Documentation for Industrial Instrument Manufacturing and Calibration: Workflow Orchestration

## What the data for this category looks like
Data for industrial instrument manufacturing and calibration comes from design documents, standard instrument data, environmental monitoring data, data exported from calibration software, laboratory information system records, and customer range requirements. The update frequency is once per calibration for each tested unit. Daily documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version records. Fields include standard instrument traceability numbers, tested unit ranges, calibration environmental parameters, error calculation results, calibration dates, and more. Units include pascals, degrees Celsius, percentages, and others. Each document corresponds to the single calibration process for one device.

## What constraints these characteristics impose on the "workflow orchestration" link
Data for this category has scattered sources, a high update frequency, and strong document correlation. Workflow orchestration must adapt to field matching across multiple data sources, trigger per single calibration, and adapt to the calibration process for a single device. Cross-checking multiple documents requires associating field consistency across multiple document types such as calibration records and metrology certificates. Break down links including standard instrument and tested unit connection, multi-point collection, error calculation, review and traceability into independent nodes to reduce repeated manual review checks. Configure parameter transfer between nodes to ensure the verification logic of the traceability chain.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Number of Loop Cycles | 1-10 times | The number of collection points for a single calibration is limited; this avoids invalid cycles consuming resources |
| Trigger Condition | Triggered after a single calibration is completed | The data update frequency is once per calibration for each device, which adapts to the calibration process for a single device |
| Call Other Applications/Plugins | Enable logging | The execution process of external calls needs to be tracked |
| Number of Failed Retries | 2 times, with a 30-second interval between each retry | Temporary data reading or network exceptions may occur during calibration; retries can reduce failure rates |
| `variables` Configuration | Store standard instrument number, tested unit range, environmental temperature (℃) | Multiple data sources require unified variable storage to ensure cross-node field transfer |
| `nodeId` Configuration | Associate calibration record nodes with metrology certificate nodes | Traceability fields of the two types of documents need to be matched to ensure the accuracy of cross-checking |

## Three Common Mistakes
- Symptom: The workflow loop runs indefinitely, continuously consuming system resources. Cause: No maximum loop cycle count is configured, leading to repeated reading of calibration data.
- Symptom: No conversation logs are generated after calling other applications or plugins. Cause: The logging switch is not enabled, so the calling process is not tracked.
- Symptom: After an upgrade, the workflow cannot call the original text processing node, and an execution error occurs. Cause: The original text processing configuration is not retained, leading to a missing document preprocessing link.

## How to Confirm the Configuration Is Correct
- Manually trigger the single calibration workflow in FastGPT v4.17.0, check whether the `variables` of each node correctly store parameters such as the standard instrument number and tested unit range.
- Associate the calibration record and metrology certificate nodes, check whether the field matching results meet traceability requirements.
- Enable the logging switch, verify whether logs for calling external applications or plugins are generated.
- After configuring the maximum number of loop cycles, check whether the number of loop executions matches the set range.
- After simulating a calibration data update, check whether the workflow is automatically triggered.

The values provided are common starting points and should be measured against the reader's own samples.
