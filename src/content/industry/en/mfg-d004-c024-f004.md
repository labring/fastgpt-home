# Cross-Review of Technical Documents for Process Change and Engineering Change: Workflow Orchestration

## What the data for this category looks like
Data sources for this category include PLM, ERP, MES, supplier materials, validation test results, and customer-specific requirements. Commonly processed documents include ECN/ECR files, change assessment reports, drawings and BOM version records, process validation reports, production switching plans, inventory disposal documents, and customer approval documents. Data is updated irregularly with each change. Documents include core fields such as version identifiers, change-associated nodes, approval status, and execution nodes.

## What constraints these characteristics impose on the workflow orchestration link
The scattered, multi-source data feature requires workflow orchestration to adapt to document retrieval formats from different systems, to avoid field parsing errors. Diverse document types and lack of fixed update cycles mean workflows must be triggered based on change events, rather than fixed-period triggers. Documents contain fields such as version identifiers and approval status. Workflows must set corresponding verification nodes covering core links including identification of chain impacts from design, materials, and processes; confirmation of old and new version switching points; synchronization of on-site documents, to ensure compliance across the entire change process.

## How to set up the configuration
The following configurations are developed based on the workflow orchestration function of FastGPT v4.17.0.

| Configuration Item | Recommended Practice | Basis for This Approach |
|---|---|---|
| Variable Update | Triggered by change nodes, cumulative count of verification failures | Adapt to the demand for classification problem call count statistics, accurately record the verification status of each change node |
| Global Variables | Bound to PLM/BOM version numbers | Ensure uniform version identifiers are used across the entire process, avoiding mixing of old and new versions |
| nodeId | Assigned unique identifiers by document type | Distinguish exclusive verification logic for different documents such as ECNs and process validation reports |
| Timeout Settings | 300-900 seconds, calibrated based on actual testing | Adapt to time differences in multi-source data retrieval, avoiding abnormal process interruptions |
| Context Window | 8000-12000 characters, calibrated based on actual testing | Cover review requirements for ultra-long change documents, fully load content of ECNs and validation reports |
| Variable Storage | Bound to `variables` and the current change work order ID | Ensure variable data for each change is stored independently, avoiding global variable conflicts |

## Three common errors
-  Configured variable updates have no response, and fields show as empty on the interface. The cause is that `variables` was not bound to the trigger condition of the corresponding change node, and variable rules were only configured globally.
-  Generated change review text is too long to load. The cause is that the character limit for the context window was not set, and full PLM and MES data was loaded directly.
-  Set global variable values do not update automatically. The cause is that global variables were not bound to the change work order ID, and the same variable instance was reused across different change work orders.

## How to confirm the configuration is complete
-  Trigger a simulated change event, check whether the workflow retrieves the corresponding documents from PLM and ERP as expected.
-  View the call count statistics for `variables`, confirm that the count for each classification verification node updates normally.
-  Verify the binding object of global variables, confirm that it is associated with the current change work order ID.
-  Validate the review process for ultra-long change documents, confirm that nodes do not experience abnormal interruptions due to excessive content length.

The values provided are common starting points and should be measured against the reader's own samples.
