# Cross-Review of Technical Documentation for Non-Ferrous Metal Smelting and Electrolysis: Document Parsing and Chunking

## What the Data for This Category Looks Like
Daily documents for this category typically include material batching lists, smelting records, electrolyzer condition logs, laboratory test reports, anode and cathode quality records, and environmental protection ledgers. Data sources include concentrate and auxiliary material analysis reports, DCS system data, cell voltage and current monitoring data, laboratory test results, and energy and environmental protection monitoring records. Documents are updated in real time upon completion of each batch of raw material processing, each furnace run, or each cell operation. Individual documents often contain multiple sets of continuous process parameters, test values, and ledger entries. Most fields use dedicated units, such as kiloamps for current intensity, percentages for material proportions, and degrees Celsius for cell temperature.

## What Constraints Do These Characteristics Impose on Document Parsing and Chunking
Real-time updated operation documents require parsing and chunking to support fast response. This avoids work backlog caused by excessive waiting time. Multiple sets of continuous process parameters, test values, and ledger entries require retaining contextual connections during chunking. This avoids losing the corresponding relationship between parameters after splitting. Dedicated units and specialized fields require the parsing stage to accurately identify the binding relationship between fields and values. This avoids extracting incorrect parameter combinations. Large differences in document formats across multiple sources require adaptation to files with different structures such as batching lists and smelting records. This ensures unified chunking logic across documents.

## How to Configure the Settings
These configurations are adapted for FastGPT v4.17.0:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | `800–1200 characters` | Documents for this category mostly contain continuous process parameters and ledger entries. This range preserves contextual connections between parameters, avoiding loss of corresponding relationships after splitting |
| `chunkSplitter` | By paragraph + semantic boundary | Documents for this category are mostly structured into paragraphs divided by operation batches or cell positions. Semantic boundaries ensure that single chunked content has complete logical integrity |
| `customPdfParse` | Enable high-precision OCR mode | Some documents for this category include hand-annotated cell condition logs or scanned test reports. High-precision OCR improves the accuracy of field identification |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120–180 seconds` | Parsing single multi-page smelting or electrolysis ledgers takes a long time. This range covers the parsing needs of most conventional documents, avoiding timeout errors |
| `chunkSettingMode` | Custom mode | Documents for this category have large format differences. Custom mode allows flexible adjustment of chunking rules to adapt to different types of ledgers and records |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | Single multi-page operation ledgers for this category typically do not exceed 500 MB. This setting covers the upload and parsing needs of conventional documents |

## Three Common Misconfigurations
- Enabling the `customPdfParse` high-precision mode results in an OCR Error alert. The cause is that some scanned cell condition logs or test reports contain blurry handwritten annotations or low-resolution images, and high-precision OCR cannot fully recognize the image content.
- A parsing timeout error occurs during private deployment, but the parsing service log shows that the task completed successfully. The cause is that the frontend timeout threshold is set lower than the actual parsing time, and does not match the `PARSE_FILE_TIMEOUT_SECONDS` configuration parameter.
- The configuration entry for `customPdfParse` cannot be found after updating the version. The cause is that the configuration entry location was adjusted after the system version update, and the advanced configuration page was not accessed.

## How to Confirm Correct Configuration
- Access the advanced configuration page, and verify whether the values of configuration items such as `chunkSize`, `chunkSplitter`, and `customPdfParse` meet the requirements in the table.
- Upload a scanned test report, and check whether the parsing result accurately extracts test values and corresponding fields, to verify that the high-precision OCR function is active.
- Upload an electrolyzer condition ledger with more than 10 pages, and check whether the parsing time is within the configured range, with no timeout errors.
- Adjust `chunkSize` to a custom value, upload a smelting record, and check whether the chunked content retains the connection of continuous process parameters, with no logical breaks.

The values provided are common starting points and should be evaluated against the reader's own samples.
