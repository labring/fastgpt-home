# Cross-Review of Technical Documentation for Incoming Material Inspection and Supplier Quality: Vector Models and Indexes

## What This Category’s Data Looks Like
Core data for this category comes from daily business documents of manufacturing enterprise IQC, SQE, purchasing quality, and supplier engineering departments. These include inspection specifications, sampling plans, incoming material reports, supplier audit reports, exception contact sheets, 8D reports, and concession acceptance approval forms.
Data sources cover purchase orders, drawing specifications, supplier quality certificates, inspection equipment logs, historical quality data, and supplier portals.
Documents contain structured fields such as batch number, defect level, and sampling ratio, as well as paragraph-style explanatory content. Update frequencies include per incoming batch, monthly or quarterly supplier evaluations, and ad-hoc special audits.

## Constraints for Vector Models and Indexing
Multi-source heterogeneous data sources require indexing systems to support unified vectorization and storage of cross-format data.
High-frequency update cycles require support for incremental indexing and version management, to avoid the time cost of full index rebuilding.
Diverse document types need adaptation to different chunking rules to ensure the integrity of structured tables and paragraph content.
Clear batch and defect level fields must be included as metadata in the index to enable subsequent precise filtering.
Cross-review business requirements demand recall results be linked to multiple documents from the same batch, to avoid isolated retrieval results that cannot support decision-making.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Documents in this category include structured sampling plans and paragraph-style inspection instructions. Excessively long chunks will split field associations, while excessively short chunks will disrupt the coherence of inspection logic |
| Overlap Length | 100–150 characters | Documents such as incoming material reports and 8D reports contain cross-paragraph batch-related information. Overlap length is used to retain contextual associations |
| Similarity Threshold | 0.75–0.85 | It is necessary to distinguish different batch inspection results of the same defect level, to avoid invalid recall across batches |
| `defaultToken` | 4096 | Documents associated with a single batch in this category have substantial content, and need to accommodate complete inspection specifications and historical exception records |
| Single Search Limit | Top 8 entries | It is necessary to cover the cross-comparison needs of multiple supplier audit reports, to avoid excessive redundant results interfering with judgment |
| Maximum Context | 12000 characters | Used to integrate associated content of incoming material inspection reports and supplier quality certificates, to support the complete logic of cross-review |

## Three Common Misconfigurations
- The symptom is that after upgrading from FastGPT v4.17.0 to a newer version, previously queryable incoming material inspection documents can no longer be recalled. The cause is that the new version enables strict matching rules for metadata indexing by default, and does not retain the index compatibility configuration from older versions.
- The symptom is that vectorized indexing results for Excel-format supplier quality certificates are incorrect. The cause is that no dedicated chunking parameters were configured for structured tables, leading to batch numbers and inspection values in cells being incorrectly split into different chunks.
- The symptom is that search results include inspection records for multiple unrelated batches. The cause is that batch number was not configured as a retrieval filtering condition, leading to recall scope exceeding the target batch for the current review.

## How to Verify Correct Configuration
- Upload a single incoming material inspection report, use the defect level keyword within the report to search, and check whether the recall results include the core inspection item content of this report.
- Set a batch number metadata filtering condition, search for documents of the target batch, and confirm that the recall results only include associated records for this batch.
- Upload an Excel-format supplier quality certificate, view the chunk preview interface, and confirm that batch numbers and inspection values in cells have not been incorrectly split.
- Perform cross-document cross-review search, and confirm that incoming material reports and supplier audit report content for the corresponding batch can be recalled simultaneously.

The values provided are common starting points and should be evaluated against relevant samples.
