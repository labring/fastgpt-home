# Cross-Review of Technical Documentation for Incoming Material Inspection and Supplier Quality: Multi-Turn Dialogue and Prompt Words

## What the Data for This Category Looks Like
Data for this category originates from purchase orders, drawing specifications, supplier quality certificates, inspection equipment, historical quality data, and supplier portals. Daily processed documents include inspection specifications, sampling plans, incoming material reports, supplier audit reports, exception contact sheets, 8D reports, and concession acceptance approval forms. New data records are generated with each batch of incoming materials. Supplier evaluation updates are completed on a monthly or quarterly basis. Special audits are conducted irregularly. Documents contain fields such as batch number, sampling ratio, non-conforming item type, and supplier code. Some documents include quantified test values and associated units.

## Constraints for Multi-Turn Dialogue and Prompt Words
Data for this category updates with each incoming material batch, monthly/quarterly evaluations, and irregular audits. Multi-turn dialogue must strictly distinguish contexts across different batches and cycles to prevent cross-batch or cross-cycle data mixing. Different document types use dedicated fields. Prompt words must clearly specify the document type for the current review to avoid incorrect field extraction. Temporary exception contact sheets and regular supplier audit reports have different timeliness requirements. Multi-turn dialogue must mark the time range of the current task to prevent misuse of data. Data sources include content from external supplier portals. Dialogue must limit retrieval scope to historical data for the currently associated supplier to ensure accurate review boundaries.

## How to Set the Configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique string of the current incoming material batch | Ensure multi-turn dialogue context only associates with inspection and review data for the current batch, avoiding cross-batch confusion |
| `messages` | Retain the first 10 rounds of interaction content | Cover the complete review process for a single incoming material inspection, covering all steps from sampling judgment to exception handling |
| `variables` | Preset supplier code and batch number as fixed variables | Automatically bring in core parameters for the current review, reducing repeated input and parameter errors |
| Maximum context window | 8000–12000 token | Accommodate core content of multiple inspection specifications, sampling plans, and historical reports, meeting information needs for cross-review |
| Single search limit | Top 5 entries | Limit the scope of historical quality data retrieval, avoiding redundant information interfering with review logic |
| Prompt optimization | Calibrate based on actual measurements | Adapt to professional terminology and field rules for documents in this category, improving the recognition accuracy of prompt words |

## Three Common Mistakes
- An error `Cannot read properties of null (reading 'q')` occurs during dialogue operation. The root cause is incorrect configuration of the `chatId` parameter, which prevents the system from identifying the session context for the current dialogue.
- Global variables fail to stay consistent across sessions in multi-turn dialogue. The root cause is failure to write core parameters such as supplier code and batch number into the `variables` configuration, leading to variable value resets with each interaction.
- Problem classification results in the workflow show significant deviation. The root cause is the prompt word not limiting the review scope to documents exclusive to incoming material inspection and supplier quality, and not clearly defining field extraction rules, causing the model to confuse business logic from other categories.

## How to Verify Proper Configuration
- Launch a simulated incoming material review dialogue, verify that the `chatId` parameter is bound to the current batch, ensuring the context only links to the current task.
- Review the multi-turn dialogue record, confirm that core fields in the `variables` parameter are not reset across sessions and remain consistent.
- Submit a test query to confirm the model only retrieves historical quality data and documents for the current supplier, with no irrelevant content included.
- Confirm the current FastGPT version is v4.17.0 to ensure configuration items align with version requirements.
