# Cross-Review of Technical Documentation for Incoming Material Inspection and Supplier Quality: Citation Sources and Traceability

## What the data for this category looks like
The data for this category primarily comes from purchase orders, drawings and specifications, supplier quality certificates, inspection equipment, historical quality data, and supplier portals. Daily processed documents include inspection specifications, sampling plans, incoming material reports, supplier audit reports, exception contact sheets, 8D reports, and concession acceptance approvals.
New records are created for each batch of incoming material as part of data updates. Supplier evaluation updates are completed monthly or quarterly. Special audits are conducted irregularly to update data.
Documents include fields such as batch number, supplier information, inspection items, and qualified judgment results. There are no unified mandatory units. Settings adjust based on the specific document type.

## Constraints on Citation Sources and Traceability from This Category’s Data Characteristics
This category’s data characteristics create multiple constraints for the citation sources and traceability link.
First, data sources are scattered and update rhythms are flexible. New data is generated with each batch of incoming material, monthly evaluations, and temporary audits. Retrieval must accurately match core associated information such as current batch and supplier. This avoids invalid citations across batches or suppliers.
Second, daily processed document types are diverse. Field logic varies significantly across different documents. Accurate identification of exclusive fields such as inspection items and qualified judgment results is required for traceability. General document field rules cannot be relied on.
Third, some temporary audit data must be quickly added to the traceability scope. Configuration must support dynamic loading of newly updated documents. This ensures the timeliness of traceability results.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Single Search Limit | Top 5-8 entries | Matches the multi-source, multi-batch retrieval needs of this category, avoids excessive redundant citations interfering with quality judgment |
| `quoteMaxToken` | 800–1200 tokens | Adapts to the average length of a single inspection or audit document for this category, ensures complete citation of key inspection and audit information |
| Return Citation Details | Enabled (returns the first 200 characters of each cited document) | Displays exclusive fields such as batch number and supplier information, while controlling the size of returned data |
| `responseData` | Structured return | Returns citation data in a format that separates metadata and content, facilitating association of core information such as batch and supplier |
| `detail` | Full field return | Retains the original document’s field format, prevents incomplete traceability information caused by missing fields |
| Dynamic Data Loading Delay | 30–60 seconds | Adapts to quick loading of temporary audit data, ensures newly generated audit documents can be retrieved in a timely manner |

## Three Common Misconfigurations
- Phenomenon: Retrieved cited documents do not match the current incoming material batch, and the batch number field is empty. Cause: Retrieval variables based on batch number and supplier information are not correctly configured, leading to failure to accurately match associated documents for the current incoming material.
- Phenomenon: After configuring `quoteMaxToken`, key inspection items in some long documents are truncated, making complete traceability impossible. Cause: The value range for `quoteMaxToken` is set too small, failing to adapt to the average length of long documents in this category.
- Phenomenon: Exclusive fields such as batch number and qualified judgment results cannot be extracted from knowledge base citation results, leading to incomplete traceability information. Cause: The `detail` configuration item is not enabled, or extraction rules for corresponding fields are not configured, resulting in citation data only returning unstructured summaries.

## How to Verify Correct Configuration
This verification must be performed using FastGPT v4.17.0.
- Upload an incoming material report and supplier audit report for the current batch, perform a retrieval, and check whether the returned cited documents include key information for the current batch.
- Adjust the value of `quoteMaxToken`, verify that key inspection items in long documents are fully displayed without truncation.
- Check whether the returned citation data includes exclusive fields such as batch number and supplier information, confirm that the `detail` configuration item is enabled.
- Submit a new document generated from temporary audits, verify that the retrieval results include the new document, confirm that the dynamic loading configuration is active.

The values provided are common starting points and should be evaluated against applicable local samples.
