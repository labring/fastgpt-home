# Cross-Review of Technical Documentation for Mold Design and Manufacturing: Vector Models and Indexes

## What the Data for This Category Looks Like
Daily documents for this category include mold design task sheets, DFM reports, part drawings, machining process cards, trial mold reports, mold modification notices, and mold history records. Data sources include customer product models, mold flow or forming simulation files, CAD/CAM output files, machining and measurement data, and trial mold sample parameters.
Data updates follow project timelines. New or modified documents are added after every trial mold or mold modification. Documents include specialized fields such as draft angle, shrinkage rate, and assembly accuracy. Most units use common engineering units like millimeters, seconds, and tons.

## Constraints Imposed on Vector Models and Indexing Workflows
The data characteristics of this category create multiple constraints for the vector models and indexing workflow.
First, document types span multiple formats, including structured machining process cards and unstructured trial mold reports. This requires the system to support mixed-format text parsing and chunking.
Second, data updates iterate alongside trial molds and mold modifications. The system must support incremental index updates without full reconstruction to lower operational costs.
Third, documents contain specialized semantic fields such as draft angle and shrinkage rate. Retrieval and matching must prioritize these high-weight semantic terms.
Finally, single projects are linked to large numbers of documents. The system must control the computational efficiency of recall and reranking to prevent retrieval timeouts.

## Configuration Recommendations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Mold design documents contain long text such as part dimensions and process steps. This length preserves complete context and avoids overly fragmented chunks |
| `maxToken` | 4096 | Matches the default context window of general large models, and adapts to the long-text input requirements of mold-related documents |
| Overlap Length | 150–200 characters | Preserves semantic connections across chunks, and prevents key professional information such as draft angle and shrinkage rate from being truncated by chunking |
| Similarity Threshold | 0.72–0.85 | Calibrated based on actual measurements, adapts to the semantic similarity range of mold-specific documents, and filters low-relevance non-project documents |
| Single Search Limit | Top 8 entries | Balances retrieval recall scope and computational efficiency, and prioritizes recall of high-relevance core project documents |
| Maximum Context | 8000–12000 characters | Integrates multiple associated documents to meet the multi-source information integration requirements of technical document cross-review |

## Three Common Mistakes
- The interface shows an embedding model load failure, with the error prompt "Model configuration not found". The cause is failure to configure the local deployment path of Ali-emb3 or import the corresponding configuration file as required by FastGPT v4.17.0.
- The retrieved trial mold report entries are correct, but the large language model generated content does not reference the mold modification suggestions in them. The cause is that the maximum context setting is too small, and the relevant documents are not included in the large model's context window.
- Incremental index update takes too long. The cause is that the number of documents updated in a single batch is not split, exceeding the system's default batch processing threshold, which causes the index process to block.

## How to Confirm Correct Configuration
- Enter the model management page of FastGPT v4.17.0, and confirm that the embedding model status of Ali-emb3 is "Loaded".
- Upload a mold trial report, perform a retrieval test, and check whether the similarity scores of the returned results fall within the preset 0.72–0.85 range.
- Import multiple documents from the same project, perform a cross-review retrieval, and confirm that the returned documents include associated types such as DFM reports, process cards, and trial mold reports.
- Perform an incremental update test, modify a mold modification notice to trigger index update, and confirm that the update time meets expectations.

The values provided are common starting points and should be measured against the reader's own samples.
