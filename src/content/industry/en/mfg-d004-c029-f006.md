# Cross-Review of Technical Documentation for Mold Design and Manufacturing: Citation Sources and Traceability

## What the data for this category looks like
Daily documents for mold design and manufacturing include mold design task sheets, DFM reports, part drawings, machining process cards, mold trial reports, mold modification notices, and mold records. Data sources cover customer product models, mold flow or forming simulation results, CAD/CAM files, machining and measurement data, and mold trial sample inspection records. Data updates proceed with project progress. New versions are generated after each mold trial or mold modification. Individual documents contain fields such as mold number, part tolerances, defect descriptions, and machining parameters. Units include millimeters, megapascals, hours, and other common engineering units.

## Constraints imposed by these characteristics on citation sources and traceability
Diverse document types that iterate alongside projects require traceability functions to accurately bind to the latest version data of the current mold project, preventing cross-project data confusion. Multi-source data needs unified association rules to ensure cited documents such as mold trial reports and mold modification notices match the corresponding design task sheets. Individual documents have lengthy content, so cited fragments must fully cover key information while avoiding irrelevant data that disrupts review logic. When errors occur, the citation source must be located quickly, so traceability information must include metadata such as document type, generation time, and associated project.

## Configuration settings
This configuration rule applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | 800–1200 token | Documents related to mold design have lengthy single segments, requiring coverage of complete DFM reports or mold trial defect descriptions |
| `responseData` | Full metadata | Citation documents’ type, generation time, and associated project must be recorded to facilitate subsequent issue tracing |
| `detail` | Enabled | Mold projects require tracing back to specific mold trial reports or mold modification notices to meet traceability requirements for engineering reviews |
| Project association rule | Bind by project ID | Data is updated iteratively by project, ensuring citations use the latest version of the current mold project |
| Single recall limit | Top 3 entries | Avoid excessive irrelevant data disrupting review logic, focusing on core mold trial and modification records |

## Three common misconfigurations
- The symptom is that the unique identifier field for the cited data source is empty. The cause is that the binding rule between projects and documents is not configured, so queried files cannot be associated with the current mold project.
- The symptom is that the temperature parameter configuration button disappears after setting variable reference mode. The cause is that some interface entrances fold advanced configuration items by default in variable reference mode, requiring expansion before adjustment.
- The symptom is that citation results include mold data from non-current projects. The cause is that the project filter switch for data sources is not enabled, causing documents from cross-projects to be incorrectly recalled.

## How to verify proper configuration
- Upload a test mold trial report and mold modification notice, submit a review request, and check if the returned results include the document’s generation time and associated project information.
- Switch to variable reference mode, verify that advanced configuration items can be expanded and temperature parameters adjusted.
- Enter a query containing a specific mold number, confirm that returned citation data only includes documents from the corresponding project.
- View citation logs, confirm that each citation result is bound to a unique data source ID and project identifier.
