# Cross-Review of Technical Documentation for Rubber Mixing and Product Vulcanization: Multi-Turn Dialogue and Prompt Engineering

## Data Profile for This Category
Data for this category comes from formula systems, raw material batch ledgers, internal mixer collection data, Mooney viscometers, rheometers, vulcanizer operation logs, and laboratory test reports. Daily generated documents include formula sheets, weighing records, mixing curves, rubber material rapid test reports, vulcanization process cards, mold usage records, and finished product performance reports. Data is updated synchronously for each batch of rubber material, each batch of raw materials, and each mold run of products. Document fields include rubber compound ratio (unit: phr), weighing and feeding value (unit: kg), mixing temperature (unit: ℃), vulcanization duration (unit: min), cavity dimensions (unit: mm), and other related items.

## Constraints Imposed on Multi-Turn Dialogue and Prompt Engineering
This category has high-frequency, closely linked data updates. Multi-turn dialogue must limit the effective scope of historical context to avoid expired data interfering with current reviews. Fields and units vary significantly across different documents, so prompts must clearly distinguish validation rules for different document types such as formula sheets and vulcanization process cards. Single-batch data has strong correlation, so multi-turn dialogue must gradually connect weighing records, mixing curves, and vulcanization parameters to avoid mixing cross-batch data. At the same time, unit validation of data fields is a core constraint. A unit matching step must be embedded in the dialogue flow to prevent process deviations caused by inconsistent units.

The following configurations are formulated based on the functional logic of FastGPT v4.17.0.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `messages` historical message retention limit | Last 8 turns of dialogue | The single-batch review process for this category typically does not exceed 8 steps. Retaining the last 8 turns covers the complete validation logic while avoiding redundancy |
| `variables` bound parameters | Bind current production batch ID | Ensure the dialogue always links to the full chain documents of the current batch's formula, weighing, mixing, and vulcanization |
| Dialogue timeout threshold | 300 seconds | The validation process for pulling multi-dimensional data across devices typically takes a relatively long time. 300 seconds covers conventional scenarios |
| `chatId` session isolation rule | Isolate by production batch | Prevent review sessions of different batches from interfering with each other, ensuring the independence of each batch's review |
| Number of documents matched per request | Top 6 entries | Documents related to a single batch typically do not exceed 5 types. 6 entries covers all associated documents while avoiding redundancy |
| Prompt optimization switch | Calibrate based on actual testing | Adjust the guidance logic of prompts based on the specific links of on-site validation |

## Three Common Mistakes
- Dialogue timeout occurs, with the interface displaying a request timeout prompt. The cause is failing to adjust the timeout threshold for the scenario of pulling multi-dimensional data across devices for this category. The default threshold is insufficient to cover the full-chain validation time.
- The dialogue does not continuously call the knowledge base, only returning results for the first request. The cause is failing to correctly bind the batch ID parameter in `variables`, causing the session to fail to continuously link to the exclusive document library of the current batch.
- The dialogue returns the error message "No valid documents matched". The cause is failing to isolate `chatId` by production batch. Sessions of different batches share irrelevant document data, leading to matching results that do not meet current review requirements.

## How to Verify Correct Configuration
- Initiate a simulated review dialogue, input the production number of the current batch, and check if returned matched documents only include the current batch's formula sheets, weighing records, and other content.
- Wait for more than 200 seconds during the dialogue, check if a timeout prompt is triggered, and confirm that the timeout threshold setting matches actual validation time.
- Initiate more than 3 consecutive rounds of dialogue, check if the context of each round retains the key parameters of the current batch and is not covered by redundant historical information.
- View the `chatId` identifier of the session, confirm that each production batch's session has an independent `chatId`, and no cross-batch sharing occurs.
