# Cross-Review of Technical Documentation for Complete Vehicle Final Assembly: Vector Models and Indexes

## What the data for this category looks like
Data sources for this category include ERP/MES systems, VIN and configuration systems, supplier batch management systems, tightening tool terminals, EOL inspection lines, and quality traceability systems. Daily documents cover production orders, VIN lists, assembly work instructions, tightening data, offline inspection reports, rework records, and consistency release documents. Data updates follow a rhythm of real-time updates per vehicle, with batch synchronization per shift. Document fields include VIN code, station number, torque value, inspection item number, and others. Corresponding units include newton meters, milliseconds, and others.

## What constraints do these characteristics impose on the vector models and indexes link
Vehicle-specific line data centered on VIN requires indexes to support fast filtering and matching by VIN, to avoid interference from cross-vehicle data. Real-time updated tightening and inspection data requires indexes to support incremental synchronization, to reduce the time spent on full reconstruction. Mixed ingestion of multiple types of documents requires index structures to support both structured fields and unstructured text, while retaining field association relationships. The total volume of documents from high-takt mixed-line production grows linearly with production capacity. This requires index retrieval response speed to match production takt, to avoid slowing down the review process. The compliance review requirement for consistency release documents requires vector retrieval recall accuracy to match business verification standards.

## How to set the configuration
This configuration is based on FastGPT v4.17.0. Specific parameters are listed below:

| Configuration Item | Recommended Range | Rationale |
|---|---|---|
| Chunk Length | 800–1200 characters | Adapts to the paragraph length of assembly work instructions, avoids breaking critical information within a chunk |
| Overlap Length | 100–200 characters | Retains cross-chunk association of VIN codes and torque parameters, prevents core associated information from being split |
| `maxToken` | 4096 token | Matches the total length of documents associated with a single batch of VINs, ensures complete context |
| `defaultToken` | 512 token | Serves as the default word segmentation limit for short single documents, balances retrieval efficiency and information completeness |
| `maxToken` | 8192 token | Extends context review length for long document types such as consistency release documents |
| Similarity Threshold | 0.75–0.85 | Differentiates compliant and abnormal tightening data and inspection results, adapts to accuracy requirements for final assembly processes |

## Three Common Mistakes
- A 60-second timeout occurs when switching knowledge base indexes. The cause is failure to configure incremental index synchronization, and failure to split batches during full index reconstruction, which exceeds the system response threshold.
- The knowledge base remains in a training or rebuilding state for an extended period. The cause is failure to split index collections by VIN dimension, and full import of multi-vehicle level documents leading to excessively long index construction time.
- An incorrect request parameter format occurs when adding indexes to collection blocks in batches. The cause is failure to specify VIN as the associated index field, and direct upload of original documents leading to inability to match review content by single vehicle line.

## How to Confirm Proper Configuration
- Import a single assembly work instruction that includes a VIN code, confirm the index can quickly recall associated tightening data documents using the VIN keyword.
- Trigger an incremental index synchronization, check for no time-consuming alerts for full reconstruction in system logs, confirm the update rhythm meets real-time requirements.
- Initiate a cross-document cross-review request, confirm returned results include work instructions for the corresponding station, historical rework records, and consistency documents.
- View the field mapping configuration of the index collection, confirm core fields such as VIN code and torque value have been correctly associated with index dimensions.
