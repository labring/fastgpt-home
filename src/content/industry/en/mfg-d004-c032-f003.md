# Cross-Review of Technical Documentation for Complete Vehicle Final Assembly: Multi-Turn Dialogue and Prompt Engineering

## What the data for this category looks like
Data for this category centers on the VIN of a single vehicle. Daily documents include production orders, VIN lists, assembly work instructions, tightening data, off-line inspection reports, rework records, consistency and release documents. Data sources cover ERP/MES systems, VIN and vehicle configuration systems, supplier batch management, workshop tightening tools, EOL off-line inspection lines, and quality traceability systems. Data updates run per single vehicle. Key tightening and inspection data sync in real time. Batch configuration and release documents update per shift. Overall data volume shifts dynamically with production tempo.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
This category uses VIN as the unique identifier for a single vehicle. Mixed-line production requires distinguishing review sessions for different vehicles. Multi-turn dialogue must bind `chatId` to isolate sessions. A single vehicle links to hundreds of configuration items and documents. The multi-turn dialogue context window must stay within a reasonable range to avoid lag from excessive data loading. Real-time tightening and inspection data require prompts to prioritize the latest data sources. Exclusive configuration information for the current vehicle must load dynamically during multi-turn interactions. Complex torque control and defect traceability logic need prompts to split review steps: first extract the VIN, then match corresponding documents. This prevents confusion across different vehicles’ review data.

## Three common misconfigurations
- Symptom: An error appears in the debug preview interface after enabling input guidance and configuring a custom thesaurus. Cause: The custom thesaurus’s format and encoding are not verified, so the model fails to load the thesaurus rules correctly and triggers a syntax error.
- Symptom: The maximum response token is set above 3000, but a complex question’s response truncates to 200 tokens. Cause: No global context token limit is configured, or the context window fills with excess historical dialogue and document data, leaving insufficient tokens for a full response.
- Symptom: New rework records or inspection data cannot be dynamically added to the knowledge base during dialogue. Cause: No trigger rules for dynamic knowledge base updates are set, or the current vehicle’s VIN is not used as the knowledge base classification identifier, so new data fails to link to the corresponding review session.

## How to verify successful configuration
- Initiate a VIN query for a single vehicle, confirm the `chatId` in the dialogue history matches the vehicle’s VIN to verify session isolation.
- Input a question involving complex configuration matching, check the response’s token consumption statistics to confirm no unexpected token truncation occurs.
- Upload new rework records, trigger the dialogue flow, confirm the model uses the newly uploaded data to complete the review.
- Check the thesaurus loading prompt in the debug preview interface, confirm the custom thesaurus imports successfully with no format errors.
