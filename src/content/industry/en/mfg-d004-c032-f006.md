# Cross-Review of Technical Documentation for Complete Vehicle Final Assembly: Citation Sources and Traceability

## What the data for this category looks like
Data sources for the complete vehicle final assembly scenario include ERP, MES systems, VIN and configuration systems, tightening tools, EOL inspection lines, and quality traceability systems.
Daily documents cover production orders, VIN lists, assembly work instructions, tightening data, offline inspection reports, rework records, and consistency release documents.
Data updates occur per vehicle, in real time, or per shift. Each vehicle matches hundreds of configuration and part information.
Document fields include VIN code, torque value, inspection item number, supplier batch, and more. Units include newton meters, percentage, batch numbers, and more.

## What constraints these characteristics impose on citation sources and traceability
Each vehicle matches hundreds of configuration documents. This requires citation traceability granularity to be precise at the VIN level to avoid mixing data across vehicles.
Real-time tightening data and offline inspection data require immediate traceability. This requires the system to support real-time pulling of the latest data.
In mixed-line production modes, assembly documents for different stations must bind accurately to corresponding vehicles. This requires traceability information to link stations and VINs.
Errors can lead to vehicles failing to roll off the line or safety defect recalls. This requires traceability information to meet high standards for accuracy and completeness, to avoid production line downtime from mismatched or missing parts.

## How to set the configuration
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the total length of hundreds of configuration documents per vehicle, avoids context overflow |
| `responseData` | Includes VIN, station, generation time fields | Matches traceability requirements for complete vehicle final assembly, ensures core associated data can be extracted |
| `detail` | Medium | Balances traceability information completeness and response speed, fits real-time interaction needs for production scenarios |
| Citation source display toggle | Enabled | Ensures citation source information for documents appears on officially published pages |
| Single recall limit | Top 6 entries | Covers the number of core assembly, tightening, and offline inspection documents per vehicle |

## Three common configuration errors
- Phenomenon: The officially published chat page does not show citation document sources, but the debug preview page displays correctly. Cause: The citation source display toggle for the formal environment is not enabled. Only the debug environment enables this configuration by default.
- Phenomenon: The text content extraction component cannot pull traceability information from knowledge base citation results. Cause: `responseData` is not configured to include traceability fields such as VIN and station. This prevents the component from recognizing valid associated data.
- Phenomenon: Program execution results are not passed as background knowledge to subsequent workflow modules. Cause: The output results of program execution are not bound to the knowledge base context module. The data flow link is not correctly configured.

## How to verify a successful configuration
- Enter the officially published chat page, initiate a query with the target VIN code, and check if corresponding citation document information displays below the reply content.
- Call the text content extraction component, pass in knowledge base citation results, and check if the extraction results include preset traceability fields such as VIN and station number.
- Configure the program execution module output to bind to the knowledge base context, initiate a test query, and check if subsequent AI replies use this execution result as background knowledge.
- View workflow running logs, confirm that `quoteMaxToken` and single recall limit values match the preset configuration.

The values provided are common starting points and should be measured against the reader's own samples.
