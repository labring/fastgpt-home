# Cross-Review of Technical Documentation for Complete Vehicle Final Assembly: Document Parsing and Chunking

## What the data for this category looks like
Daily documents for the complete vehicle final assembly scenario include production orders, VIN lists, assembly work instructions, tightening data, off-line inspection reports, repair records, and consistency release documents.
Data sources cover ERP/MES systems, VIN and vehicle configuration systems, supplier batch libraries, tightening tools, EOL inspection lines, and quality traceability systems.
Data update frequencies include two categories: real-time updates per vehicle, and batch updates per shift.
Document structures include fixed-format station operation instructions, numerical parameters with units (such as tightening torque values), uniquely identified VIN code fields, and multi-vehicle configuration difference content for mixed-line production.

## What constraints these characteristics impose on document parsing and chunking
This scenario uses VIN as the single vehicle main line for mixed-line configuration. Chunking operations must not break the contextual association between VINs and their corresponding parts and torque parameters. Otherwise, cross-review cannot match the complete configuration information of a single vehicle.
Real-time updated tightening data and off-line reports require the parsing process to have sufficient timeout tolerance space. This avoids data loss caused by large-volume file parsing timeouts.
Document structure differences from multi-vehicle mixed production require chunking rules to support custom matching logic. Generic pure paragraph splitting cannot be used, as it fails to accurately extract structured station operations and test results.
Single-vehicle associated document volume is large. Chunk length must be controlled to ensure contextual integrity during retrieval.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the paragraph length of assembly work instructions, avoids breaking the contextual association between VIN codes and their corresponding torque parameters |
| `chunkSplitter` | Paragraphs + custom VIN matching rules | Adapts to multi-vehicle document structures in mixed-line production, retains complete contextual information for single-vehicle configurations |
| `customPdfParse` | Enabled | Extracts structured content such as fixed-format station parameters and tightening data from assembly work instructions, replacing pure text extraction from generic PDF parsing |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 seconds | Meets parsing time requirements for large-volume off-line inspection reports and tightening data files associated with single vehicles |
| `chunkSettingMode` | Custom mode | Allows setting chunk association rules for VIN fields, meeting the single-vehicle cross-review requirements of complete vehicle final assembly |

## Three common errors
- Uploading an assembly work instruction and finding no results in knowledge base searches. The cause is that `customPdfParse` is not enabled. This fails to extract structured station parameters and VIN association fields, leaving only plain text which causes retrieval matching failures.
- Failing to locate the miner-u parsing function after an update. The cause is that this function has been integrated into the `customPdfParse` configuration item. Enable the custom PDF parsing switch in the knowledge base's document parsing settings.
- Accidentally setting the "custom rule" threshold to the same value as `chunkSize`. This causes chunking to break the contextual association between VIN codes and their corresponding tightening data, making single-vehicle configuration cross-review impossible.

## How to confirm proper configuration
- Upload an off-line inspection report containing a VIN code and tightening torque values. View the chunk list after parsing in the knowledge base. Confirm that each chunk retains the associated content of the VIN and its corresponding parameters.
- Enter "VIN:LSGJA5XXX" in the knowledge base's search test tool. Check if chunk results containing this VIN code are returned.
- Upload a batch tightening data file of around 10MB. Check that the parsing status has no timeout errors. Confirm that the `PARSE_FILE_TIMEOUT_SECONDS` setting meets requirements.
- View the parsing logs for FastGPT v4.17.0. Confirm that `customPdfParse` has successfully extracted structured fields, with no format parsing errors.
