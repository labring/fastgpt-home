# Cross-Review of Technical Documentation for Mass Production of Automotive Parts: Citation Sources and Traceability

## What the data for this category looks like
The primary participants in mass-produced automotive parts are suppliers of braking, steering, chassis, interior and exterior trim, and powertrain systems. Daily generated documents include control plans, process flowcharts, work instructions, first-piece and patrol inspection records, SPC reports, PPAP materials, 8D reports, and more. Data sources include customer drawings and special characteristic lists, ERP/MES systems, measuring tool data, equipment process parameters, and supplier quality certificates. Data is updated per batch, per shift, or via continuous collection. Document fields include special characteristic numbers, tolerance values, CPK values, sampling frequencies, and more. Units involve millimeters, percentages, pieces/hour, and other standard units. The length of individual documents varies widely.

## What constraints these characteristics impose on the "citation sources and traceability" link
Multi-source, frequently updated data requires that citation traceability must accurately match document versions and production batches. This prevents referencing outdated control plans or abnormal records. There are diverse document types. Corresponding review links must be associated by document category. For example, referencing PPAP materials requires linking to customer approval status. The nature of mass production requires that traceability results cover all process-related documents for a single batch. This avoids missing critical parameters. Additionally, strict constraints from vehicle customers mean referenced content must strictly align with customer-specified special characteristics. Traceability paths must be traceable back to original customer-delivered documents to ensure compliance.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Individual automotive part documents have long fragments. Sufficient token count is needed to fully display referenced control plans or SPC report content |
| `responseData` | Enabled | Original document citation source data must be returned. This is used to show original text fragments to reviewers |
| `detail` | Full document path + update time | Document versions and sources must be clearly identified for traceability. This meets quality system compliance requirements from vehicle customers |
| Single recall citation limit | Top 6 entries | Mass production has a large number of associated documents. Too many citations will cause redundant responses and reduce review efficiency |
| Context window length | 10000–15000 characters | Supports context association for multi-round cross-review conversations. This retains previously referenced document information |
| Guest citation permission | Enable per scenario | Adapts traceability needs for different access scenarios, such as account-free access at workshop sites |

## Three common configuration errors
- When accessing the application via a guest sharing link, the citation function fails to display the original text. This occurs because the citation traceability permission for guest scenarios is not enabled in the application configuration, or the `responseData` configuration item is incorrectly disabled.
- No citation marker appears at the end of paragraphs in knowledge base responses. This occurs because the `detail` configuration item is not enabled, or the `quoteMaxToken` value is too small to extract valid citation fragments.
- After multiple consecutive review questions are raised, subsequent questions cannot associate previously referenced document content, leading to off-topic responses. This occurs because the context window length is not configured sufficiently, and multi-round context-associated citation traceability settings are not enabled.

## How to verify correct configuration
- Upload an automotive parts control plan document, submit a question about special characteristic requirements, and check if the response has a clear citation source identifier at the end.
- Click the citation marker in the response, verify that the corresponding fragment of the original document can be viewed after jumping. This fragment must include key information such as document type and update time.
- Submit two consecutive review questions, check that the system associates the document content referenced in the first question when processing the second question, to complete cross-review.
- Generate a guest sharing link for FastGPT v4.17.0, access the link, and verify that the citation function works normally to view the original text with no permission errors.

The values provided here are common starting points. They should be evaluated against the reader's own samples.
