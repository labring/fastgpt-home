# Cross-Review of Technical Documentation for High-Volume Automotive Component Manufacturing: Document Parsing and Chunking

## What This Category’s Data Looks Like
The daily documents for this category include control plans, process flowcharts, work instructions, first article and inspection records, SPC reports, PPAP materials, 8D reports, and similar items. Data sources include customer drawings and special characteristic lists, ERP/MES, measuring tools, equipment process parameters, and supplier quality certificates. Data update frequency follows per batch, per shift, or continuous collection. Documents often contain multi-column tables, technical fields with units (such as torque N·m, dimensional tolerance mm), process schematics, and some documents are linked to parameter information from HTTP interface response messages.

## What Constraints Do These Characteristics Impose on Document Parsing and Chunking
The above data characteristics create multiple constraints for the document parsing and chunking process. Multi-source mixed document formats require parsing tools to support PDF, multi-column tables, process images, and HTTP interface messages simultaneously. High-frequency updated batch data requires the parsing process to have reasonable timeout settings and file capacity limits. Technical fields with specific units and multi-column layouts require chunking rules to retain field associations and table structures, preventing splitting that breaks the correspondence between processes and inspection parameters. Documents associated with interface messages require parsing logic to cover HTTP response field extraction.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to multi-column tables and technical fields with units, avoids splitting that breaks the association between processes and inspection parameters |
| `chunkSplitter` | Split by paragraph + table boundaries | Preserves structural integrity of control plans and SPC reports, prevents incorrect concatenation of multi-column content |
| `customPdfParse` | Enable image text extraction + multi-column recognition | Adapts to work instructions with process schematics and multi-column layouts, fully extracts text descriptions associated with images |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 seconds | Addresses parsing time for batch-uploaded PPAP materials and 8D reports, prevents task interruption mid-process |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Accommodates complete single-batch control plan packages and associated documents |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for different document types, adapts to multi-source data formats |

## Three Common Misconfigurations
-  The Set-Cookie field is empty after parsing HTTP interface response messages, making it impossible to extract customer special characteristic parameters. The root cause is that the default parsing logic does not cover HTTP response field extraction, and the corresponding adaptive configuration is not enabled.
-  After uploading a work instruction PDF with process images, the parsed result does not include the text description corresponding to the images. The root cause is that the image extraction switch for `customPdfParse` is not enabled, resulting in lost image information.
-  The column order of multi-column SPC reports is disrupted after parsing, making it impossible to match inspection data with corresponding processes. The root cause is that the chunking rule for splitting by table boundaries is not configured, leading to incorrect concatenation of multi-column content.

## How to Verify Correct Configuration
-  Upload a single SPC report with multi-column tables, check that the column order in the parsed result matches the original document, with no concatenation errors.
-  Upload a work instruction PDF containing process schematics, check that the positional association between images and surrounding text in the parsed result is correct.
-  Upload a single PPAP material package, check that the parsing task completes within the time set by `PARSE_FILE_TIMEOUT_SECONDS`, with no timeout errors.
-  Call the parsing interface to test HTTP response messages, check that the Set-Cookie field is correctly extracted and retained in the parsed chunks.

The values provided are common starting points and should be evaluated against the reader's own samples.
