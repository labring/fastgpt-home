# Cross-Review of Technical Documentation for Baked Goods and Convenience Foods: Workflow Orchestration

## What the data for this category looks like
Core data for this category comes from multiple systems and records across bakeries, cookie factories, instant noodle plants, and frozen pastry facilities. Daily documentation includes recipes and ingredient lists, production logs, baking or steaming curves, metal detection records, cleaning and sanitization logs, and factory release inspection reports. Data sources cover raw and auxiliary material qualification certificates, ERP/MES systems, weighing equipment, ovens or fryer lines, laboratory test data, and food traceability ledgers. Data updates follow a per-production-batch core rhythm, supplemented by shift-by-shift production log updates and daily cleaning and inspection archiving. Document fields include batch numbers, allergen labels, ingredient weights, baking temperatures and durations, cleaning and sanitization times, and more. Some documents require matching units such as grams, kilograms, degrees Celsius, and minutes to ensure accurate data validation.

## What constraints these characteristics impose on workflow orchestration
This category has a large number of recipes and frequent product line changes. It also directly serves consumers, so allergen control and foreign matter control requirements are strict. Workflows must support quick switching of review nodes for different products. There is a need to pull data from multiple sources, so workflow configurations must adapt to variable binding rules of different systems to avoid data misalignment. Following the per-batch and per-shift update rhythm, workflows must match production node triggers instead of using fixed timed triggers, to ensure review timing aligns with data updates. At the same time, errors can lead to product recalls and unqualified taste, so workflows must have clear failure branches and validation steps to ensure the completeness of cross-review. Allergen control and cleaning switching requirements for this category are higher than other food categories, so workflows must separately configure branch nodes for allergen verification and cleaning status validation.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Trigger Timing | Triggered upon completion of a production batch node | Matches the per-batch data update rhythm to avoid ineffective reviews |
| Variable Configuration | Bind `variables` to batch number, allergen list, ingredient weight | Covers dynamic data required for core reviews, adapts to multi-product line change scenarios |
| Model Call Timeout | 600 seconds | Covers the total time required for multi-source data pulling and cross-validation |
| Log Storage Limit | 1000 MB | Retains multi-batch review logs without occupying excessive storage space |
| Node ID Identification | Bind `nodeId` to the allergen review step | Facilitates quick location of the corresponding review node for troubleshooting |
| Retry Count | 2 times | Addresses occasional scenarios where data pulling from devices fails temporarily |

## Three Common Mistakes
- Connection lines cannot be added to workflows, and no small connection circles appear between nodes. Cause: The workflow node activation state in FastGPT v4.17.0 is not enabled. Connection functionality is disabled by default for some custom nodes.
- The model ID of components within workflows cannot be viewed. Cause: The model call configuration item is not bound in `variables`, so the corresponding display field fails to load on the interface.
- Task workflows run slower than debug mode runs. Cause: Workflows configured with multi-source data pulling steps skip non-essential data source validation in debug mode. Formal execution requires full data pulling from ERP, device logs, and other sources.

## How to Confirm the Configuration is Complete
- Manually trigger a test batch workflow, and verify that connection lines between nodes display normally, with no disconnected or unconnectable instances.
- View the `variables` configuration item of the workflow, confirm that core review fields such as batch number and allergen list are bound.
- Enter the log page of the corresponding node, confirm that detailed operation logs for that node can be pulled.
- Compare task time consumption between debug mode and formal operation, confirm that the configured timeout parameters match actual operation rhythms.

The values provided are common starting points and should be measured against the reader's own samples.
