# Cross-Review of Heat Treatment Technical Documentation: Tool Calling and Plugins

## What Data Looks Like for This Category
Technical documents for heat treatment scenarios include heat treatment process cards, furnace loading diagrams, furnace temperature curves, hardness and metallographic reports, equipment inspection forms, and exception handling sheets.
Data sources include material grade standards, customer technical requirements, temperature control instruments, furnace temperature uniformity testing equipment, hardness testers and metallographic equipment, and workshop MES systems.
Data is updated per furnace charge or batch.
Single furnace charge documents include fields such as heating temperature, holding duration, furnace temperature sampling values, and hardness test results.
Temperature units are degrees Celsius. Duration units are minutes. Hardness values use HRC or HV standard units.

## Constraints Imposed on Tool Calling and Plugins
Since data updates per furnace charge or batch, tool calling must support real-time pulling of the latest equipment and test data. This avoids use of expired historical documents.
Document types include structured tables and unstructured charts. Multi-format parsing plugins must be configured.
Error consequences include unqualified performance of entire furnace parts. Tool calling results must have high accuracy. Cross-document field cross-checking is required.
A single workshop has many furnace charge batches. Tool calling frequency is high. Current limiting rules must be configured to avoid platform error reports. API calling permissions for different furnace charge batches must be maintained independently. This prevents permission confusion from configuration overwrites.

| API Key Groups | Split by business scenario | Differentiates API permissions for different furnace charge batches to avoid configuration overwrites |
| Tool Call Timeout | 300 seconds | Adapts to parsing time for large-volume documents |
| Maximum Documents per Single Call | First 3 entries | Limits call volume to avoid current limiting errors |
| Current Time Tool Trigger Rule | Auto-trigger at verification node | Meets requirements for real-time comparison of furnace temperature sampling times |

## Three Common Configuration Errors
- Existing API keys are overwritten after creating a new model configuration: Multi-scenario API key grouping configuration is not enabled, and the global single-key storage logic is used, causing new configurations to overwrite old ones.
- Tool call returns 429 status code error: The maximum number of documents per single call is not set, and the number of documents called in a single round exceeds the platform's current limiting rules, triggering call frequency restrictions.
- Tool fails to load furnace temperature curve images: Outbound access rules for image pulling are not configured, causing inability to access image resources uploaded by equipment, returning loading failure prompts.

## How to Verify Successful Configuration
- Submit a single furnace charge's process card and furnace temperature curve. Check if the tool automatically calls the corresponding data parsing plugin to complete field extraction and cross-checking.
- Create two independent business scenario configurations. Fill in different API keys respectively, then initiate a call test. Confirm that the keys of the two scenarios are not overwritten by each other.
- Initiate a batch call test containing 4 documents. Check that the number of returned results is 3, matching the preset maximum per single call.
- Trigger a current time tool call. Check that the returned time matches the system's current time, meeting the verification requirements for furnace temperature sampling times.

The values provided are common starting points and should be measured against the reader's own samples.
