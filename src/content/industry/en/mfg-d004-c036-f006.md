# Cross-Review of Technical Documentation for Welded Structural Component Manufacturing: Citation Sources and Traceability

## What the Data for This Category Looks Like
Data for this category covers the entire manufacturing process of steel structures, pressure vessels, engineering machinery, and rail vehicle structural components. Daily documents include welding procedure qualifications, welding procedure specifications, consumable issue records, welder qualification records, weld inspection reports, and repair orders. Data sources are design drawings, material quality certificates, welding equipment parameters, consumable inventory records, non-destructive testing system data, and personnel qualification ledgers. Update cycles follow per weld, per batch of workpieces, or per shift. Document fields include workpiece number, consumable brand, welder qualification level, inspection results, and similar items. There are no uniform fixed units; values vary based on the specific parameters of individual records.

## What Constraints Do These Characteristics Impose on the "Citation Sources and Traceability" Link
Data for this category is scattered across multiple independent systems such as design, consumable management, and inspection. Cross-system associated traceability requires matching dynamic fields like workpiece number and consumable brand. Fixed hard-coded rules cannot be relied upon. The data update granularity is as fine as per individual weld. The number of entries recalled in a single task must be strictly controlled to avoid redundant interference. Document fields have no uniform units, so dynamic adaptation to the parameter formats of different records must be supported. The quality of welded structural components is linked to structural failure risks. Traceability results must be directly associated with original vouchers. Indirect results from fuzzy matching are not acceptable.

## How to Configure
| Configuration Item | Recommended Approach | Basis for This Approach |
|---|---|---|
| `quoteMaxToken` | `800–1200 token` | The core cited content of a single document for welded structural components typically falls within this range, and can fully cover key information such as procedure qualifications and inspection results |
| `responseData` | Return only the original fields of matching items | Direct association with original vouchers is required to avoid processed ambiguous content, which meets the rigid requirements of welded structural component quality traceability |
| `detail` | Enable full field return | Dynamic fields such as workpiece number and consumable brand must be matched to ensure accurate association with corresponding records during traceability |
| Single search limit | `Top 2–5 entries` | The data update granularity is as fine as per individual weld; too many recalled entries will increase interference in cross-review and improve audit efficiency |
| Maximum context | Calibrate based on actual measurements | Document lengths vary significantly across enterprises, and adjustments must be made based on actual document scale to avoid context overflow |

This configuration applies to FastGPT v4.17.0.

## Three Common Mistakes
- The symptom is a blank dropdown menu for reference variables in the knowledge base search node of the workflow, making it impossible to select a configured global variable. The cause is that the knowledge base association permission is not enabled in the global variable configuration, or the variable type is not set to the knowledge base selection type.
- The symptom is that the original input and response content of the knowledge base search are still displayed in the answer after the workflow is called. The cause is that the reference display switch is not turned off in the output configuration of the workflow, or the tool call result is not correctly bound to the answer generation node.
- The symptom is that the traceability result matches incorrect consumable issue records or welder qualification records. The cause is that dynamic field matching rules are not configured, and only hard-coded field name matching is used, which cannot adapt to the dynamic parameters of different workpieces.

## How to Confirm Proper Configuration
- Upload a welding procedure specification document to trigger cross-review, and check whether the returned cited content includes core fields such as the workpiece number and consumable brand of the original document.
- View the workflow log to confirm that the knowledge base search node only returns the specified number of matching records, and the fields are complete and without missing content.
- Enter the global variable configuration page to confirm that variables of the knowledge base selection type have been correctly added and can be normally selected in the reference variable dropdown menu.
- View the final generated review answer to confirm that the original input and response content of the knowledge base search are not displayed, and only structured review results are shown.
