# Cross-Review of Technical Documentation for Biologics and Aseptic Manufacturing: Vector Models and Indexes

## What Data for This Category Looks Like
Routine documents for this category include cell bank or seed lot records, culture and purification records, aseptic filling records, environmental monitoring data, media fill simulation results, sterility test reports, and batch release documentation. Data sources include cell bank and seed lot systems, process analysis equipment, clean zone monitoring systems, MES, LIMS, and equipment integrity test records. Three update rhythms apply: updates after each production batch, real-time monitoring synchronization, and updates per fixed monitoring plans.

Documents contain both structured fields and unstructured text. Structured fields include batch number, equipment ID, monitoring time, parameter values, and similar items. Unstructured text includes operation records, exception descriptions, and similar items. Some fields use dedicated units, such as colony-forming units, colony count, and pressure values.

## Constraints Imposed on Vector Models and Indexes
Multi-source, multi-format data requires unified embedding adaptation logic to prevent vector drift across different data sources from reducing retrieval accuracy. Real-time and scheduled update data requires indexes to support incremental construction and synchronization, to avoid resource consumption and delays caused by full index reconstruction.

Documents include both structured and unstructured content, so vector encoding must be applied to both text and metadata. This ensures that key information from the original document can be associated during retrieval. This category has strict data accuracy requirements; index recall accuracy and context completeness directly affect the reliability of review results. Improper chunking or index configuration must be avoided to prevent loss of key information.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the average length of documents in this category, prevents embedding accuracy degradation caused by overly scattered or excessively long single chunks |
| Overlap Length | 50–100 characters | Preserves contextual association between adjacent chunks, prevents key operation or parameter information from being truncated during chunking |
| Similarity Threshold | 0.72–0.78 | Matches the semantic similarity distribution of documents in this category, balances recall rate and accuracy, and meets the retrieval needs of professional documents |
| Single Search Limit | Top 10 results | Controls the number of retrieval results, avoids redundant information interfering with professional review judgments |
| `maxToken` | 8000 | Adapts to embedding needs for long documents, supports complete text encoding for complex production records |
| `defaultToken` | Set from representative sample documents | `defaultToken` is the default token count for direct text chunking; tune it on representative source documents. See the [v4.17.2 model-field reference](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx). It is not a vector dimension, embedding-model input cap, or retrieval/LLM context. |

## Three Common Misconfigurations
- Retrieval cannot be triggered when the index status displays as not ready. This occurs when the full workflow of vector embedding and index construction has not been completed, and the readiness judgment criteria defined in FastGPT v4.17.0 have not been satisfied.
- A compatibility error occurs when attempting to use Doubao-embedding as the vector model. This occurs when the vector model's calling interface and parameter format are not correctly specified in the model configuration, and FastGPT's vector model access specifications are not matched.
- Retrieval results do not associate with specific source fields of the original document. This occurs when the metadata extraction configuration for document traceability is not enabled, and key fields such as batch number and equipment ID are not included in index metadata storage.

## How to Verify Proper Configuration
- Upload a single typical document (such as a cell bank record), wait for index completion, and check whether the status displays as ready.
- Retrieve preset professional test questions, confirm that returned results include metadata information from the original document, including fields such as document name and batch number.
- Adjust the `maxToken` parameter, upload a long document, and verify that no truncation or errors occur during the embedding and index process.
- Upload a document updated per a monitoring plan, confirm that the index system can correctly identify updated content and synchronize it to the retrieval library.

The values provided are common starting points and should be measured against the reader's own samples.
