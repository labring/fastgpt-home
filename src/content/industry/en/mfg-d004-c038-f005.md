# Cross-Review of Technical Documents for Biologics and Aseptic Manufacturing: Tool Calling and Plugins

## What Data for This Category Looks Like
Core data for this category originates from cell banks and seed lots, process analysis systems, cleanroom monitoring systems, MES, LIMS, and equipment integrity testing systems. Daily documents include cell bank or seed lot records, culture and purification records, aseptic filling records, environmental monitoring data, media fill simulation results, sterility test reports, and batch release documentation. Data update frequencies fall into three categories: synchronized with each production batch, real-time monitoring updates, and updates per fixed monitoring plans. Documents contain both structured fields and unstructured text. Structured fields include culture temperature (℃), inoculation volume (mL), and cleanroom sedimentation bacteria count (cfu/㎡). Unstructured text includes operation records and test instructions.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins Workflows
Dispersed multi-source data requires tool calling to support integration with multiple types of system plugins, to complete cross-data-source document aggregation. Different update frequencies require plugin trigger mechanisms to adapt to both on-demand calls and batch processing. This avoids missing real-time monitoring data or compromising the timeliness of batch document reviews. Complex document structures require tool calling parameter extraction to accurately distinguish between structured fields and unstructured text. This ensures the `q` parameter matches category-specific review scenarios. Review errors carry serious safety risks, so strict verification of parameter completeness and format correctness for tool calling is required.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to structured and mixed content of category documents, automatically matches corresponding tool calling logic |
| `functionCall` | Enabled | Forces conversion of user queries into standardized tool calling parameters, to avoid format errors |
| Number of documents processed per single run | First 20 | Matches total document volume per production batch, to avoid exceeding context capacity limits |
| Parameter q extraction rule | Extract core fields related to sterility testing and batch release from user queries | Corresponds to core review scenarios for category documents |
| Context window size | 8000–12000 token | Adapts to content splicing of multiple documents, meets information needs for cross-review |
| Compatible Version | FastGPT v4.17.0 | Ensures normal operation of tool calling and plugin functions |

## Three Common Configuration Mistakes
- Symptom: Tool calling returns empty results, and the `q` parameter field contains no valid content. Cause: Core fields matching category-specific scenarios are not accurately extracted from user queries. Only generalized query content is used, and review requirements such as sterility testing and batch release are not addressed.
- Symptom: Plugins do not respond after being clicked, and the console returns a 400 status code. Cause: API permissions for the connected LIMS or cleanroom monitoring system are not configured for the plugin, or plugin permission binding is not completed.
- Symptom: Tool calling times out, returning a 504 status code. Cause: The number of documents processed per single run is set too high, exceeding system response thresholds, and does not match the batch processing rhythm of category documents.

## How to Confirm Configurations Are Correct
- Initiate a test query that includes "sterility test results" and "batch release documents". Check if the `q` parameter for tool calling extracts core fields corresponding to the target scenario.
- Navigate to the plugin management page. Confirm that added system connection plugins are enabled, and all permission configurations are complete.
- Initiate a test query for batch document review. Check that the number of results returned by tool calling matches the set number of documents processed per single run.
- View tool calling logs. Confirm that the `functionCall` parameter is enabled, and the returned calling format complies with preset requirements.

All provided configuration values are common starting points. Adjust them based on your own specific samples and requirements.
