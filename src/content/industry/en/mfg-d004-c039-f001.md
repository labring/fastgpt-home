# Cross-Review of Technical Documentation for Electric Motor and Generator Manufacturing: HTTP Interfaces and External Systems

## What Data Looks Like for This Category
Data for this category originates from electromagnetic design systems, copper wire and insulation material batch ledgers, winding equipment operation logs, balancing machine collection data, electrical test bench output reports, and ERP/MES systems. Daily generated documents include winding process cards, insulation treatment records, dynamic balance reports, withstand voltage insulation test records, and type and factory test reports. These documents contain specialized fields such as winding turns, insulation class, test voltage, temperature rise value, and vibration amplitude. Units include turns, V, ℃, N·m, and others. Data is updated per individual motor, per product batch, or for each type change. A single document links structured data from multiple source systems.

## What Constraints These Characteristics Impose on the "HTTP Interfaces and External Systems" Workflow
Multi-source system data synchronization requires interfaces to support batch pulling of structured data from different devices and systems. The interfaces must be compatible with field mapping rules from diverse sources including electromagnetic design tools, test equipment, and ERP systems. High-frequency updates for single units or batches require interface call frequencies to align with production rhythms. This prevents excessive system load or data conflicts caused by frequent calls. The specialized nature of document fields requires interface requests and responses to strictly match specialized fields such as winding turns and insulation class. Generic handling of non-standard fields is not allowed. Cross-departmental cross-review of documents requires interfaces to support cross-system data association queries. The interfaces must carry association parameters such as batch numbers and device IDs to ensure accurate data matching during reviews.

## How to Set Configurations
| Configuration Item | Recommended Configuration | Rationale |
|---|---|---|
| `Authorization` | `Bearer {Enterprise API Key}` | Ensures interface call identity is legitimate, and complies with permission control requirements for industrial systems |
| `variables` | Bind batch number, device ID, and test date as dynamic variables | Matches exclusive data for each unit or product batch, and avoids data confusion across batches |
| `responseData` | Only extract winding turns, insulation class, and test voltage fields | Focuses on core review data, and reduces invalid data transmission and processing overhead |
| Request timeout | 300–600 seconds | Industrial test data collection may take a long time, and this avoids request interruptions from timeouts |
| Batch call threshold | Maximum 5 records per single call | Matches production update frequencies, and avoids excessive interface load |
| Character encoding setting | UTF-8 encoding | Compatible with multi-language professional terms and numerical fields, and avoids garbled text issues |

## Three Common Mistakes
- Symptom: Uploaded winding process card XLSX files do not trigger AI conversations, and the interface returns empty `responseData`. Cause: The correct document parsing format parameter is not specified in the request, so the interface cannot extract structured fields.
- Symptom: Test report text uploaded via API or web pages shows garbled characters. Cause: The interface character encoding is not uniformly set to UTF-8, which does not match the local system encoding.
- Symptom: Timeout errors occur when the workflow calls HTTP interfaces in a loop. Cause: A reasonable request timeout is not set, exceeding the time limit for industrial equipment data collection.

## How to Confirm Configuration is Correct
- Based on FastGPT v4.17.0, send a single interface request for a type test report. Check whether the `responseData` includes core fields such as winding turns and insulation class.
- Upload a test XLSX winding process card file, and confirm that the parsed results returned by the interface or frontend have no garbled characters.
- Initiate a batch call test, and verify that the interface does not report load errors when calling 5 records in a single request.
- Simulate a production batch change, and verify that dynamic parameters bound to `variables` can correctly associate data for the corresponding batch.
