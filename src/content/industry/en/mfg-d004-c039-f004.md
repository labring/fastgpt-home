# Cross-Review of Technical Documentation for Electric Motor and Generator Manufacturing: Workflow Orchestration

## What the data for this category looks like
Technical documentation data for electric motor and generator manufacturing comes from electromagnetic design data, copper wire and insulation material batch records, winding equipment outputs, balancing machine outputs, electrical test bench outputs, and ERP/MES systems. Documents produced daily include winding process cards, insulation treatment records, dynamic balance reports, dielectric strength test reports, type and factory inspection reports. Core fields of the documents include winding turns, paint dipping process parameters, vibration test values, temperature rise data, and others. The data update frequency is once per motor or per product batch, and all associated documents are synced and updated whenever a type change occurs.

## What constraints these characteristics impose on workflow orchestration
Multi-source heterogeneous data sources require the workflow to support different formats of device outputs, ERP fields, and scanned paper documents. Configure multi-node format conversion and field mapping. High-frequency single-unit or batch updates require trigger-based workflow startup to match the update rhythm of each unit or batch. Specific core validation fields require the workflow to bind precise parameter extraction rules to avoid irrelevant data interfering with review results. Additionally, the business characteristic of severe consequences from errors requires the workflow to include failure rollback and exception alert links to ensure high-risk exceptions are intercepted promptly.

## Configuration settings
| Config Item | Recommended Practice | Rationale |
| --- | --- | --- |
| `variables` | Bind winding turns, insulation batch, and test data fields | Match core validation parameters for motor manufacturing documentation, ensure reviews focus on critical content |
| Trigger timing | Trigger upon completion of document upload | Match the update rhythm of each unit or batch, avoid unnecessary runs |
| Timeout duration | 600 seconds | Adapt to the total time required for pulling data from multiple sources and validating multiple documents |
| `nodeId` | Specify the associated ID for code execution and document validation nodes | Ensure accurate data transfer between workflow nodes |
| Context invocation | Call the first 3 historical validation records | Match historical reference needs after type changes, assist with exception analysis |
| Result filtering | Retain validation-failed exception entries | Focus on high-risk exceptions such as winding burnout and insulation breakdown |

## Three common mistakes
- Phenomenon: The code execution node logs show normal output content, but the output fields of the specified reply node are empty, with no printed results. Cause: The output result of the code execution node is not bound to the input parameter link of the specified reply node via `variables`.
- Phenomenon: The original execution logs of the tool call module appear directly in the final output, and redundant content cannot be hidden. Cause: No result filtering node is added to the workflow to truncate non-essential return information from tool calls.
- Phenomenon: A connection failure error is returned when calling the storage node to pull test reports. Cause: MinIO-related environment variables have not been updated to match the naming rules of FastGPT v4.17.0.

## How to confirm the configuration is correct
- Upload the winding process card for a single motor, trigger the workflow, and verify that the bound fields correctly extract core parameters from the document.
- Run the full workflow, check whether the output of the specified reply node includes the return content from the preceding code execution node.
- View the workflow run logs, confirm that non-essential output from the tool call module is not included in the final result.
- Verify the connection status of the storage node, confirm that the environment variable configuration meets the requirements of the current FastGPT version.
