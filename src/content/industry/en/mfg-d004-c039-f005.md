# Cross-Review of Technical Documentation for Electric Motor and Generator Manufacturing: Tool Calling and Plugins

## What Data for This Category Looks Like
Core data for this category originates from winding, insulation, final assembly, and testing departments of motor factories and power equipment enterprises. Daily output documents include winding process cards, insulation treatment records, dynamic balance reports, voltage withstand insulation test reports, type inspection test reports, and factory inspection test reports.
Data sources cover electromagnetic design data, copper wire and insulating material batch records, winding equipment parameters, balancing machine detection data, electrical test bench results, and production and material information from ERP and MES systems.
Data is updated once per unit or batch of products, with synchronous updates each time a product type is changed.
Document structures include clear process parameters, detection values, batch identifiers, and responsible link fields. Some documents use specialized units such as millimeters, ohms, and revolutions per minute.

## Constraints Imposed on Tool Calling and Plugin Workflows
Documents in this category contain specialized detection values and batch-related information. Tool calling must accurately match fields and units to avoid parsing deviations.
Documents across multiple batches and production links have high update frequencies. Tool calling must support triggering tasks by batch number or product type change to avoid processing outdated data.
Document structures vary significantly across different document types. Plugins must adapt to multiple formats including winding process cards and test reports. Tool calling parameters must be compatible with field extraction rules for different documents.
Document errors can lead to serious consequences such as winding burnout and insulation breakdown. The result verification link for tool calling must be strengthened to ensure the accuracy of extracted key data such as the number of turns and voltage withstand values.

## Configuration Settings
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |

| Tool calling trigger rule | Trigger by batch number or type change marker | Matches the category’s characteristic of updating data by batch or product type change, avoids repeated processing of outdated documents |
| Workflow/API tool selection | `auto` | Automatically adapts to tool calling requirements for multiple document types including winding process cards and test reports, no manual configuration switching required |
| Document parsing plugin | Doc2x | Supports parsing multi-format documents for this category, meets text extraction needs for files such as winding process cards and test reports |
| Result verification priority | Prioritize verification of the top 3 matching results | Extraction of key parameters for this category requires high confidence; prioritizing verification of top matching results reduces error rates |
| Timeout setting | 600 seconds | Parsing and data extraction for complex test reports require longer durations, prevents task interruption due to timeout |
| Context window | 800–1200 characters | Matches the parameter length of single core documents for this category, avoids truncation of key information such as the number of turns and voltage withstand values |

## Three Common Misconfigurations
- Phenomenon: When uploading a winding process card using the Doc2x plugin, the copper wire batch field is not correctly extracted. Cause: No custom field mapping rule is configured for the plugin, so it cannot recognize specialized batch identifier fields in documents for this category.
- Phenomenon: After calling tools via API, the returned results do not include the document list associated with the knowledge base. Cause: Document provenance configuration for tool calling is not enabled, and related logging is not activated.
- Phenomenon: Tool calling tasks fail due to timeout, returning status code 504. Cause: Timeout setting is configured as 300 seconds, which cannot accommodate the parsing duration of complex type test reports.

## How to Verify Successful Configuration
- Upload one winding process card and one voltage withstand test report, verify that the plugin can correctly extract fields such as copper wire batch and voltage withstand value, adjust field mapping rules to match the target document structure.
- Initiate a tool calling task via API, check whether the returned results include the document list associated with the knowledge base, confirm that the document provenance configuration is active.
- Run a tool calling task and monitor actual duration, adjust the timeout setting to cover this duration to prevent task interruption.
- After configuring `toolChoice` as `auto`, upload different types of documents, verify that the tool can automatically adapt to parsing requirements.
