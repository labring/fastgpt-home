# Cross-Review of Technical Documentation for Electric Motor and Generator Manufacturing: Document Parsing and Chunking

## What the Data for This Category Looks Like
Core documents for electric motor and generator manufacturing originate from electromagnetic design data, copper wire and insulation material batches, winding equipment, balancing machines, electrical test benches, and ERP/MES systems. Updates occur per product unit, each production batch, or every formal design change.
Daily documents include winding process cards, insulation treatment records, dynamic balance reports, dielectric strength test reports, and type and factory test reports. These documents contain specialized fields such as winding turns, insulation class, test voltage, and balance accuracy. Some documents include nested tables and vector charts, with format differences varying by document type.

## Constraints for Document Parsing and Chunking
Documents in this category contain large volumes of specialized parameters and associated data. When creating chunks, preserve the integrity of individual process steps or test data sets. Do not split cross-field associated information.
Document formats vary widely across sources: some are structured process cards, while others have complex layouts for test reports. Parsing rules must be adapted to different document types.
In mass production scenarios, a large number of batch documents must be processed. Parsing tasks require sufficient duration and capacity. Ensure recognition accuracy for specialized fields to avoid parsing errors that disrupt the verification step of subsequent cross-review.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Winding process cards and test reports include continuous process parameters and test data. This length preserves the integrity of individual test steps or process items |
| `chunkSplitter` | Separate by paragraph + table header | Motor documents contain numerous test tables with headers and process paragraphs. Separating by paragraph and table header prevents splitting associated data across table headers |
| `customPdfParse` | Enable MinerU API adaptation | Some complex-format type test reports include nested tables and vector diagrams. Adaptation improves parsing accuracy |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Single type test reports have large data volumes. This duration prevents task failure due to parsing timeout |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch upload of batch documents and large test reports, aligning with document submission needs for mass production |
| `chunkSettingMode` | Manual configuration | Adjust chunking parameters for different document types (process card/test report) to accommodate multi-format document requirements |

## Three Common Mistakes
- Symptom: Some DOCX documents fail to parse after upload. The file status shows parsing failed or returns a non-200 status code. Cause: Custom parsing rules adapted to specialized motor documents are not enabled. The default parsing engine cannot recognize the format of specialized fields such as winding turns and insulation class.
- Symptom: Some tables in uploaded documents cannot be chunked correctly. Table content is split across multiple independent chunks. Cause: `chunkSplitter` is configured to split only by character count, with no rules set to separate by table header or paragraph. This causes invalid splitting across table boundaries.
- Symptom: Out-of-memory errors occur after deploying the MinerU API, or container logs show that GPU information cannot be recognized. Cause: CUDA environment and container resource allocation parameters are not configured correctly. This prevents MinerU from calling appropriate GPU resources, or causes memory allocation to exceed the container's available range.

## How to Confirm Configurations Are Set Correctly
- Upload a typical winding process card DOCX document. Confirm that the parsed text retains specialized fields such as winding turns and enameled wire specifications, with no missing fields or garbled text.
- Upload a type test report PDF document that includes nested tables. Confirm that the chunking result treats each table as an associated chunk unit, with no random splitting.
- Submit a test report of approximately 100 MB. Confirm that the parsing task completes within 600 seconds, with no timeout error messages.
- Check the container logs for FastGPT v4.17.0. Confirm that the MinerU API has correctly recognized GPU information, with no out-of-memory related error prompts.
