# Cross-Review of Technical Documentation for Battery PACK and Energy Storage System Integration: Tool Calling and Plugins

## What this category of data looks like
This category of data originates from cell capacity grading data, MES systems, welding equipment, torque tools, BMS software, and EOL test benches.
Daily generated documents include grouping rules, BOM lists, welding and torque records, BMS flashing records, insulation and voltage withstand reports, EOL test reports, and system configuration lists.
Data updates occur once per pack or per cabinet, or each time the BMS software version changes.
Document fields include cell capacity grading parameters, material codes, torque values, insulation and voltage withstand test values, BMS version numbers, and other relevant fields. Each single document corresponds to one production batch, single energy storage system, or single battery pack.

## What constraints these characteristics impose on the tool calling and plugins workflow
Data sources are scattered across multiple systems and devices. Tool calling must support multi-source data pulling, and dedicated tool nodes must be configured to access different data sources.
Data updates are triggered per pack, per cabinet, or when software versions change. Tool calling must support data synchronization triggered by production batches or version changes. This prevents expired data from being used in cross-review.
Each complete system corresponds to a full set of documents. Tool calling must associate and match related documents such as BOMs, welding records, and EOL test reports from the same production batch.
Failure of cross-review can lead to thermal management issues, insulation failure, or system shutdown. Tool calling must include a data consistency check step. This step verifies the matching degree of each document during cross-review, and avoids production risks caused by incorrect configurations.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | Bind a preset multi-source tool group | Covers tool calls for multiple data types including cell capacity grading data, welding torque records, and BMS flashing records, and adapts to the single-pack/single-cabinet cross-review requirements of FastGPT v4.17.0 |
| Workflow/API function-call configuration | Force enable tool calling mode | Restrict the model to only perform tool calls, and avoid entering inference mode |
| Tool call failure retry count | 3 times | Adapts to the verification requirements of single-batch documents, and prevents review interruptions caused by a single failed call |
| Tool call timeout period | 600 seconds | Covers the time requirements for multi-source data pulling, and prevents review failures caused by data pulling timeouts |
| Maximum number of tool call return results | Top 5 entries | Avoid excessive data overload, and ensure the efficiency and accuracy of cross-review |
| Tool call trigger condition | Triggered by production batch or software version change | Matches the data update frequency, and ensures only the latest document data is pulled |

## Three common misconfigurations
- Phenomenon: Tool calls return natural language inference results instead of tool call outputs. The model cannot be restricted from using inference mode. Cause: The `functionCall` forced tool calling mode is not enabled. The model independently selects an inference path.
- Phenomenon: Tool calls return connection errors. Logs show that data sources cannot be found. Cause: The multi-source tool group required for the category is not bound. Tool access nodes for docking MES systems, welding equipment, and other corresponding data sources are not configured.
- Phenomenon: Document data returned by tool calls does not match the current production batch. Cause: The trigger condition based on production batch or software version change is not set. Expired document data is pulled.

## How to verify a correct configuration
In FastGPT v4.17.0, run a cross-review task for a single battery pack or energy storage cabinet. Check that tool calls only return configured multi-source tool data, with no natural language inference results.
Simulate a tool call failure scenario. Check that the preset retry mechanism triggers, and the retry count matches the configured 3 times.
View the tool call data source list. Confirm that required category data sources are bound, including cell capacity grading data, welding torque records, and BMS flashing records.
View the tool call trigger condition. Confirm that the trigger rule based on production batch or software version change is set. This ensures only the latest document data is pulled.

The values provided here are common starting points, and should be measured against the reader's own samples.
