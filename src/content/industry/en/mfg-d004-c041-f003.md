# Cross-Review of Technical Documentation for Electroplating and Chemical Surface Treatment: Multi-Turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
The typical entities for this category are electroplating plants, electronic connector workshops, and hardware surface treatment facilities. Daily documents include bath solution analysis records, process parameter cards, fixture logs, film thickness and adhesion test reports, hazardous waste ledgers, and wastewater monitoring records. Data sources include customer surface treatment specifications, bath solution laboratory results, rectifier operating data, online water quality monitoring data, and hazardous waste management ledgers. Update frequencies vary by production stage: per bath cycle, per shift, and at fixed monitoring intervals. Individual documents include dedicated fields and units such as bath number, analysis time, pH value, metal ion concentration (unit: g/L), rack plating current (A), and processing duration (min).

## What Constraints These Characteristics Impose on Multi-Turn Dialogue and Prompt Engineering
Data for this category updates frequently and ties to real-time production status. Multi-turn dialogue must bind the unique identifier of the current production bath cycle to prevent cross-bath data mixing. Multiple document types and complex professional fields require prompts to precisely limit review scope to electroplating and chemical surface treatment exclusive documents. Prompts must also clearly specify the required fields and units to call. Hazardous waste and wastewater data link to compliance requirements. Multi-turn dialogue must synchronously connect monitoring records and compliance specifications to ensure review results align with production standards. Production errors carry severe consequences. Dialogue must verify parameter rationality to avoid batch rework or compliance penalties from incorrect parameters.

## Three Common Configuration Mistakes
- Phenomenon: Historical dialogue logs are lost after creating an application via API. Cause: The `chatId` parameter is not bound. Each request generates a new dialogue session, making it impossible to associate review data from previous bath cycles.
- Phenomenon: Results returned differ from expectations when using the same prompt to submit a query. Cause: The prompt does not clearly limit the review scope to documents exclusive to electroplating and chemical surface treatment, and does not inject category-specific fields to filter data.
- Phenomenon: Parameters returned by tool calls do not meet current production requirements. Cause: The default model matching this category is not configured, and parameter requirements from the `variables` field are not associated.

## How to Verify Proper Configuration
- Submit a cross-bath-cycle review request, check if returned results only associate documents for the currently bound `chatId` bath cycle.
