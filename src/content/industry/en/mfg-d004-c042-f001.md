# Cross-Review of Technical Documentation for Petroleum Refining: HTTP Interfaces and External Systems

## What the data for this category looks like
This category of data comes from daily documents and system data from production operation, process, scheduling, equipment, and laboratory departments of oil refining enterprises. Daily documents include operating procedures, production plans, material balance reports, distillate export quality reports, interlock ledgers, shift handover records, and change management documents. Data sources include DCS/APC, LIMS, tank farm metering systems, crude oil evaluation systems, equipment management systems, and energy systems. Data update frequencies are divided into three categories: real-time, per shift, and daily. Document fields cover material flow, distillation temperature, equipment interlock parameters, and others, with corresponding units including tons per hour, degrees Celsius, megapascals, and more.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" workflow
The multi-source heterogeneous data and differentiated update rhythms of this category require interfaces to support receiving data in multiple formats and triggering requests at different frequencies. The fields and units of daily documents vary significantly, so interface request parameters must support dynamic matching of business fields, and fixed templates cannot be used. Real-time updated process data requires interfaces to have low-latency response capabilities. Batch documents updated per shift need support for batch request processing. The coupling characteristics of multiple continuous units require interfaces to support associated verification of cross-unit data to ensure the integrity of data transmission.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `Authorization` | Carry a token in the format `Bearer {API_KEY}` | Complies with the identity verification standards of external systems |
| `variables` | Configure with refinery-specific variables such as crude oil type, unit load threshold, etc. | Matches the parameter verification rules of business documents |
| `responseData` | Configure to return only the collection of document fields that passed verification | Filter irrelevant data and reduce transmission load |
| Timeout setting | 600 seconds | Adapts to the transmission delay of real-time process data |
| Number of documents per single request | First 20 items | Matches the batch processing rhythm of documents updated per shift |
| File upload size limit | 1000 MB | Accommodates large-volume documents such as crude oil evaluation reports |

## Three common configuration errors
- An interface call returns empty content, with the `responseData` field in the interface response being an empty array. This happens because the original data returned by the interface is not mapped to the standard fields of refinery documents, resulting in no valid content being returned after filtering.
- Transmission failure occurs when uploading large-volume documents such as crude oil evaluation reports. This happens because the file upload size limit is not adjusted, exceeding the receiving threshold of the external system.
- When configuring `Authorization`, only the API_KEY is filled in without adding the `Bearer` prefix, triggering a 401 unauthorized error. This happens because the standard identity verification format is not followed, causing the external system to fail to identify the request identity.

## How to confirm the configuration is complete
- Initiate a test request and check whether the `responseData` returned by the interface includes core fields of refinery documents, such as material flow and distillation temperature.
- Upload a standard shift handover record document and confirm that the verification result returned by the interface meets expectations.
- Check the system logs of FastGPT v4.17.0 to confirm that the `Authorization` verification passes, with no unauthorized errors.
- Simulate a real-time process data update scenario and confirm that the interface can return processing results within 600 seconds.
