# Cross-Review of Technical Documentation for Petroleum Refining: Workflow Orchestration
This document is based on FastGPT v4.17.0.

## What this category of data looks like
Petroleum refining technical documents include operating procedures, production plans, material balances, distillation outlet quality reports, interlock ledgers, shift handover records, and change management documents. Data sources include DCS/APC, LIMS, tank farm metering, crude oil evaluation, equipment management systems, and energy systems.
Update frequencies fall into three categories: real-time (such as DCS process parameters), shift-based (such as shift handover records), and daily (such as material balance reports).
Document fields include crude oil density, distillation range temperature, material flow rate, interlock trigger values, and more. Supporting units include kilograms per cubic meter, degrees Celsius, cubic meters per hour, megapascals, and more.

## Constraints imposed on workflow orchestration by these characteristics
Differences in update rhythms across multiple data sources require workflows to pull data using distinct cycles: real-time, shift-based, and daily. This prevents cross-review deviations caused by inconsistent data timeliness.
Structural differences across multiple document types require defining parsing rules for different documents via `variables`. This supports mixed processing of fixed fields and unstructured content.
Coupled process logic across multiple units requires workflows to associate output results from multiple nodes. This enables cross-unit parameter linkage verification.
Real-time updated process data requires workflows to support breakpoint continuation and failure retries. This avoids process risks caused by single execution interruptions.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Variable group configuration | Group by document type into 7 groups, bind corresponding data source fields to each group | Matches the fixed field structure of daily documents |
| Node timeout setting | 1200–1800 seconds | Covers the maximum execution duration for single-unit load coordination and fraction control |
| Trigger rule configuration | Trigger based on the document upload completion status defined via `variables` | Ensures input data is complete and valid |
| External search node | Bind the output of the node with `nodeId` set to the process parameter node as search keywords | Adapts to dedicated search requirements for refining processes |
| File upload node | Limit single file size to no more than 1000 MB | Matches the upload requirements for large documents such as crude oil evaluation reports |
| Form input restriction | Only allow progression to the next node after required fields are completed | Prevents invalid data from entering the workflow |

## Three Common Misconfigurations
- Workflow execution times out. The interface displays an execution duration exceeding 1200 seconds, and the API returns a timeout status code. This occurs because the node timeout settings are not adjusted based on actual time consumption of refining process coordination, and long tasks with cross-unit linkage are not split.
- External search node calls return no matching results, delivering an empty result list. This occurs because dedicated parameters such as crude oil properties and unit load are not bound as search keywords via `variables`.
- Workflow does not start after file upload, and form fields can be submitted even when empty. This occurs because form input verification rules are not configured, and progression to the next link is not restricted to only after required items are completed.

## How to Confirm Proper Configuration
- Upload a typical crude oil evaluation report, and check if the workflow automatically triggers parsing and binds corresponding fields.
- Simulate a process fluctuation scenario, trigger workflow execution, and verify if the timeout threshold falls within the preset 1200–1800 second range.
- Test filling only some form fields, and confirm the system intercepts the submission and prompts for completion of required items.
- Call the workflow API, and verify if the returned results include verification fields for interlock ledgers and quality reports.
