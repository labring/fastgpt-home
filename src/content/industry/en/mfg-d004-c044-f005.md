# Pulp and Paper Technical Document Cross-Review: Tool Calling and Plugins

## What the data for this category looks like
Pulp and paper technical documents cover daily production and management records from preparation, pulping, papermaking, quality and energy departments. These include stock preparation sheets, beating records, paper machine operation records, online quality curves, laboratory reports, and sheet break and grade change records.
Data sources include wood pulp and waste paper batch ledgers, DCS/QCS control systems, paper machine online measurement equipment, laboratory testing instruments, and energy and water treatment systems.
Update frequencies fall into three categories: real-time, per shift, and per roll. Online quality curves are updated in real time. Stock preparation sheets and beating records are updated per shift. Sheet break and grade change records are archived once each roll’s production is complete.

## What constraints these characteristics impose on tool calling and plugins
Multi-source heterogeneous data sources require tool calling to support integration with multi-system plugins, enabling cross-data-source document association and cross-verification.
Documents with different update frequencies require configured differentiated synchronization intervals. Real-time data uses short synchronization intervals to prevent review content from lagging behind production progress.
Document structures include multiple formats: plain text, structured tables, visual curves, and more. Plugins must adapt to parsing rules for each format to ensure accurate extraction of professional fields such as beating degree, grammage, and cross-direction deviation.
High-speed continuous web production requires cross-review to cover cross-direction and longitudinal quality distribution data. Tool calling must associate multi-dimensional production records. Errors directly lead to paper roll downgrading or sheet break downtime, so tool calling reliability and response speed requirements are higher.

## Three Common Misconfigurations
- Symptom: The <Reference> field is empty when calling the knowledge base chat function. Cause: No plugin for integrating DCS/QCS systems is configured, and production data is not synchronized to the knowledge base, so associated document content cannot be extracted.
- Symptom: The Doc2x plugin fails to correctly extract fields such as beating degree and pulp ratio from stock preparation sheets. Cause: No industry-specific document parsing template for pulp and paper is uploaded, and the table structure and field naming rules for this category of documents are not adapted.
- Symptom: No file list used by the knowledge base is returned after calling via API. Cause: The knowledge base file traceability configuration is not enabled, and the `functionCall` parameter for returning associated metadata is not activated, resulting in missing file information in the API response content.

## How to Verify Proper Configuration
- Submit a review request targeting parameters of a specific stock preparation sheet, and check whether the returned results include matching beating records and paper machine operation data.
- Call the API interface, and check whether the returned content includes associated file names and path information.
- Upload a test sheet break record document, and confirm that the Doc2x plugin can correctly extract fields such as sheet break time, operating speed, and paper defect type.
- View the tool calling log, and confirm that the `toolChoice` parameter triggers a review tool adapted for pulp and paper scenarios.

The values provided are common starting points and should be evaluated against the user's own samples.
