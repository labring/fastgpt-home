# Cross-Review of Technical Documentation for Pulp and Paper Industry: Model Integration and Configuration

## What the data for this category looks like
Technical documents for pulp and paper scenarios include pulp preparation sheets, beating records, paper machine operation records, online quality curves, laboratory reports, and sheet break and product change records. Data sources cover wood pulp and waste paper batches, DCS/QCS systems, paper machine online measurement equipment, laboratories, energy and water treatment systems. Data update frequencies fall into three categories: real-time online measurement, shift team records, and roll production completion records. Individual documents include fields such as production batch, process parameters, and test results. Formats vary by department and record type, with no unified fixed standard.

## What constraints these characteristics impose on the "model integration and configuration" link
Documents from multiple sources with varied update frequencies require model calls to adapt to mixed-temporal document association, to avoid missing cross-shift and cross-device process association information. The full-process document volume for a single paper roll is large, so the model must support sufficient context length to cover the complete process chain. Recognition of professional process fields requires the model to maintain consistent output, to avoid verification conclusions that do not align with pulp and paper process logic. At the same time, production data security requirements mandate that model call links do not expose intranet production data, and access permissions must be restricted.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `maxContext` | 8000–12000 token | Adapts to the context requirements of full-process production documents for a single paper roll, covering associated verification across multiple links such as pulp preparation, beating, and papermaking |
| `maxTokens` | 2000–3000 token | Meets the output length requirements for a single cross-review result, including process adjustment suggestions and document verification conclusions |
| `quoteMaxToken` | 1500 token | Limits the length of individual document fragments referenced, adapting to the extraction of long-text fragments such as online quality curves and beating records |
| Workflow/API tool selection | auto | Allows the model to autonomously select cross-department document association, adapting to cross-review scenarios between pulp preparation sheets and sheet break records |
| `temperature` | 0.2–0.4 | Ensures consistency of process suggestions, avoiding output that does not align with common pulp and paper process knowledge |
| `AIPROXY_API_ENDPOINT` | Intranet access address of the deployment node | Ensures the security of production data transmission, avoiding exposure of sensitive production information over the public internet |
| `AIPROXY_API_TOKEN` | Exclusive token bound to the deployment node | Restricts access permissions for model calls, preventing unauthorized access to production data |

## Three common configuration mistakes
- Entering an invalid token when configuring `AIPROXY_API_TOKEN`. The interface displays model test failure, returning error codes in the format 1742438308259968. The cause is that the token does not match the deployment node, or the token has expired.
- Setting `maxContext` beyond the memory limit of the deployment node, resulting in model call timeout and returning a 504 status code. The cause is failure to adjust the context length based on deployment resources, exceeding hardware carrying capacity.
- Not setting `toolChoice` to auto. The model cannot automatically associate cross-department pulp preparation sheets and sheet break records, resulting in cross-review results missing key associated information. The cause is forcing the model to use a fixed tool call logic, which cannot adapt to dynamically associated document scenarios.

## How to confirm proper configuration
- Fill in the configuration parameters on the model channel test page of FastGPT v4.17.0, initiate a test call, and confirm that no errors are returned and the result includes process parameter verification content.
- Upload the complete production document set for a single paper roll, initiate a cross-review task, and confirm that the task is completed within a reasonable time frame.
- View the model call log, confirm that the `quoteMaxToken` restriction takes effect, and that referenced document fragments do not exceed the set length.
- Compare output results across different temperature parameters, confirm that result consistency within the `temperature` value range meets process verification requirements.
