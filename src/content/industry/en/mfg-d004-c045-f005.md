# Cross-Review of Technical Documentation for Spinning and Weaving: Tool Calling and Plugins

## What the Data for This Category Looks Like
Daily documents for this category include cotton blending or batching lists, process setup sheets, equipment operation records, yarn inspection reports, grey fabric inspection reports, and defect records.
Data sources cover raw fiber inspection reports, enterprise ERP systems, real-time data from spinning machines and looms, collection results from evenness testers and fabric inspection machines, and order specification requirements.
The data update rhythm changes with production nodes: each batch of raw materials triggers an update to the cotton blending or batching list, each shift triggers updates to equipment operation and process execution records, and each piece of fabric generates inspection and defect records.
Document fields include fiber raw material specifications, blending parameters, process parameters, inspection indicators, and some parameters have clear units of measurement. For example, twist is measured in twists per meter.

## Constraints on Tool Calling and Plugins From These Data Characteristics
The data characteristics of this category impose multiple constraints on the tool calling and plugin workflow.
Multi-source heterogeneous data sources require plugins to adapt to interface formats of different systems, to unify pulling of raw fiber inspection data, ERP batching information, and real-time equipment parameters.
Differentiated update rhythms across nodes require tool calling to configure trigger rules based on production batches, shifts, and fabric pieces, to avoid invalid calls or missed critical data.
Document fields have specific units of measurement. Plugins must include built-in parameter verification logic to ensure unit consistency for cross-document comparisons of twist, fiber strength, and other metrics.
The defect spread characteristic from continuous production requires tool calling to support cross-fabric defect record association queries, to ensure the completeness of cross-review.

## Configuration Settings
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool calling trigger rules | Trigger separately by production batch, shift, and fabric piece | Matches the update rhythm of this category’s data by batch, shift, and piece, to avoid invalid calls |
| Workflow/API tool selection | auto | Automatically select tools suitable for the current review task, covering multi-source data pulling and association query requirements |
| Workflow/API function-call configuration | enabled | Enable custom function calls, to support multi-source data association queries and parameter verification |
| Parameter verification switch | Enabled | Adapts to the characteristic that document fields have specific units of measurement, to ensure parameter consistency for cross-document comparisons |
| Associated document recall limit | Top 10 entries | Covers the requirement of associating previous multiple fabric defect records for a single fabric piece, with recall quantity calibrated through actual testing |
| Tool calling retry count | 3 times | Addresses occasional fluctuations in spinning machine data interfaces, to reduce the probability of call failures |
| Maximum context length | 8000 token | Adapts to the total length of documents related to a single production batch, to meet the information completeness requirement for cross-review |

## Three Common Configuration Mistakes
- A 500 status code is returned when importing category-specific documents. Cause: The plugin fails to adapt to the multi-field mixed structure of this category’s documents, and cannot correctly parse non-general fields such as fiber specifications and blending parameters.
- An error message indicating only official models are allowed is returned when calling a custom large model. Cause: The permission configuration process for custom model calls is not completed, and the plugin cannot correctly map model call parameters.
- Expected referenced content is not returned when using an online tool to pull real-time spinning machine data. Cause: The interface access permission for the corresponding data source is not configured, or the trigger rule does not match the update node of real-time data.

## How to Verify Correct Configuration
- Trigger a batch-based tool call, and check whether the returned documents include all associated documents such as cotton blending list and process setup sheet corresponding to the batch.
- Enable the parameter verification switch, input process parameters with different units of measurement, and check whether the plugin can identify and prompt issues with inconsistent units.
- Call the custom model interface, and check whether the cross-review results generated by the model can be returned normally without permission errors.
- Trigger an association recall operation, and check whether the number of returned associated documents conforms to the preset recall limit rules.

The values provided are common starting points, and should be evaluated against the reader's own samples.
