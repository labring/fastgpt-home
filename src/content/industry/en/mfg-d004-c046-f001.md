# Cross-Review of Technical Documentation for Meat Products and Slaughter Processing: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
Data for this category originates from animal quarantine information, supplier batches, production traceability, temperature collection, metal detection, and laboratory testing. Daily documents include quarantine certificates, slaughter and cutting records, ingredient marinating records, thermal processing records, cold chain temperature records, and microbial test reports.
Data updates per batch and shift. Continuous temperature control data synchronizes in real time.
Fields include batch number, quarantine identifier, temperature value (unit ℃), detection time, microbial indicator values, and others. Some data must be bound to the unique identifier of the corresponding production link.

## What Constraints These Characteristics Impose on HTTP Interfaces and External Systems
This category of data updates per production batch and shift. Continuous temperature control data requires real-time synchronization, so HTTP interfaces must support high-frequency, short-interval bulk data pulling.
Multiple document types must be bound to a unique production batch identifier. Interfaces must pass batch numbers as associated verification parameters.
Data includes specific format fields such as quarantine numbers, temperature values, and microbial indicators. Interfaces must support custom field mapping to match local system data structures.
Some data involves biosecurity verification. Interfaces must configure identity verification parameters to ensure the legality of data transmission.

## How to Configure Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `Authorization` | Fixed prefix plus enterprise-specific secret, formatted as `Bearer {enterprise API key}` | Matches identity verification requirements of external systems, ensures the legitimacy of interface access |
| `variables` | Configured as `["批次编号", "检疫标识", "温度阈值"]` | Matches core associated fields of documents in this category, enables cross-document batch association verification |
| `responseData` | Only return `["检疫证明编号", "批次温度记录", "微生物检验结果"]` | Filters irrelevant fields, reduces interface transmission load, matches core data requirements for cross-review |
| Request timeout | 600 seconds | Adapts to real-time synchronization requirements of continuous temperature control data, prevents timeouts from high-frequency requests |
| Batch request limit | Top 20 entries | Matches data volume per shift or batch, prevents interface overload |

## Three Common Configuration Errors
- Phenomenon: Returns database-related errors after calling the associated interface. Cause: Incorrect field format mapping, causing the external system database to fail to parse incoming parameters.
- Phenomenon: Returns unauthorized errors after interface calls. Cause: Incorrect configuration of the `Authorization` parameter, or the key format does not meet external system requirements.
- Phenomenon: Returns configuration exceptions after model calls. Cause: The external system interface address is not configured in the correct location, or the `/v1` path suffix is not added.

## How to Verify Correct Configuration
- Initiate an interface request for a single batch of data, and check if the returned fields include the preset core business fields.
- Simulate high-frequency requests, and verify that the interface can stably return data without triggering timeout restrictions.
- Verify that the batch number transmitted by the interface matches the batch number of the local production system.
- Check if the interface address has the correct path suffix, and no path errors are returned.
