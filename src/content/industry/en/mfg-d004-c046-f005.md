# Cross-Review of Technical Documentation for Meat Products and Slaughter Processing: Tool Calling and Plugins

## What the data for this category looks like
Daily data for typical entities in this category includes quarantine certificates, slaughter and cutting records, ingredient marinating records, thermal processing records, cold chain temperature logs, and microbial test reports. Data sources include animal quarantine information, supplier batch archives, production traceability systems, temperature collection terminals, metal detection equipment, and laboratory test results. Updates occur per production batch and each shift. Cold chain temperature logs are updated continuously. Each document contains fields such as batch number, quarantine ID, temperature thresholds, test indicators and corresponding values. Some records require linkage to batch and quarantine information to complete valid review.

## What constraints these characteristics impose on tool calling and plugin workflows
Data must be strictly linked to batch and quarantine information. Tool calling must support cross-document linked queries to prevent review failure caused by isolated single records. The volume of continuously collected cold chain temperature logs increases with each shift. Plugins must support pagination or batch reading to avoid overload during single calls. Microbial test results must match records from the corresponding production stage. Tools must support precise filtering by batch number and test time. Partition records related to raw and cooked product separation must be cross-verified with thermal processing temperature data. Tool calling must limit query scope to documents from the corresponding production partition to ensure compliance with review requirements.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to automatic tool calling needs for cross-document cross-review, matches batch-linked retrieval scenarios |
| Query Optimization | Enabled | Optimizes retrieval logic for precise fields such as batch number and quarantine ID, improves matching accuracy for cross-review |
| Single Search Limit | Top 8 entries | Matches the average number of production documents per shift, avoids overload while covering core linked records |
| Maximum Context Window | 12000 token | Adapts to linked validation across multiple cross-stage documents, accommodates multiple data types including batch, temperature, and test data |
| `functionCall` | Force Trigger | Ensures tool calling follows preset rules, avoids irrelevant content interfering with cross-review |
| Tool Result Caching | Calibrated via actual testing | Adapts to continuously collected temperature log data, reduces resource consumption from repeated calls |

## Three common errors
- Phenomenon: Retrieval results include quarantine certificates and production records that do not correspond to the target batch. Cause: Retrieval scope is not limited to the specified batch number, and tool calling does not use batch fields for filtering.
- Phenomenon: Tool calls return timeout errors (status code 504). Cause: A single call reads an excessive number of continuously collected cold chain temperature logs, exceeding system processing limits.
- Phenomenon: The number of linked documents returned by retrieval results falls below the preset limit. Cause: The single search limit parameter is not set correctly, leading to recalled records that do not cover all linked batch entries.

## How to confirm the configuration is properly set
1. Import complete production documents and corresponding quarantine certificates for a single batch in the FastGPT v4.17.0 environment. Run a cross-review task, and check that retrieval results only include linked records for that batch.
2. Simulate the import of temperature logs from consecutive shifts. Run a tool calling task, and confirm no timeout errors occur and the number of returned results matches the preset single search limit.
3. Input queries related to microbial tests, and check that returned results link to corresponding thermal processing records and batch information.
4. View tool calling logs, and confirm that the `functionCall` and `toolChoice` parameters trigger according to preset rules, with no abnormal calls.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
