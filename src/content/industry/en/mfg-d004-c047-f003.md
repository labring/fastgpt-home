# Cross-Review of Technical Documents for Measuring Instruments and Laboratory Management: Multi-Turn Dialogue and Prompt Engineering

## What Data for This Category Includes
Data for this category comes from metrology management systems, LIMS systems, external calibration institution certificates, standard instrument parameters, and environmental monitoring data. Daily documents include measuring tool ledgers, calibration plans, calibration certificates, interim verification records, original test records, reference material ledgers, and deviation handling forms. Data updates are triggered by calibration cycles, single test results, or abnormal events. Document fields include instrument numbers, calibration values, measurement uncertainties, traceability numbers, environmental temperature and humidity, and other professional measurement units such as millimeters, pascals, and degrees Celsius.

## Constraints for Multi-Turn Dialogue and Prompt Engineering
Data fields are numerous and include professional measurement units. Multi-turn dialogue must fully retain core context such as instrument traceability numbers and calibration values to avoid deviations in review logic. Document types cover multiple categories of metrology forms. Prompt engineering must distinguish validation rules for different documents such as ledgers, calibration certificates, and deviation handling forms. Data updates have no fixed cycle. Multi-turn dialogue must support real-time association with the latest calibration records and ledger information. Traceability chain review requires cross-document association. The `messages` parameter must fully pass key identifiers from historical conversations to ensure coherent context.

## Three Common Mistakes
- Symptom: The LLM model in the debug preview interface switches from a locally deployed DeepSeek model to another model, and local calls cannot be completed. Cause: The locally deployed endpoint of OneAPI was not correctly bound in the application configuration, causing the platform to call the built-in model by default.
- Symptom: After inputting JSON-formatted calibration certificate data, conversation return results show missing fields or truncated content. Cause: The context length limit corresponding to `chatId` was not adjusted, causing long JSON content to exceed the threshold and be truncated.
- Symptom: After adding multiple associated knowledge bases, retrieval results fail to cover all metrology document types. Cause: The single recall upper limit was set too low, failing to cover matching requirements for multiple document types including calibration certificates, ledgers, and interim verification records.

## How to Verify Proper Configuration
- Initiate a multi-turn conversation containing a specific instrument number. Confirm returned results associate key fields from the corresponding ledger and calibration certificate.
- Import a single long JSON-formatted calibration certificate. Confirm the conversation fully parses all fields without truncation.
- Add multiple categories of metrology documents to the associated knowledge base. Confirm retrieval results cover types such as ledgers, certificates, and interim verification records.
- Verify local LLM model calls function normally. Confirm the model used in the debug preview matches the configured model.
