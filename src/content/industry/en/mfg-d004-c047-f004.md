# Cross-Review of Technical Documents for Measuring Instruments and Laboratory Management: Workflow Orchestration

## What data for this category looks like
Data for this category comes from daily business documents of enterprise metrology rooms and CNAS system laboratories. It includes gauge ledgers, calibration plans, calibration certificates, periodic verification records, original test records, reference material ledgers, and deviation disposition documents. Data sources include internal metrology management systems, external calibration institution certificates, standard instruments, LIMS systems, and environmental monitoring data. Updates are triggered by calibration cycles, single tests, or abnormal events. Most documents use structured formats, with dedicated fields such as gauge number, measurement range, calibration validity period, measurement uncertainty (unit: % or ppm), and test environment parameters.

## What constraints this category's data characteristics impose on workflow orchestration
This category's data characteristics impose core constraints on workflow orchestration. First, multi-source data must be pulled from multiple nodes across sources such as metrology management systems and external calibration certificates. Field matching must be implemented via parameter binding. Second, updates have no fixed cycle. Triggered nodes must be used to avoid unnecessary runs. Third, review processes must link steps such as traceability chains and calibration result verification. Error branches must be configured to handle traceability logic for inaccurate instruments. The system must also adapt to the dedicated field formats of different documents to avoid missing critical information.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Mode | Trigger via document update markers in `variables` | Data updates have no fixed cycle. Triggering based on actual document changes is more precise, and this aligns with the parameter binding features of FastGPT v4.17.0 |
| Node Timeout | 600 seconds | Pulling calibration certificates requires calls to external institution interfaces. Sufficient response time must be reserved |
| Field Binding | Associate document fields corresponding to `nodeId` | Match the dedicated field formats of gauge ledgers and calibration certificates to avoid parameter transfer errors |
| Single Pull Limit | Top 20 entries | Control the volume of data processed in a single workflow run to avoid timeouts or excessive resource usage |
| Context Window | 1500–2000 characters | Adapt to the field lengths of calibration certificates and original records to avoid truncating critical information |
| Error Branch | Trigger alert node | Errors have serious consequences. Corresponding management personnel must be notified promptly |

## Three Common Mistakes
- An error occurs when opening the workflow after local deployment: Cannot read properties of undefined (reading 'incl'). This happens because reference fields in `variables` are not configured correctly, leading to empty parameter transfer between nodes.
- An input error occurs when creating a plugin, then referencing the plugin in another workflow and connecting a code run step. This happens because the dedicated field format of calibration certificates is not matched, and plugin input parameters are not bound to data sources corresponding to `nodeId`.
- The number of results returned after workflow execution is abnormal. This happens because the single pull limit is set too small, failing to cover all calibration plan documents awaiting review.

## How to Verify Correct Configuration
- Upload a simulated calibration certificate and gauge ledger, then trigger workflow execution. Check whether each node pulls the corresponding data normally.
- View workflow run logs to confirm that `variables` parameters are correctly bound to the dedicated fields of the target document.
- Trigger an exception branch test to confirm that the alert node activates normally and generates prompts.
- Compare review results with original document content to confirm that no critical fields are truncated or omitted.
