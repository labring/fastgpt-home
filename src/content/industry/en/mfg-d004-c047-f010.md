# Cross-Review of Technical Documents for Measuring Instruments and Laboratory Management: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Data for this category comes from daily business documents of enterprise metrology rooms, quality laboratories, and China National Accreditation Service for Conformity Assessment system laboratories. The documents include measuring tool ledgers, calibration plans, calibration certificates, interim check records, original test records, reference material ledgers, and deviation handling documents.
Data sources cover metrology management systems, external calibration institution certificates, standard instruments, Laboratory Information Management System (LIMS) platforms, and environmental monitoring data. Updates are triggered by calibration cycles, completion of single tests, or abnormal events.
Document structures include fixed fields: unique instrument identifier, calibration date, validity period, measurement uncertainty, traceable standard instrument number, with corresponding physical units such as millimeters, pascals, kilograms, and others.

## Constraints Imposed on Knowledge Base Retrieval and Recall
The dispersed sources of data for this category require retrieval to support simultaneous access to multiple data sources. Uncertain update frequencies require the recall mechanism to support incremental synchronization, not full reindexing. The strong association between fixed fields and physical units requires precise matching of field keywords, not generalized full-text matching. The binding requirement for traceability chains and associated records requires recall results to include reference paths for complete associated documents. Mixed storage of multi-format documents requires unified chunking rules to ensure consistent retrieval granularity, preventing key parameters from being split and lost.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Matches the field precision requirements for high-precision measurement parameters in this category, and adapts to the retrieval threshold rules of FastGPT v4.17.0 |
| `limit` | Top 6–8 entries | Covers associated information across multiple document types including calibration certificates and interim check records, preventing key traceability chain details from being omitted in single results |
| `searchMode` | `mixedRecall` | Balances precise field matching and full-text fuzzy retrieval, adapting to the retrieval needs of this category’s fixed fields and mixed-format documents |
| `usingReRank` | Enabled | Re-ranks initial recall results by relevance, ensuring core parameters such as measurement uncertainty and calibration validity period are returned first |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands retrieval keywords to cover synonyms and abbreviations for specialized fields such as instrument numbers and traceable standard instrument numbers |
| `collectionIds` | Specified by business grouping | Isolates measuring instrument data from other business data, preventing cross-category documents from interfering with retrieval results |

## Three Common Mistakes
-  Symptom: Reference fields returned by the API are empty, and specific information from calibration certificates or measuring tool ledgers is not displayed. Cause: `datasetSearchUsingExtensionQuery` is not enabled, so specialized retrieval fields such as instrument numbers and traceable standard instrument numbers cannot be covered, leading to failure to match associated documents.
-  Symptom: Retrieval results include non-metrological production process documents, which interfere with core judgments for cross-review of technical documents. Cause: A dedicated metrological knowledge base collection is not specified via `collectionIds`, resulting in mixed document data from other business categories.
-  Symptom: Calibration validity period information returned by the AI does not match the latest ledger, and recent calibration updates are not synchronized. Cause: Incremental updates triggered by calibration cycles are not configured, and only full update mechanisms are relied on, so latest business data cannot be obtained in a timely manner.

## How to Confirm Configuration is Correct
-  Call the test API, check if the returned reference fields include specific content from calibration certificates and measuring tool ledgers, and verify that the `similarity` threshold meets the precision requirements of the current retrieval.
-  Check the number of retrieval results, confirm that the `limit` value covers at least 3 document types to meet the retrieval needs of traceability chain association.
-  Verify that after uploading a new calibration certificate, retrieval can quickly match the document, confirming that the incremental update mechanism is operating normally.
-  Check the sorting of retrieval results, confirm that after `usingReRank` is enabled, documents related to core measurement parameters are displayed first.

The values provided are common starting points and should be measured against the reader's own samples.
