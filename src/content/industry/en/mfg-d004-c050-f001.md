# Cross-Review of Technical Documentation for General Mechanical Equipment Assembly: HTTP Interfaces and External Systems

## What the Data for This Category Looks Like
Daily documentation for general mechanical equipment assembly includes assembly process cards, BOMs, torque records, gap adjustment records, commissioning reports, factory inspection sheets, and packing lists. Typical data sources include PLM/ERP, part inspection data, assembly tool collection devices, test benches, MES systems, and customer technical agreements. Data updates occur once per device or per order. Individual documents contain structured fields such as device model, order number, material code, torque value (unit: N·m), gap value (unit: mm), and coaxiality tolerance. Some documents include unstructured assembly step descriptions and test photos.

## Constraints Imposed on HTTP Interfaces and External Systems
Dispersed multi-source data requires interfaces to pull data across systems, and support authentication and data format compatibility for different external systems. The once-per-device or once-per-order update rhythm requires interfaces to locate data precisely via device ID or order number, to avoid pulling redundant historical documents. Structured fields have specific unit requirements, so configure strict field mapping rules in interface settings to prevent verification failures from unit mismatches. The need to check multi-level BOMs and physical material availability requires interfaces to return hierarchical BOM data structures, to enable layer-by-layer checking of material matching status.

## Configuration Settings
This configuration is adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| API request timeout | 600 seconds | Adapt to the time consumption requirements of multi-source data pulling, avoid request interruptions caused by large data volumes |
| `Authorization` | Bearer {fixed token} | Comply with common external system interface authentication standards, ensure data access security |
| `responseData` field filtering | Only return assembly process cards, BOMs, torque records, gap adjustment records | Reduce invalid data transmission and improve interface response speed |
| Single interface return limit | Top 20 entries | Match the conventional number of documents associated with a single device, avoid excessive data return that occupies resources |
| `variables` incoming parameters | Include device model, order number | Precisely locate exclusive document data for the corresponding device or order |
| Interface retry count | 3 times | Address scenarios of temporary network fluctuations or short response delays from external systems |

## Three Common Misconfigurations
- Failing to pass the correct appId parameter when calling the `/api/v1/chat/completions` interface causes failure to associate assembly documents from the corresponding knowledge base. This occurs because the device ID or order number is not bound to the appId configuration according to the single-device or single-order requirements of this category, and only the default global configuration is used.
- Skipping unit verification for torque record fields returned by the interface leads to errors where torque value units do not match local verification rules. This occurs because no unit mapping rules are specified in the interface configuration, raw data returned by external systems is used directly, and no unified conversion to the standard N·m unit is performed.
- Interface requests exceeding the preset timeout return a 504 status code. This occurs because no reasonable timeout is set, no retry mechanism is configured, and the time consumption requirements of multi-source data pulling cannot be met.

## How to Confirm Successful Configuration
- Call the configured interface, pass test device model and order number, and check if returned document fields include core content such as BOMs, torque records, and gap adjustment records.
- Review interface authentication logs, confirm that the `Authorization` header format is correct, and no 401 authentication failure errors appear.
- Trigger a cross-review process, check if assembly process cards and factory inspection sheet data for the corresponding device can be pulled, and automatic multi-level BOM checking is completed.
- Simulate temporary network interruptions, check if the interface triggers the retry mechanism, and no direct request failure errors appear.

The values provided here are common starting points, and should be validated against local deployment samples.
