# Cross-Review of Technical Documentation for General Mechanical Equipment Assembly: Citation Sources and Traceability

## What Data for This Category Looks Like
Core data for general mechanical equipment assembly originates from PLM/ERP systems, part inspection datasets, assembly tool collection systems, test benches, MES, and customer technical agreements. Daily documentation covers assembly process cards, BOMs, torque records, clearance adjustment records, commissioning reports, factory inspection sheets, and packing lists. Each set of documentation is updated per device or per order. Document fields include material codes, torque values, coaxiality measurements, preload force units (N·m), and additional fields. Field structures vary significantly across different document types.

## Constraints on Citation Sources and Traceability
Dispersed multi-source data requires association with unique identifiers across different systems. This ensures precise matching to corresponding documents during traceability. Update frequency requirements per order or device mean traceability logic must dynamically bind to current business context. Global fixed knowledge bases cannot support this use case. Diverse document types and differentiated field structures demand that citation rules be configured per document type. This avoids confusion over the meaning of different fields. Additionally, the high risk of assembly errors requires accurate traceability results. Strict association must be maintained between physical equipment and corresponding documentation.

## Configuration Settings
For general mechanical equipment assembly scenarios, core configurations must be adjusted to match category characteristics. Three parameters require special alignment with business requirements: `quoteMaxToken`, `responseData`, and `detail`. The following configuration guidelines apply:

| Configuration Item | Recommended Setting Range | Rationale |
| --- | --- | --- |
| Maximum context token count | 8000–12000 token | Adapts to the long-text characteristics of assembly documentation, prevents truncation of critical content such as BOMs and process parameters |
| Chunk length | 300–500 characters | Balances document completeness and recall accuracy, avoids overly fragmented or overly long single chunks |
| Single search limit | Top 6 results | Covers core assembly documentation for a single device, avoids interference from redundant information during cross-review |
| Cache validity period | 24 hours | Aligns with the update frequency per order, ensures recalled documentation is the latest version for the current order |
| Citation source return toggle | Enabled | Requires binding of PLM/ERP sourceid to document fields, ensures traceability is available |
| Detail display toggle | Configured per document type | Torque records must display torque values and tightening time; BOMs must display material codes and quantities. Adapts to field requirements of different document types |

## Three Common Configuration Errors
- Symptom: Some queries fail to retrieve matching assembly documentation, with empty recall results. Cause: Rules for associating data sources with order IDs are not configured. Only global knowledge bases are used for retrieval, which cannot match exclusive documentation for the current device.
- Symptom: Cited documentation in the context cannot be rendered as Markdown format, only plain text chunked content is displayed. Cause: Document format markers are not retained during knowledge base chunking. This prevents restoration of the original document formatting during citation.
- Symptom: Returned citation results do not include the sourceid field, making traceability to the original documentation impossible. Cause: The citation source return configuration is not enabled. Database fields are not bound to document metadata, leading to missing traceability information.

## How to Verify Proper Configuration
1. Upload exclusive documentation for a single device, such as assembly process cards and BOMs. Launch queries that include material codes or torque values. Confirm that recall results include documentation for the current order.
2. Review the metadata section of returned results. Verify that the sourceid field is present, and can be linked to the originally uploaded documentation.
3. Check cited document fragments. Confirm that formatting matches the original Markdown documentation, with no plain text garbling or missing markers.
4. Adjust the maximum context token count to different ranges. Verify recall completeness for long documents, and confirm no critical content is truncated.

The values provided here are common starting points. They should be evaluated against the reader's own samples.
