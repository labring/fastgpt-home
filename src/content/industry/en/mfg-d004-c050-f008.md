# Cross-Review of Technical Documents for General Mechanical Equipment Assembly: Document Parsing and Chunking

## What the data for this category looks like
Daily documents for the general mechanical equipment assembly category include assembly process cards, BOMs, torque records, gap adjustment records, commissioning reports, factory inspection sheets, and packing lists. Data sources include PLM/ERP systems, part inspection data, assembly tool collection terminals, test benches, MES systems, and customer technical agreements. Update frequency is once per device or per order. Document structures vary significantly: BOMs include hierarchical material codes and quantities, process cards include step-by-step operation requirements, torque records include torque values with units, and most document formats are exported from internal systems.

## What constraints do these characteristics impose on the document parsing and chunking link
The document characteristics of this category impose multiple constraints on the parsing and chunking process. First, differences in structure across multiple document types require chunking rules to adapt to each document’s logical units, avoiding splits that break process steps or BOM hierarchies. Second, the high update frequency per order or device requires the parsing process to support batch processing and rapid iteration. Third, non-standard formats from multiple sources require the parsing link to support custom rules for matching structured fields, such as material codes, torque values with units, and similar fields. Fourth, the need to review multiple associated documents requires chunk results to retain cross-document relationships to facilitate cross-checking.

## How to configure settings
This guide is written based on the configuration logic of FastGPT v4.17.0. Specific configuration items and recommendations are as follows:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the length of single steps in assembly process cards and hierarchical nodes in BOMs, avoiding splits that break process logic |
| `chunkSplitter` | Split by paragraph + heading | Adapts to structural differences across multiple document types, preserving the integrity of process steps and BOM hierarchies |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 seconds | Adapts to parsing time for single devices associated with multiple documents, avoiding task interruptions due to timeouts |
| `customPdfParse` | Enabled | Supports extracting structured fields from standardized PDF documents exported from PLM, such as material codes and quantities in BOMs |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Adapts to the need to upload multi-document packages for bulk assembly orders |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for different document types such as process cards, BOMs, and inspection sheets, adapting to specific scenarios |

## Three common configuration errors
- A timeout error with status code 504 is returned after calling the parsing interface. The cause is failure to adjust the `PARSE_FILE_TIMEOUT_SECONDS` parameter. The default configured duration is insufficient for parsing tasks associated with multiple documents per device.
- Parsing results are empty or have missing fields after enabling document parsing enhancement features. The cause is failure to adapt to encrypted PDF formats exported from PLM, or failure to configure custom parsing rules to match structured fields. This prevents extraction of key information from BOMs and torque records.
- The file parsing tool fails during a conversation, and uploaded assembly documents cannot be associated. The cause is failure to enable `customPdfParse` in the knowledge base configuration. This prevents the tool from recognizing structured assembly documents, and only plain text formats can be processed.

## How to confirm successful configuration
- Upload a typical assembly BOM document, and check if the parsing result retains the integrity of structured fields such as material codes and quantities.
- View the background logs of the parsing task, and confirm that parsing time falls within the range configured for `PARSE_FILE_TIMEOUT_SECONDS`, with no timeout interruptions.
- Test calling the parsing interface, and verify that the returned chunked results do not break process steps or BOM hierarchies.
- Trigger the file parsing tool in a conversation scenario, and confirm that uploaded assembly documents can be loaded normally and associated retrieval can be completed.
