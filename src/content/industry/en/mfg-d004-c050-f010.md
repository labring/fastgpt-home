# Cross-Review of Technical Documentation for General Mechanical Equipment Assembly: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Business data for general mechanical equipment assembly originates from PLM/ERP, part inspection data, assembly tool collection systems, test benches, MES, and customer technical agreements. Daily generated documents include assembly process cards, multi-level BOMs, torque records, clearance adjustment records, commissioning reports, factory inspection sheets, and packing lists. Data is updated once per device or order. Document fields include structured fields such as material code, torque value (N·m), clearance value (mm), and usage location, as well as unstructured content such as assembly schematics and test curves.

## Constraints on Knowledge Base Retrieval and Recall
The multi-order, per-unit update data characteristics of this category require knowledge base retrieval to support targeted recall by order or device ID. The combination of multi-level BOMs and multiple document types requires retrieval to adapt to structured tables, numeric records, and text-image mixed documents. The diversity of professional terminology, such as synonymous terms for reducers and gearboxes, requires retrieval to support terminology expansion. Frequent per-unit updates require recall to support incremental synchronization, avoiding delays from full reindexing. In addition, the precise matching requirements for numeric fields such as torque and clearance require adding numeric range filtering constraints, distinct from general semantic retrieval.

## Configuration Recommendations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Adapts to precise matching of numeric fields such as torque and clearance, filters low-relevance semantic results |
| `limit` | Top 10 entries | Adapts to the number of associated documents per single device, avoids context overload that reduces review efficiency |
| `searchMode` | Full-text retrieval + structured retrieval | Covers both text content of assembly process cards and structured tabular data from BOMs and inspection sheets |
| `usingReRank` | Enabled | Performs secondary ranking on initial recall results, optimizes matching accuracy for multimodal documents such as assembly schematics |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands associated professional terminology, such as linking "reducer" to "transmission mechanism" and "gearbox", to adapt to terminology diversity in assembly scenarios |

## Three Common Configuration Errors
- Retrieval results do not include uploaded assembly schematic images, only displaying text annotations. This occurs when multimodal retrieval configuration is not enabled, or when images are not embedded in documents with professional annotations.
- When searching for Excel BOM data with "usage location as foreign country", the number of valid returned results is far fewer than matching entries in the source file. This occurs when structured data field filtering rules are not configured, or when matching conditions for the "usage location" field are not specified during retrieval.
- An Error: write EPROT error is returned when calling the HTTPS interface of a custom system. This occurs when HTTPS two-way authentication is not configured correctly, or the request timeout threshold does not comply with FastGPT v4.17.0 default rules.

## How to Verify Proper Configuration
- Upload a test document containing an assembly schematic, BOM table, and torque records, initiate a search for "pump assembly process requirements", confirm that results include image previews and table fragments.
- Import an Excel BOM document containing a "usage location" field, initiate a search for "assembly lists with usage location as EU", verify that the number of returned results matches matching entries in the source file.
- Use the FastGPT v4.17.0 API debugging tool, call the knowledge base retrieval interface, confirm that the returned `similarity` value falls within the 0.75–0.85 range, and the number of results matches the `limit` setting.
- Initiate a search using professional terminology such as "reducer coaxiality adjustment records", confirm that results automatically link to relevant gearbox documents, verifying that the `datasetSearchUsingExtensionQuery` configuration is active.
