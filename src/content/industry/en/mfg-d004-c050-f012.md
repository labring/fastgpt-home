# Cross-Review of Technical Documentation for General Mechanical Equipment Assembly: Deployment and Upgrade

## What Data Looks Like for This Category
General mechanical equipment assembly-related data typically comes from PLM/ERP, parts inspection systems, assembly tool collection terminals, test benches, MES, and customer technical agreements. Daily documents include assembly process cards, multi-level BOMs, torque records, gap adjustment records, commissioning reports, factory inspection sheets, and packing lists. Data is updated once per device or order. Data fields include component numbers, torque values, gap parameters, coaxiality indicators, inspection results, and some parameters have clear physical units.

## Constraints Imposed on Deployment and Upgrade
Data sources for this category are scattered, and update frequency is high. During deployment, teams must adapt to access requirements for multi-source heterogeneous documents, and configure corresponding storage parameters to support multi-format documents exported by PLM, MES, and other systems. Each individual device corresponds to a separate document set, so the upgrade phase must ensure the accuracy of knowledge base incremental synchronization. This avoids excessive enterprise intranet resource usage from full synchronization. Multi-level BOMs have high field complexity, so sufficient text processing space must be reserved to prevent truncation of key component parameters and associated information during chunking.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `STORAGE_S3_ENDPOINT` | Configure as the access address for the enterprise's internal PLM/MES document storage | Adapt to the multi-source heterogeneous document storage sources of this category, and ensure normal retrieval of documents such as assembly process cards and BOMs |
| `REDIS_URL` | Point to an enterprise intranet-exclusive Redis instance with a memory quota of no less than 1000 MB | Support high-frequency document retrieval caching, and adapt to the data synchronization rhythm updated per order |
| `DB_MAX_LINK` | Set to `80–120` | Match the connection requirements for parallel access by multiple systems, and avoid document retrieval failures due to insufficient connection count |
| `FILE_TOKEN_KEY` | Configure as the encryption key consistent with the enterprise's document storage system | Ensure access security for sensitive documents such as assembly records and inspection sheets |
| `PG_URL` | Point to a dedicated PostgreSQL instance storing structured assembly data | Adapt to the document storage requirements of this category, which include structured fields such as component numbers and torque values |
| `ROOT_KEY` | Set to a random string with a complexity of no less than 16 characters | Ensure access security for system background configurations, and prevent unauthorized modifications |

## Three Common Issues
- Phenomenon: Image pull timeout or 404 error. Cause: The enterprise intranet image acceleration address is not configured, or the storage permissions pointed to by the `STORAGE_S3_ENDPOINT` parameter are not correctly configured.
- Phenomenon: Voice playback function malfunctions after upgrading to FastGPT v4.8.14-fix, while the Whisper function operates normally. Cause: The voice plugin dependency package was not updated synchronously during the upgrade process, leading to incompatibility with the existing deployment environment.
- Phenomenon: Knowledge base retrieval results deviate significantly from actual document content. Cause: Configuration adjustments were not made for the field characteristics of multi-level BOMs, leading to truncation of key component numbers and parameter association information during text chunking.

## How to Verify Proper Configuration
- Perform a single document pull test: Export an assembly process card from the PLM system, and verify that the FastGPT v4.17.0 system can normally read and index fields such as torque values and gap parameters within it.
- Check database connection monitoring in the system background, and confirm that the `DB_MAX_LINK` configuration does not trigger a connection count over-limit alert.
- Log in to the system background to check storage connection status, and verify that the `STORAGE_S3_ENDPOINT` configuration can normally access the enterprise document storage repository.
- Trigger an incremental synchronization task, and confirm that only the document set corresponding to the current order is updated, with no full synchronization operation triggered.

The values provided are common starting points and should be measured against the reader's own samples.
