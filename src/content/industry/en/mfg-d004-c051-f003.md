# Cross-Review of Technical Documentation for Metal Cutting Machining: Multi-Turn Dialogue and Prompts

## What the data for this category looks like
Metal cutting machining business data covers the full workflow of a machining workshop. Daily documents include process routes, operation cards, tool lists, CNC programs, first-piece inspection records, patrol inspection forms, and measuring tool calibration records. Data sources include product drawings and 3D models, CAPP/CAM systems, machine tool collection terminals, tool management systems, MES systems, and measuring and inspection tool data terminals. Data updates trigger when work orders, single-piece machining, spot checks, or tool changes take place. Individual documents contain fields such as operation number, G-code, tool diameter, feed rate, and dimensional tolerances. Most units are machining-specific units like millimeters, revolutions per minute, and hours.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Multi-type, high-update-frequency business data requires dialogue to accurately match exclusive documents for the current work order, to avoid mixing data across work orders. Field differences across multi-source data require prompts to clearly distinguish between document types such as process parameters, CNC codes, and inspection records, to prevent field matching errors. Frequently updated data requires limiting context length to avoid interference from redundant historical data during the current review. Additionally, errors during machining directly affect the rigor of review results. Dialogue must gradually guide users to provide complete process and inspection information to avoid missing key verification items.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Maximum context length | 8000–12000 token | Adapts to the character length of single metal cutting machining documents, and retains process parameters and inspection records for multi-turn dialogue |
| `variables` | Inject work order ID, tool number | Associates exclusive document data for the corresponding work order, avoiding retrieval of process records from unrelated work orders |
| `chatId` | Bind the unique identifier of the current work order | Distinguishes dialogue contexts for different work orders, ensuring persistent association between logs and session data |
| `messages` | Retain the last 10 turns of dialogue | Avoids interference from excessive historical machining document data during the current review |
| Question optimization | Calibrate based on actual measurements | Adapts to field extraction requirements for multiple types of machining documents, avoiding matching deviations caused by generalized questioning |
| Maximum matched documents per request | Top 3 | Focuses on core documents for the current review, avoiding processing delays caused by overload |

## Three common configuration mistakes
- Phenomenon: Dialogue logs have no records or are automatically cleared. Cause: The `chatId` parameter is not bound. The system cannot persist session-associated data, so logs fail to save normally.
- Phenomenon: The workflow interrupts after reaching the AI dialogue step, with no error prompt. Cause: The exclusive identifier of the current work order is not injected via `variables`. The system cannot retrieve corresponding operation cards, CNC programs, and other data, so the process terminates.
- Phenomenon: Streaming output has excessive delay or no segmented returns. Cause: A reasonable context truncation threshold is not set. The system processes too much historical dialogue data, so it cannot return streaming segments in a timely manner.

## How to confirm the configuration is correctly set
- Use FastGPT v4.17.0, initiate a dialogue by binding a work order ID, and check whether a dedicated record for the corresponding `chatId` exists in the session list.
- Inject the tool number variable, initiate the query "Check the calibration records for the current tool", and check whether the retrieval results include measuring tool calibration data for the corresponding tool.
- Trigger the streaming output function, check whether content is returned in character-by-character segments, with no overall delay or stuttering.
- Initiate a multi-turn dialogue: first ask about the clamping plan for the current operation, then ask about the compliance of the corresponding CNC program, and check whether the system retains the previous round's operation information for cross-verification.
