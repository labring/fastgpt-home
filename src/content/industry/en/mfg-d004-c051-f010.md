# Cross-Review of Technical Documentation for Metal Cutting Machining: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Business data for metal cutting machining comes from product drawings and 3D models, CAPP/CAM systems, machine tool collection terminals, tool management systems, MES systems, and measurement and inspection tool data. Daily generated documents include process routes, operation cards, tool lists, CNC programs, first-piece inspection records, patrol inspection forms, and measuring tool calibration records.
Data updates trigger with each work order, each workpiece machining, sampling inspection result, and tool change. Document fields include tool diameter, cutting speed, feed rate, tolerance values, and more. Common units are mm, m/min, and mm/r.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link
Data sources are scattered and update frequency is high. The knowledge base must support high-frequency incremental synchronization to avoid recalling outdated process or inspection records.
Document types cover structured parameters, code-based CNC programs, and unstructured patrol inspection records. Retrieval must balance keyword matching (for example, tool model) and semantic understanding (for example, clamping schemes).
Specific unit requirements for fields require matching unit-associated parameters during retrieval. Otherwise, irrelevant content will be recalled.
Documents for core business links must be recalled preferentially. Precise recall weights need to be configured.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale for This Value |
| ---- | ---- | ---- |
| `similarity` | 0.75-0.85 | Matches the parameter rigor of metal cutting documents, filters low-relevance non-process content |
| `limit` | Top 10 entries | Covers reference documents for core process links, avoids excessive redundant data occupying context |
| `searchMode` | `mixedRecall` | Balances model keyword matching for CNC programs and semantic logic understanding for operation cards |
| `usingReRank` | Enabled | Re-sorts recall results, prioritizes display of core business documents such as clamping schemes and CNC programs |
| `datasetSearchUsingExtensionQuery` | Enabled | Expands user search terms, adds business-specific keywords such as tool models and operation numbers |
| `collectionIds` | Bound to exclusive IDs for corresponding workshops | Limits retrieval scope, prevents irrelevant documents from cross-workshop recall |

## Three Common Misconfigurations
- Phenomenon: Retrieval results do not match the content of process documents in the knowledge base. Old version operation card parameters are returned. Cause: `datasetSearchUsingExtensionQuery` is not enabled, and the `similarity` threshold is set below 0.7. Outdated old documents are recalled.
- Phenomenon: Calling the knowledge base retrieval interface returns empty results with no matching content. Cause: `collectionIds` is not configured. The retrieval scope covers irrelevant non-metal cutting knowledge base collections.
- Phenomenon: Retrieval response times out, or the number of returned results is much lower than expected. Cause: `limit` is set to more than the top 20 entries, and `usingReRank` is not enabled. A large number of low-relevance documents are loaded and processed.

## How to Confirm Proper Configuration
- Upload a test CNC program document. Use the search keyword "T10 tool cutting parameters". Check whether the recalled results include core parameters such as cutting speed and feed rate of this document.
- Check the `usingReRank` switch status. Confirm whether the sorting of retrieval results places core business documents such as clamping schemes and CNC programs at the top.
- Check the FastGPT v4.17.0 knowledge base synchronization log. Confirm that the data update frequency matches the trigger rhythm of work orders and tool changes.
- Call the interface with the specified `collectionIds`. Verify that returned results only come from the knowledge base collection of the target workshop, with no cross-workshop irrelevant content.

The values given are common starting points and should be measured against the reader's own samples.
