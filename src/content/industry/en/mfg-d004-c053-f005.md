# Cross-Review of Technical Documentation for Iron and Steel Smelting and Continuous Casting: Tool Calling and Plugins

## What the Data for This Category Looks Like
Daily documents for this category include heat plans, batching lists, converter smelting records, composition reports, continuous casting process records, and slab judgment sheets. Data sources cover hot metal and scrap data, L2 process control systems, laboratories, MES, energy medium systems, and equipment status. Data update frequencies are per heat, real-time, and per shift. Documents use heat numbers and cast numbers as core association fields. Composition reports include element content values. Smelting records include unit-bearing parameters such as furnace temperature and blowing duration. Slab judgment sheets include defect levels and judgment results.

## What Constraints These Characteristics Impose on Tool Calling and Plugins
Multi-source heterogeneous data sources require tool calling to adapt to interface formats and permission rules of different systems. Real-time and per-heat update frequencies require tool calls to be triggered by heat nodes to avoid delayed or redundant execution. Diverse document structures and fields require tools to support associating cross-document data by heat number, to ensure relevance for cross-review. The high-temperature continuous production process requires that tool calls do not experience long blocking periods. Long blocking could lead to serious outcomes including continuous casting interruptions.

## How to Configure

| --- | --- | --- |
| Workflow/API tool selection | `auto` | Automatically select the most matching tool to adapt to cross-review needs for multiple types of technical documents |
| Workflow/API function-call configuration | `enabled` | Force enable structured tool calling to match the field verification and association logic of technical documents |
| Tool call trigger timing | After each heat is completed, before each shift handover | Matches the heat plan and shift handover data update rhythm for this category |
| Failure retry count | 2 | Balances real-time performance and data accuracy, prevents review interruptions from temporary network fluctuations |
| Timeout threshold | 600 seconds | Adapts to the time limit for pulling data from multiple sources and parsing documents |
| Multi-document association rule | Associate by heat number | Documents in this category use heat numbers as core association fields to ensure accuracy of cross-review |

## Three Common Misconfigurations
- Symptom: Tool calls return empty results, and workflow logs display "No matching data". Cause: The rule for associating documents by heat number is not configured, and global matching logic is used incorrectly, which cannot associate cross-system review data.
- Symptom: Tools are not triggered for execution, and workflow status shows "Tool not called". Cause: The `functionCall` configuration item is not enabled, so the system does not trigger the necessary logic for structured tool calling.
- Symptom: Custom tool calls return an error message "Parameter format error" with status code 400. Cause: The standard parameter format for `toolChoice` is not followed, and unofficial channel configuration rules are used incorrectly, leading to call failure.

## How to Confirm Configuration Is Complete
- Trigger a review task after a heat is completed, check the tool call logs to confirm that the `toolChoice` parameter is set to `auto` and `functionCall` is enabled.
- Review the tool call return results to confirm that associated data for heat plans, smelting records, and continuous casting process records is included, and aggregated by heat number.
- Simulate a temporary network interruption to check if the system triggers the failure retry mechanism, with retry times matching the configured 2 attempts.
- Verify cross-knowledge base result filtering logic, confirm that only review data matching the current heat number is retained, with no redundant irrelevant content.
