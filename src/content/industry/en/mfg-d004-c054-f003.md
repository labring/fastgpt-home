# Cross-Review of Technical Documents for Sheet Metal Cutting and Bending: Multi-Turn Dialogue and Prompt Engineering

## What Data Looks Like for This Category
Data for this category primarily comes from CAD/CAM software, order BOM systems, sheet metal inventory ledgers, laser cutter and bending machine equipment logs, and workshop MES systems. Daily produced documents include 3D part unfolding drawings, CNC cutting programs, bending process cards, nesting diagrams, first-piece inspection records, and process transfer cards. Data updates are triggered by order creation, daily inventory checks, and production changeovers. Document fields include bending compensation amount, sheet thickness, cutting size, bending angle, and more. Units are mostly millimeters and degrees of angle.

## Constraints Imposed on Multi-Turn Dialogue and Prompt Engineering
The high-frequency update nature of this category requires that dialogue contexts not retain historical records for too long, to avoid introducing expired sheet metal inventory or process parameters. The coexistence of multiple document types requires prompts to clearly distinguish review logic for different documents such as unfolding drawings and process cards, to avoid confusing field meanings. Individual fields with dedicated units require mandatory unit matching rules in prompts, to prevent errors caused by inconsistent size units. Parallel processing of multiple orders requires isolating contexts for different sessions via `chatId`, to avoid data crossover.

## Configuration Guidelines
This configuration guide is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context entries | Previous 3–5 turns of dialogue history | This category has frequent data updates, and overly long contexts are prone to introducing expired sheet metal inventory or process parameters |
| `chatId` binding rule | Bind to order number + process number | Parallel processing of multiple orders requires isolating session contexts to avoid data crossover |
| `variables` preset | Preset bending compensation coefficient (0.8–1.2 mm), sheet thickness range | Document fields for this category are fixed and require matching dedicated units, reducing repeated input |
| `messages` cleanup rule | Triggered when new attachments are uploaded or a changeover command is detected | Data updates occur with production changeovers and new order creation, requiring timely cleanup of expired history |
| Knowledge base reference toggle | Default off, enable as needed | Cross-review of technical documents should focus on documents uploaded in the current session, to avoid recalling redundant historical data |

## Three Common Configuration Mistakes
- Phenomenon: Old sheet metal inventory data remains after context cleanup is triggered in a dialogue. Cause: `chatId` is not correctly bound to the current order, resulting in unisolated session contexts and reading of historical data from other orders.
- Phenomenon: The knowledge base recalls nesting diagrams or process cards not from the current session. Cause: The default knowledge base reference toggle is not turned off, or prompts do not explicitly limit review to only currently uploaded documents.
- Phenomenon: Historically uploaded unfolding drawings are loaded when parsing documents. Cause: The context cleanup rule triggered by new attachment uploads is not configured, causing the system to default to loading all historical documents for associated review.

## How to Verify Successful Configuration
- Upload the bending process card and unfolding drawing for the current order, submit a query that includes size verification, and confirm that the dialogue only recalls content from the currently uploaded documents.
- Switch to the session for another order, confirm that the order number bound to `chatId` is different, and that no context crossover occurs with parameters from the previous order.
- Trigger a changeover command, confirm that the system automatically clears the dialogue history from before the last changeover, and only retains valid content for the current session.
- View the context cleanup rule in the configuration interface, confirm that the trigger condition for new attachment uploads is bound, and that the maximum context entries are set to 3–5.

The values provided are common starting points and should be measured against the reader's own samples.
