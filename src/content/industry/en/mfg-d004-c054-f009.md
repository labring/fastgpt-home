# Cross-Review of Technical Documentation for Sheet Metal Cutting and Bending: Model Access and Configuration

## Data Profile for This Category
Core data for sheet metal cutting and bending scenarios originates from CAD/CAM software, order BOM systems, sheet material inventory ledgers, laser cutting machine and bending machine device logs, and workshop MES systems. Daily generated documents include 3D part unfolding drawings, CNC cutting programs, bending process cards, nesting diagrams, first-piece inspection records, and process flow cards.
Data update frequency adjusts based on order delivery, daily production scheduling, and model changeovers. Document fields include sheet thickness, bending compensation values, cutting dimensions, bending angles, and process flow order numbers. Common units are millimeters, degrees, and kilograms.

## Constraints for Model Access and Configuration
This category uses a high-mix, low-volume production model. It requires model access to support batch parsing of multiple documents and real-time updates. Mixed input of process documents and CAD drawings in varied formats requires configuration to support visual and text hybrid parsing. Frequent order and model changeover data updates require model context to quickly load the latest process parameters. Specific fields such as bending compensation and cutting dimensions require the model to accurately identify industry-specific terminology and units, to avoid deviations from general-purpose parsing.

## Configuration Settings
| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | Supports long-text loading needs for multiple nesting diagrams and bending process cards, prevents parameter omission caused by context truncation |
| `temperature` | `0.1–0.3` | Reduces random output probability, ensures accurate matching of process parameters such as bending compensation values and cutting dimensions |
| `vision` | Enabled | Parses bending annotations and hole position information in 3D part unfolding drawings, meets cross-review requirements for text-based process documents |
| `maxTokens` | `2000–3000 token` | Adapts to the output length of review results for a single process card or nesting diagram, prevents forced truncation of results |
| `AIPROXY_API_ENDPOINT` | Fill in the official access endpoint provided by the corresponding large model service provider | Completes basic network connectivity configuration for the model, ensures normal request sending |
| `AIPROXY_API_TOKEN` | Fill in the exclusive key assigned by the service provider | Completes model identity verification, ensures valid access permissions |

## Three Common Misconfigurations
- Model test error `[] is too short - 'messages'`: The error returns during model test calls. The root cause is missing initial conversation messages or an empty message array, which fails to meet the minimum input format requirements for the model.
- New model configuration fails to display in the interface: After saving configuration changes, no new entry appears in the model list. Restarting the FastGPT service does not resolve the issue. The root cause is incorrect filling of required fields for `AIPROXY_API_TOKEN` or `AIPROXY_API_ENDPOINT`, leading to configuration verification failure and failed storage of the configuration.
- Model review results omit process parameters: The generated cross-review report does not include bending compensation values or nesting allowance information. The root cause is an excessively small `maxContext` setting, which results in insufficient loaded document context to cover all process data for review.

## How to Verify Successful Configuration
This verification process is based on FastGPT v4.17.0.
- Check the filled content for `AIPROXY_API_TOKEN` and `AIPROXY_API_ENDPOINT`. Test connectivity by calling the base model interface to confirm if the configuration takes effect.
- After enabling the `vision` configuration, upload a sheet metal unfolding drawing to verify that the model can identify visual information such as bending angles and hole position annotations, confirming normal operation of the visual parsing function.
- Set `temperature` to `0.2`, input a piece of process card text containing bending compensation values, and verify that the output maintains consistent parameter values, confirming that the temperature parameter configuration meets requirements.
- Import three or more different types of sheet metal documents, verify that `maxContext` can accommodate all loaded document content without obvious context truncation prompts.

The values provided are common starting points and should be measured against the reader's own samples.
