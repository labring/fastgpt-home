# Cross-review of Technical Documentation for Foundry (Sand Casting, Precision Casting, Die Casting): Citation Sources and Traceability

## What the data for this category looks like
Daily documents for this category include foundry process cards, batching lists, heat records, mold history logs, first article inspection records, material test reports, and nonconforming product review forms. Data sources cover ERP material master data, melting furnaces and thermometers, spectrometers, MES heat records, mold management systems, customer drawings, and technical specifications. Data update frequency is per heat, per batch, or daily. Each single record contains precise fields such as alloy batching ratio, melting temperature, pouring parameters, defect type and corresponding heat and mold number. Most fields are structured numerical and numbered content, with no redundant unstructured descriptions.

## Constraints for Citation Sources and Traceability
This category has high data update frequency, scattered sources, and precise fields. Citation traceability must match the latest heat and batch records in real time, and avoid using outdated data. Association across multiple types of documents relies on unique identifiers such as heat and mold numbers. The traceability link must accurately associate corresponding records across systems, and cannot use fuzzy matching logic. Parameters in a single record directly affect product quality. The traceability result must fully retain the field details of the original document to ensure the accuracy of subsequent verification steps. Data sources include production equipment and management systems. The traceability process must support cross-source data pulling to avoid missing key information.

## Configuration Settings
This configuration follows the interface and parameter rules of FastGPT v4.17.0, as detailed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Adapts to the length of single records in foundry documentation, avoids truncating key parameters such as alloy batching ratio and melting temperature |
| `responseData` | Enable traceability identifier switch | Ensures the returned result carries source information of the original document, used to match associated records such as heat and mold numbers |
| `detail` | Full recall mode | Retains all field details of the original document, supports accurate verification of the correspondence between defects and heat numbers |
| Single search limit | Top 6 entries | Covers multiple types of documents related to a single heat, such as process, batching, and inspection documents, avoids missing key sources |
| Maximum context | 600 seconds | Adapts to the time required for cross-system data pulling, avoids traceability failure caused by timeout |

## Three Common Configuration Errors
- Redundant citation links that are not configured appear in responses, and cannot be closed via interface settings. The cause is that the display rules for `responseData` were not configured correctly, and the unadjusted default traceability display logic was enabled.
- The traceability result cannot match the records of the corresponding heat, and only returns vague document categories. The cause is that `detail` was not set to full recall mode, and unique matching fields such as heat number and mold number were truncated.
- Cross-system data pulling times out, causing an error in the traceability link. The cause is that the maximum context setting is too short, and does not cover the actual time required for multi-source data synchronization.

## How to Verify Successful Configuration
- Initiate a query that includes alloy batching ratio and heat number, check whether the returned result carries the source identifier of the original document.
- View the configured value of `quoteMaxToken`, confirm that key parameters of single records are not truncated.
- Test turning off the citation display function, confirm that redundant citation links no longer appear in responses.
- Simulate cross-system data query, verify that no timeout errors occur.

The values provided are common starting points and should be evaluated against the reader's own samples.
