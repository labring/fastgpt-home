# Cross-Review of Technical Documentation for Forging and Die Forging: HTTP Interfaces and External Systems

## What the data for this category looks like
The data for this category primarily comes from raw material quality certificates, heating furnace systems, press collection data, MES systems, non-destructive testing equipment, and customer forging drawings. Daily generated documents include forging process specifications, cutting cards, heating furnace records, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports. Data is updated per piece, per batch, or per furnace run. Fields include forging batch number, furnace batch number, heating temperature, holding time, forging ratio, ultrasonic defect level, and others, with corresponding units such as degrees Celsius, minutes, dimensionless, millimeters.

## What constraints these characteristics impose on HTTP Interfaces and External Systems
Data sources for this category are scattered, involving multiple types of industrial systems and data from digitized paper documents. HTTP interfaces must support authentication and data formats for different external systems. Data is updated per piece, per batch, or per furnace run, so interfaces must support precise queries by furnace batch number and forging batch number to avoid mixing data across batches. Document fields include professional process parameters and test results, so the `responseData` returned by the interface must cover the complete set of fields to support cross-checking logic. Additionally, since the consequences of errors are severe, interfaces must be configured with reasonable timeout periods and error handling logic to prevent abnormal data from entering the review process.

## How to configure
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | `Basic Auth or Bearer Token, configured per external system requirements` | Forging-related external systems such as MES and non-destructive testing equipment mostly use basic authentication or token-based authentication, which aligns with security requirements in industrial scenarios |
| Request timeout | `30–60 seconds` | Industrial data collection and interface responses have delays; this interval covers response durations for most heating furnace and press systems |
| `variables` | `Bind furnace batch number and forging batch number as query variables` | Data for this category is updated per furnace run or batch; precise variables avoid pulling irrelevant data and improve cross-review efficiency |
| `responseData` | `Return fields including heating temperature, holding time, forging ratio, and ultrasonic defect level` | Covers core check fields for forging processes and quality testing, meeting field requirements for cross-review |
| Retry count | `2 times` | Industrial systems experience occasional network fluctuations; a small number of retries reduces interface call failure rates and avoids interrupting the review process |

## Three common mistakes
- Phenomenon: The interface returns a 401 Unauthorized status code, indicating authentication failure. Cause: The `Authorization` parameter is not configured correctly, and the authentication format required by the external system is not matched.
- Phenomenon: In the obtained conversation record list, user questions and AI replies cannot be matched. Cause: No conversation ID or batch identifier is bound in `variables`, causing returned data to not be sorted or grouped by associated dimensions.
- Phenomenon: The interface returns empty data fields, making cross-checking impossible. Cause: Required professional fields are not specified in `responseData`, the external system does not return corresponding data, or incorrect field filtering rules are configured.

## How to confirm the configuration is correct
- Call the interface and view the returned `responseData` to confirm that preset forging process and testing fields are included, and field names and units meet business requirements.
- After configuring the `Authorization` parameter, call the test interface to confirm that the returned status code is 200 OK, with no authentication-related errors.
- Pass test furnace batch numbers and forging batch numbers to confirm that returned data matches business data for the corresponding furnace run.
- Simulate network delay scenarios to confirm that the interface completes responses within the configured timeout period, and can normally obtain data after triggering the retry logic.
