# Cross-Review of Technical Documentation for Forging and Die Forging: Tool Calling and Plugins

## What the data for this category looks like
Core data for forging and die forging scenarios comes from raw material quality certificates, heating furnace systems, press collection data, MES, non-destructive testing instruments, and customer forging drawings. Daily maintained documents include forging process specifications, cutting cards, heating furnace records, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports. Data is updated per forging piece, batch of materials, or furnace charge. Document fields include forging ratio, fiber direction, furnace batch number, forging batch number, heating temperature range, pressure tonnage, and other items, with corresponding units including ℃, MPa, mm, and others.

## What constraints these characteristics impose on the "tool calling and plugins" link
Multiple scattered data sources require tool calling to support integration with various system interfaces to avoid data fragmentation. The high-frequency update rhythm per piece or furnace charge requires tool calling to support real-time or near-real-time data pulling to adapt to batch-level verification needs. Diverse document structures and specific fields require tools to adapt to field parsing logic for different documents, accurately extracting key information such as forging ratio and furnace batch number. Severe consequences of errors require tool calling to include strict parameter verification and result tracing, preventing the risk of forging scrap or batch fracture. Differences from other forming categories require tools to focus on dedicated verification logic for forging ratio and fiber direction.

## Three common mistakes
- Only the Qwen model functions correctly when calling tools; other models return errors. The interface returns the `function call failed` status code, and logs show the model does not support the tool calling format. The cause is that the `functionCall` parameter is not enabled, or a compatible model configuration is not selected.
- Concurrent tool calls occur, returning duplicate forging batch verification results. The phenomenon is that two tool calls are triggered simultaneously for the same batch of forgings, generating duplicate verification records. The cause is that the tool selection is not configured to one-of-two mode, leading to concurrent triggering of the workflow.
- Unable to obtain ultrasonic testing report content after calling the document reading tool. The phenomenon is that the returned document fields are empty, and defect determination results cannot be extracted. The cause is that the context window is set too small, failing to fully load the long document's testing data.

## How to confirm the configuration is complete
- Initiate a test call, input "Check whether the furnace batch number of forgings in batch 202405 matches the raw material quality certificate", and check whether the return includes structured tool calling results.
- Simulate multi-task triggering, confirm that only one tool is called at the same time, and there are no concurrent call records.
- Upload a complete ultrasonic testing report, verify that the tool can extract field content such as defect type and testing date.
- Switch to a non-Qwen model to initiate a call, confirm that there is no `function call failed` error, and the tool call executes normally.

The values provided are common starting points and should be measured against the reader's own samples.
