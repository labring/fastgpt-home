# Cross-Review of Technical Documentation for Forging and Die Forging: Citation Sources and Traceability

## What this category’s data looks like
Data sources for this category include raw material quality certificates, heating furnace systems, press collection data, MES, non-destructive testing instruments, and customer forging drawings. Daily documents cover forging process specifications, cutting cards, heating furnace records, forging process cards, mold life records, heat treatment orders, and ultrasonic testing reports.
Data updates follow a rhythm per piece, batch, or furnace heat. Single documents contain fields such as furnace batch number, forging batch number, forging ratio, fiber direction, heating temperature parameters, and defect test results. Updates only trigger alongside corresponding production processes, with no unified bulk update cycle.

## What constraints these characteristics impose on the citation and traceability link
This category’s data characteristics create multiple constraints for the citation and traceability link. First, data updates are per single furnace heat or batch. Furnace batch number and forging batch number must be accurately bound as unique identifiers. Citations must limit the recall scope to documents from the current production batch to avoid cross-batch confusion. Second, daily documents include specialized fields such as forging ratio and fiber direction. Retrieval rules matching the corresponding business scenario must be used to ensure recalled content is highly relevant to the current process or testing review needs. Third, data sources are scattered across multiple systems. Traceability requires associating unique identifiers of multi-source data. The citation module must accurately associate associated fields across documents from different sources to prevent breaks in traceability information.

## Three common errors
- Directly entering a knowledge base ID or citation variable results in no difference in output content, and an error is triggered when applying the variable to associate the knowledge base. The cause is that variable filtering rules are not configured according to the unique identifier of the forging batch, so the variable is not bound to the knowledge base scope of the corresponding production batch.
- Attempting to directly reference forging batch information from historical conversations fails to work normally, making it impossible to associate previous process records during traceability. The cause is that the historical context call switch is not enabled, or field filtering rules for historical conversations are not configured.
- Adjusting the similarity threshold to the minimum and the single search limit to the maximum does not change the number of recalled documents, which always remains at a fixed value. The cause is that the recall scope is not limited to current production batch documents, the system recalls full data by default, or the configured retrieval rules do not match the forging-specific furnace batch number field.

## How to confirm the configuration is properly set up
- Upload single furnace heat forging documents, initiate a review request for that furnace batch number, and check whether the recalled documents only include relevant content for that furnace heat.
- View the citation source display area, and confirm whether it includes specialized fields such as furnace batch number and forging batch number, as well as corresponding source system information.
- Adjust the similarity threshold and single search limit, observe whether the number of recalled documents changes with the configuration adjustments to verify that the retrieval rules take effect.
- Test the binding effect of citation variables, confirm that after entering the batch identifier, the system only recalls document content for the corresponding batch.

The values provided are common starting points and should be measured against the reader's own samples.
