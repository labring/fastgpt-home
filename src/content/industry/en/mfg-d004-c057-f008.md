# Cross-Review of Technical Documentation for Forging and Die Forging: Document Parsing and Chunking

## What the data for this category looks like
The daily documents for this category cover multiple types including forging process specifications, cutting cards, heating furnace logs, forging process cards, mold life records, heat treatment work orders, ultrasonic testing reports, and more. Data sources include raw material quality certificates, heating furnace systems, press collection data, MES systems, non-destructive testing instruments, and customer forging drawings. Documents are updated per forging part, batch of materials, or furnace batch, and include dedicated fields with specific units such as forging ratio, furnace batch number, forging batch number, heating zone, and others. Some documents such as ultrasonic testing reports use multi-column layout formats.

## What constraints these characteristics impose on the "document parsing and chunking" link
The mixed multiple document types and significant layout differences for this category impose multiple constraints on the parsing and chunking workflow. Complex layouts of documents such as multi-column ultrasonic testing reports and cutting cards require the parsing engine to support non-standard layout adaptation. The high-frequency update rhythm based on furnace batches and batches requires the parsing process to have stable batch processing capabilities to avoid timeouts or task failures. The strong association between dedicated fields such as forging ratio, furnace batch number, and forging batch number requires retaining context integrity during chunking, to avoid cutting off key associated information and reducing the accuracy of cross-review.

## How to set the configurations
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapt to the text density of forging process specifications and ultrasonic testing reports, retain contextual association for key fields such as forging ratio and furnace batch number |
| `chunkSplitter` | Split by paragraph + table | Adapt to mixed document structures of multi-column tables and process text, avoid splitting that disrupts table content integrity |

| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Adapt to file size limits for single forging process specification collections and multi-batch heat treatment work orders, meet batch upload requirements |
| `chunkSettingMode` | Manual configuration | Adjust chunking parameters separately for different document types to meet precise matching requirements for technical document cross-review |

## Three common errors
- Misaligned table content and lost column data after parsing multi-column ultrasonic testing reports. The `customPdfParse` function is not enabled to adapt to multi-column layouts, and the default parsing engine cannot recognize cross-column table structures, resulting in chaotic parsed content.
- Parsing timeout errors occur when batch uploading heating furnace logs, and the task status shows failure. The `PARSE_FILE_TIMEOUT_SECONDS` setting is too low, failing to adapt to the parsing duration of single multi-furnace batch logs, which exceeds system limits.
- Fields such as forging ratio and heating zone are empty in chunked content after uploading a docx format forging process specification. The `chunkSize` setting is too small, cutting off the contextual paragraph containing key fields during splitting and causing loss of associated information.

## How to confirm the configuration is set correctly
- Upload a typical multi-column ultrasonic testing report, check whether the parsed table maintains column alignment without content misalignment or loss.
- Upload a single heating furnace log collection under 100 MB, confirm that the parsing task completes within the set timeout period without timeout errors.
- Randomly extract text fragments after chunking, verify that key fields such as forging ratio and furnace batch number are fully retained in a single chunk.
- Batch upload 3 to 5 different types of forging documents, confirm that the parsing success rate meets expectations without batch task failures.
