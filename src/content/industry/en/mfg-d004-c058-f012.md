# Cross-Review of Technical Documentation for Precast Concrete Components: Deployment and Upgrade

## What the data for this category looks like
Data for this category originates from BIM detailed design, rebar and concrete batch ledgers, mold table and curing kiln operation logs, laboratory test reports, and QR code traceability systems. Daily documentation includes component detailed drawings, rebar cutting lists, mold inspection forms, pouring and vibration records, curing records, and demolding and factory inspection reports.
Data updates are synchronized for individual components, each batch of materials, and each curing kiln cycle. Fields include component ID, rebar diameter (mm), concrete strength grade (MPa), curing temperature (℃), batch number, and other relevant fields. Supported formats include structured tables and unstructured drawings.

## What constraints these characteristics impose on deployment and upgrades
High-frequency data updates at the individual component, batch, and curing kiln level require deployments to support persistent database storage and high-concurrency read/write operations. Multiple heterogeneous data sources and diverse document formats require configuring import and storage capabilities compatible with both structured tables and unstructured drawings.
Business errors can lead to component scrap or project delays, so upgrades must not lose historical data while maintaining secure permission controls. Multi-account collaborative access requires deployment configurations to support a unified access entry and permission sharing mechanism.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://fastgpt:SecurePass123@mongodb:27017/pc_doc_review?authSource=admin` | Stores structured and unstructured data such as component detailed drawings and inspection records, and adapts to high-frequency read/write requirements |
| `REDIS_URL` | `redis://:CachePass456@redis:6379/1` | Caches frequently queried component ID mappings and batch information to reduce database access latency |
| `STORAGE_S3_ENDPOINT` | `http://internal-storage:9000` | Stores large-volume detailed design drawings and curing record files, and supports multi-format uploads |
| `FE_DOMAIN` | `https://pc-component-review.your-org.com` | Binds a dedicated deployment domain to support multi-account collaborative access to the same knowledge base |
| `ROOT_KEY` | `32-bit random key generated based on actual measurements` | Configures the system's highest privilege credential to ensure the security of operation permissions during deployment and upgrades |
| `DB_MAX_LINK` | `200` | Limits the number of database connections to avoid connection overflow when importing batch component data |

## Three Common Misconfigurations
- Symptom: After executing `docker compose down` and restarting services, component data and knowledge base collections are lost. Cause: The database persistent volume was not mounted, and local container database files were overwritten directly during the upgrade.
- Symptom: Calling the document review interface returns `401 Unauthorized`, and the specified knowledge base collection cannot be accessed. Cause: `ROOT_KEY` or `FILE_TOKEN_KEY` was not configured correctly, causing permission verification to fail.
- Symptom: When importing rebar cutting lists in bulk, only some documents are indexed, and the remaining documents have no search results. Cause: The `DB_MAX_LINK` parameter was not set reasonably, and insufficient connections caused partial data import to be interrupted.

## How to Verify a Successful Configuration
- Execute `docker compose up -d`, then review database and cache container logs to confirm no connection timeout or authentication failure errors appear.
- Upload a precast component detailed drawing, search for the component ID in the knowledge base, and confirm the corresponding document can be retrieved.
- Log in to the system backend, and verify that multiple accounts can simultaneously access the same knowledge base and edit document collections.
- Call the system version interface to confirm the currently running version is FastGPT v4.17.0.

The values provided are common starting points and should be measured against the reader's own samples.
