# Bid Document and Quotation Preparation for PCB Manufacturing: HTTP Interfaces and External Systems

## What This Category of Data Includes
Data is sourced from engineering, production, quality control, and laboratory teams at PCB manufacturing facilities. Daily generated documents include engineering production instructions, Gerber parsing records, drilling and lamination parameters, chemical analysis reports, AOI inspection reports, electrical test reports, and slice inspection reports. Data comes from customer-provided Gerber files, drill files, BOM lists, CAM system data, production equipment parameters, bath test results, data collected from AOI and electrical test equipment, and laboratory test records. Data is updated per production batch, per shift, or via continuous collection.

## Constraints Imposed on HTTP Interfaces and External Systems
Data sources for this category are dispersed, with significant format differences. Supported data types include binary Gerber files, structured parameter tables, and test reports. As a result, HTTP interfaces must support uploading and parsing of multi-format data.
Data updates occur frequently, with continuous collection at the production batch and shift levels. Interfaces must adapt to high-frequency calls and low-latency responses.
Documents contain specialized process parameters such as drilling and lamination settings. Interfaces must support precise field mapping and validation.
Bid quotations must be linked to original materials including customer-provided Gerber and BOM files. Interfaces must support cross-data-source data pulling and association binding.

## Configuration Settings
This configuration is compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer ${custom API_KEY}, rotate every 7 days` | This category of data includes process parameters and customer confidential information. Strict identity verification is required, and regular rotation reduces the risk of data leaks |
| `variables` | `Include three required fields: customer order number, Gerber version number, and production batch number` | Bid quotations must be accurately linked to process and customer materials for the corresponding batch. Required fields filter invalid requests |
| `responseData` | `Return three types of structured fields: quotation details, document generation progress, and exception logs` | External systems need real-time synchronization of bid progress and results. Structured returns simplify parsing and display logic |
| Request timeout | `600 seconds` | Data parsing and quotation generation for a single PCB batch requires processing multiple specialized documents. A longer timeout prevents mid-process interruptions |
| Retry attempts | `Up to 3 times, with a 60-second interval` | Production data collection may experience temporary network fluctuations. Limited retries ensure interface call success rates |
| Callback access restriction | `Allow only factory internal IP ranges` | Interface callbacks contain sensitive production and quotation data. Restricting access sources ensures data security |

## Three Common Misconfigurations
- Symptom: Callback request return fields are empty, and no bid documents or quotation details are included. Cause: The `variables` field does not include the customer order number and production batch number. The interface cannot match the corresponding data to generate results.
- Symptom: The knowledge base collection does not add or delete specified documents after calling the interface. Cause: The `Authorization` parameter is not set correctly, or the key permission does not enable read/write operations for the corresponding collection.
- Symptom: The interface returns a 504 gateway timeout error. Cause: The request timeout is set to less than 600 seconds. Insufficient time is reserved for parsing multiple PCB specialized documents and calculating quotations.

## How to Validate Proper Configuration
- Call the test interface, add the correct `Authorization` parameter to the request header, pass the preset `variables` fields, and check if the returned `responseData` includes the expected structured content.
- After configuring the callback address, trigger a test request and check if the external system receives formatted callback data.
- Review the interface call logs to confirm whether the retry count and timeout settings match the actual business call rhythm.
- Attempt to upload a test document to the corresponding knowledge base collection and confirm that the interface can complete add and delete operations normally.

The configuration values provided here are common starting points. They should be evaluated against the reader's own samples and business requirements.
