# Bid Document and Quotation Preparation for PCB Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data for this category comes from client-provided Gerber files, drill files, and BOM lists, as well as factory-internal CAM systems, production equipment parameters, bath test records, AOI inspection reports, electrical testing reports, and slice reports.
Data updates occur per production batch or per shift. Some equipment parameters are collected continuously.
Daily documents include engineering production instructions, Gerber analysis records, drilling and lamination parameters, and chemical analysis reports.
Fields cover professional parameters such as hole diameter, copper thickness, layer count, and bath concentration.
There is no unified standard format, so separate matching is required for each project.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
Data for this category is scattered and has inconsistent formats. Multi-turn dialogue must gradually guide calls to parameters from different sources to avoid missing key information.
The real-time update nature of data requires dialogue contexts to sync the latest production parameters. This prevents outdated data from being used to generate quotations.
Bid documents must link professional requirements such as electrical connectivity and process compensation. Prompts must match exclusive fields for links like drilling and lamination. Generic business prompt templates cannot be used directly.
Incorrect data will lead to scrapping of entire PCB batches. The dialogue link must add parameter verification logic to ensure input Gerber parameters and bath data are accurate.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | First 20 turns of dialogue or 8000 characters | Retain the complete bidding project parameter inquiry process to avoid loss of key information |
| Variable Binding Scope | Only associate the current project's `variables` | Prevent cross-project data confusion, ensure quotation parameters only come from the current bid's customer information |
| Session Identification Rule | Bind project archives by `chatId` | Manage each bidding project's session independently to prevent cross-item historical dialogue mixing |
| Prompt Delivery Format | Deliver via `messages` array structure | Align with multi-turn dialogue interaction logic, enable the system to parse professional parameters by turn |
| File Upload Size Limit | 1000 MB | Support upload requirements for large business documents such as Gerber files and BOM lists |
| Timeout Threshold | 600 seconds | Support waiting requirements for large Gerber file parsing and multi-parameter calling |

## Three Common Misconfigurations
- Quick buttons for dialogue opening prompts fail to trigger preset questions. Checking the `messages` array shows the initial node is empty. Cause: Preset quick questions are not written into the `messages` array during session initialization, so the system cannot load preset interaction instructions.
- Calling the dialogue API to upload a Gerber file returns status code 400. Cause: The file storage path is not bound to `variables`, so the system cannot recognize uploaded business documents or extract parameters for quotation calculation.
- Historical dialogues of non-logged-in users cannot be retrieved. Entering `chatId` returns no matching records. Cause: The temporary session identifier is not bound to `chatId`, and project-associated parameters are not cached after the session ends, leading to loss of historical records.

## How to Verify Correct Configuration
- Start a new dialogue, check if the interface displays preset quick buttons. Click the buttons to send preset questions, and confirm the `messages` array contains initial preset instructions.
- Call the dialogue API to upload a single Gerber file under 1000 MB, confirm the interface returns a successful status with no missing parameter errors.
- Start a dialogue using the temporary session identifier, enter the bound `chatId`, and confirm the system loads the current project's historical dialogue and parameters.
- Modify the project's drilling parameters, start a new dialogue to ask a question, and confirm the system generates quotation suggestions using the updated parameters.

The values listed here are common starting points, and should be validated against the reader's own samples.
