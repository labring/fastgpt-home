# Bid Document and Quotation Preparation for PCB Manufacturing: Workflow Orchestration

## What Data Looks Like for This Category
PCB manufacturing bid and quotation data comes from customer-provided Gerber files, drill files, BOM lists, CAM analysis records, equipment operating parameters, bath solution test results, AOI inspection reports, electrical test reports and slice reports. Data updates continuously per production batch and shift. Document structures include production instructions, layered process parameters, defect inspection records and other content. Core fields include professional parameters such as aperture unit, lamination thickness tolerance and drilling offset.

## Constraints Imposed on Workflow Orchestration
Since data sources are scattered and formats vary widely, workflow orchestration needs built-in format verification and automatic parsing nodes to support unified import of multi-source data. Data updates at high frequency, so real-time triggered process branches must be configured to keep bid quotations synchronized with production data. The specialized nature of core fields requires the parameter mapping step to precisely match preset fields in the bid template, preventing quotation errors from parameter misalignment. Abnormal data can cause full batch scrap, so an abnormal branch must be set to trigger alerts and pause the process.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Bind Gerber aperture, lamination thickness, drilling parameters | Match core parameters from PCB manufacturing documents, used for parameter filling during tool calls |
| Loop end condition | Trigger when an abnormal mark is detected in the electrical test report | Adapt to real-time abnormal processing requirements for production data, avoid invalid loops |
| Tool call parameter binding | Pass the first 3 AOI reports and current production batch's Gerber analysis records via `q` | Meet business requirements for precise feeding of corresponding tool parameters |
| Timeout setting | 600 seconds | Adapt to processing duration for complex Gerber analysis and multi-source data integration |
| Context length | 800-1200 characters | Adapt to content length requirements for bid documents, avoid information overload |
| Login-free window trigger node | Execute after binding the quotation generation node | Match post-release process trigger logic, resolve inconsistencies between preview and release |
| `nodeId` | Bind the unique identifier of the AOI report processing node | Accurately locate the processing branch for abnormal data, improve process reliability |

## Three Common Errors
- Tool call returns results unrelated to the current production batch, with empty fields. Cause: The specific production data bound to `variables` was not passed to the `q` parameter.
- The loop body runs continuously until timeout, without terminating when copper hole abnormalities are detected. Cause: No abnormal termination condition was configured for the loop body.
- Process trigger fails after releasing the login-free window, but runs normally during preview. Cause: The node binding order of the login-free window is incorrect, and no core execution node is associated.

## How to Verify Proper Configuration
- Check whether the fields bound to `variables` include core PCB manufacturing parameters such as Gerber aperture and lamination thickness.
- Simulate input of abnormal electrical test report data to test whether the loop body automatically triggers termination.
- Release the login-free window, simulate a bid process trigger, and confirm that nodes execute in the preset order.
- View workflow logs to confirm that the `q` parameter for tool calls includes specific data for the current production batch.

The values provided are common starting points and should be measured against the reader's own samples.
