# Bid Document and Quotation Preparation for PCB Manufacturing: Tool Calling and Plugins

## What the Data for This Category Looks Like
Data for this category comes from customer-provided Gerber files, drill files, and BOM lists, combined with factory CAM systems, production equipment parameters, bath solution test records, AOI inspection reports, electrical test data, and laboratory slice reports. Data updates occur per production batch and shift frequency. Some parameters are generated via continuous collection by equipment. Daily documents include engineering production instructions, Gerber analysis records, drilling and lamination parameter tables, chemical analysis ledgers, AOI defect reports, electrical test qualification certificates, and slice failure analysis reports. Fields include aperture specifications, lamination temperature, bath solution concentration, defect point coordinates, and other related items.

## Constraints Imposed on Tool Calling and Plugins
Data for this category is scattered across multiple systems and formats. Tool calling must adapt to specialized interface formats such as Gerber analysis and CAM data pulling, to prevent general-purpose plugins from failing to recognize specialized fields. Data update frequency is high, and some data is collected in real time. Tools must support data synchronization triggered by production batch or shift, to avoid using expired parameters when generating quotations. Documents include structured parameter tables and unstructured inspection reports. Tool calling must distinguish between structured field extraction and full-text retrieval logic, adapting to processing rules for different content types. Tool calling failures directly affect bid document accuracy or quotation rationality, so a pre-check link must be added.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| :--- | :--- | :--- |
| `toolChoice` | `auto` | Automatically match tools suitable for the current task, adapting to multiple data source types and document formats |
| `functionCall` | Enable forced function calling | Ensure accurate extraction of structured production parameters, avoiding interference from unstructured report content with quotation calculations |
| Tool call timeout period | 300–600 seconds | Data pulling involves multiple system interfaces, so sufficient response and processing time must be reserved |
| Data source whitelist | Only add valid API addresses of factory CAM, AOI, and bath solution test systems | Prevent calling unauthorized data sources from introducing errors or sensitive data |
| Abnormal parameter verification rules | Trigger an alert when extracted fields fall outside the industry's reasonable range | PCB manufacturing parameters have fixed reasonable ranges, which can quickly identify abnormal data |
| Default tool calling model | Select a large language model that supports tool calling capabilities | Ensure normal execution of tool calling logic |

## Three Common Misconfigurations
- Phenomenon: Tool calling returns empty drilling parameters, and the generated bid document omits hole position accuracy requirements. Cause: The data source whitelist is not configured, and an unauthorized CAM system interface is called, resulting in failed parameter extraction.
- Phenomenon: Tool calling times out, returning status code 504. Cause: The set timeout period is shorter than the total time required for multi-system data pulling, and sufficient response time is not reserved.
- Phenomenon: Tool calling fails to recognize the uploaded Gerber file, returning a format error prompt. Cause: No file upload workflow API adaptation rules are configured, and supported PCB-specific file formats are not specified.

## How to Confirm Proper Configuration
- Log in to the FastGPT v4.17.0 tool configuration page, check if `toolChoice` is set to `auto`.
- Enter the function call settings interface, confirm that the `functionCall` forced calling mode is enabled.
- Simulate a call to the test interface, pass in a test Gerber file and CAM data, check if the returned structured parameters are complete.
- Configure the abnormal verification rules, enter test parameters that fall outside the reasonable range, confirm whether an alert is triggered.
- Check if the tool calling return corpus includes a data source identifier, confirming that the traceability function is enabled.
- Enter the default model settings interface, confirm that a large language model that supports tool calling capabilities has been selected.

The values provided here are common starting points and should be evaluated against the reader's own samples.
