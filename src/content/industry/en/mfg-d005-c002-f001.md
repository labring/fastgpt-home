# Bid Document and Quotation Preparation for SMT Mounting and Electronic Assembly: HTTP Interfaces and External Systems

## What the data for this category looks like
Business data sources for SMT mounting and electronic assembly include BOMs, Gerber files, and coordinate files provided by customers, as well as production system data from MES systems, mounting machines, SPI/AOI inspection equipment, and reflow oven temperature records. Daily documents cover BOM lists, line change sheets, stencil and furnace temperature records, first article confirmation reports, SPI/AOI inspection reports, maintenance records, and traceability labels.
Data is updated in real time per work order and each line change. Core fields include part number, reference designator, component batch, mounting coordinates, and furnace temperature parameters. Format and units must match customer-specified requirements.

## What constraints these characteristics impose on HTTP interfaces and external systems
Business data for this category is scattered across multiple sources and updated in real time. Interface calls must adapt to data formats and authentication rules of multiple systems.
BOMs and inspection data for different work orders have large structural differences. Interfaces must support dynamic request bodies and field extraction.
Real-time requirements mean interface timeouts must be controlled within a reasonable range to avoid blocking bid quotation preparation workflows.
Data errors can lead to mass production failures. Interface calls must include retry and error capture mechanisms to ensure the stability and accuracy of data acquisition.

## How to set up configurations
The following configurations are based on the tool calling logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Authentication Configuration | Include Bearer-format API keys | Complies with standard authentication requirements for external systems, and supports OneAPI access scenarios |
| Request Variables | Pass work order ID and component batch number | Binds real-time work order data to support dynamic calculation for bid quotations |
| Response Data Extraction | Only retain part number verification results and quotation detail fields | Filters redundant data to meet field requirements for bid document generation |
| Retry Count | 3 times | Addresses interface call failures caused by network fluctuations to ensure data acquisition stability |
| Request Timeout | 30 seconds | Matches the real-time update rhythm of SMT work order data to avoid workflow blocking |

## Three Common Misconfigurations
- Interface returns 401 status code, but calls work normally in Postman. Cause: The authentication parameters configured in FastGPT do not match the format required by the external system, and the Bearer identifier in the `Authorization` header is not correctly included.
- Unable to retrieve component batch data from the interface, returned fields are empty. Cause: The correct work order ID parameter is not passed in the `variables` of the request, so the external system cannot match the corresponding data.
- Custom model interface cannot be called after configuration, tool call parameters do not take effect. Cause: The model is not correctly associated in the FastGPT tool configuration, or the corresponding call permission is not enabled.

## How to Confirm the Configuration is Successful
- Initiate a test call in the FastGPT debug panel, and check whether the returned `responseData` includes the expected part number and quotation detail fields.
- Simulate a work order to trigger an interface call, verify that authentication parameters are correctly generated, and confirm there are no 401 or 403 error codes.
- Adjust the work order ID parameter in the request variables to verify that the external system can return component batch data for the corresponding work order.
- Check the interface call logs to confirm that the retry strategy triggers normally during network fluctuations, and there are no consecutive failures.
