# Bid Document and Quotation Preparation for SMT Mounting and Electronic Assembly: Workflow Orchestration

## What data for this category looks like
Data for this category comes from customer-provided BOM, Gerber files, component coordinates, plus internal factory MES systems, mounters, SPI/AOI inspection equipment, reflow oven temperature records, solder paste and component batch ledgers. Daily generated documents include BOM lists, changeover work sheets, stencil usage records, furnace temperature curve reports, first article confirmation forms, defect repair records and product traceability labels. Data updates once per work order, updates in real time during changeover operations, and key inspection data generates in real time as inspection processes run.

## Constraints for workflow orchestration
Real-time updated data per work order and changeover requires workflows to support dynamic trigger nodes, and avoid fixed static data sources. Multiple types of heterogeneous documents (BOM, coordinate files, furnace temperature records and others) require workflows to support multi-format file parsing and field extraction, and adapt to exclusive fields such as component reference designators, part numbers and coordinate parameters. Real-time inspection data access requires workflow nodes to have low-latency invocation capabilities, to avoid errors in quotations and bid documents caused by data synchronization delays. Component batches and defect records for different work orders must bind to their corresponding work order. Workflows must support variable association with work order IDs to ensure accurate data traceability.

## How to set configurations
| Config Item | Suggested Value | Basis for This Choice |
| --- | --- | --- |
| variables | Bind work order ID, component batch number, BOM version number | Ensure each bid document and quotation associates with the exclusive data of the corresponding work order, avoid cross-work order data confusion |
| nodeId | Generate unique node ID per work order, bind to corresponding inspection report node | Achieve isolation of workflow instances for different changeover batches, facilitate failed node traceability |
| File parsing trigger rules | Trigger corresponding parsing nodes based on uploaded file suffixes, support BOM, CSV coordinate files, furnace temperature PDF | Adapt to multi-format business documents of this category, automatically call corresponding parsing logic |
| Timeout threshold | 600 seconds | Cover time consumption requirements for large-size BOM file parsing and multi-device data pulling |
| Result verification rules | Compare part numbers, reference designators with customer-provided Gerber data | Proactively check core risks such as wrong parts and wrong reference designators, avoid subsequent batch issues |

## Three common misconfigurations
- Workflow calls to external nodes return 400 status codes, and tests fail. The cause is failure to bind required business parameters for the node via `variables`, resulting in missing incoming data.
- HTTP request node body fields are empty, and parameter configurations do not meet expectations. The cause is confusion between parameter names and file variables, with parameter names not matching business fields, and parameter values not associated with corresponding file links.
- Workflow instances for different changeover batches experience data crossover, and bid documents contain component information from non-current work orders. The cause is failure to configure `nodeId` to bind work order ID, resulting in unisolated workflow instances.

## How to verify correct configuration
- In the workflow debugging panel of FastGPT v4.17.0, upload test BOM and coordinate files, check if `variables` automatically binds business parameters such as work order ID and component batch number.
- Trigger workflow execution, view node logs to confirm that `nodeId` generates a unique identifier per work order, with no duplication or crossover.
- Call the HTTP request node, verify that body parameter names match business fields such as part numbers and coordinates, and that parameter values correctly associate with corresponding file links.
- Simulate submission of two work orders for different changeover batches, check if the workflow triggers independent parsing and verification nodes, with no data shared across work orders.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
