# Bid Document and Quotation Preparation for SMT Mounting and Electronic Assembly: Model Access and Configuration

## What Data Looks Like for This Category
Data sources for this category include BOM, Gerber, and coordinate files provided by customers, plus MES system data, solder paste and component batch records, placement machines, SPI/AOI testing equipment, and reflow oven temperature data. Daily documents cover changeover sheets, stencil archives, first article confirmation sheets, solder joint defect reports, maintenance records, and traceability labels.
Data updates take effect in real time with each work order and each changeover. Fields include component part numbers, reference designators, batch numbers, testing parameters, reflow temperature curves, and more. No additional pre-configured statistical fields are included.

## Constraints Imposed by These Characteristics on Model Access and Configuration
The multi-source real-time data and professional engineering document features of this category create multiple constraints for model access and configuration.
Real-time data updates tied to work orders and changeovers require model context to dynamically sync the latest work order data. This prevents quotation errors caused by outdated data.
Documents contain professional fields such as component part numbers, reflow temperature curves, and coordinate offsets. The model must adapt to professional terminology and formats used in the electronic manufacturing sector.
Generating bid documents from integrated multi-source data requires the model to consolidate content from different sources. This ensures consistency between quotations and documents.

## How to Configure Settings
| Configuration Item | Suggested Approach | Basis for This Setting |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | Fill in the official API address of the corresponding large model service provider, or the listening address of a locally deployed model. For example, `https://api.openai.com/v1` or `http://localhost:8000/v1` | Matches the model call network request path requirements of FastGPT v4.17.0 |
| `AIPROXY_API_TOKEN` | Fill in a valid key assigned by the platform or provided by the service provider | Completes identity verification for model calls, ensuring normal access permissions |
| `maxContext` | `8000–16000 token` | Adapts to the total content length of multiple BOMs, testing reports, and changeover sheets, avoiding context overflow |
| `maxTokens` | `2000–3000 token` | Controls the generation length of a single bid document and quotation, conforming to length specifications for engineering documents |
| `quoteMaxToken` | `1000–1500 token` | Controls the generation length of the quotation details section, ensuring compact and accurate content |
| `temperature` | `0.2–0.4` | Maintains accurate terminology for professional engineering documents, reducing random output deviations |
| Workflow/API tool selection | `auto` | Automatically selects appropriate logic to handle multi-source data integration and document generation requirements |

## Three Common Configuration Errors
- Phenomenon: Custom large model API calls return a 401 status code. Cause: `AIPROXY_API_TOKEN` is not configured correctly, or the key has insufficient permissions to access the target model.
- Phenomenon: Component part numbers in generated bid documents do not match the actual BOM. Cause: The `maxContext` value is too small, failing to fully load the latest BOM and changeover sheet data, leading the model to use outdated information.
- Phenomenon: No exportable standard bid document is generated after workflow execution. Cause: Document generation associated logic is not enabled in the model configuration, or output format parameters are not set correctly.

## How to Verify Successful Configuration
- Submit a test work order, call the configured model, and check that the API returns a 200 status code. This confirms normal network connectivity and authentication.
- Upload a test BOM and changeover sheet, trigger the model to generate a quotation snippet, and verify that the output includes correct component part numbers and reference designators. This confirms normal context loading.
- Adjust the `temperature` parameter and generate test content again. Observe changes in the consistency of professional terminology in the output. This confirms the parameter is active.
- Trigger the workflow to generate a complete bid document, check that the output format conforms to the general structure of bid documents in the electronic manufacturing industry. This confirms the configuration adapts to business needs.

The values provided here are common starting points, and should be evaluated against internal test samples.
