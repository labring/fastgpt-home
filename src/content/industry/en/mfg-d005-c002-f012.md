# Bid Document and Quotation Preparation for SMT Mounting and Electronic Assembly: Deployment and Upgrade

## What the Data for This Category Looks Like
Business data for SMT mounting and electronic assembly comes from BOMs, Gerber files, and mounting coordinate files provided by customers. It also comes from changeover lists, stencil usage records, first article confirmation reports, and repair traceability tags generated by in-house MES systems, mounting machines, SPI/AOI inspection equipment, and reflow oven temperature collection equipment.
Data is updated in real time per work order and each line change. Document structures include fields such as part number, reference designator, substitute part, component specification, mounting position coordinates, and furnace temperature parameters. Some documents include stencil and solder joint inspection reports in image format.

## What Constraints These Characteristics Impose During Deployment and Upgrade
Multiple data sources and high update frequencies require support for multi-data source connection and incremental synchronization configuration during deployment. This avoids full synchronization consuming excessive server resources.
Business documents include multi-dimensional structured fields and image attachments. Knowledge base chunking must match document field structures to ensure accurate association of core information such as part numbers and coordinates during retrieval.
High-priority real-time mounting coordinate and furnace temperature data requires caching. A permission verification mechanism must also be configured to protect sensitive documents such as bid documents and prevent unauthorized access.
In addition, data related to line change error prevention and solder joint quality must be linked to the quotation preparation link. A connected data link must be established during deployment.

## How to Set Configurations
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Use the MongoDB connection address corresponding to your in-house server, set `DB_MAX_LINK` to `200` | Store structured business data such as bid documents and BOM tables; limit connection count to avoid resource exhaustion |
| `REDIS_URL` | Use the local Redis service address on port 6379, set connection timeout to `800 seconds` | Cache real-time mounting coordinate and furnace temperature data to reduce multi-source data retrieval latency |
| `STORAGE_S3_ENDPOINT` | Use the node address of the in-house intranet object storage | Store large-volume documents such as stencil images and AOI reports to reduce public network transmission costs |
| `FILE_TOKEN_KEY` | Use a 32-bit randomly generated encrypted string | Encrypt download tokens for bid documents to prevent unauthorized access |
| `ROOT_KEY` | Use a strong random key only during initialization; restrict access to intranet only after deployment | Manage the highest permission configuration for the system to avoid unauthorized operations |

## Three Common Misconfigurations
- Symptom: The frontend page does not display the identity verification configuration entry, making it impossible to restrict access to bid documents. Cause: The `FILE_TOKEN_KEY` and `ROOT_KEY` parameters are not configured correctly, and the default open-source login-free deployment mode is used.
- Symptom: When classifying multiple knowledge bases, only the current question is read, and context history is not associated. This causes classification results to lean toward default categories. Cause: Context data such as line change records and work order history are not included in the retrieval window, and reasonable context association rules are not configured.
- Symptom: Data synchronization interrupts when connecting to the MES system, making real-time acquisition of mounting coordinate and furnace temperature data impossible. Cause: The connection timeout parameter for `REDIS_URL` is not adjusted, causing real-time data streams to time out and disconnect.

## How to Verify Correct Configuration
- Access the frontend address configured via `FE_DOMAIN`, check if the identity verification login page can be accessed, and attempt to log in to the system using the preset key.
- Upload a test BOM table and coordinate file, check if the file is properly stored to the storage node corresponding to `STORAGE_S3_ENDPOINT`.
- Create a knowledge base containing BOM tables and changeover lists, initiate a retrieval request, and check if the returned results include multi-source associated business data.
- View the database connection log corresponding to `MONGODB_URI`, confirm that the current connection count does not exceed the configured value of `DB_MAX_LINK`.

The values provided here are common starting points and should be evaluated against the reader's own samples.
