# Tender Document and Quotation Preparation for Dairy Processing: Vector Models and Indexes

## What the data for this category looks like
Daily documents for dairy processing include raw milk acceptance records, standardized ingredient lists, pasteurization or UHT heat treatment records, CIP cleaning records, filling records, and sample retention and microbial test reports. Data sources include milk source testing systems, production MES systems, homogenization and heat treatment equipment, online temperature and flow monitoring systems, CIP systems, and LIMS laboratory management systems. Data updates occur in real time for each milk tank and production batch. Individual documents contain structured fields such as batch numbers, test values, and process parameters. Some fields use professional units, including CFU/mL for total bacterial count and μg/kg for antibiotic residue.

## What constraints these characteristics impose on vector models and indexes
Dairy processing data updates frequently and syncs in real time per milk tank and production batch. Indexes must support incremental updates to avoid excessive system resource usage from full reconstruction. Multiple types of structured documents include professional testing and process parameters, such as raw milk antibiotic residue levels and heat treatment temperature and time parameters. Vector models must adapt to semantic recognition of professional terms to avoid losing core indicator associations. Individual documents have many structured fields and professional units. Chunking processes must retain contextual connections to prevent fragmentation of production process logic across chunks. Data links are tight: raw milk acceptance results directly impact subsequent ingredient preparation and heat treatment steps. Indexes must support cross-document associated retrieval to ensure results cover the full business chain and avoid missing key decision-making basis.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the length of individual testing and production records for dairy processing, avoiding damage to the semantic integrity of professional terms |
| `maxToken` | 8192 token | Matches the context window upper limit of mainstream open-source embedding models, preventing long documents from being truncated |
| Chunk Overlap Length | 100–150 characters | Retains contextual associations between adjacent chunks, preventing fragmentation of production process logic across chunks |
| Similarity Threshold | 0.72–0.80 | Adapts to the feature similarity distribution of dairy professional data, balancing recall accuracy and irrelevant result filtering |
| `defaultToken` | 4096 token | Adapts to the average length of core documents per batch, meeting the context requirements of basic retrieval |
| Single Recall Limit | Top 6 entries | Controls the context load of retrieval results, avoiding exceeding the model's processing capacity |

## Three common mistakes
- Phenomenon: After configuring an embedding model with the same name, existing configurations are overwritten. Cause: In FastGPT v4.17.0, only one configuration is supported per model name. Conflicts occur when model aliases are not distinguished by business scenarios.
- Phenomenon: Retrieval results return only a small number of entries or are empty. Cause: The similarity threshold is set too high, failing to match associated documents with dairy professional characteristics, or the chunk length is too long leading to truncated semantics.
- Phenomenon: Key indicators are missing in vector retrieval results for long testing records. Cause: The `maxToken` parameter is not set reasonably, leading to truncated long documents and loss of core fields such as raw milk antibiotics and physical and chemical indicators.

## How to confirm the configuration is correct
- Upload a single raw milk acceptance record, perform a retrieval test, and check if the returned result chunks retain core fields such as batch numbers and antibiotic test values.
- Configure multiple models of the same type and set different aliases, verify that the new configuration does not overwrite existing settings.
- Adjust the similarity threshold, compare the number of retrieval results under different thresholds, and confirm that the recall range meets business expectations.
- Upload multiple production documents linked by batch, verify that cross-batch associated records can be retrieved after incremental index updates.

The values listed above are common starting points and should be evaluated against the reader's own samples.
