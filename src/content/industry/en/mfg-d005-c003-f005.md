# Tender Document and Quotation Preparation for Dairy Processing: Tool Calling and Plugins

## What the data for this category looks like
Data for this category covers raw milk acceptance records, standardized ingredient lists, pasteurization or UHT heat treatment records, CIP cleaning records, filling records, retained samples and microbial inspection reports. Data sources include milk source testing equipment, production MES systems, online monitoring devices for homogenization and heat treatment, real-time temperature and flow collection systems, CIP management platforms, and LIMS laboratory management systems. Data updates are performed per individual milk tank and single production batch. Some online monitoring data is synchronized in real time, and core indicators are gradually improved as the production process advances. Document fields include raw material batch number, test value, process parameters, equipment number, retained sample number, and other items. Some parameters must match the official format issued by a statutory testing institution.

## What constraints these characteristics impose on the "tool calling and plugins" link
Production data for dairy processing is strongly bound to batches. Tool calling must accurately associate documents and real-time parameters corresponding to the target batch. General batch templates cannot be used. High-frequency updates of real-time online data require tool calling to have low-latency response capabilities, to avoid generating tender content using outdated data. The need to integrate multi-source heterogeneous data requires plugins to be compatible with interface formats of different systems, and adapt to different data structures in raw milk acceptance, heat treatment, filling and other links. Tender documents must match officially recognized test report formats. Tool calling must strictly follow preset field order and units, to prevent tender documents from being invalidated due to non-compliant formats.

## How to set up the configuration
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Workflow/API tool selection | `auto` | Automatically adapts to tool calling logic across multiple links, no manual tool type specification required |
| Workflow/API function-call configuration | `["raw milk index verification", "heat treatment parameter validation", "tender document filling"]` | Binds exclusive business tool functions for dairy processing, accurately calls data from corresponding production links |
| Tool calling switch | Enabled | Multi-system production data must be integrated to generate tender content. Enabling this allows cross-data source calls |
| Knowledge base recall limit | `0 items` | Tender content must be based on actual measured production data, no general knowledge base content is used |
| Timeout threshold | `300 seconds` | Waiting for real-time data returns from multiple devices requires sufficient interface response time |
| Response content filtering | Only retain tool calling results | Avoid irrelevant dialogue references interfering with the rigor of tender documents |

## Three common mistakes
- Symptom: A `401 Unauthorized` error is returned when calling a workflow, or an invalid API Key prompt appears. Cause: A global general API Key is used directly to call the workflow, and the exclusive API Key of the corresponding application is not used.
- Symptom: Empty production data fields are returned after workflow calling, and the raw milk acceptance records of the target batch cannot be matched. Cause: A unique workflow instance identifier is not generated for each production batch, resulting in misplaced data association.
- Symptom: General knowledge base content or irrelevant dialogue reference fragments are mixed into the generated tender documents. Cause: Response content filtering rules are not configured correctly, causing tool calling results to be contaminated by additional dialogue content.

## How to confirm the configuration is correct
- Call a test workflow, check that the returned response only contains production data content generated by tool calling, with no extra dialogue reference fragments.
- Verify API Key permissions, confirm that a `200 OK` status code is returned during calling, with no permission-related errors.
- Generate a single-batch tender document fragment, check that fields and units fully match the documents of the corresponding production batch.
- View workflow running logs, confirm that each tool call is associated with the correct production batch data.

The values given are common starting points and should be measured against the reader's own samples.
