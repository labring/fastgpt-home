# Tender Document and Quotation Preparation for Dairy Processing: Forms and Interactions

## What the Data for This Category Looks Like
Data for this category comes from milk source testing systems, MES systems, homogenization and heat treatment equipment, online temperature and flow collection systems, CIP cleaning systems, and LIMS laboratory management systems. Data is generated per milk tank, per batch, or in real time. Daily documents include raw milk acceptance records, standardized ingredient lists, pasteurization or UHT heat treatment records, CIP cleaning records, filling records, and sample retention and microbial test reports. Core fields include raw milk antibiotic and physicochemical indicators, heat treatment duration and temperature, aseptic filling parameters, and cleaning verification data. Corresponding units include mg/kg, seconds, ℃, CFU/mL, and similar units.

## Constraints on Forms and Interactions
Since data is generated per milk tank and per batch in real time, forms must support fast retrieval of equipment and testing data for the corresponding batch to avoid manual duplicate entry. Core fields have strict business validation rules. For example, raw milk antibiotic indicators must meet rejection thresholds, and heat treatment duration must meet required standards. Form interactions must embed real-time validation logic. Tender documents must integrate data from multiple links, and form triggers must bind to production batches to prevent cross-batch data confusion. The perishable nature of liquid raw materials also requires form processes to have no unnecessary delays, to avoid data expiration and invalidation.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `formInput` | Bind preset business fields such as raw milk acceptance records and ingredient lists | Match the fixed document structure of the category, reduce manual entry errors |
| `userSelect` | Associate drop-down options for equipment parameters of the current batch, limit selectable range | Avoid input errors, match real-time updated production data |
| Form validation rules | Set threshold ranges for raw milk antibiotic indicators, set fixed durations for heat treatment duration | Comply with business compliance requirements, intercept non-compliant data in advance |
| Interaction confirmation pop-up | Trigger before submission, display core parameters such as raw milk batch number and heat treatment temperature | Prevent core data errors in tender documents |
| Context length | 800–1200 characters | Match the average character count of single-batch production documents, ensure complete extraction |
| Timeout setting | 60 seconds | Match the upper limit of real-time equipment data retrieval delay, avoid process freezes |

## Three Common Configuration Mistakes
- Symptom: Core business fields are empty after form submission, preventing normal process progression. Cause: Required validation rules for `formInput` are not configured, and field mapping for the corresponding data source is not bound.
- Symptom: The process proceeds directly to the next step without waiting for user interaction after triggering the `userSelect` module. Cause: The configuration to wait for user operation is not enabled, and the interaction confirmation step is skipped directly.
- Symptom: Extracted raw milk testing data does not match actual records, and the number of results is abnormal. Cause: The form is not bound to the real-time data interface of LIMS or MES, and expired static cached data is used.

## How to Verify Successful Configuration
- Manually enter a simulated raw milk acceptance record, verify whether the corresponding fields trigger mandatory prompts, and confirm that data is synchronized to the tender document template.
- Trigger the `userSelect` module, confirm that the drop-down options include the equipment parameters of the current batch, and verify that the process proceeds normally after the user makes a selection.
- After submitting the form, check whether the interaction confirmation pop-up appears, and confirm that core parameters are displayed correctly before the process proceeds to the next step.
- Check the application logs of FastGPT v4.17.0, confirm that the equipment data pulled by the form matches the real-time data from the MES system, and there are no timeout errors.
