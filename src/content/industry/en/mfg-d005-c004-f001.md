# Tender Document and Quotation Preparation for Warehousing, Lot Tracking, and In-Plant Logistics: HTTP Interfaces and External Systems

## What Data for This Category Includes
Data for this category covers material and location information across the entire warehousing process. Daily documents include receiving slips, putaway slips, material picking and returning slips, warehouse transfer slips, inventory counts, lot ledgers, first-in first-out (FIFO) and expiration date records. Data sources primarily include ERP/WMS systems, barcode or RFID identification devices, purchase work orders, warehouse location configurations, AGV transport systems, and weighing equipment. Data update frequencies are divided into three categories: real-time (e.g., warehouse location changes, lot movement), daily (e.g., daily material in/out warehouse summaries), and monthly inventory (e.g., book vs. physical inventory discrepancy checks). Each document includes fields such as material code, lot number, warehouse location number, quantity, expiration date, and inspection status. Common units include physical measurement units such as pieces, kilograms, cubic meters, and others.

## Constraints Imposed on HTTP Interfaces and External Systems
Real-time data update requirements for this category mean interfaces must support high-frequency calls, to avoid deviations in material availability information in tender quotations caused by delays. Differences in data formats across multiple sources mean interfaces must support field mapping between different systems. For example, the lot number field returned by some ERPs uses a different name than the lot number field collected by RFID devices. The bulk import requirement for monthly inventory data means interfaces must support transmitting large datasets in a single request, so a reasonable single request limit must be set. The core requirement of book and physical inventory consistency means validation fields returned by interfaces must strictly match the material list in tender documents, to avoid quotation deviations caused by errors or omissions. Additionally, real-time validation requirements for lot expiration dates and inspection statuses mean data returned by interfaces must include corresponding fields, to ensure the accuracy of tender quotations.

## Configuration Settings
| Configuration Item | Suggested Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {enterprise-owned API key}` | Interfaces for ERP/WMS systems in this category mostly use Bearer token authentication to ensure data transmission security, and comply with the authentication configuration requirements of FastGPT v4.17.0 |
| Single request limit | Top 1000 entries | Matches the bulk transmission requirement for monthly inventory data, to avoid interface timeouts caused by overly large single request sizes |
| `variables` | Bind three core variables: material code, lot number, warehouse location number | Accurately matches the quotation item generation logic of tender documents, ensuring correct variable substitution |
| Timeout period | 600 seconds | Adapts to the transmission time required for bulk inventory data, to avoid incomplete data caused by mid-transmission interruptions |
| `responseData` | Extract four core fields: material code, lot number, available quantity, expiration date | Covers the core accounting basis required for tender quotations, simplifying subsequent field processing workflows for document generation |
| Field mapping rules | Set based on actual testing | Field names differ across ERP/WMS systems, so targeted adjustments are needed to match the return format of external systems |

## Three Common Configuration Mistakes
- Symptom: The interface call returns the `tls: failed to verify certificate` error, with a status code of 0. Cause: The interface's SSL certificate verification rule is not configured, or a self-signed certificate was not imported into the system trust store.
- Symptom: The HTTP module receives custom variables and returns empty values, making it impossible to generate corresponding quotation items. Cause: The material fields required for tender documents were not correctly bound in the `variables` configuration, or the variable names do not match the fields returned by the external system.
- Symptom: The interface returns a timeout error when bulk importing inventory data, and only partial data is processed. Cause: A reasonable single request limit was not set, and the data volume transmitted in a single request exceeds the interface's carrying capacity.

## How to Verify Successful Configuration
- Call the test interface, check if the returned `responseData` includes the preset core fields, to confirm that the field mapping configuration is correct.
- Initiate a single small-batch data request, check if the interface returns a normal status code, to verify that the timeout period configuration is effective.
- Bind test `variables`, trigger the tender document generation workflow, confirm that the variables are correctly substituted into quotation items.
- Check the validity of the `Authorization` token, call the interface and confirm that no authentication failure error occurs.
