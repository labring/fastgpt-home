# Bid Document and Quotation Preparation for Warehousing, Lot Tracking and In-Plant Logistics: Tool Calling and Plugins

## What data covers this category
This category’s data covers daily operations of raw material warehouses, line-side warehouses, finished product warehouses, and logistics and material control departments. Daily documents include receiving slips, putaway slips, material picking and return slips, stock transfer slips, inventory counts, lot ledgers, and similar records. Core fields include material code, lot number, location identifier, expiration date, quantity and unit of receipts and dispatches.
Data sources include ERP/WMS systems, barcode or RFID collection devices, purchase work orders, location configurations, AGV transport systems, and weighing equipment. Update frequencies include real-time (e.g., location changes), daily (e.g., receipt and dispatch summaries), and monthly inventory updates.

## Constraints on tool calling and plugin workflows
This category’s data characteristics create multiple constraints for tool calling and plugin workflows.
Multi-source heterogeneous data sources require plugins to adapt to different interface formats from ERP/WMS, RFID collection devices, AGV systems, and similar tools, and uniformly parse cross-system material information. Strong timeliness requirements for lots and expiration dates mean tool calls must pull the latest expiration date and inventory data in real time, to avoid using expired material information in bid quotations. Frequently updated location and receipt/dispatch data requires tool call response speeds to match business cycles, to prevent quotation deviations caused by delayed data. Field differences across multiple business documents require plugins to pre-configure field mapping rules for receiving slips, inventory counts, and lot ledgers, to ensure accurate verification of material identities.

## Configuration guidelines
Configurations are developed based on standard rules for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Workflow/API tool selection | `auto` or bound to the dedicated warehousing quotation tool group | Automatically matches inventory, lot, and logistics tools required for bids, avoiding missed business functions from manual selection |
| Workflow/API function-call configuration | `enabled` | Forces tool calls to pull real-time inventory and lot data from ERP/WMS, ensuring accuracy of quotation data |
| Tool call timeout threshold | `300–600 seconds` | Matches average response time of ERP interfaces, preventing workflow interruptions from overly long data pulls |
| Plugin field mapping rules | Pre-configure standard field mappings for receiving slips and lot ledgers | Uniformly parses core fields such as material codes and lot numbers across different business documents, ensuring data consistency |
| Multi-source data aggregation limit | `top 20 location change records` | Matches the scale of inventory data summarized once in bid documents, avoiding content overload that harms readability |
| Expiration data pull scope | `lot materials within the next 180 days` | Covers the expiration date cycle commonly used in bid projects, avoiding omission of available inventory resources |

## Three common configuration mistakes
- Phenomenon: Network connection errors occur when calling search plugins, or search results do not include content related to domestic warehousing. Cause: Search plugins adapted to domestic networks are not configured, or network proxy parameters for plugins are not set correctly.
- Phenomenon: Workflows cannot assign plain text data from lot ledgers and multimodal images scanned by RFID to corresponding tools for processing. Cause: Routing rules based on data type are not configured, and input format requirements of different tools are not distinguished.
- Phenomenon: Inventory data that does not match physical stock appears in bid documents, or lot information is blank. Cause: Trigger conditions for real-time data pulls are not set, cached historical inventory data is used incorrectly, and completeness of lot fields is not verified.

## How to verify correct configuration
- Trigger a test workflow, check tool call logs, confirm that inventory and lot data from ERP/WMS has been pulled automatically, with no missing fields or timeout errors.
- Manually adjust the expiration date data of a lot material, trigger a plugin call, confirm that the returned expiration date data is the updated latest value.
- Switch between different business document types, such as receiving slips and inventory counts, confirm that plugins can correctly parse corresponding fields and complete unified mapping.
- Verify tool routing configuration, confirm that plain text data calls text processing tools, and multimodal data calls multimodal processing tools.
