# Tender Document and Quotation Preparation for Photovoltaic Solar Cell Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What This Category of Data Looks Like
Process, equipment, quality control, and production departments of crystalline silicon solar cell manufacturing enterprises are the core users. Daily generated documents include process cards, diffusion and coating parameters, printing and sintering records, EL detection images, IV grading data, and yield reports.
Data sources include silicon wafer incoming materials, MES systems, production equipment such as diffusion furnaces, EL and IV testing equipment, and laboratory data. Update frequency follows per batch, per piece detection, and daily cycles. Fields cover photoelectric conversion efficiency, crack status, grading parameters, and other metrics. No unified fixed format exists, and content is adjusted dynamically based on production links.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
Multi-source and frequently updated data requires isolating dialogue context by tender project to avoid confusion of process data from different batches. Diverse document types require prompts to call corresponding data sources by production link. A single prompt cannot cover all business content.
The data volume of a single batch is large. Overly long dialogue history interferes with prompt parameter matching accuracy. Context range must be limited. Tender quotations must associate with specific batch production data. Multi-turn dialogue tracks exclusive parameters of the current project to ensure the prompt calls a data source matching the current tender link.

## How to Set Configurations
This configuration is formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Generate a unique identifier using tender project + batch number | Photovoltaic cell tenders quote by batch. Isolate dialogue context for different projects to avoid cross-batch data confusion |
| `messages` | Retain the last 10 dialogue records | Single batch process data volume is large. 10 records cover multi-turn communication needs for the current tender while avoiding overly long context interfering with prompt matching |
| `variables` | Load and split by process link, such as texturing, diffusion, and testing links | Different tender links call corresponding production data. Split variables to accurately match the data source called by the prompt and improve content matching accuracy |
| Maximum context length | 8000–12000 tokens, calibrated based on actual testing | Photovoltaic cell process parameters and testing data are lengthy. Sufficient context carries historical information from multi-round communication while avoiding exceeding model processing limits |
| Dialogue record offset | Offset by 2 entries after each new dialogue | Filter redundant pre-communication content. Focus on core parameter adjustments for the current tender link, aligning with user question business logic |

## Three Common Misconfigurations
- Issue: Cross-batch process parameter confusion occurs during multi-turn dialogue. Cause: `chatId` is not bound as a unique identifier for the corresponding tender project, so context is not isolated by project.
- Issue: The number of returned results when calling the interface to obtain the dialogue record list does not match expectations. Cause: The offset parameter is not set correctly, leading to incorrect pagination logic and inability to accurately obtain target dialogue records.
- Issue: The prompt does not load the current batch's IV grading data. Cause: The `variables` module is not used to associate the production data source of the corresponding batch, so the prompt cannot match the specific data required for the business.

## How to Confirm Configurations Are Properly Set
- Initiate a new tender dialogue. Check whether the session identifier includes project number and batch information to confirm the `chatId` configuration is effective.
- Send multiple rounds of questions. Check that the dialogue history panel only retains the last 10 valid records to confirm the `messages` context configuration is correct.
- Call the variable loading function. Verify that only process documents of the current link are loaded to confirm the `variables` splitting rule is effective.
- Initiate a request to obtain the dialogue record list. Adjust the offset parameter to verify that the pagination logic of the returned results meets expectations.

The values provided here are common starting points and should be measured against the reader's own samples.
