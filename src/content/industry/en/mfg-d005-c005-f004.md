# Tender Document and Quotation Preparation for Photovoltaic Cell Manufacturing: Workflow Orchestration

## What Data for This Category Looks Like
Relevant data for photovoltaic cell manufacturing mainly comes from silicon wafer incoming materials, MES systems, diffusion furnaces, coating equipment, printing presses, EL and IV testing equipment, and laboratory data. Daily documents include process cards, diffusion and coating parameters, printing and sintering records, EL inspection images, IV grading data, and yield reports.
Data updates occur per batch of materials, per wafer test result, and daily production cycle. Fields include process window parameters, inspection indicators, grading results, and yield values. Units involve current and voltage, thickness, efficiency values, and similar metrics.

## Constraints Imposed on "Workflow Orchestration"
Data from photovoltaic cell manufacturing has scattered sources, diverse types, and high update frequencies, which create multiple constraints for workflow orchestration.
Multi-source heterogeneous data must be pulled through separate nodes to avoid mixing data from different batches. Different document types such as process cards and EL inspection images require matching parsing configurations to ensure accurate field extraction. Frequently updated data needs reasonable trigger timing settings to prevent pulling expired data.
Tender document and quotation preparation requires integrating multi-dimensional production data. The workflow must connect data verification, format conversion, document generation, and other links to ensure consistent and accurate output content.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Variable group (`variables`) | Create independent variable groups by production batch and inspection batch. Each group includes process parameters, inspection data, and yield values | Aligns with batch-based data management business logic for photovoltaic cell manufacturing, avoids cross-batch data mixing, and complies with FastGPT v4.17.0 variable management specifications |
| Node ID (`nodeId`) | Name according to production links, such as pull MES data, parse EL inspection images, generate tender documents | Facilitates quick localization of abnormal nodes during debugging, and conforms to production link naming habits |
| Trigger rules | Trigger based on daily production batch completion time, or trigger within a specified time window | Matches daily data update frequency, ensures tender-required data uses latest production results |
| Timeout setting | 600 seconds | Production data pulling for photovoltaic cell manufacturing involves multiple device interfaces, reserves sufficient time to ensure complete data acquisition |
| Format verification rules | Verify parameter formats by field units | Matches specific unit requirements for this category's data, prevents parameter unit errors during quotation generation |
| Data pull interval | 3600–7200 seconds | Adapts to data update rhythms of different production lines, avoids ineffective repeated pulls |

## Three Common Misconfigurations
- Issue: When there are a large number of locally deployed workflow nodes, page text input becomes laggy. Cause: No batch loading configuration for `variables`, leading to excessive variable node data being rendered at once and causing rendering blocking.
- Issue: External links inserted into workflow reply components are displayed as "Click to Ask Immediately" instead of expected formatting. Cause: No link rendering rules configured for the reply component, default built-in interactive jump logic overrides custom link display.
- Issue: Workflow input instructions do not trigger preset production data pull nodes, and output results lack key parameters. Cause: No association bound between instructions and corresponding data sources, so the system cannot identify the required business data source.

## How to Verify Successful Configuration
- Run a simulated trigger, check workflow node running logs, confirm all data source nodes successfully pulled corresponding data.
- Generate a test tender document, verify that included process parameters and inspection data match content in preset variable groups.
- Adjust the trigger rule time window, verify whether the workflow starts automatically within the specified time.
- Insert a custom link into the reply component, check that the link displays as an expected jumpable external link.
