# Tender Document and Quotation Preparation for Photovoltaic Cell Manufacturing: Deployment and Upgrade

## What the data for this category looks like
Business data sources for photovoltaic cell manufacturing include silicon wafer incoming material records, production MES systems, real-time parameters of diffusion furnaces, coating equipment and printing presses, wafer-level test results from EL and IV tests, and laboratory yield reports.
Data updates follow this rhythm: sync incoming material and process parameters per production batch, update EL and IV data after each battery wafer completes testing, and summarize daily yield and process deviations each day.
Daily documents include process cards, diffusion and coating parameter tables, printing and sintering records, EL detection grayscale images, IV grading data tables, and yield analysis reports. Fields include wafer thickness, sintering temperature, conversion efficiency (watt-peak), crack level, and others. Common units are millimeters, degrees Celsius, and watt-peak.

## What constraints these characteristics impose on deployment and upgrade
Photovoltaic cell manufacturing business data comes from scattered sources and updates frequently. Deployment must support real-time synchronization and incremental pulling of multiple data sources, to avoid data lag affecting the accuracy of tender quotations.
Documents include unstructured images and long text parameter sections, so the system must adapt to parsing and indexing of different data formats.
Tender documents need to accurately match process parameters for corresponding batches, so the data association logic must strictly bind production batches and test results. The system must also support document access permissions across multiple departments, including process, equipment, and quality teams.
The upgrade phase must maintain consistency of historical data, to avoid data loss in archived tender documents caused by configuration changes.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `REDIS_URL` | Cloud server ECS intranet address and port 6379 | Reduce public network access latency, adapt to multi-node data caching requirements |
| `DB_MAX_LINK` | 20-30 | Adapt to concurrent connection requests from multiple devices and data sources, avoid database connection overflow |
| Chunk length | 800-1200 characters | Match the average length of single parameter sections in photovoltaic process documents, reduce chunk loss probability |
| Single recall limit | Top 10 entries | Focus on the most relevant process parameters and test data, meet the precise retrieval needs of tender documents |
| `STORAGE_S3_ENDPOINT` | Cloud object storage OSS intranet access endpoint | Reduce transmission costs for unstructured image files, improve document loading speed |
| `FILE_TOKEN_KEY` | Generate unique key per production batch | Ensure access permissions and data traceability accuracy for tender documents |

## Three common mistakes
- Setting the chunk length to 3000 characters can cause text chunk loss for some long parameter documents. This occurs because the segmentation logic does not adapt to continuous unbroken long parameter sections in photovoltaic process documents, such as diffusion furnace temperature curves.
- Failing to pull images after configuring `REDIS_URL`. This happens because VPC intranet access permissions are not configured, restricting public network access to the Redis instance.
- Failing to associate corresponding IV grading data after importing EL detection images. This occurs because batch binding indexing for structured data and unstructured images is not enabled.

## How to confirm the configuration is complete
- Log in to the FastGPT v4.17.0 system monitoring panel, check the connection status corresponding to `REDIS_URL`, and confirm it shows normal.
- Upload a typical diffusion process card document, check the background chunking logs, and confirm the number of generated text chunks matches expectations, with no loss prompts.
- Initiate a tender document generation test, verify that the returned process parameters match the MES system data for the corresponding batch.
- View the system log panel, confirm there are no data synchronization timeout, chunk loss, or permission error messages.
