# Tender Document and Quotation Preparation for Photovoltaic Module Encapsulation: HTTP Interfaces and External Systems

## What the data for this category looks like
Business data sources for photovoltaic module encapsulation include cell grading records, adhesive film and backsheet batch ledgers, production MES systems, string welding and lamination equipment logs, EL defect detector data, and IV power tester data. Data is updated in real time per individual module and per material batch. Daily generated documents include layout drawings, material batch records, lamination process parameter tables, EL crack images, IV test reports, insulation voltage withstand test records, and finished product packing lists.

Data fields include cell current gear values, lamination temperature and time parameters, EL crack level, module rated power, insulation voltage withstand values, with unique module serial numbers and batch identification strings.

## What constraints these characteristics impose on HTTP interfaces and external systems
Since data is updated in real time per individual module and batch, interface requests must match production rhythms. This avoids data lag from overly long request intervals, or system current limiting from overly high request frequencies.

Multi-source data integration requires interfaces to support parameter formats of different systems, and uniformly map to standardized fields required for tender quotations. Access to multiple types of documents requires interfaces to support fields and file returns in different formats, ensuring unstructured data such as EL images and IV test reports can be transmitted normally.

Standardization of data fields requires interface parameters to strictly match fixed units such as cell gears and power values, to avoid quotation deviations caused by inconsistent units.

## How to Configure the Settings
This configuration is compatible with FastGPT v4.17.0. Specific settings are listed below:

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `Authorization` | Fixed prefix of `Bearer ` plus the platform-generated secret key | Complies with HTTP interface authentication standards to secure interface access |
| Request timeout | 30–60 seconds | Matches the data return cycle of EL/IV testers, preventing interface interruptions from device response delays |
| `variables` | Bind business variables such as module serial numbers, cell gears, and batch numbers | Enables precise calling and matching of data for individual modules or batches |
| `responseData` | Only return fields including cell current gear values, rated power, and insulation voltage withstand values | Filters redundant data to reduce interface transmission load |
| Batch request limit | Top 50 entries | Matches the production quantity of a single batch of materials, avoiding request overload |
| API key permission settings | Restrict call duration and daily request count, only open interface permissions related to tender quotations | Meets access control requirements for business data, preventing key abuse and unrelated interface calls |

## Three Common Configuration Mistakes
- Failed to obtain target business data after calling the interface, returning `403 Forbidden` status code. The cause is that the call duration and count limits for the API key are not configured, or the key permissions do not grant access to the corresponding business interface.
- The `responseData` returned by the interface only contains partial fields, and complete batch module information cannot be obtained. The cause is that the batch request limit is set too low, and does not match the production quantity of a single batch of materials.
- A parameter missing prompt appears when calling the interface, and the module serial number variable configured in `variables` cannot be bound. The cause is that the bound business variable was not correctly passed in the interface request, or the variable name does not match the configuration item.

## How to Verify Correct Configuration
- Call the test interface, check that the returned authentication result is passed, and there are no `403 Forbidden` or `401 Unauthorized` error messages.
- Initiate a single module data request, verify that the fields returned in `responseData` exactly match the configured return fields.
- Initiate a batch request, verify that the number of returned data entries matches the set batch request limit.
- View the API key permission logs to confirm that the call duration and count limits have taken effect.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
