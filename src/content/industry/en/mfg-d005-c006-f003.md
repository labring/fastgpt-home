# Photovoltaic Module Encapsulation Tendering Document and Quotation Preparation: Multi-turn Dialogue and Prompt Words

## What the Data for This Category Looks Like
The business data sources for photovoltaic module encapsulation include battery cell grading records, glass adhesive film and backplane batch ledgers, production MES systems, string welding and lamination equipment logs, EL defect detection images, IV power test reports, insulation withstand voltage test records, and finished product packing lists.
Data is updated once per module corresponding to a test record, and once per batch of materials corresponding to a batch ledger.
A single document includes fields such as battery cell current gear, lamination process parameters, EL crack determination results, and power values, with units including amperes, watts, megapascals, and others.

## What Constraints These Characteristics Impose on the Multi-turn Dialogue and Prompt Words Link
Photovoltaic module encapsulation data is updated per individual module and per batch of materials. This requires multi-turn dialogue to associate component numbers and material batches, to avoid mixing cross-batch parameters.
Documents include process test data and visual inspection images. Prompt words must clearly specify rules for calling corresponding documents, to ensure parameters in tendering documents match actual production records.
For the most time-consuming battery cell gear matching process, multi-turn dialogue must gradually guide users to confirm parameters, reducing model misjudgments.
Frequently updated data should not be included in overly long context. The retention length of dialogue history must be limited to avoid redundant information interfering with current quotation logic.

## How to Configure the Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Session ID Configuration | Bind `chatId` | Ensures continuous association of multi-turn dialogue context, avoiding session interruptions |
| Maximum Context Length | 8000–12000 token | The single-batch document data volume for photovoltaic module encapsulation is large; this length can cover key parameters and historical dialogue required for current tendering quotations |
| Variable Binding | Bind batch numbers and component IDs in `variables` | Used to associate each batch of materials with test records of corresponding components, ensuring quotation parameters match actual production data |
| Historical Message Filtering | Retain the first 20 `messages` interaction records | Filters intermediate logs of plugin calls and redundant dialogue, avoiding irrelevant information interfering with current sessions |
| Tool Call Trigger Condition | Trigger file parsing when battery cell gear queries are detected | Quickly retrieves documents such as EL images and IV test reports to match the most time-consuming gear matching process |
| Prompt Template Configuration | Fixed call to photovoltaic encapsulation process documents | Ensures tendering documents strictly follow encapsulation processes and quotation logic, meeting business requirements |

## Three Common Mistakes
- Phenomenon: Dialogue has no streaming output. Cause: `chatId` is not bound to associate session context, preventing the model from continuously receiving dialogue status.
- Phenomenon: The model outputs multiple spaces and uppercase letters. Cause: Prompt words do not clearly specify rules for retaining document content format, leading the model to randomly modify text formatting.
- Phenomenon: File parsing tools cannot be invoked. Cause: Documents such as EL/IV test reports are not correctly bound to the `variables` variable pool, resulting in no matching data source for tool calls.

## How to Confirm Proper Configuration
- Initiate a dialogue containing a battery cell gear query, check whether corresponding batch EL images and IV test reports are automatically retrieved.
- Conduct 3 consecutive rounds of interactions regarding quotation parameters, check whether the output has no redundant formatting errors.
- View the session history, confirm that intermediate logs of plugin calls are not included in the current dialogue context.
- Submit a test tendering document request, check whether the model strictly follows prompt word requirements to call specified documents.
