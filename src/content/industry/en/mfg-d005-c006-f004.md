# Tender Document and Quotation Preparation for Photovoltaic Module Encapsulation: Workflow Orchestration

## What the data for this category looks like
Data for the photovoltaic module encapsulation link comes from battery sheet grading ledgers, glass adhesive film and backplane batch records, production MES systems, string welding and lamination equipment logs, EL/IV tester outputs, insulation voltage withstand test reports, and packing lists. The data update frequency is one corresponding record per module, with batch data synchronized for each batch of raw and auxiliary materials. Daily documents include module layout drawings, lamination process parameter sheets, EL defect images, IV power test reports, insulation voltage withstand records, and packing details. Fields include battery sheet current gear, lamination temperature/duration, crack coordinates, peak power value, and packing quantity. Units include watts, degrees Celsius, minutes, millimeters, and others.

## What constraints these characteristics impose on the workflow orchestration link
Photovoltaic module encapsulation data has fine granularity and high update frequency. This requires workflows to support real-time pulling of raw and auxiliary material ledgers and single-module test records for the corresponding bidding batch to avoid referencing expired data. The need to parse multiple types of documents requires workflow nodes to adapt to field extraction from files in different formats such as layout drawings, EL images, and IV reports. Parameters with specific units need unit verification rules bound during variable configuration to prevent confusion of power units. Tender documents need to aggregate multi-dimensional production data. Workflows must aggregate data by bidding project, and add abnormal interception nodes to block component records with excessive cracks or non-compliant power from entering the quotation link.

## How to set up the configuration
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| `variables` | Bind fields such as battery sheet current gear, lamination temperature, and peak power. The value ranges are `150–180 degrees Celsius` and `0–1000 watts`, calibrated based on actual measurements | Covers core production parameters for photovoltaic module encapsulation, ensuring consistency of data referenced in tender documents |
| Node trigger condition | Trigger by bidding project batch, execute data verification after a delay of `300 seconds` | Matches the synchronization cycle of production data to avoid pulling unfinished test records |
| External MCP plugin access | Configure to automatically call after triggering, set the timeout threshold to `600 seconds` | Adapts to the data upload delay of EL/IV testers to ensure complete test results are obtained |
| Code running node | Write field verification logic to block component records with power below the threshold | Filter unqualified component data in advance to prevent them from entering the quotation and tender document links |
| Knowledge base variable reference | Enable global variable permissions and bind the photovoltaic module encapsulation standard knowledge base | Quickly call industry-general encapsulation parameters to reduce manual entry workload |
| `nodeId` | Assign a unique identifier to each data node, and configure grouping by bidding batch | Avoid workflow node conflicts and facilitate troubleshooting of abnormal execution records |

## Three common errors
- Symptom: The code running node returns an empty result after execution, and the log shows that the target field was not read. Cause: The production data fields such as battery sheet current gear and peak power were not bound in `variables`, causing the code to fail to obtain the corresponding parameters.
- Symptom: The drop-down box for knowledge base variable reference has no optional content, and the encapsulation standard data cannot be called. Cause: Global variable permissions were not enabled, or the photovoltaic module encapsulation knowledge base was not added to the available data source list of the workflow.
- Symptom: The external MCP plugin call returns a timeout prompt, and the log shows that the request was not completed. Cause: The timeout threshold matching the production data synchronization cycle was not set, causing the workflow to time out while waiting for EL/IV test data.

## How to confirm the configuration is complete
- Manually trigger the workflow and check whether the fields bound by `variables` are correctly extracted from the production data ledger.
- Call the external MCP plugin and check whether the returned results include core data from the encapsulation link such as EL cracks and IV power.
- View the logs of the code running node to confirm that the field verification logic has been executed normally and unqualified records have been filtered.
- Open the knowledge base variable reference drop-down box and confirm that the bound photovoltaic module encapsulation knowledge base has loaded optional content.

The values provided are common starting points and should be evaluated against the reader's own samples.
