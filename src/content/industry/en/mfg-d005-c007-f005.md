# Bid Document and Quotation Preparation for Stamping and Sheet Forming: Tool Calling and Plugins

## What data for this category looks like
Data for this category comes from steel coil labels and quality certificates, press and feeder operation data, mold management systems, MES systems, coordinate measuring machine or fixture inspection data. Daily documents include stamping work instructions, material utilization rate tables, mold inspection logs, first/last piece records, dimensional inspection reports, and mold change records. Data is updated per coil of material, per batch of material, or each time a mold is changed. Document fields include material grade, material thickness, mold model, mold change time, dimensional deviation values from inspection, and similar. Common units are millimeters, tons, hours, and others.

## Constraints imposed by these characteristics on the "tool calling and plugins" link
This category has a high data update frequency. Tool calling must support high-frequency triggering to obtain the latest mold change, material batch, and inspection data. Daily documents are mostly structured tables, so plugins must adapt to table field extraction and accurately capture core parameters such as material grade and material thickness. Mold changes and material batches have a significant impact on forming stability. Tool calling must link to mold management and MES data for the corresponding batch, avoiding the use of outdated information across batches. There is a requirement to connect multiple data sources, so plugin configurations must be compatible with the interface formats of different systems to reduce data synchronization errors.

## Configuration guidelines
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | Auto | Adapts to the needs of multi-stage tool calling in bid documents, no need to manually specify a single tool |
| Workflow/API function-call configuration | Enabled | Supports structured tool calling results, facilitating organization into bid documents |
| Tool call timeout | 120 seconds | Stamping data comes from multiple system integrations; 120 seconds covers most data pulling and calculation processes |
| Single tool call limit | First 3 entries | Calibrated based on actual testing | Avoids timeouts caused by excessive data in a single call, adapting to the single-call volume of stamping data |
| Query optimization | Enabled | Optimizes requests for stamping-related technical parameters, improving the accuracy of parameters used in tool calls |
| Tool return result format | Structured table | Adapts to the table structure of stamping business documents, enabling direct reuse in bid documents |

## Three common mistakes
- Symptom: A global variable counter cannot be incremented automatically after configuration, and fields are empty after tool calling. Cause: The trigger condition of the variable update plugin was not bound to the tool call completion node, only the initial value of the variable was configured.
- Symptom: When calling a custom image generation plugin, all parameters are configured correctly but no results are returned. Cause: The plugin input field mapping was not adjusted for the multi-data-source connection logic of the stamping category, resulting in abnormal data transmission.
- Symptom: The material utilization rate data returned after tool calling does not match the actual batch. Cause: The mold and material data for the corresponding mold change batch were not bound before tool calling, and cached outdated information was used.

## How to confirm the configuration is complete
- Trigger a tool call and check if the returned results include the core fields required for stamping business. The matching degree of fields is calibrated according to business requirements.
- Check the tool call timeout logs to confirm that no timeout situations exceeding the preset threshold have occurred. Adjust the timeout threshold according to the response speed of the actually connected systems.
- Verify the global variable update logic. After triggering a tool call, check whether the variable value changes as expected, with the trigger condition bound to the tool call completion node.
- Check the parameter logs of plugin calls to confirm that the values of all configuration items match the preset settings, with no abnormal parameter omissions.

The values given are common starting points and should be measured against the reader's own samples.
