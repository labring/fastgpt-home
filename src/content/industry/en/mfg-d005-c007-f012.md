# Bid Document and Quotation Preparation for Stamping and Sheet Metal Forming: Deployment and Upgrade

## What Data for This Category Looks Like
Data for this category originates from steel coil labels and quality certificates, press and feeder operation data, mold management systems, MES systems, coordinate measuring machine or fixture inspection data. Daily associated documents include stamping work instructions, material utilization rate sheets, mold inspection sheets, first and last piece records, dimensional inspection reports, and mold change records. Data updates trigger per steel coil, production batch, or mold change. Fields include material grade, material thickness specification, mold number, mold change duration, measured dimensional deviation values, and additional relevant fields. Units include millimeters, tons, hours, and other standard units.

## Constraints Imposed by These Characteristics on Deployment and Upgrade
Dispersed data sources and non-fixed update trigger nodes require deployment to support synchronized access to multi-source heterogeneous data, and corresponding data pull scheduling rules must be configured. Frequent batch updates require storage resources to support high-concurrency writes, to avoid data lag during bid quotation preparation. Large variations in material and mold parameters across production batches require reserving field expansion space during deployment, to adapt to custom data entry for different batches. Bid documents must link to specific production data, so the deployment phase must ensure the mapping relationship between document templates and production data fields can be flexibly configured, to avoid quotation deviations caused by field mismatches.

## Configuration Settings
This page is compatible with FastGPT v4.17.0.

| Config Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30` | Adapts to concurrent read requirements for multi-source production data, prevents database connection exhaustion, and supports data synchronization from presses, MES, and mold management systems |
| `REDIS_URL` | `redis://localhost:6379` | Caches frequently called mold and material parameters, reduces backend database load, and adapts to frequent parameter query scenarios |
| `STORAGE_S3_ENDPOINT` | Internal enterprise object storage service address | Stores batch-uploaded stamping inspection reports, mold change records, and other documents, adapts to local storage requirements for private deployments |
| `FILE_TOKEN_KEY` | Random 32-character string | Generates secure file access tokens, prevents unauthorized access to uploaded production documents |
| Single file upload limit | `1000 MB` | Accommodates complete material utilization rate sheets, mold inspection sheets, and other documents for a single production batch |

## Three Common Misconfigurations
- An error indicating the missing rehype-raw module appears when building an image, even after running the installation command. The cause is that the build context does not include the dependency package directory, or the dependency installation step was not executed correctly in the Dockerfile.
- The service cannot be accessed and restarts continuously after Docker deployment. The cause is an incorrect `REDIS_URL` configuration that prevents establishment of a cache connection, or an excessively high `DB_MAX_LINK` setting that causes database connection timeouts.
- A client exception error displays in the workflow editing interface after offline private deployment. The cause is that `FE_DOMAIN` is configured with an external network address, preventing the frontend from loading local static resources.

## How to Verify Correct Configuration
- Run a database connection test to confirm the number of connections set by `DB_MAX_LINK` can normally support multi-source data synchronization tasks.
- Access the local intranet address configured in `FE_DOMAIN` to confirm the workflow editing interface loads normally, with no static resource loading failure prompts.
- Upload a stamping mold inspection sheet to confirm the file is properly stored in the storage service configured via `STORAGE_S3_ENDPOINT`.
- Simulate a parameter update after a single mold change to verify the data synchronization task completes the update within the preset cycle.

The values provided here are common starting points and should be measured against the reader's own samples.
