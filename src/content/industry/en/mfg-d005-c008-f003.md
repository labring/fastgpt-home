# Bid Document and Quotation Preparation for Cosmetics Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Cosmetics manufacturing bid-related data comes from registered and filed formulas, raw material safety documents, ERP/MES systems, production equipment, laboratory test results, and packaging material version information. Data updates per production batch or line change cycle. It includes formula process sheets, weighing and feeding records, emulsification and filling records, cleaning and sanitization records, semi-finished and finished product inspection reports, label review documents, and more. Data fields include raw material usage, production parameters, batch numbers, test results, etc. These fields dynamically generate alongside individual batch production processes, with no fixed unified statistical values.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering stage
Because data updates dynamically per batch, multi-turn dialogue must bind the exclusive identifier of the corresponding batch. This prevents cross-batch data confusion that leads to errors in bid documents. Because documents include compliance-heavy filed formulas and label content, prompts must explicitly specify reading compliance documents for the corresponding batch. This ensures generated content aligns with filing requirements. Because bid documents require combining multiple types of production and test data, multi-turn dialogue must call corresponding data step-by-step according to communication rhythm. This avoids loading too much irrelevant content at once that disrupts generation. Additionally, the dynamic update nature of data requires dialogue context to real-time associate with the latest batch data. Retaining historical content from old batches will cause generated content to mismatch current bid requirements.

## How to set the configurations
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| Maximum Context Length | 8000–12000 characters | Cosmetics manufacturing bid documents include multiple types of long text such as formula processes and inspection reports. This length must cover complete business data for a single batch. FastGPT v4.17.0 supports context loading of this length |
| `variables` | Calibrated based on actual testing | Exclusive variables such as batch numbers and filing numbers must be bound. This ensures dialogue only links to the production batch corresponding to the current bid, preventing cross-batch data confusion |
| `messages` Context Truncation Rule | Retain the last 12–15 dialogue turns | The communication logic for bid document preparation focuses on recent raw material specifications and quotation adjustments. Excessively long historical content will disrupt the accuracy of current generation |
| Document Reading Trigger Condition | Trigger based on batch keywords in `messages` | Only read filed formulas and production records for the corresponding batch. This avoids reading historical data from unrelated batches and improves compliance verification efficiency |
| Export Trigger Configuration | Generate a Word download link after dialogue completion | Bid documents must be quickly exported for internal review after preparation. This adapts to the immediate delivery requirements of the bid process |
| Permission Verification Switch | Enabled | Restrict access to bid-related filing and quotation data by unauthorized personnel. This protects enterprise commercial confidential information |

## Three common mistakes
- Phenomenon: The dialogue interface prompts "No permission to operate this conversation record". Cause: No permission verification rule based on `chatId` is configured, or the bound exclusive variables do not cover the production batch permission range corresponding to the current bid.
- Phenomenon: No Word download link appears at the bottom of generated dialogue content. Cause: No automatic export trigger rule is configured after dialogue ends, or the export configuration is not linked to the `messages` context content of the current dialogue.
- Phenomenon: The AI prompts that no files are uploaded and cannot read document content in the system prompt. Cause: Document reading is not triggered based on batch keywords in `messages`, or the bound `variables` do not point to the filed formulas and production documents of the corresponding batch.

## How to confirm the configuration is correct
- Input a test instruction that includes the specified batch number. Verify that the dialogue only calls the filed formulas and production records for the corresponding batch.
- Complete a complete bid document generation process. Confirm that a Word download link is generated at the bottom of the dialogue.
- Check the exclusive variables bound to `chatId`. Verify that only authorized personnel can access the dialogue content corresponding to the bid.
- Refresh the dialogue page. Confirm that existing dialogue records are not reset and the session identifier has not changed.

All configuration values listed here are common starting points. They should be evaluated against the reader's own samples and operational requirements.
