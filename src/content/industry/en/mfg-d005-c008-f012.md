# Bid Document and Quotation Preparation for Cosmetics Manufacturing: Deployment and Upgrade

## What the data for this category looks like
Cosmetics manufacturing business data covers full-process documents for skincare, haircare, makeup, and special cosmetics production enterprises, including formula sheets, weighing and feeding records, emulsification or filling records, cleaning and sanitization records, semi-finished and finished product inspection reports, and label review documents. Data sources include registered or archived formulas, raw material safety materials, production equipment, ERP/MES systems, laboratory test results, and packaging material version files. Updates are triggered per production batch or each production line changeover. Each document includes fixed fields such as raw material name, archive number, batch number, operation time, and compliance mark. There are no unified fixed units, and matching is flexible based on document type.

## What constraints these characteristics impose during deployment and upgrade
Because business data is updated at high frequency per batch or production line changeover, deployments must support high-frequency read/write operations and caching to avoid data query delays. Differences in structure across multiple types of business documents require deployment configurations to adapt to index rules for different documents, ensuring accurate matching of corresponding data when generating bid documents. Cosmetic formulas and labels are subject to archive requirements, so deployments must configure data traceability and access control to prevent leaks of sensitive archive data. Bid document and quotation preparation requires association of formula, packaging material, and ERP data, so deployments must enable cross-system data connections to ensure data consistency. Additionally, synchronization requirements for local code modifications and compatibility with containerized deployments also place clear requirements on deployment configurations.

## How to set configurations
| Configuration Item | Suggested Value | Rationale |
|---|---|---|
| `DB_MAX_LINK` | `10–15 entries` | Matches high-frequency data read/write requirements per production batch, prevents service interruptions caused by exhausted database connections |
| `REDIS_URL` | `password-authenticated cloud-hosted Redis instance` | Caches frequently queried archived formula and label data to reduce database access pressure |
| `STORAGE_S3_ENDPOINT` | `endpoint address compliant with domestic compliance storage requirements` | Ensures compliant storage and access for sensitive data such as raw material safety materials and archived documents |
| `FE_DOMAIN` | `public network domain name of the deployment server` | Resolves cross-domain access issues between frontend pages and backend interfaces, ensuring normal invocation of bidding tools |
| `ROOT_KEY` | `32-bit randomly generated string` | Configures access keys for administrator operations, ensuring operational security of the deployment backend |
| `FILE_TOKEN_KEY` | `signature key with a 24-hour validity period` | Generates temporary access permissions for attachments in bid documents, preventing leaks of sensitive files |

## Three common mistakes
- Issue: Port occupation or file permission errors occur during docker-compose deployment. Cause: The permission configuration of the local business document mount directory is not set to match the container runtime user, resulting in failure to read core business data such as archived formulas.
- Issue: After upgrading to FastGPT v4.17.0, the knowledge base cannot handle follow-up questions, and subsequent answers are disconnected from the context. Cause: The `REDIS_URL` parameter is not configured correctly, causing context cache to fail to store and read normally.
- Issue: Deployment instances do not synchronize updates after local code modifications, and pages show no changes. Cause: The local code directory is not mapped to the corresponding working path in the container, or the container is not restarted to load updated code files.

## How to confirm configurations are correct
- Access the frontend address corresponding to `FE_DOMAIN`, verify that the page loads normally and can call interfaces to query archived formula data.
- Execute a database connection test, confirm that the `MONGODB_URI` and `PG_URL` parameters are configured correctly and can read and write business documents normally.
- Upload a cosmetics label review document, verify that the storage service configured with `STORAGE_S3_ENDPOINT` can store and read attachments normally.
- Log in to the deployment backend using `ROOT_KEY`, confirm that all configuration items are active and there are no abnormal error logs.

The values provided here are common starting points and should be evaluated against the reader's own samples.
