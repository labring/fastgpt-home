# Bid Document and Quotation Preparation for Chemical Pharmaceutical Dosage Form Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What Data Looks Like for This Category
Business data sources for chemical pharmaceutical dosage form manufacturing include approved prescription processes, MES/electronic batch records, LIMS, and quality management systems. Daily documents include master production files, batch production records, batch packaging records, cleaning records, inspection records, deviations/CAPA/change requests, and batch release review forms.
Data updates follow a rhythm tied to each batch, each critical step, and monitoring plans. Document fields include material batch numbers, process parameter values, deviation IDs, inspection results, and related items. Corresponding units include quality units, temperature parameters, batch number formats, and related specifications.

## Constraints on Multi-turn Dialogue and Prompt Engineering
Data for this category updates independently per batch and is linked to multiple types of system documents. Multi-turn dialogue must accurately bind to the batch associated with the current bid project to avoid mixing data across batches.
Document structures are complex and must meet compliance requirements. Prompts must explicitly specify associated document types and field ranges to prevent generation of non-compliant content.
Data from multiple system sources must be validated for consistency during dialogue. Prompts must guide linking corresponding fields across different systems to ensure bid documents and quotation preparation content accurately match actual execution data for the current batch.
Data updates occur frequently. Conversation context scope must be limited to only interaction records for the current project and batch.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Generate a unique ID using bid project + batch number | Isolate conversation contexts across different projects and batches to avoid data mixing |
| `messages` | Divide conversation history by batch, only retain interaction records for the current batch | Adapt to independent business data per batch, prevent interference from cross-batch context |
| `variables` | Bind material batch number and process version number fields | Accurately link to business documents for the corresponding batch, ensure prompts can access accurate data |
| Conversation context window | First 10 rounds of conversation + historical content within 8000 tokens | Calibrated through actual testing, avoid context overload that impacts generation accuracy |
| Search recall limit | Top 6 matching documents | Meet compliance requirements, avoid interference from redundant information |
| Frontend output module binding | Only bind bid document generation module | Isolate output content across different links, ensure clear page display |

## Three Common Misconfigurations
- Phenomenon: Prompts do not take effect, generated bid documents do not include material data for the specified batch. Cause: Batch number fields are not bound in `variables`, so prompts cannot access corresponding business data.
- Phenomenon: Dialogue returns multiple unrelated batch record contents, exceeding the expected number of results. Cause: A reasonable search recall limit is not set, or the project scope of `chatId` is not restricted.
- Phenomenon: The frontend page displays output content from multiple modules at once, making it impossible to distinguish bid documents from quotation details. Cause: Exclusive frontend output modules are not bound per project, and interaction results across different links are not isolated.

## How to Verify Proper Configuration
- Enter the material batch number for a specified batch, check if the generated bid document automatically links to process and inspection data for that batch.
- View the conversation history panel, confirm only interaction records for the current bid project and batch are retained, with no old cross-batch data present.
- Trigger multi-turn follow-up questions, check if prompts can guide the generation of quotation details and document content that meet compliance requirements.
- Check the frontend page, confirm only output results from the current module are displayed, with no content from other unrelated modules.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
