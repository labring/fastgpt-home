# Tender Document and Quotation Preparation for Pharmaceutical Dosage Production: Workflow Orchestration

## What Data for This Category Entails
Data for pharmaceutical dosage production comes from approved formulation processes, material batch information, MES systems, electronic batch records, equipment and environmental monitoring data, LIMS systems, and quality management systems. Daily generated documents include master production files, batch production records, batch packaging records, cleaning records, inspection records, deviation/CAPA/change documents, and batch release review forms. Data updates align with each production batch, each key process step, and established monitoring plans. Document fields include material batch numbers, process parameter values, test result values, deviation descriptions, and other relevant fields. Units cover mass units, volume units, temperature units, and additional measurement units.

## Constraints on Workflow Orchestration
Dispersed data sources and dynamically changing update frequencies tied to production batches require workflows to support real-time data pulling from multiple systems. Manual data entry delays must be avoided. Document structures include multiple types of compliance records. Workflows must connect data across all links in accordance with GMP requirements. This ensures complete batch records, test results, and deviation handling documents can be accessed when preparing tender documents and quotations. Material parameters and process data vary across different batches. Workflows must support dynamic reading of variable data for the corresponding batch. Fixed templates should not be used to cover all scenarios. Data must pass quality release verification before being included in the preparation process. Compliance verification nodes must be embedded in workflows.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `variables` | Bind each batch's material batch number, process parameters, and test results as independent variables, using actual data from the corresponding batch, calibrated via actual measurement | Each batch of data for pharmaceutical dosage production varies, requiring dynamic calling of corresponding batch `variables` to complete parameter filling for tender documents and quotations |
| `nodeId` | Assign unique `nodeId` values to compliance verification nodes and data pulling nodes, using custom node identification strings | Facilitates precise positioning of each link's nodes in the workflow, enabling data updates and verification triggered by specific nodes |
| Global Variables | Preset GMP compliance verification rules and standard material unit price libraries, using fixed compliance rule libraries and approved price ranges, calibrated via actual measurement | Tender documents must comply with GMP requirements, and standard unit price libraries can quickly generate basic quotation data |
| Tool Call Timeout | 600 seconds | Pulling data from multiple systems and conducting compliance verification requires extended processing time, to avoid workflow interruptions due to timeout |
| Workflow Branch Triggering | Trigger subsequent preparation nodes based on batch release status | Batch data that fails quality release cannot be used for tender preparation, ensuring only compliant data enters subsequent links |

## Three Common Mistakes
- Symptom: After workflow execution, global variables do not update based on tool call results. Corresponding fields remain empty or retain initial values. Cause: The update binding logic for `variables` was not correctly configured in the tool call node, leading to unsynchronized variable modifications.
- Symptom: The configuration entry for custom reference templates and prompt words cannot be located. Only a small number of basic parameters can be adjusted. Cause: The installed FastGPT version is lower than v4.9.7. This function is supported in v4.9.7 and FastGPT v4.17.0 and later.
- Symptom: Duplicate or misaligned data pulled from multiple systems in the workflow, resulting in parameter errors in tender documents. Cause: Unique `nodeId` values were not assigned to each data pulling node, causing confusion in cross-node data calls.

## How to Confirm Proper Configuration
- Manually trigger the workflow, and check if each data pulling node correctly pulls material, process, and test data for the corresponding batch.
- After calling the tool node, verify if `variables` are synchronously updated to the actual data returned by the tool.
- Trigger the branch node, and confirm that only batch data passing quality release can enter subsequent document and quotation preparation links.
- Check if the compliance rules and unit price library in global variables match approved standards.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
