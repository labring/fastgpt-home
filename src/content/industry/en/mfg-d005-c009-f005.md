# Bid Document and Quotation Preparation for Pharmaceutical Dosage Form Manufacturing: Tool Calling and Plugins

## What Data for This Category Looks Like
Data related to pharmaceutical dosage form manufacturing is generated by production, quality assurance, quality control, and warehouse departments. Core documents include master production files, batch production records, batch packaging records, cleaning records, inspection records, deviation/CAPA/change documents, and batch release review forms. Data sources include approved formulation processes, MES/electronic batch records, equipment and environmental monitoring systems, LIMS, and quality management systems. Update frequency follows per batch production, each critical process step, and per established monitoring plans. This category must comply with GMP requirements. Documents must be synchronized with production operations, and batch record review and change control requirements are stricter than those for general food production categories.

## Constraints for Tool Calling and Plugins
The scattered data sources and high update frequency of this category require tool calling to support plugins that connect multiple production and quality management systems. Trigger timing must be tied to specific production nodes to avoid pulling outdated data. Document compliance under GMP requirements means content returned by tools must fully match the standard fields of batch records, and no key information may be omitted. Bid document and quotation preparation requires precise use of material batches, process parameters, and inspection results. As such, parameter mapping for tool calling must strictly correspond to the field names of each system, to prevent compliance issues caused by data misalignment. The need to batch summarize multiple batch records requires plugins to support batch data pulling and initial field validation. Additionally, multi-question query requirements in bid scenarios require tool calling to support simultaneous calls to the knowledge base to obtain multiple types of compliance data.

## How to Configure
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool calling trigger timing | Tied to batch production critical node completion events | Data is updated per critical step, latest compliant data must be pulled after node completion |
| Parameter mapping rules | One-to-one mapping per batch production record field names | Must accurately match GMP-required fields such as material batches and inspection results |
| Data source plugin configuration | Connect 3 plugins: MES, LIMS, QMS | Business data comes from these three types of production and quality management systems |
| Result validation threshold | 100% field integrity check pass rate | Batch record review must be complete and free of omissions, in compliance with GMP requirements |
| Context window size | 8000 token | Need to summarize content from multiple batch records and bid-related documents |

During configuration, enable `toolChoice` in auto mode, and configure field validation rules for `functionCall` to ensure tool calling meets business and compliance requirements.

## Three Common Configuration Errors
- Phenomenon: File links uploaded for simple tasks cannot be passed to workflows configured as tools, and the corresponding fields are empty. Cause: No mapping rule for file links to workflow input parameters is configured, and the file transfer plugin is not enabled.
- Phenomenon: A single knowledge base call only returns one result, which cannot cover multiple bid-related questions. Cause: No trigger logic for multi-round knowledge base calls is configured, and no rules for batch queries are set.
- Phenomenon: Material data returned by tool calling does not match batch records, and field misalignment occurs. Cause: Parameter mapping rules are not configured according to the standard field names of batch records, leading to incorrect data matching.

## How to Verify Proper Configuration
- Trigger the preset batch production critical node event, and verify whether the tool automatically starts data pulling as configured.
- Upload a test batch record file, and verify whether parameters are correctly mapped to the tool's input fields.
- Call the tool to generate bid document fragments, and verify whether the returned content includes compliant GMP-related fields.
- Simulate a multi-question query scenario, and verify whether the knowledge base returns relevant data for the corresponding batch as configured.

The values provided are common starting points and should be measured against the reader's own samples.
