# Bid Document and Quotation Preparation for Pharmaceutical Dosage Form Production: Model Access and Configuration

## Data Profile for This Category
Data related to pharmaceutical dosage form production comes from approved formulation processes, material batch information, MES systems, electronic batch records, equipment environmental monitoring data, LIMS and quality management systems. Daily documents include master production files, batch production records, batch packaging records, cleaning records, inspection records, deviation/CAPA/change documents, and batch release review forms. Data is updated per production batch, each key process step, and monitoring plan. Document fields include material batch numbers, process parameters, test results, deviation handling details, and other information. It must comply with GMP-compliant document and operation synchronization specifications.

## Constraints for Model Access and Configuration
Data for this category updates per batch and process step, and must align with GMP requirements for document and operation synchronization. As a result, model access must support associating context by batch dimension to prevent cross-batch data mixing. Daily documents include multiple types of structured records, with fields covering material batch numbers, process parameters, test results, and other details. The model must adapt to output formats from multiple source systems, and accurately identify compliance-related fields. Batch record review and release judgment rely on full-process data aggregation. The model must handle line-by-line review of long texts and deviation integration, while ensuring data processing accuracy to avoid compliance risks.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `maxContext` | 8000–12000 token | Adapt to context loading for long texts such as batch records, avoid truncating key process and compliance information |
| `maxTokens` | 4000 token | Match the output length requirements for bid documents and quotation preparation, ensure complete generation of compliance descriptions and quotation details |
| `temperature` | 0.1–0.3 | Reduce output randomness, ensure the rigor of GMP-related statements, avoid non-compliant content |
| `AIPROXY_API_ENDPOINT` | Fill in according to the proxy address of the FastGPT deployment environment | Adapt to local or cloud deployment paths, ensure normal forwarding of model requests |
| `AIPROXY_API_TOKEN` | Consistent with the third-party model key bound | Ensure valid identity verification for model access, connect to configured model services |

## Three Common Mistakes
- Phenomenon: Model calls return a 401 unauthorized error, or prompt that the key is invalid. Cause: `AIPROXY_API_TOKEN` is not configured correctly, or the bound third-party model key has not completed test verification, leading to identity verification failure.
- Phenomenon: Request timeout or concurrency restriction error occurs when processing multiple batches of data in bulk. Cause: Concurrency configuration is not adjusted for multi-batch parallel requests, and multi-data parallel processing requirements in the pharmaceutical dosage form production scenario are not met.
- Phenomenon: Missing fields or chaotic formatting appear in bid documents generated by the model. Cause: Data such as material batches and process parameters are not imported in structured format, and unstructured original documents cannot be accurately identified and integrated by the model.

## How to Verify Successful Configuration
- Initiate a text import test for a single batch record, check whether the context length loaded by the model meets expectations, and confirm that the `maxContext` configuration takes effect.
- Submit a compliance review request, check the rigor of the model's output statements, and confirm that the `temperature` configuration matches the scenario requirements.
- Verify the identity verification process for model calls, confirm that the `AIPROXY_API_TOKEN` and `AIPROXY_API_ENDPOINT` configurations are correct, and there are no call errors.
- Use the model access module of FastGPT v4.17.0 to conduct parallel tests for multiple batches of data, confirm that parallel requests can be processed normally, with no timeout or authorization exceptions.
