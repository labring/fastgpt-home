# Bid Document and Quotation Preparation for Medical Device Assembly and Clean Production: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data for this category comes from design history files, device and material batch records, manufacturing execution systems, clean environment monitoring equipment, sterilization equipment, and inspection and calibration systems. Daily documents include production process specifications, batch production records, clean zone operation records, sterilization batch records, inspection reports, software version records, adverse event and traceability materials. Data is updated per production batch or single device, and clean environment monitoring data is updated regularly per a predefined schedule. Data fields include unique device identifiers, material batch numbers, cleanliness parameters, sterilization parameters, inspection results, and other relevant items.

## What constraints do these characteristics impose on multi-turn dialogue and prompt configuration
The batch-based and compliance requirements of data for this category impose clear constraints on multi-turn dialogue and prompt configuration. Bind all batch data associated with a single bid project via `chatId` to avoid mixing information across batches. Pass specified parameters such as batch numbers and unique device identifiers via `variables` in prompts, to ensure dialogue content accurately matches corresponding production records. Limit the length of the `messages` context to prevent mixing clean zone records from unrelated batches, and explicitly require that only compliant document fields corresponding to the current bid project are referenced during dialogue. Additionally, bid documents must integrate multiple types of compliant documents, and multi-turn dialogue must guide the extraction of key information from different documents in sequence to avoid missing core compliance items.

## How to set the configuration
This configuration is based on the functional logic of FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind the unique identifier of the current bid project | Ensure dialogue contexts within the same project do not get mixed, and meet batch data traceability requirements |
| `messages` | Limit context length to 800–1200 characters | Avoid mixing unrelated batch data in overly long contexts, and adapt to the information volume of a single bid document |
| `variables` | Pass fields such as batch numbers, unique device identifiers, and sterilization parameters | Accurately match corresponding production record data, and meet bid compliance requirements |
| Question Optimization | Enable | Automatically sort out the compliance fields required for bidding, and reduce manual input errors |
| Max Dialogue Turns | First 8 turns | Control the complexity of the dialogue flow, and focus on the core goals of bid document and quotation preparation |
| Response Timeout | 600 seconds | Adapt to the time required for retrieval and organization of compliant documents |

## Three common mistakes
- Empty results displayed in the front-end after starting a dialogue, or the model returns a clear error message. Cause: Key parameters such as batch numbers and unique device identifiers are not passed via `variables`, causing the dialogue to fail to match corresponding production record data, which triggers empty model output or compliance verification failure.
- The dialogue cannot read specified online document content. Cause: Document access permissions are not configured, or the field range of the document is not explicitly specified in the prompt, resulting in failure to obtain corresponding production record data.
- Records are not cleared after calling the delete dialogue interface. Cause: The `chatId` parameter is not passed correctly, so the interface cannot locate the target dialogue, resulting in failed deletion operations.

## How to confirm the configuration is correct
- Start a dialogue, pass a known production batch number parameter, and check whether the dialogue output includes key content from the corresponding sterilization batch record.
- Check the dialogue context length to confirm it does not exceed the set 800–1200 character range, and there is no redundant data from unrelated batches.
- Test the delete dialogue interface, pass the `chatId` of the current project, and confirm that the interface returns a success status and the dialogue record is cleared.
- After enabling the Question Optimization switch, start a dialogue, and check whether the compliance field list required for bidding is automatically sorted out.
