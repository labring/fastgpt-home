# Tender Document and Quotation Preparation for Medical Device Assembly and Cleanroom Production: Workflow Orchestration
This document is compatible with FastGPT v4.17.0.

## What the data for this category looks like
Daily documents for this category include production process specifications, batch production records, cleanroom area records, sterilization batch records, inspection reports, software version records, adverse event and traceability materials. Data sources are design history files, device and material lots, MES systems, clean environment monitoring equipment, sterilization equipment, inspection and calibration systems. Data update frequency is upon completion of each batch or unit of product, and at regular intervals per the clean environment monitoring plan. Data fields include unique device identification, material lot number, clean environment parameters, sterilization parameters, inspection results, etc., with no uniform fixed single data length.

## What constraints do these characteristics impose on workflow orchestration
This category’s data has scattered sources and strict association requirements. Workflow orchestration must connect multiple heterogeneous data source nodes to ensure complete retrieval of multi-dimensional data including production, environment, sterilization, and other dimensions. The batch-based data update feature requires the workflow to support triggering by single-batch or multi-batch production tasks to avoid redundant execution. The strong compliance requirements for documents and traceability materials mean the workflow must retain parameter traceability paths for each stage to facilitate compliance verification during tendering. Additionally, the non-standardized nature of data fields requires the workflow to be configured with flexible parameter mapping rules to adapt to differences in document structures across batches.

## Configuration Settings
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| Variable Definition | Bind `variables` to unique device identification, material lot number, and sterilization parameter fields | Tender documents must be associated with corresponding production data to ensure that quotations match actual production information |
| Node ID Binding | Name `nodeId` by data source type, such as mes-data, sterilize-record | Facilitates workflow debugging and traceability, enabling quick location of data retrieval nodes |
| Trigger Rule | Trigger after each batch of production is completed | Matches the business characteristic of data updating per batch or unit |
| Cycle Processing Scope | Traverse the first 100 batch data entries | Adapts to the production batch scale covered by a single tender, avoiding system resource overload |
| Document Mapping Length | 800–1200 characters | Complies with typesetting specifications for medical device tender documents |
| Timeout Setting | 600 seconds | Reserves reasonable time for complex data verification and compliance checks |
| Parameter Verification Threshold | Calibrate based on actual measurements | Meets compliance verification requirements for medical device data |

## Three Common Mistakes
- Adding a custom plugin to a workflow without input and output parameters, with no error logged. The cause is that the input fields required by the plugin are not declared in `variables`, causing parameters to not be loaded by the system.
- Array parameters are not correctly traversed during cycle runs, and only the entire array is displayed on the input end. The cause is that the input of the cycle body is not configured as a single-element node split from the array, and the original array is bound directly.
- The workflow cannot export configuration files. The cause is that the global export permission switch for the workflow is not enabled, or the node contains unsaved temporary configurations.

## How to Confirm Proper Configuration
- Trigger a test batch workflow, check whether the production data fields for the corresponding batch are correctly loaded in `variables`.
- Run the cycle node, confirm that array elements are passed one by one to subsequent AI sessions or data processing modules.
- Verify that the input and output fields of the custom plugin are displayed normally in the node configuration panel.
- Attempt to export the workflow configuration, confirm that the export process has no errors and the generated configuration file is complete.

The values provided here are common starting points and should be measured against the reader's own samples.
