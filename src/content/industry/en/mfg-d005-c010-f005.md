# Bid Document and Quotation Preparation for Medical Device Assembly and Clean Production: Tool Calling and Plugins

## What This Category’s Data Looks Like
Data sources for this category include design history files, device and material batch records, MES systems, clean environment monitoring equipment, sterilization equipment, and inspection and calibration systems.
Daily documents include production process specifications, batch production records, clean zone operation records, sterilization batch records, inspection reports, software version records, adverse event and traceability materials.
Data is updated once per batch or per product unit. Clean environment data is synchronized regularly per monitoring plans.
Document fields include unique device identifiers, material batch numbers, sterilization parameters, clean zone temperature and humidity, inspection results, and more. Some fields must comply with controlled format requirements for medical devices.

## Constraints for Tool Calling and Plugins
The batched updates and multi-type controlled document characteristics of this category’s data require tool calling to support task triggering based on production batches. This prevents calling historical data not associated with the current bid batch.
The need to parse multiple types of controlled documents requires plugins to adapt to different formats of production records and inspection reports. It must accurately extract core fields such as unique identifiers and sterilization parameters.
Compliance traceability requirements for data mean that tool calling must automatically associate call logs with corresponding batch records. This facilitates subsequent audits.
The regular update cycle of clean environment data requires that plugin calls be limited to valid windows after data synchronization. This prevents use of expired monitoring data.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | Adapts to automatic tool calling needs for multi-type content in bid documents, no manual specification of call functions required |
| Workflow/API function-call configuration | Trigger based on controlled fields | Matches controlled fields such as unique device identifiers and sterilization parameters that require verification in category documents, ensuring compliance of called data |
| Custom plugin trigger rules | Match by production batch number | Associates production batch data corresponding to the current bid, avoids calling historical records from unrelated batches |
| Document format adaptation switch | Enable multi-document parsing for up to 5 files | Adapts to category-specific document formats such as batch production records and clean zone records, accurately extracts core fields |
| Timeout threshold | 120 seconds | Covers processing duration of complex tasks such as sterilization parameter verification and multi-document splicing, prevents mid-task interruptions |
| Number of rearranged results | Top 5 | Focuses on the most core compliance and parameter information in bid documents, improves content accuracy |
| Log retention configuration | Retention period calibrated through actual testing | Meets compliance audit requirements for medical device traceability, facilitates subsequent verification of tool calling processes |

## Three Common Mistakes
- Symptom: Connection failure or empty results are returned when calling a rerank service from a custom channel. Cause: The interface address and authentication parameters of the custom channel are not configured correctly, preventing connection to the target service.
- Symptom: Tool calling does not trigger document parsing logic. Bid documents lack sterilization parameter or clean zone temperature and humidity data. Cause: The category-specific document format adaptation switch is not enabled. This fails to recognize core fields in batch production records and sterilization batch records.
- Symptom: After multiple AI calls in a workflow, the final output includes redundant content from previous AI generations. Cause: No filtering rules for result aggregation are configured. There is no clear requirement to retain only aggregated content from the last tool call and AI generation.
