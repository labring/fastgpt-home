# Bid Document and Quotation Preparation for Medical Device Assembly and Cleanroom Production: Deployment and Upgrade

## What data for this category looks like
Data for this category originates from design history files, device and material lots, MES systems, cleanroom environment monitoring equipment, sterilization equipment, inspection and calibration systems. Daily documents cover production process specifications, batch production records, cleanroom zone records, sterilization batch records, inspection reports, software version records, adverse event and traceability materials. Data updates occur once per product batch or unit, or at regular intervals per the cleanroom environment monitoring plan. Data fields include unique device identifiers, sterilization parameters, cleanroom environment metrics, software version numbers and other specialized content. These fields must be strictly aligned with controlled documents across the entire production workflow.

## What constraints these characteristics impose during deployment and upgrade
Data sources span multiple systems and equipment across the entire production workflow. Multi-data source connection parameters must be configured during the deployment phase to ensure correct synchronization logic for different document types. Data updates are frequent and tied to product batches. During the upgrade phase, the stability of incremental synchronization mechanisms must be verified to avoid timeouts during bulk data processing. Specialized fields such as unique device identifiers and sterilization parameters require clear mapping rules in configurations to prevent missing fields or matching errors during bid document generation. Additionally, data traceability requirements must be addressed in storage configurations, ensuring document storage paths and access permissions comply with industry regulations.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://[username]:[password]@[host address]:[port]/fastgpt?authSource=admin` | Stores multiple types of data including bid documents, production records, traceability materials, requires specifying authentication source and dedicated database name |
| `REDIS_URL` | `redis://:[password]@[host address]:[port]/0` | Caches intermediate results of batch validation and cleanroom environment monitoring data snapshots. Database 0 isolates business cache to avoid interference |
| `STORAGE_S3_ENDPOINT` | `https://s3.[region].cloud.tencent.com` (or corresponding compliant cloud storage endpoint) | Stores large-volume documents such as sterilization batch records and inspection reports, meets industry-compliant storage requirements |
| `DB_MAX_LINK` | `20–30` | Connects to multiple data sources including MES and sterilization equipment, prevents data synchronization interruptions caused by exhausted connection limits |
| `FE_DOMAIN` | `https://[legitimate enterprise bid system domain name]` | Generates preview links with compliant domain names when creating bid documents, meets display specifications |

## Three common errors
- Symptom: The FastGPT aiproxy container exits automatically shortly after startup, with curl execution failure errors. Cause: Access permissions for `MONGODB_URI` or `REDIS_URL` are not configured correctly, preventing connection to dependent services.
- Symptom: After upgrading to FastGPT v4.17.0, workflows cannot read custom environment variables, returning empty fields. Cause: Custom environment variables to expose are not declared in the Docker deployment configuration, so workflows cannot call unconfigured variables directly.
- Symptom: When generating bid documents in bulk, unique device identifier fields are missing for some devices. Cause: The device lot field from the MES system is not correctly mapped to the bid document template, resulting in field misalignment during data synchronization.

## How to confirm the configuration is correct
- Run the `docker logs fastgpt-aiproxy` command to check container logs, and confirm there are no error messages related to connecting to `MONGODB_URI` or `REDIS_URL`.
- Add an environment variable call node in a FastGPT workflow, enter a preset custom variable name, and verify that the returned value matches the preset content.
- Upload a sterilization batch record document to the knowledge base, and test that the retrieval function correctly matches specialized fields such as sterilization parameters and unique device identifiers.
- Trigger a bulk bid document generation task, and check that the generated documents include complete cleanroom zone records, inspection report links and compliant fields.

The values provided are common starting points and should be evaluated against the reader's own samples.
