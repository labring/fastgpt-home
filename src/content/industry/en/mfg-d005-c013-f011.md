# Printing and Packaging Processing: Bid Document and Quotation Preparation - Forms and Interactions

## Data included in this category
This category covers color printing, label, carton, flexible packaging, and pharmaceutical packaging material processing enterprises. Daily generated documents include pre-press files, imposition sheets, printing process sheets, ink color matching records, first article sample approvals, barcode detection records, die-cutting and lamination records. Data comes from customer manuscripts, color management systems, printing press data, ink and substrate batch records, spectrometers, and barcode detectors. It updates per order, per batch, or each time plates are changed. Fields include plate version number, substrate batch number, die-cutting size, barcode check value, and more. Formats must follow industry general standards.

## Constraints for forms and interactions
Data for this category updates in real time per order, batch, or plate change. This requires forms to bind to real-time data sources, and prohibits use of static cached data. Multiple document types must be linked to the same bid document. This requires forms to support split input by module, separating sections such as content, packaging parameters, and quotation details. Field formats must strictly comply with standards. For example, barcodes must meet GS1 standards, die-cutting sizes must match production equipment ranges. This requires forms to include targeted validation rules. Additionally, handling requirements for content versions, colors, and packaging structures means forms must support multi-dimensional selection components, to avoid mixing parameters of different categories.

## Configuration settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `formInput` | Split into three sub-modules by document type: Bid Document Content, Packaging Parameters, Quotation Details. Bind each module to corresponding data source fields | This category has many documents that update per order or plate change. Splitting into modules avoids field confusion, and binding to data sources pulls the latest data in real time |
| `userSelect` | Preset options for pre-press file version, substrate batch, and ink model, support manual supplementary input | Data for this category comes from batch production records. Preset options reduce input errors, and manual supplementation adapts to temporary custom order needs |
| Field validation rules | Configure barcode format validation (compliant with GS1 standards), plate version number format validation, die-cutting size range (10–2000 millimeters) | Errors in this category have serious consequences. Format validation intercepts incorrect data early, avoiding full batch scrap |
| Data pull trigger timing | Trigger pull operations each time the form is opened | Data for this category updates per order or plate change. Real-time pulling ensures the form displays the latest version |
| Context length | 800–1200 characters, calibrated via actual testing | Bid documents include multiple types of document fragments. This length covers core content while avoiding interference from redundant information |
| Data pull timeout | 600 seconds | Sufficient response time must be reserved when connecting to production systems. A finite timeout avoids long-term blocking |

## Three common misconfigurations
- Symptom: The form's data source selection dropdown refreshes continuously, making it impossible to reliably select the target option. Cause: Data pull trigger timing was not configured, causing the system to frequently call external production data sources to pull data.
- Symptom: The form returns a barcode validation failure after submission, but does not clearly prompt the specific error format. Cause: Targeted field validation prompt text was not configured, only a generic error message was returned.
- Symptom: Packaging parameters and content parameters for bid documents are displayed together, causing confusion for reviewers. Cause: The `formInput` module split configuration was not used, placing input fields of different categories under the same section.

## How to confirm correct configuration
- Open the form for the corresponding custom order, check that the pulled substrate batch number and plate version number match records in the production system.
- Manually enter barcode content that does not meet GS1 standards, verify that a format validation prompt is triggered.
- Switch the pre-press file version option, confirm that the document content in the form updates synchronously.
- Submit the form without filling in required fields, verify that a required field intercept prompt is triggered.

The values provided are common starting points and should be measured against the sample data of the target deployment.
