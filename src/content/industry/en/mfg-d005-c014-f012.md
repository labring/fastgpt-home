# Bid Document and Quotation Preparation for Dyeing and Finishing: Deployment and Upgrade

## What this category's data looks like
Data for this category comes from customer color swatches, formula libraries, dye batch records, dye vat control equipment, colorimeters, setting machines, and environmental monitoring systems. Daily documentation includes dyeing formulas, material weighing records, dye vat curves, proofing confirmation sheets, color difference reports, setting process sheets, and sewage ledgers.
Data is updated per vat, per batch, and per shift. Fields include dye model, feeding amount, vat number, batch number, temperature parameters, color difference values, drainage volume, and more. Units include grams, liters, degrees Celsius, multiples, and others. This is wet chemical batch processing data, with core records tied to color judgment and formula scaling.

## What constraints these characteristics impose on deployment and upgrade
The multi-source data updated per vat, per batch, and per shift for this category requires deployment phase support for direct data access from equipment such as dye vat control systems and colorimeters. It also requires unified storage for both structured and unstructured documents including dyeing formulas and dye vat curves.
Generating bid documents and preparing quotations must match business field rules for dyeing formulas, color difference reports, and related content. During the upgrade phase, consistent migration of historical data such as dye batch records and sewage ledgers must be ensured, to avoid quotation deviations caused by data disconnection.
Since color judgment and formula scaling in wet chemical processing rely on precision, a data verification link must be configured during deployment to ensure the association logic between dyeing parameters and quotation calculations. During upgrades, format adaptation for historical data such as old-version dye vat curves and sewage ledgers must be supported.

## How to set configurations
All configurations below are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30 entries per second` | Matches the high-frequency data write rhythm per vat and per batch |
| `STORAGE_S3_ENDPOINT` | Existing enterprise S3-compatible storage endpoint, allocate 1000 MB of storage space | Adapts to storage needs for multiple document types including dyeing formulas and dye vat curves |
| `PG_URL` | Corresponding enterprise existing PostgreSQL instance address | Stores structured business data such as dyeing formulas and color difference reports |
| `REDIS_URL` | Locally independently deployed Redis instance | Caches real-time business data such as dye vat data and color difference reports |
| `FILE_TOKEN_KEY` | `32-bit random string` | Ensures access authentication for sensitive documents such as dyeing process sheets and color difference reports |
| `ROOT_KEY` | `For internal operation and maintenance teams only` | Restricts background configuration permissions for bid document and quotation preparation |

## Three common mistakes
1. After deployment, the service continuously consumes resources. Automatic shutdown does not activate when the balance shows a negative value. No balance warning logs appear in the background. This occurs because resource consumption thresholds and automatic shutdown rules are not configured.
2. Dependency package installation fails during deployment. The interface prompts that pnpm version 9.0 or higher is required. An error appears when running the npm install command. This occurs because the local pnpm version is lower than the required version.
3. After local deployment, accessing the page shows an invalid certificate prompt. A security warning displays in the browser. This occurs because the SSL certificate path and the binding relationship for `FE_DOMAIN` have not been correctly configured.

## How to confirm configurations are correctly set
- Verify that under the `DB_MAX_LINK` configuration, vat-level data of the specified quantity can be written per second, with no write failure logs.
- Upload documents such as dyeing process sheets and color difference reports. They can be stored and read normally through the storage service configured via `STORAGE_S3_ENDPOINT`.
- Access the domain bound to `FE_DOMAIN`. The page loads normally with no certificate error prompts.
- Generate bid documents that include parameters such as dyeing formulas and color difference values. Confirm that business field mapping complies with preset rules.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
