# Bid Document and Quotation Preparation for Active Pharmaceutical Ingredient and Pharmaceutical Intermediate Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Data for this category comes from registered process documents, raw material batch ledgers, DCS production control systems, weighing systems, LIMS laboratory information management systems, chromatography data systems, and QMS quality management systems. Daily generated documents include batch production records, material balance reports, reaction and purification step records, cleaning validation records, impurity profile reports, deviation and change control documents. Data updates trigger once per production batch and per process step. Fields include process parameters, yield data, impurity content, solvent residue levels, batch numbers, and supplier information. Most document structures use structured tables and semi-technical report formats.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Data for this category is scattered across multiple industrial and management systems. Multi-turn dialogue must accurately distinguish exclusive data for different production batches to avoid cross-batch parameter mixing. Data updates per batch and per process step. Prompt engineering must dynamically bind the latest process parameters for the batch tied to the current bid, and cannot rely on expired fixed historical data. Daily documents use both structured table and semi-technical report formats. Prompt engineering must adapt to field extraction logic for different documents, while linking to compliance requirements of registered processes to ensure bid content matches actual production capacity.

## How to set the configuration
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Max context length | `8000–12000 characters` | Single-batch process documents for this category include multi-step reaction records and impurity profile data, requiring coverage of complete process information |
| Context cleanup trigger | Triggered by new batch numbers appearing in `messages` | Each batch’s data is independent, preventing cross-batch context parameter mixing |
| Variable binding rule | Bind current batch ID in `variables` | Data updates per batch, requiring dynamic pulling of LIMS and DCS data for the corresponding batch |
| Conversation ID isolation | Assign independent `chatId` for each bid project | Contexts for different bid projects must be fully isolated to avoid data cross-talk |
| Single document load limit | `First 3 current batch-specific documents` | Bid documents only require current batch process and compliance data, no need to load historical batch documents |
| Knowledge base reference toggle | Turn off as needed | Avoid referencing irrelevant historical documents, ensuring quotations and bid content only use current batch data |

## Three common mistakes
- Failing to trigger context cleanup by batch field: The symptom is cross-batch parameter mixing in multi-turn dialogue. For example, a batch A quotation references batch B’s yield data. The cause is not binding the batch field in `messages` as a cleanup trigger, leading to failure to isolate context history in a timely manner.
- Not configuring conversation link authentication: The symptom is unauthorized personnel accessing bid-related conversation links, leaking commercial and compliance information. The cause is not enabling conversation authentication settings, or authentication rules not covering bid project conversations.
- Not limiting document load scope: The symptom is historical batch documents being loaded during dialogue, leading to redundant or conflicting process parameters in bid documents. The cause is not setting a single document load limit, with the default loading all historical documents without limiting to the current batch range.

## How to confirm the configuration is correct
- Initiate a test conversation, enter a new batch number, and verify if the context history automatically clears previous batch process parameters.
- Use an unauthorized account to copy a conversation link, confirm that the corresponding conversation content cannot be accessed.
- Upload current batch and historical batch documents, verify that only current batch-specific documents are loaded during dialogue.
- Configure the variable binding rule, verify that dynamically pulled data in the dialogue is current batch LIMS and DCS information.

The values provided are common starting points and should be measured against the reader's own samples.
