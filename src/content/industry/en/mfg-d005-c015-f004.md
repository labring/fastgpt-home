# Tender Document and Quotation Preparation for Active Pharmaceutical Ingredient and Pharmaceutical Intermediate Manufacturing: Workflow Orchestration

## What Data Looks Like for This Category
Data for this category originates from registered process documents, raw material batch ledgers, DCS systems, weighing systems, LIMS, chromatography data systems, and QMS.
Data updates trigger once per production batch and each process step.
Daily documents include batch production records, material balance sheets, reaction and purification records, cleaning validation records, impurity profile reports, and deviation and change approval documents.
Core fields include reaction yield, solvent residue (unit: ppm), impurity content, batch number, and supplier qualification information. Each field aligns with the output format of different systems.
This category produces active ingredients for downstream formulations. Its core data focuses on impurity profiles and multi-step chemical routes, differing from formulation production which prioritizes dose uniformity and packaging.

## Constraints Imposed on Workflow Orchestration
Data for this category is scattered across multiple independent systems. Workflow orchestration must support pulling fields from different data sources across nodes.
Data update frequency is tied to each batch and each process step. Workflow trigger conditions must match this rhythm to prevent use of expired data.
The professional nature of core fields requires workflow variables to strictly align with formats from documents such as registered processes and impurity profiles. Field mappings cannot be adjusted arbitrarily.
Tender documents must be linked to compliance files. Workflows must verify the approval status of deviation and change files to ensure quotations and tender content meet registration requirements.
Multi-step reaction and intermediate transfer control needs require workflows to connect multiple data nodes to complete full-process validation.

## Configuration Guidelines
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Global variable configuration | Enable `variables` to bind batch number, yield, and solvent residue | Match core data fields of the category, support automatic calculation of tender quotations and document filling |
| Node identification | Configure `nodeId` to associate database query nodes and document generation nodes | Ensure accurate tool call links, avoid variable transfer errors |
| Database connection node | Set connection timeout to 600 seconds | Adapt to delays from pulling data across multiple systems, prevent workflow interruptions caused by query timeouts |
| Context parameters | Bind the first 2 batch-related records | Match the update rhythm of each batch of data, control context length to avoid redundancy |
| User single-select variable mapping | Map process route options in `variables` to a single-select group | Support selection of process routes and suppliers during tendering |
| Workflow trigger condition | Trigger by batch completion events | Match the rhythm of each step of data updates, ensure the latest batch data is used |

## Three Common Configuration Mistakes
- Symptom: When debugging a workflow, global variable fields are empty after a tool call. Logs show variables were not updated. Cause: The scope of `variables` was not configured correctly, and tool calls were not permitted to modify global variables.
- Symptom: Single-select options on the user selection node cannot read global variable values. The option list is empty. Cause: Corresponding fields in `variables` were not mapped to the variable binding configuration of the single-select node.
- Symptom: When calling the workflow API, the returned tender document does not include context-bound batch data, which does not match the context rules set in the workflow. Cause: The context-bound database node was not bound via `nodeId` in the API request, leading to incorrect context loading.

## How to Verify a Successful Configuration
- Trigger a simulated batch completion event, then check if the global variable panel updates to show the yield and impurity content data for the corresponding batch.
- Open the configuration panel of the user selection node, confirm that single-select options are linked to optional process or supplier fields in `variables`.
- Call the workflow API, then check if the returned results include batch-related document fragments bound to the context.
- View the running logs of the database connection node, confirm that the connection timeout was not triggered and data was successfully pulled.
