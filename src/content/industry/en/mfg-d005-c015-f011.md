# Bid Document and Quotation Preparation for Active Pharmaceutical Ingredient and Pharmaceutical Intermediate Manufacturing: Forms and Interactions

## What data looks like for this category
This category’s data comes from registered process documents, raw material batch ledgers, DCS control systems, weighing systems, LIMS laboratory information management systems, chromatography data systems, and QMS quality management systems. Update frequency is per production batch and process step. Daily documents include batch production records, material balance ledgers, reaction and purification process records, cleaning validation records, impurity profile reports, and deviation and change request documents. Data fields include process step number, reaction temperature, reaction duration, yield value, impurity content, solvent residue, batch identifier, and supplier information. Units include degrees Celsius, hours, mg/g, ppm, and others.

## What constraints these characteristics impose on forms and interactions
Multi-source cross-system data sources require forms to support real-time data source binding, to avoid errors and lags from static data entry. High-frequency updates per production batch require form fields to dynamically refresh with production progress, adapting to continuous data collection for multi-step processes. The need to associate multiple types of professional documents requires forms to support nested grouping and multi-file uploads, matching submissions of documents in different formats such as batch production records and impurity profile reports. Compliance-related deviation and change fields must be forcibly linked to approval nodes to ensure data traceability. Bid documents need to reuse production data, requiring form fields to map directly to quotation and bid document templates to reduce repetitive operations.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `formInput` | Bind to the LIMS system API to automatically fill in yield and impurity data for the corresponding batch | Reduce manual entry errors and meet real-time data update requirements per batch |
| `userSelect` | Preset process step options, dynamically load associated materials according to production batches | Adapt to dynamic option requirements for multi-step production and avoid selection errors |
| File upload limit | Maximum 100 MB per file, supports PDF, CSV and chromatography data file formats | Match daily document size and format types, and adapt to impurity profile report uploads |
| Form validation rules | Numeric fields only allow valid numeric input, required fields include batch number and process step number | Ensure bid data is accurate and complete, and meet compliance requirements |
| HTTP request timeout | Timeout threshold is calibrated based on actual measurements | Adapt to chromatography data file parsing duration requirements and avoid request interruptions |
| Process trigger configuration | Automatically trigger a preset Python script after form submission completes | Connect production data and quotation preparation links and improve preparation efficiency |

## Three common errors
- Symptom: The file upload button does not appear in the input box, and batch production records cannot be associated when submitting the form. Cause: The file upload configuration for `formInput` is not enabled, or access permission for the corresponding storage path is not bound.
- Symptom: Options in the user selection module cannot dynamically update with production batches, and material options from old batches appear. Cause: Dynamic data source binding for `userSelect` is not configured, and the real-time update interface for the batch ledger is not associated.
- Symptom: No parsing result is returned after calling the Python script, and form fields are empty. Cause: Chromatography data files uploaded via the form are not correctly passed to the script interface, or the script does not support chromatography data format parsing.

## How to confirm the configuration is complete
- Open the form configuration page of FastGPT v4.17.0, check if the `formInput` module is bound to the LIMS system API interface, and confirm the file upload button displays in the input box area.
- Test the `userSelect` module, switch identifiers for different production batches, and confirm associated material options update automatically.
- Upload a standard format impurity profile report file, check if the form accepts the file and displays metadata, and confirm the script execution log generates after submission.
- Enter an invalid value or omit the required batch number field, and confirm the form shows the corresponding validation prompt.

The values provided here are common starting points and should be measured against the reader's own samples.
