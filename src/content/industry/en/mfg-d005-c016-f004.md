# Tender Document and Quotation Preparation for Transformer and High-Voltage Electrical Equipment Manufacturing: Workflow Orchestration

## What this category of data looks like
Data for this category originates from design BOMs, silicon steel sheet and insulating material procurement records, vacuum drying equipment logs, insulating oil test reports, partial discharge and withstand voltage test records from the test station, and product nameplate parameter tables. Data updates occur per individual product or per batch of raw materials. Daily documents include winding and core assembly records, vacuum drying logs, insulating oil reports, partial discharge and withstand voltage test reports, and nameplate parameter tables. Core fields include insulation distance, water content, test voltage, tap position, and more. Common units are millimeters, percentage, and kilovolts.

## What constraints these characteristics impose on workflow orchestration
Full-process traceability requirements for individual products mandate that every workflow link must bind exclusive data for the corresponding equipment batch. This prevents parameter mix-ups across batches. Frequently updated test and inspection data require workflows to support real-time pulling of newly uploaded documents. Strict verification rules for core parameters require embedding parameter check nodes in workflows. These nodes intercept non-compliant values such as insulation distance and water content early. The small batch size of products means workflows do not need to support high-speed batch loops. Instead, they should prioritize ensuring the accuracy and completeness of data for individual products.

## How to configure the workflow
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Variable binding scope | Bind `variables` as the parameter set for a single product | Adapt to the single-unit traceability business requirement and avoid parameter confusion |
| Node trigger condition | Bind the test report node by `nodeId`, trigger after test data is uploaded | Ensure subsequent quotation and document preparation links start only after test data is finalized |
| Knowledge base recall upper limit | Top 5 entries | Match the document volume for single-product customization and avoid interference from irrelevant content |
| Timeout setting | 300 seconds | Cover standard time for test data parsing and document retrieval |
| File download configuration | Allow downloading BLOB objects, maximum limit 1000 MB | Support downloading and viewing large files such as test reports |
| DingTalk Webhook node configuration | Bind bidding project name and amount parameters | Enable automatic notifications for bidding progress |

## Three common misconfigurations
- After an HTTP node in the workflow returns a BLOB object, the dialog box has no download entry. This happens when no file download configuration is added after the node, and the BLOB object is not bound as a downloadable resource.
- Advanced orchestration functions are unavailable. This occurs when the advanced orchestration switch for the workflow is not enabled in FastGPT v4.17.0 or later, or the corresponding permissions are not activated.
- The DingTalk Webhook node fails to send notifications. This happens when required bidding project parameters are not configured in `variables`, leading to empty or incorrectly formatted notification content.

## How to verify the configuration is correct
- Launch a test workflow, enter the batch number of a single transformer, and check if exclusive documents such as corresponding winding records and insulating oil reports are automatically pulled.
- Trigger the knowledge base search link, and confirm that returned results include documents with core category parameters such as insulation distance and partial discharge data.
- Upload a simulated partial discharge test BLOB file, and check if a download button appears in the dialog box.
- Configure the DingTalk Webhook node, send a test notification, and confirm the recipient receives content that includes bidding project information.

The values provided here are common starting points and should be evaluated against the reader's own samples.
