# Bid Document and Quotation Preparation for Transformer and High-Voltage Electrical Equipment Manufacturing: Model Access and Configuration

## What Data Looks Like for This Category
Data for this category originates from design BOMs, silicon steel sheet and insulating material purchase ledgers, vacuum drying equipment logs, insulating oil test reports, partial discharge and withstand voltage test records from high-voltage test stations, and product nameplate parameter tables. Updates follow a per-unit product or per-batch raw material cycle. Each document includes fixed fields such as insulation structure parameters, post-drying moisture content, test partial discharge values, and tap position identifiers. Most document formats are structured tables and standardized test reports.

## Constraints on Model Access and Configuration
Exclusive data for a single product prevents the model from reusing general bulk data, and requires association with corresponding batch raw materials and test records. Frequently updated test data requires configuration to support real-time reading of the latest reports, avoiding use of expired insulation parameters or test results. Structured test fields require the model to accurately match compliance items required for bidding, preventing errors where key parameters such as insulation distance and moisture content do not match. The single-unit traceability feature requires the quotation and documents output by the model to bind to the unique identifier of the corresponding product, preventing bidding errors caused by misassignment.

## How to Set Configuration
This document is compatible with FastGPT v4.17.0. All configuration items below follow the functional logic of this version:

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Must accommodate the complete test report, material ledger and bidding requirements for a single transformer, avoiding truncation of key compliance parameters |
| `maxTokens` | 4000–6000 token | Matches the conventional output length of bid documents and quotation sheets, ensuring complete generation of quotation details and technical descriptions |
| `quoteMaxToken` | 2000 token | Limits the generation length of the quotation details section, focusing on core price items and material cost breakdown |
| `temperature` | 0.1–0.3 | Reduces random errors, ensuring consistent output of compliance content such as insulation parameters and test data |
| `AIPROXY_API_ENDPOINT` | Fill in the dedicated endpoint according to the deployment environment | Ensures correct model request routing, avoiding cross-region call delays or permission interception |
| `AIPROXY_API_TOKEN` | Bind to the enterprise-specific secret key | Restricts call permissions, preventing unauthorized access to sensitive product test and quotation data |

## Three Common Mistakes
- Long error codes or the `llm—model—response-empty` prompt appear during calls. This occurs when `AIPROXY_API_TOKEN` or `AIPROXY_API_ENDPOINT` is incorrectly configured, resulting in failed normal forwarding of model requests.
- Generated bid documents omit key insulation test data. This occurs when `maxContext` is set too small, truncating the core content of the test report.
- The generated quotation sheet does not match the material batch of the corresponding product. This occurs when the exclusive design BOM and test records of a single product are not bound, and correct context association information is not passed during model calls.

## How to Confirm Successful Configuration
- Initiate a test call, pass in the insulating oil report, withstand voltage test record and bidding requirement text for a single transformer, and check whether the returned result includes complete compliance parameters and quotation details.
- View the model call log, confirm that the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` configurations match the deployment environment, with no format errors.
- Adjust the `temperature` parameter, run multiple test calls, and confirm that there are no obvious random deviations in the output of core content such as insulation parameters and test data, meeting business requirements.
- Verify that the generated documents are associated with the corresponding batch of silicon steel sheet and insulating material data, ensuring accurate data sources.

The values provided are common starting points and should be evaluated against the reader's own samples.
