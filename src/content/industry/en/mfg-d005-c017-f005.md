# Tender Document and Quotation Preparation for Coating and Painting: Tool Calling and Plugins

## What the data for this category looks like
This category’s data covers coating line scenarios including automobiles, home appliances, and construction machinery. Daily documents include coating process cards, paint batch sheets, paint mixing records, film thickness and color difference reports, oven curves, defect repair sheets, and VOCs ledgers. Data is sourced from paint supplier TDS/SDS, data collected from spray booths and ovens, colorimeters, film thickness gauges, environmental monitoring equipment, and MES systems. Update frequencies include per paint batch, per shift, and continuous collection modes. Core fields include paint viscosity parameters, film thickness values, oven temperature curves, VOC emission data, and more.

## What constraints these characteristics impose on the tool calling and plugins workflow
Documents for the coating category are mostly process-based files with measured parameters, and data update frequency is high. Tool calling must frequently pull the latest data such as paint batches and oven curves. Parameter differences between different paint batches require tool calling to accurately match the current project’s paint TDS data, avoiding calls to outdated historical data. Continuously collected environmental and equipment data must be filtered by time range. The context for tool calling must be limited to the current tender project’s cycle to prevent invalid data from other batches from being included. At the same time, compliance data from VOCs ledgers must be verified synchronously. Tool calling must be associated with compliance data sources to avoid generating non-compliant tender content.

## How to set up the configuration
This configuration applies to FastGPT v4.17.0. Specific parameter settings are as follows:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | Set to `auto` and bind the dedicated coating tool set | Based on the need to call dedicated tools such as paint parameters and equipment data in tender scenarios, automatically selecting matching tools improves call accuracy |
| Workflow/API function-call configuration | Enable forced tool call mode | Based on the requirement to generate quotations strictly in accordance with business data, preventing the model from freely generating content that does not comply with coating processes |
| Maximum number of single tool calls | First 3 calls | Based on the frequent updates of coating data, limiting the number of calls avoids loading outdated multi-batch data |
| Tool call timeout | 600 seconds | Based on the waiting period for collecting oven curves and film thickness data, ensuring complete business data is obtained |
| Maximum context length | 1200–1500 characters | Based on the length of core parameters in a single tender document, preventing context overlength from causing tool call timeouts |
| Number of retained historical conversation turns | 2 turns | Based on the single-call logic of tender projects, avoiding retaining too much historical data that interferes with parameter matching for current tool calls |

## Three common mistakes
- Symptom: Tool call returns an error, prompting that the specified data cannot be matched. Cause: The parameter for filtering data by the current tender project’s paint batch is not configured, and full historical data is called, leading to matching failure.
- Symptom: Tool call output has no thought process content. Cause: `functionCall` is enabled but the switch for outputting thoughts is not configured at the same time, resulting in the tool call returning only results without generating intermediate logic explanations.
- Symptom: Historical data is mixed after multiple calls. Cause: The number of retained conversation turns is not limited, leading to previous project’s coating data being brought into the current call and interfering with parameter matching.

## How to confirm the configuration is correct
- Trigger a tool call, then check if the returned paint parameters match the current tender project’s paint batch sheet.
- View the tool call log to confirm that the called tool set includes relevant data sources such as coating processes and VOCs ledgers.
- Simulate multiple calls to confirm that the context of each call only retains data related to the current project, with no redundant information from historical projects.
- Verify the tool call timeout setting: when collecting oven curve data, the waiting time does not exceed the configured threshold.

The values provided are common starting points and should be measured against the reader's own samples.
