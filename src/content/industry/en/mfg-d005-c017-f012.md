# Bid Document and Quotation Preparation for Coating and Painting: Deployment and Upgrade

## What the data for this category looks like
This category’s data comes from coating supplier TDS/SDS documents, spray booth and oven operation data, colorimeters, film thickness gauges, environmental monitoring equipment, and factory MES systems. Daily documents include coating process cards, coating batch sheets, paint mixing records, film thickness and color difference reports, oven curves, defect repair sheets, and VOCs ledgers. Data updates follow this cadence: batch sheets and paint mixing records are updated per coating batch. Oven curves and defect repair sheets are generated per shift. Critical parameters are collected continuously by equipment. Document fields include coating batch number, viscosity value, film thickness unit μm, oven temperature, VOCs concentration, and other fields. No unified standard field format exists for these documents.

## How These Characteristics Impact Deployment and Upgrade
This category has scattered data sources, including direct device data, supplier documents, and manual ledgers. During deployment, multi-source data access must be supported, and a dedicated database and storage link must be configured. Data updates occur at high frequency, and field formats are inconsistent. During upgrade, document parsing rules must be optimized to avoid parameter reference deviations in bid documents caused by field matching errors. Compliance documents such as VOCs ledgers require strict traceability. During deployment, data link traceability must be ensured to avoid compliance risks. Bid quotations must match real-time process parameters such as pretreatment, spraying, and curing windows. Multi-source data association and matching logic must be optimized for this purpose.

## How to Set the Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `80–120` | Supports concurrent access to multiple types of device data and business documents in coating scenarios, and prevents database connection exhaustion |
| `MONGODB_URI` | Points to a dedicated database instance for storing coating business documents | Stores unstructured business documents such as paint mixing records and film thickness and color difference reports, separate from structured data |
| `REDIS_URL` | Binds to the local cache service address, and configures a cache expiration time of `20–30 minutes` | Caches frequently called coating viscosity and oven temperature parameters to speed up parameter matching for bid documents |
| `STORAGE_S3_ENDPOINT` | Connects to the endpoint address of the factory’s internal object storage service | Stores large-volume documents such as batch-uploaded oven curves and VOCs ledgers |
| `FILE_TOKEN_KEY` | Generates a key string bound to factory device authentication | Restricts unauthorized access to coating business data, and ensures data security |

## Three Common Misconfigurations
- Symptom: A `504 Gateway Timeout` status code is returned when calling the PDF parsing service, and the parsing service log shows that document parsing completed successfully. Cause: The `DB_MAX_LINK` parameter is not configured properly, and the database connection pool is exhausted, causing parsing results to fail to be written to storage in time, triggering the timeout.
- Symptom: The coating batch sheet field referenced during bid document generation is empty, and the generated quotation lacks core compliance parameters. Cause: `MONGODB_URI` is not correctly bound to the dedicated business database, so the latest coating batch data cannot be read.
- Symptom: The generated response only lists reference entries at the bottom, and cannot automatically embed document fields into the corresponding positions of the bid document. Cause: Parsing rules matching the exclusive field format of coating documents are not configured, so RAG retrieved content cannot adapt to the document template.

## How to Verify Successful Configuration
- Log in to the FastGPT backend, check that the `DB_MAX_LINK` parameter configuration value matches the preset value, and run a concurrent test of 100 data requests to confirm no connection overflow errors occur.
- Upload a latest coating batch sheet and oven curve document, confirm that the system can automatically identify the batch number, viscosity value, and oven temperature fields in the document and complete the association.
- Trigger a bid document generation task, check that the generated document embeds the parameters corresponding to the coating process, and the reference entries conform to the business document format.
- Confirm that the FastGPT version is v4.17.0, check that `FILE_TOKEN_KEY` has been configured, and unauthorized requests cannot import coating business documents.

The values provided are common starting points, and should be evaluated against the reader’s own samples.
