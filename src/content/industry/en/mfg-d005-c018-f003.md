# Bid Document and Quotation Preparation for Basic Chemical Continuous Production: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data sources for the basic chemical continuous production category include DCS/SIS systems, online analyzers, LIMS laboratory management systems, equipment condition monitoring modules, energy metering nodes, and raw material storage tank sensors. Data update frequencies cover three categories: real-time, shift-based, and daily. Daily documents include operating procedures, process index cards, DCS trend charts, laboratory reports, interlock bypass records, special work permits, and shift logs. Most fields use standardized units, such as degrees Celsius for process temperature, cubic meters per hour for material flow, and megapascals for pressure.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
Real-time updated DCS data and scheduled shift logs and laboratory reports require multi-turn dialogue contexts to support filtering associated documents by update time, to avoid calling expired data. Differentiated structures across multiple business documents require prompt engineering to clearly specify field extraction rules for different document types. For example, extract isolation media and operation time limits from interlock bypass records. The business characteristic of strong interlock control requires multi-turn dialogue to retain historical verification logic, to prevent missing key interlock conditions. Differences in update frequencies across data sources require the `variables` parameter to dynamically bind the latest data source identifiers, to ensure the timeliness of called data.

## Three Common Misconfiguration Issues
- Symptom: After image packaging and deployment, uploaded process documents cannot be recognized by dialogue, with no error prompt. Cause: The file path mapping bound to `variables` was not correctly configured during deployment, causing the system to fail to access locally stored document resources.
- Symptom: When calling real-time DCS data bound to `variables` in dialogue, the returned fields do not match the actual process parameters. Cause: No update timestamp filtering rule was specified for the data, causing expired historical data to be called.
- Symptom: After multi-turn interlock condition verification, subsequent quotation parameters are not associated with earlier isolation requirements. Cause: The `messages` parameter was not configured to retain complete dialogue context, resulting in loss of key interlock verification information.

## How to Verify Correct Configuration
- Call the data source interface bound to `variables`, check the match between the returned timestamp and the current system time to confirm data timeliness.
- Upload a typical process index card, trigger a dialogue query, and check whether the returned document content matches the uploaded file to confirm that the context calling logic works correctly.
- Simulate multi-turn dialogue, submit interlock verification and quotation adjustment questions in sequence, and check whether the system retains earlier key information to confirm that the `messages` parameter configuration is active.
- View dialogue logs, confirm that the bidding project identifier bound to `chatId` has no confusion, and that all configuration item parameters are correctly loaded.

The values provided are common starting points and should be measured against the reader's own samples.
