# Tender Document and Quotation Preparation for Basic Chemical Continuous Production: Tool Calling and Plugins

## What data for this category looks like
Core data for the basic chemical continuous production category comes from DCS/SIS systems, online analyzers, LIMS laboratory management systems, equipment condition monitoring modules, energy metering devices, and raw material tank ledgers. Daily documents include operating procedures, process indicator cards, DCS trend charts, laboratory reports, interlock bypass records, special work permits, and shift daily reports. Data update cycles cover real-time (such as process parameters), per shift (such as shift reports), and daily (such as energy consumption summaries). Most document fields include quantifiable indicators with standard units, such as process temperature, pressure, and material ratio.

## What constraints these characteristics impose on tool calling and plugin workflows
Most data sources are industrial real-time systems and offline account books. Tool calling must support both real-time interface data pulling and batch document parsing. Real-time data updates have no fixed cycle, so plugins must support on-demand triggering. Document types include process records and work permits with complex quantifiable fields. Plugins must adapt to multi-format structured data extraction to avoid losing key tender basis such as interlock conditions and material ratios. Tender documents must link to accurate process parameters. Tool calling must ensure data timeliness and accuracy. Failure to do so may affect quotation rationality and tender compliance.

## How to configure settings
The following configurations follow the parameter rules of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | Adapts to scenarios where multiple tools including database query and document parsing must be called on demand during tender document preparation |
| Workflow/API function-call configuration | `allowed_functions: ["db_query", "doc_parse"]` | Limits the scope of tool calling to prevent execution of unrelated plugins |
| Single tool call timeout | `600 seconds` | Basic chemical data pulling requires covering real-time process parameters and historical account books, which takes significant time |
| Tool call result cache duration | `per shift to daily` | Matches the data update rhythm of this category to avoid using outdated or expired data |
| Plugin trigger matching rule | `Calibrated based on actual measurements` | Adapts to the field complexity of different process documents to ensure accurate associated calls |

## Three common configuration errors
- Excessively long execution times when calling database plugins. Significant speed differences exist between older and newer versions. The root cause is failure to adjust cache configurations for real-time industrial data. The default cache strategy of newer versions does not match the real-time, irregular data update rhythm of this category.
- Unhidden tool calling processes, resulting in redundant plugin execution logs appearing in tender documents. The root cause is failure to enable the configuration item that only returns final content for tool call results.
- 413 errors returned by called interfaces. The root cause is uploaded process documents or account book data exceeding the single request volume limit allowed by the plugin.

## How to confirm configurations are properly set
- Trigger a single tool call. Check whether the returned results include required process parameters, work permit information and other content needed for tenders. Verify that the data source and update time match the configured cache duration.
- Simulate uploading documents with unconventional volume. Check whether the corresponding error is triggered, and confirm that the plugin request volume limit configuration is reasonable.
- Switch between different process document fragments. Verify that tool calling only triggers plugins within the preset scope and does not perform unrelated operations.
- View tool call logs to confirm that the timeout configuration is active. Ensure no call records are interrupted due to timeout.
