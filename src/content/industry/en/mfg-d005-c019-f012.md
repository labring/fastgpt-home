# Bid Document and Quotation Preparation for Plastic Injection Molding: Deployment and Upgrade

## What Data Looks Like for This Category
This category includes two types of data: structured and unstructured. Structured data originates from resin batch property sheets, injection molding machine parameters, mold temperature controllers, MES systems, and dimensional and visual inspection equipment. Updates occur every production batch, after each mold or material change, and after each shift inspection.

Daily documents include injection molding process cards, raw material drying records, mold histories, first article inspection forms, shift inspection logs, and material change and machine cleaning records. Fields include resin moisture content, injection cycle, mold temperature, holding pressure, visual defect types, and more. Units include degrees Celsius, megapascals, seconds, and other standard units.

## What Constraints These Characteristics Impose During Deployment and Upgrade
This category’s data updates frequently and is tied to production batches. During deployment, support real-time synchronization of multi-source heterogeneous data and batch binding to avoid mixing process data from different batches. Daily documents include unstructured inspection photos and records. During deployment, configure object storage endpoints compatible with local storage.

During upgrades, ensure production data collection is not interrupted. Use a gray upgrade approach, and retain the query link for legacy data to avoid being unable to retrieve historical process supporting materials during bidding. Additionally, since data relates to production compliance, restrict access permissions during deployment to ensure only authorized personnel can modify configuration parameters related to bidding.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Point to a dedicated database instance for private deployment, including workshop network segment whitelist and authentication information | Store structured historical data such as injection molding process cards and mold histories, avoid performance interference and data leakage risks from public clusters |
| `REDIS_URL` | Configure as a cache instance in the same network segment as the injection molding workshop MES, set cache validity period to 3600 seconds | Cache real-time updated mold temperature and injection molding machine parameters, reduce data retrieval latency during bidding |
| `STORAGE_S3_ENDPOINT` | Bind the access endpoint of the enterprise’s internal object storage service, configure storage path prefixes tied to batches | Store unstructured documents such as raw material drying records and first article inspection photos, ensure data is bound to the corresponding production batch |
| `FE_DOMAIN` | Fill in the enterprise internal access domain name or IP port | Restrict front-end access scope, avoid external unauthorized calls to knowledge base interfaces related to bidding quotations |
| `DB_MAX_LINK` | Set to 20-30 connections | Adapt to the concurrent volume of multiple devices reporting data simultaneously in the injection molding workshop, adjust based on actual measurement calibration |
| `FILE_TOKEN_KEY` | Use the enterprise’s internal unified key generation tool to generate keys | Encrypt uploaded files such as injection molding inspection reports, ensure the security of bidding documents |

## Three Common Misconfigurations
- When configuring `MONGODB_URI`, fail to add the injection molding workshop network segment to the database whitelist, resulting in uncaught exception pop-ups in the interface prompting database connection failure. The cause is failure to adjust database access permissions for the production environment during private deployment, and incorrect authentication parameter entries in the configuration file.
- After upgrading to FastGPT v4.17.0, the front-end page displays browser compatibility errors and fails to load the bidding document preview module. The cause is failure to synchronize and update the cache configuration of front-end static resources during upgrade, causing older browsers to fail to recognize the new resource format.
- Fail to configure the batch-associated path prefix for `STORAGE_S3_ENDPOINT`, resulting in uploaded raw material drying records being unable to bind to the corresponding injection molding batch, making it impossible to retrieve complete process supporting materials during bidding. The cause is ignoring the path binding requirement for multi-source data, directly using the default storage path.

## How to Confirm Configuration Is Complete
- Run the database connection test script to verify the connectivity of `MONGODB_URI` and `REDIS_URL`, confirm that stored mold history data can be retrieved.
- Upload an injection molding first article inspection photo, access it via the link generated by `FILE_TOKEN_KEY`, confirm the file can be previewed normally and has not been tampered with.
- Access the address configured in `FE_DOMAIN`, confirm the front-end page loads normally and there are no cross-domain errors.
- Simulate a material change and machine cleaning operation, check whether the system can automatically synchronize and update raw material drying records, confirm the data synchronization link is working properly.
