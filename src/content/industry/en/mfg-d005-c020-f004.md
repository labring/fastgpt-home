# Tender Document and Quotation Preparation for Safety, Environmental Protection and Special Operation Management: Workflow Orchestration

This document applies to FastGPT v4.17.0.

## What data for this category looks like
Data for this category comes from regulatory standards, online environmental monitoring equipment, gas detectors, personnel qualification files, equipment isolation lists, and supervision platforms. Daily documents include risk identification records, work permits for hot work, confined space work, lifting operations, monitoring logs, hazardous waste ledgers, emission monitoring reports, and accident and hidden danger rectification reports. Data takes effect in real time with single operations, or updates per monitoring requirements and regular inspection cycles. Fields include operation type, risk level, qualification number, monitoring value, compliance status, and other related items.

## What constraints these characteristics impose on the workflow orchestration link
Multiple dispersed data sources require the workflow to integrate multiple data call nodes to connect to different data sources for information. Differences in fields across documents require the workflow to adapt to multiple data extraction rules to avoid field mismatches. Real-time or high-frequency update cycles require the workflow to support flexible triggering to adapt to temporary operations or urgent tender scenarios. The business attribute with high veto power requires the workflow to set strict verification links. Any unpassed pre-link terminates subsequent processes to prevent unqualified content from entering tender documents.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Environment variable call | Bind the custom `variables` key name during Docker deployment | Read fixed configurations such as EHS department's regulatory library paths and monitoring thresholds |
| Loop index configuration | Set initial value to 0, increment by 1 after each loop | Adapt to batch processing of work permits and avoid index out-of-bounds |
| Database query timeout | 600 seconds | Reserve sufficient time to obtain cross-platform compliance data and personnel qualification information |
| Node trigger condition | Trigger based on the completion status of the pre-bound node via `nodeId` | Ensure pre-links such as risk identification and qualification verification are completed before generating quotations |
| Custom tool variable optional configuration | Set as optional to match operation type verification rules | Adapt to field requirements for different operations such as hot work and confined space work |
| Batch execution limit | Top 20 entries | Match the conventional number of work permits included in a single tender document |

## Three common mistakes
- Calling Docker custom environment variables returns empty values. This is caused by failing to correctly bind the environment variable key name in the workflow's `variables` configuration, resulting in failure to read parameters injected during deployment.
- The loop index becomes null after incrementing. This is caused by not setting the initial index value for the loop body, or failing to correctly reset the index after the loop ends, leading to a null pointer exception.
- Database query for work permit data returns no results. This is caused by not configuring the correct database connection timeout period, or the query statement not matching the compliant field format of work permits, resulting in failure to locate target data.

## How to confirm the configuration is correct
- Manually trigger the workflow, check if environment variables correctly read the preset EHS configuration parameters.
- Run the loop body node, verify that the index value increases correctly with the number of cycles, with no null values or out-of-bounds situations.
- Execute the database query node, confirm that the returned work permit data fields match the business document structure.
- Check the node trigger conditions, confirm that subsequent workflow links only start after pre-linked nodes are completed.
