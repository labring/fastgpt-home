# Bid Document and Quotation Preparation for Furniture and Wood Products Manufacturing: Tool Calling and Plugins
This document is written for FastGPT v4.17.0, targeted at technical implementation engineers for furniture and wood products manufacturing enterprises. It explains tool calling and plugin configuration for bid document and quotation preparation stages.

## What the data for this category looks like
Data for this category mainly comes from order design systems, sheet material and wood batch ledgers, CNC cutting and drilling equipment, ERP/MES systems, and moisture content testing equipment. Daily documents include order disassembly drawings, cutting lists, edge banding and drilling programs, coating process documents, hardware material lists, and trial assembly and packaging records.
Data updates sync with order generation, daily material inventory checks, and each batch of material testing. Fields include panel size, sheet material moisture content, hardware model, production batch, and more. Units are mostly millimeters, percentage, and piece count.

## What constraints these characteristics impose on tool calling and plugin workflows
This category has custom order-driven workflows, large numbers of panels, and on-site spatial dimensions that directly impact production. These factors require tool calling to accurately match order design and on-site installation data.
Multiple types of heterogeneous documents, including order disassembly drawings and process documents, need plugins to uniformly extract structured fields. This avoids errors from manual organization.
Frequently updated material and production data require plugins to pull the latest ledgers in real time when called. This prevents use of expired sheet material batches or hardware models.
The strong correlation between panel size and on-site installation requires that quotations and documents returned by tool calling be synchronously linked to corresponding order disassembly data. This avoids quotation items with mismatched dimensions.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` or bound to the "Furniture Order Disassembly Data Extraction" plugin | Automatically match plugins adapted to this category, or specify binding a dedicated data extraction tool |
| `functionCall` | `enabled` | Force enable structured tool calling to ensure quotation fields can be automatically written into bid document templates |
| Global variable passing | Bind order ID and sheet material batch ID | Link real-time ERP and MES data to avoid using expired material information |
| Tool call timeout setting | `300 seconds` | Wait for CNC equipment data pulling and order disassembly parsing to complete |
| Number of items returned by a single tool call | `Top 3` | Focus on core panel and hardware data for the current order |
| Prompt optimization | Calibrate based on actual testing | Adapt to professional term corrections for furniture bid scenarios |

## Three common mistakes
- Inconsistent plugin name display: The internal name defined in code appears in the system plugin list, while the display name entered during plugin creation appears on the front-end page. Failure to verify this in advance causes matching errors during calls.
- Redundant characters in tool call return results: Unexpected `0` characters may appear during debugging. This mostly occurs because structured data returned by the plugin is not properly formatted and is additionally spliced by the model.
- Specified replies overwritten by tool calls: After setting fixed reply content, the tool still automatically triggers AI-generated responses. This happens when the default automatic reply switch is not turned off, leading to content conflicts.

## How to confirm the configuration is complete
- Trigger a tool call and check if the returned structured data includes core fields such as the current order's panel size and hardware model.
- Compare the system plugin list with plugin names displayed on the front end to confirm the called plugin matches expectations.
- Simulate the bid document generation process to verify that data returned by tool calls is automatically filled into corresponding template positions.
- Trigger a timeout test to confirm that tool calls complete and return within `300 seconds` with no abnormal interruptions.

The values provided are common starting points and should be measured against the reader's own samples.
