# Bid Document and Quotation Preparation for Furniture and Wood Products Manufacturing: Model Access and Configuration

## What the Data for This Category Looks Like
Typical entities for this category include panel furniture, solid wood furniture, custom home and door manufacturers. Data is sourced from order design systems, sheet and wood batch ledgers, CNC cutting and drilling equipment, ERP/MES systems, and moisture content testing equipment. Daily documents include order breakdown drawings, cutting lists, edge banding and drilling programs, coating process documents, hardware bill of materials, and assembly and packaging records.
Data updates are adjusted synchronously with order creation, daily production progress, and each batch of incoming materials. Fields include panel dimensions, material color codes, hardware models, moisture content parameters, and more. Most units are millimeters, cubic meters, and kilograms.

## Constraints Imposed by These Characteristics on Model Access and Configuration
This category is driven primarily by custom orders. The most time-consuming order breakdown step generates large volumes of panel-associated data. This requires model access to adapt to multi-source heterogeneous data, including structured panel dimension parameters and unstructured process documents.
High-frequency updates of order, production, and material data require flexible data synchronization adaptation interfaces to be reserved during configuration.
The large number of panels and complex associated relationships require ensuring the model context can carry sufficient associated information to avoid truncating critical production parameters.
Additionally, category-specific professional fields such as moisture content and hole position matching require clear identification rules during configuration to prevent the model from confusing non-standard fields with general parameters.

## How to Set the Configuration
| Configuration Item | Recommended Value Range | Basis for This Value |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Adapts to the total length of multi-panel order breakdown data and associated process documents, avoiding truncation of critical information |
| `maxTokens` | 3000–4000 token | Matches the output length requirements for bid documents and quotation sheets, ensuring complete presentation of quotation details and program descriptions |
| `quoteMaxToken` | 1500 token | Limits the token usage of referenced content, balancing answer completeness and context carrying capacity |
| `temperature` | 0.3–0.5 | Reduces random output probability, ensuring the accuracy of professional parameter output such as panel dimensions and hardware models |
| `AIPROXY_API_ENDPOINT` | Fill in the actual address of the private deployment node | Adapts to the enterprise internal network environment, ensuring the stability of model calls |
| `AIPROXY_API_TOKEN` | Fill in the actual key obtained by the enterprise | Based on the key management logic of FastGPT v4.17.0, ensuring valid identity verification for API calls |

## Three Common Misconfigurations
- Phenomenon: After increasing `quoteMaxToken`, the model output does not reference any retrieved content. Cause: The reference upper limit exceeds the context carrying threshold, causing the system to fail to correctly match the association between referenced content and answer content.
- Phenomenon: After enabling the internet tool, the generated bid document does not display clickable rendered format of reference links. Cause: The result rendering configuration for the corresponding tool is not enabled, or the reference field returned by the interface is not correctly mapped to the output template.
- Phenomenon: The panel dimensions output by the model deviate from the actual order breakdown data. Cause: No category-specific field identification rules are configured, causing the model to confuse general dimension units with category-specific units such as millimeters and cubic meters.

## How to Confirm Proper Configuration
- Upload a single custom furniture order breakdown drawing and cutting list, trigger quotation document generation, and check whether the output content includes dimension parameters for all panels.
- Adjust the value of `quoteMaxToken`, verify that the retrieved content reasonably adjusts its proportion with parameter changes, and confirm that the reference logic takes effect normally.
- Call the private deployment API interface, check whether the returned result includes complete reference link fields, and confirm that the rendering configuration is correct.
- Simulate a high-frequency data update scenario, verify whether the data source synchronization delay of the model access meets the production rhythm requirements.

The values provided are common starting points and should be measured against the reader's own samples.
