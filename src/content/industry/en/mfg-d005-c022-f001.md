# Bid Document and Quotation Preparation for Complete Home Appliance Manufacturing: HTTP Interfaces and External Systems

## What the data for this category looks like
Production and testing data for complete home appliance manufacturing comes from ERP, MES systems, tightening and charging equipment, safety performance testers, performance laboratories, and after-sales fault records. Daily documents include model configuration BOMs, assembly work instructions, refrigerant charging records, electrical safety test reports, performance spot check reports, and rework records. Data update frequency follows per single product, per shift team, or according to spot check plans. Fields include component batch numbers, charging amounts, tightening torque, test voltage, and other metrics. Units include grams, newton meters, volts, and more.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
Multiple scattered data sources require interfaces to adapt to authentication and data formats of different external system types. The high-frequency update rhythm per single product or shift team requires interfaces to support low-latency batch data pulling, to avoid delays that affect bid quotation timeliness. Complex document structures and detailed fields require the interface's `responseData` to support precise filtering and field mapping, to prevent incorrect mixed-line assembly data from being included. The large-scale mixed-line assembly scenario for consumer products requires interfaces to filter data by model, to ensure bid quotations only use compliant parameters for the corresponding model. Mandatory testing data requirements for safety, performance, and other aspects require interfaces to verify data compliance, to avoid non-compliant items from entering bid documents.

## How to set the configuration
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Interface authentication method | Set the `Authorization` header to Bearer {ERP exclusive key} + Basic {device credential} | Match different authentication rules when connecting to multiple types of external systems |
| Global variable configuration | Bind model, batch number, safety performance inspection items | Ensure bid quotations accurately associate production data for the corresponding model |
| Response data processing | Filter non-compliant test records and redundant fields | Ensure bid documents only contain compliant and necessary information |
| Request timeout setting | 600 seconds | Safety performance tests and performance laboratory data uploads take a long time |
| Retry count configuration | 3 times | Address occasional network fluctuations or timeouts from device interfaces |
| Certificate mount path | /etc/fastgpt/certs/ | Enable HTTPS access to external systems and ensure data transmission security |

## Three common mistakes
- Symptom: Interface requests return SSL certificate invalid errors, status code 403, or SSL handshake failed. Cause: Certificate mount path is not correctly configured in docker-compose.yml, so FastGPT cannot read local certificate files.
- Symptom: Pulled BOM data does not match the bid model, with mixed-model fields appearing. Cause: Model filtering parameters are not bound in the `variables` configuration, leading to cross-model data being pulled.
- Symptom: Response data includes non-compliant safety performance test results, leading to compliance risks in bid documents. Cause: No qualified item filtering rules are added in the response data processing configuration, and original test data is used directly.

## How to confirm the configuration is complete
- Initiate a single interface request, check if the returned `responseData` matches the bound `variables` parameters.
- View container runtime logs to confirm the certificate file has been successfully mounted, with no SSL-related error messages.
- Simulate multiple interface requests to verify that the retry mechanism triggers normally when interface fluctuations occur.
- Export a test bid document snippet to confirm all associated production data are valid records for the corresponding model.
