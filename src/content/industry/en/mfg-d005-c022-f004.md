# Bid Document and Quotation Preparation for Complete Household Appliance Manufacturing: Workflow Orchestration

This page’s configuration is based on FastGPT v4.17.0.

## What the data for this category looks like
This category’s data covers the full production chain of air conditioners, refrigerators, washing machines and small household appliances. Daily documents include configured BOMs, assembly work instructions, refrigerant charging records, electrical safety test reports, performance spot check reports and repair records. Data sources include ERP/MES systems, component batch ledgers, tightening and charging equipment, safety compliance testers, performance laboratories and after-sales fault databases. Update cycles run per single product, per shift production cycle or per spot check plan. Each document contains fields such as model, batch, parameter values, test results, with units changing dynamically based on document type.

## What constraints these characteristics impose on the workflow orchestration link
The multi-source, heterogeneous data characteristics of this category require workflow configurations to connect to multiple different data sources. Data pull trigger rules must be set per single product, per shift or per spot check cycle. Diverse document structures require targeted content extraction rules in workflow configurations, to adapt to hierarchical fields of configured BOMs, test items in safety compliance reports, and more. In bidding scenarios, product models must be accurately matched with corresponding document data to avoid compliance risks related to mixed-line misassembly. Parameter verification links must also be embedded to ensure process data such as refrigeration and sealing meets bidding requirements.

## How to set the configurations

| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| `variables` persistence setting | Enabled | Bidding processes need to retain core variables such as product batch and model across sessions to ensure data consistency |
| Multi-parameter supplementary node | 3-5 parameter input fields | Adapt to multi-dimensional parameter supplement requirements for safety compliance, performance, cost and other aspects in complete household appliance manufacturing |
| Debug and front-end test synchronization switch | Enabled | Avoid result differences between the same input during debugging and actual operation, ensuring process consistency |
| Knowledge base retrieval scope | Bind corresponding document type tags, limit to top 20 results | Accurately extract content from specific documents such as configured BOMs and safety compliance reports, avoid mixed-model retrieval |
| Node timeout threshold | 600 seconds, adjustable based on actual measurement | Adapt to time consumption requirements of multi-device data pulling and complex document parsing |
| `nodeId` binding rule | Bind unique identifiers in sequence of process nodes | Ensure correct call order of workflow nodes, avoid parameter transfer errors |
| Context window size | 8000 token | Adapt to content integration requirements for bid documents spliced from multiple documents |

## Three common errors
- Issue: Global variables are lost after a session exits, and cannot be reused in subsequent sessions. Cause: The `variables` persistence configuration is not enabled, causing the variable cache to be cleared after the session ends.
- Issue: Only a single parameter can be passed during MCP calls, and multi-dimensional process parameters cannot be supplemented. Cause: No multi-parameter supplementary node is configured, only a single input field is set, which cannot meet the parameter transfer requirements of multiple links in complete household appliance manufacturing.
- Issue: Document extraction results returned by front-end test are inconsistent with workflow debugging results. Cause: The debug and front-end test synchronization switch is not enabled, and there are differences in context configuration between the debugging environment and the production environment.

## How to confirm the configuration is complete
- Trigger a complete workflow, check the logs to confirm that global variables are retained after the session ends, verifying that the `variables` persistence configuration takes effect.
- Call the MCP node, pass multiple preset sets of parameters, confirm that all parameters can be completely transferred to the target node, verifying that the multi-parameter supplementary configuration takes effect.
- Enter the same set of product models in the workflow debugging environment and the front-end test environment respectively, compare the two returned document extraction results, and confirm that they are consistent.
- Retrieve documents not tagged as target, confirm they are not included in the retrieval scope, verifying that the knowledge base retrieval scope configuration takes effect.
