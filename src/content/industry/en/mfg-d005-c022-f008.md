# Bid Document and Quotation Preparation for Complete Home Appliance Manufacturing: Document Parsing and Chunking

## What the Data for This Category Looks Like
Daily documents for this category include configuration BOMs, assembly work instructions, refrigerant charging records, electrical safety test reports, performance spot check reports, and repair records. Data is sourced from ERP/MES systems, parts batch ledgers, tightening and charging equipment, safety compliance testers, performance laboratories, and after-sales fault databases. Updates are performed per single product, per shift production batch, or per spot check plan. Document fields include material codes, tightening torque values, charging pressure, insulation resistance values, and other fields with corresponding physical units.

## What Constraints These Characteristics Impose on the Document Parsing and Chunking Process
Multiple document types, high-frequency updates, and structured fields with physical units for this category create multiple constraints for the document parsing and chunking workflow.
- The material hierarchy structure of configuration BOMs must retain parent-child associations. Chunking must not separate material codes from their corresponding usage quantities.
- Test data with physical units must be bound to test conditions, to avoid losing context for parameters such as torque and voltage after chunking.
- High-frequency updated single-product or shift-level documents require the parsing process to have low latency. This prevents disruption to bid document preparation schedules.
- Exclusive documents for different home appliance models must be chunked by model. This avoids cross-mixing of parameters related to mixed-line assembly.
- Safety compliance and performance test reports, as core bid materials, require accurate extraction of key indicators. Chunk length must match the completeness of parameter combinations.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the complete length of parameter combinations and process descriptions in home appliance documents, avoiding chunking that breaks the parameter context of test reports |
| `chunkSplitter` | Semantic chunking | Adapts to the hierarchical structure of configuration BOMs and logical paragraphs of test reports, preserving the integrity of associated fields |
| `customPdfParse` | Enable Marker parsing mode | Improves structured data extraction accuracy for safety compliance test reports and BOM lists that contain complex tables |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 seconds | Covers the parsing time required for large-capacity assembly work instructions and multi-batch charging records, preventing parsing tasks from timing out mid-execution |
| `UPLOAD_FILE_MAX_SIZE` | 80–120 MB | Adapts to the upload limit for batch repair records and multi-batch documents, preventing parsing from failing to start due to exceeding size limits |
| `chunkSettingMode` | Manual configuration | Flexibly adjust chunking parameters for different types of bid documents, adapting to multi-format content such as BOMs and test reports |

## Three Common Configuration Mistakes
- Symptom: Structured fields return empty when parsing safety compliance test reports with multi-page nested tables. Cause: The Marker parsing mode for `customPdfParse` is not enabled. The default parsing logic cannot recognize parameter binding relationships in complex tables.
- Symptom: The system prompts upload failure or that parsing tasks failed to start when uploading batch repair record documents. Cause: The configured value of `UPLOAD_FILE_MAX_SIZE` is lower than the actual size of the documents, exceeding the upload limit.
- Symptom: A 504 gateway timeout error or parsing failure occurs when calling the parsing tool. Cause: The FastGPT version in use is not compatible with the Marker plugin. Switch to FastGPT v4.17.0 or a stable version to configure the parsing mode.

## How to Confirm the Configuration Is Correct
- Upload a single configuration BOM document, check if parsed chunks retain the association between material codes and their corresponding usage quantities, and adjust `chunkSize` until no key parameters are split.
- Upload a multi-page safety compliance test report, verify that structured table data is fully extracted, and confirm that `customPdfParse` has the corresponding parsing mode enabled.
- Submit a parsing task for a large-capacity assembly work instruction, check if task duration meets expectations, and adjust `PARSE_FILE_TIMEOUT_SECONDS` to a range that allows the task to complete normally.
- Test exclusive documents for different home appliance models, confirm that chunked results are categorized by model, with no cross-model parameter mixing.

The values provided are common starting points and should be evaluated against the reader's own samples.
