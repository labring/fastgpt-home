# Bid Document and Quotation Preparation for Complete Household Appliance Manufacturing: Deployment and Upgrade

## What the data for this category looks like
Data for this category is generated across the full lifecycle of complete household appliance production. Daily documents include bill of materials (BOM) configurations, assembly work instructions, refrigerant charging records, electrical safety test reports, performance sampling inspection reports, and rework logs. Data sources include ERP/MES systems, component batch ledgers, tightening and charging equipment logs, safety compliance tester data, performance laboratory test results, and after-sales fault records. Data is updated per individual product unit, and synchronized per shift and sampling plan. Fields cover material codes, process parameters, test values, fault types, and similar items. No additional statistical quantitative data is included.

## What constraints these characteristics impose during deployment and upgrade
Bid document and quotation preparation for complete household appliance manufacturing requires linking multiple real-time or near-real-time data sources. During deployment, compatibility with multiple types of industrial equipment interfaces is required to ensure synchronous acquisition of process parameters such as tightening and charging, as well as safety compliance test results. Data update frequency is high and granularity is fine. The deployment phase must configure stable caching and database connection pools to prevent service freezes caused by high-frequency read/write operations. Bid documents must match BOM and process information for multiple product models. During upgrades, configuration must be quickly adaptable to the document structure of new product lines, while ensuring field consistency for data from different batches to prevent model confusion in quotations and documents. Additionally, data is directly linked to consumer product safety. The deployment phase must strengthen access permission controls to avoid leakage of sensitive process data.

## Configuration settings
This document applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 100–150 | Adapts to high-frequency read/write industrial data synchronization scenarios, prevents database connection exhaustion |
| `MONGODB_URI` | Assemble standard connection strings using the intranet IP of the deployment environment | Stores unstructured documents such as BOMs and test reports for multiple product models |
| `REDIS_URL` | Intranet address on port 6379, set connection timeout to 30 seconds | Caches real-time process parameters and temporary context for bid documents, reduces database load |
| `FE_DOMAIN` | Enterprise intranet domain name or public network registered domain name | Binds the access entry for bid document preview and quotation tools |
| `FILE_TOKEN_KEY` | Randomly generated 32-character string | Encrypts attached files such as safety compliance test reports and rework logs uploaded to the system |
| `STORAGE_S3_ENDPOINT` | Intranet endpoint of the enterprise self-built object storage | Stores archived files of batch-generated bid documents and quotation sheets |

## Three common configuration errors
- Symptom: FastGPT service access prompts invalid certificate or failed HTTPS connection, with browser displaying NET::ERR_CERT_INVALID. Cause: Only generated an mkcert certificate but did not bind the certificate path in the `FE_DOMAIN` configuration item, or did not mount the certificate file to the corresponding service directory.
- Symptom: AI proxy reports get tiktoken dial tcp lookup error, service cannot load tokenization model. Cause: Did not pre-download tiktoken dependency packages during offline deployment, or the intranet environment did not configure a proxy that can access model resources, preventing retrieval of model files required for tokenization.
- Symptom: BOM fields for multiple product models appear confused in bid documents, and quotation data does not match actual process parameters. Cause: The data source configured in `PG_URL` or `MONGODB_URI` is not linked to the correct ERP/MES data tables, resulting in material information read that does not correspond to the current bid model.

## How to confirm proper configuration
- Access the configured `FE_DOMAIN` address, confirm that the service page loads normally in the browser with no certificate-related errors.
- Upload a household appliance safety compliance test report, verify that the file can be stored successfully and generate an accessible encrypted link.
- Initiate a simulated bid document generation process, confirm that the system can pull the configured BOM and process parameters for the corresponding model from the bound ERP/MES data source.
- Check the database connection monitoring panel, confirm that the number of concurrent connections does not exceed the value configured for `DB_MAX_LINK`.

The values given here are common starting points and should be measured against the reader's own samples.
