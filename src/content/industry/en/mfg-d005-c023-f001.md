# Bid Document and Quotation Preparation for Industrial Instrument Manufacturing and Calibration: HTTP Interfaces and External Systems

## What data looks like for this category
This category’s data is generated across the full metrology lifecycle of a single instrument. Sources include design documents, standard instruments and environmental monitoring data, calibration software outputs, laboratory information system records, and customer range requirements. Daily generated documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, software version logs, and more. Data fields include instrument model, range limits, calibration point values, error values, ambient temperature and humidity, metrology device serial numbers, and others. Units include specialized metrology units such as pascals, degrees Celsius, cubic meters per hour, and others. Data is updated immediately after each calibration for every instrument.

## Constraints on HTTP interfaces and external systems from these data characteristics
Calibration data for this category must strictly comply with metrology traceability requirements, so HTTP interfaces must support parameters related to traceability chains. Each calibration for a single instrument generates multiple associated documents, so interfaces must support precise data retrieval by instrument serial number or calibration batch. Data fields include numerous high-precision numerical values and specialized metrology units, so interfaces must standardize parameter formats to avoid parsing errors. Data updates are triggered by each individual calibration action, so interfaces must support real-time or on-demand invocation modes. Calibration records are critical deliverables, so interfaces must ensure complete and traceable data transmission.

## Configuration settings
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `Authorization` | Include a Bearer token with a 7-day validity period | Matches the interface authentication rules of laboratory information systems to secure access to calibration data |
| `variables` | Bind instrument model, calibration batch, and customer range parameters | Adapts to personalized calibration data retrieval requirements for single instruments |
| Maximum single data retrieval count | First 200 records | Matches the range of documents generated per single calibration to avoid interface overload |
| Timeout threshold | 300 seconds | Adapts to the time required for multi-point calibration data collection and error calculation |
| `responseData` | Return only core fields from metrology certificates and error curves | Reduces invalid data transmission and improves efficiency for bid document and quotation preparation |

## Three common mistakes
- The interface returns an empty field for the metrology certificate serial number. This occurs because variables linked to approved calibration records in the laboratory information system are not bound, leading to missing critical deliverable fields during data retrieval. This may cause metrology review failures.
- The interface returns a 403 status code due to authentication failure. This occurs because the `Authorization` token has expired or the correct authentication scope is not included, preventing access to the calibration data interface of the laboratory information system.
- The interface returns more results than expected. This occurs because a reasonable single retrieval limit is not set, leading to the retrieval of irrelevant calibration data across multiple batches, which disrupts quotation preparation logic for bid documents.

## How to confirm configurations are correct
This verification process follows the interface configuration rules of FastGPT v4.17.0.
- When an interface is invoked, verify that the returned data includes core metrology fields such as instrument model, calibration point values, and error values, and confirm that the fields match the preset `variables` binding parameters.
- Confirm that the `Authorization` token remains within its validity period. When an expired token is used to invoke the interface, verify that the corresponding authentication error status code is returned, confirming that the authentication configuration is active.
- When a single calibration process is simulated, the interface is invoked to retrieve calibration data for the corresponding instrument, and the number of returned results is confirmed to comply with the preset single retrieval limit rule.
- The `responseData` returned by the interface is compared with the original calibration records in the laboratory information system, and it is confirmed that data fields and formats match completely.

The values provided are common starting points and should be evaluated against samples relevant to the specific use case.
