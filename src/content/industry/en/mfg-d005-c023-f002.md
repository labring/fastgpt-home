# Bid Document and Quotation Preparation for Industrial Instrument Manufacturing and Calibration: Vector Models and Indexes

## What data for this category looks like
Data for this category comes from flow, pressure, temperature, analytical instrument manufacturers and metrology laboratories. It includes assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version records. Data sources include design documents, standard instrument monitoring data, calibration software outputs, laboratory information systems, and customer range requirements. The update frequency is after each calibration for every device. Data fields include tested part number, calibration date, environmental parameters, error calculation values, certificate traceability information, and more. Field units align with the legal metrological requirements of the measured parameters.

## What constraints these characteristics impose on vector models and indexes
The single-device, per-calibration update pattern for data in this category requires indexes to support incremental indexing and retrieval by device number and calibration batch. This avoids performance losses from full index reconstruction. Unstructured error curves, metrology certificate text, and numerical error data coexist in this dataset. Vector models must adapt to both structured fields and unstructured document embeddings to ensure accurate vector representations of traceability information and error parameters. Bidding scenario timeliness requirements mean index recall latency must match the rapid retrieval needs of document preparation. High-risk metrology audit demands also require full recall completeness for retrieval results, preventing omission of key calibration data.

## How to set configurations
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Matches the length of single sections in calibration procedures and original records, avoiding cutting critical metrological information |
| Overlap Length | 100–150 characters | Retains associated fields such as calibration date and device number across adjacent chunks, preventing context breaks |
| `maxToken` | 4096 token | Adapts to the embedding needs of long text traceability chains in metrology certificates, avoiding truncation of critical information |
| Similarity Threshold | 0.75–0.85 | Filters low-match non-calibration documents, focusing on valid metrological data required for bidding |
| Single Search Limit | Top 10 results | Controls the number of retrieval results, adapting to rapid citation needs in bid documents |
| `defaultToken` | Set from representative sample documents | `defaultToken` is the default token count for direct text chunking; tune it on representative source documents. See the [v4.17.2 model-field reference](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx). It is not a vector dimension, embedding-model input cap, or retrieval/LLM context. |

## Three common configuration errors
- Index interface returns a 400 status code with no response body. This occurs when the system fails to adapt to long text embedding requirements for metrology certificates in this category. A too-small `maxToken` setting causes request body truncation.
- Retrieval or indexing operations cause server resource exhaustion. This happens when indexing is not split by device batch. Loading all calibration records for a single device for embedding leads to excessive memory usage.
- Knowledge base upload tasks get stuck at the first or second indexing stage. This stems from missing incremental update rules configured by calibration date. Repeatedly indexing existing calibration records blocks the indexing queue.

## How to confirm configurations are applied correctly
- Upload a single calibration procedure document. Verify the number of embedded chunks matches expectations to confirm the chunk length configuration works.
- Search for the keyword "error curve". Check that returned result fields include core category information such as tested part number and calibration date to confirm vector model adaptability.
- Run a batch index of calibration records for 10 devices. Confirm server resource usage does not continue to spike to verify the indexing chunk configuration is appropriate.
- Export the index configuration from the current FastGPT v4.17.0 knowledge base. Confirm the values of `maxToken` and `defaultToken` match the preset settings to verify parameter saving took effect.

The values provided here are common starting points and should be evaluated against the reader's own samples.
