# Bid Document and Quotation Preparation for Industrial Instrument Manufacturing and Calibration: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data for this category comes from design documents, standard instrument monitoring data, calibration software outputs, laboratory information systems, and customer range requirements.
Exclusive data for each individual device is updated every time it is calibrated.
Daily documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version records.
Data fields include measured range, error calculation value, traceability number, ambient temperature and humidity, and calibration date.
Corresponding units include professional measurement units such as pascals, degrees Celsius, and ppm.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
Each individual device’s exclusive data is updated every time it is calibrated.
Multi-turn dialogue must accurately link historical calibration records for the corresponding device to avoid mixing data across devices.
Daily document types are diverse, and fields are specialized.
Prompts must clearly distinguish between calibration records and fields related to bid quotations, to prevent incorrect extraction of traceability information or units.
Bid documents must integrate calibration data for multiple devices.
Multi-turn dialogue must gradually guide users to provide information such as device lists and range requirements, to avoid missing key information due to overload from one-time input.

## Configuration Settings
This document is written for FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique calibration number of a single device | Ensure multi-turn dialogue context only associates calibration data for the current bid device, preventing cross-device confusion |
| `messages` | Retain the first 20 conversation histories and associated knowledge base entries | Data for this category is linked to multiple calibration records per device, so sufficient context must be retained to distinguish bid parameters for different devices |
| `variables` | Bind device ID, calibration date, and range fields | Accurately deliver specialized field information to meet the formal formatting requirements of bid documents |
| Single search limit | Top 8 recall results | Calibration records for a single device typically do not exceed 10. Excessive recall will introduce irrelevant data and interfere with bid document preparation |
| Response token limit | 1500–2500 tokens | Bid documents must include multiple sections of calibration data and quotation details. A sufficient token count ensures full coverage of content such as metrology certificates and error analysis |
| Prompt optimization | Enabled, calibrated based on actual testing | Calibration data fields are specialized. Optimized prompts can simplify specialized terminology to adapt to the formal format requirements of bid documents |

## Three Common Configuration Errors
- Symptom: A dialogue trigger error occurs in the debug preview interface, with the prompt "No matching calibration data found". Cause: The unique device identifier is not bound via `variables`, so the system cannot retrieve the corresponding calibration data.
- Symptom: The maximum response token for a specific question automatically switches to 200, resulting in overly short reply content. Cause: The global response token limit is not set, or the token threshold is not adjusted separately for the professional calibration data scenario, triggering the system's default limit.
- Symptom: Search results include calibration records for unrelated devices that do not match the current bid item. Cause: The unique number of a single device is not bound via `chatId`, causing the context to associate historical data from multiple devices.

## How to Verify Correct Configuration
- Enter the calibration number of a single device, and confirm that the dialogue context only displays calibration records and related parameters for that device.
- Trigger specialized terminology conversion, and confirm that the expression after prompt optimization meets the formal format requirements of bid documents.
- Submit a bid request involving multiple devices, and confirm that the system only recalls calibration data for the corresponding devices, with no cross-device confusion.
- Test extraction of complex calibration data, and confirm that the response token does not trigger the default limit, with full coverage of fields required for bid documents.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
