# Bid Document and Quotation Preparation for Industrial Instrument Manufacturing and Calibration: Workflow Orchestration

## What the Data for This Category Looks Like
Typical entities include flow, pressure, temperature, and analytical instrument manufacturers, as well as metrology laboratories. Daily documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version logs. Data sources include design documents, standard instruments and environmental monitoring data, calibration software, laboratory information systems, and customer range requirements. Data is updated after each calibration for every individual device. Data fields include individual device identification numbers, range limits, error calculation values, metrology certificate traceability numbers, environmental monitoring parameters, and more. Units include pascals, cubic meters per hour, degrees Celsius, and other metrology-specific units.

## Constraints on Workflow Orchestration
Each device’s post-calibration data requires the workflow to bind exclusive parameters for that single device, to avoid cross-device data mixing. High-time-consuming steps in the calibration process—establishing standard instrument connections, collecting multiple points to calculate errors, and auditing traceability chains and environmental conditions—must be split into independently orchestratable nodes to enable step-by-step verification. Content such as calibration procedures and error curves from daily documents must be used as a knowledge base call source for the workflow, ensuring bid document content complies with metrology regulations. Data errors can lead to measurement deviation propagation, invalid certificates, or failed metrology audits. For this reason, the workflow must configure output verification rules for each node to block intermediate data that does not meet metrology requirements.

## Configuration Specifications
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Variable Binding | Bind individual device ranges and environmental parameters from `variables` | This category’s data comes from customer range requirements and environmental monitoring, so core fields must be used as workflow inputs |
| Node ID Binding | Specify `nodeId` as the unique identifier for collection and calculation nodes | Follows workflow node call link requirements to ensure accurate cross-node data transfer |
| Knowledge Base Association | Associate metrology procedures and error calculation standard knowledge bases | Meets the requirement that daily documents include calibration procedures and error curves, to call compliant documents for content generation |
| Output Filtering | Retain metrology-related fields of no more than 800 characters | Follows the requirement for bid documents to streamline compliant deliverable information |
| Timeout Setting | 600–1200 seconds | Based on the time required for multi-point collection and error calculation, set a reasonable duration calibrated via actual testing |
| Retry Count | 2 times | Addresses potential temporary connection failures during calibration steps, to avoid workflow interruption from a single failed attempt |

## Three Common Misconfigurations
- Symptom: The output field of the specified reply node is empty, and logs show the corresponding variable was not found. Cause: The output results of the code execution node were not written to `variables`, causing subsequent nodes to fail to obtain intermediate data.
- Symptom: The output of the tool call module includes unconfigured debug information, and redundant content cannot be filtered. Cause: The tool raw output return option was not disabled in the node configuration, causing non-essential information to be mixed into the bid document.
- Symptom: The workflow returns a "knowledge base does not exist" error when calling the knowledge base. Cause: The unique identifier of the corresponding knowledge base was not copied from the knowledge base management page, or it was not correctly bound to the association configuration of the workflow node.

## How to Verify Correct Configuration
- Trigger the workflow, check whether the range and environmental monitoring parameters of the corresponding single device have been filled into `variables`.
- After running the workflow, confirm that the output node only retains fields required for bidding such as metrology certificate numbers, error values, and traceability chain information.
- Verify that the knowledge base association node can normally call calibration procedure documents to generate content compliant with metrology regulations.
- Simulate a temporary connection failure scenario, check whether the workflow executes retries according to the configured retry count.

The values provided here are common starting points and should be measured against the reader's own samples.
