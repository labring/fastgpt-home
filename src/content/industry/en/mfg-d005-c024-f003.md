# Bid Document and Quotation Preparation for Process Change and Engineering Change: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data for this category comes from manufacturing enterprises' PLM, ERP, MES, supplier materials, validation tests, and customer-specific requirements. Daily documents include ECN/ECR, change assessment reports, drawings and BOM version documents, process validation reports, transition plans, inventory disposal forms, and customer approval documents. Data updates are triggered by each change, with no fixed cycle. Document fields include change unique identifier, associated bill of materials, process node number, effective date, and validation batch number. Units include pieces, kilograms, dates in YYYY-MM-DD format, and more. Each change session corresponds to an independent set of associated data.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Data sources are scattered across multiple systems. Multi-turn dialogue must accurately bind to the data source of the corresponding change session to avoid cross-system data confusion. Updates have no fixed cycle. Each dialogue must load the latest version of change documents, and cannot rely on cached old data. Document structures include multiple associated attachments. Multi-turn dialogue must filter corresponding attachments by change number to avoid redundant content. Fields include version numbers and effective dates. Prompt engineering must specify parameters for fetching the effective version to prevent mixing of old and new versions. Bid document and quotation preparation requires accurate matching of change content. Multi-turn dialogue must bind historical context to track the change iteration process.

## How to configure the settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` binding rule | Bind the change unique identifier as `chatId` | Change data is grouped by session, and `chatId` can accurately associate with corresponding ECN/ECR documents and historical dialogues |
| Historical message loading range | Load the first 10 entries of the `messages` context | Change-related dialogue history typically does not exceed 10 turns, to avoid context overload that impacts generation efficiency |
| Preset variable configuration | Preset `variables` as change number, BOM version number, effective date | Bid documents and quotations require accurate matching of materials, processes, and customer requirements associated with the change |
| Single reply length | 800–1200 characters | Calibrated through actual testing, to meet the needs of segmented writing and clear typesetting for bid documents |
| Interface timeout threshold | 600 seconds | Pulling change data requires cross-system queries across PLM, ERP, and other systems, so sufficient response time must be reserved |

## Three common misconfigurations
- Phenomenon: After deleting the dialogue record corresponding to `chatId`, the change association record for that session in the system log disappears synchronously. Cause: Independent storage binding between logs and dialogue sessions is not configured, and log data is mistakenly bound to the `chatId` dimension.
- Phenomenon: The bid document generated by the prompt engineering does not reference the multi-turn historical communication content of the current change. Cause: The `messages` parameter is not bound in the prompt engineering, and historical dialogue context is not called to align change details.
- Phenomenon: The quotation generated by multi-turn dialogue includes irrelevant material data not associated with the current change. Cause: The query scope is not limited via `variables`, resulting in calls to bill of materials from other change sessions.

## How to verify correct configuration
- Use the FastGPT v4.17.0 test environment, enter a test change number, and check that the documents returned by the dialogue only include associated files such as the corresponding ECN/ECR, BOM version, and process validation report.
- Manually delete a test dialogue record, and check that the system log retains the operation record for that session, and does not disappear along with the deletion of the dialogue.
- Adjust the BOM version number parameter in `variables`, and check that the generated quotation content synchronously updates the corresponding material usage and process requirements.
- View the `messages` history list, confirm that only dialogue fragments from the current session are loaded, with no content from other irrelevant change sessions.

The values provided are common starting points and should be measured against the reader's own samples.
