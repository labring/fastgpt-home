# Bid Documentation and Quotation Preparation for Process Change and Engineering Change: Forms and Interactions

## What this category of data looks like
This category of data is generated by a change management team composed of R&D, process, quality, production, and procurement staff at manufacturing enterprises. Core documents include ECN/ECR forms, change assessment reports, drawings and BOM version records, process verification reports, production transition plans, inventory disposal documents, and customer approval files. Data sources cover PLM, ERP, MES systems, supplier materials, verification test results, and customer-specific requirements. Updates trigger irregularly for each change. A single change requires synchronized updates and version management across multiple document types.

## Constraints for Forms and Interactions
Data sources are scattered and connected to multiple business systems. Forms must support cross-data source field pulling and automatic matching. Multi-department collaborative participation requires fine-grained role permission configuration to block unauthorized modification or leakage of sensitive change information. A single change involves multiple document types, so forms need multiple content partitions to separate basic information, associated files, and approval nodes. Updates have no fixed cycle, so forms must support temporary field validation and version locking to prevent incomplete changes from being misused. To identify chain effects of design, material, and process changes and switching points between old and new versions, forms need built-in associated field prompts to cut down manual verification costs. Mandatory validation for customer approval files requires configuration of required fields and attachment upload rules to ensure compliance.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Maximum 2000 characters per single field | Meets the typical length requirement for ECR description text, and follows the form input limit rules of FastGPT v4.17.0 |
| `userSelect` | Optional role range includes R&D, process, quality, procurement | Matches the core participating roles of the change management team to clarify responsibility boundaries |
| Attachment upload limit | Maximum 100 MB per file, total upload cap of 500 MB | Fits the typical storage size of drawings and BOM version files, avoiding exceeding system load limits |
| Field validation trigger | Automatic validation before submission | Prevents submission of changes with incomplete required fields, lowering error rates |
| Multi-department permissions | Assign field editing permissions by role | Aligns with cross-department collaboration rules for change management, stopping unauthorized modifications |

## Three Common Configuration Mistakes
- Phenomenon: A "field format error" appears after form submission, but no specific abnormal field is indicated. Cause: No format validation rule is configured for `formInput`, so the fixed coding rule for ECN numbers cannot be matched.
- Phenomenon: When importing a BOM file exported from PLM, the page continuously refreshes and the target field cannot be selected. Cause: No data source import timeout threshold is configured for the form, leading to an unresponsive state during large file imports.
- Phenomenon: Content overwriting occurs when multiple users edit the same change form simultaneously. Cause: The collaborative editing lock configuration for `userSelect` is not enabled, and concurrent editing permissions are not restricted.

## How to Verify Successful Configuration
- Manually enter text that follows ECN number rules, and check if `formInput` triggers format validation prompts.
- Switch to accounts with different roles, and verify that the permissions configured for `userSelect` work as expected, only allowing corresponding roles to edit specified fields.
- Upload a drawing file under 100 MB, and confirm that the attachment upload completes normally and links to the form.
- Simulate multiple users editing the same form at the same time, and verify that the collaborative lock function activates to prevent content overwriting.
