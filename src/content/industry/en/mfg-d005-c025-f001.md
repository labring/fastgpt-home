# Bid Document and Quotation Preparation for Tooling, Fixture and Gauge Manufacturing: HTTP Interfaces and External Systems

## What the data for this category looks like
Daily documents for this category include tooling requirement specifications, positioning datum schemes, fixture drawings, gauge operation manuals, acceptance reports, calibration records, and change histories. Data comes from product digital models and GD&T tolerance data, process routes, coordinate measuring machine data, on-site trial feedback, and metrology systems. Data updates trigger with individual project launches, product design changes, and regular metrology calibrations. Updates include structured fields such as positioning datum parameters, dimensional tolerance values, calibration deviation values, and version numbers, plus unstructured files like 2D and 3D drawings.

## What constraints these characteristics impose on HTTP interfaces and external systems
Daily documents contain both structured fields and unstructured drawings. HTTP interfaces must support multi-type data transmission to avoid format conversion losses. Data updates have no fixed cycle. Interfaces must support on-demand trigger synchronization to adapt to full or incremental data pulls for individual projects. Data links to core business processes including positioning datum, interference verification, and GRR acceptance. Interfaces must pass corresponding parameters to external quotation and bid systems to ensure consistent data links. Metrology calibration data has strict precision requirements. Interfaces must be compatible with metrology system output formats to prevent numerical deviations from affecting bid quotation accuracy.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| API key verification | Enable `Authorization` parameter verification | Matches the high sensitivity requirements of category data to prevent unauthorized access |
| Single request data volume | 800–1200 characters of structured fields + single file no larger than 5 MB, set timeout to 600 seconds | Adapts to the interface load limits of external systems to avoid transmission timeouts and data loss |
| Context association variables | Bind project number, GD&T tolerance values | Links core business parameters of tooling and fixtures to ensure matching between bid documents and quotations |
| Streaming output switch | Calibrate based on actual measurements | Adapts to the requirements of large model calls that only support stream mode |
| Response data format | Include `responseData` field and standard error codes | Clearly distinguishes normal returns from abnormal situations to facilitate processing by external systems |
| Session parameter binding | Pass `variables` parameter to associate the current project | Meets session isolation requirements in scenarios with multiple parallel projects |

## Three common errors
- When calling the interface and passing the chatId parameter, the corresponding session identifier does not appear in the conversation log. This happens because session context association information is not bound via the `variables` parameter in the request body.
- The interface returns `{"code":514,"statusText":"unAuthApiKey","message":"common:code_error.e`. This happens because the `Authorization` parameter does not carry a valid key or uses an incorrect format.
- When calling the interface, key dimensional content of chunked fixture drawings cannot be retrieved. This happens because the chunk range of the target document is not specified via the `variables` parameter in the FastGPT v4.17.0 model configuration.

## How to confirm the configuration is correct
- Send a test request to verify the `Authorization` parameter is parsed correctly, and confirm a 200 status code is returned.
- Review the `responseData` field in the interface response to confirm it includes core parameters such as the current project's tooling requirement specification and GD&T tolerance values.
- When testing a streaming call, confirm content is returned incrementally by chunk, which matches bid document preparation requirements.
- Check that session parameters are passed via `variables` to ensure data isolation during multiple parallel projects.
