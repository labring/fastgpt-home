# Bid Document and Quotation Preparation for Fixture and Gauge Manufacturing: Multi-turn Dialogue and Prompt Engineering

## Data Profile for This Category
Data for this category originates from product 3D models and GD&T, process routes, coordinate measuring machine data, on-site trial feedback, and metrology systems. Daily documents include fixture requirement specifications, positioning datum schemes, fixture drawings, gauge operation manuals, acceptance reports, calibration records, and change histories. Data updates are conducted per project milestones, each product modification, and regular calibration. Core fields include positioning and clamping scheme parameters, interference verification results, gauge repeatability and reproducibility data, and calibration cycles.

## Constraints for Multi-turn Dialogue and Prompt Engineering Workflows
Data sources cover multi-dimensional engineering documents and metrology data. This requires multi-turn dialogue to split context by document type, to avoid mixing GD&T data and calibration records from different projects. The update pattern tied to projects and changes requires dialogue context to be bound to `chatId` to distinguish different bidding projects, preventing cross-project data confusion. The professional nature of core fields requires prompt engineering to preset engineering term mapping rules, ensuring accurate recognition of content such as positioning datums and interference verification. Additionally, the timeliness of calibration records and change histories requires the dialogue to actively inquire about the latest change nodes for the current project, avoiding expired data use when generating quotations and documents. This prevents batch out-of-tolerance issues caused by clamping deviations or gauge misjudgments.

## Three Common Misconfigurations
- Issue: Dialogue response time exceeds 600 seconds, while model call grouping displays 1 group. Cause: `variables` are not bound to reference project-specific coordinate measuring machine data, causing the large language model to repeatedly retrieve offline documents and extend processing time.
- Issue: No temperature parameter setting button is found when configuring the large language model. Cause: The advanced configuration panel for multi-turn dialogue is not enabled. The temperature parameter must be adjusted in the advanced settings after binding exclusive fields.
- Issue: A configuration error occurs after adding a database connection plugin. Cause: Database query fields are not limited to exclusive data such as calibration records and fixture drawings for this category, triggering field mismatch verification.

## How to Verify Proper Configuration
- A new bidding project dialogue is started, and `chatId` is verified for automatic generation and binding to the project number.
- A question related to positioning datums is entered, and the reply is checked for automatic matching of preset engineering term mapping rules.
- The database plugin is called, and confirmation is made that loading only triggers when calibration data is queried, with no redundant irrelevant data returned.
- Three consecutive questions are initiated, and each question is verified for correct recognition and inclusion in the context sequence.
