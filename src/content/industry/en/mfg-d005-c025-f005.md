# Bid Document and Quotation Preparation for Fixture, Jig and Gauge Manufacturing: Tool Calling and Plugins

## What this category’s data looks like
Daily documents for this category include fixture requirement specifications, positioning datum schemes, fixture drawings, gauge operation manuals, acceptance reports, calibration records, and change histories. Data sources cover product 3D models, GD&T, process routes, coordinate measuring machine inspection data, on-site trial feedback, and metrology systems. Data updates occur per project, trigger on each product change, and follow regular calibration cycles. Document fields include datum parameters, tolerance requirements, inspection values, calibration record numbers, and other items. Data structure adjusts dynamically according to project phase.

## What constraints these characteristics impose on tool calling and plugins
Data sources for this category are scattered and have varying formats. Tool calling must adapt to parsing rules for multiple data types, including product 3D models, GD&T tolerance tables, and coordinate measuring machine inspection reports, to avoid deviations in parameter extraction. Data updates have no fixed schedule. Plugins must support real-time pulling of the latest calibration records and change histories based on project milestones or change triggers, to ensure data timeliness in bid documents and quotations. Document types cover the full workflow of design, inspection, and acceptance. Tool calling must match field extraction logic for different document types. For example, extract positioning dimensions from fixture drawings, and obtain qualified judgment results from calibration records. Data errors can lead to serious consequences such as batch machining deviations. Tool calling must add a pre-check step to ensure extracted parameters meet tolerance requirements.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Workflow/API tool selection | `auto` | Adapts to tool calling needs for multiple types of fixture documents for this category. FastGPT v4.17.0 supports flexible configuration of this parameter |
| Workflow/API function-call configuration | Enabled | Forces the model to call specified tools to extract fixture data, avoiding unstructured output that affects quotation accuracy |
| Maximum number of returns per single tool call | `First 6 items` | This category has a large number of associated documents per project. Limiting return count prevents context overflow |
| Tool call timeout period | `100–150 seconds` | Coordinate measuring machine data parsing requires reasonable processing time. The interval is set based on actual measurement calibration |
| Knowledge base association trigger condition | Matching score ≥0.75 | Ensures the associated fixture standard documents meet business requirements for matching degree with current bid requirements |
| Document chunk length | `800–1200 characters` | Adapts to content length of documents such as fixture drawings and calibration records, preventing key parameters from being lost during chunking |

## Three Common Mistakes
- After local deployment, the first tool call works normally, but subsequent requests with multiple content throw errors directly. The cause is that a reasonable tool call timeout period is not configured, and coordinate measuring machine data parsing times out before a response is completed.
- The fixture parameters returned by tool calls do not match the actual documents. The cause is that the correct document chunk length is not set, leading to key parameters being lost during chunking.
- No knowledge base fixture standard documents are associated during tool calls. The cause is that knowledge base association configuration is not enabled, or the matching threshold is set too high, so relevant documents cannot be matched.

## How to Confirm Correct Configuration
- Submit a test request containing fixture requirement specification content. Check whether the parameters returned by tool calls include core fields such as datum parameters and tolerance requirements, to verify that the parsing logic adapts to the category’s document characteristics.
- Trigger a tool call, then view the number of associated knowledge base documents. Confirm that the returned count follows preset rules, to verify that the single call limit configuration takes effect.
- Simulate a bid request containing product change information. Check whether the tool can pull the latest change histories and calibration records, to verify that the real-time update configuration works properly.
- View tool call logs to confirm that responses are completed within a reasonable time frame, to verify that the timeout configuration meets the actual needs of this category’s data processing.
