# Bid Document and Quotation Preparation for Fixture and Gauge Manufacturing: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Daily documents for this category include tooling requirement documents, positioning datum schemes, fixture drawings, gauge operation manuals, acceptance reports, calibration records, and change histories. Data sources include product 3D models and GD&T, process routes, coordinate measuring machine data, on-site trial feedback, and metrology systems. Updates follow individual project timelines, each product design change, and regular calibration cycles. Most document structures include fields such as geometric tolerance parameters, process steps, calibration cycles, and change nodes. Some drawing documents also include dimension units and precision requirements.

## Constraints Imposed on Knowledge Base Retrieval and Recall
This category’s data includes multiple types of structured text and unstructured drawing documents. Retrieval must adapt to both professional terminology and geometric parameters, to avoid deviations caused by generic keyword recall. Data is updated dynamically per project and change, so indexes must support incremental synchronization by project. This prevents expired calibration records and change histories from being included in the current bid’s knowledge base. High-precision GD&T parameters and dimension unit requirements need retrieval matching accuracy that covers engineering-level numerical values, rather than relying solely on generic semantic similarity. The uncertain update cadence requires retrieval configurations to support quick index rebuild triggers. This avoids data missing during the bid process due to delayed indexing.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches engineering-level semantics for GD&T parameters and precision requirements. Avoids recalling irrelevant solutions if set too low, and misses eligible past projects if set too high. |
| `limit` | Top 8 results | Bid documents need to reference 3-5 typical past projects. This setting retains sufficient alternatives while controlling context length, adapting to engineering document retrieval needs. |
| `searchMode` | Exact matching | Adapts to structured parameter retrieval for tooling fixtures, prioritizes recalling valid documents that include specified datums and dimensions. |
| `usingReRank` | Enabled | Performs secondary sorting of recall results by matching degree with bid requirements, prioritizes returning high-value documents such as acceptance reports and calibration records. This is a general enhanced configuration that can be directly enabled on self-hosted FastGPT v4.17.0 instances. |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands industry-specific terms in bid requirements, for example expanding "positioning datum" to "GD&T positioning datum scheme", to improve recall rates for professional content. |
| `collectionIds` | Bind the current project’s tooling knowledge base collection | Prevents expired cross-project data from being included in the current bid’s retrieval scope, ensuring retrieval content only covers project documents required for the current bid. |

## Three Common Mistakes
- Symptom: 60-second timeout error occurs when switching knowledge base indexes. Cause: Incremental index updates by project dimension are not configured. When fully rebuilding a dataset containing large numbers of drawings and coordinate measuring machine data, the processing cycle exceeds the default threshold.
- Symptom: Target fixture drawings or calibration records are not returned in retrieval results, making it impossible to reference knowledge base files. Cause: `datasetSearchUsingExtensionQuery` is not enabled, leading to missing recall due to failure to match industry-specific terms, or the `similarity` threshold is set too high to filter valid content.
- Symptom: The knowledge base remains in the training or rebuilding state for an extended period, and indexes cannot be switched. Cause: Change-triggered incremental updates are not set. When fully synchronizing a dataset containing multiple types of documents, the processing cycle exceeds expectations, and reasonable synchronization trigger rules are not configured.

## How to Verify Proper Configuration
- Enter a search term including "GD&T positioning datum", check that recall results include positioning datum scheme documents from past projects.
- Trigger an incremental index update, confirm that the system log shows synchronization time falls within the preset range for project-level data volume, as calibrated through actual testing.
- Switch to the specified project’s knowledge base collection, confirm that the retrieval scope only includes documents such as current project tooling requirement documents and fixture drawings, with no cross-project data included.
- After enabling the reranking function, check that sorted recall results prioritize documents such as acceptance reports and calibration records, which ranked lower in the initial recall order.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
