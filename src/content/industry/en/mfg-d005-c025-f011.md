# Bid Document and Quotation Preparation for Fixture and Gauge Manufacturing: Forms and Interactions

## What data looks like for this category
Daily documents for the fixture and gauge manufacturing category include fixture requirement documents, positioning benchmark plans, fixture drawings, gauge operation manuals, acceptance reports, calibration records, and change histories. Data sources include product 3D models and GD&T parameters, process routes, coordinate measuring machine data, on-site trial feedback, and metrology systems. Data updates follow individual projects, product changes, and regular calibration cycles. Fields include positioning benchmark parameters, tolerance values, calibration cycles, change history numbers, and more, using units such as millimeters, newtons, and calibration days.

## What constraints these characteristics impose on forms and interactions
There are many daily structured documents. This requires forms to be split into dedicated modules by document type, to avoid mixing fields. Data comes from professional engineering data sources. This requires forms to support importing structured parameters from external systems, without manual duplicate entry. Update frequency is high. This requires forms to have version tracking and change reminder capabilities, to match project iteration rhythms. High-precision parameter input requires forms to include built-in unit verification and precision limits, to reduce manual errors. The rigor requirements for bid documents require forms to trigger necessary verification steps before submission, to proactively avoid risks such as clamping deviation and gauge misjudgment.

## How to configure the settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Limit file upload formats to STEP, IGES, TXT, maximum 100 MB per file | Match standard import formats for product 3D models and coordinate measuring machine data, avoid non-engineering files occupying resources |
| `userSelect` | Preset positioning benchmark plan and calibration cycle options, include ±0.01mm, ±0.005mm tolerance values | Reduce manual input errors, match common engineering parameters for fixture manufacturing |
| Form input control type | Adapt to field types: use value controls with units for GD&T tolerances, file upload controls for fixture drawings | Correspond to structured and unstructured field characteristics of fixture data |
| Context window size | 8000–12000 token | Cover all engineering parameters and document content required for bid documents |
| Tool call trigger timing | Automatically trigger before form submission | Proactively verify positioning plans and interference conditions, ensure accuracy of bid documents |
| Form version record | Automatically save modification time and operator for each change | Match update frequency of project changes, facilitate history tracking |

## Three common errors
- Phenomenon: Tool call cannot select the fixture-specific document knowledge base. Cause: Documents of this category such as fixture requirement documents and fixture drawings are not configured as knowledge base associated data sources.
- Phenomenon: Interface lag occurs when dragging form fields. Cause: `formInput` is configured with unlimited multi-file uploads, causing front-end overload from loading large numbers of engineering file resources.
- Phenomenon: Quotation results returned by API calls differ significantly from online chat. Cause: The context association logic consistent with online chat is not enabled in API configuration, and historical parameters of the bid project are not passed.

## How to confirm correct configuration
- Upload a product 3D model file in STEP format, confirm that the form automatically recognizes and loads GD&T parameter fields.
- Trigger tool call before submitting the form, confirm that the system automatically verifies positioning plan interference conditions and returns verification results.
- Switch between online chat and API call modes, input the same bid project parameters, confirm that returned document content is consistent.
- Modify form fields, confirm that version change records are automatically generated.
