# Tender Document and Quotation Preparation for Non-Ferrous Metal Smelting and Electrolysis: HTTP Interfaces and External Systems

## What This Category’s Data Looks Like
The data for this category comes from concentrate and auxiliary material analysis reports, DCS control systems, cell voltage and current monitoring devices, laboratory test results, and energy and environmental monitoring platforms. Daily associated documents include batching lists, smelting records, electrolytic cell status records, test reports, anode and cathode quality records, and environmental protection ledgers. Data update cycles synchronize with each batch of raw materials, each furnace run, or each electrolytic cell; some real-time monitoring indicators have higher update frequencies. Data fields cover raw material component proportions, furnace temperature parameters, cell voltage and current values, metal recovery rates, pollutant emission concentrations, and more, with units matching the indicator type.

## Constraints Imposed by These Characteristics on HTTP Interfaces and External Systems
The multi-source heterogeneous data sources and differentiated update cycles of this category require HTTP interfaces to support parallel data pulling across multiple endpoints, while adapting to timestamp alignment logic for different data. The diverse document fields and non-uniform units require interface configuration to support custom field mapping and unit conversion rules. Real-time or near-real-time update requirements require interface timeout settings to match business response thresholds, to avoid impacting quotation preparation due to data pulling delays. For core data such as metal recovery rates and environmental protection indicators, interfaces must return complete fields to prevent accounting errors caused by missing fields.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Interface Authentication Method | Use the `Authorization` header with a Bearer token | Complies with the interface authentication specifications of FastGPT v4.17.0, ensuring access security for external production system interfaces |
| Request Variable Configuration | Pass `variables` as raw material batch number and electrolytic cell ID | Accurately pull production data for the corresponding batch or cell, avoiding confusion across batches of data |
| Return Data Processing | Extract fields including metal recovery rate, cell voltage, and pollutant concentration from `responseData` | Filter redundant monitoring data not required for tendering, improving parsing efficiency for quotation preparation |
| Timeout Setting | 60–120 seconds | Adapts to the average response duration of multi-source heterogeneous data pulling, avoiding interface call interruptions |
| Data Pull Frequency | Pull batch historical data every 15–30 minutes, pull real-time indicators every 5 seconds | Balances data timeliness and the load pressure on production systems |
| Field Mapping Rules | Map production data fields to corresponding variables in the tender template | Ensures complete matching between data in tender documents and actual production records |

## Three Common Misconfigurations
- Phenomenon: External interface calls return a 401 Unauthorized status code, or configured OneApi-related pages fail to load. Cause: The token format in the `Authorization` header is not correctly configured, or the token has expired and not been updated.
- Phenomenon: Pulled data fields are empty, resulting in blank content in tender documents. Cause: The correct field path is not specified in `responseData`, or valid raw material batch numbers or electrolytic cell IDs are not passed in the `variables` parameter.
- Phenomenon: Interface calls time out, causing the tender document preparation process to interrupt. Cause: The timeout setting is too short and does not match the actual response duration of multi-source data pulling, or the production system interface has excessive load.

## How to Verify Successful Configuration
- Call the configured HTTP interface, check whether the returned `responseData` includes preset business fields such as metal recovery rate and cell voltage.
- Pass a test raw material batch number or electrolytic cell ID as the `variables` parameter, verify whether the interface returns accurate data for the corresponding batch or cell.
- View interface call logs, confirm that authentication information in the `Authorization` header is carried normally, with no authentication failure errors.
- Simulate a scheduled pulling task, confirm that the data update frequency matches the preset business rhythm, with no abnormal interruptions.

The values provided are common starting points and should be measured against the reader's own samples.
