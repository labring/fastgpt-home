# Bid Document and Quotation Preparation for Non-Ferrous Metal Smelting and Electrolysis: Workflow Orchestration

## What Data for This Category Looks Like
Data for this category comes from concentrate and auxiliary material analysis reports, DCS systems, electrolyzer voltage and current monitoring data, laboratory test results, and energy and environmental protection monitoring ledgers. Documents generated daily include batching lists, smelting records, electrolyzer condition records, test reports, anode and cathode quality records, environmental protection ledgers, and more. Data update pace advances in real time with each batch of raw material feeding, each furnace smelting cycle, and each electrolyzer’s operating conditions. Each document includes fields such as raw material composition, tank parameters, metal recovery rate, and pollutant emissions. Units include mass percentage, current intensity, tons, and others.

## What Constraints Do These Characteristics Impose on the "Workflow Orchestration" Link
Data sources are scattered and updated in real time, so workflows must support parallel pulling from multiple data sources. There are many document fields with close relationships, so cross-node field mapping relationships must be bound in `variables` to ensure consistent data flow across links. The update pace advances in real time with feeding, furnace batches, and tank conditions, so workflow triggers must match production event nodes. For links involving metal balance and byproduct accounting, fixed field verification rules are required to avoid data deviations affecting quotation accuracy. Bid documents must be associated with historical production data, so workflows must support associated query and call of historical operating condition data.

## How to Set the Configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `variables` | Bind core fields such as raw material composition, tank voltage, test results | Match the core data fields of documents in this category to ensure consistent cross-node data flow |
| Trigger method | Trigger according to production event nodes | Match the real-time production pace to avoid unnecessary runs |
| Single request timeout | 600 seconds | Adapt to the time consumption requirements of pulling multiple data sources, calibrated based on actual measurements |
| File upload parameters | Configure file type fields in form format | Support batch upload and transmission of documents such as smelting records and test reports |
| `nodeId` | Bind data verification nodes and quotation accounting nodes | Ensure that the node execution order and logic of core accounting links match |
| Failure retry strategy | Retry 2 times, interval 30 seconds | Adapt to occasional network fluctuations in real-time data pulling, avoid workflow interruptions |

## Three Common Mistakes
- Phenomenon: The workflow executes normally in the run preview page, but there is no corresponding output content in the chat page. Cause: No public output node is configured in the workflow, or the `variables` parameter mapping of the chat window is not bound.
- Phenomenon: When configuring form-data for the HTTP request node, sending fails after setting the file type parameter. Cause: The local file path is not correctly bound, or the upload control corresponding to the document type is not selected, resulting in parameter format mismatch.
- Phenomenon: An error "Load file error" is prompted when uploading production documents, but knowledge base upload works normally. Cause: The file reading permission of the workflow node is not configured, or the document fields contain unsupported special characters, resulting in file parsing failure.

## How to Confirm the Configuration Is Correct
- Trigger a simulated production event, check whether the logs of each workflow node show correct data source pulling results.
- Call test batching list and test report documents, verify that the `variables` field mapping is complete and has no missing items.
- Configure a file upload test, confirm that the file type field of the form-data parameter can normally send documents.
- View the workflow status monitoring panel, confirm that the node execution order matches the preset configuration.

The values provided here are common starting points and should be measured against the reader's own samples.
