# Bid Document and Quotation Preparation for Non-Ferrous Metal Smelting and Electrolysis: Tool Calling and Plugins

## What the data for this category looks like
Business data for non-ferrous metal smelting and electrolysis comes from concentrate and auxiliary material analysis reports, DCS production control systems, cell voltage and current monitoring systems, laboratory test results, and energy and environmental ledgers. Daily generated documents include batching lists, smelting records, electrolytic cell condition records, laboratory reports, anode and cathode quality records, and environmental ledgers. Data updates occur in real time alongside each batch of raw material feeding, completion of each furnace smelting run, and changes to each cell’s operating conditions. Core fields include raw material component proportions, cell voltage and current values, metal recovery rates, and byproduct content. Common units are percentage, ampere, volt, ton, and other standard units.

## What constraints these characteristics impose on tool calling and plugin workflows
Data updates in real time per production batch. Tool calling must bind to the latest data interface for the current batch. Using expired historical records will cause mismatches between quotations and document content. Multiple document types have different field structures. Plugins require configuration of field mapping rules for each target document when reading data. A single fixed template cannot be used universally. Real-time monitoring data for electrolytic cell groups has high volume. Plugin call frequency must match the batch update rhythm. This prevents excessive system resource usage from frequent triggers. Metal balance and byproduct disposition accounting relies on multi-source data aggregation. Tools must support cross-data source field association queries to ensure accurate accounting results. The `toolChoice` and `functionCall` parameters must be configured correctly. This ensures flexible tool calling and compliant result formats.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ------ | -------- | ----------- |
| `toolChoice` | `auto` | Adapts to dynamic calling needs for multi-source data, automatically selects matching tools to handle tasks such as batching accounting, cell condition analysis, and metal balance calculation |
| Single tool call timeout | 300–600 seconds | Matches the time range required for electrolytic cell condition accounting and metal balance calculation, prevents early termination of calls due to complex operations |
| Tool call context limit | Previous 8 historical batch data | Limits the volume of historical data per call, adapts to memory usage requirements for multi-batch data aggregation |
| `functionCall` | Enabled | Forces structured return of accounting results, facilitating automatic insertion of standardized quotation and component data into bid documents |
| Plugin trigger rule | Trigger per batch | Matches the update rhythm of raw materials and furnace/cell data, avoids unnecessary repeated calls |

This configuration is compatible with FastGPT v4.17.0.

## Three common configuration errors
- Plugin clicks do not respond. The interface or logs show empty return fields. The cause is missing field mapping rules for the target document. Tools cannot extract required component and quality data from batching lists or cell condition records.
- Continuous plugin calls overnight deplete available API credits. The cause is failure to set the per-batch trigger rule. Plugins are configured to poll real-time data on a fixed schedule, and repeatedly call interfaces even when no new batch updates occur.
- Multiple plugin call prompts appear per conversation. The cause is not disabling the in-conversation automatic plugin call switch. Each round of replies repeats tool call requests, which does not meet the requirement of only one prompt per conversation.

## How to confirm the configuration is correct
- Manually trigger a plugin call. Check if the returned results include core business fields such as current batch batching components, cell voltage and current.
- Review tool call logs. Confirm that calls are only triggered when new raw material batches or furnace/cell data are updated. No unnecessary scheduled calls appear in the logs.
- Submit a test bid document request. Check if the plugin returns accounting results in a structured format that can be directly inserted into preset document templates.
- Simulate abnormal scenarios to trigger calls. Confirm that the plugin returns reasonable prompt information. No null values or abnormal errors appear, and no irrelevant data is accidentally included.
