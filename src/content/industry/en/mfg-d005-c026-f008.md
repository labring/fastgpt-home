# Tender Document and Quotation Preparation for Non-Ferrous Metal Smelting and Electrolysis: Document Parsing and Chunking

## What data for this category looks like
This category covers smelting, electrolysis, assay, and scheduling departments of enterprises producing copper, aluminum, lead-zinc, and similar materials. Daily documents include batching lists, smelting records, electrolytic cell condition logs, assay reports, anode and cathode quality records, and environmental protection ledgers. Data sources include concentrate and auxiliary material analysis reports, DCS systems, cell voltage and current monitoring data, laboratory results, and energy and environmental protection monitoring equipment. Updates are generated in real time when each batch of raw materials, each furnace run, or each cell operation completes. Fields include composition parameters, equipment operating values, quality indicators, and environmental monitoring items. Units use specialized measurement standards for specific categories, such as current and weight.

## What constraints do these characteristics impose on document parsing and chunking
The multi-source real-time documents and specialized measurement characteristics of this category impose multiple constraints on document parsing and chunking.
Mixed-format documents include structured assay reports, time-series smelting records, and cell condition logs. Parsing must distinguish structured fields from unstructured text. This avoids losing the binding relationship between cell numbers, furnace numbers, and corresponding data during splitting.
Real-time updated operation documents require chunking matched to batch dimensions. This prevents content from different raw material batches from being mixed into the same chunk. Mixed batches would disrupt raw material cost accounting for subsequent quotations.
Specialized measurement fields must retain unit associations. This ensures parsed data can be directly used for component balance and cost accounting.
Complete entries in environmental protection ledgers must be chunked separately. This avoids truncation of compliance information.

## How to configure the settings
This configuration is based on FastGPT v4.17.0. Specific parameter configurations are listed below:

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | Matches the length of single operation records for this category, such as single-cell electrolysis data or single-furnace smelting parameters, to avoid splitting the binding of key fields |
| `chunkSplitter` | Mixed paragraph and fixed-length splitting | Adapts to mixed-format documents, retaining structured paragraphs of batching lists and assay reports while splitting long time-series logs by length |
| `customPdfParse` | Enabled | Adapts to structured PDF reports for this category, such as assay reports and environmental protection ledgers, retaining field binding relationships within tables |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Covers the upload limit for multiple document collections related to a single batch of raw materials, meeting the demand for batch submission of tender documents |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Adapts to the parsing time of multi-page complex ledgers and real-time monitoring logs, avoiding parsing timeouts for long documents |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for the specialized document structure of this category, adapting to chunking logic for different document types such as batching lists and cell condition records |

## Three common mistakes
- Phenomenon: After enabling file upload in the workflow, calling the document parsing tool with a file address returns an error. The error states the file does not exist or a timeout occurred. Cause: The `CUSTOM_READ_FILE_URL` environment variable is not configured correctly. Or the port of the locally deployed file service is not open. This prevents the parsing tool from accessing the uploaded file.
- Phenomenon: Some structured PDFs such as assay reports and environmental protection ledgers have missing fields after parsing. Table content is split into scattered text chunks. Cause: The `customPdfParse` configuration is not enabled, or the chunking rule does not retain the table structure. This causes individual table rows to be split into multiple independent chunks.
- Phenomenon: Chunking results include electrolytic cell condition records across furnace heats. This leads to confusion of raw material batches during subsequent quotation preparation. Cause: The `chunkSplitter` only uses fixed-length splitting, and does not use operation batches or cell numbers as chunking boundaries. This causes cross-batch content to be merged.

## How to confirm the configuration is correct
- Upload a single cell electrolytic cell condition record. Check whether the parsed chunks completely retain the binding relationship between the cell number and the corresponding voltage and current data.
- Upload a batch collection of documents related to tender projects. Confirm there are no prompts for failed file uploads or parsing timeouts.
- Adjust the chunking configuration. Compare the parsing results of different format documents, such as batching lists and smelting logs. Confirm the chunking rules adapt to the specialized document structure of the category.
- Check the environment variable configuration. Confirm that `CUSTOM_READ_FILE_URL` points to the correct local file service address. Ensure there are no path errors.

The values given are common starting points and should be measured against the reader's own samples.
