# Tender Document and Quotation Preparation for Non-Ferrous Metal Smelting and Electrolysis: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
The core data for this category comes from smelting, electrolysis, laboratory testing, and scheduling departments of copper, aluminum, lead-zinc, and other smelting enterprises. Daily documents include batching lists, smelting records, electrolytic cell condition records, laboratory test reports, anode and cathode quality records, and environmental protection ledgers. Data sources cover concentrate and auxiliary material analysis reports, DCS system data, cell voltage and current monitoring, laboratory test results, and energy and environmental protection monitoring systems. Data updates automatically in real time upon completion of each batch of raw materials, each furnace, or each cell operation. Some cell condition records sync hourly. Document fields include material component proportions, furnace temperature parameters, cell voltage values, metal recovery rates, pollutant emission indicators, and more. Some records require matching batch numbers and work team information.

## Constraints on Knowledge Base Retrieval and Recall
Real-time and high-frequency update requirements mean knowledge base retrieval must support low-latency recall, avoiding delayed data that could reduce tender quotation accuracy. Multiple types of heterogeneous documents and fields mean retrieval must support cross-document field matching, such as associating batch information between batching lists and electrolytic cell condition records. Fine-grained operation granularity means retrieval must accurately associate results with operation batches, avoiding mixing data across batches. Complex component and parameter fields mean retrieval must prioritize matching high-weight core indicators such as impurity content and cell voltage, focusing on semantic matching of professional parameters. Tender quotations require balancing metal recovery rates and costs. Retrieval must quickly locate historical accounting data for corresponding batches, shortening the preparation cycle.

## Configuration Settings
This configuration is adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | Matches smelting technical terms and numerical parameters, avoiding low-similarity irrelevant data |
| `limit` | Top 8 entries | Controls the number of retrieval results, adapts to multi-index verification needs of tender documents, and avoids context overload |
| `usingReRank` | Enabled | Optimizes sorting priority of core parameters via re-ranking for multi-source heterogeneous smelting data |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands technical terms in tender questions to associate with corresponding business fields |
| `collectionIds` | Configured by grouping smelting, electrolysis, and laboratory testing | Distinguishes business domains, preventing cross-domain data from interfering with precise tender document retrieval |

## Three Common Misconfigurations
- An error occurs in question answering after configuring the knowledge base, while knowledge base search tests function normally. The cause is failure to correctly associate the `collectionIds` for the business domain, with cross-domain data mixing leading to abnormal context formatting.
- Online calls fail to return valid results. The cause is that the `similarity` threshold is set too high, failing to match historical data for corresponding batches, or the `limit` value is set too low, causing result truncation.
- Retrieval results do not display core parameters first. The cause is that `usingReRank` is not enabled, and professional parameter weights are not optimized.

## How to Verify Proper Configuration
- Enter the knowledge base retrieval test interface, input a question containing electrolytic cell voltage and batching list components, and verify whether returned results include fields from the corresponding business documents.
- Check the number of retrieval results to confirm alignment with the `limit` setting value.
- Compare retrieval results with and without `usingReRank` enabled, confirming whether core parameters are prioritized in sorting.
- Review question and answer logs to confirm no cross-business domain data loading errors have occurred.

The values provided are common starting points and should be assessed against relevant on-site samples.
