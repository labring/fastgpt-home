# Bid Document and Quotation Preparation for Mold Design and Manufacturing: Workflow Orchestration

## What the data for this category looks like
Business data in the mold design and manufacturing field mainly comes from customer product models, mold flow or forming simulation files, CAD/CAM output files, machining and measurement data, and test sample inspection records. Data is updated in line with project progress, with new documents and records generated after each mold trial or modification. Daily produced documents include mold design task sheets, DFM reports, part drawings, machining process cards, mold trial reports, modification notices, and mold history records. Fields include professional parameters such as number of mold cavities, draft angle, material grade, machining tolerance (unit: mm), and other related specifications.

## What constraints these characteristics impose on the "workflow orchestration" link
Data for this category is updated per project and includes multiple types of professional documents, so workflows must bind project-specific exclusive parameters to prevent cross-project data confusion. The existence of multiple document types requires workflows to set branching nodes to adapt to the processing logic of different documents. The requirements for professional fields and units mean that knowledge base retrieval must match tags and parameter formats to ensure retrieval results comply with business specifications. Frequent mold trial and modification updates require workflows to associate the latest document versions in real time, ensuring that bid quotations align with the current mold status.

## How to configure
This configuration is adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Bind project ID, mold material grade, customer demand tags | Match project-specific data for mold design and manufacturing to avoid cross-project data confusion |
| Knowledge base retrieval tag filtering | Enable, bind preset tags `DFM report`, `mold trial report`, `machining process card` | Category documents have clear classification tags, which can narrow the retrieval scope and focus on valid content required for bidding |
| Workflow branch trigger rules | Trigger corresponding nodes by document type | Category documents include multiple types such as design, mold trial, and modification, requiring branching to handle verification and extraction logic for different documents |
| Single retrieval result limit | Top 10 entries | Control the amount of retrieval information to avoid redundant data interfering with bid document preparation |
| Historical context length | Top 3 conversation records | Focus on the current project's bidding needs, avoiding redundant historical records affecting retrieval accuracy |
| Node timeout threshold | 600 seconds | Mold data retrieval requires loading CAD models and simulation files, which takes a long time; calibrated based on actual testing |

## Three common errors
- Symptom: Workflow does not trigger branches as expected, and node execution stalls. Cause: `variables` are not bound to project-specific parameters, causing downstream nodes to fail to obtain valid trigger conditions.
- Symptom: Knowledge base retrieval returns documents of non-target categories, and the number of results does not match expectations. Cause: Knowledge base retrieval tag filtering is not enabled, or tag configuration does not match document classification.
- Symptom: Workflow does not complete all nodes and no error prompt is displayed. Cause: The `nodeId` association configuration between nodes is incorrect, or upstream nodes do not output valid parameters, causing downstream trigger conditions to be unmet.

## How to confirm the configuration is correct
- View the `variables` configuration panel, confirm that exclusive parameters for the current project are bound, such as mold number and customer demand fields.
- Trigger a test workflow, submit a retrieval request containing mold design keywords, and verify that only documents with preset tags are returned.
- Simulate a scenario where upstream nodes do not output parameters, and confirm that the workflow will throw a prompt for missing parameters.
- View the conversation history record, confirm that only the preset number of context contents are loaded, and no irrelevant historical records are associated.
