# Bid Document and Quotation Preparation for Mold Design and Manufacturing: Deployment and Upgrade

## What data for this category looks like
This category of data primarily comes from client-provided product models, mold flow/forming simulation results, CAD/CAM output files, machining and measurement data, and documents including mold trial reports and mold modification notices. Data is updated per individual project, and is synchronized and refreshed after each mold trial or modification. Daily documents include mold design task sheets, DFM reports, part machining drawings, process cards, and mold trial records. Core fields include mold cavity parameters, material grades, machining tolerances, and mold trial defect records.

## What constraints these characteristics impose on deployment and upgrade
The multi-source professional files and project-based update rhythm of this category impose targeted constraints on the deployment and upgrade process. Large-volume CAD models and simulation files require compatible high-capacity storage configurations to avoid upload or parsing timeouts. In bidding scenarios with multiple parallel projects, database connections must support stable concurrency to prevent data synchronization conflicts. Document formats vary significantly across different projects, so parsing rules compatible with multiple types of professional files must be configured, and field expansion space must be reserved to accommodate new mold-specific parameters. During the upgrade process, take care not to interrupt data synchronization for ongoing bidding projects, to avoid impacting already submitted document and quotation preparation workflows.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30 connections` | Adapts to parallel bidding document parsing and query needs for multiple projects, preventing connection exhaustion |
| `MONGODB_URI` | Points to a dedicated business database instance | Isolates mold project bidding data from other business data to ensure data security |
| `REDIS_URL` | Configured as a highly available cache instance with a 300-second timeout | Caches frequently accessed mold trial reports and process card data to reduce database query pressure |
| `STORAGE_S3_ENDPOINT` | Object storage endpoint adapted for large file storage, supporting up to 2 GB attachment uploads | Hosts large-volume bidding attachments such as CAD models and simulation files |
| `FILE_TOKEN_KEY` | Generate independent access keys per project | Differentiates file access permissions for different bidding projects to prevent data leaks |
| `ROOT_KEY` | Only configured for dedicated operation and maintenance accounts | Ensures system configuration operation permissions are only available to authorized personnel |

## Three common errors
- Symptom: A Request Timeout prompt with status code 504 appears after uploading a CAD model. Cause: No storage endpoint adapted for large files is configured, leading to file upload timeout.
- Symptom: Core fields are empty after bidding document parsing, making quotation item generation impossible. Cause: No parsing rules for mold-specific documents are configured, so key parameters such as cavity count and material grades are not recognized.
- Symptom: Database connection exhaustion errors occur when multiple projects are submitted in parallel. Cause: The `DB_MAX_LINK` configuration value is too low, and does not accommodate the concurrent bidding project scenario.

## How to confirm the configuration is complete
Perform the following verification actions under FastGPT v4.17.0:
- Upload a single large-volume professional file, verify that the upload and parsing process has no errors, and confirm that the storage configuration aligns with business needs.
- Start parallel bidding document parsing tasks for multiple projects, check that the database connection count does not exceed the preset upper limit, and confirm that the concurrency configuration is active.
- Generate an independent file access key, verify that only authorized accounts can access the bidding documents of the corresponding project, and confirm that the permission configuration is correct.
- Attempt to modify core system configuration items, verify that only authorized accounts can perform the operation, and confirm that the permission control configuration is active.

The values provided are common starting points and should be measured against the reader's own samples.
