# Bid Document and Quotation Preparation for Rubber Compounding and Product Vulcanization: Workflow Orchestration

## What Data Looks Like for This Category
Data for this category comes from formula systems, raw material batch ledgers, internal mixers, Mooney viscometers and rheometers, vulcanizing machines, and laboratory testing equipment. Daily documents include formula sheets, weighing records, mixing curves, rubber quick-test reports, vulcanization process cards, mold usage records, and finished product performance test reports.
Data is updated in correspondence with each raw material batch, each batch of mixed rubber, and each vulcanized product per mold run. Document fields include material grades, weighing values, temperature curve parameters, vulcanization time and temperature, performance indicators, and more. Most units are weight units, temperature units, time units, and performance testing units.

## What Constraints Do These Characteristics Impose on Workflow Orchestration
High data update frequency and fine granularity require workflows to support real-time association with the latest batch data and process parameters, to avoid referencing expired records.
Multiple types of heterogeneous documents need unified extraction. This requires workflow nodes to support precise cross-document field matching—for example, extracting temperature ranges from mixing curves, or extracting shaping parameters from vulcanization process cards.
Inconsistent field units across different documents require unit conversion rules to be configured in the workflow, to prevent deviations caused by unit errors during quotation preparation.
Bid documents need to be associated with performance data for specific batches. This requires workflows to bind variables to corresponding document nodes, to ensure extracted content matches the bid project.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapt to the paragraph structure of documents such as mixing curves and process cards, avoid splitting critical parameters |
| Similarity Threshold | 0.75–0.85 | Precisely match specific fields in formula sheets and performance reports, filter irrelevant document fragments |
| Single Search Limit | Top 6 entries | Cover multiple associated documents from the same batch of mixing and vulcanization, meet bid data completeness requirements |
| `variables` | Bind batch number and project number | Associate all documents for the corresponding production batch, enable precise data retrieval |
| `nodeId` | Bind the unique identifier of the corresponding workflow node | Ensure correct workflow node call order and permission configuration |
| Timeout Setting | 300–600 seconds | Adapt to the response time of multi-document searches, avoid timeouts caused by large data volumes |

## Three Common Errors
- Phenomenon: Document fragments returned after workflow runs do not match the batch required for the bid project, and some fields are empty. Cause: `variables` are not bound to the corresponding batch number, resulting in calls to expired or unrelated production data.
- Phenomenon: When debugging workflows without logging in, custom configured parameters do not take effect, and target documents cannot be called normally. Cause: The non-logged-in link does not carry variable parameters. Verify by generating a debug link with variables or using a local test environment.
- Phenomenon: The number of results returned by the knowledge base search node does not match the set single search limit, or specified fields cannot be extracted. Cause: The reference template prompt does not clearly specify the field names to be extracted, resulting in chaotic content scraping by the AI.

## How to Confirm Proper Configuration
- Trigger the workflow, check if the extracted document fragments include the batch number corresponding to the current bid project, and verify that field units match business requirements.
- Generate a debug link carrying test custom variables, verify that `variables` are passed normally and associated with the corresponding documents.
- Run the workflow and check the number of returned results, confirm that it matches the single search limit setting, with no redundant or missing document fragments.
- View the node run logs, confirm that the authentication configuration has taken effect, with no access permission error messages.
