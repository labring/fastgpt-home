# Bid Document and Quotation Preparation for Rubber Mixing and Product Vulcanization: Tool Calling and Plugins

## What this category of data looks like
Data for this category primarily comes from formula management systems, raw material batch ledgers, internal mixer operation logs, Mooney viscosity and rheometer test records, vulcanizer process parameter libraries, and laboratory finished product performance reports. Data is generated synchronously for each raw material batch, each mixed rubber batch, and each vulcanized product mold run. Standard documents include formula sheets (with compound ratio and feeding sequence), weighing records (with feeding weight), mixing curves (with temperature and torque changes), and vulcanization process cards (with temperature and time parameters). Most fields include clear units, such as internal mixer temperature (℃) and vulcanization duration (minutes).

## What constraints these characteristics impose on tool calling and plugin workflows
The high-frequency fine-grained updates and multi-device traceability of this category’s data require that tool calls must associate original production data for the corresponding batch. This prevents quotation errors caused by mixing cross-batch data. The structural differences across multiple document types require plugins to support parsing files of varying formats, including formula sheets and mixing curves. A single chunking rule cannot be universally applied. The update rhythm based on vehicle load, batch, and mold run requires that tool calls must carry clear batch identifiers as context parameters. This ensures that material usage and process parameters in bid quotations match the actual data of the corresponding batch. Additionally, the inclusion of units in data fields requires plugins to retain unit information when extracting parameters. This avoids unit mismatch issues during quotation calculations.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | Adapts to parsing needs for multiple document types, automatically selects appropriate tool calling logic |
| Workflow/API function-call configuration | `enabled` | Supports structured extraction of fields with units such as formulas and process parameters |
| Upload file size limit | `500–2000 MB` | Matches upload requirements for large-format documents including mixing curves and vulcanization process cards |
| Tool call timeout | `300–600 seconds` | Adapts to processing durations for multi-file parsing and batch data association |
| Batch call upper limit | `First 10 batch records` | Controls the data source scope for a single call, avoiding context overload |
| Variable reference toggle | Enabled | Supports passing context parameters such as batch numbers during tool calls |

## Three Common Mistakes
- An error "File exceeds maximum allowed size" occurs when calling the local `MinerU` plugin, and mixing curve documents cannot be uploaded. This is caused by failing to modify the default 2 MB upload limit of the container, and failing to adapt to the upload requirements for large-format process documents of this category.
- Custom workflow tool calls cannot reference batch number variables, and only fixed-link files can be uploaded. This is caused by failing to enable the tool's variable injection configuration, and failing to bind batch identifiers as context parameters.
- Bid document attachments cannot load properly after plugin calls, and logs show that the storage path does not exist. This is caused by failing to correctly configure MinIO access permissions and storage buckets, and failing to complete basic connectivity verification.

## How to Verify Correct Configuration
- Upload a typical mixing curve PDF document, check that the tool call can normally parse and extract parameters with units such as temperature and torque.
- Insert a batch number variable into a custom workflow, initiate a tool call, check that the corresponding batch's formula data can be correctly associated.
- Upload a test vulcanization process card file to the MinIO storage bucket, read the file via a plugin call, check that the file content can be returned normally.
- View the plugin logs for FastGPT v4.17.0, confirm that the `toolChoice` and `functionCall` parameters have taken effect as configured, with no error messages.

The values provided are common starting points and should be measured against the reader's own samples.
