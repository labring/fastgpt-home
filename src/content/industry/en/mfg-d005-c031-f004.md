# Tender Document and Quotation Preparation for Cement Clinker and Grinding: Workflow Orchestration

## What the data for this category looks like
Data sources for this category include online composition analysis devices, DCS systems, laboratory testing equipment, kiln and grinding operation equipment, raw and fuel management ledgers, and energy metering devices. Data update frequencies are divided into three categories: real-time, shift-based, and daily. Daily documents include raw material batching plans, kiln operation records, clinker test reports, quality control notices, equipment inspection logs, and energy consumption reports. Document fields are set around core production parameters, with no additional custom content.

## What constraints these characteristics impose on workflow orchestration
Data sources for this category are scattered, and update frequencies vary widely. Real-time operation data must be pulled via triggers. Scheduled data must be synchronized by shift or daily. Workflows must adapt to trigger rules for multiple data sources. Daily document structures are diverse. Differentiated parsing rules must be configured for different document types such as batching plans and test reports. Core business links rely on real-time parameters and historical quality inspection data. Workflows must link corresponding data nodes to automatically call associated documents. Verification links must also be configured to avoid risks caused by quality indicator deviations.

## Three common mistakes
- Symptom: Knowledge base search returns empty results, with no matching documents. Cause: Dynamic incoming parameters for knowledgeSearch were not correctly configured in `variables`, causing the search to fail to associate raw and fuel ledger or test report data for the current project.
- Symptom: No Word download link is generated after the workflow runs. Cause: The built-in document conversion and export node was not added, or the export format was not configured as docx.
- Symptom: Workflow nodes fail to run normally after migration. Cause: The data source and variable configuration corresponding to the original `nodeId` were not rebound, causing node parameters to become invalid in the new environment.

## How to verify a successful configuration
- Manually trigger the workflow, check whether the knowledgeSearch parameter in `variables` correctly passes the business ID of the current project.
- After running the workflow, view the knowledge base search results, confirm that the returned documents include core category documents such as raw material batching plans and test reports.
- Verify that the document export node generates a downloadable docx file, check that the file content covers business data required for tender documents.
- View the workflow logs, confirm that the trigger node executes according to preset rules, and failed tasks are retried as configured.
