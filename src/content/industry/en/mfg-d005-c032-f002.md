# Bid Document and Quotation Preparation for Complete Vehicle General Assembly: Vector Models and Indexes

## What the Data for This Category Looks Like
Typical entities are passenger vehicle, commercial vehicle, and new energy vehicle complete vehicle manufacturers. Daily documents include production orders, VIN lists, assembly work instructions, tightening data, offline inspection reports, rework records, and conformity and release documents. Data sources cover ERP/MES systems, VIN and configuration systems, supplier batch ledgers, tightening tools, EOL inspection lines, and quality traceability systems. Data updates occur per vehicle, in real time, or per shift. Data uses VIN as the single vehicle mainline, includes numerous associated configuration items, part information, torque parameters, and inspection results, with most fields bound to unique vehicle identifiers and station nodes.

## What Constraints Do These Characteristics Impose on the Vector Model and Index Link
VIN-centric single vehicle mainline data requires indexes to support rapid recall of datasets associated with a specific VIN, avoiding redundant calculations from cross-document retrieval. High-update-frequency real-time data needs incremental index synchronization mechanisms to ensure the data sources used for bid document and quotation preparation remain up to date. Documents include structured torque parameters, semi-structured inspection reports, and long-text work instructions. Vector chunking must balance semantic completeness and field association to prevent loss of critical associated information after chunking. The bidding process must match hundreds of configuration and part items, so vector recall must cover multi-dimensional business associations, ensuring retrieval results align with vehicle-specific configuration logic and avoid risks such as mismatched or missing parts.

## How to Configure the System
This configuration is based on FastGPT v4.17.0. Specific configuration items and their basis are as follows:

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Chunk Length | 800–1200 characters | Ensures semantic completeness for long texts such as assembly work instructions and VIN lists, avoiding breakage of associated part numbers and VIN identifiers within a single chunk |
| Overlap Length | 100–200 characters | Retains critical identifiers such as VIN and part numbers across chunks, preventing loss of cross-document associated context |
| Similarity Threshold | 0.72–0.85 | Meets the strong association requirement for configuration items and part information, filters low-correlation recall results, and adapts to the accuracy needs of bid quotations |
| Single Search Limit | Top 20 results | Covers the retrieval needs of hundreds of configuration items for a single vehicle, avoiding context overflow caused by excessive recall results |
| `maxToken` | Set to the selected embedding model/service maximum supported input tokens | `maxToken` is the input-token maximum supported by the selected embedding model/service; verify it in that provider configuration. See the [v4.17.2 model-field reference](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx). It is not retrieval/LLM context or a FastGPT-wide fixed cap. |
| Query Optimization | Calibrated based on actual testing | Adjusts the association weight of retrieval terms for specific VIN-associated retrieval scenarios, adapting to business-specific recall logic |

## Three Common Misconfigurations
- Symptom: The number of retrieval results is far lower than expected, and the interface shows a recall count of 0. Cause: No dedicated index configuration for the VIN field was performed, resulting in failure to associate the corresponding assembly work instructions and part lists.
- Symptom: Timeout errors occur after deployment, with logs returning a 504 status code. Cause: The upper limit of the `defaultToken` value was not adjusted based on hardware configuration, and the number of single search return results was not restricted, resulting in exhaustion of vector computing resources.
- Symptom: Exception entries with empty fields appear after the knowledge base is imported. Cause: Invalid fields in unstructured raw tightening data were not filtered, resulting in the vector model being unable to generate valid embeddings and causing null values.

## How to Verify Successful Configuration
- Import assembly documents corresponding to a single VIN, perform a retrieval action, and check whether the recall results include the part list and torque parameters associated with that VIN.
- Adjust the similarity threshold, compare changes in the relevance of retrieval results, and confirm that the threshold matches the business accuracy requirements.
- Import batch-updated rework record data, check the index synchronization status, and confirm that the real-time update configuration takes effect.
- Test the recall effect of long-text chunks, confirm that cross-chunk VIN identifiers are fully retained, and no semantic breakage occurs.

The values provided here are common starting points and should be evaluated against the reader's own samples.
