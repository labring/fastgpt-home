# Bid Document and Quotation Preparation for Complete Vehicle Final Assembly: Multi-turn Dialogue and Prompt Engineering
This document is based on the functional configuration instructions for FastGPT v4.17.0.

## What the data for this category looks like
Data primarily comes from ERP, MES systems, VIN and vehicle configuration systems, supplier batch ledgers, tightening tool collection data, EOL offline inspection lines, and quality traceability systems.
Daily documents include single-vehicle VIN lists, assembly work instructions, tightening torque records, offline inspection reports, rework records, and consistency release documents.
Data is generated in real time per single vehicle, with summary updates per work shift.
Fields include unique VIN codes, configuration item lists, torque parameters, inspection results, and more. Units include newton meters, batch numbers, inspection qualification identifiers, and more.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Mixed-model production using VIN as the unique identifier requires multi-turn dialogue to accurately match single-vehicle configuration parameters. Prompts must bind to VIN context to avoid confusion.
Real-time updated tightening and inspection data requires the dialogue link to retrieve the latest batch of compliant parameters. This ensures bid quotations align with actual production standards.
Multiple data sources mean prompts must specify data call priority: prioritize real-time data from MES and EOL inspection lines, then reference supplier batch ledger data.
The large number of configuration items per single vehicle requires limiting dialogue context scope. This prevents redundant information from interfering with bid document compliance and quotation accuracy.

## How to configure the settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind the 16-17 digit VIN code as the unique identifier | Ensure dialogue context binds to single-vehicle data, avoiding cross-vehicle configuration confusion |
| `messages` | Retain the most recent 15-20 rounds of dialogue context, truncate earlier rounds | Balance context completeness and model inference efficiency, adapting to multi-turn bid confirmation scenarios |
| `variables` | Predefine tightening torque thresholds (100-300 N·m), set VIN matching rules as global variables | Quickly access standardized complete vehicle final assembly parameters, reducing repeated entry |
| Single search limit | Call the top 6 recalled results | Cover common configuration items, avoiding redundant information disrupting bid document preparation |
| Maximum context length | Set to 8000-12000 characters | Match the full length of configuration documents for a single vehicle, ensuring the model accesses complete reference data |
| Question optimization | Enable automatic optimization, adjust expression accuracy based on actual measurement calibration | Improve bid document rigor, reducing model generation deviations |

## Three common mistakes
- Phenomenon: After configuring a stream reply trigger comment, the comment only takes effect after the full reply completes. Cause: The dialogue flow trigger timing was not correctly bound. The comment logic was attached to the full reply node, and does not adapt to single-turn interaction trigger rules.
- Phenomenon: After migrating the knowledge base, the dialogue link shows the knowledge base is empty, but all content is visible on the page. Cause: The dialogue link's knowledge base association configuration was not updated. It still points to the old knowledge base path, and the migrated resource mapping relationship was not synchronized.
- Phenomenon: After uploading an XLSX format assembly parameter file, the dialogue cannot access the file content. Cause: Text extraction adaptation for XLSX files was not enabled, or the file contains non-standardized field formats. This prevents the model from identifying valid content.

## How to confirm the configuration is complete
- Initiate a test dialogue bound to a specified VIN code. Verify the `chatId` parameter correctly binds to the specified VIN, and the dialogue context only associates configuration data for that VIN.
- Upload a test XLSX assembly parameter file. Initiate a dialogue to call the file content, and verify field information is extracted correctly.
- After migrating the knowledge base, re-associate the dialogue link's knowledge base configuration. Initiate a test query, and verify knowledge base content is retrieved normally.
- Configure the stream reply trigger logic. Initiate a multi-turn dialogue, and verify comments take effect as expected after each round of replies.

The values provided here are common starting points, and should be validated against the reader's own samples.
