# Tender Document and Quotation Preparation for Complete Vehicle Final Assembly: Workflow Orchestration

## What the data for this category looks like
The data for this category primarily comes from ERP/MES systems, VIN and vehicle configuration systems, supplier batch management systems, tightening tool terminals, EOL inspection lines, and quality traceability systems. Data is generated in real time per vehicle and archived in shifts. Daily documents include production orders, VIN lists, assembly work instructions, tightening torque data, offline inspection reports, rework records, and consistency and release documents. Core fields include the 17-digit standard VIN code, tightening torque (unit: newton meters), supplier batch numbers, and inspection item qualification status. The data volume per vehicle fluctuates with configuration complexity.

## What constraints do these characteristics impose on workflow orchestration
The data characteristics of this category impose multiple constraints on workflow orchestration. First, dynamic data generated in real time per vehicle requires workflows to support `variables` dynamic injection, and fixed parameter templates cannot be used. Second, multi-source heterogeneous data from different terminal systems must be pulled and verified in business order to avoid resource conflicts caused by parallel calls. Third, fluctuations in data volume caused by differences in vehicle configuration complexity require that workflow node processing durations can be calibrated based on actual measurements, to avoid abnormal interruptions caused by fixed timeout thresholds. Finally, branch logic must be triggered by VIN to match part lists and quotation items corresponding to hundreds of vehicle configurations.

## How to configure the workflow
The following configurations are based on FastGPT v4.17.0.
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Workflow trigger method | Trigger by VIN code | Aligns with the category's VIN-centric business logic, ensuring each call corresponds to exclusive data for a single vehicle |
| `variables` configuration | Dynamically inject VIN, torque thresholds, supplier batches | Supports real-time calls of exclusive data per vehicle, adapting to the business rhythm of updates per vehicle |
| Node timeout settings | Calibrated based on actual measurements, range 120–300 seconds | Adapts to fluctuations in per-vehicle data volume, avoiding abnormal interruptions caused by fixed timeouts |
| Branch logic trigger | Match nodes by configuration type | Covers branch processing for hundreds of vehicle configurations, meeting the part list matching requirements for tender quotations |
| External interface call limits | Call up to 5 associated data entries per request | Controls interface request load, adapting to concurrent call constraints of multi-source systems |
| `nodeId` configuration | Bind unique identifiers for each data pull node | Ensures correct workflow node call order, avoiding conflicts when pulling multi-source data |

## Three common configuration errors
- Symptom: Timeouts or no return results occur when the workflow calls external interfaces. Cause: Multi-source data is not pulled in business order, and parallel calls exhaust system resources, triggering node timeouts.
- Symptom: The workflow runs normally but the generated quotation items do not match the actual configuration. Cause: `variables` are not correctly configured to inject exclusive parameters for a single vehicle, making it impossible to match the configuration data of the corresponding vehicle.
- Symptom: The workflow branch logic fails to trigger the corresponding configuration node. Cause: The trigger identifier uses fixed parameters instead of VIN code, making it impossible to adapt to dynamic configuration requirements for mixed-line production.

## How to verify a correct configuration
- Manually enter the VIN code of a single vehicle, trigger the workflow, and check if the part list and quotation items for the corresponding configuration are pulled.
- Simulate calls to the workflow for multiple vehicles with different configurations, verify that the branch logic triggers correctly.
- View the workflow running logs, confirm that `variables` parameters are correctly injected, with no null values or incorrect fields.
- Adjust the data volume of a single vehicle, verify that the node timeout settings are adapted, with no abnormal interruptions.

The values provided here are common starting points and should be evaluated against the reader's own samples.
