# Bid Document and Quotation Preparation for High-volume Automotive Parts Manufacturing: Vector Models and Indexes

## What Data for This Category Looks Like
This category’s data originates from customer drawings, special characteristic lists, ERP/MES systems, measurement and inspection tool data, equipment process parameters, and supplier quality certificates. Daily documents include control plans, process flowcharts, work instructions, first article and patrol inspection records, SPC reports, PPAP materials, and 8D reports. Data is collected and updated per batch, per shift, or continuously. Individual documents include fields such as version number, process identifier, characteristic parameters, and batch number. Some parameters include tolerance ranges and units of measurement.

## Constraints Imposed on Vector Models and Indexing
The data characteristics of this category create multiple constraints for the vector model and indexing workflow. Data is updated continuously per batch and shift, so incremental index updates must be supported to avoid the time cost of full index reconstruction. Document types range from structured reports to unstructured process files, so text splitting logic must adapt to different formats. Some documents include characteristic parameters with tolerances and units of measurement. Vector encoding must retain the link between parameters and units to prevent semantic loss. Bid and quotation preparation requires linking compliance materials from historical batches. Indexes must support precise recall by batch and process dimensions, while meeting the quality system constraint requirements of vehicle customers.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the document length of this category with tolerance parameters, avoids splitting that breaks the semantic integrity of characteristic parameters |
| Overlap Length | 100–150 characters | Retains cross-chunk process and batch information, prevents key associated content from being split and truncated |
| Similarity Threshold | Calibrated based on actual measurements | Must match the recall accuracy requirements for compliance documents in this category, avoids incorrectly recalling materials from unrelated batches |
| Single Search Limit | Top 10 results | Balances information completeness and retrieval efficiency during bid document preparation |
| `defaultToken` | 4096 token | Adapts to the upper limit of vector encoding for long documents such as PPAP materials and 8D reports |
| `maxToken` | Set to the selected embedding model/service maximum supported input tokens | `maxToken` is the input-token maximum supported by the selected embedding model/service; verify it in that provider configuration. See the [v4.17.2 model-field reference](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx). It is not retrieval/LLM context or a FastGPT-wide fixed cap. |

## Three Common Configuration Errors
- The exported dataset.csv from the knowledge base only includes the index field, and no content field. This occurs when the post-splitting text extraction rule is not configured correctly, resulting in the vector index not being linked to the original document content.
- Vector search results do not return characteristic parameters with tolerances. This occurs when no special processing is applied to structured fields with units, causing vector encoding to lose the association between parameters and units.
- Incremental index updates trigger timeout errors. This occurs when the incremental update strategy is not configured, and each update triggers a full index reconstruction, exceeding the time limits imposed by the high-frequency update rhythm of this category's data.

## How to Verify Correct Configuration
- Upload a typical PPAP material, and verify whether characteristic parameters and batch information can be correctly extracted following vector index generation in the FastGPT v4.17.0 environment.
- Perform an incremental index update, and confirm that only documents from new batches are processed, with no system logs indicating full reconstruction.
- Initiate a search for a specific process, and verify that the recall results include control plans and patrol inspection records for that process.
- Splice the search results and bid document template, and confirm that the total context length does not exceed the configured `maxToken` limit.

The values provided above are common starting points, and should be evaluated against the reader’s own samples.
