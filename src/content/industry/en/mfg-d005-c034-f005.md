# Bid Document and Quotation Preparation for Baked Goods and Convenience Foods: Tool Calling and Plugins

## What This Category’s Data Looks Like
This category’s data is sourced from daily production and compliance documents of bakeries, cookie, instant noodle, and frozen pastry factories. It includes formulas and feeding lists, production records, baking/steaming curves, metal detection records, cleaning and disinfection records, and factory inspection reports.
Data sources cover raw and auxiliary material qualification certificates, ERP/MES systems, weighing equipment, ovens/frying lines, laboratory testing systems, and food traceability ledgers.
Data updates follow production batches, shifts, or daily schedules.
Core fields include allergen material lists, production parameters, test results, and shelf life information.

## Constraints on Tool Calling and Plugins
This category’s data updates by production batch, shift, or daily. Tool calling must bind to real-time data sources to pull the latest batch data related to formulas, inspections, and quotations.
The allergen material list is a core verification field. Tool calling must accurately match the corresponding fields to avoid missing compliance information.
Baking/frying timing curve data in production records requires plugins to support reading segmented timing data fragments.
Multi-document verification requires pulling multiple data types at once, such as ERP quotation data and laboratory test reports. Tool calling must support parallel pulling of content from different data sources.

## Three Common Configuration Mistakes
- A 429 status code is returned during a call. The symptom is an interface error reporting too many requests. The cause is that parallel call count exceeds the configured limit.
- Embedded links in streaming output only work on the current page and cannot jump. The symptom is no new page opening when clicking the link. The cause is that the new window trigger rule for the link is not configured.
- Some areas fail to complete API calls. The symptom is a connection timeout error during the call. The cause is that applicable network access rules are not configured.

## How to Verify Successful Configuration
- Trigger a bid document generation workflow, and check if the data pulled by tool calling matches the production records of the current bidding batch.
- Review the tool call log to confirm that the `toolChoice` and `functionCall` parameters follow the preset rules.
- Test embedded links in streaming output to confirm jump behavior meets business requirements.
- Cross-check the allergen information returned by the tool to confirm it matches records in the data source.
