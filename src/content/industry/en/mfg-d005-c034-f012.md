# Bid Document and Quotation Preparation for Baking and Convenience Food: Deployment and Upgrade

## What data for this category looks like
This category includes typical entities such as bakeries, cookie factories, instant noodle factories, and frozen pastry factories. Daily documents cover formulas and feeding lists, production records, baking or steaming curves, metal detection records, cleaning and disinfection records, and factory inspection reports. Data sources include raw and auxiliary material qualification certificates, ERP/MES systems, weighing systems, oven or frying line equipment, laboratory test data, and food traceability ledgers. Data updates occur per batch, per shift, or daily. The most time-consuming steps focus on reviewing formulas and allergen materials, controlling production windows, verifying foreign matter control, and packaging date and shelf life information.

## What constraints these characteristics impose on deployment and upgrade
Data sources for this category are scattered. They involve multiple carriers such as equipment, systems, and paper documents. Adaptation rules for multi-data source docking must be configured during deployment. Data update frequency is high and changes with production batches. Stability of synchronization processes must be ensured during upgrades. This avoids affecting bid document accuracy due to data lag. The frequent switching of allergens and cleaning requirements requires strengthening knowledge base field matching accuracy during deployment. It also requires configuring a data verification mechanism. Large-volume documents such as baking curves and test records need dedicated storage configuration. This prevents impact on system response speed. Bid documents involve multi-batch data aggregation. Data aggregation efficiency must be optimized during deployment. This ensures generation efficiency aligns with business rhythms.

## How to set configurations
The following configurations are based on FastGPT v4.17.0:

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://fastgpt:pass@db-host:27017/fastgpt?authSource=admin` | Connect structured production data from ERP and MES systems. Meet multi-batch data storage requirements |
| `REDIS_URL` | `redis://:redis-pass@redis-host:6379/0` | Cache frequently queried formula and allergen data. Ensure query response speed |
| `FE_DOMAIN` | `https://your-domain.com/fastgpt` | Configure access context path for private deployments. Comply with business access specifications |
| `DB_MAX_LINK` | `20–30 connections` | Adapt to high-frequency data write requests from equipment such as ovens and weighing systems. Avoid connection pool exhaustion |
| `ROOT_KEY` | Calibrated based on actual testing | Set administrator permission key for local deployments. Ensure system access security |
| `STORAGE_S3_ENDPOINT` | `http://minio-host:9000` | Store large-volume documents such as baking curves and metal detection records. Meet large-capacity storage requirements |

## Three common errors
- Issue: After modifying `ROOT_KEY`, administrator login still prompts insufficient permissions. The system configuration page cannot be accessed. Cause: Only the parameter value in the configuration file was modified. The container was not restarted or environment variables were not reloaded. The new configuration did not take effect.
- Issue: After Docker deployment, accessing the specified address shows a loading spinner followed by a failure. The page cannot load. Cause: `MONGODB_URI` or `REDIS_URL` was not configured correctly. The service failed to connect to the database or cache component. Startup failed.
- Issue: Allergen material information in generated bid documents is incorrect. It does not match the actual production batch. Cause: Cleaning and disinfection records and material data in the knowledge base were not updated per production batch. Old data was reused.

## How to confirm proper configuration
Run environment variable check commands. Confirm all configuration items have been correctly loaded into the running environment.
Initiate a test bid document generation request. Verify returned results include correct field information such as formulas and production records.
Test administrator permission modification operations. Confirm the `ROOT_KEY` configuration is effective. System parameters can be modified normally.
Check data synchronization logs. Confirm multi-data source update frequency complies with per-batch, per-shift, or daily update requirements.

The values provided are common starting points. They should be evaluated against local samples.
