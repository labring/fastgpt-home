# Heat Treatment Tender Document and Quotation Preparation: HTTP Interfaces and External Systems

## What the data for this use case looks like
Heat treatment scenario business data originates from material grade archives, customer technical requirement documents, temperature control instruments, furnace temperature uniformity testing equipment, hardness testers, metallographic testing equipment, and workshop MES systems.
Data updates once per furnace run or production batch.
Included documents cover heat treatment process cards, furnace loading layouts, real-time furnace temperature curves, hardness and metallographic inspection reports, equipment inspection records, and exception handling sheets.
Core fields include material grade, heating and holding temperature, holding duration, cooling method, furnace number, batch number, and hardness test values.
Units include industry standard units such as degrees Celsius, hours, and HRC hardness values.

## Constraints on HTTP Interfaces and External Systems
Data in this scenario updates per furnace run or batch, and includes multiple document types and standardized fields.
This requires HTTP interfaces to support precise real-time data retrieval by furnace number or batch number.
Multiple data sources require interfaces to adapt to connections with external systems such as MES and testing equipment. Support for multi-field mapping and format conversion is needed.
Image data in documents such as furnace loading layouts and furnace temperature curves requires interfaces to support binary or multi-format content transmission, to avoid data loss.
Tender document generation requires batch association of multiple furnace run data. Interfaces must support batch requests or paginated retrieval, to adapt to high-frequency business call rhythms.

## Configuration Settings
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {API_KEY}` | Complies with general HTTP interface authentication specifications, and adapts to the interface authentication requirements of the FastGPT platform |
| `variables` | `{"batch_no": "", "furnace_no": "", "hardness_hrc": ""}` | Matches the core batch, furnace number, and hardness fields required for heat treatment tenders, and aligns with business data structures |
| Request timeout | `300–600 seconds` | Covers the reasonable processing time for single furnace run data retrieval and multi-source data aggregation, preventing request interruptions from short timeouts |
| `responseData` | Standardized JSON format | Enables direct parsing of core fields by tender document generation tools, reducing additional code conversion costs |
| Context binding rule | Associate historical process data by furnace number | Ensures generated tender documents accurately match the heat treatment data for the corresponding batch |

## Three Common Misconfigurations
-  When calling the interface, a 401 unauthorized error is returned. The console displays "Invalid Authentication". The cause is that the `Authorization` parameter uses the original API key instead of the standard `Bearer {API_KEY}` format.
-  Raw heat treatment data queried via the DB node cannot be used directly for document generation. The returned `responseData` is not mapped to the standardized fields required for tenders. Additional code is needed to parse the original log format.
-  Calling the interface after using a loop node to concatenate multiple furnace run data results in a timeout. The request does not respond or returns a 504 error. The cause is that a reasonable timeout period is not configured, and batch furnace run data is not paginated, exceeding the capacity limit of a single interface request.

## How to Confirm Correct Configuration
-  Call the authentication interface, pass the configured `Authorization` parameter, confirm that a 200 status code is returned and no authentication-related errors occur.
-  Pass a valid test furnace number, check if the fields returned in `responseData` include core content required for tenders such as material grade, heating temperature, and hardness values.
-  Send a batch furnace run data request, confirm that the interface returns complete `variables` mapping results within the set timeout period, with no missing fields.
-  Connect to an external document generation tool, verify that the passed `responseData` and `variables` parameters can correctly generate tender document fragments containing heat treatment data.

The values provided are common starting points and should be measured against the reader's own samples.
