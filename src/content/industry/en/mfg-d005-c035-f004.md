# Bid Document and Quotation Preparation for Heat Treatment: Workflow Orchestration

## What this category of data looks like
This category of data comes from material grade databases, customer technical requirement documents, workshop temperature control instruments, furnace temperature uniformity test reports, hardness tester and metallographic equipment outputs, and workshop MES systems. Data updates occur per furnace charge and per batch. Daily documents include heat treatment process cards, charging layout diagrams, real-time furnace temperature curves, hardness and metallographic test reports, equipment inspection forms, and exception handling sheets. Data fields include material grades, heating, holding and cooling parameters, charging positions, furnace temperature curve node data, hardness values, and metallographic structure grades. Units include degrees Celsius, Pascals, millimeters, Rockwell hardness values, and other relevant units.

## What constraints these characteristics impose on workflow orchestration
The high-frequency update requirement for each furnace charge means workflows must support real-time access to workshop real-time data, and avoid using offline cached expired parameters. Multiple types of heterogeneous documents (process cards, curves, reports) mean workflows need multiple nodes to adapt to parsing and extraction of different formats. A single chunking rule cannot cover all use cases. Strongly associated fields such as charging positions and furnace temperature curves require cross-node verification in workflows, to prevent mixing data from different furnace charges during bid quotation preparation. The association requirement for exception handling sheets means workflows must include a traceability link for exception records. This ensures quotation process parameters match actual production records.

The following configurations are based on FastGPT v4.17.0.

## How to set the configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Variable Configuration | Create `variables` per furnace charge batch, including material grades, heating and holding parameters, and hardness test values | Adapt to per-furnace-charge data updates, ensuring real-time parameter association |
| File Upload Node | Support uploading three file types: process cards, charging diagrams, and furnace temperature curves | Cover all daily document types for this category |
| Node Flow Verification | Configure `nodeId` associated verification rules to match uploaded files with the current furnace charge's `variables` | Prevent mixing data across different furnace charges |
| Timeout Threshold | 600 seconds | Match the actual time required for multi-type document parsing and cross-node verification |
| Content Chunking Rule | Set based on actual measurement | Adapt to varying structures of heterogeneous documents, avoiding failure of a single chunking rule |
| Output Template | Fixed to three columns: process description, quotation details, and risk reminders | Align with standard format specifications for bid documents |

## Three Common Mistakes
- An error occurs when calling the document parsing tool after enabling the file upload node in a workflow. The cause is failure to adapt to heterogeneous heat treatment document formats, and failure to configure parsing adaptation rules for multiple file types.
- The quotation data field output by a workflow node is empty. The cause is failure to bind `variables` to the workshop MES system's real-time data interface, and failure to update parameters per furnace charge batch.
- An AI model is configured, but the workflow cannot call the corresponding capability. The cause is failure to associate the model configuration corresponding to `nodeId` in the workflow node, and only checking the model in global settings.

## How to confirm the configuration is correct
- Upload a heat treatment process card and furnace temperature curve file, verify that the node can parse and extract material grades and heating temperature parameters normally.
- Manually input a set of furnace charge data into `variables`, trigger cross-node verification, and confirm that the system identifies field mismatches.
- Run the complete workflow, check that the output bid document includes process description, quotation details, and risk reminders.
- Simulate a long-duration parsing task, test the timeout threshold setting, and confirm that the workflow does not trigger unexpected interruptions.
