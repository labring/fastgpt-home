# Heat Treatment Bid Document and Quotation Preparation: Tool Calling and Plugins

## What the data for this category looks like
This category of data originates from production and quality control processes at professional heat treatment facilities, as well as heat treatment workshops in automobile and bearing component factories. Daily documents include heat treatment process cards, furnace loading diagrams, furnace temperature curves, hardness and metallographic reports, equipment inspection forms, and exception handling records. Data is collected from material grade libraries, customer technical requirements, temperature control instruments, furnace temperature uniformity test results, hardness tester and metallographic equipment detection data, and MES systems, with real-time updates per furnace charge and batch. Each document includes clear fields such as process parameters, measured values, and equipment status, with units including temperature (℃), hardness (HV/HRC), time (hours/minutes), and other standard units.

## What constraints these characteristics impose on the "tool calling and plugins" link
Data for this category is updated in real time per furnace charge and batch, and sourced from multiple scattered locations. This requires tool calling to bind to real-time data interfaces, to avoid use of expired process parameters or test results. Multiple document types require cross-verification, so plugins must support simultaneous retrieval of multi-source data such as process cards, furnace loading diagrams, and furnace temperature curves. Fields have diverse units, so plugins must automatically adapt parameter verification logic. Bid quotations must combine per-furnace costs and batch coefficients, so tool calling must link to MES system equipment utilization rate data, to ensure quotation parameters match actual production capacity.

## How to set up configurations
These configurations are adjusted based on FastGPT v4.17.0.
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Workflow/API tool selection | `auto` | Adapts to retrieval needs for multi-source production data, automatically selects appropriate tool calling logic |
| Maximum number of single tool calls | Top 3 entries | Per-furnace production data volume is limited, excessive search results increase context redundancy |
| Tool call timeout threshold | 120 seconds | Must wait for data returns from temperature control instruments, hardness testers, and other equipment; overly long timeouts reduce bid efficiency |
| Workflow/API function-call configuration | `enabled` | Forces structured tool calling to ensure uniform and standardized parameter formatting for bid documents |
| Tool call retry count | 2 attempts | Prevents process interruption from a single failed call, while avoiding excessive consumption of interface quotas |
| Knowledge base association scope | Only bound to heat treatment process and testing documentation library | Avoids introducing irrelevant knowledge base content that disrupts the accuracy of quotation preparation |

## Three common mistakes
- Phenomenon: The tool call button has no response after being clicked, and no error prompt appears on the interface. Cause: The `toolChoice` parameter is not correctly configured as `auto` or `enabled`, causing the system to fail to recognize the tool call trigger logic.
- Phenomenon: Background logs show continuous tool call triggers during non-working hours, and interface quotas are rapidly consumed. Cause: No time limit is set for the plugin trigger timing, or the bound data source interface has no permission verification, causing external requests to bypass configuration and directly call the interface.
- Phenomenon: Non-heat treatment related knowledge base content is accidentally introduced when generating bid documents. Cause: The knowledge base association scope is not limited, causing the system to automatically retrieve all bound knowledge base resources.

## How to confirm the configuration is complete
- Submit a simulated bid quotation request, check the tool call log, and confirm that only content from the heat treatment process and testing documentation library is retrieved.
- Manually trigger tool calling, check whether the returned result format meets structured requirements, and whether parameter units match actual production data.
- Simulate a request initiated during non-working hours, confirm that tool calling is not triggered and interface quotas are not consumed.
- Test a single conversation flow, confirm that the tool prompt only appears once during the quotation parameter verification stage.

The values given are common starting points and should be measured against the reader's own samples.
