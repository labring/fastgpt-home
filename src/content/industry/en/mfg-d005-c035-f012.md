# Heat Treatment Bid Document and Quotation Preparation: Deployment and Upgrade

## What Data for This Category Looks Like
Data for this category comes from material grade libraries, customer technical requirements, temperature control instruments, furnace temperature uniformity testing equipment, hardness testers, metallographic equipment, and workshop MES systems. Update frequency is per furnace load or batch. Daily documents include heat treatment process cards, furnace loading diagrams, furnace temperature curves, hardness and metallographic reports, equipment inspection forms, and abnormal handling sheets. Fields cover process parameters, furnace temperature ranges, test values, equipment status, and abnormal records. Units include degrees Celsius, megapascals, millimeters, and others.

## Constraints Imposed by These Characteristics on Deployment and Upgrade
High-frequency data updates per furnace load require deployed synchronization links to have low latency. This prevents outdated process parameters from being used during bidding. Multiple types of heterogeneous documents require parsing rules adapted to different formats. This ensures accurate field extraction. Data sources are scattered across equipment and MES systems. During deployment, permissions and interfaces for multiple data sources must be connected. This avoids data silos. Bid documents need to be linked to accurate test data. During upgrades, verification logic for field mapping must be strengthened. This prevents parameter matching errors.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30` | Handle high-frequency data write and query requests per furnace load, avoid exhausting database connections |
| `REDIS_URL` | Cluster address with authentication | Cache frequently accessed document data such as furnace temperature curves and process cards, reduce database load |
| `STORAGE_S3_ENDPOINT` | Enterprise self-built object storage node address | Store large volumes of large documents such as furnace temperature curves and metallographic reports, ensure data security and access speed |
| `FILE_TOKEN_KEY` | Randomly generated 32-bit string | Encrypt document download links, prevent unauthorized access to sensitive process data used for bidding |
| `FE_DOMAIN` | Enterprise internal office domain name | Restrict front-end access scope, only allow internal engineers and bidding teams to use related functions |

## Three Common Configuration Mistakes
- Phenomenon: Document parsing API calls return 504 timeout. Cause: Parsing timeout settings are not adjusted for large PDF documents such as furnace temperature curves, leading to timeout during large file parsing.
- Phenomenon: Process parameter fields are empty in generated bid documents. Cause: Material grade and customer technical specification fields in the MES system are not mapped correctly, leading to failed data extraction.
- Phenomenon: Internal stored furnace temperature curve documents cannot be accessed after deployment. Cause: `STORAGE_S3_ENDPOINT` and access permissions are not configured correctly, leading to failed object storage interface calls.

## How to Confirm Configuration Is Complete
- Submit a simulated furnace temperature curve PDF and heat treatment process card. Use the FastGPT v4.17.0 test environment to check if extracted fields after parsing fully match document content.
- Initiate a simulated bid document generation request. Confirm that the returned result contains correct process parameters and test data.
- Check database connection logs. Confirm that the number of connections configured via `DB_MAX_LINK` is not exhausted.
- Attempt to access the front-end page from an unauthorized external domain. Confirm that access is properly blocked.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
