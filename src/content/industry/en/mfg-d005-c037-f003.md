# Tender Document and Quotation Preparation for Production Planning and Workshop Scheduling: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Daily documents for this category typically include sales orders, master production schedules, material requirement plans, weekly and daily production schedules, work orders, material shortage lists, and delivery change notices. Data is usually sourced from ERP orders and inventory, BOMs and process routes, equipment capacity, staff shifts, work in progress, and supplier deliveries. Updates occur daily, weekly, or are triggered by orders or abnormal events. Relevant fields include order numbers, material codes, process man-hours, equipment load rates, work in progress quantities, and more. There are no unified fixed units; values adjust based on the corresponding data type.

## What Constraints These Characteristics Impose on the Multi-turn Dialogue and Prompt Engineering Link
Multi-source and heterogeneous document types require dialogue contexts to support field inputs in different formats. For example, process numbers from work orders must be matched with material codes from BOMs. Irregular update triggers mean dialogue must support real-time calls to the latest data, and cannot rely on static caching. Fields without unified units require clear field mapping rules in prompt engineering to avoid unit confusion. Quotation preparation for tender scenarios must be linked to order and capacity data. Multi-turn dialogue must retain order numbers and scheduling parameters from previous interactions to ensure context continuity. When exceptions such as emergency order insertion or material shortages occur, dialogue must quickly link to the latest material shortage lists and equipment status data to adjust scheduling logic.

## Configuration Recommendations
These configurations are based on FastGPT v4.17.0

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | 8000–12000 preceding characters | Must cover core fields of multiple documents such as sales orders, BOMs, and production schedules to avoid truncation of critical data |
| Variable Binding | Bind global business datasets via `variables` | Directly call capacity and inventory data synced from ERP, no need for repeated input |
| Dialogue History Retention | Retain the most recent 20 interaction rounds via `messages` | Tender processes require repeated adjustments to scheduling parameters and quotation items; retaining historical dialogue ensures context continuity |
| Session ID Binding | Associate with the corresponding tender project via `chatId` | Distinguish scheduling data for different tender projects to avoid cross-project data confusion |
| Question Optimization Switch | Enabled | Converts vague scheduling requirements into executable field queries, adapting to terminology differences across departmental collaborations |

## Three Common Mistakes
- Symptom: When calling global variables in dialogue, only a small number of options are displayed, and the required capacity or inventory fields cannot be retrieved. Cause: The binding scope of `variables` was not configured correctly, resulting in only a portion of preset datasets being loaded.
- Symptom: After multiple rounds of dialogue, previously entered order numbers and process parameters are lost, making it impossible to continue scheduling adjustments. Cause: The `messages` history retention function was not enabled, or the maximum context length was set too low, leading to data truncation.
- Symptom: Submitted tender quotations do not match actual scheduling data, with unit confusion or field mismatches occurring. Cause: Field mapping rules were not clearly defined in prompt engineering, and field formats across documents were not unified.

## How to Verify Successful Configuration
- Test the dataset bound via `variables` to confirm that capacity and inventory data synced from ERP can be retrieved.
- Initiate multiple rounds of interaction, enter different scheduling parameters, and check whether `messages` retains historical dialogue content.
- Create sessions for two different tender projects, and verify that `chatId` is correctly bound, with no cross-project data confusion.
- Enter vague scheduling requirements, and confirm that the question optimization function can convert them into executable field queries.
