# Bid Document and Quotation Preparation for Production Planning and Shop Scheduling: Tool Calling and Plugins

This configuration is compatible with FastGPT v4.17.0.

## What Data Looks Like for This Category
Data for this category comes from enterprise ERP order and inventory systems, BOM lists, process route files, equipment capacity ledgers, staff shift schedules, work-in-progress ledgers, and supplier arrival records. Daily generated documents include sales orders, master production schedules, material requirements plans, weekly and daily scheduling tables, work orders, material shortage lists, and delivery change notices. Data update frequency is daily, weekly, or triggered when orders are created or exceptions occur. Document fields include order number, process working hours, equipment number, material code, planned delivery date, and others, with corresponding units such as hours, pieces, and shifts.

## What Constraints These Characteristics Impose on the "Tool Calling and Plugins" Link
Scattered and diverse data sources require tool calling to support connection to multiple data sources and adaptation to different document structures. Data updates have no fixed cycle, so tools must support on-demand data pulling to avoid outdated data caused by fixed polling. Document fields include specific units and business identifiers, so tool calling must verify that field formats and units match to prevent incorrect scheduling and quotation data. Bidding scenarios require accurate association of order and process data, so tool output must bind corresponding business identifiers to ensure traceable document content. Scheduling and quotations rely on real-time capacity and material status, so tool calling must prioritize pulling the latest equipment, inventory, and order data to ensure the accuracy of bidding content.

## How to Configure
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` or `required` | Adapt to tool calling requirements for different bidding scenarios. `auto` allows the model to independently determine whether to pull scheduling and quotation data. `required` forces tool calls to obtain real-time business data |
| `functionCall` | Enabled | Must explicitly specify tool calling function parameters to match the exclusive business interface for production planning and shop scheduling |
| Tool Call Timeout | 300–600 seconds | Scheduling calculations and multi-data source pulling involve multi-dimensional constraints and take a long time. Reserve sufficient time to prevent call interruptions |
| Plugin Data Source Validation | Enable field format and unit validation | Adapt to specific fields and units of documents in this category to avoid scheduling and quotation deviations caused by parsing errors |
| Number of Records Returned per Tool Call | Top 10 business records | Cover core data of main orders, work orders, and scheduling. Avoid redundant information interfering with document preparation |

## Three Common Mistakes
- Phenomenon: Abnormal tool calling judgment logic. Some scenarios generate documents directly without triggering tool calls. Cause: The `toolChoice` parameter is not configured correctly, and the exclusive business trigger conditions for production planning and shop scheduling are not bound.
- Phenomenon: Database connection plugin verification fails. The interface prompts workflow configuration exceptions. Cause: Data source connection parameters are not configured correctly, and the field format and access permissions of production planning and shop scheduling data are not matched.
- Phenomenon: Tool calling takes longer than expected, and generation delay is obvious. Cause: A reasonable timeout period is not set, or the batch processing logic of tool calls is not optimized for multi-dimensional scheduling calculations.

## How to Confirm Proper Configuration
- Trigger a simulated test scenario including production orders, equipment capacity, and material inventory. Check whether the model calls tools to pull corresponding business data.
- View tool calling logs to confirm that the returned data sources include core data types of this category, such as ERP orders, BOM lists, and equipment ledgers.
- Verify the field format and units of tool calling results to confirm that they match the business document specifications for production planning and shop scheduling.
- Simulate abnormal scenarios such as order insertion and material shortage. Check whether the tool triggers a re-pull of the latest data and updates content related to scheduling and quotations.
