# Bid Document and Quotation Preparation for Biologics and Aseptic Manufacturing: HTTP Interfaces and External Systems

## What data looks like for this category
Core data for this category comes from cell banks and seed lots, process analytics, cleanroom monitoring, MES, LIMS, and equipment integrity testing systems. Daily documents include cell bank or seed lot records, culture and purification records, aseptic filling records, environmental monitoring data, media fill simulation results, sterility test reports, and batch release documentation. Data update frequencies fall into three categories: per batch, real-time, and per monitoring plan. Active biological systems and aseptic manufacturing processes cannot guarantee quality solely through finished product sampling. Full process control and environmental monitoring data must be relied on to support quality assurance.

## What constraints do these characteristics impose on HTTP interfaces and external systems
Data sources for this category are scattered across multiple production and monitoring systems. HTTP interfaces must support cross-system data pulling to integrate business information from different sources. Data update frequencies include per batch, real-time, and per monitoring plan. Interfaces must support two trigger modes: on-demand calls and scheduled pulling, to meet the needs of different business scenarios. Document structures contain a large number of professionally compliant fields. Interfaces must match preset field formats to ensure returned data can be directly used for bid document and quotation preparation. Due to the high quality risk of aseptic manufacturing, interfaces must include basic data validation logic. This logic filters invalid or abnormal data and prevents compliance issues in subsequent processes.

## How to configure settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Fixed as Bearer {custom API key} | Used for external system identity verification, ensures interface access security, and complies with the access specifications of FastGPT v4.17.0 |
| `variables` | Populate with batch numbers, seed lot information, and cleanroom environmental parameters | Matches the core business fields required for bid documents, ensuring data consistency with actual production |
| `responseData` | Return only a subset of fields that have passed compliance validation | Filters redundant data and simplifies quotation preparation and document generation logic |
| Request timeout | 600 seconds | Adapts to the pulling and validation duration of complex business data, preventing call interruptions |
| Scheduled trigger rule | Trigger per monitoring plan cycle | Matches real-time and per-batch update frequencies, ensuring data timeliness |
| Data format mapping | Convert to the standard field structure of aseptic manufacturing documents | Compatible with data formats of existing LIMS and MES systems, reducing external system docking costs |

## Three common mistakes
- Phenomenon: A 401 Unauthorized error is returned when calling the interface, or external systems cannot obtain data normally. Cause: The `Authorization` parameter is not configured correctly, or an expired API key is used.
- Phenomenon: Fields returned by the interface are empty, or data does not match actual production records. Cause: Correct business identifiers are not passed via the `variables` parameter, resulting in irrelevant or incomplete business data being pulled.
- Phenomenon: Interface calls time out, returning a 504 status code. Cause: The request timeout is not set appropriately, and the processing duration of complex business data is not accounted for.

## How to confirm configuration is complete
- Call the configured interface and check if the `responseData` returned includes core business fields required for bid documents, such as batch numbers and environmental monitoring data.
- Verify the validity of the `Authorization` parameter: Call the interface with an incorrect key to confirm a 401 Unauthorized error is returned, and confirm valid data is returned for normal calls.
- Trigger the scheduled task and check if the interface triggers per the set cycle to pull the latest production record data.
- Check the interface data format received by the external system and confirm it matches the preset aseptic manufacturing document field structure.
