# Bid Document and Quotation Preparation for Biologics and Aseptic Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data sources for this category include cell banks and seed lots, process analysis, clean zone monitoring, MES, LIMS, and equipment integrity testing. Updates occur per production batch, for real-time monitoring data, and per fixed monitoring plans.
Daily documents cover cell bank or seed lot records, culture and purification records, aseptic filling records, environmental monitoring, media fill simulation, sterility testing, and batch release materials. Fields include batch identifiers, monitoring point numbers, test values, timestamps, equipment numbers, and more. Units include colony-forming units per square meter, degrees Celsius, hours, and other standard units.

## Data characteristics impose constraints on multi-turn dialogue and prompt engineering
Data from this category spans multiple systems. Multi-turn dialogue must accurately match corresponding records across different data sources to avoid cross-module data mixing.
Real-time and scheduled monitoring updates require context to isolate historical conversations by batch. This prevents parameters from different production batches from being mixed.
Professional documents include many detailed test fields and units. Prompts must clearly define allowed document types and field ranges. This stops generation of non-compliant production content.
Aseptic manufacturing carries severe consequences for errors. Dialogue-generated documents must strictly use real test values. No statements that conflict with actual data are permitted.

## Configuration Settings
These configurations are based on FastGPT v4.17.0, and are tailored to bidding scenarios for biologics and aseptic manufacturing.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context length | 8000–12000 token | Matches core document data volume for a single production batch, avoiding truncation of critical test records |
| Historical conversation isolation rule | Group by `chatId` | Prevents interference between conversation data from different users or production batches, meeting data security requirements |
| Variable binding configuration | Bind `variables` to production batch number | Accurately retrieves cell bank, filling, and other records for the target batch, narrowing the search scope |
| Recalled historical conversation count | Top 3 entries | Reduces redundant historical data interference with current generation, focusing on the active bidding task |
| Session timeout duration | 600 seconds | Aligns with the time required for multi-round editing and data verification, avoiding unexpected mid-process interruptions |
| Prompt context cropping | Filter by production batch | Only retains test data for the current bid’s target batch, improving information quality for prompt inputs |

## Three Common Configuration Mistakes
- Symptom: The `Human` field is empty in API call response previews. Cause: The user message structure for the `messages` parameter was not properly passed, so user-side content in the conversation history was not recorded.
- Symptom: Multiple users sharing one application cannot view their individual historical conversation records. Cause: Session isolation by `chatId` was not enabled, so all users’ conversation data is stored together.
- Symptom: Generated bid quotations include test data from non-current production batches. Cause: `variables` was not bound to the target production batch number, so retrieval scope includes unrelated batch records.

## How to Verify Successful Configuration
- Initiate a test conversation, enter a query for a specified production batch, and confirm generated content only includes data for that batch.
- Switch between test accounts, and confirm each user’s historical conversation only displays their own interaction records.
- Call the API to fetch conversation data, and confirm the returned `messages` parameter contains complete user and assistant conversation content.
- Simulate multi-round editing operations, and confirm the session completes normally within a reasonable duration without unexpected interruptions.

The values provided here are common starting points, and should be measured against the reader's own samples.
