# Bid Document and Quotation Preparation for Biologics and Aseptic Manufacturing: Document Parsing and Chunking

## What the Data for This Category Looks Like
Daily documents for this category include cell bank or seed lot records, culture and purification records, aseptic filling records, environmental monitoring data, media fill simulation results, sterility test reports, and batch release documents. Data sources cover cell bank and seed lot systems, process analysis platforms, clean zone monitoring equipment, MES, LIMS, and equipment integrity testing tools. Data updates follow production batches, real-time monitoring cycles, and established monitoring plans. Most documents combine structured tables and unstructured text. Fields include batch numbers, operating parameters, environmental indicators, and test results. Some parameters require specific units such as colony-forming units, pressure values, and temperature ranges.

## How These Characteristics Affect Document Parsing and Chunking
The mixed structure and specific field requirements of documents in this category require the parsing process to accurately identify batch, parameter, and unit information in structured tables, and prevent splits that break data relevance. Differences in update rhythms across multi-source data require chunking to match appropriate granularity based on document type, and avoid mixing short-cycle real-time monitoring data with long-cycle batch record content during splitting. Compliance requirements for aseptic manufacturing-related documents require retaining the contextual association of original data, and chunking must not truncate the complete logical chain of key parameters. Differences in document formats across sources require adapting to multiple parsing rules, to ensure consistent parsing of cell bank records and environmental monitoring reports.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | This category’s documents include structured tables and long-text parameter records. This range preserves the complete context of a single batch operation or single set of test data |
| `chunkSplitter` | Split by paragraph and table boundaries | Adapts to the mixed structure of documents in this category, and avoids splitting table rows or truncating parameter association logic |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 seconds | Some aseptic production records include multi-page historical data and batch monitoring results, so sufficient parsing time must be reserved |
| `customPdfParse` | Enable structured parsing mode | Accurately extract table fields and unit information from documents in this category, and avoid field loss caused by unstructured parsing |
| Chunk Overlap Length | 100–150 characters | Retains contextual association between adjacent chunks, and ensures logical continuity of cross-chunk data |

This page is written based on FastGPT v4.17.0 configuration guidelines.

## Three Common Configuration Mistakes
- Parsing results are empty after uploading environmental monitoring records in image format. This occurs because structured parsing configuration for image documents is not enabled, and only text-based files are parsed by default.
- Passing an image address fails to complete parsing. This occurs because the parsing whitelist for external image links is not configured, or the storage path corresponding to the address is not mapped correctly.
- Parsing times out after locally deploying MinerU. This occurs because `PARSE_FILE_TIMEOUT_SECONDS` is not adjusted to match the response duration of the MinerU service, which causes the parsing process to terminate early.

## How to Verify Correct Configuration
- Upload a typical batch release document, review the parsed chunk results, and confirm that tables and long-text paragraphs are not incorrectly truncated.
- Call the document parsing API and pass a test aseptic filling record, check whether the returned chunk data includes complete batch numbers and operating parameter context.
- Adjust the `chunkSize` parameter, compare chunk results across different values, and confirm that they meet the context retention requirements for documents in this category.
- Verify the connectivity between the locally deployed MinerU service and FastGPT, confirm that parsing tasks can be triggered normally and return results.

The values provided are common starting points and should be measured against the reader's own samples.
