# Bid Document and Quotation Preparation for Biologics and Aseptic Manufacturing: Model Integration and Configuration

## What data for this category looks like
Data for this category comes from cell banks and seed lots, process analysis, cleanroom monitoring, MES, LIMS, and equipment integrity testing. Daily documents include cell bank or seed lot records, culture and purification records, aseptic filling records, environmental monitoring, media fill simulation, sterility testing, and batch release documents. Fields include batch number, test batch, environmental monitoring point, key process parameter values, and others. Units include degrees Celsius, hours, colony-forming units, and others. Data update frequencies include per batch, real-time, and according to monitoring plans. Update rhythms vary across different documents.

## What constraints these characteristics impose on model integration and configuration
Multi-source and scattered data sources require adapting to the export formats of different systems during model integration, to avoid field matching errors. Data with different update rhythms need flexible adjustment of the context window, to ensure real-time monitoring data is timely incorporated into generation logic, while retaining compliance references from historical batch records. The complex professional document structure and exclusive fields require clear configuration of the model's professional term recognition rules during setup, to prevent generated content from deviating from business specifications. Additionally, the consequences of errors in this category are severe, so the reference range and parameter accuracy of model outputs must be strictly restricted.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Adapts to the context requirements of long documents such as batch release documents and culture and purification records, avoiding truncation of critical compliance data |
| `maxTokens` | 4000 token | Controls the output length of bid documents and quotation preparations, ensuring compliance with the format and length requirements of bidding documents |
| `quoteMaxToken` | 1500 token | Limits the length of referenced business documents, prioritizing retention of core compliance data such as sterility testing and environmental monitoring |
| `temperature` | 0.2–0.4 | Reduces output randomness, ensuring consistency of parameters and compliance statements in bidding documents |
| `toolChoice` | auto | Automatically selects whether to call tools to supplement data, adapting to the real-time update requirements of cleanroom monitoring data |
| `AIPROXY_API_ENDPOINT` | Fill in according to the enterprise's internal deployment environment | Adapts to enterprise intranet access rules, ensuring data transmission complies with security requirements |

## Three common misconfigurations
- Phenomenon: The monitoring time referenced in generated bid documents does not match the actual server time. Cause: Time synchronization logic for the local model is not configured, causing the model to use a built-in static time and fail to match real-time updated cleanroom monitoring data.
- Phenomenon: Content returned after calling the model lacks fields related to sterility testing. Cause: Context reference rules are not correctly configured, so the model cannot match exclusive fields in test reports exported from LIMS.
- Phenomenon: The generated quotation does not include cost items for media fill simulation. Cause: Material data from the MES system is not included in the context range, causing the model to omit necessary cost data from production links.

## How to verify a correct configuration
- Upload a complete batch release document as context, and check whether the model's output bid documents accurately reference sterility test result data.
- Simulate submitting real-time cleanroom monitoring data, and confirm whether the latest environmental monitoring point parameters are included in the model's output documents.
- View the FastGPT v4.17.0 API call logs to confirm that `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are configured correctly, with no connection errors.
- Test inputs with different document combinations, and check whether the format of the output bid documents complies with industry specifications and has no obvious field omissions.
