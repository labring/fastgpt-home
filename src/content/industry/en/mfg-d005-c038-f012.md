# Bid Document and Quotation Preparation for Biologics and Aseptic Manufacturing: Deployment and Upgrade

## What the Data for This Category Looks Like
The typical entities for this category are vaccine, antibody, blood product, and sterile injectable manufacturers. Daily documents include cell bank or seed lot records, culture and purification records, aseptic filling records, environmental monitoring data, media fill simulation results, sterility test reports, and batch release documents.
Data sources cover cell bank and seed lot systems, process analysis equipment, clean zone monitoring systems, MES, LIMS, and equipment integrity testing tools. Update frequencies include sync per production batch, real-time monitoring uploads, and regular updates per monitoring plans.
Each document contains fields such as batch number, test time, key parameter values, compliance check results, and others. Some original files must be linked to corresponding batch records.

## Constraints Imposed on Deployment and Upgrade
Data sources for this category are scattered, and update rhythms vary. Multiple data source connection parameters must be configured during deployment to sync records from different systems.
Documents must be associated and integrated by batch dimension. Retrieval grouping rules must be set during deployment to match batch-related content requirements in bid documents.
Data update frequencies cover real-time and scheduled scenarios. Support for incremental sync and scheduled task scheduling configuration is required.
Since errors may involve patient safety and batch scrapping, data access permissions and check rules must not be modified arbitrarily during deployment and upgrade, to avoid interrupting compliant data sync processes.
Original data source connection configurations must be retained during upgrades, to prevent critical business data from failing to be pulled normally due to configuration resets.

## Three Common Configuration Errors
- Phenomenon: After upgrading to FastGPT v4.17.0, the plugin editing page consistently displays an unsaved prompt. The prompt remains visible after clicking save. Cause: The front-end cached configuration status does not match the actual storage status of the back end. The browser cache has not been cleared, or the front-end service has not been restarted.
- Phenomenon: The rearrangement component deployed using docker returns a result of false, even though the interface call succeeds. Cause: The communication key between the rearrangement component and the main service is not properly matched, or the incoming document fields do not conform to the category data format requirements.
- Phenomenon: When calling the retrieval API, setting a single retrieval quantity greater than 6 does not take effect. Cause: The configuration value of `DB_MAX_LINK` has not been adjusted to the corresponding threshold, resulting in the system limiting the number of retrieval entries.

## How to Confirm Successful Configuration
- Check the connection status of each data source configuration item, and confirm that daily document data for the corresponding category can be pulled.
- Verify that the document types returned by the retrieval function match the category’s cell bank records, aseptic filling records, and other relevant types.
- Test the functions of the upgraded version, and confirm that there are no interface errors or data synchronization anomalies.
- Review the file access permissions in the storage configuration, and confirm that original files related to sterility tests can be uploaded and downloaded normally.

The values provided are common starting points and should be measured against the reader's own samples.
