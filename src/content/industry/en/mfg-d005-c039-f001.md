# Tender Document and Quotation Preparation for Electric Motor and Generator Manufacturing: HTTP Interfaces and External Systems

## What the Data for This Category Looks Like
This category's data originates from electromagnetic design data, copper wire and insulating material batch records, winding equipment, balancing machines, electrical test bench outputs, and ERP/MES systems. Daily generated documents include winding process cards, insulation treatment records, dynamic balance reports, withstand voltage insulation test records, and type and factory test reports.
Data is updated after each individual product or product batch is completed, and synchronized whenever product type specifications are changed.
Data fields include winding turns, insulating material batch numbers, dynamic balance accuracy values, test voltage values, and other metrics, with dedicated unit identifiers corresponding to different processing links.

## Constraints Imposed by These Characteristics on HTTP Interfaces and External Systems
Data sources for this category are scattered across multiple types of equipment and business systems. Updates occur at the individual product or product batch level.
HTTP interfaces must support on-demand triggered single or bulk data pulling to adapt to customized data requirements of different tender projects.
Daily documents include multiple types of dedicated fields and units. Interfaces must support custom field mapping rules to avoid cross-system unit conversion errors.
Product type specification changes trigger data updates. Interfaces must support dynamic parameter pulling without requiring reconfiguration of interface rules for each change.
Tender document and quotation preparation requires association with test data. Interfaces must return structured, compliant data formats to support subsequent document generation steps.

## How to Set Up Configurations
The following configurations are based on FastGPT v4.17.0

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer ${enterprise-specific API key}` | Adapts to multi-tenant interface authentication requirements, prevents unauthorized access to internal business systems |
| `variables` | `{"batchId": "current tender batch number", "productType": "specified motor model"}` | Passes batch and model parameters to accurately pull test data and process records for the corresponding product |
| `responseData` | Return only structured fields for test reports and process cards | Filters redundant data, improves interface response efficiency, and adapts to precise data calls for tender documents |
| Interface timeout period | `600 seconds` | Some test data generation takes a long time, prevents request interruption from early timeout |
| Field mapping rules | Unit conversion rules calibrated via actual measurements | Adapts to dedicated units for turns, voltage, balance accuracy and other metrics for this category, ensures data accuracy |

## Three Common Configuration Mistakes
- Phenomenon: Interface calls return the `self-signed certificate` error, and SSL handshake fails. Cause: Custom SSL certificates for internal devices or systems are not configured for trust, and HTTPS interfaces are called directly.
- Phenomenon: The `responseData` field returns empty, and corresponding test data cannot be obtained. Cause: The batch number or model in the `variables` parameter is not passed correctly, so the interface cannot match the corresponding data.
- Phenomenon: Interface requests are interrupted early, and a timeout error is returned. Cause: The timeout period is set too short, which does not adapt to the time required for test data generation in this category.

## How to Verify Proper Configuration
- Call the configured interface, check that the return status code is 200, and `Authorization` authentication verification passes.
- Review the fields returned in `responseData`, confirm that they include dedicated category data fields such as winding turns and dynamic balance accuracy.
- Pass different `variables` parameters, confirm that the interface returns test data for the corresponding batch or model.
- Test calls to internal HTTPS interfaces, confirm that no SSL-related errors occur, and the certificate trust configuration is effective.
