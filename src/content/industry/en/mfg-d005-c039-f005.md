# Bid Document and Quotation Preparation for Electric Motor and Generator Manufacturing: Tool Calling and Plugins
This page is configured based on FastGPT v4.17.0.

## What data for this category looks like
Data for this category comes from electromagnetic design databases, copper wire and insulating material batch ledgers, winding equipment operation logs, balancing machine inspection records, electrical test bench reports, and ERP/MES systems. Data is updated per finished unit or production batch, and synchronized each time a product type change occurs. Daily output documents include winding process cards, insulation treatment records, dynamic balance reports, withstand voltage insulation test records, type and factory test reports. Core fields include winding turns, insulation layer thickness, dynamic balance residual unbalance, test voltage, and rated power. Corresponding units are turns, millimeters, gram·centimeter, kilovolt, and kilowatt.

## What constraints this category’s characteristics impose on tool calling and plugins
Data for this category is updated per unit or batch, and includes multi-dimensional process, inspection, and production parameters. Tool calling and plugins must align with this characteristic. They must bind material, equipment operation, and test data for the corresponding batch to avoid cross-batch parameter mixing that causes errors in bid documents. Core fields have dedicated units, so plugins must configure unit verification logic to prevent confusion between different types of fields such as winding turns and insulation thickness. Product type changes trigger synchronized data updates, so tool calling must link to the latest type version to ensure bid document parameters match current production standards. Bids require aggregation of data from multiple units or batches, so plugins must support batch pulling of structured data from multiple source systems.

## Three common mistakes
- Tool calls return empty parameters, and the interface shows a call failure. The cause is that ERP/MES data for the corresponding batch is not bound, so the plugin cannot pull core parameters required for bids such as winding turns and dynamic balance residual unbalance.
- The call log does not show the complete request body content, making it impossible to troubleshoot abnormal parameter transmission. The cause is that request log storage in debug mode is not enabled, so complete call details cannot be traced.
- The built-in DuckDuckGo search plugin fails to return quotation information for domestic motor raw materials. The cause is that the plugin is not adapted to the domestic network environment, so it cannot pull public quotation data sources normally.

## How to confirm the configuration is complete
- Initiate a test call, check whether the returned parameters include core fields such as winding turns and dynamic balance residual unbalance for the currently selected batch.
- Check the debug log to confirm that the complete request body has been recorded, and the parameter transmission process of the call can be traced.
- Test the search plugin to confirm that raw material quotation data related to this category can be pulled, and the returned results meet the access requirements of the domestic network environment.
- Verify that the auto mode of `toolChoice` can automatically match multiple types of structured data without manually specifying the called function type.
