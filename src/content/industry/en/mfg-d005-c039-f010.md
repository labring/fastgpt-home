# Bid Document and Quotation Preparation for Electric Motor and Generator Manufacturing: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
This category of data comes from winding, insulation, final assembly, and testing departments of motor factories and power equipment enterprises. Core daily documents include winding process cards, insulation treatment records, dynamic balance reports, voltage withstand insulation test reports, and type and factory inspection test reports.
Data sources cover electromagnetic design data, copper wire and insulation material batch information, winding equipment operation data, balancing machine test results, electrical test bench test data, as well as production and material records from ERP and MES systems.
Data is updated each time a product unit or batch is produced, and associated documents are synchronized whenever the product type is modified.

## Constraints on Knowledge Base Retrieval and Recall
Documents in this category are mostly structured records with clear process parameters and test values. Update frequency changes rapidly with production batches, so knowledge base retrieval must accurately match specific fields such as winding turns and insulation system parameters.
Material data and equipment operation parameters vary across batches. Retrieval must associate corresponding batch materials and test records to avoid mixing cross-batch data.
In addition, bid document and quotation preparation requires access to three types of data: electromagnetic, insulation, and mechanical balance. This means retrieval and recall must cover multi-dimensional associated documents, and returned results must match the current bid product model and test report.

## Recommended Configuration Settings
The following settings are based on FastGPT v4.17.0, and are adapted to the knowledge base retrieval needs of electric motor and generator manufacturing scenarios:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches structured documents such as winding processes and test reports, and avoids recalling irrelevant batch motor data |
| `limit` | Top 8 entries | Covers the three core document types: winding, insulation, and testing, and prevents excessive results from exceeding the context carrying capacity |
| `searchMode` | Semantic retrieval + keyword hybrid | Simultaneously matches the turn values in process cards and the keyword requirements of bid documents |
| `usingReRank` | Enabled | Re-ranks recall results by relevance, improving the sorting accuracy of professional data such as dynamic balance and voltage withstand tests |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands retrieval terms, adding synonyms for professional terms such as winding turns and insulation grade |
| `collectionIds` | Bind exclusive knowledge base collections corresponding to winding processes, test reports, and material batches | Limits the retrieval scope to avoid mixing documents from other categories |

## Three Common Configuration Errors
- Retrieval results include winding process data from other product lines, and documents for the target batch are under-recalled. The root cause is failure to limit the retrieval knowledge base collection via `collectionIds`, leading to recall of cross-category documents.
- The first query returns accurate results, but subsequent queries in the same conversation window return irrelevant answers. The root cause is failure to reset the conversation retrieval scope, with context vectors from the previous retrieval interfering with the recall logic for new queries.
- Process cards and test reports imported via static pages cannot be updated automatically. The root cause is failure to configure scheduled synchronization tasks and associate document version change triggers, making it impossible to synchronize batch update data for each product.

## How to Verify Proper Configuration
- Input the winding turns and insulation grade parameters of a specified motor model, and check whether the returned knowledge base documents include the corresponding process cards and test records for that model.
- Submit three bid-related queries for different product models, and verify that each retrieval result only associates the current query’s product batch and documents.
- Trigger a document update task, and confirm that the insulation treatment records for the corresponding batch in the knowledge base have been synchronized to the latest version.
- Check the retrieval log to confirm that configuration items such as `searchMode` and `usingReRank` have taken effect as set, and that returned results are sorted according to the relevance requirements of professional data.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
