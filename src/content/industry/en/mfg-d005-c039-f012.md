# Tender Document and Quotation Preparation for Electric Motor and Generator Manufacturing: Deployment and Upgrade

## What the Data for This Category Looks Like
The data for this category comes from electromagnetic design systems, batch ledgers for copper wire and insulating materials, winding equipment operation logs, balancing machine test records, electrical test bench reports, and ERP and MES production management systems. Daily generated business documents include winding process cards, insulation treatment records, dynamic balance reports, voltage withstand insulation test records, and type and factory test reports. Data is updated per individual motor, per product batch, or per type change. Core fields include winding turns, wiring method, paint dipping and drying parameters, vibration and temperature rise test values, efficiency and voltage withstand indicators.

## Constraints Imposed by These Characteristics During Deployment and Upgrade
Data for this category is updated per individual unit, batch, or type change, and includes a large number of professional test parameters and process records. During deployment, access and parsing of multi-source heterogeneous data must be supported. During the upgrade process, existing indexes must not be lost, while new fields related to type changes must be compatible. Core business documents include strongly associated fields such as winding turns and voltage withstand tests, so precise field mapping rules must be configured during deployment to avoid field misalignment during retrieval. Frequent batch-level updates require deployed storage and query components to have low-latency incremental update capabilities to prevent business interruptions caused by full reindexing.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150 connections` | Adapts to concurrent requests from simultaneous access of multiple batch data, avoiding database connection exhaustion |
| `MONGODB_URI` | Points to a dedicated MongoDB instance mounted on SSD storage, configured with read-write separation | Stores large volumes of unstructured test reports and process documents; read-write separation improves query performance |
| `PG_URL` | Connects to a PostgreSQL instance deployed on enterprise-grade SSD | Stores structured batch data, winding parameters, and ERP-synced fields, ensuring transaction consistency |
| `REDIS_URL` | Configured as a single instance with a memory limit of 8 GB | Caches frequently accessed test parameters and retrieval results, reducing database query pressure |
| `STORAGE_S3_ENDPOINT` | Points to the enterprise internal object storage service address | Stores original test data and document backups, adapting to the enterprise’s existing storage architecture |

## Three Common Misconfigurations
- Symptom: After upgrading to FastGPT v4.17.0, existing electric motor test reports cannot be retrieved, and the interface returns the prompt "No matching documents found". Cause: Only the program upgrade was completed, and incremental index updates were not executed; the vector index for batch data was not synchronized.
- Symptom: Docker container fails to start, the console returns `500 Internal Server Error`, and logs show database connection timeout. Cause: The instance address configured in `MONGODB_URI` does not have external ports open, or network connectivity between the container and the database is not properly configured in docker-compose.yml.
- Symptom: File parsing fails when uploading insulation treatment records, and the interface prompts "Insufficient permissions". Cause: File permission verification failed due to missing `FILE_TOKEN_KEY` configuration, preventing reading of original document content.

## How to Confirm the Configuration Is Correct
- Run a database connection test script to verify that the number of connections configured in `DB_MAX_LINK` can be accessed normally concurrently, with no connection timeout errors.
- Upload a winding process card document to verify that core fields such as winding turns and wiring method can be correctly extracted after parsing, with no missing fields.
- Trigger an incremental index task to verify that newly uploaded test reports can be retrieved normally, and the retrieval results include correct batch and parameter information.
- View the Redis monitoring panel to confirm that the cache hit rate is stable, with no resource overload caused by a large number of repeated queries.

The values provided are common starting points and should be evaluated against the reader's own samples.
