# Bid Document and Quotation Preparation for Battery PACK and Energy Storage System Integration: Vector Models and Indexes

## What the data for this category looks like
Core data for this category comes from cell grading and sorting equipment, MES systems, welding torque tools, BMS software, and EOL test benches. Daily documents include cell grouping rules, single-unit product BOMs, welding and torque records, BMS flashing logs, insulation and pressure resistance reports, EOL test reports, and system configuration lists. Data updates occur once per produced PACK or energy storage cabinet. Each BMS software version change also triggers a data update. Each individual document includes clear fields such as cell model, grouping parameters, torque values, and test thresholds. No extra redundant statistical items are included.

## Constraints Imposed on Vector Models and Indexes
Data for this category is scattered and uses fine-grained updates. Each individual document contains many engineering parameters with units. Vector modeling must retain the binding relationship between parameters and their context. Semantic fragmentation must be avoided. Bid scenarios require fast recall of historical documents and quotation data for similar products. Indexes must support cross-document parameter matching recall. Pure text matching alone cannot meet this need. High-frequency updated single-unit product data requires indexes to support incremental updates. Full index rebuilding causes processing delays, which must be avoided. Indexes must also adapt to unified vectorization formats for multi-source heterogeneous data.

## How to Set Configurations
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Ensures semantic integrity of individual engineering documents, prevents parameter context breakage after splitting |
| Overlap Length | 100–150 characters | Retains parameter association information between adjacent chunks, prevents cross-chunk semantic loss |
| `defaultToken` | 4096 | Adapts to the token limit of FastGPT v4.17.0, covers the long text vectorization needs of BMS configuration lists and EOL test reports |
| `maxToken` | 8192 | Covers the total token upper limit after multiple documents are spliced in bid documents |
| Similarity Threshold | Calibrated based on actual measurements | Adapts to the semantic matching accuracy of engineering parameters, must be adjusted using historical bid data |
| Single Recall Limit | Top 10 entries | Controls redundancy of recall results, avoids invalid information interfering with quotation preparation |

## Three Common Misconfigurations
- Vector similarity calculation results fall outside the normal range, such as 10000+. The cause is failure to correctly configure the normalization rules for the similarity threshold. A scoring system outside the 0-1 range was used in error.
- The knowledge base dataset remains in the indexing state for a long time after import. The cause is failure to adapt to the multi-source heterogeneous data format of this category. Field naming rules for engineering parameters were not unified in advance, leading to index parsing failures.
- No available channel is found for the specified embedding model. The cause is failure to add the model access key in the platform configuration page, or failure to enable the model call permission.

## How to Confirm Proper Configuration
- Upload a typical BMS configuration list document. Check the semantic integrity after chunking. Confirm that no parameters are split into unrelated chunks.
- Enter a bid-related query such as "grouping rules for a specific cell model". Verify the relevance of recall results. Adjust the similarity threshold to a range that meets business requirements.
- Import an updated welding torque record. Check whether the index completes incremental updates automatically, without requiring full rebuilding.
- View the platform's model configuration page. Confirm that no available channel prompts remain, and the model call status is normal.

The values provided here are common starting points. They should be evaluated against the reader's own samples.
