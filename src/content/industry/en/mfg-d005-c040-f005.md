# Bid Document and Quotation Preparation for Battery PACK and Energy Storage System Integration: Tool Calling and Plugins

## What this category’s data looks like
The main entities in this category are manufacturers of power battery packs, energy storage cabinets, and BMS systems. Daily processed documents include cell grouping rules, BOM lists, welding and torque records, BMS flash records, insulation and voltage withstand reports, EOL test reports, and system configuration lists. Data sources cover cell capacity grading data, MES systems, welding equipment, torque tools, BMS software versions, and EOL test benches. Updates are triggered per individual product unit or each software version change. Individual documents contain fields such as cell parameters, grouping plans, electrical connection details, and thermal management configurations. Fields and units adjust flexibly based on document type.

## What constraints these characteristics impose on the tool calling and plugins workflow
Data sources for this category are scattered, covering production equipment, software systems, and test benches. Tool calling must support connection to multiple types of data sources to pull real-time or near-real-time data. Fields in individual documents vary significantly by type, so tools must adapt to different document structures to extract corresponding parameters. Update frequency is triggered by individual product units or software changes, so tool calling must match the high-frequency update rhythm to avoid using expired data. Bid documents and quotations must strictly match core information such as cell parameters and grouping plans. The accuracy of tool calling directly affects document compliance and quotation rationality. Incorrect calling may cause data deviations in bid submissions.

## How to set up configurations
The following configurations are formulated based on the logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to automatic selection of multiple production data pulling and document generation tools, covering all data sources required for bids |
| `functionCall` | Trigger per preset tool list | Ensures only configured production data-related tools are called, prevents unauthorized tools from being invoked, and protects bid data security |
| Single tool call timeout | 120 seconds | Matches the average response time of production equipment and systems, avoids call failures due to device delays |
| Tool call context synchronization switch | Enabled | Retains production data context across multi-step tool calls, ensuring parameter consistency during bid quotation preparation |
| Database tool call permission scope | Only open production data-related tables | Prevents unauthorized access to non-authorized data, complies with the confidentiality requirements of bid documents |

## Three common mistakes
- Symptom: A 400 status code is returned when calling the MySQL database tool with no response body. Cause: The permission scope of the database connection is not configured correctly, or the address and port in the connection parameters are filled incorrectly, preventing the tool from establishing a normal connection.
- Symptom: Context is not retained when calling a workflow API with configured context. Cause: The API request does not carry the correct context parameters, or the context trigger condition of the workflow is not bound to the corresponding tool call link, resulting in failure to pass context.
- Symptom: After passing the `model` parameter when calling an API, the task execution result does not match the expected classification or extraction logic. Cause: The specific task type bound to the `model` parameter is not clearly defined, and no mapping relationship between the parameter and the task is established in the configuration, causing the parameter to not be correctly recognized.

## How to confirm the configuration is complete
- Initiate a single-step tool call test, verify that the pulled production data is consistent with MES systems and cell capacity grading data, and adjust parameters until the target data range is matched.
- Simulate a multi-step bid document preparation process, verify the retention status of context across tool calls, and ensure correct parameter transfer.
- Check API request logs to confirm that the `toolChoice` or `functionCall` parameters are correctly identified, with no failed call records.
- Trigger a database tool call, verify that the permission scope only covers the preset production data tables, with no unauthorized access prompts.

The values provided are common starting points and should be measured against the reader's own samples.
