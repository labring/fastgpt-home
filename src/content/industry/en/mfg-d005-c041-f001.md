# Tender Document and Quotation Preparation for Electroplating and Chemical Surface Treatment: HTTP Interfaces and External Systems

## What data for this category looks like
Daily documents for this category include tank solution analysis records, process parameter cards, fixture records, film thickness and adhesion reports, hazardous waste ledgers, and wastewater monitoring records. Data sources include customer surface treatment specifications, tank solution test results, rectifier operation data, online water quality monitoring data, and hazardous waste management ledgers. Data update frequencies follow per tank batch, per shift, and fixed monitoring cycles. Core fields for a single document include tank number, chemical concentration, pH value, workpiece batch, film thickness value, hazardous waste category, and generation volume, with corresponding units such as g/L, μm, kg, and others.

## What constraints these characteristics impose on HTTP Interfaces and External Systems
Diverse and frequently updated data sources for this category require HTTP interfaces to support high-frequency pulling of multi-source structured data, while adapting to field formats of different documents. Fixed unit requirements (such as μm for film thickness and g/L for chemical concentration) mean interface-returned field units cannot be changed arbitrarily, otherwise quotation parameter errors will occur. The high-frequency update feature requires interfaces to have reasonable timeout and retry mechanisms to avoid losing real-time data due to temporary network fluctuations. Intranet-deployed business environments require interfaces to only allow intranet access, with no public network exit needed. Data is linked to production compliance and quality risks, so data transmitted and stored by interfaces must have integrity verification capabilities to prevent erroneous data from entering the tender quotation process.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Request header configuration | Add the `Authorization` request header, with the value being a pre-configured interface secret key | Meet interface authentication requirements and prevent unauthorized access |
| Variable mapping rules | Map fields such as tank solution concentration, film thickness value, and hazardous waste generation volume to variables required for tender quotations, retain original units | Match the field and unit requirements of category data to ensure accurate quotation parameters |
| Response data processing | Extract core business fields from `responseData`, filter out non-essential monitoring log data | Simplify returned content and focus on valid information required for tender documents |
| Retry strategy | Retry 2 times after failure, with a 30-second interval | Adapt to temporary network fluctuation scenarios for high-frequency updated data |
| Timeout setting | Set to 60 seconds | Match the generation cycle of category data to avoid excessive waiting that affects quotation efficiency |
| Intranet access configuration | Only allow access to the interface from specified intranet IP segments | Adapt to the intranet environment of business deployment and ensure data security |

*Note: This configuration applies to FastGPT v4.17.0*

## Three common configuration mistakes
- Phenomenon: The interface returns a 304 status code, and real-time tank solution data cannot be obtained. Cause: The interface is configured with the default cache verification mechanism, and the cache is not disabled for frequently updated category data, resulting in the return of old data.
- Phenomenon: The database connection component returns the "Access denied for user" error. Cause: The intranet IP of the FastGPT server is not added to the database whitelist, and read-write permissions for the corresponding category business data are not configured.
- Phenomenon: Hazardous waste disposal data fields are missing in the tender document. Cause: The mapping field for the hazardous waste ledger is not configured in `variables`, so the `responseData` returned by the interface is not correctly extracted into workflow variables.

## How to confirm the configuration is complete
- Initiate a simulated interface request to verify that `Authorization` authentication passes, and that `responseData` includes the core business fields required for the category.
- Test interface access permissions in the intranet environment to confirm that only specified intranet IP segments are allowed to access.
- Trigger a quotation preparation process to check whether workflow variables correctly map category data such as tank solution concentration and film thickness value.
- Simulate an interface timeout scenario to verify that the configured retry policy is triggered.
