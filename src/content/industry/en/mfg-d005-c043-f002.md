# Bid Document and Quotation Preparation for Batch Synthesis in Fine Chemicals: Vector Models and Indexes

## What the Data for This Category Looks Like
This category's data comes from formula and process libraries, raw material batch records, reactor DCS systems, weighing systems, LIMS, and warehouse systems of fine chemical enterprises including coatings, resins, additives, and agrochemical intermediates. Routine documents include batch production instructions, feeding review sheets, reaction process records, cleaning records, test reports, deviation and change orders. Fields include feeding amount (unit: kilogram, liter), reaction temperature (degree Celsius), batch number, operation time, and others. Data is updated per batch production and each key operation step. The length of a single document ranges from hundreds to thousands of characters.

## Constraints This Category Imposes on the Vector Model and Indexing Stage
The characteristic of updating data per batch production and each key step requires indexes to support incremental updates, avoiding resource consumption and delays caused by full reconstruction. The document structure with multiple fields carrying units requires vector models to accurately encode the combined semantics of numerical values and units, preventing semantic confusion between different feeding amounts and reaction temperatures. The strong association between batches and process steps requires indexes to support filtered retrieval by batch number and product category, ensuring returned results only relate to the target production task. The business requirement for formula confidentiality requires the vector embedding link to automatically shield core parameter fields of formulas, preventing sensitive information leaks during retrieval and indexing.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Matches the typical paragraph length of single process documents for this category, avoiding fragmentation of in-chunk process information |
| Overlap Length | 100–150 characters | Retains cross-chunk reaction step association information, preventing loss of key process context during retrieval |
| Similarity Threshold | 0.75–0.85 | Filters low-relevance feeding records and process descriptions, adapting to the strong semantic association characteristics of fine chemical data |
| Single Search Limit | Top 20 entries | Covers multiple associated documents involved in a single batch production, avoiding insufficient retrieval results |
| `defaultToken` | 4096 | Adapts to the vector embedding requirements of long documents, enabling complete content encoding of batch production instructions |
| `maxToken` | 8192 | Matches the retrieval context splicing limit of FastGPT v4.17.0, supporting complete reference for bid documents |

## Three Common Misconfigurations
- A 503 error is returned after starting the service, and logs show no available channels for the text-embedding-v3 model under the default group. The cause is incorrect configuration of vector model channel parameters, or exhausted call quotas for the corresponding channel.
- After modifying the CHAT_API_KEY environment variable, the service still cannot call the corresponding model. The cause is failure to rebuild the Docker container to apply the new environment variable; only the host machine configuration was modified without synchronizing it to the container.
- Retrieved documents include feeding records from non-target batches. The cause is lack of configuration of index filtering rules based on batch number, resulting in retrieval scope covering all production data.

## How to Confirm Correct Configuration
- Check the running logs of vector embedding tasks, confirm the number of chunks for a single document matches expectations, with no abnormal errors.
- Run a simulated retrieval, enter keywords from a batch's feeding review sheet, and verify that the batch numbers of returned results match the input.
- View the environment variable configuration page, confirm CHAT_API_KEY is correctly filled with no extra spaces.
- Test the incremental update function, upload new batch production records, confirm the index automatically updates with no duplicate data.

The values provided here are common starting points and should be measured against the reader's own samples.
