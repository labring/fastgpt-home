# Bid Document and Quotation Preparation for Batch Fine Chemical Synthesis: Forms and Interactions

## What data for this category looks like
Core data for the batch fine chemical synthesis category comes from the formula and process library, raw material batch records, reactor DCS system, weighing system, LIMS, and warehouse management system. Daily associated documents include batch production instructions, feeding review sheets, reaction process records, cleaning records, inspection reports, deviation and change orders. The system updates data per production batch or each key step, covering scenarios with multiple product varieties and batch switching. Fields include feeding parameters, reaction temperature, cleaning confirmation items, and more. Units follow professional chemical measurement standards such as kilograms, degrees Celsius, and cubic meters. Formula parameters for different categories have confidentiality requirements.

## What constraints these characteristics impose on forms and interactions
The category’s multi-source data sources require forms to pull real-time data from multiple systems, avoiding manual entry errors. The data update rhythm based on batches and key steps requires forms to dynamically load process parameters and associated documents for the corresponding batch. The multi-variety and batch switching scenario requires forms to include conditional display logic, automatically showing exclusive fields and parameters based on the currently selected product category. The mandatory requirements for formula confidentiality and cleaning confirmation require forms to configure sensitive field permission controls and required validation, while supporting field integrity checks in the order of production steps to prevent missing key links.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `formInput` | Supports importing 50–100 feeding records in a single batch | Adapts to the batch-based feeding review process, reducing manual data entry workload |
| `userSelect` | Presets no more than 10 common product category options | Matches the multi-variety switching scenario, quickly loading corresponding form fields and process data |
| Field validation rules | Triggers required validation in the order of production steps | Aligns with the business process of sequential feeding review, preventing missing key steps |
| Data connection configuration | Associates real-time data interfaces with LIMS and warehouse systems, with a timeout threshold of 300 seconds | Pulls raw material batch and inventory information, ensuring the accuracy of bid quotation data |
| Permission control configuration | Sets read-only permissions for formula parameter fields | Meets the business requirement for formula confidentiality, preventing sensitive information leakage |

## Three common mistakes
- Issue: The `formInput` component appears as plain text in the chat interface, with no option to input or select content. Cause: The rendering parameters for `formInput` are not correctly configured, resulting in the interactive mode not being enabled.
- Issue: The options in the `userSelect` component do not update when the product category is switched, always showing the default options. Cause: The process library data corresponding to the category is not bound, and the conditional display logic does not take effect.
- Issue: Global variables cannot be synchronized to the radio variable of the user selection component, and the radio options cannot match the preset global variable values. Cause: The variable mapping rules are not correctly configured, and the global variable values are not bound to the value fields of the radio options.

## How to confirm the configuration is complete
- Open the test chat interface of FastGPT v4.17.0, enter preset product category keywords, and verify that the `userSelect` component automatically loads exclusive options for the corresponding category.
- Upload a batch feeding data file, confirm that the `formInput` component automatically imports data and verifies field integrity in the order of production steps.
- Attempt to modify formula parameter fields, verify that users without permissions cannot edit the fields, and users with permissions can modify normally.
- Skip a preceding production step to fill in a field, confirm that the interface pops up a corresponding validation prompt to prevent incomplete form submission.
