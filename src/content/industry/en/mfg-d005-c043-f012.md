# Bid Document and Quotation Preparation for Batch Fine Chemical Synthesis: Deployment and Upgrade

## What Data for This Category Looks Like
Data for this category comes from specialty chemical enterprises including coatings, resins, and agrochemical intermediates. Sources include formula and process libraries, raw material batch records, reactor DCS systems, weighing systems, LIMS, and warehouse systems.
Daily documents include batch production instructions, feeding review sheets, reaction process records, cleaning records, inspection reports, and deviation change orders.
Data is updated per batch production or key step. Fields include feeding volume, reaction parameters, cleaning confirmation records, and formula parameters. Units cover mass, volume, temperature, time, and other metrics.
Due to multi-variety batch switching, data is linked to a unique batch identifier.

## Constraints for Deployment and Upgrade
The multi-variety, batch-switching production characteristics of this category require deployment workflows to support batch data isolation, preventing formula leakage and cross-contamination.
High-frequency batch data updates require stable, high-concurrency database connections to maintain read and write efficiency.
The need to associate multiple production document types requires the file storage module to support different formats of production records and bid-related documents.
Bid quotations must accurately match fields such as feeding volume and reaction parameters.
Deployment must reserve resource margin for model calls to accommodate future upgrades to field extraction accuracy.
Since data sources include industrial control and laboratory systems, the system must support compatible data import rules for different formats.

## Three Common Mistakes
- When deploying Qwen3 series models via VLLM, target fields cannot be extracted from feeding review sheets parsed from PDF files, and the interface returns empty results. Cause: The Qwen3 series models have insufficient context understanding accuracy for industrial scenario professional fields such as feeding percentage and reactor number, or the deployment does not adapt to the format characteristics of industrial documents.
- After upgrading via docker-compose, the pg container fails to start, and the log displays "FATAL: role "postgres" does not exist". Cause: The original database role configuration was not retained during the upgrade, or the initialization script did not correctly execute the database user creation steps.
- When the `DB_MAX_LINK` configuration value exceeds the database's carrying capacity, the database connection pool overflows, causing bid document generation tasks to time out. Cause: The concurrency volume of high-frequency batch data updates for this category was not matched, and blindly increasing the connection number leads to resource exhaustion.

## How to Verify Successful Deployment
- Test batch import of one batch of production documents and formula data, check whether the database connection is normal, and there are no read and write timeout errors.
- Call the model interface, attempt to extract specified fields from a simulated feeding review sheet PDF, and verify that the model call link is unobstructed.
- Check the file storage module, confirm that the storage path partitioned by batch has taken effect, and documents can be read and downloaded normally.
- View the connection pool monitoring in the system background, confirm that the current connection number does not exceed the `DB_MAX_LINK` configuration value.

The values provided are common starting points and should be measured against the reader's own samples.
