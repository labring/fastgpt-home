# Pulp and Paper Bidding Document and Quotation Preparation: HTTP Interfaces and External Systems

## What the Data for This Category Looks Like
External systems generate business data for the pulp and paper category, including wood pulp and waste paper batch ledgers, DCS/QCS control systems, on-machine measurement equipment for paper machines, laboratory testing systems, and energy and water treatment systems.
Organizations working with this category generate daily documents including pulp preparation sheets, beating operation records, paper machine operation logs, online quality curves, laboratory test reports, and sheet break and product change records.
Data update cycles fall into three levels: real-time, per shift, and per roll.
Pulp preparation sheets record addition amounts for different raw materials.
Beating records include beating consistency and beating degree.
Paper machine operation records include machine speed and dryer cylinder temperature.
Fields and units vary across different documents.

## Constraints on HTTP Interfaces and External System Integration
The multi-source, layered update data characteristics of the pulp and paper category impose multiple constraints on HTTP interface and external system integration.
First, data formats and units differ across sources. Interfaces must support flexible field extraction and unit adaptation to avoid errors in bidding quotation calculations.
Second, data update cycles fall into three levels: real-time, per shift, and per roll. Interface trigger frequencies must align with update requirements for each level to prevent excessive calls or data lags that reduce quotation accuracy.
Third, bidding quotations must link to raw material and capacity data for specific production batches. Interfaces must support batch number and roll number as query parameters to ensure returned data matches the bidding project.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Use the Bearer Token generated via FastGPT channel configuration | Matches identity verification rules of external production systems to ensure lawful interface call permissions |
| Timeout Duration | 600 seconds | Adapts to response delays during high load on production systems to prevent request interruptions |
| `responseData` | Extract the collection of fields including pulp preparation amount, beating degree, machine speed, and capacity | Only returns core data required for bidding quotations to reduce invalid data transmission |
| Trigger Frequency | Trigger once per shift and after each roll production is completed | Matches update cycles of different data levels to lower interface call frequency |
| `variables` | Bind batch number and roll number as query parameters | Accurately pulls historical data for the corresponding production batch to ensure quotation data accuracy |
| Data Cache Duration | 3600 seconds | Caches commonly used production data to avoid repeated calls to external systems |

## Three Common Misconfigurations
- A 404 status code is returned during HTTP interface calls. This occurs when the `Authorization` parameter is not correctly configured, failing to match identity verification rules of external production systems.
- Production data fields are empty in generated bidding documents. This occurs when the `responseData` parameter is not configured to extract required core fields, resulting in valid business data being filtered out.
- Frequent timeouts occur during interface calls. This occurs when trigger frequency is not set according to data update cycles, and timeout thresholds are not adjusted when pulling real-time data at short intervals.

## How to Verify Correct Configuration
- In the FastGPT v4.17.0 test environment, manually trigger an HTTP interface call, and confirm the returned results include the configured `responseData` field collection.
- Review interface call logs to verify the `Authorization` parameter is correctly included, with no identity verification related errors.
- Compare pulled production data against original records in external systems to confirm fields and units match.
- Simulate the bidding document generation process, and confirm template variables have been properly replaced with pulled production data.
