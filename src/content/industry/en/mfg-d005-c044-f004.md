# Pulp and Paper Tender Document and Quotation Preparation: Workflow Orchestration

## What this category's data looks like
Business data for the pulp and paper category originates from wood pulp and waste paper batch ledgers, DCS/QCS control systems, on-paper machine measurement equipment, laboratory testing systems, and energy and water treatment systems. Daily business documents include pulp preparation sheets, beating operation records, paper machine operation logs, online quality curves, laboratory quality inspection reports, and sheet break and product change batch records.

Data update cycles are divided into three types: real-time (paper machine online measurement), per shift (team operation records), and per roll (after a single roll of paper finishes production). Fields include dry weight proportion of pulp components, paper basis weight, moisture content, thickness, and energy consumption indicators. Corresponding units are tons/batch, grams per square meter, kilograms per ton, millimeters, and kilowatt hours per ton.

## What constraints these characteristics impose on workflow orchestration
Because data sources are scattered and update cycles vary significantly, workflow orchestration must match the collection cycles of different data to avoid calling real-time online data that has not finished uploading. The category-specific business document structure requires that the variable assignment step of the workflow must accurately bind specific fields such as pulp preparation sheets and beating records. Variable templates designed for general categories cannot be directly reused.

The business characteristics of high-speed continuous web production require that core workflow nodes control processing latency to ensure the timeliness of tender quotations. At the same time, the independence of single-roll production data requires that batch execution nodes be triggered according to production batches. This prevents cross-batch data mixing, which affects quotation accuracy.

## Configuration Settings
The following configurations are developed based on the workflow logic of FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Global variable assignment | Bind corresponding fields from pulp preparation sheets and beating records | Match category-specific business document structures to ensure accurate variable sources |
| Knowledge base call | Associate a self-built pulp and paper process and cost knowledge base | Retrieve category-specific data to support accurate tender quotations |
| `variables` parameter priority | Prioritize node input variables, use plugin default values if not obtained | Balance the dynamism of business data and the basic availability of plugins |
| Batch execution trigger | Trigger per roll production completion node, interval `10–30 minutes` | Match the update cycle of single-roll production data to avoid data redundancy |
| Node timeout setting | `600 seconds` | Adapt to the time consumption requirements of multi-batch data processing to avoid task interruptions |
| Knowledge base recall limit | Top 5–10 matching results | Control context length to avoid exceeding workflow processing limits |

## Three Common Configuration Mistakes
- The interface displays a knowledge base call failure, returning the message "No matching self-built knowledge base found". This occurs when the created pulp and paper process knowledge base has not been associated with the workflow's search node.
- The batch execution node outputs an insufficient number of results, returning only a small volume of data. This happens when the single processing limit for batch execution has not been configured, and the system default limit restricts the number of returned results.
- Global variables are not assigned correctly, leaving the pulp cost field in the quotation empty. This is caused by failing to bind the `variables` parameter to the actual business fields of the pulp preparation sheet, which causes variable retrieval to fail.

## How to Verify Correct Configuration
- Check the binding configuration of the `variables` parameter, confirm that the corresponding business fields from pulp preparation sheets and beating records have been associated.
- Manually trigger the workflow, view the return results of the knowledge base search node, and confirm that the self-built pulp and paper category knowledge base has been called.
- Run the batch execution node, verify that the number of processed documents matches the production batches, with no cross-batch data mixing.
- Modify the node input variable to empty, check if the plugin calls the preset default value, and confirm that the parameter priority configuration is active.

The values provided are common starting points and should be evaluated against the reader's own samples.
