# Pulp and Paper Bidding Document and Quotation Preparation: Tool Calling and Plugins

## What the data for this category looks like
This category’s data primarily originates from wood pulp and waste paper batch archives, DCS and QCS control systems, paper machine online measurement equipment, laboratory testing systems, and energy and water treatment systems. Data is updated at three frequencies: real-time, per shift, and per roll. Daily produced documents include stock preparation sheets, beating records, paper machine operation logs, online quality curves, laboratory reports, sheet break and grade change records. Common fields include pulp ratio, beating degree, paper grammage, moisture content, sheet break duration, and more. Units include percentage, °SR, g/㎡, seconds, and others.

## What constraints do these characteristics impose on tool calling and plugins
Data for this category is scattered and has notable differences in update frequencies. This requires tool calling and plugins to support unified mapping of multi-source heterogeneous data. Real-time online quality data, shift-wise energy consumption records, and per-roll sheet break archives have a wide range of update frequencies. This means tool calling must support both on-demand triggering and scheduled synchronization modes. Bidding document and quotation preparation work requires linking stock preparation records for the same batch and historical paper machine operation data. Tools must support precise filtering and retrieval using fields such as batch number and roll number. Additionally, massive web data generated by high-speed continuous production requires tool calling to set a reasonable concurrency limit to prevent system overload. ## How to Set Configurations
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| Tool calling shunting strategy | Trigger based on data timeliness: call MCP for real-time data, call the knowledge base for historical archived data | Adapt to the scenario where real-time online data and historical batch archives coexist for this category |
| `toolChoice` | `auto` | Support automatic switching between knowledge base retrieval and MCP calling, simplifying multi-source data calling configuration |
| `functionCall` | `enabled` | Support returning standardized fields required for bidding, such as stock ratio and paper machine parameters |
| Single knowledge base retrieval limit | Top 6–10 entries | The number of historical documents associated with a single bidding project for this category usually falls within this range, avoiding interference from redundant data |
| MCP calling concurrency limit | 1 call per second | The collection interval of paper machine online data is usually longer than 1 second, avoiding exceeding system load |
| Context window length | 8000 token | The total length of associated data for a single bidding document usually falls within the 6000–7000 token range, calibrated based on actual measurements |

## Three Common Mistakes
- Phenomenon: Some requests return empty values when calling MCP concurrently. Cause: No reasonable MCP calling concurrency limit is configured, exceeding the response threshold of the paper machine data collection system.
- Phenomenon: Unable to establish a proper connection to the service when calling the FastGPT chat interface via Python. Cause: The official request format and authentication method were not used, resulting in interface authentication failure.
- Phenomenon: Unable to correctly pass multiple image parameters when calling tools. Cause: The field format for multi-image parameter passing was not configured, causing the interface to fail to parse image content.

## How to Verify the Configuration is Correct
- Trigger a tool call in a simulated bidding scenario, and check if the shunting logic automatically switches between the knowledge base and MCP based on data timeliness.
- Call the `functionCall` interface, and verify that the returned structured fields include pulp and paper industry-specific parameters such as stock ratio and beating degree.
- Send 10 consecutive MCP calling requests, and confirm that all returned results are not empty and comply with data format requirements.
- View the configuration log to confirm that the context window length matches the total length threshold of the current associated data.
