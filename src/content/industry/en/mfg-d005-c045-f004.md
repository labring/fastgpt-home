# Tender Document and Quotation Preparation for Spinning and Weaving: Workflow Orchestration

## What the data for this category looks like
Daily business documents for the spinning and weaving category include cotton blending or ingredient lists, process setup sheets, equipment operation records, yarn inspection, grey fabric inspection, defect records, and more. Data is sourced from raw fiber inspection systems, ERP systems, spinning and loom equipment, evenness testers, fabric inspection machines, and other devices.
Data updates occur per raw material batch, per shift, and per piece of fabric. A single document can be 50–100 MB in size. Fields include fiber grade, yarn fineness (tex), loom speed (r/min), grey fabric width (cm), defect type, and more. Some documents require precise matching using batch numbers and piece numbers.

## What constraints these characteristics impose on workflow orchestration
The data for this category has high update frequency and is split by batch and piece number. This requires workflows to support dynamically passing batch numbers and piece numbers as variables for retrieval conditions.
Multi-source heterogeneous business documents must correspond to different knowledge base nodes to avoid data confusion. Single large document sizes require configuring reasonable chunking rules to improve retrieval efficiency.
Defect records generated per piece produce a large volume of granular data, so workflow nodes must be split to handle data per piece. Tender quotations must match the exclusive process and inspection data for the current batch, so generic templates cannot be used directly for generation.

## Configuration Setup
The following configurations are based on the workflow functionality of FastGPT v4.17.0:

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Dynamic variable passing | Pass the tender batch number as the variables parameter | Match exclusive business data such as cotton blending and process data for the corresponding batch |
| Knowledge base association scope | Associate three exclusive knowledge bases: fiber inspection, process setup, and equipment operation | Cover the core business document types for this category to avoid missing critical data |
| Node timeout setting | 600 seconds | Longer response time is required for processing multi-batch inspection data and long document analysis |
| Document chunking configuration | Chunk at 500–800 characters, with an overlap length of 50 characters | Adapt retrieval accuracy and efficiency for single large-volume documents |

| nodeId orchestration order | Arrange in the order of data validation → document analysis → quotation generation → export | Follow business process logic, with pre-validation to avoid invalid output |

## Three Common Errors
- Symptom: The workflow fails to recognize document content after uploading a cotton blending list. Cause: The corresponding document was not bound to the knowledge base association node of the workflow, so the retrieval scope did not cover the uploaded file.
- Symptom: The AI does not return referenced business documents after dynamically passing knowledge base retrieval parameters. Cause: The batch parameter in variables was not correctly bound to the knowledge base retrieval condition of the workflow node, so business data for the corresponding batch cannot be located.
- Symptom: No download link is generated after the workflow completes execution. Cause: Public access permissions were not configured for the export node, so the generated file cannot be provided for external download.

## How to Confirm the Configuration is Properly Set Up
- Upload the cotton blending list for the corresponding batch, check if the workflow's knowledge base node successfully pulls and parses the document content.
- Pass a test batch number as the variables parameter, verify that the quotation content generated by the AI is associated with the fiber inspection data for that batch.
- Trigger workflow execution, check if a clickable Word download link is generated.
- View the workflow execution log, confirm that the execution status of all four nodes (data validation, document analysis, quotation generation, export) is successful.
