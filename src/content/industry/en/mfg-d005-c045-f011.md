# Tender Document and Quotation Preparation for Spinning and Weaving: Forms and Interactions

## What data for this category looks like
This category covers cotton spinning, chemical fiber spinning, woven, and knitting enterprises. Daily documents include cotton blending or material batching lists, process setup sheets, equipment operation records, yarn inspection reports, grey fabric inspection reports, and defect records. Data sources cover raw fiber inspection data, ERP systems, spinning and loom operation data, evenness tester detection data, and fabric inspection machine detection data. Data updates occur once per batch of raw materials, per shift, and per piece of fabric. Core fields include fiber indicators, spinning twist, weaving structure parameters, defect types and grades, and similar items. There are no unified fixed general units, and professional measurement standards for each business link must be matched.

## What constraints do these characteristics impose on the "forms and interactions" link
Data for this category mostly comes from professional production equipment and inspection instruments, not manually entered scattered content. The forms and interactions link must support direct binding of multi-source structured data to avoid repeated manual input. Data updates are frequent, with new business data generated for each batch of raw materials, per shift, and per piece of fabric. Forms must support dynamic refresh of associated fields to ensure parameters in tender documents and quotations always match the latest production data. Daily documents are divided into multiple modules including cotton blending, process, inspection, and quotation. Forms must be divided into blocks according to business logic to improve filling and review efficiency. Core fields are mostly professional parameters, so preset standard options are needed to reduce manual input deviations. Custom supplementary notes must also be supported to match personalized requirements of different tender projects.

## Three common mistakes
- Phenomenon: When configuring DingTalk access, the prompt "Receiving message address verification failed" appears, and application release cannot be completed. Cause: FastGPT service is not deployed to a publicly accessible environment, or SSL certificate verification rules are not configured correctly.
- Phenomenon: After manually inserting audio and video tags in a specified reply node, the corresponding content cannot be displayed normally in the generated tender document. Cause: The rich text rendering switch is not enabled in FastGPT v4.17.0, or the tag format does not meet platform requirements.
- Phenomenon: When configuring model providers, it is not possible to select a locally deployed large model or a service provider not in the default list. Cause: The custom model access switch is not enabled in FastGPT v4.17.0, or the model call path is not configured correctly.

## How to confirm the configuration is complete
- Check whether the `formInput` field has been bound to the corresponding business data source, and confirm that the field name is exactly the same as that in ERP and inspection records.
- Test whether the options of the `userSelect` component cover the core parameters of spinning and weaving, and whether clicking any option can be normally filled into the corresponding position of the form.
- Simulate the filling process for a batch of raw materials, confirm that form block switching is smooth, data update triggers are timely, and there is no delay or loss.
- Export the test tender document, confirm that all configured fields are displayed correctly, no missing or formatting errors, and audio and video tags can be rendered normally.
