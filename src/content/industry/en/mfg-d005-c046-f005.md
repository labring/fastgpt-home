# Tender Document and Quotation Preparation for Meat Products and Slaughter Processing: Tool Calling and Plugins

## What the data for this category looks like
The main entities in this category are slaughterhouses, cooked meat and frozen prepared food enterprises. Daily documents include animal quarantine certificates, slaughter and cutting records, ingredient marinating records, thermal processing records, cold chain temperature records, and microbial test reports. Data sources include animal quarantine information, supplier batches, production traceability systems, temperature collection devices, metal detection devices, and laboratory test results. Data is updated per production batch, per shift, and through continuous temperature collection. Fields include batch number, quarantine number, processing temperature, cold chain duration, test results, and other items, with different units corresponding to different data types.

## Constraints Imposed on Tool Calling and Plugins by These Characteristics
Data for this category is updated per batch and shift, and includes biosecurity compliance-related quarantine and temperature control information. Tool calling must be bound to the unique identifier of the corresponding batch to avoid cross-batch data confusion. Continuously collected temperature control data has a large volume. Tool calling must support batch retrieval of time-series data to prevent context overflow. Tender documents and quotations must be strictly associated with compliance data. Plugins must verify the completeness of quarantine and test fields, otherwise compliance risks may arise. Data update frequency is high, so tool calling must support real-time retrieval of the latest production records to ensure the accuracy of document content.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | Automatically select tools suitable for tender document and quotation preparation, no manual specification of call type required |
| Single tool call limit | `top 3 entries` | The number of production-related documents per batch is limited, avoid calling excessive redundant data |
| Tool call timeout period | `120 seconds` | Need to retrieve quarantine certificates, multiple temperature control records, and test reports, which takes a long time |
| Plugin input field validation | `batch number required` | Tender documents must be associated with compliance data for the corresponding batch to ensure accurate traceability |
| Context window size | `8000–12000 token` | Need to embed multiple production records and compliance documents to avoid truncation of critical information |

## Common Mistakes to Avoid
- Phenomenon: Plugins cannot be triggered in the chat interface after configuration, and a 400 status code is returned. Cause: The plugin's schema file was not imported correctly, or the configuration path does not match the FastGPT plugin storage directory.
- Phenomenon: The generated tender document lacks the quarantine certificate number for the corresponding batch, and the field is empty. Cause: The batch number parameter was not bound during tool calling, and production records and quarantine information were not correctly associated.
- Phenomenon: Tool calling times out, and the request fails. Cause: The set timeout period is too short, and does not cover the time required to retrieve multiple cold chain temperature records and microbial test reports.

## How to Confirm Proper Configuration
- Upload quarantine certificates and production records for a single batch, trigger tool calling, and check whether the batch number and test data can be automatically extracted.
- Call the plugin to generate a test quotation snippet, and confirm that correct fields such as processing temperature and cold chain duration are embedded.
- View the FastGPT plugin log to confirm that each call correctly retrieves the production traceability data for the corresponding batch, with no missing fields.
- Adjust the `toolChoice` parameter to `none`, then change it back to `auto`, and confirm that the tool call trigger logic switches normally.

The values provided are common starting points and should be evaluated against the reader's own samples.
