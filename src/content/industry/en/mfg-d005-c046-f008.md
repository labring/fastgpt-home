# Tendering Document and Quotation Preparation for Meat Products and Slaughter Processing: Document Parsing and Chunking

## What Data for This Category Looks Like
The main daily documents generated by this category include quarantine certificates, slaughter and cutting records, ingredient marinating records, thermal processing records, cold chain temperature records, microbial test reports, and others. Data sources cover animal quarantine information, supplier batch ledgers, production traceability systems, temperature collection equipment, metal detection results, and laboratory test data. Document update frequency is per batch or per shift, with cold chain temperature records updated continuously in sequence. A single document often contains structured fields such as batch number, quarantine number, temperature value, test conclusion, as well as text descriptions of corresponding links. Some quarantine certificates and test reports have layouts with stamps or handwritten annotations.

## What Constraints These Characteristics Impose on the Document Parsing and Chunking Link
Documents for this category must be accurately associated with batch information. Chunking must not break up production records and quarantine certificate content from the same batch, otherwise this will affect the integrated display of batch compliance in tendering documents. Continuously updated cold chain temperature records have strict sequential logic, so chunking must retain the relevance of adjacent records, avoiding splitting that destroys the complete explanation of temperature changes. Some documents involve sensitive information related to biological safety, so parsing must fully retain field integrity, and must not miss core content such as quarantine numbers and test results. Tendering documents require integration of multiple types of production records, so chunking rules must adapt to the structure of different document types, ensuring that records from different links can be accurately extracted and classified.

## How to Set the Configuration
This configuration is based on FastGPT v4.17.0. Specific parameter settings are listed below:

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | This category of documents contains short structured fields and long paragraph descriptions. This range balances field integrity and chunk relevance |
| `chunkSplitter` | Chunk by paragraph + semantics | Cold chain and test records have sequential and link logic. Chunking by semantics can retain content relevance |
| `customPdfParse` | Enabled | Daily documents include PDFs with stamps and handwritten annotations. Enabling this improves parsing accuracy for special layouts |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 seconds | Single-batch documents may contain multiple records, and parsing time is longer than general scenarios |
| `chunkSettingMode` | Manual configuration | Chunking rules need to be adjusted for batch association fields to adapt to the integration needs of tendering documents |

## Three Common Errors
- Symptom: After uploading a stamped quarantine certificate PDF, the quarantine seal number field is empty in the parsing result. Cause: `customPdfParse` is not enabled. The basic parsing function cannot recognize special PDF layouts with stamps.
- Symptom: The number of results returned after calling the chunking interface does not match expectations. Single-batch production records are split into too many chunks. Cause: The value of `chunkSize` is too small, splitting the fully associated content of the same batch, leading to failure of batch association during tendering document integration.
- Symptom: A timeout error is triggered when parsing large cold chain record PDFs. Cause: The value of `PARSE_FILE_TIMEOUT_SECONDS` is lower than the actual parsing time, and does not adapt to the parsing needs of multi-page sequential documents for this category.

## How to Confirm the Configuration Is Correct
- Upload a single quarantine certificate PDF, check whether the parsing result includes core fields such as batch number, quarantine date, and test conclusion, to confirm that the `customPdfParse` configuration is effective.
- Import a set of production record documents from the same batch, check whether the chunking result retains the content relevance within a single batch, to confirm that the `chunkSplitter` configuration meets expectations.
- Upload a cold chain record document larger than 100MB, check whether the parsing task is completed within the set `PARSE_FILE_TIMEOUT_SECONDS`, to verify that the timeout configuration is reasonable.
- Call the chunking interface for testing, confirm that the number of returned chunks matches the document content length, to verify that the `chunkSize` configuration is correct.

The values provided here are common starting points and should be evaluated against relevant samples.
