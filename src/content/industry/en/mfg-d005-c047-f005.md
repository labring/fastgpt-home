# Bid Document and Quotation Preparation for Measuring Instruments and Laboratory Management: Tool Calling and Plugins

## What data looks like for this category
Data for this category comes from metrology management systems, external calibration institution certificates, reference standards, LIMS, and environmental monitoring equipment. Daily documents include gauge ledgers, calibration plans, calibration certificates, interim verification records, original test records, reference material ledgers, deviation disposition forms, and more. Fields include instrument identification, calibration parameters, measurement results, traceability information, environmental conditions, and others. Units vary based on the measured object, such as length, mass, pressure units, etc. Data updates are triggered by calibration cycles, each test, or abnormal situations, with no fixed unified update cycle.

## What constraints do these characteristics impose on the tool calling and plugin link
Dispersed data sources and diverse formats require tool calling to support integration with multiple types of data sources and parsing documents in different formats. There is no fixed cycle for data updates, so tool calling must adapt to on-demand triggering rhythms to avoid calling outdated or unupdated data. Documents include standardized calibration certificates and traceability chain information, so tools must accurately extract key fields such as uncertainty and instrument number. The most time-consuming manual links must be replaced by tool automation. Tool calling must cover core tasks such as traceability chain review and calibration result verification, and ensure the accuracy of data extraction to avoid compliance issues in subsequent bid documents caused by tool errors.

## Three common mistakes
- Phenomenon: Multiple metrology data extraction tools configured in the workflow do not execute in the expected sequence, and some tools have no calling logs. Cause: Serial execution dependencies for tools are not set correctly, or the parallel calling switch is not turned off.
- Phenomenon: Parsing failure is returned when calling the Playwright MCP service, while calls to other MCP services work normally. Cause: The local port configuration of the Playwright MCP service does not match the FastGPT plugin settings, or the DOM selector for calibration certificates does not adapt to industry standard formats.
- Phenomenon: The maker tool cannot be configured in the FastGPT knowledge base to extract metrology ledger data. Cause: The permission switch for the maker tool is not turned on correctly, or the data source connection parameters between the maker tool and the metrology management system are not configured.

## How to confirm the configuration is complete
- Initiate a simulated call, pass in typical documents such as calibration certificates and gauge ledgers, and check if the returned tool calling parameters include the required key fields.
- View the tool calling logs to confirm that all configured tools execute in the expected order, with no omissions or skips.
- Verify the data source synchronization results, and compare the consistency of fields between the pulled metrology data and local LIMS and external calibration institution certificates.
- Test abnormal scenarios, pass in incorrectly formatted calibration certificates, and check if the tool returns clear error prompts.

The values given are common starting points and should be measured against the reader's own samples.
