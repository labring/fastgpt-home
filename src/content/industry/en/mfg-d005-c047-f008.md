# Bid Document and Quotation Preparation for Measuring Instruments and Laboratory Management: Document Parsing and Chunking

## What Data for This Category Looks Like
Daily documents for this category include gauge ledgers, calibration plans, calibration certificates, periodic verification records, original test records, reference material ledgers, and deviation handling documents. Data sources cover enterprise metrology management systems, external calibration institution certificates, LIMS systems, and environmental monitoring equipment. Most documents have fixed headers and legal units of measurement. Updates occur based on calibration cycles, completion of single tests, or abnormal situations. Some traceability documents require linking to multiple historical records, with clear hierarchical titles and associated fields in their structure.

## Constraints Imposed by These Characteristics on Document Parsing and Chunking
Chunking logic must adapt to documents with fixed headers and diverse formats from different institutions, to avoid splitting traceability-related content across titles. Retain contextual associations during chunking to prevent ambiguity caused by separating legal units of measurement and precise numerical values from their corresponding content. Parsing logic must support batch uploads and large single documents to accommodate irregular update triggers and multi-source data imports. Preserve all associated fields for traceability chain documents, and do not break the binding relationship between instrument IDs, calibration dates, and measurement results during chunking.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | `800–1200 characters` | Core paragraphs of calibration certificates and test records mostly fall within this range, and can fully retain associated information such as traceability chains and measurement results |
| `chunkSplitter` | Split by title and paragraph boundaries | Daily documents have clear hierarchical titles, which avoids splitting associated content across titles, such as results and uncertainty analysis under the same calibration project |
| `customPdfParse` | Enabled | Adapts to the diverse PDF certificate formats of external calibration institutions, and extracts embedded text and necessary image description content |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300–600 seconds` | When large gauge ledgers or multiple calibration certificates are uploaded in batches, parsing takes a long time. This setting prevents parsing from being interrupted by timeouts |
| `chunkSettingMode` | Manual configuration | Allows adjustment of chunking boundary rules for specific business fields such as traceability chains and uncertainty analysis, to adapt to the document characteristics of this category |

## Three Common Misconfigurations
- Symptom: After uploading a document using the chunk mode pushdata API, indexing is displayed for a long time. Cause: `PARSE_FILE_TIMEOUT_SECONDS` is not configured to a reasonable duration, or `chunkSize` is set too small resulting in an excessive number of chunks, causing system overload and failed parsing.
- Symptom: After uploading a PDF calibration certificate, embedded images are not parsed and no corresponding descriptions appear in search results. Cause: The image extraction logic for `customPdfParse` is not enabled. The default parsing rule only extracts plain text content.
- Symptom: Uploading HTML interface documents generated by Javadoc results in no valid parsing output. Cause: Chunking rules based on HTML tag hierarchy are not specified, and the system cannot identify valid text blocks within nested structures.

## How to Confirm Proper Configuration
- Upload a single typical calibration certificate document, check the chunk preview interface in the knowledge base, and confirm that core fields such as traceability chains and measurement results are not split across chunks.
- Upload a large gauge ledger document under 10MB, check system logs or interface prompts, and confirm that parsing time does not exceed the preset `PARSE_FILE_TIMEOUT_SECONDS` range, with no timeout errors.
- Upload a PDF calibration report containing embedded images, verify that search results display the corresponding text descriptions and associated measurement data for the images.
- Test calling the chunk mode pushdata API, and confirm that the returned chunk data contains complete required business fields such as measuring instrument IDs and calibration dates.

The values provided are common starting points and should be measured against the reader's own samples.
