# Bid Document and Quotation Preparation for Measuring Instruments and Laboratory Management: Deployment and Upgrade

## What Data This Category Entails
Data for this category comes from enterprise metrology rooms, CNAS-accredited laboratory metrology management systems, external calibration institution certificates, LIMS systems, and environmental monitoring equipment. Daily generated documents include measuring tool ledgers, calibration plans, calibration certificates, interim verification records, original test records, reference material ledgers, and deviation handling documents. Data is updated based on calibration cycles, single test results, or abnormal events. It includes fields such as measured values, uncertainty, traceability numbers, instrument numbers, and requires association with traceability chains and product batch information.

## Constraints Imposed by These Characteristics on Deployment and Upgrade
Data sources for this category are scattered. Configure storage and synchronization parameters for multi-source data docking during deployment to ensure complete import of documents such as calibration certificates and ledgers. Adjust data synchronization trigger logic as update frequency fluctuates with calibration cycles and abnormal events, to avoid redundant updates or data lag. Associate documents with traceability chains and measurement uncertainty. Reserve configuration items for field verification and associated storage during deployment. Adapt indexing rules for long-text certificates during upgrades. Configure precise retrieval parameters for the knowledge base to ensure retrieval results match business requirements, as bid documents require precise reference to fields such as traceability numbers. This configuration is compatible with FastGPT v4.17.0.

## Configuration Recommendations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:27017/metrology_db?authSource=admin` | Stores multiple types of metrology documents such as calibration certificates and ledgers, and is compatible with JSON-structured business data |
| `REDIS_URL` | `redis://:securepass@host:6379/0` | Caches real-time calibration data and traceability chain association information, supporting low-latency read and write operations |
| `STORAGE_S3_ENDPOINT` | `https://oss-cn-beijing.aliyuncs.com` | Stores large-volume calibration certificates and original test records, and is compatible with S3-compatible file storage services |
| `DB_MAX_LINK` | `100–150 connections` | Handles status synchronization requests for multiple measuring instruments concurrently, limiting database connection count to avoid resource exhaustion |
| `FILE_TOKEN_KEY` | `32-character random string` | Generates temporary access tokens for calibration certificate downloads, ensuring token security |
| `FE_DOMAIN` | `192.168.1.100:3000` or public domain name | Configures the access address for the frontend page, ensuring links in bid document attachments are accessible normally |

## Three Common Mistakes
- Symptom: A database connection failure prompt appears after starting the container, with logs showing `connection refused`. Cause: The username, password, and port parameters for `MONGODB_URI` or `PG_URL` are not configured correctly, making it impossible to connect to the metrology data storage repository.
- Symptom: No matching results or empty results are returned when searching for calibration certificates. Cause: A reasonable value for `DB_MAX_LINK` is not configured, resulting in insufficient database connections and failure to load full metrology document indexes.
- Symptom: Knowledge base response latency is high after cloud deployment. Cause: The cache expiration time for `REDIS_URL` is not adjusted based on the update frequency of metrology data, resulting in frequent reads from the database to obtain real-time calibration data and increased link overhead.

## How to Confirm Successful Configuration
- Run container health check commands to confirm that database and cache service connection statuses are normal, with no `connection refused` errors.
- Upload a standard calibration certificate document to verify that index generation and retrieval functions work normally, and that corresponding records can be matched precisely using the traceability number.
- Configure a temporary webhook test address to trigger a metrology data synchronization task, confirming that documents and field information are fully imported into the knowledge base.
- Access the frontend page's configuration interface to verify that the `FE_DOMAIN` configuration can normally load attachment links, with no cross-domain or access failure issues.

The values provided are common starting points and should be measured against the reader's own samples.
