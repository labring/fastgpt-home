# Bid Document and Quotation Preparation for Equipment Inspection and Preventive Maintenance: Deployment and Upgrade

## What the data for this category looks like
The data sources for this category include EAM/CMMS systems, equipment sensor collection terminals, daily operator inspection records, historical maintenance work orders, spare parts inventory ledgers, and statutory special equipment inspection records. Daily generated documents include equipment ledgers, graded inspection checklists, shutdown maintenance plans, fault analysis reports, spare parts requisition lists, and special equipment inspection reports. Data update cycles cover shift-by-shift inspection submissions, daily/weekly maintenance plan distribution, real-time recording when faults occur, and monthly spare parts inventory count updates. Data fields include equipment number, inspection item, inspection cycle, spare parts model, inspection validity period, and other items, with corresponding units such as unit, time, day, piece, and others.

## What constraints these characteristics impose during deployment and upgrade
Multi-source heterogeneous data sources and differentiated update frequencies require that multi-data source synchronization rules be configured during the deployment phase to adapt to inspection documents and maintenance records in different formats. Diverse document structures require the system to support custom field parsing, ensuring that equipment parameters and spare parts lists in bid documents can accurately match the enterprise’s existing data. The compliance storage requirement for special equipment inspection records requires that the traceability of the storage service be verified during the upgrade phase. Additionally, bid quotation preparation needs to be associated with spare parts inventory and maintenance history, requiring stable database connections to avoid data reading failures caused by improper configuration, which would affect the accuracy of bid documents.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `10–15 connections` | Matches the concurrent access demand of equipment inspection data, adapts to the concurrent limit of EAM systems, and avoids connection pool exhaustion |
| `REDIS_URL` | `Local port 6379 default configuration` | Caches inspection records and temporary preview data of bid documents to reduce read/write pressure on the primary database |
| `STORAGE_S3_ENDPOINT` | `Fill in according to the enterprise’s own storage service address` | Stores compliance documents such as special equipment inspection records to ensure data traceability and compliant access |
| `FE_DOMAIN` | `Enterprise external access domain name or public network IP` | Supports external preview and sharing of bid documents to meet collaboration needs during the bidding process |
| `FILE_TOKEN_KEY` | `Calibrate according to actual measurements` | Generates temporary access tokens for document sharing to prevent unauthorized personnel from viewing confidential equipment maintenance data |

## Three Common Mistakes
- The symptom is that after deployment, the service is accessible via the local 127.0.0.1 address, but not via the external IP and port. The cause is that `FE_DOMAIN` is configured as a local loopback address, and not set to an externally exposed domain name or IP.
- The symptom is that after upgrade, the version number displayed on the homepage does not match the actual installed version, and the knowledge base cannot load normally. The cause is that the cache directory and environment variables of the old version were not cleared during the upgrade process, and residual configurations cause version verification exceptions.
- The symptom is that after clicking the knowledge base module, an error with empty fields is returned, and inspection-related documents cannot be retrieved. The cause is that the `DB_MAX_LINK` configuration value is too small, and the database connection pool cannot support concurrent read requests for multiple equipment ledgers.

## How to Verify Proper Configuration
- Access the configured `FE_DOMAIN` address, confirm that the bid document preview page loads normally, with no loading failure prompts.
- Check the FastGPT v4.17.0 service console log, confirm that the active connection count of the database connection pool does not exceed the `DB_MAX_LINK` configuration value, with no connection timeout errors.
- Upload a standard inspection checklist document, confirm that the system can automatically parse the equipment number and inspection items in the document and associate them with the imported equipment ledger data.
- Restart the FastGPT v4.17.0 service, check the connection status of `REDIS_URL`, confirm that the cache service starts normally, with no connection failure logs.
