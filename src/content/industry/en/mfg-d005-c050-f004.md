# Bid Document and Quotation Preparation for General Mechanical Equipment Assembly: Workflow Orchestration

This document was written for FastGPT v4.17.0.

## What Data Looks Like for This Category
Daily data for the general mechanical equipment assembly category originates primarily from PLM/ERP systems, part inspection data, assembly tool collection systems, test benches, MES, and customer technical agreements. Update frequency is once per equipment unit or per order. Common associated documents include assembly process cards, BOMs, torque records, gap adjustment records, commissioning reports, factory inspection certificates, and packing lists. Data fields include material codes, torque values (unit N·m), gap values (unit mm), inspection results, and others. The data structure changes dynamically based on orders and assembly models.

## Constraints on Workflow Orchestration
Decentralized and dynamically updated data sources require workflows to support connection to multiple data source nodes and real-time pulling of latest BOMs, inspection records, and other data. The multi-variety order-based assembly feature requires workflows to support parameterized template calls to adapt to bidding requirements for different equipment models. Highly specialized document fields require workflows to configure field extraction rules to ensure technical parameters in bid documents match actual assembly data. Independent assembly data for each equipment unit requires workflows to isolate data by order dimension to avoid mixing parameters from different orders.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Variable Binding Rule | Automatically map the `variables` field according to the BOM and process card associated with the order | Matches the dynamic update characteristics of category data to ensure real-time and accurate bidding data |
| Timeout Threshold | 600 seconds | Covers the average response time of connecting multiple data sources such as PLM and MES |
| Knowledge Base Recall Count | Top 8 entries | Adapts to the information density of assembly-related documents and avoids interference from redundant data |
| Text Formatting Length | 800–1200 characters | Adapts to the typesetting requirements of bid documents and ensures compact and standardized content |
| MCP Service Input Parameter Configuration | Bind the `variables` field from HTTP responses | Matches the structured characteristics of category data to ensure accurate input parameters |
| Workflow Trigger Node | Trigger according to the assembly process node bound by `nodeId` | Adapts to the process-based assembly flow of the category and standardizes the tool call sequence |
| Export Configuration | Name files using order number + assembly model | Complies with the archiving requirements of bid documents and facilitates subsequent retrieval |

## Three Common Misconfigurations
- Symptom: Workflow output uses the `array<object>` format and cannot directly generate natural language paragraphs for bid documents. Cause: No format conversion node is configured to convert structured `variables` data into text format compliant with bidding requirements.
- Symptom: Unable to add input parameter variables from HTTP responses when configuring MCP services. Cause: No field mapping rules for input parameters are declared in the workflow's `variables` configuration in advance, resulting in variables not being recognized.
- Symptom: The split logic between knowledge base calls and MCP service calls fails. Cause: No trigger conditions are configured according to process nodes, leading to disordered tool call sequences and affecting the accuracy of bid documents and quotations.

## How to Confirm Proper Configuration
- Trigger a test workflow and check whether the `variables` field correctly binds the BOM, torque records, and other data for the current order.
- Call the configured MCP service and verify that the input parameter variables from the HTTP response can be properly read and used by the workflow.
- Export the workflow configuration file and check whether all associated data source nodes and tool nodes have been correctly selected.
- Trigger the split logic and verify that knowledge base calls and MCP service calls execute in the preset assembly process node sequence.
