# Bid Document and Quotation Preparation for General Mechanical Equipment Assembly: Model Access and Configuration

This configuration guide is based on FastGPT v4.17.0.

## What Data Looks Like for This Category
Daily documents for the general mechanical equipment assembly category include assembly process cards, BOMs, torque records, clearance adjustment records, commissioning reports, factory inspection sheets, and packing lists. Data sources cover PLM/ERP systems, part inspection data, assembly tool collection equipment, test benches, MES systems, and customer technical agreements. Data updates follow a cycle per single device or individual order. Each document contains fields with clear units, such as material codes, torque values, clearance values, and inspection results. The structure includes two categories: structured lists and unstructured test records.

## Constraints on Model Access and Configuration
Dispersed multi-source data sources require the model access link to support cross-system data pulling and unified field mapping. This prevents technical parameter mismatches in bid documents caused by data format differences. Updates per single device or order mean latest assembly data must be synced in real time before each bid. Do not use expired cached data. Mixed document types require the model to handle both structured BOM data and unstructured test reports. This ensures generated bid content follows standard formats and accurately reflects actual assembly performance metrics of the equipment.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | This category’s assembly documents include multiple long BOMs, process cards, and test reports. Sufficient context capacity is needed to ensure accurate parameter verification. |
| `temperature` | `0.2–0.4` | Bid documents and quotations require consistent rigor. A lower temperature parameter reduces randomness in generated content, avoiding deviations that do not match actual assembly data. |
| `maxTokens` | `2000–3000 token` | Controls the length of a single bid document or quotation entry, adapting to standard paragraph formatting requirements for typical bid documents. |
| `toolChoice` | `auto` | Allows the model to independently determine whether to call tools to verify assembly parameters, ensuring consistency between bid content and actual production data. |
| `AIPROXY_API_ENDPOINT` | `Private enterprise-deployed proxy address` | Ensures transmission security for sensitive data such as assembly processes and customer technical agreements, preventing data leaks. |
| `AIPROXY_API_TOKEN` | `Enterprise-specific encrypted token` | Verifies interface call permissions, preventing unauthorized access to sensitive assembly and quotation data. |

## Three Common Configuration Mistakes
- Phenomenon: Knowledge base search returns non-standard JSON format that cannot be parsed normally by AI. Cause: Unified field mapping rules are not configured. Multi-source assembly data is exported directly without a unified format, resulting in chaotic returned structures.
- Phenomenon: Call conflicts occur when mixing different types of index models. Cause: Unified model routing rules are not configured, and the model type suited for assembly data processing is not clearly specified, leading to disordered model calls.
- Phenomenon: Tool calls do not select the intended parameter verification tool as expected. Cause: The `toolChoice` parameter is not set correctly, or the prompt does not specify that technical parameters related to assembly must be prioritized for verification, leading the model to select the wrong tool.

## How to Confirm Successful Configuration
- Pull the complete BOM, assembly records, and customer technical agreement for a single device. Input the configured model to generate the technical parameter section of the bid document. Verify that the generated content matches the fields in the original data.
- Call the configured interface to submit test data. Check that the returned content format meets preset structured requirements, with no abnormal errors.
- Adjust the `temperature` parameter to different ranges. Compare the rigor of the generated quotation text to confirm it meets business requirements for content accuracy.
- Test the multi-source data access process. Verify that BOM data from the PLM system and assembly torque data from the MES system can be read simultaneously, generating aligned bid content.
