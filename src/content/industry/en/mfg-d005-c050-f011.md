# Tender Document and Quotation Preparation for General Mechanical Equipment Assembly: Forms and Interactions

## What data for this category looks like
Typically, the main entities in the general mechanical equipment assembly category are manufacturers of pumps, valves, compressors, reducers, machine tools and non-standard equipment. Daily processed documents include assembly process cards, BOMs, torque records, clearance adjustment records, commissioning reports, factory inspection certificates, and packing lists. Data generally comes from PLM/ERP systems, part inspection data, data collected via assembly tools, test benches, MES systems, and customer technical agreements. The update frequency is once per equipment unit or per order. Fields include material codes, torque values (unit: newton meters), clearance values (unit: millimeters), coaxiality parameters, and others. Document structure varies significantly based on order type.

## What constraints these characteristics impose on the "forms and interactions" link
Data for this category comes from multiple dispersed sources and has a high update frequency. This requires form interactions to support real-time pulling and dynamic refreshing of multi-source data. The multi-level BOM structure creates a large number of input fields, so grouping, folding and similar interactions are needed to reduce filling complexity. Fields include physical parameters with units, so format validation must be configured to prevent incorrect entry of values or units. The characteristic of assembling multiple varieties according to orders requires forms to support custom fields to adapt to the special needs of different orders. At the same time, the accuracy of tender documents and quotation preparation is directly linked to on-site installation results, so the interaction link requires strict required field validation and data traceability capabilities.

## How to set the configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `formInput` | Enable multi-line input, limit input length to 800–1200 characters | Adapt to the entry of long-text content such as assembly process cards and BOMs |
| `userSelect` | Enable multi-option linkage, bind equipment type labels such as pumps, valves, compressors | Adapt to the scenario of assembling multiple varieties according to orders, quickly filter input fields corresponding to the category |
| Form field grouping | Split groups according to assembly processes | Match the hierarchical structure of multi-level BOMs, reduce the complexity of filling out forms |
| Data source binding | Associate with real-time interfaces of PLM/ERP systems | Ensure that data such as BOMs, torque records, and clearance adjustment records are synchronized with the production end |
| Submission verification rules | Enable required field verification and numerical format verification, set timeout to 600 seconds | Avoid missing or incorrectly filling key parameters, adapt to the waiting time for pulling data from multiple data sources |
| Knowledge base association | Bind the knowledge base of the corresponding equipment category | Support quick access to assembly standard documents and inspection specifications during bidding |

## Three common mistakes
- Phenomenon: When uploading files such as assembly process cards and packing lists, the interface prompts that the file type is not supported, or the field is empty after the file is uploaded. Cause: The file upload permission configuration of the form is not enabled, only the `formInput` function for plain text input is activated.
- Phenomenon: After selecting the knowledge base according to the bidding equipment type, no assembly document results for the corresponding category are returned. Cause: The linkage logic of `userSelect` is not configured, and equipment type labels are not mapped to the corresponding knowledge bases.
- Phenomenon: After submitting the form, the interface returns a parameter mismatch, and the BOM data of the corresponding order cannot be pulled. Cause: The field mapping for data source binding is not correctly configured, and the order number entered in the form is not passed as a query parameter to the PLM/ERP interface.

## How to confirm the configuration is complete
- Enter the test pump equipment type label, check whether `userSelect` triggers the association of the corresponding knowledge base, and confirm that the returned document list matches pump assembly standards.
- Upload a simulated assembly process card file, check whether the form normally receives and displays the file name and size, and confirm that the file upload configuration for `formInput` takes effect.
- Enter the test order number, check whether the data source binding pulls the corresponding BOM data, confirm that the field mapping configuration is correct, and fields such as material codes are normally displayed.
- Submit the test form, wait no more than 600 seconds, confirm that the submission is successful with no errors, and verify that the timeout setting meets expectations.

The values given are common starting points and should be measured against the reader's own samples.
