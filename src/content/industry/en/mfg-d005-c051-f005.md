# Tender Document and Quotation Preparation for Metal Cutting Machining: Tool Calling and Plugins

## What Data for This Category Looks Like
Data for this category originates from product drawings and 3D models, CAPP/CAM systems, machine tool collection systems, tool management systems, MES, and measuring and inspection tool data.
Daily documentation covers process routes, operation cards, tool lists, CNC programs, first-piece inspection records, patrol inspection forms, and measuring tool calibration records.
Data updates are triggered per work order, single-piece machining, sampling inspection, or tool replacement. Included fields are tool model, cutting parameters, dimensional tolerances, inspection results, and similar items. Corresponding units include rotational speed r/min, feed rate mm/r, tolerance mm, and other standard units.

## Constraints Imposed on Tool Calling and Plugins Workflow
Data for this category has dispersed sources and varied formats. Tool calling must adapt to multiple system interfaces and multi-type document parsing to ensure accurate retrieval of process routes, tool lists, and similar data.
Data updates are triggered frequently by work orders, tool replacements, and similar events. Tools must support on-demand data synchronization to avoid using expired cutting parameters or inspection records.
Fields include clear attached units. Tool calling must automatically match unit rules to prevent unit deviations in quotation calculations.
Tender documents require integration of multi-dimensional data. Plugins must support automatic field extraction to generate standardized process descriptions and cost breakdown entries.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `functionCall` | Enabled and bound to a dedicated tool group | Tender quotation for metal cutting machining requires calling structured data such as tool lists and process parameters. `functionCall` supports precise binding and calling of specified tools |
| Tool call timeout | 600 seconds | Retrieving machine tool data and parsing CNC programs may take a long time. 600 seconds covers most conventional scenarios, and can be adjusted based on actual testing |
| Number of returned entries per single tool call | Top 3 entries | Tender quotation only requires core data such as latest tool life and process working hours. Excessive entries increase context redundancy |
| `toolChoice` | auto | Tool calling must select corresponding tools based on different modules of the tender document. Auto mode adapts to multi-scenario calling requirements |
| Tool parameter validation switch | Enabled | Cutting parameters and tolerance values must comply with industry standards. Validation prevents invalid data from entering quotation calculations |
| Context splicing length | 800–1200 characters | The process description module of tender documents must retain key parameters. Excessive length interferes with intent recognition for tool calling |

## Three Common Misconfiguration Scenarios
- Symptom: Tool calling returns the "function call not supported" error. Cause: The large model service in use does not properly support the `functionCall` format, or the corresponding tool calling permission is not enabled.
- Symptom: Retrieved tool list data is missing life parameters. Cause: The tool did not properly bind the field mapping for the tool management system, and did not extract tool life data with units of minutes.
- Symptom: Tool calling times out, returning a "request timed out" prompt. Cause: The tool call timeout setting is too short, and does not cover the time required for machine tool data retrieval or complex CNC program parsing.

## How to Verify Successful Configuration
- Submit a test query specifying the generation of process cost breakdowns for tender use. Verify that the tool automatically calls the bound dedicated tool and returns matching structured data.
- Review tool call logs to confirm that the `functionCall` trigger logic is working correctly, with no format error-related alerts.
- Simulate a long-duration tool call scenario. Verify that the timeout threshold matches the actual processing pace of the current business.
- Input a query containing cutting parameters. Verify that the tool automatically validates the parameter format and returns results compliant with industry standards.

The values provided are common starting points and should be evaluated against the user’s own samples.
