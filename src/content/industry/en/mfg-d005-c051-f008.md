# Tender Document and Quotation Preparation for Metal Cutting Machining: Document Parsing and Chunking

## What the Data for This Category Looks Like
The data for metal cutting machining bidding and quotation documents originates from product drawings and 3D models, CAPP/CAM systems, machine tool collection data, tool management systems, MES, and measurement and inspection tool records. Daily documents include process routes, operation cards, tool lists, CNC programs, first-piece inspection records, patrol inspection forms, and measuring tool calibration records. Data updates are triggered by work orders, individual workpieces, sampling batches, or tool changes. Documents contain professional fields such as tool diameter, working hours, and dimensional tolerances, with common units including millimeters, minutes, and microns.

## What Constraints Do These Characteristics Impose on the Document Parsing and Chunking Link
Metal cutting bidding documents have diverse formats, mixing text descriptions, CNC code, structured tables, and professional parameters. This requires parsing tools to support multi-format content. High-frequency work-order-level data updates demand chunking rules that can be flexibly adjusted to fit the complete process chain of a single work order. The presence of professional fields and units requires the parsing process to retain the semantic association of original data, preventing splitting that breaks the binding between process parameters and corresponding operations. Bidding documents often integrate multiple types of sub-files, so chunking must retain contextual associations between different documents to ensure that retrieval can link to corresponding tool lists and operation requirements.

## How to Configure Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Metal cutting documents include continuous process descriptions and code blocks. This range preserves the contextual association between operations and corresponding parameters |
| `chunkSplitter` | By paragraph + code block | Adapts to documents mixing text process descriptions and CNC program code, avoiding splitting code blocks and breaking logical integrity |
| `customPdfParse` | Enabled | Bidding documents often include process cards with tables and PDFs with embedded CNC program screenshots. Custom parsing preserves structured content |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Large CNC programs and bundled bidding documents with multi-process drawings may exceed the default limit. This setting fits most scenarios |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Parsing complex tool lists and multi-page process cards takes longer. This range avoids task timeout failures |
| `chunkSettingMode` | Manual configuration | Chunking rules need to be adjusted for different document types such as operation cards and tool lists. Manual configuration offers greater flexibility |

## Three Common Misconfigurations
- Issue: After uploading bidding documents in docx or Excel format, retrieval result accuracy is low, and professional fields such as tool diameter and working hours are empty. Cause: Custom parsing rules for metal cutting professional parameters are not configured, and the default parsing logic cannot identify and retain professional fields.
- Issue: After uploading a PDF document that includes operation diagrams or CNC program screenshots, embedded image content cannot be viewed. Cause: `customPdfParse` is not enabled, and the default PDF parsing ignores non-text embedded content.
- Issue: Parsing large bundled bidding documents triggers a timeout error, causing the task to fail. Cause: `PARSE_FILE_TIMEOUT_SECONDS` is not adjusted, and the default timeout period is insufficient for documents that include multi-page process cards and large CNC programs.

## How to Confirm Configurations Are Correct
- Upload a test document that includes an operation card and a tool list, and check whether the parsed text retains professional unit fields such as tool diameter and working hours.
- Upload a PDF document that includes CNC program code, and confirm that the code blocks in the parsed results are not split and maintain complete logical integrity.
- Upload a bundled bidding document larger than 200 MB, and confirm that the parsing task does not trigger a timeout error.
- Adjust the `chunkSize` parameter, compare retrieval results under different chunk lengths, and confirm that the chunk length fits the content density of the current document.

The values provided are common starting points and should be measured against the reader's own samples.
