# Tender Document and Quotation Preparation for Metal Cutting Machining: Model Access and Configuration

## What data for this category looks like
Data sources for metal cutting machining include product drawings and 3D models, CAPP/CAM systems, machine tool collection terminals, tool management systems, MES systems, and measurement and inspection tool calibration records. Data update frequency triggers per work order, per workpiece, per sampling batch, or when tools are replaced. Daily generated documents include process routes, operation cards, tool lists, CNC programs, first-piece inspection records, inspection sheets, and measurement tool calibration records. Fields cover tool model, cutting speed, feed rate, process dimension tolerances, machine tool number, and more. Common units are millimeters, revolutions per minute, millimeters per tooth, and similar units.

## What constraints these characteristics impose on the model access and configuration link
Data is scattered across multiple heterogeneous systems. Access rules for multi-source data must be configured to ensure that process, tool, and machine tool data from different systems can be synchronized to the knowledge base. The high update frequency requires the vector database update strategy to match trigger nodes such as work orders and tool changes, to avoid recalling outdated data. Documents include structured process parameters, unstructured CNC programs, and 3D model screenshots, so support for mixed-format content parsing is needed. Additionally, process data for metal cutting machining is highly correlated; a parameter change in a single process will affect the overall quotation, so the rigor of model output has high requirements.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Process documents and CNC programs for metal cutting machining are lengthy. This range ensures that core content such as related processes and tool parameters is fully recalled, avoiding truncation of critical information |
| `maxTokens` | 4000–6000 token | Tender quotation documents need to include complete process descriptions, quotation details, and compliance descriptions. This value range ensures that output content is complete without truncation |
| `quoteMaxToken` | 2000 token | Complete fragments of core documents such as the quoted process route and tool list must be retained, ensuring that quotation basis is traceable |
| Workflow/API tool selection | `auto` | Can automatically call appropriate processing logic to generate documents based on different types of input content such as drawings, operation cards, and CNC programs |
| `temperature` | 0.2–0.4 | Tender documents require rigor and accuracy. This value range reduces the probability that the model will generate content that deviates from actual process parameters |
| `AIPROXY_API_ENDPOINT` | Fill in the access address according to the actual deployment environment | Ensure normal model call link, and comply with the proxy access specification of FastGPT v4.17.0 |
| `AIPROXY_API_TOKEN` | Fill in a valid token according to the authorization configuration | Verify the permission for model calls, ensuring that service calls are legal and valid |

## Three common errors
- Phenomenon: The model call returns a 503 status code. The one API link test is normal, but the current group call fails. Cause: `AIPROXY_API_TOKEN` is configured incorrectly, or the service node load is too high, preventing normal connection establishment.
- Phenomenon: Recalled process data has fragment truncation, and key process parameters are missing from the quotation document. Cause: The `maxContext` value is too small, failing to fully recall relevant content such as process routes and tool lists.
- Phenomenon: The generated quotation parameters do not match the actual process, with unreasonable cutting speeds or feed rates. Cause: The `temperature` value is too high, causing the model to generate content that deviates from actual metal cutting process requirements.

## How to confirm configuration is complete
- Test the connectivity between `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`, confirming that a normal response format is returned.
- Upload a complete operation card and tool list, check the completeness of recalled content, and confirm that no key fields or parameters are missing.
- Generate a simulated tender quotation document, verify that the output process parameters match the uploaded document content, and adjust `temperature` to the appropriate range.
- Test uploading CNC programs or 3D model screenshots, confirming that the model can identify and extract relevant cutting parameters and process requirements.

The values provided are common starting points and should be measured against the reader's own samples.
