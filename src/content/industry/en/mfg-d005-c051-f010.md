# Tender Document and Quotation Preparation for Metal Cutting Machining: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Data for this category comes from product drawings and 3D models, CAPP/CAM systems, machine tool collection terminals, tool management systems, MES, and measurement and inspection tool data. Daily documents include process routes, operation cards, tool lists, CNC programs, first-piece inspection records, patrol inspection forms, and measuring tool calibration records. CNC programs contain G-code, spindle speed, and feed rate parameters. Tool lists mark model, number of cutting edges, and service life, with units mostly millimeters, revolutions per minute, and millimeters per minute. Data updates are triggered by work orders, single-piece machining, spot checks, and tool changes, with no fixed cycle.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link
This category’s data includes structured lists, semi-structured programs, and unstructured records. The mixed-format data source requires the retrieval module to support cross-type recall. Data updates are triggered by work orders, tool changes, and spot checks, with no fixed cycle. Incremental synchronization must be supported to avoid recalling expired tool life and process parameters. Tender quotations require precise matching of process benchmarks, clamping schemes, and CNC programs. Retrieval results must link to process data for the corresponding production batch to avoid mixing parameters across batches. Professional fields use units such as millimeters and revolutions per minute. Retrieval must retain unit matching logic to prevent quotation deviations from parameter misalignment.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the professional parameter precision requirements for metal cutting machining, avoids recalling low-relevance process data |
| `limit` | Top 8 entries | Controls the number of single-recall results, adapts to the compact layout requirements of tender documents, avoids excessive redundant information |
| `searchMode` | Exact match first | Prioritizes returning fully matched results for precise fields such as CNC programs and tool models |
| `usingReRank` | Enabled | Re-ranks recall results by business relevance, prioritizes displaying core tender parameters such as benchmark clamping and tool life |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands queries based on tender requirements, supplements associated process cards and patrol inspection record data |
| `collectionIds` | Specified by business module grouping | Only retrieves knowledge base collections related to processes, tools, and quality inspection, excludes unrelated equipment maintenance data |

## Three Common Mistakes
- The knowledge base search module returns empty variable reference fields. The symptom is that after calling the retrieval interface, fields such as returned tool models and process parameters are not correctly assigned. The cause is that structured tool list and process card datasets are not configured as the target collection for variable recall, and only unstructured text data is retrieved.
- After uploading a CSV-format tool list, it cannot be directly reused via the template import function. The symptom is that the template import interface cannot recognize the uploaded CSV file. The cause is confusion between the applicable scenarios of text datasets and template imports. Template imports require matching a preset field structure, while CSV uploads must first be converted to a standardized dataset format.
- Unable to locate the storage location of knowledge base chunking and vectorization. The symptom is that the storage directory for vector data cannot be found in the system backend. The cause is lack of understanding of the default storage logic of FastGPT v4.17.0. The storage path of the built-in vector library does not require manual configuration, and only the status of associated knowledge base collections needs to be viewed via the dataset management interface.

## How to Confirm the Configuration Is Correct
- Initiate a simulated tender query, input "Benchmark clamping scheme and tool list for a specific workpiece model", and verify that the returned results include structured data of process cards and tool lists.
- Upload updated tool life data, trigger knowledge base synchronization, and verify that the returned tool life parameters are the latest version after retrieval.
- Check the `similarity` parameter range of the retrieval configuration, and confirm that it covers the professional parameter matching accuracy requirements of the current category.
- View the retrieval log, and confirm that only knowledge base data within the specified `collectionIds` range is recalled, with no results from unrelated datasets.
