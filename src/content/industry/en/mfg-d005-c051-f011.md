# Bid Document and Quotation Preparation for Metal Cutting Machining: Forms and Interactions

## What this category's data looks like
Bid-related data for metal cutting machining comes from product drawings and 3D models, CAPP/CAM systems, machine tool collection data, tool management systems, MES, and measurement and inspection tool records. Data updates are triggered by work orders, individual workpieces, spot checks, or tool changes. Covered documents include process routes, operation cards, tool lists, CNC programs, and first-piece inspection records. Fields include tool model, cutting speed, feed rate, operation man-hours, dimensional tolerances, and more. Common units are mm, r/min, mm/min, and pieces.

## Constraints for forms and interactions
Data sources are scattered and updates occur frequently. Forms must support real-time pulling of the latest data from business systems, and fixed initial values must not be used. Multiple document types correspond to complex fields, so form modules must be split by process nodes to avoid mixing fields. Fields such as tolerances and cutting parameters must align with industry process specifications, so strict input validation rules must be configured. Bidding scenarios require prioritizing display of mature solutions, so drop-down data sources for common options must be preset to reduce manual input.

## Three common configuration mistakes
- Phenomenon: Form fields always display default empty values and cannot load preset tool lists from business systems. Cause: Data source interfaces for tool management systems and MES are not bound, and only fixed initial values are configured.
- Phenomenon: After modifying tool parameters for a test work order, the cutting speed options in the form are not updated synchronously. Cause: Real-time refresh trigger rules for `userSelect` are not configured, and data is only pulled once when the page loads.
- Phenomenon: After the GPT outputs a recommended process solution, the corresponding clamping solution form is not automatically displayed. Cause: Conditional branch trigger rules based on GPT output results are not configured, so the display logic between output content and form fields cannot be associated.

## How to verify correct configuration
- Import test work order data, check whether form fields automatically load corresponding tool list and process route content.
- Modify tool parameters for the test work order, confirm that cutting speed and feed rate options in the form are updated synchronously.
- Enter a tolerance value that exceeds 0.001mm precision, confirm that a validation prompt is triggered.
- Configure conditional branch rules, enter specific cutting parameters, confirm that corresponding form fields are displayed or hidden.

The values provided here are common starting points and should be validated against in-house samples.
