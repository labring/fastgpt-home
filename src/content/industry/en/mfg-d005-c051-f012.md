# Bid Documentation and Quotation Preparation for Metal Cutting Machining: Deployment and Upgrade

## What this category of data looks like
This category of data comes from product drawings and 3D models, CAPP/CAM systems, machine tool collection data, tool management systems, MES systems, and measurement and inspection tool records. Daily documents include process routes, operation cards, tool lists, CNC programs, first-piece inspection records, patrol inspection forms, and measuring tool calibration records. Data is updated per work order, per workpiece, per sampling batch, or at tool replacement nodes. Fields include tool model, cutting linear speed, process dimensional tolerance, machine tool number, and others. Units are mostly millimeters, revolutions per minute, and meters per minute.

## What constraints these characteristics impose during deployment and upgrade
The multi-source heterogeneous data characteristics of this category require the deployment phase to support import and parsing of multi-format files such as CNC programs, process spreadsheets, and 3D models. Storage and indexing rules adapted to multiple types of data sources must be configured. High-frequency updated work order-level data requires stable database and cache connections to be configured during deployment, to avoid data synchronization delays that affect quotation preparation efficiency. Bid documentation needs to be associated with accurate process parameters and cost data. The deployment phase must reserve interface connection paths with internal CAPP and tool management systems, to ensure data traceability. During upgrades, compatibility with format migration of existing work order data is required, to avoid interrupting the existing quotation preparation workflow.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `20–30 connections` | This category of data is updated at high frequency per work order. A stable database connection pool must be maintained to avoid quotation generation interruptions caused by exhausted connections |
| `REDIS_URL` | Local Redis instance address, configured with independent password authentication | Used to cache frequently called tool parameters and process route data, reducing delays from repeated queries to internal systems |
| `FILE_TOKEN_KEY` | Randomly generated 32-bit string | Used to sign access tokens for uploaded files, preventing unauthorized access to sensitive business files such as process drawings and CNC programs |
| `STORAGE_S3_ENDPOINT` | Internal object storage service address | Used to store batch-imported process documents and bid attachments, adapting to long-term storage needs for multi-format files |
| `FE_DOMAIN` | Public IP of the deployment server plus port `3000` | Used to configure the frontend access address, ensuring workflow nodes can normally call backend interfaces to complete file processing |

## Three Common Configuration Mistakes
- When using an HTTP request node in a workflow to upload files, a 401 status code is returned. The symptom is that files are not successfully stored in the backend storage. The cause is failure to use a token matching `FILE_TOKEN_KEY` to sign the request header, resulting in interface authentication failure.
- An enabled and configured model does not appear in the workflow optional list. The symptom is an empty model list. The cause is incorrect configuration of `REDIS_URL`, resulting in failure to synchronize model configuration cache to the workflow engine. This issue requires attention to configuration verification in FastGPT v4.17.0.
- Uploading a CNC program or 3D model triggers a file size limit error. The symptom is a 413 status code returned by the interface. The cause is failure to adjust the uploaded file size threshold in container startup parameters. The default limit cannot adapt to large-sized business files of this category.

## How to Verify Proper Configuration
- Submit a test work order containing a CNC program and process spreadsheet. Check whether the backend interface normally receives and stores the file, and returns a 200 status code.
- Load the configured model in the workflow editor, and confirm that the target model appears in the optional list.
- Access the public IP and port address configured for `FE_DOMAIN`, and verify that the frontend page can normally load and call backend interfaces.
- Upload a process drawing file larger than 2MB, and confirm that the interface can normally receive and store the file, with no size limit error.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
