# Bid Document and Quotation Preparation for Steel Rolling and Finishing: Tool Calling and Plugins

## What this category of data looks like
This category of data originates from slab or billet batches, heating furnaces, mill automation control systems, online thickness and width measurement systems, surface inspection systems, and MES. Data is synchronized in real time each time a coil or individual steel product is produced. Core documents include rolling plans, heating schedules, rolling regulations, plate shape and thickness records, surface quality reports, and quality certificates. Data fields include coil numbers, thickness tolerances (unit: mm), width (unit: mm), surface defect levels, batch association information, and more, supporting full-link traceability at the coil level.

## What constraints these characteristics impose on the "tool calling and plugins" link
Real-time coil-level updated data requires tool calling to support dynamic retrieval of process and quality inspection data for single or multiple batches, and cannot rely on static caching. Structured differences across multiple document types require plugins to adapt to splicing and format conversion of different fields, to avoid field misalignment in bid documents. Bidding requires integration of multi-dimensional rolling parameters. Workflows need to connect multiple data source tools, and an exception capture mechanism must be set up to address risks such as missing data, to avoid quotation deviations caused by errors in a single link.

## How to set configurations
The following configurations are based on FastGPT v4.17.0:
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Workflow/API tool selection | `auto` | Adapts to multi-tool calling scenarios, automatically matches rolling data query, quotation calculation, and document generation plugins |
| Workflow/API function-call configuration | `enabled` | Supports structured output of dedicated fields such as coil parameters and quality inspection results required for bid documents |
| Workflow node timeout | `300 seconds` | Reserves sufficient time to wait for real-time data interface responses, adapting to the real-time return rhythm of online thickness measurement and surface inspection |
| Tool call retry count | `2 times` | Addresses temporary fluctuations in real-time data, preventing workflow interruptions caused by a single failed call |
| Context window size | `8000–12000 token` | Needs to integrate multiple document contents such as rolling regulations and quality certificates, ensuring information completeness of bid documents |

## Three common mistakes
- Running data in the conversation log is empty after triggering the interface call workflow. The cause is that the data source plugins corresponding to the mill and MES are not bound, or the coil batch parameters are not passed correctly.
- The output download address keeps jumping and finally presents the final result after the custom plugin runs. The cause is that the plugin needs to aggregate multi-batch real-time data, and no aggregation waiting node is set, resulting in batch return of results.
- Workflow A cannot fully execute when calling Workflow B. The cause is that Workflow B has no input parameter verification configured, or full execution mode is not enabled, causing preset links to terminate midway.

## How to confirm proper configuration
- Trigger the test workflow, and check whether the log contains dedicated data source return contents such as rolling plans and quality certificates for this category.
- Run the custom plugin, and check whether the output result includes dedicated fields such as coil numbers and thickness tolerances, with a format that meets bid document requirements.
- Verify nested workflow calls: confirm whether the sub-workflow fully executes all preset links without mid-run termination.
- Test the tool call retry configuration, simulate a temporary data fluctuation scenario, and confirm that the retry mechanism triggers normally.

The values provided are common starting points and should be measured against the reader's own samples.
