# Bid Document and Quotation Preparation for Steel Rolling and Finishing: Forms and Interactions

## What the data for this category looks like
Business data for steel rolling and finishing comes from slab or billet batches, heating furnaces, mill automation control systems, online thickness and width measuring equipment, surface inspection systems, and MES systems. Data is synced in real time per coil or billet. Daily associated documents include rolling plans, heating schedules, rolling specifications, shape and thickness records, surface quality reports, and quality certificates. Data fields include batch number, thickness (mm), width (mm), heating temperature (℃), surface defect level, rolling speed, and more. Each batch has a separate parameter set, and full coil-level traceability must be supported.

## Constraints on Forms and Interactions
Real-time coil-level data means forms cannot rely on static manual entry. Forms must directly connect to backend real-time data sources to avoid parameter errors from manual input. Multi-dimensional rolling parameters must be grouped in forms according to business logic. For example, heating schedules and rolling specifications must be displayed in a linked manner. Bid documents must be linked to quality certificates, surface quality reports and other documents, so form interactions must support quick retrieval of historical records for the corresponding batch. The coil-level traceability requirement means each form field must be bound to a specific billet batch to avoid parameter confusion.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
|---|---|---|
| `formInput` field configuration | Configure dynamic data source association for each rolling parameter, automatically load thickness, width, heating temperature and other data based on billet batch number | Data originates from online inspection and MES systems, updated in real time to avoid manual entry errors |
| `userSelect` option set | Preset rolling specifications and heating schedule options classified by steel grade and specification, support automatic matching by batch | Bidding must comply with internal enterprise standardization processes to reduce parameter selection deviation |
| Form submission verification rules | Trigger real-time data matching, verify whether the entered batch number exists in the online inspection database | Data update frequency is per coil or billet, to ensure real-time performance and accuracy of parameters |
| Context window size | 8000–12000 token | Must include historical data of multiple coil batches, rolling specifications and quality certificate content to ensure complete responses |
| Answer output format | Display in blocks according to bid document structure, including rolling parameters, quotation basis, and linked document links | Bid documents must be clearly structured for easy review by reviewers |

## Three Common Misconfigurations
- Phenomenon: Quotation data returned after form submission does not match actual rolling parameters. Cause: No dynamic data source association configured for `formInput`, only statically entered old data is used, and the latest shape and thickness records are not pulled based on the batch.
- Phenomenon: Unable to automatically trigger tool calls corresponding to rolling specifications. Cause: No linkage logic configured for `userSelect`, steel grade and specification parameters are not bound to tool call rules, making it impossible for the model to independently select and call tools.
- Phenomenon: After embedding FastGPT via iframe, the frontend cannot obtain conversation return results. Cause: No API callback address configured in FastGPT v4.17.0, and permission for the frontend to obtain conversation results is not enabled.

## How to Verify Proper Configuration
- Enter a known billet batch number, check whether the thickness, width and heating temperature parameters automatically loaded by the form match the records in the online inspection database.
- Select a preset steel grade option, check whether the tool call corresponding to the rolling specifications is automatically triggered to generate the corresponding quotation basis content.
- Submit a test form, check whether the returned bid document includes linked fields of rolling plans and surface quality reports, and the format meets structured requirements.
- Embed a test page via iframe, initiate a conversation, and check whether the frontend can normally receive and display the returned structured quotation content.

All configuration values provided here are common starting points and should be validated against the reader's own samples.
