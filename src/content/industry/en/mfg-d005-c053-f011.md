# Bid Document and Quotation Preparation for Iron and Steel Smelting and Continuous Casting: Forms and Interactions

## What Data for This Category Looks Like
Production data for iron and steel smelting and continuous casting originates from hot metal and scrap steel datasets, the L2 process control system, laboratory testing systems, the MES production management system, the energy medium system, and equipment condition monitoring systems. Data updates follow three cadences: per heat, real-time, and per shift. Daily production documents include heat plans, batching lists, converter smelting records, composition reports, continuous casting process records, and slab judgment sheets. Fields cover hot metal weight, scrap steel addition volume, smelting endpoint temperature, composition detection values, continuous casting pulling speed, slab qualification identification, and more, with units aligned to process standards such as tons, ℃, ppm, and meters per minute.

## What Constraints These Characteristics Impose on Forms and Interactions
Dispersed production data sources and real-time updates require forms to support synchronized pulling from multiple data sources, eliminating delays and errors from manual data entry. Heats and casting sequences are tightly coupled, so form fields must link along the production chain to ensure consistent production data referenced during bidding. Errors can directly lead to heat downgrading, continuous casting interruption, or subsequent rolling losses, so forms must include strict field validation and submission restrictions. Bid documents must match fixed qualification and production data templates, and the interaction flow must support quick binding of standardized document fields to reduce format adjustment workload.

## How to Configure the Setup
This configuration is implemented using FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Bind core heat fields synchronized from MES, set refresh interval to 10–30 seconds | Match the real-time update cadence of production data per heat, reduce manual entry errors |
| `userSelect` | Provide two mutually exclusive options: Skip Knowledge Base Retrieval, Force Retrieval of Historical Heat Data | Adapt to quick switching requirements for different quotation scenarios during bidding |
| Form Validation Rules | Enable field range validation, set hot metal temperature to 1200–1700℃, align composition detection values to process intervals | Prevent abnormal data inconsistent with smelting logic from being included in bid documents |
| Form Submission Debounce | 500 millisecond interval | Avoid repeated submission requests triggered by real-time data refreshes |
| Template Field Mapping | Bind the qualification identification field from the slab judgment sheet | Ensure bid documents automatically reference compliant production data |

## Three Common Misconfigurations
- Phenomenon: Concurrent requests trigger when configuring `userSelect` options, with multiple options simultaneously initiating data pulling. Cause: No mutually exclusive interaction lock is set for the options, leading to simultaneous calls to multiple data source interfaces and request conflicts.
- Phenomenon: SSL errors appear when `formInput` loads real-time data, with the interface displaying connection failure. Cause: No valid SSL certificate verification rules are configured for the data source, leading to interception by security policies when pulling L2 process control data.
- Phenomenon: A null value is returned after performing an index increment operation within a loop. Cause: No initial value is set for the loop variable, and no loop range is limited to match the number of heats, leading to null values returned after exceeding available data boundaries.

## How to Confirm the Configuration Is Complete
- Manually trigger a form refresh, verify that the `formInput` fields synchronously display the latest heat composition data and smelting parameters.
- Switch the `userSelect` options, confirm that only a single request for the corresponding data source is triggered each time, with no concurrent calls.
- Submit a test form, check that validation prompts matching the process parameter ranges are triggered, and abnormal data cannot be submitted.
- Run the loop script bound to heat data, confirm that the index variable increments as expected and no null return results occur.
