# Sheet Metal Cutting and Bending Bidding Documents and Quotation Preparation: Vector Models and Indexes

## What Data for This Category Looks Like
Typical data sources for the sheet metal cutting and bending category include CAD/CAM software, order BOMs, sheet metal inventory systems, laser cutters, bending machines, and MES systems. Commonly stored documents include part unfolding drawings, CNC cutting programs, bending process cards, nesting planning diagrams, first-piece inspection records, and process flow cards. Data update frequency aligns with each generated order, daily maintenance, or each equipment model change. Fields cover sheet thickness, bending compensation radius, unfolded dimensions, nesting utilization rate, and more, with units mostly millimeters, kilograms, and square meters.

## Constraints for Vector Models and Indexes
The multi-variety, small-batch business nature of this category leads to rapid growth in the number of documents to process with each order, requiring vector indexes to support high-frequency incremental updates. Most documents are text transcribed from drawings and process parameter descriptions, containing a large number of professional terms and precise numerical values such as bending compensation and nesting logic, requiring chunking strategies to avoid truncating key parameters. Data sources mix structured logs directly transmitted from equipment and manually filled process cards, requiring indexes to balance matching accuracy for both structured metadata and unstructured text. High-frequency data updates caused by model changes require index trigger mechanisms to adapt to short-cycle business rhythms.

## Configuration Settings
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Matches the length of single segments after transcription of sheet metal process cards and unfolding drawings |
| Overlap Length | 100–150 characters | Prevents key content such as bending coefficients and nesting rules from being truncated during chunking |
| Similarity Threshold | 0.75–0.85 | Filters low-match non-target process data, adapting to retrieval needs for multiple varieties |
| Single Search Limit | Top 10 entries | Adapts to the demand for a small number of matching results in multi-variety, small-batch scenarios |
| `defaultToken` | 8192 | Compatible with long text content transcribed from large-format CAD files |
| `maxToken` | 16384 | Accommodates the context of multiple process documents required for bidding quotations |

## Three Common Misconfigurations
- Phenomenon: The vector database only displays vector fields, with original document text and metadata missing. Cause: The associated storage path for original documents is not configured, only fragmented text fragments used for vectorization are uploaded, and key information such as source file order numbers and sheet metal specifications is not bound.
- Phenomenon: Retrieval results are empty or have extremely low matching accuracy when using a specified model, while conventional question-answering links can normally return content. Cause: The retrieval template is not adapted to the long-context recall logic for sheet metal categories, and relevant parameters are not adjusted, resulting in truncated recalled process content.
- Phenomenon: The index status remains in processing, with no available retrieval data. Cause: Incremental indexing triggered by order or model change is not enabled, high-frequency updated cutting programs and nesting diagrams are not included in the index in a timely manner, or chunking parameters exceed the model's supported limits leading to parsing failures.
