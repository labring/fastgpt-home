# Bid Document and Quotation Preparation for Sheet Metal Cutting and Bending: Multi-turn Dialogue and Prompt Terms

## What Data for This Category Looks Like
Usually sourced from CAD/CAM software, order BOM systems, sheet metal inventory ledgers, production data from laser cutters and bending machines, and MES manufacturing execution systems.
Update frequency: core documents are generated once per order, sheet metal inventory data is synced daily, and bending process parameters are updated when changing production setups.
Daily documents include 3D unfolding drawings, CNC cutting programs, bending process cards, nesting diagrams, first-piece inspection records, and process transfer cards.
Core fields include sheet metal thickness, bending compensation coefficient, unfolded cutting size, nesting utilization rate, and leftover material size. Common units are millimeters, square meters, and kilograms.

## Constraints Imposed on Multi-turn Dialogue and Prompt Terms
Data for this category relies on drawings and process parameters generated by CAD/CAM software. Multi-turn dialogue must accurately identify proprietary fields in drawings, and avoid generalized parsing.
Data updates frequently with orders and production setup changes. Dialogue context must bind the unique identifier of the corresponding order to ensure accurate parameter association.
Multiple documents such as nesting diagrams and process cards must be retrieved in priority order based on business scenarios. Prompt terms must clearly specify the retrieval scope.
Errors directly lead to sheet metal waste and assembly errors. Multi-turn dialogue must add a parameter verification step to avoid deviations in critical numerical values.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `chatId` | Bind to the unique identifier of the current bidding order, use order number + process code as the value | Ensure multi-turn dialogue context is associated with the sheet metal business data of the corresponding order, and avoid parameter confusion across orders |
| `messages` | Retain the first 20 rounds of dialogue content, calibrate the context window based on actual testing | Cover the full communication process of bidding quotation preparation, and avoid loss of key process parameters and drawing information |
| `variables` | Preset three variables: sheet metal thickness, bending coefficient, and nesting allowance. Sheet metal thickness ranges from 1 to 20 millimeters, bending coefficient ranges from 1.2 to 1.8 times the sheet thickness, nesting allowance ranges from 50 to 200 millimeters | Match core business parameters of sheet metal cutting and bending, and reduce redundant operations from repeated input |
| Maximum context size | 8000-12000 characters | Accommodate text content from multiple sheet metal drawings and process cards, and ensure prompt terms can access complete business data |
| Single search limit | Top 3 retrieval results | Focus on the most relevant nesting diagram and bending process card data, and avoid redundant information interfering with quotation calculations |

## Three Common Mistakes
- Phenomenon: After uploading a CAD drawing related to sheet metal cutting, the system prompts that data processing is empty or has no valid content. Cause: No dedicated rules for parsing CAD formats are specified in the prompt terms, so the model cannot identify proprietary fields such as bending coefficients and unfolded sizes in the drawing.
- Phenomenon: After calling the API to initiate a dialogue, no internal application interaction records are visible in the dialogue details. Cause: Dialogue log storage configuration is not enabled, so the system does not retain the complete `messages` sequence of multi-turn interactions.
- Phenomenon: The current bidding order's sheet metal inventory or process data cannot be associated during multi-turn dialogue. Cause: `variables` are not bound to the business ledger of the corresponding order, so context loses business association information.

## How to Verify Correct Configuration
The following verification steps are based on FastGPT v4.17.0:
- Upload a standard sheet metal cutting CAD drawing, trigger the data processing flow, and check whether core parameters such as sheet metal thickness and bending coefficient can be correctly extracted.
- Initiate a multi-turn dialogue, ask about nesting plans for different orders in sequence, and check whether the dialogue context retains the associated business data of previous orders.
- Call the API to initiate a dialogue request, view the request parameters, and confirm that `chatId`, `messages`, and `variables` are all passed in according to the configuration.
- Simulate a complete bidding quotation preparation process, and check whether the final output document includes corresponding business content from nesting diagrams and bending process cards.

The values provided here are common starting points, and should be measured against the reader's own samples.
