# Sheet Metal Cutting and Bending: Tender Document and Quotation Preparation - Workflow Orchestration

## What Data Does This Category Use
The data for this category mainly comes from CAD/CAM software, order BOMs, sheet metal inventory systems, laser cutter and bending machine equipment logs, and MES production management systems. Data update rhythm adjusts per order, daily production scheduling, and each process change. Daily associated documents include part unfolding drawings, CNC cutting programs, bending process cards, nesting diagrams, first-piece inspection records, and process transfer cards. Core fields include part unfolding dimensions, bending compensation values, sheet metal thickness specifications, cutting quantities, and bending angle requirements, with units mostly millimeters and pieces.

## What Constraints Do These Characteristics Impose on Workflow Orchestration
Data for this category is scattered and updated frequently. Workflows must automatically pull real-time data from multiple systems to avoid parameter deviations caused by manual entry. A high proportion of engineering documents requires workflows to support parsing structured parameters from unfolding drawings and process cards, extracting core content such as bending compensation values and cutting dimensions. The multi-variety, small-batch business model requires workflows to quickly adapt to process configurations for different parts without rebuilding basic processes repeatedly. Parameter changes from each process shift require workflows to support temporary variable adjustments and retain historical configurations for reuse. Parameters in core production links are closely linked. Workflows must connect cutting, bending, nesting and other links into standardized processes to reduce manual verification workload.

## How to Configure Settings
These configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` storage scope | Global variable pool | Fixed cross-conversation parameters must be retained, such as default bending compensation coefficients, sheet metal inventory thresholds |
| Node trigger condition | Trigger by order number | Each order corresponds to an independent cutting and bending process to avoid parameter confusion |
| Knowledge base recall limit | Top 6-10 entries, calibrated via actual testing | The number of sheet metal process-related documents is moderate; too many will increase parsing and calculation burden |
| Timeout threshold | 240-360 seconds | Reasonable time is required for engineering drawing parsing and multi-system data pulling |
| `nodeId` binding rule | Bind to corresponding process node | Ensure parameters for each process link only take effect in the specified node to avoid cross-node interference |
| Variable update rule | Append storage | Intermediate results from different processes must be retained, such as leftover material data after nesting, first-piece inspection parameters |

## Three Common Misconfigurations
- Phenomenon: Bending compensation value parameters in `variables` cannot be extracted after the workflow runs, and the field is displayed as empty on the interface. Cause: The parameter was not configured as a global variable, only defined in a single node, so it cannot be read when called across nodes.
- Phenomenon: The knowledge base search returns no results, with no relevant process documents. Cause: No dedicated recall rule for sheet metal unfolding drawings and bending process cards was configured, and the default recall logic cannot match keywords from engineering documents.
- Phenomenon: Historical process parameters are overwritten after variable updates, making intermediate results untraceable. Cause: The variable update rule was set to direct overwrite, causing old parameters to be replaced by new values.

## How to Verify Correct Configuration
- Manually enter the order number of a sheet metal part to trigger the workflow, and check if the corresponding BOM and sheet metal inventory data are automatically pulled.
- Call the knowledge base to search for documents related to sheet metal bending compensation, and confirm that the number of returned results matches the configured recall limit.
- Run a test node that includes variable definitions, manually modify the parameters and run again, and check if historical variable values are retained.
- View the workflow run logs, and confirm that the trigger conditions for each node and the `nodeId` binding rules match expectations.

Note: The values provided here are common starting points, and should be evaluated against the reader's own samples.
