# Bidding Document and Quotation Preparation for Sheet Metal Cutting and Bending: Tool Calling and Plugins

## What Data for This Category Includes
The data sources for this category include unfolded drawings exported from CAD/CAM software, CNC cutting programs, bending process cards, order BOMs, sheet metal inventory ledgers, operation data from laser cutting machines and bending machines, and process flow records from MES systems. Data updates are completed alongside order generation, daily inventory checks, and each production changeover. Document structures include fields such as sheet metal specifications, bending coefficients, hole position coordinates, and nesting layout plans. Most units are millimeters, kilograms, and square meters. Some process parameters require two decimal places of precision.

## Constraints for Tool Calling and Plugin Workflows
Data originates from multiple heterogeneous systems and is updated frequently. Tool calling must adapt to process documents in multiple formats and support real-time data retrieval. The multi-variety, small-batch business model requires plugins to dynamically generate tailored bidding documents and quotations for different workpieces, without relying on fixed templates. High-precision fields such as bending coefficients and hole position coordinates must be transmitted accurately. The tool calling parameter verification step must cover core process fields to prevent production errors caused by parameter deviations. Bidding documents must be linked to the latest sheet metal inventory and order data, and tool calling must trigger in alignment with business process nodes.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API function-call configuration | Enable forced function call mode | Supports accurate transmission of multiple parameters such as bending coefficients and hole position coordinates, adapting to the complex calling requirements of sheet metal process data |
| Single tool call timeout | 600 seconds | Covers the time required for unfolding calculations and nesting analysis of large sheet metal parts, preventing mid-process interruptions |
| Tool call result cache duration | 12–24 hours | Aligns with daily inventory checks and order update cycles, balancing data timeliness and calling efficiency |
| Tool return field filtering | Only retain sheet metal specifications, bending compensation values, and quotation amounts | Reduces irrelevant data interference and speeds up the integration of bidding documents |
| Plugin trigger node | Trigger after order confirmation | Matches the bidding document preparation stage in the business workflow, ensuring the called data is up to date and valid |

## Three Common Configuration Mistakes
- An error reading "Cannot load image" occurs when calling lookup tools. This happens because the tool's image loading timeout parameter is not configured, preventing process drawing materials from being retrieved when network speeds are slow.
- Calling the enterprise patent lookup tool via the tool calling component returns a message that the enterprise has no patent record. This occurs because the latest filing data for the target enterprise was not synchronized before the call, or the tool parameters were not correctly linked to the latest information of the corresponding entity.
- FastGPT v4.17.0 beta4 plugin validation fails with a MongoServerError. This error alone does not show that MongoDB 4.4.29 permissions are incompatible; inspect the complete error, the operation requested by the plugin, and database-user permissions. The v4.17.2 deployment config documents 4.4.29 as a fallback for CPUs without AVX (see [the official deployment configuration](https://github.com/labring/FastGPT/tree/v4.17.2/deploy/version/main)).

## How to Verify Successful Configuration
- Initiate a tool call for a simulated sheet metal order, and check whether the returned process parameters match those in the corresponding CAD file.
- Review the tool call logs to confirm there are no timeout interruptions or missing parameter errors, and that the returned results include all core fields required for bidding documents.
- Trigger the plugin with different workpiece types to confirm it can adapt to different unfolded drawings and nesting plans to generate corresponding content.
- Verify the database connection status to confirm there are no version compatibility or permission-related errors.

The values provided here are common starting points and should be evaluated against the reader's own samples.
