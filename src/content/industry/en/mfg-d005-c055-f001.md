# Tender Document and Quotation Preparation for Foundry (Sand Casting, Precision Casting, Die Casting): HTTP Interfaces and External Systems

## What the Data for This Category Looks Like
Data sources for this category include ERP material master data, melting furnaces and thermometers, spectrometers, MES heat records, mold management systems, customer drawings, and technical specifications. Daily business documents cover foundry process cards, batching lists, heat records, mold histories, first article inspection records, material reports, and nonconforming product review forms.
Data is updated per heat, per batch, and daily. Core fields include alloy grade, return charge ratio, melting temperature, pouring temperature, heat number, mold number, and material composition test values. Most field units are percentage and degrees Celsius.

## How These Characteristics Create Constraints for HTTP Interfaces and External Systems
Data sources span multiple types of industrial equipment and business systems. Interfaces must support parallel pulling of multi-source data and field mapping to adapt to naming differences across systems.
Frequent heat and batch updates require interfaces to have low-latency response capabilities, to avoid disrupting real-time tender document preparation.
Units and formats of core fields must strictly match foundry business standards. Interface return data must include standardized fields that can be directly used for document filling.
The relationship between nonconforming products and heats or mold numbers requires interfaces to support associated queries, to ensure accurate and complete quality traceability information in tender documents.

## How to Configure Settings
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Carry a token in the format `Bearer ${oneapi_key}` | Adapts to oneapi authentication rules, matches the authentication method that succeeded in Postman calls |
| `variables` | Configure heat number, alloy grade, and return charge ratio as dynamically filled variables | Adapts to the requirement of dynamically filling foundry parameters into tender documents for different projects |
| `responseData` | Extract melting temperature, spectral composition ratio, heat ID, and mold history number fields | Matches core business data for this category, used to quickly generate tender documents and quotation items |
| Timeout setting | 600 seconds | Covers data return delays from industrial equipment such as melting furnaces and spectrometers, adapts to time consumption of multi-source data pulling |
| Request retry count | 3 times | Addresses temporary disconnections of industrial equipment or interface fluctuations, ensures stability of data pulling |
| Field mapping rules | Associate MES heat records by ERP material number | Unifies naming differences across business systems, ensures data accuracy |

## Three Common Configuration Mistakes
- Scenario: Returns a 401 status code. Cause: Incorrect token format for the `Authorization` parameter, missing the `Bearer` prefix when concatenating the oneapi secret key.
- Scenario: Content extraction nodes cannot call self-built model interfaces. Cause: Incorrect declaration of model call parameter formats in system configuration, not matching the interface specifications of the self-built model.
- Scenario: Knowledge base cannot select locally deployed models. Cause: Incorrect configuration of oneapi access address and secret key in config.json, causing the model list to not sync to the system.

## How to Confirm Proper Configuration
- Send a test request carrying the `Authorization` parameter, verify that the return status code is 200.
- Check that the fields extracted via `responseData` include core business parameters for this category such as melting temperature and alloy composition ratio.
- After configuring dynamic variables, send a request with a specified heat number, verify that the returned data matches the business records for the corresponding heat.
- Review system logs, confirm there are no records of authentication failures or field parsing errors.
