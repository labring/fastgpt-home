# Bid Document and Quotation Preparation for Foundry (Sand Molding, Precision Casting, Die Casting): Multi-turn Dialogue and Prompt Engineering

## What Data Looks Like for This Category
Data sources for this category include ERP material master data, melting furnaces and thermometers, spectrometers, MES furnace heat logs, mold management systems, customer drawings, and technical specifications. Data update frequency is per furnace heat, per batch, or daily. Daily documents include foundry process cards, batching lists, furnace heat records, mold history logs, first article inspection records, material test reports, and nonconforming product review forms. Data fields include alloy composition parameters, pouring temperature, mold cycle count, furnace heat ID, return charge ratio, and more. Units include degrees Celsius and kilograms.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
Data for this category is updated per furnace heat, batch, or daily, and is scattered across multiple systems. This requires multi-turn dialogue to bind to a specific furnace heat ID or bidding project ID to prevent cross-batch data mixing. Professional document fields are detailed and include foundry-specific parameters. Prompts must clearly define the range of fields to extract to avoid irrelevant content disrupting results. Format differences across multiple data sources require gradual alignment of parameter sources during multi-turn interactions to ensure consistency of parameters such as melting and pouring temperatures. Parameter errors can lead to severe scrap or claims, so the dialogue flow must include a parameter verification step to confirm that batching ratios, temperatures, and other parameters meet process requirements.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to bidding project ID + furnace heat range | Ensure the session is associated with the corresponding batch of foundry data and avoid confusion across projects |
| `messages` | Retain the first 15 rounds of interactions and associated document fragments | Cover process, batching, and inspection historical data required for bidding quotations |
| `variables` | Preset furnace heat ID, alloy grade, customer drawing version | Reduce repeated input and align field mapping across multiple data sources |
| Session timeout setting | 1800 seconds | Match the average processing cycle of melting furnace heats and avoid session disconnection mid-process |
| Maximum single retrieval documents | Top 8 entries | Avoid overloading with professional document content and ensure returned results focus on core parameters |
| Document matching threshold | Calibrated based on actual testing | Adapt to semantic matching accuracy for foundry-specific terminology |

## Three Common Misconfigurations
- Phenomenon: Garbled characters or formatting errors appear in returned batching list fields. Cause: No format requirements for document fields specified in the prompt, or field mapping rules across multiple data sources are not aligned.
- Phenomenon: No like function response after calling the dialogue interface. Cause: No parameter binding for like triggers configured in `variables`, or feedback configuration for session interactions is not enabled.
- Phenomenon: Locally deployed session logs are automatically deleted. Cause: No log storage path bound to `chatId` configured, or the log rotation cycle for local deployment is set too short.

## How to Verify Proper Configuration
- Enter a known furnace heat ID and check if the session automatically associates corresponding process cards, batching lists, and other relevant data.
- Initiate multi-turn interactions and confirm that `messages` retains valid historical interaction content without premature truncation.
- Check the locally deployed log directory and confirm that session logs bound to `chatId` are not automatically deleted.
- Input foundry-specific terminology and confirm that returned parameter formats conform to industry-standard field specifications.
