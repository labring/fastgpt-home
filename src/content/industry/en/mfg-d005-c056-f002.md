# Tender Document and Quotation Preparation for Lithium-Ion Cell Manufacturing: Vector Models and Indexes

## What the data for this category looks like
Data for this category comes from raw material batch ledgers, production MES systems, slurry and coating testing equipment, workshop dew point monitoring devices, formation and grading cabinets, and laboratory testing equipment. Daily documents include batching records, coating and rolling parameter ledgers, winding or lamination process records, liquid injection volume registrations, formation and grading data reports, OCV and safety test reports. Data updates occur per production batch, with corresponding records generated for each cell. Some workshop dew point and slurry status data updates in real time. Document fields include material batch numbers, process parameter values, test result values, equipment operating status identifiers, and more. The length of individual records varies significantly.

## Constraints on vector models and indexing from these characteristics
Data sources are scattered, and update frequencies are uneven. Real-time data and batch archived data require separate processing. Indexes must adapt to data sources with different update rhythms. The length of individual records varies greatly: some process parameter records are short, while test report records are long. This affects the consistency of vector matching after chunking. The electrochemical system of lithium-ion cells has high data accuracy requirements. Subtle deviations in parameter values will affect the process rationality of tender quotations. Vector models must accurately capture the logical relationships between parameters. Document formats exported by different equipment are inconsistent. Unified field mapping rules must be set before indexing to avoid missing or misaligned fields in vector indexes.

## How to Configure
The following configurations are based on the interface settings of FastGPT v4.17.0.

| Configuration Item | Recommended Setting Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the length range of individual process records and test reports for this category, avoids breaking the logical relationship between parameters during chunking |
| Overlap Length | 100–150 characters | Retains process parameter context for adjacent chunks, prevents loss of critical associated information across chunks |
| `defaultToken` | 4096 token | Covers the vector encoding length requirements of most process parameters and test data, adapts to the input limits of basic embedding models |
| `maxToken` | 8192 token | Handles longer safety test reports or batch summary documents, avoids truncation of critical data |
| Similarity Threshold | 0.75–0.85 | Filters historical process data with high matching degrees, ensures process rationality and quotation accuracy of tender documents |
| Single Retrieval Limit | Top 8 entries | Balances indexing efficiency and data coverage, avoids excessive redundant data interfering with vector matching results |

## Three Common Misconfigurations
- The indexing task stays in a running state in the interface with no progress updates. Cause: The category’s real-time formation and grading data is not adapted, no incremental update rule is set for the indexing task, and continuous full scanning of all data causes blocking.
- The embedding model call returns a 503 status code. Cause: No reasonable model call timeout threshold is configured, or the `defaultToken` setting exceeds the maximum length actually supported by the model, causing the model service to be unresponsive.
- Some process parameter fields are missing from indexing results. Cause: Unified field mapping rules for documents exported by different equipment are not set, and some non-standard format test reports have not completed field extraction, leading to loss of critical information during vector encoding.

## How to Verify Correct Configuration
- Review indexing task logs to confirm that the chunk length and overlap length settings match the document length range for this category, with no prompts of excessive truncation or overly fine chunking.
- Test embedding model calls to verify that the `defaultToken` and `maxToken` settings do not exceed the input limits of the connected model, with no error returns.
- Sample and retrieve vector indexing results for historical process data, confirm that all key fields are correctly encoded with no missing or misaligned cases.
- Compare indexing time consumption across different batches of data, confirm that the single retrieval limit setting does not cause indexing task timeouts.

The values provided are common starting points and should be measured against the reader's own samples.
