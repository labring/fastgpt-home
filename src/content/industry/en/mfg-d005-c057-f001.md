# Bid Document and Quotation Preparation for Forging and Die Forging: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
Data for this category comes from raw material quality certificates, heating furnace systems, press collection data, MES systems, non-destructive testing equipment, and customer forging drawings. Data updates follow the rhythm of each forging piece, each batch of workpieces, or each furnace production run. Daily supporting documents include forging process specifications, cutting cards, heating furnace records, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports. Data fields include forging ratio, metal fiber direction, material heat number, forging batch number, qualified inspection items, and more. Units include millimeters, tons, furnace runs, and others.

## Constraints for HTTP Interfaces and External Systems
Data for this category is updated per furnace run or batch and sourced from dispersed locations. HTTP interfaces must support pulling production and testing data within a specified time frame using batch ranges, to avoid performance overhead from full data pulls. Data fields must align with required items for bid documents. Interfaces must return standardized fields including forging ratio, fiber direction, and heat number, to fit the filling logic of bid documents. Since data is tied to the entire production workflow, interfaces must support returning multiple types of associated data in a single request. Interfaces must also validate field completeness to prevent bid document errors caused by missing critical information.

## How to Configure Settings
This document is written based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Request timeout | 600 seconds | Adapts to the pull time required for complete production data of a single furnace run |
| `Authorization` | Bearer {custom API key} | Complies with the identity verification specifications of FastGPT interfaces |
| `variables` | Pass heat number, forging ratio, fiber direction | Used to dynamically fill fixed fields in bid documents |
| `responseData` | Only return ultrasonic testing qualified items and process parameters | Filters redundant data to simplify interface responses |
| Maximum number of data entries per single request | 500 entries | Matches the scale of forging data corresponding to a single bid document |
| Batch request limit | First 20 furnace runs | Matches the number of forging batches corresponding to a single bid document |

## Three Common Mistakes
- Phenomenon: The interface returns the `messages is empty` error. Cause: Core forging parameters required for bid documents were not passed in `variables`, causing the interface to fail to generate a valid request context.
- Phenomenon: The interface returns redundant data including mold wear records not required for bids. Cause: The `responseData` filtering rules were not configured correctly, and only the fields required for bids were not specified.
- Phenomenon: Interface calls time out in an intranet deployment environment. Cause: The request timeout setting was not adjusted based on intranet network latency, and the default timeout duration is insufficient to cover intranet data pull time.

## How to Verify Proper Configuration
- Call the configured test interface to check whether `Authorization` verification passes and returns a correct identity verification status.
- Review the fields returned in `responseData` to confirm that only forging parameters and testing data required for bid documents are included.
- Pass a test heat number and verify whether the fields passed in `variables` can correctly match the filling requirements of a simulated bid document.
- Adjust the request timeout duration to verify the call stability of the interface under different data volumes.

The values provided are common starting points and should be measured against the reader's own samples.
