# Bid Document and Quotation Preparation for Forging and Die Forging: Vector Models and Indexes

## What the Data for This Category Looks Like
The data for this category comes from raw material quality certificates, heating furnace systems, press acquisition data, MES systems, non-destructive testing instruments, and customer forging part drawings. Daily documents include forging process specifications, cutting cards, heating furnace records, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports. Data updates are synchronized after each forging part, each batch of workpieces, or each furnace production run. Most documents combine structured fields and process parameters, including fields such as forging part specifications, forging ratio, heating temperature range, mold model, and testing results. No unified fixed template exists for these documents.

## Constraints Imposed on the Vector Model and Index Link
The data characteristics of this category create multiple constraints for the vector model and index link. Multi-source heterogeneous data sources and high-frequency update cycles require indexes to support incremental synchronization and compatibility with multiple data formats. Document structures that mix structured parameters and unstructured process descriptions require vector models to adapt to both numeric business fields and semantic encoding of professional technical text. The combination of small single-data volume and dense batch production requires index architectures to support efficient batch recall. In bidding scenarios, customized customer forging part drawing requirements must be matched quickly, so indexes must prioritize recalling historical documents strongly related to forging part specifications and process parameters.

## How to Set the Configuration
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the paragraph length of forging process documents, balancing semantic integrity and retrieval efficiency |
| Overlap Length | 100–150 characters | Prevents cross-chunk process parameters from being truncated, ensuring continuity of key information such as heating ranges and forging ratios |
| `defaultToken` | Calibrated based on actual measurements | Adapts to the input length limit of embedding models, matching the total token count of single-batch forging part data |
| `maxToken` | 4096 token | Complies with the maximum input limit of mainstream embedding models, covering the core parameter scope of a single bid document |
| Similarity Threshold | 0.72–0.80 | Filters low-correlation historical process documents, matching the professional semantic similarity range of forging part parameters |
| Single Search Limit | Top 8 entries | Balances retrieval recall rate and retrieval speed, adapting to multi-parameter matching needs in bidding scenarios |

## Three Common Misconfigurations
- Issue: After enabling the index model on the model provider page in FastGPT v4.17.0, the channel configuration prompts that no available options are available. Cause: The index model has not been assigned to the corresponding group in group management, or the correct embedding model API key has not been entered.
- Issue: After accessing the BGE-M3 model deployed via Ollama, vector recall results are empty. Cause: The embedding model’s interface address and port have not been configured correctly, or the chunk length exceeds the model’s input limit.
- Issue: After enabling the reranking function, single-round retrieval tasks time out. Cause: The knowledge base chunk setting is too granular, leading to an excessive number of total retrieval entries, or the single search limit is configured too high.

## How to Confirm Proper Configuration
- Navigate to the embedding model management page in FastGPT v4.17.0, and verify that the index model connection status is shown as normal.
- Upload a typical forging process specification document, run a vector database insertion operation, and confirm that no errors occur and the insertion progress completes successfully.
- Input the core parameters of a customer forging part drawing, run a retrieval test, and confirm that returned results include matching process parameters and historical quotation data.
- Check system logs, and confirm that index update task execution frequency matches the data update rhythm, with no frequent timeout errors.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
