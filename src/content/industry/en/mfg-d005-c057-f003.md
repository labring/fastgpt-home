# Bid Document and Quotation Preparation for Forging and Die Forging: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Forging and die forging data primarily comes from raw material quality certificates, heating furnace systems, press collection data, MES, non-destructive testing equipment, and customer forging drawings. Daily documents include forging process specifications, cutting lists, heating furnace records, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports.
Data is updated per piece, per batch, or per furnace heat. Fields cover forging dimensions, forging ratio, fiber direction, furnace batch number, heat treatment hardness, and more. Units include millimeters, megapascals, furnace batch numbers, and others.

## Constraints on Multi-turn Dialogue and Prompt Engineering
Forging and die forging data is updated per piece, per batch, or per furnace heat. Multi-turn dialogue must bind precise batch variables to avoid mixing cross-batch data.
Daily document types are diverse, and fields are professional. Prompts must explicitly specify exclusive fields such as forging ratio and fiber direction. Without this, accurate bid quotations and documents cannot be generated.
Complex deformation step and heating zone calculations take significant time. Invalid context must be restricted to avoid dialogue timeouts.
The bid link requires verification of material furnace batches and forging batches. Batch matching errors can lead to serious consequences such as forging scrap and service fracture. Multi-turn dialogue must support gradual confirmation of batch information.

## Configuration Settings
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context length | 8000–12000 token | Single documents related to forging are mostly 1000-2000 characters. Combined with 10 or fewer rounds of multi-turn dialogue, this covers all data required for complete bid preparation |
| `variables` binding rules | Bind forging batch number and furnace batch number variables | Data is updated per furnace heat or batch, requiring precise matching of corresponding data for the current bid project |
| Single recall count | Top 6 matching documents | The number of forging-related documents is limited. Excessive recall will interfere with the accuracy of quotation calculations |
| Dialogue timeout | 300 seconds (adapted for locally deployed large model computing latency) | Complex deformation step and heating zone calculations require long processing times. Latency increases further in locally deployed scenarios |
| Question optimization switch | Enabled | Bid documents require accurate professional terminology. Multiple rounds of revision can align with professional expressions in the forging industry |

## Three Common Configuration Errors
- Phenomenon: Request timeout error occurs during dialogue, with a 504 status code. Cause: The timeout configuration has not been adjusted for complex forging process calculation links, and the default timeout duration is insufficient.
- Phenomenon: The extracted `chatId` parameter is empty, making it impossible to associate historical data for the corresponding forging batch. Cause: The `chatId` transfer rule was not correctly configured during dialogue initialization, leading to failure to match context.
- Phenomenon: Recalled documents include heating furnace records from expired furnace heats, leading to errors in material furnace batch and forging batch verification. Cause: No rule was configured to filter recalled data by the current bid batch, and the recall scope was not limited to project-specific data.

## How to Verify Proper Configuration
- Initiate a test dialogue, enter a forging batch number, and check if the returned `variables` include corresponding fields such as furnace batch number and forging ratio.
- Simulate a complex request involving deformation step and heating zone calculations, wait for the dialogue to complete, and confirm no timeout errors occur.
- Upload a batch of documents from expired furnace heats, initiate a dialogue for the corresponding project, and confirm that the recalled results do not include expired data from this batch.
- Copy the dialogue link, extract the `chatId` parameter, and verify that the parameter can be properly transferred to the context call link.
- Refer to the FastGPT official API documentation to verify that the transfer format of the `messages` parameter meets requirements.

The values provided are common starting points and should be measured against the reader's own samples.
