# Bid Document and Quotation Preparation for Forging and Die Forging: Workflow Orchestration

## What the data for this category looks like
Business data for forging and die forging comes from raw material quality certificates, heating furnace systems, press collection data, MES systems, non-destructive testing equipment, and customer forging drawings. Data updates follow the rhythm of individual forgings, batches of materials, or furnace heats. Daily associated documents include forging process specifications, cutting lists, heating furnace records, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports. Data fields include forging ratio, fiber direction, furnace batch number, forging contour dimensions, and heat treatment hardness requirements. Units include millimeters, degrees Celsius, tons, and others.

## Constraints on workflow orchestration
The rhythm of data updates per furnace heat or batch requires workflows to support pulling the latest raw material quality certificates, heating furnace records, and other data on demand, to avoid using expired information. Fixed formats for multiple types of structured documents require workflows to split extraction and verification nodes for different documents, to separately process dimensional parameters from cutting lists and defect records from ultrasonic testing reports. Unit requirements for specialized fields such as forging ratio and fiber direction require configuring field format verification rules in workflows. The preparation time for deformation steps and heating zones accounts for a large share, so this link must be split into independent, reusable work nodes to facilitate subsequent adjustment and optimization.

## Configuration settings
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| Global Variables | Add 3 variables: furnace batch number, forging ratio, and ultrasonic testing pass count | Match core data fields of forging business, to facilitate cross-node transfer |
| Workflow Branch Trigger | Trigger pass/fail branches based on node execution results | Adapt to process branching after forging defect detection |
| Variable Update Plugin | Set the initial counter value to 0, add 1 after each execution | Support counting the number of forgings per batch |
| Text Content Extraction | Limit the extraction range to the process specification document of the current forging, with a single extraction upper limit of 5000 characters | Avoid mixing document content from other batches, cover complete process parameters |
| Single Node Timeout Setting | 120 seconds | Cover the time requirements for complex deformation step calculations |
| `variables` | Bind the preset raw material quality certificate data interface | Pull the latest furnace batch number and material parameters |
| `nodeId` | Set to the unique number of the current forging | Distinguish workflow running instances of different batches |

## Three common errors
- Workflow templates show a successful import but have empty nodes. The cause is that the imported template does not carry node configurations corresponding to forging business, and only retains the general framework.
- Text content extraction nodes cannot select a specified model. The cause is that the call permission for the corresponding model is not bound in the workflow configuration, or the global switch for model calls is not enabled.
- Global counter variables cannot automatically accumulate. The cause is that the `variables` parameter of the variable update plugin is not configured correctly, and the current counter value is not used as the update basis.

## How to confirm proper configuration
- Manually trigger the workflow, check whether the global variables correctly load the furnace batch number and forging ratio parameters of the current forging.
- Run the text extraction node, verify that the extracted content only includes the process specification information of the current forging.
- Trigger the fail branch, confirm that the workflow jumps to the corresponding node for defect handling.
- View the workflow logs in FastGPT v4.17.0, confirm that single node execution does not exceed the preset timeout period.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
