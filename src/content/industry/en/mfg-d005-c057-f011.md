# Bid Document and Quotation Preparation for Forging and Die Forging: Forms and Interactions

## What the data for this category looks like
This category’s data covers full forging process production records and customer requirement documents. These include forging process specifications, cutting lists, heating furnace logs, forging process cards, mold life records, heat treatment work orders, and ultrasonic inspection reports.
Data sources include raw material quality certificates, heating furnace systems, press collection data, MES systems, non-destructive testing instruments, and customer forging drawings.
Update frequency is once per forging piece, batch, or furnace heat.
Core fields include forging batch number, heat number, forging ratio, fiber direction, heating temperature range, defect detection results, and more. Most fields are linked to real-time or batch data from production links.

## Constraints on Forms and Interactions
Data sources are scattered and updated frequently by batch or furnace heat. Forms must support automatic reference and verification of multi-source variables to avoid manual input errors.
There are many core fields linked to production links. Forms must be laid out in blocks according to business logic to prevent interaction lag caused by field clutter.
Fields such as forging batch number and heat number require linked verification to ensure data matching. Forms must also support custom verification rules to adapt to different customers’ forging drawing requirements.
Additionally, data volume changes with order batches. Forms must support dynamically loaded fields to avoid static configuration failing to cover quotation needs for multiple forging varieties.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `formInput` | Bind the forging batch number and heat number fields, enable cross-data source field mapping | Forging data comes from multiple systems including raw material quality certificates and heating furnace systems, requiring accurate association of business fields |
| `userSelect` | Limit optional values to the forging models associated with the current order, set to the top 3 priority matching items | There are many forging models that need to match customer requirements; limiting optional values reduces input errors |
| Interactive block settings | Split form blocks by cutting, heating, forging, and inspection processes, with a maximum of 12 fields per block | The core forging process is divided into multiple links; block layout avoids interaction lag caused by field clutter |
| Data source verification rules | Enable linked verification between heat number and forging batch number, set timeout to 30 seconds | Forging batch numbers and heat numbers must correspond one-to-one; verification avoids risks of data mismatch |
| Error prompt configuration | Display specific text for empty fields or failed verification, such as "Heat number does not match forging batch number" | Errors in forging data verification have serious consequences; clear prompts help quickly correct issues |

## Three Common Misconfigurations
- Symptom: The `userSelect` component dropdown has no optional values, making it impossible to select a forging model. Cause: The forging data source associated with the current order has not been configured, or the data source fields have not been mapped to the optional value range of `userSelect`.
- Symptom: When calling an external quotation tool, the passed JSON data contains a large number of escaped backslashes, resulting in interface return format errors. Cause: Automatic JSON formatting for form inputs has not been enabled, and special characters in the original input have not been properly escaped.
- Symptom: When selecting variable values or dragging form fields, obvious lag occurs on the front-end interface, with delayed operation response. Cause: `formInput` is bound to too many unpaginated data source fields, leading to excessive rendering load.

## How to Confirm Configuration is Complete
- Open the form editing page, check if the optional value list of the `userSelect` component includes the forging model corresponding to the current order.
- Submit test data to verify whether the linked verification between heat number and forging batch number correctly intercepts mismatched inputs.
- Drag form field blocks to confirm that the interface has no obvious lag and operation response meets expectations.
- Export test JSON data to check that special characters are properly formatted with no extra escaped backslashes.

The values given are common starting points and should be measured against the reader's own samples.
