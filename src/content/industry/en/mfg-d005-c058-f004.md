# Precast Concrete Component Bidding Document and Quotation Preparation: Workflow Orchestration

## What the data for this category looks like
Data for this category comes from BIM detailed design documents, rebar and concrete batch ledgers, mold table and curing kiln operation records, laboratory test reports, and QR code traceability systems. Daily associated documents include component detailed drawings, rebar cutting lists, mold inspection sheets, pouring and vibration records, curing cycle records, and demolding and factory inspection reports.
Data is updated per individual component, per batch of materials, and per curing kiln batch. Core fields include component number, external dimensions, rebar specification, concrete strength grade, and curing duration. Units include millimeters, cubic meters, megapascals, hours, and other standard engineering units.

## What constraints these characteristics impose on workflow orchestration
Precast concrete component data comes from dispersed sources with varied update rhythms. Workflows must support triggering different processing nodes per individual component, per batch of materials, and per curing kiln batch. This prevents data lag or duplicate processing.
Multiple document types require staged parsing. Workflows must split into independent nodes such as drawing parsing, data validation, and quotation calculation. These nodes adapt to format requirements for different documents including detailed drawings and rebar cutting lists.
Data association requirements are strict. Fields from different sources must be accurately mapped. Inaccurate mapping causes issues such as embedded position errors and inconsistent strength parameters. This impacts the accuracy of bidding documents.

## How to set the configuration
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
|---|---|---|
| Variable Mapping | Bind component number and concrete strength grade from workflow `variables` | Core precast concrete component data is extracted from BIM detailed drawings. This data must be stored in global variables for use in subsequent workflow stages |
| Node Trigger Rules | Bind mold inspection record upload events by `nodeId` | Mold inspection is a pre-production compliance step for components. This step must trigger subsequent quotation verification processes |
| Concurrent Request Limit | 6–10 requests/second | Calibrated through actual testing, this matches the daily component data processing rhythm of a single factory |
| Timeout Threshold | 500–700 seconds | This covers the average time required to parse detailed drawings of complex components and conduct multi-dimensional data validation |
| Knowledge Base Selection | Bind the precast component standard library for this project | Quotation coefficients and inspection standard data for the corresponding component category must be called |

## Three Common Mistakes
- When selecting a knowledge base, no optional values appear when referencing variables. The cause is failure to bind component data from workflow `variables` to the knowledge base’s retrieval fields.
- A 503 status code appears when calling the workflow API externally. The cause is that the set concurrent request limit exceeds the current server’s carrying capacity, and parameters were not adjusted based on actual testing calibration.
- Embedded position fields are empty in bidding documents. The cause is failure to add a field validation node for rebar cutting lists and detailed drawings in the workflow. Mapping for embedded positions was omitted.

## How to Confirm Proper Configuration
- Upload a single precast concrete component detailed drawing. Confirm the workflow automatically triggers and stores extracted fields in `variables`.
- Upload the corresponding mold inspection record. Confirm the trigger node bound by `nodeId` starts the subsequent verification process normally.
- Initiate an external API call. Confirm no abnormal error reports are triggered.
- Enter the knowledge base selection interface. Confirm the precast component standard library data for the current project is retrievable.

The values provided are common starting points and should be measured against relevant in-house samples.
