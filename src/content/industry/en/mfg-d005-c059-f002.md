# Tender Document and Quotation Preparation for Ready-Mixed Concrete Production: Vector Models and Indexes

## What the Data for This Category Looks Like
Core data for ready-mixed concrete production comes from commercial concrete batching plants, project laboratories, and quality scheduling departments. Daily documents include mix design notices, opening identification reports, production and transport slips, raw material inspection reports, test block records, and strength reports. Data sources cover engineering orders, sand, gravel, cement, and admixture test results, aggregate moisture content measurement data, batching plant control system records, and laboratory ledgers.
Data updates occur per vehicle production record, per batch raw material inspection, and daily ledger summary. Fields include aggregate moisture content, water usage, pour volume, and test block strength values. Units match industry standard measurements such as cubic meters, kilograms, and megapascals.

## Constraints on Vector Models and Indexes
The high-frequency update nature of ready-mixed concrete production requires indexes to support incremental data import. This avoids resource consumption from full reindexing.
Mixed storage of multiple document types (structured tables and semi-structured text) requires chunking logic adapted to different document structures. This prevents splitting of critical business parameters.
Tender documents need to associate multi-dimensional data from orders, production, and inspection. Indexes must support cross-document associated retrieval. This ensures completeness of quotation parameters.
Single-batch data volume grows with project scale. A balance must be struck between import efficiency and retrieval accuracy. This avoids task failure from overload during batch processing.
This page is compatible with FastGPT v4.17.0.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Matches the single-page content length of mix design notices and production transport slips, avoids splitting critical parameters |
| Overlap Length | 50–80 characters | Retains critical parameters such as slump and moisture content across chunks, prevents retrieval gaps |
| `defaultToken` | 4096 | Adapts to the long-text context of aggregated tender documents, meets multi-document splicing requirements |
| `maxToken` | Set to the selected embedding model/service maximum supported input tokens | `maxToken` is the input-token maximum supported by the selected embedding model/service; verify it in that provider configuration. See the [v4.17.2 model-field reference](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx). It is not retrieval/LLM context or a FastGPT-wide fixed cap. |
| Single Import Limit | 500 records per batch | Matches the batch update rhythm of per-batch raw material inspections and production records, reduces import pressure |
| Similarity Threshold | 0.75–0.85 | Distinguishes qualified and abnormal test block strength and batching data, ensures accuracy of quotation parameters |

## Three Common Configuration Errors
- Symptom: Vector data import takes too long, with page loading progress stalling for more than 10 minutes. Cause: Chunk length and single import limit are not adjusted. Excessive batch processing of per-vehicle production records causes elevated resource usage.
- Symptom: After uploading 100,000 CSV-format raw material inspection data entries, only more than 90,000 entries appear after vector import. Thousands of records are missing. Cause: Some records contain unescaped special characters such as dashes in raw material names. This causes parsing failure and failed import. The CSV format verification switch is not enabled.
- Symptom: Vector indexes work correctly when run locally. All retrieval results have identical similarity scores after packaging as a Docker image. Cause: The vector model cache files are not correctly mounted in the image. All text calls use the default random vector generation logic, and actual model parameters are not loaded.

## How to Verify Correct Configuration
- Upload a single mix design notice document, perform associated retrieval, and check if returned results include corresponding raw material inspection records and production transport slips.
- Batch upload that day’s production records and inspection data, verify that the number of imported entries matches the source data count, and confirm no records are missing.
- Simulate a tender quotation retrieval request, check if returned parameters such as water usage and aggregate moisture content conform to business logic, with no obvious gaps or truncation.
- Start the Docker container, run a vector model loading test, confirm no model missing errors appear in the console, and retrieval results have reasonable differences in similarity scores.

The values listed above are common starting points. They should be evaluated against the reader’s own samples.
