# Bid Document and Quotation Preparation for Ready-Mixed Concrete Production: Workflow Orchestration

## What this category’s data includes
Data related to ready-mixed concrete production comes from engineering orders, sand, gravel, cement and admixture inspection reports, moisture content measurement records, concrete mixing plant control systems, and project laboratories. Daily documents include mix proportion notices, opening identifications, production and transport slips, raw material inspection records, and test block strength reports. Fields cover aggregate moisture content, mix proportion material dosage, slump, test block compressive strength, pouring time window, and other metrics. Update frequency includes per-vehicle production data, each batch of raw material inspection results, and daily scheduling and quality records.

## Constraints on workflow orchestration
This category of data has a high update frequency. New data is generated for every vehicle’s production, each batch of raw materials, and daily scheduling tasks. Workflows must support real-time pulling of the latest mix proportion and moisture content measurement results. Static cached data must not be used. There are many specialized document fields. Precise matching of dedicated fields such as aggregate moisture content, slump, and test block strength is required. General field mapping cannot meet requirements. Production, transport, and pouring links are strongly correlated. Workflow nodes must be arranged in the order of order triggering, data verification, quotation generation, and scheduling synchronization. Support for exception branch triggering is required. For example, automatically trigger an exception handling process when slump does not meet requirements.

## Configuration Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Variable mapping rules | One-to-one binding of fields from mix proportion notices and test block reports to `variables` | Quotations for ready-mixed concrete require precise matching of dedicated business fields such as aggregate moisture content and test block strength. General mapping cannot cover professional parameters |
| Node trigger conditions | Dual trigger based on order confirmation time + raw material inspection completion time | The quotation preparation process must start only after waiting for the latest inspection data of each batch of raw materials and valid engineering orders |
| Maximum context length | 800–1200 characters | Adapts to the length of core parameter paragraphs in a single bid document. Avoids redundant information interfering with the model’s generation of accurate quotations |
| Single search limit | Top 5 entries | References the historical data volume of similar engineering orders. Excessive data increases computational load and affects generation efficiency |
| `nodeId` configuration | Bind dedicated IDs of production scheduling nodes and laboratory data nodes | Accurately associate real-time data sources from mixing plant control systems and laboratories. Avoids data confusion across nodes |
| Exception detection threshold | Slump deviation ±20 millimeters | Matches the industry’s general allowable slump deviation range. Triggers an exception branch process for manual review |

All configuration items above are compatible with FastGPT v4.17.0.

## Three common configuration errors
- Symptom: After deployment and container restart, workflow node configuration and knowledge base association relationships are lost. The interface displays blank content but the API returns normal data. Cause: The persistent storage directory for `variables` is not configured. Temporary cached variable mapping data is cleared after container restart.
- Symptom: When referencing business variables in the knowledge base search link, dedicated fields such as aggregate moisture content and slump for ready-mixed concrete cannot be matched. Cause: `variables` are not bound one-to-one according to business document fields. Undefined general variable placeholders are used.
- Symptom: The workflow’s exception detection node can only trigger a single processing process. Multi-round confirmation based on test block strength results is not possible. Cause: The workflow’s context retention setting is not enabled. Each node call only transmits context data for a single request.

## How to verify correct configuration
- Manually trigger the workflow once. Check if the generated bid document includes the latest business field data. Confirm that the `variables` binding configuration takes effect.
- View the workflow node trigger logs. Confirm that the process starts only after meeting the dual conditions of order confirmation and raw material inspection completion. Verify that the node trigger condition configuration is correct.
- Simulate a scenario where slump deviation exceeds the threshold. Check if the exception branch process is correctly called. Confirm that the exception detection threshold configuration takes effect.
- Restart the container and check the workflow configuration and knowledge base association relationships again. Confirm that the persistent configuration for `nodeId` takes effect.

The values provided here are common starting points. Adjust them based on your own specific samples and operational requirements.
