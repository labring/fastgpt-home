# Bid Document and Quotation Preparation for Ready-Mixed Concrete Production: Tool Calling and Plugins

## What this category's data looks like
Data sources include engineering orders, sand, gravel, cement admixture inspection records, moisture content test reports, mixing plant control systems, and project laboratories.
Data updates occur per vehicle production batch, per raw material delivery, and per daily scheduling cycle.
Daily documents include mix proportion notices, opening identification records, production and transport slips, raw material inspection reports, and test block strength reports.
Fields include material usage per cubic meter, transport scheduling duration, and test block compressive strength. Corresponding units are kilograms per cubic meter, minutes, and MPa.

## What constraints these characteristics impose on tool calling and plugins
High-frequency real-time data updates require tool calls to pull the latest production and inspection data. Static caching cannot be relied on.
Multiple heterogeneous data sources require plugins to adapt to interface formats of different systems. This includes different field mappings for mixing plant control systems and laboratory report systems.
Error consequences directly link to project quality and responsibility. This requires tool call configuration parameter verification and exception capture logic.
Test block strength requires age verification. Plugins must associate historical test block record data. This ensures performance commitments in quotations and bid documents match actual test results.

## How to set the configuration
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Workflow/API tool selection | `auto` | Automatically adapts to tool calling needs for ready-mixed concrete production scenarios, no manual specification of call type required |
| Workflow/API function-call configuration | `enabled` | Supports parallel calling of multiple tools, meets the need to pull data from multiple sources for bid document and quotation preparation |
| Tool call timeout period | `30–60 seconds` | Covers average time to pull data from mixing plants and query reports from laboratories, avoids excessive waiting that reduces generation efficiency |
| Data source synchronization frequency | Triggered per vehicle or per raw material batch | Matches data update frequency, ensures pulled production and inspection data are up to date |
| Exception retry count | `2–3 times` | Addresses call failures caused by temporary network fluctuations, while avoiding repeated triggering of production data pulls |
| Result verification rule | Calibrated according to actual measurements | Adapts to quality requirements of different projects, ensures generated content complies with on-site quality standards |

## Three common mistakes
- Phenomenon: Image URLs returned by tool calls cannot display normally in bid documents. Cause: The plugin's image resource whitelist is not configured, or the automatic rendering switch for URL content is not enabled.
- Phenomenon: Connection timeout error occurs when calling a local MCP service. Cause: The correct intranet address and port of the local service are not filled in the FastGPT plugin configuration, or access permissions for the corresponding port are not opened.
- Phenomenon: No thinking process is output after tool calling. Cause: The thinking process output switch is not enabled in the configuration, or `toolChoice` is set to forced tool call mode, skipping the natural language thinking step.

## How to confirm the configuration is correct
- Trigger a simulated bid document generation request. Check if the tool successfully pulls the latest mix proportion data and raw material inspection reports.
- Call the local MCP service interface. Check if the FastGPT plugin log returns correct business data.
- View the tool call return results. Confirm if they include thinking processes and detailed records of tool calls.
- Verify the configured image whitelist. Upload a test URL to confirm normal rendering and display.
