# Bid Document and Quotation Preparation for Beverage and Bottled Water: Document Parsing and Chunking

## What Data for This Category Looks Like
The main entities in this category are carbonated beverage, juice, tea, functional beverage, and packaged drinking water manufacturers. Daily generated documents include formula sheets, water treatment records, blending records, sterilization or aseptic filling records, packaging material inspection reports, and finished product inspection reports. Data comes from water source and raw material testing, formula systems, online sugar and acidity monitoring equipment, filling equipment, visual inspection systems, and LIMS systems. Update frequency follows per batch, per shift, or continuous collection. Most documents contain structured numerical fields and batch information, including feeding amount, online detection indicator values, production batch numbers, shelf life parameters, and similar fields.

## Constraints Imposed on Document Parsing and Chunking
Documents in this category combine structured numerical records and batch information. Data sources cover both automated equipment collection and manual entry scenarios. Parsing work must accurately distinguish between structured tables and free text paragraphs, and avoid separating numerical values from associated batch information. High-frequency continuously collected data generates a large number of short document fragments. Chunking work must divide boundaries according to production batches or bidding sections, to prevent mixing content across batches. Documents in this category also include industry-specific numerical values and units. After parsing, the binding relationship between fields and units must be retained, ensuring that chunked content can be directly called by subsequent quotation preparation links.

## Configuration Settings
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | `800–1200 characters` | This category’s documents include structured tables and continuously collected short data. This range balances the completeness of single-chunk content and retrieval efficiency |
| `chunkSplitter` | Split by paragraph and table boundaries | Documents mix text paragraphs and structured inspection tables. Splitting by boundaries preserves the logical integrity of content |
| `customPdfParse` | Enable | PDF documents in this category mostly include standardized inspection tables exported by equipment. Enabling custom parsing accurately extracts fields and numerical values within tables |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 seconds` | A single bidding document may include inspection records for multiple batches, resulting in long parsing time. This duration covers parsing needs for most scenarios |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | Bidding documents may include a large number of high-definition equipment inspection images and batch data tables. This upper limit meets single upload requirements |
| `chunkSettingMode` | Manual configuration | Documents in this category have large structural differences. Manual configuration allows flexible adjustment of chunking rules to adapt to different bidding document types |

## Three Common Misconfigurations
- Phenomenon: Some uploaded PDF documents have no structured table content or missing fields after parsing. Cause: The `customPdfParse` configuration is not enabled. The default parsing rule cannot accurately identify standardized inspection tables exported by equipment.
- Phenomenon: Parsing tasks time out and fail, with parsing timeout error prompts displayed on the interface. Cause: The uploaded bidding document includes continuously collected data from multiple batches, and parsing time exceeds the preset timeout threshold.
- Phenomenon: Chunked content spans production batches, and irrelevant batch detection data appears during retrieval. Cause: Splitting by batch boundaries is not performed as configured in `chunkSplitter`. The default chunking rule truncates by fixed character length, leading to merging of cross-batch content.

## How to Verify Configurations Are Correct
- Upload a single PDF document containing structured inspection tables, check if the parsed content fully retains table fields and numerical values, and confirm that the custom PDF parsing configuration takes effect.
- Upload a bidding document containing multi-batch data, check if the chunking results are divided by batch or section, and confirm that the chunking rules and chunk size configuration match the document structure.
- Upload a test document of preset size, confirm that the upload progress is normal and no file size limit exceeded prompt is triggered, verifying that the upload file size configuration is reasonable.
- Run a batch parsing test, confirm that the parsing task is not interrupted within the preset duration, and verify that the parsing timeout configuration adapts to the business scenario.

The values provided here are common starting points and should be measured against the reader's own samples.
