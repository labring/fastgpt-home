# PCB Manufacturing Inspection and Process Record Audit: HTTP Interfaces and External Systems

## What data for this category looks like
This category of data comes from Gerber files, drill files, BOMs provided by customers, as well as CAM system parameters, production equipment parameters, bath solution test results, AOI inspection reports, electrical testing reports, and laboratory slice reports. Data is updated per production batch, per shift, or via continuous collection. It includes fields such as engineering production instructions, drilling lamination parameters, chemical solution concentration records, defect coordinates, continuity test values, and more. Units include millimeters, ohms, ppm, and other units. A single production batch can be associated with over ten documents.

## Constraints on HTTP Interfaces and External Systems
Data sources for this category are scattered and have heterogeneous formats, including binary Gerber files, structured inspection reports, and proprietary equipment parameters. HTTP interfaces must support multi-format parsing and transparent transmission of original fields. Data is updated per production batch, per shift, or via continuous collection, so interfaces must support batch pulling and short-interval polling to adapt to high-frequency synchronization. A single batch can be associated with a large number of documents, so the `responseData` returned by the interface must support pagination to avoid excessive single-transmission load. Industry error consequences are directly linked to production losses, so interfaces must include complete error codes and context logs to facilitate quick location of abnormal links.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Interface timeout period | 30–60 seconds | Adapt to the parsing time of multiple documents per batch |
| `Authorization` | Fixed token or temporary session credential | Match the identity verification rules of factory production systems |
| `variables` | Pass production batch number, inspection type parameters | Accurately pull inspection and process records for the corresponding batch |
| `responseData` | Return in original format and retain industry-specific fields | Comply with data formats of downstream CAM and quality management systems |
| Retry times | 2–3 times | Respond to temporary network fluctuations or system temporary busyness |
| Polling interval | 10–30 seconds | Adapt to high-frequency data synchronization requirements for continuous collection |

## Three Common Misconfigurations
- Phenomenon: Associated images returned by the interface cannot be displayed in third-party systems, and the link format does not comply with rendering rules. Cause: The absolute path of image resources in `responseData` was not configured correctly, and only relative paths were returned, making cross-domain loading impossible.
- Phenomenon: Core fields such as production batch number and defect coordinates are missing from the `responseData` returned by the interface. Cause: Correct business parameters were not passed in `variables`, causing the interface to pull irrelevant data sets.
- Phenomenon: Interface calls frequently trigger timeout errors, with status code 504 returned. Cause: The set timeout period is too short, failing to adapt to the parsing and transmission time of multiple AOI and electrical testing reports.

## How to Verify Successful Configuration
- Call the test interface, pass the known production batch `variables` parameter, and check if the returned `responseData` includes the inspection and process record fields corresponding to this batch.
- After configuring the `Authorization` identity verification parameter, initiate a call using an invalid token, and confirm that the interface returns a corresponding identity verification failure prompt.
- Simulate the high-frequency call scenario of production batches, check if the load returned by the interface complies with the preset pagination rules, and there is no single-transmission overload problem.
- View the interface logs, confirm that the retry mechanism is automatically triggered during temporary network fluctuations, and no continuous failures occur.

The values provided are common starting points and should be measured against the reader's own samples.
