# Inspection and Process Record Audit for PCB Manufacturing: Tool Calling and Plugins

## What the Data for This Category Looks Like
Data for this category comes from customer-provided Gerber files, drill files, BOM lists, CAM system data, production equipment parameters, bath solution test results, AOI inspection reports, electrical test reports, and laboratory slice reports. Data is updated based on production batches, shifts, or continuous collection. Daily documents include engineering production instructions, drilling and lamination parameters, chemical analysis records, and various inspection reports. The number of associated documents per production batch increases with the number of board layers. Core fields include layer specifications, drill hole diameters, defect coordinates, and chemical solution concentration values. Some parameters use industry-specific units.

## Constraints for Tool Calling and Plugins
The data sources for this category are scattered and have varying formats. Tool calling plugins must adapt to multiple system interfaces and different document parsing rules to prevent data pull failures due to format incompatibility. The update rhythm tied to production batches and shifts requires tool calling trigger logic to align with production cycles, avoiding data lag or duplicate pulls. The number of associated documents per batch changes with the number of board layers. The context window for tool calling must reserve sufficient space to hold multiple document contents. Specialized parsing parameters must be configured for different document types such as Gerber files and inspection reports to ensure accurate data extraction. Errors may lead to full batch board scrapping or high-value claims. Tool calling must support multi-scenario calls via the `toolChoice` configuration. Result verification and retry logic must align with business risk levels.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Auto | Adapts to multiple tool calling scenarios including Gerber parsing and AOI defect analysis, and is compatible with the plugin management logic of FastGPT v4.17.0 |
| Single Search Limit | Top 6–10 entries | Matches the typical number of associated documents per production batch, to avoid overload during single calls |
| Reranking | Enabled | Resolves the issue where the model fails to sort long knowledge base retrieval results, ensuring key defect information is displayed first |
| Maximum Context | 7000–13000 token | Carries the full content of multiple engineering documents and inspection reports, adapting to the associated data volume of multi-layer PCBs |
| Tool Calling Timeout | 240–360 seconds | Matches the typical response cycle for production equipment data pulls, to prevent production stagnation due to excessive wait times |
| `functionCall` | Triggered based on tool return results | Ensures correct context association for tool calling, and aligns with the sequential order of business processes |

## Three Common Configuration Mistakes
- Long knowledge base retrieval results are not reranked, and the model outputs content directly in the original order. This occurs because the reranking configuration is not enabled, or the configuration parameters are not adjusted for the long text scenario of PCB inspection reports.
- Tool calling returns a 400 error with the prompt "Messages with role 'tool' must be a response to a preceding message". This occurs because the context of the tool call is not correctly associated with the preceding user query, or the role field configuration for the tool return message is incorrect.
- Module import failure and code runtime error occur during custom tool calling. This occurs because the corresponding Python dependency library is not installed in the deployment environment, or the dependency library version is incompatible with the FastGPT v4.17.0 runtime environment.

## How to Verify Proper Configuration
- A test query containing a Gerber parsing request is submitted via the plugin management module of FastGPT v4.17.0. Verification confirms whether the tool automatically calls the corresponding parsing plugin via `functionCall` and returns correct layer parameter results.
- Complete inspection reports and engineering documents for a single batch are imported. Verification confirms that the number of returned retrieval results matches the configured single search limit.
- A long-text knowledge base retrieval containing multiple inspection reports is triggered. Verification confirms whether the model reranks the results and outputs sorted key defect information.
- A tool calling timeout scenario is simulated. Verification confirms that the system returns a corresponding error prompt or automatic retry notification within the set timeout period.

The values provided are common starting points and should be evaluated against relevant operational samples.
