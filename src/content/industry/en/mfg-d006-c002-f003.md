# Inspection and Process Record Audit for SMT Mounting and Electronic Assembly: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Data sources include customer-provided BOMs, Gerber coordinate files, MES systems, solder paste and component batch records, placement machines, SPI/AOI equipment, and reflow oven temperature data. Data updates occur per work order, each line change, and in real time. Core documents include line change sheets, stencil records, first article confirmation forms, SPI/AOI reports, maintenance records, and traceability labels. Fields cover part numbers, reference designators, component batches, furnace temperature parameters, coordinate positions, and more. Units include degrees Celsius, millimeters, batch numbers, and similar units.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering
Data sources are scattered and updated in real time. Multi-turn dialogue must pull real-time latest data such as furnace temperatures and component batches to avoid using expired information. Field differences across multiple documents require prompts to clearly specify validation rules for corresponding documents. Examples include part number matching for BOMs and defect determination for SPI reports. Work order-level data association requires dialogue to bind a unique work order identifier, to prevent confusion of inspection contexts for the same work order. The high-frequency update feature also limits unrestricted context accumulation. Redundant content must be truncated appropriately.

## How to Configure Settings
Configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Maximum context length | 8000–12000 token, calibrated based on actual testing | Covers core validation content for single work orders involving multiple documents such as BOMs and SPI/AOI reports |
| `variables` | Bind part numbers and component batch numbers of the current work order | Matches core validation fields for SMT inspection, enables linkage between dialogue context and work order data |
| `chatId` | Bind unique work order number | Ensures dialogue history for the same work order is not confused, supports cross-session traceability of inspection records |
| `messages` truncation rule | Retain the first 15 valid interaction entries | Avoids context overload that disrupts validation logic |
| Dialogue history retention duration | 72 hours | Covers the full cycle from a single line change to completion of the entire work order |
| Prompt template embedded fields | Embed furnace temperature thresholds and line change sheet version numbers | Directly calls work order-specific configuration data, reduces manual input errors |

## Three Common Configuration Errors
- Background logs are deleted along with login-free dialogue sessions: Background operation logs display empty dialogue content, making inspection records untraceable. The root cause is failure to bind dialogue logs to `variables`, and login-free sessions are not associated with a unique work order identifier.
- MySQL tool calls return a 400 status code (no body): Database query nodes run without response content. The root cause is incorrect configuration of the `variables` parameter, and work order-specific database query conditions are not passed.
- Workflows fail to load historical global variables: Historical global variable fields read by workflow nodes are empty. The root cause is failure to associate historical sessions via `chatId`, and failure to correctly bind the scope of global variables.

## How to Verify Correct Configuration
- Initiate an inspection dialogue, input a work order number, confirm the dialogue automatically loads core fields of the corresponding BOM and line change sheet.
- Delete the dialogue content of a login-free session, check whether background logs retain the inspection records for that session.
- Run a database query node, confirm returned component batch and furnace temperature data matches the current work order.
- Switch to a different work order number to initiate a new dialogue, confirm the context does not mix with content from the previous work order.

The values provided here are common starting points and should be measured against the reader's own samples.
