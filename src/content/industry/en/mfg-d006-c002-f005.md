# Inspection and Process Record Audit for SMT Mounting and Electronic Assembly: Tool Calling and Plugins

## What this category of data looks like
Data related to inspection and process records for SMT mounting and electronic assembly comes from customer-provided BOMs, Gerber coordinate files, MES systems, mounting machines, SPI/AOI testing equipment, reflow oven temperature records, first-piece confirmation sheets, and maintenance traceability labels.
Updates occur per work order, each line change, and in real time, covering the entire production flow.
Daily documents include structured BOM lists, SPI/AOI reports in CSV format, time-stamped oven temperature curves, line change sheets, and component batch records.
Fields include part number, reference designator, component batch number, coordinate offset, oven temperature parameters, and more.
Units include millimeters, degrees Celsius, batch numbers, and others.

## Constraints on tool calling and plugins
High-frequency, multi-type data updates require tool calling to support real-time triggering and multi-format parsing adaptation. Format incompatibility will block inspection processes.
Fields are tightly bound to production steps. Tool calling parameters must accurately match specific fields such as part number and reference designator. Mismatches will cause errors in verification steps.
Errors directly lead to batch production failures. Tool calling results must undergo structured verification to prevent invalid or incorrect inspection data from entering the audit process.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `auto` | Automatically adapts to different types of inspection documents, no manual tool specification required, and supports multi-format data parsing needs |
| `functionCall` | `enabled` | Forces structured tool calling results, facilitating subsequent inspection data verification and audit |
| Single tool call timeout | 30–60 seconds | Matches real-time requirements of production steps, avoids work order processing blockages |
| Maximum tool call rounds | 3–5 | Controls resource usage, prevents excessive system load caused by circular calls |
| Plugin input format validation | Enabled | Adapts to FastGPT v4.17.0 plugin configuration logic, filters invalid non-production document inputs |

## Three common misconfigurations
- Document parsing tools return empty content. This occurs when the tool fails to adapt to proprietary formats such as Gerber coordinate files or SPI reports, leading to parsing failure.
- Occasional empty responses and 10-second timeout errors when calling in-house LLMs. This happens when reasonable tool call timeout settings are not configured, and occasional timeout logic on the LLM side is not handled.
- Plugin initial variables fail to take effect. This occurs when global variables are not correctly bound to tool call input parameters in plugin configuration, leading to variables not being loaded properly.

## How to verify correct configuration
- A test SPI report CSV file is uploaded, the document parsing tool is invoked, and it is confirmed that specified fields such as solder joint defect count and corresponding reference designators can be extracted.
- The `functionCall` parameter is enabled, a tool call is initiated, and it is confirmed that the returned result is structured JSON format with no redundant text.
- The single tool call timeout is adjusted to 45 seconds, 10 consecutive test calls are initiated, and it is confirmed that no blockages or timeout errors occur.
- Plugin initial variables are input, a tool call is triggered, and it is confirmed that variables are correctly passed to the tool's input parameters.

The values provided are common starting points and should be measured against the reader's own samples.
