# Inspection and Process Record Audit for Dairy Processing: Workflow Orchestration

## What the Data for This Category Looks Like
This category’s data covers the full process of raw milk acceptance, batching, heat treatment, filling, and sample retention. Data sources include milk source testing equipment, MES systems, homogenization and heat treatment equipment, online temperature and flow sensors, CIP cleaning systems, and LIMS laboratory management systems. Daily documents include raw milk acceptance records, standardized batching sheets, pasteurization or UHT heat treatment records, CIP cleaning records, filling records, and sample retention and microbial testing reports.
Data is updated in real time for every milk tank and production batch. Fields include antibiotic test values, heat treatment temperature and time, aseptic filling pressure, and corresponding testing units.

## What Constraints These Characteristics Impose on Workflow Orchestration
The real-time batch data and strongly linked document structure for this category require workflows to bind the batch ID in `variables` to ensure data from each step corresponds to the same milk tank or production batch.
Multiple heterogeneous data sources require workflows to support parallel pulling of testing and equipment data from different systems. This avoids serial delays that impact real-time performance.
The requirement for fields to include specific testing units means variable format validation rules must be configured in the workflow. These rules filter abnormal data that does not meet unit specifications.
Errors in production links can trigger large-scale risks. Workflows must include failure branches that trigger abnormal alerts and data traceability actions.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Variable Binding | Bind the batch ID and test item fields in `variables` | Match the strongly linked data requirement for each milk tank and production batch, ensure data from each step corresponds to the same production batch |
| Data Source Trigger Mode | Trigger in parallel by test node, equipment node, and LIMS node | Adapt to real-time synchronization requirements for multi-source data, reduce overall workflow runtime |
| Format Validation Rules | Configure antibiotic test value ranges, heat treatment temperature range 72-75℃, time precision to the second | Match field units and precision requirements for dairy processing, filter abnormal data |
| Failure Handling Branch | Configure an abnormal alert trigger node, bind Feishu multidimensional table writing | Address the high-risk consequences of production errors, promptly retain abnormal data and notify relevant personnel |
| Timeout Setting | 600-second timeout threshold | Adapt to the synchronization rhythm of real-time production data, avoid workflow blocking that impacts production processes |
| Node Output Storage | Bind the corresponding worksheet in the Feishu multidimensional table by `nodeId` | Ensure node output data is accurately stored in records for the corresponding production batch |

## Three Common Misconfigurations
- Workflow execution stops mid-run with no error: The workflow status remains in running, with no error logs or status prompts. The cause is that no timeout threshold is configured, or the timeout threshold is set too long. This exceeds the real-time waiting rhythm of the production link, causing the workflow to be automatically suspended by the system.
- Node output variables cannot be saved to the Feishu multidimensional table: The HTTP node call returns a non-200 status code, or no corresponding data is written to the multidimensional table. The cause is that the field mapping for the corresponding worksheet is not bound by `nodeId`, or Feishu API request header parameters are not correctly configured. This causes the interface call to fail.
- Prompt words cannot recognize spaces: The model’s parsed test item results lose fields separated by spaces, or cannot correctly match unit names that include spaces. The cause is that the prompt word does not explicitly specify spaces as field separators, or variable format validation rules are not configured to allow spaces. This causes the model to fail to correctly parse field content.

## How to Verify the Configuration Is Complete
- Simulate a single-batch raw milk acceptance process, trigger the workflow to run, check that each node executes in the configured parallel order with no blocking.
- View the workflow’s variable binding configuration, confirm that the batch ID in `variables` fully matches the batch fields of documents from each production link.
- Manually trigger the exception branch, check whether an alert is triggered and abnormal data is accurately written to the corresponding worksheet in the Feishu multidimensional table.
- Adjust the timeout threshold to 300 seconds, verify whether the workflow completes within the set time or triggers a timeout alert.

The values provided are common starting points and should be measured against the reader's own samples.
