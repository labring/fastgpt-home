# Inspection and Process Record Audit for Dairy Processing: Tool Calling and Plugins

## Data Profile for This Category
This category covers the full processing flow for liquid milk, yogurt, milk powder and dairy ingredients. Daily documents include raw milk acceptance records, standardized batching sheets, pasteurization/UHT heat treatment records, CIP cleaning records, filling records, reserved samples and microbial test reports. Data is sourced from raw milk testing equipment, production MES systems, homogenization and heat treatment equipment, online temperature and flow sensors, CIP systems, and LIMS laboratory management systems. Real-time synchronization occurs per milk tank and production batch. Fields include raw milk antibiotic and physicochemical indicators, heat treatment duration and temperature, filling environment parameters, and other items with standardized professional units.

## Constraints for Tool Calling and Plugins
This category of data updates in real time per milk tank and production batch. Tool calling must bind to real-time data source interfaces, and cannot rely on static offline documents. Professional fields across multiple production links have standardized units. Tool calling requires configured parameter validation rules to match the units and value ranges of corresponding fields. Document structures vary significantly across different production links. Dedicated tool calling trigger logic must be configured for scenarios such as raw milk acceptance, heat treatment and filling. Errors directly impact batch compliance. Tool calling must add a result pre-validation step to prevent abnormal parameters from triggering incorrect processes.

## Recommended Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Dynamically specified per production link | Adapts to dedicated tools and knowledge bases for scenarios including raw milk acceptance, heat treatment and filling, and matches real-time batch data calling requirements |
| `functionCall` | Enable parameter validation mode | Ensures tool calling values and units comply with dairy processing professional field specifications, and prevents parameter mismatches |
| Tool calling trigger timing | Triggered per production node | Matches the update rhythm per milk tank and production batch, and avoids invalid real-time polling calls |
| Single tool call timeout | 300–600 seconds | Adapts to long-cycle data acquisition needs for links such as heat treatment and CIP cleaning |
| Knowledge base recall limit | Top 3 batch-specific documents | Focuses on core records of the current production batch, filters irrelevant data to improve audit efficiency |
| Context window limit | 8000 token | Adapts to aggregation requirements for multi-link documents, and prevents exceeding model processing limits |
| Result cache duration | 24 hours | Matches the production batch cycle, and prevents data inconsistency caused by expired cache |

## Three Common Misconfigurations
- Phenomenon: Tool calling returns an abnormal format, including unclosed `<tool_call>` tags or mismatched parameters and units. Cause: Parameter validation mode for `functionCall` is not enabled, and dairy processing professional field specifications are not followed.
- Phenomenon: Tool calling logic for different production branches in the workflow is executed repeatedly, resulting in redundant calculations. Cause: Dynamic trigger rules for `toolChoice` are not configured per production link, and general tool calling configurations are reused.
- Phenomenon: Tool calling does not return valid data for the current production batch, with empty results or associated old batch records. Cause: Real-time data source interfaces are not bound, and static offline historical document data is called.

## How to Verify Correct Configuration
This verification process is designed based on the tool calling function of FastGPT v4.17.0.
- Trigger a test call for the corresponding production link, and check whether the tool calling parameters match the fields and units of the current batch.
- Review tool calling logs to confirm that only dedicated documents and data sources for the current production batch are called, and no irrelevant branches are triggered.
- Input simulated abnormal parameters, and verify whether the `functionCall` validation rules can intercept non-compliant calling requests.
- Run the complete workflow, and confirm that only the validation results returned by the tool are retained, with no redundant intermediate output content.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
