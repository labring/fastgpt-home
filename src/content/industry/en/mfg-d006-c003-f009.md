# Inspection and Process Record Audit for Dairy Processing: Model Integration and Configuration

## What this category of data looks like
Data for this category comes from raw milk testing, MES systems, homogenization heat treatment equipment, online temperature and flow monitoring, CIP systems and LIMS of liquid milk, yogurt, milk powder and dairy ingredient enterprises. Daily documents include raw milk acceptance records, standardized batching sheets, pasteurization/UHT sterilization records, CIP cleaning records, filling records, retained samples and microbial test reports. The data update rhythm is per milk tank, per batch or real-time. Fields cover raw milk antibiotics and physicochemical indicators, heat treatment time and temperature, CIP cleaning parameters, filling aseptic parameters and more, with units mostly including degrees Celsius, seconds, batch numbers and similar items.

## What constraints these characteristics impose on the "model integration and configuration" link
Data sources for this category are scattered, covering multiple types of production and testing systems, with update rhythms including real-time, per milk tank and per batch. Single-batch production documents include physicochemical indicators with specific units and time parameters. As such, model integration must support incremental synchronization configuration for multi-source data to ensure timeliness and accuracy of data pulling. At the same time, data errors can trigger serious production consequences, so result verification logic for the model must be configured to avoid misjudgments. Additionally, the continuous production characteristic requires the model's processing context to match the volume of single-batch production documents, adapting to short-cycle production record audits.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Adapts to the total character count of single-batch production documents, covering full-process records of raw milk acceptance, sterilization and filling |
| `maxTokens` | `2000–3000 token` | Balances model response speed and completeness of inspection results to meet rapid audit requirements |
| `quoteMaxToken` | `1500 token` | Retains original text references for key single-batch records to ensure audit results are traceable |
| `temperature` | `0.1–0.3` | Reduces random output, ensures consistency of inspection judgments, and is suitable for rigorous production audit scenarios |
| `AIPROXY_API_ENDPOINT` | Fill in the actual address of the deployed proxy service | Ensures network connectivity for model calls, adapting to the needs of enterprise intranet deployment |
| `AIPROXY_API_TOKEN` | Fill in the valid token generated by the proxy service | Completes identity verification for model calls, ensuring access permission compliance |

## Three common configuration errors
- When reordering models via configuration, a prompt indicates no available models. Cause: The API key and endpoint for the corresponding reordering model are not configured in the proxy service, or the configured token has insufficient permissions.
- When calling the model, an empty result is returned. Cause: The token generated by a third-party token management tool is not bound to the call permission of the corresponding model, or the token filling format is incorrect.
- The model output does not match actual production records. Cause: The `maxContext` configuration is too small, failing to cover the context of key production parameters, leading to the model being unable to obtain complete audit basis.

## How to confirm the configuration is complete
- In the model management module of FastGPT v4.17.0, initiate a model call test to confirm there are no identity verification or network error messages.
- Upload a single-batch production record document, trigger the audit process, and check whether the output includes judgment content corresponding to the production parameters.
- View the model call log, and verify that the API endpoint and token configuration information match the actually deployed service.
- Adjust the `temperature` parameter range, and verify whether the stability of the model output meets the rigor requirements of the audit scenario.

The values provided are common starting points and should be measured against the reader's own samples.
