# Inspection and Process Record Audit for Dairy Processing: Deployment and Upgrade

## Data Profile for This Category
Data for this category comes from milk source testing, production MES systems, homogenization and heat treatment equipment, online temperature and flow collection devices, CIP cleaning systems, and LIMS laboratory management systems. Data is synced in real time per milk tank and production batch. Daily documents include raw milk acceptance records, standardized ingredient lists, pasteurization or UHT heat treatment records, CIP cleaning records, filling records, retained sample and microbial test reports. Fields cover raw milk antibiotic and physicochemical indicators, heat treatment time and temperature, cleaning parameters, filling environment parameters, and more. Corresponding units include degrees Celsius, seconds, colony-forming units per milliliter, and others.

## Constraints Imposed by These Characteristics During Deployment and Upgrade
Real-time high-frequency data updates require configuring high-concurrency storage and cache links during deployment to avoid data backlog. Multi-field document structures with specific units require presetting parsing rules that match business fields before deployment, to avoid field extraction deviations from generic parsing. Independent data per milk tank and batch requires using a gray release strategy during upgrades, to ensure single-batch data processing is not affected. Interface requirements for connecting to production equipment and LIMS systems require reserving standardized interface configuration items during deployment, and verifying interface compatibility during upgrades to prevent production data sync interruptions. Additionally, production records involve compliance requirements, so data persistence must be ensured without loss during deployment and upgrade processes, to avoid impacting subsequent audits and traceability.

## Configuration Guidelines
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `REDIS_URL` | `redis://:custom password@server IP:6379/0` | This category has frequent data updates. Redis is used to cache frequently read equipment parameters and test results. This configuration ensures a stable cache link and avoids data read delays. |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.100:9000 (calibrated via actual testing)` | Process records and test report files for this category have large file sizes. Local or private object storage is required, and this address adapts to common private storage deployment scenarios. |
| `DB_MAX_LINK` | `200–300` | A single production batch generates multiple associated documents. The number of database connections under high concurrency must match production scale to avoid request failures from connection exhaustion. |
| `FILE_TOKEN_KEY` | `32-character random string` | Production records for this category involve internal business data. A dedicated token key must be configured to secure file access permissions. |
| `ROOT_KEY` | `Configured per enterprise internal permission rules` | FastGPT administrator permissions must match the enterprise's internal system management processes to avoid permission leaks that affect production data security. |

## Three Common Misconfigurations
- Phenomenon: After uploading a raw milk acceptance record, the interface shows a request failure, and no result is displayed after more than 2 minutes of parsing. Cause: Insufficient database connection count is not configured, leading to connection exhaustion under high concurrency, which prevents completion of file parsing and data extraction.
- Phenomenon: After starting the MCP server service, connection to production equipment data sources fails, or storage connection failure occurs during deployment on an enterprise all-in-one device. Cause: `STORAGE_S3_ENDPOINT` or `REDIS_URL` is not configured correctly, and the storage driver for the all-in-one device is not adapted, preventing the service from loading necessary cache and storage links.
- Phenomenon: After upgrading from version 4.8.10 to 4.9.9, historical records for some batches cannot be queried. Cause: The database data corresponding to `MONGODB_URI` was not backed up before the upgrade, or the database migration script was not executed, leading to incompatible data formats.

## How to Verify Successful Configuration
- Upload a standard raw milk acceptance record, and verify that the parsed fields match those in the business document.
- Check the cache service status corresponding to `REDIS_URL`, confirm that the connection is normal and there is no data backlog.
- Simulate uploading multiple batches of data, check the database connection usage, confirm that connection exhaustion does not occur.
- Perform a version upgrade operation, query historical production records, confirm that data is complete and accessible normally.

The values provided are common starting points and should be measured against the reader's own samples.
