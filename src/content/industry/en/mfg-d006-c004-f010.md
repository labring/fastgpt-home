# Inspection and Process Record Audit for Warehousing, Lot Tracking, and In-Plant Logistics: Knowledge Base Retrieval and Recall

## What this category's data looks like
This category's data primarily comes from ERP/WMS systems, barcode or RFID devices, procurement and work order documents, storage location management records, AGV or conveyor system data, and weighing measurement data. Daily documents include receiving slips, putaway slips, material picking and return slips, warehouse transfer slips, inventory checklists, lot ledgers, first-in first-out and expiration date records. Core fields include material codes, lot numbers, storage location numbers, inspection statuses, expiration dates, quantities and their corresponding units. Data update frequencies fall into three categories: real-time (such as barcode scanning, AGV scheduling), daily (such as inventory count summaries), and monthly (such as full warehouse inventory ledgers).

## What constraints these characteristics impose on knowledge base retrieval and recall
Data sources are scattered and update frequencies vary widely. The retrieval system must support incremental synchronization and incremental recall across multiple data sources to avoid performance losses from full retrieval. Documents are strongly bound to lots. Core matching fields are unique identifiers like lot numbers and storage location numbers. Retrieval must precisely match associated fields to prevent mismatching material data from different lots. The number of daily documents grows with lot scale. The number of results per single retrieval must be controlled to avoid exceeding context processing limits. The business scenario involves cross-process material flow tracing. Retrieval results must associate multi-dimensional information such as work orders and storage locations. Returning only a single document cannot meet requirements.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.80 | This category requires strict matching of core fields such as lot numbers and storage location numbers. A threshold that is too low will introduce irrelevant material data. A threshold that is too high will miss matching expiration date or inspection status information. Calibrated based on actual testing. |
| `limit` | Top 8–12 entries | This category has many documents associated with a single lot. Too many results will exceed the context processing limit. Too few results will miss multiple document pieces required for complete delivery. |
| `searchMode` | Precise matching mode | This category's business scenario has high requirements for matching accuracy. Precise matching mode ensures retrieval results are strictly associated with the target lot and storage location, avoiding mismatches caused by fuzzy matching. |
| `usingReRank` | Enabled | This category has strong correlations between document fields. Reranking filters out results that only match keywords but do not match the lot, improving the accuracy of final responses. |
| `datasetSearchUsingExtensionQuery` | Enabled | This category has a large number of professional business terms, such as AGV scheduling, slow-moving materials, expiration date alerts, etc. Extended queries can supplement synonyms or associated terms, improving recall coverage. |
| `collectionIds` | Bind the dataset IDs corresponding to warehousing and lot management | Narrow the retrieval scope, avoid retrieving irrelevant production work orders or general quality inspection documents, and ensure results only cover business data for this category. |

## Three common configuration errors
- Symptom: After importing static pages into the knowledge base, automatic synchronization fails when page content is updated. Cause: No automatic update trigger rules are configured. Only manual import is used, and the incremental update interface of the data source is not connected.
- Symptom: The first question is answered correctly, but the second question in the same window is off-topic. Cause: No automatic context cleanup or context length limit is set. Historical conversation context interferes with retrieval and recall for new questions, and the model confuses the association logic between previous and current questions.
- Symptom: Retrieval results cannot accurately match the expiration date information of the target lot. Cause: `usingReRank` or `datasetSearchUsingExtensionQuery` is not enabled. Recalled results are not optimized through reranking, and extended queries for business terms are not supplemented. Recall results have insufficient relevance.

## How to confirm the configuration is complete
- Check the dataset update log in FastGPT v4.17.0 to confirm that update tasks for static pages or ERP data sources trigger automatically at the preset frequency (real-time/daily/monthly).
- Submit a test query, enter a specific lot number, and verify that retrieval results include associated documents such as receiving slips and inventory checklists corresponding to that lot, and that the number of results falls within the preset `limit` range.
- Switch `searchMode` between fuzzy matching and precise matching modes, compare the matching accuracy of retrieval results, and confirm that the current setting meets business requirements.
- Submit multiple consecutive rounds of queries, confirm that conversation context does not interfere with retrieval and recall for subsequent questions, and that results from the second query are strongly correlated with the current question.
