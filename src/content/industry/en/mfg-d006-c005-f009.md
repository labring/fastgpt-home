# Inspection and Process Record Audit for Photovoltaic Cell Manufacturing: Model Access and Configuration

## What the data for this category looks like
Inspection and process record data from photovoltaic cell manufacturing links typically originates from silicon wafer incoming material ledgers, workshop MES systems, operation logs of diffusion furnaces, coating equipment, or printing presses, output results of EL and IV testing equipment, and laboratory quality inspection reports. Commonly retained documents include process cards, process parameter records, printing and sintering process ledgers, EL inspection images, IV performance grading data, and batch yield reports.

Data update rhythms shift synchronously with production batches, single-piece test results, and daily summaries. A single record includes fields such as process parameter values, test image files, grading results, and yield identifiers. Some parameters have clear unit identifiers.

## What constraints these characteristics impose on model access and configuration
The multi-source heterogeneous data characteristics of this category impose multi-dimensional constraints on model access and configuration.
Structured process parameters, unstructured EL inspection images, and text records coexist. Multi-modal interaction-enabled model access items must be configured.
High-frequency batch-level and single-piece-level data updates require model calls adapted to small-context, low-latency request logic.
Significant differences exist in document fields across different production processes. Flexible matching rules for context extraction must be adjusted to adapt to different data source formats.
Single records include image files and numerical parameters. Sufficient token quota must be reserved to fully carry content.

## How to Configure
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to the total length of process records, inspection data, and yield reports for a single batch, avoiding truncation of critical information |
| `maxTokens` | 4000–6000 token | Matches the audit output requirements for single-piece test results, balances generation quality and call costs |
| `vision` | Enabled | Supports visual recognition of EL inspection images for automatic audit of defects such as hidden cracks and color differences |
| `temperature` | 0.1–0.3 | Reduces generation randomness, ensuring consistent results for process parameter audits |
| `AIPROXY_API_ENDPOINT` | Fill in the access address provided by the model service provider | Adapts to the call path of third-party models, such as exclusive endpoints from Alibaba Bailian platform |
| `AIPROXY_API_TOKEN` | Fill in the access key assigned by the platform | Completes identity verification for model calls, ensuring interface access security |

## Three Common Misconfigurations
- A 401 status code is returned when calling Tongyi Qianwen-Max from Alibaba Bailian. The cause is incorrect `AIPROXY_API_TOKEN` entry or non-compliant address format for `AIPROXY_API_ENDPOINT`.
- Defect information is not detected during EL inspection image audit. The cause is that the `vision` configuration item is not enabled, and the model cannot process unstructured image data.
- A timeout error occurs when batch auditing multiple batches of data. The cause is that the `maxContext` value is too large, causing the single request context load to exceed the model interface limit.

## How to Verify the Configuration is Complete
- Go to the model management page in the FastGPT backend, check the configured items of the accessed model, and confirm that the values of `vision`, `maxContext` and other parameters match the preset configuration.
- Upload a single EL inspection image and corresponding process parameter record, initiate a test call, and check if the model outputs audit results including defect recognition and parameter verification.
- Simulate batch data requests, observe interface return status codes and response durations, and confirm that no timeout or permission errors occur.
- Verify the audit content generated by the model, and confirm that the matching degree between referenced document fragments and original data fields meets expectations.

The values provided are common starting points and should be evaluated against the reader's own samples.
