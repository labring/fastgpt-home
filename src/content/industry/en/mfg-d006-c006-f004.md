# Inspection and Process Record Audit for Photovoltaic Module Encapsulation: Workflow Orchestration

## What Data for This Category Looks Like
Photovoltaic module encapsulation inspection and process record data sources include the cell grading system, glass adhesive film backplane batch ledger, production MES system, string welding and lamination equipment terminals, EL defect detector, and IV power tester. Data update rhythm: one independent record is generated for each module, and batch ledgers are updated synchronously for each batch of raw materials. Daily documents include module layout diagrams, material batch records, lamination process parameter sheets, EL crack images, IV test reports, insulation withstand voltage records, and finished product packing lists. Core fields include module unique identifier, cell current grade, lamination temperature and time, EL defect coordinates, IV power value, with units including ℃, seconds, W, mm, etc.

## Constraints Imposed by These Characteristics on the "Workflow Orchestration" Link
Multi-source heterogeneous data sources require workflows to support docking with different types of equipment and system interfaces to avoid data format conversion errors. The update rhythm of per-module or per-batch updates requires workflow trigger nodes to bind unique identifiers as trigger conditions, ensuring each data entry is processed only once. Diverse document types require workflow configurations to adapt to parsing nodes for different formats such as images, tables, and text, covering links such as EL image interpretation and process parameter verification. The time-consuming nature of core business links requires setting reasonable timeout thresholds for key nodes in the workflow to avoid process blocking. The severity of error consequences requires workflows to be configured with error capture and retry mechanisms to intercept abnormal data in a timely manner.

## How to Set the Configurations

| Data Source Trigger Rule | Trigger by single module ID or batch ID | Matches the independent update rhythm of each module and each batch of materials |

## Three Common Misconfigurations
- Boolean value shows as true but downstream judgment node returns false: Phenomenon: The upstream node status in the interface is marked as true, but the downstream judgment node log shows the judgment result as false; Cause: The fields bound in `variables` are not correctly passed to the downstream node, causing the judgment condition to lack key parameters.
- Workflow tool call cannot reference knowledge base content: Phenomenon: Calling the knowledge base module returns empty results or fails to match relevant documents; Cause: The corresponding category process knowledge base is not bound in the configuration, or the context window setting does not cover the valid content of the document.
- Code execution module fails to import libraries: Phenomenon: A prompt indicating missing imported dependency libraries appears when running code; Cause: The corresponding dependency libraries are not installed in the Python environment of the FastGPT v4.17.0 container, or the dependency library versions do not match the code requirements.

## How to Verify the Configuration Is Correct
- Trigger a simulated module data upload, check whether the status logs of each node are consistent with the business process sequence of string welding, lamination, and testing.
- Simulate scenarios of device disconnection or abnormal data format, verify whether the error capture node triggers an alarm or executes the preset retry process.
- Check whether the fields bound in `variables` completely match the device data fields collected, to avoid parameter misalignment.
- Call the tool to test the knowledge base association module, confirm that it can return process reference content corresponding to the category to meet current business needs.
