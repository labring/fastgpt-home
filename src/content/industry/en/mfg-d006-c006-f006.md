# Inspection and Process Record Audit for Photovoltaic Module Encapsulation: Source Citation and Traceability

## What Data for This Category Looks Like
Data for this category originates from the wafer grading system, glass adhesive film backplane batch ledger, factory MES system, stringing and lamination production equipment, and EL and IV testers. Daily generated documents include module layout diagrams, material batch records, lamination process parameter records, EL defect images, IV power test reports, insulation voltage withstand test records, and finished product packing lists. Data updates follow one set of process records per module, with batch ledgers updated synchronously for each raw material batch. Fields include equipment operating parameters, test values, batch numbers, operator information, and additional relevant details.

## Constraints Imposed by These Characteristics on Source Citation and Traceability
The high-frequency update feature for individual modules and batches requires the citation and traceability system to support precise matching of full-link process records for a single module. This prevents information confusion across batches or modules. Document types include graphic and text files such as layout diagrams and EL defect images, and numerical files such as IV test reports. The system must support associated citation and precise matching of multimodal data sources. Data sources cover production equipment and management systems. The system must ensure cited content can be traced back to the original collection node to maintain information originality. Fields include equipment operating parameters, test values, batch numbers, and other details. Traceability requires precise extraction of original content for corresponding fields to meet the accuracy requirements of audits.

| `quoteMaxToken` | 900–1100 token | Adapts to the total length of full-link process documents for a single module, avoiding truncation of key process parameters and test data |
| `responseData` | Includes EL image metadata, original IV test report content | Meets the requirement to retrieve original test records during audits |
| `detail` | Enabled | Displays specific fields of citation sources, collection time, and equipment numbering to facilitate traceability of process details |
| Single recall citation count | Top 4–6 entries | Matches the number of core process documents for a single module, avoiding redundant information interfering with audits |
| Citation similarity threshold | 0.72–0.88, calibrated via actual testing | Filters batch records unrelated to the current module, ensuring cited content matches precisely |
| Context window length | 1500–2000 characters | Accommodates content from multiple associated documents for a single module, ensuring continuity of audit logic |

## Three Common Errors
- Retrieval fails to associate the dedicated knowledge base for the corresponding module, returning material records from other batches and displaying citation sources. The cause is that no filtering rule based on module batch ID was configured, leading to recall of irrelevant data across batches.
- A citation count limit is set, but the interface returns citations exceeding the limit. The cause is that no citation count truncation logic was added to the retrieval process, leading to unfiltered recalled raw data.
- When calling knowledge base citation variables in the application, an error message about incorrect parameters is returned. The cause is that the binding between module batch ID and knowledge base retrieval parameters was not configured correctly, leading to variable transfer format not meeting system requirements.

## How to Confirm Proper Configuration
- Submit an audit request for a single module, check that returned citation sources only include process documents corresponding to that module, adjust the citation filtering threshold until the expected range is matched.
- View the detailed content of each citation, confirm that original test reports, EL image metadata and other content required by configuration items are displayed, verify that the `detail` and `responseData` configurations are active.
- Count the number of returned citations, confirm that it meets the configured single recall citation count requirement, verify that the truncation logic related to `quoteMaxToken` is working properly.
- Simulate the application variable transfer process, confirm that no parameter errors occur when calling knowledge base citations, verify that the binding rules between variables and retrieval parameters are correct.
