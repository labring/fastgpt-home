# Inspection and Process Record Audit for Stamping and Sheet Metal Forming: Source Citation and Traceability

## What This Category's Data Looks Like
This category of data is collected from multiple types of business documents and equipment data in automotive panel, household appliance sheet metal, and hardware stamping workshops. Daily documents include stamping work instructions, material utilization sheets, mold inspection logs, first and last piece records, dimensional inspection reports, and mold change records. Raw data sources include steel coil labels and quality certificates, punch and feeder operation data, mold management systems, MES systems, and coordinate measuring machine or inspection fixture test data. Data updates trigger per steel coil, production batch, and each mold change operation. Document fields include heat number, stamping count, dimensional tolerance, mold change time, and corresponding units such as MPa, counts, mm, and hours.

## Constraints Imposed on Source Citation and Traceability by These Characteristics
The high-frequency, small-batch updated data and multi-source heterogeneous nature of this category require the citation and traceability link to accurately match associated data for production batches and mold change nodes. After a single mold change or steel coil change, reference to old data must strictly adhere to timeliness limits to avoid invalid cross-batch traceability. Field differences across multiple document and equipment data types require unified association keys during traceability. For example, use heat numbers to link steel coil quality certificates and material utilization sheets, and use mold change numbers to link mold inspection logs and stamping records. Without these keys, traceability matching failures will occur. Additionally, the batch production attribute of stamping requires traceability results to cover all associated documents of the corresponding batch, to avoid missing key inspection basis.

## Configuration Settings
These configurations are based on the logic of FastGPT v4.17.0:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Matches the total character volume of stamping-related documents for a single batch, avoids truncating key inspection, mold change, and material utilization data |
| `responseData` | Enabled | Supports outputting original document fragments cited from the knowledge base in the answer body, meeting traceability display requirements for inspection audits |
| `detail` | Enabled | Displays specific fields and source identifiers of cited documents, facilitating verification of information such as steel coil heat numbers, stamping counts, and mold change times |
| Single search limit | Top 6–10 entries | Covers core associated data for a single mold change or steel coil batch, avoiding redundant information that interferes with audit judgments |
| Maximum context duration | `500–700 seconds` | Matches the batch processing cycle of stamping production, ensuring traceability data covers the complete production process |

## Three Common Configuration Errors
- When `responseData` is not enabled, the answer body cannot display original document fragments cited from the knowledge base, only generated summary content is shown. This configuration item controls whether cited knowledge base data is synchronized to the generated result. When disabled, only large model generated content is retained.
- When `quoteMaxToken` is set above 1500 tokens, the system will truncate some associated stamping workshop document data, leading to missing key content of mold change records or dimensional inspection reports during traceability. This occurs because the token limit exceeds the total character capacity of single-batch associated documents, triggering the system's automatic truncation logic.
- When the single search limit is set above 12 entries, the context will contain a large amount of irrelevant historical batch data, causing the large model to fail to accurately match the current batch's inspection basis. It may also trigger an error that the context exceeds the limit and cannot be sent to the large model. This happens because excessive redundant data exceeds the system context's capacity threshold, blocking the model call process.

## How to Confirm Configuration Is Correct
- Initiate an inspection and audit query for the current stamping batch, check whether the answer body contains cited original document fragments, to confirm that the `responseData` configuration is effective.
- Check whether the citation source identifiers include fields such as steel coil heat numbers, mold change numbers, and detection time, to confirm that the `detail` configuration is enabled.
- View system logs or interface prompts to confirm that no context limit exceeded errors occur, verifying that the `quoteMaxToken` and single search limit configurations are reasonable.
- Manually check the field matching degree between the cited document fragments and actual production records, to confirm that association keys such as heat numbers and mold change numbers are set correctly.

The values provided are common starting points and should be measured against the reader's own samples.
