# Inspection and Process Record Audit for Cosmetics Manufacturing: Tool Calling and Plugins

## Data Profile for This Category
Data sources for this category include registered or archived formulas, raw material safety documents, weighing and emulsification equipment, ERP/MES systems, laboratory test results, and packaging material version files.
Data is updated per production batch and each production line changeover.
Daily documents include formula process sheets, weighing and feeding records, emulsification or filling records, site cleaning records, semi-finished and finished product test reports, and label review forms.
Core fields include restricted substance content of raw materials, emulsification temperature, production batch number, and packaging material version number. Corresponding units are percentage, degrees Celsius, batch number, and version string.

## Constraints for Tool Calling and Plugins Workflow
The high-frequency update pattern (per production batch and line changeover) requires tool calling to support real-time pulling of the latest batch formulas, test records, and packaging material versions. This prevents use of expired cached data.
Plugins must support structured ERP/MES data and unstructured laboratory test reports to accommodate multiple data sources. Configuration of pulling permissions and format conversion rules for each data source is required.
Archiving constraints for formulas and labels require tool calling to link to the archiving database for field validation. Preconditions for triggering validation must be set.
The data volume of a single production batch requires limiting the range of plugin return results. This prevents execution exceptions caused by excessive context load.

| Workflow/API tool selection | `auto` | Supports automatic matching of multi-source data calling needs, adapting to different tool scenarios such as formula verification and record audit |
| Workflow/API function-call configuration | `Enabled` | Forces the model to execute tools via function calls, ensuring test logic is traceable and meeting production compliance requirements |
| Tool call timeout | `600 seconds` | Compatible with time-consuming operations such as laboratory test report parsing and archiving database queries, avoiding process interruption |
| Plugin data source pulling scope | Current batch associated data | Matches the update rhythm of batch and line changeovers, only pulling documents and data for the current production batch to reduce context redundancy |
| Verification rule trigger timing | After each production batch is completed | Aligns with cosmetics batch-based management logic, ensuring every product batch undergoes compliance verification for inspection and records |

## Three Common Configuration Errors
- Phenomenon: After a custom plugin runs, the output download address flickers repeatedly before returning a result. Cause: The triggering timing for data source pulling is not configured, causing the plugin to repeatedly pull expired batch data and leading to execution delays.
- Phenomenon: After workflow A calls workflow B, workflow B cannot complete its full execution. Cause: Necessary pre-steps are not configured in workflow B, and no return trigger condition for call results is set, causing the process to interrupt midway.
- Phenomenon: An `Error: write EPROT` prompt appears when calling a third-party interface. Cause: HTTPS certificate verification rules between FastGPT and third-party systems are not correctly configured, or network connections have permission restrictions, leading to data transmission failure.

## How to Verify Successful Configuration
- Trigger a simulated batch production process. Verify that tool calling only pulls current batch associated data, with no expired data mixed in.
- Run an inspection and audit task. Confirm that the model executes tools via function calls. Specific call records can be viewed via system logs.
- Complete one data interaction by calling a third-party interface. Confirm there are no permission or certificate related error messages, and the interaction complies with preset verification rules.
- Simulate a time-consuming laboratory data parsing operation. Confirm that the tool calling process is not interrupted due to timeout, and meets the configured time threshold.

The values provided are common starting points and should be validated against in-house operational samples.
