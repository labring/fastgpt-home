# Inspection and Process Record Audit for Chemical Pharmaceutical Dosage Production: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Inspection and audit data for chemical pharmaceutical dosage production comes from approved formulation processes, MES electronic batch records, LIMS systems, and quality management systems. Updates occur per production batch, each critical process step, and per established monitoring plans. Daily documents include master production documents, batch production records, batch packaging records, cleaning validation records, inspection records, deviation/CAPA/change documents, and batch release audit forms. Data fields cover material batch numbers, process parameters, test results, deviation descriptions, and more. Corresponding units include weight, temperature, time, concentration, and others.

## What Constraints These Characteristics Impose on the Multi-turn Dialogue and Prompt Engineering Link
Multi-turn dialogue and prompt engineering configurations for this category must adapt to traits including scattered data sources, frequent updates, complex document structures, and strict audit requirements. First, data from multiple systems must be linked to the corresponding production batch during dialogue. Strictly limit the context scope to avoid mixing data across batches. Second, the volume of documents for a single batch is large. Control the length of the dialogue window to ensure interactive response efficiency. Third, different document types have dedicated audit rules. Prompts must clearly distinguish field requirements. Finally, audit results directly relate to batch release. Ensure the accuracy and traceability of dialogue context by binding a unique dialogue identifier to isolate interactive data across different batches.

## How to Configure the Setup
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
|---|---|---|
| `messages` | Retain only the first 10 valid interactions of the current production batch, filter irrelevant historical data | Batch record audits for chemical pharmaceuticals only require the interaction context of the current batch to avoid redundant information interfering with model judgment |
| `variables` | Bind the material batch number, production workshop, and process parameters of the current batch | Ensure the dialogue only links to exclusive data for the current production batch, preventing cross-batch audit errors |
| `chatId` | Generate a unique identifier based on the production batch number | Isolate dialogue contexts across different production batches, enabling data traceability and isolation |
| Maximum context length | 8000–12000 characters | Adapt to the average data volume of single-batch production records, avoiding content truncation due to exceeding window limits |
| Historical dialogue transmission rule | Automatically carry the first 5 historical interactions | Balance context completeness and interactive response speed, aligning with the interaction logic of the audit process |
| Prompt template binding | Load corresponding verification rules by document type | Differentiate audit requirements for batch production records, inspection records, and deviation reports |

## Three Common Configuration Errors
- Workflow dialogue displays failures, but model tests work normally and background response logs exist. The cause is failure to correctly bind the current batch's `variables` parameter, preventing the model from obtaining verification data such as material and process information for the corresponding batch.
- The default model when calling tools does not match the scenario requirements. The cause is failure to specify a dedicated model in the dialogue configuration, resulting in the default call of a general model not adapted to the pharmaceutical audit scenario.
- Dialogue logs are empty, and historical interactions cannot be brought into tool calls. The cause is failure to correctly generate a `chatId` bound to the production batch, or failure to enable context persistence configuration, resulting in historical `messages` not being effectively stored.

## How to Verify the Configuration Is Correct
- Initiate a test dialogue, enter the material batch number of the current batch, and verify that the returned context only includes relevant record data for that batch.
- Trigger a tool call, and check whether the log carries the historical interaction content corresponding to the `messages` parameter.
- Check whether the bound `variables` in the configuration items include the batch record fields required for the current scenario.
- Switch test data for different production batches, confirm that the dialogue context does not mix across batches.
