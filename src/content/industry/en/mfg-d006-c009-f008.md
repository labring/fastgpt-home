# Inspection and Process Record Audit for Chemical Pharmaceutical Dosage Production: Document Parsing and Chunking

## What Data for This Category Looks Like
Data for this category originates from approved prescription processes, material batch ledgers, MES systems, electronic batch records, equipment and environmental monitoring data, LIMS, and quality management systems. Daily documents include master production files, batch production records, batch packaging records, cleaning records, inspection records, deviation/CAPA/change documents, and batch release review forms. Data is updated per production batch, each critical process step, and per monitoring plans. Documents include clear fields for material batch numbers, weighing values, process parameters, deviation descriptions, and release decisions. These fields have units linked to corresponding production or quality standards.

## What Constraints These Characteristics Impose on Document Parsing and Chunking
This category has a high proportion of structured documents. These include feeding tables that associate material batch numbers with weighing values. They also include process execution records arranged by step. Document parsing and chunking must retain relational connections between data points. It must avoid losing field binding logic after splitting. Single-batch documents have coherent content arranged in order of production steps. Chunking must adapt to the complete logic of a single step or single-batch record. It must prevent disruption to the continuity of business processes. Documents integrating data from multiple sources require distinguishing content blocks from different system sources. Fields also have clear units. Chunk separators must balance text paragraphs and table boundaries. It must avoid table misalignment or field splitting.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the content length of a single process step in a single-batch record, retains complete association between material batch number and weighing value fields |
| `chunkSplitter` | Split by paragraph and table boundaries | Matches the structured table and coherent paragraph structure of documents in this category, prevents table misalignment during parsing |
| `customPdfParse` | Enabled | Adapts to PDF documents with multiple structured tables in this category, improves parsing accuracy for complex format files |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 seconds | Single-batch documents typically contain multiple pages of structured content, reserve sufficient time to complete full parsing |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Adapts to the upload size of complete single-batch production documents, prevents parsing failure due to oversized files exceeding limits |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules for the specific document structure of this category, meets the strict requirements of production quality documents |

## Three Common Mistakes
- Table misalignment appears after uploading a PDF, with cell content scrambled in parsing results. This occurs when `chunkSplitter` is not configured to split by table boundaries. The default chunking rules do not adapt to structured table structures.
- An analysis failure status is returned after uploading a file via the agent API. This occurs when `customPdfParse` is not enabled, or when `UPLOAD_FILE_MAX_SIZE` is set smaller than the actual size of the uploaded file, exceeding upload limits.
- Parsing is interrupted due to timeout, with a timeout prompt displayed on the interface. This occurs when `PARSE_FILE_TIMEOUT_SECONDS` is set to a value smaller than the actual time required for parsing, with insufficient time reserved for processing multi-page structured documents.

## How to Verify Proper Configuration
- Upload a batch record PDF that includes a structured feeding table. Check if the parsed table retains the binding relationship between cells and corresponding material batch numbers, to confirm the `chunkSplitter` configuration is active.
- Upload a complete single-batch production document. Verify that parsing completes within the duration set by `PARSE_FILE_TIMEOUT_SECONDS`, with no timeout errors.
- Upload a test file via the agent API. Confirm no parsing failure status is returned, to verify the `customPdfParse` and `UPLOAD_FILE_MAX_SIZE` configurations are correct.
- Manually adjust the `chunkSize` value. Upload process documents of different lengths, confirm that chunking results match the expected content length range.

The values provided are common starting points, and should be measured against the reader's own samples.
