# Inspection and Process Record Audit for Finished Chemical Pharmaceutical Production: Deployment and Upgrade

## What the data for this category looks like
Documents involved in inspection and process record audit for finished chemical pharmaceutical production include master production files, batch production records, batch packaging records, cleaning records, inspection records, deviation/CAPA/change documents, and batch release review forms. Data sources cover approved formulation processes, material batch information, MES systems, electronic batch records, equipment and environmental monitoring data, LIMS systems, and quality management systems. Data is updated per production batch, each critical process step, and per fixed monitoring plans. Document fields include material batch numbers, process execution parameters, inspection results, deviation numbers, release review opinions, and more. These cover compliance records across the entire production lifecycle.

## What constraints these characteristics impose on deployment and upgrade
Multi-source heterogeneous data sources require supporting integration with multiple internal systems at deployment. This avoids compliance risks from manual data import. High-frequency update cycles require configuring incremental synchronization mechanisms. This ensures data from each batch is synced to the platform in a timely manner. Complex document structures and diverse field types require the platform to support parsing and indexing of multiple document formats. It must also meet full-chain data traceability requirements. Severe consequences of errors require configuring failure retry and alert mechanisms at deployment. This prevents compliance issues caused by missing or incorrect data.

## How to set the configuration
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://fastgpt:xxxx@10.0.0.1:27017/chemical_pharma?authSource=admin` | Stores multiple types of batch production and inspection records, adapts to indexing requirements for complex document structures, and meets compliance traceability requirements |
| `REDIS_URL` | `redis://:xxxx@10.0.0.2:6379/1` | Caches frequently queried material batch and process parameter data, reduces call latency across systems such as MES and LIMS, and improves audit efficiency |
| `STORAGE_S3_ENDPOINT` | `http://s3.internal:9000` | Stores compliant documents such as electronic batch records and cleaning records, supports batch upload and management of large files |
| `DB_MAX_LINK` | `15–25` | Handles audit tasks for multiple batches simultaneously, prevents database connection exhaustion, and ensures stable batch import workflows |
| `FILE_TOKEN_KEY` | `Randomly generated 32-character encrypted string` | Encrypts file access tokens, ensures compliance of document access permissions, and meets GMP requirements for data access control |

This configuration applies to FastGPT v4.17.0

## Three Common Mistakes
- After uploading batch production records or inspection records, the file parsing result is empty, and `400 Bad Request` is returned. The cause is that a valid `FILE_TOKEN_KEY` is not configured. This causes file access permission verification to fail, and the uploaded document content cannot be read.
- After multiple department users log in simultaneously, they cannot view batch records corresponding to their permissions, and `403 Forbidden` is returned. The cause is that permission grouping for `ROOT_KEY` is not configured correctly. Access scopes for departments such as production and quality control are not differentiated.
- Task timeout with no response occurs when batch importing multiple batches of inspection records. The cause is that the value of `DB_MAX_LINK` is not adjusted. This exceeds the database connection limit, causing batch processing tasks to interrupt.

## How to Confirm Proper Configuration
- Batch import multiple compliant documents of different types. Confirm that the storage path matches the storage bucket configured via `STORAGE_S3_ENDPOINT`.
- Conduct simultaneous access tests with multiple users. Confirm that the document access scope for each user aligns with the preset permission configuration.
- Check database connection logs. Confirm that the current active connection count does not exceed the value set for `DB_MAX_LINK`.
- Upload a single large electronic batch record. Confirm that the upload and parsing processes have no errors.

The values given are common starting points and should be measured against the reader's own samples.
