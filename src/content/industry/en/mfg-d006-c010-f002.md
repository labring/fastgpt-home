# Inspection and Process Record Audit for Medical Device Assembly and Clean Production: Vector Models and Indexes

## What Data Looks Like for This Category
This category covers manufacturers of disposable medical consumables, implantable and interventional devices, diagnostic equipment, and active medical devices. Daily documents include production process specifications, batch production records, clean zone records, sterilization batch records, inspection reports, software version records, adverse event materials, and traceability data.

Data sources include design history files, device and material batch ledgers, MES systems, clean environment monitoring equipment, sterilization equipment, and inspection and calibration systems. Data updates are triggered per batch or per product. Clean zone records are updated regularly per environmental monitoring plans.

Documents include structured fields for batch numbers and unique device identifiers, plus semi-structured process parameters and monitoring data.

## What Constraints Do These Characteristics Impose on Vector Models and Indexes
Data sources are scattered and linked to batches and unique device identifiers. Vector indexes must bind metadata to enable precise filtering by business dimensions.

Data updates follow a per-batch or monitoring plan schedule. Incremental index triggers must align with this update rhythm to avoid missing newly generated inspection and record data.

Document structure varies widely. Some documents are long text process specifications, while others are short text single inspection reports. Vector chunking must balance semantic completeness and retrieval efficiency.

This category has high requirements for traceability accuracy. Semantic matching by vector models must combine business identifier constraints to prevent cross-batch mismatches.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the category’s mixed document structure of long process specifications and short inspection records, avoiding semantic breaks |
| Overlap Length | 100–150 characters | Retains key metadata such as batch numbers and device IDs across chunks, preventing missed associated information during retrieval |
| Similarity Threshold | 0.75–0.85, calibrated via actual testing | Matches the category’s traceability accuracy requirements, avoiding mismatched records from different batches |
| Single Search Limit | Top 20 results | Covers retrieval needs for multiple document types per batch, while controlling context length |
| Maximum Context | 4000–6000 characters | Aligns with the standard processing limit of FastGPT v4.17.0, accommodating associated audit data for a single batch |
| `maxToken` | 1024 | Matches the average semantic length of documents in this category, ensuring completeness of vectorization |

## Three Common Misconfigurations
- Retrieval results only display vector-related fields, with no original document content. This occurs because metadata binding between original documents and vector embeddings is not configured. Only vector results are stored, with no association to the original file’s storage path or structured content.
- Retrieval scores are consistently high, and unrelated batch records appear. This happens because filtering rules are not set for key business fields such as batch numbers and unique device identifiers for this category. Semantic matching does not incorporate business identifier constraints.
- Index status shows normal, but no matching results are returned. This is because incremental index triggers are not aligned with the update frequency of each batch or environmental monitoring plan. Newly generated batch production records and clean zone records are not synced to the index.

## How to Confirm Proper Configuration
- Randomly select batch production records and clean zone records for a single batch, run a retrieval check to confirm matching original document content is returned.
- Enter a query that includes a specific batch number, check that retrieval results only return associated documents for that batch, and exclude records from other batches.
- Add a simulated environmental monitoring record, trigger incremental indexing, then run a retrieval check to confirm the new record is included in the result set.
- View the vector embedding task logs to confirm that the `maxToken` and chunk length settings align with the actual length requirements of document processing.

The values provided are common starting points and should be measured against the reader's own samples.
