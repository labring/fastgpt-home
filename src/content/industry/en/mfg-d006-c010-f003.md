# Inspection and Process Record Audit for Medical Device Assembly and Cleanroom Production: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Data for this category comes from design history files, device and material batch ledgers, MES systems, clean environment monitoring equipment, sterilization equipment, and inspection and calibration systems. Daily documents include production process specifications, batch production records, clean zone operation records, sterilization batch records, inspection reports, software version records, adverse event and traceability materials. Data is updated per product batch or equipment cycle, and is also synchronized regularly per the clean environment monitoring plan. Document fields include unique identification numbers, batch numbers, process parameters, environmental monitoring values, sterilization parameters, inspection results, and some documents require association with device serial numbers and material batch numbers.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering by This Category’s Characteristics
The batch-based and associative nature of data in this category creates specific constraints for multi-turn dialogue and prompt configuration. First, data uses batches as the core association dimension. Multi-turn dialogues must stably bind `chatId` to the current batch’s unique identifier to avoid mixing cross-batch data. Second, document fields are numerous and closely associated. Prompts must explicitly limit retrieval scope to documents linked to the current batch to prevent interference from irrelevant data in audit logic. Third, data updates dynamically with batches. The dialogue workflow must dynamically load the latest documents for the corresponding batch, while verifying data timeliness to avoid calling expired sterilization or inspection records. Additionally, some documents involve exclusive fields such as biocompatibility and cleanroom control. Prompts must limit retrieval results to category-specific audit content to ensure compliance.

## How to Set the Configuration
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique number of the current product batch, use the combination of device serial number and batch number as the value | This category’s data uses batches as the core association dimension. Binding `chatId` to the batch number ensures that multi-turn dialogue context only links to documents for the current batch, avoiding cross-batch data mixing |
| `variables` | Pre-set variables including batch number, sterilization temperature threshold, clean zone temperature and humidity threshold, etc., use preset parameters linked to the current batch as values | Audits in this category require verification of fixed parameter thresholds. Injecting exclusive parameters for the current batch via `variables` simplifies prompt logic and ensures verification accuracy |
| `messages` | The initial system prompt limits retrieval to documents linked to the current batch. Append user questions and system replies after each dialogue turn | Multi-turn dialogues require retaining context to track audit progress. The `messages` parameter stably maintains dialogue context and ensures coherent audit logic |
| Question Optimization | Enable question optimization, set the optimization rounds to 2 | Audit questions for this category involve multi-field associations. Question optimization converts vague queries into precise field retrieval instructions, improving retrieval matching rate |
| Maximum Context Length | 8000–12000 characters, calibrated based on actual testing | Documents for a single batch in this category include multiple types of records. Sufficient context must be retained to cover all linked data for the current batch, avoiding audit omissions caused by context truncation |

## Three Common Misconfiguration Issues
- Symptom: Clicking the custom question button results in no response, and the preset audit workflow is not triggered in the dialogue interface. Cause: The custom question is not bound to `chatId`, so the system cannot identify the audit scenario linked to the current batch and fails to load the corresponding documents.
- Symptom: The online dialogue interface returns empty data or status code 500. Cause: Exclusive parameters for the current batch are not injected via `variables`, so the retrieval scope is not limited, and the system cannot match inspection and production records for the corresponding batch.
- Symptom: A complete audit result is returned directly after a single round of questioning, without step-by-step streaming output. Cause: The `messages` parameter is not correctly configured to maintain dialogue context, or context truncation prevents the system from generating audit content step-by-step. Streaming output logic is not enabled in some versions.

## How to Verify Proper Configuration
- Use the backend tool of FastGPT v4.17.0, bind `chatId` to the device serial number plus batch number of the test batch, initiate a query, and check if the dialogue context only includes documents linked to that batch.
- Call the online dialogue interface, pass the test batch parameters in `variables`, and check if the returned results include inspection and sterilization records for the corresponding batch.
- Initiate multiple consecutive queries, check if the context is correctly appended after each dialogue turn, and if system replies are output step-by-step via streaming.
- Trigger the custom question button, check if the corresponding audit process starts directly without requiring additional input.
