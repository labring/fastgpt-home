# Inspection and Process Record Audit for Medical Device Assembly and Clean Production: Source Citation and Traceability

## What Data for This Category Looks Like
This category covers full production process documents for manufacturers of single-use consumables, implanted and interventional medical devices.
Included documents are production process specifications, batch production records, clean zone environmental monitoring records, sterilization batch records, inspection reports, software version logs, and adverse event traceability materials.
Data sources include design history files, device and material batch ledgers, MES systems, clean environment monitoring equipment, sterilization equipment, and inspection and calibration systems.
Updates occur once per product batch or equipment completion. Clean environment data is synchronized per established monitoring plans.
Fields include unique device identification, material batch numbers, sterilization parameters, temperature and humidity records, and other relevant fields.

## Constraints for Source Citation and Traceability Workflows
The batch-level updates and multi-source data characteristics of this category require strict binding of batches and unique device identification during citation traceability. This prevents cross-batch mixing of production data.
Controlled data such as clean environment and sterilization parameters has high precision requirements. Search scope must be limited to the document set associated with the current batch only.
Adverse events and traceability materials have strong associative properties. Traceability results must clearly mark the generation time and affiliated batch of source documents.
Additionally, errors may affect patient safety. The total context length of a single citation must be limited to avoid introducing irrelevant redundant data that disrupts audit logic.

## Configuration Settings
This configuration is written based on FastGPT v4.17.0 logic.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 700–900 token | Limits the length of a single cited content block to avoid mixing redundant data not associated with the current batch |
| Maximum Context | 1100–1700 token | Matches the total core document content required for single-batch audits in this category |
| `responseData` | Return only unique identifiers and batch numbers of source documents | Focuses on key associative information required for traceability |
| `detail` | Enabled | Retains original fields of cited content to facilitate verification of sterilization parameters and clean environment data |
| Single Search Limit | Top 6–10 results | Covers core production and inspection documents for the current batch, avoiding excessive irrelevant results |

## Three Common Configuration Mistakes
- Symptom: The number of model context entries displayed in the interface does not match the number actually sent to the calling API. For example, the interface shows 30 entries but 310 are actually sent. Cause: The association logic between `quoteMaxToken` and maximum context was not configured correctly, causing the system to fail to truncate redundant cited content per configured rules.
- Symptom: After setting a citation limit, document blocks in the knowledge base that exceed that length are still included in the current batch's citation set. Cause: The citation limit was not bound to the filtering rules for single-batch documents, causing long document blocks from cross-batch matches to be incorrectly included.
- Symptom: Variables such as batch numbers and sterilization parameters cannot be correctly embedded into the main text of audit reports. Cause: The `detail` configuration was not enabled to retain variable mapping of original fields, causing the system to fail to extract citeable variables from documents.

## How to Verify Proper Configuration
- Generate a single-batch audit request, check the context entry count in the call log, and confirm it matches the configured maximum context range.
- Upload a batch of test documents, set a citation limit, initiate an audit, and verify that document blocks exceeding the set length are not included in the current batch's citation set.
- Trigger an audit and check the traceability results, confirm that only document identifiers and associated fields for the current batch are returned, with no cross-batch data included.
- Check the field integrity of cited content, confirm that key fields such as sterilization parameters and clean environment data are retained after the `detail` configuration is enabled.

The values provided are common starting points and should be measured against the reader's own samples.
