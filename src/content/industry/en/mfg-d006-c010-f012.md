# Inspection and Process Record Audit for Medical Device Assembly and Clean Production: Deployment and Upgrade

## What Data for This Category Includes
This category of data covers production process specifications, batch production records, clean zone monitoring records, sterilization batch records, inspection reports, software version records, and adverse event traceability materials. Data sources include design history files, device and material batch ledgers, MES systems, clean environment monitoring equipment, sterilization equipment, and inspection and calibration systems. Data updates follow cycles per product batch or single device, with synchronized updates per fixed environmental monitoring plans. Documents include fields such as controlled assembly inspection requirements, unique identifiers for key materials, cleaning and sterilization parameters, and software version records, and must be linked to production batches and full-chain traceability information.

## Constraints Imposed by This Category’s Characteristics on Deployment and Upgrade
Since data for this category is updated per batch or single device and linked to full-chain traceability requirements, deployments must support permission control linked to documents by batch to avoid cross-batch data confusion. Multi-source heterogeneous data from different devices and systems requires a compatibility layer for multi-format data import, to ensure accurate mapping of fields such as sterilization parameters and clean environment data. Fixed-cycle environmental monitoring data requires scheduled synchronization tasks to ensure data timeliness for audit workflows. At the same time, the controlled nature of inspection and process records requires that complete operation logs are retained after deployment, to facilitate traceability of configuration changes and audit processes, and must support independent validation rules for each batch of data.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | Use a dedicated replica set connection string, configure read-write separation | Data for this category is stored per batch; separating read and write operations avoids blocking audit queries during single-batch data writes |
| `PG_URL` | Configure as a dedicated database address with a connection pool; set the connection pool size to 20–30 | A large volume of batch-linked inspection records and traceability data must be stored; the connection pool adapts to concurrent batch query demands |
| `REDIS_URL` | Enable persistent storage; configure a memory limit of 8000 MB | Used to cache real-time clean environment monitoring data and batch validation rules; persistence ensures cached configuration is not lost after power outages |
| `STORAGE_S3_ENDPOINT` | Bind to an S3-compatible object storage service endpoint | Used to store large-volume documents such as sterilization batch records and inspection reports; supports bulk upload requirements for multi-batch documents |
| `ROOT_KEY` | Set to a random string with a minimum complexity of 16 characters | Used to generate system-level permission tokens, ensuring access security for core configuration interfaces, and complies with FastGPT v4.17.0 permission configuration specifications |
| `DB_MAX_LINK` | Configure to 15–25 | Restrict database concurrent connection count, preventing database overload from simultaneous audit requests across multiple batches |

## Three Common Configuration Errors
- Registration fails after the login interface loads, with a prompt that the system has no initial user. The cause is incorrect configuration of `ROOT_KEY` to generate the initial administrator token, or failure to run the initialization script to create a default user.
- Interface calls to external model platforms time out, returning a 504 status code. The cause is failure to configure cross-origin access whitelists, or a request timeout threshold set lower than the model response duration.
- Some documents are lost during bulk import of sterilization batch records; system logs show connection pool overflow. The cause is `DB_MAX_LINK` set too high, exceeding the database connection limit, or failure to split import tasks by batch to trigger concurrency restrictions.

## How to Verify Correct Configuration
- Run the initial user generation script, verify that the login interface allows login with the preset administrator account, and confirm that the `ROOT_KEY` configuration is effective.
- Import a mock sterilization batch record document, check that the storage path matches the endpoint configured in `STORAGE_S3_ENDPOINT`, and confirm that document upload works without errors.
- Initiate 10 concurrent batch inspection record query requests, observe that the database connection count does not exceed the `DB_MAX_LINK` configuration value, and confirm that the connection pool configuration is reasonable.
- Configure a scheduled synchronization task for clean environment monitoring data, check that the task logs contain no format mapping errors, and confirm that the multi-source data adaptation configuration is effective.

The values provided are common starting points and should be measured against the reader's own samples.
