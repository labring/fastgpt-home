# Inspection and Process Record Audit for Dyeing and Finishing: HTTP Interfaces and External Systems

## What data for this category looks like
Data for this category comes from customer color swatches, formula libraries, dye and chemical batch records, dye vat control equipment, colorimeters, setting machines, and environmental monitoring systems. Daily generated documents include dyeing formulas, chemical dosing records, dye vat curves, proofing confirmation sheets, color difference reports, setting process sheets, and sewage ledgers. Data updates follow the rhythm of each vat, each batch, and each shift. Real-time data such as dye vat control parameters and color difference test results is generated synchronously during a single vat’s processing. Fields include batch number, dye and chemical ratio, temperature curve, color difference ΔE value, discharge concentration, and more. Units include grams, liters, degrees Celsius, seconds, and others.

## What constraints these characteristics impose on the HTTP Interfaces and External Systems link
High-frequency, multi-node data updates require HTTP interfaces to support high-frequency calls at the per-vat and per-batch level, to avoid synchronization delays disrupting production schedules. Multiple types of data (temperature curves collected by equipment, text-based color difference reports, numerical discharge data) require interfaces to support multi-format requests and responses. Strict field validation requirements (such as batch number, ΔE color difference value, discharge concentration) require interface configuration of parameter validation logic, to prevent invalid data from flowing into downstream systems and causing production losses. Cross-system docking requirements with ERP, colorimeters, and environmental monitoring systems require interfaces to support standard authentication and cross-domain configuration, to adapt to the access rules of multiple external systems.

## How to set configurations
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `Authorization` | `Bearer {platform-generated application secret}` | This category’s docking with external production and environmental systems requires standard Bearer token authentication to prevent unauthorized access to core business data |
| `variables` | `{"batchNo": "{{system-extracted dye vat batch number}}", "dyeBatch": "{{dye and chemical batch}}" }` | Data for this category uses batch as the core association dimension. Passing batch information via global variables enables cross-node data linkage |
| `responseData` | `Return only batch number, color difference ΔE value, discharge concentration` | Downstream systems only require core business fields, reducing transmission load to adapt to high-frequency call requirements |
| Request timeout | `30–60 seconds` | Real-time requirements during dye vat processing. Timeouts will disrupt production processes. Adjust the interval based on actual measurements |
| Parameter validation rules | Validate required fields (batch number, dye and chemical ratio) | Errors in data for this category can lead to rework or scrapping of entire vats. Invalid requests must be intercepted in advance |
| Cross-domain whitelist | List of domain names for connected ERP, colorimeter, and environmental systems | Adapt to cross-domain access requirements of multiple external systems, preventing browser request blocking |

## Three common mistakes
- Phenomenon: Interface calls return results delayed by more than 60 seconds. Cause: Timeout configuration was not adjusted to match the real-time rhythm of dye vat processing. Default timeout settings do not fit production scenarios.
- Phenomenon: Global variables are not correctly bound to dye vat batch numbers, leading downstream systems to fail to associate corresponding batch data. Cause: The `variables` configuration item was not correctly mapped to the batch extraction node of the dye vat system.
- Phenomenon: Excessive raw dye vat curve data is returned by the interface, causing parsing failures in downstream environmental systems. Cause: Non-essential fields were not filtered via the `responseData` configuration item, and the configuration did not match the field requirements of downstream systems.

## How to confirm configurations are correct
- Send a test request with a valid dye vat batch number, check that the returned results only include the configured core fields with no redundant data.
- Call the interface 10 times consecutively, verify that single response times fall within the configured 30–60 second interval, with no consecutive timeouts.
- Connect to an external colorimeter system, verify that the color difference ΔE value passed by the interface matches the test results from the local colorimeter.
- Send a request using an invalid application secret, confirm that the interface returns a 401 Unauthorized status code, verifying that the authentication configuration is active.

The values given are common starting points and should be measured against the reader's own samples.
