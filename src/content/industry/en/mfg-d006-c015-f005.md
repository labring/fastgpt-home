# Inspection and Process Record Audit for Active Pharmaceutical Ingredient and Pharmaceutical Intermediate Production: Tool Calling and Plugins

## What Data for This Category Looks Like
This category of data covers batch production records, material balance records, reaction and purification records, cleaning records, impurity profile reports, deviation and change documents. Data sources include registered process documents, raw material batch ledgers, DCS systems, weighing systems, LIMS, chromatography data systems, and QMS. Data is updated per production batch and each process step. Fields include reaction parameters, impurity concentration, solvent residue levels, yield values, change approval status, and more. Data must be synced and collected from multiple heterogeneous systems, with no unified fixed format.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins
Data sources for this category are scattered and have heterogeneous formats. Tool calling must adapt to the differentiated formats of multiple system interfaces to avoid synchronization failures caused by mismatched data source formats. The characteristic of data updated per batch and step requires tool calling to be triggered bound to the batch dimension, ensuring audit data is accurately associated with the corresponding production link. Specialized process fields require tool calling parameters to match specific business field names; general templates cannot be used directly. At the same time, data association has high compliance requirements. Tool calling must include batch traceability parameters to ensure audit records can be traced.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool Calling Mode | `functionCall` | Enables precise calling of specialized process parameters, avoiding issues where general prompts fail to match business fields |
| Number of Data Sources per Call | First 3 | Controls concurrency scale to avoid timeout risks when synchronizing from multiple heterogeneous systems |
| Interface Timeout | 600 seconds | Adapts to the collection cycles of slow-response data sources such as chromatography data systems and LIMS |
| Plugin Trigger Condition | Triggered after a production batch is completed | Aligns with the rhythm of batch-based data updates, ensuring complete data for the corresponding link is available during audits |
| Plugin Call Retry Count | 3 | Addresses temporary network fluctuations or interface faults, ensuring data collection success rate |

## Three Common Misconfiguration Scenarios
- Scenario: When using the HTTP module to call LIMS or chromatography data system interfaces, connection timeout or permission errors are returned, but calls via Postman work normally. Cause: The production environment system whitelist was not added in the FastGPT configuration, or the format of the interface authentication parameters does not match the requirements of the production system.
- Scenario: Parameter errors are returned when calling the multimodal audit plugin, but direct calls to third-party interfaces via the OpenAI protocol work normally. Cause: The value range of the `toolChoice` parameter was not correctly passed according to the plugin configuration requirements of FastGPT v4.17.0, or the multimodal input content exceeds the configured context limit.
- Scenario: The deployed reranker plugin call succeeds, but the returned relevance result is always false. Cause: The input text of the reranker was not matched with the specialized fields of the active pharmaceutical ingredient impurity profile and yield data, and the input content is unrelated to the current audit task, causing the plugin to fail to generate valid results.

## How to Confirm Proper Configuration
- Manually trigger a tool call for a corresponding production batch, and check whether complete data for the target batch can be synced from the specified DCS, LIMS, and other systems.
- Review the plugin call logs to confirm that parameters in `functionCall` mode match business fields, with no format errors or missing fields.
- Simulate a temporary interface fluctuation scenario, and check whether the preset retry mechanism is triggered and data collection is ultimately completed.
- Compare the audit results returned by the plugin with manually extracted process data, and confirm that the field matching degree meets the current business audit requirements.

The values provided are common starting points and should be measured against the reader's own samples.
