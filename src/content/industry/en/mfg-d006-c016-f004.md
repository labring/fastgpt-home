# Inspection and Process Record Audit for Transformer and High-Voltage Electrical Equipment Manufacturing: Workflow Orchestration

## What the data for this category looks like
Daily documents for this category include winding and core assembly records, vacuum drying records, insulating oil reports, partial discharge and withstand voltage test reports, and nameplate parameter tables. Data sources cover design BOM, silicon steel sheet and insulating material procurement data, vacuum and drying equipment operation data, oil test results, and test station test data. Data is updated per single product and per batch of materials. Full-process traceability is required for single products, with fields including insulation parameters, test values, nameplate parameters, and more. Units match professional standards for electrical and material testing.

## What constraints these characteristics impose on the "workflow orchestration" link
The single-product traceability requirement, multi-source scattered data sources, and fixed and strict inspection procedures for this category impose multiple constraints on workflow orchestration. Independent processes must be configured for each single product to avoid mixing data from different batches. Multiple types of scattered data sources must be connected to ensure accurate pulling of data from each link. The fixed sequence of winding, drying, and high-voltage tests must be followed, and node flow must match process logic. Due to the serious consequences of errors, abnormal verification and alert nodes must be configured to proactively avoid risks such as insulation breakdown.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Data source binding rule | Bind the single product ID and corresponding test data in `variables` | Matches the core requirement of single-product traceability for this category to avoid data misuse |
| Node flow logic | Configure inspection nodes in `nodeId` order | Complies with the fixed process sequence of winding, drying, and high-voltage tests |
| Abnormal trigger threshold | Trigger manual review when partial discharge value exceeds 1000pC | Avoids serious fault risks such as insulation breakdown |
| Document export configuration | Generate a Word document containing specified fields and generate a download link | Meets the archiving and traceability requirements for process record audits |
| Process timeout setting | 1200 seconds | Adapts to the long time-consuming cycles of links such as high-voltage tests |
| Variable verification rule | Verify the insulation moisture content field in `variables` | Ensures core parameters meet process requirements |

## Three Common Mistakes
- Scenario: The inspection report generated by the workflow cannot generate a downloadable Word link, or fields are missing from the exported file. Cause: The corresponding fields in `variables` are not correctly bound in the document export node, and the field mapping rules for the export template are not configured.
- Scenario: After importing a workflow from FastGPT v4.8 to FastGPT v4.17.0, node configuration fails and the process cannot run normally. Cause: The `nodeId` mapping relationship of the original workflow is not retained, and the new version has adjusted node ID rules.
- Scenario: After uploading attachments such as insulating oil reports, the workflow cannot automatically extract test values from the attachments. Cause: The professional field extraction rules for the attachment parsing node are not configured, and the detection data parsing template corresponding to the category is not bound.

## How to Confirm the Configuration Is Correct
- Trigger the inspection process for a single product, check whether each node flows normally in `nodeId` order.
- Check whether the fields in `variables` are correctly bound to the document export node, and the exported Word document contains all required inspection record fields.
- Simulate a scenario where the partial discharge value exceeds the threshold, confirm that the abnormal node triggers the manual review process.
- Wait for the process to reach the 1200-second threshold, check whether the timeout alert mechanism is triggered.

The values provided here are common starting points and should be evaluated against the reader's own samples.
