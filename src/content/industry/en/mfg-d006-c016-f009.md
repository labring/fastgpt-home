# Inspection and Process Record Audit for Transformer and High-Voltage Electrical Equipment Manufacturing: Model Access and Configuration

## What data for this category looks like
Data for this category comes from design BOMs, silicon steel sheet and insulating material procurement data, vacuum drying equipment logs, oil test reports, high-voltage test records from test stations, and other sources. Daily documents include winding and core assembly records, vacuum drying records, insulating oil reports, partial discharge and withstand voltage test reports, and nameplate parameter tables. Each individual product corresponds to a dedicated set of documents. Data is updated once per product or batch of materials. Fields include professional parameters such as insulation moisture content, partial discharge values, and withstand voltage rating. Full-process traceability management must be performed per individual product.

## What constraints do these characteristics impose during model access and configuration
The requirement that each individual product has a dedicated document set means that model access must support dividing knowledge base boundaries by individual product or batch, to avoid mixing data across products. Differences in document formats across multiple sources mean that configuration must adapt to different text types such as structured test reports and semi-structured assembly records. The high-frequency update characteristic means that configuration must support fast incremental synchronization mechanisms to match the update rhythm of each product or batch of materials. The presence of professional fields such as insulation parameters and partial discharge values means that configuration must enable precise retrieval and citation logic to ensure information accuracy during audits and avoid irrelevant content interfering with judgments.

## How to set configurations
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Adapts to the long document set of a single product, avoiding truncation of core content such as insulation test records and oil test reports |
| `maxTokens` | 2000–3000 token | Controls the output length of single-round audit responses, ensuring clear presentation of audit key points such as lead verification and withstand voltage test results |
| `quoteMaxToken` | 1200–1500 token | Limits the total length of cited documents, prioritizing retention of key business data such as insulation parameters and partial discharge values |
| `temperature` | 0.1–0.3 | Reduces response randomness, ensuring consistency and accuracy of inspection and audit results |
| `AIPROXY_API_ENDPOINT` | Fill in the actual access address according to the deployment environment | Adapts to the network path requirements for model calls |
| `AIPROXY_API_TOKEN` | Fill in according to the assigned key | Completes identity verification for model access |

## Three common mistakes
- Phenomenon: Knowledge base retrieval takes more than 30 seconds, and the page returns a timeout prompt. Cause: The `maxContext` parameter was not adjusted for the single product's document set, causing the model to load too many irrelevant documents.
- Phenomenon: Audit results differ between web debugging and external access. Cause: Generation parameters such as `temperature` were not unified in configuration, leading to inconsistent generation logic across different environments.
- Phenomenon: Model calls return an unauthorized or channel configuration error prompt. Cause: The `AIPROXY_API_TOKEN` was filled incorrectly, or the `AIPROXY_API_ENDPOINT` address does not match the deployment environment.

## How to confirm configuration is complete
- Upload the typical document set for a single product, perform a retrieval test, and check whether the retrieval results include core business documents such as insulating oil reports and withstand voltage test records.
- Adjust the `temperature` parameter, execute the same audit question multiple times, and confirm that the consistency of the response content meets business expectations.
- View the model call log, and check whether the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` configurations match the deployment environment.
- Simulate a document update operation for a single product, confirm that the synchronization process can complete normally and the time consumption matches the business rhythm.

The values provided here are common starting points and should be measured against the reader's own samples.
