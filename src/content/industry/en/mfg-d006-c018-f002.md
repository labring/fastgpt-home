# Inspection and Process Record Audit for Basic Chemical Continuous Production: Vector Models and Indexing

## What this category of data looks like
Data sources for basic chemical continuous production scenarios include DCS/SIS systems, online analyzers, LIMS systems, equipment condition monitoring modules, energy metering devices, and raw material tank data terminals. Daily generated documents cover operating procedures, process index cards, DCS trend curves, laboratory reports, interlock bypass records, special work tickets, and shift reports.
Data updates follow three frequencies: real-time, per-shift, and daily. DCS trends and online analyzer data update in real time. Shift reports and laboratory reports submit daily or per shift. Interlock bypass records and special work tickets generate automatically when workflow processes trigger them.
Document fields include measured process parameter values, operation timestamps, equipment status identifiers, and work approval information. Units use common industrial measurement standards such as megapascals, degrees Celsius, and tons per hour.

## What constraints do these characteristics impose on the vector models and indexing link?
Real-time DCS and online analyzer data requires indexes to support low-latency incremental synchronization. This prevents audit deviations caused by data lag.
Multiple document types require chunking strategies tailored to different text lengths and structured numerical blocks. This stops process logic from being truncated.
Data with varying update frequencies needs layered indexing strategies. This balances query performance for real-time data and storage costs for batch documents.
High-risk interlock bypass records and special work tickets require indexes configured with higher recall priority. This ensures no omissions during audits.
Process parameters have numerical characteristics that demand vector generation to balance semantic consistency between structured data and unstructured text. This prevents matching logic failures.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Adapts to the average length of unstructured texts such as process index cards and shift reports, while being compatible with structured numerical blocks of DCS trends |
| Overlap Length | 50–100 characters | Prevents cross-chunk process logic from being truncated, ensuring complete semantics of interlock logic |
| Similarity Threshold | Calibrated based on actual measurements | Must match the fluctuation range of basic chemical process parameters, to avoid misjudging normal fluctuations as abnormalities |
| Single Search Limit | Top 8 entries | Covers all key process parameter related records for the current shift, balancing query efficiency and recall completeness |
| `defaultToken` | 4096 | Adapts to the context carrying capacity of long documents such as DCS trends and laboratory reports, supporting associated audits of multi-segment data |
| `maxToken` | 8192 | Supports complete vector generation for complex documents such as special work tickets and interlock bypass records, avoiding content truncation |

## Three common mistakes
- Phenomenon: Some real-time DCS trend data is missing from index recall results, and retrieval delay exceeds the business tolerance range. Cause: Incremental index trigger rules are not configured for real-time data streams, and only full index tasks are executed, causing new data to fail to be retrieved in a timely manner.
- Phenomenon: A vector generation failure prompt appears in the interface, and logs show a token limit exceeded error. Cause: The `maxToken` parameter is not set correctly, and reasonable chunking is not performed for ultra-long documents, causing a single text segment to exceed the token limit supported by the model.
- Phenomenon: Retrieval matching accuracy fluctuates greatly after mixing different vector models to generate vectors for process parameters and text documents. Cause: Specialized vector models are not configured separately for structured and unstructured data in basic chemical scenarios, and mixed models destroy the consistency of the semantic space.

## How to confirm that the configuration is correct
- View the index synchronization logs of FastGPT v4.17.0. Confirm that the update delay of real-time DCS data meets business requirements, and there are no continuous timeout or packet loss records.
- Randomly select an interlock bypass record, perform an audit retrieval, and check whether the number and coverage of returned results match the preset single search limit.
- Upload an ultra-long special work ticket, check that the vector generation result is complete, and there is no content truncation prompt.
- Compare retrieval and matching results of different document types, confirm that the recall logic for structured process parameters and non-text operation records meets expectations.
