# Inspection and Process Record Audit for Continuous Basic Chemical Production: Workflow Orchestration

## What Data Looks Like for This Category
Continuous basic chemical production core data comes from DCS/SIS systems, online analyzers, LIMS systems, equipment condition monitoring modules, energy metering devices, and raw material tank sensors. Daily documents include operating procedures, process index cards, DCS trend charts, laboratory reports, interlock bypass records, special work permits, and shift logs. Data update rhythms fall into three categories: real-time (such as reactor temperature, interlock status), shift-based (such as post operation records), and daily (such as raw material consumption shift logs). Data fields include process parameter values, equipment operating status, laboratory result values, and work approval status, with corresponding units such as degrees Celsius, cubic meters, and tons.

## Constraints Imposed on Workflow Orchestration
Real-time updated process parameters and interlock status data require workflows to support trigger-based node execution. This avoids delays and resource consumption caused by fixed-cycle polling. Heterogeneous data from multiple sources requires parameter verification links in workflows. This ensures consistent field formats and units across data returned by different systems. Non-real-time documents such as shift logs and special work permits require scheduled trigger nodes. These nodes pull data at fixed daily or shift times. Business logic with strong interlock controls requires strict timing dependencies between workflow nodes. Subsequent audit steps can only run after preceding node verification passes. Audit rules vary by document type. Independent branch workflows must be configured for each document type.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0, and are adapted for inspection and audit scenarios of continuous basic chemical production.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Session lifecycle: 600 seconds | A single audit process for continuous basic chemical production typically takes no more than 10 minutes. Automatically releasing variables after timeout prevents unnecessary resource occupation. |
| Interactive node configuration | Enable multi-parameter completion interaction | MCP tool calls often require multi-dimensional parameters such as sampling points and time intervals. Interactive nodes collect complete input parameters. |
| `nodeId` | Bind exclusive nodeId by document type | Audit logic differs significantly across operating procedures, laboratory reports, and interlock bypass records. Binding exclusive nodes avoids workflow confusion. |
| Scheduled trigger rules | Daily 02:00, 15 minutes before shift handover | Shift logs are generated daily on a fixed schedule. Special work permits must be reviewed before shift handover. Scheduled triggers ensure timely data pulling. |
| Branch judgment logic | Trigger corresponding audit rules by document type | Verification fields vary by document type. Branch judgment ensures audit logic matches the target business scenario. |

## Three Common Misconfigurations
- Symptom: An "missing parameter" error appears when calling MCP tools, or returned audit result fields are empty. Cause: Multi-parameter completion interactive nodes are not configured, and no parameter collection steps are included in the workflow. This leads to failure to correctly pass required input parameters such as sampling points and time intervals for MCP tools.
- Symptom: `variables` values set in a previous session are lost after restarting the session, preventing continuation of the audit context. Cause: Storage rules for `variables` are not correctly configured. Variables are not bound to the corresponding session lifecycle, so they are cleared when the session ends.
- Symptom: Workflow execution takes more than 10 minutes to complete, or node status remains "pending trigger" for an extended period. Cause: No timeout retry mechanism is set for trigger-based nodes. No retry is triggered after real-time data pulling fails, leading to audit process blocking.

## How to Verify Successful Configuration
Trigger a test audit process, verify whether the parameter completion interface pops up when calling MCP tools, and confirm that the multi-parameter interactive configuration takes effect.
Save the configuration and restart the session, verify whether the `variables` set in the previous session are retained, and confirm that the global variable storage rules are correct.
Manually trigger the scheduled node, verify whether the corresponding documents are correctly pulled and enter the audit process, and confirm that the scheduled trigger rules match the business time nodes.
Test with different types of documents, verify whether the workflow automatically enters the corresponding branch, and confirm that the branch judgment logic is correct.

The values provided are common starting points and should be measured against the reader's own samples.
