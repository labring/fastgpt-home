# Inspection and Process Record Audit for Plastic Injection Molding: Workflow Orchestration

## What the data for this use case looks like
Daily documents for this use case include injection molding process cards, raw material drying records, mold histories, first-piece inspections, patrol inspection forms, and material change and machine cleaning records. Data sources include resin batches and property sheets, injection molding machine parameters, mold temperature machines, MES systems, and dimensional and appearance inspection equipment. Data is updated at each production batch, each mold and material change, and at the end of each shift. Core fields include resin batch number, drying temperature, holding pressure, mold temperature, and measured dimensional values, with corresponding units such as degrees Celsius, megapascals, millimeters, and others.

## What constraints these characteristics impose on workflow orchestration
Because data updates occur frequently and have multiple trigger points, the workflow must be bound to multi-dimensional trigger conditions to match events such as mold and material changes and batch production completion. Because data sources are scattered and fields vary, unified variables must be used to manage device and document data from different sources to avoid confusion in field mapping. Because the consequences of errors are severe, the workflow must add verification links to validate data such as process parameters and raw material ratios. Because this use case involves molten polymer forming without cross-linking and curing steps, the workflow does not need to configure processing logic for corresponding links, which simplifies process nodes.

## How to Configure
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `variables` | Map core fields of injection molding process cards, raw material drying records, and mold histories, and associate data from injection molding machine, mold temperature machine, MES, and inspection equipment nodes with `nodeId` 1-4 | This use case has scattered data sources and varied fields, so unified variables are required to manage cross-node data |
| Trigger condition settings | Trigger on mold and material change events, each batch production completion, and end of shift, with verification executed after a `30 seconds` delay | Matches the data update frequency of this use case, to avoid verification failures caused by unsynchronized data |
| Tool call node timeout setting | `600 seconds` | Injection molding process parameter verification requires reading real-time data from multiple sources, which takes a long time |
| Log retention configuration | Retain component operation logs for `7 days` | Facilitates retrospective review of exceptions during inspection and audit processes |
| Model call node configuration | Bind the model for the corresponding business scenario, and associate the batch number field in `variables` | Ensures that the model call can link to the full data of the corresponding production batch |

## Three Common Misconfigurations
- Symptom: Tool call node returns Invalid JSON: Bad control chara error. Cause: No escape processing is performed for line breaks and special characters in injection molding records, causing JSON format verification failure.
- Symptom: Tool call nodes in the workflow cannot add connection lines, with no connection circles displayed. Cause: Duplicate `nodeId` configuration, or node connection permission is not enabled in the workflow settings of FastGPT v4.17.0.
- Symptom: Detailed logs of component MCP services in the workflow cannot be viewed. Cause: Detailed output configuration for component logs is not enabled, or the log retention period is set too short.

## How to Confirm Successful Configuration
- Enter the workflow preview page, check whether the fields configured in `variables` cover the core fields of injection molding process cards and raw material drying records, and confirm that the variable mapping result is correct.
- Trigger a simulated mold change event, check whether the workflow starts according to the set trigger conditions, with no error messages displayed.
- Execute a tool call node, check whether the JSON format of the returned result is normal, with no abnormal control characters.
- Enter the component log page, filter logs for the corresponding `nodeId`, and confirm that detailed MCP service operation records can be viewed.
