# Inspection and Process Record Audit for Furniture and Wood Product Manufacturing: Workflow Orchestration

## What the Data for This Category Looks Like
Data related to inspection and process record audit for furniture and wood product manufacturing originates from multiple sources. These include order design systems, sheet material and lumber batch ledgers, CNC cutting and drilling equipment, ERP/MES systems, and moisture content testing devices.
Data updates occur once per order, per day, or per material batch. Daily documents include order breakdown drawings, cutting lists, edge banding and drilling programs, coating process documents, hardware material bills, trial assembly and packaging records.
Fields covered include panel dimensions, sheet batch numbers, moisture content values, hole position parameters, and hardware models. No unified fixed BOM structure exists, and configurations adjust based on individual customized orders.

## Constraints Imposed on Workflow Orchestration
The customized order-driven nature of this category requires workflows to bind exclusive variable parameters for individual orders, and adapt to multi-source heterogeneous production documents and equipment data.
Frequently updated sheet batches and cutting data require workflows to pull latest data sources on demand, and adapt to real-time production data updates.
The large number of panels and variable document structures per order require workflows to support dynamic loading of multiple document entries, avoiding information omissions from fixed chunking rules.
The sequence requirements for multi-data source nodes must strictly match the logical order of production processes, ensuring inspection and audit sequences align with actual production steps.

## Three Common Configuration Errors
- Phenomenon: When more than 6 workflow instances run simultaneously, the system enters an unresponsive state, and the interface displays loading timeout. Cause: Workflow concurrency configuration is not adjusted to match deployed hardware, and the default concurrency limit does not fit an 8-core 32G local deployment environment.
- Phenomenon: The order ID bound to `variables` in the workflow is empty, and audit results lack corresponding panel information. Cause: Order-level variable parameters are not correctly passed before workflow startup, leading to data source matching failure.
- Phenomenon: Document sequence in workflow processing results does not match production processes, resulting in chaotic audit logic. Cause: `nodeId` is not assigned per production node sequence, reordering configuration is not enabled, or reordering rules do not match production logic.

## How to Verify Correct Configuration
- Check the workflow's data source configuration page, confirm that category-specific document sources such as order breakdown drawings, cutting lists, and coating processes are associated.
- Trigger a test workflow, verify that passed `variables` parameters include order ID and sheet material batch number.
- Run a single-instance workflow, confirm no timeout errors occur, validating the timeout threshold setting is reasonable.
- Run multiple workflow instances simultaneously, confirm normal system response, validating concurrency configuration fits the current deployed hardware.

The values provided are common starting points and should be measured against the reader's own samples.
