# Inspection and Process Record Audit for Furniture and Wood Product Manufacturing: Source Citation and Traceability

## What This Category's Data Looks Like
Typical organizations in this category include panel furniture, solid wood furniture, custom home and door enterprises. They generate daily documents including order breakdown drawings, cutting lists, edge banding and drilling programs, coating process documents, hardware lists, and assembly and packaging records.
These organizations collect data from order design systems, sheet and wood batch ledgers, CNC cutting and drilling equipment, ERP/MES systems, and moisture content testing equipment.
Update cycles follow per order, daily, or per material batch. Document fields include panel size parameters, hardware model, production batch number, and test values. No unified fixed format exists, and documents are adjusted per custom orders.

## Constraints for Source Citation and Traceability
Custom order-driven production models create a high volume of per-batch documents and large personalized differences. Traceability processes must accurately match original data for specific panels or production batches.
Multi-source heterogeneous data sources cause format inconsistencies. Teams must ensure citations correctly associate with field information from corresponding systems.
High-frequency updated production data requires traceability processes to support real-time reading of latest sheet batches and test results. This avoids using outdated information.
Accuracy of panel size, hole position and other parameters directly affects installation effects. Teams must clearly mark original document generation time and corresponding order number during traceability to ensure audit traceability.

## Configuration Setup
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum citation token count | 800–1200 token | Matches the core content length of a single cutting list or order breakdown drawing, to avoid truncating critical parameters such as panel size and hole positions |
| Return citation data toggle | Enabled | Meets the requirement to view original document fragments during inspection audits, and clarifies content sources |
| Citation detail display | Full path + generation time | Clearly traces the storage location and generation time of specific documents, adapting to differentiation of multi-source data |
| Single recall limit | Top 6 entries | Adapts to the volume of associated data for multiple panels in custom orders, avoiding recall of irrelevant historical order data |
| Recall similarity threshold | 0.75–0.85 | Filters low-relevance non-production documents, ensuring recalled content matches current inspection requirements |
| Context window length | 4000–6000 characters | Accommodates associated information from multiple panel documents, avoiding loss of critical audit basis |

## Three Common Configuration Errors
- Unlabeled citation sources: Chat interface audit results lack traceability information such as associated document filenames and generation time. This occurs when the `responseData` configuration item is not enabled, so the citation data return function is not activated.
- Excessive recalled document count: Single recall of associated documents exceeds 10 entries, including historical order data unrelated to the current inspection. This happens when the single recall limit is set too high, and the threshold is not adjusted based on the number of panels in custom orders.
- Incorrect document version in traceability: Audit results reference sheet batch data that does not match the actual batch of the current order. This occurs when recall content filtering by order number is not configured, leading to recall of expired historical data.

## How to Verify Correct Configuration
- Submit an inspection and audit request that includes panel size and sheet batch information. Check if returned results include filenames and generation times of associated documents.
- Compare returned citation content against uploaded document fragments such as cutting lists and order breakdown drawings. Adjust configuration items to match the actual recall scope.
- Simulate a scenario with multiple concurrent orders. Confirm that recall results only include documents related to the current test order, with no cross-order data mixed in.
- Review system logs to confirm that no timeout or parameter error prompts appear for citation and traceability requests.

The configuration values listed above are common starting points, and should be evaluated against the reader's own samples.
