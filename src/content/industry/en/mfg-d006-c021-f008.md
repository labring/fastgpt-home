# Inspection and Process Record Audit for Furniture and Wood Product Manufacturing: Document Parsing and Chunking

## What Data Looks Like for This Category
Typical entities in this category include panel furniture, solid wood furniture, custom home goods, and door manufacturers. Daily generated documents include order breakdown drawings, cutting lists, edge banding and drilling programs, coating process documents, hardware bill of materials, and assembly and packaging records. Data mainly comes from order design systems, sheet and wood batch management systems, CNC cutting and drilling equipment, ERP/MES systems, and moisture content testing equipment. Update frequency aligns with orders, daily cycles, or per material batch. Documents often contain precise dimension parameters, hardware model numbers, batch numbers, process parameters, and some include structured table and image content.

## Constraints Imposed on Document Parsing and Chunking
The document features of this category create multiple constraints for parsing and chunking. Structured documents with multiple tables and images require complex format parsing to avoid losing dimension and batch association information in tables. Documents updated quickly with orders require parsing processes with low latency to prevent disruptions to production linkages. Strong correlations between precise dimension parameters, hardware models, and process parameters require that chunking does not split associated fields in the same document. For example, panel dimensions in a cutting list must be bound to corresponding hardware models. Fixed formats and line break rules for CNC program documents require matching specific chunking logic to ensure complete recognition of code segments.

## How to Configure
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the length of single-block information with associated fields in documents of this category, avoiding breaking the binding relationship between panel dimensions and hardware parameters |
| `chunkSplitter` | Split by paragraph + table boundary | Matches the paragraph and table structures of order breakdown lists and process documents, preserving the integrity of structured content |
| `customPdfParse` | Enable complex format parsing mode | Adapts to embedded tables and images in order breakdown drawings and assembly records, improving recognition accuracy for non-pure text content |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses parsing time for large cutting lists and CNC program documents, preventing parsing failures due to timeout |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Meets the file upload requirements for large CNC programs and multi-panel cutting lists in this category, preventing files from being blocked by the system |
| `chunkSettingMode` | Manual configuration mode | Allows adjustment of chunking rules for different document types (such as hardware lists and CNC programs), adapting to the diverse document formats within the category |

## Three Common Misconfigurations
- Phenomenon: The document parsing node shows uploaded file is empty or no content after parsing, and background logs return a file read failure status code. Cause: `UPLOAD_FILE_MAX_SIZE` is not configured to adapt to large cutting lists or CNC program documents, exceeding the default limit and causing file truncation.
- Phenomenon: Panel dimensions and hardware model fields in tables of imported Word documents are identified as empty, and text cannot be extracted from images. Cause: The `customPdfParse` complex format parsing mode is not enabled; the default parsing only adapts to pure text documents.
- Phenomenon: After chunking, the dimensions of a single panel and its corresponding installation position are split into different blocks, making associative retrieval impossible. Cause: `chunkSplitter` is not configured to split by table boundary; splitting only by fixed character count causes associated information to break.

## How to Verify Proper Configuration
- Upload a typical cutting list document, check if the parsed text blocks retain complete fields and association relationships within tables.
- Check the file read status in parsing logs to confirm no timeout or file truncation errors occur.
- For CNC program documents, verify that the parsed code segments retain line breaks and formatting completely.
- Adjust the `chunkSize` parameter, compare chunking results under different configurations, and confirm that associated information is not split.

The values provided here are common starting points and should be evaluated against local samples.
