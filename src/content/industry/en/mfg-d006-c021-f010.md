# Inspection and Process Record Audit for Furniture and Wood Product Manufacturing: Knowledge Base Retrieval and Recall

## What this category of data looks like
Data for this category comes from order design systems, sheet wood batch ledgers, CNC cutting and drilling equipment, ERP/MES systems, and moisture content testing equipment of custom home furnishing, panel/solid wood furniture, and door enterprises.
Daily documents include order breakdown drawings, cutting lists, edge banding and drilling programs, coating process specifications, hardware accessory lists, trial assembly and packaging records.
Covered fields include panel size (millimeters), sheet moisture content percentage, hardware model numbers, cutting program numbers, and more.
Data is updated when an order is generated, daily production data is synchronized, and updates are applied after each batch of material testing.

## What constraints these characteristics impose on knowledge base retrieval and recall
Multi-document association, mixed formats, and varying update rhythms create multiple constraints for knowledge base retrieval and recall.
A single custom order links to dozens of documents such as breakdown drawings and cutting lists. It requires precise differentiation of multiple data sets from the same sheet batch.
Documents include structured lists, CNC programs, image breakdown drawings and other formats. It requires support for multimodal content matching.
Data updates follow order, daily, and batch schedules. It requires adaptation to incremental recall logic.
Professional fields such as panel size and moisture content require exact unit matching. This avoids invalid results caused by unit confusion during retrieval.

## How to configure settings
This configuration is formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches precision requirements for professional fields such as panel size and moisture content. Prevents low-match irrelevant data from being included |
| `limit` | Top 6–8 entries | Adapts to single custom orders with multiple linked documents. Returns an appropriate number of items for auditor review |
| `searchMode` | `mixedRecall` | Adapts to mixed document scenarios including structured lists, CNC programs, and image breakdown drawings |
| `usingReRank` | Enabled | Performs secondary sorting on initial recall entries. Prioritizes core audit fields such as hardware model numbers and hole position parameters |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands audit-related professional terms. Covers more relevant documents and improves recall coverage |
| `collectionIds` | Grouped by order/batch | Separates documents from different production batches. Prevents cross-batch data from interfering with retrieval results |

## Three common configuration errors
- Retrieval results only return 1 entry. The `limit` parameter is incorrectly set to 1, failing to match the requirement for multiple documents per order.
- Images recalled from the knowledge base fail to display. This occurs because multimodal document indexing is not enabled, or image storage paths are not included in the knowledge base sync scope.
- Knowledge base retrieval speed is too slow. Full retrieval of all production documents causes excessive resource usage. This happens when knowledge base collections are not divided by order and batch.

## How to verify correct configuration
- Import associated documents for one typical custom order. Run retrieval requests related to inspection and audit. Verify returned entry count matches the preset `limit` value.
- Upload one breakdown drawing document. Run a retrieval. Confirm the image loads and displays normally.
- Adjust the `similarity` parameter range. Test retrieval results under different thresholds. Confirm professional field matching meets audit requirements.
- Check retrieval time consumption. Confirm it falls within a reasonable range and meets production audit real-time requirements.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
