# Inspection and Process Record Audit for Complete Home Appliance Manufacturing: Workflow Orchestration
This document provides configuration guidance based on FastGPT v4.17.0.

## What Data Looks Like for This Category
Inspection and process record audit for complete home appliance manufacturing involves multi-source data. Data sources include ERP/MES systems, component batch ledgers, tightening and filling equipment, safety compliance testers, performance lab equipment, and after-sales fault databases.

Data update frequencies fall into three categories: filling and test records corresponding to each individual product, batch sampling reports produced per shift, and rework records generated on a fixed schedule.

Daily documents include configured BOMs, assembly work instructions, refrigerant filling records, electrical safety test reports, performance sampling reports, and rework records. Fields include material codes, torque parameters, filling volumes, and insulation resistance values, with corresponding units such as newton meters, grams, and megaohms.

## Constraints on Workflow Orchestration From These Characteristics
The multi-source, high-frequency update, and mixed-line production characteristics of this category impose multiple constraints on workflow orchestration.

First, large-volume mixed-line assembly requires workflows to support precise filtering of knowledge base content by product model and production batch. This prevents mixing of BOMs and work instructions for different models.

Second, real-time filling and safety test data requires workflow nodes to directly connect to raw data uploaded by equipment. No manual data entry is needed.

Third, mixed retrieval of multiple document types requires workflow configurations to adapt to field extraction rules for different documents. This ensures accurate retrieval of detection parameters for the corresponding process during audits.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Similarity Threshold | 0.75–0.85 | Home appliance inspection documents have high professional requirements. Precise matching of processes and inspection items is needed to avoid interference from mixed-line models |
| Single Search Limit | Top 8 entries | A large number of documents exist for the same model in mixed-line production. Controlling return volume prevents context overload |
| Referenced Content Template | {{docTitle}}<br>{{fieldName}}:{{fieldValue}} | Clearly display inspection item corresponding parameters, enabling auditors to quickly locate anomalies |
| Reference Template Prompt | Complete the audit based on the following inspection data: {{recall}} | Clearly instruct the AI to use retrieved document content for audit judgment |
| `variables` | Set to current production batch number, product model | Precisely filter BOMs and work instructions for the target batch, avoiding confusion from cross-model data |
| `nodeId` | Bind the IDs of safety compliance test nodes and filling record nodes | Automatically associate detection data for the corresponding process, enabling process linkage verification |

## Three Common Configuration Mistakes
- Custom variables in login-free links do not function as expected. Fields display as empty on the interface. Cause: Variable parameters for login-free links are not bound in workflow startup configuration. This prevents variables from being passed to nodes.
- Knowledge base search node authentication fails. Unauthorized users can access private inspection documents. Cause: Role permissions for the corresponding production department are not bound in workflow permission configuration. This causes authentication rules to not take effect.
- Audit results returned by the AI chat node do not reference specified document content. Cause: The configuration positions of the referenced content template and reference template prompt are mixed up. Retrieved content is not correctly inserted into the prompt.

## How to Verify Successful Configuration
- Start the workflow and pass parameters for the specified production batch. Check that retrieved documents only include BOMs and work instructions for the corresponding model. Confirm the `variables` configuration takes effect.
- Trigger linked retrieval for the safety compliance test node. Verify that returned detection data matches raw records uploaded by equipment. Confirm the node bound by `nodeId` is correctly associated.
- Check the output of the AI chat node. Confirm retrieved document content is displayed according to the preset template, and the prompt correctly incorporates retrieval results.
- Switch to an unauthorized role to access the workflow. Confirm private inspection documents cannot be retrieved. Confirm authentication configuration takes effect.
