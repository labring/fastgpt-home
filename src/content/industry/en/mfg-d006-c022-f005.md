# Inspection and Process Record Audit for Complete Home Appliance Manufacturing: Tool Calling and Plugins

## What Data for This Category Looks Like
Data sources for this category include ERP/MES systems, component batch ledgers, tightening and refrigerant charging equipment, safety compliance testers, performance lab data, and after-sales fault records. Data update rhythm follows per single product, per shift output, or sampling plans. Daily documents include configured BOM, assembly work instructions, refrigerant charging records, electrical safety test reports, performance sampling test reports, and rework records. Fields include component batch numbers, tightening torque values (newton meters), refrigerant charging amounts (grams), safety compliance test voltage values, and others.

## What Constraints These Characteristics Impose on Tool Calling and Plugins
The mixed-line assembly feature of this category requires tool calling to accurately match the current production line’s product model, to avoid incorrect assembly and inspection data calls across models. High-frequency single-product or per-shift data updates require plugins to support real-time pulling of the latest records from ERP/MES and equipment ends, to avoid using expired data. The need to integrate multiple types of heterogeneous data sources (device logs, test reports, after-sales data) requires plugin configurations to support cross-data-source parameter passing and result aggregation. Calls involving risk data such as safety compliance, refrigerant leakage, and others must strictly limit call scope and permissions, to prevent misuse of sensitive data.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool Calling Mode | Set `toolChoice` to `auto`, trigger conditions calibrated via actual testing | Adapt to the dynamic calling needs of mixed-line production, automatically match the current production line’s inspection process |
| Function Call Configuration | Enable multi-parameter binding for `functionCall` | Support passing multi-dimensional business parameters such as product model, batch number, and others |
| Plugin Timeout Threshold | 600 seconds | Covers the typical time range for equipment testing and data pulling |
| Logging Switch | Enable full-link execution logs | Facilitate tracing of call records for key links such as safety compliance, rework, and others |
| Data Source Scope Limitation | Only bind the current production line’s ERP/MES and equipment data sources | Avoid cross-production line data interference, comply with this category’s data isolation requirements |
| Parameter Passing Rule | Only allow passing inspection fields for the current batch | Ensure called data matches the current production link |

## Three Common Misconfigurations
- Phenomenon: When running a plugin via calling code, a prompt indicates a third-party library is not found, and the refrigerant charging amount compliance calculation logic cannot execute. Cause: The corresponding data analysis library for the electronics manufacturing field was not pre-installed in the plugin configuration, and inspection calculation requirements for complete home appliances were not adapted.
- Phenomenon: After calling a configured inspection plugin via a workflow, no corresponding conversation log is generated. Cause: The plugin’s logging switch was not enabled, or the log storage scope did not cover the current production line’s inspection links.
- Phenomenon: Calling a plugin across production lines obtains incorrect BOM data, leading to mixed-line misassembly. Cause: The plugin’s data source scope was not limited, and configuration documents from other production lines were called.

## How to Verify a Successful Configuration
- Trigger a single air conditioner safety compliance test process, then check if the plugin execution log includes fields such as the current batch’s tightening torque and charging amount.
- Run the plugin via calling code, attempt to calculate the refrigerant charging compliance for a specified batch, and confirm that third-party library dependencies load normally.
- Switch to the product model of another production line, then verify that the plugin only returns BOM and inspection data for the current production line.
- Use the FastGPT v4.17.0 workflow log panel to confirm that each step of the plugin call generates traceable execution records.
