# Inspection and Process Record Audit for Complete Home Appliance Manufacturing: Document Parsing and Chunking

## Data Characteristics for This Category
Typical entities in this category are air conditioner, refrigerator, washing machine, and small appliance manufacturers. Daily documents include configuration BOMs, assembly work instructions, refrigerant charging records, electrical safety test reports, performance sampling test reports, and repair records.
Data sources cover ERP/MES systems, component batch ledgers, tightening and charging device logs, safety tester data, performance lab reports, and after-sales fault databases.
Data is updated per individual product, shift operations, or sampling plans. Most documents include clear model fields, process parameters, test values, and batch information.

## Constraints on Document Parsing and Chunking
Mixed model production leads to document version differences. Chunking must accurately match models and process nodes to avoid cross-model content confusion.
High-frequency updated data for individual products requires parsing to support fast processing of small batch files.
Safety and performance test reports contain numerous unit-bearing values and fixed fields. Chunking must retain field relevance.
Repair records are tied to batch data. Chunking must retain the association between batches and corresponding faults.
Large individual assembly work instructions or sampling reports require parsing to control single chunk length reasonably, avoiding context breaks.

## Configuration Settings

| `chunkSize` | 800–1200 characters | Adapts to the paragraph length of home appliance manufacturing documents containing values and fields, avoiding overly scattered or redundant single-chunk content |
| `chunkSplitter` | Line break + semantic separation | Adapts to the segmentation logic of assembly work instructions and test reports, retaining the integrity of process steps and test items |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Covers the parsing time of documents over 10MB in size, avoiding parsing timeouts for large files |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Meets the upload requirements for single batch sampling reports or complete assembly manuals |
| `customPdfParse` | Enabled | Adapts structured parsing of PDF-format safety test reports and charging records, retaining original layout and field positions |
| `chunkSettingMode` | Manual mode | Supports custom adjustment of chunking rules for special fields and segmentation logic of home appliance manufacturing documents |

## Three Common Misconfigurations
- Phenomenon: Parsing times out for Word documents over 10MB, and the interface displays parsing failure or timeout status codes. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted to the value range suitable for large files. The default timeout duration is insufficient to cover the parsing time of large-volume home appliance manufacturing documents.
- Phenomenon: After importing Excel-format repair records or batch ledgers, the automatic split result merges multiple rows of content into one chunk. Cause: The `chunkSplitter` is not correctly configured to line-by-line separation mode, or custom separators are not enabled to match Excel line break rules.
- Phenomenon: After importing a configuration BOM document, some accurately matched test item content cannot be retrieved. Cause: Field relevance is not retained during chunking, causing key model and process parameter data to be split into different chunks, or the `chunkSize` is set too small, leading to truncation of key content.

## How to Verify Configuration Correctness
- Upload a typical assembly work instruction document, check the parsed chunk results to confirm that a single chunk contains complete process steps and parameter information.
- Upload a single safety test report over 10MB in size, verify that the parsing progress completes within the preset timeout duration with no timeout errors.
- Import an Excel-format batch ledger, check that each row of data corresponds to an independent chunk in the split results.
- Input accurate field content from the document, verify that the corresponding chunk results can be retrieved, confirming that associated information is not split.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
