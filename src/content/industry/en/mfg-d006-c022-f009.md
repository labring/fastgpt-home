# Inspection and Process Record Audit for Complete Household Appliance Manufacturing: Model Access and Configuration

## What the data for this category looks like
This data covers manufacturers of air conditioners, refrigerators, washing machines, and small household appliances. Daily documents include bill of materials (BOM), assembly work instructions, refrigerant charging records, electrical safety test reports, performance spot check reports, and repair records.
Data sources cover ERP/MES systems, component batch ledgers, tightening and charging device logs, safety compliance tester data, performance laboratory reports, and after-sales fault databases.
Data updates are performed per single product, per shift operation, or per spot check plan.

## What constraints these characteristics impose on the model access and configuration link
Multi-source, high-frequency updated data from complete household appliance manufacturing requires the model access link to adapt to different formats of device logs, system ledgers, and quality inspection reports.
The full-process data volume for a single product is relatively large, and real-time matching with the current process of mixed-line assembly is required. Therefore, the reasonable range of model context and output tokens must be limited to avoid response delays.
Multi-dimensional safety compliance, performance, and repair data require unified parsing logic. Tool calls must accurately trigger corresponding quality inspection links.
The batch data pull rhythm of ERP/MES must also be adapted to avoid interface timeouts.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | Covers the core full-process records from assembly to quality inspection for a single household appliance, matching the high-frequency updated data volume |
| `maxTokens` | `2000–3000 token` | Meets the output length requirements for multi-dimensional audit conclusions such as safety compliance, performance, and repairs, avoiding truncation of critical information |
| `quoteMaxToken` | `1500 token` | Prioritizes referencing core business documents such as assembly work instructions and refrigerant charging records, controlling the total length of referenced content |
| Workflow/API tool selection | `auto` | Adapts to multi-process verification needs under mixed-line assembly, automatically triggering tool call logic for corresponding inspection links |
| `temperature` | `0.1–0.3` | Reduces randomness of audit conclusions, improves consistency of safety compliance and performance judgments, matching the strict compliance requirements of household appliance manufacturing |
| `AIPROXY_API_ENDPOINT` | Fill in the corresponding address based on the deployment environment | Adapts the interface path for FastGPT v4.17.0 deployed domestically or overseas |
| `AIPROXY_API_TOKEN` | Use a valid key calibrated through actual testing | Ensures permission legitimacy for interface calls, avoiding authentication failures |

## Three common configuration mistakes
- Phenomenon: Tool selection fails during the tool call phase, and the model directly generates a natural language response. Cause: `toolChoice` is not set to `auto`, or the call rules for corresponding quality inspection tools are not bound. This prevents the model from triggering the preset inspection link verification logic.
- Phenomenon: Interface calls return authentication failure or 401 status code. Cause: `AIPROXY_API_TOKEN` is configured incorrectly or has expired, and does not match the authentication rules of FastGPT v4.17.0.
- Phenomenon: Audit response time for a single household appliance is excessively long. Cause: `maxContext` is configured too large, exceeding the model's context processing limit, leading to prolonged data loading time for the model.

## How to verify successful configuration
- Trigger an inspection and audit request for a single household appliance. Check if the model output includes referenced content from corresponding business documents, and confirm that the `quoteMaxToken` configuration aligns with business requirements.
- Simulate a mixed-line assembly scenario with multiple product models, trigger tool calls, and check if the model automatically matches verification tools for corresponding processes. Confirm that the `toolChoice` configuration has taken effect.
- Pull batch quality inspection report data for testing. Check the matching degree between interface response duration and the `maxContext` and `maxTokens` configurations, and adjust parameters to meet business response requirements.
- Verify the validity of `AIPROXY_API_TOKEN`, check if interface calls return normal audit results, and confirm that the authentication configuration is correct.

The values provided are common starting points and should be measured against the user's own samples.
