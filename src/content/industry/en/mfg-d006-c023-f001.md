# Inspection and Process Record Audit for Industrial Instrument Manufacturing and Calibration: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
This category of data originates from assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version logs from flow, pressure, temperature, and analytical instrument manufacturers and metrology laboratories. Data sources include design documents, standard instruments, environmental monitoring data, calibration software outputs, laboratory information systems, and customer range requirements. A unique dataset is generated for each tested instrument during every calibration. Dataset fields include traceability numbers, calibration environment temperature and humidity, multi-point measurement error values, and qualification determination results. Units include metrology-specific units such as ℃, kPa, and ppm. Updates take effect immediately upon completion of a single calibration workflow.

## Constraints on HTTP Interfaces and External Systems
The data characteristics of this category impose multiple constraints on HTTP interfaces and external systems. A unique dataset is generated for each tested instrument during every calibration. Interface requests must bind the traceability identifier of a single instrument. Multiple instruments’ records cannot be sent in a single request. Fields include metrology-specific units and traceability numbers. Interfaces must support custom field mapping rules to prevent unit conversion errors or loss of traceability information. Calibration records are core deliverables. Interface transmission must use authentication mechanisms to ensure data integrity. Interfaces must also connect to laboratory information systems to synchronize calibration workflow node information. The data volume of a single request must match the calibration data volume of a single instrument.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {laboratory-specific API key}` | Calibration data for this category requires strict access control. Using a dedicated key for authentication prevents unauthorized access |
| `variables` | `{"unit_mapping": {"℃": "摄氏度", "kPa": "千帕斯卡"}}` | Meets field display requirements for metrology-specific units. Ensures units received by external systems comply with industry standards |
| `responseData` | `Return only status and trace_id fields` | Interfaces for this category only need to confirm request receipt status and traceability identifier. Returning redundant data is unnecessary, reducing transmission load |
| Request timeout | 600 seconds | Processing complete calibration data for a single instrument takes a long period. This prevents timeout interruptions to calibration record synchronization workflows |
| Batch request threshold | 1 entry per request | Data for this category is generated per single calibration. Only one instrument’s records can be synchronized per batch. This prevents mixing of calibration data from different instruments |

## Three Common Misconfiguration Issues
- Symptom: After configuring Feishu Webhook, testing the hook_url individually sends messages normally, but pushing calibration records assembled via loop nodes fails to trigger delivery. Cause: Dynamic variables are not bound in the interface configuration. Multiple segments of calibration data generated by the loop cannot be passed to the request body.
- Symptom: After deploying via Docker Compose, relevant OneAPI configuration parameters cannot be found. External systems fail to forward requests. Cause: OneAPI address and authentication parameters are not added to the docker-compose.yml file. This creates missing configuration in the interface forwarding chain.
- Symptom: When using a multi-field table Webhook, only a single calibration record can be received. Multi-point measurement error data cannot be synchronized. Cause: The multi-row data parsing switch for the interface is not enabled. Multiple sets of data generated by loop nodes are truncated to a single record.

## How to Verify Successful Configuration
- Call the FastGPT built-in test interface, pass calibration record data for a single flow analyzer, and check if the externally connected laboratory information system receives complete field and unit information.
- Check the FastGPT log module to confirm that interface request authentication parameters and variable mapping rules have been loaded correctly.
- Trigger a complete calibration workflow, and check if the external system synchronously generates corresponding calibration records and traceability identifiers.
- Adjust the content spliced by the loop node, verify that dynamic variables can be correctly included in the interface request body.

The values provided are common starting points and should be measured against the reader's own samples.
