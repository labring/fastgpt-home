# Inspection and Process Record Audit for Industrial Instrument Manufacturing and Calibration: Workflow Orchestration

This configuration is written using the workflow orchestration feature of FastGPT v4.17.0.

## What the Data for This Category Looks Like
Data for this category is generated for each single instrument or single calibration activity. Daily documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version logs. Data sources include design documents, standard instrument and environmental monitoring data, calibration software outputs, laboratory information system records, and customer range requirements. A complete new dataset is generated after each instrument calibration. Fields include tested instrument model, standard instrument number, calibration date, environmental parameters, error calculation results, traceability chain number, and other relevant fields. A fixed format compliant with metrological traceability requirements must be followed.

## Constraints on Workflow Orchestration From This Category’s Characteristics
The multi-data-source nature and per-calibration update pattern of this category require workflows to trigger per single calibration task, rather than using generic batch processes. Since data must match metrological traceability formats, workflows must include built-in field validation nodes to verify the completeness of required fields such as standard instrument number and traceability chain number. The need to integrate multiple data sources requires configuring data transfer rules between workflow nodes, to ensure calibration software outputs and environmental monitoring data are combined in the order of the calibration process. The most time-consuming steps—establishing connections, calculating errors, and conducting audits—must be split into separate workflow nodes. This allows flexible adjustment of execution order, and reserves exception handling branches to address missing data or calculation deviations.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| Trigger Node Settings | Bind calibration task ID as trigger parameter | Must distinguish single calibration data for each instrument to avoid workflow confusion |
| `variables` | Configure tested instrument model, standard instrument number, and calibration date as global variables | Traceability-related fields must be reused across multiple workflow nodes to reduce repeated configuration |
| Node Timeout Setting | 600 seconds | Steps such as establishing connections between standard instruments and tested units, and collecting multi-point error data take significant time, so sufficient execution time must be reserved |
| `nodeId` | Assign independent `nodeId` to nodes that validate traceability chains and audit error results | Must independently monitor execution status of high-risk links to facilitate exception troubleshooting |
| Field Validation Rules | Configure required fields to include standard instrument number, ambient temperature and humidity, and error calculation results | Metrology certificates must fully meet traceability requirements; missing fields will cause audit failure |
| Node Flow Order | Series nodes in the order of assembly and commissioning, calibration calculation, and audit | Daily documents must follow a fixed process to ensure records are traceable |

## Three Common Mistakes
- Symptom: HTTP request nodes configured in the workflow do not trigger, and the workflow proceeds directly to the AI chat step. Cause: Calibration task parameters configured in `variables` are not passed to the request header, so request trigger conditions are not matched.
- Symptom: Workflow execution times out, and node status shows failed. Cause: Node timeout is set to 300 seconds, which is shorter than the actual time required to establish a standard instrument connection.
- Symptom: The audit link does not validate the traceability chain field, resulting in invalid metrology certificates. Cause: Traceability chain number is not configured as a required item in field validation rules, so the workflow skips compliance checks.

## How to Confirm Proper Configuration
- Review workflow trigger configuration, confirm that trigger conditions are bound to calibration task IDs, and do not use generic scheduled triggers.
- Check the `variables` configuration item, confirm that all traceability-related fields are set as globally reusable variables.
- Validate the node timeout setting, confirm that the value matches the time range of actual calibration steps. Adjust by simulating a single instrument calibration process.
- Cross-check field validation rules, confirm that all required fields for metrology audits are included in the validation scope.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
