# Inspection and Process Record Audit for Industrial Instrument Manufacturing and Calibration: Deployment and Upgrade

## What this category of data looks like
This category of data comes from design documents, standard instruments and environmental monitoring equipment, calibration software, laboratory information systems, and customer range requirements. Daily documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version records. Data is updated each time a single instrument is calibrated, with fields including calibration parameters, error values, traceability numbers, environmental temperature and humidity, and more. Units include pascals, degrees Celsius, flow units, and others. Calibration records are the core deliverable and require full traceability.

## What constraints these characteristics impose during deployment and upgrade
This category of data is updated each time a single instrument is calibrated, requiring support for high-frequency, small-batch data writing and retrieval. Document types include structured calibration records and unstructured error curves, requiring adaptation to multi-format parsing. Calibration records are the core deliverable, requiring guaranteed data traceability and access permission control. Data sources include external standard instrument data and customer-defined requirements, requiring support for external data source docking. During deployment, preprocessing capabilities for multi-format parsing must be reserved. During upgrade, format migration of original calibration records must be supported to avoid interrupting metrology audit workflows.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://calib_user:secure_pass@db.example.com:27017/calibration_db?authSource=admin` | Stores structured data such as calibration records and error curves, matching the data docking format of laboratory information systems |
| `REDIS_URL` | `redis://:redis_pass@cache.example.com:6379/0` | Caches frequently accessed calibration procedures and metrology certificates to shorten retrieval response times |
| `FILE_TOKEN_KEY` | Custom 32-character random string | Protects download permissions for files such as calibration records and error curves, preventing unauthorized access |
| `STORAGE_S3_ENDPOINT` | `http://minio.lab.example.com:9000` | Stores batch-generated error curve and metrology certificate files, adapting to multi-node access requirements |
| Single search limit | `Top 10 entries` | The document types to be matched for calibration audits are concentrated, and a small number of results can cover core audit basis |
| Maximum context length | `8000 token` | The text length of calibration records and error curves is moderate; 8000 tokens can fully cover the audit content for a single calibration run |

## Three common mistakes
- Phenomenon: Some open-source versions only allow adjustment of simple AI configuration parameters, and custom reference templates and prompt words cannot be modified. Cause: The FastGPT v4.17.0 or later version is not upgraded; earlier versions do not provide this configuration entry.
- Phenomenon: After users with login-free links delete conversation content, background log synchronization is also deleted. Cause: Independent log storage and user conversation data isolation rules are not configured during deployment, resulting in bound storage of conversation and log data.
- Phenomenon: Complete content of chunked indexes cannot be obtained when retrieving calibration records. Cause: The `REDIS_URL` or `STORAGE_S3_ENDPOINT` parameters are not configured correctly, resulting in failed access to chunked cache or stored data.

## How to confirm successful configuration
- Submit a calibration record import task for a single instrument, check that the task status is "Completed" and document parsing fields are complete, confirming that database and storage configurations are effective.
- Access the authorized download link for a calibration procedure, verify that only authorized users can obtain the file, confirming that the `FILE_TOKEN_KEY` configuration is valid.
- Trigger a calibration record retrieval request, check that the returned results include corresponding calibration parameters, error values, and traceability numbers, confirming that retrieval configurations and data source docking are working properly.
- After upgrading to FastGPT v4.17.0, open the AI advanced configuration interface, confirm that custom reference templates and prompt words can be modified, confirming that the version upgrade is effective.
