# Inspection and Process Record Review for Process Change and Engineering Change: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data for this category originates from PLM, ERP, MES, supplier materials, validation tests, and customer-specific requirements. Updates trigger irregularly each time a change occurs. Daily generated documents include ECN/ECR forms, change assessment reports, drawings and BOM version files, process validation reports, production switching plans, inventory disposal documents, and customer approval documents. Core fields include change number, version number, effective date, affected bill of materials, and validation result identifier. No unified fixed unit requirements apply. Metering rules align only with the corresponding document type.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
Data sources for this category are scattered, and updates follow no fixed schedule. Multi-turn dialogue must real-time associate with data source variables for the current change. This avoids loading outdated or irrelevant historical documents. Document structures are complex and include long-form content. Prompt engineering must gradually break down the cascading impacts of changes. It must guide dialogue to focus on validation links for design, materials, and processes. Extraction of core fields must clearly define scope. This prevents dialogue from returning other business data unrelated to the current change. It is also necessary to verify the presence of key documents such as customer approval files. This avoids missing compliance requirements.

## How to configure
Configuration examples on this page use FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Bind data source variables for the current change from PLM/ERP/MES, only load change documents associated with the session | Avoid loading historically irrelevant documents, resolve the issue of repeated parsing of historical files during sessions |
| Single search limit | Top 8 entries | The number of change-related documents is limited; too many results will dilute critical context |
| `messages` | Retain the last 12 rounds of dialogue context, truncate historical content exceeding 8000 tokens | Change review requires tracing the full workflow from application to validation; overly long context will interfere with core information extraction |
| Maximum context | 6000–10000 tokens | Adapt to long-form content such as drawings and BOM included in change documents |
| `chatId` | Bind the change number as the session identifier, isolate context for different changes | Prevent confusion of session data across different changes, ensure independence of session context |

## Three common misconfigurations
- Irrelevant historical change documents load during sessions. The cause is failure to bind `chatId` to the current change number. This results in shared session context across different changes.
- Prompt engineering fails to clearly limit document types. Returned results include irrelevant production scheduling or procurement data. The cause is failure to specify in the prompt to only retrieve change-related documents such as ECN/ECR forms and process validation reports.
- Global variables reset after a session ends. The cause is failure to configure session-persistent variables. Only temporary variables store change information, leading to variable reinitialization for each session.

## How to confirm correct configuration
- Upload the ECN document for the current change. Trigger a dialogue, and confirm parsed results only include content from this document. No historical change document information appears.
- Input questions related to the scope of change impact. Confirm returned results only include materials, processes, and validation information associated with the current change. No other irrelevant business content appears.
- Re-enter the same change session after 24 hours. Confirm previously set global variables remain intact. They are not cleared.
- Trigger a knowledge base search. Confirm only the document library bound to the current change is retrieved. No other irrelevant document entries appear.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
