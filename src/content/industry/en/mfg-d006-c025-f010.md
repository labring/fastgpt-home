# Inspection and Process Record Audit for Tooling, Fixture and Gauge Manufacturing: Knowledge Base Retrieval and Recall

## What data for this category looks like
The primary entities for this category are tooling departments at automotive, aerospace, and mechanical assembly enterprises, as well as dedicated tooling suppliers. These entities produce daily documents including tooling requirement documents, positioning datum schemes, fixture drawings, gauge operation manuals, acceptance reports, calibration records, and change histories. Data sources include product 3D models and GD&T, process routes, coordinate measuring machine data, on-site trial feedback, and metrology systems. Updates follow project progress, trigger on each product change, and occur during regular calibration exercises. Documents include fields such as version numbers, tolerance parameters, calibration dates, and change records. Units include millimeters, microns, hours, and other professional metrology parameters.

## What constraints these characteristics impose on knowledge base retrieval and recall
Documents for this category must match the current project’s product version and tolerance requirements. Retrieval must accurately filter content from non-target projects. Multi-source heterogeneous data formats require retrieval support for semi-structured GD&T parameters, coordinate measuring machine coordinate data, and structured calibration records. The update schedule tied to projects and change triggers requires the knowledge base to isolate document collections by project, and support fast synchronization of latest change histories and calibration data. Specialized industry terminology requires retrieval to cover abbreviations and industry-specific expressions, to avoid missing relevant document recalls.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Tooling fixture documents contain precise tolerances and datum parameters. Low-match irrelevant results must be filtered out. |
| `limit` | Top 8 entries | Single project document volume is moderate. Sufficient candidates are retained for subsequent re-ranking and filtering. |
| `usingReRank` | Enabled | Inspection and audit require precise matching of professional content. Re-ranking improves result relevance and accuracy. |
| `datasetSearchUsingExtensionQuery` | Enabled | The tooling industry has many specialized abbreviations and terms. Query rewriting covers more relevant documents. |
| `collectionIds` | Bound to project-specific variables | Isolate tooling document collections by project to avoid recalling irrelevant content across projects. |
| `searchMode` | `embedding` | Adapts to semantic matching requirements for semi-structured content such as GD&T and coordinate measuring machine data. |

## Three Common Misconfigurations
- Symptom: After setting a re-ranking model, the re-ranking result returned by the question-and-answer workflow is false. Cause: The `usingReRank` function is not enabled in the knowledge base configuration, or the re-ranking model is not correctly associated with the currently used dataset.
- Symptom: When selecting a variable for application in the "Knowledge Base Search" node of a workflow, no optional content appears in the reference variable dropdown menu. Cause: A text variable storing the knowledge base collection ID is not defined in the workflow or global variables, or the variable type is configured incorrectly.
- Symptom: After dynamically specifying a knowledge base, recalled results include documents from non-target projects. Cause: The `collectionIds` configuration is not bound to a project-specific variable, leading to recall of historical documents from unrelated collections.

## How to Verify Configurations Are Correct
- Access the knowledge base configuration page of FastGPT v4.17.0. Confirm the `usingReRank` toggle is enabled, and the specified re-ranking model is bound.
- Enter a tooling inspection-related query in the workflow test node. Check if valid numerical values appear in the re-ranking score field of returned results.
- Configure `collectionIds` as a project variable. Switch the variable value during testing. Confirm recalled documents only come from the corresponding project’s collection.
- Enable `datasetSearchUsingExtensionQuery`. Enter specialized tooling terms. Check if retrieval results cover relevant datum schemes and calibration records.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
