# Inspection and Process Record Audit for Garment Cutting and Sewing: Document Parsing and Chunking

## What Data for This Category Looks Like
Typical subjects for this category include garment OEM/ODM manufacturers, brand supply chains, and cutting and sewing workshops. Daily generated documents include process sheets, patterns, layout plans, cutting orders, first sample seals, process quality forms, and packaging and size matching lists.
Data sources include orders and size charts, CAD patterns, material inspection records, hanging system data, needle detector records, and customer sealed samples. Update frequency is once per order, per style, and per batch.
Documents include dedicated fields such as size, color batch, cutting piece number, and process requirements. Some documents are vector formats exported from CAD, while others are structured table documents.

## Constraints Imposed by These Characteristics on the Document Parsing and Chunking Link
This category has significant structural differences across document types. Some documents are layout plans with vector annotations exported from CAD, while others are structured table documents with multiple fields. Parsing and chunking workflows must support content extraction across different formats.
High-frequency updated order and batch data require parsing processes to have sufficient response speed. Delays in parsing must not disrupt audit progress in production links.
Dedicated fields such as size, color batch, and cutting piece supporting information form the core audit basis. The chunking process must ensure that the context of these key pieces of information is not truncated. Truncation will lead to deviations in the audit link.
The irreversible nature of cutting piece production requires a high standard of parsing result accuracy. Chunking errors must not cause loss of key verification information.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapt to multi-field documents such as process sheets and process quality forms, retain complete context of key information such as processes and sizes |
| `chunkSplitter` | Chunk by paragraph + semantics | Adapt to documents with large format differences such as layout plans and cutting orders, avoid splitting associated fields such as cutting piece numbers and sizes |
| `customPdfParse` | Enable structured parsing mode | Adapt to layout plans and pattern documents exported from CAD with vector annotations, extract structured annotation information from non-standard PDFs |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120–180 seconds | Address parsing time consumption of large-size layout plan PDFs, avoid parsing failure due to timeout |
| `UPLOAD_FILE_MAX_SIZE` | 200 MB | Accommodate batch upload requirements for batch cutting orders and process sheets, adapt to processing scenarios for multi-batch documents |
| `chunkSettingMode` | Manual configuration | Adjust chunking parameters for different document types, adapt to parsing requirements for multi-format documents in the garment category |

## Three Common Misconfigurations
- Symptom: Some PDF files cannot be recognized, and parsing results are empty. Cause: `customPdfParse` is not enabled to adapt to layout plan documents exported from CAD with vector annotations. The default parsing method cannot extract structured content from non-standard PDFs.
- Symptom: No response from the parsing node after file upload, and the task times out. Cause: `PARSE_FILE_TIMEOUT_SECONDS` is not adjusted to a value adapted to large-size layout plans. The default timeout duration is insufficient to complete complex document parsing.
- Symptom: Parsed chunks lose key field information such as size and color batch. Cause: `chunkSize` is set too small, splitting associated fields into different chunks and causing context breakage.

## How to Verify Correct Configuration
- Upload a typical process sheet PDF, and check whether the parsed result contains complete process and size field content.
- Upload a layout plan PDF exported from CAD, and confirm that cutting piece numbers and size annotation information can be extracted after `customPdfParse` is enabled.
- Upload a batch of cutting orders with a single file size not exceeding 200 MB, and check whether the parsing task completes within 180 seconds.
- Adjust `chunkSettingMode` to manual mode, fine-tune `chunkSize` for different document types, and verify whether chunks retain the associated context of key fields.

The values provided are common starting points and should be measured against the reader's own samples.
