# Incoming Material Inspection and Supplier Quality Inspection & Process Record Review: HTTP Interfaces and External Systems

## Data for this category
Data sources for this category include purchase orders, drawings and specifications, supplier quality certificates, inspection equipment, historical quality data, and supplier portals. Daily processed documents include inspection specifications, sampling plans, incoming material reports, supplier audit reports, abnormal notification sheets, 8D reports, and concession acceptance approval forms. Data is synchronized once per batch of incoming materials. Overall supplier quality evaluations are completed monthly or quarterly. Special audits are conducted on an irregular basis. Data fields include batch number, supplier code, inspection items, qualified judgment results, and defect levels. Corresponding units include batch, piece, item, and similar units.

## Constraints on HTTP interfaces and external systems
Data sources for this category are scattered and mostly sourced from external supplier systems. HTTP interfaces must support multi-source authentication and data format adaptation. High-frequency batch data updates (per batch of incoming materials) require interfaces to implement reasonable timeout and retry mechanisms. This prevents data synchronization interruptions caused by delayed responses from external systems. Multiple types of business documents require interfaces to support varying `responseData` structures, and use `variables` to accurately match core fields in incoming material reports and supplier audit reports. Additionally, data errors can trigger batch production failures or line shutdowns. Interfaces must include complete failure logging and alert capabilities.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {custom secret}` | Identity authentication when connecting to supplier portals and inspection equipment interfaces, ensuring data access security |
| `variables` | `["batchNo", "supplierCode", "inspectionResult"]` | Matches core fields of incoming material inspection sheets, enabling automatic mapping of external system data to FastGPT knowledge bases |
| `responseData` | Extract the first 20 entries after deduplication by batch number | Adapts to the data volume scale of each batch of incoming materials, avoiding interface return overload that affects synchronization efficiency |
| Interface timeout period | `600 seconds` | Adapts to slow response scenarios of supplier portal interfaces, preventing synchronization failures caused by mid-connection disconnections |
| Number of failed retries | `3 times` | Balances data reliability and timeliness requirements for incoming material inspection, reducing the impact of occasional network issues |

## Three common configuration errors
- Symptom: Uploading PDF or Excel files related to incoming material inspection fails, but template import functions work normally. Cause: The interface path for file upload is configured incorrectly, or the request header does not correctly match data format requirements, leading to failed interface verification.
- Symptom: Calling external supplier interfaces returns a 401 unauthorized error, or quality certificate data cannot be pulled. Cause: The `Authorization` parameter is not configured correctly, the secret has expired, or permission scope is insufficient.
- Symptom: External interfaces cannot be accessed via HTTPS after local deployment. Cause: The docker-compose.yml configuration for mounting certificate files is not modified correctly, or certificate path and file permission configurations are incorrect.

## How to verify successful configuration
- In the interface debugging page of FastGPT v4.17.0, pass a simulated supplier batch number, call the test interface, and check if the returned `responseData` includes core fields of incoming material inspection.
- View interface operation logs to confirm that the `Authorization` parameter is correctly carried, and there are no authentication failure or timeout error records.
- Upload a standard incoming material inspection report file, and verify that data can be synchronized normally to the configured external system.
- Use a curl command to test the HTTPS interface, confirm that there are no certificate-related connection errors, and that return data can be retrieved normally.

The values provided are common starting points and should be measured against the reader's own samples.
