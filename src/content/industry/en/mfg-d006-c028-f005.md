# Incoming Material Inspection and Supplier Quality Inspection & Process Record Review: Tool Calling and Plugins

## Data Profile for This Category
Data sources for this category include purchase orders, drawings and specifications, supplier quality certificates, inspection equipment, historical quality data, and supplier portals. Daily processed documents cover inspection specifications, sampling plans, incoming material reports, supplier audit reports, exception communication sheets, 8D reports, and concession acceptance approvals.
Data updates are triggered per incoming batch, monthly or quarterly supplier evaluations, and ad-hoc audits. Data fields include batch number, sampling quantity, defect level, rectification deadline, supplier number, and others. Corresponding units are pieces, batches, level codes, days, and identification numbers.

## Constraints Imposed on Tool Calling and Plugins Workflow
Multiple scattered data sources require tool calling to support integration with multiple external systems, including supplier portals and historical quality databases.
High-frequency update business rhythms require tool calling to trigger in real time, to meet immediate inspection needs for each incoming batch.
Diverse document formats require plugins to support parsing multiple types of business files such as structured tables and PDF reports.
Specific business fields require tool calling parameters to match dedicated incoming material inspection fields, avoiding field mismatch issues caused by generic parameters.
Standardized business documents require tool calling output to follow a fixed format, facilitating subsequent process flow and review.

## Configuration Settings
All configurations below are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | Incoming material inspection needs to call multiple types of tools such as supplier data and inspection specifications. The auto mode automatically matches required tools |
| Workflow/API function-call configuration | `enabled` | Standardized incoming material reports and exception communication sheets need to be generated. Structured output facilitates subsequent process flow |
| Stop sequences | Enter `---`, `【结束】` | Distinguish tool calling output from business document content to avoid confusion |
| Tool calling timeout | `600 seconds` | Sufficient time is required to pull cross-system data when integrating with supplier portals and historical quality databases |
| Cache validity period | `7 days` | Matches the update frequency of monthly/quarterly supplier evaluations, preventing expired data from being called |

## Three Common Configuration Mistakes
- Tool calling nodes stall after execution with no error logs. The cause is that reasonable timeout parameters are not configured for external data sources such as supplier portals and historical quality databases. The default timeout period is insufficient to complete cross-system data pulling.
- Base64-encoded inspection equipment images in plugin-generated content fail to render properly. The cause is that base64 image format support is not enabled in the plugin, or the input base64 encoding contains invalid line break characters leading to parsing errors.
- Tool calling still outputs excess content after configuring stop sequences. The cause is that the stop sequence value does not match the delimiter in business documents, or stop sequence validation is not enabled in the tool calling output rules.

## How to Verify Successful Configuration
- Trigger a simulated incoming material inspection tool call, and check if matching supplier data and inspection specification tools are automatically called.
- Input image content with valid base64 encoding, and confirm that the image displays correctly after rendering.
- After configuring stop sequences, insert the specified delimiter into the tool calling output, and check if the output is truncated at the delimiter.
- Call the integrated model interface, and confirm that the return status code is 200 with no 404 errors.
