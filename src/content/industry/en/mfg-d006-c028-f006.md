# Incoming Material Inspection and Supplier Quality Inspection & Process Record Review: Source Citation and Traceability

## What this category’s data looks like
This category of data covers multiple types of business documents and system data. Daily documents include inspection specifications, sampling plans, incoming material reports, supplier audit reports, abnormal contact sheets, 8D reports, and concession acceptance approval forms. Data sources include purchase orders, product drawings and specifications, supplier quality certificates, inspection equipment records, historical quality databases, and supplier portal data.
Data update frequency changes based on business scenarios. Corresponding inspection reports and records are generated for each batch of incoming materials. Overall supplier evaluations are conducted monthly or quarterly. Special audits are carried out irregularly.
Document fields include batch number, supplier ID, inspection date, non-conformity item descriptions, corrective actions, and other items. There is no unified fixed format. Some documents require association with multi-dimensional data to complete traceability.

## Constraints on the source citation and traceability link
The data characteristics of this category impose multiple constraints on the traceability link.
Multi-source and scattered data sources require the traceability system to associate multiple types of data sources such as purchase orders, supplier portals, and inspection equipment records. This avoids missing key information.
Frequently updated business data requires the traceability logic to match the latest batch and evaluation data in real time. This ensures the timeliness of cited content.
Diverse document structures and non-unified fields require traceability rules to adapt to exclusive fields of different documents, such as batch number and supplier ID. General matching logic cannot be relied on.
Multi-dimensional association requirements require the traceability result to display document sources, update times, and core fields at the same time. This supports auditors in completing complete quality traceability.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `quoteMaxToken` | `8000–12000 token` | Single batch of incoming material inspection-related documents has a large data volume, which needs to cover multiple inspection reports, 8D reports and other content to avoid truncation of key traceability information |
| `responseData` | Enable and return complete source data fragments | It is necessary to accurately display exclusive fields such as incoming material batch number and supplier ID to support auditors in verifying traceability details |
| `detail` | Enable | It is necessary to display the source path and update time of the cited document, and match the update rhythm of supplier quality certificates and historical quality data |
| Single recall citation count | `Top 3–5 entries` | Incoming material inspection-related citations need to focus on core batch and supplier information. Too many entries will increase the context processing burden |

## Three common configuration mistakes
- Phenomenon: After the knowledge base tool is called in the workflow, the returned result does not associate the corresponding incoming material inspection document, and the core fields are empty. Cause: The `responseData` configuration for returning source data is not enabled, or the exclusive retrieval rules matching batch numbers and supplier IDs are not configured.
- Phenomenon: Unclosed citation marks appear in the AI output results, which are automatically corrected to standard quotation marks afterwards. Cause: The citation format verification of the `detail` configuration is not enabled, or the standard citation field format of the document is not matched.
- Phenomenon: Knowledge base retrieval times out, or the single-round context is forcibly truncated. Cause: `quoteMaxToken` is set to a value exceeding the system processing limit, such as `50000 token`, which exceeds the single-round token carrying range of FastGPT v4.17.0.

## How to verify successful configuration
A simulated query for a specific incoming material batch is initiated. The returned result is verified to include the corresponding supplier's quality certificate and incoming material inspection report fragments.
The citation marks in the output result are reviewed. The format is confirmed to conform to standard quotation marks, with no unclosed abnormal marks.
The single-round query context log is reviewed. The token count is confirmed to not exceed the preset `quoteMaxToken` upper limit.
The workflow calling the knowledge base tool is tested. The returned result is confirmed to include exclusive business fields such as batch number and inspection date.

The values provided are common starting points and should be measured against the reader's own samples.
