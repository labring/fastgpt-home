# Incoming Material Inspection and Supplier Quality Inspection & Process Record Review: Document Parsing and Chunking

## What the Data for This Category Looks Like
Data for this category originates from purchase orders, drawings and specifications, supplier quality certificates, inspection equipment data, and supplier portals.
Daily processed document types include inspection specifications, sampling plans, incoming material reports, supplier audit reports, exception contact sheets, 8D reports, and concession acceptance approval forms.
Data updates trigger with each batch of incoming materials, monthly or quarterly supplier evaluations, and irregular audits. No fixed unified update cycle exists.
Most documents include fields such as batch number, inspection items, judgment results, and rectification requirements. Some documents contain numeric inspection data and unit labels.

## What Constraints Do These Characteristics Impose on the Document Parsing and Chunking Workflow?
Data sources are scattered and formats vary widely. Structured Excel incoming material reports exist alongside formal PDF audit documents. Parsing rules must support multiple formats.
Update frequency has no fixed cycle and ties to individual batches. Chunking must retain associated identifiers such as batch number and supplier. Context must not be split apart.
Document fields include specialized quality terminology and numeric units. Chunking must preserve field associations to prevent splitting that breaks links between inspection items and judgment results.
Some documents contain long-process rectification records. Cross-step rectification logic must not be split across different chunks.

## How to Configure Settings
The following configurations are based on the parameter rules for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Adapts to the length of documents in this category, which include specialized terminology and numeric fields. Prevents loss of associated information after splitting |
| `chunkSplitter` | Split by paragraph + heading | Matches the structured sections of documents in this category, such as inspection items and rectification steps. Preserves logical integrity |
| `customPdfParse` | Enabled | Adapts to PDF-format supplier audit reports and 8D reports. Retains original layout and field positions |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Addresses batch parsing requirements for multiple incoming material reports. Prevents timeout during parsing of large files or multiple files |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Accommodates batch historical quality data and supplier document packages. Supports batch-level data uploads |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for different document types in this category, such as Excel incoming material sheets and PDF audit reports. Meets personalized needs |

## Three Common Configuration Mistakes
- Uploading an Excel-format incoming material inspection report results in empty processed data. The cause is failure to configure parsing adaptation for structured tables. The system’s default text block splitting causes field loss.
- Timeout errors occur during batch parsing of PDF-format supplier audit reports. The cause is failure to adjust the `PARSE_FILE_TIMEOUT_SECONDS` parameter to a duration suitable for batch documents. The default timeout length is insufficient for parsing large volumes of multiple files.
- Vectorization takes an excessively long time. The cause is failure to properly set the `chunkSize` parameter. Oversized chunks lead to excessive single-block embedding calculation loads, or failure to enable targeted document chunking optimization rules.

## How to Verify Successful Configuration
- Upload a single Excel incoming material inspection report. Check if parsed data chunks retain associations between core fields such as batch number, inspection items, and judgment results.
- Upload a batch of PDF-format supplier audit reports. Confirm that parsing completes within the duration specified by `PARSE_FILE_TIMEOUT_SECONDS`.
- Test a single small-volume 8D report. Confirm that rectification step logic is fully retained after chunking, with no cross-step splitting.
- Check the total size of uploaded files. Confirm that the total does not exceed the threshold set by `UPLOAD_FILE_MAX_SIZE` to prevent upload blocking.

The values provided are common starting points. They should be evaluated against the reader’s own samples.
