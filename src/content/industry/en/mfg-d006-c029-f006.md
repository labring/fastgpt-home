# Inspection and Process Record Audit for Mold Design and Manufacturing: Citation Source and Traceability

## What this category of data looks like
This category of data originates primarily from customer product models, mold flow/forming simulation files, CAD/CAM design source files, machining and coordinate measuring machine data, and sample test inspection records. Daily documents include mold design task sheets, DFM reports, part manufacturing drawings, process cards, mold trial reports, mold modification notices, and mold history records.
Data updates proceed on a per-project basis. New or modified content is added after each mold trial, mold modification, or assembly debugging. Document fields include exclusive information such as cavity parameters, material grades, and defect rectification records.

## What constraints these characteristics impose on the citation source and traceability link
Data for this category comes from scattered sources with diverse formats, including structured process cards, unstructured mold trial reports, CAD binary files, and more. The citation traceability link must support parsing and chunking rules for multiple data source types.
Data update frequency fluctuates with project iterations. Each mold trial or mold modification creates a new traceability node. Index updates must be synchronized with project progress.
Business weights vary significantly across different documents. Historical mold modification records in mold history records and mold trial defect rectification data are core audit basis. High-weight document content must be prioritized during the recall phase.

## How to set up the configuration
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `quoteMaxToken` | 800–1200 token | Mold design documents have longer single-block content. This range ensures citation snippets fully cover process parameters or defect rectification records |
| Context recall count | Top 6–8 entries | A single mold project involves documents across design, machining, and mold trial stages. This range covers full-process traceability basis |
| Traceability detail display | Enabled | Auditors need to view the document type and generation time of citation sources, which matches the traceability requirements of mold projects |
| Citation source sorting | By document business weight | Core documents such as mold trial reports and mold modification notices are displayed first, which aligns with the business logic of mold audits |
| `responseData` | Include sourceMetadata field | Citation source metadata such as document ID and update time must be retained for subsequent traceability verification |
| `detail` | Enable full fields | Display contextual content of citation snippets to avoid out-of-context quotes, which meets the strict requirements of mold audits |

## Three common errors
- Symptom: After adjusting the `quoteMaxToken` parameter, the large model can recall mold knowledge base content, but no citation sources are displayed in the answer body. Cause: The `detail` configuration item is not enabled, so citation snippets are not included in the context range for large model generation.
- Symptom: After increasing the context recall count, no documents related to the current mold project can be recalled. Cause: Knowledge base documents are not grouped by individual project, which causes irrelevant cross-project data to interfere with recall matching.
- Symptom: Unable to obtain mold design-related traceability content when calling the private knowledge base API. Cause: The return field of `responseData` is not configured correctly. Not enabling metadata return causes the interface to fail to return valid recall results.

## How to confirm the configuration is correct
- Initiate a query containing mold process parameters or mold trial defects. Check whether the answer body includes the document name and generation time of the citation source.
- Adjust the `quoteMaxToken` parameter, then verify that the length of the citation snippet covers complete process card or mold trial report content.
- Call the API interface to confirm that the return result includes traceability metadata information under the `responseData` field.
- Test queries after multiple mold modifications. Verify that the recalled documents include the latest mold modification notices and mold trial reports.

The values provided here are common starting points and should be measured against the reader's own samples.
