# Inspection and Process Record Review for Mold Design and Manufacturing: Knowledge Base Retrieval and Recall

## What the data for this category looks like
This category of data primarily comes from customer product models, mold flow/forming simulation files, CAD/CAM source files, machining and measurement data, and trial mold samples.
Daily documents include mold design task sheets, DFM reports, part drawings, machining process cards, trial mold reports, mold modification notices, and mold records.
Data updates are triggered by project milestones. Updates are synchronized after each trial mold or mold modification.
Documents include fields such as mold number, demolding angle, shrinkage rate, and machining tolerance. Most dimensional fields use millimeters as the unit.
Trial mold data is associated with corresponding batch production parameters.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
Mold design and manufacturing data includes structured parameters and unstructured drawings and reports.
Multi-format data sources require retrieval tools to support CAD, PDF, text, and other file types.
Following the high-frequency update rhythm tied to project milestones, trial molds, and mold modifications, incremental recall is needed to avoid the overhead of full reconstruction.
Documents contain precise fields such as mold number and tolerance parameters. Retrieval must support field-level matching to narrow result scope.
Documents like trial mold reports and mold modification notices are linked to specific projects. Retrieval must use project dimension filtering to exclude irrelevant results.
This prevents recalling historical data from non-current projects, which could lead to excessive mold modifications or production delays due to incorrect data.

## How to set configurations
The following configurations are based on FastGPT v4.17.0, adapted for knowledge base retrieval needs for the mold design and manufacturing category:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.72–0.85 | Mold design parameters have high precision requirements. Low-match irrelevant documents must be filtered to avoid recalling incorrect demolding angle or tolerance data |
| `limit` | Top 8–12 results | Single-project document volume is moderate. Too many results exceed the context window. Too few results fail to cover mold modification history and trial mold data |
| `searchMode` | `mixedRecall` | Balances semantic matching for design logic and keyword matching for mold numbers and tolerance fields. Adapts to mixed-format documents |
| `usingReRank` | Enabled | Reranks recall results to prioritize content containing the latest mold modification notices or trial mold reports. Improves timeliness |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands retrieval terms to add category-specific terminology such as mold flow simulation and DFM reports. Boosts recall accuracy |
| `collectionIds` | Bind exclusive collections by project | Isolates mold data across different projects to avoid cross-project recall interference. Aligns with project-based data update characteristics |

## Three Common Misconfigurations
- Phenomenon: Knowledge base retrieval takes too long, exceeding business processing time limits. Cause: `usingReRank` is not enabled and the `similarity` threshold is set too low. This results in too many low-match documents being recalled, increasing processing overhead.
- Phenomenon: Retrieval returns an insufficient number of results to cover all mold modification history and trial mold data for the project. Cause: The `limit` value is lower than the actual required number of documents. It fails to match multiple associated documents within the project.
- Phenomenon: Recall results include mold records and trial mold reports from non-current projects. Cause: Exclusive datasets are not bound via `collectionIds`. Cross-project data is not isolated, leading to data confusion.

## How to Confirm Proper Configuration
- Submit a retrieval term that includes a mold number and demolding angle. Check whether the recall results include trial mold reports and mold modification notices for the corresponding project.
- Check retrieval latency to confirm it falls within business-allowed time limits with no significant delay.
- Switch the `collectionIds` for different projects. Verify that recall results only include documents from the currently bound project.
- Adjust the `similarity` threshold. Verify that low-match irrelevant documents are effectively filtered.

The values provided are common starting points and should be measured against the reader's own samples.
