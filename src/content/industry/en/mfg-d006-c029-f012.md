# Inspection and Process Record Audit for Mold Design and Manufacturing: Deployment and Upgrade

## What the data for this category looks like
The data for this category mainly comes from customer product models, mold flow/forming simulation, CAD/CAM software, machining and measurement data, and trial mold samples. Daily output documents include mold design task sheets, DFM reports, part drawings, processing technology cards, mold trial reports, mold modification notices, and mold records. Fields include parameters related to demolding feasibility, shrinkage defects, assembly accuracy, and mold life. Data updates are carried out on a per-project basis, synchronized and updated after each mold trial or modification. Data within a single project is closely linked and iterates frequently.

## What constraints these characteristics impose on deployment and upgrade
The data sources for this category are diverse, including multi-format industrial documents such as CAD models, simulation files, and measurement data. During deployment, adaptation is required for parsing and storage capabilities for non-general documents. Data is updated iteratively per project, with synchronized changes after each mold trial or modification. The deployment and upgrade link must ensure that data association relationships are not damaged, and support incremental synchronization and version rollback. The data volume within a single project is large and closely linked, so sufficient storage and computing resources must be reserved to support high-frequency read and write operations. At the same time, the data involves core parameters such as mold accuracy and life, so consistency of full-link verification must be ensured to avoid data deviations between links.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `REDIS_URL` | `redis://:custom password@server address:6379/0` | Supports high-frequency document parsing caching and session state storage, adapting to the fast read and write requirements of multi-step verification for mold projects |
| `STORAGE_S3_ENDPOINT` | Object storage endpoint adapted for industrial document storage | Stores large-volume industrial documents such as CAD models and mold trial reports, meeting the long-term storage requirements for multi-format files |
| `DB_MAX_LINK` | `20–30` | Supports the number of database connections for simultaneous parsing of multiple documents in a single project, avoids connection blocking during concurrent verification, and adapts to the concurrent processing logic of FastGPT v4.17.0 |
| File storage limit | `1000 MB` | Adapts to the total storage requirements of a single set of mold design drawings and simulation files, preventing upload failures for large-volume files |
| `PG_URL` | Dedicated relational database connection address | Stores structured data such as mold records and mold modification logs, ensuring consistency of data query and update operations |
| `ROOT_KEY` | Complex key string with a length of no less than 16 characters | Ensures the security of internal system interface calls, preventing unauthorized access to core mold data |

## Three Common Misconfigurations
- Issue: Significant lag occurs when dragging nodes on the workflow canvas after deployment, with single-node loading time exceeding 5 seconds. Cause: The `DB_MAX_LINK` parameter was not adjusted to a value suitable for multi-node concurrency, leading to exhaustion of the database connection pool and blocking of workflow node requests.
- Issue: Mold parameters recalled by the knowledge base do not match actual documents, with recalled results being empty or incorrect. Cause: Parsing rules adapted for industrial documents were not configured, leading to failure to correctly extract core fields from CAD models and DFM reports.
- Issue: Docker container failed to start, and the server returned an incompatible system error. Cause: A server system not adapted for Docker containerized deployment was selected, and system compatibility was not confirmed in advance.

## How to Verify Proper Configuration
- The system backend may be accessed, and the connection status of configuration items including `REDIS_URL` and `STORAGE_S3_ENDPOINT` may be checked to confirm no error prompts are present.
- A complete set of mold design drawings and mold trial reports may be uploaded, and the file parsing and storage process may be verified to complete successfully.
- The workflow canvas may be launched, multiple nodes may be dragged for testing, and operation responses may be confirmed to have no significant delay.
- Internal interfaces may be called to query mold record data, and structured storage and query functions may be confirmed to operate normally.

The values provided are common starting points and should be validated against applicable sample data.
