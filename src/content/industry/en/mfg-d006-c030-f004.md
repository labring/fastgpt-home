# Inspection and Process Record Audit for Rubber Compounding and Product Vulcanization: Workflow Orchestration

## What this category's data looks like
Data for this category originates from formula systems, raw material batch ledgers, internal mixers, Mooney viscometers, rheometers, vulcanizers, and laboratory testing equipment. Daily documents include formula sheets, weighing records, mixing curves, rubber compound quick test reports, vulcanization process cards, mold usage records, and finished product performance reports. Data updates are triggered when a truckload of rubber compound batches is finalized, each batch of raw materials is dispensed, and each vulcanization cycle finishes. Data fields include mixing temperature (degrees Celsius), vulcanization time (minutes), Mooney viscosity values, batch numbers, and more. Data formats vary widely across sources: device outputs are mostly structured logs, while laboratory reports are mostly semi-structured documents. ## What constraints do these characteristics impose on workflow orchestration
The high update frequency of this category requires workflows to use real-time trigger logic. This avoids data delays or omissions caused by scheduled polling. Access to multi-source heterogeneous data requires workflows to support parsing nodes for different formats. This adapts to document types such as internal mixer logs and laboratory reports. Severe error consequences require workflows to include pre-check nodes in the three core links of feeding, mixing, and vulcanization. These nodes intercept risks such as formula errors and temperature deviations. Each vulcanization cycle’s data must be separately associated with the corresponding batch’s mixing records. Workflows must support batch binding logic for `variables` to avoid data cross-contamination. Cross-link node linkage requires clear `nodeId` association rules. This ensures verification results from each process are correctly passed to the next link.

## How to Set Configuration
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| `variables` mapping rules | Bind corresponding mixing and vulcanization data by batch number | Each truckload of rubber compound uses a unique batch number, to ensure accurate data association without cross-contamination |
| `nodeId` association configuration | Bind node IDs in the process order of mixing → vulcanization → inspection | Core processes must be connected in sequence to prevent chain confusion that causes verification failures |
| Workflow trigger timing | After each truckload of rubber compound completes mixing, and after each vulcanization cycle finishes | Aligns with the data update frequency, to ensure real-time verification coverage for every batch and vulcanization cycle |
| Verification node thresholds | Mixing temperature deviation ±5 degrees Celsius, vulcanization time deviation ±2 minutes | Aligns with industry general process parameter ranges, to intercept non-compliant parameter inputs |
| Failure retry count | 2–3 times | Addresses temporary equipment fluctuations that cause verification failures, to avoid false alert triggers |
| Component replication permissions | Enable the `variables` batch export function | Supports rapid reuse of verification node configurations, to improve editing efficiency for multiple workflows |

## Three Common Misconfigurations
- Symptom: Tool call nodes return the Invalid JSON: Bad control character error. The cause is failure to escape line breaks and special characters in mixing curves and vulcanization process cards, leading to failed JSON format validation.
- Symptom: Selected workflow components cannot be dragged, copied, or moved. The cause is failure to enable the `variables` batch editing switch in the workflow editing page, preventing normal copying or movement of component attributes.
- Symptom: Connection lines cannot be added between workflow nodes, and no connection circles appear in the interface. The cause is incorrect configuration of `nodeId` association rules, leading to the system blocking the trigger link between nodes.

## How to Confirm Configuration Completion
- Import a real mixing curve document, trigger the workflow, and check whether the verification node correctly extracts core fields such as formula number and mixing temperature.
- Simulate a set of vulcanization process data that exceeds the threshold, and check whether the workflow triggers a failure alert node and generates an exception record.
- Copy a configured verification node and paste it into another workflow branch, and check whether the component’s `variables` mapping rules are fully retained.
- Open the advanced settings of the tool call node, confirm that the `nodeId` parameter has been correctly configured, and that associated node information can be viewed normally.
