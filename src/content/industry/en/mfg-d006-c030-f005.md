# Inspection and Process Record Audit for Rubber Compounding and Product Vulcanization: Tool Calling and Plugins

## What this category of data looks like
Data sources include formula management systems, raw material batch ledgers, real-time collected data from internal mixers, Mooney viscosity and rheometer test reports, vulcanizer operation logs, and laboratory finished product performance test reports. Updates occur once per raw material batch, per rubber compound production run, and per vulcanization cycle. Daily documents include: formula sheets (with rubber type ratio and feeding sequence fields), weighing records (with feeding weight and operator fields), mixing curves (with temperature and torque data over time), rapid rubber compound test reports, vulcanization process cards (with temperature, time, and pressure parameters), mold usage records, and finished product tensile strength and hardness test reports.

## What constraints these characteristics impose on the tool calling and plugins workflow
High-frequency batch data requires tool calling to pull the latest raw material and equipment parameters in real time, to avoid using expired data. Multiple document types (structured weighing records, unstructured mixing curve charts) require plugins to support multi-format data parsing and field extraction. Irreversible vulcanization processes require strict parameter validation for tool calling, to prevent the production of under-cured or over-cured defective products. The single-batch, single-cycle update logic requires that the tool calling context only associates data related to the current batch, to avoid cross-batch data interfering with audit results.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `["query_recipe_batch","check_curing_param","analyze_mixing_curve"]` | Precisely specify required business tools, avoid the large language model calling irrelevant functions, and adapt to the core audit scenarios of rubber compounding and vulcanization |
| `functionCall` | `strict: true` | Enforce that tool-returned parameters match business field requirements, for example, ratio values must use "parts" as the unit, and vulcanization time must use "minutes" as the unit |
| Context window size | `8000–12000 token` | Accommodate multiple documents for a single batch, such as formula sheets, mixing curves, and vulcanization process cards, to ensure the audit logic has sufficient contextual basis |
| Tool calling timeout | `15–30 seconds` | Adapt to data collection delays from industrial equipment such as internal mixers and vulcanizers, to prevent tool calling interruptions caused by slow device responses |
| Supported file types | Calibrated based on actual testing | Match the document formats actually used by the enterprise, for example, support CSV-format weighing records and PNG-format mixing curve charts |

## Three common errors
- Phenomenon: Inconsistent parameter formats returned by tool calls when using local large language models and online APIs. Cause: The `functionCall` strict mode configuration was not adjusted for the local large language model, leading to missing parameter fields or unit mismatches.
- Phenomenon: Empty receiving parameters when uploading files via API calls to workflows. Cause: Parameter transfer permissions for file variables were not enabled in the plugin configuration, and the parameter receiving format for file types was not specified.
- Phenomenon: Tool calling cannot be triggered when using the Qwen3-OMNI model to analyze mixing curve videos. Cause: No support rules for video formats were added in the tool configuration, and no pre-processing steps for video parsing were configured.

## How to confirm the configuration is properly set
- Trigger a test batch audit process in FastGPT v4.17.0, verify that tool calls use the preset `toolChoice` configuration to call corresponding business tools.
- Upload a single batch of mixing curve documents, confirm that the plugin can correctly extract temperature and torque parameters and return verification results.
- Upload a weighing record file via API calls to workflows, check that parameter transfer is complete with no missing fields or format errors.
- Trigger a test case with incorrect parameter formats, such as passing non-numerical ratio parameters, confirm that the system returns clear parameter verification prompts.

All provided configuration values are common starting points, and should be evaluated against the reader's own samples.
