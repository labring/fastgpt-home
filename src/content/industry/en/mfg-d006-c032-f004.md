# Inspection and Process Record Audit for Complete Vehicle Final Assembly: Workflow Orchestration

## What this category of data looks like
Daily documents for complete vehicle final assembly include production orders, VIN lists, assembly work instructions, tightening data, off-line inspection reports, rework records, and consistency and release documents. Data sources include ERP/MES, VIN and configuration systems, supplier batches, tightening tools, EOL inspection lines, and quality traceability systems. Data is updated per vehicle, in real time, and per shift. VIN serves as the main line for a single vehicle, including fields such as vehicle configuration, part batches, torque parameters, and inspection results. Units include newton meters, batch numbers, VIN codes, and station numbers, among others.

## What constraints do these characteristics impose on workflow orchestration
Mixed-model production using VIN as the single vehicle main line requires workflows to bind a single vehicle’s unique identifier as a context anchor to avoid cross-vehicle data confusion. Requirements for accessing multi-source heterogeneous data mean workflows must support parallel pulling of data from different systems such as ERP and tightening tools. Real-time updated tightening and inspection data means workflow nodes need real-time triggering and data verification capabilities, and must handle batch data processing pressure from hundreds of configuration matches for a single vehicle. Associated audits of rework records and release documents mean workflows need branch logic for cross-station data backtracking and associated verification.

## How to Set the Configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Global variable `variables` configuration | Bind VIN code, part list, torque qualified values | Anchor exclusive data for a single vehicle to avoid data confusion in mixed-model production |
| Trigger node settings | Trigger in real time based on station completion signal | Adapt to the rhythm of real-time updated production data per vehicle |
| Branch logic configuration | Branch based on the existence status of rework records | Cover normal release and secondary audit processes after rework |
| Parallel pulling nodes | Pull data from ERP and tightening tools simultaneously | Reduce total time spent collecting multi-source data |
| Timeout threshold setting | 600 seconds | Handle batch data processing for hundreds of configuration matches for a single vehicle |
| Knowledge base binding settings | Dynamically bind exclusive configuration documents corresponding to the VIN | Match the assembly work instruction requirements of a single vehicle |

## Three Common Misconfigurations
- The AI model dropdown list on the workflow configuration page is empty, with no available models to select. The cause is that the API key for the corresponding large model has not been configured in the FastGPT v4.17.0 backend, or model call permissions have not been enabled for the current workflow.
- The loop logic in API orchestration cannot be triggered, and the workflow cannot repeatedly execute the same node. The cause is that `nodeId` was not used correctly to chain the trigger logic of loop nodes, or the termination condition for loop triggering was not configured.
- The selected knowledge base in global variables cannot be dynamically assigned, and the knowledge base dropdown options remain fixed. The cause is that the knowledge base ID was not bound to the corresponding field in `variables`, causing the variable to fail to update dynamically with single vehicle data.

## How to Verify Correct Configuration
- Enter a test VIN code to trigger the workflow, and check whether the global variable automatically loads the corresponding part list and torque threshold.
- Simulate a station completion signal to trigger the workflow, and confirm that the multi-source data pulling node returns valid data synchronously.
- Trigger simulated data for the rework scenario, and confirm that the workflow automatically jumps to the secondary audit branch.
- Call the corresponding API interface of FastGPT v4.17.0, and check whether the workflow creation request returns a valid `nodeId` and configuration information.
