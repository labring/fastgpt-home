# Inspection and Process Record Audit for Complete Vehicle Final Assembly: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Business data for complete vehicle final assembly uses VIN as the main vehicle thread, covering the entire production process of passenger car, commercial vehicle, and new energy vehicle complete vehicle manufacturers. Daily documents include production orders, VIN lists, assembly work instructions, tightening data, off-line inspection reports, repair records, and consistency and release documents. Data sources include ERP/MES systems, VIN and configuration systems, supplier batch systems, tightening tools, EOL inspection lines, and quality traceability systems. Data update frequency is per vehicle, real-time, and per shift, with the core feature being mixed-line production with parallel multi-vehicle configurations.

## What Constraints These Characteristics Impose on Knowledge Base Retrieval and Recall
The single-vehicle thread centered on VIN requires retrieval to precisely match the configuration and inspection requirements of a specific vehicle, to avoid cross-vehicle mismatches during mixed-line production. Real-time updated tightening data and repair records require retrieval to support real-time data source synchronization, ensuring the latest inspection results are returned. The coexistence of multiple document types requires retrieval to distinguish matching logic between structured fields (such as VIN, torque value) and unstructured text (such as work instructions). The high-complexity mixed-line production beat requires retrieval response speed to adapt to station operation rhythms, avoiding disruption to the production process.

## How to Configure Settings
Configuration settings are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Filters low-match irrelevant documents, adapts to precise retrieval requirements in mixed-line production |
| `limit` | Top 10 entries | Adapts to final assembly station operation rhythm, avoids response timeout caused by loading excessive data |
| `searchMode` | Hybrid search | Matches both structured VIN fields and unstructured work instruction content, covers all types of business documents |
| `usingReRank` | Enabled | Improves retrieval sorting accuracy for similar configured vehicle models, reduces mismatch risk |
| `datasetSearchUsingExtensionQuery` | Enabled | Completes omitted VIN-related information in user queries, improves retrieval recall rate |
| `collectionIds` | Configured by vehicle model/workstation group | Limits retrieval scope to documents of the corresponding production unit, avoids retrieving irrelevant data across workstations |

## Three Common Misconfigurations
- Phenomenon: Retrieval results include assembly documents for non-target vehicle models. Cause: The `collectionIds` parameter is not used to limit the knowledge base set for the corresponding vehicle model, resulting in cross-category retrieval of irrelevant data.
- Phenomenon: The answer does not display document source traceability information. Cause: The knowledge base traceability configuration is not enabled, or the traceability parameter is not bound during the generation stage, failing to meet business traceability requirements.
- Phenomenon: Retrieval results do not include real-time tightening data. Cause: Real-time data source synchronization is not configured, or the retrieval scope does not cover the real-time data set, resulting in returned outdated inspection records.

## How to Verify Correct Configuration
- Enter an inspection query bound to a specific VIN, confirm that retrieval results only include production documents associated with that VIN, with no cross-vehicle content.
- Check the bottom of the generated answer, confirm that the name and source path of the matched document are displayed, verifying that the document traceability function operates correctly.
- Simulate submitting a real-time repair record query, confirm that the results include the latest updated repair data, verifying that real-time data source synchronization is active.
- Adjust the `similarity` threshold, observe changes in the matching degree of retrieval results, confirming that the threshold configuration meets business accuracy requirements.

The configuration values listed above are common starting points, and should be evaluated against the reader's own operational samples.
