# Inspection and Process Record Audit for High-Volume Automotive Component Manufacturing: Multi-Turn Dialogue and Prompt Engineering

## What Data Looks Like for This Category
Data sources for this category include customer drawings and special characteristic lists, ERP/MES systems, measurement and inspection tool collection data, equipment process parameters, and supplier quality assurance documents. Data is collected continuously according to production batches and shifts. Daily documents include control plans, process flowcharts, work instructions, first-piece and patrol inspection records, SPC reports, PPAP materials, and 8D reports. Data fields include part number, process number, inspection value, qualified judgment threshold, batch identifier, and collection timestamp. Units include physical quantity units such as millimeters, newtons, revolutions per minute, and others.

## Constraints Imposed on Multi-Turn Dialogue and Prompt Engineering
The data in this category is scattered and mostly consists of real-time production collection content. Multi-turn dialogue systems must support association with multiple types of data sources. Prompts must clearly define the scope of documents and data to be queried. Data is updated with high frequency according to production batches and shifts. Dialogue context must be isolated by production batch to avoid cross-batch data confusion. Daily document types are diverse and have strict format specifications. Prompts must specify the field priority for matching documents, and prioritize reading the customer’s special characteristic list content. The association logic between inspection values and qualified thresholds is complex. Multi-turn dialogue must gradually break down problems: first confirm the production batch, then retrieve the corresponding inspection records. Additionally, dialogue output must comply with standardized formats due to constraints from vehicle customer quality systems, and field contents must not be adjusted arbitrarily.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind to production batch ID, reuse the same `chatId` for dialogues within the same batch | Data in this category is isolated by batch to avoid cross-batch data confusion |
| Maximum context length | 8000–12000 characters | Required to accommodate document content such as control plans, patrol inspection records, and SPC reports for a single batch |
| `variables` | Pre-set three global variables: part number, process number, batch number | Quickly locate documents and collected data corresponding to the production batch |
| Single document recall limit | Top 6 entries | The number of documents associated with a single batch in this category is limited, avoiding redundant content interfering with dialogue |
| Dialogue timeout threshold | 600 seconds | Data retrieval for this category requires cross-system access to ERP, MES, and measurement and inspection tools, so sufficient time is reserved for aggregation |
| `messages` | Retain the last 3 rounds of interaction history, truncate earlier content | Production scenario problems focus on the current batch, so overly long historical context is unnecessary |

Note: This configuration applies to FastGPT v4.17.0

## Three Common Configuration Mistakes
- Phenomenon: Dialogue calls display 1 group, but single-turn dialogue response time far exceeds the group-labeled duration. Logs show multi-source data aggregation timeout. Cause: No reasonable dialogue timeout threshold is configured, or the threshold is set lower than the actual time required to retrieve data across ERP, MES, and measurement and inspection tool systems.
- Phenomenon: An error occurs during testing after adding a database connection plugin, and production-related data cannot be read. Cause: No database access permission and instance variables are pre-set in `variables`, or the database configuration of the current production environment is not matched.
- Phenomenon: Dialogues cannot accurately recall PPAP materials or 8D reports corresponding to the production batch. Cause: `chatId` is not bound according to production batch, and the context does not isolate documents and data from different batches, resulting in chaotic recalled content.

## How to Verify Correct Configuration
- Initiate a test dialogue related to a single batch, verify that control plans and patrol inspection records corresponding to the batch can be accurately recalled.
- View the dialogue context, confirm that the same `chatId` is reused for dialogues of the same batch, and `chatId`s for dialogues of different batches are distinct.
- Trigger a database connection test, verify that production data in ERP or MES can be read normally.
- Check the dialogue output format, confirm that it complies with preset standardized field requirements, and data content is not adjusted arbitrarily.

Note: The configuration values provided are common starting points, and should be evaluated against the reader's own samples.
