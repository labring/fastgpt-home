# Inspection and Process Record Audit for Baking and Convenience Foods: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
This category's data comes from various business documents of bakeries, pastry shops, cookie, instant noodle, and frozen pastry factories, including formulas and feeding lists, production records, baking or steaming curves, metal detection records, cleaning and disinfection records, and factory inspection reports. Data sources cover raw and auxiliary material qualification certificates, ERP/MES systems, weighing systems, production equipment, laboratories, and food traceability ledgers. Updates are performed per production batch, shift, or daily. Document fields include allergen material identifiers, production parameter ranges, test result values, packaging dates, shelf life, and more.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
The multi-batch rapid line change and frequently updated business data of this category impose multiple constraints on multi-turn dialogue and prompt engineering configurations. Documents updated per batch or shift must bind the context of the corresponding production cycle via `chatId` to avoid mixing cross-batch data. The high-frequency demand for allergen materials and cleaning switching requires prompts to limit the retrieval scope to the feeding and cleaning records of the current production task. For multi-turn verification scenarios of production parameters, historical dialogue parameter inputs and retrieval results must be retained to reduce repeated queries. For multi-dimensional inspection and verification workflows, multi-turn dialogue must be used to gradually guide the input of inspection items and narrow the data retrieval scope step by step.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | First 20 dialogue history entries | This category’s business data is updated per batch; 20 dialogue entries can cover the complete inspection process for a single batch, avoiding context overflow |
| `variables` Bound Fields | Batch number, production shift | Quickly locate documents such as formulas and production records for the corresponding batch, narrowing the retrieval scope |
| Question Optimization Toggle | Enabled | This category’s production parameters have multi-dimensional descriptions; optimization can improve retrieval matching accuracy |
| `messages` Role Restriction | Only retain user and system role dialogues | Filter irrelevant intermediate step records, focusing on core dialogue content for inspection and audit |
| Single Retrieval Limit | Top 8 matching documents | This category has a limited number of documents per batch; 8 entries can cover all relevant records for the current batch, avoiding information overload |

## Three common mistakes
- Issue: Production record images in dialogue history fail to load without login. Cause: The session context of the current production batch is not bound via `chatId`, making it impossible to match the storage path of the corresponding image.
- Issue: Dialogue logs are not recorded when the workflow calls other configured applications or plugins. Cause: The `messages` parameter is not passed during the call, or the session log storage switch of the application is not enabled, resulting in the context not being saved.
- Issue: The form input node’s dialog box is hidden when triggered in a single workflow, but still displays when nested in another workflow. Cause: The pop-up trigger logic of the child node is not synchronously overwritten in the nested workflow configuration, causing the parent workflow to not take over the child node’s display settings.

## How to confirm the configuration is correct
This verification process is based on FastGPT v4.17.0.
- Initiate an inspection dialogue for a single production batch, checking whether the `variables` field for the corresponding batch is bound in the dialogue history.
- Call the associated application or plugin, checking whether the `messages` content of this dialogue is saved in the session log.
- Trigger the form input node, confirming that the display status of the dialog box meets expectations in the nested workflow.
- When retrieving production records, confirm that the number of returned documents matches the configured single retrieval limit.

The values provided are common starting points and should be measured against the reader's own samples.
