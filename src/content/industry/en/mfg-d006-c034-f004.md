# Inspection and Process Record Audit for Baking and Convenience Food: Workflow Orchestration

## Data Profile for This Category
Baking and convenience food factory daily data includes formulas and feeding lists, production records, baking or steaming curves, metal detection records, cleaning and disinfection records, and factory inspection documents. Data sources include raw and auxiliary material qualification certificates, ERP/MES systems, weighing systems, ovens or frying lines, laboratory equipment, and food traceability ledgers.
Data is updated by production batch, shift, or daily. Single-batch data includes fields such as feeding amount, baking temperature, production batch number, and allergen labeling items. Common field units are kilograms, degrees Celsius, batch numbers, and similar units.

## Constraints Imposed on Workflow Orchestration
This category has a large number of formulas and frequent line changes. Workflows must support quick switching of business variables and associated documents. Multi-source data collection requires workflows to pull different types of business data across systems. Updates by batch and shift require workflows to support real-time or batch execution based on trigger events.
High-risk requirements for allergen and foreign matter control require embedding multi-layer verification links in workflows. This ensures the accuracy of each step of data. Ready-to-eat product attributes require workflow verification results to be directly used for production decisions. No additional manual review is needed.

## Configuration Settings
This configuration is based on FastGPT v4.17.0, and adapts to the inspection and process record audit scenario for baking and convenience food categories.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Bind three types of variables: production batch, feeding amount, and allergen labeling. Values are calibrated based on each batch's production data | Data for this category is generated independently per batch, and must associate corresponding business documents by batch |
| `nodeId` | Assign fixed `nodeId` to three core nodes: cleaning and disinfection, metal detection, and factory inspection | Frequent line changes require quick location and adjustment of execution logic for corresponding nodes |
| Knowledge base reference verification rule | Verify the matching degree between referenced content and current batch data, set thresholds based on actual measurements | Ensure referenced content such as formulas and production records matches actual data for the current batch |
| Failure retry strategy | Retry 3 times, with a 10-second interval | Data pulling may temporarily fail due to system latency; retries can reduce the probability of trigger failures |
| Multi-variable call configuration | Enable multi-`variables` binding support, allowing simultaneous mapping of multiple business fields | Single-batch data for this category includes multiple types of business fields, requiring complete association and reference |
| Trigger condition configuration | Trigger based on production batch completion events | Data is updated by batch; triggering by batch ensures workflows process the latest data |

## Three Common Configuration Mistakes
- Phenomenon: Global variable assignment is invalid when calling an API, and returned fields are empty. Cause: `variables` are not explicitly bound to the production batch number, resulting in parameters not being associated with business data for the corresponding batch.
- Phenomenon: The large language model does not return abnormal content when verifying knowledge base references. Cause: The workflow only terminates the process after verification failure, without configuring rules to output reference exception items.
- Phenomenon: Multi-variable reference only shows a single option, and multiple business fields cannot be bound. Cause: The multi-`variables` binding function is not enabled, and only a single dropdown variable mapping is configured.

## How to Verify a Correct Configuration
- Trigger a test batch workflow, and check whether formula and feeding list data for the corresponding batch is pulled.
- Manually enter knowledge base reference content that does not match the current batch data, and confirm whether the workflow returns an exception item prompt.
- Call the API with multiple `variables` parameters, and confirm that the returned result includes all bound business fields.
- Simulate a system latency scenario, and confirm that the workflow triggers the retry mechanism and executes normally after the system recovers.

The values provided are common starting points and should be measured against the reader's own samples.
