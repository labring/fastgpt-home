# Heat Treatment Inspection and Process Record Audit: Tool Calling and Plugins

## What data looks like for this category
Heat treatment scenario data originates from material grade archives, customer technical specifications, temperature control instruments, furnace temperature uniformity testing equipment, hardness testers, metallographic analyzers, and manufacturing execution systems. Data is updated per furnace load and per batch. Core documents include heat treatment process cards, furnace loading diagrams, furnace temperature curves, hardness and metallographic reports, equipment inspection forms, and exception handling forms. Fields include furnace number, part batch number, heating temperature (unit: degrees Celsius), holding time, cooling rate, hardness values (unit: HRC or HV), and more. Some documents use chart formats, so plugins are required to support multi-type data parsing.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
The update rhythm of per-furnace-load and per-batch data requires tool calls to be triggered by batch, to avoid uncategorized bulk calls that cause data confusion. Multiple heterogeneous data sources and mixed-format documents require plugins to support structured parameter verification and unstructured chart parsing. Fixed field units require tool calls to perform format and unit verification on indicators such as temperature and hardness, to prevent invalid data from being introduced. Severe potential consequences of errors require plugins to output verification results after being called, to facilitate subsequent exception handling.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Automatically match dedicated plugins adapted for heat treatment inspection, reducing manual configuration costs |
| `functionCall` | `enabled` | Support precise calling of structured process parameters, adapting to field verification requirements |
| Maximum documents per single call | `1-3 documents per call` | Avoid request timeouts caused by single-batch data overload |
| Timeout period | `240 seconds` | Adapt to the time required to pull and parse furnace temperature curves and hardness reports |
| Trigger timing | Trigger by furnace load batch | Match the update frequency of heat treatment per furnace load and per batch |
| Parameter verification switch | Enabled | Verify the unit and format compliance of indicators such as temperature and hardness |

## Three common configuration errors
- Phenomenon: An unauthorized error is returned when calling a third-party chatbot plugin. Cause: The correct bot key and session permissions are not bound in the FastGPT plugin configuration.
- Phenomenon: Abnormal results occur when calling the verification tool for long documents such as complete furnace temperature curves. Cause: Reasonable segmentation rules are not configured for long documents, leading to context overflow and verification deviation.
- Phenomenon: Scheduled inspection tools are not displayed in the tool list. Cause: The plugin permission switch for scheduled tasks is not enabled, or the triggered time cycle rule is not configured.

## How to confirm the configuration is complete
- Initiate a single furnace load inspection request, and verify whether the plugin correctly pulls the process card and furnace temperature curve data corresponding to the target furnace number.
- After triggering tool calling, check whether the returned result includes the verification fields for hardness and metallographic reports, and that the units meet business requirements.
- Simulate an abnormal scenario where the temperature exceeds the process range, and confirm whether the plugin triggers an exception handling prompt.
- Check the FastGPT v4.17.0 plugin call log to confirm that the timeout period and number of calls match the configured values.

The values provided here are common starting points and should be evaluated against the reader's own samples.
