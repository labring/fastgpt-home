# Inspection and Process Record Audit for Production Planning and Shop Scheduling: Workflow Orchestration

## What the data for this category looks like
Data sources include ERP orders and inventory, BOM and process routes, equipment capacity, staff shifts, work in process, and supplier deliveries. Update frequencies are daily, weekly, or when orders or exceptions occur.
Daily processed documents include sales orders, master production schedules, material requirements plans, weekly and daily scheduling tables, work orders, material shortage lists, and delivery change notices.
Core fields include order number, process ID, capacity margin, and material available quantity. Common units are pieces, hours, and days.

## What constraints these characteristics impose on the workflow orchestration link
Dispersed data sources and inconsistent update frequencies require workflows to support scheduled pulling or event-triggered real-time data synchronization.
Structural differences across multiple types of business documents require workflows to have flexible field mapping capabilities.
Complex resource constraint calculations involved in scheduling require workflows to reserve sufficient execution duration.
Rearrangement requirements in exception scenarios require workflows to be configured with independent exception branch processes.
Cross-department collaboration requires passing `variables` type global business parameters to avoid data gaps between nodes.

## Configuration Recommendations
| Configuration Item | Recommended Practice | Rationale |
| --- | --- | --- |
| `variables` | Bind the core business field set of documents such as sales orders and work orders | Match the data characteristics of the category to ensure consistency of cross-node business parameters |
| Node trigger conditions | Trigger on a daily schedule or when orders or exceptions change | Adapt to data update frequencies to reduce invalid workflow execution times |
| `nodeId` | Assign unique identifiers to core nodes such as scheduling calculations and exception verification | Facilitate workflow debugging and jump positioning of exception branches |
| Timeout settings | 600 seconds | Cover the conventional time consumption requirements of complex scheduling calculations |
| Variable mapping rules | One-to-one correspondence according to business document field names, retain original unit information | Adapt to structural differences across multiple types of business documents |
| Exception branch configuration | Jump to the rearrangement process when material shortages or equipment failures occur | Address exception scenarios in the most time-consuming links of the category |

## Three Common Configuration Mistakes
- After publishing the workflow external interface, global variables cannot be passed when called by external platforms. The symptom is that business fields are empty in the interface return results. The cause is that the global variable pass-through permission was not enabled in the release configuration.
- After multi-level problem tree orchestration, text splicing does not match business documents. The symptom is that custom business fields are missing from the output content. The cause is that custom variables were not correctly bound to the `variables` parameter.
- After the AI queries capacity or material data from the database, the results are not referenced. The symptom is that the output content does not include the actual queried data. The cause is that the query results were not bound to the output variables of the workflow node.

## How to Confirm the Configuration Is Correct
- Call the published interface, pass a test order number parameter, and check whether the return result includes the corresponding business fields.
- Simulate exception scenarios such as material shortages or equipment failures, trigger the workflow, and confirm whether it jumps to the rearrangement node.
- View the workflow logs in FastGPT v4.17.0, and confirm that the parameters in `variables` have been correctly passed to each execution node.
- Run a complete scheduling calculation task, and confirm that the execution time does not exceed the set timeout period.
