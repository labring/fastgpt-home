# Inspection and Process Record Audit for Production Planning and Shop Scheduling: Tool Calling and Plugins

## What this category of data covers
This typically covers daily operations of manufacturing enterprise PMC, planning, shop scheduling, and material control departments. Data sources include ERP orders and inventory, BOM and process routes, equipment capacity, staff shifts, work-in-progress, and supplier delivery information. Daily business documents include sales orders, master production schedules, material requirement plans, weekly and daily scheduling tables, work orders, material shortage lists, and delivery change notices. Each document contains fields such as order number, process number, equipment ID, and capacity parameters. Update frequencies include daily, weekly, and dynamic updates triggered by orders or abnormal events.

## What constraints do these characteristics impose on tool calling and plugins?
Multi-source heterogeneous data sources require tool calling to support interfacing with different systems, and adapt to cross-data-source data pulling and integration. Differences in document types and fields require plugins to have multi-format parsing capabilities to handle different types of business documents. Dynamic update frequencies require tool calling to adapt to on-demand triggering logic, avoiding invalid requests when no data updates occur. The most time-consuming scheduling and rescheduling links require tool calling to cover scenarios such as resource constraints, order insertion, and exception handling. This ensures that obtained data supports accurate scheduling calculations, and avoids delivery delays, work-in-progress accumulation, or process shutdown due to missing data.

## How to configure settings
The following configurations are formulated based on the tool calling logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports automatic identification of required tools, adapting to multiple scenarios in scheduling audit including work order decomposition, resource scheduling, and exception rescheduling |
| `functionCall` | `enabled` | Enables function calling to obtain real-time ERP order, equipment capacity, and other data, supporting structured scheduling and audit logic |
| Tool call trigger timing | Triggered by orders or abnormal events | Matches the actual rhythm of data updates, avoids invalid requests caused by fixed-period calls, and adapts to dynamic business changes |
| Number of returns per single tool call | First 8 entries | Scheduling-related data volume is moderate. Too many entries will exceed context limits, while too few will fail to cover all resource constraints and order information |
| Tool call timeout threshold | 120 seconds | Pulling ERP and equipment data usually takes a short time. Setting a timeout avoids blocking subsequent scheduling calculation processes |

## Three common misconfigurations
- Phenomenon: Raw work order, material shortage list, and other data returned by tool calls appear directly in the final response. Cause: No structured filtering is applied to the content returned by `functionCall`, and no restriction is set to only output fields required for audit, resulting in exposure of redundant data.
- Phenomenon: Tool call interfaces are triggered at fixed intervals, generating a large number of invalid requests when there are no order changes or abnormalities. Cause: Configuration does not follow the actual trigger logic of data updates, incorrectly uses timed triggering, and fails to match the trigger timing of orders or abnormal events.
- Phenomenon: When calling GPT-4o, scheduling data obtained via tool calls is not properly integrated into the reasoning workflow, leading to unexpected final output. Cause: `toolChoice` is not configured as `auto`, and the trigger timing of tool calls does not match the context processing logic of GPT-4o, resulting in ineffective use of data.

## How to confirm correct configuration
- Submit a test request containing order changes or abnormal events, check whether the tool starts calling only when the trigger conditions are met.
- View tool call logs, confirm that the returned content only includes structured fields required for audit, with no redundant raw business data.
- Verify that when `toolChoice` is set to `auto`, the system can automatically identify the required tools and obtain corresponding scheduling or work order data.
- Simulate a data pull delay scenario, confirm that the system does not show blocking errors within 120 seconds, and the timeout logic takes effect normally.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
