# Inspection and Process Record Audit for Biologics and Aseptic Manufacturing: Source Citation and Traceability

## What this category of data looks like
This category of data comes from cell banks and seed lots, process analysis systems, cleanroom monitoring equipment, MES, LIMS, and equipment integrity testing tools. Daily documents include cell bank or seed lot records, culture and purification records, aseptic filling records, environmental monitoring reports, media fill simulation records, sterility test reports, and batch release materials. Data updates follow production batch cycles, real-time monitoring data, and scheduled updates per fixed monitoring plans. Document fields include batch number, operating parameters, test results, timestamps, equipment numbers, and others. Units include degrees Celsius, colony-forming units, time units, and similar metrics.

## Constraints Imposed by These Characteristics on Source Citation and Traceability
Documents in this category are mostly structured and semi-structured data tied to specific production batches, and must be strictly linked to their respective production batches. The traceability link must therefore accurately match batch numbers and data sources. The update cadence of multi-source data varies widely. Real-time monitoring data and batch records need separate adaptation to retrieval timelines, to avoid retrieving expired or irrelevant batch data. Compliance requirements for aseptic manufacturing prohibit data tampering. The traceability link must therefore verify the integrity and traceability of data sources. It also must address format standardization for cross-system data, to ensure test and process records from different sources can be uniformly linked. Additionally, audits for this category must cover full-process data. The traceability link must therefore support batch association of multiple types of documents, to avoid missing key compliance information.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context length | 8000–12000 token | Adapts to the total character count of documents related to a single production batch, to avoid truncating critical data required for compliance audits |
| `quoteMaxToken` | 500–800 token | Limits the length of a single cited content segment, to facilitate quick location of core information during audits |
| Retrieval matching threshold | 0.85–0.90 | Accurately matches associated fields such as batch numbers and equipment numbers, to avoid invalid cross-batch associations |
| `responseData` | Return only original data fields + batch number | Ensures traceability can directly link to complete original records for the corresponding production batch |
| `detail` | Enable full-field traceability | Covers all compliance fields for inspection and process records, meeting audit requirements for aseptic manufacturing |
| Single recall limit | Top 10 results | Controls the number of retrieval results, to reduce interference from redundant information during audits |
| FastGPT version | v4.17.0 | Ensures compatibility between configuration items and the current system |

## Three Common Configuration Errors
- Phenomenon: Retrieval results include historical data from non-current production batches, where the batch number does not match the batch being audited. Cause: No precise batch number matching rule is set, leading the retrieval scope to cover documents from unrelated batches.
- Phenomenon: When calling the traceability tool in a custom workflow, it is not possible to bind the original document path via variables, and only fixed links can be uploaded. Cause: The parameter rules for tool calls are not configured correctly, and variable reference permissions are not enabled.
- Phenomenon: The traceability tool returns an error stating "data format not supported". Cause: The `responseData` parameter is not configured as required, and a non-preset field combination is returned, which cannot be recognized by the audit system.

## How to Verify Proper Configuration
- Manually enter a batch number, retrieve the corresponding documents, and check whether the batch number in the returned results exactly matches the entered content.
- Call the traceability tool, and verify whether the returned cited data fields include the required original records and batch association information.
- Trigger a complete inspection audit process, and check whether any redundant or irrelevant cited data is included in the audit scope.
- Verify whether the custom workflow supports binding document paths via variables to complete the traceability tool call.
