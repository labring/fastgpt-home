# Inspection and Process Record Audit for Biologics and Aseptic Manufacturing: Document Parsing and Chunking

## What data for this industry looks like
Typical documents for this industry include cell bank or seed lot records, culture and purification records, aseptic filling records, environmental monitoring data, media fill simulation reports, aseptic test results, and batch release documents.
Data sources include cell bank and seed lot systems, process analysis platforms, clean zone monitoring equipment, MES, LIMS, and equipment integrity testing tools.
Data update cadences include per-batch production updates, real-time monitoring data updates, and updates per fixed monitoring plans.
Most documents have fixed-format fields such as batch number, culture temperature, settleable bacteria count, equipment runtime. These fields have associated units such as ℃, cfu/m³, hours.
A single batch release document typically contains multiple pages of structured content. Some real-time monitoring documents are short, high-frequency update entries.

## Constraints on document parsing and chunking from these characteristics
Fixed-format fields and batch identifiers require that chunks do not break critical parameter groups. Breaking these groups will prevent association of complete inspection and process data for the same batch during later retrieval.
Differences in document formats across multiple sources require the parsing process to adapt to different export structures. This avoids losing field alignment information.
Short, real-time updated documents require fast parsing. Delayed parsing will compromise the timeliness of process monitoring.
Batch parsing of long documents requires sufficient timeout settings. This prevents task interruptions from long parsing times.
Incorrect splitting of critical aseptic-related data in documents may lead to compliance risks in subsequent audit steps.

## Configuration settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `UPLOAD_FILE_MAX_SIZE` | 3000 MB | Accommodates large PDF documents associated with a single production batch, prevents upload interruptions |
| `PARSE_FILE_TIMEOUT_SECONDS` | 900 seconds | Covers time requirements for long document parsing and complex table extraction, supports complete parsing of batch release documents |
| `chunkSize` | 800–1200 characters | Matches the length of critical parameter paragraphs in batch records, prevents splitting of complete parameter groups containing batch numbers and test results |
| `chunkSplitter` | Custom delimiter (newline + batch number) | Adapts to fixed-format production documents, splits paragraphs by batch identifiers, prevents cross-batch content merging |
| `customPdfParse` | Enabled | Preserves table structure and field alignment in PDFs, avoids losing format information for critical test data |
| `chunkSettingMode` | Manual configuration | Adjusts parameters separately for different document types (batch records, monitoring data) to meet multi-format data requirements |

## Three common misconfigurations
- Uploading a 3 MB PDF document triggers an error | The `UPLOAD_FILE_MAX_SIZE` configuration was not adjusted. The default value is insufficient for long documents associated with a single production batch
- Chunk length remains inconsistent with expectations after setting a custom delimiter, with paragraph merging or splitting errors | The `chunkSize` parameter was not adjusted synchronously. This causes paragraphs to still be forcibly merged or split by character count even after the delimiter takes effect
- An error occurs when processing PDFs after deploying Marker, with a JSON response containing error information | The `PARSE_FILE_TIMEOUT_SECONDS` configuration was not set correctly. Long document parsing timeouts are not properly captured, or environment variables do not match the FastGPT version

## How to verify proper configuration
- For FastGPT v4.17.0, upload a single typical batch release document PDF. Check the upload progress and parsing logs to confirm no timeout or upload failure errors are triggered
- Manually extract a section of document content containing a batch number and test parameters. Review the chunking results to confirm no cross-batch paragraph merging occurs, and critical parameter groups are not split
- Access the configuration page to check the actual effective values of parameters such as `UPLOAD_FILE_MAX_SIZE` and `chunkSize`. Confirm they match the preset values
- Import a single real-time updated clean zone monitoring record. Confirm that the original fields and unit information are retained after parsing, with no format corruption

The values provided are common starting points. They should be evaluated against the user’s own samples.
