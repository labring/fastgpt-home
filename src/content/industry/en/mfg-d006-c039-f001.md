# Inspection and Process Record Audit for Electric Motor and Generator Manufacturing: HTTP Interfaces and External Systems

## What data for this category looks like
Data for this category comes from electromagnetic design databases, copper wire and insulating material batch ledgers, winding equipment, dynamic balancing machines, electrical test benches, and ERP/MES systems. Daily produced documents include winding process cards, insulation treatment records, dynamic balancing reports, withstand voltage insulation test records, and type and factory test reports. Data is updated per single motor, per product batch, or per each type change. Fields include winding turns, insulation system parameters, test voltage, temperature rise values, and more. Corresponding units include turns, millimeters, kilovolts, degrees Celsius, and others.

## What constraints these characteristics impose on HTTP Interfaces and External Systems
Scattered data sources and involvement of multiple equipment and systems require HTTP interfaces to support multi-source data access and avoid single-point dependencies. Based on update frequencies per single unit or product batch, interfaces must adapt to high-frequency request scenarios to ensure data synchronization timeliness. Document fields are numerous and linked to multi-dimensional parameters of electromagnetism, insulation, and mechanical balance. The interface request body must strictly match field formats and units to prevent data parsing errors. Errors in the inspection and audit link carry serious consequences, so interfaces must include exception capture and retry mechanisms to avoid production process disruptions from data synchronization interruptions.

## How to Configure
| Configuration Item | Recommended Practice | Rationale |
|---|---|---|
| `Authorization` | Platform-specific key with Bearer prefix | Complies with HTTP interface standard authorization formats to ensure call security |
| `variables` | Include motor batch ID and test bench number | Accurately bind inspection data for single units or product batches to avoid data confusion |
| `responseData` | Parse and map according to winding process card and test report fields | Match the exclusive document field structure and units of this category |
| Interface request timeout | 600 seconds | Adapt to the time required for electrical test benches to read complete test data, avoiding request interruptions |
| Response data validation switch | Enable required field validation | Prevent missing key audit data such as dynamic balancing and withstand voltage test results |

## Three Common Configuration Errors
- 404 status code returned by the interface: Mostly caused by the configured interface address not matching the actual deployment path of the motor test bench, or the `Authorization` authorization key format error failing verification.
- Empty fields returned by the interface: The `responseData` parsing rules are not configured according to the document field structure of this category, causing the system to fail to recognize exclusive fields such as winding turns and test voltage.
- Interface request timeout: The set timeout period is shorter than 600 seconds, which cannot adapt to the time required for the electrical test bench to read complete test data.

## How to Confirm Configuration is Complete
- Initiate a single motor inspection data synchronization request, and check whether the `responseData` returned by the interface includes exclusive fields such as winding turns and withstand voltage test results.
- Verify the validity of the `Authorization` credential: Initiate a request with an invalid key to confirm that an authorization failure prompt is returned.
- Simulate multiple consecutive batch synchronization requests to confirm that the interface does not experience frequent interruptions or data confusion.
- Check the FastGPT v4.17.0 system log to confirm that the response time of interface requests meets the preset timeout threshold.
