# Inspection and Process Record Audit for Electric Motor and Generator Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data for this category originates from motor factory winding, insulation, final assembly, and testing departments. Sources include electromagnetic design data, copper wire and insulation material batches, winding equipment, balancing machines, electrical test benches, and ERP/MES systems. Data is updated per individual unit, per batch, or with each type modification. Core documents include winding process cards, insulation treatment records, dynamic balance reports, voltage-resistant insulation test records, and type and factory inspection reports. Fields include winding turns, insulation thickness, dynamic balance deviation values, voltage-resistant grades, and others. Corresponding units include turns, millimeters, gram·centimeters, kilovolts, and more.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Data for this category is updated per individual unit, per batch, or with type modifications. Multi-turn dialogue must bind to material, equipment, and test data for the corresponding batch to avoid mixing information across batches. Core documents contain multiple specialized fields. Prompts must clearly specify matching rules for fields such as winding turns and insulation thickness, and adapt to dedicated units. Dialogue must follow the sequential logic of winding verification, insulation treatment, and test validation, and advance multi-turn interactions in line with the production process. Data sources are dispersed. Dialogue context must carry content from multiple test reports, so reasonable limits on context scope are needed to avoid redundant interference.

## How to configure settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to production batch number | Assign a unique identifier to each motor or product batch, distinguish audit dialogues for different production units, and adapt to FastGPT v4.17.0 context storage rules |
| `variables` | Bind to material ID and equipment number for the current batch | Ensure fields called during dialogue come from the current production batch, avoid mixing data across batches |
| `messages` | Limit single-round input character count to no more than 800 | Adapt to field verification requirements for professional documents, avoid processing delays caused by overly long single-round input |
| Maximum context | Retain the first 10 historical dialogue entries + 3 core test documents | Carry sequential associated information for winding, insulation, and testing, avoid redundant content interfering with current audit |
| Automatic context cleanup | Triggered upon batch completion | Automatically clear corresponding dialogue data after each batch audit is finished, avoid data contamination between batches |
| Prompt optimization | Calibrated based on actual measurements | Adapt to specialized terminology such as winding turns and insulation thickness, optimize precise matching of questions |

## Three common configuration mistakes
- Phenomenon: Material data called during dialogue does not match the current batch, and fields are empty. Cause: `variables` are not used to bind the current batch’s material ID and equipment number, causing the model to call an incorrect data source.
- Phenomenon: Single-round dialogue processing times out, and returned results are incomplete. Cause: The single-round input character count for `messages` is not limited, and overly long professional document content exceeds the model’s processing threshold.
- Phenomenon: Multi-turn dialogue cannot reuse previous audit conclusions as current prompt input. Cause: Context binding logic is not configured, and previous winding turn verification results are not synchronized to `variables`, making it impossible to pass valid context.

## How to confirm configuration is complete
- Manually input winding process card data for a specific batch, check if the dialogue correctly matches fields such as winding turns and insulation thickness, with no irrelevant data interference.
- Check if `chatId` is automatically generated with the production batch number, and if dialogues for different batches have independent context storage.
- Trigger the batch completion event, check if the context for the corresponding dialogue is automatically cleared with no residual data.
- Test multi-turn dialogue: first verify winding turns, then validate insulation treatment results, confirm that previous conclusions are automatically carried over to subsequent questions.
