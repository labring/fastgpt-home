# Inspection and Process Record Audit for Battery PACK and Energy Storage System Integration: Workflow Orchestration

## What Data Looks Like for This Category
Daily data for battery pack, energy storage cabinet, and BMS system manufacturers includes grouping rules, BOMs, welding and torque records, BMS flashing records, insulation and voltage withstand reports, EOL tests, and system configuration lists.
Data sources include cell capacity grading data, MES systems, welding equipment, torque tools, BMS software version records, and EOL test benches.
Data is generated once per pack or cabinet, and updated synchronously each time the BMS software version changes.
Data fields include cell grade, rated capacity, torque value, flashing version number, insulation and voltage withstand value, and others. Some fields have corresponding physical units, such as torque value measured in N·m.

## What Constraints Do These Characteristics Impose on Workflow Orchestration
FastGPT v4.17.0 supports binding multi-source data nodes and configuring `variables` rules to meet the integration needs of this category's data.
This category’s data sources are scattered and update frequently. Workflows must be configured with multi-source data pull nodes, and integrate information from different data sources using the field mapping rules defined in `variables`.
There are many types of daily documents, with large differences in their field structures. Workflows must be configured with separate `variables` extraction templates for each document type, to ensure accurate extraction of keyword variables.
Errors can involve system security and downtime risks. Workflows must add key field verification nodes, to perform legality checks on core data such as insulation and voltage withstand values and BMS configuration parameters. Trigger an alert if verification fails.
The processing time for a single batch of data must match the update frequency. Workflow single execution duration must be controlled within 300 seconds.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `variables` configuration | Separate templates by document type: Extract cell grade and rated capacity for grouping rules; Extract torque value (20–50 N·m) and tightening duration (5–10 seconds) for torque records; Extract version number and flashing result for BMS flashing records | Matches the field structures of daily documents for this category, enabling accurate extraction of keyword variables |
| `nodeId` binding | Bind dedicated `nodeId` for each data source type: Bind a dedicated `nodeId` for welding equipment nodes, bind a dedicated `nodeId` for MES system nodes | Ensures the workflow can accurately pull the latest data from the corresponding data source |
| Tool call trigger condition | Trigger based on key field verification results. Call the MCP tool only when the insulation and voltage withstand value ≥ 1000V and the torque value falls within the 20–50 N·m range | Avoids invalid tool calls and reduces error risks |
| Global variable transfer configuration | Pass the workflow-generated token to the MCP tool node, set the transfer scope to the current workflow instance | Resolves issues with cross-module use of global variables, adapting to tool call requirements |
| Automatic verification node configuration | Set verification rules for EOL test results and BMS configuration parameters per pack or cabinet. Trigger an alert if verification fails | Aligns with the data update frequency of this category, ensuring the legality of each batch of data |

## Three Common Misconfigurations
- Phenomenon: Extracted variable fields are empty. For example, the cell grade in grouping rules is not correctly identified, or the torque value in torque records is not extracted. Cause: `variables` extraction rules are not configured according to the field structures of category documents, and only general template matching is used.
- Phenomenon: The MCP tool node cannot obtain the global variable token from the workflow. Cause: The global variable transfer scope is not set to the current workflow instance, causing the variable to only take effect globally and cannot be transferred across modules.
- Phenomenon: The workflow does not trigger tool calls according to rules, and directly executes all preset nodes. Cause: No trigger logic for tool calls is configured, and the output results of the verification node are not bound as the trigger basis.

## How to Confirm the Configuration is Correct
- Upload the grouping rules and torque record documents for a single batch of PACKs, run the workflow, and check whether the extracted `variables` match the corresponding fields in the documents.
- Trigger the workflow to generate a global variable token, check whether the MCP tool node successfully receives the token, and confirm that the transfer configuration is effective.
- Simulate a scenario where key field verification fails, check whether the workflow triggers an alert, and confirm that the verification node configuration is effective.
- Adjust the tool call trigger condition, verify that the tool is called only when the rules are met, and confirm that the trigger logic is correct.

The values given are common starting points and should be measured against the reader's own samples.
