# Inspection and Process Record Audit for Petroleum Refining: Model Integration and Configuration

This document applies to the model integration and configuration logic for FastGPT v4.17.0.

## What Data Looks Like for This Category
Data for this category comes from DCS/APC control systems, LIMS laboratory information management systems, tank farm metering systems, crude oil evaluation databases, equipment management systems, and energy management systems. Daily documents include operating procedures, production plans, material balance sheets, distillate outlet quality reports, interlock ledgers, shift handover records, change management documents, and similar materials.
Data update frequencies fall into three categories: real-time, per shift, and daily. Different document types correspond to different update cycles. Fields include process parameters, material components, equipment status, quality indicators, and others. Units include temperature, pressure, flow rate, component proportion, and others.

## What Constraints Do These Characteristics Impose on Model Integration and Configuration
Multi-source heterogeneous data sources require integration configurations to adapt to the interface specifications of different systems. Real-time data requires support for low-latency calls to match response requirements for process fluctuations.
Structural differences across multiple document types require configurations to adapt to parsing rules for different fields, covering formats such as step-by-step operating procedure text and quantitative quality report indicators.
The business characteristics of crude oil property fluctuations and multi-unit coupling require sufficient context length to carry cross-unit associated data.
Data sources with different update frequencies require configuration of triggers adapted to real-time or batch data, to avoid data overload or lag that affects the accuracy of model calls.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Adapts to cross-link associated data for multi-unit coupling in petroleum refining, and carries long document content such as shift handover records and material balances |
| `maxTokens` | 4000–6000 token | Meets the generation and understanding needs of quantitative analysis text such as distillate outlet quality reports and interlock ledgers, and avoids truncation of key process parameters |
| `quoteMaxToken` | 1500–2000 token | Limits the length of knowledge base recall content, and adapts to structured data fragments from crude oil evaluation and equipment management systems |
| Workflow/API tool selection | auto | Supports automatic tool selection based on inspection and audit tasks, and adapts to multi-source data call requirements |
| `temperature` | 0.1–0.3 | Reduces randomness in process audit scenarios, and ensures consistency between inspection results and operating procedures |

## Three Common Misconfigurations
- Symptom: The model response does not reference imported Chinese-English bilingual knowledge base content. The interface shows successful knowledge base association, but the retrieval result is empty. Cause: `quoteMaxToken` is not configured to adapt to the length of Chinese-English mixed knowledge base fragments, causing recalled content to be truncated and unreadable by the model.
- Symptom: Non-streaming call errors occur when calling the Qwen3 model, and the agent node executes abnormally. Cause: The streaming support parameter of the model interface is not confirmed, and `toolChoice` is not configured to a mode adapted to agent streaming calls.
- Symptom: The rerank model does not take effect as expected. The sorted process data returned by retrieval does not follow the priority of quality indicators. Cause: The call path of the rerank model is not correctly bound in the retrieval configuration, causing the reranking link to not be triggered.

## How to Confirm Configuration Is Complete
- Submit a test call prompt containing process parameters, check whether the preset knowledge base content is included in the returned results, and confirm that the configured parameters adapt to the current knowledge base fragment length.
- Submit an audit request related to real-time DCS data, check whether the model call delay meets business response requirements, and confirm that the context configuration adapts to the carrying needs of multi-source data.
- Trigger a multi-tool call test for the agent node, check whether the model can automatically select appropriate tools to complete inspection and audit tasks, and confirm that the tool call configuration is correct.
- View the model call log, confirm that the interface address and token configuration are correct, and there are no interface call errors.

The values provided are common starting points and should be measured against the reader's own samples.
