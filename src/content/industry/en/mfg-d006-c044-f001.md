# Pulp and Paper Inspection and Process Record Audit: HTTP Interfaces and External Systems

## What data for this category looks like
Pulp and paper scenario inspection and process record data comes from wood pulp and waste paper batch ledgers, DCS/QCS control systems, on-paper machine measurement equipment, laboratory testing systems, energy and water treatment systems. Data is updated in three ways: real-time sampling, shift summary, and archiving after each roll of production completes. Common documents include pulp preparation sheets, beating records, paper machine operation records, online quality curves, laboratory reports, sheet break and product change records. Online quality curves include multiple sets of time-series sampling parameters. Sheet break and product change records link production batches and downtime durations. The field structures of all document types differ significantly.

## What constraints do these characteristics impose on HTTP Interfaces and External Systems
Multi-source, heterogeneous data sources require interfaces to support connections to different external systems. Use the `Authorization` configuration to set identity verification rules. This prevents unauthorized system access. Real-time sampled online data requires interfaces to support short-cycle requests. Response latency must match production speeds. Otherwise, pulp preparation adjustments often arrive too late. Online quality curves for single-roll production contain many time-series sampling points. Interface request and response payloads must support batch data transmission. This avoids transmission failures caused by data over limits. The field structures of different documents vary greatly. Interfaces must support specifying document types via parameters. This ensures external systems can correctly parse returned content.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {custom system token}` | Adapts identity verification for multiple external systems, prevents unauthorized access |
| `variables` | Pass `{"docType": "qualityCurve", "batchNo": "P20240512"}` | Specifies the document type and production batch to obtain, matches multi-document requirements in pulp and paper scenarios |
| `responseData` | Only return `batchId, recordTime, valueList` fields | Filters redundant data, reduces interface response payloads, adapts to real-time transmission for high-speed production |
| Request timeout | 600 seconds | Covers time for batch data transmission and complex queries, prevents request interruptions from large production data volumes |
| Number of documents per single request | First 5 entries | Adapts to sampling data volume for single-roll production, avoids interface payload over limits |
| Pagination query switch | Calibrated based on actual measurements | Adapts to archive query requirements for production data of different scales |

## Three common mistakes
- Calling the interface returns Error: write EPROT. Cause: The `Authorization` parameter is not configured correctly. Identity verification fails, and the connection between the external system and FastGPT's interface is blocked.
- Non-streaming requests automatically disconnect after 180 seconds. Complex pulp preparation audit workflows cannot complete. Cause: The request timeout configuration is not adjusted. The default timeout threshold is lower than the time required for complex queries. The connection is forcibly disconnected.
- Passed document parameters are not correctly identified. The returned result is empty. Cause: The correct docType and batchNo are not specified via the `variables` parameter. The interface cannot match inspection records for the corresponding production batch.

## How to confirm the configuration is correct
- Call the configured interface with the correct `Authorization` token. Check that the returned status code is 200. This confirms identity verification is active.
- Pass the specified `variables` parameter. Check that the returned `responseData` field only contains preset production batch and quality parameters. This confirms data filtering is active.
- Initiate a single request. Wait for the result to return within 600 seconds. This confirms the timeout configuration adapts to batch data transmission requirements.
- In FastGPT v4.17.0, use the interface log page to check matching of request and response parameters. This confirms configuration items match actual calls.

The values provided are common starting points and should be measured against the reader's own samples.
