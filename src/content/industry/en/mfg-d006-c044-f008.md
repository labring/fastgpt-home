# Inspection and Process Record Auditing for Pulp and Paper: Document Parsing and Chunking

## What the data for this category looks like
Inspection and process record data for the pulp and paper sector comes from wood pulp and waste paper batches, DCS/QCS systems, on-machine measuring equipment, laboratories, energy and water treatment systems. Daily documents include stock preparation sheets, beating records, paper machine operation logs, online quality curves, laboratory reports, and sheet break and grade change records.
Data update frequencies fall into three categories: real-time, per shift, and per roll. Single-roll paper machine operation logs contain continuous timestamps and corresponding process parameters. Stock preparation sheets include fixed-format pulp ratio fields. Some documents include professional units such as grammage, moisture content, and sheet break duration.

## Constraints for Document Parsing and Chunking
Parsing logic must support text, tables, and vector curves to handle multi-source heterogeneous document formats. Chunking operations must avoid splitting professional fields and their associated units.
Low-latency parsing tasks are required for real-time online quality curves. Chunking rules must not cause data lag.
Fixed-format stock preparation sheets and beating records need retained field associations. Chunking must not split process parameters from the same batch.
Large single-roll paper machine operation log files require controlled chunking rules. Rules must avoid exceeding system processing limits, while retaining contextual connections for key events such as sheet breaks and grade changes.

## How to set configurations
All configurations below are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Matches the single-segment text length of paper machine operation logs and laboratory reports, avoids splitting professional fields and their units |
| `chunkSplitter` | Split by paragraph + table boundaries | Supports multi-source heterogeneous documents, retains complete table structures for stock preparation sheets and quality curves |
| `customPdfParse` | Enabled | Supports parsing vector-format online quality curves exported from DCS systems, extracts labeled numerical values and timestamps from curves |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Accommodates parsing durations for large single-roll paper machine operation log files, prevents timeout interruptions |
| `chunkSettingMode` | Manual mode | For fixed-field format stock preparation sheets, customizes chunk start markers and overlap length |

## Three common errors
- Importing Excel-format stock preparation sheets results in empty fields. The cause is that structured parsing for table documents via `customPdfParse` is not enabled. Default text-line splitting alone leads to field loss.
- Enabling PDF enhancement has no effect when parsing sheet break records in PPT format. The cause is that `customPdfParse` only supports PDF document formats. Parsing for PPT and DOC files requires separate configuration of general parsing rules.
- External calls cannot associate knowledge base call parameters with streaming return results for parsing. The cause is that document source identifiers and update timestamps are not retained during chunking, leading to missing chunk metadata.

## How to confirm correct configuration
- Upload a single-roll paper machine operation log PDF, check that parsed chunks retain each segment’s timestamps and corresponding parameters, with no field splitting errors.
- Upload an Excel-format stock preparation sheet, check that the parsed table is complete, with no missing fields such as pulp ratios and batch numbers.
- Set `PARSE_FILE_TIMEOUT_SECONDS` to 300 seconds, upload a monthly laboratory report larger than 100MB, confirm that the parsing task has no timeout errors.
- Import a question-answer pair knowledge base and trigger retrieval, check that returned results only match preset response text from the knowledge base, with no additional generated content.

The values provided are common starting points and should be measured against the reader's own samples.
