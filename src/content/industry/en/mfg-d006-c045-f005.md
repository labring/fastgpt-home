# Inspection and Process Record Audit for Spinning and Weaving: Tool Calling and Plugins

## What data for this category looks like
Data sources for these entities typically include raw fiber inspection reports, ERP systems, spinning and loom operation data, evenness tester test results, fabric inspection machine records, and more. Daily generated documents include cotton blending or batching lists, process setup sheets, equipment operation records, yarn inspection sheets, grey fabric inspection sheets, and defect registration ledgers. Data updates occur with each batch of raw materials, each production shift, and each roll of fabric produced. Document fields include fiber indicator parameters, spinning twist, weaving structure specifications, defect types and locations, equipment operating duration, and more. Some fields use corresponding industry standard units.

## What constraints these characteristics impose on tool calling and plugins
This category of data has high update frequency and is scattered across multiple sources. This requires tool calling to support quickly pulling the latest equipment and inspection data by production batch and shift. Different types of business documents have large format differences, so plugins must adapt to multiple data sources including CSV-format cotton blending lists, JSON-format fabric inspection machine logs, and structured ERP work orders. Plugins need built-in mapping rules for industry-specific fields and units to avoid parameter matching errors. Continuous production creates strong correlation between defect data, so tool calling must support cross-document association of inspection and production records for the same batch to avoid isolated analysis.

## Configuration Settings
This configuration guide is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically select tools suited to the business scenario to cover multi-source data calling needs |
| `functionCall` | Enabled | Support plugin calls to external data sources to obtain the latest production and inspection data |
| Tool call timeout | 120–180 seconds | Multi-source data pulling requires waiting for equipment and ERP interface responses. This range balances response speed and data integrity, calibrated based on actual testing |
| Data source matching rule | Match by batch number + production time | Data in this category uses production batches as the core association dimension to ensure called data belongs to the current audit batch |
| Industry field mapping | Enabled | Adapt to industry-specific fields and units such as twist and defect level to avoid parameter recognition errors |

## Three Common Misconfigurations
- Symptom: Inspection data returned by tool calling does not match the current production batch. Cause: The data source matching rule is not configured with batch number + production time, causing the plugin to pull historical data from other batches.
- Symptom: Direct calls to third-party model APIs respond quickly, but tool calling performance has significant delays after being configured in FastGPT. Cause: The tool call timeout period is not adjusted, or the data source matching rule is not optimized, causing additional field verification and data association processes to consume time.
- Symptom: API calls do not output the specified thought chain process. Cause: The log output configuration related to `functionCall` is not enabled correctly, or parameter settings do not match output requirements.

## How to Confirm Successful Configuration
- Manually trigger a tool call, check if the returned data source includes documents such as the current audit batch's cotton blending list and equipment operation records.
- View the tool call log to confirm that industry-specific fields such as twist and defect level names and units have been correctly mapped.
- Test call requests for different production batches to confirm that returned data only associates production and inspection information corresponding to the target batch.
- Check the API return result to confirm that it includes the intermediate processing steps of tool calling, meeting the `functionCall` configuration requirements.
