# Inspection and Process Record Audit for Spinning and Weaving: Source Citation and Traceability

## What the Data for This Category Looks Like
Data for this category primarily comes from raw fiber inspection reports, ERP systems, real-time data from spinning machines and looms, evenness testers, fabric inspection machines, and order specification documents. Daily generated documents include cotton blending lists, batching lists, process setup sheets, equipment operation records, yarn inspection sheets, grey fabric inspection sheets, and defect records. Data updates align with each batch of raw material intake, each shift’s production progress, and completion of each bolt of fabric. Document fields include fiber index parameters, process parameters, equipment operation parameters, inspection result values, defect types and locations, and more. Some fields have clear units: twist is measured in twists per meter, and strength is measured in newtons.

## How These Characteristics Impact Source Citation and Traceability
Multi-source heterogeneous data sources require unified batch identifier association across different systems during traceability, to avoid cross-data-source matching errors. The high-frequency update rhythm requires the traceability chain to cover the full cycle from raw material intake to finished product output, to prevent retrieval of expired or mismatched production data. A single document contains multiple types of fields with units. During traceability, field names and their corresponding units must be accurately matched, to avoid confusion between process parameters and inspection results. Real-time data from production and inspection equipment must be bound to production shifts and raw material batches. The traceability process must fully retain transfer node information from raw materials to finished products.

## How to Configure the System
This configuration is based on FastGPT v4.17.0.
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the average length of a single spinning or weaving document, to ensure complete citation of core inspection and process data |
| `responseData` | Includes source document ID, batch number, generation time | Corresponds to the core identification fields of this category’s data, to facilitate subsequent traceability matching |
| `detail` | Enabled | Returns the full original content of inspection sheets and process sheets, covering defect records and equipment parameter details |
| Single recall limit | Top 6 entries | Matches the number of related documents generated in a single production batch, to avoid retrieving irrelevant cross-batch data |
| Context association rule | Bound to raw material batch | Aligns with the batch-based update characteristic of this category’s data, to narrow the traceability matching scope |

## Three Common Misconfigurations
- Phenomenon: The `responseData` field is empty when calling the API, and no source citation content is returned. Cause: The return switch for the corresponding configuration item is not enabled, or the source document identification fields to be returned are not specified in the configuration.
- Phenomenon: The original text links returned during traceability cannot be accessed via the proxy path. Cause: The original document storage path of the knowledge base is not included in the proxy rules, only the API interface traffic is proxied.
- Phenomenon: After enabling the `detail` configuration, the returned citation content includes irrelevant cross-batch data. Cause: The context association rule is not set to bound to raw material batches, so production documents from other batches are retrieved.

## How to Verify Correct Configuration
- Send a test request, check whether the returned results include source document content that meets the `quoteMaxToken` length limit.
- Verify whether the `responseData` field includes core identification information such as source document ID, batch number, and generation time.
- Retrieve documents from a single production batch, confirm that the retrieved citation content only belongs to this batch, with no cross-batch data mixed in.
- Access the returned original text links, confirm that the original document content can be obtained normally.

The configuration values listed above are common starting points. Adjust them based on your own specific samples and use cases.
