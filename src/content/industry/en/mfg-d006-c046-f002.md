# Inspection and Process Record Auditing for Meat Products and Slaughter Processing: Vector Models and Indexes

## What This Category's Data Looks Like
This category's data is sourced from daily production and inspection documents of slaughterhouses, cooked meat, and frozen prepared food enterprises, including quarantine certificates, slaughter and segmentation records, ingredient marination logs, thermal processing parameter records, cold chain temperature ledgers, and microbial inspection reports. Data is updated per batch of raw materials and per shift production process, with continuous real-time generation of temperature control data. Document fields include batch number, quarantine number, temperature value, test result, and timestamp. Some documents include test attachments, with units including degrees Celsius, batch numbers, colony count units, and others.

## Constraints Imposed on the Vector Models and Indexes Workflow
This category of data has three core characteristics: strong binding to production batches, high-frequency real-time updates, and mixed multiple types of fields. Batch binding requires indexes to associate vectors with production batches to avoid mixing cross-batch inspection records. Continuous updates of high-frequency temperature control data require indexes to support incremental synchronization to reduce resource consumption from full reconstruction. For documents with mixed multiple fields, core identifiers such as quarantine numbers and batch numbers must be prioritized for vector generation to prevent non-key fields from interfering with similarity matching. For documents with attached test attachments, binary content must be filtered out, and only text fields should be extracted for vectorization. The `defaultToken` parameter must be set to adapt to the minimum vectorization length of a single field, ensuring complete vectors for core identifiers.

## Three Common Misconfigurations
- When a single batch quarantine certificate is uploaded, the interface displays 8 chunks, then refreshes to show 13 chunks with duplicate entries. The cause is that batch-associated documents in this category have duplicate batch number fields, and chunking does not use batch numbers as a separation identifier, leading to the same content being split and indexed multiple times.
- After an upgrade from an older version, previously searchable cold chain temperature records can no longer be retrieved. The cause is that default chunking parameters changed after the upgrade, and the original temperature control data chunk length is no longer compatible, leading to some text not being correctly vectorized.
- After Excel-format ingredient records are uploaded, the index preview content does not match the actual table fields. The cause is that header recognition configuration for Excel tables was not enabled, leading to content mixing headers and data rows being uniformly vectorized, resulting in field misalignment.

## How to Verify Correct Configuration
- A single typical batch quarantine certificate is uploaded, and the chunk preview interface is reviewed to confirm that core batch numbers and quarantine numbers are not split across chunks.
- A bulk upload of 3 to 5 documents from the same batch is performed, and the number of entries in the index list is checked to match the actual number of uploaded documents, with no duplicate entries.
- Following a version upgrade, one continuous temperature control record is re-uploaded, and the search function is verified to correctly recall the corresponding content.
- Excel-format ingredient records are uploaded, and the index preview is compared with the field order of the original table to confirm that the association between headers and data rows is correct.
