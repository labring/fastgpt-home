# Inspection and Process Record Audit for Meat Products and Slaughter Processing: Workflow Orchestration

## Data characteristics of this category
Data for this category originates from animal quarantine records, supplier batches, production traceability, temperature collection, metal detection, and laboratory testing.
Daily documentation includes quarantine certificates, slaughter and cutting logs, ingredient marinating records, thermal processing logs, cold chain temperature records, and microbial test reports.
Data updates follow a per-batch, per-shift cycle. Continuous temperature control links receive real-time updated collection values.
Data fields include batch number, quarantine identifier, temperature value, test result, and more. Corresponding units are batch number, no unit, degrees Celsius, colony count units, and others.

## Constraints for workflow orchestration
The strong batch binding requirement, high-frequency update nature, and high-risk consequences of data for this category create multiple constraints for workflow orchestration.
First, each batch of production data must be accurately linked to corresponding quarantine certificates. Workflows must store core identifiers such as batch numbers and quarantine IDs using global variables to prevent cross-batch mismatches.
Second, real-time updates for continuous temperature control require workflow trigger frequency to match production rhythms, with no overly long intervals.
Third, compliance checks for separate raw and cooked processing, sterilization temperature, and similar requirements require frequent Boolean judgments. Dedicated judgment nodes must be configured in the workflow.
Fourth, most data storage uses replica set architectures. Workflows must handle connection interruptions caused by primary node failover to ensure stable data synchronization.

## Configuration settings
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Node | Trigger on batch completion events, interval no more than 300 seconds | Matches the per-batch, per-shift production update rhythm of this category to ensure timely data synchronization |
| `variables` | Store batch numbers, quarantine IDs, cold chain temperature thresholds | Enable accurate binding of production data and quarantine certificates, prevent cross-batch mismatches |
| Tool Call Module | Hide tool output results | Only display final audit results, no need to expose intermediate details of tool calls |
| Judgment Node | Perform switch-based judgment on Boolean-type status in `variables` | Verify core compliance items such as separate raw and cooked processing zones, sterilization temperature compliance |
| MongoDB Change Stream | Enable automatic reconnection configuration, limit retry times to no more than 2 | Address primary node failover issues in replica sets, avoid data synchronization interruptions |
| Node ID Binding | Bind `nodeId` as the unique identifier of the inspection record query node | Ensure uniqueness of tool calls and data reads in the workflow |

## Three common configuration errors
- Symptom: Workflow nodes cannot retrieve specified inspection records, logs show batch fields are empty | Cause: Global variables for batch numbers are not pre-configured in `variables`, or variable assignments are not linked to corresponding production events
- Symptom: Tool call module output is forcibly returned, occupying workflow context space | Cause: The tool output display switch is not turned off, or the hidden output option is not selected during configuration
- Symptom: After MongoDB replica set primary node failover, change stream disconnects and cannot automatically recover | Cause: Automatic reconnection configuration is not enabled, or retry times are set too low

## How to verify correct configuration
- Manually trigger a batch completion event, check if the workflow starts as expected and retrieves inspection data for the corresponding batch
- Call the tool call module, confirm no redundant intermediate content from tool returns appears in the interface or running logs
- Simulate a MongoDB primary node failover scenario, check if the change stream automatically reconnects and resumes data synchronization
- Configure a Boolean-type global variable, trigger compliance checks via the judgment node, confirm node status switches as expected

The values listed here are common starting points, and should be evaluated against the specific samples used in the target environment.
