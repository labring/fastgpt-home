# Inspection and Process Record Audit for Meat Products and Slaughter Processing: Document Parsing and Chunking

## What the data for this category looks like
The main entities in this category are slaughterhouses, cooked meat and frozen prepared food manufacturers. Daily generated documents include quarantine certificates, slaughter and cutting records, ingredient marinating records, thermal processing records, cold chain temperature records, and microbial test records. Data sources cover animal quarantine information, supplier batches, production traceability systems, temperature collection equipment, metal detection equipment, and laboratory test results. Update frequency follows production batches and shifts. Continuous temperature control records are updated in real time. Document fields include batch identifiers, temperature values, test indicators, compliance status, and more. Corresponding units include degrees Celsius, colony-forming units, batch numbers, and more.

## Constraints Imposed on Document Parsing and Chunking
The data characteristics of this category create multiple constraints for document parsing and chunking. First, mixed documents from multiple sources — such as scanned quarantine certificates and spreadsheet temperature logs — require parsing tools to support different formats. This prevents table field loss or text garbling. Second, high-frequency updates by batch and shift require chunking to retain batch-related context. Merging cross-batch records prevents accurate matching of raw materials and test information during audits. Third, quarantine certificates and temperature control records related to biological risks must be split separately. This allows quick location of compliance-related content during audits, and prevents confusion with production operation records. In addition, long continuous temperature control records require careful chunk sizing. Too-small chunks split individual temperature records. Too-large chunks introduce redundant context.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Documents in this category include short fields such as batch numbers and temperature values. An overly large chunk size mixes irrelevant batch information. An overly small size damages the contextual integrity of test records |
| `chunkSplitter` | Paragraphs + custom delimiters | Documents in this category use fixed-format records. For example, cold chain temperature logs have one record per line. Combining custom delimiters such as "Batch Number:" and "Test Result:" enables accurate splitting |
| `customPdfParse` | Enabled | Most quarantine certificates and test reports in this category are PDFs with tables. Enabling this option preserves table structure, and avoids chaotic parsed fields |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Single-batch complete production record PDFs may include multiple pages of temperature logs. Parsing takes a long time. A timeout causes parsing failure |
| `chunkSettingMode` | Manual configuration | Documents in this category have large format differences, such as paper scans and spreadsheet formats. Manual configuration adapts to different document types |

## Three Common Configuration Mistakes
- Symptom: After uploading a cold chain temperature record PDF, the batch number field is empty in the parsed result. Cause: `customPdfParse` is not enabled. The default PDF parser does not retain the batch number column in tables, leading to loss of core fields.
- Symptom: A timeout error returns when calling the document parsing API. Cause: The value set for `PARSE_FILE_TIMEOUT_SECONDS` is lower than actual parsing time. For example, parsing a single batch of multi-page temperature logs takes longer than the default duration, causing parsing to interrupt.
- Symptom: Chunking results include cross-batch slaughter and thermal processing records. Cause: The `chunkSize` setting is too large, exceeding the character volume of a single batch of records. This merges adjacent batch records into the same chunk.

## How to Verify Configuration Correctness
- Upload a single-batch quarantine certificate PDF. Check if the parsed result includes core fields such as quarantine number and test date. The configuration is valid if no fields are missing.
- Upload a document containing multiple pages of cold chain temperature records. Check if chunking results split content by single-batch records, with no cross-batch merging.
- Simulate batch uploading 5 documents of different types: test reports, temperature logs, and slaughter records. Check if parsing time is lower than the value set for `PARSE_FILE_TIMEOUT_SECONDS`, with no timeout errors.
- Adjust `chunkSize` to 600 characters and 1200 characters. Compare chunking results. Confirm that test record context is fully retained, and no irrelevant content is included.

The values provided are common starting points and should be measured against the reader's own samples.
