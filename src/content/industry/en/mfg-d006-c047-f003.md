# Inspection and Process Record Audit for Measuring Instruments and Laboratory Management: Multi-turn Dialogue and Prompt Words

## What the data for this category looks like
This category of data comes from enterprise metrology rooms, metrology management systems of CNAS-accredited laboratories, external calibration institution certificates, Laboratory Information Management System (LIMS) platforms, and environmental monitoring equipment. Daily documents include measuring tool ledgers, calibration plans, calibration certificates, interim verification records, original test records, reference material ledgers, and deviation disposal documents. Fields include instrument number, calibration date, measurement uncertainty, validity period, and others. Some fields use dedicated units: μm for uncertainty, days for calibration cycle. Data updates are triggered by calibration cycles, single test results, or abnormal events, with no fixed batch update rhythm.

## Constraints Imposed by These Characteristics on the Multi-turn Dialogue and Prompt Words Link
Data sources are scattered and formats vary. Multi-turn dialogue must gradually guide users to clarify document types, and avoid confusing field rules for calibration certificates and original test records. Fields have dedicated units, so prompt words must strictly match standard terminology in the metrology industry. Otherwise, audit results will deviate. Updates have no fixed rhythm, so multi-turn dialogue must support real-time pulling of the latest ledgers and calibration data, and cannot rely on static knowledge base caches. Traceability chains involve multi-link associations. Multi-turn interaction must gradually sort out the relationship between misaligned instruments and corresponding test batches, and gradually supplement context information during dialogue.

## Three Common Misconfigurations
- An error occurs when calling the document parsing tool after enabling file upload in a workflow, with a prompt indicating invalid file path. The cause is that locally deployed storage mounting rules are not correctly configured, making it impossible to obtain the actual storage address of uploaded files.
- Generated dialogue replies do not associate with metrology documents in the knowledge base. The cause is that retrieved business data fragments such as calibration certificates and ledgers are not correctly injected into the `messages` parameter, preventing the AI from calling corresponding business information.
- An uncaught system exception occurs in private deployment scenarios. The cause is that database connection parameters related to `variables` in the configuration file are incorrectly configured, making it impossible to pull basic ledger data for measuring instruments.

## How to Confirm Successful Configuration
- Upload a standard calibration certificate file, check whether the file is successfully stored and can be read by the document parsing tool, and return parsed text containing calibration date and uncertainty.
- Initiate a multi-turn dialogue that includes a specified measuring tool ledger ID, confirm that the AI can correctly pull associated data such as the calibration period and interim verification records of the corresponding instrument.
- Check whether the `variables` parameter is bound to standard fields of the metrology management system, ensuring that business context information is automatically included in the dialogue.
- Test a complex traceability query, such as tracing the test batches affected by a misaligned instrument, confirm that the multi-turn dialogue can gradually sort out associated original records and release status.
