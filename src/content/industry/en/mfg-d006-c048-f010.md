# Inspection and Process Record Audit for Equipment Check and Preventive Maintenance: Knowledge Base Retrieval and Recall

## What This Category of Data Looks Like
This category of data covers production asset-related content from manufacturing enterprise equipment departments and maintenance teams. Daily documents include equipment ledgers, inspection checklists, maintenance plans, work orders, fault analysis, spare parts lists, and special equipment inspection records. Data sources include EAM/CMMS systems, equipment sensor data, operator inspection records, maintenance history, spare parts inventory, and statutory inspection information. Update frequencies include shift-based, daily, weekly, monthly, and on-demand when faults occur. Document fields include equipment numbers, inspection cycles, fault codes, spare part specifications, and more. Units include units, times, days, pieces, and other standard units.

## Constraints on Knowledge Base Retrieval and Recall
Mixed multi-source data structures require retrieval to support both structured field matching and unstructured text semantic association. Diverse update frequencies need adaptation to different synchronization rhythms to avoid recalling expired data. Rich document fields require precise matching of business keywords to prevent irrelevant content from being introduced via generalized retrieval. High-risk business outcomes require recall results to have high confidence, requiring strict filtering of low-relevance data. Exclusive business scenarios require isolating production asset data from other business content to ensure focused retrieval scope.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | Equipment check data has high field precision requirements. A too-low threshold will introduce irrelevant maintenance records, while a too-high threshold will miss matching check items |
| `limit` | Top 8 entries | Maintenance teams need to quickly review multiple associated work orders and checklists. Too many entries will exceed the context window, while too few will fail to cover all fault-related data |
| `searchMode` | Hybrid retrieval | Data includes structured EAM fields and unstructured fault analysis text. Hybrid retrieval can match both keywords and semantic associations |
| `usingReRank` | Enabled | Semantic association for equipment faults is complex. Re-ranking can filter low-relevance spare parts list entries and improve result accuracy |
| `datasetSearchUsingExtensionQuery` | Enabled | Equipment check terms are mostly industry jargon. Extended queries can supplement synonyms and improve recall coverage |
| `collectionIds` | Bind dedicated equipment check knowledge base collections | Isolate production asset data from other business data to avoid recalling irrelevant product process documents |

## Three Common Misconfigurations
- Phenomenon: The answer generated by the knowledge base has no citation marks at the end of the response paragraph. Reason: The answer citation configuration item is not enabled, and the citation permission for the corresponding knowledge base collection is not linked.
- Phenomenon: Consecutive questions in the same conversation window result in off-topic follow-up answers. Reason: The recall scope of conversation context is not restricted, or the upper limit of context length for single retrieval is not set, leading to interference from historical redundant data with current retrieval.
- Phenomenon: After the content of the knowledge base imported from static pages is updated, the platform data is not synchronized. Reason: No scheduled incremental synchronization task is configured, or no event rule for triggering updates is set.

## How to Verify Proper Configuration
- Submit a query containing a specific equipment fault, and check if associated knowledge base document citation marks are displayed at the end of the response.
- Submit inspection questions for two different devices in sequence in the same conversation window, and verify that both responses focus on data related to the corresponding device.
- Modify the content of the checklist in the static page, trigger the synchronization task, and retrieve the content to confirm it has been updated to the latest version.
- Access the retrieval configuration panel in FastGPT v4.17.0, and confirm that the values of parameters such as `similarity` and `limit` match the preset configuration.

The values provided are common starting points and should be measured against the reader's own samples.
