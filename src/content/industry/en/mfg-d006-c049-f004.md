# Inspection and Process Record Audit for In-Process Quality and Finished Product Release: Workflow Orchestration

## What the data for this category looks like
Data sources for this category include MES systems, online inspection equipment, laboratory testing systems, process parameter databases, customer quality standard libraries, and historical defect libraries. Data is updated per production batch, per shift, or via continuous collection. Daily generated documents include control plans, patrol inspection records, SPC reports, finished product inspection reports, nonconforming product review forms, release forms, and monthly quality reports. Fields covered include inspection item number, measured value, judgment result, production batch number, associated equipment ID, nonconforming type, and more. Units include measurement or classification identifiers such as length, weight, and defect level.

## What constraints these characteristics impose on workflow orchestration
Data sources are scattered and involve multi-system integration. Workflows must be configured with multiple nodes to pull information from different data sources separately. Data update frequency aligns with production rhythm. Workflows must support batch-based or scheduled triggering to avoid missing unaudited production batches. Document structures vary widely with significant field differences. Variable configuration is required to adapt field mapping rules for different documents. Process errors may cause batch nonconformity or risk of releasing nonconforming products. Clear failure handling and alert mechanisms must be configured to ensure exceptions can be addressed promptly.

## How to set up the configuration
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Map corresponding data source fields by production batch number and associated equipment ID | Matches core associated fields of category data to achieve accurate association of MES and inspection equipment data |
| Trigger Mode | Triggered by production batch completion events, poll unaudited batches at 10-15 minute intervals | Adapts to update frequency per batch or shift, aligns with production tempo |
| Node Timeout | 600 seconds | Covers conventional time requirements for cross-data-source pulling and report parsing |
| Knowledge Base Association | Associate the first 5 historical defect records | Matches the data scale of the category's historical defect library to provide reference for audits |
| File Storage Quota | 1000 MB | Adapts to storage requirements for documents such as inspection reports and SPC reports |
| Failure Handling Strategy | Trigger alerts and roll back to the pending audit node | Prevents accidental release of nonconforming products, meets risk prevention and control requirements for category error consequences |
| Tool Call Output | Hide original tool call replies, only retain custom judgment results | Adapts to output specifications for quality audit scenarios, avoids redundant information interfering with auditors |
| `nodeId` | Bind to the unique identifier of the finished product release audit node | Ensures accurate calling relationships between nodes in the workflow, avoids node confusion |

## Three Common Misconfigurations
- Phenomenon: The code execution node has output, but the downstream specified reply node cannot print the result. Cause: The output of the code execution node is not bound to `variables`, so downstream nodes cannot read the corresponding data.
- Phenomenon: The workflow cannot normally pull inspection reports stored in MinIO. Cause: Environment variable configurations adapted for FastGPT v4.13.0 and above are not updated, resulting in storage permission verification failure.
- Phenomenon: After the workflow runs, the original tool call reply is displayed, and it cannot be hidden. Cause: The switch to hide tool call output is not configured, and the default output setting for tool calls is retained.

## How to Verify the Configuration is Complete
- Trigger a simulated production batch workflow, check whether MES data, inspection equipment inspection reports, and historical defect information for the corresponding batch are automatically pulled.
- View the `variables` configuration item, confirm that the output fields of upstream nodes have been correctly mapped to the input parameters of downstream nodes.
- Simulate a failed inspection scenario, check whether a failure alert is triggered and the workflow rolls back to the pending audit node.
- Confirm that the workflow running results only display custom inspection judgments and release suggestions, and no original tool call reply content appears.

The values provided are common starting points, and should be evaluated against the reader's own samples.
