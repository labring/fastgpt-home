# Inspection and Process Record Review for In-Process Quality and Finished Goods Release: Tool Calling and Plugins

## What this category’s data looks like
This category covers quality control scenarios for manufacturing enterprise IPQC, FQC, quality engineering, and laboratory roles, spanning the full end-to-end quality record workflow from in-process product patrol inspections to finished goods release. Daily processed documents include control plans, patrol inspection records, SPC reports, finished product inspection reports, nonconforming product review forms, release forms, and monthly quality reports. Data sources include MES systems, online inspection equipment, laboratory test results, process parameter libraries, customer quality standards, and historical defect libraries. Data is collected continuously per production batch and team shift. Each document contains structured fields such as inspection items, measured values, judgment results, review opinions, and corresponding units.

## Constraints for Tool Calling and Plugins
Dispersed data sources and uneven update frequencies require calling multiple plugin types to connect to different systems. Use the `toolChoice` configuration to enable automatic calling modes to adapt to dynamic needs. Fields vary widely across different document types, so plugin field mapping rules must be configured to adapt to different data source formats and prevent mapping errors. Data volume fluctuates with production batches in mass production scenarios, so limit the number of returned entries and timeout duration for single tool calls to avoid excessive resource usage. Quality control has strict timeliness requirements, so match the tool call timeout threshold to production takt times to avoid delays to release processes.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | Adapt to dynamic calling needs across multiple quality control data sources, no manual specification of individual tools required |
| Single tool call timeout duration | 600 seconds | Match production takt times and quality review timelines, avoid delaying finished goods release processes |
| Single return result limit | Top 10 entries | Limit data volume returned per batch, prevent context overload that impacts model inference |
| Plugin exception retry count | 2 times | Offset call failures caused by temporary network fluctuations or short system freezes |
| Context splicing length | 800–1200 characters | Match the core field length of a single quality document, avoid exceeding model limits |
| Workflow/API function-call configuration | Enabled only during format verification | Perform format compliance checks for batch inspection items, ensure inputs meet system requirements |

This configuration applies to FastGPT v4.17.0.

## Three Common Misconfigurations
- Phenomenon: Total tool call duration far exceeds the preset group duration, and logs show a single batch of returned content takes over 600 seconds. Cause: Parallel execution timing was not configured for multi-data source calls, leading to serial calls to each system that lengthen total duration.
- Phenomenon: A call error triggers after configuring a database connection plugin, and the interface prompts a field format mismatch. Cause: Mapping rules were not configured according to the field structure of documents in this category, and non-quality control fields were passed to the plugin, causing verification failure.
- Phenomenon: Tool call input and response fields are retained in the output results, which does not meet the display requirements for quality review documents. Cause: Detailed output configuration for tool calls was not disabled, and full call logs are retained by default.

## How to Verify Correct Configuration
- Trigger a single-batch quality data collection process, check whether plugin call logs execute according to the expected timing sequence.
- Review the tool call return results, confirm that fields match the format of control plans and inspection reports for this category.
- Simulate an abnormal scenario where a data source connection is temporarily disconnected, check whether the plugin triggers retries according to the configured rules.
- Call the API to initiate a batch review process, confirm that node execution status matches online debugging results.

The values provided are common starting points and should be measured against the reader's own samples.
