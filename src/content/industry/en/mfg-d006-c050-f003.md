# Inspection and Process Record Review for General Mechanical Equipment Assembly: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Inspection and process record data for general mechanical equipment assembly primarily comes from PLM/ERP systems, part inspection data, assembly tool collection terminals, test benches, MES systems, and customer technical agreements. Data is updated per single device or per order. It includes documents such as assembly process cards, multi-level BOMs, torque records, gap adjustment records, commissioning reports, factory inspection sheets, and packing lists. Fields cover material codes, torque values, gap parameters, coaxiality indicators, test results, and additional relevant metrics. Units include N·m, mm, μm, and other standard measurement units.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompting
Because data is updated per single device or order and includes multi-level BOMs, multi-turn dialogue must support associating historical data with orders. Prompts must clearly distinguish review scopes for different devices to avoid mixing cross-order data. Due to the wide variety of document types and large differences in field units, the dialogue flow must first guide users to clarify the current device type and corresponding document scope, preventing misuse of parameters from non-current devices. Quantified data such as torque and gap values in the assembly phase require precise matching. Multi-turn dialogue must support passing preset thresholds with exclusive parameters. Additionally, because data update frequency is high, the context window must be limited to avoid loading expired, non-current order data.

## Configuration Settings
This document applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Maximum context window | 8000–12000 tokens, calibrated via actual testing | Adapts to the content length of multi-level BOMs and multiple inspection documents, avoiding exceeding model processing limits |
| Historical message queue | Only retain the most recent 5 messages in the `messages` parameter | Focuses on the current order's assembly review workflow, eliminating contextual interference from unrelated historical orders |
| Variable passing configuration | Enable the `variables` parameter to bind the current device ID | Accurately associates exclusive data such as the corresponding order's BOM and torque thresholds |
| Session binding rule | Bind single-device sessions via `chatId` | Ensures each device's review process is independent, avoiding mixing session data |
| Response timeout setting | 600 seconds | Adapts to the time required for loading multiple documents and review calculations, preventing mid-process interruptions |
| Document association filtering | Filter associated data by order number | Matches the feature that data is updated per single device or order, only loading documents related to the currently reviewed device |

## Three Common Configuration Mistakes
- Symptom: The associated documents returned when calling the dialogue interface are unrelated to the current order, or match inspection records from other devices. Cause: The rule for filtering associated documents by order number is not configured, leading to recall of cross-order data.
- Symptom: The model confuses torque thresholds for different devices during multi-turn dialogue, outputting incorrect qualified judgment results. Cause: Exclusive parameters for the current device are not passed via the `variables` parameter, so the model uses generic default thresholds for judgments.
- Symptom: The dialogue interface call times out and returns a 504 status code. Cause: The context window size is not limited, and historical documents from multiple devices are loaded, exceeding the model's maximum processing time limit.

## How to Verify Successful Configuration
- Initiate a test dialogue, enter the BOM number of the current order, and confirm that the associated documents returned by the model only include the current order's assembly process cards and inspection records, with no data from other orders.
- Pass the `variables` parameter carrying preset torque thresholds, initiate a review dialogue for gap adjustment records, and confirm that the model uses the passed thresholds for qualifiedness judgments.
- Initiate more than 6 consecutive dialogues, and confirm that the model only retains the most recent 5 historical contexts, without loading unrelated data from historical orders.
- Input long text content containing multiple documents, and confirm that the dialogue returns results within 600 seconds, with no timeout errors.

The values listed above are common starting points and should be evaluated against the reader's own samples.
