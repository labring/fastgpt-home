# Inspection and Process Record Audit for General Mechanical Equipment Assembly: Document Parsing and Chunking

## What this category of data looks like
Data related to inspection and process record audit for general mechanical equipment assembly typically originates from PLM/ERP, part inspection data, assembly tool collection systems, test benches, MES, and customer technical agreements. Daily documents include assembly process cards, BOMs, torque records, clearance adjustment records, commissioning reports, factory inspection sheets, and packing lists. Fields include equipment model, order number, torque value, clearance parameters, coaxiality tolerance, pre-tightening torque, and others. Updates occur once per piece of equipment or order. Data structures cover both structured tables and unstructured text.

## What constraints do these characteristics impose on the "document parsing and chunking" link
These data characteristics create multiple constraints for document parsing and chunking. First, document types mix structured BOMs and factory inspection sheets with unstructured process records, so the parsing engine must support both table extraction and text splitting. Second, data is updated per piece of equipment or order. Chunking must retain contextual association for a single piece of equipment to avoid retrieval confusion caused by cross-equipment splits. Third, fields have specific units such as N·m for torque values and mm for clearance parameters. Chunking must retain the binding relationship between fields and units to prevent damage to parameter integrity during splitting. Fourth, data formats vary across sources, so parsing logic must be compatible with different file types.

## How to set the configurations
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Matches the length of single inspection records and process steps, avoiding splitting that disrupts contextual association of torque values and clearance parameters |
| `chunkSplitter` | Chunk by paragraph + heading | Retains the heading hierarchy and step logic of assembly processes, facilitating association of operation flows during subsequent retrieval |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Accommodates parsing time for multi-page BOMs and complete commissioning reports, avoiding timeout failures when parsing large files |
| `customPdfParse` | Enable table recognition mode | Adapts to structured table documents such as BOMs and factory inspection sheets, accurately extracting fields and their corresponding units |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports bundled upload of multiple documents supporting one piece of equipment, meeting import requirements for complete assembly materials |
| `chunkSettingMode` | Manual configuration | Adjusts chunking parameters for different document types, adapting to scenarios with mixed-format data sources |

## Three common errors
- Phenomenon: After uploading files in a server deployment environment, the document parsing node returns a 404 error and cannot read file content. Cause: The temporary file directory configured for local development environments does not match the temporary directory used for server deployments, so the parsing node cannot locate the uploaded file path.
- Phenomenon: After uploading and parsing PDF or DOCX files, structured fields such as torque values and clearance parameters are lost or split chaotically. Cause: The table recognition mode of `customPdfParse` is not enabled, causing fields in table-style documents to be scattered into fragmented text.
- Phenomenon: After an external system pushes files to the platform, parsing and chunking are not automatically triggered, and file content cannot be accessed via chat. Cause: The configuration item for triggering parsing via external pushes is not enabled, or the pushed file format is not supported by the current parsing engine.

## How to confirm the configuration is properly set
- Upload a PDF of the assembly process card for a single piece of equipment, check that the parsed text retains process steps and parameter units with no obvious chunking errors.
- Set `PARSE_FILE_TIMEOUT_SECONDS` to 600 seconds, then upload a DOCX file containing a multi-page BOM, confirm that the parsing process does not time out or interrupt.
- Push a test factory inspection sheet from an external system to the platform, check that parsing is automatically triggered and corresponding knowledge base chunks are generated.
- View the platform's file storage directory, confirm that uploaded files are stored according to the configured path with no path errors.

The values listed above are common starting points and should be evaluated against the reader's own samples.
