# Inspection and Process Record Audit for Metal Cutting Machining: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Data for inspection and process record audit in metal cutting machining comes from product drawings and 3D models, CAPP/CAM systems, machine tool collected data, tool management system, MES, and measuring instrument records. The data is updated per work order, individual workpiece, sampling batch, or tool change point. Daily documents include process routes, operation cards, tool lists, CNC programs, first-piece inspection records, patrol inspection forms, and measuring tool calibration records. Fields include operation number, tool model, dimensional tolerance values, measured inspection values, and machine tool operating parameters, with units mostly millimeters, revolutions per minute, and feed rate millimeters per tooth.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
Metal cutting machining data is updated per work order or tool change point and originates from dispersed sources. Multi-turn dialogue must bind `chatId` to associate the context of a single work order, avoiding mixing data across work orders. There are many document types with specialized fields, so prompts must explicitly specify the scope for retrieving specific documents such as process routes and operation cards. Inspection records must be associated per batch, and `messages` must retain the context of benchmarks and clamping plans across turns to prevent repeated confirmation. The context window duration must also be limited to avoid calling expired measuring tool calibration or tool wear records.

## How to set the configurations
These configurations are formulated based on the logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `chatId` | Bind the unique identifier of the current work order, such as an operation card number | Associate the context of a single work order to avoid mixing data across work orders, matching the characteristic that metal cutting machining data is updated per work order |
| `messages` | Retain the context of the last 3 turns of dialogue, including key information such as operation benchmarks and tool parameters | Avoid repeated confirmation of the same process parameters, adapting to the multi-turn audit requirements of inspection records |
| `variables` | Pre-set business variables such as work order number, tool model, and tolerance range | Quickly locate corresponding documents such as operation cards and tool lists, improving retrieval accuracy |
| Maximum context duration | 8 hours | Match the work order execution cycle of metal cutting machining, avoiding calling expired measuring tool calibration or tool wear records |
| Single recall limit | Top 8 entries | Documents for metal cutting machining are mostly operation-level entries, and a small number of recalls can cover the inspection and process data of the current operation |
| Question optimization | Enabled | Convert colloquial inspection questions from users into searchable professional terms, adapting to the retrieval of specialized documents such as process routes and CNC programs |

## Three common mistakes
- Phenomenon: An API call returns an unauthorized error, even if the API Key for the knowledge base dialogue application has been configured. Cause: The permission scope of the corresponding knowledge base is not bound, or the work order associated with `chatId` does not match the preset data source permissions.
- Phenomenon: The dialogue output has no streaming effect, and only returns the complete content at one time. Cause: The streaming output configuration item is not enabled, or the front-end call does not adapt to the streaming receiving logic.
- Phenomenon: After increasing the single recall limit, the large language model does not reference any recalled content. Cause: The recalled documents do not match the retrieval scope specified by the prompt, or the key parameters of the current operation are not passed in `variables`, leading to retrieval deviation.

## How to confirm the configuration is complete
- Initiate a dialogue that includes the current operation number, check whether `chatId` is bound to the correct work order identifier. The work order information associated with the context can be viewed through logs.
- Conduct multi-turn dialogue by asking 3 consecutive questions about the clamping plan of the same operation, check whether `messages` retains the key parameters of the prior dialogue.
- Adjust the single recall limit, then check whether the number of retrieval results matches the preset value, and confirm whether the large language model references the corresponding document content.
- Call the API interface, check whether the returned response includes the correct `variables` parameter values.

The values provided here are common starting points and should be measured against the reader's own samples.
