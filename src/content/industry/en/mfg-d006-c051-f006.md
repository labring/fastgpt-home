# Inspection and Process Record Audit for Metal Cutting Machining: Citation Sources and Traceability

## What This Category of Data Entails
Metal cutting machining business data covers documents including process routes, operation cards, tool lists, CNC programs, first-piece inspection records, patrol inspection forms, and measuring tool calibration records. Data sources include product drawings and 3D models, CAPP/CAM systems, machine tool collection terminals, tool management systems, MES systems, and measuring and inspection tool data. Updates trigger with each work order, each workpiece spot check, or tool change action. Single data entries include fields such as workpiece number, remaining tool life, dimensional deviation (unit: mm), CNC program line number, and measuring tool calibration validity period.

## Constraints Imposed by These Characteristics on Citation Sources and Traceability
Scattered data sources linked to multiple systems require the traceability link to accurately match work order unique identifiers and associate cross-system process, inspection, and tool data. Diverse document types have different priorities; core documents such as first-piece inspection records and CNC programs must be prioritized for recall to avoid interference from non-critical content. High data update frequency requires real-time synchronization of the latest patrol inspection, tool change, and measuring tool calibration data to ensure cited content matches current production status. Single data entries include multi-dimensional precision parameters, so full retention of fields and unit information is necessary to avoid loss of key information such as dimensional deviation and tool life due to truncation, which would affect production decisions.

## Configuration Guidelines
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | `800–1200 token` | Matches the content length of single-process or inspection documents for metal cutting machining, avoiding truncation of key precision parameters such as dimensional deviation and tool life |
| `responseData` | Enabled | Returns the unique identifier and associated information of cited documents, supporting quick location of corresponding work orders, operation cards, and other production documents during traceability |
| `detail` | Calibrated based on actual measurements | Adapts to traceability viewing requirements of different workshops, supporting expansion of full cited content by work order dimension or display of only core fields |
| Single Recall Limit | Top 6 entries | Covers core production documents such as tool lists, CNC programs, first-piece inspection records, and patrol inspection forms required for a single process, avoiding recall of redundant content |
| Context Window | 1500–2000 characters | Retains continuous process and inspection data for the current work order, avoiding associated document matching errors caused by lost context |

*Note: This configuration is compatible with FastGPT v4.17.0*

## Three Common Misconfigurations
1. Conversation responses do not list cited production document entries. This occurs because the `responseData` configuration item is not enabled, so no cited data fields are returned.
2. Conversation API calls do not return the unique identifier of cited documents. This occurs because the cited data return switch is not properly configured, making association of corresponding work orders or operation cards impossible.
3. Large language models fail to match corresponding production document content. This occurs because the `quoteMaxToken` value is too small, truncating key dimensional or process parameters in the document and preventing successful semantic matching.

## How to Confirm Proper Configuration
1. Initiate a query that includes a specific workpiece number, then check whether returned results include associated production document entries such as operation cards and first-piece inspection records.
2. Check the `responseData` field returned by the conversation API to confirm whether it includes the unique identifier and associated information of cited documents.
3. Adjust the value range of `quoteMaxToken`, then verify that long document content is fully cited without truncation.
4. Check the FastGPT deployment version identifier to confirm that the current version is v4.17.0, which is compatible with the current configuration logic.

The values provided are common starting points and should be evaluated against the reader's own samples.
