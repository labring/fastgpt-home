# Inspection and Process Record Audit for Steel Rolling and Finishing: HTTP Interfaces and External Systems

## What this category's data looks like
Data comes from slab/billet batch ledgers, furnace operation data, mill automatic control logs, online thickness and width measuring equipment, surface inspection systems, and MES systems. Systems update data per coil or per billet, and push some key parameters such as rolling temperature and thickness deviation in real time. Daily documents include rolling plans, heating schedules, rolling specifications, shape and thickness records, surface quality reports, and quality certificates. Core fields include batch number, furnace temperature, mill reduction rate, surface defect level, and coil weight. Units include degrees Celsius, millimeters, tons, and other standard industrial units.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
Data for this category is updated frequently per coil or billet, with some parameters pushed in real time. This requires HTTP interfaces to support high-frequency, small-batch requests to avoid process delays caused by data backlog. Core fields such as batch number and rolling thickness deviation must strictly match the naming conventions of the MES system, otherwise cross-system data verification cannot be completed. Multi-source equipment data requires synchronization via interfaces, which means interfaces must adapt to requests and responses in multiple data formats. Errors may lead to coil downgrading or equipment damage, so interface failure handling logic must balance low latency and data consistency to avoid data confusion caused by repeated pushes.

## How to configure the settings
The following configurations are formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {custom API key}` | Complies with general authentication specifications for industrial system interfaces to prevent unauthorized access |
| `variables` | `{"batch_id": "{{source_batch_id}}", "thickness": "{{measured_thickness}}"}` | Matches core business fields in steel rolling scenarios to enable dynamic mapping of data fields |
| `responseData` | `{"status": "success", "record_id": "{{generated_id}}"}` | Adapts to the standard response format of MES systems to facilitate result parsing by downstream systems |
| Request timeout | `10–15 seconds` | Matches the real-time requirements of industrial equipment data to avoid process blocking caused by long waits |
| Retry count | `2 times` | Balances data consistency and system load to avoid equipment or interface pressure caused by repeated requests |
| Request body format | JSON format | Adapts to data transmission requirements of multi-source industrial equipment and is compatible with the interface specifications of most MES systems |

## Three common mistakes
- The symptom is that the interface returns a 401 Unauthorized status code, with the authentication field empty. The cause is that the `Authorization` parameter is not configured correctly, the Bearer prefix is not added, or the key is entered incorrectly.
- The symptom is that the downstream MES system cannot parse the received data, and core field matching fails. The cause is that the correct business fields are not mapped via the `variables` configuration, and field names incompatible with the MES system are used.
- The symptom is that rolling process interruptions are caused by interface request timeouts. The cause is that the request timeout is set too long, exceeding the real-time requirements of industrial scenarios, or a reasonable retry mechanism is not configured, and the single request duration exceeds expectations.

## How to confirm the configuration is complete
- A test interface call is initiated, and the returned `responseData` field is checked to confirm it contains the expected success identifier and business record ID.
- Single-coil steel billet data push is simulated, and the downstream MES system is verified to have received the complete business fields mapped via `variables`.
- A request is initiated using an incorrect API key, and the interface is confirmed to return a 401 Unauthorized status code to verify that the authentication logic takes effect.
- High-frequency, small-batch requests are simulated, and the interface is checked to confirm it completes responses within 10–15 seconds with no noticeable delay.

The values provided here are common starting points and should be evaluated against local samples.
