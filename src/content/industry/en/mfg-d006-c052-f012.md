# Inspection and Process Record Review for Steel Rolling and Finishing: Deployment and Upgrade

## What the Data for This Category Looks Like
This category of data originates from slab or billet batches, reheating furnaces, mill automatic control systems, online thickness and width measuring equipment, surface inspection devices, and manufacturing execution systems (MES). Data is generated in real time per coil or individual steel piece. Daily documents include rolling plans, heating schedules, rolling specifications, shape and thickness records, surface quality reports, and quality certificates. Fields include rolling batch number, thickness/width values, furnace temperature parameters, surface defect level, and production timestamp. Most units use industrial standard units such as millimeters, degrees Celsius, and tons.

## Constraints Imposed by These Characteristics on Deployment and Upgrade
Real-time high-frequency batch data requires adapting to high-concurrency writes and low-latency queries during deployment. Sufficient database and cache resources must be reserved. Multiple types of structured and semi-structured documents require support for multimodal parsing and field extraction. Upgrades must be compatible with the data interface formats of existing MES systems. The coil-level traceability business requirement requires that data storage and indexing are organized by rolling batch dimension to avoid mixing cross-batch data. Frequent process parameter adjustments and document updates require the deployment architecture to support hot configuration updates without interrupting core review workflows.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Dedicated internal network connection string pointing to the database synchronized with the production line MES | Adapts to mixed structured and unstructured data stored by rolling batch for this category |
| `REDIS_URL` | Local cache instance with 8 GB memory and 10 concurrent connections | Supports fast queries of real-time batch data, matching the real-time update rhythm per coil |
| `STORAGE_S3_ENDPOINT` | Internal network access address connected to the production line's existing object storage service | Stores large-volume inspection data such as surface quality reports and thickness records |
| `DB_MAX_LINK` | 150–200 connections | Matches the number of rolling batches running simultaneously on the production line, preventing connection pool exhaustion |
| `FILE_TOKEN_KEY` | Encryption key consistent with the production line MES system | Ensures process documents uploaded from the production line can be properly parsed and permission-checked |

## Three Common Configuration Errors
- Phenomenon: After uploading documents such as surface quality reports, the model cannot return matching review results, and the interface shows file parsing failure. Cause: The `FILE_TOKEN_KEY` configuration was not updated synchronously during upgrade deployment. The new key does not align with the encryption rules of the production line MES system, so uploaded files cannot be read normally.
- Phenomenon: When creating a new knowledge base, options related to image indexing are not visible. Surface inspection image documents cannot be parsed. Cause: Multimodal parsing plugins were not enabled for local deployment, or the correct storage service access address was not configured to support temporary access to image files.
- Phenomenon: A specified large language model cannot be added in the model management interface, or authentication fails after the model is added. Cause: Required keys and access addresses for model access were not correctly configured during Docker deployment. The outbound ports from the production line internal network to external model services were not opened.

## How to Verify Successful Configuration
- Perform a production line process document upload test. Verify that the key in the `FILE_TOKEN_KEY` configuration matches the MES system, and ensure upload requests are received normally.
- Check the database connection pool status. Confirm that the current number of connections does not exceed the upper limit set by the `DB_MAX_LINK` configuration, and no connection timeout errors appear.
- Traverse the knowledge base configuration items. Confirm that multimodal parsing related functions are enabled, and the format of surface inspection image documents can be recognized normally.
- Test the model call flow. Confirm that the connected large language model can receive uploaded document content normally and return review-related responses.

The values provided are common starting points and should be measured against the reader's own samples.
