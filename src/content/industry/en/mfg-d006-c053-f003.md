# Inspection and Process Record Review for Steel Smelting and Continuous Casting: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Process data for steel smelting and continuous casting includes hot metal and scrap steel entry data, real-time L2 process control data, laboratory composition reports, MES system scheduling records, energy medium and equipment status data. Data is updated by heat, real-time, and shift intervals. Daily documents include heat plans, batching lists, converter smelting records, composition reports, continuous casting process records, and slab judgment sheets. Document fields include heat number, cast sequence number, end temperature, composition content, pulling speed parameters, defect type, and others. Units include degrees Celsius, milligrams per liter, meters per minute, and similar units.

## Constraints for "multi-turn dialogue and prompt engineering"
Data updated by heat, real-time, and shift intervals requires multi-turn dialogue to bind `chatId` to associate context for the corresponding heat. This avoids confusion across heat data.
Documents contain a large number of professional metallurgical fields. Prompts must clearly limit retrieval scope to exclusive smelting and continuous casting documents. This prevents introduction of irrelevant non-process data.
Single-heat data accumulates gradually as the process advances. Dialogue context token length must be limited to avoid exceeding model processing limits.
Real-time data has strict timeliness requirements. Prompts must prioritize recalling the latest L2 process control data. This ensures review results match current production status.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind the unique 16-digit identification string of the current heat | Ensure multi-turn dialogue only associates with process records of the corresponding heat, avoiding interference from cross-heat data |
| `messages` | Limit context to the first 10 rounds of dialogue plus core documents of the current heat | Prevent context from exceeding model processing capacity, while retaining key dialogue and process data |
| `variables` | Inject the current heat’s heat number, cast sequence number, and planned composition range | Enable the model to accurately match parameters for the current smelting link and narrow retrieval scope |
| Maximum context length | 8000–12000 tokens | Match full process data volume for a single heat from batching to continuous casting, avoiding truncation of critical information |
| Number of documents recalled per query | Top 6 matching documents | Balance recall accuracy and model processing time, meeting real-time requirements for steel smelting processes |
| Prompt template | Limit retrieval to exclusive steel smelting and continuous casting documents, and require source snippets to be attached to returned results | Ensure dialogue content relies only on specified business data, improving review accuracy |

## Three Common Errors
- Phenomenon: The error message "No available indexing model detected" appears after refreshing the page. Cause: The exclusive document library for steel smelting and continuous casting is not bound to the current dialogue agent, or index updates have not completed.
- Phenomenon: Dialogue return results do not include original source document snippets and associated information. Cause: Source reference display is not enabled in the configuration, or the prompt does not explicitly require returning fields and sources for the corresponding document.
- Phenomenon: Cross-heat dialogue calls return process record data for a non-current heat. Cause: The unique identifier of the current heat is not bound via `chatId`, causing the context to call document data from historical heats.

## How to Confirm Successful Configuration
- Initiate a query about the batching list of the current heat. Verify returned results include batching ratio and hot metal composition data for the corresponding heat number.
- Check dialogue history for attached source document names and snippets for each result. Confirm the source display function operates normally.
- Switch to the `chatId` of another heat to initiate a query. Verify returned data only associates with process records for the current heat.
- In the FastGPT v4.17.0 environment, wait 10 minutes before reinitiating the same query. Verify real-time updated L2 process control data is correctly recalled.
