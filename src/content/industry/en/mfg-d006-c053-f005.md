# Inspection and Process Record Audit for Iron and Steel Smelting and Continuous Casting: Tool Calling and Plugins

## What this category's data looks like
Data sources for this category include hot metal and scrap steel ledgers, L2 process control real-time data streams, laboratory test reports, manufacturing execution systems (MES), energy medium monitoring systems, and equipment status collection terminals. Data update frequencies cover three categories: per heat, real-time, and per shift. Daily generated documents include heat plans, batching lists, converter smelting records, composition reports, continuous casting process records, and slab judgment sheets. Data fields include heat unique identifiers, measured process parameter values, test result values, and equipment operating status identifiers. Units cover commonly used industrial measurement standards such as temperature, length, and mass.

## What constraints these characteristics impose on tool calling and plugins
The decentralized nature of multiple data sources requires multiple independent plugins to be configured for the tool calling workflow, each connected to different systems such as L2 process control, laboratories, and MES. The real-time and per-heat update frequencies require tool calling trigger frequencies to match the heat production cycle. They also require binding the heat unique identifier as the session context to ensure each call is associated with the full data for the corresponding heat. The business characteristic of severe error consequences requires adding parameter validity check logic to tool calls, and configuring a failure retry mechanism to avoid production process interruptions caused by single call exceptions. The fixed document structure requires that input parameters for tool calls clearly specify the document type and corresponding heat ID to ensure accurate data retrieval.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | FastGPT v4.17.0 supports the automatic tool selection function, which adapts to the dynamic calling needs of multiple data sources |
| `functionCall` | Enabled | Force tool calling to ensure real-time production data is obtained for process record audit |
| Request timeout | 30–60 seconds | Matches the collection cycle of real-time steel smelting data, avoiding production process blocking from overly long waits |
| Session binding identifier | Heat number | Associates all production data for the same heat, ensuring consistent session context for each tool call |
| Failure retry count | 2–3 times | Offsets the impact of single network fluctuations or short system freezes, ensuring data retrieval stability |
| Parameter validation rules | Calibrated according to smelting process ranges | Filters parameter values that do not meet process requirements, reducing abnormal calls |

## Three common configuration mistakes
- Phenomenon: Tool call output appears directly in the final reply and cannot be hidden. Cause: The parameter for turning off tool call result display is not configured, resulting in redundant production data being returned.
- Phenomenon: Input text "share" is altered to "split" when passed to tool calls. Cause: Automatic correction or truncation protection for input text is not enabled, leading to character errors during transmission of short text.
- Phenomenon: Multiple API calls fail to maintain the same session context. Cause: The heat number is not bound as the session identifier, causing each tool call to be recognized as an independent session and unable to associate production data for the same heat.

## How to confirm configuration is complete
- Trigger a tool call, check if the current heat's unique identifier is included in the request parameters, and confirm the session context binding is correct.
- Simulate an abnormal network request, check if the preset failure retry logic is triggered, and confirm the retry mechanism is active.
- After configuring parameter validation rules, enter a test value that exceeds the smelting process range, check if it is intercepted, and confirm the validation rules are active.
- After disabling the tool call result display configuration, trigger a call and check if the final reply does not include tool output content, and confirm the display configuration is correct.

The values provided are common starting points and should be measured against the reader's own samples.
