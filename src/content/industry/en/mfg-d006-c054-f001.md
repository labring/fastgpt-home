# Inspection and Process Record Audit for Sheet Metal Cutting and Bending: HTTP Interfaces and External Systems

## What this category of data looks like
This category of data primarily comes from CAD/CAM software, order BOM systems, sheet metal inventory management modules, laser cutting machine and bending machine device logs, and MES manufacturing execution systems. Daily generated documents include 3D part unfolding drawings, CNC cutting programs, bending process cards, nesting drawings, first-piece inspection records, and process flow cards. Fields include sheet metal thickness, bending angle, unfolding dimensions, process number, and others. Field units are mostly millimeters, angle units are degrees, and area units are square meters. Data updates are triggered by order creation, daily inventory checks, and each production changeover.

## What constraints do these characteristics impose on the "HTTP Interfaces and External Systems" link
Data sources are scattered and have varying formats. Interfaces must support receiving multi-format data, adapting to formats such as DXF exported by CAD/CAM and CSV for process cards. Update frequency fluctuates with scenarios like orders and production changeovers. Interfaces must support on-demand triggering to adapt to different update rhythms. Single-document data volume varies significantly; a single nesting drawing can contain thousands of characters. Interfaces must be configured with reasonable transmission thresholds. Fields on process flow cards must strictly match production workflows. Interface parameters must use fixed field mapping rules to avoid audit anomalies caused by missing fields.

## How to set up configurations
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {Enterprise-specific API Key}` | Follows HTTP interface authentication specifications to secure external system calls |
| `variables` | `Pre-map fields: `sheet metal thickness`, `bending angle`, `unfolding dimensions`, `nesting utilization rate` | Matches standard fields from daily documents of this category, ensuring audit logic aligns with production data |
| `responseData` | `Return audit results, abnormal field list, correction reference values` | Directly output structured results that can be synchronized to the MES system, simplifying subsequent production process adjustments |
| Request timeout setting | `30–60 seconds` | Adapts to the average transmission duration of single audit data for this category, avoiding call interruptions caused by data volume fluctuations |
| Single-document data transmission limit | `1.2–1.8 MB` | Meets transmission requirements for large-format documents such as nesting drawings and unfolding drawings, avoiding call failures caused by data exceeding limits |
| Context transmission method | `Only pass specified business data via variables` | Avoids context redundancy caused by system history splicing, matching the business scenario of independent audit per order |

## Three common mistakes
- Phenomenon: The interface call returns a `401 Unauthorized` status code. Cause: The `Authorization` parameter is not configured correctly, and enterprise-specific API key authentication is not completed.
- Phenomenon: Abnormal empty fields appear in audit results. Cause: Required fields exclusive to sheet metal cutting and bending such as `sheet metal thickness` and `bending angle` are not passed via `variables`, causing the audit logic to fail to match production data.
- Phenomenon: Context redundancy and confusion occur in the audit logic. Cause: The context transmission method is not configured according to the business scenario, relying on system history records for splicing, and specified business data is not passed via `variables`.

## How to confirm the configuration is correct
- Call the test interface, check if the returned `responseData` includes audit results, abnormal field list, and correction reference values, confirming that field mapping meets business requirements.
- Simulate an interface call for a single production changeover scenario, verifying that the `variables` parameter correctly passes bending angle, unfolding dimensions, and other data for the corresponding process.
- View the interface call log, confirming that the `Authorization` parameter is correctly carried, and no authentication failure errors appear.
- Compare actual production data with audit results, confirming that prompts for abnormal fields match actual production deviations, and adjust configuration items until they align with business logic.
