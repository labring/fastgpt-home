# Inspection and Process Record Review for Sheet Metal Cutting and Bending: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
The typical entities in this category are cabinet and chassis manufacturers, ventilation equipment manufacturers, electrical cabinet manufacturers, and non-standard equipment manufacturers. Core data comes from CAD/CAM software, order BOMs, sheet metal inventory systems, laser cutters, bending machines, and workshop MES. Daily generated documents include part unfolding drawings, CNC cutting programs, bending process cards, nesting diagrams, first-piece inspection records, and process transfer cards. Data updates are triggered by production orders, and synchronized during model changes or daily inventory counts. Document fields include bending compensation coefficients, cutting dimensions, nesting scrap rates, process transfer nodes, inspection results, and more. Units are mostly millimeters, square meters, and piece counts.

## Constraints Imposed by These Characteristics on the "Multi-turn Dialogue and Prompt Engineering" Link
The multi-variety, small-batch production model of this category, combined with scattered data sources and update frequencies that vary with production nodes, requires multi-turn dialogue to be bound to the context of the current production order to avoid mixing data across orders. There are diverse document types with specialized fields, so prompts must clearly distinguish the retrieval priorities of different documents. For example, prioritize extracting compensation coefficient rules from bending process cards. At the same time, frequently updated sheet metal inventory and process transfer data require that the dialogue context only retains valid information from the last 3 interactions to prevent redundant data from interfering with judgment. Additionally, the specialized logic of part unfolding and nesting requires embedding matching rules for industry-specific terms in prompts to ensure accurate retrieval results.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Dialogue context window | First 2000–3000 characters | Matches the total length of core documents for a single order in this category, avoiding excessive resource usage from redundant data |
| Session binding identifier | Bind order number as `chatId` | Ensures interaction contexts for the same order are not mixed, adapting to scenarios with parallel production of multiple orders |
| Historical message filtering | Only retain the last 3 interactions in `messages` | Adapts to frequently updated production data, reducing interference from invalid information on current judgments |
| Variable binding rules | Associate order BOM and sheet metal inventory in `variables` | Automatically brings in exclusive parameters for current production without repeated input |
| Single retrieval limit | Top 5 results | Matches the volume of documents for a single order in this category, avoiding result overload that impairs judgment |

## Three Common Misconfigurations
- Issue: The error "No permission to operate this conversation record" is generated when initiating a production-related dialogue. Cause: `chatId` is not correctly bound to the unique identifier of the current production order, preventing the system from matching session permissions.
- Issue: The dialogue context includes nesting diagram data from past orders, interfering with judgment of current bending processes. Cause: The number of historical interaction rounds in `messages` is not restricted, introducing redundant data across orders.
- Issue: The prompt does not distinguish retrieval rules for unfolding drawings and process cards, resulting in returned bending coefficients that do not match actual process requirements. Cause: No category-specific document priority rules are embedded in the prompt, leading to inconsistent retrieval result matching.

## How to Verify Successful Configuration
- Initiate a query that includes an order number, confirm that the dialogue context automatically brings in the BOM and sheet metal inventory information for that order.
- Review the dialogue history record, confirm that only valid content from the last 3 interactions is retained, with no old data from cross orders.
- Submit a query that includes bending compensation coefficients, confirm that the returned results prioritize rules from bending process cards.
- Attempt to switch sessions for different orders, confirm that the session binding identifier works correctly, and no permission errors occur.
