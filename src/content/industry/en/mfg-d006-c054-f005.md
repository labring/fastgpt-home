# Inspection and Process Record Audit for Sheet Metal Cutting and Bending: Tool Calling and Plugins

## Data profile for this category
Data for this category typically comes from CAD/CAM software, order BOMs, sheet metal inventory systems, laser cutting machine and bending machine device logs, and workshop MES systems. Daily produced documents include part unfolding drawings, CNC cutting programs, bending process cards, nesting diagrams, first-piece inspection records, and process transfer cards. Data update frequency adjusts based on orders, daily production, or equipment model changes. Core fields include sheet metal thickness, bending compensation coefficient, cutting size, bending angle, and workstation transfer status.

## Constraints imposed on tool calling and plugin workflows
Data for this category is scattered across multiple types of systems and devices, and updates frequently with orders and equipment model changes. This requires tool calling to support connecting to heterogeneous data sources and pulling the latest cutting programs, bending process parameters, and process records in real time. Daily documents are mostly structured drawings and process cards. Plugins must adapt to drawing metadata extraction and associated document verification logic. The multi-variety, small-batch production model requires tool configurations to be quickly adjusted for production batches, avoiding the limitations of fixed parameters for all product categories. At the same time, errors can lead to sheet material waste and assembly deviations. Tool calling must include a parameter verification step to intercept abnormal configurations early.

## How to configure settings
This page’s configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to dynamic multi-tool calling needs, automatically matches verification and recording tools for the current production batch |
| Function call timeout | `120–180 seconds` | Covers the complete workflow of drawing parsing, database queries, and process parameter verification, with a reasonable duration calibrated via actual testing |
| `functionCall` | `enabled` | Supports calling custom tools to complete dedicated business logic such as bending coefficient calculation and nesting margin verification |
| Tool call retry count | `2 times` | Avoids call failures caused by temporary device interface fluctuations, balancing process efficiency and stability |
| Maximum number of entries returned per tool call | `Top 10` | Prevents context overload from returning too many historical process records, adapting to the single-batch data volume of sheet metal scenarios |
| Knowledge base storage limit | `1000 MB` | Adapts to the document storage needs of single-batch sheet metal orders, avoiding excessive resource usage |
| Knowledge base binding rule | Bind a dedicated knowledge base per production order | Isolates process cards and cutting program data from different orders, avoiding cross-batch data confusion |

## Three common configuration mistakes
- Scenario: When calling a custom document parsing tool, passing a custom URL returns no data, and no error is displayed in the interface. Cause: The domain whitelist for allowed tool access has not been configured, or the correct document parsing trigger parameters have not been specified in the plugin.
- Scenario: After configuring a MySQL database connection, executing an SQL query returns no results. Cause: The database account has not been granted query permissions for the corresponding table, or the SQL statement uses non-standard field names unique to sheet metal scenarios, leading to syntax mismatches.
- Scenario: When sending multiple conversation requests simultaneously, subsequent requests must wait for the previous generation to complete, and interruption is not possible. Cause: Session isolation configuration has not been enabled, and tool call contexts have not been isolated by production batch, leading to request queue blocking.

## How to verify a successful configuration
- Manually trigger a tool call, check if the returned results include core data such as the bending coefficient and nesting margin for the current production order.
- Check the tool call logs to confirm that the `toolChoice` parameter automatically matches the verification tool for the corresponding scenario, with no abnormal error messages.
- Switch the knowledge base binding relationship for different production orders, verify that the tool can only access the currently bound process cards and cutting program data.
- Simulate a temporary device interface fluctuation, confirm that the tool call retry mechanism triggers normally, with no process interruptions or data loss.

The values provided here are common starting points and should be measured against the reader's own samples.
