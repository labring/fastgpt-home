# Inspection and Process Record Audit for Sheet Metal Cutting and Bending: Source Citation and Traceability

## What Data for This Category Looks Like
Data for this category originates primarily from CAD/CAM software, order BOMs, sheet metal inventory systems, laser cutters, bending machines, and workshop MES systems. Teams generate documents including development drawings, CNC cutting programs, bending process cards, nesting diagrams, first-piece records, and process transfer cards daily. Data updates trigger when orders are created, during daily production, or after each model change. Fields include bending compensation values, cutting dimensions, sheet metal thickness, process transfer numbers, and more. Common units are millimeters, square meters, and pieces.

## Constraints on Source Citation and Traceability for This Category
The multi-variety, small-batch production model results in a high proportion of data exclusive to individual orders. Citation and traceability require precise matching of production documents corresponding to the correct order to avoid mixing data across orders. Data updates occur frequently, with new process and cutting records generated each time a model is changed. Real-time association with traceability data from the latest production links is required. Document types cover multiple formats including CAD drawings, CNC programs, and process cards. Unified indexing rules are needed to distinguish different types of production data. Errors in core links such as bending compensation and nesting can lead to subsequent assembly issues. Traceability requires locking original verification records for the corresponding process.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `quoteMaxToken` | 800–1200 token | Matches the typical length of a single sheet metal process document, fully retains key traceability information such as bending compensation values and cutting dimensions |
| `responseData` | Return only knowledge base matching results | Enforce that output strictly comes from preset production documents and inspection records, avoid generating non-traceable content |
| Single Search Limit | Top 3 results | Matches the number of documents such as development drawings, process cards, and nesting diagrams associated with a single order, avoid redundant data |
| `detail` | Enable full field display | Retain core fields of original documents such as process transfer numbers and sheet metal thickness, facilitate traceability verification |
| Retrieval Timeout | 600 seconds | Avoid unresponsive situations during long-document retrieval |
| Index Update Trigger | Execute upon order completion or model change | Aligns with the update frequency of this category, ensure citations use data from the latest production links |

## Three Common Misconfigurations
- Long unresponsive periods during retrieval. Cause: Failure to adjust index trigger rules according to order update frequency, resulting in the index database containing a large amount of expired pre-model-change data, which increases retrieval matching time.
- Output content not linked to knowledge base matching results. Cause: The `responseData` configuration item is not enabled, causing the system to generate non-traceable general content instead of strictly using preset production documents and inspection records as the output basis.
- Workflow nodes cannot select knowledge base citation variables. Cause: The `detail` field display is not enabled in the knowledge base configuration, causing the system to not expose callable original document variables.

## How to Verify Successful Configuration
- Run a query for a single order's bending process in FastGPT v4.17.0, verify whether the output content includes exclusive fields such as the order's development drawing parameters and bending compensation values.
- Check the number of retrieval results, confirm that the returned quantity matches the set single search limit.
- Review the variable list in workflow nodes, confirm that callable fields for original production documents exist.
- Simulate a model change, then run a query, confirm that the retrieval results automatically associate with the latest post-model-change process data.

The values provided are common starting points and should be measured against samples relevant to the specific use case.
