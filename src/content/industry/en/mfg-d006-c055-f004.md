# Inspection and Process Record Audit for Foundry (Sand Molding, Precision Casting, Die Casting): Workflow Orchestration

## What This Category of Data Entails
This category of data originates from ERP material master data, melting furnace thermometers, spectrometers, MES heat records, mold management systems, and customer drawings. Daily documents include casting process cards, batching lists, heat records, mold histories, first-piece inspection records, material reports, and nonconforming product review forms.
Data updates occur per heat, per batch, or daily. Fields cover alloy batching parameters, melting temperature, pouring duration, defect type and location, with no additional statistical values.

## Constraints Imposed on the "Workflow Orchestration" Link
The multi-source data and update cadence per heat or batch require workflows to bind heat ID and mold ID as `variables` to enable cross-system data association.
The need to integrate multiple document and equipment data sources requires workflows to include multi-node data retrieval steps that connect to ERP, melting equipment, and mold management systems separately.
High-frequency heat data updates require trigger logic to align with actual production rhythms to prevent data lag.
Complex defect traceability requirements require workflows to include built-in parameter verification and associated query steps to ensure parameters such as batching and temperature match process requirements.

## Configuration Settings
This page applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Basis |
| --- | --- | --- |
| Trigger Node Configuration | Triggered by production equipment completion signal | Matches the data update cadence per heat |
| Global Variable Binding | Bind heat ID, mold ID, alloy grade | Associate corresponding data from ERP and mold management systems |
| Data Verification Node | Configure parameter matching intervals calibrated via actual measurements | Ensure melting temperature and pouring duration meet process requirements |
| Exception Retry Configuration | Retry 3 times, interval 120 seconds | Address temporary failures in equipment data retrieval |
| Branch Flow Rule | Branch to qualified/non-qualified processes based on inspection results | Aligns with nonconforming product review business logic |
| Global Variable Call | Retrieve heat records from `variables` | Enable cross-node data reuse |

## Three Common Misconfigurations
- Flow execution stops without subsequent steps after reaching a node, with status showing abnormal termination. The root cause is failure to bind the heat ID in `variables`, leading to failed cross-node data retrieval and inability to match subsequent verification logic.
- Calling a global variable returns a null value, and batching list data cannot be accessed. The root cause is that the global variable is not bound to the associated parameters of the corresponding heat, or the field mapping of `variables` was not correctly configured during setup.
- A third-party API request fails when the workflow starts, returning a timeout status code. The root cause is that a reasonable retry interval and number were not configured, or the timing logic between the trigger node and API call was incorrect.

## How to Verify Proper Configuration
- Trigger node test: Simulate a heat completion signal, check whether the workflow starts automatically and matches production rhythms.
- Variable binding test: Manually input heat ID and mold ID, check whether cross-node data is correctly associated.
- Exception handling test: Simulate equipment data retrieval failure, check whether retry and branch processes are triggered.
- Branch flow test: Simulate qualified and non-qualified inspection results, check whether the workflow correctly jumps to corresponding links.

The values provided here are common starting points and should be evaluated against the reader's own samples.
