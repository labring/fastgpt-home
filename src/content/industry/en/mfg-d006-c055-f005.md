# Inspection and Process Record Audit for Foundry (Sand Molding, Precision Casting, Die Casting): Tool Calling and Plugins

## What the data for this category looks like
This category covers quality and production records across the entire foundry workflow. Data sources include ERP material master data, melting furnace thermometers, spectrometers, MES heat records, mold management systems, and customer technical drawings. Daily processed documents include foundry process cards, batching lists, heat records, mold histories, first-piece inspection records, material test reports, and nonconforming product review forms.
Data updates occur per heat, per batch, or daily. Core fields include alloy composition percentage, pouring temperature (℃), heat number, mold cycle number, defect type, and others. Some fields must match technical tolerance requirements from customer drawings.

## Constraints for tool calling and plugins
The data characteristics of this category impose multiple constraints on the tool calling and plugins workflow. Heterogeneous data sources are scattered across production equipment, management systems, and business documents. Multi-plugin linkage is required to pull data. As a result, tool calling must support precise filtering by business identifiers such as heat number and mold cycle number.
Data updates happen frequently. Tool calling must adapt to real-time query requirements per heat to avoid excessive delays that reduce audit efficiency. Document fields have fixed units and technical tolerance requirements. Plugins must return results that strictly match preset field formats, otherwise automatic audit logic cannot function.
Defect tracing requires linking data across multiple systems. The volume of data returned by a single tool call must be kept within a reasonable range to avoid context overload that disrupts audit judgments. Temporary fluctuations in data sources must also be handled, with a properly configured retry mechanism.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool call timeout period | 120–180 seconds | Melting furnace data collection cycles are typically 60 seconds, covering reasonable time for data pulling and parsing |
| `toolChoice` | auto | Adapts to multi-data-source plugin calls, automatically selects the dedicated tool matching the current heat or mold cycle number |
| Historical message filtering rules | Only retain business conversation content, exclude plugin call logs | Avoids historical plugin call records interfering with context judgment for current inspection audits |
| Plugin call retry count | 2 times | Addresses common production scenarios such as temporary spectrometer disconnections and MES interface fluctuations |
| `functionCall` | Enable strict mode | Ensures plugin return result formats match preset inspection record fields to avoid parsing errors |
| Number of records returned per single plugin call | Top 3 core records | Matches the volume of key inspection data per heat, controls context load |

## Three common configuration mistakes
- Tool call results only display when re-entering the conversation, with no results shown in the current conversation interface. This occurs because the result synchronization switch for `functionCall` is not enabled, so tool return data is not pushed to the conversation interface in real time.
- A connection wait timeout status appears when calling data source interfaces. This happens because the tool call timeout period is set too short, and does not match the data pulling cycles of melting furnaces, spectrometers, and similar equipment.
- Plugin call commands in historical conversations interfere with current audit logic. This occurs because historical message filtering rules are not configured, and plugin call logs are included in the current conversation context.

## How to confirm the configuration is correct
- Confirm that FastGPT v4.17.0 is being used, initiate a query for a heat inspection audit, and check if the dialog box displays tool call return results in real time.
- View the context panel to confirm that historical plugin call logs are not included in the current conversation's context scope.
- Simulate a temporary fluctuation in a data source interface, and check if the plugin automatically retries requests according to the set retry count.
- Verify that when `toolChoice` is configured as auto, the system automatically selects the dedicated plugin matching the current heat number.

The values provided are common starting points and should be measured against the reader's own samples.
