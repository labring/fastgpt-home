# Inspection and Process Record Audit for Lithium-ion Cell Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data sources for this category cover raw material batch ledgers, production MES systems, slurry and coating testing equipment, workshop dew point monitoring devices, formation and grading cabinets, and laboratory testing systems. Daily generated documents include batching records, coating roller pressing parameter tables, winding or lamination process records, liquid injection ledgers, formation and grading data reports, OCV and safety test reports, and similar documents. Data updates occur in real time per production batch and per individual cell. Document fields include slurry solid content, coating areal density, ambient dew point, cell internal resistance, formation and grading curve parameters, and other relevant fields, linked to a unique production batch number and cell code.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering by These Characteristics
The real-time batch-based data and specialized segmented fields for this category require that multi-turn dialogue be bound to a unique `chatId` linked to the context of a single batch or single cell, to avoid cross-batch data confusion. The context window for multi-turn dialogue must be limited to the most recent records of the current production process, to prevent redundant historical data from interfering with professional judgment. Prompts must explicitly limit the retrieval scope to inspection documents for cell manufacturing links such as batching, coating, formation and grading, while filtering non-core fields unrelated to moisture, cleanliness, and batch consistency. Real-time data updates require that dialogue history be sorted by production timestamps, with recent testing records prioritized for retrieval.

## Configuration Setup
The following configurations are adapted for FastGPT v4.17.0, for the multi-turn dialogue and prompt engineering scenario of lithium-ion cell manufacturing inspection and process record audit.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to a single cell code or production batch number | Ensure dialogue context only links to inspection data for the current production batch, avoiding cross-batch data confusion |
| `messages` | Retain the most recent 8–12 dialogue context entries | Adapt to the volume of inspection data for a single batch, preventing context overload from interfering with professional judgment |
| `variables` | Pre-set three variables: "current process", "batch number", "testing type" | Quickly filter inspection records for the current link, narrowing the retrieval scope |
| Maximum context | Limit to 1500–2000 tokens | Match the single-batch data length of lithium-ion cell manufacturing inspection documents, avoiding loading irrelevant content |
| Question Optimization | Enable professional term calibration | Adapt to industry-specific terms such as slurry, areal density, formation and grading, improving retrieval accuracy |

## Three Common Misconfigurations
- Phenomenon: An additional meaningless historical record appears before the first response when calling the API to initiate a dialogue. Cause: The `messages` array was not correctly initialized in the request parameters to an empty list containing only system prompts, causing the platform to load the global historical context by default.
- Phenomenon: The question classification module incorrectly triggers a parameter adjustment flow for a cell inspection request. Cause: The prompt did not limit the classification scope to inspection and process record audit, and did not bind preset variables for the current process to complete scenario filtering.
- Phenomenon: After exceeding the preset number of multi-turn dialogue rounds, current batch coating inspection records cannot be retrieved. Cause: No context retention upper limit was configured for `messages`, and historical data from old batches overwrote the context information for the current batch.

## How to Verify Proper Configuration
- Initiate a dialogue request for single-batch inspection, check whether the `chatId` matches the current batch number, ensuring the context does not link across batches.
- Conduct multiple consecutive inspection-related questions, observe whether the number of retained entries in the `messages` array conforms to the preset configuration, with no redundant historical data loaded.
- Submit a question containing professional terms, confirm that the system returns retrieval results only including inspection documents for cell manufacturing links such as batching, coating, formation and grading.
- When calling the API interface, verify that the `variables` parameter correctly passes preset variables such as current process and batch number, with no omissions or errors.
