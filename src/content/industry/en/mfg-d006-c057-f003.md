# Inspection and Process Record Audit for Forging and Die Forging: Multi-turn Dialogue and Prompt Words

## What Data for This Category Looks Like
Data for this category originates from raw material quality certificates, heating furnace systems, press collection systems, MES systems, non-destructive testing equipment, and customer forging drawings. Daily generated documents include forging process specifications, blanking cards, heating furnace records, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports.
Data is updated per individual part, production batch, or furnace run. Fields cover forging batch number, furnace batch number, process temperature, pressure parameters, non-destructive testing results, and more. The corresponding relationship between associated materials and production links is clearly defined.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Words
Data for this category updates by production batch and furnace run, and links to multiple documents across production stages. Multi-turn dialogue must be fixedly bound to the context of the current forging batch to prevent cross-batch data mixing.
Field associations across multiple linked documents require prompt words to clearly limit data source scope. Only heating records, testing reports, and other materials for the corresponding batch may be called.
The serious potential consequences of errors require multi-turn dialogue to gradually verify matching between material furnace batches and forging batches. This avoids missing verification steps.
Additionally, document formats and field standards are relatively consistent. Prompt words must fixedly match field units and format requirements to reduce format deviations.

## Configuration Settings
| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| `variables` binding rules | Bind the current forging batch number and furnace batch number | Ensure dialogue only calls data sources for the corresponding batch, avoiding interference from cross-batch data |
| Context window size | 8000–12000 characters | Single-batch data for this category covers multiple document types including process and testing records. Complete batch-related information must be retained |
| `messages` history retention limit | Retain the first 8–12 dialogue turns | Verification for this category requires gradual tracing of check records. Excessive history will distract from current judgment |
| Stop dialogue trigger | Bind `chatId` to call the termination interface | When serious mismatches are found during verification, the current dialogue process can be actively terminated. This adapts to abnormal handling needs |
| Content polish switch | Enabled | Automatically optimizes output content such as verification descriptions and process descriptions. This adapts to content expansion and polish requirements |

This document is written for FastGPT v4.17.0.

## Three Common Mistakes
- Phenomenon: After uploading documents such as forging process specifications and ultrasonic testing reports, the dialogue box displays no parsing results and the background has no error logs. Cause: Field matching rules for file parsing are not configured correctly, or uploaded file formats exceed the range supported by the system.
- Phenomenon: Markdown-formatted content output by multi-turn dialogue cannot retain its format when copied to external tools. Cause: Plain text escape configuration for dialogue content is not enabled. Retained Markdown symbols cause parsing exceptions in external tools.
- Phenomenon: After calling the stop dialogue interface bound to `chatId`, the current dialogue continues to generate content. Cause: The `chatId` parameter of the target dialogue is not passed correctly. The interface cannot locate the corresponding session instance.

## How to Confirm Configuration is Correct
- Enter the forging number of a specified batch. Check whether the data source returned by the dialogue only associates documents such as heating furnace records and testing reports for that batch.
- Upload the process document for the corresponding batch. Confirm that the dialogue can recognize fields including furnace batch number, process temperature, and pressure parameters in the document.
- Call the stop dialogue interface bound to `chatId`. Confirm that no subsequent responses are generated for the current dialogue.
- Copy dialogue output content to an external tool. Confirm that the format can be recognized normally.

The values provided are common starting points and should be validated against local test samples.
