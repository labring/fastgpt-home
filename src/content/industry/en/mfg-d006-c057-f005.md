# Forging and Die Forging Inspection and Process Record Audit: Tool Calling and Plugins

## What data for this category looks like
Data sources cover raw material quality certificates, heating furnace systems, press collection data, MES systems, non-destructive testing equipment, and customer forging drawings. Data updates occur per forging part, per batch of materials, or per furnace run. Daily documents include forging process specifications, cutting cards, heating furnace records, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports. Core fields include furnace batch number, forging batch number, heating temperature range, forming pressure parameters, defect location and equivalent size. Units include degrees Celsius, megapascals, millimeters, and other standard units. This page content is compatible with FastGPT v4.17.0.

## What constraints these characteristics impose on the tool calling and plugins workflow
Multi-source data access needs require the tool calling module to support integration with different types of data source plugins, including industrial systems, databases, and testing equipment interfaces. High-frequency data updates require tool calling trigger logic to bind to forging batches and furnace runs, eliminating redundant calls. Diverse specialized fields require tool calling parameter matching rules to cover sub-items such as cutting dimensions, heating duration, and testing defect types. Severe error consequences require adding a field verification step to the tool calling process, ensuring pulled records fully match the current forging batch.

## Three common configuration errors
- The tool calling module outputs both AI reply content and next-level branch execution logs. This happens when branch trigger conditions are not configured correctly, and parallel execution logic is enabled by default.
- Chinese fields in MySQL data pulled by the database plugin display garbled text. This occurs when the database connection character encoding is not uniformly set to UTF-8, and does not match the data source encoding.
- Charts generated by the basic chart plugin have no corresponding data points. This happens when data grouping rules are not configured according to the field structure of forging test items and batches, so data source fields cannot be matched.

## How to confirm configuration is complete
- Submit a test request that includes a furnace batch number query, verify that the tool call automatically triggers the corresponding database plugin to pull quality certificate data.
- View plugin execution logs, confirm that Chinese fields display without garbled text.
- After configuring the basic chart plugin, import test data for a single batch of forgings, verify that the chart generates according to preset dimensions.
- Test branch trigger logic, confirm that only the target branch executes, with no redundant content from parallel outputs.
