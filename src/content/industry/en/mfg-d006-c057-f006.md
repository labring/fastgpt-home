# Inspection and Process Record Audit for Forging and Die Forging: Source Citation and Traceability

## What Data for This Category Looks Like
Data sources for the forging and die forging category include raw material quality certificates, heating furnace systems, press collection data, MES systems, non-destructive testing instruments, and customer forging drawings. Daily documents cover forging process specifications, cutting cards, heating furnace records, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports.
Data is updated per piece, per batch, or per furnace run. Fields include forging batch number, furnace batch number, process parameters, testing results, and more. Units involve degrees Celsius, megapascals, forging ratio values, and other relevant units.

## Constraints Imposed on Source Citation and Traceability
Data sources are scattered and linked to strongly associated fields such as forging batch numbers and furnace batch numbers. Traceability links must accurately match corresponding identifiers to avoid cross-batch confusion.
There are diverse document types, including structured system-collected data and unstructured paper scan records. This requires adapting text splitting and retrieval for different formats.
Data is updated frequently per piece or per furnace run. Retrieval scopes must cover documents from the latest batches, and retrieval results must quickly link to full process records for the corresponding forging.
In addition, forging defect determination relies on professional documents such as ultrasonic testing reports. Traceability must fully retain key details of these documents, rather than only extracting generic content.

## Configuration Settings
This configuration applies to FastGPT v4.17.0. Specific parameters are listed below:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapt to documents of varying lengths such as forging process specifications and ultrasonic testing reports, avoid truncating associated key fields like forging batch numbers and furnace batch numbers |
| Similarity Threshold | 0.75–0.85 | Accurately match unique identifiers such as forging batch numbers and furnace batch numbers, filter irrelevant generic process documents, and reduce invalid retrieval results |
| Single Search Limit | Top 8 entries | Cover multiple types of process records for a single furnace run of forgings, including heating furnace data, forging process cards, non-destructive testing reports, and more, avoid missing key audit basis |
| `quoteMaxToken` | 1500 token | Retain complete quoted content from long documents such as ultrasonic testing reports and heat treatment work orders, ensure auditors can view complete defect descriptions and parameter records |
| `responseData` | Return only metadata and quoted content of associated documents | Focus on core traceability information such as forging batch numbers, furnace batch numbers, and testing results, avoid displaying redundant non-associated content |
| `detail` | Enable full details | Display professional details such as defect locations and dimensions in ultrasonic testing reports, meet the depth requirements of inspection and audit |

## Three Common Mistakes
- Simple workspace knowledge base applications only return 1 citation result per run. This is because the single search limit is configured too low, failing to cover multiple types of process records such as heating furnace records and forging process cards for the same furnace run.
- An error prompt pops up when clicking test after configuring the model. The citation function works normally after ignoring the prompt. This is because the temporary permission check during the test link does not affect the official retrieval link.
- Imported JSON-format knowledge base documents do not load automatically into the available list and require manual selection. This is because the default binding parameters of the knowledge base are not configured, so the system cannot recognize the preset JSON data source.

## How to Confirm the Configuration Is Complete
- Enter the batch number of a specified forging, check whether the retrieved documents include multiple types of associated documents such as heating furnace records, forging process cards, and ultrasonic testing reports corresponding to the forging.
- Check the completeness of the quoted fragments, confirm that the quoted content does not have truncated key fields, and meets the configuration requirements of `quoteMaxToken`.
- Switch queries for forgings from different furnace runs, verify that retrieval results only link to documents from the corresponding batch, and do not mix irrelevant content from other batches.
- Import the preset JSON-format knowledge base file, confirm that the system can load the data source and participate in the retrieval process.

The values provided are common starting points and should be validated against in-house test samples.
