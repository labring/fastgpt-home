# Inspection and Process Record Audit for Forging and Die Forging: Deployment and Upgrade

## What data for this category looks like
Data for this category primarily comes from raw material quality certificates, heating furnace systems, press collection data, MES systems, non-destructive testing equipment, and customer forging drawings. Daily associated documents include forging process specifications, cutting cards, heating furnace records, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports. Data updates follow the rhythm of individual pieces, batches, or furnace runs. Core fields include heat batch numbers, forging ratios, fiber directions, detected defect types and corresponding parameters. Units cover process parameters such as temperature, pressure, and dimensional tolerances.

## What constraints these characteristics impose on deployment and upgrade
High-frequency batch or single furnace run data updates require configuring real-time or near-real-time data synchronization links during deployment, to avoid audit delays caused by lag. Multiple heterogeneous data sources require pre-configuring corresponding data access adaptation rules to ensure uniform field formats across different systems. Structured storage requirements for batch documents require knowledge base indexes to support multi-field associated retrieval. During upgrades, core associated data such as historical heat batch numbers and forging ratios must be retained, to avoid breaks in batch traceability chains. Additionally, since defect detection directly relates to forging scrap risk, sufficient retrieval response resources must be reserved during deployment.

## How to configure the settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Database connection pool configuration | Set 20–30 connections via `DB_MAX_LINK` | Adapts to high-frequency writes from multiple data sources, avoids connection exhaustion |
| Object storage endpoint configuration | Fill in the corresponding cloud service provider node via `STORAGE_S3_ENDPOINT`, set single file maximum size to 1000 MB | Adapts to large file storage needs for batch ultrasonic testing reports |
| Cache service address configuration | Fill in self-built or hosted service addresses via `REDIS_URL` | Accelerates quick verification and retrieval of heat batch numbers and batch data |
| Relational database connection | Select corresponding data sources via `PG_URL` or `MONGODB_URI` | Adapts to storage and associated retrieval of structured forging parameters |
| Knowledge base import validation | Enable automatic format validation | Prevents training data errors caused by format mistakes |
| Single retrieval recall limit | Recall the top 20 results | Balances retrieval efficiency and full recall requirements |
| File access key configuration | Customize `FILE_TOKEN_KEY` as a random string | Ensures access security for sensitive process documents |

## Three common configuration errors
- An error indicating incompatible CSV format occurs when importing transformed knowledge base data. Cause: Fields were not adjusted strictly according to the official template for FastGPT v4.17.0, and redundant fields from older versions were retained.
- The currently deployed FastGPT version cannot be viewed. Cause: Version viewing permissions were not enabled in the system settings page, or `ROOT_KEY` was not configured for administrator identity verification.
- The reference limit for the knowledge base search module cannot be adjusted. Cause: Retrieval quotas were not adjusted via corresponding configuration items, or the cache service did not synchronize configurations normally, causing quotas to fail to take effect.

## How to confirm configuration is complete
- Perform a batch import of single furnace run data, check that the import log has no format errors, and confirm that the import validation configuration is active.
- Initiate a retrieval request for a specific forging batch, check that the number of returned results matches the preset recall limit, and confirm that the retrieval configuration is working correctly.
- Access stored ultrasonic testing report files, verify that file access permissions are normal, and confirm that the key configuration is valid.
- View the system status page, confirm that the operating metrics of the database connection pool and cache service are stable, and confirm that the basic service configurations are correct.

The values provided are common starting points and should be measured against the reader's own samples.
