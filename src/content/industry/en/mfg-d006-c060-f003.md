# Inspection and Process Record Auditing for Beverage and Bottled Water: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Data for this category originates from water source and raw material testing, formula systems, online sugar and acidity monitoring equipment, filling equipment, visual inspection systems, and LIMS systems. Daily documents include formula sheets, water treatment records, blending records, sterilization or aseptic filling records, packaging material inspection sheets, and finished product inspection reports.
Data updates follow per-production batch, shift-by-shift summary, and continuous collection of key indicators. Fields include batch number, Brix value, filling liquid level value, label batch number, and others. Corresponding units are none, Brix, millimeters, and string format.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
Multi-turn dialogue and prompt engineering configurations for this category must align with its data traits.
First, continuously collected high-frequency online indicators require limiting single-turn dialogue context length to prevent redundant data from disrupting audit judgments.
Second, field differences across multiple business document types require prompts to clearly define call rules for each document type, avoiding cross-document field confusion.
Third, production data updated per batch must be linked to `chatId` to associate with the corresponding production batch, ensuring one-to-one matching between dialogue context and production batches.
Fourth, audit scenarios require fixed audit dimensions in prompts, preventing audit standard shifts caused by context fluctuations.

## How to Set the Configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to production batch number | Ensure audit dialogue context for each production batch is linked to the corresponding batch data, avoiding cross-batch data confusion |
| `messages` | Truncate the first 20 historical dialogues per production batch | Limit context length to avoid redundant high-frequency collection data interfering with audit logic |
| `variables` | Bind to batch number, Brix threshold, filling liquid level threshold | Supply fixed audit parameters for prompts to ensure consistent audit standards |
| Maximum context length | 800–1200 characters | Match the character volume of core documents for a single production batch of this category, preventing context overflow |
| Multi-turn dialogue turn division | First 5 turns for data query, last 3 turns for audit output | Separate data retrieval and audit links, simplifying prompt logic |

This configuration is based on FastGPT v4.17.0.

## Three Common Configuration Errors
- Empty responses during concurrent workflow calls: The interface returns empty fields, and logs show workflow run counts have exceeded limits. This occurs when the maximum workflow run count configuration is not adjusted, and high-concurrency requests exceed the preset threshold.
- Superimposed variable output results: Output variable B includes content from variable A in the previous turn. This happens when `variables` are not bound to an independent `chatId` context, causing variable values from prior and current turns to be reused and superimposed.
- No expected guidance after configuring input prompts and word banks: Preset guidance questions do not appear in the dialogue interface. This occurs when the prompt does not clearly specify trigger conditions for calling the word bank, so input guidance rules are not activated.

## How to Verify Successful Configuration
- Confirm that `chatId` is bound to the production batch number by checking context parameters in dialogue history.
- Test single-turn dialogue context length to ensure it stays within the 800–1200 character preset threshold.
- Simulate 2–3 concurrent requests per second to verify workflow run counts do not trigger the limit.
- After configuring input guidance and word banks, trigger the dialogue flow to confirm preset guidance questions display correctly.
