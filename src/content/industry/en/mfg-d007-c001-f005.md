# PCB Manufacturing Production Ledger Summary and Report Generation: Tool Calling and Plugins

## What the data for this category looks like
The production ledger data for PCB manufacturing comes from customer-provided Gerber files, drill files, BOM lists, as well as CAM system data, production equipment parameters, bath solution test records, AOI inspection reports, electrical testing reports, and laboratory slicing reports.
Data update frequency follows per production batch, per shift, or continuous collection. A single batch ledger includes engineering production instructions, drilling lamination parameters, chemical analysis results, defect inspection records, and other content.
Fields include layer number, aperture size, equipment operating parameters, defect coordinates and quantity, etc. There is no unified fixed field order or format, and it is adjusted based on different production links.

## What constraints these characteristics impose on the tool calling and plugins workflow
The production ledger data for PCB manufacturing comes from scattered sources and has inconsistent formats. Tool calling must adapt to the pulling and parsing of multi-source heterogeneous data, and cannot rely on a single format input.
The data update frequency varies significantly: some parameters require real-time collection, while others are synchronized per production batch. The trigger timing of tool calling must match the rhythm of the production link.
The data volume of a single batch ledger increases with the number of PCB layers and inspection items. The single data processing scale of tool calling must adapt to this characteristic.
At the same time, the ledger needs to associate engineering, inspection, and equipment data from multiple links. Tool calling must support parameter linkage across data sources. Processing only a single link's documents cannot meet the summary requirements.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Workflow/API tool selection | `auto` | Adapt to the parsing requirements of multi-source heterogeneous data, automatically match the corresponding tool to process ledger data of different formats |
| Workflow/API function-call configuration | `enabled` | Force enable tool calling to complete cross-data-source production data summary and format conversion |
| Single tool call data pull limit | First 10 production link records | The number of production link records for a single PCB batch is controllable. Pulling too many will increase parsing and transmission overhead |
| Tool call timeout threshold | 120 seconds | Pulling and parsing multi-source data requires a reasonable duration. Timeout will interrupt the ledger generation process |
| Result output format | Markdown format | Production ledgers require a clear hierarchical structure, and Markdown format facilitates subsequent report generation and distribution |
| Context window length | 8000 token | Ledger data from multiple links has a large volume. A sufficient context window can retain complete associated information |

## Three common misconfigurations
- An error prompt "tool call parameter invalid" is returned during API debugging. The cause is that the tool input parameters are not configured according to the multi-source data format of the PCB production ledger, causing the tool to fail to recognize scattered data source fields.
- The text stream received by the frontend is unformatted plain text, and a clear ledger report cannot be generated. The cause is that the result output is not configured as Markdown format, and the structured data returned by the tool is not converted into a formatted structure.
- Stream data is disconnected after being forwarded by the intermediate service, and the frontend page data remains fixed. The cause is that the timeout retry mechanism for tool calling is not set. When multi-source data pulling times out, no retry is triggered, causing the process to interrupt.

## How to verify the configuration is properly set
- Trigger a single-batch PCB ledger generation process, and check whether the tool call log displays correct data source pulling records.
- Check the result returned by the tool call, confirm that the format is Markdown and includes hierarchical production link data.
- Simulate the intermediate service forwarding scenario, test whether the stream data transmission is stable and has no unexpected disconnections.
- Adjust the data pull limit for tool calls, verify that the number of returned production link records matches the expected setting.

The values provided here are common starting points and should be measured against the reader's own samples.
