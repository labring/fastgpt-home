# Production Ledger Summary and Report Generation for SMT Mounting and Electronic Assembly: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
Production data for SMT mounting and electronic assembly comes from multiple sources. These include BOMs, Gerber files, and mounting coordinates provided by customers, plus real-time data from MES systems, mounting machines, SPI/AOI inspection equipment, and reflow oven temperature collection devices.
Daily documents cover changeover sheets, stencil parameter records, first article confirmation sheets, SPI/AOI defect reports, maintenance ledgers, and traceability labels.
Data updates in real time per work order and each changeover. Fields include part number, reference designator, component batch number, reflow temperature curve values, and defect point coordinates. Units include degrees Celsius, millimeters, serial numbers, and additional standard units.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
Data for this category is multi-sourced and updated in real time. Multi-turn dialogue must fully retain sequential interaction context across different equipment and production processes to avoid missing key work order-associated data such as BOMs and furnace temperatures.
Fields vary widely across different document types. Prompts must clearly distinguish data formats and units for categories including part numbers, defect points, and furnace temperature parameters.
Updates occur per work order and each changeover. Dialogue context must bind to the current work order ID to ensure the latest production ledger data loads for each interaction. Context length must also be limited to stop redundant historical data from interfering with current analysis.

## Configuration Settings
This setup is adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `messages` | Retain the last 10 dialogue context entries, including the current work order ID | Data for this category is multi-sourced and real-time. Current work order historical interaction records must be associated to avoid data misalignment |
| `variables` | Bind the current work order's BOM version, changeover timestamp, and furnace temperature file path | Accurately call exclusive production ledger data for the corresponding work order, to avoid cross-work order call errors |
| `chatId` | Generate a unique identifier using work order number + changeover batch | Distinguish ledger data across different production batches, ensuring dialogue context is bound to the current production task |
| Maximum context length | 800–1200 characters | Documents for this category have many compact fields. Excessively long context will interfere with prompt parsing of core fields |
| Single data recall limit | Top 5 device inspection records | Control the volume of data loaded in dialogue, to avoid redundant information affecting report generation efficiency |

## Three Common Configuration Mistakes
- Phenomenon: When calling the production ledger summary node, the generated report does not include work order-specific data confirmed in the previous dialogue. Cause: Historical dialogue context was not passed in the `messages` parameter, so the system cannot associate corresponding data such as the current work order's BOM and furnace temperatures.
- Phenomenon: No corresponding exception record is generated after the application runs with an abnormal error. Cause: Dialogue log automatic recording configuration was not enabled, so `chatId` and parameter information at the time of the exception cannot be traced back.
- Phenomenon: Prompt-generated reports run multiple times, but errors still occur where part numbers and defect points are mixed up. Cause: The prompt did not clearly distinguish field boundaries across different documents, and did not limit calls to only the current work order's production data.

## How to Verify Proper Configuration
- Initiate a dialogue that includes a clear work order ID, check whether the generated report includes the corresponding work order's BOM version, changeover records, and inspection data.
- Trigger a reproducible abnormal error, check whether the system log records the `chatId` and incoming `variables` parameters for this dialogue.
- Adjust the maximum context length parameter, test whether the volume of text loaded in dialogue falls within the set range, to avoid context overflow or redundancy.
- Launch multiple rounds of dialogue for the same work order consecutively, check whether the context retained for each interaction only includes data related to the current work order, with no information from other work orders mixed in.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
