# Production Ledger Summarization and Report Generation for Dairy Processing: Vector Models and Indexes

## What This Category's Data Looks Like
This category of data covers the full workflow from raw milk acceptance, production processing to finished product retention sampling. Data sources include raw milk testing systems, MES production management systems, homogenization and heat treatment equipment, online temperature and flow sensors, CIP cleaning systems, and LIMS laboratory management systems. Daily documents include raw milk acceptance records, standardized ingredient lists, pasteurization or UHT sterilization records, CIP cleaning records, filling records, retention sample and microbial test reports. Data updates occur in real time for each milk tank and each batch. Fields include raw milk antibiotic test values, sterilization temperature and duration, cleaning pressure parameters, total bacterial count, and more. Units include ℃, CFU/mL, MPa, and others.

## Constraints Imposed on Vector Models and Indexes
The real-time, high-frequency update nature of this category requires indexes to support incremental synchronization, to avoid performance losses from full index rebuilding. Multiple heterogeneous data sources require unified field formats and embedding logic across different documents, to ensure consistency in the vector space. The business logic that strongly links to production batches requires retaining batch-level context during text chunking, to avoid splitting that breaks the associated information of the production workflow. The high-precision recall requirement stems from serious consequences such as raw milk rejection or aseptic process failure, so indexes must accurately match all ledger data related to a batch. This differs from solid baking scenarios where records can be isolated per batch.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Chunk Length | 800–1200 characters | Adapts to the total number of fields in a single production record, avoids splitting across batches and breaking business associations |
| Overlap Length | 100–150 characters | Retains batch-related information across adjacent chunks, prevents context breaks that cause matching failures |
| `defaultToken` | 8192 | Matches the total token limit for most dairy enterprises' single-batch ledgers, ensures full embedding of all batch data |
| Similarity Threshold | 0.75–0.85 | Balances recall precision and query speed, adapts to the precise matching needs of microbial test reports and sterilization records |
| Single Search Limit | Top 10 results | Covers multiple types of records associated with a single batch, avoids missing key ledger information |
| `maxToken` | 16384 | Supports total token limits when batch importing multiple datasets, prevents index construction timeouts |

## Three Common Misconfigurations
- Symptom: Index construction takes too long, with index generation for 10 records per batch exceeding 600 seconds. Cause: Incremental index configuration is not enabled, and full index rebuilding is triggered on every update, which cannot adapt to the real-time update rhythm of dairy processing.
- Symptom: Knowledge base API calls return empty matching results or only match partial fields. Cause: Chunk length is set too small, splitting complete ledger content linked to a batch, causing vector embeddings to lose key associated information.
- Symptom: After switching embedding models, previously imported old batch data cannot match new query requests. Cause: Existing knowledge base data is not reindexed with vector embeddings, and old model embedding results are still used, leading to inconsistent vector spaces.

## How to Verify Correct Configuration
- Manually import a single raw milk acceptance record, check the number of generated index chunks, and confirm that chunk length matches the preset configuration.
- Initiate a query targeting a specific batch, verify that the number of returned results matches the single search limit configuration.
- After switching embedding models, trigger a full or incremental reindex, confirm that new queries can match old batch data.
- Review index construction logs, confirm that no token limit error occurs, and that settings comply with the `maxToken` configuration limit.

The values provided here are common starting points, and should be evaluated against the reader's own datasets.
