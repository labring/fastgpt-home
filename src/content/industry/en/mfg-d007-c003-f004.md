# Production Ledger Summary and Report Generation for Dairy Processing: Workflow Orchestration

## What Data for This Category Looks Like
Production ledger data for dairy processing covers the entire production flow of liquid milk, yogurt, milk powder and dairy ingredients. Daily documents include raw milk acceptance records, standardized batching sheets, pasteurization or UHT heat treatment records, CIP cleaning records, filling records, and sample retention and microbial test reports.
Data sources include milk source testing equipment, production MES systems, homogenization and heat treatment equipment, online temperature and flow monitoring devices, CIP systems, and LIMS laboratory management systems. Updates happen in real time for each milk tank and each production batch. Every document includes core fields such as batch number, test value, timestamp, and equipment number.

## Constraints Imposed by These Characteristics on Workflow Orchestration
Dairy processing ledger data is updated in real time across multiple sources and strongly linked by production batch. Workflow orchestration must adapt to synchronous trigger logic for multiple data sources.
A single batch of data includes test values from multiple production links. Variable mapping must be used to associate output from each node.
Perishable liquid raw materials have no redundant waiting time in their production flow. Orchestration nodes must set reasonable timeout thresholds to avoid quality risks from data backlog.
The requirement for batch uniqueness means each data source node must be bound to a unique identifier, to prevent cross-batch data confusion.
The workflow must also support dynamic loop body execution based on production batches, to cover ledger summary logic from raw milk acceptance through to filling.

## How to Set the Configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Timing | After each batch of data is written | Matches the real-time update rhythm of per milk tank and per batch in dairy processing |
| `variables` Mapping Rules | Bind core fields of links such as raw material acceptance, heat treatment, and filling | Enable cross-node data transfer and ledger association |
| `nodeId` Binding Rules | Assign a unique identifier to each data source node | Prevent cross-batch data confusion and ensure accurate ledger association |
| Timeout Setting | 600 seconds | Adapt to the response rhythm of real-time data and avoid unlimited node waiting |
| Loop Body Execution Rules | Dynamically adjust according to the number of production batches, with a single execution interval of 10 seconds | Cover the summary requirements of full-process ledgers and avoid duplicate or missing data |
| Output Field Limit | Retain only core ledger fields, with a maximum of 1024 characters | Optimize report generation efficiency and meet conventional display needs |

## Three Common Misconfigurations
- Phenomenon: The output field of the HTTP request node is empty, and it cannot be called in subsequent nodes. Cause: The output variable is not declared in the `variables` mapping rule, or there are compatibility differences with FastGPT v4.17.0.
- Phenomenon: The number of ledger entries output after the loop body runs does not match the actual number of production batches. Cause: The trigger timing is not configured according to the update rhythm of per milk tank and per batch, leading to repeated reading or missing data.
- Phenomenon: The statement generated by text2Sql cannot match the ledger fields. Cause: Unique ledger fields for dairy processing (such as raw milk colony count, pasteurization temperature) are not added to the `variables` mapping, causing the generated SQL to fail to associate with actual data.

## How to Confirm Proper Configuration
- Trigger a simulated raw milk acceptance data write, and check whether each node's `variables` correctly transfers core fields such as batch number and test value.
- View the data source node bound to `nodeId`, and confirm that the ledger data for each link corresponds to a unique identifier with no duplicates or confusion.
- Run the loop body, and verify that the output summary report includes the required document fields for the full process from raw milk acceptance, heat treatment, through to filling.
- Simulate a data delay scenario, and verify that when the timeout is set to 600 seconds, the node will not wait indefinitely and can normally trigger subsequent processes.

The values provided here are common starting points and should be evaluated against the reader's own samples.
