# Production Ledger Summary and Report Generation for Warehousing, Lot Tracking, and In-Plant Logistics: Deployment and Upgrade

## What data for this category looks like
This category of data typically originates from ERP/WMS systems, barcode or RFID collection devices, procurement and work order documents, warehouse location management ledgers, AGV or conveyor systems, and weighing equipment. Daily documents include receiving slips, putaway slips, material picking and return slips, warehouse transfer slips, inventory count sheets, lot ledgers, first-in first-out (FIFO) and expiration date records. Data update frequencies cover real-time scenarios such as barcode-based receiving, daily scenarios such as daily inventory reports, and monthly inventory counts. Core fields include material code, lot number, warehouse location number, expiration date, incoming quantity, and inspection status. Common units include pieces, kilograms, days, and similar units.

## What constraints these characteristics impose during deployment and upgrade
The requirement to access multi-source data means support must be added for connecting different data sources such as ERP/WMS and barcode systems during deployment. Corresponding connection parameters must be configured in advance. Diverse update frequencies require flexible setup of synchronization trigger rules, to differentiate synchronization frequencies for real-time collection, daily summary, and monthly inventory counts. The existence of dedicated fields such as lot numbers and expiration dates requires vector chunking and field mapping to match business document structures, to prevent loss of critical information. The business goal of reconciling book and physical inventory means deployment must prioritize data synchronization stability and accuracy. Upgrades must be compatible with existing data formats to avoid business interruptions.

## How to set configurations
The following configurations are based on FastGPT v4.17.0.
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://fastgpt:securepass@internal-erp:27017/prod_wms?authSource=admin` | Stores metadata for business documents such as lot ledgers and inventory count sheets, requires specifying authentication information and the corresponding business database name |
| `STORAGE_S3_ENDPOINT` | `http://192.168.50.20:9000` | Stores scanned copies of uploaded documents such as receiving slips and warehouse transfer slips, as well as exported summary reports. Must match the access address of the internal object storage |
| `DB_MAX_LINK` | `20–30` | Connects to multiple ERP/WMS systems and data collection devices, prevents resource exhaustion from single connections, and adapts to concurrent requirements for multi-source data synchronization |
| `REDIS_URL` | `redis://:cachepass@internal-cache:6379/1` | Caches real-time scanned material data and lot verification results, reducing overhead from repeated queries to the ERP system |

## Three common mistakes
- Vector database connection timeout, returning 504 status code. Cause: No HTTP proxy is configured for the corresponding data source, preventing access to the internal ERP/WMS system API interface.
- Generated summary reports only output in Chinese, and do not follow the requirements of the English prompt. Cause: The model's default language parameter is not configured correctly, and the lot field mapping in the knowledge base does not match the English terminology system.
- Uploaded inventory count sheets cannot be parsed, returning a "missing fields" error. Cause: Vector chunk length is set to not match the field characteristics of business documents, leading to truncation of short fields such as lot numbers and expiration dates, which cannot be extracted correctly.

## How to confirm configurations are properly set
- Run a single receiving slip synchronization test, and verify that ledger records for the corresponding lot are created in the target database.
- Upload a standard warehouse transfer slip document, and confirm the storage service returns a valid access address with no permission or connection errors.
- Trigger a monthly inventory count summary task, and check that the synchronization task run logs have no connection exceptions or data loss prompts.
- Call the report generation interface, and confirm the output content includes core business fields such as material code, lot number, and warehouse location number.

The values provided are common starting points and should be measured against the reader's own samples.
