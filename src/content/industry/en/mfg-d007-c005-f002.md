# Production Ledger Summarization and Report Generation for Photovoltaic Solar Cell Manufacturing: Vector Models and Indexes

## What Data for This Category Looks Like
Common data sources include silicon wafer incoming material records, workshop MES systems, real-time operating parameters of diffusion furnaces, coating equipment, and printing presses, EL defect detection images, IV performance test data, and laboratory quality inspection reports.
Data updates follow this rhythm: process parameters are updated once per production batch, each solar cell generates a test record, and daily summaries cover that day’s yield and grading data.
Ledger documents typically include process cards, process parameter sheets, test images, and grading reports. Fields include diffusion temperature, coating thickness, EL defect coordinates, and IV conversion efficiency, with corresponding units of degrees Celsius, micrometers, pixels, and percentage, among others.

## Constraints Imposed on Vector Models and Indexing Workflows
The high-frequency wafer-level test data and multi-modal text-and-image mixed ledgers for this category usually require vector indexes to support incremental updates and multi-modal matching.
Fine-grained professional parameters and fixed units require vector models to use normalization configurations to ensure matching accuracy.
Daily aggregated batch data and high retrieval traffic require controlling token consumption per task and the number of retrieval results returned.
Cross-process associated data requires reasonable chunking and overlap settings to avoid splitting critical context.
Additionally, component-level defect traceability needs require indexes to retain precise wafer-level data associations, and prevent over-aggregation that causes information loss.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the standard text length of process cards and diffusion parameter records, prevents single chunks from splitting content across processes |
| Overlap Length | 100–200 characters | Retains associated context between processes, prevents critical process parameters from being split across different chunks |
| Similarity Threshold | 0.75–0.85 | Meets the accuracy requirements for matching solar cell professional parameters, filters irrelevant low-match results |
| Single Search Limit | Top 10 results | Controls the volume of vector data returned by retrieval, reduces overall `defaultToken` consumption |
| `defaultToken` | 4000 token | Adapts to the aggregated context length of a single production batch ledger, meets basic report generation requirements |
| `maxToken` | 16000 token | Covers the total context requirements of multi-batch cross-cycle report generation, prevents task interruptions mid-run |

## Three Common Configuration Errors
- Issue: Retrieval tasks frequently time out, and logs show context token limit exceeded. Cause: The `maxToken` value was not adjusted based on the actual data scale of a single batch ledger, and an overly small general-purpose configuration was used.
- Issue: Index progress does not update after switching vector models, and the original model configuration cannot be restored. Cause: The index cache of the old model was not cleared before switching, or a forced reset was not performed in accordance with FastGPT v4.17.0 version adaptation requirements.
- Issue: Retrieval and matching results for EL detection images do not meet expectations, with large fluctuations in similarity scores. Cause: The vector model normalization configuration was not enabled, causing unnormalized image vectors to mismatch model input requirements.

## How to Confirm Configurations Are Properly Set
- Check the progress bar in the FastGPT index management interface, confirm that vector generation tasks for single-batch data complete within 10 minutes.
- Initiate a retrieval targeting diffusion furnace temperature parameters, verify that the returned result fields exactly match the professional parameters in the original ledger.
- Adjust the `defaultToken` configuration, verify that the token count loaded for the context matches the set value, with no overages or truncation.
- Confirm that the current FastGPT version is v4.17.0, which adapts to the normalization requirements of the configured vector model.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
