# Production Ledger Summary and Report Generation for Photovoltaic Cell Manufacturing: Workflow Orchestration

## What the data for this category looks like
Data sources for photovoltaic cell manufacturing production ledger data include silicon wafer incoming material records, workshop MES systems, operating parameters of diffusion furnaces, coating equipment, and printing presses, EL and IV test reports, and laboratory test data. Data update frequencies cover each production batch, each product inspection, and daily summary links. Daily ledger documents include process cards, diffusion and coating parameter tables, printing and sintering records, EL defect detection images, IV performance grading data, and yield analysis reports. Fields include equipment operating temperature, coating thickness, defect coordinates, photoelectric conversion efficiency, and more, with corresponding units of degrees Celsius, micrometers, millimeters, watts, and others.

## What constraints these characteristics impose on the "workflow orchestration" link
Data sources for this category are scattered, covering multiple systems including equipment, inspection, and production management. Workflow orchestration requires configuring multiple nodes to pull information from different data sources separately. The high-frequency update rhythm requires workflow triggering timing to be bound to production batch completion nodes or daily scheduled tasks to avoid data lag. Professional fields such as diffusion furnace temperature and EL defect parameters must be accurately mapped via `variables` to ensure ledger fields align with the standard format of business documents. The large volume of wafer-level inspection data requires the workflow to support grouping and summarization by batch to prevent excessive load on a single node. Cross-departmental document circulation requires clear paths to prevent data omission in different links.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| Trigger Timing | Trigger upon production batch completion, supplement missing data for the current day at 00:00 daily | Matches the update frequency of each batch and daily cycle for this category |
| `variables` | Bind mapping rules for equipment parameters, inspection data, and user information | Align professional fields in documents such as process cards and EL detection images |
| `nodeId` | Bind unique identifiers for each data source node | Ensure accuracy and traceability of workflow node transitions |
| Node Transition Permissions | Enable cross-branch reuse configuration | Meet the requirement of calling the same form node across multiple links |
| Timeout Setting | 600 seconds | Adapt to the overall time consumption requirement of pulling data from multiple sources |
| Result Output Format | Generate structured ledgers by production batch | Match the reporting and archiving requirements of the production department |

## Three common errors
- Empty values returned after calling the workflow, with no valid content in API response results. The cause is that associated parameters of the nested knowledge base assistant are not configured in `variables`, and the interface call rules of FastGPT v4.17.0 version are not adapted.
- Cross-branch reuse form node failure: jumping to this node from other branches has no response. The cause is that the cross-branch reuse permission of the node is not enabled; by default, nodes only support single-link calls.
- The generated ledger only includes the user ID and not the name, which cannot meet business reporting requirements. The cause is that the mapping field of user information is not configured via `variables`, and only the default global user ID variable is called.

## How to confirm the configuration is complete
- Trigger a simulated production batch workflow, check node logs to confirm that data from each data source is pulled completely.
- Call the FastGPT v4.17.0 version API to initiate a test request, check whether the returned results include the configured `variables` mapping fields.
- Try jumping to the same form node from two different branches, confirm that the node can normally receive and process requests.
- View the generated ledger documents, confirm that the fields fully align with the business fields of process cards and IV test reports.
