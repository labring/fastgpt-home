# Production Ledger Summary and Report Generation for Photovoltaic Cell Manufacturing: Tool Calling and Plugins

## What the Data for This Category Looks Like
Production ledger data for photovoltaic cell manufacturing comes from silicon wafer incoming material warehousing, workshop MES systems, real-time operating data from diffusion furnaces, coating equipment, and printers, wafer-level test results from EL and IV testing, and laboratory sampling data. Data update cycles include per-batch production records, per-cell test data, and daily aggregated workshop operating data. Common document types include process cards, diffusion and coating parameter sheets, printing and sintering process records, EL defect detection images, IV grading data tables, and yield analysis reports. Fields include process temperature, coating thickness, grid line width, defect coordinates, conversion efficiency, grading level, and others. Corresponding units are mostly degrees Celsius, micrometers, watts, and level identifiers.

## Constraints Imposed by These Characteristics on Tool Calling and Plugins
Multi-source heterogeneous data sources require tool calling to adapt to different types of data source plugins, including structured parameter pulling, image parsing, and numerical calculation tools. High-frequency update cycles require tool calling to match real-time or near-real-time data pulling frequencies, to avoid delayed or expired data. Diverse document types require tools to support cross-format parsing, such as converting defect coordinates from EL detection images into structured fields, or converting raw IV test data into conversion efficiency values. Fine-grained wafer-level data increases the information returned by a single tool call, so it is necessary to limit the output scale of tool calls to prevent exceeding the model context window.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Tool calling mode | `auto` (model autonomously selects tools) | Adapts to multi-type tool calling requirements, covering scenarios such as process parameter pulling, defect detection, and data summary |
| Single tool call upper limit | `10–15 times` | Matches the multi-process ledger pulling requirements of photovoltaic cell production, avoiding returning excessive data in a single call |
| Context window limit | `8192–16384 token` | Adapts to the multi-field, multi-batch data summary requirements of photovoltaic ledgers, covering the context capacity of common large models |
| Tool call timeout duration | `300 seconds` | Adapts to the delay in device data pulling, preventing call failures caused by slow device responses |
| Data source cache cycle | `24 hours` | Matches the daily update cycle of production ledgers, reducing the overhead of repeated device data pulling |

## Three Common Misconfigurations
- Symptom: Generated production ledgers lack parameter fields for diffusion furnaces or coating equipment, with corresponding fields empty. Cause: The MCP service proxy address of the corresponding device data source was not correctly configured, and tool binding was not completed.
- Symptom: Tool call fails to trigger, returning a 400 status code or the prompt "no available tools matched". Cause: A reasonable tool calling mode was not set, or the required plugin service was not enabled.
- Symptom: Context truncation or the error "insufficient context length" occurs when generating reports. Cause: The number of returned entries per tool call was not limited, resulting in cumulative data exceeding the model context window.

## How to Verify Correct Configuration
- Submit a request containing "pull the diffusion furnace process parameters with batch number P20240520", verify that the tool can successfully pull the corresponding data and fill it into the ledger.
- Submit a request containing "parse the hidden crack defects in the EL detection image", confirm that the tool can trigger the image parsing plugin and return structured defect coordinates.
- Check the tool call log to confirm that the number of returned entries per call does not exceed the set single tool call upper limit.
- Submit a production data summary request covering more than 3 batches, verify that the context window limit does not trigger an overflow error.

The values provided are common starting points and should be measured against the reader's own samples.
