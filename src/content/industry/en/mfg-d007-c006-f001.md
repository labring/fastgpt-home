# Production Ledger Summary and Report Generation for Photovoltaic Module Encapsulation: HTTP Interfaces and External Systems

## What the data for this category looks like
Data sources for photovoltaic module encapsulation include wafer grading systems, glass adhesive film and backplane batch ledgers, factory MES systems, string welding and lamination equipment, and EL/IV testers. Data is updated per individual module and per material batch. Daily documents include layout diagrams, material batch records, lamination process records, EL defect images, IV test reports, insulation voltage resistance records, and packing lists. Data fields include component serial numbers, wafer current grades, lamination temperature and duration, EL crack coordinates, IV power values, and packing batch numbers, with corresponding units such as degrees Celsius, seconds, watts, and megaohms.

## Constraints for HTTP Interfaces and External Systems from These Data Characteristics
This category has data with high update frequencies and wide variation in single-record data size. EL defect images and IV test reports are mostly binary or large text files, so HTTP interfaces must support high-load requests and batch data pulling. Data fields include industry-specific units and identifiers, so interface requests must carry standardized field mapping rules to prevent parsing failures caused by field mismatches. Cross-system synchronization requirements mean interfaces must support authentication mechanisms, while also adapting to differences in reporting formats across external systems. Single-record data has strict timeliness requirements, so interfaces must be configured with reasonable timeout periods to avoid ledger update delays caused by latency.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {Enterprise-specific API key}` | Complies with the authentication standards of external MES and tester systems, ensuring the legitimacy of interface calls |
| `variables` | `{"component_serial": "{{input.serial_number}}", "test_type": "iv"}` | Matches the core business fields of photovoltaic module encapsulation, enabling accurate pulling of single-component ledgers |
| `responseData` | `{"material_batch": "{{$.batch_no}}", "current_grade": "{{$.battery.current}}"}` | Filters and maps redundant fields returned by external systems to meet the field requirements of ledger summary |
| Timeout setting | 60 seconds | Adapts to the time required for EL image upload and large text report pulling, avoiding data synchronization interruptions due to timeout |
| Retry count | 3 times | Addresses scenarios of network fluctuations and temporary unavailability of external systems, ensuring no data loss |

## Three Common Configuration Mistakes
- `400 invalid image` error when calling the HTTP interface: The symptom is failed EL defect image upload, with logs showing that the image format is not supported. The cause is failure to correctly convert the EL image binary stream to base64 encoding before passing it to the interface.
- HTTP module call error: The symptom is the interface returning a 500 status code or connection timeout. The cause is failure to configure a reasonable timeout period, or incorrect key format for the `Authorization` header.
- Empty ledger summary fields: The symptom is missing wafer current grade data in the generated report. The cause is failure to correctly map the corresponding fields returned by the external system in `variables`.

## How to Verify Correct Configuration
- Manually trigger an HTTP interface call to check if the returned `responseData` contains the preset business fields, with no redundant or missing content.
- Upload a standard JPEG format EL defect image to verify that the interface can receive it normally and return parsing results, with no `400 invalid image` error.
- Simulate network fluctuation interruptions during a call to confirm that the system automatically initiates retries according to the configured retry count, with no data loss.
- After connecting to an external MES system, check if the update time of ledger data matches the component production time, with no obvious delay.
