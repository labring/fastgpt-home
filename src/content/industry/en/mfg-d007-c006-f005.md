# Production Ledger Summary and Report Generation for Photovoltaic Module Encapsulation: Tool Calling and Plugins

## What the data for this category looks like
Photovoltaic module encapsulation production data sources include cell grading records, glass adhesive film and backplane batch ledgers, workshop MES systems, string welding and lamination equipment logs, and output files from EL defect detectors and IV power testers.
Data is updated in real time per individual module or material batch.
Daily documents include layout diagrams, material batch records, lamination process parameter records, EL defect images, IV test reports, insulation withstand voltage test records, and finished product packing lists.
Data fields include cell current gear, lamination temperature and pressure, EL crack coordinates, IV test power values, insulation withstand voltage resistance, and other fields corresponding to standard measurement units for each device.

## What constraints do these characteristics impose on the tool calling and plugins link
Because data is updated in real time per module or material batch, tool calling must support dynamically passing batch IDs or component serial numbers as request parameters. This adapts to pull logic across different data sources.
Multi-source heterogeneous data sources require the tool chain to call the MES system, device log interface, and test instrument API in sequence. This separately obtains process parameters and test results.
Differences in data field units require plugins to include built-in format conversion rules. This ensures field alignment during data summarization.
At the same time, errors in production ledgers may lead to batches of non-compliant modules. Tool calling must be configured with failure retry and exception alert logic. This avoids missing key data.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `functionCall` | Mandatory call of specified tools | Ensure each tool call points to the preset ledger pull interface, and prevent the model from deviating from the assigned task |
| Request timeout | 30–60 seconds | Response times for photovoltaic production equipment and test interfaces typically fall between 10 and 30 seconds. This buffer prevents false timeout judgments |
| Dynamic parameter transfer rule | Auto-fill request body with component ID | Adapt to the need to pull real-time ledger data for individual components, and match the update rhythm of production data |
| Number of failure retries | 2 times | Offset the impact of temporary network fluctuations or brief interface jitters, while controlling the frequency of repeated requests |
| Result format validation | Validate existence of core fields | Ensure pulled ledgers contain key data such as cell current gears and lamination process parameters |

## Three common misconfigurations
- Phenomenon: Tool calls return a 422 error code, and request testing fails. Cause: Dynamic parameter format is not configured correctly. For example, quotes are not added when passing component IDs as strings, or request body fields do not match interface definitions.
- Phenomenon: Ledger data pulled by the tool has empty or incomplete fields. Cause: Dynamic parameter transfer rules are not set. Fixed batch IDs are used to pull data, which cannot adapt to real-time ledgers for different components.
- Phenomenon: Subsequent summarization logic is not triggered after a tool call, and report generation stalls. Cause: Mandatory mode for `functionCall` is not configured. The model autonomously selects other non-preset tools, deviating from the preset ledger pull task.

## How to confirm the configuration is correct
- In the FastGPT v4.17.0 tool debugging interface, enter different component IDs to verify that tool calls return ledger data for the corresponding batch.
- Simulate temporary network interruptions to verify that tool calls trigger the preset failure retry logic, with retry times matching the configured requirements.
- Check the return results of tool calls to confirm that all core fields have been correctly validated, with no missing or format errors.
- Trigger the complete production ledger summarization process to confirm that the results of tool calls correctly flow into the subsequent report generation link.
