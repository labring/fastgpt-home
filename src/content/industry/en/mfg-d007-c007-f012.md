# Production Ledger Summarization and Report Generation for Stamping and Sheet Forming: Deployment and Upgrade

## What Data for This Category Looks Like
The data for this category primarily comes from steel coil labels and quality certificates, press and feeder operation data, mold management systems, MES systems, and coordinate measuring machine or fixture inspection data. Daily generated documents include stamping work instructions, material utilization rate sheets, mold inspection sheets, first/last piece records, dimensional inspection reports, and mold change records. Updates occur per coil of material, per production batch, or each time a mold is changed. Fields include material specifications, stamping parameters, mold status, inspection results, and more. There is no unified fixed format, and content changes dynamically with production batches and mold change operations.

## What Constraints These Characteristics Impose During Deployment and Upgrade
The data sources for this category are scattered and have high update frequencies. During deployment, access configuration for multi-source heterogeneous data must be adapted, and adaptation space for multiple data interfaces must be reserved. Daily production documents have no fixed format. During deployment, flexible document parsing rules must be configured to adapt to different types of production ledger fields. Mold changes and batch updates occur frequently. During upgrade, real-time data synchronization must be ensured to avoid production data loss caused by upgrade interruptions. This category relies on mold and equipment operation data. During deployment, compatibility with existing workshop equipment systems must be verified to ensure a stable data collection link and avoid data collection anomalies caused by incompatible configurations.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–200 concurrent connections` | Adapts to concurrent read requirements for multi-source production data, avoids database connection exhaustion, and supports high-frequency production ledger queries |
| `MONGODB_URI` | `MongoDB cluster address for storing production ledgers` | Stores unstructured production documents and dynamically changing production records, adapts to the diverse format of ledger data for this category |
| `PG_URL` | `PostgreSQL database address for storing structured production parameters` | Stores structured data such as steel coil specifications and stamping parameters, enabling fast query and statistical analysis |
| `REDIS_URL` | `Local Redis service address, default port 6379` | Caches frequently read production ledger data to reduce database load, adapts to scenarios with real-time updated production data |
| `STORAGE_S3_ENDPOINT` | `Workshop local object storage service address` | Stores batch-uploaded production documents, ensures local data storage complies with workshop data security requirements |
| `FILE_TOKEN_KEY` | `Encryption key consistent with the workshop file system` | Verifies the legitimacy of file upload requests, prevents unauthorized uploads of production documents, and safeguards workshop data security |

## Three Common Misconfigurations
- Symptom: After configuring a file upload node in the workflow, returning a permission error or empty result when parsing the file address. Cause: `FILE_TOKEN_KEY` is not configured correctly, leading to failure to verify access permissions for the local file system and inability to read uploaded production documents.
- Symptom: External platform calls to the chat interface experience timeout, with longer-than-expected latency. Cause: `DB_MAX_LINK` is not configured reasonably, with insufficient concurrent connections leading to backlog of multi-source production data queries and delayed interface responses.
- Symptom: Dependency package loading fails when deploying FastGPT v4.17.0 via local compilation. Cause: Dependency package versions compatible with the current version are not used, or `FE_DOMAIN` is not configured correctly leading to abnormal static resource loading.

## How to Confirm Configurations Are Correctly Set
- Run a database connection test to verify that databases configured via `MONGODB_URI` and `PG_URL` can read and write corresponding types of production data normally.
- Upload a stamping work instruction document, and use the document parsing node to confirm that document content can be read normally, verifying that `STORAGE_S3_ENDPOINT` and `FILE_TOKEN_KEY` configurations are effective.
- Call the external chat interface to confirm that responses meet expectations, verifying that `FE_DOMAIN` and `REDIS_URL` configurations adapt to intranet access scenarios.
- Simulate a production data upload after a mold change, verify that data can be synchronized to the database normally, confirming that the concurrent connection count set via `DB_MAX_LINK` meets the requirements of the current production scenario.

The values given are common starting points and should be measured against the reader's own samples.
