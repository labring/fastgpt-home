# Cosmetics Production: Ledger Summary and Report Generation - Tool Calling and Plugins

## What this category's data looks like
Data for this category comes from daily production documents of skincare, haircare, makeup, and special cosmetics manufacturers. These documents include formula process sheets, weighing and feeding records, emulsification and filling records, cleaning and site clearance records, semi-finished and finished product inspection reports, and label review forms. Data sources include registered and filed formulas, raw material safety materials, production equipment, ERP/MES systems, laboratory data, and packaging material version information. Update frequency is per production batch or each line change. Document fields include raw material batch number, usage amount, process parameters, inspection results, batch number, packaging material information, and more. Units include grams, milliliters, degrees Celsius, minutes, and others.

## What constraints these characteristics impose on the tool calling and plugins workflow
Because data is updated per batch or line change, tool calling must support pulling and aggregating data at the single batch level. It must adapt to heterogeneous data formats from multiple sources. Formulas and labels must strictly match filed information. Tool calling must connect to the filing database for verification to avoid inconsistent fields. Multiple production records must be associated and summarized by batch. Plugins must support automatic alignment of cross-system data, while handling differences in parameter formats output by different equipment. Errors carry compliance risks. Tool calling must add a compliance verification step to ensure output reports meet filing requirements.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | Automatically match tools required for ledger summary, adapt to multi-data-source pulling needs |
| Single tool call timeout | 600 seconds | Covers time required for batch pulling of data from ERP and laboratory equipment |
| Workflow/API function-call configuration | Enabled | Force generation of structured report fields to ensure ledger format meets compliance requirements |
| Plugin data pulling scope | Latest 1 production batch | Matches batch-based business update rhythm, reduces invalid data loading |
| Plugin call retry count | 2 times | Addresses temporary fluctuations in equipment or system interfaces, ensures data pulling success rate |
| Compliance verification trigger point | Before report generation | Ensure comparison and verification of filed formulas and labels are completed before output |

## Three common mistakes
- Generated reports missing packaging material version information. This appears as missing fields in plugin return results. The cause is incorrect configuration of tool calls associated with the packaging material database, and failure to reference the corresponding tool's documentation to complete parameter configuration.
- Interface returns status code 429. This appears as frequent tool calls triggering rate limits. The cause is failure to limit the single pull data range, with batch pulling of multiple production batches exceeding interface call limits.
- Calling the Chrome plugin fails to trigger ledger generation. This appears as no response from the plugin. The cause is incorrect configuration of the plugin's permissions and trigger logic, and failure to match FastGPT's tool calling specifications.

## How to confirm correct configuration
- Initiate a single batch ledger summary request. Use the log viewing function of FastGPT v4.17.0 to check if returned results include fields from core documents such as formula process sheets and weighing records.
- Trigger the compliance verification step. Input raw material usage amounts that do not match filed information, confirm that tool calls will intercept exceptions and return clear prompts.
- Simulate an interface rate limiting scenario, check if the plugin automatically retries according to the configured retry count without triggering a global error.
- Check the plugin's icon configuration, confirm that custom modifications have been completed as required.

The values given are common starting points and should be measured against the reader's own samples.
