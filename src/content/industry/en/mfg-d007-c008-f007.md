# Cosmetic Manufacturing Production Ledger Summarization and Report Generation: Database and Operations

## What this category’s data looks like
This category’s data covers end-to-end documentation for skincare, haircare, makeup, and special cosmetic manufacturers. Included documents are formula sheets, weighing and batching records, emulsification or filling logs, cleaning and sanitization records, semi-finished and finished product inspection reports, and label review documents.
Data sources include registered or filed formulas, raw material safety materials, production equipment, ERP/MES systems, laboratory data, and packaging material version information. Updates occur with each production batch or line change. Core fields include filing numbers, raw material batches, production parameters, inspection results, and packaging material batch numbers.

## What constraints these characteristics impose on database and operations workflows
The high-frequency update requirement for each batch or line change demands databases support low-latency writes and batch operations to avoid blocking production flows. Heterogeneous data from multiple sources must support both structured parameter and unstructured document storage. Unique identifiers such as filing numbers and batch numbers must be linked across datasets to ensure traceability.
Formulas and label data subject to filing rules must maintain strong consistency to prevent records that diverge from filed information. The system must support quick historical ledger queries by batch to meet compliance audit needs.

## How to configure the setup
This configuration uses FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://prod_user:secure_pass@db-host:27017/cosmetic_prod?authSource=admin` | Adapts to storage and associated queries for multiple production document types, supports batch writing of ledger data |
| `PG_URL` | `postgresql://meta_user:secure_pass@meta-host:5432/cosmetic_meta?sslmode=require` | Stores structured data requiring compliant traceability, such as filing metadata and inspection reports |
| `DB_MAX_LINK` | `20–30 connections` | Matches concurrent write and query requests per production batch, prevents database connection exhaustion |
| `REDIS_URL` | `redis://cache_user:secure_pass@cache-host:6379/0` | Caches frequently queried filing formulas and batch association data to reduce database query latency |

## Three common configuration errors
- Phenomenon: After deploying via Docker, modifying the database password causes failed database connections. The console returns authentication failure errors. Cause: The password parameter in the `MONGODB_URI` configuration was not updated synchronously, causing connection verification to fail.
- Phenomenon: After enabling problem optimization and result rearrangement functions, production ledger report generation times out. Response duration exceeds 30 seconds. Cause: The `DB_MAX_LINK` parameter was not adjusted. The database connection pool cannot support high-frequency concurrent retrieval requests.
- Phenomenon: Duplicate calls occur during tool selection. Multiple identical ledger reports are generated. Cause: No task deduplication logic was configured in the workflow. The same batch of production data triggers summarization tasks multiple times.

## How to confirm the configuration is valid
- Execute the database connection test script to verify the connectivity configured via `MONGODB_URI` and `PG_URL`, and confirm no authentication failure errors appear.
- Simulate a batch data write following a line change, check if the `DB_MAX_LINK` parameter supports concurrent write requests, and confirm no connection exhaustion prompts are generated.
- Review the Redis cached filing formula data to confirm the `REDIS_URL` configuration delivers normal cache hit rates, and check for no logs indicating frequent database penetration.
- Trigger a single ledger report generation task, check for duplicate tasks or timeouts, and confirm the workflow logic operates correctly.

The values provided are common starting points and should be evaluated against the reader's own samples.
