# Production Ledger Summary and Report Generation for Pharmaceutical Preparations Production: HTTP Interfaces and External Systems

## What this category of data looks like
Ledger data for pharmaceutical preparations production comes from approved formulation processes, material batch information, MES electronic batch records, equipment and environmental monitoring data, LIMS systems, and quality management systems.
Data update frequency follows each production batch, each execution of a key process step, and updates per fixed monitoring plans.
Daily documents include master production files, batch production records, batch packaging records, cleaning records, inspection records, deviation/CAPA/change records, and batch release review forms.
Fields cover material batch numbers, process parameters, test results, deviation descriptions, and more. Most units are standardized metric values such as kilograms, degrees Celsius, and hours.

## What constraints do these characteristics impose on HTTP interfaces and external systems
Multi-source data sources and strict update cadences for pharmaceutical preparations production require HTTP interfaces to accurately pull data from multiple systems by production batch.
Under GMP compliance requirements, interfaces must include authentication capabilities to ensure secure data access. They must also support standardized conversion of field formats and units to eliminate data discrepancies across systems.
Ledger data for each production batch is highly correlated. Interfaces must support batch correlated pulling, and ensure data update times sync with production step execution times. This maintains timeliness and accuracy of ledger summaries.
Additionally, ledger data must meet regulatory requirements. Fields returned by interfaces must be strictly limited to necessary content required by GMP, with no redundant information.

## How to configure settings

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {pre-configured GMP-compliant API key}` | Pharmaceutical preparations production data is subject to regulatory oversight; authentication ensures secure data access |
| `variables` | `{"target_batch": "{{workflow.batch_id}}", "data_sources": ["mes", "lims", "qms"]}` | Pull matching multi-source ledger data by production batch to support summary requirements |
| `responseData` | `Retain batch number, material information, process parameters, test results, and deviation record fields` | Meet GMP data integrity requirements; only pass required ledger fields |
| Timeout setting | 600 seconds | Multi-source data pulling requires sufficient processing time to avoid mid-process timeout interruptions |
| Batch pull count | First 15–20 entries | Single batch ledger data volume is moderate; balances interface load and summary efficiency |
| Data format conversion | Standardize to field units required by GMP | Match standardized requirements for batch record review |

## Three common configuration errors
- An "resource inaccessible" error is returned when calling external system interfaces. The cause is failure to configure the `Authorization` authentication parameter that meets GMP compliance requirements, resulting in interface interception.
- Pulled ledger data fields have inconsistent units, such as material weight appearing in both kilograms and grams. The cause is failure to add unit conversion rules in the interface configuration, and failure to match the standardized field format required by GMP.
- A downloadable BLOB file cannot be generated after triggering the HTTP node in the workflow. The cause is failure to correctly map the binary stream in `responseData` to a downloadable file format, and failure to configure a file name variable associated with the production batch.

## How to confirm correct configuration
- Manually input a known production batch ID, trigger the HTTP interface call, and verify that the returned `responseData` only includes ledger fields required by GMP.
- Check the `Authorization` parameter configuration, confirm that a pre-configured compliant key is used, and no public or expired keys are utilized.
- Simulate multi-source data pulling, verify that the data update time returned by the interface matches the execution time of production steps, and meets the preset update frequency requirements.
- Trigger the BLOB file generation action, confirm that the generated file can be downloaded normally, and the file name includes identification information related to the production batch.
