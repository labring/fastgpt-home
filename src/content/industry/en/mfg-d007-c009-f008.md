# Production Ledger Aggregation and Report Generation for Pharmaceutical Dosage Manufacturing: Document Parsing and Chunking

## What the Data for This Category Looks Like
Data related to pharmaceutical dosage manufacturing is generated daily by production, quality assurance, quality control, and warehouse departments. Sources include approved formulation processes, material batches, MES/electronic batch records, equipment and environmental monitoring systems, LIMS, and quality management systems.
Daily documents include master production files, batch production records, batch packaging records, cleaning records, inspection records, deviation/CAPA/change documents, and batch release review forms. Data fields include material codes, weighing values, process parameters, test results, deviation descriptions, and more. Units correspond to the data type.
Data is updated for each batch production or when each critical step is completed. Environmental monitoring data is updated regularly per established schedules.

## Constraints on Document Parsing and Chunking
The diverse document types for this category include a large number of structured tables and batch identifiers. The parsing workflow must accurately distinguish between different document sections and field content.
Data integrated from multiple source systems may have format differences. Parsed data fields must remain complete and free of misalignment.
Document update frequency is high for each batch. The parsing process must balance efficiency and completeness to avoid task interruptions caused by parsing timeouts.
Compliance requirements demand data traceability. The chunking process must retain key metadata such as document type and batch number, to prevent incorrect aggregation of cross-batch content.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Batch records for pharmaceutical dosage manufacturing contain independent content such as single process steps and test results. This range preserves the full context of a single piece of information, avoiding splitting critical parameters and descriptions. |
| `chunkSplitter` | Split by paragraph + heading | Batch records and quality documents have clear section divisions, such as feeding steps and deviation investigations. Splitting by headings ensures content from the same section is grouped together, making it easier to categorize by production stage during subsequent aggregation. |
| `customPdfParse` | Enable MinerU enhanced parsing | Documents in this category include a large number of structured tables, such as material weighing sheets and original test records. Enhanced parsing accurately extracts table fields and formatting, avoiding data misalignment or loss. |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Complete production records for a single batch may include multiple scanned pages and electronic documents. A longer timeout ensures complex files complete full parsing, avoiding interruptions due to excessive content. |
| `UPLOAD_FILE_MAX_SIZE` | 500–1000 MB | Complete production archives for a single batch may include multiple associated documents. This range covers the single-batch file size requirements of most enterprises. |
| `chunkSettingMode` | Manual configuration | Parameters for chunking must be adjusted for different document types such as batch production records and deviation reports. Manual mode allows flexible adaptation to the content structure of each scenario. |

## Three Common Mistakes
- Symptom: Parsing tasks show a timeout or return a "parsing failed" error. Cause: `PARSE_FILE_TIMEOUT_SECONDS` was not adjusted to a value suitable for the size of batch record files, resulting in complex documents being interrupted before full parsing is complete.
- Symptom: Parsed chunks contain cross-batch content, or key fields such as material batch numbers are missing. Cause: `customPdfParse` enhanced parsing was not enabled. Standard PDF parsing cannot accurately identify structured tables and batch identifiers within documents, leading to chaotic chunking logic.
- Symptom: The PDF enhanced parsing option cannot be checked in plugin or knowledge base settings. Cause: The local MinerU API access address was not correctly filled in the FastGPT configuration, or the MinerU service was not started normally, preventing the enhanced parsing function from being called.

## How to Verify Proper Configuration
- Upload a single typical batch production record PDF, view the parsed chunk list, and confirm that each chunk contains complete single-process or inspection content with no obvious splitting errors.
- Navigate to the knowledge base settings page of FastGPT v4.17.0, confirm that the `customPdfParse` option is checked, and that the MinerU local API port configuration matches the actual deployed service.
- Upload a test record PDF containing complex tables, check that the table fields in the parsed results are complete, with no misalignment or missing content.
- View the background logs of the parsing task, confirm that the parsing time does not exceed the configured `PARSE_FILE_TIMEOUT_SECONDS` value, and there are no timeout-related errors.
