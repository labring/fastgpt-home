# Production Ledger Summary and Report Generation for Pharmaceutical Preparations Production: Model Integration and Configuration

## What the data for this category looks like
Data sources for pharmaceutical preparations production include approved prescription processes, material batch information, MES electronic batch records, equipment and environmental monitoring data, LIMS test results, and deviation and change records in the quality management system. Data is updated for each production batch, when each key process step is executed, or synced according to a fixed monitoring plan. Daily documents include master production files, batch production records, batch packaging records, cleaning records, test records, deviation/CAPA/change documents, and batch release review forms. Document fields cover material batch numbers, process parameter values, test results, deviation descriptions, and other relevant content. Corresponding units include batch numbers, degrees Celsius, kilograms, percentages, and additional standard units.

## What constraints these characteristics impose on model integration and configuration
Dispersed data sources connected to multiple systems require model integration and configuration to support multi-source data pulling and association logic. Data updates occur per batch and strict compliance requirements mean the configured context window must fit the full data volume of a single batch to avoid truncating critical information. The large number of document fields and specialized pharmaceutical production terminology require model configuration to support understanding and generation of professional expressions. Batch record review requires strict data integrity, so model outputs must include clear citation sources to ensure traceability. Additionally, deviation and change records must be included in summaries in real time, so model response delay must match production rhythms to avoid impacting release workflows.

## How to Configure Settings
The following configuration items apply to FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Fits the context length of full production ledgers for single batches, avoids truncating critical process and test data |
| `maxTokens` | 2000–3000 token | Controls output length for a single report, ensures coverage of complete batch record summary and release judgment logic |
| `quoteMaxToken` | 1500 token | Limits the length of cited source data, ensures cited content is accurate and does not interfere with main report logic |
| `temperature` | 0.1–0.3 | Reduces output randomness, ensures consistent accuracy of professional pharmaceutical production expressions and compliance judgments |
| `AIPROXY_API_ENDPOINT` | Fill in the deployed model service address | Connects to local or cloud-based large model services, adapts to enterprise internal network environments |
| `AIPROXY_API_TOKEN` | Fill in the key generated during deployment | Verifies access permissions for model services, ensures security of data interactions |

## Three Common Configuration Errors
- A 404 status code is returned when calling the model. The cause is incorrect configuration of `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN`, or the deployed model service has not opened the corresponding access port.
- Generated reports truncate critical process data. The cause is that the values of `maxContext` or `maxTokens` are too small to cover the full ledger data for a single batch.
- Output results have poor consistency, with random deviations in professional expressions or compliance judgments. The cause is that `temperature` is set too high, exceeding the reasonable range for pharmaceutical production scenarios.

## How to Verify Successful Configuration
- Input a typical fragment of ledger data for a single batch, trigger summary report generation, and check if the output includes summary content for all key fields.
- Check the access logs of the model service, confirm there are no authentication failure records related to `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN`.
- After generating a report, verify that the cited source data fragments match the input ledger content, confirming that the `quoteMaxToken` configuration takes effect.
- Adjust the `temperature` value and compare output results, observe changes in generation logic consistency, confirming the configuration meets expectations.

The values provided are common starting points and should be measured against the reader's own samples.
