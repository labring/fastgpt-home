# Production Ledger Summary and Report Generation for Pharmaceutical Dosage Production: Knowledge Base Retrieval and Recall

## What This Category of Data Looks Like
Data sources for pharmaceutical dosage production include approved formulation processes, MES electronic batch records, equipment and environmental monitoring data, LIMS systems, and quality management systems. Data updates occur per production batch, when each key process step is executed, or synced according to a fixed monitoring plan. Daily documents include master production files, batch production records, batch packaging records, cleaning records, inspection records, deviation and change documents, and batch release review forms. Fields cover material batch numbers, process parameters, weighing data, deviation descriptions, inspection results, and other relevant items. Units include professional production and quality control units such as weight, time, and temperature.

## Constraints Imposed on Knowledge Base Retrieval and Recall
Data for this category is tied to production batches and process nodes. A single retrieval must accurately match the exclusive data of the corresponding batch to avoid interference from cross-batch data. Document structures have multiple levels and are dense with specialized terminology. Retrieval must accurately locate fields to match specific parameters, while ensuring recalled data fully covers audit items required by GMP. Data is updated frequently and linked to production progress, so retrieval must support real-time or near-real-time document synchronization. Since errors directly affect batch release, retrieval accuracy and response speed must meet the time requirements of production audits.

## Configuration Settings
The following configurations are based on the official documentation for FastGPT v4.17.0, adapted for the retrieval scenario of pharmaceutical dosage production ledgers.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `similarity` | 0.75–0.85 | Pharmaceutical dosage ledger data fields are precise, requiring a high similarity threshold to filter irrelevant historical batch data and ensure accurate content matching GMP requirements |
| `limit` | Top 10 entries | Single-batch ledger data volume is moderate; limiting the number of recalled entries reduces context stitching load and meets the fast summary needs of production audits |
| `searchMode` | `vector` | For structured production and quality fields, vector retrieval can accurately match specialized terminology and specific parameters, adapting to the retrieval needs of professional documents |
| `usingReRank` | Enabled | Under complex document structures, secondary reranking can improve the recall priority of specialized fields and avoid interference from non-core content on audit judgments |
| `datasetSearchUsingExtensionQuery` | Enabled | Ledger terminology is highly specialized; optimizing retrieval questions to match professional expressions improves recall accuracy |
| `collectionIds` | Bind the exclusive collection ID of the production ledger knowledge base | Isolate documents from different batches and departments, avoid recalling irrelevant data, and ensure the retrieval scope only covers the ledgers of the current audit batch |

## Three Common Misconfigurations
- Issue: Knowledge base retrieval response time exceeds expected limits. Cause: The `limit` parameter was not adjusted, resulting in recall of excessive redundant historical batch data and increased retrieval and context stitching load.
- Issue: Untriggered large model call error logs appear during workflow runtime. Cause: After enabling `datasetSearchUsingExtensionQuery`, the call permissions for the corresponding model were not configured, or unused auxiliary call configurations remained.
- Issue: Uploaded ledger documents automatically have their custom directory structures deleted. Cause: Configuration items that preserve the original document format were not retained, and automatic document structure cleaning rules were enabled, resulting in the removal of specialized directories.

## How to Verify Proper Configuration
- Access the knowledge base management interface and confirm that `collectionIds` only binds document collections related to production ledgers, with no cross-batch or irrelevant document collections.
- Initiate a test retrieval, enter the specialized search terms for the corresponding batch, and verify that the similarity of returned results falls within the 0.75–0.85 range.
- Upload a test batch record document and confirm that the custom directory structure of the document is not automatically deleted after upload.
- Run a test workflow, check that there are no unexpected large model call records in the logs, and confirm that the configuration does not trigger additional model requests.

The values provided here are common starting points and should be measured against the reader's own samples.
