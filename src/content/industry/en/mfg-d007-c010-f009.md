# Production Ledger Summary and Report Generation for Medical Device Assembly and Cleanroom Production: Model Access and Configuration

## What the data for this category looks like
Data for this category comes from design history files, device and material batches, MES systems, clean environment monitoring equipment, sterilization equipment, inspection and calibration systems. Daily documents include production process specifications, batch production records, clean zone records, sterilization batch records, inspection reports, software version records, adverse event and traceability materials. Data is updated per batch or per product, or per the clean environment monitoring plan. Data fields include unique device identifiers, material batch numbers, clean environment parameters, sterilization parameters, inspection results, and more, with unitized identifiers such as dates and batch numbers attached.

## What constraints do these characteristics impose on the model access and configuration workflow
The multi-source, scattered data sources of this category require model access to support cross-system data aggregation, eliminating additional costs from manual organization. The update frequency per batch or plan requires the model context window to accommodate the full volume of ledger data for a single batch, preventing information omission due to insufficient context. Special fields such as unique device identifiers and sterilization parameters require clear specification of data extraction rules during configuration, to avoid generated content that deviates from production compliance requirements. Additionally, the strong association requirement for adverse event and traceability materials requires retaining original data reference fragments, to prevent generation results that cannot be traced.

## How to set the configuration
This configuration is based on FastGPT v4.17.0

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 token` | This category's single-batch ledger includes multiple associated documents, requiring space to hold all input data |
| `maxTokens` | `2000–3000 token` | Ensure complete output of summary reports, avoiding truncation of key content |
| `quoteMaxToken` | `1500 token` | Retain sufficiently long original ledger reference fragments to meet traceability requirements |
| `temperature` | `0.1–0.3` | Reduce randomness of generated content, adapting to the high-precision requirements of medical device production |
| `AIPROXY_API_ENDPOINT` | Fill in according to the deployed proxy service address | Resolve the issue that the platform's built-in model list cannot cover niche or self-developed models |
| `AIPROXY_API_TOKEN` | Fill in according to the key generated by the proxy service | Ensure identity verification security for interface calls |

## Three common configuration mistakes
- The symptom is that some niche or self-developed models cannot be selected in the platform's built-in model list, and an interface not configured error is returned during calling. The cause is that the custom model access address was not configured via the proxy service, and the platform's default model library was relied on directly.
- The symptom is frequent interface call timeouts, with logs returning connection reset or request timeout status codes. The cause is that the `maxContext` and `maxTokens` parameters were not set reasonably, and the single request data volume exceeded the limit threshold of the proxy service.
- The symptom is that the generated report lacks special fields such as unique medical device identifiers and sterilization batch record numbers, with corresponding fields empty. The cause is that the special data fields to be extracted were not clearly specified in the configuration, or the `quoteMaxToken` setting was too small, resulting in truncation of reference fragments.

## How to confirm the configuration is complete
- Input the complete ledger data of a single batch of medical devices, call the generation interface, and check whether the returned report contains all required special business fields.
- View the running logs of the proxy service, confirm that the `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` configurations are correct, and there are no 401, 404, or 500-level errors.
- Adjust the `temperature` parameter to 0.1, generate reports for the same ledger multiple times, and check whether the consistency of the results meets the rigor requirements of production data.
- Test ledger input with ultra-large data volume, confirm that after the `maxContext` and `maxTokens` parameters are set, the request does not experience timeout or content truncation issues.
