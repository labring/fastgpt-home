# Production Ledger Summary and Report Generation for Medical Device Assembly and Cleanroom Production: Deployment and Upgrade

## What data looks like for this category
Data for this category comes from multi-system links of manufacturers of single-use consumables, implantable and interventional devices, and diagnostic equipment. It includes production process specifications, batch production records, cleanroom temperature and humidity records, sterilization batch records, inspection reports, software version logs, adverse event and product traceability materials.
Data sources cover design history files, device and material batch ledgers, MES systems, clean environment monitoring equipment, sterilization equipment, and inspection and calibration systems. Update frequency is once per product batch or device generation. Cleanroom monitoring data syncs on a fixed schedule.
Core fields include unique device identifier, sterilization parameters, clean environment thresholds, and material batch numbers. Some documents must meet traceability requirements.

## What constraints these characteristics impose on deployment and upgrade
The multi-source heterogeneous data, high-frequency update rhythm, and strict traceability requirements of this category impose multiple constraints on deployment.
Connect to data sources with different protocols such as MES, clean environment monitoring, and sterilization equipment. This requires flexible configuration of storage and connection parameters.
High-frequency batch production record writes and queries require adjusting the upper limit of database connections to avoid blocking.
Storage and transmission of sensitive data such as sterilization and cleanroom data require configuration of encryption tokens and permission controls.
Large files such as sterilization records and inspection reports require adapting object storage connection configurations to ensure compliant and efficient data storage and access.

## How to set configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 20–30 connections | Adapts to high-frequency write and query requests for multi-batch ledgers, avoids database connection exhaustion |
| `MONGODB_URI` | Fill in according to the enterprise internal MongoDB cluster or cloud service connection string | Stores bulk unstructured data such as batch production records and traceability materials |
| `REDIS_URL` | Local default connection string for port 6379 | Caches real-time cleanroom monitoring data, reduces overhead from repeated system queries |
| `FILE_TOKEN_KEY` | Generate a 32-bit random string | Encrypts document access tokens related to ledgers, meets medical device data confidentiality and permission control requirements |
| `STORAGE_S3_ENDPOINT` | Fill in according to the enterprise internal object storage address | Stores large files such as sterilization batch records and inspection reports, ensures persistent data storage |

## Three common mistakes
- Ledger summary page access times out, and logs show database connection exhaustion. This occurs because the `DB_MAX_LINK` parameter is not adjusted to accommodate high-frequency batch production record write requests.
- Cleanroom monitoring data fails to sync to the ledger system, returning a 403 status code. This occurs because `FILE_TOKEN_KEY` or `STORAGE_S3_ENDPOINT` is not configured correctly, causing document access permission verification to fail.
- Frontend loads slowly after local deployment, and page elements are misaligned. This occurs because build configurations are not adjusted for older browser versions, and large document resources related to ledgers are not compressed.

## How to confirm configurations are set correctly
- Run a database connection test to verify connectivity for configurations such as `MONGODB_URI` and `REDIS_URL`, and confirm there are no address errors or permission issues.
- Upload a simulated sterilization batch record file, generate an access link via `FILE_TOKEN_KEY`, and verify that the file can be downloaded normally with no permission leaks.
- Initiate a batch ledger summary task, observe the actual usage of database connections, and confirm that the configured `DB_MAX_LINK` upper limit is not reached.
- Access the configured `FE_DOMAIN` domain name, verify that the frontend page can load static resources normally, with no cross-domain or resource loading errors.

The values given are common starting points and should be measured against the reader's own samples.
