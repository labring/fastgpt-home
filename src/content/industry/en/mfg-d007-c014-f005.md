# Production Ledger Summary and Report Generation for Dyeing and Finishing: Tool Calling and Plugins

## What data for this category looks like
Data for this category comes from customer color samples, formula libraries, dye chemical batch records, dye vat control systems, colorimeters, setting machines, and environmental monitoring equipment. Daily documents include dyeing formulas, chemical weighing records, dye vat temperature and pressure curves, proofing confirmation sheets, color difference reports, setting process sheets, sewage discharge ledgers, and more. Data is updated per vat, per batch, or per shift. Fields include dye chemical usage (unit: kilograms), dye vat runtime (unit: minutes), color difference ΔE value, sewage discharge volume (unit: cubic meters), and others. This data is generated through a combination of manual records and automatic device collection.

## What constraints do these characteristics bring to the tool calling and plugins link
This category has high-frequency, fine-grained data updates. Tool calling must support real-time pulling of the latest data for individual vats or batches to avoid using outdated information in summaries. Multiple document formats require plugins to be compatible with different data source interfaces, including direct device interfaces, CSV-format production records, PDF-format quality reports, and more. Data comes from both manual and device channels, so plugins need to support verification and integration of mixed data. In addition, production errors have serious consequences. Results from tool calling must undergo field integrity checks to ensure no missing ledger data. FastGPT v4.17.0 and later versions’ tool calling framework can adapt to these requirements, but configuration must be adjusted based on category characteristics.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | auto | Allows the system to automatically select tools matching the current production scenario, adapting to the summary needs of multiple types of ledger data |
| Tool trigger timing | After each vat completes production, at shift handover | Matches the per-vat, per-batch, per-shift data update frequency, avoiding repeated calls or missed data |
| `functionCall` | forced call | Ensures that the ledger summary tool must be called each time a report is generated, avoiding relying solely on knowledge base retrieval content |
| Data source pull interval | 300 seconds | Balances data timeliness and system load, adapting to the typical cycle of dye vat operation |
| Report generation field limit | Top 15 core fields | Focuses on key information in production ledgers, avoiding redundant content that reduces report readability |
| Report generation character limit | 8000 characters | Adapts to the single-content length limit of FastGPT v4.17.0 |

## Three common misconfigurations
- Symptom: Tool activation status shows as temporary, and it cannot be called across sessions. Cause: Persistent activation parameters for the tool were not configured, and only temporary permissions for a single session were enabled.
- Symptom: Connection errors are returned when calling MCP tools, and real-time dye vat data cannot be obtained. Cause: Access configuration for the SSE protocol was not adapted, and only non-standard access logic was used.
- Symptom: Generated production reports only include historical data from the knowledge base, and do not include the latest colorimeter or dye chemical batch information. Cause: The `toolChoice` parameter was not configured correctly, and call permissions for online or device data pulling tools were not enabled.

## How to confirm the configuration is correct
- Manually trigger a tool call, and check if dye vat curves and color difference report data for the corresponding vat number can be pulled.
- View the tool call log to confirm that the `toolChoice` and `functionCall` parameters have taken effect as configured.
- Generate a complete production ledger report, and check that all core fields are included and the data is the most recently updated content.
- Switch the session environment, test whether the tool can still be called normally, and confirm that the persistent configuration has taken effect.

The values provided here are common starting points and should be measured against the reader's own samples.
