# Dyeing and Finishing Production Ledger Summary and Report Generation: Deployment and Upgrade

## What the data for this category looks like
Data from this category comes from multiple business carriers in the dyeing, setting, laboratory, and quality departments of dyeing and finishing mills. These include dyeing formulas, chemical dosing records, complete dyeing cylinder temperature curves, sample confirmation sheets, color difference reports, setting process sheets, sewage ledgers, and more. Data sources cover customer color samples, formula libraries, dye chemical batch records, dyeing cylinder control systems, colorimeters, setting machines, and environmental monitoring equipment. Update frequency is per cylinder, per batch, or per shift. Each data entry includes fields such as dyeing cylinder number, chemical batch number, process parameters, color difference detection values, and discharge concentration. Associated units include ℃, mg/L, batch numbers, and others.

## Constraints on deployment and upgrade from these characteristics
The high-frequency updates, multi-source heterogeneous, and long-text data traits of this category create clear constraints for deployment and upgrade. Real-time data updates per cylinder and per batch require stable database connections to prevent data write failures caused by insufficient connections. Long-text dyeing cylinder curves and report requirements with combined multiple parameters demand that the large model’s context window can hold complete input data. Heterogeneous data collected from multiple devices needs compatible storage configurations to ensure all document types can be uploaded and read normally. Production ledger data also involves process and environmental protection information, so deployment must meet protocol security requirements, and upgrade must ensure uninterrupted synchronization of business data.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–150` | Adapts to high-frequency data write and query requirements per cylinder and per batch, avoiding database connection pool exhaustion |
| `MONGODB_URI` | Exclusive instance address with read-write separation configuration | Stores multi-source heterogeneous dyeing and finishing ledger data, reducing query blocking probability via read-write separation |
| `REDIS_URL` | `600-second expiration cache configuration` | Caches static data frequently accessed such as dye chemical batches and standard formulas, reducing repeated database query pressure |
| `FE_DOMAIN` | Enterprise-filed HTTPS domain name | Meets protocol requirements for application release, avoiding cross-domain or protocol incompatibility issues with front-end functions such as voice features |
| `STORAGE_S3_ENDPOINT` | Intranet address of local object storage service | Stores large-volume documents such as dyeing cylinder curves and color difference reports, with intranet transmission ensuring data stability and speed |
| `FILE_TOKEN_KEY` | `32-bit random string` | Generates secure file access tokens to prevent unauthorized personnel from accessing sensitive production ledger documents |

## Three common errors
- Phenomenon: When generating dyeing reports, analysis results for complete dyeing cylinder curves deviate from actual parameters, with off-topic responses appearing. Cause: Context loading configuration was not adjusted for long-text data, so the large model cannot fully retrieve all parameters of the dyeing cylinder curve.
- Phenomenon: After application release, the voice function cannot trigger normally, and the interface returns protocol incompatibility or cross-domain errors. Cause: `FE_DOMAIN` was not set to the enterprise-filed HTTPS domain name, leading to inconsistent protocols between the front-end and back-end interfaces.
- Phenomenon: After upgrading the version, importing the old-version workflow fails, and the system prompts that the application format is incompatible. Cause: The format compatible with the current version was not selected when exporting the workflow in the old version, or basic configurations relied on by the workflow were not updated synchronously after the upgrade.

## How to confirm configurations are properly set
- Log in to the FastGPT backend, check the `DB_MAX_LINK` and `MONGODB_URI` configuration items, and verify read-write permissions and connection stability using the built-in database connectivity test tool.
- Access the domain name configured in `FE_DOMAIN`, confirm the page loads normally and uses the HTTPS protocol, and test whether the voice function trigger process operates correctly.
- Upload a complete dyeing cylinder curve document, trigger the ledger report generation task, and verify the matching degree between the generated results and input data.
- Export the old-version workflow and import it into the current system, confirm the import process has no errors, and that workflow nodes can be edited and run normally.

The configurations on this page apply to FastGPT v4.17.0. Confirm that the current running version matches via the backend version query function.
