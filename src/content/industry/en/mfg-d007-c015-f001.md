# Production Ledger Summary and Report Generation for Active Pharmaceutical Ingredient and Pharmaceutical Intermediate Manufacturing: HTTP Interfaces and External Systems

## What this category's data looks like
Data for this category comes from registered process documents, raw material batch ledgers, DCS control systems, weighing systems, LIMS systems, chromatography data systems, and QMS quality management systems. Data is updated per production batch and each process step, covering batch production records, material balance sheets, reaction and purification process records, cleaning validation records, impurity profile reports, deviation and change documents. Core fields include batch identifier, reaction temperature, feeding quantity, yield value, impurity concentration, solvent residue amount, and deviation level. Field units include degrees Celsius, kilograms, milligrams per liter, hours, and others.

## What constraints do these characteristics impose on HTTP interfaces and external systems
The multi-source, heterogeneous data sources of this category require HTTP interfaces to support integration with various external systems, and require compatibility with field formats and units returned by different systems. Following the update rhythm per batch and per step, interface calls must match the time nodes of production processes to avoid frequent calls that occupy system resources. Due to compliance requirements for pharmaceutical production data, the interface must carry strict authentication information via the `Authorization` parameter to prevent unauthorized access. The unit and format constraints of core fields require the interface to perform format verification when receiving and returning data, to avoid incorrect data entering the ledger summary process.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `Authorization` | Bearer Token, valid for 1 hour | Matches the high sensitivity requirements of pharmaceutical production data; short validity period reduces unauthorized access risks |
| Batch Request Limit | Top 3 production batches | Single batch data volume is large; limiting the quantity avoids interface timeouts or returned data overload |
| `responseData` | JSON structure containing batch identifier, core fields, and source system identifier | Facilitates external ledger systems to parse and summarize production data |
| Timeout Period | 600 seconds | Multi-source data pulling requires waiting for responses from multiple external systems; longer timeout period prevents mid-request interruptions |
| `variables` | Pass the start and end time interval of the current production batch | Accurately pull process data for the corresponding time period, reducing invalid returned data |
| Field Format Verification | Enabled | Adapts to the unit and format constraints of pharmaceutical data, intercepting non-compliant field values in advance |

## Three Common Errors
- Symptom: The configured HTTP interface returns a 504 gateway timeout error. Cause: The timeout period was not adjusted to match the duration of multi-source data pulling; the default timeout period is insufficient to cover response delays from multiple external systems.
- Symptom: The `responseData` returns an empty impurity concentration field. Cause: The correct batch identifier was not passed in `variables`, causing the interface to fail to match impurity data from the corresponding system.
- Symptom: Attempting to connect to a specified database via the HTTP interface prompts a connection failure, and connection information is confirmed to be correct. Cause: Correct network access rules were not configured, causing the interface to fail to establish a stable connection with the database.

## How to Confirm Proper Configuration
- The configured HTTP interface is invoked with the test production batch time interval passed, and the `responseData` returned fields are checked to confirm inclusion of core content such as batch identifier, feeding quantity, and impurity concentration.
- Interface call logs are reviewed to confirm that each request carries valid `Authorization` authentication information, with no errors related to unauthorized access.
- A full-process data pull for a single production batch is simulated, and the interface response duration is checked to confirm it does not exceed the preset 600-second timeout period.
- Returned data units are verified, confirming that the impurity concentration unit is milligrams per liter and the reaction temperature unit is degrees Celsius, which meet the format requirements of this category's data.
