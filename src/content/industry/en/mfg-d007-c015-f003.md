# Production Ledger Summary and Report Generation for Active Pharmaceutical Ingredient and Pharmaceutical Intermediate Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Production data for this category comes from registered process documents, raw material batch ledgers, DCS control systems, weighing systems, LIMS laboratory information management systems, chromatography data systems, and QMS quality management systems. Daily generated documents include batch production records, material balance sheets, reaction and purification step records, cleaning validation records, impurity profile reports, deviation and change documents. Data updates per batch and per production step. Fields include batch unique identifiers, reaction temperatures, feeding amounts, yield calculation values, impurity detection items, material balance data, and more. Individual document lengths vary based on production step complexity, with no unified fixed value.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Engineering
Multi-source heterogeneous data sources require dialogue context to be strongly bound to a single batch. This prevents mixing ledger data from different batches. Step-wise updated production rhythms require multi-turn dialogue to guide users to provide documents for corresponding steps gradually. Full input all at once is not suitable. Long, specialized document content requires prompts to explicitly limit usage to only the current batch’s ledger data. Prompts must also standardize definitions for specialized terms such as impurity profile and material balance. This ensures accurate model output. In scenarios with parallel batch processing, dialogue identifiers must isolate context between different batches. This prevents cross-data contamination.

## How to Configure Settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique identifier of the current production batch | Ensure dialogue context is strongly tied to a single batch, avoid cross-batch data confusion, and align with FastGPT v4.17.0 context isolation logic |
| `messages` | Concatenate core ledger snippets in the order of production steps | Match the business workflow of API manufacturing, which progresses through reaction, purification, and other steps, and reduce interference from irrelevant data |
| `variables` | Inject batch number, raw material batch, registered process version | Enable prompts to accurately call exclusive data for the current batch, improving the accuracy of report generation |
| Maximum context length | 800–1200 characters | Core ledger step data for a single batch typically falls within this range, and aligns with model processing capabilities |
| Single file upload limit | 5 individual files, each no larger than 200 MB | Aligns with common file size limits for API manufacturing ledgers, and avoids excessive interface load |
| Question optimization switch | Enabled | For ledger data with many specialized terms, optimize the accuracy of professional wording in prompts |

## Three Common Mistakes
- When debugging long-text ledger summary tasks, the interface shows the task completed normally but throws an error stating "The value of 'offset' is out of range". This occurs when concatenating multiple ledger data segments, with offset calculations exceeding the model’s supported context boundary. Reasonable segmentation of long documents is not implemented.
- Dependencies must be reinstalled each time the dialogue virtual machine starts. This happens when dependencies are not configured to a persistent storage directory. The deployment image also does not preinstall required ledger parsing dependencies.
- When calling the dialogue interface to upload multiple production ledger files, the interface returns no valid results. This occurs when file type and content references are not nested according to the content array format of the `messages` parameter. This leads to parameter parsing failure.

## How to Verify Configurations Are Correct
- Input a ledger snippet from a known batch. Check if the summary data returned by the dialogue only includes fields from that batch, with no irrelevant content from other batches.
- Upload multiple production ledger files. Call the dialogue interface, then check if the returned results associate core data from all uploaded files.
- Review deployment logs. Confirm that the logic for binding the `chatId` to the batch ID has taken effect. Check for no errors related to cross-batch context leakage.
- Test long-text ledger input. Confirm that no offset-related errors appear. Check that the returned report includes preset core fields such as yield and impurities.

The values provided here are common starting points, and should be evaluated against the reader’s own samples.
