# Production Ledger Summary and Report Generation for Active Pharmaceutical Ingredient and Pharmaceutical Intermediate Manufacturing: Tool Calling and Plugins

## What data for this category looks like
Data sources for this category include registered process documents, raw material batch ledgers, DCS control systems, weighing systems, LIMS laboratory information management systems, chromatography data systems, and QMS quality management systems.
Daily generated documents cover batch production records, material balance sheets, reaction and purification process records, cleaning validation records, impurity profile reports, and deviation and change management documents.
Data updates follow the rhythm of each production batch and each process step. Core fields include batch number, process sequence number, reaction temperature, feeding amount, yield value, impurity content, solvent residue amount, and change association number.
Data is archived on demand, with no fixed real-time push schedule.

## Constraints on tool calling and plugins workflow
Multi-system data sources require tool calling to use plugins adapted to different interface formats. These plugins pull corresponding data from systems including DCS and LIMS.
Update rhythms tied to batches and process steps require tool triggering logic to bind to production batches and process nodes. Full historical data pulls are not used.
Diverse document types require plugins to support parsing archived files in multiple formats, such as batch production records and impurity profile reports.
Core fields are strongly bound to registered processes. Tool calling must retain field association relationships to avoid data misalignment.
Data anomalies can trigger compliance risks. Plugin failure retry and data verification logic must be configured.

## Configuration settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | This category requires calling multi-system plugins. Auto mode can match corresponding tools on demand, avoiding missing necessary production data interfaces |
| `functionCall` | `enabled` | Tool calling must be forced to pull multi-source ledger data. This ensures report generation relies on real production process data |
| Plugin call timeout | `300–600 seconds` | Multi-system data pulling requires cross-module interaction. Sufficient time must be reserved for cross-system data synchronization |
| Tool call retry count | `2 times` | Occasional network fluctuations occur when pulling production data. Retries reduce failure probability and avoid interrupting the ledger summary workflow |
| Plugin format verification switch | Enabled | Data fields for this category are strongly bound to registered processes. Format verification prevents report distortion caused by data misalignment |
| Trigger timing setting | Trigger upon completion of process nodes | Data updates follow process step rhythms. Binding to process nodes ensures timeliness and accuracy of summary data |

## Three common configuration errors
- Symptom: The "Missing tool calling parameters" error is returned when calling the OpenApi interface. Cause: The `functionCall` configuration is not set to enabled. Tool calling logic is not triggered, and the interface return result does not include necessary fields for multi-source ledger data.
- Symptom: Impurity profile data fields returned by tool calling are empty. Cause: The `toolChoice` configuration is not set to auto mode. The plugin interface for the chromatography data system is not matched, so detection data for the corresponding process cannot be pulled.
- Symptom: Production ledger summary results are not displayed in segments by process step. Cause: Trigger timing is set to full data pull. Production batches and process nodes are not bound, leading to chaotic data summary workflow.

## How to confirm correct configuration
- Call the test interface. Check if the return result includes core fields such as batch number, reaction temperature, and impurity content. Confirm whether tool calling has pulled data from the corresponding systems.
- Simulate an incomplete process node. Check whether tool calling is not triggered. Confirm that trigger timing is correctly bound to completed process nodes.
- View plugin call logs. Confirm that the `toolChoice` and `functionCall` configuration parameters have taken effect, with no format errors.
- Simulate a network fluctuation scenario. Check whether the tool performs retries according to the configured retry count. Confirm that the failure handling logic operates normally.

The values provided are common starting points, and should be evaluated against the reader's own samples.
