# Production Ledger Summarization and Report Generation for Spraying and Coating: Vector Models and Indexes

## What Data for This Category Looks Like
Spraying and coating scenario production data sources include coating supplier TDS/SDS documents, real-time collected data from spray booths and ovens, test reports from colorimeters and film thickness gauges, environmental monitoring records, and MES system ledgers.
Daily generated documents include coating process cards, coating batch sheets, paint mixing records, film thickness and color difference reports, oven curves, defect repair orders, and VOCs ledgers.
Data update cadence follows these patterns: Batch sheets are updated for each coating batch. Paint mixing and repair records are generated per shift. Spray booth and oven data is collected continuously. VOCs ledgers are summarized daily.
Document fields include coating batch number, film thickness value, color difference ΔE value, oven temperature, VOCs concentration, and others. Some documents include time-series curves or image attachments.

## Constraints for Vector Models and Indexes
Multi-source mixed data types (text, numerical values, time-series curves, images) require vector models to support embedding logic for unstructured and semi-structured data.
Frequently updated continuously collected data requires indexes to support incremental construction and rapid synchronization, to avoid performance losses from full reconstruction.
Cross-process business association requirements (such as matching pre-treatment, spraying, and curing windows) require sufficient contextual association to be retained during chunking, to prevent key process information from being split.
Strict compliance and quality requirements require index recall accuracy to meet retrieval needs for defect analysis and VOCs management, to avoid low-correlation data interfering with summarization results.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Spraying-related documents include process parameters, time-series curves, and associated records. Excessively long chunks split local details, while excessively short chunks fail to cover complete process context |
| Overlap Length | 100–150 characters | Prevents cross-document associated content such as oven curves and defect repair orders from being broken by chunking, ensuring vector indexes can match front and back process data |
| Similarity Threshold | 0.72–0.85 | Filters low-correlation production ledger data, ensuring retrieval results only cover valid content matching coating processes and batch requirements |
| `maxToken` | 8192 | Meets embedding requirements for long texts such as coating process cards and oven curves, ensuring complete context is correctly encoded |
| Single Search Limit | Top 10 entries | Balances recall efficiency and coverage, meeting matching needs for multi-source data during production ledger summarization |
| Maximum Context | 600 seconds | Retains a reasonable time association range when matching continuously collected real-time spray booth and oven data |

## Three Common Mistakes
- Phenomenon: No progress is shown after switching the knowledge base vector model, and switching back is not possible. The interface returns a 404 status code. Cause: The field format of multi-source data for spraying scenarios is not adapted. An interface mapping exception is triggered during index construction, causing the task to stall.
- Phenomenon: Indexes are not synchronized after uploading updated oven curve screenshots or film thickness report images. Cause: The incremental index trigger switch for FastGPT v4.17.0 is not enabled. Only manual full updates can synchronize image documents.
- Phenomenon: Associated paint mixing records and process cards are not recalled when searching for defect repair orders. Cause: Chunk length is set too small. Association information between repair orders and associated documents is split into different chunks, leading to loss of contextual association during vector matching.

## How to Verify Proper Configuration
- Upload a single coating process card to trigger index construction. Check console logs to confirm there are no field parsing errors or embedding failure prompts.
- Enter a search term containing a specific batch number and detection indicator. Verify that search results include associated documents such as paint mixing records and film thickness reports for the corresponding batch, and that similarity values fall within the preset range.
- Attempt to switch the vector model. Confirm that the interface can save configurations normally, and that index construction tasks start normally without abnormal error reports.
- Upload an updated VOCs ledger document. Verify that the latest version of the document can be retrieved from the index.

The values provided are common starting points and should be measured against samples relevant to the specific deployment scenario.
