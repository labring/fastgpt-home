# Coating and Painting Production Ledger Summary and Report Generation: Deployment and Upgrade

All configurations on this page are based on FastGPT v4.17.0.

## What the data for this category looks like
This category covers multi-source records across the entire coating workflow. Sources include coating supplier TDS/SDS documents, real-time collected data from spray booths and ovens, test results from colorimeters and film thickness gauges, environmental monitoring data, and MES system logs. Daily documents include coating process cards, coating batch sheets, paint mixing records, film thickness and color difference reports, oven curves, defect repair orders, and VOCs ledgers. Data update frequencies cover each coating batch, each shift production node, and full-process continuous collection. Core document fields include coating batch number, viscosity parameters, oven temperature range, film thickness value, VOCs concentration, defect type, and other key information.

## What constraints these characteristics impose on the deployment and upgrade phase
Multi-source heterogeneous data sources require the deployment phase to adapt to different document import formats and structured parsing. Continuous collected real-time data requires deployed storage and computing resources to support high-frequency writes. Differences in fields across documents require presetting multiple sets of field mapping rules during configuration, to adapt to the structure of different documents such as coating process cards and paint mixing records. Compliance requirements for VOCs ledgers require the data link to retain complete audit trails. During the upgrade process, ensure that data migration does not lose the traceability of historical ledgers. Window matching and defect analysis in the coating workflow rely on accurate time-series data. Sufficient space for time-series index configuration must be reserved during deployment to ensure data query efficiency.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–150 connections` | Adapts to multi-source system access requirements in coating scenarios, supports simultaneous connection to multiple databases including MES, colorimeters, and oven data systems |
| `MONGODB_URI` | 3-node cluster address with read-write separation suffix | Meets high-frequency data read-write requirements for continuous collection, adapts to real-time data write rhythms for each shift and each batch |
| `REDIS_URL` | `600-second` expiration cache configuration | Caches temporary information such as paint mixing records and film thickness test data, avoids repeated reading of historical data from offline devices |
| `STORAGE_S3_ENDPOINT` | S3-compatible local storage endpoint | Stores large-capacity documents such as coating process cards and oven curves, reduces latency caused by cross-cloud transmission |
| `FILE_TOKEN_KEY` | `7-day` expiration configuration | Generates temporary access tokens for coating documents, ensures access security for sensitive ledgers |
| Document field mapping rules | Preset coating industry standard templates | Adapts to the fixed field structure of coating documents, reduces the workload of manual configuration mapping |

## Three common mistakes
- Symptom: After deployment, the container cannot recognize the GPU, and a memory overflow error is reported. Cause: The GPU device is not mounted in the Docker startup command, and the version of pdf-marker:v0.1 is incompatible with the CUDA 12.8 driver.
- Symptom: A 404 not found error occurs when accessing FastGPT after Nginx reverse proxy. Cause: The Nginx location path and FastGPT container port mapping are not correctly configured, or the correct request header forwarding configuration is not added.
- Symptom: Page resource loading fails after Vercel automated deployment. Cause: The `FE_DOMAIN` parameter is not correctly configured, causing front-end resource path matching errors.

## How to confirm the configuration is complete
- Run the database connection test script to verify that the cluster configured with `MONGODB_URI` can normally read and write coating-related ledger data.
- Upload a coating process card and paint mixing record, check whether the system automatically recognizes document fields and completes structured parsing.
- View the system logs to confirm that there are no error messages about failed GPU resource allocation or memory overflow.
- Access the configured `FE_DOMAIN` address, verify that the front-end page loads normally and there are no resource 404 errors.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
