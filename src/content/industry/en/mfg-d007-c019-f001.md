# Production Ledger Summary and Report Generation for Plastic Injection Molding: HTTP Interfaces and External Systems

## What data for this category looks like
Data for this category covers daily production documents including injection molding process cards, raw material drying records, mold histories, first-piece inspections, patrol inspection forms, material change and machine cleaning records. Data sources include resin batches and property sheets, injection molding machine operating parameters, mold temperature controller data, MES systems, and dimensional and appearance inspection results. Updates are triggered per production batch, each mold or material change, and each shift handover. Data fields include resin batch numbers, injection pressure, mold temperature, drying duration, and detected dimensional tolerance values, and are updated in real time or on a scheduled basis across production stages.

## Constraints imposed on HTTP interfaces and external systems by these characteristics
This category’s data has high update frequency and scattered trigger timing, requiring HTTP interfaces to support high-frequency calls and on-demand request patterns. Multi-source heterogeneous data comes from different systems such as injection molding machines, mold temperature controllers, and MES systems, requiring interfaces to support multi-format data reception and unified format verification. Single-batch data includes multiple related fields such as resin batches, process parameters, and inspection results, requiring interfaces to support batch data submission and field integrity verification. Data changes frequently in scenarios such as mold and material changes, requiring interfaces to dynamically adapt to different data field sets. Production abnormalities have serious consequences, requiring interfaces to have failure retry and abnormal status return mechanisms.

## How to set configurations
All configuration items below are compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Bearer ${custom API key} | Follow HTTP interface authentication specifications to ensure access security for production data transmission |
| Maximum number of data entries per call | Top 100 entries | Adapt to the conventional data volume of a single batch of injection molding production to avoid interface timeouts |
| `responseData` field verification rules | Include resin batch number, injection pressure, and mold temperature as required fields | Ensure the integrity of core production ledger data and prevent invalid data from being stored |
| Interface timeout period | 30 seconds | Adapt to the conventional delay range of injection molding equipment data uploads, balancing response efficiency and data reception reliability |
| `variables` binding parameters | Bind workshop ID and production line ID | Achieve isolation of production data across multiple workshops and production lines, facilitating classified summary |
| Number of failure retries | 2 times | Offset temporary call failures caused by network fluctuations and ensure data submission success rate |

## Three common configuration mistakes
- Phenomenon: The interface returns a 401 Unauthorized status code, or the interface cannot receive production data. Cause: The `Authorization` parameter is not configured correctly, or the API key has insufficient permissions to access the FastGPT ledger summary interface.
- Phenomenon: The interface returns an exception prompt with empty fields, or the summary report lacks core process data. Cause: The required field verification rule for `responseData` is not set, causing invalid data to be submitted and unable to generate valid ledgers.
- Phenomenon: No response is received for a long time after calling the interface, or a system timeout alarm is triggered. Cause: The number of data entries set per call is too high, exceeding the interface’s carrying capacity, or a reasonable timeout period is not configured.

## How to confirm the configuration is complete
- Call the interface to submit a simulated injection molding batch data set that includes resin batch number, injection pressure, and mold temperature, and check whether the verification results returned in `responseData` meet the configured required field requirements.
- View the FastGPT system log to confirm that the `Authorization` authentication information of the interface call is correctly parsed, with no authentication failure errors.
- Submit multiple sets of simulated data bound to different workshop IDs, and confirm that the parameters bound by `variables` take effect and the data is stored correctly classified.
- Simulate a temporary network interruption to trigger an interface call failure, and confirm that the system executes the failure retry mechanism and the data is submitted normally after retries.
