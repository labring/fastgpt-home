# Production Ledger Summarization and Report Generation for Plastic Injection Molding: Deployment and Upgrade

## What the Data for This Category Looks Like
Plastic injection molding production ledger data covers multi-source inputs: resin batches and property sheets, real-time injection molding machine parameters, mold temperature controller data, workshop MES systems, dimensional and appearance quality inspection records. Daily archived documents include injection molding process cards, raw material drying records, mold histories, first-piece inspection sheets, team patrol logs, and material change and machine cleaning records. Data is updated per production batch, mold change or material change event, and per shift. Fields include resin batch number, drying temperature and duration, holding pressure, mold temperature, patrol pass rate, mold usage count, and more. Units include degrees Celsius, megapascals, hours, piece counts, and others.

## What Constraints These Characteristics Impose on Deployment and Upgrade
The data for this category is multi-sourced and updated at high frequency, requiring the deployment phase to support high-concurrency database connections and multi-format file parsing. Differences in fields across multiple document types require the configuration phase to support custom field mapping rules. Data is linked to production batches and mold change events, so batch IDs from different sources must be aligned to avoid association errors during ledger generation. Additionally, data involves critical information such as raw material ratios and mold status, so strict data validation logic must be configured during deployment to prevent missed detection of risks like mixed materials or mold damage.

## Configuration Specifications
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://localhost:27017/injection_molding` | Stores unstructured real-time injection molding machine parameters, patrol records, and batch ledgers, enabling flexible storage of multi-source data |
| `DB_MAX_LINK` | `200–300` | Handles database write requests from multiple concurrent batches and frequent mold changes per shift, calibrated based on actual testing |
| `REDIS_URL` | `redis://localhost:6379/0` | Caches frequently accessed mold histories, process card templates, and resin property sheets to reduce load on the primary database |
| `STORAGE_S3_ENDPOINT` | `http://minio.example.com:9000` | Stores large files including batch quality inspection photos and raw material property sheet PDFs, enabling unified storage of multi-format documents |
| `ROOT_KEY` | `Randomly generated 32-character string` | Secures access to backend management interfaces and prevents unauthorized configuration modifications |
| `FE_DOMAIN` | `https://injection-molding.example.com` | Configures the frontend access domain name to ensure normal loading of ledger lists and report previews on frontend pages |

## Three Common Misconfigurations
- Issue: After calling the ledger summarization interface, the frontend page remains unresponsive for a long time, and backend logs show database connection exhaustion. Cause: No reasonable upper limit configured for `DB_MAX_LINK`, leading to connection limit being exceeded during multi-batch concurrent writes, preventing subsequent requests from being processed.
- Issue: The interface displays `Invalid URL (POST /v1/rerank)` and cannot generate analysis reports for quality inspection results. Cause: `STORAGE_S3_ENDPOINT` is not correctly configured to point to the quality inspection data storage address, causing the reranking function to fail to obtain quality inspection image metadata and complete analysis.
- Issue: After importing raw material drying records, the drying duration field in the ledger is empty, making it impossible to generate statistical reports for drying processes. Cause: Field mapping between the original raw material drying record fields and system ledger fields was not aligned during configuration, leading to data parsing failure.

## How to Verify Successful Configuration
- Use the database monitoring panel included with FastGPT v4.17.0 to perform a bulk import of injection molding process cards and raw material records for 10 consecutive production batches. Check that database connection counts fall within the range specified by `DB_MAX_LINK` with no connection limit exceeded errors.
- Call the ledger summarization interface, verify that mold histories and quality inspection data can be pulled normally, and that a complete report is generated with no missing fields or format error prompts.
- Access the frontend domain configured in `FE_DOMAIN`, confirm that the ledger list and report preview load normally with no timeout or resource loading failure prompts.
- Attempt to access the backend management interface using an unauthorized key, confirm that a 401 Unauthorized status code is returned to verify the security of the `ROOT_KEY` configuration.

The values provided are common starting points and should be measured against the user's own samples.
