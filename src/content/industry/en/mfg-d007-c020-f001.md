# Production Ledger Summary and Report Generation for Safety, Environmental Protection and Special Work Management: HTTP Interfaces and External Systems

## What data looks like for this category
This category’s data comes from regulatory standards, online environmental monitoring equipment, gas detectors, personnel qualification files, equipment isolation lists, and supervision platforms. Daily documents include risk identification records, work tickets for hot work, confined space work, lifting work and similar tasks, monitoring records, hazardous waste ledgers, emission monitoring data, and accident and hidden danger rectification reports. Data is updated after each work is completed, in real time, per monitoring cycle requirements, or after regular inspections. Document fields include work type, work time, guardian qualification, isolation points, hazardous waste output, emission concentration, and additional relevant fields. Units include hours, cubic meters, tons, milligrams per cubic meter, and other standard units.

## Constraints for HTTP Interfaces and External Systems
Because data sources cover multiple types of equipment and systems, interfaces must adapt to different authentication rules and data formats. Different update cycles require interfaces to support both scheduled polling and real-time push invocation modes. Core document fields have clear business meanings and are numerous, so interface returned data must map accurately to ledger fields to prevent redundant information from disrupting summarization. Work-related data has strict timeliness requirements, so interface invocations must align with data update time windows. Errors may result in personal safety risks and compliance penalties, so a complete failure handling mechanism must be configured.

## Configuration Settings
This page’s configuration applies to FastGPT v4.17.0

| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| Authentication Configuration | Configure based on external system type: supervision platforms use the `Bearer ${token}` format, internal device interfaces use custom authentication strings | External data sources for this category are diverse, with differing authentication rules |
| Global Variable Mapping | Configure `variables` such as work type, monitoring cycle, hazardous waste category, etc., to cover different work scenarios | Ledger summarization requires classified statistics by work type and monitoring cycle |
| Return Data Filtering | Map core fields such as work ticket ID, emission concentration, and rectification status via `responseData` to filter redundant data | There are a limited number of core business fields, requiring precise extraction for ledger generation |
| Interface Call Timeout | 60-120 seconds | Matches the timeliness requirements of real-time monitoring data and work data |
| Failure Retry Count | 2-3 times | Prevents task failure caused by temporary network fluctuations |
| Alert Trigger Threshold | 3 consecutive failed calls | Errors in this category have severe consequences, requiring timely notification of relevant personnel |

## Three Common Configuration Mistakes
- Phenomenon: A 401 Unauthorized error is returned when calling an external supervision platform interface. Cause: Authentication parameters are not configured correctly, and the default automatically added Bearer token does not match the authentication format required by the platform.
- Phenomenon: Work ticket-related fields are empty in ledger summary results. Cause: Core fields are not specified using `responseData` mapping, so redundant data returned by the interface is not correctly extracted.
- Phenomenon: Scheduled calls to environmental monitoring interfaces time out, causing task interruption. Cause: The interface call timeout setting is too short, and does not match the response delay of the external monitoring system.

## How to Confirm Successful Configuration
- Call the test interface, and check if the returned `responseData` includes preset core fields such as work ticket ID, emission concentration, and hazardous waste output.
- Review interface call logs to confirm that the authentication parameter format matches the requirements of the external system, with no incorrectly auto-added formats.
- Simulate two consecutive failed calls, and check if the preset alert action is triggered.
- Compare manually entered single work ledger data with data synchronized via the interface, to confirm that field mapping is accurate.

The values given are common starting points and should be measured against the reader's own samples.
