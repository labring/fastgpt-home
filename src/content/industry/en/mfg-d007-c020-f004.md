# Production Ledger Summary and Report Generation for Safety, Environmental Protection and Special Operation Management: Workflow Orchestration

## What data for this category includes
Data for this category comes from daily operations and monitoring outputs from manufacturing enterprise EHS departments and maintenance teams. It includes documents such as risk identification records, work permits for hot work, confined space work and other operations, hazardous waste ledgers, emission monitoring data, and hidden danger rectification reports.
Data sources cover regulatory standards, online environmental monitoring equipment, gas detectors, personnel qualification files, equipment isolation lists, and supervision platforms.
Data updates are triggered upon completion of individual operations, real-time monitoring requirements, or regular inspections.
Document fields include operation number, operation type, monitoring value, responsible person qualification number, rectification closed-loop status, and other items. There are no unified fixed units; values vary based on monitoring items and operation types.

## Constraints on workflow orchestration
The scattered data sources and differing update rhythms of this category impose multiple constraints on workflow orchestration.
Multiple types of data sources require cross-system pull nodes to be configured, to adapt to different data entry points such as regulatory standards, monitoring equipment, and qualification files.
Different update frequency requirements require trigger rules to distinguish between individual operation triggers, real-time polling, or scheduled synchronization, to avoid data lag or redundancy.
Document fields have no unified format, so field mapping nodes must be configured to adapt to field differences across documents such as work permits and monitoring records.
High-risk attributes require verification links to be embedded in the workflow, to check key information such as qualifications and isolation status, and ensure compliance.

## Configuration guidelines
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
|---|---|---|
| `variables` | Structured variable group including operation ID, monitoring threshold, and compliance threshold. Use 10–20 custom fields, calibrated based on actual testing | Adapt to field differences across different operation types, simplify subsequent field mapping for ledger summary |
| Node Trigger Rules | Trigger ledger summary upon operation completion node, trigger abnormal alerts upon real-time monitoring data, trigger batch summary at scheduled intervals (15 minutes/hour) | Match data update frequency, ensure timeliness of ledger data |
| Field Mapping Node | Automatically match common fields of work permits and monitoring records, manually map exclusive fields | Resolve the issue of inconsistent document fields, cover different types of operation and monitoring data |
| Verification Node Configuration | Verify personnel qualification validity (30-day early warning), equipment isolation status (required field), and monitoring value compliance | Avoid compliance oversights in high-risk operations, meet safety and environmental management requirements |
| `nodeId` | Assign unique identifiers to each data source node, verification node, and summary node. Use UUID format strings, calibrated based on actual testing | Facilitate workflow debugging and branch link management, support reuse of cross-branch nodes |

## Three common configuration errors
- Issue: Workflow links cannot reuse form fill nodes across branches, with a status code returning "node is already occupied". Cause: Unique identifiers for `nodeId` were not configured correctly, leading to node conflicts during cross-branch calls.
- Issue: The responsible person qualification number field is empty in ledger summary results, with logs showing that variables failed to load correctly. Cause: Mapping rules for responsible person identifiers were not configured in `variables`, causing nodes to fail to read corresponding data.
- Issue: Scheduled ledger generation tasks time out, with task status stuck at "running". Cause: No reasonable timeout threshold was set, and no abnormal retry nodes were configured, causing long-running tasks to occupy resources.

## How to verify a complete configuration
- Manually trigger the workflow for a single operation, check whether the output ledger documents include required fields such as operation number, monitoring data, and responsible person.
- Use the `variables` variable debugging tool to confirm that the custom field group can be passed normally between each node in the workflow.
- Configure cross-branch call nodes, verify that form fill nodes can be reused by multiple branch links without conflict errors.
- Trigger a scheduled synchronization task, check whether the generated report includes the latest monitoring data and operation records.

The values given are common starting points and should be measured against the reader's own samples.
