# Production Ledger Summary and Report Generation for Safety, Environmental Protection and Special Operations Management: Tool Calling and Plugins

## What data for this category looks like
Data for this category comes from regulatory standard libraries, online environmental monitoring equipment, gas detectors, personnel qualification files, equipment isolation lists, and supervision platforms. Daily documents include risk identification records, work tickets such as hot work, confined space work, and lifting work, environmental monitoring records, hazardous waste ledgers, emission monitoring data, and accident and hidden danger rectification reports.
Data updates are triggered upon completion of individual operations, real-time monitoring results, or regular inspection cycles. Fields include operation type, operation period, personnel qualification number, monitoring value, rectification closed-loop status, and some values have clear units. For example, hazardous waste generation is measured in tons, and emission concentration in mg/m³.

## What constraints these characteristics impose on tool calling and plugins
Data for this category comes from dispersed sources, covering multiple independent systems and equipment. Tool calling must adapt to the interface formats and permission rules of different data sources.
Data update cycles vary significantly. Real-time monitoring data requires high-frequency interface calls. Work ledger data needs to trigger synchronization immediately after work is completed. Regular inspection data is pulled at fixed intervals.
Document structures and field formats are diverse. Some documents contain numerical fields with units. Tool calling must retain field units to ensure the accuracy of ledger summary.
Additionally, due to high business decision authority, the correctness of calling results must be strictly verified. Clear retry and alert logic must be configured for failure scenarios.

## Three common configuration mistakes
- Calling the `/api/core/dataset/update` endpoint returns a 500 error, but the interface can be accessed normally from the browser. The cause is that the identity verification parameters for interface calls are not configured, and the session information automatically carried by the browser is not correctly passed during API calls.
- The semantic retrieval tool returns "Connection error". The cause is that the network proxy for tool calling or the access permissions for the target data source are not correctly configured, preventing a stable connection from being established.
- Reading a file fails when calling the Doc2x tool, and a read exception error is returned. The cause is that the correct file reading path is not specified, or the tool is not granted permission to access the corresponding ledger files, resulting in failure to obtain work ticket or monitoring record files.

## How to confirm the configuration is complete
- In the backend configuration interface of FastGPT v4.17.0, initiate a tool call request for a single operation ledger, and check whether the returned result includes the document fields required for this category, such as work tickets and monitoring records.
- Simulate a temporary network interruption scenario, verify that the tool call performs retries according to the configured number of retries, and triggers an alert after retry failure.
- Import test data with units, confirm that the summarized ledger retains the unit information of the original fields, and no separation of values and units occurs.
- Check that the `functionCall` configuration item locks the specified tool list, preventing calls to non-compliant tools.
