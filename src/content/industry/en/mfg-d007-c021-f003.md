# Production Ledger Summary and Report Generation for Furniture and Wood Products Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What data for this category looks like
It typically serves panel furniture, solid wood furniture, custom home goods, and wooden door enterprises. Daily production ledger-related documents include dismantling drawings, nesting lists, edge banding and drilling programs, coating processes, hardware inventory lists, fitting and packaging records. Data usually comes from order design systems, sheet and wood batch records, CNC nesting and drilling equipment, ERP/MES systems, and moisture content testing equipment. Updates occur per order, daily, or per material batch. Document field formats vary across sources, with core fields including panel dimensions, material batch numbers, process parameters, hardware models, and more.

## Constraints imposed by these characteristics on multi-turn dialogue and prompt engineering
Because data sources are scattered and formats are inconsistent, multi-turn dialogue needs to support mapping and unification of fields from different systems to avoid data confusion. Frequently updated ledger content requires the dialogue to pull the latest sheet batches and equipment operation data in real time, so a data validation step must be embedded in the dialogue flow. The strong association between multiple panel documents and custom orders requires prompts to accurately locate the exclusive ledger information of the current order to avoid interference from cross-order data. Additionally, the large number of panels and reliance on on-site spatial dimensions requires multi-turn dialogue to gradually break down requirements, preventing dialogue lag caused by loading too much data at once.

## Configuration settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Context window size | 8000–12000 characters | Adapts to the field length of multiple panel documents, avoiding truncation of critical dimension information in dismantling drawings and nesting lists |
| Single-turn conversation recall limit | First 6 historical messages | Matches the rhythm of production ledger updates per order batch, avoiding accumulation of redundant information from past orders |
| Variable binding rule | Associate `variables` by order ID | Accurately pulls sheet and equipment data for the corresponding batch, avoiding cross-order ledger content confusion |
| Multi-turn dialogue trigger logic | Verify fields sequentially via the `messages` sequence | Gradually cross-check ledger information from dismantling, nesting, and other links, reducing one-time input errors |
| Timeout threshold | 300 seconds | Adapts to the time required to pull CNC equipment data, avoiding dialogue interruption due to data loading delays |
| Prompt binding rule | Bind `chatId` to associate the current order | Ensures each round of dialogue is based on the exclusive context of the current order to generate corresponding reports |

## Three common mistakes
- A 401 No auth credentials found error is returned in dialogue. The cause is that access credentials for the ERP/MES system are not correctly bound to the `variables` parameter, making it impossible to pull production ledger data during the dialogue process.
- Context referenced by the knowledge base includes irrelevant panel data. The cause is that the limit on the number of historical messages recalled per turn is not set, leading to accumulation of ledger information from past orders in multi-turn dialogue that interferes with the current task.
- The generated report lacks fitting and packaging record fields. The cause is that key content from this type of document is not explicitly specified in the prompt, leading to omission of corresponding information during the dialogue process.

## How to confirm configurations are correctly deployed
- Initiate a test dialogue for a single order, enter the specified order ID, and check whether the returned ledger data includes corresponding document content such as dismantling drawings and nesting lists for that order.
- Launch 3 consecutive progressive questions, and check whether the `messages` sequence correctly retains key information from previous dialogue rounds, with no redundancy or truncation.
- Simulate an abnormal credential scenario, verify whether the expected permission error is triggered, and confirm that the binding logic of the `variables` parameter is effective.
- Generate a draft report, check whether required fields such as coating processes and hardware inventory lists are included, and confirm that the prompt's extraction rules are correct.
