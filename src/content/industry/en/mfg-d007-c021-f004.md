# Production Ledger Summary and Report Generation for Furniture and Wood Products Manufacturing: Workflow Orchestration

## What the data for this category looks like
Production data sources for this category include order design systems, sheet material and wood batch ledgers, CNC cutting and drilling equipment logs, ERP/MES systems, and moisture content testing equipment. Data updates follow per individual order, daily production batch, and per material batch. Daily documents include cutting drawings, cutting lists, edge banding and drilling programs, coating process cards, hardware matching lists, and assembly and packaging records. Core fields include panel size (millimeters), sheet moisture content, hardware model, order number, and production batch number. Format and content are flexibly adjusted based on customization requirements.

## What constraints these characteristics impose on workflow orchestration
The custom order-driven production model results in a large number of panels with significant differences. This requires workflows to support batch processing of data by order dimension. The need to associate multi-source production documents requires workflow configuration to allow binding of multiple variable types such as cutting drawings and equipment logs. The high-frequency data update rhythm requires workflows to support real-time or scheduled trigger logic. Panel size deviations can lead to full-order installation failures. This requires adding field validation logic during the ledger summary stage to prevent erroneous data from entering reports. Additionally, customized production processes differ significantly from mixed-line production models for standard home appliances. Workflows must avoid applying fixed parameter configurations from general-purpose categories.

## How to set up the configuration

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Variable Reference | Bind three core documents: cutting drawings, cutting lists, and hardware lists | Production documents for this category use these three core files as the basis for ledger summary |
| `variables` | Pass parameters grouped by order ID | Avoid parameter conflicts for panel data across different orders, and adapt to customized production scenarios |
| Timeout Setting | 600–1200 seconds | Single-order ledger summary processes dozens to hundreds of panel data pieces, so sufficient execution time is reserved |
| Batch Execution Node | Process no more than 50 panel data entries per execution | Balance execution efficiency and interface load, and adapt to panel batch processing needs for this category |
| Temperature Setting | 0.7–0.9 | Generating production reports requires a balance between rigor and readability. This interval meets output requirements for engineering documents |
| `nodeId` | Bind the unique node identifier of the sub-workflow | Ensure the main workflow can correctly pass data and synchronize logs when calling a sub-workflow |

## Three common configuration mistakes
- When the batch execution node cycles and calls the large model, online debugging completes the full process, but API calls cannot execute all links. The cause is that the `variables` parameter is not passed correctly during API calls, causing the loop logic to interrupt due to missing core production data.
- After completing the variable reference configuration, the temperature setting button disappears, and large model generation parameters cannot be adjusted. The cause is that some interface components hide the model parameter configuration item by default after binding external variables, with no manual recall entry provided.
- After the main workflow calls the sub-workflow, running data in the conversation log is empty, and sub-process execution details cannot be viewed. The cause is that the main workflow does not enable the sub-process log synchronization switch, so sub-process running data is not returned to the main log.

## How to confirm the configuration is complete
- Trigger the workflow, then check if the `variables` parameter in the running log correctly binds core documents such as the cutting drawing and cutting list for the corresponding order.
- Compare the number of output entries from the batch execution node with the total number of panels for that order to confirm the processing range meets expectations.
- Verify that the generated production ledger report includes core fields such as panel size, sheet material batch, and hardware model.
- View log details after the sub-workflow is called to confirm running data has been fully synchronized to the main workflow.
