# Production Ledger Summary and Report Generation for Furniture and Wood Product Manufacturing: Database and Operations

## What data for this category looks like
Production ledger data for this category covers the full custom order workflow. Data sources include split order drawings and cutting lists exported from order design systems, batch inspection records for panels and lumber, operation logs from CNC cutting and drilling equipment, order progress data from ERP/MES systems, and wood moisture content test data. Daily retained documents include structured hardware lists, trial assembly and packaging records, plus unstructured edge banding and drilling programs, and coating process documents. Business nodes trigger data updates: panel data for individual orders updates per production batch, device operation parameters sync daily, and raw material batch information updates when materials are put into storage.

## Constraints on database and operations workflows
Multi-source data access increases interface integration complexity, requiring compatibility with both structured business data and unstructured process file storage formats. High-frequency data updates require database connection pools with sufficient concurrent processing capacity to prevent interruptions to individual order production workflows from data read delays. Custom orders correspond to dozens to hundreds of panels per order, resulting in significantly higher per-batch ledger data volume than standardized product categories, requiring careful planning of data storage and query efficiency. Additionally, production data errors directly lead to issues such as panel size deviations and installation failures, requiring database and operations processes to maintain data consistency and traceability.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://prod_user:secure_pass@db-host:27017/furniture_prod?authSource=admin` | Stores unstructured and semi-structured ledger data such as split order drawings and cutting lists, uses the default MongoDB port 27017, and specifies a dedicated database name to distinguish production and test data |
| `PG_URL` | `postgresql://erp_user:secure_pass@pg-host:5432/furniture_erp?sslmode=require` | Stores structured business data such as orders and hardware lists synced from ERP/MES systems; PostgreSQL supports complex relational query requirements |
| `DB_MAX_LINK` | `20–30` | This category corresponds to dozens to hundreds of panels per batch of orders, with high concurrent volume of multi-source data sync. This value prevents database connection exhaustion |
| `REDIS_URL` | `redis://cache_user:secure_pass@redis-host:6379/0` | Caches CNC device operation status and real-time moisture content test data to reduce high-frequency query pressure on the database |

## Three Common Misconfigurations
- Issue: Unable to input a custom port number when configuring `MONGODB_URI`, with an interface prompt indicating port format error. Cause: The port number was incorrectly entered as a separate parameter, rather than concatenated into a full connection string in the `host:port` format.
- Issue: After starting FastGPT v4.17.0, no mongo/data folder is generated in the same-level directory. Cause: This version has migrated the MongoDB data directory to an in-container mounted path, and no longer automatically creates a local same-level directory.
- Issue: Request timeouts or empty results occur when calling workflow APIs externally, with higher error frequency under high concurrency. Cause: `DB_MAX_LINK` was not properly configured, and concurrent requests exceed the database connection limit, causing some requests to be rejected or time out.

## How to Verify Successful Configuration
- Execute the database connection test node to verify that `MONGODB_URI` and `PG_URL` can normally read corresponding business table data, and confirm that fields include category-specific fields such as panel size and material batch.
- View the cache monitoring panel to confirm that the cache instance configured with `REDIS_URL` is connected normally, and can synchronize the latest data from CNC devices and moisture content tests in real time.
- Simulate concurrent submission of multiple order requests, observe that database connection count does not exceed the `DB_MAX_LINK` set value, and there are no connection timeout or rejection errors.
- Export the production ledger summary report, confirm that it includes associated information for category-specific documents such as split order drawings, cutting lists, and hardware lists, and that data update times align with business node schedules.

The values provided are common starting points and should be measured against the reader's own samples.
