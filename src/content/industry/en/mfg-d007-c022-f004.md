# Production Ledger Summary and Report Generation for Complete Household Appliance Manufacturing: Workflow Orchestration

## Data Profile for This Category
This category covers the full production process of air conditioners, refrigerators, washing machines and small household appliances. Data sources include ERP/MES systems, component batch ledgers, tightening and refrigerant charging equipment logs, electrical safety tester records, performance laboratory reports and after-sales fault data. Daily documents include configured BOMs, assembly work instructions, process parameter records, safety compliance test reports, functional spot check forms and rework ledgers.
Data updates follow schedules for single products, shift production batches or spot check plans. Fields include component batch numbers, process parameter values, test results, rework reasons and more. Physical units such as pressure, current and volume are used for relevant metrics.

## Constraints for Workflow Orchestration
Mixed production of multiple product models requires workflows to use `nodeId` to distinguish ledger collection nodes for different appliance categories, avoiding data mixing.
Multi-source heterogeneous data requires configuring field mapping rules via the `variables` field, to unify output formats from different devices into a standard ledger structure.
Data updated per single product or batch requires workflows to support triggering based on production beat, to avoid redundant summarization.
Verification links for critical data such as safety compliance and performance testing require linking multiple nodes to complete cross-data source consistency checks, and ensure abnormal data is intercepted promptly.
Production ledgers must be associated with after-sales fault data. Workflows must configure cross-system data pull nodes to cover ledger content across the full product lifecycle.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Trigger Mode | Trigger at the end of each production shift, with an interval no longer than 4 hours | Match the data update rhythm of each shift to avoid missing batch data |
| `variables` | Configure component batch numbers, process parameters and test results as mapping fields | Unify the field formats of output from multi-source devices, adapting to the multi-data-source characteristics of this category |
| `nodeId` | Set independent node IDs for air conditioners, refrigerators and small household appliances separately | Distinguish ledger collection logic for different product models, avoiding data interference from mixed-line production |
| Maximum Retry Count | 3 retries, with a 60-second retry interval | Address temporary failures such as failed device log uploads, reducing the probability of workflow interruptions |
| Context Window | Calibrated based on actual testing, ranging from 8000–12000 tokens | Adapt to the report generation requirement after splicing multiple documents, FastGPT v4.17.0 |
| Node Timeout Threshold | 300 seconds | Match the standard time consumption of links such as safety compliance testing, avoiding invalid waiting |

## Three Common Misconfigurations
- A blank configuration appears after workflow deployment and container restart. Symptoms include an empty node list in the interface, no selectable options in the knowledge base drop-down menu, and normal return results from interface calls. The cause is that no persistent storage directory was mounted during deployment, resulting in loss of configuration files after container restart.
- Failure to configure variable reference rules via `variables` when selecting a knowledge base, leading to inability to dynamically bind the exclusive knowledge base corresponding to the production batch. Symptoms include search results matching the full knowledge base content, and inability to filter exclusive documents for the corresponding product model.
- Workflows only support single queries and cannot implement multi-round questioning. Symptoms include only the result of the first question being returned after a user inputs multiple rounds of questions, with no follow-up interactive responses available. The cause is that no context transfer node for multi-round conversations was configured, and `variables` parameters for historical interactions were not retained.

## How to Verify Successful Configuration
- Manually trigger a workflow once, check the node run logs, and confirm that the collection node corresponding to the `nodeId` product model does not have data mixing.
- Call the workflow interface, pass a test component batch number, and confirm that the returned ledger fields include the mapping items configured in `variables`.
- Simulate a scenario where device upload fails, and confirm that the workflow triggers the retry mechanism, and generates an abnormal alarm after reaching the set maximum retry count.
- View the final generated report, and confirm that it includes content exclusive to this category such as safety compliance testing and performance spot check documents, with no missing fields.
