# Production Ledger Summary and Report Generation for Complete Home Appliance Manufacturing: Tool Calling and Plugins

## Data Profile for This Category
Data sources for this category include ERP/MES systems, component batch ledgers, tightening and refrigerant charging equipment, electrical safety testers, performance laboratory equipment, and after-sales fault databases.
Data updates follow per-unit product, shift production batch, or sampling inspection schedules.
Daily documents include configured BOMs, assembly work instructions, refrigerant charging records, electrical safety test reports, performance sampling inspection reports, and repair records.
Fields include component batch numbers, tightening torque values, charging volumes, safety test voltages, repair reasons, and corresponding units such as newton meters, grams, volts, and others.

## Constraints for Tool Calling and Plugins
Multi-model mixed-line assembly scenarios require tool calls to precisely match the BOM and work instructions for the corresponding product. This prevents cross-model data confusion.
Multi-source heterogeneous data includes direct equipment collection, system exports, and laboratory data. Plugins must support parsing of different formats and unified field mapping.
High-frequency per-unit or shift updates require tool call response delays to stay within a reasonable range. This avoids blocking production ledger summary workflows.
Calls for highly compliant data such as safety and performance data must strictly limit access permissions. This prevents leakage of sensitive parameters.
Associated calls for after-sales fault data must match the unique product identifier. This ensures accuracy of ledger associations.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| Workflow/API tool selection | `auto` | Adapts to multiple types of tool calls, covering parsing and retrieval needs for different data sources |
| Tool call timeout duration | `600 seconds` | Handles parsing and upload processes for large files such as safety test reports and performance laboratory data |
| Workflow/API function-call configuration | Allow parallel multi-tool calls | Retrieves assembly records, charging data, and safety reports simultaneously, improving summary efficiency |
| Function call parameter validation | Enable required field validation | Prevents ledger data errors caused by missing core fields such as batch numbers and torque values |
| Plugin authentication configuration | Assign independent keys per device/system | Differentiates access permissions for different data sources such as ERP and safety testers, ensuring data security |

## Three Common Configuration Errors
- Phenomenon: Assembly records returned by tools do not match the product model, and core fields are empty. Cause: No model binding rules for `toolChoice` are configured. This causes tool calls to fail to filter BOM data for the corresponding model, leading to mixed-line assembly errors.
- Phenomenon: A 403 status code is returned when calling safety test data. Cause: Authentication configurations do not differentiate access permissions for different devices. Cross-system calls lack dedicated keys, violating data access control requirements.
- Phenomenon: Plugin execution times out, and production ledger summary report generation fails. Cause: No reasonable timeout duration is set. Processing large volumes of performance laboratory data exceeds the preset threshold, preventing successful data retrieval.

## How to Verify Successful Configuration
- Submit a single-unit air conditioner ledger summary request, and check whether the fields of the returned assembly records, charging data, and safety test reports match the corresponding product documents.
- Review tool call logs to confirm that parallel multi-tool calls triggered by `functionCall` execute as expected, with no duplicate or missing data sources.
- Validate authentication configurations by attempting to call an unauthorized data source interface, confirming that a correct permission denial prompt is returned.
- Simulate calls for batch shift data, confirming that tool response times meet production rhythm requirements, with no obvious blocking.
