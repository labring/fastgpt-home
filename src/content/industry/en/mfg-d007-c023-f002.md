# Production Ledger Summarization and Report Generation for Industrial Instrument Manufacturing and Calibration: Vector Models and Indexes

## What this category of data looks like
Data for this category comes from instrument manufacturers’ design documents, standard instrument and environmental monitoring data, calibration software outputs, laboratory information systems, and customer range requirements. Daily documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version records. New data is generated each time an instrument is calibrated. Fields include metrology device number, range parameters, error value, calibration date, traceability number, and other items. Some documents include numerical content with physical units.

## Constraints on Vector Models and Indexes From These Characteristics
This category of data has a high update frequency. New data is generated each time an instrument is calibrated. Indexes must support incremental updates to avoid resource consumption from full reconstruction. Document types include numerical records with physical units, standardized calibration procedures, and traceability vouchers. Field association relationships must be retained during vector modeling to prevent loss of metrology traceability information after splitting. Some documents include unstructured error curve content. Vector mapping must be adapted after text-based processing. Strict metrology audit requirements also demand precise matching of recalled content, to avoid unrelated data being mixed into summary reports.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0, and are tailored to ledger index requirements for industrial instrument manufacturing and calibration scenarios.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapt to the text length of calibration procedures and original records, retain complete context for single calibration data |
| Overlap Length | 100–150 characters | Avoid splitting the association between error values and traceability numbers after chunking |
| Similarity Threshold | 0.75–0.85 | Ensure precise matching of metrology-related keywords, avoid low-relevance calibration records from being mixed into summaries |
| Single Search Limit | Top 20 entries | Cover recent calibration records for a single instrument, meet the time range requirements for ledger summarization |
| `maxToken` | Set to the selected embedding model/service maximum supported input tokens | `maxToken` is the input-token maximum supported by the selected embedding model/service; verify it in that provider configuration. See the [v4.17.2 model-field reference](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx). It is not retrieval/LLM context or a FastGPT-wide fixed cap. |
| `defaultToken` | Set based on actual measurement | Adapt to instrument ledger data volumes of different scales, avoid context overflow |

## Three Common Configuration Mistakes
- Some metrology certificate content fails to be correctly recalled after importing into an index. The symptom is that search results do not include certificate number-related data. The cause is failure to retain the association context between certificate numbers and calibration dates during chunking, leading to loss of key association information after splitting.
- Insufficient recall precision occurs when using a pg vector database. The symptom is that similarity scores for similar calibration records have large deviations. The cause is failure to adjust the chunking strategy for numerical fields with physical units, resulting in splitting of numerical context.
- A timeout error appears during ledger summary report generation. The symptom is that the task returns status code 504. The cause is unreasonable setting of the `maxToken` parameter, where the number of spliced calibration records exceeds the model context limit.

## How to Verify Correct Configuration
- Upload a single original calibration record, view the chunk preview interface, and confirm that associated content for key fields such as error values and traceability numbers has not been split.
- Initiate a search for a specific metrology device number, and verify that the number of returned results matches the single search limit setting.
- Test splicing three recent calibration records, and confirm that the generated context content does not exceed the `maxToken` setting range.
- Import batch calibration data, and check that the system triggers incremental index updates, with no full reconstruction prompt information displayed.

The values provided are common starting points and should be measured against the reader's own samples.
