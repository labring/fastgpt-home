# Production Ledger Summarization and Report Generation for Industrial Instrument Manufacturing and Calibration: Workflow Orchestration

## What data for this category looks like
Data for this category comes from design documents, standard instruments and environmental monitoring data, calibration software, laboratory information systems, and customer range requirements. Daily documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version records. Data is updated per device and per calibration. Fields include traceability number, calibration date, measured value, and uncertainty value. Units include Pa, ℃, MPa and other metrology-related standard units.

## What constraints these characteristics impose on workflow orchestration
Data sources for this category are scattered and have diverse formats. Workflow orchestration must be configured with multiple data source access nodes to connect to different systems such as calibration software and laboratory information systems. Data is updated per device and per calibration. Workflows must support execution triggered by a single calibration task to adapt to flexible task startup logic. Documents include structured records and unstructured error curves and metrology certificates. Workflows must support mixed-format data parsing and extraction. Fields include specific measurement units. The variable verification link in the workflow must match unit rules to avoid calculation deviations across units.

## Three common configuration mistakes
- The workflow judge node returns empty results regardless of input content. The cause is that the `variables` verification rules are not configured to match the required items of metrology fields, causing the judgment logic to fail to trigger valid verification.
- The knowledge base reference cannot be selected as an input variable in the code run node. The cause is that the knowledge base data binding output is not completed in the workflow's preceding nodes, and the knowledge base results are not mounted to the global `variables`.
- Unit mismatched calculation results appear in the metrology certificate report generated by the workflow. The cause is that the unit verification rules for `variables` are not set, and measurement data of different units are directly summarized and calculated.

## How to verify the configuration is complete
- Execute a calibration task for a single device to trigger the workflow, check whether each data source node successfully pulls raw data from the corresponding system.
- View the running logs of the `variables` verification rules, confirm whether the unit verification of metrology fields is triggered normally.
- Call the workflow test interface, check whether the code run node can correctly obtain the calibration procedure content associated with the knowledge base.
- Generate a test report, verify whether the report includes core document content for this category such as error curves and metrology certificates.
