# Production Ledger Summary and Report Generation for Industrial Instrument Manufacturing and Calibration: Tool Calling and Plugins

## What data for this category looks like
Core data for this category comes from daily business processes of flow, pressure, temperature, analytical instrument manufacturers and metrology laboratories. Daily documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version records. Data sources cover design documents, standard instruments and environmental monitoring data, calibration software, laboratory information systems, and customer range requirements. Data update frequency is triggered once per device per calibration. Each calibration record includes fixed fields such as tested part number, calibration date, standard instrument number, ambient temperature (℃), pressure (kPa), error value, calibration result, and certificate number. Some documents include unstructured error curve images and metrology certificate PDFs.

## What constraints these characteristics impose on tool calling and plugins
Data sources for this category are scattered, and update frequencies are independent. This requires tool calling to support precise triggering for a single device’s single calibration, to avoid redundant data generated by batch calls. Core documents include unstructured error curves and metrology certificates. Tool calling must adapt to parsing rules for multiple file types, and retain the original units and traceability information of fields. The most time-consuming calibration steps involve establishing connections between standard instruments and tested parts, collecting multi-point error data, and auditing traceability chains and certificate information. Tool calling must prioritize automated processing of these steps to reduce the need for manual intervention. In addition, data compliance requirements are strict. Tool calling must ensure the completeness and traceability of all fields.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Tool call trigger timing | Triggered after a single calibration is completed | Matches the update frequency of one calibration per device per this category, avoids invalid calls |
| File parsing rules | Prioritize parsing original calibration records and error curve formats | Covers core business document types for this category, aligns with daily data sources |
| Context retention length | 8000–12000 token | Adapts to full reading requirements for long texts such as calibration procedures and metrology certificates, calibrated based on actual measurements |
| Single tool call timeout | 120 seconds | Covers the longest time-consuming steps of establishing standard instrument connections and collecting multi-point error data |
| Workflow/API function-call configuration | Enabled | Supports calling custom tools to connect to external data sources such as laboratory information systems and calibration software |
| Workflow/API tool selection | Manually specified | For the traceability chain audit step, specify a dedicated tool to verify the compliance of metrology certificates |

## Three common configuration mistakes
- The symptom is that calling the ledger summary workflow via API returns missing core fields, but runs normally in the application configuration test interface. The cause is that the API request does not correctly carry the unique identifier parameter of the single calibrated device, causing the tool call to fail to match the corresponding data source.
- The symptom is that a model loading failure is returned when calling calibration-related tools. The cause is that after upgrading FastGPT v4.17.0, the model configuration path relied on by the tool was not updated, causing locally deployed models to not be correctly located.
- The symptom is that parsing calibration record files takes too long. The cause is that a dedicated parsing rule for this category of documents was not configured, and the tool call defaults to parsing all file types, which additionally processes non-business-related redundant content.

## How to confirm the configuration is complete
- Trigger a tool call after a single calibration is completed, check whether the returned results include core business fields such as tested part number, calibration date, and error value.
- View the tool call log, confirm that the data format returned by the connected external data source matches the configuration expectations, and no units or traceability information are lost.
- Simulate the traceability chain audit step, call the dedicated tool to verify metrology certificate information, confirm that the tool can correctly read the traceability number and standard instrument association relationship in the certificate.
- Test local model calls in a Linux deployment environment, confirm that the tool can normally load and process calibration-related text and image data.
