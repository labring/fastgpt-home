# Production Ledger Summary and Report Generation for Industrial Instrument Manufacturing and Calibration: Model Access and Configuration

## What data for this category looks like
This category’s data covers the full calibration and production lifecycle of individual instruments. Sources include design documents, standard device and environmental monitoring data, exported calibration software outputs, laboratory information system records, and customer range requirements. Data updates are triggered after each calibration for each instrument. Daily documents include assembly and debugging slips, calibration procedures, original calibration records, error curves, metrology certificates, and software version logs. Fields include instrument model, calibration date, measurement error value, ambient temperature and humidity, standard device serial number, certificate serial number, and other related items. Units use metrology-standard units such as pascals, degrees Celsius, milliamps, and other metrology-related standard units.

## Constraints on model access and configuration
Documents generated from a single calibration for this category include multiple content types such as curves and certificates. Data updates occur after each calibration for each instrument. Adaptations for multimodal input and frequent context refreshes are required during model access. Most data fields use metrology-specific professional terminology. Model recognition accuracy for these terms must be ensured. Total input token volume must be strictly controlled to avoid exceeding model limits. Calibration records are critical deliverables. Permission checks for model calls must align with traceability requirements. Format alignment for multi-source data must be handled to prevent configuration errors caused by inconsistent data structures.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Adapts to the total context of multiple documents generated from a single calibration for this category, and avoids truncating critical metrology data |
| `maxTokens` | 4000 token | Controls the length of single-round output reports, and meets the standard length requirements of metrology certificates and calibration reports |
| `quoteMaxToken` | 1500 token | Limits the token proportion of referenced original calibration records, error curves and other documents, and ensures clear model output logic |
| `vision` | Enabled | Supports recognition of image content such as error curves and metrology certificates, and adapts to the multimodal data input needs of this category |
| `temperature` | 0.2–0.4 | Reduces output randomness, and ensures the accuracy of metrology-related values and conclusions |
| `AIPROXY_API_ENDPOINT` | Fill in according to the deployment environment | Adapts to local or cloud-based model call addresses, and ensures data transmission compliance |
| `AIPROXY_API_TOKEN` | Token bound to the corresponding model permissions | Matches the token permissions configured in the model permission management tool, and avoids call failures |

## Three Common Misconfigurations
- A `403 You do not have permission to use the model` error may be returned during model calls. This occurs because the configured `AIPROXY_API_TOKEN` has not been granted access to the target model in the corresponding model permission management tool, or the token's access scope does not cover the models required for the current scenario.
- Generated calibration reports do not meet preset length requirements. This occurs because the `maxTokens` parameter is not set correctly, causing model output to exceed expected length, or the word limit in the prompt does not align with the model output parameters.
- Error curve image content cannot be parsed correctly. This occurs because the `vision` configuration item is not enabled, or the uploaded image format does not comply with the specifications supported by the model, leading to image recognition failure.

## How to Verify a Successful Configuration
- Enter a single calibration record in the model testing interface of FastGPT v4.17.0, and check that the returned response status code is 200 with no permission-related errors.
- Upload an error curve image, confirm that the model correctly extracts numerical and annotation information from the image, and verify that the `vision` configuration is enabled.
- Set `maxTokens` to the preset value, generate a simulated calibration report, and confirm that the output length falls within the specified range.
- Switch to different calibration scenario documents, confirm that the model can normally load and process the corresponding context content, and verify that the `maxContext` configuration is appropriate.

The values provided here are common starting points, and should be evaluated against the relevant deployment’s own sample data.
