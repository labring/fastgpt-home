# Production Ledger Summarization and Report Generation for Process Change and Engineering Change: Tool Calling and Plugins

## What data for this category looks like
Data for this category is generated by change management teams composed of R&D, process, quality, production, and procurement staff at manufacturing enterprises. It includes ECN/ECR forms, change assessment records, drawings and BOM version files, process validation reports, production switchover plans, inventory disposal documents, and customer approval documents.
Data sources cover PLM, ERP, MES systems, supplier materials, validation test results, and customer-specific requirements. Updates are triggered irregularly with each change, with no fixed schedule.
Individual change-related data includes fields such as change number, involved materials/processes, version number, validation status, and switchover node. Data is stored as a mix of structured forms and unstructured documents.

## What constraints these characteristics impose on the tool calling and plugins workflow
Data for this category has dispersed sources and mixed formats, including structured system data and unstructured documents. Tool calling must connect to multiple system APIs such as PLM, ERP, and MES, and support parsing of unstructured files like drawings and validation reports. It must adapt to authentication rules and return formats of different data sources.
Change data updates are triggered irregularly with each change. Tool calling must support on-demand triggering to meet real-time summarization needs for temporary changes.
Individual change data is linked to multiple types of fields generated through cross-department collaboration. Tool calling must accurately extract linked fields to complete ledger consolidation, and avoid missing supplementary information synchronized across systems.
Additionally, data relates to production compliance and customer requirements. Tool call return results must strictly match preset field definitions to ensure consistency of summarization reports.

## How to configure settings
The following configurations are set for FastGPT v4.17.0 to meet the ledger summarization and report generation needs of this category:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` or specify the change ledger tool name | Allows the model to autonomously select tools suited for change scenarios, or lock a specified tool to ensure calling accuracy |
| Workflow/API function-call configuration | Enabled | Forces the model to call tools to complete ledger summarization, avoiding directly generating unverified reports |
| Tool timeout duration | 300–600 seconds | Adapts to average response delays from multi-system connections, preventing task failure due to system interaction timeouts |
| Number of returns per single tool call | Top 3–5 entries | Matches the typical number of linked entries for change-related data, avoiding redundant returned information |
| Document parsing chunk size | 800–1200 characters | Adapts to standard paragraph lengths of change-related documents such as ECNs and process validation reports |
| Plugin data source whitelist | Only include PLM, ERP, MES and supplier systems | Limits the scope of data sources to ensure summarized data complies with change management compliance requirements |

## Three Common Misconfigurations
- Symptom: Tool call triggers a response directly generated by the model, with no tool call related logs. Cause: The `functionCall` configuration item is not enabled, or the configured `toolChoice` parameter does not match the currently available change management tools.
- Symptom: Unable to connect to SQL Server data sources when calling database plugins. Cause: The target database is not added to the plugin data source whitelist, or correct database connection permission parameters are not configured.
- Symptom: Tool call tasks terminate due to timeout. Cause: A reasonable tool timeout duration is not set, or unhandled network delays during multi-system connections cause response timeouts.

## How to Confirm Configurations Are Correct
- Manually trigger a tool call, check if the system logs include complete tool request and return records, and confirm that the `toolChoice` and `functionCall` configurations have taken effect.
- Import a standard ECN document, check if the fields extracted after tool calling match the preset change ledger field definitions.
- Test connection to the specified PLM system API, confirm that the plugin can normally pull change-related BOM version data.
- Adjust the tool timeout duration to a reasonable range, verify that tasks can complete on time when systems respond normally.

The values given are common starting points and should be measured against the reader's own samples.
