# Production Ledger Summary and Report Generation for Process Changes and Engineering Changes: Model Access and Configuration

## What the data for this category looks like
Data for this category originates from PLM, ERP, MES, supplier materials, validation tests, and customer-specific requirements. Updates are triggered by each process or engineering change, with no fixed cycle. Daily documents include ECN/ECR forms, change assessment reports, drawings and BOM version records, process validation reports, production switching plans, inventory disposal documents, and customer approval documents. Core fields include change number, version number, list of affected materials, and approval node status. Some documents contain structured parameters and unstructured drawing content.

## Constraints on Model Access and Configuration Posed by These Characteristics
This category has scattered data sources, including structured forms and unstructured drawings. This requires the model access link to support multi-source data parsing and adapt to document formats exported by different systems. Changes are triggered without a fixed cycle, and sudden batch change requests may occur. This requires adaptation to high-concurrency access scenarios to prevent exceptions triggered by concurrency limits. Documents include compliance-related content such as customer approval documents. This requires the configuration link to lock parsing rules for sensitive fields to prevent information omission or tampering. Additionally, identifying chain impacts associated with changes relies on long context association, which sets clear requirements for the model’s context length.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `vision` | Enabled | This category includes visual documents such as unstructured drawings and validation reports, so visual parsing capability must be enabled |
| `maxContext` | 8000–12000 token | Multi-source documents associated with changes require long context association to cover all relevant content such as ECN, BOM, and customer requirements |
| `maxTokens` | 2000–3000 token | Ledger summary and report generation require complete output of change impact analysis to avoid truncation of key conclusions |
| `temperature` | 0.2–0.4 | Content related to changes must maintain rigor, reducing random output |
| `AIPROXY_API_ENDPOINT` | Fill in the address provided by the deployment service provider | Adapt to proxy configuration for multi-source data access to ensure stable cross-system data synchronization |
| `AIPROXY_API_TOKEN` | Configure based on the key length measured in actual testing | Ensure security of interface access permissions, avoiding key leaks or invalid calls |

## Three Common Misconfigurations
- Phenomenon: The visual parsing function is only displayed in the commercial version menu and cannot be enabled in an open-source deployment environment. Cause: No compatible items for the `vision` parameter are configured for the open-source version, or the deployment package does not include open-source visual model adaptation files.
- Phenomenon: A 429 status code is returned when more than 5 concurrent calls are made, and requests are blocked. Cause: No interface concurrency limit rules are configured, and thresholds are not adjusted based on the sudden call characteristics of change business.
- Phenomenon: A custom large model cannot be called normally, and the system prompts a connection timeout. Cause: The `AIPROXY_API_ENDPOINT` or `AIPROXY_API_TOKEN` parameters are filled incorrectly, or network policies restrict interface access.

## How to Verify Successful Configuration
This configuration content is based on FastGPT v4.17.0.
- Import an ECN change document and its associated BOM file, trigger a ledger summary task, and verify that core fields such as change number and affected materials are correctly extracted.
- Initiate more than 2 concurrent report generation requests, check for 429 exceptions, and confirm that the concurrency limit configuration is active.
- Review the model call log, confirm that the `vision` parameter is enabled, and ensure that parsing results for visual documents include key drawing annotation information.
- Test the custom large model interface call, confirm that change impact analysis content is returned normally, and that no connection errors occur.

The values provided here are common starting points and should be measured against the reader's own samples.
