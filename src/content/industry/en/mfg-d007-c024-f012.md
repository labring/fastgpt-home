# Production Ledger Summary and Report Generation for Process Changes and Engineering Changes: Deployment and Upgrade

## Data for This Category
This category’s data originates from PLM, ERP, MES, supplier materials, validation tests, and customer-specific requirements. Updates are triggered by each change, with no fixed cycle. Daily generated documents include ECN/ECR, change assessments, drawings and BOM versions, process validation reports, transition plans, inventory disposal documents, and customer approval documents. Core fields include change identifiers, version numbers, effective nodes, associated bill of materials, approval status, and more. There are no unified custom units; fields are flexibly adjusted based on change type.

## Constraints During Deployment and Upgrade
Since data sources cover multiple heterogeneous systems, adapt interface configuration for multi-source data pulling during deployment to avoid cross-system data synchronization failures. Since updates have no fixed cycle and a single change is associated with multiple types of documents, optimize incremental synchronization logic during upgrades to prevent duplicate or missing ledger entries. Since documents include structured fields such as approval status and effective nodes, clarify field mapping rules before deployment to ensure complete fields in ledger summaries. Since errors in changes directly impact production, retain data backups and rollback nodes during upgrades to ensure deployment process stability. Meanwhile, since document volumes vary significantly, configure appropriate storage resources during deployment to avoid large file upload failures.

## Configuration Guidelines
This configuration guide applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `PG_URL` | `postgresql://postgres:${custom password}@pg:5432/fastgpt?sslmode=disable` | Supports structured storage for multi-source PLM/ERP data; default port 5432 complies with general deployment specifications |
| `STORAGE_S3_ENDPOINT` | Enterprise existing storage service address, such as `https://s3.cn-north-1.amazonaws.com.cn` or a local MinIO endpoint | Stores large-volume files including ECN documents, BOM version drawings, etc., and matches the enterprise’s existing storage architecture |
| `DB_MAX_LINK` | `20–30 connections` | Meets concurrent connection requirements during multi-system synchronization and prevents connection pool exhaustion |
| `REDIS_URL` | `redis://:${custom password}@redis:6379/0` | Caches incremental synchronization status of change ledgers and reduces latency from multi-source data pulling |
| `ROOT_KEY` | Random string generated per enterprise security policies | Ensures access permissions for system backend configuration and prevents unauthorized modification of ledger generation rules |

## Common Misconfigurations
- Issue: PostgreSQL container fails to start, with logs displaying "role "postgres" does not exist". Cause: The default role and database tables for the PostgreSQL database were not initialized during deployment, or the username configured in `PG_URL` does not match the initialization script.
- Issue: Production ledger summary results are empty or missing core change records after an upgrade. Cause: Data synchronization mapping rules for multi-source systems such as PLM and ERP were not configured, or the incremental synchronization logic does not adapt to the update rhythm triggered by changes.
- Issue: Ledger generation tasks time out. Cause: The `DB_MAX_LINK` configuration value is too low, leading to connection pool exhaustion during multi-system synchronization and failure to pull full change data.

## How to Verify Successful Configuration
- Run the `docker logs pg` command to check that the PostgreSQL container has no role missing or connection failure errors, and confirm that the username and password configured in `PG_URL` are correct.
- Manually trigger a change ledger summary task, check that the generated report includes core fields such as ECN numbers and BOM versions, and confirm that the field mapping configuration is active.
- Log in to the storage bucket corresponding to `STORAGE_S3_ENDPOINT`, confirm that ECN documents, process validation reports, and other files have been uploaded normally and are accessible.
- Test the multi-source data synchronization interface, confirm that change records from PLM and ERP systems can be pulled normally and written to the ledger database.

The values provided are common starting points and should be measured against the reader's own samples.
