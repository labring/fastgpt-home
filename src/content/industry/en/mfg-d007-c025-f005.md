# Production Ledger Summary and Report Generation for Fixture and Gauge Manufacturing: Tool Calling and Plugins

## What data for this category looks like
Data for this category comes from product digital models and GD&T specifications, process route documents, coordinate measuring machine data, on-site trial feedback, and metrology system records. Daily produced documents include fixture requirement documents, positioning datum schemes, fixture design drawings, gauge operation guides, acceptance reports, calibration records, and change histories.
Data updates run per project milestones, each product change, or regular calibration. It includes fields such as positioning datum parameters, measurement tolerance values, and calibration cycles. Most units are standard metrology-related units like millimeters and days.

## What constraints these characteristics impose on tool calling and plugins
Data for this category is multi-source, heterogeneous, and structurally diverse. The tool calling link must adapt to data sources in different formats, including digital models, coordinate measuring machine data, and metrology records. It must support triggering data pulls based on project milestones, changes, or calibration cycles to avoid full redundant synchronization.
Multiple fixed-structure documents require plugins to achieve precise field mapping. For example, extract positioning datum parameters from fixture drawings, and extract cycle data from calibration records. Improper tool calling adaptation can lead to missing ledger fields or format errors. This will negatively impact subsequent acceptance and report generation.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | Adapts to multi-tool calling scenarios, automatically matches tools required for document parsing, data pulling, and report generation |
| Workflow/API function-call configuration | `Allow registered full-process tools` | Covers tool calling needs across all links from digital model parsing, coordinate measuring data import, to calibration record summarization |
| Tool calling timeout | `300–600 seconds` | Reserves sufficient parsing and pulling time, as single-project ledger summary processes multiple types of heterogeneous data |
| Plugin trigger rule | `Trigger by project change milestones` | Aligns with the characteristic that data for this category updates per project, change, or calibration cycle, avoids invalid repeated calls |
| Field mapping configuration | `Set based on actual measurement calibration` | Document fields vary slightly across different projects, must adapt to specific business scenarios |
| Visualization rendering configuration | `Enable AntV Chart component` | Ledger reports require visual display of metrology data such as tolerance values and calibration cycles |

These configurations are formulated based on the functional specifications of FastGPT v4.17.0.

## Three common mistakes
- Phenomenon: When calling the AntV Chart MCP plugin, only JSON or XML code blocks are returned, with no visual charts. Cause: The chart rendering component is not enabled in the configuration, or visualization output parameters are not specified during tool calling.
- Phenomenon: Large differences exist between online chat and API call results, with online chat having a higher correct rate. Cause: The API call does not correctly pass knowledge base context parameters, or the `toolChoice` parameter consistent with online chat is not configured.
- Phenomenon: Ledger fields are missing or have format errors. Cause: The plugin does not adapt to the specific document structure of this category, and has not completed field mapping for GD&T parameters and coordinate measuring data.

## How to confirm the configuration is complete
- Submit a simulated fixture project ledger generation request. Check the tool calling log to confirm that document parsing, data pulling, and visualization rendering processes are correctly triggered.
- Review plugin return results. Confirm that GD&T tolerances, calibration cycles, and other fields unique to this category are included, with no missing entries or format errors.
- Call the test interface. Compare return results from online chat and API calls to confirm their tool calling configurations are consistent.
- Trigger a simulated product change request. Check whether the plugin automatically executes data synchronization and ledger updates according to the configured trigger rules.

The values provided are common starting points and should be measured against the reader's own samples.
