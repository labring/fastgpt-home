# Production Ledger Summary and Report Generation for Tooling, Fixture and Gauge Manufacturing: Deployment and Upgrade

## What Data for This Category Looks Like
The data for this category comes primarily from product digital models and GD&T, process routes, coordinate measuring machine data, on-site trial feedback, and metrology systems. Daily generated documents include tooling requirement documents, positioning datum schemes, fixture drawings, gauge operation manuals, acceptance reports, calibration records, and change histories. Data updates are triggered by individual project progress, product design changes, and regular calibration cycles. Data fields include datum parameters, clamping schemes, interference verification results, calibration values, change records, and more. Units involve precise measurement units such as millimeters, newtons, and microns.

## Constraints Imposed by These Characteristics on Deployment and Upgrade
The mixed characteristic of precise metrology data and structured engineering documents for this category requires that the deployment phase support multi-source heterogeneous data access. Non-periodic updates triggered by individual projects, product design changes, and regular calibrations require the deployment's synchronization mechanism to support on-demand triggering. This accommodates immediate data submission for temporary changes and calibration tasks. The characteristic that multiple fields use precise measurement units such as millimeters, newtons, and microns requires that the data storage and parsing links support custom unit mapping and format verification. The storage demand for large volumes of engineering drawings and calibration records requires configuring sufficient storage space and a parsing module compatible with CAD format files. At the same time, process routes and coordinate measuring machine data associated with the data must connect to existing production systems. Deployment must reserve standardized interface adaptation space.

## How to Configure the System
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@host:port/database?authSource=admin` | Adapts to structured storage needs for multi-source engineering documents and metrology data, supports transactional data updates |
| `REDIS_URL` | `redis://:password@host:6379/0` | Caches frequently accessed fixture drawing metadata and calibration records, reduces database query pressure |
| `STORAGE_S3_ENDPOINT` | `https://s3-cn-beijing.volces.com` (or local storage node address) | Adapts to bulk storage and fast reading needs for large volumes of engineering drawings and coordinate measuring machine data |
| `FILE_TOKEN_KEY` | Set based on actual measurement | Used to encrypt access tokens for tooling documents, prevents unauthorized access to precise engineering data |
| `DB_MAX_LINK` | `100–150` | Adapts to concurrent access of ledger data for multiple parallel projects, prevents connection pool exhaustion |
| `FE_DOMAIN` | `https://your-fastgpt-domain.com` | Configures the frontend access domain name, ensures normal link for tooling document preview and report generation |

## Three Common Mistakes
- Symptom: After upgrading to FastGPT v4.17.0, a configuration failure prompt pops up when rearranging models in offline configuration. Background logs show model loading timeout. Cause: Offline model files were not placed in the specified local model storage directory, or directory permissions were not configured for read-write access.
- Symptom: Local documents fail to load after enabling the associated knowledge base function. The interface displays "Resource unavailable". Cause: `STORAGE_S3_ENDPOINT` was not configured to point to a local storage node, or the local file path was not mapped in the deployment configuration.
- Symptom: After local deployment, attempts to connect to an enterprise authentication system via SSO fail to complete login redirection. The interface displays authentication failure. Cause: `FE_DOMAIN` and the backend callback address were not correctly configured in the deployment configuration, causing SSO token verification to fail.

## How to Confirm Proper Configuration
- Run a database connection test to confirm that the addresses, ports, and authentication information configured in `MONGODB_URI` and `REDIS_URL` can connect normally.
- Upload a fixture drawing file to verify that the storage node configured in `STORAGE_S3_ENDPOINT` can normally receive the file and return a file access link.
- Initiate a ledger summary task to check whether the generated report includes category-specific data fields such as calibration records and change histories.
- Test the SSO connection process to confirm that the frontend address configured in `FE_DOMAIN` matches the SSO callback address, and complete the authentication redirection.
- Attempt to load the rearranged model offline to confirm that no timeout errors occur during model loading, meeting the requirements for local deployment configurations.

The values given are common starting points and should be measured against the reader's own samples.
