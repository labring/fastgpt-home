# Production Ledger Summary and Report Generation for Non-Ferrous Metal Smelting and Electrolysis: Multi-Turn Dialogue and Prompt Engineering

## What This Category of Data Looks Like
This data covers production data from smelting, electrolysis, laboratory testing, and scheduling departments of copper, aluminum, lead-zinc, and other smelting enterprises.
Data sources include concentrate and auxiliary material analysis reports, DCS systems, cell voltage and current monitoring data, laboratory test results, energy and environmental monitoring systems.
Daily documents include batching lists, smelting records, electrolytic cell status records, laboratory reports, anode and cathode quality records, and environmental ledgers.
Data updates per batch of raw material, per furnace, or per cell. Some monitoring data syncs in real time.
Fields include equipment numbers, process parameters, material composition, quality indicators, and more. Corresponding units include current, weight, concentration, and other categories.

## Constraints Imposed by These Characteristics on Multi-Turn Dialogue and Prompt Engineering
Multi-source heterogeneous data sources require prompts to explicitly specify data priority, to avoid confusing identically named fields from different systems.
Batch and real-time update features require dialogue contexts to retain the latest batch identifiers, to prevent calling outdated ledger data.
Field differences across multiple document types require prompts to preset parsing rules for different documents, to ensure field alignment during summarization.
High update frequency requires dialogue context token limits to match the maximum data volume for single queries, to avoid truncating critical process parameters.
Electrolytic cell group management needs multi-turn dialogue support for instruction breakdown to filter data by cell number and time period, to improve query accuracy.

## Configuration Settings
This configuration is formulated based on FastGPT v4.17.0 rules.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context token count | 8000–12000 token | Matches the number of fields in multi-source ledgers and the volume of real-time data syncs, to avoid truncating critical information |
| `variables` preset query dimensions | Cell number, smelting batch, laboratory test date, environmental indicators | Matches core query dimensions for ledgers in this category, to quickly filter target data |
| `chatId` session isolation rule | Divided by production shift and date | Ensures historical conversations from different shifts do not interfere, aligning with departmental data permission requirements |
| `messages` historical turn limit | Last 12 conversation turns | Adapts to context memory for multi-turn ledger queries, to avoid response delays from overly long contexts |
| Single recall document upper limit | Top 8 entries | Matches the number of associated ledgers per furnace or cell, to avoid excessive redundant information interfering with summarization |
| Prompt template update cycle | Every quarter or after process changes | Adapts to changes in ledger fields after smelting process adjustments, to ensure prompts match current business rules |

## Three Common Mistakes
- Phenomenon: An error reporting an empty file field is returned when calling the dialogue API and attempting to upload production ledger files. Cause: No file upload permission parameters are configured in `variables`, and the corresponding data access module is not enabled.
- Phenomenon: Shortcut buttons in the dialogue interface do not respond after being clicked, and preset ledger query questions cannot be sent directly. Cause: No `messages` trigger logic is bound to the buttons, and no parameter mapping for preset questions is configured.
- Phenomenon: Users cannot view their own historical conversation records in the login-free scenario, and session data is lost. Cause: No user unique identifier is bound via `chatId`, and session data is not stored by user dimension.

## How to Verify Proper Configuration
- Initiate a query that includes cell number and laboratory test date, and check if the returned ledger data matches the preset query dimensions.
- Switch sessions for different production shifts, and confirm that the session isolation rule takes effect, with conversation histories from different shifts not displayed to each other.
- Click preset shortcut buttons, and check if the corresponding preset content is sent directly without extra input steps.
- Upload a single production ledger file, and confirm that the API returns a non-empty file field, with the data access process operating normally.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
