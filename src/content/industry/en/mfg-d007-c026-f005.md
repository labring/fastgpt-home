# Production Ledger Summary and Report Generation for Non-Ferrous Metal Smelting and Electrolysis: Tool Calling and Plugins

## What Data for This Category Looks Like
Daily ledgers for this category include batching lists, smelting records, electrolyzer status records, laboratory reports, anode and cathode quality records, and environmental protection ledgers. Data sources include concentrate and auxiliary material analysis reports, tank voltage, current and furnace temperature parameters collected by the DCS system, component test results issued by the laboratory, and energy and environmental monitoring data. Updates are synchronized in real time with each batch of raw materials, each furnace heat, and each electrolyzer. Fields include batch identifiers, process parameters, test indicators, energy consumption and emission values.

## Constraints for Tool Calling and Plugins
Multi-source heterogeneous data sources require plugins to support integration with different types of business interfaces, and pull ledger data from smelting, electrolysis, laboratory, and environmental protection dimensions separately. High-frequency, real-time updates require that single tool call response times stay within a reasonable range, to avoid delays that harm ledger summary timeliness. Ledger fields that are strongly linked to processes require clear mapping rules for corresponding business fields during tool calling, to prevent data misalignment. Demand for batch processing of multiple ledgers requires plugins to support pulling data in groups by furnace heat or tank group, reducing context load for single calls.

## How to Set Configurations
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapt to the demand for automatic tool selection for multi-source ledger data, matching the scenario of pulling data from multiple links in this category |
| `functionCall` | Enabled | Support precise calling of corresponding business plugins to complete accurate mapping and summary of smelting ledger fields |
| Plugin data source mapping rules | Configured separately by DCS, laboratory, and environmental monitoring | Match the multi-source heterogeneous data source characteristics of this category, avoiding data misalignment across sources |
| Batch call batch size | 5–10 furnace heats/tank groups per batch | Adapt to the high-frequency update rhythm, controlling the context load of a single tool call |
| Call timeout threshold | 60–120 seconds | Match the demand for pulling real-time ledger data, avoiding summary interruptions caused by timeouts |
| Plugin retry count | 2–3 times | Address occasional fluctuations in industrial data interfaces, ensuring the stability of ledger pulling |
| API call token verification configuration | Bound to a dedicated verification key | Match the security access requirements of industrial systems, preventing unauthorized access |

## Three Common Misconfigurations
- Phenomenon: Tool calling returns empty results. Cause: The plugin's data source mapping rules are not correctly configured, leading to failure to match the exclusive business fields of non-ferrous metal smelting ledgers.
- Phenomenon: Calling fails after `functionCall` is configured, with a parameter mismatch error returned. Cause: The input parameter structure of the function call is not adjusted according to the field format of the smelting ledger, leading to incompatibility with business data.
- Phenomenon: MCP service proxy endpoint configuration is invalid, or API call token verification fails. Cause: The endpoint address is not pointed to the business interface of the corresponding electrolysis workshop, or the correct dedicated verification key is not bound.

## How to Confirm Proper Configuration
- Manually trigger a tool call to pull smelting ledger data for a single furnace heat, and verify that the returned fields include corresponding identifiers for batching lists and smelting records.
- View the plugin call log to confirm that the automatic mode configured by `toolChoice` correctly matches the data source type, and that `functionCall` is enabled normally.
- Test batch calling ledger data for 10 tank groups, confirming that no timeout or data misalignment issues occur.
- Verify connectivity of the MCP service proxy endpoint, confirm that real-time electrolyzer status parameters can be pulled normally, and that API token verification passes.

The values provided are common starting points and should be measured against the reader's own samples.
