# Production Ledger Summary and Report Generation for Garment Cutting and Sewing: Tool Calling and Plugins

## What this category’s data looks like
Data for this category primarily comes from orders and size charts, CAD patterns, fabric and accessory inspection records, hanging system data, needle detector test results, and customer sample sealing requirements. Daily generated documents include process sheets, patterns, layout plans, cutting lists, first article sample records, process quality tables, and packaging and size matching lists.
Data updates follow the rhythm of per order, per style, per batch. There are many styles with strong seasonality. Fabric cut pieces are irreversible. Most processes are manual operations. Matching of fit, size, and packaging ratios is required.

## What constraints do these characteristics impose on tool calling and plugins
Data sources are scattered across multiple systems and files in different formats. Tool calling must connect to multiple data source interfaces, and adapt to different file formats exported by CAD and hanging systems.
High-frequency updated order and batch data require tool calling to support batch triggering, to avoid delays from single-item processing. The irreversible nature of cut pieces requires that ledger data output by tools accurately match batches and sizes, to avoid batch deviations.
In scenarios with dense manual processes, tools must support extracting quality inspection data from process quality tables. During summarization, inspection records for corresponding cut pieces must be associated. Format conversion for multi-dimensional fields must also be handled, such as standardized mapping of sizes and color batches.
All these constraints are compatible with FastGPT v4.17.0’s tool calling and plugin logic.

## Three common mistakes
- Phenomenon: Batch execution nodes complete the full process during online debugging, but fail to execute all loop batches during API calls. Cause: Group triggering rules for batch nodes are not configured. A single call only runs a single batch loop, and does not trigger grouped by order batches.
- Phenomenon: After calling the workflow API, running data fields in the conversation log are empty. Cause: The data return switch is not enabled in plugin configuration. Intermediate results from tool calling are not written to log storage.
- Phenomenon: After a custom plugin runs, the output download address fluctuates repeatedly before returning the final result. Cause: The plugin does not synchronously wait for file generation to complete. It returns a temporary link first, then updates to the official download address, causing front-end status fluctuations.

## How to confirm the configuration is correct
- Trigger a test call for a single order, and check if the returned ledger data includes the cutting list and process quality table fields corresponding to that order.
- Call the API for the batch execution node, and check if the returned batch processing count matches the preset group count.
- View the conversation log of the workflow, and confirm that intermediate results from tool calling have been written to the corresponding fields.
- Test the download link generated by the plugin, and confirm that the associated business documents can be downloaded normally.
