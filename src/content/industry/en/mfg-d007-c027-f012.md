# Production Ledger Summary and Report Generation for Garment Cutting and Sewing: Deployment and Upgrade

## What data for this category looks like
Data for this category typically comes from order and size charts, CAD patterns, fabric and accessory inspection records, hanging system data, needle detector test results, and customer sample-sealed documents. Daily used documents include process sheets, patterns, layout plans, cutting orders, first-piece sealed samples, process quality sheets, and packaging size-matching sheets.
Data updates follow the rhythm of each order, each style, and each batch. Cut pieces for a single style are irreversible, and most processes rely on manual work. Common data fields include size, fabric batch number, process quality inspection results, packaging ratio, and more. There is no unified cross-factory standard format.

## What constraints these characteristics impose on deployment and upgrade
High-frequency batch data updates for this category require deployment to support dynamic loading of datasets for individual orders or styles, to avoid the time cost of full indexing.
Multiple types of non-standard documents, such as CAD patterns and process quality sheets, require deployment configurations to support multi-format parsing, especially extraction of structured tables and vector graphics.
The irreversible nature of cut pieces requires that traceability fields in ledger data are complete and cannot be altered. Strict data storage verification must be configured.
Strong seasonality and fast style iteration require that upgrade processes do not interrupt running ledger generation tasks, and support quick switching of business datasets.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `100–150` | This category associates multiple documents with each batch of orders. Database connection count must support bulk data reading, and align with the connection pool rules of FastGPT v4.17.0 |
| `REDIS_URL` | `Local port 6379, calibrated via actual testing` | High-frequency ledger generation requires caching of layout plans and process data. Local deployment reduces cross-node transmission latency |
| `STORAGE_S3_ENDPOINT` | `Intranet storage node address, such as http://192.168.1.100:9000` | Files such as CAD patterns and cut piece images for this category have large file sizes. Intranet storage reduces upload and download latency |
| `ROOT_KEY` | `32-character random string` | Strong secret keys are required for admin backend permission control, to prevent unauthorized access to ledger configurations and business data |
| `FILE_TOKEN_KEY` | `Signature key consistent with the local storage service` | Legitimacy of uploaded documents such as process sheets and packaging size-matching sheets must be verified, to prevent malicious files from being imported into datasets |

## Three common errors
- Symptom: After local Docker deployment, other applications cannot call the FastGPT API. Cause: `FE_DOMAIN` was not configured as a locally accessible public or intranet address, leading to cross-origin request blocking.
- Symptom: After importing datasets such as fabric inspection sheets and process quality sheets, the system stays in the indexing state for an extended period. Cause: `DB_MAX_LINK` was not adjusted to support bulk document parsing. Database connection pool exhaustion causes indexing blocking.
- Symptom: After deploying a local rerank model, API calls return authentication failure. Cause: `FILE_TOKEN_KEY` was not replaced with the security credential key for the rerank service, leading to failed Bearer token verification.

## How to confirm the configuration is correct
- Run a local API call test, submit a query instruction for order ledgers, and confirm that returned results include correct process, size, and packaging ratio fields.
- Check database connection logs, confirm that the connection count set in `DB_MAX_LINK` is not continuously fully occupied, and no connection timeout errors occur.
- Upload a CAD pattern file to the dataset, confirm that the number of extracted cut pieces and size information match the original document.
- Attempt to access the admin backend from an unauthorized IP address, confirm that the `ROOT_KEY` configuration takes effect, and direct login to the system is not possible.

The values provided are common starting points, and should be evaluated against the user's own samples.
