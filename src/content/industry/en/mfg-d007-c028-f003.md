# Incoming Material Inspection and Supplier Quality: Production Ledger Summary and Report Generation — Multi-turn Dialogue and Prompts

## What this category of data looks like
This category’s data comes from purchase orders, drawing specifications, supplier quality certificates, inspection equipment, historical quality data, and supplier portals. Daily associated documents include inspection specifications, sampling plans, incoming material reports, supplier audit reports, exception contact sheets, 8D reports, and concession acceptance approval forms.
This data updates on three schedules: synchronization with each batch of incoming materials, monthly or quarterly supplier evaluation updates, and updates triggered by unscheduled audits.
Data fields include batch identification, inspection date, supplier code, non-conformity type, rectification status, and others. There are no fixed unified units, and some fields are linked to original detection values collected by equipment.

## How This Category's Characteristics Impact Multi-turn Dialogue and Prompts
This category’s data comes from multiple disconnected sources: procurement, equipment, supplier portals, with inconsistent update cycles. Multi-turn dialogue must support context association across source data to avoid mixing data across batches and cycles.
There are many types of daily associated documents with clear format differences. Prompts must adapt to field mapping rules for different documents to ensure consistent extraction of ledger fields.
The business must balance supplier quality risk and production supply guarantee requirements. The dialogue flow must support dynamic adjustment of judgment logic to adapt to temporary sampling requirements for each batch of incoming materials and batch summary requirements for quarterly supplier evaluations.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chatId` | Bind to the current incoming material batch ID | Ensure multi-turn dialogue is associated with inspection data for the same batch, avoiding cross-batch confusion |
| `messages` | Enforce validation to standard JSON format | Prevent request failures caused by newline characters in dialogue responses, and adapt to interface parameter format requirements |
| `variables` | Bind to supplier code and inspection specification version | Pass core business parameters to ensure prompts adapt to current inspection rules |
| Context window length | 8000–12000 characters | Cover complete context of multi-batch historical data and current inspection process |
| Multi-turn dialogue trigger rounds | Trigger ledger summary after 3–5 rounds | Match the typical number of steps for a single incoming material inspection in this category |

## Three Common Misconfigurations
- Symptom: The dialogue interface returns an `unAuthChat` status code, even though the API key has been correctly filled. Cause: The supplier data bound to `variables` is not associated with the permission scope of the current session, causing interface verification to fail.
- Symptom: Dialogue response content contains newline characters, causing JSON request format validation for the `messages` parameter to fail. Cause: The mandatory format validation configuration for `messages` is not enabled, and response content is not escaped.
- Symptom: An error is triggered when uploading documents such as incoming material reports and supplier audit reports, but text input dialogue runs normally. Cause: No dedicated document parsing rules are configured for this category, causing non-general document formats such as inspection specifications and 8D reports to fail to be correctly identified.

## How to Confirm Configuration Is Complete
This verification must be performed on FastGPT v4.17.0.
- Initiate a simulated incoming material inspection dialogue, check whether `chatId` is bound to the correct batch ID, and whether the context includes associated supplier information.
- Construct test dialogue content containing newline characters to verify whether the format validation for the `messages` parameter takes effect and whether the request is submitted normally.
- Upload typical documents of this category (such as incoming material reports and 8D reports) to confirm that parsed fields can be correctly extracted via `variables`.
- Initiate 3–5 consecutive rounds of dialogue to check whether the context retains key information from previous inspection steps without cross-batch confusion.
