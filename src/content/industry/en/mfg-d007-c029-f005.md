# Production Ledger Summary and Report Generation for Mold Design and Manufacturing: Tool Calling and Plugins

## What the Data for This Category Looks Like
Data sources for mold design and manufacturing scenarios include customer product models, mold flow or forming simulation results, CAD/CAM files, machining and measurement data, and sample part inspection records. Data updates trigger based on project milestones, and synchronize after each trial mold or mold modification. Daily documents include mold design task sheets, DFM reports, part drawings, machining process cards, trial mold reports, mold modification notices, and mold records. Core fields include mold number, project number, machining dimension parameters, trial mold defect types, and mold modification counts. Units are typically physical quantities and counting units such as millimeters, hours, and counts.

## What Constraints These Characteristics Impose on the Tool Calling and Plugins Link
Data sources are scattered across multiple tool and system types. Plugins must support connecting to multi-format data sources and adapting to mixed inputs such as CAD files and structured reports. Data updates follow no fixed cycle, so plugins must support on-demand triggering to enable immediate data synchronization after individual projects or mold modifications. Documents and fields have specific format and unit requirements. Parameters passed during tool calls must strictly match field names and units to avoid parsing failures from format incompatibility. Collaborative data across multiple links must be unified and summarized during tool calls, requiring plugins to support cross-tool data splicing and format conversion.

## Three Common Misconfigurations
- Plugins fail to load when exporting workflow JSON and importing it to another environment. This happens because only the workflow configuration is exported, and associated plugin dependency files are not synchronized. The target environment will lack the required tool call plugins.
- Tool call return content includes redundant instruction fragments starting with `Human <Instruction>`. This happens because the default system prompt redundant configuration is not disabled, causing irrelevant system instructions to be included during tool calls.
- Parameter exceptions occur when using MCP tools. This happens because specific field units for the mold ledger are not matched. For example, passing millimeter part size parameters as centimeters causes tool parsing failures.

## How to Confirm Proper Configuration
- Test a single tool call, and check if returned results include core mold ledger fields such as mold number, trial mold defect records, and mold modification counts.
- Export the workflow and import it to a test environment, confirm all associated plugins load normally, and no "plugin missing" error prompts appear.
- Trigger a tool call, and check that returned content has no redundant system prompt fragments, and only includes ledger data and report content generated by tool execution.
- Pass test parameters with specific units, such as a 150 millimeter part size, confirm the plugin correctly parses the input and executes the corresponding operation.
