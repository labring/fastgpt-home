# Production Ledger Summarization and Report Generation for Cement Clinker and Grinding Processes: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
This category covers the full cement production workflow from mine batching to grinding and delivery. Data sources include online composition analysis equipment, DCS control systems, laboratories, kiln and grinding equipment, raw fuel ledgers, and energy metering systems. Data update frequencies fall into three categories: real-time (equipment operating parameters), shift-by-shift (inspection records, team operation ledgers), and daily (laboratory reports, quality control notices, and energy summary reports). Daily documents include raw meal batching plans, kiln operation records, laboratory reports, and more. Fields covered include raw material addition rates, firing temperature, grinding fineness, and energy consumption values, with corresponding units of ton, degree Celsius, square meters per kilogram, and kilowatt-hour.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering Workflows by These Characteristics
Data sources for this category are scattered, and update frequencies vary significantly. Multi-turn dialogue must clearly distinguish the context scope of real-time equipment parameters, shift ledgers, and daily summary reports to avoid mixing parameters across time granularities. Daily document types are diverse, so prompts must specify field rules for corresponding documents. For example, separate definitions are required for raw material addition rates in raw meal batching plans and strength indicators in laboratory reports. Some parameter units differ, so prompts must unify unit conversion logic to prevent unit confusion in results. Rotary kiln thermal regime adjustments rely on continuous historical data. Multi-turn dialogue must retain the context of the last three shifts’ operation records to ensure continuity of parameter adjustments.

## Three Common Misconfiguration Issues
- Phenomenon: A Request Time error occurs during dialogue, with a 504 status code. Cause: No reasonable dialogue timeout duration is configured, leading to exceeding the preset threshold when pulling multi-source data for ledger summarization.
- Phenomenon: Unit confusion appears in ledger data fields returned by the dialogue. For example, raw material addition rate values mix tons and kilograms. Cause: Prompts fail to specify unified unit conversion rules and unit format requirements for document fields.
- Phenomenon: Multi-turn dialogue context is lost, and previous ledger summarization requests cannot be continued. Cause: The `chatId` parameter is not bound, generating a new session identifier for each dialogue and preventing association with historical context.

## How to Verify Successful Configuration
- Initiate a multi-turn query that includes real-time kiln and grinding parameters plus that day’s laboratory reports. Verify that returned results link to the unique identifier of the corresponding session.
- Input a vague ledger query requirement. Confirm that the system automatically optimizes the request into a clear field retrieval instruction.
- Initiate a summarization query covering multi-shift ledgers. Confirm that returned results do not have context truncation or unit confusion issues.
- Test three consecutive dialogues on the same topic. Confirm that context continues normally and no session binding failure occurs.
