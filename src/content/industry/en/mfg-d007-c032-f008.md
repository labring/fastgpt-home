# Production Ledger Summary and Report Generation for Complete Vehicle Final Assembly: Document Parsing and Chunking

## What the data for this category looks like
Data sources for complete vehicle final assembly production data include ERP, MES systems, VIN and configuration systems, tightening tools, EOL inspection lines, and quality traceability systems. Daily documents cover production orders, VIN lists, assembly work instructions, tightening data, offline inspection reports, repair records, and consistency release documents.
Data updates are generated in real time per individual vehicle. Some batch data is summarized per shift.
Document structures use VIN as the core associated field. They include standardized configuration items, torque values, inspection results, and batch information. Most fields relate to vehicle identification codes, torque units, and inspection qualification status.

## What constraints do these characteristics impose on document parsing and chunking
The single-vehicle data association logic centered on VIN requires document parsing and chunking to retain the complete binding relationship between VIN and its corresponding configuration and inspection data. It also requires avoiding splitting data across multiple vehicles.
Multi-page long documents require the parsing process to support large file processing and reserve sufficient parsing time.
Real-time tightening data and inspection reports require chunking rules to quickly locate associated data blocks. This prevents delays from affecting ledger summary.
The diversity of structured fields requires parsing tools to accurately extract numerical and status information for specific units.

## How to Configure Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Complete vehicle final assembly documents include long paragraphs of configuration lists and continuous tightening records. This range avoids splitting critical associated fields. |
| `chunkSplitter` | Split by title + paragraph | Documents have hierarchical titles for VIN, workstations, and inspection items. This preserves complete context for individual data entries. |
| `customPdfParse` | Enabled | Structured fields such as embedded VIN codes and torque values require precise extraction. General parsing cannot meet matching requirements. |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Individual offline inspection reports or supplier batch documents may exceed 500 MB. This setting reserves sufficient upload space. |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Parsing several-hundred-page assembly work instructions requires sufficient time to avoid mid-process timeout interruptions. |
| `chunkSettingMode` | Manual configuration | Adjust chunking rules for VIN-associated documents to ensure data for the same VIN is not split.

## Three Common Configuration Errors
- Issue: JSON format errors appear after parsing, with missing fields or abnormal structure returned. Cause: The `customPdfParse` configuration is not enabled. Structured VIN and tightening data cannot be extracted correctly, leading to format errors during splicing.
- Issue: Parsing times out when uploading PDFs with more than 50 pages, and the task fails. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted. The default duration is insufficient to complete full parsing of multi-page documents.
- Issue: Cross-VIN continuous data blocks appear in chunking results. Cause: The `chunkSplitter` configuration is set to split by character count, not by hierarchical title. This causes ledger data for different vehicles to be merged into the same block.

## How to Verify Proper Configuration
- Upload a single 600-page offline inspection report. Check the running duration of the parsing task, and confirm no interruption occurs within the preset time. This verifies that the `PARSE_FILE_TIMEOUT_SECONDS` configuration takes effect.
- Upload a PDF containing a single VIN and its corresponding tightening data. Check that each chunk in the chunking results includes complete VIN-associated information. This verifies that the `chunkSplitter` configuration is appropriate.
- Upload a single 800 MB supplier batch document. Confirm the upload succeeds without interception. This verifies that the `UPLOAD_FILE_MAX_SIZE` configuration is correct.
- Review parsing logs. Confirm no prompts for failed structured field extraction appear. This verifies that the `customPdfParse` function operates normally.

The values listed above are common starting points and should be evaluated against the user’s own samples.
