# Production Ledger Summary and Report Generation for Complete Vehicle Final Assembly: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Production data sources for complete vehicle final assembly scenarios include ERP/MES systems, VIN and configuration systems, supplier batch management systems, tightening tool terminals, EOL inspection lines, and quality traceability systems. Daily production documents include production orders, VIN lists, assembly work instructions, tightening torque data, offline inspection reports, rework records, and consistency release documents.
Data updates occur in real time per vehicle, or in batch sync per shift. In mixed-line production modes, the same workstation handles assembly tasks for multiple vehicle models at the same time. Each complete vehicle’s associated documents usually use VIN as the unique identifier, and include structured and unstructured content such as configuration parameters, part batches, and workstation operation records. Fields cover dedicated production parameters like torque values, inspection thresholds, and rework workstation numbers.

## What constraints do these characteristics impose on the knowledge base retrieval and recall link
Production data for complete vehicle final assembly uses VIN as the core identifier. Mixed-line production scenarios require simultaneous retrieval of associated documents for multiple vehicles. Retrieval must accurately match VIN keywords and semantic content to avoid mixing unrelated data across vehicles.
Real-time updated tightening and inspection data requires the retrieval pipeline to have low latency, to prevent data lag in ledger summary.
Multi-source and heterogeneous document types require the retrieval system to support both structured field matching and unstructured text retrieval, to ensure coverage of content in different formats such as work instructions and inspection reports.
Each complete vehicle has a large number of associated documents. The number of retrieval results and their sorting priority must be controlled, to avoid redundant data affecting report generation efficiency. Retrieval result traceability information must also be complete, to meet production traceability requirements.

## How to set the configuration
| Configuration item | Recommended value | Rationale for this value |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Accurately match VIN and core production fields, filter low-relevance cross-workstation documents, and prevent incorrect associations in ledger summary |
| `limit` | Top 10 entries | Core associated documents for a single complete vehicle usually do not exceed 10 items. The top 10 entries cover key content such as tightening data, inspection reports, and release documents |
| `searchMode` | `mixedRecall` | Match both VIN keywords and semantically similar work instruction content, to meet the needs of multi-document associated retrieval in mixed-line production scenarios |
| `usingReRank` | Enabled | Document similarity from different workstations is close in mixed-line production scenarios. Reranking improves the sorting priority of key torque and inspection data |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expand retrieval to associated documents such as supplier batches and rework records based on VIN, reducing omissions from manual input |
| `collectionIds` | Enter the dedicated knowledge base collection ID for the final assembly workshop | Isolate production documents from different workshops, to prevent historical data from unrelated workshops from interfering with retrieval results for the current workstation |

## Three common mistakes
- Symptom: The response does not include traceability information such as source document names and chapters. Cause: The document traceability switch for the knowledge base is not enabled in FastGPT v4.17.0, or retrieval parameters are not configured to return source data fields.
- Symptom: When calling the `/api/v1/chat/completions` interface, no uploaded knowledge base content is retrieved after specifying appId. Cause: The target knowledge base’s `collectionIds` are not bound to the corresponding appId, or dataset-related configurations are not correctly passed in the interface request.
- Symptom: Image content from documents is not included in retrieval results. Cause: The image vectorization configuration for the knowledge base is not enabled, or output rules for image content are not configured during the generation phase.

## How to confirm the configuration is correct
- Submit a retrieval request for a specific VIN, and check whether the returned results cover associated documents such as production orders and tightening data corresponding to that VIN.
- View the metadata fields of retrieval results, and confirm that traceability information such as source document names and affiliated collections is included.
- Call the test interface for the appId bound to the target knowledge base, and verify that all document types uploaded to that knowledge base can be retrieved.
- Submit a retrieval request for a work instruction that includes embedded images, and check whether the returned results include content identifiers related to images.

The values provided are common starting points, and should be evaluated against the reader’s own samples.
