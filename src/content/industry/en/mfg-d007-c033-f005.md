# Batch Automotive Component Manufacturing: Production Ledger Summary and Report Generation - Tool Calling and Plugins

## What data looks like for this category
Data for this category comes from multiple business carriers of automotive component suppliers focused on braking, steering, and similar parts. Daily documents include control plans, process flowcharts, work instructions, first-piece and patrol inspection records, SPC reports, PPAP materials, and 8D reports. Data sources include customer drawings and special characteristic lists, ERP/MES systems, measuring tool data, equipment process parameters, and supplier quality certificates. Data is updated per batch, per shift, and via continuous collection. Fields include batch number, inspection dimensions (mm), torque parameters (N·m), inspection time, abnormal records, and more. All data must strictly match customer special characteristic requirements.

## Constraints on tool calling and plugin workflows
Data characteristics for this category impose multiple constraints on the tool calling and plugin workflow. Multi-source heterogeneous data requires calling different plugins to pull production data from ERP/MES systems, inspection data from measuring tools, and special characteristic requirements from customer drawings. This requires adapting to the API formats of different data sources. Frequently updated characteristics require tool calling to bind real-time data trigger logic for production lines, to avoid delays. Diverse document types require configuring multi-format parsing plugins to handle files with different structures such as control plans and SPC reports. Additionally, strict compliance with customer quality system constraints is required, to ensure ledger fields fully match customer special characteristics, and that field names or formats are not adjusted arbitrarily.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Workflow/API tool selection | `auto` | Adapts to automatic calling needs for multiple tool types, no manual specification of individual plugins required |
| Workflow/API function-call configuration | `enabled` | Enables function call capabilities, supports cross-plugin summarization of multi-source production ledger data |
| Tool call trigger timing | After each batch completes production | Matches the per-batch data update frequency of this category, ensures ledger data aligns in real time with current production |
| Knowledge base binding scope | Bind the dedicated knowledge base for the current production line | Follows the strict constraints of customer quality systems, enables data isolation and precise matching |
| API call timeout | `120 seconds` | Adapts to the average time required to pull data across ERP, MES, and measuring tool systems, prevents call interruptions |

## Three Common Configuration Errors
- Issue: API calls return a "knowledge base ID not found" error with status code 404. Cause: The knowledge base ID for the corresponding production line is not configured as a global variable, or the passed parameter format does not meet system requirements.
- Issue: Generated production ledgers lack fields related to customer special characteristics, with empty results or incomplete fields. Cause: The data source associated with customer drawings and special characteristic lists is not specified in the tool call configuration, so corresponding fields cannot be pulled.
- Issue: Tool calls time out, with task status marked as failed. Cause: No reasonable timeout period is set, and multiple cross-system plugins are called simultaneously, exceeding the system's default wait duration.

## How to Verify Successful Configuration
- Trigger a single tool call, check if the returned production ledger data includes core fields for specified documents such as control plans, patrol inspection records, and SPC reports.
- Review API call logs, confirm that the passed knowledge base ID matches the global variable configuration, with no format errors.
- Simulate production line abnormal data to trigger tool calls, verify that root cause analysis-related plugins are automatically called to generate corresponding reports.
- Check the `toolChoice` parameter setting, confirm that the tool call workflow automatically matches the required data source plugins, with no manual intervention needed.

The values provided here are common starting points, and should be measured against the reader's own samples.
