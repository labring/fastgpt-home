# Batch Automotive Component Manufacturing: Production Ledger Summary and Report Generation - Knowledge Base Retrieval and Recall

## What this category of data looks like
Data sources for production ledgers in this category include customer drawings, special characteristic lists, ERP/MES systems, measurement and inspection tool data, equipment process parameters, and supplier quality certificates. Data updates occur per batch, per shift, or via continuous collection, covering full process records for core components such as braking and chassis parts. Daily documents include control plans, process flow diagrams, work instructions, first-piece and patrol inspection records, SPC reports, PPAP materials, and 8D reports. Fields include process number, characteristic value, tolerance range, equipment number, batch number, and inspection results. Units follow industry-standard metrology conventions such as millimeters, newtons, and hours.

## Constraints on knowledge base retrieval and recall
Multiple scattered data sources require the retrieval link to associate multiple independent datasets, to avoid missing critical ledger information across systems. Frequently updated data requires configuring incremental recall logic to prevent excessive resource usage from full retrieval. Mixed document types require adapting chunking rules for different documents, ensuring that step descriptions in work instructions and numerical data in SPC reports can be accurately recalled. Specific business fields require retrieval to match exact fields, prioritizing business content that includes specific fields such as batch number and tolerance range. It must also comply with the quality system constraints of vehicle customers, prioritizing documents related to special characteristics.

## Configuration settings

Choose a retrieval mode through representative-query testing; configure category, batch, or entity filters separately because the mode itself does not enforce those boundaries.
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Automotive component characteristic parameters have high precision requirements, so low-match irrelevant ledger data must be filtered to avoid invalid information being included in summary reports |
| `limit` | Top 10–15 entries | Batch manufacturing generates large volumes of ledger data, so the context length of a single recall must be controlled to fit the default context limit of FastGPT v4.17.0 |
| `usingReRank` | Enabled | When multiple document types are mixed, basic retrieval sorting cannot adapt to the business priority of SPC reports and PPAP materials. The re-ranking link optimizes result order |
| `datasetSearchUsingExtensionQuery` | Enabled | User requests for ledger summary must be extended to include precise queries for batch number and process number, matching the core requirements of customer special characteristic lists |
| `collectionIds` | Configured by document type group | Different types of ledger documents (such as SPC reports and 8D reports) must be associated separately to enable accurate recall of corresponding business data |

## Three common configuration mistakes
- Phenomenon: Knowledge base search takes longer than 30 seconds, and the interface displays timeout status code 504. Cause: Incremental recall is not configured for frequently updated ledger data, and full retrieval of the entire dataset results in an overly large retrieval scope.
- Phenomenon: Retrieval results do not change after enabling `usingReRank`, and the returned sort order matches basic retrieval. Cause: Re-ranking model call parameters are not configured, or the input length of the re-ranking model exceeds the limit, causing the re-ranking link to not actually execute.
- Phenomenon: General process documents appear ahead of special characteristic lists in retrieval results, which does not meet business priority requirements. Cause: `collectionIds` grouping retrieval is not configured by document type, resulting in mixed recall of documents with different priorities.

## How to confirm the configuration is complete
- Navigate to the knowledge base management page of FastGPT v4.17.0, and check if the associated datasets include target document types such as control plans and SPC reports.
- Initiate a ledger summary query, and check if the `similarity` score of the retrieval results falls within the preset 0.75–0.85 range.
- Manually enable `usingReRank` and initiate the query again, compare the sorting differences between the two results to confirm that the re-ranking link is active.
- Check the retrieval log to confirm that `datasetSearchUsingExtensionQuery` has been triggered, and the query statement includes business fields such as batch number and process number.

The values provided here are common starting points and should be evaluated against the reader's own samples.
