# Production Ledger Aggregation and Report Generation for Baked Goods and Convenience Foods: Workflow Orchestration

## Data profile for this category
This category covers factories producing baked goods, pastries, biscuits, instant noodles and frozen dough products. Daily documents include formula and feeding lists, production records, baking/steaming curves, metal detection records, cleaning and disinfection records, and factory inspection reports. Data is sourced from raw and auxiliary material qualification certificates, ERP/MES systems, weighing equipment, production line sensors, laboratories, and food traceability ledgers. Updates run per batch, per shift, or daily. Data fields include batch numbers, feeding category and weight, processing parameters, allergen labels, inspection results, and shelf life information.

## Constraints on workflow orchestration from these characteristics
The multi-document type, high-frequency updates and batch management features of this category require workflows to support parallel pulling of multi-source data. The need for formula and allergen verification caused by frequent product line changes requires workflows to be configured with conditional branch judgment nodes. Aggregating multi-batch data requires grouping rules defined via `variables` at the batch level. The ready-to-eat product attribute means the accuracy verification step for ledger data cannot be omitted, so a data format verification node must be embedded in the workflow. The daily or shift-based update rhythm requires workflows to be configurable for scheduled triggers, to avoid omissions from manual triggering.

## Configuration guidelines
This page's configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Include batch number, feeding weight (kilograms), baking duration (minutes) | Matches the field and unit characteristics of ledgers for this category |
| Scheduled trigger settings | Trigger daily or per shift, set single trigger interval to 8 hours | Adapts to the batch and shift-based update rhythm of this category |
| Conditional branch node | Set judgment rules based on allergen materials and processing window parameters | Meets the formula verification requirements for frequent line changes |
| `nodeId` | Assign unique identifiers to ERP, oven, and laboratory nodes | Distinguishes multi-source data sources to avoid data aggregation errors |
| Data aggregation node | Aggregate multi-document data by batch | Enables bulk integration of production ledgers |
| MCP service configuration | Bind HTTP response input parameter variables, set timeout threshold to 60 seconds | Adapts to the requirements of pulling data from multiple systems in this category |

## Three common configuration mistakes
- Workflow output uses the `array<object>` format, making readable production ledger reports impossible. This occurs because no text formatting node is added to convert structured data into tables or natural language content that complies with food ledger specifications.
- MCP service cannot add HTTP response input parameter variables. This happens because the corresponding parameter fields are not pre-defined in `variables`, or variable and input parameter mapping binding is not completed in node configuration.
- Clicking the export workflow button results in no response or an error prompt. This is because the workflow's export permission setting is not enabled, or the workflow contains nodes with incomplete configuration.

## How to verify correct configuration
- Trigger the workflow once, check if the output ledger data is grouped by batch and includes core fields such as formulas, production records, and inspection results.
- Attempt to add HTTP input parameter variables for the MCP service, confirm that they can be normally selected and saved.
- Manually trigger the workflow, verify that nodes execute according to scheduled settings or conditional rules.
- Click the export workflow button, confirm that the workflow configuration file can be generated normally.
