# Production Ledger Summary and Report Generation for Welded Structural Component Manufacturing: Deployment and Upgrade

## What this type of data looks like
Welded structural component manufacturing production ledger data originates from design drawings, material quality certificates, welding equipment parameters, welding material warehouse management systems, non-destructive testing systems, and personnel qualification ledgers. Daily documents include welding procedure qualifications, welding procedure specifications, welding material consumption records, welder qualification records, weld inspection reports, and repair orders.
Data updates occur once per weld, per batch of workpieces, or per shift. Fields include workpiece number, weld location, welding material model, welder qualification number, inspection results, and more. Units are mostly engineering standard units such as millimeters, kilograms, and hours.

## What constraints these characteristics impose on deployment and upgrade
Production ledger data for welded structural component manufacturing has scattered sources and high update frequency. During deployment, it is necessary to adapt to multi-source heterogeneous data access, and reserve interface adaptation configurations for corresponding systems.
Daily documents include multiple types of rigid approval records. Deployment must support structured field extraction and verification rule configuration, to ensure automatic verification of rigid constraints such as welder qualification and welding material matching.
The per-weld update requirement means the system must support high-frequency, small-batch data writes. Database connection parameters must be adjusted to adapt to high-concurrency write scenarios.
Association between repair orders and inspection reports requires configuration of field mapping rules to avoid data association errors. During upgrade, existing field mapping configurations must be retained to ensure availability of historical data.

## How to set configurations
The following configuration scheme applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `200–300 connections` | Adapts to high-frequency, small-batch weld-level data writes, avoids database connection exhaustion |
| `MONGODB_URI` | Configure according to the actual address of the business unstructured document library | Stores unstructured original documents such as weld inspection reports and repair orders |
| `PG_URL` | Configure according to the actual address of the structured ledger business database | Stores structured field data such as welding material consumption and welder qualification |
| `REDIS_URL` | Configure according to the local cache cluster address | Caches frequently read welder qualification and welding material model dictionary data, reduces database query pressure |
| `STORAGE_S3_ENDPOINT` | Configure according to the enterprise internal object storage address | Stores original files such as design drawings and material quality certificates |
| `FE_DOMAIN` | Configure according to the deployed front-end access domain name | Ensures normal interaction between front-end pages and back-end services |

## Three common misconfigurations
- Front-end pages spin continuously and fail to load. The symptom is that the browser console returns a `404` status code. The cause is that the `FE_DOMAIN` configuration does not match the actual deployed front-end access domain name, resulting in incorrect static resource request paths.
- Local storage welding material warehouse data cannot be read when used offline. The symptom is that ledger fields are empty. The cause is that `STORAGE_S3_ENDPOINT` is not configured to point to the local storage path, resulting in failure to load local file data sources in offline mode.
- Database write timeout occurs after deployment. The symptom is that `connection timeout` errors appear in logs. The cause is that the value of `DB_MAX_LINK` is too low, and cannot support high-frequency data write requests for each batch of workpieces.

## How to verify a complete configuration
- Access the configured `FE_DOMAIN` address, confirm that the front-end page loads normally with no resource loading failure prompts.
- Submit a simulated welding material consumption record, check whether structured data is generated in the corresponding database, and verify the validity of connections for `PG_URL` and `MONGODB_URI`.
- Trigger a ledger summary task, confirm that weld inspection report and repair order data can be associated, and verify that the field mapping rule configuration is correct.
- Check the cache service status corresponding to `REDIS_URL`, confirm that frequently read dictionary data has been cached, reducing database query pressure.

The values provided are common starting points and should be measured against the reader's own samples.
