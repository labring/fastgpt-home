# Production Ledger Summary and Report Generation for Production Planning and Shop Scheduling: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data sources for this category include ERP orders and inventory, BOM lists, process routes, equipment capacity, staff shifts, work-in-progress inventory, and supplier delivery information. Daily processed documents include sales orders, master production schedules, material requirement plans, weekly and daily scheduling sheets, work orders, material shortage lists, and delivery change notices. Data is updated daily, weekly, or triggered by orders or abnormal events. Document fields include process number, capacity unit, delivery date, material code, inventory quantity, and more. Some fields require matching cross-department collaborative data formats.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
Decentralized multi-source data requires multi-turn dialogue to gradually guide users to clarify specific document types and query scopes, to avoid invalid matching across data sources. Non-fixed update frequencies mean prompt engineering must support dynamic calls to the latest order, scheduling, or abnormal data. A data time range confirmation step must be added to the dialogue flow. Cross-departmental differences in field format requirements mean the dialogue link must preset basic field verification rules, to reduce query deviations caused by format mismatches. Additionally, this category requires handling detailed dimensions such as processes and capacity. Multi-turn dialogue must support gradual breakdown of complex requirements, such as first confirming the statistical cycle, then clarifying the resource types to be summarized.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Dialogue context window | First 10 turns of dialogue or 8000–12000 characters | Must accommodate long-text interactions related to multi-turn production planning and scheduling, to avoid loss of critical context |
| `variables` preset variables | Fixed options including statistical cycle, document type, and resource type | Quickly guide users to clarify query scopes, reducing invalid interactions |
| `messages` initial prompt | Pre-opening script including data source descriptions and field verification rules | Align with the document and data characteristics of this category, reducing user input deviations |
| `chatId` binding rule | Bind to a dedicated index for the corresponding workshop or production planning group | Ensure the dialogue only calls ledger and scheduling data for this group, avoiding confusion across group data |
| Single query return limit | Top 3 matching documents | Adapt to the single data volume of work orders and scheduling sheets, avoiding returning excessive redundant information |
| Context timeout period | 600 seconds | Allow sufficient time for cross-department data collaboration queries and organization |

## Three common mistakes
- A 404 status code (no body) is displayed in the dialogue interface. The cause is failure to correctly bind the dedicated index for production planning and shop scheduling, or unconfigured data source permissions in the model call link.
- No preset multiple optional questions are shown in the dialogue opening. The cause is failure to add guiding preset options in the `messages` initial prompt, leading users to need to decompose complex ledger summary requirements on their own.
- A prompt reading "No available index model detected" pops up after refreshing the page. The cause is that the index model binding configuration was not persistently saved, or a background index update task experienced an abnormal interruption.

## How to verify correct configuration
- A test dialogue is initiated, a preset query requirement is entered, and confirmation is made that the opening displays multiple preset optional questions.
- Dialogue return results are reviewed, confirmation is made that the results include source metadata for the corresponding documents, and that the content can be traced back to original documents such as work orders or scheduling sheets.
- The dialogue page is refreshed, confirmation is made that the "No available index model detected" prompt does not appear, and that the index information bound to the session is not lost.
- A query request containing abnormal parameters is simulated, confirmation is made that the dialogue flow will guide users to correct or supplement necessary query information.
