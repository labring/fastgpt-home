# Production Ledger Aggregation and Report Generation for Electric Motor and Generator Manufacturing: Workflow Orchestration

## What data looks like for this category
Data for this category originates from electromagnetic design databases, copper wire and insulating material batch ledgers, winding equipment logs, balancing machine outputs, electrical test bench records, and ERP/MES systems. Daily outputs include winding process cards, insulation treatment records, dynamic balance reports, withstand voltage insulation test reports, and type and factory inspection reports. Data updates occur per single motor, each production batch, or each type change. It includes fields such as winding turns, insulation layer thickness, dynamic balance offset, test voltage value, and equipment operating duration, and links to material batches and production equipment numbers.

## What constraints these characteristics impose on workflow orchestration
Data sources for this category are scattered across multiple types of production equipment and management systems. Updates trigger when single unit, batch production, or type changes complete. Workflows must support execution triggered by production events, not fixed-cycle scheduling. Daily documents include multi-dimensional structured fields. Workflows must enable cross-node data pulling, field verification, and associated aggregation to avoid missing core indicators such as winding turns and insulation parameters. Production abnormalities carry severe consequences, so workflows must include node error capture and retry logic to ensure aggregation results are accurate and timely.

## How to Set Configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Trigger Mode | Trigger by production events, bind to ERP/MES production completion callbacks | Data updates follow completion of single unit/batch production or type changes, to avoid unnecessary execution |
| Global Variable Configuration | Enable the `variables` parameter, store motor batch numbers, models, and test numbers | Multi-dimensional associated data needs to be passed across nodes, to support result aggregation for batch tasks |
| Node Error Capture | Enable error capture, configure 3 retry attempts with a 60-second retry interval | Temporary abnormalities in production links have a relatively high probability, and automatic retries can reduce task failure rates |
| Batch Execution Node | Set result aggregation to link to `nodeId`, append loop sub-item results to global variables | Each production record in the loop node needs to be passed to the aggregation node |
| Model Thought Control | Switch based on task type: disable thought for structured report generation, enable thought for anomaly analysis | Avoid unnecessary thought consumption to ensure report generation efficiency |
| Field Verification Rules | Configure required fields as winding turns, insulation thickness, and withstand voltage test values | Core production document fields cannot be missing, to ensure the accuracy of aggregated reports |

## Three Common Misconfigurations
- Symptom: After batch execution completes, sub-item results from the loop node do not appear in the global variables. Cause: The append logic for global variables was not configured, and only the result of the last sub-item was overwritten.
- Symptom: The model node always has thought enabled, and cannot be turned off per task requirements. Cause: The interface's "show thought process" switch was mistakenly used as the thought control switch, and the correct configuration item was not used to switch thought state.
- Symptom: No retry is triggered after a node error, and the task terminates directly. Cause: Node error capture configuration was not enabled, or the retry parameter was set to 0 attempts.
