# Production Ledger Summary and Report Generation for Battery PACK and Energy Storage System Integration: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Production ledger data for this category comes from cell capacity grading data, MES systems, welding equipment, torque tools, BMS software version records, and EOL test benches. Data updates occur each time a battery pack or energy storage cabinet is produced, and each time a BMS software version is changed. Daily documents include grouping rules, BOM lists, welding and torque records, BMS flashing records, insulation and voltage withstand reports, EOL test results, and system configuration lists. A single ledger includes fields such as cell batch number, welding torque value, test voltage, and configuration version number.

## Constraints imposed by these characteristics on multi-turn dialogue and prompt engineering
Data is scattered across multiple types of equipment and systems. Multi-turn dialogue must clearly specify field mapping rules for each data source to avoid information misalignment. Update frequency is high, with new data generated for each produced device unit. Dialogue context must limit valid data ranges to prevent redundant information from interfering with results. Document formats vary widely, with distinct differences in the structure of grouping rules and test reports. Prompt engineering must distinguish processing logic for different document types. BMS configuration and test data are closely linked. Multi-turn dialogue must associate corresponding data by batch or cabinet number to avoid cross-batch confusion.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum context entries | 15–25 | Associated ledger data for a single device typically does not exceed 10 entries. 15–25 entries can cover recent batch, test, and configuration records, avoiding context overload |
| Context reference rule | Only reference data from the current batch/cabinet number | Based on the characteristic that category data is updated by batch, limit the context to only reference ledgers from the same batch to prevent cross-batch confusion |
| Prompt variable binding | Bind the batch number field in `variables` | Based on the characteristic of scattered data sources, automatically populate ledger data for the corresponding batch via variables, reducing manual input |
| Dialogue completion reason storage | Associate with `chatId` context | Based on the requirement for subsequent components to reference completion results, store dialogue completion reasons in the context associated with the conversation ID for use by subsequent nodes |
| Loop trigger condition | Calibrate via actual measurement | Based on differences in test pass rates across production lines, adjust trigger conditions via loop judgment results to adapt to actual production rhythms |

## Three Common Misconfigurations
- Phenomenon: When the maximum context entries are set to 30, only 2 context entries appear in the dialogue details, and replies cannot associate historical ledger data. Cause: The context loading rule for the `messages` parameter is not correctly bound, or persistent storage of dialogue context is not enabled.
- Phenomenon: After setting circular ledger generation logic, the process cannot be triggered to regenerate or terminate based on classification results. Cause: The loop judgment condition is not bound to the result field in `variables`, and clear loop termination trigger rules are not configured.
- Phenomenon: Fields with spaces in prompt engineering (such as "insulation and voltage withstand report") cannot be correctly identified, leading to missing corresponding data in ledger summaries. Cause: The prompt engineering does not clearly specify matching rules for space-separated fields, and does not adapt to field names with spaces in category documents.

## How to Verify Correct Configuration
1. Log in to the FastGPT v4.17.0 platform. A test batch number is manually entered to trigger a dialogue. The context is checked to ensure it only displays ledger data for the specified batch, confirming the context reference rule is active.
2. Circular generation logic is triggered. Ledger content that does not meet grouping requirements is input, and the dialogue is confirmed to regenerate content. Ledger content that meets requirements is input, and the dialogue is confirmed to terminate, verifying the loop configuration is active.
3. The prompt engineering is edited to add a field with spaces. The generated ledger is checked to confirm it correctly identifies the field, verifying the space recognition configuration for prompt engineering is active.
4. The context associated with the dialogue's `chatId` is viewed. The dialogue completion reason is confirmed to be stored for use by subsequent components, verifying the completion reason reference configuration is active.
