# Production Ledger Summary and Report Generation for Battery PACK and Energy Storage System Integration: Deployment and Upgrade

## What the data for this category looks like
Data sources for this category include cell grading equipment, production MES systems, welding and torque tools, BMS software, and EOL test benches. Data updates run once per battery pack or energy storage cabinet produced, and sync each time the BMS software version changes. Daily documents include grouping rules, BOM lists, welding torque records, BMS flashing logs, insulation and voltage withstand reports, EOL test reports, and system configuration lists. Fields cover cell grading parameters, torque values, test voltages, software version numbers, and other metrics, with units including newton meters, volts, and similar units.

## What constraints these characteristics impose during deployment and upgrade
This category’s data is dispersed across multiple sources. During deployment, the system must adapt to the communication protocols and data formats of different devices, and reserve configuration space for connecting multiple data sources. Data updates happen at a high frequency, and single-time data volume fluctuates with the test records of each individual product. During deployment, elastically adjustable storage and processing thresholds must be configured to prevent data backlog. Document types include structured lists and unstructured test reports. During deployment, parsing rules adapted to all document types must be preset in advance. System errors can cause thermal management failures or shutdowns. During upgrades, version rollback and verification mechanisms must be configured to maintain production continuity.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `REDIS_URL` | `redis://:custom password@deployment address:6379/0` | This category’s data is updated frequently. Redis is used to cache frequently accessed device data and production ledger cache. An independent database must be configured to avoid data interference. |
| `STORAGE_S3_ENDPOINT` | `http://minio.example.com:9000` | Production ledger documents and test reports require large-capacity, highly reliable storage. S3-compatible local storage services are adapted to meet high-frequency write requirements. |
| `DB_MAX_LINK` | `20–30` | The single production data volume of this category fluctuates greatly. The number of database connections must be limited to avoid resource exhaustion. The specific value is calibrated based on actual testing. |
| `FILE_TOKEN_KEY` | `32-bit random encrypted string` | Uploaded test reports and BOM files must be encrypted to protect against unauthorized access, and adapted to the permission verification requirements of multi-document uploads. |
| `ROOT_KEY` | `Configured according to internal enterprise security specifications` | This system involves core production data. A root key must be used to manage administrator permissions to ensure the security of configuration modifications. |

## Three common misconfigurations
- Scenario: An error indicating file size limit exceeded is prompted when uploading large files such as insulation and voltage withstand reports, and the upload cannot be completed. Cause: The file upload size limit parameter was not configured when starting the container. The default threshold cannot adapt to the volume of a single test report for this category.
- Scenario: After upgrading FastGPT v4.17.0, the version number displayed by the system does not match the actual deployed version. Cause: The front-end static resource package was not replaced correctly, or the environment variable `FE_DOMAIN` was not synchronized to the new deployment address.
- Scenario: When batch importing ledger data for multiple sets of products, some BMS flashing record fields are empty. Cause: The field mapping rules for multiple data sources were not configured. Field names exported by different devices are inconsistent, so the system cannot match the data correctly.

## How to confirm the configuration is correct
- Upload a standard insulation and voltage withstand report, check whether the file can be stored normally and displayed in the ledger, and adjust the file size limit configuration based on the upload result.
- Perform a version upgrade operation, check whether the version number displayed on the system interface matches the version identifier of the deployment package, and confirm whether the configuration of environment variables such as `FE_DOMAIN` takes effect.
- Import 10 sets of simulated production ledger data, check whether each field can be matched correctly and generate a summary report, and verify whether the field mapping configuration for multiple data sources is correct.
- Check the Redis connection number monitoring, confirm that the current connection number does not exceed the configured value of `DB_MAX_LINK` to avoid abnormal resource occupation.
