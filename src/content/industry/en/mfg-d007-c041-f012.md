# Production Ledger Summarization and Report Generation for Electroplating and Chemical Surface Treatment: Deployment and Upgrade

## What the data for this category looks like
Production data sources for this category include customer surface treatment specifications, bath test results, rectifier operation data, online water quality monitoring data, and hazardous waste management ledgers. Daily documents include bath analysis records, process parameter cards, fixture usage records, film thickness and adhesion reports, hazardous waste ledgers, and wastewater monitoring records. Data updates occur per bath cycle, per shift, or at fixed monitoring intervals. Fields include bath concentration, treatment temperature, current intensity, film thickness values, discharged pollutant concentrations, with corresponding industry-standard units of g/L, ℃, A, μm, mg/L.

## What constraints these characteristics impose on deployment and upgrade
This category’s data is multi-source, heterogeneous, and has uneven update frequencies. Deployments must support multiple data source access and custom parsing rules to adapt to ledger documents in different formats. Hazardous waste and wastewater data involve compliance management. Upgrades must retain complete data traceability capabilities to ensure ledger traceability. High-frequency updates of single-bath and real-time monitoring data require deployments to configure reasonable storage and indexing strategies to avoid query delays. Process parameters vary across different workshops. Deployments must support custom field mapping to adapt to customers’ personalized document formats.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–200 concurrent connections` | Adapts to the concurrent demand of high-frequency data writes for multiple baths, and avoids database connection exhaustion |
| `MONGODB_URI` | `mongodb://[username]:[password]@[host]:27017/electroplating?authSource=admin` | Stores unstructured process documents and ledger data, supports flexible field expansion to adapt to different customers' process parameters |
| `PG_URL` | `postgresql://[username]:[password]@[host]:5432/electroplating_logs` | Stores structured fixture records, wastewater monitoring indicators and other data, supports complex conditional queries and statistics |
| `REDIS_URL` | `redis://:[password]@[host]:6379/0` | Caches frequently queried bath parameters and real-time monitoring data to reduce the load pressure on the database |
| `STORAGE_S3_ENDPOINT` | `Configure according to the endpoint provided by local storage or cloud storage service providers` | Stores large files such as uploaded hazardous waste reports and film thickness test reports, adapts to different scenarios of local deployment and cloud deployment |
| `FILE_TOKEN_KEY` | `32-bit random encrypted string` | Protects the access permissions of uploaded files, prevents unauthorized access to sensitive production ledgers |

## Three Common Mistakes
- The symptom is that after uploading a bath analysis record or hazardous waste ledger, the system returns a "file parsing failed" log, and all extracted fields are empty. The cause is that `STORAGE_S3_ENDPOINT` is not configured correctly, or the read/write permissions of the storage directory are not enabled, causing the system to fail to access the uploaded file content.
- The symptom is that after logging in to the cloud version via WeChat scan code, the system prompts "initial password not set" and cannot enter the management interface. The cause is that `ROOT_KEY` was not configured during deployment to generate administrator initial credentials, or the compatible configuration for account password login was not enabled.
- The symptom is that after upgrading to FastGPT v4.17.0, calling the gpt-4o-mini model via the oneapi channel returns "parameter format error". The cause is that after the version upgrade, the parameter verification rules for model calls are updated, and the corresponding parameter items in the channel configuration were not adjusted synchronously.

## How to Verify Correct Configuration
- Log in to the system backend configuration page, check the current configuration value of `DB_MAX_LINK`, and verify whether it matches the preset concurrent connection number.
- Upload a standard-format bath analysis record document, check whether the system can successfully parse and extract the corresponding field information.
- Access the configured `FE_DOMAIN` domain name, verify whether the front-end page can load normally and establish a connection with the back-end service.
- Generate a simulated monthly production ledger report, check whether the system can correctly summarize multi-source data and generate the required output content.

The values given are common starting points and should be measured against the reader's own samples.
