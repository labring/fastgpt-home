# Production Ledger Aggregation and Report Generation for Petroleum Refining: HTTP Interfaces and External Systems

## What data for this category looks like
Petroleum refining production ledgers draw data from DCS/APC control systems, LIMS laboratory information management systems, tank farm metering systems, crude oil evaluation databases, equipment management systems, and energy management systems. Three update frequency categories apply: real-time, shift-based, and daily. These frequencies correspond to process parameters, shift handover records, and daily material balance reports. Daily documents include operating procedures, production plans, material balances, distillate export quality reports, interlock ledgers, shift handover records, and change management documents. Fields covered include unit number, crude oil batch, material flow rate, product distillate indicators, equipment operating status, and more. Data volume shifts dynamically based on query dimensions.

## What constraints do these characteristics impose on the "HTTP Interfaces and External Systems" link
Petroleum refining operations have multi-data source and multi-update frequency characteristics. HTTP interfaces must support both real-time pull and scheduled batch pull modes to adapt to data push or pull habits of different systems.
Different ledger document types have varying field structures. Interface requests must pass dynamic parameters via `variables` to accurately match query conditions for each document type.
Multiple refinery units operate with coupled business logic. The `responseData` returned by interfaces must include cross-unit associated fields to avoid data silos.
Refining operations carry high inherent risk. Interfaces must include authentication, retry, and timeout fault tolerance mechanisms to prevent production risks from interface anomalies.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Bearer {refining system internal API key} | Complies with internal interface authentication specifications of refining enterprises, prevents unauthorized access to core production data |
| `variables` | Bind unit ID, crude oil batch number, shift time range | Matches the multi-dimensional query requirements of refining ledgers, accurately pulls production data for the corresponding time period and unit |
| `responseData` | Extract material flow rate, distillate export quality, interlock status fields | Only retains core data required for ledger aggregation, reduces network transmission overhead |
| Timeout period | 600 seconds | Adapts to real-time data pull delays of systems such as DCS/APC, avoids interrupting data pull processes |
| Request retry count | 3 times | Responds to temporary network fluctuations in tank farm metering systems, ensures stability of data pulling |

## Three common mistakes
- Calling the configured HTTP interface returns a connection error. The interface displays "connection timed out" or status code 500. Cause: The locally deployed FastGPT address was not replaced with a fixed address accessible within the refining enterprise intranet. The `Authorization` authentication parameter was not configured correctly.
- The `responseData` returned by the interface is empty, or does not include the preset core fields of the refining ledger. Cause: The return fields of the refining system were not mapped correctly. Necessary query parameters were not passed in `variables`, causing the interface to fail to match valid data.
- Frequent timeout errors occur when connecting to enterprise messaging bots, and tasks cannot be completed. Cause: The interface timeout period was not adjusted to match the duration required for refining data pulling. The default timeout period is insufficient to cover the time taken for multi-unit data aggregation.

## How to confirm the configuration is complete
- Call the configured HTTP interface within the intranet environment. Check that the returned `responseData` includes preset refining ledger fields such as unit number and material flow rate.
- View the interface logs of FastGPT v4.17.0. Confirm that `Authorization` authentication passed, and no authentication failure errors such as 401 or 403 are present.
- Simulate a shift change scenario. Update the shift time range bound to `variables`, and check that the interface request parameters are updated synchronously.
- Run the interface continuously for 24 hours. Count timeout and retry times, and adjust parameters to fall within the fault tolerance range allowed by the business.
