# Production Ledger Summary and Report Generation for Batch Synthesis in Fine Chemicals: Workflow Orchestration

## Data Profile for This Category
This category covers enterprises producing coatings, resins, additives, agrochemical intermediates, and specialty chemicals. Daily production documents include batch production instructions, material feeding review sheets, reaction process records, cleaning records, inspection reports, and deviation and change orders. Data sources include the formula and process library, raw material batches, reactor DCS, weighing systems, LIMS, and warehouse systems. Updates occur per batch and at each key production step. Core fields include raw material batch number, feeding mass (kilograms), reactor temperature (℃), cleaning inspection items, deviation record number, and more. Single-batch data dimensions cover all process nodes from material feeding to finished product inspection.

## Constraints Imposed on Workflow Orchestration
The multi-variety, multi-step production model that switches between batches requires workflows to trigger based on batch numbers to avoid mixing data across batches. The need to connect multiple data sources requires workflows to pull variables from multiple systems such as DCS, weighing systems, and LIMS simultaneously, and adapt to data formats from different systems. Requirements for formula confidentiality and cross-contamination prevention limit the scope of workflow context transfer. Only data associated with the current batch is allowed to flow between nodes. The high frequency of batch updates requires workflows to have real-time data synchronization capabilities. Verification nodes must be added at key steps such as material feeding and reaction end point judgment to prevent delayed or incorrect data.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Mode | Trigger by batch number | Aligns with batch-based production business logic for this category, and binds to batch production instructions and raw material batches |
| `variables` configuration | Only bind data associated with the current batch | Prevents cross-batch data leakage, and complies with business requirements for formula confidentiality and batch independence |
| Node Execution Order | Linked in the order of production steps | Matches the standard production flow of feeding, reaction, post-processing, and cleaning |
| Failure Retry Count | 2 retries, 60-second interval | Addresses temporary fluctuations in single system calls, and adapts to real-time data update requirements for this category |
| Context Transfer Rule | Only transfer ledger data for the current batch | Avoids mixing fields from different batches, and ensures report data accuracy |
| API Call Timeout | Calibrated based on actual measurements | Adapts to system response speeds across different environments, and prevents workflow interruptions caused by timeouts |

## Three Common Configuration Errors
- Phenomenon: The feeding mass field in the material feeding review sheet is empty in the generated production ledger report. Cause: The data source from the weighing system was not correctly bound to the `variables` configuration, so the node cannot pull the corresponding feeding data.
- Phenomenon: The workflow API call returns a 504 timeout error. Cause: No failure retry mechanism was configured, a single call exceeds the system time limit, and no reasonable timeout fallback logic was set.
- Phenomenon: Ledger data from different batches becomes mixed when workflows are triggered simultaneously for multiple batches. Cause: The transfer scope of `variables` was not restricted, causing context to include associated data from other batches.

## How to Verify Correct Configuration
- Manually trigger a single-batch test workflow, and confirm that the generated report includes data for feeding, reaction, and cleaning records corresponding to that batch.
- View workflow node logs to confirm that each node correctly pulls data sources from the corresponding system, and that `variables` only include fields for the current batch.
- Simulate triggering workflows for multiple different batches, check for data mixing, and adjust context transfer rules until requirements are met.
- Use the FastGPT v4.17.0 workflow debugging tool to call the API, and verify that the returned report format matches the preset ledger template.
