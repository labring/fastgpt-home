# Production Ledger Summary and Report Generation for Batch Fine Chemical Synthesis: Tool Calling and Plugins

## What the Data for This Category Looks Like
Production ledger data for batch fine chemical synthesis comes from the formula and process library, raw material batch records, reactor DCS system, weighing system, LIMS laboratory information management system, and warehouse management system. Data is updated after each production batch and each key process step is completed. Daily ledger documents include batch production instructions, feeding review sheets, reaction process records, cleaning records, inspection reports, deviation and change orders. Core fields include batch number, feeding amount (kg or L), reaction temperature (℃), reaction duration (hours), cleaning validation result, inspection pass rate, and others. Fields and units vary slightly based on process links and raw material types.

## Constraints on Tool Calling and Plugins
The multi-source, heterogeneous ledger data structure of this category requires tool calling plugins to support integration with different types of data source interfaces, and adapt to different data formats such as time-series DCS data and structured inspection data. The data update rhythm tied to batches and steps requires plugin trigger logic to be bound to production batches and process step dimensions, to avoid mixing data across batches. The production mode of switching between multiple product varieties requires plugin parameters to dynamically adapt to ledger field rules for different formulas. In addition, errors in the production process can lead to serious consequences, so tool calling configurations must include failure retry and data verification mechanisms to prevent abnormal data from being included in summary reports.

## How to Configure Settings
| Configuration Item | Recommended Value | Rationale |
|---|---|---|
| `toolChoice` | Auto | Adapt to the automatic identification requirements of multiple types of ledger documents in this category, covering parsing for different links such as feeding, reaction, and cleaning |
| Plugin Trigger Timing | After each batch’s key steps are completed | Match the data update rhythm of this category by steps, to avoid repeated calls or missing data from key links |
| Maximum Number of Entries Returned per Single Tool Call | Top 5 | Correspond to the number of core fields for a single batch ledger, avoiding context overload that affects report generation |
| Call Timeout Threshold | 600 seconds | Adapt to the conventional response duration for pulling reactor DCS data, avoiding long-term blocking of the process |
| `functionCall` | Triggered by preset batch parameters | Bind the batch number as the core input parameter, ensuring that the data pulled by the tool is accurately associated with the corresponding production batch |

## Three Common Misconfigurations
- Phenomenon: Tool calls return empty fields, and logs show no matching target data source records. Cause: The batch number is not set as a required input parameter for plugin calls, making it impossible to locate ledger data corresponding to the current production batch.
- Phenomenon: Tool calls trigger timeouts, returning HTTP status code 504. Cause: The set timeout threshold is lower than the actual response duration of the reactor DCS or LIMS system, failing to adapt to the loading rhythm of data sources in this category.
- Phenomenon: Plugin return results include data from multiple batches, exceeding the context capacity limit. Cause: The number of return entries per call is not restricted, and full historical data is pulled by default, which does not meet the business requirement of single-batch ledger summary.

## How to Verify Proper Configuration
- Trigger the single-batch production ledger summary workflow in the FastGPT v4.17.0 environment, and check if the tool calling logs are bound to the batch number of the current test batch.
- Review the fields returned by the plugin, and confirm that they include core ledger fields for this category, such as feeding amount, reaction temperature, and cleaning validation result.
- Simulate a data source delay scenario, and check if the tool call triggers the preset failure retry mechanism to confirm the retry logic is active.
- Switch the formula type of the test batch, and confirm that `toolChoice` automatically adapts to the ledger field parsing rules for different formulas.
