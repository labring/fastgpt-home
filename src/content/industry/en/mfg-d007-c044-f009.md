# Pulp and Paper Production Ledger Summary and Report Generation: Model Access and Configuration

## What Data Looks Like for This Category
Production ledger data for pulp and paper enterprises comes from wood pulp and waste paper batches, DCS/QCS systems, on-paper machine measuring equipment, laboratories, energy and water treatment systems. Daily documents include pulp blending sheets, beating records, paper machine operation logs, online quality curves, laboratory reports, sheet break and product change records.
Data update frequencies fall into three tiers: real-time, per shift, and per roll. Fields and units vary significantly across different documents. For example, online quality curves include real-time sampling values for grammage, moisture, and thickness. Pulp blending sheets list pulp ratios and batch numbers.

## Constraints Imposed by These Characteristics on Model Access and Configuration
Multi-source heterogeneous ledger data and differentiated update frequencies require model access to adapt to document fragments of varying lengths. This prevents critical data loss due to insufficient context capacity.
High-frequency real-time data updates require configuration options that support fast recall of the latest records. Cross-departmental joint document retrieval requires reasonable configuration of context and retrieval token limits.
Pulp and paper production has strict requirements for report rigor. Model parameters must balance data accuracy and generation efficiency. Improper parameter settings can lead to report deviations or timeouts.

## Configuration Settings
| Configuration Item | Recommended Range | Rationale |
| --- | --- | --- |
| `maxContext` | 8000–12000 token | Pulp and paper ledgers contain multi-source real-time data, historical records, and quality curves, requiring sufficient context fragment capacity |
| `temperature` | 0.2–0.4 | Production ledger reports must maintain rigor, to avoid irrelevant or biased generated content |
| `quoteMaxToken` | 1500–2000 characters | Adapts to the length of single paper machine operation records, pulp blending sheets, or lab reports |
| `AIPROXY_API_ENDPOINT` | Fill in according to the deployed model node | Adapts to connected third-party model services |
| `toolChoice` | auto | Automatically call document retrieval tools to obtain the latest ledger data |
| `maxTokens` | 2000–3000 token | Meets the generation length requirement for a single production summary report |

## Three Common Misconfigurations
- Knowledge base search takes longer than 40 seconds. The interface shows a timeout prompt, or logs return a 408 status code. The cause is either `maxContext` set too small, leading to excessive retrieval fragments, or no reasonable interface timeout limit configured.
- Generated reports do not match web debug results, with missing fields in content returned across platforms. The cause is either `quoteMaxToken` not adapted to the joint retrieval length of multi-department documents, or `toolChoice` not enabled to automatically recall full ledgers.
- Abnormal number of recall results when using the BAAI/bge-large-zh-v1.5 model. Fewer retrieved entries than the preset quantity are returned. The cause is either `quoteMaxToken` not correctly matched to the model's token limit, or `maxContext` not reserving sufficient embedding space.

## How to Confirm Proper Configuration
- Use FastGPT v4.17.0 to import a single pulp blending sheet and paper machine operation log, trigger ledger summary, and verify that the generated content includes all required fields.
- View model call logs to confirm that the response time returned by `AIPROXY_API_ENDPOINT` meets business real-time requirements.
- Adjust the `temperature` parameter, compare report rigor across different values, and determine the applicable range for the current scenario.
- Test cross-departmental data joint retrieval, confirm that `toolChoice` automatically recalls all relevant documents from preparation, pulping, and quality control departments.

The values provided are common starting points and should be measured against the reader's own samples.
