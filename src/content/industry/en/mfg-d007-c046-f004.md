# Production Ledger Summary and Report Generation for Meat Products and Slaughter Processing: Workflow Orchestration

## What Data Looks Like for This Category
Data sources for this category include animal quarantine information, supplier batches, production traceability, temperature collection, metal detection, and laboratory test results.
Daily documents include quarantine certificates, slaughter and cutting records, ingredient marinating records, thermal processing records, cold chain temperature records, and microbial test reports.
Data updates follow three cadences: updated after each production batch completes, updated at the end of each shift, and real-time updates for continuously collected temperature control data.
Fields include batch number, quarantine ID, raw material source batch, temperature value (℃), test results, timestamp, and other fields that must align with quarantine compliance association requirements.

## Constraints for Workflow Orchestration
Multiple scattered data sources require workflows to associate ledger data from different systems by production batch to avoid batch misalignment.
Update cadences per batch and shift require workflow trigger logic to match production node completion points.
Real-time continuous temperature control data requires workflows to support scheduled pulling or event-triggered temperature data synchronization.
Compliance requirements for raw and cooked product zoning and microbial testing require workflows to include built-in field validation rules. These rules block non-compliant ledger data from entering the summary process.
Data association errors or anomalies can lead to compliance risks. Deploy failed retry and exception alert mechanisms to ensure the accuracy and compliance of ledger summaries.

## How to Set Up Configurations
This configuration follows the FastGPT v4.17.0 specification.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Mode | Triggered after a production batch completes | Matches the ledger update cadence for each production batch |
| `variables` configuration | Bind batch number, quarantine ID, and cold chain temperature threshold variables | Associates validation fields for multi-source data |
| Node Timeout Setting | 300–600 seconds | Adapts to return delays from temperature collection and laboratory testing |
| `nodeId` binding | Bind form input node and code execution node IDs | Enables data flow between nodes within the workflow |
| Exception Handling Configuration | Retry 2 times and trigger alerts | Addresses occasional anomalies in multi-source data synchronization |
| Parallel Node Count | Process the first 3 data entries in parallel | Balances operational speed and resource usage |

## Three Common Configuration Errors
- Form input node dialog boxes nested within other workflows are not hidden. Opening the outer workflow will display the pop-up continuously. This occurs because the pop-up trigger rule is not disabled in the nested workflow’s node configuration.
- No ledger data is returned after calling a custom py code function. This occurs because production batch, quarantine ID, and other input parameter variables are not configured in `variables`, so the function cannot read the corresponding data.
- Workflow runtime is too slow. This occurs because the number of parallel processed data sources is not limited. Pulling temperature and test data for multiple batches simultaneously causes node blocking.

## How to Verify Successful Configuration
- Trigger a single production batch workflow to verify that associated data such as quarantine certificates and slaughter and cutting records for the corresponding batch are automatically pulled.
- Check that the `variables` configuration binds core business fields including batch number, quarantine ID, and cold chain temperature threshold, with no omissions.
- Simulate input of abnormal data to confirm that the workflow triggers the preset exception handling process.
- Run multiple identical workflows to verify that parallel node resource usage meets expectations.
