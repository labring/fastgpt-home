# Production Ledger Summary and Report Generation for Meat Products and Slaughter Processing: Document Parsing and Chunking

## What This Category's Data Entails
The primary entities in this category are slaughterhouses, cooked meat and frozen prepared food manufacturers. Daily documents include animal quarantine certificates, slaughter and cutting records, ingredient marinating records, thermal processing records, cold chain temperature logs, microbial test reports, and more.
Data sources cover animal quarantine information, supplier batch ledgers, production traceability systems, temperature collection devices, metal detection equipment, and laboratory test results.
Update frequency follows production batches and shifts. Continuous temperature control logs are updated in real time.
Document structures mostly mix structured fields and free text, with dedicated fields such as quarantine number, batch number, temperature value, test time, and workstation number. Some documents include stamp markings and metadata.

## Constraints Imposed by These Characteristics on Document Parsing and Chunking
Category-specific batch-associated documents must be split accurately. Merging records from different production batches into the same chunk will reduce the accuracy of subsequent ledger summary work.
Continuous temperature control logs are high-frequency, small entries. Chunk length must fit the total length of a single entry or several consecutive entries to prevent truncation of time-series information.
Stamp metadata and key identifiers in quarantine certificates and test reports must be fully retained to meet traceability requirements.
Production records related to raw and cooked product zoning must be split by scenario. This avoids mixing fields related to cross-contamination.
Frequently updated documents must support fast parsing to prevent timeouts that disrupt production schedules.

## Configuration Settings
These settings apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | Fits the field density of multiple document types in this category, avoids splitting cross-batch production records and continuous temperature control entries |
| `chunkSplitter` | Paragraph + semantic chunking | Adapts to document structures mixing structured fields and free text, distinguishes between quarantine certificates, production records, and test reports |
| `customPdfParse` | Enabled | Retains stamp area text and embedded metadata in quarantine certificates and test reports, ensuring key traceability information is not lost |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 seconds | Covers parsing duration for batch continuous temperature control logs, prevents parsing timeouts for frequently updated documents |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Meets upload requirements for batch temperature control logs and test reports in this category, prevents large documents from being blocked |
| `chunkSettingMode` | Manual configuration | Adjusts chunking rules for different document types, adapts to category-specific batch, temperature, and test fields |

## Three Common Configuration Mistakes
- When calling the API to create a knowledge base, real-time feedback on parsing status cannot be obtained. Cause: The status return field of the parsing interface is not connected, and the polling logic to obtain the three states of parsing in progress, ready, and failed is not configured.
- After uploading a cold chain temperature record PDF, a single temperature-time entry is split into multiple chunks. Cause: `chunkSize` is set too small, which forcibly truncates continuous temperature control record entries and destroys time-series relevance.
- Key quarantine number and stamp information are lost after parsing a quarantine certificate. Cause: `customPdfParse` is not enabled, resulting in failure to properly extract embedded metadata and stamp area text from the PDF.

## How to Verify Proper Configuration
- Upload a single animal quarantine certificate PDF. Check if the parsed chunks include complete quarantine number, batch number, and quarantine conclusion fields.
- Upload a batch of continuous temperature control log documents. Confirm that no single complete temperature-time entry is split across chunks, and time-series relevance is preserved.
- Call the knowledge base creation API. Verify that the returned result includes the three status fields: parsing in progress, ready, and failed.
- After enabling `customPdfParse`, check if the parsed result retains stamp area text information from the document.

The values listed above are common starting points and should be measured against the reader's own samples.
