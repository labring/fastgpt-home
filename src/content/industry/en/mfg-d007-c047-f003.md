# Production Ledger Summary and Report Generation for Measuring Instruments and Laboratory Management: Multi-turn Dialogue and Prompt Words

## What data for this category looks like
Data for this category comes from metrology management systems, external calibration institution certificates, standard device data, LIMS systems, and environmental monitoring records. Daily documents include gauge ledgers, calibration plans, calibration certificates, interim verification records, original test records, reference material ledgers, deviation handling forms, and similar items. Data updates are triggered by calibration cycles, each test, or abnormal events. Fields include instrument number, calibration date, measured value, uncertainty, traceability number, environmental parameters, and some fields must use units that meet statutory metrology requirements.

## Constraints on multi-turn dialogue and prompt engineering
The multi-source nature of metrology data requires that dialogue context be strictly limited to the specified business dataset, to avoid interference from unrelated system data. The non-fixed update frequency means support is needed for dynamically pulling the latest calibration records, and prompt engineering must adapt to different types of document structures. Statutory metrology requirements for fields mean prompts must explicitly specify verification steps such as traceability chain and uncertainty review. Data errors will lead to failure of quality judgments, so multi-turn dialogue must retain complete context for backtracking verification.

| Prompt template preset | Fixed inclusion of "instrument traceability chain verification" and "uncertainty review" field requirements | Align with mandatory review steps for metrology management, reducing manual completion work |

## Three common configuration mistakes
- Symptom: When calling a form input node in a nested workflow, the dialog box continues to display, but works normally when called by a single workflow. Cause: The "Hide dialog box during external calls" switch was not turned off in the nested configuration, causing the outer workflow to not override this setting.
- Symptom: The metrology fields bound to `variables` in the prompt configuration are empty, and the generated report lacks calibration uncertainty data. Cause: No mapping rules for specific ledger fields were specified in the variable configuration, causing the system to fail to extract correct data.
- Symptom: Attempting to render web pages or text-to-image content in the dialog box results in the interface not displaying properly. Cause: The "Rich text rendering" switch was not turned on, and allowed media output types were not configured, which does not meet the standard format requirements for metrology reports.

## How to confirm successful configuration
- Initiate a query that includes "calibration certificate traceability chain", and check whether the returned results include the preset metrology fields.
- Switch between nested workflow and standalone workflow modes, and check whether the dialog box display status of the form input node matches expectations.
- View session logs to confirm whether `chatId` is generated according to the "instrument number + calibration cycle start date" rule.
- Test session recovery in timeout scenarios, and confirm whether associated metrology data can load normally.

The values provided are common starting points and should be measured against the reader's own samples.
