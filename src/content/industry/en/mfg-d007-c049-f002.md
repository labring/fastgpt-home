# Production Ledger Summary and Report Generation for In-Process Quality and Finished Product Release: Vector Models and Indexing

## What data for this category looks like
Data sources for this category include MES systems, online inspection equipment, laboratory reports, process parameter documents, customer quality standards, and historical defect databases. Data is collected continuously per production batch and per shift. Some monthly reports update on a set cycle. Daily documents include control plans, patrol inspection records, SPC reports, finished product inspection reports, nonconforming product review forms, release forms, and monthly quality reports. Fields include production batch identifiers, inspection parameters, judgment thresholds, detected values, review conclusions, and more. Units match the corresponding process or quality standard units based on document type.

## What constraints do these characteristics impose on the vector models and indexing workflow
The high-frequency, small-batch data update rhythm requires indexes to support incremental writing and fast synchronization, to avoid performance loss from full reindexing. Mixed types of documents require vector chunking to adapt to different text lengths: both short texts like patrol inspection records and long texts like nonconforming product review forms. Exclusive quality-related fields such as nonconforming item codes and batch identifiers must be bound to the index as metadata, to enable filtering by business dimension during subsequent retrieval. Multiple indexes for the same document chunk must be bound to unified business metadata, so that retrieval results can be aggregated by metadata dimension and avoid duplicate or invalid recall. The strong batch correlation of data requires indexes to support recall associated with production batches, to avoid returning invalid results across batches.

## How to configure settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Chunk length | 800–1200 characters | Adapt to the common text length of patrol inspection records and inspection reports in this category, avoid breaking the logical correlation of inspection results during chunking |
| Chunk overlap length | 100–200 characters | Retain contextual association between adjacent chunks, ensure that inspection items and review comments in long texts are not split |
| Similarity threshold | Calibrated based on actual testing | Adapt to the matching accuracy of quality standards for different enterprises, avoid false recall of nonconforming items or omission of valid historical data |
| Single search result limit | Top 20 entries | Control the volume of retrieval results, adapt to batch processing requirements during production ledger summary |
| `defaultToken` | Set from representative sample documents | `defaultToken` is the default token count for direct text chunking; tune it on representative source documents. See the [v4.17.2 model-field reference](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx). It is not a vector dimension, embedding-model input cap, or retrieval/LLM context. |
| `maxToken` | 8192 | Adapt to the indexing requirements of long documents such as monthly quality reports, and match the extended window limit of Ali-emb3 to avoid truncation of key review content |

## Three common configuration mistakes
- Retrieval results include quality data from non-current production batches: Cause is failure to bind production batch identifiers as metadata to the index, and failure to configure retrieval rules for filtering by business dimension.
- Indexing tasks take an unusually long time to complete: Cause is failure to enable incremental indexing mode, and performing full indexing on all production ledger data, leading to system queue backlog.
- Retrieved inspection records lack detected value fields: Cause is failure to retain structured data field mapping during chunking, leading to loss of key business fields in the vector index.

## How to confirm the configuration is properly set
- View the index metadata list, confirm that exclusive fields such as production batch identifiers and nonconforming item codes are bound to each index record.
- Perform a single retrieval test, verify that results can be filtered by production batch, and only return quality data for the specified current batch.
- Submit different types of documents for indexing, confirm that the chunk length adapts to processing requirements for both short-text patrol inspection records and long-text quality reports.
- View the indexing task logs, confirm that incremental indexing mode triggers normally, and there is no backlog from full indexing.

The values provided here are common starting points and should be evaluated against the reader’s own samples.
