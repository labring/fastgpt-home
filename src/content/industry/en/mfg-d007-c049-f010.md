# Production Ledger Summary and Report Generation for In-Process Quality and Finished Product Release: Knowledge Base Retrieval and Recall

## What this category of data includes
Data sources include MES systems, online testing equipment, laboratory reports, process parameter documents, customer quality standards, and historical defect databases.
Data updates synchronize with each production batch and shift end. Testing data is collected continuously.
Daily documents cover control plans, patrol inspection records, SPC reports, finished product inspection reports, nonconforming product review forms, release forms, and monthly quality reports.
Fields include batch identification, inspection item name, measured value, judgment result, responsible team, and similar items. No additional statistical percentage indicators are included.

## Constraints Imposed on Knowledge Base Retrieval and Recall
This category’s data is multi-source heterogeneous, with update cadence tightly linked to production batches. Retrieval and recall must support filtering data by production batch and team scope.
Daily document types include inspection specifications, records, reports, and other formats. Field matching logic must adapt to different document structures.
Data includes precise fields such as measured values and judgment results. Retrieval must link corresponding inspection items with historical defect cases to support anomaly identification and review.
The release review process has high requirements for retrieval accuracy. Invalid recall must be avoided to prevent interference with the review workflow.

## Configuration Settings
This document is compatible with FastGPT v4.17.0. The following are retrieval configuration recommendations for this category.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | This category requires precise matching of inspection items and defect descriptions. This range balances recall coverage and retrieval accuracy |
| `limit` | Top 10 results | Production ledger summary needs to balance information comprehensiveness and response speed. Excessive results will increase the time required for ledger summary and report generation |
| `searchMode` | `mixedRecall` | This category’s data includes structured measured values and unstructured text. Hybrid mode covers different types of retrieval needs |
| `usingReRank` | Enabled | Multi-source recall results must be sorted by relevance to help quickly locate key inspection standards and historical defect cases |
| `datasetSearchUsingExtensionQuery` | Enabled | Production documents often contain professional process terms. Extended queries improve matching rates for documents such as control plans and SPC reports |
| `collectionIds` | Bind the dedicated collection ID of this production quality knowledge base | Limit retrieval scope to documents exclusive to this category, avoiding irrelevant data interfering with quality review and ledger summary |

## Three Common Configuration Errors
- A `Query read timeout` error occurs. The retrieval scope covers too many historical batch datasets. The single-recall data volume exceeds the system processing threshold, causing a request timeout.
- No search results are returned after passing the knowledge base ID. The `collectionIds` configuration is not set to the dedicated collection ID of the corresponding production quality knowledge base. Or the configured ID corresponds to documents that do not include control plans, inspection reports, and other exclusive documents for this category.
- An `Invalid URL, code: 500` error is returned by the API call. The interface path configuration during knowledge base file upload is incorrect. Or the dedicated knowledge base collection for this category is not correctly associated, so the request fails to match valid resources.

## How to Verify Correct Configuration
- Submit a retrieval request. Check if returned results include exclusive documents for this category such as control plans and finished product inspection reports. Confirm the retrieval scope meets expectations.
- Adjust the `similarity` parameter range. Verify that the relevance of recall results matches the current inspection item or defect type for retrieval. Confirm the threshold setting is reasonable.
- Check retrieval time consumption. Confirm no timeout occurs. Verify that the `limit` and `searchMode` configurations impact response speed in line with business requirements.
- Upload a test document of this category. Submit a retrieval request. Confirm the document can be normally recalled. Verify the `collectionIds` configuration is correct.
