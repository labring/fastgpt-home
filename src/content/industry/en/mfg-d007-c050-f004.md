# Production Ledger Summary and Report Generation for General Mechanical Equipment Assembly: Workflow Orchestration
This guide is written for FastGPT v4.17.0.

## What this category of data looks like
Production ledger data for general mechanical equipment assembly typically comes from PLM systems, ERP systems, MES systems, assembly tool collection terminals, test benches, and customer technical agreements. Data updates occur per assembled device or order batch.

Daily documents include assembly process cards, multi-level BOM lists, torque tightening records, gap adjustment records, commissioning reports, factory inspection certificates, and packing lists. Document fields cover equipment model, component serial number, tightening torque value (unit: newton meters), gap adjustment value (unit: millimeters), test parameters, and inspection results. These records span the full process of component fitting and debugging.

## Constraints on workflow orchestration
The characteristics of general mechanical equipment assembly ledger data create multiple constraints for workflow orchestration.
Multi-level BOMs and scattered assembly records require cross-system data pulling. Workflows must support parallel calls to multiple data sources.
Ledger data volume per single device increases with assembly steps. Large node data structures may exceed AI context length. Configure reasonable context limits.
Update cadence per order or device requires workflows to run automatically based on trigger conditions.
Numeric fields with units such as torque and gap require workflows to preserve field formats and units during summarization to avoid data distortion.
General mechanical equipment assembly is mostly custom, multi-variety production, unlike single-part machining. Ledger data must cover full process records of component fitting and debugging.

## Three Common Configuration Errors
- Symptom: After workflow execution, the `variables` field does not update automatically. Checking system logs shows variable values match preset initial values with no changes. Cause: The variable update node is not bound to the completion event of the corresponding assembly node. Only manual trigger update logic is configured.
- Symptom: When calling multi-level BOM data, the system returns an error prompt about "context length exceeded". Cause: No reasonable single-call token limit is configured. Large node data is not split and cropped for processing.
- Symptom: When counting assembly procedure calls by category, after the tool node finishes executing, the global counter variable does not update synchronously. Cause: The `variables` parameter is not bound in the tool node's output configuration. The count result is not written to the global variable pool.

## How to Confirm Correct Configuration
- Trigger a simulated assembly node completion event. Check workflow execution logs. Confirm that ledger data in the `variables` parameter has synced updates according to assembly progress.
- Import complete multi-level BOM data for a single device. Test workflow execution. Confirm no context length overflow errors occur.
- Check each workflow node corresponding to `nodeId` in sequence. Confirm data flow order matches assembly procedures, with no misplaced nodes or missing data.
- View the automatically generated ledger report. Confirm fields like torque and gap retain original units of newton meters and millimeters, along with corresponding numeric formats.
