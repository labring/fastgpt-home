# Production Ledger Summary and Report Generation for General Mechanical Equipment Assembly: Deployment and Upgrade

## What data for this category looks like
Production ledger data for general mechanical equipment assembly scenarios typically comes from PLM/ERP systems, part inspection records, assembly tool collection data, test bench data, MES systems, and customer technical agreements. Regularly collected documents include assembly process cards, multi-level BOMs, torque and clearance adjustment records, commissioning reports, factory inspection certificates, and packing lists.
Data updates are triggered per single device or per order. Fields include device model, assembly process parameters, inspection values, customer acceptance requirements, and more. Units include torque values (N·m), clearance (mm), pressure (MPa), and others. Data is gradually completed as the assembly process advances.

## What constraints do these characteristics impose on deployment and upgrade?
Data for this category is multi-source and scattered, updated per single device or order, and includes precise numeric fields. This creates multiple constraints for deployment and upgrade.
It is necessary to integrate interfaces with multiple systems such as PLM, ERP, and MES, and configure cross-system field mapping rules to ensure accurate data synchronization.
The incremental update feature requires optimizing synchronization logic to avoid full data pulls that consume excessive storage and computing resources.
Numeric process and inspection data with units require unified value parsing and format validation rules to ensure consistency in ledger summaries.
Custom customer technical agreement fields need flexible expansion support. Upgrades must be compatible with old version custom structures to prevent historical data from becoming invalid.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | `10–15` | Adapt to concurrent ledger data pull requests from multiple systems, avoid exhausting database connections |
| `REDIS_URL` | `redis://:custom password@deployment host:6379/0` | Cache temporary assembly process data and order association relationships, reduce overhead from repeated database queries |
| `STORAGE_S3_ENDPOINT` | Fill in according to the enterprise's self-built object storage service address | Store attachments such as assembly process cards and inspection reports, ensure consistent access to attachments across multi-node deployments |
| `PG_URL` | `postgresql://username:password@database address:5432/assembly ledger database` | Store structured ledger data, adapt to summary query requirements with multiple associated fields |
| Data sync trigger rule | Triggered at order completion node | Match the update rhythm of single device assembly, avoid unnecessary full synchronization |
| `FILE_TOKEN_KEY` | Generate random string according to enterprise internal security specifications | Ensure security of download permission verification for ledger attachments, prevent unauthorized access |

## Three common mistakes
- Calling the ledger summary interface returns `code500 Cannot read p`, caused by incorrect configuration of `REDIS_URL` connection parameters, leading to failed cache data reading.
- After uploading assembly-related images or documents, the system cannot load attachments, caused by unconfigured `STORAGE_S3_ENDPOINT` or insufficient storage path permissions, leading to failed normal reading of attachments.
- Calling external model interface returns 400 error, caused by `DB_MAX_LINK` set too high, leading to exhausted database connection pool and abnormal interface response.

## How to confirm the configuration is correct
- Run the `curl` command to call the ledger synchronization interface, check that the return status code is 200 and the returned data includes core fields such as assembly process cards and BOMs.
- Log in to the FastGPT backend, check the connection status of `REDIS_URL`, confirm it shows normal connection.
- Upload an assembly inspection report attachment, check if the system can load it normally and associate it with the corresponding order ledger.
- Check the database connection pool monitoring, confirm that the current number of connections does not exceed the set value of `DB_MAX_LINK`.
