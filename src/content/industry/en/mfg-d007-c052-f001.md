# Steel Rolling and Finishing Production Ledger Summary and Report Generation: HTTP Interfaces and External Systems

## What this category of data looks like
Data for this category comes from slab or billet batches, heating furnaces, mill automation control systems, online thickness and width measurement equipment, surface inspection devices, and MES systems. Data is updated in real time per coil or individual steel product. Daily documents include rolling plans, heating schedules, rolling specifications, flatness and thickness records, surface quality reports, and quality certificates. The minimum traceable unit is a coil or individual piece, and includes fields such as geometric dimensions, surface condition, and process parameters. Units include millimeters, degrees Celsius, meters per second, and other industry standard units.

## What constraints do these characteristics impose on HTTP interfaces and external systems
Real-time data updates require HTTP interfaces to match the trigger rhythm of single coil or individual steel products, avoiding excessive calls or delayed synchronization. Coil-level traceability requirements mandate that batch identifiers transmitted by the interface accurately correspond to the unique code of a single steel coil, ensuring ledger data can be fully associated with the corresponding product. Multiple data sources require interfaces to support pulling fields from different systems such as MES and online inspection equipment simultaneously, or integrating data via aggregation interfaces. The complexity of document data fields requires interface request bodies to support large-capacity parameter transmission, while adapting to structured field formats of different documents. Severe error consequences require interfaces to have complete exception capture and retry mechanisms to avoid data loss or ledger errors.

## How to set configurations
This configuration rule applies to FastGPT v4.17.0

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {internal enterprise API key}` | This category of production system data has high sensitivity, requiring prevention of unauthorized access |
| `variables` | Custom variables including unique identifiers for single coils such as coil number, batch ID | Ensure query conditions for interface calls accurately match the production data of the corresponding steel coil |
| `responseData` | Only return core ledger fields such as coil number, rolling thickness, surface defect level | Reduce invalid data transmission, improve interface response speed, and adapt to real-time summary requirements |
| Request timeout | 30–60 seconds | Online inspection data for this category has a certain generation delay, so the timeout period must cover the normal data return cycle |
| Retry attempts | First 3 attempts | Production data anomalies are mostly temporary network fluctuations; limited retries reduce data loss risk and avoid excessive system load |

## Three common misconfigurations
- Phenomenon: `Api response error: undefined` appears after calling the interface, with no clear error information in logs. Cause: The `Authorization` parameter is not configured correctly, or the format of fields bound by `variables` in the request body does not match the requirements of the target system, causing the target system to fail to parse the request.
- Phenomenon: The `responseData` returned by the interface contains a large number of non-ledger fields, leading to redundancy in summary report generation. Cause: No data filtering rules are set, and full data from the target system is pulled directly, without adapting to the core fields required for this category's ledger.
- Phenomenon: Interface calls time out, and online inspection data for a single steel coil cannot be obtained. Cause: The request timeout period is set too short, failing to cover the normal generation cycle of online inspection data for this category.

## How to verify proper configuration
- Initiate a test call for a single steel coil, and check whether the fields returned by the interface match the preset ledger fields.
- Simulate a temporary network interruption, verify whether the interface triggers the preset retry mechanism, and no duplicate data appears.
- Check whether the `Authorization` parameter is configured correctly, attempt to call with an invalid key, and confirm that a permission error prompt is returned.
- Adjust the coil number bound by `variables` to different values, and check whether the data returned by the interface corresponds to the correct steel coil batch.

The values provided here are common starting points and should be measured against the reader's own samples.
