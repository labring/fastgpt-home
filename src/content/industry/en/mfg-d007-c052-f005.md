# Production Ledger Summary and Report Generation for Steel Rolling and Finishing: Tool Calling and Plugins

## What the data for this category looks like
Data sources for steel rolling and finishing production ledger data include slab/billet batch information, heating furnace operating parameters, mill automatic control data, online thickness and width measurement results, surface inspection reports, and MES system records. Data is generated in real time for each coil or individual steel product. Daily documents cover rolling plans, heating schedules, rolling specifications, shape and thickness records, surface quality reports, and quality certificates. A single ledger entry includes fields such as batch number, heating temperature, rolling speed, thickness deviation, surface defect level, and quality certificate number. Units include degrees Celsius, millimeters, meters per second, and other relevant units.

## What constraints these characteristics impose on tool calling and plugin workflows
The real-time, batch-level data characteristics of this category require tool calling to support precise batch-level parameter binding, to avoid cross-batch data confusion. Multi-source heterogeneous ledger documents require plugins to integrate fields from different data sources, so tool calling must support combined function orchestration. The real-time nature of single-coil data requires tool calling response times to match production line beat times; excessive delays will disrupt subsequent production coordination. Additionally, severe consequences such as coil downgrading or equipment damage require tool calling to include failure retry and result verification mechanisms, to ensure the accuracy of ledger summaries. The requirement for coil-level traceability also requires tool calling to retain the complete traceability chain for each coil, to facilitate subsequent quality troubleshooting.

## How to set the configuration
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Tool calling mode | Select `functionCall` mode | Adapts to the function orchestration needs of multi-step ledger summary, supports integration of multi-source data |
| Maximum number of files per call | First 20 entries | Matches the typical number of inspection and planning documents associated with each batch of steel coils |
| Timeout period | 600 seconds | Adapts to the time required for multi-source data retrieval and cross-document field integration |
| Variable binding rules | Bind batch number and coil number variables | Ensures accurate association between ledger data and corresponding steel coils, avoids data misalignment |
| File upload limit | 1000 MB | Adapts to the upload requirements of large documents such as quality certificates and surface quality reports |

## Three common configuration mistakes
- Symptom: A file size limit exceeded error pops up when calling a locally deployed MinerU, with a 413 status code. Cause: The file upload limit item was not configured in container startup parameters, and the default 2 MB threshold was used.
- Symptom: When calling the file upload tool for a custom workflow, batch number and other variables cannot be referenced, and only static links are supported for uploads. Cause: Variable binding configuration for tool calling was not enabled, and only static link call permissions were open.
- Symptom: Plugin calls to ledger files stored in MinIO fail to read the files, returning a 403 permission error. Cause: Access keys and bucket permissions for the plugin and MinIO were not configured, resulting in abnormal data storage and retrieval links.

## How to confirm the configuration is correct
- Initiate a test call, pass the batch number of a known steel coil, check if the returned ledger data includes corresponding fields such as rolling plans and thickness records.
- Upload a quality certificate document larger than 2 MB to the tool calling node, confirm that no file size limit exceeded error prompt appears.
- Check if ledger files for the corresponding batch are generated in the MinIO bucket, and that the file content can be read normally via the tool calling storage path.
- In FastGPT v4.17.0, adjust the tool calling timeout period to 500 seconds, verify that the call completes response within the set time.
