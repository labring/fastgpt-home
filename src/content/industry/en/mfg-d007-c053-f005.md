# Production Ledger Summary and Report Generation for Iron and Steel Smelting and Continuous Casting: Tool Calling and Plugins

## What this category of data looks like
Data for this category comes from hot metal and scrap input systems, L2 process control terminals, laboratory testing systems, manufacturing execution systems (MES), energy medium monitoring platforms, and equipment status monitoring nodes. Daily documents include heat plans, batching lists, converter smelting records, composition reports, continuous casting process records, and slab judgment sheets. Data update frequencies cover per heat, real-time, and shift cycles. Fields include heat number, hot metal weight, scrap ratio, element contents such as carbon and manganese, smelting end temperature, cast sequence associated number, slab specification parameters, and more. Units include tons, percentages, degrees Celsius, millimeters, and others.

## What constraints these characteristics impose on tool calling and plugin workflows
Data sources for this category are scattered, and update rhythms vary widely. Tool calling must support batch calls and sequential execution of multiple data source interfaces. The strongly coupled document structure between heats and cast sequences requires plugins to use unique identifiers to associate cross-process data, avoiding data matching confusion. The high-frequency updates of real-time data require tool calling request intervals to match data refresh cycles, preventing access to expired data. The non-stop production feature requires tool calling to support exception retries and result verification, avoiding production process interruptions from calling failures.

## How to configure the setup
This document is written based on FastGPT v4.17.0, and supports two tool calling modes: `toolChoice` and `functionCall`. Specific configuration items and recommendations are as follows:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to the matching needs of multi-data source calls and natural language requests, and supports on-demand triggering of tool calls |
| `functionCall` | Mandatory specification of the tool list | Locks corresponding data interfaces for fixed associated fields such as heat numbers and cast sequence numbers, avoiding incorrect tool selection |
| Tool call timeout period | 30–60 seconds | Matches the refresh cycle of real-time data in this category, preventing access to expired smelting or continuous casting parameters |
| Request interval | 5 minutes | Matches the document refresh cycle for shift-based updates in this category, preventing access to expired data |
| Exception retry count | 2 times | Responds to network fluctuations or temporary system response delays, reducing the impact of single call failures |
| Data association rule | Match by heat number | Aligns with the strongly coupled document structure of heats and cast sequences, ensuring accurate cross-process data association |

## Three common configuration mistakes
- Symptom: When multiple interfaces are called in sequence by a tool, subsequent interfaces cannot obtain the heat number parameter returned by the previous interface. Cause: No parameter transfer rule between tools is configured, causing the return value of the previous interface to not be correctly carried into subsequent requests.
- Symptom: When calling the laboratory composition data interface, the returned carbon content field is empty. Cause: The request interval is not matched to the update cycle of data in this category, resulting in access to unupdated data that has not yet completed testing.
- Symptom: An error indicating unsupported file format is returned when calling an external system interface. Cause: The transfer format and request header for file parameters are not correctly set in the tool call configuration.

## How to verify correct configuration
- Initiate a test request that includes a heat number, and check whether the tool calls the corresponding data source interface according to the configured association rules.
- Simulate a single call failure scenario, and check whether the tool triggers the preset retry mechanism.
- Initiate a request that requires multi-process data, and check whether the tool executes multiple interface calls in sequence and correctly associates the returned data.
- Send a test request that includes file parameters, and check whether the tool correctly transfers the request content in file format.
