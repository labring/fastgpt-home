# Sheet Metal Cutting and Bending Production Ledger Summary and Report Generation: Multi-turn Dialogue and Prompts

## Data for This Category
The data for this category primarily comes from CAD/CAM software, order BOMs, sheet metal inventory systems, laser cutting machine and bending machine equipment logs, and MES production management systems. Daily generated documents include 3D part unfolding drawings, CNC cutting programs, bending process cards, nesting diagrams, first-piece inspection records, and process flow cards. Data updates are triggered by each order, daily production scheduling, and each equipment model change. Data fields include sheet metal grade, thickness, unfolding dimensions, bending compensation values, process flow status, and inventory surplus, with units mostly millimeters, square meters, and kilograms.

## Constraints Imposed on Multi-turn Dialogue and Prompts
Data sources for this category are scattered, and update trigger nodes are diverse. Multi-turn dialogue must accurately link cross-system fields such as CAD/CAM unfolding parameters, MES process flow status, and sheet metal inventory surplus. Prompts must clearly specify the call priority of different data sources. There are many types of daily documents, so prompts must specify field extraction rules for specific documents such as unfolding drawings, nesting diagrams, and bending process cards to avoid confusing parameters from different processes. Data updates are triggered in real time by orders and model changes, so multi-turn dialogue must support fast retrieval of the latest data, while also limiting the context window size to prevent redundant old data from interfering with current session result generation.

## Configuration Settings
The following configurations are written for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | 800–1200 characters | Daily documents for this category are mostly process flow cards and unfolding drawings, with single-piece content concentrated in this range to avoid context overload |
| `chatId` Binding Rule | Bind by order ID | Most sessions for this category are initiated per individual order. Binding `chatId` ensures context continuity across multi-turn dialogue for the same order |
| `variables` Parameter Configuration | Pass order number, sheet metal grade | Ledger summary for this category requires linking order BOMs and sheet metal inventory. Passing specified fields via `variables` enables accurate data retrieval |
| Question Optimization Switch | Enabled | This category requires repeated verification of bending compensation and cutting dimensions. Question optimization can correct vague queries and clarify extraction targets |
| Single Recall Result Limit | Top 5 entries | Data sources for this category are clearly defined, so excessive recall results are unnecessary to avoid redundant information interfering with session results |
| Session Timeout Setting | 600 seconds | This category requires retrieving data from multiple device logs and cross-system sources, so sufficient time is reserved for data integration and ledger generation |

## Three Common Misconfigurations
- Symptom: After increasing the context window size, the session still fails to retain multi-turn dialogue memory for the same order, or returns irrelevant general knowledge base content. Cause: `chatId` is not bound by order ID, leading to confusion of session contexts across different orders, and recall range is not limited, so general knowledge base content interferes with extraction of dedicated production data.
- Symptom: Prompts do not specify document types, leading to extracted bending coefficients and cutting dimensions that do not match the unfolding drawing for the current order. Cause: Field extraction rules for different documents such as unfolding drawings and nesting diagrams are not clearly defined in the prompt, confusing parameters from different processes.
- Symptom: Session timeout occurs, or the latest sheet metal inventory data cannot be retrieved. Cause: Timeout setting is too short, failing to reserve sufficient time for retrieving data from cross-device logs and MES systems.

## How to Verify Proper Configuration
- Users may initiate a multi-turn dialogue for an order, sequentially query sheet metal specifications, cutting dimensions, and bending process parameters, and confirm that the session retains context from prior queries after each query.
- Users may pass a test order number via the `variables` parameter, and confirm that the system retrieves BOM and production data for the corresponding order.
- Users may trigger a ledger summary request, and confirm that the returned result includes fields from specified documents such as unfolding drawings and process flow cards, with no irrelevant general content.
- Users may test a session timeout scenario, and confirm that data retrieval and ledger generation are completed within the preset time.

The values given are common starting points and should be measured against the reader's own samples.
