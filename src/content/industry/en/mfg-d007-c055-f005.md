# Production Ledger Summary and Report Generation for Foundry (Sand Casting, Precision Casting, Die Casting): Tool Calling and Plugins

## What data for this category looks like
Data for this category comes from ERP material master data, melting furnaces and thermometers, spectrometers, MES heat logs, mold management systems, customer drawings, and technical specifications. Updates occur per heat, per batch, or daily. Daily documents include foundry process cards, batching lists, heat logs, mold histories, first article inspection records, material reports, and nonconforming product review forms. Core fields include alloy composition, melting temperature, pouring parameters, defect types, heat numbers, and mold numbers. Most data is stored as structured ledgers and raw device collection files.

## Constraints for tool calling and plugins
The multi-source, heterogeneous data sources of this category require tool calling to adapt to different systems’ interface formats. The high-frequency update rhythm requires plugins to use reasonable timeout and retry settings. The professional nature of core fields requires tool calling to validate parameters such as alloy composition and temperature for legality. Traceability needs require tools to support data filtering and association by heat number and mold number. The liquid metal forming business characteristics mean tool calling must prioritize core data from melting and pouring stages, to avoid missing key quality information.

## Configuration settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to tool calling needs for multi-source systems, automatically selects the corresponding interface to pull data |
| HTTP request timeout | `600 seconds` | Adapts to data return times of devices such as melting furnaces and spectrometers, to avoid business interruptions |
| Plugin request retry count | `2 times` | Addresses occasional network fluctuations in industrial equipment, reducing the probability of data pull failures |
| `functionCall` format enforcement | Enabled | Ensures tool call return formats meet ledger parsing requirements, avoiding aggregation failures caused by format errors |
| Maximum parallel tool calls | `First 3 entries` | Avoids overloading the system by pulling too much device data simultaneously |
| Parameter validation switch | Enabled | Validates the legality of core fields such as alloy composition and temperature, filtering invalid data |

## Three common configuration errors
1. Symptom: HTTP plugin call returns 200 status code but no valid ledger data is generated. Cause: Interface parameters for ERP and MES systems are not correctly bound, resulting in tool calls failing to pull actual business data.
2. Symptom: Tool call returns empty results. Cause: Filter parameters for heat number and mold number are not set, resulting in pulling irrelevant batches of historical data.
3. Symptom: Plugin call triggers timeout error. Cause: The set timeout period is shorter than the data return time of devices such as melting furnaces and spectrometers, not adapting to the business time required for foundry scenarios.

## How to verify correct configuration
- Manually trigger a tool call, check if the returned raw data includes required foundry scenario fields such as heat number, alloy composition, and pouring temperature
- Review tool call logs, confirm that the `toolChoice` parameter is correctly applied, and that the tool call process is not interrupted
- Simulate a single heat data pull, verify that the plugin request timeout period matches the device return time
- Check the enabled status of the parameter validation switch, confirm that abnormal fields are intercepted and clear prompts are returned

The values listed here are common starting points, and should be evaluated against samples from the reader’s own deployments.
