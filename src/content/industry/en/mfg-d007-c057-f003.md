# Production Ledger Summary and Report Generation for Forging and Die Forging: Multi-turn Dialogue and Prompt Engineering

## What data for this category looks like
Data sources for this category include raw material quality certificates, heating furnace systems, press collection data, MES systems, non-destructive testing instruments, and customer forging drawings.
Data updates follow the rhythm of each forging piece, each batch, or each furnace run.
Daily documents cover forging process specifications, cutting cards, heating furnace records, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports.
Data fields include forging ratio, fiber direction, furnace batch number, forging batch number, defect type, and more.
Corresponding units involve weight, temperature, pressure, and dimensional parameters.

## What constraints do these characteristics impose on multi-turn dialogue and prompt engineering
The feature that data updates per single furnace run or single batch requires multi-turn dialogue to accurately associate furnace batch numbers with forging batch numbers, to avoid cross-batch confusion.
Differences in structure across multiple daily documents require prompt engineering to clearly define field extraction rules for different documents such as process specifications and testing reports.
For scenarios combining frequently updated production data and offline documents, use the `messages` parameter to limit conversation context length, to avoid redundant information interfering with key parameter matching.
The need to verify dedicated fields such as forging ratio and fiber direction requires prompt engineering to include category-specific logical verification rules, to prevent missing fields or incorrect values.

## Three common configuration mistakes
- Symptom: Timeout errors occur when parsing Word documents for forging ledgers larger than 10 MB. Cause: Chunk configuration was not adjusted for the long paragraphs and multi-field structure of category documents, leading to excessively long single chunks that trigger parsing timeouts.
- Symptom: Prompt engineering optimization steps take longer than reasonable during multi-turn dialogue. Cause: The context range for question optimization was not limited, and irrelevant historical testing report data was included, leading to excessive load on optimization logic.
- Symptom: The debug preview interface returns an empty field error after triggering input guidance. Cause: Category-specific furnace batch number and forging batch number variables were not bound in the `variables` configuration, causing the guidance logic to fail to obtain necessary business parameters.
