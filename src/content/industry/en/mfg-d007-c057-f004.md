# Forging and Die Forging Production Ledger Summary and Report Generation: Workflow Orchestration

## What the data for this category looks like
Forging and die forging production data originates from multiple sources including raw material quality certificates, heating furnace systems, press collection data, MES, non-destructive testing instruments, customer forging drawings, and others. Daily processed documents include forging process specifications, cutting lists, heating furnace records, forging process cards, mold life records, heat treatment entrustment slips, ultrasonic testing reports, and more. Data updates occur once per piece, per batch, or per furnace run. Core fields include forging batch number, furnace batch number, heating temperature, holding time, pressure parameters, mold number, detected defect type, and life cycle. Units include ℃, min, MPa, and others.

## What constraints these characteristics impose on workflow orchestration
Multi-source heterogeneous data sources require workflows to connect to multiple independent collection nodes to avoid data format conflicts across different systems. The high-frequency update rhythm requires workflows to support batch concurrent processing to meet rapid ledger generation needs for each furnace run or batch. The rich set of documents and fields demands precise configuration of variable mapping rules to ensure core associated fields such as forging batch number run through the entire workflow. Additionally, strict requirements for forging defect handling require adding verification and failure retry steps to prevent unqualified data from entering subsequent report generation steps.

## How to set configurations
The following configurations are based on FastGPT v4.17.0.

| --- | --- | --- |
| Data Source Node Configuration | Create independent nodes for each of 6 data sources including raw material quality certificates and heating furnace systems | Matches collection needs for multi-source heterogeneous data in this category |
| Concurrent Execution Threshold | 5–10 items per run | Adapts to batch data processing rhythm for each furnace run or batch of forgings |
| `variables` Mapping Rules | Set forging batch number and furnace batch number as global variables | Unifies core associated fields across the entire workflow |
| Error Retry Count | 2–3 times | Addresses temporary system connection fluctuations |
| Node Timeout Setting | 600 seconds | Matches standard generation cycles for heating furnace records and ultrasonic testing reports |
| `nodeId` Binding Rules | Bind corresponding node instances by forging batch number | Avoids node conflicts during batch runs |

## Three common configuration mistakes
- A `500 Gateway forwarding error because service is disconnected` error appears in workflow nodes. The cause is failure to bind an independent `nodeId` for each forging batch, leading to repeated service connection occupation and disconnection during batch runs.
- Workflow model icons do not display, and a network error prompt appears for file uploads. The cause is failure to clear front-end cache and the node timeout setting not adapting to upload rhythms for large files such as ultrasonic testing reports.
- An offset-type data shift error occurs during workflow runtime. The cause is failure to match field correspondences between cutting lists and forging process cards during `variables` mapping, leading to abnormal data reading positions.

## How to verify correct configuration
- Manually input test data for a single furnace run of forgings, run the workflow, and verify that each data source node correctly pulls corresponding documents.
- Set the batch run threshold to 5 items per run, submit test data for 5 batches, and confirm that no conflicts occur during concurrent node execution.
- Access the `variables` global variable panel and confirm that core fields including forging batch number and furnace batch number are correctly mapped.
- Simulate a single node disconnection scenario, and verify that the error retry mechanism triggers and the workflow resumes operation.

The values provided are common starting points and should be measured against available local samples.
