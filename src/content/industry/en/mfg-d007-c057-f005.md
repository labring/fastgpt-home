# Production Ledger Summary and Report Generation for Forging and Die Forging: Tool Calling and Plugins

## What the data for this category looks like
This category's data mainly comes from raw material quality certificates, heating furnace systems, press collection data, MES systems, non-destructive testing instruments, and customer forging drawings. Daily ledgers cover forging process specifications, cutting cards, heating furnace records, forging process cards, mold life records, heat treatment entrustment slips, and ultrasonic testing reports. Data updates follow the rhythm of each forging piece or batch, and each furnace run. Core fields include furnace batch number, forging batch number, forging ratio, fiber direction, heating temperature range, detected defect type, and more.

## What constraints these characteristics impose on the tool calling and plugins link
The multi-source heterogeneous data sources of this category require tool calling to adapt to the interface formats of different systems. Corresponding plugins must be configured separately for heating furnace records, press data, and non-destructive testing reports. High-frequency updates by furnace run or batch require tool calling to support scheduled triggering, avoiding delays from manual operations. The exclusive attributes of core fields such as forging ratio and fiber direction require tool calling parameters to match these specific fields, and general ledger tool configurations cannot be directly reused. Tool call failures will directly affect ledger accuracy, which may lead to subsequent problems such as forging scrap. A complete failure retry mechanism must be configured.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | Adapt to the flexible calling needs of multi-source data pulling, automatically select matching tool plugins |
| Tool call timeout threshold | 300 seconds | Match the conventional return duration of heating furnace data and press collection data |
| Batch call batch size | 10-20 records | Adapt to the ledger data volume of each furnace run or forging batch, avoiding overload from single calls |
| `functionCall` parameter validation switch | Enabled | Ensure only exclusive fields for forging ledgers are matched, filter invalid calling requests |
| Local model call cache | Calibrated based on actual measurements | Adapt to storage and reading needs of forging ledger data of different scales |

## Three common configuration mistakes
- Symptom: An error is returned when calling the time synchronization plugin to obtain furnace heating records. Cause: The plugin's access permissions to the heating furnace system data source are not configured, so the timestamp field of the records cannot be read.
- Symptom: The interface displays the prompt "The tool call is not supported". Cause: The tool calling function is not enabled in the application configuration, or the selected large language model does not support tool calling capabilities.
- Symptom: The locally deployed m3e model call fails, and the configuration matches the old version. Cause: FastGPT v4.17.0 adjusted the environment variable loading logic for local models, and the plugin's model path configuration was not updated synchronously.

## How to confirm the configuration is complete
- Manually trigger tool calling to pull heating furnace records for a single furnace run, verify that returned fields such as furnace batch number and heating temperature range match ledger requirements.
- View the tool call logs, confirm that the `toolChoice` parameter takes effect, and there are no invalid call or permission error records.
- Simulate a batch call of 15 forging ledger records, check that the returned results are complete and the update time matches the current furnace run's production rhythm.
- Test the local model call, confirm that the plugin can normally generate report fields including forging ratio and fiber direction.

The values given here are common starting points and should be measured against the reader's own samples.
