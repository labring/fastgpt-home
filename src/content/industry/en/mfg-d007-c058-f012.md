# Production Ledger Summary and Report Generation for Precast Concrete Components: Deployment and Upgrade

## What data for this category looks like
Production data sources for precast concrete components include BIM or detailed design documents, steel bar and concrete batch ledgers, mold table and curing kiln operation records, laboratory test reports, and QR code traceability systems. Daily production documents include component detailed drawings, steel bar cutting lists, mold inspection records, pouring and vibration records, curing records, and demolding and factory inspection reports.
Data is updated synchronously for individual components, each batch of materials, and each curing kiln cycle. Fields include component ID, steel bar usage, concrete strength, curing duration, demolding date, and others. Corresponding units include MPa, cubic meters, days, and additional standard units.

## What constraints these characteristics impose on deployment and upgrades
Production data sources for precast concrete components are scattered and updated frequently. Multiple data source access adaptation items must be configured during deployment to ensure synchronization efficiency of ledgers across systems.
Data update frequencies cover individual components, each batch, and each kiln. High-frequency write operations increase database load. Connection pool parameters must be adjusted in advance to avoid performance bottlenecks.
Production documents include unstructured and structured data in multiple formats such as engineering drawings and test records. Storage configuration must support multi-type file uploads.
Each component corresponds one-to-one with on-site lifting positions. Ledger fields must be mapped accurately. Field matching rules must be preset during upgrades to avoid data misalignment, which can lead to risks such as embedded part misplacement or component scrapping.

## How to configure the settings
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `DB_MAX_LINK` | 10–15 | Adapts to high-frequency updated ledger data for precast concrete components, prevents database connection pool exhaustion |
| `PG_URL` | postgresql://username:password@host:5432/pc_component_db | Stores structured ledger data, matches the business field structure of steel bar usage, curing records, and other related data |
| `REDIS_URL` | redis://:password@host:6379/0 | Caches QR code associated data for high-frequency query component traceability, reduces database read and write pressure |
| `STORAGE_S3_ENDPOINT` | s3-cn-east-1.qiniucs.com | Stores unstructured documents such as component detailed drawings and pouring records, supports multi-format file uploads |
| `FILE_TOKEN_KEY` | Calibrated via actual measurement | Encrypts ledger file access tokens, ensures access security for sensitive documents such as demolding inspection reports |
| `ROOT_KEY` | Random 32-character string | Configures initial permissions for platform administrators, meets permission control requirements for precast component factories |

## Three common configuration mistakes
- A 504 Gateway Timeout is returned when accessing the ledger generation interface. The cause is that the `DB_MAX_LINK` parameter was not adjusted. High-frequency updated ledger data causes the database connection pool to be exhausted, and requests cannot be responded to in a timely manner.
- Steel bar cutting lists cannot be retrieved after knowledge base synchronization. The cause is that `STORAGE_S3_ENDPOINT` was not configured correctly. Unstructured documents failed to upload to the specified storage node, causing the synchronization task to fail.
- Embedded position information is missing from generated reports. The cause is that the preset field matching rules do not cover the embedded coordinate fields in BIM detailed drawings, resulting in data not being correctly associated with the production ledger.

## How to confirm configurations are correctly set
- Run a database connection test to verify that the `PG_URL` and `DB_MAX_LINK` configurations can normally establish and maintain 10–15 connections.
- Upload a steel bar cutting list to the platform, check whether the storage node under the `STORAGE_S3_ENDPOINT` configuration successfully receives the file.
- Trigger a ledger summary task, check whether the generated report includes preset business fields such as component ID and concrete strength.
- Log in to the FastGPT v4.17.0 platform backend, use the `ROOT_KEY` to verify whether the administrator permission configuration takes effect.

The values provided are common starting points and should be measured against the reader's own samples.
