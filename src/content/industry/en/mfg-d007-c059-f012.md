# Ready-Mixed Concrete Production: Production Ledger Aggregation and Report Generation - Deployment and Upgrade

## What the Data for This Category Looks Like
This category’s data originates from engineering orders, sand, gravel, cement admixture test reports, aggregate moisture content measurement records, mixing plant control system data, and laboratory test records. Data updates follow three cadences: per-vehicle production records, per-batch raw material test results, and daily summary reports. Daily documents include mix proportion notices, opening identifications, production and transport orders, raw material inspection ledgers, test block compressive strength records, and structural strength reports. Core fields include pouring location number, aggregate moisture content, water consumption per cubic meter of concrete, slump index, test block age, and compressive strength. Units include millimeters, liters, megapascals, days, and others.

## Constraints Imposed on Deployment and Upgrade
The high-frequency updates, multi-source heterogeneous data, and cross-cycle association traits of this category create multiple constraints for deployment and upgrade. Per-vehicle real-time data writing requires storage parameters tuned for high concurrency to prevent single-data processing timeouts. Multi-source data comes from mixing plant control systems, laboratory test systems, and engineering order systems. Deployments must include reserved import interfaces compatible with different data formats. Upgrades must retain legacy data migration capabilities. The need for daily summary reports and cross-age test block strength association requires sufficient reserved computing resources to avoid task backlogs during peak hours. Core indicator verification must run during data access to block invalid data from entering the ledger system.

## Configuration Settings
This guide is written for FastGPT v4.17.0. The following configuration items apply:
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–150 connections` | Adapts to per-vehicle high-frequency data write concurrency, avoiding connection pool exhaustion |
| `MONGODB_URI` | Dedicated MongoDB instance for ready-mixed concrete production ledgers | Isolates business data from other system data to maintain read/write performance |
| `REDIS_URL` | `redis://127.0.0.1:6379/0` | Caches frequently queried aggregate moisture content and mix proportion data to reduce database load |
| `STORAGE_S3_ENDPOINT` | Internal enterprise object storage access address | Stores unstructured documents such as production and transport orders and test block reports, supporting batch file upload requirements |
| `FILE_TOKEN_KEY` | Encryption key calibrated via actual measurements | Secures access to uploaded files including raw material test reports and strength reports |

## Three Common Configuration Errors
- A 500 error occurs when importing documents such as mix proportion notices and test block records. The root cause is missing storage permissions for the `STORAGE_S3_ENDPOINT` configuration, preventing unstructured file writes.
- Daily ledger aggregation tasks frequently time out. The root cause is an excessively low `DB_MAX_LINK` configuration value, which cannot support concurrent requests from high-frequency data writes.
- A connection refused error appears when connecting to mixing plant control system data. The root cause is unopened port access permissions and an incorrectly configured `PG_URL` pointing to the data source address.

## How to Verify a Successful Configuration
- Run a write test for a single simulated production record to confirm successful data insertion into the specified database instance.
- Upload a raw material test report to confirm the file is stored normally and linked correctly in the ledger system.
- Trigger a simulated daily ledger aggregation task to confirm completion within the preset time with no error logs.
- Check the cache instance to confirm frequent queries for aggregate moisture content data are properly cached.

The values provided are common starting points and should be measured against the user's own samples.
