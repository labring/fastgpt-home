# PCB Manufacturing Equipment Inspection and Maintenance Q&A: Tool Calling and Plugins

## What this category of data looks like
Data for this category comes from engineering, production, quality control, and laboratory roles at printed circuit board factories. Daily documents include engineering production instructions, Gerber analysis records, drilling and lamination parameters, chemical solution analysis, AOI reports, electrical test reports, and sectioning reports. Data sources cover customer Gerber/drill tape/BOM files, CAM data, equipment parameters, bath solution test results, AOI data, electrical test data, and laboratory data. Update frequency is per production batch, per shift, or continuous collection. Fields include equipment number, inspection batch, parameter value, inspection result, and others. Units are adjusted based on the standards of the corresponding production link.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
Scattered data sources and high update frequencies require tool calling to support integration with multiple types of data source plugins, to ensure real-time access to the latest equipment parameters and inspection reports. Diverse document structures require tool calling parameters to accurately match the fields of corresponding documents, to avoid data reading errors caused by field mismatches. Continuously collected production data requires tool calling trigger timing to align with production cycles, to avoid excessive calls occupying production network resources. Errors can lead to full batch board scrapping or high-value claims, so tool calling must include failure retry and data verification mechanisms to ensure the accuracy of call results.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | Adapt to multi-data-source equipment inspection scenarios, automatically match corresponding tools such as Gerber analysis, bath solution testing, AOI inspection, and others |
| Single tool call timeout | 600 seconds | Corresponds to the complex data return rhythm of drilling and lamination parameter queries, to avoid timeout interruptions caused by large data volumes |
| Tool call failure retry count | 3 times | Address scenarios such as workshop network fluctuations or temporary unavailability of equipment data interfaces, to ensure call success rate |
| Context window size | 8000–12000 token | Accommodate the complete content of multiple AOI reports and electrical test reports, to avoid loss of key information due to context truncation |
| Workflow/API function-call configuration | Enforce parameter format verification | Ensure that passed equipment ID and inspection batch number comply with PCB manufacturing field specifications, to avoid invalid parameter calls |
| Plugin data source whitelist | Only production-related plugins are allowed | Restrict unauthorized tool calls, to prevent leakage or mishandling of production data |

## Three Common Misconfigurations
- Symptom: Empty fields are returned when calling the equipment parameter query tool. Cause: The corresponding PCB manufacturing equipment ID, inspection batch, and other field mapping rules are not bound in the plugin configuration, causing the tool to fail to match the correct data source.
- Symptom: Internal network production data cannot be accessed after deploying the MinIO storage plugin. Cause: The internal network access permission of the plugin is not configured correctly, and public network mandatory verification is accidentally enabled, which does not match the actual workshop internal network deployment scenario.
- Symptom: Tool call response time exceeds the preset threshold. Cause: No reasonable timeout threshold is set, and the asynchronous queue for tool calls is not enabled, causing batch production data queries to block the main thread.

## How to Confirm Proper Configuration
- Trigger an equipment inspection tool call, and verify that the returned drilling parameters and bath solution test data match local production records.
- Simulate an internal network environment to access the AOI report stored by the MinIO plugin, and confirm that files can be pulled normally.
- Check the tool call logs to confirm that the `functionCall` parameter format verification is passed, with no abnormal errors.
- Trigger tool calls in batches 3 times, and confirm that the response time meets the requirements of production rhythm.

The values listed above are common starting points, and should be evaluated against the reader's own specific samples.
