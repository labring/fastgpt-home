# Equipment Inspection and Maintenance Q&A for SMT Mounting and Electronic Assembly: Vector Models and Indexes

## What This Category of Data Looks Like
Data related to equipment inspection and maintenance for SMT mounting and electronic assembly comes from sources including BOMs, Gerber files, component coordinates provided by clients, MES system data, operation records of placement machines, SPI/AOI inspection equipment, and reflow ovens, as well as internal line change lists, first article confirmation reports, maintenance traceability labels, and defect records. Data syncs in real time per work order and each line change. Each work order corresponds to multiple associated documents. Fields include part number, reference designator, component batch, reflow profile parameters, defect type, and maintenance measures. Some documents contain structured coordinates and temperature values.

## Constraints Imposed on Vector Models and Indexes
The high-frequency real-time updates and multi-document association traits of this category impose multiple constraints on vector index and model configuration. First, real-time work order and line change data require indexes to support incremental updates, eliminating the time cost of full reindexing. Second, documents with structured coordinates, temperature parameters, and coded fields need to preserve field associations during chunking, preventing splitting of key retrieval information such as part numbers and reference designators. Third, the strong association between maintenance records and SPI/AOI reports requires indexes to support cross-document semantic association retrieval, while embedding models must adapt to coded features in industrial scenarios. FastGPT v4.17.0’s indexing mechanism can accommodate these requirements, but core configuration items must be adjusted based on specific data characteristics.

## How to Set Configurations
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the single-paragraph content length of BOMs and maintenance records, avoids splitting key retrieval fields such as part numbers and reference designators |
| `maxToken` | 4096 token | Matches long text blocks in industrial documents, fully retains core content such as reflow profile parameters and defect analysis |
| Similarity Threshold | 0.75–0.85 | Filters low-match irrelevant records, prevents mismatching equipment issues for different part numbers |
| `defaultToken` | Calibrated based on actual measurements | Adapts to the input length limit of the selected embedding model, avoids truncation of ultra-long text that loses key information |
| Single Search Limit | Top 10 entries | Controls the number of retrieval results, meets the rapid positioning needs of equipment inspection |
| Maximum Context | 8000 characters | Integrates associated SPI reports, line change lists, and maintenance records, provides complete fault analysis basis for Q&A.

## Three Common Mistakes
- Abnormal retrieval results with similarity values over 10000 appear. Cause: The similarity threshold value range was not set correctly after using an embedding model, causing the vector calculation normalization logic to not adapt to the coded features of industrial scenarios.
- The knowledge base dataset remains in the indexing state for a long time after import. Cause: Incremental index trigger rules were not configured, and the dataset contains a large number of real-time updated work order data, leading to excessively long full index time, or the `maxToken` setting exceeds the model limit, causing the index task to interrupt.
- No available channels for m3e are found. Cause: The API key and deployment node of the corresponding embedding model were not added in the FastGPT model management page, or the access permission for the corresponding channel was not enabled.

## How to Verify Proper Configuration
- Import a test set of maintenance records and SPI inspection reports, run equipment inspection-related retrieval, and check whether the similarity values of returned results fall within the 0-1 range.
- Submit a test dataset containing 10 real-time work order data, confirm that the index completion time meets expectations, and no long-running hanging tasks exist.
- View the available channel list of the embedding model on the model management page, confirm that the target model’s channel is normally displayed and can be called.
- Adjust the similarity threshold and run retrieval, verify that the number of results changes with the threshold, matching the configured expectations.

The values provided are common starting points and should be evaluated against the reader’s own samples.
