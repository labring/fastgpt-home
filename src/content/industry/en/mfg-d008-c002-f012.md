# Equipment Inspection and Maintenance Q&A for SMT Mounting and Electronic Assembly: Deployment and Upgrade

## What the data for this category looks like

The business data for SMT mounting and electronic assembly scenarios comes from multiple sources: customer delivery files, production systems, and device terminals. These sources include BOMs, Gerber files, coordinate files, MES system line change lists, first-piece confirmation records, real-time operating data from mounters, SPI/AOI devices, and reflow soldering equipment, plus maintenance records and traceability labels.

Data updates occur per work order, each line change, and in real time. Available documents include structured fields for part numbers, reference designators, and component batches. They also contain semi-structured furnace temperature curves and defect reports, plus binary stencil parameter files.

## Constraints imposed by these characteristics during deployment and upgrade

This category has multi-source, heterogeneous data that updates frequently. During deployment, connection configurations for multiple data types must be adapted to avoid data pull failures caused by mismatched connection parameters.

Real-time updated business data requires database connection pools with sufficient capacity to prevent connection exhaustion from high-frequency read and write operations. Diverse document formats need pre-configured matching parsing rules to ensure inspection and maintenance Q&A can accurately extract key fields.

During upgrades, authentication and storage configurations must be synchronously verified to avoid system inability to access business data after parameter changes. Key configurations must also be backed up in advance to reduce upgrade rollback difficulty.

## Configuration settings

This configuration is adapted for FastGPT v4.17.0. Specific settings are listed below:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | 10–20 connections | Matches high-frequency read/write workloads of work order, line change, and inspection data in SMT scenarios, prevents database connection exhaustion |
| `MONGODB_URI` | Cluster address for storing SPI/AOI reports and maintenance records | Meets storage requirements for unstructured business documents in this category |
| `PG_URL` | PostgreSQL instance address connected to the MES system | Used to pull structured business data such as BOMs and line change lists |
| `REDIS_URL` | Dedicated cache instance address | Accelerates real-time inspection data queries and user session caching |
| `STORAGE_S3_ENDPOINT` | Endpoint provided by the enterprise object storage service provider | Used to store large files such as stencil parameters and furnace temperature records |
| `ROOT_KEY` | Random string generated per enterprise security specifications | Ensures access permission security for background configurations |

## Three common configuration errors

- Symptom: After upgrade, system login prompts incorrect account or password, and background access is blocked. Cause: User authentication configurations were not correctly synchronized during upgrade, or the `ROOT_KEY` parameter was changed, causing encryption logic errors.
- Symptom: Text content extraction function fails, and defect data in SPI/AOI reports cannot be read. Cause: Parsing rules adapted for SMT document formats were not configured, or the `STORAGE_S3_ENDPOINT` parameter is incorrect, causing file reading failures.
- Symptom: Docker deployment logs show the `Reached the max retries` error, and the `fastgpt` container cannot start. Cause: `DB_MAX_LINK` is set too small, high-frequency read/write operations cause database connection exhaustion, and retry limits are exceeded.

## How to confirm configurations are properly set

- Run the `docker ps` command to confirm all FastGPT-related containers are in running state.
- Upload a BOM file from an SMT scenario to verify that key fields such as part numbers and reference designators can be normally retrieved after file parsing.
- Log in to the background configuration page, modify the `ROOT_KEY` parameter, restart the service, and verify that the authentication logic works correctly.
- Initiate a simulated inspection query to confirm that associated business data such as line change lists and furnace temperature records can be retrieved.

Note: The values provided here are common starting points, and should be validated against the reader's own operational samples.
