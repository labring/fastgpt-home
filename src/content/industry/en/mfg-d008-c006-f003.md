# Q&A for Equipment Inspection and Maintenance of Photovoltaic Module Encapsulation: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data related to equipment inspection and maintenance for photovoltaic module encapsulation comes from battery cell grading records, glass adhesive film and backsheet batch ledgers, workshop MES systems, string welding and lamination equipment operation logs, EL/IV tester test reports, insulation withstand voltage test records, and finished product packing lists. Data is updated per single module and per batch of materials. Documents include structured process records, visual EL defect images, power test reports, and other content. Fields include equipment operating parameters, material batch numbers, test grades, defect locations, and judgment results. Some documents use binary image formats, with no unified fixed layout.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering
High-frequency updated data at the single module level requires dialogue contexts to link to the latest batches and test results in real time. This prevents calling outdated data. Multiple types of documents, including structured records and image files, require prompt engineering to clearly distinguish trigger logic for text retrieval and image interpretation. Multi-turn interactions for equipment inspection must retain historical operation records. `chatId` must bind to the full life cycle inspection process of a single device to avoid context confusion. The strong correlation between material batches and equipment parameters requires prompt engineering to embed field mapping rules. This ensures retrieval results match the current inspection’s equipment and material batches.

## How to Set Configurations
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `chatId` binding rule | Bind single device ID + daily inspection batch | Ensure multi-turn dialogue only associates data from the currently inspected device and batch, avoiding cross-device context interference |
| `messages` context truncation threshold | Retain the first 20 valid interactions | The inspection process for a single module typically does not exceed 15 turns. Retaining 20 turns covers the complete interaction chain without consuming excessive resources |
| Chunk length | 800–1200 characters | Adapts to the average length of single-segment documents such as lamination process records and EL image annotation text, reducing chunk breakage |
| Single retrieval limit | Top 6 retrieval results | Documents related to photovoltaic encapsulation have concentrated fields. 6 results can cover all associated information of equipment parameters, material batches, and test records |
| `variables` injection rule | Inject current device ID and material batch number | Force prompt engineering to associate exclusive data for the current inspection scenario, avoiding retrieval of records from unrelated batches |

These configuration items are compatible with FastGPT v4.17.0.

## Three Common Mistakes
- Phenomenon: The agent returns a 422 status code when replying to graphic and text operation guides. Cause: The retrieval priority of graphic and text content is not explicitly specified in the prompt, causing the system to trigger format verification failure when parsing unstructured image files.
- Phenomenon: Retrieval results are chaotic when the knowledge base uses #/## and other title separators. Cause: Photovoltaic encapsulation documents contain a large amount of EL image annotation text and process parameter lines. Title separators cannot distinguish between structured records and unstructured image annotations, leading to incorrect chunking.
- Phenomenon: The new conversation pop-up window cannot be hidden after private deployment, and modifying the code produces no expected effect. Cause: The pop-up window rendering logic is not commented out in the front-end code's `messages` initialization module. Directly modifying static files does not trigger a build update.

## How to Confirm the Configuration Is Correct
- Initiate an inspection dialogue for a single string welding device. Check whether the context parameters include the currently bound device ID and material batch number.
- Upload a lamination process record and an EL image. Confirm that the returned results include material information and defect annotations corresponding to the batch after retrieval.
- Initiate multi-turn interaction. Verify that the context retains the previous inspection’s equipment parameters, with no cross-batch data mixed in.
- Test the reply for graphic and text operation guides. Confirm that no abnormal status codes are returned and the format meets preset requirements.
