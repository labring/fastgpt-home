# Equipment Inspection and Maintenance Q&A for Photovoltaic Module Encapsulation: Workflow Orchestration

## What Data for This Category Looks Like
Data related to photovoltaic module encapsulation equipment inspection and maintenance comes from battery sheet grading ledgers, glass adhesive film and backplane batch records, factory MES systems, string welding and lamination production equipment, EL defect detectors, and IV power testers. Data is updated in real time per single module and per batch of materials. Daily documents include equipment layout diagrams, lamination process parameter records, EL defect images, IV test reports, insulation pressure test results, and finished product packing lists. Data fields include battery sheet current gear, lamination temperature and time parameters, EL crack location coordinates, power test values, and more. Units include amperes, degrees Celsius, seconds, watts, and others.

## What Constraints These Characteristics Impose on the "Workflow Orchestration" Link
Data sources are scattered and update frequently. Workflows must connect to multiple system interfaces to obtain real-time data, and avoid relying on offline static documents. Each single module corresponds to an independent data entry. The component's unique identifier must be passed via `variables` to achieve precise data matching. Document types include images and structured ledgers. Workflows must support serial orchestration of image recognition nodes and text retrieval nodes. Lamination and string welding process parameters are closely linked to EL images. Workflows must call corresponding data in the order of equipment nodes, ensuring the logic chain for inspection and maintenance aligns with the production process. Error consequences include non-compliant power output, lamination delamination, and more. Workflows must set exception branch processing to prevent unqualified modules from flowing to downstream links.

## How to Set Configurations
| Configuration Item | Recommended Practice | Rationale |
|---|---|---|
| `variables` | Bind component ID and device SN code as global variables | Single-module data requires precise matching to avoid cross-batch confusion |
| `nodeId` | Assign unique identifiers in the order of string welding → lamination → EL test → IV test | Workflows must execute in production process order to ensure data flow logic aligns with production flow |
| Single trigger node count | First 4 nodes | Covers core photovoltaic encapsulation inspection processes, avoids invalid nodes consuming resources |
| Timeout threshold | 600 seconds | EL image recognition and IV test data acquisition require a certain amount of time, prevents single-node stalls from blocking the overall workflow |
| Knowledge base association rules | Dynamically switch based on component batch variables | Material batch data updates with each batch, requiring dynamic matching of corresponding process documents |

## Three Common Misconfigurations
- Symptom: Workflow cannot retrieve the component ID parameter from the current page, the field is empty. Cause: No URL parameter mapping rule is configured in `variables`, and the global variable automatic extraction function is not enabled.
- Symptom: EL image recognition node execution times out, out-of-memory errors trigger when single-node concurrency exceeds 30. Cause: No node concurrency upper limit is set, insufficient computing resources are allocated to the image recognition node. For FastGPT v4.17.0, single-node image processing concurrency must be calibrated based on hardware configuration.
- Symptom: When multiple knowledge bases are selected, corresponding documents cannot be correctly retrieved, resulting in 0 result entries. Cause: Knowledge bases are not dynamically switched based on batch variables, all knowledge bases are incorrectly bound as global association items, leading to chaotic retrieval scope.

## How to Confirm Proper Configuration
- Trigger a simulated module production process, check that the component ID and device SN code passed in `variables` match the test data.
- View workflow node logs to confirm that each `nodeId` corresponding process node executes in the order of string welding → lamination → EL test, with no skipped steps or duplicates.
- Submit a test EL image, confirm that the image recognition node can correctly extract crack location information and transfer it to subsequent maintenance Q&A nodes.
- Switch the component batch variable, check that the associated knowledge base updates synchronously, and retrieval results match the current batch's process documents.

The values provided are common starting points and should be evaluated against the reader's own samples.
