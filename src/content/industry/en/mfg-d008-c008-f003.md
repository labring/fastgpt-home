# Equipment Inspection and Maintenance Q&A for Cosmetics Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data for cosmetics manufacturing equipment inspection and maintenance Q&A comes from registered or archived formulas, raw material safety documents, production equipment data such as weighing and emulsification units, ERP/MES systems, laboratory test records, and packaging material version documents.
Data updates trigger per production batch and each line change.
Daily documents include formula process sheets, weighing and feeding records, emulsification or filling records, site cleaning records, semi-finished and finished product test reports, and label review documents.
Data fields include restricted substance parameters, equipment operating temperature, batch numbers, packaging material claim content, and other relevant items. No general statistical fields are included.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering
Cosmetics manufacturing data is updated per batch and line change. Multi-turn dialogue must bind the `variables` parameter corresponding to the target batch to ensure Q&A is linked to the current production batch’s equipment and documents.
Data includes archived formula and label content subject to filing requirements. Prompts must restrict the model to only output inspection and maintenance suggestions that comply with production specifications, and must not involve content outside the production scope.
Most equipment inspection and maintenance questions use colloquial language. Queries must be optimized to match structured production documents. Context overload must be avoided, so only `messages` history related to the current batch is retained in each dialogue round.
In addition, equipment parameters and test results linked to the data directly affect production compliance. The accuracy of Q&A must strictly match the document content of the corresponding batch.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Bind production batch number, equipment number | Cosmetics manufacturing data is updated independently per batch. Passing batch and equipment information via `variables` ensures Q&A is linked to knowledge base documents for the corresponding batch |
| `messages` | Retain the first 10 rounds of dialogue context | Common equipment inspection and maintenance workflows require tracing 3-8 rounds of fault record dialogues. 10 rounds cover complete troubleshooting conversation chains |
| Maximum context length | 8000–12000 characters | Single-batch cosmetics manufacturing documents include multiple sections of formula and equipment parameter content. This length can fully accommodate all associated data, as calibrated through actual testing |
| Query optimization | Enabled | Most equipment inspection queries use colloquial language. Optimization converts phrases such as “the emulsifier stopped” to standard terminology, matching more precise knowledge base entries |
| Single recall limit | Top 6 entries | Cosmetics manufacturing equipment documents have clear classifications. Too many recalled entries will cause context overload. 6 entries cover common inspection and maintenance scenarios |
| Knowledge base update trigger | Auto-sync after each production batch is completed | Cosmetics manufacturing data is updated per batch. Real-time sync ensures Q&A uses the latest cleaning and test records |

## Three Common Misconfigurations
- Phenomenon: Dialogue responses time out or lag. Logs show excessive context loading time. Cause: The number of retained `messages` context rounds is not limited. Excessive historical dialogue data occupies model computing resources.
- Phenomenon: Uploaded feeding or cleaning records do not appear in dialogue responses. Cause: Uploaded files are not bound to `variables` parameters. The knowledge base is not linked to production documents for the corresponding batch.
- Phenomenon: Calls for multimodal equipment inspection photos return a 400 invalid image error. Cause: Uploaded images do not carry the `chatId` associated parameter, or the image format does not meet the specifications required by FastGPT v4.17.0.

## How to Verify Correct Configuration
- Initiate an equipment inspection query. Confirm automatic inclusion of the production batch number and equipment number in the dialogue to verify correct binding of the `variables` parameter.
- Upload cleaning records for a single batch. Initiate a summary query to confirm the response includes key content from the uploaded document, verifying that knowledge base linking is active.
- Call multimodal functionality to upload equipment fault photos. Confirm returned troubleshooting suggestions match the equipment parameters for the corresponding batch, verifying proper `chatId` association.
- Test multiple consecutive dialogue rounds. Confirm response times meet expected standards, verifying that the `messages` context limit configuration is active.
