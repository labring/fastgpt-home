# Cosmetics Manufacturing Equipment Inspection and Maintenance Q&A: Knowledge Base Retrieval and Recall

## What this category's data looks like
Data for this category originates from registered or filed formulas, raw material safety documents, weighing and emulsification equipment, ERP/MES systems, laboratory records, and packaging material version files. Daily documents include formula work orders, weighing and feeding records, emulsification or filling records, cleaning and sanitization records, semi-finished and finished product inspection reports, and label review documents. Data updates trigger with each production batch and each line change. Document fields cover raw material component proportions, equipment operating parameter thresholds, batch numbers, filing numbers, and more. Units align with corresponding measurement standards based on document type.

## What constraints do these characteristics impose on the "knowledge base retrieval and recall" link
Data updates for this category trigger with each production batch and each line change, requiring the knowledge base retrieval link to support high-frequency incremental updates and prioritize recalling the latest batch equipment parameters and process documents. Document types cover multiple categories including formulas, equipment records, inspection reports, and others. Document scenario weights must be distinguished during retrieval to avoid formula data interfering with accurate recall for equipment inspection. Fields include compliance-related content such as filing numbers. Recall results must match enterprise registered and filed information to prevent operational guidance that does not meet compliance requirements. Units for equipment parameters and inspection data vary by document type. The retrieval link must support contextually associated unit matching to avoid parameter confusion. Equipment inspection in production scenarios requires rapid response, so retrieval latency must be controlled within a reasonable range aligned with production rhythm.

## Three common configuration mistakes
- Issue: Matching equipment documents can be found in the knowledge base backend, but no valid output is returned after passing to the large model. Cause: The `limit` value is set too low, resulting in insufficient valid data recalled, or the context length exceeds the large model's processing limit, making the model unable to read the recalled content.
- Issue: Manually created knowledge base documents are always attached to the root directory, and cannot generate a hierarchical structure using the preset parent ID. Cause: The parent collection ID corresponding to the `collectionIds` parameter is not correctly specified, or the parameter format does not meet FastGPT's verification rules.
- Issue: Equipment inspection retrieval latency exceeds 10 seconds, with no obvious optimization even for single equipment document scenarios. Cause: `usingReRank` is not enabled to filter redundant results, or `searchMode` is configured for vector-only retrieval, adding unnecessary computation chains.
