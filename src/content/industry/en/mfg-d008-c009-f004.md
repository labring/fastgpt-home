# Equipment Inspection and Maintenance Q&A for Pharmaceutical Dosage Production: Workflow Orchestration

## What This Category's Data Looks Like
Data sources for this category include approved formulation processes, material batches, MES/electronic batch records, equipment and environment monitoring systems, LIMS, and quality management systems.
Data updates follow three schedules: per production batch, each critical process step, and execution per equipment monitoring plan.
Daily archived documents include master production files, batch production records, cleaning records, deviation/CAPA/change records, and batch release review forms.
Covered fields include equipment number, inspection time, maintenance record number, deviation type, test results, and more.
Units include temperature ℃, pressure kPa, operating duration hours, and others.
All data is archived and stored by production batch.

## Constraints for Workflow Orchestration
Data for this category is linked by production batch, and its update rhythm strictly matches process steps. Workflows must bind exclusive `variables` for the current batch to prevent cross-batch data confusion.
Multi-source system data access requires workflows to connect different nodes. This ensures data synchronization time windows align with batch production tempo.
Under GMP compliance requirements, workflows must include data validation links. This stops non-compliant maintenance or inspection records from entering the process.
After an error occurs, a deviation record synchronization process must be triggered. This meets traceability requirements of the quality management system.

## How to Configure
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger condition setup | Triggered by equipment inspection completion events | Matches the execution rhythm of equipment inspections and syncs with batch production steps |
| `variables` binding rules | Bind the current batch's equipment ID and material batch number | Associates production data and equipment maintenance records for the corresponding batch to avoid cross-batch data mixing |
| `nodeId` association rules | Bind the unique identifier of the corresponding equipment node | Ensures the workflow calls exclusive data for the currently inspected equipment |
| Node timeout setting | 1200 seconds | Equipment maintenance Q&A requires retrieving data from multiple systems, reserving sufficient response time |
| Image display configuration | Directly parse and render incoming image URLs | Meets the need to view equipment fault photos during maintenance scenarios |
| Multilingual opening configuration | Automatically switch between Chinese and English based on the initial conversation language | Adapts to language requirements for cross-department collaboration |

## Three Common Misconfigurations
- Phenomenon: Confusion between workflow and plugin functional boundaries, leading to duplicate configuration of single-function nodes. Cause: Failure to clarify the difference between workflows (used to connect multi-step processes) and plugins (used to encapsulate single functions).
- Phenomenon: Image URLs passed in the workflow cannot be rendered and displayed. Cause: The image parsing and rendering configuration item is not enabled, and the URL is not correctly bound to `variables`.
- Phenomenon: The workflow’s multilingual opening lines do not switch as expected. Cause: The conversation language identifier is not bound to `variables`, and opening line templates for corresponding languages are not configured.

## How to Verify Proper Configuration
- Use the workflow editor in FastGPT v4.17.0 to trigger a simulated equipment inspection event. Check whether the workflow starts as expected.
- Pass a test equipment fault image URL. Confirm that the workflow node can correctly render and display the image.
- Switch the conversation language to English. Check whether the opening line automatically switches to the corresponding language template.
- Simulate a node timeout scenario. Confirm that the workflow triggers the preset failure handling process and synchronizes deviation records.
