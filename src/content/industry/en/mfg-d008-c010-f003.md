# Equipment Inspection and Maintenance Q&A for Medical Device Assembly and Clean Production: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Core data for medical device assembly and clean production comes from design history files, component and material batch records, MES systems, clean environment monitoring equipment, sterilization equipment, and inspection and calibration systems. Daily documents include production process specifications, batch production records, clean zone operation records, sterilization batch records, inspection reports, software version records, and adverse event traceability materials. Data updates are performed per product batch or per piece of equipment, and are also updated regularly in accordance with clean environment monitoring plans. Document fields include controlled content such as unique device identification, material batch numbers, sterilization parameters, and cleanliness values.

## Constraints These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering
These characteristics impose clear constraints on multi-turn dialogue and prompt engineering. First, data is updated per batch or per piece of equipment. This requires dialogues to be bound to the corresponding batch identification to avoid interference from cross-batch documents. Second, documents include controlled sterilization, cleanliness parameters, and traceability information. Prompts must strictly limit calls to only controlled content related to the current inspection or maintenance issue, to prevent introduction of unrelated adverse event records. Additionally, multi-turn dialogues must retain context such as the previous round’s equipment number and batch number, to ensure accurate matching of corresponding documents during follow-up questions. Finally, the real-time nature of on-site inspection requires dialogue responses to align with production rhythms, to avoid excessive waiting times.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | 8000–12000 characters | Must accommodate key content from multiple core documents such as single-batch production records and sterilization batch records |
| Single Search Limit | Top 3 results | Meets the accuracy requirement for matching key documents in medical device assembly scenarios, and avoids redundant content |
| Referenced Content Template | Retain original text fields and units | Complies with compliance requirements for this category of documents, which need to label batches and sterilization parameters |
| Referenced Template Prompt | Only extract controlled content related to the current inspection or maintenance issue | Filters out unrelated adverse event and traceability records, and focuses on the current issue |
| `variables` | Bind current equipment batch number and clean zone number | Accurately associates production and monitoring data for the corresponding batch |
| Dialogue Timeout | 60 seconds | Adapts to the real-time response requirement for on-site production equipment inspection |

## Three Common Misconfiguration Issues
- Symptom: After creating a knowledge base via the API, calling the dialogue interface fails to retrieve content from the corresponding knowledge base. Cause: The knowledge base association identifier is not bound in the `chatId` or session parameters, causing the dialogue to fail to locate the target document library.
- Symptom: Significant differences exist between online dialogue and API call return results. When `detail` is set to true for the API, a large amount of redundant content is returned. Cause: Filter rules for the referenced template prompt are not clearly configured, causing the API to return fully matched document fragments without focusing on the current issue.
- Symptom: The configuration logic of the referenced content template and referenced template prompt is confused, leading to unexpected return content. Cause: The respective roles of the two are not distinguished. The referenced content template is used for issue filtering, while the referenced template prompt is used for format output.

## How to Verify Proper Configuration
- Initiate a test dialogue, enter an assembly inspection question for a specific batch of medical devices, and verify that the returned content only includes fragments of the production process specifications and sterilization records for that batch.
- Call the API interface, pass in the batch number and clean zone number bound via `variables`, and check that the returned results are associated with the controlled documents for the corresponding batch.
- Compare the return content of the online dialogue and API call, and confirm that the referenced fragments and prompt constraints are consistent between the two.
- Initiate consecutive multi-turn questions, and verify that the context retains the previous round’s equipment number and question information, with no content drift.
