# Equipment Inspection and Maintenance Q&A for Medical Device Assembly and Cleanroom Production: Workflow Orchestration

## What the data for this category looks like
Data sources include design history files, device and material batch ledgers, MES systems, clean environment monitoring equipment, sterilization equipment, and inspection and calibration systems. Daily documentation covers production process specifications, batch production records, clean zone operation records, sterilization batch records, inspection reports, software version records, adverse event and traceability materials. Data updates run per product batch or equipment cycle. Clean environment monitoring data updates follow a set schedule. Document fields include unique device identification, batch number, sterilization parameters, clean zone temperature and humidity values, inspection results, and other relevant items.

## Constraints imposed on workflow orchestration by these data characteristics
Data from this category has dispersed but closely linked sources. Configure cross-node data pulling logic to integrate batch, sterilization, and clean environment information from multiple systems. Data updates follow batch or scheduled cycles. Workflows must support batch-triggered or scheduled synchronization to avoid calling expired data. Documents include sensitive fields such as unique device identification and batch number. Use `variables` to store dedicated parameters to prevent mixing of data from different batches. Process errors can lead to severe consequences. Workflows must add pre-check links to ensure inspection and maintenance operations comply with controlled production requirements.

## Configuration settings
This page uses FastGPT v4.17.0 for configuration.

| Configuration Item | Recommended Approach | Rationale |
|---|---|---|
| Global variable storage | Generate dedicated `variables` sets per batch, store unique device identification and sterilization batch numbers | This category requires separate dedicated data for each device or product batch to avoid cross-session data mixing |
| Node trigger rules | Trigger per clean environment monitoring cycle (once every 7 days) or batch production node | Data updates follow scheduled or batch cycles, so inspection workflows must align with data update timelines |
| Multi-parameter supplementary configuration | Collect supplementary parameters step-by-step per session, with no more than 3 parameters collected per attempt | Some equipment inspection and maintenance tasks require multiple parameters such as device model and operating duration, which must be obtained gradually via workflow Q&A links |
| Session variable retention rule | Retain `variables` only within the current batch session | Data from different batches must be isolated to prevent cross-session parameter residue |
| Abnormal node marking | Configure `nodeId` to mark abnormal nodes and trigger manual intervention workflows | Process errors in this category can lead to severe consequences, so abnormal links must be quickly identified and intervention triggered |

## Three common configuration errors
- Symptom: Interactive nodes configured in the workflow do not respond, and the parameter supplementary link cannot be triggered. Cause: The interactive node and tool call node are not correctly linked, and no parameter transfer logic is configured.
- Symptom: Global variable values are not cleared after a session ends, and old batch data remains when the next session is called. Cause: No session-level variable isolation rules are configured, and `variables` are set to global sharing.
- Symptom: Tool calls prompt insufficient parameters, and the inspection workflow cannot be completed. Cause: Multiple parameters are not collected gradually via workflow Q&A links, and tools are called directly with preset incomplete parameters.

## How to confirm correct configuration
- Trigger a batch production node workflow, check if `variables` generate dedicated identifiers and parameters for the current batch, and confirm data is not mixed with other batches.
- End the current session, enter a new session, and check if `variables` are reset with no old batch parameter residue.
- After configuring multi-parameter supplementary nodes, trigger a tool call, and confirm the workflow will initiate parameter inquiries in sequence until all required parameters are collected.
- Simulate an abnormal node trigger, and confirm the workflow marks the abnormal link via `nodeId` and jumps to the manual intervention workflow.
