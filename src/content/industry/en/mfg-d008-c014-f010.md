# Equipment Inspection and Maintenance Q&A for Dyeing and Finishing: Knowledge Base Retrieval and Recall

## What this category of data looks like
Data originates from daily outputs and equipment collections of dyeing, setting, laboratory, and quality departments in dyeing and finishing plants. Included content covers dyeing formulas, chemical dosing records, dye vat curves, sample confirmation reports, color difference reports, setting process sheets, sewage ledgers, and similar items. Data sources include customer color samples, formula libraries, dye chemical batches, dye vat control systems, colorimeters, setting machines, and environmental monitoring equipment. Update frequency follows per vat, per batch, or per shift cycles. Each data entry contains fields such as process parameters, batch information, and test results. No unified fixed format exists; data changes dynamically based on production links.

## What constraints do these characteristics impose on knowledge base retrieval and recall
Data for this category is updated frequently by production vat, batch, or shift. Retrieval and recall processes must support real-time or near-real-time knowledge base synchronization to prevent the return of outdated process parameters. Multi-source heterogeneous data structures include structured process parameters, unstructured curves, and test reports. Retrieval must support matching content across mixed formats. Precise matching per vat and per batch is required, which involves filtering historical data from irrelevant batches. Targeted retrieval for professional fields such as color difference and dye vat curves must also be supported, to avoid redundant results interfering with equipment inspection and maintenance judgments.

## How to set configurations
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Meets the accuracy requirements for matching dyeing and finishing process parameters, filters low-relevance historical batch data, and prevents accidental recall of parameters from non-current vats |
| `limit` | Top 8–12 results | Adapts to the limited retrieval result requirements for single-vat production, avoids excessive redundant information interfering with maintenance personnel’s judgments, and covers common inspection scenarios |
| `searchMode` | `mixedRecall` | Adapts to content that includes both professional terminology and numerical parameters such as dyeing formulas and color difference reports, balances semantic matching and precise field recall |
| `usingReRank` | Enabled | Enables re-ranking to improve the ranking priority of highly relevant results for unstructured dye vat curves and color difference reports, optimizing the retrieval experience for maintenance Q&A |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands professional terminology for user inspection questions, associates "color stains" with related expressions such as "uneven dyeing" and "poor dye dispersion", covering more potential matching content |
| `collectionIds` | Bound to the exclusive knowledge base collection of the current factory | Isolates process data from different batches and production lines, prevents irrelevant cross-production line data from being recalled, and ensures the targeting of retrieval results |

## Three common configuration mistakes
- Phenomenon: Retrieval returns "no matching results" or 0 total results, and cannot recall dye vat parameters or maintenance solutions for the corresponding vat. Cause: `datasetSearchUsingExtensionQuery` is not enabled, professional term extended matching is not covered, and exclusive `collectionIds` are not bound, leading to an overly large retrieval scope that filters target data.
- Phenomenon: Retrieval results include cross-production line, non-current batch process data, leading to incorrect maintenance judgments. Cause: `collectionIds` is not configured to bind the exclusive knowledge base collection, and the retrieval scope covers all factory data, resulting in excessive redundant data.
- Phenomenon: Retrieval results are disordered, with non-critical historical data appearing first, and solutions for current problems cannot be quickly located. Cause: `usingReRank` is not enabled, and unstructured dye vat curves and color difference reports are not optimized via re-ranking; sorting only relies on basic similarity calculations.

## How to confirm the configuration is correct
An inspection question containing professional terms may be submitted. Retrieval results are verified to include process data for the corresponding vat, confirming that the `similarity` threshold range meets current production requirements.
The number of retrieval results is reviewed, confirming that the `limit` configuration value adapts to the current scenario’s information display needs.
A question with vague wording, such as "methods for handling color stains", may be submitted. Matching content related to extended terms is verified to be recalled, confirming that `datasetSearchUsingExtensionQuery` is active.
Retrieval results are checked to only include process data from the current production line, confirming that the exclusive knowledge base collection bound by `collectionIds` is configured correctly.

Note: The configuration values provided here are common starting points. They should be evaluated against production samples and operational needs specific to the deployment.
