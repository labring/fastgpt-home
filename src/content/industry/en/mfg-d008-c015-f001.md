# Equipment Inspection and Maintenance Q&A for Active Pharmaceutical Ingredient and Pharmaceutical Intermediate Manufacturing: HTTP Interfaces and External Systems

## What this category of data looks like
Data sources include registered process documents, raw material batch ledgers, DCS control systems, weighing systems, LIMS laboratory information management systems, chromatography data systems, and QMS quality management systems. Updates are triggered for each production batch and each process step. Daily documents include batch production records, material balance reports, reaction and purification process records, cleaning validation records, impurity profile reports, and deviation and change management documents. Data fields include process parameters, batch identifiers, impurity test values, cleaning validation results, quality deviation records, and more. There are no unified fixed units; values align with the corresponding business scenario.

## What constraints these characteristics impose on HTTP interfaces and external systems
Data sources for this category are scattered across multiple types of business systems, so HTTP interfaces must support pull requests for heterogeneous data sources. Updates are triggered per batch and per process step, so interfaces must support on-demand query triggering or short-cycle scheduled synchronization to avoid data lag. Document structures are complex and fields are inconsistent, so `responseData` must support nested field parsing to adapt to the field formats of different business documents. Business data is linked to batches and process nodes, so interfaces must support batch identifiers and process node IDs as query parameters. Additionally, since compliance-related data is involved, `Authorization` validation must strictly use application-level API keys.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Use application-level API keys | Data for this category involves compliance management, and application-level keys can restrict access scope to ensure data security |
| `variables` | Configure batch ID and process node ID as query variables | Data updates are tied to production batches and process steps, so variables enable precise matching of corresponding business data |
| `responseData` | Enable nested field parsing mode | Daily documents contain multiple types of business data with nested structures, and this configuration can fully extract required fields |
| Request timeout | 60–120 seconds | When connecting to multiple heterogeneous systems, sufficient time must be reserved for data pulling and parsing |
| Single query limit | Top 10 data entries | Avoid returning excessive redundant data in a single request, and adapt to query requirements for single-batch process steps |
| Context window size | 8000–12000 token | Adapt to the content length of multiple types of business documents to ensure complete contextual information |

## Three common mistakes
- An interface returns a `400 do request failed` error, and logs show key validation failure. The cause is using a globally universal API key instead of an application-level key, which does not meet the access permission requirements for compliance data in this category.
- The `responseData` field returned by the interface is empty. The cause is that `variables` are not configured as batch IDs or process node IDs, so it is impossible to accurately match business data for the corresponding production batch.
- The interface request times out. The cause is that the request timeout is not set appropriately, and sufficient time is not reserved for pulling and parsing data when connecting to multiple heterogeneous systems.

## How to confirm the configuration is correct
- Use the FastGPT v4.17.0 platform, call the interface with a test batch ID, and check whether the returned `responseData` includes process parameters and impurity test data for the corresponding batch.
- Check whether the `Authorization` field in the interface request header is an application-level API key.
- Simulate a multi-source system connection scenario to verify whether the interface can complete data return within the preset timeout period.
- Adjust the value of the `variables` parameter, and check whether the query result updates as the batch ID or process node ID changes.
