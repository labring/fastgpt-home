# Equipment Inspection and Maintenance Q&A for Active Pharmaceutical Ingredient and Pharmaceutical Intermediate Production: Forms and Interactions

## What data for this category looks like
Data sources for this category include registered process documents, raw material batch ledgers, DCS control systems, weighing systems, LIMS laboratory information management systems, chromatography data systems, and QMS quality management systems.
Data updates trigger per production batch and each process step.
Daily documents cover batch production records, material balance ledgers, reaction and purification process records, cleaning validation records, impurity profile analysis reports, deviation and change control documents.
Data fields include batch identifiers, process parameter values, material weighing data, impurity concentrations, yield calculation values, with corresponding units: batch numbers, degrees Celsius, kilograms, mg/L, and calculation units.

## Constraints imposed by these characteristics on forms and interactions
Data from multiple system sources requires forms to support cross-source data pulling and field pre-filling, to avoid duplicate data entry.
The high-frequency update rhythm requires forms to support quick submission and real-time verification, to ensure timely archiving of each step's data.
Multiple document and field types require forms to be split by business modules, to reduce filling complexity.
Data linked to batch and equipment attributes requires forms to force association with corresponding identifier fields, to ensure traceability.
Compliance-related control requirements require forms to leave full operation traces, to facilitate subsequent audits.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `formInput` | Allow association with field preset values from LIMS and chromatography data systems | Data for this category is scattered across multiple systems. This configuration reduces manual entry errors and improves data accuracy |
| `userSelect` | Preset equipment model and inspection item classification options, with no more than 20 options | Pharmaceutical API production equipment types are relatively fixed. This reduces input errors and format inconsistencies |
| Form block configuration | Split into 3 sections: inspection, maintenance, and exception reporting. Each section has no more than 10 fields | Daily documents are categorized by business module. Blocking reduces filling complexity and improves accuracy |
| Required field validation rules | Batch number and equipment number fields are required. Validation format is uppercase letters plus 6 digits | Data must link to batches and equipment, to ensure every record can be traced to the corresponding production link |
| Submission trigger configuration | Automatically sync to the QMS system after filling is complete. Sync delay does not exceed 60 seconds | Data updates occur per process step. Records must be archived to the quality management system in a timely manner |
| Context loading configuration | Load 3 historical inspection and maintenance records linked to the current batch | Maintenance and inspection work must reference past data from the same batch, to ensure consistent decision-making |

## Three common configuration mistakes
- The symptom is that the form cannot load cross-system preset fields, and no corresponding data is filled after submission. The cause is that the data source association permission for `formInput` is not configured, so the system cannot pull corresponding data from LIMS or chromatography data systems.
- The symptom is that users cannot find matching options when selecting inspection items, and cannot manually enter supplementary content. The cause is that the custom input switch for `userSelect` is not enabled, and the preset options do not cover niche equipment inspection scenarios for pharmaceutical API production.
- The symptom is that tool calls in advanced orchestration cannot select the corresponding maintenance knowledge base tool, and return empty results. The cause is that the category-specific document library is not bound in the tool configuration of FastGPT v4.17.0, so the model cannot recognize the available industry knowledge base tools.

## How to verify a correct configuration
- Submit a test batch inspection form, check if DCS parameters for the corresponding batch are automatically pulled into the form's preset fields.
- Click the inspection item dropdown menu, confirm the list includes common equipment inspection content for pharmaceutical API production, and that custom supplementary options are available.
- Submit a form without the batch number filled in, check if the system displays a format error prompt.
- Submit a complete form, check if the QMS system receives the corresponding record within 60 seconds.

The values provided here are common starting points, and should be evaluated against samples matching the actual deployment context.
