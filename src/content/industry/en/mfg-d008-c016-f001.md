# Equipment Inspection and Maintenance Q&A for Transformer and High-Voltage Electrical Manufacturing: HTTP Interfaces and External Systems

## What the Data for This Category Looks Like
Business data sources for this category include design BOM, silicon steel sheet and insulating material data, vacuum and drying equipment, oil testing, and test stations. Data is updated once per piece of equipment or per batch of materials. Daily documents include winding and core assembly records, vacuum drying records, insulating oil reports, partial discharge and withstand voltage test reports, and nameplate parameter tables. Fields cover insulating water content, partial discharge amplitude, withstand voltage test voltage, and other metrics, with units of ppm, pC, and kV respectively. Data is traced per individual piece of equipment, and each document is bound to a unique nameplate number.

## Constraints on HTTP Interfaces and External Systems
Multiple types of documents for a single piece of equipment are bound to a unique nameplate number. This requires that HTTP interfaces must carry device identification parameters to complete data association. Data sources cover multiple types of production and test equipment, so interfaces need to support pulling multi-dimensional business data by device ID and batch number. Each piece of equipment has a large volume of documents and a fixed update frequency, so interfaces need to adapt to incremental synchronization and batch pulling scenarios. Insulation-related and test-related data have strict requirements for units and value ranges. Interfaces need to include basic verification rules to prevent incorrect data from entering the Q&A process.

## How to Configure Settings
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | `Bearer {internal enterprise API key}` | Complies with HTTP interface authentication specifications, and adapts to the internal system authentication logic of power transmission and distribution equipment manufacturers |
| `variables` | Bind nameplate number, insulating oil water content, partial discharge detection value | Matches the core query dimensions of equipment inspection and maintenance Q&A, and associates all business data for a single piece of equipment |
| `responseData` | Only return test reports and maintenance records from the past 30 days | Filters redundant historical data to improve Q&A response speed |
| Request timeout | `600 seconds` | Parsing and transmission of large insulating oil reports and partial discharge test data takes a long time |
| Number of data entries per single request | `5 devices` | Balances interface load and data synchronization efficiency, and adapts to the characteristic of multiple documents per piece of equipment |

## Three Common Mistakes
- When the interface is called, the error `failed to get gpt-3.5-turbo token encoder` is returned. The cause is that exclusive insulating business variables for the transformer category are not correctly bound, which prevents the model from recognizing the encoding logic of exclusive business terms.
- Every interface call returns fixed recommended questions. The cause is that the business data filtering rule for `responseData` is not configured, and the interface returns all historical data, which causes the model to repeatedly match generic questions.
- When FastGPT is called, a prompt indicates that the model stream response is empty. The cause is that the request timeout is set too short, and large partial discharge test reports are interrupted by the interface before transmission is completed.

## How to Confirm the Configuration Is Complete
- Invoke the test interface using a known transformer nameplate number, and verify whether the returned `responseData` includes the insulating oil report and partial discharge test data for the corresponding device.
- Review the authentication configuration, confirm that the format of the `Authorization` field complies with the Bearer token specification, and there are no spelling errors or risks of key exposure.
- Initiate a batch request, confirm that the number of devices per single request does not exceed the preset threshold, and the interface has no timeout errors or data truncation issues.
- Trigger a maintenance Q&A query, verify whether the model correctly associates the bound `variables` field and generates inspection and maintenance suggestions for the device.
