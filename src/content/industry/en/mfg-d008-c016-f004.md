# Equipment Inspection and Maintenance Q&A for Transformer and High-Voltage Electrical Equipment Manufacturing: Workflow Orchestration

## What the data for this category looks like
The data for this category comes from design BOM, silicon steel sheet and insulating material inventory data, vacuum drying equipment, oil test ledger, and high-voltage test station records. The data update cycle is once per finished product and once per batch of purchased materials. Daily documents include winding and core assembly records, vacuum drying records, insulating oil reports, partial discharge and withstand voltage test reports, and nameplate parameter tables. Fields include rated voltage, insulating oil moisture content, partial discharge value, etc., with corresponding units of kV, ppm, and pC respectively.

## What constraints these characteristics impose on the workflow orchestration link
The single-unit traceability requirement for this category means the workflow must bind exclusive data for a single device, to avoid mixing batch and finished product data. The high-frequency update requirement for each unit and batch means the workflow must support dynamically passing in the document identifier or batch parameter for a single device. Fields with professional units such as insulating oil moisture content and partial discharge value require the workflow to retain the original data format, to avoid unit conversion errors. Unstructured content in high-voltage test reports requires the workflow to be configured with document splitting rules adapted to electrical professional terminology, to ensure the accuracy of keyword recall. Troubleshooting for high-voltage test abnormalities must be linked to original test data, to avoid misjudgment caused by data fragmentation.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Pass in the document ID and knowledge base ID of a single device | Adapt to the single-unit traceability requirements of this category, and support dynamic binding of test reports corresponding to the batch |
| Single search limit | Top 6 entries | Match the core parameter recall volume of high-voltage test reports, and avoid redundant data interfering with AI responses |
| Context length | 1200–1800 characters | Accommodate key content from multiple professional reports such as insulating oil and partial discharge, and ensure the information integrity of responses |
| `nodeId` | Bind to the equipment inspection task node | Accurately link the inspection process of a single device, and avoid confusion between cross-device tasks |
| Document splitting rules | Segment by report type | Match the structure of different documents such as winding records and test reports, improve keyword recall accuracy, and adapt to the document processing logic of FastGPT v4.17.0 |

## Three common mistakes
- Workflow calls prompt that the knowledge base was not found, and return empty results. The `variables` do not correctly pass the dynamic knowledge base ID, and only global variables are used without overriding the exclusive knowledge base configuration for a single device.
- After uploading the test report for a single device, the analysis process cannot be triggered. The document upload node is not linked to the inspection task bound with `nodeId`, and the trigger condition does not match the single-device identifier of this category.
- The AI response does not reference the specified partial discharge or withstand voltage test report. The document splitting rules do not segment by report type, resulting in professional keywords not being correctly recalled, and failing to link the corresponding test data.

## How to confirm the configuration is complete
- Call the workflow API, pass in the document ID and knowledge base ID of a single transformer, and check whether the returned results are linked to the content of the corresponding test report.
- Upload the insulating oil report for a single device, confirm whether the workflow automatically triggers the analysis process and generates the corresponding Q&A results.
- View the workflow log, confirm that both the `variables` parameter and the `nodeId` parameter have correctly passed the identifier of the corresponding device.
- Simulate a query for partial discharge abnormalities, confirm that the AI response includes the original values and units of the corresponding test report.
