# Spraying and Coating Equipment Inspection and Maintenance Q&A: Deployment and Upgrade

## What This Category of Data Looks Like
Data for the spraying and coating scenario covers the entire coating process. Daily documents include coating process cards, paint batch sheets, paint mixing records, film thickness and color difference reports, oven curves, defect repair orders, and VOCs ledgers. Data sources are paint supplier TDS/SDS documents, real-time collection data from spray booths and ovens, colorimeters, film thickness gauges, environmental monitoring equipment, and factory MES systems. Update frequency follows per paint batch and per shift schedules. Some device data is collected continuously. Fields include film thickness (unit μm), color difference ΔE value, oven temperature (unit ℃), VOCs concentration (unit mg/m³), and others. Most document structures fall into two categories: structured forms and time-series curves. Some documents require linking to batch and work order information.

## What Constraints These Characteristics Impose on the Deployment and Upgrade Phase
Data sources for this scenario cover equipment, testing instruments, business systems, and external supplier documents. The formats and update rhythms of multi-source data vary widely. Continuously collected real-time data from spray booths and ovens generates high-frequency write requests, which imposes clear limits on database connection counts. Storing multiple batches of paint documents alongside real-time testing data requires the knowledge base to support mixed retrieval of structured fields and time-series curves. VOCs ledgers are compliance-related business data. Deployment must include clear storage permission and encryption configurations. During upgrades, compatibility must be maintained with the original block rules of coating process cards, existing retrieval matching logic must not be disrupted, and adaptation must be made to different versions of device data reporting formats.

## Three Common Mistakes
- Phenomenon: Local debugging operates normally, but Docker image packaging results in database connection failure. Cause: Database connection parameters such as `MONGODB_URI` are not correctly injected during image construction, leading to failure to read external database configurations within the container.
- Phenomenon: Search results only display single user query content, and no matching search term list is shown. Cause: Multi-search term optimization configuration is not enabled, or the response template logic is not updated synchronously after upgrading FastGPT.
- Phenomenon: Local deployment fails to load the local coating document library. Cause: Local storage path is not configured, or offline-dependent model files and document resources are not fully packaged into the deployment image.
