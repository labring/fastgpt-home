# Equipment Inspection and Maintenance Q&A for Furniture and Wood Products Manufacturing: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Typical entities in this category include panel furniture, solid wood furniture, custom home and door enterprises. Daily business documents include order breakdown drawings, cutting lists, edge banding and drilling programs, coating process documents, hardware bill of materials, and trial assembly and packaging records.
Data mainly comes from order design systems, sheet and wood batch ledgers, CNC cutting and drilling equipment logs, ERP/MES systems, and moisture content test records.
Data is updated via three standard cadences: exclusive documents are generated for each order, production progress is synced daily, and corresponding ledgers are updated for each raw material batch.
Document fields include panel size parameters, process parameters, material codes, and test values. Most units are millimeters, cubic meters, and kilograms.

## What constraints these characteristics impose on knowledge base retrieval and recall
Custom order-driven multi-variety, small-batch requirements mean the knowledge base must quickly recall exclusive order breakdown and process data per order.
Mixed storage of multiple document types requires configuring retrieval rules adapted to different document structures.
Frequently updated batch data requires prioritizing recall of latest sheet and equipment logs during retrieval.
Retrieval needs for precise parameters such as panel size and hole positions require limiting matching precision of recall results, to avoid production errors from fuzzy matching.
Trial assembly records related to on-site installation must be linked to equipment inspection and maintenance scenarios, to ensure recall results cover full-link business.

## Three common errors
- When uploading cutting lists or order breakdown drawings in PDF format to the knowledge base, an "offset out of range" error appears when upload progress reaches around 90%, with a relatively high occurrence rate. The cause is failure to adjust parsing rules for structured PDF documents, leading to block offset calculation exceeding valid ranges during file parsing.
- When calling a workflow via API, a specified knowledge base cannot be referenced, and returns empty fields or permission errors. The cause is incorrect configuration of the `collectionIds` parameter, or failure to bind valid IDs of the corresponding dataset to global variables.
- Retrieval results show reference to professional knowledge base content, but the generated answer is completely unrelated to the knowledge base documents. The cause is failure to set a reasonable `similarity` threshold, leading to low-match recall results being included in the context.

## How to confirm the configuration is set correctly
- Upload a single structured PDF document, check that the upload process completes normally with no offset-related errors.
- Call a workflow via API, pass the configured dataset ID, check that retrieval results from the corresponding knowledge base can be obtained normally.
- Enter queries related to equipment inspection or maintenance, check that recall results meet the preset threshold rules for matching precision, and that results are strongly related to the query scenario.
- Compare retrieval results with and without the re-ranking function enabled, confirm that sorted results better align with business needs.
