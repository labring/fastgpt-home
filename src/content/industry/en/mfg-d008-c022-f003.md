# Equipment Inspection and Repair Q&A for Complete Home Appliance Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What This Category’s Data Looks Like
This category’s data includes bill of materials (BOM), assembly work instructions, refrigerant charging records, electrical safety test reports, performance sampling test reports, repair records, and more. Data sources include ERP/MES systems, component batch ledgers, tightening and charging equipment, safety compliance testers, performance laboratory data, and after-sales fault records. Data updates follow three cadences: per individual product, per shift output, and per sampling plan. Fields include component batch numbers, process parameter values, test results, fault types, and other fields.

## Constraints on Multi-turn Dialogue and Prompt Engineering
Mixed-model assembly on the same production line requires multi-turn dialogue to accurately distinguish exclusive process parameters for different product models. Prompts must bind to configuration BOMs and assembly work instructions for the corresponding model, to prevent cross-model misassembly. Per-individual-product update data requires dialogue context to retain batch information for single equipment, to avoid mixing process parameters across batches. Shift-level and sampling-level documents require dialogue support for time-based data retrieval. Prompts must be configured with logic to filter results by shift or sampling plan. For scenarios where after-sales faults are linked to repair records, multi-turn dialogue must gradually guide users to provide fault symptoms, product model, production batch, and other information, to narrow search scope and match corresponding documents.

## Three Common Mistakes
- Calling the dialogue guidance interface returns the `unAuthChat` error, while the API key has been filled. The cause is that the interface permission scope is not configured, or the function permission for equipment inspection and repair Q&A is not enabled for the application bound to the API key.
- The AI dialogue return result contains line breaks, triggering a JSON parameter request failure. The cause is that the return result is not escaped, and the result formatted output option is not enabled.
- An upload error is returned when uploading documents such as configuration BOMs and refrigerant charging records, but the text input dialogue function works normally. The cause is that the uploaded file format does not match the system-supported types, or the file size exceeds the preset limit.

## How to Verify Configuration Completion
- Initiate a test dialogue that includes product model and production batch, verify that the retrieval results match the exclusive documents for the corresponding model.
- Upload a test assembly work instruction, confirm that the upload succeeds and the document content can be called normally during retrieval.
- Trigger a multi-turn dialogue, confirm that the context retains product information from previous interactions, and no cross-batch parameter mixing occurs.
- Check the interface return result, confirm that the format complies with JSON specifications, and there are no unescaped special characters.
