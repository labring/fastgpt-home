# Equipment Inspection and Maintenance Q&A for Complete Household Appliance Manufacturing: Workflow Orchestration

This configuration is based on FastGPT v4.17.0, and adapts to workflow orchestration requirements for equipment inspection and maintenance Q&A in complete household appliance manufacturing.

## What data looks like for this category
Data related to equipment inspection and maintenance Q&A for complete household appliance manufacturing mainly comes from ERP/MES systems, component batch ledgers, tightening and refrigerant charging equipment logs, safety compliance testers, performance laboratory test reports, and after-sales fault repair records. Daily supporting documents include configured BOMs, assembly work instructions, refrigerant charging records, electrical safety test reports, performance spot check reports, and repair ledgers. Data update frequencies cover single-product level, team level, and spot check plan level. Each document corresponds to exclusive parameters for a specific production batch or single finished product.

## What constraints these characteristics impose on workflow orchestration
Multi-batch mixed-line assembly, multi-dimensional process data correlation, and high-risk error consequences for this category impose clear constraints on workflow orchestration. Exclusive data for a single product must be passed via `variables` to avoid cross-batch parameter confusion. Real-time reading of multiple data sources must adapt to different update rhythms to prevent incorrect node execution order. Associated queries for safety compliance and after-sales data require workflows to support cross-system data linkage. In batch mixed-line production scenarios, the number of parallel execution instances of a single workflow must be limited to avoid server resource overload.

## Three Common Misconfigurations
- Exporting an individual plugin in a workflow prompts a permission denied error. The cause is failure to configure the plugin export permission scope, and the setting to only open access to designated workflow groups does not take effect.
- Database connection plugin execution takes too long. The cause is failure to set a reasonable timeout threshold, and failure to adjust node execution order via `nodeId`, leading to repeated reading of process data for the same batch.
- The classify module cannot select a model during the editing phase, but works normally after publication. The cause is failure to bind the global variable for the corresponding model during the editing phase, and the application-level model configuration is automatically synchronized during publication.

## How to Confirm Correct Configuration
- Trigger a test workflow, check whether `variables` correctly transfer the preset single product BOM number and batch number.
- Run the database connection node, confirm that the time taken to read safety compliance test reports meets the preset threshold.
- Attempt to export the process document plugin in the workflow, confirm that only authorized users can perform this operation.
- After publishing the workflow, input product parameters of different models, confirm that the classify module triggers the corresponding maintenance knowledge base logic normally.
