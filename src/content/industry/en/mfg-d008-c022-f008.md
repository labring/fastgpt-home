# Equipment Inspection and Maintenance Q&A for Complete Household Appliance Manufacturing: Document Parsing and Chunking

## What data for this category looks like
Data related to equipment inspection and maintenance for complete household appliance manufacturing comes from ERP/MES systems, component batch ledgers, tightening and refrigerant charging equipment logs, electrical safety tester data, performance lab sampling reports, and after-sales repair fault records.
Document types include configuration BOMs, assembly work instructions, refrigerant charging records, electrical safety test reports, performance sampling reports, and repair work orders.
Data updates follow single-product, shift-output, or monthly/quarterly sampling schedules.
Document fields include material codes, tightening torque values, charging pressure, test voltage, fault codes, repair man-hours, and some documents include unit and batch identifiers.

## Constraints on document parsing and chunking from these characteristics
The unique data traits of complete household appliance manufacturing create clear constraints for the document parsing and chunking process.
Assembly work instructions for mixed-model production have similar titles and parameters. Chunking must retain identifiers like product model and batch number to avoid mixing documents.
Safety compliance test reports and repair records have strongly linked fields. Parsing must keep key metadata such as test voltage and fault codes to enable accurate subsequent Q&A linking.
Single-product level data updates occur frequently. This requires support for incremental parsing to avoid duplicate processing.
Batch documents have wide variation in page count. Parsing must adapt to parsing duration and memory usage for different file sizes.
Different document types have distinct structural differences. Targeted parsing rules must be configured to retain core business fields.

## Configuration settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | The length of single-segment business content for assembly work instructions and repair records falls within this range, avoiding splitting critical parameters and steps |
| `customPdfParse` | Enabled | Adapts to exclusive document formats for household appliance manufacturing, retaining business-specific fields such as BOM material codes and charging pressure |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Covers parsing duration for hundreds-page safety compliance test reports, preventing interruptions during large-file parsing |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Supports batch uploads of monthly batch documents and entire factory equipment logs |
| `chunkSplitter` | Split by title + paragraph | Matches the structured title hierarchy of assembly work instructions and sampling reports, avoiding splitting across steps |
| `chunkSettingMode` | Group by associated fields | Retains metadata such as batch numbers and product models, ensuring accurate matching of associated documents during recall |

## Three common configuration errors
- Calling the custom PDF parsing feature to process documents over 200 pages results in errors, while parsing for documents with tens of pages works normally. The cause is failure to adjust the `PARSE_FILE_TIMEOUT_SECONDS` parameter. Parsing duration for large files exceeds the default threshold and is interrupted.
- Calling the parsing interface returns the error "Cannot read properties of undefined" when deploying pdf-marker 4.9.0 locally. The cause is failure to configure document field mapping rules exclusive to household appliance manufacturing. The parsing engine cannot recognize exclusive fields such as BOM material codes, leading to exceptions.
- Recall results include a large number of duplicate documents, and the number of recalled files does not meet expectations. The cause is failure to enable `chunkSettingMode` to group by associated fields. This causes documents from the same product model to be split and recalled repeatedly.

## How to verify correct configuration
- Upload a 150-page electrical safety test report, confirm that the parsed chunks retain core fields such as test voltage, batch number, and product model.
- Adjust the `chunkSize` parameter to 1000 characters, upload an assembly work instruction, confirm that the chunked text does not split critical tightening steps and parameter values.
- Upload a single 1000 MB batch document package, confirm that the upload and parsing process has no timeout errors.
- Enter common after-sales fault codes to test the recall function, confirm that the recall results include corresponding repair records and assembly work instructions.

The values provided are common starting points and should be measured against the reader's own samples.
