# Equipment Inspection and Maintenance Q&A for Complete Household Appliance Manufacturing: Knowledge Base Retrieval and Recall

## What Data Looks Like for This Category
Daily documents for this category include configuration BOMs, assembly work instructions, refrigerant charging records, electrical safety test reports, performance sampling inspection reports, and rework records.
Data sources include ERP and MES systems, component batch data, tightening and charging equipment logs, safety compliance tester and performance laboratory test data, and after-sales fault records.
Data updates follow per-unit equipment, shift-level operations, and sampling inspection schedules.
Document fields include material codes, work stations, test parameters, fault codes, and other fields. Some documents include units of measurement, such as kilograms for refrigerant charging volumes.

## Constraints Imposed on Knowledge Base Retrieval and Recall
The mixed-line assembly of multiple models for this category requires retrieval to accurately match equipment models and station scenarios. This prevents cross-line misassembly.
Frequently updated per-unit and shift-level data requires retrieval to support real-time synchronization of the latest charging records and rework data.
Multiple document types coexist, including structured BOMs and test reports as well as unstructured work instructions. This requires adapting to different recall rules.
Safety compliance-related documents have risk attributes. Retrieval must prioritize recalling high-confidence compliant data to prevent risks such as electric leakage and refrigerant leakage.
Association between after-sales fault data and production data requires retrieval to recall associated records across data sources. This supports comprehensive anomaly judgment.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Complete household appliance manufacturing documents contain a large number of model parameters and process details, requiring filtering of low-match irrelevant documents to avoid interference from cross-line retrieval |
| `limit` | `Top 6–8 entries` | Equipment inspection and maintenance for a single unit involves multi-process documents. An appropriate number of recalled entries can cover the entire process of assembly, testing, and rework while controlling context length |
| `searchMode` | `mixedRecall` | Balances keyword matching for structured BOMs and test parameters with semantic search for unstructured work instructions, adapting to multiple document types |
| `usingReRank` | Enabled | Multiple model documents often produce results that are semantically similar but do not match the scenario. Reranking improves the ranking priority of highly relevant documents, meeting the precision requirements of mixed-line production |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands keywords related to inspection and maintenance based on user queries, such as supplementing fault codes and station numbers, to match structured data in production systems |
| `collectionIds` | Bind production-related dataset IDs | Only recall exclusive documents such as BOMs, work instructions, and test reports for this category, excluding irrelevant knowledge base content to avoid retrieval interference |

## Three Common Configuration Errors
- Phenomenon: Knowledge base retrieval returns empty results or missing fields. Cause: The `collectionIds` for the corresponding category are not bound. The retrieval scope covers irrelevant datasets, making it impossible to match exclusive documents for complete household appliance manufacturing.
- Phenomenon: Retrieval results include equipment documents from other categories. Cause: A reasonable `similarity` threshold is not set, or `usingReRank` is not enabled. Low-relevance similar documents are recalled first, creating a risk of cross-line misassembly.
- Phenomenon: Structured BOM or test report data cannot be recalled. Cause: `datasetSearchUsingExtensionQuery` is not enabled, or `searchMode` is not configured for hybrid retrieval mode. Pure semantic search alone cannot match structured fields.

## How to Verify Configuration Correctness
- Execute a query for inspection of a single household appliance unit. Check whether returned results include the BOM and assembly work instructions for the corresponding model. This confirms `collectionIds` are bound correctly.
- Adjust the `similarity` parameter. Verify whether the match degree of returned results meets the precision requirements of the production scenario. This confirms the threshold setting is reasonable.
- Upload a test refrigerant charging record file. Execute a relevant query. Verify whether structured field content can be recalled. This confirms the `searchMode` and `datasetSearchUsingExtensionQuery` configurations are effective.
- Compare retrieval result rankings after enabling `usingReRank`. Confirm that the ranking priority of highly relevant documents has been improved.

The values provided are common starting points and should be measured against the reader's own samples.
