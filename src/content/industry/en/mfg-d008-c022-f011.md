# Equipment Inspection and Repair Q&A for Complete Household Appliance Manufacturing: Forms and Interactions

## What this category of data looks like
Data for this category comes from ERP and MES systems for complete household appliance manufacturing, as well as tightening equipment, refrigerant charging equipment, safety performance testers, performance laboratory equipment, and after-sales fault data. Daily documents include configuration BOM, assembly work instructions, refrigerant charging records, electrical safety test reports, performance sampling inspection reports, and rework records. Data updates follow per single product, per shift operation, or per sampling plan, covering component batches, process parameters, test results, and after-sales abnormal information.

## What constraints these characteristics impose on forms and interactions
High-frequency update data for single products requires form interactions to support real-time association of component batches and process parameters, to prevent incorrect assembly or mismatched parameters. Mixed-line production of multiple models requires form interaction components to support dynamic matching of the current production line model, adapting to differences in inspection items for different products. Requirements covering multiple document types including safety performance tests, performance inspections, and after-sales rework require forms to call multi-source heterogeneous data, ensuring the accuracy of Q&A content. The need to link rework records with sampling data requires the interaction link to support cross-document field linkage, helping maintenance personnel quickly locate abnormal causes. Product attributes directly facing consumers require that abnormality judgments output by the form conform to general consumer-side cognition, avoiding excessive stacking of professional terms.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `formInput` | Enable attachment upload function, limit single file ≤100 MB, support batch upload of ≤5 files, compatible with JPG/PNG formats | Adapt to on-site photo and test record collection needs in home appliance inspection and maintenance scenarios, comply with FastGPT v4.17.0 component configuration rules |
| `userSelect` | Bind ERP/MES production line model and component batch data sources, set option update frequency to once per shift | Match the model switching rhythm of mixed-line production, ensure interaction options match the current production line, prevent incorrect assembly |
| Voice input support | Enable Chinese Mandarin recognition function, set response timeout to 30 seconds | Adapt to scenarios where on-site maintenance personnel cannot manually input easily, improve interaction efficiency |
| HTTP request trigger rules | Bind form submission event as trigger, set timeout threshold to 600 seconds | Ensure Q&A parsing completes after waiting for equipment test data to return, adapt to the process detection cycle of home appliance manufacturing |
| Dynamic option update | Trigger update by production line station, set update delay ≤2 seconds | Meet the need for quickly switching inspection items during mixed-line production, reduce waiting time |

## Three common misconfigurations
- The symptom is that the upload file button does not appear in the chat interface input box. The cause is that the attachment upload configuration for the `formInput` component is not enabled, and the photo collection requirements of the inspection scenario are not met.
- The symptom is that options in the user selection module cannot be dynamically adjusted based on the current production line model. The cause is that `userSelect` is not bound to the real-time updated production line model data source, and the option update frequency does not match the per-shift production line switching rhythm.
- The symptom is that when calling a Python script via an HTTP request, the uploaded image is not parsed correctly, and the interface returns empty values or format errors. The cause is that the image binary data is not correctly included in the request, and the parameter mapping rules between form fields and the script interface are not configured.

## How to verify correct configuration
- Open the chat interface input box, confirm that the attachment upload button is present. Try uploading a JPG format test photo, verify that the upload process completes normally without error prompts.
- Switch the simulated production line model, check whether the options in the `userSelect` module update synchronously, verify that the dynamic binding logic takes effect.
- Initiate a voice input test, confirm that the corresponding text content is generated within 30 seconds, verify that the speech-to-text function operates normally.
- Configure a simulated HTTP request, upload a test image and call the preset script, confirm that the interface returns the parsed text result, verify that the data flow is normal.
