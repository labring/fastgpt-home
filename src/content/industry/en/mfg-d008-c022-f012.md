# Equipment Inspection and Maintenance Q&A for Complete Household Appliance Manufacturing: Deployment and Upgrade

## What data for this category looks like
This category's data comes from ERP/MES systems, component batch ledgers, tightening and filling device logs, safety compliance testers, performance laboratory data, and after-sales fault records. Daily documents include configuration BOMs, assembly work instructions, refrigerant filling records, electrical safety test reports, performance sampling inspection reports, and rework records. Data updates are performed per single product, per shift, or per sampling plan. Document fields include component batch numbers, test parameter values, rework reasons, and similar items. No unsubstantiated statistical values are used.

## What constraints these characteristics impose on the deployment and upgrade phase
The data sources for this category are scattered, including device logs, system ledgers, and after-sales records. During deployment, permission configuration and format adaptation rules for multi-source data access must be set up. Data update frequencies cover per single product, per shift, and per sampling plan. During upgrade, flexible triggering of incremental updates must be supported to avoid excessive resource usage from full synchronization. Document types include process files, test reports, and rework records. During deployment, parsing templates for multiple document types must be preconfigured to ensure accuracy of field extraction. Additionally, the mixed-line assembly business scenario requires the knowledge base to support precise recall by model. Corresponding classification indexes must be configured before deployment.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:port/database?authSource=admin` | Adapts to storage requirements for multiple document sources, supports large-capacity process and test data |
| `REDIS_URL` | `redis://:password@host:port/0` | Caches frequently accessed device logs and after-sales data to reduce database load |
| `DB_MAX_LINK` | `20–30 connections` | Adapts to multi-shift concurrent device data write requests, avoids connection pool exhaustion |
| `STORAGE_S3_ENDPOINT` | Configured according to the enterprise's internal object storage address | Stores large-volume documents such as batch safety compliance test reports and rework records |
| Image index model configuration | Enable CLIP series models | Adapts to visual content such as device images and assembly diagrams in documents, improves recall accuracy for inspection-related Q&A |
| Incremental update trigger configuration | Triggered at the end of each shift or per sampling plan | Matches the data update frequency of this category, reduces unnecessary synchronization operations |

## Three common mistakes
- Phenomenon: After deploying FastGPT v4.17.0 locally, when creating a new knowledge base and uploading documents, no image index model option appears. Cause: The visual model-related switch is not enabled in the configuration file, or the used version does not include local deployment support for this function.
- Phenomenon: After Docker deployment is complete, accessing the configured `FE_DOMAIN` address returns no response. Cause: Port mapping is not correctly configured, or the `REDIS_URL` and `MONGODB_URI` parameters are filled incorrectly, causing service startup failure.
- Phenomenon: A version update prompt pops up every time a new conversation is opened. Cause: The version update prompt switch is not turned off in the configuration file, or the `FE_DOMAIN` parameter is not configured as the actual access domain name, causing the prompt logic to malfunction.

## How to confirm the configuration is correct
- Run a connectivity test for `MONGODB_URI` to confirm that stored document data can be read normally. The threshold is calibrated according to the actual number of accessed documents.
- Upload an assembly work instruction that includes device images, check whether an image index is generated, and verify that the image index model configuration takes effect.
- Trigger an incremental update task to confirm that only documents within the specified time range are updated, and no full synchronization is triggered.
- Access the configured `FE_DOMAIN` address to confirm that no version update prompt pop-up appears, and verify that the prompt switch configuration is correct.
