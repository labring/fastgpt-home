# Equipment Inspection and Maintenance Q&A for Industrial Instrument Manufacturing and Calibration: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data for this category comes from flow, pressure, temperature, and analytical instrument manufacturers, as well as metrology laboratories. Daily documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version logs. Data sources include design documents, standard instrument and environmental monitoring data, calibration software, laboratory information systems, and customer range requirements. Update frequency is after each calibration for every individual device. Document structure is split by calibration workflow, including fields such as metrological traceability chains, error calculation values, and range parameters. Units are mostly international standard units, such as pascals, degrees Celsius, and percentage error.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering
This category’s calibration records are core deliverables and updated per single device per calibration. Multi-turn dialogue must bind unique identifiers such as device serial numbers and calibration batches to avoid context confusion. Documents include content with traceability requirements such as error curves and metrology certificates. Prompts must explicitly require referencing calibrated standard instrument data and traceability chain information, and must not deviate from metrological specifications. Data update frequency is high, so dialogue context must limit valid duration to prevent calling expired calibration records. Equipment inspection and maintenance Q&A must link to steps from assembly and commissioning sheets. Prompts must distinguish retrieval priorities for inspection items and maintenance steps.

| ---- | ---- | ---- |
| Conversation history call parameter | Call the first 8 rounds of content from `messages`, calibrated based on actual testing | Data for this category updates frequently. Calling a limited number of conversation history rounds avoids loading expired calibration records |
| Context binding variable | Introduce device serial number and calibration batch fields from `variables` | Data for this category updates per single device calibration. Binding unique identifiers avoids confusion between calibration records of different devices |
| Session association parameter | Bind `chatId` to the current device’s inspection and maintenance workflow | This binds the dialogue session to a specific device, ensuring context consistency for multi-turn dialogue |

| Referenced file display switch | Disable | Equipment inspection and maintenance Q&A must focus on current questions. Displaying redundant referenced files disrupts dialogue readability |
| Maximum dialogue turns | Keep within 20 rounds, calibrated based on actual testing | Questions for this category mostly revolve around a single device’s single calibration or maintenance. Context with excessive turns easily deviates from the current question |

## Three Common Mistakes
- Symptom: After enabling the image recognition function, uploading photos of instrument readings or screenshots of error curves results in the system replying that it cannot recognize the image content. Cause: The prompt does not explicitly require the model to recognize metrological values and annotations in the image, or the image upload node parameters are not configured correctly.
- Symptom: The dialogue reply automatically attaches a list of referenced calibration records and error curve files, and cannot be hidden. Cause: The referenced file display switch for dialogue replies is not disabled, or the default setting for reference display is accidentally retained during configuration.
- Symptom: After multi-turn dialogue exceeds the set number of rounds, the system truncates early device serial number and calibration batch information, making subsequent Q&A unable to associate with the correct calibration record. Cause: The maximum context window or maximum dialogue turns are not set correctly, resulting in valid context being overwritten.

## How to Verify Proper Configuration
- Upload the calibration certificate image for a single device, trigger a dialogue, and check whether the reply recognizes the metrological values and traceability chain information in the image.
- Initiate a multi-turn dialogue that includes a device serial number, and check whether subsequent replies consistently associate with that device’s calibration records.
- Initiate a query that includes referenced files, and check whether the reply does not attach a redundant list of referenced files.
- Initiate a dialogue that exceeds the set number of rounds, and check whether the system retains valid context and does not truncate critical device identification information.

The values provided are common starting points and should be measured against the reader's own samples.
