# Equipment Inspection and Maintenance Q&A for Industrial Instrument Manufacturing and Calibration: Workflow Orchestration

## What this category of data looks like
Typical entities in this category are flow, pressure, temperature, and analytical instrument manufacturers, as well as metrology laboratories. Daily generated documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version records. Data sources cover design documents, standard instruments and environmental monitoring data, calibration software, laboratory information systems, and customer range requirements. Data is updated per device and per calibration event. Documents include fields such as calibration values, error values, traceability numbers, and environmental temperature and humidity, with units corresponding to the statutory metrological requirements of the measured parameters.

## What constraints do these characteristics impose on the "workflow orchestration" link
The characteristic that category data is updated per device and per calibration event requires that the workflow must be precisely bound to the exclusive calibration record of a single device, to avoid cross-device data confusion. There are various types of daily documents that are closely related, so the workflow must support associating multiple types of documents such as assembly and commissioning sheets and calibration procedures as the basis for Q&A. The most time-consuming steps include establishing standard instrument connections, multi-point error calculation, and auditing traceability chains. This requires the workflow to set pre-check nodes to reduce invalid runs. Calibration records for this category are equivalent to critical deliverables. Errors will lead to transfer of measurement deviations, invalid certificates, or failure of metrological audits. Therefore, the workflow must be configured with failure rollback and full-link log recording to ensure that exceptions can be traced.

## How to set the configuration
Before configuring the workflow, ensure that FastGPT v4.17.0 is used to obtain stable workflow orchestration functions.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow variables | Bind the calibration record ID and range of a single device | Match the characteristic that category data is updated per device and per calibration event, to precisely associate single-device business data |
| Trigger node condition | Trigger according to the calibration completion status in `variables` | Ensure the workflow starts only after valid calibration data is generated, to avoid invalid runs |
| Document association rules | Associate three types of documents: assembly and commissioning sheets, calibration procedures, and metrology certificates | Cover all business document types required for daily inspection and maintenance of the category |
| Timeout setting | 600 seconds | Cover typical time-consuming scenarios such as establishing standard instrument connections and multi-point error calculation |
| Failure handling strategy | Trigger log reporting and roll back to the pre-check node | Avoid serious consequences such as failure of metrological audits caused by incorrect data transfer |
| Node identifier binding | Bind the unique identifier of the calibration review node as `nodeId` | Ensure that the workflow accurately points to the review link during jumps, to avoid path errors |

## Three common mistakes
- Phenomenon: Loading failure occurs when entering the editing interface after creating a workflow template. Cause: The category-specific calibration document data source is not correctly bound, causing the system to fail to load the corresponding metadata.
- Phenomenon: An error occurs when opening the workflow after local deployment, with the prompt Cannot read properties of undefined (reading 'incl'. Cause: The required instrument model field is missing from the `variables` configuration, so the system cannot identify the associated calibration record.
- Phenomenon: An input error occurs when executing a code running node after referencing a custom plugin. Cause: The plugin input parameters are not configured according to the field format of the category data, and the field structure of the error curve and metrology certificate is not matched.

## How to confirm the configuration is complete
- Trigger the workflow, then check whether it starts running only after the calibration record is generated.
- View the workflow log to confirm that all associated document types are correctly loaded.
- Simulate an exception scenario to verify whether the failure handling node normally triggers log reporting and rollback.
- Check the `nodeId` configuration to confirm that the jump path of the review link matches the business process.
