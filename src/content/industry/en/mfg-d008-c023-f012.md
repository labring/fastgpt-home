# Equipment Inspection and Maintenance Q&A for Industrial Instrument Manufacturing and Calibration: Deployment and Upgrade

## What this category’s data looks like
Core data for the industrial instrument manufacturing and calibration category includes assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version logs.
Data sources include design documents, standard instruments and environmental monitoring data, calibration software, laboratory information systems, and customer range requirements.
Data is updated once per calibration for each device.
Individual data entries include fields such as instrument model, calibration date, standard instrument ID, error value, range, traceability identifier, and more.
Units cover standard physical quantity units including pressure, temperature, and flow.

## Constraints on deployment and upgrade workflows
Data for this category must be retained long-term to meet metrology traceability requirements. Highly reliable persistent storage must be configured during deployment.
Multiple versions of calibration documents for a single device must be individually associated. The deployment process must support document grouping by device ID.
Data originates from multiple internal systems. The deployment process must support importing documents in different formats.
Failed metrology audits directly impact customer production. The upgrade process must retain historical configuration backups to avoid data validation errors after changes.

## How to set configurations
The following configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | Point to a dedicated sharded cluster storing calibration records and metrology certificates | This category’s data requires long-term traceable storage, and sharded clusters support concurrent read/write operations for multiple versions of documents per device |
| `REDIS_URL` | Configure as an intranet high-availability cache instance, set timeout to 300 seconds | Used to cache query results for calibration procedures and error curves, reducing database load and adapting to high-frequency inspection and maintenance Q&A requests |
| `DB_MAX_LINK` | Set to 20–30 | The read/write peak for this category’s data aligns with calibration batch submission windows; this range prevents connection exhaustion from affecting metrology certificate generation |
| `FE_DOMAIN` | Fill in the intranet domain name of the laboratory or factory | Used to generate preview links for calibration documents, ensuring intranet users can directly access traceable files |
| `STORAGE_S3_ENDPOINT` | Point to the access address of the enterprise’s internal object storage | Used to store large files such as original calibration records and error curves, complying with compliance requirements that data does not leave the facility |

## Three common configuration mistakes
- Phenomenon: The output of HTTP request orchestration is not displayed in the chat interface. Cause: `FILE_TOKEN_KEY` was not configured to generate access tokens, so stored calibration documents cannot be returned to the chat context via the API.
- Phenomenon: A database connection error is displayed during Docker packaged deployment. Cause: `PG_URL` or `MONGODB_URI` was not modified to point to the enterprise intranet database instance; the default configuration points to a test database and cannot adapt to the production environment.
- Phenomenon: Model calls fail after mapping the intranet to the public network. Cause: `FE_DOMAIN` was not configured as the public network mapped address, and port permissions for the storage service were not opened, so the model cannot obtain context information for calibration data.

## How to confirm configurations are correctly applied
- Log in to the FastGPT backend system settings page, check the database connection status, and confirm that the instances pointed to by `MONGODB_URI` and `PG_URL` can be connected normally.
- Upload a calibration procedure document, create an inspection and maintenance Q&A application for the corresponding device, initiate a test request, and verify that the chat interface returns document content normally.
- Access the configured `FE_DOMAIN` from both the intranet and public network, confirm that domain resolution and port permissions are functioning correctly, and that calibration document previews load properly.
- Submit batch calibration records, check the system monitoring panel, confirm that database connection counts fall within the range set by `DB_MAX_LINK`, and that no connection overflow errors occur.
