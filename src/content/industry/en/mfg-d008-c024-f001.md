# Equipment Inspection and Maintenance Q&A for Process Changes and Engineering Changes: HTTP Interfaces and External Systems

## What data for this category looks like
The core data for this category is generated by a manufacturing enterprise’s change management team, with participation from R&D, process, quality, production, and procurement teams. Daily documents include ECN/ECR, change assessment reports, drawings and BOM version files, process validation reports, transition plans, inventory disposal documents, and customer approval documents. Data sources cover PLM, ERP, MES, supplier materials, validation test results, and customer-specific requirements. Updates are triggered irregularly, with one update per change. Data fields include change number, version identifier, impact scope, effective time, and more. There is no unified fixed unit system; adaptation is required based on specific business documents.

## What constraints do these characteristics impose on HTTP interfaces and external systems
The data sources for this category are scattered, and updates follow no fixed cycle. HTTP interfaces must support compatibility with multiple system data formats, and incremental synchronization to avoid redundant data transmission. Daily document fields are complex, and core identifiers are inconsistent. Interfaces must support pulling specified fields to retrieve only core information required for change management. Synchronization errors in changes can cause serious production issues. Interfaces must include authentication, retry, and data validation mechanisms to ensure data transmission accuracy and stability. Additionally, changes involve cross-department collaboration, so interfaces must support cross-system field mapping to adapt to differences in field naming across business systems.

## How to configure settings
This guidance is written for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Interface authentication configuration | Use the `Authorization` header with a Bearer token, token validity period of 1 hour | Matches the permission control requirements for change data, prevents unauthorized access |
| Request variable mapping | Bind three core fields: ECN number, BOM version number, change effective date | Corresponds to the core identifier fields of daily documents, ensures accurate data association |
| Response data filtering | Only return ECN status, change impact scope, validation report link | Reduces redundant data transmission, adapts to core query scenarios for change management |
| Retry strategy configuration | Retry 3 times after failure, 10-second interval between each attempt | Addresses temporary unavailability of external systems, ensures stability of data synchronization |
| Timeout setting | Single request timeout of 60 seconds | Adapts to the time consumption requirements of cross-system data pulling, avoids long-term blocking |
| Data validation switch | Enable field integrity validation | Identifies missing data in advance, reduces the risk of change synchronization errors |

## Three common configuration errors
- The `responseData` returned after calling the interface lacks an initial opening field. Cause: No opening field mapping was configured in the request’s `variables`, so corresponding business data was not extracted.
- After creating a new change management interface configuration, the authentication configuration of existing same-type interfaces is overwritten. Cause: No independent authentication credential was assigned to each application, leading to credential conflict and overwriting.
- The interface request returns a 504 timeout status code. Cause: No reasonable timeout threshold was set, and the time requirements for cross-system data pulling were not met.

## How to verify a successful configuration
- Initiate a simulated request, check that the `Authorization` header is correctly carried, and confirm the returned status code is 200
- Verify that the request’s `variables` parameter correctly maps core business fields, and confirm the response includes expected data such as ECN number and BOM version number
- Simulate a temporary unavailability scenario for an external system, check that the interface triggers the retry mechanism and eventually recovers normally
- Check that the response data filtering configuration only returns pre-set core fields, and confirm no redundant data is returned
