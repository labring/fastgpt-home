# Equipment Inspection and Maintenance Q&A for Process Changes and Engineering Changes: Forms and Interactions

## What this category of data looks like
This data is generated by manufacturing enterprise change management teams. It covers ECN/ECR forms, change assessment reports, drawing and BOM version records, process validation reports, production switch plans, inventory disposal documents, and customer approval documents. Data sources include PLM, ERP, and MES systems, supplier materials, validation test results, and customer-specific requirements. Updates are triggered irregularly for each change. Core data must link version information and approval status across multiple systems.

## Constraints for forms and interactions from these data characteristics
This category of data creates multiple constraints for form interactions. Cross-system data sources require forms to support linked retrieval of external documents and version information, to avoid manual input errors. Irregular update cycles require forms to dynamically load the latest ECN/ECR, drawing version, and other data, to prevent use of expired versions. Multi-role change workflows require the `userSelect` component in forms to support visible options configured by role, while validating required approval document and switch point fields. Additionally, complex chain impact identification needs require forms to pre-configure linked fields to simplify information entry.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `formInput` maximum character count | 800–1200 characters | Adapts to long text entry needs such as change descriptions and process adjustment notes in ECN/ECR forms |
| `userSelect` option loading method | Dynamically pull based on change type | Matches differences in approval roles and linked document types across different process change scenarios |
| Input box upload button | Enabled | Supports uploading attachments such as process validation reports and customer approval documents |
| Context window size | 1500–2000 tokens | Adapts to Q&A interaction needs for cross-system linked data |
| Dynamic option update interval | Calibrated based on actual testing | Adapts to version update cycles of PLM and ERP systems, avoiding loading expired data |

## Three common configuration mistakes
- Symptom: Linked PLM knowledge base documents cannot be called in real time during conversation interactions. Cause: The `userSelect` component is not configured to bind dynamic retrieval logic for external knowledge bases, and only a fixed preset option list is used.
- Symptom: The file upload button does not appear in the chat input box. Cause: The form's attachment upload configuration is not enabled, or the allowed file types and size thresholds are incorrectly restricted.
- Symptom: Options in the user selection module cannot be dynamically adjusted based on change type. Cause: The `userSelect` component is not bound to the current change's process classification, and option updates for the corresponding scenario are not triggered.

## How to confirm correct configuration
- Initiate a test Q&A for a process change, verify that the input box can normally upload process validation report-style attachments.
- Select different change types, confirm that the approval role and linked document options loaded by the `userSelect` component change accordingly.
- Enter a long text change description, verify that the character limit of the `formInput` component matches the preset 800–1200 character range.
- Wait for the PLM system to update a drawing version, confirm that the drawing version loaded by the form is the latest version.

The values provided are common starting points and should be measured against the reader's own samples.
