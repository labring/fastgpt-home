# Equipment Inspection and Maintenance Q&A for Non-Ferrous Metal Smelting and Electrolysis: Tool Calling and Plugins

## What this category of data looks like
Data for this category comes primarily from smelting, electrolysis, laboratory, and dispatch departments of copper, aluminum, lead-zinc, and other smelting enterprises. Daily documents include batching lists, smelting records, electrolytic cell status records, laboratory reports, anode and cathode quality records, and environmental protection ledgers.
Data sources cover concentrate and auxiliary material analysis, DCS systems, cell voltage and current monitoring, laboratory testing, and energy and environmental monitoring systems. Data updates occur in real time after each batch of raw materials, each furnace, or each cell operation is completed.
Data fields include raw material composition, cell status parameters, laboratory indicators, energy consumption, and emission data. Units include amperes, volts, kilograms, cubic meters, and other standard units.

## What constraints do these data characteristics impose on tool calling and plugin configuration?
This category’s data characteristics create multiple constraints for tool calling and plugin setup.
First, data sources are scattered and update rhythms vary. Plugins must support connections to multiple interfaces including DCS systems, laboratory systems, and environmental monitoring systems. They must also adapt to three data pull logic update frequencies: real-time, per furnace, and per batch of raw materials.
Second, daily document fields are complex and use fixed formats. Plugins must accurately match the field definitions of documents such as batching lists and electrolytic cell status records to avoid field misalignment during parsing.
Third, core business links depend on real-time cell status and smelting parameters. Tool calling context must prioritize loading the latest monitoring data to ensure Q&A results align with current production status.
Fourth, tool calling abnormalities may trigger serious production issues. Clear failure retry and exception alert rules must be configured.

## Three Common Misconfigurations
- Phenomenon: Tool call returns empty results or missing fields. Cause: Field mapping rules for this category of documents are not configured correctly, causing the plugin to fail to match exclusive fields for batching lists and electrolytic cell status records.
- Phenomenon: Parameter errors occur when calling external model APIs. Cause: Custom model access parameters are not configured in the format required by FastGPT, and correct interface address and authentication method are not specified.
- Phenomenon: Streamed return results cannot include both knowledge base call content and tool call results. Cause: The execution order of tool calls and knowledge base recall is not configured correctly, leading to incorrect splicing of the two types of data.

## How to Verify Correct Configuration
- Initiate a test query that includes smelting cell status parameters, and confirm that the tool call triggers the corresponding plugin and returns matching cell status data.
- After configuring custom model access, initiate a test call to confirm that the interface return result conforms to the expected format.
- Enable streamed return and knowledge base recall, and confirm that the returned result includes both knowledge base content and tool call results.
- Simulate a tool call failure scenario, and confirm that the system triggers preset retry and alert rules.
