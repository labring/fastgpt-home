# Incoming Material Inspection and Supplier Quality Equipment Inspection and Maintenance Q&A: Forms and Interactions

## What this category of data looks like
The data for this category comes from purchase orders, drawing specifications, supplier quality certificates, inspection equipment, historical quality data, and supplier portals. Daily processed documents include inspection specifications, sampling plans, incoming material reports, supplier audit reports, exception contact sheets, 8D reports, and concession acceptance approval forms. New records are generated with each incoming material batch. Overall supplier evaluations are completed monthly or quarterly. Special audits are carried out irregularly. Data fields include incoming material batch number, sampling quantity, nonconforming item description, supplier code, inspection date, and so on. No additional custom statistical units are used.

## What constraints these characteristics impose on the "forms and interactions" link
Since data updates with each incoming material batch, forms must support quick context switching by batch. This avoids mixing cross-batch data. Multiple layers of associated information including suppliers, batches, and nonconforming items are involved. Interactions must support hierarchical selection to reduce redundant user input. Daily documents include multiple standardized templates. Forms must adapt to field validation rules for different documents. For example, concession acceptance approval must link to historical audit records. Data sources include external supplier portal information. Interactions must support permission verification for external data pulling. This prevents unauthorized access. Exception contact sheets and 8D reports must link to historical quality data. Forms must provide quick access to existing records.

## Three common configuration mistakes
- Symptom: When using multi-level user selection interactions, lower-level options cannot link to the supplier code selected in the upper level. Cause: Hierarchical association rules for `userSelect` were not configured, resulting in no data linkage between options.
- Symptom: The file upload node cannot automatically adapt to all upload formats, and a format not supported prompt appears when connecting to MCP. Cause: File upload formats were not set to all enabled by default, only some commonly used formats were checked.
- Symptom: After configuring external model connection information, an empty error is reported when entering the key. Cause: The complete API address was not correctly filled in the configuration, only the key was entered, resulting in an incorrect interface request path.

## How to confirm correct configuration
- Create a new incoming material inspection form. Select the corresponding supplier code. Verify that lower-level options automatically load the supplier's historical nonconforming items.
- Upload files of different formats. Confirm there are no format restriction prompts. Verify submissions can be completed normally.
- Fill in form fields. Verify real-time validation identifies missing required fields and provides prompts.
- Initiate a model connection test request. Confirm there are no empty errors. Verify the configured model can be called normally.
