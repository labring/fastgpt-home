# Equipment Inspection and Maintenance Q&A for Mold Design and Manufacturing: Workflow Orchestration

## What data for this category looks like
Daily documents for this category include mold design task sheets, DFM reports, part drawings, machining process cards, trial mold reports, mold modification notices, and mold history records.
Data comes from customer product models, mold flow or forming simulation data, CAD/CAM data, machining and measurement data, and trial mold samples.
Updates are managed per individual project, and synchronized after each trial mold or mold modification.
Document fields include mold number, part specification, machining parameters, defect records, mold modification times, and more. There are no unified fixed units; adjustments are made based on the project's document type.

## What constraints these characteristics impose on workflow orchestration
Multi-source heterogeneous data sources require workflows to support cross-format data mapping. This prevents transfer failures caused by format differences between CAD models, simulation data, and trial mold records.
Project-based updates require workflows to isolate `variables` using project IDs. This stops cross-project data contamination.
Frequent trial mold and modification updates require workflows to support dynamic trigger nodes. The inspection and maintenance Q&A process starts automatically when a mold modification notice is uploaded.
The flexibility of document fields requires workflow node configurations to support custom fields. Hardcoded fixed field rules are not allowed.
Equipment inspection and maintenance Q&A must link to historical data for the same mold. This requires workflows to support binding historical nodes with a specified `nodeId`.

## How to set configurations
| Configuration item | Recommended setting | Rationale |
| --- | --- | --- |
| `variables` | Custom field mapping per project, including mold number, trial mold defects, and mold modification records. Suggested range is 10-15 custom fields, calibrated via actual measurement | Document fields for this category adjust per project, requiring flexible adaptation to multi-source heterogeneous mold-related data |
| `nodeId` | `nodeId` of the linked historical mold history record node, fixed as the historical data node ID of the corresponding project | Equipment inspection and maintenance Q&A needs to link to historical defects and mold modification records of the same mold, ensuring accurate Q&A context |
| Loop termination condition | Terminate the loop when the "Trial Mold Qualified" field value is "Yes", or set the maximum loop count to 3 | Mold modification usually meets standards after up to 3 iterations, avoiding invalid loops that consume resources |
| Variable reference format | Use `{{}}` format to reference custom `variables` fields, replacing the old path-based variable retrieval method | Fixes variable compatibility issues, compatible with FastGPT v4.17.0 and above |
| Single knowledge base recall limit | Top 8 entries | Mold-related document data volume is moderate; excessive recall increases context load |

## Three common mistakes
- Phenomenon: The loop body does not terminate automatically after reaching the set number of times, or does not exit the loop per the specified condition. Cause: The loop termination condition is not configured correctly, and the judgment logic for the corresponding field is not bound.
- Phenomenon: The knowledge base node returns empty results or missing fields. Cause: Custom fields in `variables` are not mapped correctly, making it impossible to match historical mold-related documents.
- Phenomenon: Format errors occur when using the path-based variable retrieval method, or variables fail to render properly. Cause: The deployed version does not support `{{}}` format references, and the old variable calling rules are still in use.

## How to confirm the configuration is correct
- Trigger a test workflow, and check whether the `variables` field in the workflow log correctly loads the mold-related data of the current project.
- Simulate triggering the loop body, input the specified termination condition, and confirm whether the loop terminates as expected.
- Call the knowledge base node, and verify that the returned documents are related to the current mold's trial mold and modification records.
- Edit the prompt and trigger the Q&A, confirm that variable rendering works normally with no format errors.
