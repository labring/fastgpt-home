# Equipment Check and Repair Q&A for Complete Vehicle Final Assembly: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Business data for complete vehicle final assembly comes from ERP/MES systems, VIN and configuration systems, tightening tools, EOL inspection lines, and quality traceability systems. Daily documents include production orders, VIN lists, assembly work instructions, tightening data, offline inspection reports, rework records, and consistency and release documents.
Data updates occur per vehicle, in real time, or per shift. Core fields include VIN code, station number, torque value, inspection result, and part batch number. Units include newton meters, seconds, piece count, and other standard units.

## What constraints these characteristics impose on knowledge base retrieval and recall
Final assembly lines use VIN as the primary vehicle identifier for mixed-line production. Retrieval must accurately match VIN-related fields to prevent mixing documents from different vehicles. High-frequency real-time updates require the knowledge base to support incremental synchronization, so that the latest tightening data and rework records are accessible during equipment check and repair.
Variations in document structure across types require the retrieval system to adapt chunking rules for different formats, while limiting context length to fit real-time station interactions. The complexity of mixed-line production also requires retrieval results to filter out irrelevant documents from non-current stations, to avoid reducing operational efficiency.

## How to set configurations
The following configurations are based on FastGPT v4.17.0.

| Config Item | Suggested Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Accurately match core business fields including VIN and torque value, filter low-relevance documents during mixed-line production |
| `limit` | Top 8–12 entries | Control the context length returned by retrieval, adapt to the tight interaction rhythm of final assembly stations |
| `searchMode` | `mixedRecall` | Match both exact keywords for VIN and semantically relevant work instruction content, balance accuracy and recall coverage |
| `usingReRank` | Enabled | Perform secondary sorting on recall results, eliminate mixed documents from different stations, and improve the relevance of core results |
| `datasetSearchUsingExtensionQuery` | Enabled | Expand the query scope, supplement auxiliary documents such as part batch and supplier information corresponding to the associated VIN |
| `collectionIds` | Specify exclusive collection IDs for final assembly workshops | Isolate equipment check and repair documents from different workshops, avoid cross-workshop data interfering with retrieval results |

## Three common errors
- 418 error after configuring the knowledge base: An application returns a 418 status code when calling knowledge base retrieval. The cause is incorrect configuration of `collectionIds`, or the knowledge base collection’s access permission is not granted to the corresponding application.
- Unexpected storage or file count limit breach: A prompt appears when uploading documents, stating insufficient storage space or exceeded file count. The cause is merging documents from multiple workshops and stations for final assembly equipment check and repair into a single knowledge base, without splitting collections by business dimension.
- Mixed station documents in retrieval results: A query about tightening check work at a specific station returns rework records from other stations. The cause is a too-low `similarity` threshold, or failure to enable `usingReRank` for result reranking.

## How to confirm correct configuration
- Open the FastGPT application debugging interface, enter a check question that includes a VIN code, and confirm only relevant documents from the current station appear in the retrieval preview.
- Check storage space and file count statistics on the knowledge base management page, and confirm single collection file counts and used space match post-split business expectations.
- Trigger a retrieval request with `usingReRank` enabled, and verify returned result sorting aligns with core business needs.
- Test that a basic unconfigured knowledge base application runs normally, and no 418 error appears after adding the knowledge base configuration.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
