# Equipment Inspection and Maintenance Q&A for Complete Vehicle Final Assembly: Deployment and Upgrade

## What the data for this category looks like
Production data sources for complete vehicle final assembly include ERP/MES systems, VIN and configuration systems, tightening tools, EOL inspection lines, quality traceability systems, and others. Daily generated documents include production orders, VIN lists, assembly work instructions, tightening data, offline inspection reports, rework records, consistency and release documents. Data update cadences include once per vehicle, real-time upload (such as tightening torque data), and shift-level summary (such as daily rework statistics). Core data fields include VIN codes, station numbers, torque values, part batch numbers, inspection results, and others. Full-link traceability per individual vehicle is required.

## What constraints do these characteristics impose during deployment and upgrade
These constraints are derived based on the deployment logic of FastGPT v4.17.0 combined with the production characteristics of complete vehicle final assembly. The mixed-model production mode of this category requires the system to support high-concurrency real-time data processing. Core links such as VIN matching and torque verification are latency-sensitive. Therefore, low-latency intranet links must be prioritized during deployment. Large volumes of structured and unstructured data generated by multi-station collaboration require storage resources to be physically isolated from business systems, to avoid impacting core production processes. The upgrade process must avoid interrupting production cycles. Therefore, a gray release strategy must be adopted, switching station nodes in batches. Historical data traceability must also be retained, to prevent data gaps after the upgrade.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `120–180` | Matches the concurrent inspection requests of hundreds of vehicles per shift in the final assembly workshop, to avoid exhausting the database connection pool |
| `MONGODB_URI` | Points to a dedicated unstructured data cluster | Stores documents such as VIN lists, rework records, and offline inspection reports, and is physically isolated from the business database |
| `REDIS_URL` | Configured as a local intranet cache cluster, with cache expiration time set to `300 seconds` | Caches frequently called assembly work instructions and VIN matching rules, to reduce backend interface latency |
| `FE_DOMAIN` | Bound to the dedicated intranet domain of the final assembly workshop | Restricts access to the production intranet, to prevent unauthorized external access |
| `STORAGE_S3_ENDPOINT` | Points to the workshop-level object storage service | Stores large-volume files such as tightening data and EOL inspection reports, to support batch data upload requirements |
| `ROOT_KEY` | Configured with layered keys by station role | Differentiates operation permissions for different stations, in compliance with on-site production permission control specifications |

## Three common misconfigurations
- Local service startup fails to access the oneAPI interface, with connection failure or 404 error prompts. Cause: `FE_DOMAIN` is not correctly configured as an intranet-accessible domain, or the frontend startup parameters are not bound to the correct backend service address, resulting in abnormal intranet access links.
- After adding a model and configuring its key, index construction fails, and database connection errors appear in the console. Cause: `MONGODB_URI` or `REDIS_URL` is not correctly configured, causing the vector database cache link to interrupt, and failing to complete persistent storage of the model index.
- When multiple stations send inspection requests concurrently, some requests time out or are rejected. Cause: `DB_MAX_LINK` is set too low, and the database connection pool cannot support concurrent write requests, failing to process batch inspection data.

## How to confirm the configuration is properly set
- Access the bound `FE_DOMAIN` from the final assembly workshop intranet environment, confirm that the oneAPI interface loads normally, with no connection timeout or 404 error prompts.
- Upload a test list containing 10 VIN records, confirm that the file is successfully stored in the storage service corresponding to the configured `STORAGE_S3_ENDPOINT`, with no upload failure prompts.
- Initiate 150 concurrent inspection requests, use monitoring tools to confirm that the database connection count does not exceed the `DB_MAX_LINK` setting, with no connection errors or request timeouts.
- Add the specified model and configure its corresponding key, wait 1 minute, confirm that the index construction progress is normal, with no configuration abnormalities or construction failure prompts.
