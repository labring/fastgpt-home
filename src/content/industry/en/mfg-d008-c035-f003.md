# Heat Treatment Equipment Inspection and Maintenance Q&A: Multi-turn Dialogue and Prompt Words

## What the Data for This Category Looks Like
This category of data is sourced from daily production documents and equipment collection data from heat treatment workshops in professional heat treatment plants, automobile component factories, and bearing parts factories. Daily documents include heat treatment process cards, furnace loading diagrams, furnace temperature curves, hardness and metallographic reports, equipment inspection forms, and exception handling sheets. Data sources cover material grades, customer technical requirements, temperature control instruments, furnace temperature uniformity testing equipment, hardness testers, metallographic equipment, and MES systems. Update frequency is per furnace load and per batch. Data fields include furnace temperature range, holding time, furnace loading workpiece position, hardness value, exception type, and more. Units include degrees Celsius, hours, HV/HRC hardness units, and more.

## Constraints Imposed on Multi-turn Dialogue and Prompt Word Workflows by These Data Characteristics
The data for this category updates per furnace load and per batch, and combines real-time equipment collection data and static process documents. Multi-turn dialogue must bind the context of the corresponding furnace load or batch to avoid mixing data across batches. Different business scenarios require calling different documents. The inspection scenario prioritizes equipment inspection forms and furnace temperature curves. The maintenance scenario links process cards and exception handling sheets. Prompt words need preset scenario trigger rules. Mixed calls of real-time data and static documents require the dialogue process to distinguish between immediate queries and historical data retrieval. Multi-round follow-up questions are needed to supplement exception details and reduce misjudgment risk.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Basis for This Approach |
| --- | --- | --- |
| `chatId` | Bind the unique identifier of the current furnace load | Data for this category updates per furnace load. Binding a unique identifier avoids mixing context across batches |
| `messages` | Retain the first 10 rounds of dialogue context. Automatically clear the earliest non-critical rounds when exceeding the limit | Heat treatment processes and exceptions are closely linked. Retaining core dialogue records while controlling context length is necessary |
| `variables` | Preset three types of variables: furnace temperature range, hardness threshold, and exception type | Matches the core business fields of this category, making it easy to dynamically call corresponding documents and data |
| Question Optimization | Calibrate based on actual measurements | Adapts to the colloquial questions of operating personnel, converting non-standard expressions into standard query statements |
| Maximum Context Length | 800–1200 characters | Core data for this category is concentrated. This length can cover key process and exception information |

## Three Common Configuration Mistakes
- Phenomenon: The dialog box accessed via iframe displays an English interface and cannot be switched to Chinese. Cause: The language parameter of the iframe is not configured, and the corresponding Chinese localization configuration is not bound.
- Phenomenon: No results are displayed in the dialog box after the tool call is completed. Results are only shown after re-entering the session. Cause: The context synchronization logic of `messages` is not configured correctly. The tool return result is not written to the message queue of the current session, causing the front end to not render in real time.
- Phenomenon: Preset inspection or maintenance prompt words cannot be dynamically loaded from the knowledge base. Manual input is required for each call. Cause: Prompt words are not configured as callable variables bound by `variables`, and are not linked to the prompt word document category in the knowledge base.

## How to Verify Successful Configuration
- Create a new session for the corresponding furnace load. Check whether the associated data of the furnace load is automatically loaded to confirm that the `chatId` binding logic takes effect.
- Enter a colloquial question, such as "Has the furnace temperature drifted today?" Check whether it is automatically converted to a standard query statement to confirm that the question optimization configuration takes effect.
- Call a tool to query exception handling plans. Check whether the results are displayed in the dialog box in real time to confirm that the context synchronization logic of `messages` is working properly.
- Call the preset inspection prompt words. Check whether the corresponding content is automatically loaded from the knowledge base to confirm that the dynamic loading configuration of `variables` takes effect.

The values provided are common starting points and should be measured against the reader's own samples.
