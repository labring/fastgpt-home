# Heat Treatment Equipment Inspection and Maintenance Q&A: Knowledge Base Retrieval and Recall

## What Data Looks Like for This Category
The service subjects for this category are professional heat treatment plants and heat treatment workshops in automotive and bearing parts factories. Data comes from material grade standards, customer technical requirements, on-site temperature control instruments, furnace temperature uniformity testing equipment, hardness testers and metallographic equipment, and workshop MES systems. Daily documents include heat treatment process cards, charging layout diagrams, real-time furnace temperature curves, batch hardness and metallographic test reports, equipment inspection records, and exception handling work orders. Data is updated per furnace load or batch. Documents contain fields such as temperature parameters, charging positions, test values, inspection time, and some documents include batch numbers and timestamps.

## What Constraints These Characteristics Impose on Knowledge Base Retrieval and Recall
High-frequency updated per-furnace or per-batch data requires the retrieval system to support incremental synchronization, to avoid excessive time spent on full indexing. Multiple types of documents coexist, including text-based process cards, tabular test reports, and curve-based furnace temperature data. This requires retrieval logic adapted to different formats, such as extracting key values from tables and matching curve time intervals. Data is strongly associated with furnace loads and batches, so retrieval must accurately match batch parameters to prevent mixing of cross-batch data. The timeliness requirements for equipment inspection and exception handling require retrieval results to prioritize work orders from recent batches, to support rapid on-site problem troubleshooting.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | Heat treatment data requires matching precise process parameters and equipment status. This range filters low-relevance non-furnace data and avoids recalling irrelevant general process content |
| `limit` | Top 8 entries | The number of relevant documents per furnace load is limited. Recalling too many increases context processing pressure, while recalling too few misses key inspection or exception handling information |
| `usingReRank` | Enabled | When retrieving multiple types of mixed documents, re-ranking prioritizes fragments strongly related to equipment inspection and maintenance issues, correcting correlation biases in initial retrieval results |
| `datasetSearchUsingExtensionQuery` | Enabled | This allows expanding user inspection or maintenance questions into query terms that include process parameters and equipment models, to match more accurate process cards and inspection records |
| `collectionIds` | Bind exclusive heat treatment equipment inspection and maintenance knowledge base collections | This prevents recalling documents from other categories, ensuring the retrieval scope only covers process, inspection, and exception data from the current workshop |

## Three Common Misconfigurations
- Enabling `usingReRank` results in empty retrieval results. Phenomenon: The interface returns no matching fragments, and logs show normal initial retrieval counts but zero results after re-ranking. Causes: The re-ranking threshold is set too high, filtering valid initial retrieval results, or the `similarity` threshold does not match the re-ranking threshold, causing all initial results to be excluded.
- Retrieval results include cross-batch documents. Phenomenon: When querying inspection issues for the current furnace load, furnace temperature curves or process cards from other batches are returned. Causes: `collectionIds` is not properly configured, so the retrieval scope covers knowledge base collections from multiple workshops, and the exclusive dataset for the heat treatment workshop is not bound.
- Retrieval fails to return exception handling work orders. Phenomenon: When querying equipment maintenance issues, the corresponding exception handling work order content is not recalled. Causes: `datasetSearchUsingExtensionQuery` is not enabled, so maintenance questions are not expanded into queries including exception handling keywords, making it impossible to match work order documents.

## How to Verify Proper Configuration
This verification is implemented based on FastGPT v4.17.0.
- Upload one test furnace temperature curve document and one equipment inspection record, initiate a query with corresponding keywords, and verify that the retrieval results include key fragments of these documents.
- Adjust the `similarity` parameter range, verify changes in retrieval counts across different thresholds, and confirm results meet business requirements.
- After enabling `usingReRank`, compare result rankings before and after enabling, and confirm that highly relevant content is displayed first.
- Check the knowledge base collection binding status, confirm that the retrieval scope only covers exclusive documents for the heat treatment workshop, with no cross-category retrieval results.

The values provided are common starting points and should be measured against the reader's own samples.
