# Heat Treatment Equipment Inspection and Maintenance Q&A: Forms and Interactions

## What Data for This Category Looks Like
Data for this category comes from material grade manuals, customer technical specifications, temperature control instruments, furnace temperature uniformity testing equipment, hardness testers and metallographic testing equipment, and workshop MES systems. Data updates are completed in line with the production rhythm of each furnace charge and production batch. Daily documents include heat treatment process cards, charging diagrams, furnace temperature curves (unit: ℃), hardness and metallographic reports, equipment inspection forms, and exception handling sheets. Document fields include heating temperature, holding time, charging station number, detected hardness value (HV or HRC), furnace temperature deviation value, and more. The structure is dynamically adjusted according to production batches.

## What Constraints These Characteristics Impose on the "Forms and Interactions" Link
Data updates for this category are completed dynamically in line with the production rhythm of each furnace charge and batch. This requires forms to support parameter entry for single batches at a time, and avoid reusing fixed universal templates. There are multiple types of daily documents with obvious differences in fields. Forms must support combinations of multiple field types, including numeric, enumeration, and relational fields. Data sources include two categories: automatic equipment collection and manual inspection. Forms must distinguish between automatically synchronized fields and manually filled fields to avoid data conflicts. The exception handling link needs to link inspection records and process data. Forms must support quick association of existing knowledge base entries to reduce duplicate entry.

## Configuration Settings
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `formInput` | Create field groups by furnace charge batch, including sub-fields such as heating section temperature, holding time, charging station, etc. | Data for this category is updated per furnace charge. Grouping facilitates centralized entry and verification of single-batch parameters |
| `userSelect` | Preset 12 exception type options, including furnace temperature deviation, charging misalignment, hardness nonconformity, etc. | Exception types in daily exception handling sheets are fixed. Preset options reduce manual input errors |
| Chunk Length | 800–1200 characters | The effective single-section content length of heat treatment process cards and furnace temperature curves falls within this range, preventing chunking from losing critical context |
| Single Search Limit | Top 6 entries | Knowledge base entries for this category are categorized by batch. The top 6 entries can cover process, inspection, and inspection data associated with a single furnace charge |
| Form Required Validation | Enable temperature range (room temperature to 1200℃) and duration interval (10–120 minutes) validation | Heat treatment parameters have fixed compliance ranges. Validation can proactively avoid invalid entry |

## Three Common Mistakes
- Phenomenon: After configuring custom form fields, calling the Q&A interface returns empty fields. Cause: The field group for `formInput` was not configured by furnace charge batch. The system cannot identify the association relationship of single-batch parameters.
- Phenomenon: After importing a multi-column Excel format equipment inspection form, automatic chunking results are chaotic, and field associations are broken. Cause: The segmentation unit was not specified as a single inspection record. The system defaults to splitting by paragraph, leading to data fragmentation.
- Phenomenon: After enabling the `userSelect` preset exception options, some on-site exceptions cannot be matched correctly. Cause: The preset options do not cover common scenarios such as quenching cooling rate abnormality and furnace body seal failure, leading to Q&A recall results that do not meet requirements.

## How to Confirm Proper Configuration
- Enter complete parameters for a single furnace charge, check that form fields are displayed grouped by batch, with no missing required items.
- Import a single heat treatment process card, check that automatically chunked content retains complete heating, holding, and cooling parameter sections.
- Submit an exception repair request, check that the preset options for `userSelect` include common on-site exception types and can be selected and submitted normally.
- Initiate a Q&A related to equipment inspection, check that recalled knowledge base entries prioritize associating the currently entered furnace charge parameters.

The values provided are common starting points and should be evaluated against the operator’s own operational samples.
