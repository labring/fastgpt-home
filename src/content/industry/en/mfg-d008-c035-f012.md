# Heat Treatment Equipment Inspection and Maintenance Q&A: Deployment and Upgrade

## What data for this category looks like
The data for this category comes from material grade standards, customer technical requirements, furnace temperature control instruments, furnace temperature uniformity test reports, hardness testers and metallographic testing equipment, and workshop MES systems.
Daily documents include heat treatment process cards, furnace loading layout drawings, furnace temperature curve records, hardness and metallographic test reports, equipment inspection forms, and exception handling sheets.
Data is updated per furnace charge and per batch. Fields include process parameters, test values, equipment operating status, and more. There are no unified fixed units; values change dynamically based on test items and process requirements.

## What constraints these characteristics impose on deployment and upgrade workflows
This category’s data is updated frequently and sourced from multiple disparate locations.
Deployment must support real-time incremental synchronization of multi-source heterogeneous data. Delays in data synchronization will reduce Q&A accuracy.
Document types are varied, and fields have no fixed standard. Index configurations must adapt to mixed formats such as process cards and test reports.
Equipment inspection and maintenance data is tightly bound to heat treatment process parameters. The Q&A system must support associative retrieval across equipment and process data. It cannot rely solely on single-source content matching.
Q&A results directly impact production quality. Post-deployment, service stability and result traceability must be ensured.
Upgrade workflows must be compatible with existing production data links. Production processes must not be interrupted during upgrades.

## Configuration settings
These configurations apply to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–150 connections` | This category’s data is updated frequently per furnace charge, so the database connection pool must support multiple concurrent synchronization requests |
| `REDIS_URL` | Cluster address with access password and 1000 MB single-node memory | Furnace charge data and equipment status must be cached to ensure response speed and storage capacity for high-frequency retrieval |
| `STORAGE_S3_ENDPOINT` | Internal enterprise object storage service endpoint, 5000 GB single-bucket capacity | Large-volume test documents such as furnace temperature curves and metallographic reports must be stored, and the configuration must adapt to existing enterprise storage links |
| `ROOT_KEY` | Hierarchical key divided by production workshop | Access permissions for equipment and process data across different heat treatment workshops must be separated |
| `FE_DOMAIN` | Internal enterprise operation and maintenance domain name | The Q&A system must be embedded into existing workshop operation and maintenance interfaces to ensure convenient access for operating personnel |
| `FILE_TOKEN_KEY` | `Token key with a 7-day validity period` | The security and validity period of shared links must match workshop operation and maintenance cycles |

## Three common configuration errors
- Scenario: After configuring multiple API key groups, the system returns an "authentication failed" error, and API keys cannot be allocated by model combination. Cause: API keys and model combinations are not bound by batch. Only a single set of keys is written in the global environment variables, which cannot support multi-model concurrent scheduling.
- Scenario: After importing documents such as furnace loading drawings and furnace temperature curves, search results cannot be linked to corresponding process card content. Cause: Cross-document associative indexing is not configured. Only individual documents are split independently, and no association between equipment, process, and test data is established.
- Scenario: After restarting the deployment server, shared links in the workspace cannot be accessed. Cause: Persistent shared token storage is not configured. Temporary tokens become invalid after server restart.

## How to confirm the configuration is correct
- Trigger a multi-source data synchronization task to verify whether production data from temperature control instruments and MES systems is synchronized to the system at the preset schedule.
- Submit a test query about equipment inspection or process abnormalities to verify whether the system can link corresponding documents such as process cards and furnace temperature curves and return associated results.
- Check system operation logs to confirm that database connection status meets configuration requirements, with no abnormal errors.
- Restart the deployment service to verify that shared links in the workspace can still be accessed normally, with no token invalidation issues.
