# Equipment Inspection and Maintenance Q&A for Production Planning and Shop Scheduling: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
Data for this category typically comes from business systems of manufacturing enterprise PMC, planning, shop scheduling, and material control departments. Core sources include ERP order and inventory data, BOM lists, process routes, equipment capacity ledgers, staff shift schedules, work-in-progress inventory, and supplier arrival records. Daily generated documents include sales orders, master production schedules, material requirements plans, weekly and daily scheduling tables, production work orders, material shortage lists, and delivery change notices. Data update frequency varies by business scenario. Basic capacity and shift data are synced daily. Scheduling baselines are updated weekly. Real-time updates trigger when orders change, materials are short, or equipment malfunctions. Fields include order numbers, material codes, process man-hours, equipment load rates, and other items. There are no unified fixed units, and units follow the field definitions of corresponding business documents.

## Constraints for HTTP Interfaces and External Systems
The data sources for this category are scattered, and update frequencies fluctuate. HTTP interfaces must support integration with multiple external system types, and accommodate different request and response formats. Data updates have no fixed cycle. Interfaces must support both scheduled pull and event-triggered synchronization modes. Daily document structures vary. Interfaces must allow custom field mapping to adapt to field definitions of different business documents. Real-time data synchronization requirements are high in abnormal scenarios. Interfaces must have fast response capabilities to avoid delays that impact scheduling adjustments and fault handling. No unified units exist for fields. Interfaces must support custom conversion of parameter units to avoid business errors caused by hard-coded adaptations.

## Configuration Settings
| Configuration Item | Recommended Value | Basis for This Setting |
| --- | --- | --- |
| `Authorization` | Carry an authentication string in the format `Bearer ${token}` | Complies with industry-standard API authentication specifications, ensuring access security for interfaces related to production planning and scheduling |
| `variables` | Pass key-value pairs containing order numbers, device IDs, and maintenance types | Adapts to the business parameter requirements of this category, supporting dynamic adjustment of the context for equipment inspection and maintenance Q&A |
| `responseData` | Extract core fields including scheduling suggestions, device status, and maintenance plans | Filters redundant data, reduces interface transmission load, and improves Q&A response efficiency |
| Timeout setting | 10–30 seconds | Adapts to the average response duration of scheduling data queries and device status synchronization, avoiding business blocking caused by long waits |
| Retry attempts | 2–3 times | Addresses network fluctuations or temporary interface exceptions, ensuring stability of data synchronization |

## Three Common Misconfigurations
- Symptom: Interface returns status code 401 with an authentication failure prompt. Cause: The `Authorization` parameter is not configured correctly, or an expired authentication token is used.
- Symptom: Equipment inspection and maintenance Q&A does not return the latest scheduling adjustment data. Cause: Only the scheduled pull mode is configured, and event-triggered synchronization is not enabled, resulting in data lag.
- Symptom: Connection to a custom large model API fails, and a module missing prompt is displayed. Cause: Custom API access configuration is not enabled in FastGPT v4.17.0, or the API key and interface address are not configured correctly.

## How to Confirm Configuration is Complete
- Send a test request containing valid order numbers and device IDs, and check whether `responseData` includes expected fields such as scheduling suggestions, device status, and maintenance plans.
- Simulate an order change or equipment fault event to verify whether the interface triggers real-time data synchronization and updates the Q&A context.
- View interface logs to confirm that the `Authorization` parameter is correctly carried and no authentication errors occur.
- Test the connected custom large model API to confirm that Q&A results can correctly call equipment inspection and maintenance related data returned by the external system.
