# Equipment Inspection and Maintenance Q&A for Production Planning and Shop Scheduling: Forms and Interactions

## What data for this category looks like
The data for this category mainly comes from ERP orders and inventory, BOMs and process routes, equipment capacity, staff shifts, work-in-progress, and supplier arrivals. Daily documents include sales orders, master production schedules, material requirements plans, weekly and daily scheduling sheets, work orders, material shortage lists, and delivery change notices. Data update cycles are daily, weekly, or triggered by order or exception adjustments. Fields include process number, equipment code, scheduling time slot, material batch, standard working hours, and more. Units include hours, piece counts, dates, and other standard units.

## Constraints on forms and interactions
Decentralized data sources and flexible update cycles require forms and interactions to support dynamic loading of fields from different business documents. This avoids adaptation issues caused by fixed configurations. Multiple types of business documents require interactions to support switching between different input modes. This adapts to scenarios such as work order filling and scheduling adjustments. Update demands triggered by exceptions require forms to have real-time field verification capabilities. This blocks inputs that do not comply with current scheduling rules. Additionally, cross-process business scopes require user selection interactions to dynamically generate options. These options match the current shop’s equipment and process ranges.

## How to set configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `formInput` | Enable multi-document binding mode, bind work order and material shortage list data sources | The core business documents for this category are work orders and material shortage lists; binding them allows automatic filling of corresponding fields |
| `userSelect` | Dynamically bind equipment capacity and staff shift data sources, set the maximum number of options to 20 | Shop equipment and shifts are updated daily; dynamic options avoid outdated data, and 20 options fit single-page browsing |
| Input box upload permission | Enable local file upload, limit single file size to 50 MB | Most business documents are scheduling sheets, work orders, and similar files; a 50 MB single file limit covers most scenarios |
| Context length | Set to 800–1200 characters | Scheduling-related Q&A needs to match work order and equipment information; this length covers core business content |
| Timeout threshold | Set to 600 seconds | Cross-data source queries require longer response times; 600 seconds avoids abnormal interruptions |

## Three common configuration errors
- Unable to select a knowledge base matching the current work order during a conversation, with the interface showing no available knowledge base options. This occurs because the business knowledge base corresponding to work orders and material shortage lists is not bound to the interaction flow, and only a general knowledge base is configured.
- No file upload button displayed in the chat input box, making it impossible to submit scheduling-related documents. This occurs because the file upload configuration for `formInput` is not enabled, or the restricted file size threshold is too low.
- Equipment options in the user selection module do not update with shop shifts, and the displayed equipment list does not match currently active equipment. This occurs because the dynamic data source pull rule for `userSelect` is not configured, and the options are only statically written fixed content.

## How to verify correct configuration
- Open the interaction configuration page of FastGPT v4.17.0, confirm that `formInput` is bound to work order and material shortage list data sources.
- Enter the test conversation interface, click the input box, confirm that a file upload button exists, and that documents under 50 MB can be uploaded.
- Submit a query containing an equipment number, confirm that the `userSelect` module can dynamically pull the equipment list for the current shop.
- Submit a simulated scheduling adjustment request, confirm that the form can automatically fill in field information for the corresponding work order.
