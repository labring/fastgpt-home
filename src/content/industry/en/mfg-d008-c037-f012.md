# Equipment Inspection and Maintenance Q&A for Production Planning and Shop Scheduling: Deployment and Upgrade

## What this category of data looks like
Typical business data comes from manufacturing enterprise ERP orders and inventory, BOM, process routes, equipment capacity, staff shifts, work-in-progress, and supplier deliveries. Daily involved documents include sales orders, master production schedules, material requirements plans, weekly scheduling sheets, work orders, material shortage lists, and delivery change notices. Data update frequency is daily, weekly, or triggered by orders or exceptions. Data fields include order number, process number, equipment capacity, material code, delivery time, and others. Units include pieces, hours, days, and other common business units.

## What constraints these characteristics impose during deployment and upgrade
Since data sources are scattered and update rhythms are inconsistent, deployment must support multi-data source connection and dynamic configuration loading. Document types are diverse and include structured business fields, so preset corresponding parsing rules to adapt to different business documents. Production scenarios have high requirements for data timeliness, so upgrade processes must avoid interrupting core services, and reserve sufficient concurrent processing resources to support daily queries and scheduling calculations.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://fastgpt:xxxx@192.168.1.100:27017/production_planning?authSource=admin` | Stores structured business data such as work orders and scheduling sheets |
| `REDIS_URL` | `redis://:xxxx@192.168.1.101:6379/1` | Caches frequently accessed equipment inspection records and real-time scheduling data |
| `DB_MAX_LINK` | `80–120 concurrent connections` | Adapts to concurrent data query requirements for production planning and shop scheduling scenarios |
| `FE_DOMAIN` | `https://your-manufacturing-site.com/fastgpt` | Frontend access root path when deploying under a secondary directory |
| `FILE_TOKEN_KEY` | Randomly generated 64-bit string | Encrypts the upload and verification process for equipment inspection documents |
| `ROOT_KEY` | Randomly generated 32-bit string | Highest privilege authentication for the admin backend |

## Three common misconfigurations
- After configuring `FE_DOMAIN`, fail to synchronously update the path forwarding rules of the Nginx reverse proxy, resulting in failed loading of frontend resources and 404 status codes on the page.
- Fail to correctly configure `REDIS_URL` and load environment variables, leading to cache failure, service timeouts and unresponsiveness during high concurrency, and inability to return normal conversation results.
- After upgrading to FastGPT v4.17.0, fail to re-adapt business document parsing rules, resulting in inability to extract valid content when passing links to scheduling sheets, work orders, and others, only returning empty results.

## How to confirm correct configuration
- Access the configured `FE_DOMAIN` path, confirm that the frontend page loads normally with no resource loading failure prompts.
- Submit test work order data, verify that the database connection is normal, and data can be written and queried normally.
- Upload a test shop scheduling sheet, confirm that the document parsing function can extract process, capacity and other field information.
- Simulate high-concurrency query requests, confirm that the number of database connections does not exceed the `DB_MAX_LINK` configuration value, and there is no abnormal service interruption.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
