# Q&A for Equipment Inspection and Maintenance in Biologics and Aseptic Production: Forms and Interactions

## What this category’s data looks like
Typical entities in this category are vaccine, antibody, blood product, and sterile injectable enterprises. Daily documents include cell bank or seed lot records, culture and purification records, aseptic filling records, environmental monitoring data, media fill simulation results, sterility test reports, and batch release materials.
Data sources cover cell banks and seed lots, process analysis systems, cleanroom monitoring equipment, MES, LIMS, and equipment integrity testing tools.
Data update frequencies include synchronization with each production batch, real-time monitoring pushes, and updates according to fixed monitoring plans.
Fields include sterilization temperature (℃), equipment operating duration (minutes), cleanroom sedimentation bacteria colony count (cfu/plate), and others, adjusted dynamically based on production stages.

## Constraints on forms and interactions
Dispersed data sources and inconsistent formats require forms and interactions to support associated retrieval from multiple data sources, avoiding duplicate data entry.
Data update frequencies include both real-time and batch modes, so interaction workflows must support on-demand refresh of real-time data and batch submission of records according to production batches.
Daily documents have complex structures and many fields, so conditional jumps and hierarchical selection must be supported to match the problem tree logic of equipment inspection and maintenance.
Compliance requirements for aseptic production and the serious consequences of errors require forms to include strict mandatory field validation and operation logging, preventing omission of key parameters.

The following configurations are based on FastGPT v4.17.0.

| Operation log recording | Enable full-process operation logging | Meet compliance requirements and facilitate traceability of inspection and maintenance processes |

## Three common mistakes
- Phenomenon: Multi-layer `userSelect` components cannot link to lower-level options, and lower-level options remain empty. Cause: Cascading trigger rules for `userSelect` are not configured, and the parameter value of the upper-level selection is not bound to the lower-level component.
- Phenomenon: File upload only supports a small number of formats and cannot connect to the MCP service. Cause: File upload format configuration is not set to full optional, and the format mapping supported by MCP is not updated synchronously.
- Phenomenon: Empty errors occur when calling external models, or knowledge base references cannot be selected in code running nodes. Cause: `formInput` binding for the corresponding parameters is not configured in the form, or system variables and knowledge base IDs are not correctly associated.

## How to confirm the configuration is complete
- Trigger the multi-layer `userSelect` component, verify that lower-level options update dynamically based on the content selected in the upper-level component.
- Upload files of different formats, verify that they meet the configured format requirements and can be submitted normally.
- Clear key fields in the form, verify that mandatory validation prompts are triggered and form submission is blocked.
- Call external models or code nodes, verify that parameters have been correctly passed to the corresponding links.
