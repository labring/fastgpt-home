# Q&A for Equipment Inspection and Maintenance in Electric Motor and Generator Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What Data Looks Like for This Category
This category’s data originates from winding, insulation, final assembly, and testing departments of electric motor and generator manufacturing enterprises. Core documents include winding process cards, insulation treatment records, dynamic balance reports, withstand voltage insulation test records, and type test and factory inspection test reports. Data sources include electromagnetic design data, copper wire and insulation material batch ledgers, winding equipment operating parameters, dynamic balancing machine test data, electrical test bench test results, and production batch information from ERP/MES systems. Data is updated once per finished product or per production batch. All associated documents are synchronized for update when product type changes.

## What Constraints These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering
This category’s independently updated per-production-batch and per-product-type data imposes specific constraints on multi-turn dialogue and prompt engineering. Multi-turn dialogue must accurately bind production documents and test records for the corresponding batch to avoid calling expired data across batches. Professional documents include detailed fields such as winding turns, paint dipping process parameters, dynamic balance allowance, and withstand voltage test values. Prompts must clearly limit dialogue to only call production batch data associated with the current session to prevent confusion of process requirements for different products. The high-frequency update feature requires multi-turn context to filter historical batch data not related to the current session, ensuring each Q&A only links to the currently discussed electric motor or generator model.

## Three Common Misconfigurations
- Model output inserts extra spaces or capitalizes letters, causing incorrect source document reference formatting. The cause is that the prompt does not clearly specify that output must strictly match the character and formatting specifications of the source document.
- Unable to invoke the file parsing tool to read specified test reports. The cause is that the document path configured in the knowledge base is not bound to the corresponding production batch, or the correct document association ID is not passed via `variables`.
- Historical records carry redundant content from specified reply plugins, interfering with multi-turn dialogue logic. The cause is that no `messages` filtering rules are configured, and plugin interaction records that are not part of business dialogue are not excluded.

## How to Verify Proper Configuration
- Initiate a dialogue to verify winding turns for a specific production batch motor, check that returned results only link to process cards and test data for that batch.
- Initiate two consecutive dialogues, then switch session parameters, confirm that the new session's historical records do not carry redundant content from the previous session.
- Upload a new test report and initiate related Q&A, confirm that the tool can correctly call and parse the new document.
- Check the model's output content, confirm that no extra spaces or capitalization errors appear, and the format matches the source document specifications.

The values provided are common starting points and should be measured against the reader's own samples.
