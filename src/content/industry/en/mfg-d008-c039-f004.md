# Equipment Inspection and Maintenance Q&A for Electric Motor and Generator Manufacturing: Workflow Orchestration

## What this category's data looks like
Data for this category comes from electromagnetic design databases, copper wire and insulation material batch ledgers, winding equipment operation logs, balancing machine test data, electrical test bench test results, and production work orders from ERP/MES systems. Daily documents include winding process cards, insulation treatment records, dynamic balance reports, withstand voltage insulation test records, and type and factory test reports. Fields cover winding turns, insulation thickness, vibration amplitude, temperature rise values, test voltage, and other metrics. Units include millimeters, amperes, degrees Celsius, revolutions per minute, and others. Data is updated per finished product or production batch. All associated documents are fully synchronized after each design change.

## What constraints these characteristics impose on workflow orchestration
Data for this category is scattered across multiple types of equipment and systems, and linked to a single finished product or production batch. Workflows must support associating multi-source heterogeneous data by work order ID. Document fields include parameters with dedicated units. Workflows must configure field standardization mapping nodes to unify data formats. Updates are triggered dynamically alongside production batches and design changes. Workflows must support on-demand startup, and not use fixed-period scheduling. For high-voltage test and temperature rise data, workflows must add a validity check step after data reading. This prevents abnormal values from causing deviations in subsequent analysis. Workflows must bind work order IDs and batch numbers via `variables` to ensure accurate data association.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `variables` | Set work order ID and winding batch number as required global variables | Accurately associate exclusive production data and test records for single units or single batches of this category |
| Bulk execution node maximum input length | 80 entries | The number of test reports for a single production batch of this category typically does not exceed 80, to avoid excessive memory usage |
| Workflow maximum run count | 1000 runs | Adapt to the full process execution requirements of a single batch of motors from inspection to maintenance |
| `nodeId` | Configure a fixed node ID for the data validity check node | Accurately locate the check step when calling MCP in loops, avoid process jump anomalies |
| Data read timeout | 600 seconds | The average time for electrical test benches to return complete test data is 300-500 seconds, reserve reasonable buffer time |

This configuration guide is based on FastGPT v4.17.0.

## Three common configuration mistakes
- Phenomenon: Database node queries return JSON arrays that cannot be directly used for text concatenation or field extraction. Cause: No data parsing node is configured, and JSON-formatted test data is not converted to structured fields.
- Phenomenon: MCP nodes return null values when concurrent call volume reaches business peak levels. Cause: No concurrency limiting policy is configured, exceeding the carrying threshold of the MCP service.
- Phenomenon: Calling Feishu Webhook has no response after text concatenation via a loop node, and the Hook URL works normally in separate tests. Cause: No text format check is added after the concatenation node. Excessively long content or content containing special characters causes the Webhook request to fail.

## How to confirm correct configuration
- Pass preset work order ID and batch number, check whether the workflow correctly pulls the winding process card and test reports for the corresponding batch.
- Simulate business peak concurrent calls, check whether the MCP node returns results with no null values.
- Trigger a process that includes a loop node and text concatenation, check whether the final pushed message content matches the concatenation result.
- Run the workflow to the preset maximum run count, check whether the process completes normally without abnormal termination.
