# Equipment Inspection and Maintenance Q&A for Battery PACK and Energy Storage System Integration: Tool Calling and Plugins

## What Data Looks Like for This Category
Typical subjects of this category are manufacturers of battery packs, energy storage cabinets, and BMS systems.
Daily documents include grouping rules, BOM lists, welding and torque records, BMS flashing records, insulation and voltage withstand reports, EOL test reports, and system configuration lists.
Data sources include cell capacity grading data, MES systems, welding equipment, torque tools, BMS software, and EOL test benches.
Update frequency is once per device pack or cabinet, or each time the BMS software version is updated.
Core time-consuming steps include cell parameter grouping, high-voltage connection and thermal management, insulation verification, BMS flashing, and charge-discharge communication testing.

## What Constraints These Characteristics Impose on Tool Calling and Plugins
Multi-source heterogeneous data sources require tool calling to support cross-system data pulling. This covers different data types such as cell capacity grading, MES, and device logs.
Fixed update frequencies require tools to support real-time data synchronization. Trigger conditions include device completion and BMS software version changes.
Complex document structures require tool calling to split parameters by module. This ensures accurate matching of field formats for different documents such as grouping rules and BMS configurations.
Severe error consequences require tool calling to configure failure verification and retry mechanisms. This prevents issues such as thermal management failure or BMS protection malfunction caused by data errors.
Differences from cell manufacturing categories require tools to adapt to high-voltage system parameters. Their processing logic is distinct from that of electrochemical parameters.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | Force set to `function` | Adapt to structured tool calling requirements for equipment inspection scenarios, avoid parameter errors from free-form output |
| Timeout duration | 600 seconds | Aligns with average time ranges for device data pulling and BMS configuration queries |
| Number of tool call results per single request | Top 3 entries | Matches core parameter scope of single-device inspection, avoids interference from redundant information |
| Number of failure retries | 2 times | Addresses common scenarios such as temporary device disconnection and interface jitter |
| Parameter mapping rules | Direct mapping by source document field names | Adapts to field formats of standardized documents including BOMs and welding records |
| `functionCall` | Enable strict mode | Ensure tool calling parameter format meets verification requirements of equipment systems |

## Three Common Misconfigurations
- Database query plugin calls fail, returning empty results or 400 errors. The cause is failure to map source document fields to device system parameter names, leading to query conditions that cannot match target data.
- The model fails to generate standardized inspection documents, with missing fields or chaotic formatting. The cause is failure to enable `functionCall` strict mode, so tool output is not organized per the preset structure.
- API calls trigger cross-domain interception, with request timeouts or server rejection. The cause is failure to configure allowed domain name whitelists on the server, which does not meet cross-domain request requirements of the device system.

## How to Verify Correct Configuration
- Initiate a simulated inspection request, check if tool calls return specified data such as BOM, welding torque, and insulation voltage withstand for the target device.
- View tool call logs in FastGPT v4.17.0, confirm parameter format under `functionCall` strict mode meets preset requirements.
- Simulate a device disconnection failure scenario, check if the preset failure retry mechanism triggers.
- Review generated inspection documents, confirm fields fully match source document parameters with no omissions or errors.
