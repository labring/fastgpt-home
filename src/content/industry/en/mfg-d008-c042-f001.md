## What the Data for This Category Looks Like
Data for petroleum refining scenarios comes from DCS/APC control systems, LIMS laboratory information management systems, tank farm metering systems, crude oil evaluation databases, equipment management systems, and energy management systems. Daily documents include operating procedures, production plans, material balance sheets, distillate export quality reports, interlock ledgers, shift handover records, and change management documents. Data update rhythms cover real-time, per-shift, and daily frequencies. Fields include equipment tag numbers, unit numbers, inspection cycles, maintenance work order numbers, crude oil property parameters, and process fluctuation thresholds. Units include megapascals (MPa) for pressure, degrees Celsius (°C) for temperature, cubic meters per hour (m³/h) for flow, and other standard units.

## Constraints Imposed on HTTP Interfaces and External Systems by These Characteristics
Multiple continuous units couple via material and hydrogen energy networks. Interfaces must support batch retrieval of real-time process data across units to avoid business disruptions from single-point request delays. Data update frequencies span a wide range. Interfaces must support data retrieval at three granularities: real-time, per shift, and daily to meet query needs for different business scenarios. Document types are diverse and fields are complex. Interfaces must support different request formats for structured ledgers and unstructured procedure texts. Data related to equipment inspection and maintenance links multiple systems. Interfaces must support cross-system data aggregation requests. They must also align request frequencies with the concurrency limits of each system to avoid triggering rate limiting rules.

## Three Common Configuration Mistakes
- Phenomenon: An "incorrect parameter" error returns when calling the `cloud.fastgpt.cn` API to upload documents. Cause: Metadata fields for petroleum refining scenario documents are not configured correctly, such as failing to add business parameters like deviceNo and shift, resulting in interface verification failure.
- Phenomenon: The Q&A result returned by the interface callback does not include the thinking process content of deepseek. Cause: The return field containing the thinking process is not specified in the `responseData` configuration, or the thinking process output setting for the corresponding model is not enabled.
- Phenomenon: When proxyAI and one-api coexist, calling the equipment inspection interface returns `404 body not found`. Cause: The dedicated petroleum refining equipment inspection interface path is not separately configured in proxy forwarding rules, resulting in requests being incorrectly forwarded to a mismatched interface pool.
