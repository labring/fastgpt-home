# Equipment Inspection and Maintenance Q&A for Petroleum Refining: Workflow Orchestration

## What Data for This Category Looks Like
Data related to equipment inspection and maintenance Q&A for petroleum refining comes from DCS/APC control systems, LIMS laboratory information management systems, tank farm metering systems, equipment management systems, and crude oil evaluation reports. Update frequencies cover real-time (unit operating condition parameters), shift-based (shift handover records), and daily (material balance and quality reports). Daily documents include operating procedures, interlock logs, change management documents, distillate outlet quality reports, and more. Fields include unit number, interlock trigger threshold, equipment vibration value, crude oil density, product distillate indicators, and more. Units include degrees Celsius, pascals, millimeters per second, tons per hour, and more.

## Constraints Imposed on Workflow Orchestration by These Characteristics
Multi-data source access is required. Data comes from multiple heterogeneous systems, so workflows must support cross-system data pulling and format unification.
Document types are diverse and highly coupled. Recall rules must be configured by document category to avoid irrelevant content interfering with judgments.
Update frequencies vary widely. Real-time data requires high-frequency triggering, while shift-based and daily data require scheduled synchronization. Workflows must support mixed triggering modes.
Logistics and energy networks couple refining units. Workflows must handle cross-unit parameter linkage to avoid overall process anomalies caused by single-point configuration.

## How to Set Configurations

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context | Top 10 conversation contexts | Matches the historical operating condition dependency characteristics of refining equipment issues, avoids excessive redundant information interfering with judgments |
| Timeout Threshold | 600 seconds | Adapts to the time consumption requirements of DCS real-time data pulling and cross-unit parameter linkage, avoids process interruption |
| Single Search Limit | Top 8 relevant documents | Balances recall accuracy and response speed, adapts to the retrieval scenario of multiple coupled documents in refining |
| `variables` Configuration | Bind unit number and crude oil density parameters | Accurately match the equipment's affiliated unit and operating conditions, narrow the retrieval scope |
| `nodeId` Setting | Associate inspection record nodes and work order nodes | Achieve automatic linkage between equipment inspection data and maintenance processes, simplify manual operations |
| Chunk Length | 800-1200 characters | Adapts to the single-section content length of refining operating procedures and interlock logs, improves retrieval matching accuracy |

## Three Common Mistakes
- Phenomenon: Workflow runs with timeout, and the interface displays a request timeout prompt. Cause: No reasonable timeout threshold configured for refining real-time DCS data, and waiting for cross-unit data synchronization time exceeds the preset upper limit.
- Phenomenon: Unable to trigger specified page jump in the workflow, and the node has no valid jump configuration. Cause: No trigger rule for the corresponding page bound in the workflow node, and the `nodeId` association parameter is not configured correctly.
- Phenomenon: The number of contexts is set to 0 but historical conversations are still retained, and multi-turn conversation functions are abnormal. Cause: Confuses the binding logic between workflow context and conversation history, and does not correctly filter historical contexts through the `variables` configuration.

## How to Verify Correct Configuration
- Import refining-specific operating procedures and interlock log documents, verify that workflow nodes can recall content of the corresponding category.
- Simulate an abnormal inspection operating condition, check whether the workflow completes data pulling within the configured 600-second timeout threshold.
- Adjust the unit number parameter in `variables`, verify that the workflow only returns maintenance documents and operating data of the corresponding unit.
- Test setting the number of contexts to 0, confirm that conversation history is not brought into the workflow nodes.
