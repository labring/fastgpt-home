# Spinning and Weaving Equipment Inspection and Maintenance Q&A: Forms and Interactions

## What this category of data looks like
This data covers cotton spinning, chemical fiber spinning, woven and knitted production entities. Daily documents include cotton blending or batching lists, process setup sheets, equipment operation records, yarn inspection sheets, grey fabric inspection sheets, and fabric defect records.
Data sources include raw fiber test results, enterprise ERP systems, real-time operation data of spinning machines and looms, evenness tester detection data, fabric inspection machine collected data, and order specification parameters.
Data updates follow production workflows. Corresponding records are generated or updated when each batch of raw materials is fed, each shift completes equipment inspection, and each piece of fabric is produced.
Fields include fiber indicators, twist parameters, loom speed, defect types, order specifications, and other items. There is no unified standard unit, and some parameters require adjustment based on the corresponding equipment model.

## Constraints imposed on forms and interactions
Multi-source heterogeneous data, high-frequency update rhythm, and precise association requirements in this production scenario create multiple constraints for forms and interactions.
Multi-source inspection and operation data requires forms to support field linkage. For example, fields in batching lists must automatically associate with fiber test results for the corresponding batch.
High-frequency update requirements for each shift and each piece of fabric require forms to support fast batch submission and status synchronization.
Single-piece fabric defect records must be bound to the corresponding loom and production batch. Forms must include automatic filling and verification rules for equipment numbers and batch numbers.
Differences in parameter units across equipment require forms to support dynamic unit switching to avoid entry errors.
Defect records must match process parameters. Forms must provide quick access to preset parameters to reduce manual input mistakes.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |

| `formInput` field validation | Match the legal value ranges of fiber indicators and twist | Adapt to the parameter standards of spinning and weaving equipment, avoid entering invalid values |
| `userSelect` dropdown options | Preset three types of options: equipment type, defect type, inspection type | Align with the problem classification logic of production scenarios, improve classification efficiency |

| Context cache duration | 600 seconds | Match the operation interval of shift inspections, retain the operation context of the current batch |
| Form automatic filling rules | Bind equipment number and batch number | Automatically fill based on ERP and loom data, reduce manual entry errors |

## Three common configuration errors
- Phenomenon: The AI model dropdown list in the equipment inspection form is empty, and no available models can be selected. Cause: The form configuration is not bound to the knowledge base permissions for the corresponding category, or the cache rules in FastGPT v4.17.0 failed to correctly load the model list.
- Phenomenon: The "Select Knowledge Base" component in global variables cannot be dynamically assigned, and production data for the corresponding batch cannot be switched. Cause: The trigger condition for knowledge base loading is not set to production batch update, or the form's linkage rules are not associated with global variables.
- Phenomenon: Unexpected reference content is returned when submitting defect records, even when the reference return switch is disabled. Cause: The form's context cache did not clear old batch data, causing cross-batch parameter interference with the reference logic.

## How to verify successful configuration
- Access the form configuration interface, and confirm whether the validation rules for the `formInput` field cover the core parameter range for spinning and weaving.
- Trigger the `userSelect` dropdown options, and confirm that the preset equipment, defect, and inspection classifications load correctly.
- Simulate a production batch switch, and verify that the knowledge base dynamic loading function operates properly.
- Submit batch test records, and confirm that the submission limit and cache duration settings align with the current production rhythm.
