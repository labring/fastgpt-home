# Equipment Inspection and Maintenance Q&A for Measuring Instruments and Laboratory Management: Tool Calling and Plugins

## What Data for This Category Looks Like
Data for this category originates from enterprise metrology management systems, LIMS platforms, external calibration institution certificates, standard instruments, and environmental monitoring equipment. Daily generated documents include gauge ledgers, calibration plans, calibration certificates, interim verification records, original test records, reference material ledgers, and deviation handling documents.
Data updates are triggered by calibration cycles, single test results, or abnormal events. Included fields are instrument number, calibration validity period, accuracy grade, measurement uncertainty, traceability standard instrument number, and other relevant fields. Supported units include specialized metrology units such as micrometers, pascals, and grams.

## Constraints on Tool Calling and Plugins
This category’s data is multi-source, heterogeneous, and has inconsistent update rhythms. Tool calling must support API integration with multiple platforms including metrology management systems and LIMS, to handle different field formats and units.
Key traceability-related fields must be fully retained, otherwise the credibility of metrology results will be compromised. Tool call return content must be concise and precise, to avoid overflowing the context window. Additionally, metrology data errors can lead to serious quality consequences, so parameter validation and failure retry mechanisms must be configured to ensure the accuracy of call results.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Supports automatically matching whether to call tools based on the user's inspection and maintenance questions, adapting to multi-scenario Q&A requirements |
| `functionCall` | `enabled` | Enables the tool calling function, allowing integration with external data sources such as metrology management systems and LIMS to retrieve instrument data |
| Tool call timeout | `300-600 seconds` | Pulling calibration certificates and traceability data requires certain network latency, this range prevents call failures from short delays |
| Tool call result cache duration | `7 days` | Calibration cycles are mostly monthly or quarterly, caching reduces repeated requests while ensuring data timeliness |
| Tool call retry count | `2 times` | Addresses temporary fluctuations in external systems, improving call success rates |
| Tool return content filter | `Only retain instrument number, calibration validity period, measurement uncertainty; total length no more than 1000 characters` | Streamlines returned content to avoid context window overflow, focusing on core metrology data |

## Three Common Misconfigurations
- Scenario: A 403 status code is returned when calling the metrology management system API, and instrument calibration data cannot be retrieved. Cause: Correct API access keys are not configured, and permission scopes are not set for the dedicated metrology instrument data interface.
- Scenario: When sequentially executing inspection Q&A and traceability query plugins, subsequent plugins cannot retrieve the instrument number passed by the previous plugin. Cause: Inter-plugin context sharing configuration is not enabled, and dedicated variables for storing key identification information are not bound.
- Scenario: The model does not proactively call the maintenance knowledge base, and only responds to inspection questions with generic answers. Cause: `toolChoice` is not set to `auto`, trigger keywords for tool calling are not configured, and the dedicated metrology maintenance knowledge base is not associated.

## How to Confirm Configurations Are Properly Set Up
- Submit a question that includes "check the calibration status of XX gauge", verify whether the tool automatically calls the external API and returns corresponding data such as calibration validity period and measurement uncertainty.
- Simulate a network interruption scenario, submit a tool call request, verify whether the system automatically retries according to the configured retry count and successfully retrieves data after network recovery.
- View plugin execution logs, verify whether the returned content only retains the specified configured fields and no redundant information appears.
- Submit consecutive inspection questions, verify whether key context information such as instrument numbers is correctly passed between plugins, ensuring subsequent calls are based on the target instrument for the current session.
