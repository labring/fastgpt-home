# Equipment Point Inspection and Preventive Maintenance Repair Q&A: Deployment and Upgrade

## What this category of data looks like
Data for this category originates from enterprise EAM/CMMS systems, equipment sensor collection terminals, daily operator point inspection records, maintenance work order history, spare parts inventory ledgers, and statutory inspection archives. Daily documents include equipment ledgers, point inspection forms, maintenance plans, repair work orders, fault analysis reports, spare parts lists, and special equipment inspection records. Fields include equipment numbers, point inspection item parameters, fault codes, spare part models, inspection validity periods, and additional metadata. Units include millimeters, operating hours, pieces, and other standard units. Data update cycles cover shift-based point inspection submissions, weekly maintenance plan releases, monthly ledger updates, and real-time records when faults occur.

## What constraints these characteristics impose during deployment and upgrade
Data sources for this category are scattered, and update cycles vary significantly. During deployment, configure multiple data source connection permissions to ensure synchronous access to data from EAM/CMMS, sensor data, point inspection records, and other sources. Daily document structures are diverse, so adapt content parsing for different formats including equipment ledgers, point inspection forms, and fault analysis reports. The real-time nature of data updates requires support for real-time synchronization in scenarios when faults occur. During upgrades, support both incremental synchronization and full update modes. Compliance requirements for special equipment inspection records demand configuration of encrypted storage options that meet storage specifications to ensure data traceability. Repair work orders and spare parts data have strong correlations, so configure association retrieval rules during deployment to ensure Q&A results match corresponding spare parts information.

The following configurations apply to FastGPT v4.17.0:
## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `PG_URL` | `postgresql://username:password@host:5432/fastgpt_device` | Stores structured data such as equipment ledgers and repair work orders, matching the structured document storage needs of this category |
| `REDIS_URL` | `redis://:password@host:6379/0` | Caches point inspection records and real-time fault retrieval results to reduce database load from high-frequency requests |
| `ROOT_KEY` | Randomly generated 32-character string | Configures the system administrator permission key to ensure initial permission security after deployment |
| `DB_MAX_LINK` | `10` | Limits the number of database connections to avoid connection exhaustion during multi-data-source synchronization |
| Re-ranking | Enabled | Optimizes the ranking of retrieval results for fault analysis and repair plans to improve matching accuracy |
| Single search limit | Top 10 entries | Meets the common result quantity requirement for fault retrieval and point inspection item matching in this category |

## Three common configuration errors
- A 404 status code is returned when calling a locally deployed model. Incorrect configuration of model connection API path parameters causes frontend requests to fail to match backend service endpoints.
- Q&A retrieval does not trigger after uploading documents such as equipment ledgers or point inspection records. Missing configuration of `PG_URL` or vector storage related parameters prevents document embedding data from being stored and recalled normally.
- Modifying the system administrator password for a Docker deployment fails. Skipping `ROOT_KEY` permission verification, directly modifying the local configuration file, and failing to restart the container causes new configuration changes to not take effect.

## How to verify successful configuration
- Run the docker compose ps command to confirm all service containers are in a running state with no abnormal exit records.
- Access the frontend address specified by `FE_DOMAIN` to confirm the management backend loads normally and administrator login verification completes successfully.
- Upload an equipment point inspection form document, trigger a retrieval Q&A test, and confirm matching results based on the document content are returned.
- Run a database connection test command to confirm normal connection establishment using the configuration parameters for `PG_URL` and `REDIS_URL`.

The values provided are common starting points and should be evaluated against the reader's own samples.
