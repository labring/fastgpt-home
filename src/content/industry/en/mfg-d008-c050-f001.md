# Equipment Inspection and Maintenance Q&A for General Mechanical Equipment Assembly: HTTP Interfaces and External Systems

## What Data Looks Like for This Category
Data for the general mechanical equipment assembly category typically comes from PLM/ERP, part inspection data, assembly tool collection systems, test benches, MES, and customer technical agreements. Daily documents include assembly process cards, BOMs, torque records, clearance adjustment records, commissioning reports, factory inspection certificates, and packing lists.

Data is updated per single device or order. Most fields include torque values, clearance parameters, concentricity indicators, and use units such as newton meters, millimeters, and micrometers.

## What Constraints Do These Characteristics Impose on HTTP Interfaces and External Systems
Data for this category is updated per single device or order, and includes multiple types of structured and unstructured documents. This requires HTTP interfaces to support pulling corresponding datasets via precise parameters such as device serial numbers and order numbers.

Most fields have specific units. Interfaces must support unit validation logic to avoid parameter format mismatches. Document types cover assembly process cards, BOMs, and more. Different interface configurations are needed to adapt to call rules for different data sources.

The high-frequency update feature also requires interfaces to support near-real-time pulling, to ensure the timeliness of data sources for equipment inspection and maintenance Q&A.

## How to Configure
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Authentication Method | Set `Authorization` header to Bearer Token format, fill in the value per external system requirements | Complies with general authentication standards for industrial system interfaces, ensures secure access to data sources such as PLM and MES |
| Request Variable Binding | Bind device serial number and order number to the `variables` parameter | Accurately matches assembly documents and inspection data for a single device, aligns with the per-unit data update characteristics of this category |
| Response Data Filtering | Only retain core fields such as torque values, clearance parameters, and concentricity indicators in `responseData` | Reduces invalid data transmission, meets the lightweight data requirements of equipment inspection and maintenance Q&A |
| Request Timeout | 10-30 seconds | Adapts to the time required to pull data from multiple sources, prevents request failures due to delayed data from assembly tools or test benches |
| Response Format | Fixed to standard JSON format | Compatible with the variable parsing logic of FastGPT v4.17.0 workflow, facilitates subsequent data calls during the Q&A stage |

## Three Common Mistakes
- Symptom: After calling the configured HTTP interface, an empty `responseData` field is returned, and no corresponding equipment inspection and maintenance Q&A content can be generated. Cause: The device serial number and order number are not correctly bound to the `variables` parameter, so the interface cannot match the exclusive assembly documents of a single device.
- Symptom: The interface returns full raw data, and custom output fields cannot be configured. Only the full dataset can be displayed. Cause: The `responseData` field filtering rule is not configured, and all original content from PLM or MES is returned directly.
- Symptom: The external system cannot receive the interface return result. The FastGPT interface displays normally, but no output is sent through the channel. Cause: The `Authorization` authentication header is not configured correctly, causing the external system to block unauthorized interface requests.

## How to Confirm the Configuration is Correct
- Call the configured interface, pass a known device serial number, and check if the returned `responseData` field contains the core parameters of the corresponding assembly document.
- Verify the `Authorization` header configuration, confirm it matches the authentication format required by the external system.
- Adjust the variables bound to the `variables` parameter, and verify that different device serial numbers can return corresponding data.
- Test different request latency scenarios, confirm that the interface completes the request within a reasonable range and returns valid data.
