# Equipment Inspection and Maintenance Q&A for General Mechanical Equipment Assembly: Forms and Interactions

## What Data for This Category Looks Like
Typical manufacturers produce pumps, valves, compressors, reducers, machine tools and non-standard equipment. Daily documents include assembly process cards, BOMs, torque records, clearance adjustment records, commissioning reports, factory inspection sheets and packing lists. Data sources include PLM/ERP systems, part inspection data, assembly tool collection systems, test benches, MES systems and customer technical agreements. Updates are completed per individual equipment or per order. Fields include professional parameters such as material codes, torque values (unit N·m), clearance parameters (unit mm) and coaxiality tolerances (unit μm).

## Constraints on Forms and Interactions
Multi-source data means forms must support cross-system field association to avoid duplicate manual entry errors. Updates per equipment or order require forms to group and archive data by order number or equipment serial number. Fixed units for professional fields require forms to pre-configure input items with units, reducing parameter format errors. The time-consuming task of multi-level BOM verification requires fast-matching selection components in interactive configurations to improve verification efficiency. Mandatory core commissioning parameters require form validation rules to avoid risks of missing or incorrect assembly, or missing commissioning data.

## Configuration Setup
The following configurations are based on FastGPT v4.17.0, adapted for the equipment inspection and maintenance Q&A scenario for general mechanical equipment assembly.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `formInput` | Pre-configure input templates with professional units, such as torque input boxes defaulting to display "N·m" and clearance input boxes defaulting to display "mm" | Match the parameter unit requirements of assembly records, reduce manual input format errors |
| `userSelect` | Associate BOM material codes as selectable values, limit matching results to the first 15 entries, and support configuring whether to skip knowledge base retrieval | Simplify alignment verification between multi-level BOMs and physical items, adapt to user needs for selecting whether to skip retrieval |
| Single Submission Limit | 8–12 records per submission | Adapt to the number of assembly record entries for a single piece of equipment, avoid data overload from a single submission |
| Mandatory Item Validation Rules | Torque values and coaxiality parameters are mandatory fields | Avoid risks of missing core commissioning data entries |
| Session Archiving Rule | Store data grouped by order number + equipment serial number | Match the data update rhythm of per-order updates, facilitate subsequent traceability |

## Three Common Configuration Errors
- A 400 error occurs when calling the `userSelect` component. The cause is incorrect configuration of field mapping for the associated BOM data source, leading to failed parameter validation.
- Concurrent selection results appear in the `userSelect` component. The cause is failure to set mutually exclusive selection rules, allowing multiple BOM entries to be selected simultaneously, which does not meet the single matching requirement for assembly verification.
- An SSL error is returned for a voice input-triggered Q&A request. The cause is failure to deploy a valid SSL certificate, or failure to configure the HTTPS protocol for the service port.

## How to Verify Successful Configuration
- An assembly torque record is manually entered. The `formInput` component is confirmed to automatically display the preset unit, and mandatory item validation is confirmed to trigger a prompt when the torque value is not filled in.
- A search for BOM material codes is initiated in the `userSelect` component. Only the first matching results are confirmed to be returned, and multiple entries are confirmed to not be selectable simultaneously.
- A set of assembly records is submitted. The session is confirmed to be automatically archived by order number + equipment serial number, and cross-order data mixing is confirmed to not occur.
- A voice input request is initiated. The request link is confirmed to comply with HTTPS protocol requirements, and no SSL error is returned.
