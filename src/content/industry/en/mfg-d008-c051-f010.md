# Equipment Inspection and Maintenance Q&A for Metal Cutting Machining: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Data sources include product drawings and 3D models, CAPP/CAM systems, machine tool collection data, tool management systems, MES systems, and measurement tool inspection records. Daily documents cover process routes, operation cards, tool lists, CNC programs, first-piece inspection records, patrol inspection forms, and measurement tool calibration records. Data updates are triggered with each work order, single-piece machining, sampling inspection, or tool replacement. Documents include fields such as tool model, process parameters (unit: μm), machine tool alarm codes, measurement tool calibration cycle (unit: days), single-segment CNC program code (length 50–200 characters), and some fields have corresponding units.

## What constraints these characteristics impose on the knowledge base retrieval and recall link
The data sources for this category are scattered, and update trigger conditions are flexible. Retrieval and recall must be associated with context such as the current work order’s tools and machine tool model to avoid recalling mismatched historical data. Mixed structured and unstructured document types require differentiated retrieval weights to improve accuracy. Structured documents include tool lists and process parameters. Unstructured documents include CNC programs and patrol inspection records. The high-frequency update feature requires the retrieval link to support incremental synchronization mechanisms to avoid loading expired inspection and maintenance records. At the same time, maintenance Q&A must be associated with precise fields such as machine tool alarm codes and measurement tool calibration status. The retrieval scope must be limited to equipment documents from the corresponding workshop.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.70–0.85` | Adapts to the density of professional terminology in metal cutting machining, balances retrieval accuracy and coverage, adjust based on actual measurements |
| `limit` | `Top 6–10 entries` | Covers multiple types of documents related to tools, machine tools, and processes for a single work order. Avoids returning excessive redundant content in a single retrieval |
| `searchMode` | `mixedRecall` | Balances keyword matching for structured fields such as CNC program codes and process parameters, and semantic retrieval for maintenance experience recall |
| `usingReRank` | `Enabled` | For mixed document types, uses re-ranking to filter low-relevance patrol inspection records or tool inventory data, improving the accuracy of maintenance Q&A |
| `datasetSearchUsingExtensionQuery` | `Enabled` | Expands synonymous expressions for inspection terminology, such as associating "tool wear" with "tool life degradation", adapting to colloquial questions from maintenance personnel |
| `collectionIds` | `Bind to the machining equipment knowledge base collection for the current workshop` | Limits the retrieval scope to process and inspection documents from the corresponding workshop, avoiding interference from irrelevant data across workshops |

## Three common mistakes
- Symptom: An error occurs in the retrieval link after enabling `usingReRank`, and no re-ranked results are returned. Cause: The associated knowledge base collection for the re-ranking model was not configured correctly, preventing loading of equipment inspection and maintenance documents for metal cutting machining.
- Symptom: The number of returned documents is far lower than the `Top 6–10 entries` set in the `limit` configuration, and maintenance Q&A cannot obtain enough fault handling solutions. Cause: `datasetSearchUsingExtensionQuery` was not enabled, and synonymous expressions for professional terminology were not expanded, resulting in some colloquial questions failing to recall corresponding documents.
- Symptom: Q&A response times out, and inference time and resource usage data are not displayed on the interface. Cause: FastGPT link log collection configuration was not enabled, and the performance statistics function during the inference process was not turned on.

## How to confirm the configuration is complete
- Log in to the FastGPT v4.17.0 knowledge base management interface, check whether `collectionIds` is bound to the machining equipment document collection for the current workshop.
- Submit a simulated inspection and maintenance question, check that the number of retrieved documents falls within the `Top 6–10 entries` range set in the `limit` configuration.
- After enabling `usingReRank`, verify that the re-ranked results prioritize core maintenance-related documents such as tool wear and machine tool alarms.
- View the retrieval link log, confirm that the `similarity` threshold is in effect, filtering out low-relevance non-machining category documents.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
