# Equipment Inspection and Maintenance Q&A for Metal Cutting Machining: Forms and Interaction

This document applies to FastGPT v4.17.0.

## What data for this category looks like
Data sources for this category include product drawings and 3D models, CAPP/CAM systems, machine tool collection data, tool management systems, MES systems, and measurement and inspection tool records. Daily documents cover process routes, operation cards, tool lists, CNC programs, first-piece inspection records, inspection sheets, and measuring tool calibration records.

Data updates trigger with each work order, each machined part, sampling inspection, or tool change. Fields include tool wear amount, machining dimensional tolerances, machine tool operating parameters, and more. Most corresponding units are millimeters, micrometers, and revolutions per minute.

## What constraints these characteristics impose on forms and interactions
Scattered data sources and frequent updates require form interaction to support flexible calls of multiple knowledge base variables, and adapt to field structures of different document types. Multiple types of daily documents correspond to different business scenarios, so the interaction link must automatically switch corresponding form fields based on work order type.

Errors during machining directly lead to workpiece scrap and machine tool downtime, so real-time verification logic must be added to interactions to avoid invalid parameter submissions. Frequent updates per work order or tool change also require form interaction to support quick loading of the latest tool lists, process parameters, and other data, to avoid using outdated business information.

## Three common mistakes
- Knowledge base variable reference failure occurs, returning an error that the field is empty. The cause is that only general knowledge base content is called, and dedicated data sources such as tool lists and operation cards for this category are not associated.
- Prompt for creation failure after uploading CNC program or process card files. The cause is that parsing rules matching the document format are not set, resulting in failure to correctly split large-volume text.
- Unable to continue question-and-answer interaction after the robot sends a push, returning status code 400. The cause is that the context saving logic for multi-turn conversations is not configured, so subsequent inspection and maintenance questions cannot be associated.

## How to confirm configurations are correct
- Submit an inspection form, check whether preset tool models and machining parameter options are automatically loaded, and confirm that the `formInput` and `userSelect` configurations take effect.
- Upload a CNC program file, verify that it can be parsed normally and associated with the question-and-answer knowledge base, and confirm that the document parsing rule configurations are correct.
- Initiate a multi-turn maintenance question-and-answer session, check whether the context retains previous inspection records, and confirm that the conversation logic configurations are correct.
- Trigger an invalid parameter submission scenario, check whether the corresponding error prompt pops up, and confirm that the verification logic configurations are valid.

The values given are common starting points and should be measured against the reader's own samples.
