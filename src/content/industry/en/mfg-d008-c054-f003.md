# Equipment Inspection and Maintenance Q&A for Sheet Metal Cutting and Bending: Multi-turn Dialogue and Prompts

## What Data for This Category Looks Like
The business data for sheet metal cutting and bending comes primarily from CAD/CAM software, order BOMs, sheet metal inventory systems, laser cutting and bending equipment, and workshop MES systems. Daily generated documents include 3D part unfolding drawings, CNC cutting programs, bending process cards, nesting diagrams, first-piece inspection records, and process transfer cards. Fields include sheet thickness (unit: mm), bending compensation, cutting dimensions, bending angle (unit: °), unfolding coefficient, and more. Data update frequency adjusts based on orders, daily model changes, or production tempo. Documents for a single production batch are archived once the order is completed.

## Constraints Imposed by These Characteristics on Multi-turn Dialogue and Prompt Workflows
The multi-variety, small-batch production model means dialogue must be tied to the exclusive process parameters of a specific order to avoid mixing data across orders. The drawing-driven business logic requires prompts to accurately associate with document fields such as unfolding drawings and bending process cards. Generalized parameters cannot be used. Frequently updated data can lead to redundant context, so multi-turn dialogue must limit valid turns to prevent historical information from interfering with current queries. Core calculations such as bending compensation and nesting surplus rely on variable passing within a single dialogue. Missing parameters must be supplemented through multi-turn confirmation.

## How to Set Configurations
| Configuration Item | Recommended Approach | Rationale |
|---|---|---|
| `chatId` | Bind to the device ID corresponding to the current order | Associate historical inspection records and exclusive process parameters for that device, avoid mixing data across orders |
| `messages` | Retain the first 10 turns of dialogue context | Adapt to the multi-step verification process for maintenance and inspection, while controlling context redundancy |
| `variables` | Pass current sheet thickness, bending angle, and device model variables | Accurately match corresponding unfolding coefficients and maintenance manual content, ensure accurate calculation results |

## Three Common Misconfigurations
- The workflow dialogue interface shows empty conversation logs, but the model backend has response logs. The cause is that the `chatId` parameter is not bound in the configuration. This prevents the system from associating context data for the corresponding session, so session logs cannot be generated.
- Reply results do not match actual bending processes, and do not reflect the compensation amount corresponding to sheet thickness. The cause is that current sheet parameters are not passed through `variables`, so the prompt cannot match the corresponding process documents.
- Duplicate or irrelevant maintenance suggestions appear after multi-turn dialogue. The cause is that the `messages` turn count is set above 10, introducing historical redundant information that interferes with current queries.

## How to Confirm Configurations Are Properly Set
- Initiate an inspection query that includes device model and sheet thickness, check whether the reply associates the corresponding sheet unfolding coefficient and bending compensation amount.
- Initiate two consecutive queries. For example, first ask about daily inspection items for a specific model bending machine, then follow up with a question about maintenance steps for the corresponding fault. Verify that the reply continues the device context from the previous query.
