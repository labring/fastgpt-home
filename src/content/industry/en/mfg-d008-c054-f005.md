# Sheet Metal Cutting and Bending Equipment Inspection and Maintenance Q&A: Tool Calling and Plugins

## What this category's data looks like
Data for this category mainly comes from CAD/CAM software, order BOM systems, sheet metal inventory ledgers, laser cutting machine and bending machine device logs, and MES production management systems. Data updates trigger with order generation, daily inventory checks, and each equipment model change. The data includes documents such as sheet metal unfolding drawings, CNC cutting programs, bending process cards, nesting diagrams, first-piece inspection records, and process transfer cards. Fields cover sheet thickness, bending coefficient, hole position tolerance, cutting dimensions, and more. Units are mostly millimeters, kilograms, and square meters. Typical service providers include cabinet and chassis manufacturers, ventilation equipment manufacturers, electrical cabinet manufacturers, and non-standard equipment manufacturers. Businesses follow a multi-variety, small-batch model, and core operations rely on drawing-driven unfolding and bending compensation calculations.

## What constraints these characteristics impose on the "tool calling and plugins" link
Multiple data sources and high-frequency updates require tool calling to support dynamic adaptation to different formats of device logs, process documents, and order data. This avoids calling failures caused by incompatible data formats. The multi-variety, small-batch business model means parameters and document content vary for each call. Tool calling must support flexible context passing and dynamic parameter binding. Core unfolding and bending compensation calculations rely on precise process parameters. Tool calling must directly link to exclusive documents for this category, and cannot use general knowledge base content as a substitute. Errors can result in entire sheet material waste and assembly errors. Tool calling must include failure retry and abnormal alert mechanisms to ensure calling link stability.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | Adapts to multi-type tool calling requirements in sheet metal cutting and bending scenarios, supports automatic selection of device plugin calls or process knowledge base access |
| Workflow/API function-call configuration | `enabled` | Enables explicit function calling format, improves large model recognition accuracy for tool calling instructions |
| Tool calling timeout | `30-60 seconds` | Operations such as sheet metal device data loading and bending coefficient calculation take a long time, so sufficient response time must be reserved |
| Concurrent call limit | `first 2 requests` | Avoids device log conflicts caused by concurrent calls for multiple processes in a single order, adapts to the multi-variety, small-batch business rhythm |
| Workflow shunting rules | Shunt by tool type | Differentiates device inspection data queries and maintenance parameter calls, improves processing efficiency of the calling link |

## Three common mistakes
- Symptom: The large model does not trigger tool calling and only returns general responses. Cause: `toolChoice` is not configured to auto mode, or trigger conditions for tool calling are not clearly specified in the system prompt.
- Symptom: Tool calling returns `none` when concurrent call volume reaches 2-3 times per second. Cause: A reasonable concurrent limit is not set, or current limiting rules for tool calling are not configured, resulting in request backlog and timeout.
- Symptom: The bending coefficient returned by tool calling does not match the actual process card. Cause: Exclusive bending process card and cutting program data sources for this category are not bound, and general knowledge base content is called instead.

## How to confirm the configuration is correct
The following verification steps are based on the system functions of FastGPT v4.17.0.
- Submit a test query containing sheet metal equipment inspection keywords such as "bending coefficient" and "cutting dimensions". Check whether the system log generates a `functionCall` format calling instruction.
- Simulate 2 concurrent requests per second. Check whether the tool calling return result contains valid process parameters, with no null values or timeout errors.
- Switch the BOM data of different orders. Verify whether the tool calling can correctly load sheet metal unfolding drawing and nesting diagram information for the corresponding order.
- Enter the system configuration page. Confirm that the `toolChoice` parameter is set to auto, and the associated device data source and process knowledge base have been checked and enabled.
