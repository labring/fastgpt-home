# Forging and Die Forging Equipment Inspection and Maintenance Q&A: Document Parsing and Chunking

## What This Category of Data Looks Like
This category of data comes from raw material quality certificates, heating furnace systems, press collection data, MES, non-destructive testing instruments, and customer forging drawings. Daily documents include forging process specifications, blanking cards, heating furnace logs, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports. Update frequency is per piece/batch, per furnace run. Document fields include forging ratio, heating temperature range, furnace batch number, forging streamline direction, mold wear amount, etc. Units include degrees Celsius, millimeters, tons, etc.

## How These Characteristics Impact Document Parsing and Chunking
Document sources are scattered and have significant structural differences. Natural segmentation of time-series heating furnace logs and tabular ultrasonic testing reports cannot cover professional field associations. Chunking must match professional field boundaries. High-frequency updated per-piece/furnace-run documents require the parsing link to support batch processing without interruptions. Professional fields such as forging ratio and furnace batch number have close contextual associations. Chunks that are too long increase retrieval redundancy. Chunks that are too short break contextual relationships. Multi-source heterogeneous data has inconsistent formats. Native PDF parsing cannot accurately extract tables and time-series fields. Custom parsing adaptation is required.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `chunkSize` | 800–1200 characters | Forging process specifications and testing reports contain technical terms and long sentences. Settings that are too long lose context, while settings that are too short break associations between linked fields such as heating ranges and forging ratios |
| `chunkSplitter` | By paragraph + custom delimiters (e.g. "Furnace batch number: ", "Forging ratio: ") | Different documents have large structural differences. Natural segmentation of time-series heating logs and tabular testing reports cannot cover professional field associations |
| `customPdfParse` | Enabled | Native parsing cannot accurately extract tabular data from ultrasonic testing reports or time-series fields from heating furnace logs. Custom parsing preserves field associations from original formatting |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Parsing a single large forging process specification takes a long time. This setting avoids interruptions during batch uploads |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | Accommodates the total size of mold life records and multi-batch testing reports archived in batches on workshop floors |
| `chunkSettingMode` | Manual configuration | Different documents have different field densities. Manual adjustment balances contextual completeness and retrieval efficiency |

## Three Common Configuration Mistakes
- Batch uploads of large document sets are interrupted mid-process, and parsing cannot resume after restarting. The cause is failing to adjust `PARSE_FILE_TIMEOUT_SECONDS` to a value suitable for large documents, or setting `UPLOAD_FILE_MAX_SIZE` too small, which causes upload truncation.
- No parsing progress is shown after uploading files via the dialog box, and no background errors are reported. The cause is failing to enable `customPdfParse`. Native parsing cannot recognize table or time-series formats from professional testing reports, causing parsing to stall.
- Retrieval results for equipment maintenance Q&A fail to associate furnace batch numbers with corresponding forging batches. The cause is `chunkSize` being set too small, which breaks the contextual association between furnace batch numbers and corresponding forging parameters.

## How to Verify Correct Configuration
- Upload a single ultrasonic testing report PDF, and check if the parsed text retains table fields for testing locations and defect types.
- Upload 10 batch heating furnace log documents, and verify that parsing completes within `PARSE_FILE_TIMEOUT_SECONDS` without mid-process interruptions.
- Adjust `chunkSize`, then retrieve "Repair plan for forgings from a specific furnace batch number", and confirm that the returned results include complete parameters for the corresponding furnace batch number.
- In FastGPT v4.17.0, check the system upload limits, and confirm that `UPLOAD_FILE_MAX_SIZE` is larger than the maximum document package size archived in a single workshop batch.

The values listed above are common starting points and should be evaluated against the user's own samples.
