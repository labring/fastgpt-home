# Forging and Die Forging Equipment Inspection and Maintenance Q&A: Forms and Interactions

## What this category of data looks like
Data sources for this category include raw material quality certificates, heating furnace systems, press collection data, MES systems, non-destructive testing instruments, and customer forging drawings. Daily documents cover forging process specifications, cutting lists, heating furnace logs, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports. Data updates follow a rhythm of per single piece, per batch, or per furnace run. Fields include forging batch number, heat lot number, mold wear amount (mm), detected defect type, process parameter values (℃, MPa), and corresponding units vary based on document type.

## What constraints these characteristics impose on the forms and interactions link
The update rhythm of per single piece, per batch, or per furnace run requires forms to support single-batch data entry at a time, to avoid redundant bulk operations. Differences in fields from multiple document sources require forms to have flexible custom field configuration capabilities, to adapt to parameter entry for scenarios such as cutting lists and heating furnace logs. The strong correlation between batch number and heat lot number requires forms to include built-in association verification logic, to prevent mismatches between forging batches and material heat numbers, and avoid scrap or other issues in subsequent production links. At the same time, differences in parameter types across different equipment inspection scenarios require forms to support multiple input component types including text, numeric, and enumeration.

## Configuration Settings
These configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Form field grouping | Split by inspection scenario: heating furnace inspection group, press inspection group, mold inspection group | Adapts to the classification logic of multiple daily documents for forging and die forging, and simplifies the entry process |
| `formInput` input component type | Match by field attribute: numeric fields use number input boxes, enumeration fields use drop-down selection boxes | Adapts to the entry format of different parameters, and reduces input error rates |
| `userSelect` knowledge base binding rules | Bind by data source category: raw material data is bound to the raw material quality certificate knowledge base, heating data is bound to the heating furnace log knowledge base | Matches the corresponding relationship between data sources and knowledge bases, and improves recall accuracy |
| Single entry limit | 10 entries per time | Matches the conventional inspection data volume per furnace run or per batch, to avoid overload during single entry |
| Batch association verification | Enable linkage verification between heat lot number and forging batch number | Matches the strong correlation between forging batches and material heat numbers, to prevent data mismatching |
| Result display fields | Display defect type, mold wear amount, process parameter values | Aligns with the core focus content of equipment inspection and maintenance, and shortens the information acquisition path |

## Three Common Configuration Mistakes
- Phenomenon: In the equipment inspection Q&A scenario, relevant results about mold wear are recalled after entering heating furnace parameters. Cause: The `userSelect` knowledge base binding rules are not configured according to data sources, and all inspection data is incorrectly bound to the same knowledge base.
- Phenomenon: An input limit error occurs when entering mold wear amount values in the form. Cause: The numeric field is not configured with the `formInput` corresponding number input component, and a text input box is used by mistake.
- Phenomenon: Entries with mismatched batch numbers and heat lot numbers are not intercepted after form submission. Cause: The batch association verification logic is not enabled, and the linkage verification rule is not configured.

## How to Verify Successful Configuration
- The form configuration interface is accessed. Field grouping is checked against scenarios including heating furnace inspection, press inspection, and mold inspection, and the grouping logic is confirmed to be reasonable.
- For each form field, the input component type is checked against the field attribute, and numeric parameters are confirmed to use numeric input components.
- The knowledge base binding configuration is reviewed, and inspection data from different sources is confirmed to be bound to the corresponding knowledge base.
- Test data is submitted, and the linkage verification between batch number and heat lot number is verified to trigger normally.

Note: The configuration values listed above are common starting points. Adjust them based on your own specific samples and operational needs.
