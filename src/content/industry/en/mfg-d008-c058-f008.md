# Equipment Inspection and Maintenance Q&A for Precast Concrete Components: Document Parsing and Chunking

## What this category of data looks like
Core data for this category originates from BIM detailed design files, steel and concrete batch ledgers, mold table and curing kiln operation records, laboratory test reports, and QR code traceability systems at precast concrete component factories. Daily documents include component detailed drawings, steel bar cutting lists, mold inspection sheets, pouring and vibration records, curing records, demolding and factory inspection reports. Data updates per individual component, each batch of materials, and each curing kiln batch. Fields cover component dimensions, steel bar parameters, curing parameters, test indicators, and additional metrics. Units include millimeters, cubic meters, megapascals, and other relevant units.

## Constraints imposed by these characteristics on document parsing and chunking
Precast concrete component documents fall into two categories: vector engineering drawings and structured ledgers. Splitting engineering drawings requires precise matching to component and embedded part lists. Failure to do so results in broken embedded position information, which disrupts installation verification during equipment inspection. Structured ledgers must be split by individual records. Examples include single steel bar parameters from steel bar cutting lists, and single-batch curing data from curing records. This ensures precise component parameters can be retrieved during maintenance. Data updates frequently and links to individual components or batches. Chunking must avoid mixing across batches to prevent incorrect matching of component information during retrieval. Parsing logic varies significantly across different document types. Targeted adaptation is required to retain critical business fields and support precise Q&A for equipment inspection and maintenance.

## Configuration Settings
Under FastGPT v4.17.0, refer to the following configurations for document parsing and chunking for this category:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Ledgers and drawing text for precast concrete components often contain continuous dimension and parameter information. This range retains complete information for a single batch of components and prevents critical parameters from being broken during splitting. |
| `chunkSplitter` | Custom separator + paragraph splitting | Daily documents include row data from steel bar cutting lists and timestamp entries from curing records. Custom separators support splitting structured files into individual records. |
| `UPLOAD_FILE_MAX_SIZE` | 200 MB | Large BIM detailed drawing files can reach dozens of megabytes. This setting supports complete upload of full lifecycle documents for components. |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large drawing parsing requires extended time. This prevents parsing processes from being interrupted by timeouts. |
| `customPdfParse` | Enabled | Component detailed drawings are structured PDF drawings. Enabling this setting accurately extracts drawing elements and annotation information, avoiding content loss from standard parsing. |

## Three Common Configuration Mistakes
- Issue: When uploading Word files larger than 10 MB, parsing progress stalls for more than 10 minutes before throwing an error. Cause: The `UPLOAD_FILE_MAX_SIZE` and `PARSE_FILE_TIMEOUT_SECONDS` parameters were not adjusted. Default settings cannot meet the parsing requirements for large component documents.
- Issue: Imported Excel steel bar cutting lists are merged into a single chunk, and cannot be split by individual steel bar parameters. Cause: The `chunkSplitter` was not configured to use custom separator splitting, or the correct row separator was not set.
- Issue: Some accurately matched component test records are not retrieved, but normal retrieval works after creating a new knowledge base. Cause: `customPdfParse` was not enabled during the initial import, or chunking parameters were configured incorrectly, leading to loss of critical component number fields during chunking.

## How to Verify Correct Configuration
- Upload a single 150 MB BIM detailed drawing file, and confirm parsing completes within 10 minutes with no timeout errors.
- Import an Excel file for a steel bar cutting list, and check that chunking results assign one chunk per individual steel bar parameter with no cross-row merging.
- Enter an inspection question for the corresponding component model, and verify that the knowledge base retrieves precise content from the matching chunk.
- View the knowledge base settings page, and confirm that parameters including `chunkSize` and `chunkSplitter` have been set according to the provided guidelines.

The values provided are common starting points and should be measured against the reader's own samples.
