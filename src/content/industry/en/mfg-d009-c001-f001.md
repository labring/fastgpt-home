# Quality Problem Traceability and Defect Analysis for PCB Manufacturing: HTTP Interfaces and External Systems
This document is written based on FastGPT v4.17.0.

## What this category's data looks like
Data for this category comes from multiple sources. These include Gerber files, drill files, and BOM lists provided by customers. They also include factory CAM systems, production equipment parameters, bath solution test records, AOI inspection reports, electrical test reports, and laboratory sectioning reports. Daily documents cover engineering production instructions, Gerber analysis records, drilling and lamination parameters, and chemical analysis reports. Data updates happen per production batch and per shift. Key parameters are collected continuously. Data fields include drilling aperture, lamination thickness, AOI defect points, and electrical test continuity values. Units include millimeters, microns, and ohms.

## What constraints these characteristics impose on HTTP interfaces and external systems
Data sources are scattered. Update frequency is high. HTTP interfaces must support batch pulling and real-time synchronization across multiple data sources. Interfaces must adapt to inspection reports and parameter files in formats like Gerber and CSV. Production batch-level bulk data requires paginated pulling. This avoids overload from single large transmissions. Continuously collected equipment parameters need low-latency response capabilities. Interfaces must also be compatible with different data field formats from multiple devices. Quality traceability requires linking full-chain data. Interfaces must support association queries via key fields such as production batch number and work order ID. This ensures consistency across cross-system data.

## How to configure the settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Generate a dedicated token and configure it | Ensure permission security for external system calls, comply with factory data confidentiality requirements |
| `variables` | Bind production batch number and work order ID as global variables | Used to associate multi-source PCB manufacturing data, enable accurate quality traceability |
| `responseData` | Extract core fields such as defect points and abnormal parameter values | Filter redundant data, improve processing efficiency for defect analysis |
| Interface timeout period | 300–600 seconds | Adapt to the duration of batch pulling production batch data, avoid timeout interruptions |
| Batch pull limit | First 100 entries | Adapt to the data scale per shift or per batch, prevent request overload |
| Data format verification | Configure according to Gerber and CSV standards | Adapt to the daily document formats of this category, ensure data validity |

## Three common mistakes
- Symptom: After calling the HTTP interface, the returned content of `responseData` does not appear in the conversation output. Cause: The output variable of `responseData` is not correctly bound in the node configuration, resulting in data not being transferred to the conversation link.
- Symptom: The interface request returns a 401 status code, and production data cannot be pulled. Cause: The `Authorization` token is configured incorrectly or has expired, and the permission configuration of the factory system has not been updated synchronously.
- Symptom: The number of returned results when pulling data in batches does not match the actual production batch data volume. Cause: A reasonable batch pull threshold is not set, or pagination parameters are not handled correctly, resulting in only partial data being pulled.

## How to confirm the configuration is correct
- Initiate an HTTP request simulating a production batch, check whether `responseData` returns expected AOI report and electrical test data fields.
- Check the validity period of the `Authorization` token, confirm that it has not expired and the permission matches the access scope of the factory system.
- Call the interface to test the production batch number parameter bound by `variables`, verify that full-link data of the corresponding batch can be associated.
- Simulate a request with abnormal data format, confirm that the system triggers a format verification prompt, and verify that the configuration takes effect.

The values provided are common starting points and should be evaluated against the reader's own samples.
