# Quality Problem Traceability and Defect Analysis for SMT Mounting and Electronic Assembly: Multi-turn Dialogue and Prompt Engineering

## What the Data for This Category Looks Like
SMT mounting and electronic assembly business data includes multiple structured and semi-structured files. These files cover BOMs and coordinate files, line change lists, stencil and reflow oven temperature records, first article inspection reports, SPI/AOI test reports, maintenance records, and traceability labels.
Data sources include BOMs, Gerber files, and coordinate files delivered by customers. Additional sources are MES systems, solder paste and component batch ledgers, mounters, SPI/AOI test equipment, and reflow oven temperature collection data.
Data updates are completed in real time as work orders are executed and line changes are made. Single work order data fields include component designators, part numbers, batch numbers, test coordinates, reflow oven temperature curve parameters, and other relevant fields.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
Data for this category is scattered and updated in real time. Multi-turn dialogue must quickly associate batch, coordinate, and test data across different systems. This avoids information silos between data sources.
There are many document types. Prompts must adapt to the field formats of different files such as BOMs, SPI reports, and reflow oven temperature curves. Prompts must accurately extract key information such as component designators and defect locations.
Single work order data is dynamically generated as work orders are executed. Multi-turn dialogue must support loading historical data for a specified work order on demand. This avoids loading full historical context for non-current work orders, preventing information overload.
Quality traceability requires full-link information to be traced layer by layer. The dialogue flow must support progressive queries by traceability labels and batch numbers. This ensures the context of each dialogue focuses on the current traceability target.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Maximum Context Length | 8000–12000 characters | Matches the context processing limit of FastGPT v4.17.0, and aligns with the total character count of multiple documents for a single work order |
| Dialogue Record Retention Period | 30–180 days | Aligns with work order delivery and quality traceability cycle requirements for EMS facilities |
| `chatId` Binding Rule | Bind to current work order ID | Ensures multi-turn dialogue context only associates with current work order data, avoiding cross-work order information confusion |
| `messages` Context Truncation | Retain the most recent 10 dialogue turns | Focuses on the current traceability process, reducing interference from redundant information |
| `variables` Preset Fields | Bind to current work order’s component designators, batch numbers, and traceability labels | Quickly access category-specific data fields, simplifying prompt writing |
| Single Search Recall Count | Top 5–8 results | Aligns with the number of defects per page in SMT test reports, avoiding excessive invalid information |

## Three Common Misconfigurations
- Symptom: Dialogue response time exceeds 10 seconds, and the interface shows a loading timeout. Cause: `chatId` is not bound by work order ID, and full historical context is loaded for each dialogue, triggering context overload.
- Symptom: Unable to query historical dialogue records for a specified work order. Cause: Dialogue record retention period is set shorter than the current business traceability cycle, causing dialogue logs for early work orders to be automatically cleared.
- Symptom: Incorrect component designator or batch matching appears in analysis results. Cause: `variables` are not bound to the current work order’s dedicated fields, and the prompt calls part numbers or batch information from other work orders.

## How to Confirm Proper Configuration
- Initiate a multi-turn dialogue for a single work order. Check that the context only includes relevant documents and historical dialogue for that work order, with no data from other work orders.
- View the dialogue record management interface. Confirm that the dialogue log retention period for the specified work order meets current business traceability requirements.
- Enter a query containing component designators and batch numbers. Check that the prompt correctly extracts information from the corresponding fields, with no cross-work order data included.
- Simulate multiple consecutive dialogues. Check that response times meet expected business usage requirements, with no unexpected timeouts.
