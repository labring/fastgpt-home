# Quality Problem Traceability and Defect Analysis for SMT Mounting and Electronic Assembly: Tool Calling and Plugins

## What the data for this category looks like
Quality traceability data for SMT mounting and electronic assembly mainly comes from BOM and coordinate files provided by customers, line change records, stencil records, MES systems, mounters, SPI/AOI inspection equipment, reflow oven temperature records, traceability labels and maintenance archives. Data is updated per work order and each line change; some inspection data is synced in real time. Single work order data includes fields such as part number, reference designator, substitute part, component batch number, mounting coordinates, defect type, temperature curve, etc. Coordinate unit is millimeters, furnace temperature unit is degrees Celsius, and batch number uses string format.

## What constraints these characteristics impose on the tool calling and plugins workflow
Data for this category is scattered across multiple systems and devices. Tool calling must connect to multiple data source plugins to pull full-process quality data. Data update frequency is short and real-time requirements are high. Tool calling must support short-cycle triggering to avoid inaccurate traceability results caused by data lag. Document fields have clear format and unit requirements. The parameter extraction step of tool calling must match specific fields such as part numbers and coordinates, and cannot be handled generically. The core link of quality traceability is verifying part numbers and defect data. Tool calling must automatically complete field comparisons across multiple documents to reduce manual operation time.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Adapts to the automatic calling needs of SMT multi-data source plugins. FastGPT v4.17.0 supports full-function configuration of this parameter |
| `functionCall` | Enable mandatory parameter validation | Ensure that extracted fields such as part numbers and coordinates meet the format and unit requirements of SMT documents |
| Single tool call timeout | 60–120 seconds | Covers the average time required to pull single work order data from MES and SPI/AOI equipment |
| Tool call return result limit | Top 10 entries | Matches the number of defect records and data entries per work order, avoids redundant information interfering with analysis |
| User input confirmation toggle | Enable | Aligns with the quality review process for SMT work orders, prevents accidental plugin calls for batch operations |
| Context window size | 8000–12000 token | Accommodates the complete content of multiple documents such as BOM and furnace temperature records, supports cross-document comparison and analysis |

## Three common misconfigurations
- Phenomenon: Tool calls return empty part number and coordinate fields. Cause: Mandatory parameter validation for `functionCall` is not enabled, and extracted fields do not match the format requirements of SMT documents.
- Phenomenon: Tool call timeout error occurs (status code 504). Cause: The set timeout period is too short, and does not cover the total time required to pull data from multiple devices.
- Phenomenon: No user input confirmation popup appears after plugin execution. Cause: The user input confirmation toggle is not enabled, and plugin calls are executed directly, which does not comply with the review process requirements for SMT work orders.

## How to confirm proper configuration
- Upload a test BOM file and SPI inspection report, trigger tool calling, and check whether the returned results include expected fields such as part numbers, reference designators, and defect coordinates.
- Simulate a single tool call, check whether the system return time is within the set timeout range, and confirm there are no timeout errors.
- Trigger the plugin call process, check whether a user input confirmation popup appears, and confirm that the review link is active.
- Test the scenario of sequential calls across multiple plugins, check whether data can be pulled from the MES system and mounter in sequence, and return complete work order traceability information.

The values provided are common starting points and should be evaluated against the reader's own samples.
