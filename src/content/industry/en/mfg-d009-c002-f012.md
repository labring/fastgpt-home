# Quality Issue Traceability and Defect Analysis for SMT Mounting and Electronic Assembly: Deployment and Upgrade

## Data profile for this category
This category’s data covers the entire electronic manufacturing process. Data sources include BOM and coordinate files provided by customers, line change lists, stencil and reflow oven temperature records, and real-time operational data from MES systems, mounting machines, SPI/AOI inspection equipment, and reflow ovens. Daily documents include first article confirmation reports, maintenance records, and product traceability labels. Fields include part number, reference designator, component batch, furnace temperature parameters, and defect type, among others. Data updates occur per work order, each line change, and in real time. Single work order data volume varies dynamically based on component count and number of inspection items.

## Constraints during deployment and upgrade
Real-time and high-frequency data updates require highly available storage and cache configurations during deployment, to avoid data query delays that reduce traceability efficiency. Multi-source heterogeneous data formats require adaptation to different import interfaces. A storage separation strategy for structured and unstructured data must be planned in advance. Frequent line change operations and work order switches require flexible permission controls, to ensure data isolation across production lines. Large-volume reflow oven temperature curves and stencil scan files require a storage service that supports large file uploads, to prevent upload failures. Accurate part number and reference designator matching requires database index optimization, to improve retrieval speed.

## How to configure settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `DB_MAX_LINK` | `100–200 concurrent connections` | Adapts to multi-source real-time data access and high-frequency query requirements, prevents database connection exhaustion |
| `REDIS_URL` | `Cloud-hosted Redis instance with 2 GB or more memory` | Caches real-time line change records and SPI inspection data to reduce repeated query overhead |
| `STORAGE_S3_ENDPOINT` | `Endpoint address compatible with industrial-grade object storage` | Supports segmented upload and storage of large-volume reflow oven temperature curves and stencil scan files |
| `MONGODB_URI` | `Configure replica set connection string` | Enables highly available storage of work order data and traceability labels, supports fast retrieval by work order ID |
| `PG_URL` | `Configure PostgreSQL connection address with index optimization` | Supports stable operation of structured queries such as BOM and reference designator matching |
| `FILE_TOKEN_KEY` | `Custom random string of 32 characters or more` | Securely generates download tokens for traceable files, prevents unauthorized access |

## Three common configuration mistakes
- Connection timeout errors appear when configuring model channels during local deployment. The cause is incorrect network port mapping for the local model, and exposed ports for the corresponding container are not opened.
- The docker-deployed reranker model cannot be called normally, and the interface prompts an invalid request address. The cause is incorrect mapping of the container's internal request address to the host machine address, and the correct custom request address is not filled in FastGPT.
- When configuring multiple table webhooks, the interface prompts that the batch synchronization function is unauthorized. The cause is that an access key that meets permission requirements is not configured, and the enterprise-level webhook concurrent processing capability of FastGPT v4.17.0 or higher is not enabled.

## How to confirm correct configuration
- Run a database connection test to verify the connection status of `MONGODB_URI` and `PG_URL`, and check system logs for connection timeout or authentication failures.
- Upload a test BOM file to verify the file upload and download functions of `STORAGE_S3_ENDPOINT`, and confirm that the generated file links can be accessed normally.
- Trigger a simulated SPI inspection data import, check the cache update logs of `REDIS_URL`, and confirm that the cache hit and data update processes are operating normally.
- Configure a custom reranker request address, run test cases to verify whether the model returns results normally, and confirm that container ports are opened and network connectivity is good.

The values provided are common starting points and should be measured against the reader's own samples.
