# Quality Problem Traceability and Defect Analysis for Warehousing, Lot Tracking and In-Plant Logistics: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
Data sources for this category include ERP/WMS systems, barcode or RFID equipment, procurement and work order records, storage location information, AGV or conveyor system logs, and weighing data. Update cycles cover real-time, daily synchronization, and monthly inventory cycles. Daily documents include receiving slips, putaway slips, material picking and return slips, stock transfer slips, inventory lists, lot ledgers, first-in first-out and expiration date records. Fields include material code, lot number, storage location code, inspection status, expiration date, material weight, and others. Units include pieces, kilograms, days, storage location numbers, and others.

## Constraints These Characteristics Impose on Multi-turn Dialogue and Prompt Engineering
Data sources for warehousing, lot tracking and in-plant logistics are scattered, and update cycles vary significantly. Multi-turn dialogue must load context categorized by data type, to avoid mixing real-time AGV operation logs with static monthly inventory data. Lot and storage location fields are closely related and exist in large quantities. Prompt engineering must clearly define the scope of retrieved fields to prevent irrelevant material records from being retrieved. Traceability of inventory-actual discrepancies and obsolete materials requires retaining historical query records. `variables` can be used to pass the current query's lot number or storage location code to accurately match corresponding documents. Queries for real-time data must control context length to avoid response delays caused by session overload.

## How to Configure
This configuration is based on the functional logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Context window size | First 20 dialogues + retrieval data from the past 1 hour | Matches the real-time update rhythm of warehousing data, filters expired redundant information |
| `variables` bound parameters | Automatically pass the current query's lot number and storage location code | Accurately locate receiving, putaway and inspection records for corresponding materials |
| Maximum context length | 800–1200 characters | Adapts to the average length of single warehousing documents, avoids content overload |
| Session timeout period | 600 seconds | Covers the batch query cycle of monthly inventory, prevents session disconnection mid-process |
| Knowledge base retrieval scope | Bind storage location fields associated with the current work order | Narrow retrieval scope, reduce loading of irrelevant data across work orders |
| Question optimization switch | Enabled | Simplifies non-standard material names in user input to match standardized codes in the system |

## Three Common Configuration Mistakes
- The knowledge base retrieval scope is not bound to the storage location and lot fields associated with the current work order, resulting in redundant cross-work order material data in retrieval results. This occurs because the prompt engineering does not limit the document fields and associated scope for retrieval, causing irrelevant data to be mixed into the context.
- After embedding the dialogue page in a mini-program, the page's top title is automatically modified and cannot be restored. This occurs because the embedding configuration does not disable the default title override logic, and the system calls the global default title template.
- The context and reply content output by the AI node cannot be distinguished, leading to subsequent dialogue context pollution. This occurs because dialogue history is not stored in accordance with the `messages` format specification, confusing the structure of user input and AI replies.

## How to Verify Correct Configuration
- Initiate a lot traceability query, check that retrieval results only include storage location and lot data associated with the current work order, with no redundant cross-work order records.
- Check whether the session's `chatId` remains consistent after page refresh, confirming that context is not lost due to session reset.
- Test modifying the embedding page's title parameter, confirm that the page title is not automatically overwritten by the system.
- Trigger a batch inventory query, confirm that the session timeout period is greater than 600 seconds, with no mid-process disconnections occurring.
