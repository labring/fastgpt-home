# Quality Problem Traceability and Defect Analysis for Warehousing, Lot Tracking and In-Plant Logistics: Document Parsing and Chunking

## What data for this category looks like
Typical data for this category usually comes from ERP, WMS systems, barcode/RFID devices, purchase work orders, storage location management, AGV transport systems and weighing equipment. Daily generated documents usually include receiving slips, putaway slips, material picking and return slips, warehouse transfer slips, inventory checklists, lot ledgers and expiration date records. These documents contain fields such as material code, lot number, storage location code, expiration date and quantity. Units include pieces, kilograms, number of pallets and others. Data update frequencies usually cover three scenarios: real-time (such as AGV position data), daily (such as material picking and return records), and monthly inventory checks.

## What constraints do these characteristics impose on the document parsing and chunking link
Warehousing documents usually have both structured form and ledger formats. Key information such as lot numbers and expiration dates needs to retain relevance across paragraphs and even pages, and must not be arbitrarily split during chunking. Documents with different update frequencies correspond to different parsing requirements. Real-time data usually requires faster parsing responses, while monthly inventory checklists may have large file sizes. At the same time, documents from multiple sources have obvious format differences. PDFs exported from ERP may have structured encryption, and ordinary parsing modes cannot accurately extract fields. These characteristics require chunking configurations to balance information integrity, parsing efficiency and format adaptability.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapt to the field density of warehousing documents, avoid splitting key traceability information such as lot numbers and expiration dates |
| `chunkSplitter` | Chunk by paragraph + semantics | Match the structured paragraph structure of material picking/return slips and inventory checklists, retain the relevance between fields |
| `customPdfParse` | Enable structured parsing mode | Adapt to PDF forms exported from ERP, accurately extract core fields such as material codes and storage location codes |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Cover the full parsing time of large-volume documents such as monthly inventory checklists and lot ledgers |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | Adapt to batch-uploaded warehousing document packages, avoid being blocked due to oversized files |
| `chunkSettingMode` | Manual configuration | Adjust chunking parameters for different document types such as receiving slips and inventory checklists, meet the information integrity requirements of traceability scenarios |

## Three common misconfigurations
- A chunk preview prompt indicates that the file content cannot be read. The cause is that the `customPdfParse` configuration is not enabled, so structured or encrypted PDF forms exported from ERP cannot be parsed.
- The local deployment environment fails to return complex formulas normally. The cause is that the deployed marker version is incompatible with FastGPT v4.17.0, and the corresponding OCR dependency package is not matched.
- Feishu knowledge base cannot synchronize PPT and PDF documents. The cause is that the access permission scope of Feishu documents is not configured, and the synchronization switch for the corresponding file types is not enabled.

## How to confirm the configuration is properly set
- Upload a typical monthly inventory checklist PDF, check whether the chunk preview retains the integrity of key fields such as lot numbers and storage location codes, and ensure that no key information is split into different chunks.
- View the parsing task log, confirm that the timeout error corresponding to `PARSE_FILE_TIMEOUT_SECONDS` is not triggered, and match the actual parsing time of the document.
- Test uploading two different types of warehousing documents: receiving slips and warehouse transfer slips, verify whether the chunking logic of `chunkSplitter` adapts to the paragraph structure of the corresponding documents.
- Check the synchronization configuration of the Feishu knowledge base, confirm that the synchronization permission for PPT and PDF files has been enabled, and verify that the synchronization task is completed normally and the file content can be parsed correctly.
