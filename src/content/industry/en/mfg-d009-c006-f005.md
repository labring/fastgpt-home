# Quality Problem Traceability and Defect Analysis for Photovoltaic Module Encapsulation: Tool Calling and Plugins

## What the data for this category looks like
Data from the photovoltaic module encapsulation link covers multiple types of sources, including battery sheet grading data, glass adhesive film backplane batch records, MES systems, string welding and lamination equipment operation logs, crack images generated by EL testers, IV test reports, insulation pressure resistance records and packaging lists.
Each module generates independent test and process data. Each batch of materials generates batch summary records.
Document structures include structured batch fields such as battery sheet current gear, lamination temperature and power value, as well as unstructured image files and report files.
Fields are attached with corresponding units: current uses amperes, power uses watts, and lamination temperature uses degrees Celsius.

## What constraints these characteristics impose on the "tool calling and plugins" workflow
Dispersed and diverse data sources require tool calling plugins to support multi-data source binding and parsing of different data formats, including structured database queries and unstructured image analysis.
High-frequency real-time data updates require tool calling contexts to remain timely, and avoid using expired batch or process data.
Multi-type documents and fields require tool calling parameters to accurately match business fields such as current gear and power value, to prevent cross-field confusion.
Batch component traceability requirements require tool calling to limit the number of items returned in a single request, to avoid context window overflow.
Correlation analysis of crack images and power data requires plugins to support cross-data source data linkage queries.

## How to set the configuration
This document applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `toolChoice` | `auto` | Adapts to multi-type tool calling scenarios, automatically matches different business needs such as material batch query and EL image analysis |
| `functionCall` | `enabled` | Forces the model to call tools to obtain real-time business data, and avoid generating non-real traceability results |
| Single tool call timeout | `300–600 seconds` | Some device data pulling and EL crack image analysis take a long time, and timeout will cause task interruption |
| Tool call return result limit | `Top 20 entries` | Limits returned data entries, and avoids context window overflow affecting analysis logic |
| Plugin data source binding | Bind by business module (string welding data binds string welding equipment data source, IV data binds tester data source) | Accurately matches data sources for corresponding business links, and reduces errors from cross-data source queries |
| Context window limit | `8000–12000 token` | Accommodates multi-batch material records and tool return results, and ensures complete logic for quality traceability |

## Three common errors
- Phenomenon: After tool calling is completed in a workflow, downstream nodes cannot obtain returned structured data fields. Cause: The result serialization switch is not enabled in tool configuration, causing returned raw data to not be standardized into a readable format.
- Phenomenon: When using knowledge base associated tool calling, the generated answer deviates from the current quality traceability question, and returns packaging defect analysis content from other categories. Cause: The data source range of tool calling is not limited in the system prompt, causing the model to call irrelevant plugin data sources.
- Phenomenon: Locally privately deployed models return connection errors when calling MCP MySQL plugins, while the same model deployed online can call normally. Cause: The locally deployed model is not configured with the network whitelist for the internal MES system, and cannot access private data source plugins.

## How to confirm the configuration is correct
- Initiate a query matching battery sheet current gear, and check that the data source returned in the tool call log matches the preset MES data source.
- Trigger tool calling for EL crack analysis, and confirm that the returned result includes analysis fields for EL images and power data from IV test reports.
- Simulate a batch component traceability query, and confirm that the number of items returned by tool calling conforms to the preset upper limit rule.
- Switch to the locally privately deployed model, test MCP plugin calling, and confirm that network connection and permission configuration are normal.

The values provided are common starting points and should be measured against the reader's own samples.
