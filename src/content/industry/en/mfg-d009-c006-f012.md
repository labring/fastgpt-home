# Quality Problem Traceability and Defect Analysis for Photovoltaic Module Encapsulation: Deployment and Upgrade

## What this category of data looks like
Data sources for quality traceability in photovoltaic module encapsulation include battery cell grading records, adhesive film and backsheet batch ledgers, factory MES systems, string welding and lamination equipment operation logs, EL defect detection images, IV power test reports, insulation withstand voltage records, and packing lists.
Data is updated such that independent test and process data is generated for each module, and batch ledgers are synchronized for each batch of raw materials.
Daily documents include structured process parameter tables and unstructured EL/IV test files. Fields cover battery cell current gear, lamination temperature and pressure parameters, crack location coordinates, power test values, and more. Association must be established by batch and component serial number.

## What constraints these characteristics impose during deployment and upgrade
Based on the deployment logic of FastGPT v4.17.0, the data characteristics of this category impose the following constraints:
Multi-source and frequently updated data requires adaptation to multiple types of data source connections during deployment, to ensure that structured and unstructured data for each module can be quickly written and retrieved.
High-frequency single-component data updates create pressure for frequent database connection creation and release. Connection pool parameters must be properly configured to avoid resource exhaustion.
Multiple document formats require the system to support diverse file storage and parsing, and upgrades must be compatible with newly added test file formats.
Additionally, accurate association between battery cell current gears and material batches is core to quality analysis. Database indexing and association logic must be accurate to avoid errors in traceability results.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `DB_MAX_LINK` | 12–20 connections | Adapt to concurrent demands of high-frequency writing per module, avoid database connection exhaustion |
| `MONGODB_URI` | Sharded cluster storage address | Support batch storage and rapid retrieval of unstructured files such as EL images and IV test reports |
| `PG_URL` | Relational database connection address | Ensure accurate associated queries for battery cell current gears, material batches, and component serial numbers |
| `REDIS_URL` | Local cache service address | Reduce database load from high-frequency queries, accelerate reading of batch association results |
| `ROOT_KEY` | Calibrate based on actual measurements | Manage system initialization permissions, adapt to security configuration requirements for local deployments |

## Three common mistakes
- A 401 status code is returned during login, prompting a permission verification failure. The cause is that the `ROOT_KEY` parameter is not properly configured in docker-compose.yml, or the initialization key set during deployment does not match the value entered in the interface.
- A 504 timeout error occurs during multi-user concurrent access. The symptom is that quality traceability results fail to load. The cause is that resource allocation is not adjusted based on concurrent access volume, and video memory and computing resources are not configured with concurrency thresholds calibrated via actual measurements.
- Local deployed models cannot be connected. The symptom is empty retrieval results. The cause is that the model connection address is not correctly specified in system configuration, or access permissions for local ports are not opened.

## How to confirm the configuration is complete
- Run the docker-compose ps command to confirm that all service containers are in a running state, with no abnormal exit records.
- Upload one EL test image and the corresponding batch material ledger, and verify that the system can successfully associate and display associated data such as battery cell current gears and lamination process parameters.
- Initiate 3–5 concurrent quality traceability queries, confirm that response times meet expectations, with no continuous timeouts.
- Log in to the system backend, verify that the `ROOT_KEY` configuration item has taken effect correctly, with no permission-related error prompts.

The values provided are common starting points and should be measured against the reader's own samples.
