# Quality Issue Traceability and Defect Analysis for Cosmetics Manufacturing: Document Parsing and Chunking

## What the data for this industry looks like
Data for this category comes from daily production and compliance documents of skincare, haircare, makeup, and special cosmetics manufacturers. Documents include formulation work orders, weighing and batching records, emulsification or filling records, cleaning and sanitation records, semi-finished and finished product inspection reports, and label review files. Data sources include registered and filed formulations, raw material safety materials, production equipment, ERP/MES systems, laboratory data, and packaging material version records. Updates occur per production batch or each line change. Most documents are structured forms and time-stamped logs, with fields including raw material names, restricted substance content, process parameters, batch numbers, and packaging material claims.

## What constraints these characteristics impose on the document parsing and chunking workflow
Documents are generated per production batch or line change, and must be linked to registered compliance data. Parsing and chunking must retain the binding relationship between batch numbers and corresponding process and inspection records. This prevents cross-batch data confusion. Documents include highly regulated fields such as raw material restricted substances and process parameters. Chunking operations must not truncate key field content. Doing so could trigger compliance risks. Update frequency is high, and single-batch document volume increases with production steps. Parsing must adapt to the splitting logic for multi-page structured forms and time-stamped logs. It must also control the time and capacity limits for a single parsing job.

## How to set up the configuration
This page is written based on FastGPT v4.17.0 configuration guidelines.

| Configuration Item | Recommended Setting | Rationale |
|---|---|---|
| `chunkSize` | `800–1200 characters` | Must retain complete compliance fields such as formulations and raw material restricted substances to avoid truncating critical information |
| `chunkSplitter` | Split by paragraph + batch number | Documents are generated per production batch, so batch associations with corresponding process records must be preserved |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300–600 seconds` | Associated documents for a single production batch include multi-page process records and inspection data, so sufficient parsing time is required |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | Total capacity of associated documents for a single production batch typically does not exceed this value, enabling combined upload of multi-step documents |
| `customPdfParse` | Enable structured parsing mode | Most documents are standardized forms, and structured parsing preserves field integrity and hierarchical relationships |
| `chunkSettingMode` | Manual configuration | Compliance fields for cosmetics manufacturing documents require adjusted chunking rules, so automatic chunking must be avoided to prevent truncation of critical content |

## Three common configuration errors
- Uploaded documents show request failure and parsing timeout. The cause is failure to adjust the `PARSE_FILE_TIMEOUT_SECONDS` parameter. Parsing time for multi-page documents from a single production batch exceeds the default threshold.
- Some fields are missing after uploading a table dataset to the knowledge base. The cause is failure to enable the structured parsing mode for `customPdfParse`. Compliance fields such as raw material restricted substances and batch numbers in tables are incorrectly split or omitted.
- Chunking logic is inconsistent after exporting and importing the knowledge base. The cause is failure to unify the `chunkSettingMode` configuration. The new server does not use the manual chunking rules from the original server, leading to chunking results that do not match the original knowledge base.

## How to confirm configuration correctness
- Upload the formulation work order for a single production batch. Verify the parsed result includes the complete raw material list, restricted substance labels, and batch number.
- Upload an emulsification record document with multiple pages. Verify parsed chunks are split by single page or single batch, without truncating critical process parameters.
- Upload a document of maximum single-file capacity. Confirm parsing does not trigger a timeout error, and that parsing time stays within the threshold set by `PARSE_FILE_TIMEOUT_SECONDS`.
- Export the configuration file of the current knowledge base. Import it to a test environment. Verify chunking results match the original environment.

The values provided are common starting points and should be evaluated against local samples.
