# Quality Issue Traceability and Defect Analysis for Pharmaceutical Preparations Production: Workflow Orchestration

## What the Data for This Category Looks Like
Quality traceability data for pharmaceutical preparations production comes from approved formulation processes, material batches, MES/electronic batch records, equipment and environmental monitoring, LIMS and quality management systems. Data is updated per production batch, each key process step and monitoring plan. Daily documents include master production files, batch production records, batch packaging records, cleaning records, inspection records, deviation/CAPA/change documents and batch release review forms. Data fields include material batch numbers, process parameter values, test results, deviation descriptions and more. Corresponding units include ℃, hours, batch number strings and more.

## What Constraints These Characteristics Impose on Workflow Orchestration
Since data is updated per batch and key steps, workflows must bind batch-level variables to ensure only production and quality data for the corresponding batch is retrieved. Multi-source heterogeneous data sources require workflows to configure association logic for multiple data sources to avoid mixing cross-batch data. Under GMP compliance requirements, workflows must strictly limit document retrieval scope, only calling compliant documents for the current batch. Workflows must also set exception branches for risk scenarios such as batch release failure and data integrity defects. Additionally, real-time data update requirements mean workflow trigger timing must match production nodes to ensure traceability results are synchronized with the production process.

## How to Set Configurations
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Variable Binding | Bind the batch number and material batch number fields in `variables` | Data is generated and updated per batch, requiring precise association with production and quality data for the corresponding batch |
| Node Trigger Timing | Trigger based on the production step event bound to `nodeId` | Must match production process nodes to ensure data calls are synchronized with actual production |
| Knowledge Base Call Scope | Limit retrieval to batch records and test reports for the current batch | Meets the rigorous requirements of data traceability under GMP, avoiding interference from unrelated documents |
| Single Execution Timeout | 300–600 seconds | Covers the conventional time interval for batch record review and deviation summary |
| Branch Execution Logic | Trigger corresponding branches based on the traceability result status | Differentiate processing paths for normal traceability and abnormal deviations |
| Exception Handling Configuration | Trigger CAPA process nodes and push alerts | Corresponds to the business requirement for rapid response after errors occur |

## Three Common Mistakes
- Phenomenon: Returns a null value when calling a knowledge base assistant nested in a workflow via API; Cause: The correct batch number parameter was not passed in `variables`, causing the knowledge base to fail to match documents for the corresponding batch.
- Phenomenon: A `quote type error` prompt appears when referencing knowledge base variables; Cause: The batch number was not passed as a string type to `variables` per requirements, so the format does not comply with system validation rules.
- Phenomenon: The tool call module prints AI replies and executes the next-level branch at the same time; Cause: No conditional judgment logic for branch triggering was configured, causing multiple paths to execute in parallel.

## How to Confirm the Configuration Is Correct
- Pass a test batch number, check if the workflow can retrieve documents such as batch production records and test reports for the corresponding batch.
- Simulate an abnormal deviation scenario to verify whether the workflow triggers the preset exception handling branch.
- Call the FastGPT v4.17.0 API, pass the `variables` parameter, and confirm that the returned result is not empty.
- Adjust the single execution timeout setting to verify that the workflow completes execution within the preset duration.
