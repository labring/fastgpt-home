# Quality Problem Traceability and Defect Analysis for Medical Device Assembly and Clean Production: Multi-turn Dialogue and Prompts

## What Data This Category Includes
The core data for this category comes from design history files, device and material batch ledgers, MES systems, clean environment monitoring equipment, sterilization equipment, inspection and calibration systems, and adverse event traceability materials. Daily documents include production process specifications, batch production records, clean zone operation records, sterilization batch records, inspection reports, software version records, and other materials, with fields including batch number, sterilization parameters, clean zone temperature and humidity, unique material identifiers, inspection results, and more. The data update frequency is once per batch or per product unit, and clean environment monitoring data is updated regularly according to a set plan.

## Constraints Imposed on Multi-turn Dialogue and Prompts
Independent data across multiple batches or product units requires that dialogue context be strictly bound to the current production batch to avoid mixing data across batches. Mixed retrieval across multiple types of documents requires prompts to clearly distinguish the retrieval priority of different documents, prioritizing matching batch records and inspection reports directly related to adverse phenomena. Frequently updated data requires a knowledge base synchronization mechanism adapted to the batch-level update rhythm, while multi-turn dialogue needs to limit the number of historical turns to prevent redundant old data from interfering with current analysis. Professional terminology and compliance requirements require prompts to strengthen the rigor of traceability logic, avoiding vague expressions.

## Configuration Settings
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Maximum Context Length | 8000–12000 characters | Covers the total text volume of core documents for a single batch, avoiding truncation of critical traceability data |
| Single Search Limit | Top 6 entries | Covers core document types such as production records and inspection reports for a single batch, avoiding interference from redundant information |
| Retrieval Matching Threshold | 0.75–0.85 | Filters low-relevance non-batch documents, focusing on core traceability data |
| Historical Turn Limit | Top 3 turns | Reduces interference from redundant history on current traceability queries, focusing on defect phenomenon information for the latest batch |
| `variables` | Bind batch number, sterilization batch number | Limit dialogue context to only documents associated with the current production batch, narrowing the retrieval scope |
| `chatId` | Bind current conversation ID | Retain batch-associated context for multi-turn dialogue, avoiding cross-conversation confusion |

## Three Common Misconfigurations
- Image links in the knowledge base cannot be displayed during dialogue: The symptom is that the returned results do not include image URLs uploaded to the knowledge base. The cause is failing to explicitly require embedding image URLs in the answer text in the prompt, and not configuring context parameters associated with image display.
- The dialogue interface cannot be called to specify a target knowledge base: The symptom is that returned results include documents from irrelevant knowledge bases. The cause is failing to correctly bind the knowledge base scope parameter in `variables`, or failing to declare retrieval restriction conditions in `messages`.
- Redundant historical interference occurs in multi-turn dialogue: The symptom is that returned results include multiple rounds of old non-current batch information. The cause is failing to limit the historical turns of `messages`, leading to redundant context.

## How to Verify Proper Configuration
A retrieval query with a known batch number is submitted, and returned results are checked to only include document content for the corresponding batch.
A test image link is uploaded to the knowledge base, a dialogue on the corresponding topic is initiated, and the image URL is confirmed to be correctly embedded in the answer text.
The dialogue interface is called with the `chatId` and `variables` parameters, and returned results are checked to have context strictly associated with the current batch information.
A multi-turn dialogue is initiated, and the historical turn limit is confirmed to be active, with no redundant old data interfering with current analysis.

The values provided are common starting points and should be measured against the reader's own samples.
