# Quality Problem Traceability and Defect Analysis for Medical Device Assembly and Clean Production: Model Access and Configuration

## What the data for this category looks like
This category’s daily documents include production process specifications, batch production records, clean zone records, sterilization batch records, inspection reports, software version records, adverse event and traceability materials. Data sources cover design history files, device and material batches, MES systems, clean environment monitoring equipment, sterilization equipment, inspection and calibration systems. Data updates follow production batches, individual devices, and clean environment monitoring plans. Single-batch data includes exclusive fields such as unique device identification, material batch number, sterilization parameters, and clean zone temperature and humidity records.

## Constraints imposed on model access and configuration
Multi-source, scattered data sources require model access to support cross-system data association matching. Configurations must adapt to field formats of different systems and bind batch dimensions. Batch-based data updates require context refresh cycles to match production batch rhythms, avoiding data lag or redundancy caused by fixed-cycle synchronization. Long documents and multi-field structures require configured token limits to cover complete single-batch production records, while restricting irrelevant data introduction to prevent exceeding model processing thresholds. Medical devices have high compliance requirements, so model output must strictly match fields and parameters of controlled documents to avoid generating deviant content.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `maxContext` | `8000–12000 token` | The total length of documents such as single-batch production records and sterilization records for this category usually falls within this token range, and can cover multi-source associated traceability data |
| `maxTokens` | `4000–6000 token` | Medical device defect analysis needs to process both traceability data and adverse event descriptions, to avoid output content being truncated |
| `quoteMaxToken` | `2000–3000 token` | The complete content of key reference fields such as clean zone monitoring and batch identification needs to be retained to ensure traceability accuracy |
| `temperature` | `0.1–0.3` | This scenario requires strict matching of controlled fields in production documents, reducing the randomness of generated content to meet compliance requirements |
| Workflow/API tool selection | `auto` | Need to automatically call tools for associating multi-source data according to traceability requirements, without manually specifying the call scope |
| `AIPROXY_API_ENDPOINT` | Fill in the dedicated interface according to the deployment environment | Local or private deployment requires using dedicated proxy endpoints to ensure the transmission security of sensitive medical device data |

## Three common mistakes
- Symptom: Model output is forcibly truncated, and logs show token limit exceeded. Cause: `maxTokens` and `maxContext` parameters were not adjusted based on the total length of single-batch documents, so complete production and sterilization records cannot be covered.
- Symptom: Connection error occurs when configuring the model channel, with the interface prompting "invalid endpoint". Cause: The local deployment's `AIPROXY_API_ENDPOINT` was not matched, and a public proxy address was used by mistake.
- Symptom: Key batch association fields are missing in traceability results. Cause: `quoteMaxToken` was not set to retain fields such as unique device identification and material batch number, so the model cannot extract core traceability information.

## How to confirm configuration is complete
- Upload complete single-batch production records and sterilization records, initiate a defect analysis test in FastGPT v4.17.0, and check if the model output covers all key fields without truncation.
- Fill in `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`, then initiate a single test call to confirm there are no connection errors or permission abnormality prompts.
- Simulate an adverse event query, check if the model automatically associates the corresponding batch's clean zone monitoring data and inspection reports, and if the output logic complies with business rules.
- Adjust the `temperature` parameter to 0.1 and 0.3 respectively to test the same query, confirm that the key fields and conclusions of the two outputs remain consistent to meet compliance requirements.

The values provided are common starting points and should be measured against the reader's own samples.
