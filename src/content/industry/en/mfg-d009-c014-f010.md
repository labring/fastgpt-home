# Quality Problem Traceability and Defect Analysis for Dyeing and Finishing: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
The core entities in this category are dyeing and finishing factories, and the dyeing, setting, laboratory, and quality departments of fabric enterprises. Daily data sources include customer color samples, formula libraries, dye chemical batch records, dye vat control systems, colorimeters, setting machines, and environmental monitoring equipment. Data is generated on a per-vat, per-batch, per-shift basis. Core documents include dyeing formulas, chemical dosing records, dye vat curves, proofing confirmation sheets, color difference reports, setting process sheets, and sewage ledgers. Fields include vat number, batch number, dye chemical dosage, temperature rise curve parameters, color difference values, holding duration, and more. Some documents include numeric data collected by equipment.

## Constraints on Knowledge Base Retrieval and Recall Imposed by These Characteristics
The business characteristics of wet chemical batch processing require precise matching of data using unique vat numbers and batch numbers. Broad retrieval can easily introduce irrelevant old batch data. The high-frequency update pattern (per vat, batch, or shift) means the knowledge base must support real-time or near-real-time synchronization to avoid recalling expired data. Documents include long curve text, numeric tables, and specialized terminology. Standard title-based chunking can break the connection between curves and their associated parameters. Retrieval for specialized fields such as color difference value ΔE and chemical dosing ratios requires exact terminology matching, otherwise recall results will have no business value. Severe errors such as full vat scrap and environmental compliance violations require strict control over the relevance and timeliness of recall results.

## Configuration Settings
This configuration is based on FastGPT v4.17.0. Specific parameter settings are as follows:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches the precision requirement for specialized fields such as dyeing processes and batch numbers, filters low-relevance non-business content |
| `limit` | Top 8 entries | Controls the total length of recall results given the large number of documents related to a single batch, and adapts to model context window limits |
| `searchMode` | Exact match | Prioritizes matching unique identifier fields such as vat number and batch number, to avoid recalling irrelevant data across batches |
| `usingReRank` | Enabled | Re-ranks recall results by color difference value and process fit, to prioritize documents that most closely match the current quality issue |
| `datasetSearchUsingExtensionQuery` | Disabled | Prevents the system from generating non-knowledge base AI-recommended questions, ensuring all recalled content comes from the enterprise’s exclusive production and quality documents |
| `collectionIds` | Specified collection IDs divided by department | Only retrieves exclusive knowledge bases for dyeing, setting, and quality departments, excluding irrelevant administrative documents |

## Three Common Mistakes
- Retrieval returns a large number of AI-generated non-business recommended questions, and the recommended content does not match the dyeing and color difference documents uploaded by the enterprise. Cause: `datasetSearchUsingExtensionQuery` is enabled, the system automatically generates irrelevant broad questions, and the retrieval scope is not limited to the enterprise’s exclusive knowledge base.
- After uploading docx format dye vat curves and process sheets, the embedded colorimeter data charts are lost. Cause: Document image retention rules are not configured, or the connection between charts and context is not preserved during chunking.
- Retrieval of long documents such as dye vat curves returns a large amount of irrelevant old data across batches. Cause: No `similarity` threshold is set, or the threshold is too low, and precise matching of unique identifier fields such as vat number and batch number is not performed.

## How to Verify Proper Configuration
- Upload a batch of test dyeing formulas and color difference reports, perform targeted retrieval, and check whether the returned results only include documents related to this batch, with no irrelevant cross-batch content.
- Check the sorting order of retrieval results, confirm that results with color difference values closest to the test question appear first, to verify that the re-ranking function is active.
- Check whether the system-recommended related questions all come from uploaded enterprise knowledge base documents, with no AI-generated non-business content.
- Re-upload a docx document with charts, check whether the content stored in the knowledge base retains the original charts and tables, to confirm that the chunking configuration is correct.

The values given are common starting points and should be measured against the reader's own samples.
