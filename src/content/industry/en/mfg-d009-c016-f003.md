# Quality Problem Traceability and Defect Analysis for Transformer and High-Voltage Electrical Manufacturing: Multi-Turn Dialogue and Prompt Engineering

## What the data for this product category looks like
Data sources include design BOMs, purchase ledgers for silicon steel sheets and insulating materials, vacuum drying equipment logs, oil test reports, and high-voltage test station records. The data update schedule is that each product corresponds to a complete set of records, and corresponding ledgers are updated synchronously for each batch of raw materials. Daily documents include winding and core assembly records, vacuum drying records, insulating oil reports, partial discharge and withstand voltage test reports, and nameplate parameter tables. Fields include insulating structure parameters, test voltage values, drying duration, partial discharge values, and other relevant metrics, with units covering professional measurement standards such as kilovolts, picocoulombs, and hours. Full-process data for a single product is independent and complete, and no cross-batch combined analysis is required.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
The independent traceability requirement for a single product means dialogue must be bound to a unique identifier to avoid cross-product data confusion. Multi-source documents have significant format differences, so prompts must guide dialogue to extract information using category-specific fields to avoid generalized analysis. Individual document lengths vary widely, so context length must be limited to a reasonable range to avoid overload that impacts response speed. In scenarios with many professional terms, prompts must limit analysis dimensions, focus on core links such as insulation and high-voltage testing, and reduce invalid output. Data updates occur at a high frequency, so dialogue contexts must prioritize calling the latest test and assembly records to ensure the timeliness of analysis results.

## Three common configuration errors
- Issue: Dialogue export records are not associated with a product number, and fields are empty. Cause: Traceability data for a single product is not bound via `chatId`, only general dialogue content is stored.
- Issue: After uploading attachments such as insulating oil reports and withstand voltage test reports, subsequent dialogue association cannot be completed. Cause: The allowed document type whitelist is not configured, or the function for binding attachments to dialogue is not enabled.
- Issue: After calling the api/v1/chat/completions interface, the returned result does not match the specified knowledge base tag. Cause: The knowledge base association identifier is not correctly passed in the request parameters, or the exclusive dataset for the corresponding product category is not bound.

## How to verify the configuration is correct
- Enter the nameplate parameters of a single transformer when initiating a dialogue, and check whether the dialogue automatically associates the corresponding batch of assembly and test records.
- After uploading an insulating oil report, initiate a partial discharge anomaly analysis, and check whether the returned result includes specific test values from the report.
- Call the api/v1/chat/completions interface, pass the specified knowledge base tag, and check whether the returned result only associates the dataset for the corresponding product category.
- View the dialogue history, and check whether `chatId` matches the unique production number of the single product.
