# Quality Problem Traceability and Defect Analysis for Spraying and Coating: Workflow Orchestration

## What the data for this category looks like
This category covers the full coating process. Data sources include TDS/SDS documents provided by coating suppliers, real-time operating data from spray booths and ovens, test results from colorimeters and film thickness gauges, workshop environmental monitoring data, and MES system records. Daily documents include coating process cards, coating batch sheets, paint mixing records, film thickness and color difference reports, oven curves, defect repair orders, and VOCs ledgers. Data update frequency varies with production batches and shifts. Some operating parameters are collected continuously.

## What constraints these characteristics impose on the "workflow orchestration" link
Dispersed data sources and uneven update frequencies require workflows to support asynchronous pulling of multiple data sources and format unification. Large differences in fields across multiple document types require configuring nodes to perform standardized mapping of fields for different documents. Continuously collected real-time data and batch-level documents must be processed separately to avoid data mixing. The association between VOCs ledgers and production data requires workflows to retain complete link traceability fields, ensuring that corresponding production windows can be traced during defect analysis. Analysis of coating defects requires matching time windows for pretreatment, spraying, and curing. Workflows must support associating multi-node data by batch or time interval.

## How to set up the configuration
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| Data source trigger condition | Execute after matching batch number | Coating production data is grouped by batch to avoid interference from cross-batch data on analysis |
| Context window size | 800–1200 characters | Adapts to the single-page content length of documents such as coating process cards and paint mixing records, avoiding truncation of critical parameters |
| Global variable binding | Bind batch ID via `variables` | Uniformly stores core parameters of the current batch, such as coating lot number and oven temperature, for subsequent analysis nodes to call |
| Node execution timeout | 600 seconds | Adapts to the parsing and associated query of large-volume data such as oven curves and continuously collected data |
| Result deduplication rule | Deduplicate by defect type + batch number | Prevents the same defect from being repeatedly identified across multiple stages such as spraying and curing |
| Number of failure retries | 3 times | Addresses temporary interruptions in real-time data collection or interface fluctuations |

## Three common mistakes
- Symptom: The workflow prompts tool call failure during execution. Checking logs reveals that `nodeId` is not correctly bound to batch parameters. Cause: The `variables` binding for the corresponding batch ID is not configured on the data source node, causing subsequent nodes to fail to obtain correct context data.
- Symptom: When the workflow processes multi-batch data, the returned results include defect records from historical batches. Cause: No deduplication rule configured by batch number, causing data from different batches to be confused and associated.
- Symptom: When uploading coating-related documents, the parsing node automatically loads content from previously uploaded files. Cause: No rule configured on the file upload node to only process attachments from the current session, causing historical files to be repeatedly included in the parsing scope.

## How to confirm the configuration is correct
- Manually trigger a single-batch workflow, check that the data source node only pulls data such as coating batch sheets and oven curves for the corresponding batch, and confirm that no historical batch data is mixed in.
- View the parameters stored in the `variables` node, confirm that the core fields of the current batch are correctly bound and can be normally called by subsequent analysis nodes.
- Simulate a data collection interruption scenario, confirm that the workflow automatically retries according to the configured number of retries after timeout, and does not directly trigger the failure process.
- Upload a single coating process card, confirm that the parsing node only processes the currently uploaded file and does not load content from previously uploaded documents.

The values provided are common starting points and should be evaluated against local samples.
