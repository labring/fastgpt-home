# Quality Problem Traceability and Defect Analysis for Spraying and Coating: Model Access and Configuration

## What the Data for This Category Looks Like
Data for this category covers the full workflow of coating production lines for automobiles, home appliances, construction machinery, metal furniture, and other related use cases. Daily documents include coating process cards, paint batch sheets, paint mixing records, film thickness and color difference reports, oven curves, defect repair orders, and VOCs logs. Data sources include paint supplier TDS/SDS documents, spray booth and oven operation data, colorimeters, film thickness gauges, environmental monitoring equipment, and MES systems. Updates are triggered per paint batch, per production shift, and for continuously collected device data. Available fields include paint batch numbers, Ford Cup 4 viscosity seconds, film thickness μm values, oven temperature and time parameters, color difference ΔE values, and more.

## Constraints on Model Access and Configuration
The multi-source, high-frequency updated data characteristics of coating scenarios create multiple constraints for model access and configuration.
First, mixed structured and unstructured data requires models to support multimodal input, or vector models adapted for multi-field indexing.
Second, high-frequency updated batch and device data requires context length to match the time span of production windows. This enables associated analysis across pre-treatment, spraying, and curing stages.
Third, differences in field units across data sources require clear data mapping rules during configuration. This avoids parameter matching deviations.
Fourth, compliance-related data such as VOCs logs requires model call permissions and data processing to meet scenario requirements.
Additionally, local model access requires adaptation to device data collection frequencies. This prevents timeouts or incomplete indexing.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Matches the total length of single-batch production documents for the full coating workflow, enabling associated analysis of process cards, batch sheets, and defect records |
| `temperature` | 0.1–0.3 | Ensures consistency in defect analysis results, avoiding deviation in defect judgment caused by random fluctuations |
| `vision` | Enabled | Adapts to image reports generated by colorimeters and film thickness gauges, supporting direct parsing of detection data in image format |
| `quoteMaxToken` | 2000 characters | Limits the length of a single referenced document, focusing on core content related to coating process parameters and defect associations |
| `AIPROXY_API_ENDPOINT` | Fill in the deployed local model address | Adapts access paths for local or cloud models including ollama, Alibaba Qwen, ensuring correct request routing |
| `AIPROXY_API_TOKEN` | Fill in the authorization key for the corresponding model | Completes model identity verification, resolving permission check issues that cause access failures |

## Three Common Configuration Mistakes
- Phenomenon: An incorrect ollama local address is entered when configuring `AIPROXY_API_ENDPOINT`. Vector model access fails, and the interface displays a connection timeout prompt. Cause: The default port path for ollama is not matched, or the access addresses for large models and vector models are confused.
- Phenomenon: A prompt of no available channels appears when selecting Alibaba Qwen text-embedding-v3. Cause: Call permissions for the corresponding model are not configured in the dedicated group, and the default group does not have usage eligibility for this embedding model.
- Phenomenon: A token limit exceeded error is returned when calling a local ollama model, or uploaded colorimeter images are not parsed. Cause: Parameters are not adjusted based on the actual maximum token limit supported by the model, or the `vision` configuration for image input is not enabled.

## How to Verify Successful Configuration
- Initiate a model test call via the configuration interface for FastGPT v4.17.0, confirming that normal text or defect analysis results are returned.
- Upload a single coating image report captured by a colorimeter, verifying whether the `vision` configuration takes effect. Check if the returned results include detection content parsed from the image.
- Import a batch of paint batch data, check the update status of the vector index, and confirm that data fields match the configured mapping rules.
- Adjust the `temperature` parameter to different ranges, compare the consistency of two analysis results, and confirm that the configuration meets scenario stability requirements.

The values provided are common starting points and should be measured against the reader’s own samples.
