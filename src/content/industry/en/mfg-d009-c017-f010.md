# Quality Problem Traceability and Defect Analysis for Spraying and Coating: Knowledge Base Retrieval and Recall

## What the data for this category looks like
Business data for spraying and coating scenarios covers full-process documents and collected data from coating lines for automotive, home appliance, construction machinery, and other applications. Daily documents include coating process cards, paint batch sheets, paint mixing records, film thickness and color difference reports, oven curves, defect repair orders, and VOCs ledgers. Data sources include TDS/SDS documents from paint suppliers, real-time collection data from spray booths and ovens, test results from colorimeters and film thickness gauges, environmental monitoring data, and MES system work orders. Update cadence follows: batch sheets are updated per paint batch, paint mixing and process execution records are updated per shift, and oven and environmental monitoring data are collected continuously. Document fields include paint batch numbers, film thickness values, color difference parameters, oven temperature curve parameters, real-time VOC concentrations, and more.

## Constraints imposed on knowledge base retrieval and recall
Multi-source heterogeneous data structures require retrieval to support cross-document-type associated matching. For example, combine viscosity parameters from paint batch sheets with temperature parameters from oven curves to analyze defects. Frequently updated data sources require incremental recall mechanisms to avoid excessive resource usage from full retrieval. Coating defect analysis needs to match parameters across the entire pre-treatment, spraying, and curing windows, leading to a wide retrieval scope. A balance must be struck between recall volume and accuracy. Field differences across documents require retrieval rules to adapt to different formats of process parameters, test data, and ledger records. Core indicators related to coating appearance and curing must be prioritized for matching, which distinguishes this category from other metal processing categories.

## Configuration settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `similarity` | 0.75–0.85 | Coating defect matching requires high confidence to avoid mixing low-relevance process or equipment data into results |
| `limit` | Top 8 entries | Covers multi-dimensional data across the full coating workflow: batch, equipment, testing, and more, avoiding result redundancy |
| `searchMode` | `fullTextRecall` | Adapts to parameter matching needs for long texts such as coating process cards and oven curves |
| `usingReRank` | Enabled | Reranking optimizes associated sorting of multi-dimensional parameters, improving matching accuracy between defects and processes |
| `datasetSearchUsingExtensionQuery` | Enabled | Expands keywords related to processes and defects based on user questions, covering more potentially matching documents |
| `collectionIds` | Configure collection IDs separately for coating processes and defect analysis | Distinguishes different types of business documents, preventing cross-category data from interfering with retrieval results |

## Three common errors
- Symptom: A `Validation failed: name: Path `name` is required.` error is returned after calling knowledge base retrieval. Cause: Required fields for coating-related documents are not fully completed. For example, batch numbers for paint batch sheets or device IDs for oven curves were not configured during import.
- Symptom: Knowledge base creation fails when using web static links. Cause: Coating-related documents such as oven curves and film thickness reports often contain charts and structured data. Field parsing fails due to incorrect crawl rule configuration.
- Symptom: The input and response reference content from knowledge base searches are forcibly displayed in the answer. Cause: The reference display switch was not turned off in workflow configuration, or the reference output function was not disabled in retrieval settings.

## How to confirm correct configuration
Under FastGPT v4.17.0, configuration can be verified using the following executable actions:
- Import a batch of coating process cards and paint batch sheets, run retrieval tests related to defect analysis, and check whether returned results include core parameters such as viscosity and film thickness for the corresponding batch.
- View retrieval logs to confirm that the `similarity` threshold is active, and similarity scores of returned results fall within the set 0.75–0.85 range.
- Test workflow invocation scenarios, verify that knowledge base reference content can be hidden or displayed as needed to meet business display requirements.
- Submit new paint mixing records and oven data, confirm that the incremental update function is active, and retrieval results include the latest business data in a timely manner.
