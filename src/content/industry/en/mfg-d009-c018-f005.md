# Quality Problem Traceability and Defect Analysis for Basic Chemical Continuous Production: Tool Calling and Plugins
This document is compatible with FastGPT v4.17.0.

## What the data for this category looks like
Core data for basic chemical continuous production comes from DCS/SIS control systems, online analyzers, LIMS laboratory management systems, equipment condition monitoring modules, energy metering systems, and raw material tank sensors. Daily documents include operating procedures, process index cards, DCS trend charts, laboratory reports, interlock bypass records, special work permits, and shift logs. Data update frequencies include real-time, per-shift, and daily. Most fields have dedicated units, such as MPa for reactor pressure, ℃ for material temperature, m³ for tank liquid level, and similar units.

## What constraints these characteristics impose on the tool calling and plugins workflow
Multi-source heterogeneous data sources require tool calling to adapt to data source interfaces with different protocols, to avoid pull failures caused by format incompatibility. High-frequency updates of real-time data require tool calling trigger intervals to match production rhythms, to avoid being too long or too short. Diverse document types require plugins to pre-set corresponding parsing rules, to adapt to the table structure of process index cards, time-series data format of DCS trend charts, and similar document structures. Calls of records related to strong interlocks require additional permission verification to prevent sensitive data leaks. Large volumes of material circulation data for large-scale continuous production require controlling the return volume of a single tool call, to avoid interface overload.

## How to Set Configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `toolChoice` | `auto` | Automatically adapts multi-tool calling logic, compatible with calling requirements of different data sources |
| Single tool call data item limit | First 500 items | Matches the single-batch data scale of basic chemical continuous production, avoids interface transmission overload |
| Tool call timeout period | 30–60 seconds | Adapts to the response rhythm of real-time data pulling and historical process data queries, calibrated based on actual measurements |
| `functionCall` parameter verification | Enabled | Intercepts invalid format calling requests, avoids JSON payload format errors |
| Document parsing rule adaptation | Pre-set chemical industry-specific parsing templates | Adapts to unique document structures such as process index cards, DCS trend charts, and interlock bypass records |
| Context update trigger timing | Per shift work cycle | Matches the shift work rhythm of basic chemical production, ensures timeliness of context data |

## Three Common Misconfigurations
- The symptom is that the text extraction tool returns a 400 Invalid JSON payload received. Unknown name error. The cause is that the `functionCall` parameter verification switch is not enabled, and calling parameters that do not meet the format requirements are passed in.
- The symptom is that preset context data cannot be obtained when calling the workflow API. The cause is that the context update trigger timing is not configured to match the shift work cycle nodes, resulting in context not being updated synchronously according to production rhythms.
- The symptom is that missing result fields or abnormal units are returned by tool calls. The cause is that the chemical industry-specific document parsing template is not enabled, so the unique fields and unit formats of process index cards and DCS trend charts cannot be adapted.

## How to Confirm the Configuration Is Complete
- Initiate a single simulated call, check that the JSON format of the returned result is compliant, and confirm that the `functionCall` parameter verification is enabled.
- View the tool call execution logs, confirm that the trigger timing aligns with the shift work cycle, and verify that the context update configuration is correct.
- Upload a DCS trend chart document, check whether the parsed time-series data and field units match actual production conditions, and confirm that the chemical industry-specific parsing template is active.
- Initiate a batch data call, confirm that the number of returned results does not exceed the preset limit, and verify that the single-call data volume configuration is reasonable.
