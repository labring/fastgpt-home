# Quality Problem Traceability and Defect Analysis for Plastic Injection Molding: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
The business entities for this category are manufacturers of injection molded parts, automotive interior components, home appliance parts, and medical plastic products. Core daily documents include injection molding process cards, raw material drying records, mold histories, first-piece inspection reports, on-shift patrol inspection forms, and material change and machine cleaning records. Data sources cover resin batch property sheets, injection molding machine operating parameters, mold temperature controller data, manufacturing execution system (MES) data, and dimensional and appearance inspection results. Data updates are triggered by each production batch, each mold or material change, and each shift handover. Document fields include production batch number, mold temperature, screw speed, holding time, raw material batch number, and others, with corresponding units such as degrees Celsius, revolutions per minute, seconds, megapascals, and others.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
The high update frequency, scattered data sources, and diverse document types for this category impose multiple constraints on multi-turn dialogue and prompt configuration. First, frequent batch-level updates require limiting the valid range of dialogue context to avoid introducing invalid historical data across batches. Second, multi-source heterogeneous data sources require prompts to explicitly specify preferred document types for retrieval to ensure accurate traceability. Third, fields with diverse units require prompts to explicitly require that corresponding units be attached when returning parameters to avoid parsing ambiguity. Fourth, significant parameter differences across production nodes require binding key identifiers such as the current production batch and mold number in each dialogue turn.

## How to set up the configuration
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `messages` context turn limit | Retain the first 6 dialogue turns and the 2 most recent on-shift production records | Injection molding data is updated per batch; overly long historical dialogue can easily introduce cross-batch interference |
| `variables` bound field configuration | Bind the current production batch number and mold number | Significant parameter differences exist across batches and molds; precise association with corresponding traceability data is required |
| Retrieval document scope | Prioritize retrieving injection molding process cards, mold histories, and raw material drying records | Core business documents for this category cover the full process chain of process, mold, and raw materials |
| Context refresh trigger rule | Trigger refresh on mold or material change events; refresh once per shift if no events occur | Data updates are triggered by mold/material changes and shift handovers, matching production rhythm |
| Result output format requirement | Attach parameter units and data source fields | Parameters for this category require clear units and traceability basis to avoid parsing ambiguity |

## Three common mistakes
- Issue: Garbled characters or abnormal field formats appear in dialogue return results. Cause: Units for injection molding data fields are not explicitly required in the prompt, leading to format errors when parsing non-standard process cards and patrol inspection form data.
- Issue: Multi-turn dialogue cannot continue interaction logic and cannot associate historical production data. Cause: Key parameters such as the current batch number and mold number are not bound via `variables`, so each dialogue turn is treated as an independent session, and traceability logic cannot be continued.
- Issue: Dialogue logs for the local deployment version are not automatically saved. Cause: The session log storage switch is not enabled in the system configuration, and the disk path for log retention is not specified.

## How to confirm the configuration is correct
- Initiate a dialogue that includes the current production batch number, and check whether the returned results associate the corresponding batch's injection molding process parameters and mold history data.
- Initiate 3 consecutive dialogue turns associated with different production nodes, and check whether the `messages` context correctly retains key production information without introducing irrelevant historical data.
- Check the local deployment's log storage path, and confirm that dialogue records are generated and saved per batch.
- Test input of abnormal parameters, and check whether the prompt requires returning standardized results with attached units and data sources.
