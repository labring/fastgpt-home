# Quality Problem Traceability and Defect Analysis for Safety, Environmental Protection and Special Operation Management: Vector Models and Indexes

## What data looks like for this category
Data for this category comes from EHS departments and production maintenance teams of manufacturing enterprises in chemical, metallurgical, machinery, light industry and other sectors. It covers documents including risk identification reports, hot work/permit-to-work in confined space/hoisting operation tickets, environmental monitoring records, hazardous waste ledgers, emission monitoring data, accident and hidden danger rectification reports, and more. Data sources include regulatory standards, online environmental monitoring equipment, gas detectors, personnel qualification files, equipment isolation lists, and supervision platforms. Data updates occur after each operation is completed, in real time or periodically per monitoring requirements, plus regular inspection updates. Documents have fixed fields such as operation time, location, personnel qualification level, monitoring value units, and also include unstructured risk descriptions and rectification instructions.

## What constraints these characteristics impose on the vector model and index link
Multi-source heterogeneous data sources require indexes to adapt to both structured fields and unstructured text, while balancing splitting and association across different formats. High-frequency real-time updated operation tickets and monitoring data require indexes to support incremental updates to avoid performance loss from full reconstruction. The presence of fixed fields and units requires vector models to adapt to embedding structured metadata, ensuring that retrieval can associate information such as the qualification and isolation status of corresponding operations. High-risk business attributes require the accuracy of recall results to meet strict standards, avoiding irrelevant data interfering with risk traceability and defect analysis.

## How to set configurations
These configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the content density of single documents such as operation tickets and risk identification reports, avoiding including too much irrelevant information in a single chunk |
| Overlap Length | 100–150 characters | Retains cross-chunk operation processes and risk-related context, ensuring that retrieval can fully associate the preceding and subsequent links of an operation |
| Similarity Threshold | 0.75–0.85 | Matches highly relevant risk and accident text, avoiding false recall of irrelevant daily monitoring records |
| defaultToken | 4096 | Adapts to the total length of multiple documents recalled in a single session, aligning with the average information volume of single-batch retrieval in EHS scenarios |
| maxToken | 8192 | Supports batch recall of associated content from accident rectification and multi-cycle monitoring records, covering complete traceability chains |
| Single Search Limit | Top 10 entries | Balances retrieval efficiency and information integrity, adapting to the associated analysis needs of multi-source data |

## Three common mistakes
- Phenomenon: Duplicate document chunks appear after knowledge base index merging, and records of the same operation appear multiple times in retrieval results. Cause: No deduplication rules are set for operation tickets and monitoring records updated per operation cycle, leading to repeated indexing of multiple submissions for the same operation.
- Phenomenon: A 401 status code is returned when calling the vector model, and text embedding requests cannot be completed. Cause: The access key for the vector model is not configured correctly, or the custom access channel does not adapt to the high-frequency call frequency in EHS scenarios.
- Phenomenon: After custom document splitting, the order of index chunks does not match the original document. Cause: No metadata identifier for document chunks is retained, and the automatic deduplication function is not turned off, leading to automatic deletion of duplicate chunks and disruption of the original order.

## How to confirm the configuration is correct
- Upload a single hot work operation ticket document, check that the split length of the index chunk is within the 800–1200 character range, and that the overlapping part retains relevant information such as the operation location and isolation measures.
- Call the vector model interface, confirm that no 401 status code is returned, and that the key configuration and access channel match the current deployment environment.
- Upload multiple monitoring records of the same type, check that there are no redundant duplicate chunks after index merging, and that the order of custom-split chunks matches the original document.
- Test retrieval of accident rectification reports, confirm that the similarity of recall results is within the 0.75–0.85 threshold range, meeting business retrieval needs.

The values listed above are common starting points and should be evaluated against the reader's own samples.
