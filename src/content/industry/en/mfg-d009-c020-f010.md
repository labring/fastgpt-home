# Quality Problem Traceability and Defect Analysis for Safety, Environmental Protection and Special Operations Management: Knowledge Base Retrieval and Recall

## What the data for this category looks like
The primary subjects of data for this category are EHS departments and production maintenance teams of manufacturing enterprises in sectors including chemical, metallurgical, machinery, and light industry. Daily documents cover risk identification records, work permits for hot work, confined space work, lifting operations, and similar tasks, online monitoring records, hazardous waste ledgers, emission monitoring data, and accident and hidden danger rectification reports.
Data sources include regulatory standard libraries, online environmental monitoring equipment, gas detectors, personnel qualification files, equipment isolation lists, and supervision platforms.
Update cycles apply after each operation completion, when real-time monitoring data is generated, and during regular compliance checks.
Document fields include operation type, approver, isolation point number, hazardous waste generation amount, monitoring value, and similar items. Corresponding units include cubic meters, kilograms, person-times, ppm, and others.

## Constraints imposed on knowledge base retrieval and recall
Multi-source heterogeneous data sources (online monitoring equipment, paper work permits, supervision platform data, and similar items) require the retrieval system to support recall of mixed-format content.
High-frequency update cycles (after each operation completion, real-time monitoring generation, regular compliance checks) require precise synchronization configuration to prevent retrieval results from lagging behind on-site compliance status.
Diverse document types and exclusive fields (such as isolation point number, hazardous waste generation amount) require retrieval logic to balance structured field matching and non-semantic text recall.
This category also involves personal safety, compliance penalties, and environmental responsibilities. Retrieval scope must be strictly limited to compliance documents of the relevant department to avoid irrelevant data interfering with decision effectiveness.

## How to configure the setup
For FastGPT v4.17.0, the following configuration items can be used to complete knowledge base retrieval and recall setup for this scenario:

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `similarity` | `0.75–0.85` | This category of data involves safety and compliance, so high matching accuracy is required to avoid recalling irrelevant work permits or monitoring records |
| `limit` | Top 8 entries | Too many single-recall results will exceed the context window, and key compliance information for EHS is mostly concentrated in the top few results |
| `searchMode` | Vector + keyword hybrid retrieval | Documents include structured fields (such as equipment isolation list number) and unstructured text (such as risk identification reports). Hybrid mode balances precise matching and semantic recall |
| `usingReRank` | Enabled | This category has high compliance requirements. Reranking filters low-correlation results and improves the ranking priority of key hidden dangers and work permit information |
| `datasetSearchUsingExtensionQuery` | Enabled | EHS scenarios often require association with regulations and qualification requirements. Extended queries can supplement retrieval of relevant compliance document content |
| `collectionIds` | Bind exclusive EHS work permit, hazardous waste ledger and other dataset IDs | Retrieval scope must be limited to compliance documents of this department to avoid recalling production data from other categories |

## Three Common Configuration Errors
- Symptom: Table datasets cannot be selected when creating a knowledge base. Cause: The table dataset has not been uploaded to the exclusive EHS compliance dataset collection, or retrieval permission for the table dataset has not been enabled.
- Symptom: Knowledge base retrieval results do not include the latest work permits or monitoring records. Cause: Incremental synchronization trigger rules are not configured, and only full synchronization is used, leading to update delays that prevent matching real-time generated compliance documents.
- Symptom: Empty results are returned after referencing variables such as operation type and isolation point number in the search card. Cause: The field corresponding to the variable has not been configured as a retrieval extension field, so the variable cannot be associated with the corresponding document content.

## How to Verify Successful Configuration
- Confirm that the bound `collectionIds` of the knowledge base only include dataset IDs related to EHS, such as work permits, hazardous waste ledgers, and monitoring records, with no production data from other categories included.
- Initiate a retrieval for confined space operation permits, and verify that the recall results include the latest work permit templates, risk identification requirements, and personnel qualification standards.
- Test referencing the isolation point number field with variables, and confirm that the retrieval results filter out compliance operation requirements for the corresponding isolation point.
- Trigger an incremental synchronization, wait 10 minutes (as confirmed by actual testing), then retrieve the newly uploaded hazardous waste ledger, and confirm that the content has been synchronized to the retrieval results.
