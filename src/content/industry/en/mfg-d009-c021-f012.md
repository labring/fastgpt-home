# Quality Issue Traceability and Defect Analysis for Furniture and Wood Product Manufacturing: Deployment and Upgrade

## What the data for this category looks like
The data for this category primarily comes from order design systems, panel and wood batch ledgers, CNC cutting and drilling equipment, ERP/MES systems, and moisture content testing equipment of panel furniture, solid wood furniture, custom home goods, and door manufacturers. Daily stored records include order breakdown drawings, cutting lists, edge banding and drilling programs, coating process documents, hardware material lists, and assembly and packaging records. Data updates occur per order, daily, or per material batch. Fields include panel dimensions, material batches, process parameters, installation matching information, and more. There is no unified fixed format, and it adjusts based on the personalized requirements of custom orders.

## What constraints these characteristics impose on deployment and upgrade
The custom order-driven nature leads to large fluctuations in single-batch data volume. This requires adapting to the access and storage of multiple types of unstructured documents. Multiple heterogeneous data sources require compatibility with device export files and system interfaces of different formats during deployment. Corresponding data synchronization rules must be configured in advance. The high-frequency update feature requires ensuring the stability of data synchronization links during upgrades, to avoid interrupting real-time data flow due to version updates. Association fields for panels and installation matching must be mapped during deployment. Otherwise, problems and corresponding production links cannot be linked during traceability. At the same time, the storage requirements for multiple types of documents require reserving sufficient storage space during deployment. Commercial edition deployments must adapt to multi-threaded parallel processing hardware configurations to handle high-frequency data requests from custom orders.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| `DB_MAX_LINK` | 100–200 connections | Adapt to query requirements for single custom orders associated with multiple panels and process documents, avoid exhausting database connections |
| `MONGODB_URI` | Configure connection string according to structured data format exported from enterprise ERP/MES | Store multiple types of documents including non-standard order breakdown drawings and cutting lists |
| `REDIS_URL` | Configure local cache service address, set cache expiration time to 3600 seconds | Cache frequently called panel batch and moisture content testing data, reduce load on primary database |
| `STORAGE_S3_ENDPOINT` | Configure according to enterprise self-built object storage service address | Store large-volume files such as coating process documents and assembly and packaging records |
| `FILE_TOKEN_KEY` | Generate key according to enterprise internal file access permission rules | Control access permissions for sensitive production documents including order breakdown drawings and hardware lists |
| `ROOT_KEY` | Configure as enterprise internal management exclusive key | Restrict unauthorized personnel from modifying core system configuration parameters |

## Three common configuration mistakes
- After upgrading to FastGPT v4.17.0, speech-to-text functionality cannot be called normally, returning a POST /v1/audio/transcriptions HTTP error. The cause is that the access address and permission parameters of the speech model were not reconfigured after the version upgrade, leading to the failure of the original configuration.
- When accessing the CogVLM model locally, recognition results for the same image are inconsistent. The cause is that unified model loading parameters were not configured during deployment, leading to inconsistent model versions or weights loaded each time the function is called.
- The application export and import function cannot be used normally, prompting missing fields. The cause is that exclusive fields for custom furniture orders were not mapped in advance, leading to the system being unable to identify panel information with non-standard BOM structures during export.

## How to confirm configurations are properly set
- Execute a panel association query for a single order, check whether the returned results include corresponding documents such as order breakdown drawings and cutting lists, confirm that the connection number configured for `DB_MAX_LINK` meets query requirements.
- Upload coating process documents to the system, verify that they can be accessed normally, confirm that `STORAGE_S3_ENDPOINT` and `FILE_TOKEN_KEY` configurations are correct.
- Call the speech-to-text interface, verify that the returned results match the input audio, confirm that the speech model access configuration is effective.
- Export the application configuration of a test order, verify that the exported file includes all custom furniture-related fields, confirm that field mapping configurations are complete.
