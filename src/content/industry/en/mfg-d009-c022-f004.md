# Quality Problem Traceability and Defect Analysis for Complete Home Appliance Manufacturing: Workflow Orchestration
This document is written based on FastGPT v4.17.0.

## What the data for this category looks like
The core data for complete home appliance manufacturing covers the full production and after-sales process of air conditioners, refrigerators, washing machines, and small home appliances. Daily documents include configured BOM, assembly work instructions, refrigerant charging records, electrical safety test reports, performance sampling inspection reports, and repair records. Data sources include ERP/MES systems, component batch ledgers, tightening and charging equipment, safety compliance testers, performance laboratories, and after-sales fault databases. Data update frequency follows one record per complete unit, process data synchronized per shift, and batch test reports generated per sampling plan. Fields include component batch number, charging volume, test voltage, repair reason, and other related items.

## What constraints do these characteristics impose on the "workflow orchestration" link
The mixed-line production mode of this category requires workflows to accurately filter data by model to avoid misassembly caused by mixed multiple models. High-frequency real-time data updates require workflow nodes to support dynamic pulling of the latest batches and process parameters from ERP/MES. Access needs for multiple types of documents require workflows to support multiple data sources including file upload, database query, and device interface. Comprehensive judgment of safety compliance, noise, and functional abnormalities requires workflows to chain analysis logic across multiple nodes, while ensuring accurate transfer of global variables to avoid deviations in traceability results.

## How to configure the settings
| Config Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Global variable configuration | Bind real-time complete unit data from ERP/MES, store classified by model | Complete home appliances are produced in mixed lines by model, so BOM and batch data for different models must be distinguished |
| File parameter transfer | Enable automatic mapping of uploaded file links, associate with the `variables` parameter | After-sales repair records and test reports are mostly uploaded files, which need to be passed to workflow nodes via links |
| `nodeId` configuration | Bind node IDs of tightening and charging equipment | Real-time process parameters collected by equipment must be associated to ensure accurate data sources |
| Node timeout setting | 600 seconds | Pulling safety compliance test and performance sampling inspection data requires waiting for device responses, which takes a long time |
| Variable reference configuration | Bind the current complete unit's batch number according to conversation context | Traceability for each complete unit must be associated with unique production batch data |
| Large model temperature setting | 0.2–0.4 | Defect analysis requires rigorous conclusions and reduced randomness |

## Three Common Configuration Errors
- Phenomenon: When a workflow is configured as a tool call, test report files uploaded via simple tasks cannot pass file links as parameters to workflow nodes. Cause: The uploaded file links are not bound to the workflow's `variables` parameter, causing nodes to fail to obtain incoming file data.
- Phenomenon: A globally variable set for the first time displays normally in two components, but after modifying the variable in the same conversation, downstream nodes prompt empty input. Cause: Real-time update triggers for variables are not configured in the workflow. Only static initial values are bound to the initial node, and subsequent modified global variables are not synchronized.
- Phenomenon: When an AI conversation component uses variable reference to specify a large model, the temperature parameter setting entry cannot be found. Cause: The custom temperature switch is not enabled in the configuration panel. The platform's preset value is used by default, and the corresponding interval is not manually adjusted.

## How to Confirm the Configuration is Complete
- Upload an electrical safety test report file for a complete home appliance, check the parameter logs of the workflow node, and confirm that the file link has been correctly passed in.
- Modify the component batch number in the global variable, trigger the workflow to run, and verify whether downstream nodes load the updated batch data.
- Open the large model configuration interface of the AI conversation component, confirm that there is an input area for the temperature parameter, and the value interval can be set manually.
- Run a workflow node with mixed-line model filtering, check whether the filtering result only includes home appliance model data associated with the current conversation.

The values provided are common starting points and should be measured against the reader's own samples.
