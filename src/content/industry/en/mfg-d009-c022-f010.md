# Quality Problem Traceability and Defect Analysis for Complete Home Appliance Manufacturing: Knowledge Base Retrieval and Recall

## What the Data for This Category Looks Like
Daily data for complete home appliance manufacturing covers the full production and after-sales process for categories including air conditioners, refrigerators, washing machines and other appliances. It includes bill of materials (BOM), assembly work instructions, refrigerant charging records, electrical safety test reports, performance sampling inspection records, and repair ledgers. Data sources cover ERP/MES systems, component batch ledgers, tightening and charging equipment logs, safety compliance testers, performance laboratory data, and after-sales fault feedback. Updates are performed per single product, per shift production batch, or per sampling plan. Each data entry includes fields such as model, batch number, process parameters, test results, and fault description. Units are adjusted flexibly based on document type.

## Constraints Imposed on Knowledge Base Retrieval and Recall
The multi-source, high-frequency, fine-grained data characteristics of complete home appliance manufacturing create multiple constraints for knowledge base retrieval and recall. Documents from multiple equipment and after-sales sources have diverse formats, so parsing and chunking support is required for structured tables, log text, test reports and other file types. The high-frequency update requirement per single product or batch means retrieval results must match the latest batch parameters and repair records. In mixed-line production scenarios with multiple parallel models, knowledge bases for different product lines must be isolated to avoid cross-model data confusion. Quality traceability requires precise matching of fault types with corresponding process and test data, so professional content strongly related to the current issue must be prioritized for recall.

## Configuration Guidelines
This page’s configuration is based on FastGPT v4.17.0. Specific configuration items and their rationale are listed below:
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `similarity` | `0.75–0.85` | Home appliance quality traceability documents contain precise batch and parameter information. This threshold filters low-match irrelevant content and prevents recall of documents for non-target models |
| `limit` | Top 8–12 results | Retrieval for complete appliance manufacturing needs to cover multiple dimensions including BOM, process, testing, after-sales and others. This quantity balances context window usage and information completeness |
| `usingReRank` | Enabled | Mixed-line production scenarios have a large number of documents for the same model. Reranking prioritizes results more relevant to the current fault type such as refrigerant leakage, safety compliance abnormalities |
| `datasetSearchUsingExtensionQuery` | Enabled | After-sales fault descriptions are often in colloquial language. This configuration matches terms in professional documents via extended queries, improving recall accuracy |
| `collectionIds` | Bind specified IDs per product line | Complete home appliance manufacturing has mixed-line production with multiple models. Isolating knowledge bases for different models avoids incorrect recall of BOM or test data |

## Three Common Configuration Mistakes
- Symptom: The system cannot repeat uploaded XLSX-format quality record content during conversation, and prompts that the file cannot be read. Cause: The retrieval and parsing configuration for spreadsheet files is not enabled, or `datasetSearchUsingExtensionQuery` is not correctly configured to parse structured spreadsheet data.
- Symptom: Retrieval results include BOM or test documents for other appliance models, and cannot accurately match the current production model. Cause: `collectionIds` are not bound per product line, resulting in mixed recall of content from cross-model knowledge bases.
- Symptom: The number of retrieval results is insufficient to cover process or test records required for fault analysis. Cause: The `limit` setting is too low, or the `similarity` threshold is set too high, filtering out relevant marginally matched content.

## How to Verify Correct Configuration
- Upload a single BOM document for a specific model, run a query that includes the model’s component name, and confirm that the recall results include this document.
- Upload documents for multiple models and bind different `collectionIds`, run a query for a specific model, and confirm that recall results only come from the knowledge base with the corresponding ID.
- Adjust the `similarity` threshold, observe changes in the relevance of recall results, and confirm that the threshold meets the business’s accuracy requirements.
- After enabling `usingReRank`, compare the sorting of recall results before and after enabling, and confirm that the reranking function is active.

The values provided are common starting points and should be measured against the reader's own samples.
