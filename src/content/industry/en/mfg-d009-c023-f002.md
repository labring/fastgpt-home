# Quality Problem Traceability and Defect Analysis for Industrial Instrument Manufacturing and Calibration: Vector Models and Indexes

## What This Category of Data Looks Like
Data in the industrial instrument manufacturing and calibration field comes primarily from documents including instrument assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version logs. Data sources include design documents, standard instrument monitoring data, calibration software exports, laboratory information systems, and customer range requirements. Data updates once per instrument for each calibration event. Each individual record includes structured fields such as instrument ID, calibration date, error values (such as Pa, ℃), traceability chain ID, and environmental monitoring parameters. It also includes unstructured content like calibration step descriptions and error analysis text.

## Constraints for Vector Models and Indexes
Data in this category uses an independent update unit per instrument per calibration. It mixes structured fields and unstructured text. Vector indexes must support precise associated retrieval using fields such as instrument ID and traceability chain ID. Calibration records and error curves vary widely in document length. The system must adapt to long-text embedding token limits. The high-frequency update feature requires indexes to support incremental synchronization. This avoids performance loss from full reconstruction. Metrology audit scenarios need precise matching of retrieval results. They have high requirements for the reasonableness of similarity thresholds.

## Configuration Recommendations
| Configuration Item | Recommended Value Range | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the typical text length of calibration records and error curve descriptions, avoiding truncation of core error data |
| Overlap Length | 100–200 characters | Preserves traceability association information between adjacent calibration batches, preventing chunking from breaking the contextual coherence of error curves |
| Similarity Threshold | 0.75–0.85 | Ensures matching of associated documents from the same calibration batch during traceability, while filtering irrelevant historical calibration records |
| Single Search Limit | Top 10 results | Matches the limited number of traceability chain entries to verify during metrology audits, avoiding excessive results that interfere with judgment |
| maxToken | 8192 | Adapts to the maximum token limit of Qwen3-Embedding-8B, enabling full embedding of long-text descriptions of error curves |
| defaultToken | Determined via actual measurement | Processes non-standardized customer range requirement text, adapting to custom input content of varying lengths |

## Three Common Misconfigurations
- Issue: In FastGPT v4.17.0, after configuring Qwen3-Embedding-8B, adding the same model again overwrites the existing configuration. Cause: No independent model configuration group is created for vector tasks of different instrument categories, and only a globally unique model name is used to bind retrieval tasks.
- Issue: Retrieval results return a large number of irrelevant calibration documents across instrument IDs, making it impossible to accurately locate the target traceability chain. Cause: No retrieval rule for pre-filtering by instrument ID field is configured, resulting in the full dataset participating in similarity matching.
- Issue: After importing a PDF document with a long error curve description, the system prompts a token limit exceeded error and embedding fails. Cause: The chunk length setting does not adapt to the long chart description text in the PDF, exceeding the token limit of the selected embedding model.

## How to Verify Proper Configuration
- Upload the complete calibration record for a single instrument, check that the chunked text fully retains core fields such as instrument ID, calibration date, and error value.
- Enter a traceability chain query term, verify that the number of returned results matches the single search limit configuration requirement.
- Import a document containing a long error curve description, confirm that the embedding task does not trigger a token limit exceeded system prompt.
- Attempt to add a second different embedding model, confirm that the existing valid configuration is not automatically overwritten.

The values listed above are common starting points and should be evaluated against the reader's own samples.
