# Quality Problem Traceability and Defect Analysis for Industrial Instrument Manufacturing and Calibration: Document Parsing and Chunking

## What data for this category looks like
Data sources include design documents, standard instrument and environmental monitoring data, calibration software outputs, laboratory information systems, and customer range requirements.
Daily documents include assembly and commissioning sheets, calibration procedures, original calibration records, error curves, metrology certificates, and software version records.
New documents are generated for each instrument after every calibration.
Most documents are forms with fixed fields or PDFs embedded with coordinate curves.
Fields include instrument ID, calibration date, standard instrument ID, error value, conformity judgment, and corresponding units of measurement.

## What constraints do these characteristics impose on document parsing and chunking?
Documents for this category are mostly structured forms or PDFs with error curves generated for a single instrument after one calibration. Traceability chain information must be retained strictly.
Parsing and chunking must adapt to two core document structures: fixed-field metrology forms and error curves with coordinate data.
Documents have small individual size but high generation frequency, since new documents are created after each calibration. Parsing must balance single-document processing efficiency and field integrity.
Documents include key traceability fields such as calibrated values with units and standard instrument IDs. Chunking must avoid splitting cross-field associated information. Otherwise, subsequent quality traceability cannot match corresponding calibration data.
Document formats vary widely across sources. Custom configuration is required to adapt parsing logic for different export formats.

## How to set configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 characters | Adapts to the length of fixed-field forms and error curve associated text for this category, avoiding splitting key traceability fields |
| `chunkSplitter` | Semantic chunking | Based on the structured characteristics of calibration documents, preserves semantic integrity of fields and curve descriptions |
| `customPdfParse` | Enabled | For error curve charts and form fields embedded in PDFs of this category, enables custom parsing to retain original typesetting and field mapping |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Adapts to parsing time of error curve PDFs, avoiding parsing timeout caused by complex chart rendering |
| `chunkSettingMode` | Manual configuration | For calibration documents from different sources (such as calibration software exports, LIS-generated documents), adjusts chunking rules flexibly to meet personalized parsing needs |

## Three common misconfigurations
- Symptom: PDF parsing tasks suddenly throw errors and return a parsing failure status code. Cause: `customPdfParse` is not enabled correctly, or recent configuration changes cause the doc2x parsing engine to fail to adapt to the error curve PDF format of this category.
- Symptom: Uploaded calibration documents are not passed to the large model as expected, only plain text content from default parsing is returned. Cause: The system default general text parsing process is not disabled, causing documents to be split in advance and cannot be directly passed to the large model.
- Symptom: Chunked text blocks lose associated description text for error curves. Cause: `chunkSize` is set too small, splitting associated paragraphs of curve descriptions and coordinate data, destroying information integrity.

## How to confirm correct configuration
- Upload a standard metrology certificate PDF, check if the parsed text retains core fields such as instrument ID, calibration date, and error value, with no field loss or misalignment.
- Review parsing task logs, confirm that no timeout error corresponding to `PARSE_FILE_TIMEOUT_SECONDS` is triggered, and parsing time meets expectations.
- Test chunked text blocks, confirm that conformity judgments and error values of the same calibration record are not split into different blocks, retaining associated information.
- Upload a PDF document with an error curve, confirm that the parsing result includes chart descriptions and corresponding coordinate data, with no content missing.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
