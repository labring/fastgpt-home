# Quality Issue Traceability and Defect Analysis for Process Changes and Engineering Changes: HTTP Interfaces and External Systems

## What this category of data looks like
Manufacturing enterprise change management teams produce this category of data.
The data includes ECN/ECR documents, change assessment records, drawings and BOM versions, process verification reports, switching plans, inventory disposal documents, and customer approval documents.
Data sources include PLM, ERP, MES systems, supplier materials, verification test results, and customer special requirements.
Updates happen irregularly, triggered by each change action.
Fields include change number, version number, effective time, impact scope, and other relevant items.
There are no standardized fixed units. Values adapt to associated business documents.

## What constraints these characteristics place on the HTTP Interfaces and External Systems link
This category of data is sourced from multiple production management systems and external materials.
HTTP interfaces must support multiple external authentication protocols and adapt to data format rules for different systems.
Data updates follow no fixed schedule, so interfaces must allow on-demand pulling to prevent invalid synchronization from consuming resources.
Document types vary widely, including both structured and unstructured content.
Interfaces must support multi-format data transfer, and must pass unique identification fields such as change number and version number to maintain complete traceability chains.
Changes involve cross-department collaboration, so interface calls must carry clear operating subject identifiers to enable locking of responsible links during subsequent quality issue traceability.

## How to configure settings
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `Authorization` | Configure enterprise-level authentication tokens with a 12-hour validity period | Meet security access requirements for enterprise systems such as PLM and ERP |
| `variables` | Pass core fields including change number, effective time, version number | Match the unique identification and key attribute requirements of this category of data |
| `responseData` | Only return change impact scope and version comparison results | Reduce invalid data transmission and improve interface response efficiency |
| Timeout threshold | 60 seconds | Adapt to the average response duration of multi-system data pulls |
| Retry count | 3 times | Address scenarios where external systems are temporarily unavailable |
| Request format | Select JSON or XML format as required by the associated system | Comply with data interaction formats of different systems such as PLM and MES |

## Three common configuration mistakes
- Symptom: Interface calls return a 401 Unauthorized status code, and change data cannot be pulled. Cause: The `Authorization` parameter is not configured correctly, or the token has expired and has not been updated in time.
- Symptom: Complete change comparison results cannot be obtained after calling a stream-mode interface. Cause: Segmented streaming response data is not processed correctly, and the content of all returned chunks is not aggregated.
- Symptom: A parameter error is returned after attaching parameters during an interface call. Cause: The attachment transmission format is not configured according to the requirements of the associated system, and the attachment field in `variables` is not correctly associated.

## How to confirm correct configuration
- Call the test interface, check whether the returned `responseData` includes core fields such as change number and version number.
- Simulate a scenario where an external system is temporarily unavailable, verify whether the interface triggers the retry mechanism and returns data normally after recovery.
- View interface logs to confirm that the `Authorization` parameter is correctly carried and the format meets requirements.
- Test the stream calling mode, confirm that all returned change data content can be fully received and aggregated.
