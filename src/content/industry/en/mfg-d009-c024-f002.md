# Quality Issue Traceability and Defect Analysis for Process Changes and Engineering Changes: Vector Models and Indexes

## What data in this category looks like
Data for this category originates from PLM, ERP, MES, supplier materials, validation tests, and customer-specific requirements. Update frequency is irregular, triggered each time a process or engineering change occurs. Daily documents include ECN/ECR forms, change assessment reports, drawings and BOM version files, process validation reports, production switching plans, inventory disposal documents, and customer approval documents. Fields cover change order number, version number, effective date, material code, inspection parameters, and more. No fixed unified format applies. Some documents contain binary drawings or test data.

## Constraints on vector models and indexing from these data characteristics
Multi-source heterogeneous data sources require indexes to support unified embedding and cross-system data association, eliminating data silos. Irregular update frequencies require indexes to support incremental updates, avoiding full reconstruction to save computing resources. Documents include structured forms and unstructured drawings and test data, so vector models must support embedding for both text and multimodal data. Fields include key identifiers such as version number and effective date. Index configurations must retain these fields for subsequent traceability, ensuring search results accurately match specific change versions and prevent confusion between old and new versions.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the paragraph length of text documents such as ECNs and change assessment reports, retains complete change logic |
| Overlap Length | 100–200 characters | Connects context between adjacent chunks, avoids splitting key change clauses |
| Similarity Threshold | 0.75–0.85 | Calibrated based on actual measurements, adapts to the similarity output range of the selected open-source index model, filters low-relevance non-target change documents |
| Single Search Limit | Top 10 results | Matches the routine traceability query scope of change management teams, avoids result overload |
| `maxToken` | Set to the selected embedding model/service input limit | This is the configured embedding model's maximum token count, not retrieval or LLM context. Check the selected model or provider documentation. See the [v4.17.2 model-field reference](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx) |
| `defaultToken` | Calibrate with representative change records | This is the default token count used for direct text splitting; inspect sample chunks to keep change-order and version identifiers together. See the [v4.17.2 model-field reference](https://github.com/labring/FastGPT/blob/v4.17.2/document/content/self-host/config/model/intro.mdx) |

## Three Common Misconfigurations
- Search results include mixed old and new version documents. This occurs when filtering rules for change effective dates and version numbers are not added to the index configuration, leading to confusion between change data from different batches.
- Calls to Tongyi multimodal vector models fail. This occurs when the invocation link for the multimodal model is not configured separately, and the request parameter format of the text vector model is used incorrectly.
- Index update tasks time out. This occurs when a single index update includes unchunked large-size drawing files, exceeding the system's single data processing limit.

## How to Confirm Proper Configuration
- Check the detailed view of chunked documents, confirm that key fields such as change order number, version number, and effective date are fully retained.
- Enter a specific ECN number to run a search, verify that returned results only include documents related to the corresponding change, with no irrelevant content.
- Upload a process drawing, test that the multimodal vector model invocation returns valid embedding results with no errors.
- View the index update logs, confirm that incremental update tasks complete normally with no timeouts or abnormal errors.

The values provided are common starting points and should be evaluated against the specific samples of the target deployment.
