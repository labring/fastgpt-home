# Quality Issue Traceability and Defect Analysis for Process Changes and Engineering Changes: Tool Calling and Plugins

## What Data for This Category Looks Like
Data sources for this category include PLM, ERP, MES, supplier materials, validation tests, and customer special requirements. Updates have no fixed cycle, and one update is triggered each time a change is submitted. Daily documents include ECN/ECR, change assessment reports, drawings and BOM versions, process validation reports, switching plans, inventory disposal documents, and customer approval documents. Data fields include change number, version number, effective date, involved materials/process items, approval status, and others. The version number uses the V.x.x format, and the effective date uses a standard date format.

## Constraints on Tool Calling and Plugins
Multiple scattered data sources require tool calling to interface with multiple heterogeneous system APIs, and dedicated calling parameters must be configured for each system. No fixed update cycle requires the trigger logic to be bound to the change submission node, so the latest data must be pulled in real time after a change is submitted. Complex document structures and version management require tool calling to specify version fields to avoid pulling invalid data from old versions. Severe consequences of errors require tool calling to configure failure retry and data verification mechanisms to prevent invalid data from entering production links.

## How to Configure Settings
The following configurations are adapted for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Mode | Bound to change submission node trigger | Change data updates have no fixed cycle, latest version must be pulled in real time after change submission |
| Workflow/API tool selection | Set to `function` to enable tool calling | APIs of systems such as PLM and ERP must be called to pull change-related data |
| Workflow/API function-call configuration | Configured to batch pull related documents | Changes involve multiple types of documents, complete related information must be obtained in one go |
| Plugin Timeout | 600 seconds | Pulling multi-source data across systems requires a longer response time |
| Number of Documents Returned Per Request | First 15 entries | The number of change-related documents is limited, too many will exceed the context capacity limit |
| Result Verification Switch | Enable required field verification | Change documents must include required items such as change number and effective date to prevent invalid data |

## Three Common Misconfigurations
- Calling an external system API returns a 514 status code. This occurs because identity verification parameters for the corresponding system are not configured, causing the request to be blocked by the target system.
- Using a generic internet plugin without configuring calling rules for dedicated systems such as PLM and ERP, which results in failure to pull structured change data.
- When configuring a knowledge base search node in a workflow, variable references are not bound to the change ID. This happens because the externally passed change ID is not passed as a parameter, so knowledge base documents for the corresponding change cannot be matched.

## How to Confirm Configuration Is Complete
- Manually trigger a simulated call for a change submission, and check if ECN documents from the corresponding system can be pulled.
- View the tool calling logs to confirm that the `toolChoice` and `functionCall` parameters have been correctly enabled.
- Verify that variable passing correctly binds the change ID, and check that knowledge base search results only include related documents for the current change.
- Simulate a timeout request to confirm that the plugin triggers the preset failure prompt logic.

The values provided here are common starting points and should be measured against the user's own samples.
