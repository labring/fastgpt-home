# Quality Issue Traceability and Defect Analysis for Process Change and Engineering Change: Deployment and Upgrade

## What Data for This Category Looks Like
This category of data originates from PLM, ERP, MES, supplier materials, validation tests, and customer-specific requirements. Daily generated documents include ECN/ECR, change assessments, drawings and BOM versions, process validation reports, switch plans, inventory disposal documents, customer approval files, and more. Data updates occur irregularly, with one update triggered per change event. Documents include fields such as change number, version number, effective time, involved materials or process items, and approval status. Version numbers use the major.minor format, and effective times are recorded in ISO 8601 standard date format.

## Constraints Imposed on Deployment and Upgrade
This deployment uses FastGPT v4.17.0. Dispersed data sources and diverse data types require configuring multi-source database connections and multi-format document parsing capabilities during deployment, to ensure change data from different systems can be retrieved and processed. Document updates follow no fixed cycle, so an incremental synchronization mechanism must be supported during upgrades to avoid excessive system resource usage from full data pulls. Multiple departments participate in change management, so fine-grained permission groups must be configured during deployment to restrict document access scope for different roles. Additionally, change data covers production and quality links, so the stability of the data link must be ensured during deployment to prevent production document version confusion caused by configuration errors.

## Configuration Settings
| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://admin:secure_pass@192.168.1.20:27017/ec_metadata?authSource=admin` | Stores metadata and associated records of change documents, requires specifying the authentication source and target database |
| `PG_URL` | `postgresql://postgres:db_pass@192.168.1.20:5432/ec_management` | Stores structured approval data and version mapping tables for process changes |
| `REDIS_URL` | `redis://:redis_secure_pass@192.168.1.20:6379/0` | Caches change notifications and permission verification data to improve query efficiency |
| `STORAGE_S3_ENDPOINT` | `http://192.168.1.20:9000` | Configures the access endpoint for local object storage, used to store drawings and reports related to changes |
| `DB_MAX_LINK` | `20–30 connections` | Adapts to concurrent requirements for pulling change data from multiple systems, avoids connection pool exhaustion |
| `FILE_TOKEN_KEY` | `Randomly generated 32-bit string` | Encrypts file access tokens to prevent unauthorized access to sensitive change-related documents |

## Three Common Configuration Mistakes
- Symptom: No output when calling change data. Cause: Authentication parameters for `PG_URL` or `MONGODB_URI` are not configured correctly, preventing connection to the data source for synchronizing change data.
- Symptom: ECN or process validation report files fail to parse after upload. Cause: `STORAGE_S3_ENDPOINT` is not configured, or storage permissions are insufficient, preventing the system from reading uploaded document files.
- Symptom: Attachment summarization or analysis becomes unresponsive after local deployment. Cause: The connection limit for `DB_MAX_LINK` is not adjusted, leading to connection pool exhaustion when pulling data from multiple systems, preventing timely response to parsing requests.

## How to Verify Successful Configuration
- Access the configured `FE_DOMAIN`, verify that the page loads normally with no database connection or storage error prompts.
- Upload a standard ECN document, verify that the system successfully parses the file and generates the corresponding text index.
- Run a manual change data synchronization task, check that background logs show no database connection timeout or authentication failure errors.
- Generate an access link for a change document, use an unauthorized account to access the link, verify that the document content cannot be retrieved.

The values provided are common starting points and should be measured against the reader's own samples.
