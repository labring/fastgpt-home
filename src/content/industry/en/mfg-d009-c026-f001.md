# Quality Problem Traceability and Defect Analysis for Non-Ferrous Metal Smelting and Electrolysis: HTTP Interfaces and External Systems

## What this category of data looks like
Data sources for this category typically include concentrate and auxiliary material analysis reports, furnace and cell condition data collected by DCS systems, quality test records issued by laboratories, and energy and environmental monitoring data. Daily documents cover batching lists, smelting records, electrolytic cell condition records, test reports, anode and cathode quality records, and environmental protection ledgers. Data updates in real time upon completion of each batch of raw material processing, each furnace operation, or each cell operation. Some cell condition parameters are synchronized in real time. Fields include raw material composition dry basis percentage, cell voltage (volts), current (amperes), single-furnace smelting duration (hours), and more. Field formats vary across different business documents.

## Constraints imposed on HTTP interfaces and external systems by these data characteristics
Data for this category is multi-source, dispersed, and has highly varied update rhythms. This requires HTTP interfaces to support integration with multiple types of external systems, including DCS, laboratory management systems, and environmental monitoring platforms. Cell condition data with high real-time requirements needs interfaces to support low-latency synchronization. Single request duration must align with operation rhythms. Field formats for multiple document types are inconsistent. Interfaces must pass dynamic business parameters via `variables` to complete adaptation. Cross-system metal balance accounting requires batch pulling of historical data. Interfaces must support pagination query mechanisms. Full-link data traceability is required for quality problem traceability. Interfaces must record complete request and response logs to facilitate subsequent problem troubleshooting and auditing.

## How to configure the settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Carry a Bearer token, set token validity period to 7200 seconds | Matches the authentication validity period of internal smelting enterprise systems, avoids frequent token refreshes that disrupt real-time data synchronization |
| `variables` | Dynamically pass furnace number and cell number parameters per operation batch, parameter range covers 100-2000 | Adapts to dedicated data queries for different smelting furnaces and electrolytic cells |
| `responseData` | Only return specified quality test and cell condition fields, limit returned entries to the first 20 | Reduces invalid data transmission and improves interface response speed |
| Timeout setting | Set to 30-60 seconds, calibrated via actual testing | Matches the collection interval of real-time cell condition data, avoids timeout interruptions to operation synchronization |
| Retry count | Set to 2 retries, retry interval of 10 seconds | Addresses temporary network fluctuations, prevents single request failures from disrupting quality traceability processes |
| Log retention | Enable complete request and response logs, set storage duration to 180 days | Meets audit requirements for quality problem traceability, complies with internal enterprise data retention specifications |

## Three Common Misconfigurations
- Symptom: The interface call returns the `Access denied for user` error with status code 403. Cause: The `Authorization` parameter is not configured correctly, or the token permissions do not cover the target system's quality data query scope.
- Symptom: Performance bottlenecks occur when pulling historical data in batches, with excessively long database query durations. Cause: No joint index for furnace number and time dimensions has been created on the PostgreSQL cell condition data table, and no limit has been set on the MongoDB query result set size.
- Symptom: The `responseData` field returned by the interface is empty, and cannot match the field mapping for batching lists or electrolytic cell condition records. Cause: Correct furnace number or batch parameters were not passed via `variables`, causing the interface to not return dedicated data fields for the corresponding electrolytic cell or smelting furnace.

## How to Confirm the Configuration Is Complete
- An interface request for smelting records for a specified furnace number is made. The `Authorization` parameter is verified for normal carriage, and returned results are checked for inclusion of preset fields such as cell voltage and raw material composition.
- A temporary network interruption is simulated to verify that the interface performs retries as configured, and that complete data is normally obtainable after retries.
- The `responseData` returned by the interface is compared with the field formats of local business documents to confirm that the mapping relationship meets business requirements.
- Interface logs are reviewed to confirm that complete records of requests and responses have been retained, and that storage duration complies with configured requirements.
