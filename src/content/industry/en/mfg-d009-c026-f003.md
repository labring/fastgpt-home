# Quality Problem Traceability and Defect Analysis for Non-Ferrous Metal Smelting and Electrolysis: Multi-turn Dialogue and Prompt Engineering

## What data for this category looks like
This category draws data from concentrate and auxiliary material analysis reports, furnace condition and cell voltage/current data collected by the DCS system, laboratory test results, and energy and environmental monitoring records. Daily documents include batching lists, smelting records, electrolytic cell condition records, test reports, anode and cathode quality records, and environmental protection ledgers.
Data updates follow business nodes. Each batch of raw materials, each furnace, or each cell generates corresponding records. Key parameters are synchronized in real time.
Data fields include raw material batch number, furnace number, cell number, measured voltage and current values, component detection items, quality rating identifiers, and more. Measurement standards match corresponding specifications based on parameter type.

## What constraints these characteristics impose on multi-turn dialogue and prompt engineering
This category’s data is multi-source, heterogeneous, and has highly varied update rhythms. Multi-turn dialogue must prompt for precise identifiers step by step according to business nodes, such as raw material batch numbers, furnace numbers, or cell numbers, to avoid mixing cross-batch data.
Prompts must clearly limit extraction of fields only from specified documents, to prevent mixing irrelevant parameters. Real-time collected cell voltage and current data require dialogue to support short-context interaction. Excessively long historical turns cause data matching delays.
Field formats of different business documents are inconsistent. Prompts must predefine standardized field mapping rules to ensure information obtained during dialogue can be directly associated with corresponding business records.

## How to set up the configuration
The following configurations are formulated based on the rules of FastGPT v4.17.0:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chatId` | Bind to the unique furnace number or cell number corresponding to each request | Quality traceability for non-ferrous metal smelting and electrolysis requires strict association with full-process data of a specific furnace, cell, or batch. Binding a unique identifier avoids cross-batch data confusion |
| `messages` | Retain the current request and the previous round of guidance information, limit historical turns to 2–3 | Real-time collected cell condition data for this category updates frequently. Excessively long historical context causes response delays. Business links are fixed, so 2–3 turns are sufficient to cover the associated information required for traceability |
| `variables` | Preset 8–12 business variables, including batch number, furnace number, cell number, laboratory test items | Business fields for this category are fixed and manageable in quantity. Presetting variables reduces repeated prompt writing and improves API call efficiency |
| Single dialogue context limit | 800–1200 tokens, calibrated based on actual testing | Text length of single business records for this category falls within this range. Excessively long context exceeds the model's processing limit, leading to truncation of key information |
| Input guidance configuration | Display guidance questions in sequence according to the smelting → electrolysis → laboratory test business links | The business process of quality traceability for this category is linear and clearly segmented. Step-by-step guidance reduces input error rates |
| Batch call concurrency limit | Set single-node concurrent call volume to 1–2 calls per second | This category's workflow relies on multi-source data synchronization. Excessively high concurrency causes data reading conflicts, resulting in empty return results |

## Three common misconfigurations
- Setting concurrent call volume above 1–2 calls per second results in empty workflow call return results. Cause: The maximum number of workflow runs or batch input length configuration does not match the concurrency threshold, leading to data synchronization conflicts and failure to return normal results.
- When calling the API, the last variable value in the output overlays the result of the previous variable. Cause: The `variables` parameter of multi-turn dialogue is not bound to a unique `chatId`, causing variable caches from different requests to be overwritten and resulting in result interference.
- After configuring input guidance and word banks, the expected guidance questions do not appear in the dialogue interface. Cause: The trigger condition for input guidance is not associated with the current session's business scenario, or the word bank configuration has not enabled real-time synchronization, leading to failure to load guidance content.

## How to verify proper configuration
- Initiate a traceability request for a known furnace number or cell number, check that returned results only associate business records corresponding to that identifier, and eliminate cross-batch data interference.
- Adjust the frequency of concurrent calls, verify that workflow calls return valid results with no empty values across different concurrency levels.
- Enter the dialogue configuration interface, confirm that the input guidance question list matches the preset business link sequence, and that the word bank configuration is enabled.
- Call the API to obtain variable filling results, check that only the business fields for the current request are included, with no variable overlay from historical requests.
