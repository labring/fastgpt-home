# Quality Issue Traceability and Defect Analysis for Garment Cutting and Sewing: Workflow Orchestration

## Data Characteristics for This Category
The data sources for this category include order and size charts, CAD patterns, raw material and accessory inspection records, hanging system station data, needle detector test results, and customer sealed samples. Daily generated documents include process sheets, pattern drawings, layout planning drawings, cutting lists, first article sealed sample records, process quality sheets, and packaging size matching lists. Data updates with each order, each garment style, and each production batch. Cut pieces are irreversible, manual processes account for a high proportion of work, and style and seasonal fluctuations are significant.

## Constraints on Workflow Orchestration
Data updates frequently with each order, style, and production batch. Workflows must support dynamic binding of exclusive data for the corresponding batch to avoid cross-batch data mixing. The irreversible nature of cut pieces requires traceability processes to lock operation records for each process. No re-cutting corrections are permitted, so process validation nodes must be added to workflow orchestration. For scenarios with intensive manual processes, hanging system station transfer data must be linked to needle detector results. Workflows must support automatic pulling and alignment of multi-source heterogeneous data to reduce manual entry errors. Seasonal style fluctuations require workflows to quickly switch templates to adapt to quality inspection standards for different categories.

## Configuration Guidelines
The following configurations are based on workflow node rules for FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Variable Binding | Bind the order number and batch number fields in `variables` | Match the independent update rules for each batch of data to avoid cross-order data misuse |
| Node Trigger Condition | Trigger based on the completion status of station nodes associated with `nodeId` | Align with the hanging system's station transfer logic to ensure process data is accessed in production order |
| Single Document Parsing Limit | Top 3 entries | Adapt to the standard number of documents for a single batch's process sheet, layout drawing, and first article sealed sample |
| Context Timeout | 120–180 seconds | Cover the full duration of multi-source data pulling and model analysis processes |
| Attachment Size Limit | 1000 MB | Adapt to standard storage and upload requirements for documents such as fabric inspection reports and process quality sheets |
| Attachment Parsing Threshold | Calibrate based on actual measurements | Adapt to parsing requirements for category-specific non-standard documents |

## Three Common Mistakes
- Phenomenon: Workflow nodes cannot read uploaded layout drawing files. Logs indicate the file field is empty. Cause: No attachment upload binding parameters are configured in `variables`, so the workflow cannot associate uploaded category-specific documents.
- Phenomenon: Workflow applications using locally deployed models cannot complete attachment summarization, while simple applications run normally. Cause: No context parameters for model calls are configured in the workflow, so the input context for the local model is not loaded correctly.
- Phenomenon: Node trigger logic fails after migrating an older version workflow to a new version. Cause: Naming rules for `nodeId` have been adjusted in the new version, and the associated configuration for the corresponding nodes was not updated.

## How to Verify Correct Configuration
- Manually upload a single batch's process sheet and layout drawing, check if the workflow automatically pulls and binds the batch number field from the corresponding `variables`.
- Trigger station node transfer, verify that the workflow executes parsing and analysis steps in sequence based on the status of nodes associated with `nodeId`.
- Upload a non-standard fabric inspection report, confirm that the parsing node can normally read the document content and output structured results.
- Switch test batch order data, check that the workflow automatically adapts to the new category's quality inspection standards with no cross-batch data mixing.

The values provided are common starting points and should be measured against the reader's own samples.
