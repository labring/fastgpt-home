# Quality Issue Traceability and Defect Analysis for Incoming Material Inspection and Supplier Quality: Document Parsing and Chunking

## What data for this category looks like
This category serves IQC, SQE, procurement quality, and supplier engineering teams at manufacturing enterprises.
Teams process daily documents including inspection specifications, sampling plans, incoming material reports, supplier audit reports, exception contact sheets, 8D reports, and concession approval documents.
Data sources include purchase orders, drawings and specifications, supplier quality certificates, testing equipment, historical quality data, and supplier portals.
Update cycles follow per incoming batch, monthly or quarterly evaluations, and irregular audits.
Documents include fields such as batch number, inspection items, non-conformity judgments, supplier information, and sampling ratio. Units vary by document type.

## What constraints do these characteristics impose on the document parsing and chunking link
This category includes diverse document types: structured tables, semi-structured reports, and unstructured text. Parsing functions must support multiple formats.
High-frequency data updates require parsing speed to match business rhythms.
Key information such as batch numbers, suppliers, and non-conformity items spans paragraphs. Chunking must retain contextual connections.
Some documents embed images. Parsing functions must support image OCR.
Large document file sizes require parsing systems to have sufficient processing capacity.

## How to configure settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Aligns with paragraph lengths of incoming material reports and 8D reports, retains contextual association between inspection items and judgment results |
| `chunkSplitter` | Split by paragraph + title | Matches the hierarchical structure of inspection specifications and audit reports, avoids splitting inspection logic across titles |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 seconds | Accommodates bulk-uploaded supplier audit reports, prevents timeout during large file parsing |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | Supports uploading compressed archives of batch historical quality data from departmental archives |
| `customPdfParse` | Enabled | Preserves table and text hierarchy in PDFs, adapts to structured data in inspection reports |
| `chunkSettingMode` | Manual configuration | Adjust chunking parameters to account for differences between inspection specifications and incoming material reports |

## Three common misconfigurations
- Phenomenon: Some fields are empty after uploading a table dataset. Cause: Table structured parsing is not enabled. Splitting content as plain text causes loss of table column data.
- Phenomenon: No image content appears after parsing a PDF with embedded images. Cause: Image OCR for `customPdfParse` is not enabled. Only plain text is extracted.
- Phenomenon: Parsing tasks time out and fail during bulk upload of large files. Cause: The `PARSE_FILE_TIMEOUT_SECONDS` parameter is not adjusted. The default timeout duration is insufficient for large file parsing.

## How to confirm correct configuration
Upload a standard incoming material report. Review parsed chunking results, and confirm each chunk contains complete inspection items and judgment results.
Upload a supplier audit report with embedded images. Confirm parsed results include text descriptions matching the images.
Upload a compressed archive file under 500 MB. Confirm the parsing task completes within the set `PARSE_FILE_TIMEOUT_SECONDS` duration.
Upload a table dataset. Confirm structured fields are fully extracted with no missing content.

The values provided are common starting points and should be evaluated against samples specific to the target deployment.
