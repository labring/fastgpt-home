# Quality Issue Traceability and Defect Analysis for Incoming Material Inspection and Supplier Quality: Deployment and Upgrade

## Data Profile for This Category
Data sources for this category include purchase orders, drawing specifications, supplier quality certificates, inspection equipment, historical quality data, and supplier portals. Daily documents cover inspection specifications, sampling plans, incoming material reports, supplier audit reports, exception notices, 8D reports, and concession acceptance approval forms.
New data records are created with each batch of incoming materials. Supplier evaluation updates are completed monthly or quarterly, and ad-hoc audit updates are conducted as needed.
Data fields include batch number, inspection item, judgment result, supplier number, rectification status, and others. No standardized fixed units exist, as fields vary based on document type.

## Constraints Imposed on Deployment and Upgrade Workflows
Data for this category is scattered and has highly inconsistent update rhythms.
During deployment, adapt to multi-source data access and ensure uniform import of information from different sources such as purchase orders and inspection equipment data.
Daily documents have diverse types and inconsistent fields, so flexible parsing rules must be configured during deployment to avoid data parsing failures caused by document format differences.
New data records are created frequently with each batch of incoming materials, so the incremental synchronization function must be maintained during upgrades to avoid interrupting ongoing incoming material inspection data processing.
Data links batch and supplier dimensions, so database indexes must be configured during deployment to support fast queries. Index compatibility must be verified during upgrades to prevent query timeouts or data association errors.

## Configuration Settings
All configuration items below are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://username:password@host:port/fastgpt_iqc` | Dedicated database for storing incoming material batch and supplier quality data; must specify the corresponding business database name |
| `REDIS_URL` | `redis://:password@host:port/1` | Caches frequently accessed supplier audit rules and sampling plans; database index 1 is reserved for business caching |
| `DB_MAX_LINK` | `20–30 connections` | Adapts to concurrent connection requirements for batch import of each incoming material batch; avoids connection exhaustion |
| `STORAGE_S3_ENDPOINT` | `Fill in according to the enterprise's internal object storage address` | Stores document attachments such as inspection reports and 8D reports; must match the enterprise's existing storage configuration |
| `ROOT_KEY` | `Generate a random string according to the enterprise's security policy` | Configures the platform super administrator permission key to ensure access security of business data |
| `FE_DOMAIN` | `https://iqc-quality.example.com` | Specifies the frontend access domain name; adapts to the dedicated access path of the supplier quality module |

## Common Misconfigurations
- The frontend page version number displayed after upgrade does not match the actual deployed version. This occurs because frontend static resource cache was not cleared, causing the system to load old version configuration files.
- An error occurs when clicking the knowledge base module. This is because `MONGODB_URI` was not correctly configured to point to the dedicated database storing knowledge base data, or `DB_MAX_LINK` was set too low, leading to database connection exhaustion.
- The model stream response returned when calling a tool is empty. This is because `REDIS_URL` was not correctly configured to cache tool call context parameters, causing tool call requests to fail to transmit normally.

## How to Verify Successful Configuration
- Run a database connection test to verify that the connection addresses configured in `MONGODB_URI` and `REDIS_URL` can be accessed normally, and the number of connections does not exceed the value set for `DB_MAX_LINK`.
- Upload an incoming material inspection report document to verify that the document can be parsed normally and stored in the specified storage path, and that the `STORAGE_S3_ENDPOINT` configuration takes effect.
- Access the frontend domain name `FE_DOMAIN` to confirm that the page loads normally and the version number matches the actual deployed version.
- Initiate a tool call test to verify that the context cache works normally, and there are no errors of empty model stream responses.

The values provided are common starting points and should be measured against the reader's own samples.
