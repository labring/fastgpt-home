# Quality Problem Traceability and Defect Analysis for Mold Design and Manufacturing: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
This category covers injection molding, stamping, and die-casting mold enterprises, as well as mold centers within manufacturing enterprises. Daily documents include mold design task sheets, DFM reports, part drawings, machining process cards, trial mold reports, mold modification notices, and mold history records. Data sources include customer product models, mold flow or forming simulation results, CAD/CAM files, machining and measurement data, and trial mold samples. Data updates follow project progress, with updates made after each trial mold or mold modification. Core time-consuming steps include reviewing demolding defects, shrinkage issues, and formability, coordinating machining and assembly accuracy for multiple parts, and repeated mold modifications based on trial mold defects. Deliverables are repeat production tooling, which undergoes design, manufacturing, and trial mold iterations, differing from the single-piece delivery model of standard part machining.

## What Constraints These Characteristics Impose on the Multi-turn Dialogue and Prompt Engineering Link
Business data for mold design and manufacturing is scattered and updated iteratively per project. Multi-turn dialogue must gradually guide users to provide key information for corresponding documents, avoiding excessive one-time input that causes context confusion. Professional fields such as demolding angle, shrinkage rate, and number of mold cavities need to accurately match business requirements, so prompts must bind standardized business variables, avoiding parameter deviation caused by general extraction logic. Dialogue must be associated with the current mold project, binding the project identifier via `chatId` to prevent cross-project data confusion. At the same time, dialogue history for trial mold iterations is lengthy, so the number of retained `messages` must be limited to avoid context overload that affects analysis efficiency.

## How to Configure the Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Suggested Setting | Rationale |
| --- | --- | --- |
| Context Binding | Bind `chatId` with the current mold project ID | Ensure dialogue only associates with trial mold and mold modification data for the current project, avoiding cross-project confusion |
| Variable Extraction Rule | Extract demolding angle, shrinkage rate, and number of trial molds as defined in `variables` | Match standard professional fields for mold quality analysis, improving parameter extraction accuracy |
| Historical Message Retention | Retain the first 15 `messages` | Adapt to the dialogue length of a single project iteration, avoiding redundant content overload |
| Context Length Limit | 10000–15000 token | Calibrated based on actual testing, adapting to the total text volume of mold documents |
| Voice Input Configuration | Enable voice input function, associating with the audio field of `messages` | Adapt to on-site trial mold voice feedback collection, supplementing text input scenarios |

## Three Common Misconfigurations
- Phenomenon: Extracted professional parameter fields are empty or extracted incorrectly. Cause: No dedicated extraction rule for `variables` defined for the mold industry, using general prompts cannot match business fields such as demolding angle and shrinkage rate.
- Phenomenon: No text conversion result after voice dialogue. Cause: No configuration of the binding logic between the voice model and `messages`, or the automatic transcription switch for voice input is not enabled, causing voice content to fail to write to the dialogue context.
- Phenomenon: Dialogue context mixes data from other mold projects. Cause: `chatId` is not bound to the current project ID, causing cross-project confusion when multi-turn dialogue calls historical data.

## How to Confirm the Configuration Is Correct
- Test dialogues can be initiated with specific parameters from trial mold reports input. Verify that `variables` correctly extract preset fields including demolding angle and shrinkage rate.
- The `chatId` for different projects can be switched, and the trial mold report for the corresponding project uploaded. Verify that the dialogue context only displays historical content for the current project, with no cross-project data.
- Voice input can be enabled, and on-site trial mold feedback content recorded. Verify that the content is automatically transcribed to text and added to the `messages` list.
- Dialogue history can be viewed, confirming that the number of retained `messages` meets the preset 15-item limit, with no redundant historical messages.

The values provided are common starting points and should be validated using in-house test samples.
