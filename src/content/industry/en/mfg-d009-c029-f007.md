# Quality Problem Traceability and Defect Analysis for Mold Design and Manufacturing: Database and Operations

## What data for this category looks like
This category’s data centers on the full lifecycle of molds. Sources include customer product models, mold flow forming simulation results, CAD/CAM design files, machining and dimensional measurement data, and sample part inspection records. Daily documents cover mold design task sheets, DFM reports, part drawings, machining process cards, mold trial reports, mold modification notices, and mold history records. Data updates are triggered by project milestones. New or modified entries are synchronized after each mold trial, mold modification, or machining process is completed. Each mold project corresponds to an independent set of associated data.

## What constraints these characteristics impose on the database and operations link
The associated data for mold projects is voluminous and isolated per project. This requires the database to support table partitioning or permission isolation by project dimension, to avoid mixing data from different projects. Data update frequency fluctuates with the mold trial and modification workflow. There will be high-frequency write requests during peak periods, so the database connection pool needs to adapt to sudden loads. Data formats vary widely across different sources. CAD files, simulation results, and measurement data each require adapted storage structures, so the database must support storage of multiple data types. Documents such as mold trial reports and mold modification notices must be linked to corresponding mold history records. This requires the database to maintain clear table association relationships, to ensure that full-chain data can be quickly linked during quality problem traceability.

## How to set configurations
The following configurations are optimized for the database and operations link of mold design and manufacturing scenarios, and are compatible with FastGPT v4.17.0.

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `MONGODB_URI` | `mongodb://fastgpt:xxxx@192.168.1.100:27017/fastgpt?authSource=admin` | Multi-type associated data for mold projects is suitable for MongoDB storage; intranet deployment avoids external network security risks |
| `DB_MAX_LINK` | `25–40` | Adapts to the hardware resources of an 8-core 64G server, matches the connection requirements during peak mold data write periods, and avoids connection exhaustion |
| `PG_URL` | `postgresql://fastgpt:xxxx@192.168.1.100:5432/fastgpt_meta` | Structured mold history records and mold trial report metadata are stored in a relational database to ensure associated query efficiency |
| `REDIS_URL` | `redis://192.168.1.100:6379/1` | Caches temporary calculation results and permission verification data for mold projects, reducing repeated query pressure on the primary database |

## Three common misconfigurations
- Symptom: The `getaddrinfo EAI_AGAIN mongo` error appears after an upgrade, and the service cannot start. Cause: The database address in the `MONGODB_URI` configuration was not updated after migrating the database directory, so the service points to an incorrect database instance.
- Symptom: Knowledge base search responses are slow, with a single query taking more than 30 seconds. Cause: The value of `DB_MAX_LINK` is too low, which cannot support concurrent query requests for mold projects, leading to connection queue backlog.
- Symptom: The table models defined in the database cannot be viewed, and the data structure cannot be verified to match business requirements. Cause: The database user was not granted metadata query permissions, or the access account configured in `PG_URL` has insufficient permissions to read table structure information from the relational database.

## How to confirm the configuration is correct
- Execute the database connection test command to verify that the addresses and account information configured in `MONGODB_URI` and `PG_URL` can establish normal connections.
- Check the database connection pool status to confirm that the current number of connections does not exceed the upper limit set by the `DB_MAX_LINK` configuration, and there is no connection backlog.
- Check the running status of the Redis cache service to confirm that the `REDIS_URL` configuration can normally read and write cache data.
- Trigger a mold project mold trial data write operation to verify that data can be correctly stored in the corresponding database collection and tables.

The values provided here are common starting points, and should be evaluated against the reader's own samples.
