# Quality Problem Traceability and Defect Analysis for Mold Design and Manufacturing: Document Parsing and Chunking

## What the Data for This Category Looks Like
For injection molding, stamping, die-casting mold enterprises and mold centers of manufacturing enterprises, daily data mainly comes from customer product models, mold flow or forming simulation files, CAD/CAM exported drawings, machining and measurement data, and sample test records.
Daily documents include mold design task sheets, DFM reports, part drawings, processing technology cards, mold trial reports, mold modification notices, and mold history records.
Data is updated according to project milestones. New version documents are generated after each mold trial or mold modification.
Most documents contain professional technical fields such as number of cavities, mold hardness, geometric tolerances, and machining parameters. Some drawing documents include layer and annotation information.

## Constraints on Document Parsing and Chunking
Documents for mold design and manufacturing have complex, professional structures. They include structured tables, annotated CAD drawings, and multi-version mold trial records. These traits create multiple constraints for document parsing and chunking.
First, multi-version mold trial reports and mold modification notices must be accurately matched to their corresponding mold ID and process link. Contextual associations must be retained during chunking.
Second, CAD-exported PDF drawings include layers and professional annotations. Standard parsing tools often lose key information during processing.
Third, multi-table content in technology cards and mold trial data will split internal parameter associations if chunked incorrectly.
Finally, high-frequency updates tied to project milestones require chunking configurations that can quickly adapt to differing document structures across projects.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `chunkSize` | 800–1200 characters | Mold documents contain professional terminology and structured tables. This range ensures that a single chunk contains complete technical descriptions or a single set of parameters, avoiding context fragmentation |
| `customPdfParse` | Enable pdf-marker v2 mode | Adapts to CAD-exported PDF drawings with layers, retains layer information and professional annotations, and prevents loss of drawing content after parsing |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 seconds | Large mold CAD drawings take a long time to parse. This duration covers the parsing process for most complex documents, preventing mid-process timeout interruptions |
| `chunkSplitter` | Split by paragraph + table | Adapts to structured content in mold trial reports and processing technology cards, retains complete parameter associations within tables, and prevents incorrect table splitting |
| `chunkSettingMode` | Manual configuration | Adapts to the differentiated structures of project-specific documents. Chunking rules can be adjusted separately for mold trial reports and drawing documents to meet professional scenario requirements |

## Three Common Configuration Mistakes
- Chunking results only extract more than 30 table entries and omit the remaining items. Cause: No corresponding chunking rules are configured for the multi-table structure of technology cards and mold trial data, and the default chunking logic does not retain the complete range of tables.
- Parsing CAD drawings using `customPdfParse` returns a parsing failure. Cause: The pdf-marker v2 version is not correctly deployed, or the parsing mode is not specified in the configuration.
- The interface returns a parameter error when uploading multiple files. Cause: The multi-file parameters are not nested into the content array as required, or the parameter format of the messages structure is not correctly configured.

## How to Verify Correct Configuration
- Upload a standard mold trial report PDF, and check whether the chunking results include complete defect description paragraphs and mold modification record entries.
- Check the parsing logs of FastGPT v4.17.0 to confirm that the `PARSE_FILE_TIMEOUT_SECONDS` configuration does not trigger timeout errors.
- Test the multi-file upload interface to verify that all uploaded files are correctly parsed and corresponding chunks are generated.
- Adjust the `chunkSize` parameter, compare the context association of the chunking results, and confirm that it meets the reading and retrieval requirements of professional documents.
