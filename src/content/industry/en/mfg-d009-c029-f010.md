# Quality Problem Traceability and Defect Analysis for Mold Design and Manufacturing: Knowledge Base Retrieval and Recall

## Data Profile for This Category
Core data for this category originates from injection molding, stamping, and die-casting mold enterprises, as well as mold centers within manufacturing enterprises. Daily stored documents include mold design task sheets, DFM reports, part drawings, processing technology cards, trial mold reports, mold modification notices, and mold history records. Data sources include customer product models, mold flow/forming simulation files, CAD/CAM source files, machining and measurement data, and records associated with trial mold samples. Updates trigger when projects progress, or after each trial mold or mold modification. Most documents include fields such as geometric parameters, process requirements, and defect records. Formats adjust flexibly based on project needs, with no unified fixed template.

## Constraints on Knowledge Base Retrieval and Recall
Professional documents for this category include subdivided fields like geometric parameters, process requirements, and defect records, with formats adjusted flexibly per project. This requires retrieval to accurately match professional terminology and project-specific information. Multi-source heterogeneous data sources create format inconsistencies, so retrieval must adapt to different content types including CAD files, simulation reports, and measurement records for recall. Updates follow project, trial mold, and mold modification cycles, so the knowledge base must support fast synchronization of the latest mold modification records and trial mold defect data to prevent retrieval of outdated content. Quality traceability also requires linking data across multiple stages, so retrieval must cover associated information across the full design, machining, and trial mold workflow.

## Configuration Guidelines
This configuration scheme is compatible with FastGPT v4.17.0.

| `collectionIds` | `Bind exclusive knowledge base collections per project` | Isolates mold data across different projects, avoids recalling irrelevant cross-project documents |

## Three Common Misconfigurations
- Phenomenon: When uploading documents such as mold design task sheets and DFM reports, the interface returns the error "Request failed with status code 400". Cause: The format requirements for mold professional documents are not adapted, or the uploaded file size exceeds the knowledge base's single upload threshold.
- Phenomenon: When retrieving content related to quality problems, only a single part drawing is returned, and cannot link corresponding trial mold report defect records and mold modification notices. Cause: Cross-document associated recall is not configured, or `searchMode` is only set to a single retrieval mode.
- Phenomenon: Retrieval results include mold modification records that have not been updated for more than 3 months. Cause: The knowledge base's bound collection is not refreshed according to project trial mold and mold modification cycles, or incremental synchronization configuration is not enabled.

## How to Confirm Successful Configuration
- Enter a professional question about mold trial mold defects, verify that recall results include associated documents such as trial mold reports and mold modification notices for the corresponding project.
- Upload a latest mold modification notice, trigger knowledge base synchronization, then retrieve content related to the mold modification, confirm the results include the latest records.
- Adjust any retrieval configuration item, compare the relevance and quantity of recall results before and after adjustment, confirm the configuration takes effect.
- Check that the knowledge base's bound collections are isolated per project, to avoid recalling irrelevant cross-project documents.
