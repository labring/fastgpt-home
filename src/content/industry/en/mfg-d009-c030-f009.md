# Quality Problem Traceability and Defect Analysis for Rubber Mixing and Product Vulcanization: Model Access and Configuration

## What data for this category looks like
Data for this category comes from formula management systems, raw material batch ledgers, internal mixers, Mooney viscometers, vulcanizing presses, and laboratory testing systems. Daily documentation includes formula sheets, weighing and feeding records, mixing temperature curves, rubber quick test reports, vulcanization process cards, mold usage records, and finished product performance test reports.

Data updates occur per raw material batch, per mixed rubber batch, and per vulcanized product per mold. Fields include united process parameters such as mixing temperature (℃), vulcanization duration (seconds), and Mooney viscosity values. Batch identifiers link to multi-stage circulation records.

## Constraints on model access and configuration from this category's data characteristics
The high-frequency, multi-stage linked data characteristics of this category impose multiple constraints on model access and configuration.
First, high-frequency updates per batch and per mold require configuration adapted to short-cycle data recall, to avoid context overload that slows response times.
Second, multi-source heterogeneous process parameters and batch data need configuration for matching field association rules, to ensure recalled content includes complete parameters for corresponding stages.
Third, united process fields require configuration to retain original units during recall, to prevent parameter ambiguity.
Fourth, cross-device circulation data needs configuration for batch-linked context splicing rules, to ensure complete traceability links.

## How to configure settings
| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | Enter the enterprise's privately deployed OneAPI forwarding address | Adapts to bulk call requirements for multi-source batch data in this category, avoids public network interface latency |
| `AIPROXY_API_TOKEN` | Generate a dedicated token with workshop data isolation permissions | Prevents unauthorized access to cross-workshop batch data, complies with production data security standards |
| `maxContext` | 8000–12000 token | Matches the document length of multiple linked mixing and vulcanization stages per mold, avoids truncation of critical process parameters |
| `quoteMaxToken` | 1500–2000 token | Retains complete fields for a single batch record, ensures recalled formula and process content is not missing |
| `temperature` | 0.2–0.4 | Reduces answer randomness, ensures accuracy of process parameters and traceability results |
| `toolChoice` | auto | Automatically triggers recall of linked batch documents, adapts to complex queries for multi-stage traceability |

## Three common configuration errors
- Model calls fail in the interface, returning a 401 unauthorized status code. The cause is failure to synchronously update `AIPROXY_API_TOKEN` and `AIPROXY_API_ENDPOINT` in FastGPT configuration, which interrupts the OneAPI forwarding link.
- Knowledge base recall results only include scattered parameters, do not link to complete batch links, and response content is overly concise. The cause is that `quoteMaxToken` is set too small, truncating complete fields of a single document and preventing output of specific process clauses.
- Single knowledge base search takes more than 30 seconds, or question-answer splitting fails to distinguish between mixing and vulcanization stages. The cause is that `maxContext` is set too large, causing context overload, or `toolChoice` is not configured as auto, so automatic linked recall is not triggered.

## How to confirm configuration is complete
- Call the FastGPT built-in model test interface, check that returned `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` match the privately deployed OneAPI parameters.
- Submit a query containing a specific mixing batch number, confirm that recall results include complete contents of the corresponding batch's weighing records, mixing curves, and vulcanization process cards.
- Adjust the `temperature` parameter to 0.3, submit the same query three times, confirm that answer content consistency meets expectations.
- View the FastGPT v4.17.0 backend logs, confirm that token consumption for model calls falls within the range set by `maxContext` and `quoteMaxToken`.
