# Quality Issue Traceability and Defect Analysis for Cement Clinker and Grinding: Multi-turn Dialogue and Prompt Engineering

## What this category of data looks like
Data sources include online composition analysis equipment, DCS control systems, laboratory testing systems, kiln and grinding operation equipment, raw fuel ledgers, and energy metering systems. Data update frequencies are divided into real-time (kiln temperature, batching flow), per shift (inspection records, energy reports), and daily (laboratory reports, quality control notices). Daily documents include raw material batching plans, kiln operation records, laboratory reports, quality control notices, equipment inspection logs, and energy consumption reports. Fields cover clinker free calcium, specific surface area, furnace thermal parameters, raw fuel ratio, equipment operating duration, and more. Matching the metering standards of corresponding data sources is required, and there is no unified fixed unit.

## What constraints these characteristics impose on the multi-turn dialogue and prompt engineering link
Due to scattered data sources and significant differences in update frequencies, multi-turn dialogue must guide users to clearly specify data type and time range, to avoid confusion between real-time operation data and historical test reports. Prompts must clearly distinguish field rules for different documents. For example, strength indicators in laboratory reports must match test batches, and DCS data must be associated with specific equipment numbers. Additionally, quality traceability requires associating multi-dimensional data. Multi-turn dialogue must retain historical interaction parameters to ensure context coherence and avoid repeated requests for supplementary information from users. Production data also has permission restrictions. Configurations must bind access rules of corresponding systems to prevent unauthorized queries of sensitive production information.

## How to set the configurations
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| Maximum context length | `15000–20000 characters` | Associated documents for cement clinker and grinding usually include multiple rounds of inspection, laboratory, and batching data. A longer context can cover a complete traceability chain and adapts to the session storage limit of FastGPT v4.17.0 |
| Question optimization switch | Enabled | Automatically completes unspecified parameters from users, such as supplementing shift and equipment numbers, to meet the information completion requirements of multi-turn dialogue |
| Single recall limit | `Top 8 entries` | Balances data relevance and response speed, avoiding excessive redundant information interfering with defect analysis judgments |
| Context retention duration | `72 hours` | Covers the traceability cycle of shift handover, meeting cross-shift quality issue traceability needs |
| `variables` configuration | Bind access keys and permission ranges of laboratory systems and DCS | Ensures that dialogue can securely call production data from corresponding systems, avoiding permission errors |
| `messages` management | Automatically retain the last 10 rounds of interaction content | Reuses historical dialogue parameters, reducing the cost of repeated information input by users |

## Three common misconfigurations
- A dialogue returns 401 No auth credentials found. The cause is that access keys for associated laboratory systems or DCS have not been configured in `variables`, and permission binding for production systems has not been completed.
- Multi-turn dialogue cannot obtain quality data for a specified date. The cause is that the prompt fails to guide users to supplement shift and test batch parameters, and fails to reuse historical context information in `messages`.
- Download of BLOB-format laboratory reports cannot be triggered in dialogue. The cause is that the file access permission of the user session has not been bound via `chatId`, and response header parameters for the HTTP node have not been configured.

## How to confirm the configuration is correct
- Initiate a test dialogue, input "Query the inspection records of the rotary kiln on June 15, 2024", verify that corresponding document fragments for the date are returned and no permission errors occur.
- Test multi-turn dialogue: first input "View the 3-day strength data of clinker on the day", then supplement "Combine the raw material batching plan of the day", verify that the context is correctly retained and the two sets of data can be associated.
- Trigger a request to generate a BLOB-format laboratory report, verify that a clickable download link appears in the dialogue interface.
- Check the key configuration in `variables`, initiate cross-system data queries, confirm that no permission-related errors occur.
