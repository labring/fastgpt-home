# Quality Problem Traceability and Defect Analysis for Complete Vehicle Final Assembly: Multi-turn Dialogue and Prompt Engineering

## What data belongs to this category
Data sources for this category include ERP/MES systems, VIN and configuration systems, supplier batch databases, tightening tools, end-of-line (EOL) inspection lines, and quality traceability systems. Daily documents include production orders, VIN lists, assembly work instructions, tightening torque data, off-line inspection reports, rework records, and consistency release documents.
Data is updated in real time for each vehicle, and updated in batches per shift. VIN is used as the core identifier for individual vehicles. This requires matching hundreds of vehicle configuration and corresponding part information, and managing torque parameters for critical connection processes.

## Constraints imposed on multi-turn dialogue and prompt engineering
The core vehicle data tied to VIN requires multi-turn dialogue to always bind the context of the corresponding VIN, to avoid mixing data across vehicles. Real-time updated tightening and inspection data requires prompt engineering to support dynamic loading of the latest station data. Dialogue context must not exceed the time range of the current batch.
For large-scale mixed-line assembly scenarios, prompt engineering must clearly distinguish configuration rules for different vehicle models. Multi-turn dialogue must retain historical records of station operations to facilitate tracing of defect-generating station links.
Large volumes of structured torque and inspection data require prompt engineering to specify parsing rules for data fields, to avoid deviations from unstructured interpretation.

## Configuration guidelines
The following configurations are tested on FastGPT v4.17.0:

| Configuration Item | Recommended Approach | Rationale |
| --- | --- | --- |
| `chatId` | Bind the unique identifier of the current VIN | Ensure independent dialogue context for each vehicle, avoid data mixing |
| `messages` | Retain the most recent 20 turns of dialogue records | Cover the full process from assembly to rework for a single vehicle |
| `variables` | Inject the current VIN, station number, and batch number | Enable prompt engineering to dynamically call structured data for the corresponding vehicle |
| Maximum context length | 8000–12000 token | Adapt to context requirements for hundreds of configuration and multi-station data items per vehicle |
| Single recall limit | Top 10 matching data entries | Control retrieval scope, avoid interference from irrelevant historical data during analysis |
| Question optimization | Calibrate based on actual measurements | Adapt to defect description habits in final assembly scenarios, optimize the accuracy of multi-turn follow-up questions |

## Three common configuration errors
- Symptom: The dialogue interface displays "No permission to operate this conversation record". Cause: The `chatId` bound to the current VIN is not associated with the permission configuration of the corresponding station account, resulting in inability to access exclusive dialogue context across accounts.
- Symptom: The AI prompts that no files have been uploaded, and cannot read the assembly work instruction content embedded in the system prompt. Cause: Work instructions were not split and embedded into `variables` according to vehicle model configuration, or document chunks did not match the prompt's reading rules.
- Symptom: After upgrading and refreshing the page, the current vehicle's dialogue record disappears, and a new dialogue is displayed. Cause: `chatId` is not persistently bound to the VIN identifier, and the historical dialogue data corresponding to the VIN is not automatically loaded after the page refresh.

## How to verify successful configuration
- Enter a test VIN, check if the dialogue interface automatically loads associated information such as the corresponding vehicle model's configuration and tightening data.
- Initiate multi-turn follow-up questions, confirm if the dialogue context retains defect descriptions and processing records from previous stations.
- Trigger a document reading test, confirm that the work instruction content embedded in the system prompt can be called normally.
- Refresh the page, confirm that the current VIN's dialogue record is not lost and still displays as historical session content.

The values provided here are common starting points and should be evaluated against the reader's own samples.
