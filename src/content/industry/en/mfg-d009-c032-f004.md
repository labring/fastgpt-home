# Quality Problem Traceability and Defect Analysis for Complete Vehicle Final Assembly: Workflow Orchestration

## What the data for this category looks like
Business data sources for complete vehicle final assembly include ERP/MES systems, VIN and vehicle configuration systems, supplier batch management systems, workshop tightening tools, End-of-Line (EOL) off-line inspection lines, and quality traceability systems. Each individual vehicle triggers real-time data generation, covering two update rhythms: per-vehicle assembly and shift-level summary. Daily documents include production orders, VIN lists, assembly work instructions, tightening torque data, off-line inspection reports, rework records, and consistency release documents. Core fields include 17-digit standard VIN codes, tightening torque values, part batch numbers, inspection result values, and similar items.

## What constraints these characteristics impose on workflow orchestration
Full-traceability per vehicle centered on VIN requires workflows to use the VIN code stored in `variables` as the only matching identifier for node flow, to avoid data cross-interference in mixed-model production. Real-time generated tightening data and off-line inspection results require workflow nodes to support low-latency triggering, and fixed-period batch scheduling cannot be used. Matching requirements for hundreds of configuration and part information per vehicle require workflows to split into multiple step-by-step verification nodes, to control the context length of a single node. Associated traceability of rework records and quality issues requires workflows to configure abnormal branch processing logic, to ensure defects can be traced through the complete chain.

## How to set configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Global variable initialization | Bind the VIN code and part batch number fields in `variables` | Match the business logic of identifying single-vehicle data using VIN as the unique identifier, to prevent data cross-interference across the full traceability chain |
| Node triggering rule | Trigger based on the station event bound to `nodeId` | Adapt to the real-time assembly rhythm of mixed-model production in workshops, to achieve precise association between data and station actions |
| Single context upper limit | 800–1200 characters | Adapt to the typical length of single-vehicle configuration information, to avoid workflow node context overflow |
| Node timeout threshold | 600 seconds | Adapt to the typical delay of workshop data transmission, balancing node waiting cost and data integrity |
| Abnormal branch retry count | 3 times | Address occasional exceptions in tightening data and inspection data transmission, to ensure data completeness |
| Recall result upper limit | Top 5 entries | Adapt to the typical number of single-vehicle defect records, to avoid interference from redundant information during analysis |

## Three common mistakes
- Symptom: An "Input is empty" prompt appears when debugging workflow nodes, and global variable values are lost after cross-node flow. Cause: Global synchronous update of `variables` is not configured, and variable modifications only apply to the current node without being synchronized to the global context.
- Symptom: The temperature parameter setting button cannot be found in the large model node. Cause: The advanced settings area of the large model node configuration panel is not expanded, as the temperature parameter is collapsed and hidden by default.
- Symptom: Corresponding documents cannot be recalled after associating a knowledge base, with a "No matching knowledge base found" prompt. Cause: The correct knowledge base ID was not copied from the FastGPT knowledge base management page, and the document name was directly used as the association parameter.

## How to confirm the configuration is complete
- Open the global variable configuration panel of FastGPT v4.17.0 workflow, confirm that core business fields such as VIN code and part batch number are bound in `variables`, and the field values match the test cases.
- Trigger a simulated station assembly event, check whether the node starts normally according to the preset rules, and no timeout-related error prompts appear.
- Adjust the single context upper limit parameter, verify that the workflow node can normally load vehicle configuration information of the corresponding length, with no context overflow warnings.
- Trigger a simulated data exception scenario, check whether the workflow executes the abnormal branch according to the configured retry count, and completes data verification or retries.
