# Quality Problem Traceability and Defect Analysis for Baked Goods and Convenience Foods: Workflow Orchestration

## What the Data for This Category Looks Like
This category’s data covers the full production process of bread, pastry, biscuit, instant noodle, and frozen pastry factories. Daily documents include formulas and feeding lists, production records, baking or steaming curves, metal detection records, cleaning and disinfection records, and factory inspection reports. Data sources are raw and auxiliary material qualification certificates, ERP/MES systems, weighing systems, oven or frying line equipment, laboratories, and food traceability ledgers. Updates run per batch, per shift, or daily. Fields include material name, batch number, test values, timestamps, and similar items, with no additional custom units.

## What Constraints These Characteristics Impose on Workflow Orchestration
This category has a large number of formulas and frequent product line changes. Workflows must support quick switching of data sources and validation rules. High-frequency updated data across multiple batches requires workflow nodes to pull data in real time without caching old data. High demand for allergen and cleaning switching requires workflows to dynamically bind different materials and cleaning standards using variables. Ready-to-eat product attributes require workflows to cover the entire quality verification link for foreign matter, microorganisms, and similar items, and strictly match the traceability requirements of each production batch.

## How to Configure Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `variables` | Bind raw and auxiliary materials and production record fields per batch | Matches formula and feeding verification requirements for multi-batch line changes in this category |
| `nodeId` | Bind node IDs for ovens and metal detection equipment | Corresponds to scenarios of real-time pulling of baking curves and foreign matter detection data |
| Data source trigger timing | Trigger after each batch of production is completed | Matches the per-batch data update frequency |
| Single recall limit | Top 8 entries | Adapts to the data volume of single-batch production and test records |
| Timeout setting | 600 seconds | Adapts to time consumption requirements for multi-source data pulling |
| Knowledge base binding rules | Bind corresponding knowledge bases by product category | Matches knowledge base requirements for multi-product line changes in this category |

*Configuration values are common starting points and should be measured against your own samples.*

## Three Common Configuration Mistakes
- An error occurs when passing parameters via `variables` during workflow database calls, but manual SQL execution works normally. Cause: Variables are not correctly bound to the parameter entry of the corresponding node, leading to failed parameter transmission.
- Real-time knowledge base switching is not supported in the workflow. Cause: The trigger logic for knowledge base switching between nodes is not configured, and a single knowledge base node is fixedly bound.
- No return result is obtained after the workflow calls a tool, or the returned result format does not meet expectations. Cause: `nodeId` is not correctly bound to the corresponding tool node, or the output format verification rule is not configured.

## How to Verify the Configuration Is Correct
- Trigger a simulated batch production workflow and check whether the formula and test data for the corresponding batch are pulled successfully.
- Manually pass test variables to verify that the database query returns the corresponding results normally.
- View the workflow node logs to confirm that the `variables` parameter and `nodeId` configuration are correctly matched.
- Simulate an allergen material switching scenario and check whether the workflow triggers the corresponding verification link.
