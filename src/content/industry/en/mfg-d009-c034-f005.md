# Quality Issue Traceability and Defect Analysis for Baked Goods and Convenience Foods: Tool Calling and Plugins

## What the Data for This Category Looks Like
This category's data originates from various business documents of bakeries, cookie, instant noodle, and frozen pastry factories, including formulas and feeding lists, production records, baking/steaming curves, metal detection records, cleaning and disinfection records, and factory inspection reports. Data sources cover raw and auxiliary material qualification certificates, ERP/MES systems, weighing equipment, production lines, laboratories, and food traceability ledgers. Updates are performed per production batch, shift, or daily. Data fields include specific business information such as allergen material labels, baking/frying temperature and duration, foreign object detection results, packaging dates, and shelf life.

## Constraints for Tool Calling and Plugins
The multi-batch, multi-document characteristics of this category require tool calling to support quick retrieval of corresponding documents by production batch, to avoid interference from cross-batch data. The high-frequency demand for allergen and cleaning switching requires plugins to integrate allergen compliance verification and production line cleaning status check logic. Format differences from multiple data sources require tool calling to unify data parsing rules to adapt to document structures exported by different systems. Additionally, the large data volume per single batch requires limiting the number of entries returned by a single tool call to prevent response timeouts.

## Configuration Settings
This configuration is formulated based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `auto` | Supports automatic calling logic for multiple types of plugins, no manual specification of tool types required |
| `functionCall` | Enabled | Supports structured return of tool call results to facilitate subsequent data organization |
| Single Search Limit | Top 3 entries | Matches core business documents for a single batch, avoids loading redundant data |
| Maximum Context | 7000–9000 token | Accommodates content from multiple production records and inspection reports, adjust based on actual measurements |
| Timeout Threshold | 15 seconds | Adapts to response speed requirements for production line data retrieval, avoids prolonged wait times |
| Query Optimization | Enabled | Restructures traceability query statements to align with professional field naming rules for food production ledgers |

## Three Common Misconfigurations
- Symptom: The tool calling module continuously outputs detailed running logs, occupying conversation display space. Cause: The log output configuration for tool calling is not disabled, and full log printing is enabled by default.
- Symptom: A single quality traceability query takes more than 10 seconds, and the interface shows a response timeout. Cause: The number of return entries for a single search is not limited, too much cross-batch redundant production data is loaded, or the timeout threshold does not match production line data volume requirements.
- Symptom: In the structured results returned by the tool call, the content of the subsequent field overlaps with the output of the previous field, for example, allergen verification results and production record content are mixed. Cause: The parameter verification logic for `functionCall` is not enabled, leading to incorrect isolation of context between multiple rounds of tool calls, and abnormal data overwriting rules.

## How to Verify Proper Configuration
- Initiate an allergen traceability query for a specific batch of bread, check whether the tool call automatically matches the corresponding compliance verification plugin without manual tool type selection.
- View the response duration of the tool call, confirm that the return is completed within the set timeout threshold.
- Export the structured results of the tool call, check that there is no overlap or overwriting of content across fields.
- Verify the number of returned document entries, confirm that it matches the single search limit setting.

The values provided are common starting points and should be measured against the reader's own samples.
