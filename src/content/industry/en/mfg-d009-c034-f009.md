# Quality Problem Traceability and Defect Analysis for Baked Goods and Convenience Foods: Model Access and Configuration

## What this category's data looks like
This category covers end-to-end production and testing records from bakeries, pastry shops, cookie, instant noodle, and frozen dough product factories. Daily documents include formulas and feeding lists, production records, baking or steaming curves, metal detection records, cleaning and disinfection records, and factory inspection reports. Data sources include raw and auxiliary material qualification certificates, ERP/MES systems, weighing systems, oven and frying line equipment, laboratory test results, and food traceability ledgers. Updates occur per production batch, shift, or daily. Fields include feeding quantity, baking temperature and duration, allergen labels, metal detection results, packaging dates, shelf life, and additional relevant items.

## Constraints on model access and configuration workflows
The multi-source, batch-updated data characteristics of this category create clear constraints for model access and configuration. Data formats vary widely across production links, requiring adaptation to structured extraction for multi-source data. Production batches are dense and line changes happen frequently. Models must quickly switch context for target batches to avoid mixing cross-batch data. Fields tied to allergen and foreign matter control have strict precision requirements. Models must accurately identify compliance for specific fields. Data update frequency aligns with production rhythm. Model call response speed must match the production process time window to avoid delays in traceability analysis.

## Three common configuration errors
- Symptom: An error occurs after adding a locally deployed Qwen 3 model to the configuration, with a prompt stating the model only supports streaming output. Cause: Streaming call parameters for the model were not configured correctly, and non-streaming data processing requirements for batch traceability analysis of this category were not addressed.
- Symptom: ChatTTS deployed via Xinference passes curl testing normally but returns code 500 after connecting to AIPROXY, with the prompt "Cannot read p". Cause: AIPROXY model mapping parameters were not configured correctly, leading to failure to recognize the format of the third-party deployed speech model.
- Symptom: Batch-corresponding baking curve data is missing or misplaced in traceability results output by the model. Cause: The value of `maxContext` is too small, truncating critical baking duration and temperature curve data and preventing the model from fully associating batch information with quality abnormalities.

## How to verify successful configuration
- Upload complete single-batch production records and test reports, and verify that model output traceability results include all required fields such as feeding quantity, baking parameters, and allergen labels.
- Simulate cross-batch traceability requests, and check that the model correctly distinguishes production data from different shifts to avoid batch mixing.
- Call the AIPROXY interface, and confirm the returned response status code is 200, with no missing fields or garbled characters in the response content.
- Adjust the `temperature` parameter, call the same test request multiple times, and confirm that the consistency of output results meets expectations.

The values given are common starting points and should be measured against the reader's own samples.
