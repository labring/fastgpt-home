# Heat Treatment Quality Problem Traceability and Defect Analysis: Workflow Orchestration

This configuration is based on FastGPT v4.17.0.

## What this category's data looks like
Data sources include material grade archives, customer technical specification documents, temperature control instruments, furnace temperature uniformity testing equipment, hardness testers, metallographic equipment, and workshop MES systems. Data is updated once per furnace load or batch. Daily generated documents include heat treatment process cards, furnace loading diagrams, furnace temperature curves, hardness and metallographic reports, equipment inspection sheets, and exception handling sheets. Document fields include furnace number, heating temperature, holding time, measured furnace temperature, hardness test values, and corresponding units such as degrees Celsius, hours, HV, etc.

## Constraints on the workflow orchestration link
Since data is updated in batches per furnace load, the workflow must match logic that triggers once for a single furnace load or batch. Multi-source heterogeneous data sources require workflow nodes to pull data sequentially by type. For example, first obtain process card information, then read furnace temperature curves and equipment inspection data, and finally associate hardness and metallographic reports. Diverse document formats require the workflow to adapt to different input types including text, tables, and images. Errors may lead to unqualified performance of all parts in a furnace load, so the workflow must be configured with exception capture and retry nodes to avoid invalid execution. It is also necessary to associate the furnace loading position and furnace temperature curve verification logic to ensure data matching accuracy.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Trigger Mode | Trigger by furnace load batch | Match the data update rhythm of each furnace load and batch to avoid repeated execution |
| Timeout Period | 1800 seconds | Cover the multi-source data pulling, analysis, and verification duration of the full process for a single furnace load, adapt to execution scenarios exceeding 1200 seconds |
| File Upload Node Format | Support PDF, CSV, and image formats | Adapt to the upload of different types of documents including process cards, furnace temperature curves, and hardness reports |
| External Search Node | Enable Tavily Search API | Supplement reference data for industry exception cases and process standards |
| `variables` | Bind furnace number, material grade, customer number | Associate batch data in the MES system to achieve precise traceability |
| `nodeId` | Assign node IDs by data source | Differentiate processing nodes for different data sources such as temperature control instruments, hardness testers, and metallographic equipment |

## Three common misconfigurations
- Workflow node error shows premature close. The cause is that no format verification rules are configured for the file upload node, causing non-standard format furnace temperature curve images or CSV files to fail normal parsing, triggering an early connection close.
- Workflow execution times out exceeding 1200 seconds. The cause is that no reasonable timeout threshold is set, and large-batch furnace load data processing nodes are not split, causing single-node processing duration to exceed the system default limit.
- The workflow cannot call Tavily search to supplement exception data. The cause is that the trigger condition of the external search node is not correctly configured in the workflow, and it is not associated with the node in the exception analysis link, causing the search request to fail to trigger.

## How to confirm the configuration is complete
- Manually trigger the workflow bound to a test furnace number, check whether it can correctly pull the heat treatment process card and furnace temperature curve data of the corresponding batch.
- Upload a test exception handling sheet file, confirm that the file upload node can parse normally and pass data to subsequent analysis nodes.
- Adjust the test parameters in `variables`, check whether the workflow can correctly associate the hardness and metallographic reports corresponding to the material grade.
- View the workflow execution log, confirm that the overall execution duration does not exceed the preset 1800 second threshold.

The values provided are common starting points and should be evaluated against the reader's own samples.
