# Heat Treatment Quality Problem Traceability and Defect Analysis: Tool Calling and Plugins
## What the data for this category looks like
Data sources for this category include material grade ledgers, customer technical requirement documents, temperature control instrument collection data, furnace temperature uniformity test reports, test results from hardness testers and metallographic equipment, and workshop MES systems. Data updates follow a per-furnace batch, per-lot rhythm. Daily generated documents include heat treatment process cards, furnace loading layout diagrams, real-time furnace temperature curves, part hardness and metallographic analysis reports, equipment inspection sheets, and exception handling sheets. Data fields include furnace temperature range (unit: ℃), holding time (unit: hours), furnace loading batch number, hardness test value (unit: HRC), and others, all corresponding to professional process requirements.

## What constraints these characteristics impose on the "tool calling and plugins" link
The high-frequency update requirement per furnace batch means tool calling must support short-cycle triggering to avoid excessive waiting that causes data lag. The coexistence of multiple types of heterogeneous documents (curves, tables, text) means plugins must adapt to different file format parsing, and a single-scenario parsing logic cannot be used universally. The professional units of data fields (such as ℃, HRC) mean tools must retain original units during calling to avoid conversion errors affecting analysis results. The need to batch associate multi-source data means plugins must support batch transfer of multi-file parameters, and cannot only handle single-file input. The associated traceability requirement for exception handling sheets means tool calling must support precise association of all data for the corresponding furnace batch by batch number.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale for This Setting |
| --- | --- | --- |
| Tool calling trigger timing | Trigger by furnace batch number | Matches the rhythm of data updates per furnace batch, avoids duplicate invalid calls |
| File parsing rules | Adapt separately by document type | Adapts to the heterogeneous format requirements of process cards, furnace temperature curves, and test reports |
| `toolChoice` | Auto | Adapts to the flexible needs of multi-type tool calling, FastGPT v4.17.0 supports this configuration |
| Parameter transfer limit | 10 files per call | Matches the upper limit of documents associated with a single furnace batch, avoids call overload |
| Timeout threshold | 600 seconds | Adapts to the parsing time of large-volume furnace temperature curves, calibrated based on actual measurements |
| Number of results returned | Top 8 abnormal associated data | Matches the number of typical abnormal types that need to be covered in daily analysis |

## Three common mistakes
- "Parameter format not supported" error is returned during calling: The cause is that parsing rules are not configured by document type, and the furnace temperature curve is parsed as plain text, resulting in format errors.
- Plugin call timeout: The cause is that the set timeout threshold is lower than the parsing time of large-volume furnace temperature curves, and the parameters are not adjusted based on actual measurements.
- Unable to transfer file type variables to the plugin: The cause is that the plugin input items and file parameters are not correctly bound, which is a common error scenario for API call file parameter transfer.

## How to confirm the configuration is complete
A single furnace batch tool call is initiated, and automatic association of the corresponding batch’s process card, furnace temperature curve and test report is verified.
A standard furnace temperature curve file is uploaded, and extraction of core fields such as furnace temperature range and holding time after parsing, plus retention of original units, is confirmed.
The tool chain with `toolChoice` set to auto is invoked, and automatic selection of matching parsing and analysis tools based on input data is verified.
A call request with multiple documents is sent, and correct receipt and processing of all incoming file parameters by the plugin is confirmed.

The values provided are common starting points and should be evaluated against samples relevant to the specific use case.
