# Quality Issue Traceability and Defect Analysis for Welded Structural Component Manufacturing: Deployment and Upgrade

## What the data for this category looks like
Business data for welded structural component manufacturing includes standardized documents such as welding procedure qualifications, welding procedure specifications, filler metal issue records, welder qualification records, weld inspection reports, and repair work orders. Data sources include design drawings, material quality certificates, welding equipment parameters, filler metal warehouse management systems, non-destructive testing systems, and personnel qualification ledgers. Data updates occur per weld, per batch of filler metal, or per work shift. Each single data entry links multiple dimensional fields, including base material quality, welding current and voltage, inspection images, and operator qualifications. There is no unified fixed unit. Parameters are dynamically matched to the corresponding business link.

## How these data characteristics constrain deployment and upgrade
The high-frequency, multi-source, and highly correlated data traits of this category create multiple constraints during deployment. First, high-frequency weld-level data updates require database connection pool configurations tuned for high read-write traffic. This prevents connection exhaustion that disrupts business continuity. Second, the need to integrate multi-source heterogeneous data requires configuring multi-data source connection parameters to support different formats from equipment interfaces and ledger systems. Third, single weld data entries link multiple dimensional fields, so vector storage capacity must match the needs of storing variable-length content. Finally, traceability requirements mandate retaining full-process historical data. Define clear data retention periods and cleanup strategies to align with business compliance rules.

## How to set configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://username:password@host:27017/fastgpt_welding?authSource=admin` | Adapts to storage needs for multi-source welding business data, specifies a dedicated database name to isolate business data |
| `REDIS_URL` | `redis://:password@host:6379/0` | Used to cache frequently queried welder qualification and filler metal inventory information, reducing database load |
| `DB_MAX_LINK` | `20–30` | Matches concurrent read-write requirements at the weld level, prevents connection pool resource exhaustion |
| `FE_DOMAIN` | `http://192.168.1.100:3000` or corresponding local area network domain name | Allows production site devices on the local area network to access the console, adapts to on-site deployment scenarios |
| `FILE_TOKEN_KEY` | Randomly generated 32-character string | Used to encrypt file upload tokens, prevents unauthorized access to sensitive files such as welding procedure documents |
| `STORAGE_S3_ENDPOINT` | `http://minio-host:9000` | Used to store unstructured data such as non-destructive testing images and repair work orders, adapts to welding business storage needs |

This configuration applies to FastGPT v4.17.0.

## Three common configuration mistakes
- Scenario: The service fails to start after modifying the administrator password, or the console login prompt shows permission exceptions. Cause: Environment variable configurations are not properly synchronized, and updated permission parameters are not loaded when restarting the service.
- Scenario: Devices on the local area network cannot access the console using the external IP of the deployment machine, only the container internal IP works normally. Cause: The `FE_DOMAIN` configuration is only bound to the container internal IP, and is not set to an address accessible externally on the local area network.
- Scenario: After configuring a secondary directory via Nginx, page loading fails or interface requests return 404 errors. Cause: Only the front-end framework BasePath configuration is modified, and the path prefix in `FE_DOMAIN` is not updated synchronously, resulting in mismatched resource request paths.

## How to confirm the configuration is successful
- Execute the status check command for the corresponding deployment method, and confirm all FastGPT-related processes are running.
- Access the address configured in `FE_DOMAIN`, log in to the console, and enter the data connection test page to confirm database and Redis connections are working normally.
- Upload a welding procedure specification document, trigger the vector generation and storage process, and confirm no errors occur during file upload and index generation.
- Simulate a weld traceability query request, and verify that returned results include linked fields such as base material information, welding parameters, and inspection records.
