# Quality Problem Traceability and Defect Analysis for Electric Motor and Generator Manufacturing: HTTP Interfaces and External Systems

## What this category of data looks like
Data for this category comes from daily documents of motor factory winding, insulation, final assembly and testing departments, including winding process cards, insulation treatment records, dynamic balance reports, voltage-resistant insulation test records, and type and factory test reports. Data sources cover electromagnetic design data, copper wire and insulating material batches, winding equipment, balancing machines, electrical test benches, and ERP/MES systems. The update frequency is per unit, per batch of products, or each type change. Data fields include winding turns, wiring methods, paint dipping and drying parameters, vibration values, temperature rise data, voltage-resistant values, etc., accompanied by equipment operating parameters and batch traceability information.

## What constraints these characteristics impose on the "HTTP Interfaces and External Systems" link
Data for this category is updated per unit, per batch of products, or each type change. HTTP interfaces must support precise retrieval by batch number and product serial number, to avoid excessive resource usage caused by full synchronization. The data includes multi-dimensional structured fields such as winding turns, voltage-resistant values, and dynamic balance values. The interface must return a standardized field format to facilitate parameter matching for subsequent defect analysis. For sensitive data such as high-voltage tests, the interface must complete permission verification via the `Authorization` parameter, while limiting the amount of data retrieved per request to prevent transmission timeouts. There are slight differences in document formats across different departments, so the interface must support basic structured data parsing to adapt to subsequent unified processing workflows.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| `Authorization` | Carry a Bearer Token-formatted secret | Complies with external system interface permission verification specifications, ensuring access security for sensitive data such as high-voltage tests |
| `variables` | Pass product batch numbers and serial numbers as retrieval parameters | Accurately locate quality inspection and production documents for the corresponding batch, improving traceability efficiency |
| `responseData` | Return structured winding parameters and test data fields | Facilitate direct extraction of key indicators in subsequent defect analysis links, without additional parsing |
| Request timeout | 600 seconds | Adapts to the transmission duration of large motor type test reports, avoiding timeouts caused by large data volumes |
| Single retrieval data volume | First 20 entries | Controls interface response load, adapting to the request rhythm of batch traceability |
| Data format compatibility | Support JSON and CSV formats | Adapts to document formats uploaded by different departments, reducing subsequent processing costs |

## Three common mistakes
- Symptom: An empty response is returned when calling the model via the HTTP interface, and the log shows an abnormal `message` field. Cause: The correct product batch parameter was not passed in `variables`, causing the interface to fail to match the corresponding data and return an empty result.
- Symptom: The interface call returns a 403 status code. Cause: The `Authorization` parameter was not configured correctly, and a valid permission verification credential was not carried, so the external system's permission verification failed.
- Symptom: After upgrading to FastGPT v4.17.0, field parsing failures occur during interface calls. Cause: The new version's `responseData` field format requirements were not adapted, and the old version's data parsing rules are still used to process structured return content.

## How to confirm the configuration is complete
- Manually construct an HTTP request containing a valid product batch number, check whether `responseData` returns structured data for the corresponding batch.
- Carry an incorrect `Authorization` credential when calling the interface, confirm that a permission verification failure prompt is returned.
- Initiate a batch request, confirm that the interface response duration meets the preset timeout threshold requirements.
- Pass test parameters in different formats, confirm that the interface can normally return response data in compatible formats.
