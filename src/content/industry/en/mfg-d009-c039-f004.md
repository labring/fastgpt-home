# Quality Problem Traceability and Defect Analysis for Electric Motor and Generator Manufacturing: Workflow Orchestration

## What Data Looks Like for This Category
Data for this category originates from electromagnetic design records, copper wire and insulating material batch records, winding equipment, balancing machines, electrical test benches, and ERP/MES systems. Routine documentation includes winding process cards, insulation treatment logs, dynamic balance reports, dielectric withstand test records, type approval and factory acceptance test reports. Data is updated per individual unit, per production batch, or per design modification. Fields include winding turns, wiring configuration, impregnation and curing parameters, vibration levels, temperature rise, efficiency, and insulation resistance values, with corresponding units: turns, %, mm/s, K, %, MΩ.

## Constraints Imposed on Workflow Orchestration by These Data Characteristics
This category's data characteristics create multiple constraints for workflow orchestration. Data is updated per individual unit or production batch. Workflows must use `variables` to bind batch numbers or equipment IDs as retrieval anchors, ensuring only associated documents from the corresponding production unit are retrieved. There are many document types with significant field differences. Workflows must configure retrieval rules for each document type, differentiating field matching logic for process cards and test reports. Additionally, workflows must account for electromagnetic, insulation, and balancing constraints, using `nodeId` to link winding, insulation, final assembly, testing, and other process data. Do not rely solely on a single retrieval module. Data is updated frequently. Workflows must support real-time pulling of the latest MES data to avoid using expired historical content.

## Configuration Guidelines
This configuration applies to FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Variable Reference | Bind batch numbers, equipment IDs, test dates | Anchor associated data for a single motor unit or production batch |
| Node Execution Order | Configure per the standard process flow: winding → insulation → final assembly → testing | Match the standard business process of motor manufacturing |
| Single Retrieval Count | Top 8 entries | Cover the number of associated documents such as process cards and test reports for a single batch |
| Context Length | 1200–1800 characters | Accommodate key field content from multiple core documents |
| Timeout Threshold | 600 seconds | Align with the conventional duration of type testing |
| Reranking Threshold | 0.7–0.9, calibrated via actual testing | Optimize relevance ranking of retrieval results |

## Three Common Misconfigurations
- When testing a workflow, the output includes an extra closing phrase: "FastGPT is a large language model (LLM)-based knowledge base question answering system". This occurs because default promotional language is not disabled in the system prompt, leading the large model to generate redundant content.
- When configuring a multi-tool chained workflow, some tools fail to execute and do not run in the preset order. This occurs because the execution link associated with `nodeId` is not properly configured, or the sequential execution switch is not enabled.
- After deploying via docker-compose, workflow and knowledge base configurations appear blank, but the interface functions normally. This occurs because the mounted local volume has insufficient permissions, preventing configuration files from being persistently saved.

## How to Verify a Completed Configuration
- Trigger a test workflow, enter the specified batch number, and confirm that retrieved documents are only associated with process and test records for that batch.
- View the workflow node execution log to confirm all configured tools start and complete calls in the preset order.
- Check the system prompt to confirm no unauthorized promotional language is included, and the output contains no redundant content.
- Validate the timeout threshold configuration, simulate a long-duration test data retrieval link, and confirm the workflow does not trigger an abnormal timeout.

The values provided here are common starting points and should be evaluated against the reader's own samples.
