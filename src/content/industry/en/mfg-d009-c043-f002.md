# Quality Problem Traceability and Defect Analysis for Batch Fine Chemical Synthesis: Vector Models and Indexes

## Data Structure for This Category
This category’s data primarily originates from formula and process libraries, raw material batch ledgers, reactor DCS systems, weighing systems, LIMS laboratory information management systems, and warehouse management systems. Data updates trigger per production batch and each key process step. Daily documents include batch production instructions, material feeding verification slips, reaction process records, cleaning validation records, test reports, and deviation and change orders. Data fields include batch number, feeding amount (kilograms/liters), reaction temperature (degrees Celsius), reaction duration (hours), cleaning validation results, and additional fields. Some documents require cross-field information association across multiple systems.

## Constraints for Vector Models and Indexes
The multi-batch, high-frequency update rhythm requires indexes to support fast, precise recall filtered by batch dimension, to prevent irrelevant cross-batch data from interfering with traceability results. The cross-system, multi-document association feature requires vector models to support cross-field semantic association, to accommodate association matching across documents from different sources. While single-batch data volume is small, updates occur frequently, so token consumption per single write must be controlled to avoid exceeding `defaultToken` or `maxToken` limits. Additionally, confidentiality requirements for formulas and processes mean index recall results must strictly restrict permission scope. When splitting text, context association of process steps must be preserved, to avoid breaking reaction logic via improper chunking.

| Maximum Context Length | 4000–6000 tokens | Accommodates multiple associated documents per single batch, meeting full-link information retrieval needs during quality traceability |

## Three Common Configuration Errors
- A prompt reading “No available index model detected” appears after refreshing the page. This occurs when process and test documents for this category are not associated with the specified vector model, or the model configuration was not saved and activated.
- A format error is returned when using a multimodal embedding model. This occurs when the embedding format for non-text fields of this category’s documents (such as temperature curve data from DCS systems) is not adapted, causing the model to fail to properly parse input.
- Old vector database data cannot be recalled normally after upgrading to a new version. This occurs when chunking rules or vector dimensions do not match between old and new versions, and a batched data reindexing process was not completed.
