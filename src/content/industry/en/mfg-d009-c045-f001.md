# Spinning and Weaving: Quality Issue Traceability and Defect Analysis: HTTP Interfaces and External Systems

## What This Category's Data Looks Like
Data for this category comes from raw fiber inspection, ERP, spinning and loom machine data, evenness testers, fabric inspection machines, and order specifications. Daily documents include cotton blending or ingredient lists, process setup sheets, equipment operation records, yarn inspection sheets, gray fabric inspection sheets, and fabric defect logs. Data updates occur per batch of raw materials, per production shift, and per roll of fabric produced. Fields include fiber moisture content, single fiber strength, 100-meter weight variation coefficient, fabric defect type and occurrence position in meters, and more. Different documents use different field combinations and units.

## What Constraints These Characteristics Impose on HTTP Interfaces and External Systems
Multiple heterogeneous data sources require interfaces to support different authentication methods and data formats. This prevents format errors when adapting to different external systems. The high-frequency, fine-grained update rhythm requires interfaces to support calls ranging from batch raw material level to single roll level. This reduces unnecessary request overhead. The complex document structure and segmented fields require interfaces to support precise filtering by document type and field parameters. This avoids returning invalid data. Additionally, the position field for defect records uses meters. Interfaces must support precise matching of numeric position parameters to ensure traceability accuracy.

## How to Configure Settings
These configurations are based on the logic of FastGPT v4.17.0:

| Configuration Item | Recommended Setting Method | Rationale |
| --- | --- | --- |
| `Authorization` | Configure Bearer Token or basic authentication based on external system type | Adapt to authentication requirements of different external systems such as spinning machines, ERP, and fabric inspection machines |
| `variables` | Set to `{"dataSource": ["erp", "loom", "testMachine"], "updateFreq": ["batch", "shift", "perRoll"]}` | Match the business characteristics of multi-source data and multiple update frequencies for this category |
| `responseData` | Configure to return only the `batchNo, rollNo, defectType, position, testValue` fields | Reduce invalid data transmission and focus on core fields required for quality traceability |
| Timeout Duration | 600 seconds | Adapt to long-duration scenarios of batch pulling fabric inspection machine data |
| Batch Call Limit | Top 200 entries | Match the typical quantity range of single-roll fabric defect records, calibrated based on actual testing |

## Three Common Misconfigurations
- The interface returns an empty `responseData` field. This occurs because the `Authorization` parameter for the target external system is not configured, preventing successful authentication and data retrieval.
- Interface calls throw timeout errors. This happens when the timeout duration is not adjusted, and the default short duration configuration is used. This fails to meet the data pulling requirements for batch fabric inspection machine data.
- The defect position field returned by the interface does not match actual values. This occurs because no field mapping rules are configured in `variables`, leading to incorrect conversion of fabric inspection machine centimeter data to meter values.

## How to Confirm Proper Configuration
- Call the interface with a test batch number, and check if `responseData` returns yarn inspection data for the corresponding batch.
- Review interface request logs to confirm that the `Authorization` parameter is correctly carried and has passed authentication verification from the external system.
- Adjust the data source parameter in `variables` to verify if the interface can switch to pulling ERP order data or real-time loom operation data.
- Send a batch call request, and confirm that the number of returned results does not exceed the configured batch call limit.
