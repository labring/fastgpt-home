# Quality Problem Traceability and Defect Analysis for Spinning and Weaving: Vector Models and Indexes

This document adapts to the vector model and index configuration logic of FastGPT v4.17.0.

## What the Data for This Category Looks Like
This category of data mainly comes from daily business and equipment collection of cotton spinning, chemical fiber spinning, woven and knitted enterprises. It includes cotton blending formulas, process setup sheets, equipment operation records, yarn and grey fabric inspection reports, defect ledgers, and other documents. Data sources cover raw fiber inspection, ERP systems, real-time data from spinning and weaving looms, evenness testers, fabric inspection machines, and order specification files. Updates sync with each batch of raw materials, each production shift, and each roll of fabric produced. Most individual documents contain fields such as fiber indicators, process parameters, inspection values, and defect types. Some equipment data includes timestamps and equipment numbers.

## What Constraints These Characteristics Impose on the Vector Model and Index Workflow
This category of data has fast update speed, scattered sources and diverse field types. It requires vector indexes to support high-frequency incremental updates and multi-source data fusion. Individual documents contain multi-dimensional information such as fiber indicators, process parameters, and defect types. Defect records are strongly bound to production batches and equipment numbers, so indexes need to support precise screening and recall based on business dimensions. At the same time, equipment and inspection data mostly combine structured numerical values and short text. Vector models must adapt to mixed-format text encoding to avoid recall deviations caused by mismatched data granularity. Since defects can spread continuously, the timeliness and relevance of recall results must be ensured.

## How to Configure the Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| Chunk Length | 800–1200 characters | Adapts to the text length of individual inspection records and process sheets for this category, avoids including too many irrelevant business fields in a single chunk |
| Overlap Length | 100–200 characters | Covers cross-chunk process parameter and defect association information, prevents key associated content from being split |
| Similarity Threshold | 0.72–0.85 | Filters low-correlation defect and process data, meets the precise traceability requirements for continuous fabric defects |
| Single Search Limit | Top 10 results | Balances recall efficiency and result completeness, matches the sample size for single-batch defect troubleshooting in enterprises |
| `maxToken` | 8192 | Adapts to the input length limit of Qwen/Qwen3-Embedding-8B, prevents information loss caused by text truncation |
| Chunking Strategy | Split by business nodes | Uses cotton blending batches, production shifts, and fabric roll numbers as splitting criteria, retains complete business relevance |

## Three Common Misconfigurations
- Symptom: When adding a vector model with the same name, the existing configuration is overwritten, and only the most recently added model is displayed in the interface. Cause: No unique model identifier is created for different deployment instances or scenarios, causing the system to overwrite configurations with the same name.
- Symptom: After importing Excel-format inspection data, the knowledge base chunks are too large. Retrieval returns coarse-grained results that cannot locate specific defects on a single fabric roll. Cause: Chunking parameters are not adjusted according to business nodes, and default chunking rules are used directly to process structured multi-row inspection data.
- Symptom: The locally deployed M3E model in a Docker environment cannot complete index construction normally, and empty results are returned during retrieval. Cause: The local deployment API address and port are not correctly filled in the FastGPT model configuration, or cross-domain access permissions for the model are not enabled.

## How to Verify the Configuration Is Correct
- Upload a single cotton blending sheet document, check the chunk preview interface, confirm that the chunk length matches the preset value and no key fiber indicator fields are lost.
- Enter a single defect query term, check the retrieval result list, confirm that the number of returned results and similarity match the preset rules.
- Switch to the locally deployed M3E model, run a retrieval test, confirm that the model returns results without errors and matches the query intent.
- Import bulk Excel inspection data, check the knowledge base chunk statistics, confirm that the chunk granularity matches the minimum unit for business troubleshooting.

The values provided here are common starting points and should be measured against the reader's own samples.
