# Quality Issue Traceability and Defect Analysis for Meat Products and Slaughter Processing: Multi-turn Dialogue and Prompt Engineering
## What the data for this category looks like
This category’s data covers daily production documents from slaughterhouses, cooked meat and frozen prepared food enterprises. Documents include animal quarantine certificates, slaughter and cutting records, ingredient pickling ledgers, thermal processing parameter logs, cold chain temperature logs, and microbial test reports.
Data sources include animal quarantine information, supplier batch ledgers, production traceability systems, temperature collection terminals, metal detection equipment, and laboratory test results.
Data updates by production batch and shift frequency. Cold chain temperature requires continuous collection and recording. Core fields include batch number, quarantine number, temperature value, test indicators, and other relevant fields.

## What constraints this category’s characteristics impose on multi-turn dialogue and prompt engineering
The category’s batch-based and continuous temperature-controlled data requires multi-turn dialogue to accurately bind full-chain data for a single batch. This prevents cross-batch confusion.
Documents include multiple specialized fields. Prompts must explicitly specify extraction of core information such as batch number and quarantine number. This stops irrelevant content from mixing into dialogue context.
High-frequency continuous temperature control data uses large context quotas. Effective context range must be limited to only retain dialogue and data related to the current batch.
Business requirements for raw-cooked separation and biological risk control require adding scene restrictions in prompts. This ensures analysis focuses on quality issues for the current batch’s raw materials or finished products.

## Three Common Misconfigurations
- Dialogue details only display a small amount of context, and cannot link production data for the corresponding batch. This occurs because `chatId` is not bound, so dialogue context only retains temporary session content, and does not associate full-chain production and test records for a single batch.
- The loop function cannot use previous round conclusions as prompt input for the next dialogue. This occurs because intermediate analysis results are not stored via `variables`, so the next dialogue cannot access prior judgment basis.
- Dialogue results mix document information from non-target batches. This occurs because prompts do not explicitly restrict extraction to fields for the current batch, so records from other batches’ quarantine or temperature data are linked.

## How to Verify Correct Configuration
- Test a single-batch quality traceability dialogue. Check whether the dialogue details include associated data such as quarantine certificates and temperature records for that batch, to confirm the context binding identifier is active.
- Trigger a cyclic analysis process. Check whether `variables` stores the previous round’s analysis conclusions, to confirm intermediate results can be called by the next dialogue.
- Input test content containing non-target batch fields. Confirm that the dialogue only extracts core information for the current batch, and does not mix irrelevant data.
- Simulate a long-duration analysis scenario. Confirm that no timeout errors occur in the dialogue, to verify the timeout threshold setting is appropriate.

The values provided are common starting points, and should be measured against samples relevant to the specific deployment.
