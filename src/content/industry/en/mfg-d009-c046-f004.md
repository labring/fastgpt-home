# Quality Problem Traceability and Defect Analysis for Meat Products and Slaughter Processing: Workflow Orchestration

## What the Data for This Category Looks Like
Data sources for this category include animal quarantine information, supplier batch ledgers, production traceability records, cold chain temperature collection data, metal detection results, and laboratory microbial test reports. Daily documents include quarantine certificates, slaughter and cutting records, ingredient marinating records, thermal processing records, cold chain temperature logs, and microbial test sheets.
Data updates follow production batches and shifts. Continuous temperature control data syncs in real time. Fields include batch number, quarantine number, processing temperature, detection time, total microbial count indicators, and other metrics, with clear unit labels attached.

## What Constraints These Characteristics Impose on Workflow Orchestration
The data characteristics of this category create multiple constraints for workflow orchestration.
Strict batch association requirements mean workflows must bind batch variables and quarantine information from `variables` to avoid cross-batch data mixing. The large volume of real-time synchronized continuous temperature control data requires workflows to limit the number of logs read per operation, to prevent node timeouts.
Controls for raw/cooked separation and biological risk demand process isolation rules between nodes in the workflow, to distinguish raw material processing and finished product processing stages.
The verification order for multi-source data must align with the production flow. Only after passing quarantine checks and meeting temperature standards can the workflow proceed to the next processing step. Data with different update frequencies must support mixed trigger logic.

## Three Common Configuration Errors
- Symptom: No optional values appear in the variable reference dropdown, making it impossible to select batch or quarantine number fields. Cause: Batch and quarantine number variables were not pre-defined in the workflow's `variables` configuration, so nodes cannot read associated fields.
- Symptom: When creating a new problem classification node and using an initialized AI model, an error occurs during operation or saving. Normal functionality resumes after switching models. Cause: The initialized model is not adapted to text classification scenarios related to meat product microbial detection and cross-contamination, and no corresponding domain model is linked in the global configuration.
- Symptom: After configuring AI response comments, downstream nodes trigger early without waiting for a complete response output. Cause: The segmented nature of streamed output is not understood, and the comment trigger is set to execute during the streaming process, leading to early downstream node activation.

## How to Verify Proper Configuration
- Open the workflow's variable configuration panel, confirm core production fields such as batch number and quarantine number are defined in `variables`.
- Access the problem classification node's settings interface, check that the AI model dropdown displays available classification models.
- Trigger a simulated workflow run with batch data, verify no timeout or missing field errors appear in node logs.
- Test the streamed AI response scenario, confirm downstream verification nodes only execute after a complete response is output.
