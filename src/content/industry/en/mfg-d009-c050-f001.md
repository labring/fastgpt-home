# Quality Problem Traceability and Defect Analysis for General Mechanical Equipment Assembly: HTTP Interfaces and External Systems

## What data looks like for this category
Quality traceability data for general mechanical equipment assembly typically originates from PLM, ERP, parts inspection systems, assembly tool collection terminals, test benches, MES, and customer technical agreements. Data is updated per individual equipment or per order, and includes documents such as assembly process cards, BOM lists, torque records, gap adjustment records, commissioning reports, factory inspection certificates, and packing lists. Data fields include measured parameters with units such as torque value, gap value, and concentricity tolerance, as well as identification fields such as equipment serial number and order number.

## What constraints these characteristics impose on the HTTP Interfaces and External Systems link
The characteristic of data updated per individual equipment or per order requires that HTTP interfaces support precise query parameters using equipment serial number or order number to pull full-link assembly data for a single piece of equipment. The need to connect data from multiple sources requires that interfaces be compatible with field formats from different systems, and parameter mapping rules must be configured to align fields. Measured data fields with units require that clear unit identifiers be retained when the interface returns data to avoid ambiguity during traceability. The real-time requirements of on-site assembly require that interface response times match the waiting rhythm of on-site debugging, and should not be excessively long.

## How to set configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `Authorization` | `Bearer {external system access key}` | Complies with standard interface authentication requirements to ensure data access permissions |
| `variables` | `{"device_sn": "{{query.device_sn}}", "order_id": "{{query.order_id}}"}` | Adapts to business scenarios of querying by equipment serial number or order number, supports extracting parameters from user input |
| `responseData` | `Retain BOM hierarchy, torque values, gap adjustment records, and inspection results` | Only returns core fields required for quality traceability to optimize data transmission efficiency |
| Request timeout period | `30-60 seconds` | Adapts to the real-time debugging rhythm of on-site assembly, avoiding traceability interruptions caused by timeouts |
| Retry count | `2 times` | Addresses temporary network fluctuations and reduces the impact of single request failures |
| Request data size limit | `1000 MB` | Adapts to the transmission requirements of assembly data, avoiding transmission failures caused by excessively large data |

## Three common mistakes
- Symptom: A 403 unauthorized error is returned when calling a backend interface deployed on Alibaba Cloud, or a prompt indicates that the domain name generated by PeanutHull cannot be resolved. Cause: The `Authorization` parameter is not configured correctly, or the domain name is not added to the access whitelist of the external system, resulting in access being blocked.
- Symptom: The `responseData` field returned after the HTTP module sends a request is empty. Cause: Request parameters are not mapped correctly, or the field names returned by the interface do not match the configured extraction rules, resulting in failure to extract valid data.
- Symptom: A timeout error occurs after sending an interface request. Cause: The request timeout period is set too short, or the backend interface response speed is slow, failing to match the business rhythm of on-site assembly.

## How to confirm the configuration is correct
- On the FastGPT HTTP module configuration page, input test equipment serial numbers and order numbers, send a simulated request, and check whether the returned `responseData` includes expected assembly data fields.
- Verify that the `Authorization` parameter is correctly included in the request header, confirm that the identity authentication configuration is correct, and validate the legitimacy of the request using an interface debugging tool.
- Simulate a network fluctuation scenario: disconnect the network then restore connectivity, check if the interface automatically retries, and confirm the retry strategy configuration is active.
- Adjust the request timeout period to different values, send requests and record response durations, and confirm the timeout setting matches actual business scenarios.

The values provided are common starting points and should be evaluated against relevant samples.
