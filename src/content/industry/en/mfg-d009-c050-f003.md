# Quality Problem Traceability and Defect Analysis for General Mechanical Equipment Assembly: Multi-turn Dialogue and Prompt Engineering

## What the data for this category looks like
Data for general mechanical equipment assembly scenarios typically comes from PLM/ERP systems, parts inspection ledgers, records collected by assembly torque tools, test bench test data, MES manufacturing execution systems, and customer technical agreements. Data is updated per single equipment or order, and includes documents such as assembly process cards, multi-level BOMs, torque/clearance adjustment records, commissioning reports, and factory inspection sheets. Fields include precise assembly-related numerical values and process requirements such as torque values (unit: N·m), coaxiality parameters (unit: μm), and clearance values (unit: mm). This document is written based on the configuration rules for FastGPT v4.17.0.

## What constraints do these characteristics impose on the multi-turn dialogue and prompt engineering process
The data characteristics of this category impose multiple constraints on the multi-turn dialogue and prompt engineering process. Multi-level BOM structures require that conversations retain the `messages` context to avoid repeated queries for same-level material information. Data updated per single equipment or order requires binding the `chatId` to associate with the exclusive dataset for the corresponding equipment, preventing cross-order data confusion. Precise numerical values with units such as torque and clearance require that prompt engineering explicitly specifies calling the corresponding document fields to avoid fuzzy matching. The scattered nature of data sources requires multi-turn dialogue to guide users to gradually provide fault symptoms and narrow down the troubleshooting scope step by step.

## How to set the configurations
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Context window size | 8000–12000 characters | Adapts to the total length of multi-level BOMs and multiple assembly documents, avoiding truncation of critical process information |
| `chatId` binding rule | Bind the unique identifier of a single piece of equipment | Ensures multi-turn dialogue only calls the exclusive dataset for the corresponding order or equipment, preventing data confusion |
| `variables` parameter configuration | Pass in the BOM number and assembly batch number of a single piece of equipment | Quickly locate assembly records and inspection data for the corresponding equipment, narrowing the retrieval scope |
| `messages` history retention count | Top 20 interaction records | Balances context completeness and response speed, avoiding excessive historical content slowing down initial screen response |
| Prompt template field specification | Explicitly call unit-bearing fields such as torque values and clearance values | Matches the precise numerical characteristics of this category’s data, improving the accuracy of defect analysis |
| Single dialogue tool call limit | Top 3 recall results | Adapts to the volume of documents in assembly scenarios, avoiding excessive results interfering with analysis logic |

## Three common mistakes
- Symptom: The first response of a conversation has a delay of more than 3 seconds before the first character is output, while subsequent responses are normal. Cause: The number of retained `messages` history entries is not limited, and excessively long context causes excessive retrieval and splicing time during initial loading.
- Symptom: No automatic question is initiated after the configuration dialog box is triggered in the workflow. Cause: The trigger event of the dialog box is not bound to the question action, or the bound parameters are not correctly associated with the device identifier in `variables`.
- Symptom: The assembly data visualization result generated by calling the chart tool is empty. Cause: The prompt does not explicitly specify calling the inspection data field for the corresponding single piece of equipment, resulting in no matching numerical content being retrieved.

## How to confirm the configuration is complete
- Initiate a fault troubleshooting conversation for a single piece of equipment, check whether the bound equipment BOM number is displayed at the top of the conversation, and confirm that the `chatId` binding rule is effective.
- View the context fragment of the conversation history, confirm that the number of retained interaction records in `messages` matches the preset retention count, with no redundant historical content.
- Input a fault description containing torque values and clearance values, check whether the prompt guides calling the corresponding document fields, and whether the retrieval results include assembly-related data of this category.
- Trigger the dialog box node in the workflow, confirm that the node automatically initiates a question after starting, and the question content is bound to the `variables` parameters of the current equipment.

The values provided here are common starting points and should be evaluated against the user’s own samples.
