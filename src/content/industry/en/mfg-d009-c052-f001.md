# Quality Problem Traceability and Defect Analysis for Steel Rolling and Finishing: HTTP Interfaces and External Systems

## What Data for This Category Looks Like
Data sources for steel rolling and finishing production include slab or billet batch identifiers, furnace operating parameters, mill automatic control data, online thickness and width measurement results, surface inspection judgment results, and MES system work order data. Daily associated documents include rolling order sheets, heating schedule tables, rolling specification cards, shape and thickness record ledgers, surface quality reports, and product quality certificates.

Data is generated in real time per coil or billet/steel coil. Fields include batch number, rolling temperature, thickness deviation value, surface defect type, and production station code. Units include degrees Celsius, millimeters, defect level codes, and others.

## Constraints for HTTP Interfaces and External Systems
Production data for steel rolling and finishing is updated in real time per coil or unit. This requires HTTP interfaces to support high-frequency, small-batch request scheduling, and avoid timeouts caused by excessive single-request data volume.

Multiple data sources require interfaces to support aggregated calls for cross-system data, and parameter mapping rules between different systems must be configured. Associated documents include multiple types of production ledgers and quality reports. Interfaces must support pulling corresponding documents by batch number, and define matching logic for metadata fields.

At the same time, errors in the production link have serious consequences. Interfaces must be configured with timeout thresholds and retry mechanisms to ensure that abnormal requests can be processed and recorded in a timely manner.

## Configuration Settings
This configuration is based on FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Interface timeout duration | 300–600 seconds | Pulling and parsing multi-source production data associated with a single coil takes a long time |
| `Authorization` header configuration | Bearer {custom access key} | Identity verification is required when connecting to multiple systems such as furnaces, mills, and MES, to ensure data access security |
| Single request batch limit | Top 20 entries | Each coil has a small data volume; too many batch requests will increase the load on external systems |
| `variables` mapping rules | Associate production data by batch number | Production data uses batch as the unique identifier, and precise matching of corresponding quality information is required |
| `responseData` filtering rules | Return only quality-related fields | Only extract data required for traceability such as thickness, surface defects, and rolling temperature, to reduce transmission overhead |
| Retry interval | 10–30 seconds | Avoid overloading external systems with frequent retries |
| Maximum document pull size | 50 MB | Avoid pulling excessively large quality report files in a single request, reducing interface load |

## Common Misconfigurations
- Phenomenon: An interface call for parsing quality documents returns a timeout error with status code 504. Cause: A reasonable interface timeout duration is not configured, and the time taken to pull multi-source data for a single coil exceeds the default threshold.
- Phenomenon: A 429 status code is returned when concurrent requests exceed 5. Cause: Concurrency limit is not configured, and the concurrency upper limit of the external system is not matched when connecting to cloud service interfaces.
- Phenomenon: Pulled quality data fields are empty. Cause: The `variables` mapping rules are not correctly configured, and production system data is not associated by batch number.

## How to Verify Successful Configuration
- Initiate a single-batch interface request, and check whether the returned `responseData` fields include preset quality-related parameters.
- Initiate multi-batch concurrent requests, and verify that the requests comply with the configured concurrency upper limit requirements.
- Pull production documents for the corresponding batch, and check whether the metadata returned by the interface matches the actual production ledger.
- Check interface logs to confirm that `Authorization` verification is passed, and there are no unauthorized access errors.

The values provided are common starting points and should be measured against the reader's own samples.
