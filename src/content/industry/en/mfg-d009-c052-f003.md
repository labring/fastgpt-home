# Quality Problem Traceability and Defect Analysis for Steel Rolling and Finishing: Multi-turn Dialogue and Prompt Engineering

## What Data for This Category Looks Like
This category of data originates from slab or billet batches, heating furnaces, mill automation control systems, online thickness and width measurement equipment, surface inspection devices, and MES systems. Data is updated per coil or billet, with real-time update cycles. Daily associated documents include rolling plans, heating schedules, rolling specifications, flatness and thickness records, surface quality reports, and quality certificates. Data fields include batch number, furnace number, rolling temperature, reduction rate, flatness, and thickness deviation values. Units include degrees Celsius, percentage, millimeters, and others.

## Constraints Imposed on Multi-turn Dialogue and Prompt Engineering
Real-time updated batch-level data requires multi-turn dialogue to bind `chatId` to the unique identifier of the current coil or billet, to avoid context confusion. Multiple associated documents and fields require prompts to pre-limit retrieval scope to the exclusive documents of the current batch, preventing cross-batch data interference. Multi-turn traceability requires follow-up questions across heating, rolling, and inspection stages. Prompts must guide supplementation of key fields such as missing furnace numbers and reduction rates. At the same time, control the length of the `messages` context to avoid response delays caused by real-time data overload. In addition, use `variables` to inject exclusive parameters of the current batch to further accurately limit the retrieval scope.

## Configuration Settings
| Configuration Item | Suggested Setting | Rationale |
| --- | --- | --- |
| Batch Binding Configuration | Bind the unique batch number of the current coil | Ensure multi-turn dialogue only associates with the current traceability batch, preventing cross-batch data confusion |
| Context Window Setting | 8000–12000 characters | Cover the interactive information required for full-process traceability of a single coil or billet from heating to finishing |
| Context Truncation Strategy | Retain the last 10 interaction records | Adapt to real-time updated batch data, avoiding response delays caused by overly long context |

| Export Function Configuration | Bind the quality analysis results generated by the dialogue, limit single file size to 500 MB | Support exporting traceability reports by batch, matching the quality certificate generation requirements of this category |

## Three Common Misconfigurations
- Phenomenon: When two conversation requests are sent consecutively with a very short interval, subsequent requests must wait for the previous generation to complete and cannot respond immediately. Cause: The rule for interrupting current generation when a new message is received is not configured, and the default behavior retains the previous conversation context until generation ends.
- Phenomenon: When calling the FastGPT API to initiate a conversation, an error message "No permission to operate this conversation record" is returned. Cause: The legal identifier of the current batch is not correctly bound, resulting in failed permission verification.
- Phenomenon: No Word export download link is generated at the bottom of the conversation. Cause: The binding logic between conversation results and the export function is not configured, and the generated quality analysis results are not mapped to the preset export template.

## How to Verify Proper Configuration
- Initiate a query that includes the current coil batch number, confirm that the dialogue only returns data related to this batch, with no cross-batch information interference.
- Send two conversation requests consecutively with a very short interval, confirm that the subsequent request can immediately interrupt the previous generation process.
- After triggering conversation generation, check whether a clickable Word export link exists at the bottom of the page, and the link points to the quality analysis results of the current batch.
- After upgrading to FastGPT v4.17.0, refresh the page and confirm that historical conversation records load normally, with no unexpected new conversation prompts.

The values provided are common starting points and should be measured against samples tailored to the specific deployment.
