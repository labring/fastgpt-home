# Quality Problem Traceability and Defect Analysis for Steel Rolling and Finishing: Tool Calling and Plugins

## What Data for This Category Looks Like
Data for this category comes from slab/billet batch identifiers, furnace operating parameters, mill automation control systems, online thickness and width measurement equipment, surface defect detection systems, and manufacturing execution systems (MES). Data is generated in real time per coil or individual steel billet. Single records include fields such as batch number, heating temperature, rolling force, shape deviation value, surface defect location and type, and others. Daily archived documents include rolling plans, heating schedules, rolling specifications, plate shape and thickness records, surface quality reports, and quality certificates, stored in a structured manner by steel coil batch.

## Constraints for Tool Calling and Plugins
The real-time, coil-level data characteristics of this category require tool calling to support high-frequency triggers and small-batch data retrieval. Multi-source heterogeneous data sources require plugins to adapt to data source connections using different protocols, and to associate records from different systems by batch dimension. The real-time update feature requires tool calling timeout thresholds to match production cycles, to avoid long waits that cause production link blockages. The coil-level traceability requirement means tool calling must support using batch numbers as the unique retrieval key, to associate full-link data from heating, rolling, and inspection stages. This ensures full process traceability from billet to finished product is available during defect analysis. Additionally, structured archived documents require plugins to support parsing standardized rolling specification and quality certificate fields, to extract key analysis parameters.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `toolChoice` | `"auto"` | Adapts to automatic multi-tool selection, matches the multi-source data calling needs of this category. FastGPT v4.17.0 supports flexible configuration of this parameter |
| Tool calling timeout threshold | `30–60 seconds` | Matches the update cycle of production real-time data, avoids long waits that block rolling links |
| `functionCall` | `Custom functions only` | Restricts the scope of tool calling, ensures only plugins related to steel rolling quality analysis are called, avoids unrelated operations |
| Data source encoding configuration | `UTF-8 mandatory` | Resolves Chinese display errors in database plugins, adapts to encoding standards of domestic production systems |
| Batch retrieval key configuration | `By steel coil batch number` | Matches the coil-level storage characteristic of this category's data, ensures accuracy of full-link traceability |
| Number of records returned per tool call | `Top 10` | Adapts to the limited data volume per coil, avoids excessive redundant information interfering with defect analysis |

## Three Common Misconfigurations
- Symptom: When using two levels of tool calls in a Workflow, the AI return content from the first call is printed, and the next level branch executes simultaneously. Cause: The tool call log output switch is not disabled, and the trigger condition for branch execution is not configured, causing AI replies and branch execution to trigger simultaneously.
- Symptom: After connecting the MySQL database plugin, query results cannot display Chinese characters, and the issue persists after adjusting all configurations. Cause: UTF-8 encoding is not force-specified in the data source configuration, or the character set parameter is not added to the database connection string, leading to failed Chinese encoding parsing.
- Symptom: When calling the tool calling function of Qwen2.5, the function call logic cannot be triggered. Cause: The `toolChoice` parameter is not configured to the required format, or the format requirements for function calls are not clearly specified in the system prompt, causing the large language model to fail to correctly recognize the calling instruction.

## How to Verify Correct Configuration
- Initiate a steel coil batch quality traceability request, check the tool calling log, confirm that only necessary analysis data is returned, with no redundant AI reply content.
- Execute a database query containing Chinese fields, confirm that Chinese content in the returned results displays correctly.
- Configure Qwen2.5 as the large language model, initiate a test request including tool calling requirements, confirm that the large language model can correctly trigger the specified plugin function.
- Simulate real-time production environment data to trigger tool calls, confirm that the call timeout time matches the preset threshold, with no link blockages.

Note: The configuration values listed above are common starting points. Adjust them based on your own specific samples and environment.
