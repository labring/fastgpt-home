# Quality Problem Traceability and Defect Analysis for Iron and Steel Smelting and Continuous Casting: Workflow Orchestration

## What Data for This Category Looks Like
Data sources for this category include iron melt and scrap steel ledgers, L2 process control systems, laboratory test reports, MES production management systems, energy medium monitoring systems, and equipment condition monitoring systems.
Data update frequencies fall into three categories: per heat, real-time, and per shift.
Covered documents include heat plans, batching lists, converter smelting records, composition analysis reports, continuous casting process parameter records, slab quality judgment sheets, and more.
Individual documents contain fields such as heat number, cast number, temperature parameters, composition components, pulling speed, and equipment operating duration. Field units include degrees Celsius, meters per minute, kilograms, and others.

## Constraints Imposed on Workflow Orchestration by These Characteristics
This category involves high-temperature continuous production processes, with strong coupling between heats and casts. Random shutdowns are not permitted.
Workflows must bind precise heat-level variable trigger nodes to avoid indiscriminate triggering.
Data from multiple systems has inconsistent field naming. A unified mapping node must be added to the workflow to ensure production data from different systems can be retrieved uniformly.
Data updates occur frequently, and errors have severe consequences. Workflows must include exception branches and retry logic to prevent process interruptions or incorrect traceability caused by single data anomalies.
Additionally, production data volume is large. Retrieval scope must be controlled to avoid process timeouts.

## How to Set Configurations
| Configuration Item | Recommended Approach | Rationale |
| ---- | ---- | ---- |
| `variables` | Bind heat number, cast number, and slab number as global variables, with values set to the real-time production number of the currently triggered workflow | Heat and cast processes are strongly coupled, so precise association of production records and quality data across all links is required |
| Node timeout setting | 600 seconds | A single heat smelting cycle typically lasts tens of minutes, so this timeout setting prevents long-term process blocking |
| `nodeId` | Bind the nodeId of the laboratory composition report node and the continuous casting process record node | Subsequent traceability and analysis logic must be triggered based on the execution results of specific nodes |
| Exception branch configuration | 3 retries + failure alert | Production data may face temporary network fluctuations or system delays; retries reduce the probability of false triggers |
| Single retrieval limit | Top 10 entries | Data volume in steel production links is large; controlling retrieval scope improves workflow execution efficiency |
| Variable mapping rule | Match relationships based on field calibration via actual measurements | Different systems have inconsistent field naming, so a unified matching logic is required to ensure accurate data association |

## Three Common Misconfigurations
- Phenomenon: The workflow stalls after executing a tool call node, and the console displays no matching data. Cause: The real-time heat number bound to `variables` was not used as a retrieval keyword, making it impossible to locate corresponding records from multi-system data.
- Phenomenon: The original file preview cannot be opened during workflow testing, with an invalid file path prompt. Cause: No mapping was created between the original file storage path of the knowledge base slices and the document path in `variables`, so retrieval results cannot be associated with original files.
- Phenomenon: The cosyvoice node call fails, returning a connection timeout error. Cause: No node timeout parameter was set, or the timeout threshold was set too short to adapt to the response delay of steel production systems.

## How to Confirm Proper Configuration
- A simulated heat workflow is triggered in the FastGPT v4.17.0 workflow editor, and the heat number and cast number in `variables` are verified to be automatically loaded as the production number for the current test.
- A tool node is called, and the returned results are checked for inclusion of smelting records and composition reports for the corresponding heat, with fields verified to match the preset mapping rules.
- The exception branch is manually triggered to confirm that the retry logic or alert notification is activated.
- The file link variable configured in the workflow is clicked to confirm successful redirection to the preview page of the corresponding original document.
