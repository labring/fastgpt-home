# Quality Problem Traceability and Defect Analysis for Iron and Steel Smelting and Continuous Casting: Tool Calling and Plugins

## What data for this category looks like
Data for this category originates from iron melt and scrap charging data, L2 process control real-time data, laboratory composition reports, MES production data, energy medium system parameters, and equipment condition monitoring data. Data is generated per heat, in real time, or per shift. Associated documents include heat plans, batching lists, converter smelting records, continuous casting process records, slab judgment sheets, and more. Fields include heat number, smelting temperature, composition parameters, equipment runtime, and other relevant metrics.

## What constraints these characteristics impose on tool calling and plugins workflows
Since data updates per heat, in real time, or per shift, tool calling must support precise association of multi-source data using heat numbers to avoid cross-heat confusion.
Multi-source heterogeneous data sources require plugins to adapt to interface formats of different systems. Reliance on a single standardized data interface is not feasible.
The high-temperature continuous production process requires tool calling to support low-latency real-time response to avoid interrupting the continuous casting process.
The tightly coupled business logic between heat and casting sequence requires tool calling to associate document data from both steelmaking and continuous casting links. This ensures traceability covers the entire production process and reduces omissions in defect analysis.

## Configuration Settings
| Configuration Item | Recommended Setting | Rationale |

| Workflow/API tool selection | `auto` | Adapts to the FastGPT v4.17.0 tool calling framework, automatically matches multi-source data calling requirements in iron and steel smelting scenarios, and reduces manual configuration costs |

| Tool calling context association scope | Current heat and associated casting sequence | Aligns with the tightly coupled business logic of heat and casting sequence, ensuring traceability data covers the entire steelmaking-continuous casting production process |
| Workflow/API function-call configuration | `enabled` | Supports structured calling of quality analysis tools to accurately extract fields such as composition reports and equipment status for defect analysis |
| Tool call result cache duration | `8 hours` | Heat data is updated per shift. An 8-hour cache matches most shift-based traceability needs while avoiding data inconsistencies caused by cache expiration |

## Three Common Mistakes
- Phenomenon: Tool calls fail with a connection unavailable error and timeout prompt. Cause: Network access permission configurations for multi-source systems in iron and steel smelting scenarios are not adapted, and access permissions for corresponding interfaces are not added for cross-system calls.
- Phenomenon: No tool-free connection can be established after a tool call terminates, and empty results are returned. Cause: Session context reset logic is not configured correctly, and the natural language interaction mode is not restored after tool call termination.
- Phenomenon: Retrieved slab judgment sheet data fields are empty. Cause: Data is not precisely associated by heat number, and the heat ID parameter is not carried during tool calls, resulting in matching of irrelevant batch documents.

## How to Confirm Configurations Are Correct
- Manually enter a heat number to trigger a tool call, and verify that returned results include smelting records and composition reports for the corresponding heat.
- Check tool call logs to confirm the timeout duration is set to 300 seconds, with no frequent timeout errors.
- Test that after terminating a tool call, initiate a natural language query without tool usage, and confirm the session can resume normally.
- Check if the `functionCall` parameter is enabled, and confirm that structured call result fields conform to document formats for iron and steel smelting scenarios.

The values provided are common starting points and should be measured against the reader's own samples.
