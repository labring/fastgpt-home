# Quality Problem Traceability and Defect Analysis for Sheet Metal Cutting and Bending: Vector Models and Indexes

## Typical Data for Sheet Metal Cutting and Bending Scenarios
Typical data sources in sheet metal cutting and bending scenarios include unfolded drawings generated by CAD/CAM, CNC cutting programs, bending process cards, nesting diagrams, order BOMs, sheet material inventory ledgers, operation data from laser cutters and bending machines, and MES process flow records. Data updates trigger with each order, daily production shift, or each equipment model change. Most documents have structured fields: unfolded drawings note bending compensation values and hole position coordinates, cutting programs include cutting feed parameters, process cards record bending sequences and sheet material specifications, and units are mostly millimeters, kilograms, seconds, and similar.

## Constraints on Vector Models and Indexing
Heterogeneous multi-format data sources require vector models to support mixed encoding of structured fields and unstructured process text. Frequent update cycles require indexes to support incremental synchronization, avoiding performance losses from full reindexing. High-mix low-volume production patterns cause fluctuating data volumes, so index sharding must adapt to dynamic data sizes. Semantic associations between high-precision fields such as bending compensation values and hole position coordinates require vector recall similarity thresholds to match industrial precision requirements, preventing false recall of non-matching process data.

## Configuration Guidelines
This document is written for FastGPT v4.17.0. The following are configuration recommendations for vector models and indexing for this scenario:

| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Chunk Length | 800–1200 characters | Adapts to the text length of unfolded drawings and process cards, avoiding semantic breaks within chunks |
| Overlap Length | 50–80 characters | Preserves cross-chunk semantic coherence for bending sequences and hole position associations |
| Similarity Threshold | 0.75–0.85 | Matches industrial process precision requirements, filtering non-matching cutting/bending data |
| `maxToken` | 4096 | Adapts to embedding model input length limits, fully carrying process parameters and coordinate information |
| Single Search Limit | Top 10 results | Balances recall efficiency and completeness, adapting to retrieval needs for small-batch production |
| `defaultToken` | Calibrated via actual testing | Adapts to encoding differences in compensation values across different sheet batches, avoiding semantic bias from generic parameters |

## Three Common Configuration Mistakes
- Retrieval response timeout, with the interface displaying "Retrieval time exceeds threshold". The cause is failure to adjust chunking strategies for frequently updated incremental indexes, leading to too many chunks per retrieval batch.
- Index tasks remain stuck in the "Indexing" state indefinitely. The cause is failure to configure incremental synchronization trigger rules, with full reindexing covering excessive equipment model change data leading to task backlog. If an embedding model is used without configuring `maxToken`, task stalls will occur due to exceeded input length limits.
- Multiple duplicate index entries are automatically generated within the dataset. The cause is failure to bind data update trigger conditions by order dimension, leading to repeated index generation each time equipment is changed or production shifts are updated.

## How to Verify Successful Configuration
- Import a single bending process card, check that the number of vector chunks after splitting matches the actual document length, with no excessive splitting or merging.
- Trigger an incremental index task, confirm that the number of updated entries synced in index logs matches the actual production data update volume.
- Run a retrieval query containing bending compensation values or hole position coordinates, confirm that the similarity scores of returned results fall within the preset threshold range.
- Restart the service, check the embedding model loading status for no error prompts, and confirm that `defaultToken` and `maxToken` configurations have taken effect.

The values listed above are common starting points, and should be validated against the user's own samples.
