# Quality Problem Traceability and Defect Analysis for Sheet Metal Cutting and Bending: Model Access and Configuration

## What the Data for This Category Looks Like
Data for this category primarily originates from CAD/CAM software, order BOMs, sheet metal inventory systems, laser cutting and bending equipment, and MES production management systems. Daily documents include 3D unfolding drawings of sheet metal parts, CNC cutting programs, bending process cards, nesting drawings, first-piece inspection records, and process flow cards. Data updates trigger with each order, daily production progress, or each equipment model change. The core workflow is drawing-driven. In multi-variety, small-batch production modes, data dimensions shift dynamically alongside process flow.

## What Constraints These Characteristics Impose on Model Access and Configuration
The multiple document types and dynamic update frequency of this category require model access to adapt to structured and unstructured data in varied formats. Sheet metal drawing documents hold geometric and process parameters, so models must accurately parse bending coefficients and nesting rules from unfolding drawings. Frequently updated data demands configuration support for real-time or near-real-time synchronization, to prevent retrieval of expired process parameters. Single-time data volume fluctuations from multi-variety, small-batch production require limiting the context scale sent to the model per session, to avoid exceeding processing limits. Retrieval and matching logic must also be optimized for time-series data such as process flow cards and first-piece records.

## How to Set Configurations
The following configurations are based on FastGPT v4.17.0.

| Configuration Item | Recommended Range | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Adapts to multi-document splicing needs for sheet metal cutting and bending, and avoids exceeding context window limits of mainstream large models |
| `quoteMaxToken` | 2000–3000 token | Limits text length for single retrieved quotes, supports parameter extraction from bending process cards and unfolding drawings, and prevents redundant content from disrupting model judgment |
| `temperature` | 0.2–0.4 | Reduces randomness to ensure consistent, accurate retrieval results for process parameters and geometric dimensions, matching the rigor required for quality traceability |
| Single search limit | Top 6 entries | Aligns with process data volumes for multi-variety, small-batch production, and avoids overcrowding context space with irrelevant retrieval results |
| `AIPROXY_API_ENDPOINT` | Fill in per deployment environment | Adapts to internal enterprise network environments, ensuring model call stability and data security |

## Three Common Misconfigurations
- Phenomenon: Semantic retrieval returns multiple results, but the model prompts that no relevant information is found. Cause: `quoteMaxToken` is not limited, single quoted text is overly long, or total context exceeds the `maxContext` limit. Valid retrieval content is truncated, and the model cannot match key parameters.
- Phenomenon: Frequent timeout errors occur during model calls. Cause: `maxContext` is not set appropriately, too much unfolding data from sheet metal drawings is sent, exceeding model processing thresholds, or configured API call timeout durations are unsuitable.
- Phenomenon: Retrieved bending coefficients deviate from actual process card parameters. Cause: `temperature` is set too high, causing random fluctuations when the model parses structured process parameters, failing to meet the precision requirements of production documents.

## How to Confirm Correct Configuration
- Upload a single bending process card and unfolding drawing, trigger retrieval, and verify that returned quoted text includes accurate bending coefficients and hole position parameters.
- Simulate a batch retrieval request containing multiple nesting drawings and bending process cards, check model call response times and content integrity, and confirm no context overflow or content truncation occurs.
- Adjust the `temperature` parameter to 0.1 and 0.5, compare consistency between the two retrieval results, and validate the parameter’s impact on result stability.
- Review system logs to confirm that `quoteMaxToken` and `maxContext` values for each model call match preset configurations, with no abnormal values.

The values provided are common starting points and should be evaluated against samples from the specific deployment context.
