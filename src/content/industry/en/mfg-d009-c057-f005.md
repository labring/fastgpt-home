# Forging and Die Forging Quality Problem Traceability and Defect Analysis: Tool Calling and Plugins

## What this category's data looks like
The quality traceability data for forging and die forging covers multiple types of production and inspection documents. Daily documents include forging process specifications, blanking cards, heating furnace records, forging process cards, mold life records, heat treatment work orders, and ultrasonic inspection reports. Data sources include raw material quality certificates, heating furnace systems, press collection data, MES, non-destructive testing instruments, and customer forging drawings. The update frequency is per forging, per production batch, or per furnace heat. Each document corresponds to dedicated fields such as process parameters, production batch associations, heating process data, mold usage status, and non-destructive testing results.

## What constraints these characteristics impose on the "tool calling and plugins" link
The batch association of multi-source data requires that tool calls be bound to production batches and furnace numbers as unique identifiers to avoid mixing data from different batches. High-frequency single-piece or batch-level updates require plugins to support low-latency data pulling to adapt to real-time analysis needs for small-batch or customized forging production. Diverse document formats and dedicated fields require plugins to have parsing capabilities for different structured documents, accurately extracting key parameters such as furnace temperature, defect size, and forging ratio. Severe quality error consequences require that tool call logs be associated with corresponding forging batch numbers to facilitate subsequent traceability and troubleshooting for defect analysis.

## How to set the configuration
| Configuration Item | Recommended Setting | Rationale |
| --- | --- | --- |
| Workflow/API tool selection | `auto` | Adapts to multi-source data calling scenarios, automatically matching tool interfaces required for quality traceability |
| Workflow/API function-call configuration | `enabled` | Allows plugins to call structured data interfaces to pull dedicated fields related to forging production and inspection |
| Tool call timeout | `300–600 seconds` | Forging data pulling involves interactions with multiple systems, so sufficient response time must be reserved |
| Data source binding rule | `Associate by production batch` | Matches the production batch and furnace number identifiers of forgings to ensure one-to-one correspondence between data and corresponding forgings |
| Log association configuration | `Bind forging batch ID` | Facilitates quick location of tool call records for corresponding production links during subsequent defect analysis |

## Three common mistakes
- The symptom is that tool calling works normally in debug mode, but throws connection failure or parameter error reports in production runtime mode. The cause is that the container network configuration in runtime mode is inconsistent with the debug environment, and the internal ports or access permissions required by the plugin are not correctly mapped.
- The symptom is that a connection failure is returned when calling the document parsing plugin, and testing with 127.0.0.1 is ineffective. The cause is that the FastGPT container deployed via Docker cannot access the host's local service address inside the container. The host's intranet IP must be used instead of the local loopback address.
- The symptom is that no relevant call records are displayed in the tool call log, and tasks are stuck in execution for a long time. The cause is that the tool call log storage switch is not enabled, or the batch association configuration is incorrect, causing logs to not be bound to the corresponding production task.

## How to confirm the configuration is correct
- Manually trigger a tool call, check the tool call log in FastGPT v4.17.0, confirm that the returned results include dedicated fields such as heating furnace records and ultrasonic inspection data corresponding to the forging batch, which match the actual production documents.
- Check the tool call configuration parameters, confirm that the configurations of `toolChoice` and `functionCall` have been correctly loaded, with no configuration parsing errors.
- Switch to runtime mode to execute batch tasks, verify that the success rate of tool calls is consistent with that in debug mode, with no additional connection or configuration errors.
- View the associated forging batch ID, confirm that the log has correctly bound the identifier of the corresponding production batch to facilitate subsequent traceability queries for defect analysis.
