# Quality Problem Traceability and Defect Analysis for Forging and Die Forging: Database and Operations

## What the data for this category looks like
This category covers the entire forging workflow. Data sources include raw material quality certificates, heating furnace systems, press collection data, MES systems, non-destructive testing instruments, and customer forging drawings. Daily documents include forging process specifications, cutting cards, heating furnace records, forging process cards, mold life records, heat treatment work orders, and ultrasonic testing reports.

Data is updated per forging piece, batch, or furnace load. Core fields include forging batch number, material heat number, heating temperature, forming pressure, defect type, and mold usage count. Corresponding units are batch number, heat number, ℃, MPa, defect category, and times respectively.

## What constraints these characteristics impose on the database and operations link
High-frequency single-piece or batch data updates require the database to support high-concurrency writes, to avoid data loss caused by connection exhaustion. Multi-source heterogeneous data sources require the operations link to support real-time collection and batch import in different formats, and adapt to data access from different types such as sensors and system reports in the forging workflow.

The strong associated query requirement between forging batches and material heat numbers requires the establishment of joint indexes to improve traceability efficiency. For offline deployment scenarios, local data synchronization and backup strategies need to be configured to avoid data loss risks during cross-version upgrades. At the same time, the data retention period must match the service life of forgings to meet business requirements for quality traceability.

## How to set the configurations
| Configuration Item | Recommended Value | Rationale |
| ---- | ---- | ---- |
| Database connection address | `mongodb://admin:your_password@127.0.0.1:27017/forging_db?authSource=admin` | Adapts to local Windows 10 deployed MongoDB connections, stores real-time collection data and batch association information for forging processes |
| Maximum database connections | `80–120` | Matches the concurrent connection requirements of high-frequency multi-source data writes, avoids connection pool exhaustion |
| Tool call retrieval threshold | `0.75–0.85` | Filters matching forging quality problem data in the knowledge base, returns associated answers if matched, returns preset prompt content if not matched |
| Cache service address | `redis://127.0.0.1:6379/0` | Caches frequently queried forging batch association data, improves response speed for quality traceability |
| Metadata database address | `postgresql://admin:your_password@127.0.0.1:5432/forging_metadata` | Stores structured metadata such as forging process specifications and testing reports, forms hot and cold data separation with MongoDB |

## Three common mistakes
- Symptom: FastGPT console returns a database connection failure error, with log showing ECONNREFUSED. Cause: The database connection address is not configured correctly, and firewall permissions for MongoDB's default port 27017 are not enabled during Windows 10 local deployment.
- Symptom: Tool call retrieval returns unexpected results, either returns answers with no matching data, or returns results with insufficient matching degree. Cause: The tool call retrieval threshold is not set correctly, causing the matching logic to not meet the business requirements of forging quality traceability.
- Symptom: Historical forging data cannot be read after cross-version upgrade, or database table models cannot be viewed. Cause: The database directory was directly migrated without exporting metadata, causing incompatibility between FastGPT v4.6.7 and FastGPT v4.8.10 database table structures, and original table definition information was not retained.

## How to confirm the configuration is complete
- Run a local MongoDB connection test, use the configured database connection address to verify connection availability via the command line tool.
- Submit a simulated forging batch query request, confirm that associated data such as heating furnace records and ultrasonic testing reports can be returned.
- Check the database connection pool status, confirm that the current active connection count does not exceed the configured maximum database connection value.
- Adjust the tool call retrieval threshold, verify that associated knowledge base answers are returned when the matching degree meets the standard, and preset prompt content is returned when the matching degree does not meet the standard.
- Check the database metadata, confirm that the fields of each table match the forging business requirements. The table structure definition can be exported via a database client.

The values provided here are common starting points, and should be evaluated against the user's own samples.
