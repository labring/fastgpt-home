# Quality Issue Traceability and Defect Analysis for Precast Concrete Components: Knowledge Base Retrieval and Recall

## What Data for This Category Looks Like
Data related to precast concrete components covers full-process documentation for factories producing PC components, pipe piles, bridge components, and municipal products. This documentation includes component detail drawings, steel bar cutting lists, mold inspection records, pouring and vibration logs, curing records, and demolding and factory inspection reports.
Data sources include BIM or detail design files, steel bar and concrete batch ledgers, mold table and curing kiln operation data, laboratory test results, and QR code traceability systems.
Data updates occur at the frequency of single components, per batch of materials, and per curing kiln batch. Core fields include unique component ID, batch number, steel bar specification, curing duration, demolding strength, and others. Document structure mixes structured tables and unstructured engineering drawings.

## What Constraints These Characteristics Impose on Knowledge Base Retrieval and Recall
The multi-source heterogeneous data structure of precast concrete components requires retrieval to support matching both structured table fields and unstructured drawing text.
High-frequency updated single-component and batch data requires the retrieval system to quickly respond to precise queries for single components, and avoid redundant data interference.
The business characteristic that each component corresponds one-to-one with on-site lifting positions requires retrieval results to strictly match component ID and batch number, preventing cross-production line and cross-batch data from being included.
Errors such as embedded part misalignment and insufficient strength have serious consequences. Retrieved results must have high precision to reduce the workload of manual secondary screening.

## Configuration Settings
Configuration instructions under FastGPT v4.17.0 are as follows:

| Configuration Item | Recommended Value | Rationale |
| --- | --- | --- |
| `similarity` | 0.75–0.85 | Matches core fields such as unique component ID and batch number for precast concrete components, balances precision and recall coverage |
| `limit` | Top 10 entries | The amount of associated data for a single batch of components is limited. Limiting returned entries avoids context overload and adapts to the conciseness of workflow calls |
| `searchMode` | `mixedRecall` | Covers both text keywords from BIM drawings (such as component numbers) and vector retrieval (such as embedded part position descriptions), adapts to mixed document structures |
| `usingReRank` | Enabled | Performs secondary sorting on initial recall results to correct deviations from single vector matching, adapts to complex association requirements such as embedded part positions and steel bar arrangement |
| `datasetSearchUsingExtensionQuery` | Enabled | Automatically expands associated queries for component IDs and batch numbers, matches cross-document auxiliary data such as steel cutting lists and curing records |
| `collectionIds` | Configured by factory production line grouping | Distinguishes component datasets for different production lines, prevents cross-factory and cross-project data from interfering with retrieval results |

## Three Common Configuration Mistakes
- Phenomenon: After importing an Excel-format steel bar cutting list into a table dataset, retrieval fails to return matching results for the corresponding component ID. Cause: The component ID and batch number fields in the Excel file were not configured as retrieval association keys, so the imported table data did not establish correct index mappings.
- Phenomenon: After an HTTP request in a workflow returns multiple variables, retrieval results include precast component data from cross production lines. Cause: The `collectionIds` parameter was not used to specify the knowledge base collection for the current production line, so the recall scope covered irrelevant datasets.
- Phenomenon: Curing records from curing kilns do not appear in quality traceability retrieval results. Cause: `datasetSearchUsingExtensionQuery` was not enabled, so automatic association between component IDs and batch fields of curing records was not possible, leading to auxiliary data not being included in the retrieval index.

## How to Confirm Proper Configuration
- Upload Excel cutting lists and detail drawing documents for a single batch of components, enter the component ID to perform retrieval, check whether returned results include all associated documents for the corresponding batch.
- Adjust the `similarity` parameter range, verify whether the matching precision of retrieval results meets the precise matching requirements for core fields, with no irrelevant data included.
- Enter the dataset configuration page, confirm that function switches such as `usingReRank` and `datasetSearchUsingExtensionQuery` are enabled.
- Simulate an HTTP request returning multiple variables in a workflow, bind the specified `collectionIds` before performing retrieval, check whether results only include component data from the current production line.

The values provided are common starting points and should be validated against samples appropriate for the specific use case.
