# Quality Issue Traceability and Defect Analysis for Ready-Mixed Concrete Production: Model Integration and Configuration

## What the data for this category looks like
Data for this category comes primarily from engineering orders, sand, gravel, cement admixture inspection records, aggregate moisture content measurement data, mixing plant control system logs, and project laboratory test block and strength reports. Daily associated documents include mix proportion notices, opening identification forms, production and transport orders, raw material inspection reports, and test block retention records.
Data updates follow per-batch raw materials, per-vehicle production tasks, and daily laboratory testing frequencies. Fields include raw material batch numbers, moisture content values, slump indicators, test block strength grades, pouring locations, and times. Units include kilograms, cubic meters, megapascals, percentages, seconds, and others.

## Constraints imposed on model integration and configuration
The multi-source, decentralized nature of the data requires model integration to support structured and semi-structured documents in different formats. It also requires configuring reading logic adapted to multiple data sources.
Frequently updated per-vehicle production data requires the context window to support real-time incremental synchronization. This avoids traceability deviations caused by data lag.
The strong association between single-batch raw materials and test blocks requires the model to accurately match batch numbers and pouring time fields when recalling associated data. It also requires preventing irrelevant data from being included.
The requirement for age verification of test block strength requires the model configuration to retain long-term storage indexes for historical data. This avoids losing traceability basis due to data expiration.

## How to set configurations
This document is written based on the configuration logic of FastGPT v4.17.0.

| Configuration Item | Recommended Setting | Rationale |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 token | Adapts to the total length of single-vehicle production data and multi-batch raw material inspection records, covering all associated documents required for a single traceability |
| `maxTokens` | 4000 token | Limits the output length of a single round of responses, avoiding overly lengthy analysis that exceeds the reading efficiency of quality management personnel and dispatchers |
| `quoteMaxToken` | 1500 token | Limits the total character count of recalled referenced documents, matching the typical length of core associated data in ready-mixed concrete production |
| `temperature` | 0.2–0.4 | Reduces randomness, ensuring consistency of quality traceability results and avoiding analysis deviations caused by fluctuations |
| `AIPROXY_API_ENDPOINT` | Fill in according to the deployment environment | Adapts to local or cloud-based model call addresses, ensuring data transmission security and stability |
| `AIPROXY_API_TOKEN` | Generate according to permission allocation | Restricts access permissions for model calls, preventing unauthorized queries of quality data |

## Three common mistakes
- Symptom: The reranker model fails to start, and the console returns a connection timeout error. Cause: `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are not configured correctly, interrupting the model call link.
- Symptom: The chat window integrated via iframe cannot retrieve the model’s returned output content. Cause: The front-end callback interface is not configured, and the listening event for model output is not bound. This prevents data from synchronizing to the parent page.
- Symptom: The token consumption displayed in model calls differs from the actual API bill. Cause: The `maxContext` parameter is not set correctly. Redundant recalled data is included in the context token statistics, which does not match the actual token amount processed by the model.

## How to confirm the configuration is complete
- Perform a traceability test for a single batch of raw materials. Verify that the associated documents returned by the model include the correct mix proportion notice and moisture content measurement data.
- Submit an analysis request involving slump abnormalities. Verify that the analysis logic output by the model matches the business process of ready-mixed concrete production.
- View the model call logs. Confirm that there are no format errors in the configuration of `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`.
- Test the iframe-integrated chat window. Confirm that analysis results returned by the model can be received and displayed normally after a query is initiated.

The values provided are common starting points and should be measured against the reader's own samples.
