# Shopify fulfillment: product questions with citation tracing

## What the documents look like

For product questions in Shopify fulfillment, this page examines FastGPT citation tracing. The original narrow-neck order and a wide-neck change request need separate source attribution. The examples are hypothetical.

## Constraints at the citation tracing step

A proposed Shopify selection exercise uses an original order entry and a variant-change message. The order lists a narrow-neck bottle with a straight brush; the message requests a wide-neck bottle, with no confirmation reply included. A question about what will now be received needs these sources kept separate. The message establishes the requested change but cannot establish that the order was updated. The original entry identifies the initial selection, while the current fulfilment variant requires any subsequent confirmation to be checked. The wide-neck request does not rewrite the brush entry. Even a later confirmation limited to bottle type would leave the brush relationship to inspect. Check which individual items a change actually covers, so that a request about one attribute does not silently reconfigure the whole originally recorded combination.

## Configuration and implementation checks

| Task check | Material condition | Evidence action |
| --- | --- | --- |
| Original combination | Bottle and brush share one order entry | Preserve their paired attributes. |
| Requested change | Wide-neck bottle appears in the message | Check for a separate confirmation. |
| Source title | Filename may differ from document role | Check confirmation wording to establish its role. |
| Current fulfilment | Subsequent confirmation absent from this fixture | State the unresolved scope. |
| Citation transfer | Order and message each have distinct wording | Compare with actual citation-array content. |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Associated knowledge bases` | Knowledge bases associated with one search node must use the same embedding model. |
| `Citation output` | The output is an array; an empty array can continue. |
| `Citation input handoff` | Inspect citations actually received by the answer step. |
| `Citation display check` | Trace displayed sources to their originals. |
| `Document-validity check` | Inspect source identity and applicable version separately. |

## Three common errors

Source confusion can create an inconsistent answer in two ways. If a citation points to the narrow-neck description while the answer gives wide-neck specifications, inspect whether the actual passage contains those attributes. If a file is labelled change confirmation but its text contains only the request, inspect its identity and the confirmation wording itself. FastGPT citation content helps show what reached the answer; a document title or a buyer preference cannot establish execution. Missing confirmation also does not establish that no later change occurred.

## How to verify the setup

Ask separately about the initial order, the requested change and the unresolved current variant. Compare each answer with its supporting material. The narrow-neck bottle and straight brush should retain their original pairing, while the wide-neck request should remain unconfirmed within the supplied record. Inspect the actual order and message passages rather than treating a displayed link as sufficient evidence. An empty citation array calls for tracing the current passage-transfer process; it cannot establish that no message was sent or that the merchant rejected the request.
