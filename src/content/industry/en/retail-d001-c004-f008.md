# Temu semi-managed sellers: workflow routing for product questions

## What the documents look like

Temu semi-managed sellers differ from fully managed suppliers in one operational respect: the seller maintains overseas inventory and arranges shipment rather than supplying goods to the platform. Whether a product can be sold and whether dispatch meets the platform deadline both feed directly into platform fulfilment outcomes. The materials relevant to this page are the product declaration form, the overseas inventory sheet, the price declaration, and the platform fulfilment order. These materials update daily or per order. In product information and selection questions, they serve as the factual source, while workflow routing carries what a user fills in or selects to downstream nodes. The act of collection does not confirm inventory, price, or fulfilment status.

## Constraints at the workflow routing step

The form input node is a user interaction node. When it triggers, the conversation enters an interaction state and the workflow state is recorded. After the user completes the required fields and submits, the node collects the submitted information and passes it to subsequent nodes. The user selection node is also a user interaction node. It triggers the same interaction state, records workflow state, and after the user makes a choice, evaluates that choice and executes the corresponding branch. Both nodes can be added repeatedly and both trigger execution.

Hypothetical paper case: the source material reads "Subject: a semi-managed store operator; Object: SKU-A product declaration form; Status: completed, pending submission; Effective scope: March 2025 batch." A second sentence reads "The overseas inventory sheet shows SKU-A available quantity at the overseas warehouse as 120 units, updated 10 March 2025." The draft sentence to be assessed is "SKU-A has completed product declaration and can be listed for sale immediately." The subject, object, status, and effective scope needed for assessment are present in the source text. The claims "has completed declaration" and "can be listed immediately" do not appear in the source text.

The constraint at this routing step is that interaction nodes collect values the user fills in or selects. A form submission does not equal business review approval, and executing a user selection branch does not equal platform approval to list. Inventory quantity and declaration status must be compared against later retrieval or judgement nodes, and a retrieval result does not constitute authorization. Order writing, document backfill, and external status synchronization require separate business interfaces or downstream processes. Workflow routing itself does not perform these actions.

## Configuration and implementation checks

| Configuration item | Setting method | Verification point |
| --- | --- | --- |
| Form input node | Enters interaction state on trigger, collects required information | Whether submitted information is passed to subsequent nodes |
| User selection node | Executes the corresponding branch after the user makes a choice | Whether branch connections are verified one by one |
| Interaction state check | Recorded state is behaviour of the interaction node | No separate global state recording switch is set |
| Output handover check | Collected information is passed to subsequent retrieval or judgement nodes | Whether each output is compared item by item against the input |
| External action division | Order writing, document backfill, external synchronization connect to separate interfaces | Whether the workflow claims to perform these actions |

Hypothetical trial starting point: set the required fields of the form input node to the SKU number and batch number from the product declaration form. The reason for this choice is that these two fields correspond uniquely within the same batch of materials. The comparison object is the record with the same SKU number and batch number in the overseas inventory sheet. This starting point is a hypothetical trial setting for this page, not an official default value.

## Three common errors

1. Treating a form submission as business review approval. The form input node collects required information and passes it to subsequent nodes; the submission action itself produces no review conclusion. During checking, compare whether the draft sentence contains statuses such as "reviewed" or "approved" that the source text does not state.

2. Treating execution of a user selection branch as platform authorization. The user selection node evaluates the user's choice and executes the "yes" branch; branch execution is an internal workflow path and does not mean the platform has approved listing or authorized sales. During checking, compare whether the draft sentence equates the branch result with external authorization.

3. Treating a retrieval result as a permission or entity filter. Similar content returned by retrieval does not confirm product, inventory, or fulfilment status, and does not exclude unauthorized records. During checking, compare whether the draft sentence infers business status from a retrieval hit.

## How to verify the setup

1. Using the source text and draft sentence from the hypothetical case, the input is "SKU-A product declaration form status is completed, pending submission." Compare whether "has completed declaration" in the draft sentence "SKU-A has completed product declaration and can be listed for sale immediately" matches the source wording "pending submission." The expected observation is that the two statuses differ and the draft sentence is not supported by the source text.

2. Using the overseas inventory sheet wording from the hypothetical case, the input is "SKU-A available quantity 120 units, updated 10 March 2025." Compare whether "can be listed for sale immediately" in the draft sentence has corresponding support in the source text. The expected observation is that the source text states only inventory quantity and update date, states no listing permission, and that part remains to be verified.

3. Using the draft sentence to be assessed from the hypothetical case, the input is the complete draft sentence text. Compare whether each business status word in it can be matched to a record with the same subject, same period, and same field in the source material. The expected observation is that "has completed declaration" and the source wording "pending submission" take different values in the same field, and "can be listed immediately" has no corresponding field in the source text. Both items are unsupported.
