# Temu semi-managed sellers: model connections for product questions

## What the documents look like

Semi-managed sellers on Temu maintain a storefront in Temu Seller Center while also running overseas warehouse stock and outbound shipping. The working documents for this category are the product declaration form, the overseas inventory sheet, the price declaration, and the platform fulfillment order. These materials update daily and per order. Product information and option-selection question answering has to line up the declared product name, specification, and declared price on the declaration form with the sellable quantity and warehouse location on the inventory sheet, so operations staff can judge whether a given product can keep selling or whether declared information needs adjustment.

FastGPT uses AI Proxy to reach model providers, and AI Proxy also supplies load balancing, model logs, and data dashboards. The system needs at least one language model and one indexing model to work normally. Indexing models index text chunks for related-text retrieval. A similarity score is a retrieval ranking value; it does not act as a permission filter or an entity-isolation filter. Knowledge-base retrieval association requires the same vector model; libraries built on different vector models cannot be associated together, and the correct step is to compare identifiers and exclude those that do not match.

## Constraints at the model connections step

Model connections depend on AI Proxy. Both App and Admin must set AIPROXY_API_ENDPOINT and a non-empty AIPROXY_API_TOKEN; missing either one causes startup validation to fail. AIPROXY_API_ENDPOINT takes the service root address without an appended /v1. The model ID is the value of the model field in the request body and is globally unique. A model channel is separated by protocol type, and one model can be configured across multiple channels to achieve load balancing.

Assume a paper exercise sample. A semi-managed seller operations staffer drafts a product declaration form. The source text reads: "Entity: a cross-border supplier in Yiwu; Object: SKU A folding table; Status: declared price 12.99 USD, overseas warehouse sellable 40 units, price declaration valid until 31 May 2026." The proposed judgment sentence reads: "SKU A's declared price has taken effect and can continue selling." That sentence treats the price declaration validity period as a supply term and does not check the platform fulfillment order status. The material does not state that the quote has been confirmed by the platform, and does not state a supply term, so the sentence is unsupported.

This page covers only model connections and configuration for product information and option-selection question answering. It does not turn retrieval or a form into an authorization action.

## Configuration and implementation checks

| Configuration item | Assumed trial starting value | Reason and comparison object |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | Assume http://aiproxy:3000 | Official requirement is the root address without /v1; compare against a value containing /v1 |
| AIPROXY_API_TOKEN | Assume a non-empty admin token | Official requirement is consistency with the server side; compare against an application API key |
| Model types | Assume one language model and one indexing model enabled | Official requirement is at least one of each; compare against enabling only a language model |
| Model ID | Assume a custom identifier | Official statement is global uniqueness; compare against the model name inside a channel |
| Vector library identifier | Assume pgvector | Official statement is that only the same vector model can be associated; compare against a Milvus identifier |
| Probe interval | Assume 15 minutes | Official range is an integer from 5 to 60; compare against 5 minutes |

These are assumed trial starting values for a paper exercise, not official defaults. The environment variables AIPROXY_API_ENDPOINT and AIPROXY_API_TOKEN are documented as required. The probe interval range of 5 to 60 integer minutes is documented. Model types, model ID uniqueness, and the same-vector-model association condition are documented. This table is an implementation check list for this page's documents, not a claim that any of these values were deployed.

## Three common errors

1. Treating the price declaration validity period as the supply term. The sample source text only states validity until 31 May 2026 and does not state a supply term. The check compares whether the proposed judgment sentence equates the validity-period field with the supply-term field; when the two fields differ, the judgment is unsupported.
2. Treating a pending review as already effective. The sample does not state that the quote has received platform confirmation. The check compares whether a platform confirmation record exists in the material; when it is absent, record the item as pending verification.
3. Associating libraries across different vector models. The sample assumes the vector library is pgvector and another library is Milvus. The check compares the two library identifiers; when they differ, exclude the association and do not run a cross-model retrieval comparison to measure missed recall.

## How to verify the setup

1. Input the sample source text and the proposed judgment sentence. Compare whether "has taken effect" in the proposed sentence and "valid until 31 May 2026" in the source text refer to the same field. When the source text does not state an effective status, the judgment is unsupported.
2. Input the sample source text and a supply-term question. Compare whether the source text contains a supply-term field. The source text contains only a price declaration validity period, so record an evidence gap and do not judge it as a negation or a conflict.
3. Input the vector library identifier pgvector and another library identifier Milvus. Compare whether the two are the same vector model. When the identifiers differ, exclude the joint association and record the actual observation without inferring a runtime result.

These verification steps describe what to compare and what remains unknown. They do not claim that any test, deployment, approval, or refund took place. A pending request is not an approval, an offered option is not an execution, and an unsigned termination is not a completed termination. Missing evidence stays missing.
