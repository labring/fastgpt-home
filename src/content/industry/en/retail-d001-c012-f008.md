# Warehouse picking and packing: workflow routing for product questions

## What the documents look like

Warehouse picking, checking, and packing handles order outbound work. It does not handle supplier arrivals or putaway, which belong to a different stage. The documents in this category are wave picking lists, checking records, shipping labels, and packaging consumable sheets. These records update per order or per hour. Pickers, checkers, and packing supervisors raise requests during product information and option-selection questions, and the system needs to connect product records and packaging consumable options to specific order lines.

The consequences of error here are wrong or missing shipments, damaged parcels, and after-sales compensation. Workflow routing therefore separates information collection, option presentation, and downstream judgment. The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and after the user submits, the collected values pass to later nodes. The User Selection node is also a user interaction node. When the user makes a choice, the node evaluates that choice and executes the corresponding "yes" branch. Waiting and state recording are behaviors of these interaction nodes. No separate global state-recording switch is documented.

## Constraints at the workflow routing step

Retrieval results supply candidate material only. They do not constitute authorization. A relevance score does not carry category, entity, or permission filtering duties, and it cannot be used to exclude unrelated business or unauthorized records. Forms collect values. Business verification, approval, database writes, and external synchronization each require their own downstream implementation. Empty-reference output and context limits keep their documented conditions. Only libraries using the same vector model can be associated together. Libraries on different vector models must first have their identifiers checked, and non-matching ones excluded.

The optional paths shown in the overall workflow diagram do not mean every request executes all of them. Image retrieval requires a corresponding image input and model capability. Reranking requires a model and must be enabled in settings. A pending review is not an approval. An offered option is not an execution. An unsigned termination is not a completed termination.

Hypothetical paper exercise sample: The wave picking list submitted by a picker reads "Wave W-0715, order line A-01, product code SKU-8842, quantity 3, pick location B-12, checking status is pending check." The checking record reads "Checker has scanned SKU-8842, physical count 3, outer carton intact." The draft sentence to be assessed reads "SKU-8842 has completed checking and may proceed to packing and consumable selection." This sample is used for paper comparison only. It does not represent any real warehouse or real order.

## Configuration and implementation checks

| Configuration item | Relevant setting or check for this page | Correspondence with the sample |
| --- | --- | --- |
| Form Input node | Enters interaction state on trigger, collects required information, passes it to later nodes after submission | Collects the checking confirmation value for SKU-8842 |
| User Selection node | Executes the corresponding "yes" branch after the user makes a choice; verify branch connections one by one | Enters the matching branch when a packaging consumable category is chosen |
| Output handoff check | Passes collected information explicitly to later retrieval, judgment, or interface nodes; compare output against input item by item | The checking value passes into consumable selection judgment |
| Interaction state check | State recording is interaction-node behavior; no separate global state-recording switch is documented | Interaction state is maintained while awaiting checking submission |
| External operation separation | Order writes, document backfill, and external status synchronization require a separate business interface or later process | Writing the completed check into the WMS requires a separate interface |
| Retrieval scope check | Only libraries on the same vector model can be associated together; check identifiers first and exclude non-matching ones | The product record library and the consumable library are checked separately |

Hypothetical starting value for this exercise: the checking confirmation is set as a required field. The reason is that the sample shows checking status as pending check, and submission is needed before the workflow continues. This starting value is not an official default. It is used for this paper comparison only, and it is compared against whether later nodes actually receive the value.

## Three common errors

1. Treating a retrieval hit as authorized execution. Retrieving the SKU-8842 record in the sample does not mean the order line is cleared for packing. The input is the retrieval result; the comparison object is the authorization status field; the continue condition is met only when checking status changes from pending check to checked.
2. Treating a pending-check draft sentence as a completed fact. The draft says "has completed checking," while the sample checking record states only that the item was scanned and the physical count is 3, with no completion conclusion. The input is the draft sentence; the comparison object is the checking record text; when the two states do not agree, the sentence is not supported.
3. Treating form submission as an external write. The Form Input node collects and passes values. In the sample, after the checking value is submitted, a separate connection to the WMS write is still required. The input is the form output; the comparison object is whether the downstream interface received that value; without that connection, the action remains incomplete.

## How to verify the setup

1. Compare the draft sentence against the sample source text. Input the wave picking list text and the checking record text; compare "checking status is pending check" with the draft sentence "has completed checking." If the source text contains no completion conclusion, the draft sentence remains unverified and must not be output as checked.
2. Compare the sample choice request against the branch. Input the User Selection node question and the hypothetical choice "select packaging consumable category"; compare the "yes" branch connected to that choice. If the branch is not connected to a consumable selection node, record that the handoff is absent and do not infer automatic selection.
3. Compare an empty result against the downstream design. Input an explicit paper retrieval result of []; compare whether the downstream node handles an empty reference. If there is no empty-result branch downstream, record the gap. Do not claim that a fabricated rule-based retrieval necessarily returns []. Libraries on different vector models cannot be associated together; check identifiers only, exclude non-matching ones, and record what is actually observed.
