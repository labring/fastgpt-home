# Letter-of-credit documents: model connections for product questions

## What the documents look like

Letter-of-credit document examination and presentation serves bank payment conditions, with document consistency as the working focus; tax matching belongs to a separate line. Each transaction involves a letter of credit, commercial invoice, bill of lading, insurance policy and draft. Source material includes issuing-bank notices, UCP600 clauses, forwarder bills of lading and bank presentation records. Document examiners, bank international settlement teams and exporters handle this work. Errors lead to refusal, deductions and delayed collection. Materials update per transaction. Model connection and configuration must let product-data and selection questions cite the text of these documents while keeping clauses, document fields and statuses distinct.

Three features shape this page. First, the document set is fixed per transaction, so questions about product data and model selection must stay attached to named documents rather than general trade knowledge. Second, the evidence for a consistency judgment lives in specific fields such as issuer, consignee and currency, so a model connection that cannot keep those fields separate produces unusable answers. Third, presentation status has stages, and a drafted sentence is not a bank receipt.

## Constraints at the model connections step

Model connection depends on AI Proxy. Both App and Admin services that reuse App/Service configuration must set `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN`; missing either causes startup validation to fail. `AIPROXY_API_ENDPOINT` holds the AI Proxy service root address without `/v1`. Model channels, model configuration and application-side parameters are checked separately; a same-named field on a chat interface does not overwrite orchestration settings.

A hypothetical drill sample, clearly labelled as such: a letter of credit requires presentation of a commercial invoice, a bill of lading and an insurance policy. The invoice must be issued by the beneficiary. The bill of lading consignee field must carry the name designated by the issuing bank. The insurance policy currency must match the letter of credit. A drafted sentence reads: "This shipment has completed presentation under the letter of credit and the documents are consistent." The drafted sentence carries no presentation record or bank receipt and remains unverified.

The system needs at least one language model and one indexing model to operate. Model channels are created on the admin model-provider page, tested through model test, and enabled before use. Model status probing applies only to currently enabled system models, retries up to three times after a first failure for a maximum of four attempts in one round, and treats a single success as valid.

## Configuration and implementation checks

| Configuration item | Hypothetical trial starting point | Comparison method |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | AI Proxy root address entered without `/v1` | Compare character by character with the deployed root address |
| `AIPROXY_API_TOKEN` | Non-empty admin token matching the server | Compare with the AI Proxy server configuration |
| Language model | One usable language model selected and enabled | Confirm enabled status on the model-provider page |
| Indexing model | One usable indexing model selected and enabled | Confirm at least one language and one indexing model exist |
| Model channel test | Model test run on the configured channel | Read the test result and request duration |
| Model probing | Automatic probing enabled as needed with an interval set | Interval is an integer between 5 and 60 minutes |

The values above are hypothetical trial starting points chosen for comparison against the documented ranges; they are not official defaults. The endpoint and token rows follow the documented startup-validation requirement. The model rows follow the documented minimum of one language model and one indexing model. The probing interval follows the documented 5-to-60-minute integer range.

## Three common errors

1. `AIPROXY_API_ENDPOINT` is filled with a full request address plus `/v1`. Check whether the input is a service root address, compare with the documented root-address requirement, and observe whether startup validation fails.
2. An application API key is used in place of `AIPROXY_API_TOKEN`. Check whether the entered value is the admin token, compare with the server configuration, and observe whether validation cannot pass.
3. The drafted sentence "This shipment has completed presentation under the letter of credit and the documents are consistent" is treated as a verified conclusion. Check whether a presentation record or bank receipt is attached, compare with the sample's unverified status, and observe whether the sentence remains pending verification.

## How to verify the setup

1. Enter the letter-of-credit requirements and the three document fields from the hypothetical sample. Compare the invoice issuer, the bill-of-lading consignee field and the insurance-policy currency against the letter of credit. Observe the item-by-item comparison result. The drafted sentence is not treated as evidence, and missing evidence stays missing.
2. Enter the drafted sentence "This shipment has completed presentation under the letter of credit and the documents are consistent." Compare whether a presentation record or bank receipt is attached. Observe whether the sentence is marked pending verification. A pending request is not approval, and an unsigned termination is not a completed termination.
3. Enter the model channel configuration. Compare whether `AIPROXY_API_ENDPOINT` is a root address without `/v1`. Observe the model test result and request duration. A model that has not been tested is not judged usable.
