# Franchisee onboarding: workflow routing for product questions

## What the documents look like

Franchisee training and opening coaching is a transfer of operating capability, not a legal filing or disclosure exercise. The working materials are training sign-in sheets, opening checklists, SOP manuals, and assessment scores. They come from the training system, the supervisor app, store photographs, and the headquarters SOP library. The brief records these materials as updated per store and per month. One store in different months can correspond to different versions, and one SOP manual can be referenced by several stores.

For product information and selection questions, the practical work is to turn the fields, statuses, and validity scope in those materials into inputs that can be checked, then let interaction nodes in the workflow collect supplementary information. The form input node is a user interaction node. When it triggers, the conversation enters an interaction state and the workflow state is recorded; after the user fills required information and submits, the node collects the submitted form information and passes it to later nodes. The user selection node is also a user interaction node. When it triggers, the conversation enters an interaction state; when the user makes a choice, the node judges the choice and executes the corresponding "yes" branch. These two node types carry information collection and branch judgment. Retrieval and authorization judgment are not performed by the nodes themselves.

## Constraints at the workflow routing step

Both form input and user selection enter an interaction state when triggered and wait for the user to complete the interaction before continuing downward. Workflow routing therefore needs a place to hold the interaction wait, and collected information must be explicitly passed to later retrieval, judgment, or interface nodes, with output and input compared item by item. Order writing, document backfill, and external status synchronization are business actions. They require a separate business interface or a later flow and cannot be completed directly by an interaction node.

The vector model identifier of a retrieval library must be checked first. Libraries that use different vector models cannot be associated together. A relevance score does not carry permission or entity isolation duties, and retrieval itself does not constitute authorization. The optional paths shown in an overall document flowchart do not mean every request executes all of them. Image retrieval requires a corresponding image input and model capability, and reranking requires a model and must be enabled according to settings.

## Configuration and implementation checks

The configuration below stays with this page's main task and one hypothetical drill sample. The sample is as follows. A chain brand training department received opening coaching materials submitted by a franchisee in March 2025. The material text reads: "This store has completed cashier and inventory training, sign-in sheet number A-2025-0312, assessment score 76, opening checklist pending regional supervisor review." The proposed determination sentence is: "This store's opening coaching is fully complete and can proceed to opening." The sign-in sheet and assessment score are stated in the material. The opening checklist status is pending review, and no review conclusion is stated.

| Configuration item | Content on this page | How to check |
| --- | --- | --- |
| Form input node | Collect required fields such as sign-in sheet number and assessment score | After submission, compare field values passed to later nodes item by item |
| User selection node | Set a branch for "whether the opening checklist has been reviewed" | Execute the corresponding "yes" branch according to the user's actual choice |
| Interaction state hold | Enter interaction state and record workflow state after triggering | Confirm that execution continues downward after the wait ends |
| Output passing | Pass collected information to later retrieval or judgment nodes | Compare input and output item by item |
| Retrieval library model identifier | Check that libraries being associated use the same vector model | Exclude those whose identifiers do not match; do not perform cross-model association |
| Business action division | Order writing, document backfill, external synchronization | Confirm a separate business interface or later flow is attached |

## Three common errors

1. Reading "opening checklist pending regional supervisor review" as "review completed." The material states only pending review and states no review conclusion. The proposed determination sentence "opening coaching is fully complete" lacks supporting evidence from the same field. This is unsupported, and it cannot be treated as a negation or a conflict.

2. Treating the sign-in sheet number and assessment score collected by the form input node as an authorization basis. The node behavior is to collect and pass information. Retrieval and authorization judgment must be done by later nodes or a separately attached flow. The collection action itself does not produce authorization.

3. Associating two retrieval libraries together without checking the vector model identifier. Libraries using different vector models cannot be associated together. The identifier must be checked first and non-matching libraries excluded, with actual observations recorded. No runtime result after association is inferred.

## How to verify the setup

The following verification uses the hypothetical drill sample above and does not claim that testing has been performed.

1. Input the material text "sign-in sheet number A-2025-0312, assessment score 76, opening checklist pending regional supervisor review" and the proposed determination sentence "this store's opening coaching is fully complete and can proceed to opening." Compare the status value of the same field, "opening checklist": the source text says pending review, and the proposed sentence says complete. If the proposed sentence cannot be supported by the same field in the source text, it is judged unsupported, and the evidence gap is retained.

2. Input the field set submitted through the form input node. Compare the fields passed to later nodes against the submitted fields item by item. If the sign-in sheet number and assessment score both appear in the later node input and the opening checklist status field remains "pending review," the output passing condition is met. If a field is missing or the status is rewritten, record the difference.

3. Input the vector model identifiers of the two retrieval libraries to be associated. Compare whether the identifiers match. Common association may be performed only when the identifiers match. When they do not match, exclude the non-matching library and record the actual observation. For empty-result handling, a clearly written paper input of [] can be used to check the downstream design. No claim is made that a fictional rule retrieval necessarily returns [].

Operational handover must keep clear which materials, operations, and requests are in what authorization state. Retrieval and forms are not authorization execution.
