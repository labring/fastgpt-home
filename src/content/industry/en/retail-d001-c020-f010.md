# Certificates of origin: citation tracing for product questions

## What the documents look like

A certificate of origin serves import-country tariff treatment and customs clearance, and it is not necessarily governed by a letter of credit. For one export consignment, the commercial invoice, packing list and production cost records may come from different staff members, while the certificate application is filed separately through China International Trade Single Window or a CCPIT system. Material updates follow a per-consignment or batch rhythm.

In product data and selection questions, a documentation clerk often needs to confirm which material, and which version of that material, supports a given answer. The objects handled at the citation tracing step are the correspondence between retrieval output and the answer. The knowledge base search node outputs cited content as an array, and the array length can be zero, which means the output path still runs when nothing is retrieved. The answer stage receives those citations, and a person checks whether the product description, origin rule judgment and selected certificate type in the answer can be matched to sentences in the cited source text.

## Constraints at the citation tracing step

Knowledge base search can select one or more knowledge bases that use the same vector model. Knowledge bases with different vector models cannot be associated together; the identifiers must be checked first and non-matching bases excluded. Retrieval is a recall operation and does not perform permission or entity isolation. The minimum relevance value is a filtering threshold and is not used to exclude unrelated businesses or unauthorized records.

The citation limit controls the maximum amount of content cited per search in tokens, and it is unrelated to thinking budget. Hybrid retrieval merges multiple result paths through RRF, which is a fusion process rather than a switch that can be turned on. Reranking requires a ReRank model and must be enabled according to settings, and image retrieval requires corresponding image input and model capability. The optional paths shown in the document flow diagram do not mean every request executes all of them.

Hypothetical drill sample: a documentation clerk at a company searches the knowledge base for "export to a Southeast Asian country, product is plastic household goods, can a certificate of origin be applied for." One material in the knowledge base states: "All production processes for this batch of plastic household goods were completed domestically, and the imported component share in raw materials is below the upper limit allowed by the rule. Commercial invoice number INV-2024-0312, packing list number PL-2024-0312, shipment date 20 March 2024." Another material is a historical version of the same product and records a higher imported component share than the current version. The draft sentence is: "This batch of goods can apply for a certificate of origin, on the basis that all production processes were completed domestically." The question is whether the material version cited by this draft sentence matches the current batch.

## Three common errors

1. Treating retrieval output directly as an authorization basis. Knowledge base search returns a citation array, and the array length may be zero; the retrieval action does not complete origin rule determination, certificate application or customer customs clearance confirmation. During checking, compare whether the subject, batch and date of the cited source text match the draft sentence, and record missing corresponding fields as pending verification.
2. Treating minimum relevance as an entity or permission filter. This value takes effect only in semantic retrieval or result reranking, and is used to filter low-relevance results. During checking, compare recalled content under different relevance settings for the same question and observe whether records of other companies or other products appear; this cannot be used to infer that the system has excluded unauthorized data.
3. Mixing historical version material with current-batch material. The same product may have multiple production record versions with different imported component share values. During checking, compare the material date, invoice number and packing list number cited by the draft sentence item by item against the current-batch material; mutually exclusive values are recorded as contradictory, and values not stated are recorded as unsupported.

## How to verify the setup

1. Input the question and the two material source texts from the hypothetical sample, and compare whether the citation array returned by retrieval contains the current-batch material. Observe whether the sentence "all production processes were completed domestically" in the answer can be matched word for word in the cited source text. If the citation points to the historical version material, the draft sentence does not match the current batch, and the version difference must be recorded.
2. Input the draft sentence "This batch of goods can apply for a certificate of origin, on the basis that all production processes were completed domestically," and compare its subject, object, status and valid scope with the cited source text. The source text contains an invoice number and a packing list number, while the draft sentence does not state a batch identifier. If the batch identifier does not appear in the cited source text, the draft sentence is unsupported; if it appears and the date matches, record it as traceable.
3. Input an empty citation array and compare the design of the downstream answer stage. The knowledge base search node outputs citations with a length that can be zero, and the output path still runs. Observe whether the answer stage still generates a conclusive statement when citations are empty. If a conclusion is generated without citation support, the answer is disconnected from its citation source, and the actual behavior of that branch must be recorded.
