# Brand member operations: citation tracing for product questions

## What the documents look like

Brand member operations in private-domain retail centers on customer data and repeat-purchase outreach. The working materials include member tag tables, outreach plans, coupon rules, and privacy authorization records. The main data sources are CRM systems, enterprise WeChat, POS transaction records, and mini-program behavior data, with daily or weekly update cycles. Product information and selection Q&A in this setting requires that answers trace back to a specific source. When fields such as member tier, coupon-eligible product scope, or authorization status are cited incorrectly, the direct consequences are outreach harassment complaints or uncontrolled coupon costs. This page addresses citation sources and tracing only: how retrieval output maps item by item to source text, and which materials, operations, or requests sit at what authorization state during an operations handover.

## Constraints at the citation tracing step

The knowledge base search node can select one or more knowledge bases that share the same vector model, and it outputs references as an array whose length may be zero. When no content is found, that output path still completes. Retrieval results pass through similarity filtering and a reference upper limit measured in tokens before reaching the answering step. The minimum relevance value takes effect only in semantic retrieval or when result reranking is used; that threshold is a filtering condition and does not perform permission or entity isolation. Hybrid retrieval merges multiple result paths through RRF. Reranking requires a model and must be enabled by configuration. Image retrieval requires corresponding image input and model capability. These optional paths do not indicate that every request executes all of them. Retrieval and forms collect or return content; business verification, approval, database writes, and external synchronization each need their own downstream implementation.

Hypothetical paper exercise sample: A brand CRM team retains one member tag table source text reading "Member ID M-2041, tier Silver, authorization status signed electronic authorization letter, authorized scope limited to member benefit notifications, authorization valid from January 1, 2025 to December 31, 2025." The same batch of materials contains an outreach plan source text: "Plan to send a new-product selection questionnaire to Silver members in June 2025, applicable product scope is current-season apparel." One draft sentence to be judged reads: "M-2041 has authorized receiving all brand marketing information and may be sent current-season apparel and beauty new-product messages." This sample is a paper exercise and involves no real customer or real identifier.

## Configuration and implementation checks

| Configuration or check item | Hypothetical starting point for this page | Reason for the choice and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Select two product information bases already marked with the same vector model | Check the vector model identifier first, exclude those that do not match, and do not run cross-model retrieval |
| Reference upper limit | Set to 2000 tokens as this exercise's starting point | Compare against the sample source text length to confirm the reference can cover the tag table and outreach plan source text |
| Minimum relevance | Set to 0.5 as this exercise's starting point | Compare against rerank scores and observe whether the sample source text remains after filtering |
| Reference output handoff | Connect retrieval output to the answering step | Check each answer sentence against the cited source text and inspect whether any authorization scope absent from the source appears |
| Material currency check | Use the 2025 tag table and outreach plan | Compare against the authorization scope stated in the draft sentence and confirm whether the validity period and applicable products match |
| Authorization status check | Manually compare authorization record fields | Check whether signing, cooperation reaching agreement, and contract taking effect are treated as three separate facts |

## Three common errors

1. Treating a retrieval hit as authorization. Error behavior: because a Silver member tag is retrieved, M-2041 is assumed to be able to receive all marketing information. Executable check: input the tag table source text and the draft sentence, compare "authorized scope limited to member benefit notifications" against "all brand marketing information," and observe whether the two share the same subject, the same period, and the same field.
2. Treating a pending review request as approved. Error behavior: when the outreach plan sits in a pending-review state, the push is executed as if approved. Executable check: input the outreach plan source text and the handover request, compare the plan status field, and observe whether an approval record exists.
3. Treating a similarity threshold as entity isolation. Error behavior: raising the minimum relevance is assumed to exclude unauthorized member records. Executable check: input the same query against records with different authorization statuses, compare the returned results, and observe whether the threshold change alters the record set.

## How to verify the setup

1. Citation tracing check. Input the tag table source text above and the draft sentence, compare the authorization scope and validity period in the draft sentence against the corresponding fields in the source text. The tracing condition is met only when each item corresponds literally with no expansion; the draft sentence containing "all brand marketing information" does not meet it.
2. Empty-reference handoff check. Input a paper reference array [] and compare the downstream answering step's design, observing whether it handles the case as content with no reference. This check does not claim that a fictional rule retrieval necessarily returns an empty array.
3. Material currency check. Input the 2025 tag table and outreach plan, compare the period stated in the draft sentence against the source validity period, and observe whether it falls within January 1, 2025 to December 31, 2025. Content outside that range or not stated in the source is recorded as unsupported or pending verification.
