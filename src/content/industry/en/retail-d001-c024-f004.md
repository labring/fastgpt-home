# Brand concession operations: vector indexes for product questions

## What the documents look like

Concession counters in shopping malls take payment through the mall's central checkout, and the brand settles with the mall under a concession deduction arrangement. The same sale therefore appears in the mall POS, the brand ERP, the finance system, and the monthly reconciliation statement, each with its own purpose and level of detail. Product information and selection questions draw on four document types: concession deduction contracts, mall activity letters, sales receipts, and monthly reconciliation statements. The people handling this material are brand retail staff, mall operations staff, and concession counter managers. These documents update daily and monthly.

For retrieval, contract clauses, activity conditions, receipt line items, and reconciliation amounts sit in separate materials. A vector model and index must connect fragments that describe the same product or the same settlement item back to a checkable original passage. The smallest search unit is the library, not the collection; collections exist for classification and do not affect search results.

## Constraints at the vector indexes step

Libraries associated for one search must share the same vector model. Before linking them, confirm the actual model identifier and its supported input types, and exclude any library that does not match. Libraries built on different vector models cannot be associated together. This is a check performed before association, not a comparison run across models.

In MongoDB's dataset.datas table, one original data record can correspond to multiple vector IDs held in an indexes field. PostgreSQL stores vectors in a vector field. During retrieval, vectors are recalled first, then the original content is fetched from MongoDB by vector ID; records mapping to the same original data are merged and the highest score is kept. Index content should be complete and focused, and the trade-off between retrieval coverage and index length depends on the sample at hand.

Image retrieval depends on whether an image description index or an image vector index was generated at ingestion time. Uploading an image on the query side does not by itself make an image retrievable. Hybrid search merges semantic and full-text results through RRF. Reranking requires a configured model and must be enabled under its settings. The minimum relevance score applies only in semantic search or when result reranking is used; it is a filtering threshold and does not perform permission or entity isolation. Retrieval is not authorization. Forms collect values; business verification, approval, database writes, and external synchronization each need their own downstream implementation.

## Three common errors

1. Associating knowledge libraries that use different vector models. The input is two libraries with non-matching model identifiers. Compare the model identifiers and input types, and observe whether the non-matching library is excluded before association. The runtime result of associating across models is not described in the documentation and is not asserted here.

2. Treating an image uploaded on the query side as making the image retrievable. The input is an image query and a library where no image index was generated at ingestion. Compare the ingestion index record with the query result, and observe whether the reference content is empty. An empty result is checked against the output path whose array length can be 0.

3. Treating the minimum relevance score as a permission or entity filter. The input is the same question group under different relevance settings. Compare the referenced original text and scores before and after filtering, and observe whether unrelated business records can still be recalled. A relevance score does not perform authorization judgments.

## How to verify the setup

1. For the draft sentence "the deduction ratio during the 15 June activity period is 22%", input this sentence together with the contract and activity letter text. Compare whether the reference content includes Clause 3 and the activity letter's date range, and observe whether the referenced original text can support that ratio statement.

2. For the handover request in the sample, input the request text. Compare whether the reference content covers both the activity letter's time range and the reconciliation statement's settlement basis, and observe whether the references are sufficient to check the adjustment target. If either item is missing from the references, record the check as not satisfied.

3. For empty-result handling, input the paper input `[]`. Compare how the downstream node handles a reference array of length 0, and observe whether the output path still runs. Do not claim that a fictional rule search necessarily returns `[]`.

After any model or index adjustment, compare referenced original text using the same question group. Do not promise results based on vector scores alone.
