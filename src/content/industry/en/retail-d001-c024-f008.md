# Brand concession operations: workflow routing for product questions

## What the documents look like

A brand concession inside a shopping mall sells through the mall POS, while the brand ERP keeps a separate record of inventory and product data. At settlement the two streams are reconciled into a monthly statement. The joint-operation concession contract sets the commission rate and the settlement cycle. The mall activity letter states the conditions and resource positions for a given promotion period. The sales receipt is the evidence for a single transaction. These materials come from different parties and cover different periods.

For product data and selection questions, the practical question is how a specific item at a specific concession should be selected for a given promotion and which commission rate applies when the figures are checked. Workflow routing is what sequences document collection, condition evaluation, and human confirmation. The Form Input node and the User Selection node both belong to the user interaction category. When either node triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. The Form Input node collects required information the user fills in and passes it to later nodes after submission. The User Selection node evaluates the user's choice and runs the corresponding yes branch. Neither node performs business verification.

## Constraints at the workflow routing step

Mall POS data, ERP product records, and activity letter conditions come from separate sources. Retrieved content indicates semantic relevance only. It does not indicate that the requesting party is authorized to view a record, and it does not indicate that an item qualifies for a promotion. Commission settlement, promotion enrollment, and monthly reconciliation involve writes to external systems. These require a separate business interface or a downstream process. The routing layer does not replace authorization or approval.

Daily updates or per-transaction updates to source materials do not, on this page, justify a batch synchronization mechanism or a transaction-triggered mechanism. The interaction state, the recording of workflow state, and the hiding of the dialog box are documented behaviors of the interaction nodes. No separate global state switch, submission count, automatic judgment, or snapshot guarantee follows from them. Mixed-result fusion is a process for combining results and is not written as a toggle. A thinking budget is a reasoning allowance and is not a citation token limit.

## Configuration and implementation checks

The following settings describe a hypothetical drill sample. They do not represent any real concession or contract.

Hypothetical drill sample: a brand concession signs a joint-operation commission contract with a mall. The contract text states: "Contract number H-001; the concession entity is Brand A; the settlement cycle is the calendar month; the commission rate is twenty percent of the month's tax-inclusive sales; the contract is valid from January 1, 2024 to December 31, 2024." The mall activity letter states: "The activity period is May 1 to May 7, 2024; concessions joining the activity keep the contract commission rate; activity resource positions are arranged in order of registration." A draft sentence to be assessed reads: "The commission rate for the Brand A concession in May 2024 is lower than twenty percent." The materials needed for the check are the contract text and the activity letter text, both within the accessible target retrieval scope.

| Configuration item | Hypothetical starting point for this drill | Check method and reason |
| --- | --- | --- |
| Form Input node | Collect concession entity, contract number, settlement month | After submission, pass to the later retrieval node and compare each form value against the source text for the same entity and same period |
| User Selection node | Set a branch for "does the commission rate match the contract" | After the user chooses, run the yes branch and verify branch connections and downstream nodes one by one |
| Retrieval scope | Limit to the two document types: joint-operation commission contract and mall activity letter | Observe whether returned content falls in this scope; semantic relevance does not indicate viewing rights |
| Empty-result handling | Paper input [] checked against downstream design | State that an empty array reaching downstream shows pending verification; do not claim a fictional rule always returns [] |
| External operation split | Commission settlement and activity enrollment marked as separately connected interfaces | The routing layer does not write settlement results; a downstream system and manual review are required |

## Three common errors

1. Treating a retrieval hit as authorization. Suppose retrieval returns a fragment of contract H-001 and routing proceeds directly into the settlement branch. The check input is the retrieval result and the current requesting entity. Compare whether the two refer to the same concession entity. The observable result should be that, without confirmed authorization, the flow stays at manual review and does not enter settlement.

2. Treating a pending review as approved. Suppose the activity letter states only "arranged in order of registration" and the draft sentence reads "the activity resource position has been obtained." The check input is the activity letter text and the draft sentence. Compare whether the source text states that a resource position has been allocated. The observable result should be that the draft sentence is unsupported and the evidence gap is preserved.

3. Associating libraries that use different embedding models. Suppose two libraries use different embedding models and routing attempts to merge retrieval. The check input is the model identifier of each library. Compare whether the identifiers match. The observable result should be that non-matching libraries are excluded and the actual observation is recorded, without running cross-model retrieval to compare missed recall.

## How to verify the setup

1. For the draft sentence "The commission rate for the Brand A concession in May 2024 is lower than twenty percent," input the contract text and the activity letter text. Compare the same entity, the same period, and the same commission rate field. Observe that the contract states twenty percent and the activity letter states the contract rate is kept. The draft sentence is unsupported.

2. For the Form Input node, input the concession entity and the settlement month. Compare the form values against the entity and period in the contract text. Observe that after submission the information passes to the downstream retrieval node, and that the downstream node does not treat the form values as verified authorization.

3. For empty-result handling, input the paper array []. Compare whether the downstream node displays a pending-verification state. The observable result should be that the flow does not enter the settlement branch, and no claim is made that a fictional rule always returns [] on retrieval.
