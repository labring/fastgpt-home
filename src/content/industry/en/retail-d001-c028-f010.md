# Brand livestream operations: citation tracing for product questions

## What the documents look like

Brand livestream operations differ from influencer-hosted sessions in that the brand itself carries the sales script, inventory, and after-sales service. Commission to external hosts is not the primary commercial mechanism. Product information and selection Q&A therefore need citation sources that map back to the livestream script, product explanation card, shift schedule, and livestream review. The script and explanation card define selling points, applicable models, and inventory wording. The shift schedule defines the handover scope of the host and floor manager on duty. The review record determines whether the same document version continues into later sessions.

Materials update per session. Within one session, the explanation card version may differ from the script version. Citation tracing must distinguish document version from the authorization scope of the current shift. Data sources include the Douyin Shop Compass, Juliang Qianchuan, livestream comments, and transaction details. These sources help check whether materials match what was actually said. They do not replace the version identifier on the material itself.

## Constraints at the citation tracing step

The knowledge base search node can link one or more knowledge bases that use the same vector model. Its output is a citation array whose length may be zero. An empty array does not mean the workflow has errored or stopped. Citation tracing requires that product information in an answer can be traced to a specific material entry. Retrieved results are candidate content only. Whether they are used still depends on the valid version and the authorization review of the current shift. The minimum relevance value takes effect only under semantic retrieval or result re-ranking. It is a filter threshold and does not perform permission or entity isolation. Hybrid retrieval merges multiple retrieval paths through RRF. After re-ranking, a 0-1 score is produced and used for filtering. That score cannot be used to conclude that a class of business records has been excluded. Image retrieval requires image input and model capability. Re-ranking requires a model and must be enabled by configuration. The optional paths listed in the documents do not mean every request executes all of them.

Hypothetical drill sample: A brand livestream team's product explanation card for the 10 June 2025 session states: "Model A portable fan, applicable models A1 and A2, inventory subject to the shift schedule note for the day, explanation wording subject to this card's 10 June version." Paragraph 3 of the same session's livestream script states: "Model A supports only model A1; model A2 does not participate in this session's explanation." The shift schedule note states: "Model A inventory 120 units, valid before 20:00 on 10 June." A draft sentence to be assessed reads: "Model A portable fan supports models A1 and A2 this session, inventory 120 units." This draft sentence conflicts with the explanation card on applicable models, and does not state the inventory validity period recorded in the shift schedule note. It is unsupported.

## Three common errors

1. Treating the retrieval score as a permission filter. The minimum relevance value is a filter threshold; it does not exclude unauthorized records or distinguish business entities. Check: input the sample question, compare whether returned citations include materials from other sessions, and observe whether entries unrelated to the authorization scope appear.

2. Treating an empty citation array as an error. The search node output length may be zero, and an empty array still passes through the output path. Check: use the paper input `[]` to review the downstream answer step design, observe whether the downstream handles it as no citation, and do not claim that a fabricated rule retrieval necessarily returns empty.

3. Linking knowledge bases with different vector models. Linking requires the same vector model. Check: verify the vector model identifier of each selected knowledge base, exclude those that do not match, and record the actual observation. Do not run cross-model retrieval to compare missed recalls.

## How to verify the setup

- Verification 1: Input the sample explanation card text and script paragraph 3. Compare the draft sentence "Model A portable fan supports models A1 and A2 this session, inventory 120 units" against both source texts. The explanation card lists A1 and A2; the script lists only A1. The same field holds mutually exclusive values, so this is judged as a conflict. The inventory validity period in the shift schedule note is before 20:00; the draft sentence does not state a validity period, so this is judged as unsupported.

- Verification 2: Input the shift schedule note "Model A inventory 120 units, valid before 20:00 on 10 June." Compare whether the draft sentence covers that time window. The draft sentence does not state a validity period, so it is judged as unsupported. The validity period must be added or the explanation window restricted.

- Verification 3: Input the search node citation array `[]`. Compare whether the downstream answer step handles it as no citation. Observe whether the downstream continues to produce an answer and whether it indicates no source. Record the actual behavior. Do not claim that this input necessarily produces a fixed result.

This page addresses only citation tracing for product information and selection Q&A in brand livestream operations. During operational handover, the explanation card version, shift schedule note, and script paragraph remain in a pending-review state. Retrieved results and form collection do not constitute authorized execution. Signing, deal completion, and contract effectiveness are three distinct facts. A quotation validity period does not indicate a supply period. Missing evidence remains missing. A pending review does not demonstrate a lack of operating permission.
