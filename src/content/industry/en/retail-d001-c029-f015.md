# After-sales repairs and reships: retrieval for product questions

## What the documents look like

After-sales repair and reship work aims to restore a product to usable condition. Closure comes from a completed repair or a delivered replacement part, while a direct refund follows a separate handling path. The main data comes from the after-sales system, the order system, repair sites, and the spare-parts warehouse WMS. Daily documents include repair applications, reship orders, inspection reports, and spare-part outbound records. Updates occur per order and per day, so retrieval faces several materials under one order that sit at different stages. Product-reference and selection questions ask whether a given model of part fits a particular repair, whether a reship order and an inspection report point to the same product, and which processing stage currently applies. Because sources are dispersed, the same object may carry different field names in the after-sales system and in the WMS, so the identifier convention must be confirmed before retrieval.

## Constraints at the retrieval step

A knowledge base consists of libraries, collections, and data. The smallest search unit is the library; a collection only classifies data and does not affect search results. The knowledge-base search node can associate one or more knowledge bases that use the same vector model. Libraries built on different vector models cannot be associated together; confirm the model identifier and exclude non-matching libraries rather than running a cross-model retrieval comparison. Full-text retrieval suits exact queries such as numbers, models, and proper nouns. Semantic retrieval suits natural-language phrasing. Hybrid retrieval merges the two paths through RRF. RRF is a result-fusion process, not a switch that can be turned on. Reranking requires a model and must be enabled in settings. Image retrieval requires image input and matching model capability. The optional paths shown in the documented flow diagram do not all execute on every request. Minimum relevance takes effect only under semantic retrieval or when result reranking is used; it is a filter threshold and does not perform permission or entity isolation. Retrieval itself does not constitute authorization.

Hypothetical drill sample: the material text for cross-checking consists of three sentences. Sentence one: "Reship order BS-2024-0517, order A-8831, product is XX brand water-purifier filter element, quantity 1 piece, applicant after-sales agent Li, submission date 17 May 2024." Sentence two: "Inspection report JC-2024-0516 states that for the same order A-8831 the filter-element joint leaks, judged as a parts quality problem, and recommends reshipping the same model of part." Sentence three: "Spare-part outbound record CK-2024-0518 logs an outbound product of XX brand water-purifier filter element, quantity 1 piece, linked to reship order BS-2024-0517, status shipped." The draft sentence to be judged is: "This order has completed the reship, and the customer has confirmed receipt." This sentence concerns receipt confirmation, which none of the three materials states, so it is unsupported.

## Three common errors

1. Treating a retrieval hit as authorized execution. In the sample the reship order status is submitted and the outbound record status is shipped; neither states receipt confirmation. Judging "reship completed" from these records treats a retrieval result as a completed business fact. Compare whether the materials state a receipt-confirmation field.
2. Treating pending review as missing permission. The sample does not state an approval status, so no conclusion follows that the applicant lacks operating permission. Record this as unsupported and preserve the evidence gap.
3. Confusing the same field with a related field. The three materials record submission, inspection, and outbound respectively, which are different fields. A contradiction exists only when the same field carries clearly mutually exclusive values. Compare field by field and do not draw conclusions across fields.

## How to verify the setup

1. Input the three sample sentences and the draft sentence, with retrieval scoped to the after-sales repair and reship library. Compare whether "reship completed" and "customer has confirmed receipt" in the draft sentence share the same subject, period, and field as the source text. The materials do not state receipt confirmation, so the judgment is unsupported, not negative and not conflicting.
2. Input the same question through semantic, full-text, and hybrid retrieval. Compare the hit differences for BS-2024-0517 and "filter-element leak reship." Full-text retrieval should hit the number, semantic retrieval should hit semantically similar content, and hybrid retrieval may order results differently after RRF fusion. A first-position hit or full recall is not guaranteed.
3. Input an empty-citation scenario and check the downstream chain with the paper input `[]`. The knowledge-base search node outputs an array whose length can be 0; even when nothing is found, the output chain still runs. Do not claim that a fabricated rule guarantees retrieval returns `[]`.
