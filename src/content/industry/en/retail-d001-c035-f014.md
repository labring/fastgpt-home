# Trade returns and claims: model connections for product questions

## What the documents look like

Trade return and claim work handles reverse logistics and liability determination after export. The material set differs from ordinary export declaration: it draws on customer email, quality inspection reports, customs systems and insurance claim systems, and the working documents are return agreements, claim letters, quality reports and return customs declarations. Product information and selection Q&A must answer whether a given shipment can be returned, who bears the cost, and which quality conclusions support a claim. These records update case by case, once per case, with no fixed cycle.

For model connection and configuration, the decisive property is that these documents carry subject, object, status and validity scope. A signature block, an effective-date clause and a cost clause are separate pieces of evidence, and a retrieval hit does not by itself establish that any of them is satisfied. The model connection step produces answers; it does not produce authorization, approval or a completed business action.

## Constraints at the model connections step

This page addresses model connection and configuration only. AI Proxy is a required dependency from V4.17.0. App and Admin services that reuse App/Service configuration must set `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN`; a missing or empty value causes startup validation to fail. Legacy OpenAI environment variables and single-model custom request addresses do not replace these two settings.

Model channels are configured on the administrator model provider page. Model ID is the value of the `model` field in the request body and is globally unique. The system needs at least one language model and one index model. A model can be configured in more than one channel to achieve load balancing. Channel priority ranges from 1 to 100, and a larger value is more likely to be selected. A disabled channel no longer provides model service. Retrieval results and similarity scores do not carry permission or entity isolation, and libraries built on different vector models cannot be jointly associated.

Hypothetical paper exercise sample. Material one is an excerpt of a Return Agreement. Party A is an exporter and Party B is an overseas buyer. The text states: "This agreement takes effect on the date both parties sign it." In the signature block, Party A has signed and Party B's signature field is blank. Material two is an excerpt of a Quality Report. The inspection object is the March 2025 shipment batch, and the conclusion states: "Appearance does not conform to Appendix 2 of the contract." The draft sentence to be assessed is: "The two parties have reached a return agreement, and the return cost is borne by the buyer." That sentence contains two facts to be checked: whether the agreement is effective, and whether there is a basis for cost bearing. The materials do not state a cost clause.

## Configuration and implementation checks

The table centers on this sample. Values are starting points for this hypothetical exercise, with the reason for choosing them and the comparison object named.

| Configuration item | Hypothetical starting point | Reason and comparison object |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | `http://aiproxy:3000` | Official example form, without `/v1`; compare against the actual deployment root address |
| AIPROXY_API_TOKEN | Non-empty administrator token | Documentation requires consistency with the server side; compare against the application API key, which cannot substitute for it |
| Language model enabled | One llm enabled | Documentation requires at least one language model; check separately from index model count |
| Index model enabled | One embedding enabled | Documentation requires at least one index model; check separately from language model count |
| Channel model ID | Matches the model inside the channel | Documentation states model ID is globally unique; compare against the model ID of the enabled model |
| Probe interval | 30 minutes | Documentation supports integers from 5 to 60 minutes; compare against this exercise's observation period |

The two required AI Proxy values are checked at startup. The model enablement checks are configuration facts, not runtime results. The channel model ID check compares an identifier, and a mismatch is recorded rather than resolved by retrieval. The probe interval is a hypothetical starting value chosen inside the documented range, and it is compared against the observation period used in this exercise; it is not an official default.

## Three common errors

1. Filling `AIPROXY_API_TOKEN` with an application API key. Input: the token value in the deployment configuration. Comparison object: the AI Proxy server administrator token. Observable result: startup validation passes when the two are consistent and non-empty, and fails when either is missing or empty.
2. Reading "Party A has signed, Party B is blank" as an effective agreement. Input: the signature block of the sample Return Agreement. Comparison object: the clause stating effectiveness on the date both parties sign. Observable result: whether a Party B signature record can be found; when it cannot, the fact is not supported.
3. Treating the appearance conclusion in the Quality Report as a basis for cost bearing. Input: the conclusion of the sample Quality Report. Comparison object: a cost clause. Observable result: whether the materials contain a cost agreement; the sample does not state one, so the cost part of the draft sentence remains unverified.

## How to verify the setup

1. For the draft sentence "The two parties have reached a return agreement," input the signature block and the effectiveness clause of the sample Return Agreement. Compare whether Party B's signature field is blank. Observable result: the Party B signature record is absent, so "have reached" is not supported and the sentence should be marked as pending verification.
2. For the draft sentence "the return cost is borne by the buyer," input the full text of both sample materials. Compare whether a cost-bearing clause exists. Observable result: the materials state no cost clause, so that part remains unsupported, and no authorization or effectiveness clause is supplied to fill the gap.
3. For the model connection, input the two settings `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`. Compare each against the actual server-side value. Observable result: startup validation passes when both are non-empty and consistent, and fails when either is missing or empty. At the retrieval step, check model identifiers and exclude those that do not match; an empty result is checked against downstream design using the explicit paper input `[]`, without claiming that a fabricated rule necessarily returns an empty result.

A pending request is not approval, an offered option is not execution, and an unsigned termination is not a completed termination. Where a document field is not provided, it remains unknown.
