# Multi-warehouse inventory: document chunking for product questions

## What the documents look like

Multi-warehouse allocation and inventory synchronization make their central decision at the order routing stage, where the system determines which warehouse ships an order. The daily materials for this stage are allocation rules, inventory synchronization tables, transfer orders, and stockout alerts. They arrive from WMS, OMS, ERP inventory, and platform inventory interfaces, and they update daily or hourly. A single paragraph often carries warehouse priority, sellable scope, transfer status, and alert conditions together. When chunking separates a condition from the object it constrains, the retrieved fragment lacks the basis for a routing judgment. Product information and selection questions need fragments that can be traced back to the source text, and the warehouse identifier, inventory basis, and effective scope in the material must stay consistent with the indexed content.

## Constraints at the document chunking step

Parsing first checks the source structure and the parsed result, preserving a document identity and version that can be traced back to the original. Segmentation completeness requires checking paragraphs against the structure of the specific material, so conditions, explanations, and the content they constrain are not split apart.

Data and index are distinct. The MongoDB `dataset.datas` table stores the original vector data, and its `indexes` field records the corresponding vector IDs as an array, so one set of original data can map to multiple vectors. The PostgresSQL table uses a `vector` field to store vectors. During retrieval, vectors are recalled first, then the vector IDs are used to find the original content in MongoDB; entries corresponding to the same set of original data are merged, and the highest vector score is taken. Multi-vector mapping balances content length against semantic richness: several vectors can be added for one long text, and recall of any one vector recalls that data. For full-text retrieval on PG and similar vector stores, the path is MongoDB `$text` with jieba tokenization. Hybrid retrieval merges semantic and full-text results through RRF. Rerank performs a second ordering of candidate text, and its score runs from 0 to 1. The reference limit is measured in tokens. The minimum relevance value takes effect only under semantic retrieval or when result reranking is used; it is a filtering threshold and does not perform permission or entity isolation. Retrieval is a recall process and does not constitute authorization.

Hypothetical exercise sample: a supply chain planning group checks an "East China Region Warehouse Priority Description (version 2026-03-01)" in March 2026. The source text reads: "East China orders ship by default from the Suzhou warehouse first; when Suzhou sellable inventory falls below the safety value, route to the Hangzhou warehouse. While a transfer order status is 'in transit,' the source warehouse inventory is not counted as sellable inventory." A draft sentence awaits judgment: "When Suzhou warehouse inventory is insufficient, all East China orders ship from the Hangzhou warehouse." The check object is that version of the description and the draft sentence. The authorization boundary is document checking and retrieval observation, with no actual routing execution.

## Configuration and implementation checks

| Configuration or check item | Setting relevant to this page | Implementation check method |
| --- | --- | --- |
| Chunking basis | Segment by the structure of allocation rules, inventory synchronization tables, transfer orders, and stockout alerts | Check whether the condition sentence and the object it constrains remain in the same fragment |
| Multi-vector mapping | One set of original data can map to multiple vectors; `indexes` records vector IDs | Check whether multiple indexes for the same original data point to the same content |
| Retrieval mode | Semantic retrieval, full-text retrieval, or hybrid retrieval | Use full-text or hybrid retrieval for numbers and warehouse names; use semantic or hybrid retrieval for natural-language questions |
| Fusion and reranking | RRF merges multiple retrieval paths; Rerank performs a second ordering with a 0-1 score | Check whether reranking is enabled per the setting and whether the rerank score is used for filtering |
| Reference limit | Each search references at most n tokens | For this exercise, start from a fragment length that covers one complete allocation rule and compare against a fragment holding only half a condition |
| Minimum relevance | A 0-1 value effective only under semantic retrieval or result reranking | Check whether fragments retaining both condition and object survive the filter |

## Three common errors

1. Splitting a condition from the object it constrains into different chunks. The input is the first sentence of the sample source text. Compare whether the chunked fragment contains both "Suzhou sellable inventory falls below the safety value" and "route to the Hangzhou warehouse." If the fragment holds only the second half, the retrieved content lacks the trigger condition.

2. Treating the draft sentence "all East China orders ship from the Hangzhou warehouse" as a source conclusion. The input is the sample source text and the draft sentence. Compare whether the source text contains the scope qualifier "all." The source text states only "route to the Hangzhou warehouse" and does not state all orders, so the draft sentence is unsupported.

3. Treating a retrieval hit as authorized execution. The input is the sample source text containing the transfer order status. Compare the retrieval result against a routing execution action. Retrieval returns reference content only; actual routing requires a separate system implementation. The transfer order status "in transit" is a recorded fact and does not constitute an execution instruction.

## How to verify the setup

1. Input the first sentence of the sample source text and the draft sentence. Compare whether the chunked fragment preserves the complete conditional relation between "East China orders ship by default from the Suzhou warehouse first" and "when Suzhou sellable inventory falls below the safety value, route to the Hangzhou warehouse." Observe whether the returned fragment can trace back to both items.

2. Input the third sentence of the sample source text and the transfer order status field. Compare whether source warehouse inventory is excluded from sellable inventory while the status is "in transit." Observe whether the returned fragment preserves the correspondence between the status and the inventory basis. If the fragment contains only "source warehouse inventory is not counted as sellable inventory" and omits the "in transit" condition, record it as incomplete segmentation.

3. Input the draft sentence and the sample source text. Compare whether the scope qualifier "all" appears in the source text. Observe that the check conclusion is unsupported. If retrieval returns an empty result, use an explicit paper input of an empty array to check the downstream design, without claiming that a fictional rule necessarily returns an empty result.
