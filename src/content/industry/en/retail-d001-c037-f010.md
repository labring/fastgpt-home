# Peak-sale fulfillment: citation tracing for product questions

## What the documents look like

Peak-sale warehousing and dispatch planning revolves around short-term peak capacity and the arrangement of people, vehicles and space. Historical peak-sale orders, platform campaign registration, WMS capacity and courier pickup capability together form the basis for scheduling. Forecasting the order peak, arranging temporary staff and coordinating courier vehicles are the most time-consuming steps. Citation tracing directly affects whether a scheduling conclusion can be reviewed by another person. The daily documents include the peak-sale forecast table, staff shift roster, courier support plan and exception daily report. The forecast table and courier support plan carry the version dates that determine whether a cited figure is still valid for the campaign being planned.

For product data and selection questions, the citation tracing step has to answer a narrow question: which document and which version does a stated figure come from, and does the wording of the draft preserve the status recorded in that document. A forecast quantity, a pickup vehicle count and an authorization state are three different fields. A figure copied accurately from the wrong version, or a figure whose status word has been strengthened, both fail the same review.

## Constraints at the citation tracing step

The knowledge base search node can select one or more knowledge bases that share the same vector model. Its output is an array of cited content, and the array length may be zero; when no content is retrieved, the output path still runs through. The citation limit controls, in tokens, the maximum amount of content cited per search. The minimum relevance value applies only under semantic retrieval or when result reranking is used. Hybrid retrieval merges multiple retrieval paths through RRF, and reranking produces a 0-1 score used for filtering. Retrieval results are passed to the answering step, where the answer and the cited source text are checked item by item.

Retrieval is not authorization. A search result showing that a courier support plan lists a co-ordinable vehicle count does not establish that those vehicles have been confirmed for a specific campaign date. The minimum relevance value is a filtering threshold, not a category, entity or permission filter, and it does not exclude unrelated businesses or unauthorized records. The same-vector-model requirement applies to associating knowledge bases within this search node; it does not extend to any external system.

Hypothetical paper exercise sample: a warehousing and dispatch project team intends to review scheduling material before a peak sale dated 18 June 2025. The source material submitted for review reads: "The 15 June 2025 version of the peak-sale forecast table states that the East China warehouse peak order volume is 80,000 orders. The courier support plan states that 40 pickup vehicles can be co-ordinated on that day." One draft sentence awaiting judgment reads: "The East China warehouse has confirmed 40 pickup vehicles on 18 June." The draft sentence converts the co-ordinable quantity in the support plan into a confirmed quantity, and it does not state the authorization status for 18 June itself.

## Configuration and implementation checks

| Configuration or check item | Hypothetical starting point for this exercise | Comparison method and reason |
| --- | --- | --- |
| Associated knowledge bases | Select the peak-sale forecast table and courier support plan bases that share the same vector model | Only bases with the same vector model can be associated together; check the identifier first and exclude those that do not match |
| Citation limit | Set a token amount that covers the peak paragraph of the forecast table and the vehicle paragraph of the support plan | Compare against the actual tokens of both source paragraphs so a key quantity is not truncated |
| Minimum relevance | Enable under semantic retrieval or reranking, with the value set by reference to the candidate score distribution | Compare against the 0-1 rerank score to filter low-relevance fragments |
| Search mode | Use semantic retrieval for "East China warehouse peak order volume" and full-text retrieval for identifier-type queries | Compare against the query type; identifiers and model numbers suit full-text matching |
| Citation hand-off | Pass the search node citation array to the answering step | Compare the answer against the cited source text item by item; answer fluency does not replace source evidence |
| Document currency check | Test sources with the 15 June 2025 version and an earlier version | Compare version dates; whether a citation is adopted still depends on review against the valid version |

## Three common errors

1. Writing "can co-ordinate 40 pickup vehicles" from the courier support plan directly as "has confirmed 40 vehicles". The input is the support plan source text; the comparison is between the status values "can co-ordinate" and "confirmed"; the observable result is that the draft introduces a confirmation state the source does not record.
2. Treating the citation limit as a top-k item count. The input is the citation limit setting; the comparison is between the token unit and a chunk item count; the observable result is that configuring by item count truncates long chunks or under-cites short chunks.
3. Treating an empty citation array as a workflow error. The input is the search node output; the comparison is between the array length and the downstream hand-off design; the observable result is that a length of zero still runs the output path through, so an error judgement lacks a basis.

## How to verify the setup

1. Input the forecast table source text and the draft sentence from the hypothetical sample. Compare whether "peak order volume 80,000 orders" is cited accurately in the draft. The condition is met when the draft does not rewrite the quantity and notes the source version date; it is not met when the draft adds a commitment the source does not record.
2. Input the support plan source text and the "confirmed 40 vehicles" draft sentence from the hypothetical sample. Compare the field values "can co-ordinate" and "confirmed". The observable result is that these are different states, the draft sentence is not supported by the source, and the authorization status must be returned for verification.
3. Input an explicit paper-form empty array `[]` to the downstream hand-off design. Compare whether the downstream handles it as a zero-citation branch. The condition is met when the downstream does not error on the empty array and records the gap. This check does not claim that a fictional rule retrieval will necessarily return an empty array.

This page addresses only peak-sale warehousing and dispatch / product data and selection questions / citation tracing. Whether material, an operation or a request is in an authorized state at handover cannot be resolved by retrieval or by a form. The forecast table and support plan carry version dates, and the review compares the draft wording against the status field actually recorded in the cited version. Where the source does not state a status, or states only a related stage, the draft is unsupported or pending verification rather than contradicted.
