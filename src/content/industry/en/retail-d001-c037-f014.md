# Peak-sale fulfillment: model connections for product questions

## What the documents look like

Peak-sale warehouse and delivery scheduling centers on short-term capacity peaks and the arrangement of people, vehicles, and space. This differs from multi-warehouse inventory synchronization, which pursues longer-term balance across locations. The working documents for this category include peak-sale forecast tables, staffing rosters, courier support plans, and daily exception reports. Their update rhythm is per event and per day.

When these materials feed product-information and selection questions, the first question is whether model connection and configuration can support retrieval and citation of the subjects, objects, and effective ranges recorded in forecast tables, rosters, and support plans. A forecast table names a warehouse, a date range, a peak order volume, a staffing ceiling, and a courier plan identifier with its applicable object. A question-answering setup has to carry those fields through to an answer without adding states the source never recorded.

The forecast, roster, and support documents are the evidence base. They are not authorization records. Whether a courier plan has taken effect, whether a staffing ceiling has been approved, and whether a handover request has been granted are separate facts that the documents may or may not state.

## Constraints at the model connections step

A hypothetical drill sample is used here for paper comparison. The source text of a warehouse peak-sale forecast table reads: "From June 1 to June 18, 2026, the East China No. 1 warehouse peak order forecast is an average of 120,000 orders per day, the temporary staffing roster ceiling is 800 people, and the courier pickup support plan number is KD-2026-06, applicable to the East China No. 1 warehouse." A draft handover sentence awaiting judgment reads: "Please confirm, based on KD-2026-06, that courier pickup support for this warehouse from June 1 to June 18 has taken effect." Comparison requires aligning the draft sentence with the source on subject, period, and status field. The source records the plan number and the applicable object. It does not record an effective status. The draft sentence's claim of "has taken effect" is therefore unsupported and must be logged as pending verification.

On model connection, the App and Admin services must both set AIPROXY_API_ENDPOINT and a non-empty AIPROXY_API_TOKEN. Missing either one causes startup validation to fail. Legacy OpenAI environment variables cannot substitute for these two settings. The system needs at least one language model and one index model to operate normally. Model capability is checked against the input the application requires, with multimodal input, tool calling, and thinking configuration verified separately.

Semantic recall and relevance scores do not perform permission or entity isolation. Retrieval is not authorization. A requirement that a knowledge base and its vector model share the same model identifier constrains only that pairing. It does not extend to business-registration sites or other external systems. A relevance score is not a category, entity, or permission filter, and a similarity setting does not exclude unrelated businesses or unauthorized records.

## Configuration and implementation checks

The table below lists implementation check items for this hypothetical trial starting point. The values are trial starting points used for comparison against documented defaults or ranges. They are not official recommendations.

| Configuration item | Hypothetical trial starting point | Comparison method and basis |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | Set to an internal service root address | Compare against the documented requirement: no appended /v1; a missing value fails startup validation |
| AIPROXY_API_TOKEN | A non-empty administrator token is entered | Compare against the server-side configuration; must be non-empty and not an application API key |
| AGENT_ENGINE | Kept at fastAgent | Compare against the documented options fastAgent and piAgent |
| Index model | One index model enabled | Compare against the requirement of at least one language model and one index model |
| Model probe | Automatic probing enabled, interval set to 10 minutes | Compare against the documented integer range of 5 to 60 minutes |
| HNSW_EF_SEARCH | Trial starting point set to 100 | Compare against the documented default of 100; applies only to PG, OceanBase, and openGauss |

The AIPROXY_API_ENDPOINT value is a service root address, not a full model request address. The AIPROXY_API_TOKEN value is a server-side administrator token, not an application API key. The probe interval is an integer within the documented range. The HNSW_EF_SEARCH setting takes effect only for the listed vector stores.

## Three common errors

1. Writing AIPROXY_API_ENDPOINT with an appended /v1 or a full chat-completions path. Check the input value for an appended path segment and compare against the documented instruction not to append /v1. An appended path fails the comparison.
2. Entering an application API key into AIPROXY_API_TOKEN. Check the source of the field value and compare against the server-side administrator token requirement. A value sourced from an application key fails the comparison.
3. Treating retrieval similarity as a permission or entity-isolation mechanism. Check whether a relevance setting is used to exclude unrelated business records or unauthorized records, and compare against the documented statement that retrieval is not authorization. Using it as an isolation basis fails the comparison.

## How to verify the setup

1. Enter the hypothetical source text and the draft sentence. Compare the draft sentence's "has taken effect" against whether the source records an effective status. The source does not record one, so the result is unsupported, not a negation and not a conflict.
2. Enter the hypothetical AIPROXY_API_ENDPOINT value. Compare whether it has an appended /v1 or /chat/completions. An appended path fails the documented requirement and counts as a configuration error.
3. Enter the hypothetical AIPROXY_API_TOKEN value. Compare whether it is empty and whether it matches the server-side configuration. An empty value or an application-key source fails; a matching non-empty value satisfies this configuration condition.

All three steps are paper comparisons. No deployment, startup, or live test is claimed. Where the source document does not record a field, the gap remains a gap and is logged as pending verification.
