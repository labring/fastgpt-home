# Tmall flagship operations: model connections for product questions

## What the documents look like

Product information and selection questions for a Tmall flagship store are checked against four working materials: the product publishing page, the brand authorization letter, the shipping commitment record, and after-sales tickets. These materials update daily and per order. The most time-consuming daily steps are category qualification checks, maintaining the 48-hour shipping commitment, and handling delayed-shipment compensation.

For model connection and configuration, these materials carry explicit authorization boundaries. The brand authorization letter limits the range of sellable goods. The shipping commitment record limits the fulfillment deadline. After-sales tickets limit the handling status. A model can only organize answers within facts already stated in these materials. A retrieved passage does not constitute sales authorization or a compensation confirmation. The update frequency of the materials does not change the connection configuration, and this page does not derive batch synchronization or transaction-triggered mechanisms from it.

## Constraints at the model connections step

Model connection depends on AI Proxy. The App and Admin sides must set AIPROXY_API_ENDPOINT and a non-empty AIPROXY_API_TOKEN. The endpoint takes the service root address and does not append /v1. The system requires at least one language model and one index model to work normally.

A model ID is the value of the model field in the request body and is globally unique. A model name is for display and can be customized. Channel testing, model testing, and model status probing correspond to channel connectivity, single-model availability, and periodic health checks. These three do not replace one another. Model status probing covers only currently enabled system models. After a first failure, the system retries at most 3 times, so a single round makes at most 4 attempts, and only when all 4 attempts fail is the model finally judged abnormal.

Retrieval finds text chunks relevant to a question. A relevance score does not carry the responsibility of filtering by subject, category, or authorization. Libraries built on different vector models cannot be associated together. During checking, compare the model identifier first, exclude libraries whose identifiers do not match, then record what is actually observed.

## Configuration and implementation checks

The following is a hypothetical drill sample used to explain how configuration checking works. It does not represent any real store or any real test.

Hypothetical source text: A Tmall flagship store product publishing page states, "This store is the flagship store of Brand A; goods on sale are subject to the SKUs on the page." The brand authorization letter states, "Authorization period 1 January 2026 to 31 December 2026; authorized scope limited to Brand A household appliance category." The shipping commitment record states, "Ship within 48 hours after payment." Draft sentence to be judged: "All Brand A goods in this store can be ordered before 31 December 2026 with a guaranteed 48-hour shipment."

| Configuration item | Hypothetical starting value for this drill | Reason for the choice and comparison object |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | Hypothetically set to `http://aiproxy:3000` | The document requires the root address; compare with a form that appends /v1 |
| AIPROXY_API_TOKEN | Hypothetically set to a non-empty admin token | The document requires a non-empty token consistent with the server; compare with an application API key |
| Language model | Hypothetically enable one language model | Meets the system minimum; compare with a not-enabled state |
| Index model | Hypothetically enable one index model | Meets the system minimum; compare with a not-enabled state |
| Model status probe interval | Hypothetically set to 15 minutes | The document allows integers from 5 to 60 minutes; compare with an out-of-range value |
| Model test | Hypothetically run a model test on the channel | Checks channel connectivity; compare with a state where no test was run |

## Three common errors

1. Treating a retrieved product passage as sales authorization. The input is the draft sentence and the retrieval result. The comparison object is the category and period stated in the brand authorization letter. The observable result is whether the draft sentence exceeds the authorized scope.
2. Treating a passed model test as completed business authorization. The input is the channel test result. The comparison object is the product publishing page and the authorization letter. The observable result is whether the passed test is used to support a sellable conclusion.
3. Treating an after-sales ticket pending review as already handled. The input is the ticket status field. The comparison object is whether the ticket states that handling is complete. The observable result is whether the draft sentence writes a ticket without a stated completion status as completed.

## How to verify the setup

1. Input the three source sentences and the draft sentence from the hypothetical sample. Compare "all goods" in the draft sentence with "limited to Brand A household appliance category" in the authorization letter. Observe whether the draft sentence narrows to the authorized category and period. If it does not narrow, the condition is not met.
2. Input "Ship within 48 hours after payment" from the hypothetical shipping commitment record. Compare it with "guaranteed 48-hour shipment" in the draft sentence. Observe whether the two are the same commitment wording. If the draft sentence adds a guarantee tone not stated in the record, the condition is not met.
3. Input the after-sales ticket status from the hypothetical sample. Compare whether the ticket states that handling is complete. Observe whether the draft sentence writes a ticket without a stated completion status as completed. If the status is not stated, record it as pending verification. An empty retrieval result can be checked against a downstream design using the explicit paper input `[]`; this does not mean a fictional rule retrieval must return empty.

This page addresses only Tmall flagship daily operations, product information and selection questions, and model connection and configuration. During operations handover, materials, actions, and requests have specific authorization states. Retrieval and forms are not authorization execution.
