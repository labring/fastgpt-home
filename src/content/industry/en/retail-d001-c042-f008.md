# Product listing reviews: workflow routing for product questions

## What the documents look like

Platform product title and detail compliance deals with advertising truthfulness and qualification display. It does not handle parcel delivery. E-commerce product operations staff, legal compliance staff, and artwork reviewers share four source types: the platform rule center, advertising law compliance lists, the brand asset library, and quality inspection agency reports. Daily documents include product title tables, detail page assets, advertising prohibited-word lists, and quality inspection reports. Updates are triggered weekly and at each new product launch. That rhythm affects the checking schedule and does not change how the nodes themselves execute. Extreme words, physical parameter claims, and non-compliant assets appearing in these documents form the concrete inputs that workflow routing must carry.

The task on this page is product material and selection Q&A. The feature is workflow routing. A Form Input node enters an interaction state when triggered, collects required information, and after submission passes that information to subsequent nodes. A User Selection node evaluates the user's choice and executes the corresponding "yes" branch. Both nodes record workflow state and wait for the user to complete the interaction before continuing. Retrieval or form collection of materials does not constitute authorization to publish, delist, or replace assets. Order writing, document backfill, and external status synchronization require separate business interfaces or downstream processes. Output handoff must pass collected information explicitly to subsequent retrieval, judgment, or interface nodes, and compare output against input item by item.

## Constraints at the workflow routing step

A hypothetical paper exercise sample follows. A draft sentence in a product title table reads: "This product has passed national-level quality inspection and is permanently valid." In the same batch of materials, the quality inspection report states that the tested object is a Type A sample and the report date is March 2024. The valid scope is not stated in the title table. The advertising prohibited-word list includes "national-level" and "permanent." A handoff request reads: "Please confirm whether this title sentence can go live directly." That request is in a pending-review state and does not indicate approval has been granted.

The Form Input node collects the draft sentence and quality inspection report fields, and after submission passes them to subsequent nodes. The User Selection node executes the "yes" branch after a choice is made. Neither node performs business verification, approval, database writes, or external synchronization. The interaction state is a documented behavior of these interaction nodes; the documents do not describe a separate global state-recording switch. The interaction state and the hiding of the dialog box are documented node behaviors, and no submission count, automatic judgment, or snapshot guarantee is documented.

A relevance score is not a category, entity, or permission filter. Retrieval is not authorization. A similarity setting does not exclude unrelated businesses or unauthorized records. The same-model retrieval association requirement applies to libraries using the same vector model; it does not extend to external systems such as business registration websites. Cross-model libraries cannot be jointly associated. When checking cross-model cases, verify identifiers and exclude non-matching libraries; do not run cross-model retrieval to compare missed recall. An empty-reference output can be checked against a downstream design using an explicit paper input of an empty array; this does not claim that a fictional rule retrieval necessarily returns an empty array. The total flow diagram lists optional paths that do not all execute on every request: image retrieval requires a corresponding image input and model capability, and reranking requires a model and must be enabled according to settings. RRF is a hybrid result fusion process and is not written as an on/off switch. Thinking budget is a thinking budget and must not be repurposed as a reference token limit.

## Configuration and implementation checks

| Configuration item | Type | How it is checked against the sample |
| --- | --- | --- |
| Form Input node | Official node | Collects the draft sentence and quality inspection report fields; passes them to subsequent nodes after submission |
| User Selection node | Official node | Executes the "yes" branch after a "go live / return" choice is made |
| Output handoff | Implementation check | Compares whether collected fields match the inputs of subsequent retrieval or judgment nodes |
| Retrieval scope | Implementation check | Confirms the advertising prohibited-word list and quality inspection report are within the accessible scope |
| External operation division | Implementation check | Title replacement and asset backfill require separate business interfaces and are not completed inside the nodes |
| Interaction state check | Implementation check | Records that state is a behavior of the interaction nodes; no separate global switch is set |

The hypothetical starting point for this exercise is two options, "go live" and "return." The reason is that this sample requires only a binary judgment, compared against the pending-review state of the draft sentence. This starting point is a paper setting and is not an official default value.

## Three common errors

1. Treating a retrieval hit as authorization. The advertising prohibited-word list containing "national-level" only shows the word is on the list. It does not show the title sentence has been approved to go live. Authorization status must be checked separately.
2. Treating a pending review as approved. The handoff request saying "please confirm" is a pending-review state and does not constitute permission to go live.
3. Treating node collection as external execution. After the Form Input node collects fields, title replacement and asset backfill still require separate business interfaces. The nodes themselves do not complete these actions.

## How to verify the setup

1. Input the hypothetical sample draft sentence and quality inspection report fields, compare "national-level" and "permanent" against the advertising prohibited-word list entries, and observe whether the list contains those two words. Inclusion only shows the words are on the list; it does not show the title sentence can go live.
2. Input the handoff request "Please confirm whether this title sentence can go live directly," compare the request wording against the authorization state, and observe whether the request states an approving party and an approval conclusion. When these are not stated, record the item as pending verification.
3. Input the quality inspection report fields, compare the report date and tested object against the title sentence wording, and observe whether the title sentence exceeds the object and period stated in the report. The portion that exceeds is recorded as unsupported.

Missing evidence remains missing. A pending request is not approval. An offered option is not execution. An unsigned termination is not a completed termination. Where a document field is not provided, it is unknown, and the corresponding check records a gap rather than a conclusion.
