# Product listing reviews: model connections for product questions

## What the documents look like

Platform product title and detail compliance handles advertising truthfulness and qualification display. It does not handle parcel delivery. The main data sources are the platform rule center, advertising-law compliance checklists, brand asset libraries, and quality-inspection agency reports. Daily documents include the product title table, detail-page assets, the prohibited-words checklist, and quality-inspection reports. Update frequency is weekly and on each new listing.

In this task, product data and selection question answering connects the title table, assets, prohibited-words checklist, and inspection reports as knowledge sources. A model answers operator questions about whether a given wording is usable, based on retrieval results. Model connection and configuration determine whether these documents can be indexed, retrieved, and cited correctly.

## Constraints at the model connections step

From V4.17.0, AI Proxy is a required dependency. The App and any Admin service that reuses App/Service configuration must set `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN`. Missing either item causes startup validation to fail. `AIPROXY_API_ENDPOINT` holds the AI Proxy service root address and does not append `/v1`. `AIPROXY_API_TOKEN` is an administrator token and cannot be replaced by an application API key.

The system needs at least one language model and one index model to work normally. The index model builds indexes over text chunks for relevant text retrieval. The language model handles conversational answers. Model capabilities are checked against the input the application requires; multimodal input, tool calling, and thinking configuration are verified separately. Application parameters are set in the application or node configuration. Same-named fields on a compatible chat interface are not assumed to override orchestration.

Hypothetical drill sample: an internal drill uses a fictional fragment of a product title table. The source text reads: "Product code A-001, proposed title uses 'lowest price on the entire web'; the detail-page asset cites inspection report Q-2026-001; the prohibited-words checklist version is V3." A separate proposed sentence awaits judgment: "The A-001 title may use 'lowest price on the entire web' because inspection report Q-2026-001 has confirmed the price advantage." This proposed sentence links the inspection report to a price claim. Checking requires whether checklist V3 includes "lowest price" and whether inspection report Q-2026-001 covers a price conclusion.

## Three common errors

1. Writing `AIPROXY_API_ENDPOINT` as a full request address that includes `/v1` or `/chat/completions`. The check compares the input variable value against the document requirement; an appended path fails the condition.
2. Filling `AIPROXY_API_TOKEN` with an application API key. The check compares the input variable value against the "administrator token" field description; an application-key characteristic fails the condition.
3. Enabling only a language model without an index model. The check compares the input enabled-model list against the requirement of at least one language model and one index model; a missing index model fails the condition.

## How to verify the setup

1. Input the hypothetical sample source text and the proposed sentence, then compare whether retrieval results cite the corresponding fields of checklist V3 and inspection report Q-2026-001. If retrieval does not return the "lowest price" entry from the checklist, or does not return the coverage statement of the inspection report, record an evidence gap and do not judge the proposed sentence usable.
2. Input the `AIPROXY_API_ENDPOINT` variable value and compare against the document example. If the value ends with `/v1`, the root-address requirement is not met; if it is a plain root address, this check passes.
3. Input the enabled-model list and compare against the requirement of at least one language model and one index model. If both categories exist, the check passes; if either category is missing, record it as unmet.

Retrieval and relevance scores do not carry permission or entity isolation. A same-vector-model requirement for a retrieval library does not extend to external systems. An empty result is checked against a paper input of `[]` for downstream design; no claim is made that a fictional rule search necessarily returns empty. For libraries across different vector models, first check the identifier and exclude non-matching ones; do not run cross-model retrieval to compare missed recall. A pending review does not demonstrate a lack of operational permission, and a quotation validity period does not indicate a supply period.
