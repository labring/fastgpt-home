# Multi-store management: model connections for product questions

## What the documents look like

Multi-store matrix management draws on several document families: platform merchant back ends, ERP channel pricing, brand anti-counterfeit systems, and dealer reports. Compared with single-store advertising, this category places more weight on cross-store authorization relationships and price order. A store authorization list records which stores hold brand authorization. A price control table records price bands per channel. A diversion complaint form records sales leads for unauthorized stores. A monthly sales report summarizes shipments per store.

These materials serve as input documents for model connections in product information and selection questions. Authorization status, price bands, and complaint handling progress come from separate documents, and when field definitions differ they cannot be compared directly. Data updates at daily and monthly cadences; this page does not derive batch synchronization or real-time trigger mechanisms from that cadence.

## Constraints at the model connections step

Model connections depend on AI Proxy. Both the App and Admin services must set `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN`; missing either item causes startup validation to fail. `AIPROXY_API_ENDPOINT` takes the AI Proxy service root address without a `/v1` suffix. Legacy OpenAI environment variables do not substitute for these two settings.

Model capabilities must be checked against the inputs each application requires. Multimodal support, tool choice, and thinking configuration are separate fields, and a same-named field on a chat interface cannot be assumed to override orchestration parameters. Retrieval and relevance scoring do not carry permission or entity isolation duties. Store authorization judgments must rest on the authorization list text, and similarity results do not stand in for that text.

Hypothetical paper exercise sample: a brand e-commerce team holds two documents. Document one is a store authorization list reading "Authorized store: East China Flagship Store, authorization valid until 31 December 2026, authorized product category: home appliances." Document two is a price control table reading "East China Flagship Store, home appliance category, minimum retail price 199, price control effective period 1 January 2026 to 30 June 2026." A draft sentence awaiting judgment reads "East China Flagship Store selling home appliances in August 2026 meets authorization and price control requirements." Checking compares the authorization validity date, the price control effective period, and the date stated in the draft sentence.

## Three common errors

1. Entering a full model request address with `/v1` appended into `AIPROXY_API_ENDPOINT`. The documentation requires the service root address, and an appended path produces incorrect request address assembly. The check compares the entered value against the documented example format and observes whether `/v1` or `/chat/completions` appears.

2. Using the application API key in place of `AIPROXY_API_TOKEN`. The documentation states the administrator token must match the server configuration and cannot be empty. The check compares the two token values and observes whether they match and whether either is empty.

3. Treating a retrieval relevance score as the basis for store authorization judgment. A relevance score reflects text similarity and does not carry permission or entity isolation duties. The check compares the store name and validity date in the authorization list text and observes whether the store named in the draft sentence falls within the authorized scope and whether the date falls inside the validity period.

## How to verify the setup

1. Input the store authorization list text and the draft sentence from the hypothetical sample. Compare the date "August 2026" stated in the draft sentence against the authorization validity "until 31 December 2026." If the date falls within the validity period, the authorization dimension meets the condition. If it exceeds the validity period, the authorization dimension is not supported.

2. Input the price control table text and the draft sentence from the hypothetical sample. Compare the date "August 2026" stated in the draft sentence against the price control effective period "1 January 2026 to 30 June 2026." If the date falls within the effective period, the price control dimension meets the condition. If it exceeds the period, the price control dimension is not supported.

3. Input a handover request awaiting verification reading "Please confirm whether East China Flagship Store's August 2026 home appliance sales passed authorization and price control review." Compare whether the request carries the authorization list and price control table text and whether it states the source of the review conclusion. If the request contains only the store name and date without the source text, the request remains in a pending-verification state and cannot be treated as having passed review.
