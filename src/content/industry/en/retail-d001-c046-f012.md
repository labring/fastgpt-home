# Marketplace category access: document chunking for product questions

## What the documents look like

Marketplace category qualification and access work happens before a listing is published or a merchant is onboarded. The central materials are the operating entity's credentials and the chain of authorization behind the brand. The documents handled day to day are the business license, the trademark registration certificate, the brand authorization chain, and the industry license. These materials come from platform merchant-recruitment pages, the national enterprise credit information publicity system, trademark office data, and license systems. They are collected again at each onboarding event, and the update cadence is irregular.

The cost of getting this wrong is concrete: the onboarding application is rejected, the category cannot be published, or the deposit is tied up. Because of that, the quality of document parsing and chunking directly shapes whether a later retrieval can locate the correct qualification clause.

## Constraints at the document chunking step

Qualification documents differ sharply in structure. A business license carries a unified social credit code and a business scope. A trademark registration certificate carries a registration number and the approved goods and services classes. A brand authorization chain carries the authorizing party, the authorized party, the authorization period, and the authorization scope. An industry license carries permitted items and a validity period. Chunking needs to preserve the complete relationship between these fields and the content they constrain, so that an authorization period and an authorization scope are not split into separate passages.

Hypothetical drill sample: a brand authorization chain document reads, "Authorizing party A, authorized party B, authorization period from January 1, 2024 to December 31, 2025. The authorization scope is limited to Class 25 apparel goods. This authorization may not be sublicensed without the authorizing party's written consent." The draft sentence to be assessed is, "B may sublicense to C for Class 25 apparel goods." The check compares the source phrase "may not be sublicensed" with the draft phrase "may sublicense," which give mutually exclusive values for the same field within the same authorization scope and the same period.

## Configuration and implementation checks

| Configuration item | Setting or check relevant to this page | Relationship to the sample |
| --- | --- | --- |
| Segmentation method | Segment by the field structure of the qualification document, keeping authorizing party, authorized party, period, and scope in the same passage | The sample's period and scope must stay together |
| Index count | One data group can map to multiple indexes; the indexes field records an array of vector IDs | The sample can build a separate index for the authorization scope |
| Reference cap | Each search references at most n tokens of content | This hypothetical trial start is set to 2000 tokens, because the sample authorization chain runs about 1500 characters and needs headroom; compare against 1000 tokens to observe truncation |
| Minimum relevance | A 0-1 value, effective only under semantic retrieval or result reranking | This hypothetical trial start is set to 0.3; compare against 0.5 to observe recall changes |
| Search mode | Semantic retrieval, full-text retrieval, or hybrid retrieval, with hybrid merged through RRF | "Class 25" in the sample is an identifier-type query, suited to full-text or hybrid retrieval |
| Question optimization | Coreference resolution and question expansion before retrieval | If the sample question contains "this authorization," enabling it completes the subject |

## Three common errors

1. Splitting the authorization period and the authorization scope into different chunks, so retrieval recalls only the period passage and misses the scope passage, leaving the draft-sentence check without complete constraints. Check: input the sample source text, compare whether the parsed chunks contain all four items — authorizing party, authorized party, period, scope — and observe whether the four appear in the same data group.
2. Treating a successful upload as an updated retrieval index, without checking the actual training and index state after a material changes. Check: input the changed authorization chain text, compare whether retrieval returns the new text, and observe whether the returned content matches the uploaded content.
3. Treating a retrieval result as grounds to execute an authorization, so the draft sentence "may sublicense" is accepted directly. Check: input the draft sentence and the source text, compare the values of the source phrase "may not be sublicensed" and the draft phrase "may sublicense" on the same field, and observe whether the two are mutually exclusive.

## How to verify the setup

1. Input the sample source text and the draft sentence, compare the source phrase "may not be sublicensed" with the draft phrase "may sublicense," and observe whether they are identified as mutually exclusive values within the same authorization scope and the same period. If the two constraints are not kept in the same passage after chunking, this comparison cannot be completed.
2. Input the "Class 25" identifier from the sample, use full-text retrieval and semantic retrieval separately, compare the candidate content returned under each mode, and observe whether full-text retrieval hits the chunk containing "Class 25." If the result is empty, record the empty result and check the downstream design, without inferring a cause.
3. Input an authorization chain text that does not state an authorization period, compare whether the retrieval result contains a period field, and observe whether the returned content lacks that field. When it is missing, record it as unsupported, without judging it as a negation or a conflict.

These checks cover the named primary task of document parsing and chunking for this category. Retrieval and relevance scores do not perform permission or entity isolation, and a shared vector-model requirement for one library does not extend to external systems such as the enterprise credit publicity system. Any system error or automatic business action not described in the source documents is not asserted here.
