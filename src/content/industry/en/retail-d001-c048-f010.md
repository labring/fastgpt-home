# Parcel labels and handoffs: citation tracing for product questions

## What the documents look like

Parcel labels and handoff records sit at the point where a package leaves the warehouse, and the responsibility boundary is formed by the carrier's scanning action. This page concerns electronic waybills, handoff manifests, pickup scan records and exception-item registrations, refreshed per batch and per day. In product-material and selection Q&A these materials act as cited sources, and answers need to point back to specific document text.

The materials carry version differences. A single batch of electronic waybills may produce multiple copies through print retries, and the timestamps on a handoff manifest and a pickup scan record do not necessarily align. Citation tracing requires an answer to identify the material, field and effective scope it relies on, and it does not treat a retrieval hit as a determination of responsibility.

## Constraints at the citation tracing step

The knowledge base search node can associate one or more knowledge bases that share the same vector model, and it outputs cited content as an array whose length may be zero. When the array is empty, the output path still runs through. The citation cap is controlled in tokens, and the minimum relevance value takes effect only in semantic retrieval or result reranking. These parameters shape the recall range and the trimming, and they do not constitute an authorization judgment about a carrier, a branch or a document.

Hypothetical drill sample. The source materials to be checked consist of three sentences. Sentence one: "This shipment's electronic waybill number is SF-TEST-0001, printed at 2025-03-10 09:12, shipping warehouse is East China Warehouse No. 1." Sentence two: "Handoff manifest HC-2025-0310-A records that this shipment was delivered to the carrier branch at 2025-03-10 17:40; the handoff signature field is empty." Sentence three: "The pickup scan record shows SF-TEST-0001 was scanned by the carrier at 2025-03-10 19:05, with status picked up." The draft sentence to be assessed is: "The parcel completed handoff on 2025-03-10 and entered the carrier network." The assessment compares the same subject, the same period and the same field: the handoff signature field is empty, so the signature status is unsupported; the pickup scan record supports only the carrier's scanning action, and it does not support completion of the handoff signature.

## Configuration and implementation checks

Configuration here centers on citation checking for this page's sample, and it lists only documented settings or implementation check items.

| Configuration item | Value or check method on this page | Relation to the sample |
| --- | --- | --- |
| Associated knowledge bases | Check the selected knowledge bases and material versions, and confirm the vector model identifier matches | Waybill, handoff manifest and scan record can be associated together only under the same vector model |
| Search mode | Semantic retrieval or hybrid retrieval, chosen for the sample question | Number-type queries may use full-text retrieval |
| Citation cap | For this hypothetical trial the starting value is 3000 tokens, because the three sample sentences are short in total; compare with 1500 tokens to observe trimming differences | Controls the total tokens of returned cited content |
| Minimum relevance | For this hypothetical trial the starting value is 0.3; compare with 0.5 to observe remaining items after filtering | Takes effect only in semantic retrieval or result reranking |
| Result reranking | Enabled or not according to whether a ReRank model is available | Rerank scores can be used for filtering and do not replace checking of the signature status |
| Cited content output handoff | Check whether the retrieval output array is passed to the answering step, and compare each answer item against the source text | Downstream design needs to handle an empty array |

## Three common errors

1. Treating the pickup scan record as evidence that the handoff manifest was signed. The input is the three source sentences above and the draft sentence; the comparison is between the handoff signature field status and the scan record field; the observable result is that the signature field is empty while the draft sentence says "completed handoff," which are different fields, so the draft sentence is unsupported.
2. Treating minimum relevance as an entity or permission filter. The input is the three sample sentences and one unrelated query; the comparison is between the relevance value and the material subject field; the observable result is that relevance affects only ordering and filtering, and it does not exclude other subjects or unauthorized records.
3. Treating an empty citation array as a workflow error. The input is the paper input `[]`; the comparison is between the node output and the downstream handoff design; the observable result is that the output path runs through, and the downstream handling of the empty array needs to be checked rather than asserted as a guaranteed system error.

## How to verify the setup

1. Input the three source sentences and the draft sentence, compare the draft phrase "completed handoff" against the handoff signature field status, and observe whether a record with an empty signature field appears. The condition is met when the draft sentence is marked as pending verification; it is not met when the draft is accepted directly.
2. Input the three sample sentences and one unrelated query, compare the minimum relevance setting against the returned items, and observe whether unrelated items are filtered out. The condition is met when the filtering behavior matches the setting; it is not met when relevance is used as a permission filter.
3. Input the paper value `[]` and the downstream handoff design, compare the node output against downstream handling, and observe whether the empty array is handled. The condition is met when downstream has an explicit handling path; it is not met when the empty array is treated as an error or ignored.

Knowledge bases with different vector models cannot be associated together; the identifier must be checked first and non-matching ones excluded. Retrieval and forms do not constitute authorization execution, and signing, reaching cooperation and contract effectiveness are separate facts. Fields not stated remain unknown, and pending review does not demonstrate a lack of operating permission.
