# Douyin storefront operations: workflow routing for product questions

## What the documents look like

Douyin storefront shelf operations centre on product cards and the store experience score. This differs from live-room operations, which depend on the rhythm of a single broadcast session. The daily materials for this category include product qualification pages, experience score breakdowns, shipping violation appeals, and store announcements. Update frequency is daily or per order, as stated in the brief.

These materials set the input boundary for product information and selection Q&A. A qualification page states the conditions under which a product may be sold. An experience score breakdown reflects service performance. Appeals and announcements record changes in status. The workflow routing step does not read these documents by itself; it collects values from the user and passes them to later nodes. The distinction matters because a collected value is not a verified business fact.

## Constraints at the workflow routing step

The Form Input node and the User Selection node are both user interaction nodes. When triggered, the conversation enters an interaction state and the workflow state is recorded. Execution continues downward after the user completes the interaction. The Form Input node collects required information and passes it to subsequent nodes. The User Selection node evaluates the user's choice and executes the corresponding "yes" branch.

Collected information must be passed explicitly to later retrieval, judgement, or interface nodes. Order writing, document backfill, and external status synchronisation require a separate business interface or a later process. Retrieval and forms do not constitute authorisation to execute. A pending request is not an approval, and an offered option is not an execution.

Hypothetical paper exercise sample: A Douyin store merchant's product qualification page states in its original text: "Entity is a certain apparel business, object is a summer short-sleeve T-shirt, status is qualification submitted and pending review, validity scope is 1 May 2025 to 30 September 2025." A separate experience score breakdown records "same entity, same product, field is experience score, value is 4.6." The draft sentence to be assessed is: "The product qualification has passed review and the product may be listed and sold normally." This sentence concerns review status and listing authorisation. The original text shows only pending review and does not state a passed conclusion.

| User Selection node | Execute the "yes" branch according to the user's choice | Verify branch connections against selection results one by one |

| Output handover check | Pass collected information to retrieval or judgement nodes | Compare output against input item by item |

## Three common errors

1. Treating a pending review status as a passed review. The input is the qualification page text "qualification submitted and pending review." The comparison object is the draft sentence "has passed review." The two status field values are mutually exclusive, so the draft sentence is judged unsupported.

2. Treating the User Selection node's "yes" branch as automatic authorisation. The input is the node branch connection. The comparison object is the order writing action. The node only executes a branch; writing requires a separate interface.

3. Treating retrieval results as permission isolation. The input is the returned retrieval records. The comparison object is the authorisation scope. Retrieval does not perform entity or permission filtering. Identifiers must be checked and non-matching records excluded.

## How to verify the setup

1. Input the hypothetical sample qualification page text and the draft sentence. Compare the review status field values. If the original text shows only pending review and the draft sentence shows passed, the draft sentence is judged unsupported and the evidence gap is recorded.

2. Input the User Selection node branch settings. Compare the selection result with execution of the "yes" branch. If selection only enters the branch without triggering order writing, confirm that the external action is not performed by the node.

3. Input the returned retrieval records and the authorisation scope identifiers. Compare whether entity, object, and period match. If the record entity or object does not match, exclude that record and record the actual observation without inferring a runtime result.

A relevance score is not a category, entity, or permission filter. Similarity settings do not exclude unrelated businesses or unauthorised records. Retrieval is not authorisation. Forms collect values; business verification, approval, database writes, and external synchronisation require their stated downstream implementation. Without a documented error code or actual observation, describe what to compare and what remains unknown. Do not assume scheduled triggers or hidden controls.
