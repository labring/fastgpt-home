# Pinduoduo seller campaigns: workflow routing for product questions

## What the documents look like

Pinduoduo low-price campaign store operations revolve around low-price resource slots, campaign inventory, and refund-rate fluctuations. Compared with Tmall flagship store operations, the emphasis falls on campaign-price gross margin and inventory capacity to fulfill campaign commitments. The documents handled day to day include campaign registration forms, product cost calculation sheets, after-sales refund slips, and platform site messages. These materials update daily or per campaign. They define the input boundary for product-information and selection questions: the cost calculation sheet supplies the campaign price and cost basis, the registration form supplies campaign inventory and resource slot, the after-sales refund slip reflects abnormal fluctuation, and site messages carry platform notices.

For this page the relevant task is product-information and selection question answering, and the relevant feature is workflow routing. The routing step decides which collected fields move to which downstream node. The materials above determine what the routing step can legitimately pass forward and what it cannot.

## Constraints at the workflow routing step

The form input node is a user-interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and after the user completes required fields and submits, the node collects the submitted form information and passes it to subsequent nodes. The user selection node is also a user-interaction node. When it triggers, the conversation enters an interaction state and the workflow state is recorded. When the user makes a choice, the node evaluates that choice and executes the corresponding "yes" branch. Both node types can be added repeatedly and trigger execution. Routing must carry the fields needed for product-information question answering through these nodes one by one. The interaction state arises from node behavior; no separate global state-recording switch is documented. Collected information must be explicitly passed to subsequent retrieval, judgment, or interface nodes. Order writes, document backfill, and external status synchronization require a separate business interface or subsequent process. Retrieval fetches material; it does not constitute authorization.

Hypothetical paper exercise sample: the source material reads, "The campaign registration form states: the entity is a certain Pinduoduo store, the object is product A, the campaign period is March 1 to March 3, campaign inventory is 500 units, and the campaign price is 19.9 yuan per unit; the product cost calculation sheet states the cost of the same product is 18.5 yuan per unit; the after-sales refund slip shows 12 refunds for this product occurred on March 2." The draft sentence to be judged is: "This store's product A executes at 19.9 yuan per unit during the March 1 to March 3 campaign period, with inventory of 500 units." The check points are same entity, same period, same field.

## Configuration and implementation checks

| Configuration item | Documented basis or implementation check | Relation to this page's sample |
| --- | --- | --- |
| Form input node | Triggers into interaction state, collects required information, passes it to subsequent nodes after submission | Carries required fields such as campaign price and campaign inventory |
| User selection node | Executes the corresponding "yes" branch after the user makes a choice | Used for the selection branch between campaign product and regular product |
| Output carry-through check | Explicitly pass collected information to subsequent retrieval, judgment, or interface nodes | Compare registration form fields against question-answering output |
| Interaction state check | Recording state is behavior of the interaction node | Check whether execution continues downward after submission |
| External operation division | Order writes, document backfill, and external status synchronization require a separate business interface or subsequent process | Refund slip backfill is not treated as completed by the node |
| Hypothetical trial starting point | This paper check uses the 19.9 yuan and 500 units stated in the registration form as the starting point | Compared against the 18.5 yuan cost calculation sheet for gross margin basis |

## Three common errors

1. Treating the campaign price field collected by the form input node as authorization to execute that campaign price. The node completes information collection and transfer only.
2. Treating the "yes" branch of the user selection node as a confirmed selection conclusion. Branch execution and business confirmation are different facts.
3. Treating the refund count on the after-sales refund slip as the result of campaign inventory deduction. The refund slip and inventory write require a separate business interface.

## How to verify the setup

1. Input the hypothetical sample source text above and the draft sentence, then compare whether entity, object, period, campaign price, and inventory fields agree. When the draft sentence and the registration form hold the same value for the same field, the condition is met. When a field is not stated, record it as pending verification.
2. Input a paper material containing only a site message notice with no campaign price and no inventory, then compare whether the output preserves the gap. When the output does not fabricate a campaign price or inventory, the condition is met.
3. Input an explicit paper empty result `[]`, then check whether the downstream design carries it as an empty result. When the downstream does not generate a product-information conclusion from the empty result, the condition is met; the actual returned content remains unknown.
