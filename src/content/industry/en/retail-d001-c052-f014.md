# Pinduoduo seller campaigns: model connections for product questions

## What the documents look like

Low-price campaign operations on Pinduoduo revolve around discounted resource slots, campaign inventory, and swings in the refund rate. The working material comes from the merchant backend, campaign resource-slot data, ERP inventory, and logistics sign-off records. The documents that matter for product information and selection Q&A are the campaign registration form, the product cost calculation sheet, the after-sales refund form, and platform in-site messages. The registration form carries the campaign price and the registration status; the cost sheet carries cost and gross-margin definitions; the refund form carries after-sales fluctuation. The brief gives a daily and per-campaign update rhythm. This page does not derive any batch synchronization, full synchronization, or transaction-triggered mechanism from that rhythm.

## Constraints at the model connections step

From V4.17.0, AI Proxy is a required dependency. Both the App and the Admin service that reuses App/Service configuration must set `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN`. A missing item causes startup validation to fail. Legacy OpenAI environment variables and single-model custom request addresses cannot replace these two settings. The system needs at least one language model and one index model to work. The model ID is the value of the `model` field in the request body and is globally unique. Model mapping translates the model FastGPT requests into the actual upstream model. Channel priority runs from 1 to 100, and a larger value is selected more easily. Model status probing covers only enabled system models; after a first failure the system retries automatically up to 3 times, so one round makes at most 4 attempts, and only when all 4 attempts fail is the model judged abnormal.

Hypothetical drill sample: a Pinduoduo campaign store operator submits a model-connection check request for product information and selection Q&A. The material supplied for checking reads: "The campaign registration form (March 2026 session) states that product A registers a campaign price of 19.9 yuan and the registration status is submitted and awaiting platform review. The product cost calculation sheet states that product A has a unit cost of 16.5 yuan, and the gross-margin definition includes platform commission and logistics fees. The after-sales refund form (1 March 2026 to 7 March 2026) records 2 refunds for product A, both for size mismatch." The draft sentence to be judged reads: "Product A passed review for the March 2026 session and can be listed for sale at 19.9 yuan." That sentence concerns review status and listing authorization, while the material shows only "submitted and awaiting platform review."

## Three common errors

1. Treating "submitted and awaiting platform review" as passed review. The input is the material wording "registration status is submitted and awaiting platform review," and the comparison object is the draft sentence "passed review." The observable result: the material does not state that review passed, the draft sentence is unsupported and remains to be verified.
2. Using an application API key in place of `AIPROXY_API_TOKEN`. The input is the document requirement of a "non-empty administrator token that must be consistent with the server configuration." The comparison object is an application API key. The observable result: the two serve different purposes, and the substitution does not meet the documented condition.
3. Reading the model status probe retry count as retries within a single request. The input is the document wording "after a first failure, retry automatically up to 3 times, at most 4 attempts per round." The comparison object is "3 retries in a single request." The observable result: the document describes total attempts in one probe round, and the two scopes differ.

## How to verify the setup

1. For the draft sentence "Product A passed review for the March 2026 session and can be listed for sale at 19.9 yuan," the input is the material wording "submitted and awaiting platform review." Compare the same subject, the same session, and the same registration-status field. The condition is met when the material explicitly states that review passed; the current material does not state it, so the finding is unsupported and remains to be verified.
2. For the model-connection check request, the input is the two settings `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN`. Compare against the documented requirements of a root address without `/v1` and a non-empty, consistent token. The condition is met when both are filled in as documented; when either is missing, startup validation fails.
3. For product-information retrieval, the input is the text of the campaign registration form, the cost calculation sheet, and the refund form. Compare whether the returned content matches the query subject, session, and field. The condition is met when the returned content shares the same subject and the same period as the input material; on an empty result, record the gap and do not treat it as a negative. Retrieval is an observation action and does not constitute authorization or approval.
