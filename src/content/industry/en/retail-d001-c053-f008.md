# Channel receivables: workflow routing for product questions

## What the documents look like

Channel receivables collection happens after credit sales. The core concerns are credit limits and cash recovery, and the main records come from the finance system, bank receipts, distributor orders and sales contracts. Everyday documents include the receivables aging table, dunning letters, credit agreements and shipment freeze notices. These materials update weekly or monthly. In product information and selection questions, workflow routing has to align the fields of the aging table, dunning letter, credit agreement and freeze notice before it can answer whether a given receivable exceeds its credit limit or whether a given dunning letter has been sent.

The aging table carries the distributor name, the cutoff date and the amount over the credit limit. The credit agreement carries an agreement number. The freeze notice carries a status field that shows whether the notice has been issued. These three documents serve different purposes and are not interchangeable. A dunning letter records a collection request; it does not record a credit decision. A freeze notice records a shipment action; it does not record approval for that action.

## Constraints at the workflow routing step

The form input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. When the user fills in the required information and submits, the node collects the submitted form values and passes them to later nodes. The user selection node is also a user interaction node. When the user makes a selection, the node evaluates that selection and executes the corresponding branch.

The interaction state is behavior of the interaction nodes. The documents do not describe a separate global state-recording switch, so none is claimed here. Collected values must be passed explicitly to later retrieval, judgment or interface nodes. Order writes, document backfill and external status synchronization require a separate business interface or a later process. Retrieval does not perform authorization. A similarity setting does not exclude unrelated business records or unauthorized records.

Hypothetical paper exercise: a brand finance team checks distributor A's receivables aging table for February 2025. The table states "Distributor A, as of 28 February 2025, amount over the credit limit is CNY 120,000, credit agreement number XY-2025-017, shipment freeze notice not yet issued." A proposed sentence reads "Distributor A has exceeded the credit limit and shipment should be frozen immediately." That sentence covers only the over-limit fact. The freeze notice has not been issued, which is a pending action. Confirming it requires a manual check of the authorization boundary.

## Three common errors

1. Treating a retrieval hit as authorization. A retrieved aging table shows only the over-limit fact. It does not show that freeze authorization was granted. The input is the aging table text; the comparison is whether an authorization record is attached; the observable result is that when no authorization record exists, the freeze must not be judged executable.

2. Treating "shipment should be frozen immediately" in the proposed sentence as already executed. The input is the proposed sentence; the comparison is the freeze notice status field; the observable result is that when the status reads "not yet issued," the sentence can only be marked as pending verification.

3. Treating the branch taken on the user selection node as a completed approval. The input is the user selection record; the comparison is whether an approval signature exists; the observable result is that when only a branch selection exists and no signature exists, approval must not be judged complete.

## How to verify the setup

- Verification one: input the aging table text and the proposed sentence from the hypothetical sample. Compare whether the proposed sentence exceeds the source text. The condition is met when the proposed sentence covers only the over-limit fact and does not state that the freeze has been executed.

- Verification two: input the required fields on the form input node and the fields in the aging table. Compare whether distributor name, cutoff date and amount over the credit limit match item by item. The condition is met when all three items match character for character.

- Verification three: input the branch record from the user selection node and the freeze notice issuance record. Compare whether an interface call record exists. When no interface call record exists, record the external action as not executed and keep the gap open.

A paper input of an empty list can be used to check downstream design. This page does not claim that a retrieval over a fictional rule set returns an empty list. Libraries using different vector models cannot be associated together. Check identifiers first, exclude non-matching items, and record the actual observation.
