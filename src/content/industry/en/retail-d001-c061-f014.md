# Fresh-food weighing and sorting: model connections for product questions

## What the documents look like

Fresh-food weighing and sorting centers on weight and specification rather than on pre-sale order aggregation. The working materials come from WMS, electronic scales, the order system, and quality-check photographs. The documents handled day to day are picking task sheets, weighing labels, short-weight compensation forms, and quality-check records. Updates arrive per order and per day, so a product question has to line up specification, weighing basis, and document fields.

A picking task sheet carries the order and the required specification. A weighing label carries the measured weight. A short-weight compensation form and a quality-check record show how a deviation was handled. These materials together form the reference base for product-data and selection questions. Because the same physical item can appear as a specification on one sheet and as a measured value on a label, the answer has to name which document and which field it relies on.

## Constraints at the model connections step

Model access runs through AI Proxy. From V4.17.0, the App and any Admin service that reuses App/Service configuration must both set `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN`. Missing either one causes startup validation to fail. `AIPROXY_API_ENDPOINT` takes the service root address and does not carry `/v1`. A language model and an index model are both required before the system works normally.

Model capability has to be checked against the inputs the application actually needs. Multimodal input, tool choice, and thinking configuration are verified separately. Application parameters are set in the application or node configuration; the same-named fields of a compatible chat interface cannot be assumed to override orchestration. Retrieval and relevance scores do not carry permission or entity isolation, and the requirement that a retrieval library share one vector model does not extend to outside systems.

A pending compensation form is not a completed compensation. A configuration value written into a variable is not a passed connection test. These distinctions matter because the question task reads document states, while the connection task reads configuration states, and the two are checked against different evidence.

## Three common errors

1. Writing `AIPROXY_API_ENDPOINT` as a full request address that includes `/v1`. The check takes the variable value as input, compares whether it is only the service root address, and observes whether an extra path is present.

2. Treating a pending short-weight compensation form as a completed compensation. The check takes the material text above and the draft sentence as input, compares the status field value, and observes whether the draft sentence goes beyond what the text supports.

3. Using retrieval relevance in place of a permission decision. The check takes one retrieval request as input, compares the returned results against the access list, and observes whether records outside the permitted scope are included in the answer.

## How to verify the setup

1. Take the values of `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` as input, compare whether they are respectively a root address and a non-empty token, and observe whether startup validation passes. The document states that missing either one fails.

2. Take the hypothetical material text and the draft sentence above as input, compare the compensation form status field, and observe whether the draft sentence agrees with "pending review." A mismatch means the sentence is not supported.

3. Take one retrieval request as input, compare the returned results against the accessible scope list, and observe whether any record falls outside that scope. Retrieval itself does not perform authorization, so an out-of-scope judgment needs a separate system implementation.

Where the material does not state a field, the value remains unknown. Where a request is pending, it is not an approval. Where an option is offered, it is not an execution. The verification steps above describe what to compare and what would satisfy the condition; they do not record a completed test, deployment, or approval.
