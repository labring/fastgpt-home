# Group-buy leader operations: workflow routing for product questions

## What the documents look like

Group-buy leader operations revolve around community nodes and commission. The working materials come from the group-buy back office, leader community groups, order detail records and after-sales records. Routine documents include leader agreements, commission tables, pickup lists and community announcements, updated daily or per group. This page addresses only one task: workflow routing inside product information and selection questions. The routing uses interaction nodes to collect a leader's or operator's choices and required information, then passes the collected values to later nodes.

A leader agreement records the parties, the scope of cooperation and the validity period. A commission table records which orders count toward commission and for which period. A pickup list records the station, product and quantity. A community announcement addresses the community. Whether these materials carry complete fields determines whether values collected by a form input node can support later judgements. Fields the materials do not state remain unknown and cannot be filled in from practices used in another category.

## Constraints at the workflow routing step

When a form input node triggers, the conversation enters an interaction state and the workflow state is recorded. After the user fills in required information and submits, the node passes that information to later nodes. When a user selection node triggers, the conversation likewise enters an interaction state; when the user makes a selection, the node evaluates that selection and executes the "yes" branch. Both nodes are user interaction nodes, can be added repeatedly, and trigger execution.

The constraint is that interaction nodes only collect and branch. They do not complete business verification. Order writes, document backfill and external status synchronization require a separate business interface or a later flow. Retrieval results do not constitute authorization, and a similarity score does not perform subject, category or permission filtering. Libraries built on different vector models cannot be associated together; identifiers must first be checked and non-matching libraries excluded, and cross-model retrieval must not be run to compare missed recall. The knowledge-reference limit follows the unit documented in the official text, and empty-reference output and context limits keep their documented conditions.

Hypothetical paper exercise sample: the source text reads "Leader agreement: Party A is a platform operator, Party B is a community group-buy leader, cooperation period 1 January 2025 to 31 December 2025; Commission table: January 2025, this leader has 12 commissionable orders; Pickup list: 5 January 2025, one station, product A, 30 units." The draft sentence to be assessed is "This leader's January 2025 commission has been settled." That sentence concerns settlement status. The materials state only the number of commissionable orders and do not state any settlement action or settlement result.

## Three common errors

1. Treating form submission as completed authorization. In the sample, the leader submitting selection information only produces collected values. The materials do not state any approval or settlement authority, so treating submission as granted authorization is a mistaken finding.
2. Treating the draft sentence's settlement wording as an established fact. The materials contain only 12 commissionable orders and no settlement action. The sentence is assessed as unsupported; it cannot be assessed as a negation or a conflict.
3. Using a similarity score to exclude unrelated subjects. The score does not perform entity or permission filtering. In the sample, a high or low score cannot be used to conclude that a settlement relationship exists between this leader and the platform.

## How to verify the setup

1. Input the sample source text and the draft sentence "This leader's January 2025 commission has been settled." Compare whether the materials state a settlement action and result. The observed result is that the materials do not state them, so the sentence should be assessed as unsupported and the evidence gap recorded.
2. Input "12 commissionable orders in January 2025" from the sample. Compare the connection of the user selection node's "yes" branch and the input of later nodes. The observed result is that the branch executes according to the selection and the collected value passes item by item into later nodes; if either is missing, the condition is not met.
3. Input an explicit paper empty result `[]`. Compare how the downstream design handles an empty reference. The observed result is that downstream treats it as empty input and preserves the unknown; no claim is made that a particular rule's retrieval necessarily returns `[]`.
