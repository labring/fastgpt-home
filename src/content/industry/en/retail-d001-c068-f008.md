# Group-buy presale orders: workflow routing for product questions

## What the documents look like

Presale group-buy collection takes orders first and organizes procurement and fulfillment afterward. Product reference and option questions in this category therefore revolve around the presale product table, the collection result, the procurement plan, and the cutoff notice. The supplied brief lists small-program orders, supplier inventory, group-leader feedback, and warehouse-delivery routing as the main data sources, with updates daily or per session. These materials change several times within a day, so workflow routing has to treat each session's cutoff moment, product scope, and quantity basis as a separate input. A collection result from one session cannot be carried over to the next session as if it were current.

The output of product reference and option questions is product information and option guidance for operations, procurement planning, and supply-chain scheduling to check against. These roles look at the same product across sessions for specification, available quantity, and cutoff status. The brief does not describe the field mapping between product master data, supplier inventory, and warehouse-delivery routing, so routing can only carry forward the known materials item by item, and missing fields stay recorded as unknown.

## Constraints at the workflow routing step

The Form Input node enters an interaction state when triggered, collects required information, and passes that information to later nodes after submission. The User Selection node evaluates the user's choice and executes the corresponding "yes" branch. Both are user interaction nodes: they record the workflow state and continue downward only after the user completes the interaction. Routing has to connect the input items, decision branches, and output handoffs of product reference and option questions to retrieval, judgment, or interface nodes one by one.

Order writes, document backfill, and external status synchronization must connect to a business interface or a later process. Retrieval results do not constitute authorization, and a similarity score does not perform permission or entity isolation. Libraries using the same vector model can be associated together; libraries using different vector models cannot be associated together, so identifiers should be checked first and non-matching libraries excluded. Empty-result handoff can be checked against downstream design using an explicit paper input, and no claim can be made that a particular retrieval necessarily returns an empty array.

Hypothetical drill sample: on 10 June 2025 a platform operations staff member prepares presale product materials for the "12 June session." The source text reads: "The cutoff time for this session is 11 June at 20:00; product A specification 500 g per unit, supplier-reported available quantity 120 units; product B specification 1 kg per unit, available quantity pending supplier confirmation." The proposed sentence is: "Product A available quantity for this session is 120 units, and product B available quantity is confirmed." The item to be judged is whether product B's available quantity is confirmed.

## Three common errors

1. Treating a retrieval result as authorized execution. In the hypothetical sample, product B's available quantity reads "pending supplier confirmation." If routing writes a historical available quantity directly into the procurement plan, the input is a historical figure, the comparison object is the source text of this session's materials, and the observable result is a quantity in the procurement plan that has not been confirmed. The correct handling is to mark the field as pending verification and wait for supplier confirmation or manual input.

2. Treating a pending review as a missing operation permission. In the hypothetical sample, one product material item has the status "pending procurement plan review." If routing concludes from this that operations has no right to view it, the input is the status field, the comparison object is the status stated in the source materials, and the observable result is that the process skips the product. A pending review only indicates that review is unfinished; it does not demonstrate that permission is absent.

3. Associating libraries that use different vector models. In the hypothetical sample, the product material library and another library use different vector models. If routing merges their retrieval results directly, the input is the two library identifiers, the comparison object is whether the model identifiers match, and the observable result is returned entries that cannot correspond to the same product. Identifiers should be checked first, non-matching libraries excluded, and the actual observation recorded.

## How to verify the setup

1. For the hypothetical sample's proposed sentence "Product A available quantity for this session is 120 units, and product B available quantity is confirmed," the input is the source materials and the proposed sentence, the comparison object is the source wording "pending supplier confirmation" for product B's available quantity field, and the observable result is that the proposed sentence does not match the source and is judged unsupported. The condition is met when the proposed sentence is changed to "product B available quantity is pending supplier confirmation."

2. For "the cutoff time for this session is 11 June at 20:00" in the hypothetical sample, the input is the cutoff notice and the session information collected by the Form Input node, the comparison object is the cutoff time field, and the observable result is that when the two agree, the Form Input node can continue downward; when they differ, the difference is recorded and the cutoff time is not rewritten automatically.

3. For empty-result handoff, the input is the paper input [], the comparison object is the downstream node's design for handling an empty array, and the observable result is whether the downstream gives a clear prompt or moves to manual checking as designed. This check does not claim that a particular retrieval necessarily returns an empty array; it verifies only the downstream handoff logic.
