# Group-buy presale orders: citation tracing for product questions

## What the documents look like

Presale group buying collects orders first and organizes procurement and fulfillment afterward. Daily work centers on a presale product table, group-order results, a procurement plan, and a cut-off notice. Product information and selection questions usually point to a specification in one presale product table, a quantity in one group-order result, or a line item in one procurement plan. These documents update daily or per session, and the same product may have different document versions across sessions.

Citation tracing must establish which document an answer relies on, which original passage it cites, and what version and state that document is in. The supplied brief gives an update frequency of daily and per session. This page does not derive batch synchronization, full synchronization, or transaction-triggered mechanisms from that frequency.

## Constraints at the citation tracing step

A knowledge base search node can select one or more knowledge bases that share the same vector model. Its output is a citation array whose length may be zero; when nothing is found, the downstream path still runs. Search results can be passed to an answering step, and the answer must be checked line by line against the cited original text. Retrieval is not authorization and does not perform entity isolation or permission filtering.

Hypothetical paper exercise: an operations role keeps a "Session 12 Presale Product Table (hypothetical identifier YS-12)" whose original text states: "Product: hypothetical variety A, specification 500g; presale unit price per this table; cut-off time is the time stated in this session's cut-off notice." A separate "Session 12 Group-Order Result (hypothetical identifier JD-12)" states: "Hypothetical variety A group-order quantity 120 units." One draft sentence awaiting judgment reads: "Hypothetical variety A has completed procurement ordering for 120 units." That draft sentence concerns a procurement execution state. Neither document states that procurement ordering is complete, so the sentence is unsupported.

## Configuration and implementation checks

| Configuration or check item | Hypothetical starting point for this exercise | Reason and comparison object |
| --- | --- | --- |
| Linked knowledge bases | Include the knowledge base holding YS-12 and JD-12 | First check each base's vector model identifier; only matching models may be linked together |
| Search mode | Hybrid search | Compared with semantic search alone, identifier-style queries rely more on full-text hits |
| Citation limit | Hypothetical starting point 2000 tokens for this exercise | Compared with a smaller value, observe whether citations cover the needed original text |
| Minimum relevance | Hypothetical starting point 0.3 for this exercise | Compared with a higher value, observe whether relevant original text is filtered out |
| Result reranking | Enabled per settings | A rerank model must be available; compare ordering with the disabled case |
| Citation display check | Compare answer and cited original text line by line | Compared with judging only answer fluency, which is not source evidence |

The citation limit is counted in tokens and differs from top k. A thinking budget is a model thinking setting and is not used as a citation token limit.

## Three common errors

1. Treating retrieval output as authorization. Input: the citation array returned by search. Comparison object: the authorization state for procurement ordering. Observable result: whether the citation array exists does not change the authorization fact.
2. Treating an empty citation as an error. Input: an explicit paper output []. Comparison object: whether the downstream design accepts an empty array. Observable result: the empty array still runs through the path.
3. Treating an unstated state as a negative. Input: the original text of YS-12 and JD-12. Comparison object: the draft sentence "procurement ordering completed." Observable result: neither document states that state, so the sentence is unsupported.

## How to verify the setup

- Check one: input the YS-12 original text and the draft sentence, compare the procurement ordering state described in the draft sentence against the fields stated in the original text, and the condition is met only when the original text explicitly states that state. It is not met in this exercise.
- Check two: input the JD-12 original text and a question about "group-order quantity 120 units," compare whether the answer citation points to the JD-12 original text, and the condition is met when each citation can be traced back to that original text.
- Check three: input the paper output [], compare whether the downstream answering design accepts an empty array, and the condition is met when the path runs through and no fabricated source is produced.

All of the above is paper checking. No actual retrieval, deployment, or business action was performed. Missing evidence remains missing.
