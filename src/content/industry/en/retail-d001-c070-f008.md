# Cross-border product labels: workflow routing for product questions

## What the documents look like

Cross-border product compliance and labelling work happens before listing and before import. The centre of the work is assembling and judging product safety and label evidence rather than moving money or scoring transactions. The main data sources named for this category are platform policy centres, testing laboratory reports, destination-country regulation libraries, and supplier materials. The documents handled day to day are product test reports, English-language labels, MSDS files, and platform prohibited-item lists. Updates arrive irregularly, and each new listing can bring new compliance requirements.

These traits make the input to product-information and selection questions visibly heterogeneous. A test report is a low-structure statement of test conclusions. An English label is a text object still awaiting checking. An MSDS is a chemical safety description. A platform prohibited-item list is a set of policy entries. Workflow routing has to place these different document shapes into a traceable processing order, so that later nodes can carry forward what an earlier step collected.

The workflow routing step is therefore about ordering and hand-off, not about deciding compliance on its own. The form input node and the user selection node both belong to the user-interaction family. Each can be added repeatedly and each triggers execution. When one is triggered, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user finishes interacting. After submission, the form input node collects the required information the user filled in and passes it to later nodes. When the user makes a choice at the user selection node, the node judges that choice and executes the corresponding "yes" branch. Neither node performs business verification, approval, database writes, or external synchronisation. Order writing, document back-filling, and external status synchronisation require a separate business interface or a later process. Retrieval results do not constitute authorisation, and a relevance score does not act as a permission or entity filter.

## Constraints at the workflow routing step

The interaction state, the recorded workflow state, and the hidden dialogue box are existing behaviours of these nodes. They do not imply a global state-recording switch, a submission-count limit, or an automatic judgement mechanism. Waiting for interaction, recording state, and continuing after user input are the documented conditions; anything beyond them stays unknown unless a document states it.

A clearly labelled hypothetical paper exercise follows. On 10 June 2025, a compliance specialist at a cross-border seller submits materials for an electronic desk lamp intended for the German market. The source text to be checked reads: "Product test report number TR-2025-0610; test items are electrical safety and electromagnetic compatibility; the report conclusion states conformity with the referenced standards. The English label draft states Input: 100-240V~ 50/60Hz, 0.5A. The MSDS file states that the product does not contain a lithium battery." The draft sentence awaiting judgement is: "This product has completed German market compliance review and can be listed directly." The scope of checking is limited to those three materials. The authorisation boundary is internal material checking, with no platform submission and no customs declaration.

Within that boundary, the routing question is which node collects what, which branch follows which answer, and where the collected values must reappear downstream. The destination country determines the later regulation-library search scope, and the report number is the identifier the sample explicitly provides. Nothing in the three materials states that a German market compliance review was completed or that listing permission exists.

## Configuration and implementation checks

The table below lists settings or implementation checks relevant to this page's sample. The hypothetical starting point is used only for this paper exercise and is not an official default value.

| Configuration item | Setting or check in this page's sample | Reason and comparison method |
| --- | --- | --- |
| Form input node | Make the destination-country field required; pass it to the later retrieval node after submission | The destination country determines the later regulation-library search scope and matches the sample's German market |
| User selection node | Configure a "test report already available" branch; choosing yes enters report checking | The sample supplies a report number, which is used to verify the branch connection |
| Retrieval scope | Limit to platform policy centre and destination-country regulation-library entries | Consistent with the sample's authorisation boundary; no extension to external systems |
| Output hand-off | Pass the collected destination country and report number into downstream nodes | Compare each output item against the corresponding input item |
| External action split | Mark listing, declaration, and similar actions as requiring a separate business interface | The nodes themselves perform no writes or synchronisation |
| Hypothetical starting point | Use the report number as the checking starting point and compare it with the form submission value | This paper exercise selects that starting point because the sample explicitly states the number |

## Three common errors

1. Treating information collected by the form input node as completed business verification. In the sample, the form submits the destination country and the report number. The submission action completes information collection only and does not constitute a passed compliance review. The check compares the submitted values with the values the later node actually receives; a successful submission is not a completed review.

2. Treating the "yes" branch of the user selection node as authorised execution. In the sample, choosing "test report already available" triggers the report-checking branch only. It does not mean the report has been accepted or that listing has been approved. The check verifies whether the branch connection points to the report-checking node and observes whether that node's output is only a material comparison result.

3. Treating a retrieval result or relevance score as a permission filter. In the sample, the destination-country regulation-library search returns entries. The relevance of an entry does not exclude unauthorised records and does not show that the product meets every requirement. The check verifies whether the retrieval scope stays within the authorised materials and records the actual returned content, without inferring compliance status from a score.

## How to verify the setup

1. Enter the sample's form submission values "Germany" and report number "TR-2025-0610", then compare the destination country and number received by the later retrieval node against the submitted values. If a received value is missing or differs from the submitted value, the output hand-off is not correctly configured. The expected condition is that the received values match the submitted values; no actual test is claimed.

2. Enter the sample's user selection "test report already available", then compare whether the executed branch path enters the report-checking node. If another branch runs, or the checking node is not entered, the branch connection needs review. The expected condition is entry into the report-checking node, with the actual result left to runtime observation.

3. Enter the sample's draft sentence "This product has completed German market compliance review and can be listed directly", then compare that sentence against the three source materials. The materials state only a test report conclusion, a label draft, and MSDS content. They do not state that a German market compliance review was completed or that listing permission exists. The draft sentence is unsupported and should be marked as pending verification rather than judged as a negation or a conflict. The missing review and permission evidence remains missing.
