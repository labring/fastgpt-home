# Cross-border settlements: retrieval for product questions

## What the documents look like

Settlement and foreign-exchange material for cross-border platforms centres on funds already collected from completed orders. Fraud chargebacks belong to a different operational stage and are not handled here. This page deals with four document types: platform settlement statements, exchange-rate tables, service-fee invoices, and collection reconciliation sheets. Their update cycle is weekly or monthly.

In product-information and selection questions, these documents serve two purposes. They act as selection evidence, describing which fields a given settlement document contains for a particular platform, currency, and settlement period. They also act as reconciliation evidence, letting operations staff judge at handover whether a document covers the required object and period.

Retrieval here targets the document text itself. It answers questions such as which fields a settlement statement includes, or which interval an exchange-rate table covers. The retrieval step does not verify authenticity, does not perform reconciliation, and produces no authorisation effect. A retrieval hit is not a business confirmation, and an offered option is not an executed action.

## Constraints at the retrieval step

Settlement document numbers, settlement periods, and currency codes are precise query targets suited to full-text or hybrid retrieval. Natural-language questions about field meaning suit semantic retrieval. The knowledge-base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases using different vector models cannot be associated together; the model identifier is checked first and any mismatch is excluded rather than tested by running a cross-model search.

The citation limit is measured in tokens. Settlement statements and reconciliation sheets differ widely in length, so the completeness of returned citations is observed separately for each. The minimum relevance score takes effect only under semantic retrieval or when result reranking is used. It is a filter threshold, not a ranking rule, and it does not perform permission or entity isolation. A relevance score is not a category, entity, or permission filter, so it cannot exclude unauthorised records on its own.

Question optimisation performs coreference resolution and question expansion. The optimised question is compared against the original to check whether the subject or the period was altered. The search output is an array whose length may be zero, and the downstream chain still runs on an empty result.

Hypothetical paper test case: the source text for comparison reads, "March 2024 platform settlement statement (sample number S-2403), currency covered USD, settlement period 2024-03-01 to 2024-03-31, containing order deduction details and total service fees." The draft sentence to be judged reads, "This settlement statement has confirmed the full service-fee amount for March 2024 and completed collection." The draft sentence concerns collection status. The source text does not state any collection fact, so the claim is unsupported.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this page | Reason and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Settlement-statement base and exchange-rate base | Both use the same vector model; model identifiers are checked one by one and mismatches excluded |
| Search mode | Hybrid retrieval | The sample contains both an identifier and natural-language fields; results are compared against semantic-only and full-text-only runs |
| Citation limit | Hypothetical starting point 3000 tokens | Using the full fields of sample S-2403 as reference, the cut-off point is compared for loss of the total service-fee field |
| Minimum relevance score | Hypothetical starting point 0.4 | Relevant and irrelevant samples are labelled first, then the citation set is compared as the threshold changes |
| Question optimisation | Enabled for multi-turn follow-ups | The original and optimised questions are compared to check whether subject and period were altered |
| Result reranking | Enabled when candidates are numerous | A rerank model must be available and enabled per settings; rerank scores are compared against vector scores |

These values are starting points for this hypothetical trial and are not official defaults. RRF is the fusion process for hybrid retrieval results and is not configured as a standalone switch. Image retrieval requires image input and the corresponding model capability; reranking requires the model and its enabled setting. The optional paths in the overall retrieval flow are not all executed on every request.

## Three common errors

1. Treating the minimum relevance score as a permission or entity filter. Input is a retrieval request for sample S-2403. The comparison is whether returned citations contain other currencies or unauthorised settlement-period records. If such records appear, the relevance setting is not performing isolation, and a separate permission implementation is required.

2. Treating a retrieval hit as business confirmation. Input is the draft sentence claiming completed collection. The comparison is whether the source text states collection status. When the source does not state it, the claim is unsupported and must not be recorded as collected.

3. Forcing knowledge bases with different vector models into one association. Input is the model identifiers of the settlement-statement base and the exchange-rate base. The comparison is whether the two identifiers match. On mismatch, that base is excluded and no cross-model retrieval is run.

## How to verify the setup

1. Input the full source text of sample S-2403 and the draft sentence. Compare whether the collection fact asserted in the draft appears in the source. When the source does not state it, record the claim as unsupported and do not judge it as completed collection.

2. Input a retrieval request for sample S-2403. Compare whether the returned citation contains the total service-fee field. If the citation limit truncates the field, adjust the limit and observe again. A first-hit guarantee is not claimed.

3. Input a paper empty result `[]`. Check whether the downstream design handles an array length of zero. No claim is made that a fictional rule search necessarily returns an empty array.

This page covers only cross-border platform settlement and foreign exchange, product-information and selection questions, and knowledge-base retrieval and recall. Whether materials, operations, or requests are authorised at operations handover cannot be settled by retrieval or by a form. Forms collect values; business verification, approval, database writes, and external synchronisation require their stated downstream implementation.
