# Creator commission settlement: citation tracing for product questions

## What the documents look like

Creator commission settlement and deduction happen after a sale closes. The objects being reconciled are valid promotion orders and post-sale deduction results. Source materials come from the affiliate marketplace back office, order after-sales data, the finance system and creator contracts. Day-to-day documents include commission setting records, settlement statements, refund deduction details and invoices. Citation tracing answers a narrow question: when an answer states a commission rate, a deduction basis, a statement amount or a refund handling conclusion, which document, which version and which field does that statement come from.

Materials update weekly and monthly, and version differences directly affect whether a citation is still valid. A settlement statement from July and the same statement reissued in August can carry different figures for the same creator and the same order period, so the version identifier matters as much as the content.

## Constraints at the citation tracing step

The knowledge base search node can link one or more knowledge bases that share the same vector model. Its output is an array of cited content, and the length may be zero; an empty array still lets the downstream chain run. Cited content must be handed to the answering step, where each answer sentence is compared against the cited source text.

The minimum relevance setting takes effect only under semantic retrieval or result reranking. It is a filter threshold, and it does not perform permission or entity isolation. Hybrid retrieval merges multiple result paths through RRF. Reranking requires a model and must be enabled by configuration. Image retrieval requires image input and matching model capability. These paths describe what the documented flow can include; they do not mean every request executes all of them.

Hypothetical paper exercise sample. Source text: "Settlement statement A-07 for July 2025 records: for creator A, the commission rate for the period 1 June to 30 June is 12%, and refund deductions are offset against the actual refunded order amount." Draft sentence under review: "Creator A's June commission rate is 15%, and refunds do not offset commission." Comparing the same subject, the same period and the same field, the source value 12% and the draft value 15% are mutually exclusive values in one field, which is a contradiction. The refund statement in the draft is opposite to the source text and is likewise unsupported. If a material only states "the June commission setting has been submitted for review," then both the commission rate and the deduction basis remain unsupported and pending verification.

| Linked knowledge bases | Select only commission settlement bases sharing one vector model | Same vector model is required for joint linking; check the identifier first and exclude non-matching bases |
| Cited content output | Accept the array; length may be zero | An empty array does not mean the workflow terminated with an error |
| Citation token ceiling | Hypothetical trial starting value 3000 tokens | Mixed materials vary widely in chunk length; compare against 2000 and 4000 for stability |
| Minimum relevance | Hypothetical trial starting value 0.35 | Compare against 0.2 and 0.5 to see whether valid commission fields are filtered out |
| Search mode | Use full-text or hybrid retrieval for identifiers and model numbers | Semantic retrieval suits natural-language questions |
| Material version check | Retrieve against the current and the historical statement separately | Whether a citation is adopted still depends on review of the effective version |

## Three common errors

1. Treating a retrieval hit as a permission decision. The erroneous input is "statement A-07 was retrieved, so it may be disclosed to the creator." The comparison object is the authorization boundary material. The observable result is that the disclosure action must not be executed when no authorization record exists.

2. Writing a pending-review state as already effective. The erroneous input is "the June commission setting has been submitted for review, so June settles at 15%." The comparison object is the review status field. The observable result is that a setting not yet approved cannot serve as a settlement basis.

3. Treating an empty citation array as a retrieval failure. The erroneous input is the paper input `[]`. The comparison object is the downstream node design. The observable result is that the downstream chain continues on the empty-citation branch and does not trigger a fabricated error.

## How to verify the setup

1. Enter the hypothetical source text and the draft sentence above, then compare 12% against 15% and the refund-offset wording against its opposite. When one field holds mutually exclusive values, record it as a contradiction and keep the source citation attached.

2. Enter the paper citation array `[]` and compare whether the downstream node continues on the empty-citation branch. The chain running through meets the expectation; this does not claim that a rules-based retrieval must return an empty array.

3. Enter the same question against the current and the historical statement, then compare the version identifiers the citations point to. The condition is met when the citation points to an effective version and the answer can be traced back to the source text. When the version is not stated, record the gap.
