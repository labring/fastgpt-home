# Creator commission settlement: retrieval for product questions

## What the documents look like

Commission settlement happens after a sale closes. The records that matter for this category describe valid promotion and post-sale commission deduction, and they come from several systems at once: the selected alliance backend, order after-sales data, the finance system, and creator contracts. Day-to-day documents include commission setting records, settlement statements, refund deduction details, and invoices. These materials update weekly and monthly.

For retrieval, the practical consequence is that one question often needs the same field from more than one source. The commission rate, refund status, and settled amount for a single order may sit in different documents, and the retrieval step has to surface traceable fragments for each. In this category, product information and selection questions are really about matching commission setting wording, deduction rules, and statement fields to one another. The retrieved content supports later manual reconciliation. Retrieval itself does not change any settlement state.

## Constraints at the retrieval step

The search unit is the whole library. A collection is only a way to group data for management, and it does not affect search results. A knowledge base search node can associate one or more knowledge bases that use the same vector model. Bases built on different vector models cannot be associated together. The correct step is to check the model identifier and exclude the ones that do not match; do not run a cross-model search to compare what was missed.

Reference content is output as an array, and its length can be zero. A chain with no retrieved content still completes. Mixed retrieval merges multiple result paths through RRF, which is a fusion process rather than a switch that can be turned on. The minimum relevance value only takes effect in semantic retrieval or when result reranking is used. It is a filter threshold, not a permission or entity isolation mechanism, and retrieval does not make authorization decisions.

Image retrieval requires image input and the corresponding model capability. Reranking requires a rerank model and must be enabled in the settings. The optional paths listed in the documentation do not mean every request executes all of them.

Hypothetical drill sample: a creator contract attachment states, "For the period 1 March 2026 to 31 March 2026, the commission rate for order A is 15%, and refunded orders deduct the corresponding commission based on the actual transaction amount." A selected alliance backend export shows the same order's settlement statement marked "commission rate 12%, refund deduction executed at the original rate." The draft sentence to be judged is: "Order A settles at 15% in March, and refunded portions are not deducted." This sample is used to check value differences for the same subject, the same period, and the same field.

## Configuration and implementation checks

| Configuration item | Hypothetical trial starting point | Reason and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Commission setting records base and refund deduction details base | Both bases use the same vector model; check identifiers before associating |
| Search mode | Mixed retrieval | Commission rates and order numbers are exact fields; mixed retrieval covers both semantics and keywords |
| Reference limit | Hypothetical starting point of 2000 tokens | Settlement statement fragments are long; compare whether content is complete using materials of different lengths |
| Minimum relevance | Hypothetical starting point of 0.4 | Label relevant and irrelevant samples first, then compare recall changes after threshold adjustment |
| Question optimization | Enabled for multi-turn follow-up scenarios | Compare the original question with the optimized question, and check whether the order subject was changed incorrectly |
| Result reranking | Enabled when candidates are numerous | A rerank model must be available and enabled in settings; compare ordering using rerank scores |

## Three common errors

1. Treating minimum relevance as a permission filter. Incorrect behavior: assuming that raising the threshold excludes other creators' settlement records. Check method: input the same question, compare reference content returned before and after the threshold change, and observe whether fragments from non-target subjects still appear.
2. Associating knowledge bases that use different vector models. Incorrect behavior: selecting the commission setting records base and another base with a different model at the same time. Check method: check each base's vector model identifier, exclude those that do not match, and record the actual observed association result.
3. Treating a retrieval hit as settlement authorization. Incorrect behavior: executing a commission deduction directly based on a retrieved commission rate. Check method: compare the retrieval result with the contract and statement originals, and confirm that business execution requires a separate system implementation; retrieval does not produce authorization.

## How to verify the setup

1. Input the contract attachment sentence and the draft sentence from the hypothetical sample. Compare the draft sentence "settles at 15%, refunded portions are not deducted" with the attachment's "refunded orders deduct the corresponding commission based on the actual transaction amount," and observe whether the draft sentence conflicts with the original. Expected observation: the draft sentence and the attachment take mutually exclusive values on the refund deduction field, so the draft is judged unsupported.
2. Input the backend export sentence from the hypothetical sample. Compare "commission rate 12%" with the attachment's "commission rate is 15%" on the same order, the same period, and the same field, and observe whether the two contradict each other. Expected observation: the same field has explicitly mutually exclusive values, so the result is judged contradictory and requires manual source verification.
3. Input a short question with no order subject, containing only "how is refund deduction calculated." Compare whether the returned reference content covers the contract attachment and the backend record, and observe empty results or irrelevant fragments. Expected observation: if an empty array is returned, check the downstream design as documented; if irrelevant content is returned, record the gap without inferring a cause of retrieval failure.
