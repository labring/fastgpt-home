# Import and export permits: vector indexes for product questions

## What the documents look like

Permit handling takes place before customs declaration and determines whether a shipment may lawfully cross a border. Product data and selection questions in this category draw on automatic import licences, dual-use item licences, contracts and product descriptions. Source material arrives from commerce authority systems, customs commodity codes, supplier files and customer end-use statements. New files appear irregularly, and each shipment can introduce a fresh set.

The structural differences among these materials shape index design. A licence excerpt carries a document name, regulatory conditions, validity period and permitted scope. A contract carries transacting parties, a goods description and signature status. A product description carries technical parameters and final use. Subject, object and status fields differ across the three material types, and one data chunk usually covers only one of them.

## Constraints at the vector indexes step

Knowledge bases linked for retrieval must share the same vector model. Confirm the actual model and its supported input types first. One source data block can map to multiple indexes, and index text is checked separately from source text. Index content is built from complete, focused information, while retrieval coverage and index length are weighed against the sample at hand.

Image retrieval depends on whether image descriptions or image vectors were generated at ingestion time. Uploading an image at query time does not by itself make stored images retrievable. After a model or index change, compare cited source text across the same question set rather than treating a vector score alone as a quality guarantee. Semantic recall and relevance scores carry no permission or entity isolation role, and a retrieval hit does not constitute an authorization state.

The documented flow diagram lists paths that do not all run on every request. Image retrieval requires a corresponding image input and model capability. ReRank requires a model and must be enabled in settings. Knowledge bases built on different vector models cannot be linked together; check the identifiers, exclude non-matching bases and record what was observed.

Hypothetical paper exercise: an enterprise holds a paper excerpt of a Dual-Use Items and Technology Import Licence. The excerpt records the applicant as "Jia Import and Export Co., Ltd.", the licence status as "issued", the permitted scope as "limited to graphite products under this contract", the contract number as "HT-2024-017", and the signature field as blank. A draft sentence reads: "Jia Import and Export Co., Ltd. has obtained a licence for this batch of graphite products, and the contract has taken effect." Comparison against the excerpt shows that the excerpt supports "issued" and "limited to this contract" only. It does not state that the contract took effect, and the blank signature field leaves that point unsupported.

## Configuration and implementation checks

| Configuration item | Hypothetical trial starting point for this page | How to check |
| --- | --- | --- |
| Vector model | Select a model supporting text input and record the actual model identifier | Compare with the model identifier of each linked knowledge base; exclude bases whose identifiers differ |
| Index content | Build focused indexes separately for licences, contracts and product descriptions | Sample index text and compare subject, object and status against the source text |
| Image index | Only where an image description or image vector was generated at ingestion | Inspect the data block record for the corresponding index; where none exists, record the gap |
| Search mode | Run the same question set under semantic retrieval first | For code and model-number questions, switch to full-text or hybrid retrieval and compare |
| Citation limit | Set to a token amount that can hold one licence excerpt | Compare against the actual returned citation length; adjust when too short |
| Minimum relevance | Start at a middle value and observe how many results remain after filtering | Compare cited source text for the same question set before and after adjustment |

The citation-limit starting point follows from the sample excerpt running two to three sentences and needing to hold the full licence status field. The minimum-relevance starting point aims to avoid filtering out exact contract-number matches. Both values are adjusted against comparison results for the same question set.

## Three common errors

1. Treating a retrieval hit as authorization confirmation. A returned licence excerpt shows only that the text was recalled; it does not show that the applicant obtained a licence or that the contract took effect. Compare the draft sentence for status words the source does not contain, and mark any such word as unsupported.
2. Linking knowledge bases built on different vector models. With two knowledge bases carrying different model identifiers as input, compare the model identifier fields, exclude the non-matching base and record it. Do not run cross-model retrieval to compare missed recalls.
3. Treating image retrieval as a query-side capability alone. With a product image as input, compare the ingestion record for a generated image description or image vector index. Where none was generated, record the gap rather than judging retrievability from the query-side upload.

## How to verify the setup

1. Enter the licence excerpt and the draft sentence from the hypothetical sample, and compare whether the draft contains "the contract has taken effect", which the source does not state. Where that wording appears, judge it as beyond the evidence and record it as pending verification.
2. Enter two knowledge bases with different model identifiers and the same question, compare the model identifier fields, exclude the base whose identifier differs and record it. Do not continue with cross-model retrieval.
3. Enter a code-type question and run it under semantic retrieval and full-text retrieval separately, comparing whether the returned cited source text contains that code. Where full-text retrieval returns the code and semantic retrieval does not, record that exact queries suit full-text retrieval.

For empty-result handling, a paper input of an empty array can be used to check the downstream design, without claiming that a fictional rule search necessarily returns an empty array. A pending review does not show a lack of operating permission. Signature, agreement reached and contract effectiveness are three distinct facts, and evidence gaps remain pending verification.
