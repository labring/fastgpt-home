# Chain-store site selection: retrieval for product questions

## What the documents look like

Site selection and store opening happen before a store begins trading. The work centers on lease and engineering delivery. The everyday materials are the site evaluation form, the lease letter of intent, the renovation budget, and the opening schedule. These materials update on an irregular basis, per store. Product information and selection questions must answer which model applies to a given store at a given stage, which version of a quotation is current, and which delivery item a schedule entry covers. Retrieval therefore has to separate store number, stage, and document version. Vector model quality, data completeness, and the quality of the search terms jointly affect recall precision. Mixed use of numbers and model codes inside the materials lowers hit rates directly.

## Constraints at the retrieval step

The knowledge base search node can associate one or more libraries that use the same vector model. Libraries built on different vector models cannot be associated together. Check the vector model identifier first, exclude libraries that do not match, and record the observation. Do not run a cross-model retrieval to compare missed recall.

A single retrieval combines several capabilities according to the input and the search parameters: question optimization, semantic retrieval, full-text retrieval or hybrid retrieval, image retrieval, RRF fusion, and Rerank. The final result passes through similarity filtering and a reference cap. The reference cap is measured in tokens. The minimum relevance score takes effect only in semantic retrieval or when result reranking is used. Retrieval and similarity scores do not carry permission or entity isolation functions. A retrieval result does not constitute any authorization.

Hypothetical drill sample: the source material reads, "Xingqiao Road store site evaluation form (number XQ-014) states: the lease letter of intent is pending landlord signature, the renovation budget is version V2, and the opening schedule is a first draft." The draft sentence to be judged is, "The Xingqiao Road store lease letter of intent has been signed and is effective, so renovation can start against the V2 budget." The field needed for judgment is the letter of intent status. The source gives only "pending signature" and states no signing date or effectiveness clause. That draft sentence is unsupported.

## Configuration and implementation checks

| Configuration item | Hypothetical trial starting point for this page | Reason for the choice and the comparison object |
| --- | --- | --- |
| Associated knowledge base | Associate only the same-vector-model library holding the site evaluation form, lease letter of intent, renovation budget, and opening schedule | Check the vector model identifier first and exclude each non-matching library |
| Search mode | Start with hybrid retrieval | Compare recalled items one by one against semantic retrieval alone and full-text retrieval alone |
| Reference cap | Hypothetical starting value of 2000 tokens | Compare a long XQ-014 budget entry against a short schedule entry to see whether reference content is truncated |
| Minimum relevance score | Hypothetical starting value of 0.3 | Label relevant and irrelevant samples first, then compare filtering results at 0.2 and 0.4 |
| Question optimization | On for multi-turn follow-ups, off for questions containing a number | Compare the subject of the original question against the optimized question to see whether it was altered incorrectly |
| Result reranking | Enabled when a rerank model is available | Compare the ranking position of the same candidate before and after reranking |

## Three common errors

1. Reading a pending-signature status as already effective. The input is the XQ-014 source text "pending landlord signature." The comparison field is the letter of intent status. An output of "signed and effective" is wrong. The correct observation is to record the evidence gap.
2. Treating a retrieval hit as operational authorization. The input is a budget fragment returned by one retrieval. The comparison object is the authorization boundary. A hit fragment shows only that content was recalled. It does not mean renovation can start.
3. Associating libraries with different vector models. The input is two libraries with different vector model identifiers. The comparison is whether the identifiers match. When they do not match, exclude the library and do not continue by inventing missed recall or redundant results.

## How to verify the setup

- Check one: input the XQ-014 source text together with the draft sentence "signed and effective." Compare the status field in the draft sentence against the source wording "pending landlord signature." The expected result is that the sentence is unsupported and the evidence gap on signing and effectiveness is preserved.
- Check two: input a query containing the number XQ-014. Compare the hits from full-text retrieval against hybrid retrieval. The expected result is that the number is matched exactly. If it is not matched, record the failure branch and inspect tokenization and indexing.
- Check three: input a paper empty result `[]`. Compare whether the downstream node still runs through its output path. The expected result is that the path runs through with a reference length of zero. Do not claim that any rule-based retrieval necessarily returns an empty result.

This page addresses only chain headquarters site selection and store opening, product information and selection questions, and knowledge base retrieval and recall. At operational handover, the authorization status of materials, actions, and requests cannot be inferred from retrieval or a form.
