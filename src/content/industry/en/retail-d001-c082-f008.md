# Returned-goods inspections: workflow routing for product questions

## What the documents look like

Returned-goods inspection handles parcels that have already arrived back at the warehouse. The object is the returned item and its condition grade, and no new-order outbound picking is involved. The main data sources are the WMS returns module, platform after-sales records, carrier return shipments and the inspection bench. Everyday materials are the return inbound receipt, inspection photos, the grade decision table and the resale listing sheet. The supplied brief gives an update frequency of per item and daily; this page does not derive batch sync, full sync or real-time triggering from that.

In this category, product information and selection Q&A means collecting the required inputs through a conversation and then deciding the next path from those inputs. Workflow routing covers node triggering, interaction waiting, information passing and branch selection. Business writes and external synchronization belong to interfaces connected separately.

## Constraints at the workflow routing step

After the form input node triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues downward once the user completes the interaction. After submission, the node collects the form information and passes it to later nodes. The user selection node also enters an interaction state, and after the user makes a choice it executes the corresponding "yes" branch. Recording state is behavior of the interaction node itself; no separate global state-recording switch is set. Interaction waiting, hiding the dialog, submission counts and snapshot guarantees are read as the documents explain them, and no corresponding controls are invented.

Collected information must be passed explicitly to later retrieval, decision or interface nodes, and output is compared item by item against input. Order writes, document backfill and external status synchronization require a separately connected business interface or later process. A form collects values only; it does not perform business verification, approval, database writes or external synchronization. Retrieval and semantic recall do not carry permission or entity isolation, and a similarity setting cannot exclude unrelated businesses or unauthorized records.

Hypothetical paper exercise sample: a return inbound receipt reads "Return number RT-2026-0417, item is a vacuum flask, exterior has scratches, inspection bench received it on 17 April 2026." A proposed draft sentence reads "This return has completed grade decision and can go directly to resale listing." A pending handover request reads "Please release according to the resale listing sheet." The source text states only receipt and an exterior description. It states no grade decision conclusion and no resale authorization, so the draft sentence and the request are both unsupported.

## Configuration and implementation checks

| Configuration or check item | Use on this page | Relation to the sample |
| --- | --- | --- |
| Form input node | Collects required information and passes it to later nodes after submission | Collects the return number and exterior description |
| User selection node | Executes the "yes" branch after the user chooses | Used for the grade decision direction |
| Interaction state check | Node enters interaction state and records state after triggering | Waits for the grade conclusion to be entered |
| Output acceptance check | Compares output against input item by item | Checks whether a decision conclusion comes from the input |
| External operation split | Writes and synchronization connect to a separate interface or later process | Resale listing is not completed by the form |

This page does not specify a numeric starting value. If a later trial needs one, the reason for choosing it and the value it is compared against must be stated, and it must not be called an official default.

## Three common errors

1. Treating form submission as a completed grade decision. The sample source text states only exterior scratches and no decision conclusion; the submission action does not produce a decision result.
2. Treating a retrieval hit as permission or entity isolation. A similarity score is not a category, entity or permission filter, and retrieval does not constitute authorization.
3. Treating a pending review or a draft sentence as approved. The draft sentence "can go directly to resale listing" is unsupported by the source text, and pending review does not show that authorization was granted.

## How to verify the setup

1. Enter the sample source text and the draft sentence, then compare whether the draft sentence matches the source text on the same subject, the same period and the same field. The source text states no grade decision conclusion, so the draft sentence is unsupported; only an explicit mutually exclusive value in the source text would constitute a contradiction.
2. Enter the handover request "Please release according to the resale listing sheet" and compare whether the decision conclusion the request relies on is stated in the materials. When that conclusion is missing, record the evidence gap and do not judge the request as approved.
3. Use the paper input `[]` to check the downstream design, and observe whether later nodes accept an empty result as designed. Do not claim that a fictional rule retrieval will necessarily return `[]`, and do not guarantee a first hit or full recall. Libraries built on different vector models cannot be associated together; check identifiers first, exclude those that do not match, and record the actual observation.
