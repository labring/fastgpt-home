# Store counts and loss control: workflow routing for product questions

## What the documents look like

Store counting and loss control work on the gap between book quantities and physical counts, and on shrinkage. They do not handle supplier settlement. The main data sources are POS inventory, WMS, monitoring systems, and the SB/T counting specification. Updates follow monthly and quarterly cycles. Everyday documents include count sheets, variance analyses, damage and loss approval forms, and monitoring access records. In product information and selection questions, these materials serve as the basis for cross-checking: a count sheet records book quantity and physical quantity, a variance analysis records the differing SKU and the reason judgment, a damage and loss approval form records the application and approval state, and a monitoring access record records the access time and scope. Workflow routing has to bring materials at these different stages into interaction nodes, where a user completes or selects values that are then passed to later nodes.

## Constraints at the workflow routing step

The form input node enters an interaction state when triggered, collects required information, and passes that information to later nodes after submission. The user selection node executes the corresponding "yes" branch after the user makes a choice, and each branch connection needs to be verified one by one. The interaction state is recorded by the node itself; no separate global state-recording switch is documented. Collected information must be explicitly passed to later retrieval, judgment, or interface nodes, and output must be compared with input item by item. Order writing, document backfill, and external state synchronization require a separate business interface or later process; the node itself does not perform these actions. Retrieval or a form does not constitute authorization to execute. A requirement that retrieval libraries share the same vector model cannot be extended to external systems. Libraries on different vector models cannot be associated together; the identifier can only be checked and non-matching items excluded, with the actual observation recorded.

Hypothetical paper exercise sample: a store loss prevention unit, within the March 2025 counting cycle, produces one count sheet stating "Category A goods: book quantity 120 pieces, physical count 113 pieces, variance 7 pieces." The variance analysis records "variance reason: picking omission, pending verification." The damage and loss approval form has the status "pending review." The monitoring access record states "accessed shelf aisle footage for 12 March, 20:00 to 21:00." The proposed draft sentence is: "The Category A variance at this store has been confirmed as caused by picking omission, and the damage and loss report has been approved." This sentence does not match the source in subject, period, or field: the variance analysis is only "pending verification," and the approval form is "pending review." Pending review does not constitute approval.

## Configuration and implementation checks

| Configuration item | Type | Relation to this page's task |
| --- | --- | --- |
| Form input node | Interaction node | Collects required information such as count sheet number, variance SKU, and approval form status; passes values to later nodes after submission |
| User selection node | Interaction node | Poses choices such as "is the variance verified" and "is the damage and loss report approved," continuing along the "yes" branch |
| Branch connection check | Manual check | Verifies one by one that each user selection node's "yes" branch points to the correct later node |
| Output handoff check | Manual check | Compares form-collected values against the input of later retrieval or judgment nodes |
| External action division | Implementation check | Order writing, document backfill, and external state synchronization connect to a separate business interface; the node does not perform them |
| Retrieval scope check | Manual check | Confirms that materials needed for the check fall within an accessible target retrieval scope, and records the gap when missing |

Hypothetical starting point for this exercise: pass the variance analysis value "pending verification" and the approval form value "pending review" as two independent fields into a judgment node, then compare whether the proposed draft sentence shares the same subject, period, and field as the source. This starting point is chosen because the source explicitly records these two states, and the comparison object is the draft sentence's "confirmed" and "approved."

## Three common errors

1. Treating pending review as approved. In the sample, the approval form status is "pending review," while the draft sentence says "the damage and loss report has been approved." Same subject, same period, same field, mutually exclusive values: this is a contradiction.
2. Treating pending verification as confirmed. The variance analysis records "pending verification," while the draft sentence says "confirmed as caused by picking omission." The source states no confirmation result, so the claim is unsupported.
3. Treating retrieval or a form as authorization to execute. A form collecting approval form status does not change the approval state; a retrieval hit does not grant access permission; external synchronization requires a separate interface.

## How to verify the setup

1. Input the hypothetical sample source text and the draft sentence, and compare subject, period, and field. If the draft sentence contains "approved" while the source reads "pending review," judge it a contradiction and return the draft sentence for revision.
2. Input the variance analysis source "pending verification" and the draft sentence "confirmed," and compare whether a confirmation conclusion is stated. The source states no confirmation result, so judge it unsupported, record the evidence gap, and do not write it as a denial.
3. Input the approval form status "pending review" and the draft sentence "approved," and compare the value of the approval status field. The two are mutually exclusive, so judge it a contradiction; if the source lacks the approval status field, judge it unknown and wait for supplementary material before checking again.
