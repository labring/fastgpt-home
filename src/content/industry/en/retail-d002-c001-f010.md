# B2B marketplaces: after-sales questions with citation tracing

## What the documents look like

For after-sales questions in B2B marketplaces, this page examines FastGPT citation tracing. Accounting closure, consultation obligations and request forwarding do not combine into completed service. The examples are hypothetical.

## Constraints at the citation tracing step

A proposed B2B aftersales fixture includes a contract promising post-delivery usage consultation, a settlement ledger marked account closed and a service entry saying the consultation request was forwarded. These texts describe an obligation, an accounting state and request routing. They do not include a completed consultation reply. Source tracing should keep each conclusion within its own dimension. Accounting closure can coexist with continued service handling, so the word closed cannot establish that every aftersales matter has ended or that the consultation obligation was fulfilled. Forwarded does not identify whether the recipient was a technical adviser or another handling role. It cannot establish that a suitably responsible person accepted the consultation. Progress reporting needs actual acceptance and response records, with contractual scope, request destination and reply content retained as distinct evidence objects.

## Configuration and implementation checks

| Task check | Material condition | Evidence action |
| --- | --- | --- |
| Promised obligation | Post-delivery usage consultation | Trace the clause and service scope. |
| Accounting state | Account closed | Limit the statement to the ledger dimension. |
| Routing action | Request forwarded | Retain action and subject. |
| Execution gap | No actual reply record supplied | Obtain consultation response evidence. |
| Conclusion boundary | Multiple citations still omit service outcome | Inspect evidence coverage for each conclusion. |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Associated knowledge bases` | Knowledge bases associated with one search node must use the same embedding model. |
| `Citation output` | The output is an array; an empty array can continue. |
| `Citation input handoff` | Inspect citations actually received by the answer step. |
| `Citation display check` | Trace displayed sources to their originals. |
| `Document-validity check` | Inspect source identity and applicable version separately. |

## Three common errors

One common error is treating the settlement source as proof of consultation performance. Another is treating the contractual promise itself as evidence that service occurred. The first needs an actual service record; the second needs separation of obligation and execution. A FastGPT citation array containing both contract and ledger does not create the missing reply. A forwarded-request passage should retain the action and its subject, since routing alone cannot establish that an answer was received or determine that a contractual obligation has ended.

## How to verify the setup

Acceptance questions can ask what consultation is promised, where the request currently sits and whether a reply is evidenced. Trace the answers to the clause and forwarding entry, and identify the actual reply material still required for the final question. Compare the cited content with its qualifications, rather than treating an aftersales-record title as proof of a completed chain. Empty references warrant checking current retrieval scope and passage transfer. Failure to return service evidence and proof that service never occurred must remain separate conclusions.
