# Temu semi-managed sellers: retrieval for after-sales questions

## What the documents look like

Semi-managed Temu sellers maintain overseas inventory and complete shipments themselves, unlike fully managed suppliers who only deliver goods to the platform. Records sit across Temu Seller Center, overseas warehouse WMS, logistics tracking and purchase cost sheets. Daily documents include product declaration forms, overseas inventory sheets, price declarations and platform fulfilment orders, with updates occurring daily and per order. In order fulfilment and after-sales question handling, retrieval requests often point to a specific fulfilment order, inventory batch or declaration entry. The same material set may therefore hold a declared value, an inventory value and a platform-returned value at once. The retrieval step needs to keep these source identifiers so that later manual checks can tell them apart.

## Constraints at the retrieval step

The dataset search node can associate one or more knowledge bases that use the same vector model. Bases with different vector models cannot be associated together; the check is to confirm each base's vector model identifier, exclude those that do not match, and record the observed result. Search modes are semantic retrieval, full-text retrieval and hybrid retrieval. Hybrid retrieval merges multiple result paths through RRF; RRF is a fusion process, not a switch that can be turned on. The minimum relevance setting takes effect only under semantic retrieval or when result reranking is used. The citation limit is measured in tokens. Question optimisation performs coreference removal and question expansion, and adds one model call. The output citation content is an array whose length can be 0, so the empty-result path still completes. Retrieval results reflect content similarity and do not carry permission or entity isolation; a retrieved record is not a record that has been authorised for use.

Hypothetical paper exercise sample: the source material reads "Overseas inventory sheet row A: SKU-TM-0417, Germany warehouse, available quantity 120, update date 2025-03-11. Platform fulfilment order row B: order 8825001, SKU-TM-0417, status pending shipment, creation date 2025-03-11. Price declaration row C: SKU-TM-0417, declared price 12.90 EUR, valid until 2025-04-30." The draft sentence to be judged is "SKU-TM-0417 has sufficient stock in the Germany warehouse, and order 8825001 can be shipped immediately." The draft merges an inventory quantity with a fulfilment order status into a shipment conclusion. The material does not state shipment authorisation or inventory freeze rules, so the draft is unsupported.

## Three common errors

1. Treating a retrieval hit as authorisation. Input the query "order 8825001", compare the retrieved result against the authorisation status field, and if the result contains only fulfilment order content with no authorisation record, the observable result is that a record was returned while authorisation remains unknown.

2. Deriving a shippable conclusion directly from an inventory quantity. Input the draft sentence "sufficient stock, can be shipped immediately", compare the inventory sheet against the fulfilment order status field, and if the order status is pending shipment with no shipment authorisation record, the observable result is that the draft exceeds the material's scope.

3. Treating minimum relevance as an entity filter. Input the unrelated query "other sellers' inventory", compare the returned content against the query subject, and if entries from other sellers in the same base are returned, the observable result is that the relevance threshold did not exclude a non-target subject.

## How to verify the setup

1. Input the three sample source rows and the draft sentence, compare "can be shipped immediately" in the draft against whether the material states shipment authorisation, and if the material does not state it, the draft should be judged unsupported and the evidence gap recorded.

2. Input the query "SKU-TM-0417 Germany warehouse inventory", compare whether the returned content contains the original text of inventory sheet row A, and if the returned content includes that row in full within the citation limit, the query path is usable for this case; if the returned array is empty, handle it through the empty-result downstream design and do not infer that a rule always returns empty.

3. Input the question containing a reference, "can this order ship", compare whether the subject still points to order 8825001 before and after question optimisation, and if the subject is replaced by another order after optimisation, record it as a deviation introduced by question optimisation and require manual review.
