# General export declarations: after-sales questions with citation tracing

## What the documents look like

For after-sales questions in General export declarations, this page examines FastGPT citation tracing. Declaration submission, packing counts and receipt confirmation concern separate stages. The examples are hypothetical.

## Constraints at the citation tracing step

A proposed export aftersales packet records declaration submitted, package count checked and awaiting receipt confirmation. These concern a filing action, a packing check and receipt correspondence. A question about completed delivery cannot equate submission with release or package checking with buyer receipt. FastGPT citations should preserve which source supplies each sentence. Similar document names do not join these process states into a completed delivery chain, and the available wording does not supply a release decision or actual recipient confirmation. The place and stage of the count matter as well. Checking packages during packing does not establish that the recipient counted the same objects. Comparing a handover difference requires records from both sides and matching shipment identities; a packing-side sentence cannot create recipient acceptance of the quantity.

## Configuration and implementation checks

| Task check | Material condition | Evidence action |
| --- | --- | --- |
| Filing action | Submitted does not contain a release finding | Seek actual release evidence. |
| Packing check | Package count checked | Limit the statement to packing review. |
| Receipt correspondence | Awaiting receipt confirmation | Retain the unresolved confirmation state. |
| Delivery evidence | Actual receipt record not supplied | Check received quantities and confirmation. |
| Uneven citation coverage | Array contains only packing review | Check coverage of the other stages. |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Associated knowledge bases` | Knowledge bases associated with one search node must use the same embedding model. |
| `Citation output` | The output is an array; an empty array can continue. |
| `Citation input handoff` | Inspect citations actually received by the answer step. |
| `Citation display check` | Trace displayed sources to their originals. |
| `Document-validity check` | Inspect source identity and applicable version separately. |

## Three common errors

One common error is deriving release from declaration submitted, which requires release evidence. Another is deriving complete receipt from package count checked, which requires received quantities and confirmation. Investigate these gaps separately rather than repeatedly citing the same packing sheet as though more references created additional evidence. Correspondence awaiting confirmation also cannot establish that the recipient refused delivery. Source tracing should retain action, subject and wording scope, since a well-formed document packet cannot substitute for the actual events required by the delivery conclusion.

## How to verify the setup

Acceptance questions should distinguish filing, packing checks and receipt confirmation, matching each answer to the passage actually supplied. The fixture supports submission and checking actions, plus receipt still awaiting confirmation; a delivery conclusion needs its own evidence list. Inspect a citation array containing only the packing check to ensure other stages are not completed through inference. When references are empty, investigate current source scope and passage transfer. That execution result cannot establish that no declaration was filed or that the goods were never packed.
