# General import declarations: multi-turn prompts for after-sales questions

## What the documents look like

Each general trade import declaration shipment produces an import declaration form, a commercial invoice, a packing list, a bill of lading, and a contract. The commercial focus sits on customs value, freight and insurance, and duty payment. In order fulfilment and after-sales question answering, conversations tend to circle around confirming the transaction term, the basis used to report freight and insurance, and the progress of customs inspection cooperation. Every shipment carries its own document set, and the status of each shipment changes with that shipment.

The multi-turn prompts step handles how these documents are cited, referred to, and bounded across follow-up questions. Answers stay constrained by the wording of the source documents. Because each document set is independent, a phrase such as "this shipment" or "the previous order" only resolves correctly when the actual history carried into the conversation supports that reference.

## Constraints at the multi-turn prompts step

Multi-turn dialogue carries prior turns into the request. The actual content of that history determines whether the model can resolve references such as "this shipment" or "the last order." When a knowledge base is used for continuous conversation, reference resolution and question expansion need to be checked, and whether short questions apply depends on the actual configuration.

Model and length settings require checking the supported context capacity against the reply limit. A long document combined with follow-up questions can exceed the range that can be referenced. The reply format is chosen according to what downstream processing needs; selecting `json_schema` requires filling in the corresponding format requirement and verifying the returned structure.

Similarity scores affect recall ordering only. They do not perform permission or entity isolation, and excluding unrelated business records requires a separate identifier check. Associating records within the same knowledge base requires first confirming that the vector model identifier matches; libraries built on different vector models cannot be associated together.

Hypothetical paper exercise: an importer's customs manager submits the following source wording in a conversation: "This shipment's bill of lading number is XXXXX, the transaction term is CIF, freight and insurance are already included in the invoice amount, the declaration form has been filed, and no inspection notice has been received." The draft sentence to be judged is: "This shipment has completed inspection and been released, and pickup can be arranged." The question is whether the source wording supports that draft sentence.

## Three common errors

1. Treating "has completed inspection and been released" in the draft sentence as a fact supported by the source wording. The source wording states only that no inspection notice has been received; it does not record completion of inspection or release, so the claim is unsupported.
2. Using a similarity score to exclude unrelated business records. Similarity affects recall ordering only and does not perform entity or permission filtering; an exclusion action requires a separate identifier check.
3. Treating the display configuration returned by an interactive node as an authorized execution result. Interaction collects choices or form values only; business verification, approval, and writes require downstream implementation.

## How to verify the setup

1. Input the source wording and the draft sentence from the hypothetical exercise, compare whether the draft sentence contains "has completed inspection and been released," and observe whether the answer preserves the gap that "no inspection notice has been received." The condition is met when no release conclusion appears.
2. Input consecutive follow-up questions under the same chatId, compare the history actually carried in against the expected range, and observe whether references are resolved correctly. The condition is met when content beyond the document scope is not filled in.
3. Input a paper input with an empty reference list, compare the downstream node's design for handling empty references, and observe whether an unsupported business conclusion appears. The condition is met when none appears; this result does not claim that a fictional rule retrieval necessarily returns an empty list.
