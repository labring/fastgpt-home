# General import declarations: after-sales questions with citation tracing

## What the documents look like

For after-sales questions in General import declarations, this page examines FastGPT citation tracing. Document registration and description correction do not establish physical warehouse arrival. The examples are hypothetical.

## Constraints at the citation tracing step

A proposed import aftersales fixture contains a transport-document entry marked registered, invoice-correction correspondence saying goods description awaiting confirmation and an arrival query with no unloading record attached. A warehouse-arrival question concerns physical location. Registration describes document handling, the correction concerns invoice wording and the absent unloading record is a gap in this packet. None establishes current location. Registering documents cannot become an arrival event, and an unresolved invoice description cannot by itself establish that transport stopped or that arrival was prevented. Description correction may concern document wording alone; the fixture does not say that the goods changed. Keep the revision subject separate from physical condition. A name awaiting confirmation cannot establish substitution of goods or a transport incident. Physical location still requires an actual event record relevant to that question.

## Configuration and implementation checks

| Task check | Material condition | Evidence action |
| --- | --- | --- |
| Document handling | Registration concerns documents | Do not derive warehouse arrival. |
| Invoice correction | Description awaits confirmation | Check final wording and correction relationship. |
| Location evidence | Unloading and receipt material absent | Specify actual records still needed. |
| Date clue | Later edit does not establish confirmation | Check the actual status sentence. |
| Citation content | Populated array may omit location evidence | Inspect coverage passage by passage. |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Associated knowledge bases` | Knowledge bases associated with one search node must use the same embedding model. |
| `Citation output` | The output is an array; an empty array can continue. |
| `Citation input handoff` | Inspect citations actually received by the answer step. |
| `Citation display check` | Trace displayed sources to their originals. |
| `Document-validity check` | Inspect source identity and applicable version separately. |

## Three common errors

Separate two risks during citation review. An arrival answer may cite only the transport-document registration, requiring warehouse receipt or unloading evidence. Alternatively, an early invoice may be treated as the final confirmed description despite unresolved correction correspondence, requiring inspection of the correction relationship and final wording. FastGPT source dates help locate versions but a later date does not establish completed confirmation. Populated citations still need content relevant to location; an accessible document link is not evidence of the physical movement asked about.

## How to verify the setup

Acceptance questions should separate document progress, correction progress and warehouse-arrival evidence. Trace answers to registration and pending confirmation, while identifying the actual receipt material still needed for arrival. Retain the original invoice and correction correspondence as distinct sources, then inspect which passage actually reached the answer so that pending wording is not lost. Empty references require investigation of current scope and transfer. They cannot establish non-arrival, missing document registration or a failed correction simply because no supporting passage returned in that run.
