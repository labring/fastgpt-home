# Warehouse picking and packing: workflow routing for after-sales questions

## What the documents look like

Warehouse picking, checking and packing serves order outbound movement, a different stage from supplier arrival and put-away. The working materials are wave picking lists, check records, shipping labels and packaging consumable sheets. Data arrives from the WMS, the order system, the electronic waybill platform and weighing equipment, and it updates per order and per hour. Mis-shipment, missing items, parcel damage and after-sales compensation are the main consequences when this stage goes wrong. Generating waves, scan-based checking and choosing packaging materials consume the most time.

For order fulfilment and after-sales answering, these materials do two jobs. One is to compare picking, checking, packing, weighing and label information for consistency. The other is to answer customer questions about shipment status, parcel contents and consumable choice. Workflow routing connects interaction nodes such as form input and user selection to later judgment, retrieval or interface-call nodes so that each order path stays traceable. When an interaction node triggers, the conversation enters an interaction state and the state is recorded; after the user submits or selects, execution continues downward. This behaviour comes from the official node documents and does not imply a separate global state switch.

A useful detail for this stage: the same order can be queried by a customer while the warehouse is still moving it, so the workflow must separate what the documents record from what a customer states. Per-order updates mean the routing decision for one order does not carry over to the next.

## Constraints at the workflow routing step

Interaction nodes collect values a user fills in or selects. Those values are not business authorization. The form input node passes collected information to later nodes after submission. The user selection node evaluates the user's choice and executes the corresponding branch, documented as the "yes" branch. Order writes, check-record backfill, waybill requests and external status synchronization are business actions that require a separate business interface or a later process. Retrieval and forms do not perform those actions.

Retrieval results and relevance scores do not act as permission or entity filters. Libraries built on different vector models cannot be associated together; the library identifier must be checked first and non-matching libraries excluded, without running a cross-model retrieval to compare missed recalls. The optional paths shown in the overall workflow diagram do not all execute on every request. Image retrieval requires image input and model capability. Reranking requires the model and must be enabled in settings. An empty-result handoff can be checked with the explicit paper input `[]` against the downstream design, without claiming that any rule-based retrieval necessarily returns empty. The thinking budget is a reasoning budget and cannot be repurposed as a citation token limit.

Hypothetical drill sample, clearly labelled: wave picking list WJ-0417 states that order A requires picking 3 items. The check record states that 3 items were actually checked. The shipping label states a recipient address in a named locality. Draft sentence under review: "The customer has confirmed receipt, so a refund can be issued directly." The form input node only collects what the customer fills in. A refund is a business action requiring a separate interface and approval, so the draft sentence exceeds the node's capability.

## Three common errors

1. Treating collected form values as authorization. Using the drill sample above, the draft sentence "The customer has confirmed receipt, so a refund can be issued directly" is compared against the wave picking list, check record and shipping label. The form input node only collects what the customer filled in; a refund is a business action requiring a separate interface and approval. The sentence exceeds node capability. Check: input the draft sentence and the three materials, compare whether the sentence treats a filled value as an executed refund, and treat that wording as not satisfying the condition.

2. Treating the "yes" branch of a user selection node as a completed termination. Hypothetical drill sample: the user selection node records that the customer chose "yes", and the branch points to an after-sales registration node. Draft sentence: "The after-sales process has been terminated." A selection only triggers branch execution; termination requires a later node to complete. Check: input the selection record and branch connection, compare whether execution evidence from a termination node exists, and record missing evidence as unsupported.

3. Using a relevance score to exclude unrelated records. Hypothetical drill sample: retrieval returns several records with scores, one of which is a check record for a different order. Draft sentence: "The score is below the threshold, so that record has been excluded." A relevance score does not perform entity filtering. Check: input the retrieval results and the draft sentence, compare whether the sentence substitutes a score for entity verification, and treat that wording as not satisfying the condition.

## How to verify the setup

- Verification one: input the wave picking list, check record, shipping label and the draft sentence "The customer has confirmed receipt, so a refund can be issued directly." Compare whether the sentence equates a collected form value with an executed refund. The condition is met when the sentence is marked as exceeding node capability and the refund action is marked as pending a separate interface.

- Verification two: input the user selection record, the "yes" branch connection and the draft sentence "The after-sales process has been terminated." Compare whether execution evidence from a termination node exists. The condition is met when the sentence is marked unsupported and the termination status remains pending verification.

- Verification three: input the returned records, their scores and the draft sentence "The score is below the threshold, so that record has been excluded." Compare whether the sentence substitutes a score for entity verification. The condition is met when the sentence is marked as not holding and entity verification is reassigned to manual checking by order number.

All three verifications use paper samples. No test, deployment, approval or refund is claimed to have occurred. Missing evidence stays missing, a pending review is not approval, and an offered option is not execution.
