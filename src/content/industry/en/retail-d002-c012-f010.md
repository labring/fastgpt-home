# Warehouse picking and packing: citation tracing for after-sales questions

## What the documents look like

Outbound order fulfillment in warehouse picking, checking, and packing differs from inbound receiving and shelving. This category handles order dispatch, not supplier arrivals. The working records come from a WMS, an order system, an electronic waybill platform, and weighing equipment. The daily documents are wave picking lists, checking records, waybills, and packaging material sheets. Records update per order or at an hourly cadence.

For after-sales questions, a reply is useful only when it can be tied to a specific document and a specific field. Citation tracing is the step that keeps an answer anchored to the wave picking list, the checking record, the waybill, or the packaging material sheet instead of to a general impression of the order. A customer asking about a missing item, a wrong item, or a damaged parcel needs an answer that points to the record that carries the relevant field.

## Constraints at the citation tracing step

The knowledge base search node can select one or more knowledge bases that share the same vector model. Its output is an array of citations, and that array may have length zero. An empty array still lets the downstream chain run through. The minimum relevance value takes effect only under semantic search or when result reranking is used. It is a filter threshold. It does not act as a permission filter or an entity isolation boundary, so it cannot be relied on to keep unrelated orders or unauthorized records out of a reply.

Hybrid search combines multiple recall paths through RRF. Reranking requires a rerank model and must be enabled according to the configuration. Image retrieval requires an image input and the corresponding model capability. Knowledge bases built on different vector models cannot be associated together. Before any association, compare the vector model identifiers, exclude the ones that do not match, and record what was actually observed.

Hypothetical drill sample: a warehouse wave picking list dated 3 June 2025 shows order A picked complete. The checking record shows an actual dispatched quantity of 2 items. The packaging material sheet shows a medium carton was used. The waybill has been printed, but the weighing equipment has not returned a weight. A draft sentence reads, "This order has completed checking and packing and can be dispatched." This sentence lacks the weight return and the outbound handover evidence, so it is unsupported. The evidence gap should be recorded rather than filled in.

The minimum relevance starting value of 0.3 is chosen for this drill because it is a mid-range threshold to compare against 0.5; it is not an official default. The citation limit of 2000 tokens is chosen to compare against 1000 for completeness of the returned source text; it is not an official default. Both are hypothetical starting points for comparison, not documented platform values.

## Three common errors

1. Treating minimum relevance as a permission or entity filter. Input: an after-sales question about one customer order. Compare: the retrieved citations against the authorized order scope. Observable result: citations from unrelated orders appear in the reply, which shows the threshold did not perform an isolation function.
2. Describing RRF as a switch that can be turned on. Input: a hybrid search configuration. Compare: the documented description of RRF as a fusion step against the settings shown on the page. Observable result: a page control labelled as an RRF switch appears, which does not match the documented behavior.
3. Treating a retrieval hit as an authorized action. Input: the draft sentence "can be dispatched." Compare: the checking record and the outbound handover evidence. Observable result: the weight return is absent, so the sentence is judged unsupported rather than confirmed.

## How to verify the setup

1. Input the hypothetical sample source text and the draft sentence. Compare the checking record quantity, the packaging material sheet, and the waybill fields against the reply. The condition is met when the reply points to each source item and explicitly notes the missing weight return.
2. Input a paper empty array as the citation output. Compare the downstream node design against that input. The condition is met when the chain runs through without error and the empty array is handled as a valid input.
3. Input two knowledge bases on different vector models. Compare the vector model identifiers. The condition is met when the non-matching base is excluded and the observation is recorded. Do not infer missed recall or redundant results from this comparison.

These checks describe expected outcomes for a paper drill. They do not report a completed test, an approval, or a deployment. Where a field is not provided in the source documents, the correct state remains unknown and the gap is recorded.
