# Convenience fresh-food orders: citation tracing for after-sales questions

## What the documents look like

Convenience-store fresh food is ordered by the store at high frequency against short shelf lives. Each day or each shift produces an order sheet, a loss report, a near-expiry handling sheet and a temperature record. These four materials are the working set. POS sales, the headquarters ordering system, store inventory and cold-chain temperature records each capture a different fact, so a missing item removes the basis for an answer. Citation tracing requires that every statement in an after-sales reply map back to a checkable line in the original text. Fluent wording does not replace source evidence.

## Constraints at the citation tracing step

The knowledge base search node can associate one or more knowledge bases that share the same vector model, and it outputs citations as an array whose length may be zero. An empty array still lets the output path run through; it does not mean the workflow has failed and stopped. Search results must be handed to the answering step, and each answer statement must be checked line by line against the cited original. A similarity value only filters low-relevance content; it does not perform permission or entity isolation. Retrieval is not authorization, and a form collecting values is not the same as business verification, approval, a database write or an external synchronization having been completed.

Hypothetical drill sample: a store submits a fresh-food order sheet on the morning shift of 10 March 2025. The original text reads "Order date 2025-03-10, item A, quantity 12, store submitted." The same day's temperature record reads "03-10 morning shift, refrigerated cabinet 4 degrees Celsius, recorder signed." The draft sentence to be judged is "This order sheet was approved on 2025-03-10 and delivery can be arranged." The original text only states that the store submitted; it does not record an approving party, an approval status or delivery authorization. The draft sentence is unsupported, and the approval evidence gap must remain open.

## Three common errors

1. Treating a retrieval hit as authorization. Input the order sheet original text above together with the draft sentence, compare the fields "submitted" and "approved", and the error appears when the answer outputs an approval conclusion directly. The observable result is that the draft sentence is unsupported by the original text.
2. Treating an empty citation array as a system fault. Input a paper citation output of [] and compare whether the downstream design continues to run; if the downstream is configured to error out and stop, that conflicts with the documented behavior.
3. Associating knowledge bases that use different vector models. Input two base identifiers, compare whether the vector model identifiers match, and if they do not match while association is still attempted, the association condition is violated. Do not run a cross-model retrieval to compare missed recall.

## How to verify the setup

1. Citation-to-original check. Input the order sheet and temperature record originals above, and compare whether each citation in the answer can be found as a corresponding sentence in the original. The condition is met when the cited content agrees with the original on subject, period and field.
2. Empty-result handling check. Input a paper citation output of [] and compare whether the downstream node continues to execute. The condition is met when the downstream does not error out and records the gap.
3. Document-currency check. Input the current version and a historical version of the order sheet, and compare which version the citation source points to. The condition is met when the answer marks the version and does not treat the historical version as currently effective. These are expected check methods and no actual test is claimed.
