# Franchisee onboarding: workflow routing for after-sales questions

## What the documents look like

Franchisee training and opening coaching is a transfer of operating capability. It differs from franchise filing administration, which is a legal disclosure activity. The main data sources for this category are the training system, the supervisor app, store photographs, and the headquarters SOP library. The documents handled day to day are training sign-in sheets, opening checklists, SOP manuals, and assessment scores. These materials serve two purposes in order fulfillment and after-sales question answering. One purpose is to show that training and coaching actions took place. The other purpose is to support checking of opening materials and SOP actions. A training sign-in sheet records people and sessions. An opening checklist records materials and item status. Assessment scores record trainee results. The SOP manual provides the basis for actions. The brief gives an update frequency of per store, per month.

Workflow routing must treat these materials as node inputs and keep clear which values are collected by forms, which are grounds for manual checking, and which require a separate business interface for writing or synchronization. The form input node and the user selection node are the two documented interaction nodes relevant here. Both are user interaction nodes, can be added repeatedly, and trigger execution. When a form input node triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. The node collects the required information the user fills in and passes it to later nodes. The user selection node behaves in the same interaction pattern and, when the user makes a choice, executes the corresponding "yes" branch. The basic use is to pose a question that requires the user to decide and then design different workflow paths from the user's feedback.

## Constraints at the workflow routing step

Collected sign-in counts, checklist item status, and assessment results are form values. They do not constitute an authorization conclusion. Order writing, document backfill, and external status synchronization require a separate business interface or a later flow. The same-vector-model requirement for retrieval libraries applies only to knowledge base association. It does not extend to requiring the same model for business registration sites or other external systems. Semantic recall and relevance scores do not carry permission or entity isolation. A retrieval result cannot serve as the basis for authorized execution.

Hypothetical drill sample. On 10 June 2025, a regional supervisor in a chain training department submits an opening coaching handover request. The attached material reads as follows. The training sign-in sheet states that franchisee Wang completed cashier and inventory training on 5 June 2025, with one sign-in. The opening checklist states that store photographs have been uploaded and that the cashier machine has no marked in-place status. The assessment record states that Wang scored 78 on the cashier assessment and that the inventory assessment is not stated. The draft sentence under review is: "Wang has completed all opening coaching, and the store can enter the opening state." The request to be judged is: "Please have the workflow continue performance on the basis that opening coaching has passed."

The gap is specific. One sign-in and a score of 78 are stated values. The inventory assessment is not stated. The cashier machine in-place status is not marked. The draft sentence converts an unstated assessment and an unmarked item into completed coaching. That conclusion is not supported by the material.

## Configuration and implementation checks

| Configuration item | Type | Relation to this page's sample |
| --- | --- | --- |
| Form input node | Documented node | Collects required information such as sign-in count, checklist item status, and assessment results |
| User selection node | Documented node | Executes the "yes" branch after the user chooses whether to continue performance |
| Interaction state check | Implementation check | Confirm that triggering enters the interaction state, records state, and continues after completion |
| Output handoff check | Implementation check | Compare each form output against the inputs of later retrieval, judgment, or interface nodes |
| External action separation | Implementation check | Order writing, document backfill, and external status synchronization connect to a separate business interface |
| Hypothetical trial starting point | Hypothetical trial starting point for this page | Use one sign-in and a score of 78 as the comparison starting values, compared against the unmarked checklist item |

The reason for choosing this hypothetical trial starting point is that one sign-in and a score of 78 are values expressly stated in the sample text, while the unmarked cashier machine in-place status is a missing field. The comparison method is field-by-field checking for whether an explicit value exists.

## Three common errors

1. Treating a collected sign-in count or assessment score as an opening authorization conclusion. In the sample, one sign-in and 78 show a training and assessment record. The draft sentence "has completed all opening coaching" goes beyond the material.

2. Treating execution of the user selection node's "yes" branch as order writing completed or external status synchronized. Branch execution means the flow continues. Order writing and synchronization require a separate business interface.

3. Treating a retrieval relevance score as a permission or entity filter. Relevance does not perform authorization judgment. A retrieval result cannot replace an authorization check.

## How to verify the setup

1. Input the sample material text and the draft sentence. Compare "one sign-in, score 78, checklist item unmarked" against "has completed all opening coaching." The draft sentence writes the unstated inventory assessment and the unmarked cashier machine status as completed. Judge it as unsupported and record the evidence gap.

2. Input the request to be judged, "Please have the workflow continue performance on the basis that opening coaching has passed," and compare the form output against the inputs of later nodes. If later nodes do not receive a marker for the missing checklist item, the output handoff is incomplete and the field transfer must be completed.

3. Input an explicit paper empty result [] to check the downstream design, and observe whether the downstream handles it through an empty-result branch. An empty result does not mean retrieval necessarily returns []. It is used only to check the handoff design.
