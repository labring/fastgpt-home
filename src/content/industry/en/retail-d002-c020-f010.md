# Certificates of origin: citation tracing for after-sales questions

## What the documents look like

Certificates of origin serve import-country tariff and customs clearance purposes and are not necessarily bound by a letter of credit, which distinguishes this category from letter-of-credit document examination. The main data sources are China International Trade Single Window, CCPIT systems, enterprise production records, and customer customs clearance requirements. The everyday documents are the certificate of origin application, the commercial invoice, the packing list, and production cost materials. Data updates per shipment or in batches. The citation tracing step requires matching certificate application content against the invoice, packing list, and cost materials item by item. Judging origin rules depends heavily on the traceability of production records.

The knowledge base search node can be linked to one or more knowledge bases that share the same vector model, and it outputs citations as an array whose length may be zero. When the array is empty, that output path still completes. The citation limit is controlled in tokens. The minimum relevance value takes effect only in semantic search or when result reranking is used, and that threshold is a filter condition rather than a permission or entity isolation mechanism. Hybrid search merges multiple retrieval paths through RRF. Reranking requires a configured model and must be enabled in settings.

The following is a hypothetical drill sample.

Hypothetical drill sample: A hypothetical exporter applies for a certificate of origin for the hypothetical object "men's cotton knitted shirts" to a hypothetical import country during the hypothetical date range March 1 to March 31, 2026. The source text provided for checking reads: "The commercial invoice states the country of origin as China, invoice number HYP-2026-0312." "The packing list states a quantity of 1,200 pieces, consistent with the invoice." "The production cost materials state that cotton yarn was purchased from a supplier, and cutting and sewing were completed at a factory." One draft sentence to be assessed reads: "The goods under this certificate originate in China, the application materials are complete, please review." This sentence only restates what the materials state and the completeness status, and does not claim that a visa has been issued or that tariff preference has been granted.

## Constraints at the citation tracing step

Citation output is an array and may be empty. An empty array is not a workflow error and does not terminate the downstream path. The citation limit is measured in tokens, not in a top-k item count. The minimum relevance value applies only to semantic search or reranking, and it filters low-relevance results; it does not exclude unrelated businesses or unauthorized records. Retrieval output is not authorization. A pending review request is not approval, and an unsigned termination is not a completed termination.

The certificate of origin application, commercial invoice, packing list, and production cost materials must be matched against each other at the same subject, same period, and same field. A contradiction exists only when the same field carries clearly mutually exclusive values. A field that is not stated, or evidence that covers only a related stage, remains unsupported or pending verification. The materials needed for checking must fall within the target retrieval scope to which access rights apply, or within an explicit manual input. When they are missing, the gap is recorded.

## Three common errors

1. Treating the minimum relevance value as a permission or entity filter. The input is the sample draft sentence and the search parameters. The comparison is between the filter threshold and the business ownership of the returned records. The observable result is that after adjusting the threshold, fragments not belonging to this shipment may still be returned. Relevance does not exclude unrelated businesses or unauthorized records.

2. Treating retrieval output as authorization execution. The input is the handoff request "please review." The comparison is between the request status and three distinct facts: visa issuance, signing, and contract effectiveness. The observable result is that a pending review does not demonstrate a lack of operating permission, and it does not equal approval.

3. Treating an empty citation array as an error. The input is the paper input `[]`. The comparison is between the node output and the downstream handoff design. The observable result is that the path still completes when the length is zero, and this cannot be used to assert that the retrieval rule will necessarily return an empty result.

## How to verify the setup

1. Against the sample source text, input the three source sentences from the invoice, packing list, and cost materials together with the draft sentence. Compare whether the draft sentence only restates what the materials state. The condition is not met when wording such as "visa obtained" or "tariff preference confirmed" appears beyond the source text.

2. Against the same subject, same period, and same field, input the country-of-origin field from the invoice and the country-of-origin field in the draft sentence. Compare whether the two values are mutually exclusive. A contradiction exists only when the same field carries clearly mutually exclusive values. A field that is not stated, or evidence covering only a related stage, is recorded as pending verification.

3. Against the citation output handoff, input the paper empty array `[]` and the downstream answering design. Compare the node output with the handoff logic. The condition is met when the downstream path still completes and no fabricated source is produced. For knowledge bases using different vector models, verify the identifiers first and exclude those that do not match; do not run cross-model retrieval to compare missed recall.
