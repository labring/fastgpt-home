# Retail packaging reporting: multi-turn prompts for after-sales questions
## What the documents look like
The data for this category comes from the Ministry of Commerce reporting system, POS plastic bag sales, the procurement system, and store ledgers. It includes procurement ledgers, sales vouchers, semiannual reports, and self-discipline commitments. Daily updates and semiannual reporting coexist, so prompts must state which materials are being used and what time range applies, avoiding any mixing of the two.

## Constraints at the multi-turn prompts step
Assume a drill sample: an excerpt from a supermarket store’s “Plastic Bag Procurement Ledger” reads, “From March 1 to March 31, 2025, this store purchased 12,000 medium shopping bags and 6,000 large shopping bags; the supplier is Factory A, and the delivery note number is A-0331.” A draft “Semiannual Report” reads, “In the first half of 2025, this store’s plastic bag usage decreased compared with the same period last year.” The sentence to be judged is, “According to the ledger, this store purchased 18,000 plastic bags in March, and it is confirmed that usage declined in the first half of the year.” The objects to check are the original text of these two materials and the drafted sentence.

Prompts must specify which categories are being relied on among the procurement ledger, sales vouchers, semiannual report, and self-discipline commitment, and must state that no answer can be given when evidence is missing. For continued sessions, the session is retrieved from the database and the last message is treated as the user question; a new session does not use context and relies entirely on the passed-in messages. Question optimization checks referent resolution during continuous knowledge-base dialogue, and whether short questions apply must be checked in practice. The model’s maximum context and reply limit must be checked, and long documents combined with follow-up questions must be tested. The reply format is chosen according to downstream handling; when json_schema is selected, the corresponding format requirements must be filled in and the returned structure verified.

In the sample, the drafted sentence directly equates ledger procurement volume with usage volume and connects March single-month data to a first-half conclusion. Both points exceed the valid scope of the original materials. The ledger records procurement quantity and supplier, while the semiannual report draft gives only a trend judgment and no verifiable numerical value. The existence of materials does not mean submission has been completed, a draft does not mean it has been submitted, and a procurement record does not mean environmental review has passed.

## Three common errors
1. Writing the procurement ledger quantity directly as usage volume. The ledger contains only procurement quantity, supplier, and delivery note number, not usage volume; the drafted sentence should be compared with the ledger fields, and if unsupported, this should be recorded.
2. Treating the semiannual report draft as an already submitted report. The draft gives only a trend judgment, with no submission status, date, or receipt; it should be compared to see whether a submission action and recipient are stated, and any absence should be recorded as pending verification.
3. Treating historical messages in a continued session as the basis for the current question. In a continued session, the last message is the user question and the rest are ignored; the actual context brought in should be compared with the current question to confirm that the answer is based on the current input.

## How to verify the setup
1. Input the original text of the two materials in the above hypothetical sample and the drafted sentence. Compare “18,000 bags” in the drafted sentence with the sum of 12,000 and 6,000 in the ledger original text; if the values match, that part can be verified. Compare “usage declined in the first half of the year” with the original text of the semiannual report draft; because the draft gives only a trend judgment and no usage figure, record that part as unsupported.
2. Input a continued-session request with chatId as a non-empty string and the last message in messages as “How many bags were purchased in March?” Compare the context on which the answer is based with the current question to confirm that the answer relies on the current input. Then input a request without chatId and compare whether it relies entirely on the passed-in messages.
3. Input a question involving submission status and compare the answer with whether the materials state a submission action, recipient, and receipt; when missing, record the evidence gap. If the configuration selects json_schema, check whether the returned structure meets the filled-in format requirements; if not, record the actual returned content.
