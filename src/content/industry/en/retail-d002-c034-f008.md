# Export tax rebate filings: workflow routing for after-sales questions

## What the documents look like

Export tax rebate filing for traded goods happens after the goods leave the country, and its core work is matching tax vouchers. The main data sources are the electronic tax bureau, the export tax rebate filing system, customs electronic information, and the finance ledger. The documents handled day to day are the export tax exemption and rebate filing form, the export customs declaration, purchase invoices, and foreign exchange receipt vouchers. The typical roles are finance staff at trading companies, tax accountants, and documentation clerks. These materials move in batches, and in order fulfilment and after-sales question handling the routing layer has to deal with two kinds of interaction: form collection and user selection, plus the transfer of information to later nodes once the interaction completes.

## Constraints at the workflow routing step

When the form input node is triggered, the conversation enters an interaction state and the workflow state is recorded. After the user fills in the required information and submits, the node collects the submitted form values and passes them to later nodes. The user selection node also enters an interaction state, and when the user makes a choice the node evaluates that choice and executes the corresponding "yes" branch. Interaction nodes do not perform order writes, document backfill, or external status synchronization; those actions need a separate business interface or a later process. Information obtained through retrieval or form collection does not constitute authorization to execute. During operational handover, the authorization state of materials, actions, and requests has to be kept distinct.

Hypothetical paper exercise sample: a finance staff member at a trading company raises an after-sales question handover request for one batch of exported goods. The source text supplied for checking reads: "The export customs declaration states an export date of 15 March 2024; the filing form covers the March 2024 period; the purchase invoice was issued on 10 March 2024; the foreign exchange receipt voucher shows a receipt date of 2 April 2024." The draft sentence to be assessed reads: "This batch of goods has completed foreign exchange receipt and the rebate filing can be submitted." This sample is used only for paper checking and does not indicate that any actual filing or receipt confirmation has occurred.

## Configuration and implementation checks

| Configuration item | Assumed trial starting point for this page | Reason for the choice and comparison method |
| --- | --- | --- |
| Required fields on the form input node | Export customs declaration number, filing form period | Compare field by field against the source text; a missing field does not proceed downstream |
| Branches on the user selection node | Two branches, "materials complete" and "materials pending" | Execute the matching "yes" branch per the user choice; check the branch connections |
| Interaction state recording | Use the node's interaction state as documented | Compare against the documented behaviour of recording workflow state |
| Information transfer target | A designated later retrieval or judgement node | Compare each collected value against the downstream node input |
| External action split | Order writes and status synchronization attach to a separate interface | Check whether that action is carried by a later process |

## Three common errors

1. Treating information collected by the form as authorization to execute. Input: the submitted form values. Comparison: the authorization boundary. Observable result: whether an independent business interface or approval step exists.
2. Treating the "yes" branch of the user selection node as the only execution path. Input: the user's selection result. Comparison: the node's branch connections. Observable result: whether the unselected branch is skipped.
3. Treating retrieval results as a permission or entity filter. Input: records returned by retrieval. Comparison: the target retrieval scope and access permissions. Observable result: whether unauthorized or unrelated records appear.

## How to verify the setup

1. Using the hypothetical sample above, input the three source sentences and the draft sentence, compare whether the draft sentence goes beyond the receipt status stated in the source, and observe whether the draft's claim of "completed foreign exchange receipt" forms a mutually exclusive value against the receipt voucher date for the same subject and the same period.
2. Using the same hypothetical sample, input the required form fields and the user selection branches, compare the submitted values against the downstream node input, and observe whether the collected information is passed through completely and whether branch execution matches the selection.
3. Using an explicit paper input of [] to check the empty-result handling design, compare how the downstream node handles empty input, and observe whether an unsupported automatic judgement or external synchronization action appears.
