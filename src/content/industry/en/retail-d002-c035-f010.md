# Trade returns and claims: citation tracing for after-sales questions

## What the documents look like

Trade returns and claims handle reverse logistics and liability determination after export. The working materials move among customer emails, quality inspection reports, customs system records, and insurance claim systems. Four document types form the main evidence base for order fulfillment and after-sales answers: the return agreement, the claim letter, the quality report, and the return customs declaration. Updates are irregular, once per case.

A single return shipment can involve three parallel lines at the same time: confirming the return reason, filing the return declaration, and submitting claim evidence. The version and validity scope of each material directly determine whether it can be cited in an answer. A customer email may state that an agreement was signed, while the customs declaration remains incomplete. The quality report may describe a different inspection date and a different defect from the one named in the agreement. These are separate facts carried by separate documents, and an answer that merges them without checking each source will misstate the case status.

## Constraints at the citation tracing step

Citation tracing requires that every conclusion in an answer can be traced back to a specific material. The knowledge base search node outputs a citation array, and the length of that array can be zero. When the array is empty, the output path still runs through, so downstream design must be able to accept an empty result. Linked knowledge bases must use the same vector model. Libraries with different vector models cannot be linked together; the identifier must be checked first and non-matching libraries excluded, with the actual observation recorded. Whether a retrieval result is adopted still requires manual review against the valid version of the material. A similarity score reflects only the degree of content relevance. It does not perform permission or entity isolation.

Hypothetical walkthrough sample: An after-sales staff member at a trading company receives a customer email. The body reads: "Return agreement number TR-2024-087 was signed by both parties on June 3, 2024. The agreement states the return reason is packaging damage. The return customs declaration has not yet been completed." A separate quality report states: "Inspection date for this batch of goods is May 28, 2024. Conclusion: outer carton damp and deformed." The draft sentence to be assessed is: "The return agreement for this shipment has been signed, the return customs declaration has been completed, and a claim can be submitted." Compare the draft sentence against the source text of the materials.

## Configuration and implementation checks

| Configuration or check item | Purpose on this page | How to check |
| --- | --- | --- |
| Linked knowledge bases | Limit the searchable scope of return and claim materials | Verify selected knowledge bases and material versions; exclude libraries with different vector models |
| Search mode | Choose semantic, full-text, or hybrid search by material type | Number and reference queries favor full-text search |
| Citation limit | Control the length of cited content per search | Starting point for this hypothetical trial is 2000 tokens, chosen to cover agreement and report excerpts; compare against the default and adjust |
| Minimum relevance | Filter low-relevance results | Takes effect only in semantic search or after reranking; does not perform permission filtering |
| Question optimization | Complete references in multi-turn follow-ups | Decide whether to enable based on actual effect; adds one model call |
| Citation content output | Carry the citation array to the answer step | Check each answer sentence against cited source text; confirm downstream design when the array is empty |

## Three common errors

1. Treating a retrieval hit as an authorization basis. Retrieval returns relevant content only. Agreement signing, claim submission, and customs declaration completion are separate facts and must each be checked against source text. Check action: input the draft sentence and the source text, compare whether "signed" and "completed" appear in the same field and same period. If the draft sentence contains "customs declaration completed" while the material does not state it, that portion is unsupported.

2. Treating minimum relevance as an entity or permission filter. This value takes effect only in semantic search or after reranking. It does not exclude unrelated business or unauthorized records. Check action: use the same question to search two different knowledge bases, compare whether returned content includes materials beyond the target scope. If it does, relevance does not perform an isolation function.

3. Treating an empty citation array as a process error. The node output length may be zero, and the path still runs through when the array is empty. Check action: use the explicit paper input [] to check the downstream node design, confirm whether downstream handles the empty result. Do not claim that a fictional rule search will always return [].

## How to verify the setup

1. Input the customer email source text and the draft sentence from the hypothetical sample. Compare whether "return agreement signed" and "return customs declaration completed" are both stated in the same material. If the material states only the signing, the "completed" portion of the draft sentence is unsupported and the evidence gap should be recorded.

2. Input the number TR-2024-087 as a search term. Compare whether the citation content returned by full-text search and by semantic search contains the source text of that number. If full-text search hits and semantic search does not, record the difference between the two modes. Do not guarantee a first-hit result or full recall.

3. Input an empty citation array [] to the downstream answer step. Compare whether downstream accepts it normally and outputs a pending-verification notice. If downstream errors or outputs a definitive conclusion, the empty-result handling design needs adjustment. Actual behavior depends on observed operation.

This page addresses only trade returns and claims, order fulfillment and after-sales answers, and citation tracing. At operational handover, the authorization status of materials, operations, and requests must not be confused with retrieval or form submission. Retrieval and forms collect values; business verification, approval, database writes, and external synchronization require their stated downstream implementation.
