# Multi-warehouse inventory: shared access for after-sales questions

## What the documents look like

Multi-warehouse split fulfillment occurs at the order routing stage and determines which warehouse ships an order. This differs from courier handover, which happens after routing. The data sources for this category include WMS, OMS, ERP inventory, and platform inventory interfaces. The daily documents are split-fulfillment rules, inventory synchronization tables, transfer orders, and shortage alerts. In order fulfillment and after-sales question handling, the sharing and embedding feature concerns what an external collaborator sees and can trigger after receiving a no-login window link. The link identifier itself only opens a conversation. It does not act as business authorization for split-warehouse operations or inventory writes.

The update frequency of these documents does not change the behavior of the sharing feature. If mentioned, the supplied brief states daily and hourly updates; no batch synchronization, full synchronization, real-time, or transaction-triggered mechanism follows from that.

## Constraints at the shared access step

The no-login window is created under Application Details, Publish Channel, No-login Window. The system generates a complete link that is copied for use. The configurable parameters include name, expiration time, QPM, point cap, identity verification, real-time running status, viewing reference snippets, viewing full reference text, and downloading or opening the source original. Some parameters are supported only in the commercial edition. The identity verification root address receives POST requests. Initialization, conversation start, and conversation end each send a request to the corresponding endpoint. The system checks whether success is true to decide whether the user may continue. The uid must be returned and must not contain specific characters and must not exceed 255 bytes in length. The anonymous localId depends on the same device and same browser, and only the most recent 30 days and 20 records can be pulled. The share link carries only the conversation entry point. Split-fulfillment rule changes, inventory synchronization table updates, transfer order execution, and shortage alert handling all require their corresponding downstream system implementations. Retrieval and form collection do not constitute authorization.

Hypothetical paper exercise sample: A supply chain planning team writes on a paper handover sheet — the split-fulfillment rule document is marked "East China warehouse priority, applicable from March 1, 2025 to March 31, 2025"; the inventory synchronization table is marked "sellable inventory field updated daily"; the transfer order is marked "pending review." The handover request reads: "Please send the no-login window link to regional operations, and the recipient can directly modify the East China warehouse priority after opening it." The operating permission involved in this request is not stated in the materials.

The numeric starting point is used only for this paper exercise. April 30, 2025 was chosen because the handover sheet validity range ends on March 31, 2025, and a comparison is needed to see whether the link covers the handover period. QPM and point cap have no provided values and remain pending.

## Three common errors

1. Treating the no-login window link identifier as authorization for split-warehouse operations. The input is the handover request text. The comparison target is whether the materials state the permission to modify East China warehouse priority. The observable result is that the materials only state "pending review" and a validity range, and do not state the operating permission, so the request remains unsupported.

2. Treating a success return from identity verification as a successful inventory write. The input is the authentication interface response. The comparison target is whether the response contains inventory fields or a write result. The observable result is that the official response contains only success, message, msg, and data.uid, and does not contain an inventory write result, so the inventory change still requires downstream implementation.

3. Treating the anonymous localId boundary of 30 days and 20 records as cross-device session assurance. The input is the share link usage record. The comparison target is whether the same device and same browser are used. The observable result is that switching devices or clearing browser cache loses records, and cross-device sessions require separately designed identity management.

## How to verify the setup

1. Use the hypothetical sample text to check the expiration time. The input is the handover sheet text "applicable from March 1, 2025 to March 31, 2025" and the configuration starting point of April 30, 2025. Compare the coverage relationship between the two. The condition is met when the link validity period covers the handover period; otherwise record the gap.

2. Use the hypothetical handover request to check the authorization boundary. The input is "Please send the no-login window link to regional operations, and the recipient can directly modify the East China warehouse priority after opening it." Compare whether the materials state this operating permission. The condition is met when the materials clearly state the authorizing party and scope; when not stated, record as pending verification.

3. Use the authentication interface response to check identity verification. The input is a response returning success as true and data.uid meeting the character and byte length requirements. Compare whether the user is allowed to continue. The condition is met when success is true and uid is compliant; otherwise handle according to the official prompt. Retrieval and relevance do not carry permission or entity isolation. An empty result can be checked against the paper input [] for downstream design, without claiming that a fictional rule necessarily returns empty.
