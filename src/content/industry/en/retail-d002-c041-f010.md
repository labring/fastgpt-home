# Marketplace promotions: citation tracing for after-sales questions

## What the documents look like

Platform promotion enrollment and price management centers on four working documents: the campaign enrollment form, the promotional price approval form, the inventory lock sheet, and the campaign review sheet. The data that matters is price, stock, and campaign cadence, not advertising wording. Staff calculate the lowest final price a buyer can reach, lock inventory for a campaign, and synchronize prices across platforms. These materials are cited repeatedly during order fulfillment and after-sales question handling, so a citation tracing step has to connect any stated price, stock figure, or campaign status back to the exact wording in a source document.

Two features of this category shape the task. First, promotional price approval passes through states such as pending finance review before it becomes an approved price, and the two states sit in the same field with mutually exclusive values. Second, an inventory lock sheet records a lock status that can read as submitted rather than locked and sellable. Wording that upgrades either state produces a citation that the source text does not support. The materials are refreshed weekly and per campaign; where refresh timing does not affect citation tracing, it is left out of this page.

## Constraints at the citation tracing step

The knowledge base search node can associate one or more knowledge bases that share the same vector model. Its reference output is an array, and that array length may be zero. An empty array means the search path completed without a content hit; it does not mean the workflow raised an error and stopped. The minimum relevance value is a filter threshold that takes effect only under semantic retrieval or result re-ranking. It is not a permission filter and does not separate business entities or unauthorized records. Retrieval itself is not authorization. A form that collects values is not an approval, and a submitted status is not an executed action.

Hypothetical drill sample: the source text reads, "The promotional price approval form dated 1 March 2025 (number C-0301) states: product A campaign price 89 yuan, approval status pending finance review, valid until 7 March 2025. The inventory lock sheet of the same date states: product A locked 200 units, lock status submitted, with no release condition noted." The draft sentence to be judged reads: "Product A campaign price 89 yuan has received finance approval, and the 200 units of stock are locked and sellable." This draft treats pending review as approved and treats submitted as locked and sellable. Both moves cite an unfinished state as a finished one. The source does not state who may approve the price, whether approval grants any operating authority, or any supply term, so those points stay unknown.

## Configuration and implementation checks

| Configuration item | Hypothetical trial starting point | Reason and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Promotion approval and inventory lock library | Check whether the selected libraries share the same vector model; libraries with different vector models are not associated together |
| Search mode | Hybrid retrieval | Compare against semantic retrieval alone and observe whether number-type queries reach the source text |
| Reference cap | 3000 tokens as the hypothetical starting point | Compare against a lower cap and observe whether a long approval form is truncated |
| Minimum relevance | 0.3 as the hypothetical starting point | Compare against 0.5 and observe whether low-relevance fragments enter the reference array |
| Result re-ranking | Enabled | Compare against disabled and observe whether ordering changes when candidates are numerous |
| Reference output | Passed to the answer node | Check whether each answer line corresponds to source wording, and inspect the downstream design when the array is empty |

These are implementation checks and named trial starting points, not documented defaults. The reference cap uses the documented token unit. RRF is a fusion step for combining multiple retrieval paths, not a switch to be turned on. Thinking budget is a reasoning budget and is not reused as a reference token cap. Image retrieval requires an actual image input and model capability, and re-ranking requires a re-ranking model enabled by setting; neither path runs on every request.

## Three common errors

1. Writing pending finance review as approved. Input: the approval form wording "approval status pending finance review." Comparison: the draft phrase "has received finance approval." Observable result: the status field in the draft and the status field in the source do not match.
2. Rewriting the lock status. Input: the lock sheet wording "lock status submitted." Comparison: the draft phrase "locked and sellable." Observable result: the lock status value has been changed from the source value.
3. Treating the price validity date as a supply period. Input: the wording "valid until 7 March 2025." Comparison: the draft phrase "sellable." Observable result: a validity field has been used where a supply field would be required, and no supply field exists in the source.

## How to verify the setup

1. Enter the approval form source text and the draft sentence from the hypothetical sample. Compare the approval status field. When the draft reads "has received finance approval" while the source reads "pending finance review," the draft is unsupported by the source.
2. Enter the inventory lock sheet source text and the draft sentence. Compare the lock status field. When the draft reads "locked and sellable" while the source reads "submitted," the status has been rewritten.
3. Enter the price validity wording and the draft sentence. Compare the validity field against a supply field. When the draft treats the validity date as a supply period, the fields have been mixed.

Each check compares the same subject, the same period, and the same field. Only mutually exclusive values within one field count as a contradiction. A state that is not stated, or that is supported only by evidence from a related stage, is unsupported or pending verification rather than negated or conflicting. A pending review does not show that operating authority is absent. Signing, reaching cooperation, and contract effectiveness are three separate facts. A price validity date does not state a supply period. Where the source is silent, the gap stays open.

For the empty-result path, a paper input of an empty array can be used to check the downstream design; this does not assert that any constructed query returns an empty array. When libraries use different vector models, check the identifier, exclude the non-matching library, and record the actual observation. Do not associate them and then claim a run-time outcome such as missed recall or redundant results. Retrieval checks describe what to observe and which failure branch to note, without guaranteeing a first-position hit, full recall, or an empty result for an unrelated query.
