# Marketplace promotions: retrieval for after-sales questions

## What the documents look like

Order fulfillment and after-sales answering for marketplace promotion enrollment and price management rests on four record types: the campaign enrollment form, the promotional price approval sheet, the inventory lock sheet, and the campaign review sheet. The people who work with these records are platform campaign operations staff, brand sales planners, and finance business partners. They reconcile price, inventory, and campaign timing. Source material arrives from the platform marketing backend, ERP inventory, and historical transaction prices, refreshed weekly or per campaign.

Retrieval has to preserve the version of each record. When a price complaint or a fulfillment question arrives, the answer has to trace back to the approval sheet, the lock sheet, and the execution record separately, because those are distinct documents with distinct states. The campaign enrollment form carries the campaign name, the product object, the requested promotional price, the approval status, the enrollment deadline, and the locked inventory quantity. Those fields do not collapse into one another.

## Constraints at the retrieval step

Knowledge base search treats the library as the smallest search unit. Collections exist for classification and do not change search behavior. A citation has to return to specific source text. A retrieval score does not substitute for verifying approval status.

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Libraries built on different vector models cannot be associated together. The operator checks the vector model identifier first, excludes non-matching libraries, and records the actual observation. A cross-model retrieval is not run to compare missed recalls.

Search modes include semantic search, full-text search, and hybrid search. Hybrid search merges multiple result paths through RRF. RRF is a fusion process for hybrid results, not a switch that can be turned on. Result reranking uses a ReRank model to reorder candidate text a second time; reranking requires the model and must be enabled according to settings. Image retrieval requires corresponding image input and model capability. The optional paths shown in the overall document flow diagram do not mean every request executes all of them. The citation limit controls the maximum content cited per search, measured in tokens. Minimum relevance is a filter threshold that takes effect only under semantic search or when result reranking is used; it is not the final ranking rule. Question optimization performs coreference resolution and question expansion, and it adds one model call before the formal retrieval.

Retrieval output is an array of cited content whose length can be zero; even when nothing is found, the output path still runs through. Semantic recall and relevance scores do not perform permission or entity isolation. The same-vector-model requirement for associated libraries does not extend to business registration sites or other external systems.

Hypothetical drill sample: A brand has a promotional price approval sheet during a platform major promotion. The source text reads: "Campaign name: Spring Major Promotion; Product object: Model A running shoes; Requested promotional price: 199 yuan; Approval status is Pending review; Enrollment deadline: March 20, 2025; Locked inventory quantity: 500 units." A draft sentence reads: "Model A running shoes Spring Major Promotion promotional price has been approved, fulfillment and shipping can be arranged." The task is to determine whether the draft sentence matches the approval sheet source text. The approval sheet does not state approval; it records only "Pending review." The draft sentence's statement about approval status is unsupported.

## Configuration and implementation checks

| --- | --- | --- |
| Associated knowledge bases | Check whether the libraries participating in retrieval use the same vector model | The promotional price approval sheet and the inventory lock sheet must be associable under the same vector model |
| Search mode | Compare actual recall of semantic, full-text, and hybrid search against the test question | "Pending review" in the sample is an exact term, checkable with full-text or hybrid search |
| Citation limit | Unit is token; test content completeness with actual material of differing lengths | The approval sheet entry is short, the inventory lock sheet entry is long, observe each separately |

## Three common errors

1. Treating "Pending review" as "Approved." The sample approval sheet source text explicitly records "Approval status is Pending review," while the draft sentence writes "has been approved." The two values on the same field are mutually exclusive. Pending review does not demonstrate a lack of operating authority, and it does not equal approval. When checking, compare the approval status field in the approval sheet source text against the draft sentence's statement, and record any inconsistency as unsupported.

2. Treating retrieval results as authorization to execute. Knowledge base search outputs cited content; it does not execute approval, write to a database, or trigger external synchronization. In the sample, even if the approval sheet is retrieved, that does not mean the promotional price has been approved or the inventory has been locked. Business verification, approval, database writes, and external synchronization require their stated downstream implementation.

3. Treating minimum relevance as a permission or entity filter. Minimum relevance is a 0-1 filter threshold that takes effect only under semantic search or result reranking; it does not exclude unrelated business or unauthorized records. In the sample, if approval sheets from other campaigns are retrieved, raising minimum relevance cannot isolate them. Check whether the campaign name and product object match instead.

## How to verify the setup

1. Input the sample approval sheet source text and the draft sentence, and compare the approval status field. Observe whether the retrieved cited content contains the source text "Approval status is Pending review." Satisfied condition: the field source text appears in the cited content, and the draft sentence's "has been approved" is inconsistent with the source text. Failure branch: the cited content does not contain the approval status field; record this as not recalled and do not judge the draft sentence correct.

2. Input an empty citation array [], and check the downstream design. Observe whether the output path runs through. Satisfied condition: the output path runs through and the downstream handles the empty result. This check uses the paper input []; it does not claim that a fictional rule retrieval necessarily returns [].

3. Using "Model A running shoes promotional price approval status," try enabling question optimization, and compare whether the product object and approval field are retained before and after optimization; record an optimization error when another product or field is substituted. The actual optimized text and call result remain to be tested.
