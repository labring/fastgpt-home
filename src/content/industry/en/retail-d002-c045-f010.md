# Seller ratings management: citation tracing for after-sales questions

## What the documents look like

Ratings maintenance works on consumer feedback that follows after-sales fulfilment, and it does not set the pricing decisions that promotion enrolment handles. The material for this page comes from platform experience scores, service indicators, after-sales reviews and customer service systems. The working documents are negative-review handling records, experience score breakdowns, service diagnostic reports and rectification ledgers. Updates arrive daily or weekly. This page does not derive batch synchronization, full synchronization, real-time behaviour or transaction-triggered mechanisms from that cadence. The most time-consuming steps are attributing a negative review, requesting supplementary evidence and tracking indicators after rectification. Citation source and tracing affect the credibility of the material used in all three steps.

A negative-review handling record typically carries a date, an order reference, the buyer feedback, the service actions taken and the buyer response. An experience score breakdown carries the score components for a stated period. A service diagnostic report carries the observed service problems. A rectification ledger carries the planned correction and its follow-up. These four documents are the reference material that an after-sales answer may cite, and the citation array is what a knowledge base search node returns.

## Constraints at the citation tracing step

The knowledge base search node can associate one or more knowledge bases that share the same vector model. Knowledge bases built on different vector models cannot be associated together. At this step the identifiers are checked first, and any knowledge base that does not match is excluded.

The node output is an array of citations, and the array length may be zero. An empty array does not mean the workflow has reported an error or terminated. The minimum relevance value is a filter threshold. It does not act as a permission filter or an entity isolation filter, and retrieval itself does not constitute authorization. The citation limit is measured in tokens and is a separate setting from any thinking budget; the two are not interchangeable. Optional paths shown in the overall retrieval flow, such as image retrieval and reranking, run only when the corresponding input and model capability are present.

Hypothetical paper exercise: the source text of a negative-review handling record reads: "On 12 March 2025, the buyer of order A-2031 reported that the outer packaging was damaged. Customer service called on 13 March and the call was not answered. A supplementary text message was sent on 14 March. On 15 March the buyer replied accepting a replacement shipment." The proposed draft sentence is: "The store has completed all after-sales handling for this negative review and obtained the buyer's written confirmation." The draft sentence goes beyond what the source text records. The source text contains no written confirmation material.

## Configuration and implementation checks

| Configuration or check item | Hypothetical starting point for this exercise | Reason for the choice and comparison object |
| --- | --- | --- |
| Associated knowledge bases | Select one ratings maintenance knowledge base with a single vector model | Compare its identifier against a knowledge base on a different vector model; exclude the non-matching one |
| Search mode | Semantic retrieval | Compare against the full-text retrieval path; choose by the natural-language character of review text |
| Citation limit | Tentatively 2000 tokens | Compare against the length of the sample citation source text; observe whether it is truncated |
| Minimum relevance | Tentatively 0.4 | Compare against the retrieval score of the sample negative-review record; observe whether it enters the citations |
| Citation content output | Keep the array format | Compare against the empty-array downstream design; check whether the downstream step reports an error |
| Citation display check | Compare each answer sentence against the citation source text | Compare against the three sample source sentences; mark any part that goes beyond them |

The values above are hypothetical starting points for this exercise and are not official defaults.

## Three common errors

1. Treating the minimum relevance value as a permission filter. When the same knowledge base holds records for other stores, relevance does not exclude those records. The retrieval scope must be checked separately.
2. Treating an empty citation array as a retrieval failure. The node output length may be zero. Use the paper input `[]` to check the downstream handling design.
3. Treating the phrase "written confirmation" in the draft sentence as a fact already recorded in the source text. The source text records only a text-message reply accepting a replacement shipment. That wording is not supported.

## How to verify the setup

1. Input the three source sentences and the draft sentence, then compare whether the draft sentence contains "written confirmation" that the source text does not record. If it appears, the sentence is judged to exceed the evidence range.
2. Input the identifier of the same-vector-model knowledge base together with the identifier of the different-vector-model knowledge base, then compare whether both are associated at the same time. If both are associated, the association condition is judged not to be met.
3. Input the paper empty array `[]` into the citation handling step, then compare whether the downstream step reports an error and terminates. If it reports an error, the handling design is judged not to cover the empty result. All three checks are paper comparisons and were not actually executed.
