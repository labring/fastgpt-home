# Marketplace category access: citation tracing for after-sales questions

## What the documents look like

Marketplace category access review happens before a listing goes live or a store joins a platform. The review object is the operating entity's qualifications and the chain of authorization behind the brand. The documents handled day to day include the business license, trademark registration certificate, brand authorization chain, and industry license. Data sources named in the brief include platform recruitment pages, the national enterprise credit information publicity system, trademark office data, and license systems. These materials are updated irregularly, and each onboarding round requires collecting and checking them again.

In the order fulfillment and after-sales question-answering scenario, a service or operations person answers buyer follow-up questions about where a qualification comes from. A typical question asks whether a brand authorization covers the current store, or whether a license is still within its valid period. The answer rests on citation content returned by knowledge base search. That citation content is output as an array, and its length may be zero. The search scope is limited to the selected knowledge bases, and only knowledge bases sharing the same vector model can be associated together.

## Constraints at the citation tracing step

The dataset search node outputs a citation array. An empty array still passes through the output path and does not by itself mean the workflow has errored out and stopped. The answering step receives these citations and needs to check, item by item, how the drafted answer corresponds to the cited source text.

The citation upper limit controls how much content a single search may cite, measured in tokens. The minimum relevance value is a number from 0 to 1 and takes effect only in semantic retrieval or when result reranking is used. That threshold filters low-relevance results. It does not act as a permission filter or an entity isolation filter. Retrieval does not constitute authorization, and it does not verify whether a material is authentic.

Hybrid retrieval merges multiple result paths through RRF, and a rerank model performs a second ordering of candidate text. These processes affect the ordering of citation content. They do not change the facts of whether a material is valid or whether an authorization covers a given scope. The currency of a document needs a separate check. Testing a source with both a current version and a historical version is one way to observe this; whether a citation is adopted still depends on review against the effective version.

## Configuration and implementation checks

The items below center on one hypothetical drill sample. Sample material text: "Party A, XX Brand Management Co., Ltd., authorizes Party B, XX E-Commerce Co., Ltd., to operate the XX category on the XX platform, with an authorization period from January 1, 2025 to December 31, 2025. This authorization letter is limited to the above platform and category." Draft sentence to be judged: "This brand authorization covers all categories of this store and is valid long term."

| Associated knowledge bases | Select the qualification access material library | Check the vector model identifier of each selected knowledge base; only identical vector models can be associated together |
| Search mode | Hybrid retrieval | The authorization letter contains entity names and dates, so semantic and full-text recall both carry value |

## Three common errors

1. Treating a retrieval hit as authorization confirmation. The input is the authorization-letter citation returned by retrieval. The comparison object is the phrase "covers all categories and is valid long term" in the draft sentence, while the source text states only the XX category and an end date of December 31, 2025. The observable result is that the draft sentence and the source text disagree on two fields, category scope and term, and the draft sentence must be marked as unsupported.

2. Using minimum relevance in place of a permission filter. The input is one low-scoring citation. The comparison object is whether the current operator has the right to view that material. Minimum relevance affects only whether the item is returned; it does not judge viewing permission. The observable result is that even when the score passes, permission still requires a separate check.

3. Treating an empty citation array as a retrieval failure. The input is the explicit paper input `[]`. The comparison object is the downstream node's handling design. Citation content length may be zero and the output path still passes through. The observable result is whether the downstream, on receiving an empty array, displays "no citation retrieved" as designed instead of entering an error branch.

## How to verify the setup

1. Input the authorization-letter source text and the draft sentence from the hypothetical drill sample, then compare the category scope and term in the draft sentence against the corresponding fields in the source text. The expected observation is that the differences between "all categories" and "the XX category," and between "valid long term" and "to December 31, 2025," can be pointed out, and the unsupported conclusion is retained.

2. Input two knowledge bases whose vector model identifiers differ, then compare whether they are allowed to be associated together. The expected observation is that, after checking identifiers, the non-matching one is excluded, no cross-model retrieval is performed, and the actual observation is recorded.

3. Input the explicit paper empty array `[]`, then compare the downstream node's handling of an empty citation. The expected observation is that the output path passes through and the downstream handles the empty citation as designed, without treating the empty array as workflow termination.

This page addresses only marketplace category access, order fulfillment and after-sales question-answering, and citation source tracing. When operations hands work over, the authorization state of which materials, actions, and requests are in play cannot be treated as authorization execution through retrieval or a form.
