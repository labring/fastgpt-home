# Parcel labels and handoffs: multi-turn prompts for after-sales questions

## What the documents look like

Handoff between warehouse and carrier happens at the point a parcel leaves the warehouse, and the carrier scan is the event that assigns responsibility. The working materials for this category are electronic waybills, handoff manifests, pickup scan records and exception parcel registers. They come from the courier system, WMS shipping and carrier billing, and they refresh per batch and per day. Refresh cadence does not change what this page's feature does; what matters is whether each batch states the subject, the object and the status clearly.

For multi-turn prompts, this means the model must keep three states apart when it answers questions about shipping delays, lost-parcel disputes or false shipment claims. A printed waybill, a parcel listed on a handoff manifest, and a parcel that has appeared in a pickup scan record are three distinct fields. One field cannot stand in for another.

A second relevant fact is that the same batch may carry several document types whose status vocabularies differ. The handoff manifest records what the warehouse released; the pickup scan record records what the carrier accepted; the exception register records what was flagged. A draft answer that merges these into one status will misstate the parcel's position.

## Constraints at the multi-turn prompts step

Prompts must state the document scope, the answering task and the handling of missing evidence, so the model does not fill business facts on its own. History handling must be checked against the context actually carried in, distinguishing a new session from a continued one. Question optimization is checked only in knowledge-base continuous-conversation scenarios for pronoun resolution and question expansion; short questions are not assumed to fit in every case. Model and length settings must be checked against the model's supported context and reply settings. Reply format follows downstream consumption; when json_schema is selected, the format requirement is filled in and the returned structure is verified.

Retrieval and similarity do not carry authorization or entity isolation. The quoteList and score returned by knowledge-base search are recall results; they do not indicate that a specific parcel, a specific carrier branch or a specific authorized record is available. The interactive value returned by an interaction node is a display configuration containing only type and params; a form collecting values does not mean the business step has been verified, approved or written.

Hypothetical drill sample

Source text for review (hypothetical): "Electronic waybill SF-0001 was printed on 2025-03-01. The handoff manifest lists this waybill as handed to carrier branch A. Pickup scan records as of 2025-03-02 do not show SF-0001. The exception parcel register has no entry for this waybill."

One draft sentence to be judged: "SF-0001 has been picked up by branch A and is in normal transit."

Judgment: the materials support "printed" and "listed on the handoff manifest." The pickup scan record does not show the waybill, and the exception register has no entry. The draft sentence states a status that is not supported as having occurred, so it cannot be used. The unsupported part remains pending verification.

## Configuration and implementation checks

| Configuration item | Value or check on this page | Basis and comparison method |
| --- | --- | --- |
| AI model | Select a model whose maximum context fits the intended conversation length | The configuration dialog shows maximum context and tool-calling capability; compare against this page's long-conversation need |
| Memory turns | Starting value for this hypothetical trial is a small number of turns | Customer-service and knowledge-base applications typically keep a small number of history turns; compare against a new-session input that passes no history |
| Reply cap | Enable and adjust to the needed answer length | A low setting truncates the reply; compare against the length of this page's draft sentence |
| Temperature | A low value | Customer service and knowledge-base Q&A suggest a low setting; compare against divergent writing scenarios |
| Reply format | Default for ordinary Q&A | Switch to json_schema only when a downstream node reads a fixed structure, and fill in the format requirement |
| Multimodal recognition | Decided by model capability | The dialog shows only the media types the model supports; image retrieval requires a corresponding image input and model capability |

## Three common errors

1. Writing "listed on the handoff manifest" as "picked up." The input is the source text and the draft sentence; the comparison is against the pickup scan record field; the observable result is that the draft sentence still claims pickup while the scan record does not show the waybill.
2. Treating a knowledge-base search score as an authorization filter. The input is the quoteList and score; the comparison is whether the materials contain an authorization field; the observable result is that score level has no correspondence with authorization status.
3. Treating an interaction node's form collection as a completed business step. The input is the type and params of interactive; the comparison is whether the materials contain a verification, approval or write record; the observable result is that form values exist while the downstream business status has not changed.

## How to verify the setup

1. Enter the hypothetical sample's source text and draft sentence. Compare whether the draft sentence matches the pickup scan record field. The condition is met when the draft sentence is judged unsupported and the gap is preserved.
2. Enter an explicit paper-based empty result []. Compare whether the downstream design branches on the empty result. The condition is met when the downstream does not produce an invented entry.
3. Enter the library identifiers of two different vector models from the same batch of materials. Compare whether the identifiers match. The condition is met when mismatched identifiers are excluded and the observation is recorded, without running a cross-model retrieval to compare missed recall.
