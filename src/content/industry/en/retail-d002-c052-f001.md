# Pinduoduo seller campaigns: after-sales questions with HTTP integrations

## What the documents look like

For after-sales questions in Pinduoduo seller campaigns, this page examines FastGPT HTTP integrations. Campaign-service queries separate enrollment, platform acceptance and order fulfillment. The examples are hypothetical.

## Constraints at the HTTP integrations step

Suppose campaign material contains enrollment submission without platform review, supplier wording covers one package, and an order summary remains in preparation. Check product, campaign and order correspondence against real interface documentation, comparing earlier-node outputs with request parameters. Inject authentication safely. Successful authentication establishes neither platform approval nor store handling authority. No price, sales quantity or actual review finding is invented.

## Configuration and implementation checks

| Campaign-service HTTP | Hypothetical state | Check |
| --- | --- | --- |
| Enrollment | Submitted/unreviewed | Platform acknowledgment |
| Package scope | Specified package | No all-variant claim |
| Order preparation | No dispatch evidence | Logistics record |
| Response coverage | May be name only | Actual source body |
| External operation | Separate handling | Authority and receipt |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Request address and method` | The request address and method follow the external contract. |
| `Params and Headers` | Inspect parameters, headers and authentication separately. |
| Body | Where a JSON body is used, validate its structure against the external contract. |
| `Variable references` | Variables can come from global, system or upstream outputs. |
| `Debug identity fields` | Test mode lacks chatId and responseChatItemId. |

## Three common errors

Enrollment reported as approved needs a platform acknowledgment checked. Package-specific wording applied to every variant needs product scope checked. Preparation reported as dispatched needs logistics evidence checked. These concern campaign stage, product range and fulfillment, using material from the current matter.

## How to verify the setup

Retain request and raw return, confirming that response coverage includes source text rather than a campaign name alone. Retest the same question after review or logistics evidence arrives, leaving other gaps unresolved. Campaign configuration, product changes and shipment operations require business interfaces, authority and receipts. The HTTP node transfers information under its contract without guaranteeing an external system completed an action. Link enrollment material to the current item variant and preserve only the fulfillment stage actually stated.
