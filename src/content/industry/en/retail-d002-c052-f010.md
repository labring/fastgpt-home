# Pinduoduo seller campaigns: citation tracing for after-sales questions

## What the documents look like

Pinduoduo low-price campaign store operations revolve around campaign resource slots, campaign inventory, and refund-rate fluctuation. The daily materials named in the brief are the campaign registration form, the product cost calculation sheet, the after-sales refund order, and platform in-site messages. Order fulfillment and after-sales question handling depend on tracing each statement in a draft reply back to one of these source documents.

Three features of this category shape the tracing work. First, campaign price and campaign inventory are recorded on the registration form, while unit cost is recorded on a separate calculation sheet, so a single reply may need to reconcile two documents with different authors and dates. Second, refund orders carry a status field, and a status such as pending review is not the same fact as a completed refund. Third, the brief states a daily and per-campaign update frequency; this page only uses that frequency for currency checking of the cited version and does not infer any batch synchronization, full synchronization, real-time mechanism, or transaction-triggered mechanism.

The documents are used here for source tracing, not for authorization. Retrieval returns content; it does not grant permission and does not constitute approval.

## Constraints at the citation tracing step

The knowledge base search node can select one or more knowledge bases that share the same vector model, and it outputs cited content as an array whose length may be zero. A zero-length array means the output path still runs; it does not mean the workflow has errored and terminated. Similarity score is a relevance number used for filtering and ordering. It does not act as a permission filter or an entity filter, and it cannot be used to decide whether a record belongs to a particular store or has been approved.

Hybrid search merges multiple retrieval paths through RRF, and Rerank performs a second ordering when a rerank model is available and the setting is enabled. Image retrieval requires image input and matching model capability. These paths are not executed on every request. The documented flow diagram lists optional paths; listing them does not mean each request runs all of them.

Hypothetical paper exercise sample. A campaign operator retains three source sentences. Sentence one: "The campaign registration form states: campaign price 9.9 yuan, registered quantity 2000 units, registration deadline 10 June 2025." Sentence two: "The product cost calculation sheet states: unit cost 8.5 yuan, calculation date 5 June 2025." Sentence three: "The after-sales refund order states: order number A0001, refund reason out of stock, refund status pending review." The draft sentence to be judged is: "This order has completed the refund at the campaign price, and the cost calculation has been confirmed as showing no loss." This draft sentence asserts two facts: that the refund is complete, and that the cost has been confirmed. The materials show only a refund status of pending review, and the cost sheet carries no confirmation conclusion. Both assertions are unsupported.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | Reason and comparison object |

| Associated knowledge bases | Select only knowledge bases sharing the same vector model | Compare against the search node requirement that associated knowledge bases share the same vector model, and exclude bases with a different vector model |
| Search mode | Hybrid search | Compare against semantic search and full-text search; identifiers and monetary fields need keyword hits |

| Minimum relevance | Starting point set to a low value | Compare against the no-results-found symptom; first confirm whether the data has finished training |
| Result rerank | Enabled by setting, requires a rerank model | Compare against the number of candidate results; second ordering applies when candidates are numerous |
| Citation handoff | Retrieval output passed to the answering step for item-by-item checking | Compare against the source text cited in the answer, checking subject, object, period, and field |

## Three common errors

1. Treating a pending-review refund order as a completed refund. Input: a refund order whose refund status is pending review, together with the draft sentence "has completed the refund." Compare the value of the refund status field. Observable result: the draft sentence does not match the source text and must be recorded as unsupported.
2. Treating a similarity score as a permission filter. Input: a low-scoring record returned by retrieval, together with the draft sentence "this record belongs to this store." Compare the record ownership field against the retrieval score. Observable result: the score supplies no ownership information, and ownership must be checked separately.
3. Treating the cost calculation sheet as a confirmed cost. Input: a calculation sheet containing unit cost and calculation date, together with the draft sentence "the cost calculation has been confirmed as showing no loss." Compare whether a confirmation conclusion field exists in the sheet. Observable result: that field is not stated, and the item must be recorded as pending verification.

## How to verify the setup

1. Use the three source sentences as input. Compare each citation in the answer against the source text on subject, object, period, and field. The condition is met when each citation can be traced back item by item and the answer adds no conclusion absent from the source text.
2. Use the draft sentence "This order has completed the refund at the campaign price, and the cost calculation has been confirmed as showing no loss" as input. Compare the refund status field and the cost confirmation field. The condition is met when both points are recorded as unsupported and the evidence gap is logged.
3. Use a paper input of an empty citation array to check the downstream handoff design. Compare whether the downstream step continues to execute when the array is empty. The condition is met when the output path runs without an error; this observation does not mean that a fictional rule search will necessarily return an empty array.
