# Channel receivables: HTTP integrations for after-sales questions

## What the documents look like

Channel receivables collection begins after credit sales, so the working core is credit exposure and cash recovery rather than matching buyers with sellers. The records that matter here come from finance systems, bank receipts, distributor orders and sales contracts. The documents handled day to day are the receivables aging table, dunning letters, credit agreements and shipment freeze notices. In the order fulfillment and after-sales question stage, staff match aging figures, remaining credit and shipment freeze status against the values sent to an external service.

The HTTP module sends a request to a configured address and returns parsed values to the workflow. It does not perform credit decisions, approvals or database writes; those actions belong to a downstream service. The aging table, dunning letter, credit agreement and freeze notice are the material identities this page works with. Update cadence is weekly and monthly at the business level, and that cadence does not by itself define any synchronization mechanism inside the integration.

## Constraints at the HTTP integrations step

The HTTP module sends a request to a target address. Params are mainly used for path parameters in GET requests, Body mainly for POST and PUT requests, and Headers carry special information. URL, Params, Body and Headers can all reference variables through `{{}}`. Variables come from global variables, system variables and outputs of preceding nodes. System variables include appId, chatId, responseChatItemId, variables, cTime and histories; histories defaults to at most 10 items and its length cannot be changed. chatId and responseChatItemId do not exist in test mode.

Response values are not the interface response itself. Each configured key describes how to extract a value from the response using JSON path syntax, and extraction follows JavaScript object access rules. Since FastGPT v4.6.8, when the output type is set to string, the value at the corresponding key is converted into a JSON string. This allows an HTTP output to feed text processing and then an AI dialogue node.

On the conversation API side, the appId and runtime fields of FastGPT are not generic parameters of an external business service. Key usage follows the documented rules: `body.appId` is recommended when calling `chat/completions`, and `Authorization: Bearer <apiKey>-<appId>` is supported for OpenAI SDK compatibility. The `model` and `temperature` fields passed in are ineffective because the orchestration decides them. A `detail=true` response does not return actual consumed tokens; the `tokens` values inside `responseData` must be calculated manually if needed. The `authProxy` option requires the team owner to enable it when creating or editing the key, and the proxied identity still needs permission on the target app and conversation.

Hypothetical paper exercise sample. The material text reads: "The credit agreement states that distributor A has a credit limit of 500,000 yuan and a payment term of 30 days. As of 20 March 2025, the receivables aging table shows distributor A has an overdue amount of 120,000 yuan. The draft shipment freeze notice states that shipment to distributor A is proposed to be suspended, and the approval column is empty." The sentence to be assessed is: "Distributor A has exceeded its credit limit and this shipment freeze has taken effect." Assessment requires evidence on the same subject, the same period and the same field. The empty approval column means the existing draft lacks an approval record; the actual approval stage and the effective status of the freeze remain to be checked, and neither a pending review nor a rejection may be inferred.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | Comparison method and basis |
| --- | --- | --- |
| Request address | External credit query service address containing a `{{}}` variable placeholder | Address and method chosen from the external interface document; the address may reference a provided variable |
| Headers authentication | Authorization uses Bearer plus a credential variable | Credential injected through secure configuration; no actual value is written into public samples |
| Body structure | Distributor identifier and period checked against the real credit agreement | FastGPT appId is not treated as a generic required field of the external service; fields and types remain to be checked |
| Variable references | Reference the aging amount and credit limit from preceding node outputs | Global variables, system variables and preceding node outputs are all permitted; actual passed values are checked item by item |
| Response value parsing | Configure keys to extract credit balance and freeze status fields | Extraction follows JSON path; when the output type is string, the value is converted into a JSON string |
| Debug identity | chatId and responseChatItemId are empty in test mode | The empty value is a documented test-mode difference and is not treated as a business fault |

## Three common errors

1. Treating the response value parsing configuration as a switch that makes the interface return a value. The input is the interface response JSON, the comparison object is the configured key against the JSON path extraction result, and the observable result is that the corresponding output is empty when the key does not match. The error is assuming that configuring a key means the interface has returned that field.

2. Treating a form submission at an interactive node as a completed business approval. The input is the distributor identifier and amount collected by the form, the comparison object is the approval column status against the submission record, and the observable result is that the approval column remains empty. Forms collect values; approval and database writes need a downstream implementation.

3. Inferring a fault from the absence of chatId in an external response. The direct check is the node running mode and the source of the system variable; in test mode the variable does not exist per the documentation. What an external response should contain is decided by the credit interface contract, not by the FastGPT system variable list.

## How to verify the setup

1. Using the sample above, take the 500,000 yuan limit, the 120,000 yuan overdue amount and the draft freeze notice. Check total credit usage, overdue balance and evidence that the freeze has taken effect, as three separate items. The 120,000 yuan is not the total usage; total usage is not given, so whether the limit has been exceeded cannot be judged. The empty approval column does not show that no approval was given, and the basis for the freeze taking effect is missing. Both claims remain to be checked.

2. For one HTTP request, the input is a response value parsing configuration with a key set. Compare the interface response JSON with the extraction result. Confirm that when the key matches, the output agrees with the response field, and that when the key does not match, the output is empty and the gap is recorded. Do not infer a cause for an interface error from an empty output.

3. For one interactive node form submission, the input is the distributor identifier and amount collected by the form. Compare the submitted values with the approval column status. Confirm that the approval column is still empty before the form values reach any downstream step. Business approval and database writes are actions that require a separate system implementation and are not completed by the form submission itself.
