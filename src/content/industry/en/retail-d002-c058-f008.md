# Fresh-food supplier claims: workflow routing for after-sales questions

## What the documents look like

Fresh-food supplier claims pursue responsibility for quality at arrival. They do not handle natural in-store shrinkage, and that boundary defines which materials belong in this workflow. The main data sources are the quality inspection system, WMS receiving records, supplier contracts and financial reconciliation. Day-to-day documents include quality exception sheets, photo evidence, deduction notices and claim reconciliation statements.

Photo evidence and the quality exception sheet determine whether a deduction calculation can stand. The deduction notice and the claim reconciliation statement determine whether both sides cite the same basis during negotiation over replacement goods or compensation. Data updates on two rhythms: per batch and monthly. The workflow routing on this page covers how interaction nodes collect and pass these materials. It does not cover internal writes into the quality inspection system or WMS.

Because the underlying claim depends on batch-level evidence, the routing step must keep the batch identity, the exception description and the photo evidence reference together before any downstream node acts. Losing any one of the three leaves the request in an unresolved state.

## Constraints at the workflow routing step

The form input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution waits. After the user fills the required information and submits, the node collects the submitted form values and passes them to later nodes. The user selection node is also a user interaction node. It triggers the same interaction state and waits for the user to make a choice, then evaluates that choice and executes the corresponding branch.

Both node types only collect values and evaluate branches. Order writes, document backfill and external status synchronization require a separate business interface or a later process. The interaction state, the hidden dialog box and the state recording described in the documentation are node behaviors; no separate global switch, submission count limit or automatic judgment is documented.

Hypothetical drill sample: a batch of fresh produce arrives. The quality inspection record states: "Arrival batch A; sampling found a high proportion of wilted leafy vegetables; photographs retained." The WMS receiving record states: "Batch A received quantity matches the order; receiving conclusion is partially nonconforming." The proposed handover request reads: "Please initiate a supplier deduction for batch A based on the quality exception sheet." That request attaches no deduction notice and states no deduction amount or reconciliation period.

## Configuration and implementation checks

| Configuration or check item | Hypothetical starting point for this drill | Reason and comparison method |
| --- | --- | --- |
| Required form input fields | Batch number, exception description, photo evidence number | Compare field by field against the quality inspection record; submission is blocked while any of the three is absent |
| User selection branches | Compensation, replacement goods, route to human negotiation | Compare against the handling methods in the claim reconciliation statement; each branch must be connected |
| Interaction state recording | Workflow state recorded when the interaction node triggers | Compare against the documented interaction state behavior; no additional switch is set |
| Output handover | Form output passed to a retrieval or judgment node | Compare each output field against the downstream node input fields |
| External operation split | Deduction notice generation marked as requiring a separate interface | Compare against the documented node capability; confirm it is not completed inside the node |
| Retrieval scope check | Limited to the target retrieval scope with access rights | Compare against the actual storage location of the materials; record a gap when missing |

## Three common errors

1. Treating form submission as deduction authorization. The user filling in the batch number and exception description completes information collection only. No deduction notice has been generated, and the handover request remains pending verification.

2. Treating a user selection branch as an executed result. The user choosing compensation indicates the branch direction only. When the compensation amount and reconciliation period are not stated, that branch does not support a conclusion that compensation was completed.

3. Treating a retrieval hit as a permission confirmation. A relevance score does not constitute an entity or permission filter. Libraries using different vector models cannot be associated together; verify identifiers first and exclude non-matching records.

## How to verify the setup

1. Input the quality inspection record and WMS receiving record from the hypothetical sample above. Compare whether the required form fields cover the batch number, exception description and photo evidence number. The condition is met when all three are present and the workflow proceeds downstream only after submission; when one is missing, the workflow remains in the interaction state.

2. Input the proposed handover request. Compare whether it states the deduction amount and the reconciliation period. When they are not stated, record an evidence gap and do not judge the deduction as authorized.

3. Input an explicit paper empty result []. Compare whether the downstream node is designed to accept empty input. Do not claim that a fictional rule retrieval necessarily returns []; record only the output and failure branch actually observed.
