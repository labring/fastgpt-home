# Livestream violation appeals: retrieval for after-sales questions

## What the documents look like

Violation appeals deal with penalties that have already been issued. The material set is built around the violation notice, the livestream recording, the product qualification file, and the appeal statement. One livestream session may produce a penalty record, a replay segment, and a qualification document at the same time. These three share a subject and a time range, yet their field states are independent of each other. In the order fulfillment and after-sales question scenario, retrieval requests usually arrive through a customer service handover. The question tends to point at whether a penalty tied to a specific order affects shipment or refund. The retrieval scope therefore has to stay inside the knowledge bases the requester is authorized to access.

Material updates are irregular. Each violation produces a batch of documents. This frequency does not change the retrieval parameter choices on this page, because the search node itself does not carry a synchronization duty. Penalty status, appeal status, and fulfillment status are separate fields and cannot be derived from one another.

## Constraints at the retrieval step

The knowledge base search node can link one or more knowledge bases that use the same vector model. Bases built on different vector models cannot be linked together. The handling approach is to check the vector model identifier of each base first, exclude those that do not match, and record what was actually observed. A cross-model retrieval is not run to compare missed recalls.

A single retrieval combines text, images, semantic recall, full-text recall, question optimization, and reranking according to the input content and search parameters, then fuses the multiple result paths into reference content. The optional paths in this chain do not all execute on every request. Image retrieval requires an image input and the corresponding model capability. Reranking requires a rerank model and must be enabled in the settings. Hybrid retrieval fuses multiple result paths through RRF. RRF is a fusion process, not a switch that can be turned on.

The minimum relevance score is a filter threshold. It takes effect only under semantic retrieval or when result reranking is used, and it does not carry any permission or entity isolation duty. The same-vector-model requirement for linked bases does not extend to external systems needing the same model. Reference content is output as an array, and its length can be zero. When nothing is retrieved, the output path still completes.

## Configuration and implementation checks

Hypothetical drill sample: a store compliance staff member receives a violation notice whose original text reads, "On 12 March 2025, account A displayed product B during a livestream without a qualification page; penalty status is effective." The same batch contains a replay segment labeled "12 March 2025, account A, product B," and a qualification file for product B stating "valid until 30 June 2025." The handover request to be assessed reads: "Please confirm whether product B's current qualification covers 12 March 2025, and state whether this penalty affects shipment of order C." Order C does not appear anywhere in the material.

| Configuration item | Hypothetical starting point for this drill | Reason for the choice and comparison method |
| --- | --- | --- |
| Linked knowledge bases | Link only the base containing the three documents above | Check each base's vector model identifier first, exclude mismatches, then confirm the material is retrievable |
| Search mode | Use semantic retrieval and full-text retrieval together | Penalty date, account, and product number are exact queries; qualification validity is a semantic query; observe hits separately |
| Reference limit | Start at a value covering the body text of the three documents | The unit is tokens; test with actual material of different lengths to see whether content stays complete, then adjust |
| Minimum relevance | Label relevant and irrelevant samples first, then set the value | This value takes effect only under semantic retrieval or reranking, and is not used for permission judgment |
| Question optimization | Enable for "does this penalty affect shipment" | Used for coreference resolution and question expansion; compare the original and optimized questions and check whether the subject was altered |
| Result reranking | Enable when a rerank model is available | Reranking yields a 0-1 score used for filtering; when no model is present, record that this path did not execute |

## Three common errors

1. Treating a retrieval hit as an authorization conclusion. A retrieved penalty record shows only that the material exists. It does not show that the penalty is effective, that an appeal has been accepted, or that an order may ship. The input is the retrieval request; the comparison is between the material text and the fields named in the handover request; the observable result is whether the material states that field. When the field is not stated, record the gap.
2. Merging different fields of the same subject into a contradiction. Penalty status, appeal status, and fulfillment status belong to separate fields. A contradiction exists only when the same field carries explicitly mutually exclusive values. The input is the same field in two documents; the comparison is whether the values are mutually exclusive; the observable result is whether two mutually exclusive values appear at once.
3. Treating optional retrieval paths as always executing. Image retrieval needs an image input and the corresponding model capability. Reranking needs a model and must be enabled in settings. The input is the actual input type of this request; the comparison is against the enabled paths; the observable result is which recall paths actually ran.

## How to verify the setup

1. For the sample above, input "does product B's qualification cover 12 March 2025." Compare the validity period stated in the qualification file against the penalty date. The condition is met when the qualification file is retrieved and the date range can be checked. If it is not retrieved, record that result and inspect the chunking and the retrieval terms. A first-item hit is not presumed.
2. For "order C" in the handover request, input that request. Compare the retrieval output against material related to order C. The condition is met when the output array contains no order C content. A clearly labeled paper input `[]` can be used to check how the downstream design handles empty references. Do not claim that a fabricated rule retrieval necessarily returns an empty array.
3. For "does this penalty affect shipment," input the original question. Compare the original question against the optimized phrasing. The condition is met when the subject remains account A, product B, and the penalty date unchanged. If optimization replaces the subject or expands in a shipment rule not stated in the material, record that deviation. Do not use it to judge the penalty's effect on fulfillment.

Whether an appeal is accepted, whether a penalty is revoked, and whether an order may ship all require a separate system implementation or manual verification. Retrieval and forms do not carry out these business actions.
