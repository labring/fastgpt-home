# Short-video affiliate sales: workflow routing for after-sales questions

## What the documents look like

Short-video affiliate distribution depends on long-term content exposure and product-link conversion rather than live explanation. Order fulfillment and after-sales question handling requires checking four document types at the same time: short-video scripts, attached-product lists, commission plans, and violation feedback. These materials come from content operations, creator business development, and product distribution specialists. Selected Alliance, short-video playback data, product transaction data, and platform rules form the main data sources. Daily and weekly update rhythms mean the same order may appear in script, list, and commission plan versions that carry different dates. The central routing problem is to take fulfillment or after-sales information submitted by a user and connect it accurately to downstream retrieval, judgment, or interface nodes, while distinguishing node behavior, configurable fields, manual verification actions, and business actions that require a separate system implementation.

The Form Input node enters an interaction state when triggered, records the workflow state, and passes collected required information to later nodes after the user submits. The User Selection node executes the corresponding branch after the user makes a choice. Neither node constitutes authorization, and neither replaces order writing, document backfill, or external status synchronization; those actions require a separate business interface or downstream process. A shared vector model requirement applies only to libraries that can be associated together and does not extend to external systems. A relevance score does not carry permission or entity isolation functions. Optional paths shown in a general workflow diagram do not mean every request executes all of them. Image retrieval requires a corresponding image input and model capability. Reranking requires a model and must be enabled according to settings.

## Constraints at the workflow routing step

Consider a hypothetical paper exercise sample. The material text for verification reads: "Attached-product list row A-17: product number SP-204, listing date March 10, 2025, status on sale; commission plan row C-09: product number SP-204, commission rate 8%, effective period March 1, 2025 to March 31, 2025; violation feedback row F-32: product number SP-204, feedback date March 18, 2025, content states the title contains an absolute term, handling status pending review." The draft sentence to be judged reads: "SP-204 was on sale on March 18, 2025 and its commission plan was effective, so it can continue affiliate promotion." This sentence touches three different fields: list status, commission effective period, and violation handling status. Judgment must use the same subject, the same period, and the same field.

The interaction state records workflow state as behavior of the interaction node; no separate global state-recording switch is assumed. When a required field is not passed to a later node, the gap is recorded rather than assumed to be auto-filled. A pending review status does not by itself prove that operational permission is absent. Signing, cooperation reaching agreement, and contract taking effect are three distinct facts. A quotation validity period does not indicate a supply period. Missing authorization or effective clauses are not fabricated to obtain a definite answer; evidence gaps remain explicit.

## Three common errors

1. Treating form submission as authorized execution. In the sample, violation feedback row F-32 has handling status pending review. If the draft sentence is written from this row to say promotion can continue, that treats pending review as approved. Check method: input the original row text, compare the handling status field value, and observe whether the draft sentence presents pending review as executable.

2. Merging the commission effective period and the product on-sale status into one field. In the sample, the commission plan effective period ends March 31, 2025, and the list status is on sale; these are different fields. Check method: input both row texts, compare field names and values, and observe whether a cross-field combined judgment appears.

3. Treating retrieval relevance as permission or entity filtering. The sample involves the single product number SP-204. If the configuration uses a relevance score to exclude other products or unauthorized records, that exceeds its scope. Check method: input retrieval conditions and returned records, compare the product number each record belongs to, and observe whether any statement substitutes a score for permission judgment.

## How to verify the setup

- Verification one: Using the sample original text above as input, compare the draft sentence's three statements "on sale status," "commission plan effective," and "can continue affiliate promotion" against the three fields of list status, commission effective period, and violation handling status. The draft sentence meets the condition only when all three fields share the same subject, the same period, and the same field with consistent values. When the handling status is pending review, the sentence does not meet the condition.

- Verification two: Using the Form Input node required fields as input, compare the field names and values received by downstream nodes after submission and observe whether they match the submitted content item by item. If a field is not passed, record the gap and do not assume the node auto-fills it.

- Verification three: Using paper input `[]` as input, compare the downstream branch design and observe whether the downstream treats it as an empty set and retains a gap record. Do not claim that a fabricated rule retrieval necessarily returns `[]`, and do not guarantee a first hit or full recall.
