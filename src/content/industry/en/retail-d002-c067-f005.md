# Group-buy leader operations: multi-turn prompts for after-sales questions

## What the documents look like

Group-buy leader operations manage community pickup nodes and commission, and the work does not include cold-chain quality inspection. The materials handled in this category are leader agreements, commission tables, pickup lists, and community announcements. For order fulfillment and after-sales questions, one conversation often crosses several of these materials: a user may first ask about a shortage record on a pickup list for one group, then follow up on the matching deduction in the commission table, and finally request a community announcement for neighbors. Material update frequency is daily and per group, so the number of history turns carried into a single request directly affects whether these cross-material follow-ups are answered against the correct group and period.

## Constraints at the multi-turn prompts step

Multi-turn context comes from the session record tied to chatId. The documented behavior is: when chatId is not passed, context is built entirely from the messages array; when a non-empty chatId is passed, the session is read from the FastGPT database and the last item in the messages array is used as the user question, with the remaining messages ignored. Prompts need to state the material scope, the answering task, and how to handle missing evidence, so the model does not fill in business facts such as commission rates or shortage quantities. Knowledge-base continuous conversation requires checking reference resolution and question expansion, and short questions cannot be assumed to work in every case.

Hypothetical paper exercise sample, used only for checking on this page and not drawn from any real customer:

Material text one: "Leader agreement clause 3: the leader is responsible for checking the pickup list for this group; a wrong or missed delivery found on the pickup day should be recorded that day, and a late record does not affect later supplementary delivery." Material text two: "Commission table, June 2025 version: short-shipped orders are commissioned on the actually fulfilled amount, and the short-shipped portion is not commissioned." Draft sentence: "Under clause 3 of the agreement, a late record will cause this shortage to receive no supplementary delivery, so the leader should record it as soon as possible."

Proposed finding: the draft sentence turns "a late record does not affect later supplementary delivery" into "no supplementary delivery," and mixes this with the commission basis described in material text two in the same sentence. Checking requires the same subject, the same period, and the same field. A supplementary delivery deadline that the materials do not state remains unsupported and cannot be written as a negative conclusion.

## Configuration and implementation checks

| Configuration item | Relevant value or check item on this page | Relation to the sample |
| --- | --- | --- |
| AI model | Choose a model whose context length can hold the agreement and commission table fragments; the capabilities shown in the configuration dialog govern | The sample contains two materials, so maximum context needs checking |
| Memory turns | For this hypothetical trial the starting value is set at 3 turns, because the sample follow-up crosses two rounds of material; compare with the default and adjust to the actual session length | Determines whether the earlier shortage follow-up is carried in |
| Temperature | A lower value is suggested for customer service and knowledge-base question answering, to keep answers stable | Reduces the chance that the draft sentence rewrites the agreement clause on its own |
| Response format | Ordinary question answering keeps the default; choose json_schema with the corresponding format requirement only when a later node must read a fixed structure | The draft sentence is text and needs no structured output |
| Hide AI output | Enable when an internal result must be prepared first and rewritten by the next node; the content can still be passed on through the AI reply output | Relevant if the announcement needs a second rewrite |
| Multimodal recognition | Enable only when the model supports it and the input contains images, audio, or video; document content still needs file parsing into text | The sample is text material and does not involve this |

## Three common errors

1. Applying the commission basis from material text two to the supplementary delivery rule in material text one. The input is the two material texts plus the draft sentence; the comparison object is the field "a late record does not affect later supplementary delivery"; the observable result is that the draft sentence rewrites it as "no supplementary delivery," which reverses the source wording.
2. Reusing history without checking the chatId state. The input is the earlier shortage follow-up under the same chatId; the comparison object is the last item in the current messages array; the observable result is that the model cites the previous group's data as this group's data.
3. Treating the form configuration returned by an interactive node as already submitted. The input is the data.interactive of event=interactive; the comparison object is whether a further request is sent with a consistent chatId; the observable result is that the flow still waits for input and no later node response is produced.

## How to verify the setup

1. Provide material text one, material text two, and the draft sentence together as input, compare whether the draft sentence stays consistent with "a late record does not affect later supplementary delivery," and observe whether the draft sentence keeps the source wording or clearly marks that field as not stated. The expected result is that the draft sentence preserves the source wording or flags the missing field; this is an expected outcome, not a record of a completed test.
2. Under the same chatId, send the shortage follow-up first and then the commission follow-up, compare the historyPreview or completeMessages of the two requests, and observe whether the number of turns carried in matches the memory turns setting and whether records from another group are mixed in.
3. Use the paper input `[]` as an empty retrieval result for the downstream handoff, check the downstream node's output design when no reference is present, and observe whether the downstream treats it as missing evidence rather than filling in a commission rate or shortage quantity. Retrieval is not authorization; a relevance score does not filter out unrelated businesses or unauthorized records, and the empty result itself does not prove that any rule-based search would return an empty list.
