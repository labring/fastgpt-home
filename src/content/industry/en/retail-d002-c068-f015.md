# Group-buy presale orders: retrieval for after-sales questions

## What the documents look like

Presale group-buy operations collect orders first and organize procurement and fulfillment afterward. The working documents for this category are the presale product table, the group-order result, the procurement plan, and the cut-off notice. These materials are updated daily or per sales session, so retrieval and recall face version differences of the same document set across sessions.

The materials carry product name, specification, cut-off time, expected arrival window, and after-sales handling wording. A field-level check requires the same subject, the same period, and the same field before two statements can be compared. Retrieval returns existing library content as citations. Business authorization, refund execution, and procurement ordering sit downstream, and a retrieval result by itself does not grant any authorization.

A presale cut-off time and an expected arrival window are separate fields with separate values. A draft sentence that restates an after-sales deadline has to be compared against the after-sales wording actually present in the session document, not against the cut-off time or the arrival window.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Bases built on different vector models cannot be associated together; the check is to verify the model identifier and exclude non-matching bases, not to run a cross-model retrieval and compare recall. Search mode can be semantic retrieval, full-text retrieval, or hybrid retrieval. Hybrid retrieval merges multiple result paths through RRF, and RRF is a fusion process rather than a separate switch that can be turned on.

The citation limit is measured in tokens. The minimum relevance value applies only under semantic retrieval or when result reranking is used, and it is a filter threshold rather than a final sort rule. Question optimization performs coreference resolution and question expansion before retrieval and adds an extra model call. Image retrieval requires image input and the corresponding model capability. Reranking requires a rerank model and has to be enabled according to settings. Cited content is output as an array whose length can be zero, and the downstream path still runs when nothing is retrieved.

Hypothetical paper test case: an operations staff member at a community group-buy platform holds two passages from the Session 0417 Presale Product Table. Passage one reads: "The cut-off time for this session is 17 April 20:00; the expected arrival window is 19 April to 20 April." Passage two reads: "After-sales wording for this session's product 'spring bamboo shoots 500g': a stock-out refund can be requested within 24 hours after arrival, with group leader confirmation attached." The draft sentence to be judged is: "The stock-out refund request for Session 0417 spring bamboo shoots 500g closes at 21 April 20:00." The date in this draft sentence does not match the 24-hour-after-arrival wording in the source, so it remains a pending verification item and cannot be treated as a confirmed conclusion.

## Configuration and implementation checks

| Associated knowledge bases | Associate only presale group-order bases that use the same vector model | Check each base's vector model identifier first, exclude non-matching ones, then confirm joint association |
| Search mode | Start with full-text retrieval to check the session number and cut-off time | Session numbers and times are exact queries; compare hit differences against semantic retrieval result by result |

| Question optimization | Off at the start | Compare item by item with the expanded results when enabled, and check whether the subject has been altered |
| Result reranking | Not enabled at the start | When a rerank model is available, enable it according to settings and compare candidate order before and after reranking |

These values are hypothetical starting points for this exercise and are not official default values.

## Three common errors

1. Treating a retrieval hit as business authorization. Retrieval only returns cited content; refunds, procurement, and synchronization require downstream implementation. Treating a recalled result as an executable authorization crosses the authorization boundary.
2. Forcing knowledge bases with different vector models into a joint association. The documents require the same vector model for joint association. When identifiers do not match, the base should be excluded and the observation recorded, without inferring missed recall or redundant results from that exclusion.
3. Treating minimum relevance as an entity or permission filter. That value is a filter threshold that applies only under semantic retrieval or result reranking, and it cannot be used to exclude unrelated businesses or unauthorized records.

## How to verify the setup

1. Enter the hypothetical source passages and the draft sentence described above, compare the draft sentence's date against the source wording "within 24 hours after arrival," and observe whether the system recalls the source passage and preserves the date difference. If the passage is not recalled, record that as a gap.
2. Enter a short question containing only "Session 0417 cut-off," compare the hits from full-text retrieval and semantic retrieval, and observe whether full-text retrieval hits the cut-off time field and whether the semantic retrieval result drifts away from that field.
3. Use the paper input [] to check the empty-citation path, and observe whether downstream nodes continue to execute with a citation length of zero. Do not claim that a fictional rule necessarily returns an empty array.
