# Cross-border product labels: shared access for after-sales questions

## What the documents look like

Evidence for cross-border product compliance and labelling is produced before listing and before import. The working documents are product test reports, English-language labels, MSDS files and platform prohibited-item lists. Sources include platform policy centres, testing laboratory reports, destination-country regulation libraries and supplier materials. Updates are irregular, and each new product launch can introduce a new destination requirement or a new label version.

During order fulfilment and after-sales question handling, these documents are frequently requested through a share link or an embedded window for an external counterparty. The share entry point resolves an access path only. Whether a document may be released externally, which version is current, and whether a submission is still pending review all require separate checking.

## Constraints at the shared access step

The no-login window is created under the application details, in the publishing channel area. The system generates a complete link, which can be copied and used. The link name is kept for record display only and does not act as a business authorisation credential. Expiry time, QPM and points cap are set according to the intended scope of use; some parameters are restricted by edition, so the configurable set must be checked against the actual edition.

Identity verification falls within the commercial edition scope. After a root address is configured, initialisation of the share link, the start of a conversation and the end of a conversation each send a POST request to the corresponding endpoint at that address. When the returned success value is true, the user may continue. The uid value must be returned and must be a string that does not contain "|", "/" or "\" characters and does not exceed 255 bytes in length. Conversation records depend on localId: the same device and the same browser can retrieve the recent 30 days of records, limited to 20 items, and switching devices or clearing browser cache loses them.

Hypothetical paper exercise sample: a compliance specialist prepares a draft English label for checking. The source text reads: "This label applies to model A children's tableware, material food-grade silicone, migration testing completed to destination-country requirements, report number TR-2024-031, issued 12 March 2024, valid until 11 March 2025." The proposed handover request reads: "Please share the above label together with the test report with the overseas warehouse receiving party, for use in this batch's order fulfilment." That request does not state whether the receiving party holds viewing permission, and does not state whether the label has passed platform review. Both points remain to be verified.

## Three common errors

1. Treating the share link identifier as a business authorisation credential. The link can be copied and used, which does not mean the receiving party has permission to view or receive the label and test report. Authorisation status requires separate checking, and an unstated permission remains missing.

2. Treating a label under review as already approved. The sample does not state the platform review status of the label, and the proposed handover request asks for sharing directly. This handles a matter still to be verified as though it were complete.

3. Applying the same-device conversation record boundary to a cross-device handover. The localId depends on the same device and the same browser. When the overseas warehouse receiving party uses a different device, the records cannot be retrieved.

## How to verify the setup

1. Input the sample source text and the proposed handover request. Compare the share link name and expiry time against the sample label validity period. If the expiry time falls before 11 March 2025, the link stops working while the label is still valid, and the setting needs adjustment.

2. Input the identity verification root address and the authToken. Compare the returned success value and uid against the documented format. If success is not true, or the uid contains "|", "/" or "\" characters, or exceeds 255 bytes, authentication does not pass.

3. Input the sample phrases "migration testing completed to destination-country requirements" and "valid until 11 March 2025". Compare against the label review status field. If that field is not stated, the review status is unsupported by the available evidence and requires further evidence from the platform or supplier. Direct sharing is not supported at this point.
