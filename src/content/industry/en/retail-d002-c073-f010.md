# Cross-border payment reviews: citation tracing for after-sales questions

## What the documents look like

Cross-border independent-site payment risk control centers on card-network disputes and receiving accounts. Parcel status is one part of that picture. The working materials come from payment-backend chargeback notices, independent-site order records, carrier proof of delivery, and customer-service email threads. These materials update daily and per order, so every dispute citation corresponds to a specific point in time and a specific document state.

Preparing chargeback evidence and tracking frozen funds consume significant time. Whether a citation source can be traced affects whether appeal materials hold together. A fraudulent-order list and an invoice are different documents, and the same order may sit at different stages in each. Reviewers need to distinguish what each material records.

## Constraints at the citation tracing step

The knowledge-base search node selects one or more knowledge bases that share the same vector model, and outputs cited content as an array whose length may be zero. A zero-length array means this search returned no items. That fact alone does not indicate a workflow error or a business conclusion.

Minimum relevance is a filter threshold between 0 and 1, effective only under semantic search or when result reranking is used. It filters low-relevance results and does not perform permission or entity isolation. Search scope is determined by the selected knowledge bases; the act of searching does not authorize any order, account, or operation. Hybrid search merges multiple recall paths through RRF, and a rerank model reorders candidate text a second time. These are steps in the retrieval flow and do not change the validity state of the underlying materials.

Hypothetical drill sample: a risk-control specialist at an independent-site merchant retains three verbatim material sentences. Sentence one: "The payment provider chargeback notice states: order A-2231, disputed amount USD 180, notice date 4 March 2025, current status awaiting evidence submission." Sentence two: "The carrier proof of delivery states: order A-2231, delivery date 26 February 2025, recipient signature field blank." Sentence three: "The customer-service email record states: the buyer wrote on 1 March 2025 claiming the parcel was not received; this email has no reply record." A draft sentence to be judged: "This order has complete proof of delivery and can be submitted for the chargeback appeal." The phrase "complete proof of delivery" in the draft conflicts at the field level with the blank recipient signature field in sentence two, and must be checked against the same order and the same field.

## Configuration and implementation checks

| Configuration item | Hypothetical trial starting point | Reason and comparison object |
| --- | --- | --- |
| Linked knowledge bases | Two bases sharing one vector model | Documentation requires the same vector model before bases can be linked together; verify each base identifier |
| Search mode | Hybrid search | Materials contain exact fields such as order numbers; compare against pure semantic search results |
| Minimum relevance | 0.35 | Hypothetical starting point; compare returned item counts against 0.2 and 0.5 before adjusting |
| Citation limit | 3000 tokens | Hypothetical starting point; compare citation completeness against 1500 and 6000 |
| Result reranking | Enabled | Compare ordering before and after reranking when candidates are numerous |
| Question optimization | Disabled | The current question has a complete subject; compare elapsed time and retrieval results when enabled |

The values in this table are hypothetical trial starting points and are not official defaults. The citation limit uses tokens as its unit; thinking budget belongs to model thinking configuration and the two must not be mixed.

## Three common errors

1. Treating a returned citation array as an authorization credential. Error symptom: reading a chargeback-notice search result as permission to submit. Check input is sentence one of the hypothetical sample; compare the search output against authorization materials; the observable result is that the citation array exists while the authorization status field remains awaiting evidence submission.

2. Reading a blank recipient signature field as a completed signature. Error symptom: the draft sentence claims complete proof of delivery. Check input is the verbatim sentence two; compare the recipient signature field against the draft wording; the observable result is that the source field has no value and the draft conclusion is unsupported.

3. Forcing knowledge bases with different vector models into a shared link. Error symptom: selecting two bases whose model identifiers differ. Check input is each base's vector model identifier; compare whether they match; the observable result is that the non-matching base is excluded and no cross-model retrieval comparison is performed.

## How to verify the setup

1. Input the three verbatim hypothetical sentences and the draft sentence; compare the draft conclusion against each source field; the observable result is that the recipient signature field is empty, the draft phrase "complete proof of delivery" is unsupported, and the item is recorded as pending verification.

2. Input an explicit paper empty array as the search output; compare the downstream answer step's handling design; the observable result is that the empty array still passes through the chain, and whether the downstream step issues a no-citation notice is determined by that step's design rather than automatic judgment.

3. Input the vector model identifiers of two knowledge bases; compare whether the identifiers match; the observable result is that the non-matching base is excluded and the actual observation is recorded, without inferring runtime behavior after a shared link.

This feature has verified public technical facts: check the selected knowledge bases and material versions first for search scope, since only the same vector model allows shared linking; the search node outputs a citation array whose length may be zero, and an empty array does not mean the workflow has errored out; check whether retrieval output is handed to the answer step and verify each answer against the cited source text; use traceable samples to check source display, and do not substitute thinking process or fluent answers for source evidence; test sources with current and historical document versions, and whether a citation is adopted still requires review against the effective version.
