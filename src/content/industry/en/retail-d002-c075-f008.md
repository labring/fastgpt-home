# Creator sales campaigns: workflow routing for after-sales questions

## What the documents look like

Creator sales campaigns operate through external creator fulfillment and commission settlement. The main data sources are the selected alliance, the creator marketplace, historical creator data, and store transaction details. Brand commerce staff, MCN agencies, and creator agents work around creator cooperation agreements, commission setting sheets, sample shipment sheets, and livestream reports. Selecting creators, negotiating commission and slot arrangements, and checking after-sales commission deductions are time-consuming steps. Errors in these steps can produce commission settlement disputes, false traffic, and damage to brand reputation.

These materials feed directly into workflow routing for order fulfillment and after-sales questions. A creator cooperation agreement identifies the parties and the fulfillment scope. A commission setting sheet sets the settlement basis. A sample shipment sheet records shipment and return status. A livestream report provides the session and transaction basis. The supplied update frequency is per session and weekly. This page does not derive batch synchronization, full synchronization, real-time processing, or transaction-triggered mechanisms from that frequency.

## Constraints at the workflow routing step

The form input node and the user selection node are user interaction nodes. When either node is triggered, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. The form input node collects required information and passes it to later nodes after submission. The user selection node evaluates the user's choice and executes the corresponding branch. Checking the interaction state belongs to the behavior of the interaction node itself; no separate global state-recording switch is documented. Output handoff checks require that collected information be clearly passed to later retrieval, judgment, or interface nodes, comparing output against input item by item. Order writes, document backfill, and external status synchronization require a separate business interface or a later process. Retrieval and forms do not constitute authorized execution.

Hypothetical paper exercise sample: A brand commerce staff member holds the following material text. "The creator cooperation agreement states that Party A is a brand commerce entity and Party B is a creator agent entity; the cooperation session is a creator special session on a given month and day; commission is executed according to the commission setting sheet. The sample shipment sheet shows the sample has been sent; return status is not stated. The livestream report shows transaction details for that session." The draft sentence to be judged is: "After-sales commission deduction for this creator special session has been settled according to the cooperation agreement." This sentence lacks stated evidence of settlement completion and after-sales commission deduction. It is unsupported, and the evidence gap must remain.

## Three common errors

1. Treating information collected by the form input node as business authorization. The input is the form submission value; the comparison object is the stated scope of the creator cooperation agreement and the commission setting sheet; the observable result is that a submission value outside the stated scope must not trigger settlement-type downstream actions.
2. Treating a user selection node branch as automatic judgment. The input is the user's selection result; the comparison object is the branch connection configuration; the observable result is that when a branch is not connected, the process remains in the interaction state.
3. Treating retrieval or relevance as a permission or entity isolation filter. The input is a retrieval request; the comparison object is the accessible retrieval scope identifier; the observable result is that libraries across different vector models cannot be associated together, so the identifier is checked first and non-matching items are excluded.

## How to verify the setup

1. Using the hypothetical sample text, input the draft sentence "After-sales commission deduction for this creator special session has been settled according to the cooperation agreement." Compare the stated fields of the cooperation agreement, the commission setting sheet, and the livestream report. The condition is satisfied only when the same entity, the same session, and the same field all state that settlement is complete; otherwise record it as unsupported.
2. Using the paper input [] to check empty-result handling, compare whether the downstream node design has explicit handling for an empty result. The observable result is that when the downstream design has no handling, record the gap. Do not claim that a fictional rule retrieval necessarily returns [].
3. Using the sample shipment sheet text, input "return status not stated." Compare the shipment record against the return record. Return completion is determined only when the return field is explicitly stated; when it is not stated, keep it as pending verification.
