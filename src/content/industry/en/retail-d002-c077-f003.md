# Import and export permits: shared access for after-sales questions

## What the documents look like

Permit handling takes place before customs declaration and determines whether a shipment may lawfully be imported or exported. In order fulfilment and after-sales question handling, the material shared with a counterparty commonly includes an automatic import licence, a dual-use item licence, a contract, and a product description. These materials originate from the commerce authority system, customs commodity codes, supplier documents, and customer statements of use. They are updated irregularly and per shipment. The three most time-consuming steps are judging the applicable regulatory document, preparing the statement of use, and following the approval status. A shared link is an access entry point. The link identifier does not function as a business authorisation. A retrieved licence fragment does not replace an approval decision. When material status is shared, the participant in the conversation needs to see which stage the material has reached.

## Constraints at the shared access step

The no-login window is created under the publishing channel, and the complete system-generated link is copied for use. Any internet user can use the application through that address, and the resulting cost is charged to the team that owns the application. The system generates a localId for each user to identify the user and pull conversation records from the cloud. This method only supports use on the same device and the same browser. Switching devices or clearing browser cache loses those records. Only the most recent 30 days and 20 records can be pulled. Identity verification is a POST request root address. Initialisation, conversation start, and conversation end each send a request to a specific endpoint under that address. The server only needs to return whether verification succeeded. The unified response contains success, message or msg, and data with uid. FastGPT judges success to decide whether the user may continue. The uid is the unique user credential and must be returned. It must be a string that does not contain "|", "/", or "\" and is no longer than 255 bytes. Otherwise an Invalid UID error is returned. Expiry time, QPM, points limit, and identity verification are partly configurable only in the commercial edition. Conversation record boundaries depend on the anonymous local identifier, and cross-device records require separate identity and session management design.

Hypothetical paper exercise sample: a foreign trade compliance staff member intends to share a licence handling progress note with a customer. The material text to be checked reads: "The automatic import licence application has been submitted to the commerce authority system, and the approval status is pending review; the delivery date agreed in the contract is 20 March 2026; the purpose field in the product description is stated as production for own use." The draft sentence to be assessed is: "The licence has been completed and shipment can be arranged." This request sits at the sharing and embedding step. The authorisation boundary is to display only the current status of the material, and it does not constitute approval or a shipment permit.

## Three common errors

1. Treating the shared link identifier as a shipment authorisation. The input is the sample link and the draft sentence. Compare the link identifier with the approval status field. The observable error is that the draft sentence states "the licence has been completed", while the material text states only "pending review".
2. Treating a retrieved licence fragment as an approval conclusion. The input is the licence fragment returned by retrieval. Compare the status description in the fragment with the current status in the commerce authority system. The observable error is that the fragment is taken directly as evidence that the licence is completed.
3. Treating a pending request as an executed action. The input is the success and uid returned by the identity verification interface. Compare that return with the approval record. The observable error is that a successful interface check is misread as the licence having been approved.

## How to verify the setup

1. For the sample draft sentence, input the material text "approval status is pending review" and compare it with the draft sentence "the licence has been completed". The expected observation is that the draft sentence does not match the source status and must be changed to pending review.
2. For identity verification, input the authToken and the root address, and compare whether the returned uid does not contain "|", "/", or "\" and does not exceed 255 bytes. The expected observation is that only a valid uid allows the user to continue.
3. For the conversation record boundary, input access from the same device and same browser, and compare whether records can still be pulled after switching devices. The expected observation is that records are missing across devices, and identity and session management must be designed separately.
