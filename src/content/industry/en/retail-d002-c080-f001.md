# Store price and display checks: after-sales questions with HTTP integrations

## What the documents look like

For after-sales questions in Store price and display checks, this page examines FastGPT HTTP integrations. Audit-service requests preserve store observations, price versions and correction stage. The examples are hypothetical.

## Constraints at the HTTP integrations step

Suppose an inspection note says a shelf label awaits review, a screenshot concerns another variant and a correction notice asks the store to reply only. Pass store, item and audit matter under actual interface documentation, checking Params, Headers, Body and variable correspondence without inventing parameters. Query authentication grants no price-change or compensation authority. No real violation finding is supplied.

## Configuration and implementation checks

| Audit-service HTTP | Hypothetical record | Inspection |
| --- | --- | --- |
| Label observation | Review pending | Not confirmed error |
| Variant screenshot | Another variant | Current mapping |
| Correction notice | Reply requested | Not completed |
| Version/time | Original evidence | No filename guesses |
| Service handling | Authorized process | Separate authority/receipt |

| `Request address and method` | The request address and method follow the external contract. |
| `Params and Headers` | Inspect parameters, headers and authentication separately. |
| Body | Where a JSON body is used, validate its structure against the external contract. |
| `Variable references` | Variables can come from global, system or upstream outputs. |
| `Debug identity fields` | Test mode lacks chatId and responseChatItemId. |

## Three common errors

An unreviewed label reported as confirmed wrong pricing needs actual comparison evidence checked. Another variant screenshot applied here needs item identity checked. A request to reply reported as completed correction needs execution acknowledgment checked. These concern observation level, subject and action stage; HTTP return decides no dispute.

## How to verify the setup

Compare redacted requests and raw responses sentence by sentence with sources. Label version and applicable time need original support rather than filename guesses. Added current-variant evidence corrects correspondence alone while pricing and correction remain separate. Price changes, service handling and store writes require authorized procedures and business interfaces. The query chain organizes existing evidence and gaps without making unapproved promises to consumers. Retain the inspection observation, verifying variant correspondence and locating correction notices separately from execution so each proposed service answer traces to its store record.
