# Store price and display checks: shared access for after-sales questions

## What the documents look like

Price and display audits happen during ordinary trading periods, and their purpose is sustained execution of standards rather than one-off launch support. The working materials come from the supervision system, the POS price list, store cameras and head office promotion calendars. Weekly and monthly update rhythms mean the most common documents are store visit photographs, price tag lists, display standards and rectification notices. Order fulfilment and after-sales question handling needs to place these materials in front of regional supervisors, store managers or a third-party service entry point, which makes sharing and embedding the delivery channel. The materials carry a period and a store scope, and using them outside that scope changes what the conclusions cover.

A price tag list for a specific month and region states which stores were checked and which discrepancies were found. A rectification notice states that a notice was issued and on what date. Neither document, on its own, states that the store corrected anything.

## Constraints at the shared access step

The no-login window is created in the publish channel and the system generates a complete link that can be copied. The link name is used only for record display and does not act as business authorization. Identity verification falls within the commercial edition scope and works through a POST root address: the initialization, conversation start and conversation finish steps each send a request, and the returned `success` value together with a `uid` determines whether the user continues. The `uid` must be a string of 255 bytes or fewer that does not contain the characters `|`, `/` or `\`, otherwise the `Invalid UID` error is returned. Conversation records depend on a localId that is tied to the same device and the same browser, and only the most recent 30 days and 20 records can be pulled; moving to another device requires separate identity and session design. Retrieval and similarity scores do not perform permission filtering or entity isolation, and a retrieved record is not an authorized record.

Hypothetical drill sample: a chain operations department intends to share a store visit material with regional supervisors. The source text to be checked reads: "March 2025 East China Region Class A store price tag spot check record. Twelve stores were checked. Three stores had promotion price tags inconsistent with the POS price list. A rectification notice was issued on 18 March. Rectification receipts were not complete as of 31 March." The handover request to be assessed reads: "Open this material to supervisors through a share link and allow them to view all quoted fragments and source text."

The material supports statements about the check scope, the count of inconsistent stores, the notice issue date and the receipt status. It does not support a statement that rectification was completed, because the receipts were not complete.

## Configuration and implementation checks

| Configuration item | Value or check action on this page | Basis and boundary |
| --- | --- | --- |
| Name | Enter a name used for record display only | The official description states the name is for record display |
| Expiry time | Set according to the intended sharing window and confirm whether the current edition supports it | Some parameters are limited by edition |
| QPM | Read as the maximum access count per user per minute and verify it | Officially defined; no default value is inferred |
| Points cap | Check the usage limit at the sharing entry and which team bears the cost | Costs are produced under the team that owns the application |
| Identity verification | Enter the POST root address and decide admission from `success` and `uid` | Commercial edition scope; the interface returns only the verification result |
| View quoted fragments and source text | Decide whether to enable according to the authorized material scope | Displaying quotes does not change the authorization state of the material |

For this drill, a hypothetical starting value for the expiry time is 14 days, chosen because the material covers a March check period and the receipts were still incomplete on 31 March; it is compared against the actual date on which the supervisors need access. This is a drill starting point, not an official default.

## Three common errors

1. Treating the link identifier as business authorization. A link can be created and copied, while the authorization state is only confirmed when the identity verification interface returns `success` as true and a compliant `uid`. A missing response or a false value is unsupported, not approved.

2. Treating a retrieval result as permission filtering. Similarity and recall reflect content matching only. They do not exclude unrelated businesses or unauthorized records, and finding a material through retrieval does not mean that material has been cleared for sharing.

3. Treating a pending or issued item as completed. A rectification notice that has been issued with receipts not yet complete is stage evidence. It does not support a conclusion that rectification closed, and it does not support a conclusion that the store has executed the correction.

## How to verify the setup

1. Input the sample source text and the handover request, then compare whether the share link carries the `authToken` parameter and whether the identity verification interface returns `success` and a `uid` that meets the format requirement. The admission condition is met only when `success` is true and the `uid` is compliant. When the response is false or the `uid` contains a forbidden character, record the case as unsupported and keep the evidence gap open.

2. Input the field "three stores inconsistent, receipts not complete" from the sample and compare the proposed draft sentence against it. A draft sentence claiming that rectification closed is inconsistent with the source text. A draft sentence stating only that the notice was issued and receipts were not complete is consistent with the source text.

3. Input the sample material together with the enabled quote display settings, then compare the quoted fragments and source text that supervisors can actually view against the authorized scope of that material. When the visible content exceeds the material scope or includes records from other stores, record the case as pending verification. Do not run a cross-scope retrieval to produce a comparison result.

A paper input of an empty list may be used to check the downstream design for empty results. This does not mean that any particular rule-based retrieval returns an empty list.

When libraries use different vector models, they cannot be associated together. Check the identifiers first and exclude those that do not match, then record what was actually observed. Do not run a cross-model retrieval to compare missed recall.
