# Returned-goods inspections: shared access for after-sales questions

## What the documents look like

Returned-goods inspection handles reverse parcels and product grading. It does not handle outbound picking for new orders. The working materials are the return inbound receipt, inspection photos, the grade determination sheet, and the resale listing sheet. Data sources include the WMS return module, platform after-sales records, carrier returns, and the inspection station. Updates occur per item and per day. These materials determine which document and which grade conclusion an after-sales answer may cite.

A shared or embedded conversation entry moves the material boundary and the authorization boundary into the same page. The link identifier opens a conversation. It does not grant business authorization to send any inspection document outside the warehouse.

## Constraints at the shared access step

The no-login window is created under the publish channel and the system-generated full link is copied. The name field is only a record label for display. The expiration time makes the link unusable after that point. QPM is the maximum access count per user per minute. The points cap is the maximum billing data produced by that link, and some parameters are restricted by edition. Identity verification is restricted to the commercial edition. Access is judged by the returned `success` state and the returned `uid`. The anonymous localId depends on the same device and the same browser, and the system allows pulling only the last 30 days and 20 records. Cross-device records require separate identity and session design.

Hypothetical drill sample: on 10 March 2025 a returned-goods inspection team at an after-sales warehouse processes return inbound receipt RT-20250310-017, an electric kettle of a stated model. The inspection photos show a scratch on the base. The grade determination sheet is drafted as grade B, resalable. The resale listing sheet has not been generated. The handover request is: share this receipt's grade determination sheet through the no-login window with an external after-sales agent, so that agent can answer the buyer's refund dispute. This request involves sending material outside and confirming identity, and it remains a pending item.

## Configuration and implementation checks

| Configuration item | Setting or check on this page | Relation to the sample |
| --- | --- | --- |
| Name | Record label only, used for display | The name must distinguish the batch that contains RT-20250310-017 for handover |
| Expiration time | Link is unusable after this time; set by use scope and check the actual edition | The dispute reply needs a validity period covering the reply cycle |
| QPM | Maximum access count per user per minute | Check whether concurrent external agent access reaches the rate limit |
| Points cap | Maximum billing data produced by the link; some parameters restricted by edition | Cost falls to the owning team; check the usage cap |
| Identity verification | Fill in the POST root address; judge release by `success` and `uid` | The external agent must first pass the verification interface and obtain a `uid` |
| View quote chunk / full text | See the system introduction; enable as needed | Check item by item whether inspection photos and the grade sheet enter the quote |

## Three common errors

1. Treating the link identifier as business authorization. The full link generated by the no-login window only opens a conversation. Whether the grade determination sheet for RT-20250310-017 may be sent outside still requires manual confirmation. A usable link does not mean the material may be shared.
2. Treating the anonymous localId as a cross-device identity. In the sample, the external agent cannot pull the same conversation record after switching devices. The system allows only the last 30 days and 20 records, so identity and session management require separate design.
3. Treating a successful verification as material compliance. The identity verification interface returning `success` and a `uid` only shows that identity verification passed. Whether the content of the grade determination sheet suits a refund dispute reply still requires checking against the material boundary.

## How to verify the setup

1. Input the sample link with the appended `authToken`, and compare the `success` and `uid` fields returned by the verification interface. The identity check condition is met only when `success` is true and `uid` is a string that does not contain "|", "/" or "\" and does not exceed 255 bytes in length. When `success` is false, the `message` content is shown and the result is recorded as not passed.
2. Input the sample request sentence "share the grade determination sheet with the external after-sales agent", and compare it against the scope recorded in the return inbound receipt, inspection photos, and grade determination sheet. The grade sheet is drafted as grade B, resalable, and the resale listing sheet has not been generated. Whether the material state matches the request purpose requires manual judgment, and any part not supported is recorded as pending confirmation.
3. Input an empty quote list `[]` to check the downstream display design, and compare whether `quoteList` in the `responseData` returned by the conversation result reporting interface is empty. When it is empty, the downstream handles it as an empty quote. Do not claim that retrieval necessarily returns an empty result. At the same time, check whether the `uid` identifier matches the one returned by the verification interface, and rule out collections that cannot be associated together across different vector models.
