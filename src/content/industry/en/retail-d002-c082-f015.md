# Returned-goods inspections: retrieval for after-sales questions

## What the documents look like

Reverse returned-goods inspection handles returned parcels and product grades. It runs on a different chain from in-warehouse picking and packing, which handle outbound orders for new purchases. The working materials are the return inbound order, inspection photographs, the grade determination table, and the resale listing order. Data arrives from the WMS return module, the platform after-sales channel, carrier return shipments, and the inspection bench. Each returned item is scanned, its condition judged, and a decision made on resale or disposal. Errors here produce resale of defective goods, refund disputes, and inventory contamination.

When these materials enter a knowledge base, retrieval answers order fulfilment and after-sales questions: what state a returned item currently holds, what basis the grade determination rests on, and whether resale is possible. Retrieval output supplies quoted content only. It does not constitute authorization, approval, or a database write.

## Constraints at the retrieval step

The knowledge base search node can associate one or more libraries that use the same vector model. Libraries built on different vector models cannot be associated together. Verify the model identifier first, exclude any library that does not match, and do not run a cross-model search to compare missed recalls.

Semantic retrieval relies on vector distance. Full-text retrieval relies on keyword hits. Hybrid retrieval merges the two paths through RRF. RRF is a fusion process, not a toggle. The minimum relevance value is a filter threshold and takes effect only in semantic retrieval or when result reranking is used. It does not perform permission or entity isolation. The citation cap is measured in tokens and controls how much content a single search may quote. Question optimization adds one model call before retrieval for coreference removal and question expansion, and it increases overall latency.

Hypothetical paper exercise sample: an inspector processes return inbound order TH-20260310-017 on 10 March 2026. The item is a Bluetooth earphone of a stated model. The inspection photograph shows scratches on the casing. The grade determination table marks it grade B, resalable. The draft sentence awaiting review reads: "This return order has completed resale listing and the refund is settled." The source wording supplied for comparison reads: "Return inbound order TH-20260310-017, status: inspection complete, grade: B, resale listing order not generated." The subject, object, and state needed for the judgment all appear in that source wording.

## Configuration and implementation checks

| Configuration item | Hypothetical trial starting point | Reason for the choice and comparison method |
| --- | --- | --- |
| Associated libraries | Return inbound order library, grade determination table library | Both libraries use the same vector model; verify identifiers before association |
| Search mode | Hybrid retrieval | Return order numbers are exact identifiers and grade descriptions are natural language; compare the semantic and full-text recall paths |
| Citation cap | 2000 tokens | Return orders and inspection photo descriptions differ greatly in length; compare long and short samples for content completeness, then adjust |
| Minimum relevance | 0.4 | Label related and unrelated samples first, then compare whether key grade determination sentences survive filtering |
| Question optimization | Enabled | In multi-turn follow-ups, compare the original question with the optimized question and check whether the subject was altered |
| Result reranking | Enabled | When candidates are numerous, compare rerank scores with vector scores and confirm whether ordering tracks the question more closely |

## Three common errors

1. Treating retrieval output as authorized execution. The input is a retrieval request for return order TH-20260310-017. Compare the quoted content returned with whether a resale listing order has been generated. The observable result is that the quoted content shows inspection complete and grade B only, and does not show that listing was executed. Retrieval does not perform approval or writes.
2. Associating libraries across vector models. The input is two library identifiers on different vector models. Compare whether the identifiers match. The observable result is that a mismatch excludes the association, no cross-model search runs, and no inference is drawn about missed recalls or redundancy.
3. Treating minimum relevance as a permission filter. The input is a query containing unrelated business content. Compare returned content before and after filtering. The observable result is that low-relevance content is filtered out, while the filter does not exclude unauthorized records; permissions require a separate system implementation.

## How to verify the setup

1. Input the draft sentence from the hypothetical sample, "This return order has completed resale listing and the refund is settled." Compare it with the source wording, "resale listing order not generated." The observable result is that the resale listing and settled refund stated in the draft are not supported by the source wording and remain pending verification.
2. Input return order number TH-20260310-017 in full-text retrieval. Compare whether the returned content contains that order number and the grade field. The observable result is a hit on the return inbound order source, with grade B. First-position hits and complete recall are not guaranteed.
3. Input an empty-citation case. Compare whether the node output array length is 0. The observable result is that the output path still completes. Downstream design can be checked against a paper input of []; no claim is made that a fictional rule search always returns [].

This page addresses only reverse returned-goods inspection, order fulfilment and after-sales question answering, and knowledge base retrieval and recall. During operational handover, the authorization state of materials, operations, and requests must be established separately. Retrieval and forms do not perform authorized execution.
