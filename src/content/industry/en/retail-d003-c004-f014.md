# Temu semi-managed sellers: model connections for copy drafting

## What the documents look like

Semi-managed sellers on Temu maintain overseas stock and handle their own dispatch, so the working papers differ from those of a full-managed supplier that only delivers goods to the platform. Four documents carry most of the material used in product and marketing copy drafting: the product declaration form, the overseas inventory table, the price declaration, and the platform fulfilment order. These records are updated daily and per order. That update rhythm belongs to the seller's own operations; it does not create a batch synchronisation mechanism or a transaction trigger inside the model connection layer.

Copy drafting draws on attributes, quantities, prices and fulfilment states recorded in those papers. The wording produced is bounded by what the papers actually state. A field that is absent from the papers stays absent, and a period stated for one purpose does not become a period for another.

## Constraints at the model connections step

Copy drafting depends on a language model and an index model. The system requires at least one of each to work. Model capability is checked against the input the application actually receives: multimodal input, tool choice, and thinking configuration are verified separately rather than assumed from a model name.

Application parameters are set in the application or node configuration. A same-named field on a compatible chat interface is not assumed to override the orchestration. Retrieval results carry relevance, and relevance does not perform permission or entity isolation. A similarity score is not a category filter, an entity filter or an authorisation check.

A hypothetical paper exercise is set out here for illustration only. The source material reads: "The product declaration form states the product name is a folding storage box, the material is polypropylene, and the colour is grey. The overseas inventory table states the sellable quantity of this SKU in the overseas warehouse is 120 units. The price declaration states the declared unit price is USD 12 per unit, valid for the current month." The draft sentence to be assessed is: "This product uses polypropylene, has a grey appearance, is currently sellable at 120 units in the overseas warehouse, and is priced at USD 12 per unit this month."

| Index model | One enabled for retrieving the source material | Compared against the not-enabled state |
| Model capability | The vision field checked against whether the material contains images | Compared against text-only capability |
| Application parameters | Set in the application or node configuration | Compared against assuming a compatible interface field overrides orchestration |

## Three common errors

1. Treating the validity period of the price declaration as a supply commitment. The input is the price declaration text above. The comparison is between "valid for the current month" and a supply commitment. The observable error is that the month range is written as a long-term supply promise.
2. Treating the sellable quantity in the inventory table as the quantity listed on the platform. The input is the overseas inventory table text above. The comparison is between "sellable quantity of 120 units in the overseas warehouse" and the platform listing quantity. The observable error is a direct claim about platform stock.
3. Treating a retrieval hit as a basis for authorisation. The input is one material retrieval result. The comparison is between the hit record and the material range the current account may access. The observable error is releasing unauthorised material on the strength of a similarity score.

## How to verify the setup

1. Input the source material text and the draft sentence above. Compare, sentence by sentence, whether the material, colour, quantity and price in the draft sentence match the source on the same subject, the same field and the same period. The condition is met only when all four items have a corresponding statement in the source. A missing item is recorded as unsupported.
2. Input the price declaration text. Compare whether the draft sentence rewrites "valid for the current month" as a supply period. The condition is met only when the draft keeps the month-range wording. A long-term supply statement is recorded as beyond the material.
3. Input one retrieval result and the list of material the current account may access. Compare whether the hit records fall inside that list. The condition is met only when all hit records are inside the list. A record outside the list is recorded as pending verification, and the retrieval itself does not constitute authorisation.
