# Temu semi-managed sellers: retrieval for copy drafting

## What the documents look like

Semi-managed sellers on Temu keep overseas stock and ship orders themselves. The product declaration and the price declaration define what may be sold; the overseas inventory sheet and the platform fulfillment order define the delivery promise. Copy drafting for products and marketing has to align declaration fields, stock status and fulfillment conditions. The retrieval step takes back citable source fragments from these materials.

These materials update daily and per order. Retrieval configuration does not change with update frequency, and this page does not cover synchronization mechanisms.

## Constraints at the retrieval step

The knowledge base search node can link one or more knowledge bases that use the same vector model. Knowledge bases with different vector models cannot be linked together. During checking, read the vector model identifier first and exclude any base that does not match, then record the actual observation. Do not run a cross-model search to compare missed recalls.

Cited content is output as an array, and its length can be zero. When nothing is found, the output path still completes. A downstream design can be checked against a clearly written empty result `[]`.

The minimum relevance score takes effect only in semantic retrieval or when result reranking is used, and it acts as a filter threshold. Similarity does not perform subject, permission or entity isolation. Retrieval results do not constitute authorization.

Hypothetical drill sample: the source text states that the product declaration records a storage box as on sale on the Germany site, with a declaration validity ending 30 June 2025. The overseas inventory sheet records zero shippable units for that item in the Germany warehouse. The platform fulfillment order records a shipping deadline of 20 June 2025 and a current status of pending shipment. The draft sentence to be judged is: "This storage box is well stocked on the Germany site and ships the same day the order is placed."

## Configuration and implementation checks

| Configuration or check item | Setting on this page | Basis and comparison method |
| --- | --- | --- |
| Linked knowledge bases | Link only the product declaration, inventory and fulfillment bases that share one vector model | Read the vector model identifier and confirm it matches before linking |
| Search mode | Hypothetical starting point for this drill: hybrid retrieval | Number and status fields need keyword hits; compare the semantic and full-text result paths |
| Citation cap | Hypothetical starting point for this drill: 800 tokens | Chosen from the combined length of the declaration, inventory and fulfillment passages; compare whether fragments are truncated |
| Minimum relevance score | Hypothetical starting point for this drill: 0.4 | Label relevant and irrelevant samples first, then compare results on both sides of the threshold |
| Question optimization | Hypothetical starting point for this drill: enabled | Compare the original question with the optimized question and check whether the subject was altered |
| Result reranking | Hypothetical starting point for this drill: enabled | When candidates are numerous, compare the order before and after reranking |

These values are starting points for this hypothetical drill, used for comparison against adjusted values. They are not defaults.

## Three common errors

1. Treating similarity as a permission filter. With the same retrieval request as input, compare the returned fragments against the scope the current account may access. Observing a fragment outside that scope means the condition is not met.
2. Using the minimum relevance score to exclude unrelated businesses. With a question that has no clear subject as input, compare results before and after filtering. Observing the threshold used as an entity filter means the condition is not met.
3. Treating RRF as a toggle. Inspect the configuration item list. Listing RRF as a switch item means the condition is not met; it is a fusion process for mixed results.

## How to verify the setup

1. Enter the three source passages of the hypothetical sample and the draft sentence. Compare "well stocked" and "ships the same day" in the draft against the zero shippable units and the pending shipment status. Observing that the draft sentence is not supported by the materials meets the condition.
2. Enter the declaration validity ending 30 June 2025 and the draft sentence. Compare the values of the same field. Observing that a validity date does not represent a supply period meets the condition.
3. Enter the clearly written empty result `[]`. Compare the downstream handling design. Observing that the path still completes with a zero-length citation meets the condition.

Fields that are not stated, or that have only stage-related evidence, are recorded as pending verification, and the evidence gap remains open.
