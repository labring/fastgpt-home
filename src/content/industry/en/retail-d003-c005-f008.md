# TikTok Shop US operations: workflow routing for copy drafting

## What the documents look like

This page covers copy drafting for product and marketing text in TikTok Shop US store operations. Four document types are in scope: product listings, return and refund records, Return Grading evidence, and settlement statements. Compared with shelf-based operations on other platforms, the US TikTok Shop is more constrained by local return windows, return grading, and overseas logistics. When a drafted sentence about return promises, timing, or responsibility does not match the return and refund records or the Return Grading evidence, the documented consequences include platform automatic refunds, higher return fees, and failed appeals. The supplied material gives a data update frequency of daily and per order. This page does not derive batch synchronization or transaction-triggered mechanisms from that frequency. The workflow routing task here is to connect material checking, draft submission, and downstream node handoff into a traceable interaction path for copy drafting.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When it is triggered, the conversation enters an interaction state, the workflow state is recorded, and after the user completes the required fields and submits, the node collects the submitted form information and passes it to subsequent nodes. The User Selection node is also a user interaction node. When triggered, the conversation enters an interaction state and the workflow state is recorded. When the user makes a selection, the node evaluates that selection and executes the "yes" branch. Both nodes can be added repeatedly and trigger execution. This page does not claim the existence of a global state-recording switch, a submission-count limit, automatic judgment, or snapshot guarantees.

Hypothetical paper exercise sample, not pointing to any real entity. Source text one: "The return window for this store is 30 days after signed receipt; return shipping is borne by the buyer." Source text two: "The signed receipt date for this batch of orders is March 1, 2025; the return and refund record shows a return initiated on March 20; the Return Grading evidence marks the product condition as used." Draft sentence to be assessed: "Free return shipping within 30 days of signed receipt; full refund if the product is unused." The subject, object, state, and effective scope needed for the assessment are all contained in the source texts above.

## Configuration and implementation checks

| Configuration item | Value or check item on this page | Relation to this document |
| --- | --- | --- |
| Form Input node | Enters interaction state when triggered; collects required fields | Collects the drafting task, target listing, and material scope |
| User Selection node | Executes the "yes" branch after the user selects | Applies an adopt-or-return choice to the draft sentence |
| Output handoff | Passes collected information to subsequent nodes | Passes source text and draft sentence to the checking step |
| Retrieval scope | Limited to product listings, return and refund records, Return Grading evidence, settlement statements | Checking materials must be within an accessible target retrieval scope |
| Hypothetical test starting point | This paper sample records two source texts and one draft sentence | The starting point is only for this check; the comparison target is the source texts sentence by sentence |
| External operation division | Order writes, document backfill, and external status synchronization connect separately to business interfaces | This page performs no writes or synchronization |

## Three common errors

1. Treating "free shipping" in the draft sentence as already supported by the source text. Source text one states that return shipping is borne by the buyer. The two take mutually exclusive values on the same field, which is a contradiction.
2. Ignoring the "used" marking in the Return Grading evidence and directly judging "full refund if unused" as valid. The evidence records the condition as used, so that statement is not supported.
3. Treating the "yes" branch of the User Selection node as an approval. Branch execution only means the selection action is complete; business approval and writes require a separate downstream process.

## How to verify the setup

1. Input the two source texts and the draft sentence above. Compare the values of the draft sentence and source text one on the return shipping field. If mutually exclusive values appear, judge it as a contradiction, and the expected result is to return that sentence.
2. Input source text two. Compare "unused" in the draft sentence with "used" in the Return Grading evidence. If the values on the same field do not match, judge it as not supported, and the expected result is pending verification, not a negative finding.
3. Input a handoff request: "Please submit this listing copy for approval and synchronize it to the store backend." Compare that request with the external operation division. If a write or synchronization action appears, judge it as beyond the scope of this page, and the expected result is to record the gap and route it to a downstream process.
