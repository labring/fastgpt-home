# General export declarations: retrieval for copy drafting

## What the documents look like

General trade export declaration work generates an export declaration form, a commercial invoice, a packing list and a contract for every shipment. Classifying commodity codes, completing the declaration form, and reconciling freight and insurance are the three most time-consuming steps. Export declaration also affects the matching of export tax rebate vouchers, and a declaration error can lead to document return inspection and blocked rebate processing.

Copy drafting for goods and marketing draws product names, specifications, quantities, transaction terms and trade terms from these materials. The retrieval input therefore carries a clear document source and a single-shipment scope. Each shipment refreshes the underlying records, and the drafting step depends on which shipment's materials are in scope.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Semantic retrieval, full-text retrieval and hybrid retrieval each have their own fit. Hybrid retrieval merges multiple result paths through RRF, and result reranking uses a ReRank model for a second ordering. The minimum relevance value is a filtering threshold that takes effect only under semantic retrieval or when result reranking is used. It does not perform permission or entity isolation, and retrieval itself does not constitute authorization. The reference limit is measured in tokens, so declaration materials of uneven length can be cut mid-section. Question optimization performs coreference resolution and question expansion, calls the model an extra time, and can alter the subject.

Hypothetical paper exercise sample: a document specialist at a foreign trade company cites a commercial invoice in a draft. The invoice reads: "Invoice No. INV-2024-0871, Contract No. CT-2024-033, product name stainless steel flange, quantity 1200 pieces, transaction terms FOB Shanghai, invoice date 6 May 2024." The packing list in the same batch reads: "Packing list No. PL-2024-0871, corresponding invoice No. INV-2024-0871, quantity 1200 pieces, gross weight 2400 kg." The draft sentence under review is: "This batch of stainless steel flanges totals 1200 pieces, traded on FOB Shanghai terms, and customs release of the export declaration form has been obtained." The question is whether the cited materials support that draft sentence.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | Reason and comparison object |
| --- | --- | --- |
| Associated knowledge bases | Associate only the knowledge base holding this shipment's invoice, packing list and contract | First check each base's vector model identifier and exclude those that differ |
| Search mode | Hybrid retrieval | Compare item by item against semantic retrieval alone and full-text retrieval alone |
| Reference limit | Set to a token amount covering the full invoice and packing list | Compare against a smaller value covering only the invoice fragment to see whether content is complete |
| Minimum relevance | Start at a middle value, then adjust up and down | Compare hit results against labelled relevant and irrelevant samples |
| Question optimization | Enable for follow-up questions containing references | Compare against the disabled state to see whether the subject is altered |
| Result reranking | Enable when candidates are numerous | Compare against the non-reranked state to see the ordering of relevant entries |

All values in the table are hypothetical starting points for this exercise, not official defaults.

## Three common errors

1. Treating minimum relevance as a permission or entity filter. A retrieval score reflects content relevance only. Unauthorized records are not excluded by a threshold, and access scope must be checked separately.
2. Associating knowledge bases with different vector models. The node requires the same vector model. Check identifiers first and exclude non-conforming bases; do not run cross-model retrieval to compare missed recalls.
3. Using the draft sentence to assert declaration status directly. The sample source text records only invoice and packing list fields and does not record the release fact. That sentence is unsupported, and the evidence gap must be recorded.

## How to verify the setup

1. Input the invoice source text above and the draft sentence. Compare whether "customs release of the export declaration form has been obtained" appears in any of the materials. When the materials do not record that status, judge it unsupported and keep a gap record.
2. Input "1200 pieces" and "FOB Shanghai" from the draft sentence. Compare the corresponding fields in the invoice and packing list. When the two quantities match and the transaction terms appear in the invoice, that part is supported. When the packing list quantity differs, record it as a same-field contradiction pending verification.
3. Use a paper input of an empty reference array to check the downstream chain. Confirm that the output chain still runs when the reference length is 0, and record the downstream behaviour actually observed. Do not presuppose that retrieval necessarily returns an empty array.

This page addresses only general trade export declaration, copy drafting for goods and marketing, and knowledge base retrieval and recall. Whether a specific promotional sentence in product copy is supported by the materials cannot be turned into an enterprise identity certification tutorial.
