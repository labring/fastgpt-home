# Amazon FBA preparation: workflow routing for copy drafting

## What the documents look like

Amazon FBA preparation moves inventory into platform-operated warehouses ahead of demand. The category's central risks are inbound discrepancies and inventory age, and errors can produce stockout-related ranking loss, higher storage fees, or failed claims. The working documents are the FBA inbound plan, box labels, inventory reports, and compensation applications. These materials update daily or weekly.

For copy drafting, the relevant facts inside those documents are product names, specifications, inbound batch identifiers, and quantity scopes. The documents supply operational facts. They do not supply promotional substantiation, and a name or quantity appearing in an inbound plan does not authorize a marketing claim. A draft sentence can only be checked against the fields the source materials actually state.

## Constraints at the workflow routing step

In FastGPT v4.17.2, the form input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and the workflow continues after the user completes the interaction. The node collects the required form values the user submits and passes them to later nodes. The user selection node is also a user interaction node with the same interaction-state behavior. When the user makes a selection, the node evaluates that selection and executes the corresponding branch. Both nodes can be added repeatedly and can trigger execution.

For this task, the routing step collects the copy type and the target material scope through an interaction node, then passes the collected values downstream to retrieval or evaluation nodes. Retrieval is not authorization, and a relevance score is not a category, entity, or permission filter. A similarity setting does not exclude unrelated businesses or unauthorized records. Same-model retrieval association applies within the documented condition; libraries using different vector models cannot be associated together, so model identifiers must be checked and non-matching libraries excluded rather than compared.

Hypothetical paper test case, clearly labelled as hypothetical and not drawn from real records: the material text reads "FBA inbound plan number PLN-2024-0311, product stainless steel vacuum flask 500 ml, planned inbound quantity 1,200 units, effective date 11 March 2024"; and "the inventory report shows 860 units of this product in warehouse, report date 10 March 2024." The draft sentence to be judged is "this product has sufficient stock on hand to support immediate replenishment of 1,200 units." The judgment requires the same subject, the same period, and the same field. The materials state a planned inbound quantity and an in-warehouse quantity. They do not state sellable inventory or replenishment authorization, so the draft sentence remains unsupported.

## Configuration and implementation checks

| Configuration item | Value or check on this page | Basis and boundary |
| --- | --- | --- |
| Form input node | Collect copy type and target material number | Submitted values pass to later nodes |
| User selection node | Select "reference inbound plan" or "reference inventory report" | The corresponding branch executes after the selection |
| Retrieval input | Use the material number passed from the previous step | The interaction node output feeds the next node |
| Empty-result handling | Check the downstream branch design against paper input `[]` | No claim that retrieval must return empty |
| Vector model identifier | Check identifier consistency across the retrieval libraries | Libraries with different models are not associated together |
| External write-back | Final copy write-back requires a separate business interface | The nodes do not perform database writes |

## Three common errors

1. Treating "sufficient stock on hand" in the draft sentence as supported by the materials. The materials give a planned inbound quantity and an in-warehouse quantity, and do not state a sellable-stock definition. The comparison should record the sentence as unsupported.
2. Treating the user selection node's branch as an automatic judgment. The node executes the corresponding branch after the user makes a selection. While no selection has been made, the workflow remains in the interaction state.
3. Treating retrieval relevance as a permission or entity filter. Relevance does not exclude unrelated businesses or unauthorized records, and retrieval by itself does not constitute authorization.

## How to verify the setup

1. Input the hypothetical material text and the draft sentence given above, then compare whether the draft sentence falls within the fields the materials state. When the sentence contains "sufficient stock on hand," which the materials do not state, the result should be recorded as unsupported. This is an expected comparison, not a completed test.
2. Input the submitted values of the form input node and compare whether the values received by later nodes match the submitted values. The condition is satisfied when the submitted values pass through completely to the retrieval or evaluation node.
3. Input the paper empty result `[]` and compare whether the downstream branch handles it as designed. The condition is satisfied when the downstream design provides an explicit handling path for empty input. Whether actual retrieval returns empty remains unknown.

The verification scope is limited to this page's primary task: whether a proposed copy sentence is supported by the supplied material wording and its stated limits. It does not extend to identity certification, report analysis, or any other task.
