# Amazon FBM fulfillment: workflow routing for copy drafting

## What the documents look like

Amazon FBM fulfillment is operated by the seller, who handles delivery and sets the return address without relying on platform warehouse inspection. The daily document set for this category includes order picking lists, shipment confirmation forms, return address settings and logistics tracking sheets. These records update per order and per day. Drafting product and marketing copy draws on the verifiable fulfillment facts recorded in these documents: carrier name, tracking number, return address and order status. Statements in drafted copy about dispatch timing or return conditions need to correspond to actual fields in those documents. Where a field is not present, the corresponding claim has no support in the material and cannot be treated as confirmed.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. Required information collected on submission is passed to subsequent nodes. The User Selection node behaves the same way at the interaction level and, once the user makes a choice, evaluates that choice and executes the corresponding branch. Both nodes wait for user interaction before the workflow proceeds. For copy drafting, the Form Input node is suited to collecting product facts and target market details needed for a draft, and the User Selection node is suited to deciding between alternative copy directions.

External operations must be separated from these nodes. Order writes, document backfill and external status synchronization require a separate business interface or a downstream process. The interaction nodes themselves do not perform those actions. A collected value is a collected value; business verification, approval and database writes need their own downstream implementation.

Hypothetical paper exercise. A logistics tracking sheet contains the following three sentences: "Order number A-001, carrier is an overseas local carrier, tracking number TR-8801, dispatch date 5 March 2024, return address is a warehouse address in a US state." A draft sentence under review reads: "This product supports 30-day no-reason returns and ships from a local US warehouse." The material records only that the return address is a warehouse address in a US state. It does not record a 30-day return period, and it does not record that the dispatch location is a local US warehouse. Both the return period and the dispatch location in the draft sentence lack support in the material. The draft must be returned for additional material or revised wording.

## Configuration and implementation checks

| Configuration item | Setting or check content | Relationship to this page's documents |
| --- | --- | --- |
| Form Input node | Enters interaction state on trigger, collects required information, passes it to subsequent nodes | Collects product facts needed for drafting |
| User Selection node | Executes the "yes" branch after the user makes a choice; verify branch connections one by one | Decides between alternative copy directions |
| Interaction state check | Recording state is behavior of the interaction node; no separate global state switch is set | Confirms the waiting behavior of interaction |
| Output handoff check | Pass collected information explicitly to subsequent retrieval, judgment or interface nodes | Compare outputs against inputs item by item |
| External operation separation | Order writes, document backfill and external status synchronization require a separate business interface | Finalized copy does not write to orders automatically |
| Hypothetical trial starting value | This exercise uses 30 days as a candidate return period, compared against the tracking sheet text | Hypothetical for this exercise only, not an official default |

## Three common errors

1. Treating "30-day no-reason returns" in the draft sentence as an already verified fact. The logistics tracking sheet records only the return address and does not record a return period, so the statement lacks support.
2. Treating information collected by the Form Input node as completed business verification. The node collects values; business verification, approval and database writes require downstream implementation.
3. Treating the "yes" branch of the User Selection node as the only path. Branch connections must be verified one by one, and an unconnected branch does not execute.

## How to verify the setup

1. Input the tracking sheet text and the draft sentence from the hypothetical exercise, then compare "30 days" against the return period field in the source text. When the source text does not record that field, the result is unsupported and the draft needs additional material or revised wording.
2. Input the product facts collected by the Form Input node and compare whether they are passed completely to subsequent retrieval or judgment nodes. The condition is met when outputs correspond to inputs item by item.
3. Input the two branch options of the User Selection node and compare the selection result against the branch execution record. Selecting "yes" executes the corresponding branch; selecting the other option does not execute that branch. An empty result handoff can be checked against the downstream design using an explicit paper input of [], without claiming that a fictional rule retrieval necessarily returns [].
