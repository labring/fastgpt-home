# JD POP seller operations: retrieval for copy drafting

## What the documents look like

JD POP third-party store operations work with four recurring document types: product information sheets, dispatch-time commitments, dispute handling forms, and warranty-period service records. These materials update daily and are produced per order. For product and marketing copy drafting, the subject to be checked is the store and the product itself, the object is the proposed promotional sentence, and the state is whether the materials support that sentence.

Frequent updates mean a retrieval pass may return an earlier version of a product information sheet. Before drafting, confirm that the cited material matches the current product state. Because open-platform dispute rules and warranty-period service documents coexist, one product may have both a dispatch-time commitment and a warranty-period service record. Retrieval must be able to distinguish the fields each material covers. The category differs from a flagship-store context in that POP operations commonly center on open-platform dispute rules and warranty-period service documents.

## Constraints at the retrieval step

A knowledge base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases with different vector models cannot be associated together. Check the vector model identifier first and exclude any that do not match. Reference content is output as an array and its length can be 0, which means the output path still runs even when nothing is retrieved.

The minimum relevance score is a filter threshold and takes effect only under semantic retrieval or when result reranking is used. It does not perform permission or entity isolation. Hybrid retrieval merges multiple result paths through RRF; RRF is a fusion process, not a switch that can be turned on. Reranking requires a model and must be enabled by configuration. Image retrieval requires corresponding image input and model capability. The optional paths shown in the documented flow diagram do not all execute on every request.

Hypothetical paper exercise sample: the source material for the product information sheet reads, "Product information sheet states: this item is a household stainless steel vacuum flask, capacity 500 ml, material 304 stainless steel, applicable temperature range -20°C to 100°C." The dispatch-time commitment reads, "This store commits to dispatch within 48 hours after payment; during major promotions the product page notice applies." The draft sentence to be assessed is, "This vacuum flask uses 304 stainless steel, has a capacity of 500 ml, and can withstand temperatures from -20°C to 100°C." The check is whether the subject, capacity, material, and temperature range in that sentence are all covered by the source material.

## Three common errors

1. Treating the minimum relevance score as a permission or entity isolation mechanism. Incorrect manifestation: assuming that raising the threshold excludes other stores or unauthorized records. The input to check is the draft sentence and the retrieval scope; compare whether the actual retrieved content still contains fragments from unrelated stores. The observable result is that threshold changes do not affect permission boundaries.
2. Forcing knowledge bases with different vector models into a joint association. Incorrect manifestation: associating a product base and a dispute base that use different vector models and expecting normal retrieval. The input to check is the vector model identifier of each base; compare whether the identifiers match. The observable result is that non-matching bases are excluded, and no further inference about runtime results should be drawn.
3. Judging an unstated field as contradictory. Incorrect manifestation: the material only says "warranty-period service record" without a specific period, yet the draft sentence's period wording is judged to conflict with the material. The input to check is the source material text and the draft sentence; compare the values for the same field. The observable result is that the field is not stated, so the conclusion should be unsupported or pending verification.

## How to verify the setup

1. For the hypothetical sample, input the draft sentence "This vacuum flask uses 304 stainless steel, has a capacity of 500 ml, and can withstand temperatures from -20°C to 100°C." Compare the material, capacity, and temperature range fields in the source material. The condition is met when all three fields correspond word-for-word in the retrieved reference content and the subject is the same vacuum flask. If the temperature range appears only in the warranty-period service record and not in the product information sheet, record it as a different field source and do not judge it as contradictory.
2. For empty-result continuation, input the paper input []. Compare whether the downstream design continues along the path where reference length is 0. The condition is met when the downstream can accept an empty array and record the gap; do not require a fabricated rule retrieval to return [].
3. For cross-model association, input the vector model identifiers of two knowledge bases and compare whether the identifiers match. The condition is met when only matching identifiers can be associated together; non-matching ones are excluded and the actual observation is recorded. Do not execute cross-model retrieval to compare missed recalls.

These checks address the named primary task: whether a proposed promotional sentence is supported by the supplied source wording. They do not extend into identity certification, report analysis, or any other task.
