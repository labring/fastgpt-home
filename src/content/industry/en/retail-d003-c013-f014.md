# Franchise store supervision: model connections for copy drafting

## What the documents look like

In franchise supervision, the material used to draft product and marketing copy sits in four document types: store visit forms, franchise contracts, rectification notices, and merchandising standards. Headquarters and stores produce these on weekly and monthly rhythms, and the supervisor converts the execution requirements they contain into copy that can be issued to stores.

The comparison with direct-operated convenience store fresh food ordering matters here. In the franchise setting the central action is headquarters supervising how franchisees carry out standards. When drafted copy drifts from the wording of the source material, the possible consequences are franchise disputes and damage to brand image.

These documents do not arrive with a uniform field structure. A store visit form records merchandising and order-check results. A franchise contract states the permitted scope of promotion. A rectification notice describes items awaiting correction. Merchandising standards give position and method requirements. For copy drafting, model connections need to make these documents retrievable and usable as context sent to the model, while keeping the original wording available for sentence-by-sentence checking.

## Constraints at the model connections step

Model connections depend on AI Proxy. Both the App and an Admin service that reuses App/Service configuration must set `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN`. Missing either one causes startup validation to fail. `AIPROXY_API_ENDPOINT` holds the AI Proxy service root address and does not take an appended `/v1`. The system needs at least one language model and one index model to work normally. The model ID is the value of the `model` field in the request body and is globally unique; the model name is for display only.

Retrieval libraries and vector models carry an association constraint: libraries across different vector models cannot be associated together. Checking should first confirm the identifier, exclude non-matching items, and then record the actual observation. A relevance score does not carry permission or entity-isolation duties, and retrieval itself does not constitute authorization.

Hypothetical paper exercise sample (paper material, not a real record): an attachment to a franchise contract states that "summer drink promotion for this brand may use material images provided by headquarters; recommendation text written by the store must not contain efficacy claims." A rectification notice from the same month states that "the freezer display at the XX Road store was not executed according to standard; correction is limited to seven days." A draft sentence awaiting judgment reads: "The drinks at this store clear heat and relieve summer heat, with notable effects." The object of checking is whether this draft sentence falls inside the promotion scope the contract permits.

## Configuration and implementation checks

| Configuration item | Hypothetical starting value for this exercise | Reason for the choice and comparison object |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | The AI Proxy service root address, with no appended `/v1` | Matches the documented requirement; the comparison object is a form with `/v1` appended |
| `AIPROXY_API_TOKEN` | A non-empty administrator token consistent with the server side | Documentation requires non-empty and consistent; the comparison object is an application API key |
| Language model and index model | At least one of each enabled | Documentation requires at least one of each; the comparison object is enabling only a language model |
| Model ID | Consistent with the "model" field in the channel | Documentation states the two are consistent; the comparison object is the display model name |
| Context scope sent in | Only the text of that contract attachment and rectification notice | Limited for this exercise; the comparison object is mixing in material from other stores |
| Retrieval result checking | Record the material identifier of each hit | Limited for this exercise; the comparison object is recording only the relevance score |

## Three common errors

1. Treating the display model name as the model ID in the request body. The input is the model name in the channel list, the comparison object is the "model" field in the channel, and the observable result is whether the two are consistent.
2. Using the relevance score in place of a permission judgment. The input is the score returned by retrieval, the comparison object is the range of material this user may access, and the observable result is whether the score level is treated as a basis for authorization.
3. Recording an unstated item as a negative finding. The input is a promotion method the contract attachment does not mention, the comparison object is the permitted scope the attachment does state, and the observable result is whether that method is recorded as unsupported or as prohibited.

## How to verify the setup

1. Take the contract attachment text and the draft sentence "The drinks at this store clear heat and relieve summer heat, with notable effects" from the hypothetical sample. The input is these two passages, the comparison object is the attachment wording "must not contain efficacy claims," and the observable result is whether the draft sentence falls inside that prohibited range. The expectation is that it falls inside the range; this expectation has not been tested.
2. Take the rectification notice text from the hypothetical sample. The input is that notice, the comparison object is the period wording "correction is limited to seven days," and the observable result is whether the notice states a start date. If no start date is stated, record it as awaiting verification rather than judging it overdue.
3. Take the list returned by a retrieval call. The input is the returned items from one retrieval, the comparison object is the vector model identifier each item belongs to, and the observable result is whether libraries across different vector models are associated together. If such an association exists, exclude the non-matching items and record the actual observation; if the return is empty, check the downstream design against the paper input `[]` rather than claiming that retrieval under a fictional rule necessarily returns empty.
