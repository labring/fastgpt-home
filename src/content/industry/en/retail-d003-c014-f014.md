# Convenience fresh-food orders: model connections for copy drafting

## What the documents look like

Convenience-store fresh-food ordering revolves around short-shelf-life items. Stores place orders frequently, by day or by shift, and the working documents are the fresh-food order form, the loss report, the near-expiry handling sheet, and the temperature record. The data sources named in the brief are POS sales, the headquarters ordering system, store inventory, and cold-chain temperature records. The three most time-consuming steps are forecasting next-day sales, checking shelf life, and registering losses.

For copy drafting, those documents set the material boundary. Usable content comes from dates, quantities, statuses, and temperature ranges already recorded on those sheets. Promotional wording that the documents do not carry stays unsupported. The brief gives daily and shift-level update frequency, and this page checks material only at that granularity. It does not infer batch synchronization, real-time triggers, or transaction-triggered mechanisms.

## Constraints at the model connections step

This page covers copy drafting for fresh-food goods and marketing text. Model connection and configuration only establishes the conditions for feeding material into a model and obtaining a draft. It does not perform business approval of the copy itself.

Per the official documents, FastGPT connects to model providers through AI Proxy. From V4.17.0, AI Proxy is a required dependency. Both the App and the Admin service that reuses App/Service configuration must set `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN`; missing either one causes startup validation to fail. Older OpenAI environment variables or a single-model custom request address cannot replace these two settings. The system needs at least one language model and one index model to work normally, and only one speech-recognition model takes effect.

Model capability is checked separately for each input the application needs. Multimodal input, tool calling, and thinking configuration are verified individually. Application parameters are set in the application or node configuration, and it cannot be assumed that a same-named field on a compatible chat interface overrides orchestration. Retrieval and relevance scores affect text recall ranking only; they do not constitute permission or entity isolation. Libraries that share a vector model can be associated together, and this requirement does not extend to external systems.

### Hypothetical paper test case

The following is a paper exercise for explaining the checking method. It does not represent any real store, real document, or executed test.

Material text one (fresh-food order form): Store A, object is a rice-ball product line, date 23 September 2026, order quantity 40 units, status submitted to the headquarters ordering system.

Material text two (temperature record): For the same store and date, the cold-chain temperature record shows a refrigerated cabinet range of 2 to 5 degrees Celsius, record status registered for the shift.

Material text three (near-expiry handling sheet): For the same store and date, the near-expiry handling sheet states the batch shelf life runs to 24 September 2026 at 12:00, handling status pending store confirmation.

Draft sentence to be judged: This store's rice balls are made fresh on the day, held at constant temperature all day, with guaranteed quality.

## Three common errors

1. Treating promotional wording absent from the material as supported. The draft sentence says "made fresh on the day," while the order form records only order quantity and submission status, with no production-time field. Comparing the material text against the draft sentence shows the draft sentence lacks a corresponding field.
2. Expanding a recorded temperature range into "constant temperature all day." The temperature record states only a shift range of 2 to 5 degrees Celsius and does not cover the full day. Comparing the record's covered period against the draft wording shows the ranges do not align.
3. Treating a near-expiry handling status of pending store confirmation as completed handling. The handling sheet status is pending store confirmation. Comparing the status field against the conclusion implied by the draft sentence shows handling is not complete.

## How to verify the setup

1. Input material text one and the draft sentence. Compare whether the order form carries a production-time field. The observable result is that the field does not appear, so "made fresh on the day" is unsupported.
2. Input material text two and the draft sentence. Compare the period covered by the temperature record against the "all day" wording. The observable result is that the record covers only the shift, so "constant temperature all day" is unsupported.
3. Input material text three and the draft sentence. Compare the handling status field against the "guaranteed quality" conclusion. The observable result is that the status remains pending store confirmation, so the conclusion is not yet verified. If retrieval returns an empty result, an explicit paper input of an empty list can be used to check the downstream design, without claiming that a fictional rule necessarily returns empty.
