# Convenience fresh-food orders: interactive forms for copy drafting

## What the documents look like

Convenience-store fresh food is ordered by the store at high frequency against short shelf life, and it is not handled as a joint-operation revenue share. The data sources tied to that difference are POS sales, the headquarters ordering system, store inventory, and cold-chain temperature records. The working documents are the fresh-food order form, the damage/loss report, the near-expiry handling sheet, and the temperature record. Update frequency is daily or per shift. This page covers only product and marketing copy drafting. It does not cover order quantity calculation, damage-report approval, or temperature compliance decisions.

The materials carry different scopes. An order form identifies a store and a batch with an order date and a shelf-life end date. A near-expiry handling sheet records a state change for that batch on a given date. A temperature record covers one leg of the cold chain, such as transport, on one date. None of these documents automatically covers store storage temperature, and none of them, by itself, supports a claim about the whole chain.

## Constraints at the interactive forms step

The Form Input node is a user-interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues downward after the user completes the interaction. The node collects the information the user fills in and passes it to later nodes. It does not include business database functions. The User Selection node is also a user-interaction node with the same interaction-state behavior; when the user makes a choice, the node evaluates that choice and executes the corresponding branch. It does not act as a personnel directory or a business-data selector. Field validation, business approval, write-back, and batch operations require an external system or a later node.

Hypothetical paper exercise, not submitted or tested. Material text one: "The fresh-food order form for this batch corresponds to Store A, order date 10 March 2025, shelf life to 12 March 2025." Material text two: "The near-expiry handling sheet records that this batch moved to near-expiry status on 11 March 2025." Material text three: "The temperature record shows 4 degrees Celsius for the transport leg on 10 March 2025." Draft sentence to be assessed: "This batch of fresh food was at a safe temperature throughout and did not enter near-expiry status." The subject required for assessment is Store A and the same batch; the period is 10 to 12 March 2025; the fields are temperature and near-expiry status. Material text three covers only the transport leg, not store storage temperature. Material text two states that the batch did enter near-expiry status. The draft sentence contradicts material text two on the same batch, same field, with mutually exclusive values. The "safe temperature throughout" part lacks evidence for store storage and is unsupported. This exercise is a paper scenario only.

## Configuration and implementation checks

| Configuration item | Type | Use on this page |
| --- | --- | --- |
| Form Input node | Documented node behavior | Collects the draft sentence, the source material text, and the batch identifier, then passes them to later nodes after submission |
| User Selection node | Documented node behavior | Presents a branch choice on whether the draft sentence and the material share the same batch and period, then executes the selected branch |
| Required-information check | Manual review action | Lists the three items this task cannot omit: batch, date, field; records a gap when any is missing |
| Interaction state | Documented node behavior | Records the workflow state on trigger and waits for the interaction before continuing downward |
| Downstream division of work | Requires a separate system | Field validation, approval, write-back, and batch operations are implemented in an external system or a later node |

Hypothetical starting value for this exercise: set "chain leg covered by the material" to "transport leg," because that value comes from the explicit statement in material text three. The comparison target is the "throughout" scope claimed by the draft sentence. When the two scopes do not match, mark the claim as unsupported. This starting value is a paper setting, not an official default.

## Three common errors

1. Treating "throughout" in the draft sentence as equivalent to the transport-leg temperature in material text three without comparing coverage scope. The missing evidence for store storage then goes unnoticed.
2. Reading "the near-expiry handling sheet records a move to near-expiry status" as "approaching near-expiry but not yet entered." This changes the status value in material text two and removes the mutually exclusive relationship on the same field.
3. Assuming that after Form Input submission the system automatically completes a temperature compliance decision or a damage-report write-back. The node passes the filled-in information only; those business actions require an external system.

## How to verify the setup

1. Input the hypothetical material texts one, two, and three together with the draft sentence. Compare the batch, date, and near-expiry status fields between the draft sentence and material text two. If the same batch and the same field hold mutually exclusive values, output "contradiction." If store storage temperature evidence is missing, output "unsupported." Do not substitute a constructed case for this input.
2. Input Store A, the period 10 to 12 March 2025, and the temperature field from the hypothetical exercise. Compare the chain leg covered by material text three with the scope claimed by the draft sentence. If the scopes differ, record "insufficient coverage, pending verification" and do not classify the result as a negation or a conflict.
3. Input a paper-labelled empty material list []. Check whether the downstream design distinguishes an empty result from "the material does not exist." If the downstream treats the empty result directly as a negative conclusion, record that design gap. Do not claim that a fictional rule retrieval necessarily returns an empty array.

A relevance score is not a category, entity, or permission filter, and retrieval is not authorization. Similarity settings do not exclude unrelated businesses or unauthorized records.
