# Letter-of-credit documents: workflow routing for copy drafting

## What the documents look like

Letter-of-credit document examination and presentation serves the payment conditions of a bank. The working focus is consistency across documents rather than the tax-matching logic used in export tax rebate filing. The main data sources are issuing bank notices, UCP600 clauses, freight forwarder bills of lading, and bank presentation records. The documents handled in daily work are the letter of credit, commercial invoice, bill of lading, insurance policy, and draft. Data updates per shipment.

This page covers product and marketing copy drafting. Workflow routing must compare proposed copy sentences against those materials item by item and decide whether a promotional statement is supported by the material. The material usually contains the parties, goods description, amount, shipment period, and validity period. Copy must not exceed those ranges.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. Required information is collected and, after submission, passed to downstream nodes. The User Selection node is also a user interaction node. When the user makes a choice, the node evaluates that choice and executes the corresponding "yes" branch. Branch connections need to be verified one by one. The interaction state is existing node behavior; no separate global state-recording switch is set.

Collected information must be explicitly passed to downstream retrieval, judgment, or interface nodes, and outputs must be compared against inputs item by item. Order writing, document backfill, and external status synchronization require a separate business interface or downstream process; interaction nodes do not perform them automatically. Semantic recall and relevance scores in a retrieval library do not carry permission or entity isolation. Libraries using different vector models cannot be associated together; identifiers must be checked first, non-matching items excluded, and actual observations recorded.

Hypothetical paper exercise sample: a letter-of-credit notice states "beneficiary is Company A, goods are stainless steel vacuum flasks, quantity 2,000 units, shipment period March 2026, validity until April 15, 2026." Proposed copy sentence to be judged: "This product has passed EU CE certification and is suitable for all age groups." The material does not state certification information or applicable age range. The sentence exceeds the material scope and is unsupported. Handoff request to be judged: "Please confirm the invoice quantity against the bill of lading quantity and synchronize it to the order system." The material does not state a bill of lading quantity field, and order system synchronization requires a separate interface. This item is pending verification and needs downstream implementation.

## Configuration and implementation checks

| Configuration item | Use on this page | Basis and boundary |
| --- | --- | --- |
| Form Input node | Collect proposed copy sentences and corresponding source material text | After submission, information is passed to downstream nodes |
| User Selection node | Judge whether a proposed sentence is supported by the material | Connect subsequent steps via the "yes" branch |
| Interaction state check | Confirm the node enters interaction and records state | Existing node behavior; no additional switch |
| Output handoff check | Compare collected information with downstream node inputs | Compare item by item; do not assume automatic judgment |
| External action separation | Order writing and document backfill | Requires a separate business interface or downstream process |
| Retrieval scope check | Check material identifiers and vector models | Cross-model association is not possible; check identifiers first |

Hypothetical trial starting point: set the number of manual reviews for the supported/unsupported judgment of a proposed sentence to 1. The reason is that the number of copy sentences per shipment is limited. Compare against sentence-by-sentence review results and observe whether any judgment is missed. This value is only a starting point for this paper exercise and is not an official default.

## Three common errors

1. Treating a certification or applicability scope not stated in the material as already supported. In the sample, the proposed sentence mentions CE certification and all age groups, while the material contains only the goods name, quantity, shipment period, and validity period. After comparison, this should be recorded as unsupported, not as contradictory or negated.
2. Treating order system synchronization in the handoff request as existing node behavior. The Form Input and User Selection nodes only collect and pass information. Order writing and external synchronization require a separate business interface. The sample request should be recorded as pending verification with a note on the downstream implementation gap.
3. Using a relevance setting to exclude unrelated businesses or unauthorized records. Relevance is a retrieval ranking result and does not carry permission or entity isolation. Libraries using different vector models cannot be associated together; check identifiers, exclude non-matching items, and record actual observations.

## How to verify the setup

1. Input the sample material text and the proposed copy sentence. Compare whether the proposed sentence contains certification and applicable age range not stated in the material. Expected observation: the judgment result is unsupported, and the material gap is recorded as missing certification information and applicable age range fields.
2. Input the handoff request and the material text. Compare whether the request asks the node to write to the order system automatically. Expected observation: the judgment result is pending verification, with a note that order writing and external synchronization require a separate business interface and are not performed by interaction nodes.
3. Input an empty-result paper input []. Compare whether the downstream node is designed to handle an empty result. Expected observation: the downstream handles it via the empty-result branch. Do not claim that a fictional rule retrieval necessarily returns []. If the retrieval library identifier and vector model do not match, record the actual observation and exclude non-matching items; do not run cross-model retrieval to compare missed recalls.
