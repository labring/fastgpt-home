# Franchise fee settlement: workflow routing for copy drafting

## What the documents look like

Franchise fee and deposit settlement centers on funds and breach deductions. It does not handle government filing. The main materials come from the finance system, the franchise contract, bank statements, and store violation records. Everyday documents include franchise fee invoices, deposit ledgers, deduction notices, and contract payment schedules. These materials determine whether draft copy can state the nature of a fee, the reason for a deduction, and the conditions for a refund.

The supplied brief gives an update frequency of monthly and per deduction. This page uses that cadence only to describe the rhythm of the source material. It does not infer batch synchronization or real-time triggering. In copy drafting, the three most time-consuming steps are checking contract payment terms, confirming the reason for a deduction, and issuing an invoice. Workflow routing needs to map these three material types to individual draft sentences.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and the dialog box is hidden. After the user completes the required fields and submits, the node collects the submitted form information and passes it to later nodes. The User Selection node also enters an interaction state and records workflow state. When the user makes a choice, the node evaluates that choice and executes the "yes" branch. Both nodes wait for the user to finish interacting before the workflow continues.

The documents do not describe a control switch for the interaction state, a submission count limit, or automatic judgment. Those remain unknown. The knowledge base association requirement applies only within the same vector model in the same library. It does not extend to business registration sites or other external systems. A relevance score does not perform permission or entity isolation, and retrieval does not constitute authorization. Order writes, document backfill, and external status synchronization require a separate business interface or a later workflow stage.

Hypothetical paper test case: the source material reads, "Party A shall pay the brand usage fee of 8,000 yuan before the tenth day of each month; if Party B pays late by more than fifteen days, Party A may deduct a penalty from the deposit and shall notify Party B in writing after the deduction." The draft sentence under review reads, "If the franchisee pays late, the deposit will be automatically deducted in full." Checking this sentence, the material supports only "may deduct a penalty" and "written notice." It contains no wording about automatic execution or full deduction.

## Configuration and implementation checks

| Configuration or check item | Purpose on this page | Basis and boundary |
| --- | --- | --- |
| Form Input node | Collect the draft sentence, source material, and fee type | Submitted information passes to later nodes |
| User Selection node | Make a manual choice on the "whether deduction is permitted" branch | The "yes" branch runs according to the choice |
| Interaction state check | Confirm the wait and state-recording behavior | No separate global state switch is set |
| Output handoff check | Compare collected information with downstream input | Compare output and input item by item |
| Knowledge base association check | Confirm the same vector model identifier | Libraries with different models cannot be associated together |
| External operation division | Mark that writes and synchronization need a separate implementation | The nodes do not complete business actions automatically |

This page does not specify numeric default values. If a test needs a starting value, a hypothetical "late payment day threshold" of fifteen days may be assumed. The reason is that it matches the sample material, and the comparison method is a word-by-word check against the contract clause.

## Three common errors

1. Writing "may deduct a penalty" as "automatically deducted in full." The input is the sample draft sentence and the source material. Compare the deduction method and the amount scope. When the material contains no wording about automatic execution or full deduction, the draft sentence is unsupported.
2. Treating a retrieval relevance score as a permission filter. The input is one in-library retrieval setting. Compare the score with the authorization record. A high score does not mean the record has been authorized.
3. Treating the "yes" branch of the User Selection node as an approval. The input is one selection record. Compare the selection result with an approval document. The selection itself does not constitute approval.

## How to verify the setup

1. Check the sample source material against the draft sentence. Input the two texts. Compare the deduction method, the amount scope, and the notice obligation. The draft sentence counts as supported only when it matches the material on the same subject, the same period, the same field, and the same value. Record any wording about automatic execution or full deduction as unsupported.
2. Check empty-result handoff with the paper input `[]`. Input an empty list. Compare whether the downstream node handles it through the empty-result branch, and observe whether an undefined output appears. Do not claim that a search under a fictional rule necessarily returns empty.
3. Check association with the same vector model identifier. Input the model identifiers of two libraries. Compare whether they match. When the identifiers differ, exclude that library and record the actual observation. Do not run a cross-model search to compare missed recall.
