# On-demand retail fulfillment: copy drafting with context limits

## What the documents look like

For copy drafting in On-demand retail fulfillment, this page examines FastGPT context limits. Inspect picking demonstrations, historical closed orders and current stock evidence with their separate times and subjects. The examples are hypothetical.

## Constraints at the context limits step

A proposed instant-retail introduction demonstrates picking steps while explicitly lacking delivery records and leaving current saleable items to be checked. Historical copy concerns another order that closed. The present task explains a demonstration rather than reporting live stock or a new order’s outcome. Inspect whether demonstration identity, order subject and the material’s stated period reach the actual request before examining historical events. Describing the supplied steps establishes neither delivery nor a current catalogue of saleable goods.

## Configuration and implementation checks

| Context check | Material in this test | Acceptance action |
| --- | --- | --- |
| Material identity | Picking demonstration | Do not recast it as fulfillment. |
| Order referent | A different historical order closed | Inspect which order this refers to. |
| Stock scope | Saleable items need separate evidence | Trace each item’s status. |
| Event time | Source period differs from retrieval time | Do not infer progress from retrieval date. |
| Structured result | Separate demonstration and facts | Inspect their sources after parsing. |

## Three common errors

- If demonstration identity is lost and displayed steps become completed fulfillment, compare the original note, actual input and completion wording.

- If a follow-up about this order borrows another closed order’s record, hold current material fixed across history conditions and inspect order identity and event time.

- If saleable items are listed without a current stock source, trace each name and status. Appearance in a demonstration establishes no present availability.

## How to verify the setup

Ask what the demonstration did, which order has an outcome and whether current stock evidence exists, tracing each sentence to actual input. When delivery or stock material is added, inspect subject and period separately; later retrieval is not a later event. Check citation limits apart from reply length. Actual model capability and context configuration need their own basis; one successful call measures no complete window. Parse structured store descriptions before checking the demonstration-versus-business distinction. This test places no order and publishes no promotion; retain visible evidence gaps.
