# Certificates of origin: workflow routing for copy drafting

## What the documents look like

Origin certificates serve import-country tariff and customs clearance purposes, and they are not necessarily bound by a letter of credit. That difference sets the material boundary for copy drafting in this category: the origin certificate application, the commercial invoice, the packing list, and production cost records. Letter-of-credit examination rules sit outside this boundary and are not introduced here. Materials update per shipment or in batches; this page addresses the routing of a single drafting request and does not describe batch synchronization or automatic triggering. Among the three most time-consuming steps — determining origin rules, completing the certificate, and sending documents to the customer for clearance — copy drafting receives already-completed application information and customer clearance requirements. It does not replace declaration judgment.

## Constraints at the workflow routing step

The form input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and the dialog is hidden. After the user fills in required information and submits, the node collects the submitted values and passes them to subsequent nodes. The user selection node also belongs to the user interaction nodes. When the user makes a selection, the node evaluates that selection and executes the corresponding "yes" branch. Routing must verify each branch connection one by one and pass collected information explicitly to later retrieval, judgment, or interface nodes. Order writes, document backfill, and external status synchronization require separate business interfaces or later processes; the interaction nodes themselves do not perform those actions.

Hypothetical paper exercise sample: the source material reads, "Applicant: an export enterprise; goods: plastic storage boxes; production completion date: March 10, 2026; intent to apply for a China origin certificate; customer clearance requirement: attach an English product description." The draft sentence to be assessed is, "This product originates in China and can enjoy import-country tariff preferences." The comparison object is origin qualification and tariff preference. The material states only the production completion date and the intent to apply for a certificate. It does not state an origin-rule conclusion or a preference-applicability conclusion. The draft sentence is not supported.

## Configuration and implementation checks

The table below is tied to this sample and lists documented settings or implementation checks relevant to this feature and primary task. The hypothetical starting values apply only to this paper exercise and are not official defaults.

| Configuration item | Hypothetical starting point for this exercise | Reason and comparison method |
| --- | --- | --- |
| Form input node | Enabled, with fields for applicant, goods, production completion date, and intended certificate type | The material contains these four kinds of information; compare submitted values against the source text item by item |
| Required fields | Applicant, goods, production completion date | Without any one of these fields the comparison object cannot be located; compare against the source text item by item |
| User selection node | Enabled, with branches "materials complete" and "materials pending" | The sample material lacks an origin conclusion, so it follows the pending branch and the gap is recorded |
| Output receiving node | Passes form values to a later judgment node | Compare the later node's input against the submitted form values item by item |
| Retrieval scope | Limited to origin-certificate materials the requester may access | Relevance does not perform permission filtering; records outside access rights do not enter the comparison |
| External actions | Document backfill and status synchronization are not implemented at this node | Interaction nodes collect and pass values only; writes require a separate interface |

## Three common errors

1. Treating the draft sentence "This product originates in China and can enjoy import-country tariff preferences" as already supported by the material. The material contains only the production completion date and the intent to apply. Neither the origin-rule determination nor the preference-applicability conclusion is stated. The sentence is unsupported, and the evidence gap must be recorded.

2. Treating the "materials pending" branch of the user selection node as completed supplementation. Pending is a selection result within the interaction state. Whether supplementation is complete depends on later submitted content. Until that content is submitted, the matter remains to be verified.

3. Treating retrieval relevance as a permission or entity filter. Relevance does not exclude unrelated business records or unauthorized records. Materials outside access rights must first have their identifiers checked and be excluded before they enter copy comparison.

## How to verify the setup

1. Input the sample source material and the draft sentence, then compare whether the draft sentence is supported by material with the same subject, same period, and same field. The material does not state an origin-rule conclusion or a preference conclusion. The expected observation is that the sentence is judged unsupported and the gap is retained; no definite conclusion of "originates in China" or "can enjoy preferences" appears.

2. Input the submitted form values, then compare whether the fields actually received by the later judgment node match the submitted values item by item. The expected observation is that the four fields correspond to the submitted values; when a field is missing, the flow enters the pending branch and records the gap.

3. Input an explicit paper empty result and compare how the downstream node is designed to receive an empty result. The expected observation is that the downstream node handles the empty input and records the gap. It does not claim that retrieval of a fictional rule necessarily returns an empty result, and it does not guarantee a first hit or full recall.
