# Brand member operations: workflow routing for copy drafting

## What the documents look like

Brand member private-domain operations work from customer data and repeat-purchase outreach. The materials that matter for copy drafting are member tag tables, outreach plans, coupon rules and privacy authorization records. These come from the CRM system, enterprise messaging, POS transaction records and mini-program behavior data, and they update daily or weekly. A tag table defines the audience scope, an outreach plan defines the period and channel, coupon rules define the benefit, and privacy authorization records define the usable boundary. The copy drafting step reads these materials and turns supported facts into text awaiting review.

## Constraints at the workflow routing step

Member materials update on a daily or weekly cycle. Each workflow execution reads the input supplied at that run and does not perform bulk synchronization or real-time refresh. When the Form Input node triggers, the conversation enters an interaction state that records the workflow state; after the user completes required fields and submits, the node collects the submitted information and passes it to later nodes. When the User Selection node triggers, it likewise enters an interaction state and records the workflow state; after the user makes a choice, the node evaluates that choice and executes the "yes" branch. Both nodes are user-interaction nodes, can be added repeatedly, and trigger execution. Collected information must be explicitly handed to a later retrieval, decision or interface node, and input and output must be compared item by item. Order writes, document backfill and external state synchronization require a separate business interface or later process; interaction nodes do not perform these actions themselves.

Hypothetical exercise sample. Source text for comparison: a brand member tag table states "high repeat-purchase group, three or more transactions in the last 90 days"; the outreach plan states "this period's outreach theme for this group is summer new arrivals, channel is enterprise messaging"; the coupon rules state "this group may use a spend 300 reduce 50 coupon, valid until the end of this period"; the privacy authorization record states "this member has authorized marketing outreach, scope is recommendations for this brand's products." Draft sentence to be assessed: "This brand's summer new arrivals have arrived in store, and high repeat-purchase members may claim a spend 300 reduce 50 coupon." The subject is the brand and members, the object is summer new arrivals and the coupon, the state is claimable, and the scope is this period. The materials do not state the coupon claim entry point or the in-store arrival time; these two items are unsupported.

## Configuration and implementation checks

| Configuration item | Hypothetical trial starting point | Reason and comparison method |
| --- | --- | --- |
| Form Input node fields | Member ID, outreach theme | The outreach plan distinguishes periods by theme, so fields must match that period's theme; compare period by period |
| Form Input required fields | Member ID set as required | Without an ID the record cannot be matched to the tag table; after submission check whether it passed to later nodes |
| User Selection node branches | Two branches, "confirm claim" and "not now" | These correspond to the benefit stated in the coupon rules; check whether the "yes" branch is connected correctly |
| Output receiving node | Pass submitted information to a retrieval node | Copy drafting needs to cite tags and coupon rules; compare retrieval input with form output |
| Material comparison scope | Tag table, outreach plan, coupon rules, authorization record | These four document types together form the usable facts; mark each item as stated or unstated |
| External action split | Coupon issuance and redemption connect to a separate business interface | Interaction nodes do not issue coupons; check whether an interface node exists separately |

## Three common errors

1. Treating the Form Input node as authorization verification. The node only collects and passes information the user fills in; authorization status comes from the privacy authorization record. If a draft says "authorized members may claim," the subject, scope and state must be compared against the authorization record. A node submission action does not produce an authorization conclusion.

2. Treating a User Selection branch as coupon issuance. A user choosing "confirm claim" only means a choice was made and the corresponding branch was entered. Coupon issuance, redemption and inventory deduction belong to a separately connected business interface. Writing the branch result as "already credited" lacks support.

3. Writing tag-table audience conditions directly as promotional language. The tag table states "three or more transactions in the last 90 days," which is a segmentation condition, not external copy. A draft saying "claim after three transactions" rewrites an internal segmentation condition as a claim threshold, which is not the same field as the "spend 300 reduce 50" stated in the coupon rules.

## How to verify the setup

1. Input the four source materials from the hypothetical sample and the draft sentence "This brand's summer new arrivals have arrived in store, and high repeat-purchase members may claim a spend 300 reduce 50 coupon." Compare the draft's subject, object, state and scope against the fields stated in the materials. If the coupon rules state only the eligible group and validity period, and do not state the claim entry point or in-store arrival time, then "have arrived in store" and "may claim" are unsupported and should be recorded as pending verification, not as a negative finding.

2. Input the Form Input node fields "member ID, outreach theme" and the output after submission. Compare whether the submitted information passed completely to the later retrieval node, checking field names and values item by item. If the retrieval node input lacks the member ID, output receiving is incomplete and the node connection must be checked; do not infer a system error cause.

3. Input the User Selection node "confirm claim" branch and the coupon issuance interface node record. Compare whether branch execution and interface call are two separate actions. If only branch execution is recorded and no interface call is recorded, coupon issuance state is unknown and must not be written as issued or not issued. Retrieval checks record actual observations and do not guarantee a first-hit match or that an unrelated query returns empty; empty-result receiving can be checked against a paper input of [] for downstream design.
