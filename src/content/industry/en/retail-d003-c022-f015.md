# Omnichannel stock transfers: retrieval for copy drafting

## What the documents look like

Omnichannel stock transfer work moves goods between stores and warehouses. It does not handle marketing outreach. The main data sources are ERP inventory, store POS, e-commerce orders, and WMS. The documents handled day to day are transfer requests, inventory snapshots, store shortage lists, and transfer logistics notes. Data updates daily or weekly.

For product and marketing copy drafting, four document types matter and they sit at different stages. A transfer request records the requesting party, the origin and destination store or warehouse, and the proposed quantity; it is an intent record that precedes approval. An inventory snapshot records the book quantity at one point in time, which may differ from the physical in-transit state. A store shortage list reflects the demand gap on the store side. A transfer logistics note reflects the carrier handover fact. These four have different field definitions and different stages. When copy drafting mixes them, a request can be written as an executed transfer, and a book quantity can be written as physical stock.

The update frequency affects how the citation content is time-stamped. It does not change the recall logic of the retrieval step itself.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Bases with different vector models cannot be associated together. Before retrieval, check the vector model identifier of each base, exclude any base whose identifier does not match, and record the identifier values actually observed.

Cited content is output as an array, and its length can be 0. When nothing is found, the output link still runs through. The downstream copy drafting step needs to accept an empty array.

Search mode compares semantic retrieval, full-text retrieval, and hybrid retrieval against a test question. Semantic retrieval depends on vector distance. Full-text retrieval depends on keyword hits. Hybrid retrieval fuses the two result sets through RRF. RRF is a fusion process, not a standalone switch. ReRank requires a rerank model enabled according to settings. Image retrieval requires the corresponding image input and model capability. The paths listed in the overall document flow diagram do not mean every request executes all of them.

The minimum relevance value is a filter threshold and takes effect only in semantic retrieval or when result reranking is used. That number does not carry out permission or entity isolation. The relevance ordering of retrieval results does not decide whether a given inventory record falls within the scope a user may view. The citation limit is measured in tokens and controls the maximum length of content cited per search.

### Hypothetical paper exercise sample

The following is a paper-constructed checking sample, not a real customer or real document.

Material text one (transfer request): "Request T-2024-0312, requesting party East China store A, proposes to transfer 120 units of a certain coat from East China warehouse B, request date 2024-03-12, status pending approval."

Material text two (inventory snapshot): "Snapshot date 2024-03-12, East China warehouse B book available quantity of this coat 300 units, of which 80 units are locked pending dispatch."

Draft sentence: "The coat has been transferred 120 units from East China warehouse B to store A, and the store supply has been secured."

Judgment point: the status in material text one is pending approval, and material text two states only the book quantity and locked quantity at warehouse B. The phrases "has been transferred" and "has been secured" are not supported by the materials and remain to be verified. The check compares the action stage described in the draft sentence with the status field stated in the material; when the two do not agree, the draft sentence is judged unsupported.

## Three common errors

1. Writing a pending-approval transfer request into copy as an executed transfer. The input is "status pending approval" in material text one; the comparison is against "has been transferred" in the draft sentence; the observable result is that the stage described in the draft sentence does not agree with the status field, and the sentence is judged unsupported.
2. Treating the book available quantity as the quantity the store can receive. The input is "book available 300 units, 80 units locked" in material text two; the comparison is against "supply has been secured" in the draft sentence; the observable result is that the material states no actual dispatch or arrival, and the conclusion remains to be verified.
3. Using the minimum relevance value to exclude inventory records outside the current scope. The input is the minimum relevance setting; the comparison is between the returned retrieval content and the viewable-scope list; the observable result is that a relevance score carries no ownership information, so this setting cannot perform scope isolation and requires a separate system implementation.

## How to verify the setup

1. For material text one and the draft sentence, input the draft sentence and run retrieval, then compare whether the returned citations contain the "pending approval" field. If the citations do not contain that status field, or contain only the requested quantity, the draft sentence is judged unsupported and the gap is recorded.
2. For material text two and the draft sentence, input the draft sentence and run retrieval, then compare whether the returned citations contain the "locked" field. If the citations contain only the book total without the locked quantity, the supply-secured conclusion remains to be verified and the evidence gap is retained.
3. For empty-result handling, input the paper empty array [] and compare whether the downstream copy step proceeds to the next step normally. If the downstream step halts or errors on the empty array, record that design gap. This check does not claim that a fictional rule search necessarily returns an empty array.

The checks above are paper expectations and were not actually executed. They do not constitute a test, deployment, or approval conclusion.
