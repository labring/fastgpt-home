# Brand repair services: citation tracing for copy drafting

## What the documents look like

Brand after-sales repair service documentation is organized around warranty responsibility and physical repair locations. It differs from e-commerce platform after-sales processes, which center on platform refunds. The documents that matter for copy drafting are warranty cards, repair work orders, inspection reports and replacement approvals. These materials determine whether statements about warranty coverage, repair timelines and return or exchange conditions can be supported by a source. Records update per order and daily. A citation must correspond to the specific document version it draws from.

For citation tracing, the practical consequence is that a drafted sentence about warranty scope or repair duration cannot be validated against the category in general. It must be checked against the warranty card, work order or inspection report that carries the relevant subject, object, status and validity period. A knowledge base search node can associate one or more knowledge bases that share the same vector model. The node outputs cited content as an array, and the array length may be zero; the output path still completes when no content is retrieved. The minimum relevance value applies only during semantic retrieval or when result reranking is used. It is a filtering threshold and does not perform permission or entity isolation. Hybrid retrieval merges multiple result paths through RRF. Reranking requires a rerank model and must be enabled in settings. Image retrieval requires image input and corresponding model capability.

## Constraints at the citation tracing step

The primary task is drafting product and marketing copy for brand after-sales repair services. Citation tracing means checking whether a proposed sentence is supported by the source material it cites. The check compares the draft wording against the specific document fields that would need to support it. It does not verify business identity, analyze inspection conclusions as a separate task, or confirm that any approval, refund or replacement actually occurred.

A hypothetical paper exercise sample follows. Material text one: "Warranty card number BX-2024-0731, product model A-12, purchase date 31 July 2024, warranty period 12 months, covers mainboard failure." Material text two: "Repair work order GD-2025-0115 records: received 15 January 2025; inspection report JC-2025-0115 concludes mainboard capacitor damage, within warranty scope." The draft sentence to be assessed: "Mainboard failure on this product model is covered by free warranty for 18 months after purchase." The comparison objects are the warranty card and the inspection report above. The question is whether the draft sentence is supported by these materials.

The warranty card states a 12-month period. The draft sentence states 18 months. The periods are the same field with mutually exclusive values, so the 18-month claim is not supported by the cited material. The inspection report addresses mainboard capacitor damage and places it within warranty scope. The draft sentence refers to mainboard failure generally. Whether the broader term is supported depends on whether the cited material uses the same object wording; where the material names a specific component and the draft uses a broader category, the draft exceeds what the material states.

## Configuration and implementation checks

The table below ties configuration items to the sample above. Values marked as hypothetical starting points are chosen for this exercise and compared against alternative values to observe differences in retrieved citations. They are not official defaults.

| Configuration item | Hypothetical starting point for this exercise | Reason and comparison method |
| --- | --- | --- |
| Associated knowledge bases | After-sales document base containing warranty cards, work orders, inspection reports | Check that the vector model identifiers of the selected knowledge bases match; exclude bases with different vector models |
| Search mode | Hybrid retrieval | Model numbers and document numbers benefit from full-text recall; semantic recall supplements natural-language phrasing |
| Minimum relevance | Hypothetical starting point 0.5 | Compare against 0.3 and 0.7, observing whether cited content stays closer to the sample source text |
| Citation limit | Hypothetical starting point 2000 tokens | Compare against 1000 and 4000, observing whether long work orders are truncated |
| Result reranking | Enabled, with a rerank model available | Compare against the disabled state, observing whether candidate ordering aligns more closely with the question |
| Question optimization | Disabled | The sample question has a complete subject; compare against the enabled state for response time |

The minimum relevance value filters low-relevance results. It does not exclude unauthorized records or separate business entities. Retrieval is not authorization. The citation limit controls the maximum tokens of cited content per search. RRF is a fusion process applied to hybrid retrieval results; it is not a separate toggle. Thinking budget belongs to reasoning configuration and must not be applied to the citation token limit.

## Three common errors

1. Treating minimum relevance as a permission filter. Input the same query, compare the citation array with minimum relevance enabled and disabled, and observe whether unauthorized material is retrieved. Relevance affects ordering and filtering only; it does not isolate entities or enforce access control.

2. Treating an empty citation array as a workflow error. Input an explicit paper input of an empty array to the downstream node, compare whether the downstream design continues execution, and observe whether the path completes. An empty array does not indicate that the node has terminated.

3. Confusing thinking budget with the citation limit. Input a thinking intensity setting and a citation limit setting, compare the fields each one affects, and observe whether a thinking budget value is written into the citation token limit. These are separate configuration areas.

## How to verify the setup

1. Input the warranty card and inspection report text from the hypothetical sample above. Compare the draft sentence "free warranty for 18 months" against the source wording "warranty period 12 months." Observe whether the sentence is supported. The material states 12 months only; the 18-month claim is not supported.

2. Input repair work order GD-2025-0115 and inspection report JC-2025-0115. Compare the draft sentence's reference to "mainboard failure within warranty scope" against the inspection report conclusion. Observe whether subject, object and period match. Where all three align, that portion is supported. Where the material names a specific component and the draft uses a broader term, the draft exceeds the material and remains unsupported on that point.

3. Input a paper empty array to the downstream node. Compare the downstream design's handling of zero-length citations and observe whether the path continues. This check confirms empty-result handling; it does not claim that any rule-based retrieval will return an empty array.

Missing evidence remains missing. A pending request is not an approval. An offered option is not execution. An unsigned termination is not a completed termination. Where a document field is not provided, it is unknown.
