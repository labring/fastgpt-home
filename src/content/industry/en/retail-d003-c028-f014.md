# Brand livestream operations: model connections for copy drafting

## What the documents look like

Brand livestream operations differ from influencer-hosted sessions in that the brand itself carries the script, inventory and after-sales obligations. The working documents for the copy drafting task are the livestream script, the product explanation card, the shift schedule and the livestream review. Material for product and marketing copy comes from Douyin Store Compass, Juliang Qianchuan, livestream comments and transaction details. When drafted copy diverges from those materials, the documented consequences are false-advertising complaints and declining conversion.

This page addresses only how model connections and configuration support the drafting task. It does not cover influencer commission settlement. The eight-dimensional brief describes a category rather than a named customer, so the details below are conditional on the deployment actually matching the brief.

## Constraints at the model connections step

Model access depends on AI Proxy. From V4.17.0, both the App and any Admin service that reuses App/Service configuration must set `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN`; missing either causes startup validation to fail. Legacy OpenAI environment variables or a single-model custom request address cannot substitute for these two settings. `AIPROXY_API_ENDPOINT` takes the service root address without appending `/v1`.

Model capability must be checked against the inputs the application actually needs. When an illustrated explanation card involves images, the model must support image input; tool choice and function call support are verified separately. Application parameters are set in the application or node configuration, and the documentation does not state that identically named fields on a compatible chat interface will override orchestration settings. The system needs at least one language model and one index model to operate normally.

Hypothetical paper exercise sample (not a real record):

Source text one: "The featured item A for this session is a light spring jacket; the fabric composition is labelled as 60% cotton and 40% polyester; currently sellable inventory is 120 units."

Source text two: "Campaign wording: orders placed in this session receive a matching storage bag; the gift is subject to system registration after actual payment of the order."

Draft sentence to be assessed: "This jacket is pure cotton, inventory is ample, and a storage bag is given immediately upon order."

## Configuration and implementation checks

The table below is a hypothetical paper starting point for cross-checking, not an official default.

| Configuration item | Hypothetical starting point | Reason and comparison object |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | Assume `http://aiproxy:3000` | Compare against the service root address format; confirm no `/v1` suffix |
| AIPROXY_API_TOKEN | Assume a non-empty administrator token | Compare against the server-side configuration; confirm it matches and is non-empty |
| Language model | Assume one language model that passed a channel test is enabled | Compare against the channel test result; confirm availability |
| Index model | Assume one index model that passed a channel test is enabled | Compare against the minimum system requirement; confirm it is met |
| Model capability | Assume image input and tool choice are checked against the illustrated explanation card | Compare against the inputs the drafting task requires |
| Application parameters | Assume parameters are set in the application or node configuration | Compare against identically named chat interface fields; confirm no mutual override |

## Three common errors

1. Writing `AIPROXY_API_ENDPOINT` as a full request address that includes `/v1`. Check the input field value against the service root address format and observe whether a path suffix has been appended.

2. Using an application API key as `AIPROXY_API_TOKEN`. Check the token source against the server-side configuration and observe whether it matches and is non-empty.

3. Assuming that identically named fields on the chat interface override application orchestration parameters. Check where the parameters are set and observe whether the orchestration node configuration is actually adopted.

## How to verify the setup

The following checks use the hypothetical sample above and are paper reasoning only; no test was executed.

1. Input source text one and the draft phrase "pure cotton". Compare the labelled 60% cotton and 40% polyester against "pure cotton", observing whether the two share the same subject, the same field and mutually exclusive values. If they are mutually exclusive, the draft phrase is not supported by the material.

2. Input source text two and the draft phrase "a storage bag is given immediately upon order". Compare the material condition "subject to system registration after actual payment of the order" against "immediately", observing whether the draft phrase exceeds the state range the material states. Any excess is unsupported.

3. Input source text one and the draft phrase "inventory is ample". Compare the stated sellable inventory of 120 units against the undefined term "ample", observing whether the material states a threshold for judging sufficiency. When no threshold is stated, the phrase remains unverified and is not judged as a negation or a conflict.

All three checks address only whether the copy is supported by the material. They do not involve identity certification, report analysis or any other task.
