# Brand livestream operations: retrieval for copy drafting

## What the documents look like

Brand livestream operations place script, inventory, and after-sales responsibility on the brand itself, which differs from influencer-hosted sessions that rely mainly on commission arrangements. The daily document set for this category includes livestream scripts, product briefing cards, shift schedules, and livestream retrospectives. Data sources named in the brief include the Douyin store compass, Qianchuan advertising console, livestream comments, and transaction details, with updates occurring per session or hourly.

For product and marketing copy drafting, these materials serve distinct roles. A product briefing card supplies the product object and selling points. A script supplies the wording stance for the session. A retrospective supplies historical conversion feedback. The retrieval step aligns a proposed sentence against source text so that a reviewer can confirm whether a promotional statement is supported by the material. Update frequency by itself does not change retrieval settings, but material versions change per session, so the version used must be confirmed as matching the current session before retrieval.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. The smallest search unit is the knowledge base; a collection serves only as a classification layer and does not affect search behavior. Search mode can be semantic retrieval, full-text retrieval, or hybrid retrieval. Hybrid retrieval merges multiple result channels through RRF, which is a fusion process rather than a toggle. The reference limit is measured in tokens. The minimum relevance value takes effect only under semantic retrieval or when result reranking is used. Question optimization performs coreference resolution and question expansion and adds one model call. Reranking requires an available model and must be enabled in settings. Image retrieval requires image input plus the corresponding model capability. Similarity and relevance scores do not perform permission or entity isolation, and retrieval results do not constitute authorization.

Hypothetical paper exercise sample: the source material for a brand livestream team consists of three sentences. Sentence one: "The product featured in this session is item A, a vacuum flask with a capacity of 500 milliliters and a body material of 304 stainless steel." Sentence two: "The livestream price for item A is 99 yuan, and the activity period runs from March 1, 2025 to March 7, 2025." Sentence three: "Item A is not eligible for the seven-day no-reason return policy." The proposed sentence reads: "Item A vacuum flask has a capacity of 500 milliliters, a 304 stainless steel body, a price of 99 yuan, and supports the seven-day no-reason return policy." The comparison target is whether capacity and material match sentence one, whether price and activity period match sentence two, and whether the return statement is mutually exclusive with sentence three on the same field. Sentence three and the proposed sentence take opposite values on the return field, which forms a same-field contradiction. Price and activity period are both stated in sentence two; the proposed sentence omits the activity period, which counts as incomplete citation rather than a contradiction.

## Three common errors

1. Treating minimum relevance as a permission or entity filter. Incorrect behavior: assuming a threshold excludes unrelated businesses or unauthorized records. Check: input the proposed sentence, compare whether returned content is determined only by similarity, and confirm that permission requires a separate system implementation.

2. Describing RRF fusion after hybrid retrieval as a toggle that can be switched on. Incorrect behavior: adding an "RRF switch" to configuration. Check: verify in the documentation that RRF is a fusion process and confirm that no such switch exists among configuration items.

3. Treating an unstated field as a contradiction. Incorrect behavior: judging the proposed sentence as conflicting with the source because the activity period is absent. Check: compare values on the same field and confirm that an unstated value counts as unsupported, while only mutually exclusive values on the same field form a contradiction.

## How to verify the setup

1. Input the three hypothetical source sentences and the proposed sentence, then compare whether capacity, material, and price fields match and whether the return field is mutually exclusive on the same field. Expected observation: the first three items match and a contradiction notice appears on the return field.

2. Input an explicit paper empty result `[]` and check whether the output path still completes. Expected observation: the reference content length is zero and the downstream design can accept an empty array; do not claim that a fabricated rule search necessarily returns empty.

3. Input the proposed sentence with question optimization enabled, then compare whether the optimized question and the proposed sentence share the same subject. Expected observation: the subject is not altered and the coreference result can be reviewed; added optimization time is an observable effect and is not claimed as measured.

All of the above are paper checks. No actual retrieval, deployment, or approval was performed. Missing fields remain unknown, a pending review does not indicate approval, and a quotation validity period does not indicate a supply period.
