# After-sales repairs and reships: interactive forms for copy drafting

## What the documents look like

After-sales repairs and reships aim to restore a product to use, so the work does not close through a direct refund the way a refund-only dispute does. The documents named for this category are the repair request, the reship order, the inspection report and the accessory outbound order. Each carries a different kind of fact. A repair request records the user request and the product object. A reship order records the item and quantity to be sent again. An inspection report records the inspection conclusion. An accessory outbound order records that accessories left the warehouse.

Copy drafting in this category depends on those documents. A promotional sentence about repair scope, reship conditions or timing needs a matching field for the same subject, the same object and the same period. The supplied brief gives an update frequency of per order and daily. This page does not derive batch synchronization, full synchronization, real-time triggers or transaction-triggered mechanisms from that frequency.

## Constraints at the interactive forms step

The form input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. The node collects the information the user fills in and passes it to later nodes. It does not carry business database functions of its own. The user selection node is also an interaction node. It evaluates the user choice and executes the corresponding branch. It is not a personnel directory and not a business data selector.

For copy drafting, the constraints follow from this. Which fields are collected, which fields are required, and which branch follows a user choice are all decided by node configuration. Field validation, business approval, write-back and batch operations are implemented in external systems or later nodes as needed. Retrieval and similarity scores do not carry permission or entity isolation duties, and retrieval results do not constitute authorization.

Hypothetical paper exercise: a brand after-sales desk receives a reship request. The supplied material text reads: "Reship order number B-2024-0317, item is a folding chair seat cushion, quantity one piece, status is pending outbound; the inspection report states the seat cushion buckle is broken, conclusion is eligible for reship; the accessory outbound order has not yet been generated." The draft sentence to be assessed is: "This brand's after-sales service promises that all reship requests are dispatched the same day after inspection passes." The comparison objects are the reship order, the inspection report and the accessory outbound order.

The table below lists settings or implementation checks that the official documents describe, tied to this feature and this drafting task. The values are hypothetical starting points for this exercise, not official defaults.

| Downstream division of work | Field validation, approval and write-back are implemented by external systems | The node does not perform database writes or external synchronization |

## Three common errors

1. Writing "status is pending outbound" from the material as already outbound. The input is the reship order status field; the comparison object is whether an outbound order exists; the observable result is that when the outbound order has not been generated, the promotional sentence is not supported.

2. Treating "conclusion is eligible for reship" as an executed reship. The input is the inspection report conclusion field; the comparison object is a reship execution record; the observable result is that with only a conclusion and no execution field, the sentence remains pending verification.

3. Treating a retrieval similarity result as permission or entity filtering. The input is the returned retrieval entry; the comparison object is the authorized scope; the observable result is that similarity does not constitute authorization, and when the authorization field is missing, the gap is recorded.

## How to verify the setup

- Verification one: input the material text "Reship order number B-2024-0317, item is a folding chair seat cushion, quantity one piece, status is pending outbound," and compare the words "all" and "same day" in the draft sentence "all reship requests are dispatched the same day after inspection passes" against the material. Observe whether the material states a full scope and a dispatch time point. When neither is stated, the sentence is not supported.

- Verification two: input the material text "the inspection report states the seat cushion buckle is broken, conclusion is eligible for reship," and compare whether the draft sentence turns the conclusion into a completed reship. Observe whether a reship execution field exists. When it is missing, record the item as pending verification.

- Verification three: input the material text "the accessory outbound order has not yet been generated," and compare whether the draft sentence claims the accessory has already left the warehouse. Observe the outbound order status field. When the order has not been generated, the claim is not supported.

All three verifications are paper comparisons. No run, deployment, approval or refund took place.
