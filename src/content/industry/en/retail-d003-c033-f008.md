# Trade and FX administration: workflow routing for copy drafting

## What the documents look like

Copy review in the foreign-exchange receipt and settlement category centers on the authenticity of FX funds and the underlying trade background. The materials examined are receipt vouchers for incoming foreign exchange, trade contracts, invoices, and foreign-exchange business registration records. A full set of letter-of-credit documents sits outside this page's scope, because settlement work does not review the complete documentary package that letter-of-credit examination covers. Materials update per transaction, and some reporting runs on a monthly aggregate basis. For a single transaction, the counterparty, amount, and goods description must line up across these several documents.

The people doing this work are typically foreign-trade finance staff, bank relationship managers, and FX specialists. Errors lead to bank rejection of documents, an abnormal FX classification, or funds that cannot be booked. Copy drafting has to treat these materials as the checkable source, and the drafted result can only fall within what the materials already state.

## Constraints at the workflow routing step

The Form Input node is a user-interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and after the user fills in the required information and submits, the node passes the collected information to subsequent nodes. The User Selection node also enters an interaction state, and once the user makes a selection, the node evaluates that selection and executes the corresponding "yes" branch. Both nodes are repeatable trigger-execution nodes. Interaction waiting, state recording, and hiding the dialog box are documented node behaviors. The documentation does not provide switches that control these behaviors, a submission-count limit, or automatic judgment rules.

Collected information must be explicitly passed to subsequent retrieval, judgment, or interface nodes, and output is compared item by item against input. Order writing, document backfill, and external status synchronization require a separate business interface or a later process; the nodes themselves do not perform these actions. A retrieval relevance score does not carry permission or entity-isolation functions. Libraries built on different vector models cannot be associated together; identifiers must be checked first and non-matching records excluded.

Hypothetical paper exercise. The source material reads: "Exporter: a machinery parts plant in East China; Importer: an overseas buyer; Contract No. HX-2024-018; Goods: hydraulic connectors, 2,000 pieces; Receipt voucher dated March 12, 2024, amount USD 48,000; Invoice No. FP-0312, amount USD 48,000." The draft sentence to be judged is: "The plant's hydraulic connectors have passed the overseas buyer's acceptance inspection, and its long-term supply capability has been recognized." The materials state only the goods, quantity, amount, and dates across the contract, receipt voucher, and invoice. They do not state an acceptance conclusion or long-term supply capability, so the sentence is unsupported.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | Reason and comparison method |
| --- | --- | --- |
| Form Input node | Collect three required fields: contract number, invoice number, receipt voucher date | These three are the minimum fields in the sample for aligning counterparty and period; after submission they are compared character by character against the materials |
| User Selection node | Set a branch for "whether the materials cover the draft sentence" | The documentation states that a selection executes the "yes" branch; verify branch connections one by one |
| Retrieval scope | Limit to the four material types for this transaction | The sample materials are the retrieval target; when an item is missing, record the gap and do not widen the scope |
| Output handoff | Pass form values to a comparison node | The documentation requires information to be passed to subsequent nodes; check output against input item by item |
| External actions | Do not configure writing or synchronization | The documentation does not state that the node performs writing itself; a separate interface is needed, so leave this empty |
| Prompt scope | Allow reference only to fields already stated in the materials | The sample draft sentence exceeds the materials and is used to observe whether it is stopped |

## Three common errors

1. Treating interaction-state recording as a global state switch. The documentation states only that an interaction node records workflow state when triggered; it provides no global recording switch. Check against node behavior during configuration and add no switch item.

2. Treating retrieval relevance as a permission filter. Relevance does not distinguish counterparties and does not exclude unauthorized records. Check identifiers first and exclude non-matching records; do not rely on a similarity setting.

3. Treating form submission as business completion. Submission completes only information collection and handoff. Order writing, document backfill, and external synchronization require a separate business interface; without that interface, the related actions remain unimplemented.

## How to verify the setup

1. Input the sample source material and the draft sentence, then compare "acceptance inspection" and "long-term supply capability" in the draft against the material fields. When the materials do not state these two items, the output should be marked unsupported; an output containing wording such as "has passed acceptance" does not satisfy the condition.

2. Input contract number HX-2024-018 and invoice number FP-0312, then compare the amount fields each corresponds to. When both are USD 48,000, treat them as consistent on the same field. When either side is missing, record it as pending verification rather than as a contradiction.

3. Input the paper input [] for an empty-result handoff, then compare whether the downstream node handles it through the no-match branch. An output downstream that cites material that does not exist does not satisfy the condition. The documentation does not state what a retrieval under a fictional rule returns; the actual return remains to be observed and recorded.
