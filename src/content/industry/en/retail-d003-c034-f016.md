# Export tax rebate filings: interactive forms for copy drafting

## What the documents look like

Export tax rebate filing happens after goods leave the country, and the work is tax voucher matching rather than customs declaration. The data comes from the electronic tax bureau, the export tax rebate filing system, customs electronic messages and the accounting ledger. The documents handled day to day are the export tax exemption and rebate filing form, the export customs declaration, purchase invoices and foreign exchange receipt vouchers. For the copy drafting task, the sentences under review state product name, quantity, amount, trade mode and transaction terms, and the check is whether those statements have corresponding records within what the declaration, purchase invoice or receipt voucher actually records. Material updates monthly or per batch. This page's form interaction does not depend on that frequency, and no batch synchronization or real-time trigger is inferred from it.

## Constraints at the interactive forms step

When the form input node is triggered, the conversation enters an interaction state and the workflow state is recorded. After the user completes the required information and submits, the node collects what was filled in and passes it to later nodes. The node does not carry its own business database function. The user selection node also enters an interaction state and executes a branch according to the user's choice; it does not act as a personnel directory or a business data selector. Field validation, business approval, write-back and batch operations need to be implemented in an external system or in later nodes. The declaration, invoice and receipt voucher content needed for copy checking must be provided by a person within an accessible retrieval scope or through explicit manual input; retrieval itself does not carry authorization judgment.

Hypothetical paper exercise sample: the draft sentence is "The transaction mode for this batch of goods is CIF, quantity 1,200 pieces." The source text supplied for comparison is: "The export customs declaration records the transaction mode as CIF and the quantity as 1,200 pieces; the purchase invoice records the quantity as 1,200 pieces; the foreign exchange receipt voucher records a receipt amount consistent with the total price on the customs declaration." The subject is the same batch of exported goods, the object is transaction mode and quantity, the status is filed and awaiting check, and the effective scope is this batch. The item to be determined is whether the draft sentence matches the declaration and invoice records on the same fields.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | Reason and comparison object |
| --- | --- | --- |
| Required form fields | Product name, quantity, transaction mode | These correspond to the fields the draft sentence must be checked against; the node cannot submit when a required item is missing |
| Material source | Customs declaration, purchase invoice, receipt voucher | Matches the sample source text and serves as the comparison baseline |
| User selection branches | Consistent / inconsistent / pending verification | Branches execute on the same-field comparison result |
| Interaction state handling | Wait for submission after trigger, then continue | Follows documented node behavior; no submission-count limit is set |
| Downstream division of work | Validation and approval implemented in an external system | The node itself does not write to a business database |

## Three common errors

1. Comparing "CIF" in the draft sentence against a trade mode the invoice does not record, treating them as the same field. The input is the draft sentence and the invoice text, the comparison object is misaligned, and the observable result is that consistency cannot be determined.
2. Comparing the declaration quantity of 1,200 pieces directly against the receipt voucher amount. The input is two materials with different fields, the comparison object differs, and the observable result is an unsupported contradiction conclusion.
3. Treating a related-stage record in the materials as grounds to negate the draft sentence. The input is a stage record, the comparison object is a complete field, and the observable result is a negation issued past the "not supported" state.

## How to verify the setup

1. Input the hypothetical sample draft sentence and source text, compare the transaction mode and quantity fields, and when the materials record the same values on those fields, the draft sentence is determined consistent.
2. Input the draft sentence together with a material containing only a receipt amount, compare field types, and when the fields do not correspond, the result is pending verification with the evidence gap recorded.
3. Input an empty material list, compare whether the downstream design accepts an empty result, and confirm that no consistency conclusion is produced when no material exists, leaving the unsupported state in place.
