# Trade returns and claims: workflow routing for copy drafting

## What the documents look like

Trade returns and claims handle reverse logistics and liability determination after export. The difference from ordinary export declaration work sits in responsibility attribution and the evidence chain. Everyday documents include the return agreement, the claim letter, the quality report, and the return customs declaration. Source data arrives from customer email, inspection reports, customs systems, and insurer claim systems. Updates are irregular and case by case.

For copy drafting, whether a proposed sentence can stand depends on whether these materials record the same subject, the same period, and the same field with a matching status. A sentence that asserts a completed return or a settled claim needs material that actually records that completion or settlement. A return agreement still awaiting signature, or a quality report that has only been submitted, supports neither assertion.

## Constraints at the workflow routing step

The form input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and after the user completes the required fields and submits, the node collects the submitted form values and passes them to later nodes. The user selection node is also a user interaction node. When it triggers, the conversation enters the interaction state and the workflow state is recorded; after the user makes a selection, the node evaluates that selection and executes the corresponding "yes" branch. Both node types are user interaction nodes, can be added repeatedly, and trigger execution.

Hypothetical drill sample: the material text reads "Company A submitted a quality report on 10 March 2025 for batch B-0310, recording that surface scratches exceeded the standard; the return agreement for the same batch is awaiting signature, with Company A and the carrier as signing parties." The proposed draft sentence under review is "The batch has completed the return and received compensation." This sentence involves two facts, completed return and compensation received. The material shows only that a quality report was submitted and that the return agreement awaits signature. It does not record signature completion, return execution, or a claim outcome.

The constraint follows from this gap. Fields collected by interaction nodes serve only as input values for later nodes. Business verification, approval, database writes, and external status synchronization require a separate business interface or a later process. Retrieval is the process of fetching material and does not perform authorization judgment. A relevance score does not constitute a subject, entity, or permission filter. Knowledge base reference limits are counted in the documented unit. Empty-reference output and context limits retain their documented conditions. Libraries using different vector models cannot be associated together; identifiers must be checked first and non-matching libraries excluded, without running a cross-model retrieval comparison of missed recall. Image retrieval requires a corresponding image input and model capability. Reranking requires a model and must be enabled according to settings. Thinking budget is thinking budget and cannot serve as a reference token limit.

## Three common errors

1. Reading "return agreement awaiting signature" in the material as a completed return. Input is the sample text and the proposed sentence; the comparison point is the agreement status field; the observable result is that the proposed sentence exceeds the status recorded in the material.
2. Reading a submitted quality report as an established quality liability determination. Input is the quality report field; the comparison point is whether a liability determination field exists; the observable result is that the material does not record that field.
3. Treating a retrieval relevance score as a permission or entity filter. Input is the retrieval return item; the comparison point is whether it carries a subject and authorization identifier; the observable result is that the score carries no permission information.

## How to verify the setup

1. Input the sample text and the proposed sentence, then compare the facts stated in the proposed sentence against the material fields. If the material does not record completed return and compensation received, the proposed sentence is unsupported, and the evidence gap is recorded.
2. Input the awaiting-signature status from the sample and the proposed sentence, then compare the agreement status field. If the field reads awaiting signature, no wording stating a completed return may be output.
3. Input the paper empty result [] and the downstream node design, then compare whether the downstream handles empty input. If the downstream defines no empty-input branch, record it as pending, without claiming retrieval must return empty.

All of the above is paper review. No actual test, deployment, or approval was performed. Missing evidence remains missing; awaiting signature does not equal signed; a quotation validity period does not indicate a supply period.
