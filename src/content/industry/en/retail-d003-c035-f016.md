# Trade returns and claims: interactive forms for copy drafting

## What the documents look like

Trade returns and claims handling works on the reverse flow that follows an export and on the allocation of responsibility for it. The material comes from customer email, quality inspection reports, customs systems and insurer claim systems. The documents handled day to day are return agreements, claim letters, quality reports and return customs declarations. Updates arrive irregularly and case by case, so each file is assembled rather than refreshed on a schedule.

For copy drafting in this category, the practical task is to turn a return reason, a responsibility position and a claim demand into outward-facing text. Whether a drafted sentence holds depends on whether the underlying material covers the same subject, the same object and the same valid scope. A quality report about outer packaging does not describe the function of the contents. A draft return agreement that carries no signature is not a completed return. A claim letter with a blank date line does not supply a date.

The interactive forms step sits at the point where the drafter supplies the draft sentence and the source passages, and where the comparison result is recorded. The form input node and the user selection node are user interaction nodes. When either is triggered, the conversation enters an interaction state, the workflow state is recorded, and execution waits until the user finishes interacting. After submission, the form input node collects the information the user filled in and passes it to later nodes. The user selection node judges the user's choice and executes the relevant branch. Neither node performs field validation, business approval, write-back or batch operations on its own; those belong to external systems or later nodes as required.

## Constraints at the interactive forms step

The nodes collect and branch. They do not verify a business fact, approve a claim, sign an agreement, write to a database or synchronize with an external system. A submitted form value is a value the user entered, not a confirmed fact. A selected branch is a path through the workflow, not an authorization decision.

A hypothetical paper exercise sample, used only for illustration:

Source passage one: "On 10 March 2025, Company A sent Company B a draft return agreement for twelve cartons of batch B-0311, stating the return reason as moisture damage in transit; the agreement has not been signed."

Source passage two: "A quality inspection report for the same batch was issued by inspection body C on 12 March 2025, concluding that the outer cartons showed moisture damage and the inner items functioned normally."

Source passage three: "A draft claim letter states that all goods in the batch suffered functional damage and demands full compensation; the date line is blank."

Draft sentence to be assessed: "The batch suffered full functional damage from moisture in transit, Company A has completed the return under the return agreement, and full compensation has been received."

The comparison runs across the three source passages. The subject is Company A, the object is batch B-0311, the period is March 2025, and the status fields are the signature state of the return agreement and the date state of the claim letter. The inspection conclusion records normal function of the inner items. The return agreement is unsigned. No material supports a compensation payment. The draft sentence therefore remains unsupported at three points: full functional damage, completed return, and compensation received.

## Configuration and implementation checks

| Configuration item | Relevant setting or check on this page | Relation to the sample |
| --- | --- | --- |
| Form input node | Collects the draft sentence, the source passages and the assessment conclusion; passes them to later nodes after submission | Carries the three source passages and the one draft sentence |
| Required information check | Lists subject, object, period and status as four fields; tests the behaviour when one is missing and when it is supplied | All four are present in the sample, so comparison can proceed |
| User selection node | Executes a branch according to the user's choice; not a personnel directory or business data selector | Used for the supported, unsupported and pending-verification branches |
| Interaction state | Records workflow state and waits for interaction after the node is triggered; continues downward when interaction completes | Waiting for the filled fields and the selection before comparison begins |
| Downstream division of work | Field validation, business approval and write-back are implemented in external systems or later nodes | This page does not carry out compensation or signature actions |
| Hypothetical trial starting point | This exercise starts from all four fields being present, and compares against the behaviour when any one is missing | The starting point is chosen because the sample supplies all four; it is not an official default value |

## Three common errors

1. Reading the quality report conclusion "inner items function normally" as "all functions damaged" replaces the value of the same field, so the comparison object is misaligned.
2. Treating the draft return agreement as signed upgrades the status field; signature, reached cooperation and contract effectiveness are three distinct facts.
3. Filling the blank date line of the draft claim letter with a valid date fabricates the period field; content that is not stated is recorded as unsupported.

## How to verify the setup

1. Enter the three source passages and the draft sentence, compare the draft sentence against the sources on subject, object, period and status, and observe whether the three points "full functional damage", "completed return" and "compensation received" are marked unsupported. The condition is met when none of the three points is covered by the source passages.
2. Enter the same set of material with the quality inspection report removed, compare whether the remaining material can support the conclusion "inner items function normally", and observe whether the result changes to pending verification. The condition is met when no affirmative or negative finding appears.
3. Enter the draft sentence together with a return agreement whose subject differs, compare whether the subject field matches, and observe whether that material is excluded and the gap recorded. The condition is met when the material does not enter the supported conclusion and the gap remains recorded as unsupported.

All of the above is paper review. No actual submission, approval, compensation payment or synchronization action has been carried out.
