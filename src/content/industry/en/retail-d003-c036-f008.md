# Multi-warehouse inventory: workflow routing for copy drafting

## What the documents look like

Multi-warehouse allocation happens at the order routing stage and decides which warehouse ships an order. This timing differs from courier handover, which occurs later in fulfillment. The main data sources are WMS, OMS, ERP inventory and platform inventory interfaces. Everyday documents include allocation rules, inventory synchronization tables, transfer orders and stockout warnings. The task on this page is product and marketing copy drafting, and workflow routing has to connect draft copy material with allocation and inventory facts. Update frequency is daily or hourly, and it matters here only when it affects whether a copy claim is still timely.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and after the user completes the required fields and submits, the collected information passes to later nodes. The User Selection node is also a user interaction node. When it triggers, the conversation enters an interaction state, and when the user makes a selection, the node evaluates that selection and executes the corresponding "yes" branch. These are existing node behaviors. No separate global state-recording switch is defined, and no submission count, automatic judgment or snapshot guarantee should be assumed.

Information collected at these nodes has to be passed explicitly to later retrieval, judgment or interface nodes, and outputs must be compared item by item against inputs. Order writes, document backfill and external status synchronization require a separate business interface or a later process. Interaction waiting, state recording and dialog hiding follow the documented behavior.

The same-vector-model requirement for retrieval libraries applies only to that library itself. Libraries using different vector models cannot be associated together. Check the model identifier first and exclude libraries that do not match; do not run cross-model retrieval to compare missed recall. An empty-reference output can be checked against downstream design using a clearly labelled paper input of []. RRF is a hybrid result fusion process, not a switch to be turned on. Thinking budget is a reasoning budget and cannot be repurposed as a citation token limit.

Hypothetical paper exercise: the source material reads "East China warehouse sellable inventory from 1 June 2025 to 30 June 2025 was 1,200 units; South China warehouse sellable inventory for the same period was 800 units; the allocation rule states that East China orders are shipped from the East China warehouse first." One draft sentence to be assessed reads "All East China regional orders are dispatched from the East China warehouse on the same day." The words "all" and "same day" have no corresponding statement in the source material and are unsupported. The authorization boundary is review of copy consistency with the material only, with no actual shipment or inventory write.

## Three common errors

1. Treating "All East China regional orders are dispatched from the East China warehouse on the same day" as a conclusion supported by the material. The material states only sellable inventory for the East China and South China warehouses and that East China orders are shipped from the East China warehouse first. It does not state "all" or "same day." The check takes the draft sentence and the source material as input, compares subject, period and field, and records the result as unsupported when the source has no corresponding statement.

2. Treating the "yes" branch of the User Selection node as automatic authorization. The node behavior is to execute the corresponding branch after the user makes a selection. An authorization decision requires a separate business interface or later process. The check takes the branch connection and authorization material as input, compares the selection result against the authorization scope, and records the result as pending verification when authorization material is missing.

3. Extending the same-vector-model requirement for retrieval libraries to external systems. That requirement applies to the retrieval library itself and does not apply to business registration websites or other external systems. The check takes the library identifier and the model identifier as input, compares whether they use the same model, and excludes the library when they differ, without running cross-model retrieval to compare missed recall.

## How to verify the setup

1. For the draft sentence "All East China regional orders are dispatched from the East China warehouse on the same day" in the hypothetical exercise, input the sentence and the source material. Compare whether "all" and "same day" have corresponding statements. The expected result is unsupported, with the evidence gap retained.

2. For the allocation rule "East China orders are shipped from the East China warehouse first" in the hypothetical exercise, input the rule and the User Selection node branch connections. Compare the selection result against the rule scope. The expected result is that branch connections match the rule; when they do not match, record the result as pending verification.

3. For the paper input [], input the empty result and the downstream node design. Compare whether the downstream design handles an empty result as such. The expected result is that the downstream design explicitly handles the empty result, without claiming that a fictional rule retrieval necessarily returns [].
