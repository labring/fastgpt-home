# Multi-warehouse inventory: model connections for copy drafting

## What the documents look like

Multi-warehouse allocation and inventory synchronization sits at the order routing stage, where the system decides which warehouse ships an order. The working materials come from WMS, OMS, ERP inventory, and platform inventory interfaces. Day-to-day documents include allocation rules, inventory synchronization tables, transfer orders, and stockout warnings. Copy drafting for products and marketing draws warehouse, inventory, and timing statements from these materials, and the stated inventory and dispatch position in a draft needs to sit inside the same time range as the material it cites.

The materials may carry a daily or hourly update cadence. Where that cadence matters, a draft sentence about sellable stock or dispatch cut-off should be checked against the same period as the source line, without assuming any bulk, full, real-time, or transaction-triggered synchronization mechanism beyond what the source states.

For this page the task is narrow: decide whether a specific proposed promotional sentence is supported by the cited material. The page does not extend into identity verification, report analysis, or any other task.

## Constraints at the model connections step

Model access and configuration in FastGPT run through AI Proxy. From V4.17.0, AI Proxy is a required dependency. The App and any Admin service that reuses the App/Service configuration must set `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN`; a missing one of either causes startup validation to fail. `AIPROXY_API_ENDPOINT` takes the AI Proxy service root address and does not append `/v1`. The system needs at least one language model and one index model to work normally. Model capability is checked against the input a given application requires, and multimodal support, tool calling, and thinking configuration are each verified separately. Application parameters are set in the application or node configuration; the same-named field on a chat-completions interface cannot be assumed to override orchestration. Copy drafting judges only whether a proposed sentence is supported by the cited material.

Hypothetical drill sample: a supply chain planning role, on 10 March 2026, prepares an allocation-rule excerpt. The source text reads: "East China warehouse sellable stock 1,200 units; orders paid before 18:00 on the same day ship from the East China warehouse. South China warehouse sellable stock 300 units; accepts only South China region orders." A draft sentence prepared the same day reads: "All nationwide orders paid before 18:00 on the same day can ship from the East China warehouse, stock sufficient." The question is whether the draft sentence is supported by the source text above.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this page | Reason and comparison object |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | AI Proxy root address | Official guidance is the root address with no `/v1`; compared against a form that appends a path |
| `AIPROXY_API_TOKEN` | Non-empty administrator token | Official requirement is non-empty and consistent with the server; compared against an empty value or an application API key |
| Language model | One tested language model enabled | The system needs at least one language model; compared against a not-enabled state |
| Index model | One tested index model enabled | The system needs at least one index model; compared against a not-enabled state |
| Model capability | Checked against the input the copy task requires | Multimodal and tool calling verified separately; compared against an unchecked state |
| Application parameters | Set in the application or node configuration | Official guidance places parameters there; compared against assuming a same-named chat-completions field overrides orchestration |

These rows are implementation checks tied to this page's materials and the model-connection step. No numeric default, limit, unit, menu, or global switch is asserted beyond what the official documents state.

## Three common errors

1. Filling `AIPROXY_API_ENDPOINT` with a full request address that includes `/v1`. Check: input the official root-address form, compare whether a path is appended, and observe whether startup validation passes.
2. Using an application API key in place of `AIPROXY_API_TOKEN`. Check: input a non-empty administrator token, compare the token type and consistency with the server, and observe whether startup validation passes.
3. Treating the draft sentence "all nationwide orders can ship from the East China warehouse" as supported by the source. Check: input the source text and the draft sentence above, compare subject and scope, and observe whether the source states a nationwide scope and an East China warehouse acceptance relationship.

## How to verify the setup

1. Input the hypothetical sample source text and the draft sentence. Compare the subject, object, and effective scope in the source against the draft. Observe whether the draft stays inside the East China and South China warehouse scope the source states. The source does not state a nationwide scope, so the draft sentence is unsupported.
2. Input the root-address form of `AIPROXY_API_ENDPOINT` and a form that appends `/v1`. Compare whether a path is appended. Observe the startup validation result. The appended-path form does not match the official guidance.
3. Input the configuration with an enabled language model and an enabled index model. Compare whether at least one of each is enabled. Observe whether the model test returns a result. With neither enabled, the system cannot work normally.

When a paper check produces an empty result, a clear `[]` may be used as input to carry the downstream design, without claiming that a fictional rule lookup necessarily returns empty. Libraries on different vector models cannot be associated together; check the identifier first, exclude non-matching ones, and record what is actually observed. Retrieval is not authorization, and a similarity score is not a category, entity, or permission filter.
