# Multi-warehouse inventory: retrieval for copy drafting

## What the documents look like

Multi-warehouse order routing and inventory synchronization copy drafting draws on four document types: allocation rules, inventory synchronization tables, transfer orders, and shortage alerts. Allocation rules decide which warehouse ships an order. Inventory synchronization tables record sellable quantities. Transfer orders record movements between warehouses. Shortage alerts mark constrained supply. These materials originate from WMS, OMS, ERP inventory, and platform inventory interfaces, with update frequencies given as daily or hourly.

For copy drafting, the retrieval step answers a narrow question: can an existing material support a proposed promotional sentence, and do the subject, object, status, and effective scope in the material match the draft? Because inventory data changes quickly, a retrieved fragment may correspond to an older version. Verification must confirm the material's own date or version identifier before treating a fragment as current.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases using different vector models cannot be associated together. During verification, first check the vector model identifier, exclude those that do not match, and record the actual observation. Do not run cross-model retrieval to compare missed recalls.

Search mode may be semantic retrieval, full-text retrieval, or hybrid retrieval. Compare modes against test questions rather than assuming one mode suits all materials. The citation limit is measured in tokens; test with materials of different lengths to see whether content is complete, then adjust the limit. Minimum relevance takes effect only under semantic retrieval or when result reranking is used; label relevant and irrelevant samples first, then adjust the threshold.

Question optimization performs coreference resolution and question expansion. Compare the original question with the optimized question and check whether the subject was altered incorrectly. A similarity score is a relevance measure and does not perform permission or entity isolation. When retrieval returns nothing, the output path still completes, and cited content is output as an array whose length may be zero.

Hypothetical paper exercise sample: the material text reads "Allocation rule A applies to East China region orders, effective date March 1, 2025; this rule designates the Shanghai warehouse for priority shipment." The proposed draft sentence reads "This product ships with priority from the Shanghai warehouse in the East China region." The point to judge: whether the subject, region, and shipment priority in the draft sentence match the material text, and whether the material covers this product.

## Configuration and implementation checks

| Configuration item | Hypothetical trial starting point for this page | Reason and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Associate only libraries containing allocation rules, inventory synchronization tables, transfer orders, and shortage alerts that use the same vector model | Check the vector model identifier first, exclude libraries with different models, then confirm document type coverage library by library |
| Search mode | Run semantic retrieval and full-text retrieval separately on test questions containing region names and warehouse names | Compare recall of draft-relevant fragments under both modes; do not assume a single mode |
| Citation limit | Start from the token quantity needed to cover one complete allocation rule | Test with rule fragments of different lengths and observe whether cited content truncates key conditions |
| Minimum relevance | Start from the score between labeled relevant and irrelevant samples | Adjust only when semantic retrieval or result reranking is active; compare sample changes before and after filtering |
| Question optimization | Enable for test questions containing pronouns; disable for test questions with a clear subject | Compare retrieval results from the original and optimized questions; check whether the subject was altered incorrectly |
| Result reranking | When a rerank model is available and enabled per settings, observe ordering on test questions with many candidates | Compare scores and order before and after reranking; do not describe RRF as a switch |

## Three common errors

1. Treating a similarity score as a permission or entity isolation mechanism. Input a test question spanning regions, compare whether returned fragments include rules from other regions, and observe whether warehouse names or region names outside the target region appear. Similarity reflects relevance only and does not perform authorization decisions.

2. Judging "not stated in the material" as "denied by the material." Input the draft sentence "This product ships from the Guangzhou warehouse in the South China region," while the material contains only East China allocation rules. Compare the region fields and observe whether the material records the South China region or the Guangzhou warehouse. Not stated means unsupported, not contradictory.

3. Treating a pending-review or pending-signature status as a completed fact. Input a handover request stating "Transfer order B is effective and can support drafting a shipment commitment," while the material shows transfer order B in pending-review status. Compare the status field and observe whether an effective date or approval record exists. Pending review does not demonstrate effectiveness.

## How to verify the setup

1. Input the material text and draft sentence from the hypothetical sample, compare the three fields of subject, region, and shipment priority, and observe whether the draft sentence corresponds item by item with the material text. If the material does not cover this product, record it as an evidence gap and do not judge it as supported or denied.

2. Input a test question containing a pronoun, disable and then enable question optimization, compare the cited content returned by the two retrievals, and observe whether the subject of the optimized question matches the original question. If the subject is altered incorrectly, record the observation and adjust the question optimization setting.

3. Input a test question with no corresponding material, observe whether the cited content output is an array of length zero, and check whether the downstream design accepts an empty result. Do not claim that retrieval of a fictional rule necessarily returns an empty array; record only the output form actually observed.
