# Peak-sale fulfillment: workflow routing for copy drafting

## What the documents look like

Peak-sale warehouse and delivery scheduling centers on short-window peak capacity and the arrangement of people, vehicles and yard space. This differs from routine multi-warehouse inventory synchronization, which follows a steadier balancing logic. Four material types enter the copy drafting step: historical peak-sale orders, platform campaign registration, WMS capacity figures, and courier pickup capacity. Together they form the factual boundary that promotional sentences can be checked against.

The main documents handled in this step are the peak-sale forecast table, staff shift schedules, courier support plans, and the exception daily report. Forecasting order peaks, arranging temporary staff, and coordinating courier vehicles are the most time-consuming activities. When drafted copy touches shipping timeliness, handling capacity, or support commitments, the corresponding wording has to be traced back to these documents. Warehouse overflow, delayed dispatch, and falling campaign scores are the consequences of error; copy that asserts timeliness or capacity not supported by the materials amplifies these risks.

Peak-sale scheduling updates per campaign and daily. The capacity, timeliness and support scope cited in copy may therefore change during the campaign period. At drafting time the campaign instance and date that the underlying materials correspond to need to be confirmed.

## Constraints at the workflow routing step

The form input node is a user interaction node. When triggered, the conversation enters an interaction state and the workflow state is recorded. After the user completes the required fields and submits, the node collects the submitted form information and passes it to subsequent nodes. The user selection node is also a user interaction node. When triggered, the conversation enters an interaction state and the workflow state is recorded. When the user makes a selection, the node evaluates that selection and executes the corresponding branch. Both nodes can be added repeatedly and are trigger-executed. These are existing node behaviors and carry no automatic business action.

Hypothetical paper exercise sample. The material text for checking consists of three sentences. Sentence one: "This peak-sale support plan covers the East China region, applicable from June 1 to June 3, 2025." Sentence two: "During this period the warehouse can process 80,000 orders per day on average; the source is the WMS capacity table." Sentence three: "Courier pickup capacity is 60,000 orders per day; the excess is deferred to the next day." One draft sentence to be assessed reads: "During the peak sale, all national orders can be dispatched the same day, with no regional limit."

The draft sentence does not match the material text on subject scope or regional scope. The material covers the East China region only, and the pickup capacity carries a deferral condition. The draft sentence is unsupported. Within the workflow, a user selection node can be configured to let the drafter confirm the regional scope, or a form input node can collect the campaign instance and date, with the collected values passed to subsequent nodes for comparison.

## Configuration and implementation checks

| Configuration item | Type | Relation to this page's sample |
| --- | --- | --- |
| Form input node | User interaction node | Collects campaign instance, region and date needed for drafting; passes submitted values to subsequent nodes |
| User selection node | User interaction node | Puts the choice of whether a given regional scope is adopted to the drafter; executes a branch according to the selection |
| Interaction state check | Implementation check item | Confirms that triggering enters the interaction state and records state; no separate global state switch is set |
| Output handoff check | Implementation check item | Compares collected information item by item against the inputs of subsequent retrieval or judgment nodes |
| External action division | Implementation check item | Order writes, document backfill and external state synchronization require a separate business interface or later flow |
| Hypothetical trial starting point | Hypothetical value for this exercise | Uses "East China region, June 1 to June 3" from the sample as the comparison starting point, compared field by field against "national, same day" in the draft sentence |

Reason for choosing the hypothetical trial starting point: the sample material already states a clear region and date range, while the draft sentence sets no regional limit and adds a "same day" condition. The two differ in value on the same fields and can be compared directly. This starting point is set for this paper exercise and does not represent any official default value.

## Three common errors

1. Expanding the support scope "East China region, June 1 to June 3" directly into "national, no date limit." The inputs are the material text and the draft sentence; the comparison is on the region field and the date field; the observable result is that the draft sentence takes "national" for region against "East China" in the material, and the date limit is absent.
2. Rewriting "courier pickup capacity is 60,000 orders per day; the excess is deferred to the next day" into "all can be dispatched the same day." The inputs are the third sentence and the draft sentence; the comparison is on the timeliness condition field; the observable result is that the material contains a deferral condition and the draft sentence does not reflect it.
3. Treating the region value collected by the form input node as already passing business review by default. The inputs are the node output value and the review record; the comparison is between the collection action and the review action; the observable result is that the node only passes the submitted value, and without a review record that value remains pending verification.

## How to verify the setup

1. Take the first sentence of the sample material and the draft sentence, and compare region and date field by field. The inputs are the two texts; the comparison covers the region value and the date range; the draft sentence gives "national" for region against "East China" in the material, and the date limit is absent from the draft sentence. The result is judged unsupported.
2. Take the third sentence of the sample material and the draft sentence, and compare the timeliness condition. The inputs are the two texts; the comparison covers whether a deferral condition is present; the material states that the excess is deferred to the next day, while the draft sentence says "all can be dispatched the same day." The result is judged unsupported.
3. Take the output value of the form input node and the manual review record, and compare the collection action against the review action. The inputs are the submitted value passed by the node and any retrievable review record. When no review record exists, the submitted value remains pending verification and is not judged approved or effective. An empty-result handoff can use an explicit paper input of an empty list to check the downstream design, without claiming that retrieval necessarily returns an empty result.
