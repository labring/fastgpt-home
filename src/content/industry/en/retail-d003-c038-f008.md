# Fresh-food concession counters: workflow routing for copy drafting

## What the documents look like

A large-format fresh-food concession counter is frequently operated on site by a supplier under a revenue-sharing arrangement with the store. Copy material for a product therefore arrives from two sides at once: the store's fresh-food department and the concession supplier. The main data sources are the POS system, supplier delivery notes, food-safety ledgers and store stock counts. The documents handled day to day are the concession contract, the daily sales report, loss sheets and food incoming inspection records. For copy drafting, the decisive part of these materials is what they record about the product subject, the batch, the status and the effective scope, because whether a promotional sentence is supported depends on what the source text actually states. The update frequency is daily and per batch; this page does not infer any batch synchronization or transaction-triggered mechanism from that frequency.

## Constraints at the workflow routing step

Copy drafting needs to send the proposed sentence awaiting assessment together with the source text used for comparison into subsequent nodes. When the form input node is triggered, the conversation enters an interactive state, collects the required information, and after submission passes that information to later nodes. When the user selection node is triggered, it likewise enters an interactive state, and after the user makes a choice it executes the corresponding "yes" branch. The documents describe these node behaviours and do not describe a separate global state-recording switch, a fixed number of submissions, automatic judgement or snapshot guarantees.

Hypothetical paper exercise sample: Source text one reads "Concession supplier A delivered spinach to the fresh-food counter of store B on 1 March 2025, batch number SP-0301, with one food incoming inspection record attached." Source text two reads "The fresh-food department of store B recorded in its 1 March 2025 stock count that this spinach batch had a loss of 3 kilograms that day." The proposed sentence awaiting assessment is "The spinach at this counter is picked and delivered fresh the same day, with extremely low loss." The subjects needed for assessment are supplier A and store B, the object is that spinach batch, the status is delivered and recorded as loss, and the effective scope is 1 March 2025. The source texts do not state any assessment basis for "picked and delivered fresh the same day" or "extremely low loss," so the proposed sentence is unsupported.

## Configuration and implementation checks

| Configuration item | Type | Hypothetical starting point for this exercise and reason |
| --- | --- | --- |
| Form input node | User interaction | Collects the proposed sentence awaiting assessment and the source text, then passes them to later nodes after submission |
| User selection node | User interaction | Makes a choice about entering the next comparison branch and executes the "yes" branch |
| Interactive state check | Manual check | Checks whether the interactive state is entered after triggering and whether the state is recorded |

The "hypothetical starting point for this exercise" column is a paper exercise setting, not an official default. The same vector model requirement for a retrieval library applies only to associations within the same retrieval library and does not extend to business registration sites or other external systems.

## Three common errors

1. Treating a promotional wording that the source text does not state as supported. In the sample, the source texts record only delivery, batch and loss quantity, and do not state any assessment basis for "picked and delivered fresh the same day" or "extremely low loss." Outputting that proposed sentence directly is an error.
2. Treating pending review as absence of operating permission. The sample source texts state no review status at all, so inferring that supplier A lacks the right to submit copy would fabricate an authorization conclusion.
3. Treating retrieval relevance as permission or entity isolation. The retrieval scope check in the sample verifies only identifiers and access rights; using a similarity setting to exclude unrelated businesses or unauthorized records goes beyond what the documents describe.

## How to verify the setup

1. Enter source text one, source text two and the proposed sentence awaiting assessment; compare whether "picked and delivered fresh the same day" and "extremely low loss" have corresponding records in the source texts. When the source texts state no such basis and no other evidence exists, the condition is satisfied by outputting "unsupported" and preserving the evidence gap.
2. Enter the sample source texts and a handover request "please write this proposed sentence into the daily sales report"; compare whether the source texts state authorization for writing. When the source texts state no authorization, the condition is satisfied by recording the gap and escalating to manual review without performing the write.
3. Enter a paper empty result [] and the downstream handover design; compare whether the downstream node has an explicit way to handle an empty result. The condition is satisfied when the downstream design states how an empty result is handled and does not claim that a fictional rule retrieval necessarily returns [].
