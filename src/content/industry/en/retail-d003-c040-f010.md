# Customer-service knowledge: citation tracing for copy drafting

## What the documents look like

Customer-service knowledge base maintenance sits in the pre-answer stage of e-commerce support and after-sales work. It prepares reference material rather than approving refunds. The documents handled day to day include FAQ entries, reply templates, product parameter tables, and escalation tickets. The material comes from the customer-service system, product detail pages, after-sales issue statistics, and quality spot checks. The people doing the work are customer-service supervisors, knowledge base operators, and product operators. When this work fails, the visible results are answers that miss the question, escalated complaints, and failed agent training.

For product and marketing copy drafting, citation tracing means checking each promotional sentence in a draft against the wording of the source material. The knowledge base search node outputs cited content as an array, and the array length can be zero. When nothing is found, the output path still runs. The citation limit controls the maximum amount of content cited per search, measured in tokens. The minimum relevance value takes effect only in semantic retrieval or when result reranking is used. These traits mean copy drafting needs a separate check of whether each citation actually supports the specific wording in the draft sentence.

## Constraints at the citation tracing step

A knowledge base has three parts: library, collection, and data. The smallest search unit is the library. Collections only classify and manage data and do not affect search results. When linking knowledge bases, one or more knowledge bases that share the same vector model can be selected for vector search. Knowledge bases with different vector models cannot be linked together. Search results pass through similarity filtering and citation-limit trimming before cited content is returned, and that output may be an empty array.

Hypothetical drill sample

Material source text (for checking, drawn from a product parameter table entry):
"Product name: portable folding table. Material: aluminum alloy. Unfolded dimensions: 60 cm x 40 cm x 30 cm. Load capacity: static placement not exceeding 15 kg. Intended use: outdoor picnics, camping."

Draft sentence to be judged: "This folding table carries up to 20 kg and suits outdoor camping."

Judgment: the material source states a load ceiling of 15 kg, while the draft says 20 kg. Same subject, same field, mutually exclusive values, so this part is unsupported. The intended-use wording matches the source, so that part can be mapped.

A second handover request: "Please confirm whether this product has a quality inspection report number, so it can be noted in the FAQ."

Judgment: the material source does not state a quality inspection report number, so that field is unknown. A pending review state does not show a lack of operating permission and does not show that approval was granted.

## Configuration and implementation checks

The items below concern only this page's feature and primary task. The values are hypothetical starting points for this drill, not official defaults.

| Configuration item | Hypothetical starting point for this drill | Reason for the choice and comparison method |
| --- | --- | --- |
| Linked knowledge bases | Select only knowledge bases with the same vector model | Check whether the vector model identifiers match; exclude those that do not, and do not run cross-model retrieval comparisons |
| Search mode | Semantic retrieval | Run the same question under full-text retrieval and hybrid retrieval, then compare whether the cited content covers the material source text |
| Citation limit | Set to the token amount needed to cover a single FAQ entry | Compare against the length of the material source text involved in the draft sentence, so the cited range can hold the full source |
| Minimum relevance | Leave filtering off for now | Compare against the number of cited items when filtering is on, and observe whether the material source text is missed |
| Question optimization | Off | Compare retrieval time and cited content against the version with it on, to judge whether source mapping is affected |
| Result reranking | Off for now | Compare cited ordering against the version with it on, to confirm whether rerank scores change source mapping |

## Three common errors

1. Treating an empty retrieval output array as a workflow error that stops execution. Error symptom: seeing a cited-content length of zero and concluding the system has failed. The documentation states the output path still runs, and an empty array is a permitted output state.
2. Treating minimum relevance as a permission or entity filter. Error symptom: assuming that raising minimum relevance excludes unrelated businesses or unauthorized records. This value only filters low-relevance content during semantic retrieval or result reranking, and it does not perform authorization isolation.
3. Linking knowledge bases that use different vector models. Error symptom: selecting knowledge bases with different vector models to run retrieval, then comparing missed recalls from that. The documentation requires the same vector model for joint linking. Knowledge bases with different models should first have their identifiers checked and be excluded.

## How to verify the setup

The checks below use the hypothetical drill sample above. They describe input, comparison object, and the condition that must be met. They do not claim that any test was actually run.

1. Input the material source text and the draft sentence, then compare the load value in the draft sentence against the load field in the source. If the draft value exceeds the range stated in the source, judge it unsupported. If the values match, that field can be mapped. Observe whether the cited content includes that material source entry.
2. Input a handover request whose material source does not state a quality inspection report number, then compare the field the request asks about against the fields actually stated in the material source. If the source has no such field, record it as unknown, keep the evidence gap open, and do not judge it as a denial or a conflict.
3. Input an explicit paper-form empty array [] and check how the downstream step is designed to receive empty citations. Observe whether the downstream step still runs when there is no cited content, and whether it handles the empty array separately from an error. This check does not claim that a fictional rule search will necessarily return an empty array.

These three checks cover a numeric contradiction, a missing field, and empty-result handling. Each one requires the actual observed result to be recorded, and missing evidence stays missing.
