# Marketplace promotions: interactive forms for copy drafting

## What the documents look like

Platform promotion registration and price management draws on platform marketing back ends, activity back ends, ERP inventory records and historical transaction prices. The working documents for this category are activity registration forms, promotional price approval sheets, inventory lock sheets and post-activity review sheets. The recurring update rhythm is weekly and per activity.

Compared with product title compliance, the central concern here is price, inventory and activity pacing. Promotional wording review is a secondary matter. When this work goes wrong, the consequences are activity losses, removal of resource slots and price complaints. Copy drafting in this category therefore has to stay tied to the values recorded in the registration form, the approval sheet and the lock sheet, because those documents carry the price, quantity and status facts that any drafted sentence depends on.

The interactive forms step is where a draft request is collected and where a choice between drafting paths is made. The form input node belongs to the user interaction nodes. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues downward after the user completes the interaction. The node collects the information the user fills in and passes it to later nodes. It does not carry a business database function of its own. The user selection node is also a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. When the user makes a selection, the node evaluates that selection and executes the corresponding branch. Its basic use is to pose a question that requires a decision and then design different workflow paths according to the feedback. It is not a staff directory or a business data selector.

Field validation, business approval, write-back and batch operations are implemented as needed in external systems or later nodes. The nodes themselves do not perform those actions. This page does not cover batch synchronization or real-time triggering.

## Constraints at the interactive forms step

The form input node records workflow state and waits for the interaction to complete before continuing. It collects filled-in information and passes it to later nodes. It does not provide submission-count guarantees or snapshot guarantees, and no such controls are documented. The user selection node executes a branch according to the user's selection. It does not query a business database, and no documented setting turns it into one.

Because the collected values feed later drafting, the drafting step inherits the status of the source documents. A field that is present in a form is a collected value, not a verified business fact. A filled-in quantity is a recorded quantity, not evidence that a lock action was executed. An approval sheet status is a recorded status, not evidence that approval was granted.

Hypothetical paper exercise sample. The material text reads: "A brand registers for a platform spring promotion for the period 1 March 2025 to 31 March 2025. The registration form records an activity price of 79 yuan. The inventory lock sheet records a locked quantity of 500 units. The promotional price approval sheet status is pending review." The draft sentence to be assessed reads: "The product activity price has been approved and inventory locking has been completed." The comparison point is this: the approval sheet status field reads pending review, while the draft sentence states that approval has passed. These are mutually exclusive values on the same subject, the same period and the same field, so the sentence is not supported. The inventory lock sheet contains a quantity, while the draft sentence states that locking has been completed. Whether the lock action was executed is a separate fact. The material does not state it, so that part remains to be verified.

## Configuration and implementation checks

| Configuration item | Type | Check point for this page |
| --- | --- | --- |
| Form input node | Documented node behavior | Enters interaction state on trigger, collects filled information and passes it to later nodes |
| User selection node | Documented node behavior | Executes the corresponding branch according to the selection, does not query business data |
| Required information check | Implementation check item | List the fields this task cannot omit, then test the missing-field case and the completed case separately |
| Approval status field | Manual comparison action | Compare the approval sheet status against the wording of the draft sentence |
| Inventory lock execution | Requires a separate system implementation | A filled quantity in the lock sheet does not equal an executed lock action |
| Interaction state recording | Documented node behavior | Waits for the interaction to complete before continuing, with no documented submission count or snapshot guarantee |

The required information check is an implementation check item rather than a documented setting. For this page, the fields that cannot be omitted are the activity period, the activity price, the locked quantity and the approval status. The reason for selecting these four is that the hypothetical draft sentence above depends on all four, and each one is compared against a specific value in the material. A test of the missing-field case compares the behavior when one of these fields is absent against the behavior when all four are present. A test of the completed case compares the collected values against the material text. No numeric default, limit or unit is documented for these fields, and none is asserted here.

## Three common errors

1. Treating a pending-review approval status as approved. The input is the material text above together with the draft sentence. The comparison is between the approval status field value and the wording of the draft sentence. The observable result is that the field reads pending review while the sentence states approval has passed, so the sentence is not supported.

2. Treating a filled quantity in the inventory lock sheet as an executed lock action. The input is the quantity field in the lock sheet. The comparison is whether an execution record exists for the lock action. The material does not state an execution status, so the observable result is that the question remains to be verified and the draft sentence cannot be judged complete on this point.

3. Treating the user selection node as a business data selector. The input is the node definition. The comparison is between the documented function and the configured behavior. The observable result is that the node executes a branch according to the selection, and a configuration that makes it query a business database falls outside the documented function.

## How to verify the setup

1. Take the material text and the draft sentence given above. Check whether the approval status field reads pending review and whether the draft sentence states that approval has passed. When the two are mutually exclusive on the same subject, period and field, the sentence is not supported. The expected observation is a mismatch between the field value and the sentence wording.

2. Take the quantity field in the inventory lock sheet. Check whether an execution record for the lock action exists. When only a quantity is filled in, whether the lock was executed remains to be verified, and completion cannot be concluded. The expected observation is the presence or absence of an execution record, with absence leaving the question open.

3. Take the user selection node configuration. Check whether its branch logic depends only on the user's selection. If it is configured to query business data, that exceeds the documented function. The expected observation is a branch that follows the selection, and any data query behavior is a deviation from the documented scope.

These checks compare drafted sentences against the supplied source wording and its limits. They do not extend to identity certification, report analysis or any other task. Where the material is silent, the gap is recorded rather than filled.
