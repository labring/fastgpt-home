# Marketplace category access: context limits for copy drafting

## What the documents look like

Category access happens before a product is listed or a store is onboarded. The core materials are the business license, the trademark registration certificate, the brand authorization chain, and industry licenses. The entity names, authorized parties, validity periods, and permitted scope written in these materials determine which promotional sentences a draft product description can rely on. The drafting step rewrites fields already stated in the materials into checkable wording. Materials are collected again at each onboarding, and this page does not describe any batch synchronization mechanism.

For this drafting task, three facts matter most. First, the model context is checked against the actual model capability; the reply length limit is not the full context window. Second, the knowledge base reference limit is measured in tokens, so a long single material may be truncated, and whether key fields enter the context intact must be checked against a question sample. Third, retrieval similarity only affects recall ordering and does not perform entity isolation or permission filtering.

## Constraints at the context limits step

The model context is confirmed from the actual model capability. The reply length limit controls how long one answer may be and is not the complete context window, so a long authorization chain can exceed what a single request carries even when the reply limit looks generous.

The knowledge base reference limit is expressed in tokens. When one section of material is long, it may be trimmed before reaching the model, so the drafting step needs to check, against a question sample, whether the entity name, authorized party, validity period, and permitted scope all arrive in the context.

History changes the actual input for the same question. Comparing the same question with empty history and with history isolates the difference caused by context rather than by the materials.

When a fixed reply format is used, field completeness and successful parsing are verified separately; checking text length alone does not confirm that the required fields were returned. Retrieval similarity affects recall ordering only. It does not decide whether the entity in a draft matches the entity in a certificate, and it does not exclude unauthorized records.

## Configuration and implementation checks

The following is built around a hypothetical paper exercise sample. Sample material text (fictional): a trademark registration certificate numbered 12345678 records the registrant as "Company A" and lists registered goods including Class 25 clothing; a brand authorization letter states that "Company A authorizes Company B to sell Class 25 clothing from 1 January 2026 to 31 December 2026." Draft sentence to be assessed: "Company B is the brand's exclusive national general agent, and the authorization is valid long term."

| Configuration item | Hypothetical starting point for this exercise | Reason for the choice and comparison object |
| --- | --- | --- |
| AI model | Select a model that supports the required context | Compared with the total material length and the draft sentence review needs |
| Reply limit | Hypothetical starting point of 800 tokens | Compared with the measured length of the draft sentence plus its basis note |
| Reference limit | Hypothetical starting point of 3000 tokens | Compared with the single-section length of the authorization letter plus the registration certificate |
| Minimum relevance | Hypothetical starting point of 0.5 | Compared with the score distribution after reranking is enabled |
| Reply format | Select json_schema and fill in the field requirements | Compared with the downstream parsing field list |
| Memory rounds | Hypothetical starting point of 3 rounds | Compared with the input difference across multi-turn follow-up scenarios |

These values are starting points for this paper exercise, not official defaults. Each is compared against a stated object, and the comparison result determines whether the value is adjusted.

## Three common errors

1. Reading "the authorization letter states a sales period" as "valid long term." The input is the authorization letter text above; the comparison object is "valid long term" in the draft sentence. The authorization letter states no long-term clause, so the phrase is unsupported.
2. Expanding "registered goods include Class 25 clothing" into "exclusive national general agent." The input is the trademark registration certificate text above; the comparison object is "exclusive national" in the draft sentence. The certificate states no exclusivity or territory, so the phrase is unsupported.
3. Treating a retrieval similarity score as an entity filter. The input is the returned score; the comparison object is the entity field. The score does not judge whether entities match, and entity checking requires a separate field comparison.

## How to verify the setup

1. Input the authorization letter text above together with the draft sentence "Company B is the brand's exclusive national general agent," and compare whether the exclusivity and territory wording in the draft can be found in the authorization letter fields. The condition is met only when the authorization letter states exclusivity and a territory range; otherwise record the wording as unsupported.
2. Input the trademark registration certificate text above together with the draft sentence "the authorization is valid long term," and compare the registrant and registered goods stated in the certificate against the entity and period in the draft sentence. Record a contradiction only when the same entity, the same period, and the same field show mutually exclusive values; record an unstated item as pending verification.
3. Input an empty reference result as a paper input, and check the downstream node's design for handling an empty result. Do not infer that a fictional-rule retrieval necessarily returns an empty array; record only the observed output and the downstream handling action.

All of the above is paper reasoning. No actual retrieval, approval, or listing action was performed.
