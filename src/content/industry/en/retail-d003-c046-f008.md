# Marketplace category access: workflow routing for copy drafting

## What the documents look like

Category access on a marketplace platform happens before a product is listed or a store is onboarded. The review target is the operating entity's qualifications and the brand authorization chain, not the store's ongoing rating history. The working documents are the business license, the trademark registration certificate, the brand authorization chain, and industry licenses. These materials come from platform recruitment pages, the national enterprise credit information publicity system, trademark office data, and license systems. They are updated irregularly, and each onboarding submission starts a fresh review.

Copy drafting depends on these materials. Brand names, category terms, and qualification claims that appear in proposed copy must correspond to what the authorization chain and licenses actually record. Collecting the authorization chain and matching the operating category are the time-consuming steps. Drafting work compares material fields against each proposed sentence, so that a claim without support is caught before listing rather than after a rejection.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. After the user fills the required information and submits, the node collects the submitted form values and passes them to subsequent nodes. The User Selection node is also a user interaction node. When the user makes a choice, the node evaluates that choice and executes the "yes" branch. Branch connections are verified one by one. Both nodes can be added repeatedly and trigger execution. The interaction state is node behavior; no separate global state-recording switch is documented.

Information collected at these nodes must be explicitly passed to later retrieval, judgment, or interface nodes, and outputs are compared against inputs item by item. Order writing, document backfill, and external status synchronization require a separate business interface or a later process. The nodes themselves do not perform those actions.

Hypothetical paper exercise. Source text one: "Trademark registration number XXX has registrant Company A, with approved goods in Class 9, computer software." Source text two: "Company A authorizes Company B to sell Class 9 software products in mainland China, authorization period 1 January 2025 to 31 December 2026." The draft sentence to be assessed: "Company B is officially authorized for exclusive sale of the full software product series in mainland China." The comparison checks authorization subject, goods category, territory, and period. The word "exclusive" does not appear in either source text. Whether the authorization period covers the intended publication date requires separate verification.

| User Selection node | User interaction node | Executes the "yes" branch after a choice; branch connections verified one by one |

| Output handoff check | Implementation check | Collected information is explicitly passed to later retrieval, judgment, or interface nodes and compared item by item |
| External action split | Implementation check | Order writing, document backfill, and external synchronization attach to a business interface or later process |
| Hypothetical starting value | Starting point for this exercise | Draft-sentence comparison uses the authorization period 1 January 2025 to 31 December 2026 as its baseline, chosen because the sample source text records that period |

## Three common errors

1. Treating the interaction state record as a global state switch. Triggering the node enters the interaction state and records workflow state as node behavior. Configuring a separate global switch has no documented basis; the check covers the node's own behavior only.
2. Treating form-collected information as already verified. The node collects and passes what the user submits. Entity qualification verification and authorization-chain comparison belong to later judgment or manual review. The node does not complete verification.
3. Writing external actions into node responsibilities. Order writing, document backfill, and external status synchronization require a separate business interface or later process. Node output carries information transfer only.

## How to verify the setup

1. Input the two hypothetical source texts and the draft sentence "Company B is officially authorized for exclusive sale of the full software product series in mainland China." Compare authorization subject, goods category, territory, period, and the wording of the draft sentence. The condition is met when "exclusive" is recorded as unsupported because neither source text contains it, and whether the authorization period covers the publication date remains to be verified. When the condition is not met, keep the evidence gap and do not supply authorization terms.
2. Input the required fields and the submit action of the Form Input node. Compare whether the submitted field values reach the later node. The condition is met when the later node receives field values consistent with what was submitted. If a field is empty or not passed, record a handoff failure and check the node connections.
3. Input one selection action at the User Selection node. Compare the branch taken against the configured connection. The condition is met when the corresponding "yes" branch executes after the choice. If the branch does not execute, check the branch connections one by one and record the actual observation rather than inferring a runtime result.
