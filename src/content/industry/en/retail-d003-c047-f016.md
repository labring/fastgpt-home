# Marketplace returns: copy drafting with interactive forms

## What the documents look like

For copy drafting in Marketplace returns, this page examines FastGPT interactive forms. A torn-bag claim, an outer-packaging inspection and a refund approval support different sentences. The proposed copy exercise follows each statement into the draft with its own evidence limits. The examples are hypothetical.

## Constraints at the interactive forms step

Proposed return material contains “the bag opening is torn” in the application, while an inspection excerpt only records scratches on the outer packaging. An attached image is marked as another order. Preserve each source instead of merging similar descriptions into one inspection finding. A form can collect the passages and let a person choose inspection-source organization or refund evidence collection. Submission passes input onward; it does not merge applicant statements with inspector findings.

## Configuration and implementation checks

| Return-copy comparison | Proposed passage | Drafting check |
| --- | --- | --- |
| Applicant statement | Torn bag opening | Not promoted to an inspector finding |
| Inspection excerpt | Scratched outer packaging | Does not establish an opening defect |
| Photograph origin | Marked as another order | Cannot support this item’s appearance |
| Refund approval | Approval without execution result | Not worded as returned |
| Human choice | Collect processing evidence | Inspect receipt on connected branch |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Form input` | Collect input and pass values after submission. |
| `Required-information check` | Design required business inputs and missing-input handling. |
| `User selection` | The selected option maps to a connected branch. |
| `Interaction state` | Inspect waiting and completed interaction separately. |
| `Downstream responsibility` | Verify validation, approval and write results separately. |

## Three common errors

Claim promoted to inspection finding: If the draft calls the torn opening confirmed, inspect this item’s actual inspection passage; packaging scratches do not establish that conclusion. Another order’s image mixed in: Compare its order marking and origin before using it to describe this item. Approval promoted to executed refund: “Returned” needs the corresponding refund-processing record and result. Approval wording cannot fill that execution gap.

## How to verify the setup

Compare submitted text with downstream input to see whether applicant and inspector remain distinct and whether the photograph’s origin stays separate. For the choice to collect refund evidence, follow the connected branch and inspect the passage actually received. Submission of that choice does not complete a refund. After adding this item’s inspection conclusion, redraft and check that only supported appearance claims change. Keep the refund outcome unresolved while its evidence is missing; actual refund and inventory handling require the separately connected business process.
