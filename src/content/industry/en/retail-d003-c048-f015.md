# Parcel labels and handoffs: retrieval for copy drafting

## What the documents look like

Parcel handoff happens at the point where a package leaves the warehouse, and the central question is carrier scan responsibility. The documents in this category are electronic waybills, handoff manifests, pickup scan records, and exception item registers. They come from courier systems, WMS shipment records, carrier billing, and GB/T courier service standards. When these materials are used to draft product and marketing copy, retrieval has to answer whether a proposed sentence can be supported by a waybill field or a handoff record. Typical claims concern delivery time commitments, pickup status, and how exceptions are described. These materials update per batch and per day. This page does not derive batch synchronization, full synchronization, real-time behavior, or transaction-triggered mechanisms from that update frequency.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases built on different vector models cannot be associated together. The check is to compare vector model identifiers and exclude those that do not match. A cross-model retrieval is not run to compare missed recalls.

Retrieval recalls candidate content through semantic search, full-text search, or hybrid search. Hybrid search merges multiple result paths through RRF. RRF is a fusion process, not a switch that is turned on. The minimum relevance score takes effect only under semantic search or when result reranking is used. It is a filter threshold. It is not a permission or entity isolation mechanism, and retrieval itself does not constitute authorization. The reference limit is measured in tokens. The output reference content is an array, and its length can be 0.

Hypothetical drill sample: the source material reads, "This batch of electronic waybills was handed to the carrier branch on March 10, 2025. The handoff manifest lists 120 items. The pickup scan record shows 118 items scanned that day. The exception item register records 2 items pending verification." The draft sentence to be assessed is, "This batch of parcels has been fully picked up." The assessment requires the same subject, the same period, and the same field. The scan record shows 118 items, while the draft sentence claims all. That claim is unsupported. The 2 exception items pending verification are also not covered.

## Three common errors

1. Treating "118 items in the scan record" as "fully picked up." The input is the draft sentence and the scan record. The comparison is the item count field. When the scanned count is lower than the handoff count, the result should be unsupported. It cannot be judged as consistent.

2. Treating the minimum relevance score as a permission filter. The input is an unrelated business question. The comparison is between its recall results and the authorized scope. A relevance score does not exclude unauthorized records. Retrieval results cannot replace an authorization decision.

3. Forcing knowledge bases with different vector models into a joint association. The input is two knowledge bases with different vector model identifiers. After comparing the identifiers, those that do not match should be excluded. No further claims about missed recall or redundancy should be fabricated.

## How to verify the setup

1. Input the hypothetical sample source text and the draft sentence "This batch of parcels has been fully picked up." Compare the scanned item count with the draft wording. When the scanned count is lower than the handoff count, the unsupported judgment is met, and the gap of 2 items pending verification is recorded.

2. Input a question containing an exact identifier. Use full-text search and semantic search separately and compare the hits. Observe whether the identifier field can be recalled through the full-text path. A first-position hit is not guaranteed.

3. Input a clearly labeled paper empty reference array []. Check whether the downstream design can accept an output of length 0. Do not claim that a fictional rule retrieval will necessarily return an empty result.
