# Complaints and official replies: workflow routing for copy drafting

## What the documents look like

Complaints and official replies are directed at platforms or regulators, so the material has to carry formal evidence and corrective wording. The main sources are the 12315 platform, platform complaint centers, customer service chat, and order systems. Everyday documents include complaint tickets, regulatory inquiry letters, order evidence, and corrective action reports. Compared with after-sales repair or reshipment, this category depends more heavily on written material that can be checked line by line, and the outcome can lead to administrative investigation, platform penalties, or brand exposure. Updates are irregular and case by case; this page's workflow routing does not change node behavior based on update frequency.

For product and marketing copy drafting in this category, proposed promotional sentences or draft reply sentences must be compared against existing material sentence by sentence. Workflow routing is responsible for collecting the necessary information at interaction nodes and then passing that information to later nodes. Node behavior has clear boundaries: the Form Input node enters an interaction state when triggered, collects required information, and after submission passes the information to later nodes; the User Selection node executes the corresponding "yes" branch after the user makes a choice. Order writes, document backfill, and external status synchronization require a separate business interface or a later process; the nodes themselves do not complete those business actions.

## Constraints at the workflow routing step

Complaint and regulatory material has three elements: subject, period, and field. Copy judgment must use the same subject, the same period, and the same field. A statement that is not recorded, or that has only evidence from a related stage, is unsupported or pending verification; it cannot be called a denial or a conflict. Pending review does not demonstrate a lack of operating permission; signing, reaching cooperation, and contract effectiveness are three different facts; a quotation validity period does not indicate a supply period.

Hypothetical drill sample: the source material reads, "A certain shop sold Model A thermos cups from March 1, 2025 to March 31, 2025, and the page stated '24-hour heat retention.' The shop received a platform complaint ticket on March 20, and the complaint content was that the heat retention duration did not match the page statement. The shop manager submitted a corrective action report on March 25, stating that the page had been taken down." The draft sentence to be judged is, "This shop's Model A thermos cup has been tested and can maintain water temperature within 24 hours, and the page statement is true and accurate." Against the material, the source only records the sales period, the page statement, the complaint ticket, and the submission of the corrective action report. There is no test report field and no test conclusion field. The draft sentence's "has been tested" and "true and accurate" are unsupported by the material and should be recorded as pending verification, not as a denial.

The workflow routing constraints follow from this: information collected by the Form Input node must be explicitly passed to later retrieval, judgment, or interface nodes, and output and input must be compared item by item. Interaction state recording is behavior of interaction nodes; no separate global state recording switch is set or claimed. The "yes" branch of the User Selection node must be verified connection by connection. The requirement that retrieval libraries share the same vector model cannot be extended to claim that business registration sites or other external systems must also use the same model. Semantic recall and relevance scores are not responsible for permission or entity isolation; retrieval is not authorization. Libraries across different vector models cannot be associated together; first check identifiers and exclude those that do not match, and do not run cross-model retrieval to compare missed recalls.

## Configuration and implementation checks

The configuration centers on the hypothetical drill sample and lists only documented settings or implementation check items relevant to this feature and the primary task.

| Configuration item | Hypothetical trial starting point | Reason for choice and comparison method |
| --- | --- | --- |
| Form Input node | Set two required fields, "source material" and "draft sentence" | The documentation states that Form Input collects required information and passes it to later nodes; after submission, compare field values against the sample source item by item |
| User Selection node | Set a branch, "does the material contain a test conclusion" | The documentation states that User Selection executes the "yes" branch after a choice; check the branch connection against the choice result |
| Interaction state check | After triggering the node, confirm the conversation enters the interaction state | The documentation states that interaction nodes record state; no separate global state recording switch is set |
| Output handoff check | Pass the collected fields to a later judgment node | The documentation states that information is passed to later nodes; compare output and input item by item |
| External action division | Order writes, document backfill, and external status synchronization connect to separate interfaces | The documentation states that these actions require a separate business interface or later process, and nodes do not complete them automatically |
| Retrieval scope check | Check the target retrieval scope and access rights | Retrieval is not authorization; when access rights are missing, record the evidence gap |

## Three common errors

1. Writing "the material does not record a test conclusion" as "the material denies a test conclusion." The error is treating lack of support as denial. Check: input the sample source material, compare whether a test conclusion field appears in the source; if it does not appear, record it as pending verification, not as denial.
2. Treating the "yes" branch of the User Selection node as an external action that has already been executed. The error is treating a branch choice as a completed order write or document backfill. Check: input the user selection result, compare whether the later node connects to a business interface; if it does not connect, record that the external action is not implemented.
3. Treating retrieval relevance as a means of permission or entity isolation. The error is assuming that a similarity setting can exclude unrelated business or unauthorized records. Check: input a retrieval query, compare the returned results against the authorized scope; if the authorized scope is not configured separately, record that retrieval does not serve an authorization function.

## How to verify the setup

1. Input the source material and draft sentence from the hypothetical drill sample, and compare whether "has been tested" and "true and accurate" in the draft sentence have corresponding fields in the source. If the source has no test report field, the expected result is pending verification, not denial or conflict.
2. Input the user selection "does the material contain a test conclusion," and compare the selection result against the "yes" branch connection. If the choice is "no," the expected behavior is to execute the corresponding branch, and check whether the later node passes the field to the judgment node.
3. Input an explicit paper-based empty result [], and compare whether the downstream design handles the empty result. If the downstream does not have an empty-result handoff design, record it as unverified; do not claim that a fictional rule retrieval will necessarily return [].

These expectations are paper-based checks. No actual deployment, approval, or external synchronization has been performed. Missing evidence remains missing; pending review is not treated as approval; an offered option is not treated as executed; an unsigned termination is not treated as a completed termination.
