# Complaints and official replies: model connections for copy drafting

## What the documents look like

Complaint and regulatory reply work is directed at a platform or a supervisory authority, and it depends on formal evidence and rectification wording. The everyday materials are complaint tickets, regulatory inquiry letters, order evidence, and rectification reports. In this setting, product and marketing copy drafting produces an explanation or a rectification position for a disputed promotional sentence, and the basis for judgment comes from the original wording in the ticket, the inquiry letter, and the order evidence.

These materials update irregularly and differ case by case. That characteristic means the connection step cannot run on a fixed batch schedule; it proceeds by case-by-case checking.

## Constraints at the model connections step

Model access requires AI Proxy. Both App and Admin must set AIPROXY_API_ENDPOINT and a non-empty AIPROXY_API_TOKEN, and a missing item causes startup validation to fail. AIPROXY_API_ENDPOINT holds the service root address without an appended `/v1`. AIPROXY_API_TOKEN is an administrator token and cannot be replaced with an application API key.

Model capability is checked against the input the application needs. Multimodal input and tool calling are verified separately. Application parameters are set in the application or node configuration, and the same-named fields of a chat interface cannot be assumed to override the orchestration.

Hypothetical drill sample: a shop receives a platform complaint ticket stating that the consumer claims the product page asserted "results within three days", with order number A-2024-0312 and order date 12 March 2024. The shop retains a historical version of the product page whose text reads "this product is an ordinary skincare item, and continued use is recommended". The draft sentence to be judged is: "The product page never made any efficacy promise." The comparison object is whether the promotional sentence cited in the ticket and the retained page text share the same subject, the same period, and the same field.

## Configuration and implementation checks

Configuration centres on checking the sample and lists only documented settings or implementation checks relevant to this task. The values are hypothetical starting points for this exercise, used for comparison with the sample materials.

The starting point is chosen because the sample involves only text and a retained page, and does not need image input. The comparison object is the order number and date stated in the ticket.

## Three common errors

1. Treating the draft sentence as a verified fact. The draft sentence "never made any efficacy promise" is text awaiting judgment; the ticket original states only the consumer's claim, and the retained page states only that continued use is recommended. The input is the draft sentence and the two materials, the comparison is same subject, same period, same field, and the observable result is that the retained page contains no efficacy promise wording while the ticket claim remains to be verified.
2. Treating a passed channel test as a passed copy judgment. A channel test verifies only model connectivity, not whether a promotional sentence is supported by the materials. The input is the model test result and the draft sentence, the comparison objects differ, and the observable result is that the two cannot substitute for each other.
3. Treating retrieval relevance as a permission or entity filter. Relevance does not exclude unrelated businesses or unauthorized records. The input is the retrieval return and the ticket subject, the comparison is the subject identifier, and the observable result is that records with a mismatched subject must be excluded manually.

## How to verify the setup

1. Check the draft sentence against the ticket and the retained page. The input is the three original sentences of the sample, the comparison is same subject, same period, same field, and the condition is met when the retained page text and the ticket claim point to the same product and the same period, and the draft sentence wording agrees with the retained text.
2. Check model access. The input is the hypothetical values entered for AIPROXY_API_ENDPOINT and AIPROXY_API_TOKEN, the comparison is the deployment document format requirement, and the condition is met when the root address has no `/v1` and the token is non-empty and matches the server configuration.
3. Check material gaps. The input is the sample material list, the comparison is the fields stated in the ticket against the fields in the retained page, and the condition is met when gaps are explicitly recorded as pending verification, without fabricated authorization or effective clauses. An empty result can be checked against downstream design using the paper input `[]`, without asserting that a fabricated rule search necessarily returns empty.
