# Douyin storefront operations: context limits for copy drafting

## What the documents look like

Douyin storefront shelf operations centre on product cards and the store experience score, and do not depend on the rhythm of a single livestream. The working documents for this category are product qualification pages, experience score breakdowns, shipping violation appeals, and store announcements. These materials update daily or per order. Product and marketing copy drafting draws checkable statements out of those materials and turns them into product card copy or a handover request.

Whether a promotional sentence in a draft can stand depends on whether the qualification page states the corresponding subject, object, and validity scope, and whether the experience score breakdown records the relevant status. Context and token settings control how much material, how many history turns, and how much quoted content length are sent to the model during drafting, so that each drafted sentence stays traceable to the source text it rests on.

## Constraints at the context limits step

The context window is set by the chosen model. The reply limit only caps generated length and cannot be treated as the full context window. The knowledge base reference limit is controlled by tokens; a long single passage may be trimmed, so question samples are needed to check whether the quoted content is complete. Memory turns determine how many prior rounds are referenced; a large value brings in unrelated content and raises consumption. When a fixed reply format such as json_schema is used, field completeness and successful parsing need to be verified. A relevance score filters low-relevance content and does not perform permission or entity isolation. Libraries across different vector models cannot be associated with each other; identifiers are checked and non-matching items are excluded. RRF is the fusion process for mixed retrieval results, not a switch that can be turned on. Thinking budget belongs to model thinking strength configuration and is a different concept from the reference token limit.

## Configuration and implementation checks

The following items address the product and marketing copy drafting task and are checked against a hypothetical drill sample. The values are starting points for this hypothetical trial, used for comparison, and do not represent official defaults.

| Configuration item | Hypothetical trial starting point and reason | Check method |
| --- | --- | --- |
| AI model | Choose a model whose context length can hold the qualification page passage and the drafted sentence | Compare the model maximum context with the total length of material sent in |
| Memory turns | Set to 2, since this task mainly checks a single document | Compare the input difference between empty history and 2 turns of history |
| Reply limit | Set to 800, enough to hold the basis explanation and the drafted sentence | Check whether the reply is truncated at the basis explanation |
| Knowledge base reference limit | Set to 2000 tokens, estimated from the length of a single qualification passage | Check whether the quoted content contains the complete validity scope |
| Minimum relevance | Set to 0.5, used to filter low-relevance fragments | Compare the correspondence between quoted content and the question before and after filtering |
| Reply format | Select json_schema when fixed fields are required | Check field completeness and the parsing result |

## Three common errors

1. Treating the reply limit as the full context window. The reply limit only caps generated length, while the material length the model can reference is set by the maximum context. During the check, compare the total length of material sent in with the model maximum context and observe whether the material is truncated.
2. Treating the relevance score as a permission or entity filter. Relevance only reflects how similar the content is to the question and does not exclude unrelated business or unauthorized records. During the check, verify whether the quoted content contains statements about another subject or beyond the authorized scope.
3. Mixing up thinking budget and the reference token limit. Thinking budget controls model thinking strength, while the reference limit controls the length of quoted content sent to the model. During the check, verify the value and the target of each setting separately.

## How to verify the setup

Hypothetical drill sample: the source material reads, "This store sells a certain model of insulated cup, material 304 stainless steel, capacity 500 millilitres, standard GB/T 29606, quality inspection report number JC-2024-0312 for this batch, report date 12 March 2024, applicable to store announcement No. 7 of 2024." The drafted sentence reads, "This product uses 304 stainless steel, capacity 500 millilitres, and meets the national standard." The check request reads, "Please judge, based on the qualification page content above, whether this drafted sentence is supported."

1. Input the source material and the drafted sentence, and compare whether the material, capacity, and standard statements in the drafted sentence correspond to the same subject and the same fields in the source. The source states the material and capacity but does not state the conclusion "meets the national standard." That conclusion is unsupported and should be recorded as pending verification, not judged as a negation or a conflict.
2. Input the same question with empty history and with 2 turns of history, and compare the difference in the input sent to the model across the two runs. If the run with history quotes old material unrelated to this qualification page, the memory turn setting is too large and should be lowered before rechecking.
3. Input a clear empty reference result [] and check how the downstream node behaves when there is no quoted content. This check confirms the downstream design and does not claim that a fictional rule lookup must return an empty result.
