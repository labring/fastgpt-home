# Franchise filing management: interactive forms for copy drafting

## What the documents look like

Franchise filing management works with the commercial franchise information management system, enterprise licences, store lists and contract ledgers. The subject matter is legal disclosure and the commerce department system, not the engineering of a specific site. The documents handled day to day are franchise contracts, operations manuals, filing materials and information disclosure documents. These materials are updated irregularly or once a year. This page does not derive batch synchronization or real-time triggers from that update pattern.

Drafting product and marketing copy depends on these documents for verifiable wording. Sentences about operating resources, service content and store conditions need to correspond to what the contract, manual and disclosure documents state. Wording that the materials do not state remains unsupported; copy phrasing cannot fill the gap.

## Constraints at the interactive forms step

The form input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution waits until the user completes the interaction. After the user fills required information and submits, the node collects the entered form information and passes it to later nodes. The user selection node also enters an interaction state and executes a branch according to the user's choice. Neither node includes business database functions. Field validation, business approval, write-back and batch operations must be implemented in an external system or in later nodes.

Hypothetical paper exercise sample: a franchise headquarters legal reviewer submits material for checking. The source text reads: "Section 3.2 of this brand's operations manual states: franchise stores must use ingredients uniformly delivered by headquarters." A second source sentence reads: "The manual does not state any authorization for franchisees to procure ingredients independently." The proposed copy sentence is: "All ingredients at franchise stores are supplied exclusively by headquarters." A handover request accompanies it: "Please confirm whether this proposed sentence can be used on the recruitment page."

The constraint is that the form collects the correspondence between the proposed sentence and the source text. The form itself does not judge whether the promotional sentence is supported. The user selection branch can distinguish "stated in materials" from "not stated in materials", but the branch result does not constitute approval. The source text does not state authorization or effective clauses, and that gap stays open.

## Configuration and implementation checks

| Configuration item | Type | Use and checking method on this page |
| --- | --- | --- |
| Form input node | Existing node behaviour | Collects three entered items: proposed sentence, source text, material name |
| Required-field check | Implementation check | When the proposed sentence or source text is missing, the interaction state does not complete submission |
| User selection node | Existing node behaviour | Executes two branches: "stated in materials" and "not stated in materials" |
| Interaction state | Existing node behaviour | Records workflow state after triggering and waits for the user to complete the interaction |
| Downstream division of work | Implementation check | Field validation, approval and write-back are implemented in an external system or later nodes |

For this exercise the assumed starting point is the three required form fields. This starting point is chosen because the sample contains three kinds of information — proposed sentence, source text and material name — matching the input needed for the later branch decision. The comparison method is to delete one field at a time and observe whether the interaction state completes.

## Three common errors

1. Treating the proposed sentence as an already verified conclusion. In the sample the proposed sentence says "all ingredients", while the source text says only "ingredients uniformly delivered". The scopes do not match. The error is to skip the scope comparison and output that the sentence is usable.
2. Treating the "stated in materials" branch of user selection as approval. The branch only represents a selection result; approval requires an external system. The error is to write back "approved" directly after the branch.
3. Treating form input as a business database. The node collects entered information and passes it on; it does not perform database writes. The error is to assume that submission automatically updates the filing material ledger.

## How to verify the setup

1. Enter the three sample fields and submit. Compare the scope wording of the proposed sentence with the source text. The condition is met when the interaction state records completion and the later node receives the three field values.
2. Delete the source text field and submit. Compare whether the interaction state completes. The condition is met when the interaction state does not complete and the required-field check reports the missing item.
3. At the user selection node, choose the "not stated in materials" branch. Compare the subsequent execution path. The condition is met when the "not stated in materials" branch executes and no approval or write-back action appears.

All three verifications are paper checks and were not actually run. Authorization or effective clauses not stated in the source text remain missing and are not fabricated.
