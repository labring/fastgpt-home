# Producer export tax processes: workflow routing for copy drafting

## What the documents look like

Producer export tax processes combine the offset of domestic-sales tax against export refund in a single calculation. That combination shapes the material set for copy drafting. For this page, the material set is the exemption, offset and refund declaration detail table, the export contract, the sales detail ledger, and the export customs declaration. These materials update monthly. Product names, trade terms, transaction prices and quantity scopes in drafted copy need to stay consistent with them.

The drafting difficulty comes from four different recordkeeping purposes. The declaration detail table records a tax calculation basis. The export contract records a transaction agreement. The sales detail ledger records bookkeeping aggregation. The export customs declaration records customs electronic information. Their fields do not map one to one, so a phrase from one material can be carried into copy without checking whether another material states the same fact.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and after the user completes the required information and submits, the node passes the collected form information to later nodes. The User Selection node is also a user interaction node. When the user makes a selection, the node evaluates that selection and executes the "yes" branch. Both nodes can be added repeatedly and trigger execution.

The constraint is that interaction nodes collect values and route branches. They do not perform business verification. Whether a promotional sentence in drafted copy is supported by the materials has to be checked in a later node or by a person. Order writing, document backfill and external status synchronization require a separate business interface or a later process.

Hypothetical paper exercise: an export producer, tax accountant, declaration period July 2024. A product copy draft is submitted. The material texts available for comparison are: the export contract states "goods name: aluminum alloy bracket, trade term FOB, quantity 1,200 pieces"; the export customs declaration states "commodity name: aluminum alloy bracket, trade term FOB, quantity 1,200 pieces"; the exemption, offset and refund declaration detail table states "total export goods FOB price, quantity 1,200 pieces". The sentence to be assessed is: "This product uses an aluminum alloy material, suits outdoor scenarios, and has a monthly capacity of 5,000 pieces." The comparison scope is limited to those three materials.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | Comparison method |
| --- | --- | --- |
| Form Input node | Collect the copy draft text and the corresponding declaration period | After submission, compare output with input for consistency |
| User Selection node | Branch condition set to "whether materials cover the promotional point" | Verify the "yes" branch connection item by item |
| Interaction state check | Enters interaction state after triggering | Confirm the recorded state is node behavior; no separate global switch is set |
| Output handoff check | Pass collected information to a later judgment node | Compare output with input item by item |
| External operation separation | Order writing connects to a separate business interface | Confirm it is not completed inside the interaction node |

The values in the table are hypothetical starting points for this exercise. The reason for selecting the July 2024 declaration period is that it matches the dates of the sample materials. The comparison objects are the quantity and trade term in the material texts.

## Three common errors

1. Treating the total FOB price in the exemption, offset and refund declaration detail table as the sales price in copy. That table records a tax calculation basis, and the transaction price in the export contract is a different field. Check: input the three sample materials, compare the field "trade term FOB" with the field "total FOB price", and observe whether the two are merged into one statement.

2. Setting the branch condition of the User Selection node as a business judgment. That node evaluates the user's selection and executes the "yes" branch. It does not check whether materials support a promotional point. Check: input the sample draft sentence, compare the branch condition text with "whether materials cover the promotional point", and observe whether the branch is treated as a business review.

3. Treating the recorded interaction state as an approval. The Form Input node records workflow state and passes information after submission. It does not produce an approval conclusion. Check: input the sample draft, compare the node output with the words "approval passed", and observe whether an approval conclusion appears in the output.

## How to verify the setup

1. Input the three sample material texts and the draft sentence "This product uses an aluminum alloy material, suits outdoor scenarios, and has a monthly capacity of 5,000 pieces." Compare whether the materials state "outdoor scenarios" and "monthly capacity of 5,000 pieces". Expected observation: the materials do not state these two items, so the corresponding parts of the draft sentence are unsupported and the evidence gap is recorded. The support condition is met only if the same field appears in the materials with a consistent value.

2. Input "trade term FOB" and "quantity 1,200 pieces" from the sample. Compare these fields across the export contract, the export customs declaration and the exemption, offset and refund declaration detail table. Expected observation: the check condition is met when the three fields are consistent. When a difference appears, record the difference and do not judge it as a contradiction unless the same field has clearly mutually exclusive values.

3. Input the paper empty result [] and check whether the downstream design handles an empty result. Expected observation: the downstream node has a defined handling path for an empty result. Do not claim that a fictional rule retrieval necessarily returns []. If the downstream has no handling path, record the gap and do not infer a system error or an automatic action.

This page addresses only producer export tax processes, product and marketing copy drafting, and workflow routing. Whether a specific promotional sentence in product copy is supported by materials is not an enterprise identity certification tutorial. The interaction nodes collect and branch; they do not verify business facts. A submitted form is not an approval. An offered branch is not an executed business action. An unsigned termination is not a completed termination. Missing evidence remains missing.
