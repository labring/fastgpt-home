# Fresh-food weighing and sorting: model connections for copy drafting

## What the documents look like

Copy drafting for fresh-food weighing and sorting draws on four document types: sorting task sheets, weighing labels, short-weight compensation forms, and quality inspection records. These materials carry weight, specification, batch, and time information, and they update per order and daily. Weight ranges, specification descriptions, and compensation commitments in drafted copy need corresponding fields in those materials. Grade, origin, or timing details that the materials do not state remain unsupported content.

The weighing and sorting stage sits inside warehouse fulfillment, where weight and specification are the core variables. That placement shapes what a drafting model can be asked to do. A drafted sentence about a weight floor or a completeness rate is a claim about a specific batch record, not a general product attribute, so the drafting step needs the source material available at the point of generation.

## Constraints at the model connections step

Model access runs through AI Proxy. App and Admin must each set `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN`; a missing item in either place causes startup validation to fail. Legacy OpenAI variables and single-model custom request addresses cannot substitute for these two settings. Model capabilities are checked against the inputs the application actually needs: image recognition, tool calling, and thinking configuration are verified separately. Application parameters are set in the application or node configuration; a same-named field on a compatible chat interface is not assumed to override orchestration.

Hypothetical drill sample: the source material reads, "Sorting task sheet 2026-09-23 batch A, spinach net weight 480 g to 520 g, specification mid-leaf, quality inspection record shows leaf completeness rate 95%." The drafted sentence under review reads, "Each portion of spinach in this batch has a net weight of no less than 480 g, with a leaf completeness rate of 95%." The comparison object is the drafted sentence against the source material, checking whether the weight floor and the completeness rate match the values in the original. The material does not state whether "no less than" covers every order in the batch, so that wording remains pending verification.

A relevance score is not a category, entity, or permission filter. Retrieval does not grant authorization. A similarity setting does not exclude unrelated businesses or unauthorized records, and no configuration on this page should be read as doing so.

## Configuration and implementation checks

| Configuration item | Hypothetical starting value for this exercise | Reason and comparison object |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | AI Proxy root address, no `/v1` appended | Compare against the official requirement that the value is the service root without a path suffix |
| `AIPROXY_API_TOKEN` | Non-empty token matching the server side | Compare against the startup validation requirement that the value is non-empty |
| Model capability check | Item-by-item against the inputs the copy task needs | Compare against the capability fields on the model configuration page |
| Application parameters | Temperature and response ceiling set in the application or node configuration | Compare against the actual fields present in the orchestration node |
| Probe interval | 30 minutes for this hypothetical exercise | Compare against the documented 5 to 60 minute integer range |

Each row is a check to perform, not a record of a completed test. The starting values are chosen for this exercise and carry no official status.

## Three common errors

1. Writing `AIPROXY_API_ENDPOINT` as a full model request address with `/v1` appended. Check whether the input is a root address, compare against the official description, and observe whether a path suffix is present.
2. Using an application API key in place of `AIPROXY_API_TOKEN`. Check the token source, compare against the server-side configuration, and observe whether the value is empty or mixed with `ADMIN_KEY`.
3. Treating "no less than 480 g" in the drafted sentence as a conclusion the material already supports. Check whether the source text states the coverage scope of that floor, compare the fields, and observe whether only a single-batch weight range is present.

## How to verify the setup

1. Input the source material and the drafted sentence from the hypothetical sample. Compare whether the 480 g weight floor and the 95% completeness rate appear in the original, and observe whether the drafted sentence only restates values from the source. When the original does not state coverage scope, record the item as pending verification.
2. Input the hypothetical `AIPROXY_API_ENDPOINT` value. Compare whether it ends as a root address with no `/v1`, and observe whether startup validation passes. That result requires an actual deployment to confirm; this page does not claim it was executed.
3. Input an empty reference list `[]`. Check whether the downstream design marks output with no references as unsupported, and observe whether unsupported promotional sentences appear. This check is a paper exercise and does not claim that retrieval necessarily returns an empty result.

The validation above tests the named primary task: whether specific drafted copy sentences are supported by the supplied source wording and its stated limits. It does not extend to identity certification, report analysis, or any other task.
