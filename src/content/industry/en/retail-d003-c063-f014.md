# Livestream after-sales service: model connections for copy drafting

## What the documents look like

Livestream after-sales work concentrates around the refund, reshipment and promise-explanation wave that follows a single selling session. The materials come from shop after-sales records, customer service IM, warehouse WMS and logistics tracking. The working documents are livestream order lists, refund applications, reshipment orders and script templates. Copy drafting for products and marketing draws on the promises and statuses recorded in those materials, and a draft sentence holds only when the material states the matching fact.

The copy output depends on a language model. Model connection and configuration decide which capabilities and parameter boundaries are available. This step sits apart from the after-sales documents themselves. The documents supply the facts; the model connection supplies the drafting ability.

## Constraints at the model connections step

AI Proxy is a required dependency. The App service and the Admin service must each set `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN`. Missing either one causes startup validation to fail. Older OpenAI environment variables and single-model custom request addresses do not replace these two settings.

The system needs at least one language model and one index model to work. A model ID is the value of the `model` field in the request body and is globally unique. A model name is for display and can be customized. A channel can carry a model mapping, so the requested model and the upstream model can differ. Model capabilities are checked separately against the input the application needs; multimodal input, tool calling and thinking settings are each verified on their own. Application parameters are set in the application or node configuration. Same-named fields on a compatible chat interface do not override orchestration.

The following hypothetical paper case is labelled as such and was not run.

Hypothetical exercise sample. A livestream after-sales team holds three source sentences: "Promise for this session: returnable within 7 days, shipping paid by us." "Order A status: signed for, refund application pending review." "Reshipment order B: created, not yet out of warehouse." The draft sentence to be judged is: "This product supports 7-day no-reason return, shipping fully free, refund available right after signing." The sentence touches the subject (this product against the session promise), the objects (order A, reshipment order B), the statuses (pending review, not yet out of warehouse) and the valid range (7 days). Each item is compared against the source text.

## Three common errors

1. Filling `AIPROXY_API_TOKEN` with an application API key. The input is the environment variable value. The comparison object is the AI Proxy server administrator token. The observable result is whether startup validation passes.
2. Using a model name as a model ID. The input is the `model` field in the request body. The comparison object is the model ID configured in the channel. The observable result is the model list and result returned by the channel test.
3. Deriving a completed refund or a shipped item from a pending-review or not-yet-out-of-warehouse status. The input is the status field in the source material. The comparison object is the status wording in the draft sentence. The observable result is whether both refer to the same subject and the same field with matching values.

## How to verify the setup

1. Input the three hypothetical source sentences and the draft sentence. Compare "7 days", "shipping fully free" and "refund available right after signing" in the draft against "returnable within 7 days", "shipping paid by us" and "refund application pending review" in the source. The observable result: the promise period and the shipping wording match, and the refund status wording does not match. Pending review is not a completed refund.
2. Input the draft subject "this product" and the source subject "promise for this session". Compare whether the two refer to the same object. The observable result: whether the subject correspondence is stated. When the material does not state it, record it as pending confirmation.
3. Input the status of reshipment order B, "created, not yet out of warehouse", and note that the draft sentence does not mention reshipment. Compare whether any shipping statement appears beyond the material. The observable result: the item passes when the draft adds no shipping promise, and is marked as unsupported when such wording appears.
