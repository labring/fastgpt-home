# Livestream sample inspections: interactive forms for copy drafting

## What the documents look like

In livestream product selection and sample quality inspection, the work sits before the broadcast. The question is whether a product can be sold and whether it suits on-camera demonstration. The documents that feed copy drafting are sample evaluation forms, quality inspection reports, supplier qualification files, and prohibited-item lists. Background data comes from supplier materials, testing-agency reports, platform negative catalogs, and historical return rates, refreshed weekly and per item.

For this page, only the interactive step matters. The form input node and the user selection node belong to the interactive node family in the official documentation. When triggered, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user finishes interacting. The form input node collects the required information the user fills in and passes it to later nodes. The user selection node evaluates the user's choice and runs the corresponding branch. Neither node is a business database, a supplier directory, or an approval engine. Field validation, approval, write-back, and batch operations require an external system or later nodes.

The practical consequence is narrow: these nodes gather values and route on a choice. Whether a drafted marketing sentence is supported by the underlying inspection material is a human comparison performed against the collected values, not a property of the node.

## Constraints at the interactive forms step

The interaction state is a pause with recorded workflow state, not a snapshot guarantee, not an automatic judgment, and not a submission-count control. The documentation describes the dialog hiding during interaction and the workflow continuing after completion. It does not describe switches for those behaviors, so none are assumed here.

A form collects values. It does not verify a supplier's qualification file, approve a sample, write to a database, or synchronize with an external platform. Those actions need their own downstream implementation. A pending request is not an approval. An offered option is not an execution.

Retrieval and relevance scoring do not act as permission or entity filters. A similarity setting does not exclude unrelated businesses or unauthorized records. Retrieval is not authorization. Where a knowledge reference limit applies, it uses the documented unit, not a guessed item count. Same-model retrieval association, empty-reference output, and context limits keep their documented conditions. Libraries built on different vector models cannot be jointly associated; the correct step is to check identifiers and exclude non-matching libraries rather than to run cross-model retrieval and compare results.

Hypothetical paper test case, clearly labelled as hypothetical and not drawn from any real record: Supplier A submits a sample evaluation form for a batch of insulated bottles. The material text supplied for comparison reads: "Sample number B-0715; submission date 10 July 2025; test item: thermal insulation performance; report conclusion: pass; supplier qualification document valid until 31 December 2025." The draft sentence under review reads: "This product's thermal insulation performance has been tested and passed, so it is safe to buy." The comparison object is the same subject, the same period, and the same field. The report covers thermal insulation performance only. It does not cover material safety or the compliance of marketing wording. The draft sentence therefore contains content the report does not support. No approval, deployment, or business action is claimed.

## Configuration and implementation checks

| Configuration item | Type | What this page checks |
| --- | --- | --- |
| Form input node | Documented | Enters interaction state, collects required information, passes it to later nodes |
| User selection node | Documented | Enters interaction state, runs the branch matching the user's choice |
| Required field list | Implementation check | Sample number, submission date, test item, report conclusion, qualification validity |
| Draft sentence versus material | Implementation check | Compare each marketing sentence against the report's coverage |
| Interaction wait and state record | Documented | Node records workflow state and continues after interaction completes |
| Downstream division of labour | Implementation check | Approval, write-back, and batch operations handled by external system or later nodes |

## Three common errors

1. Extending a report conclusion of "thermal insulation performance: pass" into a claim that the whole marketing sentence is compliant. Input: the report text and the draft sentence. Comparison: the field coverage of each. Observable result: the draft sentence asserts content the report does not address.
2. Treating the user selection node as a supplier qualification directory. Input: the node's branch configuration and the qualification file. Comparison: the node's documented function against where business data lives. Observable result: the node cannot hold qualification records.
3. Treating a recorded interaction state as a completed approval. Input: the node state and the approval action. Comparison: the definitions of the two. Observable result: interaction completion is not business approval.

## How to verify the setup

1. Input the hypothetical material text and the draft sentence given above. Compare the report's covered fields against the wording of the draft sentence. If the draft sentence contains promotional content the report does not cover, record it as unsupported. Do not supply authorization or effective clauses to reach a definite answer.
2. Input the required field list and check whether all five items are present: sample number, submission date, test item, report conclusion, qualification validity. If an item is missing, record the gap as a gap. Do not infer a missing value.
3. Input the user selection node's branch configuration. Compare the selection result against the branch taken. If the selection does not trigger the matching branch, record what was observed. Do not claim automatic judgment or snapshot guarantees.

Across all three checks, the standard is the same subject, the same period, and the same field. Contradiction applies only when one field has clearly mutually exclusive values. Where a field is unstated, or only related-stage evidence exists, the result is unsupported or pending verification, not a denial and not a conflict. A pending review does not show a lack of operating permission. Signing, reaching cooperation, and contract effectiveness are three distinct facts. A quotation validity period does not indicate a supply period. Where the material needed for verification is absent from an accessible target scope or from a clearly identified manual input, record the gap and leave it open.
