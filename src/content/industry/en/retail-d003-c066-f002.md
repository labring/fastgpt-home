# Short-video affiliate sales: context limits for copy drafting

## What the documents look like
Short-video affiliate sales distribute products through persistent content exposure and product-link conversion. Real-time explanation is not the primary mechanism. Four document types recur in drafting: short-video scripts, the product list attached to the cart, commission plans, and violation feedback. A promotional sentence in a script must align with verifiable facts in the product list. The commission plan determines which products may be attached to the cart. Violation feedback may require rewriting a specific expression. These materials update daily or weekly, so drafting that draws context from versions of different dates will base its judgment on shifting evidence.

## Constraints at the context limits step
The length of content available to a drafting node is bounded by the maximum context of the selected model. The reply limit constrains output only and does not serve as the full context window. Knowledge-base references are bounded by a token-based reference limit; when a single passage is long, referenced content is trimmed and script source text may be missing. A large memory-round setting pulls in earlier conversation; a small one cannot use earlier product information. When json_schema is used to fix the reply format, field completeness and successful parsing require separate checks, and text length cannot substitute for structural validation.

Hypothetical paper exercise sample: Material text A reads, "Attached product list, row 12: product name is Portable Folding Water Bottle, status is on sale, commission plan is Plan A, applicable period is 1 March 2025 to 31 March 2025." Material text B reads, "Violation feedback, item 4: the script for this product must not contain absolute efficacy claims." The draft sentence to be judged is, "This water bottle is suitable for daily commuting." The review request is, "Based on the two material passages above, judge whether this draft sentence may be written into the script."

## Configuration and implementation checks
| Configuration item | Hypothetical starting point for this exercise | Reason and comparison object |
| --- | --- | --- |
| AI model | Select a model shown in the configuration dialog as supporting the required capabilities | Compare against material length and format requirements; this is not a default recommendation |
| Memory rounds | Retain a small number of rounds | Compare against an empty-history input containing only this sample; observe whether unrelated products are introduced |
| Reply limit | Set to a length that can fully output the judgment and its basis | Compare against a truncated output that omits the basis |
| Reply format | Choose json_schema when fixed fields are required | Compare against plain-text output for field completeness |
| Reference limit | Cover both material passages by token | Compare against a result trimmed so that feedback item 4 is absent |
| Minimum relevance | Takes effect only under semantic retrieval or reranking | Compare against recalled content when it is not enabled |

## Three common errors
1. Treating the reply limit as the full context window. Input is a long script plus two material passages; the comparison object is the model maximum context; the observable result is whether the script source text is truncated.
2. Estimating the reference limit by item count. Input is two material passages; the comparison object is token measurement; the observable result is whether violation feedback item 4 remains in the referenced content.
3. Substituting text length for json_schema validation. Input is a fixed-format output; the comparison object is the field list; the observable result is whether the judgment field and the basis field are both present.

## How to verify the setup
1. Input the material passages and the draft sentence above. Compare whether the draft sentence contains an absolute efficacy claim. The condition is met when the sentence does not contain such a claim; when it does, the sentence requires rewriting.
2. Input the same question under empty history and under a small amount of history. Compare whether the referenced content is identical in the two runs. The condition is met when the content is identical, indicating that history did not introduce unrelated products.
3. Input the fixed-format request. Compare the returned fields against the json_schema definition. The condition is met when fields are complete and parsing succeeds; when fields are missing, record the gap.

Retrieval checks record only actual observations. A first-position hit, full recall, and an empty result for an unrelated query are not guaranteed. Libraries using different vector models cannot be jointly associated; verify identifiers first and exclude those that do not match. For empty-result handoff, a clearly labelled paper input of `[]` may be used to check downstream design. A pending review does not demonstrate the absence of operating permission. A quotation validity period does not indicate a supply period. When evidence is missing, the gap remains.
