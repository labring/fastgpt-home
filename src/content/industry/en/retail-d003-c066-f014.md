# Short-video affiliate sales: model connections for copy drafting

## What the documents look like

Short-video affiliate distribution depends on long-running content exposure that drives product-link conversion, so the working material is not built around live explanation. The documents this page concerns are short-video scripts, cart product lists, commission plans, and violation feedback. Product information from the selected alliance, playback data, transaction data, and platform rules feed into those documents. Content operations staff, creator business development staff, and product distribution specialists handle them, and the update rhythm is daily or weekly.

For copy drafting, the practical requirement is that selling points recorded in a cart product list, promotion conditions recorded in a commission plan, and a script draft line up sentence by sentence. Model connection and configuration determine whether those materials can be called on reliably during drafting. A drafting tool that cannot reach a configured language model or index model cannot consume the same source material consistently, and a mismatch between a drafted claim and the underlying list or plan becomes a promotion failure, wasted commission, or a removed video.

## Constraints at the model connections step

Model access runs through AI Proxy. The App service and any Admin service that reuses App/Service configuration must set `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN`; missing either one causes startup validation to fail. `AIPROXY_API_ENDPOINT` holds the service root address and does not carry `/v1`. The system needs at least one language model and one index model before it works normally. Model capabilities are checked against the input the application actually needs, and multimodal support, tool calling, and reasoning settings are verified separately. Application parameters are set in the application or node configuration; the same-named fields of a compatible chat interface cannot be assumed to override orchestration.

A hypothetical paper exercise sample is used below. It is a constructed case, not a real record, and no test has been run against it. The source material reads: "The cart product for this session is a summer ice-silk sun-protection sleeve, commission rate 15%, campaign period June 1 to June 30." "Product list note: this product does not support seven-day no-reason return." "Violation feedback record: the title must not contain 'lowest price across all channels'." The draft sentence to be judged is: "This sun-protection sleeve carries 15% commission, the lowest price across all channels, and supports seven-day no-reason return." The comparison subject is the same product, the same campaign period, and the same field.

## Configuration and implementation checks

| Configuration item | Hypothetical starting value for this exercise | Check method |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | The AI Proxy service root address | Confirm no `/v1` is appended and the value matches the deployment address |
| `AIPROXY_API_TOKEN` | A non-empty administrator token | Compare against the server-side configuration and confirm it is non-empty |
| Language model | One language model enabled | Confirm it shows as enabled in the system model list |
| Index model | One index model enabled | Confirm it shows as enabled in the system model list |
| Model capability | Selected according to the input copy drafting needs | Verify multimodal support and tool calling separately |
| Application parameters | Set in the application or node configuration | Confirm the parameters take effect inside the orchestration |

The starting values above are chosen for this paper exercise only and are compared against the deployment's own configuration; they are not official defaults.

## Three common errors

1. Writing `AIPROXY_API_ENDPOINT` as a full request address that includes `/v1`. The check is to inspect the input value, compare it against the service root address described for the deployment, and confirm no extra path segment is present.
2. Using an application API key in place of `AIPROXY_API_TOKEN`. The check is to inspect where the token value comes from, compare it against the server-side administrator token, and confirm the two agree and the value is non-empty.
3. Treating "lowest price across all channels" in the draft sentence as supported by the material. The check is to inspect whether the source text contains that phrase, compare the product list and the violation feedback record, and confirm no corresponding supporting sentence exists.

## How to verify the setup

1. Input the hypothetical sample source text and the draft sentence, then compare "15% commission" against the commission plan field. The condition is met when the numeric value agrees; a mismatch means the claim is not supported.
2. Input "supports seven-day no-reason return" and compare it against the product list note "does not support seven-day no-reason return." The condition is met when the same field holds mutually exclusive values, which makes the two statements contradictory.
3. Input "lowest price across all channels" and compare it against the violation feedback record and the product list. The condition is met when the material does not state that phrase, in which case it is recorded as unsupported, and the missing evidence stays missing.
