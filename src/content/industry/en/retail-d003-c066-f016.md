# Short-video affiliate sales: interactive forms for copy drafting

## What the documents look like

Short-video affiliate sales rely on long-term content exposure and product-link conversion rather than live explanation. The practitioners handling this work are content operators, creator business-development staff, and product distribution specialists. Their daily or weekly documents include short-video scripts, attached-product lists, commission plans, and violation feedback. Matching videos to products, setting commission rates, and checking title violations consume the most time. Errors in these areas can make promotion ineffective, waste commission, or cause a video to be taken down.

For the copy-drafting task on this page, the form input node collects the values a user fills in and passes them to later nodes after submission. It does not provide its own business database function. The user selection node executes a branch according to the user's choice. When either node is triggered, the conversation enters an interactive state, the workflow state is recorded, and execution continues only after the user completes the interaction. Field validation, business approval, write-back, and batch operations require separate implementation in an external system or in later nodes.

## Constraints at the interactive forms step

Copy drafting needs checkable source material. A form collects filled-in values, while business verification connects to a separate system. The interactive nodes wait for a submission or a selection; they do not supply a submission-count limit, automatic judgment, or snapshot guarantee. User selection is a branch decision, and it does not constitute a personnel directory or a business-data selector.

Hypothetical paper exercise: the source material reads, "The commission plan for attached product A in this campaign takes effect on March 1, 2025, and remains valid through March 31, 2025; the short-video title for this product must contain the category term." The proposed copy sentence reads, "The commission plan for product A is valid long term, and the title may omit the category term." The check requires the same subject, the same period, and the same field. The material states that validity ends on March 31, 2025, while the proposed sentence calls the plan valid long term; the two conflict on the validity-period field. The material requires the category term in the title, while the proposed sentence says the term may be omitted; the two conflict on the title-requirement field. This exercise is a paper construct and does not involve a real customer or a real identifier.

## Configuration and implementation checks

| Configuration item | Type | What this page checks |
| --- | --- | --- |
| Form input node | Documented official behavior | Enters the interactive state when triggered and passes collected values to later nodes |
| User selection node | Documented official behavior | Executes the corresponding branch according to the user's choice |
| Required-field check | Implementation check | Lists the information this task cannot omit and tests the behavior with a missing item and after it is supplied |
| Field validation | Requires separate implementation | Performed by an external system or a later node |
| Business approval and write-back | Requires separate implementation | Not completed automatically inside the interactive nodes |
| Hypothetical starting value | Starting point for this paper exercise | Uses March 31, 2025, as stated in the material as the validity comparison basis, chosen because the material gives that date, and compares it with the proposed sentence "valid long term" |

## Three common errors

1. Treating a form submission as completed business approval. The input is the hypothetical proposed sentence and the source material; the comparison is between the submission action and the approval state; the submission remains pending verification.
2. Treating a user-selection branch as a permission filter. The input is one selection record; the comparison is between the branch taken and the authorization scope; executing the branch does not produce an authorization conclusion.
3. Treating the recorded interactive state as a snapshot guarantee. The input is one interaction trigger; the comparison is between the state record and data retention; recording the workflow state does not promise a snapshot.

## How to verify the setup

1. Enter the hypothetical source material and the proposed sentence, then compare the validity-period field. When the proposed sentence "valid long term" does not match the date range stated in the material, the proposed wording is unsupported.
2. Enter the hypothetical source material and the proposed sentence, then compare the title-requirement field. When the proposed sentence "may omit the category term" does not match the material's requirement, the proposed wording is unsupported.
3. Enter a form submission that omits a required item, then compare the flow before and after submission. With the item missing, the interactive state waits for it to be supplied; after it is supplied, execution continues to later nodes.

These checks state expected observations for the paper exercise. They do not report a completed test, an approval, or a deployment.
