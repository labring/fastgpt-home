# Group-buy leader operations: workflow routing for copy drafting

## What the documents look like

Group-buy leader operations revolve around community nodes and commission, and this category does not directly carry out cold-chain quality inspection. The daily documents are leader agreements, commission tables, pickup lists and community announcements. Data sources are the community group-buy backend, leader community groups, order details and after-sales records, with an update rhythm of daily or per group.

For the task of drafting product and marketing copy, the material actually consumed is the authorization scope in the agreement, the settlement basis in the commission table, the arrival status in the pickup list and the existing wording in community announcements. Whether a promotional sentence in a draft can stand depends on whether these materials record the corresponding subject, object, status and effective scope. It does not depend on how strong or weak the wording of the draft itself is.

A practical consequence is that a workflow built for this page routes material collection, draft assessment and human review in order. The copy task sits downstream of documents that were written for other purposes, so the routing step has to keep the exact source fragment attached to each draft sentence under review.

## Constraints at the workflow routing step

Workflow routing here strings together material collection, draft assessment and human review as ordered steps. The form input node is a user interaction node. When it is triggered, the conversation enters an interaction state, the workflow state is recorded, and the flow waits until the user completes the interaction before continuing. The node collects the required information the user fills in and passes it to later nodes after submission. The user selection node is also a user interaction node. It records workflow state, waits for completion, and when the user makes a choice the node evaluates that choice and executes the "yes" branch. Both nodes can be added repeatedly and are trigger-execution nodes.

Retrieval in this workflow only recalls relevant passages by semantics. A relevance score does not constitute a subject, object or permission filter, and retrieval itself does not constitute authorization. Order writes, document backfill and external status synchronization require a separate business interface or a later process. This page does not assume scheduled triggers or hidden controls exist.

Hypothetical drill sample: the source material text is "Party A of this agreement is a community group-buy platform, Party B is leader Zhang, the effective scope of the agreement is 1 March 2025 to 31 August 2025, and Party B may use the product images and price information provided by the platform within the authorized scope for promotion in this community." The draft sentence to be assessed is "This community supplies fresh produce shipped directly from the place of origin year-round, at the lowest price in the whole city." The fields needed for assessment are the scope of promotional wording and the basis for the price comparison. The material does not record authorization or a basis corresponding to "year-round", "shipped directly from the place of origin" or "lowest price in the whole city".

## Configuration and implementation checks

| Configuration item | Type | Use on this page |
| --- | --- | --- |
| Form input node | Interaction node | Collect the draft sentence, material fragment and assessment fields; pass them to later nodes after submission |
| User selection node | Interaction node | Make a yes/no choice on whether the material records the promotional point; verify the yes branch connection |
| Interaction state check | Manual review | Confirm the interaction node recorded state and is waiting for completion; no separate global state switch is set |
| Output handoff check | Manual review | Compare each collected field against the input of the later retrieval and assessment nodes |
| Retrieval scope check | Manual review | Confirm the retrieval library and the query use the same vector model identifier; exclude those that do not match |
| External action split | Implementation check | Order writes, document backfill and external synchronization connect to a separate business interface and are not implemented here |

The hypothetical starting point for this trial is: place the draft sentence and the source material text into the form together, and set the selection branch to "material does not record it". The reason for choosing this starting point is that the source material text gives only the subject, the effective scope and authorization to use images and prices; it gives no authorization for promotional wording. The comparison method is to check the source material text against the draft sentence field by field and observe whether unrecorded fields are marked as pending verification.

## Three common errors

1. Treating a retrieval relevance score as an authorization filter. The input is a draft-sentence query; the comparison object is the returned passage against the source material text. If a high-relevance passage is taken directly as usable grounds, the fact that retrieval does not perform permission judgment is ignored.
2. Treating the interaction node's state record as a guarantee of submission count or snapshots. The input is one form submission; the comparison object is the node documentation against the implementation record. Claiming an automatic retry or snapshot mechanism goes beyond what the documentation states.
3. Judging an unrecorded field as a contradiction or a negation. The input is the source material text and the draft sentence; the comparison object is the value of the same field for the same subject over the same period. When the material has only related-stage evidence or records nothing at all, the result is recorded as unsupported or pending verification.

## How to verify the setup

1. Input the source material text and the draft sentence from the hypothetical sample. Compare whether the three expressions "year-round", "shipped directly from the place of origin" and "lowest price in the whole city" have corresponding fields in the source material text. The condition is met when the observed result is that all three expressions are marked as unsupported.
2. Input the same source material text and a draft sentence that uses only images and prices within the authorized scope. Compare whether that sentence falls inside "use the product images and price information provided by the platform within the authorized scope for promotion in this community". The condition is met when the observed result is that the sentence is marked as supported by the material.
3. Input an explicit empty reference []. Compare whether the downstream node handles it along the empty-result branch. The condition is met when the observed result is that the downstream node does not execute the retrieval or assessment step and records the gap. Do not claim that a fictional rule retrieval necessarily returns [].

These checks compare the collected fields, the source material text and the draft sentence against each other. No test, deployment or approval is claimed to have occurred.
