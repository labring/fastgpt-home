# Group-buy leader operations: interactive forms for copy drafting

## What the documents look like

Group-buy leader operations centre on community nodes and commission, and they do not directly carry out cold-chain quality inspection for fresh produce. The working documents in this category are leader agreements, commission tables, pickup lists and community announcements. Data arrives from the group-buy backend, leader community groups, order details and after-sales records.

For this page the relevant split is between two kinds of material. Leader agreements and commission tables carry rules that have already been stated. Pickup lists and community announcements carry confirmed arrival, specification and timing information. Copy drafting compares a proposed sentence against those confirmed materials line by line.

The form input node handles one half of that work. When it is triggered, the conversation enters an interactive state, the workflow state is recorded, and execution waits. After the user completes the required information and submits, the node collects what was filled in and passes it to later nodes. The node does not include a business database function of its own. The user selection node is also a user interaction node: when triggered, the conversation enters the interactive state, the workflow state is recorded, and execution waits; when the user makes a choice, the node evaluates that choice and runs the "yes" branch. Its basic use is to pose a question that requires a decision and then route the workflow according to the response. It is not a personnel directory and not a business data selector.

Field validation, business approval, write-back and batch operations belong to external systems or later nodes as needed. Update frequency does not change how the form and interaction are configured.

## Constraints at the interactive forms step

Drafting product and marketing copy requires comparing a pending sentence against confirmed materials sentence by sentence. A form collects values; it does not complete business verification. The fields should therefore cover the draft sentence, the source of the corresponding material, the status of that material and the intended publication scope. The comparison itself is carried out by a person or by an external node.

Hypothetical paper exercise sample. Material text one: the leader agreement states that "commission for this group is settled at eight percent of the actual completed order amount, and refunded orders are not counted." Material text two: the pickup list states "arrival on 12 March 2025, specification five jin per box, forty boxes in total." Draft sentence: "All products in this group carry eight percent commission, refunds are settled as usual, forty boxes arrive on 12 March, first come first served." Handover request: "Please confirm whether this draft sentence can be published directly."

Points for judgement: the commission rate and the refund treatment must be compared under the same subject, the same period and the same field; the arrival quantity and specification must match the pickup list; "first come first served" has no corresponding statement in the materials, so it is unsupported, and the absence of a statement in the materials does not make it a denial or a conflict. Pending review does not demonstrate a lack of operating permission. Signing, reaching cooperation and contract effectiveness are three separate facts.

## Configuration and implementation checks

| Configuration item | Type and role | Check method on this page |
| --- | --- | --- |
| Form input node | User interaction node; collects filled information and passes it to later nodes | Confirm the fields include the draft sentence, material source and material status |
| User selection node | User interaction node; runs a branch according to the choice | Use only for decisions such as "continue editing / submit for checking" |
| Interactive state | After triggering, records workflow state and waits for interaction | Confirm that execution continues downward after submission |
| Required information check | Lists the information this task cannot omit | Test the missing-field case and the completed case separately |
| Downstream division of labour | Field validation, approval and write-back implemented externally as needed | The form does not carry business verification or database writes |

Hypothetical starting point for this exercise: set "material source" as required, on the reasoning that the draft sentence must correspond to the materials line by line; compare this with the submission behaviour after that field is completed, and observe whether execution proceeds to the next node. This starting point is a hypothetical setting for this exercise and is not an official default value.

## Three common errors

1. Treating form collection as business verification. The input is a completed draft sentence; if it is treated as publishable directly, that exceeds the role of the form input node. Compare whether a separate checking node or a human confirmation exists.
2. Treating user selection as a data selector. The input is "continue editing / submit for checking"; if it is treated as a leader directory or an order selector, that conflicts with the documented description. Compare whether the branch design handles only the decision.
3. Treating absence from the materials as a denial. The input is "first come first served," which has no corresponding statement in the materials; if it is judged a conflict or a denial, there is no basis in mutually exclusive values in the same field. Record it as unsupported or pending verification.

## How to verify the setup

1. Enter the draft sentence and the two material texts from the hypothetical sample, and compare whether the commission rate and the refund treatment share the same subject, the same period and the same field. Record a contradiction only where mutually exclusive values appear in the same field; otherwise record unsupported or pending verification.
2. Enter a submission with "material source" missing and a submission with it completed, and compare whether both enter the interactive state and continue downward. Observe whether the filled information is passed on after submission, without claiming that this has been tested.
3. Enter the handover request "Please confirm whether this draft sentence can be published directly," and compare whether the form only completes collection and passing on, and whether business verification and publication approval are carried by an external system or a later node. Missing evidence stays missing; pending review is not approval.

On retrieval and association, libraries using different vector models cannot be associated together; check the identifiers first and exclude those that do not match, rather than running a cross-model retrieval to compare missed recall. An empty result can be handled by checking the downstream design against an explicit paper input, without claiming that a fictional rule retrieval necessarily returns an empty array. Image retrieval requires a corresponding image input and model capability, and reranking requires the model and must be enabled according to the settings. Optional paths shown in the overall document flow diagram do not mean that every request executes all of them.
