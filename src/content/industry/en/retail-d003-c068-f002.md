# Group-buy presale orders: context limits for copy drafting

## What the documents look like

Group-buy presale collection takes orders first and organizes procurement and fulfillment afterward. Drafting product copy and marketing copy for this category draws on four working documents: the presale product table, the collection result, the procurement plan, and the cut-off notice. The product table carries item name, specification, place of origin, arrival batch, and cut-off time. The collection result carries ordered quantity and pickup-point distribution. The procurement plan carries available quantity and arrival date. The cut-off notice carries the deadline communicated to group leaders and users. These materials update daily or per collection round, and within one round the available quantity and cut-off time cited in copy must match those documents.

The drafting context has two parts: the material fragments the draft needs to cite, and the historical input carried by the conversation or node. Any quantity, time point, specification, or place of origin appearing in copy must map to a field in the materials. Selling points, commitments, or time promises absent from the materials remain unsupported content.

## Constraints at the context limits step

Context and token limits constrain three things in this task: the content length a single model request can reference, the reply length cap, and the knowledge-base reference cap measured in tokens. Maximum context is the content length a single request can reference; the reply cap only controls single-answer length. The two cannot substitute for each other. The reference cap controls the maximum tokens cited per search, so when a single material passage is long, the draft may receive only a fragment, and the cited fragment must be checked for coverage of specification, quantity, and time fields.

Memory turns control how many prior turns are referenced. The same question under empty history and under history presents different visible content to the model, and draft wording may shift accordingly. In structured hand-off scenarios, a fixed reply format requires complete and parseable fields; checking text length alone cannot confirm field completeness.

Hypothetical drill sample: the source material reads, "This round's presale item is Gannan navel orange, specification 5-jin pack, cut-off time March 12 at 20:00, procurement plan arrival date March 14, available quantity 800 boxes." The sentence to be judged reads, "This round's navel orange cuts off March 12 at 20:00, arrives March 14, limited to 800 boxes." The comparison object is the specification, cut-off time, arrival date, and available quantity fields for the same round and the same item.

## Three common errors

1. Treating the reply cap as the full context window. The reply cap limits only single-answer length, while maximum context is the content length a request can reference. Check: input the sample material plus historical input, compare visible model content against the reply length setting, and observe whether the draft loses the arrival date field because the reply cap truncates it.
2. Setting the reference cap too low, so a material passage is trimmed. Check: input the navel orange source material, compare the reference cap against the single-passage token amount, and observe whether the returned reference lacks the available quantity or cut-off time field.
3. Treating similarity or relevance as a permission or entity filter. Minimum relevance only filters low-relevance results; it does not perform business isolation. Check: input materials from different rounds in the same library, compare the round identifier in returned results, observe whether fragments from another round appear, and record the actual observation.

## How to verify the setup

1. Use the hypothetical sample material and the draft sentence to check field consistency. The input is the source material above and the draft sentence; compare the four items of specification, cut-off time, arrival date, and available quantity. The condition is met when all four correspond and no mutually exclusive values appear. Selling points absent from the materials remain unsupported.
2. Use empty history and history-bearing input to check context differences. The input is the same drafting request under two history states; compare the visible model input and observe whether draft wording changes trace to historical content. When the source of a difference is unclear, record it as pending verification.
3. Use a fixed reply format to check field completeness. The input is a drafting request that requires a json_schema return; compare the returned structure against the preset fields. The condition is met when all fields are present and parsing succeeds. When parsing fails or a field is missing, record the gap without inferring a failure cause.

Libraries built on different vector models cannot be jointly associated; first check the library identifier and exclude those that do not conform, and do not run cross-model retrieval to compare missed recalls. Rerank requires a model and must be enabled per settings; image retrieval requires corresponding image input and model capability. Empty-result hand-off can use an explicit paper input of an empty array to check downstream design, without claiming that a fictional rule search necessarily returns an empty result.
