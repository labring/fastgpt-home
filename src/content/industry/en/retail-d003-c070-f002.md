# Cross-border product labels: context limits for copy drafting

## What the documents look like

Product compliance work happens before listing and before import, and its core is product safety and label evidence. Copy drafting for this category draws on platform policy centers, testing laboratory reports, destination-country regulation libraries, and supplier materials. Four document types recur: product test reports, English labels, MSDS files, and platform prohibited-item lists. These materials update irregularly, and each new product launch can introduce a new material version.

The input to drafting is the specific wording cited from those materials, together with the promotional sentence that must be judged as supported or unsupported. A material may cover only one model, one batch, or one destination country. When a draft sentence extends beyond the scope the material states, the sentence becomes one that cannot be checked against anything. The context and token step addresses whether the material excerpt a draft relies on can enter the model input in full, and whether the judgment still holds after that input is trimmed.

Test reports and regulation clauses commonly carry four kinds of information: the subject, the object, the status, and the effective scope. Losing any one of them through truncation can change the conclusion. The knowledge base reference limit is controlled in tokens, so a long single excerpt may be trimmed before it reaches the model, leaving the basis for a draft sentence incomplete. The reply limit constrains model output length only; it is a different quantity from the full context window the model can reference. Memory turns determine whether earlier conversation is carried in, so the same question can reference different content under empty history and under history-bearing input. When a fixed reply format is used, field completeness needs a separate check, because acceptable text length does not mean the structure is parseable. Semantic recall and relevance scores reflect content similarity alone; they do not perform permission isolation or entity-scope filtering.

## Constraints at the context limits step

The reference limit is measured in tokens per search. When a material excerpt is long, the content entering the model may be trimmed, and the basis for judging a draft sentence becomes incomplete. Comparing an excerpt's full length against the configured reference limit shows whether all four information types survive.

The reply limit and the model context window are separate. Raising the reply limit does not admit more source material, and lowering it does not protect source material from trimming. A drafting task that must show both the basis and the handling action needs enough output room for both, which is a different question from how much material the model can read.

Memory turns change the input. Running the same question with empty history and with two turns of history can surface different referenced material, and the difference must be recorded rather than assumed away.

Structured output requires its own verification. Selecting `json_schema` means the returned fields must be present and parseable. A response that reads well but omits a required field fails the structural check even when its length is acceptable.

Relevance thresholds filter low-scoring results and apply only under semantic retrieval or when reranking is used. A relevance score is not a category, entity, or permission filter. A high-scoring excerpt is not thereby authorized for use, and a similarity setting does not exclude unrelated businesses or unauthorized records. Retrieval is not authorization.

Thinking strength settings affect the thinking budget only. They have no relationship to the reference token limit and cannot be used to control material trimming.

## Three common errors

1. Treating the reply limit as the full context window. The reply limit constrains output length, while the material length the model can reference is determined by model capability together with the knowledge base reference limit. The observable failure is that a draft sentence is judged supported after the excerpt was trimmed. The check compares the four information types in the source text against what entered the model and confirms nothing was cut.

2. Using a semantic relevance score in place of a scope check. Relevance reflects content similarity and does not determine whether the material covers the same subject, the same destination country, or the same batch. The observable failure is that a high-scoring excerpt is used as the basis for a draft sentence while the model or destination country it states differs from the sentence. The check compares subject, object, status, and effective scope item by item.

3. Treating material under review as an effective basis. Pending review, submitted, and signed are distinct statuses. When material is pending review, a draft sentence cannot be judged against it as if it were in effect. The observable failure is citing a test report that has not completed review and concluding the draft sentence is supported. The check records the material status and, where effective evidence is absent, keeps the item as pending verification.

## How to verify the setup

Hypothetical paper exercise sample. A supplier provides an English label draft. The source text reads: "This product is suitable for household use of Model A. The label content was prepared according to the destination country's label requirements in effect in 2024." One draft sentence to be judged reads: "This product is suitable for household use of Model A and Model B." In this sample the material subject is Model A, while the draft sentence subject is Model A and Model B; the two scopes do not match.

- Verification one: check the subject scope. Input the source text and the draft sentence, and compare the model stated in the material against the models listed in the draft sentence. The material states Model A only; the draft sentence lists Model A and Model B. The result is that the draft sentence exceeds the material scope and is unsupported. If the source text also stated Model B, this item would be satisfied.

- Verification two: check completeness under the reference limit. Input the source text and the hypothetical reference limit of 3000 tokens, and compare whether the content entering the model includes all four items: the model, the use scenario, the basis year, and the destination country. When all four are present, the basis is complete. When any one is missing, record the input as trimmed and hold the judgment.

- Verification three: check empty-result handling. Input a clearly labelled paper empty result `[]` and compare how the downstream node behaves on receiving it. If the downstream node returns a pending-verification notice as designed, handling is normal. If the downstream node continues along the result-bearing path and generates a draft sentence, record the handling as abnormal. This check does not claim that a fictional rule lookup will return an empty result.

All three verifications address this page's primary task: whether a draft sentence is supported by the material. Parts the material does not state remain missing. Pending review is not treated as effective. Retrieval behavior is not treated as authorization.
