# Cross-border settlements: interactive forms for copy drafting

## What the documents look like

Cross-border platform settlement and foreign exchange covers the collection of funds from orders that have already been completed. It does not handle fraud chargebacks. That boundary shapes which materials may be cited when drafting product and marketing copy, because the copy must stay inside the settlement evidence that actually exists.

The main data sources are the platform settlement center, bank statements, payment institution back office, and ERP orders. The documents handled day to day are platform settlement statements, exchange rate tables, service fee invoices, and collection reconciliation tables. The typical roles involved are cross-border seller finance staff, tax accountants, and platform operations staff. Errors in this work affect profit calculation, tax filing, and cash availability.

The update rhythm of these documents is weekly or monthly. That rhythm affects the date labels attached to figures quoted in copy, and it has no direct bearing on the interactive form itself.

## Constraints at the interactive forms step

The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. The node collects the information the user fills in and passes it to later nodes. It does not carry a business database function of its own.

The User Selection node is also a user interaction node. It triggers the same interaction state and, once the user makes a choice, evaluates that choice and runs the corresponding branch. It does not act as a staff directory or a business data selector. Field validation, business approval, write-back, and batch operations need to be implemented in an external system or in later nodes.

Hypothetical paper exercise sample. The source material reads: "Platform settlement statement, March 2025, store A, settlement amount USD 12,000, deduction items include commission USD 600; the exchange rate table states that the USD to CNY central parity rate on 1 March 2025 was 7.10; the service fee invoice was issued on 2 April 2025 for CNY 300." The draft sentence under review reads: "This month's settlement carries zero fees, and the exchange rate is locked at 7.10 throughout." That sentence touches two facts. The material states a commission of USD 600 and a single-day rate. It does not state zero fees, and it does not state the scope over which the rate is locked.

## Configuration and implementation checks

| Configuration item | Setting or check relevant to this page | Relation to the sample |
| --- | --- | --- |
| Form Input node | Collect settlement statement number, store identifier, settlement period | Corresponds to March 2025 and store A in the sample |
| Required field check | List settlement amount, deduction items, rate date | When an item is missing, the interaction state does not complete and later nodes do not run |
| User Selection node | Run a branch based on the choice, deciding whether the copy may be submitted | Two paths: material sufficient, material insufficient |
| Interaction state | Record workflow state on trigger and wait | The dialog is hidden before submission and execution continues after submission |
| Downstream division of work | Field validation, approval, and write-back are implemented by an external system | The node does not write to a database and does not perform approval |
| Hypothetical trial starting value | Set the deduction item threshold at USD 0 as the comparison starting point for this exercise | Chosen to test the zero-fee wording; compared against the USD 600 in the sample |

## Three common errors

1. Treating the information collected by the node as a business database held by the node. The Form Input node only passes on the filled-in information. Write-back and approval require an external system. The settlement statement number and store identifier in the sample do not land in a database automatically.

2. Treating the User Selection node as a business data selector. The node runs a branch according to the choice made. In the sample, the material sufficient branch does not mean the material has passed business verification.

3. Treating the zero-fee wording in the draft sentence as a verified fact. The material states only a commission of USD 600. It does not state zero fees. That wording is unsupported.

## How to verify the setup

1. Input the source material text and the draft sentence, then compare the fee wording in the draft against the deduction items in the material. The material states a commission of USD 600; the draft sentence claims zero fees. The two are mutually exclusive values on the same field, so the wording is judged unsupported and the material is returned for completion.

2. Input the rate table date from the sample and the rate scope claimed in the draft sentence, then compare the applicable period of the rate. The material states only the central parity rate of 7.10 on 1 March 2025. The draft sentence claims a lock throughout, and the applicable period is not stated, so the claim is judged pending verification.

3. Use an empty paper input to check the downstream design, and observe whether a later node still requires submission when no retrieval result is present. If the interaction state has not completed, the form does not submit. If it does submit, record what was actually observed in that branch rather than inferring that a fictional rule must return an empty result.
