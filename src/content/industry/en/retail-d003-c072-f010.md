# Overseas stock replenishment: citation tracing for copy drafting

## What the documents look like
Cross-border overseas warehouse replenishment can serve several sales channels, and the seller allocates stock across them. The daily document line consists of replenishment plans, warehouse inbound appointments, inventory aging tables, and last-mile delivery notes. Data arrives from the overseas warehouse WMS, ERP sales forecasts, freight forwarder systems, and carrier bills, with weekly or daily update frequency. When drafting product and marketing copy, statements about replenishment lead time, aging status, or delivery scope must be traced back to those documents. Where the source is missing, the statement stays pending verification.

## Constraints at the citation tracing step
A knowledge base search node can associate one or more knowledge bases that share the same vector model. Its output is a citation array whose length may be zero; when nothing is retrieved, that output path still runs. The citation limit controls how many tokens are cited per search. The minimum relevance value applies only during semantic retrieval or result reranking and acts as a filter threshold. Hybrid retrieval merges multiple result paths through RRF, and ReRank performs a second ordering of candidate text. These mechanisms govern recall and ordering. Retrieval itself does not constitute authorization, and it does not confirm that a promotional statement is true.

Hypothetical paper exercise: an overseas warehouse operator plans to draft the product line "This batch of replenished goods can ship same-day from the German overseas warehouse." The source text supplied for checking reads: "The inbound appointment dated 10 June 2025 states that the batch is expected to arrive at the warehouse on 18 June, and outbound operations will be scheduled according to in-warehouse work queues after arrival." The draft line and the source disagree on the outbound timing point. The promotional line is not supported by the material and should be marked pending verification.

## Configuration and implementation checks
| Configuration or check item | Purpose on this page | Value and explanation |
| --- | --- | --- |
| Associated knowledge bases | Define the retrieval scope | Select only knowledge bases with the same vector model; verify the identifier first and exclude those that do not match |
| Citation limit | Control tokens cited per search | The starting value for this exercise is set at 2000 tokens, because individual documents in this batch are long; compare against 1000 tokens to observe recall completeness |
| Minimum relevance | Filter low-relevance results | Applies during semantic retrieval or reranking; it does not perform permission or entity isolation |
| Search mode | Choose the recall path | Use full-text or hybrid retrieval for codes and model numbers; use semantic retrieval for natural-language statements |
| Result reranking | Second ordering of candidates | Runs only when a rerank model is available and enabled in the settings |
| Citation handoff | Check answer against source text | Compare each answer sentence with the cited source line; treat an empty array as a zero-length citation for downstream checking |

## Three common errors
1. Treating a retrieval hit as proof that a promotional line is confirmed. Input the draft line above and the inbound appointment source text, compare the outbound timing field, and observe that the source does not state same-day shipping, so the line is unsupported.
2. Treating minimum relevance as a permission filter. Input cross-channel inventory records and retrieval parameters, compare the returned records against the access scope, and observe that the relevance score does not distinguish business ownership, so unauthorized records may still be recalled.
3. Treating an empty citation array as a workflow error. Input a paper citation output of [], compare the downstream node design, and observe that an empty array is a permitted length; whether the downstream continues requires separate checking.

## How to verify the setup
1. Input the draft line and the source text from the hypothetical exercise above, compare the outbound timing field with the arrival scheduling field, and mark the line pending verification when the two do not match. This condition is satisfied.
2. Input the identifiers of two knowledge bases that share the same vector model and one identifier from a different vector model, compare whether the identifiers match, exclude the non-matching one, and associate only the matching pair. This condition is satisfied.
3. Input a paper citation output of [], compare whether the downstream handoff design treats it as zero-length, and if the downstream still runs without error, the condition is satisfied. Actual returned content depends on observation; do not assume the result must be empty or must contain a hit.
