# Cross-border payment reviews: interactive forms for copy drafting

## What the documents look like

Cross-border independent-site payment risk control operates around card network disputes and receiving accounts. The material handled at this step is not parcel status alone; it includes chargeback notices, fraudulent order lists, invoices and proof of delivery. The supplied brief states a daily and per-order update frequency, and this page does not derive batch synchronization or transaction-triggered mechanisms from it.

Copy drafting for products and marketing therefore has to reconcile two document families at once. A promotional sentence about dispatch time, refund conditions or product specification often appears in parallel in an invoice, a delivery receipt and chargeback evidence. When the drafted sentence and those materials diverge, the dispute-stage evidence and the page promise form two separate versions of the same fact.

The form input and user selection nodes carry information collection and branch choice at this step. When triggered, the conversation enters an interactive state, the workflow state is recorded, and execution continues after the user completes the interaction. The form input node collects entered information and passes it to later nodes. It does not include a business database function of its own.

## Constraints at the interactive forms step

The object of verification in copy drafting is the correspondence between a specific proposed sentence and the source wording of the materials. The form input node can collect the sentence to be checked, the target market, the product identifier and the order period. The user selection node can execute a branch according to the user's choice. Field validation, business approval, write-back and batch operations need to be implemented in an external system or in later nodes.

Hypothetical paper exercise sample

Source wording one: "Store order number SO-2024-0871, product is a portable juicer cup, payment date 12 March 2024, invoice amount USD 39.90, carrier delivery date 19 March 2024."

Source wording two: "This order received a card network chargeback notice on 2 April 2024, the reason code field reads 'goods not received', and the proof of delivery submitted by the merchant shows a recipient address matching the order shipping address."

Source wording three: "The refund terms page states: a return may be requested within 14 days of delivery, and the refund is initiated within 5 business days after the returned goods are received."

Proposed sentence to be judged: "This product supports 30-day no-reason returns after delivery, and refunds arrive instantly."

Verification request: "Based on the three source sentences above, determine whether the proposed sentence is supported, and state the missing evidence items."

In this sample the subject is the same order and the same merchant, the period runs from 12 March 2024 to 2 April 2024, and the fields are the return window and the refund timing. The materials state 14 days and 5 business days; the proposed sentence states 30 days and instant arrival. The values for the same field are mutually exclusive. The materials do not state an instant-arrival mechanism, so that part remains unsupported.

## Configuration and implementation checks

| Configuration item | Value or check item on this page | Basis and boundary |
| --- | --- | --- |
| Form input node | Collect order number, product identifier, target market, proposed sentence to be checked | The node collects entered information and passes it to later nodes |
| Required fields | Order number, source wording, proposed sentence | When an item is missing the interactive state does not complete; it continues after the item is supplied |
| User selection node | Branches are "supported", "unsupported", "pending verification" | The node executes a branch according to the user's choice |
| Interactive state | After triggering, the workflow state is recorded and the flow waits | Execution continues after the interaction completes |
| Field validation and write-back | Implemented by an external system or later nodes | The node does not include a business database function |
| Verification scope | Same subject, same period, same field | The starting point of this hypothetical exercise, compared sentence by sentence with the source wording |

The hypothetical exercise starting point uses "same period, same field" as the comparison basis because the source wording already states dates and clause fields. The comparison is made against the same field in the proposed sentence, without introducing authorization or effective-date clauses that the materials do not state.

## Three common errors

1. Treating an unstated item as a denial. Source wording three does not describe an instant-arrival mechanism, so "refunds arrive instantly" in the proposed sentence is unsupported. That is not a denial conclusion that conflicts with the materials.
2. Comparing across fields. The chargeback reason code in source wording two and the return window in source wording three are different fields. The existence of a chargeback does not support an inference that the return clause is invalid.
3. Replacing a business action with node behavior. The form input node collects and passes information. Field validation, approval and write-back need to be implemented in an external system or later nodes, and cannot be described as completed automatically by the node.

## How to verify the setup

1. Enter order number SO-2024-0871 and the proposed sentence from the hypothetical sample, then compare the 14 days in source wording three with the 30 days in the proposed sentence. The values for the same field are mutually exclusive, so the result is unsupported. The materials do not state instant arrival, so that part is recorded as unsupported.
2. Enter the same order number but provide only source wording one, then compare the payment date and delivery date fields in that wording. Source wording one does not state a return window, so the result is pending verification and is not recorded as a denial.
3. Enter source wording three and the proposed sentence, then compare the refund timing field. Source wording three states 5 business days; the proposed sentence states instant arrival, so that field is unsupported. If the proposed sentence were changed to "the refund is initiated within 5 business days after the returned goods are received", it would match source wording three. These are paper expectations and were not actually executed.
