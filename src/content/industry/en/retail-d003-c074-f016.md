# Cross-border resale returns: interactive forms for copy drafting

## What the documents look like

Cross-border resale returns handle reverse logistics and item condition, a different stage from overseas warehouse inbound replenishment. The documents in scope are the return inspection form, the refurbishment record, the scrap form, and the relisting checklist. Data comes from the overseas warehouse WMS, the TikTok return center, Amazon return reports, and item inspection photos, with daily or per-batch updates. Copy drafting for the product and marketing text happens before relisting. Statements about item condition, cosmetic grade, and refurbishment in the draft need to correspond to what the inspection form and refurbishment record actually say.

A hypothetical paper sample is used for checking. The inspection form states: "The item has minor scratches on the exterior, functions normally, packaging is damaged, recommend refurbishment and relisting." The refurbishment record states: "Outer packaging replaced; no repair performed on the item body." The draft sentence under review is: "This item has been professionally refurbished and looks like new." The subject is the returned item in this batch, the object is exterior and packaging condition, and the recorded state is packaging replaced with no body repair. The phrases "professionally refurbished" and "looks like new" have no corresponding basis in the inspection form or the refurbishment record.

## Constraints at the interactive forms step

In FastGPT v4.17.2, the Form Input node is a user interaction node. When triggered, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. The node collects the information the user fills in and passes it to later nodes; it does not include a business database function. The User Selection node is also a user interaction node. When triggered, it enters the interaction state and executes a branch based on the user's choice. It does not act as a personnel directory or a business data selector. Field validation, business approval, write-back, and batch operations are implemented in external systems or later nodes as needed.

These constraints matter for copy drafting because the draft sentence must be checked against the inspection form and refurbishment record, not against the fact that a form was submitted. A submitted form confirms that information was collected and passed onward. It does not confirm that a marketing phrase is supported by the underlying record.

## Three common errors

1. Treating the User Selection node as a business data selector. The node executes a branch based on the user's choice; it does not provide a personnel directory or item record lookup. If the form asks the user to pick a return batch from node options, the node itself does not verify that the batch exists in the WMS. That verification belongs to a later node or an external system.

2. Treating promotional phrasing in the draft as already verified. In the hypothetical sample, the draft sentence "This item has been professionally refurbished and looks like new" does not match the inspection form text "minor scratches" or the refurbishment record text "no repair performed on the item body." The copy drafting step needs to compare against the source text. A submitted form does not make the description supported.

3. Treating the interaction state wait as automatic approval or automatic write-back. After the Form Input node is submitted, it passes information to later nodes. Approval and database writes require separate system implementation. A pending review state does not show that approval passed, and a submission action does not constitute business confirmation.

## How to verify the setup

1. Input the inspection form text and refurbishment record text from the hypothetical sample, together with the draft sentence "This item has been professionally refurbished and looks like new." Compare "professionally refurbished" in the draft against "no repair performed on the item body" in the refurbishment record. Compare "looks like new" against "minor scratches" in the inspection form. If neither phrase has a corresponding basis, the draft sentence is not supported by the materials and needs revision or additional basis.

2. In the Form Input node, set the required fields to the inspection form number and the refurbishment record number. Submit with either field missing. Observe whether the node blocks submission or marks the missing field. Supply both fields and submit again. Observe whether the information is passed to later nodes. This test checks required-field behavior; it does not claim that the test was actually run.

3. In the User Selection node, set two branch options corresponding to "refurbish and relist" and "scrap." Choose the "scrap" branch and observe whether the workflow executes the corresponding branch. This test only verifies branch selection behavior. It does not verify whether a scrap form was generated or whether inventory was deducted; those require external system implementation.

These checks test the named primary task of copy drafting against the supplied source wording. They do not test identity certification, report analysis, or any other task. Where evidence is missing, it remains missing. A pending request is not approval, an offered option is not execution, and an unsigned termination is not a completed termination.
