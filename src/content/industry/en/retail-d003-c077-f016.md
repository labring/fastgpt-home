# Import and export permits: interactive forms for copy drafting

## What the documents look like

Import and export permit handling takes place before declaration and determines whether a shipment may lawfully cross a border. The working materials for this category come from commerce authority systems, customs commodity codes, supplier documents and customer statements of use. Everyday files include automatic import licences, dual-use item licences, contracts and product descriptions. This page addresses one task only: drafting product and marketing copy, and judging whether a proposed promotional sentence is supported by the materials on hand. Enterprise identity certification sits outside this page.

Material updates are irregular and occur per shipment. The interactive form function described here does not depend on batch synchronisation or real-time mechanisms. The slowest steps in this category are determining the applicable regulatory certificate, preparing statements of use and following approval status. The quality of those inputs directly shapes the range of evidence that draft copy may rely on.

## Constraints at the interactive forms step

The form input node is a user interaction node. When triggered, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. The node collects the information the user submits and passes it to later nodes. It does not carry a business database function of its own. The user selection node is also a user interaction node with the same interaction-state behaviour, and it executes a branch according to the user's choice. It is not a personnel directory or a business data selector. Field validation, business approval, write-back and batch operations need implementation in an external system or in later nodes.

Hypothetical paper exercise sample: an enterprise holds an automatic import licence. The licence records the commodity as "Model X industrial pump", the licence status as "valid", and the effective scope as limited to "Mainland China customs districts". The product description reads: "Model X industrial pump, maximum flow 50 cubic metres per hour, suitable for room-temperature clean water transfer." A draft sentence under review reads: "This product can be used for the transfer of various corrosive liquids." The object "corrosive liquids" does not appear in the product description's scope of application, and the commodity named on the licence does not match the object range described in the draft sentence. The draft sentence is recorded as unsupported.

## Configuration and implementation checks

| Configuration item | Type | Description |
| --- | --- | --- |
| Form input node | Node | Enters the interaction state when triggered, collects submitted information and passes it to later nodes |
| User selection node | Node | Executes a branch according to the user's choice; does not serve as a business data selector |
| Required information check | Implementation check | Lists the information this task cannot proceed without, and checks the missing-field case and the completed case separately |
| Licence status field | Implementation check | Compares the recorded status, valid or expired, against the condition cited in the draft sentence |
| Licence effective scope field | Implementation check | Compares the recorded scope against the object described in the draft sentence |
| Product description scope of application | Implementation check | Checks whether the description text states the use named in the draft sentence |

## Three common errors

1. Treating a licence status of "valid" as direct support for the use named in a draft sentence. Licence status and product description scope of application are different fields and need separate checks. Check: input the sample above, compare the licence status field against the condition cited in the draft sentence, and observe whether the two point to the same object and scope.

2. Extending "suitable for room-temperature clean water transfer" in the product description into "can be used for the transfer of various corrosive liquids". The description text does not state corrosive liquids, so the draft sentence is unsupported. Check: input the product description text and the draft sentence, compare the object ranges of the two, and observe whether the draft sentence exceeds the range stated in the source text.

3. Treating the branch outcome of the user selection node as a business approval conclusion. The node only executes a branch according to the choice; approval needs an external system. Check: input one selection action, compare the node branch output against the approval status field, and observe whether an approval record exists.

## How to verify the setup

- Verification one: input the hypothetical sample's licence status "valid", effective scope "Mainland China customs districts", the product description text and the draft sentence "This product can be used for the transfer of various corrosive liquids". Compare the object of the draft sentence against the object stated in the product description. The expected result is that the draft sentence is unsupported, and the evidence gap is recorded.

- Verification two: input the same licence's full fields with the draft sentence "This product is suitable for room-temperature clean water transfer". Compare the draft sentence against the product description text. The expected result is that object and use match, and the draft sentence is supported by the material.

- Verification three: input a blank material that states neither licence status nor effective scope, and submit one draft sentence. Compare the draft sentence against the blank material. The expected result is that no determination can be made; the item is recorded as pending verification, with no definite conclusion issued.

Retrieval checks observe actual returned results and do not guarantee a first hit or full recall. An empty result may be checked against a downstream design using an explicit paper input of an empty list. Libraries built on different vector models cannot be associated together; check identifiers first, exclude those that do not match, and record what is actually observed.

This page resolves one scope only: import and export permit handling, product and marketing copy drafting, and interactive forms. Whether a specific promotional sentence in product copy is supported by the materials is the question here; enterprise identity certification is a different task.
