# Chain-store site selection: context limits for copy drafting

## What the documents look like

Site selection and store opening work happens before a store begins trading, and its central materials are the site evaluation form, the letter of intent for lease, the renovation budget, and the opening schedule. These documents form around lease terms and engineering handover. Drafting product and marketing copy from them means drawing on trade-area footfall, store type, rent, and handover milestones, and each promotional sentence needs a corresponding basis in those materials. The materials are maintained separately by chain headquarters expansion, regional development, and engineering managers. Updates are irregular and happen per store, so one batch of copy requests can involve different versions of materials for several stores at once.

The site evaluation form carries trade-area footfall and the candidate site description. The letter of intent for lease carries monthly rent, rent-free period, and a signing status field. The renovation budget lists the cost items. The opening schedule lists handover nodes. A copy request that describes rent conditions or footfall therefore depends on fields whose values and status are recorded in specific documents, and on whether those documents are complete for the store in question.

## Constraints at the context limits step

The context window determines how much material content a single request can carry. The reply limit constrains output length only, and the two settings cannot substitute for each other. The knowledge base reference limit is controlled in tokens; lease clause passages in site selection materials tend to be long, and a small reference limit can trim key sentences about rent and the rent-free period, leaving the copy without a basis. The number of memory turns brings earlier site selection discussion into the request, so the same question has different input with an empty history and with history; checking requires holding the history condition fixed. When a fixed reply format such as json_schema is used, complete fields and successful parsing are separate checks, and acceptable text length does not mean the structure is usable.

The documented retrieval chain combines several optional paths. Problem optimization, semantic retrieval, full-text retrieval, hybrid retrieval, image description retrieval, image vector retrieval, RRF fusion, and ReRank each apply under their own conditions. A relevance score is a filtering threshold, not a category, entity, or permission filter, and retrieval does not grant authorization. The reference limit uses the documented token unit.

## Configuration and implementation checks

The following settings are starting points for this page's hypothetical exercise, chosen for comparison against a contrast value. They are not official default values.

| Configuration item | Hypothetical starting point for this exercise | Reason and comparison object |
| --- | --- | --- |
| AI model | A model that supports a long context | Compare against the length of the lease clause passage and confirm one request can hold the sample source text |
| Memory turns | 0 turns | Compare against the same question with 3 turns of history to exclude differences introduced by history |
| Reply limit | Enabled, set to a length that can hold basis and action | Compare against a short conclusion-only reply and confirm the basis sentence is not truncated |
| Reference limit | Set in tokens to cover all sample source paragraphs | Compare against a smaller value and observe whether the rent sentence is trimmed |
| Reply format | Default text | Compare against json_schema and confirm whether downstream needs to read fixed fields |
| Temperature | Low | Compare against a higher value; site selection copy needs to restate material facts stably |

Hypothetical exercise sample. The source text is a three-sentence excerpt from a site evaluation form: a candidate ground-floor unit in a residential community, floor area one hundred and twenty square meters, trade-area footfall mainly nearby residents. The letter of intent for lease states a monthly rent ceiling and a two-month rent-free period, with signing status pending review. The renovation budget lists two items, base works and storefront modification. The draft sentence to be judged is: this store opens with established community footfall, and rent terms have been agreed with the landlord. The judgment points are whether the footfall description has material support and whether the rent clause has been signed into effect; a letter of intent pending review does not constitute agreement reached.

## Three common errors

1. Treating the reply limit as the context window. The input is the model's maximum context value and the reply limit value; compare whether the two are conflated. The observable result is that long material is misjudged as fully carryable.
2. Setting the reference limit too small so key sentences are trimmed. The input is the sample source text and the reference limit token value; compare whether the trimmed content still contains the rent and rent-free period sentences. The observable result is that the copy cites a missing basis.
3. Treating a letter of intent pending review as an effective contract. The input is the signing status field in the material and the draft sentence; compare the values of the same field. The observable result is a draft sentence claiming rent has been agreed.

## How to verify the setup

1. Context capacity check. The input is the three-sentence sample source text and the selected model's maximum context value; compare the source token count against the capacity. The condition is met when the source text can be carried in full and the reply limit is set independently.
2. Reference trimming check. The input is the sample source text and the reference limit value; compare whether the trimmed text retains the rent and rent-free period sentences. The condition is met when the key basis sentences are not truncated. Where the search returns an empty result, an explicit paper input of an empty array can be used to check the downstream design; a hit on the search itself is not assured.
3. Draft sentence basis check. The input is the draft sentence and the source text; compare the footfall description and the signing status field. The condition is met when the footfall sentence has material support and the rent sentence is restated as pending review. Missing evidence remains missing: a pending request is not approval, and an offered option is not execution.
