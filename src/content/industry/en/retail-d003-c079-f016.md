# Central chain procurement: interactive forms for copy drafting

## What the documents look like

Central chain procurement and distribution keeps its daily paperwork in centralised procurement contracts, replenishment plans, distribution notes and store requisition forms. The operating data comes from ERP purchasing, WMS, store POS and supplier delivery data, and it is refreshed daily or weekly. For product and marketing copy drafting, the material facts that matter sit in those documents: the contracting parties, the object of supply, the quantity scope, the relevant dates and the boundary of authorisation. A promotional sentence can only be treated as supported when the underlying document actually records the corresponding fact. Where a document states a contract validity period and a single replenishment delivery quantity, it has not stated continuous supply across a whole year, and the gap stays a gap.

The parties involved are the chain supply chain centre, procurement managers and the distribution centre. Errors at this step lead to store stockouts, inventory build-up and supplier claims, so the drafting task is not decorative: a sentence that overstates what the contract or plan records can travel outward as if it were verified fact.

## Constraints at the interactive forms step

The form input node is a user interaction node. When it is triggered, the conversation enters an interaction state, the workflow state is recorded, and execution waits until the user completes the interaction. After the user fills in the required information and submits, the node collects the submitted form information and passes it to subsequent nodes. The node itself does not carry business database functions. Field validation, business approval, write-back and bulk operations need to be implemented in an external system or in subsequent nodes.

The user selection node is also a user interaction node. It triggers the interaction state, records the workflow state, waits for the user to complete the interaction, and then judges the user's choice and executes the corresponding branch. It is used to pose a decision question and route the workflow according to the feedback. It does not serve as a personnel directory or a business data selector.

Hypothetical paper exercise sample: the source material reads, "Party A is a chain headquarters; Party B is a food supplier. Centralised procurement contract number H-001, signed on 1 March 2024, supply object is 12 directly operated stores in the East China region, category is ambient dairy products, valid until 31 December 2024. Replenishment plan P-007 records a June 2024 delivery of 3,000 cases." The draft sentence to be assessed is, "Since March 2024 this supplier has supplied the 12 East China stores steadily over the long term, with no stockouts all year." Comparing the draft sentence against the the source material reads the material records only the contract validity period and one replenishment plan's delivery quantity. It does not record "steady over the long term" or "no stockouts all year." The draft sentence is unsupported and must not be written into external copy as a verified fact.

## Configuration and implementation checks

| Configuration or check item | Relation to this page | Implementation note |
| --- | --- | --- |
| Form input node | Collects the fields needed for product copy | Enters the interaction state when triggered; passes submitted values to subsequent nodes |
| Required-field check | Parties, object, quantity, dates, authorisation boundary | Test the missing-item case and the completed case separately for what is passed onward |
| User selection node | Chooses between copy positions | Executes a branch based on the choice; not a business data selector |
| Interaction state handling | Waits for filling or selection to complete | Continues the workflow downward after completion |
| Downstream division of work | Field validation, approval, write-back | Implemented in an external system or subsequent nodes |
| Hypothetical starting point for this exercise | Threshold for checking a draft sentence | Begin from sentence-by-sentence comparison with the source material, and compare against the unsupported sentence |

## Three common errors

1. Turning one delivery quantity in a replenishment plan into "no stockouts all year." Input: the source material and the draft sentence. Comparison: the quantity and period fields. Observable result: the draft sentence contains a conclusion the material does not record.
2. Using the user selection node as a supplier directory or store list. Input: the node's trigger behaviour. Comparison: the documented branch execution. Observable result: the node is used for something other than a decision.
3. Treating form submission as completed business approval. Input: the submit action. Comparison: whether approval is connected to another system. Observable result: copy is circulated as if it were approved content.

## How to verify the setup

1. Input the source material and the draft sentence from the hypothetical sample. Compare whether the draft sentence corresponds item by item to the parties, object, quantity and dates. The observable result is that the unsupported sentence is marked as pending verification.
2. Input a form missing the authorisation boundary. Compare whether the required item is demanded before proceeding. The observable result is that the interaction state waits for the entry, and values are passed only after submission.
3. Input the two branch options of the user selection node. Compare the selection result with the branch execution. The observable result is that the corresponding branch is triggered and the unselected branch does not execute.
