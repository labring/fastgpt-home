# B2B marketplaces: document comparison with tool calls

## What the documents look like

For document comparison in B2B marketplaces, this page examines FastGPT tool calls. Compare the material received with the sources used in the answer. The examples are hypothetical.

## Constraints at the tool calls step

The proposed electronic contract and quotation contain matching quantities and unit prices. Limit the tool description to reading and comparing those passages. Actual field names, types and whether the implementation accepts files or text must come from the tool contract. First inspect the selected tool and whether its request contains both source identities, then trace its result. Matching two numbers supports that text comparison; it does not establish reviewed contract totals, fulfillment or legal effect.

## Three common errors

For differing total-price statements, first establish whether the tool implements passage location, text comparison or a business calculation. A real request containing only the contract lacks the quotation input needed for two-source comparison, even if both materials appear in the parameter description. Retain tool selection and request content, then inspect each original’s identity and version. When both sources actually arrive, trace the returned difference to its location rather than diagnose a transaction fault from a result explanation alone. If both sources are present but no tool request occurs, inspect the available tool’s connection to the tool-calling module and the actual selection record. A description of comparison purposes does not establish execution of this instance.

## How to verify the setup

A payment-method clause without a voucher or bank statement cannot establish receipt of funds. If the proposed tool requires such evidence, test both missing input and a populated value lacking a source. When invocation does not occur, inspect required inputs and available tool connections. If a request uses an inferred voucher identifier, trace its origin and stop relying on it. After obtaining real evidence, recheck the request. Verify the recipient separately when using tool termination, because no later AI summary of that result follows.
