# Temu semi-managed sellers: workflow routing for document comparison

## What the documents look like

Temu semi-managed sellers hold overseas inventory and ship orders themselves. Compared with fully managed supply, fulfillment responsibility extends into overseas warehouses and logistics. The daily material set includes product declaration forms, overseas inventory sheets, price declarations and platform fulfillment orders, with updates occurring daily and per order. The comparison task for contracts and transaction materials is to check subject, object, status and validity scope in these materials against a proposed sentence or handover request, and to decide whether the sentence is supported. Data sources include the Temu Seller Center, overseas warehouse WMS, logistics tracking and procurement cost sheets. These sources do not automatically recognize one another's records.

A hypothetical exercise sample is used below. The material text offered for checking consists of three sentences. "Supplier A issued a product declaration form to overseas warehouse A on 1 March 2025, declaring model T-100, quantity 200 units, status submitted." "Overseas warehouse A received 180 units of model T-100 into stock on 3 March 2025, recorded in the inventory sheet as in stock." "The price declaration states a unit price of USD 12 for model T-100, valid from 1 March 2025 to 31 March 2025." The sentence to be judged is: "Supplier A has completed the receipt of 200 units of model T-100 and can supply continuously at a unit price of USD 12." This sentence touches three fields: received quantity, price validity period and supply duration.

## Constraints at the workflow routing step

The form input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and after the user completes required fields and submits, the node passes the collected values to later nodes. The user selection node is also a user interaction node. When the user makes a choice, the node evaluates that choice and executes the corresponding branch. Both nodes can be added repeatedly and trigger execution. These nodes collect values. They do not constitute business authorization, approval or database writes. Order writes, document backfill and external status synchronization require a separate business interface or a later process.

Retrieval is not authorization. A relevance score is not a permission or entity filter. Knowledge bases that share the same vector model can be associated together; this condition does not extend to external systems. Optional paths shown in an overall document flow diagram do not mean every request executes all of them. Image retrieval requires an image input and model capability. Reranking requires a model and must be enabled by configuration.

## Configuration and implementation checks

| Configuration item | Purpose on this page | Basis or checking method |
| --- | --- | --- |
| Form input node | Collect field values of the material to be compared | Official documentation: after submission, values are passed to later nodes |
| User selection node | Choose a branch for each field judgment result | Official documentation: after the user chooses, the corresponding branch executes |
| Interaction state check | Confirm the interaction state is entered after triggering | Documentation states the state is recorded; no separate global switch is set |
| Output handover check | Pass collected values to retrieval or judgment nodes | Compare output against input item by item |
| External action division | Order writes, backfill and synchronization require separate interfaces | Documentation does not state automatic execution |
| Hypothetical exercise start | Draft-sentence judgment threshold set to field-by-field checking | A start value for this page only, compared field by field against the material text |

## Three common errors

1. Treating form submission as business authorization. Submission only collects values. Supplier A's declaration status is submitted, which does not mean receipt is complete or the price has taken effect.
2. Treating the relevance score as a permission or entity filter. Retrieval results do not exclude unauthorized records and do not isolate by business subject.
3. Associating knowledge bases that use different vector models. The model identifier must be checked first and non-matching bases excluded. A cross-model retrieval comparison for missed recall is not performed.

## How to verify the setup

1. Input the three hypothetical source sentences and the draft sentence. Compare the draft phrase "has completed the receipt of 200 units" with the inventory sheet entry of 180 units received. When the two quantities differ, the field is judged unsupported.
2. Input the price declaration "valid from 1 March 2025 to 31 March 2025" and the draft phrase "can supply continuously." Compare the validity period field with the supply duration field. When the material does not state a supply duration, record an evidence gap.
3. Input a paper input of [] for the empty-result handover and check whether the downstream design explicitly handles the empty value. Do not claim that retrieval under a fictional rule will necessarily return [].

These checks describe expected observations. They do not report a completed test, an approval, a refund or any other business action. Where the material text is silent, the field remains unknown rather than negative.
