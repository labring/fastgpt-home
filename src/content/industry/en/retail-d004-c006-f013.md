# General export declarations: document comparison with access controls

## What the documents look like

For document comparison in General export declarations, this page examines FastGPT access controls. Match contract, invoice and packing resources to the actual identities that may use them, inspecting grants beyond classification. The examples are hypothetical.

## Constraints at the access controls step

A proposed broker exercise requires a document specialist to read a contract and packing attachment while finance checks only the invoice. This allocation is a test condition, not a ready-made system role. Inspect actual accounts against reading and operation rights on each resource, including exposure of a confidential contract appendix. If a denied identity still reads that appendix, retain its visible content and configured grant scope. Putting documents in the same classification does not establish a basis for sharing.

## Configuration and implementation checks

| Permission check | Export-comparison resource | Actual evidence |
| --- | --- | --- |
| Proposed allocation | Document work reads contracts; finance checks invoices | Match each task to real accounts |
| Appendix scope | Inspect confidential attachments separately | Content visible to a denied identity |
| Business labels | Buyer, seller and customs agent | No automatic team grant |
| External source | ERP invoice interface | Separate authentication and resource access |
| Same-question test | Authorized, denied and invoice-only identities | Full responses and operation results |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Team roles` | Inspect roles for the actual member identity. |
| `Resource permissions` | Inspect reading, editing and management by resource. |
| `Document classification` | Classification and tags do not replace authorization. |
| `External-system permissions` | Verify external-interface authentication separately. |
| `Per-account validation` | Test the same source with authorized and unauthorized accounts. |

## Three common errors

- If buyer, seller or customs-agent names become access grants, inspect accounts and contract, invoice and attachment scope. Company labels create no resource rights.

- If a denied identity reads a confidential appendix, retain originals and configuration, checking full responses beyond absent citations or attachment displays.

- If ERP invoice success becomes FastGPT business authorization, separate external-call and resource evidence. Contract reading approves neither amendment nor declaration completion; verify each necessary source.

## How to verify the setup

Test the same question with a contract-authorized identity, a denied identity and an invoice-only identity, recording visible originals and allowed operations. If an answer contains restricted contract content with no displayed citation, an empty citation alone cannot establish absence of disclosure; inspect the full response. After access checks pass, transaction correspondence and packing quantities still require content review. Reading permission does not authorize amendment of a business document or establish completed declaration authority.
