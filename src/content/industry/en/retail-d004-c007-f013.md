# General import declarations: document comparison with access controls

## What the documents look like

For document comparison in General import declarations, this page examines FastGPT access controls. Inspect source access by importer, broker and payment-review task while preserving bill-of-lading roles and external-source boundaries. The examples are hypothetical.

## Constraints at the access controls step

A comparison exercise pairs a bill of lading, import invoice and payment note. The bill distinguishes consignee and notify party, while the payment attachment names a separate payer. Identify the actual people needing each original before inspecting accounts, resources and operations. Related parties do not automatically share one system identity. A broker’s necessary documents also do not open every internal payment note. Retain the specific bill and transaction behind each read rather than deriving matching scope from matching document names.

## Configuration and implementation checks

| Comparison-permission check | Import-source relationship | Acceptance object |
| --- | --- | --- |
| Bill roles | Separate consignee and notify party | Actual account correspondence |
| Payment party | Grant payment appendices separately | Denial for a bill-only identity |
| Specific transaction | Matching document names do not match scope | Document and transaction actually read |
| External source | Inspect window and forwarder independently | Interface versus internal-resource tests |
| Role substitution | Notify party rewritten as payer | Input roles checked separately from grants |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Team roles` | Inspect roles for the actual member identity. |
| `Resource permissions` | Inspect reading, editing and management by resource. |
| `Document classification` | Classification and tags do not replace authorization. |
| `External-system permissions` | Verify external-interface authentication separately. |
| `Per-account validation` | Test the same source with authorized and unauthorized accounts. |

## Three common errors

- If a notify party becomes an authorized member, inspect original role and actual account correspondence. A business label configures no team role; the owner confirms missing mapping.

- If a bill-only collaborator receives the full payment appendix, retain response and resource settings. An undisplayed attachment may still be paraphrased.

- If external window or forwarder retrieval becomes universal internal access, test interface and FastGPT rights separately. Readability also establishes no approved trade or declaration condition.

## How to verify the setup

Ask importer staff, broker collaboration, payment-review and unrelated-transaction identities about the same documents, recording originals, operations and denials. If access is correct but the notify party becomes payer, inspect input roles and versions rather than widening rights. Retest identity scope after adding bills or payment sources, leaving absent explanations unresolved. Permission review establishes who obtained which document; actual declaration, payment and arrival handling still need operational records and owner confirmation.
