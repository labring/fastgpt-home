# Amazon FBM fulfillment: workflow routing for document comparison

## What the documents look like

Amazon FBM fulfillment places fulfillment and returns-address configuration with the seller rather than a platform warehouse inspection step. The documents that carry comparison evidence are therefore spread across four material types: order picking lists, shipment confirmation sheets, returns address settings, and logistics tracking sheets. These materials update per order and daily, and each comparison proceeds order by order.

For this task, the relevant fields are the selling entity, the goods object, the stated status, and the effective scope or period. A picking list can state a goods quantity without stating that shipment was completed. A shipment confirmation sheet can state the same quantity without stating the carrier handover. A returns address setting can state an address without stating that any synchronization action occurred. A logistics tracking sheet can state a carrier and tracking number without stating delivery. Workflow routing in this task connects collection, field comparison, and downstream handoff into a reviewable chain. Retrieval and forms collect and route values; they do not constitute authorization to execute a business action.

## Constraints at the workflow routing step

The form input node is a user interaction node. When triggered, the conversation enters an interaction state, the workflow state is recorded, and the workflow continues after the user completes the interaction. Required fields are collected on submission and passed to subsequent nodes. The user selection node is also a user interaction node. When the user makes a selection, the node evaluates that selection and executes the corresponding "yes" branch. Branch connections require verification one by one. The interaction state record is behavior of the interaction nodes; no separate global state-record switch is documented.

Collected values must be explicitly passed to subsequent retrieval, judgment, or interface nodes, and outputs must be compared against inputs item by item. Order writes, document backfill, and external status synchronization require a separate business interface or a subsequent process. A pending request is not approval. An offered option is not execution. Retrieval is not authorization, and a relevance score is not a category, entity, or permission filter.

Hypothetical drill sample: the material text reads, "Order A-8801, selling entity is a cross-border store, the picking list states goods X, two units, the shipment confirmation sheet states goods X, two units, the returns address setting states overseas local address R, and the logistics tracking sheet states carrier C and tracking number T, date range March 1 to March 5, 2025." The draft sentence to be judged reads, "This order has completed shipment per contract and synchronized the returns address." That sentence asserts two facts, shipment completion and address synchronization, and each requires separate comparison.

## Three common errors

1. Treating form submission as shipment confirmation or address synchronization. The form input node collects required fields and passes them to subsequent nodes; business writes and external synchronization require a separate interface. Check: input the sample draft sentence, compare its "completed shipment" wording against the status stated on the shipment confirmation sheet. If the material states only a goods quantity and does not state shipment completion, the claim is unsupported.

2. Treating the "yes" branch of a user selection as an executed operation. The user selection node executes the corresponding branch after the user makes a selection, and branch connections require verification one by one. Check: input the sample draft sentence, compare its "synchronized the returns address" wording against the content of the returns address setting. If the setting states only address R and does not state a synchronization action, record the item as pending verification.

3. Treating a retrieval result as authorization or as an entity separation basis. Retrieval does not perform permission or entity separation. Check: input sample order number A-8801, compare the entity and object fields of the returned records against the selling entity. If a returned record's entity differs from the selling entity, exclude that record and record the actual observation.

## How to verify the setup

1. Input the sample material text and the draft sentence. Compare the goods quantity stated on the shipment confirmation sheet against the goods quantity stated on the picking list. If both state goods X, two units, the same-field consistency condition is met. If shipment completion status is not stated, record it as unsupported.

2. Input the sample returns address setting and the draft sentence. Compare address R stated in the setting against the "synchronized the returns address" wording. If the setting does not state a synchronization action, record it as pending verification. Do not supply an authorization or effectiveness clause to force a determinate answer.

3. Input sample order number A-8801. Compare the entity, object, and period fields of returned records. If the entity matches the selling entity and the period falls within March 1 to March 5, record the actual observation. If the result is empty, use an explicit paper input of an empty list to check the downstream design, and do not claim that a fabricated rule search necessarily returns empty.

Missing evidence remains missing. Where a material does not state a status or action, the correct outcome is unsupported or pending verification, not a negative finding.
