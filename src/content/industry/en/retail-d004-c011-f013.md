# Refund-only disputes: document comparison with access controls

## What the documents look like

For document comparison in Refund-only disputes, this page examines FastGPT access controls. Inspect shipping and receipt evidence by service, appeal and warehouse task without deriving grants from a shared order. The examples are hypothetical.

## Constraints at the access controls step

A comparison exercise contains a refund-only request, outbound note and carrier receipt. Service reviews the request, an appeal handler reviews evidence, and warehouse work checks the parcel’s dispatch. Identify actual accounts needing each original and operation instead of opening everything for one order. Buyer, signer and warehouse handler are distinct subjects; names configure no members. Trace every read to its order and parcel rather than deriving equivalent scope from matching filenames.

## Configuration and implementation checks

| Permission check | Refund-only evidence relationship | Acceptance object |
| --- | --- | --- |
| Request reading | Buyer request and handling task | Original visible to service account |
| Outbound source | Warehouse needs this parcel’s evidence | Denial of excluded chat |
| Receipt subject | Signer differs from operator account | Actual member-resource correspondence |
| External tracking | Inspect carrier authentication independently | No refund or liability conclusion substituted |
| Wrong-order check | Another signature enters the answer | Parcel correspondence and input scope |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Team roles` | Inspect roles for the actual member identity. |
| `Resource permissions` | Inspect reading, editing and management by resource. |
| `Document classification` | Classification and tags do not replace authorization. |
| `External-system permissions` | Verify external-interface authentication separately. |
| `Per-account validation` | Test the same source with authorized and unauthorized accounts. |

## Three common errors

- If appeal-handler or signer labels become system roles, inspect actual accounts and operations. Business entries grant no rights; the owner confirms missing correspondence.

- If an outbound-evidence identity reads complete chats or other orders, retain originals and full response. One parcel does not authorize every source.

- If readable tracking establishes an approved refund or receipt conclusion, inspect external authentication, grants and business evidence separately. A signature alone determines neither condition nor platform responsibility.

## How to verify the setup

Ask service, appeal, warehouse and unrelated-order identities about the same evidence, retaining originals, operations and denials. Correct access with another order’s signature needs input and parcel checks rather than wider rights. Retest the same scope after adding messages or appeal results, keeping absent material unresolved. Readability performs no refund, appeal submission or platform handling; verify those outcomes through actual systems and the responsible owner instead of treating source access as business acceptance.
