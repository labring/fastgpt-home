# Warehouse picking and packing: retrieval for document comparison

## What the documents look like

Warehouse picking, checking and packing handles outbound orders. It does not handle supplier arrivals or put-away, which belong to a different work stage. The materials involved are wave picking lists, check records, shipping labels and packaging consumable sheets. These materials are produced and updated per order and per hour, so versions in a retrieval library move as work progresses. Any comparison must lock onto the same order and the same work stage.

The subjects of these materials are orders and parcels. The objects are items, quantities, label numbers and consumable specifications. States include picked, checked and packed. Knowledge base retrieval and recall finds the material fragments to be compared and hands them to the comparison step. Retrieval itself does not judge authorization, does not complete approval and does not write to any system.

## Constraints at the retrieval step

The smallest search unit is the library. A collection only classifies data and has no effect on search results. The knowledge base search node can associate one or more libraries that use the same vector model. Libraries with different vector models cannot be associated together. Check the vector model identifier first, exclude libraries that do not match, and record the actual observation. Do not run a cross-model search to compare missed recalls.

Cited content is output as an array, and its length can be 0. Even when nothing is found, this output path still completes. Search modes should be compared against test questions across semantic, full-text and hybrid retrieval. Do not assume one mode suits all materials. Hybrid retrieval merges multiple result paths through RRF. RRF is a fusion process, not a switch that can be turned on.

Minimum relevance is a filter threshold and takes effect only in semantic retrieval or when result reranking is used. It does not perform permission or entity isolation, and it does not exclude unrelated records by business category. The citation limit uses tokens as its unit. Test whether content stays complete using materials of different lengths. Question optimization performs coreference resolution and question expansion. Compare the original question with the optimized question and check whether the subject was altered incorrectly.

Image retrieval requires a corresponding image input and the relevant model capability. Reranking requires a model and must be enabled in settings. The optional paths listed in the documentation do not mean every request executes all of them.

Hypothetical drill sample

Material text for comparison (a paper sample, not a real record):

"Wave list W-0715-A, order O-2281, item SKU-9, quantity to pick 12; check record R-0715-03 states 12 items checked, status: checked; label SF-0001 corresponds to order O-2281, status: printed."

Draft sentence to be judged: "Order O-2281 has completed packing and has been handed over to the carrier."

The packing completion and carrier handover in this draft sentence have no corresponding fields in the sample text. They are unsupported.

## Three common errors

1. Treating a retrieval hit as authorization or completed approval. In the sample, the check record status is checked. Finding that record only shows the material exists. It does not support a conclusion that packing is complete or that carrier handover has occurred. For the check, input the sample text and the draft sentence, then compare whether each assertion in the draft sentence has same-subject, same-period, same-field support in the source text. The condition is met only when the source text explicitly records the corresponding state.

2. Using minimum relevance to exclude unrelated business or unauthorized records. Minimum relevance is a filter threshold. It does not perform entity or permission isolation. For the check, input the sample text and one unrelated fragment, then compare whether the unrelated fragment is filtered out because of low relevance after adjusting the threshold. If permission isolation is the goal, the condition is not met and this should be recorded as requiring a separate system implementation.

3. Associating libraries that use different vector models. For the check, input the vector model identifiers of two libraries and compare whether the identifiers match. When they do not match, exclude that library and record the observation. Do not infer runtime results of associating them together.

## How to verify the setup

1. Identifier retrieval verification. Input "order O-2281" from the draft sentence together with the sample text, use full-text retrieval, and compare whether the returned content contains that order number and the corresponding label number SF-0001. The condition is met when the returned content contains both identifiers and does not mix in other order numbers. If the return is empty, record the empty result and check whether the data has completed training.

2. State field completeness verification. Input the sample text with a citation limit of 800 tokens, and compare whether the returned content completely contains "status: checked" and "status: printed". The condition is met when both state fields appear. If a field is truncated, record the truncation position and compare with the result at 400 tokens.

3. Unsupported assertion verification. Input the draft sentence and the sample text, and compare whether "has completed packing" and "has been handed over to the carrier" have same-subject, same-period, same-field records in the source text. When the source text does not record them, judge them as unsupported and preserve the evidence gap. Do not judge them as a negation or a conflict. A paper input of an empty array can be used to check how the downstream design handles empty citations. Do not claim that a fictional rule retrieval necessarily returns an empty array.
