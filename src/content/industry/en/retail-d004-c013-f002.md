# Franchise store supervision: document comparison with context limits

## What the documents look like

For document comparison in Franchise store supervision, this page examines FastGPT context limits. Preserve store type, period and exclusions when summarizing correction evidence. The examples are hypothetical.

## Constraints at the context limits step

A proposed store-comparison packet marks the current endcap plan pending review, describes a reference layout for wide-aisle stores only and retains acceptance for another store. This exercise defines the current store as narrow-aisle. A question about adopting the older plan needs store type and reference scope together. The reference is no universal franchise requirement. Longer history may concern the other store, so actual input must identify the present subject. Shared region or plan title cannot transfer an earlier acceptance or complete the current review.

## Three common errors

First, dropping wide-aisle reference only may turn the page into a current-store requirement; compare the source limitation with delivered input. Second, history summarization may lose the other-store identity; compare original dialogue and current request, testing the same question with empty history. Third, output may announce confirmation while omitting current pending review; inspect state and store attribution, adjusting response length if needed before repeating. These concern scope delivery, historical subject and answer state. A longer answer provides no evidence that the required store review actually occurred.

## How to verify the setup

Ask whom the reference covers, what state the current store has and which store the old acceptance concerns, retaining actual inputs and sentences. Reference-token budgeting needs store qualifiers and state text available for inspection; missing content should be demonstrated in the request instead of presumed from model capacity. Missing current review records remain a source gap. Inspect model window and reply limit separately against actual capabilities and task. This test performs no visit or acceptance and presents no proposed reference as real company policy or a confirmed current operational rule.
