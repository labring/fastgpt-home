# Franchise store supervision: workflow routing for document comparison

## What the documents look like

Franchise supervision in convenience retail centers on headquarters oversight of how franchisees carry out brand standards. The comparison of contracts against transaction materials therefore draws on several document families: store visit forms, franchise contracts, rectification notices, and display standards. The main data sources are the supervisor app, POS sales, the franchise system, and store photographs. Updates arrive on weekly and monthly cycles. These materials sit in separate systems with differing field conventions, so any comparison begins by confirming each document's source and the scope in which it applies.

## Constraints at the workflow routing step

Workflow routing in this setting connects material collection, comparison triggering, and result handling. A Form Input node is a user interaction node: when it fires, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. Required fields are collected and passed to later nodes. A User Selection node is also a user interaction node; after the user makes a choice, the node evaluates that choice and runs the "yes" branch. These documented behaviors describe node actions. Retrieval results do not constitute authorization, and values collected by a form do not equal business approval. Order writes, document backfill, and external status synchronization require a separate business interface or a later process.

Hypothetical paper exercise. The source franchise contract states: "Party A authorizes Party B to use the brand mark at the store at No. 12 XX Road; the contract is valid from January 1, 2024 to December 31, 2026." The source store visit form states: "On March 5, 2025, supervisor Zhang San inspected this store; display standards were met; no violations were found." A draft rectification notice sentence reads: "According to the March 5, 2025 store visit record, this store's contract expired on February 28, 2025; immediate cessation of brand mark use is required." The question to decide: does the draft sentence agree with the contract source text?

## Configuration and implementation checks

| Configuration item | Type | Description |
| --- | --- | --- |
| Form Input node | Interaction node | Enters interaction state on trigger; collects required fields and passes them to later nodes |
| User Selection node | Interaction node | Runs the corresponding branch after the user makes a choice; verify each branch connection |
| Interaction state check | Implementation check | Recorded state is behavior of the interaction node; no separate global state switch is set or claimed |
| Output handoff check | Implementation check | Confirm collected values are passed explicitly to later retrieval, judgment, or interface nodes |
| External action split | Implementation check | Order writes, document backfill, and external synchronization require a separate business interface |
| Retrieval input check | Implementation check | Confirm the fields carried in the retrieval request match the materials being compared |

## Three common errors

1. Treating the draft sentence's date as identical to the contract source date. In the exercise, the contract is valid through December 31, 2026, while the draft sentence says the contract expired on February 28, 2025. These are mutually exclusive values in the same field, which is a contradiction. Check: input the contract source text and the draft sentence, compare the validity period field, and mark a contradiction when the values differ. Do not accept either statement on its own.

2. Treating the store visit form's inspection conclusion as proof of contract status. The visit form records only that display standards were met; it does not address the contract term, so the point is unstated. Check: input the visit form source text and the draft sentence, compare whether the fact the draft relies on appears in the visit form, and mark it unsupported when it does not appear. Preserve the evidence gap.

3. Treating a rectification request collected by a form as a completed rectification. The Form Input node collects information and passes it to later nodes; business approval and external synchronization require a separate interface. Check: input the form submission record and the downstream node configuration, compare whether an approval or write interface exists, and mark the item as pending verification when only form collection is present. Do not conclude that rectification was completed.

## How to verify the setup

1. Take the contract source text and the draft sentence from the hypothetical exercise and input them into the comparison flow. Compare the validity period field values. The condition is met when the system outputs that the two dates differ. If the system outputs that they agree, or outputs no comparison result, manual review is required. This verification does not claim that any run has occurred.

2. Take the store visit form source text and the draft sentence and input them into the comparison flow. Compare whether the fact the draft relies on appears in the visit form. The condition is met when the system marks the point as unsupported. If the system directly concludes that the contract expired, examine whether the comparison logic went beyond what the visit form records.

3. Take the form submission record and the downstream node configuration and input them into the flow. Compare whether an approval interface or a write interface exists. The condition is met when the configuration contains only form collection and handoff. If the configuration claims that rectification was completed automatically, verify whether a corresponding business interface implementation exists.
