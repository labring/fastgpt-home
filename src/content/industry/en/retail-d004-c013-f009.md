# Franchise store supervision: tool calls for document comparison

## What the documents look like

Franchise supervision centers on headquarters oversight of how franchisees carry out standards. The comparison materials are store visit forms, franchise contracts, rectification notices and display standards. Sources include the supervision app, POS sales, the franchise system and store photographs, with weekly or monthly update cycles. Contract and transaction material comparison places visit records, order transactions and contract clauses under one subject, one period and one field to judge execution status and the authorization boundary.

Three facts shape this task. First, the operator is a headquarters supervising a franchisee, so the comparison bears on contract performance and dispute risk rather than internal store operations alone. Second, the materials arrive from different systems at different cadences, so a visit form and a contract attachment can describe the same store in the same month while covering different fields. Third, the field being compared decides the conclusion: display consistency, transaction amount and settlement status are separate fields, and evidence for one does not answer another.

## Constraints at the tool calls step

The tool call node decides whether to invoke a tool from the tool description, the parameter descriptions and whether each parameter is required. System module parameters are fixed; plugin parameters are configurable. When a required parameter has no suitable value in context, the model may decline to call the tool, and prompts can guide the user to supply it. In advanced orchestration, available tools are connected to the tool call module, and tuning a small number of tools before adding more is the documented advice. The tool call termination node ends the current call, invokes no further tools and does not call the AI to summarize tool results.

Hypothetical drill sample. A franchise contract attachment states: "Party A authorizes Party B to sell Party A's designated fresh food products from 1 January 2024 to 31 December 2024, with settlement every two weeks." A store visit form for March 2024 records: "On 15 March the store's fresh food items on sale matched the headquarters catalogue." The draft sentence awaiting judgment is: "The store's March 2024 fresh food sales complied with the contract." Judging that sentence requires the contract authorization scope, the visit record and transaction data under one subject, one period and one field. The available material supports display consistency only; transaction amount and settlement status are not stated.

## Configuration and implementation checks

| Configuration item | Type | What this page checks |
| --- | --- | --- |
| Tool description | System module or plugin | States the purpose, the input conditions and the situations where the tool should not be called |
| Tool parameters | Plugin, configurable | Check parameter descriptions and whether each is required; a parameter description is not an execution guarantee |
| Required parameters | Call condition | When no suitable required parameter exists, complete it through interaction and check the actual request |
| Tool connection | Advanced orchestration | Connect available tools to the tool call module and tune a small number before expanding |
| Tool call termination | Additional node | Ends the current call, invokes no further tools and no AI summary of tool results |
| Custom tool variables | Additional node | Supplies parameter descriptions for nodes not treated as tool parameters |

Hypothetical trial starting point for this page: the visit form and the contract attachment are supplied as two separate inputs, and the tool description is limited to "compare materials sharing one subject, one period and one field." No default numeric value is set. This starting point is chosen so that the comparison target is stated explicitly rather than inferred, and it is compared against the draft sentence to see which fields the material actually covers.

## Three common errors

1. Treating display consistency in a visit form as transaction compliance. The inputs are the visit form and the contract attachment. The compared fields are "items on sale matched the catalogue" and "sales complied with the contract." These are different fields, and display consistency does not satisfy the conditions for checking transaction amount and settlement status.
2. Treating a rectification notice awaiting review as completed rectification. The inputs are the rectification notice and the visit form. Comparing the status field, a notice under review does not support a conclusion that rectification is complete.
3. Treating tool call termination as business termination. The input is the workflow node configuration. Comparing node behavior with business action, the termination node ends only the current tool call and changes no contract or transaction status.

## How to verify the setup

1. Using the sample text and the draft sentence, input the visit form line "on 15 March the fresh food items on sale matched the catalogue" and the contract line "authorized period 1 January to 31 December 2024." Compare subject, period and field. If the draft sentence claims "sales complied with the contract" while transaction data is not stated, the claim is unsupported. The expected observation is that the comparison identifies the missing transaction field; no test has been run.
2. Using the rectification notice sample, input the notice status field and compare "under review" with "completed." If the status is under review, no conclusion of completed rectification may be output. The expected observation is that the status value blocks the conclusion.
3. Using the tool call termination node configuration, input the node connections and compare termination node behavior with business action. If AI summary output still appears after termination, the configuration does not match the documented description. The expected observation is the presence or absence of downstream summary output.

An empty result can be carried forward with the paper input `[]` to check downstream design; this page does not claim that a fictional rule lookup returns `[]`.

Operational handover must keep clear which materials, operations and requests sit at which authorization state. Retrieval and forms are not authorization, and a pending review is not an approval. Where a field is not stated in the supplied material, the gap remains open rather than being filled by inference.
