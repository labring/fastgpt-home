# Convenience fresh-food orders: tool calls for document comparison

## What the documents look like

Convenience-store fresh food is ordered frequently against short shelf lives. Store staff produce the fresh-food order form, the spoilage report, the near-expiry handling sheet and the temperature record on a daily or per-shift basis, drawing on POS sales, the head-office ordering system, store inventory and cold-chain temperature records. These materials sit in different steps of the same operation, so contract-and-transaction material comparison has to work on the value relationships of the same entity, the same period and the same field. Tool calls and plugins carry the reading, field extraction and comparison decision into a checkable sequence here. They do not carry authorization decisions.

Three features of this category shape the task. Ordering and spoilage reporting happen at short intervals, so the comparison window is narrow and a date or shift mismatch changes the meaning of every value. The materials are produced by store staff rather than by a single counterparty, so the entity, item and period recorded on each form have to be matched before any field is compared. The cost of a wrong conclusion is practical: expired sales, stock-out loss and food-safety complaints. The comparison step therefore has to show which values were read and which were left unverified.

## Constraints at the tool calls step

The tool description tells the model what the tool is for, so the description should state the input conditions and the situations in which the tool should not be called. System-module parameters and plugin-configurable parameters are checked separately. A parameter description does not guarantee execution. When a suitable required parameter is absent, the model may not call the tool; prompts can guide the user to supply the missing value, and the actual request still has to be checked. In advanced orchestration, available tools are connected to the tool call module by linking the connection point, and the documentation advises starting with a small number of tools and tuning before adding more. The tool call termination node ends the current call, does not call other tools, and does not call the AI to summarize the tool result.

Hypothetical drill sample. Material A is a fresh-food order form for a store dated 10 March 2025, stating entity: Store Jia; item: rice ball; quantity: 120 units; order date: 2025-03-10. Material B is a spoilage report for the same store and the same day, stating entity: Store Jia; item: rice ball; spoilage quantity: 8 units; spoilage date: 2025-03-10. The sentence to be judged reads: "The rice ball order quantity and the spoilage quantity for Store Jia on 10 March 2025 are consistent." The comparison scope is limited to the order quantity field and the spoilage quantity field under the same entity, the same date and the same item.

## Three common errors

1. Treating a parameter description as a guarantee of execution. The parameter description only affects whether the model calls the tool; the actual request still has to be checked. Check: input Materials A and B together with the sentence to be judged, compare whether the parameters the tool actually received include entity, date and item, and observe whether the logged parameters match the materials.

2. Deciding directly when a required parameter is missing. When entity or date is absent, the model may not call the tool. Check: input a material that contains only the item, compare whether a completion prompt appears, and observe whether the call is made only after completion.

3. Treating retrieval or a form as authorized execution. Retrieval and forms collect values only; authorization and writing require downstream implementation. Check: input the sentence to be judged, compare whether the output is only a comparison conclusion, and observe whether any unconfigured write or synchronization action appears.

## How to verify the setup

1. Input Material A, Material B and the sentence to be judged. Compare the order quantity field of 120 with the spoilage quantity field of 8. Observe whether the output states that the two values are inconsistent. The condition is met when the output lists both field values explicitly and gives an inconsistency conclusion.

2. Input a material that contains only the item and the date. Compare whether the tool requests completion of the entity. Observe whether no comparison call is made before the entity is completed. The condition is met when a completion prompt appears and the call occurs after completion.

3. Input an empty-result handover scenario and check the downstream design against a paper input of an empty list. Compare whether the downstream handles the empty input as such. Observe whether no comparison conclusion is produced. The condition is met when the downstream records the empty input explicitly and does not output a judgment. All of the above are paper checks; no deployment or testing has taken place.
