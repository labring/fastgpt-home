# Franchise fee settlement: document comparison with citation tracing

## What the documents look like

For document comparison in Franchise fee settlement, this page examines FastGPT citation tracing. Trace receipt category, refund requests and review comments by payment identity and handling action. The examples are hypothetical.

## Constraints at the citation tracing step

A proposed franchise settlement packet contains a receipt labelled store deposit, an application requesting return of a franchise service fee and a handler reply saying the materials were forwarded for review. A refund-register template has a blank status field. A question about an approved deposit return needs payment identity checked first. Receipt and application name different categories, forwarding records a process step and an empty template contains no current result. A common store cannot make them one request or establish that the applicable return conditions have been met.

## Configuration and implementation checks

| Transaction-source check | Material and action scope | Acceptance action |

| Handling stage | Forwarded for review | Do not make it approval. |
| Template identity | Blank status field | Do not call it an actual event. |

## Three common errors

First, a service-fee request may become a deposit request; compare receipt purpose, application object and current correspondence evidence, retaining the category difference. Second, forwarding for review may become an approved return; inspect the reply action and actual review outcome rather than substituting routing for decision. Third, an empty register template may become an executed refund; check document identity and current execution evidence. A status column alone contains no outcome. These concern payment identity, handling stage and record authenticity, with no same-transaction inference from similar document names.

## How to verify the setup

Ask what the receipt is for, what the application requests and what the handler did, inspecting actual references for categories and states. Receipt-only input leaves application correspondence and outcome unresolved, rather than establishing either entitlement or refusal. Added review or execution records must match store, payment identity and process; approval and actual payment remain separate events. Empty references require scope and transfer investigation. This page supplies no refund rule or responsibility decision and treats neither a blank template nor a handling plan as completed settlement.
