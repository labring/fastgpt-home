# On-demand retail fulfillment: workflow routing for document comparison

## What the documents look like

On-demand retail store fulfillment processes online orders on a minute-level cadence, which differs from periodic stocktaking. The supplied brief lists the daily documents as instant orders, picking lists, out-of-stock reports, and delivery exception forms. Data sources include Douyin on-demand retail, the Meituan or JD Daojia backend, store inventory, and rider trajectories. Contract and transaction material comparison must check whether the parties, objects, statuses, and validity scope across these documents agree. Workflow routing here collects the materials that comparison needs in sequence, passes human judgment results downstream, and gives external system actions a defined receiving position.

The brief states that the three most time-consuming steps are fast picking, handling out-of-stock substitution, and returning delivery status. These steps shape what the comparison step must handle. An out-of-stock report and a substitution request are separate records from a delivery status return. The comparison task checks whether the same order, same item, same time, and same status field align across documents. The brief also states that errors can lead to delivery overtime compensation, false-delivery penalties, and customer refunds. That consequence makes status accuracy the core concern, and it makes unsupported completion claims a material risk.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, records the workflow state, and resumes after the user completes the interaction. After the user fills required information and submits, the node collects the form information and passes it to subsequent nodes. The User Selection node is also a user interaction node with the same interaction-state behavior. When the user makes a choice, the node judges the selection and executes the "yes" branch. Both nodes collect values and branch. Neither node performs authorization, approval, or database writes. Order writing, document backfill, and external status synchronization require a separate business interface or a later process. Retrieval results and form submissions cannot serve as credentials that execution has been authorized.

Hypothetical paper exercise sample: a store's out-of-stock report reads "Order number A-1024, item is room-temperature milk 250 ml, picker reported out of stock at 14:05, substitution request is same-spec soy milk, awaiting store duty confirmation." A draft sentence to be assessed reads "This order has completed substitution and shipped." Comparison must check the same order number, same item field, and same-time report status. The source text states only that confirmation is pending. The draft sentence treats pending confirmation as completed shipment, which is unsupported.

## Configuration and implementation checks

| Configuration item | Setting on this page | Relation to the sample |
| --- | --- | --- |
| Form Input node | Enabled, marked required | Collects order number, item, report time, substitution request |
| User Selection node | Enabled, "yes/no" branches | Confirms or rejects the substitution request |
| Interaction state | Triggered and recorded by the interaction node | Holds state while duty confirmation is pending |
| Output handoff | Passes collected fields to later nodes | Comparison result enters a judgment or interface node |
| External action | Separate business interface or later process | Shipment status synchronization is not done by this node |
| Retrieval scope | Limited to the target range with access rights | Missing material is recorded as a gap |

The starting value for the required-field setting is a hypothetical exercise choice, selected because the sample comparison needs order number, item, report time, and substitution request before any status check can run. It is compared against the sample source text to confirm those fields are present. This is not an official default. The retrieval scope entry describes a comparison action: check whether the target range carries an access-rights marker. It does not mean a similarity score filters businesses or unauthorized records. Retrieval is not authorization.

## Three common errors

1. Treating form submission as completed authorization. In the sample, a duty operator submitting "agree to substitution" shows only a selection result, not that a shipment action ran. The check inputs that submission record, compares whether a separate shipment interface receipt exists, and observes that without a receipt the status remains pending verification.

2. Treating a retrieval hit as a permission pass. The check inputs the retrieval result for order number A-1024, compares whether the result carries an access-rights marker, and observes that without such a marker no statement of "all materials checked" can be written.

3. Writing a pending review as already effective. The check inputs the draft sentence "completed substitution and shipped," compares it against the source text "awaiting store duty confirmation," and observes that the two status fields are mutually exclusive, so the draft is unsupported.

## How to verify the setup

Use the sample source text and draft sentence for item-by-item checks.

1. Input order number A-1024 and the item field. Compare the report status against the draft sentence status. Only when both read "completed" does the consistency condition hold. The current source text reads awaiting confirmation, so the condition is not met.

2. Input the duty selection record. Compare whether an external interface receipt appears. Only when a receipt exists can shipment completion be written. No receipt is present, so record a gap.

3. Input an empty-result paper sample. Check whether the downstream design distinguishes an empty result from a lack of permission. Observe whether the downstream design misjudges an empty result as verified.

All three checks rest on actual observation. No system error or automatic action is presumed.
