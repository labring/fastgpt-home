# On-demand retail fulfillment: retrieval for document comparison

## What the documents look like

On-demand retail store fulfillment handles online orders on a per-minute cycle. Each order produces and returns an order record, a picking list, an out-of-stock report, and a delivery exception note. This rhythm shapes contract and transaction material comparison: the task does not rely on periodic stocktaking summaries. The store agreement, platform settlement terms, substitution authorization, and delivery exception statement to be checked often appear as short text, identifiers, and status fields. Retrieval therefore needs to cover both natural-language descriptions and exact identifiers such as order numbers, store codes, and exception codes.

The document update frequency is per-minute and per-order. The retrieval step only carries the per-order rhythm given in the material. It does not derive batch synchronization, full synchronization, real-time mechanisms, or transaction-triggered mechanisms from that frequency.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases built on different vector models cannot be associated together. During checking, first verify the model identifier and exclude non-matching bases; do not run cross-model retrieval to compare missed recalls. Search modes are compared against the test question using semantic, full-text, and hybrid retrieval, without assuming one mode suits all material. The citation limit is measured in tokens; use materials of different lengths to test whether content stays complete. The minimum relevance score takes effect only under semantic retrieval or when result reranking is used; label relevant and irrelevant samples first, then adjust the threshold. Question optimization performs coreference resolution and question expansion; compare the original question with the optimized question and check whether the subject has been altered. Hybrid retrieval merges multiple result paths through RRF, and Rerank performs a second ordering; both are enabled according to settings. The optional paths shown in the overall document flow diagram do not mean every request executes all of them. Retrieval and similarity scores do not perform permission or entity isolation, and they do not determine whether a contract is effective or whether a request has been approved.

Hypothetical paper exercise sample: a contract and transaction material comparison scenario for a supermarket home-delivery store. The source material available for checking reads: "Store code S-1024 submitted an out-of-stock substitution report on 1 March 2025. The reported object is bottled water in order 7781. The substitute is another brand of the same specification. The report status is pending review." The draft sentence to be judged reads: "Store S-1024 has obtained substitution authorization and may directly execute the substitution for order 7781." The draft sentence matches the source in subject, object, and period, but the source status is pending review and the authorization boundary is not stated. The judgment is unsupported and pending verification.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | Reason and comparison method |
| --- | --- | --- |
| Associated knowledge base | Associate only one store fulfillment base using the same vector model | Verify the vector model identifier first, exclude bases with different models, then compare retrieval results |
| Search mode | Run semantic retrieval and full-text retrieval once each | Use the order number and the natural-language description in the sample to compare hit differences |
| Citation limit | Set to a token amount that can hold the single report source text | Use the sample source length as reference, compare truncated and complete cases |
| Minimum relevance score | Set to a threshold that retains only the sample source text | Label the sample as relevant and unrelated material as irrelevant first, then compare filtering results |
| Question optimization | Enable for follow-up questions containing references | Compare the original question with the optimized question, check whether S-1024 and order 7781 are altered |
| Result reranking | Enable according to settings and observe scores | Compare candidate order before and after reranking; do not assume the first item always matches |

## Three common errors

1. Treating a pending-review report as granted authorization. Input is the sample source text and the draft sentence; compare the status field "pending review" with the draft phrase "has obtained substitution authorization." The observable result is that the two do not agree, and the draft sentence is unsupported.
2. Treating the minimum relevance score as a permission or entity filter. Input is the sample question and unrelated store material; compare candidates before and after filtering. The observable result is that unrelated material may still be recalled, and permission judgment requires a separate downstream system implementation.
3. Describing RRF as a toggle switch. Input is the hybrid retrieval setting description; compare the RRF fusion description in the document with the configuration item list. The observable result is that RRF has no independent switch field and is a result fusion process.

## How to verify the setup

1. Input the sample source text and the draft sentence; compare "pending review" with "has obtained substitution authorization." If the retrieval result preserves the source status and the draft sentence is judged unsupported, the item meets the condition.
2. Input the sample question and unrelated store material; compare the candidate list before and after filtering. If unrelated material is not excluded by the similarity setting, record that observation and confirm that permission requires downstream implementation.
3. Input an empty-result continuation scenario, using the explicit paper input `[]` to check the downstream chain. If the output chain still runs and its length can be 0, the item meets the condition. Do not claim that a fictional rule retrieval necessarily returns an empty array.

Materials that are not stated, or that provide only related-stage evidence, are recorded as unsupported or pending verification. Signing, reaching cooperation, and contract effectiveness are three distinct facts. A quotation validity period does not indicate a supply period. Material needed for verification must be within an accessible target retrieval scope or an explicit manual input; when missing, preserve the evidence gap.
