# Certificates of origin: workflow routing for document comparison

## What the documents look like

Certificates of origin serve import-country tariff and customs clearance purposes. Compared with letter-of-credit document examination, a certificate-of-origin application is not necessarily governed by a letter of credit. The materials handled for this category include the certificate-of-origin application, commercial invoice, packing list, and production cost records. Sources include China International Trade Single Window, CCPIT systems, enterprise production records, and customer customs-clearance requirements.

For contract and transaction material comparison, the same field must be aligned item by item across subject, object, period, amount, and status. The task is to determine which fields agree, which are mutually exclusive, and which remain unstated. A certificate-of-origin application draft may state an origin criterion and an exporter declaration; a commercial invoice may list buyer and seller plus goods description; a packing list may give package count and gross and net weight; a contract or customer clearance requirement may carry a different quantity or consignee wording. Workflow routing collects these materials in node order, passes them forward, and separates actions that require human judgment from actions that require a downstream system.

## Constraints at the workflow routing step

The Form Input node triggers an interaction state. The workflow state is recorded, and after the user completes required fields and submits, the node passes the form information to subsequent nodes. The User Selection node also enters an interaction state when triggered. When the user makes a selection, the node evaluates that selection and executes the “yes” branch. Interaction state and state recording are behaviors of the interaction nodes themselves; no separate global state-recording switch is documented. Collected information must be explicitly passed to later retrieval, judgment, or interface nodes, and output must be compared item by item against input.

Order writing, document backfill, and external status synchronization require a separate business interface or subsequent process. Form and selection nodes do not perform these actions. Retrieval or a form does not constitute authorized execution. Determining origin rules, confirming signature and effectiveness, and approving an amendment are distinct facts. The workflow can present materials and branch outcomes; it cannot treat a pending review as approved.

Hypothetical paper exercise sample: an exporter submits a commercial invoice, invoice number INV-2405-017, dated 20 May 2024, buyer Company A, goods “stainless steel fasteners, 500 pieces,” total price USD 12,500. The packing list states the same shipment of 500 pieces, gross weight 620 kg. The certificate-of-origin application draft reads “exporter Company B, consignee Company A, origin criterion WO.” The draft sentence or handover request to be assessed is: “Please change the consignee to Company C under INV-2405-017 and backfill the certificate-of-origin application.” This request involves a subject change and document backfill. It lacks material linking Company C to this shipment and states no authorization basis.

## Configuration and implementation checks

| Configuration item | Type | Relation to this page’s sample |
| --- | --- | --- |
| Form Input node | Official node | Collects required fields such as invoice number, date, buyer, goods, quantity, and amount; passes them to later nodes after submission |
| User Selection node | Official node | Presents a branch on whether to change the consignee per the draft sentence; executes the “yes” branch after the user selects |
| Output handoff check | Implementation check item | Compares form output against the input of later retrieval or judgment nodes item by item |
| Interaction state check | Implementation check item | Confirms the node enters an interaction state and records state; no separate global switch is set |
| External action separation | Implementation check item | Document backfill and external status synchronization connect to a separate business interface, not completed inside these nodes |
| Comparison field list | Hypothetical exercise starting point for this page | Selects invoice number, date, buyer, goods, quantity, and amount as six comparison starting fields, checked against the sample text |

The comparison field list uses six fields because the sample text states exactly these six, which allows item-by-item observation of agreement, mutual exclusion, or non-statement. This is not declared an official default value. This paper exercise uses the given sample text as the comparison baseline.

## Three common errors

1. Treating a retrieval hit as authorization. Finding materials related to INV-2405-017 only shows the materials were located within accessible scope; it does not show the consignee change was approved. The check input is the retrieval result and the draft sentence; the comparison is whether an authorization-basis field appears; the observable result is that the authorization basis remains absent.
2. Treating pending review as approved. A certificate-of-origin application draft marked “pending review” is not the same as passing review. The check input is the draft status field; the comparison is whether an approval record exists; the observable result is that no approval record appears.
3. Treating the User Selection node’s “yes” branch as completed business execution. A user selecting “yes” only indicates that branch was chosen; document backfill and external synchronization still require a separate business interface. The check input is the branch execution record and the external interface call record; the comparison is whether both exist; the observable result is that the external interface call record is absent.

## How to verify the setup

1. Input the sample text and the draft sentence. Check whether the Form Input node collects the six fields: invoice number, date, buyer, goods, quantity, and amount. Compare the collected result against the sample text. The condition is satisfied when all six appear with consistent values; record a difference when a value is inconsistent or a field is missing.
2. Input the draft sentence “Please change the consignee to Company C under INV-2405-017 and backfill the certificate-of-origin application.” Check whether the User Selection node presents a branch on the consignee change. Compare the branch result against the draft sentence. The condition is satisfied when the branch presents a yes/no choice; record an exception when no branch appears or the change executes directly.
3. Input an explicit paper empty result []. Check how downstream nodes are designed to receive an empty result. Compare the downstream input against the empty result. The condition is satisfied when downstream continues on the empty result or clearly indicates no match; record an exception when downstream treats the empty result as a match and continues processing. This does not claim that a fictional rule retrieval necessarily returns [].

Retrieval checks describe observation and failure branches only. They do not guarantee a first hit, full recall, or that an unrelated query is necessarily empty. Libraries across different vector models cannot be associated together; verify identifiers first, exclude non-conforming ones, and record actual observations. Image retrieval requires corresponding image input and model capability. Reranking requires a model and must be enabled according to settings. Optional paths do not mean every request executes all of them.
