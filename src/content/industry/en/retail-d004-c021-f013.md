# Brand member operations: document comparison with access controls

## What the documents look like

For document comparison in Brand member operations, this page examines FastGPT access controls. Authorize activity terms, label descriptions and communication plans separately; access does not establish permission to contact people. The examples are hypothetical.

## Constraints at the access controls step

A comparison can use proposed activity terms, label definitions and communication plans without actual member lists. Brand operations reviews rules, stores inspect local activity, and service staff read approved explanations. List their required sources and operations. An active label describes a classification rather than consent to a particular contact. Readable assets grant no sending authority. Inspect actual team members and resources before activity, store and version relationships, keeping internal analysis and other-store material outside the comparison unless specifically authorized.

## Configuration and implementation checks

| Membership-term access | Reading subject | Actual evidence |
| --- | --- | --- |
| Duty mapping | Operations, store and service rules | Accounts, resources and operations |
| Activity scope | Terms, store and version | Actual input passage |
| Restricted resources | Other lists and internal label analysis | Full answer and denial |
| Separate permissions | CRM reads, resource access and contact | Inspect each authority basis |
| Business execution | Comparison creates no audience or message | Actual handling and records |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Team roles` | Inspect roles for the actual member identity. |
| `Resource permissions` | Inspect reading, editing and management by resource. |
| `Document classification` | Classification and tags do not replace authorization. |
| `External-system permissions` | Verify external-interface authentication separately. |
| `Per-account validation` | Test the same source with authorized and unauthorized accounts. |

## Three common errors

- If an activity owner becomes a universal member-resource maintainer, inspect the account, store and operations. Duties configure no role; the owner confirms missing mapping.

- If local terms return other-store lists or internal label analysis, retain full answers and source scope. Renaming people replaces no resource restriction, including paraphrased content.

- If CRM authentication proves internal access or permission to contact members, inspect external reads, FastGPT resources and this contact’s authority separately. Labels and plans supply no permission.

## How to verify the setup

Have operations, store and service accounts read their respective rules, then request the same restricted sources through unrelated-store identities. Retain readable passages and denials. If an allowed account receives expired activity conditions, compare the rule’s stated period with the text actually sent in this request. Recheck the same permitted sources after correcting the input version. Separate unobtained applicable terms from obtained terms omitted from the request, then repeat. Comparison creates no audience, sends no message and changes no points. Contact, membership handling and retention require their actual business basis and authority to be verified separately.
