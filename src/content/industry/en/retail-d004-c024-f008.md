# Brand concession operations: workflow routing for document comparison

## What the documents look like

In brand concession operations, a counter accepts the shopping mall's unified cashiering and commission settlement. Sales data passes first through the mall POS, then into the brand ERP and finance systems. Contract and transaction material comparison centers on four document types: the joint-operation commission contract, mall activity letters, sales receipts, and monthly reconciliation statements. Sales receipts are produced per transaction; monthly reconciliation statements form once per month. Daily-frequency and monthly-frequency materials sit inside the same comparison task, so the workflow needs separate reconciliation bases by material type. Comparing a daily receipt amount directly against a monthly statement total mixes two scopes.

A mall activity letter can change the commission rate or the party bearing a fee. During comparison, the applicable scope of the activity letter and the contract clause must be checked for the same counter and the same period. The concession manager and operations staff confirm which materials are under comparison, for which period, and for which counter, before any retrieval or judgment node runs.

## Constraints at the workflow routing step

The form input node enters an interaction state when triggered, collects required information, and passes that information to downstream nodes after submission. The user selection node evaluates the user's choice and executes the corresponding "yes" branch. Both nodes record workflow state and wait for the user to complete interaction before continuing. This mechanism fits the material confirmation step of a comparison task: the concession manager or operations staff confirm material type, period, and counter identifier, then proceed to later retrieval or judgment nodes.

The constraint is that forms collect values and do not constitute authorization. Adjusting a mall commission amount, confirming an activity fee, or handling a monthly reconciliation difference each requires a separate business interface or downstream process; an interaction node does not perform these actions. Retrieval results also do not represent permission. A relevance score is a similarity ranking result and does not exclude unrelated counters or unauthorized records. Libraries built on different vector models cannot be associated together; identifiers must be checked first and non-matching records excluded.

Hypothetical paper exercise sample: the source material text reads, "Party A mall and Party B brand sign a joint-operation commission contract for counter A on the third floor, contract period 1 January 2024 to 31 December 2024, commission rate 18% of the month's tax-inclusive sales. A mall activity letter dated March 2024 states that from 1 March to 31 March the commission rate for this counter is temporarily adjusted to 15%." The draft sentence to be assessed is, "In March 2024 this counter settles commission at 18%." The comparison condition is the same counter, the same period, and the same commission-rate field. The activity letter states 15% for March; the draft sentence states 18% on the same field. The two values are mutually exclusive on the same field, and the draft sentence is not supported.

## Configuration and implementation checks

| Configuration item | Setting or check content | Relation to this page's materials |
| --- | --- | --- |
| Form input node | Set counter identifier, material type, and period as required fields | Collects the three locating fields needed for comparison |
| User selection node | Set a "materials complete" branch; the choice enters the corresponding path | Keeps a gap record when materials are incomplete |
| Retrieval scope check | Confirm the target library and the materials under comparison use the same vector model | Libraries on different vector models cannot be associated together |
| Output handoff check | Pass the counter identifier and period collected by the form to the retrieval node | Compare output against input item by item |
| External action division | Connect commission adjustment and monthly difference handling to a separate business interface | Forms and retrieval do not execute authorization actions |
| Empty-result handoff | Use a paper input of [] to check the downstream design | Does not claim a fictional retrieval necessarily returns empty |

## Three common errors

1. Treating form submission as authorization to adjust the commission rate. The form input node collects required information and passes it to downstream nodes; the submission itself does not produce a commission change. In the hypothetical sample, the draft sentence's 18% conflicts with the activity letter's 15% and must be recorded as unsupported. A submitted form does not mean the settlement rate has been confirmed.

2. Treating a retrieval hit as confirmation of counter attribution. The relevance score is a similarity ranking result and does not act as a counter or permission filter. In the hypothetical sample, a retrieved contract fragment containing "18%" still requires checking whether the counter identifier and period point to the same object as the activity letter.

3. Treating execution of a user selection branch as completion of business approval. The user selection node executing the "yes" branch only indicates the process direction. In the hypothetical sample, selecting "materials complete" does not mean a monthly reconciliation difference has been handled; difference handling requires a separate business interface.

## How to verify the setup

1. Input the hypothetical sample's source material text and draft sentence, then compare the draft sentence's commission rate against the rate stated in the activity letter. On the same counter, same period, and same commission-rate field, 18% and 15% are mutually exclusive. The expected result is that the draft sentence is unsupported. If the output reads "confirmed" or "no conflict," the configuration has not correctly performed same-field comparison.

2. Input the hypothetical sample's counter identifier and period to the retrieval node, then compare whether the counter identifiers and periods in the returned results match the input. The expected result is that returned records all carry the same counter identifier and period, or that an empty result is returned and the downstream node records the gap. If other counters' records are returned without a marker, the retrieval scope check has not taken effect.

3. Input a paper empty result of [] to the downstream handoff node, then compare whether the downstream node keeps a gap record. The expected result is that the downstream node records "no comparable material retrieved" and does not generate a commission confirmation conclusion. If the downstream output is a confirmatory conclusion, the empty-result handoff design has not been implemented.

All of the above is paper-based checking, not executed in a real system, and does not constitute deployment, approval, or settlement action.
