# Brand livestream operations: workflow routing for document comparison

## What the documents look like

Brand-run livestream rooms carry their own scripts, inventory responsibility and after-sales handling, and creator commission is not the main cost structure. For contract and transaction material comparison, this means the comparison objects are chiefly the livestream script, the product explanation card, the shift schedule and the livestream review. Data arrives from the Douyin Shop Compass, Qianchuan, livestream comments and transaction details. The materials therefore include both outward-facing commitment text and internal execution records. The first affects exposure to false-advertising complaints; the second affects the ability to trace oversold inventory and conversion decline.

## Constraints at the workflow routing step

The form input node is a user interaction node. When it triggers, the conversation enters an interaction state and the workflow state is recorded. After the user fills the required information and submits, the node collects the submitted form values and passes them to later nodes. The user selection node is also a user interaction node; when the user makes a choice, the node evaluates that choice and executes the corresponding "yes" branch. Both nodes can be added repeatedly and trigger execution.

The routing constraint follows from this. Interaction nodes collect values, and collected values do not constitute authorization. Order writes, document backfill and external status synchronization require a separate business interface or a later process. Similarity results from a retrieval library do not carry permission or entity-isolation duties. Libraries built on different vector models cannot be associated together; identifiers must be checked first and non-matching entries excluded. Image retrieval requires a corresponding image input and model capability, and reranking requires a model and must be enabled according to settings. The optional paths shown in the overall document flow diagram do not mean every request executes all of them.

Hypothetical walkthrough sample: a brand livestream team retains the original text of an "April 18 livestream product explanation card." Two sentences read: "Item 3 in this session is a light spring jacket, promised to ship within 48 hours of order placement" and "the stock for this item is subject to the quantity actually purchasable in the livestream room." The April 18 shift schedule for the same session records one floor controller and one host. A draft sentence now awaits judgment: "All items in this session ship within 48 hours of order placement." The objects to be judged are the explanation card and the shift schedule above; the subject is the brand livestream team; the period is the single April 18 session; the field is the scope of the shipping-time commitment. The draft sentence turns the shipping time of item 3 into a commitment covering all items, which is an expansion of the value range within the same field and is inconsistent with the original text.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this trial | Reason and comparison method |
| --- | --- | --- |
| Required fields of the form input node | Draft sentence, source material text, judgment field | All three are needed for a same-field comparison; check submitted values one by one for completeness |
| User selection node branch | The "yes" branch carries the comparison forward | The documentation states the "yes" branch executes after the user makes a choice; verify the branch connection item by item |
| Interaction state check | Workflow state is recorded after triggering | Recording state is behavior of the interaction node; no separate global state-recording switch is set |
| Output handoff check | Collected values pass to a later retrieval or judgment node | Compare output against input item by item and confirm the field correspondence |
| Retrieval input | Source material text and judgment field text | Observe the correspondence between returned entries and input fields; a first-item hit is not guaranteed |
| Empty-result handoff | Check downstream design against a paper input of [] | Use an explicit empty input to check the downstream branch; do not claim that a fictional rule-based retrieval necessarily returns empty |

## Three common errors

1. Treating a draft sentence collected by the form as an already authorized execution basis. The form node only collects values; order writes and external synchronization require a separate business interface, and collection is not authorization.
2. Using a similarity score to exclude unrelated materials or unauthorized records. Relevance does not carry permission or entity-isolation duties, and libraries on different vector models cannot be associated together; identifiers must be checked and non-matching entries excluded.
3. Treating "item 3 ships within 48 hours" and "all items ship within 48 hours" as the same commitment. The subject, period and field are the same, and the value ranges are mutually exclusive, which makes them inconsistent. If the original text does not state a shipping time, the draft sentence is unsupported rather than conflicting.

## How to verify the setup

1. Input the explanation card text, the shift schedule and the draft sentence from the hypothetical sample, and compare the judgment field "scope of the shipping-time commitment." Condition to satisfy: the draft sentence range is broader than the item 3 range in the original text, the result is recorded as inconsistent, and the source location in the original text is noted.
2. Input a draft sentence containing only "items in this session are subject to the quantity actually purchasable," and compare the stock field. Condition to satisfy: the sentence and the original text share the same field and the same value, and the result is recorded as consistent. If the draft sentence adds an "all items" qualifier, record it as a range expansion.
3. Input a paper empty result of [] and compare the downstream branch design. Condition to satisfy: the downstream node has a defined handoff path for empty input. If the downstream does not define empty-input handling, record a design gap and do not infer a system error or an automatic action.
