# Trade and FX administration: access controls for document comparison

## What the documents look like

This category concerns foreign-exchange receipts and settlement together with trade directory records. The working materials are receipt advices, trade contracts, invoices, and foreign-exchange business registration records. Unlike letter-of-credit document examination, this work does not review a full set of credit documents; the comparison focuses on whether the receiving entity, the amount, and the trade contract and invoice correspond to one another. Materials update per transaction and monthly, and they draw on bank online portals, corporate finance books, and customs export data.

Those characteristics shape access control. A single trade contract can correspond to several receipts, and a single receipt can correspond to several invoices. Any widening of visibility across entities can expose fund information or lead to incorrect posting. Access control therefore has to operate record by record, at the level of the individual contract and transaction material.

## Constraints at the access controls step

In the documented permission system, resources are typed. A knowledge base is a dataset; a file or folder is a collection. Knowledge base permission is always the threshold: collection permission cannot bypass knowledge base permission. File-level permission is off by default, and in the off state collection readability matches the knowledge base exactly, with no collection permission records queried. Once enabled, every file and folder receives a permission snapshot, and lists, details, and retrieval recall are each authorized against that snapshot item by item.

Retrieval recall applies file-level filtering only when authentication runs as the current member identity. A workflow that preselects a knowledge base without member-identity authentication does not perform file-level filtering and still recalls by knowledge base permission. Similarity and relevance scores do not carry permission or entity isolation. Retrieval settings cannot substitute for an authorization decision.

The snapshot materializes synchronously inside the request and can take time when many files exist. The switch is set only after materialization succeeds; a mid-way failure leaves it off, and re-running is idempotent. Closing deletes all collaborator configurations under that knowledge base and restores inheritance, and this cannot be reversed. Team administrators do not bypass file-level permission; system root and the team owner are treated as holding full permission on all files.

## Configuration and implementation checks

The following is a hypothetical drill sample. A trade finance staff member intends to compare contract and invoice materials against one receipt. The material supplied for comparison reads: "Exporter: a machinery manufacturer in East China (hypothetical name); importer: a trading company in Southeast Asia (hypothetical name); contract number HX-2024-031; contract amount USD 120,000; signing date 5 March 2024." A second material reads: "The receipt advice shows the payee as the East China machinery manufacturer, amount USD 118,000, date 10 April 2024." The draft sentence awaiting judgment is: "This receipt matches the contract amount, so the trade background can be confirmed as genuine."

| Configuration item | Hypothetical starting point | Comparison method |
| --- | --- | --- |
| Knowledge base file-level permission switch | Off state (documented default) | Confirm collection permission has no effect before enabling |
| Collaborator configuration | Only the finance specialist added with read permission | Compare against the creator record and confirm the list contains the creator |
| Retrieval recall authentication mode | As current member identity | Distinguish from the preselected knowledge base without identity authentication |
| Collection permission inheritance state | Inherited state | Compare with independent state and confirm whether parent changes propagate |
| Team administrator identity | Does not bypass file-level permission | Distinguish from system root and team owner |

The collaborator list uses full-overwrite semantics: the submitted list is the final result, and it must contain the current creator or it is rejected. Modifying or deleting a collaborator inherited from a parent in the inherited state raises a conflict; after confirmation the node becomes independent, and parent permission is not silently rewritten.

## Three common errors

1. Treating a retrieval relevance setting as a permission filter. The input is one knowledge base search request; the comparison object is the returned results against the current member's readable file list. If a file the member cannot read is returned, the retrieval setting is not performing isolation, and the member-identity authentication path needs checking.

2. Treating a pending review state as an effective operation permission. The input is a collaborator addition request awaiting approval; the comparison object is the approval state against the effective permission record. Where only a pending record exists and no effective permission, the member still cannot access the target file.

3. Modifying a collaborator inherited from a parent while in the inherited state. The input is a collaborator modification on an inherited file; the comparison object is the parent permission against the current node permission. Where the system reports a conflict and converts the node to independent state, parent permission has not been silently rewritten.

## How to verify the setup

1. For the hypothetical sample above, the input is the finance specialist account accessing the contract file; the comparison object is the file-level permission snapshot against the knowledge base threshold permission. The expected observation is visibility when both knowledge base read permission and file read permission are present, and no visibility when either is absent.

2. For the draft sentence "This receipt matches the contract amount, so the trade background can be confirmed as genuine," the input is the contract amount of USD 120,000 and the receipt advice amount of USD 118,000; the comparison object is the amount value in the same field over the same period. The expected observation is that the sentence is not supported when the two figures differ, and the difference plus the verification gap should be recorded. The receipt advice does not state a contract number, so the correspondence between this receipt and contract HX-2024-031 remains unestablished on the supplied materials.

3. For retrieval recall, the input is a knowledge base search request authenticated as member identity; the comparison object is the returned files against the current member's readable list. The expected observation is that files beyond the member's permission are not recalled. Where an empty result appears, check the downstream design against an explicit paper input of an empty list, and do not assert that a rule returns an empty result.

Across these checks, a pending request is not an approval, an offered option is not an execution, and an unsigned termination is not a completed termination. Where a document field is not provided, it remains unknown.
