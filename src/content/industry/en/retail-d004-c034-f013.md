# Export tax rebate filings: access controls for document comparison

## What the documents look like

Export tax rebate filing happens after goods leave the country, and its work is matching tax vouchers rather than declaring goods at the border. The working materials are the export exemption and rebate filing form, the export customs declaration, purchase invoices, and foreign exchange receipt vouchers. Each item carries a subject, a filing batch, and amount fields, and the set is refreshed monthly or per batch. For contract and transaction material comparison, the contract, customs declaration, purchase invoice, and receipt voucher for one filing batch are checked against each other, so access control has to cover vouchers from different sources inside the same batch.

## Constraints at the access controls step

FastGPT permissions combine attribute-based and role-based management across members, departments, and groups. Member permissions have the highest priority, and department and group permissions are combined as a union. Resource types include team, app, dataset, and collection. Knowledge base file-level permission is a commercial-edition feature: in the closed state the readability of a collection matches the knowledge base, and in the open state each file or folder receives a complete permission snapshot, with lists, details, and retrieval recall authorised entry by entry against that snapshot. Knowledge base permission remains the threshold throughout, so collection permission cannot bypass it. Retrieval recall filters by the files the current member can read, and this applies only when authorisation runs under the current member identity. Team administrators do not bypass file-level permission. During comparison, the customs declaration and purchase invoice in one batch can therefore sit under different file-level permissions, and the visible range has to be checked account by account.

Hypothetical paper exercise sample. A foreign trade enterprise finance staff member submits a batch of export rebate filing materials. The draft sentence under review is: "The customs declaration, purchase invoice, and receipt voucher in this batch have completed contract comparison and can be submitted for filing." The source text supplied for checking is: customs declaration number HYP-2024-001, export date 12 March 2024, contract number HT-2024-018, filing batch 202403A; purchase invoice number FP-2024-056, issue date 15 March 2024, amount consistent with the customs declaration; receipt voucher SW-2024-022, credit date 2 April 2024, amount covering 80% of the customs declaration. The pending request is that finance staff member A asks to view and export all materials in this batch for comparison. The request concerns subject A, object 202403A batch materials, and status pending review.

## Configuration and implementation checks

| Configuration item | Official basis or check action | Hypothetical starting value and comparison method |
| --- | --- | --- |
| Knowledge base file-level permission switch | Commercial-edition feature; closed state inherits knowledge base permission, open state authorises per file | Paper assumption: open. Compare the number of visible files against the closed state |
| Knowledge base read permission | Knowledge base permission remains the threshold | Assume finance staff member A holds read permission on this knowledge base; an account without read permission should see no files |
| Collection read permission | In the open state each file is authorised against its snapshot | Assume read permission is configured separately for the customs declaration, purchase invoice, and receipt voucher; check visible entries account by account |
| Member and group permissions | Member permissions have the highest priority; department and group permissions form a union | Assume A also belongs to the finance group; compare A's individual permission with the union result of the finance group permission |
| Retrieval recall filtering | Filters by files the current member can read; applies only when authorisation runs under member identity | Assume A runs a retrieval; observe whether returned entries fall inside A's readable file range |
| Collaborator list full overwrite | The submitted list is the final result, and the creator must appear in it | Assume the creator is retained when the collaborator list is submitted; compare the creator record before and after submission |

## Three common errors

1. Treating retrieval relevance as permission filtering. The input is the query A submits; compare the returned entries against A's actual readable file list and observe whether an unauthorised file appears. A relevance score does not perform entity or permission isolation.
2. Treating team administrator identity as grounds for bypassing file-level permission. The input is the team administrator account; compare its visible files against the file-level permission snapshots and observe whether authorisation still follows the collaborator configuration. Team administrators do not bypass file-level permission.
3. Treating a pending-review request as granted authorisation. The input is finance staff member A's export request; compare the request status against the authorisation records and observe whether an approved authorisation record exists. Pending review does not demonstrate the absence of an operating permission, and it does not mean the export has been executed.

## How to verify the setup

1. Input the three materials from the hypothetical sample, customs declaration HYP-2024-001, purchase invoice FP-2024-056, and receipt voucher SW-2024-022. Compare finance staff member A's account visible range against the collection read permission configured for each of the three materials, and observe whether A sees only authorised files. The expected condition is that the visible range matches the authorised range and unauthorised files appear in neither the list nor the retrieval results.
2. Input the draft sentence "The customs declaration, purchase invoice, and receipt voucher in this batch have completed contract comparison and can be submitted for filing." Compare it against the source facts that the receipt voucher credit date is 2 April 2024 and the amount covers 80% of the customs declaration, and observe whether the draft exceeds what the source supports. The source does not state that contract comparison is complete, so this sentence remains unverified.
3. Input finance staff member A's export request. Compare the request status against the authorisation records and observe whether an approved export authorisation exists. If only a pending-review request exists, record it as not authorised and do not execute the export. Where a retrieval check returns an empty result, an explicit paper input empty list can be used to check the downstream design; do not claim that a fictional rule necessarily returns an empty list. Libraries on different vector models cannot be associated together, so verify the identifier first and exclude those that do not match, then record the actual observation.
