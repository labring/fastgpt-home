# Trade returns and claims: access controls for document comparison

## What the documents look like

Trade returns and claims handle reverse logistics and liability determination after export. The working materials come from customer email, quality inspection reports, customs systems and insurance claim systems. A return agreement, a claim letter, a quality report and a return customs declaration form the comparison base. Each case is filed separately and updates are irregular, per case. The same shipment can carry a customer position, an inspection conclusion and a customs record at the same time, and these three do not automatically agree on party, object or status. Access controls and data isolation answer two questions: who may read which materials within which scope, and whether the materials behind a comparison conclusion sit in an accessible, verifiable authorization state.

## Constraints at the access controls step

Knowledge base permission is the threshold. Collection permission cannot bypass knowledge base permission. While file-level permission is off, collection readability matches the knowledge base and the system queries no collection permission records. Once enabled, each file or folder generates a full permission snapshot, and list, detail and retrieval recall are authorized item by item against that snapshot. Retrieval recall filters by readable files only when authorization runs under the current member identity. A workflow that preselects a knowledge base without member-identity authorization performs no file-level filtering. A team administrator does not bypass file-level permission. Similarity and relevance scores do not carry entity or permission filtering, and a retrieval result is not an authorization result.

Hypothetical paper exercise sample: a foreign trade company's after-sales role holds read permission on a knowledge base, and file-level permission is enabled on that knowledge base. The return agreement file text reads: "Party A is the shipper, Party B is the carrier; this agreement takes effect on the date both parties sign." The claim letter file text reads: "The company files a claim for shipment batch A, and the amount is subject to the conclusion of the quality report." The quality report file text reads: "Sampling date is March 1; conclusion is partial moisture damage." The draft sentence to be assessed is: "The return agreement has taken effect and the claim amount is confirmed." This draft sentence touches two facts, agreement effectiveness and claim amount, and each must be checked against its own file and authorization scope.

## Configuration and implementation checks

| Check item | Documented setting or implementation check | Relation to this page's sample |
| --- | --- | --- |
| Knowledge base read permission | Knowledge base "usable" allows calling the knowledge base in an application | The sample account must hold read permission on the knowledge base, or the files stay invisible |
| File-level permission switch | Off state inherits the knowledge base by default; on state authorizes item by item against the snapshot | The sample must confirm switch state; while off, a single-file permission write is rejected |
| Single-file collaborator | Full-overwrite semantics; the submitted list is the final result | Collaborator lists for the three materials in the sample must include the current creator |
| Retrieval recall authorization | Filters by readable files when authorization runs under current member identity | The sample comparison must run at an entry point that authorizes by member identity |
| Team administrator boundary | A team administrator does not bypass file-level permission | The administrator identity in the sample does not automatically obtain file content |

## Three common errors

1. Treating a retrieval recall result as an authorization basis. Similarity and relevance scores carry no permission filtering, so recalling a file does not mean the member holds read permission on that file. Compare the member's actual readable file list against the recall result.
2. Treating team administrator identity as a substitute for file-level permission. A team administrator does not bypass file-level permission; the knowledge base and files are still authorized by their own collaborator configuration. Verify per account whether the same file differs in visibility between an administrator and an ordinary member.
3. Judging agreement effectiveness and claim amount in the draft sentence as one item. In the sample, the return agreement text states only a signature effectiveness condition, and the claim letter text states only that the amount follows the quality report. Party, object and field differ. Check them separately, and record unstated parts as pending verification.

## How to verify the setup

1. Input the three material texts and the draft sentence from the sample, then compare the draft clause "the return agreement has taken effect" against the signature effectiveness condition in the return agreement text. If the text carries no signature record and no effective date, that clause is unsupported; record the evidence gap.
2. Input the claim letter text and quality report text from the sample, then compare "the claim amount is confirmed" against the amount fields in both texts. If the quality report states no amount and the claim letter only points to the report conclusion, that clause is pending verification, not a contradiction.
3. Input the sample account and another account without read permission on the file, then compare the same file list and retrieval recall result. If the first sees the file and the second does not, and recall excludes the file, file-level isolation behaves as expected. If both see it, check the switch state and the collaborator list.
