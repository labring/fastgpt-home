# Multi-warehouse inventory: access controls for document comparison

## What the documents look like

Multi-warehouse allocation happens at the order-routing stage and determines which warehouse ships an order. The materials that support contract and transaction comparison span allocation rules, inventory synchronization tables, transfer orders and stockout warnings. These fields are distributed across WMS, OMS, ERP inventory and platform inventory interfaces. Update frequency is daily or hourly, and material versions may differ as inventory changes, so a comparison must lock to a single point in time or a single document version. For access controls and data isolation, the central question is whether the person viewing a material holds read permission on both the target knowledge base and the target file, and whether retrieval recall filters each file by member identity.

The fields that matter for this task are the subject, the object, the status and the effective range. A comparison that does not lock these four fields can treat an unstated fact as a confirmed one. The team administrator role does not bypass file-level permissions, and retrieval relevance does not perform authorization filtering.

## Constraints at the access controls step

Knowledge base permission is the threshold. File-level permission takes effect only after it is enabled. In the disabled state, files and folders share the knowledge base permission. In the enabled state, each file generates a complete permission snapshot, and the list, the detail view and retrieval recall all authenticate against the snapshot item by item. Retrieval recall filters unauthorized files only when authentication runs by the current member identity; a workflow that preselects a knowledge base without member-identity authentication still recalls by knowledge base permission. A similarity or relevance score does not constitute entity isolation or permission filtering, and a retrieval hit does not mean access is authorized. External system interface authentication and FastGPT resource permissions are verified separately.

A hypothetical paper exercise sample: a supply chain planning team maintains a knowledge base containing an allocation rule and an inventory synchronization table. The source material reads: "Allocation rule R-01 states that orders in the East China region ship preferentially from the Suzhou warehouse, effective from 1 March 2025 to 31 March 2025." "Transfer order DB-20250310-07 records a transfer of 200 units from the Suzhou warehouse to the Hangzhou warehouse, with status pending review." The draft sentence to be judged is: "The Suzhou warehouse has completed shipment of this order under R-01." That sentence concerns subject, object, status and period, but the material does not record an order number, a shipment time or a shipment completion record.

## Configuration and implementation checks

Configuration centers on the sample above and lists only documented settings or implementation check items. The values are starting points for this hypothetical exercise and are not official defaults.

| Configuration item | Hypothetical starting point | Reason and comparison method |
| --- | --- | --- |
| Knowledge base file-level permission switch | Enabled | The sample requires distinguishing the allocation rule from the transfer order by file; after enabling, authentication is per file, compared with the disabled state that shares knowledge base permission |
| Collaborator on the allocation rule file | Supply chain planning member read permission | The rule text must be viewed; compare visibility against an account holding only knowledge base read permission |
| Collaborator on the transfer order file | Supply chain planning member read permission | The transfer order status is pending review; viewing permission and approval permission are checked separately |
| Retrieval entry authentication mode | Authenticate by current member identity | A workflow that preselects a knowledge base without member authentication performs no file-level filtering; observe the two entries separately |
| No-permission account control | A member account outside the same knowledge base | Used to check whether the same material is visible without file read permission, and to record the actual result |
| External inventory interface authentication | Checked separately | External interface authentication and FastGPT resource permissions are verified separately and do not substitute for each other |

## Three common errors

1. Treating a retrieval hit as access authorization. The input is a no-file-read-permission account issuing a retrieval, and the comparison is whether that account recalls allocation rule R-01. A recall indicates filtering did not take effect; retrieval relevance does not carry permission filtering responsibility.

2. Treating a pending-review status as executed. The input is transfer order DB-20250310-07 with status "pending review," and the comparison is whether the draft sentence "transfer completed" matches the source. The source records no completion record, so the draft sentence is unsupported.

3. Treating knowledge base permission as file permission. The input is an account holding only knowledge base read permission viewing the transfer order file, and the comparison is whether that account can see the file after file-level permission is enabled. If it cannot, the file-level snapshot has taken effect, and knowledge base permission does not automatically cover it.

## How to verify the setup

1. Input the source text of allocation rule R-01 and the draft sentence "The Suzhou warehouse has completed shipment of this order under R-01," and compare subject, object, status and period. The source has an effective period and a shipping warehouse, and records no order number or shipment completion record, so the draft sentence is unsupported.

2. Input the source text of transfer order DB-20250310-07 and the draft sentence "transfer completed," and compare the status field. The source status is pending review; pending review is not execution completion, and the draft sentence is inconsistent with the source status.

3. Input a no-file-read-permission account and a read-permission account, and have each issue a retrieval against the same allocation rule file, then compare the actual recalled content of the two accounts. If the no-permission account does not recall while the permission account does, file-level filtering works as expected; if the result does not match, record the actual observation and check whether the authentication entry is by member identity.
