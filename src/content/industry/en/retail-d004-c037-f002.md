# Peak-sale fulfillment: context limits for document comparison

## What the documents look like

Peak-sale warehouse and delivery scheduling centers on short-term peak capacity and the arrangement of people, vehicles, and space. The main data sources are historical peak-sale orders, platform campaign registrations, WMS capacity, and courier pickup capability. The category updates its materials per campaign and per day, and the daily documents include the peak-sale forecast table, staffing rosters, courier assurance plans, and exception daily reports.

For the contract and transaction material comparison task, the field definitions across these documents directly affect comparison conclusions. The order-volume range in a forecast table, the onboarding date for temporary staff in a roster, and the committed vehicle count in a courier assurance plan sit in different documents and different fields. A judgment about contradiction is possible only when the same subject, the same period, and the same field are aligned. The per-campaign and per-day update frequency does not by itself establish any batch synchronization or transaction-triggered mechanism.

## Constraints at the context limits step

The comparison task places several materials into the model context for field-level checking. The model's maximum context determines how much content a single request can reference. The reply limit constrains output length only, and the two values cannot be used interchangeably. The knowledge-base reference limit is controlled by tokens, so an overly long single passage may be truncated and leave the comparison basis incomplete. The memory-round setting changes the input for the same question under different conversation histories. When `json_schema` fixes the reply format, field completeness and successful parsing need separate checks.

Hypothetical drill sample: Material A (peak-sale forecast table) reads, "During this peak-sale period, East China Warehouse No. 1 is expected to ship between 80,000 and 100,000 orders per day, with campaign dates from November 1 to November 11." Material B (staffing roster) reads, "East China Warehouse No. 1 temporary staffing roster from November 1 to November 11 has 120 people reporting each day, of whom 80 are in sorting positions." The draft sentence to be judged is: "During this peak-sale period, East China Warehouse No. 1 ships no fewer than 80,000 orders per day, and the staffing roster already covers this capacity requirement." The draft turns the lower bound of a forecast range into a definite floor and presents the match between roster and capacity requirement as a confirmed fact.

## Configuration and implementation checks

| Configuration item | Assumed trial starting point for this drill | Reason for the choice and comparison method |
| --- | --- | --- |
| AI model | Select a model that supports the required context length | Compare the combined length of Material A, Material B, and the draft sentence against the model's displayed maximum context |
| Reply limit | Assumed set long enough to hold the basis and the action | Compare whether the draft output is truncated and confirm the basis fields remain complete |
| Knowledge-base reference limit | Assumed set in tokens to cover the key passages of both materials | Compare retrieved content against the source text and confirm no single passage was truncated |
| Memory rounds | Assumed to keep a small number of prior rounds | Compare the input for the same question with empty history and with history present |
| Reply format | Use `json_schema` when fixed fields are needed | Check field completeness and successful parsing, not text length alone |
| Minimum relevance | Assumed to take effect only under semantic retrieval or rerank | This value is a filter threshold and does not carry permission or entity isolation |

## Three common errors

1. Rewriting the forecast range lower bound. Material A states "between 80,000 and 100,000 orders per day," and the draft renders this as "no fewer than 80,000 orders per day," converting a range into a definite floor. The check inputs the Material A source text and the draft sentence, compares the field value "between 80,000 and 100,000 orders" against "no fewer than 80,000 orders," and observes whether the draft has changed the range meaning of the source.
2. Treating roster headcount as proof of capacity coverage. Material B records 120 daily temporary staff, and the draft asserts the roster "already covers this capacity requirement." The check inputs the Material B source text and the draft sentence, compares whether headcount and capacity requirement are linked within the same document and the same field, and observes whether any matching basis appears in the source.
3. Treating a knowledge-base retrieval hit as authorization or approval. The check inputs the retrieval return content and the draft sentence, compares whether the retrieval result contains any authorization status field, and observes whether the draft treats a retrieval hit as granted authorization. Retrieval does not perform permission filtering.

## How to verify the setup

1. Input the Material A source text, the Material B source text, and the draft sentence. Compare whether the draft's rendering of "between 80,000 and 100,000 orders" matches the source range, and observe whether the draft has converted the range lower bound into a definite floor. The condition is satisfied when the draft preserves the range wording or explicitly marks the point as pending verification.
2. Input the Material B source text and the draft sentence. Compare whether headcount and capacity requirement correspond within the same document and the same field, and observe whether any matching conclusion appears that the source does not state. The condition is satisfied when the draft does not treat roster headcount as already covering the capacity requirement.
3. Input the retrieval return content and the draft sentence. Compare whether the retrieval result contains an authorization status field, and observe whether the draft treats a retrieval hit as granted authorization. The condition is satisfied when the draft does not treat retrieval or a form as authorization execution and keeps the authorization status as pending verification when it is missing.
