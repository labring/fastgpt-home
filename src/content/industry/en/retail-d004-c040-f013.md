# Customer-service knowledge: access controls for document comparison

## What the documents look like

Customer-service knowledge base maintenance works with FAQ entries, script templates, product parameter tables, and escalation tickets. The work is preparation of question-and-answer material that sits upstream of any refund or return decision, so the comparison task does not approve refunds itself. Material is refreshed weekly or monthly, and the comparison of contracts and transaction materials requires checking the subject, the object, the status, and the valid range across orders, contracts, and after-sales records.

Two features of this material shape the access problem. First, a relevance score from knowledge base retrieval reflects textual similarity only. It does not act as an entity filter or a permission filter, and a document category or tag does not replace an access authorization. Second, file-level permissions have a defined default state: while the switch is off, a collection's readability matches the knowledge base, and the system queries no collection permission records. Once the switch is on, each file or folder carries a permission snapshot, and the list, the detail view, and retrieval recall are each checked against that snapshot.

A hypothetical drill sample: the source material reads "Party A: Xinglan Trading (sample entity); object: March 2025 batch of care sets; status: contract signed, effective date not stated; quotation valid until April 30, 2025." A second sentence reads "The supply deadline for this batch is April 30, 2025." The draft sentence to be judged reads "The supply deadline for Xinglan Trading's March 2025 batch of care sets is April 30, 2025, and the contract has taken effect." The comparison pairs the draft sentence against the two source sentences and checks whether subject, object, period, and field agree.

## Constraints at the access controls step

The comparison requires the same subject, the same period, and the same field before a contradiction can be judged. Where a value is not stated, or where only evidence of a related stage exists, the result is unsupported or pending verification. A pending review status does not show that an operation permission is missing. Signing, reaching cooperation, and contract effectiveness are three distinct facts. A quotation validity period does not express a supply deadline.

Knowledge base permission is always a threshold, and a collection permission cannot bypass it. A team administrator does not bypass file-level permissions: team-level management permission covers only team resources such as member groups and organizations, while knowledge bases and files are checked against their own collaborator configuration. The team owner and the system root are treated as holding all permissions on all files. Retrieval recall filters by readable files only when authentication runs as the current member; a workflow that preselects a knowledge base without member-identity authentication does not apply file-level filtering.

For the drill sample, the source states that the contract is signed and that the effective date is not stated. The draft sentence asserts that the contract has taken effect. The source also states a quotation validity date, while the draft sentence converts that date into a supply deadline. Both moves need to be checked against the source wording rather than accepted.

## Configuration and implementation checks

The table below covers settings or implementation checks the official documents describe, tied to this page's sample. The values are hypothetical starting points for this drill, used for comparison against the sample text, and are not official defaults.

| Configuration item | Hypothetical drill starting point | Check method and reason |
|---|---|---|
| Knowledge base file-level permission switch | On | Check whether the target file has a permission snapshot; while off, collection permission matches the knowledge base and per-file authorization is unavailable |
| Target file collaborator role | Read permission | Check whether the member holds knowledge base read permission plus the file's read permission; a collection permission cannot bypass knowledge base permission |
| Retrieval entry authentication mode | Authenticated as the current member | Check whether the workflow search node filters by member identity; a preselected knowledge base without member authentication applies no file-level filtering |
| Team administrator identity | Does not bypass file-level permissions | Check whether team-level management permission covers only member groups and organizations; knowledge bases and files use their own collaborator configuration |
| Draft sentence field comparison scope | Subject, object, period, status | Check the same subject, the same period, and the same field; quotation validity and supply deadline are different fields and cannot substitute for each other |
| Contract effectiveness evidence | Effective date not stated in source | Check whether the source states an effective clause; where absent, record as pending verification and do not supply an authorization or effectiveness clause |

## Three common errors

1. Treating a retrieval relevance score as a permission or entity isolation mechanism. Input: a retrieval request authenticated as the current member together with a file the member cannot read. Compare whether the recall result contains unreadable files, and observe whether the unauthorized file is filtered out. A similarity setting does not exclude unrelated businesses or unauthorized records.

2. Treating a quotation validity period as a supply deadline. Input: the sample source "quotation valid until April 30, 2025" and the draft sentence "supply deadline is April 30, 2025." Compare the field names and the meaning of the period, and observe whether the two belong to the same field. A quotation validity period does not express a supply deadline.

3. Treating a signed contract as an effective contract. Input: the source "contract signed, effective date not stated" and the draft sentence "the contract has taken effect." Compare the status field and the effectiveness evidence, and observe whether the source states an effective date. Where it does not, record the item as pending verification.

## How to verify the setup

1. Input the sample source "Party A: Xinglan Trading; object: March 2025 batch of care sets; status: contract signed, effective date not stated; quotation valid until April 30, 2025" together with the draft sentence "the contract has taken effect." Compare whether the draft sentence supplies an effective date the source does not state. Where the source states no effective date, the sentence is unsupported and the evidence gap is recorded.

2. Input the sample source "the supply deadline for this batch is April 30, 2025" together with the draft sentence "quotation valid until April 30, 2025, which is the supply deadline." Compare whether quotation validity and supply deadline are the same field. The two fields carry different meanings and cannot substitute for each other, so the result is unsupported.

3. Input a retrieval request authenticated as the current member together with the target file, and compare whether the recall result contains only files that member can read. The condition is met when unauthorized files are not recalled and the list is filtered by readable files. Where a workflow preselects a knowledge base without member-identity authentication, no file-level filtering applies, and the actual authentication mode of that entry is recorded. The retrieval check records observations and failure branches; it does not guarantee a first-position hit or full recall.

Operational handover must distinguish what material, operation, or request sits in which authorization state. A retrieval result or a form value is not an authorization execution, and business verification, approval, database writes, and external synchronization each need their stated downstream implementation.
