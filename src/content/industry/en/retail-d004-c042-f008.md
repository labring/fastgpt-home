# Product listing reviews: workflow routing for document comparison

## What the documents look like

This page covers contract and transaction material comparison inside platform product title and detail compliance. The working documents are the product title table, detail page assets, the advertising prohibited-word list, and quality inspection reports. Compared with platform shipment operations, this category handles advertising truthfulness and qualification display, and does not handle parcel delivery. The daily high-frequency work is checking absolute claims, comparing physical parameters, and replacing non-compliant assets. Consequences of error include product delisting, complaints, and administrative penalty risk. Data sources are the platform rules center, advertising law compliance checklist, brand asset library, and inspection agency reports. Update frequency is weekly and on each new listing.

For document comparison, the title table, detail assets, and inspection report must be checked under the same field, same period, and same subject. The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and after the user completes the required information and submits, the node collects the submitted values and passes them to later nodes. The User Selection node is also a user interaction node; when the user makes a choice, the node evaluates that choice and executes the "yes" branch. The interaction state record is node behavior, and no separate global state switch is assumed. Collected values must be passed explicitly to later retrieval, judgment, or interface nodes, and outputs must be compared item by item against inputs. Order writing, document backfill, and external status synchronization require a separate business interface or later flow. Retrieval or form collection does not constitute authorization to execute. A pending review does not demonstrate that an operation permission is absent. The same-vector-model requirement applies to knowledge bases that are associated together, and does not extend to external websites or other systems.

Hypothetical paper exercise sample: a product title table states "subject: Merchant A; object: Batch A insulated cup; field: capacity; value: 500 ml; period: March 2025." A quality inspection report states "subject: Merchant A; object: Batch A insulated cup; field: capacity; value: 500 ml; period: March 2025." A draft detail page sentence reads "This insulated cup has a capacity of 500 ml and a heat retention time of 12 hours." The request to be judged is "compare the title table, inspection report, and draft sentence, confirm whether the capacity field is consistent, and state whether the heat retention time field has corresponding inspection evidence." In this sample the capacity field is consistent across the three sources. The heat retention time field appears in neither the title table nor the inspection report, so it is unsupported and cannot be judged as contradictory.

## Constraints at the workflow routing step

The Form Input node triggers execution and enters the interaction state. The workflow state is recorded while the conversation waits. After the user fills required fields and submits, the collected values are passed to later nodes. The User Selection node presents a choice; after the user chooses, the node evaluates the choice and executes the "yes" branch. Each branch connection must be verified individually. The interaction state record belongs to the interaction node behavior; no separate global state recording switch is documented, and none is assumed here.

Collected values must be routed explicitly to the comparison node. Outputs must be compared item by item against inputs so that missing required fields are recorded as gaps rather than silently filled. Order writing, document backfill, and external status synchronization are not performed by these interaction nodes; they require a later business interface or flow. Retrieval and form collection are not authorization. A pending review is not approval, an offered option is not execution, and an unsigned termination is not a completed termination. Similarity scores do not perform entity or permission isolation, and the same-vector-model requirement applies only to knowledge bases that are associated together. Cross-model association is not permitted; library identifiers must be checked first and non-matching libraries excluded, with actual observations recorded rather than assumed run-time outcomes.

## Three common errors

1. Treating form-collected values as authorization to execute. Input: the request to be judged in the sample above. Comparison object: the Form Input node output and the authorization state. Observable result: the form only collects values and produces no approval or write action.

2. Judging an unstated field as contradictory. Input: the draft sentence field "heat retention time 12 hours." Comparison object: the field lists in the title table and inspection report. Observable result: the field does not appear, so it is recorded as unsupported; the source wording contains no opposite value, and a missing item cannot be judged as a contradiction.

3. Using retrieval similarity in place of subject and period checks. Input: the three-source capacity records. Comparison object: the four identifiers subject, object, period, and field. Observable result: the capacity value may be compared only when those four identifiers match; similarity does not perform entity isolation.

## How to verify the setup

- Verification one: input the title table, inspection report, and draft sentence from the sample above; compare the subject, object, period, field, and value of the capacity field; observe whether the three sources agree. Expected result: the capacity field is consistent, and the heat retention time field is recorded as unsupported.

- Verification two: input the request to be judged above; compare the Form Input node output after submission against the input received by the later comparison node; observe whether all required items are passed completely. Expected result: the five required items match item by item, and any missing item is recorded as a gap.

- Verification three: input an explicit paper empty result []; compare whether the downstream node design accepts an empty result; observe whether invented records or automatic writes appear. Expected result: the downstream flow retains the empty result and records the gap without producing a business action.
