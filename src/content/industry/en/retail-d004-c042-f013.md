# Product listing reviews: access controls for document comparison

## What the documents look like

Platform product title and detail compliance handles advertising truthfulness and qualification display. It does not handle parcel delivery. The working materials include the product title table, detail page assets, the advertising prohibited-words list, and third-party quality inspection reports. These materials come from different sources: the title table is maintained by operations, assets are produced by designers, the prohibited-words list derives from the platform rules center and advertising law compliance checklist, and inspection reports are issued by external testing bodies. Update frequency is weekly and on each new listing.

The contract and transaction material comparison task requires that parameters and qualification claims in the title table, assets, and inspection reports be checked item by item. Access controls and data isolation govern this step: members in different roles can read and operate only the materials they are authorized for, and a comparison conclusion cannot rest on content visible through unauthorized access. Document classification, labels, and retrieval relevance do not constitute access authorization.

## Constraints at the access controls step

Knowledge base permission is the threshold. A collection (file or folder) permission cannot bypass knowledge base permission. When file-level permission is enabled, each file generates a permission snapshot, and list, detail, and retrieval recall are each authenticated against that snapshot. The disabled state is the default, and the system queries no collection permission records. The enable entry is the menu on the target row of the file list on the knowledge base detail page, and the permission requirement is knowledge base manage. After enabling, configuring collaborators uses full-overwrite semantics; the creator cannot be granted or modified through collaborator configuration, and the submitted list must contain the current creator.

Retrieval recall filters by the files the current member can read, and this takes effect only when authentication is by current member identity. Scenarios where a workflow preselects a knowledge base and does not authenticate by member identity perform no file-level filtering. A team administrator does not bypass file-level permission. System root and team owner are treated as having full permission on all files.

Hypothetical paper exercise sample: a team knowledge base has file-level permission enabled. Source text of the material reads: "Inspection report number JC-2024-0871, sample name children's insulated cup, test item stainless steel material migration, conclusion conforms to GB 4806.9-2016, issue date 12 March 2024." "Product title table row 42: children's insulated cup 316 stainless steel food grade." The draft sentence to be assessed reads: "This product has passed GB 4806.9-2016 testing and uses 316 stainless steel food-grade material." Comparison request: member A checks whether the material wording in title table row 42 and inspection report JC-2024-0871 agree, and confirms whether member A holds read permission on the inspection report file.

## Configuration and implementation checks

| Configuration item | Relevant setting or check on this page | Relation to the sample |
| --- | --- | --- |
| File-level permission toggle | Enabled by a knowledge base manage member from the file list menu | The sample knowledge base is enabled, so the inspection report can have its own collaborators |
| Inspection report collaborators | Full-overwrite semantics; the list must contain the creator | Member A must appear in the inspection report collaborator list with read permission |
| Knowledge base read permission | Collection permission cannot bypass knowledge base permission | Member A must also hold read permission on that knowledge base |
| Retrieval recall authentication | Files beyond authorization are filtered when authentication is by current member identity | When member A searches for the inspection report, only files member A can read are recalled |
| Comparison scope check | Same file, same field, same period | The material field must be compared in the same field across the title table and the inspection report |
| Hypothetical starting value | Member A read permission set to present, as the starting point for this check | Chosen because the sample request assumes member A participates in the comparison; compared against the visible result for an account without permission |

## Three common errors

1. Treating retrieval relevance as permission filtering. A similarity setting or category label in retrieval does not exclude unauthorized records. Check: enter member A's account, compare the range of inspection reports visible in the retrieval entry against those visible in the file list, and observe whether the two agree; if retrieval shows a report that the list does not, record it as a permission configuration gap.

2. Treating team administrator identity as a bypass of file-level permission. A team administrator does not bypass file-level permission. Check: use a team administrator account to open inspection report JC-2024-0871, compare its collaborator list against that account, and observe whether the report can be read while no collaborator record exists.

3. Treating a pending review request as granted authorization. Submitting the draft sentence for review does not mean the comparison is complete or that authorization has taken effect. Check: enter the draft sentence and the comparison request, compare their status fields against approved records, and observe whether the status is pending review; when no authorization result is stated, record it as unverified.

## How to verify the setup

- Verification one: enter member A's account and inspection report JC-2024-0871, compare whether the file collaborator list contains member A with read permission, and compare knowledge base read permission at the same time. The expected observation is that member A can see the report in the file list and detail; if not visible, record a permission gap and do not infer that the file does not exist.

- Verification two: enter the draft sentence "This product has passed GB 4806.9-2016 testing and uses 316 stainless steel food-grade material," and compare the material field in title table row 42 against the test item field in inspection report JC-2024-0871. The expected observation is that both point to stainless steel material and the test standard agrees; if the title table does not state grade 316, record it as unsupported rather than as a contradiction.

- Verification three: enter the comparison request status and compare its field values against approved records. The expected observation is that a request in pending review status must not be treated as authorized; if the status field is not stated, record an evidence gap. An empty result can be checked against downstream design using the paper input []; do not claim that a fictional rule search necessarily returns [].

Knowledge bases across different vector models cannot be associated together; check identifiers first and exclude those that do not match. RRF is a hybrid result fusion process and is not an enable switch. Image retrieval requires a corresponding image input and model capability.
