# Multi-store management: retrieval for document comparison

## What the documents look like

Multi-store matrix management involves brand e-commerce leads, channel operations staff, and distributor e-commerce teams. The working materials include store authorization lists, price control tables, cross-territory complaint forms, and monthly sales reports. These come from platform merchant backends, ERP channel pricing, brand anti-counterfeiting systems, and distributor reports, with daily or monthly update cycles.

The comparison of contracts and transaction materials is difficult because authorization status and price order vary across stores. The same distributor may hold different authorization scopes on different platforms. The same store may have different price commitments in different periods. At the retrieval step, a reviewer needs to place the authorized entity, the store object, the validity period, and the price field into the same material before judging whether a proposed sentence or handover request has documentary support.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases using different vector models cannot be associated together. During implementation, verify the vector model identifier first, exclude those that do not match, and record the actual observation. Do not run cross-model retrieval to compare missed recalls.

Search mode is tested by comparing semantic, full-text, and hybrid retrieval against the same test question. No single mode is presumed suitable for all materials. The citation limit uses tokens as its unit. Test with actual materials of different lengths to see whether content stays complete, then adjust the limit. The minimum relevance value takes effect only under semantic retrieval or when result reranking is used. Label relevant and irrelevant samples before tuning the threshold. Question optimization performs coreference resolution and question expansion. Compare the original question with the optimized question and check whether the subject has been altered incorrectly. Hybrid retrieval merges multiple result paths through RRF. RRF is a fusion process, not an on/off switch. Image retrieval requires corresponding image input and model capability. Reranking requires a model and must be enabled according to settings.

Retrieval or form collection gathers values. It does not constitute authorization execution. Business verification, approval, database writes, and external synchronization each require their own downstream implementation.

## Configuration and implementation checks

Hypothetical paper exercise sample: a brand e-commerce lead intends to check a distributor handover request. The material text is: "Authorization Letter A states: authorized distributor Jia operates store M-01 on platform M, authorization period from January 1, 2025 to December 31, 2025, authorized category is household cleaner. Price Control Table B states: store M-01's minimum retail price for household cleaner in June 2025 is 39 yuan per unit. Cross-Territory Complaint Form C states: in July 2025, a complaint was received regarding store M-02 selling household cleaner, complaint status is pending verification." The proposed sentence to be judged is: "Distributor Jia's store M-01 on platform M complied with the minimum retail price of 39 yuan per unit in June 2025." This sentence involves subject Jia, object store M-01, period June 2025, and field minimum retail price. The materials do not state the actual transaction price for that store in that month, so the sentence is unsupported.

| Configuration item | Hypothetical starting point for this exercise | Reason for selection and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Associate only knowledge bases using the same vector model; identifier subject to actual verification | Verify the vector model identifier first, exclude non-matching ones, do not run cross-model retrieval |
| Search mode | Test semantic retrieval and full-text retrieval separately on the same question | Compare recalled content between the two modes by test question; no single mode presumed suitable for all materials |
| Citation limit | Start from the tokens needed to fully cover 2 to 3 sentences of source material | Test with actual materials of different lengths to see whether content stays complete, then adjust |
| Minimum relevance | Label relevant and irrelevant samples first, then set the threshold | This value takes effect only under semantic retrieval or when result reranking is used |
| Question optimization | Enable for test questions containing coreference; compare original and optimized questions | Check whether the subject has been altered incorrectly; do not default to running it on every request |
| Result reranking | Test when a reranking model is available and enabled according to settings | Reranking scores can be used for filtering; do not write it as a mandatory switch |

## Three common errors

1. Treating a retrieval hit as authorization confirmation. Input is the material text "Authorization Letter A states distributor Jia operates store M-01 on platform M." The comparison object is the proposed sentence "Distributor Jia's store M-01 on platform M complied with the minimum retail price of 39 yuan per unit in June 2025." Observable result: the material does not state the actual transaction price for that store in that month, the sentence is unsupported, and a retrieval hit does not constitute proof of price compliance.

2. Treating pending-verification status as a confirmed violation. Input is Complaint Form C stating "complaint status is pending verification." The comparison object is any proposed sentence describing that complaint as confirmed cross-territory selling. Observable result: pending verification differs from confirmed, and the statement is unsupported.

3. Associating knowledge bases that use different vector models. Input is the vector model identifiers of two knowledge bases. The comparison object is whether the two identifiers match. Observable result: when identifiers do not match, exclude the non-matching one and record it; do not proceed with cross-model retrieval.

## How to verify the setup

1. Input is the material text "Authorization Letter A states: authorized distributor Jia operates store M-01 on platform M, authorization period from January 1, 2025 to December 31, 2025." The comparison object is the proposed sentence "Distributor Jia's store M-01 on platform M complied with the minimum retail price of 39 yuan per unit in June 2025." Observable result: the material lacks the actual transaction price field for that month, the sentence is unsupported, and the evidence gap must be recorded.

2. Input is Complaint Form C stating "complaint status is pending verification." The comparison object is the proposed sentence "Store M-02 has been confirmed for cross-territory selling." Observable result: pending verification and confirmed are different statuses, and the sentence is unsupported.

3. Input is the knowledge base search node outputting citation content as an array whose length can be 0. The comparison object is whether the downstream design accepts an empty array. Observable result: use the explicit paper input [] to check the downstream design; do not claim that a fictional rule's retrieval necessarily returns [].
