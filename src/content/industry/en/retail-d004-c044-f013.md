# Marketplace advertising: document comparison with access controls

## What the documents look like

For document comparison in Marketplace advertising, this page examines FastGPT access controls. Inspect advertising-source comparison rights by brand, operator and report resource, testing backend interfaces separately from actual accounts. The examples are hypothetical.

## Constraints at the access controls step

A comparison exercise pairs campaign-plan commitments with attribution wording. A brand reads its plan; the agency operator uses the corresponding keyword report; another brand’s audience appendix is excluded. Inspect resource reads and operations with actual accounts. Shared agency collaboration authorizes no universal brand access. If one identity receives another brand’s segmentation, retain the original passage and configuration. Channel classification supplies no access basis, and a brand name in a plan creates no grant.

## Configuration and implementation checks

| Permission check | Advertising-comparison resource | Acceptance basis |
| --- | --- | --- |
| Brand boundary | Separate own plan and another audience appendix | Originals readable by actual account |
| Operator allocation | Responsibility is not universal modification rights | Owner-confirmed resource operations |
| External report | Backend identity and return scope | Separate interface and resource evidence |
| Measure scope | Inspect period and attribution definitions | Grants choose no settlement basis |
| Full response | Restricted segmentation may be paraphrased | Same-question reads, denials and version checks |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Team roles` | Inspect roles for the actual member identity. |
| `Resource permissions` | Inspect reading, editing and management by resource. |
| `Document classification` | Classification and tags do not replace authorization. |
| `External-system permissions` | Verify external-interface authentication separately. |
| `Per-account validation` | Test the same source with authorized and unauthorized accounts. |

## Three common errors

- If a named operator becomes a member with every report-edit right, inspect actual account mappings and operations. Business responsibility is no configured authorization.

- If one brand reads another segmentation, retain originals and full response. Agency work or channel classification cannot enlarge reading, including paraphrases of undisplayed reports.

- If advertising API success becomes internal access or an accepted settlement measure, inspect external identity, grants, definitions and periods separately. Reading decides no contract or commercial responsibility.

## How to verify the setup

Ask the brand, relevant operator and unrelated-brand identities the same question, recording visible originals, denials and operations. Inspect full responses for paraphrased restricted audience text even when reports are undisplayed. Correct access with another campaign period in the answer requires input and version checks rather than wider grants. State resource scope individually. Advertising outcomes, customer acceptance and commercial responsibility require actual agreements and data, not an inference from successful permission testing.
