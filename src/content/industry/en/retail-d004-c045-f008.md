# Seller ratings management: workflow routing for document comparison

## What the documents look like

Seller ratings and experience-score maintenance work centers on consumer feedback that arrives after fulfillment, and it does not directly set promotional prices. The primary data sources named in the brief are Douyin Shop experience score, Tmall service indicators, JD after-sales reviews, and the customer service system. The documents handled day to day are negative-review handling records, experience-score detail sheets, service diagnostic reports, and rectification ledgers. Typical roles are store operations staff, customer service supervisors, and quality inspection specialists.

For the contract and transaction material comparison task, each of these documents has to be checked against a corresponding transaction voucher. The check is whether the subject, the object, the period, and the field values agree across the two sides. A negative-review handling record and a rectification ledger entry may each need to be lined up against the same order, so the workflow has to carry the collected values forward without treating collection as verification.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. After the user fills the required information and submits, the node collects the submitted form information and passes it to later nodes. The User Selection node is also a user interaction node: when it triggers, the conversation enters the interaction state and the workflow state is recorded, and after the user makes a choice, the node evaluates that choice and executes the corresponding "yes" branch. The interaction-state recording is behavior of the interaction nodes; it does not establish a separate global state-recording switch.

Collected information has to be passed explicitly to later retrieval, judgment, or interface nodes. Order writing, document backfill, and external status synchronization require a separate business interface or a later process. Retrieval and form collection do not constitute authorized execution, and a pending-review status does not demonstrate that operating permission is absent.

Hypothetical paper exercise sample: a store operations staff member submits a negative-review handling record whose text reads "March 5, 2025, order A-2031, buyer reports the item arrived damaged, customer service has contacted the buyer to supplement evidence, handling status is pending review." Alongside it, a handoff request is submitted: "Please compare this negative-review record against the transaction materials, then directly backfill the rectification ledger and synchronize the external system." The backfill and synchronization in that request are business actions that require a separately connected system implementation; the workflow nodes themselves do not perform them.

The sample text provides a subject role, an order object, a date, and a status value. It does not state that any comparison has been performed, that the ledger has been written, or that the external system has been contacted. Those remain open.

## Three common errors

1. Treating the "pending review" status collected by the Form Input node as authorized execution, and on that basis triggering backfill or synchronization. Input: the handling-status field in the sample text. Comparison: the value "pending review" against the value "completed." Observable result: whether the node only passes information forward and performs no external write.
2. Treating the "yes" branch of the User Selection node as an automatic judgment without verifying branch connections one by one. Input: the selection options in the sample handoff request. Comparison: the branch connections against the actual selection made. Observable result: whether only the selected branch executes.
3. Treating retrieval or form collection as authorized execution while ignoring that external actions require a separately connected business interface. Input: the request in the sample to "directly backfill the rectification ledger and synchronize the external system." Comparison: the node's existing behavior against the business actions that require a separately connected system implementation. Observable result: whether any undeclared write or synchronization occurs.

## How to verify the setup

1. Enter the sample text "March 5, 2025, order A-2031, buyer reports the item arrived damaged, customer service has contacted the buyer to supplement evidence, handling status is pending review." Compare the handling-status field against the value "completed." Observe whether the Form Input node only collects and passes that information forward and performs no backfill. The condition is met when the node output matches the input and no external write occurs.
2. Enter the selection options from the sample handoff request. Compare the User Selection node's branch connections against the actual selection. Observe whether only the selected "yes" branch executes. The condition is met when each branch connection corresponds one-to-one and unselected branches do not execute.
3. Enter the request in the sample to "directly backfill the rectification ledger and synchronize the external system." Compare the node's existing behavior against the business actions that require a separately connected system implementation. Observe whether any undeclared write or synchronization appears. The condition is met when the external actions are not performed by the node, and the gap is recorded as awaiting a separately connected business interface.

Across these checks, a pending request is not an approval, an offered option is not execution, and an unsigned termination is not a completed termination. Where the sample does not state a value, the field remains unknown rather than negative.
