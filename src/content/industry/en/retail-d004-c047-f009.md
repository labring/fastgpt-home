# Marketplace returns: document comparison with tool calls

## What the documents look like

For document comparison in Marketplace returns, this page examines FastGPT tool calls. Applications, return transport, inspection and approval need correspondence to this order. Textual comparison does not independently decide refunds, responsibility or payment outcomes. The examples are hypothetical.

## Constraints at the tool calls step

Return-related transaction comparison can inspect the application, warehouse receipt and refund approval separately. Proposed input contains claims and transport text without item inspection or payment processing. Limit the tool to those sources. Retain order, item and statement status rather than treating applications as approval or images as readable findings. Producing readable image evidence needs actual implementation, not an assumed tool capability.

## Configuration and implementation checks

| Transaction-comparison check | Proposed material | Actual evidence |
| --- | --- | --- |
| Order mapping | Present and other-order returns | Mismatched source removed |
| Item condition | Warehouse receipt separate from inspection | No direct passed-inspection claim |
| Financial stage | Approval separate from processing | Not described as received funds |
| Readable evidence | Image and how text is produced | Automatic recognition not presumed |
| Actual handling | Separate refund, decision and writing | Comparison is not execution |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Tool description` | Describe purpose, inputs and non-applicable situations. |
| `Tool parameters` | Inspect module and plugin parameters separately. |
| `Required parameters` | The model may not invoke a tool without suitable required inputs. |
| `Tool connections` | Available tools must connect to the calling module. |
| `Tool-call termination` | Termination ends the call without a later AI summary. |

## Three common errors

Another order’s return requires identity checks. Warehouse receipt described as passed inspection needs this item’s actual findings. Refund approval treated as returned funds needs payment-processing evidence. These concern subject, physical condition and financial stage rather than complete-looking fields.

## How to verify the setup

Inspect actual requests, calls and citations. Repeat with this order’s inspection or payment sources, retaining bounded conclusions. Missing suitable required input may prevent invocation; collect it through interaction and inspect the request, starting with a small tool set. Termination ends this call without another AI summary. Refund execution, dispute decisions and stock writes require separate authority and receipts; comparison establishes no completed action.
