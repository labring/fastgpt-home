# Parcel labels and handoffs: access controls for document comparison

## What the documents look like

Parcel handoff occurs at the point where packages leave the warehouse, and the central question is carrier scan responsibility. The working documents are electronic waybills, handoff manifests, pickup scan records, and exception item registers. They originate in courier systems, WMS shipping modules, and carrier billing files, and they are updated per batch and per day.

For comparison work, one structural fact matters most: the waybill, the handoff manifest, and the scan record for the same batch of parcels normally live in different systems, and the readable range of each is governed by its own permissions. An account that can see a waybill does not thereby see the matching handoff manifest or the carrier's scan return. Permission resolution gives member permissions priority, then takes the union of department and group permissions. Resource types include team, app, dataset, and collection. When file-level permission is enabled, list views, detail views, and retrieval recall are each checked against a per-file snapshot, and dataset permission always remains the threshold.

## Constraints at the access controls step

Contract and transaction material comparison requires that the waybill, handoff manifest, and scan record be checked inside one authorized scope. Retrieval relevance does not perform authorization, and a similarity setting does not exclude unrelated business records or unauthorized records. A workflow that preselects a dataset and does not authenticate by member identity performs no file-level filtering and still recalls by dataset permission. A team administrator does not bypass file-level permission. The team owner and system root are treated as holding all permissions on all files. External system permissions and FastGPT resource permissions are verified separately.

Hypothetical paper exercise sample: a warehouse shipping group submits a comparison request. Source text one (handoff manifest): "On 10 March 2025, the shipping group handed batch A, 40 parcels, to the carrier branch, and the handover signature field is filled in." Source text two (pickup scan record): "On 10 March 2025, the carrier system recorded 38 pickup scans for batch A." Draft sentence under review: "Batch A completed the full 40-parcel pickup handoff on 10 March 2025." The parties in this draft are the shipping group and the carrier branch, the object is the 40 parcels of batch A, the asserted state is completed pickup handoff, and the effective scope is 10 March 2025.

## Configuration and implementation checks

| Configuration or check item | Use on this page | Basis and boundary |
| --- | --- | --- |
| Dataset read permission | Determines whether an account can view the dataset holding comparison material | Dataset permission is the threshold; collection permission cannot bypass it |
| File-level permission switch | Determines whether an individual file is checked against a snapshot | In the closed state, collection readability matches the dataset and no collection permission records are queried |
| File read permission | Determines whether an account can view a given waybill or handoff manifest | Requires file-level permission to be enabled on the dataset |
| File administrator permission | Determines whether an account can configure collaborators or restore inheritance | A team administrator does not bypass file-level permission |
| Creator identity | Determines whether an account can delete a file or transfer ownership | Write permission and administrator permission do not permit deletion |
| Retrieval authentication mode | Determines whether recall is filtered by current member identity | Takes effect only when authenticated by member identity |

This page involves no numeric configuration. Hypothetical starting point: if a visible range is to be set for the directory holding comparison material, start from "readable by the shipping group all-member group," because handoff material needs to be shared inside the shipping group; the comparison method is to access the same file with a shipping group account and an account outside the group, and record the visible and not-visible results. This starting point is hypothetical for this exercise and is not an official default value.

## Three common errors

1. Treating retrieval relevance as access authorization. Observable error: assuming that a waybill record with a high similarity score will automatically be visible to an authorized account, or that unrelated records will be excluded by the similarity setting. Executable check: input a shipping group account and an account outside the group, run retrieval against the same dataset with each, compare the returned file lists, and observe whether unauthorized files appear for the outside account.

2. Treating team administrator identity as a bypass condition for file-level permission. Observable error: using a team administrator account to read a handoff manifest that has not been authorized for that account. Executable check: input the team administrator account, access a handoff manifest to which that account has not been granted read permission, compare the returned result with the file-level permission snapshot, and observe whether access is refused.

3. Treating an unstated state as a completed fact. Observable error: the draft sentence states "completed the full 40-parcel pickup handoff" while the scan record shows only 38. Executable check: input source text one, source text two, and the draft sentence, compare the quantity in the draft sentence with the quantity in the scan record, and observe whether the two agree; where the quantities disagree, the draft sentence is not supported.

## How to verify the setup

- Verification one: for the draft sentence "Batch A completed the full 40-parcel pickup handoff on 10 March 2025." The inputs are source text one (handoff manifest stating 40 parcels) and source text two (scan record stating 38). Compare the quantity in the draft sentence with the quantity in the scan record. Expected observation: the quantities disagree, the draft sentence remains pending verification, and the full pickup handoff cannot be determined as completed. This is a paper check and was not actually executed.

- Verification two: for the closed state of the file-level permission switch. The input is a dataset with file-level permission closed, accessed by an account holding dataset read permission for a file that has no individually configured collaborators. Compare the access result with dataset permission. Expected observation: the file's readability matches the dataset, and the system queries no collection permission records. If the switch is in the open state, each file is checked against its snapshot, and any refusal is observed.

- Verification three: for the retrieval authentication mode. The inputs are a retrieval request in a workflow that preselects a dataset and is not authenticated by member identity, and a retrieval request on the same dataset that is authenticated by member identity. Compare the recalled file ranges of the two. Expected observation: without member-identity authentication, recall follows dataset permission; with member-identity authentication, recall is filtered by the files readable to the current member. If retrieval returns an empty result, the downstream design can be checked against the explicit paper input []; no claim is made that a fictional rule necessarily returns []. Datasets built on different vector models cannot be associated together; verify identifiers first and exclude those that do not match.
