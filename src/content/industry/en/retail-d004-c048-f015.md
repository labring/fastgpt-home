# Parcel labels and handoffs: retrieval for document comparison

## What the documents look like

Parcel label and handoff work sits at the point where a parcel leaves the warehouse, and the carrier scan is the key action that moves responsibility. The materials handled in this category are electronic waybills, handoff lists, pickup scan records, and exception item registrations. These come from courier systems, WMS shipment records, GB/T express service standards, and carrier billing. Updates arrive per batch and per day.

For the contract and transaction material comparison task, the waybill, the handoff list, the scan record, and the exception registration must be checked under the same entity, the same period, and the same field. The retrieval step only recalls the relevant source material from the knowledge base. It does not judge authorization status, and it does not execute a handoff or a shipment.

Three features of this category shape the retrieval step. First, the carrier scan is the responsibility-transfer action, so a scan record and a handoff list can disagree about the same batch. Second, waybill number ranges and carrier names are exact strings, which makes full-text recall useful alongside semantic recall. Third, exception registrations sit beside normal scan records, so a recalled set can contain both completed and incomplete items for one batch. The daily update frequency does not change how this page's retrieval function works.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases built on different vector models cannot be associated together. Check the vector model identifier first and exclude any knowledge base whose identifier does not match.

Reference content is output as an array, and its length can be 0. When nothing is found, the output path still runs. An empty result does not mean the underlying material is absent from the business record; it means this search returned no reference.

Search modes are semantic retrieval, full-text retrieval, and hybrid retrieval. Hybrid retrieval merges multiple result paths through RRF. RRF is a fusion process inside hybrid retrieval, not a separate switch. The minimum relevance value takes effect only under semantic retrieval or when result re-ranking is used. It is a filter threshold, not a sorting rule, and it does not perform permission or entity isolation. The reference limit is measured in tokens. Question optimization performs coreference resolution and question expansion, and it adds an extra model call. Image retrieval requires image input and the corresponding model capability. Re-ranking requires a model and is enabled according to settings.

Hypothetical paper exercise sample: a warehouse shipping group keeps one handoff list with this text: "On 10 March 2025, the shipping group handed batch B-0310, 40 parcels, to the carrier branch, waybill number range SF3100001 to SF3100040; the pickup scan record shows 38 parcels scanned and 2 parcels registered as exception items." A draft sentence awaits judgment: "All parcels in this batch have completed pickup handoff." The comparison objects are the handoff list, the pickup scan record, and the exception item registration.

## Three common errors

1. Treating a retrieval recall as an authorization confirmation. Input is the draft sentence "All parcels in this batch have completed pickup handoff." The comparison objects are the handoff list and the scan record. The list states 40 parcels, while the scan record shows 38 scanned and 2 exception items. The draft sentence is not supported. Recalling material does not mean the handoff is complete.

2. Forcing knowledge bases with different vector models into one association. Input is two knowledge base identifiers. Compare their vector model fields. When the identifiers differ, exclude the combination and record it. Do not run a cross-model retrieval to compare missed recalls.

3. Treating minimum relevance as a permission or entity filter. Input is a query containing an unrelated company name. Compare whether the returned content is decided only by similarity. If unrelated fragments are returned, this shows the threshold does not perform an isolation function, and the actual observation should be recorded.

## How to verify the setup

1. Input the handoff list text from the hypothetical sample and the draft sentence "All parcels in this batch have completed pickup handoff." Compare the draft sentence against the field values in the handoff list, the scan record, and the exception registration. The draft sentence is supported only when all three materials agree on the same entity, the same period, and the same field. The 38 scanned parcels and 2 exception items are not supported, and the evidence gap must be recorded.

2. Input the waybill number range "SF3100001 to SF3100040" for full-text retrieval. Compare whether the returned content contains that number range text. If the return is an empty array, use the paper input [] to check the downstream design. Do not claim that a fictional rule must return an empty result.

3. Input a request to associate a cross-vector-model knowledge base combination. Compare the vector model identifiers of the two bases. When the identifiers differ, exclude the combination and record it. Do not continue to infer any runtime result of the combined association.

A pending review does not demonstrate a lack of operating permission. Signing, reaching cooperation, and contract effectiveness are three separate facts. Retrieval and forms collect values; business verification, approval, database writes, and external synchronization each need their own downstream implementation.
