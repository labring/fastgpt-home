# Complaints and official replies: document comparison with tool calls

## What the documents look like

For document comparison in Complaints and official replies, this page examines FastGPT tool calls. Complaints, inquiries and rectification replies retain their source status. Comparing supplied material does not independently determine responsibility or acceptance by an external authority. The examples are hypothetical.

## Constraints at the tool calls step

Complaint-source comparison can read claims, inquiry scope and order evidence without legal reply requirements. Proposed input supplies a complaint and draft response, not actual external handling. Limit a tool to these passages, retaining case, order and provider. Claims are not verified facts, and report titles establish neither correction nor resolved disputes or decision-making capability.

## Configuration and implementation checks

| Transaction-comparison check | Proposed material | Actual evidence |
| --- | --- | --- |
| Case and order | Complaint and corresponding evidence | Other case not borrowed |
| Statement status | Claim separate from actual inspection | Not promoted to fact |
| Reply stage | Draft separate from external handling | Obtain current actual response |
| Tool scope | Supplied passages and request | No presumed decision capability |
| Formal submission | Separate closure, writing and sending | Comparison is not external acceptance |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Tool description` | Describe purpose, inputs and non-applicable situations. |
| `Tool parameters` | Inspect module and plugin parameters separately. |
| `Required parameters` | The model may not invoke a tool without suitable required inputs. |
| `Tool connections` | Available tools must connect to the calling module. |
| `Tool-call termination` | Termination ends the call without a later AI summary. |

## Three common errors

Another order’s evidence needs case correspondence checks. Complaint wording treated as verified needs original business or inspection sources. A draft reply described as accepted needs this actual external response. These concern subject, evidence status and stage, none supplied by one call.

## How to verify the setup

Inspect requests, invoked tools and citations. Repeat with this case’s evidence and retain traceable differences. Missing suitable required input may prevent invocation; collect it through interaction and inspect requests with a small tool set. Termination prevents another AI summary. External submission, closure and writes require authority and receipts. Comparison establishes neither responsibility, external acceptance nor satisfied legal requirements.
