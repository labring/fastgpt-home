# Complaints and official replies: access controls for document comparison

## What the documents look like

Complaint and regulatory-reply work centers on four document types: complaint tickets, regulatory inquiry letters, order evidence, and rectification reports. Sources include the 12315 platform, platform complaint centers, customer-service chat, and the order system. Updates are irregular and case-by-case.

Unlike after-sales repair or reshipment work, complaint and reporting matters are addressed to a platform or a regulatory authority, so the response text and the evidence package carry formal weight. Errors can lead to administrative investigation, platform penalties, or brand exposure.

For contract and transaction material comparison, one case may require reading contract clauses, transaction records, and a draft reply together. Access scope is usually divided by case or ticket, so different members of the same shop may not see the same order evidence or rectification wording.

## Constraints at the access controls step

Knowledge-base permission is a threshold. Collection-level permission cannot bypass knowledge-base permission. A user still needs read permission on the knowledge base to reach a file, even when that file has been separately authorized.

Collection-level permission is off by default. In the off state, collection readability matches the knowledge base exactly; the system does not query any collection permission records. When enabled, each file or folder generates a full permission snapshot, and list, detail, and retrieval recall are each checked against that snapshot.

Retrieval recall filtering applies only when authentication runs as the current member identity. A workflow that preselects a knowledge base without member-identity authentication does not perform file-level filtering and still recalls by knowledge-base permission. Team administrators do not bypass collection-level permission. Team owners and system root are treated as having full permission on all files. Relevance scoring does not carry permission or entity-isolation duties.

Hypothetical paper exercise sample. A shop customer-service supervisor organizes one complaint ticket. The source text reads: "Ticket number TS-0001. The complainant placed an order on 5 March 2024, order number A100, product: insulated cup, complaint: lid leaks. Customer service replied on 7 March 2024 agreeing to reship the lid, reshipment number B200." One draft sentence awaits judgment: "This shop completed the reshipment on 7 March 2024, and the complainant has confirmed receipt." Authorization boundary: the supervisor holds manage permission on the knowledge base, collection-level permission is enabled, and the operations assistant holds only use permission on the knowledge base with no read permission granted on this ticket file.

## Configuration and implementation checks

| Configuration item | Setting relevant to this page | How to check |
| --- | --- | --- |
| Knowledge-base permission | Supervisor holds manage; operations assistant holds use | Check the knowledge-base collaborator list against actual member identity |
| Collection-level permission switch | Enabled for this knowledge base; enabling materializes snapshots for all files | Read the enable notice and close entry in the knowledge-base information bar |
| Ticket file collaborators | Supervisor is administrator; operations assistant is not listed | Open the ticket file's right panel and read the collaborator list |
| Retrieval recall scope | Files beyond authorization are filtered when authentication runs as current member identity | Search the same keyword with both accounts and record visible files |
| Creator record | The submitted collaborator list must contain the current creator | Compare the file creator field with the submitted list |
| Hypothetical trial starting point | Search "lid leaks" with the operations assistant account; the ticket file is expected not to be returned | Compare against the supervisor account's result and record the difference |

## Three common errors

1. Treating retrieval relevance as permission filtering. With the collection-level permission switch off, searching ticket content with the operations assistant account does not query collection permission records, so the file may be returned. That outcome does not show the permission configuration is correct.

2. Treating team administrator identity as a bypass of collection-level permission. Team administrators do not bypass collection-level permission. Concluding from a team management role alone that all ticket files are visible does not match the documented authentication logic.

3. Treating a draft sentence as a completed fact. The draft states the reshipment is complete and the complainant confirmed receipt. The source text shows only that customer service agreed to reship and gave a reshipment number. The confirmation of receipt is not stated there, so the draft claim is unsupported.

## How to verify the setup

1. Input the supervisor account and the operations assistant account, then compare visibility of the ticket file inside the same knowledge base. The supervisor can view the file list and detail. With collection-level permission enabled and no read permission granted, the operations assistant cannot see the file, and the list is filtered item by item by what the current member can read.

2. Input the draft sentence and the source text, then compare the two states "reshipment completed" and "agreed to reship." The source text supports only the agreement to reship. The completed state in the draft is unsupported and would need a reshipment receipt record before it can be checked.

3. Input a search for "lid leaks" with the operations assistant account and observe the returned result. If the ticket file is returned, authentication did not filter as expected or collection-level permission is not enabled. If the result is empty, record that observation without inferring that a fictional rule must return empty.

A paper input of an empty list can be used to check downstream design. An empty result does not by itself confirm that retrieval under a fictional rule returns an empty list. Cross-model libraries cannot be jointly associated; check identifiers first and exclude non-matching items, then record actual observations rather than predicting recall behavior. Pending review does not show that an operation permission is missing. Signing, reaching cooperation, and contract effectiveness are three distinct facts. A quotation validity period does not indicate a supply period. Where the source text does not state a field, that field remains unknown, and the evidence gap is preserved.
