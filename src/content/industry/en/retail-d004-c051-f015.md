# Douyin storefront operations: retrieval for document comparison

## What the documents look like

Douyin storefront shelf operations center on product cards and store experience scores. The materials handled day to day include product qualification pages, experience score detail records, shipping violation appeals, and store announcements. These materials update daily or per order. Contract and transaction material comparison works on the licensed scope recorded in a qualification page, the penalty records in an experience score detail, the handling status in an appeal, and the effective wording in an announcement. The retrieval step needs to place the same field of the same subject side by side for checking.

Material states differ clearly. A qualification page may sit at pending review, an appeal may sit at submitted and awaiting handling, and an announcement may sit at draft. Text returned by retrieval only shows that a record was recalled. It does not show that a review passed, that an appeal was upheld, or that an announcement took effect.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Bases using different vector models cannot be associated together. When vector model identifiers do not match, check the identifiers first, exclude the non-matching base, and record the actual observation. Do not run a cross-model retrieval to compare missed recalls.

Search modes include semantic retrieval, full-text retrieval, and hybrid retrieval. Semantic retrieval computes similarity by vector distance and suits natural language questions. Full-text retrieval relies on keyword hits and suits numbers, model codes, and proper nouns. Hybrid retrieval uses both paths at once and merges them through RRF. RRF is a fusion process for mixed results, not a switch that can be turned on. Reranking requires a ReRank model and must be enabled through settings; the rerank score runs from 0 to 1. The minimum relevance value takes effect only under semantic retrieval or when result reranking is used. It is a filter threshold and does not perform permission or entity isolation.

The reference cap is measured in tokens. Output reference content is given as an array and its length can be 0. When nothing is found, the output path still runs through. Question optimization performs coreference resolution and question expansion and adds one model call before formal retrieval.

Hypothetical drill sample: a Douyin store merchant submits a qualification page for one product with the original text "Subject: Merchant A; Object: one model of insulated cup; Status is pending review; Licensed scope: food-contact use." The store announcement for the same shop reads "Subject: Merchant A; Object: one model of insulated cup; Effective date: March 1, 2025; Content: this product already holds food-contact sales qualification." The draft sentence reads "Merchant A's food-contact sales qualification for this insulated cup has passed review and taken effect."

## Configuration and implementation checks

| Configuration item | Setting on this page | Basis and checking method |
| --- | --- | --- |
| Associated knowledge bases | Associate only qualification page, experience score detail, appeal, and announcement bases whose vector model identifiers match | Check vector model identifiers one by one; exclude any base whose identifier does not match |
| Search mode | Starting point for this hypothetical trial is hybrid retrieval | Compare full-text hits for qualification-number questions and semantic hits for natural language questions |
| Reference cap | Starting point for this hypothetical trial is 2000 tokens | Chosen from the length differences among materials; compare against a shorter cap to see whether content stays complete |
| Minimum relevance | Starting point for this hypothetical trial is 0.4 | Label relevant and irrelevant samples first, then compare filtering results against adjacent values |
| Question optimization | Enable for multi-turn follow-ups and short questions | Compare the original question with the optimized question and check whether the subject was altered |
| Result reranking | Enable when candidates are many and a ReRank model is available | Compare ordering before and after reranking and check against the 0-1 score |

## Three common errors

1. Treating a retrieval recall as an authorization conclusion. The draft sentence says "has passed review and taken effect," while the qualification page says only "pending review" and the announcement gives only an effective date. The input is the two original passages above plus the draft sentence. Compare the value of the "Status" field under the same subject and same object. The qualification page value "pending review" and the draft sentence value "passed review" are mutually exclusive on the same field, so the judgment is not supported. A retrieval hit does not change this conclusion.
2. Treating a quotation validity period as a supply term. When the material states only a quotation validity period, the supply term is not recorded and remains an evidence gap. A supply obligation cannot be judged as established or as absent from this.
3. Forcing association of bases with different vector models. The input is the vector model identifiers of two bases. Compare whether the identifiers match. When they do not match, exclude the base and record the actual observation. Do not assert a runtime result after association.

## How to verify the setup

1. Input the qualification page original text, the announcement original text, and the draft sentence from the hypothetical sample. Compare the value of the "Status" field under the same subject, same object, and same field. When the qualification page reads "pending review" and the draft sentence reads "passed review," the judgment is not supported. Also record that the announcement states only an effective date and no review conclusion. If retrieval does not return the qualification page, record a recall gap and do not judge the draft sentence as established.
2. Input a material original text that contains only a quotation validity period and a draft sentence asking about the supply term. Compare whether the draft sentence contains a supply term statement. When the material does not record that field, judge it as pending verification, not as a denial or a conflict.
3. Input the vector model identifiers of two knowledge bases. Compare whether the identifiers match. When they do not match, exclude that base and record it. Input an explicit paper-based empty result [] and check how the downstream design handles an empty reference. Do not claim that a fictional rule retrieval necessarily returns [].

Signing, reaching cooperation, and contract effectiveness are three distinct facts. Pending review, awaiting handling, and draft do not amount to completed approval. Retrieval and forms collect values; business verification, approval, database writes, and external synchronization each need their own downstream implementation.
