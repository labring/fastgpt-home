# Channel diversion reviews: workflow routing for document comparison

## What the documents look like

Channel diversion reviews address regional and price order. They do not address rebate amounts, which belong to rebate accounting. The material set for this category comes from anti-counterfeit code systems, e-commerce platform prices, distributor shipment records, and market inspections. Day-to-day documents include diversion complaint forms, anti-counterfeit code records, penalty notices, and investigation photographs. Updates arrive weekly and irregularly.

For contract and transaction material comparison, three facts shape the work. First, the complaint form, code records, shipment records, and photographs are separate documents that must be matched on the same subject, the same period, and the same field before any conclusion holds. Second, a code scan outside the expected region is stage evidence; it does not by itself state that a cross-region shipment occurred. Third, penalty notices are drafted documents whose authority depends on approval records that sit outside the comparison itself. The weekly and irregular update pattern does not justify inferring batch synchronization, full synchronization, real-time processing, or transaction-triggered mechanisms for this page.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. The node collects required information the user submits and passes that information to later nodes. The User Selection node is also a user interaction node. When it triggers, the conversation enters an interaction state and the workflow state is recorded. When the user makes a selection, the node evaluates that selection and executes the corresponding branch.

Both nodes record workflow state as part of their documented behavior. No separate global state-recording switch is described. Form collection and retrieval gather values; they do not constitute authorization. Order writes, document backfill, and external status synchronization require a separate business interface or a later process.

Assumed paper exercise sample: a brand channel control party receives diversion complaint form XC-2024-0317. The form states that complained-about distributor A shipped 200 units outside the East China region on 5 March 2024. An attached anti-counterfeit code record shows that 50 of those units were scanned in South China. A draft penalty notice also arrives, containing the sentence "A is confirmed to have committed cross-region diversion and shall have the security deposit deducted." The authorization boundary is: the regional manager holds investigation authority only; penalties require approval by the channel control lead. The item to be judged is whether the draft sentence "confirmed to have committed cross-region diversion" is supported by the available material.

## Configuration and implementation checks

| Configuration item | Value or check for this page | Basis and comparison method |
| --- | --- | --- |
| Form Input node | Collect complaint number, complained-about party, shipment date, quantity | Node collects required information and passes it to later nodes |
| User Selection node | Set a "materials complete" branch | Node executes the corresponding branch after user selection |
| Interaction state check | Trigger enters interaction state and records state | Documented node behavior |
| Output handoff check | Pass form values to the comparison node | Compare each output item against its input item |
| Penalty execution split | Penalty action connects to a separate approval interface | Form submission does not constitute authorization to execute |
| Retrieval scope check | Retrieve only within target scope with access rights | Retrieval does not perform permission isolation |

## Three common errors

1. Treating form submission as penalty authorization. The form collects values only. A penalty requires approval by the channel control lead. These are two different facts, and the draft penalty notice is not an executed penalty.

2. Writing an out-of-region code scan directly as "confirmed cross-region diversion." An out-of-region scan is stage evidence. It becomes usable only after comparison with shipment records and the complaint form on the same subject and the same period.

3. Treating a User Selection branch as an automatic determination. The User Selection node executes a branch based on user feedback. It does not generate a diversion conclusion on its own.

## How to verify the setup

1. Input the complaint form text above and the draft sentence. Compare "confirmed to have committed cross-region diversion" against the shipment and scan facts the material records. If the material shows only an out-of-region scan and does not state a cross-region shipment, the determination is not supported and is recorded as pending verification.

2. Input the form field values and the values the comparison node receives. Compare whether the two sets match item by item. If the shipment date collected by the form is not passed into the comparison node, the output handoff is incomplete.

3. Input the penalty request. Compare whether it carries an approval record from the channel control lead. If no approval record is present, the penalty remains pending approval and must not be executed.

For the retrieval scope check, observe which records the retrieval returns within the authorized target scope, and record the failure branch when the returned set does not contain the needed material. An empty result can be handled by feeding an explicit paper input of [] into the downstream design and checking how that design responds; this does not assert that any rule-based retrieval returns []. Where libraries use different vector models, they cannot be jointly associated. Check identifiers first, exclude non-matching items, and record what is actually observed rather than predicting missed recall or redundant returns.
