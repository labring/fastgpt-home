# Near-expiry markdowns: document comparison with workflow routing

## What the documents look like

For document comparison in Near-expiry markdowns, this page examines FastGPT workflow routing. A near-expiry list, a disposal approval and a spoilage record describe different events. The workflow preserves their batch and handling relationships. The examples are hypothetical.

## Constraints at the workflow routing step

A proposed list names yogurt batch A. Handling wording permits a display adjustment, while a spoilage excerpt concerns batch B. Collect the item, batch and actual handling passages, then let a person request A’s evidence or inspect B’s spoilage source. No prices or discount rates are supplied, and display adjustment does not establish sale eligibility. Preserve each document’s batch downstream; a matching product name does not make these one disposal event.

## Three common errors

Mixed batches: B’s spoilage applied to A needs list and spoilage batch passages. Expanded approval: Display adjustment rewritten as unrestricted disposal needs the approved scope beside transmitted wording. Record promoted to completion: A spoilage request described as a stock deduction needs this batch’s actual inventory outcome. These inspect subject, scope and execution separately.

## How to verify the setup

Start with A’s list and follow the option for A’s evidence. Inspect whether the downstream recipient still recognizes that B’s spoilage cannot support A. After adding A’s actual record, change only the supported handling interpretation without erasing batch boundaries. Sale handling, inventory changes and spoilage approval need actual business records in subsequent steps. A selected next action and continued node execution establish neither sale eligibility nor completed disposal.
