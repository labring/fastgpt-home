# Fresh-food supplier claims: citation tracing for document comparison

## What the documents look like

Fresh-food supplier claims pursue responsibility for quality problems found on arrival. They do not cover natural in-store shrinkage, so the working materials cluster around batch-level quality exceptions. The main data comes from the quality inspection system, WMS receiving, supplier contracts and financial reconciliation. Day-to-day documents include quality exception notices, photo evidence, deduction notices and claim reconciliation statements. The most time-consuming steps are securing evidence, calculating deductions, and negotiating replacement or compensation. Data updates per batch and per month; this page does not cover bulk synchronization or transaction-triggered mechanisms.

These traits bear directly on citation tracing. The inspection conclusion, receiving record and contract clause for one batch must be able to point at each other, and a deduction amount must trace back to a specific exception notice and reconciliation record. The retrieval step only brings candidate source text forward. It does not decide whether evidence is sufficient or whether a deduction is valid.

## Constraints at the citation tracing step

Knowledge base search can select one or more knowledge bases that share the same vector model. It outputs cited content as an array whose length may be zero, and an empty array still completes the output path. The citation limit is controlled by tokens. The minimum relevance value takes effect only under semantic retrieval or result reranking. Hybrid retrieval merges multiple result paths through RRF, and reranking requires a model and runs according to its setting. Image retrieval requires image input and matching model capability.

Retrieval does not carry authorization. A similarity score is not a permission or entity filter, and it cannot be used to exclude unrelated suppliers or unauthorized records. Knowledge bases built on different vector models cannot be associated together. The vector model identifier should be checked first and non-matching bases excluded, then the actual observation recorded, without running a cross-model search to compare missed recalls.

Hypothetical exercise sample (paper materials, not real records):

Material one, quality exception notice text: "On 10 March 2025, batch A-0310, broccoli on arrival, sampling found leaf yellowing at roughly 12%, the receiver marked it as failed, and payment for the batch was temporarily withheld."

Material two, supplier contract text: "Where goods delivered by Party B fail Party A's acceptance inspection, Party A may temporarily withhold payment for the corresponding batch and initiate a deduction after both parties confirm the quality exception notice."

Material three, claim reconciliation statement text: "Batch A-0310, deduction notice not yet issued, supplier business proposed replacement, replacement quantity still under negotiation."

Draft sentence to be judged: "The batch deduction has been completed and the supplier has agreed to replacement."

Points to check: whether the contract clause covers this batch, whether the exception notice has been confirmed, whether the deduction notice has been issued, and whether replacement has been agreed. The draft sentence turns a temporary withholding and an ongoing negotiation into completed facts. It lacks evidence of a deduction notice and of a negotiation outcome, so it should be judged unsupported.

## Configuration and implementation checks

| Configuration or check item | Hypothetical starting point for this exercise | Reason for the choice and comparison object |
| --- | --- | --- |
| Associated knowledge bases | Contract base, inspection base, reconciliation base | All three must share the same vector model; compare against bases on a different model and exclude non-matching ones |
| Search mode | Hybrid retrieval | Batch numbers and clause numbers need exact hits, and semantically close content also needs recall |
| Citation limit | Hypothetical starting point of 3000 tokens | Compare against the combined length of the exception notice, contract and reconciliation excerpts to avoid truncating key clauses |
| Minimum relevance | Hypothetical starting point of 0.3 | Compare against the rerank score; takes effect only under semantic retrieval or reranking |
| Result reranking | Enabled | Second-pass ordering when candidates are numerous; a rerank model must already be available |
| Citation handoff | Check source text item by item | Check whether retrieval output is passed to the answering step, and compare the answer against the cited source text |

## Three common errors

1. Treating a retrieval score as an authorization filter. The input is a replacement request raised by supplier business, the comparison object is the cited array returned by retrieval, and the observable result is whether that array contains materials for that supplier and batch. A high or low score does not mean the request has been approved, and does not mean the record has been authorized for access.
2. Treating a temporary withholding as a completed deduction. The input is the quality exception notice and the contract clause, the comparison object is whether the deduction notice has been issued and whether the supplier has confirmed, and the observable result is that a missing notice or an unfinished negotiation should be recorded as pending verification, not written as a completed deduction.
3. Forcing an association across knowledge bases on different vector models. The input is two knowledge bases with different vector model identifiers, the comparison object is whether the identifiers match, and the observable result is that a mismatch means exclusion, with no further search run and no inference about missed recalls or redundant results.

## How to verify the setup

1. Test with the three source texts and the draft sentence from the hypothetical exercise sample. The input is material one, material two, material three and the draft sentence. Compare "deduction has been completed" and "has agreed to replacement" in the draft against "temporarily withheld", "not yet issued" and "still under negotiation" in the source texts. The observable result is that the draft sentence is marked unsupported and the citations point to specific materials.
2. Test empty-result handoff. The input is an explicit paper citation array `[]`. Compare whether the downstream answering step still completes. The observable result is that the chain is not interrupted, and no claim is made that a fabricated rule search must return an empty array.
3. Test material version currency. The input is the current and a historical version of a contract clause. Compare the version the citation points to against its effective scope. The observable result is that the citation can distinguish versions. Whether the clause is adopted still depends on review of the effective version, and a retrieval hit is not treated as the clause being in force.

This page addresses only fresh-food supplier claims, contract and transaction material comparison, and citation tracing. Which materials, operations and requests sit in which authorization state during an operational handover cannot be settled by retrieval or by a form. Retrieval checks record observations and failure branches; they do not guarantee a first-position hit, full recall, or that an unrelated query must be empty.
