# Fresh-food supplier claims: document chunking for document comparison

## What the documents look like

Fresh-food supplier claims pursue quality liability for goods at arrival. Store-level natural shrinkage falls outside this scope. That boundary shapes which materials matter: quality exception forms, photo evidence, deduction notices and claim reconciliation statements. The primary data sources are the quality inspection system, WMS receiving records, supplier contracts and financial reconciliation. Inspection records and receiving records point to the same batch. Contract clauses govern deduction and replenishment liability. Reconciliation statements show the confirmation state between the two parties. These materials act as evidence during claim negotiation, so parsing and chunking need to preserve the correspondence among batch, party, date and amount, and retrieval results must be traceable to the original material.

Material structures differ in kind. A quality exception form carries a batch number and an inspection conclusion. Photo evidence depends on an image index created at ingestion time. Deduction notices and reconciliation statements carry amounts and confirmation states. Chunking must keep conditions, conclusions and the objects they constrain inside the same segment, so that an inspection conclusion and its batch number are not split apart. Raw data and retrieval indexes are stored separately, and one group of raw data can map to multiple indexes. Retrieval is a recall process. It does not perform authorization checks and does not confirm whether a material has been approved. After a material changes, successful upload and completed index training are two separate events and must be checked separately.

Hypothetical paper test case: the source text reads, "Quality exception form QA-2405-017: batch A240517, arrival date 17 May, inspection conclusion is that the wilting ratio of leafy vegetables exceeds the limit, deduction determined." "Supplier contract clause 4.2: when the wilting ratio of leafy vegetables at arrival exceeds the agreed limit, a deduction applies at the agreed proportion of the accepted amount for that batch." "Deduction notice D-2405-017: batch A240517, deduction amount pending supplier confirmation, status pending confirmation." The draft sentence to be assessed is: "The deduction for batch A240517 has received supplier confirmation and can be executed." This draft sentence conflicts with the status recorded in the deduction notice.

## Constraints at the document chunking step

The batch number is the linking key across the quality exception form, the contract clause and the deduction notice. If a chunk separates the batch number from the inspection conclusion, a query on batch A240517 may return a conclusion that belongs to a different batch, or return the contract clause without the specific batch it constrains. The same applies to amounts and confirmation states on deduction notices and reconciliation statements.

Photo evidence adds a separate dependency. Whether a photo can be retrieved depends on whether an image index was created when the material was ingested, not only on whether the photo was uploaded at query time. A visual model or an image-capable vector model affects which retrieval paths are available; without either, a pure image query is largely unusable. This is a documented condition, not a configuration choice that can be assumed.

The draft sentence in the hypothetical case illustrates the core risk. The deduction notice records status "pending confirmation." The draft sentence asserts that supplier confirmation has been received. The two statements concern the same subject, the same batch and the same field, and the field values are mutually exclusive. The draft sentence is unsupported by the source material. A pending confirmation is not an approval. An offered option is not an execution. An unsigned termination is not a completed termination.

Retrieval results are not authorization. A contract clause returned by a search does not carry an approval state and cannot support an execution conclusion. A relevance score is a similarity measure; it is not a category filter, an entity filter or a permission filter, and it does not exclude unrelated businesses or unauthorized records. Whether a downstream system treats an empty reference result as "no relevant material" depends on that system's design, which must be checked rather than assumed.

## Three common errors

1. Treating a "pending confirmation" status on a deduction notice as confirmed. Input: deduction notice D-2405-017 and the draft sentence. Compare the status field value against the draft sentence. Observable result: the draft sentence's assertion of supplier confirmation does not match the recorded status, and the draft sentence is unsupported.

2. Treating a retrieval result as an authorization basis. Input: a contract clause returned by one retrieval. Compare it against the authorization record. Observable result: the retrieval result carries no approval state and cannot support an execution conclusion.

3. Treating successful upload as completed index update. Input: the upload record of a changed material. Compare the upload time against the actual training record. Observable result: the training status is unknown and requires separate verification.

## How to verify the setup

1. Input the three source sentences and the draft sentence from the hypothetical sample. Compare the draft sentence's statement "has received supplier confirmation" against the deduction notice's recorded status "pending confirmation." The condition is met when the two are inconsistent and the draft sentence is unsupported.

2. Input batch number A240517 and a natural-language question separately. Compare whether the returned content includes the quality exception form and the contract clause. The condition is met when the segmentation preserves the correspondence between batch and conclusion.

3. Input an empty reference result using the explicit paper input `[]`. Check the downstream design for handling no-recall content. The condition is met when the downstream behavior for an empty result is identified; do not infer that a fictional rule necessarily returns an empty set.
