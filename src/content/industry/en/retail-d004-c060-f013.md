# Fruit-store procurement: access controls for document comparison

## What the documents look like

Fruit-store procurement comparison work centers on four material types: purchase orders, receiving records, pesticide-residue test reports, and loss records. Wholesale-market pricing and grade-based acceptance mean that the price and quantity for one batch can differ across inquiry, order placement, and arrival. Comparison therefore has to lock the subject and the period to a single batch. The brief gives a daily or per-batch update frequency. This page does not derive any batch-sync, full-sync, real-time, or transaction-triggered mechanism from that frequency, and where the frequency does not affect the access-control step it is left out.

Two features of this category shape the access-control task. First, documents for one batch come from different hands: a buyer, a store fresh-produce supervisor, a market stall, and a quality-inspection role may each hold a different part. Second, the same batch can carry conflicting values across documents, so a comparison result depends on which records a given member is allowed to read. Permissions decide what enters the comparison, and missing permission looks the same as a missing record unless the two are separated.

## Constraints at the access controls step

Permission judgment checks a member's individual permission first, then takes the union of department and group permissions. Individual member permission overrides a whole-team group permission. A dataset permission is always a threshold: a collection permission cannot bypass it. For a file to be viewed, the member needs the dataset read permission plus that file's read permission, and lists are filtered per member item by item, with unreadable files not occupying a slot and pagination remaining correct.

File-level permission is a commercial-edition feature and is off by default. In the off state, collection readability matches the dataset exactly and no collection permission records are queried. When it is on, each file or folder has a full permission snapshot, and list, detail, and retrieval recall are authenticated against that snapshot. Turning the switch on is the only entry point that produces collection-level custom permissions; while it is off, any write that configures a single file's permission is rejected with a prompt to enable it first. Materialization runs synchronously inside the request, and the switch is set only after materialization succeeds; on failure the switch stays off and the operation can be rerun. Turning it off deletes all collaborator configurations under that dataset and restores inheritance, and this cannot be reversed.

Collaborator configuration uses full-overwrite semantics: the submitted list is the final result, and the submitted list must contain the current creator or it is rejected. Creator status cannot be granted or changed through collaborator configuration. Deletion is limited to the creator; a member with admin or write permission cannot delete. The team administrator role does not bypass file-level permissions; team-level management covers team resources only. The system root and the team owner are treated as holding all permissions on all files.

Retrieval after enabling file-level permission filters by files the current member can read, and unauthorized files are not recalled. This applies only when authentication is by current member identity. A workflow that preselects a dataset without member-identity authentication does not do file-level filtering and recalls by dataset permission. A relevance score is not a permission, category, entity, or authorization filter. Retrieval is not authorization. Datasets using different vector models cannot be associated with each other; identifiers must be checked first and non-matching items excluded.

## Configuration and implementation checks

The sample below is a hypothetical paper exercise, not a record of anything tested or deployed. Hypothetical source text: "Purchase order SC-0417 states that on 17 April, 200 boxes of mandarin oranges were purchased from stall A at a unit price of 32 yuan; receiving record YS-0417 states that 186 boxes were actually received the same day, of which 12 boxes were downgraded for compression damage; pesticide-residue test report JC-0417 states that the batch passed sampling inspection, issued 18 April." The proposed sentence to judge is: "All 200 boxes of this batch were settled at 32 yuan." The values in the table are hypothetical starting points for this exercise, not official defaults.

| Configuration item | Hypothetical starting point | Comparison object and reason |
| --- | --- | --- |
| Dataset file-level permission switch | On | Compare with the off state to confirm the switch is set only after snapshot materialization succeeds |
| Purchase-order collection collaborators | Buyer read permission, fresh-produce supervisor admin | Compare with the team administrator identity to confirm no automatic bypass |
| Receiving-record collection collaborators | Store fresh-produce supervisor admin | Compare with the creator record to confirm full overwrite did not remove the creator |
| Test-report collection collaborators | Quality-inspection role read permission | Compare with the dataset read permission to confirm the threshold still applies |
| Loss-record collection collaborators | Store fresh-produce supervisor write permission | Compare with admin permission to confirm deletion is limited to the creator |
| Retrieval authentication mode | By current member identity | Compare with the preselected-dataset unauthenticated scenario |

## Three common errors

1. Treating the retrieval relevance score as a permission filter, on the assumption that a higher similarity setting excludes files the member cannot read. Unauthorized files are excluded by snapshot authentication, and the similarity setting is not involved. The input to check is the retrieval configuration and the member identity; the comparison is between the returned items and the snapshot; the observable result is whether an unauthorized file appears.
2. Treating the team administrator identity as a bypass condition for file-level permission. Team-level management covers team resources only, and datasets and files are still authenticated by their collaborator configuration. The input is the member's team role and the file's collaborator list; the comparison is between that role and the file permission; the observable result is whether the file is visible to that member.
3. Treating a pending review or an issued quotation as already authorized or already effective. A quotation validity period does not state a supply period, and signing, reaching cooperation, and contract effectiveness are three separate facts. The input is the document status text; the comparison is across those three facts; the observable result is which fact the document actually supports, with the rest left as a gap.

## How to verify the setup

1. Input the proposed sentence together with the purchase-order and receiving-record text above, and compare the 200-box figure with the 186 boxes received and the 12 downgraded boxes. A contradiction requires mutually exclusive values for the same field, the same subject, and the same period. The batch's settlement unit price for downgraded boxes is not stated, so that field is unsupported and the gap is recorded.
2. Use an account with purchase-order read permission and an account without it to search the same batch number, then compare the returned entries. The condition is met when the permitted account can see the purchase order, the unpermitted account cannot, unreadable items do not occupy a slot, and pagination remains correct. If the unpermitted account sees the purchase order, the file-level permission or the dataset threshold is not in effect for that member.
3. Use a paper input of an empty result list to check the downstream design, and compare whether the system handles it as an empty set. This page does not claim that a query against a fictional rule necessarily returns an empty list; only the actually observed return content is recorded. Where the material needed for verification lies outside the target retrieval scope the member can access, or is absent from a defined manual input, the gap is recorded rather than filled.
