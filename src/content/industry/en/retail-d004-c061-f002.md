# Fresh-food weighing and sorting: context limits for document comparison

## What the documents look like

Fresh-food weighing and sorting happens inside the warehouse fulfilment stage. The central facts are weight and specification, and the working materials are the sorting task sheet, the weighing label, the short-weight compensation form and the quality inspection record. These materials update per order and per day, so a comparison run has to place the weighing value, the specification text and the compensation status of one order inside the same context.

The comparison task reads several short materials at once. Context length decides whether the task sheet, the label and the compensation form fit together in one request. The reply cap controls how long a single answer may be. The knowledge-base citation cap controls how many tokens one search may cite. Together these settings decide whether a comparison conclusion can keep enough supporting detail and handling action.

Materials are short but numerous. A low citation cap can trim a single segment, so a subject or a status disappears from the request. Historical input changes what the same question retrieves when history is empty and when history is present, and both conditions need separate checking. A structured hand-off requires complete fields, and checking text length alone does not confirm that parsing succeeded. Semantic recall and relevance scores carry no permission or entity-isolation duty, and the requirement that a search library use one vector model does not extend to external systems using the same model. RRF is a fusion step over mixed result paths, not a switch that can be turned on. A thinking budget is a reasoning budget and cannot be moved into the citation token cap.

## Constraints at the context limits step

A hypothetical paper exercise sample follows. The materials supplied for comparison read: "Sorting task sheet A-0715 records order Jia, specification 500g±20g, quantity 2 pieces, sorter Yi, date 2025-07-15. Weighing label A-0715-1 records actual weight 486g, labelling time 2025-07-15 09:12. Short-weight compensation form A-0715-C records order Jia, compensation quantity 1 piece, status pending review, submission time 2025-07-15 10:00." The draft sentence awaiting judgment reads: "Order Jia has completed the short-weight compensation, and the compensation form has taken effect."

This sentence writes a pending-review status as already effective. That is an unsupported judgment. The status field in form A-0715-C says pending review, and the draft sentence says the compensation is complete and effective, so the two do not agree on the same field of the same subject.

The citation cap is set in tokens, and a low value can cut a segment before its subject or status arrives. A reply cap is a separate setting from the model context window, and treating one as the other produces a wrong reading of how much material fits. The knowledge-base citation cap limits cited content per search; it does not grant permission to read a record and does not isolate one business from another. A relevance score is a filter threshold over returned segments, not a category, entity or permission filter. Retrieval is not authorization. Whether a compensation form may be acted on depends on a downstream approval step, and a form that collects values does not by itself write to a database or synchronize to an external system. No scheduled trigger or hidden control is assumed here.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | Reason for the choice and comparison method |
| --- | --- | --- |
| Citation cap | Hypothetical start 2000 tokens | The three materials total roughly 150 characters, so 2000 tokens should hold them; compare against the actual token count of the materials and observe whether trimming appears |
| Minimum relevance | Hypothetical start 0.3 | Used to filter low-relevance segments; compare against the scores of returned segments and observe whether unrelated segments are excluded |
| Reply cap | Hypothetical start 500 tokens | Must hold the supporting detail and the handling action; compare against the actual length of the draft sentence plus its grounds |
| Memory turns | Hypothetical start 2 turns | The comparison task is usually single-turn, and a small history supports checking follow-up questions; compare against results with empty history |
| Reply format | json_schema | Fixed fields are needed to carry the comparison conclusion; after parsing, check whether the fields are complete |
| Question optimization | Enabled | Material names contain identifiers, and optimization can fill in references; compare against retrieval results with the setting off |

These numbers are hypothetical starting points for this exercise and do not come from official defaults. The citation cap uses tokens as its documented unit and does not use top k. Image retrieval requires image input and model capability, and reranking requires a model and must be enabled in the settings. The optional paths shown in the overall document flow diagram do not mean every request executes all of them.

## Three common errors

1. Writing a pending-review status as already effective. The input is the status field "pending review" in short-weight compensation form A-0715-C. The comparison object is the draft sentence "has completed the short-weight compensation, and the compensation form has taken effect." The observable result is that the status field and the draft sentence disagree, so the judgment is unsupported.

2. Treating the reply cap as the full context window. The input is the documented maximum context of the model. The comparison object is the reply cap setting value. The observable result is that the two values differ, so the two settings have been confused.

3. Using a relevance score to exclude unrelated businesses. The input is the minimum relevance setting. The comparison object is the business ownership of returned segments. The observable result is that the score carries no permission filtering, so the attribution is wrong.

## How to verify the setup

1. Input the three material texts from the hypothetical sample above together with the draft sentence. Compare the compensation status in the draft sentence against the status field of short-weight compensation form A-0715-C. The condition is met when the draft sentence is marked unsupported. This is an expected outcome, not a recorded test result.

2. Input the same question with empty history and with 2 turns of history. Compare the cited content returned by the two retrieval runs. The condition is met when the cited content differs; record the difference and check the effect of the context. This is an expected outcome, not a recorded test result.

3. Input a clearly written empty result `[]` together with the downstream hand-off design. Compare whether the downstream step treats the empty result as empty. The condition is met when the downstream step does not treat the empty result as having content. Libraries built on different vector models cannot be associated together; check the identifier first, exclude those that do not match, and record the actual observation. This is an expected outcome, not a recorded test result.

This page covers one task only: fresh-food weighing and sorting, contract and transaction material comparison, context and tokens. During operational hand-off, the authorization state of materials, operations and requests is a separate matter, and retrieval or a form must not be treated as authorization to execute.
