# Livestream sample inspections: context limits for document comparison

## What the documents look like

Sample inspection for livestream commerce happens before a broadcast. The decision is whether a product can be sold and whether it suits on-camera demonstration. The working materials are supplier profiles, testing-agency reports, platform negative catalogs, and historical return rates. Day to day, the team handles sample evaluation forms, quality inspection reports, supplier qualifications, and prohibited-item lists. Contract and transaction material comparison checks the subject, object, status, and validity scope recorded in those materials.

Material updates run weekly or per item. This page does not depend on that cadence; retrieval and comparison operate on the materials already present.

Comparison input combines source material text and a draft sentence awaiting judgment. Both occupy model context. The maximum context a model can reference in a single request is set by model capability, while the reply cap controls output length; the two are not interchangeable. Knowledge-base reference limits are controlled by tokens, so a long source passage may be trimmed, and the portion actually entering context needs checking against a question sample. A larger memory-round count brings in more prior content and can affect consumption and response speed.

Semantic retrieval, full-text retrieval, and hybrid retrieval are fused through RRF, and reranked results carry a 0–1 score that participates in filtering. The minimum relevance value is a filter threshold; it does not perform permission or entity isolation, and retrieval results do not constitute authorization. Libraries built on different vector models cannot be associated together; identifiers must be checked first and non-matching ones excluded.

Hypothetical drill sample. Source material one: "Party A: Xinglan Daily Chemicals Co., Ltd.; Party B: Yunji Supply Chain Co., Ltd.; contract object: disposable face towels, specification 80 pulls; signing date: March 10, 2025; status: signed by both parties, effective date subject to separate written confirmation by both parties." Source material two: "Yunji Supply Chain Co., Ltd. sample evaluation form: sample number YJ-2025-031, evaluation conclusion pending re-inspection, re-inspection arrangement not stated." Draft sentence awaiting judgment: "The Xinglan and Yunji face towel purchase contract took effect on March 10, 2025, and the sample evaluation passed."

## Constraints at the context limits step

The comparison carries three constraints tied to this step.

First, context capacity is bounded by the selected model. Source passages plus the draft sentence must fit within the maximum context the model can reference in one request. The reply cap governs only output length and cannot substitute for context capacity.

Second, the knowledge-base reference limit is measured in tokens, not item count. When a single source passage is long, the referenced content may be trimmed. The portion actually reaching the model must be checked against a concrete question sample rather than assumed.

Third, memory rounds add prior conversation content. A larger value draws in more material and can raise consumption and slow the response. A smaller value may leave earlier information unused. The setting is not a substitute for supplying the source text directly.

Retrieval itself does not grant authorization. Whether a material may be compared, and whether a downstream action may proceed, depends on the operational handover state, not on a search result. A pending review does not demonstrate the absence of operating authority. Signing, reaching cooperation, and contract effectiveness are three distinct facts. A quotation validity period does not state a supply period.

## Configuration and implementation checks

| Configuration or check item | Hypothetical starting point for this drill | Reason and comparison object |
| --- | --- | --- |
| AI model | A model supporting long context | Compared against the combined length of source material and draft sentence, to confirm the maximum context is not exceeded |
| Reply cap | Set to 800 for this hypothetical drill | Compared against the length needed for the draft sentence to express its basis and handling action fully |
| Reference limit | Set to 2000 tokens for this hypothetical drill | Compared against a single source passage length, to observe whether the passage is trimmed |
| Minimum relevance | Set to 0.4 for this hypothetical drill | Compared against semantic or rerank scores, used only as a filter threshold |
| Search mode | Hybrid retrieval | Materials contain company names and numbers, so full-text recall supplements semantic recall |
| Reply format | json_schema when fixed fields are needed | Compared against downstream parsing requirements, to check field completeness |

## Three common errors

1. Treating the signing date as the contract effective date. The source material records only that both parties signed, with the effective date subject to separate written confirmation. The draft sentence states effectiveness on March 10, 2025, which is unsupported. Check: input the source material and the draft sentence, compare the effectiveness field, and when the material does not state an effective date, record the item as pending verification.

2. Writing a pending re-inspection conclusion as a passed evaluation. The source material records the evaluation conclusion as pending re-inspection, with the re-inspection arrangement not stated. The draft sentence's "passed" occupies the same field with a mutually exclusive value. Check: input the sample evaluation form text, compare the evaluation conclusion field, and when pending re-inspection appears, record the draft sentence as not established.

3. Using minimum relevance to exclude unrelated subjects. That value is only a filter threshold and does not perform entity or permission isolation. Check: input a query containing a different subject, compare returned content against the target subject identifier, and record actual observations without assuming unrelated records must be filtered out.

## How to verify the setup

1. Input the source material and draft sentence above, compare the draft sentence's effective-date field against the source material, and when the material states only a signing date with effectiveness subject to separate written confirmation, record the item as pending verification rather than effective.

2. Input the sample evaluation form text and the draft sentence, compare the evaluation conclusion field, and when the source reads pending re-inspection, record the draft sentence's "passed" as not established and record the evidence gap as the re-inspection arrangement not stated.

3. Use a paper input of an empty reference result to check the downstream handover design, compare the downstream node's output when no referenced content is present, and confirm it handles the case as designed without asserting that a fabricated rule retrieval necessarily returns an empty result.
