# Group-buy leader operations: tool calls for document comparison

## What the documents look like

Leader operations materials include leader agreements, commission tables, pickup lists and community announcements. They come from the group-buy backend, order details and after-sales records, and they update daily and per group. In a comparison task, the reviewer checks the leader or community identifier, the period, the amount and the payment status separately. A community name does not automatically stand in for a leader identity, and an amount due does not equal a settled amount.

Three features of this category shape the comparison work. First, the materials mix contractual text with transaction text, so the same period and the same subject appear in more than one document with different field meanings. Second, the volume is small but frequent, which makes a per-group check practical rather than a bulk reconciliation exercise. Third, the documents are operational rather than audited, so a status such as settled or paid may be absent from every source even when the amount is recorded.

## Constraints at the tool calls step

Tool calling depends on a tool introduction and tool parameters. The introduction tells the model what the tool is for, and it should state the input conditions and the situations in which the tool should not be called. For system modules the parameters are already fixed; for plugins the parameters need separate configuration. Within the parameters there are two key values: the parameter introduction and whether the parameter is required. When a suitable required parameter is missing, the model may not call the tool, so the prompt has to guide the user to supply the parameter, and the actual request then has to be checked.

In advanced orchestration, available tools are connected to the tool call module. A connected tool automatically separates tool input from ordinary input, and the introduction can be edited to make the call timing more precise. The official guidance recommends not adding too many tools at once, and tuning a small set before expanding. When the tool call termination node is placed after a tool, it forces the current tool call to end, does not call other tools, and does not call the AI to summarize the tool result. Custom tool variables extend the variable input of tools, so nodes that are not treated as tool parameters can still be called.

Several states need to be kept apart: behavior a node already has, fields that are actually configurable, manual review actions, and business actions that require a separate downstream implementation. Retrieval or a form collecting values does not constitute authorization to execute. Business verification, approval, database writes and external synchronization each need their own downstream implementation. Semantic recall and relevance scores do not handle permission or entity isolation.

Hypothetical paper exercise sample: the leader agreement text states that Party A entrusts Party B to carry out group-buy operations in Sunshine Lane community, that commission is settled at eight percent of monthly received amount, and that the settlement period ends before the fifteenth of the following month. The commission table text states Sunshine Lane community, March 2025, received amount forty-two thousand yuan, commission due three thousand three hundred and sixty yuan. The pickup list text states Sunshine Lane community, March 2025, one hundred and twenty items arrived, one hundred and eighteen signed for. The draft sentence to be judged is: "Sunshine Lane community commission for March 2025 has been settled under the agreement." That sentence concerns settlement status, and none of the three materials records payment completion or settlement confirmation.

## Three common errors

1. Writing the tool introduction as a general description without stating the situations where the tool should not be called. The model may then call the comparison tool on unsuitable material. The check is to input the three sample material texts, compare whether the tool introduction covers the input conditions and the exclusion conditions, and observe whether the model still issues a call when the leader name is missing.

2. Treating a missing required parameter as something that can be executed. If the period is not provided in the sample, the model may not call the tool or may fabricate a parameter. The check is to input material containing only the leader name, compare whether the parameter is required against whether it can be extracted, and observe whether the period field in the actual request is empty or abnormal.

3. Treating the phrase "has been settled" in the draft sentence as a fact the materials support. None of the three sample materials records payment completion. The check is to input the draft sentence and the three source texts, compare the values for the same subject, the same period and the same field, and observe whether mutually exclusive values exist or whether the evidence is only at a related stage; missing evidence is recorded as pending verification.

## How to verify the setup

1. Input the three sample material texts and the draft sentence "Sunshine Lane community commission for March 2025 has been settled under the agreement." Compare the settlement status in the draft sentence against whether the three source texts record payment completion or settlement confirmation. The expected observation is that the source texts do not record that status, the draft sentence is not supported, and the item is recorded as pending verification rather than as a denial or a conflict.

2. Input the sample materials with the period field removed, and compare whether the required parameter can be extracted. The expected observation is that the model may not call the tool, or the period in the request may be empty; the prompt then has to guide the user to supply the parameter, and the actual request is checked again.

3. Input the sample materials with the comparison tool and the termination node connected, and compare the output after the termination node. According to the documentation, after execution reaches the termination node no other tool is called and no AI summary is produced. How the comparison result is displayed or handed to a person requires a separate path; the termination alone does not mean the result was delivered directly to the user.

The verification steps above are paper expectations and were not executed. A retrieval check needs to observe the actual return and the failure branch, and it does not guarantee a first hit, full recall, or an empty result for an unrelated query. Libraries using different vector models cannot be associated together; check the identifier first, exclude those that do not match, and record the actual observation. An empty result can be carried forward by checking the downstream design against a clearly stated paper input of an empty list.
