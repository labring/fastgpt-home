# Dealer rebate calculation: access controls for document comparison

## What the documents look like

Rebate calculation happens after sales close, and its center of gravity is policy interpretation and financial treatment. The working materials come from ERP sales records, dealer remittances, the contract ledger, and the finance system. Day-to-day documents include rebate policies, volume attainment tables, reconciliation statements, and red-letter invoices. These materials update monthly or quarterly, so a comparison run for one rebate period draws on a fixed set of policy and transaction documents rather than a live feed.

For contract and transaction material comparison, a single rebate line requires checking the policy clause, the attained quantity, the return deduction, and the invoice offset together. Access control and data isolation at this step determine which parties can see which materials. Channel sales staff should not see another dealer's rebate policy or reconciliation data, and finance staff working one dealer's rebate should not automatically reach a different dealer's ledger.

The relevant platform facts are specific. Knowledge base permission is a threshold: collection permission cannot bypass knowledge base permission. File-level permission is off by default, and in the off state collection readability matches the knowledge base. When it is on, list, detail, and retrieval recall are each authorized against a snapshot. Retrieval recall applies file-level filtering only when authentication runs as the current member identity; a workflow that preselects a knowledge base without member-identity authentication does not filter by file. Team administrators do not bypass file-level permission. Retrieval relevance is not a permission filter and cannot substitute for authorization.

Hypothetical paper exercise. A brand finance staff member submits a handover request: "Move Dealer A's 2024 fourth-quarter rebate policy, volume attainment table, and reconciliation statement into the shared knowledge base for the channel sales group to view." The material text to be checked reads: "Dealer A, 2024 fourth-quarter rebate policy, applicable to Dealer A, rebate rate calculated on quarterly volume attainment rate. The volume attainment table states Dealer A's fourth-quarter volume as 1,200 units. The reconciliation statement states Dealer A's fourth-quarter returns as 80 units, with a red-letter invoice already issued." The draft sentence to be assessed reads: "Dealer A's fourth-quarter rebate is calculated in full on 1,200 units." The subject needed for judgment is Dealer A, the object is the fourth-quarter rebate, and the state is 80 returned units with a red-letter invoice issued. In this exercise, whether the channel sales group holds read permission on the shared knowledge base, and whether Dealer A's materials have been individually authorized, are both unstated and remain items to verify. The draft sentence also omits the 80-unit return deduction, so the 1,200-unit full calculation does not follow from the stated materials.

## Constraints at the access controls step

Knowledge base read permission gates everything. If the channel sales group lacks read permission on the shared knowledge base, individual file authorization produces no access. File-level permission is a separate switch, and while it is off the system does not query any collection permission record, so collection readability follows the knowledge base.

When file-level permission is on, each file or folder carries a permission snapshot, and list, detail, and retrieval recall are authorized one by one. The collaborator list submitted for a file is a full overwrite: the submitted list is the final result. The submitted list must include the current creator, or the submission is rejected. Creator status is not granted or changed through collaborator configuration.

Retrieval recall filters by the current member's readable files only under member-identity authentication. A workflow knowledge base search node that preselects a knowledge base without member-identity authentication does not apply file-level filtering and still recalls under knowledge base permission. Team administrators do not bypass file-level permission; knowledge bases and files remain authorized by their own collaborator configuration. External system permission, such as an ERP or finance system interface, is verified separately from FastGPT resource permission, and neither substitutes for the other.

The handover request in the exercise is pending review. A pending request is not approval, and it does not show that the channel sales group has read permission or that file-level permission has been turned on. An offered option is not execution.

## Configuration and implementation checks

| Check item | Input | Comparison and observation |
| --- | --- | --- |
| Knowledge base read permission | Channel sales group member account | Whether that account holds read permission on the shared knowledge base; without it, file-level authorization has no effect |
| File-level permission switch | Shared knowledge base detail page | Whether the switch is on or off; in the off state, collection permission records are not queried |
| Collection collaborator list | Dealer A rebate policy file | Whether the submitted collaborator list includes the channel sales group; under full overwrite the list is the final result |
| Creator record | Dealer A volume attainment table file | Whether the submitted collaborator list includes the current creator; a missing creator causes rejection |
| Retrieval identity authentication | Workflow knowledge base search node | Whether the node authenticates as the current member identity; without it, no file-level filtering occurs |
| External system permission | ERP or finance system interface | External interface authentication and FastGPT resource permission are verified separately and do not replace each other |

Hypothetical starting value for this exercise: set the channel sales group as a read-permission collaborator on the Dealer A rebate policy file. This starting value is chosen because the exercise request asks the channel sales group to view the material, and it must be compared against the knowledge base read permission threshold. It is a setting for this hypothetical exercise, not an official default.

## Three common errors

1. Treating retrieval relevance as permission isolation. Retrieval settings do not exclude unrelated business records or unauthorized records, and recall results still require per-member authorization.
2. Treating team administrator status as a bypass for file-level permission. Team administrators do not bypass file-level permission, and knowledge bases and files remain authorized by collaborator configuration.
3. Treating the pending handover request as executed. The "move into shared knowledge base" action is pending review, which does not show that the channel sales group has obtained read permission or that file-level permission has been turned on.

## How to verify the setup

1. Input the channel sales group member account, and compare that account's read permission on the shared knowledge base with the file-level permission switch state. The condition is met when the account holds knowledge base read permission, the switch is on, and the collection collaborator list includes the member group. If knowledge base read permission is missing, file-level authorization has no effect.
2. Input the submitted collaborator list for the Dealer A rebate policy file, and compare whether the list includes the current creator. The condition is met when the list includes the creator and the submission succeeds. If the list omits the creator, the submission is rejected, and the gap is recorded.
3. Input the workflow knowledge base search node configuration, and compare whether the node authenticates as the current member identity. The condition is met when the node authenticates by member identity and retrieval recall filters by readable files. If the node does not authenticate by member identity, retrieval applies no file-level filtering, and the difference is recorded.

For the draft sentence in the exercise, the comparison is against the stated materials: the policy names Dealer A and a quarterly attainment basis, the attainment table states 1,200 units, and the reconciliation statement states 80 returned units with a red-letter invoice issued. The draft claims a full calculation on 1,200 units, which omits the stated return deduction. The materials do not state the rebate rate value or the resulting amount, so the final rebate figure remains unknown. Whether the channel sales group holds read permission on the shared knowledge base and whether Dealer A's materials carry individual authorization are not provided and remain unanswered.
