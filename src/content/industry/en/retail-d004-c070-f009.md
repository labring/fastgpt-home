# Cross-border product labels: tool calls for document comparison

## What the documents look like

For cross-border product compliance and labelling, comparison material sits before listing and import, and its core is product safety and label evidence. Four document types form the comparison base: product test reports, English labels, MSDS files, and platform prohibited-item lists. Sources include platform policy centres, testing laboratory reports, destination-country regulation libraries, and supplier materials. Updates are irregular, and each new product listing can bring a new comparison task.

The contract and transaction material comparison task in this step places the product description, label content, and test conclusions from a contract or transaction material against those compliance documents field by field. A comparison conclusion depends on whether the document text states the subject, object, status, and effective scope. A field that is not stated stays unknown.

## Constraints at the tool calls step

The tool call node lets the model decide whether to call a tool based on the tool introduction and parameter descriptions. The tool introduction needs to state the purpose, the input conditions, and the situations in which the tool should not be called. For system modules, the tool parameters are already fixed. For plugins, the tool parameters are a configurable item. Parameters contain two key values: the parameter description and whether the parameter is required. When a suitable required parameter is absent, the model may not call the tool, and a prompt can guide the user to supply the parameter.

The tool call termination node can be attached after a tool. When the workflow reaches this node, it forcibly ends this tool call, calls no further tools, and does not call the AI to answer questions about the tool call result. Custom variables can extend the variable input of a tool, adding parameter descriptions for nodes that are not treated as tool parameters or cannot be called as tools.

Retrieval is an action that obtains reference material and does not constitute authorisation. A similarity setting does not carry permission or entity isolation functions. Libraries across different vector models cannot be associated together; identifiers need to be checked first and non-matching items excluded. An empty result can carry a clearly stated paper input into a downstream design check.

### Hypothetical exercise sample

The following are paper materials for this hypothetical exercise. They do not come from any real customer or real record.

Material text one (contract excerpt): "The seller shall deliver batch A-031 of children's insulated cups before 1 March 2025, and the label shall mark material and warning text in English."

Material text two (test report excerpt): "Report number T-2025-014, sample is a children's insulated cup, test item is migration amount, conclusion is compliance with the limit value provided by the commissioning party, report date 20 January 2025."

Material text three (supplier material excerpt): "The label draft for this batch is complete and awaits confirmation by the compliance specialist before printing."

Draft sentence to be assessed: "The children's insulated cup of contract batch A-031 has completed the compliance label comparison, and the label content is consistent with the test report conclusion."

Assessment points: the contract states the delivery date and the label language requirement. The test report states the sample and the test conclusion. The supplier material states only that the label draft status is awaiting confirmation. The draft sentence claims that the compliance label comparison has been completed and that the label content is consistent with the test report conclusion, but the label draft is in an awaiting-confirmation state and the test report does not state the label text content, so the two cannot be compared on the same field. The draft sentence is not supported and should be recorded as pending verification.

## Configuration and implementation checks

| Configuration item | Hypothetical exercise starting point | Reason for the choice and comparison method |
| --- | --- | --- |
| Tool introduction | State: "used to compare field consistency across contract, test report, and label draft; input is the original text of the three document types; when the label draft status is awaiting confirmation, no consistency conclusion is output" | Lets the model judge when to call, compared against the situations in which the tool should not be called |
| Tool parameters | Parameter descriptions state "contract batch number, test report number, label draft status"; each required value is set to yes | When a required parameter is absent, the model may not call the tool, and interaction is needed to complete it |
| Tool connection | Connect only the contract material reading tool and the test report reading tool | A small number of tools is easier to debug, compared against adding many tools at once |
| Tool call termination | Attach after the label draft status reading | When the status is awaiting confirmation, end the call and do not let the AI summarise consistency |
| Custom variable | Add the parameter description "draft confirmation status" for the label draft status node | This node is not treated as a tool parameter and needs a custom variable to be connected |

## Three common errors

1. Treating the label draft's awaiting-confirmation status as a completed comparison. The input is the supplier material sentence "awaits confirmation by the compliance specialist before printing." The comparison object is "has completed the compliance label comparison" in the draft sentence. The observable result is that the draft status field remains awaiting confirmation, and no consistency conclusion should be output at this point.

2. Using the test report conclusion in place of a label text comparison. The input is the test report sentence "conclusion is compliance with the limit value provided by the commissioning party." The comparison object is "the label content is consistent with the test report conclusion" in the draft sentence. The observable result is that the report does not state the label text, the same field has no comparison value, and the claim should be recorded as unsupported.

3. Treating the tool call termination node as an authorisation confirmation. The input is the termination node attached after the label draft status reading. The comparison object is the statement that the comparison is completed. The observable result is that termination only ends this call and produces no authorisation or confirmation effect, while the awaiting-confirmation status stays unchanged.

## How to verify the setup

1. For material text one and the draft sentence, input the contract excerpt and the draft sentence, compare whether the draft sentence claims a completed comparison, and observe that the draft sentence contains "has completed the compliance label comparison" while the material states no confirmation record. The result is unsupported.

2. For material text two and the draft sentence, input the test report excerpt and the draft sentence, compare the report conclusion field with "the label content is consistent with the test report conclusion," and observe that the report does not state the label text content, so the same field has no comparison value. The result is pending verification.

3. For material text three and the draft sentence, input the supplier material excerpt and the draft sentence, compare the label draft status field with the draft sentence, and observe that the status is awaiting confirmation while the draft sentence claims a completed comparison. The result is unsupported. All three verifications keep the evidence gap open and do not claim that testing was actually performed.
