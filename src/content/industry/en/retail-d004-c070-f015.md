# Cross-border product labels: retrieval for document comparison

## What the documents look like

Retrieval material for cross-border product compliance and labelling clusters into four types: product test reports, English-language labels, MSDS documents, and platform prohibited-item lists. Their shared trait is that the evidence format is not uniform. A test report carries a report number and tested items; an English label carries ingredients and warning statements; an MSDS carries a version number and revision date; a prohibited-item list carries a platform and an effective scope. When contract and transaction materials are compared, the subject, object, status, and validity scope in these materials must be aligned field by field. The retrieval step returns candidate source text; the comparison conclusion comes from a human reviewer or a downstream step.

Compliance work happens before listing and import, and its core is product safety and label evidence. The consequence of error is platform delisting, customs seizure, or consumer claims. Materials update irregularly, and each new listing can introduce a new label version or a new report. The retrieval configuration must allow one product to have several materials at different points in time, with the cited content carrying the source text for checking.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases using different vector models cannot be associated together; the vector model identifier must be checked first and non-matching bases excluded. Retrieval searches the whole knowledge base, and a collection is only for classification management. Cited content is output as an array, and its length can be zero, meaning the output path still runs when nothing is found.

Semantic retrieval, full-text retrieval, and hybrid retrieval each have a suitable scope. Numbers, models, and proper nouns suit full-text or hybrid retrieval; natural-language questions suit semantic or hybrid retrieval. Hybrid retrieval merges multiple result paths through RRF. Rerank performs a second ordering of candidate text and produces a score from 0 to 1. The minimum relevance value takes effect only in semantic retrieval or when result reranking is used; it is a filter threshold and does not perform permission or entity isolation. Retrieval does not constitute authorization. Forms collect values; business verification, approval, database writes, and external synchronization each need their own downstream implementation.

Image retrieval requires image input and the corresponding model capability, and reranking requires a model and must be enabled by configuration. Optional paths in the overall flow do not mean every request executes all of them.

Hypothetical drill sample: a batch of portable chargers is intended for export. The source materials are: "Test report number TR-2024-0871, applicant entity Sample Trading Co., Ltd., tested object portable charger, report date 12 March 2024, tested items include battery overcharge protection"; "English label states input 100-240V, warning statement Keep away from children"; "MSDS version number V3, revision date 20 February 2024". The draft sentence awaiting a decision is: "This batch of chargers has completed destination-country compliance testing and can be listed directly." The handover request is: "Please confirm whether the above materials support this draft sentence."

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this drill | Reason for the choice and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Associate only knowledge bases holding the three material types above that share one vector model | Check that the vector model identifiers match before associating, and exclude those that do not match |
| Search mode | Full-text retrieval first, then hybrid retrieval | The report number and version number are exact queries; compare whether the recalled source text in each mode contains the number |
| Citation limit | For this drill, set a starting value covering the token volume of one full report | Chosen because a single report needs complete checking; compare against a half-report volume to see whether content is truncated |
| Minimum relevance | For this drill, set a starting value at the middle of the range | Label relevant and irrelevant samples first, then compare whether irrelevant fragments decrease after a threshold change |
| Question optimization | Enable for multi-turn follow-up questions | Compare the original question with the optimized question, and check whether the subject was altered incorrectly |
| Result reranking | Enable when candidates are numerous | Compare scores and ordering before and after reranking, and confirm the score can be used for filtering |

## Three common errors

1. Treating a retrieval hit as completed authorization. The input is the handover request above. If the draft sentence is judged listable directly, the error is that retrieval only returns cited content and does not verify authorization status. The cited source text should be compared against the draft sentence for whether subject, object, and status agree.

2. Treating an unstated field as a contradiction. The draft sentence says destination-country compliance testing is complete, while the source text states only tested items and a report date, with no destination country and no compliance conclusion. This should be recorded as unsupported or pending verification, not as a denial or a conflict.

3. Forcing an association across vector models. The input is several knowledge bases. If they are associated without checking the vector model identifiers, the error is that the same-vector-model requirement is violated. The identifiers should be checked first, non-matching bases excluded, and the actual observation recorded.

## How to verify the setup

1. Input the test report source text above and the draft sentence. Compare the five fields of report number, applicant entity, tested object, report date, and tested items. The support condition is met only when every item in the draft sentence has a corresponding value in the same field of the source text. The destination country and the compliance conclusion are not stated and should remain pending verification.

2. Input the handover request above. Compare the authorization wording in the request against the status field in the source text. The authorization condition is met only when the source text states a status such as signed, approved, or effective. Pending review does not demonstrate a lack of operating permission, and a quotation validity period does not indicate a supply period.

3. Input an explicit paper empty result []. Check how the downstream design handles an empty citation, and confirm the output path runs through. Do not claim that a fictional-rule retrieval necessarily returns [].
