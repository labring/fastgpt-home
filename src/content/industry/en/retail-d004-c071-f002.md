# Cross-border settlements: context limits for document comparison

## What the documents look like

Cross-border platform settlement and foreign exchange work covers fund collection for completed orders. The working materials are platform settlement statements, exchange rate tables, service fee invoices and receipt reconciliation sheets, with weekly or monthly update cycles. Contract and transaction material comparison requires that the settlement statement, invoice and reconciliation sheet sit inside the same context so that the counterparty, the period and the individual fields can be checked against one another.

A single settlement statement commonly contains multiple order deductions, and the length of each segment varies widely. The reference ceiling is controlled in tokens, so a long segment may be truncated and the basis for comparison then becomes incomplete. This page addresses one step only: the context and token conditions that apply when contract text and transaction materials are compared for this category.

## Constraints at the context limits step

The context window is checked against the actual model capability. The reply ceiling does not constitute the complete context window. The knowledge base reference ceiling is counted in tokens, and whether content has been truncated must be checked against the length of a single segment and against a sample question. Semantic retrieval scores and rerank scores reflect relevance only; they do not carry permission or entity isolation, and retrieval itself does not constitute authorization. Libraries that share the same vector model can be associated; across different vector models the identifier is checked first and non-matching libraries are excluded, without running a cross-model retrieval to compare missed recalls. RRF is the fusion process applied to mixed results, not a switch that can be turned on.

For this page's task, the material that matters is the settlement statement, the exchange rate table, the service fee invoice and the receipt reconciliation sheet. The comparison target is the counterparty, the settlement period and the fee field, and the evidence must come from within the accessible retrieval scope or from an explicit manual input. Where that evidence is absent, the gap is recorded as a gap.

## Configuration and implementation checks

Hypothetical drill sample: the material text reads, "Party A Haiyue Supply Chain Co., Ltd. and Party B Xingzhou Payment Services Co., Ltd. signed the Cross-border Settlement Services Agreement on 1 March 2025, agreeing that the service fee for the March 2025 settlement period is charged at 0.8% per transaction, and the agreement takes effect on the date of signature by both parties." The draft sentence to be assessed reads, "The two parties have reached cooperation, and the service fee has been executed at 0.8% since March." This sentence merges signature and effectiveness into a single fact of cooperation reached, and it does not check the actual deduction field on the settlement statement.

| Configuration item | Value or check action on this page | Basis and comparison method |
| --- | --- | --- |
| Reference ceiling | 3000 tokens as the hypothetical starting point for this drill | Compared against the length of a single settlement statement segment to observe truncation |
| Minimum relevance | 0.5 as the hypothetical starting point for this drill | Compared against the rerank score to observe whether low scores are filtered |
| Reply ceiling | Kept sufficient to express the basis and the handling action | Compared against the completeness of the draft sentence to observe truncation |
| Memory turns | A small number of history turns retained | Compare the same question under empty history and under history |
| Reply format | json_schema selected when fixed fields are required | Verify that fields are complete and parsing succeeds, not only length |
| Thinking strength | Chosen by question complexity | The thinking budget is a reasoning budget and is unrelated to the reference token ceiling |

The reference ceiling starting value is chosen because a single settlement statement segment in this category can run long when it lists many order deductions; the value is compared against the actual segment length to see whether content is cut. The minimum relevance starting value is chosen because rerank produces a 0-1 score; the value is compared against that score to see which results are filtered. Neither value is an official default.

## Three common errors

1. Treating the reply ceiling as the complete context window. Input is the draft sentence and the material text; the comparison is between the model maximum context and the reply ceiling as two separate fields; the observable result is whether reply length has been mistaken for context capacity.
2. Using the relevance score in place of a permission judgment. Input is the retrieval result together with its score; the comparison is between the score and the authorization state; the observable result is whether a high-scoring result has been taken directly as an executable basis.
3. Treating signature as cooperation reached or as contract effectiveness. Input is the signature date and the effectiveness clause in the material text; the comparison covers three distinct facts; the observable result is whether the draft sentence states a definite conclusion while the evidence is missing.

## How to verify the setup

1. Input the material text and the draft sentence; compare the three fields "signature", "effectiveness" and "cooperation reached". The condition is met only when the draft sentence is revised to match the original wording, or is marked as pending verification.
2. Input the same question under empty history and under history; compare the two inputs. The condition is met only when the referenced content and the draft sentence conclusion agree and no authorization absent from the history has been introduced.
3. Input a paper empty result []; check whether the downstream handling design treats it as empty reference. Whether retrieval returns an empty result is not guaranteed; only the actual observation is recorded. A pending review state does not demonstrate that an operation permission is missing, and absent evidence remains a gap.
