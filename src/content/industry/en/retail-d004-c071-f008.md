# Cross-border settlements: workflow routing for document comparison

## What the documents look like

Cross-border platform settlement and foreign exchange work concerns the collection of funds from orders that have already been concluded. The materials in scope are platform settlement statements, exchange rate tables, service fee invoices, and receipt reconciliation sheets. These materials update weekly or monthly, and their sources sit in separate places: the platform settlement center, bank transaction records, payment institution back offices, and ERP order data.

The comparison task for contracts and transaction materials is to place the deduction items, applicable exchange rate values, and service fees on a settlement statement side by side with the service fee invoice and the receipt reconciliation sheet, then confirm whether the same entity, the same period, and the same field carry consistent values. Because the materials are scattered, comparison requires gathering them first. In a workflow, that gathering is carried by interaction nodes and the nodes that follow them. Retrieval itself does not perform an authorization function.

Two characteristics of this category shape the routing step. First, the comparison target is a settled order, so the relevant evidence is a completed transaction record rather than a fraud or chargeback decision. Second, the materials arrive from several systems on a weekly or monthly rhythm, which means a routing step has to accept values collected from a person and pass them to later comparison nodes without treating collection as verification.

## Constraints at the workflow routing step

The form input node is a user interaction node. When it is triggered, the conversation enters an interaction state, the workflow state is recorded, and the workflow continues after the user completes the interaction. The node collects the required information the user submits and passes that information to subsequent nodes. The user selection node is also a user interaction node. When triggered, the conversation likewise enters an interaction state and the workflow state is recorded. When the user makes a selection, the node evaluates that selection and executes the corresponding "yes" branch. During interaction, the dialog box is hidden. These are existing node behaviors. They do not constitute a global state-recording switch, and they do not guarantee a number of submissions or automatic judgment.

Hypothetical paper exercise sample. The source material reads: "Platform settlement statement (settlement period 1 June 2024 to 30 June 2024) states: order A-1001 deduction amount USD 120.00, applicable exchange rate 7.10." The second source reads: "Service fee invoice (invoice date 5 July 2024, corresponding period June 2024) states: order A-1001 service fee USD 120.00." The draft sentence to be assessed reads: "The deduction amount for order A-1001 matches the service fee invoice amount, so this settlement can be confirmed as complete." Assessment requires the same entity (order A-1001), the same period (June 2024), and the same field (amount USD 120.00). The draft sentence extends an amount match into settlement completion. Settlement completion is a separate fact. The materials do not state it, so that extension is not supported.

During routing, the order number, period, and field name collected by the form input node are passed to later comparison nodes. The user selection node is used for a manual confirmation branch direction. Order writes, document backfill, and external status synchronization require a separate business interface or a later process. The nodes themselves do not perform those actions.

## Configuration and implementation checks

| Configuration item | Hypothetical trial starting point for this page | Reason for the choice and comparison method |
|---|---|---|
| Required form input fields | Order number, settlement period, field name | Comparison requires the same entity, period, and field; each is necessary. Compare item by item against the source material. |
| User selection branches | "Amount matches", "Amount does not match", "Insufficient material" | Covers three assessment outcomes. Check item by item against the draft sentence conclusion. |

The same vector model requirement for a retrieval library is limited to association within one library. It does not extend to business registration sites or other external systems. A relevance score does not carry an authorization or entity isolation function.

## Three common errors

1. Treating an amount match as settlement completion. The draft sentence "the deduction amount matches the service fee invoice amount, so this settlement can be confirmed as complete" extends a same-field value match into a separate fact. Settlement completion requires separate statement in the material. The material does not provide it, so it should be recorded as unsupported.
2. Treating a pending review status as missing operating permission. If the material shows an item in pending review status, that shows only that the item's status is pending review. It does not support a conclusion that operating permission is absent.
3. Treating interaction state recording as a global switch. The recording of workflow state by the form input node and the user selection node is node behavior. It does not constitute a configurable global state-recording switch, and it does not guarantee a snapshot.

## How to verify the setup

1. Enter the source material and the draft sentence from the hypothetical sample, then compare the order number, period, and amount fields. If the three fields match while the draft sentence concludes "settlement complete", the observable result is that the conclusion is not supported by the material, and an evidence gap should be recorded.
2. Enter the three branch options of the user selection node, then compare the user selection against the branch execution result. If "Insufficient material" is selected, observe whether the corresponding branch executes, confirming that branch connections are verified one by one.
3. Enter the paper empty result [], then compare how the downstream node handles empty input. Observe whether the downstream receives it as designed. Do not claim that a fictional rule retrieval necessarily returns [].

All three checks address the contract and transaction material comparison task. They do not drift into identity certification or report analysis. Retrieval does not carry an authorization function, and a value collected by a form does not equal business verification or approval.
