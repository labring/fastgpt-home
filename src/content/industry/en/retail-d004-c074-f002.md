# Cross-border resale returns: context limits for document comparison

## What the documents look like

Cross-border return refurbishment and resale handles reverse logistics and item condition, a different chain from overseas-warehouse inbound replenishment. The materials involved in this comparison task are return inspection sheets, refurbishment records, scrap declarations, and relisting lists. They arrive from overseas-warehouse WMS, TikTok return centers, Amazon return reports, and item inspection photographs. Updates occur daily or per batch.

The four document types carry different fields. The same returned unit may be marked as refurbishable on the inspection sheet, as pending determination on the scrap declaration, and may not yet appear on the relisting list. A comparison across these materials requires the model to read the relevant fragments of all of them within one request. Context length determines how many materials fit and how many fields of each are retained. The knowledge-reference limit is measured in tokens, so an overlong cited fragment can be trimmed and a key field can drop out of the comparison. History input changes the context of the same question, so a check has to compare an empty-history request against a with-history request to separate context drift from genuine material conflict.

## Constraints at the context limits step

Reply length caps only the model's output. Whether the input-side materials fit depends on the model's maximum context. These are two separate numbers and must be compared separately. The knowledge-reference limit controls how many tokens of cited content are returned; when a single material is long, the limit can trim it before the model sees the comparison-relevant fields. When structured output is required, a fixed reply format must return complete, parseable fields; checking text length alone does not confirm this.

Retrieval is not authorization. Finding a fragment that says a scrap decision is pending supervisor review only shows the decision is at the pending stage. It does not show approval or completed scrapping. A pending request is not approval, and an offered option is not execution.

The comparison must stay within one batch and one item object. Inspection sheets, refurbishment records, scrap declarations, and relisting lists have to be scoped to the same batch identifier and the same item identifier before any status field is compared. Materials from different batches or different items are excluded, not merged.

Cross-vector-model libraries cannot be jointly associated. Only identifiers are checked, non-matching records are excluded, and the actual observation is recorded. Empty-reference output can be checked against an explicit paper input `[]` for downstream design; no claim is made that a fictional rule search returns `[]`. Image retrieval requires the corresponding image input and model capability. ReRank requires a ReRank model and must be enabled by its setting. RRF is a fusion step for mixed results, not a switch.

## Configuration and implementation checks

Hypothetical drill sample: a cross-border seller has one return batch, item is a portable juicer, quantity 12 units, return date 2025-03-10. Return inspection sheet text: "12 portable juicers, motor noise, minor surface scratches, determined refurbishable." Refurbishment record text: "motor assembly replaced on 8 units, housing cleaned on 12 units, refurbishment completed 2025-03-15." Scrap declaration text: "same batch, 4 units with burned motors, determined scrapped, pending supervisor review." Relisting list text: "8 units refurbishment complete, pending inspection recheck before listing." Draft sentence to be judged: "All 12 units in this batch have completed refurbishment and are ready to list." The comparison goal is to judge whether the draft sentence is consistent with the materials above.

| Configuration item | Assumed trial starting point | Reason and comparison method |
| --- | --- | --- |
| AI model | Select a model supporting long context | Must hold fragments of four materials at once; compare model maximum context against estimated total material tokens |
| Reply cap | Set to a length that holds basis and conclusion | Compare against the field count the comparison conclusion needs; too short truncates the basis text |
| Knowledge-reference limit | Set in tokens to cover key fragments of four materials | Compare against single-material length; confirm key fields are not trimmed |
| Memory rounds | Keep a small number of history rounds | Compare the same question under empty history and with history |
| Reply format | Use json_schema when fixed fields are needed | Verify field completeness and successful parsing; text length alone is not sufficient |
| Minimum relevance | Takes effect under semantic retrieval or ReRank | Compare against recall relevance scores to filter low-relevance fragments |

## Three common errors

1. Treating the reply cap as the full context window. The reply cap controls only output length; whether input materials fit depends on the model maximum context. The check compares total material tokens against the model maximum context and against the reply cap as two separate values.
2. Treating retrieval as authorized execution. Finding the fragment "pending supervisor review" in the scrap declaration shows only that the scrap decision is at the pending stage; it does not support an inference of approval or completed scrapping. The check compares the status field in the material against the completed-action wording in the draft sentence.
3. Mixing materials from different batches or different item objects. Inspection sheet, refurbishment record, scrap declaration, and relisting list must be scoped to the same batch and the same item. The check first compares batch identifier and item identifier, excludes non-matching records, then compares status fields.

## How to verify the setup

1. Input the four material texts and the draft sentence from the hypothetical drill sample above. Compare the draft sentence "All 12 units in this batch have completed refurbishment and are ready to list" against the refurbishment record "motor assembly replaced on 8 units," the scrap declaration "same batch, 4 units with burned motors, determined scrapped, pending supervisor review," and the relisting list "8 units refurbishment complete, pending inspection recheck before listing." If the model output states the draft sentence is inconsistent with the materials and explains that 4 of the 12 units are at pending scrap review and 8 are pending inspection recheck, the expectation is met.
2. Input the same question under empty history and under with-history conditions. Compare whether the material fragments in the two inputs are the same. If the with-history run cites a status that does not appear in the current materials, record the context difference; this is not judged as a material contradiction.
3. Input a request in which one material fragment is missing. Compare whether the model output explicitly marks the missing field. If the model outputs completed scrapping while the scrap declaration is absent, the expectation is not met and the result is recorded as unsupported.
