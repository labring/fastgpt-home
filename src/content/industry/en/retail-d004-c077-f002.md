# Import and export permits: context limits for document comparison

## What the documents look like

Import and export permit handling takes place before customs declaration and determines whether a shipment may lawfully cross a border. The working materials for this category include automatic import licences, dual-use item licences, contracts and product descriptions. These come from commerce authority systems, customs commodity codes, supplier materials and customer end-use statements. Errors in this work can lead to a blocked clearance, a contract breach or an administrative penalty.

Contract and transaction material comparison places the licence, the contract and the product description into one shared context for cross-checking. Materials update irregularly and on a per-shipment basis, so each comparison uses the current shipment's documents. The context and token step addresses three practical questions: how much content a single model request can reference, which fragments the reference cap trims, and whether earlier inputs have changed the basis for the current determination.

Licences and contracts are often long, and a product description may carry specifications, model numbers and end-use wording. A model's maximum context determines how much content one request can reference. The reply cap controls only the length of the answer and does not serve as a full context window. The knowledge base reference cap is measured in tokens, so a long single passage may be trimmed; the single-passage length and the question sample need to be checked together to confirm whether the content entered the context in full.

Historical input changes what the model sees. The same question produces different inputs with an empty history and with history, and may reference materials from different turns. When a fixed reply format is used, complete fields and successful parsing require separate verification; text length does not substitute for a structural check.

## Constraints at the context limits step

The maximum context of the selected model sets the ceiling for one request. When the combined licence, contract and product description exceed that ceiling, part of the material does not reach the model, and any comparison drawn from the request is incomplete. The reply cap is a separate setting that limits answer length; treating it as the context window hides the truncation that occurs on the input side.

The knowledge base reference cap is expressed in tokens. A contract clause placed at the end of a long passage may fall outside the referenced content when the cap is smaller than the passage. Checking the longest single passage against the cap shows whether key clauses are included. The minimum relevance value is a filter threshold that applies only in semantic retrieval or when result reranking is used; it does not perform permission or entity isolation.

Memory turns determine how much earlier conversation the model may reference. A comparison run with a small number of prior turns may draw on materials from an earlier shipment, so the same question should be compared under an empty history and under history to confirm that unrelated materials have not entered. When a fixed reply format such as `json_schema` is selected, the returned fields must be checked for completeness and parseability rather than judged by text length.

## Three common errors

Hypothetical paper exercise sample: a company holds an automatic import licence whose licensed importer is Company A, whose goods are a certain model of equipment, and whose validity runs to a stated date. A purchase contract has Company B as seller and Company A as buyer, covers the same equipment model, and states a quantity matching the licence. One draft sentence reads: "The licence and the contract agree on the parties, the subject matter and the quantity, so declaration may be arranged."

1. Treating the reply cap as the full context window. Observable error: the combined material exceeds the model maximum context, yet the check looked only at the reply cap. Check: input the three source documents above, compare the combined material length against the model maximum context, and observe whether the key clauses enter the request in full.
2. Overlooking trimming of long material by the reference cap. Observable error: a key contract clause sits at the end of a long passage and does not enter the context when the reference cap is too small. Check: input the contract source text and the reference cap setting, compare the single-passage token count against the cap value, and observe whether the referenced content contains that clause.
3. Substituting text length for a structured field check. Observable error: after the reply format is set to `json_schema`, only the answer length is inspected and the fields are not. Check: input the draft sentence and the format requirement, compare the returned fields against the required fields, and observe whether they are complete and parseable.

## How to verify the setup

- Verification one: input the licence, contract and product description source texts above together with the draft sentence; compare the model maximum context against the combined length of the three documents; observe whether the key clauses of all three appear in the request. If the combined length exceeds the maximum context, record the truncated portion and judge the context to be insufficient.
- Verification two: input the contract source text and the reference cap setting; compare the single-passage token count against the reference cap; observe whether the key contract clause is referenced. If the key clause does not appear in the referenced content, record the trimming position and judge that the reference cap needs adjustment.
- Verification three: input the draft sentence and the `json_schema` format requirement; compare the returned fields against the required fields; observe whether the fields are complete and parseable. If fields are missing or parsing fails, record the missing fields and judge that the structured handoff did not pass.

All of the above are paper checks and no live test is claimed. Retrieval and similarity settings do not carry permission or entity isolation, and the same-vector-model requirement for a knowledge base does not extend to external systems. An empty-result handoff can be checked on paper by inputting an empty list against the downstream design; no claim is made that a fictional rule search will return an empty list.
