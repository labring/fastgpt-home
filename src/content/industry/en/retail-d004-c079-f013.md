# Central chain procurement: access controls for document comparison

## What the documents look like

Central chain procurement and distribution work centers on four document families: centralized procurement contracts, replenishment plans, distribution notes, and store requisition forms. These materials come from ERP purchasing, WMS, store POS, and supplier delivery data. The headquarters supply chain center and procurement managers compare what a contract commits to against what distribution actually executed; the distribution center arranges waves from replenishment plans. The comparison task here sits between contract text and transaction materials, and it does not involve store display inspection. Material updates arrive daily or weekly. That rhythm does not change the underlying access requirement: before any comparison, each material used as evidence needs a confirmed read authorization for the person performing the comparison.

## Constraints at the access controls step

A comparison task reads contract materials and transaction materials at the same time. These two groups may sit in different knowledge bases or different file collections. When file-level permission is off, collection readability matches the knowledge base, and the system queries no collection permission records. When it is on, each file or folder carries a permission snapshot, and list views, detail views, and retrieval recall each authenticate against that snapshot item by item. Knowledge base permission remains the threshold throughout; collection permission cannot bypass knowledge base permission. Retrieval recall filters by the files the current member can read, and files beyond that member's authorization are not recalled. That filtering applies only when authentication runs under the current member identity. A team administrator does not bypass file-level permission; team-level management permission covers only the team's own resources. System root and the team owner are treated as holding all permissions on all files.

Hypothetical paper exercise sample: a member of a chain enterprise supply chain center, member A, is responsible for checking a centralized procurement contract against a distribution note. The knowledge base "Centralized Procurement Contract Library" has file-level permission enabled. The file "2025 East China Dry Goods Centralized Procurement Contract" has member B as creator, and its collaborator list contains member A with read permission and member B with administrator. Member A submits a handover request: "Compare the March 2025 East China dry goods distribution quantities in the distribution note against the contracted quantities in the centralized procurement contract, item by item, and output a difference list." The draft sentence is: "The March 2025 East China dry goods distribution quantity matches the contracted quantity, so no replenishment plan adjustment is needed." Two sentences from the contract read: "This contract sets the East China dry goods monthly supply quantity at 1,200 boxes, valid from January 1, 2025 to December 31, 2025." "The monthly actual distribution quantity is governed by the distribution note; any amount above the contracted quantity requires written confirmation from the procurement manager." One sentence from the distribution note reads: "The March 2025 East China dry goods actual distribution quantity was 1,350 boxes." In this sample, member A holds read permission on the contract file and can read the contract text. The collaborator configuration of the file collection holding the distribution note is not given in the sample, so whether member A holds read permission on the distribution note remains unsupported.

## Configuration and implementation checks

The table below ties documented settings or implementation checks to this sample and to the primary task on this page.

| Configuration item | Documented content | Check action in this sample |
| --- | --- | --- |
| Knowledge base file-level permission switch | Off state is the default; when on, a permission snapshot is generated, and lists and retrieval authenticate item by item against the snapshot | Confirm whether "Centralized Procurement Contract Library" has it enabled; while off, a write operation configuring a single file's permission is rejected |
| Collection collaborator roles | Read permission, write permission, administrator, creator; the creator cannot be granted or changed through collaborator configuration | Verify member A's role on the contract file is read permission, and member B is administrator and creator |
| Full-overwrite semantics of collaborator configuration | The submitted list is the final result and must contain the current creator | If the contract file's collaborators are adjusted, verify the submitted list contains member B |
| Inherited state and independent state | Inherited state follows the parent; independent state is not overwritten by the parent; restoring inheritance keeps node-specific permissions | Confirm whether the contract file is currently in inherited or independent state, and record the actual state |
| Retrieval recall authentication condition | Applies when authentication runs under the current member identity; a preselected knowledge base without member-identity authentication performs no file-level filtering | Verify whether member A's comparison operation authenticates by member identity, and record the actual observation |
| Team administrator boundary | A team administrator does not bypass file-level permission; knowledge bases and files authenticate by their own collaborator configuration | Confirm whether member A is a team administrator; that identity does not affect the read-permission determination on the contract file |

## Three common errors

1. Treating retrieval relevance as a permission filter. Retrieval recall filters by the files the current member can read, and a relevance score carries no permission or entity-isolation function. If member A lacks read permission on the distribution note file, that file does not appear in retrieval results, and this outcome cannot be explained as insufficient relevance.

2. Treating team administrator identity as a substitute for file-level permission. A team administrator does not bypass file-level permission, and team-level management permission covers only the team's own resources. If member A is a team administrator, the contract file and the distribution note file still require item-by-item checking against their collaborator configurations.

3. Treating a pending-review or pending-confirmation state as already effective. In the sample, an amount above the contract quantity requires written confirmation from the procurement manager, and the distribution note records 1,350 boxes. Whether that confirmation has occurred is not given in the sample. The draft sentence states the quantities match, which lacks evidence on how the excess portion was handled and remains unsupported.

## How to verify the setup

1. Input the two contract sentences and the one distribution note sentence from the sample, and compare the contracted quantity of 1,200 boxes against the distribution note quantity of 1,350 boxes. These are different values for the same period and the same field, which constitutes a quantity difference. Expected observation: the difference list records this difference and notes that the excess portion requires written confirmation from the procurement manager, with that confirmation status recorded as unsupported.

2. Input member A's member identity and the contract file's collaborator list, and compare whether member A's role is read permission. Expected observation: member A can read the contract text; if member A attempts to configure the contract file's collaborators or restore inheritance, the operation is rejected, because configuring collaborators requires administrator permission on that file.

3. Input member A's access request for the distribution note file, and compare the collaborator configuration of that file collection. That configuration is not given in the sample. Expected observation: if member A holds read permission on the distribution note, the distribution note file is visible in retrieval recall; if not, that file does not appear in retrieval recall. Both cases require recording the actual observation, and no permission conclusion may be inferred from a relevance setting.
