# Returned-goods inspections: context limits for document comparison

## What the documents look like

Reverse returned-goods inspection handles returned parcels and item grading. Its data sources include the WMS returns module, platform after-sales records, carrier return shipments, and the inspection bench. The everyday materials are returned-goods warehouse receipts, inspection photographs, grade determination sheets, and resale listing sheets, updated per item and per day. Contract and transaction material comparison in this category has to hold the fields of the returned-goods warehouse receipt, the item condition shown in the inspection photographs, the conclusion of the grade determination sheet, and the disposition action of the resale listing sheet in one context. Materials arise with each return, and the context window often has to carry key fields from several materials at once, so token consumption and reference trimming directly affect whether the comparison can see complete grounds.

## Constraints at the context limits step

Model context is checked against actual model capability, and the reply cap is a different concept from the full context window. The knowledge-base reference cap controls, in tokens, the maximum content cited per search; when a single material passage is long, trimming can drop the fields needed for a judgment. Historical input changes the actual input for the same question, so the empty-history and with-history conditions are observed separately. Retrieval and similarity scores reflect content relevance only; they do not perform permission or entity isolation, and retrieval by itself is not authorization. RRF is a hybrid result fusion process inside the retrieval chain, with no independent switch. Thinking budget is a model thinking-strength setting, separate from the reference token cap.

Hypothetical paper exercise sample: the returned-goods warehouse receipt text supplied for checking reads "Return number RT-2024-0871, item subject a certain model of electric kettle, return status already at the inspection bench, quantity 1 unit, registration date 3 June 2024." The grade determination sheet text reads "Same number RT-2024-0871, determined grade B, determination note slight surface scratches, function normal." The draft sentence to be judged reads "This return has completed inspection and is determined ready for resale listing." That draft sentence does not state whether a resale listing sheet has been generated or whether disposition authorization has been granted, so it is in an unsupported state and the evidence gap is retained.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | Reason and comparison method |
| --- | --- | --- |
| AI model | Select a model that supports the required context length | Compare total material length against the model maximum context to confirm key fields are not truncated |
| Reply cap | Hypothetical starting point long enough to hold grounds and disposition action | Compare against the number of fields the draft sentence requires; too short truncates the grounds |
| Memory turns | Hypothetical starting point of a small number of history turns | Compare against the input under the empty-history condition to exclude context differences |
| Reference cap | Hypothetical starting point estimated from the sample material token volume | Compare against single-passage length and observe whether content is trimmed |
| Reply format | Use a structured format when fixed fields must be carried downstream | Verify field completeness and successful parsing, not text length alone |
| Minimum relevance | Adjusted from observed sample results | Filters low-relevance results only, not a permission or entity filter |

## Three common errors

1. Treating the reply cap as the full context window. Input the same batch of return materials, compare the reply cap and the model maximum context fields, and observe whether reply length is mistaken for context capacity.
2. Treating retrieval results or similarity scores as grounds for authorization. Input the draft sentence and the retrieved hits, compare the retrieved-hit state and the disposition-authorized state, and observe whether a hit is taken as authorization for resale.
3. Mixing thinking budget with the reference token cap. Input the thinking configuration and the reference cap as two settings, compare the fields each acts on, and observe whether thinking budget is moved into reference trimming.

## How to verify the setup

1. Input the returned-goods warehouse receipt text and the grade determination sheet text, compare whether the number, subject, status, and date fields of the two materials share the same subject, the same period, and the same field, and observe whether the same field carries mutually exclusive values. If the draft sentence concerns resale listing, the listing sheet text and authorization state must be attached separately; when absent, record it as unsupported.
2. Input the same question under the empty-history and with-history conditions, compare the two actual inputs, and observe whether history changed the retrieval grounds. Empty-result downstream handling can be checked with an explicit paper input of an empty array; do not claim that a fictional rule search necessarily returns empty.
3. Input the structured reply format setting and the sample request, compare returned fields against the required field list, and observe whether fields are complete and parseable. For libraries across different vector models, check the identifier first and exclude non-matching ones; do not run cross-model retrieval to compare missed recall.
