# Returned-goods inspections: access controls for document comparison

## What the documents look like

Returned-goods inspection handles reverse parcels and item grading. It does not handle outbound picking for new orders. Each returned item is tied to a return warehouse receipt, inspection photos, a grade determination sheet, and a resale listing form. Records update per item and per day.

Contract and transaction material comparison checks whether these documents, together with platform after-sales records and carrier return records, point to the same party, the same object, and the same status. Access control and data isolation at this step means the inspector, the inventory administrator, and the after-sales warehouse each see a different scope of return files. A comparison conclusion can only rest on materials the reviewer is permitted to access.

## Constraints at the access controls step

Knowledge-base file-level permission is off by default. While off, a collection's readability matches the knowledge base itself, and the system queries no collection permission records. Once enabled, each file or folder receives a full permission snapshot, and list views, detail views, and retrieval recall are authorized item by item against that snapshot. Knowledge-base permission remains the threshold; collection permission cannot bypass it. A team administrator does not bypass file-level permission. System root and the team owner are treated as holding full permission over all files.

Retrieval recall filters by readable files only when authorization runs under the current member identity. A workflow that preselects a knowledge base without member-identity authorization performs no file-level filtering and still recalls under knowledge-base permission. Similarity and relevance scores do not perform entity isolation or authorization judgment. A retrieval hit is not an authorization credential.

Hypothetical paper exercise sample: an after-sales warehouse inspection desk submits the original text of one return warehouse receipt, reading "Return number RT-0001, original order number SO-0001, item A, quantity 1, return signed date 2026-03-02, inspection conclusion pending." The same batch carries one draft handover sentence: "RT-0001 for item A has been determined resalable; please generate the resale listing form directly." What is to be judged is whether that draft sentence can serve as a resale basis, and whether the submitter holds write permission on the corresponding file.

## Configuration and implementation checks

| Check item | Configuration or check content | Correspondence to the sample |
| --- | --- | --- |
| Knowledge-base file-level permission switch | Confirm whether the target knowledge base has enabled it; while off, collection permission write operations are rejected with a prompt to enable first | Determines whether the file holding RT-0001 can receive individual collaborators |
| Collection collaborator role | Read permission views content, write permission changes content, administrator assigns permission | The drafter needs write permission to submit a resale conclusion |
| Creator constraint | A submitted collaborator list must include the current creator, otherwise it is rejected | Preserves the RT-0001 file creator during a full overwrite |
| Retrieval recall authorization mode | Under current member identity, filtering follows readable files; without member-identity authorization, no filtering occurs | Checks whether RT-0001 appears in that member's retrieval results |
| Team role boundary | A team administrator does not bypass file-level permission; knowledge base and file authorize separately | Team administrator identity does not automatically grant write permission on this file |
| Hypothetical trial starting point | This paper check starts from read permission, because the member only needs to view; compare against write permission to judge whether submission is possible | Permission level of the draft-sentence submitter |

## Three common errors

1. Treating a retrieval hit as authorization. The input is a member's retrieval returning RT-0001; the comparison is whether that member holds read permission on the file. If retrieval filters under member identity and the member lacks read permission, the file does not appear in results. Appearance of a result does not imply write permission.

2. Treating a pending state as a completed determination. The input is the return warehouse receipt conclusion "pending"; the comparison is the draft sentence "has been determined resalable." These are mutually exclusive values in the same field, so the draft sentence is unsupported and the inspection conclusion must update first.

3. Treating team administrator identity as file permission. The input is a team administrator account; the comparison is the file's collaborator list. A team administrator does not bypass file-level permission, so if the list lacks that account, there is no write permission. Configuring collaborators requires file administrator permission and an enabled file-level permission state on the knowledge base.

## How to verify the setup

1. Input the RT-0001 file from the hypothetical sample together with a member holding only read permission. Compare whether that member can submit the draft sentence. The observable result is a rejected write operation or no write-permission record after submission. Isolation is in effect when this condition holds.

2. Input the draft sentence and the original return warehouse receipt text. Compare the inspection conclusion field. The observable result is the mismatch between "pending" and "has been determined resalable." The draft sentence is unsupported by the original text when this condition holds, and the evidence gap remains.

3. Input an empty-result downstream scenario, using the explicit paper input `[]` to check the downstream design. Compare whether downstream handles it as no recall. The observable result is that no resale conclusion is generated. An empty retrieval does not indicate that permission passed, and it does not indicate that a rule must return empty.
