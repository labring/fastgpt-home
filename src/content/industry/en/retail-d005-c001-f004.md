# B2B marketplaces: procurement with vector indexes

## What the documents look like

For procurement in B2B marketplaces, this page examines FastGPT vector indexes. Follow the sample record and the supplementary timing sheet separately to see which evidence the procurement question actually retrieves. The examples are hypothetical.

## Constraints at the vector indexes step

A B2B procurement-index test can use new proposed quotation text: “Material samples can be supplied; mass-production lead time requires separate confirmation.” Sample access and production timing are different reading targets. Check suitable search wording for the same original without summarizing sample availability as production stock. Once retrieved, the answer should distinguish what the text supplies from what remains unconfirmed. An index hit does not establish an actual lead time. Sample collection and production supply capability are also distinct evidence targets. An index check should identify the supporting passage and the lead-time explanation still missing. One retrieval hit cannot replace both sources or establish an unprovided production commitment.

## Configuration and implementation checks

| Procurement check | Material to inspect | Evidence needed |
| --- | --- | --- |
| Searching both documents | The quotation attachment and the missing timing supplement | If their knowledge bases are associated with one search node, check embedding-model consistency at that node. |
| What the sample wording establishes | Attachment: material samples can be supplied. Earlier record: samples available for collection. | Keep the subject as samples. Neither sentence states production stock or when manufacturing will finish. |
| Where a timing query points | The buyer asks for mass-production lead time rather than a sample collection location. | Identify whether the recalled index points to the sample attachment or the added timing sheet, then read what that original actually says. |
| Identity after the supplement arrives | The timing sheet has been ingested while the earlier sample record remains searchable. | Compare the two document identities and their returned locations. Adding a sheet does not turn the earlier record into a timing statement. |
| Use of returned timing evidence | A candidate contains timing wording, but the response mentions sample collection alone. | Compare the actual citation with the response to locate omission during answering. Retain any conditions attached to the timing statement. |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Embedding model` | Knowledge bases associated with one search node must use the same embedding model. |
| `Original data and indexes` | One original data block can have multiple indexes. |
| `Index content` | Index wording should be complete and focused. |
| `Image indexes` | Where image retrieval is used, inspect descriptions or image vectors. |
| `Version and result check` | After a change, reuse questions to compare originals. |

## Three common errors

- If the index turns sample availability into immediate production delivery, compare the entry with the quotation original to trace the added supply claim.

- If added production material still yields only an old sample record, inspect the new table’s retrieval scope and index target rather than using sample evidence for lead time.

- If returned lead-time wording disappears from the answer, compare candidates, actual citations and response. Failure to retrieve a source differs from failing to use a retrieved condition.

## How to verify the setup

If the supplementary supply-condition sheet is absent, distinguish the unverified production lead time from the available sample wording. After obtaining and ingesting the sheet, inspect its original data and index target before repeating the procurement question. A retest returning only the old sample record requires candidates and citations to be retained. Investigate exclusion of the new sheet from the associated scope, an index pointing to old data, and omission of retrieved timing text at the answer step as separate possibilities. Bases associated within one search node need matching embedding models. Authorization and supply conditions remain separate checks; relevance does not establish supplier qualification.
