# MCN operations: procurement with HTTP integrations

## What the documents look like

For procurement in MCN operations, this page examines FastGPT HTTP integrations. Compare the material received with the sources used in the answer. The examples are hypothetical.

## Constraints at the HTTP integrations step

An MCN procurement inquiry can begin with locating the records of one cooperation. Proposed inputs include the contracting party, a session note and a request for training material. Those passages do not establish supplier admission. The actual owner must supply the external record service’s contract before the address, method and subject correspondence can be checked. No ready-to-use MCN query endpoint is assumed or introduced in this example.

## Configuration and implementation checks

| Object | Proposed input | Acceptance evidence |
| --- | --- | --- |
| Service contract | Record owner’s actual interface specification | Address and method have a documented basis |
| Party identity | Contracting party alongside scheduled account | Request and response concern that cooperation |
| Version transfer | Source version from the preceding step | Transmitted value is neither omitted nor substituted |
| Training gap | Contract present; training record absent | The response preserves the missing evidence |
| Ledger update | Separately authorized proposed write | Inspect its actual operation receipt |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Request address and method` | The request address and method follow the external contract. |
| `Params and Headers` | Inspect parameters, headers and authentication separately. |
| Body | Where a JSON body is used, validate its structure against the external contract. |
| `Variable references` | Variables can come from global, system or upstream outputs. |
| `Debug identity fields` | Test mode lacks chatId and responseChatItemId. |

## Three common errors

Using a schedule’s display name in place of the contracting party may retrieve another account’s records. Inspect source identity, request parameters and the subject of the response, retaining unresolved correspondence. A separate failure occurs when the source version never enters the request. Compare previous-node output with transmitted values to distinguish absent business material from a transfer defect; similarly named fields do not establish a match. If attendance alone becomes complete cooperation evidence, compare the actual return with the contractual scope and training content needed here. Attendance does not establish that the content was supplied; retain the missing corresponding passages.

## How to verify the setup

Test with a supplied contract and missing training evidence, then repeat after the corresponding material is added. Inspect whether request and response concern the same party, limiting the answer to obtained records. Inject authentication through protected configuration without exposing credentials. Updating a cooperation ledger or initiating approval requires its own authorization and business receipt. Completion of the HTTP exchange does not establish completion of supplier review.
