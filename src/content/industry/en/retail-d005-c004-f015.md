# Temu semi-managed sellers: retrieval for procurement

## What the documents look like

Semi-managed sellers on Temu maintain overseas stock and complete shipments themselves, rather than supplying goods to the platform under full-managed terms. This changes what the operational record set contains. Product declaration forms, overseas inventory tables, price declarations and platform fulfillment orders form the daily material body, while a procurement cost table records supplier-side cost. Updates arrive daily or per order, so retrieval results shift as ingestion progresses. The subject, object and validity scope recorded in a product declaration or price declaration provide the basis for later cross-checking, and the quantity and status fields in an overseas inventory table or platform fulfillment order determine whether a handover request can be supported. These materials sit across Temu Seller Center, an overseas warehouse WMS, logistics tracking and the procurement cost table. The retrieval step recalls content already ingested. It does not perform authorization judgment.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Bases built on different vector models cannot be associated together, so the vector model identifier needs checking first and non-matching bases excluded. Search mode may be semantic retrieval, full-text retrieval or hybrid retrieval; hybrid retrieval merges multiple result paths through RRF, and RRF is a fusion process rather than a standalone switch. Minimum relevance takes effect only under semantic retrieval or when result re-ranking is used, and that value is a filtering threshold that does not carry entity isolation or permission filtering. Reference limit is measured in tokens and controls the maximum content referenced per search. Question optimization performs coreference resolution and question expansion, and enabling it adds one model call. Image retrieval requires image input and the corresponding model capability, and re-ranking requires a ReRank model enabled per configuration; optional paths do not mean every request executes all of them. The node outputs referenced content as an array whose length may be 0, and the empty-result path still completes.

Hypothetical drill sample: a semi-managed seller operations staff member holds the following source text. Material one (procurement cost table excerpt): "Supplier number S-2210, product object is a folding storage box, quote validity ends 31 March 2025, procurement unit price is a hypothetical starting value of 12.00 yuan, no supply term clause stated." Material two (overseas inventory table excerpt): "Warehouse code US-WEST-03, product object is a folding storage box, available quantity as of 20 March 2025 is 0, status is awaiting replenishment." Proposed determination sentence: "Supplier S-2210 has confirmed continued supply at 12.00 yuan in April 2025." Check target: whether this sentence obtains support from materials one and two.

## Configuration and implementation checks

| Configuration item | Hypothetical trial starting point | Reason and comparison object |
| --- | --- | --- |
| Associated knowledge bases | Associate only the procurement cost table and overseas inventory table | Both bases use the same vector model; check the identifier before associating |
| Search mode | Run the sample question once each under semantic retrieval and full-text retrieval | Compare how the two modes recall supplier number and product object |
| Reference limit | Hypothetical starting point of 800 tokens | Compare content completeness using declaration fragments of differing length, then adjust |
| Minimum relevance | Hypothetical starting point of 0.30 | Label related and unrelated samples first, then compare threshold changes |
| Question optimization | Off first, retrieve with the sample question as written | The sample question has a complete subject; compare whether enabling changes the subject |
| Result re-ranking | Not enabled for now | Candidate count is small; compare ordering before and after enabling |

## Three common errors

1. Treating quote validity as a supply term. Material one states only that quote validity ends 31 March 2025 and states no supply term, while the proposed sentence claims continued supply in April. This is unsupported and the evidence gap must be recorded.
2. Inferring a supplier commitment from inventory status. The quantity 0 and awaiting-replenishment description in material two describe current warehouse stock, while the proposed sentence describes a future supplier supply confirmation, which is a different field. The source text does not state that confirmation, so record it as unsupported; a stock quantity of 0 also cannot be used to deny a future commitment.
3. Associating knowledge bases across vector models. If the two bases carry inconsistent vector model identifiers, exclude the non-matching one before retrieval and record the actual observation; do not fabricate running results for a joint association.

## How to verify the setup

1. Input material one and the proposed sentence, and check quote validity and the April supply commitment separately. The source text gives only a 31 March quote deadline and gives no April supply or price commitment, so the proposed sentence lacks a basis; do not treat the quote deadline directly as a supply term.
2. Input material two and the proposed sentence, and list three fields: inventory quantity, inventory status and supplier confirmation. The first two have source text values of 0 and awaiting replenishment, while the third is missing. Keep the known inventory status and the pending commitment separate; the first two cannot yield the third.
3. Input a paper empty result array [] and check whether the downstream design continues along the path where referenced content length is 0. This check verifies only empty-result handling and does not claim that any rule-based retrieval necessarily returns an empty array.
