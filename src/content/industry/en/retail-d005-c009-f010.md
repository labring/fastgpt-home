# Amazon FBM fulfillment: procurement with citation tracing

## What the documents look like

For procurement in Amazon FBM fulfillment, this page examines FastGPT citation tracing. Left-right accessory catalogues and replenishment requests need the current main-unit subject checked. The examples are hypothetical.

## Constraints at the citation tracing step

A proposed FBM procurement packet lists left and right accessory versions separately, requests a left connector and records connector packs organized. A question about readiness of the current left part needs those levels preserved. The catalogue identifies options, the request expresses demand and the organization record lists neither side nor compatible main unit. Connector pack cannot become left version through inference. A left option in a catalogue also cannot establish compatibility with the current unit or completion of this particular preparation activity.

## Configuration and implementation checks

| Procurement source check | Proposed material and scope | Evidence action |
| --- | --- | --- |
| Catalogue distinction | Left/right versions | Retain option identities. |
| Current demand | Left connector requested | Check requested subject. |
| Pack detail | Record says connector pack only | Seek version and contents. |
| Main-unit fit | Current-unit detail insufficient | Check model relation without borrowing another variant. |
| Preparation event | Added detail may concern another run | Check event before citing. |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Associated knowledge bases` | Knowledge bases associated with one search node must use the same embedding model. |
| `Citation output` | The output is an array; an empty array can continue. |
| `Citation input handoff` | Inspect citations actually received by the answer step. |
| `Citation display check` | Trace displayed sources to their originals. |
| `Document-validity check` | Inspect source identity and applicable version separately. |

## Three common errors

First, a selectable left part may become prepared stock for this request; inspect actual preparation detail. Second, a connector-pack record may become left-version confirmation; inspect pack contents and corresponding main unit. Third, a left-part description for another model may answer the current need; inspect unit identity and catalogue applicability. These require activity results, contents and model relationships separately. Similar names or multiple citations cannot replace subject matching. Where the main-unit information is absent, the compatibility gap remains rather than being resolved by a direction word.

## How to verify the setup

Acceptance should ask how the catalogue distinguishes versions, which side is requested and which details the preparation record lists. Preserve left-side demand and the missing pack detail without claiming picked or compatibility verified. Inspect actual citations for main-unit correspondence; a left-part source name still needs its text read. Added detail must match the preparation event before citations are compared. Empty references cannot establish that a left part is unavailable, while a catalogue alone cannot establish that a supply event has occurred or that the right object was prepared.
