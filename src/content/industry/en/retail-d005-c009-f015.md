# Amazon FBM fulfillment: retrieval for procurement

## What the documents look like

Amazon FBM fulfillment is operated by the seller. The seller arranges delivery and sets the return address, so the platform warehouse inspection step is not part of the flow. In this category, retrieval results for inventory procurement and supplier records feed directly into picking, shipment confirmation and return-address entry. A mismatched retrieval result can contribute to order cancellation, A-to-z claims or a decline in store performance.

The records used here come from Amazon Seller Central, carrier systems, ERP orders and customer-service email. Updates happen per order and daily. For this page the relevant documents are the order picking list, the shipment confirmation, the return address setting and the logistics tracking sheet, together with supplier quotations and purchase requests. This page addresses one task only: inventory procurement and supplier records, at the knowledge-base retrieval and recall step. Authorization status of materials, operations and requests during an operational handover is a separate matter; retrieval and forms do not by themselves grant authorization.

## Constraints at the retrieval step

The knowledge-base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases using different vector models cannot be associated together. The practical check is to compare the vector model identifier and exclude those that do not match. No cross-model retrieval comparison is performed to compare missed recall.

Search mode is compared per test question across semantic retrieval, full-text retrieval and hybrid retrieval. No single mode is assumed to suit all materials. Reference upper limit is measured in tokens. Minimum relevance takes effect only under semantic retrieval or when result reranking is used. Question optimization performs coreference resolution and question expansion; the original question and the optimized question are compared, and the subject is checked for incorrect substitution. A similarity score does not perform permission or entity isolation. A retrieval pass does not mean procurement or handover has been authorized. RRF is a fusion process for mixed results, not a switch to be turned on. Optional paths in the overall flow diagram are not all executed on every request: image retrieval requires a corresponding image input and model capability, and reranking requires the model to be present and enabled per settings.

Hypothetical paper exercise sample. The source text supplied for checking is: "Supplier A quotation dated March 2025: A-type label paper for picking lists; unit price as stated in the quotation; valid until 30 June 2025." "Purchase request PO-2025-0312: request to purchase A-type label paper; quantity pending supplier confirmation; applicant has not signed." "Return address setting page: United States marketplace return address is warehouse W1; effective date not filled in." A draft sentence to be assessed reads: "Supplier A has confirmed the supply quantity of A-type label paper, the purchase request has taken effect, and the return address is enabled." The source text contains the subject, the object, the quotation validity period and the unsigned status. The draft sentence treats the quotation validity period as a supply term, treats the unsigned request as effective, and treats the unfilled effective date as enabled.

## Configuration and implementation checks

| Configuration item | Setting or check for this page | Relation to the sample |
| --- | --- | --- |
| Associated knowledge bases | Associate only knowledge bases using the same vector model; compare the vector model identifier | Exclude knowledge bases with a different model; no cross-model retrieval comparison is run |
| Search mode | Try semantic, full-text and hybrid retrieval separately per test question | Number and model-type content is checked first for full-text hits |
| Reference upper limit | Unit is tokens; test completeness with actual materials of differing length | Observe whether label paper specification and validity period are truncated |
| Minimum relevance | Takes effect only under semantic retrieval or result reranking; label relevant and irrelevant samples first | In the sample, the quotation and the return address page are labelled separately |
| Question optimization | Compare original and optimized question; check whether the subject was changed incorrectly | Check whether "Supplier A" was replaced by another subject |
| Result reranking | Requires a rerank model enabled per settings | Observe ordering changes when candidates are numerous |

## Three common errors

1. Treating a quotation validity period as a supply term. The input sample source text states "valid until 30 June 2025." Comparing this with the draft sentence "has confirmed the supply quantity" shows the error: a validity-period field is treated as a supply commitment. The check compares the same field; quotation validity period and supply term are different fields.
2. Treating an unsigned purchase request as effective. The input states "applicant has not signed." Comparing this with the draft sentence "the purchase request has taken effect" shows the error: an incomplete signature is treated as effective. Signing, reaching cooperation and contract effectiveness are three distinct facts.
3. Treating an unfilled effective date as enabled. The input states "effective date not filled in." Comparing this with the draft sentence "the return address is enabled" shows the error: a missing field is treated as enabled. Missing evidence is recorded as unsupported.

## How to verify the setup

The following verification uses the hypothetical source text and draft sentence above. Each item states the input, the comparison and the observation, and does not claim that testing has been performed.

1. Input the draft sentence and the quotation source text. Compare "valid until 30 June 2025" with "has confirmed the supply quantity." The condition is met only when the draft sentence no longer presents the validity period as a supply term and explicitly records that the supply quantity is pending confirmation; otherwise it is recorded as unsupported.
2. Input the draft sentence and the purchase request source text. Compare "applicant has not signed" with "the purchase request has taken effect." The condition is met only when the draft sentence no longer states that it has taken effect and retains the unsigned status. A pending review does not demonstrate a lack of operating permission.
3. Input the draft sentence and the return address setting source text. Compare "effective date not filled in" with "the return address is enabled." The condition is met only when the draft sentence no longer states that it is enabled and records that the effective date is missing. If retrieval returns an empty reference array, the downstream design can be checked for how it handles empty results using the explicit paper input []. It cannot be claimed that a fictional rule would necessarily return an empty array on retrieval.

Across these checks, the required materials must be inside the target retrieval scope to which access exists, or within an explicit manual input. When they are missing, the gap is recorded. Where the source text is silent, or where only evidence of a related stage exists, the result is recorded as unsupported or pending verification, not as a contradiction.
