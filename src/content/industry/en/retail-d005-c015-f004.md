# Letter-of-credit documents: procurement with vector indexes

## What the documents look like

For procurement in Letter-of-credit documents, this page examines FastGPT vector indexes. Trace supplier, dispatch warehouse and production attachments without mixing roles or batches. The examples are hypothetical.

## Constraints at the vector indexes step

A proposed invoice annotation for a procurement-source question says: “Supplier A; manufacturing location appears in the batch attachment.” A packing note says only that goods leave Warehouse B. Indexes should distinguish supplier identity, the pointer to manufacturing information and dispatch location. They must not merge A, B or an address into one role. The batch attachment has not been supplied, and dispatch location does not establish manufacturing location. Ask who supplies, where goods leave and where they are manufactured, inspecting the actual evidence for each answer.

## Configuration and implementation checks

| Implementation check | Material in this test | Evidence action |
| --- | --- | --- |
| Party roles | Supplier, dispatch warehouse and manufacturing site differ | Trace each role to its original. |
| Attachment pointer | The current production attachment is absent | Do not infer manufacturing from an address. |
| Wrong-batch citation | An old attachment may share a supplier name | Compare cited batch and current pointer. |
| Models and indexes | Verify conditions for joint retrieval | Repeat the fixed role questions after changes. |
| Examination boundary | Retrieval locates source material | A hit establishes no bank acceptance. |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Embedding model` | Knowledge bases associated with one search node must use the same embedding model. |
| `Original data and indexes` | One original data block can have multiple indexes. |
| `Index content` | Index wording should be complete and focused. |
| `Image indexes` | Where image retrieval is used, inspect descriptions or image vectors. |
| `Version and result check` | After a change, reuse questions to compare originals. |

## Three common errors

- If Warehouse B becomes the manufacturer in an index, inspect whether its target is packing or production material, retaining the role substitution beside the original.

- If an old batch attachment is used for this batch, compare the invoice pointer, attachment batch and actual citation. A shared supplier name does not establish correspondence.

- If the current attachment is added but only old records return, inspect new data and index targets. Distinguish failure to retrieve the new source from role mixing after retrieval.

## How to verify the setup

Once the current production attachment is obtained, register it as new data and inspect whether associated indexes still target the earlier batch. Repeat fixed role and batch questions before and after model or index changes, comparing cited sentences rather than fluency alone. Check vector-model conditions and available sources when jointly retrieving invoice, logistics and production collections. A missing attachment remains an evidence gap. For scans, compare extracted parties and batch identifiers with the source, inspecting image-retrieval content only where that route is used. Finding material does not perform formal document examination, supplier approval or subsequent transaction handling.
