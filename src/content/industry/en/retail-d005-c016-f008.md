# Franchisee onboarding: workflow routing for procurement

## What the documents look like

Franchisee training and opening coaching is a transfer of operating capability. It differs from franchise registration management, which is a legal disclosure process. The documents handled day to day are training sign-in sheets, opening checklists, SOP manuals and assessment scores. The typical data sources are the training system, the supervisor app, store photographs and the headquarters SOP library. The typical parties are the chain training department, regional supervisors and franchise store owners. The task on this page is inventory procurement and supplier materials, and the feature is workflow routing. That combination means the store's procurement request, the supplier qualification materials and the headquarters review action need to be arranged as a traceable sequence of nodes. Opening material checks and SOP action correction consume the most time. If inventory procurement is not checked before opening, the documented consequences include opening failure and inconsistent customer experience.

## Constraints at the workflow routing step

The form input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and after the user completes the interaction the workflow continues downward. The node collects the required information the user fills in and, after submission, passes that information to subsequent nodes. The user selection node is also a user interaction node with the same interaction behaviour. When the user makes a choice, the node judges that choice and executes the "yes" branch. Both nodes record workflow state and wait for the user to finish interacting before continuing.

For inventory procurement and supplier materials, the information collected at these nodes has to be passed explicitly to downstream retrieval, judgement or interface nodes, and the output has to be compared item by item against the input. Order writing, document backfill and external status synchronisation require a separate business interface or a later process. The form itself only collects values. The same-vector-model requirement for retrieval libraries is limited to retrieval association and does not extend to business registration websites or other external systems. Semantic recall and relevance scores do not carry permission or entity isolation duties. Interaction waiting, state recording and hiding the dialogue box follow the documented explanation; no global state-recording switch is documented.

Hypothetical drill sample: a franchise store submits a pre-opening inventory procurement handover request in March 2025, with three sentences of source material — "Store name: Chengdong Demonstration Store; Application date: 10 March 2025; Procurement categories: receipt paper and price tags; Supplier qualification attachment: business licence scan uploaded; Headquarters review status is pending review." The proposed judgement sentence is "This store's inventory procurement has been approved by headquarters and the order may be placed." In this sample, pending review is not approval, and the proposed judgement sentence does not match the material status.

## Configuration and implementation checks

| Configuration item | Documented setting or implementation check | Link to the sample on this page |
| --- | --- | --- |
| Form input node | Enters interaction state on trigger, collects required information, passes it to later nodes after submission | Collects store name, application date, procurement categories |
| User selection node | Executes the "yes" branch after the user makes a choice; verify each branch connection | Reviewer selects "pass" or "return" |
| Interaction state check | State recording is behaviour of the interaction node; no separate global state-recording switch is documented | Check where the pending-review status is recorded in the sample |
| Output handover check | Pass collected information explicitly to later retrieval, judgement or interface nodes | Compare the procurement categories and supplier attachment fields |
| External action division | Order writing, document backfill and external status synchronisation require a separate business interface or later process | The order action is not completed inside the form node |

Hypothetical starting point for this drill: the review status field is compared against two mutually exclusive values, "pending review" and "approved". The reason for choosing this starting point is that the field appears explicitly in the sample and is required for the judgement. The comparison method is a literal comparison of the same field between the source material and the proposed judgement sentence. This starting point is set for this paper drill and is not an official default value.

## Three common errors

1. Treating the form-collected line "Supplier qualification attachment: uploaded" as verified qualification. Uploading and verification are different facts. The source material states only that the attachment exists and does not record a verification result.
2. Treating execution of the user selection node's "yes" branch as completed business approval. Branch execution is node behaviour. Business approval requires the headquarters review status field to change explicitly to approved, and in the sample that field is pending review.
3. Treating a relevance score returned by retrieval as a basis for permission filtering. Relevance does not carry entity isolation duties. Unauthorised records are not excluded because their score is low, and a separate permission check step is required.

## How to verify the setup

1. Input the sample source material and the proposed judgement sentence, and compare the "headquarters review status" field. The source material gives pending review, and the proposed judgement sentence claims approval has been obtained. The observable result is that the two values differ on the same field. The proposed judgement sentence is not supported by the material and should be recorded as requiring further verification, not judged as approved.
2. Input the sample sentence "Supplier qualification attachment: business licence scan uploaded" and compare the qualification verification status field. The source material does not record a verification result. The observable result is that this field is missing, and the gap should be recorded as an evidence gap without inferring that qualification passed.
3. Input the sample procurement categories "receipt paper and price tags" and compare the receiving field at the later retrieval or interface node. The observable result is whether the category values are passed through unchanged. If the downstream node does not receive those values, record the output handover as incomplete, without asserting a system error or automatic repair.
