# Regional dealer stock: workflow routing for procurement

## What the documents look like

Regional dealer stock replenishment runs as a daily rolling order pattern. It is not a seasonal concentrated ordering event, so the documents arrive continuously rather than in a single campaign. The main data sources are the dealer ERP, the brand ordering system, warehouse inventory, and sales receipts. The documents handled day to day are replenishment requests, inventory turnover sheets, outbound delivery notes, and payment collection plans. Update frequency is roughly weekly or monthly.

Each document carries a different kind of fact. A replenishment request expresses demand. An inventory turnover sheet reflects turnover condition. An outbound delivery note records what was actually dispatched. A payment collection plan describes the funding arrangement. Workflow routing has to connect information collected at interaction nodes with the nodes that follow, and it cannot treat a completed form as authorization or as business execution. The most time-consuming steps in this category are calculating safety stock, coordinating brand shipment, and following up on payment collection.

## Constraints at the workflow routing step

The form input node is a user interaction node. When it is triggered, the conversation enters an interaction state, the workflow state is recorded, and execution continues downward only after the user completes the interaction. The node collects required information and passes what the user submitted to subsequent nodes. The user selection node is also a user interaction node with the same interaction state and state recording behavior. When the user makes a choice, the node evaluates that choice and executes the corresponding yes branch. Its basic use is to pose a question that requires a decision, then design different workflow paths based on the user's feedback.

For the inventory procurement and supplier materials task, the interaction nodes can only collect information and select branches. Order writing, document backfill, and external status synchronization require a separately connected business interface or a downstream process. Semantic recall and relevance scores from the retrieval library do not perform permission or entity isolation, and retrieval output does not replace an authorization judgment.

Hypothetical drill sample. A regional dealer submits a replenishment request whose text reads: "Request to replenish 300 units of model A, request date 10 June 2025, requester Zhang, owning warehouse East China Warehouse No. 2." A supplier material excerpt is attached: "Supplier B, supply scope model A, quotation valid until 30 June 2025." One draft sentence awaiting judgment reads: "Supplier B has confirmed delivery of 300 units on 10 June." Checking requires comparing the delivery confirmation in the draft sentence against both source texts. The replenishment request only expresses a request. The supplier material only states supply scope and quotation validity. Neither contains a delivery confirmation. The phrase "has confirmed delivery" is unsupported by the source texts and remains pending verification.

## Three common errors

1. Treating replenishment request information collected by the form input node as procurement authorization. The form input node only collects required information and passes it along; order writing and supplier confirmation require a separately connected business interface. Compare the form output with the input of the subsequent node. If the subsequent node is not connected to a business interface, the replenishment request remains in request status.

2. Treating the yes branch of the user selection node as already executed. The user selection node executes the corresponding branch after the user makes a choice, and the branch connections need to be verified one by one. Compare the branch connection with the subsequent node. If the yes branch is not connected to any business processing node, the selection result produces no execution effect.

3. Treating supplier material returned by retrieval as an authorization basis for supply. Semantic recall and relevance scores from the retrieval library do not perform permission or entity isolation. Compare the retrieval output with the original supplier material text. If the original text only states supply scope and quotation validity and contains no delivery confirmation, the phrase "has confirmed delivery" in the draft sentence is unsupported.

## How to verify the setup

1. Input the replenishment request text and the supplier material excerpt from the hypothetical drill sample, then compare the draft sentence "Supplier B has confirmed delivery of 300 units on 10 June" against both source texts. If neither source text contains a delivery confirmation statement, the draft sentence is unsupported and the evidence gap must be recorded.

2. Input the required field settings of the form input node, then compare whether the output after submission is passed to the subsequent node. If the subsequent node does not receive the form output, the output handoff is incomplete and the node connection must be checked.

3. Input the branch settings of the user selection node, then compare whether the yes branch is connected to a subsequent processing node. If the yes branch is not connected, the selection result produces no execution effect, and the connection must be added or recorded as pending implementation.

This page addresses only regional dealer stock replenishment, inventory procurement and supplier materials, and workflow routing. During operational handoff, the authorization status of which materials, operations, and requests must not be inferred from retrieval or form completion.
