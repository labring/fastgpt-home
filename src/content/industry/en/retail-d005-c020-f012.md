# Certificates of origin: document chunking for procurement

## What the documents look like

Certificates of origin support tariff treatment and customs clearance in the importing country. The underlying assessment draws on production records, purchase invoices and supplier materials; letter of credit terms do not necessarily govern this work. For the inventory procurement and supplier materials task, the typical records are purchase contracts, inbound invoices, supplier declarations, bills of materials and production cost statements. Formats vary, versions change frequently, and one certificate application can involve multiple batches of materials from several suppliers. These materials are compared item by item against origin rules, so the quality of document parsing and chunking determines whether a later search can locate the origin status of a specific material in a specific period. Updates arrive per order or in batches, and the same material may appear with different sources across batches, so chunking must retain batch and period information.

## Constraints at the document chunking step

Origin rule assessment depends on conditional clauses and exception statements. If a segment splits "if imported content is used, then..." away from its main clause, a retrieved fragment will lack the constraining condition. One set of source data can map to multiple vector indexes: supplier name, material number and invoice number can each have an index, but an index does not create a permission boundary, and a retrieval hit does not mean the material is authorized for this filing. Full-text retrieval suits numbers and model designations; semantic retrieval suits natural language descriptions; hybrid retrieval merges multiple result paths through RRF. Reranking participates only when a model is available and the setting enables it. The citation limit is measured in tokens. The minimum relevance value takes effect only under semantic retrieval or when reranking is used. Image indexes must already exist at ingestion time and the model must support them; otherwise image input cannot participate in recall.

## Configuration and implementation checks

The settings below address this page's primary task. The values are hypothetical starting points for this paper exercise, used for comparison against retrieval output, and are not official defaults.

| Configuration item | Hypothetical starting point | Reason and comparison object |
| --- | --- | --- |
| Search mode | Hybrid retrieval | Supplier numbers and material descriptions coexist; both exact hits and semantic similarity are needed |
| Citation limit | 3000 tokens | Compared against the parsed length of one purchase invoice plus a supplier declaration, to avoid truncating conditional clauses |
| Minimum relevance | 0.35 | Compared against unfiltered recall items, to observe whether low-scoring fragments contain exception statements |
| Question optimization | Enabled | Completes references in multi-turn follow-ups about supplier batches; compared against recall items with it disabled |
| Rerank | Enabled with a configured model | Second-pass ordering when candidate items are numerous; compared against ordering from RRF fusion alone |
| Index fields | Supplier name, material number, invoice number | Identity fields that can point back to the source text; compared against the default text index only |

## Three common errors

1. Treating a successful upload as an updated index. After material changes, the actual training and index state must be checked. Upload and index effectiveness are two separate steps, and the index state remains unknown until checked.

2. Treating a retrieval hit as authorization. Retrieval returns similar content only. Whether supplier material may be used for this certificate filing must be checked manually against the authorization boundary; similarity does not perform entity or permission filtering.

3. Splitting conditional clauses across chunks. If "if imported content exceeds the threshold" and the conclusion fall into different data blocks, a retrieved fragment lacks the constraining condition, and the basis for the origin decision is incomplete.

## How to verify the setup

Hypothetical paper exercise sample: the supplier material text reads, "Supplier A provided batch B-03 of cotton yarn in March 2025. This batch contains imported content, and the imported content proportion is 40%. If the imported content proportion exceeds 35%, the batch does not meet origin eligibility." The draft sentence to be assessed reads, "Batch B-03 meets origin eligibility and may be used for this certificate filing." The draft sentence reaches the opposite conclusion from the conditional clause in the source text, and the source text states no exemption or exception.

1. Input the source text above and the draft sentence. Compare the draft conclusion against the conditional clause on the same batch and the same proportion field. If the source condition holds and the draft gives the opposite conclusion, the draft sentence is unsupported.

2. Input "B-03" for full-text retrieval and observe whether the returned fragment contains both the batch number and the imported content proportion. If only the batch number returns and the proportion condition is missing, chunk completeness is insufficient and the chunking must be adjusted.

3. Input "Supplier A cotton yarn origin" for semantic retrieval and compare whether returned items include material from that supplier. If items describe other suppliers or other materials with similar wording, record this as a recall deviation and do not use it to judge authorization status.
