# Brand member operations: citation tracing for procurement

## What the documents look like

Brand member private-domain operations work from four recurring document families: member tag tables, outreach plans, coupon rules, and privacy authorization records. In the procurement and supplier context, these sit alongside supplier quotation sheets, internal purchase requests, and handover records. The citation tracing question for this page is narrow: when a figure, supplier name, or authorization status appears in a draft, which material, which version, and which handover does it actually come from.

The main data sources are the CRM system, enterprise WeChat, POS transaction records, and mini-program behavior data. Update frequency is daily or weekly. That frequency does not change the tracing rule. A citation must point to a specific material. When the material is missing, the conclusion stays pending verification. Typical operators are the brand CRM team, store guides, and enterprise WeChat operators. Errors in this area can produce outreach harassment complaints, uncontrolled coupon cost, and member churn. These consequences are the reason retrieval output cannot stand in for an authorization decision, and a search result is not a permission credential.

## Constraints at the citation tracing step

The core constraint is that retrieval output supplies candidate content only. It does not supply business authorization.

The knowledge base search node can select one or more knowledge bases that share the same vector model. Its output is a citation array, and the length may be zero. Even when nothing is found, that output path still completes. An empty array does not mean the workflow has errored out, and it does not mean a particular purchase record does not exist.

Hybrid search merges multiple retrieval paths through RRF. ReRank performs a second ordering pass over candidate text. Minimum relevance takes effect only under semantic retrieval or when result reordering is used. These mechanisms affect ordering. They do not perform permission isolation or entity filtering. The citation limit controls how much content each search may cite, measured in tokens, and it is unrelated to a thinking budget. Image retrieval requires the corresponding image input and model capability. Reordering requires a capable model and must be enabled by its setting. Optional paths shown in the overall document flow diagram do not mean every request executes all of them.

Knowledge bases with different vector models cannot be associated together. Check the identifier first and exclude those that do not match; do not run a cross-model search to compare missed recalls. Retrieval and forms collect values. Business verification, approval, database writes, and external synchronization each need their own downstream implementation.

## Configuration and implementation checks

The following items are built around one hypothetical paper exercise sample. The sample is set as follows: a brand member private-domain operations team hands over a batch of procurement and supplier materials on 10 March 2025. The materials include a supplier quotation and an internal purchase request. The sample source text is: "Supplier A submitted a quotation on 5 March 2025, valid until 31 March 2025. The internal purchase request states a proposed purchase quantity of 200 units, and the request status is pending review." The draft sentence to be judged is: "Supplier A has confirmed supply, and the purchase quantity of 200 units is now effective."

| Configuration or check item | Setting on this page | Note |
| --- | --- | --- |
| Associated knowledge base | Select one knowledge base and confirm its vector model identifier | Only the same vector model may be associated together; exclude mismatches first |
| Search mode | Semantic retrieval or hybrid retrieval | Hybrid retrieval merges through RRF; do not write it as a switch |
| Minimum relevance | Hypothetical exercise starting point 0.5 for this run | Takes effect only under semantic retrieval or result reordering; compare against 0.3 and observe |
| Citation limit | Hypothetical exercise starting point 2000 tokens for this run | Measured in tokens; compare against 1000 and observe |
| Citation handoff | Check whether the citation array is passed to the answering step | Compare each answer statement against the cited source text |
| Material currency check | Test sources with the current version and a historical version | Whether a citation is adopted still depends on review against the valid version |

## Three common errors

1. Treating a retrieval hit as authorization confirmation. The input is the retrieval result for the Supplier A quotation. The comparison is between the quotation source text and the draft sentence. The observable result is that the draft claims confirmed supply, while the source text shows only a validity period and states no supply confirmation. This error conflates citation source with business authorization.

2. Writing a pending-review status as already effective. The input is the purchase request source text "the request status is pending review." The comparison is between "pending review" and "effective." The observable result is that these are mutually exclusive values of the same field, so a draft that writes "effective" contradicts the source. Pending review does not demonstrate a lack of operating permission, and it does not equal approval.

3. Forcing two knowledge bases with different vector models into one association. The input is the vector model identifier of each knowledge base. The comparison is whether the identifiers match. The observable result is that different identifiers cannot be associated together. This error does not go on to invent missed recalls or redundant results; record the identifier mismatch and exclude the knowledge base.

## How to verify the setup

1. Against the hypothetical source text "Supplier A submitted a quotation on 5 March 2025, valid until 31 March 2025," input that sentence together with the draft sentence "Supplier A has confirmed supply, and the purchase quantity of 200 units is now effective." Compare whether the quotation validity period and the supply confirmation are the same fact. The observable result is that the source text states no supply confirmation, so the draft sentence is unsupported and should be marked pending verification.

2. Against the hypothetical source text "The internal purchase request states a proposed purchase quantity of 200 units, and the request status is pending review," input that sentence together with the word "effective" in the draft. Compare the values of the same field. The observable result is that "pending review" and "effective" are mutually exclusive, so the draft contradicts the source and should be returned for revision.

3. Against a hypothetical input of an empty citation array [], input that array and inspect the design of the downstream answering step. Compare whether the downstream step can continue when the citation length is zero. The observable result is that the path does not error out because of the empty array, and no claim is made that a fictional retrieval run necessarily returns an empty array.
