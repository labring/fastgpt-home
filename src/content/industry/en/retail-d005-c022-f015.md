# Omnichannel stock transfers: retrieval for procurement

## What the documents look like

Omnichannel transfer work moves goods between stores and warehouses. Its operational data comes from ERP inventory, store POS, e-commerce orders and WMS, and its daily paperwork includes transfer requests, stock snapshots, store shortage lists and transfer logistics notes. Procurement and supplier records sit upstream of the same business objects, so retrieval for this task has to handle purchase requests, supplier qualification files, quotations and goods-receipt records. These documents vary widely in length. They also mix precise identifiers such as supplier codes, material codes and contract numbers with status words such as "transferable", "pending review" and "confirmed". A retrieval step that serves this task therefore has to support both exact identifier lookup and natural-language status lookup, because either path alone can miss part of the material.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases built on different vector models cannot be associated together. During implementation, confirm the vector model identifier first, exclude any knowledge base that does not match, and record what was actually observed rather than running a cross-model search to compare missed recalls.

Semantic retrieval depends on vector distance. Full-text retrieval depends on keyword hits. Hybrid retrieval merges the two paths through RRF. ReRank performs a second ordering of candidate text. The minimum relevance value takes effect only under semantic retrieval or when result reranking is used; it is a filtering threshold and does not perform permission or entity isolation. Retrieval by itself does not constitute authorization. Forms collect values, while business verification, approval, database writes and external synchronization each need their own downstream implementation. The citation limit is measured in tokens. An empty result is output as an array of length zero, and the downstream chain still runs.

Hypothetical paper exercise sample: an internal verification document states "supplier code GYS-0417, material code WL-2291, quotation number BJ-2026-018, quotation valid until 30 June 2026, current status pending review, purchasing handler Group A". A second sentence states "this supplier has completed admission and may take part in this quarter's transfer replenishment procurement". A draft sentence awaiting judgment reads "GYS-0417 has been approved to take part in this quarter's transfer replenishment procurement". Judgment requires the same subject, the same period and the same field: the document records only "pending review" and states no admission conclusion, so the draft sentence is unsupported.

## Configuration and implementation checks

| Configuration item | Hypothetical trial starting point | Basis and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Associate only supplier-record bases that use the same vector model | Confirm the vector model identifier first, exclude non-matching bases, record the actual observation |
| Search mode | Use full-text retrieval for identifier questions and semantic retrieval for status questions | Compare the three paths against the test question; do not presume one mode suits all material |
| Citation limit | Set a starting point covering the full token length of one quotation | Chosen because a quotation carries both identifiers and a validity date and needs complete citation; compare with a shortage list holding one sentence |
| Minimum relevance | Label relevant and irrelevant samples first, then set the threshold from them | This value takes effect only under semantic retrieval or result reranking; compare against the labelled samples |
| Question optimization | Enable for multi-turn follow-ups, disable for identifier queries | Compare the original question with the optimized question and check whether the subject was altered |
| Result reranking | Enable when candidates are numerous and a rerank model is available | Rerank scores run from 0 to 1 and filter by that score; compare with results before reranking |

## Three common errors

1. Treating a retrieval hit as authorized execution. The input is a supplier record marked "pending review"; retrieval can return that record, and the return does not mean admission has been approved. The check compares the material's status field against the draft sentence's conclusion. The draft sentence is supported only when the status field explicitly states an admission conclusion.
2. Treating minimum relevance as a permission or entity filter. Given an unrelated question, retrieval may still return low-scoring content, and minimum relevance only affects whether that content is kept. The check compares returned items before and after filtering and confirms that permissions are carried by a downstream implementation.
3. Forcing knowledge bases with different vector models into one association. The input is two bases with different vector model identifiers; implementation confirms identifiers first and excludes non-matching bases. The check records the actual observation and draws no inference about missed recalls or duplicate results after a joint association.

## How to verify the setup

1. Take the hypothetical sample text "supplier code GYS-0417, material code WL-2291, quotation number BJ-2026-018, quotation valid until 30 June 2026, current status pending review" and enter the draft sentence "GYS-0417 has been approved to take part in this quarter's transfer replenishment procurement". Compare the material's status field with the draft sentence's conclusion. When the material states no admission conclusion, judge the sentence unsupported and keep the evidence gap open.
2. Take the hypothetical sample text "this supplier has completed admission and may take part in this quarter's transfer replenishment procurement" and place it beside the pending-review status record for the same subject and the same period. Compare the value in the same field. Judge a contradiction only when the same field carries explicitly mutually exclusive values; when only related-stage evidence exists, record the item as awaiting verification.
3. Use a clearly paper-based input of an empty array to check the downstream design and confirm that the chain still runs when the cited content has length zero. Compare whether the downstream node handles the empty-array branch. Do not claim that a fictional rule search necessarily returns an empty array.

This page covers only one scope: omnichannel stock transfers, procurement and supplier records, and knowledge base retrieval and recall. During operational handover, the authorization state of materials, actions and requests cannot be inferred from retrieval or from a form.
