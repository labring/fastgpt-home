# Brand concession operations: workflow routing for procurement

## What the documents look like

A brand concession inside a shopping mall accepts the mall's unified cashiering and deduction-based settlement. Sales records therefore originate on the mall POS side, while the brand ERP side reconciles against them. For inventory procurement and supplier records this produces two data lines: one for concession sales and settlement records, one for brand-side purchase receipts and supplier records.

The daily documents in this category are the joint-operation deduction contract, mall activity letters, sales receipts and monthly reconciliation statements. Updates occur daily and monthly. Workflow routing at this step fixes how form collection, user selection and the downstream retrieval, judgment or interface nodes connect, so that purchase requests and supplier record checks move along a defined path.

## Constraints at the workflow routing step

The form input node is a user-interaction node. When it triggers, the conversation enters an interaction state and the workflow state is recorded. After the user fills the required information and submits, the node collects the submitted form information and passes it to subsequent nodes. The user selection node is also a user-interaction node: it triggers the same interaction state, and when the user makes a choice the node evaluates that choice and executes the "yes" branch. Recording state is behavior of the interaction nodes; no separate global state-recording switch is documented.

Collected information must be explicitly passed to the following retrieval, judgment or interface node, and output must be compared against input item by item. Order writing, document backfill and external status synchronization require a separate business interface or a later process. Retrieval and form collection do not themselves constitute authorization.

The optional paths shown in an overall document flowchart do not mean every path executes on every request. Image retrieval requires a corresponding image input and model capability; reranking requires a model and must be enabled in settings. Libraries built on different vector models cannot be associated together; check the identifier and exclude those that do not match, then record what is actually observed.

Hypothetical paper exercise: a concession store manager submits a supplementary procurement request, attaching a supplier record page and a mall activity letter. The source text reads: "This letter confirms the March concession promotion period; expenses settle as agreed in the joint-operation deduction contract." "The supplier record page states that this supplier is the gift supplier for this promotion, and the record is valid until 30 June." The draft sentence to be judged is: "This supplier has been approved to supply for this promotion and an order may be placed on that basis." The subject, object, status and validity scope present in the source reach only the record's validity date. No ordering authorization is stated, so the draft sentence is unsupported.

## Three common errors

1. Treating form collection as authorization. In the sample, the record page states only the supplier's role and validity date, yet the draft sentence reads "has been approved to supply for this promotion and an order may be placed on that basis," mistaking collected record-page information for ordering authorization.

2. Treating a user selection branch as already executed. The user selection node executes the "yes" branch only after the user makes a choice. No selection record exists in the sample, so the procurement flow cannot be treated as having entered the ordering branch.

3. Treating a retrieval result as a permission filter. The same-vector-model requirement for libraries applies only to associating libraries of the same model. Whether the supplier record is retrievable and whether the supplier is approved to supply are two different matters; a retrieval hit does not yield authorization.

## How to verify the setup

1. Input the sample source text and the draft sentence; compare "has been approved to supply for this promotion" in the draft against "the record is valid until 30 June" in the source. When the source states no ordering authorization, the draft sentence should be judged unsupported, and the evidence gap kept open.

2. Input the sample supplementary procurement request and the user selection node; compare whether a record exists of the user making a choice. With no selection record, the "yes" branch should not be treated as executed, and the output stays pending verification.

3. Input the sample record page and the retrieval scope; compare the retrieval hit against the authorization status. A hit shows only that the record is in the library; authorization status requires confirmation through a later business interface or manual check. For an empty-result handoff, a paper input of [] can be used to check the downstream design, without claiming that a fictional-rule retrieval necessarily returns [].

This page addresses only brand concession operations / inventory procurement and supplier records / workflow routing. At operational handover, which materials, actions and requests sit in which authorization state cannot be resolved by treating retrieval or form collection as authorized execution.
