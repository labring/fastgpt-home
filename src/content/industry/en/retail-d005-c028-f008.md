# Brand livestream operations: workflow routing for procurement

## What the documents look like

A brand-run livestream room carries its own scripting, inventory, and after-sales obligations. Creator commission does not form the main cost structure, so procurement orders and supplier qualification material set the ceiling on what the room can promise. In this category the routine documents are the livestream script, the product briefing card, the shift schedule, and the post-session review. Procurement orders and supplier material sit upstream of those documents: they define the goods range that may be offered, while scripts and briefing cards organize expression inside that range. The brief records data updates at each session and at hourly frequency. That update cadence does not, on its own, justify batch synchronization or transaction-triggered mechanisms in this page.

## Constraints at the workflow routing step

The Form Input node and the User Selection node both belong to the user-interaction node family. When either node is triggered, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. The Form Input node collects required information and passes the submitted values to later nodes. The User Selection node evaluates the user's choice and executes the corresponding "yes" branch. For procurement and supplier material, routing therefore splits into steps that can actually be carried: interaction nodes obtain the field values awaiting comparison, and later retrieval, judgment, or interface nodes carry the comparison forward. Order writes, document backfill, and external status synchronization require a separate business interface or downstream process; interaction nodes do not perform those business actions themselves. Retrieval is not authorization, and semantic recall or relevance score does not enforce permission or entity isolation.

Hypothetical paper exercise: the source material reads, "Supplier A submitted a quotation on 1 March 2026, valid until 31 March 2026; the quotation states that the goods available for supply are Model A and Model B." The sentence under review reads, "As of 10 April 2026, Supplier A's supply commitment for Model A remains valid." The sentence involves a subject, an object, and a validity scope, each of which must be compared against the source text item by item.

## Configuration and implementation checks

| Configuration item | Setting or check on this page | Relation to the sample |
| --- | --- | --- |
| Form Input node | Collects supplier name, goods code, quotation date | Obtains the subject and object fields in the sample |
| User Selection node | Branch decides whether the quotation falls inside the stated validity period | Corresponds to the date comparison in the sample |
| Interaction state check | Confirm the node enters the interaction state and records state after triggering | Confirms comparison continues after interaction completes |
| Output handoff check | Pass collected fields to a later retrieval or judgment node | Compare output against input fields for consistency |
| Retrieval scope check | Confirm the target retrieval scope contains the quotation source text | Record an evidence gap when it is absent |
| External action split | Order writes and status sync connect to a separate business interface | This page performs no write or sync |

## Three common errors

1. Treating quotation validity as supply validity. The sample source states only that the quotation is valid until 31 March 2026, and states no supply period; the sentence under review merges the two.
2. Treating an interaction node as authorized execution. The Form Input node collects information and passes it along; it does not constitute procurement approval or order-write authorization.
3. Using relevance score in place of entity filtering. The relevance of a retrieval result does not exclude records for other suppliers or other goods.

## How to verify the setup

1. Enter the sample source text and the sentence under review, compare the quotation validity end date with the date 10 April 2026 in the sentence, and observe whether the sentence is found unsupported by the source text.
2. Enter the fields for Supplier A and Model A, compare whether the retrieval results fall inside the target scope containing the quotation source text, and observe whether records outside that scope appear.
3. Enter an empty-result handoff scenario, using the explicit paper input [] to check the downstream design, and observe whether the downstream treats it as no result obtained, without claiming that a fictional rule retrieval necessarily returns [].
