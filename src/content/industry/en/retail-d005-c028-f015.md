# Brand livestream operations: retrieval for procurement

## What the documents look like

Brand-run livestream rooms carry their own scripts, inventory, and after-sales work; commission structures for external talent do not dominate. For inventory procurement and supplier materials, the working documents are livestream scripts, product explanation cards, shift schedules, and livestream reviews. These draw on Douyin Shop Compass, Juliang Qianchuan, live-room comments, and transaction details, with updates each session or each hour. The same materials carry the supplying entity, the product object, the procurement stage, the quantity scope, and the authorization boundary. At the retrieval step these fields need to be treated as checkable content. A similarity score is not a category, entity, or permission filter, and retrieval is not authorization.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases with different vector models cannot be associated together. Problem optimization is optional and, when enabled, performs coreference resolution and question expansion before retrieval. Recall can use semantic retrieval, full-text retrieval, or hybrid retrieval; hybrid retrieval merges multiple result channels through RRF, ReRank performs a second ordering, and the final output passes similarity filtering and a reference cap. The output is an array of references and its length can be 0, so the downstream link still runs when nothing is found. Minimum relevance takes effect only under semantic retrieval or when result reordering is used. Image retrieval requires image input and the corresponding model capability, and reordering requires a model and is enabled by configuration; neither path runs on every request.

A hypothetical paper exercise sample: the source material reads, "This livestream session is supplied by Company A. The procurement object is Product A insulated cup. The stage is inquiry. The planned procurement quantity range is 200 to 300 units. The supply authorization awaits written confirmation by the procurement lead." The draft sentence to be judged reads, "Company A has obtained authorization to supply 300 units of Product A insulated cup." The draft turns the inquiry stage into obtained authorization, takes the upper bound of the range as the quantity, and turns a pending authorization into a completed one. The comparison checks whether the entity, object, stage, quantity range, and authorization boundary match the source. When the authorization confirmation document is missing, record the item as pending verification.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | Reason and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Associate only the procurement materials base that uses the same vector model | Check the vector model identifier first, exclude non-matching bases, and do not run cross-model retrieval |
| Search mode | Run semantic retrieval and full-text retrieval once each | Compare which materials the same draft sentence hits, then decide whether to switch to hybrid retrieval |
| Reference cap | Hypothetical starting point of 800 tokens | Test whether content stays complete using explanation cards of different lengths, and compare against a shorter cap |
| Minimum relevance | Hypothetical starting point of 0.4 | Label relevant and irrelevant samples first, then compare against adjacent values |
| Problem optimization | Enable only for multi-turn follow-ups or short questions | Compare the original question with the optimized question and check whether the entity was changed incorrectly |
| Result reordering | Enable by configuration and record scores | Reordering performs a second ordering; scores can be combined with a threshold for filtering, and permissions are checked separately |

## Three common errors

1. Treating a similarity score as an authorization filter. The erroneous input is a supply record that has authorization but a low relevance score; the comparison object is the permission field; the observable result is that the record may still be filtered out. The check confirms that minimum relevance applies only to semantic retrieval or reordering, and verifies permissions separately.
2. Writing an inquiry stage as already authorized. The erroneous input is the source material above; the comparison object is the stage and authorization fields; the observable result is that the draft sentence does not match the source. The check compares the entity, object, stage, quantity range, and authorization boundary field by field.
3. Associating knowledge bases that use different vector models. The erroneous input is two bases with different vector model identifiers; the comparison object is the model identifier; the observable result is that the association condition does not hold. The check verifies identifiers only, excludes non-matching bases, and records the actual observation.

## How to verify the setup

1. Input the source material and the draft sentence above, and compare the authorization status field. The draft sentence should be judged as unsupported; when the authorization confirmation document is missing, keep the evidence gap.
2. Input the sample that already contains "Company A, Product A insulated cup, 200 to 300 units," and compare whether full-text and semantic retrieval references preserve the entity, product, and planned procurement range. Record missing or mismatched fields; do not fabricate a procurement number, and do not write the upper bound of the range as a confirmed order quantity.
3. Input an empty-reference scenario and check the downstream design against the paper input []. Observe whether the link still runs when the reference content length is 0. Do not claim that an invented rule necessarily returns an empty array.

This page addresses only brand livestream operations, inventory procurement and supplier materials, and knowledge base retrieval and recall. Whether materials, operations, or requests are in a given authorization state at handover cannot be settled by retrieval or by a form. Documents not provided remain unknown.
