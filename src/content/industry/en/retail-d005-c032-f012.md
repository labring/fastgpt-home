# Retail checkout and loyalty: document chunking for procurement

## What the documents look like

Retail checkout and loyalty work for procurement and supplier records draws on four recurring document families: promotional price tags, membership points rules, daily checkout reports, and exception refund slips. These materials arrive from the point-of-sale system, the membership CRM, the payment platform, and the price-tag system, with updates at daily or per-shift frequency. Price tags carry a price together with an effective scope. Points rules carry entitlement conditions and their exceptions. Daily checkout reports carry shift-level cash and tender results. Exception refund slips carry a refund reason and an approval field.

For procurement and supplier records, the practical consequence is that a chunk boundary can separate a condition from the content it governs. If an effective date range is split away from the price it applies to, retrieval returns a price without its period. If a refund reason is split from its approval state, retrieval returns a reason without the state that determines whether anything was executed. Finance audit and CRM operations need to locate clauses, identifiers, and statuses in these materials, so chunking quality determines whether a retrieved passage can be traced back to its source wording.

The document structures differ sharply. Price tags are short text plus a date range. Points rules are conditional sentences plus exceptions. Daily reports are tables plus totals. Refund slips are a document header plus an approval column. Chunking has to preserve the relationship between a condition and what it constrains.

## Constraints at the document chunking step

Within a knowledge base, one group of source data can map to more than one vector. The `indexes` field in the `dataset.datas` table records the corresponding vector IDs as an array. The reference limit is expressed in tokens, not as a top-k count, because chunk lengths differ widely in mixed knowledge bases. Semantic retrieval and full-text retrieval serve different purposes: identifiers, model numbers, and proper nouns suit full-text retrieval, while natural-language questions suit semantic retrieval or hybrid retrieval. The minimum relevance value applies only under semantic retrieval or when result reranking is used. It is a filter threshold and does not perform permission or entity isolation.

A hypothetical paper exercise sample is used throughout this page. The source wording under review is: "From March 1 to March 31, 2025, members of A-class stores who purchase designated cooking oil accumulate points at double rate; on return, points already accumulated are deducted in step." The draft sentence awaiting judgment is: "Members who purchase designated cooking oil within March receive double points, and returns do not affect points." The source wording contains a subject (members of A-class stores), an object (designated cooking oil), a state (double accumulation), and an effective range (March 1 to March 31). The draft sentence removes the store scope and the return-deduction condition.

## Configuration and implementation checks

| --- | --- | --- |
| Search mode | Hybrid retrieval | Price tags contain date and category terms; hybrid retrieval covers both semantic and keyword matching. Compare identifier hit behavior against semantic retrieval alone. |
| Minimum relevance | 0.3 | Used as a starting value for this exercise to filter low-relevance fragments. Compare the number of recalled fragments against 0.5. |
| Reference limit | 2000 tokens | Used as a starting value for this exercise to cover price-tag and rule passages. Compare against 1000 to see whether conditional sentences are truncated. |
| Question optimization | Enabled | Completes references when a follow-up question asks about a price tag's effective scope. Compare short-question recall against the disabled state. |
| Result reranking | Enabled | Provides second-pass ordering when candidates are numerous. Compare the first returned item against the disabled state. |
| Segmentation method | By clause boundary | Preserves the relationship between a condition and its constraint. Compare conditional completeness against fixed-length segmentation. |

These values are starting points for a paper exercise. They are not documented defaults, and no test has been run against them.

## Three common errors

1. Treating the draft sentence "returns do not affect points" as a verified conclusion. The source wording states that points already accumulated are deducted on return. The draft sentence and the source wording take mutually exclusive values on the same subject, the same period, and the same field. Check: input the draft sentence and the source wording, compare the return-points field, and observe whether the retrieved result presents a statement opposite to the source wording.

2. Treating a successful upload as a completed retrieval update. After a material changes, the actual training and index state needs to be checked. Check: input the updated price-tag date range, compare the date range returned by retrieval, and observe whether the old date range is still returned.

3. Using minimum relevance to exclude unauthorized records. Minimum relevance is a filter threshold and does not perform permission isolation. Check: input an out-of-scope query term, compare the returned content against the authorized scope, and observe whether unauthorized material appears.

## How to verify the setup

1. Input the hypothetical source wording and the draft sentence, compare the return-points field. If the retrieved result presents both the source wording's deduction condition and the draft sentence's statement, the contradiction can be identified. If only the draft sentence is returned, check whether segmentation separated the return condition from the rest.

2. Input the price-tag date range "March 1 to March 31, 2025" and compare the returned date range. If the returned range matches the source wording, segmentation preserved the effective scope. If the start or end date is missing, adjust the segmentation boundary.

3. Input a clearly labelled paper empty result `[]` and check the downstream handling design for empty references, observing whether it follows the empty-reference path. Do not claim that a query against a fictional rule returns `[]`. When two different vector models cannot be associated together, first check the identifiers and exclude the non-matching ones, record the actual observation, and do not run a cross-model retrieval to compare missed recalls.

Across these checks, retrieval does not establish authorization. Forms collect values; business verification, approval, database writes, and external synchronization require their stated downstream implementation. A pending request is not approval, an offered option is not execution, and an unsigned termination is not a completed termination. Where the source materials do not state an error code or a system action, what remains is an unknown to be recorded rather than a deterministic failure cause.
