# Export tax rebate filings: workflow routing for procurement

## What the documents look like

Export tax rebate filing happens after goods leave the country, and its work is tax voucher matching rather than customs declaration. The data sources named in the brief are the electronic tax bureau, the export tax rebate filing system, customs electronic information, and the financial ledger. The documents handled day to day are the export tax exemption and rebate filing form, the export customs declaration form, purchase invoices, and foreign exchange receipt vouchers. For the inventory procurement and supplier records task, the core fields are supplier name, purchase invoice number, commodity name, quantity, amount, and customs declaration number. These fields need to correspond item by item with the filing form.

The update rhythm is monthly or per batch. That rhythm matters here because a workflow routing step may be triggered once for a batch of supplier records, and the interaction state it creates is tied to that run rather than to a continuous feed. A form that collects supplier fields for one batch does not by itself refresh, resubmit, or synchronize anything on a schedule.

## Constraints at the workflow routing step

The form input node is a user interaction node. When it is triggered, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. When the user fills the required information and submits, the node collects the submitted form information and passes it to later nodes. The user selection node is also a user interaction node with the same interaction-state behavior. When the user makes a choice, the node judges that choice and executes the "yes" branch. Both nodes can be added repeatedly and both trigger execution.

Two consequences follow for this task. First, collected information must be explicitly passed to later retrieval, judgment, or interface nodes, and the output must be compared item by item against the input. Second, order writing, document backfill, and external status synchronization require a separate business interface or a later process. Retrieval and form submission do not constitute authorization to execute. Submitting the rebate filing and confirming it are downstream business actions.

Hypothetical paper exercise sample. The supplier record source text reads: "Supplier: Huadong Textile Co., Ltd.; purchase invoice number: INV-2024-0356; commodity: men's cotton shirts; quantity: 1,200 pieces; amount: RMB 84,000; corresponding customs declaration number: BG-2024-1187." The proposed handover request reads: "Enter this invoice data into the current period export tax exemption and rebate filing form and submit it." The authorization status of this request is not stated in the source text. The form submission action does not replace the approval and submission authority for the rebate filing.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | How to check |
| --- | --- | --- |
| Form input node fields | Supplier name, invoice number, commodity, quantity, amount, customs declaration number | Compare each field against the purchase invoice source text |
| User selection node branches | Two options, "continue" and "pause" | Check the connection target of the "yes" branch |
| Interaction state recording | Workflow state recorded after the node is triggered | Observe state retention after the conversation enters the interaction state |
| Output handoff | Pass collected form fields to a later judgment node | Compare the passed fields with the values entered in the form |
| External operation split | Filing submission connects to a separate business interface | Confirm that an interface node and an approval step exist |
| Retrieval scope | Retrieve supplier records within the target scope that carries access rights | Check the retrieval library identifier and vector model consistency |

The starting values above are chosen for this exercise only. They are not official defaults. Each is selected because it matches a field or behavior named in the supplier record sample or in the documented node descriptions, and each is checked against that same source.

## Three common errors

1. Treating form submission as authorized execution of the rebate filing. The form input node collects information and passes it on; filing submission requires a separate business interface or approval process. Input is the proposed handover request, the comparison point is whether an approval record exists, and the observable result is that submission must not be executed when the approval record is absent.
2. Treating a retrieval result as a permission filter. A relevance score does not perform entity or permission isolation, and the same-vector-model requirement for retrieval libraries does not extend to external systems also needing the same model. Input is a retrieval request, the comparison point is the retrieval library identifier against the target scope, and the observable result is that a library with a mismatched identifier is excluded.
3. Reading interaction state recording as a global state switch. Interaction state is the behavior of the interaction nodes, and no separate global state recording switch is documented. Input is the node trigger record, the comparison point is the documented node behavior, and the observable result is that no additional switch configuration exists.

## How to verify the setup

1. Enter the supplier record source text and the proposed handover request from the hypothetical sample above. Compare the form fields against the invoice source text and observe whether the six fields correspond item by item. If the customs declaration number is missing, record it as unsupported rather than as a conflict.
2. Enter the two options of the user selection node. Compare the selection result against the connection target of the "yes" branch and observe whether selecting "continue" proceeds to the next node. If the branch connection is not configured, record it as pending verification.
3. Enter an explicit paper input of an empty result, written as []. Compare how the downstream node is designed to handle empty input and observe whether the downstream node preserves the empty value in the handoff. Do not claim that a fictional rule retrieval necessarily returns [].

Across all three checks, a judgment requires the same subject, the same period, and the same field. A contradiction exists only when one field has explicitly mutually exclusive values. Evidence that is not stated, or that only covers a related stage, is recorded as unsupported or pending verification. A pending review does not demonstrate the absence of operating authority. Signing, reaching cooperation, and contract effectiveness are three distinct facts. A quotation validity period does not indicate a supply period. Authorization or effectiveness clauses are not to be supplied in order to reach a definite answer, and the evidence gap remains open. Materials needed for a check must sit within a retrieval scope that carries access rights or within an explicit manual input; when they are missing, record the gap.
