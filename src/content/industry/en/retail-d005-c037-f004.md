# Peak-sale fulfillment: vector indexes for procurement

## What the documents look like

Peak-sale fulfillment scheduling centers on short-term peak capacity and the arrangement of people, vehicles, and sites. It differs from routine balanced replenishment across multiple warehouses. The materials handled on this page are the peak-sale forecast table, staffing rosters, courier support plans, and daily exception reports. The task sits with inventory procurement and supplier records. These materials update per peak-sale event, while exception reports update daily. Because updates are frequent, the same supplier's capacity commitment, arrival quantity, or vehicle arrangement can appear in different versions on different dates. If retrieval mixes versions from different dates, the cited content may contain both expired commitments and current-period numbers, and later procurement judgments lack a consistent basis for cross-checking.

## Constraints at the vector indexes step

Knowledge base search runs against the whole library; collections serve only to classify and manage data and do not affect search results. Knowledge bases associated for retrieval must use the same vector model; when selecting multiple knowledge bases, verify the actual model and input type first, and do not jointly associate libraries whose models differ. One set of source data can correspond to multiple indexes, and the indexes field records an array of vector IDs; index content and original content must be checked separately. Indexes are built from complete and focused information, and retrieval coverage against index length must be weighed with samples. Whether an image can be retrieved depends on whether an image description or image vector was generated at ingestion; uploading an image at query time does not itself constitute an index. Hybrid retrieval merges multiple result paths through RRF, and reranking requires a model and must be enabled by configuration; these are optional retrieval paths and not every request necessarily executes all of them. Semantic recall and relevance affect only candidate ordering and filtering; the retrieval step does not perform permission or entity isolation.

## Three common errors

1. Jointly associating knowledge bases that use different vector models. The input is two libraries with different model identifiers; the comparison action is checking the model identifiers; the observable result is that the association is excluded or the retrieval scope differs from expectation. The correct approach is to check identifiers first, exclude those that do not match, and record the actual observation, without inferring missed recalls or redundant results from cross-model retrieval.
2. Treating an image uploaded at query time as an established image index. The input is one retrieval request carrying an image; the comparison action is checking whether an image description or image vector was generated at ingestion; the observable result is that image content is not recalled or only the text portion participates in retrieval. The image index must be confirmed at the ingestion step.
3. Treating minimum relevance as a permission or entity filter. The input is one semantic retrieval request; the comparison action is checking whether returned citations are determined solely by the similarity threshold; the observable result is that unrelated business records or unauthorized records may still enter the candidate set. Retrieval does not perform authorization, and business verification must be implemented downstream.

## How to verify the setup

The following uses the same hypothetical drill sample. The source material text is: "Supplier A confirmed on May 10, 2026 that during the peak-sale period it can provide 8 box trucks per day, and this commitment applies from June 1, 2026 to June 18, 2026. A supplementary note on May 20, 2026 stated that from June 10 to June 12, due to maintenance, it can provide 5 trucks per day." The draft sentence to be judged is: "Supplier A can provide 8 box trucks per day throughout the entire peak-sale period." This sentence conflicts with the source on the subject, period, and quantity fields for the June 10 to June 12 interval, and is judged unsupported.

1. Input the source material text above and the draft sentence; compare the draft sentence's quantity against the source field for the same period; the observable result is that the retrieval citation contains the May 20 supplementary note and the draft sentence is marked as conflicting with the source.
2. Input a precise query containing only a supplier name; compare whether the returned citations contain a contract number or commitment date; the observable result is that full-text or hybrid retrieval matches the number field, and when pure semantic retrieval does not match, record it as pending verification.
3. Input a paper empty-result array `[]`; compare whether the downstream flow continues to execute; the observable result is that the citation path completes with length zero, and downstream design handles the empty citation, without claiming that a particular rule necessarily returns an empty array.
