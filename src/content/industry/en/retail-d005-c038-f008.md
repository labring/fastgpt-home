# Fresh-food concession counters: workflow routing for procurement

## What the documents look like

Fresh-food concession counters in hypermarkets are often staffed on site by a supplier, with revenue shared according to sales. This structure means that inventory procurement and supplier records involve three parties at once: the hypermarket fresh-food department, the concession supplier, and the store manager. The main data sources are the POS system, supplier delivery notes, food safety ledgers, and store stock counts. Everyday documents include the concession contract, daily sales reports, loss reports, and food incoming inspection records. Data updates by day and by batch.

For workflow routing, this matters because the interaction nodes that collect information must pass values to later retrieval, judgment, or interface nodes. The records themselves do not authorize procurement or settlement actions.

## Constraints at the workflow routing step

The Form Input node is a user-interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. The node collects required information and passes it to later nodes. The User Selection node is also a user-interaction node. When the user makes a choice, the node evaluates that choice and executes the corresponding branch.

The interaction state record is behavior of the interaction node itself. No separate global state-recording switch is documented. Collected information must be explicitly passed to later retrieval, judgment, or interface nodes, and outputs must be compared item by item against inputs. Order writing, document backfill, and external status synchronization require a separate business interface or downstream process. Retrieval and forms do not constitute authorized execution.

Hypothetical drill sample: A hypermarket fresh-food department and a concession supplier sign a concession contract for a chilled pork counter. The contract states that the supplier operates on site and receives a monthly sales-share settlement. Food incoming inspection records are completed by the supplier at each delivery and kept at the store. The store manager intends to submit a handover request to the workflow: "Please summarize this month's loss reports for the chilled pork counter and write them directly into the supplier settlement statement." The request does not attach the loss report source text, does not state the authorized signer for the settlement statement, and does not state which downstream interface carries out the write action.

## Configuration and implementation checks

| Configuration item | Setting or check for this page | Relation to the sample |
| --- | --- | --- |
| Form Input node | Enters interaction state on trigger, collects required information, passes it to later nodes after submission | Collects fields needed for the loss-report summary; does not replace settlement authorization |
| User Selection node | Executes the corresponding "yes" branch after the user makes a choice | Used to confirm whether to continue the summary; branches must be verified one by one |
| Interaction state check | State recording is interaction-node behavior; no separate global switch is documented | Checks whether the loss-report summary request is waiting or submitted |
| Output handoff check | Explicitly passes collected information to later retrieval, judgment, or interface nodes | Compares loss-report fields against fields required by the settlement statement |
| External action split | Order writing, document backfill, and external synchronization require a separate business interface or downstream process | Writing to the settlement statement must be carried by a downstream interface; the form does not perform the write |
| Hypothetical test starting point | For this exercise, the starting value for the loss-report summary count is set to 1, for comparison against the count in the loss-report source text | This starting value is a paper comparison baseline for this exercise only, not an official default |

## Three common errors

1. Treating the loss-report summary fields collected by the Form Input node as authorization to write the settlement statement. Input: the "write directly" wording in the handover request. Comparison: whether the authorized signer for the settlement statement is stated in the materials. Observable result: the authorized-signer field is missing.
2. Treating execution of the User Selection node's "yes" branch as completion of external synchronization. Input: the user's selection result. Comparison: whether a downstream interface has a record of carrying out the write. Observable result: no interface handoff record appears.
3. Treating the interaction state record as a global state switch. Input: the Form Input node trigger record. Comparison: whether an independent global state-recording setting exists. Observable result: only the interaction node itself records state.

## How to verify the setup

1. Input the handover request text from the hypothetical sample. Compare the count of loss-report source texts attached to the request against the hypothetical starting value of 1. If the loss-report source count is zero and the authorized signer is not stated, the pending-verification condition is met, and the request is not judged as authorized for writing.
2. Input the "yes" branch result from the User Selection node. Compare whether a downstream interface shows a record of carrying out the write. If no interface handoff record appears, the external-synchronization-not-executed condition is met, and the action is not judged as synchronized.
3. Input the loss-report fields collected by the Form Input node. Compare them against the field list required by the settlement statement. If that field list is not stated in the materials, the field-not-supported condition is met, and the evidence gap is preserved without inventing authorization or effective clauses.

This page addresses only the fresh-food concession counter category, inventory procurement and supplier records, and workflow routing. During operational handover, the authorization state of materials, actions, and requests must be kept distinct from retrieval or form submission.
