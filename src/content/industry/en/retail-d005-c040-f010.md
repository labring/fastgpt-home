# Customer-service knowledge: citation tracing for procurement

## What the documents look like

Inventory procurement and supplier material belongs to the front-end question-and-answer preparation layer of knowledge-base maintenance. It does not approve refunds. The typical documents are FAQ entries, reply templates, product parameter tables and escalation tickets. They draw on the customer-service system, product detail pages, after-sales issue statistics and quality spot checks, and they are maintained by customer-service supervisors, knowledge-base operators and product operators. The update cadence is weekly or monthly; this page does not depend on that cadence.

These materials answer questions about arrival time, minimum order quantity, supplier qualification and quote validity. That is why citation tracing matters here: a reply can only be checked when the material behind it can be located and compared. The knowledge-base search node returns cited content as an array, and the array length may be zero; an empty array means the output path still runs, and it does not show that the workflow terminated with an error. Linking knowledge bases requires selecting one or more knowledge bases that share the same vector model, and knowledge bases with different vector models cannot be linked together. Search output has to be passed to the answering step so that each reply can be compared against the cited source text. The minimum relevance value is a filtering threshold that takes effect only in semantic retrieval or when result reranking is used; it does not perform permission or entity isolation. A similarity score does not exclude unrelated businesses or unauthorized records, and retrieval itself is not authorization.

Hypothetical paper exercise sample, not a real record. Three source sentences: "The signature page of Supplier A's Annual Framework Agreement states that the signing date is 10 March 2025, with seals from both parties." "Clause 4.2 of that agreement states that the quote is valid for 90 calendar days from the signing date." "As of 20 June 2025, the Supplier Renewal Intention Form submitted by the procurement handler shows the status 'awaiting review by the procurement supervisor', with no signature page seen." Draft sentence to be judged: "Supplier A's agreement has been renewed, and the quote validity extends to 2026." A separate handover request: "Please have the retrieval library directly confirm that Supplier A currently holds supply qualification." Judgement requires the same subject, the same period and the same field. Signing, reaching cooperation and contract effectiveness are three distinct facts. Awaiting review does not show that an operating permission is missing, and quote validity does not indicate a supply period.

## Constraints at the citation tracing step

The search node accepts one or more knowledge bases that share the same vector model. Before retrieval, the selected knowledge bases and the document versions they contain are checked, and any knowledge base whose vector model identifier does not match is excluded. Retrieval is not authorization, so a returned citation array cannot confirm a qualification, an approval or a contract state.

Optional paths in the overall retrieval flow are not all executed on every request. Image retrieval requires an image input and matching model capability. Reranking requires a rerank model and has to be enabled in the settings. RRF is the fusion step that combines multiple retrieval channels; it is not a switch that is turned on. The thinking budget is a reasoning budget and is not the citation token limit. The minimum relevance value filters low-relevance results and does not act as a permission or entity filter. When the search node returns an empty array, downstream design can be checked with a paper input of `[]`, and that check does not establish that any particular query must return an empty array.

## Three common errors

1. Treating the minimum relevance value as a permission or entity filter. The input is one retrieval request; the comparison is between the score threshold and the record ownership field; the observation is that changing the threshold does not change the visibility of unauthorized records, and permission has to be implemented downstream.
2. Treating an awaiting-review status as already effective. The input is the Supplier Renewal Intention Form with status "awaiting review by the procurement supervisor"; the comparison is against a signature page and an effectiveness clause; the observation is that neither the renewal nor the extended quote validity is supported, and the item is recorded as pending verification.
3. Treating an empty citation array as a workflow failure. The input is the search node output `[]`; the comparison is whether the downstream node still executes; the observation is that the path runs, and no error termination can be asserted.

## How to verify the setup

1. Input the three source sentences above and the draft sentence "Supplier A's agreement has been renewed, and the quote validity extends to 2026." Compare the draft against the signing date, the validity clause and the renewal status field in the source text. The sentence is supported only when the source text states both a renewal signature and an effectiveness clause; with the current evidence gap, it remains unsupported.
2. Input the handover request "Please have the retrieval library directly confirm that Supplier A currently holds supply qualification." Compare the retrieval output against the authorization boundary. A returned citation array does not constitute authorization; the observation is that the request has to be routed to a person or to a separately implemented system, and retrieval itself does not produce a qualification confirmation.
3. Input the paper empty array `[]` and one normal citation array. Compare whether the downstream answering step runs in both cases. The observation is that both paths execute, and the empty array does not trigger an error assertion.
