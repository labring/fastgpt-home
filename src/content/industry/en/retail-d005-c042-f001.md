# Product listing reviews: procurement with HTTP integrations

## What the documents look like

For procurement in Product listing reviews, this page examines FastGPT HTTP integrations. Titles, assets, inspection reports and applicable requirements have separate evidence scopes. Procurement reading does not independently establish legal approval, product performance or supplier qualifications. The examples are hypothetical.

## Constraints at the HTTP integrations step

A procurement-source check can read titles, assets and inspection wording without legal or prohibited-word conclusions. Proposed material lacks complete requirements or supplier approval. Inspect the actual contract’s item and source coverage without assuming complete asset-library and inspection access. A described feature is not an evidenced finding, and a list establishes neither listing eligibility nor supplier admission.

## Configuration and implementation checks

| Procurement-reading check | Proposed material | Actual supporting evidence |
| --- | --- | --- |
| Report subject | Other-item inspection introduced | Inspect sample scope and remove |
| Asset status | Description separate from measured observation | No direct verified-performance claim |
| Applicable requirements | Word list is not current approval | Inspect actual criteria and evidence |
| Reading scope | Item, source and actual request | Return covers the question |
| Actual approval | Separate entry, change or release | Query is not qualification determination |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Request address and method` | The request address and method follow the external contract. |
| `Params and Headers` | Inspect parameters, headers and authentication separately. |
| Body | Where a JSON body is used, validate its structure against the external contract. |
| `Variable references` | Variables can come from global, system or upstream outputs. |
| `Debug identity fields` | Test mode lacks chatId and responseChatItemId. |

## Three common errors

Another product’s report requires item and inspection-scope checks. Asset descriptions treated as measured performance need actual observations and limitations. A word list treated as compliance approval needs the applicable requirements and approval evidence. These concern subject, source status and business judgment rather than populated fields.

## How to verify the setup

Retain item, source identity, actual request and return. Repeat with corresponding inspection or requirement material and limit conclusions to evidence. Check parameters, headers and any appropriate body under the external contract without public credentials. Procurement entries, title changes and publication need permission and real receipts. Reading establishes neither performance, satisfied legal requirements nor platform acceptance, and an empty result does not establish unqualified suppliers.
