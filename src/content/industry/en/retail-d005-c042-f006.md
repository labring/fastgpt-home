# Product listing reviews: procurement with scheduled workflows

## What the documents look like

For procurement in Product listing reviews, this page examines FastGPT scheduled workflows. Scheduled product-copy checks collect supplier wording for review before any publishing decision. The examples are hypothetical.

## Constraints at the scheduled workflows step

Suppose a supplier description contains material wording awaiting review, certification evidence is absent and a historical page concerns another product. Confirm the available trigger route and data interface, then configure requests under the real contract. A trigger does not approve copy. Pass retrieved wording with product identity to review and list the certification gap; an older page supplies no evidence for this item. No actual listing or compliance outcome is claimed.

## Configuration and implementation checks

| Scheduled product-copy check | Paper issue | Inspection |
| --- | --- | --- |
| Supplier wording | Material claim pending | Keep original wording |
| Certification | Evidence absent | List the gap |
| Historical page | Another product | Check identity/version |
| Repeated trigger | No publication inference | Find publishing receipt |
| Approval/publication | Separate downstream handling | Verify real authority |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Trigger responsibility` | Inspect the available trigger and responsible component. |
| `Data reads` | External read interfaces require explicit configuration. |
| `HTTP requests` | Construct requests and check variables against the external contract. |
| `Repeated-trigger responsibility` | Implement deduplication, idempotency and writes explicitly. |
| `Execution records` | Inspect actual triggers, inputs and business responses. |

## Three common errors

Successful reading reported as approval needs a review decision checked. Older supplier wording used for this item needs product identity and version checked. Repeated triggers reported as completed publication need publishing receipts checked. These separate access, ownership and execution.

## How to verify the setup

Retain trigger time, actual input, raw return and review gaps. Check that the returned material description is complete and belongs to this item. Approval, publishing authority, idempotency and writes require their downstream processes. Retest after evidence is supplied. Scheduling determines when collection runs without replacing source review or page operations.
