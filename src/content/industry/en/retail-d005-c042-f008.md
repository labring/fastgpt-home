# Product listing reviews: workflow routing for procurement

## What the documents look like

This page covers workflow routing for the inventory procurement and supplier material part of platform product title and detail compliance. The core materials are the product title sheet, detail page assets, the advertising prohibited-words list, and quality inspection reports. Compared with platform shipping operations, this category handles advertising truthfulness and qualification display, and does not handle parcel delivery. Materials update weekly and at each new listing. Collection can be organized by actual submission batch; update frequency on its own does not determine how a workflow is triggered, and does not exclude other trigger designs.

Three facts matter most for workflow routing. First, sources are scattered across the platform rules center, the advertising law compliance checklist, the brand asset library, and inspection agency reports, so a form input node suits one-time collection of the title sheet, assets, and report number. Second, checking extreme wording, comparing physical parameters, and replacing non-compliant assets are the three time-consuming steps, and a user selection node can confirm the handling direction between branches. Third, error consequences include product delisting, complaints, and administrative penalty risk, so the workflow must keep a manual review position and must not treat retrieval results as an approval conclusion.

## Constraints at the workflow routing step

When the form input node triggers, the conversation enters an interaction state and the workflow state is recorded. After the user fills required information and submits, the node passes that information to later nodes. The user selection node also enters an interaction state, and after the user makes a choice the corresponding "yes" branch executes. Both nodes are user interaction nodes, can be added repeatedly, and trigger execution. The documents state that these interaction nodes record workflow state, so the connection between trigger, completed interaction, and downstream continuation should be checked.

Documented limits apply to retrieval and generation. The knowledge reference limit uses the unit stated in the documentation, not a guessed item count. Only libraries with the same vector model can be associated together; different models cannot be associated together, so identifiers should be checked first and non-matching libraries excluded, without running cross-model retrieval to compare missed recall. A relevance score does not carry entity isolation or permission filtering; retrieval itself is not authorization. For empty-result handling, a paper input of [] can be used to check the downstream design. Image retrieval requires a corresponding image input and model capability, and reranking requires a model and must be enabled per settings; optional paths do not mean every request executes all of them.

Order writes, document backfill, and external status synchronization require a separate business interface or downstream process. Forms collect values; business verification, approval, database writes, and external synchronization each need their own downstream implementation.

## Configuration and implementation checks

Hypothetical drill sample: a store operator submits a title sheet with the title "the most durable stainless steel thermos on the entire internet," detail page assets containing the phrase "national-level certification," inspection report number QC-2024-0317, and supplier material marked "quotation valid until June 30, 2024." The draft sentence to be judged is "this product has obtained national-level certification and can be procured with confidence." The comparison goal is whether the subject, object, status, and validity scope of the four materials—title sheet, assets, report, and supplier material—are consistent.

| Configuration item | Basis type | Check method for this pass |
| --- | --- | --- |
| Form input node collects title sheet, assets, report number, supplier material | Documented node behavior | Check whether required fields cover the four material types |
| User selection node sets "pass / return for supplement" branches | Documented node behavior | Check the "yes" branch connection and the return branch connection |
| Retrieval library vector model identifier | Documented association condition | Check that jointly associated libraries share the same model identifier; different models are not associated together |
| Empty-result handling | Documented output condition | Use paper input [] to check the downstream branch; do not claim an empty return is guaranteed |
| Image retrieval and reranking enablement conditions | Documented optional path | Check whether an image input and a reranking model exist; skip if not enabled |
| Order writes and external synchronization | Requires a separate system implementation | Check whether the interface node exists; do not treat it as executed |

Hypothetical trial starting point: set the form required fields to one item for each of the four material types, chosen because the sample contains four material types; the comparison object is the actual number of submitted materials, and a missing item enters the return branch. This is a trial starting point, not an official default value.

## Three common errors

1. Treating a retrieval hit as procurement authorization. Check whether the title, assets, report number, and supplier material can correspond to the same product; this sample gives only a report number, not the full report or a procurement approval record. Even if the same number is matched, this cannot be described as obtained procurement authorization.
2. Treating quotation validity as approved procurement. The source gives only "quotation valid until June 30, 2024," with no procurement approval status, supply period, or current check date; these items remain separately pending, and cannot be filled in as pending review, expired, or approved.
3. Associating libraries together without checking model identifiers. First compare candidate library model identifiers, and include only libraries that match; exclude those that do not. This sample gives no library configuration, so no claim can be made that a retrieval request was sent to a non-matching library.

## How to verify the setup

1. Form input and user selection branch check. The input is the hypothetical sample's four material types and the "pass / return for supplement" choice; the comparison object is the node output and the downstream node input; the condition is met when all four material types pass to downstream nodes and the branch connections match the choice. Check how a missing item in the design connects with the interaction branch; complete forms mean only that collection finished, and do not automatically mean business approval passed. No live test was run.
2. Draft sentence check. The input is the draft sentence "this product has obtained national-level certification and can be procured with confidence"; the comparison object is inspection report number QC-2024-0317 and the supplier material quotation validity; the condition is met when the draft sentence matches the subject, object, and status of the materials. Although the asset says "national-level certification," the given report number does not contain certification proof content; that advertising claim still lacks support, and the evidence gap remains.
3. Empty-result and cross-model check. The input is paper input []; the comparison object is the downstream branch design; the condition is met when the downstream branch can accept an empty result and no guaranteed empty return is claimed. For the cross-model check, the input is the model identifiers of two libraries; the comparison object is the identifier field; the condition is met when identifiers match before joint association, and non-matching cases are excluded with the actual observation recorded.
