# Seller ratings management: workflow routing for procurement

## What the documents look like

Seller ratings and experience-score maintenance for platform stores revolves around consumer feedback collected after order fulfilment. The working documents include negative-review handling records, experience-score detail sheets, service diagnostic reports, and remediation ledgers. Their subjects are stores, orders, and after-sales tickets; their fields cover review timestamps, experience-score indicators, remediation status, and whether supporting evidence has been supplied. Data sources named in the brief include Douyin store experience scores, Tmall service indicators, JD after-sales reviews, and customer-service systems, with daily or weekly update frequency.

Inventory procurement and supplier materials enter this setting as a parallel document line: replenishment requests, supplier qualification files, and procurement handover forms. In the workflow-routing step, these two lines meet when a routing decision must distinguish what a form has collected from what a business process has actually approved. The interaction nodes documented for this step are the form input node and the user selection node.

## Constraints at the workflow routing step

The form input node is a user-interaction node. When it triggers, the conversation enters an interaction state; the workflow state is recorded, and after the user completes the interaction the workflow continues downward. The node collects required information the user fills in and passes it to later nodes. The user selection node is also a user-interaction node: when it triggers, the conversation enters an interaction state, and after the user makes a choice the node evaluates that choice and executes the "yes" branch. The interaction-state record is the node's own behavior; the documents do not describe a separate global state-recording switch, a submission-count limit, an automatic judgment, or a snapshot guarantee.

Collected values must be explicitly passed to later retrieval, judgment, or interface nodes, and outputs must be compared item by item against inputs. Order writing, document backfill, and external status synchronization require a separate business interface or subsequent process. Retrieval and form collection do not constitute authorization to execute. A pending-review status does not demonstrate that operating permission is absent.

Hypothetical paper exercise sample. A store operator submits an inventory procurement handover request. The material text reads: "The copy of Supplier A's business license is valid until 31 December 2025; the current replenishment request quantity is 200 units; the applicant has filled in the form but has not submitted it; in the remediation ledger, the negative-review attribution record corresponding to this supplier is still under review by the customer-service supervisor." The draft sentence to be judged reads: "Supplier A's qualification is valid, the replenishment request has been approved, and the order can be placed directly." Checkpoints: the license validity period covers the current date, but the unsubmitted form means the request has not entered the approval process, and a remediation-ledger record under review does not indicate that authorization is complete. This sample is an invented paper case for this page, not a real customer, company, or identity record.

## Configuration and implementation checks

| Configuration item | Type | Description |
| --- | --- | --- |
| Form input node | Interaction node | Enters interaction state on trigger, collects required information, passes it to later nodes after submission |
| User selection node | Interaction node | Executes the "yes" branch after the user makes a choice; branch connections require item-by-item verification |
| Output handoff | Manual check item | Explicitly pass form-collected information to later retrieval, judgment, or interface nodes |
| Supplier qualification validity | Manual check item | Compare the business-license validity period with the current date to judge coverage |
| Approval status field | Manual check item | Form submission and completed review are distinct facts and are recorded separately |
| External operation division | Implementation check item | Order writing, document backfill, and external status synchronization require a separate business interface |

Hypothetical starting value for this exercise: set the form submission status to "submitted" as a comparison baseline, used to check whether the approval process is incorrectly triggered under the unsubmitted state. This starting value is set for this exercise and is not an official default.

## Three common errors

1. Treating supplier information collected by the form as approved authorization. The form node collects values; business verification and approval require downstream implementation. Check: input the form field content, compare whether the approval status field shows "reviewed," and observe whether the result remains pending review.
2. Treating a retrieved supplier qualification document as a permission credential. Retrieval does not handle permission or entity isolation, and a relevance score does not constitute an entity filter. Check: input the document identifier returned by retrieval, compare whether that identifier matches the subject of this procurement request, and observe whether a mismatch is excluded.
3. Judging a remediation-ledger record under review as a negative conclusion. A record that is not stated, or that has only related-stage evidence, is unsupported or pending verification. Check: input the review status in the remediation ledger, compare whether that status is "reviewed," and observe whether it remains "under review."

## How to verify the setup

1. Using the material text in the hypothetical sample, input Supplier A's business-license validity period and the current date, compare whether the validity period covers the current date, and observe whether the result is "covered." The expectation is coverage, without claiming that this was actually tested.
2. Using the draft sentence in the hypothetical sample, input the form submission status field, compare whether that field is "submitted," and observe whether the approval process is triggered. The expectation is that it is not triggered, and the evidence gap is retained.
3. Using the remediation-ledger record in the hypothetical sample, input the review status field, compare whether that field is "reviewed," and observe whether it remains "under review." The expectation is "under review," without judging it as a negative or conflicting conclusion.
