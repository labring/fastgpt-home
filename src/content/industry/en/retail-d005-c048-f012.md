# Parcel labels and handoffs: document chunking for procurement

## What the documents look like

Handoff between warehouse dispatch and carrier pickup occurs at the point where parcels leave the warehouse, and responsibility passes with the carrier scan. This node characteristic means that material must be traceable back to a specific batch and document. The documents handled on this page are electronic waybills, handoff lists, pickup scan records, and exception parcel registrations, all organized around the primary task of procurement and supplier records. Data sources are the courier system, WMS shipment records, the GB/T courier service standard, and carrier bills. Update frequency is per batch and daily, and that frequency does not change the functional boundary of parsing and chunking described here.

Material structure and semantic completeness directly affect retrieval precision. When segmenting, conditions, explanations, and the content they constrain should stay in the same segment, so that quantities in a handoff list are not separated from the corresponding document number. Original data and retrieval indexes sit in different layers: one group of original data can map to multiple indexes, and the indexes field records vector identifiers. Retrieval operates on the whole library as the unit, and collections serve only as classification management. Semantic recall and relevance scores do not perform permission or entity isolation.

## Constraints at the document chunking step

Chunking decisions at this node must preserve the link between a batch, its handoff list, and its scan outcome. A waybill number alone does not carry the pickup state; the pickup scan record carries it. An exception registration carries the damaged quantity, and the handoff list carries the total quantity. Splitting these apart weakens the ability to answer a question about one batch.

Hypothetical paper exercise sample: the source material reads, "On 10 March 2025, carrier A picked up 120 parcels from batch B, handoff list number J-0310, of which 2 parcels had damaged outer packaging and were registered as exceptions, and the remaining 118 scanned normally." The draft sentence to be assessed reads, "All parcels in this batch have completed pickup with no exceptions." Checking requires comparing subject (batch B), period (10 March 2025), and field (pickup status and exception count): the source states 2 parcels were registered as damaged exceptions, while the draft sentence states no exceptions, so the same field holds mutually exclusive values.

The optional paths in the overall retrieval flow are not all executed on every request. Image retrieval requires a corresponding image input and model capability, and reranking requires a rerank model that is enabled according to settings. Libraries built on different vector models cannot be jointly associated; identifiers should be checked first, non-matching libraries excluded, and actual observations recorded.

## Configuration and implementation checks

| Configuration item | Relevant setting or check on this page | Explanation and comparison method |
| --- | --- | --- |
| Search mode | Semantic search, full-text search, or hybrid search | Full-text search is preferred for number-type queries; semantic search can be used for natural-language queries |
| Minimum relevance | A 0-1 value, effective only in semantic search or with reranking | A hypothetical trial starting value of 0.3 is chosen to filter low-relevance fragments; compare with 0.5 to observe changes in recall range |
| Reference limit | Measured in tokens, not top k | In mixed knowledge bases chunk lengths vary widely, so tokens control the referenced amount |
| Question optimization | Adds one model call before retrieval | Can be enabled for multi-turn follow-up; when the question is already clear, decide based on observed effect |
| Result reranking | Requires a ReRank model enabled according to settings | The rerank score is 0-1 and can be used for filtering |

The minimum relevance value is a filtering threshold, not a final ranking rule. After question optimization, hybrid retrieval, image retrieval, or result reranking are enabled, final results may pass through multi-path recall fusion and are not necessarily ordered strictly by a single vector similarity. RRF is a fusion process for hybrid results, not a switch that is turned on.

## Three common errors

1. Treating multiple indexes of the same group of original data as multiple independent data groups. Input is a chunk containing multiple indexes; compare the indexes array in MongoDB with the correspondence to original data, and observe whether the results merge into the same group.
2. Ordering hybrid retrieval results directly by vector similarity. Input is a result set that hits both semantic and full-text paths; compare the order before and after RRF fusion, and observe whether it follows the fused score.
3. Treating a successful upload as retrieval already updated. Input is changed material; compare the training state with the actual recalled content, and observe whether retrieval still returns the old version.

## How to verify the setup

1. Input the hypothetical sample source text and the draft sentence, and compare subject, period, and field for consistency. The source states 2 exceptions, the draft sentence states no exceptions, and the same field holds mutually exclusive values, so the judgment is a contradiction and the draft sentence is not supported.
2. Input handoff list number J-0310 for full-text search, and compare whether the returned content contains that number and the corresponding quantity. If the result is empty, record it as not recalled, check the index state, and do not infer a system error cause.
3. Input "pickup status of batch B on 10 March 2025" for semantic search, and compare whether the returned fragment retains the quantity and the exception condition. If the fragment contains only "scanned normally" while separating out the damage registration, judge the segmentation as incomplete and adjust chunking.

A pending review does not demonstrate a lack of operating authority. Signing, reaching cooperation, and contract effectiveness are three distinct facts. Where the source does not state a field, that field remains unknown, and the evidence gap is preserved rather than filled with an assumed authorization or effective clause.
