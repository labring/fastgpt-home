# Pinduoduo seller campaigns: vector indexes for procurement

## What the documents look like

Pinduoduo low-price campaign store operations revolve around campaign resource slots, campaign inventory, and refund-rate fluctuation. The daily materials are campaign registration forms, product cost calculation sheets, after-sales refund slips, and platform in-site messages. The procurement and supplier profile task places product and quantity definitions from registration forms, supply and price definitions from cost sheets, supplier qualifications and contact details, and the after-sales fluctuation shown by refund slips into one knowledge base for retrieval.

These materials update daily or per campaign, and the same product can carry different quantities and prices across campaign sessions. A search that recalls only by product name can return the registration quantity of another session or the quotation of another supplier. Vector model and index configuration needs to let materials for the same product, session, and supplier be distinguished, and let precise fields such as part numbers and models go through full-text or hybrid recall.

## Constraints at the vector indexes step

Knowledge bases associated for retrieval must use the same vector model. Before selecting several knowledge bases, check each library's actual model and input type, exclude libraries whose identifiers differ, and record the observation without inferring runtime results. One original data block can be associated with several indexes; index content and original content are checked separately. Indexes are written completely and focused, and retrieval coverage against index length is weighed against samples of this task.

Image retrieval depends on whether an image description index or image vector index was generated at ingestion time. Uploading an image at query time is not sufficient for the image to be retrieved; the corresponding model capability is also required. Reranking requires a ReRank model enabled per settings. Hybrid retrieval merges multiple result paths through RRF, which is a fusion process rather than a switch that can be turned on. The minimum relevance value is a filter threshold effective only in semantic retrieval or with result reranking, and it does not carry supplier entity isolation or permission isolation. The reference limit controls the maximum tokens of content referenced per search, which differs from top k. Retrieval itself does not constitute authorization; purchase ordering, supplier admission, and refund handling each require their own business verification and approval.

## Configuration and implementation checks

Hypothetical drill sample: the source material reads "Campaign registration form (session A): product Jia, registered quantity 800 units, supplier Yi, quotation valid until March 20." and "Product cost calculation sheet: product Jia, supplier Yi supply price 12.5 yuan, calculation date March 5." The draft sentence to be judged is "Supplier Yi has confirmed supply of 800 units of product Jia for session A." That sentence treats the quotation validity period and the registered quantity as a supply confirmation, while the source material states no confirmation status.

| Configuration item | Value or check method on this page | Basis and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Associate only procurement and supplier profile libraries with matching vector model identifiers | Check the model identifier library by library; exclude and record mismatches |
| Index content | Index states product, session, supplier, and quantity definition | Compare field by field against the source; cover the key distinguishing fields |
| Search mode | Part numbers, sessions, and supplier names go through full-text or hybrid retrieval | For precise fields, compare whether recalled source text contains that identifier |
| Minimum relevance | Hypothetical drill starting value 0.5, used in semantic retrieval or reranking | Compare referenced source text for the same question group at different values |
| Reference limit | Hypothetical drill starting value 2000 tokens | Compare against candidate chunk length distribution and observe reference coverage |
| Image index | Confirm at ingestion whether an image description or image vector index was generated | Check ingestion records; query-time upload does not replace the ingestion index |

The minimum relevance of 0.5 and reference limit of 2000 tokens are hypothetical drill starting values for this page. The reason is that the sample materials are short per item and several candidates from the same session need to be retained. The comparison method is the change in referenced source text for the same question group at different values. These numbers are not official default values.

## Three common errors

1. Treating a quotation validity period as a supply term. The erroneous input is the source material above together with the draft sentence. Compare the quotation validity field with the supply confirmation field and observe that the draft sentence writes "has confirmed" while no confirmation evidence exists.
2. Using minimum relevance to exclude unrelated suppliers or unauthorized records. The erroneous input treats the similarity threshold as an entity filter. Compare recalled entities before and after the threshold change and observe that the threshold does not change entity ownership; permission still requires separate verification.
3. Assuming an image is retrievable because it was uploaded at query time. The erroneous input has only a query image and no image index generated at ingestion. Compare the ingestion index record with the query result and observe that the image was not recalled, with the gap at the ingestion step.

## How to verify the setup

1. For the source material and the draft sentence: the input is the source material above and the draft sentence. Compare whether the draft sentence shares the same entity, session, and field as the source. When the draft sentence writes "has confirmed" while the source only carries a quotation validity period, judge it as unsupported and keep the evidence gap.
2. For supplier entity isolation: the input is candidates containing supplier Yi and another supplier. Compare the entity identifiers in the recalled results and confirm that the threshold setting did not change entity ownership. If isolation by supplier is required, a separate business verification implementation must be connected.
3. For empty-result handling: the input is a paper-defined empty reference array. Compare whether the downstream node is designed for a reference array whose length can be 0, and observe whether the downstream path runs through. Do not claim that a fictional rule search necessarily returns an empty array.
