# Channel receivables: workflow routing for procurement

## What the documents look like

Channel receivables collection happens after credit sales. The work centers on credit control and cash recovery rather than on matching buyers with sellers. The records involved come from finance systems, bank receipts, distributor orders and sales contracts. On a daily basis the collection team handles the receivables aging statement, the dunning letter, the credit agreement and the shipment freeze notice. The task on this page is inventory procurement and supplier records, and the workflow routing step connects interaction nodes such as form input and user selection with the retrieval, decision or interface nodes that follow. Material collected at an interaction node must be passed explicitly to the downstream node that consumes it.

## Constraints at the workflow routing step

The form input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and the workflow continues after the user completes the interaction. After the user fills the required information and submits, the node collects the submitted form information and passes it to later nodes. The user selection node is also a user interaction node. When it triggers, the conversation enters an interaction state and the workflow state is recorded. When the user makes a choice, the node evaluates that choice and executes the "yes" branch. Recording the interaction state is behavior of the interaction node itself; no separate global state-recording switch is documented, and none should be assumed. Information collected at these nodes must be passed explicitly to the later retrieval, decision or interface node, and the output must be compared item by item against the input. Order writes, document backfill and external status synchronization require a separate business interface or a later process. Retrieval and form submission do not constitute authorization to execute a business action.

Hypothetical paper exercise sample: a brand finance user checks distributor A's February 2025 aging statement in March 2025. The statement text reads: "As of 28 February 2025, distributor A is under shipment freeze for exceeding the credit limit; credit agreement number XY-2025-017; the freeze scope is limited to new order shipments." One draft sentence awaiting judgment reads: "Distributor A's credit agreement XY-2025-017 has been terminated; shipments may resume." The sample is used to check field consistency between the draft sentence and the original statement text.

## Configuration and implementation checks

| Configuration item | Type | Starting point for this exercise and explanation |
|---|---|---|
| Form input node | Documented node | Triggers the interaction state, collects required information, and passes it to later nodes after submission |
| User selection node | Documented node | Executes the "yes" branch after the user makes a choice; verify each branch connection one by one |
| Information passing check | Implementation check | Compare collected form fields against downstream node inputs item by item and confirm nothing is missing |
| Interaction state check | Implementation check | Verify the interaction node's own state-recording behavior; no separate global state switch is claimed |
| External action separation | Implementation check | Order writes, document backfill and external status synchronization require a separate business interface |
| Retrieval output handling | Implementation check | Use a paper input of [] to check the downstream design for empty results; do not claim a mandatory return of [] |

## Three common errors

1. Treating the interaction state recorded by a form input or user selection node as business authorization. In the sample, the original statement text records only that the freeze is in effect, while the draft sentence says the agreement has been terminated and shipments may resume. These are different field meanings, and collecting a freeze status through a form does not constitute termination authorization.
2. Treating a retrieval result as entity isolation or a permission filter. The sample check must use the same subject, the same period and the same field. The original statement limits the freeze scope to new order shipments, and retrieving related text does not mean that all other records for that distributor are authorized for processing.
3. Treating pending review or stage evidence as a settled conclusion. The sample draft sentence concerns termination of the credit agreement, and the statement does not record a termination clause. This is unsupported rather than a denial or a conflict.

## How to verify the setup

1. Input the sample statement text and the draft sentence, then compare whether "under freeze" and "has been terminated" share the same subject, the same period and the same field. If the two field values are mutually exclusive and the original text records no termination, the draft sentence is unsupported and the evidence gap must be recorded.
2. Input the sample credit agreement number XY-2025-017 and the freeze scope "limited to new order shipments", then compare whether the draft phrase "shipments may resume" exceeds the effective scope in the original text. If the draft sentence widens the applicable scope, mark it as inconsistent and retain the original scope.
3. Input a paper empty result of [] to check the downstream node design, then compare whether the downstream has an explicit branch for handling an empty result. If the downstream has no corresponding handling, record it as pending supplementation and do not claim that a fabricated rule always returns [].

This page addresses only channel receivables collection, inventory procurement and supplier records, and workflow routing. During operational handover, the authorization state of materials, actions and requests must be kept separate from retrieval or form submission, because neither retrieval nor a form constitutes authorization to execute a business action.
