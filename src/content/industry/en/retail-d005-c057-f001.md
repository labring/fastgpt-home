# Near-expiry markdowns: HTTP integrations for procurement

## What the documents look like

Near-expiry markdown handling tracks the shelf-life of stock rather than weighing individual order items. The working materials are near-expiry lists, discount approvals, damage reports and promotional price tags. They draw on POS stock-age data, store inspections, ERP inventory and quality inspection records, and they are updated daily or per shift. In the procurement and supplier materials task, the HTTP module carries data exchange with external systems, passing near-expiry lists, approval status and supplier information between systems. The stated update frequency is daily or per shift; this page does not derive batch synchronization or transaction-triggered behavior from it.

A discount decision depends on what the source material actually records. A near-expiry list can show a batch, a quantity and a shelf-life date while leaving the approval outcome unstated. A supplier record can name a supplier while leaving the contract number unstated. Those gaps matter when a request proposes to send an approval result to an external settlement system.

## Constraints at the HTTP integrations step

The HTTP module sends a request to a given address. Params, Headers and Body can each reference variables through `{{key}}`, and the URL can also reference variables. Variables come from global variables, system variables and preceding node outputs. Among the system variables, chatId and responseChatItemId do not exist in test mode, so an empty value during debugging is an environment difference rather than a business fault. Return values are extracted through JSON path, and when the output type is set to string, the corresponding value is converted to a JSON string.

The chat interface authenticates with an APIKey. The appId priority order is `body.appId`, then `<apiKey>-<appId>`, then the appId associated with the apikey. Passed-in `model` and `temperature` fields are ineffective because the orchestration determines them. With `detail=true`, the response contains `responseData`, which holds module status and the complete result.

Hypothetical paper exercise sample: a store inspection record dated 10 June 2025 reads "Cold cabinet A, batch 20250608, yogurt, 12 units, shelf life to 13 June 2025, status is pending discount approval." The same set of materials contains the sentence "Supplier record: this batch was supplied by Supplier B; contract number not stated." The draft handover request to be assessed reads "Please synchronize the discount approval result for batch 20250608 to Supplier B's settlement system." The source text does not state whether the batch has received discount approval, and it does not state the interface address or authorization scope of Supplier B's settlement system. The authorization boundary of this request remains unsupported.

## Configuration and implementation checks

| Configuration item | Starting point for this hypothetical exercise | Object of comparison and notes |
| --- | --- | --- |
| Request address | Enter per the external interface document | The address can reference variables; check whether it points to the target system |
| Request method | Select per the external interface document | Match the external interface contract; do not assume |
| Headers authentication | Authorization Bearer referencing a token variable | Credentials are injected through secure configuration, not written into public samples |
| Body structure | Per the external interface JSON contract | Takes effect only under the relevant request type |
| Return value extraction | Configure key and JSON path | Check that extracted values correspond to external response fields |
| Output type | String, or as needed | String converts the corresponding value to a JSON string |

These starting points are set for this paper comparison and are used to check item by item against the external interface document. They are not official default values.

## Three common errors

1. Treating an empty chatId in test mode as a business failure. This field does not exist in test mode, and the request must be checked separately from a production-environment request.
2. Treating a pending discount approval status as an approved one. The sample text states only "pending discount approval"; the approval outcome is not stated, so the synchronization request has no confirmed authorization basis.
3. Treating the return value extraction configuration as the interface return value itself. That configuration describes how to parse the response and must be compared item by item against actual response fields.

## How to verify the setup

1. Input the sample source text and the draft handover request, and compare "pending discount approval" with the phrase "synchronize the discount approval result" in the draft. When the source text does not state an approval outcome, the request remains unsupported, and the evidence gap must be recorded.
2. Input the sentence "contract number not stated" from the sample and compare whether the supplier record fields are complete. When the contract number is missing, the conditions for connecting to Supplier B's settlement system cannot be checked and remain to be verified.
3. Input one request address and Headers configuration, and compare whether the Authorization reference variable carries an actual value in a production-environment request. An absent chatId in test mode is an environment difference and is recorded separately from an authentication failure.

The primary task here is assessing whether a proposed handover request is supported by the source materials. Verification inspects specific proposed wording against the supplied source text and its stated limits. A pending approval is not an approval, an offered option is not execution, and an unsigned termination is not a completed termination. A relevance score is not a category, entity or permission filter, and retrieval is not authorization. Forms collect values; business verification, approval, database writes and external synchronization need their stated downstream implementation. Where a document field is not provided, it remains unknown.
