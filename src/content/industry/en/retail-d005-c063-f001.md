# Livestream after-sales service: HTTP integrations for procurement

## What the documents look like

Livestream after-sales work concentrates after a single session's traffic, and refund requests and reshipment orders stack up in the same window. Host promises are strongly tied to that work, so inventory procurement and supplier records have to carry the livestream order list, refund requests, reshipment orders and script templates at the same time. The material update rhythm is after each session and daily. In this page that rhythm affects when a person checks status; it does not establish batch synchronization, full synchronization or transaction-triggered behavior. Douyin Shop after-sales, customer-service IM, warehouse WMS and logistics tracking are the main data sources, and the HTTP integration carries the above material toward downstream services.

## Constraints at the HTTP integrations step

The HTTP module sends a request to the corresponding address. Params, Body and Headers can each reference variables with `{{}}`, and the URL can also reference variables. Variables come from global variables, system variables and preceding node outputs. System variables include appId, chatId, responseChatItemId, variables, cTime and histories. The histories variable takes at most 10 records by default, and its length cannot be modified. chatId and responseChatItemId do not exist in test mode, so empty values during debugging are expected rather than a fault.

Return-value configuration describes how to parse the interface response, using JSON path extraction. When the output type is set to string, the value at the corresponding key is converted to a json string. The chat interface uses APIKey authentication; when calling chat/completions, passing body.appId in the request body is recommended, and Authorization: Bearer is also supported. Passed fields such as model and temperature have no effect, because the orchestration determines them. detail=true returns intermediate values, and tokens must be calculated manually. An interactive node's returned interactive object contains only type and params; entryNodeIds, memoryEdges, nodeOutputs and nodeResponseId are not returned. Form input requires serializing an object into a string as the messages content while keeping chatId consistent. A plugin application defaults to detail mode, receives input through variables, and takes pluginOutput from the element whose moduleType is pluginOutput.

Hypothetical drill sample: on 18 June 2025, after a livestream session, an after-sales team for a livestream room organizes reshipment orders. The source material reads: "Supplier A confirms that 30 units can be reshipped before 20 June; the 12 refund requests from this session are still under platform review; the warehouse exception role has not finished counting the wrong and missing items." The proposed handover request is: "Please synchronize the above reshipment arrangement to the supplier and update inventory." That request is in a pending state and has not been authorized for execution.

## Configuration and implementation checks

| Configuration item | Relevant value or check on this page | Check method |
| --- | --- | --- |
| Request address and method | Selected per the external interface document; the address can reference a provided variable | Compare word by word against the interface document |
| Params and Headers | List request parameters and request headers separately; inject authentication credentials through secure configuration | Check that credentials are not written into public samples |
| Body | Used only under the corresponding request type; check the JSON structure against the external contract | Compare key names and types field by field |
| Variable reference | Reference a global variable, system variable or preceding node output | Check the actual passed value item by item |
| Return-value parsing | Configure key and output type per JSON path | Use the response example to verify the extraction result |
| Debugging identity fields | chatId and responseChatItemId do not exist in test mode | Confirm the empty value is expected and not treated as a fault |

## Three common errors

1. Treating a refund request under platform review as an approved refund and triggering inventory deduction on that basis. The check input is the source sentence "the 12 refund requests from this session are still under platform review"; the comparison object is the value of the refund status field; the execution condition is met only when the status is explicitly completed refund.
2. Treating Supplier A's "confirms that 30 units can be reshipped before 20 June" as a supply deadline commitment and updating the inventory quantity on that basis. The check input is that sentence; the comparison object is the commitment subject and the date range; the execution condition is met only when an explicit inventory-change authorization appears.
3. Treating the warehouse exception role's "has not finished counting the wrong and missing items" as a count result of no wrong or missing items. The check input is that sentence; the comparison object is the count status; the execution condition is met only when a completed count record appears.

## How to verify the setup

1. Using the hypothetical sample's source sentences as input, compare "synchronize the above reshipment arrangement to the supplier and update inventory" in the proposed handover request against the authorization status in the source. Observe whether an explicit authorization record appears; when no authorization record appears, the request remains pending.
2. Using the refund request status in the hypothetical sample as input, compare the status field value against "completed refund" and observe whether the deduction condition is met; when the status is under review, the condition is not met.
3. Using the supplier reshipment confirmation sentence in the hypothetical sample as input, compare the commitment subject and the date range and observe whether an inventory-change authorization appears; when no authorization appears, the inventory quantity must not be updated.
