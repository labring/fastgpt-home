# Livestream after-sales service: workflow routing for procurement

## What the documents look like
Livestream after-sales work tends to arrive in bursts after a single broadcast, and refund requests are strongly tied to what the host promised on air. For the inventory procurement and supplier records task, the materials handled include livestream order lists, refund applications, reshipment orders, and script templates. Data sources include the platform after-sales system, customer service IM, the warehouse WMS, and logistics tracking. After-sales supervisors and warehouse exception staff compare the quantity relationship between refund applications and reshipment orders, and the correspondence between supplier records and procurement records, either after each broadcast or during daily checks.

These materials can sit at different stages. A refund application may be a request awaiting review, a reshipment order may already be scheduled, and a supplier record may still lack supplier confirmation. The distinction matters because an offered option is not execution, and a pending request is not approval.

## Constraints at the workflow routing step
The form input node is a user interaction node. When it is triggered, the conversation enters an interaction state, the workflow state is recorded, and the dialog is hidden. After the user fills in the required information and submits, the node collects the submitted values and passes them to later nodes. The user selection node is also a user interaction node. When the user makes a choice, the node evaluates that choice and executes the corresponding "yes" branch. Both nodes record workflow state and wait for the user to finish interacting before the workflow continues.

For inventory procurement and supplier records, workflow routing must treat the comparison results for refund applications, reshipment orders, and supplier records as inputs or outputs of these interaction nodes. Retrieval results do not constitute authorization. Values collected by a form do not equal business approval. Order writes, document backfill, and external status synchronization require a separate business interface or a downstream process.

Hypothetical paper exercise sample: a livestream order list fragment states "Order A-2024-001, refund application R-001, reshipment order B-001, supplier S-01, procurement quantity 20 units, application date June 1, 2024." A supplier record fragment states "Supplier S-01, contact Zhang, supply category apparel, contract status pending review." A draft sentence awaiting judgment reads "Supplier S-01 has confirmed the 20-unit procurement for reshipment order B-001, and reshipment can proceed." In the check, the supplier record shows only "pending review" and contains no confirmation entry. Reshipment order B-001 and the procurement quantity of 20 units appear in the order list, but the fact of supplier confirmation is not stated.

## Configuration and implementation checks
| Configuration item | Type | Description |
| --- | --- | --- |
| Form input node | Interaction node | After triggering, enters the interaction state, collects required information, and passes it to later nodes after submission |
| User selection node | Interaction node | After the user makes a choice, executes the "yes" branch; verify branch connections one by one |
| Interaction state check | Implementation check | Recording state is behavior of the interaction node; do not posit or claim a separate global state-recording switch |
| Output handoff check | Implementation check | Explicitly pass collected information to later retrieval, judgment, or interface nodes; compare output against input item by item |
| External action separation | Implementation check | Order writes, document backfill, and external status synchronization require a separate business interface or downstream process |
| Retrieval scope check | Implementation check | Check whether the target retrieval scope contains the needed supplier records; when absent, record the gap |

Hypothetical starting point for this exercise: set the required fields of the form input node to "order number, refund application number, reshipment order number, supplier number," because these four items are used to locate materials in the sample. Compare them item by item against the fields received by later nodes, and observe whether they match.

## Three common errors
- Treating a retrieval result as authorization. In the hypothetical sample, retrieving the supplier S-01 record does not mean the supplier confirmed procurement. Compare the retrieval output against the "contract status" field in the supplier record. When the status reads "pending review," reshipment cannot proceed.
- Treating form submission as completed approval. The form input node collects required information and passes it to later nodes; the submission action itself produces no approval result. Compare the submitted form values against the confirmation entry in the supplier record. When the confirmation entry is absent, the draft sentence "has confirmed" is not supported.
- Treating the "yes" branch of the user selection node as business execution. The user selection node executing the "yes" branch indicates only the direction of the flow; it does not indicate that an order write or external synchronization has completed. Compare the branch execution record against the external interface call record. When the interface is not connected, the business action has not occurred.

## How to verify the setup
- Input the hypothetical supplier record fragment "contract status pending review," compare it against the draft sentence "Supplier S-01 has confirmed the 20-unit procurement for reshipment order B-001," and observe whether the supplier record contains a confirmation entry. When the confirmation entry is absent, the draft sentence is not supported and should be recorded as pending verification.
- Input the hypothetical order list fragment "refund application R-001, reshipment order B-001, procurement quantity 20 units," and compare whether reshipment order B-001 and the procurement quantity of 20 units correspond under the same order number A-2024-001. When the correspondence is consistent, the quantity field can be checked. When the supplier confirmation field is absent, the authorization status remains unknown.
- Input the hypothetical branch setting of the user selection node, and compare whether the downstream nodes connected to the "yes" branch include an external interface. When the downstream nodes are only retrieval or judgment nodes, order writes and external synchronization have not executed, and a separate business interface is required.
