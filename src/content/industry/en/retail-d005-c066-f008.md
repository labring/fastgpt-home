# Short-video affiliate sales: workflow routing for procurement

## What the documents look like

Short-video affiliate sales rely on long-term content exposure and product-link conversion rather than live explanation. For the procurement and supplier-record task, the material to be checked usually comes from the selected affiliate program, short-video playback data, product transaction data, and platform rules. Daily documents include short-video scripts, product lists for attached links, commission plans, and violation feedback. The update frequency given for this material is daily and weekly.

Three document types carry the states that matter here. A script may be in draft or published. An attached-link product list may mark a line as on sale or awaiting restock. A commission plan may be pending review or already effective. Supplier records may contain a quotation with no stated supply period. Workflow routing has to pass these states through as they are recorded. A pending review is not an approval, and a quotation validity date is not a supply period.

## Constraints at the workflow routing step

The Form Input node is a user-interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and after the user completes the interaction the workflow continues. The node collects required form information and passes it to later nodes. The User Selection node also triggers an interaction state and records workflow state. When the user makes a choice, the node evaluates that choice and executes the "yes" branch. Each branch connection needs to be verified individually. The interaction state is recorded by the interaction node; no separate global state-recording switch is documented.

Information collected at these nodes must be passed explicitly to later retrieval, judgment, or interface nodes, and output must be compared item by item against input. Order writing, document backfill, and external state synchronization require a separate business interface or a later process. Retrieval and relevance scores affect recall ordering only; they do not perform permission or entity isolation. Libraries built on different vector models cannot be associated together. The correct step is to check identifiers and exclude non-matching libraries, not to run a cross-model search and compare missed recalls. Knowledge-base reference limits use the unit stated in the documentation. An empty-result handoff can be checked against downstream design using a clearly specified paper input. Image retrieval requires a corresponding image input and model capability, and reranking requires a model and must be enabled by configuration. These optional paths do not all execute on every request.

Hypothetical drill sample. The material to be checked consists of three sentences. "Attached-link product list, row 7: supplier A, product is a portable juicer cup, stock status is awaiting restock, quotation valid until 30 June 2025." "Commission plan, clause 3: this product's commission rate is 18%, status is pending review." "Short-video script, sentence 12: this juicer cup is well stocked, ships the same day the order is placed." The handoff request to be judged is: "Add the row 7 product to this week's attached-link plan and synchronize the stock status." The request names a subject (supplier A), an object (portable juicer cup), states (awaiting restock, pending review), and a scope (quotation validity). The material does not state when restocking will be completed, and does not state that the commission plan has been approved.

## Configuration and implementation checks

| Configuration item | Setting or check relevant to this page | Relation to the sample |
| --- | --- | --- |
| Form Input node | Triggers the interaction state, collects required information, passes it to later nodes | Collects the restock confirmer and confirmation time |
| User Selection node | Executes the "yes" branch after the user chooses; verify each branch connection | Splits "restocked or not" into two paths |
| Output handoff check | Passes collected information explicitly to later retrieval, judgment, or interface nodes and compares item by item | Compares the stock-status field with the request field |
| Retrieval scope check | Checks identifiers and excludes cross-vector-model libraries; relevance score is not a permission filter | Excludes libraries that do not contain supplier A |
| External action split | Order writing, document backfill, and external state synchronization connect to a separate business interface | Attached-link plan execution is not performed by the node |
| Hypothetical trial starting value | This drill starts from "awaiting restock" because the material states that value, compared with "on sale" | Used only for judging this sample |

## Three common errors

1. Treating a commission plan pending review as already effective. In the sample, clause 3 records status as pending review. If commission is calculated or the attached-link plan is written on that basis, the input is a pending-review record, the comparison is against the effective condition, and the observable result is an execution action taken without approval.
2. Treating a quotation validity date as a supply period. The sample's quotation is valid until 30 June 2025, and the material does not state a restock completion time. If the quotation field is used to conclude that stock is sufficient, the input is the validity field, the comparison is against a supply-time field, and the observable result is two different fields being merged.
3. Using a relevance score in place of a permission check. The sample request requires excluding libraries that do not contain supplier A. If similarity ranking decides readability, the input is the score, the comparison is against library identifiers and access scope, and the observable result is unrelated or unauthorized records being treated as readable.

## How to verify the setup

1. Input the three sample sentences and the handoff request. Compare whether "awaiting restock" and "well stocked" point to the same field. The observable result is that the script wording and the list status disagree, so the request is not supported and a restock completion time must be supplied.
2. Input commission plan clause 3. Compare whether "pending review" and "approved" are mutually exclusive values of the same field. The observable result is that the status field records only pending review, so the commission rate cannot be used for execution, and the evidence gap is retained.
3. Input a paper empty result and the downstream node design. Compare whether the downstream declares an explicit handoff for empty input. If the downstream states no handling method, record this as unresolved rather than claiming that a rule retrieval must return an empty result.
