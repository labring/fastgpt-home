# Short-video affiliate sales: citation tracing for procurement

## What the documents look like

Short-video affiliate sales rely on long-term content exposure and product-link conversion rather than live explanation. Inventory procurement and supplier materials for this category typically arrive from selected affiliate programs, product transaction data, and platform rules, with daily or weekly update rhythms. Supplier quotations, stock quantities, and authorization status can change between versions. Citation tracing addresses a specific question: which version a stock or supplier record came from, who supplied it, and what scope it covers. During operational handover, some materials sit at pending review, some at signed, and some at effective, and these are distinct states.

The documents involved in this page include short-video scripts, product lists attached to videos, commission plans, and violation feedback. For procurement and supplier work, the relevant records are supplier quotations, stock quantity statements, authorization documents, and version histories. A citation must point back to the exact source version and field, not merely to a plausible document.

## Constraints at the citation tracing step

Retrieval runs through the knowledge base search node. That node can associate one or more knowledge bases that share the same vector model. Its citation output is an array whose length may be zero, and an empty array does not mean the workflow has errored or stopped. Hybrid search combines semantic and full-text results through RRF, which is a fusion process rather than a toggle. Reranking requires a rerank model and must be enabled by configuration. The minimum relevance value applies only under semantic search or reranking, and it is a filter threshold; it does not perform permission or entity isolation. The citation limit is measured in tokens. Knowledge bases with different vector models cannot be associated together, so identifiers must be checked first and non-matching bases excluded. Retrieval by itself does not constitute authorization, and a form collecting values does not equal approval or a database write.

A hypothetical paper exercise sample: a supplier document states, "This quotation is valid until June 30, 2025; supply scope is limited to the East China warehouse; stock quantity is 1,200 units; signing status is pending review." A draft sentence reads, "The supplier has confirmed supply and completed signing." The comparison must use the same subject, same period, and same field. The source states only a quotation validity date and a pending-review status; it does not state completed signing or a supply commitment. The draft sentence is therefore unsupported, and the evidence gap must remain recorded.

## Three common errors

1. Treating a retrieval hit as authorization. Input is a pending-review supplier document; compare the retrieval output against the authorization status field. The observable result is that citation content appears while signing status remains pending review. Check: verify the source signing status field and confirm the retrieval result is not written as effective.

2. Treating quotation validity as a supply period. Input is the sample source text; compare the validity date field against the supply scope field. The observable result is that the source contains only a quotation validity date. Check: compare field by field and confirm the draft sentence adds no supply period.

3. Treating an empty citation array as an error. Input is a paper []; compare the node output against the workflow state. The observable result is that the output path completes. Check: verify whether downstream handling is designed for an empty array, and do not infer automatic retry.

## How to verify the setup

1. Input the sample source text and the draft sentence; compare same subject, same period, same field; observe whether the draft sentence is supported by the source. The condition is met when the source states completed signing or a supply commitment; otherwise record it as unsupported.

2. Input two knowledge bases sharing the same vector model and one base with a different model; compare base identifiers; observe whether the non-matching base is excluded. The condition is met when only same-model bases are associated; record the actual observation and do not infer missed-recall results.

3. Input a paper [] and a query containing a validity-date paragraph; compare the citation output against downstream handling; observe whether the empty array path completes and whether the validity-date field appears in the citation. The condition is met when the empty array path completes and the validity-date field appears in the citation; otherwise record the gap for verification.
