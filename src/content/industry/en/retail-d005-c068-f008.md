# Group-buy presale orders: workflow routing for procurement

## What the documents look like

Presale group-buy collection takes orders first and then organizes procurement and fulfillment. This differs from leader relationship maintenance, which is a separate task. The main data comes from mini-program orders, supplier inventory, leader feedback, and warehouse delivery routing. The daily documents are the presale product table, collection results, procurement plan, and cut-off notice. The supplied brief gives an update frequency of daily and per session; this page does not derive batch synchronization, full synchronization, real-time, or transaction-triggered mechanisms from that frequency. After the cut-off, placing procurement orders and arranging sorting waves consume more time. Workflow routing must connect form collection, user selection, and downstream retrieval, judgment, or interface nodes one by one.

The Form Input node is a user interaction node. When triggered, the conversation enters an interaction state, the workflow state is recorded, and after the user completes required information and submits, the node passes the collected form information to subsequent nodes. The User Selection node is also a user interaction node. When triggered, the conversation enters an interaction state, and when the user makes a selection, the node evaluates that selection and executes the corresponding "yes" branch. Recording state during interaction is behavior of the interaction node; no separate global state-recording switch is documented. Collected information must be explicitly passed to subsequent retrieval, judgment, or interface nodes, and outputs must be compared item by item against inputs. Order writing, document backfill, and external status synchronization require a separate business interface or downstream process. Form submission does not constitute authorized execution. Retrieval and relevance scores do not carry permission or entity isolation; libraries using different vector models cannot be associated together, and identifiers must be checked first with non-matching items excluded.

Hypothetical exercise sample: a cut-off notice states, "This presale session is 10 March 2025, the object is South China warehouse leafy vegetables, the cut-off time is 18:00, and the procurement plan is pending generation." A draft sentence to be assessed reads, "Supplier materials have been reviewed and approved, procurement can be arranged." The source text contains the subject, object, and status scope, but does not state a review conclusion or an authorization boundary. That draft sentence is unsupported.

## Constraints at the workflow routing step

The interaction state belongs to the interaction nodes and is not a global control that can be toggled elsewhere. A triggered Form Input node waits for the user to complete required fields and submit before the workflow continues. A triggered User Selection node waits for the user to choose before the "yes" branch runs. Neither node performs business verification, approval, database writes, or external synchronization on its own.

The values collected by the form must be handed to specific downstream nodes. Retrieval, judgment, and interface nodes each need their input compared against the form output. If a downstream node is designed to receive a procurement plan, the routing must show how the collected session, category, and cut-off time reach that node. Where the downstream action is an order write or a document backfill, a separate business interface or subsequent process is required; the form node does not supply that.

Retrieval and relevance do not act as permission or entity filters. A similarity setting does not exclude unrelated businesses or unauthorized records. Retrieval is not authorization. Knowledge-reference limits use the documented unit, and same-model retrieval association, empty-reference output, and context limits retain their documented conditions. Libraries using different vector models cannot be associated together; the check is to verify identifiers and exclude non-matching items rather than to run cross-model retrieval and compare missed recalls.

The cut-off notice sample shows the boundary clearly. The notice names the session date, the object, the cut-off time, and the pending status of the procurement plan. It does not name a supplier review outcome, an approval, or an authorization to place procurement. A draft sentence that adds "reviewed and approved" moves beyond the source. A pending request is not approval, an offered option is not execution, and an unsigned termination is not a completed termination.

## Three common errors

1. Treating form submission as authorized execution. The sample draft sentence says "reviewed and approved, procurement can be arranged," while the source only says the procurement plan is pending generation. Submission and review conclusion are different facts.
2. Treating a user selection branch as automatic judgment. The User Selection node executes the corresponding "yes" branch after the user makes a selection. Before a selection is made, the branch must not be presumed executed.
3. Associating libraries across different vector models. Libraries using different vector models cannot be associated together. Identifiers must be checked first and non-matching items excluded; cross-model retrieval is not run to compare missed recalls.

## How to verify the setup

1. Input the sample cut-off notice source text and the draft sentence. Compare whether the draft sentence contains a review conclusion not present in the source. If "reviewed and approved" appears, the condition is not met and the sentence is recorded as unsupported.
2. Input the sample session and category. Compare whether the fields collected by the Form Input node match the source on the same subject, same period, and same field. The condition is met only when the fields match and the cut-off time also matches.
3. Input the paper empty result []. Compare whether the downstream node handles it as empty input. The condition is met when the downstream does not presuppose return content and does not claim it must return []. The actual return is recorded as an observation.

A pending review does not demonstrate the absence of operating permission. A quotation validity period does not indicate a supply period. Missing evidence remains missing, and items pending verification are not written as negations or conflicts.
