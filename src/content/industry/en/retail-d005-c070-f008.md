# Cross-border product labels: workflow routing for procurement

## What the documents look like

Work on cross-border product compliance and labelling for inventory procurement and supplier materials centres on four document types: product test reports, English-language labels, material safety data sheets, and platform prohibited-item lists. These materials are produced before listing and before import, and they carry product safety and labelling evidence. Sources include platform policy centres, testing laboratory reports, destination-country regulation libraries, and supplier materials. Updates are irregular; each new product launch can bring a new version.

For the inventory procurement and supplier materials task, workflow routing connects supplier submissions, compliance reviewer judgements, and procurement handover requests into a traceable interaction sequence. The material update rhythm describes when documents are produced. This page does not derive batch synchronisation, full synchronisation, real-time, or transaction-triggered mechanisms from it.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and after the user completes the interaction the workflow continues downward. The node collects required form information and passes it to later nodes.

The User Selection node is also a user interaction node with the same trigger and state behaviour. When the user makes a choice, the node evaluates that choice and executes the corresponding "yes" branch. Each branch connection needs separate verification.

Interaction state is recorded by the interaction node itself. No separate global state-recording switch is documented, and none should be asserted. Collected information must be explicitly passed to later retrieval, judgement, or interface nodes, and outputs must be compared field by field against inputs. Order writing, document backfill, and external status synchronisation require a separate business interface or downstream process. Retrieval and form submission do not constitute authorised execution.

Hypothetical paper exercise sample. Supplier material text: "This batch of children's drinking cups is accompanied by test report number LAB-2024-0871, report date 12 March 2024, test item phthalates, conclusion within limits; English label version V3, marked suitable for ages 3 and above; MSDS version date 20 February 2024." Draft handover request: "Please mark this batch of cups as compliant and ready for warehousing, and notify procurement to place the order." The subject is the supplier, the object is the children's drinking cup batch, the state is materials submitted, and the effective scope is limited to the report and label versions above. The materials do not state a platform prohibited-item list check result, and they do not state procurement authorisation.

## Configuration and implementation checks

| Configuration item | Setting or check in this page's sample | How input and observation work |
| --- | --- | --- |
| Form Input node | Collects supplier name, batch number, report number, label version, MSDS version | After submission, check whether all fields pass through to later nodes |
| User Selection node | Sets "materials complete / materials pending" branches | After a choice, check whether the corresponding "yes" branch executes |
| Interaction state recording | Recorded by the interaction node; no separate global switch | After triggering, observe whether the conversation enters interaction state |
| Output handover | Passes collected fields to retrieval or judgement nodes | Compare output and input fields one by one |
| External operation separation | Warehousing and ordering require a separate business interface | Check whether a corresponding interface call record exists |
| Hypothetical test starting point | This page's sample uses report number LAB-2024-0871 as the retrieval starting point | Compare word by word against the supplier material text |

The hypothetical test starting point is chosen because the report number is the only unique identifier in the sample material; it is compared against the supplier material text, not against any official default.

## Three common errors

1. Treating a retrieval hit as authorised execution. Input is the draft handover request above; the comparison object is the authorisation state in the material text; the observable result is that the text states no procurement authorisation, so the request remains pending verification.
2. Treating form submission as completed business verification. Input is the fields collected by the form; the comparison object is the supplier material text; the observable result is that the report number and label version can be matched, while the platform prohibited-item list check result is absent.
3. Treating the User Selection "materials complete" branch as warehousing permission. Input is the user selection result; the comparison object is the external operation separation requirement; the observable result is that warehousing requires a separate business interface, and the selection itself produces no warehousing action.

## How to verify the setup

1. Input the supplier material text and draft request above; compare the subject, object, state, and effective scope in the material text; the observable result is that the report number and label version match, the procurement authorisation field does not appear, and the judgement is pending verification.
2. Input the fields collected by the form; compare the report number, label version, and MSDS version in the supplier material text; the observable result is that all three can be matched, while the prohibited-item list check result is not stated, and the judgement is an evidence gap.
3. Input the User Selection "materials complete" branch; compare the external operation separation requirement; the observable result is that no warehousing interface call record exists after the branch executes, and the judgement is that no warehousing action was performed.

These are expected outcomes for the stated paper inputs, not records of completed testing. Where the material text is silent, the gap remains open.
