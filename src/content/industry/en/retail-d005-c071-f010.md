# Cross-border settlements: citation tracing for procurement

## What the documents look like

Cross-border platform settlement and foreign exchange work concerns the collection of funds for completed orders. Fraud chargeback handling sits outside this scope. The inventory procurement and supplier records task brings purchase contracts, supplier statements, payment receipts, platform settlement statements and collection reconciliation sheets onto one evidence chain. Each conclusion must trace back to specific source wording.

Source material arrives weekly or monthly. Platform settlement centers, bank statements, payment provider back ends and ERP orders supply the underlying values. The people doing this work are cross-border seller finance staff, tax accountants and platform operations staff. When citation tracing fails, profit calculation errors, tax filing deviations and cash shortfalls follow.

Citation tracing for this task means that a drafted sentence about a supplier balance, a settlement amount or a payment deadline can be checked against the exact document that supports it. The knowledge base search node returns cited content as an array, and that array can have a length of zero. An empty array still allows the output path to run; it does not mean the workflow stopped with an error.

## Constraints at the citation tracing step

Only knowledge bases that share the same vector model can be selected together for a search. When the vector model identifiers differ, the bases cannot be associated jointly. The identifiers must be checked first and non-matching bases excluded. A cross-model retrieval should not be run to compare missed recalls.

Retrieval does not perform permission or entity isolation. A similarity score is a relevance value, and it cannot serve as an authorization decision. Retrieval and forms collect values; business verification, approval, database writes and external synchronization each need their own downstream implementation. A pending review status does not establish that an operation is permitted, and an unsigned termination is not a completed termination.

A hypothetical paper exercise sample is set out here for illustration. Source wording one: "Supplier A issued a statement on 10 March 2025, recording purchase payables of USD 12,000 for February 2025, with a payment deadline of 30 April 2025." Source wording two: "The platform settlement statement for the February 2025 cycle shows a settled amount of USD 8,000, with the receiving account ending 4821." The draft sentence to be assessed is: "Supplier A's February 2025 payables have been settled in full." This sentence lacks a payment receipt or bank statement as evidence, so it is assessed as unsupported.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | Reason and comparison method |
| --- | --- | --- |
| Associated knowledge bases | One supplier records base and one settlement records base | Check that both bases carry the same vector model identifier before associating them jointly |
| Search mode | Hybrid search | Supplier names and contract numbers need exact hits, while semantic recall supplies surrounding context |
| Citation cap | 3000 tokens as the hypothetical starting point | Compare against the combined source length of one statement plus one settlement statement, then adjust |
| Minimum relevance | 0.4 as the hypothetical starting point | Compare against whether cited source wording covers the subject, amount and period |
| Question optimization | Pending check on whether to enable | A single clear question may not need it; multi-turn follow-ups call for reassessment |
| Rerank | Pending check on model availability | It takes effect only when a rerank model exists and is enabled in the settings |

Hybrid search combines semantic recall and full-text recall through RRF, which is a fusion process rather than a switch. Image retrieval requires an image input and the corresponding model capability. Rerank requires an available model and an enabled setting. The optional paths in the overall retrieval flow do not all execute on every request.

## Three common errors

1. Treating a retrieval score as a permission filter and assuming that low-scoring records have been excluded. The check takes one query and two records as input, compares the score against the authorization scope field, and observes whether score level and authorization status move together.
2. Treating an empty citation array as a retrieval failure. The check takes a clearly labelled paper input of `[]`, compares whether the downstream node still executes, and observes whether the empty array passes through the output path.
3. Writing a pending review status as approved. The check takes a handover request marked "pending review", compares the request status field against the value "approved", and observes whether the two are mutually exclusive values in the same field.

## How to verify the setup

1. Take the supplier A statement wording from the hypothetical sample together with the draft sentence. Compare whether the draft sentence is supported by a payment receipt or bank statement. When that evidence is absent, the observed result is a finding of unsupported.
2. Take the platform settlement statement wording together with the draft sentence. Compare whether the settled amount of USD 8,000 and the payables of USD 12,000 share the same subject, period and field. When the amounts do not match, the observed result is that settlement in full must not be concluded.
3. Take two knowledge bases whose vector model identifiers differ. Compare whether the identifiers match. When they do not match, the observed result is that joint association is excluded and the actual observation is recorded, without inferring a missed-recall outcome.

Each verification covers the named primary task of citation tracing for procurement records. Missing evidence stays missing, and no test, deployment, approval or refund is claimed to have occurred.
