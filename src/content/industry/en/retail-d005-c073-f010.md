# Cross-border payment reviews: citation tracing for procurement

## What the documents look like

Cross-border independent-site payment risk control revolves around card network disputes and receiving accounts. The working materials are chargeback notices, fraudulent order lists, invoices, and proof of delivery. These come from payment backends, order systems, carriers, and customer service email, and they update daily or per order. For inventory procurement and supplier records, the traceable scope must also cover purchase contracts, supplier quotations, invoices, and signed delivery receipts, so that each citation can be traced back to a specific document. A single document may carry only part of the needed fields, and missing parts stay unknown.

## Constraints at the citation tracing step

Knowledge base search can associate one or more knowledge bases that share the same vector model, and it outputs citations as an array whose length may be zero. An empty array means the output path still completes. Minimum relevance takes effect only in semantic retrieval or when result reranking is used, and it is a filter threshold. The same-vector-model requirement applies to knowledge base association; it does not extend to external business registration systems or supplier portals.

Hypothetical drill sample: the source text to be checked reads, "Supplier A submitted a quotation on March 1, valid through March 31. The buyer replied on March 5 that it intended to purchase; no contract has been signed. The warehouse received the goods on April 2, and the receipt states a quantity of 200 units." The draft sentence to be judged reads, "Supplier A has completed delivery under the contract, and payment is authorized." That sentence carries three facts: contract signing, completed delivery, and payment authorization. The source text contains only a quotation, an intent to purchase, and a signed receipt record, none of which support those conclusions.

## Configuration and implementation checks

| Configuration or check item | Hypothetical starting point for this drill | Reason for the choice and comparison object |
| --- | --- | --- |
| Associated knowledge bases | Only supplier-record bases sharing one vector model are selected | Compare against the identifier of a base using a different vector model, and exclude the mismatched one |
| Citation limit | A hypothetical starting value in tokens | Compare against the total length of the sample material, and observe whether citations are truncated |
| Minimum relevance | A hypothetical starting value between 0 and 1 | Compare against the rerank score or semantic score, and observe whether low scores are filtered |
| Question optimization | Enabled only for multi-turn follow-ups and short questions | Compare against a single clear question, and observe whether latency increases |
| Result rerank | Enabled or not according to actual model capability | Compare against unranked results, and observe ordering changes |
| Citation output handoff | Pass the citation array to the answering step | Compare against the answer content item by item, and check correspondence to the source text |

## Three common errors

1. Treating retrieval output as an authorization basis. Retrieval returns citation content only; payment authorization, contract signing, and completed delivery each require a separate system implementation or manual approval. Check: input the sample source text and the draft sentence, compare whether the authorization wording in the draft appears in the source text, and mark any absent wording as unsupported.
2. Treating a quotation validity period as a supply deadline. Quotation validity and supply deadline are different fields. Check: input the quotation source text, compare the validity date with the receipt date, and record the result as pending verification rather than as a mutually exclusive value of one field.
3. Treating a pending-review status as missing operating permission. Pending review is not a denial, and it does not show that permission is absent. Check: input the status field in the handover request, compare whether it states an authorization conclusion, and record an evidence gap when none is stated.

## How to verify the setup

1. Citation source check. Input the three sample source sentences and the draft sentence, compare whether each clause of the draft has a corresponding statement in the source text, and satisfy the condition only when each clause corresponds; keep unmatched parts as unsupported.
2. Empty-result handoff check. Input a paper-based hypothetical citation array of [], compare whether the downstream design continues to execute, and satisfy the condition only when the downstream does not stop because of the empty array.
3. Cross-model association check. Input the identifiers of two knowledge bases using different vector models, compare whether the identifiers match, and satisfy the condition only when the mismatched one is excluded and the actual observation is recorded.
