# Creator commission settlement: workflow routing for procurement

## What the documents look like

This page covers workflow routing for inventory procurement and supplier records inside creator commission settlement and commission deduction. In this category, settlement happens after a sale, so the review focus falls on valid promotion orders and post-sale commission deductions. That is why inventory purchase orders, supplier reconciliation material, refund commission deduction details, invoices and settlement statements need to enter one routing chain.

The typical roles are finance settlement, Selected Alliance operations and creator business staff. Data update frequency is weekly and monthly, so routing works on periodic batch reconciliation rather than per-order real-time triggering. The workflow must keep material collection, branch decisions and external business actions as separate steps.

The documents involved are commission setting records, settlement statements, refund commission deduction details and invoices. A supplier reconciliation statement may show a pending review status while a refund commission deduction record for the same period shows a confirmed deduction. These two fields answer different questions and must not be merged into one authorization signal.

## Constraints at the workflow routing step

The Form Input node and the User Selection node are both user interaction nodes. When triggered, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. The Form Input node collects required information and passes it to later nodes. The User Selection node evaluates the user's choice and executes the corresponding "yes" branch. Recording the interaction state is behavior of the node itself; no separate global state-recording switch is documented.

Collected information must be explicitly passed to later retrieval, decision or interface nodes. Order writes, document backfill and external status synchronization require a separate business interface or a later process. Retrieval results do not constitute authorization, and a similarity setting does not perform entity isolation or permission filtering.

Hypothetical paper exercise sample: the source material reads "Supplier A submitted an inventory procurement reconciliation statement on 1 March 2025, amount 12,000 yuan, status pending review; the refund commission deduction details for the same period show order A refund commission of 300 yuan confirmed." The draft handover sentence to be judged is "The reconciliation statement has been reviewed and approved and may proceed to payment." When checking this sentence, the subject is Supplier A, the object is the March reconciliation statement, the status field is pending review, and payment authorization does not appear in the source text.

## Three common errors

1. Treating a pending review status as reviewed and approved. In the sample the status field is "pending review," while the draft sentence says "reviewed and approved." The input and the comparison field do not match, and the observable result is that the judgment is not supported by the source text.

2. Treating a retrieval hit as authorization. In the sample the refund commission deduction detail is confirmed, which is a different field from the reconciliation statement review status. If payment is released on that basis, the comparison object is misaligned, and the observable result is a missing authorization boundary.

3. Treating an interaction node as automatic execution. The Form Input and User Selection nodes wait for the user to complete the interaction. If the downstream path continues before the user submits, the observable result is that the branch connection did not execute under the documented condition.

## How to verify the setup

- Check one: input the sample source text and the draft sentence, compare the two values of the same field, "pending review" and "reviewed and approved." The sentence meets the condition only when the source status is changed to reviewed and approved and a payment authorization statement appears. Otherwise the evidence gap remains.

- Check two: input the reconciliation statement and the refund commission deduction detail from the sample, compare subject, period and field. Record a contradiction only when the same subject, same period and same field show mutually exclusive values. Otherwise record the item as pending verification rather than as a conflict.

- Check three: input a paper empty result [] and check whether the downstream design explicitly accepts an empty input. Do not claim that a fictional rule retrieval necessarily returns []. Also check that libraries using different vector models are not jointly associated; verify identifiers first, exclude non-matching items, and record the actual observation.
