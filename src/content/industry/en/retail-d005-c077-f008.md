# Import and export permits: workflow routing for procurement

## What the documents look like

Permit handling occurs before customs declaration and determines whether a shipment may legally be imported or exported. This timing difference places inventory procurement and supplier records in a front-end judgment role within workflow routing. The main data sources for this category are the competent commerce department system, customs commodity codes, supplier records, and customer end-use statements. Routine documents include automatic import licenses, dual-use item licenses, contracts, and product descriptions. Typical practitioners are trade compliance staff, customs affairs staff, and procurement staff. Consequences of error include inability to clear customs, breach of contract, and administrative penalties. The brief rates its confidence in these category observations as broadly accurate. Document updates are irregular and occur per shipment. This page does not derive batch synchronization, full synchronization, real-time updates, or transaction-triggered mechanisms from that update pattern.

Within workflow routing, the relevant FastGPT v4.17.2 nodes are Form Input and User Selection. Both are user interaction nodes. When either node is triggered, the conversation enters an interaction state, the workflow state is recorded, and execution continues downward after the user completes the interaction. The Form Input node collects required information and passes it to later nodes. The User Selection node evaluates the user's choice and executes the corresponding "yes" branch. The interaction state record is behavior of the interaction nodes, and no separate global state-recording switch is documented. Collected information must be explicitly passed to later retrieval, judgment, or interface nodes. Order writing, document backfill, and external status synchronization require a separate business interface or a later process. Retrieval or form collection does not constitute authorized execution. During operational handover, the authorization status of materials, operations, and requests must be distinguished.

## Constraints at the workflow routing step

The interaction state is entered when a Form Input or User Selection node triggers. The workflow state is recorded, and execution resumes after the user completes the interaction. The Form Input node gathers required fields and forwards them. The User Selection node branches on the user's choice and runs the "yes" branch. Neither node performs order writing, document backfill, or external synchronization on its own.

Hypothetical drill sample: A foreign trade enterprise procures a batch of goods that requires an automatic import license. The supplier record states: "Supplier A, supply scope includes this model, contract number pending signature, license application materials to be prepared by the purchasing party." The proposed handover request is: "Please write the procurement order directly from the supplier record and synchronize to the external system." This request involves order writing and external synchronization, which exceed the capability of the interaction nodes and require a separate business interface. The pending contract number does not constitute a signed contract.

## Configuration and implementation checks

| Configuration item | Relationship to this page's documents | Check method |
| --- | --- | --- |
| Required fields on the Form Input node | The document states required information is collected and passed to later nodes | Verify fields correspond to the inventory procurement and supplier record task |
| Branch connection of the User Selection node | The document states the "yes" branch executes after a choice | Verify each branch connection against the intended routing |
| Interaction state recording | Behavior of the interaction nodes, not a standalone switch | Check whether the interaction state is entered after triggering |
| Output handoff | Collected information is passed to later retrieval, judgment, or interface nodes | Compare each output against the corresponding input |
| Division of external operations | Order writing, document backfill, and external synchronization require a separate business interface | Check whether a corresponding downstream implementation exists |

Hypothetical trial starting point for this page: set the Form Input node's required fields to three items. The reason for selecting three is that the sample needs one item each for the subject, the object, and the status. Compare this against the number of fields actually accepted by later nodes; if the counts differ, adjust.

## Three common errors

1. Treating supplier records collected by the Form Input node as authorization to write an order. Input: the sample request "Please write the procurement order directly from the supplier record." Comparison target: the output handoff scope of the node. Observable result: the node output only passes field values and does not trigger order writing.
2. Treating the "yes" branch of the User Selection node as evidence that external synchronization has executed. Input: the branch direction after selecting "yes." Comparison target: whether an external interface node exists. Observable result: the branch connects only to later process nodes and contains no synchronization action.
3. Treating a pending contract number as a signed contract. Input: the sample wording "contract number pending signature." Comparison target: the signature status field. Observable result: the pending and signed values differ, and the signed status is not supported.

## How to verify the setup

1. Input the sample wording "Supplier A, supply scope includes this model, contract number pending signature." Compare the proposed handover request "Please write the procurement order directly from the supplier record and synchronize to the external system." Observable result: the request exceeds node capability and requires a separate interface; the judgment is pending verification.
2. Input the required-field settings of the Form Input node. Compare them against the fields actually accepted by later nodes. Observable result: matching fields pass; mismatches are recorded as gaps.
3. Input the "yes" branch connection of the User Selection node. Compare it against whether an external synchronization node exists. Observable result: if the branch does not connect to an external interface, record it as requiring separate implementation.
