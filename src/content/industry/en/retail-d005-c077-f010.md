# Import and export permits: citation tracing for procurement

## What the documents look like

Import and export permit handling occurs before customs declaration and determines whether a shipment may lawfully cross the border. The materials in daily use include automatic import licences, dual-use item licences, contracts and product descriptions. Their sources span commerce authority systems, customs commodity codes, supplier materials and customer end-use statements. These materials are updated irregularly, on a per-shipment basis. In the inventory procurement and supplier materials step, licence documents, contract clauses and product description text must be matched to their original wording so that later work on regulated-document determination and end-use statements can cite a traceable source.

The practical difficulty is that these materials come from different parties at different times. A citation has to point back to a specific document, a specific version and a specific field. The knowledge base search node outputs a citation array, and that array may have a length of zero. An empty array does not mean the workflow has errored or terminated. Retrieval itself does not constitute authorisation and does not perform entity or permission isolation. Knowledge bases that are associated together must share the same vector model; bases whose identifiers do not match should be excluded first, and the actual observation recorded. The minimum relevance value is a filtering threshold; it does not exclude unrelated business lines or unauthorised records.

## Constraints at the citation tracing step

A hypothetical paper exercise sample follows. An import-export enterprise's procurement department holds a product description supplied by a vendor. The original text reads: "This product is an industrial-grade sensor, operating temperature minus twenty to sixty degrees Celsius, intended for automated production line inspection." In the same batch of materials there is a draft application for an automatic import licence, in which the proposed wording states: "This product may be used in dual-use item related scenarios." The contract text does not record a final user or final use clause. A draft sentence now awaits determination: "According to the supplier product description, this product falls within the scope of dual-use item control." The point to check is that the product description only describes a temperature range and an inspection use; it does not mention a control classification. The draft sentence expands a use description into a control conclusion and lacks support from licence document text or a commerce authority determination.

Because the source materials are versioned and time-stamped, a citation that cannot be tied to a field cannot support a conclusion. The search node's citation output is an array; downstream handling must be checked against that array rather than assumed. Retrieval is not authorisation, and a retrieved passage is not an approval, a signed contract or a completed filing.

The citation limit uses tokens as its unit, not an item count. A thinking budget is a model thinking configuration and cannot be repurposed as a citation token limit. Rerank requires a model and must be enabled by configuration; the optional paths listed in the documentation do not mean every request executes all of them.

## Three common errors

1. Treating a use description in a product description as a basis for control classification. The product description states only a temperature range and an inspection use and records no control category; the draft sentence reaches a dual-use item conclusion directly and lacks licence document support. In checking, input the product description original text and the draft sentence, compare whether the two contain mutually exclusive values for the same field, and observe whether the draft sentence introduces a classification conclusion absent from the original.

2. Treating a retrieval hit as authorisation or completed approval. A citation array returned by search only indicates that text was recalled; it does not mean a licence has been granted or a contract has taken effect. In checking, input the retrieval output and the approval status record, compare whether the cited content corresponds to an approval field, and observe whether any statement treats a cited entry as proof of approval.

3. Forcing knowledge bases with different vector models into a joint association. Cross-model association is outside the documented supported scope; identifiers must be checked first and mismatches excluded. In checking, input the vector model identifiers of the bases to be associated, compare whether the identifiers are consistent, and observe whether any base with a mismatched identifier was still added to the association. Do not run a cross-model retrieval to compare missed recalls.

## How to verify the setup

1. Input the product description original text, the licence draft sentence and the draft sentence awaiting determination from the hypothetical sample. Compare whether the conclusion of the draft sentence can be matched to a statement with the same subject and the same field in the product description or the licence original text, and observe whether the draft sentence contains a control classification not recorded in the original. If the original contains only a use description, record the conclusion as unsupported.

2. Input the citation array output by the search node. Compare the array length and the cited content item by item against the original text, and observe whether downstream handling still proceeds as designed when the array is empty. Use the paper input `[]` to check the downstream design; do not claim that a particular retrieval will necessarily return an empty array.

3. Input the vector model identifiers of the knowledge bases to be associated. Compare whether the identifiers are consistent, and observe whether bases with mismatched identifiers are excluded and recorded. For bases with matching identifiers, observe whether the cited content includes a licence document original fragment; do not guarantee a first hit or a complete recall.

The checks above are paper-based reasoning and no retrieval, approval or signing has been carried out. Whether a licence is granted, whether a contract takes effect and whether a final use falls within a controlled scope all require valid-version materials together with a competent authority determination; where evidence is missing, it remains pending verification.
