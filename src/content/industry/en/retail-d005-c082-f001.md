# Returned-goods inspections: procurement with HTTP integrations

## What the documents look like

For procurement in Returned-goods inspections, this page examines FastGPT HTTP integrations. Parts procurement after return inspection separates item identity, grading and supply state. A shared model establishes neither inspected condition nor available parts. The examples are hypothetical.

## Constraints at the HTTP integrations step

A proposed parts request supplies only a product model. Return grading awaits review, work wording requests an accessory and supplier confirmation is absent. Establish how the real contract distinguishes a returned item from a procurement subject instead of guessing identity from the model. Required accessories describe demand, not stock. Pending grading cannot become permission to adopt or resell. Interpret returned passages individually without filling gaps through a shared model name.

## Configuration and implementation checks

| Return-parts reading | Proposed identity and state | Evidence needed |
| --- | --- | --- |
| Product model | Insufficient item identity | Actual return relationship |
| Grading record | Review pending | Not purchasing release |
| Work note | Accessory required | Not confirmed supply |
| Return scope | Current versus other item | Actual response |
| Formal operation | Parts and orders separate | Query completes no inspection |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Request address and method` | The request address and method follow the external contract. |
| `Params and Headers` | Inspect parameters, headers and authentication separately. |
| Body | Where a JSON body is used, validate its structure against the external contract. |
| `Variable references` | Variables can come from global, system or upstream outputs. |
| `Debug identity fields` | Test mode lacks chatId and responseChatItemId. |

## Three common errors

Same model promoted to same item needs item correspondence beside the actual request. Pending grading promoted to release needs the real decision. Accessory demand promoted to available stock needs actual supplier confirmation. These inspect identity, decision and supply stage independently of nonempty records.

## How to verify the setup

Retain source subjects, transmission and response. Add item correspondence and inspect whether another object still returns. A newly obtained work request leaves supply unresolved. Check parameters, headers and appropriate body under the real read contract without assuming warehouse or procurement integration. Parts purchasing, stock classification and order creation need separate authority and receipts. Reading completes no inspection and establishes neither saleability nor part compatibility.
