# Returned-goods inspections: scheduled workflows for procurement

## What the documents look like

Returned-goods inspections handle inbound reverse parcels and item grades. They do not handle outbound picking or packing for new orders. The main data sources are the WMS returns module, platform after-sales records, carrier return parcels, and the inspection bench. Daily documents include the returns inbound note, inspection photos, the grade determination sheet, and the resale listing note. Updates occur per item and per day.

For scheduled workflows, per-item updates mean each trigger reads a scope defined by the current day or a named batch of returns inbound notes. Inspection photos and grade determination sheets exist as attachments or linked records. The resale listing note is a downstream document produced after inspection is complete. Procurement and supplier records supply supplier ownership, purchase batch, and return-responsibility party information used in grade decisions and later stock handling. A scheduled task reads these documents. The read itself does not establish a connection to a business system, and it does not constitute authorization.

## Constraints at the scheduled workflows step

Trigger responsibility must be stated: whether the application's scheduled capability or an external scheduler performs the trigger, checked against the actual version's available entry points. Data is read through a configured interface. A scheduled trigger does not by itself create a connection to the WMS, platform after-sales, or carrier systems. HTTP requests are checked against the external interface document for method, headers, body, and variable inputs. Deduplication, idempotency, and business writes require explicit design in the interface or a later step. Execution records are checked for trigger time, actual input, returned result, and business state.

Hypothetical drill sample: a returns inbound note R-20250310-007 dated 10 March 2025 from an after-sales warehouse, supplier named as a certain East China supplier, item being a model of small home appliance, inspection bench note reading "housing scratched, function normal," grade determination sheet initially judged "Grade B, resalable." In the same batch, returns inbound note R-20250310-008 has an inspection photo showing "screen shattered," and its grade determination sheet is marked "pending review." The proposed handover request reads: "Have the scheduled task read the day's returns inbound notes and grade determination sheets at 18:00 daily, and write Grade B records into the resale listing note."

This request involves two actions, reading and writing. The read scope, interface address, authentication method, and write target are not given in the request. R-20250310-007 has an initial grade judgment; R-20250310-008 is pending review. Pending review does not mean an operating permission is missing. An initial judgment does not mean resale has been approved.

## Configuration and implementation checks

| Configuration item | Hypothetical trial starting point | Note and comparison method |
| --- | --- | --- |
| Trigger method | External scheduler, 18:00 daily | Check the application's scheduled capability or external scheduler entry point and confirm which is actually available |
| Data read interface | Returns inbound note query interface | Check method, headers, body, and variable references against the interface document |
| Read scope | Same-day returns inbound notes | Compare with actual fields in the WMS returns module; confirm the date field and the state field |
| Write target | Resale listing note interface | Check whether the interface exists, whether it accepts Grade B records, and whether human confirmation is required |
| Authentication | Bearer token | Check the Authorization header format against the interface document |
| Execution record | Trigger time and returned result | Check whether actual input, returned state, and business state agree |

The values in the table are hypothetical trial starting points chosen to allow comparison with the day's document scope. They are not official defaults.

## Three common errors

1. Treating the scheduled trigger as an established business-system connection. Input is the hypothetical request phrase "the scheduled task reads the day's returns inbound notes." The comparison point is whether a returns inbound note query interface and authentication information have been configured. The observable result is an interface call record or its absence. When absent, record the gap and do not infer that a connection exists.

2. Treating a pending-review grade determination as writable into the resale listing note. Input is the "pending review" mark on R-20250310-008. The comparison point is whether that record meets the write condition. The observable result is whether the write request contains that note number. Pending review does not mean approval has been given.

3. Mixing the date field in the read scope with the document's own date field. Input is "same day" in the hypothetical request and the date on R-20250310-007. The comparison point is whether the interface date field and the document date field are the same field. The observable result is whether returned records fall within the named date range. When the field is not stated, record it as pending verification.

## How to verify the setup

1. Using hypothetical samples R-20250310-007 and R-20250310-008, input is the original text of both returns inbound notes and their grade determination sheets. The comparison point is whether the interface response contains both notes and whether their state fields are respectively the initial judgment and pending review. The condition is met when the returned records match the originals and the state fields have not been rewritten.

2. Using the write action from the proposed handover request, input is a write request to the resale listing note interface. The comparison point is whether the request body contains only approved records and whether it contains R-20250310-008. The condition is met when the pending-review record does not appear in the write request and the interface result can be checked against business state.

3. Using "18:00 daily" from the hypothetical request, input is the trigger configuration and execution records. The comparison point is whether trigger time, actual input, and returned result agree. The condition is met when an execution record can be matched to a specific trigger time and input scope. When it cannot be matched, record it as pending verification.
