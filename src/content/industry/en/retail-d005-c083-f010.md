# Store counts and loss control: citation tracing for procurement

## What the documents look like

Store counts and loss control examine book-to-physical differences and shrinkage. The working records are count sheets, variance analyses, write-off approvals and monitoring retrieval logs. Supplier account settlement sits outside this scope. When inventory procurement and supplier material enters a retrieval chain, a citation must lead back to a specific document and version.

Data sources named in the brief include POS inventory, WMS, the monitoring system and the SB/T count standard. Typical roles are the store loss-prevention department, the store warehouse keeper and financial audit. Count sheets and variance analyses update monthly or quarterly, so citation tracing has to separate the current version from historical versions. The same SKU can carry a different variance conclusion in a different document version, and a citation has to state which version it came from.

## Constraints at the citation tracing step

The knowledge base search node can associate one or more knowledge bases that share the same vector model. Its output is a citation array whose length may be zero. A zero-length array does not mean the workflow has errored and stopped; the output path still runs. Citation content is handed to the answering step and checked line by line against source text. The minimum relevance value is a filter threshold that applies only during semantic retrieval or result reranking, and it does not perform permission or entity isolation. The same-vector-model requirement constrains which knowledge bases may be associated together. It does not extend to business-registration sites or other external systems.

Hypothetical paper exercise sample. A store count sheet dated March 2025 records: "Puffed snack A, book quantity 120 units, physical count 113 units, variance 7 units, status is pending variance review." The variance analysis for the same month records: "Puffed snack A variance 7 units, cause under investigation, no write-off submitted." A draft sentence reads: "Puffed snack A variance of 7 units has been confirmed as a write-off." Judging whether the draft sentence has source support: both the count sheet and the variance analysis show a pending-review, no-write-off state. The draft sentence turns a pending review into a completed write-off, so it is unsupported.

## Three common errors

1. Treating minimum relevance as a permission filter. Similarity affects ranking and filtering only; it does not exclude unrelated business lines or unauthorized records. Check: input the same query at different relevance values, compare the returned record count, and observe whether records from a non-target store still appear.
2. Treating an empty citation array as an error. The node output length may be zero and the path still runs. Check: input the paper value `[]`, compare whether the downstream node continues executing, and observe whether any interruption appears.
3. Writing a pending-review state as a completed write-off. Both the count sheet and the variance analysis show pending review, while the draft sentence states a confirmed write-off. Check: input the two source texts and the draft sentence, compare the status fields, and observe whether the draft sentence matches the source text.

## How to verify the setup

1. Input the source text of the hypothetical count sheet and variance analysis. Compare the draft sentence "confirmed as a write-off" against the source wording "pending variance review" and "no write-off submitted." If the draft sentence state differs from the source state, the sentence is unsupported.
2. Input the same query at minimum relevance 0.3 and 0.5. Compare the returned count and content. If records from a non-target store still appear at the higher threshold, relevance has not produced isolation.
3. Input the paper empty array `[]`. Compare whether the downstream answering node continues executing. If the downstream path still runs and returns an empty-citation notice, the empty-result handling matches the documented description.

For knowledge bases with different vector models, check the identifier first and exclude those that do not match; do not run a cross-model retrieval comparison. Image retrieval requires an image input and model capability, and reranking requires a model enabled in the settings. Signing, reaching cooperation and contract effectiveness are three distinct facts, and a quotation validity period does not indicate a supply period. Evidence gaps remain open for verification.
