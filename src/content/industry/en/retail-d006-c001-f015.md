# B2B marketplaces: retrieval for staff training

## What the documents look like

B2B marketplace matching relies more on online certification and electronic contracts than wholesale market stall trading, and it does not depend on a physical stall. The working materials for store service and internal training are enterprise certification files, inquiry and quotation sheets, electronic contracts, and platform settlement statements. These materials update daily and per order, so a training answer can go stale if it is written from memory rather than from the current document.

The three most time-consuming activities in this category are reviewing enterprise identity, matching inquiries and quotations, and tracking fulfillment. Store service and internal training route these three question types into knowledge base retrieval, and the retrieval output feeds directly into training answers and handover notes. Within one batch of materials, fields such as entity name, unified social credit code, contract number, quotation validity period, and settlement cycle sit in different documents. Retrieval recall must return to the source text for verification. A retrieval hit is not an audit conclusion and is not an authorization basis.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases built on different vector models cannot be associated together; the model identifier must be checked first, non-conforming bases excluded, and the actual observation recorded. Search mode is compared across semantic, full-text, and hybrid retrieval using the same test question, and no single mode is presumed suitable for all materials. The citation cap is measured in tokens. The minimum relevance score takes effect only in semantic retrieval or when result reranking is used. Question optimization performs coreference resolution and question expansion.

Hybrid retrieval merges multiple result paths through RRF. Reranking requires a model and must be enabled according to configuration. Image retrieval requires a corresponding image input and model capability. Retrieval is recall; it does not carry permission or entity isolation. Pending review, quoted, and signed are separate facts and cannot be derived from one another.

### Hypothetical exercise sample

Source text one (inquiry and quotation sheet excerpt for internal training): "Supplier A submitted a quotation for model A-100 on 10 March 2025, the quotation is valid until 31 March 2025, and the purchasing party has not yet confirmed."

Source text two (platform settlement statement excerpt): "Settlement statement number JS-2025-0312, corresponding contract number HT-2025-0308, settlement status pending review."

Draft sentence to be judged: "Supplier A has reached cooperation with the purchasing party, and model A-100 will be supplied at the quoted price until 31 March 2025."

Checkpoints: the quotation validity period constrains the quotation only and does not indicate a supply period. Pending review does not indicate completed settlement. The materials do not state that cooperation was reached or that the contract took effect.

## Three common errors

1. Treating a retrieval hit as an authorization or audit conclusion. The input is a "Supplier A quotation" retrieval result. The comparison object is "the purchasing party has not yet confirmed" in the source text. The observable result is whether the draft sentence contains a status such as "has reached cooperation" that the source text does not state. A status not stated in the source text is unsupported, and the evidence gap must be preserved.

2. Treating the quotation validity period as a supply period. The input is source text one. The comparison object is "valid until 31 March 2025" against "will be supplied at the quoted price until 31 March 2025." The observable result is whether the draft sentence merges two different fields into one fact. Only mutually exclusive values within the same field constitute a contradiction; a derivation across fields is unsupported.

3. Treating a pending-review settlement as a completed settlement. The input is source text two. The comparison object is "settlement status pending review" against the completed-settlement wording in the draft sentence. The observable result is whether the draft sentence writes pending review as completed. Pending review does not demonstrate a lack of operating permission, and it does not demonstrate that settlement was executed.

## How to verify the setup

1. For the draft sentence "Supplier A has reached cooperation with the purchasing party, and model A-100 will be supplied at the quoted price until 31 March 2025," input source text one and source text two. Compare whether the draft sentence contains cooperation reached, a supply period, or contract effectiveness that the source text does not state. The condition is met when the draft sentence is marked unsupported and the missing fields are recorded.

2. For retrieval scope, input the list of training material bases sharing the same vector model identifier. Compare whether any base built on a different vector model has been associated together. The condition is met when only same-model bases remain in the list and the excluded items are recorded. Do not run a cross-model retrieval to compare missed recall.

3. For empty-result handling, input a paper retrieval result of []. Compare whether the downstream design continues along the path where the citation content length can be 0. The condition is met when the downstream does not treat the empty result as a retrieval failure or as an authorization pass. Do not claim that a fictional-rule retrieval necessarily returns [].

This page addresses only B2B marketplace matching, store service and internal training, and knowledge base retrieval and recall. During operational handover, which materials, operations, and requests sit at which authorization status must be identified separately. Retrieval and forms are not authorization execution. Semantic recall and relevance scores do not carry permission or entity isolation. The same-vector-model requirement for associated knowledge bases does not extend to business registration systems or other external systems.
