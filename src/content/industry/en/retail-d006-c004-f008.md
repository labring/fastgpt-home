# Temu semi-managed sellers: workflow routing for staff training

## What the documents look like

Semi-managed Temu sellers maintain overseas inventory and ship orders themselves, which separates the operating model from full-managed supply to the platform. Daily materials include the product declaration form, the overseas inventory table, the price declaration, and the platform fulfillment order. Updates occur daily or per order. Store service and internal training need to arrange the filling, handover, and cross-checking of these materials into a repeatable workflow, so that staff follow the same material definitions when submitting a store application, synchronizing overseas inventory, and handling platform fulfillment exceptions.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and the workflow continues downward after the user completes the interaction. It collects required information, and after submission passes the collected values to later nodes. The User Selection node is also a user interaction node. When the user makes a selection, the node evaluates that selection and executes the corresponding "yes" branch. Both node behaviors are documented as existing behavior.

Workflow routing must separate four kinds of items. The first is documented node behavior, such as entering an interaction state and recording workflow state. The second is fields that can actually be configured. The third is manual cross-check actions performed by staff. The fourth is business actions that require a separate system implementation, such as order writes, document backfill, and external status synchronization, which the interaction nodes do not perform themselves. Values collected through retrieval or forms do not constitute authorization. Business verification, approval, and external synchronization each need their own downstream implementation.

Hypothetical paper exercise sample. The source material text reads: "Store A submitted the overseas inventory table on 10 March 2025, declaring SKU-001 in the Germany warehouse with an available quantity of 120 units and a status of pending regional supervisor review." The draft judgment sentence under evaluation reads: "Store A's SKU-001 overseas inventory has been approved and can be sold externally." The subject needed for judgment is Store A, the object is the SKU-001 Germany warehouse inventory, and the status field is "pending regional supervisor review." A pending review does not demonstrate the absence of operating permission and does not constitute approval. The draft judgment sentence is not supported by the material and remains to be verified.

## Configuration and implementation checks

| Configuration item | Type | Description |
| --- | --- | --- |
| Form Input node | Documented node behavior | Enters an interaction state on trigger, collects required information, passes it to later nodes after submission |
| User Selection node | Documented node behavior | Executes the corresponding "yes" branch after the user makes a selection; verify branch connections one by one |
| Interaction state cross-check | Manual cross-check action | Recording state is behavior of the interaction node; no separate global state-recording switch is set or claimed |
| Output handoff cross-check | Manual cross-check action | Pass collected information explicitly to later retrieval, judgment, or interface nodes; compare each output against its input |
| External action division | Requires separate system implementation | Order writes, document backfill, and external status synchronization need a separate business interface or later process |
| Hypothetical exercise starting point | Hypothetical value | Use "pending regional supervisor review" from the sample as the current status starting point, compared word by word against the source material; not treated as an official default |

## Three common errors

1. Treating the inventory quantity collected by the Form Input node as sellable inventory. The node collects values the user entered; business verification and inventory availability judgment need a separate downstream implementation. Check: input the sample values "available quantity of 120 units" and "status of pending regional supervisor review," compare the draft judgment sentence "has been approved and can be sold externally," and observe that the status field does not match "has been approved."
2. Treating the "yes" branch of the User Selection node as a completed business action. The node executes the corresponding branch after the user makes a selection, and branch connections must be verified one by one. Check: input the record of the user selecting "yes" in the sample, compare whether later nodes actually receive that selection result, and observe that a branch connection exists while the downstream node does not receive it.
3. Treating retrieval or form results as authorization credentials. Retrieval and forms do not handle permission or entity isolation. Check: input the draft judgment sentence "Store A's SKU-001 overseas inventory has been approved," compare it against the status field in the source material, and observe that the source text states only "pending regional supervisor review" while approval evidence is missing.

## How to verify the setup

1. For the sample source text "Store A submitted the overseas inventory table on 10 March 2025, declaring SKU-001 in the Germany warehouse with an available quantity of 120 units and a status of pending regional supervisor review," input the draft judgment sentence "Store A's SKU-001 overseas inventory has been approved and can be sold externally." Compare the subject, object, and status field against the source material. The condition is met when the judgment result states that the status field is "pending regional supervisor review," which does not match "has been approved," and that approval evidence is missing. This is the expectation, not an actual test.
2. For the same source material text, input the handover request "Please synchronize SKU-001 Germany warehouse inventory to the sales channel." Compare the request against the status recorded in the source material. The condition is met when the judgment result states that the material records only a pending review status, that the synchronization action needs a separate business interface or later process, and that the current request does not constitute authorized execution. This is the expectation, not an actual test.
3. For the same source material text, input the draft judgment sentence "Store A lacks the operating permission to submit the overseas inventory table." Compare the sentence against the source material. The condition is met when the judgment result states that the material does not record a permission field, that pending review does not demonstrate the absence of operating permission, and that the sentence is unsupported. This is the expectation, not an actual test.

For empty-result handoff, a clearly defined paper input `[]` can be used to check the downstream design; this does not claim that a fictional rule retrieval will necessarily return `[]`. Libraries using different vector models cannot be associated together. Verify identifiers first and exclude those that do not match, rather than running a cross-model retrieval to compare missed recalls.
