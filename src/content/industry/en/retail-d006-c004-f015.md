# Temu semi-managed sellers: retrieval for staff training

## What the documents look like

Temu semi-managed seller operations differ from fully managed supply in one practical respect: the seller maintains overseas inventory and arranges shipment rather than only supplying goods to the platform. Day-to-day material therefore gathers around product declaration forms, overseas inventory sheets, price declarations, and platform fulfillment orders. In store service and internal training, staff reuse retrieval results from these documents for handover notes and training answers. The brief describes update frequency as daily or per order. That frequency does not by itself add a synchronization mechanism to this page, so it is noted only as the stated cadence of the source material.

Retrieval in this task returns reference content. It does not approve, authorize, or write anything. A retrieved declaration fragment is evidence of what the declaration says, not evidence that a downstream business step has occurred.

## Constraints at the retrieval step

The knowledge base search node can be linked to one or more knowledge bases that use the same vector model. Search modes are semantic retrieval, full-text retrieval, and hybrid retrieval. Hybrid retrieval merges multiple result paths through RRF. Result reranking uses a ReRank model for a second ordering pass. The minimum relevance value takes effect only under semantic retrieval or when result reranking is used. The reference cap is measured in tokens. Retrieval output is an array, and its length can be 0, which means the output path still runs even when nothing is found.

A hypothetical drill sample is set out here for later checks. In a store training file, a product declaration fragment states: "Subject: a cross-border supplier in East China; object: the outdoor folding table of semi-managed store A; status: the declaration was submitted to the platform on 10 March 2025, and the platform receipt shows pending review; effective scope: this store and this product only." A separate internal handover draft reads: "The declaration for store A's outdoor folding table has been approved, so overseas warehouse shipment can be arranged and the inventory sheet synchronized." The question is whether the draft sentence matches the declaration text.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | Reason and comparison method |
| --- | --- | --- |
| Linked knowledge bases | Link only knowledge bases that hold product declaration forms, overseas inventory sheets, price declarations, and platform fulfillment orders under one vector model | First check whether the vector model identifiers match across bases; exclude any that do not match and do not run a cross-model search |
| Search mode | Start with full-text retrieval to test declaration numbers and status fields | Compare hits for the status value "pending review" in the sample between semantic and full-text retrieval |
| Reference cap | Set to cover the token volume of one declaration fragment | Test with declaration and fulfillment fragments of different lengths to see whether content is truncated, then adjust |
| Minimum relevance | Leave disabled until relevant and irrelevant samples are labelled | This value takes effect only under semantic retrieval or result reranking, so labelled samples are needed before setting a threshold |
| Question optimization | Start disabled and test with complete questions | Compare the original question with the optimized question and check whether the subject "store A" and the object "outdoor folding table" were altered |
| Result reranking | Use only when a ReRank model is available and enabled by configuration | The rerank score can serve as a filter basis; compare ordering against results without reranking |

## Three common errors

1. Treating retrieval output as authorization to act. In the sample, the declaration status is "pending review." Retrieving that fragment does not mean approval has taken effect, and the draft sentence "has been approved" is unsupported by the source text.
2. Treating minimum relevance as a permission or entity filter. It is a similarity threshold and does not exclude unrelated businesses or unauthorized records. Retrieval is not authorization.
3. Forcing a link across knowledge bases with different vector models. The node requires knowledge bases that share the same vector model. When model identifiers differ, exclude the base and record that fact rather than describing a combined run.

## How to verify the setup

1. Input the declaration text from the sample and the draft sentence "The declaration for store A's outdoor folding table has been approved, so overseas warehouse shipment can be arranged and the inventory sheet synchronized." Compare subject, object, and status field by field. The source status is "pending review" and the draft states "has been approved." These are mutually exclusive values in the same field, so the draft is unsupported. If the status field is absent from the source, record an evidence gap.
2. Input the declaration fragment from the sample and query "pending review" once with full-text retrieval and once with semantic retrieval. Compare whether the returned reference content includes the status field. If semantic retrieval returns content without the status field while full-text retrieval includes it, record that difference without claiming one mode is always better.
3. Input a clearly labelled paper empty-result case and check whether downstream nodes continue along the path for a reference length of 0. If the downstream design routes an empty array to a manual review branch, record that design. Do not claim that a fictional rule search necessarily returns an empty array.

Across all three checks, the comparison stays within the same subject, the same period, and the same field. A pending review does not show that an operating permission is missing. Signing, reaching an agreement, and a contract taking effect are three separate facts. A quotation validity period does not state a supply period. Where the source does not carry an authorization or effectiveness clause, that gap remains open rather than being filled to produce a definite answer.
