# TikTok Shop US operations: interactive forms for staff training

## What the documents look like

TikTok Shop US store operations differ from Douyin shelf-store operations because of local return windows, return grading, and overseas logistics constraints. The documents handled day to day include product listings, return and refund records, Return Grading evidence, and settlement statements. Data sources named in the research brief are TikTok Shop Seller Center, the order center, carrier tracking, and advertising reports. The stated update frequency is daily and per order.

For store service and internal training, the handover material, the operational request, and the authorization state all need to be recorded together. The form interaction step collects required information and passes it to later nodes. Business approval, write-back, and batch operations belong to external systems or later nodes as needed.

## Constraints at the interactive forms step

The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. The dialog box is hidden during that state. The node collects the information the user fills in and passes it to later nodes. The documentation does not state that the node carries a business database function, and it does not describe a submission count, automatic judgment, or snapshot guarantee.

The User Selection node is also a user interaction node. When it triggers, the conversation enters an interaction state and the workflow state is recorded. When the user makes a selection, the node judges that selection and executes the "yes" branch. The documented use is to pose a question requiring a decision and to design different workflow paths from the feedback. The documentation does not describe the node as a personnel directory or a business data selector.

Required-information checks need a list of what this task cannot proceed without, with the missing case and the completed case tested separately. Field validation, business approval, write-back, and batch operations are implemented in external systems or later nodes as needed. Retrieval and form submission do not constitute authorization to execute. A pending review does not demonstrate that an operation permission is absent.

Hypothetical paper exercise sample: in a store service and internal training setting, the material available for checking reads as follows. "Return and refund record number R-2024-0512. Product listing number L-8891. Return Grading evidence upload date 12 May 2024. Settlement statement number S-2024-05. Handover request: after-sales specialist A asks operations specialist B to complete the internal training confirmation for this return record by 15 May 2024." The draft sentence to be assessed is: "This return record has completed the internal training confirmation." The material shows a handover request only. It does not show a completed confirmation, so the draft sentence is unsupported.

## Three common errors

1. Treating a handover request as a completed confirmation. In the sample, the material shows only "complete the internal training confirmation by 15 May 2024" and does not show a completed confirmation. The draft sentence "this return record has completed the internal training confirmation" is unsupported. The input is the material text and the draft sentence, the comparison is between the request state and the completed state, and the observable result is that the draft sentence lacks completion evidence.

2. Treating the User Selection node as a personnel directory or a business data selector. The documentation states that the node executes a branch according to the user's selection, and it does not state that the node queries a personnel directory or business data. The input is the node purpose description, the comparison is between branch execution and directory query, and the observable result is that the documentation does not record a directory query capability.

3. Treating retrieval or form submission as authorized execution. The documentation states that the Form Input node collects information and passes it to later nodes, and it does not state that the node performs approval or write-back. The input is the node function description, the comparison is between information collection and authorized execution, and the observable result is that the documentation does not record an authorized execution capability.

## How to verify the setup

1. Use the hypothetical sample material text and the draft sentence. The input is "return and refund record number R-2024-0512, handover request to complete the internal training confirmation by 15 May 2024" together with "this return record has completed the internal training confirmation." The comparison is between the state recorded in the material and the state recorded in the draft sentence. The observable result is that the draft sentence is unsupported. The condition is met when that gap is recorded.

2. Use the missing-required-information case from the hypothetical sample. The input is a form missing the Return Grading evidence upload date. The comparison is between the required-information list and the fields already filled in. The observable result is that the missing item is identified. The condition is met when, after the item is supplied, behavior continues downward as described in the documentation.

3. Use the handover request date 15 May 2024 and the material upload date 12 May 2024 from the hypothetical sample. The input is the two dates. The comparison is the order in which they occur. The observable result is that the request date is later than the upload date. The condition is met when that time relationship is recorded, without inferring that confirmation has been completed.
