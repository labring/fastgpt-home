# General export declarations: workflow routing for staff training

## What the documents look like

General trade export declaration work processes four core documents on every shipment: the export declaration form, the commercial invoice, the packing list and the contract. Data originates from the China International Trade Single Window, the customs commodity code library, forwarder bills of lading and the company ERP system. Compared with general trade import declaration, export declaration also affects the matching of export tax rebate vouchers. Returned documents, inspection, declaration errors or blocked rebates can follow from mistakes in this material.

For store service and internal training, workflow routing operates on these per-shipment materials and on handover requests exchanged among document clerks, customs brokers and trading companies. The training setting does not change the underlying documents; it changes who performs the routing and how the steps are explained.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When triggered, the conversation enters an interaction state, the workflow state is recorded, and the dialog box is hidden. After the user completes the required fields and submits, the node collects the form information and passes it to subsequent nodes. The User Selection node is also a user interaction node. It enters the interaction state, records the workflow state and hides the dialog box. When the user makes a selection, the node evaluates that selection and executes the corresponding yes branch. Interaction state, state recording and dialog hiding are behaviors of the interaction nodes. No separate global state-recording switch is documented.

Collected information must be explicitly passed to later retrieval, judgment or interface nodes. Order writing, document backfill and external status synchronization require a separate business interface or a downstream process. Retrieval does not perform authorization, and a relevance score is not a permission or entity-isolation condition.

Hypothetical paper exercise: a document clerk at a trading company submits one export declaration packet in a store training system. The source text reads: "Commercial invoice number INV-2026-0417, contract number CT-2026-0417, packing list states 120 cartons, draft export declaration form declaration date 17 April 2026, freight and insurance fields not yet completed." The draft sentence to be assessed is: "This export declaration has completed declaration and obtained the tax rebate voucher." The source text shows only a draft and uncompleted fields, so the draft sentence exceeds the source.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | Reason and comparison method |
|---|---|---|
| Form Input required fields | Invoice number, contract number, declaration date | Compare against the sample source text; a missing item prompts completion |
| User Selection branch | Yes branch corresponds to complete materials | Check each branch connection against the sample state |
| Output receiving node | Pass form information to the later judgment node | Compare output fields with input fields for consistency |
| Retrieval input scope | The sample material text for this exercise | Observe whether returned results cover the sample fields |
| Empty-result handling | Paper input of an empty list | Check how the downstream design handles no result |
| External operation split | Declaration and rebate handled by separate interfaces | Separate node behavior from actions requiring another system |

## Three common errors

1. Treating form submission as a completed declaration. The sample source text records only a draft declaration date. Submitting the form collects information; the declaration state remains draft.
2. Treating the yes branch of User Selection as authorized execution. The branch only evaluates the user's selection. Order writing and external synchronization require a separate business interface.
3. Treating retrieval results as a permission filter. Relevance does not exclude unrelated business or unauthorized records. Retrieval is not authorization.

## How to verify the setup

1. Input the sample source text and the draft sentence "This export declaration has completed declaration and obtained the tax rebate voucher." Compare the declaration state field in the source with the wording of the draft sentence. The source shows only a draft, so the draft sentence is unsupported and the evidence gap should be recorded.
2. Input the sample material text and observe whether retrieval results cover the invoice number, contract number and declaration date. If the returned results do not contain these fields, record the actual observation. First-hit matching or full recall is not guaranteed.
3. Input a paper empty list and check whether the downstream node design handles the no-result case. Empty-result handling is checked against an explicit paper input; no claim is made that a fictional rule retrieval necessarily returns an empty list.
