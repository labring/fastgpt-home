# General import declarations: workflow routing for staff training

## What the documents look like

General trade import declaration work centres on five recurring materials: the import declaration form, the commercial invoice, the packing list, the bill of lading, and the contract. Staff draw these from the International Trade Single Window, customs tariff schedules, freight forwarder arrival notices, and foreign exchange payment documents. Import declaration differs from export declaration in where the attention sits: dutiable value, freight and insurance charges, and tax payment. Those three items carry the money and the exposure, so any workflow routing built for storefront service and internal training has to keep them visible at each handoff. The consequences of getting this wrong are supplementary tax with late declaration fees, cargo sitting at port, and administrative penalties, which is why the routing step needs to record what was collected and what was passed on.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When it is triggered, the conversation enters an interaction state, the workflow state is recorded, and after the user completes the interaction the workflow continues downward. Once the user fills the required information and submits, the node collects the submitted form values and passes them to later nodes. The User Selection node is also a user interaction node with the same trigger behaviour: the conversation enters an interaction state, the workflow state is recorded, and once the user makes a choice the node evaluates that choice and executes the "yes" branch. The recorded interaction state is a behaviour of the interaction nodes; no separate global state-recording switch is documented.

Retrieval and form collection do not constitute authorized execution. Collected information must be passed explicitly to a later retrieval, judgement, or interface node, and order writes, document backfill, and external status synchronization require a separate business interface or a later process. Semantic recall and relevance scores do not perform permission or entity isolation. Retrieval checks record observations and failure branches; they do not guarantee a first hit or full recall. Empty-result handling can be checked against a clearly labelled paper input of `[]` to inspect the downstream design. Libraries built on different vector models cannot be associated together; verify the identifier first and exclude non-matching ones. RRF is a hybrid result fusion process, not a switch to be turned on. Image retrieval requires a corresponding image input and model capability, and reranking requires a model and must be enabled according to its settings.

Hypothetical drill sample. An importer's customs manager submits a paper document during a storefront training session. The material text reads: "Commercial invoice number INV-2025-0417, contract number CT-2025-008, transaction terms CIF, freight and insurance listed in the invoice attachment." A draft sentence under review reads: "The above materials are complete and can proceed directly to the declaration form entry node." The pending request under review reads: "Submit the above materials to the declaration form entry node." The material identifiers are used for field comparison only, not for permission decisions.

## Configuration and implementation checks

| Form Input node | Interaction node | Enters interaction state on trigger, collects required information, passes it to later nodes |
| User Selection node | Interaction node | Executes the "yes" branch after the user makes a choice; verify each branch connection |
| Interaction state check | Implementation check | Recorded state is interaction-node behaviour; no separate global switch is documented |
| Output handoff check | Implementation check | Pass collected information explicitly to a later retrieval, judgement, or interface node |

| Hypothetical trial starting point | This drill only | Sample materials identified by INV-2025-0417 and CT-2025-008; chosen so the same fields can be compared |

## Three common errors

1. Treating form submission as authorized execution. The draft sentence in the sample says the materials "can proceed directly to the declaration form entry node," yet complete materials do not mean submission has been authorized. Check the input as the sample material text together with the draft sentence, compare the two distinct facts of "materials complete" and "submission authorized," and observe whether the draft sentence treats the first as the second.

2. Treating a user selection branch as automatic judgement. The pending request in the sample says to submit the materials to the declaration form entry node, yet the User Selection node executes the corresponding branch only after the user makes a choice. Check the input as the pending request together with the node documentation, compare the requested action with the node behaviour, and observe whether the request skips user selection and moves straight downstream.

3. Treating retrieval results as permission isolation. The sample identifiers INV-2025-0417 and CT-2025-008 are used for comparison only, not for permission decisions. Check the input as the retrieval return together with the material identifiers, compare retrieval relevance with entity permission, and observe whether similarity is used to exclude unauthorized records.

## How to verify the setup

1. Take the sample material text as input and compare "Commercial invoice number INV-2025-0417, contract number CT-2025-008, transaction terms CIF, freight and insurance listed in the invoice attachment" against the draft sentence "The above materials are complete and can proceed directly to the declaration form entry node." When the draft sentence equates complete materials with authorized submission, the judgement is unsupported. The expected observation is that the draft sentence lacks a source of authorization or a signature status.

2. Take the pending request "Submit the above materials to the declaration form entry node" as input and compare the requested action against the User Selection node documentation, which states that the branch is executed when the user makes a choice. When the request demands submission without passing through user selection, the condition is unmet. The expected observation is that the request lacks a user selection record.

3. Take the paper input `[]` as input and inspect the downstream node design. When retrieval returns an empty result, observe whether the downstream handles it as an empty result. The expected observation is that the downstream node has a defined path for empty input; do not claim that a hypothetical rule retrieval necessarily returns `[]`.
