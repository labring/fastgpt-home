# General import declarations: retrieval for staff training

## What the documents look like

General trade import declaration work centres on the import declaration form, commercial invoice, packing list, bill of lading and contract. The distinguishing pressure in this category sits in customs dutiable value, freight and insurance, and tax payment. Material changes once per declaration order. In store service and internal training, customs managers and customs broker staff retrieve transaction terms, the freight and insurance basis, and inspection cooperation requirements from these documents, then reuse the retrieved content when answering an importer or explaining a point internally. Retrieval returns reference content only. It does not constitute authorization, approval or a declaration action.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases with different vector models cannot be associated together. Search modes are semantic retrieval, full-text retrieval and hybrid retrieval. Hybrid retrieval merges multiple result paths through RRF; RRF is a fusion process inside hybrid retrieval, not a separate switch. The reference limit is measured in tokens. Minimum relevance takes effect only under semantic retrieval or when result reranking is used. Question optimization performs coreference resolution and question expansion, and adds one model call. Reference content is output as an array whose length can be 0, so the downstream chain still runs when nothing is retrieved. Retrieval and relevance scores do not carry permission or entity isolation duties; whether a record is visible depends on the retrieval scope itself.

Hypothetical paper exercise sample: the source text in a store internal training file reads, "The transaction term for this order is CIF; freight and insurance are borne by the seller and have been included in the invoice amount. The consignee on the bill of lading is the sample importer, and the arrival date is 10 March 2025." The draft sentence to be judged reads, "Freight and insurance for this order are paid separately by the buyer." The draft sentence and the source text give mutually exclusive values for the same field, so the draft is contradictory and cannot be used as training wording. A separate handover request reads, "Please arrange cargo pickup and complete the declaration according to the above bill of lading." That request concerns declaration and pickup execution. Retrieval results cannot substitute for authorization, so it is recorded as an item pending verification.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this page | Reason for the choice and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Associate only import declaration material bases that use the same vector model | Check the vector model identifier of each base first, exclude those whose identifiers differ, and do not run cross-model retrieval comparisons |
| Search mode | Hybrid retrieval | Test with a code-type question and a natural-language question separately, then compare retrieved content across semantic, full-text and hybrid modes |
| Reference limit | Hypothetical starting point of 3000 tokens | Test with actual document fragments of different lengths to see whether content is truncated, and compare completeness against a longer or shorter value |
| Minimum relevance | Hypothetical starting point of 0.4 | Label relevant and irrelevant samples first, then compare the composition of filtered samples against a higher or lower value |
| Question optimization | Enabled for multi-turn follow-up scenarios | Compare the original question with the optimized question and check whether the subject and period were altered |
| Result reranking | Enabled when candidates are numerous | Compare ranking positions before and after enabling, and confirm that a rerank model is configured |

## Three common errors

1. Treating minimum relevance as a permission or entity filter. Input an out-of-scope query and observe whether the returned content still includes non-authorized records. If it does, the setting does not carry isolation duties, and the retrieval scope itself needs checking.
2. Writing the RRF fusion of hybrid retrieval as a switch that can be turned on. Check whether such a switch exists in the configuration interface. If it does not exist, record it as a control item not provided by the documentation and do not infer behaviour from it.
3. Treating a handover request awaiting review as already authorized. Input a request such as "please arrange pickup and declaration", compare its authorization status field, and if the status is pending review, record it as not authorized and do not perform subsequent actions.

## How to verify the setup

1. For the sample source text and the draft sentence, input the draft sentence and compare whether the returned reference contains the wording "freight and insurance are borne by the seller" from the source. If the returned content matches the source, the contradiction check is usable. If an empty array is returned, record it as not retrieved and check whether the data has finished training.
2. For the handover request, input the request text and compare whether the returned reference contains an authorization or approval conclusion. If it contains only document fields and no authorization conclusion, retrieval does not produce authorization, and the evidence gap is preserved.
3. For cross-model bases, input the same question against two bases whose vector model identifiers differ, and compare the list of associable bases. If one base falls outside the associable range, record it as an identifier mismatch and exclude it, rather than running a cross-model retrieval to compare missed recalls.
