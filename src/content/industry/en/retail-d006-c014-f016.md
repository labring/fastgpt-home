# Convenience fresh-food orders: interactive forms for staff training

## What the documents look like

Convenience-store fresh food sits apart from large-format fresh counters. Stores order frequently against short shelf life, and the work is not handled as a joint-operation revenue split. The practical consequence for this page is that ordering, waste, near-expiry handling and cold-chain temperature records move on a daily and shift-level rhythm, so any interactive form used in store service or internal training has to match material that is already refreshed often.

The daily documents named in the brief are the fresh-food order form, the waste report, the near-expiry handling sheet and the temperature record. These are the records a store manager, fresh-food buyer or regional supervisor would work with. The costly failure modes are sales of expired product, loss from stockouts and food-safety complaints, which is why the interactive step needs to collect the right fields before anything downstream depends on them.

The two relevant workflow nodes are documented as user-interaction nodes. The form input node collects information the user fills in and passes it to later nodes; it does not carry its own business database function. The user selection node judges the user's choice and runs the corresponding branch; it does not act as a personnel directory or a business-data selector. Both can be added repeatedly and both trigger execution. When either is triggered, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction.

## Constraints at the interactive forms step

The interaction state is the central constraint. A form input node or user selection node that has been triggered records workflow state and waits. Execution resumes only after the user finishes the interaction. This means the form does not itself validate fields against a business rule, approve anything, write to a database, or synchronise with an external system. Field validation, business approval, write-back and batch operations need to be implemented in an external system or in later nodes according to the actual requirement.

Retrieval and form filling do not constitute authorisation to execute. A completed form is a collection of values, and a user selection is a branch decision. Neither one establishes that a store is permitted to place an order, that a waste report has been approved, or that a temperature record is valid. Those states have to be checked separately.

The following hypothetical drill sample is used only to explain a checking method. It does not describe any real store or any real record.

Hypothetical drill sample: a convenience-store manager submits a fresh-food order form on the morning shift of 10 June 2025. The material text reads: "Store number A07, order date 10 June 2025, fresh-food category rice balls, order quantity 30 units, waste report number BS-0610-02, temperature record number WD-0610-01, near-expiry handling sheet number LQ-0610-01." A draft sentence to be judged reads: "This store has completed the waste approval for the 10 June rice-ball order." The subject, object and period needed for the judgment are present in the source text, but the waste approval status is not stated.

## Configuration and implementation checks

The configuration below is organised around the form fields and interaction branches in that sample. The values are a hypothetical starting point for this drill and are used for comparison; they are not official default values.

| Configuration item | Hypothetical starting point for this drill | How to check |
| --- | --- | --- |
| Required fields on the form input node | Store number, order date, fresh-food category, order quantity | If a required field is missing at submission, the interaction state does not end |
| Branches on the user selection node | Yes and no branches | After the choice, execution continues along the corresponding branch |
| Interaction state recording | Workflow state is recorded after the node is triggered | Check whether execution continues downward after the interaction completes |
| Waste report fields | Waste report number, waste date, waste quantity | Check separately from the order form number |
| Temperature record fields | Temperature record number, record time, temperature value | Check separately from the order form number |
| Near-expiry handling sheet fields | Near-expiry handling sheet number, handling date, handling quantity | Check separately from the order form number |

The reason for choosing these starting points is that they correspond to the fields named in the sample material and to the two documented node behaviours. The comparison method is to place the sample text beside the draft sentence and ask which fields and which states the text actually carries.

## Three common errors

1. Treating the user selection node as a personnel directory or business-data selector. The node judges the user's choice and runs the corresponding branch. It does not provide a query capability over personnel records or business data.

2. Treating form submission as completed business approval. The form input node collects the filled-in information and passes it to later nodes. Approval has to be implemented in an external system or in later nodes.

3. Treating a retrieval result or a completed form as authorised execution. Retrieval and forms do not perform permission or entity isolation. Authorisation status has to be checked separately.

## How to verify the setup

1. Enter the hypothetical sample text and compare the draft sentence "This store has completed the waste approval for the 10 June rice-ball order" against the source. The source states only the waste report number BS-0610-02. It does not state the waste approval status. The draft sentence is not supported by the source, and the evidence gap should be recorded as an open item.

2. Enter the hypothetical sample text and compare whether the store number A07, order date 10 June 2025, fresh-food category rice balls and order quantity 30 units in the order form match the subject, object and period of the draft sentence. Where they match, that part is supported. The waste approval part remains to be verified.

3. Enter the hypothetical sample text and compare whether the draft sentence cites temperature record number WD-0610-01 and near-expiry handling sheet number LQ-0610-01. The draft sentence cites neither, so no judgment about temperature or near-expiry handling status can be drawn from it. Both remain unstated.
