# Brand member operations: retrieval for staff training

## What the documents look like

Member private-domain operations revolve around customer records and repeat-purchase outreach. The working documents are member tag tables, outreach plans, coupon rules and privacy authorization records. They come from a CRM system, enterprise messaging, POS purchase records and mini-program behavior data. Store service and internal training draw on the same material: a guide or an enterprise messaging operator looks up a consistent wording for a member question, and a trainer prepares the same wording for a class.

Two properties matter for retrieval. First, the material is versioned on a daily or weekly cycle, so a retrieved passage reflects the version that was indexed, not necessarily the version in use today. Second, when a brand CRM team, store guides and enterprise messaging operators share one knowledge base, the subject, object, state and validity range inside each passage have to be checkable against the source. A retrieval result is a pointer to text. It is not a verification of the member's status, and it is not an authorization to act.

## Constraints at the retrieval step

The knowledge base search node can link one or more knowledge bases that use the same vector model. Knowledge bases with different vector models cannot be linked together; the identifiers are checked first and non-matching bases are excluded. This same-model requirement applies to the retrieval bases themselves and does not extend to external systems such as business registration sites.

Cited content is output as an array whose length can be zero. An empty result still passes through the downstream chain, so the flow design must accept a zero-length citation array rather than assume a hit.

The minimum relevance value is a filter threshold that takes effect only under semantic retrieval or when result reranking is used. It is not an authorization filter and does not separate entities or permissions. RRF is the fusion step that combines multiple recall paths; it is a process, not a switch. Image retrieval requires an actual image input and model capability, and reranking requires a model and must be enabled in the settings. The optional paths in the overall retrieval diagram do not all run on every request.

Hypothetical drill sample: a brand CRM team maintains a member tag table whose source text reads "Member A-2024-017, registered store Riverside, member tier Silver, benefit scope double points in the birthday month, valid until 31 December 2024." A separate privacy authorization record reads "Member A-2024-017, authorization channel enterprise messaging, authorization state signed, authorization date 10 March 2024." The draft sentence to be judged is "Member A-2024-017's Silver benefit can be extended into 2025, and the authorization state is pending review." This sample is used only to check retrieval and recall output. It does not represent a real customer or a completed business action.

## Three common errors

1. Treating a retrieval result as an authorization state. Input the draft sentence "authorization state is pending review" and compare it with the source privacy authorization record "authorization state signed." Observe whether both share the same subject, the same period and the same field. Pending review does not show that operating permission is missing. Signing, reaching cooperation and a contract taking effect are three separate facts.

2. Linking knowledge bases with different vector models. Input the member tag table base together with another base that uses a different vector model. Compare the base identifier and the vector model identifier, and observe whether the non-matching base is excluded. Bases with different vector models cannot be linked together. Check identifiers, exclude non-matching bases and record what is actually observed.

3. Treating an empty result as a necessary rule outcome. Input an explicit paper input of an empty array and compare whether the downstream design accepts a citation array of length zero. Observe whether the empty-result chain continues. It cannot be claimed that a fictional rule retrieval necessarily returns an empty array.

## How to verify the setup

1. Input the hypothetical sample source text and the draft sentence. Compare "valid until 31 December 2024" with "can be extended into 2025." Observe whether the retrieval result recalls the source text and exposes the date difference. The expected outcome is that the difference can be checked by a person. No actual test is claimed.

2. Input the authorization state query for Member A-2024-017. Compare "signed" with "pending review." Observe whether both share the same subject, the same period and the same field. A field that is not stated, or evidence that covers only a related stage, is unsupported or awaiting verification. It is not a negation and not a conflict.

3. Input an empty citation array. Compare whether the downstream node accepts an output of length zero. Observe whether the chain continues to execute. Missing evidence must remain missing. Authorization or effective clauses cannot be supplied to obtain a definite answer.

This page addresses only brand member private-domain operations, store service and internal training, and knowledge base retrieval and recall. When operations are handed over, the authorization state of materials, actions and requests cannot be inferred from retrieval or from a form.
