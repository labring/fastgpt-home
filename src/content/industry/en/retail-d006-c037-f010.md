# Peak-sale fulfillment: citation tracing for staff training

## What the documents look like

Peak-sale warehouse and delivery scheduling turns on short-window peak capacity and the arrangement of people, vehicles and yard space. Historical peak-sale orders, platform campaign registrations, WMS capacity and courier pickup capacity together form the scheduling basis, and each campaign or each day can produce a new version. In the store-service and internal-training setting, the working materials are the peak-sale forecast table, the staffing roster, the courier support plan and the exception daily report. Each of these documents has to be checked for version and effective scope at the citation-tracing step.

A knowledge-base search node can be linked to one or more knowledge bases that share the same vector model, and it outputs cited content as an array whose length may be zero. Whether a retrieved item is adopted still depends on a review of the document's effective version; retrieval itself does not constitute authorization. The citation ceiling controls, in tokens, the maximum amount of content cited in a single search. The minimum relevance value takes effect only under semantic search or result reranking, and it is a filter threshold rather than a permission or entity-isolation mechanism. Hybrid search merges multiple result paths through RRF, reranking runs when a rerank model is configured, and image retrieval requires corresponding image input and model capability. These optional paths do not mean that every request executes all of them.

## Constraints at the citation tracing step

The tracing task is to take a drafted sentence or a handover request and compare it against the wording of the source document, field by field, for the same subject, the same period and the same field. A claim of approval is supported only when the source document actually records an approval field for that subject and period. A claim about a peak order quantity is supported only when the source states that quantity for the same scope. Where the source is silent, the status remains unsupported or pending verification; silence is not a denial and is not a conflict.

Semantic recall and relevance scores do not carry permission or entity isolation. A query across stores can return records that are semantically close even when the requester has no business relationship with them, because the relevance score is a similarity measure and not an access filter. The same-vector-model requirement for linking knowledge bases applies to the search scope; it does not extend to business-registration sites or other external systems.

Hypothetical paper exercise. The warehouse document "Peak-Sale Forecast Table (Version 3)" states in its original text: "This table applies to 1 November 2025 through 3 November 2025, covers the East China warehouse, and the expected peak order volume is 80,000 orders per day; the data source is platform campaign registrations and orders from the same period in prior years." The accompanying "Staffing Roster" states: "The roster period is 1 November 2025 through 3 November 2025, and temporary staff arrival time is 06:00 each day." A drafted sentence reads: "The East China warehouse peak order volume during the peak-sale period has received written approval from the operations lead and can be used directly for courier vehicle coordination." The drafted sentence's claimed approval status is not found in either the forecast table or the roster, so the approval status is unsupported.

## Configuration and implementation checks

| Configuration item | Setting or check for this page | Note |
| --- | --- | --- |
| Linked knowledge bases | Check the selected knowledge bases and material versions; only bases sharing the same vector model can be linked together | Cross-model bases cannot be linked together; verify identifiers first and exclude those that do not match |
| Search mode | Choose semantic search, full-text search or hybrid search according to the question type | Hybrid search merges through RRF and is not a standalone switch |
| Citation ceiling | Set the cited amount per search in tokens | For this hypothetical exercise the starting value is 3000 tokens, chosen because the forecast table and roster together are about 2500 tokens; comparing with 2000 tokens shows truncation |
| Minimum relevance | A filter threshold that takes effect only under semantic search or result reranking | For this hypothetical exercise the starting value is 0.5; comparing with 0.3 shows the change in recall scope |
| Question optimization | Decide whether to enable it for multi-turn follow-ups or short questions | Enabling it adds one model call and increases overall latency |
| Cited-content handoff | Check whether the search output is passed to the answering step and compared item by item against the source text | The downstream design must handle an empty array |

## Three common errors

1. Treating a retrieval hit as authorization. Input: the drafted sentence above and the forecast table text. Compare the approval status claimed by the drafted sentence against the applicable period and coverage actually stated in the forecast table. The observable result is that the forecast table records no approval field, so the approval status is unsupported.
2. Treating minimum relevance as a permission or entity filter. Input: a cross-store query and the linked knowledge base. Compare the returned citations against the querying subject. The observable result is that the relevance score does not perform entity isolation, and unrelated records may be recalled because they are semantically close.
3. Treating an empty citation array as a workflow error. Input: a paper-constructed empty array []. Compare the downstream node design. The observable result is that a citation length of zero is allowed, and an empty array does not mean the workflow terminated.

## How to verify the setup

1. Input the forecast table text above and the drafted sentence. Compare the approval status described in the drafted sentence against the applicable period and coverage actually stated in the source. If the source has no approval field, the "unsupported" determination is satisfied; if an approval field appears in the source, the signing subject still has to be checked further.
2. Input the roster text above and the drafted sentence. Compare whether the roster period and the temporary-staff arrival time match what the drafted sentence states. If the drafted sentence does not mention arrival time, that is missing information and does not constitute a contradiction.
3. Input the paper-constructed empty array [] and the downstream answering node design. Compare whether the downstream can accept a zero-length citation. If the downstream design explicitly handles an empty array, the condition is satisfied; if the downstream design assumes citations always exist, record it as an item to be corrected.
