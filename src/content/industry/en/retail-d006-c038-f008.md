# Fresh-food concession counters: workflow routing for staff training

## What the documents look like

A fresh-food concession counter in a hypermarket is commonly operated by a supplier who stations staff on site and shares sales revenue with the store. Store fresh-food departments, resident suppliers, and the store manager all take part in daily operations. This page addresses one task: store service and internal training, with workflow routing as the feature under discussion.

The materials that matter for this task are the concession contract, daily sales reports, loss reports, and food purchase inspection records. These materials are produced daily or per batch. Reconciling weighed sales, handling loss allocation, and checking purchase vouchers are three time-consuming steps. In store service, customer questions, staff operating instructions, and handover requests can each trigger workflow routing.

Workflow routing requires separating four things: behavior a node already performs, fields that can actually be configured, manual comparison actions, and business actions that need a separate system interface or a later process. Retrieval and form collection do not constitute authorized execution. At operational handover, the material, the action, and the request each need their authorization state identified.

## Constraints at the workflow routing step

The Form Input node is a user-interaction node. When it is triggered, the conversation enters an interaction state, the workflow state is recorded, and the dialogue waits. After the user fills in the required information and submits, the node collects the submitted form information and passes it to later nodes. The User Selection node is also a user-interaction node. When the user makes a selection, the node evaluates that selection and executes the corresponding "yes" branch.

The recorded interaction state is behavior of the interaction node itself. The documents describe no separate global state-recording switch, no submission-count control, and no snapshot guarantee. Information collected by these nodes must be explicitly passed to a later retrieval node, judgment node, or interface node, and output must be compared item by item against input. Order writing, document backfill, and external status synchronization require a separate business interface or a later process.

Hypothetical paper exercise: a fresh-food concession counter in a hypermarket, where the store fresh-food department plans loss-report completion training for resident staff. The source text supplied for comparison reads: "Annex 3 of the concession contract states that the loss report must be completed by the employee on duty and countersigned by the store manager; the daily sales report is submitted each day by the supplier's resident staff." One draft sentence to be judged reads: "After the loss report is completed, the system automatically synchronizes the loss data to the supplier settlement account." This draft sentence concerns external status synchronization. The source text states no automatic synchronization mechanism, so the action requires a separate business interface or a later process and cannot be completed by form submission or user selection.

## Configuration and implementation checks

| Configuration item | Type | Description |
| --- | --- | --- |
| Form Input node | Interaction node | Enters interaction state when triggered, collects required information, passes it to later nodes after submission |
| User Selection node | Interaction node | Executes the corresponding "yes" branch after the user makes a selection; branch connections are verified one by one |
| Output handoff check | Implementation check | Passes collected information explicitly to a later retrieval, judgment, or interface node, comparing output against input item by item |
| External action separation | Implementation check | Order writing, document backfill, and external status synchronization require a separate business interface or a later process |
| Interaction state check | Implementation check | Recorded state is behavior of the interaction node; no separate global state-recording switch is set or claimed |

Hypothetical starting point for this page: the required fields of the Form Input node in the loss-report training flow are set to "loss report number, employee on duty name, loss quantity." The reason for choosing these three is that the source text requires completion by the employee on duty and countersignature by the store manager, so verifiable identity and quantity information must be collected first. The comparison method is to check the required fields item by item against the completion requirements stated in Annex 3 of the concession contract and confirm that the required fields cover the fields listed in the material. This starting value is a hypothetical exercise input, not an official default.

## Three common errors

1. Treating information passed on after Form Input submission as completed external status synchronization. The Form Input node collects information and passes it to later nodes; order writing, document backfill, and external status synchronization require a separate business interface or a later process. The draft sentence "the system automatically synchronizes the loss data to the supplier settlement account" describes external synchronization, and the source text states no such mechanism.

2. Treating execution of the "yes" branch of a User Selection node as authorization approval. The User Selection node designs different workflow paths according to user feedback. A pending review does not show that an operating permission is absent. Signing, reaching cooperation, and contract effectiveness are three distinct facts.

3. Treating the recorded interaction state as a global state-recording switch. Recorded state is behavior of the interaction node, and no separate global state-recording switch is set. No corresponding control switch, submission count, automatic judgment, or snapshot guarantee may be asserted.

## How to verify the setup

1. Input the source text and the draft sentence from the hypothetical paper exercise above, and compare whether the draft sentence contains an external synchronization action that the source text does not state. If the draft sentence claims automatic system synchronization while the source text states only completion and countersignature, the draft sentence is not supported by the material, and the evidence gap is recorded.

2. Input the required-field settings of the Form Input node, and compare whether they cover "loss report number, employee on duty name, loss quantity" as listed in the source text. If the required fields match the fields listed in the material, the output handoff design meets the comparison condition. If any field is missing, record it as not covered.

3. Input the branch connections of the User Selection node, and compare whether the "yes" branch points to a later comparison node or interface node. If the branch points to external synchronization without a separate business interface, the connection does not meet the external action separation requirement and is recorded as an implementation still to be supplied.

These checks describe expected observations on paper inputs. They do not report a completed test, a deployment, or an approval. Where the material does not state a mechanism, the gap remains an evidence gap.
