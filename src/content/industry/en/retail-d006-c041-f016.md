# Marketplace promotions: staff training with interactive forms

## What the documents look like

For staff training in Marketplace promotions, this page examines FastGPT interactive forms. Pass combination restrictions, member conditions and test-page purpose without inferring enrollment from a button. The examples are hypothetical.

## Constraints at the interactive forms step

This exercise invents classroom activity cards: one prohibits combination, another requires verified membership, and a screenshot comes from a test page without real enrollment records. These are teaching restrictions, not a platform’s actual promotion policy. Collect original conditions, product and source, then choose combination or eligibility review. Downstream input must retain restrictions. Entering a name does not establish verified membership, and a visible test button proves neither usable production enrollment nor an effective campaign. No price, discount magnitude or actual member data is supplied.

## Configuration and implementation checks

| Promotion-class form | Invented restriction | Learning check |
| --- | --- | --- |
| Combination | Card prohibits it | Inspect passed negation |
| Eligibility | Verified members only | Not entered names |
| Environment | Test screenshot | Not production enrollment |
| Choice route | Combination or eligibility | Inspect actual handoff |
| Real campaign | No platform receipt | Separate rule/authority review |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Form input` | Collect input and pass values after submission. |
| `Required-information check` | Design required business inputs and missing-input handling. |
| `User selection` | The selected option maps to a connected branch. |
| `Interaction state` | Inspect waiting and completed interaction separately. |
| `Downstream responsibility` | Verify validation, approval and write results separately. |

## Three common errors

- If a prohibition disappears and combined use becomes permitted, compare the card, submitted content and received values to locate lost negation.

- If verified-member eligibility expands to every form entrant, inspect the condition and actual verification evidence. Entered information is no membership-query result.

- If a test enrollment button becomes successful registration, inspect environment labels, real platform records and receipts rather than screenshot appearance.

## How to verify the setup

Test missing activity identity and completed input. Follow both choices and ask learners to identify gaps in combination, eligibility and environment evidence. Added eligibility changes its subject only without removing combination restrictions; real campaign existence stays separate. The node waits and passes entered wording without validating members, enrolling or changing prices. Applicable rules, identity interfaces and operations need responsible version and authority review. Teaching examples create no actual promotion promise.
