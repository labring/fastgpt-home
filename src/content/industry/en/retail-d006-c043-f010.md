# Multi-store management: citation tracing for staff training

## What the documents look like

Platform multi-store matrix management covers several store entities, several platform merchant back ends and distributor channels. Four document families form the working base for store service and internal training: store authorization lists, price control tables, cross-territory complaint forms, and monthly sales reports. These materials update daily or monthly, and cross-store authorization plus price order are the operating focus.

For citation tracing, each statement in a final answer must be aligned with the source passage it came from. The store authorization list is the material that decides which store may sell under the brand and under what terms. A price control table records the price order that authorized stores are expected to follow. A cross-territory complaint form records a reported violation, which is a claim under review rather than a confirmed fact. A monthly sales report records volume by store and period.

These four families differ in what they can support. An authorization list can support a statement about which store is authorized and for which period. A complaint form cannot support a statement that a store has been confirmed as unauthorized. A pending complaint and an approved authorization are separate states, and the training material must keep them apart.

## Constraints at the citation tracing step

The knowledge base search node can associate one or more knowledge bases that share the same vector model. Its output is an array of cited content, and the array length may be zero. An empty array means the search path ran and returned no match; it does not mean the workflow raised an error and stopped.

Search output is passed to the answering step, and only after that can each answer statement be checked against the cited source text. The minimum relevance value is a filter threshold. It does not carry permission or entity isolation duties, and retrieval itself does not constitute authorization. Knowledge bases built on different vector models cannot be associated together; the vector model identifier must be checked first and non-matching bases excluded. Image retrieval and reranking appear as optional paths in the overall flow diagram and run only when the corresponding input and model capability are present.

Hypothetical paper exercise sample. A brand e-commerce lead holds two passages from a store authorization list. Passage one reads: "Authorized stores: Store A, Store B; authorization period: 1 January 2025 to 31 December 2025; authorization scope: online sales and price execution." Passage two reads: "Store C is not included in the authorized scope of this list." A draft sentence under review reads: "Store C has obtained online sales authorization for this brand and may take part in the price execution segment of this store service training." This draft sentence directly conflicts with passage two of the list and is unsupported.

## Configuration and implementation checks

| Configuration or check item | Hypothetical starting point for this exercise | Reason and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Two knowledge bases with the same vector model | Check the vector model identifier first; exclude any base that does not match; do not run cross-model retrieval |
| Search mode | Hybrid retrieval | Compare recalled content against semantic retrieval and full-text retrieval separately, and observe differences for identifiers and natural-language questions |
| Citation limit | Set in tokens; a smaller value as the starting point here | Compare citation counts against a larger value and observe whether a key passage is truncated |
| Minimum relevance | A middle value as the starting point here | Compare returned counts against lower and higher values, observe the filtering effect, and treat it as a threshold rather than a permission filter |
| Question optimization | Not enabled in this exercise | Compare recall on follow-up questions with it enabled, and reassess for short-question cases |
| Citation output handoff | Check whether the output array is passed to the answering step | Use an empty array and a non-empty array separately to check the downstream design |

## Three common errors

1. Treating a retrieval hit as authorization confirmation. Input is the two passages of the store authorization list above plus the draft sentence. Compare the subject of the draft sentence against the authorized store field of the list. If the draft sentence presents Store C, which is not in the list, as authorized, the statement is unsupported. Executable check: compare the authorized store field of the list against the subject of the draft sentence character by character, and record each mismatch.

2. Treating minimum relevance as an entity or permission filter. Input is the returned array for the same query under different relevance settings. Compare whether the returned content contains information about a store outside the authorized list. If it does, relevance is not performing authorization filtering. Executable check: inspect the store identifiers in the returned array against the authorization list, and record any out-of-scope entry.

3. Treating an empty citation array as a workflow error. Input is a paper empty array and the downstream handoff design. Compare whether the downstream step continues to run. If the downstream step halts on the empty array, that contradicts the documented behavior. Executable check: use the empty array against the downstream node design and record the observed result.

## How to verify the setup

1. Check the draft sentence against the sample source text. Input is the two passages of the store authorization list and the draft sentence. Compare the authorized store field against the subject of the draft sentence. If the draft sentence presents Store C as authorized, the statement is unsupported, and the evidence gap remains open.

2. Check the downstream handoff with an empty array. Input is a paper empty array. Compare whether the downstream design continues to run. If the downstream step proceeds as designed, the condition is met. Do not claim that a fictional rule search will necessarily return an empty array.

3. Check citation display with a traceable sample. Input is a citation array containing specific passage identifiers plus the answer text. Compare whether each citation in the answer can be traced back to the corresponding source passage. If a citation cannot be traced back, traceability fails, and answer fluency does not substitute for source evidence.

For the training material itself, the authorization list can support statements about which store is authorized and for which period. A complaint form records a reported violation and cannot support a statement that a store has been confirmed as unauthorized. A pending review is not an approval, and an unsigned termination is not a completed termination. Where a document field is not provided, the value remains unknown, and the training material should record the gap rather than fill it.
