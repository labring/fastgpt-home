# Complaints and official replies: workflow routing for staff training

## What the documents look like

Complaint and regulatory reply work is addressed to a platform or a regulatory body, so the file set carries a different weight from ordinary after-sales repair or reshipment material. The routine documents are complaint tickets, regulatory inquiry letters, order evidence, and rectification reports. Each of these has its own subject, period, and fields, and one complaint ticket may sit alongside order evidence, chat records, and a regulatory letter at the same time. When staff check a case, subject and time range have to be confirmed item by item rather than assumed to match.

Data arrives irregularly and on a per-case basis. Workflow routing therefore has to let each interaction record its own state. Batch synchronization and real-time triggering are not part of this picture.

## Constraints at the workflow routing step

The Form Input node is a user-interaction node. When it triggers, the conversation enters an interaction state and the workflow state is recorded. After the user fills in the required information and submits, the node collects what was entered and passes it to later nodes. The User Selection node is also a user-interaction node. It triggers the same interaction state, and when the user makes a choice, the node evaluates that choice and executes the corresponding "yes" branch. The interaction state and the state record are behaviors of the interaction nodes. No separate global state-recording switch exists.

Information that is collected has to be passed explicitly to later retrieval, judgment, or interface nodes. Order writes, document backfill, and external status synchronization require a separate business interface or a later process. Retrieval and form collection do not constitute authorization to execute. A pending review does not show that operating permission is missing.

Hypothetical drill sample. A store receives a complaint ticket numbered "HYP-2024-001". The ticket names the complaint subject as "Hypothetical Store A", states the complaint period as "1 March 2024 to 15 March 2024", and states the demand as "refund and rectification". A regulatory inquiry letter numbered "HYP-LTR-007" arrives at the same time and requires "a written explanation of the order evidence for the above period". The available material consists of one set of order evidence and one set of customer service chat records; neither states a signature or approval status. The proposed sentence for review is: "Hypothetical Store A completed rectification in March 2024 and submitted a rectification report." The handover request awaiting a decision is: "Move the above ticket and inquiry material into the rectification reply process."

## Configuration and implementation checks

| Configuration item | Type | Description |
| --- | --- | --- |
| Form Input node | Interaction node | Enters the interaction state when triggered, collects required information, and passes it to later nodes after submission |
| User Selection node | Interaction node | Executes the corresponding "yes" branch after the user makes a choice; verify each branch connection individually |
| Interaction state check | Implementation check | The state record is a behavior of the interaction nodes; no separate global state-recording switch is set |
| Output handover check | Implementation check | Pass collected information explicitly to later retrieval, judgment, or interface nodes, and compare each output against its input |
| External action separation | Implementation check | Order writes, document backfill, and external status synchronization require a separate business interface or a later process |
| Hypothetical trial starting point | Implementation check | This page uses ticket "HYP-2024-001" as the starting point and compares it against letter "HYP-LTR-007" item by item on subject, period, and fields; this is not an official default value |

## Three common errors

1. Treating information collected by the Form Input node as authorization to execute. Input: ticket "HYP-2024-001" and letter "HYP-LTR-007". Comparison: whether the ticket demand and the letter requirement agree on subject and period. Observable result: a step appears that uses collected information directly for an order write or external synchronization. Form collection does not constitute authorization; order writes require a separate business interface.

2. Treating the "yes" branch of the User Selection node as automatic judgment. Input: the branch connections of the User Selection node. Comparison: the user's selection against the branch execution condition. Observable result: a branch executes without the user having made a selection. The User Selection node evaluates the choice and executes the corresponding branch after the user makes it.

3. Treating retrieval or similarity results as a permission or entity filter. Input: records returned by retrieval. Comparison: whether the subject of each record matches the subject of the ticket. Observable result: records for an unrelated subject enter the rectification reply process. Retrieval does not perform permission or entity isolation, and libraries built on different vector models cannot be associated together; confirm identifiers first and exclude records that do not match.

## How to verify the setup

1. Input ticket "HYP-2024-001" and letter "HYP-LTR-007". Compare subject, period, and fields between the two. Observe whether the Form Input node passes the information to later nodes after submission. Compare the proposed sentence "Hypothetical Store A completed rectification in March 2024 and submitted a rectification report" against the available material. The material does not state completion of rectification or submission status, so the sentence is unsupported and the evidence gap must be recorded.

2. Input the branch connections of the User Selection node. Compare the user's selection against the "yes" branch execution condition. Observe whether the corresponding "yes" branch executes after the user makes a choice. The handover request "Move the above ticket and inquiry material into the rectification reply process" requires human confirmation of its authorization status. A pending review does not show that operating permission is missing, and it does not constitute approved execution.

3. Input an explicit paper-based empty result []. Compare whether the downstream node design accepts an empty result. Observe whether the empty result is treated as a retrieved record or triggers external synchronization automatically. The retrieval check records observations and failure branches only; it does not guarantee a first hit, full recall, or that an unrelated query returns empty.
