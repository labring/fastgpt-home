# Channel diversion reviews: interactive forms for staff training

## What the documents look like

Channel diversion review covers regional order and price order. The working materials are diversion complaint forms, anti-counterfeit code records, penalty notices and investigation photographs. This differs from rebate accounting: the data here concerns whether goods have moved outside an authorized sales region, and it does not process rebate amounts. Sources include the anti-counterfeit code system, e-commerce platform prices, distributor shipment records and market inspections. Updates are weekly and irregular.

Store service and internal training sit inside this category, and three actions need to stay separate: complaint intake, evidence comparison, and training handover. The form input node collects the information a user fills in and passes it to later nodes after submission; it does not provide a business database. The user selection node executes a branch according to the user's choice; it does not act as a staff directory or a business data selector. Both nodes enter an interaction state when triggered, record the workflow state, and continue downward after the interaction completes. Field validation, business approval, write-back and batch operations belong to external systems or later nodes as required.

## Constraints at the interactive forms step

Complaint forms, anti-counterfeit code records, penalty notices and investigation photographs come from different sources and sit in different states. Values collected by a form are filled-in content only. They do not establish goods flow, the scope of an authorization, or the effectiveness of a penalty. Retrieval and forms do not carry authorization or execution effect.

Hypothetical drill sample: a brand channel control role records one diversion complaint in a paper log. The source text reads: "Complainant: East China distributor A; subject of complaint: one e-commerce store link; anti-counterfeit codes involved: three, with a consistent code segment prefix; complaint date: 10 March 2025; request: verify whether cross-region sales occurred." The same batch of materials includes one investigation photograph whose caption reads: "Taken at a warehouse entrance; the carton code matches the prefix listed on the complaint form; date taken 12 March 2025." The draft sentence to be assessed is: "The store has committed cross-region diversion; issue a penalty using the penalty notice template." That draft relies only on the matching prefix and the photograph caption. It does not state the relationship between the store entity and distributor A's authorized region, and it does not state who holds penalty authority. The finding is therefore unsupported and remains pending verification.

## Three common errors

1. Treating form submission as authorized execution. Input: the complaint source text above and the draft sentence. The erroneous action is entering penalty issuance directly after submission. The correct comparison point is whether penalty authority ownership is stated; when it is not stated, the result should be pending verification. Observable result: the flow stops at the pending verification node and no penalty notice is generated.

2. Treating the user selection "Accept" as a factual finding. Input: the option "Accept" and the complaint source text. The erroneous action is concluding from it that cross-region sales occurred. The correct comparison point is whether the complaint states the relationship between the store entity and the authorized region. Observable result: the selection result advances handover only and does not change the evidence status field.

3. Treating a consistent anti-counterfeit prefix as a same-batch conclusion. Input: three codes with a consistent segment prefix and the photograph caption. The erroneous action is finding that all of them are diversion from the same batch. The correct comparison point is whether the code segment prefix and the batch identifier occupy mutually exclusive values in the same field. Observable result: the record keeps the consistent prefix as an observation, and the batch conclusion remains unsupported.

## How to verify the setup

- Verification one: input the complaint source text above and the draft sentence, then compare whether the draft states the entity's authorized region relationship and penalty authority ownership. When neither is stated, the expected result is pending verification and the flow must not enter the penalty issuance branch. This expectation is a paper exercise and was not actually run.

- Verification two: input the "Accept" option from the user selection node and the same complaint source text, then compare whether the selection result is written into the evidence status field. The expected observation is that the handover direction is recorded while the evidence status stays unchanged. If the evidence status is rewritten, record that as an observation difference pending verification.

- Verification three: input the investigation photograph caption and the three anti-counterfeit code prefixes, then compare whether the prefix field and the batch identifier field hold mutually exclusive values. The expected observation is that the consistent prefix is retained as an observation item and the batch identifier remains empty. If downstream design needs to receive an empty result, a paper input of [] can be used to check that design; no claim can be made that a fictional rule retrieval necessarily returns []. Libraries built on different vector models cannot be associated together; check identifiers first, exclude non-matching items, and record the actual observation.
