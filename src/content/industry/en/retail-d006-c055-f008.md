# Franchise filing management: workflow routing for staff training

## What the documents look like

Franchise filing management handles legal disclosure and the commerce department system. It sits apart from head-office site selection and store opening, and it does not cover specific premises engineering. The main data sources are the commercial franchise information management system, enterprise licences, store lists, and contract ledgers. The daily documents are franchise contracts, operations manuals, filing materials, and information disclosure documents. Errors in this category can lead to an order to file, franchise contract disputes, or administrative penalties.

In the store service and internal training setting, the materials that workflow routing must carry are mostly contract clause extracts, operations manual chapters, filing material checklists, and information disclosure document passages. The status fields on these materials are frequently incomplete and need manual entry or cross-checking. An update frequency of irregular or annual does not change the routing behaviour described on this page, so it is not treated as a routing input.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and the dialogue box is hidden. After the user completes the required fields and submits, the node collects the submitted form information and passes it to subsequent nodes. The User Selection node is also a user interaction node with the same interaction state and state recording. After the user makes a choice, the node evaluates that choice and executes the "yes" branch. State recording and dialogue box hiding are behaviours of the interaction nodes; no separate global state recording switch is documented.

Collected information must be explicitly passed to later retrieval, judgement, or interface nodes. Order writing, document backfill, and external status synchronisation require a separate business interface or a later process. Retrieval and forms do not constitute authorised execution.

Hypothetical drill sample: a franchisor head-office legal staff member submits a "Store Service and Internal Training Handover Request". The attached material text reads: "Franchise contract number HYP-2024-017, signing date 12 March 2024, contract status field blank; operations manual Chapter 4 'Store Service Standards' marked version V2, release date February 2024; filing material checklist item 7 'information disclosure document' status 'to be supplemented'." The draft judgement sentence under review is: "This franchise contract has taken effect, operations manual V2 can be used for store training, and the information disclosure document has completed filing." This sentence touches three separate facts: contract effectiveness, manual version applicability, and filing completion. The materials provide no confirming field for any of the three.

## Configuration and implementation checks

| Configuration item | Use on this page | Hypothetical starting point and comparison method |
| --- | --- | --- |
| Form Input node | Collect the contract number, manual version, and filing material status from the handover request | Required fields set to contract number and filing material status; compare item by item against the material text for completeness |
| User Selection node | Decide whether the handover request continues to route | Branch condition set to "is the material status to be supplemented"; compare against the status field in the material text |
| Output receiving node | Pass collected information to a later retrieval or judgement node | Check whether output fields match input fields |
| External operation split | Contract effectiveness confirmation and filing completion backfill | Mark as requiring a separate business interface; not implemented inside this node |
| Manual cross-check action | Cross-check the contract status field and the filing material status | Compare against the blank or "to be supplemented" field in the material text |

These starting points are hypothetical choices for this drill, not documented defaults. Each is selected because it maps directly to a field present or absent in the sample material, and each is compared against that material text.

## Three common errors

1. Treating a blank contract status field as proof that the contract has not taken effect or has taken effect. The material does not state an effectiveness status, so the only supportable record is that the claim is unsupported.
2. Treating the information disclosure document status "to be supplemented" as completed filing. "To be supplemented" and "completed" are different states and cannot be substituted for each other.
3. Using the contract number collected by the Form Input node directly for an external system write. A collected form value is not authorised execution; the write requires a separate business interface.

## How to verify the setup

1. Input the hypothetical sample material text. Compare the draft judgement sentence "this franchise contract has taken effect" against the blank contract status field. If the status field remains blank, the judgement sentence is unsupported.
2. Input the hypothetical sample material text. Compare the draft judgement sentence "operations manual V2 can be used for store training" against manual version V2 and its release date. If the material does not state an applicable training scope, the sentence remains to be verified.
3. Input the hypothetical sample material text. Compare the draft judgement sentence "the information disclosure document has completed filing" against filing material checklist item 7, whose status is "to be supplemented". If the status is still "to be supplemented", the sentence conflicts with the material field.

These comparisons state expected observations only. No test has been run, no deployment has occurred, and no approval, refund, or other business action has taken place. Where a field is absent from the material, the gap stays a gap.
