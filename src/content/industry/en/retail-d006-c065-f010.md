# Livestream violation appeals: citation tracing for staff training

## What the documents look like

Livestream violation appeals respond to penalties that have already been issued. The working materials are the platform violation notice, the livestream recording, product qualification files and the draft appeal statement. These materials are assembled when a violation occurs, so the update rhythm is irregular rather than scheduled. In a store service and internal training setting, the handover between operations staff must carry the source text, the proposed wording and the authorization state together, because the three are not interchangeable.

Citation tracing is the slow part of this work. Locating the violating segment, supplementing evidence and writing the appeal reason all depend on checking the source text line by line. A livestream recording is long, and product qualification files exist in multiple versions. A handover that passes along conclusions without the original source location cannot be reviewed later by another person.

## Constraints at the citation tracing step

The knowledge base search node outputs cited content as an array, and the array length may be zero. When no content is retrieved, that output branch still completes. The retrieval output is then handed to the answering step, where each answer sentence is checked against the cited source text. Citation display checks require a traceable sample; the model's thinking process and the fluency of the answer do not substitute for source evidence. Version currency checks require both the current version and a historical version of a document; whether a citation is adopted still depends on review against the effective version.

Semantic recall and the minimum relevance setting are filter thresholds. They do not perform permission or entity isolation. Knowledge bases that use different vector models cannot be associated together; the vector model identifier must be checked first and any mismatched base excluded. RRF is the fusion process for mixed retrieval results, not a toggle that can be switched on.

Hypothetical paper exercise sample (fictional, used only to illustrate the checking method): a store compliance specialist receives a platform violation notice whose source text reads: "This livestream, between 20:14 and 20:19 on 12 March 2025, displayed a product without qualification documents, involving product number A-2210; penalty status is pending appeal." The same batch contains a product qualification file marked valid until 30 June 2025. The proposed handover request reads: "Please confirm the violating segment for this session has been located, and that the appeal statement may cite the qualification file directly as supplementary evidence."

## Configuration and implementation checks

| Associated knowledge bases | Violation notice base, livestream recording index base | Both bases must use the same vector model; check the vector model identifier one by one and exclude any base that does not match |
| Search mode | Mixed retrieval | Exact queries for numbers and dates depend on full-text recall; compare against a pure semantic retrieval result before deciding |

| Minimum relevance | Hypothetical starting point 0.4 | Used to filter low-relevance segments; compare recall count and false recall against a 0.2 starting point |
| Result rerank | Enabled | Second-pass ordering when candidate segments are numerous; compare ordering against the result with rerank not enabled |
| Cited content output | Passed to the answering step | Check each answer sentence against the cited source text for the same subject, the same period and the same field |

## Three common errors

1. Treating retrieval output as an authorization conclusion. The search node returns cited content, which does not confirm authority to act on the appeal. A pending-review status does not show that operating authority is missing; the authorization record must be checked separately.
2. Associating knowledge bases that use different vector models. When the vector model identifiers of two bases do not match, they cannot be associated together. The mismatched base is excluded and the actual observation recorded. A missed recall or a redundant result cannot be inferred from the mismatch.
3. Using answer fluency in place of source checking. An answer sentence and the cited source text must share the same subject, the same period and the same field. When only evidence from a related stage exists, the item is recorded as pending verification, not as a denial or a conflict.

## How to verify the setup

1. Input the source text of the hypothetical notice and the source text of the qualification file above. Compare the proposed sentence "cite the qualification file directly as supplementary evidence" against the validity period marked in the source text. When the qualification validity period covers the date of the violation, the sentence is supported by the source text; when it does not cover that date, the sentence is recorded as unsupported.
2. Input the proposed handover request. Compare its statement "the violating segment for this session has been located" against the actual return from the livestream recording index base. When the returned segment contains the 20:14 to 20:19 interval, that status is supported; when the return is an empty array, the status is recorded as pending verification, and an empty array does not mean the process has terminated.
3. Input the vector model identifiers of the two bases. Compare whether they match. Association is permitted only when the identifiers match. When the identifiers do not match, exclude that base and record the observation; do not run cross-model retrieval to compare missed recall.
