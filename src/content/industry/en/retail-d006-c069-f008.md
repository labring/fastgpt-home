# Dealer rebate calculation: workflow routing for staff training

## What the documents look like

Dealer rebate calculation takes place after sales are completed. The working materials are rebate policies, sales attainment tables, reconciliation statements, and red-letter invoices. Brand finance, channel sales, and dealer finance all handle these documents, and updates follow a monthly or quarterly rhythm. In store service and internal training settings, a workflow needs to connect policy terms, attainment data, and invoice offset actions so operations staff can check and hand off each step.

A rebate policy states the conditions and calculation basis for a rebate. A sales attainment table records actual completion. A reconciliation statement confirms the amount both sides accept. A red-letter invoice carries the offset function. The subject, period, and fields across all four materials must agree before the next check step can proceed. When these elements diverge, the result is rebate disputes, channel conflict, and incorrect revenue recognition.

## Constraints at the workflow routing step

Rebate calculation inputs sit in several systems. A workflow can arrange the order of transfer between nodes and the timing of interaction. It cannot replace writes, approvals, or synchronization in a business system. The form input node enters an interaction state when triggered, collects required information, and passes that information to later nodes after submission. The user selection node executes the corresponding yes branch after the user makes a choice. Both are user interaction nodes. When triggered, they record the workflow state and continue downward after the user completes the interaction. Retrieval results and form entries do not constitute authorization. Order writes, document backfill, and external status synchronization require a separate business interface or a later process.

Hypothetical drill sample: A brand finance staff member receives a reconciliation statement during quarterly rebate calculation. The source text states: "Subject: a dealer in East China; Object: 2024 third-quarter rebate; Status: both sides have confirmed the amount; Valid scope: limited to the sales attainment portion of this quarter." A draft sentence also arrives: "This dealer has completed full-year rebate settlement and can proceed directly to red-letter invoice issuance." The question is whether the draft sentence has support in the reconciliation statement source text. The source text covers only the third quarter and does not state a full-year settlement status. The draft sentence exceeds the valid scope.

## Three common errors

1. Treating information collected by the form input node as authorized execution. A form collects values only. Business verification, approval, database writes, and external synchronization need downstream implementation. Check method: input the reconciliation statement source text above, compare the form output fields against the subject, object, status, and valid scope in the source text, and observe whether the output only passes values without triggering a write.

2. Treating the yes branch of the user selection node as automatic judgment. That node executes the corresponding branch after the user makes a choice and does not judge business status on its own. Check method: input the draft sentence, compare the branch direction against the valid scope in the reconciliation statement source text, and observe whether the branch runs according to the user selection without replacing business judgment.

3. Treating retrieval results or similarity scores as a permission or entity filter. Retrieval is a separate step outside authorization. Check method: input the subject and period from the reconciliation statement source text, compare returned records against the subject and period in the source text, observe whether records from another subject or period appear, and record the actual observation.

## How to verify the setup

- Verification one: Input the reconciliation statement source text and the draft sentence from the hypothetical drill sample. Compare the draft sentence claim of "full-year rebate settlement" against the source text valid scope of "limited to the sales attainment portion of this quarter." Observe whether the draft sentence has support in the source text. The expected result is unsupported; record the evidence gap and do not judge it as negation or conflict.

- Verification two: Input the subject "a dealer in East China," object "2024 third-quarter rebate," and status "both sides have confirmed the amount" from the reconciliation statement source text. Compare the workflow output fields against these four elements in the source text. Observe whether the output keeps the same subject, same period, and same fields. The expected result is consistent fields; if a field is missing, record the gap.

- Verification three: Input an explicit paper input of []. Check how the downstream design handles an empty result. Observe whether the downstream processes the empty input according to its design. The expected result is that the downstream handles it as designed; do not claim that a fictional rule retrieval necessarily returns []. If the downstream design does not define empty-result handling, record it as pending verification.
