# Cross-border product labels: citation tracing for staff training

## What the documents look like

Compliance evidence for cross-border product labels is created before listing and import. Store service and internal training rely on four material types: product test reports, English labels, MSDS documents, and platform prohibited-item lists. These materials come from platform policy centers, testing laboratory reports, destination-country regulation libraries, and supplier files. Updates are irregular and every new listing requires fresh checking. When store staff explain a product's compliance status to a customer, the cited source must trace to a specific document version. The same applies to retrieval results demonstrated during training. The same product may have different test report versions at different points in time, so checking requires confirming that the cited version matches the current listing state.

## Constraints at the citation tracing step

The knowledge base search node can associate one or more knowledge bases that share the same vector model, and outputs citations as an array whose length may be zero. An empty array does not mean the workflow has errored or terminated. Retrieval output must pass to the answering step, where each answer sentence is checked against the cited source text. The minimum relevance score is a filter threshold that takes effect only during semantic retrieval or result reranking; it does not perform permission or entity isolation. Hybrid retrieval merges multiple result paths through RRF. Reranking requires a model and is enabled according to configuration. Image retrieval requires corresponding image input and model capability. Knowledge bases using different vector models cannot be associated together; the identifier must be checked first and non-matching bases excluded.

Hypothetical exercise sample: A store receives an English label draft from a supplier with the text "Product: Children's Toy, Model KT-2024, Batch 2024-08, Age Grade: 3+, Manufacturer: ABC Toys Co., Ltd." A separate test report draft reads "Test Report No. TR-2024-0815, Sample: KT-2024, Test Date: 2024-08-10, Result: Pass for EN71-3." A draft sentence under review is "This product has passed EN71-3 testing and is suitable for children aged 3 and above." Checking requires confirming that the sample model in the test report matches the model in the label draft, that the test date falls within the valid range, and that "has passed" in the draft sentence corresponds to "Result: Pass" in the report. The report does not state a conclusion about suitability for children aged 3 and above; that part remains unsupported.

## Configuration and implementation checks

| Configuration item | Hypothetical trial starting point | Reason and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Select the compliance document base for listed products | Check base identifier and vector model identifier; exclude bases with different vector models |
| Search mode | Hybrid retrieval | Uses semantic and full-text recall together, suitable for model and number queries |
| Minimum relevance score | 0.5 | Trial starting point for this exercise; compare returned results against 0.3 and 0.7 |
| Citation limit | 2000 tokens | Compare returned content against 1000 and 4000 tokens |
| Result reranking | Enabled | Requires a ReRank model; compare ordering before and after enabling |
| Citation output | Array format | Check output length; when the array is empty, inspect downstream handling design |

## Three common errors

1. Treating retrieval output as an authorization conclusion. Returned citations indicate that document fragments were matched; they do not indicate that a product has been approved or that a label has passed review. The check compares the cited source text against the draft sentence and confirms whether any conclusion is unsupported by the source.

2. Associating knowledge bases that use different vector models. The documentation requires the same vector model for joint association. The check inspects base identifiers and vector model identifiers, excludes non-matching bases, and records actual observations without inferring runtime behavior.

3. Using the minimum relevance score for permission or entity isolation. The minimum relevance score is a filter threshold and does not exclude unrelated business records or unauthorized records. The check confirms whether the retrieval scope contains the required materials and records an evidence gap when they are missing.

## How to verify the setup

1. Using the label draft and test report from the hypothetical sample, enter the retrieval question "KT-2024 EN71-3 test result" and compare whether the returned citations include the test report source text. Observe whether the cited content matches "Result: Pass" in the report. The expected observation is that the returned citations include that report fragment; first-position matching is not guaranteed.

2. Using the draft sentence "This product has passed EN71-3 testing and is suitable for children aged 3 and above," compare the draft sentence against the cited source text and observe whether "suitable for children aged 3 and above" has corresponding source support. The expected observation is that this part is marked unsupported and requires additional evidence or revision of the draft.

3. Using an empty array input [] as a paper exercise, inspect the downstream handling design and observe whether the downstream node processes empty citations. The expected observation is that the downstream design can handle an empty array; this does not claim that any fabricated rule retrieval will always return [].
