# Creator commission settlement: citation tracing for staff training

## What the documents look like

Creator commission settlement happens after a sale closes. The objects being reconciled are valid promotion orders and post-sale commission deductions. In store service and internal training, staff need to explain how four materials cite one another: commission setting records, settlement statements, refund deduction details, and invoices. These materials update weekly or monthly. Statement amounts change with refund status, and the same order can sit at different stages across different materials. Citation tracing requires every conclusion to return to a specific field in a specific material. Any status the material itself does not record stays unknown.

The knowledge base search node can associate one or more knowledge bases that share the same vector model, and it outputs citations as an array whose length may be zero. Retrieval is a lookup action and does not constitute authorization. Store training often treats a search hit as an approval basis, or treats a filled form as a completed business action. Those inferences lack material support.

Hypothetical drill sample: an internal store training document titled "Commission Settlement Reconciliation Notes (Hypothetical Version)" states three sentences. Sentence one: the commission amount in the settlement statement is calculated over orders whose status in the Selected Alliance backend is "completed." Sentence two: the refund deduction detail records orders whose after-sale refund is complete and the corresponding deducted amount. Sentence three: the correspondence between the invoice amount and the settlement statement amount is checked by finance during invoicing. The draft sentence to be judged is: a given order is registered in the refund deduction detail, therefore that order's commission has been deducted from the current period settlement statement.

Judging this draft sentence requires the same subject, the same period, and the same field. The refund deduction detail records a deduction entry. Whether the settlement statement has already deducted it belongs to a different field. The materials do not state the synchronization point between the two, so the draft sentence is unsupported and needs either the deduction field for the corresponding period in the settlement statement or a manual reconciliation record.

## Constraints at the citation tracing step

The search node returns citations as an array, and a zero-length array still lets the downstream chain run. An empty citation array does not mean the workflow errored out. A retrieval hit is not an approval, and a form value is not a database write, an approval, or an external synchronization. Those downstream steps need their own stated implementation.

The minimum relevance value is a filter threshold, not a final ranking rule and not a permission or entity filter. It does not exclude unrelated businesses or unauthorized records. Enabling question optimization, hybrid retrieval, image retrieval, or result reranking can produce multi-path fused results that are not strictly ordered by a single vector similarity.

The citation limit is measured in tokens, not in a guessed item count. The documented unit controls how much content is cited per search. Reranking requires a rerank model and must be enabled per its setting; it is not automatic. Image retrieval requires actual image input and the matching model capability. The overall retrieval diagram lists optional paths, and not every request executes all of them.

Knowledge bases must share the same vector model before they can be associated. If the vector model identifiers differ, the correct action is to exclude the mismatched base and record the observation, not to run a cross-model retrieval and infer missed recalls or redundant returns.

## Three common errors

1. Treating a registration entry in the refund deduction detail as evidence that the settlement statement has already deducted it. The input is one deduction entry in the detail; the comparison object is the deduction field for the same period in the settlement statement; when that field is not recorded, the conclusion is unsupported and the evidence gap must be recorded.

2. Treating a knowledge base search hit as an authorization basis for creator commission. The input is a citation array returned by one search; the comparison object is whether the materials record an approval or authorization field; a retrieval result does not constitute authorization, and when the authorization field is missing the status stays unknown.

3. Associating knowledge bases with different vector models and then inferring retrieval behavior. The input is the vector model identifiers of two bases; the comparison object is whether the identifiers match; when they differ, only exclude and record, without inferring missed recalls or redundancy.

## How to verify the setup

1. Use the three source sentences and the draft sentence from the hypothetical sample above. The input is the draft sentence plus the three source sentences; compare whether the deduction conclusion in the draft sentence has support from a settlement statement field; when the source text does not record that field, the judgment is unsupported, and a satisfied condition shows the judgment conclusion and the evidence gap recorded together.

2. Use an explicit paper input of an empty array. The input is citation output `[]`; compare whether the downstream answer step continues through the empty citation path; a satisfied condition shows the downstream step does not error out or terminate and does not fabricate citation sources.

3. Use two knowledge bases whose vector model identifiers differ. The input is the two model identifiers; compare whether the identifiers match; when they do not match, exclude joint association and record the observation; a satisfied condition shows no cross-model retrieval was executed and no retrieval result was inferred.
