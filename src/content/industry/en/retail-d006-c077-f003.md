# Import and export permits: shared access for staff training

## What the documents look like

Import and export permit handling takes place before customs declaration and determines whether a shipment may lawfully cross a border. In store service and internal training, the shared and embedded materials are the automatic import licence, the dual-use item licence, the contract and the product description. These materials update irregularly, per shipment, and draw on the commerce authority system, customs commodity codes, supplier materials and customer statements of use. The stated frequency is irregular and per shipment; this page does not derive batch synchronisation, full synchronisation or real-time triggers from it.

When a no-login window link is sent to trainees or colleagues, the link identifier is an access entry point. It is not a business authorisation. Identity verification is limited by the commercial edition scope and is judged by the success and uid values returned by the official interface. The anonymous local identifier depends on the same device and the same browser; cross-device records require separate identity and session design.

## Constraints at the shared access step

The no-login window is created from the publishing channel and the system-generated full link is copied. Expiry time and QPM are set for the usage scope and checked against the actual version; QPM is the maximum number of visits per user per minute. The points cap is checked against the usage limit of the sharing entry point and the cost attribution, and some parameters are restricted by version. After the identity verification root address is configured, initialisation, conversation start and conversation end send requests to that address, and the server only needs to return whether verification succeeded. The uid is used to pull and save conversation records, and its format is a string that excludes specific characters and is no longer than 255 bytes.

Existing node behaviour, actually configurable fields, manual verification actions and business actions that require a separate system implementation must be kept separate. Retrieval and similarity do not perform permission or entity isolation. Libraries across different vector models cannot be associated together; check the identifier first and exclude non-matching items, and do not run cross-model retrieval to compare missed recall.

Hypothetical paper exercise sample: a store internal training handover sheet records the material text "Automatic import licence application, commodity code 8471.30, applicant Group A, status pending review; dual-use item licence application, item a certain model of sensor, status submitted; product description states the use is industrial inspection." The proposed handover sentence is "This permit has been completed and shipment can be arranged." The request to be judged is "Send the no-login window link to the trainee so the permit progress can be viewed directly through the link."

## Configuration and implementation checks

| Configuration item | Corresponding material on this page | Implementation check |
| --- | --- | --- |
| No-login window name | Store training sharing entry point | The name is for record display only and does not indicate business authorisation |
| Expiry time | Scope of use of the training link | Set according to the actual version; after expiry the link cannot be used |
| QPM | Maximum visits per user per minute | Check against the official description; do not infer other rate-limiting mechanisms |
| Points cap | Sharing entry point usage and cost attribution | Check the team to which billing is attributed; some parameters are restricted by version |
| Identity verification | Third-party system identity authentication | Limited by the commercial edition scope; judge by the success and uid returned by the interface |
| Conversation record boundary | Anonymous local identifier | Depends on the same device and same browser; design cross-device handling separately |

Hypothetical starting value for this exercise: set the expiry time to a date consistent with the training period. The reason for this choice is that the link is used only for this training, and the comparison object is the training end date. This value is not an official default.

## Three common errors

1. Treating the link identifier as business authorisation. The input is the sharing link, the comparison object is the pending review status of the permit, and the observable result is that the link opens while the material status remains pending review, which does not support a conclusion that the matter is completed.
2. Using similarity in place of permission filtering. The input is a retrieval request, the comparison object is the owning subject of the returned records, and the observable result is that the similarity score does not distinguish subjects, which does not support a conclusion that the records are authorised.
3. Treating pending review as a negative conclusion. The input is "status pending review" in the handover sheet, the comparison object is the wording "completed", and the observable result is that the values of the same field are mutually exclusive, so the proposed handover sentence is not supported.

## How to verify the setup

1. Input the hypothetical sample material text and the proposed handover sentence, compare whether the proposed sentence and "status pending review" concern the same subject, the same period and the same field, and observe that the two values are mutually exclusive, so the proposed sentence is judged unsupported.
2. Input the request to be judged "Send the no-login window link to the trainee", compare the link identifier with the authorisation scope of the permit, and observe that the link provides only an access entry point and does not constitute business authorisation, so the request requires separate confirmation of the authorisation status.
3.
