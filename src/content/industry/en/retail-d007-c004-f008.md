# Temu semi-managed sellers: workflow routing for operating reviews

## What the documents look like

Semi-managed sellers on Temu maintain overseas inventory and ship orders themselves, rather than only supplying goods to the platform. This difference shapes the material set for operating reports and exception reviews. The relevant documents are the product declaration form, the overseas inventory table, the price declaration, and the platform fulfillment order. Data sources sit across Temu Seller Center, overseas warehouse WMS, logistics tracking, and procurement cost tables. Updates arrive at daily and per-order frequency, so review material appears at order-level and day-level granularity.

Handling platform fulfillment exceptions is one of the most time-consuming steps. Exception review therefore serves as the main trigger scenario for workflow routing on this page. A review that compares the fulfillment order, the inventory snapshot, and the logistics trace in one view can route an interaction, but the routing step itself does not authorize any downstream business action.

## Constraints at the workflow routing step

The form input node belongs to the user interaction nodes. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. After the user fills required information and submits, the node collects the submitted form information and passes it to subsequent nodes. The user selection node also belongs to the user interaction nodes. When it triggers, the conversation enters an interaction state and the workflow state is recorded. When the user makes a choice, the node judges that choice and executes the "yes" branch.

The recorded interaction state is behavior of the interaction node itself. No separate global state-recording switch is documented. Collected information must be explicitly passed to later retrieval, judgment, or interface nodes, and outputs must be compared item by item against inputs. Order writing, document backfill, and external status synchronization require a separate business interface or a later process. Retrieval or a form does not constitute authorized execution.

Hypothetical paper exercise sample: an operator submits material while reviewing one fulfillment exception. The source text reads: "Overseas inventory table, 2024-06-01 to 2024-06-30, shows SKU-A has 120 sellable units at the US West warehouse; platform fulfillment order dated 2024-06-15 records that the SKU-A order should ship before 2024-06-18 and its status is pending shipment; logistics tracking as of 2024-06-20 has no pickup record." A draft sentence reads: "The SKU-A order of June 15 is overdue and unshipped, inventory is sufficient, please reship directly and synchronize WMS." The draft sentence contains a reship request, which is an external operation and requires a separately confirmed authorization boundary.

## Three common errors

1. Treating a reship request collected by a form as already authorized execution. The draft sentence contains "please reship directly and synchronize WMS." A form only collects values; reship and synchronization require a separate business interface, and the authorization state remains pending verification when it is not stated.
2. Treating the "yes" branch of the user selection node as automatic judgment. The node executes the corresponding branch after the user makes a choice. Branch connections require verification one by one, and automatic attribution of an exception must not be assumed.
3. Treating retrieval or a relevance score as permission or entity isolation. Retrieval does not handle authorization, and a relevance score does not exclude unrelated businesses or unauthorized records. Libraries using different vector models cannot be associated together.

## How to verify the setup

1. Input the three source sentences and the draft sentence from the hypothetical sample, then compare whether the form node output fields completely carry the fulfillment order number, exception date, and inventory snapshot. If fields are missing or are not passed to later nodes, the condition is not met.
2. Input the choice result of the user selection node, then compare whether the "yes" branch connects to the report summary node. If the branch is unconnected or connects to an unrelated node, the condition is not met.
3. Input a paper empty result [], then compare whether downstream nodes handle the empty value as designed. If downstream treats the empty value as a valid record, the condition is not met. All three checks are paper comparisons and have not been run.

These checks test the named primary task of workflow routing for operating reports and exception reviews. They do not test identity certification, report analysis, or any other task. Missing evidence remains missing: a pending request is not approval, an offered option is not execution, and an unsigned termination is not a completed termination.
