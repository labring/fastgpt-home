# Temu semi-managed sellers: citation tracing for operating reviews

## What the documents look like

Semi-managed sellers on Temu maintain overseas inventory and complete fulfillment themselves. The daily document set includes product declaration forms, overseas inventory sheets, price declarations, and platform fulfillment orders. Operating reviews and exception retrospectives depend on these four document types because a conclusion about stock, price, or shipment must point back to a specific material, a specific version, and a specific field.

Data sources named in the category brief are Temu Seller Center, overseas warehouse WMS, logistics tracking, and procurement cost sheets. Update frequency is daily and per order. That frequency supports freshness checking of a cited source. It does not create a batch synchronization, full synchronization, real-time trigger, or transaction-triggered mechanism.

The citation tracing task answers one question: which material, which version, and which field support a stated conclusion. Retrieval supplies candidate content. It does not decide whether the reader is authorized to use that content.

## Constraints at the citation tracing step

The knowledge base search node can associate one or more knowledge bases that share the same vector model. Its output is an array of cited content, and the length may be zero. When the array is empty, the output path still completes. The citation limit controls the maximum tokens of content cited per search. The minimum relevance value applies only during semantic retrieval or when result reranking is used, and it acts as a filter threshold. A similarity score is not an authorization, entity, or permission filter, and retrieval results do not carry permission or entity isolation.

Assume a paper exercise sample. Material one: "Overseas inventory sheet (version A, 1 March 2026) states that SKU-A has 120 units available in the Germany warehouse." Material two: "Platform fulfillment order (2 March 2026) states that 40 units of SKU-A have been shipped." Material three: "Procurement cost sheet (version A) states that the unit cost of SKU-A is 8 USD." A draft sentence under review reads: "As of 2 March 2026, SKU-A has 120 units available in the Germany warehouse and can continue to accept new orders." The draft sentence and the fulfillment order concern the same SKU, the same period, and the same inventory field. The comparison must check whether the 40 shipped units should be deducted. The materials do not state an inventory deduction rule. That gap remains open for verification.

## Three common errors

1. Treating a retrieval hit as authorization. Input is the sample retrieval result; the comparison object is the authorization status record. A high retrieval score does not mean the current subject may use that record. Authorization requires a downstream system implementation.
2. Treating a pending request as approved. Input is a request for an inventory deduction rule that the sample materials do not state; the comparison object is the effective rule text. While the request is pending review, the rule cannot be treated as effective.
3. Associating knowledge bases with different vector models. Input is two knowledge bases with different vector model identifiers; the comparison object is the identifier of the selected base. Exclude those that do not match and do not run cross-model retrieval.

## How to verify the setup

1. Input the three sample source texts and the draft sentence. Compare the available inventory figure in the draft sentence against the shipped quantity in the fulfillment order. The condition is met only when the materials state a deduction rule and the draft sentence has been adjusted according to that rule.
2. Input a paper empty array []. Compare whether the downstream answering step accepts the empty citation. The empty-result handoff condition is met only when the path completes without error.
3. Input the two versions of the sample materials. Compare the version identifier that the citation output points to. The traceability condition is met only when the citation can be located to a specific version.

These checks describe expected observations. They do not report a completed test, a deployment, an approval, or a refund.
