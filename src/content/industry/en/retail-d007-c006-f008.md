# General export declarations: workflow routing for operating reviews

## What the documents look like

A general trade export declaration produces a per-shipment set of materials: the export customs declaration form, the commercial invoice, the packing list and the contract. Data sources named in the brief include China International Trade Single Window, the customs code library, the freight forwarder bill of lading and the company ERP. Compared with general trade import declarations, an export declaration also affects export tax rebate voucher matching. For operating reports and exception reviews this means the declaration form fields and the invoice and contract fields that the rebate voucher depends on must be checked inside the same shipment scope. Materials update per shipment, so the workflow must organize input, judgment and output one shipment at a time and must not compare fields across different shipments.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When it is triggered, the conversation enters an interaction state, the workflow state is recorded, and after the user completes the interaction and submits, the node collects the entered form information and passes it to later nodes. The User Selection node is also a user interaction node. When it is triggered, the conversation enters an interaction state and the workflow state is recorded; when the user makes a selection, the node evaluates that selection and executes the "yes" branch. In this task, the shipment identifier, material status and fields to be checked that these interaction nodes collect are input values. A retrieval hit or a submitted form does not by itself constitute authorization. Order writes, document backfill and external status synchronization require a separate business interface or a later process. If retrieval libraries use different vector model identifiers, they cannot be associated together; the identifiers must be checked first, non-matching libraries excluded, and only actual observations recorded.

Hypothetical paper exercise: a documentation clerk at a foreign trade company submits a handover request during an operating report exception review. The draft sentence is "This shipment has completed export tax rebate voucher matching." The three source sentences supplied for checking are: "The export customs declaration form states a declaration date of 12 March 2024 and contract number HX-2403-07." "The commercial invoice states invoice number INV-2403-07, and the amount agrees with the declaration form." "The contract states the signing parties are Company A and Company B and does not state any rebate voucher matching status." The authorization boundary of this request is that the clerk submits a review note; it does not include approving a rebate or amending the declaration form.

## Configuration and implementation checks

The table below lists documented settings or implementation checks tied to the exercise above. Where a value is needed it is stated as a hypothetical starting point for this exercise with the comparison object named, and is not an official default.

| Configuration item | Setting or check | Relation to the exercise |
| --- | --- | --- |
| Form Input node | Mark shipment identifier, material name and fields to be checked as required | Collects contract number and invoice number, passed on after submission |
| User Selection node | Set an "enter exception review" branch and execute the "yes" branch after the user selects | Clerk chooses to enter review, triggering the later checking path |
| Output handoff | Pass collected form fields explicitly to the later retrieval or judgment node and compare output against input item by item | Checks whether the draft sentence fields come from the source sentences |
| Retrieval scope check | Check the vector model identifier of the target retrieval library and exclude non-matching ones | Exercise materials must sit in an accessible target scope |
| External action split | Order writes, document backfill and external status sync connect to a separate interface or later process | The exercise request triggers no rebate status change |
| Empty result handoff | Check downstream design with the paper input [] and record the actual observation | When the matching status field is absent, the gap is retained |

## Three common errors

1. Treating a retrieval result as authorization. In the exercise the clerk submits a review note; a retrieved material only shows that text exists and does not show that rebate voucher matching has been approved. The input to compare is the draft sentence and the source sentences; compare subject, period and field; the observable result is that the sentence is unsupported.
2. Associating libraries with different vector models. If the exercise materials sit in retrieval libraries with different identifiers, check the identifiers first and exclude non-matching ones. Do not run a cross-model retrieval to compare missed recall; record only the actual observation.
3. Treating pending review as missing operating permission. In the exercise the contract does not state rebate voucher matching status, which is unsupported or pending verification. It does not constitute a denial or a conflict, and the evidence gap must be retained.

## How to verify the setup

1. Input the exercise draft sentence "This shipment has completed export tax rebate voucher matching" and the three source sentences, then compare subject, period and field: the materials do not state the matching status, so the observable result is that the sentence is unsupported and the gap must be recorded.
2. Input the exercise contract number HX-2403-07 and invoice number INV-2403-07, then compare the required form fields with the later node output: the fields correspond item by item and are passed on after submission, so the observable result is that the handoff holds; if a field is missing, record it as not passed.
3. Input the paper empty result [] and compare whether the downstream node design handles the empty-result branch: the observable result is that downstream retains the gap without inventing a matching conclusion. Whether retrieval returns an empty result is subject to actual observation and is not guaranteed.
