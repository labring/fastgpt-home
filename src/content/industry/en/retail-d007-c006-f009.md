# General export declarations: tool calls for operating reviews

## What the documents look like

For general trade export declaration, one difference from import declaration is that export tax rebate voucher matching is also affected. Operating reports and exception reviews draw on the export declaration form, commercial invoice, packing list and contract, with the main sources being China International Trade Single Window, the customs code library, freight forwarder bills of lading and enterprise ERP. These materials update per shipment. In this task, tool calls and plugins connect those document fields to report definitions and exception records for human comparison. A tool description tells the model what the tool is for. Tool parameters divide into fixed parameters for system modules and configurable parameters for plugins. When a required parameter has no suitable value, the model may not call the tool. The tool call termination node ends the current call and does not call the AI to summarize tool results. Custom tool variables extend inputs for nodes not treated as tool parameters.

## Constraints at the tool calls step

Tool calling depends on the model judging whether to execute a tool from the tool description, the parameter descriptions and whether each parameter is required. For operating reports and exception reviews, document fields come from different sources, so a plugin's parameter descriptions must state the input conditions and the situations in which the tool should not be called. When a suitable required parameter is absent, the model may not call the tool; the gap can be completed through interaction and the actual request checked. In advanced orchestration, connect available tools to the tool call module and tune with a small number of tools first. Retrieval or a form collecting a value does not constitute authorization; business verification, approval, database writes and external synchronization each need their own downstream implementation. Knowledge bases using different vector models cannot be associated together; check the identifiers and exclude those that do not match. For an empty result, a paper input of [] can be used to check the downstream design; it cannot be claimed that a fictional rule retrieval necessarily returns [].

Hypothetical paper exercise sample: the material text reads "Export declaration number HYP-2026-001, declaration date 10 March 2026, commodity code 8544422900, commercial invoice amount USD 12000, packing list quantity 300, contract number HT-2026-018, freight USD 800, insurance USD 120." The draft sentence to be judged is "The freight and insurance for this shipment total USD 920, consistent with the contract, and rebate voucher matching is complete." The sentence contains a subject, an object and an amount scope, but the contract does not state freight and insurance terms, and the rebate voucher matching status is not provided. This sample is for paper comparison only.

## Three common errors

1. Treating a parameter description as a guarantee of execution. In the sample, the plugin parameter description mentions "freight and insurance total", but the contract does not state that term. Judging rebate voucher matching complete on that basis treats the parameter description as an execution result. Check: input the sample material text and the draft sentence, compare whether the contract term field states freight and insurance, and observe that matching cannot be judged complete when the contract does not state it.
2. Treating a retrieval or form-collected value as authorized execution. In the sample, the draft sentence claims rebate voucher matching is complete, but no approval or verification record is provided. Check: input the sample request, compare whether authorization or verification evidence is attached, and observe that without evidence the item can only be recorded as pending verification.
3. Associating knowledge bases that use different vector models. The sample does not involve vector model identifiers. Directly associating and comparing documents from different sources skips the identifier check. Check: input the sample document source identifiers, compare whether the vector model identifiers across the bases match, and observe that non-matching identifiers should be excluded and the actual observation recorded.

## How to verify the setup

1. For the sample draft sentence "The freight and insurance for this shipment total USD 920, consistent with the contract, and rebate voucher matching is complete", input the material text and the draft sentence, compare whether the contract states freight and insurance terms and whether the rebate voucher matching status is present, and observe that when the contract does not state them and the matching status is missing, the sentence should be marked as unsupported and matching must not be judged complete.
2. For the sample request "Please complete rebate voucher matching directly based on declaration HYP-2026-001", input that request and the sample materials, compare whether an approval or verification record is attached, and observe that without an authorization record the item can only be recorded as pending verification and matching must not be executed.
3. For the sample document sources, input the source identifiers of the commercial invoice, packing list and contract, compare whether the vector model identifiers across the sources match, and observe that non-matching identifiers should be excluded and cross-model retrieval must not be executed to compare missed recalls. All three verifications are paper expectations and were not actually run.
