# General import declarations: citation tracing for operating reviews

## What the documents look like

General trade import declaration work centres on the dutiable value, freight and insurance, and tax payment. Each declaration produces an import declaration form, a commercial invoice, a packing list, a bill of lading, and a contract. Operating reports and exception reviews need these documents as cited sources, traced line by line, so that every figure in a report can be returned to a specific document and field. Importers, customs brokers, and customs managers work on the same document set, and citation tracing requires each summary figure to be traceable to a concrete document and field. The data update frequency is per declaration, and the reporting scope advances document by document as the paperwork is filed.

For this page, the operating report and exception review task is the primary task. Citation tracing means checking whether a proposed statement in a report is supported by the wording of the underlying import documents. It does not mean certifying identities, analysing report totals, or executing any customs action.

## Constraints at the citation tracing step

The knowledge base search node outputs cited content as an array, and the length may be zero. An empty array means the search path ran through without returning citations; it does not mean the workflow raised an error and stopped. Cited content is handed to a later answer or reporting step, where each answer is checked against the cited original text. Material currency checks use the current version and a historical version of a document as test sources, and whether a given citation is adopted still depends on review against the valid version. Semantic retrieval and the minimum relevance score are filter thresholds; they do not perform permission or entity isolation. Knowledge bases must share the same vector model before they can be associated together, and this requirement does not extend to business registration sites or other external systems.

Hypothetical paper exercise sample: a customs manager at an importer is preparing the March 2025 batch report. The source material provided for checking consists of three sentences. Sentence one: "Contract HT-2025-0312 specifies CIF terms, with the buyer bearing freight and insurance." Sentence two: "Bill of lading BL-0312 shows an arrival date of 18 March 2025, consignee Company A." Sentence three: "Commercial invoice INV-0312 states a goods value of USD 120,000, consistent with the contract amount." The draft sentence to be assessed: "The dutiable value for this batch has been confirmed at the contract amount, so freight and insurance need not be declared separately." The handover request to be assessed: "Please attach the cited sources for the three documents above to the March operating report exception review record."

## Three common errors

1. Treating an empty citation array as a workflow error. Check the input against a clearly written empty array, compare the node output with the downstream receiving design, and observe whether the path continues to run.
2. Treating the minimum relevance score as a permission or entity filter. Check the input against a cross-entity query, compare the returned content with the authorised scope, and observe whether records outside authority appear.
3. Writing the draft sentence straight into the report. Check the input against the three source sentences and the draft sentence, compare the draft against the original wording, and observe whether the freight and insurance field has support in the source text.

## How to verify the setup

1. Input the three source sentences and the draft sentence. Compare the draft claim "freight and insurance need not be declared separately" with sentence one, "the buyer bears freight and insurance." Observe whether the conclusion is supported by the source. The source does not state how freight and insurance are handled for declaration, so the conclusion is unsupported.
2. Input the handover request to be assessed. Compare the three document identifiers in the request with the retrieval scope, and observe whether the three documents fall within the selected knowledge base. If they are missing, record the evidence gap.
3. Input a clearly written empty array. Compare the node output with the downstream reporting reception, and observe whether the empty array is recorded as no citations returned rather than judged as an error that terminated the run.

These checks describe what to compare and what to observe. They do not claim that any test was executed, that any configuration was deployed, or that any approval, declaration, or refund took place. Where the source text is silent, the gap remains open.
