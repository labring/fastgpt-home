# Amazon FBA preparation: retrieval for operating reviews

## What the documents look like

FBA preparation moves inventory into platform warehouses, so the operating risk sits with inbound progress and inventory age. The working materials for this category are FBA inbound plans, carton labels, inventory reports and compensation claims. They come from Seller Central, freight forwarder tracking and ERP purchase orders. An operating review and exception review has to check the subject, object, status and validity scope recorded in those materials. The materials update daily and weekly, while the retrieval step reads only what has already been stored in a knowledge base. Update cadence does not change how recall works.

Retrieval cannot be treated as a substitute for authorization. A recalled sentence about an inbound plan describes what the document says. It does not confirm that a warehouse receipt is complete, that a claim is eligible, or that any downstream action has been approved. The knowledge base search node can associate one or more knowledge bases that use the same vector model. Cross-model association is not available, and the correct handling is to check the vector model identifier and exclude the libraries that do not match.

## Constraints at the retrieval step

The smallest search unit is the library. Collections serve classification and do not affect search results. Semantic search, full-text search and hybrid search suit different question types. Hybrid search merges multiple recall paths through RRF, and reranking is a second ordering pass. The minimum relevance value takes effect only under semantic search or when result reranking is used. The reference limit is measured in tokens, not in a guessed number of items. A knowledge base search node outputs references as an array, and the length can be zero, which means the downstream chain still runs when nothing is retrieved.

A hypothetical paper exercise sample: the source material reads, "Inbound plan A-03 for March 2025: the responsible party is a Shenzhen preparation team, the object is FBA warehouse FTW1, the planned inbound quantity is 120 cartons, the carton labels have been produced, the inbound status is in transit, and the authorization scope is limited to verification of this batch's inbound." The draft sentence to be judged reads, "This batch has completed inbound and holds claim eligibility." The source states only that the batch is in transit. It does not state completed inbound and does not state claim eligibility. The draft sentence is unsupported.

## Configuration and implementation checks

| Configuration item | Value or check on this page | Basis and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Associate only FBA preparation libraries that share one vector model | Compare vector model identifiers across libraries and exclude those that differ |
| Search mode | Check the sample first under hybrid search | Compare against semantic search and full-text search results for the same question |
| Reference limit | Hypothetical trial starting point set to hold one complete inbound plan body | Compare completeness against shorter and longer materials, then adjust |
| Minimum relevance | Label relevant and irrelevant samples before adjusting | Takes effect only under semantic search or result reranking |
| Question optimization | Not enabled for this sample because the subject is already explicit | Compare the original question with the optimized question and check whether the subject was altered |
| Empty-reference handling | Verify the downstream design with a paper input of an empty array | Observe whether the chain runs when reference length is zero |

The reference limit is a token-based cap. The starting value above is a hypothetical trial value chosen so that one full inbound plan body fits inside the returned references; it is compared against the actual completeness of shorter and longer materials. It is not an official default. The minimum relevance value is a filter threshold, not a final ordering rule. After question optimization, hybrid search, image retrieval or reranking are enabled, results may be merged from multiple recall paths and will not necessarily follow a single vector similarity order.

## Three common errors

1. Treating a retrieval hit as authorization. In the sample the inbound status is in transit. Retrieving that sentence does not show that inbound is complete, and it does not show that claim eligibility exists. The correct comparison is between the status word in the source and the status word in the draft.

2. Forcing association across libraries with different vector models. Libraries that use different vector models cannot be associated together. The correct action is to check the vector model identifier, exclude the libraries that do not match, and record the exclusion. Running a cross-model search to compare missed recall is not the check.

3. Treating a pending review as an existing operating permission. The sample does not record a signature or an effective clause. A pending verification status cannot support a negative conclusion, and it cannot be filled in with an invented authorization clause. The evidence gap stays open.

## How to verify the setup

1. Input the sample source material and the draft sentence, then compare "in transit" against "completed inbound and holds claim eligibility." Observe whether the system returns only the source reference without producing an eligibility conclusion. The condition is met when the returned reference matches the source and no status absent from the source appears.

2. Input two libraries that carry the same vector model identifier and compare whether they can be associated. Then input a library with a different vector model identifier and observe whether it is excluded. The condition is met when only same-model libraries enter the association and the mismatched library is recorded as excluded.

3. Use a paper input of an empty reference array to check the downstream design, and observe whether the empty-result chain still runs. The condition is met when the chain executes with a reference length of zero, without asserting that a fictional rule search must return empty.
