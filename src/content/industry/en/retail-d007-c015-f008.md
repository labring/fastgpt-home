# Letter-of-credit documents: workflow routing for operating reviews

## What the documents look like

Letter-of-credit document examination and presentation serves bank payment conditions. The controlling question is whether the documents agree with each other and with the credit terms, not whether a tax position matches a filing. Each transaction is organized around the issuing bank's advice, UCP600 clauses, the freight forwarder's bill of lading, and the bank's presentation record. The working documents are the letter of credit, the commercial invoice, the bill of lading, the insurance policy, and the draft.

Operating reports and exception reviews for this category collect the examination conclusion, the discrepancy handling, and the presentation date per transaction. The most time-consuming steps are reviewing credit terms, producing conforming documents, and handling discrepancies, so the review evidence concentrates on clause-review records, document versions, and presentation receipts. The category differs from export tax rebate filing because the comparison object is document terms against bank payment conditions. Tax matching sits outside this page.

## Constraints at the workflow routing step

Workflow routing here divides state advancement from human judgment. The form input node enters an interaction state when triggered, collects required information, and passes that information to later nodes after submission. The user selection node judges the user's choice and executes the corresponding "yes" branch. The interaction state record is the node's own behavior; no separate global state-recording switch is documented. Collected information must be passed explicitly to later retrieval, judgment, or interface nodes, and each output is compared item by item against the input.

Order writing, document backfill, and external status synchronization require a separate business interface or a later process. Retrieval and forms do not constitute authorized execution. Operating reports and exception reviews require the same subject, the same period, and the same field. A fact that is not stated, or that exists only as a related-stage record, is recorded as pending verification.

Hypothetical paper exercise sample: under one letter of credit, the issuing bank's advice states "latest shipment date 31 March 2025, presentation period 21 days after shipment date"; the freight forwarder's bill of lading states "date of shipment 28 March 2025"; the bank presentation record states "date of presentation 15 April 2025." The proposed finding sentence is "this presentation was completed within the credit's presentation period." Under the quoted text, 21 days after the shipment date is 18 April 2025, and the presentation date of 15 April falls inside that range, so the proposed sentence agrees with the source text. If the proposed sentence is changed to "this presentation has been paid by the issuing bank," the source text does not state a payment fact, so that sentence is unsupported.

## Configuration and implementation checks

| Configuration item | Setting or check | Relation to this page's sample |
| --- | --- | --- |
| Form input node | Collect required information such as examination conclusion, discrepancies, and presentation date; pass to later nodes after submission | The presentation date in the sample is collected here |
| User selection node | Execute the "yes" branch according to the user's choice; verify each branch connection | Whether the sample enters exception review is decided by this branch |
| Interaction state check | Check that the node enters the interaction state and records state | Before submission in the sample, the conversation is in the interaction state |
| Output handoff check | Compare collected information item by item against the input of later retrieval or judgment nodes | The presentation date in the sample must reach the judgment node |
| External operation division | Order writing, document backfill, and external status synchronization connect to a separate interface or later process | Payment status in the sample is not written by this workflow |
| Hypothetical trial starting field | Use "presentation date" as this exercise's starting field, because it directly decides whether the period is exceeded, compared against shipment date plus 21 days | This is a page-level hypothesis, not an official default value |

## Three common errors

1. Treating the interaction state record as a global state switch. The form input node enters the interaction state and records state when triggered; this is node behavior and does not indicate that a global state-recording switch exists.
2. Treating retrieval or form submission as authorized execution. Retrieval and forms collect information; order writing, document backfill, and external status synchronization require a separate business interface or later process.
3. Treating an unstated fact as a negative finding. The sample source text does not state a payment fact, so the proposed sentence "has been paid by the issuing bank" is unsupported and cannot be recorded as either paid or unpaid.

## How to verify the setup

1. Input the sample source text and the proposed finding sentence "this presentation was completed within the credit's presentation period." Compare 21 days after the shipment date against the presentation date. The condition is met when the presentation date falls inside that range.
2. Input the sample source text and the proposed finding sentence "this presentation has been paid by the issuing bank." Compare whether the source text states a payment fact. When the source text does not state it, record the result as unsupported.
3. Input the sample source text and check whether the presentation date collected by the form input node reaches the later judgment node. The condition is met when output and input agree; when they do not agree, record the gap.
