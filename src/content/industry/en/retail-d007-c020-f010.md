# Certificates of origin: citation tracing for operating reviews

## What the documents look like

Certificate-of-origin work for this category runs on four document families: the certificate application, the commercial invoice, the packing list, and production cost records. The public brief places the main data sources at China International Trade Single Window, CCPIT systems, enterprise production records, and customer customs-clearance requirements. The category serves import-country tariff treatment and customs clearance and is not necessarily bound by a letter of credit, so source tracing in operating reports and exception reviews concentrates on consistency among origin-rule determination, certificate entries, and the material the customer uses for clearance. The brief gives the update frequency as per certificate, with batch situations counted separately.

For citation tracing, the practical consequence is that each conclusion in a report or review must point back to a specific material and its effective version. A certificate application, an invoice, a packing list, and cost records are separate identities. The stage of each one matters: a draft application, a submitted application, and an approved certificate are different facts, and a retrieval result that returns one of them does not convert it into another.

## Constraints at the citation tracing step

The knowledge-base search node can associate one or more knowledge bases that share the same vector model, and it outputs citations as an array whose length may be zero. A zero-length array still lets the output path run through. The node is a core module, can be added repeatedly, has external input, and has static configuration. Retrieval can combine question optimization, semantic retrieval, full-text retrieval, hybrid retrieval, RRF merging, ReRank second-pass ordering, similarity filtering, and citation-limit trimming. These paths execute according to settings and input conditions; their presence in the overall flow does not mean every request runs all of them. Image retrieval requires image input and model capability. ReRank requires a model and is enabled by settings.

The minimum relevance value is a filter threshold that takes effect only under semantic retrieval or result reordering. It does not perform permission or entity isolation. Retrieval itself is not authorization. Forms collect values; business verification, approval, database writes, and external synchronization each need their own downstream implementation. RRF is a fusion step for mixed results, not a switch. Thinking budget is a reasoning budget and is not a citation token limit.

Hypothetical drill sample, labelled as such: on 10 March 2025 an export document clerk prepares an exception-review report for one certificate-of-origin application. The material text available for comparison reads: "Commercial invoice INV-0310 states the buyer is Company A, the goods are 200 valves, and the invoice date is 5 March 2025." "Production cost records show this batch of valves was assembled locally and the main components were purchased from outside the country." "The certificate-of-origin application draft states the country of origin as China and the application date as 10 March 2025." The draft sentence to be judged is: "The goods originate in China, and the customer can use this certificate to obtain import-country tariff preference." The request is at draft stage, not submitted, not approved.

## Three common errors

1. Treating a similarity score as a permission or entity filter. Minimum relevance only filters low-relevance results; it does not distinguish business ownership or authorization status, and citation content still needs manual tracing back to the material text.
2. Treating retrieval output as business authorization. Retrieving a draft application does not mean the application has been submitted, approved, or taken effect. Draft, pending review, signed, and contract-effective are separate facts.
3. Associating knowledge bases that use different vector models. The documentation requires the same vector model for joint association; check model identifiers first and exclude non-matching ones, record what is actually observed, and do not infer runtime results of joint association.

## How to verify the setup

1. Input the three material sentences and the draft sentence from the hypothetical sample above, and compare "the goods originate in China" in the draft sentence with "the main components were purchased from outside the country" in the cost records. The material needed for the origin-rule determination is not fully stated, so this conclusion is unsupported and the evidence gap must be recorded; do not judge it as a contradiction or a negation.
2. Input the draft sentence "the customer can use this certificate to obtain import-country tariff preference" and compare it with the application draft status. The draft is not submitted and not approved, so the tariff-preference conclusion in this sentence is unsupported and pending verification; do not treat it as approved or executed.
3. Use a paper input citation array of [] to check the downstream answer step's handling design, observe whether the empty array still runs through the output path, and record that path behavior; do not claim that a fictional rule retrieval necessarily returns an empty array.
