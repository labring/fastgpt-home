# Brand repair services: HTTP integrations for operating reviews

## What the documents look like

Brand after-sales repair work is organized around warranty responsibility and physical repair outlets. It does not stop at platform refunds. The materials that matter for reporting and exception review are the warranty card, the repair work order, the inspection report, and the exchange approval. These four documents carry different states: a work order may sit at pending inspection, pending approval, or closed; an exchange approval may or may not have completed its authorization step.

Data sources for this category include the after-sales system, store orders, repair outlet feedback, and the national three-guarantees catalogue. Update frequency is per order and daily. The HTTP integration step sends or retrieves state between FastGPT and an external system. The interface itself does not judge warranty scope and does not substitute for approval. It sends a request according to the external interface contract and parses the response. Reporting and review therefore must separate fields that come from an interface response from fields that still require manual comparison against the source material.

## Constraints at the HTTP integrations step

The HTTP module sends an HTTP request to the corresponding address. Params carry path request parameters and are used more in GET requests. Body carries the request body and is used more in POST and PUT requests. Headers carry request headers for special information. All three data types can reference variables through `{{}}`, and the URL can also reference variables. Variables come from global variables, system variables, and preceding node outputs.

Among system variables, `chatId` and `responseChatItemId` do not exist in test mode. An empty value during debugging is a documented test environment difference and does not by itself indicate a business fault. Authentication credentials are injected through security configuration and are not written into public samples. The `score` returned by an interface is a similarity value and does not perform permission or entity isolation. A retrieval result is not an authorization result.

Hypothetical paper exercise sample: a brand after-sales center receives a repair work order on 10 March 2025. The source material reads: "Work order WX-0310-07, product model A2, fault described as screen flicker, warranty card valid until 30 June 2025, inspection report conclusion: human-caused damage." The draft sentence to be judged is: "This work order falls within warranty scope and a free exchange can be arranged directly." The subject required for judgment is work order WX-0310-07, the object is product model A2, the state is the inspection report conclusion "human-caused damage," and the validity range is the warranty card valid until 30 June 2025. The draft sentence and the inspection report conclusion occupy the same field with mutually exclusive values, so the draft is unsupported.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | Reason and comparison method |
| --- | --- | --- |
| Request address | The address given by the external interface document | Compare character by character against the document address; the address can reference variables |
| Request method | Selected according to the external interface contract | Compare against the method declared in the contract; do not assign by experience |
| Headers authentication | Credentials injected through security configuration | Compare against the authentication method required by the document; do not write into public samples |
| Body structure | JSON checked against the external interface contract | Compare field by field against the contract; effective only under the corresponding request type |
| Variable reference | References a global variable or a preceding node output | Compare against the node's actual output; check each passed value |
| Return value extraction | Key configured with JSON path syntax | Compare against the interface response example; when output type is string, the value is converted to a json string |

These starting points are used for this hypothetical exercise and are not official default values. Numeric values and fields follow the external interface document. Where the document does not state a value, the value remains unknown.

## Three common errors

1. Treating retrieval similarity as a permission filter. The input is the `score` field returned by the interface; the comparison object is the authorization scope statement; the observable result is that a high score does not mean the record is visible to the current caller. Similarity only indicates textual relatedness.
2. Treating an empty `chatId` in test mode as a business fault. The input is the empty `chatId` returned in test mode; the comparison object is the document's statement about test mode; the observable result is that this empty value is a documented difference and does not constitute evidence of a business exception.
3. Writing a pending exchange work order as approved. The input is the work order status field; the comparison object is the approval completion record; the observable result is that a status of pending approval does not support a conclusion of approved.

## How to verify the setup

1. For hypothetical sample WX-0310-07, input the draft sentence "This work order falls within warranty scope and a free exchange can be arranged directly." Compare it against the inspection report conclusion "human-caused damage" and the warranty card validity range. The observable result is that the draft sentence and the inspection report conclusion occupy the same field with mutually exclusive values, so the draft is judged unsupported.
2. For return value extraction, input a response containing `data.user.name`. Compare against the configured key. The observable result is that the extracted value matches the corresponding field in the response. If the response is an empty array, the extraction result is empty, and downstream design must handle the empty value; do not claim that a fictional rule retrieval necessarily returns empty.
3. For authentication configuration, input a request carrying the Authorization header. Compare against the authentication method required by the document. The observable result is that the request is accepted or returns an authentication error. When no actual response has been observed, that result remains unknown. The same-vector-model requirement for a retrieval library applies only to that library and does not extend to other external systems.
