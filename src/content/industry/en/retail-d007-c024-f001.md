# Brand concession operations: HTTP integrations for operating reviews

## What the documents look like

Brand concession counters in shopping malls settle sales through the mall's unified cashiering, and the brand reconciles sales amounts and concession fees against a joint-operation concession contract and a monthly reconciliation statement. The working materials are the joint-operation concession contract, mall activity letters, sales receipts and the monthly reconciliation statement. Data originates from the mall POS, the brand ERP, mall membership campaigns and the finance system. These materials enter the HTTP integration step of operating reporting and exception review, where subject, object, period and authorization status must be confirmed item by item.

A concession contract states a fee percentage and a settlement base. An activity letter states a time window and whether sales inside that window participate in the fee calculation. A monthly reconciliation statement states a period and a total. When these three sources are combined into one report sentence, the sentence must stay within the period and scope each source actually covers.

## Constraints at the HTTP integrations step

The HTTP module sends a request to a configured address. Params, Headers and Body can each reference variables through `{{}}`, and variables come from global variables, system variables and output of preceding nodes. The URL can also reference variables. `chatId` and `responseChatItemId` do not exist in test mode, so an empty value read in a test environment is a debugging condition and not a business fault.

The chat endpoint authenticates with an APIKey. The appId priority order is `body.appId`, then `<apiKey>-<appId>`, then the appId associated with the apikey. The `model` and `temperature` fields passed in the request have no effect, because the orchestration decides them. When `detail=true`, intermediate values are returned, and tokens in `usage` must be calculated manually from `responseData`. The `similarity` value in a retrieval result is a relevance score and does not perform permission or entity isolation. Forms collect values; business verification, approval, database writes and external synchronization require a separate downstream implementation.

Hypothetical paper exercise, not executed. Source text for comparison: "Joint-operation concession contract HT-2024-031 provides that concession counter A applies an 18% concession rate for July 2024, and the monthly reconciliation statement uses the mall POS aggregated sales amount as the settlement base. Mall activity letter HD-2024-017 states that counter A participates in a spend-and-save campaign from 12 July to 14 July 2024, and sales during the campaign period do not participate in the concession calculation." Draft sentence to be judged: "All sales of counter A for the full month of July 2024 are subject to the 18% concession rate." The draft sentence conflicts with the time window stated in the activity letter, so it is not supported.

## Configuration and implementation checks

| Configuration item | Hypothetical trial starting point | Comparison method |
| --- | --- | --- |
| Request address and method | Address and method taken from the external interface document, with the address referencing an already provided variable | Compare the address and method against the external interface document |
| Params and Headers | Authentication credential injected through secure configuration | Check that the credential does not appear in any public example |
| Body | Body populated only under the corresponding request type | Compare the JSON structure against the external interface contract |
| Variable reference | Reference global variables, system variables or output of preceding nodes | Check each actually passed value item by item |
| Return value extraction | Key configured by JSON path | Compare the extracted result against the original response |
| Debug identity fields | `chatId` and `responseChatItemId` do not exist in test mode | Distinguish a debug empty value from a business fault |

The trial starting point for the address and method is chosen because the external interface document is the only supplied source that names an address and a method, and the comparison is a direct match against that document. No default value, limit or unit is asserted for any row.

## Three common errors

1. Treating the time window stated in the activity letter as applying to the whole month, so the concession accrual scope no longer matches the contract and the activity letter.
2. Treating the `similarity` relevance score as a permission or entity filter, and assuming that low-scoring records have been excluded.
3. Treating a value collected by a form as a completed business verification or approval, and treating it as executable without confirming the downstream implementation.

## How to verify the setup

1. Input contract HT-2024-031, activity letter HD-2024-017 and the draft sentence from the hypothetical sample. Compare the draft sentence against the time window stated in the activity letter. When the two differ on the period in which the concession rate applies, the draft sentence is not supported.
2. Input a retrieval response containing a `similarity` field. Compare that field against permission or entity identifiers. When the response contains no permission field, record the permission status as not supported, and do not use the relevance score as a filtering basis.
3. Input a form collection result. Compare that result against business verification and approval records. When only a form value exists and no verification or approval record exists, record the request as pending verification, and do not treat it as authorized for execution.

These three checks state what to input, what to compare and what observable condition must hold. They do not assert that any test, deployment, approval or synchronization has occurred, and they leave missing evidence as missing.
