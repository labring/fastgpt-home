# Brand concession operations: workflow routing for operating reviews

## What the documents look like

Brand concession operations in shopping malls settle sales through two parallel records. The mall POS system captures actual transactions and the concession fee deduction, while the brand ERP holds the figures the counter reports. Daily and monthly updates run alongside each other, so operating reports and exception reviews have to work with sales receipts, the joint-operation concession contract, mall activity letters, and the monthly settlement statement at the same time.

Three tasks consume most of the working hours: reconciling mall sales, taking part in mall activities, and processing concession fee charges. Workflow routing has to fix how these materials are collected, judged, and handed over between stages. The category differs from a directly operated street store because the counter accepts unified mall cashiering and deduction-based settlement. Errors surface later as monthly settlement differences, reduced activity resources, or counter withdrawal.

## Constraints at the workflow routing step

The Form Input node is a user-interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and the workflow continues after the user finishes the interaction. Once the user fills in the required information and submits, the node collects the submitted form values and passes them to later nodes.

The User Selection node is also a user-interaction node. It triggers the same interaction state and records the workflow state. When the user makes a choice, the node judges that choice and executes the "yes" branch.

Both nodes only collect information and route branches. Order writing, document backfill, and external status synchronization require a separate business interface or a later flow. Retrieval is not authorization. A relevance score is not a category, entity, or permission filter, and similarity settings do not exclude unrelated businesses or unauthorized records.

Hypothetical paper exercise sample. The source material reads: "For March 2025, a brand counter's mall POS sales total RMB 180,000. The joint-operation concession contract sets the concession rate at 20%. The mall activity letter states that activity resources for that month are subject to the mall's confirmation letter. The monthly settlement statement shows pending confirmation by mall operations." A draft sentence to be judged reads: "The March concession fee has been confirmed by the mall and can be carried forward directly from the brand ERP." The request concerns the mall operations confirmation status, and no confirmation result is stated in the source.

## Configuration and implementation checks

| Configuration item | Type | Description |
| --- | --- | --- |
| Form Input node | Interaction node | Enters interaction state on trigger, collects required information, passes values to later nodes after submission |
| User Selection node | Interaction node | Executes the "yes" branch after the user makes a choice; verify each branch connection |
| Interaction state check | Manual check | State recording is behavior of the interaction node; no separate global state-recording switch is set or claimed |
| Output handover check | Manual check | Pass collected information explicitly to later retrieval, judgment, or interface nodes; compare output against input item by item |
| External operation split | Implementation check | Order writing, document backfill, and external status synchronization require a separate business interface |

## Three common errors

1. Treating form submission as mall operations confirmation. Submission only collects information. The confirmation status requires a separate business interface or manual check.
2. Treating the "yes" branch of User Selection as authorized execution. The branch only decides the flow direction. Order writing and external synchronization require a separate implementation.
3. Treating retrieval results as a permission filter. Similarity does not exclude unrelated businesses or unauthorized records, and retrieval does not carry authorization duties.

## How to verify the setup

1. Enter the hypothetical source text and the draft sentence above, then compare whether "confirmed by the mall" in the draft and "pending confirmation by mall operations" in the source share the same subject, the same period, and the same field. When the source states no confirmation result, judge the draft as pending verification.
2. Check whether the Form Input node's output after submission is explicitly passed to a later retrieval or judgment node, and compare input against output item by item. When the value is not passed or a field is missing, record the gap.
3. Check the User Selection node's "yes" branch connection and the external operation split, confirming whether order writing, document backfill, and external synchronization connect to a separate business interface. The node branch alone does not constitute execution.

A relevance score is not a category, entity, or permission filter. A similarity setting does not exclude unrelated businesses or unauthorized records. Retrieval is not authorization. Forms collect values; business verification, approval, database writes, and external synchronization need their stated downstream implementation. The interaction state, the recorded workflow state, and the collection of submitted values are documented behaviors of the interaction nodes. Do not assume scheduled triggers or hidden controls.
