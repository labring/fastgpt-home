# Brand-owned store operations: retrieval for operating reviews

## What the documents look like

Brand-owned stores are staffed and accounted for directly by the brand, so operating reviews draw on internal systems rather than franchise agreements. The working documents are daily sales reports, shift schedules, display photos, and inventory transfer orders, sourced from POS, member CRM, ERP inventory, and store inspections. An operating review has to reconcile sales targets, inventory status, and store performance on one consistent basis. When material is missing or the basis differs, target tracking and transfer decisions are affected directly. Retrieval in this step lets store managers and regional managers locate the relevant document fragments and cite the original wording in the review.

## Constraints at the retrieval step

Retrieved results are reference content only. They do not constitute authorization, approval, or business execution. The knowledge base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases using different vector models cannot be associated together; check the vector model identifier first, exclude those that do not match, and record what was observed. Search modes are semantic search, full-text search, and hybrid search. Hybrid search merges multiple result paths through RRF. RRF is a fusion process and is not written as an on/off switch. The minimum relevance score takes effect only in semantic search or when result reranking is used. It is a filter threshold and does not perform permission or entity isolation. The reference limit is measured in tokens. Question optimization performs coreference resolution and question expansion and makes an additional model call. The output reference content is an array whose length can be 0, and the downstream path still runs with an empty result. Image retrieval requires corresponding image input and model capability. Reranking requires a model and is enabled according to settings. The optional paths shown in the overall flow diagram do not mean every request executes all of them.

Hypothetical paper exercise sample: a regional manager for a brand-owned store keeps the following paper material. "From March 1 to March 31, 2025, the daily sales report for Store A shows monthly sales of RMB 1.2 million. The shift schedule for the same period records 6 sales staff on duty each day in March. Inventory transfer order number DB-2025-0315 states that on March 15, Store B transferred 30 units of size M goods to Store A, with status shipped." The draft sentence to be assessed is: "Store A met its March sales target, and the inventory transfer has been received into stock." This draft sentence involves two conclusions, sales target attainment and transfer receipt. The material does not state the sales target value, and it does not state the receipt status or signed acceptance record of the transfer order.

## Configuration and implementation checks

The configuration below covers only settings documented in the official material or implementation checks relevant to this feature and this primary task, tied to the sample above. Values are hypothetical starting points for this exercise, used for comparison, and are not official defaults.

| Configuration item | Hypothetical starting point for this exercise | Reason for the choice and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Associate only the knowledge base holding the daily sales report and the inventory transfer order under the same vector model | Check the vector model identifier first, exclude knowledge bases on a different model, then run retrieval |
| Search mode | Use full-text search for "transfer order number DB-2025-0315" and hybrid search for "cause of the March sales anomaly" | Compare retrieved content for an exact number query against a natural-language question |
| Reference limit | Start at a token amount covering one daily report plus one transfer order | Test with material of different lengths and check whether the reference content is complete, then adjust |

| Question optimization | Enable for the follow-up question "what about that transfer" | Compare the original question with the optimized question and check whether the subject was changed incorrectly |
| Result reranking | Enable when candidates are numerous and the question is complete | Filter using the rerank score from 0 to 1 and compare relevance against results without reranking |

## Three common errors

1. Treating a retrieval hit as business authorization. In the sample, the transfer order status is "shipped." Retrieving that order does not equal completed receipt, and it does not equal sales target attainment. The error is substituting reference content for receipt acceptance and target comparison. Check: input the transfer order text, compare the values of the "shipped" and "received into stock" fields, and only an inbound or signed acceptance record satisfies the receipt conclusion.

2. Associating knowledge bases across vector models. The error is associating the daily sales report knowledge base together with a knowledge base using a different vector model. Check: input the vector model identifiers of both knowledge bases, compare whether they match, exclude those that do not match and record this, and do not run cross-model retrieval to compare missed recalls.

3. Using the minimum relevance score as a permission filter. The error is assuming that raising the relevance score excludes unrelated stores or unauthorized records. Check: input the same question with material from different stores, compare the reference content returned before and after filtering. Relevance changes ordering and filtering only; it does not change the accessible range.

## How to verify the setup

1. For the sample draft sentence "Store A met its March sales target, and the inventory transfer has been received into stock," input the daily sales report text and the transfer order text, and compare whether the material states the sales target value and the receipt acceptance status. When neither is stated, the draft sentence is unsupported, record the evidence gap, and do not conclude target attainment or completed receipt.

2. For transfer order number DB-2025-0315, input the full-text search query and compare whether the returned reference contains the original number and the status field. If the returned content contains only the number without status, the receipt conclusion remains to be verified. If the returned array is empty, check how the downstream design handles an empty result, and do not claim that a fabricated rule makes retrieval necessarily return empty.

3. For the follow-up question "what about that transfer," input the original question and the completed question after question optimization is enabled, and compare whether the completed subject is the transfer order corresponding to DB-2025-0315. When the completed subject is changed to another document, record the deviation introduced by question optimization and do not treat it as a retrieval conclusion.
