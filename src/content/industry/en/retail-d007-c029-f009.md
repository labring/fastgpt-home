# After-sales repairs and reships: operating reviews with tool calls

## What the documents look like

For operating reviews in After-sales repairs and reships, this page examines FastGPT tool calls. A repair-and-replacement report separates requests, inspection and handoff. Parts dispatch establishes neither repaired goods nor customer receipt. The examples are hypothetical.

## Constraints at the tool calls step

A proposed repair application describes an anomaly, inspection awaits retesting, a replacement order was created and parts dispatch has a separate record. Organize passages by item correspondence without filling missing identity from a model name. Parts dispatch establishes neither installation, repair nor delivery to the customer. Preserve pending retest and distinguish applicant descriptions from inspected findings. Supply no repair effects or timing promises.

## Configuration and implementation checks

| Repair-replacement report tool | Proposed stage | Actual evidence |
| --- | --- | --- |
| Repair application | Customer anomaly description | Not inspection diagnosis |
| Inspection state | Retest pending | Retain unresolved status |
| Parts dispatch | Parts released only | Not complete repair |
| Replacement plan | Creation, not delivery | Actual logistics |
| Call input | Source-backed item relationship | Model name cannot fill identity |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Tool description` | Describe purpose, inputs and non-applicable situations. |
| `Tool parameters` | Inspect module and plugin parameters separately. |
| `Required parameters` | The model may not invoke a tool without suitable required inputs. |
| `Tool connections` | Available tools must connect to the calling module. |
| `Tool-call termination` | Termination ends the call without a later AI summary. |

## Three common errors

Application promoted to diagnosis needs actual inspection. Parts dispatch promoted to full repair requires operations and retest evidence. A created replacement promoted to receipt needs actual handoff and receiving records. These inspect fact status, work stage and logistics independently of successful invocation.

## How to verify the setup

Retain actual input and raw response. Added retest conclusions change only covered functions while shipment gaps remain visible. Parts collection alone cannot become complete repair. Missing suitable required input may prevent invocation, so describe purpose and input limits. Repair, dispatch and customer notices need separate authority and receipts. Tool termination supplies neither a subsequent summary nor proof of business completion.
