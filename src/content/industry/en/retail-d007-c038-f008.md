# Fresh-food concession counters: workflow routing for operating reviews

## What the documents look like

A fresh-food concession counter in a hypermarket is commonly operated by a supplier who stations staff on site and shares revenue by sales. The material set for an operating review therefore spans documents that originate with different parties: the concession contract, the daily sales report, the loss report, and the food inbound inspection record. These materials draw on the POS system, supplier delivery notes, the food-safety ledger, and store stock counts. The brief gives a daily or per-batch update frequency for this category.

For operating reporting and anomaly review, the practical consequence is that daily sales, loss allocation, and inbound inspection evidence have to be compared under one operating entity, one period, and one field definition. When the materials sit in separate sources, that comparison depends on manual handover and on workflow nodes passing values forward in sequence.

## Constraints at the workflow routing step

The Form Input node is a user-interaction node. When it is triggered, the conversation enters an interaction state and the workflow state is recorded. After the user completes the required fields and submits, the node collects the submitted form values and passes them to later nodes. The User Selection node is also a user-interaction node. When it is triggered, the conversation likewise enters an interaction state, and when the user makes a choice the node evaluates that choice and executes the "yes" branch.

These two nodes collect values and route branches. Order writes, document backfill, and external status synchronization require a separate business interface or a later process. Retrieval or a submitted form does not constitute authorization to execute, and a pending-review status does not demonstrate that an operation permission is absent.

Hypothetical paper exercise. A hypermarket fresh-food department holds a concession contract with one concession supplier. The contract states a settlement period from 1 March 2025 to 31 March 2025, and revenue sharing is confirmed against the daily sales report. The daily sales report for 15 March records weighed sales of 4,820 yuan. The loss report for the same day records a loss amount of 310 yuan. The food inbound inspection record states that the certificates for that day's arriving batch were inspected. One draft sentence is under review: "The 15 March loss amount has been deducted from that day's revenue share." The contract contains no loss-allocation clause, the loss report does not mark an allocation target, and the deduction fact asserted in the draft sentence is not supported by the available materials.

## Configuration and implementation checks

| Configuration item | Relevant setting or check on this page | Relation to the exercise |
| --- | --- | --- |
| Form Input node | Enters interaction state when triggered; collects required fields; passes values to later nodes after submission | Collects the field values needed to compare the 15 March report |
| User Selection node | Executes the "yes" branch after the user makes a choice | Confirms whether loss allocation should enter a manual review branch |
| Interaction state check | State recording is behaviour of the interaction nodes; no separate global state-recording switch is documented | Verifies state recording after the form and selection nodes are triggered |
| Output handover check | Collected values are passed explicitly to later retrieval, decision, or interface nodes | Verifies whether the 15 March field values reach the comparison node intact |
| External action separation | Order writes, document backfill, and external status synchronization require a separate business interface or later process | If a loss deduction is to be persisted, a separate business interface is required; this node does not perform it |

## Three common errors

1. Treating form submission as authorization that a loss deduction has been granted. In the exercise, the loss report marks no allocation target and the contract contains no loss-allocation clause. Collecting a loss amount only shows that a field value was submitted. It does not show that a deduction action was authorized or executed.
2. Treating the "yes" branch of User Selection as a completed business approval. Executing the "yes" branch only shows that the workflow moved to that branch. A completed approval requires a corresponding approval record, and no such record exists in the exercise.
3. Treating retrieval results as a permission filter. Retrieval or semantic recall does not perform permission or entity isolation. In the exercise, checking the 15 March materials must occur within a target retrieval scope the operator has access to, or through explicit manual input. When that is absent, record the gap.

## How to verify the setup

1. Input the weighed sales amount of 4,820 yuan from the 15 March daily sales report, the loss amount of 310 yuan from the loss report, and the inspection status from the food inbound inspection record. Compare whether all three belong to 15 March 2025, the same concession supplier, and the same field definition. If the loss report marks no allocation target, the deduction fact is unsupported and should be recorded as pending verification.
2. Input the draft sentence "The 15 March loss amount has been deducted from that day's revenue share" and compare it against the contract settlement clause and the loss report entry. When the contract contains no loss-allocation clause, the draft sentence is inconsistent with the available materials, should be marked unsupported, and must not be rewritten as already deducted.
3. Input the field values collected by the Form Input node and the branch result of the User Selection node, then compare whether the output reaches the later comparison node intact. If field values are missing or the branch did not execute, record the flow as incomplete and do not infer that a deduction was executed. An empty-result handover can be checked against downstream design using the explicit paper input [], without asserting that a fictional rule retrieval necessarily returns [].

The verification questions above test the named primary task: comparing the 15 March sales, loss, and inspection materials under one entity, one period, and one field definition, and testing whether the draft sentence is supported. They do not test identity certification, report analysis, or any other task. Where the contract, loss report, or approval record does not supply a needed field, that field remains unknown.
