# Marketplace promotions: database operations for operating reviews

## What the documents look like

Promotion enrollment data turns on price, inventory and campaign rhythm. This differs from product-title compliance work, which centers on reviewing promotional wording. The main sources are the Tmall marketing backend, the JD campaign backend, ERP inventory, and historical transaction prices. The daily documents are the campaign enrollment form, the promotional price approval form, the inventory lock form, and the campaign review form. Updates follow a weekly cadence or a per-campaign cadence.

For database and operations work, these traits mean raw material and its operating state must stay paired. An enrollment form in a pending-review state does not demonstrate an absence of operating permission. A promotional price approval form carries a quotation validity window, and that window does not state a supply period. Database connections are checked against the chosen deployment plan, and configuration values are not inferred from variable names. Business source-data storage and the vector retrieval backend have different responsibilities, and each is checked against the actual deployment. Retrieval or a form collects values; business verification, approval, database writes and external synchronization each need their own downstream implementation. Retrieval does not constitute authorization.

The three most time-consuming steps in this category are calculating the lowest net price, locking campaign inventory, and synchronizing prices across platforms. Errors lead to campaign losses, loss of a resource slot, or price complaints.

## Constraints at the database operations step

Operating reports and anomaly reviews depend on the correspondence between source material and operating state. A hypothetical drill sample is set out here for paper comparison only.

Sample source text, sentence one: “Campaign enrollment form number A-0715, subject is a brand sales planning group, object is a single-item promotion from July 15 to July 21, state is submitted and pending review.”

Sample source text, sentence two: “Promotional price approval form number P-0715, quotation validity runs through July 20, no supply period is stated.”

Draft sentence to be assessed: “The single-item promotion has been approved and may be executed at the approval-form price through July 21.”

This draft treats pending review as approval, and it treats the quotation validity window as an execution period. Both moves are unsupported by the source text.

The same discipline applies to configuration. A connection string is checked against the deployment plan rather than guessed from its name. The main business data store and the log store are checked separately, because the log connection reuses the main connection when it is not configured. Index creation and cleanup at startup is a documented behavior tied to a switch, and console log output is a documented behavior used during anomaly review. Vector retrieval backends and business source data have distinct roles, and the corresponding service is checked per deployment.

## Three common errors

1. Treating a pending-review state as approval. Input is the source text “state is submitted and pending review.” The comparison object is the draft sentence “has been approved.” The observable result is that the state field values do not match, and the draft sentence is unsupported.

2. Treating a quotation validity window as a supply or execution period. Input is “quotation validity runs through July 20, no supply period is stated.” The comparison object is the draft sentence “may be executed at the approval-form price through July 21.” The observable result is that the source text does not state that execution period, so the conclusion remains to be verified.

3. Treating retrieval or a submitted form as authorized execution. Input is one retrieval request or one submitted form. The comparison object is the authorization state field. The observable result is that retrieval and forms collect values and do not produce an approval or a database write.

## How to verify the setup

1. Input the source text “Campaign enrollment form number A-0715, state is submitted and pending review.” Compare against the draft sentence “the single-item promotion has been approved.” Observe whether the state field values match. The expected result is that they do not match, and the draft sentence is unsupported.

2. Input the source text “Promotional price approval form number P-0715, quotation validity runs through July 20, no supply period is stated.” Compare against the draft sentence “may be executed at the approval-form price through July 21.” Observe whether the source text states that execution period. The expected result is that it does not state it, and the conclusion remains to be verified.

3. Input one retrieval request and one submitted form. Compare against the authorization state field. Observe whether an approval record or a database write appears. The expected result is that neither appears, because retrieval and forms do not constitute authorized execution.

Where a field is not provided in the source document, that field remains unknown. A pending request is not approval, an offered option is not execution, and an unsigned termination is not a completed termination. Retrieval is not authorization.
