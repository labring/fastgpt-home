# Product listing reviews: tool calls for operating reviews

## What the documents look like

Compliance checking for platform product titles and detail pages works from four document types: the product title table, detail page assets, the advertising prohibited-terms list, and quality inspection reports. The subject matter is advertising truthfulness and qualification display. Package delivery sits outside this step. Title and detail asset changes occur weekly and at each new listing, so reports and retrospective reviews must align materials by the same product, the same field, and the same period before any comparison is meaningful.

Tool calls enter this work as a way to read and compare materials. Writing manual comparison results into a report requires a separate write tool and a permission check; the tool call itself does not perform that write. The tool introduction, parameter descriptions, and whether a parameter is required jointly shape whether the model decides to call the tool. When a material lacks a subject, object, status, or validity scope, the model has no basis for a checkable conclusion.

## Constraints at the tool calls step

The tool introduction states the purpose, the input conditions, and the situations where the tool should not be called. The model uses that introduction to decide whether to invoke the tool. System module parameters are fixed; plugin parameters are configurable. The parameter description and the required flag together influence the call decision. When a required parameter has no suitable value in context, the model may decline to call the tool; an interactive step can supply the missing value, and the actual request should then be checked.

In advanced orchestration, available tools are connected to the tool call module, and tuning with a small number of tools first is the documented recommendation. The tool call termination node ends the current call, stops further tool calls, and stops the AI from summarizing tool results. Custom variables extend tool input, bringing in nodes that are not treated as tool parameters.

Retrieval and similarity scores carry no permission or entity-isolation role. Retrieval results do not constitute authorization. Libraries built on different vector models cannot be associated together; identifiers must be checked first and non-matching items excluded. An empty result can be checked against a clearly stated paper input of `[]` to verify downstream design, without claiming that a fictional rule search always returns `[]`.

Hypothetical paper exercise. Material one (product title table, a store's own product, status pending review): `Product A | draft title: lowest price on the entire internet | effective scope: this store's Product A detail page | period: 2025-06-01 to 2025-06-30`. Material two (advertising prohibited-terms list, version marked as an internal compliance list): `prohibited wording: lowest price on the entire internet, national-level`. Material three (quality inspection report, issuing body a testing institution, object Product A, status issued): `report number example-QA-001 | conclusion: meets the commissioned items | valid until 2025-12-31`. Sentence to assess: `The Product A title uses "lowest price on the entire internet" and cites report number example-QA-001 as a qualification display.` Handover request: `Please confirm whether the Product A title can be published, and whether report number example-QA-001 can be displayed on the detail page.` All of the above is a paper hypothesis. Nothing was submitted, reviewed, or published.

## Configuration and implementation checks

| Configuration object | Documented setting or implementation check | Relation to this page's exercise |
| --- | --- | --- |
| Tool introduction | State purpose, input conditions, and situations where the tool should not be called | Describe that this tool reads the title table and prohibited-terms list and compares them |
| Tool parameters | System module parameters are fixed; plugin parameters are configurable; check parameter description and required flag | Pass product identifier, field name, and period; design an interactive step for a missing required parameter |
| Tool connection | In advanced orchestration, connect available tools to the tool call module; tune with a small number of tools first | Connect only the title-table read and the prohibited-term comparison |
| Tool call termination | Ends the current call, stops further tool calls, and stops AI summarization | Terminate after the comparison, without triggering extra summarization |
| Custom variables | Extend tool input to include nodes not treated as tool parameters | Bring the quality inspection report read node into the call |
| Material version check | Compare against the internal prohibited-terms list given on this page | Check the Product A title word by word against the list entries, and record the version gap separately |

## Three common errors

1. Treating a parameter description as a guarantee of execution. A parameter description only explains what the parameter means; the model decides whether to call based on context, and a missing required parameter may prevent the call. Check: input the product identifier and period from the exercise, compare the actual tool request parameters against the exercise fields, and record a missing required parameter as an incomplete call.
2. Treating a retrieval or similarity score as a permission or entity filter. A score reflects similarity only and does not exclude unauthorized records. Check: input the Product A identifier from the exercise, compare the subject and object in the returned results, and record any non-Product A record as requiring manual exclusion.
3. Treating a pending-review status or a handover request as granted authorization. The exercise title status is pending review and the handover request is pending confirmation; neither constitutes publication permission. Check: input the exercise status field and request text, compare against any signed, approved, or effective record, and record the gap as pending verification when none exists.

## How to verify the setup

- Verification one: for material one and the draft sentence, input the Product A draft title and period, compare the phrase "lowest price on the entire internet" in the draft against the prohibited wording in the list. If the list explicitly contains that wording and the draft uses it, the result is that replacement is required. If the list does not contain it, record the result as unsupported rather than compliant.
- Verification two: for material three and the handover request, input report number example-QA-001, the issuing body, the object, and the validity period, then compare the display request against the object and validity stated in the report. If the object matches and the request date falls within the validity period, the result is that the item may proceed to manual review. If the report states no display authorization, record an evidence gap rather than a displayable result.
- Verification three: for the tool call termination setting, input one completed prohibited-term comparison call, compare the termination node's connection position against subsequent nodes. If the termination node follows the comparison, the call ends and no AI summarization is invoked. If the termination node is not connected, record the subsequent call behavior actually observed, without presupposing an outcome.

All of the above judgments are expectations under a paper hypothesis. No tool call was executed, no review was submitted, and no product was published.
