# Parcel labels and handoffs: citation tracing for operating reviews

## What the documents look like

Parcel handoff takes place when a parcel leaves the warehouse, and the central question is carrier scan responsibility. Operating reports and exception reviews for this category work with electronic waybills, handoff manifests, pickup scan records, and exception item registers. These materials come from the courier system, WMS shipment records, and carrier billing, and they are updated per batch and daily. Citation tracing matters here because a review of a shipping timeout or a lost-parcel dispute needs to point to which material and which sentence a report conclusion relies on, together with the version and validity scope of that material.

Three facts shape this task. First, the handoff node sits between warehouse dispatch and carrier acceptance, so evidence about scan counts and exception items belongs to different systems and may not agree. Second, the same batch can appear in a manifest, a scan record, and an exception register with different field values, and a review must compare the same batch, the same date, and the same field. Third, an operating report conclusion is a statement about cited material, so the review must trace each conclusion back to a specific sentence rather than relying on the fluency of a generated summary.

## Constraints at the citation tracing step

A knowledge base search node can associate one or more knowledge bases that share the same vector model. Citation content is output as an array, and its length can be zero; when nothing is retrieved, the output path still completes. A similarity score expresses how related content is to the question, and it does not perform permission filtering or entity isolation. Retrieval output is passed to an answering step, where each answer sentence is checked against the cited source text. Material timeliness checks distinguish the current version from historical versions, and adopting a citation still requires review against the valid version.

Hypothetical paper exercise sample: a warehouse dispatch team keeps one handoff manifest whose source text reads, "On 10 March 2025, dispatch batch B-0310, 48 parcels handed over, carrier outlet scan records show 46 parcels picked up, the remaining 2 parcels are registered as exception items pending verification." A draft sentence is submitted for judgment: "All 48 parcels in this batch completed pickup." The comparison target is the scan record and the exception item register for the same batch, the same date, and the same field. The draft sentence is inconsistent with the source text stating 46 parcels picked up and 2 exception items pending verification, so it is judged unsupported. Authorization boundary: this manifest is used only for the review of this batch, and it does not indicate that the carrier has confirmed compensation or that the platform has determined shipping completion.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | Reason for the choice and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Associate only the dispatch team handoff manifest base | Confirm the vector model identifier matches before associating bases together, and exclude bases with a different model |
| Search mode | Hybrid search | Batch numbers and exception item fields suit full-text hits, while natural-language review questions suit semantic recall |
| Citation limit | Set to a token amount that covers the full text of one handoff manifest | Compare against the length of a single manifest to avoid truncating key fields |
| Minimum relevance | Set as the starting point for this exercise to observe filtering behavior | Compare against the number of recalled items without filtering, without claiming an official default value |
| Question optimization | Off initially | Batch number and date are already explicit, so observe hits without optimization |
| Result reranking | Not enabled initially | With few candidates, observe the original ordering first; enabling requires a rerank model |

## Three common errors

1. Treating a similarity score as permission filtering. Input: the same question retrieves handoff manifests from other warehouses. Comparison: the score level has no relation to access permission. Observable result: a high-scoring record may still belong to a warehouse without viewing rights, and the permission boundary must be checked separately.

2. Treating an empty citation array as a workflow error. Input: the paper input [] passed to the downstream answering step. Comparison: a node output of length zero and an interrupted path are two different states. Observable result: the downstream step still receives an empty array, and a message for handling empty results needs to be designed.

3. Mixing versions during a material timeliness check. Input: the current manifest and a historical manifest are cited together. Comparison: the batch and date fields of the two materials. Observable result: the answer cites historical data without marking the version, which is recorded as pending verification.

## How to verify the setup

1. Input the hypothetical sample source text "On 10 March 2025, dispatch batch B-0310, 48 parcels handed over, carrier outlet scan records show 46 parcels picked up, the remaining 2 parcels are registered as exception items pending verification." Compare the draft sentence "All 48 parcels in this batch completed pickup." Observable result: the answer cites 46 parcels picked up and 2 exception items pending verification from the source text, and the draft sentence is judged unsupported.

2. Input the same batch number B-0310, and compare whether the retrieval results include both the handoff manifest and the exception item register. Observable result: both material types are recalled, and the cited content can be traced to specific fields; if only one type is hit, record it as a gap.

3. Input the empty array [], and compare whether the downstream answering step handles it normally. Observable result: the downstream step outputs an empty-result notice and the path is not interrupted; do not claim that a fabricated rule retrieval will necessarily return [].
