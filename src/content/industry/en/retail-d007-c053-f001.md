# Channel receivables: HTTP integrations for operating reviews

## What the documents look like

Channel receivables collection happens after credit sales, and its center is credit exposure and cash recovery. The working materials are the receivables aging table, dunning letters, credit agreements, and shipment freeze notices. Operating reviews and exception reviews align aging, repayment, credit usage, and freeze status by week or by month.

This page examines one step only: how the HTTP request is constructed, how variables are referenced, and how the response value is extracted. The HTTP module sends a request to a given address. Params carry path parameters, Body carries the request body, and Headers carry request headers. All three can reference variables through `{{}}`. Variables come from global variables, system variables, and prior node outputs. System variables include appId, chatId, responseChatItemId, variables, cTime, and histories; histories takes at most 10 records by default and its length cannot be changed.

Return values are not the interface response itself. They describe how to parse that response, using JSON path or JavaScript object access rules. When the output type is set to string, the value at the corresponding key is converted into a JSON string. The chat interface uses APIKey authentication, and passing body.appId in the request body is recommended. It also supports `Authorization: Bearer <apiKey>-<appId>`. The appId priority order is body.appId, then `<apiKey>-<appId>`, then the appId associated with the apikey. Fields such as model and temperature are decided by the orchestration and do not change with API parameters. Actual consumed Token values are not returned; when needed, set `detail=true` and compute the tokens inside responseData manually. In test mode, chatId and responseChatItemId do not exist.

## Constraints at the HTTP integrations step

The HTTP module can be added repeatedly, is configured manually, and triggers execution. The address, Params, Body, and Headers follow the external interface contract rather than local habit. String references inside Body need surrounding quotes, for example `"{{string}}"`, while number and boolean references are written without quotes. A return value key follows the format after FastGPT conversion, so the key must match the parsed structure rather than the raw response text.

Authentication credentials belong in secure configuration and do not belong in public examples. The chat interface does not return actual Token consumption, so any cost review that needs tokens must set `detail=true` and compute from responseData. Retrieval and similarity scores are not authorization or entity filters, and an HTTP call is not a business approval. A form collects values; business verification, approval, database writes, and external synchronization each need their own downstream implementation.

A hypothetical paper exercise sample: the source material reads, "A distributor credit agreement states a credit limit of 500,000 CNY, valid until March 31, 2026. As of January 31, 2026, the receivables aging table shows that this distributor is overdue by more than 30 days in the amount of 120,000 CNY. The shipment freeze notice is in draft status, pending review, and unsigned." The draft sentence to be judged is, "This distributor has exceeded its credit limit, so shipment should stop and collection should begin." The review scope is the January 2026 aging period, this distributor entity, and the credit limit and freeze status fields.

## Configuration and implementation checks

| Configuration item | Value or practice | Basis and check point |
| --- | --- | --- |
| Request address | Enter per the external interface document; variables may be referenced | The address may contain `{{}}`; for this exercise the starting point is the service address given in the interface document, compared word by word |
| Request method | Choose GET or POST per the external interface contract | The method is decided by the external interface document, not by experience |
| Headers authentication | Authorization: Bearer `{{token}}` | Credentials are injected through secure configuration and are not written into public examples |
| Body | Effective only under the corresponding request type; fill per the JSON structure | String references need `""`; number and boolean references take no quotes |
| Return value extraction | Configure a key using JSON path or JavaScript object access | The key matches the format after FastGPT conversion; the output type decides string conversion |
| Test identity fields | chatId and responseChatItemId do not exist in test mode | An empty value in test mode is not treated as a business fault |

## Three common errors

1. Treating the return value configuration as the interface response itself. The input is the interface response JSON, the comparison is between the configured key and the response structure, and the observable result is whether the extracted value matches the expected value. When no key is configured, that value remains unknown.

2. Treating an empty chatId or responseChatItemId in test mode as a business exception. The input is a test mode request, the comparison is against the documented statement that these values do not exist in test mode, and the observable result is that an empty value appears. That appearance does not point to a business fault.

3. Passing body.appId and the Authorization form at the same time with inconsistent values. The input is the two appId values, the comparison is against the documented priority order, and the observable result is which appId takes effect. When they differ, body.appId takes precedence and a manual check is required.

## How to verify the setup

1. For the hypothetical sample, the input is the credit agreement text, the aging table text, and the draft freeze notice status. Compare the draft sentence "has exceeded its credit limit, so shipment should stop and collection should begin" against the source text. The observable result is that the source states only the credit limit and validity period, the overdue amount, and the pending freeze notice. It does not state a credit limit breach determination or authorization to stop shipment, so the draft sentence is not supported and remains to be verified.

2. For the HTTP request, the input is the address, method, and Headers entered per the external interface document. Compare the actually sent Params, Body, and Headers against the interface contract. The observable result is whether the fields and types match. Record differences without inferring external system behavior.

3. For return value extraction, the input is the interface response JSON and the configured key. Compare the extracted value against the value at the corresponding path in the response. The observable result is a match or a missing value. When missing, record it as not obtained and do not conclude that the interface failed.

Paper check for an empty result: if the interface returns an empty array `[]`, downstream design may accept an empty result; this does not claim that a retrieval rule necessarily returns empty. Libraries using different vector models cannot be associated together; check identifiers and exclude those that do not match. Retrieval does not handle authorization, and a similarity score is not a permission or entity filter. Authorization and effectiveness clauses that are not stated remain evidence gaps.
