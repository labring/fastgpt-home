# Channel receivables: workflow routing for operating reviews

## What the documents look like

Channel receivables collection happens after credit sales, and the operating core is the credit line and the cash recovery. The working materials are the receivables aging table, the collection letter, the credit agreement and the shipment freeze notice. Brand finance, sales back office and the distributor owner each hold part of the information. The aging table is updated weekly or monthly, while the collection letter and the credit agreement are formed within a single transaction.

Operating reporting and exception review must align the party, the object, the amount, the period and the status across these materials before anyone can judge whether a given receivable is overdue or whether a shipment falls under a freeze constraint. This page addresses one task only: channel receivables collection, operating reporting and exception review, at the workflow routing step. It does not treat retrieval or a form as authorization to execute a business action.

## Constraints at the workflow routing step

The form input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and the workflow continues after the user completes the interaction. It collects required form information and passes it to later nodes. The user selection node is also a user interaction node: when the user makes a choice, the node evaluates that choice and executes the corresponding "yes" branch. The interaction state is recorded by the interaction node; no separate global state-recording switch is documented.

Collected values must be passed explicitly to later retrieval, judgment or interface nodes, and the output must be compared item by item against the input. Order writing, document backfill and external status synchronization require a separate business interface or a later process; the form itself does not perform these actions. Retrieval and forms do not constitute authorization to execute.

Hypothetical drill sample: a brand finance reviewer examines one receivable of Distributor A in March 2025. The aging table states: "Distributor A, contract number H-203, receivable balance as of 28 February 2025 is 480,000, payment due date 31 January 2025." The credit agreement states: "Distributor A credit line 400,000, valid until 30 June 2025." The shipment freeze notice states: "Distributor A shipments suspended from 1 March 2025, to resume after the over-limit portion is settled." One draft sentence to be judged is: "Distributor A has settled the over-limit portion; shipment resumption is approved." That draft sentence concerns the authorization status of shipment resumption and must be compared against the release conditions in the freeze notice and against actual payment evidence.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this drill | Check method |
| --- | --- | --- |
| Required form input fields | Distributor name, contract number, receivable balance, payment due date | Compare item by item against the aging table fields |
| User selection branches | Resume shipment, continue freeze | Verify each "yes" branch connection one by one |
| Output receiving node | Pass form values to the later judgment node | Compare input values with values received downstream |
| Retrieval scope | Aging table, credit agreement, freeze notice | Confirm the materials fall within an accessible retrieval scope |
| External action split | Shipment resumption requires a separate business interface | Confirm the interface node is connected |

The hypothetical starting point applies to this paper drill only and is not an official default value. The four required fields were chosen because the aging table carries exactly these attributes for the same party and contract, so a downstream comparison is possible; the comparison target is the corresponding field in the aging table.

## Three common errors

1. Treating the "resume shipment" choice collected by the form as an executed shipment resumption. The user selection node only evaluates the branch direction; actual shipment resumption requires a separate business interface. Compare the selection result with the interface execution record. The condition is met only when both exist.
2. Subtracting the credit line from the aging table balance to obtain the over-limit amount while ignoring the payment due date and the effective date of the freeze notice. Compare the balance and the credit line for the same party, the same contract number and the same cutoff date, and confirm whether the release conditions in the freeze notice are satisfied.
3. Treating a retrieval result as the basis for authorization. Retrieval returns materials; it does not judge whether shipment resumption is permitted. Compare whether the materials underlying the draft sentence contain explicit evidence of freeze release. When that evidence is absent, record the item as pending verification.

## How to verify the setup

1. Input the aging table text and the credit agreement text from the hypothetical sample. Compare Distributor A's receivable balance of 480,000 as of 28 February 2025 with the credit line of 400,000, and confirm the over-limit amount is 80,000. If the downstream node outputs an over-limit amount different from 80,000, inspect the form field mapping.
2. Input the freeze notice text from the hypothetical sample and the draft sentence "Distributor A has settled the over-limit portion; shipment resumption is approved." Compare the release conditions in the freeze notice with the status stated in the draft sentence. If the materials contain no settlement evidence, the status stated in the draft sentence is unsupported; record it as pending verification.
3. Input the user selection "resume shipment" from the hypothetical sample. Compare the selection result with the external interface execution record. If only the selection result exists and no interface execution record exists, shipment resumption has not been executed and must not be treated as completed.

Judgment requires the same party, the same period and the same field. Only explicitly mutually exclusive values in the same field constitute a contradiction. Values that are not stated, or evidence that covers only a related stage, are unsupported or pending verification, not a negation or a conflict. A pending review does not demonstrate the absence of operating permission. Signing, reaching cooperation and contract effectiveness are three distinct facts. A quotation validity period does not indicate a supply period. Do not supply authorization or effectiveness clauses in order to obtain a definite answer; keep the evidence gap explicit. Materials needed for verification must sit within an accessible target retrieval scope or within a clearly identified manual input; when they are missing, record the gap.
