# Channel diversion reviews: workflow routing for operating reviews

## What the documents look like

Channel diversion review concerns regional and price order. The objects it handles are goods flow and selling prices. Rebate amounts sit outside this stage. The main data sources are the anti-counterfeit code system, e-commerce platform prices, distributor shipment records, and market inspections. Everyday documents are diversion complaint forms, anti-counterfeit code records, penalty notices, and investigation photographs. These materials update weekly and irregularly. This page does not derive batch synchronization or real-time trigger mechanisms from that update rhythm.

Anti-counterfeit code records supply the goods-source code and the query time. E-commerce platform prices supply the store listing price and the page time. Shipment records supply the shipping party and the receiving region. Inspection materials supply on-site photographs and written records. Across these four material types, the subject, object, and time range may not agree. Workflow routing has to map each field collected through interaction to the later nodes one by one, and keep fields without support as pending verification.

## Constraints at the workflow routing step

When the form input node triggers, the conversation enters an interaction state and the workflow state is recorded. After the user fills the required information and submits, the node passes that information to later nodes. When the user selection node triggers, the conversation likewise enters an interaction state. When the user makes a choice, the node evaluates the choice and executes the "yes" branch. Both nodes are user interaction nodes, can be added repeatedly, and trigger execution. The interaction state, the recorded state, and the hidden dialog box are existing node behaviors. No separate global state-recording switch is set here.

Retrieval and forms do not carry authorization execution. Order writes, document backfill, and external state synchronization require a separate business interface or a later process. Semantic recall and relevance scores do not handle permission or entity isolation, and a retrieval result cannot be treated as authorization already granted. Libraries across different vector models cannot be associated together; verify the identifier first and exclude those that do not match, rather than running cross-model retrieval to compare missed recalls. Empty-result handling can use a clearly defined paper input to check the downstream design.

Hypothetical drill sample: the source material reads, "Complaint form T-0417 records that anti-counterfeit code segment 8812 to 8860 for a certain batch was queried in the East China region; during the same period e-commerce page P-23 listed a price below the regional guidance price, with a page time of April 12; distributor D-07 shipment records show that batch shipped to South China." The draft sentence to be assessed is, "This batch was diverted through East China, and the penalty notice has taken effect." In this sample, the subject, object, state, and scope are paper settings only and point to no real customer or number.

## Three common errors

1. Treating form submission as a penalty already executed. In the sample, the draft sentence states the penalty notice has taken effect, while the material records only the complaint form, query records, page listing price, and shipment records. It does not record a penalty decision or an effective state. The check takes the draft sentence and the source material as input, compares whether a penalty notice and its effective record exist, and records the item as unsupported when the material does not state it.

2. Treating different periods or different fields as a contradiction. In the sample, the query region is East China and the receiving region on the shipment record is South China. These are different fields and do not form mutually exclusive values on the same field. The check takes the two source passages as input, compares the field names and values, and records the item as pending verification when the fields differ.

3. Treating a retrieval result as authorization or entity isolation. In the sample, a retrieval hit on a record does not mean that record is authorized for use in a penalty. The check takes the retrieval output and the authorization scope statement as input, compares whether an authorization record exists, and records the item as unauthorized when it is missing.

## How to verify the setup

1. Input the sample source material and the draft sentence, and compare whether the subject, object, and state in the draft sentence have corresponding records in the source text. The condition is met when, if the source text does not state that the penalty took effect, the draft sentence is judged unsupported and the evidence gap is retained.

2. Input the field list of the form input node and the inputs of later nodes, and compare whether the field names and values correspond item by item. The condition is met when a missing or misplaced field is recorded as a handoff inconsistency, without deriving an automatic correction.

3. Input the branch connection of the user selection node and the selection result, and compare whether the "yes" branch points to the expected later node. The condition is met when the branch connection and the selection result agree, recorded as a branch check pass, without claiming that a live test was performed.
