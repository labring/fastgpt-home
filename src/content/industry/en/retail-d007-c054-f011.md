# Channel diversion reviews: database operations for operating reviews

## What the documents look like

Channel diversion review concerns regional and price order. The objects handled are goods flow and selling price, and rebate amount calculation falls outside this scope. The main materials come from anti-counterfeit code systems, e-commerce platform prices, distributor shipment records, and market inspections. Daily documents include diversion complaint forms, anti-counterfeit code records, penalty notices, and investigation photographs. In operating reports and exception reviews, these materials share one requirement: only the same subject, the same period, and the same field can support a checkable conclusion. Anti-counterfeit code records are used to trace goods source codes, and e-commerce platform prices are used to compare low-price stores. When the two time bases do not agree, the result can only be recorded as pending verification, and diversion cannot be judged as established.

## Constraints at the database operations step

The database operations step requires separating business source data storage from the vector retrieval backend, and checking the corresponding service against the actual deployment. Connection configuration values cannot be inferred from variable names. Retrieval results do not carry authorization duties, and a similarity score does not act as a category, entity, or permission filter. Libraries built on different vector models cannot be associated together; the identifier must be checked first and non-matching libraries excluded, with the actual observation recorded.

Hypothetical drill sample: in March 2025 a brand channel control team received a diversion complaint form reading "Complaint target: East China distributor A; product batch involved: produced January 2025; complaint reason: found on an e-commerce platform selling below the suggested retail price." A separate anti-counterfeit code record reads "Scan time: 10 March 2025; scan location: South China; corresponding shipment record: shipped February 2025 to East China distributor A." An investigation photograph is annotated "taken 12 March 2025, screenshot of an e-commerce platform store page." The draft sentence to be judged is: "Distributor A committed cross-region diversion; a penalty is recommended." That sentence merges scan location with complaint region by inference, lacks direct correspondence evidence for the same period and the same field, and is unsupported.

## Three common errors

1. Treating the scan location in an anti-counterfeit code record as the diversion location directly. The input is the scan location "South China" and the complaint target "East China distributor A" in the sample above; the comparison is whether the two are mutually exclusive values of the same field. Scan location and the distributor's region are different fields, so they do not form a contradiction and can only be recorded as pending verification.
2. Treating retrieval results as an authorization basis. The input is an operating report query request, and the comparison is whether returned records contain unauthorized distributor data. A retrieval library similarity score does not perform permission filtering, and the authorization scope must be checked separately.
3. Treating a penalty notice still under review as an executed penalty. The input is the draft sentence "a penalty is recommended" in the sample, and the comparison is the signature state of the penalty notice against execution records. Pending review does not show that a penalty was executed; when signature and execution evidence are missing, the gap remains.

## How to verify the setup

1. Input the sample source text and the draft sentence above, and compare whether the draft sentence contains direct correspondence evidence for the same subject, the same period, and the same field. If the draft sentence relies only on scan location and complaint region by inference, judge it unsupported and record the evidence gap.
2. Input an operating report query request, and compare whether returned records match the authorization scope. If returned records contain unauthorized distributor data, record a permission check failure and inspect the authorization configuration.
3. Input the anti-counterfeit code record and shipment record from the sample, and compare whether scan time, scan location, and shipment record point to the same batch and the same period. If the time or location fields do not agree, record the result as pending verification and do not run cross-model retrieval to compare missed recall.
