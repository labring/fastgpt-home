# Franchise filing management: workflow routing for operating reviews

## What the documents look like

Franchise filing management handles legal disclosure and the commerce department system. It does not handle specific site engineering, which separates it from head-office site selection and store opening. The main data sources are the commercial franchise information management system, enterprise licences, the store list, and the contract ledger. The documents handled day to day are franchise contracts, operations manuals, filing materials, and information disclosure documents. In operating reports and exception reviews, these materials serve as evidence, and the state values recorded in them directly determine the review conclusion. The supplied brief gives the data update frequency as irregular and annual. This page does not derive any batch synchronization or real-time trigger mechanism from that frequency.

The materials carry different evidentiary roles. A contract ledger records signing status and signing dates. Filing materials record version labels and submitted content. An information disclosure document records the version issued to a franchisee. These are separate fields, and a value in one field does not by itself establish a value in another. When a review asks whether filing is complete, the reviewer must locate a field that records filing completion for the same subject, the same period, and the same field. Where that field is absent, the conclusion remains unsupported and the evidence gap is recorded.

## Constraints at the workflow routing step

The form input node is a user interaction node. When it is triggered, the conversation enters an interaction state, the workflow state is recorded, and the workflow continues after the user completes the interaction. The node collects the required information the user fills in and passes that information to subsequent nodes. The user selection node is also a user interaction node. When the user makes a selection, the node evaluates the choice and executes the "yes" branch. Branch connections are verified one by one. The recorded interaction state is behaviour of the interaction node. No separate global state recording switch is set here.

Retrieval and relevance scoring do not carry permission or entity isolation duties. Retrieval is not authorization. Order writing, document backfill, and external status synchronization require a separate business interface or a subsequent process. The workflow does not write a filing completion status.

Hypothetical drill sample, clearly labelled as hypothetical: a franchise head-office legal reviewer, during an operating report exception review, receives the following material text for assessment. "Franchisee A submitted filing materials in March 2026; the information disclosure document version is labelled V2. The contract ledger records the franchisee's contract signing status as signed, with a signing date of February 2026." The proposed draft sentence is: "The franchisee's filing materials and contract ledger are consistent, so filing completion can be confirmed." The task is to determine whether this draft sentence holds.

## Configuration and implementation checks

| Configuration item | Setting or check on this page | Relation to the sample |
| --- | --- | --- |
| Form input node | Enters interaction state when triggered; collects required information | Collects the exception type and material version entered by the reviewer |
| User selection node | Executes the corresponding branch after the user makes a selection | Branch decides whether the draft sentence holds |
| Interaction state check | Recorded state is node behaviour | Checks whether a state record exists during interaction |
| Output handover check | Passes collected information to subsequent nodes | Compares form output with the input of the later judgement |
| External operation split | Writing and synchronization connect to a separate interface or process | Filing completion status is not written by this workflow |
| Retrieval scope check | Verifies identifiers and excludes non-matching records | Confirms the material sits within the authorized access scope |

## Three common errors

1. Treating "filing completion" in the draft sentence as an established fact. The sample text records only a material version and a contract signing status. It does not record filing completion, so the conclusion is unsupported.
2. Treating the branch result of the user selection node as business authorization. The branch determines workflow direction only. It produces no filing or signing effect.
3. Treating a retrieval relevance score as a permission filter. The score does not exclude unrelated business or unauthorized records. Retrieval itself is not authorization.

## How to verify the setup

1. Input the sample text and the draft sentence, then compare whether "filing completion" has evidence for the same subject, the same period, and the same field. The source text does not record that field. The expected result is unsupported, and the evidence gap is recorded.
2. Input the branch result of the user selection node, then compare whether that result is used as business authorization. The branch executes workflow direction only. The expected result is that no filing effect is produced.
3. Input an explicit paper empty result `[]`, then check whether the downstream handover design handles an empty reference. The expected result is that the downstream shows no available reference. No claim is made that a fictional rule retrieval necessarily returns `[]`.

A cross-model library cannot be jointly associated. Verify identifiers first and exclude non-matching records. Do not run cross-model retrieval to compare missed recalls. The optional paths shown in the overall document flow diagram do not mean every request executes all of them. Image retrieval requires a corresponding image input and model capability. Reranking requires a model and must be enabled according to its settings.
