# Fruit-store procurement: citation tracing for operating reviews

## What the documents look like

Fruit procurement at store level depends on wholesale-market price movement and grade acceptance at delivery. This differs from convenience-store prepared-food ordering, where the assortment and specification largely follow a headquarters standard menu. The working papers for this category are purchase orders, acceptance records, pesticide-residue test reports and loss records. They update daily or per batch. In citation tracing, these papers serve one purpose: to let a figure in an operating report and a conclusion in an exception review point back to a specific document and a specific field.

A test report states a result for a stated batch. An acceptance record states arrived quantity, damaged quantity and a grade decision. When the report text or the acceptance grade conclusion is not attached to the review, the loss attribution in the report has no object to compare against. The same applies to purchase orders: a unit price written as "per that day's market quotation" cannot be checked against a number that the paper does not contain.

## Constraints at the citation tracing step

The knowledge-base search node can associate one or more knowledge bases that share the same vector model, and it outputs cited content as an array. The array length may be zero, which means the search path still completes and the output path is not cut off by an empty result. The citation limit controls, in tokens, the maximum amount of content cited per search. The minimum relevance value is a 0–1 filter threshold and takes effect only under semantic retrieval or result reranking. Hybrid retrieval merges multiple recall paths through RRF, and reranking requires a model and runs when configured. These mechanisms handle retrieval and ordering. They do not perform permission checks or business authorization.

Hypothetical drill sample. Three source sentences are available for comparison. Sentence one: "On 10 June 2025, purchase order CG-0610-03 bought 80 boxes of Red Fuji apples from stall A, unit price per that day's market quotation." Sentence two: "On 10 June 2025, acceptance record YS-0610-03 logged 78 boxes of this apple batch as arrived, of which 2 boxes were crushed, grade decision level two." Sentence three: "On 10 June 2025, pesticide-residue test report JC-0610-03 shows the batch result as qualified, and the report's valid scope is this batch." A draft sentence awaiting judgment: "On 10 June, all 80 boxes of Red Fuji apples passed inspection and entered storage, with no loss." This draft conflicts with the acceptance record's 78 arrived boxes and 2 crushed boxes, and it also conflicts with the test report's qualified conclusion, whose scope is limited to the batch.

## Three common errors

1. Treating a cited-content array of length zero as a workflow failure. The search node output array is allowed to have length zero, and an empty array means no content was retrieved while the path still completes. The error lies in equating an empty result with an execution failure.

2. Treating minimum relevance as a permission or entity filter. Minimum relevance is a 0–1 filter threshold that takes effect only under semantic retrieval or result reranking, and it does not exclude unrelated businesses or unauthorized records. The error lies in substituting a similarity setting for a permission check.

3. Treating the draft sentence "all 80 boxes passed inspection and entered storage, with no loss" as a verified conclusion. The acceptance record logs 78 arrived boxes and 2 crushed boxes, and the test report's qualified scope covers only this batch. The error lies in merging values from different fields into one fact.

## How to verify the setup

1. Input the three source sentences and the draft sentence, then compare the box count and loss wording in the draft against the acceptance record text. If the retrieval output contains the acceptance record text and the draft box count differs from that text, the draft is judged unsupported. The expectation is that retrieval can locate the acceptance record and the draft requires revision.

2. Input "10 June Red Fuji apple test result" and compare whether the retrieval output contains the test report text and its valid-scope wording. If the output contains the report text and the scope wording reads as this batch, the citation source is traceable. The expectation is that the report text appears in the cited content.

3. Input a paper-level empty array `[]` as the retrieval output and compare whether the downstream answer step is designed to accept an empty array. If the downstream design explicitly handles an empty array without interruption, the empty-result acceptance condition is met. The expectation is that the downstream design document records how an empty array is handled; no claim is made that retrieval will return an empty array.

Authorization boundaries stay outside this page. A pending request is not an approval, an option offered is not an execution, and an unsigned termination is not a completed termination. Where the source papers do not state a field, that field remains unknown.
