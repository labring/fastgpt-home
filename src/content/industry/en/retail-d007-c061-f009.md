# Fresh-food weighing and sorting: tool calls for operating reviews

## What the documents look like

Fresh-food weighing and sorting happens inside warehouse fulfilment, and its central facts are weight and specification. The working document set is the sorting task sheet, the weighing label, the short-weight compensation form and the quality inspection record. These materials update per order and per day. Sources include the WMS, electronic scales, the order system and inspection photographs.

For operating reports and exception review, four fields have to be read together under one subject, one period and one field name: the required specification on the sorting task sheet, the actual reading on the weighing label, the compensation status on the short-weight compensation form, and the judgement result on the quality inspection record. Tool calls and plugins matter here because they let the model decide from context whether to invoke a data-retrieval, comparison or lookup tool, so that fields scattered across documents come back for human review.

The brief marks this category description as broadly indicative rather than verified, so the material identities below are treated as the working assumption for this page.

## Constraints at the tool calls step

A tool introduction tells the model what the tool is for, and it needs to state the input conditions and the situations in which the tool should not be called. Tool parameters split into fixed parameters for system modules and configurable parameters for plugins. A parameter description is not an execution guarantee.

When a required parameter has no suitable value in context, the model may not call the tool at all. A prompt can guide the user to supply the missing parameter, and the actual request then has to be checked. In advanced orchestration, available tools are connected to the tool call module, and the documented advice is to start with a small number of tools and tune before expanding. The tool call termination node ends the current call; no further tools run and the AI does not summarise the tool results.

Retrieval and similarity do not carry permission or entity-isolation duties. Libraries built on different vector models cannot be associated together; the workable step is to check identifiers first and exclude non-matching records, then record what was actually observed. A similarity score is not a category, entity or permission filter, and it does not exclude unrelated businesses or unauthorised records. Retrieval is not authorisation.

Optional paths drawn in a document flow diagram do not mean every request executes all of them. Image retrieval needs a corresponding image input and model capability. Reranking needs a model and must be enabled through its setting. An empty result can be checked against a clearly written paper input when reviewing downstream design.

Hypothetical drill sample (not a real record). Text supplied for checking:

> Sorting task sheet FT-0417-02: subject is a front warehouse, object is the 17 April batch of spinach, 500 g specification, 120 orders, status sorted and awaiting review.
> Weighing label CT-0417-088: same subject, same object, actual reading 465 g, status printed.
> Short-weight compensation form BC-0417-15: same subject, same object, compensation status awaiting review.

One draft sentence to be judged: "The short weight in this batch has been compensated and the variance is closed."

The compensation status in the supplied text is awaiting review. A pending request is not approval, and awaiting review does not constitute completed compensation or a closed variance. The draft sentence and the source text disagree on the compensation status field, so the sentence is unsupported. On the authorisation boundary, the task sheet and weighing label are in a checkable state, while the compensation form is pending review; any compensation execution needs a separate system implementation and cannot be replaced by retrieval or a form.

## Configuration and implementation checks

| Tool introduction | State that it retrieves fields from the sorting task sheet, weighing label, short-weight compensation form and quality inspection record, and state that an awaiting-review compensation status must not trigger compensation wording | The introduction decides whether the model calls the tool; compare it item by item against what the draft-sentence judgement needs |
| Tool parameters | Subject, object, period and field name set as required parameters | With a required parameter missing, the model may not call the tool; check whether the actual request carries all parameters |

## Three common errors

1. Writing an awaiting-review status as completed compensation. In the hypothetical sample, compensation form BC-0417-15 has compensation status awaiting review, while the draft sentence says compensated and variance closed; the two values are mutually exclusive on the same field. Check: take the compensation status field from the source form and compare it word by word with the compensation wording in the draft sentence; the appearance of "compensated" means the sentence is unsupported.
2. Treating a tool parameter description as an execution guarantee. In the hypothetical sample, if subject and object parameters are not supplied, the model may not call the retrieval tool. Check: inspect the actual request for the four parameters subject, object, period and field name; a missing item is recorded as still to be supplied, and the tool is not assumed to have run.
3. Treating similarity as permission or entity isolation. In the hypothetical sample, if retrieval returns a weighing label belonging to another subject, a high similarity score does not make that record usable for this subject's review. Check: compare the subject identifier on each returned record with the task sheet subject; exclude and record non-matching records, and do not conclude from this that the system exceeded its authority.

## How to verify the setup

1. Input the three source passages from the hypothetical sample — sorting task sheet FT-0417-02, weighing label CT-0417-088 and short-weight compensation form BC-0417-15 — together with the draft sentence "The short weight in this batch has been compensated and the variance is closed." Compare the compensation wording in the draft sentence with the compensation status field in the source form. Expected observation: the compensation status is awaiting review, the draft sentence is judged unsupported, and no completed-compensation conclusion appears.
2. Input the same hypothetical sample and inspect the actual request made by the retrieval tool. Compare the subject, object, period and field name in the request with the task sheet source text. Expected observation: all four parameter groups are present and the subject matches; if any is missing, record it as still to be supplied, and do not state that the tool ran or returned.
3. Input the same hypothetical sample and check the subject identifier on each returned record. Compare each returned record's subject with the task sheet subject. Expected observation: records with a non-matching subject are excluded and recorded, records with a matching subject enter the review, and no claim is made that retrieval provides permission filtering.

These checks describe expected observations for a paper drill. No test, deployment, approval, refund or other business action has taken place.
