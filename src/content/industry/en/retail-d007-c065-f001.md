# Livestream violation appeals: HTTP integrations for operating reviews

## What the documents look like
Livestream violation appeals address penalties that already occurred, so the operating review must reconstruct the evidence chain. The working materials come from the platform violation center, livestream replay, customer service records, and the product qualification library. Routine documents include the violation notice, livestream recording, product qualification files, and the appeal statement. Data updates are irregular and each violation triggers one round of material assembly. Locating the violation segment, supplementing evidence, and drafting appeal reasons consume the most time. At the operating review and anomaly retrospective step, these materials move through HTTP requests into external systems, and the request and response records need to remain checkable.

## Constraints at the HTTP integrations step
The HTTP module sends a request to the corresponding address. Params, Headers, and Body can reference global variables, system variables, and upstream node outputs through `{{}}`, and the URL can also reference variables. Return values are extracted with JSON path syntax, and when the output type is set to string, the value of the corresponding key is converted into a json string. The chat interface uses APIKey authentication; when calling `chat/completions`, passing `body.appId` in the request body is recommended, and `Authorization: Bearer <apiKey>-<appId>` is also supported. `chatId` and `responseChatItemId` do not exist in test mode, so an empty test value does not constitute a business fault. Retrieval and similarity do not carry permission or entity isolation duties, and retrieval results cannot serve as authorization credentials.

Hypothetical exercise sample: A store compliance staff member receives a violation notice dated March 10, 2026. The notice text reads: "In the livestream replay from 20:15 to 20:22 on March 8, 2026, the qualification statement for Product A during the explanation segment did not match the registration in the product qualification library. A livestream ban is now imposed on this product, and the appeal period is 5 working days after delivery of the notice." The same batch of materials includes the livestream recording link for that time window and the qualification file for Product A. The draft sentence to be judged is: "The qualification statement inconsistency for Product A has been fully remediated, and the livestream ban is requested to be lifted." This draft claims remediation is complete, while the materials contain only the violation notice, the recording, and the qualification file. No remediation record or review conclusion appears, so the claim remains unsupported.

## Configuration and implementation checks
| Configuration item | Setting for this page | How to check |
| --- | --- | --- |
| Request address | External appeal system address, entered according to the counterparty interface document | Compare path and method word by word against the interface document |
| Headers | `Authorization` references a configured authentication variable | Check the variable source and injection position; do not write it into public samples |
| Body | Build JSON according to the counterparty interface contract, with fields referencing upstream node outputs | Check field names, types, and nested structure |
| Variable references | Reference global variables, system variables, and upstream node outputs | Check each actual passed value item by item |
| Return value extraction | Extract required fields by JSON path, with output type chosen by purpose | Check extraction results against a sample response |
| Debug identity fields | `chatId` and `responseChatItemId` do not exist in test mode | Record the empty value in test mode; do not judge it as a business fault |

## Three common errors
1. Treating a retrieval result or similarity score as an authorization credential. Retrieval returns content matches; it does not judge whether the material qualifies for an appeal, and it does not judge whether the operator has the right to submit.
2. Treating "fully remediated" in the draft sentence as a verified fact. The sample materials contain only the violation notice, the recording, and the qualification file. No remediation record or review conclusion appears, so the claim remains unsupported.
3. Judging a missing `chatId` or `responseChatItemId` in test mode as an interface fault. The documentation states that these two fields do not exist in test mode, so a debug empty value must be distinguished from a business anomaly.

## How to verify the setup
1. Input the violation notice text, the recording link, and the qualification file from the sample, then compare the draft sentence "The qualification statement inconsistency for Product A has been fully remediated, and the livestream ban is requested to be lifted" against the material scope. The materials do not state a remediation record or review conclusion. The draft sentence remains unsupported and should not be submitted as a verified fact.
2. Input the violation notice text from the sample, then compare the window "20:15 to 20:22 on March 8, 2026" against the window indicated by the recording link. When the two match, the window check passes. When they differ or the recording does not cover that window, record the item as pending verification.
3. In test mode, send one request and compare whether `chatId` and `responseChatItemId` appear in the response. When both are absent, record this as normal behavior in test mode according to the documentation, and do not judge it as an interface fault. To confirm a business session, switch to non-test mode and check the actual return values.
