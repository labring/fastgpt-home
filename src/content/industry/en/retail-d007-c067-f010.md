# Group-buy leader operations: citation tracing for operating reviews

## What the documents look like

Group-buy leader operations manage community pickup nodes and commission settlement. The work does not include cold-chain quality inspection, which belongs to a separate acceptance process. Four document types carry most of the operational record: leader agreements, commission tables, pickup lists, and community announcements. These materials update daily and per group. An operating review or an exception review has to answer a narrow question: which material, which version, and which field supports a stated conclusion.

Each document type has its own scope. A leader agreement sets the cooperation and settlement framework. A commission table records amounts due. A pickup list records quantities received and issued. A community announcement records commitments made to residents. Validity, signature status, and effective status are independent across these materials, so a citation check has to examine each one on its own terms. Historical and current versions can coexist, and the tracing task anchors a conclusion to a specific material and a specific field rather than to the category as a whole.

## Constraints at the citation tracing step

The knowledge base search node can select one or more knowledge bases that share the same vector model. Its output is an array of citations, and the length can be zero. An empty array means the output path still runs; it does not mean the workflow raised an error and stopped. Retrieval output has to be passed to the answering step, where each answer is checked against the cited source text. Retrieval does not perform permission checks. A similarity score is not a filter for subject, entity, or access rights, and the act of retrieval does not itself grant authorization.

Hypothetical paper exercise sample. Material one is a leader agreement text stating: "This agreement takes effect on the date both parties sign. Commission is settled by calendar month." Material two is a commission table for one month stating: "Settlement period: 1 May 2024 to 31 May 2024. Amount due: a stated sum in RMB." Material three is a pickup list for the same month stating: "Pickup date: May 2024. Quantity received: a stated number." The draft sentence under review is: "This leader's May commission has been settled in full." The fields needed to judge it are settlement status and settlement time. None of the three materials states that settlement is complete, so the draft sentence is not supported and remains pending verification. If a further material stated "Settlement status: not settled" with the same subject, period, and field, that would be a mutually exclusive value in the same field and could be judged a contradiction. Signing, reaching cooperation, and contract effectiveness are three distinct facts. When a material does not state one of them, the evidence gap stays open.

## Three common errors

1. Treating retrieval output as authorization or as an executed result. The input is the citation array returned by retrieval; the comparison object is whether the material states an approval or settlement status; the observable result is a non-empty citation array while the material does not state that status, which means the claim is not supported.
2. Treating an empty citation array as an error. The input is an empty array returned for a clearly specified paper input; the comparison object is whether the downstream node continues to run; the observable result is that the downstream step proceeds as designed, so no claim that the workflow terminated should be made.
3. Treating a similarity score as a permission filter. The input is one low-scoring citation; the comparison object is whether the material behind that citation falls within the current authorized scope; the observable result is that score level and authorized scope have no correspondence, so accessibility cannot be inferred from the score.

## How to verify the setup

1. Citation source check. The input is the text of materials one through three in the hypothetical sample above; the comparison object is the phrase "settled in full" in the draft sentence against the settlement status field in the materials; the observable result is that none of the materials states settlement is complete, so the claim is judged not supported.
2. Empty-result handling check. The input is an empty citation array for a clearly specified paper input; the comparison object is the design of the downstream answering step; the observable result is that the downstream step continues with the empty array and no error assertion is produced.
3. Material currency check. The input is the current version and a historical version of the same material; the comparison object is whether the field cited by the draft sentence changes between versions; the observable result is that the two versions carry different values for that field, so the difference is recorded and the item stays pending verification.

These checks describe expected observations. They do not report a completed test, an approval, or a deployment.
