# Group-buy presale orders: citation tracing for operating reviews

## What the documents look like

Group-buy presale collection takes orders first and organizes procurement and fulfillment afterward. Operating reports and exception reviews for this category answer whether the collection result for a given session and cutoff moment matches the procurement plan that follows. The main materials come from mini-program orders, supplier inventory, group-leader feedback, and warehouse routing. Daily documents include the presale product table, collection results, procurement plan, and cutoff notice. These materials update daily or per session, so a review must first lock the session and cutoff time before discussing differences. Citation tracing here means every number and conclusion in a report can point back to a specific field and version in one of those materials, so that attribution of stockout refunds, fulfillment delays, and group-leader complaints can stand.

## Constraints at the citation tracing step

The knowledge-base search node can associate one or more knowledge bases that share the same vector model, and outputs cited content as an array whose length may be zero. When no content is found, that output path still runs. This node behavior shapes the downstream tracing design: an empty citation array is a possible normal output and cannot by itself be treated as a retrieval error or business exception. Similarity and minimum relevance only filter and rank recall results; they do not isolate operating entities, sessions, or permissions. Retrieval is not authorization. Hybrid retrieval merges multiple result paths through RRF, reranking participates only when a model is available and enabled by settings, and image retrieval requires image input and model capability. These paths are optional steps listed in the flow diagram, not steps executed on every request. Knowledge bases with different vector models cannot be associated together; during checking, compare vector model identifiers first, exclude those that do not match, and do not run cross-model retrieval to compare missed recalls.

Hypothetical drill sample: a platform operator reviews the March 18, 2025 session. Available materials are the cutoff notice text "This session closes at 20:00 on March 18; presale product table version V3; collection results use orders at that moment as the basis," and the procurement plan text "This plan is compiled from the collection result closed at 20:00 on March 18 and covers the March 19 sorting wave." A draft sentence to be judged reads: "The collection result for this session matches the procurement plan, and the stockout refund was caused by insufficient supplier inventory." The sentence has a clear subject, session, and field reference, but neither "matches" nor "caused" appears in the above source texts, so it is unsupported.

## Configuration and implementation checks

| Configuration or check item | Hypothetical trial starting point for this session | Reason for the choice and comparison object |
| --- | --- | --- |
| Associated knowledge bases | Select only bases sharing the vector model of this session's materials | Compare vector model identifiers against already selected bases; exclude non-matching ones |
| Search mode | Hybrid retrieval | Compare hit behavior on exact queries such as numbers and session labels against semantic retrieval alone |
| Citation limit | Hypothetical starting point of 4000 tokens | Compare against the length of the cutoff notice and procurement plan texts to keep source text fully citable |
| Minimum relevance | Hypothetical starting point of 0.4 | Compare against recall entries without filtering to observe whether irrelevant fragments decrease |
| Question optimization | Not enabled for this session review | Compare retrieval latency and completion results against the enabled state |
| Citation output handling | Pass the citation array to the answer step and check each item against source text | Compare against the downstream branch design when the citation array is empty |

These values are hypothetical trial starting points, not official defaults. The configuration separates four kinds of items: existing node behavior (citation array may be zero), configurable fields (knowledge base association, search mode, citation limit, minimum relevance, question optimization), manual checking actions (comparing vector model identifiers, checking each citation against source text), and business actions requiring separate system implementation (procurement plan writes, stockout refund approval, external synchronization).

## Three common errors

1. Treating an empty citation array as retrieval failure. Input is a query with no hit; the comparison object is the empty array versus a node error; the observable result is that the output path runs and downstream receives an empty array. Asserting a business exception from this is wrong.
2. Using similarity scores as a substitute for permission or session isolation. Input is a cross-session query; the comparison object is recall results versus authorized scope; the observable result is that low-relevance entries are filtered while unauthorized records may still be recalled. Concluding that isolation has occurred is wrong.
3. Treating a procurement plan pending review as already approved and executed. Input is a plan text marked "pending review"; the comparison object is the review status field; the observable result is that the status has not changed. Concluding that procurement has been placed is wrong.

## How to verify the setup

1. Input the cutoff notice and procurement plan texts from the hypothetical sample, and compare whether the draft sentence "the collection result matches the procurement plan" has a same-session, same-field counterpart in the source texts. The observable result is that the source texts do not state "matches," so the sentence is judged unsupported.
2. Input a paper case where the citation array is empty, and compare whether the downstream answer step has an empty-citation branch. The observable result is that downstream can still return a "no source retrieved" notice, which satisfies the condition.
3. Input two knowledge bases with different vector model identifiers, and compare whether the association operation allows selecting both. The observable result is that only same-model bases can be associated together, while non-matching ones are excluded and the observation recorded, without further inferring missed-recall outcomes.
