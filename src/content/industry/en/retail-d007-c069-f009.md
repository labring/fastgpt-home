# Dealer rebate calculation: tool calls for operating reviews

## What the documents look like

Rebate calculation happens after sales close. The governing question is how the policy basis and the financial treatment are defined, not how inventory is replenished. The working data comes from ERP sales, dealer remittances, the contract ledger and the finance system. The documents handled day to day are rebate policies, sales attainment tables, reconciliation statements and red-letter invoices. Monthly and quarterly updates mean an operating review must aggregate a single period, and the most time-consuming steps are checking the attainment basis, deducting returned goods, and offsetting by invoice. For tool calls, this means organizing the checking actions across rebate policy, sales attainment table, reconciliation statement and red-letter invoice into a reviewable call chain, so that an exception review rests on identifiable inputs.

## Constraints at the tool calls step

A tool consists of a tool introduction and tool parameters. The introduction tells the model what the tool is for. For parameters, the parameter introduction and whether the parameter is required together determine whether the model calls the tool. Where a required parameter exists and no suitable parameter is present in context, the model may not call the tool; prompts can guide the user to supply it. Where no parameter is required, the model may fabricate a parameter, so the actual request needs manual checking. In advanced orchestration, available tools are connected to the tool call module; connected tools separate tool inputs from ordinary inputs, and the introduction can be edited to sharpen call timing. The official guidance is not to add many tools at once, but to tune a small set first. A tool call termination node ends the current call, calls no further tools, and does not call AI to summarize tool results. A custom variable can add a variable description for a node that is not treated as a tool parameter. Retrieval and similarity do not carry permission or entity isolation; retrieval is not authorization. Libraries on different vector models cannot be associated together; identifiers are checked and non-matching items excluded.

Hypothetical paper exercise: a brand finance reviewer checks Q4 2025 dealer rebates in January 2026. Source text: "The rebate policy states that the quarterly attainment rate is calculated on net sales after deducting returns, and an attainment rate below 90% does not trigger a rebate." "The sales attainment table shows Dealer A Q4 net sales of RMB 8.6 million against a target of RMB 10 million." "The reconciliation statement records Dealer A Q4 returns of RMB 400,000, and red-letter invoices of RMB 120,000 have been issued." Draft sentence to be judged: "Dealer A's Q4 attainment rate is 86%, no rebate is triggered, and the red-letter invoice amount is unrelated to the rebate." The request is pending review and has not been approved.

## Configuration and implementation checks

| Configuration item | Use on this page | How to check |
| --- | --- | --- |
| Tool introduction | State the purpose of rebate policy, sales attainment table, reconciliation statement and red-letter invoice, and the situations where a call should not occur | Check whether the introduction states input conditions and exclusion conditions |
| Tool parameters | System module parameters are fixed; plugin parameters are configurable | Check parameter introduction and required status; do not treat a parameter introduction as a guarantee of execution |
| Required parameters | Where a suitable required parameter is absent, the model may not call | Complete through interaction, then check the actual request content |
| Tool connection | Connect available tools to the tool call module in advanced orchestration | Connect a small number of tools and tune before expanding |
| Tool call termination | Ends the current call; no further tools and no AI summary | Confirm the termination node position matches the intended end scope |
| Custom variable | Adds a variable description for a node not treated as a tool parameter | Check whether the variable description corresponds to the node's actual input |

Hypothetical starting point for this page: set the attainment-threshold check as one call, because that field appears directly in the source material and is comparable; compare it against the 90% threshold in the source text. This starting point is not described as an official default.

## Three common errors

1. Treating a parameter introduction as a guarantee of execution. A parameter introduction only explains what the parameter means; whether the model calls still depends on context. Input: the sample material and draft sentence above. Compare: whether the parameters in the model's actual request come from the source text. Observable result: whether values not stated in the material appear.
2. Treating similarity as a permission or entity filter. Retrieval does not exclude unauthorized records. Input: a library and query on the same vector model. Compare: whether the business entity of returned records falls within the scope of this review. Observable result: whether records for other dealers or other periods are mixed in.
3. Treating a pending review request as approved execution. The draft sentence is pending judgment and has not been approved. Input: the draft sentence and the source text. Compare: whether the attainment calculation uses the same entity, the same period and the same field. Observable result: whether "no rebate is triggered" in the draft is supported by the source text, and whether any link between the red-letter invoice and the rebate is stated.

## How to verify the setup

1. Input the sample source text and the draft sentence above. Compare the 86% attainment rate in the draft against the RMB 8.6 million net sales and RMB 10 million target in the material, and observe whether the result is consistent with the material. If the material does not state the complete calculation of net sales after returns, the conclusion remains to be verified and is not judged as a denial or a conflict.
2. Input the sample material above and one query request. Compare whether the entity, period and fields of returned records match Dealer A Q4, and observe whether records cross entities or periods. An empty result can be checked against a downstream design using the explicit paper input []; do not claim that a search on a fictional rule must return empty.
3. Input the draft sentence above and the tool call termination node setting. Compare whether AI summary output still occurs after termination, and observe whether the termination node covers the scope of the current call. If the node is not connected or the introduction is not clear, record it as a configuration gap and do not infer a runtime result.
