# Overseas stock replenishment: retrieval for operating reviews

## What the documents look like

Overseas stock replenishment for third-party warehouses covers replenishment plans, inbound appointment requests, inventory aging tables and last-mile delivery notes. A third-party warehouse can serve several sales channels, and the seller allocates stock across those channels. Source data arrives from the overseas warehouse WMS, ERP sales forecasts, freight forwarder systems and carrier bills, with weekly or daily update cycles.

Operating reviews and exception reviews align the subject, object, period and status recorded in these materials. Knowledge base retrieval locates historical materials relevant to the current review question. The retrieval step returns cited content only. It does not allocate stock, confirm an inbound appointment or settle storage and last-mile charges. A retrieval hit shows that a record exists in the searched library. It does not show that any downstream business action was approved or carried out.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Libraries built on different vector models cannot be associated together. When two libraries carry different vector model identifiers, the identifier is checked and the non-matching library is excluded; no cross-model retrieval is performed to compare missed recalls.

Search mode can be semantic retrieval, full-text retrieval or hybrid retrieval. Hybrid retrieval merges multiple result paths through RRF. The citation limit is measured in tokens. The minimum relevance value is a 0-1 filter threshold and takes effect only under semantic retrieval or when result reranking is used. It is a filter threshold, not a final ranking rule, and it is not a category, entity or permission filter. Question optimization performs coreference resolution and question expansion and adds one model call before retrieval. Result reranking requires a rerank model and must be enabled in the settings. Image retrieval requires image input and matching model capability.

Hypothetical paper test case: the source material reads, "Replenishment plan for March 2025; subject is an overseas warehouse operations group; object is product model A; status is pending review; effective range is 1 March to 31 March 2025." A draft sentence reads, "This replenishment plan was approved and executed on 5 March." The draft sentence has no corresponding record in the source material. The source material states only "pending review." The two statements share the same subject, the same object and the same period, and the status field takes different values, so the draft sentence is unsupported. Pending review does not show that operating permission is absent, and it does not equal approval.

## Three common errors

1. Treating a retrieval hit as authorization. The sample source material records the status "pending review." A retrieval result that returns this sentence shows only that the material exists. It does not show approval or execution. Check: input the draft sentence "approved and executed," compare it with the status field "pending review" in the source material, and observe whether the two are judged consistent. A judgment of consistency is an error.
2. Treating minimum relevance as a permission or entity filter. Minimum relevance is a 0-1 filter threshold. It does not exclude unrelated businesses or unauthorized records. Check: input the sample question, compare whether the returned results include replenishment plans belonging to other subjects, and observe whether a result is filtered out only because its similarity score is low. A conclusion that the threshold isolates subjects is an error.
3. Associating knowledge bases that use different vector models. The documentation states that only knowledge bases using the same vector model can be associated. Check: verify the vector model identifiers of two libraries, exclude the library whose identifier differs, and do not run cross-model retrieval. Forcing the association and then inferring missed recalls is an error.

## How to verify the setup

1. Input the sample source material and the draft sentence. Compare "approved and executed" in the draft sentence with "pending review" in the source material. Observe whether the result is marked unsupported. Condition met: the output states clearly that the source material does not record approval and preserves the evidence gap.
2. Input the sample question and run semantic retrieval and full-text retrieval separately. Compare whether the returned citations include the "pending review" field. Condition met: both modes return the sentence, or a mode that does not return it is recorded explicitly. A first-position hit or complete recall is not guaranteed.
3. Input a paper sample with an empty result, namely citation content as an empty array. Check whether the downstream design continues to run. Condition met: the downstream chain receives the empty array and records it. No claim is made that a fictional rule search must return an empty array.

The retrieval step returns cited content and does not perform stock allocation, inbound confirmation or charge settlement. Where a business action requires approval, database writes or external synchronization, that action needs its own stated downstream implementation.
