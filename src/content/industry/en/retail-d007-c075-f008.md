# Creator sales campaigns: workflow routing for operating reviews

## What the documents look like

Creator special-event sales collaboration centers on external creator fulfillment and commission settlement. Brand commerce staff, MCN agencies, and creator managers take part together. Operating reports and anomaly reviews draw on Selected Alliance, Juliang Xingtu, creator historical data, and shop transaction details. Everyday documents include creator cooperation agreements, commission setting forms, sample shipment forms, and livestream battle reports. The supplied material gives update frequency as per event and weekly; this page does not derive batch synchronization or transaction-triggered mechanisms from that.

These materials carry different statuses that directly affect routing. A cooperation agreement may sit at pending review or signed. A commission setting form may be only a quotation. A sample shipment form may record shipment only. A livestream battle report may cover only part of a time window. Workflow routing has to keep material status, authorization boundary, and downstream actions separate. Retrieval and form collection do not themselves constitute authorization.

## Constraints at the workflow routing step

When a Form Input node triggers, the conversation enters an interaction state, the workflow state is recorded, and after the user completes the required information and submits, the node passes the collected information to later nodes. When a User Selection node triggers, the conversation likewise enters an interaction state. After the user makes a choice, the node judges that choice and executes the corresponding "yes" branch. Branch connections need to be verified one by one. The interaction state is recorded by the interaction node; no separate global state-recording switch is documented.

Collected information must be passed explicitly to later retrieval, judgment, or interface nodes, and outputs must be compared item by item against inputs. Order writes, document backfill, and external status synchronization require a separate business interface or a later flow. Forms and retrieval do not perform those business actions. Semantic recall and relevance scores do not handle permission or entity isolation, and a retrieval result cannot serve as an authorization credential.

Hypothetical exercise sample: the paper materials are "Creator cooperation agreement (number H-01) states a signing date of 2025-03-01, a commission rate of 18%, and a settlement cycle of 15 days after each event ends; commission setting form (number Y-07) states the same creator and same special event with a commission rate of 18%, status pending review; sample shipment form (number S-12) states that on 2025-03-05, 2 sample items were shipped." The handover request to be judged is: "Please write the commission rate from Y-07 into settlement and execute according to the already-effective agreement." In this request, Y-07 is pending review, and the agreement signing date and the commission setting form status belong to different fields, so they must be checked separately.

## Configuration and implementation checks

| Configuration item | Relevant setting or check on this page | Basis and boundary |
| --- | --- | --- |
| Form Input node | Collect creator number, special-event date, commission rate, material status | Enters interaction state on trigger; passes to later nodes after submission |
| User Selection node | Set a yes branch for "enter settlement check" | Executes the corresponding yes branch after the user makes a choice |
| Interaction state check | Check whether the interaction node records state | State recording is interaction-node behavior; no global switch is documented |
| Output handoff check | Compare form output against later node inputs item by item | Information must be passed explicitly to retrieval, judgment, or interface nodes |
| External action split | Order writes, document backfill, external sync connect to separate interfaces | Forms and retrieval do not perform these business actions |
| Retrieval scope check | Check target library identifier and vector model identifier | Libraries using different vector models cannot be associated together |

This hypothetical trial starting point sets the commission rate threshold at 18%. The reason for choosing it is alignment with the 18% stated in sample H-01. The comparison method is field-by-field comparison of the same field between the commission setting form and the cooperation agreement. This value is only a starting point for this exercise and is not an official default.

## Three common errors

1. Treating a pending-review commission setting form as an already-effective agreement for execution. Input: Y-07 status "pending review." Comparison object: the signing fact of H-01. Observable result: the two status fields do not match, and a pending-verification record must be kept.
2. Treating a retrieval result as an authorization credential. Input: a creator record returned by one retrieval. Comparison object: the authorization scope of the cooperation agreement. Observable result: the retrieval result states no authorization field, so settlement cannot be written on that basis.
3. Treating form collection as equivalent to a business write. Input: the commission rate submitted through the form. Comparison object: the actual invocation record of the order-write interface. Observable result: the form node produces no write action, so a separate interface is required.

## How to verify the setup

1. For samples H-01 and Y-07, input the commission rate and status fields of both materials, and compare the values of the same field. If Y-07 status is pending review while H-01 is signed, judge the case as pending verification rather than as a contradiction.
2. For the handover request "execute according to the already-effective agreement," input that request and the signing date of H-01, and compare the effectiveness condition the request relies on against the facts stated in the materials. If the materials state no effectiveness clause, record the evidence gap and do not fabricate authorization.
3. For empty-result handoff, input an explicit paper retrieval result `[]`, and compare whether the downstream node handles it through the empty-result branch. If the downstream still enters settlement writing, judge the handoff design as not matching expectations; do not claim that a fictional rule retrieval necessarily returns `[]`.

Libraries using different vector models cannot be associated together. Check identifiers first and exclude those that do not match; do not run cross-model retrieval to compare missed recall. Image retrieval requires a corresponding image input and model capability. Reranking requires a model and must be enabled according to settings. Optional paths do not mean every request executes all of them.
