# Creator sales campaigns: retrieval for operating reviews

## What the documents look like

Creator sales campaigns are fulfilled by external creators and involve commission settlement, so the working materials differ from brand self-broadcast operations. The four document types for this category are creator cooperation agreements, commission setting sheets, sample shipment forms, and livestream performance reports. Operating reviews and exception reviews draw subject, object, period, and status from these materials in order to check commission definitions and after-sales commission deductions. Retrieval therefore faces multiple records of the same creator, the same session, and the same field, where values may originate separately from an agreement, a setting sheet, and a performance report. Materials update per session and per week, so retrieval needs to be scoped by session and period to keep one session's data out of another session's review.

## Constraints at the retrieval step

The search unit is the library. A collection only classifies data and does not affect search results. When associating multiple knowledge bases, they must use the same vector model; identifiers that do not match should be excluded first, and cross-model retrieval should not be run to compare missed recalls. Retrieval outputs references as an array, and the length may be 0, meaning the output path still completes even when nothing is found. Minimum relevance takes effect only under semantic retrieval or result reranking; it is a filter threshold and does not perform permission or entity isolation, and retrieval itself does not constitute authorization. Hybrid retrieval merges multiple result paths through RRF. Reranking and image retrieval require the corresponding models and must be enabled by configuration. The paths listed in the overall flow diagram do not mean every request executes all of them.

Hypothetical paper exercise sample: A brand business staff member keeps a paper record. The agreement text states that Party A is a brand and Party B is a creator, the cooperation session is the March 18 special, and the commission rate is fifteen percent. The commission setting sheet states that for the same session the commission rate is twelve percent, with an effective date of March 10. The livestream performance report states that the session's transaction amount is a certain figure, and after-sales commission deduction is pending verification. One draft sentence to be assessed reads: "This session's commission is settled at fifteen percent, and after-sales commission deduction is complete." The assessment scope of this draft sentence is limited to the subject, session, and fields recorded in the three materials above.

## Configuration and implementation checks

| Configuration item | Relevant setting or check on this page | Relation to the sample |
| --- | --- | --- |
| Associated knowledge bases | One or more libraries using the same vector model may be associated | The four document types must share a vector model to be associated together |
| Search mode | Semantic retrieval, full-text retrieval, hybrid retrieval | Session and rate are exact fields; full-text and hybrid can be compared |
| Reference limit | Unit is token | Set by actual length of performance report and setting sheet; observe whether content is complete |
| Minimum relevance | Takes effect only under semantic retrieval or result reranking | Label relevant and irrelevant samples first, then compare thresholds |
| Question optimization | Coreference resolution and question expansion | Compare the original question with the optimized question; check whether the subject was changed incorrectly |
| Result reranking | Requires a model and must be enabled by configuration | When candidates are many, compare order before and after reranking |

The hypothetical starting value for the reference limit in this exercise is 800 tokens. The reason is that this value is enough to hold a setting sheet and a performance report fragment, and it can be compared against a 400-token result for content completeness. This starting value is hypothetical and is not an official default.

## Three common errors

1. Treating the agreement rate returned by retrieval as the settlement basis. The error is that the input takes only the agreement record, and the comparison omits the setting sheet's effective date and its different value. The observable result is that the draft sentence adopts a definition that was not checked.
2. Writing a pending-verification status as complete. The error is that the input is "after-sales commission deduction pending verification" in the performance report, and the comparison object is "complete" in the draft sentence. The observable result is that the status was rewritten.
3. Treating an empty result as proof that no record exists. The error is that the input is an explicit paper empty array, and the comparison object is the downstream design. The observable result is that the empty path is misread as a negative conclusion.

## How to verify the setup

1. Input the three material texts above and the draft sentence. Compare whether the agreement rate, the setting sheet rate, and the effective date share the same subject, session, and field. Only when the same field shows clearly mutually exclusive values should this be judged a contradiction; otherwise record it as pending verification.
2. Input "after-sales commission deduction pending verification" from the performance report and "complete" from the draft sentence. Compare the status field values. The condition is met only when the materials record the completion fact; current evidence does not support this.
3. Input the paper empty array. Compare the downstream design for handling a reference length of 0. Observe whether the empty result still completes the path, and do not claim on this basis that retrieval necessarily returns empty.

This page addresses only creator sales campaigns, operating reviews and exception reviews, and knowledge base retrieval and recall. Which materials, operations, and requests are in what authorization state during an operations handover cannot be treated as authorization execution through retrieval or a form.
