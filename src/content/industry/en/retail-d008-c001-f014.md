# B2B marketplaces: multilingual work with model connections

## What the documents look like

For multilingual work in B2B marketplaces, this page examines FastGPT model connections. Does a multilingual discrepancy concern delivery of input, interpretation or an absent source? The examples are hypothetical.

## Constraints at the model connections step

A proposed supply statement has parallel Chinese and English sections whose scope restrictions need to enter the model input together. Save the submitted content and request response, checking delivery of both sections before examining preservation of their restrictions. If only one section was sent, locate the input path first. If both arrived, inspect how the generated text uses each original. The AI Proxy root address and service authentication establish connection conditions; successful connectivity does not establish correspondence between the language versions.

## Configuration and implementation checks

| Check | Condition for this question | Evidence to inspect |
| --- | --- | --- |
| AI Proxy dependency | Inspect model channels separately from application settings | Actual request and response for the parallel-text question |
| AIPROXY_API_ENDPOINT | Use the service root without a chat path | Delivery of both original language sections |
| AIPROXY_API_TOKEN | Nonempty and matching the service; an application key cannot replace it | Service authentication separate from document authorization |
| Model capability | Test languages and conditions using the actual text input | Business scope is not turned into product suitability |
| Application parameters | Inspect the actual effect of application or node settings | Input and output before and after adding the counterpart |

## Three common errors

- If only one bilingual column reaches the request, inspect the submission and input route rather than assuming the other column was read.

- If a component-company profile conflicts with a whole-device use description, retain each subject, language and source position while checking for changed translation referents.

- If Chinese settlement input produces English treated as a confirmed counterpart, distinguish generated text from confirmation evidence. Connectivity establishes no correspondence between the languages.

## How to verify the setup

If a task requires a business-confirmed English settlement counterpart but the input contains only a Chinese statement, record the English evidence as absent. Fluent generated translation cannot establish that the version has received confirmation. The proposed acceptance separates original-text delivery, the model response and business-confirmation status. After obtaining the counterpart, repeat the question and inspect whether that source actually entered the input. Test image or tool support only where the document path needs it; neither is an assumed prerequisite for reviewing ordinary parallel text.
