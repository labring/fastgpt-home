# MCN operations: model connections for multilingual work

## What the documents look like

MCN operations manage long-term account compliance for multiple creators, not a single brand campaign. The working documents are creator signing contracts, training records, violation handling forms and account schedules. In cross-border material and multilingual retrieval work, one batch of material can arrive from different platforms and language environments, and retrieval results need to be checked back against the specific document. Material update frequency is daily and weekly; this page's function does not depend on batch synchronization or real-time triggers. Model connection and configuration determine whether a retrieval request can be issued and which text blocks are returned. It does not determine whether a record is visible to a particular operations staff member.

## Constraints at the model connections step

From V4.17.0, AI Proxy is a required dependency. A missing `AIPROXY_API_ENDPOINT` or an empty `AIPROXY_API_TOKEN` causes startup validation to fail. The system needs at least one language model and one index model to work normally. The model ID is the value of the `model` field in the request Body and is globally unique. Model mapping can map the model FastGPT requests to the actual upstream model. Built-in models can be enabled directly; custom models are added through a form or a configuration file. Model capabilities are checked separately against the input each application needs; multimodal input, tool calling and thinking configuration do not substitute for one another. The same-vector-model requirement for a retrieval library applies only to vector association and does not extend to business registration sites or other external systems needing the same model.

Hypothetical drill sample: the source material reads "Page 3 of creator A's signing contract states validity from 1 January 2026 to 31 December 2026; page 2 of the training record notes compliance training completed in March 2026; page 1 of the violation handling form records one warning in May 2026." The draft sentence to be judged is "Creator A's contract is valid for all of 2026, so cross-border live scheduling can be arranged." The objects to check are the contract page, the training record page and the violation handling form page.

## Configuration and implementation checks

The following are hypothetical starting points for this trial and items to check, not official default values.

| Configuration item | Hypothetical starting point for this trial | How to check |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | Assume `http://aiproxy:3000` is entered | Confirm no `/v1` or `/chat/completions` is appended |
| `AIPROXY_API_TOKEN` | Assume a non-empty admin Token is used | Compare with the server configuration; confirm non-empty and consistent |
| Language model | Assume one tested channel is enabled | Send a request on the model test page and observe the response |
| Index model | Assume one tested channel is enabled | Confirm it is usable separately from the language model |
| Model mapping | Assume the requested model is mapped to an upstream model | Compare the request Body `model` with the actual upstream `model` |
| Retrieval library identifier | Assume the vector model identifier is recorded | Compare library identifiers and exclude mismatched ones |

## Three common errors

1. Filling `AIPROXY_API_ENDPOINT` with a complete model request address that appends `/v1`. Check whether the input contains only the service root address, compare against the documented description, and observe whether startup validation passes.
2. Entering an application API Key as `AIPROXY_API_TOKEN`. Check whether the input is an admin Token, compare with the server configuration, and observe whether it is non-empty and consistent.
3. Using a similarity score to infer that a record has been authorized. Check whether the input is a retrieval request, compare the returned text block with the source material, and observe whether the authorization boundary still requires checking back against the contract page.

## How to verify the setup

1. Enter the hypothetical sample source material and draft sentence. Compare the draft phrase "valid for all of 2026" with the contract page phrase "1 January 2026 to 31 December 2026" and observe whether the draft range matches the source. If it does not match, record the difference and do not use it to execute scheduling.
2. Enter a retrieval request concerning only creator A. Compare whether the returned text blocks come from creator A's contract page, training record page or violation handling form page, and observe whether material for other creators appears. If it does, record it and exclude it.
3. Enter the paper input `[]` for empty-result handling. Compare whether the downstream design treats it as an empty result and observe whether an undefined action is triggered. This check does not claim that a fictional rule retrieval necessarily returns `[]`.
