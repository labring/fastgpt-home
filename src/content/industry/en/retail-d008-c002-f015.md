# MCN operations: retrieval for multilingual work

## What the documents look like

An MCN organization manages long-term account compliance for multiple creators, and a single brand session is only one segment of that record. The working documents concentrate in four types: creator signing contracts, training records, violation handling forms, and account schedules. These materials are stored in Chinese, English, or bilingual form across the MCN backend, platform violation notices, creator account data, and the contract ledger.

The central difficulty for cross-border materials and multilingual retrieval is that one creator's contract clauses, violation records, and scheduling information may be retained in different languages. Retrieval has to hit the same field of the same subject across those languages. Materials update daily or weekly; this page does not cover any batch synchronization mechanism.

FastGPT's semantic retrieval supports cross-multilingual understanding, for example matching a Chinese question against an English knowledge point. Full-text retrieval depends on keyword hits and suits precise queries such as numbers and proper nouns. The search node can associate one or more knowledge bases that use the same vector model; knowledge bases with different vector models cannot be associated together.

## Constraints at the retrieval step

The search node accepts one or more associated knowledge bases sharing a vector model. The reference cap is measured in tokens. The minimum relevance value applies only under semantic retrieval or when result reranking is used. Question optimization performs coreference resolution and question expansion and adds one model call before formal retrieval. Retrieval recalls candidate content; it does not perform permission judgment or entity isolation. When the returned reference array has length 0, the output path still proceeds.

Hypothetical paper exercise sample: an MCN ledger holds a bilingual contract excerpt with the original text: "Creator Lin (stage name: A-Lin) signed a live-streaming cooperation agreement with the agency, cooperation period from March 1, 2025 to February 28, 2026. Clause 4 of the contract stipulates that the creator shall not provide live-streaming services for competing platforms during the cooperation period." A separate violation handling form records: "On July 10, 2025, creator Lin conducted a live stream on Platform B, which belongs to the competing platforms listed in Clause 4 of the contract." The draft sentence to be assessed is: "Creator Lin's contract was terminated in July 2025, therefore the Platform B live stream does not constitute a breach." This sentence concerns contract status and breach determination and must be checked field by field against the contract original and the violation form.

## Configuration and implementation checks

The following are configuration check items for this hypothetical trial starting point, built around the sample above. The values are trial starting points only and need adjustment after comparison with actual materials.

| Check item | Hypothetical trial starting point | Reason and comparison method |
| --- | --- | --- |
| Associated knowledge base | Associate only the knowledge base holding this contract and violation form under the same vector model | First check the vector model identifier used by that base, and exclude bases with other vector models |
| Search mode | Start with hybrid retrieval | Contract clauses contain numbers and proper nouns, the violation form contains natural-language description; compare hit content under both modes |
| Reference cap | Hypothetical starting point of 800 tokens | The contract excerpt and violation form total roughly 600 characters; compare whether the cap accommodates complete fields |

| Question optimization | Start with it off | The draft sentence has a clear subject; compare whether the retrieval term has its subject altered when on versus off |
| Result reranking | Start without enabling it | When candidates are few, compare ordering before and after reranking to confirm whether extra latency is introduced |

## Three common errors

1. Treating a retrieval hit as authorization or status confirmation. Input "creator Lin contract terminated" and retrieve the contract excerpt; compare the retrieval result against the cooperation period field in the contract original, and observe whether the word "terminated" appears. The contract original states only that the cooperation period runs to February 28, 2026, and does not state a termination fact. A retrieval hit does not mean the contract was terminated.
2. Treating a pending-review state as missing operation permission. Input the violation handling form; compare the review status field on the form against the form original, and observe whether an approval conclusion is stated. The form original records only the violation fact and does not state an approval conclusion. Pending review does not show that operation permission is absent.
3. Inferring runtime results after associating knowledge bases with different vector models. Check the vector model identifiers of two knowledge bases and observe whether the identifiers match. When identifiers differ, exclude that base; do not run cross-model retrieval to compare missed recalls, and do not infer the return behavior after joint association.

## How to verify the setup

All three checks below use the hypothetical exercise sample above and state input, comparison, and satisfying condition.

1. Contract status field check. Input the draft sentence "Creator Lin's contract was terminated in July 2025" and retrieve the contract excerpt in the associated knowledge base. Compare "terminated" in the draft sentence against "cooperation period from March 1, 2025 to February 28, 2026" in the contract original. The contract original does not state a termination fact; it carries only the cooperation period field. Satisfying condition: the retrieval result returns the contract excerpt original, and the check record notes that "terminated" is unsupported, preserving the evidence gap.
2. Violation fact against contract clause comparison. Input "On July 10, 2025, creator Lin conducted a live stream on Platform B" from the violation handling form, and retrieve Clause 4 of the contract. Compare the platform name "Platform B" in the violation form against the "competing platforms" listed in Clause 4. Satisfying condition: the retrieval result returns both the Clause 4 original and the violation form original, and the check record notes that the platform name still needs verification as to whether it falls within the scope listed in Clause 4.
3. Empty-result downstream handling check. Input a paper-constructed query whose retrieval result is expected to be an empty array []. Compare the downstream node's design for handling an empty array and observe whether the output path proceeds. Satisfying condition: the downstream node still executes subsequent steps when receiving empty reference content, and the check record notes that the empty-result handling design is confirmed, without claiming that any fictional rule retrieval necessarily returns an empty array.

This page addresses only MCN organization creator management / cross-border materials and multilingual retrieval / knowledge base retrieval and recall. Whether materials, operations, or requests are in a given authorization state during operational handover cannot be treated as authorization execution through retrieval or forms.
