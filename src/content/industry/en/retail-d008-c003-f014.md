# Shopify fulfillment: model connections for multilingual work

## What the documents look like
A Shopify standalone store leaves payment, shipping and fulfillment service setup to the merchant, not to a platform-wide automatic return flow. Order details, shipping templates, shipping labels and refund records therefore sit across Shopify Admin, payment gateways, carrier systems and inventory location data. Cross-border reference work and multilingual retrieval must handle the same order appearing with different languages and field conventions in each system, and any retrieved passage has to be checked against the original document text. Materials change per order and daily. That cadence describes document movement only; it does not imply batch synchronization, full synchronization, real-time updates or transaction-triggered processes.

## Constraints at the model connections step
Retrieval depends on an index model and a language model. The system needs at least one language model and one index model to operate normally. A model ID is the value of the `model` field in a request body and is globally unique; a model name is a display label and can be customized. In channel configuration, enter a `BaseUrl` and check whether `/v1` must be appended; do not enter a complete model request address. `AIPROXY_API_ENDPOINT` takes the AI Proxy service root address without `/v1` appended. `AIPROXY_API_TOKEN` must match the server-side configuration and must not be empty. Semantic similarity does not carry permission or entity isolation, and a retrieval hit does not mean the record is authorized for processing. Libraries belonging to different vector models cannot be associated together; first check the model identifier and exclude those that do not match.

Hypothetical paper exercise: on 10 March 2026 a standalone-store operator reviews the refund record for order A. The source text reads: "Order A submitted a refund request on 5 March 2026, status pending review, refund amount 40 USD." The proposed sentence is: "Order A's refund is complete." The check requires the same subject, the same period and the same field. The source status is pending review; the proposed sentence states complete. These are mutually exclusive values in the same status field, so the proposed sentence is unsupported. Pending review does not show that processing permission is absent, and it does not equal an executed refund.

## Configuration and implementation checks
The table below is a hypothetical trial starting point for this review only. It is not an official default.

| Configuration item | Hypothetical starting point | Reason and comparison object |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | `http://aiproxy:3000` | Compare with the service root address to confirm `/v1` is not appended |
| AIPROXY_API_TOKEN | A non-empty string | Compare with the AI Proxy server configuration to confirm a match |
| Language model | One enabled | Compare with the system requirement of at least one language model |
| Index model | One enabled | Compare with the system requirement of at least one index model |
| Model ID | Matches the channel model | Compare with the model name in the channel configuration |
| Vector library identifier | A single library identifier | Compare with the target retrieval library and exclude libraries from a different model |

## Three common errors
1. Treating a retrieval hit as authorization. Input is a retrieval request for order A's refund record; compare the retrieval result with the authorization scope. If the record is returned but no processing authorization exists, a refund or status change cannot be executed.
2. Writing pending review as complete. Input is the proposed sentence above; compare the source status field value "pending review" with the proposed sentence value "complete." The two are mutually exclusive and the proposed sentence does not hold.
3. Associating libraries across vector models. Input is two library identifiers from different vector models; compare the model identifiers. When they differ, exclude the association and do not run a cross-library retrieval comparison.

## How to verify the setup
1. Input the hypothetical source text and proposed sentence, compare the status field values, and if the source says pending review while the proposed sentence says complete, judge the proposed sentence unsupported.
2. Input the hypothetical `AIPROXY_API_ENDPOINT` value, compare whether `/v1` is appended, and if it is not appended and matches the service root address, the configuration condition is met.
3. Input the vector model identifiers of two libraries, compare whether the identifiers are the same, and if they differ, exclude joint association, record the actual observation, and do not infer missed recall or redundant results.
