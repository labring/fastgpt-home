# TikTok Shop US operations: workflow routing for multilingual work

## What the documents look like

TikTok Shop US store operations sit under local return windows, return grading, and overseas logistics constraints, which separates this category from Douyin store shelf operations. The daily documents are product listings, return and refund records, Return Grading evidence, and settlement statements. Data sources are TikTok Shop Seller Center, the order center, carrier tracking, and advertising reports. These materials update daily and per order.

This page covers workflow routing inside cross-border materials and multilingual retrieval. Material language may be English or Chinese. Retrieval and form collection are information-flow steps. They do not constitute authorized execution.

A return and refund record may carry an order identifier, a returned quantity and item, a return date, a closing date for the return window, and a carrier tracking status. A settlement statement carries its own fields. The two documents are not the same record, and a value collected from one does not become a value written into the other.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and the workflow continues after the user completes the interaction. When the user fills in the required information and submits, the node collects the submitted form values and passes them to later nodes. The User Selection node is also a user interaction node with the same interaction-state behavior. When the user makes a choice, the node evaluates that choice and executes the "yes" branch.

The interaction-state record belongs to the interaction node itself. The documentation does not describe a global state-record switch, so none can be assumed. Collected values must be explicitly passed to later retrieval, decision, or interface nodes. Order writes, document backfill, and external status synchronization require a separate business interface or a later process. Retrieval results and similarity scores do not perform permission or entity isolation.

Hypothetical paper exercise sample. The material text to compare against is: "Order US-2025-0417, buyer returned 2 units of item A on 2025-05-06; return window closed 2025-05-20; carrier tracking shows delivered 2025-05-09." A pending handover request reads: "Mark this order as refunded and synchronize it to the settlement statement." This request concerns refund execution and statement synchronization, which are business actions requiring separate system implementation. The available form node can only collect field values.

## Three common errors

1. Treating a retrieval result or similarity score as a permission filter. Input is a sample order query. Compare the returned records against the range the current user may access. Observe whether records outside that range appear. A similarity score does not perform entity isolation.
2. Treating form collection as business execution. Input is the request "Mark this order as refunded and synchronize it to the settlement statement." Compare the node's actual output against the requested action. Observe whether only field values are present, with no write or synchronization.
3. Treating the interaction-state record as a global snapshot guarantee. Input is a Form Input node trigger. Compare the documented behavior against the configuration interface. Observe whether an undocumented global state switch exists.

## How to verify the setup

1. Input the sample text "Order US-2025-0417, buyer returned 2 units of item A on 2025-05-06; return window closed 2025-05-20; carrier tracking shows delivered 2025-05-09." Compare the form output fields against the subject, object, and status in the source text. The condition is met when the output contains only collected values and does not mark the refund as completed.
2. Input the pending request "Mark this order as refunded and synchronize it to the settlement statement." Compare the node output against the requested action. The condition is met when only field values are passed and the refund and synchronization remain pending downstream implementation.
