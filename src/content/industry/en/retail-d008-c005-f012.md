# TikTok Shop US operations: document chunking for multilingual work

## What the documents look like

TikTok Shop US store operations sit under local return windows, return grading, and overseas logistics constraints. Errors in this setting can lead to platform automatic refunds, higher return fees, and failed appeals. The daily material set concentrates on product listings, return and refund records, return grading evidence, and settlement statements, with updates occurring daily and per order. These materials are frequently mixed-language: one batch of return records may contain English platform fields alongside Chinese operations notes in the same file. Chunk quality directly affects whether multilingual retrieval can locate the right passage.

A single group of source data may map to multiple indexes. When retrieval hits any one of those vectors, the whole group of data is recalled. Semantic retrieval can match a Chinese question to an English knowledge point, but its precision depends on keywords and sentence completeness. Full-text retrieval suits exact lookups such as identifiers, model numbers, and proper nouns. Hybrid retrieval combines multiple channels through RRF, and reranking produces a 0-1 score that can be used for filtering. The minimum relevance value only takes effect during semantic retrieval or when result reranking is used; it is a filtering threshold and does not perform permission or entity isolation. The reference limit is controlled by tokens, which differs from top k.

## Constraints at the document chunking step

Chunking needs to keep a condition, its explanation, and the content it constrains in the same segment. A return record typically carries a status field, an evidence field, and an operations note; splitting these apart can separate a pending state from the note that explains what is still pending. Because one group of source data can hold several indexes, a chunk can be annotated to raise its precision without discarding the surrounding record.

The retrieval mode choice interacts with chunk shape. Full-text retrieval depends on keyword hits and suits exact fields, while semantic retrieval depends on vector distance and suits natural-language questions. Hybrid retrieval uses both and merges them with RRF. Reranking then reorders candidate text and yields a 0-1 score. The minimum relevance value filters low-relevance results only in semantic retrieval or when reranking is used; it does not separate unrelated businesses or unauthorized records. Retrieval itself is not authorization.

Hypothetical paper exercise sample. The source material is three sentences. Sentence one: "Return ID R-2024-0912, product SKU A-118, buyer signed on September 3, 2024." Sentence two: "On September 10, 2024 the buyer applied for a return, reason: size mismatch, status is pending review." Sentence three: "Operations note: evidence images for this order have been uploaded, awaiting platform decision." A draft sentence pending judgment reads: "R-2024-0912 has completed the return and refund." Comparing against the source, the source only states pending review and awaiting decision; the completed refund asserted in the draft is not supported.

## Three common errors

1. Treating "pending review" as a completed refund. The source only states pending review and awaiting platform decision, while the draft says "has completed the return and refund." The two values occupy the same field and are mutually exclusive, so the draft is judged unsupported.
2. Using minimum relevance to filter unrelated businesses. This value only filters low-relevance results and does not distinguish entities or permissions. Treating a similarity setting as permission isolation produces a misjudgment.
3. Treating a successful upload as an updated index. After material changes, the actual training and index state must be checked. Upload completion and index effectiveness are two separate facts.

## How to verify the setup

1. Input the three hypothetical source sentences and the draft sentence, then compare the two values "pending review" and "completed." The draft is supported only if the source contains a completed refund status field; the current observation is unsupported.
2. Input Return ID R-2024-0912 and use full-text retrieval and semantic retrieval separately, comparing whether the returned content contains that group of source data. If semantic retrieval misses while full-text retrieval hits, record this as an observation without inferring a failure cause.
