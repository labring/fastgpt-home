# General import declarations: model connections for multilingual work

## What the documents look like

General trade import declaration work revolves around the import declaration form, commercial invoice, packing list, bill of lading and contract. The core data sits in dutiable value, freight and insurance, and tax payment. Records update per shipment and arrive from the International Trade Single Window, customs tariff schedules, freight forwarder arrival notices and foreign exchange payment documents. Cross-border material and multilingual retrieval has to handle multilingual fields and clause wording inside these documents, and model connection and configuration determine whether retrieval reliably returns the matching passages. When classification, extraction or tool calling is involved, toolChoice and functionCall are the fields to check; when a model supports neither, the documentation describes a prompt mode.

## Constraints at the model connections step

Model connection depends on AI Proxy. From V4.17.0, the App and any Admin service reusing App/Service configuration must set AIPROXY_API_ENDPOINT and a non-empty AIPROXY_API_TOKEN; missing either one causes startup validation to fail. AIPROXY_API_ENDPOINT takes the AI Proxy service root address without appending /v1 or /chat/completions; AIPROXY_API_TOKEN takes the administrator token matching the server side, and an application API key cannot substitute for it. At least one language model and at least one index model are required for the system to work normally. Multimodal input, tool calling and reasoning settings are verified separately, and application or node parameters are set in the orchestration.

Hypothetical paper exercise sample: an importer's customs manager prepares a paper verification set. The source text reads: "The commercial invoice states the transaction term as CIF, and freight and insurance are already included in the invoice total; the number of packages on the packing list matches the number on the bill of lading; the contract signing date is 2 March 2026, and no effective condition is stated." The proposed sentence is: "The contract took effect on 2 March 2026, and freight and insurance require no separate declaration." The pending request is: "Please confirm whether the proposed sentence above can be used directly for the customs document handover." The source text states no contract effectiveness clause and no declaration rule for freight and insurance, so both the effectiveness conclusion and the declaration conclusion in the proposed sentence are unsupported.

## Configuration and implementation checks

The table below lists the connection checks for this page. Every value is a hypothetical trial starting point, and configuration and test results remain to be verified in practice.

| --- | --- | --- |

| AIPROXY_API_TOKEN | Assume a non-empty administrator token | Compare against the AI Proxy server-side configuration to confirm they match |
| Language model enabled | Assume one language model enabled | Compare against the requirement of at least one language model |
| Index model enabled | Assume one index model enabled | Compare against the requirement of at least one index model |
| toolChoice capability | Assume toolChoice is true in that model's metadata | Compare against the capability requirement for classification, content extraction and tool calling |
| Model probe interval | Assume 15 minutes | Documentation supports integers from 5 to 60 minutes; compare against the sample review cycle |

Model probing covers only currently enabled system models. After a first failed probe request, the system retries automatically up to 3 times, so a single round makes at most 4 attempts, and only when all 4 attempts fail is the model judged abnormal. The alert Webhook pushes on state edge changes, with event types model_status_error and model_status_recovered. The same-vector-model requirement for a retrieval library constrains only the vector store and the index model identifier, and does not extend to business registry websites or other external systems.

## Three common errors

1. Filling AIPROXY_API_ENDPOINT with a full request address that includes /v1. Input is an address containing /v1; compare against the documented root-address form and record that the address format does not match the documentation. The actual path and response remain to be tested. This error belongs to the connection layer and is unrelated to the proposed sentence judgment in the sample.
2. Using an application API key as AIPROXY_API_TOKEN. Input is an application API key; compare against the server-side administrator token requirement and record that the credential purpose does not match. The actual authentication result remains to be tested. This item sits at a different layer from the contract effectiveness judgment in the sample source text.
3. Treating the contract signing date in the proposed sentence as the contract effectiveness date. Input is the sample source text and the proposed sentence; compare the value of the same field, contract effectiveness. The source text states no effectiveness condition, and the observable result is that the proposed sentence's conclusion is unsupported. This is an evidence gap and does not constitute a contradiction between the source text and the proposed sentence.

## How to verify the setup

1. Input the three sample source sentences and the proposed sentence, then compare the value of the same field, contract effectiveness. The source text states only the signing date and no effectiveness condition, while the proposed sentence asserts that effectiveness already occurred. The observable result should be that the proposed sentence's conclusion is unsupported and pending verification, not judged as a contradiction.
2. Input the sample source text and the pending request, then compare the field value for whether freight and insurance require a separate declaration. The source text states only CIF and that freight and insurance are already included in the invoice total, and states no declaration rule. The observable result should be that this declaration conclusion is unsupported and needs separate checking against the customs tariff schedule or declaration requirements.
3. Input the sentence "the number of packages on the packing list matches the number on the bill of lading" from the sample source text, then compare the package count fields of the packing list and the bill of lading. The source text states that the two match, so the observable result should be that this consistency statement is supported by the source text and can be kept as a verified item. Only if the two package count field values are mutually exclusive would this constitute a contradiction.

All three items take the paper sample as input and make no claim of actual testing. An empty result can carry a clearly stated paper input [] for checking downstream design, without claiming that a search for a fictional rule necessarily returns []. Retrieval and forms do not constitute authorized execution, and a pending review does not mean a lack of operating permission.
