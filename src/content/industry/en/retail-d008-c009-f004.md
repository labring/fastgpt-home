# Amazon FBM fulfillment: multilingual work with vector indexes

## What the documents look like

For multilingual work in Amazon FBM fulfillment, this page examines FastGPT vector indexes. An FBM return-address draft is neither an outbound address nor proof of an engaged carrier. The examples are hypothetical.

## Constraints at the vector indexes step

Proposed FBM material labels a customer-return address as a draft pending confirmation by the receiving party. Its English attachment says carrier booking is not made in this note. A question about the original order’s destination cannot be answered by that return address; shared address vocabulary must not erase direction. Index wording can retain customer return and pending recipient confirmation while pointing to the draft, but cannot name it an outbound-order record. The memo’s booking scope also does not establish that no external booking has ever been made.

## Configuration and implementation checks

| Material check | Conditions in this test | Implementation evidence |
| --- | --- | --- |
| Address direction | Return versus outbound | Check journey object. |
| Text stage | Draft pending confirmation | Trace confirmation evidence. |
| Order identity | Current order | Check same-address mapping. |
| Booking scope | Not done in this note | Do not infer that no carrier booking occurred outside this note. |
| Outbound query | Current record absent | Do not answer with return address. |

## Three common errors

First, an index may change return address into shipping destination; inspect direction and object instead of letting related English terms reverse the journey. Second, an answer may present the draft as confirmed; trace the receiving-party condition and seek a separate confirmation text. Third, another order’s carrier information may enter a similarly named address; inspect order identity and original-data mapping rather than join records through a shared street or city. These concern direction, stage and order ownership. They require source checking without populating a real address or arranging a shipment.

## How to verify the setup

Test original destination, proposed return recipient and confirmation evidence against actual returned text, stating insufficiency for unsupported questions. Multilingual hits do not replace order-identity checks, and several indexes for one original are not independent transport sources. Check the same embedding model within bases linked to the same retrieval node when relevant. This exercise collects no customer address and books no carrier. Failure to retrieve an outbound record does not establish that dispatch never occurred; an unconfirmed draft also decides no actual right to return goods.
