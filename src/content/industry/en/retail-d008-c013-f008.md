# Franchise store supervision: workflow routing for multilingual work

## What the documents look like

Franchise supervision in convenience retail centres on headquarters oversight of how franchisees execute standards, which differs from direct-operated fresh-food ordering. The working materials come from a supervisor app, POS sales, the franchise system and store photographs. Day-to-day documents concentrate in four types: store visit forms, franchise contracts, rectification notices and display standards. Updates follow weekly and monthly rhythms.

Under cross-border and multilingual conditions, one store visit form may exist in several language versions, and the clause text of franchise contracts and rectification notices needs cross-language comparison. Workflow routing therefore has to settle document location and language correspondence before any judgement step begins.

## Constraints at the workflow routing step

The form input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and after the user completes the required information and submits, the node collects what was entered and passes it to later nodes. The user selection node also enters an interaction state; when the user makes a choice, the node evaluates that choice and executes the corresponding "yes" branch. The interaction state and the hiding of the dialogue box are behaviours of the node itself. The documentation does not describe a global state-recording switch or a submission-count control.

Retrieval and form collection do not constitute authorization. Order writing, document backfill and external status synchronisation require a separate business interface or a later process. Libraries using different vector models cannot be associated together; the library identifier should be checked first and non-matching libraries excluded, rather than running a cross-model retrieval to compare missed recalls. An empty-result handoff can be checked against downstream design using the explicit paper input []; this does not establish that a retrieval will return empty.

Hypothetical exercise sample: the original text of a franchise contract annex states "Rectification notice number ZG-0417, subject is South China franchise store A, rectification item is missing cold-display temperature records, rectification deadline is 30 June 2025, status is pending store-owner confirmation." A draft handover request reads: "This store's rectification is complete; please archive and synchronise to the franchise system." The task is to judge whether the draft sentence is consistent with the original text.

## Configuration and implementation checks

| Configuration item | Type | Basis and starting point for this exercise |
| --- | --- | --- |
| Form input node | Documented node behaviour | Documentation states it enters an interaction state on trigger, collects required information and passes it to later nodes |
| User selection node | Documented node behaviour | Documentation states the "yes" branch executes after the user makes a choice; verify branch connections one by one |
| Interaction state check | Manual verification action | Check whether the node records state; do not add a global state switch |
| Output handoff check | Implementation check item | Compare collected information against the input and output of later retrieval and judgement nodes, item by item |
| External operation separation | Requires a separate system implementation | Archiving and franchise-system synchronisation need a business interface; the form itself does not execute them |
| Retrieval library identifier check | Implementation check item | Check the vector model identifier; exclude non-matching libraries and do not associate them together |

The retrieval starting point for this exercise sample is a single library with a single model. The reason for this choice is that the sample involves only one contract annex, so cross-model association is unnecessary when compared with a multi-library scenario.

## Three common errors

1. Treating a form submission as completed rectification or as archiving authorization. In the sample the original status is "pending store-owner confirmation" while the draft sentence says "complete." This treats a pending review as finished and lacks confirming evidence.
2. Treating the "yes" branch of the user selection node as automatic business execution. The documentation only states that the branch executes; archiving and franchise-system synchronisation still require a separate interface.
3. Associating retrieval libraries that use different vector models directly. The documentation does not state that cross-model libraries can be associated; the identifier should be checked first and non-matching libraries excluded, without inventing missed-recall or redundant-result outcomes.

## How to verify the setup

1. Input the sample original text and the draft sentence, then compare whether "pending store-owner confirmation" and "complete" share the same subject, the same period and the same field. These are mutually exclusive status values for the same rectification item; where they disagree, the draft sentence is judged unsupported.
2. Input the sample original text and check whether the form input node and the user selection node record the interaction state and pass information to later nodes. If an interaction state record is observed and the information reaches the next node, the condition is met; if not observed, record the gap.
3. Input the explicit paper empty result [] and check whether downstream nodes accept it as designed for empty input. If downstream handles it as empty input, the condition is met; the documentation does not state that a fabricated rule retrieval will necessarily return [], so no assertion is made on that basis.

This page addresses only franchise store supervision, cross-border materials and multilingual retrieval, and workflow routing. Which materials, operations and requests sit at which authorization state during an operational handover is a separate matter; retrieval and forms are not authorization to execute.
