# Letter-of-credit documents: citation tracing for multilingual work

## What the documents look like

Letter-of-credit document examination and presentation serves the bank's payment conditions, and the working focus is document consistency rather than tax matching. The materials handled each time include the letter of credit, commercial invoice, bill of lading, insurance policy and draft. Multilingual retrieval matters here because a Chinese-language question needs to reach the original English or bilingual clause text, while citation tracing requires that an answer can be returned to a specific document and a specific clause. The update frequency is per presentation, so the retrieval scope has to correspond to the current presentation batch rather than to a general document pool.

Two or three industry facts shape this page directly. First, the materials are structured trade documents whose clauses carry fixed field positions, such as the documents-required field of the credit, the on-board notation on the bill of lading, and the risks-covered field of the insurance policy. Second, the consequence of an unsupported statement is a discrepancy, a refusal, a fee deduction or delayed collection, which makes unsupported drafting costly. Third, the retrieval layer only supplies clause text; it does not decide whether documents are consistent, and it does not grant any authorization over the presentation.

## Constraints at the citation tracing step

A knowledge-base search node can be linked to one or more knowledge bases that use the same vector model. Knowledge bases built on different vector models cannot be linked together, so the vector model identifier of each candidate knowledge base is checked and non-matching ones are excluded before any search is configured. The citation output is an array whose length may be zero, which means the output path still runs even when no content is retrieved. An empty array is not a workflow error and does not terminate the branch.

The minimum relevance value is a 0-1 number that filters low-relevance results, and it takes effect only in semantic retrieval or when result reranking is used. It is a filtering threshold, not a final ordering rule, and it does not act as a permission filter or an entity filter. RRF is the fusion step for mixed retrieval results, not a toggle. The citation cap limits how many tokens of content a single search may cite, and it is a separate matter from a model's thinking budget. Thinking budget belongs to model thinking configuration and must not be reused as a citation token cap.

Hypothetical exercise sample. A presentation batch under one letter of credit contains the following source sentences. Credit field 46A: "DOCUMENTS REQUIRED: FULL SET OF CLEAN ON BOARD OCEAN BILL OF LADING." Bill of lading on-board notation: "SHIPMENT DATE: 2025-03-10." Insurance policy risks-covered field: "COVERING ALL RISKS AS PER OCEAN MARINE CARGO CLAUSES." The draft sentence to be judged is: "This batch of documents satisfies all documentary requirements of the credit, and document consistency can be confirmed." The source sentences do not state that the full set of documents has been submitted, and they do not state any examination conclusion. The draft sentence therefore reaches beyond the cited text and remains unsupported.

Image retrieval requires image input and matching model capability, and it is not part of this text-only sample.

## Three common errors

1. Treating a retrieval hit as authorization or as an examination conclusion. The draft sentence "satisfies all documentary requirements" exceeds the cited source text, which does not state that the full set of documents is complete. Retrieval supplies clause text only; a consistency conclusion requires human examination.

2. Treating minimum relevance as a permission or entity filter. The value is a similarity threshold and does not exclude unrelated businesses or unauthorized records. Retrieval is not authorization.

3. Treating an empty citation array as an error. The node output length may be zero, so downstream design has to handle an empty result. An empty array does not by itself indicate a workflow failure.

## How to verify the setup

1. Input the three source sentences above together with the draft sentence, and compare whether the draft sentence is supported by the source text. The source text does not state that the full document set is complete, so the expected result is unsupported, and the evidence gap is recorded rather than filled.

2. Input an explicit paper empty array [] and observe the downstream handling design. The expected behaviour is that the path runs through. This check does not assert that a fictitious rule will always return an empty array in live retrieval.

3. Check the vector model identifier of each selected knowledge base and exclude those that do not match, recording what is actually observed. Cross-model retrieval is not executed to compare missed recalls, and no runtime outcome is inferred from the identifier mismatch alone.

A pending request is not an approval, an offered option is not an execution, and an unsigned termination is not a completed termination. Where the source text is silent, the gap stays open.
