# Franchisee onboarding: document chunking for multilingual work

## What the documents look like

Opening coaching is a transfer of operating capability. Training attendance sheets, opening checklists, SOP manuals and assessment scores together record how a store moves from receiving training to meeting opening conditions. These materials are produced across languages: the head office SOP library is in Chinese, regional supervisors complete checklists in a local language, and attendance or score records submitted by franchisees may use another language. Materials update per store and per month, so the same store accumulates several versions across months.

Material structure directly affects chunking. Attendance sheets run as rows of person, date and course. Opening checklists run as entries of check item, result and rectification note. SOP manuals run as paragraphs of operating steps and applicable conditions. Assessment scores run as fields of person, subject and score. If a check item and its rectification note are split into separate chunks, retrieval may return the check item while the rectification requirement is lost. Chunking also needs to preserve the document identity and version that allow a block to be traced back to its source. When different versions of one SOP manual share identical text fragments, retrieval results cannot distinguish the applicable period.

## Constraints at the document chunking step

One set of source data can map to multiple vector indexes. Adding indexes does not change the underlying source content, so verification must separate the source data layer from the index layer. The vector model requirement of a retrieval library is an internal condition of that library and does not extend to external systems. Libraries built on different vector models cannot be associated together. During verification, confirm the identifier first, exclude those that do not match, and record the observed result.

Semantic retrieval can match across languages, for example a Chinese question matching an English knowledge point, but a match only reflects semantic proximity. It does not confirm a store's authorization status or opening qualification. A pending request is not approval, and an offered option is not execution.

Hypothetical drill sample: a chain brand's training department received in March 2026 an "Opening Checklist (Manila Store)" submitted by a regional supervisor. Three source sentences read: "Check item: cashier counter petty cash count procedure. Result: failed. Rectification note: the franchisee must complete retraining and re-assessment before April 10." A draft sentence awaits judgment: "This store's cashier procedure has passed the opening check." The material available for comparison shows only a failed result and a rectification deadline that has not yet arrived. The passed status asserted by the draft sentence is not stated in the material. This sample illustrates chunking and retrieval verification and does not represent any real store or completed business conclusion.

## Three common errors

1. Treating a successful upload as retrieval already updated. After a supervisor submits a checklist in March, confirming only that the file upload finished without checking actual training and index status can leave retrieval returning older content. Check method: input the checklist number and store name, compare whether the date field in the returned content is the March version, and observe whether an older date appears.

2. Treating a semantically similar retrieval hit as an authorization conclusion. The draft sentence "this store's cashier procedure has passed the opening check" is not semantically close to the "failed" result in the material, but retrieval returning another store's passed record could be misused. Check method: input the full draft sentence, compare whether the returned content's subject is the Manila store and whether the field is the check result, and observe whether records from other stores or other fields are returned.

3. Treating minimum relevance as a permission or entity filter. Minimum relevance is a filter threshold and does not distinguish store ownership or authorization scope. Check method: input a generic question without a store name, compare whether returned results include other stores' checklists, and observe whether threshold changes affect store-ownership filtering.

## How to verify the setup

1. Segment completeness check. Input the source text "Check item: cashier counter petty cash count procedure. Result: failed. Rectification note: the franchisee must complete retraining and re-assessment before April 10." Compare whether the retrieved chunk contains all three items: check item, result and rectification note. Satisfied condition: all three appear together and belong to the same store and the same checklist version.

2. Draft sentence judgment check. Input the draft sentence "This store's cashier procedure has passed the opening check." Compare against the actual value of the check result field in the material. Satisfied condition: if the returned material shows a failed result and an unexpired rectification deadline, the passed status asserted by the draft sentence is unsupported; if the check result field is missing from the material, record it as pending verification without judging it as a denial or a conflict.

3. Retrieval scope check. Input a clearly defined paper input empty-result scenario and check how the downstream design handles an empty result. Satisfied condition: the downstream design explicitly states that an empty result returns no referenced content and does not interpret an empty result as the store failing the check or the store not existing. This check does not claim that any invented rule retrieval necessarily returns an empty array.
