# Brand member operations: workflow routing for multilingual work

## What the documents look like

Brand member private-domain operations work from member tag tables, outreach plans, coupon rules and privacy authorization records. The data arrives from a CRM system, enterprise messaging, POS transaction records and mini-program behavioral data. In cross-border material and multilingual retrieval, one member may leave tags and authorization texts in different languages across markets, and an outreach plan has to reference the coupon rules of the market it targets.

The workflow routing step decides which materials enter the retrieval scope, how retrieval results pass into later nodes, and who receives the values collected by a form or selection node. Member tag tables update daily or weekly. That cadence affects version checking of materials. It does not create real-time synchronization or a transaction trigger.

A routing design that ignores language and scope will pull the wrong text into a decision. A design that treats a retrieval hit as permission will let an outreach plan move forward without a matching authorization. Both problems are visible at the node boundaries, which is where the checks below operate.

## Constraints at the workflow routing step

Cross-border multilingual material means one business object has several language versions. The retrieval node needs an explicit target language and material scope. The form input node is a user-interaction node: when it triggers, the conversation enters an interaction state, the workflow state is recorded, and after the user fills the required information and submits, the node passes that information to later nodes. The user selection node evaluates the user's choice and executes the corresponding "yes" branch. The interaction state is behavior of the interaction nodes. There is no separate global state-recording switch.

Retrieval results and collected form values are inputs. Order writes, document backfill and external state synchronization require a separately connected business interface or a later process. A similarity score does not perform permission or entity isolation, and retrieval is not authorization. Libraries built on different vector models cannot be associated together; identifiers must be checked first and non-matching libraries excluded.

Hypothetical drill sample. A brand CRM team prepares an extract of a member tag table in March 2026. The source text reads: "Member number M-2026-0317, market Singapore, tag language English, authorization record status signed, authorization scope marketing outreach." A separate outreach plan draft reads: "Send this member a Chinese coupon." The proposed judgment sentence is: "This member's authorization scope covers Chinese-language outreach." The pending request is: "Submit the above outreach plan for execution."

## Three common errors

1. Treating a retrieval hit as authorization confirmation. In the sample, the authorization scope reads marketing outreach and does not state language coverage. Retrieving the English tag table does not support the conclusion that Chinese outreach is authorized. Check: input member number M-2026-0317 and the authorization record source text, compare the authorization scope field against the proposed outreach language, and observe whether the two share a field with mutually exclusive values. If the scope does not list a language, record it as unsupported.

2. Treating a user selection branch connection as executed. In the sample, the user choosing "continue retrieval" means the selection action completed. It does not mean retrieval ran or that outreach was submitted. Check: input the selection result "continue retrieval", compare it against the later node's actual input, and observe whether the later node received a retrieval request. If the later node has no input, record it as pending verification.

3. Treating collected form values as written into a business system. In the sample, the form collects member number and target language. The form node collects and passes values only; order writes or document backfill require a separate interface. Check: input the form submission values, compare the form output against the business system record, and observe whether a corresponding change appears. If no change record exists, record the external action as not executed.

## How to verify the setup

- Verification 1. Against the proposed judgment sentence "This member's authorization scope covers Chinese-language outreach." Input the authorization record source text and the proposed sentence. Compare whether the authorization scope field states a language. Observe whether the scope explicitly lists Chinese. If the source text says only marketing outreach, the sentence is unsupported and the evidence gap remains.

- Verification 2. Against the pending request "Submit the above outreach plan for execution." Input the outreach plan draft and the request. Compare the execution action in the request against the nodes configured in the workflow. Observe whether the workflow contains an outreach execution node or an external interface. If the workflow contains only retrieval and judgment nodes, the request stays pending verification and is not treated as submitted.

- Verification 3. Against the retrieval scope. Input the target language "English" and the material identifier "Singapore market English tag table." Compare the retrieval node input language against the material identifier. Observe whether the retrieval results come from that material scope. If retrieval returns material in another language, record the actual observation and check that material identifier; do not infer cross-model recall failure. For empty-result handover, a paper input of [] can be used to check the downstream design, without claiming that a fictional rule retrieval necessarily returns [].

Across all three, the comparison must use the same subject, the same period and the same field. A contradiction requires one field with explicitly mutually exclusive values. A field that is not stated, or evidence that covers only a related stage, is recorded as unsupported or pending verification.
