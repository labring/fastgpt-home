# Brand member operations: citation tracing for multilingual work

## What the documents look like

Member private-domain operations centre on customer data and repeat-purchase outreach. The working materials are member tag tables, outreach plans, coupon rules and privacy authorization records. In a cross-border setting the same body of material often exists in several language versions, and a retrieved answer needs to point back to a specific source. CRM systems, enterprise WeChat, POS transaction records and mini-program behavioural data form the main inputs. The brief gives daily and weekly update frequencies; this page does not derive any synchronization mechanism from them.

Citation tracing means that every cited passage can be matched to a checkable original and version. The knowledge base search node can be linked to one or more knowledge bases that share the same vector model, and it outputs citations as an array whose length may be zero. An empty array does not mean the workflow has errored or stopped. The retrieval result is passed to the answering step, where each answer is checked line by line against the cited original. Semantic retrieval offers cross-language understanding, so a Chinese question can match an English knowledge point. A similarity score reflects content relatedness only; it carries no permission or entity-isolation duty, and retrieval itself is not authorization. The citation limit is measured in tokens. The minimum relevance value applies only under semantic retrieval or result re-ranking, and it is a filter threshold. Hybrid retrieval merges paths through RRF. Re-ranking requires a model and must be enabled in settings. Image retrieval requires an image input and the corresponding model capability. These paths do not run on every request.

Hypothetical drill sample: A brand member operations team holds an outreach plan titled "Outreach Plan — Southeast Asia Member Day Edition." Its original text reads: "This plan applies to members registered between 1 March 2025 and 31 March 2025; coupon rules follow the version posted in stores." A separate privacy authorization record reads: "Authorization scope: SMS and enterprise WeChat outreach; authorization status is awaiting member confirmation." A draft sentence reads: "This member has authorized SMS outreach and can be included in this outreach list." This sample exists for checking only and points to no real party.

## Constraints at the citation tracing step

The search node's citation output is an array that may be empty, and the downstream chain still runs. Checking therefore has to compare the draft or answer against the cited original rather than treat a hit as proof of anything else. The authorization record states a status of awaiting member confirmation, so the draft sentence asserting completed authorization does not match the source. A similarity score is not a category, entity or permission filter; it cannot establish that a member falls inside an authorized scope. The minimum relevance value only filters low-relevance results under semantic retrieval or re-ranking, and it does not exclude unrelated businesses or unauthorized records. The citation limit counts tokens, and the comparison object is the length of the cited original, not a guessed item count.

Several paths are conditional. Hybrid retrieval fuses semantic and full-text recall through RRF; re-ranking needs a model and must be enabled; image retrieval needs an image input and matching model capability. None of these runs on every request, so a check cannot assume they executed. Knowledge bases can be linked only when they share the same vector model, so the vector model identifier is compared first and non-matching bases are excluded. The linkage requirement does not extend to business-registration sites or other external systems. Retrieval is not authorization, and a form that collects a value does not by itself perform business verification, approval, a database write or external synchronization.

## Three common errors

1. Treating a retrieval hit as completed authorization. In the sample, the authorization status is "awaiting member confirmation," while the draft sentence states completed authorization. This treats a pending state as approved. Check: input the two originals and the draft sentence, compare the authorization status field values, and mark the draft as unsupported when it does not match the original.

2. Treating a similarity score as a permission filter. A retrieval score reflects content relatedness and does not judge whether a member falls inside the authorized scope. Check: input the retrieved entry and the authorization record, compare the subject of the entry against the authorized subject, and mark it unsupported when the subjects differ.

3. Treating an empty citation array as a workflow failure. The node output length may be zero and the chain still runs. Check: input a paper-level empty array `[]`, compare whether the downstream node handles it as designed, and record the actual observation if an error appears.

## How to verify the setup

1. Input the two sample originals and the draft sentence, then compare the authorization status stated in the draft against the "awaiting member confirmation" field in the original. When the two agree the draft is supported; when they differ it is recorded as unsupported.

2. Input the retrieved entry and the sample authorization scope, then compare subject, period and field for common origin. A contradiction is recorded only when the same field carries mutually exclusive values. Where a field is not stated, it remains to be verified.

3. Input a paper-level empty array `[]` and the downstream answering step, then compare whether the downstream handles it normally and observe whether an error appears. No error is recorded as consistent with the design; an error is recorded as an observed phenomenon without inferring a cause.

All judgements rest on the sample originals. Unstated matters remain missing, and no authorization or effective clause is supplied to force a definite answer.
