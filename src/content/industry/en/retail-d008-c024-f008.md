# Brand concession operations: workflow routing for multilingual work

## What the documents look like

A brand concession inside a shopping mall differs from a brand-owned street store in one structural way: the mall operates the unified cashier and settles with the brand through a deduction arrangement. Sales data therefore originates at the mall POS, while the brand ERP and the finance system keep separate records, and the monthly reconciliation statement has to be checked line by line against the mall's own figures. The documents handled day to day are the joint-operation deduction contract, mall activity letters, sales receipts, and the monthly reconciliation statement. The brief gives daily and monthly as the update rhythm; that rhythm does not change anything on this page, so it is noted and set aside.

For cross-border material and multilingual retrieval, these documents may exist in more than one language version. A retrieval result has to be taken back to a specific contract clause, an activity letter condition, or a reconciliation line before it means anything. Workflow routing here strings together manual verification steps, form collection, and retrieval calls into a repeatable order. It does not replace any approval or settlement action.

## Constraints at the workflow routing step

The form input node is a user interaction node. When it triggers, the conversation enters an interaction state and the workflow state is recorded; after the user submits the required information, the node passes that information to later nodes. The user selection node is also a user interaction node. It triggers the same interaction state, and once the user makes a choice, the node evaluates that choice and runs the corresponding branch. Both nodes can be added repeatedly and both trigger execution. Neither node performs approval, writes to a database, or synchronizes anything externally; those actions need a separate business interface or a later process.

Retrieval carries its own conditions. Where multilingual material is involved, the vector model identifier of the retrieval library has to be stated. Libraries built on different vector models cannot be associated together. The check is to compare identifiers first, exclude the ones that do not match, and record what was actually observed. Retrieval is a way of obtaining material and does not constitute an authorization decision. A relevance score is not a category, entity, or permission filter, and a similarity setting does not exclude unrelated businesses or unauthorized records. An empty result can be carried forward by checking the downstream design against a clearly stated paper input. The overall document flow diagram lists optional paths; those paths are not all executed on every request. Image retrieval requires a corresponding image input and model capability, and reranking requires a model and must be enabled in settings.

Hypothetical drill sample, used only for illustration on this page. A concession holds a joint-operation deduction contract whose original text reads: "Sales receipts of the concession shall be collected by the mall under unified cashiering; the brand shall be settled against the monthly reconciliation statement; the deduction rate is twenty percent." A separate mall activity letter states: "The registration deadline for the activity covered by this letter is March 10; late submissions will not be accepted." A draft sentence awaiting judgment reads: "The concession has completed registration for the March activity." The verification material contains no registration submission record and no mall confirmation. The draft sentence is unsupported.

## Three common errors

1. Treating a retrieval hit as an authorization basis. The input is a retrieved fragment of the activity letter; the comparison object is the registration submission record; the observable result is that the fragment contains only a deadline and no submission confirmation. Concluding that registration is complete from this is an error.

2. Writing a pending state as approved. The input is the draft sentence "The concession has completed registration for the March activity"; the comparison object is the source text of the material; the observable result is that the source text carries no registration submission and no mall confirmation. Outputting "registered" is an error.

3. Associating libraries across vector models. The input is the model identifiers of two libraries; the comparison object is whether the identifiers match; the observable result is that they differ. Performing the association anyway and drawing a conclusion from it is an error.

## How to verify the setup

1. Using the contract text and activity letter text from the hypothetical sample above, input the draft sentence "The concession has completed registration for the March activity," compare whether the source text contains a registration submission or mall confirmation, and observe that the result is unsupported. If the output is "unsupported" and a gap is recorded, the condition is met.

2. Input the paper empty result [], compare whether the downstream design emits a gap record, and observe whether the gap record appears. If the downstream emits a definite conclusion instead, the condition is not met.

3. Input the vector model identifiers of two retrieval libraries, compare whether the identifiers match, and observe that association is excluded when they differ. If cross-model association is still performed, the condition is not met.
