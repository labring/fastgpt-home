# Brand-owned store operations: model connections for multilingual work

## What the documents look like

Brand-owned stores are staffed and accounted for directly by the brand, without franchise contracts governing the relationship. The working documents include daily sales reports, shift schedules, display photos and inventory transfer orders. In cross-border material and multilingual retrieval, these items may arrive in Chinese, English or another language, and retrieval depends on a language model working together with an index model. The boundary of this page is model connection and configuration: bringing usable model channels into the system so retrieval requests can be routed correctly. Store scheduling, sales targets and transfer approval sit outside this task.

## Constraints at the model connections step

The system needs at least one language model and one index model before it can be used normally. AI Proxy is a required dependency. Both the App and any Admin service that reuses App/Service configuration must set AIPROXY_API_ENDPOINT and a non-empty AIPROXY_API_TOKEN; a missing item causes startup validation to fail. Older OpenAI environment variables and single-model custom request addresses do not replace these two settings. A model ID is the value of the model field in the request body and is globally unique; a model name is for display and can be customized. Model channels correspond to different provider protocols, and one model can be configured across several channels for load balancing. Channel priority runs from 1 to 100, and a larger value is selected more readily. Retrieval relevance is determined by the vector model and the index model. Retrieval itself does not perform authorization judgment, and a similarity setting does not exclude unrelated business records or unauthorized records.

Hypothetical exercise sample (paper construction only, used to explain a checking method; it does not represent any real system result):

Material text one, excerpted from a daily sales report of a brand-owned store dated 15 March 2026: "The store recorded 42 cross-border online orders that day, of which 17 were placed through the English interface and 25 through the Chinese interface; 3 orders were returned, all from English interface orders."

Material text two, excerpted from the shift schedule of the same store dated 15 March 2026: "Morning shift 3 people, evening shift 2 people; the evening shift is responsible for organizing display photos after closing and uploading them."

Draft sentence awaiting judgment: "The return rate for English interface orders at this store on 15 March 2026 was 3/42."

## Three common errors

1. Treating AIPROXY_API_TOKEN as interchangeable with an application API key. Input: an environment variable list for a deployment. Comparison object: the documented description of AIPROXY_API_TOKEN. Observable result: if the variable is empty or holds an application API key, the configuration does not meet the requirement.
2. Appending /v1 or /chat/completions to AIPROXY_API_ENDPOINT. Input: the address value as filled in. Comparison object: the documented statement that /v1 must not be appended. Observable result: if /v1 appears at the end of the address, the value does not match the documented requirement.
3. Treating retrieval relevance as a permission filter. Input: a retrieval request and its returned records. Comparison object: the business scope of the records against the requesting party's authorization scope. Observable result: if unauthorized records are returned, the retrieval step did not perform authorization judgment and downstream implementation is required.

## How to verify the setup

The three checks below use the hypothetical sample above and do not claim that any test was actually executed.

1. For material text one and the draft sentence: input is "17 were placed through the English interface" in the source and "the return rate for English interface orders was 3/42" in the draft. Comparison object is the value of the same field over the same period. Observable result: the draft denominator 42 does not match the English interface order count of 17 in the source, so the sentence is not supported by the source and the origin of the denominator needs verification.
2. For material text two: input is "the evening shift is responsible for organizing display photos after closing and uploading them." Comparison object is whether the draft sentence contains a status description such as "uploaded" or "completed." Observable result: the source states only a division of responsibility and does not record an upload completion status; if the draft sentence asserts completion, it goes beyond the source.
3. For model configuration: input is the system model list and channel configuration. Comparison object is the documented requirement of at least one language model and one index model. Observable result: if the list contains at least one enabled language model and one enabled index model, the minimum configuration condition is met; if either category is missing, it is not met.

A retrieval check should observe the correspondence between actually returned records and the request language and model identifier, and record failure branches. It does not guarantee a first-position hit or full recall. An empty result can be checked against a clearly written paper input of [] to examine downstream design; this does not claim that a fictional rule retrieval necessarily returns []. Libraries built on different vector models cannot be associated together; the identifier should be checked first, non-matching libraries excluded, and actual observations recorded. A pending review status does not demonstrate the absence of operation permission. Signing, reaching cooperation and contract effectiveness are three distinct facts, and evidence gaps must remain explicit.
