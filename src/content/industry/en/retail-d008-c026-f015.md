# Brand-owned store operations: retrieval for multilingual work

## What the documents look like

Brand-owned stores are staffed and accounted for directly by the brand, so store documentation sits with the brand retail company, store managers and regional managers rather than being governed through a franchise contract. The recurring records are daily sales reports, shift schedules, display photographs and stock transfer orders. Display photographs and transfer orders frequently carry fields in more than one language, which makes cross-language retrieval a practical concern rather than a theoretical one. The brief places update frequency at daily or weekly. That frequency describes how often the source records change; it does not by itself establish any batch synchronization, full synchronization, real-time or transaction-triggered mechanism on the retrieval side. The retrieval step only needs the material to have completed training before it can be cited.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases with different vector models cannot be associated together. The cited content is output as an array and its length may be 0, which means the output path still runs even when nothing is retrieved. The minimum relevance value is a filter threshold and takes effect only in semantic retrieval or when result reranking is used; it does not perform permission filtering or entity isolation. Image retrieval requires image input and the corresponding model capability. Reranking requires a model and must be enabled according to the settings. RRF is the fusion step that combines results from several recall paths; it is not a switch that is turned on.

A hypothetical paper exercise sample: a regional manager for a brand-owned store submits a handover request for assessment. The source material reads: "1 March 2025 to 31 March 2025, Store A stock transfer order No. 12, transferring party Store A, receiving party Store B, quantity 40 items, status pending regional manager review." The draft sentence under assessment reads: "This transfer order has completed the transfer and has been counted into Store B inventory." The scope of comparison is limited to the stated dates, the order number and the two store entities.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | Reason and comparison method |
| --- | --- | --- |
| Associated knowledge bases | A base containing transfer orders and display photographs | Check whether the vector model identifier matches; exclude any base whose identifier differs |
| Search mode | Hybrid retrieval | Compare the candidates returned for the same question under semantic retrieval, full-text retrieval and hybrid retrieval |
| Citation cap | Starting point set to 2000 tokens | Compare whether citations remain complete using transfer orders of different lengths |
| Minimum relevance | Starting point set to 0.5 | Label relevant and irrelevant samples first, then compare against 0.4 and 0.6 |
| Question optimization | Enabled | Compare the original question with the optimized question and check whether the subject was altered |
| Result reranking | Enabled according to model availability | Compare candidate ordering before and after enabling, recording only what is observed |

These values are starting points for this paper exercise and are not official defaults.

## Three common errors

1. Treating minimum relevance as a permission or entity filter and using it to exclude unrelated stores or unauthorized records. The input to check is the similarity setting; the object of comparison is the permission field and the entity identifier; the condition is satisfied only when a separate authorization step is observed.
2. Associating knowledge bases that use different vector models and then asserting missed recalls or redundant returns on that basis. The input to check is each base's model identifier; the object of comparison is the association requirement; the condition is satisfied only when the identifiers match.
3. Writing a pending-review status as a completed transfer. The input to check is the transfer order status field; the object of comparison is "pending review" against "completed"; the condition is satisfied only when the same order and the same field show a completion record.

## How to verify the setup

1. Input the source material and the draft sentence above, compare the transfer order status field with the wording of the draft sentence, and observe whether the draft sentence presents a pending review as completed. A status mismatch identifies the error.
2. Input the source material above and compare whether the retrieval result covers 1 March to 31 March, order No. 12, and Stores A and B. Any missing element is recorded as unsupported.
3. Input an empty citation array and compare whether the downstream design accepts an output whose length may be 0. The condition is satisfied only when the downstream explicitly handles an empty array; no claim is made that a fictional rule search necessarily returns an empty array.
