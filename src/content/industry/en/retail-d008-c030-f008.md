# Supermarket supplier accounts: workflow routing for multilingual work

## What the documents look like

Supermarket supplier onboarding and settlement revolves around purchase-sale or consignment payables. A supplier does not necessarily operate a staffed counter inside the store, which separates this category from a large-format joint-operation counter. The everyday materials are purchase contracts, delivery acceptance notes, rebate agreements, and reconciliation statements. Data arrives from ERP purchasing, supplier portals, POS sales, and finance systems, with weekly and monthly update rhythms. In cross-border material and multilingual retrieval work, one settlement case may involve a Chinese purchase contract, an English delivery acceptance note, and a rebate agreement in another language. Retrieval has to locate each material by document type and language before workflow routing connects the verification steps.

## Constraints at the workflow routing step

The form input node is a user-interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution waits until the user completes the interaction. After the user fills required fields and submits, the node collects the submitted form information and passes it to subsequent nodes. The user selection node is also a user-interaction node. It likewise enters an interaction state and records workflow state; when the user makes a choice, the node evaluates that choice and executes the corresponding "yes" branch. Both node types only collect values and route branches. Order writing, document backfill, and external status synchronization require a separate business interface or a downstream flow.

If retrieval libraries use different vector models, they cannot be associated together. The model identifier must be checked first, and libraries that do not match are excluded. A relevance score does not perform permission or entity isolation, and retrieval itself does not constitute authorization.

Hypothetical paper exercise sample: A supplier submits an English delivery acceptance note whose text reads "Supplier: A-102. Delivery date: 2025-03-14. Accepted quantity: 480 cartons. This acceptance is subject to the rebate agreement signed on 2025-01-20." A Chinese rebate agreement states that Party A is the supermarket purchasing side and Party B is supplier A-102, with rebates settled quarterly. The draft sentence to be judged is "The accepted quantity of 480 cartons is confirmed, rebates are settled quarterly, and the case may proceed to payment." The comparison scope is limited to these two materials and does not involve a real customer or a legal identity number.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | Comparison and explanation |
| --- | --- | --- |
| Form input node | Enabled, collecting supplier number, acceptance note number, and date | Compare field by field against the delivery acceptance note text |
| User selection node | Enabled, with branches "continue verification" and "return for supplement" | Check whether branch connections correspond to the "yes" branch |
| Retrieval library vector model | Recorded by existing library identifier | Libraries with different models are not associated; check identifiers only |
| Interaction state check | State recorded after trigger, waiting for submission | No separate global state switch is set |
| Output handoff | Collected fields passed to subsequent verification nodes | Compare output against input item by item |
| External operation split | Payment and backfill connect to a separate business interface | Form and selection do not execute payment |

## Three common errors

1. Treating a retrieval hit as authorization. In the hypothetical sample, retrieving the rebate agreement does not mean payment has been approved. Payment still requires a downstream interface and manual verification.

2. Treating a pending review as a missing permission. The phrase "may proceed to payment" in the draft sentence is an unverified statement. The materials do not state an approval status, so this cannot be used to conclude the supplier lacks operating permission.

3. Directly associating libraries across vector models. If the two library identifiers in the sample differ, exclude the non-matching one first and record the actual observation. Do not continue to infer missed recall or redundant results.

## How to verify the setup

1. Input the English delivery acceptance note text and the Chinese rebate agreement from the hypothetical sample. Compare the supplier number, acceptance note number, and date collected by the form input node against the source text. Observe whether the fields are passed to subsequent nodes after submission.

2. Input the draft sentence "The accepted quantity of 480 cartons is confirmed, rebates are settled quarterly, and the case may proceed to payment." Compare this sentence against the two source materials. Observe whether mutually exclusive values appear for the same subject, same period, and same field. When approval status is not stated, record it as pending verification.
