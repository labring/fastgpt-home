# Supermarket supplier accounts: document chunking for multilingual work

## What the documents look like

Supermarket supplier onboarding and settlement centers on purchase-sale or consignment payables. A supplier under this arrangement does not necessarily operate an on-site counter, which separates the category from large-format joint-operation counters. Records arrive from ERP purchasing, the supplier portal, POS sales, and the finance system. The recurring documents are purchase contracts, delivery acceptance notes, rebate agreements, and reconciliation statements, refreshed weekly or monthly.

In a cross-border setting, one batch of material may exist in Chinese and in a second language at the same time. Clauses, item names, accepted quantities, and rebate percentages need to correspond across the two language versions. Document structure differs by type: a purchase contract carries clause hierarchy and an effective scope, an acceptance note carries batch and quantity, a rebate agreement carries percentage conditions, and a reconciliation statement carries period and amount. Chunking has to preserve those structures so that a condition is not separated from the content it governs.

## Constraints at the document chunking step

Parsing starts by checking the source structure and version, and by keeping a document identity that can point back to the original text. Segmentation follows the structure of each document type: conditional sentences in a purchase contract, batch lines in an acceptance note, percentage bands in a rebate agreement, and period totals in a reconciliation statement each form their own group. This keeps explanations attached to their subject.

Original data and retrieval indexes are handled separately. One group of original data can map to multiple indexes, and this multi-vector mapping balances completeness against semantic richness. During retrieval, vectors are recalled first, then the vector ID is used to fetch the original content from the `dataset.datas` table in `MongoDB`. Records that resolve to the same group of original data are merged, and the highest vector score is kept.

Semantic retrieval supports cross-language understanding, so a Chinese question can match material written in another language, which helps cross-border document checking. Full-text retrieval depends on keyword hits and suits numbers, model codes, and proper nouns. Hybrid retrieval combines multiple result paths through `RRF`, and a setting then determines whether `ReRank` performs a second ordering. The minimum relevance value is a filter threshold that takes effect only under semantic retrieval or when result reranking is used. It does not perform permission or entity isolation, and retrieval itself does not constitute authorization.

## Configuration and implementation checks

Hypothetical exercise sample: a purchase contract excerpt between a supplier and a supermarket reads, "This contract takes effect on the date both parties sign, and remains valid until March 31 of the following year; the settlement cycle is monthly settlement with thirty days." The matching delivery acceptance note excerpt reads, "Batch A-07, accepted quantity one thousand two hundred pieces, acceptance date March 5." The draft handover request to be assessed reads, "Based on the above contract and acceptance note, confirm that payment for this batch has entered the current reconciliation period." This request touches three separate facts: signing, acceptance, and reconciliation. Signing does not equal a concluded cooperation, acceptance does not equal completed reconciliation, and retrieving documents does not equal authorization to settle.

| Search mode | Contract clauses and acceptance note numbers coexist | Start with hybrid retrieval, compare number hit rate against semantic retrieval alone |
| Reference limit | Controls returned tokens so long clauses do not crowd out other content | Start at a value covering one contract excerpt plus one acceptance note, compare against a smaller value for omissions |
| Minimum relevance | Filters low-relevance results | Start at a mid-range value, compare against a higher value for whether the acceptance note is dropped |
| Question optimization | Completes references in follow-up turns | Start disabled, compare with enabled for whether "this batch" resolves to A-07 |
| Result reranking | Second ordering when candidates are numerous | Start enabled, compare with disabled for the acceptance note's ordering position |
| Index check | Confirms original data maps to indexes | Check whether the `indexes` field in `dataset.datas` contains the index for this batch |

## Three common errors

1. Treating a successful upload as an updated retrieval index. After material changes, the actual training and index state must be checked. Uploading and retrieval availability are two separate matters.
2. Treating a retrieval result as an authorization basis. Retrieving a contract and an acceptance note does not support a conclusion that reconciliation is complete or that payment can be settled. Business verification and database writes require downstream implementation.
3. Treating minimum relevance as a permission filter. That value is a similarity threshold and does not exclude unrelated business or unauthorized records. Libraries built on different vector models cannot be associated together.

## How to verify the setup

1. Enter the contract excerpt and acceptance note excerpt above, and search for "A-07 accepted quantity." Compare whether the returned content includes the original sentence with batch and quantity, and observe whether the number is pushed out by semantically similar results. The condition is met when that original sentence is hit and the quantity matches.
2. Enter the draft request, "Based on the above contract and acceptance note, confirm that payment for this batch has entered the current reconciliation period." Compare whether the returned content contains only the contract validity period and the acceptance record, and observe whether any statement of completed reconciliation or settlement authorization appears. The condition is met when the return contains only original clauses and no authorization conclusion.
3. Enter an explicit paper input of an empty array `[]`, check the downstream design's handling path for empty results, and observe whether an empty result is converted into a default pass. Record the actual observation without presuming that an empty result necessarily returns `[]`.
