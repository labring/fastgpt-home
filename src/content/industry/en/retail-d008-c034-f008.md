# Export tax rebate filings: workflow routing for multilingual work

## What the documents look like

Export tax rebate filing happens after goods leave the country, and the work is tax-voucher matching rather than customs declaration. The main data sources are the electronic tax bureau, the export rebate filing system, customs electronic messages and the finance ledger. Day-to-day documents include the export tax exemption and rebate filing form, the export customs declaration, purchase invoices and foreign exchange receipt vouchers. Typical roles are foreign-trade enterprise finance staff, tax accountants and documentation clerks. Data updates monthly or per batch; this page does not depend on that frequency.

The difficulty in cross-border material and multilingual retrieval is that one export batch maps to several documents whose languages, numbering systems and issuing parties differ. Workflow routing has to collect retrieval conditions first, then run retrieval, then hand results to human review or a downstream interface. The Form Input node is a user-interaction node: when triggered, the conversation enters an interaction state, the workflow state is recorded, and after the user completes the interaction and submits, the collected values pass to later nodes. The User Selection node is also a user-interaction node; when the user makes a choice, the node evaluates that choice and executes the "yes" branch. Retrieval itself is not authorization, and values collected by a form still need business verification and downstream implementation to carry them forward.

## Constraints at the workflow routing step

This page addresses only workflow routing within cross-border material and multilingual retrieval. Interaction nodes record workflow state, hide the dialog box and wait for the user to finish; the documentation does not provide submission-count control, a global state-recording switch or snapshot guarantees, so no claim is made about them. Retrieval results must be passed explicitly to later retrieval, judgment or interface nodes, and outputs compared against inputs item by item. Order writing, document backfill and external status synchronization require a separate business interface or later process; retrieval and forms cannot perform them directly.

A similarity score is a relevance-ranking basis. It does not act as a permission or entity-isolation filter, and retrieval is not authorization. Sharing one vector model is the precondition for joint association inside one knowledge base; libraries on different vector models cannot be jointly associated. In that case, check identifiers, exclude the non-matching library and record the actual observation. An empty result can be accepted downstream; use an explicit paper input to check the downstream design, and do not claim that a fabricated rule makes retrieval return an empty array. RRF is a hybrid-result fusion process and is not written as an on/off switch. Thinking budget is a reasoning budget and is unrelated to the citation token limit.

Hypothetical drill sample: a foreign-trade enterprise finance staff member submits a batch of export rebate retrieval requests in June 2025. The source text supplied for checking reads: "Export customs declaration No. A0001, export date 15 March 2025, declared amount USD 120,000, domestic consignor Company A." "Purchase invoice No. B0002, invoice date 20 March 2025, amount RMB 840,000, buyer Company A." The draft sentence to be judged reads: "Declaration A0001 and purchase invoice B0002 belong to the same entity and the same export batch, and can proceed to filing data generation." The judgment conditions are: matching entity, connectable period, corresponding document numbers. The source text does not state a foreign exchange receipt voucher or a filing form, so that evidence is missing.

## Three common errors

1. Treating a retrieval hit as authorization approval. The input is declaration No. A0001 collected by the form; the comparison object is the authorization status field. If that field is not stated, record it as pending verification; the retrieval result is not authorization.
2. Jointly associating libraries on different vector models. The input is two knowledge base identifiers; compare the vector model identifiers. If they differ, exclude the library and do not run cross-model retrieval to compare missed recalls.
3. Treating pending review as signed or effective. The input is the phrase "can proceed to filing data generation" in the draft sentence; compare it against the source text. If the source text does not state review, signature or effective status, record the evidence gap.

## How to verify the setup

1. Input the declaration source text and the purchase invoice source text from the hypothetical sample; compare the three fields of entity, period and document number. If the entity matches and the periods connect, the entity and period parts of the draft sentence are satisfied. The foreign exchange receipt voucher and filing form are not stated, so record them as pending verification.
2. Input the paper empty result []; compare it against the downstream branch design. If the downstream branch explicitly accepts an empty result and records the gap, the empty-result handoff configuration is satisfied. Do not claim that a fabricated rule makes retrieval return [].
3. Input two knowledge base identifiers; compare the vector model identifiers. If the identifiers match, joint association is allowed; if they differ, exclude and record the actual observation. Do not invent missed recalls or redundant results after joint association.
