# Export tax rebate filings: model connections for multilingual work

## What the documents look like

Export tax rebate filing happens after goods leave the country, when tax vouchers are matched. The working set includes the export tax exemption and rebate filing form, the export customs declaration, purchase invoices, and foreign exchange receipt vouchers. Finance staff match each customs declaration to its purchase invoice, then generate filing data from that match. Cross-border material commonly carries English product names, overseas entity names, and multilingual documents, so retrieval groups records by the same filing batch. Material updates monthly or per batch, and a document may sit in a pending-verification, pending-supplement, or pending-submission state.

Three facts shape this page. First, voucher matching is the core task, so any retrieval setup must keep one filing batch together rather than mixing batches. Second, source documents arrive in more than one language, so the language model and index model must handle the actual inputs. Third, the filing form, customs declaration, invoice, and receipt voucher each carry a different status, and no status may be inferred from a related document.

## Constraints at the model connections step

Model connection depends on AI Proxy. Both the App and Admin services must set AIPROXY_API_ENDPOINT and a non-empty AIPROXY_API_TOKEN; if either is missing, startup validation fails. The endpoint holds the service root address without an appended /v1. The system needs at least one language model and one index model to operate. A retrieval dataset and its index model must share the same model identifier; datasets built on different vector models cannot be associated together, so the identifier is checked first and non-matching datasets are excluded. A relevance or similarity score does not act as a permission or entity filter, and a retrieval result does not constitute authorization.

Hypothetical drill sample: a document clerk at a foreign trade enterprise submits a paper record. The source text reads: "Export customs declaration number A-2026-0311, export date 11 March 2026, overseas buyer Northwind Trading LLC, product English name Stainless Steel Flask, quantity 2000 pieces; corresponding purchase invoice number INV-2026-0311, invoice date 5 March 2026, supplier a domestic manufacturing enterprise." The draft sentence to be judged is: "This batch of goods has completed foreign exchange receipt and can be submitted for rebate filing." The sample provides no foreign exchange receipt voucher, and the receipt status is not stated.

## Configuration and implementation checks

The table below gives assumed starting points for this page's drill. The values are hypothetical and unrelated to official defaults.

| Configuration or check item | Assumed starting point | Reason and comparison method |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | Assume `http://aiproxy:3000` | Matches the service root address; compare whether `/v1` was appended by mistake |
| AIPROXY_API_TOKEN | Assume a non-empty admin token | Must match the server side; compare whether an application API key was used instead |
| Index model identifier | Assume one index model enabled | Compare with the model identifier used by the retrieval dataset; they must match |
| Language model identifier | Assume one language model enabled | Compare with the capability required by the intended node |
| Multilingual retrieval input scope | Assume limited to this filing batch | Compare with the sample document numbers; exclude other batches |
| Empty-result handling | Assume paper input `[]` checked against downstream | Observe whether downstream treats it as an empty result; no return value is presumed |

## Three common errors

1. Mixing AIPROXY_API_TOKEN with an application API key. Input is the environment variable entry; comparison object is the AI Proxy admin token; observable result is whether startup validation passes.
2. Treating a similarity score as a permission or entity filter. Input is the retrieval request and returned list; comparison object is the sample filing batch and the authorized scope; observable result is whether returned records fall outside that batch.
3. Using the draft sentence to assert completed foreign exchange receipt. Input is the sample source text and the draft sentence; comparison object is whether a receipt voucher is stated; observable result is whether the sentence is supported by the source.

## How to verify the setup

1. Against the sample source text and draft sentence: input is the two source sentences on the customs declaration and purchase invoice plus the sentence to be judged; comparison object is whether the source states a foreign exchange receipt voucher. If the source does not state receipt, the draft sentence is unsupported and the evidence gap is recorded.
2. Against index model consistency: input is the retrieval dataset identifier and the enabled index model identifier; comparison object is whether the two are the same. If the identifiers differ, exclude that dataset and do not run cross-model retrieval.
3. Against empty-result handling: input is the paper input `[]`; comparison object is the downstream node's design for an empty list. If downstream defines no empty-result branch, record it as pending verification and do not claim retrieval must return empty.

This page covers only export tax rebate filing, cross-border material and multilingual retrieval, and model connection and configuration. Retrieval and form entry do not constitute authorization, and no filing, approval, or submission action is asserted here.
