# Multi-warehouse inventory: vector indexes for multilingual work

## What the documents look like

Multi-warehouse order routing decides which warehouse ships an order, and that decision sits before carrier handover. The working materials come from WMS, OMS, ERP stock records and platform inventory interfaces: routing rules, stock synchronization tables, transfer orders and shortage alerts. In cross-border and multilingual retrieval, the same routing rule may be stored in a Chinese source version and an English translation, and a searcher needs to find the matching clause across languages.

This page covers one link only: which materials enter the knowledge base, which index causes them to be recalled, and how recalled content is checked against the source text. The brief gives a daily or hourly update rhythm. That rhythm is not used here to infer scheduled synchronization, full synchronization or transaction-triggered behavior; it only affects when a person chooses to re-check a comparison.

## Constraints at the vector indexes step

Knowledge bases joined in one retrieval must use the same vector model. Check the actual model identifier and the input types it accepts first, exclude knowledge bases that do not match, and record the observation. Do not run a cross-model retrieval to compare missed recalls.

One source data block can be linked to several indexes. Check index content and source content separately. Build index content from complete, focused information, and weigh retrieval coverage against index length using samples. Image retrieval also depends on whether an image description or image vector was generated at ingestion time. Uploading an image on the query side does not create an index.

Semantic recall and the minimum relevance value do not perform permission or entity isolation. The same-vector-model requirement for joined knowledge bases does not extend to external systems. The overall retrieval flow lists optional paths; not every request executes all of them. Image retrieval needs image input and model capability. ReRank needs a model and must be enabled by configuration. An empty citation output can have length 0, and that path still completes, so downstream design must accept an empty array.

Hypothetical paper exercise: a cross-border e-commerce supply chain team stores the Chinese source of the "East China Warehouse Routing Priority Rules (March 2025 version)" and its English translation in separate knowledge bases. The Chinese source states: "When sellable stock at the East China warehouse falls below safety stock, route to the South China warehouse; this rule applies to orders from March 1 to March 31, 2025." The English translation reads: "When sellable stock at the East China warehouse falls below safety stock, route to the South China warehouse." A draft sentence awaits judgment: "Retrieving this sentence from the English knowledge base shows that the English translation fully covers the validity period of the Chinese source." The draft involves a subject (East China warehouse), an object (routing rule), a state (sellable stock below safety stock) and a validity scope (March 1 to 31). Judgment requires comparing whether the English translation states that validity period.

## Three common errors

1. Treating an English translation hit as proof that the Chinese source validity period is covered. Input: the translated sentence returned from the English knowledge base. Comparison: the Chinese source limitation "March 1 to March 31." Observation: whether the English translation states that date range. When the translation does not state it, the draft sentence is unsupported.

2. Treating the minimum relevance value as a permission or entity filter. Input: the threshold setting and one cross-warehouse query. Comparison: whether returned records include data from a warehouse outside the searcher's access. Observation: whether changing the threshold alters the record set. The threshold affects relevance filtering only; it does not change the accessible set.

3. Confusing an ingestion-time image index with a query-side image upload. Input: one image-to-image request and the ingestion record. Comparison: whether an image description or image vector was generated at ingestion. Observation: whether uploading an image on the query side returns that image. When no index was built at ingestion, a query-side upload does not produce a recall for that image.

## How to verify the setup

1. For the hypothetical draft sentence, input the English knowledge base query "East China warehouse safety stock route." Compare whether the returned citation includes the "March 1 to March 31" validity sentence. Observe whether the translation states that range. If it does not, record the draft as unsupported and keep the evidence gap.

2. For the cross-warehouse permission check, input the same question set and one warehouse identifier outside the searcher's access. Compare whether that warehouse's records appear in the returned citations. Observe whether threshold or mode changes alter that appearance. If it appears, record it as a business action requiring a separate system implementation; retrieval alone does not constitute authorization.

3. For empty-result handling, input a paper empty array []. Compare whether the downstream node completes that path as designed. Observe whether an exception is triggered. This check verifies downstream handling only; it does not assert that any retrieval rule returns an empty array.

All three checks record actual observations. No test, deployment, approval or refund is claimed to have occurred.
