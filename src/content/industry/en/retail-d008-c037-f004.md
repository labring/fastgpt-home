# Peak-sale fulfillment: vector indexes for multilingual work

## What the documents look like

Peak-sale warehouse and delivery scheduling revolves around short-term peak capacity and the arrangement of people, vehicles and space. Materials update on a per-campaign and daily rhythm. The peak forecast table states a peak interval, the staffing roster and the courier support plan carry the execution terms, and the exception daily report records that day's deviations. Cross-border materials and multilingual retrieval must handle Chinese forecast tables, foreign-language support plans and multilingual exception descriptions at the same time, and the retrieval entry point must be able to reach the same set of materials across languages.

The subject, object and status of these materials are often spread across separate documents. A retrieval result can only present the source text. Whether a document has been authorized, and whether a request has been approved, must be confirmed separately in the corresponding business step.

## Constraints at the vector indexes step

Knowledge bases joined in one retrieval must use the same vector model. Check the actual model identifier and input type first; knowledge bases with different vector models cannot be associated together. A single source data block can be linked to multiple indexes, and the index and the source content are checked separately. Index content should be complete and focused, and retrieval coverage against index length must be weighed against the sample. Image retrieval also depends on whether an image description or image vector was generated at ingestion time; uploading an image on the query side alone does not guarantee a hit.

Semantic recall and relevance values do not carry authorization or entity-isolation duties. The minimum relevance is a filtering threshold and takes effect only under semantic retrieval or when result reranking is used. After question optimization, hybrid retrieval, image retrieval or result reranking is enabled, the final result may pass through multi-path recall fusion. RRF is the fusion process for hybrid retrieval results, not a standalone switch. The reference cap is measured in tokens, and an empty-result output can have length 0 while that path still completes.

Hypothetical drill sample: in one set of peak-sale warehouse and delivery scheduling materials, the source text provided for checking consists of three sentences: "The peak forecast for this campaign is concentrated between 20:00 and 23:00 on the first day of the event." "The temporary staffing roster has been signed by the warehouse manager, effective on the first day of the event." "The courier support plan is still pending review, and the carrier's vehicle count has not been finalized." One draft sentence to be judged is: "The courier support plan has confirmed the vehicle count and can be executed according to the roster." The scope of judgment is limited to the three source sentences above, and the authorization boundary is limited to the roster signed by the warehouse manager; the courier support plan is outside the authorized scope.

## Configuration and implementation checks

The configuration is built around the sample above and lists only settings already described in the official material or implementation checks. The values in the table are starting points for this hypothetical trial, used to compare against the cited source text under the same set of questions; they are not official defaults.

| Configuration item | Hypothetical starting point for this trial | How to check |
| --- | --- | --- |
| Associated knowledge bases | Include only bases using the same vector model identifier | Check the model identifier and input type first, and exclude those that do not match |
| Search mode | Hybrid retrieval | Observe semantic recall and full-text recall candidates together on the multilingual sample |
| Reference cap | Set as a token amount covering the three source sentences of the sample | Compare with the source sentence length and observe whether citations are truncated |
| Minimum relevance | Take a middle value between 0 and 1 for this trial | Compare with semantic retrieval or rerank scores and observe whether low-scoring items are filtered out |
| Result reranking | Enabled per settings, requires a rerank model | Compare candidate order and 0-1 scores before and after reranking |
| Index check | Check each block's index against the source content | Compare index text with the source and confirm whether an image index was generated at ingestion |

## Three common errors

1. Treating a retrieval hit as authorization confirmation. In the sample, the courier support plan is pending review; retrieval can return that source sentence, and the returned result does not mean the plan has been approved or the vehicle count confirmed. When checking, compare the retrieval output against the signing and review status fields; pending review does not constitute an execution basis.
2. Associating knowledge bases with different vector models. If a base with another model identifier is mixed into the sample, the check should first compare each base's model identifier, exclude those that do not match, and record the actual observation. Do not run cross-model retrieval to compare missed recalls.
3. Treating a similarity score as an entity or authorization filter. Minimum relevance filters only by score and does not distinguish subject or authorization scope. When checking, compare the filtered-out items against the source text of the sample and confirm that the filter acts only on score and does not carry business isolation.

## How to verify the setup

1. Input the three source sentences of the sample above and the draft sentence, and compare "has confirmed the vehicle count" in the draft against "pending review, and the carrier's vehicle count has not been finalized" in the source. The source values for the same field are mutually exclusive, the draft sentence is unsupported, and this should be recorded as pending verification rather than written as a denial or conflict.
2. Input the source text of the sample and a base with the same vector model identifier, and compare the cited source text returned by retrieval against the three sample sentences. The expectation is that cited content comes from the sample scope. If content outside the scope appears, record that observation and check the correspondence between index and source.
3. Input an explicit paper empty result `[]` and compare whether the downstream path completes. An empty-result output can have length 0 and the path still completes; do not infer from this that retrieval for a fabricated rule will necessarily return `[]`. If retrieval does not return the sample source text, record it as a miss, check whether the data has finished training and whether the question lacks a subject, and do not promise a first-hit or full recall.
