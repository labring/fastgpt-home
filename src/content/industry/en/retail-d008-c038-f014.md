# Fresh-food concession counters: model connections for multilingual work

## What the documents look like

Fresh-food concession counters in hypermarkets are frequently run on site by a supplier, with revenue shared between the store and that supplier. The working papers for this category are the concession contract, the daily sales report, the shrinkage (loss) sheet, and the food incoming inspection record. In cross-border and multilingual retrieval work, these materials may carry foreign supplier names, foreign delivery notes, or bilingual contract clauses. Daily sales reports and shrinkage sheets are produced per day or per batch, and the incoming inspection record is formed as each batch arrives. Reconciling weighed sales, handling shrinkage allocation, and checking incoming purchase evidence are the three time-consuming steps, and any retrieval result has to be taken back to these source materials to check the party, the batch, and the status.

## Constraints at the model connections step

Concession suppliers may operate under foreign names, so the party descriptions in contracts, delivery notes, and inspection records need to be aligned across languages. At model connection time, the system needs at least one language model and one index model before it works normally. Multilingual retrieval depends on the index model building vectors for text chunks, and a retrieval result expresses similarity only; it does not carry permission or entity isolation duties. When configuring a model channel, the proxy address field takes a BaseUrl, not a complete model request address, and the model ID stays consistent with the model in the channel. Model status probing covers only system models that are currently enabled; disabled models do not take part in probing and produce no history.

Hypothetical paper exercise sample: a store fresh-food department receives a paper submission from a concession supplier. The text reads: "The shrinkage sheet for this counter for last month has been signed and confirmed by the on-site staff, and the shrinkage amount is allocated according to the ratio in Annex 3 of the contract. One daily sales report is attached, batch number 2024-05-18-A." A separate handover request awaits a decision: "Please confirm, on the basis of the above materials, that the shrinkage allocation has taken effect, and authorize deduction from this month's payment." The signature confirmation and the allocation ratio are contents stated in the materials; the deduction authorization is a separate business action, and the materials do not state an authorization clause.

## Three common errors

1. Treating a retrieval result as an authorization basis. The input is the shrinkage sheet and handover request in the hypothetical sample; the comparison is whether the materials state a deduction authorization clause; the observable result is that the materials state only signature confirmation and an allocation ratio, with no deduction authorization. Reading a similar retrieval hit as granted authorization is an error.
2. Treating a pending-review status as a completed signature. The input is the wording "signed and confirmed by the on-site staff" in the hypothetical sample; the comparison is whether the materials state the signing party, the signing date, and the conditions for taking effect; the observable result is that the materials state none of these fields, so the status remains to be verified.
3. Associating libraries that use different vector models. The input is two retrieval library identifiers that use different index models; the comparison is whether the index model identifiers of the two libraries match; the observable result is that when the identifiers differ, the libraries cannot be associated together, and only the actual observation is recorded, without inferring missed recall or redundant results.

## How to verify the setup

1. Input the hypothetical sample text and the handover request; compare the contents stated in the materials against the authorization wording in the request; the observable result is that the materials state no deduction authorization clause, so the request is recorded as unsupported and the evidence gap is retained.
2. Input batch number 2024-05-18-A from the hypothetical sample together with the daily sales report; compare whether the batch number on the report matches the batch number on the shrinkage sheet; the observable result is that a match places both in the same batch, while a mismatch is recorded as pending verification.
3. Input a clearly labelled hypothetical empty result `[]`; compare how the downstream design handles an empty result; the observable result is that the downstream treats it as an empty result, without claiming that a fictional rule retrieval always returns `[]`.
