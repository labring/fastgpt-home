# Tmall flagship operations: vector indexes for multilingual work

## What the documents look like

Daily Tmall flagship store operations handle cross-border materials and multilingual retrieval across four recurring document types: product publishing pages, brand authorization letters, delivery commitment records, and after-sales work orders. These materials mix Chinese product titles, English authorization clauses, and multilingual customer service exchanges, so retrieval frequently has to match across languages rather than within one. Brand authorization and flagship store identity require traceable sourcing. When a retrieved citation points at the wrong authorization text, the documented consequences include product delisting, delayed-shipment compensation, and a drop in store rating. Materials update daily and per order, and any index rebuild scope should correspond to the actual ingestion batch rather than an assumed full refresh.

The operational focus here is narrower than the category as a whole: this page addresses the vector model and index conditions that apply when cross-border materials and multilingual retrieval run against a knowledge base, and the checks an operator can perform on the documents themselves.

## Constraints at the vector indexes step

Knowledge bases selected together for retrieval must use the same vector model. Before associating them, confirm the actual model identifier and the input type each base accepts. Bases built on different vector models cannot be associated together; the correct action is to compare identifiers, exclude the mismatched base, and record what was observed. Retrieval itself is not authorization, and a similarity score is not a category, entity, or permission filter. A low score does not exclude an unauthorized record, and a high score does not grant permission to act on one.

A single original data block can map to multiple indexes. Index text and original text are checked separately. Index content should be complete and focused; retrieval coverage and index length need to be weighed against actual samples rather than assumed. Image retrieval depends on whether image descriptions or image vectors were generated at ingestion time, so query-side behavior alone does not determine whether an image can be found. Mixed retrieval merges multiple result paths through RRF, which is a fusion process rather than a switch to enable. Reranking requires a rerank model and must be enabled according to configuration. The reference limit is counted in tokens, and the minimum relevance threshold applies only under semantic retrieval or result reranking.

Hypothetical paper exercise sample. The source text to be checked reads: "This authorization letter is issued by Brand Party A to Store B, valid from January 1, 2025 to December 31, 2025, covering the Tmall channel in mainland China." The draft sentence awaiting judgment reads: "Store B's authorization covers cross-border sales in March 2026." The source text does not state any 2026 authorization. The draft sentence is unsupported, and the evidence gap must be recorded rather than filled by inference.

## Configuration and implementation checks

| Configuration item | Hypothetical trial starting point | How to check and compare |
| --- | --- | --- |
| Vector model | Same model identifier | Check each base's model identifier and input type; exclude bases that differ |
| Index content | Complete authorization paragraph | Compare index text against the source paragraph for consistency |
| Image index | Generated at ingestion | Check ingestion records for image description or image vector |
| Search mode | Mixed retrieval | Observe recall separately for identifier-type and natural-language questions |
| Minimum relevance | 0.3 for this trial | Compare citations before and after filtering; confirm the threshold only filters |
| Reference limit | 2000 tokens for this trial | Compare citation length before and after trimming; confirm the unit is tokens |

The numeric values above are hypothetical trial starting points chosen to make filtering and trimming behavior observable. They are compared against adjusted citation output, not treated as official defaults.

## Three common errors

1. Treating a semantic retrieval score as a permission filter. The error is concluding that a low similarity score excludes an unauthorized record. Check: submit the same question, compare score values against the authorization status field, and observe that the score does not change the authorization determination.

2. Treating RRF as a toggle. The error is searching configuration for an RRF switch. Check: review the configuration item list, compare whether such a switch exists, and observe that mixed retrieval merges results through the documented flow.

3. Associating knowledge bases across different vector models. The error is selecting bases with different models together. Check: review each base's model identifier, compare whether identifiers match, exclude the mismatched base, and record the observation.

## How to verify the setup

1. Input the hypothetical sample source text and the draft sentence. Compare whether the 2026 authorization described in the draft appears in the source. When the source does not state it, the draft is unsupported, and the evidence gap is recorded.

2. Input a retrieval question containing the authorization period. Compare whether the returned citation points to that source paragraph. The condition is satisfied when citation content matches the source. An empty result is checked against a paper input of [] to confirm downstream design handling.

3. Input an image query. Compare whether ingestion records contain an image description or image vector. When the corresponding index is absent, record it as not established rather than inferring that retrieval must fail.
