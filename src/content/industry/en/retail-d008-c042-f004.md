# Product listing reviews: multilingual work with vector indexes

## What the documents look like

For multilingual work in Product listing reviews, this page examines FastGPT vector indexes. Trace intended use and compatibility subjects without introducing performance or certification into translated entries. The examples are hypothetical.

## Constraints at the vector indexes step

A hypothetical product specification says that a dust cover is for storage and must be removed during operation. The English test counterpart retains both instructions. A separate compatibility note states only that a housing fits a particular equipment model; it provides no operating-performance statement. A proposed entry saying dust cover for operation has already changed the use described by the original; retrieving that entry cannot validate its added claim. Inspect the verbs and the subjects: a compatible housing does not establish that a cover may remain in place while equipment runs. These are ordinary example labels, without a product safety assessment or certification result.

## Configuration and implementation checks

| Product-language check | Original subject | Evidence to inspect |
| --- | --- | --- |
| Use boundary | Dust cover for storage | Retain removal during operation. |
| Compatibility subject | A housing fits a particular equipment model | Distinguish that fit from the cover’s storage use. |
| English entry | Proposed for operation wording | Trace the operating use to an actual original. |
| Performance evidence | Compatibility note lacks performance claims | A fit statement is not performance or certification evidence. |
| Additional instructions | The same cover and model | Check identity before repeating citation comparisons. |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Embedding model` | Knowledge bases associated with one search node must use the same embedding model. |
| `Original data and indexes` | One original data block can have multiple indexes. |
| `Index content` | Index wording should be complete and focused. |
| `Image indexes` | Where image retrieval is used, inspect descriptions or image vectors. |
| `Version and result check` | After a change, reuse questions to compare originals. |

## Three common errors

- If an index changes storage use into operating protection, compare both use statements with the proposed entry to locate the added operating scenario.

- If a statement that a housing fits a model becomes whole-device performance, trace the housing, model and stated relationship. Fit alone establishes neither whole-device performance nor use of the cover during operation.

- If removal before operation disappears from the answer, compare the candidate passage, actual citation and response to locate the omitted instruction.

## How to verify the setup

Ask in both languages about use, compatibility and removal, comparing the sentences actually retrieved. When another use document is supplied, check that it covers the same cover and model before repeating the questions. Later receipt alone does not supersede an earlier restriction. Multiple entries should point to the original data supporting their wording. An index hit establishes neither translation approval nor a compliance review. Check embedding consistency where one search node associates the relevant bases, while inspecting citations for the actual cross-language queries. This exercise certifies no product and makes no safety decision.
