# Product listing reviews: model connections for multilingual work

## What the documents look like

Platform product title and detail compliance work deals with advertising truthfulness and qualification display, and it does not handle parcel delivery. The everyday materials are a product title table, detail page assets, a prohibited advertising words list, and quality inspection reports, drawn from platform rule centers, advertising law compliance lists, brand asset libraries, and inspection body reports. Cross-border materials and multilingual retrieval place Chinese titles, foreign-language detail assets, and the prohibited words list into one knowledge base so that product operations, legal compliance, and artwork reviewers can search by language and by launch batch. Materials update weekly and at each new launch. This page checks language, batch and source correspondence; the synchronization method has not been provided.

## Constraints at the model connections step

Multilingual materials require an index model that handles text in different languages and a language model that produces review opinions in the target language. FastGPT connects to model providers through AI Proxy, and the system needs at least one language model and one index model to work normally. App and Admin must set AIPROXY_API_ENDPOINT and a non-empty AIPROXY_API_TOKEN; missing either one causes startup validation to fail. AIPROXY_API_ENDPOINT takes the service root address without an appended /v1. Model channels are configured on the administrator model provider page, and channel testing outputs each model's test result and request duration. Model probing covers only currently enabled system models; after a first failure it retries at most 3 times, and only when all 4 attempts fail is the model finally judged abnormal. Retrieval results reflect text similarity only and carry no permission or entity isolation. Only libraries on the same vector model can be associated together; when vector models differ, check the identifier first and exclude the non-matching library.

Hypothetical drill sample: in one cross-border launch batch, the title table source text reads "This product uses imported raw materials and has passed EU standard testing," the detail page asset source text reads "Suitable for all skin types, no irritation whatsoever," and the prohibited advertising words list source text records "absolute, 100% effective, no side effects whatsoever" as prohibited. The draft sentence to be judged is "This product has no side effects whatsoever and suits all skin types." The object of checking is this batch's materials, that draft sentence, and the prohibited words list; the scope is limited to this launch batch; the authorization boundary is compliance reviewers viewing and annotating, and it excludes external publication.

## Configuration and implementation checks

| Configuration item | Assumed trial starting point | Checking method |
| --- | --- | --- |
| AIPROXY_API_ENDPOINT | Assume http://aiproxy:3000 | Compare against the documented requirement and confirm no /v1 is appended |
| AIPROXY_API_TOKEN | Assume a non-empty administrator token | Compare against the AI Proxy server configuration for consistency |
| Index model | Assume one multilingual index model enabled | Confirm on the model test page that this model passes testing |
| Language model | Assume one language model enabled | Confirm on the model test page that this model passes testing |
| Probe interval | Assume 30 minutes | Compare against the documented supported integer range of 5 to 60 minutes |
| Knowledge base scope | Assume only this batch's materials are included | Check whether the retrieval scope contains other batches or unauthorized records |

The starting values are used only for this paper drill to make the comparison objects clear, and they are not official defaults.

## Three common errors

1. Entering AIPROXY_API_ENDPOINT as a full request address with /v1, which causes startup validation or calls to fail. Check the string entered for this variable and compare whether it contains only protocol, host, and optional port; the presence of /v1 fails the check.
2. Treating a similar fragment returned by retrieval as having passed compliance review. Check the text block returned by the query and compare whether it contains words listed in the prohibited words list, such as "no side effects whatsoever"; a hit shows similarity only, and the review status remains pending verification.
3. Associating material libraries on different vector models and then comparing recall results directly. Check the vector model identifier of each library and compare whether they match; when identifiers differ, exclude that library and do not run a cross-model comparison.

## How to verify the setup

1. Input the draft sentence "This product has no side effects whatsoever and suits all skin types" from the hypothetical sample together with the prohibited words list source text, and compare whether the draft sentence contains a prohibited word listed in the list. The appearance of "no side effects whatsoever" means the draft sentence conflicts with the list and needs manual review.
2. Input the title table source text "has passed EU standard testing" from the hypothetical sample together with the quality inspection report fields, and compare whether the report states the corresponding test conclusion and its valid scope. When the report does not provide that conclusion, record it as unsupported and do not judge it false.
3. Input the empty result [] together with the downstream handover request "please mark this batch as compliance passed," and compare whether the request carries a reviewer signature and an effective date. When both are missing, the request stays in a pending verification state, and the retrieval result does not constitute authorization to execute.

All of the above is paper checking; no deployment or testing took place.
