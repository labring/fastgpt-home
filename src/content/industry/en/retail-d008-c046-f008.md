# Marketplace category access: workflow routing for multilingual work

## What the documents look like

Category access review happens before a listing goes live or a store is onboarded. The object of review is the operating entity's qualification and the chain of authorization, not the store's service history. The material set for this category is a business license, a trademark registration certificate, a brand authorization chain, and any industry license. These documents come from platform recruitment pages, the national enterprise credit information disclosure system, trademark office data, and license systems. Updates are irregular and tied to each onboarding event.

In cross-border work the same material can exist in several language versions. Retrieval therefore has to handle certificate names, entity names, and authorization wording across languages at the same time. A single authorization chain may name the licensor, the licensee, a trademark number, a class of goods, a term, and a nature of authorization, and each of those fields can be phrased differently across versions.

## Constraints at the workflow routing step

The form input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. The node collects the information the user fills in and passes it to later nodes. The user selection node is also a user interaction node. When the user makes a choice, the node evaluates that choice and executes the "yes" branch. Both nodes can be added repeatedly and are trigger-executed.

Retrieval and form collection do not constitute authorization. A form collects values. Business verification, approval, database writes, and external synchronization require a separate business interface or a later process. A relevance score is not a category filter, an entity filter, or a permission filter. Retrieval is not authorization.

Hypothetical drill sample: an onboarding specialist submits a brand authorization chain. The source text reads: "Licensor: A Brand Management Co., Ltd.; Licensee: B Trading Co., Ltd.; Licensed trademark: No. 12345678; Licensed class: Class 25 clothing; Term: 1 January 2024 to 31 December 2026; Nature of authorization: ordinary authorization." The proposed determination sentence reads: "B Trading Co., Ltd. has obtained an exclusive authorization for Class 25 clothing." The proposed sentence and the source text take different values on the same field, the nature of authorization. This is a mutually exclusive pair of values on one field.

## Configuration and implementation checks

| Configuration item | Setting or check on this page | Note |
| --- | --- | --- |
| Form input node | Enters interaction state on trigger; collects required information | Information passes to later nodes after submission |
| User selection node | Executes the "yes" branch after the user makes a choice | Verify each branch connection individually |
| Interaction state check | Recorded state is behavior of interaction nodes | No separate global state-recording switch is set or claimed |
| Output handoff check | Collected information is passed explicitly to a later retrieval, judgment, or interface node | Compare output and input item by item |
| External operation separation | Order writes, document backfill, external status synchronization | Require a separate business interface or later process |
| Retrieval scope check | Verify the target library's vector model identifier | Libraries on different vector models cannot be associated together |

Hypothetical trial starting point for this page: the comparison threshold for the nature-of-authorization field is set to "exactly identical." This value is chosen because ordinary authorization and exclusive authorization must be distinguished. The comparison objects are the source text's value for nature of authorization and the proposed sentence's value for that same field.

## Three common errors

1. Treating an authorization term collected by the form as proof that the authorization is already in effect. The form input node collects the value the user entered. Whether the authorization has taken effect requires checking the signing and effectiveness clauses. When those are absent, record the gap.
2. Treating a retrieved authorization-chain record as a permission credential. Retrieval obtains information and does not perform authorization or entity isolation. A similarity score does not constitute a category filter or a permission filter.
3. Treating execution of the user selection node's "yes" branch as completion of a business approval. The user selection node evaluates the user's choice and executes a branch. Approval requires a separate business interface or a later process.

## How to verify the setup

1. Input the hypothetical sample source text and the proposed determination sentence, and compare the value of the nature-of-authorization field. The source text gives "ordinary authorization" and the proposed sentence gives "exclusive authorization." The same field carries different values, so the pair is contradictory and the proposed sentence is not supported.
2. Input an authorization-chain document that lacks the authorization term field, and check whether a downstream node passes the missing field onward as a verified value. If the downstream node uses the missing value as a valid term, the evidence gap has not been preserved.
3. Input one retrieval request and observe whether the returned results include records outside the target library. If records from a library on a different vector model appear, check the library identifier and exclude the non-matching ones, and record the actual observation. Do not infer missed recall or redundant results.

A paper input of an explicitly empty list can be used to check downstream handling of an empty-reference output. This does not assert that a fictional rule returns an empty list. Libraries on different vector models cannot be associated together; verify the identifier first and exclude non-matching libraries rather than running a cross-model retrieval to compare recall. Optional paths in a general workflow diagram do not mean every path executes on every request. Image retrieval requires a corresponding image input and model capability, and reranking requires a model and must be enabled according to its settings. The thinking budget is a reasoning budget and is not a citation token limit.
