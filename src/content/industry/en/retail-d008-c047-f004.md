# Marketplace returns: multilingual work with vector indexes

## What the documents look like

For multilingual work in Marketplace returns, this page examines FastGPT vector indexes. Follow application, dispatch and merchant receipt separately from the refund record. The examples are hypothetical.

## Constraints at the vector indexes step

A hypothetical return application covers the main item and leaves gift handling awaiting the merchant’s reply. A logistics extract records handoff to the carrier, while no merchant receipt is supplied. The English counterpart must keep handed to carrier at the dispatch stage. Naming a return item in an application establishes neither its shipment nor acceptance by the merchant. Entries for whether both main item and gift were received should preserve the application’s scope and point to corresponding receipt evidence. The main item’s transport record cannot supply a missing gift-handling decision. These are invented text inputs without real return or payment records.

## Configuration and implementation checks

| Return-language check | Hypothetical original | Inspection |
| --- | --- | --- |
| Application scope | Main item; gift reply pending | Preserve the items separately. |
| Transport event | Handoff to the carrier only | Inspect event subject and destination receipt evidence. |
| Merchant receipt | Not currently supplied | Add no merchant-received state through indexing. |
| Gift handling | Awaiting the merchant’s reply | Do not reuse the main item’s transport conclusion. |
| Refund evidence | Separate payment-processing record | Cite receipt and refund status independently. |

| `Embedding model` | Knowledge bases associated with one search node must use the same embedding model. |
| `Original data and indexes` | One original data block can have multiple indexes. |

## Three common errors

- If a carrier handoff becomes merchant receipt in an English index, compare the logistics event with the receiving party and inspect whether destination receipt evidence exists.

- If transport of the main item becomes receipt of the gift as well, inspect application scope, the pending gift reply and item-specific records. One item’s event does not cover the group.

- If a receipt-related hit becomes a completed refund, inspect the actual refund source. Receiving goods and processing payment need separate evidence.

## How to verify the setup

Ask in both languages about application scope, shipment stage, gift handling and the basis for any refund statement. Trace each actual citation. When a merchant receipt arrives, check which item it covers; check the corresponding matter separately when refund evidence arrives. Several entries for one original should preserve event subjects without compressing stages through translation. Inspect actual embedding consistency for the bases associated within one search node. Retrieval settings confirm no physical receipt and complete no refund. Keep missing records visible instead of substituting a transport extract.
