# Douyin storefront operations: model connections for multilingual work

## What the documents look like

Douyin storefront shelf operations centre on product cards and store experience scores. The working material comes from the Douyin store workbench, the Douyin e-commerce learning centre, Selected Alliance data, and logistics interfaces. For cross-border material and multilingual retrieval, the documents in scope are product qualification pages, experience score breakdowns, shipping violation appeals, and store announcements. Updates arrive daily and per order. Retrieval only checks against material that already exists; it does not create batch synchronisation or transaction-triggered mechanisms.

Product qualification pages often carry multilingual fields alongside source notes. Before model connection, confirm that both an index model and a language model are enabled. The system needs at least one language model and one index model to work normally. Model ID is the value of the `model` field in the request body and is globally unique. The model name is display-only and can be customised. Channel tests and model tests send real requests and are used for an initial check that a model works.

## Constraints at the model connections step

From V4.17.0, AI Proxy is a required dependency. Both App and Admin must set `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN`; missing either causes startup validation to fail. `AIPROXY_API_ENDPOINT` takes the service root address without `/v1` appended. Legacy OpenAI environment variables and single-model custom request addresses cannot replace these two settings. A custom request address and key can bypass a model channel, and the documentation does not recommend this because it is harder to manage.

Model probing covers only system models that are currently enabled. Disabled models do not participate and produce no history. A probe round retries a failed request up to three times, so a single round makes at most four attempts; only when all four attempts fail is the model judged abnormal. A successful call with latency at or below 30s is normal, above 30s is high latency, and four consecutive failed requests is abnormal. Model call logs are kept for one hour, configurable through an environment variable.

Retrieval is not authorisation. Whether a qualification page, experience score breakdown, shipping appeal, or store announcement sits inside an accessible target retrieval scope is a separate manual check. A relevance score does not act as a category, entity, or permission filter, and it does not exclude unrelated businesses or unauthorised records.

## Three common errors

1. Filling `AIPROXY_API_ENDPOINT` with a full model request address and appending `/v1`. The document requires the service root address without `/v1`; an appended path does not match the expected request path.
2. Replacing the two required AI Proxy settings with legacy OpenAI environment variables or a single-model custom request address. The document states these cannot substitute, and startup validation fails when either required item is missing.
3. Reading the model probe scope as covering all models. The document states probing covers enabled system models only; disabled models do not participate and produce no history.

## How to verify the setup

The checks below use one hypothetical paper case. Hypothetical paper case: a product qualification page reads, in substance, "Subject: a certain trading firm; Object: a certain insulated cup; Status: qualification page submitted, under review; Valid scope: 1 January 2026 to 31 December 2026." The draft sentence to be judged is: "This product qualification has passed review and can be used for cross-border material retrieval." Subject, object, period, and field all align with the source text.

1. Input the draft sentence and the source text, and compare the values "under review" and "passed review" in the same field. The source status is under review while the draft says passed review; these two values are mutually exclusive, so the draft is unsupported.
2. Input the hypothetical `AIPROXY_API_ENDPOINT` value and compare whether it ends with `/v1`. If it ends with `/v1`, it does not match the document requirement and needs to be changed to the service root address.
3. Input the model probe result and compare the attempts in one round against the four-attempt ceiling, and whether the status changed from non-red to red. Only four failed attempts produce an abnormal judgement; a continuing abnormal state does not trigger a repeated push.

This page addresses one scope only: Douyin storefront shelf operations, cross-border material and multilingual retrieval, model connection and configuration. It does not treat retrieval or a form as an authorisation action. Where a field is not stated in the source material, or where only related-stage evidence exists, the finding is unsupported or pending verification. Material under review does not establish that an operation permission is absent.
