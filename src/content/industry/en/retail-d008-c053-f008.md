# Channel receivables: workflow routing for multilingual work

## What the documents look like

Channel receivables collection happens after credit sales, where the central concerns are the credit line and cash recovery. The daily materials are the accounts receivable aging table, the collection letter, the credit agreement, and the shipment freeze notice. Data arrives from the finance system, bank receipts, distributor orders, and sales contracts. In a cross-border setting, one receivable can appear in a Chinese credit agreement and a foreign-language statement of account at the same time. Materials update weekly or monthly, and retrieval has to map documents in different languages onto the same receivable.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state and the workflow state is recorded; after the user completes the required fields and submits, the node collects the submitted form information and passes it to later nodes. The User Selection node is also a user interaction node. When the user makes a choice, the node evaluates that choice and executes the "yes" branch. Both nodes can be added repeatedly and trigger execution.

In cross-border multilingual retrieval, the language preference, receivable number, or period range collected by an interaction node serves only as input to later retrieval and judgment. It does not confirm receivable ownership, credit status, or freeze authority. The vector model identifier of each retrieval library must be checked one by one; libraries built on different vector models cannot be associated together. A relevance score does not perform entity isolation or permission filtering. Order writes, document backfill, and external status synchronization require a separate business interface or a later process.

Hypothetical paper exercise sample: a credit agreement reads "Party A grants Party B a credit line of CNY 800,000, payment term sixty days, valid from 1 January 2024 to 31 December 2024." A foreign-language statement of account reads "Invoice No. A-107, due 2024-03-15, amount CNY 120,000, unpaid." The draft sentence to be assessed is "Party B has exceeded the credit line and shipment should be frozen immediately." This draft sentence lacks the cumulative receivable balance as of a given date, so it cannot be compared with the CNY 800,000 line. Freezing shipment is a business action that a later process must execute.

## Configuration and implementation checks

| Configuration item | Value or check content | Relation to the sample |
| --- | --- | --- |
| Form Input node | Collect receivable number, period range, language preference; pass to the retrieval node after submission | A-107 and March 2024 can serve as input in the sample |
| User Selection node | Execute the "yes" branch after the user chooses; verify branch connections one by one | Used to confirm whether statement retrieval continues |
| Interaction state | Record state after the interaction node triggers; wait for the user to complete interaction | The sample draft sentence is assessed only after interaction completes |
| Retrieval library vector model identifier | Check each library model identifier, exclude non-matching ones, and do not run cross-model retrieval comparison | The Chinese agreement and foreign statement must have identifiers checked first |
| Output handoff | Pass collected information explicitly to later retrieval, judgment, or interface nodes | Assessment of the draft sentence depends on retrieval results reaching the judgment node |
| External operation split | Order writes, document backfill, and external status synchronization connect to a separate business interface | Shipment freeze is not executed inside this page's nodes |

## Three common errors

1. Treating the receivable number collected by the Form Input node as confirmation of receivable ownership. Input is A-107 in the sample; the comparison object is the credit agreement principal and the statement of account header; the observable result is whether the two principals match. When they do not match, record it as pending verification and do not enter the freeze judgment.
2. Treating the "yes" branch of the User Selection node as authorized execution. Input is the sample draft sentence; the comparison object is the credit line in the agreement and the amount on the statement; the observable result is whether cumulative receivables exceed CNY 800,000. When the cumulative balance is missing, record the evidence gap.
3. Treating a relevance score as permission or entity filtering. Input is the score returned by retrieval; the comparison object is the receivable number and period fields; the observable result is whether the returned record belongs to the same receivable. The score itself does not exclude unrelated records.

## How to verify the setup

1. Input the sample credit agreement text and the statement of account text; compare the principal names and receivable numbers in the two materials; observe whether the retrieval result contains both materials. If only one is returned, record it as unsupported.
2. Input the sample draft sentence "Party B has exceeded the credit line and shipment should be frozen immediately"; compare the credit line of CNY 800,000 with the statement amount of CNY 120,000; observe whether a cumulative receivable balance as of a given date exists. When that balance is missing, the draft sentence is assessed as pending verification.
3. Input an explicit paper empty result `[]`; compare whether the downstream judgment node handles it according to its empty-input design; observe whether an unconfigured automatic business action appears downstream. If one appears, record it as requiring separate interface implementation.
