# Channel receivables: document chunking for multilingual work

## What the documents look like

Channel receivables collection begins after credit sales. The work centres on credit limits and cash recovery rather than on matching buyers and sellers. The documents handled in this category include the receivables ageing table, the collection letter, the credit agreement, and the shipment freeze notice. These come from the finance system, bank receipts, distributor orders, and sales contracts. In cross-border work, the same batch of material may contain Chinese, English, and the language of the distributor's region at the same time. The ageing table is updated weekly or monthly.

For document parsing and chunking, this mix matters. Structured fields such as ageing brackets, credit limits, and freeze conditions sit alongside paragraph text such as collection letter bodies and agreement clauses. Parsing and chunking need to keep these two kinds of content usable, so that retrieval can hit an exact identifier and also follow a natural language description.

## Constraints at the document chunking step

When multilingual material enters one knowledge base, semantic retrieval can match across languages, but chunk quality directly shapes recall precision. According to the official documentation, a segment should keep its structure and meaning complete and carry a single topic. One group of source data can map to several indexes, and a shorter, more precise index content usually raises retrieval precision while narrowing retrieval range. Full-text retrieval suits exact queries such as identifiers, model numbers, and proper nouns. Semantic retrieval suits natural language questions. Hybrid retrieval merges multiple result paths through RRF, and a ReRank model can reorder candidate text and produce a score from 0 to 1. The reference cap is measured in tokens. The minimum relevance value takes effect only in semantic retrieval or when result reordering is used. Both are filtering and trimming controls. Neither carries permission or entity isolation. Knowledge base search operates at the library level, and a collection serves only as a classification unit.

Hypothetical paper exercise sample: a brand finance staff member prepares an excerpt of a distributor credit agreement. The source text reads: "The credit limit under this agreement is RMB 800,000, and the payment term is sixty days from the shipment date. If the ageing exceeds sixty days and no written repayment plan has been received, subsequent shipments may be suspended." A separate handover request awaits a decision: "Please confirm that this distributor's credit limit is RMB 1,000,000 and that shipment suspension has been agreed." The check compares the amount value, the ageing condition, and the suspension trigger state between the agreement source text and the request, and judges whether the request content is supported by the source text.

These values are hypothetical starting points for this paper exercise. They are not official default values.

## Three common errors

1. Treating a successful upload as an updated retrieval state. After material changes, the actual training and index state needs checking. The upload action alone does not show that new content can be recalled.
2. Treating semantic similarity as a permission or entity filter. The minimum relevance value filters low-relevance results only. It cannot exclude unauthorized records or separate different distributor entities.
3. Treating one group of source data mapping to several indexes as cross-library joint association. Libraries built on different vector models cannot be jointly associated. Verify the identifier first and exclude those that do not match.

## How to verify the setup

1. Input the agreement source text and the handover request from the hypothetical sample. Compare the requested amount "RMB 1,000,000" against the source text "RMB 800,000", and compare the suspension state against the source text condition. Observe whether the retrieval result returns the agreement source paragraph and does not output the request content as a confirmed fact.
2. Input one identifier-type query against the ageing table and one natural language question. Compare the recalled content from full-text retrieval and semantic retrieval. Observe whether the identifier query hits the corresponding row and whether the natural language query hits the related clause. If one path does not return the expected content, record it as a miss and keep the original input.
3. Input an empty reference list `[]` to check the downstream display design. Compare the output form when no reference content is present. Observe whether an unsupported business conclusion appears. This check does not claim that a fictional rule retrieval necessarily returns an empty result.
4. Search the same question against the same material before and after a change. Compare whether the returned content reflects the changed wording. If the old wording still returns, record it as an index not updated and check the training state.

The above are paper expectations and were not actually executed as tests. Retrieval, forms, and request states do not constitute authorization, approval, or business execution. Pending review does not equal missing operating permission. A quotation validity period does not indicate a supply period. Missing evidence remains pending verification.
