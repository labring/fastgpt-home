# Channel receivables: model connections for multilingual work

## What the documents look like

Channel receivables collection happens after credit sales, so the working material centers on credit limits and cash recovery rather than on matching buyers to sellers. The four recurring documents are the accounts receivable aging table, the dunning letter, the credit agreement, and the shipment freeze notice. A cross-border, multilingual retrieval task has to place these materials, exported from different finance systems and written in different languages, into one searchable scope so that brand finance staff, sales back-office staff, and dealer owners can check the same entry.

The materials update weekly or monthly. Translation conventions, field naming, and date formats differ between language versions. Retrieval returns candidate passages; it does not decide who may see them and does not confirm that a party, period, or amount is correct. Every hit still has to be checked against the source text for subject, period, and field.

## Constraints at the model connections step

Model access depends on AI Proxy. Both the App and the Admin service must set `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN`; if either is missing, startup validation fails. `AIPROXY_API_ENDPOINT` takes the service root address and must not carry a `/v1` suffix. The system needs at least one language model and one index model. The index model turns text chunks into vectors; the language model handles question answering and extraction.

A similarity score is a retrieval ranking value. It is not a category filter, an entity filter, or a permission filter. A high or low score does not exclude unrelated businesses, unauthorized records, or records outside the requester's scope. Retrieval is not authorization. Datasets that use different vector models cannot be associated together, so the vector model identifier has to be checked first and non-matching datasets excluded before any comparison is attempted.

Hypothetical paper exercise. This exercise is written for this page only and was not run against any live system. It uses invented material.

Source A, a Chinese credit agreement excerpt: "Party A grants Party B a credit sales limit; the payment term runs sixty days from the shipment date."

Source B, an English aging table excerpt: "Invoice INV-2043, due 2026-03-31, outstanding USD 18,200."

Source C, a drafted dunning letter sentence: "Your overdue balance has entered the freeze process."

The request under review: place all three materials into one multilingual retrieval scope and check whether the drafted sentence is consistent with the credit agreement and the aging table. The credit agreement does not state the freeze trigger condition. The aging table does not state the shipment date. Whether the freeze process has started is therefore unsupported by these materials and needs separate verification.

## Configuration and implementation checks

The table below is a hypothetical starting point for this exercise. It is used to check access conditions and is not an official default value.

| Configuration item | Hypothetical starting value | Reason and comparison method |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | Assumed set to `http://aiproxy:3000` | Documented as the service root; compare against a value that wrongly appends `/v1` |
| `AIPROXY_API_TOKEN` | Assumed set to a non-empty admin token | Documented as matching the server side; compare against an empty value |
| Language model | Assumed one tested model enabled | Documented minimum of one; compare against the model test result |
| Index model | Assumed one tested model enabled | Documented minimum of one; compare against the model test result |
| Model mapping | Assumed `gpt-4o-test` mapped to `gpt-4o` | Documented mapping example; compare against the `model` field in the request |
| Retrieval scope | Assumed the three materials sit in one dataset | Requires the vector model identifier to match |

Forms collect values. Business verification, approval, database writes, and external synchronization require their own downstream implementation and are not created by filling in a field.

## Three common errors

1. Writing `AIPROXY_API_ENDPOINT` as a full request address that includes `/v1`. Check: read the variable value, compare whether it is the root address without a path suffix, and observe whether startup validation reports a failure.
2. Treating a similarity score as a permission filter and assuming low-scoring results automatically exclude unauthorized records. Check: run the hypothetical English aging table query, compare the returned records against a manually prepared authorization list, and observe whether any unauthorized record appears among the hits.
3. Treating the freeze wording in the drafted dunning letter as an executed fact. Check: compare that sentence against the credit agreement and aging table text, and observe whether the source states a freeze trigger condition and a shipment date; where neither is stated, record the point as pending verification.

## How to verify the setup

1. Input the three hypothetical materials and the drafted sentence. Compare the overdue and freeze wording in the draft against the payment term clause in the credit agreement and the due date field in the aging table. Record a contradiction only when the same subject, the same period, and the same field carry mutually exclusive values. Record an unsupported point when the source is silent.
2. Input the hypothetical English aging table query. Compare the language and fields of the returned records and observe whether the matching entry is recalled. If the result is empty, use the explicit paper input `[]` to check the downstream design; do not claim that a fabricated rule necessarily returns an empty result.
3. Input the hypothetical credit agreement excerpt. Compare the subject name and authorized scope fields in the retrieval results against the source text and observe whether they agree. For datasets on different vector models, check the identifier first and exclude non-matching ones rather than comparing recall gaps across them.

A pending request is not an approval. An offered option is not an execution. An unsigned termination is not a completed termination. Where the documents do not state a trigger, a date, or an authorization boundary, that evidence remains missing and the item stays pending verification.
