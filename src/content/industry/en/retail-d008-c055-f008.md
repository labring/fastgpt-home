# Franchise filing management: workflow routing for multilingual work

## What the documents look like

Franchise filing management centres on legal disclosure and the commerce department system. It does not handle the engineering of a specific retail unit, which distinguishes it from head-office site selection and store opening. The main data sources are the commercial franchise information management system, enterprise licences, store lists and contract ledgers. Day-to-day documents are franchise contracts, operations manuals, filing materials and information disclosure documents.

In cross-border material and multilingual retrieval, one franchise contract may exist in a Chinese version and a translated version. An operations manual may be divided into volumes by language. The language versions of filing materials and information disclosure documents need to correspond item by item with the source text. These materials are updated at irregular intervals and annually, so a workflow cannot rely on a fixed cadence. A person confirms the currently effective version before retrieval begins.

## Constraints at the workflow routing step

The Form Input node and the User Selection node are both user interaction nodes. When either node is triggered, the conversation enters an interaction state and the workflow state is recorded. After the user completes the interaction, the workflow continues downward. The constraint is that the language, target document type and authorization scope of a retrieval request must be collected through interaction nodes. The nodes themselves only collect and pass on information; they do not constitute an authorization decision.

If a retrieval library uses a different vector model, the libraries cannot be associated together. The model identifier must be checked first and non-matching libraries excluded. Empty-result handling can be checked against a paper input of `[]` to verify the downstream design; it cannot be claimed that a fictional rule retrieval will always return `[]`. External operations such as order writing, document backfill and external status synchronization require a separate business interface or a later flow. Interaction nodes do not perform these actions.

Hypothetical paper exercise sample: the source material reads "Franchisor A signed the Chinese version of the Franchise Contract on 1 March 2024; the operations manual attached to the contract is the Chinese version; the English translation submitted by Company B is marked 'Translation for internal review only, not for filing'." The draft sentence to be assessed is "The English translation may be submitted as filing material." The check points are: the subject is Franchisor A, the object is the English translation, the status marking is internal review only, and the effective scope does not cover filing submission. The draft sentence is not supported.

## Configuration and implementation checks

| Configuration item | Setting or check content | Relation to the sample |
| --- | --- | --- |
| Form Input node | Collect target document type, language and intended use | Collects the two inputs "filing material" and "English translation" |
| User Selection node | Execute the corresponding "yes" branch according to the user's choice | Branch decides whether the translation is used for filing submission |
| Interaction state check | Recorded state is behaviour of the interaction node; no separate global switch is set | Checks the state record after the sample interaction |
| Output handover check | Pass collected information explicitly to a later retrieval or decision node | Compares the translation marking with the draft sentence |
| Retrieval library identifier check | Check the vector model identifier and exclude non-matching libraries | Check multilingual libraries separately; do not associate across models |
| External operation division | Filing submission and document backfill connect to a separate business interface | The submission action in the sample is not executed at this node |

## Three common errors

1. Treating an English translation marked "internal review only" as filing material that may be submitted. The input is the sample source text and the draft sentence; the comparison is between the status marking and the filing submission condition; the observable result is that the draft sentence is not supported.
2. Treating the language and intended use collected by the Form Input node as an authorization permit. The input is the node output field; the comparison is between the field content and the authorization boundary; the observable result is that the field only passes on information and does not produce an authorization conclusion.
3. Inferring missed recall after associating retrieval libraries that use different vector models. The input is the two library identifiers; the comparison is whether the identifiers match; the observable result is that non-matching libraries are excluded, and the actual retrieval behaviour is not described in the documentation.

## How to verify the setup

- Check one: input the sample source text and the draft sentence, compare the status marking of the English translation with the filing submission condition, and expect the draft sentence to be unsupported, with the pending verification status retained.
- Check two: input the language and intended use fields collected by the Form Input node, compare the field content with the authorization boundary, and expect the fields to serve only as transmission and to produce no authorization conclusion.
- Check three: input the vector model identifiers of the two retrieval libraries, compare whether the identifiers match, and expect non-matching identifiers to be excluded from association, with the actual observation recorded as pending verification. All three are paper checks; no actual retrieval or submission was executed.
