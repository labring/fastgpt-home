# Producer export tax processes: workflow routing for multilingual work

## What the documents look like

Producer export tax refunds combine the offset of domestic sales tax with the refund calculation. This structure shapes the inputs for cross-border material handling and multilingual retrieval. The main data sources are the electronic tax bureau, ERP sales records, customs electronic information, and financial ledgers. The documents handled day to day include the exemption, offset, and refund declaration detail table; export contracts; sales detail ledgers; and export customs declarations. The typical practitioners are export production enterprises, tax accountants, and sales documentation staff. Materials update monthly, which in routing means documents arrive in batches within the same declaration period.

In cross-border settings, an export contract may use non-Chinese text, while the customs declaration and the declaration detail table use Chinese conventions that must be mapped item by item. When the retrieval scope includes multilingual materials, the same business fact may appear in different languages, and routing must treat language difference as a material attribute. Language difference is not an authorization difference.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When triggered, the conversation enters an interaction state, the workflow state is recorded, and the conversation continues downward only after the user completes the interaction. The node collects required information the user fills in and, after submission, passes that information to subsequent nodes. The User Selection node is also a user interaction node. When triggered, the conversation enters the interaction state and the workflow state is recorded. When the user makes a choice, the node evaluates that choice and executes the "yes" branch. Recording state is behavior of the interaction nodes; the documents do not describe a separate global state-recording switch.

Retrieval finds relevant text by semantics. It does not perform permission judgment and does not perform entity isolation. Values collected by a form must be explicitly passed to a later retrieval, judgment, or interface node. Order writing, document backfill, and external status synchronization require a separate business interface or a later process; the routing itself does not complete those actions.

Hypothetical drill sample: a tax accountant at an export production enterprise organizes materials during the March 2026 declaration period. The source text provided for checking reads: "Export contract number HX-2026-03, buyer is an overseas entity, goods are self-produced equipment, and the total free-on-board price is as stated in the contract annex." "Exemption, offset, and refund declaration detail table, period February 2026, line 7: export sales amount agrees with the customs declaration amount." The draft sentence to be judged reads: "This export business has completed the exemption, offset, and refund declaration and has received the refund." The completion and the receipt of the refund have no support in the source text.

## Configuration and implementation checks

| Configuration item | Type | Implementation check note |
| --- | --- | --- |
| Form Input node | Interaction node | Enters interaction state when triggered, collects required information, passes values to later nodes after submission |
| User Selection node | Interaction node | Executes the "yes" branch after the user makes a choice; verify branch connections one by one |
| Interaction state check | Check item | State recording is behavior of the interaction nodes; no separate global state switch is set |
| Output handoff check | Check item | Compare collected information item by item against the inputs of later retrieval, judgment, or interface nodes |
| External action division | Implementation boundary | Order writing, document backfill, and external status synchronization connect to a separate business interface |
| Retrieval scope identifier | Check item | Confirm accessible scope by material identifier; only libraries on the same vector model can be associated together |

## Three common errors

1. Treating a retrieval hit as an authorization result. Input is a multilingual export contract retrieval request. Compare the returned text against the authorization scope identifier. The observable result is that retrieval returned text while access rights were not checked, which is judged as permission unconfirmed.

2. Writing a pending-review state as completed. Input is the draft sentence above and the source text. Compare "has completed the declaration and has received the refund" against the source text, which contains only the contract and the detail table. The observable result is that the draft sentence exceeds what the source supports, judged as unsupported.

3. Using a submitted interaction value directly for a business write. Input is the declaration period value submitted at the Form Input node. Compare that value against whether the downstream interface node has a write implementation. The observable result is that the submitted value is only passed to later nodes, judged as requiring a separate implementation for the business action.

## How to verify the setup

1. Use the hypothetical sample source text and draft sentence. Input is the two source sentences and the draft sentence. Compare whether the draft sentence contains completion or refund-receipt wording absent from the source. If the draft sentence contains unsupported content, the result is not passed.

2. Use the contract number and declaration detail line from the hypothetical sample. Input is contract number HX-2026-03 and detail table line 7. Compare whether the subject, period, and amount fields of the two are from the same source. If the fields correspond, the result passes; if missing, record the gap.

3. Use an explicit paper input of [] to check empty-result handling. Input is an empty retrieval result. Compare whether downstream nodes are designed with a branch for the empty result. If downstream does not treat the empty result as a hit, the result passes. Do not claim that retrieval under a fictional rule necessarily returns empty.

This page addresses only producer export tax refunds, cross-border materials and multilingual retrieval, and workflow routing. During operations handover, the authorization state of which materials, operations, and requests must be kept separate from retrieval or forms treated as authorized execution.
