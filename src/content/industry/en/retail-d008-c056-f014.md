# Producer export tax processes: model connections for multilingual work

## What the documents look like

Producer export tax treatment under the exemption-offset-refund method merges domestic-sales tax offsets with export refunds into one calculation. For the producer category, the heaviest work sits in three places: gathering self-produced export items, computing the exemption-offset-refund amount, and reconciling free-on-board price differences. Cross-border material handling and multilingual retrieval work with four document types: the exemption-offset-refund declaration detail schedule, the export contract, the sales detail ledger, and the export customs declaration. These arrive from the electronic tax bureau, ERP sales records, customs electronic messages, and the financial books, and they refresh monthly.

Multilingual retrieval has to read foreign-language goods descriptions, trade terms, and amount wording on contracts and customs declarations. Whether those fields can be read and recalled depends on how models are connected and configured. FastGPT reaches model providers through AI Proxy. From V4.17.0, AI Proxy is a required dependency: both the App service and any Admin service that reuses App/Service configuration must set `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN`, and startup validation fails if either is missing. `AIPROXY_API_ENDPOINT` takes the service root address without an appended `/v1`. The system needs at least one language model and one index model to work normally. A model ID is the value of the `model` field in a request body and is globally unique; a model channel can map the model requested by FastGPT onto the actual upstream model. Retrieval is recall. It does not carry authorization, entity isolation, or business verification.

## Constraints at the model connections step

A hypothetical drill sample, clearly labelled as such: a clerk at an export producer organizes one batch of paper materials. It contains one export contract dated March 2026, whose buyer field names an overseas trading company, whose goods description is a foreign-language product name, and whose amount field is stated as free on board. It also contains one export customs declaration for the same month, whose domestic consignor is the producer and whose commodity name field carries the corresponding foreign-language product name. The drafted sentence under review reads: "The goods under this contract have been produced and exported by the producer, and the declaration detail schedule can directly gather them." The pending request reads: "Please retrieve and confirm that this contract and this customs declaration can be gathered as self-produced exports."

Two constraints follow from this sample. First, retrieval can show whether the two documents are recalled; it cannot confirm the self-produced attribute, because that attribute is a business fact that must appear in the source text. Second, the drafted sentence asserts a status the sample text does not state. The sample text names the buyer, the consignor, the goods description, and the free-on-board amount. It does not state a self-production attribute or a gathering authorization. That gap stays a gap.

## Three common errors

1. Setting `AIPROXY_API_ENDPOINT` to a full request address that ends in `/v1`. Check: read the variable value and compare it against the documented instruction to use the service root address without `/v1`. If the value ends in `/v1`, the setting does not conform.
2. Using an application API key as `AIPROXY_API_TOKEN`. Check: verify the token's source against the server-side configuration. If the source is an application-side key, or the value is empty, the setting does not conform.
3. Treating a retrieval recall as an authorization or verification conclusion about self-produced export. Check: for the drafted sentence, examine whether the contract and customs declaration source text states a self-production attribute and a gathering authorization. The sample source text does not state either. The drafted sentence remains unsupported.

## How to verify the setup

The three items below apply to the hypothetical sample above. They state expectations only. No test is claimed to have been run.

1. Input: the foreign-language product name text from the contract and the customs declaration in the hypothetical sample. Compare: whether the retrieval result hits these two materials. Satisfied condition: a hit is recorded; a miss is recorded as a failure branch. First-position hits and full recall are not guaranteed.
2. Input: the drafted sentence "The goods under this contract have been produced and exported by the producer, and the declaration detail schedule can directly gather them." Compare: whether the source text, under the same subject, the same period, and the same field, states a self-production attribute. Satisfied condition: when the source text does not state it, the sentence is judged unsupported and the evidence gap is retained. No authorization clause is supplied to fill the gap.
3. Input: a paper input of `[]` together with the downstream gathering design. Compare: whether the downstream design handles an empty result explicitly. Satisfied condition: being able to describe the empty-result branch is sufficient. No claim is made that a hypothetical rule-based retrieval necessarily returns `[]`.

Operational handover must keep material, action, and request authorization states distinct. Retrieval and forms are not authorization to execute.
