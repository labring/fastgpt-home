# Producer export tax processes: retrieval for multilingual work

## What the documents look like

Producer export tax processing combines the offset of domestic sales tax with the calculation of refundable tax. That combined calculation requires the underlying records to agree on business entity, period, and field definitions. The records handled in daily work include the exemption, offset, and refund declaration detail sheet, export contracts, the sales detail ledger, and customs export declarations. These materials arrive from the electronic tax bureau, ERP sales data, customs electronic information, and financial accounts, and the update frequency is monthly.

For cross-border materials and multilingual retrieval, these records are placed in a knowledge base so that retrieval can return citations. Multilingual retrieval depends on the cross-language understanding of semantic search, while exact content such as declaration numbers and customs declaration numbers depends on keyword matching in full-text search. The completeness and length of the stored material directly affect index quality.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases with different vector models cannot be associated together, so their model identifiers must be checked first and non-matching bases excluded. The search mode is compared across semantic search, full-text search, and hybrid search according to the test question, and no single mode is assumed to suit all materials. Hybrid search merges multiple result paths through RRF, and RRF is a fusion process rather than a standalone switch.

The citation limit is measured in tokens, so materials of different lengths must be used to test whether the cited content remains complete. The minimum relevance score takes effect only in semantic search or when result reranking is used. Question optimization handles coreference resolution and question expansion, so the original question and the optimized question must be compared to check whether the subject has been altered incorrectly. Retrieval and similarity scores do not perform permission or entity isolation, and a retrieval result does not equal an authorization status. Cited content is output as an array and its length can be 0, meaning the empty-result path still runs. Image retrieval requires corresponding image input and model capability, and reranking requires a model that is enabled according to settings. The optional paths listed in the documented flow do not mean every request executes all of them.

## Configuration and implementation checks

The settings below are tied to the sample on this page. The values are hypothetical starting points for this paper exercise and are not official defaults.

| Configuration item | Hypothetical starting point for this exercise | Reason and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Associate only one exemption, offset, and refund material base whose vector model identifier is consistent | Check each base's vector model identifier first, exclude non-matching ones, and do not run cross-model retrieval comparisons |
| Search mode | Run semantic search and full-text search once each, then run hybrid search | Use the same test question to compare the three recall paths and observe differences between number-type and natural-language questions |
| Citation limit | Set to a token amount that covers the clauses of one complete export contract | Test with contracts and detail sheets of different lengths to see whether cited content is truncated, then adjust |
| Minimum relevance score | Label relevant and irrelevant samples first, then try a middle value | Takes effect only in semantic search or result reranking; observe whether irrelevant fragments are filtered |
| Question optimization | Turn it off first and test with a complete question; then turn it on and test with a coreference question | Compare the original and optimized questions and check whether the subject or period was altered incorrectly |
| Result reranking | Run it when a reranking model is available and enabled according to settings | For text questions with many candidates, observe reranking scores and ordering changes |

## Three common errors

1. Associating knowledge bases that use different vector models. The input is two exemption, offset, and refund material bases whose vector model identifiers do not match; the comparison is the vector model identifier of each base; the observable result is that association does not hold for bases with non-matching identifiers, so non-matching bases should be excluded and the actual observation recorded, without inferring missed recall or redundancy.
2. Treating the minimum relevance score as a permission or entity filter. The input is an authorization status statement whose relevance score is below the threshold; the comparison is the authorization field of that statement against the retrieval score; the observable result is that the retrieval score does not change the authorization status, and a pending review does not equal an approval, so authorization materials must be checked separately.
3. Treating RRF as a switch that can be turned on. The input is the hybrid search configuration interface and search results; the comparison is the configuration item names against the parameters listed in the documentation; the observable result is that RRF appears in the result fusion description and the configuration interface provides no corresponding switch, so the actual configurable fields must be confirmed against the documentation.

## How to verify the setup

Hypothetical exercise sample. Material text one: "The export sales amount listed in this enterprise's March 2025 exemption, offset, and refund declaration detail sheet is based on that month's customs export declarations and the sales detail ledger." Material text two: "This batch of export contracts specifies an FOB price, and any difference between the customs declaration amount and the contract amount is explained separately at declaration." Draft sentence to be judged: "The above export contract has taken effect, and the related refund has been approved." The judgment compares the same entity, the same period, and the same field: contract effectiveness and refund approval are different facts, and the draft sentence states no approval document number or effectiveness clause, so it is unsupported and the evidence gap must be preserved.

- Check one: input the draft sentence and the two material texts; compare the "has taken effect" and "has been approved" statements in the draft against the content recorded in the source texts; the support condition is met only when the source texts contain effectiveness and approval records for the same entity, and otherwise the result is recorded as unsupported.

- Check two: input one precise query containing a customs declaration number and one natural-language query; compare the content recalled by full-text search and by semantic search respectively; observe how the number-type query performs under full-text search, without guaranteeing a first-position hit or complete recall.

- Check three: input an empty citation array [] and a downstream citation-handling design; compare the array length against the downstream processing logic; observe whether the empty-result path runs through, without claiming that a fictional rule-based retrieval necessarily returns [].
