# Livestream violation appeals: model connections for multilingual work

## What the documents look like

Livestream violation appeals respond to penalties that have already been issued, so the work centers on reconstructing an evidence chain. A violation notice, a livestream recording, product qualification material and an appeal statement may each arrive from a different language site. Before retrieval can help, the store, the violation notice number and the penalty period attached to each document must be identified, and then a specific sentence in the appeal can be checked against what a document actually covers. Materials appear irregularly with each violation, so retrieval configuration is scoped to the document set of one appeal and does not perform cross-store bulk synchronization.

In cross-border work, the language of a document does not settle which store or notice it belongs to. A qualification statement issued in one language may carry a date but no store number, and a notice issued in another language may name a store and session date without listing the qualification documents that were reviewed. The retrieval step therefore has to keep document identity and document coverage separate from retrieval ranking.

## Constraints at the model connections step

Model connections determine whether multilingual material can be indexed and recalled. Under v4.17.2, the App and any Admin service that reuses App or service configuration must set `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN`; missing either causes startup validation to fail, and legacy OpenAI variables or a single-model custom request address do not substitute for them. The system needs at least one language model and one index model to operate normally.

A retrieval dataset and its index model carry a same-model association requirement: datasets built on different vector models cannot be associated together. This check is limited to the index model identifier; it does not extend to external systems such as business registration sites. Semantic recall and relevance scores do not perform permission or entity isolation, and retrieval does not constitute authorization. Empty results, context limits and the same-model association keep the conditions stated in the documentation.

Hypothetical paper exercise sample. A cross-border store receives an English violation notice reading: "Notice ID: CN-2026-0417. This notice applies to store S-8842 and covers the live session held on 2026-04-10. The alleged violation is the display of an unverified cosmetic claim." The same batch contains a Chinese product qualification statement dated 2026-03-28 that does not state which store number it covers. The draft appeal sentence is: "The product qualification was filed before the livestream and covers the violation period." That sentence relates to the statement's issue date, but the statement does not record the store or the notice number, so the sentence is unsupported until the coverage scope is supplied.

## Configuration and implementation checks

| Configuration or check item | Hypothetical starting point and reason | Comparison method |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | The AI Proxy root address, with no `/v1` appended, because the documentation requires the root address | Compare against the documented requirement and confirm no path suffix |
| `AIPROXY_API_TOKEN` | A non-empty administrator token matching the server, because an empty value fails startup validation | Distinguish it from an application API key and confirm it is non-empty |
| Index model activation | At least one index model enabled, because the system needs one language model and one index model | Check the system model list for an enabled index model |
| Dataset and index model | Each dataset uses one index model identifier, because datasets on different vector models cannot be associated | Compare identifiers dataset by dataset and exclude mismatched ones |
| Multilingual PDF parsing | PDF enhanced parsing selected with a configured service, because the documentation requires the selection at upload | Check whether the selection was made; without it the built-in parser is used |
| Model probe | Automatic probing enabled with an interval set as an integer between 5 and 60 minutes, chosen as a paper starting value for this exercise | Compare the value against the documented range and confirm it is an integer |

## Three common errors

1. Treating a retrieval hit as authorization. Input: the English notice above and the Chinese qualification statement. Compare the coverage claimed by the draft sentence against what the statement records. If the statement does not name the store and notice number, the sentence remains unsupported; retrieving the document does not make the appeal reason valid.
2. Associating datasets built on different vector models. Input: two retrieval datasets whose index model identifiers differ. Compare the identifiers; when they differ, exclude that dataset rather than running a cross-model retrieval to compare missed recalls.
3. Using a similarity setting to exclude unrelated businesses or unauthorized records. Input: an ordinary query. Compare the returned results against the permission boundary. A relevance score does not perform entity or permission filtering, and whether unauthorized records appear depends on downstream permission implementation, which remains unknown.

## How to verify the setup

1. Input the English notice text above and the draft sentence. Compare the claim that filing was completed against the issue date and coverage actually recorded in the qualification statement. The sentence is supported only if the statement names the store number and notice number and its date precedes the livestream period; the current material lacks those fields, so record it as pending verification.
2. Input two retrieval datasets with different index model identifiers. Compare whether the identifiers match; association is permitted only when they match. When they differ, exclude the dataset and record the actual observation without inferring runtime behavior.
3. Input an explicit paper empty result `[]`. Compare whether the downstream design treats an empty result as such, without asserting that a fictional rule must return `[]`. At the same time, check that `AIPROXY_API_ENDPOINT` has no `/v1` suffix and that `AIPROXY_API_TOKEN` is non-empty, as startup validation check items; this does not indicate that deployment or testing has been completed.
