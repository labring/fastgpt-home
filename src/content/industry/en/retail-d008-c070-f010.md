# Cross-border product labels: citation tracing for multilingual work

## What the documents look like

Cross-border product compliance work happens before listing and before import. The core activity is assembling product safety and label evidence. The main data sources are platform policy centers, testing laboratory reports, destination-country regulation libraries, and supplier materials. The documents handled day to day include product test reports, English-language labels, material safety data sheets (MSDS), and platform prohibited-item lists. These materials exist in mixed Chinese and English, and in multiple languages side by side. They are updated irregularly, and each new product listing can change them.

In the cross-border materials and multilingual retrieval task, citation tracing requires that every cited item can be traced back to a specific material. The retrieval step uses a vector recall path and a full-text recall path, and the results are fused into citation content. Different material versions mean the same test report or label file can correspond to different destination-country requirements. Version and scope of applicability must be checked at citation time.

## Constraints at the citation tracing step

A knowledge base search node can be linked to one or more knowledge bases that share the same vector model. Citation content is output as an array, and its length can be 0. Even when nothing is retrieved, the output path still runs. An empty array means that retrieval returned no citations; it does not by itself indicate that the workflow has errored and stopped.

The combination of semantic retrieval, full-text retrieval, and hybrid retrieval is set by search parameters. Hybrid retrieval merges multiple result paths through RRF. ReRank performs a second ordering of candidate text. Minimum relevance takes effect only under semantic retrieval or when result reordering is used; it is a filtering threshold and does not perform permission or entity isolation. Retrieval is not authorization. Citation tracing requires human checking.

Hypothetical paper exercise sample

Source material for checking:

- A supplier's March 2025 English label draft states: "Product safety data sheet attached; destination market requirements pending confirmation."
- The same supplier's April 2025 email body states: "Updated test report for the EU market will be provided after the lab completes retesting."

Proposed sentence to be assessed: "The product already has the complete test report and label evidence required for the EU market."

The proposed sentence lacks evidence of subject authorization and effective scope. The March 2025 label draft marks destination-country requirements as pending confirmation. The April 2025 email states that the EU test report will be provided after retesting is complete. Both materials are in a pending state. The proposed sentence writes a to-be-provided material as already held, which is unsupported.

## Configuration and implementation checks

| Configuration item | Hypothetical exercise starting point | Reason for the choice and comparison method |
| --- | --- | --- |
| Linked knowledge bases | Select one existing compliance material library | Check the vector model identifier of each library, exclude those with a different vector model, and do not run cross-model retrieval |
| Search mode | Use semantic retrieval and full-text retrieval together | Semantic retrieval covers multilingual meaning; full-text retrieval covers model numbers and codes; compare hit differences between the two question types |
| Citation limit | Set to 4000 tokens for this hypothetical exercise | Control citation length using the documented token unit; compare against the number of citations when no limit is set |
| Minimum relevance | Set to 0.3 for this hypothetical exercise | Takes effect only under semantic retrieval or result reordering; compare the change in filtered item count against 0.5 |
| Question optimization | Enable for multi-turn follow-up scenarios | Coreference resolution and question expansion add one model call before retrieval; compare follow-up hits against the disabled state |
| Result reordering | Enable ReRank when candidates are numerous | ReRank scores range from 0 to 1; compare ordering stability against vector scores |

## Three common errors

1. Treating minimum relevance as a permission filter. Input is a retrieval request against the same compliance material library. Compare the returned citations against all materials in the library. If the citations only cover passages semantically close to the question and are not filtered by business ownership, this shows the relevance threshold performs relevance filtering only. Permission decisions require a separate system implementation.

2. Treating an empty citation array as retrieval failure. Input is a retrieval that returns `[]`. Compare the node output against the downstream answer node. If the downstream still runs and produces an answer without citations, this shows the empty array runs through the output path as documented, without triggering an error.

3. Writing a to-be-provided material as already held. Input is the two materials in the hypothetical sample above and the proposed sentence. Compare the proposed sentence against the source status. If the source contains "pending confirmation" and "will be provided after," and the proposed sentence writes "already has," the sentence is judged unsupported.

## How to verify the setup

1. Input the hypothetical sample's March 2025 English label draft and April 2025 email. Compare the proposed sentence against the status fields for destination-country requirements and the test report in the source text. Observe whether the proposed sentence rewrites pending confirmation or to-be-provided into completed. The condition is met when the proposed sentence preserves the source's pending status.

2. Input a retrieval output that returns `[]`. Compare that output against the downstream answer node's handling design. Observe whether the downstream continues to run with an empty citation. The condition is met when the downstream does not error on the empty array and the answer does not fabricate citation sources.

3. Input two knowledge bases whose vector model identifiers differ. Compare their model identifier fields. Observe whether they are linked together. The condition is met when libraries with different vector models are excluded, retrieval runs only against libraries with the same vector model, and the actually observed citation content is recorded.
