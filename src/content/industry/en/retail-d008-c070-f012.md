# Cross-border product labels: document chunking for multilingual work

## What the documents look like

Cross-border product compliance work happens before listing and before import. The evidence base is product safety and label material, and the documents handled day to day include product test reports, English-language labels, MSDS files, and platform prohibited-item lists. These materials arrive from platform policy centers, testing laboratory reports, destination-country regulation libraries, and supplier submissions. Updates are irregular, and each new product launch can bring a new version.

A single test report may carry a Chinese conclusion page together with English data pages. English label text and MSDS terminology do not follow the same conventions as Chinese-language source material. The mapping between a document version and a destination-country requirement has to be checked document by document. These traits shape parsing and chunking directly: a segment must keep conditions bound to the conclusions they qualify, and retrieval must be able to land on the same fact across languages.

## Constraints at the document chunking step

The goal of parsing and chunking here is that every chunk can point back to the document identity and version of its source. One set of original data can map to several indexes, and a hit on any one index recalls that set. Semantic retrieval supports cross-language understanding, so a Chinese question can match an English knowledge point, subject to the capability of the vector model. Full-text retrieval suits exact queries such as numbers, model designations, and proper nouns. Hybrid retrieval uses semantic recall and full-text recall together and merges the two result sets through RRF. Rerank performs a second ordering of candidate text, produces a score in the 0–1 range, and the minimum relevance value takes effect only under semantic retrieval or when result reranking is used. The reference limit controls, in tokens, the maximum content referenced per search. Image retrieval requires an image input and the matching model capability, and reranking requires an available model enabled in settings; these paths do not run on every request.

Hypothetical paper exercise sample: an English MSDS contains three sentences — "Section 3: Composition — Contains substance CAS 000-00-1 at 15%." "Section 7: Handling — Store below 25°C away from ignition sources." "Section 13: Disposal — Dispose in accordance with local regulations." The draft sentence awaiting assessment is: "This MSDS has been confirmed to meet the destination-country labeling requirements." That draft sentence lacks a destination-country name and a labeling regulation clause, and none of the three source sentences states a labeling compliance conclusion.

## Three common errors

1. Treating a successful upload as an updated index. After source material changes, the actual training and index state has to be checked; the upload action itself does not change an index that has already been built.

2. Treating semantic recall or a relevance score as a permission or entity filter. The minimum relevance value is a filtering threshold and does not exclude unrelated businesses or unauthorized records; retrieval does not perform authorization decisions.

3. Associating libraries built on different vector models. Libraries using different vector models cannot be associated together. Check the identifier first and exclude those that do not match, rather than running retrieval across models to compare missed recalls.

## How to verify the setup

1. Input the three source sentences of the sample English MSDS together with the draft sentence "This MSDS has been confirmed to meet the destination-country labeling requirements." Compare whether the draft sentence contains a destination-country name and a labeling regulation clause. The source text contains no destination country and no labeling compliance conclusion, so the draft sentence is unsupported and remains pending verification.

2. Input the CAS number "000-00-1" and run retrieval. Compare whether the returned chunk contains the Section 3 source sentence and the document identity. If the returned chunk is missing the CAS number or separates the composition from the concentration, the segmentation does not meet the completeness requirement.

3. Input the Chinese question "What are the storage conditions for this substance?" and run semantic retrieval. Compare whether the returned chunk contains the Section 7 source sentence "Store below 25°C away from ignition sources." If the returned chunk holds only the storage temperature and drops the away-from-ignition-sources condition, the condition has been separated from the content it qualifies. When the result is empty, check the downstream design against the paper input [] rather than asserting that a fictional rule must return [].
