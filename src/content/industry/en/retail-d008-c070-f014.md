# Cross-border product labels: model connections for multilingual work

## What the documents look like

Cross-border product compliance work at the model connection step draws on product test reports, English-language labels, material safety data sheets (MSDS), and platform prohibited-item lists. Sources include platform policy centers, testing laboratories, destination-country regulatory libraries, and supplier materials. Documents are added when a new product is listed, and one product can carry different label versions and different test conclusions for different destination countries. A retrieval task has to connect multilingual documents to a specific product, destination country, and batch, then return quotable passages that a compliance specialist can check against the source. Updates are irregular; this page does not derive batch synchronization, full synchronization, or transaction-triggered behavior from that irregularity.

For this category, the practical consequence is that the retrieval corpus mixes languages inside one product record, and the same product identifier may appear with several label texts. The model connection step therefore has to keep the request model name, the upstream model name, and the retrieval corpus aligned, so that a query about one label version does not silently pull a passage from a different version. Nothing in the supplied documents states that similarity scoring performs entity isolation or permission filtering, and nothing states that libraries built on different embedding models can be associated with each other. Model identifiers have to be checked first, and non-matching libraries excluded, before any retrieval is attempted.

## Constraints at the model connections step

Model access depends on AI Proxy. App and Admin must both set `AIPROXY_API_ENDPOINT` and a non-empty `AIPROXY_API_TOKEN`; a missing value in either one causes startup validation to fail. The endpoint is the AI Proxy service root address and does not carry `/v1`. The token is the AI Proxy administrator token and must match the server-side configuration; an application API key does not substitute for it. Model channels are configured on the administrator model provider page through protocol type, model, model mapping, proxy address, and API key. The proxy address is a BaseUrl, not a full request path.

Language model and indexing model fields such as `maxContext`, `maxToken`, and `defaultToken` come from the model configuration. Coverage relationships between identically named fields in other interfaces cannot be inferred. A rerank model is an optional path in the overall flow: it requires a configured rerank model and must be enabled according to its settings, and it does not run on every request. Image retrieval likewise requires an actual image input and a model with the corresponding capability. The system needs at least one language model and one indexing model to operate.

A relevance score is not a category, entity, or permission filter. Retrieval is not authorization. When a form collects a destination country or a batch number, that value is a collected field; business verification, approval, database writes, and external synchronization require their own downstream implementation. A pending review request is not an approval, an offered option is not an execution, and an unsigned termination is not a completed termination.

## Configuration and implementation checks

The table below is a hypothetical starting point for this page's paper exercise. It is not an official default value, and it is not a record of a completed test.

| Configuration item | Hypothetical starting value | Reason and comparison object |
| --- | --- | --- |
| `AIPROXY_API_ENDPOINT` | Assume `http://aiproxy:3000` | Compare with the documented service root address format; confirm no `/v1` is appended |
| `AIPROXY_API_TOKEN` | Assume a non-empty administrator token | Compare with the AI Proxy server-side configuration; confirm the two match and neither is empty |
| Language model `maxContext` | Assume 125000 | Compare with the model configuration's `maxContext` value; confirm it covers the sample reference length |
| Indexing model `defaultToken` | Assume 512 | Compare with the sample file's chunking requirement; confirm each chunk's token count does not exceed this value |
| Channel model mapping | Assume `gpt-4o-test` maps to `gpt-4o` | Compare with the channel's model mapping field; confirm the request model name and the upstream model name correspond |
| Rerank model | Assume not configured | Compare with the retrieval reranking requirement; confirm whether reranking capability is present at this step |

## Three common errors

1. Setting `AIPROXY_API_ENDPOINT` to a full request address that includes `/v1`. The input to check is the environment variable value; the comparison object is the documented service root address format; the observable result is whether `/v1` or `/chat/completions` appears in the value.
2. Using an application API key in place of `AIPROXY_API_TOKEN`. The input to check is the token's source; the comparison object is the AI Proxy administrator token expected by the server; the observable result is whether the value is non-empty and matches the server-side configuration.
3. Treating a similarity score as a permission or entity filter. The input to check is the returned record set; the comparison object is each record's owning subject and authorization scope; the observable result is whether a record outside the authorized scope appears because of similarity ranking.

## How to verify the setup

Hypothetical paper exercise sample. A batch of children's drinking cups is intended for export to Germany. The supplier's English label text reads: "Suitable for children over 3 years. BPA free. Not suitable for microwave use." The test report number is the hypothetical TEST-2024-0001, with the conclusion "conforms to EN 14350". One draft sentence awaiting judgment reads: "The product label and test report both satisfy the German listing requirements." That sentence draws on three material types: the label text, the report conclusion, and the destination-country requirement. Only the label and the report are provided; the destination-country regulatory library text is not provided.

- Verification one. Input the label text "Suitable for children over 3 years. BPA free. Not suitable for microwave use." as a retrieval query. Compare whether the returned citation contains that exact passage. The condition is met when the cited text matches the input text. If the result is empty, record it as a miss and do not infer that the rule does not exist.

- Verification two. Input the draft sentence "The product label and test report both satisfy the German listing requirements" together with the sample materials. Compare whether the sentence obtains support from both the label text and the report conclusion. The observable result is that the sentence exceeds the scope of the provided materials, and the destination-country requirement portion remains unsupported.

- Verification three. Input the report number TEST-2024-0001 as a retrieval query. Compare whether the returned record's report number field and conclusion field match the input. The condition is met when the number and the conclusion correspond. If the retrieval returns a record with a different number, record it as an identifier mismatch and exclude it.

Across all three checks, the retrieval scope must be a target corpus the operator has access to, or an explicit manual input. When material is absent, record the gap. An empty result does not establish that a rule is absent. Libraries built on different embedding models cannot be associated with each other; check the model identifiers first, exclude non-matching libraries, and record what was actually observed rather than predicting a runtime outcome.
