# Cross-border payment reviews: citation tracing for multilingual work

## What the documents look like

Cross-border standalone-site payment risk control operates around card-network disputes and the receiving account. The working materials include payment chargeback notices, fraudulent order lists, invoices and carrier proof of delivery. These arrive from payment back offices, standalone-site orders, carrier delivery records and customer service email. The brief gives a daily and per-order update rhythm, and this page does not extend that into batch, full-sync or real-time mechanisms.

For citation tracing, the practical difficulty comes from mixed languages and split sources. A chargeback notice and a delivery record can sit in different languages and different systems, and a retrieval result that reads as semantically close does not carry identity, permission or business validity. Tracing therefore means comparing each drafted sentence against the original text and its version, field by field.

The knowledge base search node can associate one or more knowledge bases that share the same vector model. Its output is an array of cited content, and the length may be zero; when nothing is retrieved, the output path still runs through. Hybrid retrieval merges multiple recall paths through RRF, and reranking produces a 0-1 score. The minimum relevance value takes effect only in semantic retrieval or when result reranking is used; it filters low-relevance content and is not a permission or entity filter. The citation limit controls, in tokens, how much content a single search may cite.

## Constraints at the citation tracing step

A hypothetical drill sample is used here. The source text reads: "Chargeback notice DN-2201 states that the cardholder raised a dispute on 12 March 2025, the disputed amount is USD 480, the receiving account ends in 6621, and the current status is evidence pending submission." A second sentence reads: "The carrier delivery record shows the order was signed for by the recipient on 8 March 2025." The draft sentence to be assessed reads: "This chargeback has completed evidence submission and has been closed."

When checking, the comparison must stay on the same subject, the same period and the same field. The source text records only a status of evidence pending submission. The draft sentence asserts completed submission and closure. On the same status field the two values are mutually exclusive, so the draft sentence is not supported. The delivery record is a separate fact and remains pending verification for any link between the signature and the dispute outcome.

Several documented conditions shape this step. Associating knowledge bases requires confirming the same vector model first; bases with different vector models cannot be associated together, and no cross-model retrieval is performed to compare missed recalls. The search node output is an array, and an empty array is a valid output rather than a workflow error. RRF is the fusion process for hybrid retrieval results, not a separate switch. The minimum relevance value is a filtering threshold, and a relevance score is not a category, entity or permission filter. Forms collect values; business verification, approval, database writes and external synchronization each need their own downstream implementation.

## Configuration and implementation checks

| Configuration or check item | Hypothetical starting point for this drill | Reason and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Two bases confirmed to share the same vector model | Compare the base identifiers item by item, exclude any with a different vector model, and do not run cross-model retrieval |
| Search mode | Hybrid retrieval | Compare the recall scope against semantic retrieval and full-text retrieval; numbered materials rely on keyword hits |
| Citation limit | Set to 3000 tokens for this drill | This is a hypothetical starting value; compare it against the actual combined length of the chargeback notice and the delivery record, then adjust |
| Minimum relevance | Set to 0.5 for this drill | This is a hypothetical starting value; compare it against the rerank score distribution, and candidates scoring below it are filtered |
| Result reranking | Enabled | Compare against ordering without reranking; the rerank score is used for filtering |
| Cited content output | Accept the array, empty allowed | Use an empty array to check the downstream design; an empty result does not mean the workflow terminated with an error |

## Three common errors

1. Treating the minimum relevance value as a permission or entity filter. The input is one semantic retrieval request; the comparison is between that threshold and the retrieval results; the observable result is that low-relevance content is filtered. Permission and entity isolation still require separate checks.
2. Treating RRF as a switch that can be turned on. The input is a hybrid retrieval configuration; the comparison is against the multi-path recall fusion process; the observable result is the fused candidate set. This process has no separate switch.
3. Treating evidence pending submission as completed submission. The input is the chargeback notice source text and the draft sentence; the comparison is on the same status field; the observable result is that the two values are mutually exclusive, and the draft sentence is not supported.

## How to verify the setup

1. Input the chargeback notice and delivery record source text above, and compare the status field in the draft sentence against the source text. If the source text records only evidence pending submission while the draft sentence asserts closure, the draft sentence is judged not supported.
2. Input a retrieval request containing only the chargeback notice and no delivery record, and compare the cited content array against the source text. If the array contains only the chargeback notice entry, the citation source matches the original, and the delivery fact remains pending verification.
3. Input an empty array as the cited content output and compare it against the downstream answer step design. If the downstream handles the empty citation and the path runs through, the empty-result handling matches the documented behavior. This does not establish that a retrieval will necessarily return empty.

For document timeliness, test the source with a current version and a historical version, and whether a citation is adopted still depends on review of the effective version. Retrieval and form collection produce values; business verification, approval, database writes and external synchronization require their own downstream implementation.
