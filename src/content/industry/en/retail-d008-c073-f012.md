# Cross-border payment reviews: document chunking for multilingual work

## What the documents look like

Cross-border independent-site payment risk work centers on card-network disputes and receiving accounts. The daily material set includes payment chargeback notices, fraudulent order lists, invoices and proof of delivery. These records frequently mix Chinese, English and other languages in the same file. A single chargeback notice may carry a card-network rule number, a transaction amount, the cardholder's stated reason and a response deadline in one block of text. Updates arrive daily or per order.

For document parsing and chunking, this mix creates a specific demand: the chunk must keep identifiers, amounts, deadlines and the identity of the parties attached to the statements that constrain them. Conditions, explanations and the content they govern belong in the same unit. When a deadline sits in a separate chunk from the dispute it belongs to, retrieval can return the date without the case it applies to. The same risk applies to rule numbers and amounts. Multilingual mixing and dense identifiers mean that segment completeness and full-text retrieval capability directly affect how quickly dispute evidence can be assembled.

## Constraints at the document chunking step

Chunking follows the structure of the actual material. A condition, an explanation and the content that condition limits stay together. One group of source data may map to more than one index, and a retrieval hit on any one of those indexes recalls that group. Building multiple indexes for the same chargeback notice helps cover different phrasings of the same fact.

Semantic retrieval supports cross-language understanding, so a Chinese question can match an English knowledge point, but precision depends on the quality of the vector model and on keyword and sentence completeness. Full-text retrieval suits exact lookups such as numbers, model designations and proper nouns. Hybrid retrieval combines semantic and full-text recall and merges the two result sets through RRF. The citation limit is measured in tokens. The minimum relevance value takes effect only under semantic retrieval or when result re-ranking is used. The minimum relevance value is a filter threshold, not a final ordering rule.

Retrieval does not perform authorization checks. Search scope covers the whole library, and collections serve only to classify data; they do not affect search results. A retrieved fragment does not establish that a business action was approved.

Hypothetical paper test case: an independent-site merchant receives an English chargeback notice. The source text reads: "Dispute ID: CB-2024-0871. Transaction amount: USD 320.00. Reason: merchandise not received. Response deadline: 2024-06-15." The proposed draft sentence under review is: "The response deadline for this chargeback notice is 2024-06-15, and the dispute reason is merchandise not received." The check compares the Dispute ID, amount, reason and deadline in the source text against the draft sentence. This is a paper exercise; no live retrieval, training or business action is claimed.

## Three common errors

1. Treating a retrieval result as an authorization basis. Input a retrieval request for a chargeback notice, compare the returned content against the authorization status field, and if the returned content contains only document fragments and no authorization record, the retrieval does not establish that the operation was approved. A pending review does not show that an operator lacks permission, and an unsigned termination is not a completed termination.

2. Treating a successful upload as an updated index. Input an updated chargeback notice, compare the upload time against the actual training status, and if training has not completed, retrieval may still return the previous content. Upload success and index refresh are separate facts.

3. Reading the minimum relevance value as a business filter. Input a query containing an identifier, compare results before and after filtering, and if the identifier is filtered out because its semantic score is low, switch to full-text or hybrid retrieval. A relevance score is not a category, entity or permission filter, and a similarity setting does not exclude unrelated businesses or unauthorized records.

## How to verify the setup

1. Input the English chargeback notice from the hypothetical sample and the proposed draft sentence. Compare the deadline and the reason in the draft sentence against the source text. If both match, the chunk retained the key fields. If the deadline appears without the dispute it belongs to, record the gap rather than assuming a rule.

2. Input the Dispute ID "CB-2024-0871" as a full-text query. Compare whether the returned result contains the passage holding that identifier. If it does, exact lookup is available for this case. A first-hit guarantee is not claimed, and an unrelated query returning empty is not guaranteed.

3. Input the Chinese question "What is the deadline for this chargeback?" Compare whether the returned content points to the same notice. If it does, cross-language semantic retrieval worked for this case. If the result is empty, record the gap and do not infer that a rule necessarily returns an empty result.

Libraries using different vector models cannot be associated together. Check the model identifier first and exclude libraries that do not match; do not run a cross-model retrieval to compare missed recalls. For an empty result, a paper input of [] may be used to check downstream design, without claiming that a fictional rule returns [].

Distinguish four kinds of items: behavior a node already performs, fields that are actually configurable, manual verification actions, and business actions that require a separate system implementation. RRF is a merge process for hybrid results, not an on/off switch. Forms collect values; business verification, approval, database writes and external synchronization require their stated downstream implementation. Scheduled triggers and hidden controls are not assumed. Without a documented error code or an actual observation, describe what to compare and what remains unknown.
