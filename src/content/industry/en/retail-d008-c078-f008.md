# Chain-store site selection: workflow routing for multilingual work

## What the documents look like

Chain-store site selection happens before a store opens. Its core work is lease negotiation and engineering handover, which places it in a different business stage from post-opening store supervision. The documents handled at this stage include site evaluation forms, lease letters of intent, renovation budgets and opening schedules. The main data sources are trade-area footfall, map POIs, POS records of historical store types and landlord materials. Updates are irregular and occur per store. This page does not derive batch synchronization, full synchronization, real-time or transaction-triggered mechanisms from that frequency.

Cross-border materials and multilingual retrieval treat these documents as retrieval targets. One lease letter of intent may exist in several language versions, and a site evaluation form may be completed by regional development staff and then checked by an engineering manager. Retrieval results support human judgement. They do not constitute lease authorization, engineering approval or a payment basis.

## Constraints at the workflow routing step

Workflow routing here involves the form input node and the user selection node. Both are user interaction nodes. When either is triggered, the conversation enters an interaction state and the workflow state is recorded; after the user completes the interaction, the workflow continues downward. The form input node collects required information and passes it to later nodes. The user selection node evaluates the user's choice and executes the corresponding "yes" branch. State recording is behavior of the interaction node; no separate global state-recording switch is documented. Retrieval nodes and form nodes carry no authorizing effect: retrieval is not authorization, and collected form values are not business verification, approval, a database write or external synchronization. Those actions require a separate business interface or a later process.

Hypothetical paper exercise sample (paper materials, not a real customer): on 10 March 2025 a chain headquarters development department receives a scanned lease letter of intent stating "Lessor: certain real estate company; Lessee: chain headquarters development department; intent deposit: RMB 50,000; quotation valid until 30 April 2025; the two parties have not signed a formal lease contract." On the same day there is a draft opening schedule stating "engineering handover milestone to be filled in after the renovation budget is confirmed." One draft sentence to be assessed reads: "The letter of intent has confirmed the lease relationship, the deposit has been paid, and renovation can be scheduled to begin."

## Three common errors

1. Treating a retrieval hit as authorization. The input is the scanned letter of intent above. If the draft sentence states "the lease relationship has been confirmed" on the basis of a retrieval result, the comparison object is the source wording "the two parties have not signed a formal lease contract." The observable result is that the draft sentence exceeds the source status, so it is unsupported.
2. Treating a pending review as missing permission. Suppose a handover request states "renovation entry pending approval," while the materials only state "engineering handover milestone to be filled in after the renovation budget is confirmed." The comparison object is the pending item described in the source. The observable result is that a pending confirmation is misread as a denial or as missing permission.
3. Treating a quotation validity period as a supply period. The input is "quotation valid until 30 April 2025." If the draft sentence says "supply until 30 April 2025," the comparison object is the meaning of the validity period in the same field. The observable result is that the field meaning has been replaced, filling an evidence gap.

## How to verify the setup

1. Use the hypothetical sample above to check the draft sentence. The input is the three source sentences from the letter of intent and the draft sentence "The letter of intent has confirmed the lease relationship, the deposit has been paid, and renovation can be scheduled to begin." Compare the same subject, the same period and the same field: the source states that no formal lease contract has been signed, while the draft sentence claims the lease relationship is confirmed. The two are mutually exclusive in the same field. When this condition is met, the draft sentence is judged unsupported. The expectation is to preserve the evidence gap; no actual test is claimed.
2. Use an explicit paper input to check the empty-result handover. The input is a retrieval return of []. Compare whether the downstream node design has an explicit handover path for an empty result. The condition is met when the downstream does not interpret the empty result as "no related business" or "no permission." No claim is made that a fictional rule retrieval must return [].
3. Use the interaction node output to check handover. The input is the required information collected by the form input node. Compare whether later retrieval, judgement or interface nodes take over that output item by item. The condition is met when outputs correspond to inputs item by item and any external write or synchronization has a separate interface description. No guarantee is made of a first hit or full recall.

Optional paths shown in the overall document flow diagram are not executed on every request: image retrieval requires a corresponding image input and model capability, and reranking requires a model and must be enabled according to settings. Semantic recall and relevance do not handle permission or entity isolation. Fields that are not stated, or for which only related-stage evidence exists, are recorded as pending verification.
