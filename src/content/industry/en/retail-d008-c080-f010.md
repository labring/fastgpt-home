# Store price and display checks: citation tracing for multilingual work

## What the documents look like

Price and display audits take place during day-to-day operations, where the focus is sustained execution of standards rather than launch preparation. The working base combines supervisor systems, POS price tables, store camera records and head-office promotion calendars. Daily documents are store-visit photographs, price tag lists, display standards and rectification notices.

In cross-border settings a single price tag list may exist in several language versions, so the retrieval step must connect quoted content back to a specific source document. Material updates follow a weekly or monthly rhythm, and citation checks must be based on the version currently in force.

## Constraints at the citation tracing step

The knowledge base search node can be linked to one or more knowledge bases that use the same vector model, and it outputs quoted content as an array whose length may be zero. When nothing is retrieved, the output path still completes.

The citation limit is controlled in tokens. The minimum relevance value applies only during semantic retrieval or result re-ranking; it is a filtering threshold and does not perform permission or entity isolation. Retrieval scope is determined by the knowledge bases already selected, and retrieval by itself is not authorization. Hybrid retrieval merges multiple result paths through RRF, re-ranking requires a re-rank model enabled by configuration, and image retrieval requires image input plus the corresponding model capability. Knowledge bases with different vector models cannot be linked together; the model identifier must be checked first and non-matching bases excluded.

Hypothetical drill sample: a chain brand's operations department audits a store in March 2025. The materials are the price tag list text "This store's product A is marked at 12.5 yuan, promotion period 1 March to 31 March 2025", and the store-visit photograph note "photographed 10 March 2025, shelf price tag shows 12.5 yuan". The proposed judgement sentence is "the store applied head-office pricing during the promotion period". The request is "please retrieve the March price tag basis for this store from the knowledge base and give the citation source". This request is pending; neither the retrieval result nor the authorization status has been confirmed.

## Configuration and implementation checks

| Configuration item | Setting or check | Relation to the sample |
| --- | --- | --- |
| Linked knowledge bases | Select one or more knowledge bases with the same vector model | Check the vector model identifier of the store audit knowledge base |
| Search mode | Semantic, full-text or hybrid retrieval | Price tag identifier questions suit full-text or hybrid retrieval |
| Citation limit | Controls quoted content length in tokens | Hypothetical starting point set to cover two to three price tag records, compared against single-record length |
| Minimum relevance | Value from 0 to 1, effective only in semantic retrieval or re-ranking | Hypothetical starting point set to a mid value, compared against the sample citation score |
| Result re-ranking | Re-rank model present and enabled by configuration | Used for secondary ordering when candidates are numerous |
| Quoted content output | Array format, length may be zero | Downstream must still accept an empty array |

## Three common errors

1. Treating a retrieval result as an authorization basis. Retrieval only returns quoted content; whether the store's price tag execution complies must be checked manually by the operations department against the version in force. A successful retrieval does not mean approval is complete.
2. Treating the minimum relevance value as an entity or permission filter. That value only filters low-relevance results and cannot exclude unrelated stores or unauthorized records; cross-store data isolation requires a separate system implementation.
3. Forcing knowledge bases with different vector models into a joint link. The documentation requires the same vector model for joint linking; where identifiers do not match, the base should be excluded and the observation recorded, without proceeding to comparison.

## How to verify the setup

1. Input the price tag list text and the proposed judgement sentence from the hypothetical sample. Compare whether the quoted content points to this store, this product and this promotion period, and observe whether the citation array contains the corresponding source passage. If the citation points to another store or another period, the condition is not met.
2. Input a clearly paper-based empty result []. Compare whether the downstream answer step still completes and returns a no-citation notice. If the downstream step errors out and terminates, the condition is not met.
3. Input a knowledge base identifier with a different vector model. Compare whether the system permits joint linking. If the identifier does not match, the base must be excluded and the actual observation recorded, without running cross-model retrieval to compare missed recall.

This page addresses only: chain store price and display audits / cross-border materials and multilingual retrieval / citation tracing. When operations hands over, which materials, actions and requests are in what authorization state must not be confused with retrieval or a form acting as authorization.
