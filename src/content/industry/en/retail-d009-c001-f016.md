# B2B marketplaces: interactive forms for operations handover

## What the documents look like

B2B marketplace matching operations revolve around four document families: enterprise certification materials, inquiry and quotation sheets, electronic contracts, and platform settlement statements. Compared with wholesale-market stall trading, online certification and electronic contracts are more common, and transactions do not depend on a physical stall. That difference shapes what an operations handover must check. The receiving and sending operators need to confirm the review status of a given certification record, whether a given electronic contract has been signed, and whether a given settlement statement has entered the settlement process. A retrieval result or a form submission does not replace those status checks.

Data sources named in the brief are the B2B platform, the National Enterprise Credit Information Publicity System, payment records, and logistics traces. Update frequency is daily and per order. The most time-consuming steps are reviewing enterprise identity, matching inquiries and quotations, and tracking performance. Each step involves a permission boundary: who may view, who may submit, and who may confirm. Those boundaries have to be written out item by item during handover. This page addresses only the interactive forms step of operations permission and handover management.

## Constraints at the interactive forms step

The Form Input node is a user-interaction node. When it is triggered, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. The node collects the information the user fills in and passes it to later nodes. It does not carry a business database function of its own.

The User Selection node is also a user-interaction node. When triggered, the conversation enters an interaction state and the workflow state is recorded. When the user makes a selection, the node evaluates that selection and executes the corresponding branch. Neither node performs business approval, database writes, or external synchronization.

Hypothetical paper exercise. An operations staff member A hands over one matching transaction to operations staff member B. The three source sentences available for checking are: "Supplier A's enterprise certification materials passed the platform's initial review on 10 March 2025; the re-review status is pending." "Inquiry and quotation sheet number XJ-2025-0312 records purchaser B's quotation request for rebar, valid until 20 March 2025." "Electronic contract HT-2025-0315 is in a pending-signature state; purchaser B has not completed signing." The handover request to be assessed is: "Transfer both the re-review permission for Supplier A and the signature-confirmation permission for contract HT-2025-0315 to B; after transfer, B may sign on behalf of purchaser B." In this request the re-review status is pending, the contract is pending signature, and purchaser B has not signed. Signing on another party's behalf falls outside the operations permission scope and cannot be replaced by a form submission or a user-selection branch.

## Configuration and implementation checks

| Configuration item | Type | What this page checks |
| --- | --- | --- |
| Form Input node | Documented node behavior | Enters interaction state on trigger; collects filled information and passes it to later nodes |
| User Selection node | Documented node behavior | Enters interaction state on trigger; executes the branch matching the user's selection |
| Required-field setting | Actually configurable field | List the information this task cannot omit; check the missing-item case and the completed case separately |
| Field validation | Requires a separate system implementation | The form node carries no validation; validation logic runs in later nodes or an external system |
| Handover status record | Manual checking action | Re-review pending and contract pending signature are confirmed by hand, not by retrieval |
| Signature-confirmation permission | Requires a separate system implementation | Signing on another's behalf needs business-system authorization; a form submission does not create that permission |

Hypothetical starting value for this exercise: set the "re-review status" field as required, because that status determines whether the handover can proceed. Compare it against the source sentence "the re-review status is pending." When the field is missing, the form should not submit. This starting value is set for this exercise and is not an official default.

## Three common errors

1. Treating a form submission as completed authorization. In the exercise, B submitting the form signals acceptance of the handover. That action does not change the pending re-review status and does not create a signing-on-behalf permission.
2. Treating a user-selection branch as a personnel directory. The User Selection node executes a branch according to the selection; it does not assign personnel permissions. In the exercise, "selecting B" does not mean B obtains signature-confirmation permission.
3. Treating a retrieval hit as status confirmation. Retrieval results do not perform permission or entity isolation. In the exercise, retrieving contract HT-2025-0315 does not mean the contract has been signed.

## How to verify the setup

1. Input the three source sentences and the handover request. Compare "sign on behalf of purchaser B" in the request against "purchaser B has not completed signing" in the source. Observe whether the form or User Selection node executes a signing-on-behalf branch. Expected: the node does not execute signing on behalf; that permission requires external-system authorization.
2. Input the source sentence "the re-review status is pending." Compare whether the required field "re-review status" is filled in. Observe whether the form submits when that field is missing. Expected: with the field missing, the interaction state does not end and the submission does not pass.
3. Input the source sentences and the request. Compare "transfer the re-review permission" against "the re-review status is pending." Observe whether the status changes after handover. Expected: the status remains pending; a change requires a business-system operation and is not completed by the form node.
