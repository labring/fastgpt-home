# MCN operations: citation tracing for operations handover

## What the documents look like

An MCN manages long-term account compliance for multiple creators, so its records run in parallel rather than serving one brand session. Four document types circulate: creator signing contracts, training records, violation handling forms, and account scheduling. Operations permission and handover work needs traceable citation relationships between these documents. A violation handling form cites a specific version of a contract clause. A scheduling adjustment cites a specific training record. During handover, the receiving side needs to follow the citation chain back to the original material.

Data sources are the MCN backend, platform violation notices, creator account data, and the contract ledger. Update frequency is daily or weekly. The core question for citation tracing is whether every conclusion in a handover package can be located to a specific document, a specific version, and a specific status. The retrieval step only returns candidate content. It does not decide whether material is valid or whether an operation has been approved.

## Constraints at the citation tracing step

The knowledge base search node selects one or more knowledge bases that share the same vector model and outputs a citation array. The array length can be zero, which means the output path still runs even when nothing is found. The citation limit is controlled in tokens. The minimum relevance value takes effect only in semantic retrieval or when result reranking is used, and it is a filter threshold. It does not perform permission or entity isolation. Hybrid retrieval merges multiple result paths through RRF. Reranking requires a model and must be enabled by configuration. Image retrieval requires image input and model capability. Optional paths in the documented flow do not mean every request executes all of them.

After retrieval results pass to the answering step, each answer statement must be checked against the cited original text. A thinking process or a fluent answer does not replace source evidence. Material timeliness checks use the current version and a historical version separately to test the source. Whether a citation is adopted still depends on review of the valid version. Retrieval recall does not constitute authorization. A form collecting values does not mean business verification, approval, a database write, or external synchronization has completed; those actions need their own downstream implementation.

Hypothetical paper exercise sample: Material text one: "Creator A signing contract (number HT-2024-011), valid until 31 December 2025, account compliance clause 7 requires violation handling to carry dual signatures from the agent and content review." Material text two: "Creator A violation handling form (number WG-2024-033), status pending dual signature, agent signed, content review not signed." The proposed handover request sentence to be judged: "Creator A account compliance is confirmed; scheduling handover may proceed." The comparison objects are the two material texts above and the request sentence. The valid scope is limited to the December 2024 handover batch. The authorization boundary is that before dual signature completes, the state is not executable.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this exercise | Reason for the choice and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Contract ledger base and violation handling form base, both using the same vector model | Only the same vector model can be associated together; check the vector model identifier first and exclude inconsistent ones |
| Search mode | Hybrid retrieval | Numbers HT-2024-011 and WG-2024-033 are exact queries, and hybrid retrieval uses semantic recall and full-text recall together |
| Citation limit | Set in tokens, compared against the combined length of one contract clause plus the handling form summary | This value is a starting point for this exercise, not an official default; compare whether recalled content covers the key sentences of both materials |
| Minimum relevance | Takes effect in semantic retrieval or reranking, compared against recalled fragment scores | This value is a filter threshold and is not used to exclude unrelated business or unauthorized records |
| Question optimization | Enabled or disabled according to observed effect | Enable when multi-turn references are unclear; a single clear question can disable it to reduce latency |
| Result reranking | Enabled by configuration when a ReRank model is available | The rerank score is 0-1 and is used for secondary ordering; it does not perform permission decisions |

## Three common errors

1. Treating retrieval recall as an authorization basis. The input is the proposed request sentence "Creator A account compliance is confirmed; scheduling handover may proceed." The comparison object is the pending dual signature status of violation handling form WG-2024-033. If the presence of a returned contract clause and handling form summary is taken as grounds that handover may proceed, the authorization boundary that dual signature is incomplete has been ignored.

2. Treating minimum relevance as an entity or permission filter. The input is a low-relevance query. The comparison object is whether recalled results contain other creators' materials. If raising the relevance threshold is expected to exclude unauthorized records, similarity filtering has been confused with permission isolation. Retrieval itself does not perform authorization.

3. Treating an empty citation array as a process failure. The input is a retrieval that matched no content. The comparison object is the node output array length. If a zero-length array is judged to mean the workflow errored and stopped, this conflicts with the documentation: the output path still runs with an empty array, and the downstream side must be designed to accept an empty result.

## How to verify the setup

1. Input the two material texts from the hypothetical sample and the proposed request sentence. Compare the "confirmed" wording in the request against the "pending dual signature" status of handling form WG-2024-033. Observe whether the retrieval output recalls both the contract clause and the handling form summary, and whether the check conclusion marks that dual signature is incomplete and the state is not executable.

2. Input the same request sentence and check the citation display. Compare each conclusion in the answer against the cited original text. Observe whether the answer maps statement by statement to clause 7 of HT-2024-011 and the status field of WG-2024-033. If the answer contains an "approved" statement not present in the materials, the citation display and the original text are inconsistent.

3. Input an explicit paper empty result []. Compare the downstream handover process design. Observe whether the downstream side continues through with zero citations and marks the source as missing. If the downstream side treats the empty array as an error and stops, the empty-result handling has not been configured according to the documented condition.

These checks are paper reasoning only. No retrieval, approval, refund, or any business action was actually executed.
