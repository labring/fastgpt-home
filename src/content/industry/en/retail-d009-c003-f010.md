# Shopify fulfillment: citation tracing for operations handover

## What the documents look like

A Shopify storefront is configured by the merchant. Payment, shipping and fulfillment services sit with the merchant rather than with a single platform that also handles returns automatically. The materials relevant to a handover therefore come from several places: order details, shipping templates, shipping labels and refund records, drawn from Shopify Admin, payment gateways, carrier systems and inventory location data.

Each of these materials carries a different kind of status. A shipping template is a configuration item. A shipping label is a carrier-side product. A refund record is a payment-gateway-side result. When operations staff hand work to a colleague, citation tracing means the receiving person can check which system each material came from, which order it belongs to, and which step it has reached. Order-level and daily updates are the documented cadence; a handover check works at the level of a single order and does not assume batch synchronization.

## Constraints at the citation tracing step

The knowledge base search node can associate one or more knowledge bases that share the same vector model, and it outputs citations as an array whose length may be zero. An empty array still passes through the output path; it does not by itself mean the workflow has failed or stopped.

Similarity and the minimum relevance threshold act as filtering thresholds. They do not perform permission isolation or entity isolation, and retrieval by itself does not constitute authorization. The citation limit is measured in tokens and is unrelated to thinking budgets. Optional paths shown in the overall retrieval diagram, such as image retrieval and Rerank, require the corresponding inputs and model capability and must be enabled by configuration; their presence in the diagram does not mean every request executes all of them.

A hypothetical paper exercise sample is provided here for illustration. The source material reads: "Order A-1042, created on 11 March 2025, product X, quantity two, payment gateway status captured, carrier system shows label purchased and not yet picked up, refund record empty." A draft sentence under review reads: "Order A-1042 refund completed, handover can be closed." This draft misreads an empty refund record as a completed refund and does not identify an authorizing person.

| Citation handoff | Review each answer line against the source text | Check whether the output array is passed to the answering step |
| Material version check | Use one current version and one historical version | Compare source versions and confirm which version is used |

## Three common errors

1. Treating an empty refund record as a completed refund. The input is the refund record field for order A-1042; the comparison object is the payment gateway refund status; the observable result is an empty field coexisting with an unconfirmed status.
2. Treating a retrieval hit as operational authorization. The input is the citation array returned by the knowledge base search; the comparison object is the handover authorization boundary; the observable result is that the citation content contains no authorizing signature.
3. Associating knowledge bases that use different vector models. The input is the vector model identifiers of two knowledge bases; the comparison object is the documented same-model condition; the observable result is that they cannot be associated together when the identifiers differ.

## How to verify the setup

1. Input the hypothetical sample source text and the draft sentence; compare whether the draft sentence matches the empty refund record; the result is a fail when the draft sentence conflicts with the source text.
2. Input an explicit paper empty array []; compare whether the downstream answering step passes through; the result satisfies the empty-citation handoff condition when the chain is not interrupted.
3. Input two knowledge bases whose vector model identifiers differ; compare whether the identifiers match; when they do not match, exclude that base and record the actual observation, without running a cross-model retrieval comparison.
