# Temu semi-managed sellers: interactive forms for operations handover

## What the documents look like

Semi-managed Temu sellers differ from fully managed suppliers because they maintain overseas inventory and ship orders themselves, which brings warehouse management systems and logistics tracking into the document set. The working documents in this category are the product declaration form, the overseas inventory table, the price declaration, and the platform fulfillment order, with updates occurring daily or per order. For operations permission and handover management, the central question is which materials, operations, and requests sit at which authorization state when a shift or role change takes place.

Two facts shape the interactive forms step directly. First, the overseas inventory table and the platform fulfillment order carry per-order or daily states, so a handover request can reference a document whose status is still pending. Second, the price declaration and the inventory table use different date concepts, and treating one as the other changes the scope of what is being handed over. The form input node collects filled-in information and passes it to later nodes after submission, and the user selection node runs a branch according to the user's choice. Neither node grants permission or writes to a business database.

## Constraints at the interactive forms step

The form input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. The user selection node behaves the same way at the interaction level and then evaluates the user's choice to run the "yes" branch. The interaction state is not a personnel directory, a business data selector, or an authorization mechanism. Field validation, business approval, write-back, and batch operations belong to external systems or later nodes as needed.

Hypothetical paper exercise sample. The materials supplied for checking are as follows. Overseas inventory table A lists SKU-001 at the Germany warehouse with a quantity of 120 units and a status of on sale. Price declaration B states that the declared price for SKU-001 has an effective date range of 1 March 2024 to 31 March 2024. Platform fulfillment order C shows one pending shipment order for SKU-001 with a status of pending review. The handover request to be assessed is: transfer the inventory adjustment permission and the price declaration submission permission for SKU-001 to the next shift operator.

In this request, the materials do not state the authorizing party or scope for the inventory adjustment permission. Price declaration B carries only a quotation validity period and does not state a supply period. Fulfillment order C is at pending review. A pending review is not an approval and is not an executed action.

## Configuration and implementation checks

| Configuration item | Type | What this page checks |
| --- | --- | --- |
| Form input node | Documented behavior | Enters interaction state on trigger, collects required information, passes it to later nodes after submission |
| User selection node | Documented behavior | Runs a branch according to the user's choice; does not act as a personnel directory |
| Required information check | Implementation check | List the fields this task cannot omit, then test the behavior when a field is missing and when it is supplied |
| Handover request state | Implementation check | Check whether the request states the authorizing party, the object, and the effective scope |
| Pending review state | Implementation check | Pending review is not treated as approval and not treated as executed |
| Downstream business action | Implementation check | Field validation, approval, and write-back require an external system or a later node |

For this hypothetical trial, the starting point is to set the required fields to inventory quantity, declared price, and fulfillment order number. The reason for this choice is that these three items directly relate to identifying the object in the handover request. The comparison method is to remove each field in turn and observe whether the interaction state continues to wait. This starting value is a hypothetical trial setting, not an official default.

## Three common errors

1. Treating the quotation validity period in price declaration B as a supply period. The material states only that the declared price effective date runs from 1 March 2024 to 31 March 2024, and it does not state a supply period. The check compares whether this field is used to judge the scope of the handover; if it is cited for that purpose, the inference goes beyond the source text.

2. Treating the pending review status of fulfillment order C as approved or executed. The material shows the status as pending review and states no approval record. The check compares whether the handover request relies on that status as the basis for transferring permission; if it does, the approval evidence is missing.

3. Treating retrieval results or form collection as an authorization action. The form input node collects filled-in information and passes it to later nodes and does not grant permission. The check compares whether the handover request asks the form submission to complete the permission change directly; if it does, collection and authorization have been conflated.

## How to verify the setup

1. Input the material text and the handover request from the hypothetical sample, then compare whether the request states the authorizing party, the object, and the effective scope. If the materials do not state the authorizing party for the inventory adjustment permission, record the result as unsupported and log the evidence gap. Do not record it as a denial or a conflict.

2. Input the date range 1 March 2024 to 31 March 2024 from price declaration B, then compare whether that field is used to infer a supply period. If the handover request cites the date as a supply period, record the result as beyond the source scope. If the request cites it only as a quotation validity period, the use matches the source text.

3. Input the pending review status from fulfillment order C, then compare whether the handover request treats it as approved. If the request transfers permission directly on the basis of that status, record the result as missing approval evidence. If the request marks the item as pending verification and keeps the gap open, the use matches the requirement that pending review is not approval. All three checks are paper comparisons and were not executed against a live system.
