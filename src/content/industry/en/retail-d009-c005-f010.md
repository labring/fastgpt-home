# TikTok Shop US operations: citation tracing for operations handover

## What the documents look like

TikTok Shop US store operations work under local return windows, return grading, and overseas logistics constraints. The daily materials for this category concentrate in product listings, return and refund records, return grading evidence, and settlement statements. These materials update daily and per order. The point that most often breaks during handover is that a material is only a record: retrieving a record does not mean the current operator holds the authority to act on it. Operations authority and handover management require separating the material, the action, and the authorization status of a request. Citation tracing answers the question of which sentence in which material supports a conclusion.

Because citation content is returned as an array and its length can be zero, the output path still completes when nothing is retrieved. A blank citation in a handover document therefore only shows that this retrieval returned no content. It does not support a conclusion that the material is absent or that authority has lapsed. Knowledge base search can only associate knowledge bases that share the same vector model, so cross-model association is not available. A minimum relevance value is a filter threshold that takes effect only under semantic retrieval or result reranking, and it does not perform permission filtering or entity isolation. Retrieval output must be passed to the answering step and checked line by line against the cited source text; fluent answers and thinking traces do not replace source evidence.

## Constraints at the citation tracing step

The following hypothetical drill sample is used throughout this page. It is a paper exercise, not a record from any real store or person.

Material sentence one: "From March 1, 2025 to March 31, 2025, after-sales specialist A is responsible for handling return and refund records for store B, and the authority to upload return grading evidence belongs to after-sales specialist A."

Material sentence two: "The authority to verify settlement statements for store B belongs to operations specialist C, effective March 1, 2025."

Draft handover request sentence to be assessed: "After-sales specialist A may verify settlement statements for store B on behalf of others and sign to confirm."

In this request, the subject is after-sales specialist A, the object is the settlement statement, and the requested action is verification and signing confirmation. The material states only that after-sales specialist A holds return and refund handling authority and return grading evidence upload authority. Settlement statement verification authority belongs to operations specialist C. Whether after-sales specialist A holds settlement statement signing authority is not stated in the material, so it remains pending verification.

This sample keeps the evidence gap open. The material does not add an authorization or effective clause that would produce a definite answer. The stage is a draft request, not an approval. A pending request is not approval, and an unsigned confirmation is not a completed act.

## Three common errors

1. Treating a retrieval result as an authorization credential. In the drill sample, a retrieved record showing after-sales specialist A handling return and refund records is used to conclude that this person may verify settlement statements and sign to confirm. The input is the retrieval output; the comparison object is the authority field stated in the material; the observable result is that the material does not state settlement statement authority for this person, so the finding is pending verification.

2. Treating minimum relevance as a permission or entity filter. The input is a low relevance score; the comparison object is the authority field; the observable result is that the score level does not change the authorization status, so the finding is that the score does not constitute a basis for authority.

3. Treating a pending review request as approved. The input is the draft handover request sentence; the comparison object is a signing or approval record; the observable result is that only the draft sentence exists and no signing record is present, so the finding is that the request is not supported.

## How to verify the setup

1. Use the drill sample material sentences and the draft sentence to check the authority scope of after-sales specialist A. The input is the two material sentences; the comparison object is the subject, object, and action in the draft sentence; the observable result is that the material does not state settlement statement signing authority for this person, so the finding is pending verification and the evidence gap is recorded.

2. Use the explicit paper input [] to check the empty-citation handoff. The input is a defined empty array; the comparison object is the design of the downstream answering step; the observable result is that the downstream step does not treat the empty array as an error or as a denial of authority, so the finding is that the handoff design meets the expectation.

3. Use mutually exclusive values for the same field to check for contradiction. The input is two records of the same authority field in the material; the comparison object is whether the values are mutually exclusive; the observable result is that only mutually exclusive values for the same field count as a contradiction, while stage-only evidence or an unstated field counts as unsupported or pending verification.

The same-subject, same-period, same-field rule applies to all three checks. A missing statement or stage-only evidence remains unsupported or pending verification, and is not recorded as a denial or a conflict. The retrieval library requirement of the same vector model does not extend to business registration sites or other external systems.
