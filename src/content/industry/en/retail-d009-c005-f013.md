# TikTok Shop US operations: operations handover with access controls

## What the documents look like

For operations handover in TikTok Shop US operations, this page examines FastGPT access controls. Transfer rights by unresolved returns and evidence tasks, checking former personnel, external platforms and image sources independently. The examples are hypothetical.

## Constraints at the access controls step

A handover exercise lists a return awaiting evidence, a completed refund and another shop’s settlement sources. The incoming operator follows the first. Identify needed return records, image descriptions and order, then inspect actual reading and operations. Receiving only the completed refund cannot establish evidence availability. Retain handover references and returns to inspect mapping. A shared title authorizes no universal shop scope; cross-shop and historical settlement access need owner confirmation.

## Configuration and implementation checks

| Handover-permission check | Return and shop boundary | Actual verification |
| --- | --- | --- |
| Current matter | Separate evidence-pending return and completed refund | Original reads and operations for new account |
| Cross-shop sources | Other settlement does not transfer automatically | Owner-confirmed scope |
| Former personnel | Revoke photo and settlement access | Full responses and denials |
| Distinct actions | Test archiving, expiry and revocation separately | Inspect external platform sessions |
| Business approval | Operation does not approve refund or appeal | Execution results and unresolved items |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Team roles` | Inspect roles for the actual member identity. |
| `Resource permissions` | Inspect reading, editing and management by resource. |
| `Document classification` | Classification and tags do not replace authorization. |
| `External-system permissions` | Verify external-interface authentication separately. |
| `Per-account validation` | Test the same source with authorized and unauthorized accounts. |

## Three common errors

- If a completed refund establishes evidence readiness, inspect the current order, image descriptions and versions beside handover lists and returns. An older result cannot replace current sources.

- If a former identity reads restricted photo or settlement text, retain full responses beyond image lists. Completed handover establishes no denial.

- If archiving, expiry or membership changes become revoked external sessions, test resources, platform and image-interface identities separately. These actions do not substitute for one another or approve refunds and appeals.

## How to verify the setup

Use the incoming identity to read current evidence, with former and unrelated-shop identities negatively tested against the same source. Record content and operations. Correct grants followed by an older return’s appearance require subject and history checks, not wider access. Technical operation does not approve refunds, deductions or appeals; inspect responsibility and platform outcomes separately. Retain resource gaps and external-revocation actions without presenting a personnel change as a resolved return dispute.
