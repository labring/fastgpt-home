# TikTok Shop US operations: interactive forms for operations handover

## What the documents look like

TikTok Shop US store operations sit under local return windows, return grading, and overseas logistics constraints. Compared with Douyin store shelf operations, the materials that matter at handover are the product listing, return and refund records, return grading evidence, and settlement statements. These materials update daily and per order. At handover, both sides need to confirm the authorization state of a specific return record, a specific settlement statement, or a specific operation request, and who is entitled to continue handling it.

The Form Input node and the User Selection node are both user interaction nodes. When triggered, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. The Form Input node collects the information the user fills in and passes it to subsequent nodes; it does not carry its own business database function. The User Selection node executes a branch based on the user's choice. Field validation, business approval, write-back, and batch operations are implemented as needed in external systems or downstream nodes. Neither retrieval nor form collection constitutes authorized execution.

## Constraints at the interactive forms step

The core constraint for handover management is that the existence of materials does not equal transferred authority, form submission does not equal approval, and a user selection branch does not equal an executed business action.

Hypothetical drill sample: a US store operations staff member A submits a handover request on June 1, 2025, asking to transfer return handling authority for store B to operations staff member C. The source text available for checking consists of three sentences. First sentence: "The return handling operation authority for store B is currently registered under operations staff member A, valid until June 30, 2025." Second sentence: "Operations staff member C's authority application was submitted on June 1, 2025, with status pending review." Third sentence: "Store B's May 2025 settlement statement has been generated, and the deduction items include a return handling fee." The draft sentence to be judged is: "Operations staff member C has obtained return handling authority for store B and may handle returns from June 1, 2025."

This draft sentence contradicts the materials. The second sentence shows C's application status as pending review; pending review does not constitute approval and does not constitute transferred authority. The validity until June 30, 2025 in the first sentence belongs to A's authority scope and does not change because C submitted an application. The third sentence only states that the settlement statement has been generated and does not concern authority ownership. The Form Input node can collect the three source sentences and pass them to subsequent nodes, and the User Selection node can set branches for "approve handover" and "do not approve handover," but the approval action itself needs to be implemented in an external system or a downstream node. The nodes do not complete approval automatically.

## Three common errors

1. Treating pending review status as approved. The second sample sentence states clearly that C's application status is pending review. If the draft sentence says C has obtained authority, that treats pending review as approval. Pending review does not demonstrate the absence of operation authority, and it does not constitute transferred authority.

2. Treating form submission as business execution. The Form Input node collects information and passes it to subsequent nodes; it does not carry its own business database function. Treating submission of a handover request as completion of authority transfer treats an existing node behavior as a downstream business action.

3. Treating settlement statement generation as authority evidence. The third sample sentence only states that the May 2025 statement has been generated and includes a return handling fee, which is unrelated to authority ownership. Using statement generation to support the conclusion that C has obtained authority uses evidence across fields.

## How to verify the setup

1. Input the three source sentences and the draft sentence, and compare whether the subject, period, and field in the draft sentence match the materials. Expected observation: the draft sentence states C has obtained authority, while the second source sentence states C's status is pending review. The same subject and same field hold mutually exclusive values, so the draft is judged unsupported.

2. Input the handover request and check whether the content passed after Form Input submission matches the filled content. Expected observation: the content received by subsequent nodes includes the three source sentences and the draft sentence. If the passed content is missing source text, record it as incomplete passing and do not judge it as an approval result.

3. Trigger the User Selection node, choose the "do not approve" branch, and check whether the executed branch corresponds to the choice. Expected observation: the workflow enters the "do not approve" branch and continues downward. If the executed branch does not match the choice, record the actual observation and do not infer a system error cause.
