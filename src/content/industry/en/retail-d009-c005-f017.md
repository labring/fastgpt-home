# TikTok Shop US operations: upgrades for operations handover

## What the documents look like

US TikTok Shop operations sit under local return windows, return grading and overseas logistics constraints. The working documents are product listings, return and refund records, Return Grading evidence, and settlement statements. Those materials update daily and per order. The handover step concerns which materials, operations and requests hold which authorization state. Document refresh frequency does not change the scope of this page, and neither retrieval nor a form constitutes authorization.

## Constraints at the upgrades step

Version upgrades begin by checking the current version, the target version and the matching upgrade notes. Current behaviour is not inferred from an old configuration name. The V4.17.2 upgrade notes list two manually triggered scripts: historical chunk training task migration (`20261008_migrate_chunk_training`) and knowledge base rebuild status migration (`20261009_migrate_dataset_rebuild_status`). The second depends on the first completing, and neither blocks service startup. Before execution, all old-version FastGPT App and Pro instances must be fully stopped and old task leases must have expired. `AIPROXY_API_ENDPOINT` and `AIPROXY_API_TOKEN` are required for App and Admin; a missing item causes startup validation to fail. Retrieval does not perform permission or entity isolation, and a relevance score does not constitute an authorization decision.

Hypothetical drill sample: the handover material reads "Store A return and refund record directory, transferred on 8 October 2026 from operator A to operator B; the directory contains Return Grading evidence images and settlement statements for 1 October to 7 October; operator B's account permission is read-only view." The draft sentence under review reads "Operator B has obtained return and refund operation permission and may execute refund approval." The sentence involves subject operator B, object return and refund operations, and the state of read-only view permission. The judgement compares the permission field with the operation type.

## Three common errors

1. Treating read-only permission as operation permission. In the sample, operator B's permission field is "read-only view", while the draft sentence says "may execute refund approval". Comparing the permission field with the operation type shows no match, so the draft sentence is unsupported.
2. Treating a pending review state as completed authorization. The handover material records only the transfer fact and states no approval outcome. Comparing the material fields with the authorization state shows the approval record is absent, so the matter is pending verification.
3. Treating a retrieval result as a permission basis. A relevance score does not constitute a category, entity or permission filter. Comparing retrieval output with the permission field shows no correspondence, so retrieval produces no authorization.

## How to verify the setup

1. Input the sample source text and the draft sentence, then compare the two fields "read-only view" and "refund approval". The draft sentence is supported only when the permission field explicitly includes refund approval; in the sample the field is read-only, so it is unsupported.
2. Input the upgrade script status fields and compare the execution order of `20261008` and `20261009`. The condition matches the upgrade notes only when `20261008` has completed and the dependency for `20261009` is satisfied; if the `20261008` status is not executed, `20261009` does not meet its execution condition.
3. Input the retrieval return result and the permission field, then compare whether an authorization mapping exists between them. Retrieval output carries no permission information, so it cannot be used to decide that operator B may execute a refund; permission decisions require a separate downstream implementation. For an empty result, a paper input of `[]` can be used to check the downstream design, without asserting that a fictional-rule query necessarily returns `[]`.
