# Refund-only disputes: operations handover with access controls

## What the documents look like

For operations handover in Refund-only disputes, this page examines FastGPT access controls. Transfer access by open request and evidence package, checking former-personnel revocation and external service-backend identity. The examples are hypothetical.

## Constraints at the access controls step

A handover exercise lists a request awaiting evidence, a completed dispute and current parcel records. The incoming operator handles the first. Inspect actual access to current request, shipping and receipt sources, retaining order, parcel and version. A readable closed dispute establishes no complete current evidence. A filename configures no grant. The owner confirms necessary operations instead of treating a similar service job as automatic transfer of every historical chat and platform source.

## Configuration and implementation checks

| Handover-permission check | Request and evidence package | Actual verification |
| --- | --- | --- |
| Current request | Separate open evidence task and closed dispute | Order and version read by new account |
| Required evidence | Confirm shipping, receipt and chat by task | Resource reads and operations |
| Former personnel | Revoke chats and attachments | Full responses and denials |
| External identity | Inspect service backend and carrier interfaces | No synchronized invalidation inferred |
| Retention boundary | Keeping evidence grants no former access | Unresolved rights and business actions |

### Documented conditions

| Documented item / implementation check | Condition |
| --- | --- |
| `Team roles` | Inspect roles for the actual member identity. |
| `Resource permissions` | Inspect reading, editing and management by resource. |
| `Document classification` | Classification and tags do not replace authorization. |
| `External-system permissions` | Verify external-interface authentication separately. |
| `Per-account validation` | Test the same source with authorized and unauthorized accounts. |

## Three common errors

- If old-dispute access establishes current appeal readiness, compare list, order and return to inspect resource mapping. Missing evidence leaves this case unverifiable.

- If former personnel read revoked chats or receipt attachments, retain full response and configuration. Signatures and archiving establish no actual denial.

- If internal roles imply terminated platform or carrier identity, test external accounts and interfaces separately. Technical operations also approve no refund or appeal submission for the owner.

## How to verify the setup

Test current evidence with the incoming identity and the same restricted sources with former or unrelated-order identities, recording originals and operations. Correct grants with an old platform opinion need subject and input-version checks rather than wider access. Distinguish evidence retention from former-personnel access: keeping records grants no continued reading. Retain unresolved resources, external revocations and business actions without presenting completed handover as a resolved refund-only dispute.
