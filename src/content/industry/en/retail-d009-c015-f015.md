# Letter-of-credit documents: retrieval for operations handover

## What the documents look like

Letter-of-credit document examination and presentation serves the payment conditions set by the issuing bank. The working materials are the letter of credit, the commercial invoice, the bill of lading, the insurance policy and the draft. The sources behind them include the advising bank notice, UCP600 clauses, forwarder bills of lading and bank presentation records. The update cadence is per transaction, which matters here because each handover concerns one transaction set rather than a rolling pool of records.

These materials sit in different states during an operations handover. A draft may exist as an unsigned document. A received bill of lading may still await verification. A presentation request may sit at pending review. Retrieval locates relevant passages. It does not change the authorization state of any material or request.

The knowledge base is built from three levels: the library, the collection and the data. The smallest search unit is the library. A collection only classifies data and does not affect search results.

## Constraints at the retrieval step

Search runs against the whole library. When several libraries are associated, they must use the same vector model. Semantic search depends on vector distance. Full-text search depends on keyword hits. Hybrid search merges the two paths through RRF. A ReRank model reorders candidate text and returns a score between 0 and 1. The minimum relevance value takes effect only under semantic search or when result reordering is used, and it acts as a filter threshold. It does not carry permission or entity isolation.

The reference limit is measured in tokens. The output reference array can have length 0, and the downstream chain still completes when nothing is found. Question optimization handles coreference resolution and question expansion, and it adds one model call. Image retrieval requires image input and matching model capability. Reordering requires a model and must be enabled by configuration. These paths do not run on every request.

Hypothetical drill sample: a document examiner's handover record states that "commercial invoice INV-077 under letter of credit L-2024-077 was completed by examiner A on 10 May 2024 and is at pending review; bill of lading B/L-077 was issued by the forwarder on 9 May 2024 and the consignee field awaits verification." The draft sentence to be judged: "INV-077 has completed review and can be used for presentation." The retrieval request is "review status and presentation conditions for INV-077."

## Three common errors

1. Treating a retrieval hit as authorization. Recalling the INV-077 passage only means the content was retrieved. It does not mean review is complete. The input is the draft sentence and the recalled source text. The comparison is between "pending review" and "has completed review." If the source states only pending review, the draft sentence is unsupported.

2. Treating minimum relevance as a permission or entity filter. The input is a retrieval request spanning different parties. The comparison is between recalled results and the access scope. If recalled content includes records outside that scope, the parameter does not perform isolation, and a separate permission implementation is required.

3. Treating an empty reference output as an anomaly. The input is a retrieval request that matches no data. The comparison is against the output array. If its length is 0 and the downstream chain still completes, this matches documented behavior and is not an error.

## How to verify the setup

1. Input the hypothetical source text and the draft sentence. Compare "pending review" against "has completed review and can be used for presentation." If the source does not state that review was completed, the draft sentence is unsupported and is recorded as awaiting verification.

2. Input the retrieval request "review status and presentation conditions for INV-077." Compare whether the recalled content contains the INV-077 passage and the note that the bill of lading consignee field awaits verification. If recall is empty, record the gap and do not assert that a rule necessarily returns empty.

3. Input the identifiers of two libraries using different vector models. Compare the identifiers. If they differ, exclude that combination and record the observation. Do not run a cross-model retrieval to compare missed recall.

This page addresses only letter-of-credit document examination and presentation, operations permission and handover management, and knowledge base retrieval and recall. Whether materials, operations or requests sit at a given authorization state during handover is a separate fact from retrieval, and retrieval or a form does not execute authorization.
