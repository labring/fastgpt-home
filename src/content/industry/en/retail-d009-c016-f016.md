# Franchisee onboarding: operations handover with interactive forms

## What the documents look like

For operations handover in Franchisee onboarding, this page examines FastGPT interactive forms. Attendance, assessment and opening verification support different conclusions. This handover carries the applicable handbook and the store’s remaining source needs so the next reader can inspect each claim. The examples are hypothetical.

## Constraints at the interactive forms step

An opening handover can collect applicable SOP, this store’s pending work and training-source identities. Proposed input supplies attendance and an opening checklist without assessment or site confirmation. Preserve instructions and unresolved checks downstream instead of declaring handover complete from document titles. Human choices arrange evidence or reading; actual recipient roles and permissions need business design, not a presumed staff directory or opening approval feature.

## Configuration and implementation checks

| Handover check | Proposed input | Receiving evidence |
| --- | --- | --- |
| Version applicability | SOP passage and store scope | Earlier version is not treated as current |
| Assessment | Attendance without actual test | No direct competence conclusion |
| Checklist status | Opening checks still to perform | Not rewritten as completed |
| Evidence destination | Corresponding learner or store addition | Downstream actually receives it |
| Formal recognition | Separate training, opening and transfer | Submission does not replace approval |

## Three common errors

Wrong handbook version: An earlier SOP treated as current requires source and applicability checks. Attendance mistaken for competence: Attendance described as competence needs this learner’s actual assessment. Pending checklist mistaken for completion: A checklist naming pending checks described as completed needs this store’s item-specific verification. These concern version, performance and site execution separately. Neither form submission nor one selection supplies any of those outcomes.

## How to verify the setup

Trace the store question, submitted passages, selected destination and received sources. Repeat with corresponding assessment or verification and inspect downstream use. The triggered node records state, waits and continues without automatically creating profiles. Validation, formal recognition, opening approval and handover confirmation need separate authority and actual receipts. Form completion establishes neither a passing learner nor permission for the store to open.
