# On-demand retail fulfillment: citation tracing for operations handover

## What the documents look like

On-demand retail store fulfillment processes online orders on a minute-by-minute basis, in contrast with periodic stocktaking. The materials in scope include instant orders, picking lists, out-of-stock reports, and delivery exception forms. Data sources named in the brief are Douyin on-demand retail, Meituan or JD Daojia backends, store inventory, and rider tracks. Errors in this category can lead to delivery overtime compensation, false-delivery penalties, and customer refunds. These documents serve simultaneously as evidence and as operational basis during handover, so citation tracing must answer which source a quoted passage comes from, what state that source records, and who has authority to act within what boundary. The brief states that data updates at minute level and per order; this describes how materials are produced alongside orders and does not imply batch synchronization, full synchronization, or automatic triggers.

## Constraints at the citation tracing step

The dataset search node returns citation content as an array, and the length may be zero. Even when no content is found, the output path still runs. Associated knowledge bases must use the same vector model; bases with different vector models cannot be associated together. This step only verifies the identifier and excludes non-matching bases; it does not run cross-model retrieval to compare missed recalls. The minimum relevance value is a filter threshold, not a permission or entity isolation mechanism, and a similarity score does not perform authorization judgment. Hybrid search merges multiple result paths through RRF, reranking requires a rerank model enabled by configuration, and image retrieval requires image input and corresponding model capability. These are optional paths and do not mean every request executes all of them. Retrieval and form value collection do not constitute authorization; business verification, approval, database writes, and external synchronization each require their own downstream implementation.

Hypothetical paper exercise sample. The picking list text available for comparison reads: "Order A-204, store S-07, generated 12 March 2025 at 14:20, status is awaiting picking; out-of-stock report B-11 records: submitted 14:35, replacement product awaiting store duty confirmation; delivery exception form C-03 records: registered 15:02, reason field blank." A draft handover sentence to be assessed reads: "Order A-204 has completed picking, the out-of-stock replacement has been confirmed, and the delivery exception has been fully handled." Assessment requires the same subject, the same period, and the same field. The status field on the list reads "awaiting picking," while the draft states "completed picking," which are mutually exclusive values in the same field. The out-of-stock report records only "awaiting store duty confirmation," which is unsupported. The delivery exception form has a blank reason field, which is an evidence gap.

## Configuration and implementation checks

| Configuration or check item | Hypothetical starting point for this exercise | Comparison object and reason |
| --- | --- | --- |
| Associated knowledge base | Include only bases with matching identifier and the same vector model | Compare against the vector model identifier of already selected bases; exclude those with different models |
| Citation limit | Hypothetical starting value 2000 tokens | Compare against total length of handover materials for one instance; this value is chosen only for this paper exercise |
| Minimum relevance | Hypothetical starting value 0.4 | Compare against recalled text scores; this value only filters low-relevance results |
| Search mode | Hybrid search with reranking enabled | Compare against whether a rerank model is available and configured; do not enable without a model |
| Citation output handoff | Pass search output item by item to the answering step | Compare against citation source text; check whether the answer exceeds the source range |
| Material currency | Use the current version of the picking list and report | Compare against historical version documents; adoption still requires separate valid-version review |

## Three common errors

1. Treating a retrieval hit as authorization. Error manifestation: because order A-204 is recalled, the out-of-stock replacement is treated as confirmed. Check: the input is the report text "awaiting store duty confirmation," the comparison object is the draft sentence "has been confirmed," and the observable result is that the source text records no confirming party or time, so the claim is unsupported.

2. Treating the similarity threshold as a permission or entity filter. Error manifestation: lowering the minimum relevance is assumed to introduce unrelated store records. Check: the input is the minimum relevance value, the comparison object is the document description of that parameter, and the observable result is that the document describes only low-relevance filtering and does not describe permission or entity isolation.

3. Writing a pending-review state as a completed operation. Error manifestation: the draft sentence states the delivery exception has been fully handled. Check: the input is the blank reason field on the exception form, the comparison object is the completion wording in the draft sentence, and the observable result is that the source has no handling record or handler, so this is an evidence gap.

## How to verify the setup

1. Citation handoff check. Input is the three source texts and the draft sentence from the hypothetical sample. Compare the draft sentence against the source texts field by field. The observable result is that the "awaiting picking" versus "completed picking" conflict, the unconfirmed replacement, and the blank exception reason are all flagged. The condition for satisfaction is that the draft sentence does not exceed the source text.

2. Empty citation handoff check. Input is a paper input of an empty array. Compare whether the downstream design continues execution when citation length is zero. The observable result is that the path runs through and produces no source conclusion. The condition for satisfaction is that the downstream does not treat the empty array as an error that terminates the flow. This does not claim that a fictional rule retrieval will necessarily return an empty array.

3. Material currency check. Input is the current version and a historical version of the picking list. Compare the status field for the same order number across both versions. The observable result is that version value differences are recorded. The condition for satisfaction is that a separate valid-version review is completed before any adoption conclusion. All of the above are paper expectations and have not been executed.
