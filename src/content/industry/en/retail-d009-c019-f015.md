# On-demand retail fulfillment: retrieval for operations handover

## What the documents look like
On-demand retail fulfillment processes online orders minute by minute, a different cadence from periodic stocktaking in store loss prevention. The working materials for this category include live orders, picking lists, out-of-stock reports, and delivery exception forms. They originate from on-demand retail back ends, store inventory records, and rider tracking. These materials determine which subjects, objects, and status fields retrieval and recall must handle, for example whether one order's picking, out-of-stock report, and delivery exception sit within the same authorization chain. The brief states that updates are minute-level and per order; this page draws no batch synchronization or transaction-triggered mechanism from that fact.

## Constraints at the retrieval step
The knowledge base search node can associate one or more knowledge bases that use the same vector model. Bases built on different vector models cannot be associated together. Check the model identifier first and exclude those that do not match; do not run cross-model retrieval to compare missed recall. Compare semantic, full-text, and hybrid search against the test question rather than assuming one mode suits every material. The citation limit is measured in tokens. The minimum relevance value takes effect only in semantic retrieval or when result reranking is used. Question optimization handles coreference resolution and question expansion; compare the original question with the optimized question and check whether the subject was altered. Semantic recall and relevance scores do not perform permission or entity isolation, and retrieval results cannot serve as an authorization basis.

Hypothetical drill sample: the source text for checking reads, "Store A submitted out-of-stock report QB-0312 on March 12, 2026, covering item M-12 in order 7788, with report status pending review. The picking list for that order shows the picker has picked substitute item M-15, and the handover record notes that the substitution awaits confirmation by the store duty manager." The draft sentence to be judged is: "The out-of-stock substitution for order 7788 has been confirmed by the store duty manager and delivery status can be returned." This draft sentence treats pending review and pending confirmation as completed authorization, which is unsupported.

## Three common errors
1. Treating a pending-review out-of-stock report as already authorized. The input is the source text "report status pending review"; compare it with the draft sentence "confirmed by the store duty manager." The observable result is that the two status fields do not match, and the draft sentence is unsupported.
2. Treating a picked substitute as an effective substitution. The input is "the picker has picked substitute item M-15, and the handover record notes that the substitution awaits confirmation by the store duty manager"; compare it with the precondition in the draft sentence for returning delivery status. The observable result is that the handover record remains pending confirmation, and the return condition is not met.
3. Treating a retrieval hit as a permission determination. The input is a recall of the out-of-stock report within the target retrieval scope; compare it with whether the draft sentence uses that recall to assert operating permission. The observable result is that recalled content supplies text only, and authorization status requires separate checking of the handover record and review fields.

## How to verify the setup
1. Against the source text "report status pending review," input the draft sentence "the out-of-stock substitution has been confirmed by the store duty manager"; compare the report status field with the draft sentence wording. The observed result is a status mismatch, judged unsupported, with the evidence gap recorded.
2. Against the source text "the picker has picked substitute item M-15, and the handover record notes that the substitution awaits confirmation by the store duty manager," input a request to return delivery status; compare the handover record's confirmation status with the request precondition. The observed result is that the pending status is unchanged, and the request does not meet the execution condition.
3. For empty-result handling, input an explicit paper retrieval result `[]` and check whether the downstream design continues to run with a citation length of 0; observe whether the output path still executes. Do not claim that a fictional rule retrieval necessarily returns `[]`.
