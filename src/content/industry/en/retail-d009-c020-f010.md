# Certificates of origin: citation tracing for operations handover

## What the documents look like

Certificates of origin serve import-country tariff treatment and customs clearance requirements. That purpose separates this category from letter-of-credit document examination, which follows a credit's own terms. The materials handled here come from China International Trade Single Window, CCPIT systems, enterprise production records, and customer clearance requirements. The working documents are the certificate-of-origin application, commercial invoice, packing list, and production cost materials. Updates occur per shipment, and some scenarios are handled in batches.

For operations handover, citation tracing has to answer a narrow question: a given material, retrieval output, or proposed draft sentence sits at a particular state, is checked by a particular person, and rests on a particular source text. Retrieval output supplies quoted content. It does not supply an approval conclusion, and it does not decide who may act.

## Constraints at the citation tracing step

The knowledge base search node outputs cited content as an array, and the length may be zero. Even when nothing is retrieved, the output path still runs. This documented behavior means an empty citation array is not a workflow error and not a rejected business request. During handover, retrieval returning nothing and a missing authorization state must be recorded as separate facts.

A knowledge base search can associate one or more knowledge bases that share the same vector model. Knowledge bases built on different vector models cannot be associated together. The retrieval step does not carry permission or entity-isolation duties. The minimum relevance value is a filter threshold; it is not an authorization judgment about a particular enterprise, certificate, or operation. The citation limit is measured in tokens and controls how much content a single search may cite. It is unrelated to any thinking budget.

When a handover request concerns the current state of a material, the material's source text must be checked directly. Form fields collect values. Business verification, approval, database writes, and external synchronization each require their own downstream implementation. None of these steps happens because a retrieval node ran.

The overall retrieval flow combines optional paths: question optimization, semantic retrieval, full-text retrieval, or hybrid retrieval; image description or image vector retrieval when an image input and the required model capability exist; RRF fusion; ReRank; then similarity filtering and citation-limit trimming. A listed path does not mean every request executes it. ReRank requires a model and must be enabled under the settings. Image retrieval requires an image input and the corresponding model capability.

## Configuration and implementation checks

The values below are hypothetical starting points for a paper exercise on this page. They are not official defaults.

| Configuration item | Hypothetical starting point and reason | Comparison method |
| --- | --- | --- |
| Associated knowledge base | One trained knowledge base with a consistent vector model identifier is selected for this paper exercise | Check the knowledge base identifier and vector model identifier; exclude any that do not match |
| Citation limit | 2000 tokens is the starting point, to observe whether cited content covers the source material | Compare against the length of the source material needed for handover; record whether truncation occurs |
| Minimum relevance | 0.5 is the starting point, to observe whether low-relevance fragments enter the citations | Compare each cited fragment; record whether any fragment below this value appears |
| Search mode | Hybrid retrieval is selected, to observe semantic recall and full-text recall together | Compare whether cited content contains both semantically close fragments and keyword-hit fragments |
| Result reordering | ReRank is enabled, to observe reordering scores and citation order | Compare reordering scores with citation order; record whether scores are used for filtering |
| Citation output handoff | The citation array is passed to the answering step | Check each answer sentence against the cited source text; record sentences without source support |

## Three common errors

1. Treating an empty citation array as a denied authorization. The knowledge base search node outputs a citation array whose length may be zero, and the output path still runs. When the authorization state of a handover request is not stated in the source material, record it as unsupported or pending verification. Do not write it as denied or contradictory.

2. Treating retrieval association as permission isolation. The same-vector-model requirement applies only to knowledge base association. It does not extend to business registration sites or other external systems. The minimum relevance value is a filter threshold and does not exclude unrelated enterprises or unauthorized records. Retrieval is not authorization.

3. Treating a pending-review state as approved. A pending-review state does not show that operating permission is absent, and it does not show that approval was granted. Signing, reaching cooperation, and contract effectiveness are three separate facts. A quotation validity period does not state a supply period. A handover record should mark the state of each fact separately.

## How to verify the setup

The following checks use one paper exercise sample. The source material text reads: "Party A submitted a draft certificate-of-origin application to Party B on March 1, 2026. Party B replied 'pending review' on March 2, 2026. As of March 5, 2026, the two parties had not signed any authorization document." The draft sentence to be judged reads: "Party B approved the certificate-of-origin application on March 2, 2026." This sample is a paper exercise and does not refer to any real entity or real business.

1. Check the draft sentence against the source material text. The input is the source material text above and the draft sentence. Compare whether "pending review" and "approved" are mutually exclusive values of the same field. The draft sentence is supported only when the source material text explicitly states "approved" or an equivalent authorization expression. In this sample, the source material text states only "pending review," so the draft sentence is unsupported.

2. Check the citation output handoff. The input is the citation array output by the knowledge base search node. Compare whether the citation array is passed to the answering step. Observe whether each answer sentence corresponds to cited source text. If the citation array is empty, record an empty citation output. Do not infer a workflow error or a business rejection.

3. Check cross-model knowledge base association. The input is the vector model identifier of each knowledge base to be associated. Compare whether the identifiers match. Only knowledge bases with matching identifiers may be associated together. When identifiers do not match, record that they cannot be associated together. Do not run cross-model retrieval to compare missed recalls.

All three checks describe expected observations and failure branches only. They do not claim that any test was performed. Missing evidence stays missing, and a pending-review state stays pending verification.
