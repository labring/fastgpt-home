# Brand member operations: workflow routing for operations handover

## What the documents look like

Member private-domain operations center on customer data and repeat-purchase outreach, and they do not handle store shift scheduling. The working materials are member tag tables, outreach plans, coupon rules, and privacy authorization records. Data arrives from CRM systems, enterprise messaging, POS transaction records, and mini-program behavior data, at daily and weekly update frequencies. These materials together determine one question: whether a given customer, within a given time range, may be reached, in what capacity, and by whom the outreach is executed.

The core issue at the operations permission and handover step is the authorization state of specific materials, operations, and requests at the moment of handover. Workflow routing connects interaction nodes such as form input and user selection into an execution path. When an interaction node triggers, the conversation enters an interaction state and the workflow state is recorded; after the user completes the interaction, execution continues downward. A form node collects required information and passes it to later nodes. A user selection node executes the corresponding branch based on the user's choice. Retrieval or a form does not by itself constitute authorization. Business writes and external synchronization require a separately connected interface or a downstream process.

## Constraints at the workflow routing step

The member tag table, coupon rules, and privacy authorization records are items that must be checked one by one during handover. A form input node can collect information and pass it to later nodes; this behavior is information collection and does not mean that operations permission has transferred. A user selection node executes a branch according to the choice, and branch connections must be verified individually. The existence of a branch cannot be treated as authorization already in effect.

Hypothetical drill sample: the source material states that "Member A's privacy authorization record specifies an authorization scope of 'SMS outreach,' valid from January 1, 2025 to June 30, 2025; the member tag table marks A as 'high repeat purchase - reachable'; the coupon rules document states that the 'high repeat purchase - reachable' tag may claim a spend-based discount coupon, and the claim channel is limited to the mini-program." The draft sentence to be assessed is "Member A may receive a discount coupon push through enterprise messaging in May 2025." The subject of this request is Member A, the object is the coupon push, the state involves the authorization scope and channel, and the effective range is May 2025.

On this basis, workflow routing must distinguish four kinds of action: behavior an interaction node already has (entering the interaction state, recording workflow state, hiding the dialog box), fields that are actually configurable (required form information, branch connections), manual verification actions (comparing source material with the draft sentence item by item), and business actions that require a separately connected system implementation (order writes, document backfill, external state synchronization). A same-vector-model requirement for a retrieval library constrains only associations within that same library and does not extend to business registration sites or other external systems. RRF is a hybrid result fusion process and is not set as an on/off switch. Thinking budget is a reasoning budget and is not treated as a citation token limit.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this drill | Verification method and reason |
| --- | --- | --- |
| Required fields of the form input node | Member identifier, outreach channel, request date | Confirm against the source material that the fields cover subject, object, and time; the starting point is set only for this drill |
| Branch connections of the user selection node | Within-scope branch, out-of-scope branch | Verify branch connections one by one and confirm the choice maps to the correct downstream node |
| Interaction state recording | Workflow state is recorded after the node triggers | Check against the documented explanation; no separate global state-recording switch is set |
| Output handoff | Form information is passed to a later retrieval or judgment node | Compare output with input item by item and confirm the passed object and fields match |
| Division of external operations | Order writes, document backfill, and external synchronization connect to separate interfaces | Check whether a corresponding downstream process exists; record a missing one as not implemented |
| Retrieval library association scope | Association within a library using the same vector model | Check the identifier first and exclude non-matching items; do not run cross-model retrieval to compare missed recall |

## Three common errors

1. Treating form collection as a transfer of authorization. A form input node collects required information and passes it to later nodes; this is an information collection behavior. If the draft sentence states that Member A may receive a coupon push through enterprise messaging, while the source material's authorization scope is SMS outreach and the claim channel is limited to the mini-program, then the draft sentence and the source material differ on the channel field and the request is unsupported.
2. Treating the existence of a user selection branch as authorization already in effect. A user selection node executes the "yes" branch according to the choice, and branch connections must be verified one by one. The existence of a branch only shows that the path can run; it does not show that operations permission has been handed over.
3. Treating retrieval results as a permission or entity filter. Semantic recall and relevance do not perform permission or entity isolation. Retrieving a record does not mean the operation corresponding to that record has been authorized.

## How to verify the setup

1. Input the source material and the draft sentence, and compare the authorization scope field. The source material's authorization scope is SMS outreach, and the draft sentence uses enterprise messaging push; the two take different values on the same field, so the judgment is unsupported. If the source material does not state a channel, record it as pending verification and do not judge it as a denial or a conflict.
2. Input the request date of May 2025 from the draft sentence, and compare it with the authorization validity period of January 1, 2025 to June 30, 2025. The request date falls within the validity period, so this field is satisfied; if the request date falls outside the validity period, the judgment is that it exceeds the authorized validity range.
