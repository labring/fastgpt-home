# Brand-owned store operations: retrieval for operations handover

## What the documents look like

Brand-owned stores are staffed and accounted for directly by the brand retail company, so operations handover runs between store managers, regional managers and the company itself rather than through a franchise contract. The working document set for this category is the daily sales report, the shift schedule, display photographs and the inventory transfer order. These materials arrive from the POS system, the membership CRM, ERP inventory and store inspections. Daily and weekly update rhythms mean handover materials belong to different time batches, and retrieval work has to establish which period a given document covers before treating it as evidence about a handover.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Bases built on different vector models cannot be associated together; the vector model identifier is checked first and non-matching bases are excluded. Retrieval output is an array whose length can be zero, and the output path still runs when nothing is found. Retrieval itself performs no authorization judgement, and a similarity score is not a permission or entity filter.

Hypothetical paper exercise sample. Source text for comparison: "From 1 March 2024 to 31 March 2024, the shift schedule for brand-owned store A in the East China region was compiled by store manager Zhao; regional manager Qian signed for receipt on 5 March. For the same period, inventory transfer order DB-2024-0312 records store A as the transferring-out party and store B as the transferring-in party, applicant Zhao, approval status pending regional manager approval." Draft sentence to be assessed: "Store A's March transfer has completed approval and been executed." The check points are the same subject, the same period and the same field. "Pending regional manager approval" and "approval completed" are mutually exclusive values of one field, so the draft sentence is not supported. The signed receipt for the shift schedule does not establish that the transfer was approved.

## Configuration and implementation checks

| Configuration item | Setting or check relevant to this page | Relation to the sample |
| --- | --- | --- |
| Associated knowledge bases | Associate only knowledge bases that use the same vector model | Check the vector model identifier first and exclude non-matching bases |
| Search mode | Compare semantic, full-text and hybrid retrieval against the test question | The identifier DB-2024-0312 suits full-text or hybrid retrieval |
| Reference upper limit | Unit is tokens; test whether content stays complete using real materials of differing length | A hypothetical starting value for this exercise is a length covering the full transfer order text, compared against a shorter value for completeness |
| Minimum relevance | Takes effect only in semantic retrieval or when result reranking is used | Label relevant and irrelevant samples first, then adjust the threshold; it is not a permission filter |
| Question optimization | Used for coreference resolution and question expansion | Compare the original question with the optimized question and check whether the subject was altered |
| Result reranking | Requires a ReRank model and must be enabled in settings | Useful for a second ordering when candidates are numerous; score range 0-1 |

## Three common errors

1. Treating retrieval recall as authorization confirmation. Retrieving a transfer order marked "pending regional manager approval" shows only that the record exists, not that approval passed. Check: input the sample source text and the draft sentence, compare the value of the approval status field, and treat the draft as supported only when the same field carries the same value.
2. Treating a signed receipt as approval. The regional manager's receipt of the shift schedule and the approval of the transfer order concern different objects and different fields. Check: input the receipt record and the transfer approval field, compare whether subject, object and field are the same; when they are not the same, the draft is not supported.
3. Associating bases across different vector models. The node requires the same vector model, and non-matching bases are excluded. Check: verify the vector model identifier of each base and record the actual observation rather than inferring run-time behaviour after association.

## How to verify the setup

1. Input the hypothetical sample source text and the draft sentence, compare whether "pending regional manager approval" and "approval completed" are mutually exclusive values of the same field, and observe whether the draft sentence is judged unsupported. If it is judged approved, the condition is not met.
2. Input the identifier DB-2024-0312, compare the recalled content from full-text retrieval and from semantic retrieval, and observe whether the identifier is matched exactly. If only semantic retrieval is used and the identifier is not matched, record that observation; a first-position hit is not guaranteed.
3. Input an empty reference array [] and compare whether downstream nodes still run, observing whether the output path executes. If the downstream design depends on a non-empty reference and does not handle an empty array, record that gap.
