# Supermarket supplier accounts: workflow routing for operations handover

## What the documents look like

Supermarket supplier entry settlement revolves around four document types: purchase contracts, delivery acceptance notes, rebate agreements, and reconciliation statements. Supplier entry settlement generally involves purchase-and-sale or consignment payables, and does not necessarily include on-site counter operations. The basis for judging permissions and handover therefore rests mainly on those four document types. Data sources include ERP procurement, supplier portals, POS sales, and financial systems, with weekly or monthly update frequency.

During an operations handover, the question is which material, operation, or request sits in which authorization state. Retrieval results and completed forms cannot be treated as authorization to execute. A form input node collects required information and passes it to later nodes; a user selection node executes the "yes" branch after a user makes a choice. Neither node performs business approval, database writes, or external synchronization on its own.

## Constraints at the workflow routing step

The form input node is a user interaction node. When triggered, the conversation enters an interaction state, the workflow state is recorded, and the workflow continues after the user completes the interaction and submits. The node collects the submitted form information and passes it to subsequent nodes. The user selection node is also a user interaction node. When triggered, the conversation enters the interaction state and the workflow state is recorded. When the user makes a selection, the node judges that selection and executes the "yes" branch. Branch connections need to be verified one by one.

The interaction state is behavior of the interaction nodes. No separate global state-recording switch is documented. Collected information must be explicitly passed to subsequent retrieval, judgment, or interface nodes, and outputs must be compared with inputs item by item. Order writes, document backfill, and external status synchronization require separate business interfaces or downstream processes. Retrieval and similarity scores do not carry permission or entity-isolation duties; retrieval is not authorization.

Hypothetical paper exercise sample: the source material reads, "Party A, the supermarket, and Party B, the supplier, signed a purchase contract in March 2025, agreeing on monthly settlement with a 30-day payment period; the May 2025 delivery acceptance note records an accepted quantity of 100 boxes, of which 5 boxes were returned; the rebate agreement provides for an annual rebate of 2%, settled quarterly." The draft sentence to be judged reads, "This handover request: write the rebate deduction rate of the May reconciliation statement directly into the financial system at 2% and synchronize it to the supplier portal." The subject is Party A and Party B; the object is the May reconciliation statement rebate deduction rate; the state is pending review; the effective scope is May 2025. The source text does not state the final approver of the rebate deduction rate, and does not state the authorization boundary for the financial system write and portal synchronization.

## Configuration and implementation checks

| Configuration item | Setting or check for this page | Relation to the sample |
| --- | --- | --- |
| Form input node | Enters the interaction state when triggered; collects required information | Collects subject, object, and period of the handover request |
| User selection node | Executes the "yes" branch after the user makes a selection | Confirms whether the rebate deduction rate enters the approval branch |
| Interaction state check | State recording is interaction-node behavior; no separate global switch | Checks whether the May reconciliation request waits in interaction or has been submitted |
| Output handoff check | Collected information is explicitly passed to later retrieval, judgment, or interface nodes | Checks whether the rebate deduction rate is passed to the financial interface node |
| External operation division | Order writes, document backfill, and external status synchronization require separate business interfaces | The financial system write and portal synchronization are not completed inside these nodes |
| Hypothetical starting value | The 2% rebate deduction rate is taken from the rebate agreement text as a comparison baseline | Compared with the actual deduction value on the reconciliation statement; differences require manual review |

The hypothetical starting value of 2% is chosen because the rebate agreement text explicitly states an annual rebate of 2%. This value is used to compare against the deduction field on the reconciliation statement. It is not a system default.

## Three common errors

1. Treating the rebate deduction rate collected by the form input node as approved authorization without checking the approver field. Input: the May reconciliation request. Comparison object: the rebate agreement and approval record. Observable result: when the approver field is empty, the flow must not enter the financial write branch.
2. Treating the "yes" branch of the user selection node as completed business approval. Input: the user selection result. Comparison object: the approval status field. Observable result: selecting "yes" only indicates branch direction; the approval status remains pending review.
3. Treating the retrieved rebate agreement text as the final basis for the reconciliation statement deduction rate. Input: the rebate agreement text returned by retrieval. Comparison object: the deduction field on the reconciliation statement. Observable result: when the two values differ, record the difference and do not overwrite automatically.

## How to verify the setup

1. Input the draft sentence and source material from the hypothetical sample. Compare the 2% rebate deduction rate with the deduction field on the reconciliation statement. Observable result: when the approver field is empty, the flow stops at the manual review node and does not enter the financial interface node.
2. Input a user selection result of "yes". Compare the approval status field. Observable result: the approval status still shows pending review; branch direction and completed approval are two distinct facts.
3. Input the rebate agreement text returned by retrieval. Compare the deduction field on the reconciliation statement. Observable result: when the values match, record the match; when they differ, record the difference and preserve the evidence gap without claiming automatic correction.
