# Trade and FX administration: retrieval for operations handover

## What the documents look like

Trade and FX administration records are organized around the authenticity of foreign-exchange funds and the underlying trade background. This differs from letter-of-credit document examination, which reviews a full set of credit documents. The four recurring materials here are the foreign-exchange receipt voucher, the trade contract, the invoice, and the foreign-exchange business registration material. Each records a different fact: the voucher records funds arriving, the contract records the transaction terms, the invoice records the priced goods, and the registration material records the business registration status.

During an operations handover, the counterparty names, amounts, dates, and business numbers on these materials need to correspond item by item. The person taking over first confirms whether each material is currently a draft, awaiting review, signed, or registered. Materials update per transaction and per month. Knowledge-base retrieval only returns candidate text from content that has already been indexed; it does not confirm that any counterparty is authorized, that a transaction is approved, or that funds may be credited.

## Constraints at the retrieval step

A retrieval result expresses how related a piece of content is to a query. It does not express that a counterparty has been authorized, that a business matter has been approved, or that a payment may be credited. A search node can associate one or more knowledge bases, and those knowledge bases must use the same vector model. When vector model identifiers differ, the operator checks the identifiers first and excludes the non-matching base, then records what was observed. Cross-model retrieval is not run to compare recall differences.

Referenced content is output as an array whose length may be 0, and the downstream path still runs when nothing is retrieved. The minimum relevance setting takes effect only under semantic retrieval or when result re-ranking is used. It is a filtering threshold and does not perform permission or entity isolation.

Hypothetical drill sample: a finance staff member at a foreign-trade company provides three source sentences during a handover for checking. Sentence one: "The foreign-exchange receipt voucher shows the payer as Company A, the payee as Company B, the amount as USD 120,000, and the value date as 10 March 2025." Sentence two: "The trade contract specifies the seller as Company B, the buyer as Company A, the goods as one batch of machinery parts, and the contract signing date as 20 February 2025." Sentence three: "The status field of the foreign-exchange business registration material is marked as pending review, and the registered entity is Company B." The draft handover request to be judged is: "The above materials are complete, so the trade background corresponding to this receipt can be confirmed as authentic and the handover can be closed." Checking compares the counterparty, object, and status across the three materials: the voucher payer and the contract buyer are both Company A; the voucher payee and the contract seller are both Company B; the registration material status is pending review. Pending review does not mean approved. The words "can be confirmed" and "can be closed" in the request lack support.

## Configuration and implementation checks

| Configuration item | Relevant setting or check on this page | Relation to this sample |
| --- | --- | --- |
| Associated knowledge bases | One or more knowledge bases using the same vector model may be associated | Check each base's vector model identifier first and exclude mismatches |
| Search mode | Semantic, full-text, or hybrid retrieval | Use full-text or hybrid for counterparty names and amounts; semantic for background description |
| Reference upper limit | Each search references at most n tokens of content | Hypothetical trial starting value of 2000 tokens, chosen because the three sample sentences are long; compare against a smaller value to see whether content is truncated |
| Minimum relevance | A 0-1 value effective only under semantic retrieval or when result re-ranking is used | Hypothetical trial starting value of 0.3; label relevant and irrelevant samples first, then compare |
| Question optimization | Used for coreference resolution and question expansion | Check whether the optimized question alters the Company A or Company B counterparty |
| Result re-ranking | Uses a ReRank model for secondary ordering, with a 0-1 score | When a model is available and enabled per settings, compare the re-rank score with the vector score |

## Three common errors

1. Treating retrieval recall as authorization confirmation. The input is the draft request above. If the output states "the trade background is authentic and the handover is closed" because the contract and voucher were retrieved, the error is that retrieval returns related text only; confirming business authenticity and closing the handover require a separately connected system or manual review.

2. Reading a pending-review registration material as approved. The input is sentence three, "the status field is marked as pending review." If the output states "registration is complete," the error is that pending review and approved are different states; only mutually exclusive values in the same field constitute a contradiction.

3. Forcing knowledge bases with different vector models into a joint association. The input is two knowledge bases with different vector model identifiers. If they are associated directly and recall is compared on that basis, the error is that the association condition is the same vector model; the correct action is to check the identifiers, exclude the non-matching base, and record the observation.

## How to verify the setup

1. Input the three source sentences above together with the draft handover request. Compare the counterparty and status fields across the voucher, contract, and registration material. Observe whether the output writes pending review as approved, or writes a retrieval hit as an authorized and closed handover. The condition is met when the output clearly preserves the gaps: registration pending review and handover not closed.

2. Input a retrieval question containing only "Company A." Compare the referenced content returned by full-text retrieval and by semantic retrieval. Observe whether the reference array contains contract and voucher passages. The condition is met when the referenced content can be checked against specific materials and does not contain conclusions such as "authorized" or "credited."

3. Input an explicit paper empty result of []. Compare how the downstream node is designed to accept an empty reference. Observe whether the path continues to run. The condition is met when the downstream handles it as an empty array and does not fabricate that a rule-based retrieval necessarily returns an empty result.
