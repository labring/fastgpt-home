# Trade returns and claims: citation tracing for operations handover

## What the documents look like

Trade returns and claims cover reverse logistics and liability determination after export. The working materials are return agreements, claim letters, quality reports, and return customs declarations. They arrive from customer email, inspection reports, customs systems, and insurer claim systems. Updates are irregular and case by case.

For operations handover, the state of a material decides whether handover can continue. A signed return agreement and an agreement still under negotiation carry different operational meaning. Citation tracing requires that every handover can point to which sentence of which material supports a conclusion, and what state that material was in at handover time. Retrieval results and form entries are candidate evidence only. They do not constitute authorization.

## Constraints at the citation tracing step

A knowledge base search node can link one or more knowledge bases, on the condition that those knowledge bases use the same vector model. Knowledge bases with different vector models cannot be linked together. In that situation, check the identifiers and exclude the mismatched ones, record what was observed, and do not run a cross-model search to compare missed recalls.

The search node outputs cited content as an array, and the length may be zero. An empty array means the output path still runs; it does not mean the workflow errored out or stopped. The citation upper limit is measured in tokens, and it is unrelated to any thinking budget. The two cannot be substituted for each other. The minimum relevance value is a filter threshold and applies only during semantic retrieval or when result reranking is used. It does not perform permission or entity isolation. Hybrid retrieval merges multiple result paths through RRF, which is a fusion process and has no corresponding switch. Image retrieval needs image input and the matching model capability. Reranking needs a model and must be enabled in settings. Optional paths shown in the document flow diagram do not mean every request executes all of them.

Hypothetical drill sample: the material text reads, "Return agreement (No. HYP-2026-0417) states: Party A submitted the return application on 17 April 2026, both parties agree the return reason is a batch quality mismatch, and the agreement takes effect from the date both parties sign. The current status of this agreement is Party A signed, Party B not signed." A separate quality report (No. HYP-QC-0417) states, "The sampled nonconforming rate for this batch is 3.2%." The draft sentence to be judged is: "The return agreement is in effect, so the return declaration can be filed and claim evidence submitted." The judgment point: the agreement text states the effective condition as signature by both parties, while the current status is Party B not signed. The draft sentence's claim that it is "in effect" does not match the stated status and is unsupported. The quality report supports only the nonconforming rate field and does not support an effectiveness judgment. Whether the return declaration can be filed and whether claim evidence can be submitted depend on later approval and authorization; the materials themselves do not state this.

## Three common errors

1. Treating a retrieval hit as authorization. The input is the citation array returned by the search node; the comparison object is the signature status in the return agreement text. If the draft sentence directly states "the return declaration can be filed" while the text states only that Party B has not signed, the claim is unsupported. The observable result is that the draft sentence exceeds the scope of the source text.

2. Treating an empty citation array as a failure. The input is the explicit paper input `[]`; the comparison object is the design of the downstream answering step. If the downstream step still continues and produces a notice, the empty array is a normal handoff. The observable result is that the flow is not interrupted.

3. Treating minimum relevance as a permission filter. The input is the same set of return materials; the comparison object is the number of returned items at different relevance thresholds. If changing the threshold only changes the citation count and does not change the accessible range, relevance does not carry a permission function. The observable result is that the permission boundary does not move with the threshold.

## How to verify the setup

1. Check the draft sentence against the hypothetical sample text. The input is the HYP-2026-0417 agreement text and the draft sentence "the return agreement is in effect." The comparison object is the source phrase "takes effect from the date both parties sign" together with the current status "Party B not signed." The condition is met only when the draft sentence is changed to pending verification or the effectiveness judgment is removed.

2. Check empty-citation handoff with the paper input `[]`. The input is an empty array; the comparison object is the design description of the downstream node. The condition is met only when the downstream step continues without an error. This does not claim that a fictional rule search will necessarily return `[]`.

3. Check the linking scope with the same vector model identifier. The input is the vector model identifiers of two knowledge bases; the comparison object is whether the identifiers match. Joint linking is permitted only when the identifiers match. When the identifiers differ, record the observation and exclude the mismatched library, without inferring missed recalls or redundant results.
