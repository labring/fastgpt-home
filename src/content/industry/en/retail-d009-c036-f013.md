# Multi-warehouse inventory: access controls for operations handover

## What the documents look like

Multi-warehouse allocation happens at the order-routing stage and determines which warehouse ships an order. The working materials are allocation rules, inventory synchronization tables, transfer orders and shortage alerts. Their sources are WMS, OMS, ERP inventory and platform inventory interfaces. In daily operations these materials move between roles: supply chain planning maintains allocation rules, a WMS administrator maintains inventory synchronization, and e-commerce operations handles shortage alerts. Materials may be updated daily or hourly, but update frequency does not change when permission is evaluated; the state recorded in the material at the time of review governs.

For operations handover, the question is not which document exists but which person or group holds which permission on the resource that stores it. A handover note, a draft sentence or a pending request describes an intended state. It does not by itself change a permission record.

## Constraints at the access controls step

FastGPT permissions are evaluated per resource type. Team resources cover creating applications, creating knowledge bases, creating team API keys and managing members. Applications and knowledge bases each have three levels: usable, editable and manageable. Files and folders (collections) have read permission, write permission and administrator; deletion is limited to the creator. Permission evaluation first checks the individual member's permission, then takes the union of department and group permissions. Knowledge base permission is always a threshold: collection permission cannot bypass knowledge base permission. Retrieval recall filters by files the current member can read, and this applies only when authentication is by the current member identity; a workflow that preselects a knowledge base without member-identity authentication does not apply file-level filtering. Team administrators do not bypass file-level permission. System root and team owner are treated as having all permissions on all files.

Hypothetical paper exercise. A supply chain planning group submits a handover document containing the following original text: "This group has maintained the East China warehouse allocation rules since 1 March 2025; the inventory synchronization table is updated daily by the WMS administrator; transfer orders require confirmation by e-commerce operations before they proceed." A separate draft sentence reads: "After handover, this group no longer has edit permission on the East China warehouse allocation rules." The subject is the supply chain planning group, the object is the East China warehouse allocation rules, and the claimed state is the ownership of edit permission after handover. The original text does not state this group's current resource permission configuration in FastGPT, and it does not state whether handover has completed. A determination requires a permission record for the same subject, same object and same period. The available material provides only a description of duties; the permission state remains to be verified.

## Three common errors

1. Treating retrieval relevance as permission filtering. Retrieval recall filters by files the current member can read, and a relevance score does not perform entity or permission isolation. The erroneous input is a setting that uses relevance to exclude files the member cannot access. The comparison object is the actual list of readable files. The observable result is that a file without read permission still appears among the candidates.

2. Treating team administrator identity as a bypass for file-level permission. Team administrators do not bypass file-level permission; knowledge bases and files are still authenticated against their own collaborator configuration. The erroneous input is the assumption that a team administrator can directly view all files. The comparison object is that administrator's collaborator role on the target knowledge base. The observable result is that the file list does not show the file when no read permission exists.

3. Treating a pending handover request as a completed permission change. The draft sentence describes a permission state after handover, and the material does not state a review result or a change to the permission record. The erroneous input is the draft sentence taken as the final permission. The comparison object is the subject and role in the resource permission record. The observable result is that the state described in the draft sentence is unsupported while the permission record remains unchanged.

## How to verify the setup

1. Input the original exercise text and the draft sentence, then compare whether the subject, object and period described in the draft sentence match the original text. The original text describes duties only and does not state this group's resource permission configuration in FastGPT. The edit-permission state described in the draft sentence is unsupported and requires a permission record before any determination.

2. Input the draft sentence and the knowledge base collaborator configuration, then compare this group's role on the target knowledge base. If the configuration is read permission, the edit permission described in the draft sentence does not match the configuration. If the configuration is editable, the period and the completion state of handover still require checking. The observed phenomenon is the correspondence between the role field and the wording of the draft sentence.

3. Input an empty-result check scenario, using the paper input `[]` to check the downstream design. The comparison object is the downstream handling of an empty candidate set. The observed phenomenon is whether the downstream preserves the empty result without fabricating records. This check does not claim that any retrieval necessarily returns an empty result; it checks design behavior under an empty input.

All three verification items use the hypothetical exercise as input. Expected results must be recorded after actual comparison, and a verification note does not replace comparison against the specific exercise material.
