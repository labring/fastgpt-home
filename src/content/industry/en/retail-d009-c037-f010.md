# Peak-sale fulfillment: citation tracing for operations handover

## What the documents look like

Peak-sale warehouse and delivery scheduling revolves around short-term peak capacity and the arrangement of people, vehicles, and space. The inputs that shape scheduling decisions are historical peak-sale orders, platform campaign registrations, WMS capacity, and courier pickup capability. These inputs update per campaign and per day. The working documents are the peak-sale forecast table, staff rosters, courier assurance plans, and exception daily reports. Forecasting order peaks, arranging temporary staff, and coordinating courier vehicles consume the most time.

These characteristics mean that materials cited during a handover are often in a fast-changing state. Source version and authorization status require document-by-document checking. A forecast table version and a courier assurance plan version can carry different dates, different submitting parties, and different geographic scopes, and those differences matter when one document is cited to support another.

## Constraints at the citation tracing step

The knowledge base search node can select one or more knowledge bases that share the same vector model, and it outputs citations as an array whose length can be zero. Even when no content is retrieved, the output path still completes. The retrieval step itself does not perform permission judgment. The minimum relevance value is a filtering threshold and does not constitute an entity or permission boundary. The citation limit controls the maximum tokens of content cited per search, and this value is a different concept from a thinking budget. Hybrid retrieval fuses multiple result paths through RRF, and reranking produces a 0-1 score. These ranking mechanisms do not change the authorization status of any material.

Hypothetical drill sample: the source material reads, "This peak-sale forecast table V3 was submitted by the scheduling group on June 1, covering the order peak estimate for June 1 to June 3; courier assurance plan V2 was submitted by courier business on June 2, covering pickup capacity in East China only." The draft sentence to be assessed reads, "The courier assurance plan already covers nationwide pickup capacity and can support this scheduling handover." A separate handover request reads, "Please transfer forecast table V3 and assurance plan V2 together to the duty manager and treat the scheduling authorization as completed."

## Three common errors

1. Treating retrieval output directly as scheduling authorization. Retrieval returns a citation array whose length can be zero, and that output contains no approval status. Treating cited content as completed authorization exceeds the granted scope.
2. Treating minimum relevance as a permission filter. This value only filters low-relevance results and does not distinguish the entity or authorization scope a material belongs to. Using similarity to exclude unrelated businesses or unauthorized records has no basis.
3. Treating a material pending review as an effective material. In the sample, assurance plan V2 covers East China only, while the draft sentence claims nationwide coverage, which is a value inconsistency in the same field. The handover request phrase "treat the scheduling authorization as completed" lacks signing or effectiveness evidence.

## How to verify the setup

1. Input the sample source text and the draft sentence, compare the coverage scope "East China" in assurance plan V2 with "nationwide" in the draft sentence, and observe whether the two values are mutually exclusive in the same field. If they are, the draft sentence is unsupported.
2. Input the handover request, compare the phrase "treat the scheduling authorization as completed" with whether a signing or effectiveness record exists in the material. When no authorization clause is stated, record the item as pending verification and do not judge it as authorized.
3. Input an explicit empty citation array [] and compare whether the downstream answer step accepts it normally, observing whether the path completes. Do not claim that an actual search necessarily returns an empty array.
