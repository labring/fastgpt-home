# Peak-sale fulfillment: retrieval for operations handover

## What the documents look like

Peak-sale fulfillment planning centers on short-term peak capacity and the coordination of people, vehicles, and dock space. The working materials are the peak-sale forecast table, staff shift schedules, courier support plans, and exception daily reports. These draw on historical peak-sale orders, platform campaign registrations, WMS capacity, and courier pickup capacity. The materials are updated per campaign and per day. During handover, the current version and the applicable campaign must be confirmed.

For operations permissions and handover management, retrieved material must map to a specific campaign, position, and authorization boundary. A retrieval result is reference content. It is not an executable authorization, and it does not by itself confirm that a plan, a shift, or a vehicle arrangement has been approved for execution.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Retrieval recalls candidate content through semantic search, full-text search, or hybrid search, then applies similarity filtering and a token-based reference cap before outputting a reference array. The array length can be zero, so the output path still runs when nothing is found. The minimum relevance value takes effect only in semantic search or when result reranking is used. It is a filtering threshold and does not perform permission or entity isolation. The same-vector-model requirement for associated knowledge bases does not extend to external systems. Question optimization performs coreference resolution and question expansion and adds one model call before retrieval.

Hypothetical drill sample: a fulfillment operations group hands over one peak-sale production plan on 3 November 2025. The source text reads: "The forecast table version for this campaign is the 3 November final version, applicable to the 10 November to 12 November dispatch waves. The staff shift schedule marks the night-shift temporary worker arrival time on 10 November as 22:00; the schedule status is pending review. The courier support plan states that pickup vehicles on 11 November number 6, plan number KD-1111, and the plan has been confirmed by the courier business contact." Draft sentence to be assessed: "The 11 November pickup vehicles have obtained operations authorization for execution." The source states confirmation by the courier business contact. That is a different subject and a different fact type. Operations authorization cannot be derived directly from the retrieval result.

## Configuration and implementation checks

| Configuration item | Hypothetical trial starting point for this page | Basis and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Select knowledge bases containing this campaign's forecast table, staff shift schedule, and courier support plan | Check whether the vector model identifiers of the libraries match; exclude those that do not; do not run cross-model comparison |
| Search mode | Hybrid search | Test with numbered queries and natural-language queries separately; observe whether recalled content covers both needs |
| Reference cap | Set to the token amount that holds a complete shift paragraph | Test with short and long shift material; compare whether the truncation point drops key fields |
| Minimum relevance | Set to 0.5 for this trial | Label relevant and irrelevant samples first; observe whether necessary items survive filtering |
| Question optimization | Enable for multi-turn follow-up questions | Compare the original question with the optimized question; check whether subject and campaign were altered |
| Result reranking | Enable when candidates are numerous | Check whether the rerank score is used for filtering; observe it separately from the semantic score |

## Three common errors

1. Treating a retrieval result as an authorization credential. Error: reading "confirmed by the courier business contact" in the courier support plan as operations authorization for execution. Check: input the plan source text and the draft sentence, compare subject and fact type, and observe whether business confirmation and operations authorization are merged into one fact.

2. Treating a pending-review status as already effective. Error: the staff shift schedule is marked pending review, yet handover proceeds according to the arrival time. Check: input the schedule status field and the handover request, compare status against execution conditions, and observe whether execution advances without approval.

3. Associating knowledge bases across vector models. Error: associating knowledge bases with different vector models and then comparing recall. Check: verify each library's vector model identifier, exclude those that do not match, record the actual observation, and do not infer runtime results.

## How to verify the setup

1. For the hypothetical drill sample, input the courier support plan source text and the draft sentence, and compare the subject and fact type of "confirmed by the courier business contact" against "operations authorization for execution." Condition met: the system output reference content contains the plan source text and does not describe business confirmation as operations authorization.

2. Input the staff shift schedule source text and the handover request, and compare the "pending review" status against the execution condition. Condition met: the retrieval result retains the status field, and the handover request is not judged executable while the status is unchanged.

3. Input an explicit paper empty-result array [] and check whether the downstream design handles an empty reference. Condition met: the downstream flow has a defined reception for the empty array, and no claim is made that a fabricated rule query necessarily returns empty. All of the above are paper checks and were not actually executed.
