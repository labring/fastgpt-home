# Customer-service knowledge: citation tracing for operations handover

## What the documents look like

Customer-service knowledge-base maintenance is preparatory question-and-answer material work. It does not approve refunds directly. The everyday materials are FAQ entries, script templates, product parameter tables, and escalation tickets. They come from the customer-service system, product detail pages, after-sales issue statistics, and quality spot checks. Updates follow a weekly or monthly rhythm. Operations permission and handover management must connect material versions, retrieval scope, and citation output.

The knowledge-base search node can select one or more knowledge bases that use the same vector model. Its output is citation content in array format, and the length can be zero. During handover, a retrieval that returns output is not treated as completed authorization, and an empty array is not treated as a terminated process. Whether citation content is adopted, who reviews it, and which version range it is valid in are boundaries that operations permission and handover management must check.

## Constraints at the citation tracing step

Citation tracing requires checking each answer against the cited source text. Semantic retrieval relies on vector similarity. Full-text retrieval relies on keyword hits. Hybrid retrieval merges multiple result paths through RRF. Rerank produces a score from 0 to 1. These scores serve relevance ordering. They do not perform permission isolation or entity filtering. Retrieval itself does not constitute authorization. The citation limit is measured in tokens and is unrelated to the thinking budget.

The same vector model is the precondition for joint association. At handover, first check the vector model identifier of the selected knowledge bases, exclude those that do not match, and record the actual observation. Do not run cross-model retrieval to compare missed recalls. The search node output citation array may have a length of zero. An empty array can serve as a paper input to check the downstream design. It cannot be claimed that a fictional rule retrieval necessarily returns an empty array.

Hypothetical drill sample: the source text is "FAQ-2024-031 entry: the return address follows what is displayed on the order page. Script template T-07: the agent may tell the user to check the order page. Product parameter table P-22: this model supports 7-day no-reason returns." The draft sentence to be judged is "The agent may directly tell the user the return address is Warehouse A, without the user checking the order page." The handover request is "transfer the citation source permission of FAQ-2024-031 to the new knowledge-base operator."

## Three common errors

1. Treating retrieval output as authorized execution. The input is the citation array returned by the search node. Compare whether the draft sentence exceeds the authorization scope of FAQ-2024-031. The observed phenomenon is that the draft sentence writes "Warehouse A" while the source text only says "follows what is displayed on the order page."
2. Treating a pending handover request as a completed transfer. The input is "transfer the citation source permission of FAQ-2024-031 to the new knowledge-base operator." Compare whether a signed or effective record exists. The observed phenomenon is that only the request text exists and no effective evidence is present.
3. Mistaking the thinking budget for the citation limit. The input is the budget value in the thinking configuration. Compare it with the token unit of the citation limit. The observed phenomenon is that the two are mixed as the same field.

## How to verify the setup

1. Input the source text of FAQ-2024-031 and the draft sentence "The agent may directly tell the user the return address is Warehouse A." Compare whether "follows what is displayed on the order page" and "Warehouse A" are the same subject and the same field. The observed phenomenon is that the two are mutually exclusive, judged as unsupported.
2. Input the handover request "transfer the citation source permission of FAQ-2024-031 to the new knowledge-base operator." Compare whether a signed, effective, or authorization record exists. The observed phenomenon is that only the request text exists, judged as pending verification.
3. Input the paper citation array []. Compare whether the downstream answer step receives it according to the empty-array design. The observed phenomenon is that the downstream reports no error and generates no source citation. Record this as an observation. Do not claim that retrieval necessarily returns an empty array.
