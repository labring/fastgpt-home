# Seller ratings management: citation tracing for operations handover

## What the documents look like

Seller ratings work handles consumer feedback that arrives after post-sale fulfillment, and it does not directly set promotional prices. The daily materials for this category include negative-review handling records, experience-score breakdowns, service diagnostic reports, and rectification ledgers. These materials update on a daily or weekly rhythm. The people involved are store operations staff, customer service supervisors, and quality inspection specialists.

Citation tracing answers a narrow question: for a given conclusion or ledger entry, which material, which version, and which authorization state does the supporting evidence come from. Retrieval results only supply candidate content, and they do not grant any permission. Forms collect entered values, while business verification, approval, database writes, and external synchronization each require a separately implemented step. When a handover treats a pending review request as an approved action, later rectification and responsibility assignment lose their basis.

## Constraints at the citation tracing step

The knowledge base search node can associate one or more knowledge bases that share the same vector model, and it outputs citation content as an array whose length may be zero. A zero-length output means the downstream chain still runs; it does not mean the workflow raised an error and stopped. The citation limit is measured in tokens. The minimum relevance value is a filter threshold that takes effect only under semantic retrieval or result reranking. A similarity score is not a category, entity, or permission filter, so it cannot be used to exclude unrelated businesses or unauthorized records.

Hybrid retrieval merges multiple result paths through RRF. Reranking requires a model and is enabled according to settings. Image retrieval requires image input and corresponding model capability. These optional paths are not all executed on every request. Knowledge bases built on different vector models cannot be associated together; during checking, compare identifiers first, exclude non-matching ones, and record actual observations without inferring runtime consequences. Thinking budget is a model reasoning parameter and is unrelated to the citation token limit.

## Three common errors

1. Treating a retrieval hit as authorization. Input is a retrieval over one negative-review handling record; the comparison object is the retrieval output against the approval record; the observable result is that a citation entry exists while the approval field is empty. The authorization state remains unsupported.

2. Writing a pending review request as approved. Input is a rectification request marked pending review in a handover form; the comparison object is the request status field against the signature field; the observable result is a pending-review status with no signature. This request does not constitute a completed approval.

3. Treating a zero-length citation as a failure. Input is a paper retrieval result `[]`; the comparison object is whether the downstream node continues to execute; the observable result is that downstream still receives an empty array. This observation does not show that a retrieval rule necessarily returns empty.

## How to verify the setup

Hypothetical drill sample: the material source text reads "On March 10, 2025, a store's negative-review handling record number A-014, handler Li, status pending review, unsigned." A separate draft handover request reads: "A-014 is approved and rectification can proceed directly."

- Verification one: input the source text above together with the draft handover request; compare the source status fields "pending review, unsigned" against the draft sentence "approved"; the observable result is that the two take mutually exclusive values on the same field, the draft sentence is unsupported, and the item should be recorded as pending confirmation.

- Verification two: input the same source text; compare the handler field against the operator field in the handover form; the observable result is that a match makes attribution clear, while a mismatch records an evidence gap without inferring missing permission.

- Verification three: input the paper retrieval result `[]`; compare whether the downstream node still executes and outputs empty citations; the observable result is that downstream continuing to run matches the documented empty-array acceptance behavior. This result does not indicate that any invented rule necessarily returns empty.

All of the above are paper checks that were not actually executed, and they do not constitute a test, deployment, or approval conclusion.
