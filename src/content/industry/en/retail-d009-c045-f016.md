# Seller ratings management: interactive forms for operations handover

## What the documents look like

Seller ratings and experience-score maintenance draws on platform experience scores, marketplace service indicators, after-sales review records, and customer-service systems, with updates occurring daily or weekly. The working documents are negative-review handling records, experience-score detail sheets, service diagnostic reports, and rectification ledgers. For operations permission and handover work, these materials are the objects of comparison: who submitted which fields at what time, who holds authority to modify or approve, and how material status moves between stages.

The form input node collects the information a user fills in and passes it to later nodes after submission; it does not carry a business database function of its own. The user selection node executes a branch according to the user's choice, and does not act as a personnel directory or a business-data selector. The interactive state records the workflow state and waits for the interaction; after the interaction completes, execution continues downward. Retrieval and forms do not constitute authorization.

## Constraints at the interactive forms step

A form collects values only. Business verification, approval, database writes, and external synchronization require an external system or a later node. During operations handover, the authorization status of a material, an action, or a request must be judged from the material text itself; a retrieval result or a form submission cannot be treated as an executed authorization.

Hypothetical paper exercise sample. In a store operations handover scenario, the material text available for comparison consists of three sentences. First: "Negative-review handling record number A-017; handling status is pending customer-service supervisor review; submitter: operations role; submission date: 10 March 2025." Second: "Rectification ledger entry T-022; rectification status: registered; tracker: quality-inspection role; registration date: 12 March 2025." Third: "Experience-score detail sheet, 10 March to 16 March 2025; store experience score 4.6; service diagnostic report marked 'pending re-check'." The draft sentence to be assessed is: "A-017 has completed review, and the operations role has authority to modify the experience-score detail sheet directly." Comparison points: the A-017 status is pending review; a pending state does not demonstrate the absence of operating permission, and it does not equal completed review. The experience-score detail sheet carries a pending-re-check mark and does not state which role holds modification authority. The draft sentence converts a pending-review status into completed review and converts an unstated modification authority into an existing one; it is unsupported.

## Configuration and implementation checks

The configuration below stays with the sample above and lists only documented settings or implementation check items. Where a value is needed, it is labelled as a hypothetical starting point for this exercise.

| Configuration item | Hypothetical starting point for this exercise | Comparison method |
| --- | --- | --- |
| Form input node | Collect negative-review record number, handling status, submitter, submission date | After submission, check whether the fields pass to later nodes |
| User selection node | Branch options set as "submit for review" and "return for supplement" | After a choice, check whether the corresponding branch executes |
| Interactive state | After the node triggers, workflow state is recorded and the system waits for interaction | After interaction completes, check whether execution continues downward |
| Required-field check | List number, status, submitter, and date as required | Test missing-item and completed-item behaviour separately |
| Downstream division of labour | Field validation, business approval, write-back, and batch operations are implemented in an external system or later nodes | Check whether form submission enters an external approval step |

The starting point for the required-field check is chosen because the sample material supplies exactly these four fields; the comparison is against the same field list in the sample text. No official default is claimed.

## Three common errors

1. Writing a pending-review status as completed review. Input: A-017 original text "handling status is pending customer-service supervisor review". Compare with the draft sentence "has completed review". Observable result: the status field does not match.
2. Writing an unstated modification authority as an existing authority. Input: experience-score detail sheet original text "pending re-check", with no stated holder of modification authority. Compare with the draft sentence "the operations role has authority to modify directly". Observable result: the authority basis is missing.
3. Treating a form submission as executed authorization. Input: the form input node collects and passes fields. Compare with the statement "submission completes approval". Observable result: no approval action appears inside the form node.

## How to verify the setup

1. Input the A-017 original text and the draft sentence "A-017 has completed review". Compare the handling-status field: the original reads "pending customer-service supervisor review", the draft reads "completed review". The condition is met when the two differ, and the draft sentence is judged unsupported.
2. Input the experience-score detail sheet original text "pending re-check" and the draft sentence "the operations role has authority to modify directly". Compare the authority basis: the original does not state which role holds modification authority. The condition is met when the authority basis is absent, and the draft sentence is judged unsupported.
3. Input the field-passing record after form submission and the statement "submission completes approval". Compare whether later nodes contain an approval action: the form node only collects and passes fields. The condition is met when no approval action appears in the form node, and the statement is judged unsupported.

These checks are paper comparisons. No test, deployment, approval, refund, or other business action has occurred. Where a field is not provided in the material, the value remains unknown.
