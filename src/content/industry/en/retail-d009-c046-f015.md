# Marketplace category access: retrieval for operations handover

## What the documents look like

Marketplace category qualification access happens before listing or merchant onboarding. The core materials are the business license, trademark registration certificate, brand authorization chain and industry license. Together they answer who the operating entity is, which category it operates, who authorizes whom, and which scope a license covers. A brand authorization chain commonly spans several entities and several periods, so collecting the chain and matching it to an operating category are the time-consuming steps. Materials are updated irregularly, and every onboarding requires a fresh check.

For operations permission and handover management, these materials determine whether a given entity holds a submittable qualification state for a given category and period. Retrieval only locates the relevant materials for human review. It does not decide authorization.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases with different vector models cannot be associated together. Check the vector model identifier first, exclude those that do not match, and record what is observed. Do not run cross-model retrieval to compare missed recalls.

Semantic retrieval relies on vector similarity. Full-text retrieval relies on keyword hits. Hybrid retrieval fuses the two paths through RRF, and RRF is a fusion process rather than a switch. The minimum relevance value takes effect only in semantic retrieval or when result reranking is used. It is a filter threshold, not a sorting rule, and it does not act as a category, entity or permission filter. When retrieval returns nothing, the quoted content is output as an array whose length can be 0, and the output path still runs. The quotation limit controls the amount of quoted content in tokens. Question optimization handles coreference resolution and question expansion, and adds one model call. Image retrieval requires corresponding image input and model capability. Reranking requires a model and must be enabled in settings. These paths do not mean every request executes all of them. Retrieval does not perform permission isolation and does not judge pending review, signature or effective status. Those states come from human review and downstream systems.

Hypothetical paper exercise sample: a paper material records that "Entity A holds a Class 30 trademark registration certificate valid until 1 January 2030; Entity B issues an authorization letter permitting Entity A to use the trademark to operate that category from 1 January 2025 to 31 December 2027." The draft sentence to be assessed is "Entity A holds category operating authorization in 2025." The check compares whether the authorization letter period covers 2025, whether the authorized entity is Entity A, and whether the trademark registration certificate covers Class 30. All three must hold to support the draft sentence. Holding a trademark registration certificate alone does not mean operating authorization has been obtained.

## Three common errors

1. Treating a retrieval hit as established authorization. The input is the sample material above, and the comparison is between the retrieved content and the draft sentence "Entity A holds category operating authorization in 2025." If only the trademark registration certificate is hit and the authorization letter period is not, the draft sentence is unsupported. Executable check: open each hit source text and check whether the entity, category and period fields all appear together.

2. Treating a pending review state as an existing operating permission. The input is the handover request "submit Entity A's qualification for onboarding," and the comparison is whether the material states a review conclusion. If only a submission record exists, the request remains pending verification. Executable check: look for a review conclusion field in the material and record the evidence gap when it is absent.

3. Associating knowledge bases with different vector models together. The input is the vector model identifiers of two bases, and the comparison is whether they match. If they do not match, do not associate them together. Executable check: read each base identifier, record it, and exclude those that do not match.

## How to verify the setup

- Verification one: input the sample material text above and the draft sentence. Compare whether the authorization letter period covers 2025, whether the authorized entity is Entity A, and whether the registration certificate category is Class 30. All three must hold to support the draft sentence; otherwise record it as unsupported or pending verification.

- Verification two: input the same sample with a quotation limit of 800 tokens. Compare whether the returned quoted content contains the complete authorization period paragraph. If the period is truncated, the condition is not met, and the limit needs adjustment followed by re-observation.

- Verification three: input the same sample with a minimum relevance of 0.3. Compare whether returned results contain fragments unrelated to category qualification. If unrelated fragments appear, the condition is not met, and relevant and irrelevant samples must be labeled first before adjusting the threshold.

Empty-result continuation: use an explicit paper input of an empty array to check the downstream design and confirm the output path still runs. Do not claim that retrieval under a fictional rule necessarily returns an empty array. Cross-model association is not allowed; only check identifiers and exclude those that do not match.
