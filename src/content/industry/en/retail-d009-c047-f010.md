# Marketplace returns: citation tracing for operations handover

## What the documents look like

Platform refund and return handling occurs continuously by order rather than being tied to a single live-stream promise. Materials come from the platform after-sales console, customer service chat, WMS receiving records, and payment refund records. Four document types form the main objects of comparison: refund applications, return logistics notes, quality inspection photos, and refund approvals. Updates occur per order and daily.

This matters for citation tracing because the handover parties must be able to follow material text back to a specific source. A refund application, a return logistics note, a quality inspection photo, and a refund approval each carry different states. A record that has been retrieved is not the same as a record that has been authorized for execution. A form that has been filled in is not the same as a business step that has been completed. The citation tracing step has to keep these apart: what a node already does, what can be configured, what a person checks by hand, and what requires a separate downstream system.

## Constraints at the citation tracing step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Its output is an array of citations, and the length can be zero. When the array is empty, the output path still runs. The citation upper limit is measured in tokens. The minimum relevance value takes effect only in semantic retrieval or when result reranking is used. Hybrid retrieval merges multiple result paths through RRF, and reranking produces a score from 0 to 1. These parameters determine the scope and ordering of citation content. They do not determine operational authority. Retrieval does not grant authorization, and a similarity score is not an entity or permission filter. The same-vector-model condition is a precondition for association; knowledge bases with different vector models cannot be associated together. At check time, verify the identifier first and exclude those that do not match, rather than running a cross-model retrieval to compare missed recalls.

Hypothetical drill sample: a platform after-sales handover record states that refund application number H-2024-0871 concerns a batch of household textiles. The applicant submitted a return and refund request on 12 March, with status "pending review." The return logistics note shows the warehouse signed for the goods on 15 March. The quality inspection photo shows outer packaging damage and intact inner contents. The refund approval field is empty. Proposed determination sentence: "This refund application has been approved and the refund can be executed." The material text for comparison reads: "Refund application status is pending review. Refund approval field: not filled in." Judge whether the proposed determination sentence is supported by the material.

## Three common errors

1. Treating a retrieval hit as authorized execution. In the sample, the refund application status is "pending review" and the approval field is empty. Retrieving that application does not mean it has been approved. The proposed determination sentence "has been approved and the refund can be executed" lacks material support.
2. Treating minimum relevance as a permission filter. Minimum relevance is a 0-1 filtering threshold that takes effect only in semantic retrieval or result reranking. It does not exclude unrelated businesses or unauthorized records, and it cannot be used to judge whether a refund record falls within the current operator's authority.
3. Treating an empty citation output as a process error. The citation array length can be zero, and the output path still runs when the array is empty. This cannot be used to assert that retrieval failed or that the workflow terminated.

## How to verify the setup

1. Input the sample material text "Refund application status is pending review. Refund approval field: not filled in." and the proposed determination sentence "This refund application has been approved and the refund can be executed." Compare whether they share the same subject, the same period, and the same field. If the approval field is empty, the proposed determination sentence is not supported and should be recorded as pending verification, not judged as approved.
2. Input the vector model identifier V1 in the sample and the vector model identifier of the knowledge base to be associated. Compare whether they are the same. If they differ, exclude that knowledge base, do not run a cross-model retrieval, and record the observed identifier difference.
3. Input a clearly written paper empty array [] and a downstream answer step. Compare whether the downstream step handles it according to the empty-citation design. If the downstream step still runs normally without error, this matches the documented condition that the output path runs when the array is empty. Do not claim that a fictional rule retrieval will necessarily return [].
