# Wholesale stall trading: interactive forms for operations handover

## What the documents look like

Wholesale market stall trading runs on on-site price negotiation and consignment shipping. The working papers are purchase notes, handwritten sales slips, stall lease contracts and payment receipts, and they are updated daily or per order. Three features of this setting shape the interactive forms step. Different parties fill in the papers at different points, so field completeness varies from slip to slip. During a handover, materials, operations and requests arrive in the same conversation. Authorization status has to be checked item by item as the handover proceeds. The form input node collects the information a user fills in and passes it to later nodes after submission; it does not carry a business database of its own. Material needed for an authorization decision therefore has to come from an accessible retrieval scope or from explicit human input.

## Constraints at the interactive forms step

The form input node and the user selection node are both user interaction nodes. When either is triggered, the conversation enters an interaction state, the workflow state is recorded, and execution waits until the interaction is complete before continuing downward. The user selection node judges the user's choice and runs the "yes" branch. It is not a staff directory and not a business data selector. Field validation, business approval, write-back and batch operations are implemented in an external system or in later nodes as required. A retrieval result or a similarity score is not an authorization basis; retrieval is not authorization. The optional paths drawn in the overall workflow diagram do not mean that every request executes all of them.

Hypothetical paper exercise sample. Stall owner A and purchaser B sign a handwritten sales slip for a lot of dried goods. The slip states: "10 March 2025, A sells B 30 boxes of dried goods, total payment in RMB to be settled by B before 20 March." A signs at the foot; B does not sign. A stall lease contract also exists, stating that A leases a stall in a certain market from 1 January 2025 to 31 December 2025, with the lessor's seal and no signature by A. The draft handover request reads: "Register the above sales slip and lease contract together as a completed handover, and authorize B to use the stall from 11 March." The question to decide is whether the authorization in that request already has an effective basis.

## Three common errors

1. Treating retrieval or form submission as authorization execution. In the sample, B has not signed the sales slip and A has not signed the lease contract. Registering the draft handover request directly as a completed handover treats a pending review as already authorized. The input is the text of the two materials and the request sentence; the comparison object is the signature status field; the observable result is that the authorization in the request sentence lacks a signing basis.

2. Treating the branch outcome of the user selection node as a staff directory or business data selector. The input is the branch selection action; the comparison object is the branch execution behavior described in the node documentation; the observable result is that the branch only determines the direction of the flow and produces no subject identity or permission data.

3. Associating libraries with different vector models. The input is the model identifier of the two libraries; the comparison object is whether the identifiers match; the observable result is that mismatched libraries are excluded and the actual observation is recorded, without inferring missed recall or redundant results.

## How to verify the setup

1. Check the required fields against the sample text. The input is the three sentences of the sales slip text and the one sentence of the lease contract text; the comparison object is the required field list of the form input node; the condition is met when each field can be matched to wording in the source text or is clearly marked as a gap. If signature status is missing, record it as unsupported rather than judging it as a denial or a conflict.

2. Check the authorization boundary against the draft handover request. The input is "Register the above sales slip and lease contract together as a completed handover, and authorize B to use the stall from 11 March"; the comparison object is the signing status of the two materials and the authorization scope in the request; the condition is met when the authorization in the request has an explicit basis in the materials with the same subject, the same period and the same field. In the sample that basis is absent, so record it as pending verification.

3. Check empty result handling with the paper input []. The input is an empty result; the comparison object is the downstream node design; the condition is met when the downstream can handle empty input and record the gap.
