# Complaints and official replies: interactive forms for operations handover

## What the documents look like

Complaint, report and regulatory-reply work draws on the 12315 platform, platform complaint centres, customer-service chat and order systems. The working documents are complaint tickets, regulatory inquiry letters, order evidence and rectification reports. Compared with after-sales repair and reshipment, this category faces a platform or a regulator, so it needs formal evidence and rectification wording. The consequences of error include administrative investigation, platform penalties and brand exposure.

The brief states that update frequency is irregular, on a per-case basis. This page addresses operations authority and handover management only. That update rhythm does not change how interactive forms are configured, so no synchronisation mechanism is described here.

Two document types matter at this step. A complaint ticket carries a subject, an object, a matter and a current status. A regulatory inquiry letter carries a deadline and a current drafting status. Neither document type, by itself, states who may hand the case over or whether a reply has been filed.

## Constraints at the interactive forms step

The form input node is a user-interaction node. When it triggers, the conversation enters an interactive state, the workflow state is recorded, and execution continues after the user completes the interaction. The node collects the values the user submits and passes them to later nodes. It does not carry a business database function of its own.

The user selection node is also a user-interaction node. It triggers the same interactive state, records the workflow state, and continues after the user completes the interaction. When the user makes a selection, the node evaluates that selection and executes the corresponding branch. Its basic use is to pose a question that requires a decision and to design different workflow paths from the feedback.

Neither node is a staff directory, a business-data selector or an authorisation credential. A branch outcome records which option was chosen. It does not execute a handover, grant a permission or file a reply.

Hypothetical drill sample. The source text reads: "Ticket A-0714, complained object is a shop, complaint matter is delayed shipment, current status is awaiting assignment by the customer-service supervisor; regulatory inquiry letter B-0714 requires a rectification report within five days, current status is awaiting confirmation of the drafter by legal compliance." The handover request to be assessed reads: "Transfer ticket A-0714 and inquiry letter B-0714 together to legal compliance, and treat the rectification reply as already filed."

This request exceeds the source in two places. The source shows only an awaiting-assignment status and an awaiting-drafter-confirmation status. It does not state a transfer recipient and does not state that filing is complete. Filing a rectification reply is a downstream business action; form interaction does not produce that result.

## Configuration and implementation checks

| Configuration item | Type | Check point for this page |
| --- | --- | --- |
| Form input node | Existing node behaviour | Triggers the interactive state; on submission collects fields and passes them to later nodes |
| Required-field list | Implementation check | For the sample, list subject, object, status and validity scope as four field classes |
| User selection node | Existing node behaviour | Executes a branch from the selection; does not act as an authorisation decision |
| Interactive-state wait | Existing node behaviour | Records workflow state and continues after the interaction completes |
| Handover request fields | Implementation check | Hypothetical starting value for this drill is four items, chosen to correspond to the four sample field classes; the comparison object is item-by-item coverage of the sample source text |
| Downstream business action | Requires a separate system implementation | Approval, write-back and filing of the rectification reply are carried by an external system |

The four-item handover request field set is a hypothetical starting value for this drill, not an official default. Its reason is that the sample source text supplies exactly four classes of information. The comparison method is to walk the source text item by item and record which classes are present.

## Three common errors

1. Treating a user-selection branch outcome as a completed authorisation. In the sample, inquiry letter B-0714 is awaiting confirmation of the drafter by legal compliance. Choosing "transfer to legal compliance" is an offered option; it is not an executed transfer.
2. Treating form submission as a filed rectification reply. Form input collects and passes fields. The submission action and the filing of a regulatory reply are two different facts.
3. Reading an awaiting-review status as an absence of operating permission. Ticket A-0714 is awaiting assignment by the customer-service supervisor. That status is unsupported for a handover decision; it is not a denial of permission.

## How to verify the setup

1. Input the sample source text and the handover request. Compare "treat the rectification reply as already filed" against "awaiting confirmation of the drafter by legal compliance". The observable result is that the source does not state filing is complete, so the request is recorded as pending verification.
2. Input the sample source text. Compare whether ticket A-0714's "awaiting assignment by the customer-service supervisor" contains any wording about missing permission. The observable result is that no such wording is present, so the item is recorded as unsupported.
3. Input an explicit paper input of an empty list. Check whether the downstream design retains a manual-intervention branch when the result is empty. The observable result is a pass when the design contains that branch. This does not assert that a fictional rule search returns an empty list.

All three verification items are expected phenomena only. No test has been run, and no deployment, approval, refund or filing has occurred.
