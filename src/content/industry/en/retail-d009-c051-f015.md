# Douyin storefront operations: retrieval for operations handover

## What the documents look like

Douyin storefront shelf operations centre on product cards and store experience scores rather than a single livestream rhythm. The working materials named in the brief are product qualification pages, experience score breakdowns, shipping violation appeals, and store announcements. These materials update daily and per order, so the same field can carry different values on different dates, and a handover between operators has to reconcile which value is current.

For operations permissions and handover management, the practical question is narrower than general search quality. It is whether a given material shows a particular state, whether an operational request already has a documented authorization basis, and whether the two sides of a handover record the same field in the same way. The knowledge base search node contributes only retrieval and quoted content. Its documented output is an array of references whose length can be zero, and the output path still runs when nothing is found. Retrieval does not decide permission.

## Constraints at the retrieval step

The search node can associate one or more knowledge bases that use the same vector model. Knowledge bases built on different vector models cannot be associated together. When candidate bases are checked, compare their vector model identifiers and exclude those that do not match, then record what was observed. Do not extend this same-model requirement to any other system, and do not infer recall behaviour from an association that was never performed.

Semantic retrieval computes similarity from vector distance. Full-text retrieval depends on keyword hits and suits identifiers, model numbers, proper nouns, and error codes. Hybrid retrieval uses both paths and merges them through RRF. Rerank performs a second ordering of candidate text and yields a score from 0 to 1. The minimum relevance value is a filter threshold that takes effect only in semantic retrieval or when result reordering is used. It is not a permission filter and does not isolate entities or unauthorized records. Question optimization performs coreference resolution and question expansion before retrieval, at the cost of an extra model call. Image retrieval requires an image input and the relevant model capability; reordering requires a reordering model enabled in the settings. The optional paths in the overall flow diagram do not all execute on every request.

Hypothetical paper exercise sample: the source material reads, "Store A submitted a shipping violation appeal on 1 March 2025, appeal number S-031, status pending review; the same day's store announcement states that the deadline for receiving supporting materials for this appeal is 10 March 2025." The draft sentence to be assessed reads, "Store A's appeal has been approved, and after handover the compensation offset can be executed directly." The source states only a pending review status and a materials deadline. It states no review conclusion and no authorizing party for a compensation offset. The draft sentence is unsupported.

## Configuration and implementation checks

| Configuration or check item | Hypothetical starting point for this page | Reason and comparison object |
| --- | --- | --- |
| Associated knowledge bases | Associate only knowledge bases using the same vector model as the sample material | Compare vector model identifiers item by item against candidate bases; exclude mismatches |
| Search mode | Run the sample question once with semantic retrieval and once with full-text retrieval | Compare whether the two recall paths cover appeal number S-031 and the status field |
| Reference limit | Starting point set to the token volume needed to cover the three source passages | Compare against the actual token volume of the source text and observe whether quoted content is truncated |
| Minimum relevance | Starting point set to 0.5 | Compare against scores of labelled relevant and irrelevant samples and observe the filtering result |
| Question optimization | Run the sample question once with it off and once with it on | Compare whether the optimized question retains the subject Store A and number S-031 |
| Result reordering | Run once where a reordering model exists and is enabled in the settings | Compare the ordering of the source passages under the reordering score and the semantic score |

The reference limit uses tokens as its unit. The starting value is a setting for this hypothetical exercise and is not an official default.

## Three common errors

1. Treating retrieved content as an authorization basis. Input: the sample question "can Store A's appeal proceed to a compensation offset". The retrieval recalls the appeal text and the announcement. Compare whether the recalled content contains a review conclusion and an offset authorization field. The observed result is that the source carries only a pending review status, so the draft sentence is unsupported; the retrieval action itself produces no authorization.
2. Writing a pending review status as approved. Input: the source phrase "status pending review". Compare the draft sentence's "has been approved" against the source value for the same field. The observed result is that the two values are mutually exclusive for that field, so the draft contradicts the source and should be returned for verification.
3. Associating knowledge bases built on different vector models. Input: two candidate bases with different vector model identifiers. Compare the two identifiers. The observed result is that they do not match, so the non-matching base is excluded and the observation recorded; no recall behaviour is inferred from the association.

## How to verify the setup

1. For the source text and the draft sentence, the input is the appeal text, the announcement text, and the draft sentence. Compare the draft's review conclusion field against the source status field. The observed result is that the source states no review conclusion, so the draft is unsupported. Where a downstream design needs to handle an empty reference, a paper input of `[]` can be used to check whether the downstream path runs; do not claim that a fabricated rule search necessarily returns `[]`.
2. For question optimization, the input is the sample question. Compare the question text before and after optimization. The observed result is whether the optimized question still retains the subject Store A and number S-031. If the subject is altered, record the observation and keep the original question.
3. For minimum relevance, the input is a labelled relevant sample and a labelled irrelevant sample. Compare their scores under semantic retrieval or reordering. The observed result is whether the relevant sample is retained and the irrelevant sample is filtered. This threshold is not used to exclude unauthorized records; permission decisions require a separate system implementation.

Across all three checks, the comparison must use the same subject, the same period, and the same field. Only explicitly mutually exclusive values for one field constitute a contradiction. A value that is not stated, or evidence that covers only an earlier stage, is unsupported or pending verification rather than contradicted. A pending review does not show that an operating permission is absent. Signing, reaching agreement, and contract effectiveness are three distinct facts. Retrieval and relevance scoring carry no permission or entity-isolation function.
