# Pinduoduo seller campaigns: citation tracing for operations handover

## What the documents look like

Pinduoduo low-price campaign store operations revolve around campaign resource slots, campaign inventory and refund-rate fluctuation. The working materials are campaign registration forms, product cost calculation sheets, after-sales refund slips and platform internal messages. These materials update daily or per campaign. During an operations handover, both sides must judge what state a given material is in: whether a registration form is a draft or already submitted, whether a cost sheet is an estimate or a confirmed version, whether a refund slip is pending review or already handled, and whether an internal message is a notice or a request for a reply. Citation tracing at this step lets the receiving operator see the original source behind each conclusion, so that a retrieved fragment or a form field is not treated as a completed authorization action.

## Constraints at the citation tracing step

The knowledge base search node outputs cited content as an array whose length may be zero; when nothing is found, the output path still runs through. The citation limit is controlled by tokens. The minimum relevance value applies only under semantic retrieval or result reranking, and it is a filter threshold. These settings affect how retrieval results are presented and trimmed; they do not constitute a permission judgment or an entity isolation rule. Associated knowledge bases must use the same vector model. During handover checking, first verify the knowledge base identifier and the material version, and exclude those that do not match; do not run cross-model retrieval to compare missed recalls.

Hypothetical paper exercise sample: in one Pinduoduo store's handover materials, the campaign registration form reads "Campaign name: Spring Low-Price Special; Registration status is Submitted; Submission date: 2025-03-01; Campaign inventory: 500 units." The product cost calculation sheet reads "Product code: SP-001; Calculation version: V2; Calculation date: 2025-03-02; Campaign-price gross margin: Pending confirmation." The platform internal message reads "Please confirm campaign inventory before 2025-03-05; failure to confirm by then is treated as giving up this resource slot." The handover request sentence to be judged is "The Spring Low-Price Special registration is submitted, the campaign inventory of 500 units is confirmed, and shipment can be arranged directly." This sentence equates the registration form's "Submitted" with inventory being "Confirmed." The materials do not state an inventory confirmation status, so the sentence is unsupported.

## Configuration and implementation checks

| Configuration or check item | Assumed starting point for this exercise | Reason for the choice and comparison method |
| --- | --- | --- |
| Associated knowledge bases | Select the knowledge bases holding the campaign registration form and internal messages | Check whether the vector model identifiers of each base are the same; exclude those that differ |
| Search mode | Hybrid retrieval | Compare against semantic retrieval and full-text retrieval separately for whether the cited original text is hit |
| Citation limit | Assumed starting point of 2000 tokens for this exercise | Compare with 1000 and 4000 tokens for number of citations and completeness of original text |
| Minimum relevance | Assumed starting point of 0.5 for this exercise | Compare with 0.3 and 0.7 for changes in the number of citations after filtering |
| Result reranking | Enabled | Compare with disabled for candidate text ordering and scores |
| Citation output handoff | Check whether the citation array is passed to the answering step | Compare each answer sentence against the cited original text one by one |

## Three common errors

1. Treating the internal message "Please confirm before 2025-03-05" as inventory already confirmed. The message text only expresses a request for a reply and does not state a confirmation result. Check action: input the internal message text and the draft sentence, compare whether "requested confirmation" and "confirmed" are the same field, and observe whether the draft sentence goes beyond the original text.

2. Treating the registration form's "Submitted" as the campaign already approved. The form text only records the submission status and does not state an approval result. Check action: input the registration form text and the handover request, compare whether submitted and approved are the same status field, and observe whether an approval record exists.

3. Treating the cost sheet's "Pending confirmation" as gross margin already finalized. The original text reads "Campaign-price gross margin: Pending confirmation." Check action: input the cost sheet text and the draft conclusion, compare whether pending confirmation and finalized are the same value, and observe whether a definite conclusion appears that the text does not state.

## How to verify the setup

1. Input the registration form text from the hypothetical sample and the draft sentence "the campaign inventory of 500 units is confirmed," compare whether the original text states an inventory confirmation status, and observe whether the draft sentence is supported. Expected phenomenon: the original text does not state a confirmation status, and the draft sentence is judged unsupported.

2. Input the internal message text and "failure to confirm by then is treated as giving up this resource slot," compare whether the original text states that consequence, and observe whether the sentence matches the original text. Expected phenomenon: the original text states that consequence, and the sentence is judged to have original-text support.

3. Input an empty citation array `[]` and the downstream answering step design, compare whether the downstream handles the empty array separately, and observe whether the output path still runs through. Expected phenomenon: the downstream has an explicit handoff design for the empty array and does not treat it as an error that terminates the run.

These judgments are all paper checks. No actual retrieval, approval or shipment action was executed.
