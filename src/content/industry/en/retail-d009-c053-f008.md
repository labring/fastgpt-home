# Channel receivables: workflow routing for operations handover

## What the documents look like

Channel receivables collection happens after credit sales. The operating core is credit granting and cash recovery, which distinguishes this work from B2B matchmaking transactions. The main materials come from the finance system, bank receipts, dealer orders, and sales contracts. The recurring documents are the receivables aging table, the collection letter, the credit agreement, and the shipment freeze notice.

These materials sit in different states during an operations handover. The aging table is an analysis result. The collection letter is text that is pending send or already sent. The credit agreement is a signed document. The shipment freeze notice is an action that is pending review or already executed. Workflow routing has to let interaction nodes collect information and pass that information to later nodes, while material state and authorization state are recorded separately.

The brief gives a weekly or monthly update frequency for this category. This page does not derive any batch sync, full sync, real-time mechanism, or transaction trigger from that frequency.

## Constraints at the workflow routing step

The form input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and the workflow continues downward only after the user completes the interaction. Once the user fills the required information and submits, the node collects the submitted form information and passes it to later nodes. The user selection node is also a user interaction node with the same interaction-state behavior. When the user makes a choice, the node evaluates that choice and executes the "yes" branch.

Retrieval or form collection completes information gathering only. Neither constitutes authorization or execution. Order writes, document backfill, and external status synchronization require a separate business interface or a later process. Semantic recall and relevance scores do not carry permission or entity isolation. Libraries built on different vector models cannot be associated together; the identifiers must be checked first and non-matching libraries excluded, without running cross-model retrieval to compare missed recall. The optional paths listed in the documented overall flow diagram do not mean every request executes all of them.

Hypothetical paper exercise sample. Source text one: "The March 2025 aging table for Dealer A shows an overdue amount of CNY 120,000, corresponding to credit agreement number SX-2025-017; the signing parties are Dealer A and the brand, signing date 10 January 2025." Source text two: "The draft shipment freeze notice names Dealer A as the object and carries the status pending review; the proposed freeze scope is 30 days." Draft handover request to be judged: "Please execute the over-credit shipment freeze for Dealer A and backfill the collection letter send record." The request contains a subject, an object, and a proposed action, but the freeze notice is in pending review status and no collection letter send record is stated.

## Three common errors

1. Treating a pending-review freeze notice as an executed freeze. In the sample, the freeze notice status is pending review while the handover request asks for freeze execution. Comparing the input against the status field should identify the request as unsupported, and the execution branch should not be entered.

2. Treating form submission as completed authorization. The form input node collects required information and passes it to later nodes. In the sample, the submit-handover selection produces an interaction result only; authorization state still has to be judged by a later business interface.

3. Treating a retrieval hit as a permission filter. Semantic recall and relevance scores do not carry permission or entity isolation. In the sample, retrieving the aging table does not mean Dealer A has been authorized for a freeze.

## How to verify the setup

1. Input source text one, source text two, and the draft handover request. Compare the freeze notice status field against the requested action. Observe whether the flow stays at the pending-review branch and whether the evidence gap is recorded, with no freeze executed.

2. Input the required form fields from the sample. Compare dealer name, agreement number, and overdue amount against the aging table source text. Observe whether a missing item fails to enter later nodes. The condition is met only when output matches input item by item.

3. Input an empty result [] and check the downstream design. Compare whether the downstream node handles it as empty input and whether it produces no fabricated rule retrieval result. For cross-model libraries, check identifiers first and exclude non-matching ones, then record the actual observation. First-hit return and full recall are not guaranteed.
