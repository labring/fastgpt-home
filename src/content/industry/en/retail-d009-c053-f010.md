# Channel receivables: citation tracing for operations handover

## What the documents look like

Channel receivables collection happens after credit sales. The operational focus is credit control and cash recovery. The working materials are the accounts receivable aging table, the demand letter, the credit agreement and the shipment freeze notice. These materials originate from the finance system, bank receipts, distributor orders and sales contracts, and they are refreshed weekly or monthly.

Operations handover in this category means that the outgoing and incoming staff check each material's source, version and current status, and confirm which actions already carry authorization and which requests are still pending. Citation tracing at this step lets every statement about aging, credit or freezing point back to specific source text, so a pending review state is not written as an approved state during handover.

## Constraints at the citation tracing step

The knowledge base search node can associate one or more knowledge bases that use the same vector model, and it outputs citations as an array whose length can be zero. The citation limit is counted in tokens, and the minimum relevance value takes effect only under semantic retrieval or result reranking. These parameters control retrieval scope and result trimming. They do not perform permission checks or entity isolation. Retrieval does not verify operational authorization, and a similarity score does not mean a record has been approved or falls within the current handover scope. Hybrid retrieval merges multiple result paths through RRF, reranking requires a model and must be enabled by configuration, and image retrieval requires image input and model capability. These paths are not mandatory steps on every request. Knowledge bases with different vector models cannot be associated together; check the identifiers first, exclude those that do not match, and record the actual observation without inferring runtime results.

Hypothetical paper exercise sample: Source text one reads "The brand finance department of Party A issued a demand letter to distributor Party B on 10 March 2025, stating an outstanding balance of RMB 1.2 million as of 28 February 2025 and requiring repayment by 31 March 2025." Source text two reads "Party B replied on 20 March 2025 with a repayment plan proposing two installments, the first RMB 600,000 due by 15 April 2025 and the second RMB 600,000 due by 15 May 2025; this plan still awaits written confirmation from Party A." The draft sentence to be assessed reads "Party B has completed the first installment repayment under the credit agreement, and Party A agrees to lift the shipment freeze." This draft sentence involves subject, object, status and effective scope, and must be compared item by item against the source texts above.

## Configuration and implementation checks

| Check item | Material or setting basis | Handover check action |
| --- | --- | --- |
| Associated knowledge bases | The knowledge base search node can select knowledge bases with the same vector model | Check the selected base identifiers against the vector model identifiers, and exclude those that differ |
| Citation output | Output is an array, and its length can be zero | Use the paper input `[]` to check the downstream handling design; do not infer that retrieval must return empty |
| Citation limit | Counted in tokens | Record the starting value used in this hypothetical exercise and compare it with the actual number of entries in the aging table |
| Minimum relevance | Takes effect only under semantic retrieval or result reranking | Check whether semantic retrieval or reranking is enabled; when neither is enabled this value does not participate in filtering |
| Response format | Select `json_schema` and fill in the format requirement when a fixed structure is needed | Check whether the draft sentence follows the filled format and compare it sentence by sentence with the source text |
| Thinking configuration | Controls thinking intensity and is unrelated to the citation limit | Check the thinking budget setting; do not use it as the citation token limit |

## Three common errors

1. Treating a retrieval hit as proof of authorization. Input: the demand letter source text and the draft sentence. Compare whether the draft sentence contains the statement "has completed repayment". The source text shows only that Party B proposed a repayment plan that still awaits written confirmation from Party A. Observable result: the draft sentence exceeds what the source text supports and should be marked as pending verification.
2. Writing a pending review state as an approved state. Input: the phrase "still awaits written confirmation from Party A" in source text two. Compare it with "Party A agrees to lift the shipment freeze" in the draft sentence. The source text does not state that Party A agreed. Observable result: that statement is unsupported, and the evidence gap remains.
3. Associating knowledge bases that use different vector models. Input: two knowledge base identifiers and their vector model identifiers. Compare whether the two identifiers match. When they differ, do not perform the joint association, record the actual observation, and do not infer missed recall or redundant results.

## How to verify the setup

1. Input source text one and the draft sentence. Compare whether the amount, date and subject in the draft sentence match the source text. The source text states a balance of RMB 1.2 million as of 28 February 2025. The draft sentence states no amount and no date. Observable result: the draft sentence lacks verifiable fields and should have its source added.
2. Input source text two and the draft sentence. Compare whether "still awaits written confirmation from Party A" and "Party A agrees" share the same subject, the same period and the same field. The two values are mutually exclusive. Observable result: the draft sentence contradicts the source text and should be changed to a pending-confirmation state.
3. Input the paper value `[]` and the downstream node design. Compare whether the downstream design handles an empty citation array. Observable result: the downstream design needs to specify how an empty array is handled; do not claim that a fictional rule makes retrieval always return an empty array.
