# Fresh-food supplier claims: retrieval for operations handover

## What the documents look like

Fresh-food supplier claims pursue quality liability for goods at arrival. The materials handled are quality exception forms, photographic evidence, deduction notices and claim reconciliation statements. Store-level natural shrinkage and markdown handling sit outside this scope. Data originates from quality inspection systems, WMS receiving records, supplier contracts and finance reconciliation, and it refreshes both per batch and per month.

For retrieval, this means one delivery batch may carry a quality conclusion, a receiving record and a reconciliation amount as three separate materials. A search has to gather them by batch, supplier and date range. When any one of the three is absent from the returned content, the only correct record is that the item remains to be verified. Quality photographs are image material. Whether they can be retrieved depends on whether an index was built when the material was stored and on the current model capability. A photograph that is not returned shows that this path produced no content; it does not show that the photograph does not exist.

## Constraints at the retrieval step

The retrieval step locates related materials. It does not decide authorization. A knowledge base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases with different vector models cannot be associated together. At that point the vector model identifier of each base is checked and the non-matching ones are excluded; a cross-model search is not run to compare missed recalls. Semantic retrieval, full-text retrieval and hybrid retrieval each fit different inputs. Exact queries such as a batch number, a deduction notice number or a claim number suit full-text or hybrid retrieval. Natural-language descriptions of a quality problem suit semantic retrieval. Hybrid retrieval merges multiple result paths through RRF; this is a result fusion process, not a switch that can be turned on.

The minimum relevance value takes effect only in semantic retrieval or when result reranking is used. It is a filter threshold. It does not perform permission or entity isolation, and it cannot be used to exclude unrelated suppliers or unauthorized records. The reference limit is measured in tokens, so materials of very different lengths need an actual check of whether their content is truncated. Question optimization performs coreference resolution and question expansion and adds an extra model call. A check compares the subject of the original question with the subject of the optimized question and looks for a changed supplier or batch. The output reference content is returned as an array and its length can be zero, so an empty result still completes the path.

Hypothetical drill sample: after a fresh produce delivery, the quality inspection system produces a quality exception form reading "Batch A-2405, supplier A, arrived 12 May 2024, leafy vegetables found at receiving with an excessive wilting ratio, judged a quality exception." The WMS receiving record of the same day reads "Batch A-2405 received into warehouse, accepted quantity 300 boxes." The finance reconciliation material reads "Batch A-2405 deduction notice generated, amount pending supplier confirmation." A draft sentence awaiting judgment reads: "The claim for batch A-2405 has been confirmed by the supplier and the deduction can be executed." The comparison objects are the three materials above, and the judgment scope is limited to this batch, this supplier and the period around 12 May 2024.

## Configuration and implementation checks

The configuration below is set around that sample and lists only settings documented for this function or implementation checks tied to this task.

| --- | --- | --- |
| Associated knowledge bases | Associate only bases holding quality, receiving and reconciliation materials whose vector model identifiers match | Check each base's vector model identifier first, exclude non-matching ones, and do not run a cross-model search |
| Search mode | Use full-text or hybrid retrieval for batch number A-2405 | Compare with semantic retrieval results and observe whether the batch number is matched exactly |

| Result reranking | Use when a rerank model is available and enabled by configuration | Compare scores before and after reranking and observe whether candidate order changes |

## Three common errors

1. Treating a retrieval hit as an authorization conclusion. A retrieved deduction notice shows only that the material exists. Whether the deduction can be executed depends on supplier confirmation, and in the sample the statement "amount pending supplier confirmation" is an unsupported state that cannot be written as confirmed.
2. Treating minimum relevance as a permission filter. That threshold only filters low-relevance content and does not distinguish supplier or record ownership. Using it to exclude unrelated suppliers embeds an authorization judgment into a retrieval parameter.
3. Treating RRF as a switch to enable, or forcing knowledge bases with different vector models into one association. RRF is the result fusion process of hybrid retrieval. Bases with different models require checking identifiers and excluding non-matching ones, without fabricating an outcome of the joint association.

## How to verify the setup

1. Input the three source materials from the sample together with the draft sentence "The claim for batch A-2405 has been confirmed by the supplier and the deduction can be executed." Compare the draft sentence with the wording "amount pending supplier confirmation" in the reconciliation material and observe whether the two agree on confirmation status. If the reconciliation material shows only a pending state, the draft sentence is unsupported and is recorded as to be verified.
2. Input batch number A-2405 into full-text retrieval and semantic retrieval separately. Compare whether the returned content from each path contains the quality exception form and the receiving record, and observe whether the batch number is matched exactly. If full-text retrieval matches and semantic retrieval does not, record that difference without inferring that the material is missing.
3. Input a paper empty result array [] to check the downstream design. Compare whether the downstream step continues on the empty reference and observe whether the path completes. This check only verifies how an empty result is carried; it does not claim that a fictional rule returns an empty array.
