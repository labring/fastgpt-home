# Store cold-chain receiving: retrieval for operations handover

## What the documents look like

Store cold-chain receiving for fresh goods centers on transport temperature, arrival batch, and store receipt records. The main data sources are cold-chain vehicle temperature control, WMS, the store receiving system, and quality inspection photos. The daily documents are cold-chain temperature records, arrival acceptance forms, rejection forms, and supplier delivery notes. These materials are produced per batch and per day, and one batch may carry both a temperature record and an acceptance conclusion as separate materials. The retrieval step needs to keep temperature records, acceptance forms, rejection forms, and delivery notes apart so that the acceptance conclusion for one batch is not applied to another batch. Materials are updated frequently, and a retrieval result reflects the content state at the time of ingestion, which is a different fact from whether the store has currently released the goods.

## Constraints at the retrieval step

Retrieval returns reference content for a question and does not perform permission judgment. The knowledge base search node can associate one or more knowledge bases that use the same vector model; knowledge bases with different vector models cannot be associated together. The vector model identifier must be checked first and non-matching bases excluded, with the actual observation recorded, and cross-model retrieval is not executed to compare missed recalls. Reference content is output as an array and its length can be 0, which means the downstream path still runs when nothing is found; a paper input of an empty array can be used to check the downstream design. The minimum relevance value takes effect only in semantic retrieval or when result reranking is used, and it is a filter threshold rather than a permission or entity-isolation mechanism. Hybrid retrieval merges multiple result paths through RRF, which is a result fusion process and not a switch. Image retrieval requires the corresponding image input and model capability, and reranking requires an available model enabled through the settings.

Hypothetical drill sample: a store receiving system records "arrival batch A on 10 March 2025, cold-chain vehicle temperature record shows 2 to 6 degrees Celsius, quality inspector sampled on site and filled in the arrival acceptance form, conclusion pending review." A rejection form draft of the same day states "batch A partially rejected, reason pending quality inspection confirmation." A draft sentence to be judged reads "batch A has passed acceptance and can be put on the shelf for sale." The check compares the draft sentence with the acceptance form text: the form conclusion is pending review while the draft sentence says acceptance has passed, the same field holds mutually exclusive values, and the draft sentence is not supported by the source text. The rejection form draft is in a pending-confirmation state and does not mean the rejection is complete.

## Three common errors

1. Treating retrieval recall as an authorization release. The input is the draft sentence "batch A has passed acceptance and can be put on the shelf for sale," and the comparison object is the acceptance form text "conclusion pending review." The two hold mutually exclusive values in the same field; releasing goods on this basis would treat a retrieval result as authorized execution, while the actual authorization state remains pending review.
2. Writing a pending-review state as completed. The input is the rejection form draft "reason pending quality inspection confirmation," and the comparison object is whether a signed rejection form exists. The draft is in a pending-confirmation state, and signing, completion of rejection, and contract effectiveness are three different facts; anything not stated remains to be verified.
3. Associating knowledge bases across vector models. The input is two knowledge bases whose vector model identifiers differ, and the comparison object is the vector model identifier field. When the identifiers do not match, only the identifiers are checked and the non-matching base is excluded; cross-model retrieval is not executed, and no missed recall or redundancy outcome is inferred.

## How to verify the setup

1. For the draft sentence "batch A has passed acceptance and can be put on the shelf for sale," input the sentence and the acceptance form text "conclusion pending review," and compare the values of the same field for the same batch. When mutually exclusive values appear, judge that the draft sentence is not supported by the source text, record the evidence gap, and do not supply an authorization clause.
2. For the rejection form draft, input the draft text and the check item for whether a signed rejection form exists, and compare the signing status field. Only when a signed rejection form with a matching date and batch appears may the rejection be recorded as complete; otherwise record it as pending verification.
3. For the associated knowledge bases, input the vector model identifier of each base and compare whether the identifiers match. Only bases with matching identifiers may be associated together; bases with non-matching identifiers are excluded and the actual observation is recorded, without claiming that cross-model retrieval would produce a particular result.
