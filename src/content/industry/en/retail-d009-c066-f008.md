# Short-video affiliate sales: workflow routing for operations handover

## What the documents look like

Short-video affiliate sales depends on long-term content exposure and product-link conversion rather than live explanation. During an operations handover, four document types form the material basis for authorization judgments: short-video scripts, the affiliate product list, the commission plan, and violation feedback. The supplied brief gives a daily and weekly update frequency. This page refers to updates only within that range and does not infer batch synchronization or real-time mechanisms.

These materials play different roles in a handover. The script and the product list describe how content maps to products. The commission plan describes the distribution arrangement. Violation feedback records platform-side handling. Together they indicate which authorization state a given operation request occupies. A pending review status, an approved status, and an executed status are separate facts, and the documents do not merge them.

## Constraints at the workflow routing step

Within workflow routing, the Form Input node and the User Selection node are both user-interaction nodes. When either node triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. The Form Input node collects required information and passes it to later nodes after submission. The User Selection node evaluates the user's choice and executes the corresponding "yes" branch. The interaction state and state recording are behaviors of the node itself. The documentation does not describe a global state-recording switch, a submission-count limit, or an automatic judgment mechanism.

Retrieval and forms do not constitute authorization. A form collects values; business verification, approval, database writes, and external synchronization require a separate business interface or a later process. An empty-result handoff can use an explicit paper input to check downstream design; there is no claim that a fictional rule retrieval returns an empty array. Libraries built on different vector models cannot be associated together. Check the identifier first and exclude non-matching libraries rather than running a cross-model retrieval to compare missed recalls.

Hypothetical drill sample: the source text reads, "Creator A submitted a short-video affiliate product list on March 1, 2025. The list states product M and a commission rate, with status pending review. On the same day, Creator A submitted a commission plan covering March 1 to March 31, 2025." The draft sentence to be judged reads, "Creator A's affiliate product list has been approved and can be executed according to the plan." The source text states only pending review and does not state approval, so the draft sentence is unsupported.

## Configuration and implementation checks

| Configuration item | Hypothetical starting point for this drill | Comparison method |
| --- | --- | --- |
| Required fields of the Form Input node | Product identifier, commission rate, start and end dates | Compare field by field against the source affiliate product list |
| User Selection node branch | The "yes" branch connects to a later node | Verify each branch connection is reachable |
| Interaction state check | The conversation enters the interaction state after triggering | Observe whether the conversation enters the interaction state |
| Output handoff check | Collected values pass to later nodes | Compare each output item against the input |
| External action division | Order writing connects to a separate business interface | Check whether the action falls inside the interface or a later process |

The starting point is chosen because the sample material contains product, rate, and period, which allows field-by-field comparison. The comparison target is the field stated in the source text, not an official default value.

## Three common errors

1. Treating a pending-review status as approved. The sample source text states pending review, while the draft sentence states approved. The same subject and the same field carry mutually exclusive values, which forms a contradiction.
2. Treating a form-collected value as authorized execution. The Form Input node collects required information and passes it on; approval and writing require a separate business interface.
3. Treating a retrieval result as a permission filter. A relevance score does not carry entity or permission isolation, and retrieval does not constitute authorization.

## How to verify the setup

1. Input the sample source text and the draft sentence. Compare the two values "pending review" and "approved." A contradiction is found only when mutually exclusive values appear for the same field.
2. Input the output of the Form Input node. Compare it against the value received by the later node. The handoff condition is met only when every item matches.
3. Input an external write request. Compare whether the action falls inside a business interface or a later process. The division condition is met only when the action falls inside the interface. These are paper checks and were not actually executed.
