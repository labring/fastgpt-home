# Short-video affiliate sales: retrieval for operations handover

## What the documents look like

Short-video affiliate sales relies on long-term content exposure and product-link conversion, without depending on live explanation. The working documents in this category are short-video scripts, product lists for attached links, commission plans, and violation feedback. Daily and weekly updates are the stated frequency for this material. The retrieval step reads what has actually been ingested and does not assume batching, full synchronization, or real-time mechanisms. When retrieval goes wrong, the stated consequences are failed promotion, wasted commission, and video takedown. Because of those consequences, retrieval output must be kept separate from the authorization state recorded at handover.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Bases with different vector models cannot be associated together. Check the model identifier first, exclude bases that do not match, and record what was observed. Compare semantic, full-text, and hybrid retrieval against the actual test question rather than assuming one mode suits all material. The reference upper limit is measured in tokens; use long and short script fragments to test whether content stays complete. The minimum relevance value takes effect only in semantic retrieval or when result reranking is used. Question optimization performs coreference resolution and question expansion. The retrieval output is an array whose length can be 0, meaning the downstream path still runs when nothing is retrieved. RRF is a fusion process for mixed results, not a switch. Retrieval and similarity scores do not carry permission or entity isolation.

Hypothetical paper exercise: on 10 June 2025 a content operator submits a handover request. The source text reads: "On 10 June 2025 I transfer the short-video script library retrieval permission for account A to product distribution specialist B. The transfer scope is limited to the script library and excludes the commission plan library. B may perform retrieval and may not modify the original data." The draft sentence to be judged reads: "B has obtained modification permission for all knowledge bases of account A." The draft sentence differs from the source in permission scope and in operation type. This is a paper exercise only; no test, approval, or handover was actually executed.

## Configuration and implementation checks

| Configuration item | Setting or check relevant to this page | Relation to the exercise |
|---|---|---|
| Associated knowledge bases | Select one or more knowledge bases with the same vector model | Check whether the script library and commission plan library share a vector model; exclude non-matching bases from joint association |
| Search mode | Semantic, full-text, or hybrid retrieval | Compare separately for script keywords and natural-language questions |
| Reference upper limit | Unit is token | Use long and short script fragments to test content completeness |
| Minimum relevance | Takes effect only in semantic retrieval or result reranking | Label relevant and irrelevant samples first, then adjust the threshold |
| Question optimization | Coreference resolution and question expansion | Compare original question with optimized question; check whether the subject was altered |
| Result reranking | Requires the model and must be enabled in settings | Rerank scores are 0-1 and can be used for filtering |

For the minimum relevance setting, a hypothetical starting value of 0.5 is chosen for this exercise because the labelled samples sit on either side of the middle of the 0-1 range, and it is compared against the scores of the labelled relevant and irrelevant samples. This is a starting value for the exercise, not an official default. Image retrieval requires an actual image input and the corresponding model capability. Reranking requires the model and must be enabled in settings. The optional paths in the overall flow diagram are not all executed on every request.

## Three common errors

1. Treating retrieval output as an authorization credential. Input: the source text and the draft sentence above. Compare permission scope and operation type. Observed result: the draft sentence exceeds the source scope and states a different operation type, so it is not supported by the source.
2. Forcing joint association of bases with different vector models. Input: the vector model identifiers of the script library and the commission plan library. Compare whether the identifiers match. Observed result: when the identifiers differ, joint association is excluded and the actual observation is recorded. Do not run a cross-model retrieval to compare missed recalls.
3. Treating a pending handover request as completed authorization. Input: the handover request text. Compare whether it contains a completed-approval field. Observed result: the text does not state an approval status, so the item remains pending verification. A pending request is not approval.

## How to verify the setup

1. Input the source text and the draft sentence from the exercise. Compare permission scope and operation type. The condition is satisfied when the draft sentence is observed to exceed the source scope; the draft sentence is then judged unsupported.
2. Input the vector model identifiers of the script library and the commission plan library. Compare whether the identifiers match. The condition is satisfied when the identifiers differ; joint association is then excluded and the actual observation is recorded. No cross-model retrieval is performed.
3. Input an explicit paper empty result `[]`. Check whether the downstream path continues. The condition is satisfied when the output array length is 0 and the downstream path still runs. This checks the documented empty-result behavior only; it does not claim that a fictional-rule retrieval must return `[]`.

Where the source text does not state an approval status, the authorization state remains unknown and must be recorded as a gap rather than as a denial or a conflict. Retrieval and similarity do not perform permission or entity isolation, and the same-vector-model requirement for associated knowledge bases does not extend to any external system.
