# Group-buy presale orders: citation tracing for operations handover

## What the documents look like

Presale group-buy operations collect orders first and organize procurement and fulfillment afterward. The operational difference from leader-relationship work is that a handover must transfer four document types together with their citation sources: the presale product table, the group-order result, the procurement plan, and the cut-off notice. These materials update daily and per session. If a handover transfers only conclusions and omits sources, the receiving operator cannot determine which version of the product table or which cut-off notice produced a given order quantity. The citation tracing step exists so that each key conclusion in operations permission and handover management can be traced back to a specific document version and a specific field.

A retrieval node returns citations as an array whose length may be zero. An empty array does not mean the workflow has errored or terminated. A knowledge base association requires the same vector model; knowledge bases with different vector models cannot be associated together. During checking, compare the identifiers first and exclude those that do not match. The minimum relevance value is a filter threshold and does not perform permission or entity isolation. Retrieval results do not constitute authorization.

The following sample is for paper-based checking.

Hypothetical drill sample: the source text reads, "Presale product table V3 records: for the 2025-06-10 session, warehouse A spinach 200 units, cut-off time 18:00. Cut-off notice N-0610 records: for that session spinach is procured at 200 units, procurement plan P-0610 has been generated, status pending review." The draft sentence to be judged reads, "Procurement plan P-0610 has been approved, spinach 200 units may proceed to procurement."

The difference between the draft sentence and the source is that the source states pending review only, while the draft writes approved; the source records no approving party and no approval time. Pending review does not demonstrate a lack of operating permission, and it does not equal approval. Judgment proceeds by same subject, same period, same field. A status field constitutes a contradiction only when it carries clearly mutually exclusive values; here the conclusion is unsupported.

## Constraints at the citation tracing step

The knowledge base search node outputs citation content as an array, and the length may be zero. A downstream answer step must be designed so that an empty citation array still flows through and does not fabricate a source. The associated knowledge bases must share the same vector model; a library with a different vector model is excluded rather than jointly searched. The minimum relevance value acts only as a filter threshold under semantic retrieval or when result reranking is used; it does not act as a permission filter or an entity filter.

Citation limits are expressed in tokens, not in a top-k item count. The documented unit is the token, and the limit caps how many tokens of content are cited per search. Reranking produces a score between 0 and 1 representing relevance between the search content and the question, and that score can be used for filtering. Hybrid search combines vector and full-text results through RRF, and the final ordering may not follow a single vector similarity order. RRF is a fusion process, not a toggle.

At the handover step, the operator must distinguish four things: behavior the node already performs, fields that are actually configurable, manual checking actions, and business actions that require a separate downstream implementation. A retrieval hit is not an authorization. A pending request is not an approval. An offered option is not execution. An unsigned termination is not a completed termination.

## Configuration and implementation checks

| Configuration or check item | Hypothetical starting value for this drill | Reason for the choice and comparison object |
| --- | --- | --- |
| Associated knowledge base | Select only the presale library whose vector model matches | Compare identifiers against a library with a different vector model; exclude non-matching ones |
| Search mode | Hybrid search | Compare against semantic search for hits on numbered fields |
| Citation limit | Hypothetical starting value 3000 tokens | Compare against 1500 tokens to see whether citation count covers the four document types |
| Minimum relevance | Hypothetical starting value 0.4 | Compare against 0.2 to see whether unrelated fragments decrease |
| Citation content handoff | Retrieval output passed to the answer step | Check each answer statement against the cited source text |
| Document timeliness check | One current-version and one historical-version product table | Compare whether the quantity field for the same session is consistent |

The citation limit starting value is a hypothetical figure chosen for this drill; it is not an official default. The comparison method is to run the same query at two values and count how many of the four document types appear in the returned citations. The minimum relevance starting value is likewise hypothetical, and the comparison method is to observe whether unrelated fragments are filtered out at the lower value.

## Three common errors

1. Writing a pending-review status as approved. Input: the sample source text. Comparison: the status field value. Observable result: the draft sentence contains an approval conclusion that the source does not contain.

2. Treating a retrieval hit as operating authorization. Input: the citation array returned by one retrieval. Comparison: the citation content against authorization fields. Observable result: the citations contain no approving party and no authorization scope.

3. Associating knowledge bases with different vector models together. Input: the vector model identifiers of two libraries. Comparison: whether the identifiers match. Observable result: the non-matching library is excluded.

## How to verify the setup

1. Input the sample source text and the draft sentence. Compare the status field. The condition is satisfied only when the draft sentence retains pending review and adds no approval conclusion.

2. Input a paper citation array `[]`. Compare the design of the downstream answer step. The condition is satisfied only when the downstream step continues through the empty citation and does not fabricate a source.

3. Input two library vector model identifiers that differ. Compare the identifiers. The condition is satisfied only when the non-matching one is excluded and no cross-model retrieval is executed.

These are paper-based checks. They have not been executed. Where the source does not state an approving party, an approval time, or an authorization scope, those remain missing evidence and are recorded as gaps rather than filled in.
