# Cross-border resale returns: access controls for operations handover

## What the documents look like

Cross-border return refurbishment and resale handles reverse logistics and item condition, which places it on a different chain from overseas-warehouse replenishment. The working materials are the return inspection form, the refurbishment record, the scrap form and the resale listing sheet. Source data arrives from the overseas-warehouse WMS, the TikTok return center, Amazon return reports and inspection photographs. These materials are updated daily or per batch, and handover requires checking each one.

For access control and handover, the material identities matter as much as the content. A return inspection form records graded condition; a refurbishment record documents packaging replacement; a scrap form records write-off; a resale listing sheet records items proposed for listing. Each of these is a separate object with its own collaborators, and the state recorded inside a document is not the same as an authorization to act on an external system.

## Constraints at the access controls step

Team permissions are judged across three dimensions: member, department and group. Member permissions take priority; department and group permissions are combined as a union. File-level permissions for a knowledge base are off by default. In the off state, collection readability matches the knowledge base and the system does not query collection permission records. Once enabled, each file or folder generates a complete permission snapshot, and list, detail and retrieval recall are checked item by item against that snapshot. Knowledge base permission remains the threshold: a collection permission cannot bypass knowledge base permission. Team administrators do not bypass file-level permissions. Retrieval recall filters only when authentication runs under the current member identity; a preselected knowledge base without member-identity authentication does not apply file-level filtering.

Hypothetical paper exercise sample: a cross-border seller's after-sales supervisor submits a handover request reading: "On 10 June 2025, return inspection form RT-0610 records that 20 returned units of SKU-A were graded by overseas-warehouse inspection as refurbishable; refurbishment record FR-0610 completed packaging replacement; resale listing sheet RS-0610 places 15 of those units as pending listing; scrap form SC-0610 records 5 units scrapped. Please synchronize this sheet to the Amazon backend." Proposed determination sentence: "The 15 units in RS-0610 already hold resale listing authorization." The request does not state who holds Amazon backend operating permission, nor who executes the synchronization.

## Configuration and implementation checks

| Check item | Documented basis | Implementation check on this page |
| --- | --- | --- |
| Member permission priority | Member permission is highest; department and group permissions form a union | Compare the after-sales supervisor's actual individual permission against the group permission combination |
| Knowledge base threshold | Collection permission cannot bypass knowledge base permission | Confirm read permission has been granted on the knowledge base holding the inspection form |
| File-level permission switch | Off state does not query collection permission records | Check the switch state of the knowledge base holding the return inspection form |
| Creator constraint | The collaborator list must include the creator | Inspect whether the refurbishment record collaborator configuration includes its creator |
| Retrieval recall scope | Filtering applies when authentication runs under current member identity | Check whether resale listing sheet retrieval authenticates by member |
| External system permission | External interface authentication and resource permission are verified separately | Check whether Amazon backend operating permission is configured separately |

## Three common errors

1. Treating retrieval relevance as access authorization. In the hypothetical sample, a member being able to retrieve RS-0610 does not mean that member holds Amazon backend synchronization permission; external system authentication must be checked separately.

2. Ignoring the knowledge base threshold. If read permission has not been granted on the knowledge base holding the inspection form, the member still cannot access it even when file-level permission has been configured.

3. Treating a pending-review state as granted authorization. In the hypothetical sample, RS-0610 places units as pending listing and does not state that approval is complete, so the units cannot be determined to hold listing authorization.

## How to verify the setup

1. Input the hypothetical sample text and the proposed determination sentence. Compare "already hold resale listing authorization" against the source wording "pending listing." The source does not state that approval is complete, so the determination sentence is not supported.

2. Input the RS-0610 sheet and a member account. Compare what that member can actually see in knowledge base retrieval. If the retrieval result includes RS-0610 and the member holds knowledge base read permission, file-level filtering is in effect; if the retrieval result is empty, record the empty result and do not infer that the rule necessarily returns empty.

3. Input the synchronization action in the handover request and the Amazon backend permission configuration. Compare whether the requester holds external system operating permission. The source does not state the permission holder, so this item remains to be verified.
