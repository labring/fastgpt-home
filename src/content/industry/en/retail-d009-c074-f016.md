# Cross-border resale returns: interactive forms for operations handover

## What the documents look like

Cross-border return refurbishment and resale handles reverse logistics and item condition. The records come from overseas warehouse WMS, TikTok return centers, Amazon return reports, and item inspection photos. The working documents are the return inspection form, the refurbishment record, the scrap or disposal form, and the resale listing list. This page covers one slice only: operations permissions and handover management at the interactive forms step, meaning which materials, actions, and requests sit at which authorization state when a handover is proposed.

The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution waits until the user completes the interaction. After submission, the node collects the entered form information and passes it to later nodes. The node does not carry a business database function of its own. The User Selection node also triggers the interaction state and executes a branch based on the user's choice. Both nodes perform information collection and branch judgment. Field validation, business approval, write-back, and batch operations need an external system or a later node.

Because handover depends on knowing the authorization state of each document, the inspection form, refurbishment record, disposal form, and resale list must each be traceable to a stage: submitted, pending review, approved, or executed. The interactive nodes can gather and route that information. They do not decide whether the authorization holds.

## Constraints at the interactive forms step

A handover request can only be judged against the state of the material it cites. The following is a clearly labelled hypothetical paper exercise, not a real record and not a completed test.

Material text available for checking: "Return inspection form RT-2024-0512, inspector Li, 12 May 2024, item A, inspection conclusion: can be refurbished. Refurbishment record RF-2024-0512, refurbishment staff Wang, 13 May 2024, item A, refurbishment complete, pending inspection re-check. Disposal form SC-2024-0512, after-sales supervisor Zhao, 14 May 2024, item A, disposal requested, status pending review."

One handover request to be judged: "Move item A from the refurbishment record into the resale listing list, with disposal form SC-2024-0512 as the authorization basis."

The disposal form cited is at pending review, which is not an approval. The refurbishment record is marked pending inspection re-check, so the re-check is not complete. The handover request therefore lacks an approved disposal decision or a completed inspection re-check as its authorization basis. The Form Input node can collect the fields of this request. The node itself does not determine whether authorization is established.

## Configuration and implementation checks

The table stays with this page's documents and primary task. It separates documented node behavior from implementation checks that a team must define. No numeric value is asserted as an official default.

| Configuration item | Type | Description |
| --- | --- | --- |
| Form Input node | Documented | Triggers the interaction state, collects entered information, passes it to later nodes after submission |
| User Selection node | Documented | Triggers the interaction state, executes a branch based on the user's choice |
| Required-field check | Implementation check | List the fields a handover request cannot omit; test the missing case and the completed case separately |
| Authorization state field | Implementation check | Record whether the material is submitted, pending review, approved, or executed |
| Downstream division of work | Implementation check | Field validation, business approval, write-back, and batch operations are implemented in an external system or a later node |
| Interaction state recording | Documented | After the node triggers, the workflow state is recorded and execution waits; after interaction completes, execution continues |

For this paper exercise, a hypothetical starting point is three required fields in the Form Input node: material number, current state, and authorization basis number. The reason for choosing this starting point is that a handover request needs at least these three items to check authorization state. The comparison method is to remove one field at a time and submit, then observe whether the node enters the interaction state and indicates the missing item. This is a proposed comparison, not a recorded result.

## Three common errors

1. Treating pending review as approved. Input: disposal form SC-2024-0512 with status pending review. Comparison object: the approved state. Observable result to watch: after form submission, a downstream node receives that disposal form number and proceeds with resale listing. Pending review does not constitute approval, so that result does not satisfy the authorization condition.

2. Treating pending inspection re-check as a completed re-check. Input: refurbishment record RF-2024-0512 marked pending inspection re-check. Comparison object: the completed re-check state. Observable result to watch: the handover request uses that refurbishment record as its only authorization basis. Pending re-check does not constitute a completed re-check, so that basis is insufficient.

3. Treating form submission as authorization execution. Input: the Form Input node has collected the handover request fields. Comparison object: an approval record in the external system. Observable result to watch: the workflow continues and performs the resale listing action. The Form Input node only collects and passes information; business approval needs an external system or a later node, and form submission itself does not produce authorization.

## How to verify the setup

1. Input the hypothetical disposal form SC-2024-0512 at status pending review. Compare that status with the approved state. Observe whether, after form submission, the downstream node refuses to use that disposal form as the authorization basis for resale listing. If the downstream node receives the number and performs the listing, the condition is not met.

2. Input the hypothetical refurbishment record RF-2024-0512 marked pending inspection re-check. Compare that marking with the completed re-check state. Observe whether the handover request uses that refurbishment record as its only authorization basis. If the request uses it as the only basis and continues execution, the condition is not met.

3. Input the complete handover request fields from the hypothetical sample. Compare the fields collected by the Form Input node with an approval record in the external system. Observe whether the workflow continues to perform resale listing without an external approval record. If the workflow continues, the condition is not met. This comparison must occur within a target retrieval scope the reviewer has access to, or through an explicit manual input. Where that access or input is absent, record the evidence gap rather than a conclusion.

Across all three checks, a pending request is not an approval, an offered option is not execution, and an unsigned termination is not a completed termination. Where a required field or approval record is not provided, that field remains unknown.
