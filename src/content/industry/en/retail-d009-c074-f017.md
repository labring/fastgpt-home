# Cross-border resale returns: upgrades for operations handover

## What the documents look like

This page covers one task inside cross-border return refurbishment and resale: operations permissions and handover management at the deployment and upgrade step. The working documents are the return inspection sheet, the refurbishment record, the scrap sheet, and the relisting list. The inspection sheet records the quality conclusion, the refurbishment record covers the rework performed, the scrap sheet records the scrap decision, and the relisting list defines the scope approved for a second listing. Overseas warehouse inspectors and after-sales supervisors maintain these materials. Data arrives from the overseas warehouse WMS, the TikTok return center, Amazon return reports, and product inspection photos. Grading a return, arranging refurbishment packaging, and deciding scrap or resale are the slowest steps. Increased refund cost, repeat complaints, and inventory that does not match the books are the consequences of error. At the deployment and upgrade step, permission and handover state must bind to a specific material and a specific operation. A retrieval hit or a completed form does not constitute authorization.

## Constraints at the upgrades step

Before upgrading, compare the running version against the target version and its upgrade notes. Do not infer current behavior from an old configuration name. The V4.17.2 upgrade notes list two manually triggered scripts: the historical chunk training task migration (`20261008_migrate_chunk_training`) and the knowledge base rebuild status migration (`20261009_migrate_dataset_rebuild_status`). The second depends on the first completing. Neither blocks service startup. Before running them, confirm that all old-version FastGPT App and Pro instances have fully stopped and that old task leases have expired.

The following is a hypothetical paper exercise used to show the comparison method. It does not state that any upgrade or handover was actually performed.

Hypothetical exercise sample. The handover material reads: "Return inspection sheet Q-2026-0312, subject: after-sales group, object: 40 returned items in batch B-77, status field: 'inspection complete, pending refurbishment', date 12 March 2026, authorization scope field empty." The proposed determination sentence is: "This batch has completed refurbishment and is approved for relisting." Comparison result: the material records only inspection completion and pending refurbishment. The refurbishment record and the relisting list were not provided. Refurbishment completion and relisting authorization are unsupported and remain pending verification.

## Three common errors

1. Reading "pending refurbishment" on the inspection sheet as completed refurbishment. Input: Q-2026-0312 with status field "inspection complete, pending refurbishment". Comparison object: whether a refurbishment record exists. Observable result: the refurbishment record is absent, so refurbishment completion is unsupported.
2. Treating a completed form as an authorization action. Input: the inspection sheet with an empty authorization scope field. Comparison object: whether a signed or approved record exists. Observable result: no approval material is present, so relisting authorization is unsupported.
3. Treating a retrieval hit as a permission release. Input: a return record returned by a knowledge base search. Comparison object: the actual permission scope of the current account. Observable result: the search result carries no permission information, so authorization must be checked separately.

## How to verify the setup

1. Input the hypothetical sample text above and the proposed determination sentence "This batch has completed refurbishment and is approved for relisting". Compare the status recorded in the material against the assertion in the sentence. The sentence is supported only when both the refurbishment record and the relisting list state the matching subject, batch, and date. The current sample does not satisfy this.
2. Input the upgrade script precondition check. Compare the stopped state of cluster instances against the lease state. The training task migration precondition is satisfied only when all old instances are stopped and leases have expired. This remains a hypothetical pending item.
3. Input a cross-library retrieval request. Compare the vector model identifier of each library. Association is permitted only when the identifiers match. Exclude non-matching entries and record the actual observation. Do not run a cross-model retrieval to compare missed recalls.

An empty result check may use an explicit paper input `[]` to carry the downstream design. Do not claim that a fabricated-rule search necessarily returns empty. Retrieval and relevance do not carry permission or entity isolation duties.
