# Creator sales campaigns: interactive forms for operations handover

## What the documents look like

Creator sales campaigns centre on external creator fulfilment and commission settlement. Brand business teams, MCN agencies and creator managers work from the selected alliance, the star map, creator historical data and store transaction details. Each campaign and each week brings fresh material, so the creator cooperation agreement, the commission setting sheet, the sample dispatch note and the live campaign report become the basic handover documents. These four documents record cooperation intent, fee arrangements, physical sample movement and result data respectively, and none of them substitutes for another.

The operational difficulty sits in the handover: what state each document is in, who may act on it, and whether any authorization has actually been granted. A retrieval hit or a form submission does not by itself constitute authorization to execute anything downstream.

## Constraints at the interactive forms step

The form input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution waits until the user completes the required fields and submits. The collected information then passes to later nodes. The user selection node also enters the interaction state and records workflow state; when the user makes a choice, the node evaluates that choice and executes the corresponding branch. Neither node carries a business database. Field validation, business approval, write-back and batch operations belong to an external system or to later nodes.

Hypothetical paper exercise sample. The material text reads: "Party A commissions Party B to conduct one creator campaign live stream on 18 June 2025; the slot fee and commission ratio are set out in the commission setting sheet; this agreement takes effect from the date both parties sign." A separate sample dispatch note states: "The sample was sent on 10 June, addressed to Party B's live streaming team." The draft handover request to be assessed reads: "This creator campaign cooperation is already effective; please open commission settlement permission and transfer live campaign report viewing permission." Signing, cooperation being reached, and the contract taking effect are three distinct facts. The material records only the condition for taking effect on signing. It does not record a signing completion date or any record granting settlement permission. The commission setting sheet and the live campaign report are not provided. The draft sentence states a pending state as already effective and requests permission opening, which goes beyond the material.

## Configuration and implementation checks

| Configuration item | Setting or check relevant to this page | Relation to the sample |
| --- | --- | --- |
| Form input node | Enters the interaction state on trigger, collects required information, passes it to later nodes | Collects the fields the handover request needs |
| Required-field check | List the fields this task cannot do without; check missing items and behaviour after completion separately | Sample lacks a signing date and a permission grant record |
| User selection node | Executes a branch based on the user choice; it is not a personnel directory or business data selector | Separates the continue-handover branch from the supply-materials branch |
| Interaction state | Records workflow state and waits for interaction, then continues downward | Keeps the pending state while materials are supplied |
| Downstream division of work | Field validation, approval, write-back and batch operations are implemented in an external system or later nodes | Permission opening does not follow automatically from form submission |
| Hypothetical starting point for this exercise | Proposed required fields: agreement signing date, commission setting sheet number, live campaign report scope. Reason: these three determine whether handover can continue. Comparison method: check each missing item and the branch taken once it is supplied | A paper check starting point only, not an official default value |

## Three common errors

1. Treating form submission as completed authorization. In the sample the draft sentence asks to open commission settlement permission. The form input node only collects and passes information; approval and permission opening require an external system, and the submission action produces no authorization effect.

2. Writing a pending state as already effective. The sample material records only the condition for taking effect on signing and does not record that signing was completed. The draft sentence writes "already effective", presenting an unsupported fact as a settled conclusion.

3. Using a retrieval hit in place of a permission decision. Relevance and semantic recall carry no permission or entity isolation duty. A hit on commission setting sheet text does not mean the record may be viewed or acted on by the current handover person.

## How to verify the setup

1. Input the sample material text and the draft sentence. Compare whether "already effective" in the draft and "takes effect from the date both parties sign" in the source share the same subject, the same period and the same field. When the source records no signing completion date, the finding is pending verification and the draft should be rewritten as a pending statement.

2. Input the sample with the missing signing date and missing permission grant record. Compare the required-field check result with the branch taken at the user selection node. The condition is met when the supply-materials branch appears and the interaction state is retained. Entering the permission-opening branch directly does not meet the condition.

3. Input a paper empty result [] and check the downstream design. Observe whether the downstream treats an empty result and an unauthorized state as separate cases. Record only what is observed. Do not assume an empty result necessarily appears, and do not state that retrieval necessarily returns empty.

This page addresses one scope only: creator sales campaigns, operations permission and handover management, interactive forms. Which materials, actions and requests sit at which authorization state during handover is the question, and neither retrieval nor a form may be treated as authorization to execute.
