# Creator commission settlement: citation tracing for operations handover

## What the documents look like

Commission settlement for creators happens after a sale closes. The objects being checked are valid promotion orders and after-sales commission deductions, not the pre-sale terms that a creator special session would use. The working materials are commission setting records, settlement statements, refund deduction details and invoices. These come from different systems: the selection alliance backend, order after-sales data, the finance system and creator contracts. The update cadence is weekly or monthly, so a handover needs both sides to confirm which period and which version each material covers before deciding whether a citation still supports the current settlement basis.

Citation tracing has one direct job here. Any commission rate, deduction amount or settlement conclusion must point back to specific source text. A retrieval hit does not grant authority to pay, approve or continue processing. The operations handover task is to separate what a document records from what a person is permitted to do next.

## Constraints at the citation tracing step

The knowledge base search node selects one or more knowledge bases that share the same vector model, and outputs cited content as an array whose length can be zero. The output link still runs when nothing is found. The citation upper limit is controlled in tokens. The minimum relevance value takes effect only under semantic retrieval or result reranking. Hybrid retrieval merges multiple result paths through RRF. Reranking needs a rerank model and must be enabled by configuration. Image retrieval needs corresponding image input and model capability. These paths do not all execute on every request.

Semantic recall and relevance scores do not carry permission or entity isolation. A same-vector-model requirement only constrains which knowledge bases can be associated together. It does not extend to business registration sites or other external systems.

Hypothetical paper exercise sample. Material text one: "June 2025 settlement statement: Creator A, June valid order commission 8000 yuan, refund deduction 1200 yuan, payable 6800 yuan, status pending finance review." Material text two: "Commission setting record: Creator A, commission rate 15% from 1 June 2025, 12% before 31 May 2025." Draft sentence to be judged: "Creator A's June commission was settled at 15% and payment was completed." Handover request: "Operator B is asked to continue processing Creator A's June payment based on the above statement."

## Three common errors

1. Treating a retrieval hit as operational authorization. Input is the handover request above and the retrieved statement. The comparison object is the statement status "pending finance review" against the draft sentence "payment was completed." The observable result is that the draft sentence asserts a completed payment with no corresponding record in the material, so it is unsupported.

2. Associating knowledge bases that use different vector models. Input is the vector model identifiers of the two bases. Compare whether the identifiers match. The observable result is that differing identifiers lead to exclusion; do not run cross-model retrieval to compare missed recalls.

3. Treating a relevance score as a permission or entity filter. Input is a semantic retrieval score and the scope of Creator A's materials. Compare the score level against material ownership. The observable result is that the score does not change whether a record belongs to the current handover object.

## How to verify the setup

1. Input the statement text, the commission setting record text and the draft sentence from the hypothetical sample. Compare the rate and payment status claimed in the draft sentence against the corresponding fields in the source text. Only mutually exclusive values for the same field in the same period count as a contradiction. Here the completed payment claim is unsupported.

2. Input the handover request and the statement status field. Compare whether "pending finance review" and "authorized to continue payment" are the same fact. Only an explicit authorization record satisfies the condition to continue. The evidence gap remains open at this point.

3. Input an explicit paper empty array as the cited content output. Compare whether the downstream design continues to run with a citation length of zero. The condition is met when downstream does not halt because of the empty citation. Do not claim that a fictional retrieval necessarily returns an empty array.

Each question uses the full hypothetical evidential context given above, or remains an explicitly unanswered case. Missing evidence stays missing. A pending request is not approval, and a retrieval hit is not execution.
