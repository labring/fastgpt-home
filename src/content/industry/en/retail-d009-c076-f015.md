# Creator commission settlement: retrieval for operations handover

## What the documents look like

Commission settlement occurs after a sale closes. The objects being reconciled are valid promotion orders and post-sale commission deductions, and the material set updates on a weekly and monthly rhythm. Four document types form the retrieval library: commission setting records, settlement statements, refund deduction details, and invoices. Their field definitions are spread across the affiliate program backend, order after-sales data, the finance system, and creator contracts.

At the retrieval step, the knowledge base search node returns relevant passages to the model. Authorization decisions and business execution belong to downstream systems. The update frequency of the material only describes how often documents are produced; the retrieval configuration itself does not change with that rhythm.

For operations handover, the practical question is which materials, operations, and requests sit at which authorization state. Retrieval output and form values are not authorization. A settlement statement that has been recalled is still a statement, not a payment confirmation. A handover request that has been submitted is still a request, not an approved permission change.

## Constraints at the retrieval step

The knowledge base search node can associate one or more knowledge bases that use the same vector model. Knowledge bases with different vector models cannot be associated together. Before association, the vector model identifier must be checked and non-matching libraries excluded.

Semantic retrieval, full-text retrieval, and hybrid retrieval should be compared against the same test question. No single mode is presumed suitable for all material. The citation limit is measured in tokens. The minimum relevance value takes effect only under semantic retrieval or when result re-ranking is used. Question optimization performs coreference resolution and question expansion, and it adds an extra model call before retrieval. Hybrid retrieval merges multiple result paths through RRF; RRF is a fusion process, not a toggle switch.

Image retrieval requires image input and the corresponding model capability. Re-ranking requires a re-rank model and must be enabled according to configuration. The optional paths listed in the documented flow do not mean every request executes all of them. Citation content is output as an array, and its length can be 0, meaning the downstream chain still proceeds even when nothing is retrieved. Similarity and relevance serve ranking and filtering; they do not perform permission or entity isolation.

Hypothetical paper exercise sample: the source material reads, "The March 2025 settlement statement for Creator A shows valid order commission of 8,000 yuan, refund deduction of 1,200 yuan, and net settlement of 6,800 yuan; the commission setting record for the same month states a 15% commission rate for the food category; the invoice column notes 'to be issued after creator confirmation.'" The draft sentence to be assessed is: "Creator A's March commission has been settled in full and the invoice has been issued." The comparison holds the same subject, same period, and same field: whether the net settlement field matches "settled in full," and whether the invoice note status matches "invoice has been issued." The note is in a pending-confirmation state, so the invoicing fact is not supported, and the draft sentence must retain the evidence gap.

## Three common errors

1. Treating a retrieval hit as authorization. The input is the draft sentence "Creator A's March commission has been settled in full and the invoice has been issued." Retrieval may recall the settlement statement passage. The comparison must check the invoice note status. Recalling a relevant passage does not mean invoicing has been executed; a pending-confirmation state remains unsupported.

2. Treating minimum relevance as a permission or entity filter. The input is the same test question, and the comparison is the recalled content under different thresholds. Relevance affects ranking and filtering only. It does not exclude unrelated businesses or unauthorized records. Authorization decisions require downstream implementation.

3. Treating a pending-review request as an approved operation. The input is a handover request item reading "apply to enable settlement statement export permission." The comparison is the request status field. Pending review does not demonstrate the absence of an operation permission, and it does not constitute approval. Signing, cooperation reaching agreement, and contract taking effect are three distinct facts.

## How to verify the setup

1. Input the hypothetical sample source text and the draft sentence. Compare the settlement statement's net settlement field against "settled in full," and the invoice note against "invoice has been issued." The condition is satisfied when the draft sentence retains a to-be-verified formulation and does not state a definite conclusion.

2. Input the same test question through semantic retrieval and full-text retrieval separately, and compare the recalled content. The condition is satisfied when a numbering or proper-noun question is matched under full-text retrieval and a natural-language question is matched under semantic retrieval. Record the observation when no match occurs.

3. Input an explicit paper-based empty result `[]` and check whether the downstream node handles it normally. The condition is satisfied when the citation array length is 0 and the chain still proceeds. Do not claim that a fictional rule retrieval necessarily returns an empty array. For libraries with different vector models, verify identifiers first and exclude non-matching ones; do not run cross-model retrieval comparisons.
