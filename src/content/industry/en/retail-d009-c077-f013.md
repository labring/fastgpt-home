# Import and export permits: access controls for operations handover

## What the documents look like

Import and export permit handling happens before customs declaration, and it determines whether a shipment may lawfully cross a border. The working materials come from commerce authority systems, customs commodity codes, supplier records, and customer end-use statements. Day-to-day documents include automatic import licences, dual-use item licences, contracts, and product descriptions. These materials are updated per shipment rather than on a fixed schedule.

For this page the scope is narrow: operations permissions and handover management, specifically permission and data isolation. The question is which materials, actions, and requests sit in which authorization state at the moment of handover. Retrieval visibility and form submission do not by themselves constitute an authorization to act. A licence application that has been submitted and is awaiting a decision is not a licence that has been issued.

## Constraints at the access controls step

Permit materials are generated per shipment. The contract, the end-use statement, and the licence draft for one shipment are frequently handled by different roles, so handover is where visible scope and operating permission drift apart. FastGPT configures permissions across three dimensions: members, departments, and groups. Member permission carries the highest priority; department and group permissions are combined by union and rank below member permission. Knowledge base permission is always a threshold, and collection-level permission cannot bypass it.

Collection-level permission is off by default. In the off state, collection readability matches the knowledge base and the system queries no collection permission records. When it is on, each file or folder receives a permission snapshot, and lists, details, and retrieval recall are authorized item by item against that snapshot. Retrieval recall filters by the files the current member can read, and this applies only when authentication runs as the current member identity. A similarity or relevance setting does not perform permission or entity isolation.

Hypothetical drill sample. A trade compliance role intends to hand one shipment's automatic import licence work to a customs role. The materials supplied for checking are three sentences. First: "The application materials for this shipment's automatic import licence were compiled by compliance role A, comprising one contract and one product end-use statement, with compilation completed on 10 March 2025." Second: "Customs role B is responsible for follow-up on this shipment from 11 March 2025, with material viewing scope limited to this shipment's folder." Third: "The licence for this shipment has not yet been issued by the commerce authority; the application is in a submitted, pending-approval state." The draft sentence to be assessed is: "Customs role B is authorized to modify all licence materials for this shipment and may synchronize materials to an external supplier system." The material object, handling subjects, date scope, and authorization boundary are all given in the request, but the modification authorization and external synchronization described in the draft sentence have no corresponding basis in the source text.

## Configuration and implementation checks

The table below lists only settings or implementation checks that the official documents describe, tied to the sample above.

| Configuration item | Documented setting or check | Relation to the sample |
| --- | --- | --- |
| Knowledge base collection-level permission switch | Off by default; turning it on requires knowledge base manage permission, and the switch is set only after materialization succeeds | Whether this shipment's folder has it enabled determines whether single-file collaborators can be configured |
| File collaborator roles | Read, write, admin, creator; the creator cannot be granted or modified through collaborator configuration | The role granted to customs role B must be compared against the modification scope in the draft sentence |
| Collaborator submission semantics | Full overwrite; the submitted list is the final result and must contain the current creator | Whether the handover collaborator list retains the creator record |
| Retrieval recall authorization condition | When authenticating as the current member, filtering is by readable files | The visible scope when customs role B consults this shipment's folder |
| Team administrator boundary | Team administrators do not bypass collection-level permission | Team-level management permission does not automatically extend to file operation authorization |
| External system permission | External interface authentication and FastGPT resource permission are verified separately | The external supplier system synchronization in the draft sentence has no corresponding implementation basis |

## Three common errors

1. Treating retrieval visibility as operating authorization. The input is customs role B viewing this shipment's folder; the comparison is the draft sentence's modification of all materials; the observable result is that viewing visibility produces no write or admin permission.
2. Treating pending approval as issued. The input is the third source sentence stating submitted, pending approval; the comparison is the draft sentence implying the licence already meets conditions; the observable result is that pending approval does not constitute completed issuance.
3. Omitting the creator in a full-overwrite collaborator list. The input is the collaborator list submitted at handover; the comparison is whether the current creator appears in that list; the observable result is that submission is rejected when the list lacks the creator.

## How to verify the setup

1. Input the three source sentences and the draft sentence. Compare the modification authorization described in the draft sentence against the viewing scope given in the source text. The observable result is that the draft sentence's modification authorization is unsupported by the source text and remains to be verified.
2. Input the role configuration record for customs role B. Compare that role against the file operation requirement. The observable result is that when the role does not reach admin, the configure-collaborators entry is not displayed; this is the expected behavior and no actual test is claimed.
3. Input a retrieval query against this shipment's folder. Compare the returned files against the readable scope for customs role B. The observable result is that files outside that scope do not appear. An empty result can be checked against a paper input of an empty list for downstream design; no claim is made that a fictional rule necessarily returns empty.

Two further distinctions belong here. Same-model retrieval association, empty-reference output, and context limits retain their documented conditions; a cross-model association cannot be formed, so the check is to verify identifiers and exclude non-matching items rather than to run a cross-model retrieval and compare missed recall. The optional paths in the overall document flow are not executed on every request: image retrieval requires a corresponding image input and model capability, and reranking requires a model and must be enabled by setting.
