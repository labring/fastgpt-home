# Store price and display checks: workflow routing for operations handover

## What the documents look like

Price and display auditing for chain stores happens during ordinary trading periods, so the material accumulates on a weekly and monthly cycle. Supervision systems produce store-visit photographs. POS price sheets record shelf-edge labels and settlement prices. Store cameras supply display images. Head-office promotion calendars define the execution window. Operations departments, regional supervisors and store managers pass store-visit photographs, price label lists, display standards and rectification notices between one another during permission and handover work. Each item carries a subject, an object, a stage and a validity range. Workflow routing has to hand information collected by interaction nodes to later nodes accurately, and it has to record authorization status and execution status as separate facts.

Three features of this category shape the routing step. The first is that the material spans several holders: a price label list may be checked by a store manager while a rectification notice still sits with a regional manager. The second is that the audit concerns continuing execution of a standard, so a document being present does not mean the standard was applied. The third is that the documents are dated and scoped, which means a promotion window and a label-check status belong to a particular store and period. The update frequency itself does not change the routing behaviour described here.

## Constraints at the workflow routing step

The Form Input node is a user interaction node. When it triggers, the conversation enters an interaction state, the workflow state is recorded, and execution continues after the user completes the interaction. Once the user fills the required information and submits, the node collects the submitted form information and passes it to later nodes. The User Selection node is also a user interaction node with the same interaction behaviour. When the user makes a choice, the node evaluates that choice and executes the "yes" branch. Both nodes record workflow state and wait for the user to complete the interaction before continuing.

In operations permission and handover work, retrieval or form collection does not constitute authorized execution. Submission of a rectification notice, confirmation of a price label list and archiving of store-visit photographs are different authorization states. Workflow routing only carries inputs and branches. Business writes and external synchronization require a separate interface or a later process.

Hypothetical paper exercise sample. A chain brand operations department, during a June 2025 promotion window, receives a handover request submitted by a regional supervisor. The source text reads: "Store A executes the promotion price from 10 June 2025 to 20 June 2025; the price label list has been checked by the store manager; the rectification notice awaits approval by the regional manager." The sentence proposed for judgement reads: "The promotion price for Store A is in effect and the handover is complete." The request contains subjects (Store A, the regional supervisor, the store manager, the regional manager), objects (the promotion price, the price label list, the rectification notice), states (checked, awaiting approval) and a validity range (10 June 2025 to 20 June 2025). Awaiting approval does not equal approval granted, and the handover completion claim lacks support.

## Configuration and implementation checks

| Configuration item | Relevant setting or check on this page | Correspondence with the sample |
| --- | --- | --- |
| Form Input node | Enters interaction state on trigger, collects required information, passes it to later nodes after submission | Collects store identifier, promotion period and label-check status |
| User Selection node | Executes the "yes" branch after the user makes a choice | Branches correspond to "submit for approval" and "return for completion" |
| Interaction state check | Recording state is behaviour of the interaction nodes | Checks whether the sample request is waiting for approval |
| Output handover check | Passes collected information explicitly to later retrieval, judgement or interface nodes | Compares the fields passed for the price label list and the rectification notice |
| External operation split | Order writes, document backfill and external status synchronization require a separate business interface | Promotion price effect and handover completion require business system confirmation |
| Hypothetical trial starting point | This exercise sets the approval waiting period starting point at 24 hours, chosen so it can be compared against a manual checking cycle, with the regional manager's actual response time as the comparison object | Used for paper checking only; not an official default value |

## Three common errors

1. Treating a rectification notice awaiting approval as approved. The sample source text states "awaits approval by the regional manager" while the proposed judgement sentence says "the handover is complete." The input and the judgement lack evidence of approval being granted.
2. Treating the store identifier and promotion period collected by the form as the promotion price being in effect. The Form Input node only collects and passes information. Price effect requires business system confirmation, and the two are not the same fact.
3. Treating the "yes" branch of the User Selection node as authorized execution. The branch only determines the direction of the process. It does not change the check status of the price label list and does not replace the regional manager's approval action.

## How to verify the setup

1. Input the sample source text and the proposed judgement sentence, then compare whether "awaiting approval" and "handover complete" refer to the same subject, the same period and the same field. If the approval status field still reads awaiting approval, the proposed judgement sentence is unsupported and should be recorded as pending verification.
2. Input the price label list field and the promotion period from the sample, then compare whether the Form Input node output passes the store identifier, the period and the check status in full. If the output lacks any required field, the downstream judgement node cannot take it over, and the gap should be recorded.
3. Input the rectification notice status from the sample, then compare whether the "yes" branch of the User Selection node has been misread as approval granted. If the approval status field is unchanged after branch execution, both the promotion price being in effect and the handover being complete remain unknown and require confirmation from the regional manager's approval record.
