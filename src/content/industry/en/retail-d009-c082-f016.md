# Returned-goods inspections: interactive forms for operations handover

## What the documents look like

Returned-goods inspection at the warehouse handles inbound reverse parcels and assigns a condition grade to each item. It does not process outbound picking for new orders. The working data comes from the WMS returns module, platform after-sales records, carrier return parcels, and the inspection bench. The four documents that move through a handover are the returned-goods inbound order, inspection photos, the grade determination sheet, and the resale listing order. The most time-consuming steps are scanning the return, judging the item condition, and deciding between resale and scrap. These materials update per item and per day, so the same inbound order may already carry a different status by the time a handover is reviewed. Both sides of a handover compare the current field values rather than relying on an earlier copy.

In FastGPT v4.17.2, the Form Input node is a user-interaction node. When it triggers, the conversation enters an interactive state, the workflow state is recorded, and execution continues after the user completes the interaction. The node collects the values the user fills in and passes them to later nodes. The User Selection node is also a user-interaction node with the same trigger, state-recording, and continuation behavior; it evaluates the user's choice and runs the corresponding branch. Neither node performs business verification, approval, database writes, or external synchronization on its own.

## Constraints at the interactive forms step

Interactive nodes collect values and route branches. Field validation, business approval, write-back, and batch operations require implementation in an external system or in later nodes. A completed form submission does not constitute an inspection conclusion. A user selection does not constitute authorization. Whether a handover request is supported depends on the current status of the returned-goods inbound order, the object each inspection photo corresponds to, the determination period on the grade determination sheet, and the authorization boundary of the resale listing order.

Hypothetical paper exercise sample. The handover material text reads: "Returned-goods inbound order RMA-0417, item A, status: under inspection; grade determination sheet JD-0417, determination period 2025-04-17, conclusion: pending review; resale listing order RS-0417, status: unsigned." The draft sentence awaiting judgment reads: "RMA-0417 has completed inspection and is approved for resale, and listing may proceed." The comparison objects are the inbound order status, the determination sheet conclusion, and the listing order signature status for the same RMA-0417.

The sample is a paper construction for this page. It records no actual inspection, approval, signature, listing, refund, or system action. A pending request is not an approval. An offered option is not execution. An unsigned termination is not a completed termination.

## Three common errors

1. Treating a form submission as a completed inspection. The Form Input node collects values and passes them to later nodes; it produces no inspection conclusion. Check: use the sample status "under inspection" for RMA-0417, compare it with the draft wording "has completed inspection," and observe whether the two agree.

2. Treating a user selection as authorized execution. The User Selection node runs a branch based on the choice; it does not constitute approval. Check: use the sample listing order status "unsigned" for RS-0417, compare it with the draft wording "approved for resale," and observe whether any signature or authorization evidence appears.

3. Treating a pending-review conclusion as a final determination. The grade determination sheet conclusion "pending review" is an unfinished state. Check: use the sample conclusion "pending review" for JD-0417, compare it with the draft wording "has completed inspection," and observe whether the conclusion field supports that statement.

## How to verify the setup

1. Input the sample text "RMA-0417, status: under inspection." Compare it with the draft sentence "has completed inspection and is approved for resale." Observe whether the inbound order status field agrees with "completed." If the status remains under inspection, the draft sentence is not supported by the sample.

2. Input the sample text "RS-0417, status: unsigned." Compare it with the draft sentence "listing may proceed." Observe whether the listing order carries a signature or authorization record. An unsigned status does not support proceeding with listing.

3. Input the sample text "JD-0417, conclusion: pending review." Compare it with the draft sentence "has completed inspection." Observe whether the determination sheet conclusion is a final determination. Pending review is an unfinished state and is recorded as pending verification.
