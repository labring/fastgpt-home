# CDMO临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样

CDMO（合同研发生产组织）在临床试验预筛环节的数据主要来自内部LIMS（实验室信息管理系统）、EDC（电子数据采集系统）以及合作方提供的临床前研究报告、毒理学数据和药代动力学（PK/PD）数据。数据更新频率较高，尤其在临床前研究阶段可能每周甚至每天都有新数据生成。文档结构复杂，包含非结构化文本（如研究报告、方案变更记录、伦理审批文件）和结构化数据（如受试者基线信息、实验室检测结果、不良事件报告）。结构化数据字段繁多，涉及生物标志物浓度（单位通常为 ng/mL 或 µg/mL）、基因表达量（单位为 FPKM 或 TPM）、细胞活力百分比等，单位特异性强，且常伴有批次号、实验条件等元数据。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

CDMO临床试验预筛的数据特征对HTTP接口与外部系统集成提出了明确要求。高频数据更新需要接口支持实时或近实时的数据同步机制，例如基于Webhook的回调或短间隔的轮询。复杂的文档结构意味着接口需能处理多种数据类型，包括JSON、XML以及PDF、DOCX等非结构化文件，这对文件解析能力和数据抽取准确性构成挑战。字段与单位的特异性要求接口在数据传输和接收时能进行严格的校验，避免因单位不匹配或字段缺失导致的数据错误。此外，多系统集成涉及不同系统间的身份认证和授权机制，确保数据传输的安全性与合规性。大规模数据量也对接口的并发处理能力和响应速度有较高要求。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `API_KEY` 或 `token` | 确保与外部系统一致，使用有效期较长的密钥 | 外部系统通常采用API Key或OAuth 2.0 Token进行认证，长期有效可减少频繁刷新 |
| `requestTimeout` | `60000 毫秒` | 处理复杂数据解析和传输可能耗时，避免连接过早中断 |
| `maxConnections` | `按实测标定`，例如 `10-20` | 需根据外部系统并发限制及FastGPT自身资源情况动态调整，确保稳定连接 |
| `payloadSizeLimit` | `50 MB` | 考虑传输大型研究报告或多份结构化数据时的最大负载 |
| `retryAttempts` | `3 次` | 应对网络波动或外部系统临时故障，提高数据传输成功率 |
| `pollingInterval` | `300 秒` | 针对非实时数据更新，平衡数据新鲜度与外部系统负载 |

## 容易做错的三处

*   连接外部系统时提示“令牌无效”或“Unauthorized”。原因是没有正确配置或刷新API密钥，外部系统通常对令牌的格式、有效期或权限有严格要求。
*   数据导入后部分字段为空或单位不匹配。原因是没有在接口配置中明确指定数据映射规则，导致外部系统返回的数据字段无法正确对应到内部结构。
*   大量数据同步时出现超时错误。原因是没有合理设置`requestTimeout`参数，或外部系统响应速度慢于预期，导致连接在数据传输完成前中断。

## 怎么确认配好了

*   通过FastGPT的调试日志查看HTTP请求和响应状态码，确保返回 `200 OK` 或其他成功代码。
*   对导入的数据进行抽样检查，核对关键字段（如受试者ID、生物标志物浓度、单位）是否与外部系统数据源一致。
*   模拟高并发请求，观察接口响应时间是否在可接受范围内，并检查系统资源使用情况。
*   配置定时任务，监测数据同步的成功率和完整性，确保数据能按预期频率和质量更新。
