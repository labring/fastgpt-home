# CMC 研究临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样

CMC 研究的数据主要来源于药物研发过程中的实验室报告、生产批次记录、质量控制文档以及注册申报资料。这些数据以非结构化文档为主，例如 PDF 格式的分析方法验证报告、稳定性研究报告、生产工艺流程图、杂质谱分析报告等。数据更新频率通常随研发阶段推进而变化，早期研发阶段可能较为频繁，临床试验阶段则趋于稳定。文档内部结构复杂，包含大量表格、图谱和专业术语，例如批次号、检测项目、检测结果、单位（如 `ppm`、`ng/mL`、`%`）、分析仪器型号和检测方法编号。字段命名可能不统一，存在缩写和别名。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

CMC 研究数据以非结构化文档为主，这要求外部系统具备强大的文档解析能力，能够从 PDF、Word 等格式中准确提取关键信息。文档内部的复杂结构，特别是表格和图谱，使得常规的文本提取方法不足以满足需求，需要更专业的结构化信息抽取技术。字段命名不统一和专业术语的存在，对接口返回的数据字段映射和语义理解提出挑战，需要定义清晰的映射规则或采用语义匹配。数据更新的阶段性特征，决定了外部系统在不同研发阶段对数据同步频率的需求不同，需要灵活配置定时任务或事件触发机制。同时，单位的一致性校验和转换是确保数据准确性的关键，接口设计时需考虑单位信息的传递和处理。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `external_api_url` | `https://api.example.com/cmc/data` | 指向用于获取 CMC 数据的外部系统 API 端点，确保协议为 HTTPS |
| `request_timeout_seconds` | `600 秒` | CMC 报告数据量通常较大，需要较长的响应时间以完成数据传输和初步处理 |
| `headers` | `{"Authorization": "Bearer YOUR_TOKEN", "Content-Type": "application/json"}` | 认证信息和请求体类型是访问外部 API 的基本要求，确保安全性和数据格式正确 |
| `response_parsing_template` | 按实测标定 | 针对不同 CMC 报告结构，提取 `批次号`、`检测项目`、`检测结果` 等字段，需要定制化 JSONPath 或正则表达式 |
| `error_retry_count` | `3 次` | 考虑到网络波动或外部系统临时故障，适当的重试机制可以提高数据获取的成功率 |
| `data_update_frequency_cron` | `0 0 * * *` | 每天凌晨执行一次数据同步，满足 CMC 报告阶段性更新的需求 |

## 容易做错的三处

*   HTTP 请求返回 `500 Internal Server Error` 状态码，或者接口调用超时。这通常是由于外部系统处理复杂 CMC 报告的请求负载过大，或者 `request_timeout_seconds` 配置过短导致。
*   接口返回的 JSON 数据中，关键字段如 `检测结果` 为空或数据格式不正确。这往往是因为 `response_parsing_template` 未能准确匹配到外部系统返回的实际字段路径，或者未正确处理单位转换。
*   数据同步后，发现部分 CMC 报告中的表格数据未能被正确提取，例如 `杂质谱` 数据缺失。这表明外部系统对复杂表格结构的解析能力不足，或者 `response_parsing_template` 仅针对纯文本内容进行匹配。

## 怎么确认配好了

*   通过 FastGPT 的 HTTP 请求组件发起一次测试调用，检查返回的 HTTP 状态码是否为 `200`，确认接口连通性。
*   检查测试调用的响应体，确认 `response_parsing_template` 配置的字段（如 `批次号`、`检测项目`、`检测结果`）能够从返回数据中正确提取，并核对其值和单位是否符合预期。
*   模拟不同类型的 CMC 报告数据（例如包含复杂表格、图谱的 PDF 文件），通过外部系统接口获取并观察 FastGPT 中的数据摄入结果，确保关键信息被完整、准确地抽取。
*   在配置的 `data_update_frequency_cron` 时间点后，检查 FastGPT 中的知识库数据是否按预期进行了更新，确认定时同步机制生效。
