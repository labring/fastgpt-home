# 代谢与内分泌临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样
代谢与内分泌疾病，如糖尿病、甲状腺功能异常等，其临床试验预筛数据通常来源于电子病历系统（EHR）、实验室信息管理系统（LIMS）以及患者报告结局（PRO）数据。这些数据更新频率较高，特别是血糖、激素水平等关键指标，可能以小时甚至分钟为单位更新。文档结构以半结构化或非结构化为主，例如临床医生的诊疗记录、影像报告文本、基因检测报告。字段方面，除了常规的人口统计学信息外，还包含大量专有指标，如糖化血红蛋白（HbA1c）、空腹血糖（FPG）、C肽、甲状腺素（T4）、促甲状腺激素（TSH）等，单位严格且多样，如 mmol/L、mg/dL、IU/L、μg/dL等，单位的正确解析对后续判断至关重要。此外，病程进展、并发症记录等文本信息也构成重要数据源。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
代谢与内分泌数据的高更新频率要求HTTP接口设计上支持实时或近实时的数据拉取与同步机制，例如采用Webhook或轮询策略，以确保预筛结果的及时性。半结构化和非结构化文档的存在，对接口的数据解析能力提出挑战，需要支持多种数据格式（如JSON、XML，甚至纯文本），并能有效从中提取关键信息。字段的专有性和单位的严格性，意味着外部系统在接收数据后，需要有完善的数据校验和标准化流程，避免因单位混淆或字段缺失导致预筛错误。例如，血糖值若未注明单位，可能导致误判。同时，由于数据源的多样性，接口需要具备从不同EHR、LIMS系统集成数据的能力，可能涉及不同的认证方式（如OAuth 2.0、API Key）和数据传输协议。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `externalApiUrl` | 实际数据源的API地址 | 确保数据来源准确，指向EHR或LIMS系统 |
| `requestMethod` | `POST` 或 `GET` | 依据外部系统API文档确定 |
| `headers` | 包含 `Authorization: Bearer <token>` | 满足外部系统认证要求，确保数据安全 |
| `pollingIntervalSeconds` | `300` 秒 | 兼顾数据实时性与系统负载，代谢指标更新较快 |
| `responseTimeoutMilliseconds` | `10000` 毫秒 | 考虑到复杂查询和大数据量传输，防止请求超时 |
| `jsonPathExtract` | `$.patient.lab_results[*].hba1c.value` | 精确提取特定代谢指标，如糖化血红蛋白值 |

## 容易做错的三处
*   现象：API接口返回 401 Unauthorized 错误码。原因：外部系统认证凭证 `Authorization` 头中的 `token` 失效或配置不正确。
*   现象：HTTP 请求节点成功返回数据，但后续工作流节点无法正确解析出关键字段值，显示为空或格式错误。原因：`jsonPathExtract` 配置路径不准确，未能匹配到代谢与内分泌数据中实际的字段结构，例如 `hba1c` 可能被嵌套在不同的层级下。
*   现象：在 FastGPT 调试页面可以正常获取知识库内容，但通过 API 方式调用时部分问题未能召回知识。原因：API 调用时 `maxContext` 或 `recallTopK` 等参数设置过小，导致传递给知识库的上下文信息不足或召回条目过少，无法触发相关代谢疾病知识。

## 怎么确认配好了
*   对配置的HTTP接口发起测试请求，检查返回的 `HTTP Status Code` 是否为 200，并确认返回的 JSON 结构中包含预期的代谢与内分泌相关字段，如 `glucose_level` 或 `thyroid_hormone_values`。
*   使用 FastGPT 的“测试与调试”功能，模拟实际查询，验证工作流中通过HTTP接口获取的数据能够被正确解析，并被知识库有效利用，例如输入一个血糖值，看是否能触发与糖尿病相关的知识条目。
*   定期检查外部系统日志或 FastGPT 的系统日志，确认数据同步任务按预期频率执行，没有出现连接失败、数据解析错误或超时等异常记录，特别是针对 `pollingIntervalSeconds` 设定的时间窗。
