# 供应商审计临床试验预筛的工具调用与插件

## 这个品类的数据长什么样

供应商审计的数据主要来源于审计报告、资质文件、历史合作记录以及第三方评估报告。这些数据更新频率不一，资质文件可能每年更新，审计报告则按项目或周期生成，历史记录持续累积。文档结构通常包含标准化的章节，如审计范围、发现项、纠正预防措施 (CAPA) 等，但也存在大量非结构化文本。字段方面，常见的包括供应商名称、审计日期、审计员、发现问题描述、严重等级、CAPA 状态、完成日期。单位则涉及日期、文本描述、枚举状态码等。

## 这些特征在「工具调用与插件」这一环带来什么约束

供应商审计数据的异构性与半结构化特点，要求工具调用与插件具备强大的文本解析能力。例如，从审计报告中提取关键发现项和 CAPA 详情，需要精确识别文本中的实体与关系。由于数据更新频率差异，工具在进行供应商评估时，需要能够按需调用最新数据源，例如通过 API 获取实时资质状态。字段的枚举状态码和日期格式多样性，对插件的数据校验和标准化处理提出了要求。此外，审计过程中的复杂逻辑判断，如根据发现项严重等级自动触发特定流程，需要工具调用能够编排多步骤操作，并处理中间状态。

## 配置怎么定

| 配置项             | 建议取法                                            | 这样取的依据                                                 |
| :----------------- | :-------------------------------------------------- | :----------------------------------------------------------- |
| `maxContext`       | `16000 tokens`                                      | 审计报告和资质文件通常包含大量文本，需要足够大的上下文窗口处理。 |
| `toolCallTimeout`  | `600 秒`                                            | 外部 API 调用（如获取第三方评估）可能耗时较长，避免因超时中断。 |
| `maxTokens`        | `4000 tokens`                                       | 确保工具返回的详细审计结果或 CAPA 描述能够完整呈现。         |
| `pluginRetryCount` | `3 次`                                              | 外部服务偶发性故障，重试机制可提高成功率。                   |
| `jsonParseMode`    | `Strict`                                            | 确保从外部系统获取的结构化数据（如供应商资质）严格符合预期格式。 |

## 容易做错的三处

*   工具调用返回 `HTTP 401 Unauthorized` 错误：原因在于 `Authorization` 头中的 API Key 配置不正确或已过期。
*   工作流执行后，知识库搜索结果中出现大量无关信息：原因可能是 `相似度阈值` 设置过低，导致召回了与供应商审计不直接相关的文档。
*   插件执行成功但返回结果的某个关键字段为空：原因在于插件在解析外部系统响应时，路径表达式 (`JSONPath` 或 `XPath`) 未能准确匹配目标数据。

## 怎么确认配好了

*   通过 FastGPT 的调试界面，观察工具调用日志，确认每个外部 API 请求的状态码均为 `200 OK`。
*   创建一个模拟供应商审计场景的对话，检查模型回复中是否准确引用了来自工具调用的具体数据点，例如供应商的最新资质更新日期。
*   针对包含复杂条件判断的审计逻辑，设计多组测试用例，验证工具调用在不同输入下能否触发正确的后续操作。
