# 冷链物流临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样
冷链物流在临床试验预筛环节的数据，主要围绕药品、生物样本的温湿度、光照、震动等环境参数，以及运输路径、存储节点、到货时间等物流信息。数据来源包括传感器设备实时回传、物流平台API接口、人工录入的批次信息等。更新节奏受物流环节影响，从秒级（传感器数据）到天级（批次到货确认）不等。文档结构通常包含时间戳 `timestamp`、设备ID `deviceId`、环境参数 `environmentalParameters`（如 `temperature`、`humidity`）、地理位置 `geoLocation`、事件类型 `eventType` 等字段，常以 JSON 或 CSV 格式传输。温度单位通常为摄氏度 `°C`，湿度为百分比 `%RH`。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
冷链物流数据的多源性和实时性对HTTP接口的并发处理能力提出要求。传感器数据的秒级更新需要接口具备高吞吐量，以避免数据积压和延迟。物流信息的结构化特点，要求接口能灵活接收不同格式的数据负载，并在内部进行统一解析。同时，对历史数据的追溯和查询需求，使得知识库的存储结构需支持高效的时间序列数据检索。此外，由于涉及药品安全，数据传输的可靠性和完整性至关重要，异常情况下的重试机制和错误通知成为接口设计的关键考量。不同批次或样本的唯一标识 `batchId` 或 `sampleId` 必须在每次数据交互中明确传递。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `HTTP_REQUEST_TIMEOUT` | `60000 毫秒` | 考虑传感器数据回传可能因网络波动延迟，预留足够响应时间。 |
| `MAX_CONCURRENT_REQUESTS` | `100` | 平衡高频传感器数据与批量物流信息上传，避免瞬时过载。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 处理大型物流批次或传感器历史数据文件时，确保解析完成。 |
| `分段长度` | `800 字符` | 适应不同传感器数据记录与物流事件描述，保持语义完整。 |
| `相似度阈值` | `0.75` | 识别相似的异常事件模式，例如温度超标的多次出现。 |
| `REQUEST_BODY_MAX_SIZE_MB` | `50 MB` | 允许上传包含多个传感器数据点或批量物流记录的请求体。 |

## 容易做错的三处
*   接口调用返回 `400 Bad Request` 且响应体提示 `Invalid JSON format`。原因通常是上送的冷链环境参数或物流事件的 JSON 结构不符合预设的 `schema`，例如缺少必需的 `timestamp` 字段或 `temperature` 字段类型不正确。
*   知识库中部分冷链数据缺失或更新不及时。原因可能是外部系统在网络不稳时未实现有效的重试机制，导致数据包丢失，或 `HTTP_REQUEST_TIMEOUT` 设置过短，请求未完成即被中断。
*   通过接口查询特定 `batchId` 的历史温湿度数据时，结果条数明显少于预期。原因可能是在数据入库时，用于关联的 `batchId` 字段未能正确解析或映射，导致查询时无法匹配全部相关数据。

## 怎么确认配好了
*   模拟不同频率（例如每秒一次、每分钟一次）的传感器数据上报，检查接口响应时间和数据入库的完整性，确保无数据丢失且响应在可接受范围内。
*   使用包含不同结构和字段的模拟物流批次数据，通过接口上传，验证知识库中各字段的正确解析和存储，特别是 `temperature`、`humidity` 等关键参数的单位和数值范围。
*   配置一个异常情况（如网络中断或发送无效数据），观察外部系统是否触发预设的重试逻辑，并在重试失败后是否有相应的错误通知或日志记录。
