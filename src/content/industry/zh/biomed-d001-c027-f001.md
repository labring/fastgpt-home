# 减毒灭活疫苗临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样
减毒灭活疫苗的临床试验数据，主要来源于临床研究机构的电子数据采集（EDC）系统、中心实验室系统（CLS）和药代动力学/药效学（PK/PD）分析平台。这些数据通常以结构化表格形式存在，如CSV、JSONL或XML。数据更新频率在临床试验的不同阶段有所差异：早期安全性数据可能每日更新，而后期有效性数据则通常以周或月为周期进行汇总更新。文档结构严谨，遵循ICH GCP和CDISC SDTM/ADaM标准，包含受试者基本信息、生命体征、实验室检查结果、不良事件、合并用药等字段。数值型数据常带有明确的计量单位，如 `mg/dL`、`IU/mL`、`mmHg`。文本型数据则包括医学术语、诊断描述和研究者评估。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
减毒灭活疫苗临床试验数据的来源多样性，要求 HTTP 接口具备多源数据集成能力，能同时对接 EDC、CLS 等不同系统。数据更新频率的差异，决定了外部系统调用接口时需要灵活配置轮询间隔，例如安全性数据可能需要更高的调用频率。严谨的文档结构和标准化字段，意味着接口需要精确的数据映射和转换逻辑，以确保数据一致性，避免因单位不匹配（如 `mmol/L` 与 `mg/dL` 混淆）导致的数据解析错误。大量的数值型和文本型数据，对接口的吞吐量和数据处理能力提出要求，特别是在处理大规模受试者队列时，需要考虑分批处理机制。此外，数据敏感性要求接口必须具备严格的身份验证和授权机制，例如使用 OAuth2.0 或 API Key。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `external_api_url` | 临床试验EDC系统提供的 `/api/v1/clinical_data` | 确保数据源的权威性和实时性 |
| `http_method` | `POST` | 多数临床数据同步接口采用 POST 方法传输结构化数据 |
| `request_timeout_seconds` | `60 秒` | 考虑到大数据量传输和外部系统处理时间，避免过早超时 |
| `auth_header_name` | `Authorization` | 通用的认证头字段，与大多数外部系统兼容 |
| `data_polling_interval_minutes` | `1440 分钟` | 针对减毒灭活疫苗临床试验后期有效性数据，每天轮询一次 |
| `batch_size_records` | `1000 条` | 平衡单次请求的数据量和接口处理效率，避免过大的负载 |

## 容易做错的三处
* 现象：外部系统返回 `HTTP 401 Unauthorized` 错误。原因：`Authorization` 请求头中携带的 API Key 或 Bearer Token 已过期或不正确。
* 现象：从外部接口获取的数据中，某些关键字段（如 `adverse_event_severity`）为空。原因：接口返回的数据结构与预期不符，或数据映射配置错误，导致特定字段未能正确解析。
* 现象：处理文件解读时，外部系统收到两次请求，第二次请求的 `Authorization` 头不正确。原因：FastGPT 内部机制在某些文件处理场景下会进行重试，但重试逻辑未正确复用初始请求的认证信息。

## 怎么确认配好了
* 模拟一次完整的数据请求，检查 `HTTP 200 OK` 状态码，并验证返回数据结构和内容是否符合预期。
* 检查日志中是否有认证失败或数据解析错误的记录，确认 `request_timeout_seconds` 配置是否生效。
* 选取数条样本数据，人工比对外部系统原始数据与FastGPT内部存储数据，核对关键字段的准确性，特别是数值型字段的单位一致性。
