# 医保准入临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样
医保准入相关的临床试验数据，主要涉及国家医保目录、各省市增补目录、药品带量采购结果、以及相关政策法规文件。这些数据通常来源于国家及地方医保局、药品集中采购平台、药监局等官方渠道，以PDF、Excel、Word或结构化数据库的形式发布。更新频率受政策发布周期影响，通常为季度或年度更新，部分目录调整可能为不定期更新。文档结构复杂，包含药品通用名、剂型、规格、医保支付标准、适应症、报销限制条件、以及对应的临床试验批文号等字段。单位涉及毫克（mg）、毫升（ml）、国际单位（IU）等，且支付标准常以元（RMB）为单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
医保准入数据的多源异构性要求HTTP接口设计具备高度的兼容性和解析能力，以适应PDF和Excel等非结构化数据源。其政策驱动的更新频率意味着外部系统需要支持周期性或事件驱动的数据抓取机制，并能处理版本迭代带来的数据结构变化。报销限制条件中的文本描述，如“限二线用药”或“需经专家会诊”，需要接口能够传输并由后端AI模型进行语义理解。此外，不同省份医保政策的差异性，要求接口支持区域参数，以确保预筛结果的准确性。数据字段的复杂性和单位的多样性，对数据清洗和标准化提出了较高要求，需要外部接口在数据传输前完成预处理，或在接收后进行规范化转换。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `requestTimeout` | `600 秒` | 应对医保政策文档解析耗时，避免因响应慢而中断 |
| `maxConnections` | `10` | 平衡数据抓取效率与目标系统负载，防止过载 |
| `contentType` | `application/json` | 确保结构化数据传输效率与兼容性，方便后续处理 |
| `headers.Authorization` | `Bearer <API_KEY>` | API认证，保障数据接口访问的安全性 |
| `body.provinceCode` | `按实际需求传入` | 医保政策的地域性差异，确保预筛结果的地域准确性 |
| `retryAttempts` | `3 次` | 应对网络波动或外部系统临时故障，提高数据获取成功率 |

## 容易做错的三处
*   HTTP 请求返回状态码为 500 或 502，但日志中未见明确错误信息，这通常是由于外部系统处理复杂查询或大数据量时发生内部错误或网关超时。
*   从外部接口获取的医保支付标准字段为空或数据格式不正确，原因在于部分医保目录文件数据抽取时未正确识别或转换金额单位。
*   预筛结果中部分药品的报销限制条件未能准确识别，现象是文本描述被截断或理解偏差，这往往是接口传输的文本长度限制或AI模型未针对特定政策术语进行优化。

## 怎么确认配好了
*   对医保目录中具有典型复杂报销限制条件的药品进行预筛，核对接口返回的限制条件文本是否完整且无乱码。
*   随机抽取不同省份的医保政策数据，通过接口获取并比对关键字段，确认 `body.provinceCode` 参数是否正确生效，且返回数据与源文件一致。
*   模拟高并发请求，观察 `requestTimeout` 设置下，接口是否能稳定返回数据，并检查日志中是否存在超时错误。
