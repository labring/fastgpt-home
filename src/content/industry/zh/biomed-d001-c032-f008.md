# 医保结算临床试验预筛的工具调用与插件

## 这个品类的数据长什么样

医保结算数据主要来源于各级医保局、医疗机构以及第三方支付平台，通常以结构化数据库或半结构化文件的形式存在。其更新频率因地域和政策差异较大，部分地区可实现 T+1 级别更新，另一些则可能按月或季度批量更新。数据文档结构复杂，包含患者基本信息、诊断代码 ICD-10、治疗方案 CPT/HCPCS 代码、药品通用名、费用明细、支付类型、报销比例、结算状态等多个核心字段。字段单位多样，如金额以“元”为单位，数量以“次”、“盒”等计，时间戳精确到“秒”。数据中常伴随大量的编码值，需对照官方字典进行解析。

## 这些特征在「工具调用与插件」这一环带来什么约束

医保结算数据的复杂性和多样性，对工具调用与插件提出了严格要求。首先，数据源分散且更新频率不一，要求插件具备多源数据集成与异步处理能力，以确保预筛结果的时效性。其次，大量的编码值和非标准字段，使得数据预处理成为关键环节，插件需能调用外部服务进行编码转换和数据清洗。医保数据的高敏感性，对工具的数据安全和合规性有强制性要求，限制了部分云服务的使用。此外，结算状态、报销比例等动态字段的实时查询需求，要求插件在工具调用时能精确传递复杂查询参数，并处理可能出现的多种响应状态，例如 `HTTP 403` 或 `HTTP 404` 错误码。

## 配置怎么定

| 配置项                 | 建议取法                               | 这样取的依据                                                                                             |
| :--------------------- | :------------------------------------- | :------------------------------------------------------------------------------------------------------- |
| `toolCallTimeout`      | `600 秒`                               | 医保数据查询链路长，涉及多系统联调，需预留足够响应时间，避免因超时而中断。                               |
| `maxContext`           | `2000 字符`                            | 医保规则和患者信息描述可能较长，确保上下文完整传递。                                                     |
| `pluginRetryCount`     | `3`                                    | 外部服务偶发性网络抖动或瞬时负载高，重试可提高成功率。                                                   |
| `authHeaderName`       | `X-Auth-Token`                         | 医保数据接口通常采用 Token 认证，此为常见且安全的头部字段名。                                            |
| `responseSchema`       | 按实际接口返回的 JSON Schema 定义      | 精确解析医保结算明细、报销状态等关键字段，确保数据结构化提取。                                           |
| `dynamicParamMapping`  | `patientId -> 医保系统病人ID`          | 将 FastGPT 内部的患者标识映射为医保系统可识别的参数名，例如 `patientIdentifier`。                       |

## 容易做错的三处

*   工具调用返回 `HTTP 500` 或空响应体，现象是预筛结果缺失或报错 `Internal Server Error`。这往往是由于医保接口的输入参数格式不符或必填字段 `policyNumber` 缺失导致的。
*   插件激活后，临床试验预筛结果显示报销比例错误或费用计算不准确。原因在于医保数据中的编码未正确转换为可理解的文本，例如 ICD-10 编码未映射到具体的诊断名称，导致模型理解偏差。
*   长时间等待后，工具调用最终返回 `Timeout` 错误，但医保系统日志显示请求未到达。这可能是因为网络代理 `http_proxy` 配置不当或防火墙规则阻止了出站请求。

## 怎么确认配好了

*   通过 FastGPT 的工具调试界面，模拟调用医保结算查询插件，检查返回的 `HTTP Status Code` 是否为 `200`，并确认响应体包含预期字段，如 `totalAmount` 和 `reimbursementStatus`。
*   选择一个已知报销结果的患者案例，在系统中输入其信息，观察预筛结果中的报销比例和结算金额是否与实际情况或测试数据一致。
*   检查 FastGPT 运行日志中是否有工具调用相关的错误信息，特别是关于参数解析、API 认证或网络连接的警告或错误。
*   验证插件配置中所有 `dynamicParamMapping` 的源字段和目标字段，确保其在 FastGPT 内部数据结构与医保接口要求之间建立正确的一对一映射。
