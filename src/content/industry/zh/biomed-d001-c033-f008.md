# 医学事务临床试验预筛的工具调用与插件

## 这个品类的数据长什么样

生物医药领域的医学事务在临床试验预筛环节，其数据主要来源于公开的临床试验注册库（如 ClinicalTrials.gov、WHO ICTRP）、药企内部的临床研究数据库、以及医学文献平台。这些数据更新频率较高，ClinicalTrials.gov 上的记录可能每周更新，而药企内部数据则随项目进展实时变动。文档结构多样，包括结构化的试验方案摘要、非结构化的研究者手册（Investigator's Brochure, IB）、病例报告表（Case Report Form, CRF）以及医学文献的 PDF 格式。字段涵盖疾病适应症、药物名称、剂量、给药途径、入排标准、主要/次要终点、研究中心地理位置等。剂量通常带有 `mg`、`μg`、`ml` 等单位，时间周期则使用 `周`、`月`、`年`。

## 这些特征在「工具调用与插件」这一环带来什么约束

高频的数据更新要求工具调用具备实时或近实时的查询能力，以确保预筛基于最新信息。多样化的文档结构意味着需要支持多种数据源的解析，特别是对非结构化 PDF 文档的内容提取，这涉及到 OCR 与自然语言处理的结合。复杂的入排标准通常包含多个逻辑判断和数值范围，需要工具调用能够精确匹配或计算，例如判断患者年龄是否在 `18-65 岁` 之间，或某种生物标志物水平是否高于 `10 ng/mL`。地理位置信息则可能需要与地图服务插件结合，进行研究中心的可达性分析。字段单位的一致性处理至关重要，避免因单位不匹配导致的数据误判，例如将 `mg` 误读为 `g`。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `tool_timeout_seconds` | `60 秒` | 处理复杂查询和外部 API 调用可能耗时，避免过早超时中断。 |
| `max_tokens_per_response` | `1500 tokens` | 确保能够完整返回医学文献摘要或入排标准的详细描述。 |
| `function_call_strictness` | `高` | 临床试验预筛对参数精度要求高，严格模式减少误调用。 |
| `external_api_retry_attempts` | `3 次` | 应对外部临床数据库或文献平台偶尔出现的瞬时网络波动。 |
| `parse_pdf_timeout_seconds` | `180 秒` | 处理大型研究者手册 PDF 文件解析，预留充足时间。 |
| `context_window_size` | `4096 tokens` | 容纳足够多的入排标准描述和患者信息，进行综合判断。 |

## 容易做错的三处

*   工具调用返回 `400` 错误或 `InvalidParameter`：原因常是模型生成的参数格式或值不符合外部 API 的预期，例如日期格式错误或数值超出允许范围。
*   预筛结果出现遗漏或误判：通常是因为知识库召回的入排标准不完整，或工具调用在处理多条件逻辑时未能正确组合。
*   大模型无法正确触发工具调用：可能是因为 `function_call_strictness` 设置过低，或者模型在理解用户意图与可用工具功能之间的映射上存在偏差。

## 怎么确认配好了

*   针对典型的临床试验预筛场景，使用模拟患者数据进行端到端测试，核对输出的入排判断与预期是否一致。
*   检查工具调用日志，确认外部 API 调用参数与返回结果是否符合预期，特别是字段单位和数值范围。
*   选取包含复杂入排标准的 PDF 文档，测试其内容解析和关键信息提取的准确性，确保 `parse_pdf_timeout_seconds` 能够满足需求。
*   观察在不同查询负载下 `tool_timeout_seconds` 的表现，确保在高峰期也能稳定响应。
