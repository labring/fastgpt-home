# 医药电商临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样

医药电商平台在临床试验预筛场景中的数据，主要来源于药品或医疗器械的线上销售记录、用户健康档案（经授权）、问卷调查结果以及合作医疗机构提供的初步体征数据。这些数据更新频率较高，销售记录与用户行为数据近乎实时，健康档案与问卷结果则在用户主动更新或完成时同步。文档结构通常为结构化与半结构化数据混合。结构化数据包括产品ID、购买时间、剂量、用户ID、年龄、性别、既往病史等；半结构化数据则体现在用户提交的自由文本描述症状、用药反馈等。字段与单位具有高度标准化要求，例如药品剂量单位通常为毫克（mg）、毫升（ml），年龄单位为岁，血常规指标则有其特定的国际单位或常用单位。数据中常包含大量医学术语和缩写。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

医药电商数据的高更新频率要求HTTP接口具备高效的实时或准实时数据同步能力，以确保预筛结果基于最新信息。数据源的多样性（销售、健康档案、问卷）意味着外部系统需要处理多种数据格式的输入，并进行有效整合。其中，用户提交的自由文本症状描述对自然语言处理能力提出高要求，需要通过HTTP接口将文本数据发送至大语言模型进行解析，提取关键医学实体和症状。医学术语的标准化使得接口传输的数据字段必须严格遵循预设的编码或映射规则，避免歧义。例如，药品名称、疾病代码需与标准医学词典对齐。此外，患者隐私数据的敏感性决定了HTTP接口传输必须采用强加密协议，并实施严格的访问控制与审计机制，确保合规性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `4096 tokens` | 适应医学文本长度，保证上下文完整性，避免关键信息截断 |
| `分段长度` | `500 字符` | 平衡文本语义完整性与RAG召回效率，避免过长或过短分段 |
| `召回条数` | `前 8 条` | 综合考虑精确度与效率，确保相关度高的文档被检索到 |
| `相似度阈值` | `0.75` | 过滤低相关度结果，提高预筛准确性，可根据实测进一步微调 |
| `重排返回条数` | `3 条` | 筛选最相关的核心信息，减少模型处理负担，提升响应速度 |
| `HTTP Timeout` | `60 秒` | 应对外部系统数据处理复杂性，防止因网络或处理延迟导致请求中断 |

## 容易做错的三处

*   HTTP接口返回状态码514，或显示“{"code":514,"statusTex”等错误提示，原因可能是API密钥`api_key`配置不正确或已失效，导致外部系统认证失败。
*   预筛结果中部分关键医学字段（如药品剂量、疾病代码）为空或格式错误，原因通常是外部系统在处理半结构化或自由文本数据时，未进行充分的实体识别和标准化转换。
*   预筛响应时间过长，甚至出现请求超时，现象为`HTTP Timeout`错误，原因可能在于外部知识库或大语言模型处理复杂医学查询耗时过长，或网络带宽不足。

## 怎么确认配好了

*   通过模拟提交包含多种数据类型的临床试验预筛请求，验证HTTP接口返回的数据结构与预期一致，且所有关键字段均有有效值。
*   针对不同复杂度的医学描述，测试预筛结果的准确性与相关性，并与人工判断结果进行比对，验证`相似度阈值`的有效性。
*   监控接口调用日志，检查HTTP状态码是否均为200或20x，同时记录平均响应时间，确保在可接受范围内。
*   通过API文档或管理界面，核对`api_key`、`kb_id`等认证及资源标识符是否与外部系统配置完全匹配。
