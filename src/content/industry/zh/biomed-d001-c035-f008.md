# 医院运营临床试验预筛的工具调用与插件

## 这个品类的数据长什么样

医院运营在临床试验预筛环节的数据主要来源于电子病历系统（EHR）、实验室信息系统（LIS）、影像归档和通信系统（PACS）以及临床试验管理系统（CTMS）。数据更新频率较高，通常随患者就诊、检查结果回传和临床事件记录实时或准实时更新。文档结构复杂，包含非结构化的医生手写病程记录、结构化的诊断编码（如 ICD-10）、检验报告、影像报告以及半结构化的知情同意书模板。字段与单位多样，例如实验室结果涉及 mmol/L、g/dL 等单位，影像报告包含 DICOM 格式的图像数据，而病程记录则以自然语言文本为主。

## 这些特征在「工具调用与插件」这一环带来什么约束

医院运营数据的高度异构性决定了工具调用与插件需要具备强大的数据解析和标准化能力。非结构化文本数据要求插件能够进行命名实体识别（NER）和关系抽取，将医学术语、疾病、药物等关键信息结构化。实时或准实时的数据更新频率，意味着工具调用需要支持异步处理和高并发访问，以避免系统阻塞。多源异构的数据来源，例如 EHR 和 LIS，强制要求插件具备多系统集成能力，通过 API 或消息队列进行数据交换。此外，敏感的患者信息要求工具调用和插件在数据传输和处理过程中严格遵守 HIPAA 等隐私法规，进行数据脱敏或加密处理。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `MAX_PARALLEL_CALLS` | `20` | 处理高并发的病历数据抽取请求，避免排队延迟。 |
| `PARSE_TIMEOUT_SECONDS` | `300` 秒 | 应对大型影像报告或复杂病程记录的解析时间。 |
| `NER_MODEL_VERSION` | `v2.1.3` | 特定医学领域命名实体识别模型版本，确保准确性。 |
| `DATA_ANONYMIZATION_LEVEL` | `FULL_DEID` | 符合医疗数据隐私法规，进行全面去标识化。 |
| `API_KEY_ROTATION_INTERVAL` | `90` 天 | 提高系统安全性，定期更换外部服务 API 密钥。 |
| `KNOWLEDGE_BASE_EMBEDDING_MODEL` | `text-embedding-ada-002` | 适用于医学文本的嵌入模型，提升语义召回质量。 |

## 容易做错的三处

*   调用外部应用时，提示 `You need to use the app key rather than the account key`，原因是使用了通用账户密钥进行应用级调用，需要切换为专门的应用级别密钥。
*   工作流中嵌套知识库助手后，通过 API 调用工作流返回空值，原因是工作流配置中知识库助手的输出未正确映射到 API 响应字段，或者知识库版本与 API 调用版本不匹配。
*   嵌入页面无法显示应用图像或用户头像，原因是浏览器安全策略（如 CORS 或 CSP）阻止了跨域资源加载，需要配置服务器允许特定域名的资源访问。

## 怎么确认配好了

*   通过模拟一批包含不同文档类型（文本、PDF、DICOM）的患者数据，验证预筛结果的准确性和完整性。
*   检查系统日志，确认所有工具调用和插件执行过程中没有出现非预期的错误码或超时记录。
*   对比预筛结果与人工专家判断的一致性，通过小规模抽样评估模型召回率和精确率。
*   监控系统资源使用情况，确保在高峰时段仍能稳定响应，不出现性能瓶颈。
