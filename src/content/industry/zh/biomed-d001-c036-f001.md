# 单克隆抗体临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样

单克隆抗体临床试验预筛涉及的数据主要来源于公开的临床试验注册库（如 ClinicalTrials.gov、WHO ICTRP）、生物医药数据库（如 DrugBank、PubChem）以及各类文献资料。这些数据更新频率不一，临床试验状态变更可能每周甚至每天发生，而药物基本信息更新相对稳定，通常是每季度或半年。数据文档结构复杂，通常包含多个层级，例如试验方案（`Protocol`）、受试者招募标准（`Eligibility Criteria`）、研究药物信息（`Investigational Product`）等。字段方面，特异性地包含靶点信息（`Target`）、作用机制（`Mechanism of Action`）、给药途径（`Administration Route`）和抗体类型（`Antibody Type`，如 IgG1、IgG4）等，单位则涉及剂量（`mg/kg`）、频率（`周`、`月`）和持续时间（`天`、`年`）。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

单克隆抗体数据的多源性和动态更新频率，要求 HTTP 接口具备高效的数据同步与增量更新能力。复杂的文档结构和嵌套字段，使得接口返回数据的解析和结构化成为关键挑战，需要支持深层 JSON 或 XML 解析。特异性字段如靶点、抗体类型等，在外部系统调用时必须作为精确查询或过滤条件传递，确保预筛结果的准确性。剂量、频率等带有单位的数值字段，在数据传输和校验时需注意单位一致性，避免因单位差异导致的数据误判。此外，部分数据源可能对 API 调用频率有限制，需要在接口设计时考虑缓存机制和熔断策略，以应对高并发请求或外部系统故障。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `requestTimeout` | `60 秒` | 考虑到外部数据源响应速度不一及数据量较大，适当延长超时时间。 |
| `maxRetries` | `3` | 应对临时性网络波动或外部服务瞬时不可用，提高数据获取成功率。 |
| `headerContentType` | `application/json` | 大多数生物医药相关 API 返回 JSON 格式数据，确保正确解析。 |
| `queryParamKeys` | `target`, `antibodyType`, `phase` | 单克隆抗体预筛的核心筛选条件，便于外部系统精准查询。 |
| `dataRefreshInterval` | `24 小时` | 临床试验状态更新频率较高，保持数据相对新鲜度。 |
| `responseSchemaValidation` | 启用 | 验证外部系统返回数据的结构和字段，确保数据完整性和正确性。 |

## 容易做错的三处

*   现象：外部系统调用接口后返回 `400 Bad Request` 错误码。原因：请求体中缺少了关键的筛选参数，例如 `target` 或 `phase` 字段，这些字段对于单克隆抗体预筛是强制性的。
*   现象：接口返回的临床试验结果列表为空或结果数量明显偏少。原因：`queryParamKeys` 中某个参数值拼写错误或单位不匹配，导致查询条件无法匹配到有效数据。
*   现象：调用接口后长时间无响应，最终出现 `504 Gateway Timeout` 错误。原因：`requestTimeout` 设置过短，外部数据源处理复杂查询耗时较长，导致在数据返回前连接已中断。

## 怎么确认配好了

*   通过模拟调用发送包含所有核心参数（如 `target`、`antibodyType`）的请求，检查是否能正常返回结构完整且非空的数据。
*   在外部系统日志中查看 API 调用记录，确认 `headerContentType` 等 HTTP 头信息是否正确发送，以及响应状态码是否为 `200 OK`。
*   随机选取几个返回结果，核对其中特定字段（如 `dosage`、`frequency`）的单位和数值，与原始数据源进行比对，确认数据解析和单位转换无误。
