# 合理用药临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样
合理用药临床试验预筛的数据核心是药物说明书、临床指南、医学文献及患者电子病历。这些数据来源多样，更新频率不一。药物说明书和临床指南通常按季度或年度更新，涉及药物适应症、禁忌症、用法用量、不良反应等结构化信息。医学文献则以月度甚至周度更新，包含大量非结构化或半结构化的研究报告、病例分析。患者电子病历数据实时生成，涉及用药史、过敏史、诊断结果和检验指标等。数据文档结构复杂，既有标准化的 XML/JSON 格式数据，也有大量 PDF、HTML 格式的非结构化文本。字段与单位方面，涉及药物剂量（mg、g）、检验结果（mmol/L、U/L）等，单位标准化是数据处理的关键。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
合理用药预筛对数据时效性和准确性要求高，因此与外部系统的 HTTP 接口集成必须考虑数据源的更新频率。实时更新的患者病历数据需要低延迟的接口调用，而季度更新的药物说明书则可接受周期性批量同步。文档结构复杂性决定了接口需要支持多种数据格式的解析，例如，对于 PDF 格式的药物说明书，接口需能调用 OCR 服务或预处理服务进行文本提取。字段与单位的标准化问题，要求接口在数据接收后进行严格的数据校验和转换，确保药物剂量和检验指标单位的一致性。例如，当外部系统返回的药物剂量单位与内部系统不一致时，需要进行自动转换，否则可能导致预筛结果的偏差。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `AIPROXY_API_ENDPOINT` | `http://localhost:8080/v1/chat/completions` | 本地开发与测试环境，避免直接调用生产API。 |
| `MAX_RETRIES` | `3` | 应对外部系统暂时性故障或网络波动，提高接口稳定性。 |
| `REQUEST_TIMEOUT_SECONDS` | `60 秒` | 多数合理用药规则计算复杂，需要较长的响应时间。 |
| `ACCESS_TOKEN` | 按外部API文档要求配置 | 确保接口调用的身份验证和授权。 |
| `DATA_FORMAT_CONVERSION` | `JSON to Internal Schema` | 统一不同来源数据的结构，便于内部模型处理。 |
| `ERROR_NOTIFICATION_EMAIL` | `devops@example.com` | 接口调用失败时及时通知相关人员进行排查。 |

## 容易做错的三处
*   接口返回的响应记录预览中 `Human` 字段为空，原因是外部系统返回的对话消息结构与内部期望不符，导致字段映射失败。
*   在 Flow 中添加的流式 SSE 输出 HTTP 请求，前端无法实时展示，原因是 HTTP 客户端未正确处理 `Content-Type: text/event-stream` 头部，没有按事件流解析数据块。
*   HTTP 接口调用时常出现 `401 Unauthorized` 错误，原因是 `ACCESS_TOKEN` 参数填写不正确或已过期，未能通过外部系统的身份验证。

## 怎么确认配好了
*   对核心的合理用药规则，通过模拟不同患者病历数据，调用 HTTP 接口，检查返回的预筛结果是否与预期一致。
*   在开发模式下，检查 `AIPROXY_API_ENDPOINT` 配置指向的本地服务是否正常启动并可访问，且能够正确处理请求。
*   监测接口调用日志，查看是否有 `200 OK` 以外的状态码出现，并检查错误日志中关于数据解析或转换的警告信息。
*   通过前端界面提交一条包含复杂药物组合的预筛请求，确认流式输出能够正常逐条展示预筛建议，且最终结果完整。
