# 呼吸系统临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样

呼吸系统疾病的临床试验数据主要来源于电子病历（EHR）、临床试验管理系统（CTMS）、实验室信息系统（LIS）以及患者报告结局（PRO）数据。数据更新频率较高，尤其在试验进行期间，患者访视、检查结果、不良事件等信息可能每日甚至实时更新。文档结构通常遵循临床数据交换标准，如 CDISC ODM 或 FHIR 资源，涉及结构化数据与非结构化文本。字段方面，特有指标包括肺功能测试（如 FEV1、FVC）、影像学报告（如胸部 CT 描述）、症状评分（如 CAT 评分、mMRC 呼吸困难评分）以及特定生物标志物。单位需严格遵循医学规范，例如 FEV1 以升（L）表示，氧饱和度以百分比（%）表示，药物剂量以毫克（mg）或微克（µg）表示。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

呼吸系统临床试验数据的高更新频率要求外部系统接口具备实时或近实时的数据同步能力，避免预筛结果基于过期信息。复杂的文档结构，特别是影像学报告和症状描述中的非结构化文本，需要接口支持多种数据格式的传输与解析，例如 JSON、XML 或 HL7 消息，并可能涉及文本嵌入与向量检索。特定字段如肺功能指标的精确单位要求，意味着接口在数据传输时需严格校验数据类型和数值范围，防止因单位转换错误导致预筛结果偏差。此外，患者隐私和数据安全是核心考量，接口必须支持 HTTPS 加密传输，并实施严格的身份认证和授权机制，确保数据合规性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `requestTimeout` | `60000 毫秒` | 应对复杂查询或大数据量传输可能导致的延迟 |
| `maxConnections` | `按实测标定` | 确保在并发请求高峰期系统性能稳定，避免连接池耗尽 |
| `headers.Authorization` | `Bearer <token>` | 多数医疗数据API采用OAuth2或JWT进行身份验证 |
| `payload.dataType` | `JSON` | 普遍支持且易于解析结构化与非结构化混合数据 |
| `retryStrategy.maxRetries` | `3` | 应对网络瞬时抖动或外部系统暂时性不可用 |
| `errorHandling.statusCodeMapping` | `400:INVALID_PARAMS, 401:UNAUTHORIZED, 403:FORBIDDEN, 404:NOT_FOUND, 500:SERVER_ERROR` | 精确识别并分类常见的HTTP错误类型 |

## 容易做错的三处

*   调用外部API时出现 `401 Unauthorized` 错误，原因在于 `headers.Authorization` 中提供的令牌已过期或权限不足。
*   接口返回的患者肺功能指标 `FEV1` 字段为空，原因是请求参数中未包含正确的患者ID或数据查询范围不准确。
*   在 FastGPT 工作流中配置的变量 `patientID` 未能正确传递给 HTTP 接口，导致外部系统查询失败，这通常是由于变量名与接口期望的参数名不匹配。

## 怎么确认配好了

*   通过 FastGPT 的调试界面，检查 HTTP 请求的 `headers` 和 `body` 是否与外部API文档要求一致。
*   模拟多种临床场景下的患者数据，分别调用接口，核对返回的 `statusCode` 和 `response.data` 内容，验证数据完整性与准确性。
*   使用 FastGPT 的日志功能，追踪接口调用链，确认每次数据同步或查询操作的耗时是否在可接受范围内，以评估性能。
