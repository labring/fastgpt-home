# 工艺验证临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样

工艺验证数据主要来源于制药企业的生产执行系统（MES）、质量管理系统（QMS）和实验室信息管理系统（LIMS）。数据更新频率相对较低，通常在批次生产结束后或关键质量节点进行，例如每批次生产完成、关键工艺参数变更或年度回顾时。数据文档结构复杂，常以结构化的 XML 或 JSON 格式存储，也存在大量的非结构化 PDF 报告，包含详细的批生产记录、检验报告、偏差处理记录。核心字段包括批次号、产品代码、工艺步骤、关键质量属性（CQA）、关键工艺参数（CPP）、设备 ID、操作员 ID、检验结果、稳定性数据等。单位多样，涉及温度（℃）、压力（kPa）、流速（L/min）、浓度（mg/mL）、pH 值、时间（小时）等，且不同参数的单位可能在不同批次或产品间存在差异。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

工艺验证数据来源分散，需要集成 MES、QMS、LIMS 等多个异构系统，HTTP 接口需支持多种认证方式和数据格式解析。更新频率低但数据量大，单次拉取可能涉及数千条记录，要求接口具备高效的数据传输能力和分页机制。文档结构复杂，尤其是非结构化 PDF 报告，对外部系统的文件解析能力提出要求，需要支持 OCR 或 PDF 内容抽取。字段与单位的多样性，意味着接口返回的数据需要进行严格的标准化和单位转换，避免下游模型因单位不一致产生误判。此外，数据链路的稳定性至关重要，任何接口调用失败都可能导致关键工艺验证信息的缺失，影响预筛的准确性。因此，需要设计 robust 的重试机制和错误处理流程。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `API_ENDPOINT` | `https://api.example.com/process_validation` | 指定数据源的 RESTful API 地址，确保协议和路径正确。 |
| `AUTH_TOKEN_TYPE` | `Bearer Token` | 大多数企业级 API 使用 OAuth2 的 Bearer Token 进行身份验证。 |
| `REQUEST_TIMEOUT_SECONDS` | `120 秒` | 工艺验证数据量大，单次请求处理时间可能较长，避免因超时中断。 |
| `MAX_RETRIES` | `3` | 应对网络波动或服务瞬时不可用，提高数据拉取成功率。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | PDF 报告解析耗时较长，预留足够时间完成文件内容抽取。 |
| `DATA_SCHEMA_VERSION` | `v2.1` | 明确指定接口期望或返回的数据模式版本，保证字段与单位的一致性。 |

## 容易做错的三处

*   现象：接口返回 401 错误，数据拉取失败。原因：`AUTH_TOKEN_TYPE` 配置不正确或 `API_KEY` 过期，导致认证失败。
*   现象：部分关键字段（如 CPP 值）在知识库中为空或格式异常。原因：外部系统返回的数据中，字段名与预设不匹配，或单位未正确转换，导致数据解析失败。
*   现象：FastGPT 知识库只能回答少量问题，后续追问无法联系上下文。原因：知识库构建时，拉取的数据量不足或分段策略不合理，导致相关上下文信息缺失。

## 怎么确认配好了

*   通过 FastGPT 的调试工具，对 `API_ENDPOINT` 发送测试请求，检查是否成功返回 200 状态码和预期数据结构。
*   上传一份包含复杂表格和多单位描述的工艺验证 PDF 报告，观察知识库是否能正确抽取并理解其中的关键质量属性和工艺参数。
*   在知识库中提问关于特定批次的关键工艺参数，验证系统能否准确提供相关数值和单位，并能对不同单位进行简单换算。
