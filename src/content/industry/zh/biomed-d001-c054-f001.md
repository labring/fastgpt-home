# 康复设备临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样
康复设备在临床试验预筛阶段的数据，主要来源于设备传感器、电子病历系统（EHR）、以及临床试验管理系统（CTMS）。传感器数据通常以时间序列形式存在，例如步态分析仪记录的受试者步态参数（步长、步频、支撑相时间等），或智能手环记录的活动量、心率等。EHR 系统提供受试者的既往病史、用药情况、诊断结果等结构化与非结构化文本数据。CTMS 则包含试验方案、筛选标准、受试者招募进度等信息。这些数据更新频率不一，传感器数据可达秒级，EHR数据更新相对滞后，而CTMS数据则随试验进展周期性更新。文档结构多样，包含 JSON、CSV、XML 等格式的结构化数据，以及 PDF、DICOM 图像等非结构化数据。字段与单位通常遵循医学标准，例如步长单位为厘米（cm），心率单位为次/分钟（bpm）。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
康复设备数据的高更新频率和多样化格式，对 HTTP 接口的实时性与数据解析能力提出要求。例如，步态分析数据可能需要每秒数百次的接口调用，以捕获受试者运动的细微变化，这要求接口具备高并发处理能力。EHR 系统中的非结构化文本数据，如医生诊断记录，需要通过自然语言处理（NLP）技术进行信息抽取，并转换为结构化数据再进行预筛判断，这增加了接口处理的复杂性。此外，不同数据源的单位与字段命名差异，需要在接口层进行标准化映射，确保数据一致性，避免因单位不匹配导致的筛选错误。接口的失败处理机制需要考虑数据源不稳定或网络延迟的情况，例如，部分传感器数据丢失不应导致整个预筛流程中断。对外部系统调用时，需确保数据传输的加密与合规性，特别是涉及患者隐私的敏感信息。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `HTTP_TIMEOUT_SECONDS` | `30 秒` | 平衡高频传感器数据传输的实时性与网络不稳定性，避免过长等待导致任务堆积。 |
| `MAX_RETRIES_ON_FAILURE` | `3 次` | 针对外部系统偶发性故障，提供重试机制，减少因瞬时网络波动造成的数据丢失。 |
| `DATA_PARSING_SCHEMA` | `JSON Schema 严格校验` | 确保接收的传感器与EHR数据格式符合预期，减少因数据格式错误导致的预筛异常。 |
| `BATCH_SIZE_FOR_SENSOR_DATA` | `500 条记录` | 优化高频传感器数据传输效率，减少单次HTTP请求的开销，提高吞吐量。 |
| `DATA_ENCRYPTION_STANDARD` | `TLS 1.2` | 保证患者敏感数据在传输过程中的安全性与合规性要求。 |
| `ERROR_NOTIFICATION_CHANNEL` | `Slack 或邮件` | 确保接口调用失败时，研发人员能及时收到告警，快速响应处理。 |

## 容易做错的三处
*   现象：外部系统调用时出现 `401 Unauthorized` 错误码。原因：API Key 或身份验证令牌过期或配置错误，导致无法通过外部系统的安全认证。
*   现象：从外部系统获取的受试者数据字段为空或类型不匹配，导致预筛规则无法正确执行。原因：外部系统接口返回的数据结构与预期的 `DATA_PARSING_SCHEMA` 不一致，或数据映射关系配置有误。
*   现象：高频传感器数据传输时，工作流执行超时或数据处理延迟。原因：`HTTP_TIMEOUT_SECONDS` 设置过短，或 `BATCH_SIZE_FOR_SENSOR_DATA` 过大，导致单次请求处理的数据量超出接口承载能力。

## 怎么确认配好了
*   对每个外部系统接口进行独立的功能测试，验证其能正确返回预期数据。
*   使用实际的康复设备传感器数据模拟高并发场景，观察工作流的执行时间与数据处理延迟，确保在峰值负载下仍能稳定运行。
*   检查日志系统，确认接口调用无 `HTTP_TIMEOUT_SECONDS` 超时错误，且 `MAX_RETRIES_ON_FAILURE` 配置的重试机制正常工作。
*   随机抽取一批经过预筛的受试者数据，手动比对其关键字段，验证 `DATA_PARSING_SCHEMA` 及数据单位转换的准确性。
