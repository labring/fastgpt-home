# 影像设备临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样
影像设备在临床试验预筛阶段的数据主要来源于 DICOM (Digital Imaging and Communications in Medicine) 标准格式的医学图像，例如 CT、MRI、X光等。这些数据通常由医院的 PACS (Picture Archiving and Communication System) 系统生成并存储。数据的更新频率取决于临床试验的入组速度和影像检查计划，可能从每日数次到每周数次不等。DICOM 文件内部包含复杂的层级结构，包括患者信息、研究信息、序列信息以及图像像素数据。字段方面，除了标准的 DICOM 标签，还可能包含研究方案特有的自定义标签。单位通常遵循医学影像领域惯例，例如毫米 (mm) 用于尺寸，豪斯菲尔德单位 (HU) 用于 CT 密度。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
DICOM 数据的复杂结构和较大文件体积对 HTTP 接口的传输效率提出了挑战，尤其是在网络带宽受限的环境下。数据中的患者隐私信息要求接口必须具备严格的身份验证和授权机制，确保数据传输的合规性。DICOM 标签的标准化程度高，但自定义标签的存在需要接口具备灵活的字段解析能力，以适应不同研究方案的数据特异性。此外，影像数据通常以二进制流的形式传输，接口需支持大数据块的上传和下载。数据更新的非实时性决定了接口设计上不应过度依赖即时响应，而应考虑异步处理和状态查询机制。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `MAX_PAYLOAD_SIZE_MB` | `1024 MB` | 影像文件体积大，需支持单次传输大容量数据。 |
| `API_TIMEOUT_SECONDS` | `300 秒` | 考虑到大文件上传和网络延迟，预留足够长的接口响应时间。 |
| `AUTH_HEADER_NAME` | `X-API-Key` | 采用标准的自定义 HTTP 头进行 API 密钥认证，提高安全性。 |
| `ASYNC_UPLOAD_ENDPOINT` | `/api/v1/dicom/upload/async` | 区分同步与异步上传，应对影像数据处理耗时长的场景。 |
| `DICOM_TAG_PARSING_RULES` | 按实测标定 | 根据具体研究方案中的自定义 DICOM 标签定义解析规则。 |

## 容易做错的三处
*   现象：API 调用返回 413 Payload Too Large 错误。原因：`MAX_PAYLOAD_SIZE_MB` 配置过小，无法承载单个 DICOM 文件的传输。
*   现象：外部系统上传文件后长时间无响应或返回 504 Gateway Timeout。原因：`API_TIMEOUT_SECONDS` 设置不足，导致在处理或传输大型影像数据时超时。
*   现象：上传的影像数据在 FastGPT 中无法正确识别患者信息或研究 ID。原因：`DICOM_TAG_PARSING_RULES` 未能正确配置，无法解析特定研究方案中的自定义 DICOM 标签。

## 怎么确认配好了
*   上传一个典型的 DICOM 文件包，检查接口是否返回 200 OK 状态码，并记录文件 ID。
*   通过 FastGPT 内部查询功能，使用返回的文件 ID 检索，核对患者基本信息、研究编号等关键字段是否与原始 DICOM 数据一致。
*   上传一个包含自定义 DICOM 标签的影像文件，确保 FastGPT 能够正确提取并显示这些自定义信息，核对字段名与值是否符合预期。
