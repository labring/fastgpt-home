# 心血管介入临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样

心血管介入领域的临床试验预筛数据主要来源于医院电子病历系统（EHR）、影像归档和通信系统（PACS）以及实验室信息系统（LIS）。数据更新频率因来源而异，例如患者生命体征数据可能实时更新，而实验室检查结果通常在数小时内更新。文档结构以半结构化和非结构化数据为主，包括医生诊疗记录、影像报告、检查检验报告等，常采用 HL7 v2 或 FHIR 标准进行传输。关键字段包括患者 ID、诊断信息（如 ICD-10 编码）、手术记录（如 CPT 编码）、影像学测量值（如血管狭窄程度百分比）、生物标志物结果（如肌钙蛋白 I，单位 ng/mL；NT-proBNP，单位 pg/mL）以及用药记录。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

心血管介入数据的多样性与复杂性，对 HTTP 接口的兼容性提出要求。半结构化和非结构化数据需要接口支持灵活的数据格式，如 JSON 或 XML，并能处理嵌套结构。数据更新频率的差异意味着接口需要支持多种触发机制，例如针对实时数据的 webhook 推送，以及针对周期性更新数据的定时轮询。文档结构中的标准编码（HL7、FHIR、ICD-10、CPT）要求接口在数据解析时具备相应的语义理解能力，确保字段映射的准确性。影像学测量值和生物标志物结果的精确单位，要求接口在数据传输和存储过程中保持数据类型和精度的完整性，避免因类型转换导致的精度丢失或单位混淆。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `externalApi.url` | 外部系统 API 地址 | 根据医院 EHR/PACS/LIS 系统的实际 API 端点配置，例如 `https://ehr.hospital.com/api/v2/patients`。 |
| `request.method` | `POST` 或 `GET` | 多数数据推送采用 `POST`，查询数据采用 `GET`。 |
| `request.headers.Content-Type` | `application/json` 或 `application/xml` | 适应不同系统的数据交换格式，FHIR 标准常用 `application/fhir+json`。 |
| `request.body.template` | 自定义 JSON/XML 模板 | 依据目标系统 API 文档定义请求体结构，包含患者 ID、诊断、关键指标等字段。 |
| `response.timeout` | `60000` 毫秒 | 考虑到临床系统可能存在较高的负载，预留充足的响应时间，避免因超时导致的数据同步失败。 |
| `data.extraction.jsonPath` | `$.patients[*].data` | 针对返回的 JSON 数据，通过 JSONPath 表达式准确提取所需的患者信息和检查结果。 |

## 容易做错的三处

*   HTTP 状态码 `400 Bad Request` 或 `500 Internal Server Error`，原因是请求体中的必填字段缺失或数据格式不符合外部系统要求。
*   数据同步后，FastGPT 中部分关键指标字段为空，原因是 `data.extraction.jsonPath` 配置不正确，未能准确解析外部系统返回的嵌套 JSON 结构。
*   外部系统数据更新后，FastGPT 中未及时反映最新状态，原因是未正确配置 webhook 监听或定时任务，导致数据同步频率不足。

## 怎么确认配好了

*   通过 FastGPT 的 HTTP 接口调试工具，模拟一次完整的患者数据查询或推送操作，检查返回的 HTTP 状态码是否为 `200 OK`。
*   在 FastGPT 知识库中创建一个测试患者，手动导入一条外部系统模拟的心血管介入数据，核对关键字段（如 `血管狭窄程度`、`肌钙蛋白I`）的值与单位是否与源数据一致。
*   配置一个定时任务，例如每 30 分钟同步一次最新的实验室检查结果，随后检查 FastGPT 知识库中相关患者的数据更新时间，确认同步机制正常工作。
*   监控外部系统的 API 日志，查看 FastGPT 发起的请求是否按照预期频率和格式发送，并验证外部系统是否成功处理这些请求。
