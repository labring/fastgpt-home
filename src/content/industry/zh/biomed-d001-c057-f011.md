# 心血管介入临床试验预筛的文档解析与分块

## 这个品类的数据长什么样

心血管介入领域的数据主要来源于医疗机构的电子病历系统、影像报告、手术记录、药物不良反应报告以及临床试验方案文档。这些数据更新频率较高，特别是对于住院患者，每日甚至每小时都有新的生理指标和治疗记录生成。文档结构上，电子病历多为半结构化文本，包含大量自由文本描述，如主诉、现病史、查体、辅助检查结果等。影像报告（如心电图、超声心动图、冠脉造影报告）通常有固定模板，但诊断结论部分仍是自由文本。临床试验方案文档则通常是长篇幅的 PDF 或 Word 文件，结构严谨，包含研究背景、入排标准、研究方法、统计分析计划等多个章节。字段与单位方面，涉及血压（mmHg）、心率（次/分）、血氧饱和度（%）、肌钙蛋白（ng/mL）等，单位标准化程度较高。

## 这些特征在「文档解析与分块」这一环带来什么约束

心血管介入数据的半结构化特性对文档解析提出了挑战。自由文本段落需要更精细的切分策略，以避免语义丢失或过度泛化。高更新频率要求知识库具备快速增量更新和局部索引重建的能力，确保检索结果的时效性。长篇幅的临床试验方案文档则强调了对文档整体结构和层级的理解，分块时需兼顾章节完整性和内容连贯性。例如，入排标准往往分散在多个小节中，需确保相关条件被聚合在一个知识块内。影像报告中的数值和结论常以“数值+单位”或“描述性短语”形式出现，解析时需准确识别并提取，这影响到后续的问答和推理。对特定医学术语和缩写的识别准确性，也直接关系到分块质量和信息检索的精度。

## 配置怎么定

| 配置项             | 建议取法                                 | 这样取的依据                                     |
| :----------------- | :--------------------------------------- | :----------------------------------------------- |
| `分段长度`         | `400–600 字符`                           | 兼顾语义完整性与召回效率，避免单个分块过长或过短 |
| `分段重叠长度`     | `50–100 字符`                            | 确保上下文衔接，减少因分块导致的信息割裂         |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`                                 | 处理大型临床试验方案 PDF 文档的解析时间          |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB`                                 | 适应包含大量影像或病历数据的文档体积             |
| `文件类型白名单`   | `pdf`, `docx`, `txt`, `csv`              | 涵盖临床试验文档、病历和数据报告的常见格式       |
| `自定义分隔符`     | 按实测标定，例如 `\n\n`, `###`, `---`    | 根据实际文档结构，特别是半结构化病历，进行精确切分 |

## 容易做错的三处

*   现象：上传的临床试验方案 PDF 文件解析超时或失败。原因：`PARSE_FILE_TIMEOUT_SECONDS` 设置过短，无法处理超大文件或复杂排版文档的解析耗时。
*   现象：Excel 导入的患者数据，多行记录被合并到一个知识块中。原因：未正确配置或启用 `自定义分隔符`，系统按默认规则进行分段，导致行间分隔符被忽略。
*   现象：用户提问关于“入排标准”时，召回结果不完整或关联度低。原因：`分段长度` 设置过小，将分散在文档不同段落但语义相关的入排条件切分到不同的知识块中。

## 怎么确认配好了

*   上传典型的心血管介入临床试验方案 PDF 文档，检查解析状态，确保无超时或解析错误提示。
*   导入一份结构化的患者病历 CSV 文件，随机抽查多个知识块，验证每条患者记录或关键信息是否独立成块。
*   针对心血管介入领域的核心术语，如“冠脉狭窄”、“心肌梗死”、“支架植入”，进行模拟提问，观察召回结果的完整性和相关度，判断是否能有效关联到包含这些术语的知识块。
