# 感染性疾病临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样

感染性疾病临床试验预筛的数据通常来自多个源头，包括电子病历系统（EHR）、实验室信息系统（LIS）、医学影像归档与通信系统（PACS）以及公共卫生机构报告。数据类型多样，涵盖患者人口学信息、诊断编码（如 ICD-10）、病原体检测结果（包括菌株类型、耐药性谱）、影像学报告描述、用药记录、既往感染史等。数据更新频率较高，尤其在疫情爆发或患者病情变化时，部分实验室结果可能每小时更新。文档结构以半结构化或非结构化为主，例如临床医生手写的病程记录、影像报告的自然语言描述。字段与单位方面，病原体载量常以 `拷贝数/mL` 或 `IU/mL` 表示，耐药性结果则为 `MIC` 值（最低抑菌浓度），具体数值单位需严格识别。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

感染性疾病数据的高更新频率要求 HTTP 接口具备高效的轮询或webhook接收能力，以确保预筛结果的时效性。半结构化和非结构化文档的存在，使得对接口返回数据的解析需要更强的灵活性，不能仅依赖固定字段映射，需结合自然语言处理（NLP）技术。字段与单位的特异性，例如 `MIC` 值，在数据传输和解析时必须精确匹配，否则可能导致筛选逻辑错误。此外，涉及病原体敏感性等关键信息的数据源，往往对访问权限和数据安全有严格要求，这会影响 API 密钥的配置策略和接口访问频率。数据来源的异构性也意味着需要处理多种数据格式（如 JSON、XML、HL7），并进行标准化转换。

## 配置怎么定

| 配置项                       | 建议取法                                 | 这样取的依据                                                                    |
| :--------------------------- | :--------------------------------------- | :------------------------------------------------------------------------------ |
| `requestTimeoutSeconds`      | `60 秒`                                  | 感染性疾病数据源可能涉及大数据量查询，避免因数据拉取时间过长导致接口超时。    |
| `maxRetries`                 | `3`                                      | 应对临时性网络波动或外部系统瞬时故障，提高数据获取的成功率。                    |
| `apiSecretExpirationHours`   | `24 小时`                                | 兼顾安全性与便利性，定期轮换密钥可降低泄露风险，并符合部分医疗系统安全规范。    |
| `concurrentRequestsLimit`    | `10`                                     | 避免对外部系统造成过大压力导致其拒绝服务，同时保持一定的数据获取效率。        |
| `dataParseMode`              | `混合模式（JSON & Regex）`               | 感染性疾病数据存在结构化与半结构化混合情况，兼顾效率与灵活性。                  |
| `customHeaderFields`         | `X-API-Version: 2.0`                     | 明确指定外部 API 版本，确保兼容性，防止因版本升级导致接口行为变化。           |

## 容易做错的三处

*   接口返回的病原体检测结果字段为空，原因可能是外部系统数据更新延迟，或接口设计未完全覆盖所有检测项。
*   临床试验预筛结果中，患者的耐药性判断错误，原因是 `MIC` 值的单位未正确解析，导致数值比较逻辑失效。
*   频繁触发外部系统接口调用限制，现象是收到 `429 Too Many Requests` 状态码，原因是未合理配置并发请求限制或轮询间隔。

## 怎么确认配好了

*   通过模拟多个患者数据请求，检查 HTTP 接口返回的响应时间是否在 `requestTimeoutSeconds` 设定的阈值内。
*   对比 FastGPT 内部存储的患者关键字段（如病原体名称、`MIC` 值）与外部系统原始数据，确认数据解析与单位转换的准确性。
*   持续监控 FastGPT 对外部系统的 API 调用日志，确保未出现 `429` 或 `5xx` 等错误状态码，并检查 `apiSecretExpirationHours` 配置是否按预期触发密钥更新。
*   随机抽取一批已完成预筛的患者，人工核对其临床指标是否符合入组标准，以验证筛选逻辑的正确性，特别是对半结构化文本的解析效果。
