# 护理管理临床试验预筛的工具调用与插件

## 这个品类的数据长什么样

护理管理在临床试验预筛中的数据主要来源于患者电子健康档案（EHR）、护理记录系统（NRS）以及部分穿戴设备数据。EHR 数据结构化程度较高，包含诊断、用药、检验结果等，更新频率通常在患者就诊或治疗后即时同步。NRS 数据则更侧重于护理评估、生命体征、护理干预记录，通常以半结构化文本为主，更新频率高，可能每小时或每天多次更新。穿戴设备数据则提供连续的生理指标，如心率、睡眠模式，数据量大且实时性强。文档形式多样，包括结构化的医疗表格、非结构化的护理日志、以及PDF格式的报告。字段名称和单位需特别注意，例如血压可能以 `mmHg` 记录，血糖可能以 `mmol/L` 或 `mg/dL` 记录，存在多标准并存的情况。

## 这些特征在「工具调用与插件」这一环带来什么约束

护理管理数据的高更新频率和多样性，对工具调用的实时性和鲁棒性提出了要求。EHR 和 NRS 中存在大量医学术语和缩写，需要插件具备强大的语义理解能力。半结构化文本和非结构化护理日志，要求插件能有效抽取关键信息，并将其转化为结构化数据，供后续判断。多单位并存的字段，在进行数值比较和筛选时，插件需要具备单位转换能力，避免因单位不一致导致的误判。此外，敏感的患者信息要求工具调用和插件在数据处理过程中严格遵守隐私保护规范，确保数据脱敏或在安全沙箱环境中运行。实时性要求体现在预筛工具需要快速响应，以便护理人员及时调整患者管理策略。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `tool_timeout_seconds` | `60 秒` | 多数外部 API 调用在处理复杂医疗数据时，通常需要较长时间，避免因超时中断。 |
| `max_tokens` | `2048` | 处理包含大量医学术语和护理日志的文本时，需要更大的上下文窗口以捕获完整语义。 |
| `response_format` | `JSON` | 结构化输出便于后续程序化处理，例如根据预筛结果触发下一步通知或记录。 |
| `plugin_retry_attempts` | `3` | 外部系统可能因网络波动或服务瞬时负载过高导致失败，增加重试提高稳定性。 |
| `data_extraction_model` | 按实测标定 | 针对半结构化护理日志，需选择对医学文本实体识别和关系抽取能力强的模型。 |
| `unit_conversion_enabled` | `true` | 确保不同来源的生理指标数据在比较时单位统一，避免逻辑错误。 |

## 容易做错的三处

*   现象：API 调用返回 `400 Bad Request` 错误，提示缺少必要参数或参数格式不正确。原因：外部工具调用时，未正确封装请求体中的特定医学字段，例如 `patient_id` 或 `lab_test_code`，或数据类型不匹配。
*   现象：返回的预筛结果中，患者的某个生理指标（如血糖）判断错误。原因：插件未正确识别或转换不同来源数据中的单位，导致数值比较时出现偏差。
*   现象：系统在处理大量护理日志时出现响应缓慢或超时。原因：`tool_timeout_seconds` 配置过短，或用于文本解析的插件在处理非结构化医学文本时效率低下，未能及时返回结果。

## 怎么确认配好了

*   选择一组包含典型护理记录和EHR数据的测试用例，运行工具调用，核对输出的预筛结果与预期是否一致，尤其是涉及单位转换和复杂条件判断的场景。
*   检查系统日志，确保所有外部工具调用均成功完成，没有出现 `HTTP 5xx` 或 `Connection Timeout` 等错误，并记录平均响应时间，评估是否满足实时性要求。
*   针对不同数据源的字段，例如血压、血糖，手动验证插件是否能正确识别其字段名，并进行单位标准化处理，确保数值比较的准确性。
