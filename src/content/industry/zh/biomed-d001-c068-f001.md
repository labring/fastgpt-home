# 智能导诊临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样
智能导诊在临床试验预筛场景中，其数据主要来源于医疗机构的电子病历系统（EHR）、临床试验管理系统（CTMS）以及公开的临床试验注册库（如 ClinicalTrials.gov）。EHR 数据包含患者的诊断、用药、检验检查结果等结构化与非结构化信息；CTMS 数据则涵盖试验方案、入排标准、受试者招募状态等。这些数据的更新频率不一，EEHR 数据实时性要求高，随患者就诊动态更新；CTMS 数据则在试验进展中阶段性更新；注册库数据通常按试验周期更新。文档结构复杂，涉及 ICD 编码、SNOMED CT 术语以及各种医学专有名词。字段包含患者ID、诊断名称、用药记录、实验室检查值（如血常规、肝肾功能）、影像报告描述、入排标准文本等。单位类型多样，如毫克（mg）、毫升（mL）、mmol/L、U/L，以及各种时间单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
复杂且异构的数据源要求 HTTP 接口具备强大的数据集成能力，能够同时对接多种医疗信息系统。高实时性需求意味着接口设计需要支持高并发访问和低延迟响应，以确保智能导诊系统能即时获取最新的患者信息进行预筛。非结构化文本数据（如病历描述、影像报告）的存在，对接口传输的数据格式提出挑战，需要支持 JSON 或 XML 格式承载复杂文本，并可能需要额外的文本处理服务。大量的医学术语和单位，要求接口在数据传输过程中保持术语一致性，避免因单位转换或术语不匹配导致的预筛错误。此外，临床试验入排标准的复杂逻辑，要求外部系统接口能接收并处理复杂的查询参数，以便进行精确的条件匹配，例如基于多个诊断、用药和检验指标的组合查询。数据安全性与隐私保护是核心约束，所有 HTTP 通信必须采用加密协议。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `30 秒` | 多数医疗系统接口响应时间在数秒到十数秒，此值可覆盖大部分稳定请求。 |
| `MAX_BODY_SIZE_MB` | `5 MB` | 考虑传输电子病历、检验报告等可能包含大量文本信息的 JSON 或 XML 数据。 |
| `AUTH_HEADER_NAME` | `Authorization` | 符合 OAuth2.0 或 JWT 等主流鉴权机制的规范。 |
| `CONCURRENT_CONNECTIONS_LIMIT` | `200` | 平衡系统资源占用与多用户并发预筛的需求，可根据实际负载调整。 |
| `RETRY_ATTEMPTS_ON_FAILURE` | `3 次` | 应对网络瞬时波动或外部系统偶发性错误，减少因暂时问题导致的失败。 |
| `DATA_ENCRYPTION_PROTOCOL` | `TLSv1.2+` | 确保患者敏感数据在传输过程中的机密性和完整性，符合合规要求。 |

## 容易做错的三处
*   接口调用返回 403 Forbidden 错误，原因在于鉴权密钥 `API_KEY` 或 `Authorization` token 未正确配置或已过期。
*   部分患者的检验结果字段为空或格式异常，原因在于外部系统返回的数据结构与预期不符，未能正确解析特定单位或术语。
*   预筛结果与预期不符，例如遗漏符合条件的患者，原因在于 HTTP 请求参数中入排标准的逻辑表达式未能准确映射到外部数据库的查询语句。

## 怎么确认配好了
*   执行模拟请求，检查 HTTP 响应状态码为 200 OK，并验证返回数据结构与预期一致。
*   针对包含特殊字符或多种医学单位的测试数据，调用接口并核对返回的字段值是否完整且格式正确。
*   设计覆盖不同入排标准组合的测试用例，通过接口调用，确认返回的患者列表与手动查询结果匹配。
