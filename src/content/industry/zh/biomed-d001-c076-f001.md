# 病历质控临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样

病历质控数据主要来源于医院信息系统（HIS）、电子病历系统（EMR）及临床试验管理系统（CTMS）。数据更新频率根据业务需求差异较大，通常在临床试验进行中保持实时或准实时更新，例如每日或每周更新一次。文档结构复杂，常以结构化（如 JSON、XML）、半结构化（如临床文档 CDA）和非结构化（如自由文本病程记录）混合形式存在。字段包含患者人口学信息、诊断、治疗方案、实验室检查结果、影像学报告、病理报告等。单位多样，如 `mg/dL`、`mmol/L`、`kPa`、`mL/min` 等，且存在不同标准单位间的转换需求，例如血压单位 `mmHg`。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

病历质控数据的多源性与复杂结构，要求 HTTP 接口具备强大的数据解析与转换能力，以应对不同系统间的数据格式差异。实时或准实时的更新频率，意味着接口需要支持高并发请求和低延迟响应，确保数据同步的及时性。特别是当数据量较大时，需要考虑分批次传输和断点续传机制。字段单位的规范化是关键，接口在接收数据时需进行单位校验与标准化，避免因单位不一致导致的质控错误。此外，由于涉及患者敏感信息，接口必须强制使用 HTTPS 协议，并实施严格的身份验证（如 `OAuth 2.0` 或 `Basic Auth`）和权限控制，确保数据传输的安全性与合规性。

## 配置怎么定

| 配置项                   | 建议取法                               | 这样取的依据                                       |
| :----------------------- | :------------------------------------- | :------------------------------------------------- |
| `requestTimeout`         | `60000 毫秒`                           | 应对复杂病历数据查询与处理可能耗时较长的情况       |
| `maxConnections`         | `50`                                   | 平衡并发处理能力与后端系统负载，按实际并发量调整   |
| `headers.Authorization`  | `Basic base64(username:password)`      | 满足医疗系统常用的 `Basic Auth` 鉴权要求           |
| `dataChunkSize`          | `1024 KB`                              | 优化大体积病历文档传输效率，避免单次请求过大       |
| `retryAttempts`          | `3`                                    | 应对网络波动或后端服务瞬时不可用，提高数据传输韧性 |
| `responseSchema`         | 按实际返回 JSON/XML 结构精确定义       | 确保数据解析的准确性，减少运行时错误               |

## 容易做错的三处

*   调用接口后，对话日志中的运行数据为空，原因是接口返回的数据格式与预设的 `responseSchema` 不匹配，导致数据解析失败。
*   批量执行节点调用大模型时，在线调试正常但 API 调用无法完成，现象是请求超时或返回 500 错误，原因可能是 API 调用的并发量超过了后端系统的处理上限，或 `requestTimeout` 设置过短。
*   获取对话记录列表接口返回的数据，无法明确哪个 AI 回复对应用户提问，原因是接口设计时未在响应体中包含明确的 `conversationId` 或 `messageId` 关联字段。

## 怎么确认配好了

*   通过 Postman 或类似工具，使用配置的 `HTTP Basic Auth` 凭证，模拟请求目标接口，检查是否能正常获取数据且返回状态码为 `200 OK`。
*   在 FastGPT 平台配置 HTTP 模块后，运行测试流程，观察日志输出，核对返回数据结构与字段值是否符合预期，特别是关键的诊断、检验结果字段。
*   部署到生产环境后，通过监控系统观察接口的平均响应时间 (`response_time`) 和错误率 (`error_rate`)，确保在高并发下仍能保持稳定。
