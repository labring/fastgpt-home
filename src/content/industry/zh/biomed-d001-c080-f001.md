# 眼科临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样

眼科临床试验预筛涉及的数据主要来源于电子病历系统、影像诊断系统以及基因检测报告。这些数据通常以非结构化文本、DICOM 格式图像和结构化表格形式存在。更新频率方面，患者病历数据可能实时更新，而影像数据和基因报告则在检查或分析完成后批量录入。文档结构上，电子病历包含主诉、现病史、既往史、家族史、检查结果等，字段繁多且存在大量自由文本描述。影像数据如 OCT、眼底照相则携带丰富的元数据。字段与单位方面，视力通常以 E 值或 Snellen 分数表示，眼压以 mmHg 为单位，视野检查结果以 dB 表示，这些都需精确解析。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

眼科数据的多模态特性要求 HTTP 接口具备处理复杂数据结构的能力，例如 DICOM 文件或高分辨率图像的传输与解析。实时或准实时的数据更新频率，特别是对于患者状态的变化，要求接口设计支持高并发和低延迟的数据同步机制，避免数据陈旧导致预筛结果偏差。电子病历中自由文本描述的普遍性，使得对自然语言处理的需求大幅增加，接口需要能有效传递非结构化文本，并支持后续的语义理解。此外，视力、眼压等专业字段的精确单位和格式要求，意味着接口在数据传输时必须确保字段类型和值的准确性，例如对 `IOP` 字段的 `mmHg` 单位进行严格校验，防止单位混淆或数据丢失。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `requestTimeout` | `60 秒` | 眼科影像文件传输及初步解析可能耗时较长，避免请求过早超时。 |
| `maxPayloadSize` | `100 MB` | 支持传输大型 DICOM 图像和复杂的电子病历数据。 |
| `contentType` | `application/json`, `multipart/form-data` | 兼顾结构化数据传输和多模态文件上传的需求。 |
| `concurrencyLimit` | `按实测标定` | 根据外部系统承载能力和预期数据量，避免过载。 |
| `retryAttempts` | `3 次` | 应对外部系统瞬时故障或网络波动，提高数据传输成功率。 |
| `dataValidationSchema` | `JSON Schema` | 确保传入 `patientId`、`IOP` 等关键字段的格式和单位符合预期。 |

## 容易做错的三处

*   HTTP 接口返回 `413 Payload Too Large` 错误，原因是传输的眼底照片或 OCT 图像文件大小超过了服务器配置的限制。
*   临床试验预筛结果中，患者的视力数据出现偏差，原因是对外部系统返回的 `VA` 字段未进行单位转换，导致单位不一致。
*   数据同步接口偶尔出现 `504 Gateway Timeout` 错误，这是由于批量处理电子病历数据时，单个请求处理时间过长，超出了网关的默认超时时间。

## 怎么确认配好了

*   通过模拟提交包含 DICOM 图像和结构化病历数据的请求，检查 HTTP 接口是否能正常接收并返回成功状态码。
*   随机抽取一批预筛数据，核对关键字段如 `ocularPressure`、`visualAcuity` 的值和单位是否与外部系统原始数据完全一致。
*   在高峰时段进行压力测试，观察接口的 `response time` 和 `error rate`，确保在高并发下数据传输稳定且无明显延迟。
