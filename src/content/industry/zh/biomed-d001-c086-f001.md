# 罕见病临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样
罕见病临床试验预筛的数据主要来源于全球和区域性的罕见病注册中心、医学文献数据库（如PubMed、Medline）、临床试验注册平台（如ClinicalTrials.gov、EU Clinical Trials Register）以及特定疾病患者组织的数据共享计划。这些数据更新频率不一，部分注册信息可能实时更新，而文献数据则随期刊发布周期更新，临床试验状态则依据试验进展定期更新。文档结构复杂多样，通常包含结构化字段（如疾病名称、基因突变、入排标准、药物名称、试验阶段、研究中心联系方式）和大量的非结构化文本（如试验方案描述、患者病例报告、不良事件记录）。字段方面，常涉及OMIM ID、Orphanet ID等罕见病特有编码，基因位点描述（如`HGVS`命名法），以及剂量单位（如`mg/kg`、`µg/mL`）等医学专业单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
罕见病数据来源分散且异构的特点，要求HTTP接口具备强大的多源数据聚合能力。非结构化文本内容丰富，使得对返回数据的解析和信息抽取成为关键环节，需要高级的自然语言处理（NLP）能力支撑。数据更新频率的不一致性，决定了外部系统调用接口时，既要支持实时查询，也要考虑周期性同步更新的机制，以保证预筛信息的时效性。字段的专业性和多样性，特别是罕见病特有的编码和医学单位，要求API设计时，对于数据类型和格式有严格的定义，并能有效处理单位转换或归一化问题。此外，由于数据可能涉及患者隐私，接口在数据传输和访问控制上必须符合HIPAA、GDPR等法规要求，确保数据安全。

## 配置怎么定

| 配置项                       | 建议取法                                 | 这样取的依据                                                               |
| :--------------------------- | :--------------------------------------- | :------------------------------------------------------------------------- |
| `requestTimeout`             | `600 秒`                                 | 罕见病数据查询复杂，可能涉及多个外部API调用和大量文本处理，需要更长的等待时间 |
| `maxConnections`             | `100`                                    | 同时处理多个患者预筛请求，保持较高的并发处理能力                           |
| `responseBodySizeLimit`      | `50 MB`                                  | 临床试验方案、文献摘要等可能包含大量文本，防止因响应体过大导致截断           |
| `retryAttempts`              | `3`                                      | 外部系统偶发性网络波动或服务不可用，增加重试机制提高成功率                 |
| `authenticationMethod`       | `OAuth2`                                 | 确保数据访问安全，遵循行业标准认证协议                                     |
| `extractFieldMappings`       | `{"OMIM ID": "$.omim_id", "基因突变": "$.gene_mutation_hgvs"}` | 精准提取特定罕见病相关标识和专业字段                                       |

## 容易做错的三处
*   HTTP 请求返回的链接缺少 `http://` 或 `https://` 前缀，导致前端无法直接点击跳转，原因通常是外部系统API返回的URL字段仅包含路径信息或相对路径。
*   API 调用时，工作流中已配置的变量未能正确传递或解析，导致返回数据中变量部分为空，通常是由于接口参数名称与外部系统要求不符，或数据类型不匹配。
*   知识库返回的阅读链接点击报错 `message: "Only support .txt, .m..."`，表明外部系统在处理文件类型时存在限制，而返回的链接指向了不支持的文件格式。

## 怎么确认配好了
*   对配置的HTTP接口发起模拟请求，核对返回的JSON结构中是否包含所有预期的罕见病相关字段，如`OMIM ID`、`gene_mutation_hgvs`。
*   检查日志输出，确认HTTP请求的`requestTimeout`和`retryAttempts`配置是否按预期生效，例如请求超时后是否触发重试。
*   通过API调用工作流，验证非结构化文本内容的抽取和处理是否准确，特别关注入排标准等关键信息的提取完整性。
*   测试返回的外部链接，确保所有链接均可正确访问，且文件类型符合系统支持范围。
