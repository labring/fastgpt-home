# 自身免疫临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样

自身免疫疾病的临床试验数据具有高度专业性和复杂性。数据源主要来自全球各国的临床试验注册中心（如 ClinicalTrials.gov、EU Clinical Trials Register）、药企内部数据库、医学文献以及患者登记系统。这些数据更新频率不一，注册中心数据通常按月或季度更新，而医学文献则持续发布。文档结构多样，包括结构化的试验方案、非结构化的研究报告、患者招募标准文本，以及包含生物标志物、基因型、疾病活动评分等多种数据类型的表格。字段特异性强，例如针对类风湿关节炎的 `DAS28-CRP` 评分、针对系统性红斑狼疮的 `SLEDAI` 指数，以及免疫抑制剂的剂量单位 `mg/kg` 或 `mg/day`。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

自身免疫临床试验数据的多样性和专业性，对 HTTP 接口与外部系统的集成带来了显著约束。首先，多源异构数据要求接口具备强大的数据解析能力，能处理 JSON、XML、HTML 等多种格式。其次，非结构化文本内容（如纳入/排除标准）需要通过自然语言处理技术提取关键信息，这增加了数据预处理的复杂性。再次，专业字段的规范化和统一是关键，例如 `SLEDAI` 指数可能存在不同版本，需要在接口层进行映射或版本识别。数据更新频率不一致，要求接口设计具备增量同步和全量同步的灵活策略。最后，数据量庞大且包含敏感信息，对接口的稳定性和安全性提出了更高要求，需要考虑认证、授权机制，以及错误处理和重试策略。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `60 秒` | 多数临床试验数据库响应较慢，需预留充足时间避免超时中断。 |
| `MAX_RETRIES` | `3 次` | 外部系统偶发性故障常见，适当重试机制可提高数据获取成功率。 |
| `AUTH_HEADER_NAME` | `Authorization` | 多数临床数据API采用标准OAuth2或API Key认证，此为通用头部。 |
| `DATA_PARSING_STRATEGY` | `JSON/XML 自动识别，HTML 结构化提取` | 应对多源异构数据格式，提高解析效率。 |
| `ERROR_RETRY_INTERVAL_SECONDS` | `5 秒` | 避免短时间内频繁重试对外部系统造成压力，留出恢复时间。 |
| `MAX_CONCURRENT_REQUESTS` | `10-20` | 根据外部API速率限制和系统资源，平衡并发与稳定性。 |

## 容易做错的三处

*   HTTP 请求返回 `401 Unauthorized` 错误，导致数据无法获取。这通常是由于 `Authorization` 头部中的令牌过期或格式不正确。
*   知识库检索结果传递到 HTTP 请求后，AI 对话未能正确引用相关信息。原因在于知识库引用字段与 HTTP 接口返回的数据字段不匹配，导致 AI 无法识别有效上下文。
*   外部系统接口返回 `500 Internal Server Error`，但 FastGPT 未能触发重试。这可能是 `MAX_RETRIES` 配置过低，或错误处理逻辑未将 `5xx` 错误码纳入重试范围。

## 怎么确认配好了

*   通过 FastGPT 的工作流测试功能，验证 HTTP 请求模块能够成功获取并解析来自 ClinicalTrials.gov 或其他指定临床数据库的试验方案数据。
*   检查 FastGPT 后台日志，确认在数据同步过程中，未出现 `HTTP_REQUEST_TIMEOUT_SECONDS` 或 `MAX_RETRIES` 相关错误信息，且数据解析无异常。
*   在 FastGPT 知识库中导入一部分自身免疫临床试验数据，并通过 AI 对话提问，核实 AI 能够引用并正确解释来自外部系统的数据字段（例如 `SLEDAI` 指数、药物名称），评估引用准确性。
