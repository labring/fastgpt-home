# 药物警戒临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样

药物警戒在临床试验预筛阶段的数据主要来源于临床试验方案、受试者病历、不良事件报告和实验室检查结果。这些数据以非结构化文本、半结构化表格和结构化数据库记录的形式存在。更新频率方面，不良事件报告具有实时性，可能随时产生；受试者病历和实验室检查结果通常在每次访视后更新，频率从数天到数周不等。文档结构方面，临床试验方案是规范性文本，包含试验设计、入选/排除标准等，通常以 PDF 格式存在。不良事件报告则可能包含自由文本描述、医学术语编码（如 MedDRA 编码）和发生时间。字段与单位的特殊性体现在医学术语的标准化、剂量单位（如 mg/kg、IU）、时间单位（如天、周、月）以及不良事件严重程度分级。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

药物警戒数据的多样性和更新频率对 HTTP 接口的设计提出了具体要求。实时性的不良事件报告需要支持高并发的事件推送机制，例如使用 Webhook 或轮询频率较高的 API 接口。非结构化文本数据，如受试者病历和不良事件描述，需要通过接口传输并支持后续的自然语言处理（NLP）分析。这要求接口能够处理较大的数据载荷，并且对文本编码有明确规定，通常是 UTF-8。半结构化和结构化数据则需要接口定义清晰的数据模型和字段，确保数据传输的准确性。例如，不良事件的 MedDRA 编码需要通过接口正确传递，以便后续的风险信号检测。此外，数据中的时间信息，如不良事件发生时间、报告时间，要求接口支持标准化的时间戳格式，例如 ISO 8601，以避免时区和格式转换问题。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `HTTP_REQUEST_TIMEOUT` | `600 秒` | 针对不良事件报告等可能包含大量自由文本的请求，需要预留足够的传输和处理时间。 |
| `MAX_PAYLOAD_SIZE_MB` | `50 MB` | 考虑到临床病历和不良事件报告可能包含较长的文本描述或附件，确保单次请求的数据载荷容量。 |
| `API_AUTHENTICATION_METHOD` | `OAuth 2.0` | 确保临床试验数据传输的安全性，OAuth 2.0 提供成熟的授权和认证机制。 |
| `WEBHOOK_RETRY_INTERVAL` | `10 秒` | 针对不良事件推送，若首次失败，应在短时间内重试以保证数据送达的及时性。 |
| `DATA_ENCODING` | `UTF-8` | 确保医学术语、患者描述等多种语言和特殊字符能够正确传输和解析。 |
| `DATE_FORMAT_STANDARD` | `ISO 8601` | 统一时间表示格式，避免因日期格式不一致导致的数据解析错误和时区问题。 |

## 容易做错的三处

*   HTTP 接口返回 `400 Bad Request` 状态码，并提示“字段缺失或格式错误”。原因通常是外部系统在发送不良事件报告时，未按照接口文档要求提供所有必填字段，或者某个字段的值不符合预期的数据类型或枚举范围，例如将 `MedDRA_CODE` 字段留空。
*   外部系统推送数据后，FastGPT 中未见相关数据更新，或者数据更新延迟。原因可能是 Webhook 配置的回调 URL 不正确，导致事件通知未能送达；或者外部系统推送的频率过高，超出了 FastGPT 接口的处理能力，导致部分请求被丢弃或排队。
*   查询接口返回的数据条数少于预期，或者某些关键字段的值为空。原因可能是接口在处理复杂查询条件时，对医学术语的匹配不够精确，导致部分相关数据被过滤；或者数据源系统在同步时，某些非必填字段的数据未能成功传输，导致 FastGPT 接收到的数据不完整。

## 怎么确认配好了

*   通过 FastGPT 的接口测试工具，模拟发送一个包含完整药物警戒数据的 HTTP POST 请求，检查返回状态码是否为 `200 OK`，并验证响应体中是否有成功处理的提示。
*   在 FastGPT 知识库中，通过关键字搜索测试数据中包含的医学术语或受试者标识符，确认数据是否已成功摄入并可被检索，并检查关键字段（如 `ADVERSE_EVENT_TERM`、`ONSET_DATE`）的值是否与发送时一致。
*   配置一个外部系统 Webhook，模拟触发一次不良事件报告推送，然后检查 FastGPT 内部日志或相关模块中是否有接收到该事件的记录，并确认数据内容无误。
*   针对预期高频更新的数据源，例如实验室检查结果，连续观察一段时间内 FastGPT 知识库中相关数据的更新频率和及时性，确保与外部系统的同步机制符合预期。
