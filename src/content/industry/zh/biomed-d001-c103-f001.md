# 零售连锁临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样
零售连锁的临床试验预筛数据主要来源于其门店销售系统、会员管理系统和线上预约平台。这些数据通常以结构化的形式存储，例如 JSON 或 XML，包含患者的年龄、性别、过往病史（通过销售记录中的药品购买推断）、体征数据（如部分门店提供的自助检测结果）以及联系方式。数据更新频率较高，门店销售数据可能实时同步，会员信息则在每次交互后更新。文档结构方面，通常遵循零售行业的数据交换标准，字段命名直观，例如 `patientID`、`age`、`gender`、`medicationHistory`。单位方面，年龄以“年”为单位，体重以“千克”为单位，血压数据则以“毫米汞柱”为单位，均有明确定义。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
零售连锁数据的高更新频率要求 HTTP 接口具备高并发处理能力，以避免数据积压和延迟。结构化数据特性使得接口设计可以更侧重于精确的字段映射和数据校验。由于数据来源于多个系统，接口需要支持多种认证方式，例如 API Key 或 OAuth 2.0，确保数据传输的安全性。数据字段的标准化有助于 FastGPT 在接收数据时进行准确的解析和实体识别。同时，考虑到数据量可能较大，接口响应时间需要优化，并可能需要支持分页或增量同步机制。对于潜在的敏感健康数据，接口必须严格遵守数据隐私法规，例如传输加密和访问控制。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `API_KEY_HEADER` | `X-Retail-API-Key` | 零售连锁常用自定义头部认证方式 |
| `BATCH_SIZE` | `500` | 平衡单次请求数据量与服务器处理能力 |
| `REQUEST_TIMEOUT_SECONDS` | `60 秒` | 多数零售系统接口响应时间在 30-45 秒 |
| `MAX_RETRY_ATTEMPTS` | `3` | 应对网络波动或临时服务不可用 |
| `DATA_FORMAT` | `JSON` | 零售连锁系统主流数据交换格式 |
| `ERROR_LOG_LEVEL` | `WARNING` | 详细记录非致命错误，便于问题定位 |

## 容易做错的三处
*   接口返回 `401 Unauthorized` 错误，原因在于 `API_KEY_HEADER` 配置的键名与外部系统实际要求的认证头部不匹配。
*   部分患者信息字段（例如 `medicationHistory`）为空，原因可能为外部系统接口返回的数据结构与 FastGPT 预期不符，导致解析失败。
*   数据同步缓慢或超时，现象可能为 `REQUEST_TIMEOUT_SECONDS` 设值过低，未能充分考虑外部系统处理批量请求的耗时。

## 怎么确认配好了
*   执行一次小批量数据同步，检查 FastGPT 控制台日志，确认没有出现 `4XX` 或 `5XX` 状态码的接口错误。
*   从外部系统中随机抽取 5-10 条记录，比对 FastGPT 中对应知识库条目的字段值，确认数据完整且格式正确。
*   模拟高并发请求，观察 FastGPT 的资源使用情况和接口响应时间，确保在预期负载下系统稳定运行。
