# 靶点发现临床试验预筛的HTTP 接口与外部系统

## 这个品类的数据长什么样

靶点发现的数据通常来源于公开的生物医学数据库（如ChEMBL、DrugBank、Target Validation Platform）、学术文献、专利信息以及内部实验数据。这些数据更新频率不一，公开数据库可能按季度或半年更新，文献和专利则实时涌现。数据结构复杂，包含蛋白质序列、基因表达谱、小分子化合物结构、生物活性数据、疾病关联信息等。字段类型多样，涉及文本描述、数值（如IC50、Ki值）、枚举（如作用机制类型）、链接（指向其他数据库）。单位标准化程度不一，例如活性数据可能使用纳摩尔（nM）或微摩尔（µM），结构数据则以SMILES或InChI编码呈现。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

靶点发现数据的多样性和复杂性要求HTTP接口具备灵活的数据解析能力，以适应不同数据源的格式差异。更新频率的不确定性，使得接口设计需要考虑增量更新和全量同步的策略，避免重复处理大量不变数据。多字段、多单位的特点，对数据映射和标准化提出了挑战，需要在接口调用时进行精确的字段匹配与单位转换。例如，化合物活性数据可能需要统一为纳摩尔以便后续计算。此外，大量结构化和非结构化混合数据，要求接口能处理复杂的JSON或XML结构，甚至直接处理文本描述，并能有效利用外部计算资源进行分子结构分析或文本挖掘。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `requestTimeout` | `120 秒` | 靶点数据查询可能涉及复杂计算或多源聚合，需要更长的等待时间。 |
| `maxConnections` | `10` | 考虑到外部数据库的访问频率限制和内部资源消耗，平衡并发请求数量。 |
| `headers.Content-Type` | `application/json` 或 `text/xml` | 外部API通常要求明确的数据格式声明，确保数据解析正确。 |
| `retryAttempts` | `3` | 针对网络波动或外部服务瞬时故障，提供自动重试机制。 |
| `responseBodyMaxSize` | `50 MB` | 靶点相关数据（如基因表达谱、化合物结构）响应体可能较大，需要足够的缓冲区。 |
| `paramMap.target_id` | `target_gene_id` | 确保内部系统字段与外部API参数的精确映射，例如将内部基因ID映射为外部靶点ID。 |

## 容易做错的三处

*   HTTP请求超时，现象为长时间无响应或`connection timed out`错误。原因在于未根据靶点数据查询的复杂度和外部服务响应时间，合理设置`requestTimeout`参数。
*   外部系统返回数据解析失败，现象为JSON解析错误或字段缺失。原因在于外部API返回的数据格式或字段名称与预期不符，未在`paramMap`或解析逻辑中进行适配。
*   账户认证失败，现象为`401 Unauthorized`或`403 Forbidden`状态码。原因在于API密钥或凭证未正确配置或已过期，或者`headers.Authorization`字段格式不符合外部系统要求。

## 怎么确认配好了

*   通过模拟请求，验证HTTP状态码是否为`200 OK`，确保外部接口可达且认证通过。
*   检查返回的响应体结构，验证关键字段（如`target_name`、`compound_id`、`activity_value`）是否存在且数据类型正确。
*   针对不同查询参数组合进行测试，确保在各种输入条件下都能获取到预期的数据子集。
*   监控接口调用日志，核对请求参数、响应时间以及潜在的错误信息，确认接口运行稳定。
