# CRO产品的表单与交互

## 这个品类的数据长什么样
CRO（合同研究组织）产品的数据通常具有高度专业性和结构化特点。数据来源包括临床试验方案、受试者病例报告表（CRF）、实验室检测结果、生物样本信息、药品批次记录以及药政审批文件等。这些数据更新频率高，尤其在临床试验进行期间，实时性要求强。文档结构复杂，常涉及多种标准数据格式，如CDISC（临床数据交换标准协会）标准下的SDTM（提交数据制表模型）和ADaM（分析数据集模型）。字段与单位极为严谨，例如剂量以毫克（mg）或微克（μg）为单位，时间点以小时（h）、天（d）或周（w）表示，生物指标则有特定的国际单位（IU）或浓度单位（如ng/mL）。数据内部逻辑关联性强，需严格遵循医学伦理和法规要求。

## 这些特征在「表单与交互」这一环带来什么约束
CRO产品数据的专业性和结构化特性，对表单与交互设计施加了多重约束。高更新频率要求表单能够支持实时数据录入与查询，并提供版本控制能力，以追踪数据变更历史。复杂的文档结构和标准数据格式，意味着表单字段需要精确映射到CDISC等标准，避免数据歧义。字段与单位的严谨性，要求表单输入框具备严格的数据校验机制，例如对数字范围、单位选择和格式进行限制，防止录入错误。数据内部的强关联性，促使表单需支持联动逻辑，如根据药物批次自动填充生产日期，或根据受试者ID查询其既往病史。同时，法规遵循要求表单在数据收集过程中，需嵌入知情同意、隐私保护声明等交互元素，并确保所有操作可审计。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `2000 字符` | 适应CRO产品描述通常较长，包含技术细节和实验方法 |
| `分段长度` | `500 字符` | 确保知识库分段能包含完整实验步骤或试剂说明 |
| `召回条数` | `8 条` | 提高从海量CRO文档中获取相关信息的覆盖率 |
| `相似度阈值` | `0.75` | 保证召回结果与用户查询的生物医药术语高度相关 |
| `WORKFLOW_MAX_RUN_TIMES` | `500` | 应对CRO咨询中可能涉及多轮次数据查询和逻辑判断 |
| `UPLOAD_FILE_MAX_SIZE` | `200 MB` | 允许上传大型临床试验报告、SOP或产品说明书 |

## 容易做错的三处
*   表单提交后，部分关键字段为空，原因是字段配置时未设置必填校验或默认值引用变量失败。
*   用户在免登录页面进行语音输入时，有时会出现延迟或输入内容不显示，原因为语音识别服务响应超时或前端交互逻辑未正确处理异步回调。
*   查询结果中某些生物指标的单位错误，原因是数据导入时未进行单位标准化转换，或表单校验规则未覆盖所有可能的单位表示。

## 怎么确认配好了
*   在实际环境中模拟提交多种典型CRO产品咨询表单，验证所有必填字段均能正确收集数据，且数据类型与格式符合预期。
*   测试不同复杂度的CRO产品查询场景，检查知识库召回结果的相关性，确保召回条目能准确命中关键技术参数和实验方法。
*   对包含特殊字符、长文本或大文件的CRO文档进行上传与处理测试，确认系统能稳定解析并提取核心信息，无超时或解析失败报错。
