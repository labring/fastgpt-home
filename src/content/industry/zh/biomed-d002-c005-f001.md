# CSO产品的HTTP 接口与外部系统

## 这个品类的数据长什么样
CSO（Contract Sales Organization）产品的数据主要围绕医药代表的销售活动、客户关系管理及药品流转信息展开。数据源头多样，包括 CRM 系统、销售报表、医药电商平台、第三方市场调研报告等。更新频率受业务流程影响，销售数据通常按天或周更新，库存和物流信息可能实时变动。文档结构多变，销售合同、产品说明书、培训材料等通常以 PDF、Word 或结构化的 JSON/XML 格式存在。字段方面，特有字段包括 `rep_id`（代表ID）、`territory_code`（区域编码）、`product_sku`（产品SKU）、`sales_volume`（销售量）、`target_physician_id`（目标医生ID）。单位涉及 `盒`、`片`、`毫克`、`元`、`百分比` 等，且不同产品或销售区域可能存在单位换算规则。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
CSO产品数据来源的复杂性，要求 HTTP 接口具备高度的灵活性，能够对接多种数据格式。销售数据的高更新频率，使得接口设计时需考虑增量同步机制，避免全量拉取造成的资源浪费和响应延迟。不同文档格式的存在，对外部系统的解析能力提出要求，需要支持 PDF、DOCX 等非结构化文档的预处理，并从中提取关键实体信息。特有字段如 `product_sku` 和 `target_physician_id` 意味着在进行数据映射和查询时，需要精确的字段匹配和类型转换，尤其是在跨系统集成时，确保数据一致性。单位的多元性和换算规则，则要求在数据传输和展示前进行标准化处理，防止因单位不统一导致的数据误解或计算错误。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `60 秒` | 应对外部系统响应慢或数据量大时的传输时间，防止因超时中断 |
| `MAX_BODY_SIZE_MB` | `20 MB` | 适应包含图片、复杂报表等大尺寸请求或响应体 |
| `API_KEY_HEADER_NAME` | `X-CSO-Auth` | 遵循行业惯例，使用自定义头字段传递鉴权凭证 |
| `DATA_SYNC_FREQUENCY_CRON` | `0 0 */1 * *` | 每日凌晨同步核心销售数据，平衡数据时效性与系统负载 |
| `JSON_SCHEMA_VALIDATION_ENABLED` | `true` | 确保接收到的 CSO 数据符合预期结构，避免脏数据影响后续处理 |
| `RETRY_STRATEGY` | `指数退避，最大 5 次` | 应对外部系统偶发性故障，提高数据传输的稳定性 |

## 容易做错的三处
*   API 调用频繁返回 `401 Unauthorized` 错误，原因在于 `API_KEY` 未正确配置或过期，或请求头中认证信息格式不符合外部系统要求。
*   工作流通过 API 调用上传文件后，提示 `文件解析失败`，原因是文件类型不在外部系统支持范围内，或文件内容编码与预期不符。
*   从外部系统拉取到的销售量数据与业务报表不一致，原因是 `sales_volume` 字段在不同系统中单位不统一，未进行必要的单位换算。

## 怎么确认配好了
*   通过 `curl` 命令或 Postman 等工具，模拟 API 请求，检查能否成功获取到指定 `product_sku` 的产品信息，并验证返回的 `sales_volume` 字段值和单位是否正确。
*   配置一个包含文件上传步骤的工作流，执行后检查外部系统是否能正确接收并解析上传的销售合同 PDF 文件，以及是否能从中提取出 `contract_id` 等关键信息。
*   在 FastGPT 中配置一个定时同步任务，观察任务日志，确认 `HTTP_REQUEST_TIMEOUT_SECONDS` 内接口调用是否成功，以及 `DATA_SYNC_FREQUENCY_CRON` 设定的频率下数据是否按时更新。
