# GMP 合规产品的HTTP 接口与外部系统

## 这个品类的数据长什么样
GMP 合规产品的数据主要来源于生产批记录、质量检测报告、设备校验记录、偏差调查报告、CAPA（纠正与预防措施）文件等。这些数据通常以结构化文档（如 PDF、Word、Excel）或半结构化数据（如 LIMS 系统导出的 CSV 文件）形式存在。数据更新频率因具体环节而异，生产批记录随批次完成而生成，质量检测报告随检验结果出具，而 CAPA 报告则可能在较长周期内持续更新。文档结构严谨，字段与单位标准化程度高，例如批号、生产日期、有效期、检验项目、检验结果、判定标准、偏差描述、根本原因分析、改进措施等，各字段均有明确的定义和计量单位，如 `mg/L`、`pH`、`°C`、`%`。数据完整性、准确性和可追溯性是 GMP 合规的核心要求，通常包含时间戳、操作员签名等审计追踪信息。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
GMP 合规数据的严格性和高可追溯性，对 HTTP 接口与外部系统提出了特定的约束。由于数据通常以文档形式存在，接口设计需要重点考虑文件上传、解析和结构化提取能力，以应对多样化的文档格式。更新频率的差异要求接口具备灵活的触发机制，既能支持实时数据同步（如 LIMS 结果），也能适应周期性或事件驱动的数据更新（如批记录归档）。字段与单位的高度标准化，意味着在数据传输和接收时，必须进行严格的数据类型校验和单位一致性检查，确保数据的准确性不被破坏。此外，数据的完整性和审计追踪要求，使得接口在处理数据时，需要保留原始数据来源信息，并可能需要支持数字签名或哈希校验，以保证数据的不可篡改性。接口的响应速度和稳定性也至关重要，因为任何数据处理延迟或失败都可能影响合规性评估流程。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `50 MB` | 考虑到GMP文档可能包含大量图片或扫描件，确保能上传大型文件。 |
| `MAX_RETRIES_ON_FAILURE` | `3 次` | 应对网络瞬时波动或外部系统偶发故障，增加数据传输的鲁棒性。 |
| `HTTP_REQUEST_TIMEOUT` | `60 秒` | 多数外部系统处理请求的时间，避免因等待过久导致超时。 |
| `BATCH_PROCESS_SIZE` | `10 条记录` | 平衡处理效率与系统负载，尤其适用于批量上传检测报告。 |
| `AUTH_TOKEN_EXPIRY_BUFFER` | `5 分钟` | 在令牌实际过期前进行刷新，避免因令牌过期导致的认证失败。 |
| `ERROR_NOTIFICATION_RECIPIENT` | `合规团队邮箱` | 确保接口调用失败时，相关团队能及时收到通知并介入处理。 |

## 容易做错的三处
*   现象：外部系统接收到的字段为空或类型不匹配。原因：HTTP 请求体中的 JSON 字段名与外部系统预期的字段名不一致，或者数据类型（如字符串与数字）未正确转换。
*   现象：文件上传后外部系统无法识别或解析。原因：文件编码或格式与外部系统支持的类型不符，或者未正确设置 `Content-Type` HTTP 头。
*   现象：接口调用频繁出现 `401 Unauthorized` 错误。原因：`tokenLogin` 接口获取的认证令牌过期，但未在后续请求中及时刷新或重新获取。

## 怎么确认配好了
*   上传一份包含标准字段和单位的 GMP 批记录文档，检查外部系统是否完整、准确地接收并解析了所有关键信息。
*   模拟网络中断或外部系统短暂离线，验证接口的重试机制是否按预期工作，并在恢复后数据是否成功同步。
*   检查外部系统或 FastGPT 内部日志，确认 HTTP 请求的响应时间在可接受范围内，且没有出现非预期的错误码。
*   上传一个超过 `UPLOAD_FILE_MAX_SIZE` 限制的文件，确认系统能正确返回文件大小超限的错误提示。
