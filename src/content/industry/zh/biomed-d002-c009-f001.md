# II-III 期临床产品的HTTP 接口与外部系统

## 这个品类的数据长什么样
II-III 期临床试验数据主要来源于全球各地的临床研究机构、CRO 公司及制药企业的内部数据库。这些数据包含患者入组信息、用药记录、不良事件报告、实验室检查结果、影像学数据和访视记录等，结构复杂且多模态。数据更新频率较高，尤其是在试验进行中，实时产生的大量数据需要持续同步。文档通常遵循 ICH GCP 规范，包括试验方案、知情同意书、CRF 表格、SAE 报告等。字段名和单位严格遵循医学标准，例如剂量单位 `mg/kg`，时间点记录 `D+n`，不良事件编码使用 `MedDRA` 术语。数据的完整性、准确性和可追溯性是核心要求。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
II-III 期临床数据的复杂性和高更新频率，对 HTTP 接口的设计和外部系统集成提出了严格要求。数据量庞大，需要支持高效的分页查询和增量同步机制，以避免单次请求过载。多模态数据意味着接口需要支持不同格式的数据传输，例如结构化 JSON 用于患者信息，二进制流用于影像文件。严格的合规性要求数据传输必须加密，并具备身份验证和授权机制。字段的标准化和单位的一致性，要求接口在数据解析时进行严格校验，避免因数据格式不匹配导致错误。高更新频率则要求外部系统具备定时拉取或事件驱动的推送能力，确保 FastGPT 内部知识库的时效性。

## 配置怎么定

| 配置项                   | 建议取法       | 这样取的依据                               |
| :----------------------- | :------------- | :----------------------------------------- |
| `requestTimeout`         | `60000 毫秒`   | 适应复杂查询和大数据量传输，避免因超时中断 |
| `maxConnections`         | `20`           | 应对高并发请求，确保数据同步效率         |
| `authType`               | `Bearer Token` | 行业标准认证方式，提供较高安全性           |
| `maxRetryAttempts`       | `3`            | 处理瞬时网络波动或服务暂时不可用           |
| `chunkSize`              | `5000 字符`    | 优化长文本切分，保持语义完整性             |
| `metadataFields`         | `trial_id, patient_id, visit_date` | 确保关键元数据随内容导入，便于检索和溯源 |

## 容易做错的三处
- 调用外部接口时返回 `401 Unauthorized` 错误，原因在于 `Bearer Token` 未正确配置或已过期。
- 数据同步时出现 `504 Gateway Timeout`，这通常是由于 `requestTimeout` 设置过短，无法完成大数据量的传输。
- 外部文件上传后，FastGPT 中无法检索到期望内容，现象为 `content` 字段为空，这是由于 `PARSE_FILE_TIMEOUT_SECONDS` 过短，未能在规定时间内完成文件解析。

## 怎么确认配好了
- 通过 FastGPT 后台的“外部服务”测试功能，模拟一次数据拉取或推送，观察响应状态码是否为 `200 OK`。
- 检查 FastGPT 知识库中导入的数据，确保关键字段如 `trial_id`、`patient_id` 等均已正确解析并存储。
- 上传一份包含复杂结构和多种数据类型（如文本、数字、日期）的临床文档，确认其内容和元数据均能被准确识别和索引。
