# IVD 诊断试剂产品的工具调用与插件

## 这个品类的数据长什么样
IVD 诊断试剂产品的数据来源广泛，涵盖官方注册文件、产品说明书、技术白皮书、临床性能评估报告以及市场宣传资料。这些数据更新频率不一，新产品上市、批次更新或法规修订都可能引发数据变动。文档结构通常高度标准化，包含产品名称、注册证号、生产企业、适用范围、检测原理、预期用途、主要组成成分、储存条件、有效期、检验方法、结果判读、局限性等字段。其中，注册证号 (`Registration_Number`)、批号 (`Batch_Number`)、有效期 (`Expiration_Date`) 是核心标识。单位方面，试剂浓度通常以 `mol/L`、`mg/mL` 表示，检测限以 `IU/mL` 或 `ng/mL` 表示，温度以 `℃` 或 `K` 表示，时间以 `min`、`h` 或 `day` 表示。

## 这些特征在「工具调用与插件」这一环带来什么约束
IVD 诊断试剂数据的高度结构化和标准化，使得工具调用在参数解析和结果映射时有明确的参照。例如，通过注册证号可以精准检索到特定产品的详细信息。数据更新的不规律性，特别是涉及到批次信息和有效期，要求工具调用机制能够支持实时或近实时的数据查询，避免使用过期信息。文档中大量的专业术语和计量单位，要求插件在处理自然语言查询时，能够准确理解并映射到对应的字段和数值，例如将“储存温度”识别为 `Storage_Temperature` 字段。此外，由于医疗器械的严谨性，任何对产品信息的查询都必须确保准确性和可追溯性，这要求工具调用在数据源选择和错误处理上具备高可靠性。

| `PARSE_FILE_TIMEOUT_SECONDS` | `60` 秒                                | 适应 IVD 试剂说明书可能包含的图片和复杂表格解析时间。                            |

## 容易做错的三处
*   调用外部 HTTP 服务时，即使参数被正确解析，实际执行可能因请求头 `Content-Type` 不匹配或 `Authorization` 令牌过期而失败，导致服务无响应。
*   多模态图片识别在通过 `base64` 编码调用接口时，若 `base64` 字符串过长或格式不正确，可能导致 `413 Payload Too Large` 错误或解码失败。
*   HTTP 插件配置了代理，但代理服务器不支持 `HTTPS` 协议，导致访问 `HTTPS` 目标资源时连接超时或握手失败。

## 怎么确认配好了
*   对常见的 IVD 诊断试剂产品名称、注册证号进行查询，核对返回的产品名称、生产企业、适用范围是否与官方数据一致。
*   尝试查询包含批号和有效期信息的试剂，检查工具调用是否能准确返回实时或最新的批次信息，并验证有效期是否正确。
*   模拟用户咨询“某试剂的储存温度”，确认工具能正确解析意图，并通过工具调用返回 `Storage_Temperature` 字段的数值和单位。
*   检查工具调用日志，确保 HTTP 请求状态码为 `200`，且参数 `Registration_Number` 或 `Batch_Number` 等关键字段在请求中被正确传递。
