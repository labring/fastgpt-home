# IVD 诊断试剂产品的表单与交互

## 这个品类的数据长什么样

IVD（体外诊断）诊断试剂的数据来源多样，包括产品说明书、技术文档、检测报告、注册证信息以及临床验证数据。这些数据通常以结构化（如数据库记录、XML文件）和非结构化（如PDF文档、图片）混合的形式存在。数据更新频率较高，特别是新产品上市、批次更新、性能优化或监管要求变化时。文档结构标准化程度不一，但核心字段如产品名称、型号、批号、生产企业、注册证号、预期用途、检测原理、检测范围、精密度、准确度、特异性、灵敏度、储存条件、有效期、注意事项等较为固定。部分性能指标字段常带有特定单位，如 `ng/mL`、`IU/L`、`%`、`mol/L`，且常包含范围或阈值。

## 这些特征在「表单与交互」这一环带来什么约束

IVD 诊断试剂数据的多来源和混合结构，要求表单设计能够灵活处理不同类型的信息录入。高更新频率意味着知识库内容需要频繁同步与更新，表单提交后可能需要触发后台验证流程，以确保信息的时效性与准确性。文档结构的不一致性，使得在表单中直接引用或解析特定字段时，需要更强的容错机制或预处理步骤。大量包含单位和范围的性能指标，要求输入控件支持数值范围校验、单位自动转换或提示，避免用户输入错误。长篇幅的产品说明书和技术文档，可能导致知识库检索时面临上下文过长的问题，需要优化分段策略和召回机制。此外，对注册证号等关键信息的严格性要求，表单交互中需提供即时的数据格式校验和重复性检查。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `3000 Tokens` | IVD 产品说明书信息密度高，需保证足够上下文捕获关键信息，兼顾响应速度。 |
| `分段长度` | `500 字符` | 确保每个分段包含完整的产品特性或检测方法描述，避免关键信息被截断。 |
| `召回条数` | `前 8 条` | 提高从知识库中检索到相关技术参数、注意事项或注册信息的概率。 |
| `相似度阈值` | `0.78` | 确保召回结果与用户查询高度相关，减少不准确的试剂信息。 |
| `重排返回条数` | `前 3 条` | 在高召回率基础上，进一步精选最相关且权威的产品资料或技术文档。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 考虑到大型 PDF 说明书解析时间，预留充足处理时长防止超时失败。 |

## 容易做错的三处

*   现象：用户提交的注册证号或批号未能匹配到任何产品，系统返回“未找到匹配项”。原因：表单输入字段未进行严格的格式校验或模糊匹配，导致用户输入与知识库存储格式不符。
*   现象：用户咨询特定试剂的性能指标，返回结果中缺少单位或数值范围，导致信息不完整。原因：知识库在录入或解析文档时，未将数值型字段的单位和范围作为独立属性抽取，或在表单展示时未正确渲染。
*   现象：用户输入的咨询内容篇幅过长，导致系统响应缓慢或返回不相关信息。原因：知识库的文本切分策略不当，未能有效处理长文本的语义边界，或检索算法对长查询的权重处理不佳。

## 怎么确认配好了

*   选择不同复杂度的 IVD 试剂产品说明书，通过表单提交并观察知识库解析结果，核对关键字段（如注册证号、预期用途、检测原理）是否准确抽取。
*   模拟用户咨询，输入包含产品型号、批号、性能指标等信息的查询，检查返回结果是否准确、完整，并验证关键数值是否带有正确单位。
*   针对知识库中存在多个版本或批次的试剂产品，测试查询能否区分不同版本，并返回对应批次的准确信息。
*   检查表单提交后的日志，确认 `PARSE_FILE_TIMEOUT_SECONDS` 等参数是否在预期范围内，且没有出现解析失败或超时错误。
