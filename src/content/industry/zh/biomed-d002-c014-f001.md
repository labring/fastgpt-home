# siRNA 核酸药产品的HTTP 接口与外部系统

## 这个品类的数据长什么样

siRNA 核酸药的数据主要来源于生物信息学数据库（例如 NCBI Gene、miRBase、DrugBank）、专利数据库、临床试验注册平台（如 ClinicalTrials.gov）以及科研文献。数据更新频率较高，尤其是在新靶点发现、修饰技术进展或临床试验结果发布后。文档结构通常包含靶基因信息、siRNA 序列、化学修饰、递送系统、作用机制、药代动力学（ADME）参数、毒理学数据以及临床前/临床试验状态。字段方面，除了通用药物信息，还会涉及核酸序列特异性字段（如 `sense_strand_sequence`、`antisense_strand_sequence`）、化学修饰位点（如 `2'-O-methyl`、`phosphorothioate`）、靶点结合亲和力（`Kd` 值）、脱靶效应预测、体内外稳定性数据。单位上，序列长度以碱基对（bp）计，浓度常用 nM 或 µM，结合亲和力常以 nM 或 Kd 值表示。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

siRNA 核酸药数据来源分散且更新频繁，要求 HTTP 接口具备高并发处理能力和灵活的数据同步机制。序列数据和修饰信息通常以长字符串形式存在，可能导致请求体或响应体较大，需要关注 `payload_size` 限制。靶点结合亲和力、脱靶效应等数值型数据需要精确解析，避免浮点数精度丢失。多源数据整合时，不同数据库的字段命名和单位可能存在差异，需要通过 `schema_mapping` 进行统一。此外，由于药物研发数据的敏感性，接口的安全认证和授权机制（例如 `OAuth2` 或 `API_KEY` 验证）至关重要。临床试验状态的动态性要求接口能支持 `webhook` 推送或定时拉取，以确保信息实时性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `request_timeout` | `60 秒` | 生物信息学数据库接口响应时间可能较长，尤其在查询复杂序列或大批量数据时。 |
| `max_retries` | `3` | 外部系统可能因网络波动或服务器负载出现瞬时错误，适当重试可提高成功率。 |
| `max_connections` | `50` | 应对多源数据并发请求，平衡系统资源与数据获取效率。 |
| `payload_max_size` | `10 MB` | 考虑到 siRNA 序列、修饰信息及相关元数据可能形成较大的 JSON 或 XML 请求/响应体。 |
| `auth_method` | `API_KEY` 或 `OAuth2` | 大多数生物医药数据库和内部系统采用这两种主流认证方式，确保数据访问安全。 |
| `polling_interval` | `3600 秒` | 对于临床试验状态等更新频率中等的数据，以小时为单位定时拉取可以保持数据相对新鲜。 |

## 容易做错的三处

*   调用接口时收到 `413 Payload Too Large` 错误，原因是请求体中包含了过长的 siRNA 序列或批量数据，超出了服务器允许的最大载荷。
*   解析响应数据时发现 `Kd` 值或 `IC50` 值出现精度丢失或格式错误，原因是没有正确配置浮点数解析规则或未处理不同源系统的小数表示差异。
*   外部系统状态更新后，FastGPT 未能及时反映，原因是没有配置 `webhook` 监听或定时拉取任务的 `polling_interval` 过长。

## 怎么确认配好了

*   通过模拟请求，验证 `request_timeout` 设置是否能有效处理外部系统慢响应，并观察超时错误是否能被捕获。
*   检查日志中是否有 `400 Bad Request` 或 `URIError: URI malformed` 报错，并核对请求体结构和 URL 编码是否符合外部系统 API 文档要求。
*   针对包含序列或数值型数据的接口，进行多组请求测试，比对响应数据与原始数据源，确认 `schema_mapping` 和数据解析的准确性。
*   配置 `webhook` 或定时拉取任务后，手动更新外部系统数据，观察 FastGPT 中数据同步的时间延迟，并根据业务需求调整 `polling_interval`。
