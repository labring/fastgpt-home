# 临床决策支持产品的HTTP 接口与外部系统

## 这个品类的数据长什么样
临床决策支持系统的数据核心是医学证据与患者诊疗信息。数据来源多样，包括医学指南、临床研究文献、药品说明书、基因测序报告、影像学报告、以及电子病历中的结构化和非结构化数据。数据更新频率高，尤其涉及新药上市、治疗方案更新或疾病流行病学变化时。文档结构复杂，常包含大量医学术语、缩写和特定编码体系（如 ICD-10、SNOMED CT）。字段方面，除常规的患者人口学信息外，还涉及大量的临床指标（如实验室检查结果、生命体征）、诊断编码、治疗方案编码、用药剂量与频次、不良反应事件等。单位严格遵循国际标准，如 mmol/L、mg/dL、IU/mL 等，对于特定基因表达或蛋白质含量，可能使用更专业的单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
临床决策支持的数据特性对HTTP接口与外部系统集成提出了明确要求。高更新频率意味着接口需要支持增量更新机制，并具备数据版本管理能力，以确保决策依据的时效性。复杂的数据结构和专业术语要求接口具备强大的数据解析能力，能处理嵌套 JSON 或 XML 结构，并对医学术语进行标准化映射。严格的单位规范要求接口在数据传输过程中保持单位一致性，并提供必要的单位转换功能，避免因单位差异导致的决策错误。此外，由于涉及敏感的患者健康信息，接口必须采用强加密措施（如 HTTPS），并实施严格的身份验证和授权机制，确保数据传输的安全性与合规性。数据量通常较大，对接口的响应速度和并发处理能力有较高要求。

## 配置怎么定

| 配置项                   | 建议取法                               | 这样取的依据                                                               |
| :----------------------- | :------------------------------------- | :------------------------------------------------------------------------- |
| `maxContext`             | `4096`                                 | 临床决策通常涉及大量上下文信息，确保模型能处理完整的病例描述和相关证据。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`                               | 处理大型医学文献或报告可能耗时较长，预留充足解析时间。                   |
| `分段长度`               | `800–1200 字符`                        | 平衡文本语义完整性与召回效率，避免过度切分导致语义丢失。                 |
| `召回条数`               | `前 10–15 条`                          | 确保能召回足够多相关的医学证据，提高决策准确性。                         |
| `相似度阈值`             | `0.75–0.85`                            | 平衡召回的精准度与覆盖度，过滤不相关信息。                               |
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `120 秒`                               | 外部医学知识库接口响应可能较慢，防止过早超时。                           |

## 容易做错的三处
*   现象：API 调用返回 `HTTP 500` 错误，或 `{"error": "invalid_api_key"}`。
    原因：外部系统接口的认证信息（如 API Key 或 Token）配置错误或已过期。
*   现象：AI 回答中引用的医学数据不准确或过时，但外部接口返回状态码为 `200 OK`。
    原因：外部数据源提供了旧版本数据，而系统未配置或未成功触发增量更新机制。
*   现象：调用外部接口后，返回的 JSON 字段为空或缺失关键医学指标。
    原因：请求参数中的字段名与外部接口的期望字段名不匹配，或外部系统返回的数据结构与预期不符。

## 怎么确认配好了
*   对核心医学术语进行多轮查询，验证 AI 回答中引用的外部数据是否最新且准确。
*   模拟多种临床场景，观察系统对复杂病例的决策支持能力，并与专家意见进行比对。
*   检查系统日志，确认与外部知识库的 HTTP 请求和响应状态码均为 `200 OK`，且数据传输量符合预期。
