# 供应商审计产品的工具调用与插件

## 这个品类的数据长什么样
生物医药领域的供应商审计数据通常来源于审计报告、供应商资质文件、质量管理体系文档以及历史审计记录。这些数据更新频率不一，资质文件可能每年更新，而审计报告通常按计划周期性生成，例如每半年或每年一次。文档结构多样，包括 PDF 格式的审计报告、Word 格式的质量手册、Excel 格式的合规性检查表等。数据字段涉及供应商名称、审计日期、审计员、审计发现（缺陷描述、风险等级）、整改措施、完成日期、批次号、产品名称、试剂批次等，单位可能包括日期、文本描述、风险等级（如高、中、低）、数量单位（如批、件）。

## 这些特征在「工具调用与插件」这一环带来什么约束
供应商审计数据的多样性与非结构化特性，对工具调用与插件提出了特定要求。首先，大量 PDF、Word 文档需要强大的文档解析能力，确保关键审计发现和整改措施能够准确提取。其次，审计发现的描述性文本需要自然语言处理能力进行语义理解和分类，以便与法规标准或内部策略进行比对。Excel 表格中的结构化数据，如审计项和得分，则需要精确的字段映射。更新频率的不一致性要求工具具备灵活的数据同步机制，能够根据不同数据源的更新周期触发相应的抽取与索引流程。此外，对批次号、产品名称等特定字段的精确匹配需求，也强调了工具调用中参数传递的准确性与严格性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `3000` | 供应商审计报告通常篇幅较长，需要更大的上下文窗口以理解报告全文的语境和关联性。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大文件解析时间较长，避免因超时导致解析失败，特别是对于包含大量图表的 PDF 报告。 |
| `similarityThreshold` | `0.75` | 确保召回的审计条款或合规性要求与用户查询高度相关，减少误报。 |
| `retrievalQuantity` | `前 8 条` | 考虑到审计问题的复杂性，增加召回条目有助于覆盖更多潜在的关联信息。 |
| `postRequestFormat` | `application/json` | 多数现代 API 接口采用 JSON 格式进行数据交换，确保工具调用与目标服务兼容性。 |
| `pluginRetryCount` | `3 次` | 审计系统接口可能存在瞬时网络抖动或服务繁忙，多次重试可提高调用成功率。 |

## 容易做错的三处
*   插件调用后返回 400 错误码：通常是由于 `postRequestFormat` 设置与目标 API 接口要求不符，或 `payload` 中的字段类型、必填项缺失导致。
*   模型回答中未能提及审计报告中的关键缺陷编号：原因可能在于文档解析时未能准确识别并提取特定格式的缺陷编号字段，或 `similarityThreshold` 设置过高导致相关文本未被召回。
*   对供应商合规性问题的追溯查询结果不准确：这往往是由于数据更新机制不完善，导致模型获取的是过时数据，未能反映最新的审计整改状态。

## 怎么确认配好了
*   执行模拟审计查询，检查模型回答是否能准确引用审计报告中的具体条款和发现，并检查引用的文档来源与页码。
*   使用不同格式（PDF、Word、Excel）的供应商审计文档进行上传和索引，核对关键字段（如供应商名称、审计日期、缺陷描述）是否被正确提取和展示。
*   调用一个带有复杂参数的审计系统 API 插件，检查请求是否成功发送，并比对工具日志中的 `payload` 与预期参数是否一致。
