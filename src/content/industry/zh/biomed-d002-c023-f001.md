# 偏差与 CAPA产品的HTTP 接口与外部系统

## 这个品类的数据长什么样
生物医药领域的偏差与 CAPA（纠正与预防措施）数据通常来源于质量管理系统（QMS）、生产执行系统（MES）或实验室信息管理系统（LIMS）。这些数据记录了生产过程中的异常事件、质量缺陷、根本原因分析、以及实施的纠正与预防措施。数据更新频率通常较高，尤其是在生产高峰期，新偏差记录和CAPA进展会实时产生。文档结构通常包含结构化的字段，如偏差编号、发生时间、发现部门、偏差类型、影响范围、调查结果、根本原因、CAPA计划、责任人、预期完成日期和实际完成日期。字段中可能包含专业术语和缩写，单位涉及时间（小时、天）、数量（批次、单位）等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
偏差与 CAPA 数据的高更新频率要求 HTTP 接口具备高效的实时数据拉取或推送能力，以确保知识库内容的时效性。结构化的字段和专业术语意味着在数据解析时需要精确匹配，避免因字段名不一致或术语理解偏差导致的信息失真。例如，`deviation_id`、`root_cause_analysis` 等字段必须准确映射。文档中可能包含附件，如图片、PDF 报告，这要求接口支持文件上传和下载功能。复杂的关联关系，如一个偏差可能导致多个 CAPA，或一个 CAPA 解决多个偏差，需要在接口设计中考虑数据关联和嵌套结构，例如 JSON 格式中的数组对象。对时间戳字段的严格要求（如 `creation_timestamp`、`completion_timestamp`）也意味着需要注意时区转换和格式统一。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `API_ENDPOINT` | `https://your-qms.com/api/v1/deviations` | QMS 系统的标准 API 接口地址，确保数据源正确。 |
| `AUTH_TOKEN` | 按实测标定 | QMS 系统要求的认证凭证，确保数据访问权限。 |
| `PULL_INTERVAL_SECONDS` | `600 秒` | 偏差与 CAPA 数据的更新频率较高，10 分钟一次可兼顾时效性与系统负载。 |
| `MAX_RECORDS_PER_REQUEST` | `100 条` | 避免单次请求数据量过大导致超时或内存溢出，兼顾效率。 |
| `FIELD_MAPPING` | `{"deviation_id": "编号", "description": "描述"}` | 确保 QMS 字段与 FastGPT 知识库字段的准确映射，避免信息丢失。 |
| `TIMEOUT_SECONDS` | `30 秒` | 给予接口足够的响应时间，防止因网络延迟或服务器处理慢导致的请求失败。 |

## 容易做错的三处
*   调用外部接口时经常遇到返回 `HTTP 401 Unauthorized` 错误，原因在于 `AUTH_TOKEN` 配置错误或已过期，导致无法通过身份验证。
*   数据拉取后发现部分字段为空或内容不完整，这通常是由于 `FIELD_MAPPING` 配置不准确，外部系统字段名与 FastGPT 期望的字段名不匹配。
*   在 FastGPT 中尝试查询新近的偏差记录但未返回结果，通常是由于 `PULL_INTERVAL_SECONDS` 设置过长，数据同步不及时。

## 怎么确认配好了
*   在 FastGPT 的日志中检查 HTTP 请求的返回状态码，确认所有请求均返回 `HTTP 200 OK`。
*   手动从外部 QMS 系统获取几条最新的偏差与 CAPA 记录，然后在 FastGPT 知识库中进行查询，比对关键字段（如偏差编号、描述）是否一致。
*   观察 FastGPT 知识库中偏差与 CAPA 数据的更新时间戳，确保其与外部系统的最新数据保持在设定的 `PULL_INTERVAL_SECONDS` 间隔内。
*   在 FastGPT 中构建一个简单的 Agent，尝试提问关于特定偏差编号的问题，验证其能否准确引用到拉取进来的详细信息。
