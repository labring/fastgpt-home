# 先导优化产品的HTTP 接口与外部系统

## 这个品类的数据长什么样
先导优化数据源于高通量筛选、体外活性测试及计算化学模拟结果。其核心数据围绕化合物结构、生物活性（如 IC50、EC50）、ADMET（吸收、分布、代谢、排泄、毒性）性质预测值及合成路线信息。数据更新频率较高，尤其在多轮优化迭代过程中，新化合物合成与测试结果会持续流入。文档结构通常包含化合物 ID、SMILES 或 InChI 结构式、CAS 号、目标靶点、各项活性指标的数值与单位（如 nM、µM），以及实验条件描述。字段的命名往往遵循IUPAC命名法或行业惯例，单位统一性对后续分析至关重要。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
先导优化数据的高更新频率要求 HTTP 接口具备高效的数据同步机制，以确保 AI Agent 访问到最新实验结果。结构式数据（SMILES）的特殊性，使得在数据传输和解析时需额外注意编码与格式校验，避免因字符转义或截断导致结构错误。多样的活性指标与单位字段，要求接口设计时能灵活处理不同数值类型和单位转换，保证数据准确性。同时，由于数据量可能较大，尤其在化合物库遍历时，对接口的请求频率、并发处理能力以及响应时间都有较高要求，避免成为研发流程中的瓶颈。错误处理机制需要细化，能够区分结构解析失败、活性值缺失或单位不匹配等具体问题。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `requestTimeout` | `600 秒` | 先导优化数据处理可能涉及复杂计算或大规模数据检索，确保有足够时间完成请求。 |
| `maxConnections` | `按实测标定` | 根据外部系统并发处理能力和FastGPT部署环境资源，优化并发连接数。 |
| `header.Content-Type` | `application/json` | 生物医药领域数据交换多采用 JSON 格式，便于结构化数据传输。 |
| `body.compound_id_field` | `SMILES` | 以标准化的化合物结构标识符作为查询或更新的主键，确保唯一性。 |
| `error_retry_count` | `3` | 针对网络波动或外部系统瞬时负载，提供有限次的自动重试机会，提高稳定性。 |
| `data_parse_strategy` | `JSONPath` | 针对返回的复杂 JSON 结构，通过 JSONPath 精准提取所需活性、ADMET 字段。 |

## 容易做错的三处
*   调用 HTTP 接口后返回状态码 500，但日志中未见明确错误信息，导致难以定位问题。原因通常是外部系统内部逻辑错误，未将详细错误信息通过响应体返回。
*   AI Agent 在查询化合物活性时，返回结果中的数值为空或单位不正确。原因在于外部接口返回的 JSON 字段名与预期不符，或未对不同单位进行标准化处理。
*   频繁发起数据同步请求后，外部系统响应变慢或直接拒绝连接。原因往往是未设置合适的请求速率限制或并发连接数，导致外部系统过载。

## 怎么确认配好了
*   针对核心化合物 ID，通过 HTTP 接口手动发起查询请求，核对返回的SMILES、IC50等关键字段与预期值是否完全一致。
*   模拟一次数据更新操作，例如修改某个化合物的预测 ADMET 值，然后立即通过查询接口验证数据是否已同步更新。
*   在 FastGPT 知识库中创建一个包含先导优化相关问题的测试集，通过 AI Agent 提问，观察其是否能准确引用外部系统提供的最新数据。
*   监控 HTTP 接口的响应时间和错误日志，确保在高峰期也能保持在可接受的响应范围内，并且没有持续性的连接错误。
