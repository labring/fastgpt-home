# 减毒灭活疫苗产品的工具调用与插件

## 这个品类的数据长什么样
减毒灭活疫苗产品的数据主要来源于药品注册批件、临床试验报告、生产质检报告以及上市后监测数据。这些数据通常以结构化（如批次信息、成分含量、有效期）和非结构化（如临床研究论文、不良反应报告文本）形式存在。更新频率方面，注册批件和临床数据相对稳定，但上市后监测数据（如不良事件报告）则呈现持续动态更新。文档结构复杂，常包含 PDF 格式的说明书、CSV 格式的批次数据、以及符合 ICH E2B 标准的安全性报告。字段与单位具有高度专业性，例如“滴度”（TCID50/mL）、“抗原含量”（μg/剂），且常涉及批号、生产日期、有效期、储存条件等关键信息。

## 这些特征在「工具调用与插件」这一环带来什么约束
减毒灭活疫苗数据的复杂性对工具调用与插件提出了特定要求。首先，多源异构的数据特性要求工具能够整合不同格式的数据接口，例如，需要同时处理数据库查询和文档内容提取。其次，数据的专业性和高精度要求，使得模型在调用工具时需要精确理解查询意图，并能处理带有专业单位的数值。例如，对“滴度”的查询，模型需要能识别并调用计算或检索相关数值的工具。动态更新的上市后监测数据，要求工具调用具备实时或近实时的数据同步能力，以确保信息时效性。此外，严格的合规性要求，例如对批号、有效期等敏感信息的处理，需要工具在数据访问和处理过程中遵循特定协议和权限管理，避免信息泄露或误用。

## 配置怎么定

| 配置项             | 建议取法       | 这样取的依据                                     |
| :----------------- | :------------- | :----------------------------------------------- |
| `maxContext`       | `4000`         | 疫苗说明书或临床报告篇幅较长，确保上下文完整性     |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒`       | 大型 PDF 文档解析耗时，避免解析中断              |
| `similarityThreshold` | `0.85`         | 精准匹配疫苗批次、成分等专业术语，降低误召回率   |
| `extract_table_data` | `True`         | 疫苗质检报告常含表格数据，需精确提取结构化信息     |
| `tool_request_timeout` | `60 秒`        | 外部 API（如药品数据库）响应时间波动，预留足够时间 |
| `sql_query_template` | `SELECT * FROM vaccine_batches WHERE batch_id = '{batch_id}'` | 针对批次查询的常见模式，提高 SQL 生成准确性      |

## 容易做错的三处
*   调用外部 API 返回 `422 Unprocessable Entity` 错误：通常是由于模型生成的请求参数格式或数据类型与 API 接口定义不符，例如数值型参数传入了字符串。
*   多模态对话中图片相关工具调用报错 `400 Invalid Image`：发生于尝试处理疫苗包装图片时，通常是图片 URL 无效、图片格式不支持或图片内容不符合安全审查要求。
*   非工具调用模式下，大模型未能引用网络搜索节点内容：表现为模型回答中缺失最新的疫苗研究进展或不良事件报告，原因在于网络搜索工具未被正确触发或其返回结果未被有效整合到模型的上下文。

## 怎么确认配好了
*   测试不同批次疫苗的查询请求，检查工具是否能准确返回批次号、生产日期、有效期等核心字段，并核对返回数据的单位是否一致（如 `TCID50/mL`）。
*   模拟用户提问关于疫苗不良反应的场景，观察模型是否能触发外部数据库查询工具，并从返回结果中提取相关报告条目，核对报告编号和发生时间。
*   上传包含疫苗说明书或临床试验报告的 PDF 文件，验证文件解析工具是否能正确识别并提取其中的关键表格数据和文本段落，检查 `extract_table_data` 配置是否生效。
*   执行包含专业术语（如“减毒株”、“佐剂成分”）的查询，检查模型能否通过知识库检索或外部 API 调用，提供准确的定义或相关产品信息，并通过调试日志确认 `similarityThreshold` 的召回效果。
