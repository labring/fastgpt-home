# 减毒灭活疫苗产品的表单与交互

## 这个品类的数据长什么样

减毒灭活疫苗产品的数据主要来源于各国药监机构的审批文件、临床试验报告、生产工艺规程以及上市后的不良反应监测数据。这些数据更新频率相对较低，通常随新产品上市或现有产品批次变更而更新，每年可能仅有数次。文档结构复杂，包含大量非结构化文本，如详细的生产工艺描述、毒株来源、灭活工艺参数、佐剂成分、以及临床试验中的免疫原性、保护率等指标。字段与单位具有高度专业性，例如“半数感染剂量（TCID50）”、“抗体滴度（ELISA IU/mL）”、“病毒载量（copies/mL）”等，且常伴随特定的检测方法和标准。

## 这些特征在「表单与交互」这一环带来什么约束

减毒灭活疫苗产品的数据特性对表单与交互设计提出了特定要求。首先，数据更新频率低意味着前端缓存策略可以更激进，但需要提供明确的数据版本标识。其次，文档的复杂性和非结构化特性，要求表单设计能够处理多层级的嵌套信息，并支持富文本输入，例如疫苗的生产工艺流程描述。字段的专业性和多样化单位，使得在表单中需要提供详细的字段解释或预设单位选择，避免用户输入错误。同时，对于像“半数感染剂量”这类关键参数，可能需要在用户输入时进行实时校验，确保其符合生物学或药学上的合理范围，并与特定批次信息关联。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `3000 Tokens` | 疫苗文档内容丰富，需足够上下文支持复杂查询。 |
| `分段长度` | `500 字符` | 兼顾语义完整性与召回效率，避免过度截断关键信息。 |
| `召回条数` | `10 条` | 保证多维度信息覆盖，应对专业术语和关联数据的查询。 |
| `相似度阈值` | `0.75` | 疫苗名称、批次号等有高精度要求，减少不相关结果。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 处理大型PDF、Word格式的临床报告和审批文件。 |
| `ENABLE_VOICE_INPUT` | `true` | 支持实验室或生产现场人员语音查询，提升操作便捷性。 |

## 容易做错的三处

*   查询结果中疫苗批次或生产日期字段为空，原因在于原始数据抽取时未正确识别文档中的日期格式或批次编号模式。
*   用户输入“TCID50”后系统返回大量不相关内容，原因在于模型未针对特定专业术语进行充分的词向量训练或未配置同义词扩展。
*   语音输入后无法转换为有效文本，或转化内容与预期相去甚远，原因在于 `speech_model_id` 未选择适合生物医药领域术语识别的语音模型。

## 怎么确认配好了

*   提交包含不同疫苗批次号、生产日期、特定毒株信息的查询，核对返回结果是否准确关联到对应产品数据。
*   输入多个生物医药领域的专业术语，例如“佐剂成分”、“免疫原性”，检查返回内容是否聚焦于相关概念，且无明显偏离。
*   使用语音输入方式，提问有关疫苗生产工艺或临床指标的问题，检查语音转文字的准确性，并核对后续答案的合理性。
