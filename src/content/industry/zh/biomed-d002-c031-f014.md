# 医保准入产品的表单与交互

## 这个品类的数据长什么样

医保准入相关数据主要来源于国家及地方医保局发布的政策文件、药品/器械目录、支付标准、谈判结果公告等官方渠道。这些数据更新频率较高，如国家医保目录通常每年调整一次，地方政策可能根据实际情况不定期发布。文档形式多样，包括 PDF 格式的正式文件、Excel 表格形式的目录清单、以及网页公示信息。数据结构上，目录清单通常包含药品名称、通用名、剂型、规格、医保支付范围、报销比例、限定支付条件等字段。政策文件中则多为非结构化文本，需要通过自然语言处理技术提取关键信息，如适用疾病、适应症、特殊审批流程等。字段名称可能存在不统一，例如“医保编码”或“支付代码”，单位如“元/盒”、“mg/片”等需要标准化处理。

## 这些特征在「表单与交互」这一环带来什么约束

医保准入数据的高时效性要求表单设计具备快速更新和版本管理能力。例如，当新的医保目录发布时，系统需能迅速导入并更新相关药品或器械的报销信息，并确保用户查询到的是最新数据。多源异构的数据格式决定了表单输入不仅要支持结构化数据录入，还需要提供非结构化文本的上传与解析功能，例如解析 PDF 政策文件中的限定支付条件。字段名称的不统一性要求表单具备灵活的字段映射机制，以适应不同来源数据的字段命名习惯。复杂的限定支付条件和报销比例，使得简单的下拉选择或文本输入不足以满足需求，需要设计多层级、条件触发的动态表单控件。此外，由于涉及合规性，表单交互需要提供清晰的错误提示和数据校验，确保用户输入的信息符合医保政策规定。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `分段长度` | `500-800 字符` | 医保政策文本通常包含较长的描述性条款，此长度有助于保持上下文完整性。 |
| `召回条数` | `前 10-15 条` | 医保准入查询通常需要综合多条政策信息，增加召回条数可提高相关性覆盖。 |
| `相似度阈值` | `0.75-0.85` | 医保政策术语专业性强，高阈值可确保召回结果的精确匹配，避免误导。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大型医保目录或政策文件解析耗时较长，需要足够的处理时间。 |
| `maxContext` | `32k tokens` | 医保政策解读常涉及复杂逻辑和多条件判断，大上下文窗口有助于模型理解。 |
| `允许上传文件类型` | `PDF, XLSX, DOCX` | 覆盖医保政策文件、目录表格等常见官方发布格式。 |

## 容易做错的三处

*   查询结果中缺少最新政策条目，原因是数据同步机制未及时触发或解析器未能正确处理新版文件格式。
*   用户输入特定药品名称后，系统无法返回准确的医保支付范围，原因是字段映射配置有误，导致药品名称与医保目录中的标准名称不匹配。
*   表单提交后，系统提示“报销比例计算错误”，原因在于动态表单逻辑未正确处理限定支付条件下的阶梯报销规则。

## 怎么确认配好了

*   上传最新发布的医保政策文件，验证系统是否能正确解析并提取关键字段信息。
*   输入不同药品或器械的名称及规格，核对返回的医保支付范围、报销比例和限定条件是否与官方文件一致。
*   模拟多种复杂的报销场景，包括不同医保类型和特殊用药情况，检查表单的动态交互逻辑和计算结果是否准确。
