# 医保结算产品的HTTP 接口与外部系统

## 这个品类的数据长什么样
医保结算产品的数据核心是诊疗项目、药品、耗材的编码、价格、支付比例、限制条件等。这些数据主要来源于国家及地方医保局发布的官方文件和标准，如《国家基本医疗保险、工伤保险和生育保险药品目录》、《医疗服务项目目录》等。更新频率通常是季度或年度，遇政策调整可能临时更新。数据文档结构复杂，常以 Excel 表格或数据库导出文件形式发布，包含多层级分类和交叉引用。字段名称常涉及`项目编码`、`医保支付类别`、`报销比例`、`限价`、`适用症`等，单位包括`元`、`百分比`、`次`、`单位`等，且存在大量文本描述字段用于说明支付范围和限制。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
医保结算数据来源的官方性决定了接口需要高度重视数据准确性和一致性，通常需要通过医保局提供的官方API或数据文件进行对接。季度或年度的更新频率意味着系统需具备周期性数据同步机制，并能处理增量更新及全量覆盖。复杂的数据结构要求接口设计能够灵活映射多层级数据，处理嵌套关系和交叉引用，例如一个诊疗项目可能对应多个耗材的医保支付规定。大量的文本描述字段要求接口支持长文本传输，并能有效解析其中的关键信息，例如提取`限价`、`支付条件`中的数值和逻辑。此外，医保结算数据的高敏感性意味着HTTP接口必须满足严格的安全认证和授权机制，例如使用`OAuth2`或`API Key`进行访问控制，并对传输数据进行加密。

## 配置怎么定

| 配置项             | 建议取法                               | 这样取的依据                                                                                             |
| :----------------- | :------------------------------------- | :------------------------------------------------------------------------------------------------------- |
| `API_ENDPOINT`     | 医保局官方接口地址                   | 确保数据来源的权威性和实时性，避免第三方数据可能存在的滞后或偏差。                                     |
| `REQUEST_TIMEOUT`  | `60 秒`                                | 医保接口响应时间可能受网络和服务器负载影响，适当延长超时时间以减少因瞬时网络问题导致的请求失败。         |
| `SYNC_FREQUENCY`   | `每季度一次，或按政策发布及时触发`     | 匹配医保政策和目录的发布周期，确保数据的时效性。                                                       |
| `AUTH_METHOD`      | `API Key` 或 `OAuth2`                  | 医保数据敏感，采用强认证机制保障接口安全，防止未经授权的访问。                                           |
| `MAX_TEXT_LENGTH`  | `1024 字符`                            | 医保项目描述和限制条件通常较长，确保能完整接收和处理文本内容，避免截断。                               |
| `ERROR_RETRY_COUNT` | `3 次`，间隔 `5 秒`                   | 应对偶发性网络抖动或服务暂时性不可用，提高数据同步的稳定性。                                             |

## 容易做错的三处
*   调用API时返回 `401 Unauthorized` 或 `403 Forbidden`，原因是没有正确配置或传递`API Key`或`Access Token`，导致认证失败。
*   数据同步后部分医保项目的`报销比例`或`限价`字段为空，原因是对接口返回的数据结构理解有误，没有正确解析嵌套或可选字段，导致数据丢失。
*   本地开发环境切换模型渠道后，接口返回 `304 Not Modified`，原因是前端请求头中携带了`If-None-Match`或`If-Modified-Since`等缓存控制字段，导致服务器认为资源未修改而返回缓存响应。

## 怎么确认配好了
*   对核心医保项目（如常见药品、诊疗项目）进行多次API调用，比对返回的`项目编码`、`报销比例`、`限价`等关键字段与官方数据是否完全一致。
*   模拟医保政策更新场景，通过触发数据同步机制，检查新发布或修改的医保目录数据是否能在指定时间内正确同步到系统中。
*   使用不同的`API Key`或`Access Token`进行接口访问测试，确保未授权的请求会被正确拒绝，并返回相应的错误码（如 `401`）。
*   检查系统日志，确认在数据同步或接口调用过程中没有出现 `Timeout`、`Parsing Error` 或其他与数据处理相关的异常信息。
