# 医保结算产品的工具调用与插件

## 这个品类的数据长什么样

医保结算数据主要来源于各地医保局、定点医疗机构和商业保险公司。数据更新频率较高，通常按日或按周进行批次更新，部分核心业务数据如实时结算信息可达分钟级。数据结构以结构化表格为主，常见文件格式包括 CSV、XML 和 JSON。关键字段包括 `交易流水号`、`参保人ID`、`医疗机构编码`、`收费项目编码`、`费用总额`、`医保支付金额`、`个人支付金额`、`结算时间` 和 `结算状态`。特别需要注意的是，不同地区的医保政策可能导致字段含义或编码规则存在差异，例如 `医疗服务项目编码` 在不同省份可能采用不同的标准体系。金额字段通常精确到分，单位为“元”，日期时间字段格式多样，常见为 `YYYY-MM-DD HH:MM:SS`。

## 这些特征在「工具调用与插件」这一环带来什么约束

医保结算数据的高更新频率要求工具调用具备实时或近实时的查询能力，以确保获取信息的时效性。结构化数据特性使得通过 API 接口进行精确字段查询和过滤成为可能，减少了非结构化文本处理的复杂性。然而，不同地区医保政策和编码规则的差异，使得工具调用在处理跨区域查询时，需要内置或动态加载多套映射规则，避免因编码不一致导致的查询失败或结果偏差。例如，查询特定 `收费项目编码` 时，需要根据用户提供的地区信息，动态选择对应的编码标准进行匹配。此外，金额和日期时间字段的精确性要求，对工具函数在参数解析和结果返回时的数据类型转换提出了严格要求，确保数值计算的准确性。

## 配置怎么定

| 配置项                       | 建议取法                               | 这样取的依据                                                                 |
| :--------------------------- | :------------------------------------- | :--------------------------------------------------------------------------- |
| `maxContext`                 | `4096 tokens`                          | 确保能容纳医保查询或结算请求的详细描述及少量历史上下文，避免频繁截断。     |
| `timeout_seconds`            | `60 秒`                                | 考虑到医保接口可能存在网络延迟或后端处理时间，预留充足的响应时间。         |
| `response_format`            | `JSON`                                 | 医保数据多为结构化，JSON 格式便于后续解析和信息提取。                       |
| `max_retries`                | `3 次`                                 | 应对瞬时网络抖动或接口偶发性错误，提高调用成功率。                           |
| `error_code_mapping`         | 按实测标定 `200` 为成功，其他为失败码 | 根据医保接口文档定义，精确识别不同错误类型，进行针对性处理。               |
| `dynamic_parameter_mapping`  | 运行时根据 `region_code` 动态加载     | 应对不同地区医保政策和编码规则差异，实现参数的灵活适配。                   |

## 容易做错的三处

*   调用工具后返回 `{"error": "Invalid parameter value for 'medical_item_code'"}`：原因是传入的 `收费项目编码` 不符合目标医保接口所在区域的编码标准。
*   查询结果中的 `医保支付金额` 字段为空或显示为 `0.00`：可能由于 API 接口在特定查询条件下未返回该字段，或数据类型转换失败。
*   医保结算状态查询长时间无响应，最终返回 `504 Gateway Timeout`：工具调用超时配置过短，未能等待医保后端服务完成查询。

## 怎么确认配好了

*   针对不同地区和不同类型的医保查询，验证工具调用能够返回正确的 `交易流水号` 和 `结算状态`。
*   通过模拟多次并发请求，检查工具调用的响应时间是否稳定在 `60 秒` 以内。
*   构造包含异常 `参保人ID` 或 `医疗机构编码` 的请求，确认工具能正确捕获并返回 `error_code_mapping` 中定义的错误码。
