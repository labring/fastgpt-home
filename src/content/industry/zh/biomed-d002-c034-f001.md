# 医药电商产品的HTTP 接口与外部系统

## 这个品类的数据长什么样
医药电商平台的数据源具有其独特性。商品信息通常来源于药企或经销商提供的产品目录，更新频率受新品上市、批次调整、库存变动等因素影响，可能每日多次甚至实时更新。数据文档结构复杂，包含药品通用名、商品名、剂型、规格、生产厂家、批准文号、适应症、用法用量、禁忌、不良反应等多种字段。试剂类产品则涉及化学成分、纯度、批次号、存储条件等。单位表示多样，如毫克（mg）、毫升（ml）、国际单位（IU）等，且存在不同单位间的换算。这些数据往往以结构化（JSON、XML）或半结构化（PDF说明书、Excel表格）形式存在，并可能散布于多个独立的系统。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
医药电商数据的多源性与高更新频率，要求HTTP接口设计具备高并发处理能力和实时同步机制。复杂的文档结构意味着需要灵活的解析器来处理多样化的数据字段，尤其是药品的批准文号和试剂的批次号这类关键信息，它们对数据准确性和溯源性至关重要。单位多样性要求在数据摄入时进行标准化转换或明确标识，防止因单位混淆导致的使用错误。此外，由于数据可能来自不同的供应商系统，接口需要处理多种认证方式（如API Key、OAuth 2.0）和错误码体系。对半结构化数据的处理，例如PDF说明书，则需要结合OCR或文档解析技术，将其转换为可用的结构化信息。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `Request Timeout` | `30 秒` | 多数医药电商API响应时间较长，预留足够时间处理复杂查询或批量数据同步。 |
| `Max Retries` | `3 次` | 应对网络瞬时波动或API服务器短暂不可用，提高数据同步成功率。 |
| `Content-Type` | `application/json` | 医药电商API常用JSON格式进行数据交互，确保请求体正确解析。 |
| `Chunk Size` | `5000 字符` | 药品说明书等文本内容较长，合理分段有助于知识库构建和召回效率。 |
| `Polling Interval` | `600 秒` | 针对库存、价格等高频变动数据，设定适当轮询间隔确保信息及时性。 |
| `Error Code Mapping` | 按实测标定 | 将外部系统特有的错误码（如 `1001: Invalid Product ID`）映射为内部可理解的错误类型。 |

## 容易做错的三处
*   现象：部分药品或试剂的规格、单位信息在知识库中缺失或显示错误。
    原因：HTTP接口返回的JSON或XML数据中，规格字段的单位表示不统一，未进行标准化处理，导致解析器无法正确识别。
*   现象：导入大量产品数据时，接口经常返回 `504 Gateway Timeout` 错误。
    原因：HTTP请求的 `Request Timeout` 设置过短，未能覆盖后端处理大批量数据所需的时间。
*   现象：知识库检索结果中，同一药品的批准文号信息不一致。
    原因：数据源的API接口在不同批次或不同供应商处，批准文号字段的命名或格式存在细微差异，未在数据清洗阶段统一处理。

## 怎么确认配好了
*   对核心商品（如常用药品、高值试剂）进行数据同步测试，核对其通用名、规格、批准文号等关键字段是否与源系统一致。
*   模拟高并发场景，观察HTTP接口的响应时间与成功率，确保在压力下系统能稳定运行。
*   随机抽取部分包含长文本（如药品说明书）的产品数据，验证其在知识库中的分段和检索效果是否符合预期，检查 `Chunk Size` 配置的有效性。
*   触发外部系统可能返回的常见错误码，确认系统是否能正确捕获并处理这些异常，例如 `401 Unauthorized` 或 `404 Not Found`。
