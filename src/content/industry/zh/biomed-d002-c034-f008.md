# 医药电商产品的工具调用与插件

## 这个品类的数据长什么样

医药电商产品的数据主要来源于药企、经销商、医疗器械生产商等上游供应商提供的产品目录、说明书、库存信息和价格清单。这些数据通常以结构化或半结构化的形式存在，如 CSV、Excel、XML 或 JSON 文件，也可能通过供应商的 API 接口获取。数据更新频率较高，特别是库存和价格信息，可能每日甚至每小时更新，以反映市场供需变化和促销活动。产品文档通常包含药品通用名、商品名、剂型、规格、批准文号、生产企业、适应症、用法用量、不良反应、禁忌、贮藏条件等字段。医疗器械则涉及型号、注册证号、生产许可证号、技术参数等。单位方面，剂量常用毫克（mg）、克（g）、毫升（ml），规格常用片、粒、支、盒，有效期则精确到年月。

## 这些特征在「工具调用与插件」这一环带来什么约束

医药电商数据的高频更新特性，要求工具调用能够支持实时或近实时的拉取机制，避免因数据滞后导致的库存不准或价格错误。结构化数据源多，意味着插件需要具备强大的解析能力，能够灵活适配不同供应商的数据格式，例如处理 XML 或 JSON 嵌套结构。批准文号、注册证号等关键字段的唯一性和合规性要求，使得工具在查询时需要精确匹配，避免模糊查询带来的混淆。同时，药品说明书等非结构化文本内容，在进行产品咨询时，需要结合向量检索技术，提升查询准确性。单位的标准化处理也至关重要，例如将不同供应商提供的剂量单位统一转换，以确保准确的推荐和计算。这些约束共同决定了在设计工具调用和插件时，需要兼顾数据时效性、格式多样性、字段精确性和内容理解深度。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `tool_timeout` | `30000 毫秒` | 医药电商接口响应时间可能受网络、数据量影响，适当延长超时时间，避免因短暂延迟导致调用失败 |
| `max_retries` | `3 次` | 针对外部 API 调用，提供重试机制，应对瞬时网络波动或服务不稳定 |
| `json_parse_depth` | `5 层` | 供应商提供的 JSON 数据可能存在多层嵌套，确保能解析到关键业务字段 |
| `api_cache_ttl` | `3600 秒` | 对于非实时性要求极高的产品信息，设置缓存，减少重复调用，降低供应商接口压力 |
| `recall_top_k` | `5` | 在进行产品说明书等文本内容检索时，召回前 K 个最相关的结果进行处理 |
| `similarity_threshold` | `0.75` | 设定向量检索的相似度阈值，过滤掉不相关的产品信息，提高咨询准确性 |

## 容易做错的三处

*   调用外部 API 时返回 HTTP 500 错误码，或出现 "Invalid JSON response" 错误。原因在于供应商接口可能返回非标准 JSON 格式或服务内部异常，插件未进行充分的错误处理和容错机制。
*   用户咨询特定药品价格时，返回的数值与电商平台显示不一致，或价格字段为空。原因在于价格数据更新频率高，但工具调用未配置实时拉取或缓存过期策略不当，导致获取到的是过期数据。
*   导出工作流到新环境后，工具调用环节提示 "Plugin not found" 或 "Function definition missing"。原因在于工作流中引用的自定义插件或工具在目标环境中未部署或注册，导致无法解析和执行。

## 怎么确认配好了

*   进行端到端测试，模拟用户咨询，检查工具调用是否能准确获取到药品的实时价格和库存信息，并与实际电商平台数据比对，确保一致性。
*   审查工具调用日志，确认没有出现 HTTP 4xx 或 5xx 错误码，并且 JSON 解析过程没有报错，关键字段如 `product_id`、`price`、`stock_quantity` 能够正确提取。
*   编写测试用例，覆盖多种数据格式和异常情况，例如供应商返回空数据、字段缺失或非标准单位，验证插件是否能正确处理并给出合理响应。
*   核对插件定义与外部 API 文档，确保参数名称、数据类型、请求方式与响应格式完全匹配，特别是药品批准文号、注册证号等关键标识符的传输与接收。
