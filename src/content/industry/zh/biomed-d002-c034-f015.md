# 医药电商产品的部署与升级

## 这个品类的数据长什么样

医药电商产品的数据核心是药品、医疗器械、保健品等商品信息，以及相关的医学文献、疾病知识和用户咨询记录。商品信息通常包含商品名称、规格、生产厂家、批准文号、适应症、用法用量、禁忌、不良反应、价格、库存等字段。这些数据来源多样，包括药监局公开数据、药企提供的产品说明书、第三方数据服务商接口、以及平台内部的用户行为数据。数据更新频率较高，特别是价格和库存信息可能实时变动，药监政策和药品说明书也存在定期修订。文档结构通常标准化，例如药品说明书有固定的章节划分，但不同厂家或不同品类的商品，其字段名称和单位可能存在细微差异，例如药品剂量可能涉及毫克（`mg`）、毫升（`ml`）、单位（`U`）等多种表示。

## 这些特征在「部署与升级」这一环带来什么约束

医药电商产品数据的多样性和高更新频率，对部署与升级方案提出了特定要求。首先，商品信息量大且字段复杂，在知识库分段时需要更精细的控制，确保关键信息不被截断，例如药品批准文号 `国药准字H20080001` 等。其次，药监政策和药品说明书的更新，要求知识库具备高效的增量更新和版本管理能力，避免出现信息滞后或错误。如果使用外部 API 获取实时价格或库存，需要确保 API 密钥的妥善管理和接口的稳定性。此外，用户咨询中常包含专业术语，对模型理解和生成能力有较高要求，部署时需评估模型在特定领域的表现，并在升级时优先关注模型在专业词汇理解上的优化。对于语音咨询，`CosyVoice2-0.5B` 这类语音模型若无法正常使用，需要排查其依赖库和运行环境，确保与 FastGPT 版本 `4.8.17` 及 `xinference V1` 等基础设施兼容。

## 配置怎么定

| 配置项                 | 建议取法       | 这样取的依据                                                 |
| :--------------------- | :------------- | :----------------------------------------------------------- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB`       | 商品说明书或医学文献文件较大，需要支持上传大文件。           |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`       | 复杂的 PDF 或图片格式说明书解析耗时较长，避免解析超时。      |
| `分段长度`             | `800–1200 字符` | 确保药品关键信息如适应症、用法用量等能完整分段，避免信息丢失。 |
| `召回条数`             | `前 10 条`     | 医药咨询的严谨性要求更全面的初始召回，增加相关性。           |
| `相似度阈值`           | `0.75`         | 确保召回结果与医学专业问题的高度相关性，降低误导风险。       |
| `重排返回条数`         | `前 5 条`      | 经过重排后，筛选出最相关且具有权威性的少数结果进行回答。     |

## 容易做错的三处

*   语音识别模型 `CosyVoice2-0.5B` 无法正常工作，导致语音咨询功能失效，原因可能是 `xinference V1` 版本与模型依赖不兼容，或者部署环境缺少必要的运行库。
*   知识库更新后，回答中出现过时的药品价格或政策信息，原因是未能正确配置增量更新策略，导致旧数据未被及时替换或删除。
*   用户提问药品用法用量时，回答内容不完整或出现关键字段缺失，原因通常是知识库分段策略过于激进，将重要信息拆分到不同段落，导致召回时无法获取完整上下文。

## 怎么确认配好了

*   上传一份包含复杂表格和专业术语的药品说明书 PDF 文件，检查解析后的文本内容是否完整且无乱码，特别是批准文号、生产厂家等关键字段。
*   随机抽取 10 个近期有更新的药品，查询其价格和库存信息，验证 FastGPT 返回的数据与实际最新数据是否一致。
*   模拟用户咨询关于某种药品的适应症、用法用量、禁忌等问题，评估回答的准确性、完整性和专业性，并检查引用来源是否正确。
