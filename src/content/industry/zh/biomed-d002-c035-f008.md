# 医院运营产品的工具调用与插件

## 这个品类的数据长什么样

医院运营数据通常来源于医院信息系统（HIS）、电子病历系统（EMR）、财务系统、设备管理系统及供应链管理系统等，呈现出多样化的结构。数据更新频率高，门诊量、住院床位周转率、药品库存等核心指标通常实时或每日更新，财务数据按月或季度汇总。文档形式以结构化数据为主，如数据库表、CSV文件，但也包含非结构化或半结构化文档，如设备维护记录、供应商合同扫描件、患者满意度调查报告等。字段方面，涉及大量业务特有标识，例如 `patient_id`、`dept_code`、`drug_batch_no`、`device_sn` 等，单位则涵盖数量（人次、件）、金额（元）、时间（小时、天）、百分比等。

## 这些特征在「工具调用与插件」这一环带来什么约束

医院运营数据的高实时性要求工具调用能快速响应，例如查询实时床位状态或库存。数据源的多样性决定了插件需要支持多种数据接口，包括数据库直连、API 调用、文件解析等。结构化数据占据主导，使得工具调用在处理查询、统计类需求时，能有效利用 SQL 或类 SQL 接口。非结构化文档的存在，则要求插件具备文档解析能力，例如识别设备故障描述中的关键信息。业务特有字段和单位的准确性至关重要，插件设计时需明确参数映射关系，避免单位混淆或字段误用，例如查询药品库存时，需明确是按盒还是按最小包装单位。高频更新的特性，也对插件的缓存策略和数据同步机制提出了要求，确保调用结果的最新性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `max_tokens` | `1024` | 保证复杂查询结果的完整性，避免截断关键运营数据。 |
| `temperature` | `0.1` | 确保工具调用结果的准确性和稳定性，减少生成性偏差。 |
| `tool_request_timeout` | `60 秒` | 多数医院系统接口响应时间在 5-30 秒内，预留足够缓冲。 |
| `max_retries` | `3` | 应对网络波动或后端服务瞬时负载高导致的偶发性失败。 |
| `json_mode` | `true` | 大多数医院API接口返回数据为 JSON 格式，便于结构化解析。 |
| `response_schema` | 明确定义输出字段 | 确保返回数据格式符合预期，方便后续处理和展示，例如 `{"bed_status": "occupied", "department": "Cardiology"}`。 |

## 容易做错的三处

*   插件调用后返回 `HTTP 400 Bad Request` 错误，内容提示 `Invalid JSON format`。原因通常是请求体内容类型（`Content-Type`）设置错误，例如发送了 `application/x-www-form-urlencoded` 而接口只接受 `application/json`。
*   工具调用返回的数据量不足或字段缺失。原因可能是 `response_schema` 未精确定义所有预期字段，导致模型在解析时遗漏，或 `max_tokens` 设置过小未能完整接收响应。
*   调用医院内部 API 时，长时间无响应直至超时。原因可能是网络安全策略限制了对外部 IP 的访问，或内部服务负载过高未及时处理请求。

## 怎么确认配好了

*   通过模拟用户输入，触发工具调用，检查 `tool_code` 日志输出，确认请求参数与目标系统接口文档一致。
*   观察工具调用的响应时间，确保在 `tool_request_timeout` 阈值内返回结果，并对响应时间进行基线测试。
*   验证返回结果的数据结构和字段内容，与医院运营系统的实际数据进行比对，确认 `patient_id`、`drug_batch_no` 等关键业务字段的准确性。
