# 医院运营产品的文档解析与分块

## 这个品类的数据长什么样
医院运营数据主要来源于内部管理系统、HIS（医院信息系统）、电子病历系统、财务系统、供应链管理系统、人力资源系统等，以及外部政策法规、行业标准和市场调研报告。数据更新频率较高，如财务报表可能按月、季度更新，运营指标日报、周报常见，政策法规则是不定期发布。文档结构多样，包括标准化的表格数据、带有章节标题的结构化文本（如管理制度、质量报告）、半结构化的合同与协议，以及非结构化的会议纪要、邮件沟通记录。字段与单位具有行业特异性，例如床位周转率、平均住院日、医保支付比例、耗材批次号、药品通用名、国家医保编码等，对数字精度和文本匹配有较高要求。

## 这些特征在「文档解析与分块」这一环带来什么约束
医院运营文档来源广泛且格式多样，对文档解析器的兼容性提出挑战，需要支持 PDF、DOCX、XLSX 等多种常见格式。数据更新频率高，要求知识库能够快速响应数据变更，避免过时信息误导决策。文档中包含大量专业术语、编码和指标，需要分块策略能有效保留这些关键信息的上下文关联，防止语义碎片化。例如，关于“医保支付比例”的描述可能跨越多个段落，简单的固定长度分块容易切断其完整性。此外，许多运营数据以表格形式呈现，如何将表格内容转化为可检索、可理解的文本块，是分块环节的关键考量。对字段与单位的精确识别，也要求分块后仍能保持其原始形态，以支持后续的精准问答。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `分段长度` | `500–800 字符` | 兼顾信息完整性与检索效率，避免过长导致无关信息干扰，过短丢失上下文。 |
| `重叠长度` | `100–150 字符` | 确保分块边界处的语义连续性，尤其在处理包含专业术语的长句时。 |
| `解析策略` | `按标题分段优先` | 医院管理制度、报告多有清晰的章节标题，此策略能更好地保留逻辑结构。 |
| `表格处理` | `转换为 Markdown` | 大量运营数据以表格呈现，转换为结构化文本利于后续检索和理解。 |
| `文件类型白名单` | `pdf, docx, xlsx, txt, md` | 覆盖医院运营文档主要格式，确保文件可被解析。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 应对大型运营报告或复杂结构文档的解析时长，防止超时失败。 |

## 容易做错的三处
*   解析大型 PDF 运营报告时出现超时或部分内容缺失，原因在于 `PARSE_FILE_TIMEOUT_SECONDS` 参数设置过低，未能给复杂文档足够的处理时间，或默认解析器对嵌入对象处理不佳。
*   知识库问答结果中，关于某个运营指标的解释不完整或前后矛盾，现象是检索到的分块文本未能包含该指标的全部定义和相关说明，原因通常是 `分段长度` 过短，导致关键信息被切断。
*   上传多个 DOCX 格式的规章制度文件后，知识库构建耗时过长，且并行处理能力不足，这通常与系统默认的单文件处理模式相关，未能充分利用多核 CPU 的并行能力。

## 怎么确认配好了
*   随机抽取多份不同格式（如 PDF、DOCX、XLSX）的医院运营文档，上传至知识库，检查解析状态是否成功，并查看分块预览内容是否完整、无乱码。
*   选择包含表格的文档，查看其分块后文本是否已正确转换为易于理解的 Markdown 格式，检查关键字段和数值是否准确保留。
*   针对核心运营指标（如“床位周转率”、“平均住院日”），构造包含其定义、计算方法及影响因素的问句，测试知识库的召回结果，判断分块内容是否能提供完整且相关的上下文信息。
