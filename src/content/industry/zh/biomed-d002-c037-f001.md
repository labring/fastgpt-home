# 双特异性抗体产品的HTTP 接口与外部系统

## 这个品类的数据长什么样

双特异性抗体（BsAb）产品的数据通常来源于生物医药数据库、临床试验报告、专利文献和企业内部研发文档。这些数据更新频率不一，基础结构信息（如靶点、作用机制）相对稳定，而临床试验进展、适应症拓展、副作用报告则可能实时更新。文档结构以半结构化和非结构化数据为主，包括研究论文的PDF、临床试验的XML或JSON报告，以及结构化的药物分子信息（SMILES、InChIKey）。字段方面，常见的有 `靶点1`、`靶点2`、`抗体序列`、`作用机制`、`适应症`、`临床阶段`、`生产批次`、`储存条件`、`药代动力学参数`（如 `半衰期`、`Cmax`），单位则涉及毫克、摩尔、小时、摄氏度等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

双特异性抗体数据来源的多样性要求 HTTP 接口具备强大的数据整合能力，需要从多个外部 API 获取信息。更新频率的不一致性意味着数据同步策略需要精细化，核心结构数据可以定期全量或增量同步，而临床进展等动态信息则需要更频繁地通过事件驱动或定时轮询获取。文档结构以非结构化为主，这要求 FastGPT 的 HTTP 接口在获取原始数据后，能够与后续的文本解析、知识抽取模块紧密配合，提取关键字段。特定字段如 `抗体序列` 可能长度较长，需要确保 HTTP 请求体和响应体大小支持；`药代动力学参数` 的数值类型和单位多样，在接口参数设计时需考虑数据类型校验和单位转换。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `请求超时时间` | `60 秒` | 考虑到部分生物数据库接口响应可能较慢，以及数据量较大时的传输耗时。 |
| `最大并发请求数` | `5` | 避免对外部数据库 API 造成过大压力，遵守多数公共 API 的调用频率限制。 |
| `HTTP 方法` | `POST` 或 `GET` | 根据外部 API 的具体要求选择，`POST` 适用于复杂查询或大量参数。 |
| `Content-Type` | `application/json` | 大多数生物信息 API 倾向于使用 JSON 格式进行数据交换。 |
| `重试策略` | `指数退避，最多重试 3 次` | 应对外部 API 的瞬时故障或网络波动，提高数据获取的成功率。 |
| `解析响应体字段` | `data.results[].sequence` | 从嵌套的 JSON 结构中准确提取 `抗体序列` 等核心信息。 |

## 容易做错的三处

*   现象：HTTP 请求长时间无响应或返回 504 Gateway Timeout。原因：外部生物信息数据库接口响应慢，或者请求数据量过大导致传输超时，`请求超时时间` 配置过短。
*   现象：外部 API 返回 403 Forbidden 错误码。原因：未正确配置 `Authorization` 或 `API Key` 请求头，导致权限认证失败。
*   现象：获取到的 `抗体序列` 字段为空或不完整。原因：`解析响应体字段` 配置路径不准确，未能正确匹配外部 API 返回的 JSON 结构中 `抗体序列` 对应的键名。

## 怎么确认配好了

*   通过 FastGPT 的 HTTP 模块测试功能，使用一个典型的双特异性抗体 ID 进行查询，检查是否能成功获取到完整的 JSON 响应体。
*   检查日志输出，确认没有出现 HTTP 状态码 4xx 或 5xx 的错误记录，且 `请求耗时` 在预期范围内。
*   检查 FastGPT 知识库中导入的数据，核对 `抗体序列`、`靶点`、`适应症` 等关键字段是否已正确提取并存储，并与原始数据源进行比对，验证其准确性。
