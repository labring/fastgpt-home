# 合理用药产品的工具调用与插件

## 这个品类的数据长什么样
合理用药领域的数据通常涵盖药品说明书、临床指南、药物相互作用、不良反应、禁忌症、用法用量、特殊人群用药指导等。数据来源多样，包括国家药监局数据库、专业医学期刊、药典、临床试验报告以及医院内部的药事管理系统。更新频率高，新药上市、适应症拓展、不良反应报告、临床指南修订都会导致数据更新，部分数据如药品批次信息甚至会每日更新。文档结构以半结构化或非结构化文本为主，如 PDF 格式的药品说明书、HTML 格式的临床指南，以及结构化数据如药物成分表、相互作用矩阵。字段与单位具有专业性，例如剂量单位（mg/kg、U/L）、频率（tid、qd）、疗程（天、周），以及特定的医学术语和编码系统（如 ATC 分类、ICD-10 疾病编码）。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据更新频率高，要求工具调用能够及时同步最新信息。例如，药物相互作用或不良反应数据若未及时更新，可能导致不准确的用药建议。半结构化和非结构化文档的存在，使得在工具调用前需要进行有效的信息抽取和结构化处理。这限制了简单文本匹配类插件的有效性，需要更复杂的 NLP 和信息抽取能力。专业化的字段和单位，以及医学编码系统，要求插件能够理解并正确解析这些信息，例如将口语化的“一天三次”转换为医学上的 `tid`，或将药品通用名映射到标准编码。同时，由于合理用药涉及生命健康，对工具调用的准确性和召回率有极高要求，任何误判或遗漏都可能产生严重后果，因此对错误处理和结果校验的机制提出了更高要求。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `externalApiTimeout` | `60000 毫秒` | 药品数据接口响应可能较慢，需要预留足够时间 |
| `maxChunkSize` | `800 字符` | 药品说明书和指南文本量大，小分段利于语义匹配 |
| `topK` | `10 条` | 初始召回更多相关条目，提高准确率，后续进行重排 |
| `embeddingModel` | `text-embedding-ada-002` 或更高版本 | 提高专业医学术语的向量化精度 |
| `fallbackStrategy` | `人工审核` | 关键用药建议涉及安全，自动化失败后需人工介入 |
| `parsingTemplate` | 按实测标定 | 针对不同来源文档结构，优化信息抽取规则 |

## 容易做错的三处
*   调用外部 API 返回空响应，查看日志显示 `HTTP 500` 错误，原因是请求参数中的药品编码格式不符合 API 接口要求，导致后端服务处理失败。
*   插件返回的用药剂量单位不一致，例如有时是 `mg` 有时是 `g`，现象是推荐结果无法直接用于临床，原因是数据解析时未对单位进行标准化处理，或不同来源数据单位不统一。
*   模型在回答中未能提及某个重要的药物禁忌症，原因是工具调用返回的数据量不足，或相关禁忌信息在原始文档中被识别为低相关度而被过滤。

## 怎么确认配好了
*   对多组典型用药场景（如特定疾病、特殊人群用药）进行测试，核对工具调用返回的药品信息是否全面、准确，并与最新临床指南进行比对。
*   验证插件对不同格式的药品说明书、临床指南（如 PDF、HTML）的信息抽取能力，检查关键字段如用法用量、不良反应、禁忌症是否能被正确解析。
*   模拟异常情况，如外部 API 响应慢、返回错误数据或无数据时，观察 FastGPT 的错误处理机制是否符合预期，例如是否正确触发回退策略或给出明确提示。
*   检查工具调用日志，确认 `request body` 和 `response body` 的数据结构和内容符合预期，特别是专业医学字段的解析和映射是否正确。
