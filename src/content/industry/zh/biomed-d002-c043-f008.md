# 基因治疗 AAV产品的工具调用与插件

## 这个品类的数据长什么样

基因治疗 AAV（腺相关病毒）产品的数据主要来源于临床前研究报告、临床试验报告、监管申报文件和学术论文。这些数据通常以非结构化的文本形式存在，例如 PDF 文档、Word 文档，以及结构化的数据库记录。数据更新频率相对较低，主要集中在临床试验进展、新适应症获批或生产工艺改进时。文档结构复杂，包含分子生物学信息（如血清型、载体构建）、生产工艺参数（如病毒滴度、纯度）、质量控制指标（如基因组完整性、宿主细胞残留）、药效学和药代动力学数据，以及安全性数据。字段与单位多样，例如病毒滴度常以 `vg/mL`（基因组拷贝数每毫升）表示，纯度以百分比表示，基因表达量可能涉及 `mRNA copies/cell` 或荧光强度单位，生物学活性数据则可能包括 `IC50` 或 `EC50` 值。

## 这些特征在「工具调用与插件」这一环带来什么约束

基因治疗 AAV产品数据的高度非结构化特性，导致直接从原始文档中提取精确信息进行工具调用面临挑战。需要预处理步骤，例如利用文档解析工具将 PDF 转换为可结构化处理的文本。数据更新频率较低意味着工具调用的缓存策略可以相对宽松，但每次更新都可能涉及大量新数据，要求工具具备高效的索引和更新机制。复杂的文档结构和多样化的字段单位，对工具调用中参数的识别和校验提出了高要求，例如需要区分不同血清型名称，并正确解析 `vg/mL` 和 `pfu/mL` 等不同滴度单位。此外，由于AAV产品数据的专业性，工具调用的语义理解能力必须足够强大，以避免因术语歧义导致调用失败或返回错误结果。对特定生产批次或临床试验编号的精确查询，要求工具能处理复杂查询逻辑和多条件筛选。

## 配置怎么定

| 配置项                       | 建议取法       | 这样取的依据                               |
| :--------------------------- | :------------- | :----------------------------------------- |
| `maxContext`                 | `4000 字符`    | 适应 AAV 报告中常见较长的段落和描述        |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`       | 应对大型 PDF 文档解析的耗时                |
| `召回条数`                   | `前 10 条`     | 确保覆盖 AAV 产品查询中多维度关联信息      |
| `相似度阈值`                 | `0.75`         | 兼顾 AAV 术语的专业性和查询的宽泛性        |
| `重排返回条数`               | `5 条`         | 聚焦于 AAV 产品最相关的核心数据            |
| `API_RATE_LIMIT_INTERVAL`    | `1000 毫秒`    | 规避外部生物信息数据库的接口调用频率限制   |

## 容易做错的三处

*   调用外部数据库 API 时，频繁出现 `HTTP 429 Too Many Requests` 错误，原因是没有正确配置或启用 API 调用频率控制。
*   工具调用返回的结果中，关键字段如 `病毒滴度` 或 `基因组完整性` 为空，原因是没有适配 AAV 产品报告中多样化的字段命名或数据格式。
*   AI 对话模块在工具调用后无法正确使用返回数据，原因在于工具输出的 JSON 结构与下一个模块预期的输入结构不符，导致数据解析失败。

## 怎么确认配好了

*   通过模拟多个并发查询，检查外部 API 调用是否能稳定返回 `HTTP 200 OK` 状态码，并记录每次调用的响应时间。
*   针对不同格式的 AAV 产品文档（如 PDF、Word），验证工具调用能准确提取 `血清型`、`生产批次`、`滴度` 等核心字段，并检查字段值与单位的正确性。
*   设计包含多个工具调用步骤的复杂查询，验证前一个工具调用的输出能够作为后一个工具调用的有效输入，并最终得到预期结果。
*   检查日志中是否有 `chatId` 参数的正确传递和记录，确保会话上下文在工具调用链中得到维护。
