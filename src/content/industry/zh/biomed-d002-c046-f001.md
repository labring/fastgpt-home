# 实体瘤产品的HTTP 接口与外部系统

## 这个品类的数据长什么样
实体瘤相关数据主要来源于临床试验报告、病理诊断系统、分子检测平台和药物研发数据库。这些数据更新频率不一，临床试验数据随进展阶段性发布，分子检测结果则实时或准实时生成。文档结构复杂，常包含半结构化的医学文本、结构化的实验结果以及图像报告。字段名称具有高度专业性，例如肿瘤类型、分期、基因突变位点、PD-L1 表达水平等，单位涉及微摩尔（µM）、纳摩尔（nM）、拷贝数（CN）等生物学和药学计量单位。数据中常包含大量医学术语缩写和编码体系。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
实体瘤数据的多样性和专业性，要求 HTTP 接口具备强大的数据解析和校验能力。半结构化文本的解析需要复杂的正则匹配或自然语言处理（NLP）预处理，以提取关键信息。高频更新的分子检测数据，要求接口设计支持高并发访问和低延迟响应，以确保信息实时性。多种计量单位的存在，意味着接口在接收和发送数据时需明确单位标注，避免混淆。此外，涉及到敏感的患者信息或临床数据，外部系统集成时必须遵守严格的数据安全和隐私保护协议，例如 OAuth 2.0 认证和数据加密传输，确保数据流转的合规性。

## 配置怎么定

| 配置项                       | 建议取法       | 这样取的依据                                       |
| :--------------------------- | :------------- | :------------------------------------------------- |
| `maxRequestTimeout`          | `30000 毫秒`   | 考虑到复杂数据处理和外部系统响应时间，预留充足超时 |
| `requestBodyType`            | `application/json` | 多数生物医药API采用JSON格式进行数据交换          |
| `authMethod`                 | `OAuth 2.0`    | 行业标准，提供安全的用户授权和数据访问             |
| `responseParsingRules`       | `自定义正则或JSONPath` | 适应半结构化数据和复杂JSON嵌套，精确提取关键字段 |
| `retryAttempts`              | `3 次`         | 应对网络波动或外部服务瞬时故障，提高成功率         |
| `rateLimitPerMinute`         | `按实测标定`   | 依据外部API的限流策略和自身业务需求灵活调整        |

## 容易做错的三处
*   HTTP 接口返回 5xx 状态码或空响应，原因可能是外部系统过载或接口路径配置错误。
*   响应数据中某些关键字段为空，通常是由于响应解析规则不准确，未能正确匹配到数据。
*   请求数据发送后长时间无响应，表现为请求超时，可能是由于 `maxRequestTimeout` 设置过短或外部API处理耗时过长。

## 怎么确认配好了
*   对核心实体瘤数据查询接口，使用不同参数进行多次调用，检查响应数据是否完整且符合预期字段结构。
*   模拟外部系统异常响应（例如，返回错误状态码），验证 FastGPT 是否能正确捕获并处理异常情况。
*   在高峰期或并发场景下进行接口性能测试，确保响应时间在可接受范围内，并检查是否出现限流错误。
*   对照外部API文档，逐一核对请求头、请求体参数、响应体字段及其单位，确保数据传输格式和内容无误。
