# 实验室服务产品的工具调用与插件

## 这个品类的数据长什么样
实验室服务产品的数据来源多样，主要包括内部实验管理系统（LIMS）、供应商的产品目录、技术文档以及科学文献。这些数据更新频率不一，新品发布、试剂批次变更、实验方案优化等都会触发更新，通常为季度或月度更新，但紧急情况也可能随时调整。文档结构上，产品目录通常是结构化的表格或数据库记录，包含产品名称、货号、规格、批次、价格、技术指标等字段。技术文档如产品说明书、COA（Certificate of Analysis）则多为半结构化或非结构化文本，其中包含实验原理、操作步骤、性能参数、储存条件、安全信息等。字段方面，常涉及浓度（`mg/mL`、`µM`）、纯度（`%`）、活性（`U/mg`、`IU`）、储存温度（`℃`）等，单位精确且具有行业特异性。

## 这些特征在「工具调用与插件」这一环带来什么约束
实验室服务产品数据来源的异构性，要求工具调用能够灵活处理结构化与非结构化数据。供应商产品目录的定期更新，意味着知识库需要有高效的增量更新机制，以确保产品信息的时效性。技术文档中的专业术语和计量单位，对模型理解和工具函数参数的解析精度提出了更高要求，例如精确识别 `pH 7.4` 或 `100 ng/µL`。当用户查询特定试剂的批次信息或实验条件时，工具需要能够精准地从LIMS或COA报告中提取对应字段，并在必要时进行单位转换。此外，处理多批次、多规格的产品信息时，工具的参数传递和结果筛选逻辑必须足够健壮，避免因数据量大或字段缺失导致查询失败。

## 配置怎么定

| 配置项                 | 建议取法       | 这样取的依据                                   |
| :--------------------- | :------------- | :--------------------------------------------- |
| `maxContext`           | `2000–3000` 字符 | 兼顾技术文档的详尽度与模型处理效率             |
| `召回条数`             | `10–15` 条     | 确保覆盖多规格、多批次的产品信息               |
| `相似度阈值`           | `0.75–0.82`    | 过滤不相关结果，同时保留专业术语的模糊匹配能力 |
| `重排返回条数`         | `3–5` 条       | 精炼最终呈现结果，提升用户体验                 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600` 秒       | 适应大型技术文档或COA报告的解析时间            |
| `tool_param_strict_mode` | `true`         | 确保工具函数参数的精确匹配，避免单位或格式错误 |

## 容易做错的三处
- 调用工具时返回 HTTP 500 错误，现象是日志显示 `{"object":"error","message":"Only allowed now"}`。原因可能是工具服务端的认证令牌过期或权限配置不当。
- 工具调用后，参数被正常解析但实际操作未执行。原因通常是工具函数内部逻辑未能正确处理接收到的参数值，例如单位不匹配导致的数据校验失败。
- 查询结果中缺少关键的产品规格或批次信息。原因可能是RAG召回阶段未能获取到包含完整结构化数据的文档块，或者工具函数未能正确从非结构化文本中提取所有必要字段。

## 怎么确认配好了
- 针对典型产品查询，模拟用户输入，检查工具是否能准确识别产品名称、货号、规格等关键信息，并成功调用后台接口获取数据。
- 验证工具函数在处理不同计量单位（如 `µM`、`nM`、`mg/mL`）的参数时，是否能正确转换或匹配，不出现单位错误导致的逻辑中断。
- 导入包含更新信息的最新产品目录或COA文档，检查知识库的增量更新机制是否生效，并能通过工具调用查询到最新的产品批次或技术参数。
- 观察工具调用日志，确保没有出现如 `HTTP 500` 或 `parameter missing` 等错误状态码，且每次调用都能在预设的 `PARSE_FILE_TIMEOUT_SECONDS` 内完成。
