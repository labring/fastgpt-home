# 家用医疗产品的HTTP 接口与外部系统

## 这个品类的数据长什么样

家用医疗产品的数据来源广泛，包括制造商官方网站、产品说明书、技术文档、临床试验报告以及用户反馈平台。这些数据更新频率相对较低，通常随产品迭代或法规更新而调整，例如每年发布新版本或修订说明。产品文档常以 PDF、Word 或结构化 XML 格式存在，内容涵盖产品规格、使用方法、禁忌症、维护保养、故障排除等。字段方面，常见的有产品型号 `product_model`、序列号 `serial_number`、生产批次 `batch_number`、有效期 `expiration_date`、注册证号 `registration_number`、适用人群 `target_user`。单位方面，血压计数据会涉及 mmHg，血糖仪涉及 mmol/L 或 mg/dL，而测量结果通常带有时间戳 `timestamp` 和数值 `value`。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

家用医疗产品数据更新频率低，意味着对外部系统的数据同步实时性要求不高，但对数据准确性和完整性要求极高。文档结构多样化，例如 PDF 和 XML 格式并存，需要 HTTP 接口具备强大的文档解析能力，能够处理不同格式的非结构化和半结构化数据。字段名称和单位的标准化程度不一，例如血糖浓度单位差异，要求接口在数据摄取时进行单位转换或明确标识，避免混淆。此外，部分数据可能涉及用户健康隐私，要求 HTTP 接口在数据传输和存储过程中遵循严格的安全协议，如 HTTPS 加密传输。由于产品生命周期长，历史数据和旧版文档的查询需求也较多，接口需要支持对版本化数据的有效索引和检索。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `API_ENDPOINT` | 制造商官方开放 API 或数据服务接口 | 确保数据来源的权威性和准确性 |
| `REQUEST_TIMEOUT_SECONDS` | `60 秒` | 多数制造商 API 响应时间在合理范围，避免长时间等待 |
| `MAX_BODY_SIZE_MB` | `100 MB` | 考虑 PDF 或 XML 文档可能较大，允许传输足够大的请求体 |
| `AUTH_TOKEN_LIFETIME_HOURS` | `24 小时` | 减少频繁令牌刷新，平衡安全性和便利性 |
| `RETRY_ATTEMPTS` | `3 次` | 应对网络瞬时抖动或服务器临时过载，提高请求成功率 |
| `DATA_PARSING_SCHEMA` | 按实测标定 | 根据具体产品文档的 XML Schema 或 JSON Schema 定义 |

## 容易做错的三处

*   调用接口时收到 `413 Payload Too Large` 错误，原因是上传的文档或数据包大小超过了服务器设定的限制。
*   接口返回的字段值为空或单位不一致，原因是没有正确配置数据解析规则或未进行单位转换。
*   数据同步后，部分旧版产品信息未能及时更新，原因是没有正确处理制造商提供的版本控制字段。

## 怎么确认配好了

*   通过调用接口获取一个典型产品的完整信息，核对关键字段如 `product_model`、`registration_number` 与官方文档一致。
*   上传一个包含不同数据格式（如 PDF 说明书和 XML 规格）的请求，检查系统是否能正确解析并提取出文本内容。
*   模拟一次数据更新操作，确认系统能够识别并处理产品版本号 `version_number` 的变化，从而同步最新信息。
