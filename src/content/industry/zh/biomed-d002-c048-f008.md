# 家用医疗产品的工具调用与插件

## 这个品类的数据长什么样

家用医疗产品的数据具有多源异构的特点。它们通常来源于制造商的官方网站、产品说明书、用户手册，以及第三方电商平台的产品详情页。数据更新频率相对较低，主要集中在新产品发布、旧产品迭代或法规政策调整时。文档结构以半结构化为主，包含产品参数、功能描述、使用方法、禁忌事项、售后服务等。字段方面，常见的有产品型号、批次号、生产日期、有效期、适用人群、测量范围、精度、电源类型等。单位则涵盖国际单位制（如毫米、克、摄氏度、伏特）以及特定医疗领域的计量单位（如毫米汞柱、血糖单位）。

## 这些特征在「工具调用与插件」这一环带来什么约束

家用医疗产品数据的多源性要求工具调用能灵活适配不同数据接口，例如通过网页抓取或API集成。数据更新频率低意味着历史数据沉淀价值高，但同时也需定期检查新版本或修订。半结构化的文档结构决定了在解析时需要兼顾结构化字段提取和非结构化文本理解，这可能需要更复杂的正则匹配或自然语言处理能力。特定字段和单位的存在，要求工具在处理时能正确识别并进行单位转换或校验，以避免因单位混淆导致的信息误判。例如，血压计的测量单位与血糖仪的测量单位存在显著差异，工具必须能准确区分。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | 4000 字符 | 兼顾产品说明书的完整性和模型处理效率 |
| `分段长度` | 800 字符 | 适应家用医疗产品文本段落逻辑，保持语义完整性 |
| `召回条数` | 5 条 | 平衡召回广度与模型处理负荷，确保核心信息不遗漏 |
| `相似度阈值` | 按实测标定，例如 0.75 | 区分度高，过滤无关内容，避免低相关信息干扰 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 180 秒 | 确保大型PDF说明书有足够时间解析 |
| `tool_call_timeout` | 60 秒 | 应对外部工具接口响应慢的情况，避免长时间阻塞 |

## 容易做错的三处

*   调用外部API时出现 `401 Unauthorized` 错误，原因在于 API 密钥未正确配置或已过期。
*   上传产品说明书PDF后，知识库检索结果为空，现象是 `embedding` 失败或 `chunk` 数量为零，原因可能是文件过大或解析超时。
*   查询特定产品参数时，返回结果缺少关键字段，例如血压计的“测量范围”或血糖仪的“校准方法”，原因在于工具函数未能正确从非结构化文本中提取所有必要信息。

## 怎么确认配好了

*   上传典型产品说明书（例如血压计、体温计），检查 `分段长度` 是否符合预期，并且每个 `chunk` 都具有可读的上下文。
*   通过模拟用户提问，验证工具调用是否能准确识别问题意图并调用正确的外部工具或插件。
*   针对多个产品参数进行查询，核对返回结果中的字段与单位是否与原始数据源一致，并检查是否有遗漏。
*   监控工具调用日志，确认外部 API 调用成功，且响应时间在可接受范围内。
