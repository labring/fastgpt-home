# 工艺验证产品的工具调用与插件

## 这个品类的数据长什么样

工艺验证数据主要来源于实验室分析报告、生产批次记录、设备校准报告和偏差调查文档。数据更新频率通常与生产批次和验证阶段同步，可能为每周、每月或每季度。文档结构以结构化表格和非结构化文本混合为主，涉及实验方案、原始数据、分析结果、结论与批准等部分。字段包括批次号、设备ID、样品ID、检测项目、检测方法、结果值、单位（如 %、ppm、mg/L、kPa）、偏差代码、处理措施和批准状态。单位的精确性和一致性要求极高，通常符合 GLP/GMP 规范。

## 这些特征在「工具调用与插件」这一环带来什么约束

工艺验证数据的混合结构对工具调用提出挑战，需要兼顾结构化字段的精确匹配与非结构化文本的语义理解。更新频率限制了实时数据同步的需求，更侧重于批次或阶段性数据的集成。文档中严格的单位要求，使得工具在处理数值时需进行单位识别与转换，避免因单位不一致导致的数据误判。偏差代码和处理措施等字段，需要工具能触发工作流进行关联查询或建议。此外，对历史批次数据的追溯能力，要求工具能够处理大规模、多版本的数据集，并保证查询效率。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `8000` | 兼顾长文档理解与模型推理成本 |
| `召回条数` | `前 5 条` | 提高相关性，减少无关信息干扰 |
| `相似度阈值` | `0.75` | 确保召回结果与查询意图高度匹配 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 适应大型工艺验证报告的解析时间 |
| `分段长度` | `1000 字符` | 优化长文本分段，保持语义完整性 |
| `重排返回条数` | `3 条` | 在高召回率基础上，进一步精炼关键信息 |

## 容易做错的三处

*   工具调用失败，日志显示 `HTTP 500` 错误。原因：外部 API 接口鉴权信息过期或参数格式不符。
*   模型未能正确提取检测结果数值，返回空值。原因：非结构化报告中数值单位多样，未能被工具内置单位识别器覆盖。
*   大模型响应耗时过长，有时达到 `10-15s`。原因：调用的外部服务（如数据库查询、文件解析）响应延迟高，或模型本身推理速度慢。

## 怎么确认配好了

*   通过测试用例，验证工具调用能够准确识别批次号 `BATCH-20230815-001` 等关键字段并返回正确结果。
*   检查工具调用日志，确认没有出现 `401 Unauthorized` 或 `404 Not Found` 等错误码。
*   对包含不同单位（如 `mg/L` 和 `ppm`）的测试数据进行查询，确认工具能正确处理并转换。
