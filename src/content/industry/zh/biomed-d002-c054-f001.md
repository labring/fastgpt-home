# 康复设备产品的HTTP 接口与外部系统

## 这个品类的数据长什么样

康复设备的数据通常包含设备型号、序列号、生产日期、质保期、功能参数（如最大承重、调节范围、运动模式）、耗材清单、维护记录、以及相关认证信息。数据源多样，包括设备制造商的官方数据库、医疗机构的采购系统、以及第三方服务商的维修保养平台。更新节奏方面，新产品发布、软件版本迭代、耗材更换、维修事件等均会触发数据更新，频率从每月数次到每年数次不等。文档结构以半结构化为主，JSON 或 XML 格式常见，但也存在大量 PDF 格式的产品手册和技术规范。字段名称通常遵循行业标准，如 ISO 13485 相关规范，单位则严格按照国际单位制（SI），例如长度单位为毫米（mm）、重量单位为千克（kg）、功率单位为瓦特（W）。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

康复设备数据来源多样且更新频率不一，要求 HTTP 接口设计时需考虑多源数据集成策略，例如通过定时任务拉取或事件驱动回调。半结构化和 PDF 格式的文档特性，使得接口在处理数据时需要具备灵活的解析能力，对 PDF 文档可能需要引入 OCR 或文档解析服务。字段与单位的标准化要求，意味着接口在数据传输和存储时需要进行严格的数据类型校验和单位转换，以确保数据一致性。例如，某些设备可能以磅为单位报告重量，而系统内部统一使用千克，则需要明确的转换逻辑。此外，质保期、维护记录等敏感信息，对接口的鉴权和授权机制提出了更高要求，确保只有获得授权的外部系统才能访问特定数据，避免未授权访问导致的 `unAuthChat` 错误。

| `maxContext`                 | `4000 字符`    | 康复设备说明书常见段落长度，保证一次召回能覆盖完整功能描述。 |

| `分段长度`                   | `800 字符`     | 适配康复设备技术文档中常见的功能模块或维护步骤描述。         |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`       | 康复设备产品手册通常较大，需充足时间完成解析，避免解析超时。 |

## 容易做错的三处

*   HTTP 请求发送两次，第二次鉴权失败：这通常是由于客户端或代理层在首次请求失败后自动重试，但重试逻辑未能正确携带或刷新鉴权信息，导致第二次请求的 `Authorization` 头部失效。
*   调用接口返回 `unAuthChat`：接口调用时提供的 API Key 或 Token 权限不足，或者在请求头部 `Authorization` 字段中缺失、格式不正确。
*   API 上传文件时文件名中文乱码：外部系统在发送文件时未正确设置 `Content-Disposition` 头部中的 `filename` 编码，导致服务器端解析时出现字符集不匹配。

## 怎么确认配好了

*   通过 FastGPT 后台日志查看 HTTP 接口调用记录，核对请求 URL、HTTP 方法、请求头和响应体是否符合预期。
*   上传一个包含中文文件名的康复设备产品手册，检查知识库中文件名称是否正常显示，无乱码现象。
*   使用一个已知权限受限的 API Key 尝试调用受保护的接口，确认系统返回 `unAuthChat` 或类似的鉴权失败信息。
*   针对一个典型的康复设备查询场景，通过接口发起提问，检查返回结果是否包含相关设备的功能参数、维护建议等信息，并核对字段单位是否一致。
