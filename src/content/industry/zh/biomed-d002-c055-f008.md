# 影像设备产品的工具调用与插件

## 这个品类的数据长什么样

影像设备的数据来源多样，通常包括设备制造商提供的技术手册、产品规格书、临床应用指南以及固件更新日志。这些文档以 PDF、XML 或专有数据库格式存在，更新频率通常与产品生命周期和软件版本迭代同步，可能为季度或半年一次。文档结构复杂，包含大量专业术语、图表和表格。关键字段如“成像模式”、“空间分辨率”、“信噪比”、“扫描时间”、“辐射剂量”等，单位涉及毫米、特斯拉、毫安秒、毫希沃特等，且不同厂商对同一概念的表述可能存在差异。此外，设备产生的 DICOM 图像元数据也包含丰富的设备配置信息。

## 这些特征在「工具调用与插件」这一环带来什么约束

影像设备数据的高度专业性和文档复杂性，使得直接的文本匹配或关键词搜索效果有限。工具调用需要能够解析结构化与非结构化混合数据，并理解其中的专业术语和上下文关联。例如，查询特定成像模式下的设备性能参数时，插件必须能识别文档中散布的参数表，并根据用户输入进行单位换算或范围判断。更新频率相对较低，意味着无需频繁触发数据同步工具。然而，一旦有新版本发布，则需要插件能够高效识别并整合新旧版本间的差异。DICOM 元数据的存在，要求插件具备解析这类特殊二进制格式的能力，以提取设备型号、序列参数等信息，辅助问答。

## 配置怎么定

| 配置项                   | 建议取法                                           | 这样取的依据                                                 |
| :----------------------- | :------------------------------------------------- | :----------------------------------------------------------- |
| `maxContext`             | 3000–4000 字符                                     | 影像设备文档段落长，确保模型能获取足够上下文理解专业描述。   |
| `similarityThreshold`    | 0.78–0.85                                          | 术语专业且存在同义词，高阈值可提高召回精确度。               |
| `maxRetrieve`            | 15–20 条                                           | 提升相关信息覆盖率，应对文档结构复杂和信息分散的情况。       |
| `toolCallThreshold`      | 0.7                                                | 影像设备问答通常需要精确数据，避免不必要的工具调用或误判。   |
| `PARSE_FILE_TIMEOUT_SECONDS` | 180 秒                                             | 大型技术手册解析时间较长，预留充足处理时间。                 |
| `DICOM_PARSER_ENABLED`   | `true`                                             | 启用 DICOM 元数据解析，利用图像数据中的设备配置信息。        |

## 容易做错的三处

*   模型未调用自定义插件，直接给出通用回答。原因在于插件描述不够清晰或触发条件过于严格，模型无法判断何时需要调用。
*   插件调用后返回数据为空或不完整。原因可能是外部接口返回格式与预期不符，或解析逻辑未能正确处理文档中特定字段的缺失或异常值。
*   查询特定参数时，模型返回的数值单位错误。原因在于文档中存在多种单位制，插件在提取或转换时未明确指定目标单位。

## 怎么确认配好了

*   针对多种成像模式、设备型号和性能参数组合提问，核对模型是否准确调用了相关插件，并返回了正确、完整的技术规格。
*   上传一份包含 DICOM 图像元数据的测试文件，并询问关于设备配置的问题，确认 `DICOM_PARSER_ENABLED` 参数生效且解析无误。
*   故意提出需要进行单位换算的查询（例如，询问以英制单位表示的尺寸），验证插件的单位处理逻辑是否正确执行。
