# 心血管介入产品的HTTP 接口与外部系统

## 这个品类的数据长什么样

心血管介入产品的数据通常来源于医疗器械制造商的产品目录、临床研究报告、销售数据和合规文件。这些数据更新频率相对较低，新品发布或现有产品迭代通常以季度或年度为周期。文档结构复杂，常包含产品规格书（例如尺寸、材料、涂层）、使用说明书、注册证信息、临床证据摘要以及不良事件报告。字段与单位具有高度专业性，例如球囊导管的“标称压力（atm）”、“通过性（mm）”、“推送杆直径（F）”，支架的“径向力（N）”、“镍钛合金含量（%）”等，以及器械的“预期寿命（年）”、“灭菌方式”等关键信息。部分数据可能以 PDF 扫描件或非结构化文本形式存在。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

心血管介入产品数据更新频率低，意味着对外部系统的实时性要求不高，但对数据完整性和准确性的要求极高。复杂且专业的字段与单位，要求在 HTTP 接口设计时，对数据模型进行精细化定义，避免信息丢失或误解。非结构化文档的存在，如 PDF 版的产品说明书和临床报告，对外部系统的文件解析能力构成挑战，需要支持 OCR 和高级文本提取技术。此外，由于医疗器械数据的合规性要求，HTTP 接口需考虑数据加密传输（HTTPS）和严格的访问控制。数据源分散于不同制造商的系统，要求外部系统具备灵活的多源数据集成能力，并能处理不同数据格式与接口规范。

## 配置怎么定

| 配置项                   | 建议取法       | 这样取的依据                                   |
| :----------------------- | :------------- | :--------------------------------------------- |
| `maxRequestTimeout`      | `600 秒`       | 应对大型文件解析及复杂数据处理的潜在耗时       |
| `concurrencyLimit`       | `5`            | 平衡数据源系统负载与数据同步效率               |
| `chunkSize`              | `1000 字符`    | 适应产品规格书等文档中细节描述的长度           |
| `embeddingModel`         | `text-embedding-ada-002` | 适用于医疗器械专业术语的语义理解             |
| `sslVerifyPeer`          | `true`         | 确保与外部系统通信的安全性，避免证书问题       |
| `proxyBypass`            | `按实测标定`   | 依据部署环境，确定是否需要代理或绕过代理       |

## 容易做错的三处

*   HTTP 请求返回 `404 page not found` 错误，原因通常是 API 路径或端点配置不正确，未能指向外部系统正确的资源地址。
*   解析医疗器械产品的规格数据时，特定字段（如“标称压力”、“推送杆直径”）为空或格式异常，这往往是由于外部系统返回的数据结构与预期不符，或解析器未能正确处理非标准单位与特殊字符。
*   集成外部系统时遇到 `self-signed certificate` 错误，这表示外部系统的 SSL 证书未经公共 CA 机构签发，需要配置信任该自签名证书或禁用证书校验（不推荐）。

## 怎么确认配好了

*   通过 FastGPT 的调试工具向配置的 HTTP 接口发送测试请求，核对返回的 JSON 结构与预期产品数据模型一致。
*   导入一份包含心血管介入产品规格书的 PDF 文档，检查其关键字段（例如“尺寸”、“材料”）是否被正确提取并索引。
*   模拟用户查询“某款支架的径向力是多少”，验证返回结果中包含准确的数值与单位，且与原始数据来源相符。
*   检查系统日志，确认没有与 HTTP 请求相关的 SSL/TLS 握手失败或连接超时错误。
