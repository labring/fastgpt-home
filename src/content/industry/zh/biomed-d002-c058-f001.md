# 患者援助产品的HTTP 接口与外部系统

## 这个品类的数据长什么样
患者援助项目的数据通常来源于药企内部的 CRM 系统、药房管理系统或第三方患者服务平台。这些数据更新频率相对较低，通常按月或按季度进行批量同步，紧急情况可能触发实时更新。文档结构以结构化数据为主，常采用 JSON 或 XML 格式，包含患者基本信息、诊断信息、用药记录、援助方案状态、随访记录等。字段名多为英文缩写或拼音，例如 `patientId`、`diagnosisCode`、`drugName`、`assistanceStatus`。单位方面，剂量常用毫克（mg）或克（g），时间单位多为天（day）或月（month），金额单位为人民币元（CNY）。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
患者援助数据的低更新频率决定了 FastGPT 在集成时无需频繁轮询外部接口，减少不必要的系统开销。结构化数据为主的特点，使得 `HTTP 请求体`和`响应体`的解析规则相对固定，便于预设解析模板。字段名缩写和拼音的特性，要求在 FastGPT 侧配置接口时，需仔细映射内部知识库的字段，确保语义准确。金额、剂量等数值单位的存在，意味着在数据传输和处理过程中需要进行严格的类型校验，防止因单位不一致导致的数据错误或混淆。患者敏感信息的处理，则强制要求接口采用 HTTPS 协议，并实施严格的身份认证和授权机制，确保数据安全。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `请求方法` | `POST` 或 `GET` | 依据外部系统 API 文档规定，查询类多为 `GET`，操作类多为 `POST`。 |
| `请求URL` | 外部系统提供的 API 地址，例如 `https://api.example.com/pa_data/query` | 确保 FastGPT 能够正确访问到外部数据源。 |
| `请求头` (`Authorization`) | `Bearer <API_KEY>` 或 `Basic <BASE64_CREDENTIALS>` | 外部系统接口认证要求，保障数据访问安全。 |
| `超时时间` (`timeout`) | `60 秒` | 患者援助数据查询可能涉及复杂业务逻辑，预留足够响应时间，避免因后端处理慢导致连接中断。 |
| `响应体解析规则` (`responseParser`) | `JSONPath` 表达式，例如 `$.data.list[*]` | 结构化 JSON 响应体，通过路径精确提取所需字段数据。 |
| `错误码处理` (`errorHandler`) | 检查 `$.code` 字段，例如 `{"code": 401, "message": "鉴权失败"}` | 识别外部接口返回的业务错误码，进行针对性错误提示或重试。 |

## 容易做错的三处
*   现象：FastGPT 查询患者援助数据时响应缓慢，甚至出现超时。原因：外部系统 API 接口处理复杂查询时耗时过长， FastGPT 的 `超时时间` 配置过短，未能等待完整响应。
*   现象：从外部系统获取的患者援助方案状态字段为空或解析错误。原因：外部系统返回的 JSON 响应中，相关字段名与 FastGPT 中 `响应体解析规则` 配置的 `JSONPath` 表达式不匹配，导致无法正确提取数据。
*   现象：调用外部系统接口时收到 `HTTP 401 Unauthorized` 错误。原因：`请求头`中 `Authorization` 参数未正确配置，例如 `API_KEY` 过期或格式有误，导致鉴权失败。

## 怎么确认配好了
*   在 FastGPT 接口配置界面，使用模拟数据进行 `测试` 运行，检查返回的 HTTP 状态码是否为 `200`，并确认响应体数据是否能被正确解析。
*   通过 FastGPT 的 `调试` 功能，观察实际请求日志，核对 `请求URL`、`请求头`、`请求体`等参数是否与外部系统 API 文档要求一致。
*   在 FastGPT 中，使用实际患者 ID 进行一次知识库问答，验证系统能否通过配置的 HTTP 接口成功查询并展示相关患者援助信息，并检查金额、剂量等关键数值字段的单位是否正确。
