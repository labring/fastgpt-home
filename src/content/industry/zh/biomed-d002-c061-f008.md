# 手术机器人产品的工具调用与插件

## 这个品类的数据长什么样

手术机器人产品的数据来源多样，包括产品说明书、技术白皮书、临床报告、维护手册以及软件更新日志。这些文档通常以 PDF、Word、XML 或结构化数据库的形式存在。数据更新频率相对较低，主要集中在产品型号迭代、软件版本升级或新的临床应用发布时。文档结构复杂，包含大量专业术语、图表、操作流程和技术参数。字段与单位具有高度专业性，例如“自由度”（Degrees of Freedom）、“重复定位精度”（Repeatability Accuracy，单位毫米或微米）、“力反馈阈值”（Force Feedback Threshold，单位牛顿）以及“手术路径规划算法版本号”。部分数据可能存在于私有数据库或 API 接口中，需要特定的认证和授权才能访问。

## 这些特征在「工具调用与插件」这一环带来什么约束

手术机器人产品数据的高度专业性和复杂文档结构，要求工具调用与插件能够精确解析和理解多模态信息，例如从 PDF 中提取表格数据或从图像中识别关键部件。低更新频率意味着知识库构建时需要重点关注历史数据的完整性和版本管理，确保检索结果的时效性与准确性。专业字段与单位的特殊性，使得在进行参数查询或产品对比时，需要插件具备单位转换或量纲校验能力，避免因单位不匹配导致的误判。数据访问权限的限制，则要求工具调用机制能够支持多种认证方式，并能安全地与内部系统集成，确保数据合规性和安全性。此外，由于涉及医疗器械，对工具调用的响应速度和错误处理机制有更高的要求，以保障信息获取的及时性和可靠性。

## 配置怎么定

| `maxContext`                 | `3000-4000` 字符                                | 手术机器人文档单篇信息密度高，需保证足够长的上下文窗口以捕获关键技术细节和操作步骤。                                                                                                                                |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300-600` 秒                                    | 处理大型技术白皮书或包含复杂图表的 PDF 文件时，解析时间可能较长，需要更长的超时时间以避免解析失败。                                                                                                                |

## 容易做错的三处

*   工作流中工具调用在运行模式下报错，但在调试模式下正常运行，这通常是由于运行环境与调试环境的网络隔离或权限配置差异导致，例如生产环境缺少对特定内部 API 的访问权限。
*   调用 `marker-pdf` 这类解析工具时出现连接失败，即使尝试 `127.0.0.1` 也无效，这可能是 Docker 容器内部网络配置问题，容器无法正确解析或路由到宿主机上的服务，或者服务未正确暴露端口。
*   知识库问答对提取一直卡在“训练中”状态，且日志无调用记录，这表明后台任务队列或资源调度出现问题，可能是训练服务崩溃或任务调度器未能正确启动训练流程。

## 怎么确认配好了

*   通过构造包含手术机器人产品型号、关键性能参数的查询，验证工具调用能够准确从知识库或外部接口中提取并呈现对应数据，核对返回的“自由度”、“重复定位精度”等字段值是否与原始文档一致。
*   模拟一次对特定试剂供应商库存或价格的查询，检查工具调用能否成功触发外部 API，并获取到正确的“批次号”或“有效期”等信息，同时观察响应时间是否在预期范围内。
*   上传一份新的手术机器人技术白皮书，检查知识库能否正确解析文档内容，并能在后续查询中召回其中提及的“手术路径规划算法版本号”等专业术语，通过比对召回结果与原文内容，评估解析准确度。
