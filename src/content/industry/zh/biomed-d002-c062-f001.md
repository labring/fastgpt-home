# 批记录审核产品的HTTP 接口与外部系统

## 这个品类的数据长什么样
批记录审核涉及的数据源于制药企业生产线的电子批记录系统。这些数据通常以结构化或半结构化形式存在，包含生产设备参数、物料批次信息、操作员签名、偏差记录、中间产品检测结果及成品放行数据。数据更新频率较高，通常在批次生产结束后立即生成，并可能在审核过程中进行少量补充或修正。文档结构复杂，常包含表格、文本描述和附件（如分析报告PDF）。关键字段包括批号、产品代码、生产日期、有效期、关键工艺参数（如温度、压力、时间）、偏差类型与描述、审核状态、审核人及审核意见。单位多样，涉及质量（kg, mg）、体积（L, mL）、温度（℃）、时间（min, h）等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
批记录数据的高度结构化与复杂性要求HTTP接口能够处理多层嵌套的JSON或XML数据结构。数据更新的实时性要求接口具备高并发处理能力，以应对生产线批次数据提交的峰值，并确保数据一致性。文档中包含的文本描述和附件，特别是偏差记录和审核意见，对接口的文本处理能力提出挑战，需要支持长文本字段和文件上传/下载。字段与单位的多样性意味着在数据传输和解析时需要严格的类型校验和单位标准化，以避免数据误读或计算错误。此外，批记录的合规性要求所有数据传输和操作都必须有审计日志，并在接口层面确保数据完整性和安全性。

## 配置怎么定

| 配置项                       | 建议取法       | 这样取的依据                                   |
| :--------------------------- | :------------- | :--------------------------------------------- |
| `requestTimeout`             | `30000 ms`     | 批记录数据量大，避免因网络延迟或处理时间过长而超时 |
| `maxConnections`             | `50`           | 应对多批次并发提交，保障生产数据实时上传       |
| `payloadSizeLimit`           | `50 MB`        | 批记录可能包含附件，确保大文件传输能力         |
| `retryAttempts`              | `3`            | 提高数据传输的可靠性，应对瞬时网络抖动         |
| `header.X-API-Key`           | 按实测标定     | 用于身份验证和访问控制，确保数据安全           |
| `dataValidationSchema`       | JSON Schema 规范 | 确保传入数据的结构和类型符合批记录标准         |

## 容易做错的三处
- 现象：API 调用长时间无响应，最终返回 `HTTP 504 Gateway Timeout`。原因：`requestTimeout` 设置过短，无法处理批记录数据量大或服务器处理耗时长的请求。
- 现象：部分批记录数据提交成功，但附件（如分析报告）丢失或无法解析。原因：`payloadSizeLimit` 限制过小，导致包含大尺寸附件的请求被截断。
- 现象：业务系统对接后，无法区分不同用户提交的批记录数据。原因：API 调用缺少用户标识符（如 `X-User-ID`），导致后端系统无法关联具体操作者。

## 怎么确认配好了
- 调用批记录提交接口，使用包含标准文本和多个大尺寸附件的模拟批记录数据，确认返回 `HTTP 200 OK` 状态码。
- 模拟高并发场景，连续发送数十个批记录提交请求，观察系统响应时间和错误率，确保在可接受范围内。
- 检查后端系统日志，确认每次成功的接口调用都记录了完整的请求信息，包括请求头中的身份验证信息和用户标识符。
- 随机抽取已提交的批记录数据，核对关键字段值、文本描述和附件内容是否与原始数据完全一致。
