# 护理管理产品的HTTP 接口与外部系统

## 这个品类的数据长什么样
护理管理产品的数据核心在于患者个体化护理计划、执行记录与效果评估。数据来源多样，包括电子病历系统（EMR）、生命体征监测设备、医嘱系统、以及护士通过移动终端录入的患者状态与干预措施。数据更新频率高，例如生命体征数据可能每小时更新，用药记录与护理操作日志则实时生成。文档结构通常包含结构化数据（如患者 ID、床位号、诊断、用药剂量、护理类型代码）和大量的非结构化文本（如护士评估记录、患者反馈、护理观察日志）。字段单位涉及计量单位（如 `mg`、`ml`、`mmHg`、`℃`）、时间单位（`h`、`min`）以及状态描述（如“清醒”、“嗜睡”）。这些数据共同描绘了患者在特定护理周期内的动态健康画像。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
护理管理数据的多样性与高更新频率对 HTTP 接口的设计提出了特定要求。结构化数据需要高效的字段映射与类型转换，以确保数据一致性。非结构化文本数据，尤其是护理观察日志，其长度不固定且包含大量专业术语，需要接口支持大文本传输，并在上游处理时考虑文本嵌入与语义理解。实时性要求使得接口设计需支持高并发与低延迟响应，例如患者生命体征异常报警或紧急医嘱下达，数据传输时延需控制在毫秒级。字段单位的标准化是关键，不同系统可能使用不同的缩写或表达方式，接口层需进行统一转换，避免数据混淆。此外，鉴于数据敏感性，接口的安全认证与授权机制 (`Authorization` 头、`API Key`) 至关重要，确保数据传输的合规性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `requestTimeout` | `60000 ms` | 应对非结构化文本传输和大批量数据同步可能产生的延迟。 |
| `maxConnections` | `100` | 支持高并发场景下的数据实时更新与查询，如多护士同时录入。 |
| `payloadSizeLimit` | `50 MB` | 适应包含大量护理日志、图片等非结构化数据的请求体大小。 |
| `retryAttempts` | `3` | 提高数据传输的可靠性，应对网络瞬时波动或外部系统短暂不可用。 |
| `authTokenRefreshInterval` | `3600 seconds` | 平衡安全与接口调用便利性，减少频繁认证开销。 |

## 容易做错的三处
*   现象：外部系统接收到的护理日志文本出现截断或乱码。
    原因：接口未正确设置 `Content-Type` 为 `application/json; charset=UTF-8` 或未对大文本字段进行适当编码。
*   现象：生命体征数据更新后，FastGPT 中模型响应仍基于旧数据。
    原因：外部系统数据同步接口触发频率过低，或 FastGPT 内部缓存策略未及时失效。
*   现象：调用外部系统API时返回 `HTTP 401 Unauthorized` 错误。
    原因：`API Key` 或 `Bearer Token` 配置错误，或其有效期已过，未能及时刷新。

## 怎么确认配好了
*   通过模拟高并发请求，观察HTTP接口的响应时间与成功率，确保在峰值负载下仍能稳定运行。
*   核对FastGPT中模型问答结果，验证其是否能准确引用最新同步的护理计划、用药记录等关键信息。
*   检查外部系统日志与FastGPT的接口调用日志，确认数据传输的请求体大小、响应状态码与传输耗时符合预期。
