# 护理管理产品的表单与交互

## 这个品类的数据长什么样

护理管理产品的数据来源多样，包括电子病历系统（EHR）、患者穿戴设备、护理记录、以及患者自述信息。数据更新频率较高，部分生理指标数据可达分钟级，护理计划和执行记录则为每日或每次护理活动后更新。文档结构通常包含结构化的患者基本信息、诊断、用药记录、护理计划（长期、短期目标）、护理评估（主观、客观数据）、干预措施、效果评价，以及非结构化的护理日志和医嘱。字段包括患者 ID、姓名、年龄、性别、诊断、过敏史、生命体征（血压、心率、体温、呼吸频率、血氧饱和度）、疼痛评分、跌倒风险评估、压疮风险评估、用药依从性、功能状态评分（ADL/IADL）、以及护理人员的观察和记录。单位统一性较好，例如血压为 mmHg，体温为 ℃，血氧为 %。

## 这些特征在「表单与交互」这一环带来什么约束

护理管理数据的高更新频率要求表单能够快速响应并同步最新数据，避免信息滞后导致的决策偏差。结构化与非结构化数据并存的特点，使得表单设计既要支持精确的数据录入，也要提供灵活的文本输入区域，以捕获护理日志等非标信息。生命体征、评分量表等字段的标准化单位，在表单交互中需要有明确的单位提示或自动单位转换功能，减少录入错误。患者信息的多维度关联性，要求表单在录入或查询时能快速关联相关历史数据，例如在评估跌倒风险时能自动调取患者既往跌倒史。此外，涉及敏感健康数据，表单和交互设计必须严格遵循数据隐私保护规范，确保信息安全。

## 配置怎么定

| 配置项             | 建议取法                               | 这样取的依据                                   |
| :----------------- | :------------------------------------- | :--------------------------------------------- |
| `maxContext`       | `3000 Tokens`                          | 需覆盖完整护理记录和相关病史，超出易丢失关键信息 |
| `分段长度`         | `800-1200 字符`                        | 兼顾语义完整性与召回效率，避免长段落信息冗余   |
| `召回条数`         | `前 8 条`                              | 确保覆盖多维度护理信息，同时控制 LLM 输入规模  |
| `相似度阈值`       | `0.75`                                 | 精准匹配护理计划或评估，降低不相关信息干扰     |
| `重排返回条数`     | `前 5 条`                              | 提供最相关的核心信息，便于护理人员快速查阅     |
| `PARSE_FILE_TYPE`  | `PDF`, `DOCX`, `TXT`, `JSON`           | 涵盖常见护理记录和报告格式                     |

## 容易做错的三处

- 交互表单加载缓慢或提交失败，原因是后端数据接口频繁请求或数据量过大导致超时。
- 患者信息查询结果不准确，原因是对非结构化护理日志的语义理解不足，未能正确提取关键信息。
- 护理建议生成内容与患者实际情况不符，原因是在多模态数据融合时，模型未充分考虑实时生理指标数据的权重。

## 怎么确认配好了

- 验证表单提交后，核心护理数据字段（如生命体征、用药记录）在后台数据库中的准确性和实时性。
- 在不同网络环境下，测试表单加载速度和数据同步延迟，确保响应时间符合预期。
- 模拟多种典型患者案例，输入不同的护理记录和评估数据，检查系统给出的建议与实际护理指南的一致性。
- 检查历史护理记录查询功能，确保能够根据患者 ID 或时间范围，准确召回并展示所有相关护理信息。
