# 招标挂网产品的HTTP 接口与外部系统

## 这个品类的数据长什么样

生物医药领域的招标挂网产品数据，主要来源于各省市药品集中采购平台、医用耗材阳光采购平台以及部分商业招采信息发布平台。这些平台的数据更新频率不一，省级平台通常按月或季度发布中标/挂网结果，临时调整或补录信息则可能每周更新。数据文档形式多样，常见为 Excel 表格或 PDF 公告，部分平台提供结构化的 API 接口。核心字段包括产品名称、生产企业、注册证号、剂型/规格、挂网价格、挂网时间、采购区域及有效期限。价格字段通常精确到小数点后两位，单位涉及元/盒、元/支、元/片等，需注意单位换算。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

招标挂网数据的分散性与非标准化，对 HTTP 接口的设计提出了挑战。多个数据源意味着需要集成不同的 API 协议或解析多种文档格式。更新频率的不一致性要求外部系统具备灵活的调度机制，以适应不同数据源的更新周期，避免数据滞后或重复抓取。文档结构的多样性，尤其是 Excel 和 PDF 文件，需要强大的数据抽取与清洗能力，将非结构化数据转化为统一的结构化格式。价格单位的不一致性则要求在数据摄入阶段进行标准化处理，确保后续计算与比较的准确性。注册证号等关键标识符的准确提取与匹配，是连接不同数据源和实现数据去重的重要前提。

## 配置怎么定

| 配置项                 | 建议取法                               | 这样取的依据                                       |
| :--------------------- | :------------------------------------- | :------------------------------------------------- |
| `requestTimeout`       | `30000 毫秒`                           | 部分省级平台响应较慢，需预留足够时间防止请求超时。 |
| `maxRetries`           | `3`                                    | 应对网络波动或服务器瞬时故障，提高数据获取成功率。 |
| `concurrencyLimit`     | `5`                                    | 平衡系统资源占用与数据获取效率，避免对目标服务器造成过大压力。 |
| `parseFileChunkSize`   | `2000 字符`                            | 优化大文件（如PDF）的解析效率，降低内存消耗。      |
| `dataValidationSchema` | 按实测标定                             | 确保导入数据的结构与类型符合预期，例如`挂网价格`为浮点数。 |
| `updateFrequency`      | `每天一次` 或 `每周一次`               | 多数招标平台数据变化频率，确保数据时效性。         |

## 容易做错的三处

*   现象：HTTP 请求长时间无响应或返回 `504 Gateway Timeout`。
    原因：目标招标平台服务器负载高或网络延迟，`requestTimeout` 设置过短导致请求未能完成。
*   现象：导入的挂网价格字段出现非数字字符或单位混乱。
    原因：数据源中的价格字段格式不统一，未进行充分的清洗和单位标准化处理。
*   现象：部分挂网产品信息无法导入，系统报错 `Invalid or missing required field: '注册证号'`。
    原因：不同平台的文档对关键字段的命名或格式存在差异，数据抽取时未能正确匹配或识别。

## 怎么确认配好了

*   通过外部系统手动触发一次数据抓取任务，检查日志中是否有 `200 OK` 状态码，并确认返回数据量与预期一致。
*   随机抽取几个已导入的挂网产品，核对其 `挂网价格` 和 `注册证号` 等关键字段，确保数据准确且单位正确。
*   配置一个小型自动化测试，模拟数据源更新后，验证外部系统是否能按预设 `updateFrequency` 成功拉取并处理新增或变更的数据。
