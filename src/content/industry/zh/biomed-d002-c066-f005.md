# 招标挂网产品的多轮对话与提示词

## 这个品类的数据长什么样

生物医药领域的招标挂网数据主要来源于各级政府药品器械集中采购平台、省级公共资源交易中心及医疗机构的采购公示。数据更新频率通常为每月或每季度，涉及新产品挂网、价格调整、中标信息公布等。文档结构以结构化表格为主，例如 Excel、CSV 或 PDF 扫描件中的表格，但也包含非结构化的通知公告、澄清文件。核心字段包括产品名称、通用名、生产企业、注册证号、剂型规格、挂网价格、采购单位、采购数量、中标状态、采购周期等。单位涉及金额（元）、数量（盒/支/片等）、日期（年/月/日）。部分数据可能存在字段命名不规范、单位缺失或不一致的情况，尤其在跨省或跨平台整合时更为突出。

## 这些特征在「多轮对话与提示词」这一环带来什么约束

招标挂网数据以结构化表格为主，要求在多轮对话中能够精准定位特定字段信息。由于更新频率固定且数据量较大，知识库的更新机制需支持批量导入与增量更新，以保证查询时效性。非结构化通知公告的存在，意味着需要结合文本理解能力，从复杂语境中提取关键信息。字段命名不规范和单位不一致，对提示词的鲁棒性提出要求，需要通过同义词或别名映射来提高召回率。多轮对话中，用户可能基于挂网价格、生产企业或采购周期等字段进行筛选和比较，这要求系统能维护对话上下文中的筛选条件，并进行逻辑组合。例如，当用户询问“某产品在A省的挂网价格是多少”后，可能会追问“那B省呢”，此时需要系统能识别并沿用产品名称这一核心实体。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `分段长度` | `500 字符` | 兼顾表格行信息的完整性和文本嵌入模型的处理效率，避免单行过长或过短。 |
| `召回条数` | `前 8 条` | 招标挂网数据检索结果通常较多，增加召回条数可提高覆盖面，减少漏检。 |
| `相似度阈值` | `0.75` | 针对结构化数据，要求较高的相似度以确保检索结果的准确性，避免无关信息干扰。 |
| `maxContext` | `2000 token` | 确保多轮对话中能容纳足够多的历史信息和检索结果，支持复杂条件筛选。 |
| `重排返回条数` | `前 5 条` | 对初次召回的结果进行二次排序，精选出最相关的条目，提升回答质量。 |
| `enableVariable` | `true` | 支持在对话中动态存储和更新查询条件（如产品名、省份），实现多轮筛选。 |

## 容易做错的三处

*   现象：对话中用户询问“某产品在湖南的挂网价”，系统未能返回准确价格，反而给出其他省份的信息或提示知识库未找到。原因：提示词中未有效引导模型优先匹配省份字段，或知识库分段策略导致省份信息与价格信息分离。
*   现象：用户在同一对话中连续追问不同产品的价格时，系统响应速度显著变慢，甚至出现超时。原因：对话历史上下文过长，每次查询都携带了过多的冗余信息，导致模型处理负荷增加。
*   现象：用户输入“XX注射液”，系统无法检索到相关挂网信息，但知识库中实际存在“XX注射剂”的记录。原因：未配置充分的同义词或别名映射，导致用户查询词与知识库中的标准词不匹配。

## 怎么确认配好了

*   选取一批包含产品名称、生产企业、剂型规格、挂网价格等核心字段的测试用例，验证系统在单轮对话中能否准确检索并返回对应信息。
*   设计包含两到三轮筛选条件的对话场景，例如“查询A产品在B省的挂网价格，再问C省的价格”，核对系统能否正确继承和更新查询变量。
*   准备一批包含同义词、错别字或简称的查询词，测试系统是否能通过同义词映射或模糊匹配，成功召回相关挂网数据。
*   模拟用户在不同时间点（例如知识库更新后）进行查询，验证系统返回的数据是否为最新版本，并检查响应时间是否在可接受范围内。
