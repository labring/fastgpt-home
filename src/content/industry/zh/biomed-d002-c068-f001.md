# 智能导诊产品的HTTP 接口与外部系统

## 这个品类的数据长什么样

智能导诊系统所需的数据主要来源于权威医疗机构发布的疾病诊疗指南、药品说明书、医学期刊文献以及临床病例。这些数据更新频率较高，特别是新药上市、诊疗方案调整时，需要及时同步。数据结构通常包含疾病的症状描述、诊断标准、鉴别诊断、治疗方案、预后信息，以及药品的适应症、禁忌症、用法用量、不良反应等。字段设计上，会涉及如 ICD-10 疾病编码、ATC 药品分类编码、SNOMED CT 临床术语等标准化医学术语体系，确保数据准确性和互操作性。单位则严格遵循医学计量标准，例如药物剂量以毫克（`mg`）、毫升（`ml`）计，时间以天（`天`）、小时（`小时`）计。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

智能导诊数据的专业性和高更新频率，对 HTTP 接口的设计和外部系统交互提出了特定要求。首先，数据源头多样且分散，需要接口具备聚合多源信息的能力，例如同时从疾病知识库和药品数据库获取数据。其次，医学术语的标准化使得接口在数据传输时必须严格遵循特定编码规范，例如 `Content-Type` 设置为 `application/json` 并指定 `charset=utf-8` 以支持多语言和特殊字符。高更新频率要求外部系统能够支持定时或事件驱动的数据同步机制，确保导诊信息的时效性。字段的复杂性意味着接口返回的数据结构可能较为深层，需要客户端有较强的解析能力。同时，涉及到患者隐私和医疗安全，接口必须具备严格的身份验证 (`Authorization` header) 和数据加密传输 (HTTPS) 机制，确保数据安全。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `requestTimeout` | `60000 毫秒` | 应对外部医学知识库响应慢或数据量大导致的处理延迟，避免请求超时。 |
| `maxRetries` | `3 次` | 提高数据获取的可靠性，应对临时性网络波动或外部服务不稳定。 |
| `Cache-Control` | `no-cache` | 确保每次请求都能获取到最新的诊疗信息，避免使用过期数据进行导诊。 |
| `Authorization` | `Bearer Token` | 采用标准的 OAuth 2.0 令牌认证，确保接口访问权限的安全性。 |
| `responseBodySizeLimit` | `5 MB` | 限制单个响应体大小，防止因返回超大医学文档导致内存溢出或网络拥堵。 |
| `headers.Accept-Language` | `zh-CN,en-US` | 优先获取中文内容，同时兼容英文，以适应多语言医疗资源。 |

## 容易做错的三处

*   现象：智能导诊结果缺少新上市的药品信息。原因：外部药品数据库的同步策略未能及时拉取最新数据，或接口调用频率过低。
*   现象：导诊建议中的疾病诊断码显示为空或格式错误。原因：HTTP 接口返回的 JSON 字段名与系统预期的不一致，或未正确处理 `SNOMED CT` 等医学术语的编码解析。
*   现象：在对话中上传患者病历文件后，系统无法对文件内容进行分析。原因：文件解析服务 (`PARSE_FILE_TIMEOUT_SECONDS`) 超时，或文件类型 (`UPLOAD_FILE_MAX_SIZE`) 不支持，导致无法提取有效信息。

## 怎么确认配好了

*   通过模拟器或真实环境，使用包含新药或最新诊疗方案的查询，检查导诊结果是否包含相关最新信息，并核对其更新时间戳。
*   调用 HTTP 接口获取疾病或药品数据，检查返回的 `ICD-10` 或 `ATC` 编码是否符合预期格式，并验证 `Content-Type` 头是否正确。
*   上传不同大小和格式的医疗文件，观察系统是否能够成功解析并提取关键信息，检查文件解析服务的日志，确认没有超时错误。
