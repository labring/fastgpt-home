# 智能导诊产品的工具调用与插件

## 这个品类的数据长什么样

智能导诊领域的数据主要源于医学教科书、临床指南、药品说明书、疾病数据库（如 ICD-10）、医学期刊文献以及医院内部的病历数据。这些数据更新频率不一，药品说明书和临床指南可能季度或年度更新，而疾病流行病学数据则可能实时或准实时更新。文档结构上，数据多以半结构化或非结构化形式存在，例如疾病描述、症状体征、诊断标准、治疗方案等文本，以及药品成分、用法用量、不良反应等表格或列表。字段和单位方面，医学术语标准化程度高，如疾病编码、药物通用名、剂量单位（mg、ml）、检验指标（mmol/L、U/L）等。

## 这些特征在「工具调用与插件」这一环带来什么约束

数据来源的广泛性和更新频率的差异，要求工具调用与插件具备灵活的数据源集成能力和版本管理机制。半结构化和非结构化文档的存在，使得插件在数据解析时需要强大的文本理解和抽取能力，例如识别症状描述中的关键实体和修饰词。医学术语的标准化特性，决定了工具调用在参数传递时需要严格遵循预定义的医学编码或术语集，避免歧义。同时，对于药品剂量、检验指标等带有单位的数值型数据，插件在处理时必须考虑单位转换和量纲一致性，确保计算结果的准确性。实时或准实时更新的数据源，对插件的缓存策略和数据同步机制提出了更高要求。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `API_TIMEOUT_SECONDS` | `60 秒` | 避免因外部医学知识库或药品数据库响应慢导致用户等待过久 |
| `MAX_RETRIES` | `3` | 针对外部 API 偶发性网络抖动或服务不稳进行容错处理 |
| `HEADER_AUTH_TOKEN` | `Bearer your_api_key` | 外部医学知识库 API 通常需要基于令牌的身份验证 |
| `RESPONSE_PARSE_MODE` | `JSONPath` | 外部 API 返回多为 JSON 格式，便于精确提取所需字段 |
| `CONTEXT_WINDOW_SIZE` | `4096 tokens` | 确保能够承载完整的病历信息和相关医学知识，避免截断 |
| `ERROR_RETRY_INTERVAL_SECONDS` | `5 秒` | 在 API 失败后进行短暂等待，防止瞬时高并发请求导致服务过载 |

## 容易做错的三处

*   现象：外部 API 调用返回 502 错误码，或显示“连接超时”。原因：网络代理配置不当或 `API_TIMEOUT_SECONDS` 参数设置过短，导致请求在完成前被中断。
*   现象：工具调用后返回的数据中，关键医学字段（如诊断名称、药品剂量）为空或格式错误。原因：`RESPONSE_PARSE_MODE` 未能准确匹配外部 API 返回的 JSON 结构，导致字段提取失败。
*   现象：智能导诊结果与最新医学指南不符。原因：外部知识库的数据缓存未及时更新，或工具调用未触发最新数据同步机制。

## 怎么确认配好了

*   针对典型的症状描述，调用工具后检查返回的疾病诊断或推荐药品是否与权威医学指南一致。
*   模拟网络异常或外部 API 响应延迟，观察 `MAX_RETRIES` 和 `ERROR_RETRY_INTERVAL_SECONDS` 配置是否能成功触发重试机制并最终获取结果。
*   检查日志中是否有因 `API_TIMEOUT_SECONDS` 导致的请求中断记录，并调整至合理范围。
*   选取包含复杂医学术语和数值单位的查询，验证工具调用返回结果的字段提取准确性和单位一致性。
