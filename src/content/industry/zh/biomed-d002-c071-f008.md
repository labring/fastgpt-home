# 洁净区管理产品的工具调用与插件

## 这个品类的数据长什么样

洁净区管理的数据主要来源于环境监测系统、设备运行记录、人员进出日志以及清洁消毒规程文档。环境监测数据，如温湿度、压差、尘埃粒子数、浮游菌和沉降菌数量，以结构化时序数据为主，更新频率通常为分钟级至小时级。设备运行记录，例如高效过滤器压差、风机运行状态，也呈现为结构化时序数据。人员进出日志包括人员ID、进出时间、区域等信息。清洁消毒规程、SOP（标准操作程序）等文档，多为非结构化文本，包含详细操作步骤、使用的试剂、频率和责任人，通常以 PDF 或 Word 格式存储，更新频率较低，一般为季度或年度修订。尘埃粒子数据常见单位为 `个/立方米`，浮游菌和沉降菌为 `CFU/皿`。

## 这些特征在「工具调用与插件」这一环带来什么约束

洁净区管理数据的多样性要求工具调用能处理不同类型的数据源。时序数据高频更新的特点，决定了对数据接口的实时性要求较高，插件需要能够快速查询和整合最新状态。非结构化文档内容的检索，则需要插件具备高效的文本解析能力，能够从复杂的规程中提取关键信息，例如特定操作的步骤或试剂用量。单位和字段的标准化是关键，例如 `CFU/皿` 和 `个/立方米` 需要在数据摄取或工具调用时进行正确识别和转换，避免混淆。当查询跨越不同数据源时，例如结合环境数据和SOP，插件需要设计统一的查询逻辑。此外，历史数据的查询需求，例如追溯某段时间内的环境异常与SOP执行情况，要求工具接口具备灵活的时间范围查询能力。

## 配置怎么定

| 配置项                       | 建议取法                               | 这样取的依据                                                              |
| :--------------------------- | :------------------------------------- | :------------------------------------------------------------------------ |
| `maxContext`                 | `16384 tokens`                         | 确保能够容纳查询相关的多份 SOP 文档片段和历史环境数据。                 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`                               | 应对大型 PDF/Word 格式 SOP 文档的解析需求，避免解析超时。               |
| `分段长度`                   | `800 字符`                             | 平衡文本语义完整性与召回效率，适用于规程类文档。                        |
| `召回条数`                   | `8 条`                                 | 确保在复杂查询中能够覆盖多个相关的规程章节或数据点。                    |
| `相似度阈值`                 | `0.75`                                 | 过滤掉低相关性结果，提升召回精度，特别是针对专业术语。                  |
| `tool_request_timeout`       | `30 秒`                                | 保证对实时环境监测接口的响应速度，避免长时间等待。                      |

## 容易做错的三处

*   调用外部环境监测接口时返回 `HTTP 504 Gateway Timeout`，原因是后端服务处理时间过长，未能按时响应。
*   查询清洁规程时，结果未能准确提取出特定试剂的用量，因为文档解析插件未针对规程中的表格结构进行优化。
*   在需要结合历史环境数据和人员进出记录进行分析时，返回结果缺少部分关键字段，原因在于不同数据源的API接口字段命名不一致，插件未做统一映射。

## 怎么确认配好了

*   通过模拟查询不同时间段内的环境监测数据，核对返回的尘埃粒子数、温湿度等指标与原始数据是否一致，并检查单位 `个/立方米` 是否正确。
*   执行针对具体清洁操作规程的查询，验证是否能准确提取出操作步骤、所需试剂名称及用量，并与原始 SOP 文档内容逐条比对。
*   调用涉及人员进出记录的工具，核实返回的人员ID和进出时间是否完整且格式正确，确保与实际日志记录匹配。
*   测试包含多个数据源的复合查询，例如查询某个区域在环境异常期间的清洁记录，验证所有相关信息是否都被有效整合。
