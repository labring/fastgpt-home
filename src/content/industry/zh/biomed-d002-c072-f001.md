# 清洁验证产品的HTTP 接口与外部系统

## 这个品类的数据长什么样

清洁验证数据主要来源于实验室分析报告、生产设备运行日志和质量管理系统。其数据更新节奏通常遵循批次生产周期，或按照设备清洁频率进行，具有一定的时效性。文档结构常以 PDF 报告、Excel 表格或 XML 文件的形式存在，包含批次号、设备ID、取样点、残留物名称、检测方法、检测限、实测浓度、可接受限度等字段。单位涉及微克/平方厘米（`μg/cm²`）、ppm、ppb 等，并常伴随检测方法标准号和分析仪器型号等辅助信息。数据通常具备严格的溯源要求，字段间存在复杂的逻辑关联，例如一个批次可能对应多个取样点，每个取样点有多种残留物的检测结果。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

清洁验证数据的高时效性和结构化特性，要求 HTTP 接口具备高效的数据传输能力和精确的数据解析机制。大量的 PDF 或 Excel 报告作为数据源，意味着在接口设计时需考虑文件上传与解析的流程，可能涉及 OCR 或结构化数据提取服务。数据中包含的多种单位和检测限值，要求系统在接收数据后进行单位转换或合规性校验。批次号、设备ID等关键标识符的唯一性和关联性，决定了外部系统在数据同步时需要精确匹配，避免数据错乱。若数据更新不及时或解析失败，可能直接影响生产放行决策，因此接口的稳定性和错误处理机制至关重要。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `50 MB` | 清洁验证报告通常包含图表和大量数据，文件体积较大，预留充足上传空间。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大文件解析和 OCR 处理耗时较长，需防止因超时导致处理中断。 |
| `MAX_RETRIES` | `3` | 外部系统调用或文件解析偶发失败，重试机制可提高成功率。 |
| `CONTENT_TYPE_WHITELIST` | `application/pdf, application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` | 明确允许的报告文件类型，增强安全性与解析兼容性。 |
| `CHUNK_SIZE` | `1024 KB` | 对于大型清洁验证数据文件，分块传输可提高传输稳定性，尤其在网络波动时。 |
| `BATCH_PROCESS_INTERVAL_MINUTES` | `60 分钟` | 清洁验证数据通常按批次或周期性生成，设置合理的批处理间隔可平衡实时性与系统负载。 |

## 容易做错的三处

*   调用外部清洁验证数据服务时，接口返回 `HTTP 400 Bad Request`，原因常是请求体中的批次号或设备 ID 字段格式不符，未严格按照 API 文档要求传输。
*   上传清洁验证报告后，智能体后端响应缓慢甚至卡死，通常是由于文件体积过大或包含复杂图像，导致解析服务处理时间过长，超出 `PARSE_FILE_TIMEOUT_SECONDS` 限制。
*   获取到的清洁验证数据中，残留物浓度数值为空或单位错误，这往往是外部系统返回的数据结构与预期不符，或数据解析器未正确处理多种单位格式。

## 怎么确认配好了

*   通过 FastGPT 的工具调试界面，使用一个实际的清洁验证报告文件进行上传，并检查是否能成功解析并提取出批次号、检测结果等关键字段。
*   模拟外部系统通过 HTTP 接口提交一份包含多个取样点和多种残留物检测结果的清洁验证数据，观察系统能否正确接收并存储所有关联数据。
*   检查 FastGPT 后台日志，确认没有出现 `HTTP 500 Internal Server Error` 或 `Timeout` 相关的错误信息，尤其是在处理边缘情况数据时。
*   配置一个预期残留物浓度超过阈值的清洁验证数据，通过 HTTP 接口提交，验证系统是否能触发相应的预警或异常处理流程。
