# 生物制药设备产品的工具调用与插件

## 这个品类的数据长什么样

生物制药设备的数据来源多样，主要包括制造商的官方技术文档、产品手册、销售合同、以及第三方检测报告。这些数据更新频率不一，新品发布或型号升级时更新较快，通常为季度或半年更新，而核心技术参数和合规认证信息则相对稳定。文档结构复杂，常包含图表、CAD 图纸、PDF 格式的详细技术规格书。字段方面，除了通用设备参数（如尺寸、重量、功率），还特有生物兼容性材料列表、灭菌方式、验证周期、符合 GMP/GLP 标准的认证编号、以及关键部件的批次追溯码。单位通常涉及国际单位制（SI）和一些行业特定单位，例如反应釜的体积单位可能用升（L）或立方米（m³），过滤器的孔径单位为微米（µm），而处理能力则可能以批次/小时或公斤/天衡量。

## 这些特征在「工具调用与插件」这一环带来什么约束

生物制药设备数据的复杂性对工具调用与插件提出了特定约束。首先，多源异构的数据导致数据集成难度高，需要插件能够灵活处理不同格式的文档解析。其次，更新频率差异要求工具调用具备增量更新和版本管理能力，确保获取最新且准确的设备信息。文档中包含的图表和 CAD 图纸，意味着纯文本处理不足以提取全部关键信息，需要考虑图像识别或专业解析插件的集成。特有的生物兼容性材料、灭菌方式、合规认证编号等字段，要求插件在数据抽取时有更高的准确性和语义理解能力，避免误读或遗漏关键合规信息。单位的混用与转换，则需要在工具调用中内置单位规范化处理逻辑，确保参数比较和计算的准确性。例如，当查询设备的最大处理量时，插件不仅要返回数值，还要确保单位的一致性。

## 配置怎么定

| 配置项                   | 建议取法                                    | 这样取的依据                                                                                             |
| :----------------------- | :------------------------------------------ | :------------------------------------------------------------------------------------------------------- |
| `maxContext`             | `8000 tokens`                               | 生物制药设备的技术文档通常较长，包含大量细节描述，需要较大的上下文窗口以理解完整信息。                 |
| `chunkSize`              | `500 字符`                                  | 确保每个分段包含足够的技术细节，同时避免单个分段过长导致信息冗余或降低召回效率。                       |
| `overlapSize`            | `50 字符`                                   | 适度的重叠有助于保持分段间的语义连续性，尤其在处理描述性文本时，避免关键信息被切割。                 |
| `vectorModel`            | `bge-large-zh-1.5`                          | 针对中文技术文档优化，能够更好地捕捉专业术语和上下文语义，提升向量召回准确性。                       |
| `similarityThreshold`    | `0.75`                                      | 较高的相似度阈值有助于筛选出与查询高度相关的设备参数或技术规范，减少不相关结果。                     |
| `toolCallTimeout`        | `600 秒`                                    | 考虑到部分设备数据查询可能涉及复杂的数据源整合或外部 API 调用，预留充足的执行时间防止超时。         |
| `pluginPayloadFormat`    | `application/json`                          | 确保与大多数现代 API 接口兼容，简化数据传输和解析流程。                                               |

## 容易做错的三处

*   现象：设备参数查询结果为空或不完整。原因：插件在解析 PDF 或扫描文档时，OCR 识别率不足，未能正确提取所有字段。
*   现象：调用外部 API 获取设备实时库存或价格时，返回 4xx 状态码。原因：API 请求的认证凭证过期或格式不正确，或者 `pluginPayloadFormat` 未能匹配目标 API 要求的 `application/x-www-form-urlencoded` 格式。
*   现象：系统在处理用户关于设备合规性查询时，无法给出明确结论。原因：知识库中缺少最新的法规更新或制造商提供的合规认证文件未被有效索引，导致工具调用无法获取相关信息。

## 怎么确认配好了

*   针对核心设备型号，进行模拟查询，验证返回的技术参数、合规认证信息是否与原始文档一致，并检查单位是否统一。
*   测试包含图表或表格的文档提取能力，确保关键数值和关联描述能够被插件正确识别并转化为可用数据。
*   执行模拟外部 API 调用，检查 `toolCallTimeout` 设置是否能覆盖正常响应时间，同时确认 `pluginPayloadFormat` 能正确发送请求并接收数据。
