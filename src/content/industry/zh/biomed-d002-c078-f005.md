# 监护设备产品的多轮对话与提示词

## 这个品类的数据长什么样

监护设备数据主要来源于生产商官方技术文档、产品说明书、用户手册以及医疗行业标准。这些文档通常以 PDF、Word 或结构化 XML 格式提供，更新频率相对稳定，通常随产品型号迭代或法规更新而发布。文档内容包含详细的设备参数（如心率测量范围、血氧饱和度精度、血压测量模式）、报警阈值设置、操作流程、维护指南及故障排除方法。字段通常包含具体的数值范围（例如“心率：30–300 bpm”）、单位（如 mmHg、%SpO2）以及特定专业术语（如“波形增益”、“无创血压”）。部分数据还可能以表格形式呈现，用于比对不同型号设备的性能差异。

## 这些特征在「多轮对话与提示词」这一环带来什么约束

监护设备数据的专业性与数值范围约束，要求多轮对话系统在理解用户查询时，能够准确识别设备型号、参数名称及数值单位。例如，用户提及“血氧”时，系统需能区分“血氧饱和度”与“血氧分压”，并根据上下文引导用户提供具体数值或范围。文档中大量的表格数据和专业术语，使得提示词设计必须强调实体识别和关系抽取，以确保从复杂文本中精确提取关键信息。此外，设备操作和故障排除流程的序列性，要求多轮对话能够引导用户按步骤进行，提示词需要包含明确的指令和条件判断。数据更新频率较低但影响深远，意味着知识库构建时对版本管理和数据一致性有较高要求，提示词应能引用特定版本文档。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `2000–3000 Tokens` | 确保在多轮对话中能够保留足够的上下文信息，覆盖设备参数、操作步骤等细节，同时避免过长的上下文导致模型性能下降。 |
| `分段长度` | `400 字符` | 监护设备文档中通常包含较长的技术描述和操作指南，较长的分段长度有助于保持语义完整性。 |
| `召回条数` | `10 条` | 鉴于监护设备参数和故障诊断的复杂性，需要召回更多相关文档片段以提高回答的准确性和全面性。 |
| `相似度阈值` | 按实测标定 | 根据实际测试，在保证召回相关内容的前提下，优化阈值以减少不相关信息的引入。 |
| `重排返回条数` | `5 条` | 对召回的文档片段进行二次排序，确保最相关的核心信息优先呈现，提升回答质量。 |
| `对话轮次限制` | `8–12 轮` | 考虑到故障排查和产品咨询可能涉及多个来回，设置合理轮次限制以支持复杂问题的解决。 |

## 容易做错的三处

*   系统无法准确识别用户提到的具体设备型号或参数，导致回答通用化或不相关，原因是提示词未充分引导用户提供具体信息，或知识库中设备型号与参数的关联性不足。
*   用户询问设备故障排除时，系统未能提供按步骤的操作指引，而是给出零散的知识点，原因是文档分段时破坏了操作流程的连贯性，或提示词未明确要求按步骤输出。
*   在多轮对话中，系统重复回答相同信息或忽略用户新提出的问题，原因是 `maxContext` 设置不当，未能有效管理历史对话，或者 `获取对话记录列表` 接口的偏移量参数理解有误，导致上下文处理出现偏差。

## 怎么确认配好了

*   模拟用户提问特定监护设备（例如“Mindray BeneVision N1”）的某个参数（例如“无创血压测量范围”），检查系统能否准确给出数值范围和单位。
*   模拟用户进行多轮故障排查对话，例如“我的心电监护仪报警显示‘导联脱落’，我该怎么做？”，检查系统能否提供逻辑清晰、步骤明确的解决方案。
*   测试系统在不同轮次对话中，对用户新提出的问题是否能保持准确理解，同时不丢失前期对话上下文，可以通过检查 `获取对话记录列表` 接口返回的数据与对话内容的对应关系来验证。
