# 眼科产品的工具调用与插件

## 这个品类的数据长什么样

眼科产品的数据主要来源于药品注册批件、医疗器械注册证、临床试验报告、药品说明书、诊疗指南以及学术文献。这些数据更新频率因来源而异，药品批件和器械注册证的更新周期通常较长，但说明书和诊疗指南会随临床证据积累而定期修订，一般为半年到两年。学术文献的更新频率最高，几乎是持续性的。文档结构方面，药品说明书和注册证多为结构化或半结构化的 PDF 文档，包含明确的适应症、用法用量、不良反应、禁忌等字段。临床试验报告则可能包含大量非结构化的自由文本描述。字段与单位具有高度专业性，例如眼内压（IOP，单位 mmHg）、视力（Snellen 分数或 LogMAR）、视野缺损程度（dB）、药物浓度（mg/mL 或 %）。

## 这些特征在「工具调用与插件」这一环带来什么约束

眼科产品数据的高度专业性和多样化的文档结构，对工具调用与插件的准确性和鲁棒性提出了要求。由于数据源更新频率不一，需要设计灵活的同步机制，避免模型基于过时信息进行响应。例如，药品说明书的修订可能涉及用法用量或禁忌的重大变更，若未能及时同步，可能导致错误推荐。此外，大量专业术语和缩写，如“视网膜中央动脉阻塞（CRAO）”或“玻璃体腔注射（IVT）”，要求模型具备识别和正确理解的能力。非结构化临床试验报告中的数据提取，需要更强大的自然语言处理能力和实体识别工具。眼科疾病的复杂性也意味着多个产品或治疗方案之间存在交叉和互作用，工具调用需要能够整合来自不同数据源的信息，进行综合判断。

## 配置怎么定

| `maxContext`             | `4096`                                 | 眼科专业术语密集，需足够上下文维持语义完整性                               |

| `召回条数`               | `前 8 条`                              | 确保覆盖多源信息，如说明书、指南、临床文献中与产品相关的片段             |
| `相似度阈值`             | `0.75`                                 | 眼科术语精确性要求高，提高阈值可减少不相关或模糊的召回                  |
| `重排返回条数`           | `前 3 条`                              | 经过重排后，聚焦最相关的核心信息，提高响应精准度                         |

## 容易做错的三处

*   现象：模型对某种眼科药物的适应症回答不完整或错误。原因：知识库中该药物的最新说明书未及时同步，或关键信息在文档切分时被截断。
*   现象：调用外部工具查询眼内压正常范围时，返回结果为空或格式错误。原因：外部工具的 API 参数配置不正确，或返回的数据单位与预期不符导致解析失败。
*   现象：针对复杂的眼科病例，模型无法综合多个产品信息给出建议。原因：工作流设计时未充分考虑多工具协调调用，或不同工具返回的数据缺乏有效整合机制。

## 怎么确认配好了

*   针对核心眼科产品，通过模拟用户提问，核对模型回答中的关键信息（如适应症、用法用量、不良反应）与官方说明书是否一致。
*   测试包含专业术语和缩写的查询，确保模型能够正确识别并利用知识库或工具进行响应，并检查响应中是否包含必要的专业单位。
*   执行包含文件上传和解析的工作流，检查文件内容是否被正确提取，以及提取出的关键字段是否能被后续工具或模型有效利用。
*   验证外部工具调用链，确保每次调用都能返回预期格式的数据，并且数据中的数值和单位都符合预设。
