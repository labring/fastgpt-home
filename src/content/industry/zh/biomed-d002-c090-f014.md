# 药物经济学产品的表单与交互

## 这个品类的数据长什么样

药物经济学数据多来源于临床试验报告、真实世界研究（RWE）、医保支付标准、药品定价数据库和卫生技术评估（HTA）机构发布的报告。数据更新频率通常较低，一般随新药上市、医保目录调整或大型研究结果发布而更新，可能为季度、半年或年度更新。文档结构通常包含详细的方法学描述、成本效用分析（CUA）、成本效果分析（CEA）或成本效益分析（CBA）模型，以及敏感性分析结果。字段方面，常见的包括 `ICER`（增量成本效果比）、`QALY`（质量调整生命年）、`LYG`（生命年增益）、`DrugCost`（药品成本）、`MedicalServiceCost`（医疗服务成本）等，单位涉及货币（如 `USD`、`CNY`）、生命年（`年`）或无单位比率。

## 这些特征在「表单与交互」这一环带来什么约束

药物经济学数据的低更新频率意味着知识库构建时，一次性导入大量历史数据是常见做法，后续更新以增量补齐为主。文档结构复杂性要求表单设计能够引导用户准确提取关键指标，例如通过下拉菜单限制 `分析类型` 的选择。字段的特异性，如 `ICER`、`QALY`，决定了在交互层面需要提供清晰的字段解释或预设校验规则，避免用户输入错误或混淆概念。货币单位与生命年单位的存在，要求在表单提交前进行单位转换或明确单位标识，确保模型理解的准确性。此外，由于数据通常以结构化表格和非结构化文本混合呈现，表单与交互设计需要兼顾两者，例如支持上传 PDF 报告并辅以结构化数据录入。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `8192 tokens` | 药物经济学报告文本量大，需支持较长上下文窗口 |
| `similarityThreshold` | `0.75` | 确保召回与特定经济学指标或分析方法高度相关的文档片段 |
| `maxRetrieveResults` | `10 条` | 复杂查询可能涉及多维度数据，需要更多召回结果进行综合判断 |
| `PARSER_MODE` | `TABLE_AND_TEXT` | 数据常包含大量表格与文本混合内容，需要兼顾解析 |
| `documentExpirationTime` | `365 天` | 考虑到数据更新频率低，一年有效期可覆盖大部分更新周期 |
| `feedbackThreshold` | `0.8` | 确保用户反馈的有效性，过滤掉低置信度的反馈 |

## 容易做错的三处

*   模型在回答药品成本相关问题时，经常给出过期数据或错误单位的成本数值。原因是知识库文档更新不及时，或解析时未正确识别和转换货币单位。
*   用户提交包含“成本效果比”的复杂问题后，模型未能有效利用相关工具进行计算或引用。原因是工作流设计中，工具调用条件过于宽泛，导致模型无法准确判断何时调用特定经济学分析工具。
*   上传药物经济学报告 PDF 后，部分表格数据未被正确提取，导致后续问答中缺失关键数值。原因是 `PARSER_MODE` 设置未充分考虑表格解析能力，或 `PARSE_FILE_TIMEOUT_SECONDS` 过短导致解析中断。

## 怎么确认配好了

*   上传一份包含 `ICER`、`QALY` 等关键指标的典型药物经济学报告 PDF，并检查知识库中是否正确提取了这些数值和其对应单位。
*   模拟用户提问“某药品的增量成本效果比是多少？”或“该药品相较于现有疗法的成本效益如何？”，检查模型回答中是否能准确引用知识库中的数据并给出合理的分析。
*   在配置了外部计算工具（例如用于 `ICER` 敏感性分析）的工作流中，测试输入一组参数，验证模型是否能触发工具调用并返回计算结果。
