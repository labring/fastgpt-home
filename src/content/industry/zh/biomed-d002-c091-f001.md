# 药物警戒产品的HTTP 接口与外部系统

## 这个品类的数据长什么样

药物警戒数据主要来源于临床试验报告、上市后监测（如不良事件报告系统、医学文献、社交媒体）以及药品监管机构数据库。数据更新频率较高，例如美国 FDA 的 FAERS 数据库每日更新，欧洲 EMA 的 EudraVigilance 数据库也保持高频更新。文档结构通常包含患者信息、药品信息（如通用名、商品名、批次号）、不良事件描述（包括 MedDRA 编码）、事件发生与报告日期、事件结局等。字段类型多样，包括文本描述、枚举值、日期、数值。单位方面，剂量常以毫克（`mg`）、克（`g`）或国际单位（`IU`）表示，频率以每日（`QD`）、每周（`QW`）等表示。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

药物警戒数据的多源性和高频更新要求 FastGPT 在通过 HTTP 接口集成外部系统时，必须支持灵活的数据抓取策略和实时或准实时的数据同步能力。复杂多样的文档结构意味着需要强大的数据解析和预处理能力，以确保信息能够准确提取并结构化，例如对 MedDRA 编码的识别和映射。字段与单位的标准化是关键，特别是在处理不同来源的数据时，需要定义清晰的数据模型和转换规则，防止因单位不一致导致的误判。此外，敏感患者信息的处理，要求接口设计必须符合 HIPAA 或 GDPR 等隐私法规，确保数据传输和存储的安全性，例如采用 `HTTPS` 协议和 `OAuth 2.0` 认证机制。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `数据源类型` | `HTTP Pull` | 适应外部系统主动推送或定时拉取模式 |
| `抓取频率` | `每 4 小时` | 兼顾数据实时性与系统负载，可根据数据源更新频率调整 |
| `最大并发请求数` | `10` | 平衡数据同步效率与外部系统承载能力 |
| `超时时间` | `60 秒` | 应对外部系统响应延迟，避免长时间阻塞 |
| `数据解析器` | `JSONPath` 或 `XPath` | 灵活处理多样的 JSON/XML 数据结构 |
| `错误重试策略` | `指数退避，最大 5 次` | 应对瞬时网络波动或外部系统临时故障 |

## 容易做错的三处

*   HTTP 请求返回 `403 Forbidden` 或 `401 Unauthorized`，表明认证信息（如 `API Key` 或 `Bearer Token`）配置错误或已过期。
*   接口调用成功但返回的数据字段为空或不完整，通常是因为 `数据解析器` 配置的 `JSONPath` 或 `XPath` 表达式与实际返回的数据结构不匹配。
*   数据同步任务长时间无响应或最终失败，这可能是由于 `超时时间` 设置过短，外部系统未能及时响应，或者 `最大并发请求数` 过高导致外部系统限流。

## 怎么确认配好了

*   通过 FastGPT 的日志系统检查 HTTP 接口调用的状态码，确认是否持续返回 `200 OK`。
*   在 FastGPT 的数据管理界面查看导入的数据样本，检查关键字段（如 `MedDRA 编码`、`药物剂量`）是否被正确解析和填充。
*   手动触发一次数据同步任务，并监控任务执行时长，确保在预期的 `超时时间` 内完成。
