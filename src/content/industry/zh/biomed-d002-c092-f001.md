# 血液肿瘤产品的HTTP 接口与外部系统

## 这个品类的数据长什么样
血液肿瘤产品的数据源主要来源于临床试验报告、药品说明书、医学指南、学术论文及专业数据库。这些数据更新频率较高，尤其是在新药上市、临床研究进展或治疗方案调整后。文档结构通常包含药物成分、适应症、用法用量、不良反应、禁忌、药代动力学等标准医学信息。在字段方面，常涉及 `药品通用名`、`商品名`、`CAS号`、`靶点`、`作用机制`、`批准文号`、`药物浓度`（单位如 `mg/mL`、`µg/L`）、`剂量`（单位如 `mg`、`IU`）、`疗程`（单位如 `天`、`周`）等。部分数据还包含基因突变信息和生物标志物检测结果。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
血液肿瘤产品数据的高更新频率，要求 HTTP 接口具备高效的数据同步机制，例如支持增量更新或 webhook 回调，以确保信息的时效性。数据来源的多样性与复杂文档结构，对接口返回的数据格式提出挑战，需要统一的 JSON Schema 或 XML 结构来封装，确保 `药品通用名` 等关键字段的准确解析。此外，药物浓度和剂量等字段的单位统一性，是避免误解的关键。接口设计时，需将单位作为独立字段或在数值字段中明确标注，以防不同数据源的单位混淆。对于涉及敏感医学信息的接口，还需考虑认证与授权，例如采用 `OAuth 2.0` 协议，以满足数据安全与合规性要求。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `2000 字符` | 适应药品说明书和临床指南中较长的描述性文本，确保上下文完整性。 |
| `API_TIMEOUT_SECONDS` | `30 秒` | 考虑到外部医学数据库可能存在查询延迟，留出足够时间获取响应。 |
| `CHUNK_SIZE` | `500 字符` | 兼顾 RAG 召回效率与文本语义完整性，避免切分造成关键信息丢失。 |
| `SIMILARITY_THRESHOLD` | `0.75` | 针对医学术语的精准匹配，提高相关性，减少不相关结果。 |
| `RETRY_COUNT` | `3 次` | 应对外部系统偶发性网络波动或服务瞬时不可用，提高接口稳定性。 |
| `RATE_LIMIT_PER_MINUTE` | `按实际授权配置` | 遵循外部数据源的 API 调用频率限制，避免触发封禁。 |

## 容易做错的三处
*   API 知识库返回的阅读链接 URL 在点击时报错，提示 "Only support .txt, .m"，原因在于前端组件未正确识别或处理后端返回的文档类型，或后端未将原始文档格式正确映射为可预览的类型。
*   调用外部系统接口时频繁出现 `HTTP 500` 错误或 `Connection Timeout`，原因可能是外部服务不稳定、网络延迟过高，或请求体过大导致服务器处理超时。
*   查询结果中药物剂量或浓度数值不一致，原因在于未对不同数据源返回的单位进行标准化处理，例如将 `mg` 与 `µg` 混淆。

## 怎么确认配好了
*   对核心的血液肿瘤产品，通过调用 HTTP 接口，检查返回数据中的 `药品通用名`、`适应症`、`剂量` 等关键字段是否与原始文档内容完全一致，并核对数值字段的单位是否正确。
*   模拟外部系统数据更新场景，验证知识库中的产品信息是否能在指定时间内自动同步并生效，以确认 `webhook` 或轮询机制正常工作。
*   故意构造包含模糊或部分匹配的查询，检查 `SIMILARITY_THRESHOLD` 在实际召回中是否能够有效过滤低相关性结果，并评估召回的精准度。
*   监控接口调用日志，检查是否存在 `HTTP 429` 状态码（请求过多）或 `HTTP 502/504` 状态码（网关错误/超时），以评估 `API_TIMEOUT_SECONDS` 和 `RETRY_COUNT` 是否合理。
