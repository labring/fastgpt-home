# 零售连锁产品的工具调用与插件

## 这个品类的数据长什么样

生物医药零售连锁的数据来源多样，核心数据包括商品销售记录、库存信息、会员档案、促销活动细则、药品说明书与禁忌。销售数据通常从 POS 系统获取，实时性要求高，更新频率可达分钟级。库存数据则与供应链系统联动，每日或每周同步。会员数据通常存储于 CRM 系统，包含购买历史、偏好标签等。药品与试剂的详细信息，如用途、成分、用法用量、注意事项等，常以结构化文本（如 JSON、XML）或非结构化文档（如 PDF、Word）形式存在，更新频率相对较低，主要随产品批次或监管要求变动。字段名可能包含药品通用名、批号、生产日期、有效期、零售价、会员价、库存数量、货架位置等，单位涉及克、毫升、盒、瓶等。

## 这些特征在「工具调用与插件」这一环带来什么约束

零售连锁数据的高实时性要求，特别是销售与库存数据，决定了工具调用需要支持高并发和低延迟的 API 接口。如果未能及时响应，可能导致推荐过期商品或提供错误的库存信息。药品试剂的复杂说明文档，要求工具插件具备强大的文本解析和语义理解能力，能够从非结构化数据中准确提取关键信息，例如特定药物的相互作用或禁忌症。文档更新频率相对较低，但一旦更新，需确保知识库能快速同步并重新索引，以避免提供过时的产品咨询。此外，会员数据的个性化特征，要求工具调用能够根据用户画像进行精准的产品推荐或优惠查询，这涉及到对多个内部 API 的组合调用，以及对敏感数据的安全处理。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :------------------------- | :----------------------------- | :------------------------------------------------------- |
| `maxContext` | `4096` | 兼顾响应速度与上下文长度，适应产品咨询和会员信息查询。 |
| `相似度阈值` | `0.75` | 确保召回的药品或试剂信息与用户查询高度相关，减少误答。 |
| `召回条数` | `5` | 提供足够多样的产品选择或相关信息，覆盖用户潜在需求。 |
| `重排返回条数` | `3` | 精选最相关的产品或试剂信息展示给用户，提高用户体验。 |
| `TOOL_API_TIMEOUT_SECONDS` | `30 秒` | 多数内部库存和会员 API 响应时间在秒级，避免长时间等待。 |
| `MAX_PARALLEL_TOOL_CALLS` | `3` | 平衡并发请求对后端系统的压力，提高多轮对话效率。 |

## 容易做错的三处

*   回答中出现过期的促销信息或错误的库存量，原因是工具调用未能及时同步 POS 或供应链系统的实时数据，导致知识库中的信息滞后。
*   无法正确解析药品说明书中的用法用量或禁忌，原因在于插件未能有效处理 PDF 或图片格式的非结构化文档，导致关键字段提取失败。
*   工具调用后模型未能输出思维过程，直接给出简单答案，原因通常是工具的返回结果过于简短或缺乏足够背景信息，不足以触发模型的推理链。

## 怎么确认配好了

*   模拟用户查询当前库存或最新促销活动，检查返回的产品数量、价格和活动详情是否与后台系统实时数据一致。
*   上传一份包含复杂医学术语和用药禁忌的药品说明书，然后提问相关问题，核对模型能否准确提取并回答关键信息。
*   进行多轮产品咨询，观察模型是否能在不同查询之间维持上下文连贯性，并准确调用多个工具（如先查询产品详情，再查询会员价格）。
*   在高峰时段进行并发测试，检查工具调用响应时间是否在预期范围内，`TOOL_API_TIMEOUT_SECONDS` 配置是否能有效避免超时。
