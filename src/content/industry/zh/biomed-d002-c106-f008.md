# 高值耗材产品的工具调用与插件

## 这个品类的数据长什么样

高值耗材的数据主要来源于生产厂商的产品说明书、临床使用指南、国家药监局数据库、医院采购目录以及经销商报价单。这些数据更新频率相对较低，通常随产品迭代或政策调整而变化，但涉及到批次、有效期等信息时则更新频繁。文档结构通常包含产品基本信息（型号、规格、注册证号）、技术参数（材料、尺寸、精度、性能指标）、临床适应症、禁忌症、使用方法、灭菌方式、储存条件、供应商信息、价格等。字段中常包含特定计量单位，例如毫米（mm）、微米（μm）、高斯（Gs）、单位（U）等，且可能存在多种命名方式指代同一参数。部分关键参数会以图表或图片形式嵌入文档，难以直接抽取。

## 这些特征在「工具调用与插件」这一环带来什么约束

高值耗材数据的低更新频率意味着工具调用在获取基础信息时对实时性要求不高，但对历史版本溯源有较高需求。复杂的文档结构和非结构化数据（如图片、图表）的存在，要求工具在信息抽取时具备多模态处理能力，或依赖预处理流程将关键信息结构化。特定计量单位和多种命名方式要求工具能进行单位转换和同义词映射，以确保查询准确性。价格信息通常是动态的，且与采购量、供应商、议价策略相关，这使得直接调用固定价格接口的适用性受限，需要更复杂的逻辑来整合多方数据源。此外，注册证号等强监管字段的准确性对合规性至关重要，要求工具调用具备严格的数据校验机制。

## 配置怎么定

| 配置项                 | 建议取法                                 | 这样取的依据                                                 |
| :--------------------- | :--------------------------------------- | :----------------------------------------------------------- |
| `maxContext`           | `4096`                                   | 应对产品说明书等长文本，保留足够上下文理解语义               |
| `segmentLength`        | `500` 字符                               | 平衡文本语义完整性和向量检索效率，避免过长分段              |
| `recallTopK`           | `5–8` 条                                 | 确保检索到足够相关信息，同时减少无关信息干扰                 |
| `similarityThreshold`  | `0.78–0.85`                              | 适应高值耗材技术参数描述的精确性要求，过滤不相关结果         |
| `toolCallTimeout`      | `60` 秒                                  | 应对外部API调用可能存在的延迟，尤其是在数据量较大时         |
| `maxRetryAttempts`     | `3` 次                                   | 处理临时网络波动或外部服务不可用情况，提高调用成功率         |

## 容易做错的三处

*   工具调用返回 `HTTP 500` 或 `Gateway Timeout` 错误，原因在于外部数据源（如药监局数据库）响应慢或并发处理能力不足。
*   插件执行后，结果中特定字段（如“灭菌方式”、“注册证号”）为空或格式不正确，原因在于信息抽取规则未能覆盖所有文档变体或单位转换逻辑缺失。
*   模型在调用价格查询插件后，给出的价格与实际采购价格不符，原因在于插件未能整合不同供应商、不同采购量的动态定价策略，或未考虑有效期、批次等影响因素。

## 怎么确认配好了

*   针对核心产品信息，通过模拟用户提问，检查工具调用能否准确抽取并呈现产品型号、规格、注册证号等关键信息。
*   随机选取包含特殊计量单位或图表的文档，验证工具调用后，相关技术参数是否能被正确识别、解析并转换为标准格式。
*   设计包含同义词或不同表述方式的查询，观察工具调用能否通过内部映射或知识图谱，准确匹配到对应的产品或参数。
*   在特定场景下，尝试调用外部价格查询或库存查询插件，验证其是否能成功连接并返回有效数据，且能处理异常情况。
