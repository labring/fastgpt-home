# 记录归档企微群自动化管理的分享与嵌入

## 这个品类的数据长什么样

生物医药行业企微群的记录归档数据主要来源于群聊消息、文件传输、会议纪要等。这些数据通常以非结构化文本为主，包含大量行业术语、药品名称、临床试验数据、研发进展报告等。更新节奏取决于群组活跃度和项目周期，可能每天产生大量消息，也可能在特定项目节点出现集中更新。文档结构多样，可以是纯文本聊天记录、PDF 格式的报告、图片形式的实验结果，或结构化的数据表格。字段与单位的特殊性体现在对药物剂量（如 `mg/kg`）、实验指标（如 `nM`、`%`）、时间戳（精确到秒）以及特定疾病编码（如 `ICD-10`）的严格要求。

## 这些特征在「分享与嵌入」这一环带来什么约束

记录归档数据量的庞大和更新频率的不确定性，对分享链接的实时性与嵌入页面的加载性能提出要求。包含敏感研发信息和患者数据的文档，要求分享与嵌入模块具备精细化的权限控制，防止信息泄露。多样的文档格式意味着嵌入组件需要支持多种文件类型的预览或下载。行业术语和专业缩写的高频出现，要求底层模型在处理查询时能准确理解上下文，避免因歧义导致错误信息传递。此外，语音消息的存在，使得嵌入组件在处理用户输入时，需要具备可靠的语音转文本能力，并妥善处理浏览器权限请求，以确保语音输入功能的正常使用。

## 配置怎么定

| 配置项             | 建议取法       | 这样取的依据                                   |
| :----------------- | :------------- | :--------------------------------------------- |
| `maxContext`       | `8000 tokens`  | 确保复杂医学术语和长段落能被完整理解         |
| `recallTopK`       | `前 8 条`      | 提高相关度召回率，覆盖更多潜在关联信息       |
| `similarityThreshold` | `0.78`         | 过滤掉低相关性文档，聚焦核心问题               |
| `segmentLength`    | `400 字符`     | 兼顾语义完整性与召回效率                       |
| `speechInputEnabled` | `true`         | 支持语音输入，方便移动端用户和快速提问         |
| `avatarUrl`        | 按实测标定     | 统一品牌形象，或根据用户角色动态加载头像       |

## 容易做错的三处

*   分享链接或嵌入页面中语音输入功能提示 `permission denied`。原因在于浏览器安全策略限制了非 HTTPS 环境下或未明确授权的页面访问麦克风。
*   嵌入页面无法显示应用图标和用户头像，部分浏览器显示异常。原因通常是跨域资源共享（CORS）策略配置不当，导致浏览器阻止了对这些资源的加载。
*   免登录窗口刷新后总是新建聊天会话，无法恢复之前的对话上下文。原因是没有正确配置会话持久化参数，或浏览器本地存储策略限制了会话 ID 的保存。

## 怎么确认配好了

*   在不同浏览器（Chrome、Firefox、Edge）和设备上测试分享链接，确认语音输入功能正常启用，且无权限报错。
*   检查嵌入页面在不同浏览器中的显示效果，特别是应用图标和用户头像是否正常加载，无控制台 `CORS` 错误。
*   在免登录窗口中进行多轮对话，刷新页面后验证是否能恢复到之前的聊天状态，会话 ID 是否保持一致。
*   通过分享链接或嵌入页面提交包含生物医药专业术语的问题，验证返回结果的准确性和相关性。
