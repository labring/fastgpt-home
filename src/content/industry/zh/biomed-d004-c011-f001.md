# OA 流程发起内部办公助手的HTTP 接口与外部系统

## 这个品类的数据长什么样

生物医药领域 OA 流程发起的数据主要来源于员工在内部系统中的操作，例如请假、报销、项目申请、采购审批等。这些数据更新频率相对较低，通常在员工提交申请时产生，审批过程中可能伴随状态变更。文档结构多为结构化或半结构化，包含发起人、申请类型、申请内容、金额、日期、审批历史等字段。字段单位明确，例如金额以“元”或“美元”计，时长以“天”或“小时”计，药品数量以“盒”或“支”计。这些数据通常存储在内部关系型数据库或特定的 OA 系统中，通过 API 接口对外提供服务。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

OA 流程发起的低更新频率意味着对实时性的要求相对宽松，但数据准确性与完整性至关重要。结构化数据特性使得接口设计时字段映射清晰，减少解析复杂性。例如，报销流程中的金额字段必须严格校验数值类型与单位。审批历史作为半结构化数据，可能需要更灵活的数据结构（如 JSON 数组）来承载不同阶段的审批意见与操作人。由于涉及敏感的内部操作，接口安全性要求高，需要严格的认证授权机制。数据来源的单一性（通常是特定的 OA 系统 API）决定了对特定接口协议和数据格式的依赖性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `timeout_seconds` | `60 秒` | OA 流程发起通常涉及少量数据传输和简单的业务逻辑处理，60 秒足以应对，避免因网络波动或后端瞬时负载导致的不必要超时。 |
| `max_retries` | `3 次` | 考虑网络瞬时抖动或后端服务短暂不可用，重试机制能提高成功率，3 次重试可在多数情况下恢复。 |
| `request_method` | `POST` 或 `PUT` | OA 流程发起是创建或更新资源的操作，应使用 `POST` 创建新流程，或 `PUT` 更新现有流程状态，符合 RESTful 规范。 |
| `content_type` | `application/json` | 生物医药 OA 流程数据多为结构化，JSON 格式便于数据传输与解析，且兼容性好。 |
| `auth_header_name` | `Authorization` | 标准的认证头字段，用于传递 API Key 或 JWT Token 等凭证，确保接口安全性。 |

## 容易做错的三处

*   调用接口时出现 `HTTP 504 Gateway Timeout` 错误。这通常是由于后端服务处理时间过长，超出了代理服务器或 FastGPT 自身的 `timeout_seconds` 设置。
*   接口调用成功但流程状态未变更。原因可能是请求体中的必填字段缺失或格式不正确，导致后端系统未能正确解析并执行业务逻辑。
*   数据库查询返回空结果，即使 SQL 语句在其他工具中可以正确执行。这可能与数据库连接池配置、权限问题或 FastGPT 执行 SQL 的上下文环境差异有关。

## 怎么确认配好了

*   通过 FastGPT 的调试界面，观察 HTTP 请求的 `HTTP Status Code` 是否为 `200` 或 `201`。
*   在 OA 系统中核对，确认对应的流程是否已成功发起或状态是否已按预期更新。
*   检查 FastGPT 的运行日志，查找是否有 `timeout_seconds` 相关的错误信息或接口返回的业务错误码。
