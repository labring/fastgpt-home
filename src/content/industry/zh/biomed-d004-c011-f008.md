# OA 流程发起内部办公助手的工具调用与插件

## 这个品类的数据长什么样
生物医药领域的 OA 流程发起，其数据源通常是企业内部的 ERP、CRM 或自研业务系统。数据更新频率因流程类型而异，例如请假审批流程的数据变动是实时的，而项目立项或采购申请可能在流程关键节点才更新。文档结构通常是结构化的表单数据，包含发起人、申请时间、审批状态、申请事项等固定字段，以及根据不同流程定义的动态字段。字段值通常是文本、数字、日期、枚举类型，例如药品批号、项目编号、员工工号、申请金额（单位：元或美元），这些字段往往带有特定的业务校验规则和上下文含义。

## 这些特征在「工具调用与插件」这一环带来什么约束
OA 流程数据的结构化特性，使得工具调用时参数映射相对直观，但需要严格匹配字段名和数据类型，避免因类型不符导致调用失败。实时性要求高的流程（如紧急审批），对工具调用的响应速度和并发处理能力有较高要求，需要确保插件底层接口具备低延迟特性。动态字段的存在，要求插件或工具具备一定的灵活性，能够根据流程模板动态生成或解析参数，不能仅依赖固定参数列表。此外，生物医药行业对数据准确性和合规性要求极高，工具调用返回的结果需要有明确的状态码和错误信息，便于追溯和审计。单位（如金额、数量）的识别和转换是关键，避免因单位混淆导致业务逻辑错误。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `max_tokens` | `2048` | 确保能够承载复杂流程的完整描述和参数列表，避免截断 |
| `timeout_seconds` | `60 秒` | 多数 OA 流程接口响应时间在此范围内，避免过早超时 |
| `tool_call_retries` | `2` | 应对偶发性网络波动或后端服务短暂不可用，增加调用成功率 |
| `schema_validation_level` | `strict` | 严格校验传入参数的数据类型和格式，确保业务数据准确性 |
| `response_parsing_template` | 按实测标定 | 适配不同 OA 系统的接口返回结构，精确提取关键信息 |
| `error_code_mapping` | 按实测标定 | 将 OA 系统返回的错误码映射为业务可理解的错误提示 |

## 容易做错的三处
*   调用工具时提示 `400 Messages with role 'tool' must be a response to a preceding message`：这通常是由于工具调用请求的格式不符合预期，导致平台无法正确识别工具响应。
*   API 调用结果与在线对话结果差异大：可能是因为 API 调用时 `stream` 设置为 `false`，且 `detail` 设置为 `true`，导致返回的数据结构或处理逻辑与流式对话不同，需要对返回的完整数据进行精确解析。
*   OA 流程状态更新失败，但工具调用显示成功：这可能是因为工具调用只确认了接口请求的发送，而没有对 OA 系统实际返回的业务状态码进行判断，流程并未真正完成。

## 怎么确认配好了
*   针对核心 OA 流程，通过模拟不同场景的请求，核对工具调用返回的 `status_code` 是否均为 `200`，且 `response_body` 中的业务状态字段符合预期。
*   检查工具调用日志，确认所有关键参数（如申请人、金额、审批类型）都被正确传递，且单位与 OA 系统要求一致。
*   在 OA 系统中查询通过工具调用发起的流程，核对流程状态、字段值是否与预期完全一致，特别是日期、金额等敏感字段。
