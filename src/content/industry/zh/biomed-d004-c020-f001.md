# 会议纪要内部办公助手的HTTP 接口与外部系统

## 这个品类的数据长什么样
生物医药领域的会议纪要数据通常以非结构化文本为主，来源多样，包括内部研讨会、项目进展会议、临床试验讨论会等。更新频率根据会议周期而定，可能是每周、每月或按项目阶段。文档结构上，常见包含会议主题、时间、地点、参会人员、讨论议题、关键决策、待办事项及责任人等部分。这些纪要往往涉及大量专业术语、实验数据、药物名称和患者信息，其中可能包含缩写、代码和特定计量单位，例如 `mg/kg`、`nM`、`μM` 等，以及特定的实验批次号和项目编号。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
会议纪要的非结构化特性和专业术语密度，要求外部系统在处理数据时具备强大的文本解析和语义理解能力。频繁的更新周期意味着HTTP接口需要支持高效的增量同步或事件驱动的数据摄入机制，以确保信息的时效性。文档中包含的特定字段（如批次号、计量单位）和潜在的敏感信息（如患者数据），对接口的数据清洗、脱敏和结构化抽取提出了高要求。此外，由于会议纪要可能包含多语言内容或特殊符号，HTTP请求和响应的编码格式（如 `UTF-8`）必须一致，并能妥善处理各种字符集。接口设计上应考虑对大文本体的分块传输或异步处理，以避免传输超时。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxChunkSize` | `800-1200 字符` | 平衡语义完整性和分段处理效率，避免过长或过短的文本块。 |
| `overlapSize` | `100 字符` | 确保分段之间有足够的上下文重叠，提高召回准确性。 |
| `requestTimeout` | `600 秒` | 应对生物医药会议纪要可能包含的复杂文本解析任务，防止接口超时。 |
| `batchSize` | `50` | 优化批量上传或处理的效率，减少HTTP请求次数。 |
| `encoding` | `UTF-8` | 确保多语言、特殊符号和专业术语的正确解析和传输。 |
| `maxRetries` | `3` | 应对网络波动或外部系统暂时性故障，提高数据传输的健壮性。 |

## 容易做错的三处
- 现象：HTTP 接口返回 `400 Bad Request` 错误，内容解析失败。原因：上传的会议纪要文本中包含特殊字符或编码不一致，导致外部系统无法正确识别请求体。
- 现象：部分关键信息（如药物剂量、实验批号）在处理后丢失或识别错误。原因：文本分段策略未充分考虑生物医药领域特有的命名实体和计量单位，导致信息被截断或误判。
- 现象：会议纪要上传后长时间未见更新或处理进度停滞。原因：`requestTimeout` 参数设置过低，对于包含大量文本和复杂结构的会议纪要，接口处理时间超出设定阈值而中断。

## 怎么确认配好了

- 模拟外部系统通过HTTP接口推送一份更新的会议纪要，观察系统日志，确认数据摄入流程无异常，且知识库内容已按预期刷新。
