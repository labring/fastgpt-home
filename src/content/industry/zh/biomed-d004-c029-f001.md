# 制度检索内部办公助手的HTTP 接口与外部系统

## 这个品类的数据长什么样

生物医药领域的制度检索，其数据主要来源于企业内部的质量管理体系文件、SOP（标准操作规程）、GMP（良好生产规范）文档、法规符合性报告以及研发项目管理规范等。这些文档通常以 PDF、Word 或内部知识库格式存储。数据更新频率相对较低，主要发生在法规政策调整、内部流程优化或新产品研发阶段。文档结构高度规范化，通常包含标题、章节、版本号、生效日期、修订记录和附件等标准字段。内容涉及专业术语和缩略词，例如“批生产记录”、“偏差管理”、“QC 放行”等，对语义理解的准确性要求高。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

制度文档的规范化结构要求 HTTP 接口能够处理结构化或半结构化数据，例如通过 API 调用获取特定章节或元数据。由于更新频率不高，对外部系统接口的实时性要求相对宽松，但需要支持版本控制和历史查询。文档中大量的专业术语和缩略词，使得在通过 HTTP 接口传输时，需要确保编码一致性，避免乱码或语义丢失。文档通常存储在企业内部的文件服务器或内容管理系统中，因此 HTTP 接口需要具备相应的认证授权机制，确保数据安全和合规性。文档体积可能较大，HTTP 接口在文件传输方面需要支持大文件分片上传或下载。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `HTTP_REQUEST_TIMEOUT` | `60 秒` | 处理大体积制度文档的上传下载，避免网络波动导致超时 |
| `MAX_FILE_SIZE_MB` | `200 MB` | 覆盖生物医药领域常见的大型 PDF 或 Word 文档 |
| `CHUNK_SIZE_BYTES` | `1048576 字节` | 优化大文件传输效率，减少单次请求负载 |
| `AUTH_HEADER_NAME` | `Authorization` | 符合行业通用的认证机制，例如 Bearer Token |
| `RETRY_ATTEMPTS` | `3 次` | 应对网络瞬时抖动，确保制度数据传输的可靠性 |
| `RESPONSE_CONTENT_TYPE` | `application/json` | 统一接口响应格式，便于解析和处理结构化数据 |

## 容易做错的三处

*   HTTP 请求返回 `401 Unauthorized` 或 `403 Forbidden` 状态码，原因是认证信息（例如 `Authorization` 头中的 Token）未正确传递或已过期，导致外部系统拒绝访问。
*   接口返回的文档内容出现乱码或部分字符无法识别，原因在于外部系统返回的数据编码与 FastGPT 期望的编码不一致，例如外部系统使用 GBK 而 FastGPT 默认 UTF-8。
*   上传大型制度文档时接口返回 `504 Gateway Timeout`，原因通常是 HTTP 模块的 `HTTP_REQUEST_TIMEOUT` 参数设置过短，未能覆盖大文件传输所需的全部时间。

## 怎么确认配好了

*   通过 FastGPT 的 HTTP 模块发起对外部系统制度检索接口的请求，检查响应状态码是否为 `200 OK`。
*   在 FastGPT 中配置一个简单的查询，模拟用户对制度内容的检索，核对返回的文档内容与原文是否一致，特别是专业术语和缩略词的显示。
*   上传一个典型的、中等大小的制度文档，观察 HTTP 请求的响应时间是否在 `HTTP_REQUEST_TIMEOUT` 设定的阈值内完成。
*   尝试检索一个包含多种语言或特殊字符的制度文档，确认返回结果无乱码现象。
