# CSO制度的HTTP 接口与外部系统

## 这个品类的数据长什么样

生物医药行业中，CSO（合同销售组织）的制度与SOP文档通常包含复杂的业务流程、合规要求、岗位职责、考核细则以及销售行为规范。这些文档的来源多样，包括企业内部规章、行业监管政策、法律法规解读、以及商业伙伴协议。更新节奏方面，核心制度如薪酬体系、合规政策可能季度或半年更新一次，而具体的SOP或项目管理细则可能每月甚至每周都有修订。文档格式以PDF、Word、Markdown为主，部分内容可能以内部wiki或知识库的形式存在。字段与单位方面，常见有“生效日期”、“版本号”、“审批人”、“适用范围”、“违规处罚细则（罚款金额、扣分比例）”、“绩效指标（销售额、覆盖率、利润率）”、“报销标准（元/公里、元/天）”等，其中涉及金额、比例、日期、人员、流程步骤等多种数据类型。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

CSO制度文档的复杂性和多源性要求HTTP接口设计具备高度的灵活性和鲁棒性。例如，文档更新频率较高，需要接口支持增量同步或定期全量刷新，以确保知识库的时效性。多样的文档格式意味着外部系统需要提供强大的文件解析能力，特别是对PDF中表格和复杂排版的准确提取。字段的异构性，如金额单位、日期格式差异，要求接口在数据传输时进行标准化转换。此外，制度文档中包含大量敏感信息和合规要求，HTTP接口在传输过程中必须严格遵守加密协议，并具备细粒度的权限控制，确保只有授权用户才能访问相关内容。处理失败时，需要明确的错误码和详细的错误信息，以便快速定位是网络问题、认证失败、文件解析错误还是数据格式不符。

## 配置怎么定

| 配置项                   | 建议取法                               | 这样取的依据                                                                                                                                              |
| :----------------------- | :------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `datasource_url`         | `https://cso-policy.example.com/api/docs` | 指定制度文档的API入口，确保能访问到最新数据。                                                                                                             |
| `auth_header`            | `Bearer your_api_key`                  | 使用Token或API Key进行认证，保障数据接口安全。                                                                                                            |
| `update_interval_seconds` | `86400` 秒                             | 设定每日全量或增量同步，平衡数据新鲜度与系统负载。                                                                                                        |
| `file_type_whitelist`    | `pdf, docx, md, txt`                   | 限制只处理已知的文档类型，避免解析异常或引入非预期内容。                                                                                                  |
| `max_document_size_mb`   | `50` MB                                | 限制单文档大小，防止超大文件导致内存溢出或处理超时。                                                                                                      |
| `timeout_seconds`        | `300` 秒                               | 设置接口请求超时时间，应对网络不稳定或外部系统响应慢的情况，避免长时间等待。                                                                              |

## 容易做错的三处

*   现象：同步任务长时间无响应最终报错超时。原因：外部系统接口响应缓慢，或者文档内容过大导致传输及解析耗时超出`timeout_seconds`设定。
*   现象：部分文档内容缺失或格式混乱。原因：文件解析器未能正确处理PDF中的复杂表格、图片或特殊字体，导致文本提取不完整。
*   现象：明明外部系统有新版本，FastGPT中仍是旧内容。原因：`update_interval_seconds`设置过长，或外部系统未正确标记文档更新状态，导致FastGPT未能触发更新。

## 怎么确认配好了

*   通过`datasource_url`访问指定接口，确认HTTP状态码为`200 OK`且返回数据结构符合预期。
*   上传并解析一份包含复杂表格和多级标题的CSO制度PDF文档，检查文本提取是否完整且格式正确。
*   手动修改外部系统中的一份SOP文档，并在`update_interval_seconds`周期结束后，检查FastGPT中该文档内容是否已更新至最新版本。
*   模拟一次认证失败的请求，观察是否能收到`401 Unauthorized`或`403 Forbidden`等正确的错误码反馈。
