# 临床决策支持制度的HTTP 接口与外部系统

## 这个品类的数据长什么样

临床决策支持（CDS）制度的数据主要来源于医疗机构内部的规章制度、操作规范（SOP）、诊疗指南、药品说明书以及各类医疗文献。这些数据通常以非结构化文档（如 PDF、Word 文档）或半结构化数据（如 JSON、XML 格式的药品说明书）存在。更新节奏相对稳定，但涉及法规、指南修订或新药上市时，可能出现集中更新。文档内容严谨，包含大量专业术语、缩写和计量单位，例如药品剂量（`mg/kg`）、治疗时长（`天`）、检验指标范围（`mmol/L`）等。文档内部常包含交叉引用和版本控制信息，强调制度的时效性和权威性。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

CDS 制度数据的严谨性要求 HTTP 接口具备高可靠性与错误处理机制，以确保数据传输的完整性。非结构化文档的特点意味着在通过 HTTP 接口上传后，需要强大的解析能力来提取关键信息，并对专业术语进行标准化处理。更新节奏的稳定性允许在接口设计时考虑增量更新策略，减少全量同步的资源消耗。文档中的交叉引用和版本控制信息，则要求在数据索引时保留这些元数据，以便在问答过程中提供溯源能力。此外，计量单位的准确识别和转换是避免临床误判的关键，接口在处理数据时需支持单位解析与校验，防止因单位混淆导致的错误。对于大文件上传，需要支持分片上传和断点续传，以应对传输中断。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 制度文档可能包含大量图表与附件，需要支持较大文件上传。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大型 PDF 文档解析复杂，需要较长的超时时间防止解析中断。 |
| `maxContext` | `3000 字符` | CDS 制度条文长且逻辑严密，需要更多上下文才能准确理解。 |
| `分段长度` | `800-1200 字符` | 确保单个分段能包含完整的制度条款或逻辑单元，避免语义割裂。 |
| `召回条数` | `前 10 条` | 制度问答对准确性要求高，增加召回条数提高相关性文档命中率。 |
| `相似度阈值` | `0.75-0.85` | 严格控制相似度，确保召回结果高度相关，减少误答风险。 |

## 容易做错的三处

*   HTTP 接口返回 `400 Bad Request` 且消息为 `Multimodal file size is too large`，原因是上传的制度文档大小超过了 `UPLOAD_FILE_MAX_SIZE` 参数限制。
*   API 调用后，MongoDB Change Streams 断开连接无法重连，原因是 MongoDB 副本集主节点发生漂移，旧连接未及时更新。
*   问答结果中出现计量单位错误或缺失，原因是文档解析时未能准确识别或标准化制度文档中的专业计量单位。

## 怎么确认配好了

*   通过 HTTP 接口上传多个不同大小和格式（如 PDF、DOCX）的典型制度文档，检查文件是否成功解析并入库，观察 `PARSE_FILE_TIMEOUT_SECONDS` 是否足够。
*   针对上传的制度文档，构造包含专业术语和计量单位的复杂问题，验证问答结果的准确性与完整性，并检查计量单位是否正确。
*   模拟 MongoDB 副本集主节点切换，观察系统是否能自动重连并继续处理数据流，确保数据同步的连续性。
