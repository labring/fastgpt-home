# 临床决策支持制度的知识库检索与召回

## 这个品类的数据长什么样

临床决策支持（CDS）系统的制度与SOP文档，其数据主要来源于医疗机构内部的规章制度、操作手册、指南、临床路径等，以及国家和地方卫生主管部门发布的法规文件。这些文档的更新频率受政策变动、医学进展和内部流程优化的影响，通常为季度或年度更新，部分紧急预案或新药指南可能会有更快的更新周期。文档结构以层级分明的章节、条款为主，常包含流程图、表格、图示等非文本元素。字段方面，涉及诊断标准、治疗方案、用药剂量、禁忌症、不良反应、操作步骤、风险评估等，单位涉及毫克（mg）、毫升（ml）、分钟（min）、国际单位（IU）等，且对数值精度有严格要求。

## 这些特征在「知识库检索与召回」这一环带来什么约束

CDS制度文档的层级结构和专业字段对知识库的切分粒度提出了要求，粗粒度切分可能导致关键信息丢失，细粒度则可能破坏上下文。专业术语和缩写（例如“QID”表示每日四次）在不同语境下含义可能固定，需要模型具备专业词汇理解能力。文档中包含的数值（如药物剂量、检验结果范围）对召回的精确性至关重要，简单的关键词匹配不足以应对。更新频率和版本管理要求知识库能够快速同步最新内容，并支持对历史版本的追溯与对比。流程图和表格等非文本信息需要转换为可检索的结构化数据，确保其内容在检索时能够被有效利用。召回结果必须高度相关且准确，以避免误导临床决策，直接关系到医疗安全。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `分段长度` | 800–1200 字符 | 兼顾上下文完整性与检索效率，避免切分破坏关键制度条文的语义。 |
| `重叠长度` | 100 字符 | 确保段落间上下文的连续性，衔接前后文，减少切分带来的语义割裂。 |
| `召回条数` | 前 5-8 条 | 确保涵盖足够多的潜在相关制度和SOP，同时避免引入过多噪声。 |
| `相似度阈值` | 按实测标定（建议初始值 0.78） | CDS领域对精度要求高，需根据实际数据和模型表现进行精细调整，确保高召回率和高准确率。 |
| `重排返回条数` | 3 条 | 在召回结果中精选最相关的核心制度或条款，直接支持临床决策。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对大型PDF或Word格式的SOP文档解析，保证文件能被完整处理。 |

## 容易做错的三处

*   知识库检索结果中出现大量无关或过时的制度条款，原因在于`相似度阈值`设置过低，未能有效过滤低相关性内容，或知识库未及时更新。
*   对于特定疾病的用药指南查询，召回结果未能包含完整的剂量和禁忌信息，现象是返回的文档片段不完整，原因在于`分段长度`设置过短，导致关键信息被截断。
*   用户上传的多个制度文件在知识库中无法被有效识别和检索，导致查询失败，原因在于文件解析失败或索引构建异常，可能与 `PARSE_FILE_TIMEOUT_SECONDS` 参数设置不足有关。

## 怎么确认配好了

*   针对典型临床场景提问，核对召回结果是否包含所有相关的制度条文、操作步骤和用药规范，确保结果的全面性。
*   验证针对具体数值（如药物剂量、检验指标范围）的查询，召回的文档片段能否准确提供对应的数值和单位信息。
*   模拟制度更新后的查询，确认知识库能够优先召回最新版本的SOP或指南，同时旧版本不再被优先呈现。
*   检查知识库日志，确保文件上传和索引构建过程中没有出现 `ERR_FILE_PARSE_FAILED` 或 `INDEX_BUILD_TIMEOUT` 等错误信息。
