# 偏差与 CAPA制度的HTTP 接口与外部系统

## 这个品类的数据长什么样

生物医药行业的偏差（Deviation）与纠正预防措施（CAPA）数据通常来源于质量管理系统（QMS）、生产执行系统（MES）或实验室信息管理系统（LIMS）。这些数据记录了从偏差的发现、记录、调查、根本原因分析到CAPA的制定、实施、验证及有效性评估的全过程。更新频率取决于事件的发生和处理进度，可能为每天多次，也可能为每周或每月一次。文档结构通常包含事件编号、发生时间、涉及产品/批次、描述、分类（如重大、主要、次要）、根本原因、CAPA计划、责任人、预期完成日期、实际完成日期、验证结果等字段。部分字段可能包含枚举值（如偏差分类），日期字段需要精确到小时，并可能涉及特定编码或缩写，例如“OOS”（Out of Specification）或“OOT”（Out of Trend）。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

偏差与 CAPA 数据的实时性要求，决定了 HTTP 接口需要支持高并发和低延迟的请求处理，以确保信息的及时同步。其复杂的文档结构和多样的字段类型，要求 FastGPT 的外部系统连接器具备灵活的数据映射和转换能力，能够准确解析并存储各类结构化与非结构化数据。例如，偏差描述可能包含大量自由文本，需要高效的文本嵌入和索引。枚举值和日期格式的标准化，对接口的数据校验逻辑提出了要求，避免因格式错误导致的数据导入失败。此外，由于这些数据涉及质量合规性，接口的安全性和审计日志功能也成为关键考量，以确保数据传输的完整性和可追溯性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `API_ENDPOINT` | `https://qms.example.com/api/deviations` | QMS系统提供的标准偏差数据接口地址 |
| `HTTP_METHOD` | `POST` 或 `GET` | 根据外部系统接口设计，`POST` 用于批量更新，`GET` 用于查询最新数据 |
| `REQUEST_TIMEOUT_SECONDS` | `60 秒` | 考虑到可能涉及复杂查询或批量数据传输，预留足够响应时间 |
| `MAX_RETRIES` | `3 次` | 应对网络瞬时抖动或外部服务短暂不可用，提高数据同步成功率 |
| `DATA_MAPPING_TEMPLATE` | 按实测标定 | 将外部系统字段映射到 FastGPT 知识库字段，确保数据解析准确 |
| `AUTH_HEADER` | `Authorization: Bearer <TOKEN>` | 基于 OAuth2 或 API Key 的认证机制，保障接口访问安全 |

## 容易做错的三处

*   HTTP 请求返回 `401 Unauthorized` 或 `403 Forbidden`：这通常是由于 `AUTH_HEADER` 配置不正确或令牌过期造成的，需要检查 API Key 或 Bearer Token 的有效性及权限。
*   知识库中部分字段数据为空或格式错误：原因在于 `DATA_MAPPING_TEMPLATE` 配置与外部系统返回的数据结构不匹配，或者外部系统返回的日期、枚举值未按预期格式化。
*   接口调用频繁出现 `504 Gateway Timeout`：这可能表明 `REQUEST_TIMEOUT_SECONDS` 设置过短，外部系统处理请求耗时超出预期，需要适当延长超时时间。

## 怎么确认配好了

*   通过 FastGPT 后台的“测试连接”功能，确认 HTTP 接口能够成功连接并返回 `200 OK` 状态码。
*   手动触发一次数据同步，检查知识库中是否新增或更新了偏差与 CAPA 数据，并核对关键字段（如事件编号、发生时间、偏差描述）的数据完整性与准确性。
*   在 FastGPT 知识库中，针对新导入的偏差数据进行提问，验证 AI 平台是否能正确理解并回答与偏差、CAPA 流程相关的问题，评估回答的准确性和相关性。
*   监控外部系统接口的调用日志，确认 FastGPT 发出的请求频率、请求体内容与预期一致，且没有过多的错误日志。
