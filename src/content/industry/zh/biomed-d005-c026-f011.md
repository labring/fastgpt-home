# 冷链物流制度的文档解析与分块

## 这个品类的数据长什么样
生物医药冷链物流领域的制度与SOP文档，主要来源于企业内部质量管理体系、药监部门法规文件以及国际标准组织规范。这些文档的更新节奏通常在半年到两年一次，以适应法规变化和业务流程优化。文档结构上，常包含多层级标题、流程图、表格和附件。文本内容大量涉及特定术语，例如“温控范围”、“GSP”、“GMP”、“批次管理”、“验证”等。字段常涉及温度、湿度、时间、批号、序列号等，单位精确到摄氏度、百分比、小时、天，并严格遵循计量标准。

## 这些特征在「文档解析与分块」这一环带来什么约束
冷链物流制度文档的特点对文档解析与分块提出了特定要求。首先，更新频率决定了需要支持增量更新和版本管理，确保知识库内容的实时性和准确性。其次，复杂的文档结构意味着需要智能识别标题层级、区分正文与附录、解析表格数据，避免信息丢失或分块错误。特定术语和字段的存在，要求分块时能保持术语的完整性，并能识别带单位的数值，这对于后续的精确问答至关重要。流程图和图片内容，则对多模态解析能力提出了需求，尽管目前主流RAG方案主要针对文本，但预留多模态扩展性是必要的。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `分段长度` | `500–800 字符` | 兼顾语义完整性和召回效率，避免单个分块过大导致信息冗余，或过小导致上下文缺失。 |
| `重叠长度` | `80–120 字符` | 确保上下文连续性，降低因分块边界造成的语义割裂，特别是对于流程描述。 |
| `分段方式` | `按标题层级与固定长度结合` | 优先保持章节语义完整性，再按固定长度切分，处理长篇幅制度文件。 |
| `文件类型` | `PDF, DOCX, XLSX` | 冷链物流制度文档主要采用这几种格式，确保全面覆盖。 |
| `解析超时时间` | `600 秒` | 考虑到大型SOP文档的复杂性，防止解析中断，确保 `status_code` 200。 |
| `最大文件大小` | `100 MB` | 覆盖常见制度文件的体积，防止因文件过大导致 `UPLOAD_FILE_MAX_SIZE` 限制。 |

## 容易做错的三处
*   解析后部分关键术语或流程描述被截断，导致问答结果不准确。原因在于 `分段长度` 设置过短，未充分考虑冷链专业术语和流程描述的长度。
*   上传PDF格式的制度文件后，系统报错 `文件解析失败` 或长时间无响应。原因可能是 PDF 中包含大量图片或扫描件，导致 OCR 识别耗时过长或失败，超过了 `解析超时时间`。
*   上传 Excel 表格数据后，解析结果无法有效提取表格中的温控范围或批次信息。原因在于默认解析器对复杂表格结构的识别能力有限，未将表格单元格内容作为独立语义块处理，导致字段 `temperature_range` 或 `batch_number` 提取不完整。

## 怎么确认配好了
*   上传一份典型制度文档，检查解析后文档的分块预览，确保各章节标题、关键流程步骤、表格内容等语义边界清晰，没有出现明显截断。
*   针对解析后的知识库内容，通过关键词搜索，验证冷链特有术语（如“GSP”、“温控验证”）在不同分块中是否保持完整，并能够被有效检索。
*   选取文档中包含表格数据的部分，提问关于表格内容的查询，例如“XX批次产品的温控范围是多少？”，验证问答结果是否能准确返回表格中的 `value` 与 `unit`。
