# 医保准入制度的HTTP 接口与外部系统

## 这个品类的数据长什么样

医保准入制度的数据主要来源于国家及地方医保局发布的政策文件、药品目录、诊疗项目范围、支付标准等。这些数据更新频率较高，通常按季度或年度进行调整，遇重大政策变动时可能临时更新。文档形式多样，包括 PDF 格式的正式文件、Excel 格式的药品或诊疗项目清单，以及部分在线发布平台的结构化数据。字段方面，药品目录会包含通用名、商品名、剂型、规格、医保支付类别、限定支付范围等；诊疗项目则有项目编码、名称、价格、支付比例等。单位通常为“元”、“百分比”、“毫克/片”等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

医保准入制度数据来源的多样性要求 HTTP 接口具备强大的文件解析能力，尤其是对 PDF 和 Excel 文件的结构化提取。高更新频率意味着系统需支持定时任务或Webhook机制，以便及时拉取最新政策变动。文档结构复杂性，特别是限定支付范围等描述性文本，对自然语言处理和语义理解提出了更高要求，影响知识库分段策略。字段与单位的标准化处理是确保问答准确性的关键，需要接口在数据摄入时进行单位归一化。此外，由于政策敏感性，对接口的鉴权机制和数据传输安全性也有较高要求，确保政策信息的准确无误传递。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `3000 Tokens` | 医保政策文档通常较长，需要更大的上下文窗口来理解政策细节 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大型 PDF 或 Excel 文件解析耗时较长，预留足够时间防止超时 |
| `分段长度` | `800 字符` | 政策条款通常包含多个条件和解释，该长度有助于保持语义完整性 |
| `相似度阈值` | `0.75` | 医保政策问答对准确性要求高，提高阈值减少不相关召回 |
| `重排返回条数` | `前 5 条` | 确保核心政策条款优先展示，提升用户获取关键信息的效率 |
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `120 秒` | 外部医保数据源可能存在网络延迟，延长超时时间避免请求中断 |

## 容易做错的三处

*   调用外部API后返回数据为空，原因可能是外部系统鉴权失败或请求参数缺失。
*   知识库更新后，应用对话返回的仍是旧政策信息，原因在于知识库与应用之间的关联接口未触发或未正确配置。
*   解析医保政策文件时，部分关键字段（如限定支付范围）未能正确提取，原因在于文件解析规则未能充分覆盖所有文档结构或OCR识别精度不足。

## 怎么确认配好了

*   通过 HTTP 接口上传一份最新的医保政策 PDF 文件，确认文件解析状态正常，且知识库中能检索到文件内容。
*   通过 API 模拟一次医保准入相关的提问，观察返回结果中是否包含预期的政策条款，并核对其准确性。
*   检查外部系统同步接口的日志，确认数据拉取任务按预期频率执行，且无连接错误或数据解析异常。
*   配置一个包含医保政策更新的Webhook，触发后验证知识库内容是否及时更新。
