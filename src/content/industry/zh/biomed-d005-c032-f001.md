# 医保结算制度的HTTP 接口与外部系统

## 这个品类的数据长什么样
医保结算制度的数据通常来源于国家医保局、省级医保中心或市级医保经办机构发布的官方文件。这些文件包括各类政策法规、操作细则、编码标准（如疾病诊断编码 ICD-10、医疗服务项目编码）以及费用报销目录。数据更新频率不一，政策法规可能每年或每季度调整，而编码标准和报销目录的更新则更为频繁，可能每月或每双月发布。文档结构以 PDF、Word 或 Excel 居多，部分机构也提供 XML 或 JSON 格式的接口。字段与单位具有高度标准化要求，例如费用金额精确到分，药品用量单位需符合国家药品标准，诊断与手术编码必须与医保信息系统保持一致。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
医保结算制度数据来源的权威性决定了接口需要优先对接官方发布渠道，确保数据准确性。更新频率的不确定性要求接口具备定时拉取与增量更新的能力，避免因政策变动导致问答结果过时。文档结构的多样性意味着数据解析模块需支持多种文件格式，特别是 PDF 和 Excel 中的表格结构化提取。字段与单位的严格规范性，尤其是编码体系，要求接口在数据传输和校验环节进行严格的格式验证，确保与医保信息系统的数据互操作性。例如，当医保结算问答涉及费用计算时，对金额字段的精度处理至关重要，任何小数位误差都可能导致结算错误。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `60 秒` | 多数医保接口响应时间较长，预留充足时间避免超时中断。 |
| `MAX_FILE_SIZE_MB` | `100 MB` | 医保政策文件，尤其是包含大量表格的 PDF，文件体积可能较大。 |
| `TEXT_SPLIT_CHUNK_SIZE` | `800–1200 字符` | 确保单个文本块包含足够上下文，同时避免过长导致语义分散，适用于法律条文解析。 |
| `RECALL_TOP_K` | `前 5 条` | 医保政策条文关联性强，多召回几条相关规定可提高准确率。 |
| `SIMILARITY_THRESHOLD` | `0.75` | 医保政策问答对精确性要求高，适当提高相似度阈值过滤不相关内容。 |
| `HTTP_AUTH_HEADER` | `Bearer Token` 或 `Basic Auth` | 确保接口调用的安全性，符合医保数据访问的合规性要求。 |

## 容易做错的三处
* 现象：调用外部医保接口时，返回状态码 401 或 403，提示“认证失败”或“无权访问”。原因：`HTTP_AUTH_HEADER` 配置的认证凭证过期、错误或未正确传递。
* 现象：问答系统对最新的医保政策变动无法给出正确答案，仍引用旧规定。原因：数据源接口未配置定时拉取任务，或增量更新机制失效，导致本地知识库未能及时同步官方最新数据。
* 现象：在涉及费用计算的问答中，返回结果的金额出现小数位偏差或单位错误。原因：外部系统返回的费用字段未进行严格的单位转换或精度处理，例如将“元”误读为“分”，或数值类型转换不当。

## 怎么确认配好了
* 选取近期发布的医保政策文件，通过 HTTP 接口拉取并检查其内容是否完整且无乱码。
* 针对医保报销目录中的特定疾病或药品，提问相关费用报销比例，并核对返回结果与官方规定是否一致。
* 模拟一次涉及多项医疗服务和药品费用的复杂医保结算场景，检查问答系统能否准确计算出个人支付和医保支付金额。
