# 医学事务制度的工具调用与插件

## 这个品类的数据长什么样

医学事务领域的制度与标准操作规程（SOP）数据通常以 PDF、Word 或扫描图片形式存在，内容涵盖药物临床试验规范、上市后药物警戒、医学信息沟通、合规审查流程等。这些文档的更新频率取决于法规变动和公司内部政策调整，通常为季度或年度更新，部分紧急指南可能即时发布。文档结构复杂，包含大量专业术语、法规条款、流程图和表格。字段包括文件编号、发布日期、修订版本、生效日期、负责人、适用范围等，单位多为日期、版本号或特定业务指标。

## 这些特征在「工具调用与插件」这一环带来什么约束

医学事务制度文档的复杂性决定了工具调用需要具备强大的语义理解能力，以准确识别不同版本间的差异和特定条款的含义。多样的文档格式要求系统具备灵活的文件解析能力，特别是对扫描件的光学字符识别（OCR）能力。字段的标准化程度不高，要求在工具调用前进行数据预处理或在插件中嵌入额外的解析逻辑。更新频率的不确定性使得工具调用结果需要能够追溯到具体的文档版本和生效日期，这要求插件能够与版本管理系统集成。专业术语的密集使用，对模型理解和生成准确回答提出了更高要求，可能需要定制化的词汇表或领域模型。

## 配置怎么定

| 配置项               | 建议取法       | 这样取的依据                                                              |
| :------------------- | :------------- | :------------------------------------------------------------------------ |
| `maxContext`         | `4000 字符`    | 医学事务文档单句信息量大，需确保模型能捕获上下文。                      |
| `分段长度`           | `500 字符`     | 保证每个段落包含完整概念，避免信息截断。                                  |
| `召回条数`           | `8 条`         | 增加召回数量，提高从复杂文档中获取相关信息的概率。                        |
| `相似度阈值`         | `0.78`         | 设定较高阈值以过滤掉语义不相关的结果，提升召回质量。                    |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`       | 大型 PDF 文件解析耗时较长，预留充足时间避免超时。                       |
| `ENABLE_OCR`         | `true`         | 确保对扫描件和图片格式的制度文档进行有效内容提取。                      |

## 容易做错的三处

- 模型调用工具时返回 400 状态码，通常是由于插件接口的请求体格式不符合预期，例如字段类型错误或缺少必填参数。
- 函数调用效果不佳，表现为模型未能准确识别调用工具的时机或参数，这可能是因为模型本身对函数调用指令的理解能力不足，或者提供的函数描述不够清晰。
- 连接外部工具时遇到认证失败，表现为 HTTP 401 或 403 错误，原因在于插件未正确配置请求头中的认证信息，例如 `Authorization` 字段缺失或令牌过期。

## 怎么确认配好了

- 调用插件并观察日志输出，确认请求参数与返回结果是否符合预期数据结构。
- 针对特定制度条款进行提问，检查模型是否能通过工具调用准确检索到相关文档段落，并引用正确的版本号和生效日期。
- 模拟用户提问多种查询场景，特别是涉及多文档交叉引用的情况，验证工具调用能否正确处理复杂逻辑并给出连贯回答。
- 对比不同版本制度的差异点进行提问，确认模型能否识别并告知版本间的变动，这需要插件能访问到版本控制信息。
