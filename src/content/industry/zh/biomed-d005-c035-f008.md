# 医院运营制度的工具调用与插件

## 这个品类的数据长什么样

医院运营相关的制度与 SOP 文档，其数据来源多为医院内部管理系统、规章制度库、质量管理体系文件等，通常以 PDF、Word、Excel 或内部知识库页面形式存在。更新节奏受政策法规变化、医院管理层决策及实际运营反馈影响，通常为季度或年度更新，但涉及医疗安全、感染控制等关键领域可能会有更频繁的修订。文档结构上，通常包含标题、章节、条款编号、责任部门、实施细则、附件等标准化字段。内容中常出现如“小时”、“天”、“次”、“%”、“mg/dL”等时间、频率、比率及医学检验单位，以及各类医疗设备型号和药品名称。

## 这些特征在「工具调用与插件」这一环带来什么约束

医院运营制度的标准化文档结构，要求工具调用时能够精准解析各层级信息，例如提取特定条款下的具体操作步骤。字段中包含的单位和专业术语，使得在进行数值比较或条件判断时，需要插件具备单位识别和规范化处理能力，避免因单位不一致导致判断错误。例如，某制度规定“用药时间间隔不少于 `6 小时`”，插件在接收到“`360 分钟`”时需能正确换算。更新频率的影响在于，工具和插件需要支持定期数据同步或版本管理机制，确保始终基于最新制度进行问答和决策，防止因制度滞后引发合规风险。此外，制度中常包含流程图、表格等非结构化信息，对工具的 OCR 或表格解析能力提出要求，以支持更复杂的查询和操作。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `2000 字符` | 医院制度文档单条内容往往较长，需保证上下文完整性。 |
| `召回条数` | `前 5 条` | 制度问答对准确性要求高，适当增加召回量以提高命中率。 |
| `相似度阈值` | `0.78` | 确保召回内容与查询意图高度相关，避免误导性答案。 |
| `分段长度` | `500 字符` | 兼顾语义完整性和搜索效率，避免过长或过短的分段。 |
| `重排返回条数` | `3 条` | 在召回基础上进行二次排序，进一步提升结果的精准度。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 处理大型 PDF 或 Word 文档可能需要较长时间解析。 |

## 容易做错的三处

*   工具调用后部分工具未执行：常见原因是一个工作流中挂载的多个工具，其触发条件或依赖关系未正确配置，导致模型在决策时未能按预期依次调用。
*   模型调用欠费或失败：经常是由于 API Key 配置错误、账户余额不足或模型服务提供商的并发限制导致，尤其在非流式调用模式下，单次请求资源消耗可能更高。
*   前端页面嵌入后功能异常：通常是由于 FastGPT 的前端组件与 Vue3 项目的依赖冲突、CSS 样式覆盖或跨域安全策略限制，导致接口调用失败或页面渲染不正常。

## 怎么确认配好了

*   针对典型制度查询，验证 AI Agent 是否能准确调用相关工具并返回预期结果，例如查询“急诊科收治流程”后，确认是否调用了流程图解析工具。
*   模拟制度更新场景，上传新版制度文档后，再次查询相同问题，检查 AI Agent 返回的内容是否已基于最新版本。
*   检查系统日志，确认工具调用环节无异常报错，特别是 `HTTP 5xx` 或 `Connection Timeout` 错误，确认工具调用链路畅通。
*   验证插件对制度中包含单位的数值型字段的识别和处理能力，例如询问“某药品最大剂量”，检查返回结果是否包含正确单位。
