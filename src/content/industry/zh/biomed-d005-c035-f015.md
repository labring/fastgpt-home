# 医院运营制度的部署与升级

## 这个品类的数据长什么样

医院运营制度数据主要来源于医院内部管理系统、行政部门发布的规章制度文件、以及各科室根据实际情况制定的操作规程（SOP）。这些数据更新频率不一，基础性制度如人事管理办法可能每年修订一次，而感染控制指南、设备操作规程则可能根据国家标准或新设备引入进行季度或月度更新。文档结构上，通常以 PDF、Word 或内部知识库页面的形式存在，内容包含大量层级标题、表格、流程图和专业术语。字段与单位方面，涉及科室名称、岗位职责、流程步骤、审批权限、时间节点（如“审批时限：3 个工作日”）、药品剂量单位、设备参数单位等，具有高度的专业性和规范性。

## 这些特征在「部署与升级」这一环带来什么约束

医院运营制度的数据特征对部署与升级带来了特定约束。首先，文档的复杂结构和多格式要求知识库平台具备强大的文档解析能力，尤其对 PDF 和 Word 中的表格及嵌套列表需要准确识别，以保证语义完整性。其次，更新频率不一的特点，要求部署方案支持增量更新和版本管理，避免每次更新都进行全量重新索引，降低系统负荷。专业术语和流程图的存在，意味着在文本切分时需格外注意上下文关联，避免关键信息被割裂。此外，字段中包含的时间、剂量等数值信息，在RAG检索时需要确保其准确性，否则可能导致错误的操作指导，因此对文本嵌入模型和检索策略的选择提出了更高要求。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 医院制度文件通常较大，包含图片和表格，需要支持上传大文件。 |
| `分段长度` | `800–1200 字符` | 制度文件段落较长，过短易丢失上下文，过长则影响检索精度。 |
| `召回条数` | `前 8 条` | 确保覆盖制度中多方面信息，提高答案的全面性。 |
| `相似度阈值` | 按实测标定 | 避免过度泛化或遗漏相关性高的制度条文。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 处理大型 PDF 文档解析可能耗时较长，防止因超时导致解析失败。 |
| `maxContext` | `3000 Tokens` | 制度问答对上下文长度要求较高，保证问答的准确性。 |

## 容易做错的三处

*   调用聊天接口响应缓慢，现象为 API 调用返回时间超过 `30 秒`：原因可能是文本嵌入模型负载过高，或者数据库查询索引未优化。
*   `npm install` 报错 `chakra-ui/react` 错误：通常是由于本地 Node.js 环境版本与项目依赖要求不符，或 npm 缓存问题导致。
*   `curl` 测试返回 `500` 错误码：往往是后端服务配置错误、环境变量缺失或数据库连接异常，需要检查服务日志文件。

## 怎么确认配好了

*   上传一份包含复杂表格和流程图的 PDF 制度文件，检查文档解析后是否能正确识别并切分内容。
*   针对一份包含更新内容的 SOP 文档，执行增量更新操作，确认系统仅处理变动部分，并能检索到最新信息。
*   选取至少 5 个涵盖不同业务场景的制度问题进行测试，对比系统回答与制度原文，评估回答的准确性和完整性，并根据实际业务需求设定准确率阈值。
*   模拟高并发调用场景，监控接口响应时间，确保在预期负载下响应速度符合要求，根据业务高峰期设定响应时间上限。
