# 呼吸系统制度的HTTP 接口与外部系统

## 这个品类的数据长什么样

呼吸系统相关的制度与SOP（标准操作规程）数据主要来源于医疗机构内部的规章制度、临床路径、诊疗指南以及药品说明书等。这些文档通常以PDF、Word或纯文本格式存储，内容涵盖疾病诊断标准、治疗方案、药物使用规范、护理流程、设备操作指南等。数据更新频率相对稳定，一般遵循国家卫健委或医院内部的年度审核与修订周期。文档结构通常包含章节标题、正文、图表、附录等，部分内容会涉及特定的医学术语、剂量单位（如毫克、微克、毫升）、时间单位（如小时、天、周）以及医学检查指标（如血氧饱和度百分比、肺功能指标升/秒）。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

呼吸系统制度文档的特性，对HTTP接口与外部系统集成提出了特定要求。首先，文档的多样性（PDF、Word）要求接口具备灵活的文件解析能力，能够准确提取不同格式中的文本信息、表格数据和图表描述。其次，医学术语的专业性和剂量单位的精确性，意味着在数据传输和处理过程中，需要避免语义丢失和单位混淆，这可能要求接口在数据预处理阶段进行标准化。再者，规章制度的更新周期性，决定了外部系统在调用接口时，需要考虑数据的版本管理和缓存策略，确保问答结果的时效性。HTTP接口的响应时间也需优化，以应对可能包含大量医学细节的复杂查询，尤其是在处理多文档交叉引用时。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `3000-4000` 字符 | 呼吸系统制度文档通常包含较长段落和详细描述，需要更长的上下文窗口来捕获完整语义。 |
| `分段长度` | `500` 字符 | 确保每个文本段落包含足够的上下文信息，同时避免单个段落过长影响召回效率。 |
| `召回条数` | `8-12` 条 | 复杂医学问题可能涉及多个制度章节，增加召回条数有助于覆盖更全面的信息。 |
| `相似度阈值` | `0.7-0.75` | 医疗领域的问答对准确性要求高，适当提高阈值能过滤掉不相关的低质量召回。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600` 秒 | 呼吸系统SOP文档可能包含大量图表和复杂排版，解析耗时可能较长。 |
| `HTTP_REQUEST_TIMEOUT` | `120` 秒 | 外部系统调用接口时，考虑到后端可能需要进行多文档检索和复杂推理，适当延长超时时间。 |

## 容易做错的三处

*   现象：API调用返回 `{"code":514,"statusText":"Internal Server Error"}` 错误，或返回结果为空。
    原因：文件解析失败，可能是上传了不支持的文档格式，或文档内容过于复杂导致解析器超时。
*   现象：问答结果中出现的药物剂量或检查指标单位错误，或数值被误解。
    原因：文本提取时未能正确识别和处理医学专用单位，导致数值与单位脱节。
*   现象：用户提问关于最新版制度，但系统返回的是旧版信息。
    原因：外部系统未及时同步或刷新知识库，导致HTTP接口调用的数据版本滞后。

## 怎么确认配好了

*   上传多种格式（PDF、Word）的呼吸系统制度文档，检查是否都能成功解析并入库。
*   针对文档中包含剂量、指标的典型问题进行提问，核对回答中数值和单位的准确性。
*   模拟制度更新场景，上传新版本文档后，通过API查询相关内容，确认返回的是最新信息。
*   使用包含复杂医学术语和长句的查询，测试API响应时间是否在可接受范围内。
