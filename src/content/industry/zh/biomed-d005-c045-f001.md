# 学术推广制度的HTTP 接口与外部系统

## 这个品类的数据长什么样

生物医药领域的学术推广活动，其制度与标准操作规程（SOP）文档具有独特的结构。数据源主要包括企业内部规章制度库、合规部门发布的指引、以及国家或地区药监部门的政策法规文件。这些文档通常以 PDF、DOCX 格式存储，更新频率较高，尤其是在政策调整或新产品上市时。文档内容包含大量专业术语、法规条款、流程图、审批节点、责任人定义、以及具体的行为规范。字段方面，往往涉及 `policy_id`、`version_number`、`effective_date`、`approver_department`、`related_product_lines` 等，其中日期和版本号对合规性审查至关重要。文档篇幅从数页到数百页不等，且经常包含内嵌表格和图示。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

学术推广制度文档的更新频率和合规性要求，决定了 HTTP 接口需要支持高效的文档版本管理和增量同步。大量非结构化文本、复杂的图表和表格，对文件解析和内容提取提出了高要求，直接影响 `chunk_size` 和 `overlap_size` 的设置。专业术语和法规条文的准确理解，要求 RAG 模型在召回阶段能有效处理长尾实体和多词短语。同时，由于合规性查询的严谨性，接口返回的答案必须能够追溯到原始文档段落，并提供 `document_id` 和 `page_number` 等元数据。对于外部系统，例如合规审批流或培训平台，HTTP 接口需提供稳定且具备授权机制的查询服务，以确保敏感信息的访问安全。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `100 MB` | 学术推广制度文档可能包含大量图表和附件，导致文件体积较大。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大型 PDF/DOCX 文件解析复杂，需要较长的处理时间。 |
| `分段长度` | `800 字符` | 确保法规条款和制度细则的语义完整性，避免关键信息被截断。 |
| `召回条数` | `前 10 条` | 提高合规性查询的覆盖率，增加相关制度被召回的概率。 |
| `相似度阈值` | `0.75` | 保证召回结果与查询内容高度相关，减少不准确的制度引用。 |
| `HTTP_CALL_TIMEOUT` | `30 秒` | 外部系统调用通常需要快速响应，避免长时间等待。 |

## 容易做错的三处

*   HTTP API 调用返回 `Invalid URL, code: 500`：通常是 `apiCollection` 中配置的外部服务 URL 格式不正确，例如缺少协议头 `http://` 或 `https://`。
*   上传大型制度文件时，接口返回 `400 <400> InternalError.Algo.InvalidParameter: Multimodal file size is too large`：这表明文件大小超过了系统设定的 `UPLOAD_FILE_MAX_SIZE` 限制，需要调整配置或对文件进行预处理。
*   外部系统在 MongoDB 主节点切换后无法重连，导致数据同步中断：这是因为连接字符串中未正确配置副本集信息或未启用 `replicaSet` 选项，使得驱动无法感知主节点漂移。

## 怎么确认配好了

*   上传一份典型的学术推广制度 PDF 文档，检查知识库中是否成功创建了多个分段，并核对每个分段的 `document_id` 和 `page_number` 元数据是否正确。
*   通过 HTTP 接口调用知识库查询与某项具体法规相关的制度，验证返回结果中包含至少 5 条相关度较高的制度条文，并确认每条条文的原文链接可访问。
*   模拟外部系统通过 HTTP 接口查询，并观察日志系统，确保在 MongoDB 主节点切换时，外部系统能够自动重新连接并继续获取数据，无明显服务中断。
