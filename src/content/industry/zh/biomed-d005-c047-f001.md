# 实验室服务制度的HTTP 接口与外部系统

## 这个品类的数据长什么样
实验室服务制度的数据主要来源于实验室内部管理系统、质量管理体系文件（如 ISO/IEC 17025 认证文档）、仪器设备操作手册以及实验方法验证报告。这些文档通常以 PDF、Word 或内部知识库页面的形式存在。数据更新频率相对较低，一般在制度修订、新设备引入或方法更新时进行，周期可能为季度或年度。文档结构通常包含标题、章节、条款、图表和附录。字段方面，会涉及标准操作程序（SOP）编号、版本号、生效日期、修订历史、适用范围、职责、操作步骤、安全注意事项、质量控制点等。单位方面，可能包含时间（分钟、小时）、温度（摄氏度）、压力（帕斯卡）、浓度（摩尔/升、毫克/升）等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
实验室服务制度文档的特性对 HTTP 接口与外部系统集成提出了具体要求。首先，文档多为非结构化文本，且包含大量专业术语和交叉引用，要求文本处理模块具备强大的语义理解能力，能够准确识别 S.O.P. 编号、仪器型号等关键实体。其次，更新频率较低意味着数据同步不必过于频繁，可以采用定时全量同步或基于版本号的增量更新策略，减少不必要的 API 调用。文档中包含的图表和特殊格式，可能需要预处理步骤将其转换为纯文本或结构化数据，才能有效进行知识嵌入。字段如生效日期、修订历史等，在知识库构建时可作为元数据，用于过滤或排序搜索结果。此外，对特定单位的识别和转换能力，对于确保问答结果的准确性至关重要，例如，当用户询问“培养箱温度要求”时，系统应能理解并返回正确的数值和单位。

## 配置怎么定

| 配置项                   | 建议取法       | 这样取的依据                                       |
| :----------------------- | :------------- | :------------------------------------------------- |
| `分段长度`               | `500–800 字符` | 制度文本逻辑性强，过短可能切断上下文，过长则引入噪音 |
| `召回条数`               | `前 8–12 条`   | 确保覆盖相关制度条款，避免遗漏关键信息             |
| `相似度阈值`             | `0.75–0.85`    | 保证召回内容的精准性，过滤不相关条款               |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`       | 制度文档可能较大，解析时间较长，需适当放宽超时限制 |
| `HTTP_REQUEST_TIMEOUT`   | `300 秒`       | 外部系统响应可能受网络或处理复杂性影响             |
| `maxContext`             | `8000 tokens`  | 制度问答通常需要较长的上下文来理解复杂条款         |

## 容易做错的三处
*   从外部系统同步文档时，出现 `404 Not Found` 错误，通常是由于 API 路径配置不正确或文档 ID 映射关系出错。
*   上传的 PDF 或 Word 文档内容无法被正确解析，导致知识库为空或信息不全，原因是文档中存在扫描件图片、复杂表格或特殊字体，未进行 OCR 识别或结构化提取。
*   问答结果中缺乏关键的数值或单位信息，例如只返回“温度要求”，没有具体数值，这往往是由于知识分段时未能有效保留数字与单位的关联性，或未在提示词中强调提取具体数值。

## 怎么确认配好了
*   上传典型实验室 SOP 文档，检查知识库中是否已正确抽取并存储了文档标题、版本号、主要章节内容。
*   针对特定制度条款提问，例如“培养基配制 SOP 的关键步骤是什么”，验证系统能否准确召回包含这些步骤的原文段落。
*   模拟用户对特定数值或单位的查询，例如“PCR 仪退火温度是多少”，检查返回结果是否包含正确的数值和单位，并与原文核对。
*   检查外部系统同步日志，确认文档同步任务是否按预期周期成功执行，并核对最新文档版本号。
