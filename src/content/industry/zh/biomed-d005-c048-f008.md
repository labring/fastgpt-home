# 家用医疗制度的工具调用与插件

## 这个品类的数据长什么样

家用医疗领域的制度与SOP文档，其数据来源多为各级监管机构发布的法规、行业协会制定的标准，以及企业内部依据这些规定编制的操作规程。更新频率相对稳定，通常在政策调整或技术迭代时进行修订，周期可能从数月到数年不等。文档格式以PDF、Word居多，内容结构化程度较高，常包含章节、条款、附件等，并有明确的编号体系。字段方面，常见的有“器械名称”、“适用范围”、“操作步骤”、“风险提示”、“维护周期”等，其中涉及计量单位时，如“压力”、“温度”、“时间”等，会严格遵循国际单位制或行业特定标准。这些文档的语言通常严谨、规范，专业术语较多。

## 这些特征在「工具调用与插件」这一环带来什么约束

家用医疗制度文档的结构化特性，要求工具调用与插件在处理时能有效识别章节、条款，实现精准定位。更新频率相对稳定，意味着在数据同步和缓存策略上可以采取周期性更新，不必追求实时性，减少不必要的资源消耗。文档中包含大量专业术语和计量单位，对模型理解和参数提取提出了更高要求，可能需要定制化的实体识别模型或词典，确保工具调用时参数的准确传递。此外，法规条文间的引用关系，决定了插件在进行知识检索时，需要支持复杂的关系图谱查询，以提供上下文完整、逻辑连贯的回答。对于涉及操作步骤的SOP，插件需要能够解析序列信息，并将其转化为可执行的指令或建议。

## 配置怎么定

| 配置项                       | 建议取法       | 这样取的依据                                                                                                                                                                             |
| :--------------------------- | :------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `maxContext`                 | `4000` tokens  | 家用医疗制度文档单次查询往往涉及多个关联条款，需要较大的上下文窗口以保证信息完整性。                                                                                                       |
| `召回条数`                   | `8` 条         | 制度问答对准确性要求高，适当增加召回条数可以提高相关信息的覆盖率，减少遗漏。                                                                                                           |
| `相似度阈值`                 | `0.78`         | 高阈值有助于过滤掉低相关性结果，确保召回的制度条文与查询意图高度匹配，避免误导。                                                                                                       |
| `重排返回条数`               | `3` 条         | 经过重排后，最相关的少数条目能有效满足用户对核心制度条款的快速获取需求。                                                                                                               |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300` 秒       | 家用医疗文档可能包含大量图表和复杂排版，解析时间较长，需要更长的超时设置。                                                                                                               |
| `UPLOAD_FILE_MAX_SIZE`       | `500` MB       | 考虑到法规文档可能包含大量附件和高分辨率图像，单文件大小限制应放宽以支持上传。                                                                                                         |

## 容易做错的三处

*   调用外部API时，`file` 格式参数未正确编码或上传，导致接口返回 `400 Bad Request` 错误，原因在于未将文件内容转换为 base64 字符串或使用多部分表单数据。
*   使用全局变量进行API参数赋值时，变量值为空或类型不匹配，导致工具调用失败，表现为接口返回 `500 Internal Server Error` 或字段为空，原因是变量作用域或数据转换处理不当。
*   CSV文件解析后，数据与原始界面显示不一致，出现部分行或列缺失，原因在于CSV文件中的特殊字符（如逗号、换行符）未按 RFC 4180 标准进行正确转义或引用。

## 怎么确认配好了

*   通过 FastGPT 的调试日志，检查工具调用时传递的参数是否与预期值一致，尤其是涉及专业术语和计量单位的字段。
*   针对典型的制度问答，在测试环境中执行查询，并比对模型返回的答案与原始文档中的相关条款，确认回答的准确性和完整性。
*   模拟制度文档更新场景，上传新版文件，检查知识库索引是否正确更新，并验证基于新文档的问答结果是否符合预期。
*   检查工具调用过程中，HTTP 请求的状态码是否均为 `200 OK`，确保外部接口调用成功且数据传输无误。
