# 小分子化药制度的HTTP 接口与外部系统

## 这个品类的数据长什么样

小分子化药的制度与标准操作规程（SOP）数据主要来源于药监部门发布法规、药企内部质量管理体系文件、研发流程文档以及生产工艺规范。这些数据更新频率相对稳定，通常在法规修订或内部流程优化时进行，周期可能为数月至数年。文档结构以层级分明的文本为主，常包含大量的条文、定义、图表和附录。字段与单位具有高度专业性，例如“半衰期”以小时（h）计，“剂量”以毫克（mg）计，批次号通常为字母数字组合，且常涉及严格的版本控制信息和审计追踪记录。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

小分子化药制度与SOP文档的专业性与结构化特点，要求HTTP接口在数据传输时必须严格遵守预定义的字段类型和格式，例如批次号或化学结构式字符串的准确传递。文档更新频率较低，意味着接口设计时对实时性要求不高，但对历史版本追溯能力有较高要求。大量层级文本的特性，使得文件上传接口需要支持多种文档格式（如 `.pdf`、`.docx`），并确保内容解析的完整性，尤其是对表格和嵌入式对象的识别。字段与单位的严谨性，要求外部系统在接收数据时能够进行有效的数据校验，例如确保剂量单位的正确性，避免因单位混淆导致的语义错误。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `MAX_FILE_SIZE_MB` | `50 MB` | 考虑SOP文档可能包含大量图表和版本历史，确保大文件上传。 |
| `PARSE_TIMEOUT_SECONDS` | `300 秒` | 复杂PDF或Word文档的解析耗时较长，避免因超时中断。 |
| `CHUNK_SIZE_TOKENS` | `800–1200 字符` | 确保制度条文的完整性，避免关键信息被切割。 |
| `SIMILARITY_THRESHOLD` | `0.75` | 保证召回结果与制度条款的高度相关性，减少误召回。 |
| `HTTP_REQUEST_TIMEOUT` | `60 秒` | 外部系统处理请求可能涉及数据库查询和复杂逻辑，预留充足响应时间。 |
| `ERROR_RETRY_COUNT` | `3 次` | 应对网络瞬时波动或外部系统偶发性故障，提高接口稳定性。 |

## 容易做错的三处

*   HTTP 请求返回 `502 Bad Gateway` 或 `504 Gateway Timeout`：现象是外部系统处理时间过长，超过了网关或代理服务器的默认超时设置。
*   上传文档后，知识库内容缺失或乱码：现象是解析器未能正确处理文档中的特定字体、嵌入对象或复杂表格结构。
*   调用外部接口时，返回 `400 Bad Request` 或 `422 Unprocessable Entity`：现象是请求体中的数据格式、字段类型或枚举值与外部系统API定义不符，例如批次号格式不正确。

## 怎么确认配好了

*   上传一份包含复杂表格和多级标题的 `.pdf` 文档，检查知识库中内容的层级结构是否完整，并能被正确检索。
*   通过HTTP接口向外部系统发送一个包含所有必填字段的请求，并验证外部系统是否成功接收并处理，可查看外部系统日志确认。
*   尝试调用对话接口，提问一个关于某个具体制度条款的细节问题，验证回答是否能准确引用原文并提供依据，核对引用的`doc_id`是否指向正确的文件。
*   使用一个故意填写错误数据格式的请求调用外部接口，确认外部系统返回的错误码和错误信息是否明确指出具体的问题字段。
