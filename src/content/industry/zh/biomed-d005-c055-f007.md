# 影像设备制度的工作流编排

## 这个品类的数据长什么样
影像设备，特指如 CT、MRI、超声诊断仪等医疗影像设备。其相关制度与 SOP 文档通常以 PDF、Word 或扫描图片形式存在，涵盖设备操作规程、维护保养手册、故障排除指南、质量控制标准及安全管理规范。数据来源主要是设备制造商提供的官方说明书、医院内部制定的管理细则及监管机构发布的合规要求。更新频率相对较低，通常随设备型号升级、法规更新或医院内部管理流程调整而进行，每年或每两年修订一次。文档结构严谨，多采用章节、条款编号，并包含大量专业术语、图示和表格。字段包括设备型号、序列号、操作步骤、参数范围（如 kVp、mA、曝光时间）、校准周期、安全注意事项等，单位涵盖物理量（如 kV、mA、ms、Hz）和时间周期。

## 这些特征在「工作流编排」这一环带来什么约束
影像设备制度数据的低更新频率意味着知识库构建时，初期数据同步后的增量更新压力较小，重心放在首次导入的准确性和完整性。文档中严谨的章节结构和专业术语要求工作流在文本分割时需考虑语义完整性，避免将关键操作步骤或参数描述拆散。PDF 和扫描图片格式的存在，对光学字符识别（OCR）的准确性提出了较高要求，OCR 质量直接影响后续文本嵌入的有效性。大量图示和表格内容，可能需要工作流具备多模态处理能力，或在文本提取后进行结构化信息识别。此外，参数范围和物理单位的出现，使得在问答场景中，对数值型信息的理解和比对成为一个挑战，工作流需要能够识别并处理这些特定数据类型，以提供精确的制度遵循建议或故障排查指引。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `分段长度` | `500–800 字符` | 确保单个知识块包含完整的操作步骤或条款，兼顾语义连贯性 |
| `召回条数` | `前 5–8 条` | 覆盖多条相关制度规定或操作指引，提高答案全面性 |
| `相似度阈值` | `0.78–0.85` | 平衡召回准确性与相关性，避免无关制度干扰 |
| `重排返回条数` | `前 3 条` | 精选最相关的制度条目，减少用户筛选成本 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 应对大型 PDF 或复杂扫描件 OCR 处理耗时，防止超时中断 |
| `CHUNK_OVERLAP_SIZE` | `100–150 字符` | 确保相邻段落间的上下文衔接，处理跨段落的专业术语解释 |

## 容易做错的三处
*   工作流执行超时或处理失败，常见于导入扫描版设备手册时，原因通常是 `PARSE_FILE_TIMEOUT_SECONDS` 参数设置过低，未能充分预留 OCR 处理复杂图像所需时间。
*   用户提问后，回答中未能提及关键操作参数，例如缺少 `kVp` 或 `mA` 值，这往往是由于文本分割时将包含数值信息的句子拆开，或 OCR 识别率低导致这些字段值丢失。
*   在需要多轮对话以明确故障现象时，工作流未能正确引导用户提供更多信息，表现为对话中断或回答泛泛，原因在于 `maxContext` 参数不足以保留完整的用户提问历史和系统追问逻辑。

## 怎么确认配好了
*   选取不同类型（PDF、Word、扫描件）的影像设备制度文档，进行知识库导入，检查日志中是否存在 `PARSE_FILE_TIMEOUT_SECONDS` 相关的错误，并确认所有页面内容均被正确提取。
*   针对典型的设备操作、故障排查和维护保养问题进行提问，核对回答中是否包含文档中的关键操作步骤、参数值和注意事项，评估 `相似度阈值` 和 `召回条数` 的组合效果。
*   模拟用户进行多轮对话，例如询问设备启动流程后，再追问某一步骤的详细参数，验证工作流在保持上下文连贯性方面是否达到预期，这与 `CHUNK_OVERLAP_SIZE` 和 `maxContext` 有关。
