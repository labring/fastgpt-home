# 心血管制度的HTTP 接口与外部系统

## 这个品类的数据长什么样
心血管疾病领域的制度与标准操作规程（SOP）数据主要来源于国家卫健委、各级医疗机构、行业协会发布的指南、共识以及内部管理文件。这些文档更新频率相对稳定，通常为每年或每两年修订一次，遇重大医学进展或政策调整时会有额外更新。文档结构以 PDF、Word 格式为主，包含大量表格、图示和流程图。文本内容涉及疾病诊断标准、治疗路径、药物使用规范、手术操作流程、护理要点等。字段与单位具有高度专业性，例如心率（次/分钟）、血压（mmHg）、药物剂量（mg/kg）、时间（小时/天），以及各种医学指标的正常范围。文档中常出现交叉引用和术语定义，对文本理解的准确性要求极高。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
心血管制度文档的更新频率决定了外部系统通过 HTTP 接口拉取或更新知识库的周期不宜过于频繁，避免资源浪费，但需确保在新版本发布后及时同步。文档中包含的复杂表格和图示，对文件解析提出了高要求，纯文本提取可能丢失关键信息，需要支持多模态解析或结构化信息提取能力。专业医学术语和单位的存在，要求在数据传输时保持其完整性和准确性，避免在编码或解析过程中产生歧义。例如，血压 `120/80 mmHg` 必须作为一个整体被识别和处理。文档间的交叉引用意味着知识库需要建立有效的关联机制，以支持深度问答。此外，制度问答对实时性要求不高，但对答案的准确性和可追溯性有严格要求，因此接口设计需支持来源文档的引用。

## 配置怎么定

| 配置项                       | 建议取法                                 | 这样取的依据                                                                                                                               |
| :--------------------------- | :--------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------- |
| `UPLOAD_FILE_MAX_SIZE`       | `100 MB`                                 | 心血管制度文档可能包含大量图片和复杂排版，文件大小通常较大。                                                                               |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`                                 | 处理大型 PDF 或 Word 文档需要较长时间，避免因超时导致解析失败。                                                                           |
| `chunk_size`                 | `800 字符`                               | 保证每个分段包含足够上下文，同时避免分段过长导致语义分散。                                                                               |
| `overlap_size`               | `100 字符`                               | 适当的重叠可以确保上下文的连贯性，尤其在处理流程描述时。                                                                                 |
| `recall_top_k`               | `10 条`                                  | 制度问答需要全面召回相关条款，保证答案的完整性，防止遗漏关键信息。                                                                       |
| `similarity_threshold`       | `0.75`                                   | 提高相似度阈值，确保召回的制度条目与用户查询高度相关，减少无关信息干扰。                                                                 |

## 容易做错的三处
*   调用 HTTP 接口后，返回的答案内容为空或不完整，现象是 `response.data` 字段为空。原因可能是文档解析失败，未能成功提取有效文本内容，或解析器无法处理文档中的表格和图示信息。
*   语音输入功能报错，提示 `Invalid audio format` 或 `Unsupported media type`。原因常在于外部系统上传的音频文件格式与接口要求的 `audio/mpeg` 或 `audio/wav` 等格式不符，导致服务器无法识别。
*   问答结果中出现的医学指标数值或单位错误，例如 `血压 120/80` 被识别成 `120 80`。原因多是文本分词器或实体识别模块未能正确处理带斜杠或特定单位的复合医学术语，导致信息丢失或误解。

## 怎么确认配好了
*   上传一份包含复杂表格和流程图的心血管 SOP 文档（例如《高血压诊断与治疗指南》PDF 版），通过 HTTP 接口调用知识库查询功能，确认返回内容能正确识别并呈现表格中的关键数据和流程步骤。
*   使用包含医学术语和单位的查询语句（例如“心肌梗死患者的肌钙蛋白 I 正常值是多少？”），通过 HTTP 接口进行问答，检查返回结果是否包含准确的数值和单位，并能引用到原文中的 `肌钙蛋白 I` 相关段落。
*   模拟外部系统通过 HTTP 接口上传多个不同格式（PDF、DOCX）的心血管制度文档，检查接口返回的 HTTP 状态码是否均为 `200 OK`，确保所有文件都能被系统正常接收和处理。
*   检查日志系统，确认在文档解析过程中没有出现 `PARSE_FILE_TIMEOUT_SECONDS` 设定的 `600 秒` 超时错误，同时验证 `UPLOAD_FILE_MAX_SIZE` 设定的 `100 MB` 大文件上传成功。
