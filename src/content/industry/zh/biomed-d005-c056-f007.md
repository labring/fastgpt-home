# 心血管制度的工作流编排

## 这个品类的数据长什么样

心血管领域的制度与SOP文档通常来源于国家卫生健康委员会、中华医学会心血管病学分会发布的临床指南、专家共识，以及各级医疗机构内部制定的诊疗规范、护理流程和设备操作手册。这些文档更新频率相对稳定，大型指南通常每3-5年更新一次，而医院内部SOP则可能根据实际情况每年修订。文档结构多为PDF或Word格式，包含大量医学术语、疾病分类编码（如ICD-10）、药物剂量、检查指标范围（如心肌酶谱、BNP）和治疗路径图表。字段方面，常涉及患者年龄、性别、既往病史、症状描述、体格检查结果、影像学报告（如超声心动图、冠脉CTA）、实验室检验值及其单位（如mmol/L、ng/L），以及治疗方案（药物名称、用法用量）和并发症处理。

## 这些特征在「工作流编排」这一环带来什么约束

心血管制度文档的数据特性，对工作流编排提出了特定要求。首先，文档中包含的ICD-10编码、药物通用名和剂量单位等标准化信息，使得在实体识别和知识图谱构建时需要精确匹配，避免因同义词或缩写导致的混淆。其次，大量的检验指标和影像学描述，要求工作流中的信息提取组件能准确解析数值和单位，并能关联到相应的疾病诊断或治疗指征。例如，`BNP` 值高于特定阈值可能触发心力衰竭的风险评估流程。再次，诊疗路径中的条件分支和决策点，如“是否进行PCI治疗”取决于“冠脉狭窄程度”和“患者症状”，这要求工作流编排支持复杂的条件逻辑判断 (`IF-THEN-ELSE`)。此外，指南的定期更新，意味着知识库需要具备高效的版本管理和增量更新能力，以确保工作流引用的制度始终是最新版本。对于历史文档的查询需求，则需要工作流能指定查询特定版本的知识。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `分段长度` | `500 字符` | 确保单个分段包含足够上下文，同时避免过长导致语义漂移 |
| `召回条数` | `8` | 平衡召回精度与模型处理负荷，覆盖多个相关制度点 |
| `相似度阈值` | `0.75` | 过滤低相关性文档片段，提升回答准确性 |
| `maxContext` | `3500 tokens` | 兼顾模型上下文窗口限制与心血管制度的复杂性 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 应对大型PDF指南解析耗时较长的情况，避免解析超时 |
| `重排返回条数` | `3` | 优先展示最相关的核心制度条款，提高最终回复质量 |

## 容易做错的三处

*   工作流中的AI模型选项为空，现象是下拉菜单未显示可用模型，原因可能是模型服务未正确注册或配置路径错误。
*   AI对话组件的`stream`回复内容注释未生效，现象是回复完成后才触发后续动作，原因在于对`stream`触发机制理解偏差，其触发条件在流式回复结束时。
*   文本内容提取组件返回的JSON结果为空，现象是输出数据结构缺少预期字段，原因常为正则表达式或JSON Path表达式与实际文档结构不匹配。

## 怎么确认配好了

*   通过模拟心血管疾病的典型问诊场景，验证工作流能否准确识别疾病名称、症状和关键检验指标。
*   使用不同版本的临床指南进行测试，确认工作流能根据指定的文档版本提供相应制度回答，并能识别出新旧版本差异。
*   在工作流中设置多个条件分支，输入不同患者特征，核对流程是否按照预设的诊疗路径正确跳转。
*   检查知识库中关于药物剂量和单位的提取结果，确保数值和单位 (`mg/kg/day`、`μg/min`) 均被正确解析和呈现。
