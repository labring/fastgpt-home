# 患者援助制度的HTTP 接口与外部系统

## 这个品类的数据长什么样
患者援助制度的数据主要来源于制药企业、慈善机构以及医疗服务提供方。这些数据通常以结构化或半结构化的文档形式存在，如 PDF 格式的制度文件、Word 文档的申请指南、以及 Excel 表格的药品清单与报销标准。更新频率方面，制度文件通常一年更新一次或根据政策调整进行不定期修订；药品清单与报销标准可能按季度或半年更新。文档内容涉及药品名称、适用病症、患者资格要求、申请流程、所需材料清单、援助比例或金额、以及援助周期等。字段包括`药品通用名`、`商品名`、`适应症`、`患者年龄范围`、`疾病分期`、`经济状况证明`、`申请表编号`、`援助上限`、`报销比例`等，单位常涉及`元`、`百分比`、`天`、`月`、`年`。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
患者援助制度文档的半结构化特性决定了在通过 HTTP 接口拉取数据时，需要支持多种文件类型的解析。更新频率的不确定性要求外部系统具备灵活的同步机制，例如支持周期性全量抓取与事件驱动的增量更新，以确保信息的时效性。文档中包含的敏感患者资格要求和经济状况证明字段，对数据传输的安全性提出了高要求，需要使用 HTTPS 协议，并可能涉及额外的身份验证机制。字段的精确性，如援助金额和报销比例，意味着在数据抽取和结构化过程中必须保证数值的准确性，避免因浮点数精度问题或单位转换错误导致信息偏差。此外，制度文件的复杂逻辑，如多条件并存的资格判断，要求在集成外部系统时，不仅要传输原始数据，还要考虑如何在 AI Agent 中有效构建知识图谱或业务规则，以支持复杂的问答场景。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `externalApiUrl` | 实际接口地址，例如 `https://api.example.com/pa_policy` | 外部系统提供的数据接口端点 |
| `requestMethod` | `GET` 或 `POST` | 根据外部系统 API 定义，通常用于获取静态文档或查询动态数据 |
| `headers` | `Authorization: Bearer <token>` | 确保数据传输的安全性与身份验证，外部系统通常要求携带认证信息 |
| `timeout` | `60000` 毫秒 | 考虑到可能涉及大文件传输或复杂查询，预留足够响应时间，避免因网络延迟或处理时间过长导致超时 |
| `maxResponseSize` | `50` MB | 制度文件可能包含图片或详细附件，预估单个响应的最大体积，避免因响应过大导致处理失败 |
| `rateLimitInterval` | `5` 秒 | 外部系统可能对访问频率有限制，设置合适的间隔以避免触发限流保护 |

## 容易做错的三处
*   HTTP 请求返回 403 Forbidden 状态码，现象是无法获取任何数据。原因可能是 `headers` 中 `Authorization` 字段的 token 过期或无效。
*   文件解析后，特定字段如`援助金额`或`报销比例`为空或格式错误。原因通常是文件解析器未能正确识别文档中不同排版格式下的数值信息，或者单位转换逻辑缺失。
*   在集成外部系统后，Agent 问答时经常给出过时信息。原因在于外部系统数据更新后，FastGPT 未能及时触发知识库的同步或重索引。

## 怎么确认配好了
*   在 FastGPT 知识库管理界面，手动触发一次数据同步，检查同步日志中是否有成功抓取新文件的记录。
*   通过 FastGPT 的调试接口，构造一个针对患者援助制度的查询，核对返回的答案是否准确包含了最新制度中的关键信息，例如最新的援助比例或资格要求。
*   检查外部系统提供的 API 监控日志，确认 FastGPT 发出的请求频率是否符合预期，且未触发限流错误。
