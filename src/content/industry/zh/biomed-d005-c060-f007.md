# 感染性疾病制度的工作流编排

## 这个品类的数据长什么样

感染性疾病领域的制度与 SOP 数据，主要来源于国家卫健委、疾控中心发布的指南、规范，以及各医疗机构内部制定的诊疗流程、防控手册。这些文档以 PDF、Word 或内部系统页面为主，更新频率相对较高，尤其是在新发传染病流行期间。文档结构通常包含引言、定义、流行病学、临床表现、诊断标准、治疗方案、预防与控制措施等章节。字段方面，常涉及病原体名称、宿主、传播途径、潜伏期、临床分型、药物名称、剂量、疗程、生物安全等级、隔离措施等。单位则涵盖时间（天、小时）、剂量（mg、g、IU）、浓度（mg/L）、温度（℃）等。

## 这些特征在「工作流编排」这一环带来什么约束

感染性疾病制度文档的快速更新特性，要求工作流中的知识库同步机制具备高效性，以确保问答结果的时效性。多样的文档格式和复杂的结构，使得文档解析环节需要更强的鲁棒性，特别是对表格、图示内容的抽取能力。字段类型与单位的丰富性，对问答结果的结构化输出提出了要求，例如在提供药物剂量时，需要同时给出单位。此外，由于感染性疾病的特殊性，某些制度问答可能涉及敏感信息，需要在工作流中集成权限控制或脱敏处理模块。工作流需要能够处理跨文档的知识关联，例如从一个指南中提取诊断标准，再从另一个SOP中获取对应的治疗流程。

## 配置怎么定

| 配置项             | 建议取法                               | 这样取的依据                                                                                                                                                             |
| :----------------- | :------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chunk_size`       | `800–1200 字符`                        | 确保知识块包含足够上下文，同时避免过长导致召回效率降低。感染性疾病制度的段落通常包含较多专业术语和逻辑关联。                                                               |
| `overlap_size`     | `100–200 字符`                         | 维持知识块间的连续性，减少因切分导致的语义断裂。                                                                                                                         |
| `recall_top_k`     | `5–8 条`                               | 适度增加召回条数，提升复杂查询下相关知识被命中的概率，尤其当制度文档涵盖多个相关病种或治疗路径时。                                                                     |
| `rerank_top_n`     | `3–5 条`                               | 对召回结果进行二次排序，确保最相关的知识片段优先展示，提高问答的准确性。                                                                                               |
| `parse_timeout`    | `300 秒`                               | 应对大型PDF或Word文档的解析耗时，避免因超时导致文档上传或处理失败，特别是包含大量图表和复杂布局的指南。                                                               |
| `max_tokens_output` | `1024–2048`                            | 确保模型有足够空间生成详细的回答，特别是当需要解释复杂的诊疗流程或列举多种治疗方案时。                                                                               |

## 容易做错的三处

*   发布的工作流通过 API 访问时返回 `403 Forbidden` 错误，原因在于 API Key 或访问权限未正确配置，或是工作流发布时未勾选“允许外部调用”选项。
*   工作流中串联多个 AI 对话节点，最终输出包含所有对话结果，原因是没有在最后一个 AI 对话节点配置 `response_mode` 为 `stream_last_node` 或 `whole_output`，导致默认聚合所有中间结果。
*   JSON 输入框在开发插件时无法选择变量，原因在于 `JSON_input` 类型的输入字段不支持直接引用上游节点的变量，需要通过 `JavaScript` 节点进行变量转换和 JSON 结构构建。

## 怎么确认配好了

*   上传一份包含复杂表格和图示的感染性疾病指南，检查知识库分段预览中表格内容是否被正确解析并保留上下文。
*   针对典型感染性疾病（如流感、结核病）的诊断或治疗流程，构造多轮问答，验证工作流能否持续追踪上下文并给出准确、连贯的回答。
*   使用 API 接口调用已发布的工作流，检查返回的 JSON 结构是否符合预期，特别是对于包含药物剂量、疗程等关键信息的字段，确保其单位和数值的正确性。
