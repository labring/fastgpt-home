# 手术机器人制度的工具调用与插件

## 这个品类的数据长什么样

手术机器人相关的制度与SOP文档，数据主要来源于医疗机构内部的质量管理部门、设备科以及厂商提供的操作手册。这些文档多以 PDF、Word 或扫描件形式存在，包含大量结构化和非结构化信息。更新频率相对较低，通常随法规修订、设备升级或临床实践优化而进行，可能是季度或年度更新。文档结构严谨，通常包含章节标题、编号、版本号、生效日期、修订记录、操作步骤、注意事项、故障排除等。字段方面，可能涉及 `设备型号`、`序列号`、`校准参数`、`耗材批次`、`操作人员资质` 等，单位则包括 `毫米 (mm)`、`度 (°) `、`牛顿 (N)`、`毫升 (ml)` 等精确的工程与医学单位。

## 这些特征在「工具调用与插件」这一环带来什么约束

手术机器人制度文档的数据特征对手术机器人制度的工具调用与插件提出了特定要求。文档更新频率低，意味着初期索引构建的成本较高，但后续增量更新压力较小，重点在于确保更新机制能准确识别版本差异。多样的文档格式需要强大的文件解析能力，尤其是对于扫描件的OCR识别精度要求高，确保 `设备型号` 等关键字段能被正确提取。文档中包含的精确工程与医学单位，要求工具调用时能准确识别和处理这些单位，避免因单位转换错误导致的操作风险。此外，大量的结构化信息和操作步骤，使得在问答时，需要插件能精确抽取特定步骤或参数，并可能需要结合外部数据库进行验证，例如验证 `操作人员资质` 是否符合要求。

## 配置怎么定

| 配置项                 | 建议取法                               | 这样取的依据                                                                                                                                      |
| :--------------------- | :------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------ |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB`                               | 考虑到制度文档可能包含大量图片或扫描件，文件体积偏大，此值可容纳多数情况。                                                                        |
| `PARSE_FILE_TIMEOUT`   | `600 秒`                               | 复杂 PDF 或 OCR 任务耗时较长，增加超时时间可避免解析中断。                                                                                      |
| `chunk_size`           | `800–1200 字符`                        | 制度条文段落长度适中，此范围可保证语义完整性且不至于过长影响召回效率。                                                                          |
| `overlap_size`         | `100 字符`                             | 确保上下文衔接，防止重要信息因分段而丢失。                                                                                                       |
| `max_tokens`           | `2048`                                 | 保障模型能处理较长的制度描述或操作步骤，避免截断关键信息。                                                                                      |
| `similarity_threshold` | 按实测标定，建议 `0.75-0.85` 之间       | 制度问答对准确性要求高，此范围能在保证召回率的同时，过滤掉不相关的低质量内容。                                                               |

## 容易做错的三处

*   调用外部API后，返回结果为空或不完整，导致最终回答无法生成。原因可能是外部API的鉴权失败或请求参数格式不正确，尤其是在传递 `设备序列号` 或 `耗材批次` 这类特定字段时未进行编码或类型转换。
*   上传的文档长时间显示“索引中”，无法进行问答。这是由于文档解析器在处理复杂的扫描件 PDF 时，OCR识别耗时过长，或因 `PARSE_FILE_TIMEOUT` 设置过短导致解析任务被中断。
*   用户提问“校准参数是多少”时，返回了多个不相关的参数或信息。这可能是因为 `similarity_threshold` 设置过低，导致召回了语义相似度不高但字面匹配的片段，未能精准定位到特定 `校准参数` 的定义。

## 怎么确认配好了

*   上传多种格式（PDF、Word、扫描件）的制度文档，检查其是否能在规定时间内完成解析并成功索引，特别是包含表格和图示的复杂文档。
*   针对文档中的特定 `设备型号`、`操作步骤` 或 `故障代码` 进行提问，验证工具调用插件能否准确识别并从文档中抽取相应信息，必要时与原始文档进行比对。
*   设计包含外部API调用的复杂问题，例如查询特定 `耗材批次` 的有效日期（假设此信息需从外部系统获取），检查插件能否成功发起HTTP请求并返回正确数据。
*   通过反复测试，逐步调整 `similarity_threshold` 和 `chunk_size` 等参数，直至在保证召回相关内容的前提下，有效过滤掉不相关信息，形成高质量的回答。
