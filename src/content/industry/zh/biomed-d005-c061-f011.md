# 手术机器人制度的文档解析与分块

## 这个品类的数据长什么样

手术机器人相关制度文档主要来源于医疗器械监管机构发布的法规文件、医院内部管理部门制定的操作规程（SOP）以及生产厂商提供的产品说明书。这些文档的更新频率相对稳定，通常在法规修订、新产品上市或技术升级时进行。文档结构上，法规文件常包含多级标题、条款编号、附件和引用标准；SOP 则呈现为流程图、步骤描述、责任人、风险点与应急预案；产品说明书侧重于技术参数、操作指引、维护保养和故障排除。数据字段方面，会涉及器械型号、序列号、软件版本、校准参数、使用年限、灭菌方式、故障代码及对应的解决方案。单位上，除了常见的长度、重量、时间单位，还会出现如“毫米汞柱（mmHg）”、“焦耳（J）”等特定医学或物理单位。

## 这些特征在「文档解析与分块」这一环带来什么约束

法规文件的层级结构和引用关系要求文档解析器能够准确识别并保持原文的上下文关联，避免将相互关联的条款错误分割。SOP 中的流程图和步骤描述对文本提取的顺序性和完整性提出高要求，任何步骤的遗漏或错位都可能导致问答结果的偏差。产品说明书中的技术参数和故障代码通常以表格或特定格式呈现，需要解析器具备结构化数据提取的能力，以确保数值和单位的准确性。此外，医疗器械领域的专业术语和特定单位，要求分块策略在处理这些内容时保持其语义完整性，例如“毫米汞柱”不应被拆分为“毫米”和“汞柱”。文档更新的周期性意味着知识库需要定期进行增量更新和版本管理，解析过程应能有效处理新旧文档的差异，避免冗余或冲突。

## 配置怎么定

| 配置项             | 建议取法       | 这样取的依据                                                 |
| ------------------ | -------------- | ------------------------------------------------------------ |
| `分段长度`         | 800–1200 字符  | 兼顾法规条款的完整性和SOP步骤的连贯性，避免关键信息被截断。  |
| `分段重叠长度`     | 100–200 字符   | 确保分段边界上下文的连续性，提高跨分段问答的准确性。         |
| `知识库类型`       | 文本知识库     | 针对制度、SOP和说明书等非结构化和半结构化文本内容进行优化。  |
| `解析策略`         | 递归分段       | 有效处理法规文档中的多级标题和嵌套结构，保持层级关系。       |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB         | 适应大型产品说明书或包含大量图表的SOP文档的文件大小。        |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒         | 预留足够时间处理结构复杂的PDF文档和长篇法规文件。            |

## 容易做错的三处

*   文档上传后显示解析失败或解析进度停滞，原因通常是文件内容复杂或文件大小超出系统限制，导致解析器超时或内存溢出。
*   用户提问后得到的回应未能涵盖文档中的完整步骤或相关条款，现象是回复内容跳过或简化了关键环节，原因在于分块策略未能有效保持SOP流程或法规条文的上下文连续性。
*   对于产品型号、校准参数等特定字段的提问，回答结果不准确或缺失单位，原因可能是解析器在结构化信息提取时未能正确识别或保留这些字段的语义完整性。

## 怎么确认配好了

*   上传典型法规文件和SOP文档，检查解析后的分块内容是否完整保留了条款编号、步骤顺序和图表说明，并核对关键术语和单位是否被正确识别。
*   针对文档中包含的复杂流程或多级嵌套的条款，进行提问测试，确保系统能够根据上下文提供连贯且准确的回答，并评估回答中引用的原文是否覆盖了足够的上下文信息。
*   选取文档中包含数值和特定单位（如“毫米汞柱”、“焦耳”）的技术参数，进行问答测试，验证回答中是否准确地包含了数值和对应的单位，并检查是否存在单位缺失或误识别的情况。
