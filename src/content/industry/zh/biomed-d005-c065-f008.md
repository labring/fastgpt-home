# 护理管理制度的工具调用与插件

## 这个品类的数据长什么样

护理管理制度的数据主要来源于医院管理部门、护理部内部文件、国家及地方卫健委发布的规范性文件。其更新频率相对较低，通常为季度或年度修订，遇重大政策调整或突发事件会进行临时更新。文档形式以 PDF、Word 居多，部分规章制度可能以网页形式发布在内部知识平台。核心文档通常包含标题、发布日期、修订历史、适用范围、职责分工、操作流程、考核标准等结构化字段。其中，操作流程部分常以步骤分解、条件判断、异常处理等逻辑描述为主，涉及的单位包括时间（分钟、小时、天）、数量（人次、件）、比率（百分比）等。

## 这些特征在「工具调用与插件」这一环带来什么约束

护理管理制度的低更新频率意味着知识库的索引重建成本较低，但对召回结果的时效性要求极高，因为制度一旦生效便具有强制执行力。文档结构化程度较高，尤其是操作流程部分，为工具解析和结构化信息抽取提供了便利，有助于精确匹配用户查询意图。然而，流程中的条件判断与异常处理逻辑复杂，需要工具调用能支持多步骤推理和条件分支。字段与单位的特定性，如“操作时间 30 分钟内完成”，要求工具在生成答案时能准确引用并处理这些数值信息，避免模糊表述。此外，制度文本中常包含大量专业术语和缩略语，对模型的语义理解能力和工具的准确匹配提出挑战。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `分段长度` | `500–800 字符` | 确保单个分段能完整包含一个操作步骤或制度条款，便于上下文理解。 |
| `召回条数` | `5–8 条` | 兼顾召回的全面性与模型处理上下文的效率，减少无关信息干扰。 |
| `相似度阈值` | `0.75–0.85` | 提高召回结果的相关性，过滤掉与制度内容关联度较低的文档片段。 |
| `重排返回条数` | `3–5 条` | 进一步优化排序，确保最相关的核心制度条文优先展示。 |
| `tool_call_timeout` | `60 秒` | 多数工具执行时间较短，预留足够时间处理复杂查询或外部服务响应。 |
| `max_tokens` | `2048` | 为模型生成详尽的制度解释和操作流程预留足够的输出长度。 |

## 容易做错的三处

- 工具调用失败并返回 `HTTP 500` 错误，常见原因是外部 API 服务鉴权信息 `api_key` 配置不正确或已过期。
- 用户询问特定护理操作流程时，模型仅返回制度条文，未提供具体操作步骤，原因在于工作流设计中缺少对抽取出的结构化流程数据的进一步处理或工具调用。
- 模型在回答中错误引用了制度中的时间或数量单位，例如将“30 分钟”误写为“30 小时”，这通常是由于未在工具定义中明确参数的单位或在模型输出时缺乏单位校验机制。

## 怎么确认配好了

- 针对包含具体时间、数量等单位的制度查询，检查模型输出是否准确引用了这些数值和单位。
- 模拟用户提问涉及多步骤操作流程的问题，验证模型是否能通过工具调用，按顺序拆解并生成正确的操作指引。
- 选取制度中包含条件判断（例如“如果...则...”）的条款进行测试，确认模型能识别并根据条件给出相应分支的回答。
