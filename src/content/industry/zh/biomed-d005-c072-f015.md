# 清洁验证制度的部署与升级

## 这个品类的数据长什么样
清洁验证制度的数据主要来源于企业内部的质量管理体系文件，包括清洁验证主计划、验证方案、验证报告、标准操作程序（SOP）、风险评估报告、偏差处理记录等。这些文档通常以 PDF、Word、Excel 等格式存储，部分数据可能以扫描件形式存在。更新频率方面，制度类文档更新周期相对较长，通常为一年一次或根据法规要求、工艺变更进行修订；验证报告和偏差记录则随生产批次或事件实时生成。文档结构上，SOP 具有明确的层级和步骤，验证报告包含设备信息、清洁剂、取样点、分析方法及残留限度等结构化与非结构化信息。字段方面，常见的有设备编号、批次号、清洁剂名称、残留物名称、检测方法、限度值、实际检测结果等，单位涉及 ppm、µg/cm²、mg/L 等。

## 这些特征在「部署与升级」这一环带来什么约束
清洁验证制度数据的特点对部署与升级提出了具体要求。文档更新周期长但内容严谨，要求知识库能够有效处理版本迭代，并确保历史版本可追溯。大量 PDF 和扫描件的存在，意味着需要强大的文件解析能力，尤其是对表格和图片内容的识别。结构化与非结构化信息混杂，要求 FastGPT 在数据导入时能进行智能抽取和分段，确保关键字段如限度值、检测结果等被准确索引。字段与单位的特定性，例如 ppm 和 µg/cm²，需要系统在问答时能够理解并避免混淆，可能需要定制化的后处理逻辑。此外，制度文件的敏感性要求部署环境具备高安全性，并支持权限管理，升级过程需确保数据完整性与可用性，避免因内存或文件上传问题导致服务中断。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 清洁验证报告和 SOP 文件可能包含大量图表与扫描件，单个文件体积较大。 |
| `分段长度` | `800 字符` | 制度文件段落较长，过短分段会丢失上下文，过长则降低检索精度。 |
| `重叠长度` | `100 字符` | 确保相邻段落间的语义连续性，避免关键信息被切割。 |
| `maxContext` | `32768` | 复杂制度问答需要更长的上下文窗口来理解前后关联的法规条款。 |
| `相似度阈值` | `0.75` | 制度文本专业性强，提高阈值可减少不相关或模糊结果的召回。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大文件解析耗时较长，防止因超时导致文件导入失败。 |

## 容易做错的三处
*   在创建知识库时出现 `worker terminated due to reaching memory li` 错误，通常是由于服务器内存不足，无法处理大文件解析或高并发导入任务。
*   升级 FastGPT 版本后，上传文件报错 `Failed to create post presigned url`，可能原因是没有正确配置对象存储服务（如 S3）的访问权限或端点，导致预签名 URL 生成失败。
*   问答结果中清洁剂残留限度值与实际检测结果混淆，原因是文本分段或实体识别时未能有效区分相似的数值型字段。

## 怎么确认配好了
*   上传并解析一份包含表格与图表的清洁验证报告 PDF 文件，检查知识库中是否正确提取了设备编号、限度值等关键信息。
*   对多份清洁验证 SOP 文档进行问答测试，验证系统能否准确回答“XX 设备清洁验证的步骤是什么”或“YY 清洁剂的推荐使用浓度是多少”等问题。
*   通过 FastGPT 管理界面检查 `UPLOAD_FILE_MAX_SIZE` 和 `PARSE_FILE_TIMEOUT_SECONDS` 等系统参数是否已按预期生效。
*   在升级后，尝试上传多个大文件（例如超过 100 MB 的 PDF），确保文件能够正常上传并解析，没有出现 `Failed to create post presigned url` 或内存溢出错误。
