# 生物制药设备制度的HTTP 接口与外部系统

## 这个品类的数据长什么样

生物制药设备的制度与 SOP 数据通常来源于设备供应商提供的操作手册、内部质量管理体系文档、以及设备日常维护记录。这些文档多以 PDF、Word 或扫描件形式存在，内容结构复杂，包含大量图表、流程图和技术参数。数据的更新频率相对较低，主要发生在设备升级、工艺变更或法规更新时，通常为季度或年度更新。文档中涉及的字段包括设备型号、序列号、校准周期、维护步骤、故障代码及处理方法等，单位涉及压力（kPa, psi）、温度（℃, ℉）、流量（L/min, mL/s）等，对精度要求极高。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

生物制药设备制度数据的高度结构化和专业性，要求外部系统在接入时能准确解析复杂文档格式，特别是图表和流程图中的关键信息。其较低的更新频率意味着无需过于频繁地触发全量同步，增量更新机制更为高效。文档中包含的特定技术参数和单位，如 `校准周期` 字段可能以 `天` 或 `月` 为单位，需要接口具备灵活的数据类型处理能力。此外，由于这些数据通常存储在内部文档管理系统（DMS）或企业资源规划（ERP）系统中，HTTP 接口设计需考虑与这些系统的认证机制和数据导出能力兼容，确保数据安全和完整性。对于扫描件，OCR 识别的准确率和后处理能力是关键，需要接口能够处理潜在的识别错误。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `800–1200 字符` | 确保能够捕获单个制度条款或操作步骤的完整语义，避免截断关键信息。 |
| `分段长度` | `300 字符` | 兼顾语义完整性和向量检索效率，避免单个分段过长导致噪声。 |
| `召回条数` | `前 5 条` | 生物制药领域问题通常需要精确且聚焦的答案，过多召回可能引入不相关信息。 |
| `相似度阈值` | `0.75–0.85` | 保证召回结果与提问高度相关，过滤掉相似度较低的制度条目。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 处理大型 PDF 或 Word 文档可能需要较长时间，避免因超时导致解析失败。 |
| `重排返回条数` | `3 条` | 在少量高相关性的召回结果中进行排序，进一步提升答案精准度。 |

## 容易做错的三处

*   调用问答接口时报错 `配额不足`：外部系统访问凭证可能配置错误，或关联的 API Key 额度已用尽，需要检查密钥配置与平台用量。
*   文档导入后，问答结果中关键技术参数（如压力值 `kPa`）缺失：文档解析环节对图表或复杂表格的 OCR 识别效果不佳，导致关键数值或单位未能正确提取。
*   集成后前端平台无法显示渠道界面或数据：通常是由于 `API_URL` 或 `API_KEY` 等环境变量在 Docker 部署时未正确挂载或配置，导致服务间通信失败。

## 怎么确认配好了

*   上传一份包含设备型号、校准周期的 PDF 文档，通过问答接口查询该设备的校准周期，核对返回结果是否准确包含数值和单位。
*   模拟一次设备故障场景的提问，验证系统能否从 SOP 中准确召回对应的故障代码和处理步骤。
*   检查外部系统日志，确认 HTTP 请求的响应状态码为 `200 OK`，且数据传输无异常，特别是对于包含大量文本的文档。
*   针对一个特定设备参数（例如 `清洗液温度`），修改其在源文档中的值，然后触发数据同步，验证问答结果是否更新为最新值。
