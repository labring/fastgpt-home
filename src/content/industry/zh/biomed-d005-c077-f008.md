# 皮肤科制度的工具调用与插件

## 这个品类的数据长什么样

皮肤科制度与 SOP 文档主要来源于医院、药企、医疗器械厂商的内部规章、国家卫健委发布的临床诊疗指南、行业协会的实践共识。这些文档通常以 PDF、Word、或结构化的 XML/JSON 格式存储。更新频率不一，国家指南可能每年或数年更新一次，医院内部 SOP 则可能根据新技术或新药物的引入进行季度或半年度修订。文档结构上，通常包含章节标题、正文、图表、参考文献、附件。字段和单位具有很强的专业性，例如药物剂量（mg/kg）、治疗时长（周/月）、诊断标准（mm、cm²）、评估量表分数。

## 这些特征在「工具调用与插件」这一环带来什么约束

皮肤科制度文档的专业性和结构化特点，对工具调用与插件提出了特定要求。例如，对药物剂量的查询，需要插件能理解并处理不同单位的换算；对诊断标准的查询，可能涉及多字段匹配和数值范围判断。文档更新频率不一，意味着工具调用需要支持版本管理，以确保查询结果基于最新或指定版本的制度。此外，文档中包含的图表和参考文献，如果需要通过工具提取信息，则需要插件具备图像识别或链接解析能力。当制度涉及多个步骤时，工具调用需要能够串联多个信息点，模拟决策路径，这要求插件具备更强的逻辑处理能力。

## 配置怎么定

| 配置项             | 建议取法       | 这样取的依据                                   |
| :----------------- | :------------- | :--------------------------------------------- |
| `maxContext`       | `4000` token   | 兼顾上下文长度与响应速度，避免超长输入导致调用失败。 |
| `toolCallTimeout`  | `600` 秒       | 应对复杂查询和外部 API 调用可能产生的延迟。    |
| `pluginRetryCount` | `3` 次         | 提高因网络波动或外部服务瞬时故障导致的插件调用成功率。 |
| `streamOutput`     | `false`        | 避免工具运行记录在回复中流式输出，提升用户体验。 |
| `responseMode`     | `tool_message` | 确保工具调用结果以结构化消息形式返回，便于后续处理。 |
| `maxTokens`        | `1024` token   | 限制插件输出长度，防止过长输出占用过多资源。 |

## 容易做错的三处

*   工具调用模块反复输出运行记录，原因通常是 `streamOutput` 参数未设置为 `false`，导致中间步骤信息被直接输出。
*   调用外部工具后响应速度慢，可能是 `toolCallTimeout` 参数设置过短，或者 `maxTokens` 限制过大，导致模型等待或生成过长内容。
*   插件无法正确解析文档中的专业术语或单位，现象是返回结果为空或不准确。原因在于插件未针对皮肤科特有的数据字段和单位进行适配，缺乏相应的解析逻辑。

## 怎么确认配好了

*   通过模拟实际查询，检查工具调用是否能准确返回皮肤科制度中特定药物的剂量范围，并与原始文档进行比对，确认数值和单位的正确性。
*   验证当制度文档更新后，重新索引知识库并执行查询，确保工具调用结果反映最新版本内容。
*   测试插件在处理包含图表或参考文献的查询时，是否能正确识别并提示无法处理此类信息，或能通过特定插件成功提取关键信息。
