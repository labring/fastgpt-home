# 监护设备制度的HTTP 接口与外部系统

## 这个品类的数据长什么样
监护设备相关制度与SOP文档通常以PDF、Word或内部知识库页面形式存在。其数据来源主要是医疗机构的质量管理部门或设备科，更新频率相对较低，通常为每年一次或根据法规要求进行修订。文档内容结构化程度不一，包含大量专业术语、流程图和操作步骤。关键字段包括设备型号、操作规程、维护周期、故障处理流程、耗材清单、校准标准等。单位方面，会涉及压力（kPa, mmHg）、时间（秒, 分钟）、温度（℃）、流量（L/min）等，且对数值精度有明确要求。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
监护设备制度文档的低更新频率意味着外部系统同步时无需频繁轮询，更适合事件驱动或定期（例如每月）全量同步。文档中包含的流程图和表格结构，对解析工具提出了较高要求，需要确保这些非文本信息能被有效识别和索引。专业术语和计量单位的精确性要求，使得在数据抽取和知识图谱构建时，需特别关注词汇表和单位转换规则的维护，避免语义丢失或误解。此外，文档通常存储在受限的内部网络或飞书等协同平台，外部接口需具备相应的认证和授权机制，以保障数据安全和合规性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `2000 字符` | 监护设备SOP单条规程内容较长，需保证上下文完整性 |
| `chunkOverlap` | `100 字符` | 确保分段衔接，避免关键信息被切割 |
| `requestTimeout` | `600 秒` | 飞书等平台API响应可能较慢，需预留足够时间 |
| `concurrencyLimit` | `2` | 避免对内部系统造成过大压力，保障服务稳定性 |
| `errorRetryCount` | `3` | 应对间歇性网络波动或API限流情况 |
| `authHeaderName` | `X-Feishu-Token` | 飞书API认证通常使用自定义Header传递Token |

## 容易做错的三处
*   外部系统返回状态码 `400`：通常是由于请求参数格式不正确或缺少必要字段，例如认证 `token` 过期或无效。
*   文档内容解析后部分字段为空：原因在于解析器未能正确识别文档中的表格或流程图结构，导致关键数据丢失。
*   HTTP 请求超时：可能由于目标系统响应延迟，或网络链路不稳定，特别是当请求需要处理大型PDF文件时。

## 怎么确认配好了
*   执行一次完整的文档同步流程，检查日志中是否出现非 `200` 状态码的HTTP响应。
*   随机抽取多份已同步的监护设备SOP，比对原始文档与FastGPT中解析出的内容，检查关键字段、流程步骤和计量单位是否完整且准确。
*   模拟用户提问，查询关于特定监护设备型号的操作规程或故障处理方法，验证回答的精确性和完整性，并核对引用原文段落的准确性。
