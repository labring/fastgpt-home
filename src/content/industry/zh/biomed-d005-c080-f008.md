# 眼科制度的工具调用与插件

## 这个品类的数据长什么样

眼科制度与 SOP 文档通常来源于国家卫健委、药监局、医院管理部门发布的规章制度、临床诊疗指南、药品说明书以及各级医疗机构内部制定的操作流程。这些文档以 PDF、Word 或结构化数据库的形式存在，更新频率不一，国家层面的法规可能数年更新一次，而医院内部的 SOP 则可能每年或根据新技术、新设备引入进行修订。文档内容涵盖眼部疾病诊断标准、治疗方案、手术规范、器械使用说明、药物剂量与禁忌、感染控制流程等。字段与单位方面，常涉及视力（如 `LogMAR`、`Snellen`）、眼压（`mmHg`）、药物浓度（`mg/ml`）、手术时间（`分钟`）、设备参数（`焦耳`、`赫兹`）等专业计量单位。

## 这些特征在「工具调用与插件」这一环带来什么约束

眼科制度文档的专业性与更新周期决定了工具调用需要高度精确的语义理解能力，以避免误诊误治风险。大量专业术语和计量单位的存在，要求插件能够识别并正确处理这些信息，例如将 `眼压` 转换为 `mmHg` 单位进行比较或计算。文档更新的不规律性，使得定期的数据源同步和索引重建成为必要，确保知识库的时效性。此外，不同来源的文档可能存在格式差异，对 PDF 和 Word 文档的解析能力，以及从结构化数据中提取关键信息的能力，直接影响问答的准确性。在涉及药物剂量和手术参数等敏感信息时，工具调用需要有严格的验证机制，避免直接输出未经核实的数值。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `2000` 字符 | 确保能包含眼科制度中较长的段落，同时避免过大的上下文导致模型理解偏差或推理成本过高。 |
| `召回条数` | `8` 条 | 兼顾召回率与模型处理效率，覆盖多个相关制度条目。 |
| `相似度阈值` | `0.75` | 眼科制度问答要求高准确性，提高阈值可过滤掉相关性较低的结果。 |
| `重排返回条数` | `3` 条 | 精选最相关的少量制度条款，便于用户快速定位核心信息。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300` 秒 | 考虑到眼科制度文档可能包含大量图表和复杂排版，解析时间可能较长。 |
| `http_plugin_timeout` | `60` 秒 | 外部 API 调用需要有足够的响应时间，尤其是在查询药品数据库或设备参数时。 |

## 容易做错的三处

*   调用外部药品数据库 API 时返回 `502 Bad Gateway` 错误，原因在于 HTTP 插件配置的 `URL` 或 `请求头` 与实际 API 要求不符，或目标服务暂时不可用。
*   搜索插件返回的网页链接无法直接读取内容，导致关键信息缺失，这是因为插件默认仅返回链接和简要描述，未能配置进一步的网页内容抓取或解析步骤。
*   模型在回答眼科手术流程时，提供的参数或步骤不完整，原因可能是知识库中相关 SOP 文档的分段粒度过大，导致召回时无法精准定位到具体的子步骤。

## 怎么确认配好了

*   针对典型眼科疾病的诊断流程、用药禁忌等问题，测试问答系统是否能准确引用相关制度或 SOP 的具体条款和数值，并核对引用内容与原始文档一致。
*   使用包含专业术语和计量单位的查询，验证系统能否正确识别并处理这些信息，例如输入 `青光眼治疗眼压目标`，检查返回结果是否包含 `mmHg` 单位的数值范围。
*   模拟制度更新场景，上传新版文档，随后提问相关内容，确认知识库已完成索引更新，并能提供最新信息，验证数据同步与索引重建机制的有效性。
*   通过调用外部药品查询插件，输入特定药物名称，检查能否成功获取到药物说明书中的详细信息，并核对返回的字段是否与 API 预期输出一致。
