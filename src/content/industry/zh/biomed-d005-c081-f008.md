# 神经退行性制度的工具调用与插件

## 这个品类的数据长什么样

神经退行性疾病领域的制度与SOP文档，其数据来源主要为各级医疗机构、药企研发部门、临床试验中心以及监管机构发布的指南、标准操作流程和研究报告。这些文档更新频率相对较低，通常随政策调整或新研究进展进行修订，周期可能为数月至数年。文档结构多为层级分明的文本，包含大量专业术语、缩写、图表和交叉引用。字段方面，常见有疾病分类代码、药物剂量与给药途径、诊断标准、治疗方案、伦理审查编号、临床试验阶段、不良事件报告格式等。单位使用严谨，如药物浓度单位 `mg/mL`、时间单位 `小时`、`天`、`年`，以及生物标志物浓度 `pg/mL`。

## 这些特征在「工具调用与插件」这一环带来什么约束

神经退行性疾病制度文档的低更新频率意味着知识库构建时，初期数据同步和后期增量更新策略需要关注，避免频繁重复索引。复杂的层级结构和交叉引用对文档解析器提出要求，需确保语义关联性不丢失，方便后续的精确问答。大量的专业术语和缩写，要求工具调用时能准确识别并映射到对应的知识图谱或外部数据库，例如，缩写 `AD` 需正确解析为阿尔茨海默病。字段与单位的严谨性，使得在执行药物剂量计算、治疗周期推断等插件功能时，必须严格校验输入输出格式，防止因单位混淆导致错误。例如，处理 `药物剂量` 字段时，需要确保单位转换的准确性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `8000` | 神经退行性制度文档通常篇幅较长，需要更大的上下文窗口来捕获完整语义。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 处理包含大量图表和复杂排版的PDF或Word文档时，解析耗时可能较长，避免解析超时。 |
| `分段长度` | `800–1200 字符` | 保障每个分段包含足够信息，同时避免过长导致召回效率降低，兼顾专业术语上下文完整性。 |
| `召回条数` | `前 5 条` | 考虑到文档的专业性和精确性要求，适当增加召回条数以提高相关性召回概率。 |
| `相似度阈值` | 按实测标定 | 根据具体语料库的相似度分布进行调整，确保召回结果既相关又不多余。 |
| `PLUGIN_EXECUTION_TIMEOUT` | `60 秒` | 外部工具调用（如药物计算器）可能涉及复杂逻辑或外部接口响应慢，预留足够执行时间。 |

## 容易做错的三处

*   调用外部模型时，出现 `401 Unauthorized` 错误，原因为 API 密钥配置不正确或已过期。
*   使用 Fetch API 调用 `/api/v1/chat/completions` 接口时，遇到 `CORS policy` 错误，原因是前端请求域名与 FastGPT 服务部署域名不一致，且服务器未正确配置跨域头。
*   插件执行后返回结果为空或格式不正确，现象为 `plugin_output` 字段缺失或数据类型不匹配，原因在于插件代码未严格按照定义的数据结构返回结果，或者外部服务接口数据结构发生变化未及时同步。

## 怎么确认配好了

*   上传一份包含复杂图表和专业术语的神经退行性疾病SOP文档，检查文档解析后知识库中分段内容的完整性和准确性。
*   测试一个涉及药物剂量计算的问答，观察工具调用日志，确认 `plugin_output` 字段返回的计算结果与预期一致，并检查单位是否正确。
*   使用外部 Fetch API 模拟用户提问，检查 `/api/v1/chat/completions` 接口是否能正常响应，且没有出现跨域相关的错误提示。
*   对知识库进行多轮提问，包含对疾病诊断标准、治疗方案、不良事件处理等内容的查询，验证问答结果的准确性和相关性，并根据实际效果调整召回条数和相似度阈值。
