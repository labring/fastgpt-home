# 稳定性研究制度的HTTP 接口与外部系统

## 这个品类的数据长什么样

稳定性研究在生物医药领域中，主要涉及药物、制剂或活性成分在不同环境条件（温度、湿度、光照）下，随时间推移的质量变化。其数据来源通常是实验室测试报告、批生产记录、分析方法验证报告等。这些数据更新频率相对较低，通常在研究启动、特定时间点取样测试后进行录入。文档结构多为结构化或半结构化，例如批次信息、取样时间点、测试项目、测试结果（如含量、溶出度、杂质、pH值）、分析方法编号、检测仪器编号、操作人员等。字段类型多样，包含日期、时间、批号、数值（带单位）、布尔值、文本描述等。数值型字段常伴随特定的计量单位，如 `mg/mL`、`%`、`°C`、`%RH`。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

稳定性研究数据的低更新频率意味着系统不必频繁轮询外部数据源，减少了不必要的资源消耗。文档的半结构化特性要求HTTP接口在数据解析时具备一定的灵活性，能够处理不同批次或不同研究项目间细微的字段差异，例如某些测试项目可能只针对特定剂型存在。数值型字段及其单位的存在，要求接口在接收或发送数据时，对单位进行校验或转换，以避免数据误解。例如，含量数据可能以 `ug/mL` 或 `mg/mL` 形式存在。此外，历史数据的追溯性对于稳定性研究至关重要，要求接口在数据同步时能够保留完整的历史版本或时间戳信息，确保数据可审计。如果外部系统在数据传输过程中发生编码问题，如 `UTF-8` 与 `GBK` 混用，可能导致文本描述字段出现乱码。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `600 秒` | 稳定性研究数据量可能较大，且外部系统响应时间不确定，预留充足超时时间。 |
| `MAX_FILE_SIZE_MB` | `100 MB` | 稳定性研究报告通常包含图表和大量数据，文件体积可能较大，此值可容纳多数报告文件。 |
| `DATA_ENCODING` | `UTF-8` | 确保在多语言或特殊字符环境下，文本描述字段不会出现乱码，符合现代系统标准。 |
| `BATCH_PROCESSING_INTERVAL_HOURS` | `24 小时` | 稳定性研究数据更新频率低，每日批处理足以满足需求，避免频繁调用。 |
| `FIELD_MAPPING_DEFINITION` | 按实测标定 | 稳定性研究报告字段多样，需要根据具体报告模板定义详细的字段映射规则，包含单位转换。 |
| `ERROR_RETRY_COUNT` | `3 次` | 面对网络波动或外部系统瞬时故障，提供有限次的重试机制，提高数据同步成功率。 |

## 容易做错的三处

*   调用文件上传接口后，返回状态码 `200` 但AI对话无法识别 `xlsx` 文件，原因可能是文件内容解析失败，例如缺少必要的 `Sheet` 页或数据格式不符合预期。
*   通过API上传文本时，数据集内容显示为乱码，原因可能是在API请求头中未正确指定 `Content-Type` 或 `charset`，导致服务端以错误的编码方式解析。
*   工作流调用HTTP接口后，返回数据中关键字段为空，原因可能是外部系统返回的数据结构与预期不符，或者接口配置中的字段路径提取错误。

## 怎么确认配好了

*   通过API上传一份包含典型稳定性研究数据的 `xlsx` 文件，观察AI对话是否能正确提取关键信息，例如批号、含量值及单位。
*   调用HTTP接口获取一份测试数据，检查返回的文本描述字段是否正常显示，没有出现乱码或异常字符。
*   执行一次完整的数据同步流程，检查数据集中的数值型字段是否包含正确的单位，并且与外部系统中的原始数据一致，无精度丢失。
*   在HTTP接口调用失败后，检查系统日志，确认错误重试机制是否按预期触发，并且最终的错误信息是否准确反映了外部系统的响应。
