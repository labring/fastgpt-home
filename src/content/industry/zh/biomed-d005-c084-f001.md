# 精神类疾病制度的HTTP 接口与外部系统

## 这个品类的数据长什么样

精神类疾病的制度与SOP数据，主要来源于国家卫健委、地方医保局、医院管理部门发布的各类政策文件、诊疗指南、临床路径、操作规程。这些文档通常以 PDF、DOCX 格式为主，也包含部分网页内容。数据更新频率相对较低，通常按年度或政策调整周期进行修订。文档结构复杂，包含大量专业术语、图表、表格和交叉引用。字段方面，涉及疾病诊断标准（如 ICD-10 编码）、药物清单（如国家基本药物目录）、治疗方案（如电休克治疗适应症）、患者管理流程（如随访周期）等，单位多为医学计量单位、时间单位、百分比或布尔值。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

精神类疾病制度数据的复杂性和专业性，要求 HTTP 接口与外部系统在数据抽取和处理时具备高鲁棒性。PDF 和 DOCX 文档的解析需要专门的库或服务支持，以准确提取文本内容、识别章节结构和表格信息。较低的更新频率意味着不需要过于频繁地触发数据同步，但每次同步需要确保数据完整性和版本一致性。文档中的专业术语和交叉引用，对语义理解和知识图谱构建提出挑战，可能需要调用外部的医学本体服务进行辅助。此外，字段中包含的医学计量单位和特殊编码，要求接口返回的数据能被下游系统正确解析和利用，例如 `ICD-10` 编码的准确传递。

## 配置怎么定

| 配置项                 | 建议取法                               | 这样取的依据                                                                                                                                              |
| :--------------------- | :------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `max_chunk_size`       | `800-1200 字符`                        | 精神类疾病制度文档段落较长，包含上下文关联强的专业描述，此范围有助于保持语义完整性。                                                                      |
| `chunk_overlap`        | `100 字符`                             | 确保相邻文本块之间有足够重叠，避免因切分导致关键信息丢失，尤其在跨段落的政策解读中。                                                                      |
| `parse_timeout_seconds`| `600 秒`                               | 政策文件和指南的 PDF/DOCX 解析耗时较长，尤其是包含大量图表和复杂排版的文档，需要较长的超时时间。                                                            |
| `api_request_timeout`  | `120 秒`                               | 调用外部医学本体或药物数据库接口时，网络延迟或数据量较大可能导致响应缓慢，预留足够时间。                                                                  |
| `max_retries`          | `3 次`                                 | 外部接口调用可能因网络瞬时波动或服务短暂不可用而失败，适当重试机制可提高成功率。                                                                          |
| `rate_limit_interval`  | `按实测标定`                           | 依据目标外部系统的 API 限流策略进行配置，例如对医学本体接口或药物数据库的调用频率。                                                                      |

## 容易做错的三处

*   HTTP 接口返回的 JSON 中，关键医学字段如 `ICD-10` 编码或药物 `CAS` 号为空，原因是没有正确配置接口的参数映射，导致上游数据源的特定字段未被正确抓取或转换。
*   外部系统调用超时，现象是接口请求长时间无响应或返回 `HTTP 504` 错误，原因可能是 `api_request_timeout` 设置过短，未能应对复杂查询或网络延迟。
*   知识库问答结果中出现政策条款断章取义的现象，原因是 `max_chunk_size` 设置过小或 `chunk_overlap` 不足，导致文档切分时破坏了重要的语境和逻辑关联。
