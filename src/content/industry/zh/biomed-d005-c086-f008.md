# 罕见病制度的工具调用与插件

## 这个品类的数据长什么样

罕见病制度与SOP的数据主要来自国家及地方卫生健康委员会、药品监督管理局发布的政策法规、临床诊疗指南、药品目录和报销细则。这些文档通常以PDF、Word或结构化数据库的形式存在，更新频率不一，法规类文件可能每年修订或不定期发布补充通知，而临床指南则可能数年更新一次。文档结构复杂，包含大量专业术语、表格和附件。字段方面，涉及药品名称、适应症、报销范围、诊疗路径、审批流程等，其中药品剂量、给药途径、特定基因检测结果等常带有明确的单位和数值范围。

## 这些特征在「工具调用与插件」这一环带来什么约束

罕见病制度数据的复杂性和多源性对工具调用与插件提出了特定要求。首先，文档的多样性决定了需要支持多种文件格式的解析插件，并且对结构化信息的抽取能力要求较高，例如从PDF表格中准确获取药品报销比例。其次，数据更新的不确定性要求工具调用能够灵活触发外部数据源同步或API查询，以确保信息时效性。再次，专业术语和数值范围的存在，使得在执行工具调用时，需要对输入参数进行严格的校验和单位转换，避免因格式不匹配导致的查询失败。最后，由于罕见病诊疗往往涉及多学科协作，工具调用可能需要集成不同的外部系统，如基因检测报告系统或医保结算平台，以提供全面的信息。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :------------------------- | :----------------------------- | :--------------------------------------------- |
| `maxContext` | `2048` | 罕见病制度文档通常较长，需要更大的上下文窗口来理解复杂条款 |
| `embeddingModel` | `text-embedding-ada-002` | 适用于生物医药领域文本，能更好捕捉专业术语的语义相似性 |
| `toolCallTimeout` | `120 秒` | 外部API调用可能涉及复杂查询或多系统集成，需要较长的超时时间 |
| `maxToolCallsPerTurn` | `3` | 罕见病问题往往需要链式调用多个工具，例如先查询政策再查询药品 |
| `functionCallSchema` | 参照API文档生成 | 确保工具调用的参数类型、名称和描述与实际外部API接口严格匹配 |
| `retrievalTopK` | `10–15` | 制度文档相似条款较多，增加召回条数可提升相关性覆盖 |

## 容易做错的三处

- 现象：工具调用返回错误码 `400 Bad Request`，并提示“参数格式不正确”。
  原因：外部API对输入参数的类型或格式有严格要求，而插件在传递参数时未进行充分的校验或转换，例如将字符串传递给期望数值的字段。
- 现象：模型多次尝试调用同一个工具，但每次都以超时结束，最终无法提供答案。
  原因：外部API接口响应时间过长，超过了FastGPT应用中配置的 `toolCallTimeout` 阈值，导致工具调用中断。
- 现象：在查询罕见病报销政策时，模型未能正确提取报销比例，返回结果为空或不准确。
  原因：文档解析插件对PDF或Word中的表格数据提取能力不足，或者未针对特定文档结构进行优化，导致关键字段信息丢失。

## 怎么确认配好了

- 针对特定罕见病名称或药品，进行多次问答测试，观察模型是否能准确触发相关的政策查询工具。
- 检查系统日志，确认工具调用成功时的HTTP状态码为 `200 OK`，并且响应内容符合预期的数据结构。
- 构造包含不同参数类型（如数值、日期、字符串）的查询，验证工具调用能够正确传递参数，并在外部API中得到有效处理。
