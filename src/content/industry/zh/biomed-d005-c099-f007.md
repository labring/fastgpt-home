# 远程医疗制度的工作流编排

## 这个品类的数据长什么样
远程医疗制度与SOP文档通常来源于国家卫生健康委员会、各省市卫健委发布的规范性文件，以及医疗机构内部制定的实施细则。这些文档的更新频率相对较低，通常随政策调整或技术进步进行修订，可能每年或数年更新一次。文档结构以层级分明的章节、条款为主，常包含流程图、示例表格和定义术语。字段方面，涉及医疗行为规范、责任主体、操作步骤、风险评估、应急预案等。单位则多为时间单位（例如“分钟”、“小时”）、频率（例如“次/日”）、资质要求（例如“执业医师”），以及特定医疗参数的数值范围。

## 这些特征在「工作流编排」这一环带来什么约束
远程医疗制度文档的权威性与严谨性要求工作流编排对信息提取的准确性有极高要求，不能容忍误读或遗漏关键条款。其层级分明的结构，决定了在知识切片时需要兼顾语义完整性与粒度适中，避免将一个完整制度拆解得过于零散。更新频率低意味着一旦数据入库，其稳定性较高，但当有新规发布时，需要快速识别并更新受影响的部分，这要求工作流具备版本管理和增量更新能力。文档中包含的流程图和表格，提示工作流在处理非文本信息时，需要有对应的解析与结构化能力，例如通过图像识别或特定解析器提取流程步骤与表格数据，确保问答能覆盖这些非文本信息。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | 4000 token | 确保能容纳远程医疗制度中一个完整条款的上下文，避免语义截断。 |
| `分段长度` | 800 字符 | 兼顾语义完整性与召回效率，避免单个知识块过大。 |
| `召回条数` | 前 5 条 | 远程医疗制度的问答通常需要多角度印证，提供充足相关信息。 |
| `相似度阈值` | 0.78–0.82 | 制度问答对准确性要求高，阈值过低易引入不相关内容，过高可能漏掉关联信息。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 180 秒 | 远程医疗制度文档结构复杂，解析耗时可能较长，给予充足处理时间。 |
| `http_timeout` | 60 秒 | 外部数据源如政策库查询可能存在网络延迟，避免过早超时中断。 |

## 容易做错的三处
*   现象：用户提问“远程会诊需要什么资质”时，工作流直接给出通用 AI 回答，没有触发外部知识库查询或文档召回。原因：`http_request` 组件的触发条件配置不准确，未将包含“资质”、“要求”等关键词的查询路由到对应的外部知识源。
*   现象：工作流处理一个包含多个附件的上传请求时，仅识别并处理了主文档，忽略了附件中的补充条款或表格。原因：文件解析器未配置对多文件或特定附件类型的支持，例如 `allowed_file_types` 参数未包含 `.pdf` 或 `.docx` 等。
*   现象：在处理关于“远程医疗服务费用结算”的提问时，返回的答案中关于费用标准的信息缺失或不准确。原因：制度文档中关于费用标准的表格数据未能被有效解析并结构化，导致在问答召回时无法匹配到具体数值。

## 怎么确认配好了
*   选取远程医疗制度中的关键条款，模拟用户提问，检查工作流是否能准确召回相关文档片段，并生成符合制度原文的答案。
*   上传一份包含流程图或表格的远程医疗SOP文档，验证工作流在解析后能否正确识别并提取流程步骤或表格数据，并通过问答验证其可访问性。
*   对涉及外部数据源（例如政策法规库）的查询，检查工作流中的 `http_request` 组件是否能够成功触发并获取到外部数据，同时验证返回数据的完整性。
*   在工作流中设置一个新政策发布场景，测试其能否通过增量更新机制，快速识别并更新受影响的旧条款，并验证问答结果已切换至最新政策。
