# 远程医疗制度的文档解析与分块

## 这个品类的数据长什么样

远程医疗领域的数据源多样，主要包括国家及地方卫健委发布的法规、规章、指导意见，医疗机构内部制定的远程诊疗流程、会诊规范、病历管理细则，以及医保支付标准、数据安全与隐私保护协议等。这些文档更新频率不一，国家级法规可能每年或数年修订一次，而机构内部SOP则可能随技术发展或服务模式调整而季度性更新。文档结构通常包含章节、小节、条款、附录等层级，部分文档会嵌入图表、流程图。字段方面，常见有“适用范围”、“责任主体”、“操作步骤”、“风险提示”、“数据传输标准”等，单位多为“小时”、“工作日”、“MB/s”、“加密算法名称”等技术或时间度量。

## 这些特征在「文档解析与分块」这一环带来什么约束

远程医疗制度文档的数据来源广、更新周期差异大，要求解析器能处理多种文件格式（PDF、DOCX、XLSX），并有效识别版本更新。文档中严谨的层级结构，如“章节”、“条款”，对分块的逻辑完整性提出高要求，需要避免将关键条款拆分。字段如“数据传输标准”中的具体加密算法名称、传输速率单位，以及“操作步骤”中的时间或流程节点，需要被精准识别并保留在同一分块中，确保RAG召回时能提供完整、准确的制度依据。此外，部分文档可能包含复杂的表格或流程图，这要求解析器在处理非文本内容时，能提取其语义信息或将其转化为可理解的文本描述，避免关键信息丢失。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `UPLOAD_FILE_MAX_SIZE` | `100 MB` | 远程医疗制度文档通常篇幅较长，包含多媒体内容，需支持大文件上传。 |
| `分段长度` | `800–1200 字符` | 确保单个分块包含足够上下文，覆盖完整的条款或操作步骤，减少语义缺失。 |
| `分段重叠长度` | `100–200 字符` | 保证相邻分块间有一定上下文重叠，避免关键信息被分块边界切断，提高召回连贯性。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 处理大型PDF或复杂DOCX文件时，解析耗时可能较长，需预留充足时间。 |
| `文件集合解析策略` | `按章节/标题结构` | 远程医疗制度文档层级清晰，按结构解析可保留原文逻辑，提高分块质量。 |
| `辅助数据启用` | `是` | 利用文档元数据（如章节标题、发布日期）作为辅助信息，增强召回的准确性和相关性。 |

## 容易做错的三处

*   RAG检索返回的Excel数据条目少于预期，可能是因为Excel文件解析时，部分表格结构或非标准单元格内容未被正确识别并转化为可检索的文本分块，导致部分数据未能进入知识库。
*   上传PDF文件后，接口请求未能返回完整的章节标题，这通常是由于PDF文档扫描质量不佳或文本层缺失，导致光学字符识别（OCR）未能准确提取标题信息。
*   知识库分块内容中辅助数据未发挥作用，导致匹配精度不高，这可能是因为辅助数据（如文档类型、来源）在索引时未被正确关联到主要内容，或在召回阶段未被纳入相似度计算考量。

## 怎么确认配好了

*   上传典型远程医疗制度文档（PDF、DOCX、XLSX），检查解析后的分块数量与内容是否符合预期，特别是表格和流程图部分是否被有效转化。
*   通过知识库检索界面，输入制度文档中的特定条款或关键词，检查返回结果是否包含完整的相关分块，并验证其上下文连贯性。
*   针对更新频率较高的文档，上传新版本后，检查系统是否能正确识别并更新知识库内容，同时验证旧版本相关信息的召回情况。
