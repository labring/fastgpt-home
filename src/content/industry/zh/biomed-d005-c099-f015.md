# 远程医疗制度的部署与升级

## 这个品类的数据长什么样

远程医疗制度的数据主要来源于国家及地方卫健委发布的政策法规、医疗机构内部制定的规章制度、操作流程（SOP）、以及相关的医学指南和专家共识。这些文档通常以 PDF、Word 或结构化文本形式存在，更新频率相对较低，通常是季度或年度更新，遇重大政策调整会有临时性修订。文档结构上，通常包含政策背景、适用范围、具体条款、操作步骤、责任划分等章节。字段与单位方面，涉及医疗服务项目编码、费用标准、审批流程节点、时间限制（例如 `审批时限` 以 `工作日` 为单位）、以及资质要求（例如 `执业医师资格证编号`）。

## 这些特征在「部署与升级」这一环带来什么约束

远程医疗制度文档的低更新频率意味着在知识库构建初期可以进行较为彻底的文本预处理和向量化，但后续的增量更新需要关注版本控制和修订内容的精准识别。文档的结构化特点决定了在知识切分时，应优先考虑章节、条款等语义边界，避免跨越关键信息点。涉及大量专业术语和编码，要求模型对医疗领域词汇有良好的理解，并能区分同义词和近义词。时间限制和流程节点的字段，需要系统能够解析并提供明确的数值或步骤，这对知识库的召回精度和答案生成逻辑提出了要求。同时，这些文档的权威性和严谨性，使得在问答结果中必须强调原文出处和政策依据，避免误导性信息。

## 配置怎么定

| 配置项             | 建议取法       | 这样取的依据                                   |
| :----------------- | :------------- | :--------------------------------------------- |
| `分段长度`         | `800–1200 字符` | 适应政策法规文档的章节和条款粒度，保持语义完整性 |
| `分段重叠长度`     | `150 字符`     | 确保跨段落上下文的连贯性，提高召回准确率       |
| `召回条数`         | `8–12 条`      | 覆盖制度问答可能涉及的多个相关条款和细节       |
| `相似度阈值`       | 按实测标定     | 保证召回内容的精确性，排除不相关条款           |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`       | 应对大型制度文件或 SOP 的解析时间              |
| `UPLOAD_FILE_MAX_SIZE` | `100 MB`       | 适应大型政策文本或操作手册的文件大小           |

## 容易做错的三处

*   知识库文档按分隔符切分后，字数超长的分段未能有效处理，导致问答时遗漏关键信息，原因是未配置合适的 `分段长度` 或未采用多策略切分。
*   升级到新版本后，API Key 无法正常使用，报错 `Invalid API Key`，原因是旧版本 `通用key` 在新版本中可能需要重新生成或配置 `应用特定key`。
*   问答结果中出现流程步骤或时间限制的错误，原因是知识库在文档处理时未能正确识别和提取文本中的数字和单位，或未将这些信息进行结构化存储。

## 怎么确认配好了

*   上传一份包含复杂流程和多章节的远程医疗SOP文档，检查知识库是否能正确分段，且分段内容保持语义完整。
*   使用包含医疗服务编码或特定时间限制的提问，核对系统返回的答案是否准确提及了相关的编码和时间单位，并与原文内容一致。
*   模拟一次版本升级，验证现有知识库和应用配置在新版本下是否能平稳运行，特别是API调用和知识检索功能。
