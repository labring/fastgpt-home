# 标准应答库医学信息 MI 应答的HTTP 接口与外部系统

## 这个品类的数据长什么样

标准应答库在生物医药领域的医学信息（MI）应答中，其数据通常来源于临床试验报告、药品说明书、医学指南、专业文献等权威渠道。这些数据以结构化或半结构化的形式存在，例如常见问题解答（FAQ）对、药物作用机制描述、不良反应列表、剂量用法等。更新节奏通常与药品生命周期和医学进展紧密相关，例如新适应症获批、安全性信息更新、临床研究发布等，可能为季度或半年度更新，重要更新则会即时发布。文档结构高度规范，常包含问题、标准答案、参考文献链接、更新日期、以及可能的产品代码 `product_id` 或疾病代码 `disease_code` 等字段，确保医学信息的准确性和可追溯性。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

标准应答库的数据特征对HTTP接口与外部系统集成提出了特定约束。首先，数据来源的权威性和更新频率要求接口具备高可靠性和事务性，确保数据同步的完整性，例如在更新过程中避免部分数据写入。其次，结构化与半结构化的文档特征意味着接口设计需支持复杂的数据模型，例如嵌套 JSON 对象，以便准确传输包含问题、答案、引用和元数据的完整应答。字段的规范性，如 `question_id`、`answer_text`、`reference_url` 等，要求接口参数和返回体严格遵循预定义的协议。此外，由于医学信息的敏感性，接口必须支持严格的身份验证与授权机制，并确保数据传输加密，例如通过 HTTPS 协议。对于更新操作，需要考虑幂等性，避免重复提交导致数据不一致。

## 配置怎么定

| 配置项             | 建议取法       | 这样取的依据                                   |
| :----------------- | :------------- | :--------------------------------------------- |
| `requestTimeout`   | `60000 毫秒`   | 应对外部系统数据量大或网络延迟，确保完整响应   |
| `maxRetries`       | `3 次`         | 应对瞬时网络抖动或外部服务短暂不可用，提高健壮性 |
| `batchSize`        | `500 条/批`    | 兼顾外部系统处理能力与数据传输效率             |
| `authHeaderName`   | `Authorization` | 行业常用标准，易于集成                         |
| `contentType`      | `application/json` | 结构化数据传输标准格式，兼容性好           |
| `updateFrequency` | `每日 02:00 UTC` | 确保每日最新医学信息同步，避开业务高峰       |

## 容易做错的三处

*   现象：外部系统报错 `HTTP 500 Internal Server Error`，日志显示 `Database connection timeout`。原因： FastGPT 侧的 `requestTimeout` 参数设置过短，未能等待外部数据库完成复杂查询。
*   现象：通过 API 提交的MI应答数据在知识库中出现重复记录，或缺少部分字段内容。原因：API 调用未实现幂等性处理，或 `batchSize` 过大导致部分数据处理失败后重试机制不完善。
*   现象：知识库内容更新后，用户通过 FastGPT 提问时仍然得到旧的MI应答。原因：外部系统更新触发机制未正确配置或 `updateFrequency` 间隔过长，导致知识库同步延迟。

## 怎么确认配好了

*   通过 FastGPT 的管理界面，检查知识库中随机抽取 5-10 条最新同步的MI应答，核对 `answer_text`、`reference_url` 等关键字段内容与外部源系统一致。
*   执行一次完整的 HTTP 接口数据同步操作，监控 FastGPT 侧的日志输出，确认没有出现 `HTTP 4xx` 或 `HTTP 5xx` 错误码，且数据处理耗时在 `requestTimeout` 设定的阈值内。
*   模拟用户提问，针对刚更新的几条MI应答进行测试，验证 FastGPT 能够准确召回并提供正确的最新应答，并检查返回的 `source` 字段是否指向正确的知识库条目。
