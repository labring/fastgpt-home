# 剂量调整合理用药问答的工具调用与插件

## 这个品类的数据长什么样

剂量调整相关数据主要来源于药品说明书、临床指南、药典、以及药代动力学（PK）/药效动力学（PD）数据库。其更新频率相对较低，通常随药品说明书修订或临床指南更新而发生，周期可能为数月至数年。数据文档结构多样，药品说明书常为非结构化文本，包含用法用量、特殊人群用药（肝肾功能不全、老年、儿童等）等章节。临床指南则可能以结构化表格形式呈现，明确不同生理指标下的推荐剂量。关键字段包括药物名称、适应症、患者生理指标（如肌酐清除率 `CrCl`、体重 `BW`、肝功能分级 `Child-Pugh Score`）、调整前剂量、调整后剂量、调整依据、给药途径和频率。单位涉及毫克（mg）、毫升（mL）、千克（kg）、毫升/分钟（mL/min）、小时（h）等，单位转换在处理中是常见需求。

## 这些特征在「工具调用与插件」这一环带来什么约束

剂量调整数据的非结构化和半结构化特性，要求工具调用能够灵活处理文本解析和信息抽取。例如，从药品说明书中提取特定患者群体下的剂量调整规则，需要结合自然语言处理（NLP）能力。由于涉及多种生理指标和复杂的判断逻辑，工具或插件需支持多参数输入和条件分支处理，以模拟临床决策过程。数据更新频率较低，意味着知识库的构建和维护可以采用周期性更新策略，不必追求实时同步。然而，一旦数据更新，工具调用逻辑可能需要随之调整，特别是当剂量调整的判断依据或计算公式发生变化时。此外，单位的多元性和转换需求，要求工具能够内置或调用外部单位转换服务，确保计算的准确性。对外部数据库的依赖，如查询肌酐清除率计算公式或药物相互作用，也对工具调用的外部接口能力提出了要求。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `2000 字符` | 确保能完整传入患者基本信息和相关药物信息，为剂量计算提供足够上下文。 |
| `toolCallTimeout` | `60 秒` | 考虑到可能涉及多个外部API调用（如PK/PD模型计算），预留充足的执行时间。 |
| `knowledgeBaseIds` | 特定知识库 ID | 绑定包含药品说明书、临床指南的知识库，确保工具能获取最新用药信息。 |
| `functionSchema` | 动态生成或预定义 | 针对不同药物或调整场景，函数参数可能不同，需要灵活定义或通过模板生成。 |
| `maxIterations` | `3` | 允许工具在复杂场景下进行有限的多次尝试，如首次调用失败后调整参数重试。 |
| `outputFormat` | `JSON` | 统一输出格式，便于后续流程解析和展示，包含调整剂量、依据和注意事项。 |

## 容易做错的三处

*   工具调用返回 `500` 错误或空结果，原因在于传递给工具的患者生理指标字段名与工具期望的参数名不匹配，导致内部计算失败。
*   AI 平台在对话中无法引用知识库内容，即使知识库已全局设置，原因在于工具调用工作流中未显式将 `knowledgeBaseIds` 参数传入，导致工作流无法感知并利用指定的知识库。
*   工具执行 SQL 语句后未返回预期结果，原因在于数据库连接池配置不当或 SQL 查询语句中存在语法错误，导致数据库操作未能成功执行。

## 怎么确认配好了

*   构造包含典型患者生理指标（如 `CrCl` 30 mL/min、`BW` 60 kg）和特定药物的问答，观察工具是否能准确返回调整后的剂量和调整依据。
*   测试边缘情况，例如肝肾功能极度异常的患者，检查工具是否能给出合理的剂量建议或提示禁忌。
*   验证当知识库内容更新后，工具调用的结果是否能反映最新的用药指南或药品说明书信息，通过比对更新前后的输出判断。
