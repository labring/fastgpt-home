# 禁忌与相互作用合理用药问答的HTTP 接口与外部系统

## 这个品类的数据长什么样

禁忌与相互作用数据通常来源于专业药学数据库、国家药品监管机构发布的数据集以及临床药理学研究报告。这些数据更新频率较高，尤其当有新药上市、药品说明书修订或临床研究发现新的相互作用时，数据源会在数周到数月内更新。文档结构多为结构化或半结构化，例如 XML、JSON 或 CSV 格式。核心字段包括药品名称（通用名、商品名）、活性成分、相互作用类型（药-药、药-食、药-疾病）、相互作用机制、临床表现、严重程度（轻微、中度、严重、禁忌）、处理建议及参考文献。剂量单位常涉及毫克（mg）、微克（μg）、毫升（ml）等，时间单位为小时（h）、天（d）。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

禁忌与相互作用数据的高更新频率，要求 HTTP 接口设计支持增量同步或定期全量刷新，以确保问答结果的时效性。结构化数据特性使得接口返回 `JSON` 或 `XML` 格式更为高效，便于解析和字段映射。复杂的相互作用机制和多种严重程度分级，需要在接口查询参数中提供精细化的过滤选项，例如按严重程度或相互作用类型筛选。大量药品名称和活性成分的存在，对外部系统的模糊匹配能力提出要求，避免因名称差异导致查询失败。此外，处理建议通常包含长文本描述，这要求接口返回字段 `interaction_details` 或 `management_suggestions` 支持较长的字符串长度，并考虑 `UTF-8` 编码以支持多语言药品名称。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `externalApiUrl` | `https://api.pharmadrugdb.com/interactions/query` | 示例API地址，应替换为实际药学数据库接口URL |
| `requestMethod` | `POST` | 多数复杂查询推荐使用 `POST` 方法，支持请求体传递多参数 |
| `requestTimeout` | `60000 ms` | 应对外部接口偶发延迟，避免因超时导致查询中断 |
| `maxRetries` | `3` | 应对网络抖动或外部服务瞬时不可用，提高请求成功率 |
| `responseParsingPath` | `$.data.interactions[*]` | 假定API返回JSON，路径指向交互数据列表，便于FastGPT解析 |
| `errorHandlingStatusCode` | `400-499, 500-599` | 涵盖客户端错误和服务器错误，确保异常情况能被捕获 |

## 容易做错的三处

*   现象：用户输入药品名称后，问答系统无法返回任何相互作用信息。原因：外部系统接口未能正确处理药品名称的模糊匹配或别名映射，导致 `drug_name` 参数值与数据库记录不符。
*   现象：查询结果中，相互作用的严重程度字段 `severity` 为空或显示为未知。原因：HTTP 接口响应数据中，该字段可能缺失或使用了非预期的数据格式，未能在 FastGPT 的 `responseParsingPath` 中正确提取。
*   现象：对话框中无法下载通过 HTTP 节点获取的 BLOB 对象。原因：HTTP 节点配置中未将 `Content-Disposition` 响应头正确解析，或未提供前端下载链接，导致用户界面无法触发文件下载。

## 怎么确认配好了

*   使用 FastGPT 的 HTTP 节点测试功能，向外部API发送包含已知禁忌药品对的请求，核对返回的 `JSON` 或 `XML` 结构与预期是否一致。
*   检查 HTTP 节点返回的 `status_code` 是否为 `200`，并确认核心字段如 `drug_name`、`interaction_type`、`severity` 在响应体中存在且值正确。
*   使用不同严重程度的相互作用药品进行查询，观察返回结果中 `severity` 字段的取值范围和准确性，与外部数据源的定义进行比对。
*   模拟外部 API 出现 `500` 错误或 `404` 错误的情况，确认 FastGPT 的错误处理逻辑是否按预期触发，并给出友好的错误提示。
