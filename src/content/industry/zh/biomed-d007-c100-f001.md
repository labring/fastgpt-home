# 适应症合理用药问答的HTTP 接口与外部系统

## 这个品类的数据长什么样

适应症数据主要来源于药品说明书、临床指南、药典、以及药监局公开数据库。这些数据更新频率相对稳定，通常是季度或半年一次，但新药上市或适应症扩展时会有突发性更新。文档结构以半结构化文本为主，包含药品名称、通用名、适应症描述、用法用量、禁忌症等字段。适应症描述常包含医学术语、疾病分类代码（如 ICD-10），并涉及剂量单位（如 mg、g、ml）、频率（如每日一次、每 8 小时）等信息。数据的完整性和准确性直接影响合理用药问答的质量。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

适应症数据的半结构化特性要求 HTTP 接口能够处理复杂的 JSON 或 XML 结构，并支持灵活的字段映射。由于更新频率不一，外部系统需要实现周期性全量或增量同步机制，以确保问答数据的时效性。突发性更新则要求接口支持实时数据推送或高频拉取。数据中包含的医学术语和单位，对数据预处理和向量化模型的准确性提出了更高要求。接口需要提供强大的检索能力，以支持基于疾病名称、药品名称或症状的模糊查询，并能快速返回相关适应症信息。数据量庞大时，接口响应时间成为关键考量。

## 配置怎么定

| 配置项             | 建议取法       | 这样取的依据                               |
| :----------------- | :------------- | :----------------------------------------- |
| `HTTP_TIMEOUT`     | `60 秒`        | 确保外部接口在数据量较大时有足够时间响应   |
| `CHUNK_SIZE`       | `1000 字符`    | 适应症描述长度不一，平衡语义完整性与分段效率 |
| `BATCH_INSERT_SIZE`| `500 条`       | 优化数据库写入性能，减少网络往返开销       |
| `CRON_SCHEDULE`    | `0 0 * * *`    | 每日凌晨同步，兼顾数据时效性与系统负载     |
| `RETRIES_COUNT`    | `3 次`         | 应对外部接口偶发性故障，提高数据同步成功率 |

## 容易做错的三处

*   同步任务偶尔失败，日志显示 `HTTP Status 500`。原因在于外部系统处理请求超时，未能及时返回数据。
*   问答结果中适应症信息不完整或出现错误医学术语。原因在于数据预处理时未能正确识别和抽取所有关键字段，或词典未及时更新。
*   外部群聊中 AI 应用无法主动发送最新适应症更新通知。原因在于企业微信 API 调用方式不正确，或缺乏必要的权限配置。

## 怎么确认配好了

*   检查 HTTP 接口日志，确认数据同步任务按预期频率成功完成，且状态码为 `200`。
*   通过 FastGPT 平台检索特定疾病或药品，验证返回的适应症描述是否准确、完整，并与源数据进行比对。
*   调用外部系统 API，模拟新适应症数据更新，并观察 FastGPT 平台是否能实时或在下一个同步周期内反映这些变更。
*   在 FastGPT 中配置一个基于适应症数据的问题，验证 AI 回答的准确性与相关性，并根据实际业务场景校准召回阈值。
