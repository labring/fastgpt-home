# 产品使用智能客服的HTTP 接口与外部系统

## 这个品类的数据长什么样

生物医药领域的产品使用数据通常来源于多个渠道，包括产品说明书、药品不良反应报告系统、临床研究报告、患者教育手册以及在线问答平台。这些数据格式多样，既有结构化的数据库记录，也有大量的非结构化文本，如 PDF 文档、Word 文档和网页内容。数据更新频率不一，产品说明书和官方指南相对稳定，但不良反应报告和临床进展数据可能每日或每周更新。文档结构上，说明书往往包含剂量、用法、禁忌症、副作用等固定章节，而患者咨询数据则呈现出自由对话的特点。字段方面，可能涉及药品名称、批次号、生产日期、有效期、患者年龄、性别、诊断、用药依从性、症状描述、治疗结果等，其中症状描述和不良反应报告通常是自由文本，不具备统一的单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

产品使用数据的多样性和更新频率直接影响 HTTP 接口的设计和外部系统对接策略。大量的非结构化文本要求接口能够处理多种文件类型，并支持高效的文本抽取和解析。例如，从 PDF 产品说明书中提取关键信息，需要依赖 OCR 或文档解析服务。更新频率不一的数据源，例如不良反应报告，要求 HTTP 接口支持增量更新和实时同步机制，以确保智能客服提供的信息时效性。字段的特殊性，尤其是自由文本的症状描述，意味着外部系统在接收到这些数据后，需要进行进一步的自然语言处理（NLP），如实体识别和症状分类，才能有效支撑智能客服的问答逻辑。此外，药品批次号、有效期等字段的精确匹配，对接口的参数校验和数据准确性提出了严格要求，防止因数据错误导致误导性回复。

## 配置怎么定

| 配置项                   | 建议取法                                        | 这样取的依据                                                 |
| :----------------------- | :---------------------------------------------- | :----------------------------------------------------------- |
| `maxContext`             | `1200 Tokens`                                   | 确保能涵盖患者提问及产品说明书中的关键信息，平衡理解深度与响应速度。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `180 秒`                                        | 适应生物医药产品说明书等大型 PDF 文档的解析时间，防止超时。  |
| `分段长度`               | `300 字符`                                      | 平衡文本语义完整性与召回效率，避免过度拆分或信息冗余。       |
| `召回条数`               | `前 8 条`                                       | 提高相关信息覆盖率，尤其在处理复杂产品问题时。               |
| `相似度阈值`             | `0.78`                                          | 保证召回结果与患者提问高度相关，减少不准确信息的干扰。       |
| `HTTP 请求超时`          | `60000 毫秒`                                    | 考虑到外部系统（如药品数据库或不良反应报告系统）可能存在的网络延迟和处理时间。 |

## 容易做错的三处

*   调用外部药品数据库接口时返回空内容，现象是智能客服无法回答特定药品信息。这通常是由于请求参数中的药品名称或批次号与数据库存储格式不完全匹配，或者 `HTTP 请求超时` 设置过短导致。
*   模型配置中填写的请求地址不生效，智能客服无法调用第三方大模型服务。原因可能是 `请求地址` 格式错误，缺少必要的协议头（例如 `https://`），或者 `API Key` 未正确配置或已失效。
*   HTTP 响应中的入参变量无法被服务识别，导致后续逻辑中断。这往往是由于响应体中的字段名与预期不符，或者 JSON 路径表达式错误，未能准确提取所需数据。

## 怎么确认配好了

*   通过模拟患者提问，涵盖产品使用说明、不良反应咨询、药品剂量查询等多种场景，观察智能客服的回复是否准确、完整，并核对回复中引用的数据来源。
*   检查 FastGPT 后台的 HTTP 请求日志，确认外部系统调用的状态码均为 `200` 或 `204`，且响应时间在可接受范围内。
*   在 FastGPT 中配置一个测试用的 HTTP 接口，手动输入所有预期的入参变量，验证其能正确解析并返回预期的结果。
*   针对更新频率较高的数据源，例如药品不良反应报告系统，定期触发数据同步任务，并抽查部分最新数据，确认智能客服能获取并利用这些更新的信息。
