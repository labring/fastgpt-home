# CAR-T 细胞治疗注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样
CAR-T 细胞治疗的注册申报资料涉及多源异构数据，包括临床试验数据、生产工艺记录、质控报告、非临床研究报告等。临床试验数据通常来自电子数据采集（EDC）系统，更新频率不一，可能在试验进行中每周更新，或在关键时间点批量更新。生产工艺记录和质控报告则来自制造执行系统（MES）和实验室信息管理系统（LIMS），通常以批次为单位生成，更新频率与生产批次同步。文档格式多样，常见的有 PDF、Word、Excel，以及符合 CDISC 标准的 SAS XPT 文件。字段方面，涉及剂量、不良事件代码（MedDRA）、生物标志物表达量、细胞扩增倍数等，单位包括 mg/kg、个/mL、%等，具有高度特异性。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
CAR-T 细胞治疗数据的多源性要求外部系统具备灵活的数据源连接能力，支持多种协议和认证方式。数据更新频率的不确定性，特别是临床试验数据的阶段性更新，决定了 HTTP 接口需要支持增量同步和全量同步两种模式，并能处理大量数据并发请求。文档的多样性意味着接口需要能接收和解析不同格式的文件，可能需要集成文件转换或内容抽取服务。特异性字段和单位的存在，要求接口在数据传输时能保持原始数据完整性，并在接收端进行严格的校验，避免数据语义丢失或单位混淆。此外，CAR-T 数据的敏感性，对数据传输的安全性提出了更高要求，例如强制使用 HTTPS 协议，并实施令牌或证书认证。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `external_api_url` | 外部系统 API 地址 | 确保指向正确的上游数据源服务 |
| `request_timeout_seconds` | `180–300 秒` | 应对大批量文件上传和数据处理的耗时 |
| `max_concurrent_requests` | `5–10` | 平衡系统资源占用与数据同步效率 |
| `auth_token_refresh_interval_minutes` | `60 分钟` | 确保认证令牌有效性，避免频繁过期 |
| `data_schema_validation_level` | `严格校验` | 保证 CAR-T 关键字段和单位的准确性 |
| `ssl_certificate_path` | `按实际部署路径` | 强制使用 HTTPS，保障数据传输安全 |

## 容易做错的三处
- 现象：接口调用返回 `HTTP 401 Unauthorized` 错误。原因：认证令牌过期或配置错误，未及时更新或刷新。
- 现象：上传大文件时接口频繁出现 `HTTP 504 Gateway Timeout`。原因：`request_timeout_seconds` 配置过短，未能覆盖大型文件传输或复杂数据处理的耗时。
- 现象：部分关键字段在导入后为空或单位丢失。原因：接口返回的数据结构与预期的解析模型不符，或数据校验规则过于宽松。

## 怎么确认配好了
- 验证所有配置的 `external_api_url` 都能通过 `/ping` 或 `/health` 接口成功响应。
- 模拟上传一个包含所有典型字段和单位的 CAR-T 申报资料文件，检查数据是否完整且准确地导入。
- 触发一个大批量数据同步任务，观察 `request_timeout_seconds` 内任务是否能正常完成，并检查日志中是否存在超时错误。
- 检查系统日志，确认在数据传输过程中，`ssl_certificate_path` 指向的证书被正确加载和使用，没有出现安全警告。
