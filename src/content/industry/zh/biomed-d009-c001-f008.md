# CAR-T 细胞治疗注册申报资料准备的工具调用与插件

## 这个品类的数据长什么样

CAR-T 细胞治疗的注册申报资料主要包括临床前研究数据、临床试验数据、生产工艺信息、质量控制标准等。数据来源多样，涵盖体外实验报告、动物实验报告、I/II/III 期临床试验报告、生产批次记录等。数据更新频率在临床试验阶段较高，特别是安全性与有效性数据，可能按季度或半年度更新。文档结构复杂，常包含 PDF 格式的报告、Excel 格式的统计数据、Word 格式的方案与总结。字段与单位具有高度专业性，例如“细胞扩增倍数”（X-fold）、“CD3+ 细胞百分比”（%）、“病毒载体拷贝数”（VCG/cell）、“不良事件等级”（CTCAE v5.0 等级）等，且不同来源的数据可能存在单位不统一或命名差异。

## 这些特征在「工具调用与插件」这一环带来什么约束

CAR-T 细胞治疗数据来源的多样性与复杂文档结构，要求工具调用与插件具备强大的文件解析与异构数据整合能力。例如，从 PDF 报告中提取关键安全性数据，或从 Excel 表格中读取特定批次的质量控制指标，这都需要精确的文本识别与结构化提取。高频的数据更新，特别是临床试验数据，对工具的数据同步与增量处理能力提出要求，避免重复处理已有的庞大数据集。专业化的字段与单位，以及潜在的命名差异，使得工具在参数传递与结果解析时必须进行严格的校验与标准化转换，否则容易导致数据错位或计算错误。此外，由于申报资料的严谨性，工具在调用失败时需要提供清晰的错误信息与回溯机制。

## 配置怎么定

| 配置项                       | 建议取法                               | 这样取的依据                                                                 |
| :--------------------------- | :------------------------------------- | :--------------------------------------------------------------------------- |
| `maxContext`                 | `4000`                                 | 应对复杂报告与多源数据整合，保持上下文连贯性。                               |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`                               | 处理大型 PDF 报告或复杂的 Excel 统计表，避免解析超时。                       |
| `相似度阈值`                 | `0.75`                                 | 确保检索到的法规条文或既往申报案例与 CAR-T 资料高度相关。                    |
| `重排返回条数`               | `前 5 条`                              | 在大量检索结果中精选最相关项，提升后续处理效率。                             |
| `mcp_tool_retries`           | `3`                                    | 应对外部 MCP 工具因网络波动或服务瞬时不可用导致的调用失败。                  |
| `enable_streaming_output`    | `否`                                   | 注册申报资料的回复通常需要完整性与准确性，禁用流输出以确保最终结果的完整呈现。 |

## 容易做错的三处

*   工具调用返回空数据或不完整数据，原因是 PDF 解析器未能正确识别报告中的表格结构或关键字段。
*   API 调用时文字输出速度过慢，原因是后端服务在处理大量结构化数据提取与复杂逻辑判断时耗时较长，且未优化异步处理。
*   工具调用记录自动回复，但不少 MCP 工具无法与调用终止节点建立连接，原因是 MCP 工具的输出格式与预期不符，或缺乏必要的交互协议支持。

## 怎么确认配好了

*   通过测试用例，验证工具能够准确解析不同格式的 CAR-T 申报资料，并成功提取关键字段，检查提取值的准确性与单位一致性。
*   执行模拟申报流程，观察整个工具链的响应时间与数据处理速度，确保 API 输出速度满足要求，并与基准时间进行比较。
*   检查工具调用日志，确认所有 MCP 工具的调用状态均为成功，且调用终止节点能够正确接收并处理工具的返回结果。
