# GMP 合规注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样
GMP 合规资料主要包括生产过程记录、质量控制报告、设备验证文件、人员培训记录以及偏差处理报告等。数据来源多样，涵盖生产执行系统 (MES)、质量管理系统 (QMS)、文档管理系统 (DMS) 等。更新节奏与生产批次、质量事件、法规修订密切相关，例如批生产记录随批次完成即生成，偏差报告在事件发生后立即更新，而设备校准记录则按周期更新。文档结构高度标准化，遵循 ICH Q 系列指南和各国药监机构（如 FDA、NMPA）的规定，常以 PDF、Word、或结构化的 XML/JSON 格式存在。字段与单位严格，例如批号、生产日期、有效期、检测结果、计量单位（mg/L、℃、kPa）等，且通常附带签名与时间戳。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
GMP 资料的高度标准化和严格性，要求 HTTP 接口在数据传输时必须确保字段的完整性与准确性。例如，批生产记录通常包含数十个关键参数，任何遗漏或格式错误都可能导致合规性问题。多源数据特性决定了接口需要支持多种数据源的集成，例如从 MES 拉取生产数据，从 QMS 获取质检报告。更新频率的差异性，要求接口设计支持事件驱动（如偏差报告）和周期性拉取（如设备校准记录）两种模式，避免数据延迟或冗余。严格的字段与单位要求，意味着接口在数据解析和入库前需进行严格的校验，例如确保温度单位的一致性（摄氏度 `℃` 或华氏度 `℉`），或数字字段的范围检查。此外，大量文档型数据（PDF、Word）的存在，对接口的文件上传和内容解析能力提出了较高要求，需要支持大文件传输和结构化信息提取。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `external_api_timeout_seconds` | `600` 秒 | 考虑到部分 GMP 文档解析复杂，接口响应时间可能较长。 |
| `max_document_size_mb` | `100` MB | 适应大型 PDF 批生产记录或验证报告的文件大小。 |
| `data_polling_interval_hours` | `24` 小时 | 针对周期性更新数据（如设备校准）的合理拉取频率。 |
| `json_schema_validation_strict` | `true` | 确保结构化数据（如批次参数）的字段类型与范围严格匹配。 |
| `file_type_whitelist` | `pdf, docx, xml, json` | 限制上传文件类型，确保只处理 GMP 相关的标准文档格式。 |
| `api_key_header_name` | `X-API-Key` | 遵循常见的 API 认证方式，确保外部系统调用的安全性。 |

## 容易做错的三处
*   调用外部系统接口时，返回 `HTTP 401` 或 `HTTP 403` 状态码，通常是 API 密钥 `api_key` 或鉴权令牌 `Authorization` 配置错误或已过期。
*   上传大型 GMP 文档后，系统长时间无响应或报错 `504 Gateway Timeout`，这往往是 `external_api_timeout_seconds` 配置过短，未能覆盖大文件上传及解析所需的时间。
*   从外部系统获取的结构化数据（如批次参数），在 FastGPT 中部分字段为空或数据类型不匹配，这通常是 `json_schema_validation_strict` 未启用或 `data_mapping_rules` 配置不正确，导致数据解析时忽略了格式差异。

## 怎么确认配好了
*   通过 FastGPT 的接口测试工具，使用一个典型的 GMP 批生产记录文件（如 50MB PDF）进行上传，观察是否能正常完成处理且无超时错误。
*   配置一个包含关键结构化数据（如批号、生产日期、检测结果）的模拟外部接口，并触发数据同步，检查 FastGPT 中对应知识库的字段值是否与源数据完全一致，包括单位和数据类型。
*   模拟外部系统触发一个事件驱动的数据更新（例如提交一个偏差报告），检查 FastGPT 是否能及时接收并处理该数据，并验证相关内容是否可被检索。
