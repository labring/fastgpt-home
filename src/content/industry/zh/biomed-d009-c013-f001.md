# mRNA 疫苗注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样

mRNA 疫苗的注册申报资料具有鲜明的生物医药特色。数据来源多样，包括临床试验报告（Protocol、CSR）、非临床研究报告（GLP/GCP）、CMC（化学、制造与控制）文件、质量标准、稳定性数据以及监管机构的沟通记录等。这些数据更新频率高，尤其是临床试验数据和CMC变更，可能每周甚至每天都有小版本迭代。文档结构复杂，通常遵循ICH通用技术文档（CTD）格式，包含模块1到模块5，其中模块3（CMC）和模块5（临床研究）数据量庞大且结构化程度各异。字段方面，涉及基因序列、蛋白质表达量、纯度、效价、批次号、储存条件等，单位精确到纳克、摩尔、百分比，并常伴随特定的检测方法学描述。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

mRNA 疫苗申报资料数据量大且更新频繁，对HTTP接口的并发处理能力和数据同步机制提出要求。CTD格式的复杂性意味着外部系统需要支持多层级、多类型文件的解析与索引，例如PDF、Word、Excel和结构化数据库导出文件。高精度的生物学字段和特定单位，要求接口在数据传输时保持数据完整性和一致性，避免精度损失或单位混淆。此外，申报资料中可能包含受严格监管的敏感信息，HTTP接口必须支持高级别的身份验证和授权机制，并确保传输过程中的加密安全性。对于频繁的小版本更新，外部系统需要提供版本管理功能，并支持增量同步，以减少不必要的全量数据传输。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `MAX_REQUEST_BODY_SIZE` | `256 MB` | 考虑单个文档（如详细的CMC报告或临床试验报告）可能较大，避免因请求体过大导致HTTP `413 Payload Too Large` 错误。 |
| `API_TIMEOUT_SECONDS` | `300 秒` | 应对大型文档解析、数据清洗或复杂查询可能耗时较长的情况，避免 `504 Gateway Timeout` 错误。 |
| `CONCURRENT_REQUEST_LIMIT` | `20` | 平衡系统资源与数据更新频率，允许在不影响性能的前提下处理多个并发的数据同步或查询请求。 |
| `AUTH_HEADER_TYPE` | `Bearer Token` | 提供基于JWT或OAuth2的认证机制，增强数据传输的安全性，符合生物医药数据监管要求。 |
| `DATA_VERSION_FIELD` | `document_hash_md5` | 利用文档内容的MD5哈希值作为版本标识，实现快速增量更新判断，减少不必要的数据传输。 |
| `ERROR_RETRY_POLICY` | `指数退避，最大重试 5 次` | 应对网络瞬时波动或外部系统临时过载，提高数据同步的健壮性。 |

## 容易做错的三处

*   HTTP 接口返回 `400 Bad Request` 且提示 `Invalid character in field 'sequence_data'`：通常是由于基因序列数据中包含了非ASCII字符或特殊符号，而接口未进行适当的编码或验证。
*   文档导入后，部分字段（如“批次效价”）显示为空或数值错误：这往往是由于外部系统解析Java接口文档时，未能正确识别或映射Excel或PDF中的特定数据区域和单位，导致数据提取不完整。
*   在调用外部知识库检索时，长时间无响应并最终超时：这可能是因为API调用中传入了过大的 `payload` 或 `context_window` 参数，导致外部模型处理时间过长，超出了 `API_TIMEOUT_SECONDS` 的设置。

## 怎么确认配好了

*   选取一个包含复杂表格、图表及大段文本的mRNA疫苗CMC报告，通过HTTP接口上传，并检查知识库中数据解析的完整性与字段匹配度。
*   模拟高并发场景，同时发送多个注册申报资料的更新请求，观察接口的响应时间及错误率，确保在负载下系统稳定运行，且无 `503 Service Unavailable` 错误。
*   针对一个已导入的申报资料，修改其中一个关键字段（如批次号或稳定性数据），通过增量更新接口提交，并核对知识库中该字段是否正确更新，同时检查 `DATA_VERSION_FIELD` 的变化。
