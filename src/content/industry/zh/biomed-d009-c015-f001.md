# 临床决策支持注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样

临床决策支持（CDS）在注册申报资料准备环节的数据，主要来源于临床试验报告、药物说明书、医学指南、药典以及各类医学数据库。这些数据通常以非结构化文本（如 PDF 格式的临床研究报告、Word 格式的指南）和半结构化数据（如 XML 格式的药物说明书、JSON 格式的医学知识图谱条目）形式存在。数据更新频率较高，特别是医学指南和药品说明书，会随着新的临床证据和监管要求进行修订。字段和单位方面，涉及药物剂量（毫克 `mg`、微克 `mcg`）、时间单位（小时 `h`、天 `d`）、生物标志物浓度（纳摩尔每升 `nmol/L`、毫克每分升 `mg/dL`）以及疾病诊断编码（如 ICD-10 编码）等，对精确性要求极高。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

临床决策支持数据的多源异构性，要求 HTTP 接口具备强大的数据解析和整合能力。非结构化文档需要高效的文本提取和语义理解，这可能导致文件处理时间延长，进而对接口超时时间提出更高要求。高频的数据更新意味着外部系统需要支持周期性或事件驱动的数据同步机制，确保决策依据的时效性。例如，当新的临床指南发布时，系统应能及时拉取并更新相关知识。字段和单位的严格性，要求接口在数据传输和接收时进行严格的校验，防止因单位不匹配或数值格式错误导致的决策偏差。同时，大量的医学术语和缩写，需要接口在与外部系统交互时，能够正确识别和映射，避免信息失真。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `API_REQUEST_TIMEOUT_SECONDS` | `180 秒` | 处理大型临床报告或进行复杂知识推理时，需要较长响应时间。 |
| `MAX_FILE_SIZE_MB` | `50 MB` | 注册申报资料中的 PDF 文档常包含大量图表和文本，文件体积较大。 |
| `CHUNK_SIZE_TOKENS` | `800–1200 字符` | 兼顾语义完整性和模型处理效率，避免上下文丢失。 |
| `MAX_RETRIES` | `3 次` | 外部医学数据库或监管平台接口可能存在间歇性不稳定。 |
| `SIMILARITY_THRESHOLD` | `0.75` | 确保召回的医学信息与查询高度相关，降低误判风险。 |
| `CONCURRENT_REQUESTS_LIMIT` | `按实测标定` | 需根据外部系统 API 速率限制和自身服务承载能力进行调整。 |

## 容易做错的三处

*   接口请求长时间无响应或返回 `504 Gateway Timeout` 错误。原因在于，处理复杂的临床数据或调用外部模型进行推理时，默认的超时时间不足以完成任务。
*   接收到的数据中关键医学指标字段为空或格式错误。原因在于，未对外部系统返回的数据进行严格的结构和类型校验，导致数据解析失败。
*   Agent 在多次请求后，无法将文件正确传递给下游 API。原因在于，`messages` 字段中文件参数的 `type` 或 `media_type` 定义不符合目标 API 期望，或文件编码存在问题。

## 怎么确认配好了

*   通过模拟请求，验证接口在处理包含多个大型 PDF 临床报告时，是否能在 `API_REQUEST_TIMEOUT_SECONDS` 内成功返回结果。
*   检查日志中是否有因 `MAX_FILE_SIZE_MB` 限制导致的文件上传失败记录，并尝试上传接近该限制的文件以验证其有效性。
*   调用外部医学数据库接口，并核对返回的关键字段（如 `drug_name`、`dosage_unit`）是否与预期数据类型和格式一致。
*   观察系统在处理高并发请求时，`CONCURRENT_REQUESTS_LIMIT` 是否有效防止了外部系统因过载而拒绝服务。
