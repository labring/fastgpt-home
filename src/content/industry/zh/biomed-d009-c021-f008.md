# 供应商审计注册申报资料准备的工具调用与插件

## 这个品类的数据长什么样

供应商审计报告数据通常结构化与半结构化并存。数据来源包括审计报告、质量协议、供应商资质文件、生产场地照片及缺陷项整改记录。更新频率因供应商风险等级和审计周期而异，高风险供应商可能每年更新，低风险则可能两到三年一次。文档格式以 PDF、Word 和 Excel 居多，部分系统导出为 XML 或 JSON 格式。字段包含审计日期、审计员、供应商名称、产品范围、缺陷描述、风险评级、整改措施及完成日期。单位涉及日期、数量、百分比及文本描述，例如缺陷项数量、整改完成率等。

## 这些特征在「工具调用与插件」这一环带来什么约束

供应商审计数据的异构性要求工具调用能够处理多种文档格式，并具备从半结构化文本中提取关键信息的能力。更新频率不高，但单次更新的数据量可能较大，例如一份审计报告可能包含数十页内容，这要求文件解析和向量化的过程高效稳定，并能处理长文本。缺陷项、风险评级等关键字段的准确提取，依赖于模型对生物医药专业术语的理解和上下文关联能力。多行查询的需求，源于需要同时获取审计历史数据和当前整改状态，这要求数据库连接插件支持事务性或多语句执行。联网工具的使用，旨在获取外部法规更新或行业标准，确保审计标准的时效性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 审计报告通常包含图片和大量文本，单个文件可能较大 |
| `maxContext` | `8192 token` | 确保能够容纳完整的审计报告段落，避免关键信息被截断 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 处理大型 PDF 或 Word 文档需要较长的解析时间 |
| `分段长度` | `800 字符` | 兼顾语义完整性和召回效率，避免过度碎片化或过长段落 |
| `召回条数` | `10 条` | 增加从向量库中检索相关信息的广度，提高命中率 |
| `API_TIMEOUT` | `120 秒` | 外部大模型或数据库查询可能耗时，避免因超时中断 |

## 容易做错的三处

*   数据库连接插件执行多行 SQL 查询时报错，显示语法错误或只执行了第一行。原因在于连接器默认只支持单行语句执行，需要配置为支持多语句模式或拆分查询。
*   上传大型 PDF 格式的审计报告后，系统返回 `500` 错误或处理超时。原因在于文件大小超过了 `UPLOAD_FILE_MAX_SIZE` 限制，或文件解析时间超出了 `PARSE_FILE_TIMEOUT_SECONDS`。
*   通过联网工具获取的行业法规内容不完整或引用来源缺失。原因在于联网工具的抓取深度不足，或者目标网站有反爬机制，未能获取到完整的引用内容。

## 怎么确认配好了

*   上传一份包含 100 页以上审计报告的 PDF 文件，观察文件是否能正常解析并向量化，检查日志中是否有解析失败的错误。
*   构建包含 `INSERT` 和 `SELECT` 操作的 SQL 语句，通过数据库连接插件执行，验证数据插入和查询结果是否符合预期。
*   使用联网工具查询最新的生物医药法规更新，验证返回结果的完整性和引用来源的准确性。
