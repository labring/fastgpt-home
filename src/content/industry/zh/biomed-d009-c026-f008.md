# 冷链物流注册申报资料准备的工具调用与插件

## 这个品类的数据长什么样

冷链物流在注册申报资料准备中涉及的数据具有高度专业性和时效性。数据来源包括温湿度记录仪（如 `LogTag`、`Testo` 等品牌）、RFID 标签、GPS 定位系统、以及企业内部的 SOP 文档、验证报告和风险评估文件。这些数据更新频率高，例如温湿度数据可能每隔数分钟记录一次，而 SOP 和验证报告则在修订或周期性复审时更新。文档通常以 PDF、Excel、CSV 或 XML 格式存储，结构化数据中包含关键字段如 `设备序列号`、`测量时间戳`、`温度值`（单位：摄氏度或华氏度）、`湿度值`（单位：%RH）、`地理位置坐标`、`报警状态`。非结构化文档则涉及详细的操作规程、偏差处理记录和合规性审计结果。

## 这些特征在「工具调用与插件」这一环带来什么约束

冷链物流数据的多源性和高频更新对工具调用提出了实时性和准确性要求。例如，从温湿度记录仪导出的 CSV 文件可能包含大量时间序列数据，需要插件能快速解析并提取 `温度` 和 `时间` 字段。非结构化文档中的专业术语和缩写，要求模型能调用术语表插件进行准确识别和解释。注册申报资料对数据完整性和可追溯性有严格要求，因此工具调用需要确保每次数据提取或处理都能记录其来源和操作历史。此外，不同设备或系统导出的数据格式可能存在细微差异，需要插件具备一定的容错能力和数据清洗能力。地理位置数据和时间戳数据需要特定的地理编码和时区转换插件来保证一致性和准确性。

## 配置怎么定

| 配置项                       | 建议取法           | 这样取的依据                                                 |
| :--------------------------- | :----------------- | :----------------------------------------------------------- |
| `UPLOAD_FILE_MAX_SIZE`       | `500 MB`           | 冷链物流的日志文件或验证报告可能较大，需支持上传大型文件。   |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`           | 大文件解析耗时较长，避免因超时导致解析失败。                 |
| `maxContext`                 | `8192 token`       | 确保能够容纳较长的 SOP 文档或验证报告的关键信息。            |
| `分段长度`                   | `800–1200 字符`    | 兼顾语义完整性和处理效率，适合处理文本型文档。               |
| `召回条数`                   | `前 10 条`         | 提高相关信息召回率，覆盖更多潜在关键数据点。                 |
| `相似度阈值`                 | `0.75`             | 确保召回内容的强相关性，减少噪声干扰。                       |

## 容易做错的三处

*   调用外部 API 时出现 `401 Unauthorized` 错误，原因是 API 密钥配置不正确或已过期。
*   解析温湿度 CSV 文件时，`温度值` 字段为空或格式错误，原因是 CSV 文件编码与预期不符或分隔符解析有误。
*   地理位置信息在提取后无法正确转换为标准坐标，原因是调用的地理编码插件服务不稳定或配额不足。

## 怎么确认配好了

*   上传一份包含温湿度记录、SOP 和验证报告的混合文档包，检查是否所有文件都能被成功解析并提取出关键字段，如 `设备序列号`、`温度值`、`修订日期`。
*   执行一次包含地理位置数据和时间戳数据的查询，核对返回结果中的坐标和时间是否与原始数据一致，并确认时区转换正确。
*   模拟一次外部 API 调用，观察日志中是否返回 `200 OK` 状态码，并检查返回数据结构是否符合预期。
