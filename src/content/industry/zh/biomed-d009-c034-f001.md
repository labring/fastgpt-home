# 医药电商注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样

医药电商的注册申报资料数据主要来源于药品生产企业、医疗器械生产企业、以及电商平台自身的运营数据。这些数据更新频率相对较低，通常在产品上市前或发生重大变更时集中提交。文档结构复杂，包含药品说明书、注册证扫描件、批件、检验报告、临床试验数据、企业资质证明等，多以 PDF、Word、Excel 等非结构化或半结构化形式存在。字段内容高度规范化，例如药品通用名、规格、剂型、注册证号等，但不同批次或不同来源的文档可能存在命名差异或单位不统一（如 mg、g、ml、IU 等），且常伴随大量医学术语。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

医药电商注册申报资料的低更新频率决定了数据同步策略不必追求实时性，周期性批量导入更为合适。文档的多样化格式要求 HTTP 接口支持多种文件类型上传与解析，并能处理非结构化文本的提取。字段的规范性与潜在差异性，对外部系统的数据清洗与标准化能力提出了要求，HTTP 接口在接收数据时需能携带元数据以辅助后续处理。医学术语的复杂性意味着在数据传输过程中，可能需要结合特定词典进行预处理或校验，以确保语义准确性，防止因术语理解偏差导致的申报错误。

## 配置怎么定

| 配置项                       | 建议取法       | 这样取的依据                                   |
| :--------------------------- | :------------- | :--------------------------------------------- |
| `UPLOAD_FILE_MAX_SIZE`       | `500 MB`       | 单个申报文件（如批件扫描件）可能较大           |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`       | 大型 PDF 文档解析耗时较长                      |
| `maxContext`                 | `4000 字符`    | 适应单个申报文件片段的平均信息密度             |
| `分段长度`                   | `800–1200 字符` | 兼顾语义完整性与模型处理效率                   |
| `相似度阈值`                 | `0.8`          | 确保召回结果与申报材料高度相关                 |
| `HTTP_REQUEST_TIMEOUT`       | `120 秒`       | 应对外部系统处理复杂请求或大文件时的延迟       |

## 容易做错的三处

*   HTTP 请求返回 504 Gateway Timeout 状态码，通常是由于外部系统在处理上传的大文件或复杂解析任务时，未能在 FastGPT 的默认请求超时时间内完成响应。
*   导入的申报资料中部分关键字段（如注册证号、批准文号）为空，这往往是由于外部系统在解析非结构化文档时，未能准确识别或提取这些特定格式的字段。
*   工作流 API 调用后，未能创建新的知识库或导入文件，这可能与 API 密钥权限不足或请求体中缺少必要参数（如知识库名称、文件路径）有关。

## 怎么确认配好了

*   上传一份包含多种格式（PDF、Word、Excel）的典型申报资料，观察是否能正常解析并提取出关键信息，核对提取字段的完整性。
*   通过 API 接口上传一份超过预期大小的申报文件，验证 `UPLOAD_FILE_MAX_SIZE` 配置是否生效，观察返回的错误信息是否符合预期。
*   模拟外部系统响应延迟的情况，检查 FastGPT 与外部系统之间的 HTTP 请求超时机制是否按 `HTTP_REQUEST_TIMEOUT` 配置生效。
