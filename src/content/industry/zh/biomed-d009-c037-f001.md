# 双特异性抗体注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样

双特异性抗体注册申报资料涉及的数据类型多样且复杂。数据来源包括临床前研究报告（如药效学、药代动力学、毒理学）、临床试验数据（如I/II/III期临床报告、不良事件报告、生物标志物分析）、生产工艺文件（如细胞株构建、纯化过程、质量控制标准）以及稳定性研究报告等。这些数据更新频率不一，临床试验数据可能按季度或年度更新，而生产工艺数据相对稳定。文档结构通常遵循ICH M4E（通用技术文档，CTD）格式，包含模块1至模块5，其中模块3（质量）和模块4（非临床研究报告）对双抗的结构特殊性有详细要求。字段与单位方面，例如在药代动力学数据中，涉及的血药浓度单位常为 `ng/mL` 或 `μg/mL`，半衰期单位为 `h`，而体外结合亲和力数据可能使用 `nM` 或 `pM` 作为单位。生产工艺参数如细胞密度单位为 `cells/mL`，纯度单位为 `%`。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

双特异性抗体数据多样的来源和复杂的结构对HTTP接口与外部系统交互提出了具体要求。首先，由于数据更新频率不一，系统需要支持定时抓取与增量更新机制，以确保申报资料的时效性。其次，CTD格式的复杂层次结构要求API设计能够支持嵌套数据结构或提供清晰的路径映射，以便准确提取和关联不同模块的信息。例如，将双特异性抗体的特有结合机制和靶点信息从非临床研究报告中解析，并与临床数据中的疗效指标进行关联。字段与单位的标准化是关键，不同来源的数据可能存在单位不一致的问题，接口需要内置或支持外部转换服务进行统一，避免因单位错误导致的数据解读偏差，特别是对于生物活性和药代动力学参数。此外，由于涉及敏感的药物研发数据，接口必须具备严格的认证授权机制和数据加密传输能力。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `requestTimeoutSeconds` | `300 秒` | 多数生物医药数据接口在处理复杂查询或大量数据时，响应时间可能较长，避免提前超时。 |
| `maxRetries` | `3` | 考虑远程接口偶发性网络抖动或服务瞬时不可用，增加重试次数可提高数据获取成功率。 |
| `concurrencyLimit` | `5` | 平衡对外部系统的访问压力与自身处理能力，避免因并发过高触发限流或导致外部系统过载。 |
| `dataSchemaVersion` | `v1.2` | 确保与外部数据源预期的CTD或特定数据字段版本兼容，避免因版本不匹配导致解析失败。 |
| `httpMethod` | `POST` | 双特异性抗体申报数据量大且可能包含敏感信息，`POST` 方法更适合承载复杂请求体和保护数据。 |
| `authHeaderName` | `X-API-Key` | 多数专业生物医药数据平台采用 API Key 或 Token 进行认证，此为常见且安全的实践。 |

## 容易做错的三处

*   HTTP 请求返回 `500 Internal Server Error`，现象是外部系统处理请求时发生内部错误，通常是请求体格式不符合外部系统预期或参数校验失败。
*   接口返回数据中关键字段 `targetAffinity` 或 `PKParameters` 为空，原因可能是请求参数中缺少必要的过滤条件或外部系统未能正确解析双抗的特有结构信息。
*   数据抓取任务长时间无响应或最终超时，这可能是因为外部数据源在处理针对特定双特异性抗体的复杂查询时，计算资源消耗过大，导致响应延迟。

## 怎么确认配好了

*   针对注册申报资料中不同模块的核心数据（如模块3的 `productSpecification`、模块4的 `PKProfile`），分别进行小批量请求，检查返回数据结构和关键字段是否完整且符合预期。
*   模拟网络波动或外部系统瞬时不可用情况，观察配置的重试机制是否按预期触发，并最终能否成功获取数据。
*   选取具有代表性的双特异性抗体案例，通过接口获取其完整的临床前和临床数据，核对数据中的单位、数值范围与原始报告是否一致。
