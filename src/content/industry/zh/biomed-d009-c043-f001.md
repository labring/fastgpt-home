# 基因治疗 AAV注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样

基因治疗 AAV（腺相关病毒）注册申报资料的数据具有高度专业性和结构化特征。数据来源主要包括临床试验报告、非临床研究报告、生产工艺文件、质量控制记录等。更新频率通常与研发进展和监管要求紧密相关，例如临床试验数据会定期更新，生产工艺变更则触发新的文档版本。文档结构复杂，常包含大量图表、序列信息、实验数据和批次报告。字段与单位的特殊性体现在基因序列（如 `AAV_vector_sequence`）、滴度（如 `viral_titer`，单位 `vg/mL`）、纯度（如 `purity_percentage`，单位 `%`）以及宿主细胞系（如 `cell_line_identifier`）等。这些数据往往以 PDF、XML、JSON 或专有数据库格式存储。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

基因治疗 AAV 注册申报资料的专业性与复杂结构，要求 HTTP 接口具备强大的数据解析和验证能力。多源数据特性决定了接口需要支持多种数据格式的输入与输出，例如解析 PDF 中的表格数据，或从 XML 文件中提取特定字段。更新频率的不确定性，使得接口设计时应考虑增量更新机制，避免全量同步带来的资源消耗。文档中包含的基因序列和滴度等关键字段，对数据传输的准确性和完整性提出了高要求，需要严格的校验机制。此外，与外部系统（如临床试验数据库、LIMS 系统）的集成，要求接口能处理大量并发请求，并具备良好的错误处理和重试策略，以应对外部系统的不稳定或网络延迟。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `HTTP_TIMEOUT_SECONDS` | `180 秒` | 应对外部系统数据量大、响应慢的情况，特别是拉取大型报告文件时。 |
| `MAX_RETRIES` | `3` | 外部系统偶发性网络抖动或服务不可用，保证数据传输的鲁棒性。 |
| `DATA_FORMAT_SUPPORT` | `JSON, XML, PDF(结构化)` | 覆盖 AAV 申报资料常见的结构化数据和文档格式。 |
| `BATCH_SIZE_RECORDS` | `500` | 平衡单次请求的数据量，避免过大导致超时或内存溢出，同时减少请求次数。 |
| `AUTHENTICATION_METHOD` | `OAuth2.0` | 满足外部系统对安全认证的高要求，确保数据传输的保密性。 |
| `ERROR_NOTIFICATION_CHANNEL` | `Webhook URL` | 将接口调用失败信息实时推送到内部监控系统，便于及时响应。 |

## 容易做错的三处

*   现象：HTTP 请求返回 401 Unauthorized 错误码。原因：`AUTHENTICATION_METHOD` 配置的凭证过期或不正确，或者外部系统权限未授予。
*   现象：解析 AAV 临床报告 PDF 时，关键字段（如 `viral_titer`）为空。原因：PDF 格式非结构化，或解析器未针对该特定文档模板进行适配，导致无法准确提取字段。
*   现象：数据同步任务长时间无响应或最终超时。原因：`HTTP_TIMEOUT_SECONDS` 设置过短，或 `BATCH_SIZE_RECORDS` 过大导致单次请求数据量超出外部系统处理能力。

## 怎么确认配好了

*   通过 FastGPT 的日志功能，检查所有 HTTP 请求是否返回 2xx 成功状态码，并确认无超时错误。
*   随机抽取 5–10 份已导入的 AAV 申报资料，核对关键字段（如 `AAV_vector_sequence`、`viral_titer`）是否与原始数据源完全一致。
*   模拟外部系统间歇性故障，观察 FastGPT 是否能按 `MAX_RETRIES` 配置进行重试，并最终成功获取数据，或通过 `ERROR_NOTIFICATION_CHANNEL` 发出通知。
