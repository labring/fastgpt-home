# 实体瘤注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样
实体瘤注册申报资料的数据通常来源于多中心临床试验、病理报告、影像学检查、基因测序结果以及药物不良事件报告。这些数据更新频率不一，临床试验数据在试验期间持续累积，而病理和基因报告则在特定时间点生成。文档结构复杂，常包含PDF格式的临床研究报告、Word格式的专家意见、Excel格式的原始数据表，以及DICOM格式的影像文件。字段方面，涉及肿瘤大小（如 `Tumor_Size_mm`）、病理分级（如 `Histologic_Grade`）、基因突变类型（如 `Mutation_Type`）等特定指标，单位需严格遵循国际标准，例如肿瘤尺寸以毫米（mm）为单位，基因突变信息可能采用HGVSc或HGVSp命名规范。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
实体瘤注册申报资料的复杂数据结构和多样化文件格式，对HTTP接口的数据解析能力提出了高要求。例如，处理DICOM影像文件需要专门的解析库和API，常规的JSON或XML解析器不足以应对。多来源的数据更新频率不一，要求接口具备增量同步和版本控制能力，以避免数据冲突和重复。严格的单位和字段规范，意味着接口在数据传输和接收时必须进行严格的校验，例如确保 `Tumor_Size_mm` 字段仅接受数值且单位正确。此外，敏感的患者隐私信息，例如 `Patient_ID`，要求接口必须支持端到端加密和严格的权限控制，确保数据安全合规。

## 配置怎么定

| 配置项             | 建议取法                               | 这样取的依据                                                                                             |
| :----------------- | :------------------------------------- | :------------------------------------------------------------------------------------------------------- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB`                               | 影像文件和临床报告通常较大，需要足够的上传容量。                                                         |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`                               | 大型PDF报告和DICOM文件解析耗时较长，避免解析超时导致任务失败。                                          |
| `maxContext`       | `4000–8000 字符`                       | 确保能一次性处理较长的病理诊断或临床结论文本，维持上下文完整性。                                         |
| `分段长度`         | `800–1200 字符`                        | 平衡文本语义完整性和处理效率，适应医学文档中复杂的段落结构。                                             |
| `相似度阈值`       | `0.75`                                 | 确保检索到的临床试验数据与用户查询高度相关，减少误报。                                                   |
| `API_KEY_ROTATION_INTERVAL` | `90 天`                                | 定期更换API密钥，降低安全风险，符合医疗数据安全标准。                                                    |

## 容易做错的三处
*   调用外部基因测序API时，返回401 Unauthorized错误，原因是 `API_KEY` 未正确配置或已过期。
*   上传大型影像文件后，系统提示“文件解析失败”，现象是 `PARSE_FILE_TIMEOUT_SECONDS` 配置过低，未能完成DICOM文件的解析。
*   从外部数据库获取临床试验数据时，部分关键字段如 `Tumor_Size_mm` 为空，原因是接口未正确映射或校验外部系统的数值字段与单位。

## 怎么确认配好了
*   对不同大小和格式的文件（如PDF、DICOM）执行上传操作，并检查系统日志，确认文件解析过程无异常且耗时在预期范围内。
*   使用包含特定医学术语和数值单位的查询，通过HTTP接口调用外部知识库，核对返回结果中的字段值和单位是否准确。
*   模拟并发请求，测试接口在高负载下的响应时间和错误率，确保外部API调用的稳定性。
*   定期检查 `API_KEY` 的有效性，并验证其在外部系统中的权限设置是否与业务需求一致。
