# 家用医疗注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样
家用医疗器械的注册申报资料数据，主要来源于生产企业的内部质量管理体系文档、产品设计文档、临床评价报告、检测报告以及法规符合性声明。这些数据通常以结构化文档（如 Word、PDF、Excel）和非结构化数据（如图片、CAD 图纸）的形式存在。数据更新频率较低，主要集中在产品研发、注册申请、变更申请等关键节点。文档结构遵循国家药品监督管理局（NMPA）的注册申报要求，字段涵盖产品名称、型号规格、预期用途、技术指标、主要组成成分、生产工艺、检验方法等，单位严格遵循国际单位制或行业标准，例如功率单位为瓦特（W），尺寸单位为毫米（mm），重量单位为克（g）。数据内容的准确性和完整性是申报成功的关键。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
家用医疗器械申报资料的低更新频率，意味着外部系统通过 HTTP 接口获取数据时，不需要频繁轮询。接口设计应侧重于批量文档传输和版本管理，例如提供`getDocumentVersion`和`downloadDocument`等API。文档结构的高度规范性，要求接口在数据解析时能准确识别并提取关键字段，例如通过`documentType`参数指定文档类型，以便后端进行针对性解析。字段与单位的严格性，对接口返回数据的校验提出了高要求，需要确保数值类型和单位的正确性，防止因数据格式错误导致的申报失败，例如在数据传输过程中明确`unit`字段。非结构化数据的存在，则要求接口支持大文件传输和文件预览功能，例如提供`uploadAttachment`接口，并设置合适的`timeout`参数，以应对上传大文件时的耗时。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | 8000 tokens | 确保能够容纳单个申报文档的完整上下文，避免信息截断。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 应对大型 PDF 或图片文件解析耗时，防止超时中断。 |
| `maxConcurrentRequests` | 5 | 平衡外部系统并发访问压力与FastGPT处理能力，避免过载。 |
| `similarityThreshold` | 0.75 | 提高知识召回的准确性，过滤不相关信息，因为申报资料对精确度要求高。 |
| `retryAttempts` | 3 | 应对网络波动或外部系统暂时性故障，增加接口调用的鲁棒性。 |
| `documentChunkSize` | 1000 字符 | 优化文本分段，确保每个段落包含完整语义，便于后续检索。 |

## 容易做错的三处
*   外部系统调用接口时，返回状态码 400，并且错误信息显示`INVALID_UNIT_FORMAT`。原因是传输的数据中，某个关键字段的单位与预期不符，例如将“毫升”写成了“ml”。
*   上传大型检测报告 PDF 文件后，系统长时间无响应，最终提示`GATEWAY_TIMEOUT`。原因是HTTP接口的`timeout`参数设置过短，未能覆盖大文件传输和解析所需时间。
*   通过API创建应用后，尝试调用知识库接口却无法获取到预期的申报资料内容，返回结果为空。原因是知识库配置中`similarityThreshold`设置过高，导致召回过于严格，无法匹配到相关资料。

## 怎么确认配好了
*   对一个典型的申报文档，通过 FastGPT 平台的文件上传功能进行测试，核对文件内容是否被完整解析，关键字段是否正确提取。
*   使用外部系统模拟调用`uploadDocument`接口，上传一个包含所有常见数据类型（文本、图片、表格）的测试文档，并检查接口返回状态码为 200。
*   通过 FastGPT 的检索测试功能，输入申报资料中的关键术语或法规条文，验证能否准确召回相关文档片段，并调整`similarityThreshold`至合适的数值。
