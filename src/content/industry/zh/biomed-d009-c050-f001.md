# 工艺验证注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样

工艺验证数据主要来源于生产过程控制系统、实验室信息管理系统（LIMS）以及质量管理系统（QMS）。数据更新频率取决于批次生产周期和验证阶段，可能从每日多次到每周一次不等。文档结构通常遵循ICH Q7、FDA和NMPA等法规指南，包含验证方案、验证报告、偏差处理记录、变更控制记录等。数据字段涉及关键工艺参数（如温度、压力、时间）、关键质量属性（如纯度、含量、杂质）、批次信息、设备ID、操作员ID、分析方法ID等。单位通常严格遵循国际单位制（SI）或行业标准，例如温度单位为摄氏度（℃），压力单位为帕斯卡（Pa）或巴（bar），时间单位为秒（s）或分钟（min）。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

工艺验证数据的多源性要求HTTP接口设计需支持多种数据源的集成，例如与LIMS系统对接获取分析结果，与生产SCADA系统对接获取实时参数。数据更新频率的不一，特别是涉及实时监控数据的场景，需要接口具备高效的数据拉取或推送机制，避免数据延迟影响申报资料的准确性。严格的法规遵从性决定了数据传输必须确保完整性、一致性和可追溯性，要求接口支持身份认证、数据加密（如HTTPS）和详细的日志记录，以满足审计要求。文档结构复杂且规范性强，意味着HTTP接口在接收和解析数据时，需要针对特定的XML或JSON Schema进行严格校验，确保数据格式符合预期。字段与单位的标准化，要求接口在数据传输过程中保持单位的一致性，并在必要时进行单位转换，避免因单位不匹配导致的数据误解。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `8000 tokens` | 适应工艺验证报告的详细程度，确保完整上下文理解。 |
| `UPLOAD_FILE_MAX_SIZE` | `100 MB` | 允许上传大型工艺验证报告（含图表、附件）。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 应对复杂PDF或Word文档解析时间长的情况。 |
| `分段长度` | `800 字符` | 平衡文本语义完整性与召回效率，避免过度截断。 |
| `相似度阈值` | `0.75` | 确保召回的验证数据与查询高度相关，减少噪声。 |
| `重排返回条数` | `前 5 条` | 聚焦最相关的关键验证数据，提升信息提取效率。 |

## 容易做错的三处

*   HTTP接口调用返回 `404 Not Found` 错误，原因通常是外部系统API路径配置不正确，或者FastGPT的路由未正确映射到外部服务。
*   上传大型工艺验证报告后，日志显示 `File size exceeds limit`，这是因为系统参数 `UPLOAD_FILE_MAX_SIZE` 设定值低于实际文件大小。
*   外部系统数据同步后，部分关键字段（如批次号 `batch_id` 或设备编码 `equipment_code`）在知识库中为空，原因可能是HTTP接口响应中的字段名与预设的解析规则不匹配，或JSON/XML路径表达式有误。

## 怎么确认配好了

*   通过FastGPT的HTTP接口测试工具，向配置的外部系统接口发送模拟请求，观察是否返回 `200 OK` 状态码和预期的数据结构。
*   上传一份包含多页图表和表格的典型工艺验证报告，检查知识库中是否能够正确分段并提取出关键信息，例如“关键工艺参数”或“质量属性限度”。
*   在知识库中针对特定批次的工艺验证数据进行提问，例如“批次 `20230815-001` 的纯度验证结果”，验证FastGPT是否能准确召回并引用相关数据段落，并核对召回内容与原始报告的一致性。
