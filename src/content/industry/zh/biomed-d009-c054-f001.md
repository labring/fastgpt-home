# 康复设备注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样
康复设备的注册申报资料数据来源广泛，通常包括产品技术要求、检验报告、临床评价报告、说明书、标签和生产制造信息。这些数据往往分散在内部研发文档管理系统、质量管理体系（QMS）和第三方检测机构的数据库中。数据的更新频率不一，技术要求和说明书可能随产品迭代而更新，而检验报告和临床数据则在特定批次或版本发布时生成。文档格式多样，常见的有 PDF（扫描件和可编辑文本）、Word 文档、Excel 表格和少量图片。字段与单位方面，涉及机械尺寸（毫米、厘米）、电气参数（伏特、安培、瓦特）、材料特性（硬度、密度）、生物相容性指标等，单位通常采用国际单位制，但一些旧版文档或特定测试报告可能出现非标准单位，需要在数据整合时进行单位转换。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
康复设备申报资料数据来源多样性，要求 HTTP 接口具备高度的灵活性，能够与多种内部系统（如 PLM、QMS）和外部系统（如检测机构报告平台）进行数据交换。文档格式的多样性对接口的数据解析能力提出了挑战，尤其对于 PDF 扫描件，需要 OCR 技术辅助提取文本，这意味着 HTTP 请求可能需要发送二进制文件或 Base64 编码的图像数据。不一致的更新频率要求接口能够支持增量同步和全量同步两种模式，并能处理版本冲突。字段与单位的特殊性，特别是单位转换的需求，意味着接口在接收数据后需要进行预处理，或者在发送请求时携带元数据以指导后端处理。此外，由于申报资料的敏感性，HTTP 接口必须强制采用 HTTPS 协议，并实施严格的身份验证与授权机制，确保数据传输的安全性与合规性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `API_KEY_HEADER` | `X-API-Key` | 行业标准做法，便于识别和管理凭证 |
| `REQUEST_TIMEOUT_SECONDS` | `600 秒` | 多数外部系统处理复杂文档解析所需时间，避免超时中断 |
| `MAX_FILE_SIZE_MB` | `100 MB` | 考虑单个检验报告或临床评价报告可能包含大量图表和文本 |
| `PARSING_CONCURRENCY_LIMIT` | `2–4` | 平衡系统资源占用与处理效率，避免瞬时高并发导致系统过载 |
| `RETRY_STRATEGY` | 间隔重试 (3 次，5s, 10s, 30s) | 应对外部系统瞬时网络波动或服务暂时不可用情况 |
| `DATA_ENCODING_FORMAT` | `UTF-8` | 确保多语言字符和特殊符号在数据传输中不出现乱码 |

## 容易做错的三处
*   现象：FastGPT 提示“无可用渠道”或模型调用失败。原因：HTTP 接口配置中 `API_ENDPOINT` 地址有误，或 `API_KEY` 未正确配置，导致无法连接到外部 AI 服务或认证失败。
*   现象：上传 PDF 文件后，AI 提取的内容为空或不完整。原因：HTTP 请求在发送文件时，未正确设置 `Content-Type` 为 `multipart/form-data` 或 `application/octet-stream`，导致外部系统无法识别文件类型并进行解析。
*   现象：系统处理康复设备申报资料时，某些数值型字段的单位转换错误。原因：HTTP 请求未在 `body` 或 `headers` 中传递必要的单位元数据，或外部系统未配置相应的单位转换规则，导致数据处理时默认采用不一致的单位。

## 怎么确认配好了
*   对每一个配置的 HTTP 接口执行一次模拟调用，检查是否收到成功的状态码（如 200 OK）和预期的数据结构。
*   上传一份包含复杂表格和图示的康复设备检验报告 PDF 文件，观察 AI 提取的关键字段（如 `测试项目`、`结果`、`单位`）是否完整且准确，并核对单位是否正确转换。
*   检查系统日志，确认 HTTP 请求的 `REQUEST_TIMEOUT_SECONDS` 设置是否生效，以及在外部系统响应慢时是否触发了 `RETRY_STRATEGY`。
*   尝试上传一个超出 `MAX_FILE_SIZE_MB` 限制的文件，确认系统是否正确拒绝并返回相应的错误提示。
