# 感染性疾病注册申报资料准备的部署与升级

## 这个品类的数据长什么样

感染性疾病领域的注册申报资料，其数据来源广泛，通常包括临床试验报告、非临床研究报告、药物警戒数据、流行病学数据、微生物学检测报告及全球监管机构发布的指南与法规文件。这些数据更新频率较高，尤其是在新发传染病爆发或耐药性变异出现时，相关指南和临床数据会迅速迭代。文档结构复杂多样，涵盖 ICH E3 临床研究报告格式、CTD（通用技术文件）模块化结构、WHO 指南、CDC 报告等。字段与单位具有高度专业性，例如微生物最低抑菌浓度（MIC，单位 µg/mL）、病毒载量（copies/mL）、抗体滴度（IU/mL）、感染率（%）、发病率（每十万人）。数据中常包含大量表格、图表和医学图像，文本内容涉及专业术语、缩写及复杂的因果链条描述。

## 这些特征在「部署与升级」这一环带来什么约束

感染性疾病注册申报资料的数据特征，对 FastGPT 的部署与升级提出了特定要求。高频更新和多源异构的数据，要求系统在数据同步和索引重建方面具备高效且稳定的机制，以确保知识库的时效性和准确性。复杂的文档结构和专业字段单位，需要更精细的文本分段策略和实体识别能力，避免关键信息丢失或混淆。例如，微生物学检测报告中的 MIC 值必须被准确识别并与药物剂量关联。同时，大量医学图像和图表的存在，对文件解析能力提出了挑战，可能需要增强图像识别与表格结构化提取功能。在升级过程中，必须考虑新旧数据格式的兼容性，以及模型对新知识的快速学习与适应能力，确保升级不会导致已有知识的降级或偏差。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 临床试验报告、CTD 模块等文件通常较大，需支持大文件上传。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 处理包含大量图表、复杂表格的 PDF 文件，解析时间可能较长。 |
| `分段长度` | `800-1200 字符` | 确保医学专业术语和上下文的完整性，避免语义被截断。 |
| `重叠长度` | `150 字符` | 保证相邻段落间的语义连续性，尤其在描述复杂病理过程时。 |
| `相似度阈值` | `0.75-0.85` | 提高检索精确度，过滤掉与感染性疾病领域相关度低的文档片段。 |
| `重排返回条数` | `前 10 条` | 确保在复杂查询下，能从大量相关信息中筛选出最精准的关键数据。 |

## 容易做错的三处

*   Rerank 模型部署后返回 `401 Unauthorized` 错误，通常是由于 API Key 或访问凭证配置不正确，或私有化部署时网络策略限制了内部服务间的通信。
*   升级 FastGPT 版本后，部分 Deepseek 模型无法正常调用，日志显示模型 API 密钥无效，这往往是由于新版本对模型认证机制有所更新，需要重新配置或刷新 API Key。
*   知识库文档上传后，检索结果中微生物检测报告的关键数值（如 `MIC` 值）缺失或错误，原因在于默认文件解析器未能正确识别并提取复杂表格或特定医学字段。

## 怎么确认配好了

*   上传一份典型的临床试验报告（PDF 格式），观察其分段数量和内容完整性，确保关键数据和专业术语未被割裂。
*   针对一份包含微生物药敏结果的文档进行检索，查询特定病原体的 `MIC` 值，核对返回结果中的数值与原始文档是否一致。
*   在更新流行病学数据后，执行相关疫情趋势查询，验证系统是否能够召回最新发布的数据和分析报告。
*   通过 FastGPT 界面测试不同大小的文档上传功能，确认上传大文件时没有超时或失败提示。
