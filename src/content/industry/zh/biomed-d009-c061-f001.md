# 手术机器人注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样

手术机器人注册申报资料的数据来源多样，包括临床试验报告、动物实验数据、设计验证报告、风险管理文件、生产工艺文件以及用户手册等。这些数据更新频率相对较低，主要集中在产品研发、临床试验和审批阶段。文档结构通常高度标准化，遵循医疗器械监管机构（如NMPA、FDA）的特定模板和指南。字段方面，涉及医学术语、工程参数、统计学指标等，例如临床有效性指标（`有效率`、`并发症率`）、机械精度（`重复定位精度`、`力反馈精度`）和生物相容性材料数据（`材料成分`、`溶出物`）。单位则涵盖常见的国际单位制（如 `毫米`、`牛顿`、`秒`）以及特定医学计量单位（如 `ml/min`）。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

手术机器人申报资料的标准化文档结构要求HTTP接口在数据传输时严格遵循预定义的数据模型，确保字段类型和格式的准确性。数据更新频率低，意味着接口设计时对实时性要求不高，但对数据的完整性和一致性有较高要求，需要支持大文件传输和断点续传。医学和工程参数的精确性要求接口在数据序列化和反序列化过程中避免精度损失。例如，`重复定位精度`这类关键指标，数值的微小差异可能导致申报结果的不同。此外，大量结构化和非结构化数据的混合（如PDF报告、DICOM图像）要求外部系统具备强大的文件解析和内容抽取能力，以及对不同数据类型的适配性，从而保证申报资料的全面性和准确性。

## 配置怎么定

| 配置项                   | 建议取法                                 | 这样取的依据                                                                 |
| :----------------------- | :--------------------------------------- | :--------------------------------------------------------------------------- |
| `maxRequestTimeout`      | `600 秒`                                 | 手术机器人申报资料文件通常较大，需要足够时间完成上传或下载。                 |
| `maxFileSize`            | `200 MB`                                 | 适应临床报告、影像数据等大型文件的传输需求。                               |
| `retryCount`             | `3`                                      | 考虑到网络波动或外部系统瞬时故障，增加重试机制提高传输成功率。               |
| `contentType`            | `application/json; charset=UTF-8` 或 `multipart/form-data` | 应对结构化数据传输以及文件上传的需求。                                     |
| `dataValidationSchema`   | 按实测标定                               | 确保传输数据的字段类型、范围和格式符合申报规范，例如 `有效率` 必须为 `0-100`。 |
| `apiEndpoint`            | `https://api.example.com/robot-submission/v1` | 明确指向专门处理手术机器人申报资料的外部系统接口。                           |

## 容易做错的三处

*   HTTP 请求返回 `413 Payload Too Large`：现象是文件上传失败，原因为请求体大小超过服务器或网关限制，`maxFileSize` 配置不足。
*   接口调用成功但返回数据中关键字段（如 `重复定位精度`）为空：原因通常是外部系统未能正确解析或提取PDF等非结构化文档中的特定字段，`dataValidationSchema` 未能覆盖所有数据提取场景。
*   长时间无响应导致连接超时：原因可能是传输文件过大，或外部系统处理复杂医学数据耗时过长，`maxRequestTimeout` 设置过低。

## 怎么确认配好了

*   进行端到端测试，上传一个包含所有典型数据类型（如PDF、DICOM）的完整申报资料包，检查外部系统是否能完整接收并正确解析所有文件和字段。
*   验证关键数值型字段（如 `力反馈精度`、`材料成分`）的精度是否在传输和处理后保持一致，可通过比对源数据与外部系统处理后的数据。
*   模拟网络异常或外部系统短暂不可用情况，检查 `retryCount` 配置是否有效，确保数据传输具备一定的容错能力。
*   检查外部系统日志，确认所有HTTP请求的 `contentType` 与实际发送的数据类型匹配，避免因类型不匹配导致的数据解析错误。
