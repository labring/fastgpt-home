# 注册申报注册申报资料准备的工具调用与插件

## 这个品类的数据长什么样

生物医药领域的注册申报资料主要包括临床试验数据、非临床研究报告、生产工艺、质量控制、稳定性研究、药品说明书等。数据来源广泛，涉及医院、实验室、生产车间、研究机构等多个实体。更新频率通常与研发进展和监管要求相关联，例如临床试验数据会阶段性更新，而生产工艺变更则可能触发不定期更新。文档结构高度标准化，遵循各国药监机构（如 FDA、EMA、NMPA）发布的指导原则，如通用技术文档（CTD）格式。字段命名规范且专业性强，涉及药学、毒理学、药代动力学、统计学等专业术语，单位精确到微克、毫升、摩尔等。

## 这些特征在「工具调用与插件」这一环带来什么约束

注册申报资料的标准化文档结构对工具调用提出了明确的格式要求，例如解析 CTD 格式的 PDF 文件时，需要精确识别章节标题、表格内容和图片说明。数据更新的不规则性，要求工具能够灵活处理增量数据导入和版本控制，避免因数据陈旧导致判断失误。专业性强的字段与单位，意味着在执行数据提取或转换时，需要预置大量行业词典和单位换算规则，避免语义理解偏差或单位错误。同时，由于数据敏感性和合规性要求，工具调用必须确保数据流的安全性和可追溯性，例如对外部 API 调用的审计记录。对工具的准确性和鲁棒性要求极高，任何细微的数据偏差都可能影响申报结果。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `4000`–`8000` token | 应对复杂报告的上下文需求，同时兼顾处理效率 |
| `分段长度` | `500`–`800` 字符 | 平衡文本语义完整性与召回精度，减少信息丢失 |
| `相似度阈值` | `0.75`–`0.85` | 提高相关信息召回的准确性，避免无关内容干扰 |
| `重排返回条数` | `5`–`10` 条 | 在保证相关性的前提下，提供足够多的参考信息 |
| `API_TIMEOUT_SECONDS` | `60` 秒 | 应对外部工具或数据库查询时可能出现的网络延迟 |
| `MAX_RETRIES` | `3` 次 | 增强工具调用的稳定性，处理短暂性网络或服务故障 |

## 容易做错的三处

*   工具调用返回空结果或错误码，通常是由于传递给工具的参数格式不符合预期，例如日期格式不正确或必填字段缺失。
*   在解析长篇幅的临床试验报告时，工具未能正确识别所有表格数据，导致关键统计结果遗漏，这往往是分段策略未能充分考虑表格跨页或复杂嵌套结构造成的。
*   调用外部数据库查询药品批准文号时，返回结果与预期不符，可能是因为查询参数未进行标准化处理，如药品名称存在多种别名而工具只识别了其中一种。

## 怎么确认配好了

*   通过模拟提交包含常见字段和多种数据类型的测试用例，验证工具能够正确解析并提取所有关键信息。
*   对工具调用日志进行审查，确认每次 API 调用都返回了预期的状态码，并且没有出现超时或错误重试。
*   随机抽取多份不同格式的申报资料，运行工具后人工比对其输出结果与原始文档，确保数据提取的完整性和准确性，例如核对关键试验数据的 P 值是否一致。
