# 清洁验证注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样

清洁验证的数据主要来源于生产现场的采样分析报告、设备清洗记录、残留物检测报告以及验证方案与风险评估文档。这些数据通常以结构化（如检测结果表格、设备参数表）和非结构化（如实验方法描述、偏差处理报告）混合的形式存在。更新频率方面，清洁验证数据在验证周期内相对集中，验证结束后则以归档为主，但会因工艺变更、设备维护或定期复验而产生新的批次数据。文档通常包含批次号、设备编号、分析方法、检测限、回收率、残留限度、样品编号及检测结果等字段。单位方面，常见有 ppm、ppb、μg/cm²、CFU/cm² 等，且不同物质和分析方法可能采用不同单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

清洁验证数据多源且更新周期性强，要求 HTTP 接口具备高效的数据聚合与增量同步能力。结构化数据部分需要接口支持精确的字段映射与数据类型校验，确保数值型数据的正确解析及单位转换。非结构化文档的引入则要求外部系统能处理 PDF、Word 等多种文件格式，并具备文本抽取与语义理解能力，以便从中提取关键信息如验证结论或偏差描述。由于涉及敏感生产数据，接口的认证与授权机制必须严格，确保数据传输的安全性与合规性。数据量虽然单次验证后不会爆发式增长，但历史数据的累积要求外部系统具备良好的存储扩展性和查询性能。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `API_KEY_AUTH_METHOD` | `Header: Authorization` | 符合业界标准的安全认证实践，易于管理和审计 |
| `UPLOAD_FILE_MAX_SIZE` | `50 MB` | 考虑单个清洁验证报告可能包含多页图片或图表，确保文件上传成功 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 清洁验证报告的复杂度和页数可能导致较长的解析时间 |
| `CHUNK_SIZE` | `800 字符` | 平衡文本块大小与语义完整性，确保关键信息不被割裂 |
| `FIELD_MAPPING_RULES` | `JSON 配置文件` | 灵活适配不同检测报告的字段名称差异，便于后期维护 |
| `RETRY_ATTEMPTS` | `3 次` | 应对网络瞬时波动或外部系统偶发性故障，提高数据传输成功率 |

## 容易做错的三处

*   上传清洁验证报告后，系统一直显示“索引中”，长时间未完成。原因是文件解析超时，可能是 `PARSE_FILE_TIMEOUT_SECONDS` 设置过短，或文件内容过于复杂导致解析耗时。
*   部分检测结果数据导入后单位错误或数值异常。原因是数据源的单位未被正确识别，或 `FIELD_MAPPING_RULES` 中缺乏单位转换逻辑。
*   无法通过 API 上传特定格式的设备清洗记录。原因是外部系统未集成该文件格式的解析器，或 `UPLOAD_FILE_MAX_SIZE` 限制了大型记录文件的上传。

## 怎么确认配好了

*   通过 API 接口上传一份包含结构化数据和非结构化内容的典型清洁验证报告，检查系统是否能正确解析所有字段并提取关键信息。
*   模拟网络中断或外部系统短暂离线的情况，观察数据上传的重试机制是否按预期工作，并最终成功完成传输。
*   检查外部系统日志，确认数据传输过程中没有出现认证失败、数据格式错误或超时等异常报错，特别关注 HTTP 状态码是否为 2xx。
