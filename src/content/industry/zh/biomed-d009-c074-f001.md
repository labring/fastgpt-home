# 生物制药设备注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样

生物制药设备的注册申报资料数据通常呈现出高度结构化与半结构化并存的特点。数据来源主要包括设备设计文档、生产工艺流程、质量控制记录、临床前与临床试验报告、以及上市后监测数据。这些数据更新频率不一，设计与生产文档可能在设备生命周期内更新较少，而质量控制与监测数据则可能按批次或定期更新。文档结构复杂，常包含大量图表、CAD 图纸、检测报告扫描件等非文本信息，以及技术参数表、合规性声明等结构化文本。字段与单位具有高度专业性，例如“灌装精度”可能以 `±0.5%` 表示，“灭菌温度”以 `121℃` 标识，“批次号”遵循 `YYYYMMDD-XXX` 格式，对数据解析与校验提出较高要求。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

生物制药设备数据的高度结构化与专业性，要求 HTTP 接口在数据传输时需严格遵循预定义的Schema，以确保字段的准确映射与单位的一致性。大量的非文本信息，如设计图纸和检测报告，意味着接口需要支持大文件上传，并考虑文件类型的校验。由于数据更新频率差异大，外部系统在拉取或推送数据时，需要支持增量更新机制，避免全量同步带来的性能负担。此外，申报资料的合规性要求使得数据传输的安全性成为关键，例如采用 HTTPS 协议进行加密传输，并对接口进行严格的认证授权。对于可能出现的接口调用频率限制，需要外部系统具备合理的请求队列管理和重试机制，以平滑处理突发流量。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `20000 字符` | 用于处理单次请求中包含的申报资料文本，确保能覆盖大部分技术规格描述。 |
| `maxFileSize` | `200 MB` | 适配大型设计图纸或检测报告扫描件的上传需求。 |
| `requestTimeout` | `600 秒` | 为处理复杂数据解析和可能的外部系统响应延迟预留充足时间。 |
| `concurrencyLimit` | `5` | 在保证处理效率的前提下，避免对外部系统造成过大压力，减少触发限流。 |
| `retryInterval` | `30 秒` | 当外部接口出现临时性故障或限流时，提供合理的重试间隔。 |
| `authHeader` | `Bearer <token>` | 采用标准的 OAuth 2.0 Token 认证机制，确保接口调用的安全性。 |

## 容易做错的三处

*   现象：外部系统日志显示 `HTTP 429 Too Many Requests`。原因：未对大模型接口调用频率进行有效控制，并发请求超过了服务提供商的限制。
*   现象：申报资料中的某些关键字段在导入后为空或格式错误。原因：HTTP 接口传递的 JSON 或 XML 结构与目标系统要求的Schema不符，或者数据类型转换失败。
*   现象：上传大型文件时接口超时，返回 `HTTP 504 Gateway Timeout`。原因：未配置足够长的请求超时时间，或服务器端未优化大文件上传的处理流程。

## 怎么确认配好了

*   通过模拟请求工具，发送带有不同数据量和文件类型的请求，检查接口响应时间是否在预期范围内。
*   对照外部系统提供的 API 文档，逐一核对请求参数、响应字段与数据类型，确保 `chatId` 等关键标识符能够正确传递并在日志中体现。
*   持续监控 FastGPT 与外部系统之间的接口调用日志，观察 `HTTP` 状态码分布，确保 `2xx` 成功响应占比高，`4xx`/`5xx` 错误率低。
