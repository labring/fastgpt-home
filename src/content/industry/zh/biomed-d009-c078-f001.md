# 监护设备注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样

监护设备的注册申报资料数据来源广泛，涵盖了产品设计文档、测试报告、临床评价数据、风险管理报告、以及法规符合性声明等。这些数据往往以结构化（如数据库记录、XML文件）和非结构化（如PDF文档、Word报告、图片）混合的形式存在。数据的更新频率受研发进展、法规修订、临床反馈等因素影响，可能在几个月到一年内发生多次局部更新，特别是临床数据和风险评估部分。文档结构通常遵循医疗器械注册申报的通用格式，但监护设备特有的性能指标、报警参数、电磁兼容性、生物相容性等部分会有详细的专业描述。字段与单位方面，涉及生理参数（如心率 `bpm`、血氧饱和度 `SpO2 %`、血压 `mmHg`）、设备性能指标（如测量精度 `±X %`、响应时间 `ms`）、以及各种国际标准代码和分类。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

监护设备注册申报资料的复杂性和动态性，对HTTP接口与外部系统的设计提出了具体要求。数据来源的多样性意味着接口需要支持多种数据格式的解析与集成，例如从研发管理系统获取结构化数据，同时从文档管理系统获取非结构化报告。更新频率的不确定性要求接口具备增量更新和版本控制的能力，避免重复上传和数据冲突，并确保引用的是最新批准版本。文档的专业结构和特定字段与单位，则要求外部系统能理解并正确处理这些信息，例如将生理参数的数值与单位关联，或识别特定标准代码。此外，由于申报资料的敏感性，HTTP接口必须强制使用HTTPS协议，并实施严格的身份验证与授权机制，以保障数据传输的安全性。对于大型文件，接口还需要支持分块上传和断点续传功能。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `api_key_validity_period` | `90 天` | 定期轮换 API 密钥，降低长期泄露风险，符合安全审计要求。 |
| `max_document_size_mb` | `50 MB` | 兼顾大型报告和图谱，避免单次传输过大导致超时，同时控制资源消耗。 |
| `chunk_size_characters` | `800–1200 字符` | 优化文本处理效率，平衡上下文完整性与模型处理能力，避免截断关键信息。 |
| `similarity_threshold` | `0.75` | 高于通用阈值，确保召回的资料与查询内容高度相关，减少误报。 |
| `recall_top_n_documents` | `前 10 条` | 考虑到监护设备资料的专业性和关联性，适当增加召回数量以覆盖潜在信息。 |
| `http_timeout_seconds` | `600 秒` | 应对大型文件上传或复杂查询的响应时间，特别是涉及外部系统数据处理时。 |

## 容易做错的三处

*   调用接口后收到 `HTTP 401 Unauthorized` 错误码，原因可能是 `api_key` 未正确配置或已过期。
*   上传大型测试报告文件时出现连接中断或数据不完整，这是因为 `http_timeout_seconds` 配置过短或未启用分块上传功能。
*   查询特定性能指标时，返回结果中缺少关键数据或数据格式不正确，这通常源于外部系统数据源的字段映射有误，或者接口未正确处理监护设备特有的单位转换。

## 怎么确认配好了

*   通过调用 `/status` 或 `/health` 接口，确认外部系统连接状态正常，且所有依赖服务都已启动。
*   使用一小部分模拟监护设备申报数据，通过配置好的HTTP接口进行端到端测试，验证数据能够完整且准确地传输至目标系统。
*   随机选取几份复杂的申报文档，测试其上传和解析过程，并检查目标系统中这些文档的结构化提取结果与原始数据是否一致。
*   在实际申报资料准备过程中，观察系统日志，确认没有出现异常错误码或超时记录，并且数据更新能够及时反映。
