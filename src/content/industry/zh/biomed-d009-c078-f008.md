# 监护设备注册申报资料准备的工具调用与插件

## 这个品类的数据长什么样

监护设备注册申报资料的数据来源广泛，包括企业内部的研发记录、测试报告、临床验证数据、风险管理文件以及外部的法规标准、指导原则等。这些数据更新频率不一，法规标准可能每年修订，而内部测试报告则随产品迭代而更新。文档结构多样，涵盖 PDF 格式的法规文件、Word 格式的说明书与技术要求、Excel 格式的性能参数表。字段方面，特有生物医学参数如心率（bpm）、血氧饱和度（SpO2 %）、血压（mmHg）等，单位精确到小数点后一位或两位。数据特点在于高度结构化与非结构化并存，且对数据溯源性与一致性要求极高。

## 这些特征在「工具调用与插件」这一环带来什么约束

监护设备资料的复杂性与多样性对工具调用与插件提出了特定要求。首先，大量 PDF 格式的法规文件和技术文档需要强大的 PDF 解析能力，以准确提取关键条款和数据。其次，多源异构数据要求插件具备灵活的数据集成与转换能力，能处理不同格式和结构的字段，并统一单位。例如，血压数据可能存在 mmHg 和 kPa 两种单位，需要统一处理。再次，对数据准确性和溯源性的高要求，使得插件在提取信息后，需要能够标记数据来源，并支持人工校对与修正。最后，法规标准的动态更新，意味着插件需要定期更新其知识库，以确保所引用的法规依据是最新的。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 监护设备文档通常较大，包含大量图表和复杂排版，需要更长的解析时间。 |
| `分段长度` | `800–1200 字符` | 兼顾长篇技术说明与法规条款的语义完整性，避免关键信息被截断。 |
| `召回条数` | `前 10 条` | 注册申报资料对信息完备性要求高，增加召回数量有助于覆盖更多相关法规与技术细节。 |
| `相似度阈值` | `0.78` | 确保召回内容的精准性，减少无关信息的干扰，尤其针对法规条款的精确匹配。 |
| `ENABLE_PDF_ENHANCED_PARSING` | `true` | 监护设备申报资料中大量使用复杂排版的 PDF 文档，增强解析能提高提取准确率。 |
| `MAX_CONCURRENT_API_CALLS` | `按实测标定` | 确保外部法规数据库或标准查询服务的稳定调用，避免因并发过高导致服务中断。 |

## 容易做错的三处

*   现象：插件无法正确识别 PDF 文档中的表格数据，导致字段为空或信息缺失。原因：`ENABLE_PDF_ENHANCED_PARSING` 未启用或配置不当，未能处理复杂的表格结构。
*   现象：引用法规条文时，出现过时的版本信息。原因：外部法规数据库的同步插件未定期更新，导致知识库滞后于最新法规发布。
*   现象：在调用外部 API 获取标准信息时，长时间无响应或返回 503 错误。原因：`MAX_CONCURRENT_API_CALLS` 设置过高，超出外部 API 服务的并发限制。

## 怎么确认配好了

*   选取包含复杂表格和图示的监护设备技术文档进行解析，验证提取出的关键参数和单位是否完整准确。
*   随机抽取多份申报资料，通过插件调用法规查询工具，核对引用的法规条文是否为最新版本。
*   模拟高并发调用外部标准查询 API，观察系统响应时间和错误日志，确保 `MAX_CONCURRENT_API_CALLS` 配置合理。
