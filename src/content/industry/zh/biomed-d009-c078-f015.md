# 监护设备注册申报资料准备的部署与升级

## 这个品类的数据长什么样

监护设备注册申报资料的数据来源广泛，涵盖产品技术要求、检验报告、临床评价报告、风险管理报告、说明书、标签、生产工艺流程图以及软件验证报告等。这些文档多以 PDF、Word、Excel 等格式存在，其中包含大量的结构化与非结构化信息。数据更新频率通常与产品生命周期、法规修订、临床反馈等因素相关，例如软件版本升级、关键部件更换或适应症扩展时，相关资料会进行修订。文档结构复杂，常包含大量图表、附录和交叉引用。字段方面，涉及如 `测量范围`、`精度`、`报警限值`、`EMC 测试结果`、`软件版本号` 等，单位则包括 `mmHg`、`bpm`、`℃`、`kPa`、`dBμV/m` 等医疗专用或工程单位。

## 这些特征在「部署与升级」这一环带来什么约束

监护设备申报资料的数据量通常较大，且包含大量非结构化文本、图片和表格。这要求部署方案在数据存储和处理能力上具备高扩展性，以应对未来资料的持续积累和更新。资料更新频率的不确定性，特别是法规或产品变更导致的突发性更新，对知识库的增量更新机制提出了要求，需要支持高效的局部更新，避免全量重新索引带来的长时间停机。文档结构复杂和多样化的字段与单位，意味着在资料解析阶段需要更精细的文本分段策略和更强大的实体识别能力。例如，对于 `EMC 测试报告` 中的图表数据，单纯的文本切分可能导致关键信息丢失，需要结合图像识别或表格解析技术。此外，医疗器械领域的严格合规性要求，使得任何知识库升级都必须确保数据完整性、检索准确性以及历史版本可追溯，不能因升级导致数据丢失或检索逻辑偏差。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 监护设备申报资料常含大型 PDF 或图片文件，确保单文件上传无障碍。 |
| `分段长度` | `800–1200 字符` | 兼顾长文档上下文关联性与检索效率，避免过短分段丢失语义。 |
| `召回条数` | `前 10 条` | 申报资料中上下文关联性强，增加召回条数提高相关信息覆盖率。 |
| `相似度阈值` | `0.75` | 医疗领域对准确性要求高，适当提高阈值减少不相关结果。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大文件解析耗时较长，预留充足时间避免解析超时失败。 |
| `QUERY_REWRITE_ENABLE` | `true` | 复杂的技术术语和法规条款，开启查询重写可优化检索效果。 |

## 容易做错的三处

*   知识库搜索时间明显增加，排查发现是嵌入模型升级后，部分历史数据未按新模型重新嵌入，导致检索效率下降。
*   Docker 部署时拉取插件失败，通常是 `docker-compose.yml` 文件中镜像源配置错误或网络代理设置不当，导致无法连接到外部仓库。
*   数据库连接节点无法输入端口号，可能是前端界面缓存问题或后端服务版本与前端不匹配，导致 UI 控件渲染异常或数据校验逻辑错误。

## 怎么确认配好了

*   上传一份典型监护设备申报资料（例如包含图表和大量专业术语的临床评价报告），检查知识库分段是否合理，关键信息是否被正确提取。
*   执行针对性的检索查询，对比不同提问方式下返回结果的相关性与完整性，确认召回条数与相似度阈值的效果符合预期。
*   检查系统日志，确认文件解析过程中没有出现超时或错误信息，且知识库构建和更新操作均能顺利完成。
*   模拟一次小版本升级，验证现有知识库数据在升级后仍能正常访问，且检索性能无明显下降。
