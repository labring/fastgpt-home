# 真实世界研究注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样
真实世界研究（Real-World Study, RWS）注册申报资料的数据通常来源于多中心、长期随访的医疗机构电子病历系统、患者报告结局（PRO）数据库、国家医保数据库、疾病登记系统等。数据更新频率不一，可能从每日、每周到每月、每季度不等，取决于研究方案和数据源的特性。文档结构复杂，包含非结构化的临床笔记、半结构化的病历摘要和高度结构化的CRF（Case Report Form）数据。字段类型多样，涵盖患者基本信息、诊断、治疗方案、实验室检查结果、影像学报告、不良事件等，其中包含大量医学术语、缩写和特定编码系统（如ICD-10、SNOMED CT），单位也需严格遵循临床标准，例如血压（mmHg）、血糖（mmol/L）、药物剂量（mg/kg）。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
RWS数据的多源性与异构性，要求HTTP接口具备强大的数据集成能力，能够处理来自不同数据库和系统的API请求。非结构化与半结构化数据的存在，意味着需要通过POST请求发送大段文本，并可能涉及JSON或XML格式的数据体。更新频率的不确定性，对接口的实时性和稳定性提出要求，可能需要支持Webhook回调机制。医学术语和编码的标准化，制约了数据传输格式，要求接口能够支持自定义的数据映射规则，并在请求头或请求体中明确指定编码标准。此外，大量历史数据的批量导入与增量更新，对接口的并发处理能力和超时设置构成挑战。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `AIPROXY_API_ENDPOINT` | `http://your-ai-proxy-service:port/v1/chat/completions` | 指向内部AI代理服务，用于统一鉴权和路由，避免直接暴露外部AI服务接口 |
| `AIPROXY_API_TOKEN` | `your_long_generated_token` | 用于AI代理服务的身份验证，保障内部API调用的安全性 |
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `600` 秒 | RWS数据处理可能涉及复杂文本解析和大量数据传输，需要较长的超时时间 |
| `MAX_BODY_SIZE_MB` | `200` MB | 临床报告、病历摘要等非结构化数据可能文件较大，需支持大容量请求体 |
| `RETRY_ATTEMPTS` | `3` 次 | 面对多源数据接口的不稳定性，适当重试机制可提高数据获取成功率 |
| `CONTENT_TYPE_HEADER` | `application/json; charset=UTF-8` | 确保在传输包含医学术语和多语言字符的数据时，编码正确无误 |

## 容易做错的三处
*   HTTP 请求返回 401 或 403 错误码，现象是请求无法通过认证。这通常是 `AIPROXY_API_TOKEN` 配置不正确或过期导致。
*   工作流中 HTTP 请求的 Body 参数无法动态生成，现象是请求体中的变量始终是固定值。原因在于未正确使用工作流变量语法，或者变量作用域未覆盖到 HTTP 请求节点。
*   接口调用频繁出现连接超时，状态码为 504 Gateway Timeout。这可能是 `HTTP_REQUEST_TIMEOUT_SECONDS` 设置过短，或者后端服务处理RWS数据耗时过长。

## 怎么确认配好了
*   在 FastGPT 控制台的工作流中，创建一个简单的 HTTP GET 请求，指向一个已知可访问的公共API，查看是否能成功获取数据并返回 200 状态码。
*   配置 `AIPROXY_API_ENDPOINT` 和 `AIPROXY_API_TOKEN` 后，尝试调用一个需要认证的AI服务，核对是否能成功获取AI响应，同时检查AI代理服务的日志，确认请求已正确转发。
*   构造一个包含大文件或复杂 JSON 结构的 HTTP POST 请求，通过工作流发送，检查请求是否能成功发送且未触发 `MAX_BODY_SIZE_MB` 限制，并验证接收端是否能完整接收数据。
