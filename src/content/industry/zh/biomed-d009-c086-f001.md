# 罕见病注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样

罕见病注册申报资料的数据来源多样，包括临床试验报告、非临床研究报告、流行病学数据、基因组学数据以及患者登记信息等。这些数据通常散布在不同的数据库、科研文献和监管机构文档中。更新频率相对较低，主要集中在新药研发阶段性成果发布、临床试验结果公布或监管政策调整时。文档结构复杂，常包含大量非结构化文本，如病理描述、试验方法、统计分析结果，以及结构化数据，如患者基本信息、用药剂量、不良事件代码等。字段与单位具有高度专业性，例如基因突变位点描述、酶活性单位（U/L）、药物浓度（ng/mL）等，且不同罕见病之间的数据规范差异显著，标准化程度较低。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

罕见病数据的分散性和非结构化特性，要求HTTP接口设计具备高度的灵活性和鲁棒性，以适应不同数据源的API规范。由于数据更新频率不高，对接口的实时性要求相对宽松，但对数据完整性和准确性有极高要求，避免关键信息遗漏导致申报失败。文档结构复杂性意味着在调用外部系统时，需要更精细的数据解析和预处理逻辑，例如针对特定报告模板提取关键信息。字段和单位的专业性与多样性，使得接口在数据传输和验证时必须能够处理多种数据类型和单位转换，避免因单位不匹配或数据格式错误导致解析失败。此外，部分敏感的基因组学或患者隐私数据，对外部系统的安全性和合规性提出了更高要求。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `requestTimeout` | `60000 毫秒` | 罕见病数据量大，接口响应时间可能较长，预留充足时间防止超时。 |
| `headers` | `Content-Type: application/json` | 多数API接口采用JSON格式传输数据，确保正确解析。 |
| `maxRetries` | `3` | 外部系统可能因网络波动或服务瞬时负载过高导致失败，增加重试提高成功率。 |
| `retryDelay` | `5000 毫秒` | 错峰重试，避免短时间内再次触发相同的失败原因。 |
| `responseBodyFormat` | `JSON` | 外部系统返回的数据多为JSON格式，便于后续结构化处理。 |
| `authenticationType` | `Bearer Token` | 外部API通常采用JWT或OAuth2的Bearer Token进行认证。 |

## 容易做错的三处

*   现象：调用外部API时返回 `401 Unauthorized` 错误码。原因：`headers` 中 `Authorization` 字段的 `Bearer Token` 未正确设置或已过期。
*   现象：接口返回数据字段为空或类型不匹配。原因：`responseBodyFormat` 与外部系统实际返回的数据格式不符，或者对返回的JSON结构解析路径不正确，未能匹配到罕见病特有的数据字段名如 `gene_mutation_locus`。
*   现象：工作流中调用外部接口后，后续步骤无法获取到所需的 `clinical_trial_id` 等关键参数。原因：外部接口返回的JSON中，关键数据嵌套层级较深，或字段名与预期不符，导致数据提取失败。

## 怎么确认配好了

*   通过模拟请求工具（如Postman）验证外部API接口的连通性和认证机制，确保能获取到 `200 OK` 状态码和预期数据结构。
*   在FastGPT工作流中配置HTTP请求节点后，使用调试功能逐步执行，检查每个输出变量是否能正确获取到罕见病相关的 `patient_id`、`drug_concentration_unit` 等字段值。
*   针对核心数据提取逻辑，编写单元测试或集成测试，确保在不同数据场景下，能准确解析并提取出注册申报所需的 `adverse_event_code`、`study_design_type` 等信息，核对数据类型和单位。
*   监控外部接口的调用日志和响应时间，观察是否有异常的 `requestTimeout` 或 `maxRetries` 行为，以确定接口配置是否稳定。
