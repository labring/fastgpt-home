# 自身免疫注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样

自身免疫疾病注册申报资料的数据来源广泛，包括临床试验数据、非临床研究报告、生产工艺与质量控制文件、药理毒理报告、以及已发表的学术文献等。这些数据更新频率不一，临床试验数据在试验进行过程中会持续产生，而生产工艺文件相对稳定，仅在变更时更新。文档结构通常高度标准化，遵循各国药监机构（如 FDA、EMA、NMPA）的指导原则，例如 ICH M4E 格式。数据字段涉及药物活性成分、剂型、适应症、用法用量、不良反应、药代动力学参数、免疫原性指标等，单位严格统一，如剂量单位毫克（mg）、浓度单位微摩尔/升（µmol/L）、时间单位小时（h）等。部分数据涉及复杂的免疫学指标，如细胞因子水平、自身抗体滴度等，其解读需要专业背景。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

自身免疫疾病注册申报资料的高度标准化与多源性对 HTTP 接口集成提出特定要求。首先，数据来源的多样性要求接口能够灵活对接不同类型的数据系统，例如临床试验管理系统（CTMS）、实验室信息管理系统（LIMS）以及内部文档管理系统。其次，严格的文档结构要求接口在数据抽取和转换时，必须精确映射到 ICH M4E 等规范定义的字段，确保合规性。数据更新频率的不一致性，例如临床数据的高频更新与生产数据的低频更新，需要接口支持增量同步和定时全量同步相结合的机制。最后，免疫学指标的专业性和单位的严格性，要求接口具备强大的数据校验能力，识别并纠正不符合规范的数据，例如剂量单位错误或免疫学指标超出合理范围的情况，以避免生成错误的申报内容。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `300 秒` | 应对大型临床报告或复杂免疫学数据传输的耗时，避免因超时中断。 |
| `MAX_BODY_SIZE_MB` | `200 MB` | 考虑到包含高分辨率图片或大量表格的非临床研究报告文件大小。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 处理PDF格式的药理毒理报告中嵌入的图表和复杂文本结构。 |
| `maxContext` | `8000 字符` | 确保能够捕获自身免疫病理机制描述、临床试验结果解读等长文本上下文。 |
| `分段长度` | `500–800 字符` | 在保留语义完整性的前提下，优化免疫学实验方法和结果的索引效率。 |
| `相似度阈值` | `0.75` | 确保召回的法规条款或相似案例与当前申报资料的免疫学细节高度相关。 |

## 容易做错的三处

- 现象：外部系统返回 504 Gateway Timeout 错误码，或接口调用长时间无响应。原因：未针对大数据量文件上传或复杂数据处理设置足够的 `HTTP_REQUEST_TIMEOUT_SECONDS`。
- 现象：从外部导入的文档内容在知识库中出现乱码或格式错乱。原因：未正确配置 `PARSE_FILE_ENCODING` 或 `FILE_TYPE_PARSER_CONFIG`，导致文件解析器无法正确识别特定格式的自身免疫研究报告。
- 现象：知识库训练订单长时间处于待处理状态，或训练失败。原因：知识库中 `UPLOAD_FILE_MAX_SIZE` 参数限制过小，无法处理包含大量图表和表格的自身免疫临床试验报告。

## 怎么确认配好了

- 调用接口成功上传一份包含自身免疫标志物数据的 PDF 文档，检查知识库中该文档的内容解析是否完整无误，特别是免疫学指标和单位是否正确识别。
- 模拟外部系统接口调用，上传一份大于 100 MB 的非临床安全性评价报告，验证 `HTTP_REQUEST_TIMEOUT_SECONDS` 和 `MAX_BODY_SIZE_MB` 配置是否能支撑大文件传输和处理。
- 创建一个包含复杂药理学机制描述的训练订单，观察订单状态变化，确保 `PARSE_FILE_TIMEOUT_SECONDS` 能覆盖其内容解析时间。
