# 药物警戒注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样

药物警戒注册申报资料主要包含不良事件报告、安全性更新报告、风险管理计划等。数据来源多样，包括临床试验数据、上市后监测数据、文献回顾以及真实世界数据。这些数据更新频率较高，特别是上市后监测数据，可能涉及持续的事件报告。文档结构通常遵循ICH E2B、CIOMS I等国际标准格式，数据字段标准化程度较高，例如不良事件描述、药物信息、患者人口统计学信息、事件发生/结束日期、因果关系判断等。单位则严格按照医学和药学规范，如剂量单位 mg、μg，时间单位天、周、月等。数据量可能庞大，且包含大量非结构化文本描述。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

药物警戒数据的多源性和高更新频率，要求HTTP接口具备高并发处理能力和实时或近实时的同步机制。标准化的文档结构和字段，使得接口设计时需要严格遵循特定的数据模型，例如JSON Schema或XML Schema，以确保数据的准确解析和传输。非结构化文本的存在，则对接口的输入参数长度和编码格式提出要求，需支持UTF-8编码及较长的文本字段。此外，由于数据的敏感性，接口的安全认证和传输加密（如TLS）是强制性的，以符合数据隐私保护法规。数据量庞大可能导致单次请求响应时间过长或数据分块传输的需求，需要接口支持分页或流式传输。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `requestTimeout` | `60000 ms` | 确保处理复杂查询和大量数据上传时有足够响应时间 |
| `contentType` | `application/json` 或 `application/xml` | 符合ICH E2B等标准的数据交换格式 |
| `maxPayloadSize` | `10 MB` | 适应包含非结构化文本和附件的较大报告文件 |
| `authMethod` | `Bearer Token` 或 `OAuth2` | 提供安全的身份验证机制，符合数据安全规范 |
| `retryCount` | `3` | 应对网络瞬时波动或外部系统短暂不可用，提高数据传输可靠性 |
| `tlsVerify` | `true` | 确保通信链路加密和服务器身份验证，防止中间人攻击 |

## 容易做错的三处

*   HTTP 请求返回 `tls: failed to verify certificate`。这通常是由于外部系统的TLS证书无效、过期或未被FastGPT运行环境信任链识别。
*   接口调用成功但返回数据字段为空或格式错误。这可能是因为请求参数与外部系统期望的数据模型不符，例如字段名拼写错误或数据类型不匹配。
*   长时间等待后请求超时。这可能源于外部系统处理能力不足、网络延迟较高，或者接口设计时未考虑数据量过大导致的处理时间。

## 怎么确认配好了

*   使用标准的API测试工具，发送符合ICH E2B或CIOMS I规范的最小数据集，检查HTTP响应状态码是否为 `200 OK`。
*   验证从外部系统获取的关键药物警戒数据字段，例如 `adverseEventTerm` 和 `patientAgeUnit`，其值和单位是否与预期一致。
*   通过模拟高并发请求，评估接口在数据量高峰期的响应时间和稳定性，确保 `requestTimeout` 设置合理。
*   检查FastGPT工作流中对返回数据的解析逻辑，确保所有必需字段都能正确提取并用于后续处理。
