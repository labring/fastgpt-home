# 血液肿瘤注册申报资料准备的工具调用与插件

## 这个品类的数据长什么样

血液肿瘤注册申报资料涉及的数据类型多样，主要包括临床试验报告、药学研究数据、非临床研究报告、药物警戒数据和生产工艺文件。这些数据通常来源于全球多中心临床试验、实验室研究以及药企内部质量控制体系。数据更新频率不一，临床试验数据在试验进行期间会阶段性更新，药学和生产工艺数据则在研发和变更时更新。文档结构以 ICH M4 Common Technical Document (CTD) 格式为主，涵盖模块 1 到模块 5。字段方面，常见的有患者入组标准、疗效指标（如完全缓解率 `CR`、总生存期 `OS`）、不良事件（`AE`）编码（如 MedDRA 术语）、药物剂量 `mg/kg`、单位 `ng/mL`、`IU/mL` 等。

## 这些特征在「工具调用与插件」这一环带来什么约束

血液肿瘤注册申报资料的复杂数据特征对工具调用与插件提出了特定约束。首先，CTD 格式要求严格的文档结构，这意味着工具在抽取信息时需要具备强大的结构化识别能力，避免跨模块信息混淆。其次，数据来源多样且更新频率不一，要求插件能够适配不同的数据接口和更新机制，例如定期从 `EDC` 系统同步临床数据，或根据文件上传触发药学数据解析。再者，疗效指标、不良事件编码等专业字段和单位，需要工具能准确识别并进行语义理解，以支持后续的合规性校验和风险评估。最后，高敏感性数据（如患者隐私信息）的存在，要求工具在调用过程中严格遵循数据安全和脱敏规范，防止信息泄露。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `tool_selection_strategy` | `auto_with_fallback` | 优先 AI 自动识别工具，失败时回退至预设规则，适应复杂查询与专业术语 |
| `max_tool_execution_time` | `300 秒` | 多数结构化数据提取和 API 调用可在该时间内完成，避免长时阻塞 |
| `response_parsing_template` | `JSON with schema validation` | 确保提取的临床数据和不良事件信息符合预期格式，便于后续处理 |
| `external_api_timeout` | `60 秒` | 针对外部数据库查询或文献检索，平衡响应速度与数据完整性 |
| `document_chunk_size` | `1024 字符` | 优化血液肿瘤 CTD 文档中段落与表格的语义完整性，减少信息截断 |
| `meddra_version` | `26.0` | 确保与当前注册申报指南中不良事件编码的最新版本一致性 |

## 容易做错的三处

*   调用外部数据库接口时频繁出现 `HTTP 401 Unauthorized` 错误，原因在于 API 密钥过期或权限配置不当。
*   临床试验报告中的疗效数据字段 `CR_rate` 提取为空，原因在于文档中该字段的表述多样或存在非标准缩写，未在工具配置中充分覆盖。
*   插件在处理大型 PDF 文档时频繁超时，原因在于 `PARSE_FILE_TIMEOUT_SECONDS` 参数设置过低，未能适应血液肿瘤资料动辄数百页的文档体积。

## 怎么确认配好了

*   通过模拟提交包含常见血液肿瘤相关查询的请求，观察工具调用日志，确认 `tool_name` 字段与预期调用的工具名称一致。
*   针对不同模块的 CTD 文档，执行数据抽取任务，检查输出结果中的关键字段（如 `patient_id`、`AE_term`、`drug_dose`）是否完整且格式正确。
*   在集成测试环境中，多次触发外部 API 调用，监控 `response_time` 和 `status_code`，确保接口响应稳定并在 `external_api_timeout` 阈值内返回 `200 OK`。
*   上传一份包含复杂表格和图表的血液肿瘤申报资料 PDF，验证 `document_chunk_size` 配置下，工具是否能有效解析内容而无明显信息丢失。
