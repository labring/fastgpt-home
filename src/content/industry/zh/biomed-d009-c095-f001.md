# 质量文档管理注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样

生物医药领域的质量文档，主要包括 SOP（标准操作规程）、批生产记录、检验方法、稳定性报告、偏差处理报告、变更控制文件等。这些文档的来源通常是企业内部的质量管理系统（QMS）、实验室信息管理系统（LIMS）以及电子批记录系统（EBR）。更新频率相对较低，通常遵循严格的变更控制流程，年度审核或根据法规要求、工艺变更触发更新。文档结构严谨，常采用 PDF、Word 或专门的 XML 格式。字段方面，包含版本号、生效日期、修订历史、批准人、执行人、产品批次、检测结果、单位（如 `mg/mL`、`IU/mg`、`%`、`pH` 值）等。数据特征强调溯源性、完整性和合规性。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

质量文档的低更新频率意味着无需频繁进行全量数据同步，增量更新机制更为高效。严格的文档结构要求接口设计时需精确映射文档内的关键字段，确保信息提取的准确性，特别是版本号和批准日期等合规性强的数据。字段与单位的标准化，强制要求外部系统在数据传输和解析时，对特定单位进行校验或转换，避免因单位不匹配导致的数据误解。溯源性要求使得每一次文档获取或状态更新，都需要记录详细的请求日志，包括操作用户、时间戳和变更内容。此外，由于文档内容通常较大，接口需要支持大文件传输和分块处理，同时对传输过程中的数据完整性（如 MD5 校验）有较高要求。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `HTTP_TIMEOUT_SECONDS` | `300 秒` | 质量文档文件较大，传输和解析耗时较长，需要预留充足的超时时间 |
| `MAX_FILE_SIZE_MB` | `50 MB` | 兼顾常见文档大小与传输效率，支持单份大型文档上传 |
| `CHUNK_SIZE_KB` | `1024 KB` | 大文件分块传输，提高传输稳定性，降低单次请求失败的风险 |
| `AUTH_HEADER` | `Bearer Token` | 基于行业对数据安全的严格要求，采用强认证机制 |
| `PARSE_DOCUMENT_TYPE` | `PDF, DOCX, XML` | 覆盖最常见的质量文档格式，确保解析兼容性 |
| `VERSION_FIELD_NAME` | `documentVersion` | 确保能够准确识别和提取文档的关键版本信息 |

## 容易做错的三处

*   现象：API 调用返回 `401 Unauthorized` 或 `403 Forbidden`。原因：`AUTH_HEADER` 中的认证凭证过期或不正确。
*   现象：上传文档后，系统显示文档内容为空或解析失败。原因：`PARSE_DOCUMENT_TYPE` 未包含该文档格式，或文档结构与预期不符导致解析器无法正确提取内容。
*   现象：外部系统拉取文档列表时，部分文档未被同步。原因：增量同步逻辑中，`LAST_SYNC_TIMESTAMP` 未正确更新或外部系统在指定时间段内未记录所有变更。

## 怎么确认配好了

*   通过调用外部系统提供的健康检查接口，验证连接状态和认证凭证的有效性。
*   上传一份包含标准字段和单位的测试质量文档，检查系统能否正确解析其版本号、生效日期和关键检测结果。
*   模拟一次文档更新操作，观察外部系统是否能通过接口接收到更新通知，并同步最新版本的文档内容。
*   执行一次大文件上传，检查 `HTTP_TIMEOUT_SECONDS` 和 `MAX_FILE_SIZE_MB` 配置是否能支持完整传输，并确认文件完整性（例如通过比对文件哈希值）。
