# 院感管理注册申报资料准备的HTTP 接口与外部系统

## 这个品类的数据长什么样
院感管理注册申报资料的数据特点鲜明。数据源头通常包括医院内部信息系统（HIS、LIS、PACS）、微生物实验室系统、感染控制监测平台以及少量外部公共卫生数据。数据更新频率相对稳定，日常监测数据通常按日或按周更新，而年度报告或特定事件报告则有其固定周期。文档结构以结构化数据为主，例如感染病例报告、抗菌药物使用记录、病原体检出率等，但也包含非结构化数据，如调查报告、专家意见。字段方面，涉及患者 ID、感染部位、病原体名称、耐药情况、用药方案、消毒措施等，单位则涵盖数量（例：`例`、`次`）、百分比（例：`%`）、时间（例：`天`、`小时`）以及微生物学单位（例：`CFU/mL`）。这些数据需要严格遵循医疗行业的隐私和安全规范。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
院感管理数据的高度敏感性决定了 HTTP 接口在身份验证和数据加密上的严格要求。例如，患者 ID 等敏感信息需要进行脱敏处理，或者通过加密传输保证安全。数据更新的周期性要求接口具备定时拉取或事件触发的能力，以确保申报资料的时效性。结构化与非结构化数据并存的特点，使得接口设计需要同时支持 JSON 或 XML 等结构化数据格式，以及文件上传或文本嵌入等非结构化数据处理方式。特别是微生物学单位和特定医学术语的标准化，要求接口在数据解析和字段映射上具备高度的准确性，避免因单位不一致或术语歧义导致数据错误。同时，考虑到数据量可能较大，接口应支持分页查询和增量更新，以优化传输效率。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `REQUEST_TIMEOUT` | `60 秒` | 多数院感数据查询响应时间在此范围内，避免长时间等待。 |
| `MAX_RETRIES` | `3 次` | 应对临时性网络波动或服务瞬时不可用，确保数据拉取成功率。 |
| `AUTH_HEADER_NAME` | `Authorization` | 行业通用标准，便于与各类认证系统对接。 |
| `API_KEY_ENV_VAR` | `FASTGPT_API_KEY_IC` | 明确区分不同业务场景的 API 密钥，提高安全性。 |
| `DATA_PARSING_SCHEMA` | 按实际接口文档定义 JSON Schema | 确保结构化数据字段与类型正确解析，例如 `patientId` 为字符串，`infectionDate` 为日期格式。 |
| `RATE_LIMIT_DELAY` | `500 毫秒` | 遵守外部系统接口调用频率限制，避免触发限流。 |

## 容易做错的三处
*   调用外部接口时收到 `HTTP 401 Unauthorized` 错误码，现象是无法获取任何数据。原因通常是 `Authorization` 请求头中的 API 密钥或 Token 配置有误，或者已过期。
*   接口返回的 JSON 响应中，部分关键字段如 `pathogenName` 为空值或格式异常，现象是数据解析失败。原因在于外部系统返回的数据格式与预期的 `DATA_PARSING_SCHEMA` 不符，可能存在字段名不一致或数据类型不匹配的问题。
*   数据拉取速度缓慢，甚至出现 `REQUEST_TIMEOUT` 错误，现象是数据更新不及时。原因可能是未正确配置分页参数或未启用增量更新机制，导致单次请求数据量过大。

## 怎么确认配好了
*   执行一次完整的接口调用流程，检查 HTTP 响应状态码是否为 `200 OK`，并确保返回数据结构与预期一致。
*   随机抽取多条返回数据，核对关键字段（如 `patientId`、`infectionDate`、`pathogenName`）的值与单位，确认其准确性与标准化程度。
*   模拟数据更新场景，观察接口的拉取与处理速度，并根据实际业务需求确定是否满足时效性阈值。
