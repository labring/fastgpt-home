# 医保结算研发文档结构化解析的部署与升级

## 这个品类的数据长什么样

医保结算研发文档主要包括政策法规文本、结算细则、药品目录（如国家医保目录、各省增补目录）、诊疗项目目录、服务设施收费标准、费用计算公式、以及相关的解释性文件和常见问题解答。这些文档的来源通常是政府机构（国家医保局、省级医保部门）的官方网站发布，更新频率较高，如国家医保目录通常每年调整一次，地方政策可能根据实际情况不定期更新。文档结构多为层级分明的法律条文、列表、表格，包含大量专业术语、药品通用名、疾病诊断编码（如 ICD-10）、医疗服务项目编码、金额单位（元）、比例（%）等字段。文档格式以 PDF 居多，部分为 Word 或 Excel。

## 这些特征在「部署与升级」这一环带来什么约束

医保结算文档的更新频率和复杂结构对部署与升级提出了特定要求。首先，高频的政策更新意味着知识库需要具备高效的版本管理和增量更新能力，以确保信息时效性。其次，文档中大量的表格数据、编码信息和计算公式，要求结构化解析器能够准确识别并提取这些关键实体，避免数据丢失或解析错误。特别是 PDF 格式文档中的复杂排版，可能导致文本提取不完整或乱码，进而影响后续的语义理解和检索效果。因此，在升级过程中，需要重点关注解析模块对新版本文档格式的兼容性，并对历史数据进行有效迁移，确保知识库的连续性和准确性。数据源的权威性要求部署环境具备稳定的外部数据接口访问能力，并对数据完整性进行校验。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 医保政策文档通常包含大量图片和复杂排版，单个文件体积可能较大。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大文件解析和复杂表格识别耗时较长，需要更长的超时时间。 |
| `分段长度` | `800–1200 字符` | 医保政策条款逻辑严密，较长的分段有助于保持语义完整性，避免关键信息被截断。 |
| `召回条数` | `前 5 条` | 医保结算查询对准确性要求高，适当增加召回条数可提高相关性。 |
| `相似度阈值` | `0.75` | 医保术语专有名词较多，提高阈值有助于过滤不相关的结果。 |
| `maxContext` | `4000 token` | 复杂的医保结算问题需要较长的上下文窗口进行推理。 |

## 容易做错的三处

*   升级后部分医保政策条款的查询结果不准确，现象为返回内容缺失关键数字或条件。原因在于新版本解析器对特定 PDF 布局的表格或多栏文本识别不完全，导致结构化数据提取失败。
*   系统升级后，原有的医保药品编码查询功能响应变慢，甚至出现 504 Gateway Timeout 错误。原因在于数据库迁移过程中，索引未正确重建或优化，导致对大型药品目录表的查询效率显著下降。
*   部署新版本 FastGPT 后，日志中出现 `invalid version string` 错误。原因在于安装包版本与实际运行环境版本不匹配，或在手动配置 `config.json` 时，版本号字符串格式有误。

## 怎么确认配好了

*   上传典型包含复杂表格和多级标题的医保政策 PDF 文档，检查知识库中分段内容是否完整，关键字段（如药品名称、编码、报销比例）是否被正确识别。
*   针对医保结算中的常见问题，如“某药品在特定情况下的报销比例是多少？”，进行多轮提问测试，评估回答的准确性、完整性与响应速度。
*   检查系统日志，确保没有出现 `PARSE_FILE_TIMEOUT` 或 `data integrity check failed` 等与数据解析和完整性相关的错误信息。
*   通过 FastGPT 管理界面，查看当前部署版本号是否与预期升级版本号（例如 `4.8.20`）一致，并检查系统健康状态指标是否正常。
