# 双特异性抗体研发文档结构化解析的对话日志与审计

## 这个品类的数据长什么样

双特异性抗体（BsAb）研发文档的数据来源多样，包括内部实验报告、临床试验方案、专利文献、生物信息学分析结果以及药学研究数据。这些文档的更新频率取决于研发阶段，从早期研究的每周更新到临床阶段的每月或每季度更新不等。文档结构通常包含预临床数据、CMC（化学制造与控制）信息、药代动力学、药效学、毒理学研究结果及临床试验数据。字段涉及靶点识别、抗体设计序列、结合亲和力（如 `KD` 值，单位 nM）、细胞株构建、生产工艺参数（如发酵罐体积，单位 L）、纯化收率（单位 %）、稳定性数据（如降解率，单位 %/月）和生物活性（如 IC50，单位 nM）。

## 这些特征在「对话日志与审计」这一环带来什么约束

BsAb 研发文档的复合性对对话日志的记录粒度提出了要求，需要能够追溯到具体的实验批次或序列信息。高更新频率意味着知识库内容可能快速迭代，对话日志需记录查询时所依赖的知识版本，确保审计的可复现性。文档中包含的敏感序列数据和未公开的实验结果，要求日志具备严格的访问控制和匿名化处理能力，防止信息泄露。此外，BsAb 研发中的专业术语和缩写众多，对话日志应能正确识别并记录这些实体，避免歧义。字段与单位的标准化也影响审计的准确性，日志需能区分不同度量衡下的数值差异，例如 nM 与 µM。

## 配置怎么定

| 配置项                   | 建议取法                                      | 这样取的依据                                                 |
| :----------------------- | :-------------------------------------------- | :----------------------------------------------------------- |
| `logRetentionDays`       | `365 天`                                      | 满足研发项目全生命周期的追溯需求，覆盖多年期临床试验周期。 |
| `maxLogEntrySize`        | `2048 字符`                                   | 适应包含抗体序列、实验条件等详细信息的长文本记录。         |
| `anonymizeSensitiveFields` | `true`                                        | 保护未公开的靶点信息、专利序列及患者数据。                 |
| `knowledgeVersionTag`    | `按知识库快照版本号`                          | 确保对话审计时能精确回溯到当时的知识状态。                 |
| `timestampGranularity`   | `毫秒`                                        | 精确记录实验数据查询与更新的时间顺序，便于问题排查。       |
| `entityRecognitionModels` | `bsab_specific_ner_v2.0`                      | 提升对 BsAb 相关专业术语、缩写及字段的识别准确性。         |

## 容易做错的三处

*   对话记录中部分关键数值或序列为空白，原因在于知识库解析时未正确识别文档中的字段。
*   审计时无法复现特定对话的结果，原因在于对话日志未记录查询时所依赖的知识库版本。
*   系统返回 `HTTP 403 Forbidden` 错误，原因在于日志存储配置未正确设置访问权限，导致敏感数据泄露风险。

## 怎么确认配好了

*   核对任意一条对话日志，检查其中是否包含查询所涉及的抗体序列、靶点信息及关键实验参数。
*   选择一个历史对话，尝试使用日志中记录的知识库版本进行复现，比对结果一致性。
*   模拟一次包含敏感信息的查询，检查日志中相应的字段是否已被匿名化处理或脱敏。
*   检查日志存储位置的访问控制列表（ACL），确保只有授权用户和系统服务具备读写权限。
