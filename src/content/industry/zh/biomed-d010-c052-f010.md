# 干细胞治疗研发文档结构化解析的数据库与运维

## 这个品类的数据长什么样

干细胞治疗的研发文档数据主要来源于临床前研究报告、临床试验方案、伦理审查文件、生产工艺规程、质量控制记录以及监管申报资料。这些文档的更新频率高，尤其在临床试验阶段，协议修订、数据补充、安全性报告等会频繁产生。文档结构复杂，包含大量非结构化文本、表格、图片和嵌入式图表。其中，关键字段包括细胞来源、培养条件、给药途径、剂量、受试者特征、不良事件、疗效指标及其单位（如 `细胞数/kg`、`治疗周期`、`疾病缓解率 %`）。数据多以 PDF、Word、Excel 等格式存在，通常存储在内部文件服务器或专门的文档管理系统。

## 这些特征在「数据库与运维」这一环带来什么约束

高更新频率要求数据库支持高效的增量更新与版本管理，避免重复解析和存储冗余数据。文档的复杂结构和多模态内容，使得传统文本数据库难以直接存储和检索，需要引入向量数据库或支持多模态数据索引的混合存储方案。关键字段的准确提取和标准化是结构化解析的核心，对 FastGPT 的实体识别与关系抽取能力提出挑战，需要精细配置解析模型。大规模文档解析可能导致计算资源消耗剧增，对运维侧的资源调度和并发处理能力提出要求。此外，数据合规性与安全性在生物医药领域至关重要，数据库的访问控制、加密存储和备份策略必须严格。

## 配置怎么定

| 配置项                   | 建议取法                                 | 这样取的依据                                                                                       |
| :----------------------- | :--------------------------------------- | :------------------------------------------------------------------------------------------------- |
| `UPLOAD_FILE_MAX_SIZE`   | `200 MB`                                 | 干细胞治疗文档通常包含大量图片和图表，文件体积较大，需要更高的上传限制。                           |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`                                 | 复杂 PDF 和 Word 文档解析耗时较长，防止因超时导致解析失败。                                        |
| `分段长度`               | `800–1200 字符`                          | 确保每个分段包含足够的上下文信息，同时避免单个分段过长影响召回效率和生成质量。                   |
| `召回条数`               | `前 10 条`                               | 确保覆盖到多个相关段落，特别是针对复杂问题，能够提供更全面的信息。                               |
| `相似度阈值`             | `0.75`                                   | 医药领域对信息准确性要求高，较高的阈值有助于过滤掉不相关或弱相关的结果。                         |
| `maxContext`             | `16000 tokens`                           | 应对复杂查询和多文档交叉验证场景，提供足够长的上下文窗口以支持深度理解和推理。                   |

## 容易做错的三处

*   解析任务频繁失败并报 `PARSE_FILE_TIMEOUT_SECONDS` 错误，原因是文档内容复杂或文件损坏，`PARSE_FILE_TIMEOUT_SECONDS` 参数设置过低未能覆盖实际解析所需时间。
*   知识库内容更新后，查询结果仍包含旧信息，原因是没有启用版本控制或增量更新机制，导致数据库中存在数据不一致。
*   数据库连接错误或 `init root user` 失败，原因是 Docker 部署环境下，FastGPT 容器与数据库容器之间的网络配置问题，或者数据库凭证信息不正确。

## 怎么确认配好了

*   上传一份包含复杂表格和图表的干细胞治疗临床试验报告 PDF，确认文件能够成功上传、解析并生成知识库分段。
*   对知识库进行查询，提问一个需要综合多个文档才能回答的问题，检查返回的召回条目是否准确、全面，并且与预期结果高度相关。
*   执行一次知识库的增量更新操作，修改部分原始文档内容后再次导入，然后查询修改过的部分，验证数据库内容已正确同步。
*   通过 `docker logs` 命令检查 FastGPT 容器和数据库容器的日志输出，确保没有持续性的连接错误或异常警告信息。
