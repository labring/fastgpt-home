# 药物经济学研发文档结构化解析的对话日志与审计

## 这个品类的数据长什么样

药物经济学研究文档主要来源于临床试验报告、真实世界研究数据、卫生技术评估报告、药物上市申请材料以及各类学术论文。这些文档的更新频率相对较低，通常随药品研发阶段进展或政策法规调整而变化，一般为季度或年度更新。文档结构复杂，包含大量表格、图表和文本描述，涉及成本（直接成本、间接成本）、效果（QALY、DALY）、效用、时间折扣率、敏感性分析参数等关键字段。单位多样，如货币单位（美元、欧元、人民币）、时间单位（年、月）、比率（百分比）、生命质量调整生命年（QALY）等，且常出现简写和专业术语。

## 这些特征在「对话日志与审计」这一环带来什么约束

药物经济学文档的复杂结构和多样化单位，要求对话日志能精确记录解析过程中对表格和图表的识别情况，以及对不同单位的标准化处理结果。低更新频率意味着历史日志的长期可追溯性更为重要，便于比对不同版本文档的解析差异。专业术语和简写的大量存在，对语义理解的准确性提出挑战，日志需详细记录模型在术语消歧和概念映射上的决策路径，以便审计其合理性。此外，成本效益分析中的数值计算和逻辑推理步骤也需要日志进行细致的记录，确保审计人员能完整复现AI的决策过程，验证其符合药物经济学评估规范。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `LOG_LEVEL` | `INFO` | 记录关键操作和结果，便于日常监控和问题定位。 |
| `AUDIT_LOG_RETENTION_DAYS` | `365 天` | 适应药物经济学文档更新周期长，需长期追溯历史解析记录的需求。 |
| `PARSE_TABLE_STRUCTURE` | `true` | 药物经济学文档表格众多，确保表格结构能被准确解析并记录。 |
| `EXTRACT_UNIT_MAPPING` | `true` | 确保货币、时间等单位的标准化映射过程被记录，方便审计单位转换的准确性。 |
| `MAX_LOG_MESSAGE_LENGTH` | `8192 字符` | 适应药物经济学文档解析过程中可能产生的长文本描述和复杂结构信息。 |
| `ENABLE_DIAGNOSTIC_LOGS` | `按实测标定` | 在初期部署和优化阶段开启，用于捕获更详细的内部执行细节，稳定后可关闭。 |

## 容易做错的三处

*   日志中缺少关键字段的解析结果，例如成本或效果的数值为空，原因在于文档解析模型未能正确识别表格或文本中的特定字段。
*   审计日志中出现 `TypeError: Cannot read properties of undefined` 错误，通常是由于自定义插件在工作流中未正确配置输入输出参数，导致数据流转中断。
*   对话日志复制按钮点击后无反应，表现为前端交互问题，可能与前端脚本加载失败或事件绑定异常有关，需检查浏览器控制台报错。

## 怎么确认配好了

*   检查日志系统，确认 `LOG_LEVEL` 设置为 `INFO` 后，核心解析步骤的日志信息能被完整记录。
*   随机抽取一份药物经济学文档，通过平台解析后，在审计日志中核对关键数值（如 QALY 值、成本）及其单位是否与原文一致，且单位转换过程有记录。
*   模拟一次解析失败场景（例如上传一个损坏的 PDF 文件），检查日志中是否有对应的错误信息记录，并确认错误码和堆栈信息是否清晰。
*   定期检查日志存储空间占用情况，确保 `AUDIT_LOG_RETENTION_DAYS` 的设置与实际存储策略相符，避免存储溢出或日志过早被清理。
