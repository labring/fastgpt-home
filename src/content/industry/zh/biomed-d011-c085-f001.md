# 线索同步私域咨询转化的HTTP 接口与外部系统

## 这个品类的数据长什么样

生物医药行业的线索同步，通常指从各类市场活动、线上平台或合作渠道获取的潜在客户信息。这些数据以结构化形式为主，例如 JSON 或 XML 文档，包含姓名、联系方式、意向产品、咨询时间、来源渠道等字段。数据更新频率较高，可能根据活动实时产生，或按日、小时批量同步。字段名称常包含行业特有缩写，如 `patientID`、`drugCode`、`trialPhase`。联系方式字段可能涉及多维度，如手机号 `mobile`、邮箱 `email`，以及微信 `wechatId`。意向产品字段通常是枚举值，对应具体的药品或服务，如 `product_A_therapy`。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

线索数据的高实时性要求 HTTP 接口具备低延迟和高可用性，以确保新线索能迅速进入私域咨询流程。其结构化的数据特性决定了接口设计需精准映射字段，避免数据丢失或解析错误。多样的来源渠道可能导致不同接口的数据格式存在细微差异，需要统一的适配层或多套接口配置。行业特有字段的存在，意味着在数据传输和存储时需要保留其语义，避免通用字段映射带来的信息失真。同时，由于涉及用户隐私，数据传输必须采用 HTTPS 加密，并对敏感字段进行脱敏处理，确保合规性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `HTTP_METHOD` | `POST` | 线索数据通常作为新资源创建或更新，POST 方法更符合语义。 |
| `CONTENT_TYPE` | `application/json` | JSON 格式轻量且易于解析，是当前主流的 API 数据交换格式。 |
| `REQUEST_TIMEOUT_SECONDS` | `10` | 确保接口在合理时间内响应，避免因网络延迟导致线索积压。 |
| `RETRY_COUNT` | `3` | 应对临时性网络波动或服务瞬时不可用，提高线索同步成功率。 |
| `MAX_PAYLOAD_SIZE_MB` | `2` | 限制单次请求体大小，防止超大请求影响接口性能或被服务器拒绝。 |
| `AUTH_HEADER` | 按实测标定 | 根据外部系统要求的认证机制配置，例如 `Bearer Token` 或 `Basic Auth`。 |

## 容易做错的三处

*   外部系统返回 `HTTP 500 Internal Server Error`，但 FastGPT 侧未能有效捕获具体错误信息。这通常是由于外部接口的错误响应体未按预期格式返回，导致 FastGPT 无法解析。
*   线索数据同步后，外部系统部分关键字段为空或值不正确。原因在于 FastGPT 的 HTTP 请求体字段名与外部系统接口要求不匹配，或者数据类型转换不正确。
*   同步请求频繁超时，导致大量线索积压或丢失。这可能是外部系统接口处理能力不足，或 FastGPT 发送请求的并发数过高，未进行合理的限流。

## 怎么确认配好了

*   通过 FastGPT 的调试日志，检查 HTTP 请求的 `URL`、`Header` 和 `Body` 是否与外部系统接口文档一致。
*   在 FastGPT 中手动触发一次线索同步，并登录外部系统检查对应线索数据是否完整、准确地创建或更新。
*   模拟高并发场景，观察 FastGPT 的同步队列处理情况及外部系统接口的响应时间，确保在预期负载下接口稳定。
