# 线索同步私域咨询转化的表单与交互

## 这个品类的数据长什么样

生物医药领域的线索同步数据主要来源于各类学术会议注册、线上研讨会报名、行业报告下载、CRM 系统以及用户在官网或第三方平台留下的咨询表单。这些数据通常以结构化或半结构化的形式存在，更新频率从实时（如在线咨询表单提交）到每周或每月批量导入不等。文档结构方面，常见为 CSV、Excel 或 JSON 格式，包含字段如 `姓名`、`单位`、`职务`、`联系方式`（手机、邮箱）、`咨询产品`、`留言内容`、`线索来源`、`首次接触时间`等。其中，`咨询产品`字段可能包含药品名称、医疗器械型号或服务类型，并带有特定的内部编码或缩写；`留言内容`则通常是自由文本，长度不一，可能涉及复杂的专业术语。

## 这些特征在「表单与交互」这一环带来什么约束

线索同步数据的多样来源和更新频率，要求表单与交互设计具备高度的灵活性和实时性。例如，针对实时提交的在线咨询表单，需要确保数据能即时捕获，并触发后续的自动化流程。`留言内容`字段的自由文本特性，意味着表单需要提供足够的输入空间，并支持对文本内容的初步解析或分类。`咨询产品`字段的专业性和编码要求，使得前端表单可能需要提供下拉选择、模糊搜索或多选功能，以确保用户输入的准确性。同时，由于数据源可能涉及多个系统，交互设计需要考虑如何统一呈现和处理不同来源的线索信息，避免数据冗余或冲突，并支持管理员对数据进行清洗和标准化。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `2000 字符` | 适应生物医药领域线索留言中常见的详细咨询内容，确保上下文完整性。 |
| `表单提交超时` | `3000 毫秒` | 应对网络波动或后端处理复杂性，避免用户等待过久导致重复提交或放弃。 |
| `线索去重周期` | `7 天` | 兼顾线索新鲜度和避免短期内重复录入，减少资源浪费。 |
| `字段校验规则` | `按实测标定` | 针对 `联系方式`、`咨询产品` 等关键字段，确保数据格式符合业务规范。 |
| `API_KEY` | `按安全规范生成` | 用于与外部 CRM 或数据源系统进行集成时的身份认证，保障数据传输安全。 |
| `分段长度` | `500 字符` | 处理长篇 `留言内容` 时，优化知识库检索效率和准确性。 |

## 容易做错的三处

*   用户提交表单后未收到确认信息，或系统显示提交失败，但实际上数据已部分录入后端。这通常是由于前端提交状态与后端数据处理结果不同步，或者 `表单提交超时` 设置过短导致。
*   线索数据录入后，`咨询产品` 字段出现大量不规范或无法识别的自由文本。原因在于前端表单缺乏有效的输入限制或推荐选项，用户可以随意填写，导致数据标准化程度低。
*   知识库搜索中，选择知识库并引用变量时提示“没有可选值”。这可能是因为 `知识库关联字段` 未正确配置，或者知识库中的数据字段与表单提交的线索字段不匹配。

## 怎么确认配好了

*   模拟多种用户身份和输入场景，提交测试表单，检查所有字段数据是否完整、准确地同步到后端系统。
*   在 FastGPT 平台后台，检查线索数据对应的知识库检索日志，确认 `召回条数`、`相似度阈值` 等参数是否能有效匹配用户咨询。
*   核对 `线索去重周期` 内的重复提交行为，验证系统是否能正确识别并处理重复线索，避免无效录入。
*   随机抽取一批已同步的线索数据，与原始表单数据进行比对，确保 `姓名`、`单位`、`联系方式`、`咨询产品` 等关键字段的一致性。
