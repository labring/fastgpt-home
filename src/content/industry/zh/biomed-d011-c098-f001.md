# 跟进提醒私域咨询转化的HTTP 接口与外部系统

## 这个品类的数据长什么样

生物医药领域私域咨询转化的跟进提醒数据，主要来源于企业内部的客户关系管理（CRM）系统、销售自动化（SFA）平台以及合规的在线问诊或咨询记录。数据更新频率通常为实时或准实时，例如客户咨询提交后立即生成跟进任务，或销售人员更新沟通记录后触发提醒。文档结构方面，数据通常以结构化 JSON 或 XML 格式存储，包含 `patient_id`（患者或咨询者唯一标识）、`consultation_id`（咨询会话ID）、`consultation_time`（咨询时间，ISO 8601格式）、`followup_due_date`（跟进截止日期）、`priority_level`（优先级，如“高”、“中”、“低”）、`assigned_agent`（负责跟进的AI或人工客服ID）以及 `consultation_summary`（咨询概要文本）等字段。时间字段通常精确到秒，优先级字段为枚举值。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

跟进提醒数据实时或准实时的更新频率，要求 HTTP 接口具备高可用性和快速响应能力，以避免提醒延误。结构化的数据格式简化了 FastGPT 对传入数据的解析，但需要精确映射 `patient_id`、`consultation_id` 等关键业务标识符，确保提醒的准确性和唯一性。文本字段 `consultation_summary` 的存在，意味着接口需要能够处理可变长度的字符串，并可能涉及文本摘要或关键词提取，以便 FastGPT 更好地理解跟进背景。优先级字段 `priority_level` 决定了提醒的紧急程度，需要在接口调用时作为参数传递，并可能影响 FastGPT 内部的任务调度策略。此外，医药行业的合规性要求，如数据脱敏或加密，可能对 HTTP 请求头或正文的格式提出额外约束。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `HTTP Method` | `POST` | 跟进提醒通常涉及创建或更新数据，`POST` 方法更符合语义 |
| `Request URL` | `https://api.example.com/followup/reminders` | 明确指向外部系统用于接收跟进提醒的服务端点 |
| `Content-Type` | `application/json` | 外部系统数据通常为 JSON 格式，方便解析和处理 |
| `Timeout` | `6000 ms` | 兼顾网络延迟与外部系统处理时间，避免因等待过久而中断 |
| `Max Retries` | `3` | 应对外部系统瞬时故障，提高提醒发送的成功率 |
| `Rate Limit` | `100 requests/minute` | 匹配外部系统的API限流策略，防止因请求过载被封禁 |

## 容易做错的三处

*   HTTP 502 错误：原因在于 FastGPT 配置的代理或网关与外部目标服务之间的连接问题，可能是代理配置不正确或网络路由不通。
*   跟进提醒未按时触发：原因在于外部系统返回的数据中 `followup_due_date` 字段格式不符合预期，导致 FastGPT 解析失败或时间戳计算错误。
*   `assigned_agent` 字段为空：原因在于 HTTP 接口返回的 JSON 结构中缺少该字段，或字段路径映射不正确，导致 FastGPT 无法识别负责跟进的客服。

## 怎么确认配好了

*   在 FastGPT 界面中，手动触发一次跟进提醒，并通过外部系统的日志或数据库查询，确认是否收到数据且字段内容正确。
*   使用 FastGPT 的调试工具，检查 HTTP 请求的 `Request URL`、`HTTP Method` 和 `Content-Type` 是否与外部系统 API 文档一致。
*   模拟外部系统返回带有不同 `priority_level` 的跟进提醒，观察 FastGPT 中相关任务的优先级是否按预期设置。
*   通过 FastGPT 的请求历史，检查 HTTP 接口的响应状态码是否均为 `200 OK` 或其他表示成功的代码，并且响应体内容符合预期。
