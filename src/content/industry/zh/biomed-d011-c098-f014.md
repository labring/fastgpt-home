# 跟进提醒私域咨询转化的表单与交互

## 这个品类的数据长什么样

生物医药私域咨询转化的跟进提醒数据主要来源于内部 CRM 系统、线上问诊平台和患者教育活动记录。数据更新频率较高，通常为实时或准实时，例如新咨询的创建、跟进状态的变更、用户行为的触发等。文档结构以结构化数据为主，通常包含患者 ID、咨询时间、最近跟进时间、跟进内容摘要、建议提醒时间、提醒类型、触发条件和关联的咨询记录 ID 等字段。关键字段如 `patient_id` 采用统一编码，`consultation_id` 关联具体咨询，`due_date` 用于设定提醒时限，单位为日期或时间戳。`reminder_type` 字段可能包含“复诊提醒”、“用药指导”、“活动通知”等枚举值。

## 这些特征在「表单与交互」这一环带来什么约束

高频且实时的数据更新要求表单和交互设计能够快速响应，避免数据延迟导致提醒失效。结构化数据特性使得表单可以预设多种字段类型，减少人工输入错误，提高数据准确性。例如，`patient_id` 可以通过下拉选择或自动补全关联现有患者档案。提醒类型的多样性要求交互界面提供灵活的配置选项，支持不同触发条件和提醒内容。历史咨询记录的关联性则要求表单具备查询和引用历史数据的功能，例如在创建新的跟进提醒时，能够便捷地查阅患者过去的咨询详情。表单需要支持对 `due_date` 字段的日期选择器，并能根据 `reminder_type` 动态调整其他相关字段的可见性或必填性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `800` 字符 | 确保跟进内容摘要的完整性，同时控制模型输入长度 |
| `表单提交超时` | `30` 秒 | 应对网络波动和后端处理耗时，防止用户重复提交 |
| `历史记录召回条数` | `5` 条 | 在创建提醒时提供足够的上下文，避免信息过载 |
| `reminder_type` 预设值 | `复诊提醒`, `用药指导`, `活动通知` | 覆盖生物医药领域常见的跟进场景，便于快速选择 |
| `due_date_offset` 默认值 | `7` 天 | 对于一般性跟进，提供合理的默认提醒周期 |
| `webhook_retry_count` | `3` 次 | 确保提醒消息能够稳定送达外部系统 |

## 容易做错的三处

*   现象：创建跟进提醒后，外部系统迟迟未收到通知。原因：`webhook_url` 配置错误或外部系统接口响应超时。
*   现象：在表单中选择患者 ID 时，下拉列表加载缓慢或不显示完整。原因：后端查询接口未对患者数据进行分页或索引优化。
*   现象：用户提交跟进提醒表单时，反复提示“数据格式不正确”。原因：`due_date` 字段的日期格式校验规则与前端日期选择器输出格式不一致。

## 怎么确认配好了

*   通过实际创建不同类型的跟进提醒，检查 `webhook_url` 配置的外部系统是否按预期收到通知，并核对通知内容。
*   在表单中尝试搜索并选择不同数量级的患者 ID，观察加载速度和数据完整性，确保 `patient_id` 字段的交互流畅。
*   使用不同日期和时间格式填写 `due_date` 字段，提交表单后检查系统是否正确解析并存储，确认日期格式校验规则的有效性。
*   模拟网络延迟或后端服务中断情况，测试 `表单提交超时` 配置是否能按预期触发，并给出用户友好的提示。
