# CAR-T 细胞治疗药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

CAR-T 细胞治疗药物警戒的数据主要来源于临床试验报告、真实世界研究（RWE）、患者随访记录、医疗机构报告以及监管机构的上市后监测数据库。这些数据通常以结构化（如数据库记录、XML）、半结构化（如电子病历中的临床笔记、PDF 报告）和非结构化（如自由文本描述）形式存在。数据更新频率较高，尤其在上市初期和关键临床试验阶段。文档结构复杂，常包含患者基本信息、治疗方案、不良事件（AE）描述、严重程度、发生时间、结局、相关实验室检查结果及伴随用药等字段。特别的字段包括特定于细胞治疗的免疫效应细胞相关神经毒性综合征（ICANS）分级、细胞因子释放综合征（CRS）分级，以及 CAR-T 产品批次号、输注剂量、细胞活性等关键信息。单位涉及时间和剂量，例如 `天`、`小时`、`μg/kg`。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

CAR-T 细胞治疗数据的高更新频率要求 HTTP 接口支持高效的实时或准实时数据同步机制，例如基于时间戳的增量拉取或事件驱动的推送。复杂多样的文档结构意味着接口需要具备灵活的数据解析能力，以处理不同格式的输入，并能将半结构化和非结构化数据进行初步提取和标准化。特定于细胞治疗的 ICANS 和 CRS 分级字段，以及产品批次号等，需要在接口设计时明确定义其数据类型、枚举值或验证规则，确保数据传输的准确性和完整性。数据量通常较大，对接口的吞吐量和稳定性有较高要求。此外，涉及患者敏感信息，接口需严格遵循数据安全和隐私保护协议，例如 HTTPS 加密传输。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `60 秒` | 应对外部系统数据传输延迟，避免因短暂网络波动或处理耗时导致频繁超时。 |
| `MAX_RETRY_ATTEMPTS` | `3` | 允许在网络瞬时故障或外部系统短暂不可用时进行重试，提高数据同步成功率。 |
| `DATA_PULL_INTERVAL_MINUTES` | `15 分钟` | 平衡数据实时性与外部系统负载，适用于增量数据更新。 |
| `BATCH_SIZE_RECORDS` | `500` | 优化单次请求的数据量，降低外部系统处理压力，同时兼顾传输效率。 |
| `ERROR_NOTIFICATION_EMAIL` | `alert@yourdomain.com` | 确保接口失败时能及时通知相关人员介入处理。 |
| `AUTHENTICATION_METHOD` | `OAuth 2.0` | 提供安全的身份验证机制，保护数据传输的安全性。 |

## 容易做错的三处

*   HTTP 接口返回 `504 Gateway Timeout` 错误，因为外部系统处理复杂查询或返回大量数据时，未能及时响应。
*   部分不良事件报告字段为空，原因在于外部系统返回的数据结构与接口预期不符，或数据解析逻辑未能正确处理可选字段。
*   接口接收到数据后，关键的 ICANS 或 CRS 分级信息无法正确识别，这是由于接口未能针对 CAR-T 细胞治疗特有的分级体系进行适配。

## 怎么确认配好了

*   通过模拟请求调用 HTTP 接口，验证能够成功接收并解析至少包含一个 CAR-T 细胞治疗不良事件的完整报告数据。
*   检查日志系统，确认接口在不同数据量和网络条件下，没有出现 `HTTP_REQUEST_TIMEOUT_SECONDS` 设置值以外的超时错误。
*   核对成功导入的数据，随机抽取 10 条记录，检查其 ICANS 分级、CRS 分级、CAR-T 产品批次号等关键字段是否准确无误地映射到 FastGPT 知识库中，并与原始数据一致。
