# CDMO药物警戒的工具调用与插件

## 这个品类的数据长什么样

CDMO（合同研发生产组织）在药物警戒领域的数据，主要来源于其承接的临床试验或上市后药物的监测活动。数据类型包括不良事件（AE）报告、严重不良事件（SAE）报告、药物安全数据库记录、临床研究报告、病例报告表（CRF）数据以及相关医学文献。这些数据通常以结构化（如数据库字段）和非结构化（如自由文本描述）形式并存。数据更新频率取决于项目的阶段和监管要求，临床试验期间可能每日或每周更新，上市后监测则依据报告发生频率。文档结构遵循ICH E2B等国际标准，字段包含患者信息、药品信息、事件描述、预后和因果关系评估等，单位涉及剂量（mg、g）、频率（次/日、周）、时间（天、月、年）等。

## 这些特征在「工具调用与插件」这一环带来什么约束

CDMO药物警戒数据的特性对工具调用与插件提出了具体约束。数据来源的广泛性和结构化与非结构化并存，要求插件具备多源数据集成和自然语言处理能力，以从自由文本中提取关键信息。高更新频率，特别是临床试验期间的每日更新，需要工具调用支持高并发和实时数据同步，确保模型基于最新数据进行判断。ICH E2B等文档标准，意味着插件需能解析特定XML或JSON格式，并对字段进行标准化映射。字段的细致划分和多样的单位，要求插件在数据预处理阶段能进行严格的类型校验和单位转换，例如，确保剂量单位一致性，避免因单位不匹配导致的数据误判。对因果关系评估的复杂性，则促使插件在调用外部专家系统或知识图谱时，能传递足够上下文信息。

## 配置怎么定

| 配置项                       | 建议取法                                        | 这样取的依据                                                 |
| :--------------------------- | :---------------------------------------------- | :----------------------------------------------------------- |
| `max_tokens`                 | `2048`                                          | 确保能完整处理典型不良事件报告的详细描述，避免截断关键信息。 |
| `timeout_seconds`            | `60` 秒                                         | 适应外部安全数据库或因果关系评估API的响应时间，避免因等待过久导致调用失败。 |
| `function_call_retries`      | `3` 次                                          | 应对外部服务偶发性网络抖动或临时不可用，提高调用成功率。     |
| `data_schema_validation`     | `严格模式`                                      | 确保输入数据严格符合ICH E2B或内部定义的字段规范，减少数据质量问题。 |
| `extraction_template`        | 包含患者ID、药品名、事件描述、发生日期等关键字段 | 指导LLM精确提取不良事件报告中的结构化信息。                  |
| `api_key_refresh_interval`   | `30` 天                                         | 满足CDMO行业对数据安全和凭证管理的合规性要求。             |

## 容易做错的三处

*   插件调用后返回 `llm model response empty`，并伴随长时间卡顿。这通常是由于传递给大模型的输入过长，超过了模型 `max_tokens` 限制，导致模型无法生成有效回复。
*   工具调用返回的结果中，关键字段（如药物剂量）为空或单位错误。这源于数据预处理阶段对非结构化文本的解析不充分，或未正确进行单位标准化转换。
*   工作流在工具调用步骤直接报错，日志显示 `HTTP 401 Unauthorized`。这通常指示外部API的 `api_key` 配置过期或不正确，导致认证失败。

## 怎么确认配好了

*   针对不同复杂度的模拟不良事件报告，执行端到端的工作流，检查插件是否能准确提取所有预设的关键字段，并验证字段内容与原始报告一致。
*   模拟外部API的偶发性响应延迟或错误，观察 `function_call_retries` 配置是否能触发重试机制，并最终成功获取结果。
*   使用包含不同剂量单位（如mg、g、mcg）的测试数据，验证插件在调用外部工具前，是否能正确进行单位转换，并确保转换后的数据格式符合外部工具的输入要求。
*   定期检查 `api_key` 的有效期，并在过期前完成更新，以避免因认证问题导致的工具调用失败。
