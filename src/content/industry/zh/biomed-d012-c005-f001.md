# CSO药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样
CSO（合同销售组织）在药物警戒领域的数据主要来源于其合作药企的产品销售与推广过程中收集到的真实世界数据，以及通过自身渠道获取的上市后不良事件报告。这些数据更新频率较高，通常按天或周进行增量更新。文档结构以结构化或半结构化报告为主，如个例安全性报告（ICSR）或汇总安全性报告（PSUR）的局部数据。关键字段包括患者标识符（脱敏处理）、药品名称、不良事件描述、事件发生日期、报告来源、处理措施等。数据单位通常涉及剂量（毫克、克）、频率（次/日）、持续时间（天、周）。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
高频的增量数据更新要求 HTTP 接口具备高效的数据同步机制，能够处理大量小批次的数据提交。半结构化或结构化的报告格式决定了接口设计时需要预定义清晰的数据模型，以确保字段的准确映射和解析。脱敏的患者标识符意味着数据传输过程中需要严格遵守数据隐私规范，例如使用 HTTPS 加密传输。同时，由于数据来源多样，接口需要具备一定的容错性，能够处理因不同源头数据格式微小差异导致的数据解析异常。高频更新还对外部系统的处理能力提出要求，避免因接口调用过载或数据处理延迟导致数据堆积。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `batchSize` | `500` 条/批 | 兼顾传输效率与单次请求处理耗时，减少网络开销 |
| `timeout` | `600` 秒 | 应对复杂报告解析或大批量数据传输的耗时 |
| `maxConnections` | `20` | 平衡并发处理能力与后端系统资源占用 |
| `retryAttempts` | `3` 次 | 应对瞬时网络抖动或外部系统短暂不可用 |
| `payloadCompression` | `gzip` | 降低传输数据量，提高传输效率 |
| `rateLimitPerMinute` | `120` 次 | 保护外部系统免受过载，确保服务稳定性 |

## 容易做错的三处
- 现象：HTTP 接口返回 `400 Bad Request` 错误，提示字段格式不匹配。原因：外部系统接收的日期格式要求为 `YYYY-MM-DD`，而发送方提供了 `YYYY/MM/DD` 格式。
- 现象：数据同步任务长时间无响应，最终超时失败。原因：单次请求传输的数据量过大，超过了外部系统或网络传输的承载能力。
- 现象：部分不良事件报告数据未成功导入，但接口返回 `200 OK`。原因：外部系统在接收到数据后进行了异步处理，接口只确认了接收，实际处理过程中发生了数据校验错误，但未及时通过接口状态码反馈。

## 怎么确认配好了
- 通过模拟工具或实际数据，以峰值更新频率持续调用接口，检查数据能否稳定、及时地导入外部系统。
- 检查外部系统的数据日志，核对导入数据的完整性与准确性，特别关注字段映射和单位转换是否正确。
- 随机抽取一定比例的原始数据与导入到外部系统的数据进行比对，确认数据内容一致性。
- 监控接口响应时间与错误率，确保在正常负载下接口性能符合预期，错误率低于设定阈值。
