# SMO药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样
SMO（Site Management Organization，临床试验现场管理组织）在药物警戒与不良反应领域的数据主要来源于临床试验机构（CRC、研究者）上报的SAE（严重不良事件）/AE（不良事件）报告、伴随用药记录、实验室检查结果以及受试者访视记录。这些数据通常以结构化或半结构化的形式存在，例如EDC（电子数据采集）系统导出文件、XML报告、PDF报告或定制化的JSON数据包。数据更新频率较高，尤其是在试验进行中，SAE/AE报告可能需要24小时内上报。文档结构复杂，涉及医学术语、剂量单位、时间戳、报告者信息、事件描述等多个字段，且不同试验或不同申办方可能存在字段差异和单位不统一的情况。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
SMO药物警戒数据的高时效性要求HTTP接口具备低延迟和高可用性，以确保SAE/AE报告能及时送达。数据来源多样性（EDC系统、实验室等）意味着接口需要支持多种数据格式的解析能力，例如JSON、XML。字段差异和单位不统一对数据预处理和映射提出了挑战，需要灵活的配置来处理不同来源的数据结构。此外，敏感的医疗数据属性，例如受试者信息，要求HTTP传输必须强制使用HTTPS协议，并可能涉及额外的身份验证机制（如OAuth2或API Key）。频繁的数据更新也意味着API调用频率可能较高，需要考虑接口的并发处理能力和速率限制。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `requestTimeout` | `60000 毫秒` | 应对网络波动和外部系统处理时间，防止因超时导致数据丢失。 |
| `maxRetries` | `3` | 临时性网络问题或外部系统瞬时故障时，通过重试机制确保数据最终送达。 |
| `contentType` | `application/json` 或 `application/xml` | 匹配主流EDC系统和实验室系统导出的数据格式。 |
| `headers.Authorization` | `Bearer <token>` 或 `API Key <key>` | 满足医疗数据传输的认证要求，确保数据安全。 |
| `dataMappingRules` | 按实测标定 | 不同申办方和试验的数据字段可能存在差异，需要灵活配置映射规则。 |
| `batchSize` | `50–100 条记录` | 平衡单次请求的数据量和外部系统处理能力，避免单次请求过大导致失败。 |

## 容易做错的三处
*   现象：API调用返回空内容或非预期数据。原因：`dataMappingRules`配置不正确，导致外部系统无法识别或解析发送的数据字段。
*   现象：HTTP请求频繁超时或报错 `503 Service Unavailable`。原因：`requestTimeout`设置过短，或外部系统存在速率限制，而未在调用逻辑中加入重试或退避策略。
*   现象：外部系统无法验证请求身份。原因：`headers.Authorization`中的认证凭据过期、格式不正确或未正确传递。

## 怎么确认配好了
*   对核心的SAE/AE上报接口，使用模拟数据进行端到端测试，核对外部系统是否成功接收并正确解析所有字段。
*   检查FastGPT的HTTP接口日志，确认请求状态码为 `200 OK` 或其他表示成功的状态码，并且响应体内容符合预期。
*   监控外部系统的接收日志或数据库，核对数据字段、单位和时间戳是否与发送的数据一致，并验证数据完整性。
*   在高峰期或高并发场景下，通过压力测试验证接口的稳定性和响应时间是否满足业务需求，尤其关注 `requestTimeout` 和 `batchSize` 的表现。
