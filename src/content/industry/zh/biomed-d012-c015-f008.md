# 临床决策支持药物警戒的工具调用与插件

## 这个品类的数据长什么样

临床决策支持在药物警戒领域的数据主要来源于药品说明书、临床试验报告、真实世界证据（RWE）数据库、不良事件报告系统（如 FAERS、EudraVigilance）以及医学文献。这些数据更新频率不一，药品说明书和临床试验报告随药品生命周期更新，不良事件报告系统数据通常是持续流入，医学文献则按期刊发布周期更新。文档结构多样，包括结构化的数据库记录、半结构化的 XML 或 JSON 格式报告，以及非结构化的临床笔记和文献PDF。字段包括药品通用名、商品名、适应症、用法用量、不良反应、禁忌症、药物相互作用、患者人口统计学信息、事件发生时间、严重程度、结局等，单位涉及剂量（mg、g、IU）、频率（次/日）、时间（小时、天、年）等，需要特别注意单位的一致性和标准化。

## 这些特征在「工具调用与插件」这一环带来什么约束

数据来源的多样性要求工具调用插件能够灵活对接不同数据接口，例如通过 API 调用 RWE 数据库，或解析 PDF 格式的药品说明书。更新频率的差异意味着需要设计定时任务或事件触发机制来同步最新数据，以确保决策支持的实时性。文档结构的多样性对插件的数据解析能力提出要求，需要具备处理结构化、半结构化和非结构化数据的能力，例如使用自然语言处理（NLP）技术从非结构化文本中提取关键信息。字段和单位的复杂性要求插件在数据处理阶段进行标准化和归一化，以避免因单位不一致导致的决策错误。例如，剂量单位的转换、时间格式的统一等。此外，药物警戒的专业性要求工具调用插件能够集成专业的医学术语库和本体，辅助理解和推理。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `tool_timeout_seconds` | `600 秒` | 考虑到外部数据库查询和复杂数据解析可能耗时，避免过早超时。 |
| `max_tokens_per_call` | `4000` | 确保能够承载一次工具调用返回的完整医学文本或结构化数据。 |
| `plugin_max_retries` | `3` | 外部服务偶发性故障，重试可提高成功率。 |
| `data_source_sync_interval_hours` | `24 小时` | 针对不良事件报告系统等持续更新的数据源，保证数据时效性。 |
| `parser_batch_size` | `100 条` | 处理大量历史数据或文献时，平衡内存消耗与处理速度。 |
| `embedding_model_name` | `text-embedding-ada-002` | 兼顾准确性和成本，适用于医学文本的语义理解。 |

## 容易做错的三处

*   调用外部 API 时出现 `HTTP 504 Gateway Timeout` 错误，原因通常是后端服务处理时间过长，超过了网关或代理的默认超时设置。
*   插件返回结果中关键字段为空或格式不正确，这往往是由于数据解析逻辑未能充分覆盖源数据的多种变体或异常格式。
*   模型无法正确使用已配置的工具，例如无法进行网络搜索，原因可能是工具描述（`tool_description`）不够清晰，未能准确引导模型理解工具的功能和使用场景。

## 怎么确认配好了

*   通过模拟真实查询，检查工具调用是否能成功触发外部数据检索或API执行，并返回预期格式的结果。
*   验证插件从不同数据源（如药品说明书PDF、FAERS数据库API）提取的关键信息是否完整且准确，例如药品名称、不良反应列表。
*   测试工具在处理异常数据或边界条件时的表现，例如输入不存在的药品名称时是否能返回合理的错误提示。
