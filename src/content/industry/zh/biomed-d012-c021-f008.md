# 供应商审计药物警戒的工具调用与插件

## 这个品类的数据长什么样

供应商审计在药物警戒领域涉及的数据，核心是审计报告、供应商资质文件和药物不良反应（ADR）报告。审计报告通常是 PDF 或 Word 格式，内容包含审计发现、纠正预防措施（CAPA）及完成情况，更新频率依据审计周期，通常为每年或每两年一次。供应商资质文件如生产许可证、质量管理体系认证（如 ISO 9001、GMP 证书）等，多为扫描件或电子文档，更新频率取决于证书有效期，通常为 3-5 年。ADR 报告则来自各种来源，包括临床试验数据、上市后监测数据和自发报告系统，数据结构多样，可能包含患者基本信息、药品信息、不良事件描述（通常是自由文本）、严重程度评级和因果关系评估等字段，更新频率较高，可能每天都有新增。

## 这些特征在「工具调用与插件」这一环带来什么约束

供应商审计数据的异构性和更新频率差异，直接影响工具调用与插件的设计。审计报告和资质文件的 PDF/Word 格式，要求文件解析工具能有效提取结构化信息，尤其要注意表格和嵌套文本的识别准确性，这可能需要专门的 OCR 或文档解析插件。由于更新不频繁，相关数据在知识库中的索引更新策略可以采用周期性全量或增量更新。ADR 报告的自由文本描述对自然语言处理（NLP）能力提出更高要求，需要插件能处理医学术语、缩写和非标准表达，并能从中抽取关键实体和关系。高频更新的 ADR 数据，则要求工具调用具备实时或准实时的数据摄取能力，并能快速触发知识库的增量索引和检索。此外，不同数据源的字段和单位不一致，要求工具调用层进行标准化或映射处理。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `分段长度` | `500–800 字符` | 确保单个分段包含足够上下文，避免过度切割导致语义丢失，同时适应审计报告的段落长度。 |
| `重叠长度` | `50–100 字符` | 保证分段间的上下文连续性，尤其在处理长篇审计发现或药物不良事件描述时。 |
| `最大文件大小` | `100 MB` | 兼顾大型审计报告和扫描资质文件的上传需求，避免因文件过大导致的上传失败。 |
| `解析超时时间` | `300 秒` | 考虑到包含大量图片或复杂表格的 PDF 文件解析耗时，预留充足时间。 |
| `召回条数` | `前 8 条` | 在药物警戒审查中，通常需要综合多方面信息，适量增加召回条数可提升结果全面性。 |
| `相似度阈值` | `0.75` | 平衡召回率与准确率，确保检索结果与查询内容高度相关，避免无关信息干扰。 |

## 容易做错的三处

*   工具调用返回 `404` 错误：通常是由于 OneAPI 配置的后端 API 地址或路由不正确，或者 FastGPT 插件中调用的 URL 与实际服务地址不匹配。
*   插件执行后返回结果为空或不完整：可能是因为文档解析插件未能正确识别 PDF 或扫描件中的表格数据，导致关键字段提取失败。
*   RAG 结果中未包含最新的 ADR 信息：知识库更新策略未与 ADR 数据源的更新频率同步，导致索引数据滞后于实际发生的不良事件。

## 怎么确认配好了

*   上传典型审计报告（PDF/Word）和资质文件样本，检查知识库中是否已正确分段并提取出关键信息，例如审计发现、CAPA 状态。
*   设计包含医学术语和不良事件描述的查询，验证工具调用能否正确识别并调用相关插件，并从 ADR 知识库中召回相关且完整的报告。
*   模拟新的 ADR 数据入库，并在短时间内查询，确认知识库的增量更新机制是否按预期工作，新数据是否可被检索。
