# 供应商审计药物警戒的部署与升级

## 这个品类的数据长什么样

供应商审计在药物警戒领域，其数据主要来源于审计报告、整改计划、现场检查记录以及相关法规遵循文件。这些文档通常以 PDF、Word、或扫描件形式存在，结构化程度不高。数据更新频率不一，通常在审计周期结束后集中更新，或在整改措施落实后进行补充。审计报告可能包含对供应商质量管理体系、生产流程、不良事件报告机制的评估，其中涉及的字段包括审计发现的缺陷类型、严重程度、建议整改措施、完成日期以及责任人等。单位多为文本描述，涉及时间时以日期格式呈现，涉及数量时以整数或百分比表示。

## 这些特征在「部署与升级」这一环带来什么约束

审计报告的非结构化特性，对 FastGPT 的文档解析能力提出更高要求。部署时需考虑配置 OCR 插件以处理扫描件，并优化分段策略，确保关键信息不被割裂。更新频率的不确定性，意味着模型训练与知识库同步不宜过于频繁，应采用事件驱动或周期性增量更新模式，避免资源浪费。文档中包含大量专业术语和法规条款，要求基础模型具备较强的领域理解能力，并在知识库构建时进行术语表导入。字段描述的多样性，例如对缺陷严重程度的定性描述，会影响召回与匹配的准确性，需通过调整相似度阈值和重排策略来优化。

## 配置怎么定

| 配置项                   | 建议取法       | 这样取的依据                                   |
| :----------------------- | :------------- | :--------------------------------------------- |
| `UPLOAD_FILE_MAX_SIZE`   | `200 MB`       | 单个审计报告文件可能较大，包含多页附件           |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`       | 应对复杂或扫描件多的文档解析时间，防止超时       |
| `分段长度`               | `800–1200 字符` | 保持语义完整性，兼顾长篇描述和细节信息           |
| `召回条数`               | `前 10 条`     | 确保覆盖供应商审计报告中可能分散的关键信息     |
| `相似度阈值`             | `0.75`         | 应对专业术语和描述多样性，提高匹配准确率         |
| `重排返回条数`           | `前 3 条`      | 聚焦最相关的审计发现或整改建议，减少无关干扰     |

## 容易做错的三处

*   知识库更新后，查询结果仍出现旧信息。原因在于知识库同步策略未配置为增量更新，导致新旧数据混淆。
*   上传审计报告文件时，界面显示“文件过大”错误。原因在于 `UPLOAD_FILE_MAX_SIZE` 参数设置过小，未能覆盖实际文件大小。
*   聊天界面在 iOS 设备上无法加载，显示白屏。原因在于前端资源加载路径配置不当，或跨域策略限制了移动端访问。

## 怎么确认配好了

*   上传一份包含扫描件的审计报告 PDF 文件，确认文件能够正常解析并生成问答内容。
*   查询关于特定供应商的审计发现，核对返回结果是否准确包含报告中的缺陷编号和整改措施。
*   模拟一次新的审计报告上传，确认知识库内容已更新，且新旧信息能够正确区分。
