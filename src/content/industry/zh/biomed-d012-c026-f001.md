# 冷链物流药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样
冷链物流药物警戒的数据主要来源于温湿度传感器、GPS 定位设备、运输车辆管理系统、仓储管理系统以及药品批次信息。这些数据以结构化和半结构化形式为主，例如 JSON、XML 或 CSV。数据更新频率较高，温湿度和位置信息可能每隔几分钟甚至几十秒更新一次，批次和状态信息则可能在关键节点（如入库、出库、运输中转）更新。文档通常包含运输单号、药品批号、生产日期、有效期、存储条件、实时温湿度读数、地理位置坐标、运输路线、异常事件记录等字段。温湿度数据常带有时间戳和单位（摄氏度、华氏度），位置数据则有经纬度。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
高频更新的温湿度和位置数据要求 HTTP 接口具备高吞吐量和低延迟，以避免数据堆积或滞后。实时性要求使得批量导入或长时间轮询不适用于核心监控数据，需要采用更接近流式的数据摄取方式。药品批号和有效期等关键信息需要严格的数据校验，防止因录入错误导致药物失效或召回风险。多源异构的数据结构（传感器数据、系统日志、人工录入）要求接口设计具备良好的兼容性和扩展性，能够灵活处理不同格式的数据字段。异常事件（如温度超限、运输路线偏离）的快速上报机制要求接口能够支持实时的告警触发，并通过外部系统进行及时响应。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `batchSize` | 100–500 条记录 | 平衡接口调用频率与单次传输效率，避免超大包体导致网络延迟或超时 |
| `requestTimeout` | 3000–5000 毫秒 | 适应网络波动与外部系统处理时间，确保高频数据及时上传 |
| `maxConnections` | 10–20 个 | 支撑并发数据上传需求，防止连接池耗尽影响实时性 |
| `contentType` | `application/json` | 广泛支持且易于解析结构化数据，确保数据传输格式统一 |
| `retryAttempts` | 3 次 | 应对瞬时网络故障或外部系统短暂不可用，提高数据上传成功率 |
| `heartbeatInterval` | 60 秒 | 保持与外部系统的连接活跃，及时发现连接中断 |

## 容易做错的三处
*   HTTP 请求返回 500 状态码，内容为“数据校验失败，批号格式不符”：原因在于药品批号字段未按外部系统要求进行格式化或包含非法字符。
*   温湿度数据上传后，外部系统显示为空或为默认值：原因可能是数据载荷中温湿度字段名与外部系统接口定义不一致，或单位转换错误。
*   警报事件未能在温度超限后及时触发：原因在于接口轮询间隔过长，未能实时获取到最新的温湿度数据，导致告警延迟。

## 怎么确认配好了
*   执行模拟数据上传，检查外部系统相应字段是否准确填充，并核对温湿度、批号、地理位置等关键数据的单位和精度。
*   通过 FastGPT 内部日志或外部系统监控，确认 HTTP 接口调用成功率达到预期，并检查是否有 4xx 或 5xx 错误码出现，若有则进一步排查。
*   模拟温度超限等异常情况，观察外部系统是否在规定时间内接收到告警信息，并验证告警内容的完整性与准确性。
