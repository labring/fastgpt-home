# 冷链物流药物警戒的文档解析与分块

## 这个品类的数据长什么样

冷链物流药物警戒领域的数据主要来源于药品运输过程中的温湿度监测记录、运输协议、质量管理体系文件、供应商资质证明、异常事件报告及调查记录等。这些数据更新频率较高，特别是温湿度记录，可能以分钟或小时为单位实时生成。文档结构多样，既有结构化的表格数据，如温湿度日志、批次信息，也有半结构化或非结构化的文本，如运输风险评估报告、偏差处理报告、SOP（标准操作程序）文件。字段与单位具有行业特异性，例如温度数据会精确到小数点后一位（如 `2.5°C`），湿度数据以百分比表示（如 `60% RH`），时间戳通常包含日期和精确到秒的时间信息（如 `2023-10-26 14:35:01`），批号、序列号等标识符也遵循特定编码规则。

## 这些特征在「文档解析与分块」这一环带来什么约束

高频更新的温湿度记录要求解析系统能够快速处理增量数据，避免数据积压，并支持时间序列数据的有效分块。多样化的文档结构意味着需要灵活的解析策略，既要能准确抽取表格中的关键数值，也要能理解非结构化文本中的药物警戒相关语义。例如，SOP 文件通常包含流程步骤、责任人、风险点等信息，这些都需要被独立识别和分块。行业特异的字段与单位对解析的准确性提出了挑战，需要定制化的正则表达式或命名实体识别模型来确保正确提取，例如区分不同类型的时间戳、识别温度范围等。此外，异常事件报告往往包含对事件发生、调查和处理过程的详细描述，这类文本需要更细粒度的分块，以确保关键信息不被稀释，方便后续的药物警戒分析与召回。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `分段长度` | `500–800 字符` | 平衡上下文完整性与召回效率，适应报告和SOP文件的段落长度。 |
| `分段重叠` | `50 字符` | 确保分段边界上下文连续，避免关键信息被切割。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 适应大型温湿度日志或复杂协议文档的解析时间。 |
| `maxContext` | `1000 令牌` | 确保在处理异常事件报告时，能够包含足够多的事件描述细节。 |
| `文档类型识别规则` | `按实测标定` | 针对温湿度日志、SOP、报告等不同文档格式定制解析策略。 |
| `自定义实体识别` | `批号、药品名称、温度、湿度` | 精确抽取药物警戒核心要素，提高信息提取准确性。 |

## 容易做错的三处

*   解析状态长时间停留在“解析中”或显示“解析失败”，原因可能是 `PARSE_FILE_TIMEOUT_SECONDS` 设置过低，无法处理超大文件或包含复杂表格的文档。
*   在检索结果中发现关键温湿度数据或药品批次信息缺失，这通常是由于文档解析过程中未正确配置自定义实体识别规则，导致特定格式的数据未能被有效抽取。
*   API返回的响应报文中 `Set-Cookie` 字段未能被成功解析，这可能发生在尝试通过HTTP请求模块处理带有会话管理需求的接口时，需要检查组件是否支持此类HTTP头解析。

## 怎么确认配好了

*   上传典型温湿度日志文件、运输协议和异常报告，检查解析状态是否最终显示“就绪”。
*   对已解析的文档进行关键词检索，验证批号、温度范围、时间戳等关键字段是否能被准确召回。
*   针对上传的PDF文档（包含图片和文本），核对AI输出内容是否完整包含文档中的文本信息，并能识别出图片中的必要信息（如果模型支持）。
