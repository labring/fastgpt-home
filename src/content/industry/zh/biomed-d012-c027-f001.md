# 减毒灭活疫苗药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样
减毒灭活疫苗的药物警戒数据主要来源于临床试验报告、真实世界研究、上市后主动监测系统以及自发报告系统。数据更新频率较高，尤其在上市初期或大规模接种期间，监测数据可能每日或每周更新。文档结构通常包含患者基本信息、疫苗批次号、接种日期、不良反应发生日期、具体症状描述（如发热、红肿、过敏反应）、严重程度、转归情况、相关实验室检查结果以及因果关系评估。字段内容标准化程度较高，常遵循医学术语编码（如 MedDRA），单位则涉及剂量（μg）、体温（℃）、时间（天、小时）等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
减毒灭活疫苗数据更新的实时性要求，决定了外部系统通过 HTTP 接口拉取数据时，需要支持高频次的请求，并具备增量更新的能力，避免每次全量同步。详细的症状描述和因果关系评估字段，意味着接口返回的数据结构应支持嵌套或复杂对象，以便完整传输临床细节。MedDRA 编码等标准化字段的存在，要求 FastGPT 在处理数据时能正确解析和映射这些编码，以便后续的知识抽取和推理。此外，不同来源的数据可能存在格式差异，HTTP 接口需提供灵活的参数配置，以适应多种数据源的接入，同时对请求超时和错误处理机制提出了更高的要求，以确保数据传输的稳定性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :------------------------------- | :------------------------------- | :------------------------------------------- |
| `FETCH_INTERVAL_SECONDS` | `600 秒` | 应对减毒灭活疫苗不良反应数据的高频更新需求。 |
| `MAX_RETRIES` | `3` | 减少因瞬时网络波动导致的数据同步失败。 |
| `TIMEOUT_SECONDS` | `180 秒` | 考虑疫苗不良反应报告中可能包含大量文本描述和附件，确保数据传输完整性。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 应对可能包含详细临床报告的大文件解析需求。 |
| `CHUNK_SIZE` | `800–1200 字符` | 平衡文本块的语义完整性和检索效率。 |
| `MAX_OUTPUT_TOKENS` | `2048` | 确保在处理复杂查询时，能返回足够详细的分析结果。 |

## 容易做错的三处
*   现象：通过 API 调用 FastGPT 时，输出内容在中间环节停止。原因：`TIMEOUT_SECONDS` 参数设置过短，导致复杂查询或大量数据处理未完成即被截断。
*   现象：上传疫苗不良反应报告文件后，智能体无法准确回答报告内容。原因：`PARSE_FILE_TIMEOUT_SECONDS` 参数不足以处理包含多页或复杂表格的 PDF/Word 文档，导致文件解析不完整。
*   现象：外部系统调用 FastGPT 接口时，偶发 `Error: write EPROT` 报错。原因：HTTP 接口在处理大文件传输或高并发请求时，服务器资源（如内存、连接数）达到上限，导致写入错误。

## 怎么确认配好了
*   执行一系列包含不同复杂程度的减毒灭活疫苗不良反应查询，检查返回结果的完整性和准确性，确保所有关键信息均被包含。
*   模拟高频次的数据更新，观察 FastGPT 的知识库同步情况，确认新增数据能及时被索引并用于问答，同步延迟应在可接受范围内。
*   通过 API 接口上传多种格式（PDF、Word、TXT）和大小的疫苗不良反应报告文件，验证文件上传、解析和知识抽取流程无误，并能正确识别 MedDRA 编码等专业字段。
