# 分子诊断药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样
分子诊断药物警戒的数据主要来源于临床试验报告、真实世界研究（RWE）、基因组测序结果、生物标志物检测报告以及患者电子病历（EHR）。数据更新频率因来源而异，临床试验数据通常在试验阶段性报告或最终报告发布时更新，RWE数据则可能以季度或年度批次更新，而EHR数据则实时或准实时生成。文档结构复杂，常包含非结构化的文本描述、半结构化的表格数据以及结构化的基因位点信息。字段特异性强，例如基因突变类型（如 `SNP`、`Indel`）、变异频率（`Allele Frequency`）、生物标志物浓度（如 `ng/mL`、`IU/L`）以及不良事件编码（如 `MedDRA` 术语）。数据量庞大且异构，需要整合处理。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
分子诊断数据来源的多样性要求 HTTP 接口具备高度的灵活性，能够适配不同来源系统的数据协议和认证机制。高频的数据更新，尤其是来自 EHR 或实时监测设备的数据，对接口的实时性、并发处理能力和错误重试机制提出了要求。非结构化与半结构化数据并存的特点，使得接口在接收数据时需支持多种数据格式，例如 `JSON`、`XML` 以及文本文件，并要求后端有强大的解析能力。特异性字段的存在，如基因位点、药物靶点等，意味着接口在设计时需要预留足够的数据结构扩展性，并确保这些关键字段能被准确识别和映射。数据量大则要求接口具备分批上传、断点续传能力，并对 `Content-Length` 等参数有合理限制。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 应对包含基因测序原始数据或大量临床报告的文档上传需求 |
| `maxContext` | `2000 字符` | 平衡分子诊断报告的详细度与向量数据库的索引效率 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 允许对大型、复杂结构的分子诊断报告进行充分解析 |
| `分段长度` | `800–1200 字符` | 确保单个文本段落包含足够上下文，支持基因突变、不良事件等信息的完整性 |
| `召回条数` | `前 10 条` | 提高从复杂知识库中检索相关分子诊断信息的准确性 |
| `相似度阈值` | `0.75` | 确保检索结果与查询的分子诊断相关性高，过滤无关信息 |

## 容易做错的三处
*   外部系统调用 FastGPT 接口时，`payload` 中的 `event` 字段未正确设置，导致事件日志记录不完整或触发了非预期的处理流程。
*   上传大量分子诊断相关 `md` 文档时，由于文件大小或数量超出接口默认限制，导致部分文档无法成功导入知识库，系统返回 `413 Request Entity Too Large` 错误。
*   在处理来自不同实验室的分子诊断报告时，由于字段命名不统一或单位不匹配，导致数据解析失败或信息丢失，系统日志显示 `KeyError` 或 `ValueError`。

## 怎么确认配好了
*   通过 FastGPT 的 API 接口，模拟上传一份包含基因测序数据和不良事件描述的典型分子诊断报告，观察是否能成功返回 `200 OK` 状态码。
*   在知识库中检索与上传报告相关的关键词，比对召回结果与原始报告内容，确保关键信息（如基因突变、药物名称、不良反应描述）被准确提取和索引。
*   检查 FastGPT 后台的日志系统，确认数据解析过程中未出现 `ERROR` 级别的日志，特别是关于数据格式、字段匹配或超时相关的错误。
*   测试高并发场景下多个外部系统同时向 FastGPT 接口推送数据，监控接口响应时间与错误率，确保系统在高负载下仍能稳定运行。
