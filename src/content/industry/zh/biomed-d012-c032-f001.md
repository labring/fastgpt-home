# 医保结算药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

医保结算数据主要来源于各级医保局、医疗机构或第三方结算平台。这些数据通常以结构化格式提供，如 XML、JSON 或 CSV，并通过标准化的接口进行传输。数据更新频率较高，通常按日或按周进行批次更新，以反映最新的结算记录。文档结构方面，医保结算数据通常包含患者基本信息、诊断信息（如 ICD-10 编码）、药品信息（如国家医保药品目录编码、通用名、剂型、规格、生产厂家）、费用明细（单价、数量、总金额）以及结算状态等字段。其中，药品信息和诊断信息是药物警戒分析的关键字段，其编码体系和标准需要严格遵循国家相关规定。费用单位通常为人民币“元”，精确到小数点后两位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

医保结算数据的高更新频率要求 HTTP 接口具备高效的并发处理能力和稳定的连接。结构化的数据格式意味着在接口配置时需要精确定义请求体和响应体的字段映射，以确保数据正确解析。例如，药品编码和诊断编码的标准化要求在数据抽取和转换（ETL）阶段进行严格的数据清洗和校验。费用单位的精度要求在数据处理时避免浮点数计算误差。此外，数据来源的多样性可能导致不同平台接口规范的细微差异，需要针对性地调整 `URL` 路径、`HEADER` 参数和认证方式，以适应各种外部系统。对于敏感的患者信息，接口必须支持安全的传输协议，如 HTTPS，并可能需要额外的加密或脱敏处理，这会增加接口调用和数据处理的复杂度。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `HTTP_METHOD` | `POST` | 医保结算数据量大，且通常包含敏感信息，`POST` 方法更适合传输复杂数据体和保障数据安全。 |
| `CONNECT_TIMEOUT_SECONDS` | `30 秒` | 多数医保结算系统接口响应时间在数秒内，此值可避免长时间等待，同时允许一定网络延迟。 |
| `READ_TIMEOUT_SECONDS` | `60 秒` | 考虑到批量数据传输和后端处理时间，`60 秒` 能覆盖大多数正常响应场景。 |
| `MAX_RETRIES` | `3 次` | 临时网络波动或服务器瞬时负载高可能导致失败，适当重试可提高成功率。 |
| `AUTH_TYPE` | `Bearer Token` | 医保结算系统常采用 OAuth 2.0 或 JWT 进行身份验证，`Bearer Token` 是主流且安全的认证方式。 |
| `DATA_SCHEMA_VERSION` | `V2.1.0` | 明确指定数据接口版本，确保解析器与数据结构匹配，避免因版本差异导致字段解析错误。 |

## 容易做错的三处

*   现象：接口返回 401 Unauthorized 错误码。原因：`Authorization` 头中的 `Bearer Token` 已过期或不正确，未能通过外部系统的身份验证。
*   现象：返回数据中药品名称或诊断编码字段为空。原因：外部系统接口的字段名与 FastGPT 配置的字段映射不一致，或者数据在传输过程中被截断。
*   现象：系统处理医保结算数据时出现金额计算偏差。原因：原始数据中的费用单位未被正确识别或处理，导致浮点数精度问题或单位转换错误。

## 怎么确认配好了

*   调用接口后，检查 HTTP 响应状态码是否为 200 OK，确认接口连接成功。
*   检查返回数据的关键字段，如 `drug_code`、`diagnosis_code`、`total_amount` 是否有值且格式正确。
*   通过少量样本数据进行端到端测试，对比 FastGPT 中解析出的数据与原始医保结算数据是否完全一致，特别是金额和编码类字段。
