# 医院运营药物警戒的工具调用与插件

## 这个品类的数据长什么样
医院运营场景下的药物警戒数据主要来源于医院内部信息系统，包括电子病历（EMR）、医嘱系统、药房管理系统、检验检查系统以及不良事件报告系统。数据更新频率高，不良事件报告通常在事件发生后 24–48 小时内录入，用药记录更是实时更新。文档类型多样，包含结构化的数据库记录（如药品批次、患者 ID、用药剂量、用药时间、诊断代码 ICD-10）、半结构化的临床医嘱、以及大量的非结构化文本（如医生查房记录、护士观察记录、患者主诉、不良反应描述）。关键字段包括患者唯一标识符 `patient_id`、药品通用名 `drug_generic_name`、药品商品名 `drug_trade_name`、批号 `batch_number`、剂量 `dose`（单位 mg/g/ml）、给药途径 `administration_route`、给药时间 `administration_time`、不良反应事件 `adverse_event_description`、事件发生时间 `event_time`、处理措施 `management_action` 等。

## 这些特征在「工具调用与插件」这一环带来什么约束
医院运营数据的高度实时性和多样性，对工具调用与插件的响应速度和数据解析能力提出了严格要求。实时用药数据和不良事件报告的快速更新，意味着工具需要能够频繁且高效地拉取最新信息，并及时触发分析。非结构化文本（如医生查房记录）的大量存在，要求插件具备强大的自然语言处理能力，从自由文本中准确提取关键医学实体和事件，例如识别药品名称、不良反应症状、剂量、时间关系等。结构化与半结构化数据则需要灵活的字段映射和数据类型转换机制，以适应不同系统间的数据格式差异。此外，药物剂量的精确单位（mg/g/ml）和时间戳格式（`YYYY-MM-DD HH:MM:SS`）要求工具在参数传递时保持高精度和严格的格式校验，避免因单位或格式错误导致的结果偏差或调用失败。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `tool_request_timeout` | `60 秒` | 多数医院内部 API 响应在 30 秒内，预留冗余处理复杂查询和网络波动。 |
| `max_api_retries` | `3 次` | 内部系统偶尔出现瞬时网络抖动或服务繁忙，多次重试可提高成功率。 |
| `text_extraction_model` | `特定医学领域预训练模型` | 医院病历文本专业性强，通用模型对医学实体和关系识别准确率不足。 |
| `json_schema_validation` | `启用` | 确保从 API 获取的数据结构符合预期，避免因数据格式不一致导致后续处理失败。 |
| `rate_limit_per_minute` | `120 次` | 多数医院内部 API 有调用频率限制，根据实际 API 文档标定，避免触发限流。 |
| `datetime_format_standard` | `YYYY-MM-DD HH:MM:SS` | 统一时间格式，确保跨系统数据时间戳解析一致性，如 `administration_time`。 |

## 容易做错的三处
*   调用外部 API 收到 `404 Not Found` 错误，常见原因是 API 地址 `base_url` 或路径 `path` 配置有误，或认证 `API_KEY` 不正确导致请求未被正确路由。
*   插件执行后返回数据字段为空或类型不符，通常是由于对非结构化文本的实体提取规则不足，未能正确解析出 `adverse_event_description` 等关键信息，或 `json_schema_validation` 未严格校验数据类型。
*   工具调用频繁超时或响应缓慢，这可能是 `tool_request_timeout` 设置过短，或后端 API 接口本身存在性能瓶颈，尤其在处理大量历史数据或复杂计算时。

## 怎么确认配好了
*   对核心工具调用路径进行端到端测试，模拟真实的用药记录和不良事件报告，验证插件是否能够成功调用后端 API 并返回预期结构的数据。
*   检查日志输出，确认 `tool_request_timeout` 参数是否生效，以及是否有 `AxiosError` 等网络或请求错误，并核对返回数据的 `status_code`。
*   验证从非结构化临床记录中提取的 `drug_generic_name`、`dose`、`event_time` 等关键字段的准确性，确保与原始文本信息一致，并校验单位和时间格式的正确性。
*   监控工具调用频率，确保 `rate_limit_per_minute` 等参数能够有效控制调用行为，避免触发目标 API 的限流机制。
