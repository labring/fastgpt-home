# 单克隆抗体药物警戒的部署与升级

## 这个品类的数据长什么样

单克隆抗体（mAb）药物警戒数据主要来源于临床试验报告、真实世界研究、上市后监测数据库（如 FDA Adverse Event Reporting System, FAERS；欧洲药品管理局 EudraVigilance）以及文献报道。这些数据通常以结构化（例如，数据库中的不良事件报告表单）和非结构化（例如，临床医生记录、患者访谈文本、科学论文）的形式存在。结构化数据包含患者人口统计学信息、药物暴露史、不良事件描述（MedDRA 编码）、严重程度、结局等字段。非结构化数据则提供更丰富的叙述性细节，涉及不良事件发生过程、治疗干预及转归。数据更新频率因来源而异，上市后监测数据库通常是持续更新，而临床试验报告则在特定时间点发布。文档方面，存在大量 PDF 格式的临床研究报告、说明书和审评文件，其中包含不良反应的详细描述。

## 这些特征在「部署与升级」这一环带来什么约束

单克隆抗体药物警戒数据的多样性和复杂性对 FastGPT 的部署与升级提出了具体要求。大量非结构化文本数据（如临床报告、病例叙述）需要高效的文本嵌入和语义理解能力，这意味着在部署时需关注模型对长文本的处理能力和向量数据库的性能。频繁的数据更新要求知识库具备增量更新机制，避免全量重建带来的资源消耗和时间延迟。PDF 等文档格式的存在，对文件解析模块的鲁棒性提出了挑战，需要能够准确提取文本内容并处理表格、图片等复杂布局。此外，不良事件描述中常出现专业术语和缩略语，对分词和实体识别的准确性有较高要求，这影响到知识库的召回精度和问答质量。

## 配置怎么定

| 配置项                       | 建议取法                                   | 这样取的依据                                                 |
| :--------------------------- | :----------------------------------------- | :----------------------------------------------------------- |
| `UPLOAD_FILE_MAX_SIZE`       | `500 MB`                                   | 应对包含大量图表或扫描内容的 PDF 文档大小，避免上传失败。  |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`                                   | 单克隆抗体临床试验报告通常较长，需要足够时间完成解析。       |
| `分段长度`                   | `800–1200 字符`                            | 平衡上下文完整性和嵌入模型处理效率，适应不良事件描述的详细程度。 |
| `召回条数`                   | `前 8 条`                                  | 确保能覆盖不良反应相关信息的多个角度和上下文，提高召回准确性。 |
| `相似度阈值`                 | 按实测标定，例如 `0.75`                    | 需根据实际数据和查询语料进行测试，平衡召回的广度与精度。     |
| `maxContext`                 | `32000 token`                              | 确保处理长篇不良事件叙述和多轮追问时，模型能维持上下文。     |

## 容易做错的三处

*   部署后知识库无法连续追问，模型答非所问。这通常是由于 `maxContext` 设置过小，导致模型无法记住之前的对话历史。
*   上传大型 PDF 报告时出现超时或失败。这可能是因为 `UPLOAD_FILE_MAX_SIZE` 或 `PARSE_FILE_TIMEOUT_SECONDS` 的值不足以处理文件大小和解析复杂性。
*   Docker-compose 部署后服务启动失败，日志显示端口冲突或数据库连接错误。这通常是由于宿主机或 Docker 网络中存在端口占用，或者数据库配置参数（如 `DB_HOST`、`DB_PORT`）不正确。

## 怎么确认配好了

*   上传一份包含多页不良反应详细描述的单克隆抗体临床试验报告 PDF，确认文件能够成功解析并生成知识库分段。
*   针对上传的报告，提出一个需要联系前后文才能正确回答的复杂不良反应问题，确认模型能够连续追问并给出相关性高的回答。
*   检查 FastGPT 后台的知识库分段数量和内容，确认分段长度符合预期，并且关键的不良反应术语和描述被准确提取。
*   通过 Docker 日志或系统监控，确认所有 FastGPT 容器服务（如 `fastgpt-api`、`fastgpt-web`、`fastgpt-mongo`、`fastgpt-pg`）均处于运行状态，且无持续的错误输出。
