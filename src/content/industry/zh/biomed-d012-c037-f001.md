# 双特异性抗体药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

双特异性抗体药物警戒数据主要来源于临床试验报告、真实世界研究、上市后监测以及全球药物警戒数据库（如 WHO VigiBase、FDA FAERS）。其更新频率通常较高，尤其是上市初期和临床研究阶段，可能以周或月为单位进行报告。数据文档结构复杂，常包含患者人口统计学信息、用药史、合并用药、不良事件描述（MedDRA 编码）、不良事件发生时间、严重程度、结局、因果关系评估以及批次号等。字段方面，特异性体现在靶点组合、作用机制编码、抗体类型（如 `IgG1-bsAb`、`IgG4-bsAb`）等，单位则涉及剂量（`mg/kg`）、频率（`q2w`）、持续时间（`天`）等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

双特异性抗体数据的高更新频率要求 HTTP 接口具备高效的增量同步机制，避免全量拉取带来的性能负担。复杂的数据文档结构意味着接口返回的数据体量可能较大，需要支持分页或流式传输。不良事件的 MedDRA 编码和抗体类型等特有字段，要求外部系统在数据解析时能准确识别和处理。此外，剂量、频率等单位信息，在数据校验和整合时需进行标准化转换。因果关系评估等半结构化或自由文本字段，对接口的字符编码和文本处理能力提出要求，确保数据完整性。批次号等溯源信息则要求接口支持精确查询。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `requestTimeout` | `60000 毫秒` | 应对复杂查询和大数据量传输，避免因超时导致的数据同步失败。 |
| `maxConnections` | `按实测标定` | 确保在数据拉取高峰期能维持稳定的并发连接数，防止连接池耗尽。 |
| `batchSize` | `500–1000 条` | 兼顾单次请求的数据量与处理效率，降低内存消耗。 |
| `encoding` | `UTF-8` | 确保不良事件描述等自由文本字段的正确解析，支持多语言字符。 |
| `retryAttempts` | `3 次` | 应对网络波动或外部系统暂时性故障，提高数据同步的成功率。 |
| `pollingInterval` | `3600 秒` | 适用于定期增量同步，平衡数据实时性与外部系统负载。 |

## 容易做错的三处

*   现象：外部系统接收到的不良事件描述字段出现乱码或部分缺失。原因：HTTP 接口的字符编码设置与外部系统不一致，导致文本解析错误。
*   现象：在增量同步时，部分新报告的不良事件数据未被拉取。原因：外部系统未正确解析或利用 HTTP 接口提供的 `lastModifiedDate` 或 `sequenceId` 等时间戳/序列号字段进行增量查询。
*   现象：拉取双特异性抗体相关数据时，接口返回 `HTTP 429 Too Many Requests`。原因：未合理设置请求频率，短时间内对外部系统发起过多请求，触发了限流机制。

## 怎么确认配好了

*   通过模拟高并发请求，观察 HTTP 接口的响应时间和成功率，确保在预期负载下能稳定运行。
*   随机抽取一批包含多语言和特殊字符的不良事件报告，验证外部系统是否能完整且正确地解析所有字段。
*   在外部系统配置增量同步后，对比外部系统和源数据库中指定时间段内的新增数据，确认数据同步的完整性。
