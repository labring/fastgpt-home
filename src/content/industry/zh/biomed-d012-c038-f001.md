# 合理用药药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

合理用药药物警戒相关数据主要来源于药品说明书、临床指南、不良事件报告系统（如国家药品不良反应监测中心数据库）、医学文献以及药学知识库。这些数据更新频率不一，药品说明书和临床指南通常季度或年度更新，不良事件报告则可能每日甚至实时增加。数据文档结构复杂，常包含非结构化文本（如不良反应描述、用药医嘱）、半结构化数据（如药品成分、适应症、禁忌症）和结构化数据（如 ICD-10 疾病编码、ATC 药物分类编码）。字段方面，可能涉及药品通用名、商品名、剂量、给药途径、不良反应事件、发生时间、严重程度、患者基本信息（脱敏后）、合并用药等。单位则涵盖 mg、g、ml、IU 等剂量单位，以及天、小时等时间单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

合理用药药物警戒数据的多样性和复杂性，对 HTTP 接口的设计与外部系统集成提出了特定要求。非结构化文本字段要求接口具备处理长文本的能力，并可能需要额外的文本分析服务进行预处理。半结构化和结构化数据则需定义清晰的 JSON 或 XML 格式，确保数据传输的准确性。数据更新的实时性要求 HTTP 接口支持高并发访问，并考虑增量更新机制，以减少全量同步的资源消耗。字段中包含大量医学术语和缩写，可能需要自定义词典进行匹配和解析。此外，敏感患者信息的脱敏处理需要外部系统在数据源头或接口层进行严格控制，确保数据安全与合规性。复杂的单位转换也可能需要在接口调用方或接收方进行逻辑适配。

## 配置怎么定

| 配置项                       | 建议取法                               | 这样取的依据                                                              |
| :--------------------------- | :------------------------------------- | :------------------------------------------------------------------------ |
| `API_REQUEST_TIMEOUT_SECONDS`  | `60 秒`                                | 应对外部系统响应慢或数据量大时的延迟，避免过早超时。                      |
| `MAX_BODY_SIZE_MB`           | `10 MB`                                | 适应药品说明书或不良事件报告中可能存在的长文本或多字段数据。              |
| `RATE_LIMIT_PER_MINUTE`      | `300 次`                               | 平衡数据更新频率与外部系统承受能力，防止因高并发导致服务拒绝。            |
| `ERROR_RETRY_COUNT`          | `3 次`                                 | 应对网络波动或外部系统偶发性故障，提高数据同步的健壮性。                  |
| `CUSTOM_HEADER_AUTH_TOKEN`   | 按外部系统要求配置，例如 `Bearer xxx` | 确保与外部药学知识库或不良事件报告系统进行安全认证和授权。                |
| `DATA_SCHEMA_VALIDATION_MODE` | `严格模式`                             | 确保传入或传出的数据严格遵循预定义的结构和字段类型，减少解析错误。        |

## 容易做错的三处

*   HTTP 请求返回 4xx 或 5xx 状态码，但业务数据未正确处理。这通常是由于接口认证失败、权限不足或外部系统处理业务逻辑异常导致。
*   接口调用频繁，导致外部系统负载过高，甚至被限流。原因在于未合理配置请求频率，或未利用外部系统提供的批量查询接口。
*   接收到的数据字段缺失或格式不正确，导致后续处理逻辑报错。这多是由于外部系统数据结构变更未及时同步更新接口配置，或未进行严格的数据校验。

## 怎么确认配好了

*   通过 FastGPT 的日志系统，检查 `API_REQUEST_TIMEOUT_SECONDS` 配置下所有请求是否均在规定时间内完成响应，且无超时错误记录。
*   模拟高并发场景，观察 `RATE_LIMIT_PER_MINUTE` 配置下，外部系统是否能稳定提供服务，无频繁的限流错误码返回。
*   对来自外部系统的重要数据字段，例如 `drugName`、`adverseEventDescription` 等，进行随机抽样检查，确保其类型、格式和内容与预期一致。
*   针对 `ERROR_RETRY_COUNT` 配置，主动触发几次外部系统偶发性错误（例如临时关闭外部服务），检查 FastGPT 是否能按预期进行重试并最终成功获取数据。
