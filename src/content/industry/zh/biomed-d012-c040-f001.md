# 呼吸系统药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

呼吸系统药物警戒数据主要来源于临床试验报告、上市后监测报告、医疗机构不良事件申报、患者自发报告以及专业文献。数据更新频率通常为季度或月度，高风险药物或新上市药物可能更频繁。文档结构复杂，常包含自由文本描述、结构化字段和医学编码。结构化字段如患者基本信息、用药史、不良反应事件、严重程度、结局等。医学编码遵循国际通用标准，如 MedDRA（医学词典监管活动）编码，用于统一描述不良反应事件和疾病。剂量单位常见有毫克（mg）、微克（µg）、毫升（mL）等，事件发生时间以日期时间戳格式记录。部分非结构化数据包含患者病程、医生诊断意见和治疗方案。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

呼吸系统药物警戒数据的多源性和复杂性，要求 HTTP 接口具备强大的数据解析能力，尤其针对 MedDRA 编码和自由文本的识别。数据更新频率决定了外部系统调用接口的周期性，需要支持定时任务触发。文档结构的多样性，特别是含有大量非结构化描述，对接口的数据模型设计提出挑战，需要兼顾结构化字段的准确映射和非结构化内容的有效抽取。字段与单位的标准化是关键，接口应能处理不同来源的单位转换，例如将微克（µg）自动转换为毫克（mg），避免数据不一致。医学编码的引入，意味着接口需要与外部 MedDRA 数据库或服务进行集成，以实现编码的校验与扩展。

## 配置怎么定

| 配置项                 | 建议取法       | 这样取的依据                                   |
| :--------------------- | :------------- | :--------------------------------------------- |
| `maxContext`           | 800–1200 字符  | 兼顾自由文本描述的完整性和模型处理效率       |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒         | 应对大型临床报告或多个文件上传的解析时间     |
| `分段长度`             | 400–600 字符   | 优化长文本的处理，提高召回准确率             |
| `召回条数`             | 前 10–15 条    | 确保覆盖多源数据中的潜在关联信息             |
| `相似度阈值`           | 0.75–0.85      | 提高对不良反应事件描述的匹配精度             |
| `重排返回条数`         | 前 5 条        | 精炼最终输出，聚焦最相关的不良反应信息       |

## 容易做错的三处

*   HTTP 请求返回 `400 Bad Request` 状态码，原因是请求体中的 `MedDRA_Code` 字段格式不符合预期的编码规范。
*   外部系统定时调用接口后，发现部分不良反应事件的严重程度字段为空，原因是接口未能正确解析原始报告中的非标准严重程度描述。
*   调用接口上传包含多个附件的临床报告时，出现 `504 Gateway Timeout` 错误，原因是 `PARSE_FILE_TIMEOUT_SECONDS` 配置过短，文件解析时间超出上限。

## 怎么确认配好了

*   通过模拟请求，验证包含 MedDRA 编码的结构化数据能够被接口正确接收和处理，且返回预期的医学术语扩展。
*   上传包含自由文本描述的呼吸系统不良反应报告，检查解析后的数据中，关键实体（如药物名称、不良反应、剂量）是否被准确抽取。
*   测试不同文件大小和格式的报告上传，确认接口在 `PARSE_FILE_TIMEOUT_SECONDS` 限制内能稳定完成解析，并通过日志确认无超时报错。
