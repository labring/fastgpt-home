# 基因治疗 AAV药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

基因治疗 AAV (腺相关病毒) 药物警戒数据具有高特异性和复杂性。数据源主要包括临床试验报告、真实世界研究（RWE）数据、患者报告、以及上市后监测数据库。这些数据更新频率不一，临床试验数据通常在特定时间点批量发布，而患者报告和上市后监测数据则可能持续实时流入。文档结构多样，多为非结构化或半结构化文本，如不良事件描述、患者病史、用药史等。字段方面，除了通用药物警戒字段（如事件类型、严重程度、发生日期），基因治疗 AAV 特有字段包括 AAV 血清型、载体剂量、基因拷贝数、靶细胞类型、以及预存免疫状态等。单位通常涉及剂量（如 `vg/kg` 病毒基因组拷贝数每公斤体重）、时间（如 `天`、`周`、`月`）和生物指标（如 `IU/mL` 抗体滴度）。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

基因治疗 AAV 药物警戒数据的复杂性对 HTTP 接口设计和外部系统集成提出多重约束。首先，多源异构数据要求接口具备强大的数据解析和标准化能力，以应对不同来源和格式的数据输入。其次，高特异性字段（如 AAV 血清型、预存免疫状态）需要专门的字段映射和验证规则，确保数据准确性和一致性。再次，部分数据（如临床试验报告）的批量更新模式，要求接口支持批量数据传输和事务性处理，避免数据不完整。实时性要求较高的患者报告和上市后监测数据，则需要低延迟、高并发的接口设计。此外，生物指标单位的多样性，要求系统能正确识别和转换，以避免单位错误导致的数据误判。对非结构化文本的解析，则需要集成自然语言处理（NLP）能力。

## 配置怎么定

| 配置项                   | 建议取法                               | 这样取的依据                                                                                                                                              |
| :----------------------- | :------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `maxContext`             | `2000–3000 字符`                       | 适应 AAV 药物不良事件报告中较长的文本描述，确保上下文完整性。                                                                                            |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`                               | 应对复杂 PDF 或非结构化报告的解析，避免因解析时间过长导致超时中断。                                                                                      |
| `similarityThreshold`    | `0.75–0.85`                            | 平衡 AAV 变异株和不良事件描述的相似性召回，避免过度泛化或遗漏。                                                                                          |
| `recallCount`            | `10–15 条`                             | 考虑 AAV 药物警戒数据中潜在的罕见不良事件，增加召回条数以提高检出率。                                                                                    |
| `requestTimeoutMs`       | `30000 毫秒`                           | 应对外部系统处理 AAV 特异性数据（如基因序列比对、免疫原性评估）可能带来的较长响应时间。                                                                  |
| `customHeaders`          | `X-AAV-Type: AAV2`                     | 用于在外部系统集成时传递 AAV 血清型等关键元数据，实现精细化路由和处理。                                                                                  |

## 容易做错的三处

*   HTTP 状态码返回 `200 OK` 但响应体中关键字段（如 `adverseEventSeverity`）为空。原因通常是外部系统在处理 AAV 特有字段时映射失败或数据清洗不彻底。
*   接口调用频繁出现 `504 Gateway Timeout` 错误。原因在于外部系统处理涉及 AAV 载体剂量或基因拷贝数等复杂计算时耗时过长，超出了 FastGPT 的默认等待时间。
*   通过 HTTP 接口导入的数据，在 FastGPT 中检索时，与 AAV 血清型相关的结果匹配度低。原因可能是数据导入时未能正确识别和索引 AAV 血清型信息，或者分词策略不适合生物学专有名词。

## 怎么确认配好了

*   通过 FastGPT 的数据管理界面，随机抽取已导入的 AAV 药物警戒报告，核对其中的 AAV 血清型、载体剂量等关键字段是否与原始数据一致。
*   使用包含 AAV 特有关键词（如 `AAV5`、`肝毒性`、`免疫原性`）的查询语句，在 FastGPT 中进行检索，观察召回结果是否包含相关且准确的文档。
*   模拟外部系统向 FastGPT 发送一批包含不同严重程度、不同 AAV 载体信息的不良事件报告，并检查 FastGPT 中对应知识库的更新情况和字段解析的准确性。
*   监控 HTTP 接口的日志，确认没有出现大量 `4xx` 或 `5xx` 错误码，并且数据传输速率符合预期。
