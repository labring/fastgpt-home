# 基因治疗 AAV药物警戒的多轮对话与提示词

## 这个品类的数据长什么样

基因治疗 AAV（腺相关病毒）药物警戒数据主要来源于临床试验报告、真实世界研究（RWE）数据、上市后监管机构报告以及学术文献。这些数据通常以非结构化文本形式存在，如病例报告、随访记录、医学期刊文章，也包含结构化的实验室检测结果和患者基本信息。数据更新频率较高，临床试验数据随研究进展定期发布，上市后数据则持续累积。文档结构复杂，常包含大量医学术语、基因序列信息、病毒载体设计细节以及不良事件描述。关键字段包括患者 ID、AAV 血清型、载体剂量、给药途径、靶基因、不良反应事件（AE）描述、严重程度、发生时间、转归以及相关性评估。单位涉及病毒基因组拷贝数（vg/mL）、剂量（vg/kg）、时间（天、周、月）等。

## 这些特征在「多轮对话与提示词」这一环带来什么约束

基因治疗 AAV药物警戒数据的复杂性对多轮对话与提示词设计提出了特定要求。非结构化文本中的医学术语和专业缩写需要模型具备高精度实体识别能力，以避免误解关键信息。多轮对话需要追踪患者在不同时间点报告的多个不良事件，并能结合 AAV 载体细节进行关联分析。例如，当用户询问“该患者在给药后出现的肝酶升高与 AAV 载体剂量有关吗？”时，系统需能从历史对话和知识库中提取患者剂量、肝酶检测结果及 AAV 血清型等信息进行综合判断。此外，数据更新频率高，要求知识库能够快速同步最新研究进展和监管动态，确保对话内容的实时性和准确性。提示词设计必须精准引导用户提问，例如明确询问不良事件的发生时间、严重程度或与特定 AAV 载体的关系，以缩小搜索范围并提高回答质量。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `6` 轮 | 兼顾复杂场景的上下文理解和对话效率，避免过长上下文导致模型性能下降。 |
| `分段长度` | `800–1200 字符` | 平衡文本块的完整性和召回效率，确保单个分段能包含一个完整的不良事件描述或关键研究结论。 |
| `召回条数` | `前 5 条` | 覆盖最相关的知识点，减少无关信息干扰，提高检索效率。 |
| `相似度阈值` | `0.78–0.85` | 有效过滤掉低相关性文档，聚焦于基因治疗 AAV 药物警戒的专业内容。 |
| `重排返回条数` | `前 3 条` | 进一步精炼结果，确保呈现给用户的信息是最核心、最相关的。 |
| `prompt` | 按实测标定 | 根据特定 AAV 血清型或靶基因的查询需求，动态调整提示词以优化召回与生成。 |

## 容易做错的三处

- 报错信息显示“API Key 无效或权限不足”。原因在于使用了错误的 API Key 类型，例如尝试用全局通用 API Key 调用应用对话接口，或者 Key 未绑定对应的应用权限。
- 对话中模型无法准确关联不同轮次提及的患者不良事件。原因在于 `maxContext` 参数设置过小，导致模型丢失了关键的上下文信息，无法进行有效的多轮推理。
- 回答中出现大量与 AAV 药物警戒无关的通用医学知识。原因在于 `相似度阈值` 设置过低，导致召回了大量非特异性的文档分段，稀释了专业性。

## 怎么确认配好了

- 进行多轮对话测试，验证模型是否能准确理解并关联前几轮对话中提及的患者信息、AAV 载体细节和不良事件描述。
- 模拟查询特定 AAV 载体的不良事件发生率或严重程度，检查模型能否从知识库中召回并整合相关数据。
- 提交包含专业医学术语和基因序列信息的复杂问题，评估模型回答的准确性和专业性，确认回答内容是否紧扣基因治疗 AAV 药物警戒领域。
