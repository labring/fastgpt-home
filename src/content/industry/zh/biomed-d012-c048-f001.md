# 家用医疗药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

家用医疗器械的药物警戒数据主要来源于用户通过App、智能设备上传的日志、健康报告，以及售后服务记录和用户反馈。数据更新频率通常为实时或准实时，取决于设备连接状态和用户使用习惯。文档结构呈现多样性，包括非结构化的用户文本描述、半结构化的事件报告表单以及结构化的设备传感器数据。字段方面，除了常规的时间戳、设备ID、用户ID外，还包含如`device_model`（设备型号）、`firmware_version`（固件版本）、`event_type`（事件类型，如“异常心率”、“血糖超标”）、`measurement_value`（测量值）、`unit_of_measure`（测量单位，如“mg/dL”、“bpm”）、`user_comment`（用户评论）等特有字段。数据量相对分散，但单个事件的详细程度较高。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

家用医疗数据的实时性和多样性对HTTP接口设计提出了高要求。事件触发型的数据上传（如异常事件）需要接口具备高并发处理能力，以避免数据积压和延迟。非结构化`user_comment`字段的存在，要求接口能够接收大文本数据，并可能需要支持文件上传以处理用户提交的图片或视频证据。半结构化的事件报告表单，意味着请求体中需要包含复杂嵌套的JSON或XML结构。此外，设备固件版本和测量单位的差异性，要求外部系统在接收数据时能进行灵活的解析和标准化处理，例如，`unit_of_measure`字段可能包含“mmol/L”或“mg/dL”，接口下游系统需要进行单位转换。数据来源的分散性也意味着需要多个独立的HTTP接口端点，或者一个统一接口通过特定参数区分不同数据类型。

## 配置怎么定

| 配置项                   | 建议取法                                 | 这样取的依据                                       |
| :----------------------- | :--------------------------------------- | :------------------------------------------------- |
| `request_timeout_seconds` | `30 秒`                                  | 保证实时事件处理，避免长时间等待导致数据堆积。     |
| `max_payload_size_mb`    | `5 MB`                                   | 适应用户评论、图片等可能较大的请求体，平衡性能。   |
| `api_endpoint_url`       | `https://api.example.com/medical/events` | 统一入口，便于管理和安全防护，通过路径区分不同事件。 |
| `max_retries`            | `3 次`                                   | 应对网络波动或外部系统短暂不可用，提高数据传输可靠性。 |
| `backoff_factor`         | `1.5`                                    | 指数退避，防止重试风暴，给外部系统恢复时间。       |
| `content_type`           | `application/json`                       | 适应半结构化数据，便于解析和处理复杂数据结构。     |

## 容易做错的三处

*   HTTP 状态码返回 `200 OK` 但实际业务处理失败，导致数据未正确入库。这通常是因为仅检查了HTTP连接层面，而未验证响应体中的业务错误码或成功标识。
*   上传用户反馈图片或视频时，接口返回 `413 Payload Too Large` 错误。这表明HTTP服务器或网关的请求体大小限制低于实际业务需求。
*   外部系统接收到的测量值单位不一致，例如血糖数据混用“mmol/L”和“mg/dL”。这是由于接口未强制要求或未正确处理`unit_of_measure`字段的标准化。

## 怎么确认配好了

*   通过模拟工具发送包含大文本`user_comment`和复杂JSON结构的请求，验证接口能够成功接收并返回 `200 OK` 状态码，且响应体中包含业务成功标识。
*   使用不同 `device_model` 和 `firmware_version` 的模拟数据，调用接口后检查外部系统是否能正确解析和存储这些特有字段。
*   发送包含不同 `unit_of_measure`（如“mmol/L”和“mg/dL”）的测量数据，核对外部系统内存储的数据是否已按预期进行单位转换或标准化处理。
