# 小分子化药药物警戒的工具调用与插件

## 这个品类的数据长什么样

小分子化药的药物警戒数据主要来源于国家药品监督管理局（NMPA）、FDA、EMA 等监管机构的药品不良反应报告系统、临床试验数据库、上市后监测数据以及学术期刊。这些数据更新频率较高，尤其是不良反应报告，可能按日或周更新。文档结构通常包含药品基本信息、活性成分、适应症、用法用量、不良反应事件描述、事件发生时间、严重程度、结局、相关实验室检查结果等字段。字段单位多样，例如剂量单位毫克（mg）、微克（μg），时间单位天、小时，实验室指标单位如 mmol/L、U/L 等。不良反应描述常以非结构化文本形式存在，需要进行自然语言处理。

## 这些特征在「工具调用与插件」这一环带来什么约束

小分子化药不良反应报告的非结构化文本特性，要求工具调用与插件具备强大的文本处理能力，例如利用 NLP 工具从报告中提取结构化信息。高频数据更新对数据同步与增量处理提出要求，需要工具插件能定期拉取最新数据并高效整合。多样的字段单位意味着在进行数据比对或分析时，需确保单位一致性或进行单位转换，这可能通过预处理插件或在工具调用时指定转换函数实现。同时，数据源的合规性与安全性是核心考量，工具调用需遵循严格的数据访问权限和安全协议，尤其是在涉及患者隐私信息时。对于结构化数据，工具调用需要精确的字段映射，以确保数据在不同系统间的准确传输和解析。

## 配置怎么定

| 配置项                       | 建议取法                                 | 这样取的依据                                                 |
| :--------------------------- | :--------------------------------------- | :----------------------------------------------------------- |
| `API_TIMEOUT_SECONDS`        | `300 秒`                                 | 应对外部API调用可能存在的网络延迟或复杂计算耗时，尤其是涉及大规模数据处理的场景。 |
| `MAX_RETRIES`                | `3`                                      | 提高外部工具调用的稳定性，减少因瞬时网络波动或服务暂时不可用导致的失败。 |
| `CHUNK_SIZE_KB`              | `1024 KB`                                | 优化文件上传和处理效率，平衡内存占用与传输速度。             |
| `FILE_PARSER_CONCURRENCY`    | `5`                                      | 考虑小分子化药文档（如临床报告）可能包含大量文本，多并发处理能加快解析速度。 |
| `EXTERNAL_TOOL_SCHEMA`       | 按实际工具 API 文档定义                  | 确保 FastGPT 能正确理解和构造工具调用的请求体与解析响应。    |
| `DATA_SYNC_INTERVAL_HOURS`   | `24 小时`                                | 兼顾不良反应数据更新频率（通常按日或周）与系统资源消耗，可根据实际需求调整。 |

## 容易做错的三处

*   调用外部工具时，返回的 JSON 字段缺失或类型不匹配，导致后续处理失败。这通常是由于未严格遵循工具 API 的响应契约，或工具端返回的数据结构发生变化但未及时更新 FastGPT 中的配置。
*   在处理药物不良反应报告文本时，提取的实体（如药品名、症状）不准确或遗漏。这源于 NLP 插件的预训练模型对特定医学术语的识别能力不足，或未针对小分子化药的语言特征进行微调。
*   工具调用后，数据同步任务长时间未完成或报错，检查日志发现连接超时或认证失败。原因多是外部数据源的 API 密钥过期、IP 白名单限制或网络策略变更，但 FastGPT 侧的凭证或网络配置未及时更新。

## 怎么确认配好了

*   通过 FastGPT 界面手动触发一次工具调用，检查其返回结果是否符合预期的数据结构和内容。
*   配置一个包含小分子化药不良反应报告的测试集，运行批处理任务，验证提取的结构化信息与人工标注结果的符合度。
*   模拟外部数据源的增量更新，检查 FastGPT 的数据同步插件是否能准确识别并导入新的不良反应事件，同时确认历史数据未受影响。
*   检查 FastGPT 的日志系统，确认工具调用过程中没有出现 `connection timeout`、`authentication failed` 或 `schema validation error` 等关键错误信息。
