# 市场准入药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

市场准入阶段的药物警戒数据主要来源于临床试验报告、早期上市后观察性研究以及相关监管机构发布的指导文件。这些数据通常以结构化或半结构化的形式存在，例如 CSV、JSON 或 XML 文件，也可能包含非结构化的文本报告。数据更新频率在早期上市阶段通常较高，可能按月或按季度更新，以反映药物在真实世界中的安全性表现。文档结构复杂，常包含药物活性成分、适应症、不良事件术语（如 MedDRA 编码）、严重程度、发生频率、相关性评估及处理措施等字段。单位涉及剂量（mg、g）、频率（次/日）、时间（天、周、月）等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

高频次的数据更新要求 HTTP 接口具备高效的增量同步机制，避免全量拉取导致的资源浪费。数据源的多样性与复杂结构，特别是 MedDRA 编码等专业术语，对接口的数据解析能力提出要求，需要支持多种数据格式的解析器。鉴于数据敏感性，接口的安全认证与授权机制至关重要，例如 OAuth 2.0 或 API Key 验证。对于非结构化文本报告，需要额外的文本处理模块进行信息抽取。字段的专业性和单位的规范性，要求接口能够准确映射并处理这些信息，避免数据语义丢失。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `API_ENDPOINT` | `https://api.example.com/pv/v1/adverse_events` | 外部系统提供的标准 API 接口地址，明确指向不良事件数据。 |
| `AUTH_HEADER` | `Authorization: Bearer YOUR_TOKEN` | 使用 OAuth 2.0 令牌进行身份验证，确保数据传输的安全性。 |
| `REQUEST_METHOD` | `POST` 或 `GET` | 根据外部系统 API 文档要求，`GET` 用于查询，`POST` 用于数据提交或复杂的查询。 |
| `RETRY_COUNT` | `3` | 应对网络瞬时抖动或外部系统暂时性故障，提高数据同步的稳定性。 |
| `TIMEOUT_SECONDS` | `60` | 避免因外部系统响应缓慢导致请求长时间阻塞，影响整体性能。 |
| `DATA_FORMAT` | `JSON` | 外部系统通常采用 JSON 格式进行数据交换，便于结构化数据的解析与处理。 |

## 容易做错的三处

*   现象：API 调用返回 401 或 403 错误码。原因：`AUTH_HEADER` 配置的令牌过期或权限不足，未能通过外部系统的身份验证或授权。
*   现象：HTTP 请求成功，但返回的数据内容为空或不完整。原因：`REQUEST_METHOD` 或请求体参数与外部系统 API 文档不符，导致查询条件未正确传递或数据过滤错误。
*   现象：知识库关联失败，提示“知识库 ID 无效”或“关联操作未授权”。原因：在尝试通过接口关联知识库时，未提供正确的知识库标识符或缺乏执行此操作的必要权限。
