# 干细胞治疗药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

干细胞治疗药物警戒数据主要来源于临床试验报告、真实世界研究（RWE）、患者自愿报告以及监管机构发布的安全性更新。这些数据通常以非结构化文本（如医学记录、病例报告表）和结构化表格（如不良事件报告系统数据）的形式存在。数据更新频率较高，尤其是在新产品上市初期，可能每日都有新报告产生。文档结构复杂，包含患者基本信息、治疗方案、不良事件描述、严重程度、结局、相关性评估等字段。特别需要关注的是，干细胞产品的批次号、细胞来源、制备工艺等信息是其特有字段，且不良事件描述中常涉及细胞毒性、免疫原性、移植物抗宿主病（GVHD）等专有医学术语。剂量单位可能涉及细胞数（如 `10^6 cells/kg`）或体积（如 `mL`）。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

干细胞治疗数据的高更新频率要求 HTTP 接口具备高并发处理能力和低延迟响应，以确保不良事件报告能及时录入和分析。数据来源多样性意味着接口需要支持多种数据格式的解析，例如 JSON、XML 或表单数据，并能处理不同数据源的字段映射与标准化。非结构化文本的存在，尤其是医学记录和患者报告，要求外部系统具备强大的自然语言处理（NLP）能力，能从自由文本中准确提取关键不良事件信息、干细胞产品特有属性及相关性判断。此外，由于涉及患者隐私和敏感医疗信息，接口传输必须采用加密协议（如 HTTPS），且外部系统需符合 HIPAA、GDPR 等数据安全与隐私法规要求。干细胞特有字段的准确识别和解析，直接影响警戒信号的发现与风险评估。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `requestTimeout` | `60000 ms` | 应对复杂数据传输和外部系统处理时间，防止因超时导致的数据丢失。 |
| `maxConnections` | `100` | 保证在并发报告高峰期，系统能有效处理多路数据请求。 |
| `contentType` | `application/json;charset=UTF-8` 或 `application/xml` | 适配主流数据交换格式，提高数据解析的兼容性和准确性。 |
| `headers` | 包含 `Authorization: Bearer <token>` | 确保接口调用的安全性，通过身份验证机制保护敏感数据。 |
| `retryAttempts` | `3` | 应对网络瞬时抖动或外部系统短暂不可用，提高数据传输的可靠性。 |
| `payloadSizeLimit` | `5 MB` | 考虑单个不良事件报告可能包含较长的文本描述或附件，避免因请求体过大被拒绝。 |

## 容易做错的三处

- HTTP 模块返回 `4xx` 或 `5xx` 状态码，但未配置重试或告警机制，导致部分不良事件数据未能成功提交，原因是外部系统暂时性故障或认证信息过期。
- 接收到的不良事件报告中，干细胞产品的批次号、细胞来源等关键特有字段为空，原因是接口数据映射配置不准确，未能正确识别和抽取这些字段。
- 外部系统处理速度过慢，导致 FastGPT 工作流中的 HTTP 请求频繁超时，原因是 `requestTimeout` 设置过短，未能充分考虑外部系统处理复杂医学文本所需的时间。

## 怎么确认配好了

- 通过模拟大量不良事件报告数据，观察 HTTP 接口的响应时间和成功率，确保在峰值负载下仍能稳定运行。
- 对接后，随机抽取一定数量的报告，比对 FastGPT 处理后的数据与原始数据，核对干细胞特有字段（如批次号、细胞来源）的提取准确性。
- 验证外部系统是否能正确解析和存储所有接收到的数据，并定期检查其日志，确认没有因数据格式不匹配或字段缺失而产生的错误记录。
