# 康复设备药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样
康复设备产生的不良事件数据通常来源于医院不良事件上报系统、患者随访记录、生产企业售后反馈以及监管机构报告。这些数据更新频率不一，医院上报可能实时或按批次，患者随访则有固定周期。数据文档结构复杂，包含结构化字段如设备型号、序列号、事件类型、发生日期，也包含大量非结构化描述，如患者主诉、医生诊断、处理过程。字段与单位方面，涉及设备运行参数如 `功率 (W)`、`时长 (min)`，患者生理指标如 `心率 (bpm)`、`血氧饱和度 (%)`，以及不良事件严重程度的定性描述。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
康复设备不良事件数据来源多样且更新频率不同，要求 HTTP 接口具备高并发处理能力，能够适应突发性数据高峰，并支持多种数据格式的接收。数据文档中结构化与非结构化信息并存，使得在接口设计时需要考虑字段的灵活扩展性，以便捕获详尽的上下文信息。特别是患者主诉和医生诊断等非结构化文本，需要支持长文本传输，并可能涉及特定医学术语的编码或标准化处理。此外，设备运行参数和生理指标的字段单位必须明确，避免因单位混淆导致的数据误判，这要求接口在数据校验环节能识别并处理单位信息。历史数据的批量导入与增量更新机制也需要接口能有效区分，以确保数据完整性与时效性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `requestTimeout` | `60000 ms` | 处理包含长文本和多附件的请求，避免因数据量大导致超时中断 |
| `maxConnections` | `100` | 应对多源头数据上报的并发请求，确保系统稳定性 |
| `payloadSizeLimit` | `10 MB` | 支持上传包含详细描述和少量图片附件的不良事件报告 |
| `retryAttempts` | `3 次` | 应对网络波动或外部系统暂时性不可用造成的传输失败 |
| `authMethod` | `Bearer Token` | 确保数据传输的安全性与接口访问的权限控制 |
| `dataEncoding` | `UTF-8` | 确保包含多语言或特殊字符的描述性文本能正确解析 |

## 容易做错的三处
1. 接口返回 `HTTP 500 Internal Server Error`，原因是后端解析非结构化文本时，未对特定医学术语进行预处理，导致解析器异常。
2. 接收到的不良事件报告中，设备运行参数字段为空，原因是对接方系统未强制要求填写，而接口未进行非空校验。
3. 外部系统调用接口时返回 `401 Unauthorized`，原因是 `Bearer Token` 配置过期或未正确传递。

## 怎么确认配好了
1. 使用Postman等工具模拟多种不良事件报告场景，包括结构化数据、长文本描述、多附件等，检查接口是否返回 `HTTP 200 OK` 状态码，并确认数据在FastGPT中正确入库。
2. 验证数据入库后，随机抽取数条记录，核对 `设备型号`、`事件类型`、`发生日期` 等关键字段，以及 `功率 (W)`、`时长 (min)` 等带单位的数值字段是否与原始数据一致，单位是否被正确识别。
3. 模拟并发请求，观察系统资源占用情况，并检查是否有请求因超时或连接数限制而被拒绝，以确定 `maxConnections` 和 `requestTimeout` 是否合理。
4. 故意提交包含不规范 `Bearer Token` 的请求，确认接口返回 `HTTP 401 Unauthorized`，验证安全配置是否生效。
