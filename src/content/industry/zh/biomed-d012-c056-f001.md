# 心血管药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样
心血管药物警戒数据主要来源于临床试验报告、真实世界研究、不良事件自发报告系统（如 FDA FAERS、WHO VigiBase）以及医学文献。这些数据更新频率较高，尤其自发报告系统通常是持续接收和处理新报告。文档结构多样，包括结构化的病例报告表（CRF）、半结构化的医学文本（如出院小结、门诊病历）以及非结构化的文献摘要。结构化数据中，常见字段包括患者基本信息、用药史、不良事件描述（MedDRA 编码）、事件发生与结局时间、实验室检查结果等。单位方面，剂量常涉及 `mg`、`g`、`IU`，时间单位为 `天`、`小时`，血压单位为 `mmHg`，心率单位为 `次/分钟`。特别的是，心血管领域常涉及心电图（ECG）数据，其解读结果通常以文本形式存在，包含复杂术语。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
心血管药物警戒数据的高更新频率要求 HTTP 接口具备高效的增量同步机制，避免重复上传和处理历史数据。多样化的文档结构意味着接口需要支持多种数据格式，例如 JSON 用于结构化数据，XML 或纯文本用于半结构化和非结构化内容。特别是来自自发报告系统的数据，可能存在大量非标准化的自由文本，需要后端在数据摄入阶段进行预处理和标准化，这对接口的数据承载能力和处理时效性提出要求。MedDRA 编码的准确映射是关键，接口在接收不良事件描述时，可能需要额外调用外部本体服务进行实时编码或验证。心血管特有的生理参数单位，如血压、心率等，在数据传输时必须严格保持一致，避免因单位转换错误导致的数据偏差。此外，由于数据敏感性，接口的安全认证和传输加密（如 HTTPS）是强制性要求。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `PUSH_DATA_API_TIMEOUT` | `600 秒` | 应对批量数据上传时，外部系统处理时间较长的情况，避免因超时中断。 |
| `MAX_FILE_SIZE_MB` | `50 MB` | 兼顾上传包含多份报告的压缩包或大型文献附件的需求，平衡传输效率。 |
| `BATCH_CHUNK_SIZE` | `100 条` | 针对不良事件报告等结构化数据，分批处理可提高系统吞吐量和错误隔离能力。 |
| `CONCURRENT_REQUEST_LIMIT` | `5` | 限制并发请求数量，避免对外部报告系统或本体编码服务造成过大压力。 |
| `RETRY_STRATEGY` | 线性退避，`3 次` | 应对网络波动或外部系统瞬时过载，提高数据传输的健壮性。 |
| `HTTP_AUTH_TYPE` | `Bearer Token` | 提供安全的 API 访问控制，令牌过期可刷新，符合行业安全规范。 |

## 容易做错的三处
*   HTTP 请求返回 400 状态码，并提示 `Invalid MedDRA Code`：原因通常是上传的不良事件描述未通过外部本体编码服务的验证，或本地映射表未及时更新。
*   数据同步后，部分患者的血压或心率数据为空：原因可能是外部系统传输时未包含单位信息，或接口未正确解析带有 `mmHg` 或 `次/分钟` 等单位的字段。
*   上传大型文献 PDF 后，长时间显示“索引中”：原因可能为 `PARSE_FILE_TIMEOUT_SECONDS` 设置过短，导致文件解析服务在处理复杂文档时超时中断。

## 怎么确认配好了
*   选取涵盖不同数据类型（结构化、半结构化、非结构化）的样本数据，通过 HTTP 接口上传，检查 FastGPT 中对应知识库的字段内容是否完整且准确。
*   模拟一次包含已知错误 MedDRA 编码的请求，验证接口是否能正确返回错误提示，并检查错误日志中是否有相应的记录。
*   上传一个接近 `MAX_FILE_SIZE_MB` 上限的大文件，监控上传进度和处理时间，确保在 `PUSH_DATA_API_TIMEOUT` 内完成，并检查知识库中文件内容是否可检索。
