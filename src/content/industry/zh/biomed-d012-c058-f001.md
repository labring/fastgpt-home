# 患者援助药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

患者援助项目（PAP）药物警戒数据主要包含患者注册信息、用药记录、不良事件报告（ADR）以及随访情况。数据来源多样，包括医疗机构、患者自报、项目管理方等。更新节奏通常是准实时或每日批量更新，尤其是不良事件报告，需要及时录入。数据文档通常以结构化格式为主，例如 JSON、XML 或 CSV，其中可能包含嵌套结构。关键字段包括患者唯一标识 `patient_id`、药品名称 `drug_name`、不良事件描述 `adverse_event_description`、事件发生日期 `event_date`、严重程度 `severity`（例如：轻度、中度、重度），以及报告来源 `report_source`。时间字段通常精确到日或时分秒，例如 `2023-10-27 14:30:00`。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

患者援助数据的多源性与实时性要求，决定了 HTTP 接口需要支持多种数据格式的解析能力，并能处理高并发的写入请求。不良事件报告的及时性意味着接口响应时间必须足够短，以避免数据延迟导致的安全风险。结构化数据的特点，要求接口能精确映射外部系统数据字段到 FastGPT 知识库或 Agent 的变量中，特别是像 `severity` 这样的枚举值，需要进行规范化处理。历史数据的批量导入与定期更新，则要求 HTTP 接口支持高效的数据同步机制，例如增量更新或全量覆盖。此外，敏感患者信息的处理，意味着接口必须具备严格的身份验证与授权机制，并确保数据传输的加密性，例如使用 HTTPS 协议。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `HTTP 方法` | `POST` 或 `PUT` | 适用于创建或更新不良事件报告，支持批量数据传输。 |
| `Content-Type` | `application/json` | 适应主流外部系统数据格式，易于解析和处理。 |
| `超时时间` | `3000–5000 毫秒` | 确保实时不良事件报告的及时响应，避免长时间阻塞。 |
| `认证方式` | `Bearer Token` 或 `API Key` | 提供安全的接口访问控制，保护患者数据隐私。 |
| `请求体大小限制` | `5-10 MB` | 适应单次批量导入或多条不良事件报告的数据量。 |
| `错误码映射` | `自定义` | 将外部系统错误码映射为 FastGPT 可理解的错误类型，便于失败处理。 |

## 容易做错的三处

*   外部系统向 FastGPT 接口发送数据后，FastGPT 侧未收到数据或部分字段缺失。原因在于外部系统 `Content-Type` 设置不正确或请求体 JSON 结构与 FastGPT 期望不符。
*   接口调用频繁出现 `401 Unauthorized` 或 `403 Forbidden` 错误。原因通常是 `Authorization` 请求头中的 Bearer Token 过期、无效，或 API Key 未正确配置。
*   数据库工作流执行报错，提示 SQL 语句查不出数据。原因可能是外部系统传入的查询参数（例如 `patient_id`）与数据库中实际存储的字段类型或值不匹配。

## 怎么确认配好了

*   通过外部系统发送一个模拟的不良事件报告数据，观察 FastGPT 知识库中是否新增了对应的文档，并核对关键字段（如 `adverse_event_description`、`severity`）内容是否准确。
*   在 FastGPT 接口日志中检查是否有 `200 OK` 或 `201 Created` 的 HTTP 状态码，并确认请求处理时间是否符合预期。
*   使用 FastGPT 的 Agent 调试功能，通过模拟用户提问，验证 Agent 是否能正确检索并利用通过 HTTP 接口导入的不良事件数据进行回复，例如查询某个患者的历史不良事件。
*   检查外部系统发送大量数据时，FastGPT 接口的并发处理能力和错误处理机制是否正常工作，尤其关注 `5xx` 错误码的出现频率。
