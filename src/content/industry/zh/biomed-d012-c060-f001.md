# 感染性疾病药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

感染性疾病领域的药物警戒数据主要来源于临床试验报告、真实世界观察、患者自发报告以及专业文献。数据更新频率较高，尤其是在新发传染病流行期间，可能出现每日甚至每小时的数据增量。文档结构呈现多样性，包括结构化的病例报告表（CRF）、半结构化的患者随访记录、以及非结构化的医学文本（如医生手写病历、患者描述）。字段方面，除了常规的患者基本信息、用药史、不良事件描述外，还会特别关注病原体信息、感染部位、疾病严重程度评分（如 SOFA 评分）、治疗方案调整、以及微生物药敏结果等。单位方面，剂量常涉及毫克/公斤、毫升/小时等，时间单位精确到小时或天，而实验室检测结果则有各自特定的计量单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

感染性疾病数据更新频率高，要求 HTTP 接口具备高吞吐量和低延迟，以支持实时或准实时的信息同步。大量非结构化文本的存在，使得常规的结构化数据接口不足以高效处理，需要引入文本解析和信息抽取服务。病原体、感染部位等特有字段，在外部系统集成时需确保数据模型能够准确映射，避免信息丢失或误解。复杂的单位体系要求接口在数据传输时能明确标识单位或提供单位转换机制。此外，敏感的患者隐私信息（如 HIV 感染状态）在 HTTP 传输中必须强制使用 HTTPS 协议，并考虑数据脱敏处理。面对突发疫情，外部系统可能需要快速扩容以应对数据洪峰，对接口的稳定性与可伸缩性提出更高要求。

## 配置怎么定

| 配置项             | 建议取法                                        | 这样取的依据                                                 |
| :----------------- | :---------------------------------------------- | :----------------------------------------------------------- |
| `maxConcurrentRequests` | 按实测标定，例如 `20-50` 个并发请求                  | 感染性疾病数据更新快，需要较高并发处理能力，同时避免过载。   |
| `requestTimeoutSeconds` | `30` 秒                                         | 确保接口响应及时，避免长时间等待导致数据延迟。               |
| `chunkSize`        | `500-800` 字符                                    | 非结构化文本较多，适中分段长度有助于提高嵌入和检索质量。     |
| `maxRetryAttempts` | `3` 次                                          | 网络波动或外部系统瞬时故障时，提供有限重试机制增强鲁棒性。   |
| `securityProtocol` | `HTTPS`                                         | 传输患者敏感信息，强制加密以保障数据安全。                   |
| `dataValidationSchema` | 严格定义病原体、感染部位等特有字段的枚举值或格式 | 确保感染性疾病特有字段的数据质量和一致性。                   |

## 容易做错的三处

*   现象：外部系统接收到的不良事件报告中，病原体或感染部位字段为空。原因：HTTP 接口在数据映射时，未正确识别或抽取非结构化文本中的特定实体。
*   现象：在处理大规模疫情数据时，HTTP 接口频繁出现 `503 Service Unavailable` 错误。原因：未充分预估数据量增长，`maxConcurrentRequests` 设置过低，导致系统处理能力不足。
*   现象：知识库检索结果中，针对特定药物剂量的查询，返回结果与实际不符。原因：HTTP 接口传输的剂量数据未明确单位，导致知识库在解析时单位混淆。

## 怎么确认配好了

*   通过模拟高并发请求，检查 HTTP 接口的响应时间和错误率，确保在预期负载下能稳定运行。
*   随机抽取多份包含非结构化描述的感染性疾病报告，通过接口导入外部系统，核对病原体、感染部位等关键字段是否准确抽取并映射。
*   设计包含不同计量单位的药物剂量数据，通过接口传输，验证外部系统是否能正确解析并保留单位信息或进行合理转换。
