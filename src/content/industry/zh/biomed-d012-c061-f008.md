# 手术机器人药物警戒的工具调用与插件

## 这个品类的数据长什么样

手术机器人药物警戒的数据主要来源于器械制造商提交的上市后监测报告、医院不良事件报告系统、以及监管机构的数据库。这些数据更新频率不一，制造商报告可能按季度或年度提交，而医院报告则可能实时录入。文档结构通常包含结构化字段，如器械型号、批次、不良事件代码（如 MedDRA 编码）、患者信息（脱敏）、操作过程记录、以及非结构化的自由文本描述。字段单位涉及时间（日期、时长）、数量（台次、件数）、严重程度分级（1-5级）、以及操作参数（如力矩单位 N·m，角度单位 °）。

## 这些特征在「工具调用与插件」这一环带来什么约束

手术机器人相关不良事件报告中，存在大量非结构化文本，这要求工具调用时能有效处理长文本内容的摘要与实体识别，避免关键信息丢失。字段单位的差异，例如力矩和角度，意味着在数据预处理或插件调用时需要进行单位归一化或明确指定单位，防止数值误解。更新频率的不一致性，特别是监管数据库的周期性更新，决定了数据同步插件的调度策略，不能采用高频实时同步，需要适应批量更新模式。此外，不良事件报告中常涉及多方系统数据交叉引用，要求工具能够通过 ID 或编码进行跨系统查询与关联，实现数据链的完整性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `3000 Tokens` | 适应不良事件报告中常见的中长文本描述，兼顾处理效率。 |
| `分段长度` | `500 字符` | 确保文本分段能保留上下文语义，同时避免单段过长影响召回效率。 |
| `召回条数` | `前 8 条` | 覆盖相关度较高的多个潜在知识点，提高信息完整性。 |
| `重排返回条数` | `前 3 条` | 经过重排模型筛选，聚焦于最相关的核心信息，减少冗余。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `180 秒` | 处理PDF格式的手术记录或设备日志时，预留充足的解析时间。 |
| `MedDRA_Code_Extractor.enabled` | `True` | 自动识别并提取不良事件报告中的标准 MedDRA 编码，实现结构化信息提取。 |

## 容易做错的三处

*   调用工具后返回 400 错误，提示 "Messages with role 'tool' must be a response to a preceding message"。原因在于工具调用执行成功后，结果未能正确回传给模型，或者回传格式不符合协议，导致上下文错乱。
*   知识库检索结果未能有效排序，导致关键信息沉底。原因在于对重排模型的配置不当，例如 `重排返回条数` 设置过高，或者重排模型本身未被正确激活，导致仅依赖向量相似度召回。
*   插件未能成功控制外部机械臂或机器人系统。原因在于 Python 运行环境缺少必要的控制库，或者插件中的 API 密钥、IP 地址等连接参数配置错误。

## 怎么确认配好了

*   通过测试调用，观察工具执行日志，确认 `tool_code` 和 `tool_result` 字段是否按预期填充，且无异常报错信息。
*   进行多轮对话测试，输入包含长文本不良事件描述的查询，检查回答中是否准确引用了报告中的关键细节和 MedDRA 编码。
*   模拟不良事件查询场景，比对模型回答与预期结果，确认 `重排返回条数` 是否有效地将最相关的知识条目置于前列。
*   针对机器人控制插件，检查插件执行时是否能通过 `API_KEY` 和 `ENDPOINT_URL` 等参数成功连接到外部系统，并接收到正确的响应码，例如 `200 OK`。
