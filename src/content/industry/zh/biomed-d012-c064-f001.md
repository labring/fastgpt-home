# 抗体偶联药物 ADC药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

抗体偶联药物（ADC）药物警戒数据主要来源于临床试验报告、真实世界研究、上市后监测以及患者自发报告。这些数据通常以结构化和半结构化形式存在，涉及药物批次、患者人口统计学信息、给药方案、不良事件（AE）描述、严重程度、结局、相关性评估及采取的措施等。数据更新频率较高，特别是上市后监测阶段，需要持续收集并快速响应新出现的不良反应信号。文档结构方面，常见的有 ICH E2B 格式的 XML 文件，其中包含如 `patient.reaction.reactionmeddrapt`（不良反应 MedDRA 首选术语）、`drug.drugcharacterization`（药物特征）等字段。此外，还有非结构化的临床笔记、病理报告等文本数据。数据的特殊性在于其高度专业化的医学术语，以及不良反应与特定抗体、连接子、细胞毒药物三者之间复杂关联的表达方式。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

ADC 药物警戒数据的复杂性对 HTTP 接口与外部系统提出了特定要求。首先，高频率的数据更新和大量结构化/半结构化数据要求接口具备高吞吐量和稳定的数据传输能力，以支持持续的数据摄入。其次，ICH E2B XML 等专业格式的解析能力是必须的，需要针对 `messageheader.messagetype` 和 `safetyreport.safetyreportid` 等关键字段进行准确识别和提取。非结构化文本数据则需要接口能够接收并传递给后续的自然语言处理（NLP）模块进行实体识别和事件抽取。此外，ADC 药物不良反应的特异性，例如免疫原性、脱靶毒性等，要求系统能处理具有特定医学编码和本体论关联的字段，例如 MedDRA 编码的 `reaction.reactionoutcome`。数据量大且涉及敏感患者信息，对接口的安全性和数据完整性校验也提出了严格要求，例如使用 HTTPS 和 API Key 进行认证，以及对接收到的数据进行 `checksum` 校验。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxPayloadSize` | `50 MB` | 考虑到 ICH E2B 文件可能包含大量不良事件报告，单个请求体大小需支持大规模数据传输。 |
| `requestTimeoutSeconds` | `600 秒` | 处理大型 XML 文件或批量数据上传时，解析和处理时间可能较长，避免因超时导致失败。 |
| `contentType` | `application/xml; charset=utf-8` | ADC 药物警戒数据常以 XML 格式传输，明确指定内容类型有助于正确解析。 |
| `errorHandlingStrategy` | `重试 3 次，间隔 30 秒` | 应对网络瞬时波动或外部系统临时不可用，提高数据传输的健壮性。 |
| `authenticationMethod` | `API Key` | 确保只有授权的外部系统能访问接口，保护敏感的药物警戒数据。 |
| `dataValidationSchema` | `ICH E2B R3 XML Schema` | 严格按照行业标准验证传入数据的结构和字段，保证数据质量和合规性。 |

## 容易做错的三处

*   HTTP 请求返回 `400 Bad Request` 错误，常见原因是上传的 XML 文件不符合 ICH E2B 规范，例如缺少 `safetyreport.safetyreportversion` 字段或结构错误。
*   接口调用成功但部分关键字段（如 `reaction.reactionmeddrapt`）为空，这往往是由于外部系统在生成数据时未正确映射或编码医学术语，导致 FastGPT 无法识别。
*   大量数据提交后系统响应缓慢或出现 `504 Gateway Timeout`，可能的原因是 `requestTimeoutSeconds` 配置过短，无法应对处理复杂或大规模 XML 数据所需的计算时间。

## 怎么确认配好了

*   通过提交一个包含完整不良事件报告的 ICH E2B XML 文件，检查接口是否成功返回 `200 OK` 状态码，并确认所有关键字段（如 `drug.drugname` 和 `patient.patientinitial`）均已正确解析入库。
*   使用一个故意篡改的 XML 文件（例如，修改一个必填字段的格式），测试接口是否能够返回 `400 Bad Request` 错误并提供清晰的错误信息，表明数据验证机制已生效。
*   持续监测接口的请求延迟和成功率指标，确保在高并发数据传输场景下，请求延迟维持在可接受的范围内，并且成功率接近 100%，以验证 `requestTimeoutSeconds` 等性能相关配置的有效性。
