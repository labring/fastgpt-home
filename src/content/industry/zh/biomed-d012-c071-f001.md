# 洁净区管理药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

洁净区管理中的药物警戒数据主要关注生产环境与产品质量之间的潜在关联。数据来源包括环境监测系统（如粒子计数器、微生物采样器）、设备运行日志、人员进出记录、物料批次信息以及生产过程中的异常事件报告。这些数据通常以结构化或半结构化形式存在，例如 CSV、JSON 或 XML 文件，也可能包含非结构化的日志文本。更新频率较高，环境监测数据可能每隔数分钟甚至实时更新，而批次信息和异常报告则随生产流程和事件发生而更新。字段内容涉及环境参数（温度、湿度、压差）、微生物种类与数量、粒子大小与数量、设备 ID、操作人员 ID、批次号、生产阶段、异常描述、发生时间等，其中微生物数量常以 CFU/m³ 或 CFU/皿 表示，粒子数量以个/m³ (≥0.5μm, ≥5μm) 表示。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

洁净区管理数据的实时性要求高，尤其是在环境异常事件发生时，需要迅速触发药物警戒流程。这要求 HTTP 接口具备低延迟和高吞吐量，以处理频繁的数据上传。数据来源多样化，导致接口需要支持多种数据格式的解析能力。例如，粒子计数器可能直接推送 JSON 格式数据，而微生物检测结果可能通过 CSV 文件批量导入。字段的特异性，如 CFU/m³ 和不同粒径的粒子计数，要求接口能够准确识别并验证这些带有单位的数值，避免数据解析错误。此外，生产过程中偶发的异常报告可能包含非结构化文本，对接口的数据预处理和语义理解能力提出要求，以便从中提取关键药物警戒信息。外部系统对接时，需考虑不同系统之间的数据标准差异，可能需要进行数据转换和映射。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `30 秒` | 多数环境监测数据推送可在短时间内完成，防止长时间等待导致任务堆积。 |
| `MAX_PAYLOAD_SIZE_MB` | `10 MB` | 兼顾批量上传的监测数据与异常事件报告，避免因单次请求过大而失败。 |
| `RETRY_ATTEMPTS` | `3 次` | 应对短暂的网络波动或外部系统瞬时负载高，确保数据传输的可靠性。 |
| `DATA_FORMAT_SUPPORT` | `JSON, CSV, XML` | 覆盖洁净区环境监测系统、设备日志和生产管理系统常见的输出格式。 |
| `BATCH_PROCESSING_INTERVAL_MINUTES` | `5 分钟` | 对于非实时性要求的数据（如每日汇总），可降低接口调用频率，优化资源。 |
| `ERROR_NOTIFICATION_CHANNEL` | `Slack 告警` | 确保数据传输或处理失败时，能及时通知相关工程师介入处理。 |

## 容易做错的三处

*   HTTP 请求返回 `400 Bad Request` 或 `500 Internal Server Error` 状态码，通常是由于上传的 JSON 或 XML 数据结构与接口预期的 `schema` 不符，或必填字段 `batch_id`、`event_timestamp` 缺失。
*   环境监测数据上传后，下游系统中的 `particle_count_0_5um` 或 `cfu_per_m3` 字段为空或显示为非数值，原因在于接口未能正确解析带有单位的字符串或数值类型转换失败。
*   异常事件报告的非结构化文本上传后，未能触发预期的药物警戒规则，这通常是由于文本内容未经过合适的语义解析，导致关键词 `microbial_contamination` 或 `pressure_differential_excursion` 未被识别。

## 怎么确认配好了

*   通过模拟环境监测系统，向配置好的 HTTP 接口发送包含 `environment_parameter_json` 数据的请求，检查返回状态码是否为 `200 OK`，并验证下游系统是否成功接收并解析了 `temperature_celsius` 和 `humidity_percentage` 等字段。
*   上传一份包含微生物检测结果的 `csv_report_file` 文件，检查接口是否正确处理了 `cfu_plate_count` 字段，并确保数值与文件中保持一致。
*   提交一个描述生产线 `pressure_differential_alarm` 事件的 JSON 请求，验证接口是否能正确识别并提取 `device_id` 和 `alarm_description`，同时检查药物警戒系统是否根据此事件触发了相应的预警。
