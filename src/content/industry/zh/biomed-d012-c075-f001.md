# 生物等效性药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

生物等效性研究的数据主要来源于临床试验报告、药代动力学（PK）和药效学（PD）数据、以及不良事件（AE）报告。这些数据通常以结构化表格形式存在，如符合CDISC（Clinical Data Interchange Standards Consortium）标准的SDTM（Study Data Tabulation Model）和ADaM（Analysis Data Model）数据集，或以非结构化的文本报告形式呈现。更新节奏方面，临床试验数据在试验进行过程中会持续产生，不良事件报告的提交则具有实时性或周期性，例如ICH E2B标准要求在特定时限内提交严重不良反应报告。字段包括受试者ID、给药方案、血药浓度、药时曲线下面积（AUC）、峰浓度（Cmax）、达峰时间（Tmax）等药代动力学参数，以及不良事件描述、发生日期、严重程度、结局等，单位则严格遵循国际标准，如血药浓度常使用纳克/毫升（ng/mL），时间单位为小时（h）。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

生物等效性数据的多样性和更新频率，对HTTP接口设计提出了明确要求。结构化数据如PK/PD参数，需要接口支持批量上传和精确的字段映射，以确保 `AUC`、`Cmax` 等关键指标的准确导入。非结构化文本报告，例如不良事件描述，则需要接口能够处理包含大量自由文本的请求体，可能涉及对文本编码格式的兼容性考量。不良事件报告的实时或周期性更新，意味着HTTP接口需要支持高并发请求，并具备幂等性处理机制，避免重复数据录入。此外，由于生物等效性数据涉及敏感的临床信息，接口的安全性，例如通过 `TLS` 加密传输，以及严格的身份认证和授权机制，是不可或缺的。数据单位的标准化要求接口在数据传输过程中保持单位一致性，避免因单位转换错误导致的数据异常。

## 配置怎么定

| 配置项                   | 建议取法                               | 这样取的依据                                                 |
| :----------------------- | :------------------------------------- | :----------------------------------------------------------- |
| `requestTimeoutSeconds`  | `600 秒`                               | 生物等效性报告数据量大，处理复杂，需要较长的接口响应时间。   |
| `maxPayloadSizeMB`       | `200 MB`                               | 传输包含大量PK/PD数据或详细不良事件文本的请求体时，需要支持较大的载荷。 |
| `concurrentConnections`  | `按实测标定`                           | 不良事件报告提交具有实时性，根据实际并发量进行压力测试后确定。 |
| `authHeaderName`         | `Authorization`                        | 行业标准做法，便于安全认证，例如 `Bearer Token`。            |
| `responseBodyEncoding`   | `UTF-8`                                | 确保非结构化文本数据，特别是不良事件描述中的多语言字符正确解析。 |
| `retryAttempts`          | `3 次`                                 | 应对网络波动或外部系统瞬时故障，提高数据传输的可靠性。       |

## 容易做错的三处

*   现象：外部系统调用HTTP接口后，部分药代动力学参数字段为空或数值异常。原因：接口返回的数据结构与预期不符，或 `JSON` 字段名在映射时大小写不匹配。
*   现象：向外部系统发送不良事件报告时，偶尔出现 `tls: failed to verify certificate` 错误。原因：FastGPT部署环境未正确配置或信任外部系统的 `TLS` 证书链。
*   现象：批量导入生物等效性数据时，接口响应超时，最终数据导入失败。原因：单次请求的数据量过大，超过了 `requestTimeoutSeconds` 的设置，或外部系统处理能力不足。

## 怎么确认配好了

*   通过POSTMAN或类似的HTTP客户端，模拟发送一个包含完整生物等效性结构化数据的请求，并检查FastGPT侧是否正确解析了所有 `AUC` 和 `Cmax` 等关键字段。
*   发送一个包含非结构化不良事件描述的请求，确认接口返回状态码为 `200 OK`，且文本内容在FastGPT知识库中可被检索。
*   在高峰期或模拟高并发场景下，持续发送请求，观察 `concurrentConnections` 限制是否生效，并检查外部系统日志中是否有因连接数过多而被拒绝的记录。
*   检查FastGPT与外部系统之间的网络流量，确认数据传输通过 `TLS` 加密，并且没有明文敏感信息泄露。
