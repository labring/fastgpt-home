# 真实世界研究药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

真实世界研究在药物警戒领域的数据主要来源于电子健康档案、患者登记系统、医保理赔数据库及移动医疗应用。这些数据通常以非结构化文本形式（如临床笔记、不良事件报告）和结构化表格形式（如诊断编码 `ICD-10`、用药记录 `ATC`）混合存在。数据更新频率不一，部分高频数据源可能每日更新，而患者随访数据则可能按季度或年度更新。文档结构多样，涉及病历报告、实验室结果、影像学报告等，字段名和单位在不同来源间可能存在差异，例如剂量单位可能是 `mg` 或 `g`，时间单位可能是 `天` 或 `周`。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

真实世界研究数据源的多样性要求 HTTP 接口具备灵活的数据解析能力，以适应不同格式和编码的数据。非结构化文本内容，如不良事件描述，需要高级文本处理和实体识别能力来提取关键信息，这增加了数据预处理的复杂性。数据更新频率的不一致性，特别是低频更新数据，要求外部系统在拉取策略上进行差异化配置，避免不必要的资源消耗。同时，由于涉及患者隐私，数据传输和存储必须符合 `HIPAA` 或 `GDPR` 等法规要求，确保接口的安全性和合规性。字段与单位的异构性则强制要求在数据摄入阶段进行标准化和映射，否则会影响后续分析的准确性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `HTTP_REQUEST_TIMEOUT` | `600 秒` | 真实世界数据源往往体量大，传输和处理时间长，防止请求过早中断。 |
| `MAX_FILE_SIZE_MB` | `500 MB` | 支持大型结构化数据文件（如 CSV、JSONL）和非结构化 PDF 文档的上传。 |
| `PARSE_PDF_ENABLED` | `true` | 大量临床报告以 PDF 格式存在，需要启用 PDF 内容解析功能。 |
| `CHUNK_SIZE_TOKENS` | `800–1200 字符` | 兼顾文本语义完整性和处理效率，适应临床文本的段落长度。 |
| `RECALL_TOP_K` | `5–7 条` | 在药物警戒场景中，需要召回足够多的相关上下文以进行全面判断。 |
| `DATA_SOURCE_POLLING_INTERVAL` | 按实测标定 | 根据具体数据源的更新频率，设定合理的轮询间隔，避免频繁请求。 |

## 容易做错的三处

*   通过 HTTP 接口上传文件后，知识库内容未按预期增加，或部分关键信息缺失。原因常是未正确指定 `file_type` 或 `parse_strategy` 参数，导致文件未被正确解析或处理。
*   从外部系统拉取数据时频繁出现 `HTTP 504 Gateway Timeout` 错误。原因通常是数据量过大，单个请求处理时间超出服务器或网关的默认超时限制。
*   外部系统推送的数据在 FastGPT 中部分字段为空，或数值单位不统一。原因在于外部系统字段名与 FastGPT 内部期望的字段名不匹配，或未进行单位转换和标准化处理。

## 怎么确认配好了

*   通过 FastGPT 的管理界面，检查对应知识库中文件解析状态，确认所有上传文件均已成功处理。
*   触发一次完整的 HTTP 数据拉取或推送流程，检查 FastGPT 日志中是否存在 `HTTP 200 OK` 状态码，并确认无超时错误。
*   在 FastGPT 知识库中，随机抽取几条导入的真实世界研究数据，检查关键字段（如不良事件类型、药物名称、剂量单位）是否准确无误且格式统一。
