# 眼科药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样
眼科药物警戒数据主要来源于临床试验报告、真实世界研究、医生自发报告、患者报告以及上市后监测数据库。数据更新频率高，尤其是在新药上市初期或发现新的不良反应信号时，可能会有每周甚至每日的更新。文档结构多样，包括结构化的病例报告表（CRF）、非结构化的自由文本描述、医学影像报告、实验室检查结果等。字段包含患者人口统计学信息、用药史、不良反应事件（AE）描述、严重程度、结局、相关性评估以及眼科特有的检查指标，如视力（VA）、眼压（IOP）、视野（VF）和光学相干断层扫描（OCT）结果。单位通常遵循国际医学标准，例如视力使用LogMAR或Snellen分数，眼压使用mmHg。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
眼科药物警戒数据的高更新频率要求HTTP接口具备高效的数据同步机制，以确保FastGPT能够及时获取最新不良反应信息。多样化的文档结构，特别是大量的非结构化文本，对外部系统的文本解析能力提出挑战，需要能够处理不同格式的眼科专业术语和缩写。眼科特有的检查指标，如VA、IOP等，要求接口能够准确传输这些带有特定单位的数值，并在FastGPT内部进行正确的解析和索引，以支持基于这些指标的精细化查询。此外，涉及患者隐私和敏感医学信息的传输，对HTTP接口的安全性、数据加密和访问控制有严格要求。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `HTTP_TIMEOUT_SECONDS` | `60 秒` | 眼科报告数据量可能较大，预留足够时间完成传输和初步处理，避免因网络延迟或处理耗时导致连接中断。 |
| `MAX_PAYLOAD_SIZE_MB` | `20 MB` | 考虑单个不良反应报告可能包含图像或详细文本，此值可容纳大多数上传需求。 |
| `API_KEY_HEADER_NAME` | `X-FastGPT-API-Key` | 采用自定义头部字段传递鉴权信息，增强安全性。 |
| `PARSING_CONCURRENCY` | `5` | 兼顾数据处理效率与系统资源占用，适应高并发数据更新。 |
| `DATA_UPDATE_INTERVAL_HOURS` | `24 小时` | 平衡数据实时性与外部系统负载，确保每日至少一次全量或增量同步。 |
| `ERROR_RETRY_COUNT` | `3` | 应对瞬时网络波动或外部系统临时故障，提高数据传输的健壮性。 |

## 容易做错的三处
*   HTTP请求返回400/401状态码，现象是接口调用失败，日志显示权限不足或请求格式错误，原因在于`API_KEY`或`Content-Type`头部字段未正确设置。
*   上传大型眼科影像文件后，FastGPT接收到的数据不完整或解析失败，现象是文件大小与原始文件不符或关键字段缺失，原因在于`MAX_PAYLOAD_SIZE_MB`配置过小导致请求被截断。
*   外部系统调用FastGPT接口创建应用或模型时，接口返回500错误，现象是系统日志显示内部处理异常，原因在于请求的JSON结构不符合FastGPT API的预期，例如缺少必填字段或字段类型不匹配。

## 怎么确认配好了
*   通过FastGPT管理界面，检查已配置的HTTP接口状态，确认显示为“已连接”且无异常告警。
*   手动触发一次包含眼科不良反应报告的HTTP数据同步，观察FastGPT知识库中是否新增了相关文档，并核对关键字段如`视力值`、`眼压值`是否正确解析。
*   模拟外部系统通过API创建FastGPT应用或模型，检查API返回的状态码为200，并能在FastGPT应用列表中找到新创建的项。
