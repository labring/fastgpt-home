# 精神类疾病药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

精神类疾病药物警戒数据，其主要来源包括国家药品不良反应监测中心数据库、临床试验报告、真实世界研究（RWE）数据以及学术文献。数据更新频率因来源而异，国家监测中心的数据通常按季度或年度发布，而临床试验和RWE数据则随项目进展不定时更新。文档结构上，这些数据常以结构化报告、EDC（电子数据采集）系统导出文件或非结构化的文本形式存在。字段方面，除了药品通用信息、患者基本情况、不良反应事件描述等常规项外，特别关注精神症状量表（如 HAM-D、PANSS 评分）、精神科诊断编码（如 ICD-10 F章）、治疗方案调整记录以及患者依从性数据。单位上，量表评分通常是整数或小数，剂量单位为毫克（mg）、克（g）等，时间单位为天、周、月。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

精神类疾病药物警戒数据的多源性与异构性，对HTTP接口设计提出了挑战。例如，来自监测中心的数据可能采用特定的XML或JSON Schema，而临床试验数据则常以CSV或Excel格式提供，需要接口具备灵活的数据解析能力。精神症状量表等字段的数值范围和语义特殊性，要求接口在数据校验时能识别并处理这些专业数据类型，避免误判或丢失信息。数据更新频率的不一致性，决定了HTTP接口的调用策略，部分数据源需要定期全量或增量同步，部分则可按需触发。此外，精神类疾病患者隐私保护的严格要求，使得接口在数据传输过程中必须强制使用HTTPS协议，并对敏感字段进行加密处理，确保数据安全性与合规性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `requestTimeout` | `120000 毫秒` | 应对外部系统数据量大、响应慢的情况，避免超时中断 |
| `maxRetries` | `3` | 增加请求的鲁棒性，应对瞬时网络波动或外部系统偶发故障 |
| `headers` | `Authorization: Bearer <TOKEN>` | 外部系统通常采用OAuth2或API Key进行身份验证 |
| `payloadSchema` | `JSON Schema 严格模式` | 确保传入数据的结构和类型符合精神类疾病特有字段要求 |
| `responseParser` | `自定义脚本解析` | 处理不同来源的异构响应数据，提取关键的药物警戒信息 |
| `sslVerify` | `true` | 强制进行SSL证书验证，保障精神类疾病患者数据传输安全 |

## 容易做错的三处

*   HTTP请求返回“证书验证失败”或“SSL握手失败”错误，现象是请求无法成功建立连接。原因通常是FastGPT部署环境无法访问外部系统的CA证书链，或外部系统使用了自签名证书，未在FastGPT环境中配置信任。
*   接口调用成功但返回数据中精神症状量表字段为空或格式错误，现象是日志显示字段解析异常。原因在于外部系统返回数据格式与预期不符，或自定义解析脚本未能正确处理精神类疾病特有的量表数据结构。
*   数据同步接口调用超时，现象是长时间等待后返回“请求超时”错误。原因可能是外部系统处理请求时间过长，或网络延迟过大，默认的HTTP请求超时设置不足以覆盖此场景。

## 怎么确认配好了

*   通过测试工具模拟HTTP请求，检查是否能正常获取外部系统返回的药物警戒数据，并验证返回的状态码是否为200。
*   解析返回数据，核对精神症状量表、诊断编码等关键字段的取值、单位和格式是否正确，与预期的数据规范进行比对。
*   观察日志输出，确认HTTP请求的超时时间、重试机制是否按配置生效，以及SSL证书验证是否成功。
