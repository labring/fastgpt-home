# 药物经济学药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

药物经济学在药物警戒领域的应用，其数据主要来源于真实世界证据（RWE）、临床试验数据、药品上市后监测报告以及各国药监机构发布的药物不良反应（ADR）数据库。这些数据通常以结构化或半结构化形式存在，例如 CSV、JSON、XML 文件，也包含大量的非结构化文本，如医生诊断记录、患者自述、医学文献。数据更新频率较高，特别是上市后监测数据，可能按周或月更新。文档结构复杂，常包含药品通用名、商品名、ATC 分类码、适应症、不良反应事件、严重程度、发生频率、治疗成本、住院天数、患者QALY（质量调整生命年）等字段。字段单位多样，例如成本以当地货币计价，发生频率为百分比，时间为天或年。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

药物经济学数据的高更新频率要求 HTTP 接口具备高效的数据同步机制，以确保模型分析结果的时效性。数据来源的多样性与复杂结构，使得外部系统接口需要支持多种数据格式的解析能力。例如，处理来自不同国家药监机构的 XML 格式不良反应报告，同时也要能解析临床研究的 JSON 格式效益成本数据。字段单位的多样性，特别是货币单位和时间单位，要求在接口调用时进行明确的单位转换或标注，避免数据混淆。大量的非结构化文本数据，则需要接口能够有效地传输和处理长文本，并与后端文本处理服务（如实体识别、情感分析）协同工作。数据量通常较大，对接口的稳定性和响应速度提出要求，尤其是在进行批量数据导入或复杂查询时。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `requestTimeout` | `120000 毫秒` | 药物经济学数据量大，复杂查询或批量导入可能耗时较长，预留充足时间避免超时中断。 |
| `maxPayloadSize` | `20 MB` | 外部系统传输原始不良反应报告或临床试验数据文件时，单个请求负载可能较大。 |
| `contentType` | `application/json` 或 `application/xml` | 适应主流的结构化数据格式，支持解析不同来源的药物经济学数据文档。 |
| `retryAttempts` | `3` | 外部系统可能因网络波动或服务暂时不可用导致请求失败，多次重试可提高数据同步成功率。 |
| `authHeaderName` | `Authorization` | 遵循常见的 API 认证机制，确保数据传输的安全性，例如使用 Bearer Token。 |
| `dataSchemaVersion` | `V2023-09-01` | 明确数据接口版本，应对药物经济学字段随时间演进的变化，保持兼容性。 |

## 容易做错的三处

*   调用接口后返回 400 状态码，并提示“Invalid JSON format”。原因在于外部系统发送的数据不符合接口预期的 JSON 结构，例如缺少必要的字段或数据类型不匹配。
*   接口调用成功但返回的数据字段为空或数值异常。这通常是由于外部系统的数据单位与 FastGPT 内部处理逻辑不一致，例如货币单位未转换或时间单位未标准化。
*   应用调用接口后长时间没有响应，最终出现超时错误。这可能是因为外部系统处理请求耗时过长，或者 FastGPT 的 `requestTimeout` 参数设置过短，未能等待外部系统完成数据处理。

## 怎么确认配好了

*   通过 FastGPT 的调试工具或日志，检查 HTTP 请求的响应状态码是否为 200，并确认返回的数据结构与预期一致。
*   针对关键的药物经济学字段，例如 `cost_value`、`adverse_event_rate`，验证返回数据中的数值和单位是否正确，并与原始数据源进行比对，确认数据已按预期转换。
*   模拟高并发或大数据量请求，监测接口的响应时间和稳定性，确保在实际应用场景下不会出现超时或性能瓶颈，必要时调整 `requestTimeout` 参数。
*   检查 FastGPT 工作流中对外部系统返回数据的处理逻辑，确保能正确解析和利用所有相关字段，特别是长文本内容和嵌套结构。
