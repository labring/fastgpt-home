# 药物经济学药物警戒的部署与升级

## 这个品类的数据长什么样

药物经济学数据通常来源于真实世界证据（RWE）研究、临床试验、医疗索赔数据库、药品注册数据库以及药监部门的不良事件报告系统。数据更新频率不一，部分临床试验数据为定期发布，而药品不良反应（ADR）数据可能实时或每日更新。文档结构多样，包括结构化的数据库记录、半结构化的医疗报告（如 HL7 CDA）以及非结构化的学术论文和监管文件。字段与单位具有高度特异性，例如成本数据可能以 `美元/年` 或 `欧元/疗程` 计，效用数据以 `QALY` (质量调整生命年) 或 `LYG` (生命年增益) 表示，药品名称使用国际非专利名称（INN）或商品名，涉及剂量、频率、途径等关键医学字段。

## 这些特征在「部署与升级」这一环带来什么约束

药物经济学数据来源的复杂性要求 FastGPT 在部署时需配置多源数据连接器，以整合来自不同系统的数据流。更新频率的差异性，特别是实时 AD R数据，对知识库的增量更新机制提出要求，需要支持高频小批量数据摄入，避免全量重建。文档结构的多样性意味着需要健壮的文档解析器，能够处理结构化 CSV/JSON、半结构化 XML/CDA 以及非结构化 PDF/DOCX 等多种格式，并准确提取关键信息。字段与单位的特异性则要求在知识库构建时，对特定医学和经济学概念进行精确的实体识别和关系抽取，例如识别 `治疗费用`、`QALY值`，并确保数值与单位的正确关联，这直接影响后续 RAG 检索的准确性和生成回答的专业性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 药物经济学报告和临床试验文档通常较大，需支持单个文件上传上限。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 处理大型 PDF 或复杂 XML 文件时，解析时间可能较长，防止因超时中断。 |
| `分段长度` | `800–1200 字符` | 确保每个段落包含足够上下文以理解经济学模型或临床研究细节，但不过长。 |
| `召回条数` | `前 10 条` | 药物经济学问题通常需要综合多方面证据，增加召回量可提升相关性。 |
| `相似度阈值` | `0.75` | 药物警戒数据对准确性要求高，适当提高阈值可减少不相关召回。 |
| `重排返回条数` | `5 条` | 在药物经济学评估中，通常需要比较几项最相关的研究或报告。 |

## 容易做错的三处

- 现象：模型在处理 `QALY` 或 `ICER` 相关问题时，回答缺乏数值或计算逻辑。
  原因：文档解析器未能正确识别并抽取半结构化报告中的关键数值字段和单位。
- 现象：知识库更新后，新录入的药品不良反应数据未能在检索中体现。
  原因：增量更新机制未正确配置或定时任务未按预期执行，导致实时数据未能及时同步。
- 现象：本地部署后，访问 FastGPT 登录界面提示 `Database connection error`。
  原因：数据库配置（如 `DB_HOST`、`DB_PORT`）不正确或数据库服务未启动。

## 怎么确认配好了

- 导入一份包含药物经济学评估报告和 AD R数据的测试集，检查知识库中是否正确识别并存储了 `QALY值`、`治疗成本`、`药品名称` 等关键实体。
- 模拟一次新的 AD R数据批量上传，观察知识库更新日志，并验证最新数据是否可被检索。
- 使用不同格式（如 PDF、XML、CSV）的药物经济学文档进行文件上传测试，确认解析器能够无误处理。
- 针对药物经济学中的复杂计算问题（如成本效益分析），向 FastGPT 提问，检查回答是否能引用到相关文档中的数值和方法论。
