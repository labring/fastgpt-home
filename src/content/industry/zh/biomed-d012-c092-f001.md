# 血液肿瘤药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样
血液肿瘤药物警戒数据通常包含患者报告、医护人员报告、企业自发报告及文献检索结果。数据来源广泛，如国家药品不良反应监测中心数据库、国际药品监管机构数据库（如 FDA Adverse Event Reporting System, FAERS）及临床试验报告。数据更新频率不一，FAERS 通常每季度更新，而企业内部报告可能实时提交。数据文档结构复杂，常包含患者人口统计学信息、药品使用情况、不良事件描述（使用医学术语和编码，如 MedDRA）、事件严重性、结局以及相关性评估。字段多为分类变量和文本描述，部分字段需通过自然语言处理提取结构化信息，如不良事件的发生日期、持续时间、治疗措施等。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
血液肿瘤药物警戒数据的多源性与异构性，要求 HTTP 接口具备高度的兼容性和灵活性，以适配不同来源的数据格式，例如 JSON、XML 或 CSV。数据更新频率的差异性，决定了接口调用需要支持定时任务与实时触发相结合的机制，确保数据时效性。复杂的文档结构，特别是不良事件的自由文本描述，对接口的数据预处理能力提出挑战，需通过 `preProcessScript` 参数执行清洗和标准化。医学术语和编码（如 MedDRA `LLT_CODE`、`PT_CODE`）的存在，意味着接口在传输和处理时需要保留这些编码，方便后续的专业分析，且对字符编码有严格要求，通常为 UTF-8。字段的分类变量和文本描述特性，影响了数据传输量和处理负载，可能需要分批传输或压缩处理。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `externalApiUrl` | `https://api.fda.gov/drug/event.json` 或私有部署的 API 地址 | FDA FAERS 是公开且权威的数据源，私有 API 用于企业内部数据集成 |
| `requestMethod` | `GET` 或 `POST` | 根据外部系统 API 规范选择，FAERS 查询通常使用 `GET` |
| `requestHeaders` | `Content-Type: application/json` | 确保正确解析 JSON 数据，或根据目标 API 要求设置 |
| `requestTimeout` | `60000` 毫秒 | 考虑到外部 API 响应时间及数据量，防止长时间等待导致任务失败 |
| `preProcessScript` | 按实测标定 | 用于清洗不良事件描述文本、提取关键日期字段，例如将日期字符串统一为 `YYYY-MM-DD` 格式 |
| `maxConnections` | `5` | 平衡数据获取效率与外部系统负载，避免频繁请求被限流 |

## 容易做错的三处
1. 错误现象：HTTP 接口调用返回 `HTTP 429 Too Many Requests` 错误。原因：未正确配置请求间隔或并发连接数，导致短时间内对外部系统发起过多请求，触发了限流机制。
2. 错误现象：不良事件描述字段（例如 `patient.reaction.reactionmeddrapt`）在 FastGPT 中显示为空或乱码。原因：外部系统返回的数据编码与 FastGPT 期望的编码不一致，或 `preProcessScript` 未正确处理特殊字符或 MedDRA 编码。
3. 错误现象：工作流中调用外部 API 后，无法正确解析返回的 JSON 数据，导致后续步骤报错。原因：API 返回的 JSON 结构与预设的数据模型不匹配，或者在 `preProcessScript` 中对返回数据进行了不恰当的修改。

## 怎么确认配好了
1. 通过 FastGPT 的调试工具，对配置好的 HTTP 接口进行一次完整的调用测试，检查返回数据的 `status_code` 是否为 `200`，并核对返回的原始数据是否符合预期。
2. 检查导入的数据中，关键字段如 `LLT_CODE`、`PT_CODE` 和不良事件描述文本是否完整且无乱码，确保医学术语的正确识别。
3. 针对不同来源的数据，分别调用接口，比对不同时间点的数据更新情况，确认 `preProcessScript` 能正确处理各种格式的数据。
