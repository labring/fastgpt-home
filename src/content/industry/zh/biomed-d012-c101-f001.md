# 重组蛋白药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

重组蛋白药物警戒数据主要来源于临床试验报告、真实世界研究、上市后监测以及患者自发报告。这些数据通常以结构化或半结构化的形式存在。结构化数据包括药物名称、批次号、给药途径、不良事件编码（如MedDRA编码）、发生时间、严重程度、结局等字段。半结构化数据可能包含自由文本描述，例如医生记录、患者访谈摘要。数据的更新频率不一，临床试验数据通常在试验阶段性报告或结束后集中更新，上市后监测数据则可能持续实时或准实时地汇集。文档结构方面，常见的是CSV、JSON或XML格式，用于交换和存储。字段单位通常是标准化的，如剂量单位为mg、g，时间单位为天、小时。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

重组蛋白药物警戒数据的多源性、半结构化特性以及更新频率差异，对HTTP接口与外部系统集成提出了特定约束。首先，MedDRA编码等标准化字段的存在，要求接口在数据传输时能有效映射和校验这些编码，确保数据一致性。自由文本描述需要接口具备文本解析能力，或将其作为原始字段传递，供后续NLP处理。其次，数据来源的广泛性意味着需要与多个外部系统建立HTTP连接，例如与电子健康档案系统、药品监管数据库以及患者报告平台进行数据交换。更新频率的不同，要求接口设计具备灵活性，支持定时拉取（如临床试验数据）和事件驱动推送（如实时患者报告）两种模式。此外，重组蛋白药物的特定副作用可能需要更精细的数据粒度，例如某个特定免疫原性反应的详细描述，这要求接口能够承载更长的文本字段或嵌套数据结构。

## 配置怎么定

| 配置项                 | 建议取法                               | 这样取的依据                               |
| :--------------------- | :------------------------------------- | :----------------------------------------- |
| `maxContext`           | `2000` 字符                            | 适配MedDRA编码、自由文本描述与结构化字段的混合内容 |
| `requestTimeout`       | `300` 秒                               | 应对外部系统响应慢或数据量大时的传输延迟   |
| `callbackUrl`          | `https://yourdomain.com/webhook/alert` | 接收外部系统主动推送的实时不良事件报告     |
| `authHeader`           | `Authorization: Bearer your_token`     | 确保与外部系统通信的安全与身份验证         |
| `retryAttempts`        | `3` 次                                 | 应对网络波动或外部系统临时性不可用         |
| `parseJsonPath`        | `$.data.adverseEvents[*]`              | 精确提取JSON响应中不良事件数组的数据       |

## 容易做错的三处

*   HTTP请求超时，现象为系统日志中出现 `HTTP 504 Gateway Timeout` 或 `java.net.SocketTimeoutException` 错误。原因在于外部系统处理请求耗时过长，或网络延迟超出默认超时设置。
*   数据字段映射错误，现象为导入数据中关键字段为空或值不符合预期，例如 `MedDRA_Code` 字段经常出现 `null` 值。原因在于外部系统返回的字段名与接口期望的字段名不一致，或JSON Path表达式编写有误。
*   API密钥或认证信息失效，现象为接口调用返回 `HTTP 401 Unauthorized` 或 `HTTP 403 Forbidden` 状态码。原因在于外部系统API密钥过期、被撤销，或请求头中认证信息格式不正确。

## 怎么确认配好了

*   通过 FastGPT 的“测试连接”功能，验证HTTP接口与外部系统的连通性，确保返回状态码为 `200 OK`。
*   执行一次模拟数据拉取或推送操作，检查 FastGPT 内部日志中是否有数据成功写入的记录，并核对关键字段（如 `drug_name`、`event_type`）是否正确解析。
*   与外部系统管理员确认其日志中是否有 FastGPT 发出的请求记录，并检查请求参数与响应数据是否符合预期，特别是关于 `MedDRA` 编码和 `report_time` 字段的格式。
