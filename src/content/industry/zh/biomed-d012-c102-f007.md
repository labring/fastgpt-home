# 院感管理药物警戒的工作流编排

## 这个品类的数据长什么样

院感管理中的药物警戒数据主要来源于医院信息系统（HIS）、电子病历（EMR）、实验室信息系统（LIS）以及医护人员手动填报的不良事件报告。数据更新频率较高，如患者用药记录实时更新，检验结果通常在数小时内生成，不良事件报告则根据发现情况即时录入。文档结构上，数据通常以结构化或半结构化形式存在，例如药品医嘱记录包含 `药品名称`、`剂量`、`给药途径`、`给药时间` 等字段；检验报告则包含 `检验项目`、`结果值`、`参考范围`、`单位`（如 `mg/dL`、`U/L`）等。不良事件报告通常包含自由文本描述，但也会有 `事件类型`、`发生时间`、`涉事药品` 等结构化字段。

## 这些特征在「工作流编排」这一环带来什么约束

院感药物警戒数据的多源性和高更新频率，要求工作流具备实时或近实时的触发能力，以便及时捕捉潜在风险。结构化与半结构化数据并存的特点，意味着工作流在数据摄取环节需要支持多种解析器，例如用于解析标准HIS数据表的结构化数据解析，以及用于处理不良事件报告中自由文本的自然语言处理能力。此外，数据中包含的多种单位和数值范围，对判断器节点和工具调用节点提出了更高的精度要求，需要精确的单位转换和阈值比较逻辑，避免因单位不匹配或数值类型错误导致的误判。例如，对血药浓度监测数据的处理，必须严格区分不同药物的治疗窗单位。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `触发器类型` | 消息触发 / 定时触发 | 实时监测患者用药与检验结果变化，定时触发可用于批量分析历史数据。 |
| `文档解析器` | JSON 解析器 / 文本解析器 | HIS/LIS数据常为JSON格式，不良事件报告多为自由文本。 |
| `分段长度` | `500–800 字符` | 兼顾文本语义完整性与模型处理效率，适用于不良事件报告。 |
| `相似度阈值` | `0.75` | 确保召回相关性，避免无关信息干扰，适用于症状与药品关联分析。 |
| `工具调用超时` | `60 秒` | 多数外部系统（如药品说明书数据库）响应时间在此范围内。 |
| `全局变量类型` | `Boolean` / `String` | 用于标记特定风险状态或流程分支，方便判断器节点逻辑控制。 |

## 容易做错的三处

*   判断器节点对布尔型全局变量状态判断异常，表现为流程分支不按预期流转。原因在于全局变量的布尔值被错误地当作字符串处理，导致判断逻辑失效。
*   AI 对话节点开启图片识别后，上传图片却收到“无法提供图片内容”的回复。原因可能是模型服务侧图片识别功能未正确启用，或者请求中的图片数据格式不符合API要求。
*   前端在打包部署后，文档解析节点无法解析上传文件，报 `404` 错误。原因通常是前端文件上传的路径配置在服务器环境中失效，导致后端无法找到文件资源。

## 怎么确认配好了

*   通过模拟提交各类数据（结构化数据、自由文本不良事件报告），观察工作流是否按预期触发，并检查各节点输出。
*   上传包含图片的文件，验证多模态AI节点是否能正确识别图片内容并生成相关回复，确认无“无法提供图片内容”的提示。
*   检查工作流日志，确认所有工具调用节点执行无误且返回结果正确，并比对工具调用结果与预期输出。
*   在前端部署环境下，上传测试文件，确保文档解析节点能够成功解析文件内容，且无 `404` 错误报告。
