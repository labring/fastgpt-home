# 零售连锁药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

零售连锁企业在药物警戒领域的数据主要来源于药店销售系统、药师上报系统以及消费者反馈渠道。这些数据更新频率较高，销售数据通常是实时或准实时的，而不良反应报告则可能按日或按周汇总。数据文档结构呈现多样性，既有结构化的销售记录和药品批次信息，也包含半结构化的不良反应事件描述和患者用药史。关键字段包括药品通用名、批号、生产企业、销售日期、患者基本信息、不良反应发生时间、症状描述及严重程度等。单位涉及数量（如片、盒）、金额（元）、时间（年、月、日、时、分）以及严重程度分级（如轻度、中度、重度）。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

零售连锁的药物警戒数据特性对HTTP接口与外部系统集成提出了特定要求。高频的销售数据更新需要接口支持批量或流式传输，以避免数据积压和延迟。半结构化的不良反应报告则要求接口具备灵活的数据解析能力，能够处理非标准化的文本信息，并将其映射到预定义的知识库结构中。此外，由于涉及患者隐私信息，接口在数据传输过程中必须严格遵守数据安全和合规性要求，例如采用HTTPS协议加密传输。多样的字段和单位要求接口在数据校验时能识别不同类型的数据格式，并进行必要的单位转换或标准化处理，确保数据一致性，避免因单位不统一导致误判。

## 配置怎么定

| 配置项                 | 建议取法                               | 这样取的依据                                       |
| :--------------------- | :------------------------------------- | :------------------------------------------------- |
| `HTTP_TIMEOUT_SECONDS` | `60 秒`                                | 兼顾数据量与实时性，避免长连接导致系统资源占用。 |
| `MAX_RECORDS_PER_BATCH` | `2000 条`                              | 适应零售连锁销售数据批量上传，平衡传输效率与单次处理压力。 |
| `DATA_SCHEMA_VERSION`  | `v1.2`                                 | 确保与外部系统数据结构定义保持一致，便于数据解析。 |
| `ERROR_RETRY_INTERVAL` | `300 秒`                               | 针对外部系统偶发性故障，提供合理重试间隔。       |
| `AUTHENTICATION_METHOD` | `API Key`                              | 适用于系统间调用，便于权限管理与追踪。           |
| `LOG_LEVEL`            | `INFO`                                 | 记录关键操作与错误，便于问题排查。               |

## 容易做错的三处

*   接口返回 `500 Internal Server Error`，日志显示字段解析失败，原因可能是外部系统传输的数据格式与接口预期的 `DATA_SCHEMA_VERSION` 不符。
*   部分不良反应报告未成功导入，状态码显示 `202 Accepted` 但数据缺失，原因可能是在传输过程中未对半结构化文本进行有效编码，导致特殊字符丢失。
*   数据同步延迟严重，尽管 `HTTP_TIMEOUT_SECONDS` 设置合理，原因可能是外部系统在请求高峰期处理能力不足，导致大量请求排队。

*   通过模拟零售连锁销售系统的数据上报，观察FastGPT日志中是否能完整捕获销售记录及相关药品批次信息。
*   从药师上报系统导出包含多种症状描述和严重程度分级的模拟不良反应报告，通过HTTP接口上传，检查FastGPT知识库中是否能准确识别并分类这些信息。
*   监控接口的错误日志，确保在连续运行一段时间后，没有出现 `5xx` 错误码或数据解析异常的记录。
