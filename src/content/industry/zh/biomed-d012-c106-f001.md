# 高值耗材药物警戒的HTTP 接口与外部系统

## 这个品类的数据长什么样

高值耗材的药物警戒数据主要来源于医疗机构上报、生产企业自发收集以及国家药品不良反应监测中心的数据。其更新频率相对较高，尤其是上市后监测数据，通常以周或月为周期进行汇总和发布。文档结构方面，数据常以结构化表格形式呈现，如 CSV、Excel 或 HL7 消息格式，包含产品批次号、生产日期、有效期、植入/使用日期、不良事件描述、患者基本信息、医疗机构代码、上报人员信息等字段。不良事件描述可能包含大量非结构化文本。单位方面，涉及尺寸、重量、容量等物理参数时，会使用毫米（mm）、克（g）、毫升（ml）等标准单位，而事件发生时间则以日期时间戳格式记录。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

高值耗材数据更新频率高，要求 HTTP 接口具备高效的数据同步能力，以支持准实时的数据拉取或推送。结构化数据与非结构化文本并存的特点，意味着接口在处理数据时需要同时支持结构化字段的映射和非结构化文本的有效解析与索引，例如对不良事件描述进行关键词提取。数据来源多样性导致的数据格式差异，使得接口需要具备灵活的数据转换和清洗能力，以统一录入标准。批次号、生产日期等关键字段的精确匹配，对数据传输的完整性和准确性提出了高要求，需要确保 API 请求参数的严格校验。此外，高值耗材的特殊性可能导致不良事件描述中包含大量医学术语，对知识库的语义理解能力形成挑战。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `4000` | 确保能够容纳单条不良事件的完整描述及相关产品信息。 |
| `分段长度` | `500 字符` | 平衡文本块的完整性和检索效率，避免过长文本影响相似度计算。 |
| `召回条数` | `前 10 条` | 考虑到高值耗材不良事件的复杂性，增加召回数量以提高相关性覆盖。 |
| `相似度阈值` | `0.75` | 兼顾精确匹配和语义泛化，过滤掉不相关或弱相关结果。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 预留足够时间处理包含大量非结构化文本的报告文件。 |
| `UPLOAD_FILE_MAX_SIZE` | `100 MB` | 考虑到可能上传包含多条不良事件的批量数据文件。 |

## 容易做错的三处

*   调用 API 创建文件集合后，索引速度缓慢。原因在于上传的原始文件未经预处理，包含大量冗余信息或格式不统一，导致分词和向量化效率低下。
*   通过 API 调用工作流时，知识库助手返回空值。原因可能是工作流中嵌套的知识库助手未正确配置关联的知识库 ID，或者知识库版本不兼容，例如在 v4.8.10 以下版本创建的知识库在更高版本中调用时出现问题。
*   使用 API 上传 CSV 模板文件后，无法正确识别问题和答案列。原因在于 CSV 文件编码格式不正确，或者列顺序与预期不符，导致系统无法按 `第一列是问题，第二列是答案` 的约定进行解析。

## 怎么确认配好了

*   通过 API 上传一个典型的高值耗材不良事件报告文件（例如 CSV 格式），检查知识库索引状态，确认所有文档均已成功处理且索引完成。
*   使用 API 调用知识库检索功能，输入包含高值耗材产品型号和不良反应症状的查询语句，核对返回结果的相关性与准确性，并与预期答案进行比对。
*   模拟外部系统通过 HTTP 接口推送一条新的不良事件数据，观察系统是否能够正确接收、解析并入库，并通过查询接口验证数据是否可检索。
*   检查系统日志，确认在数据同步和知识库更新过程中没有出现 HTTP 5xx 错误码或 `Connection Timeout` 异常。
