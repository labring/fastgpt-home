# 高值耗材药物警戒的工具调用与插件

## 这个品类的数据长什么样
高值耗材的药物警戒数据主要来源于医疗机构的上报系统、生产企业的主动监测以及监管部门的抽查结果。数据更新频率不一，上市后监测数据通常按季度或年度汇总，但严重不良事件报告要求在规定时限内（例如 72 小时内）提交。文档形式多样，包括结构化的数据库记录、非结构化的临床报告文本（如 PDF 格式）、影像学资料。关键字段包括耗材的唯一标识符（如 UDI）、生产批次号、型号规格、植入或使用日期、患者基本信息、不良事件描述（ICD-10 编码或自由文本）、处理措施、事件结局以及报告来源。部分数据还会包含耗材的材料成分、灭菌方式等技术参数。

## 这些特征在「工具调用与插件」这一环带来什么约束
高值耗材数据来源的复杂性和更新频率的差异，要求工具调用与插件具备强大的数据整合能力，能够处理多种数据格式。非结构化文本和影像资料的存在，意味着仅依赖结构化查询接口不足以全面获取信息，需要结合文本解析和图像识别插件。高值耗材的唯一标识符 `UDI` 和生产批次号 `batch_number` 是追溯的关键，任何工具调用都必须能准确传递和匹配这些参数。同时，不良事件描述的自由文本内容，需要自然语言处理（NLP）工具进行实体抽取和事件分类，以便进行后续分析。对时效性要求高的严重不良事件，插件需要支持实时或近实时的 API 调用，确保数据更新的及时性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `50 MB` | 高值耗材不良事件报告常包含多页文档或影像附件，需支持较大文件上传。 |
| `maxContext` | `3000 Tokens` | 用于处理较长的不良事件描述和临床报告，确保上下文完整。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `180 秒` | 解析复杂的 PDF 报告或包含多张图片的文档可能耗时较长。 |
| `插件调用超时时间` | `60 秒` | 外部 API 调用，如查询耗材批次信息或编码映射，需预留足够响应时间。 |
| `参数传递格式` | `JSON` | 广泛支持且易于处理复杂结构化数据，如包含 `UDI` 和 `batch_number` 的查询。 |
| `错误重试次数` | `3 次` | 针对网络波动或外部服务瞬时故障，提高插件调用的健壮性。 |

## 容易做错的三处
*   调用插件时，文件类型的变量 `file_content` 传递为空，导致外部服务无法处理。这通常是由于前端文件上传组件未正确将文件内容编码为 Base64 字符串，或者后端 `file` 参数未配置为 `string` 类型。
*   Claude 模型结合工具调用时，频繁出现 `invalid_request_error` 报错。原因可能是 `tool_code` 定义与实际插件接口的 `function` 定义不一致，或者传递给工具的 `arguments` 结构不符合预期。
*   调用接口并设置 `stream: true` 后，无法正确接收到最终结果。这通常是由于客户端在处理流式响应时，未正确聚合所有分块数据，导致 `final_answer` 字段缺失或不完整。

## 怎么确认配好了
*   上传一份包含高值耗材不良事件报告的 PDF 文件，验证系统能否正确解析并提取出 `UDI`、`batch_number` 和 `不良事件描述` 等关键字段。
*   通过 FastGPT 的调试界面，模拟一次带 `UDI` 和 `batch_number` 参数的插件调用，检查外部系统是否收到正确参数并返回预期结果。
*   发送一个复杂查询，触发文本解析和外部工具调用，观察响应时间是否在 `插件调用超时时间` 设定范围内，且最终结果是否包含外部工具返回的关键信息。
