# CAR-T 细胞治疗质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

CAR-T 细胞治疗的质量文档涵盖研发、生产、质控到临床应用的全生命周期数据。其主要数据源包括实验记录、批生产记录、检验报告、偏差管理、变更控制、供应商资质、设备校准记录等。这些文档多以 PDF、Word 或结构化数据库记录形式存在，更新频率受研发进展、生产批次和监管要求驱动，呈现阶段性集中更新的特点。文档结构高度标准化，遵循 GMP (药品生产质量管理规范) 和 GxP (优良规范) 法规要求。字段方面，包含批次号、生产日期、有效期、检测项目、结果、单位 (如 `cells/mL`、`%`、`IU/mL`)、操作人员、审核人员签名等，部分关键数据具有严格的数值范围和精度要求。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

CAR-T 细胞治疗质量文档的规范性与高价值特性，对其通过 HTTP 接口与外部系统交互提出了严格要求。首先，文档结构高度标准化，要求接口具备精确的字段映射能力，以确保数据完整性。其次，数据更新的阶段性集中特点，意味着接口需支持批量导入和高效的数据同步机制，减少人工干预。再次，涉及生命科学领域的专业单位和精度要求，使得接口在数据解析时必须能正确识别并处理各类单位，避免因单位转换错误导致的数据偏差。此外，文档中包含的签名、审批流等信息，要求接口在传输过程中保持数据的不可篡改性，并能与电子签名系统集成。最后，大量历史文档的归档与查询需求，对外部系统的存储容量和检索性能构成挑战。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `分段长度` | `500–800 字符` | 确保单个文本段落包含足够上下文，同时避免过长影响召回效率，兼顾专业术语的完整性。 |
| `最大连接数` | `10–20` | 平衡高并发请求与外部系统处理能力，适应文档批次性更新的负载峰值。 |
| `超时时间` | `60 秒` | 考虑大型 PDF 或复杂结构化文档的解析与传输耗时，避免因网络波动或处理延迟导致连接中断。 |
| `HTTP 方法` | `POST` | 适用于批量上传或创建新文档记录，支持携带复杂请求体，确保数据传输安全性。 |
| `内容类型` | `application/json` | 标准化数据交换格式，便于结构化字段的解析与映射，支持复杂数据结构。 |
| `重试策略` | `指数退避` | 当外部系统暂时不可用时，通过逐步延长重试间隔，提高任务完成率，减少资源浪费。 |

## 容易做错的三处

*   HTTP 请求返回 `400 Bad Request` 错误，因为 JSON 请求体中包含未转义的特殊字符，导致数据解析失败。
*   文档内容导入后，部分关键数值字段为空或显示错误单位，原因是接口未正确识别或转换 `cells/mL` 这类专业单位。
*   外部系统日志显示 `software.amazon.awssdk.services.bedrockruntime.model.validationexception` 错误，通常是由于传递给大模型的输入参数格式不符合其 API 规范。

## 怎么确认配好了

*   选择一份包含复杂表格和专业术语的 CAR-T 细胞治疗批生产记录，通过 HTTP 接口上传，检查所有字段是否正确映射并保存。
*   模拟一次批量文档导入，监控外部系统的处理队列和资源占用，确保在高并发下系统稳定运行，无超时或数据丢失。
*   从外部系统随机抽取 5 份导入的文档，验证其关键数值字段的单位和精度是否与原始文档保持一致，并进行一次简单的语义查询。
