# CDMO质量文档的工具调用与插件

## 这个品类的数据长什么样

CDMO（合同研发生产组织）的质量文档涉及药品、医疗器械等产品的研发、生产全生命周期，数据来源多样，包括实验记录、批生产记录、检验报告、偏差调查、变更控制、供应商资质文件等。这些文档通常以 PDF、Word、Excel 等格式存储，部分数据可能存在于 LIMS（实验室信息管理系统）或 MES（制造执行系统）中。文档更新频率高，尤其是生产批记录和检验数据，可能按批次或每日更新。文档结构严谨，遵循 GMP 等法规要求，包含大量结构化和半结构化数据。字段例如批号、产品名称、规格、生产日期、有效期、检验项目、检验结果、判定标准、单位（如 mg/mL, ppm, EU/mL）等，精度要求高，单位换算需准确。

## 这些特征在「工具调用与插件」这一环带来什么约束

CDMO质量文档的复杂性与高精度要求，对工具调用与插件带来了特定约束。首先，大量文档以非结构化形式存在，需要强大的文档解析能力，将关键信息提取为可操作的数据。其次，数据分散在不同系统和文件类型中，工具链需要整合多种数据源的连接器。再次，法规遵循和审计追溯性要求，使得工具调用的每一步操作，尤其是数据修改和外部系统交互，都必须有明确的日志记录和权限控制。对于检验结果等关键数值，单位的识别和标准化至关重要，避免因单位不一致导致的数据误读。此外，频繁的文档更新要求工具调用能快速同步最新数据，并触发相应的业务流程，例如批次放行前的复核。对外部 LIMS 或 MES 系统的调用，需要确保数据传输的稳定性和安全性，并处理可能出现的 API 响应延迟或错误。

## 配置怎么定

| 配置项                 | 建议取法                                        | 这样取的依据                                                                                             |
| :--------------------- | :---------------------------------------------- | :------------------------------------------------------------------------------------------------------- |
| `maxContext`           | `8192`                                          | 质量文档通常篇幅较长，需要更大的上下文窗口来捕获完整信息。                                               |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`                                        | 大型 PDF 或多页 Excel 文档解析耗时较长，避免因超时导致解析失败。                                          |
| `ChunkSize`            | `500-800 字符`                                  | 质量文档中的关键信息密度高，适中的分段长度有助于保持上下文完整性，提高召回准确率。                       |
| `embeddingModel`       | `text-embedding-ada-002` 或更高版本             | 需要高精度的向量化模型，以准确捕捉质量文档中专业术语和概念的语义相似性。                                 |
| `toolCallMaxRetry`     | `3 次`                                          | 外部系统（如 LIMS）API 调用可能因网络波动或服务瞬时负载高而失败，增加重试次数提高成功率。                |
| `apiTimeoutSeconds`    | `120 秒`                                        | 外部系统 API 响应可能因数据量大或复杂查询而延迟，设置较长的超时时间以避免中断。                           |

## 容易做错的三处

*   现象：工具调用后，模型未输出预期的思维过程或直接给出错误结果。
    原因：工具定义中对参数的描述不明确或示例不足，导致模型无法正确理解工具功能和参数要求。
*   现象：尝试调用本地服务时，报错 `Connection refused` 或 `Timeout`。
    原因：本地服务未正确配置网络访问权限，或 FastGPT 容器无法访问到本地服务的 IP 地址和端口。
*   现象：在处理检验报告时，数值字段被识别为文本，导致后续计算或比较失败。
    原因：文档解析器在处理表格或特定格式的报告时，未能正确识别数值类型，单位信息也未被提取和标准化。

## 怎么确认配好了

*   选择一个典型的批生产记录 PDF 文件，上传并观察其解析后的分段内容，检查关键字段和数值是否被正确提取。
*   配置一个调用 LIMS 查询批次检验结果的工具，通过实际对话测试，验证工具能否成功调用并返回准确的检验数据。
*   设计一个包含单位转换的复杂查询，例如“将批次 X 的某种成分含量从 ppm 转换为 mg/mL”，观察模型是否能正确调用插件进行单位换算并给出结果，且结果单位正确。
