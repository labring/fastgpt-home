# DTP 药房质量文档的部署与升级

## 这个品类的数据长什么样

DTP 药房的质量文档核心围绕药品流通、储存、调配与患者服务环节，数据来源主要是药房内部管理系统、药监部门合规要求、以及药厂提供的药品说明书与批次信息。文档更新节奏相对频繁，尤其涉及新药上市、药品批次变更、GSP（药品经营质量管理规范）修订或药监检查反馈时。文档结构上，通常包含标准操作规程（SOP）、质量管理手册、培训记录、偏差处理报告、不良反应监测记录、冷链管理记录等。字段与单位方面，涉及药品批号、有效期、储存条件（如温度单位摄氏度 `℃`）、调配剂量（毫克 `mg`、毫升 `ml`）、患者用药依从性数据等，对数据准确性、溯源性要求极高。

## 这些特征在「部署与升级」这一环带来什么约束

DTP 药房质量文档的数据来源多样且更新频繁，对 FastGPT 的部署带来了数据同步的实时性与准确性挑战。例如，新药批次信息或GSP更新后，需快速导入并索引，确保检索结果的时效性。文档内容涉及大量规范性文本和精确数值，要求 FastGPT 在文档解析和向量化过程中保持对专业术语和计量单位的敏感性。部署时需要考虑与药房现有管理系统的集成，实现文档的自动化抓取和更新。升级过程中，由于文档关联药品安全和合规，任何中断或错误都可能影响药房正常运营，因此对回滚机制和兼容性测试有严格要求。此外，文档中包含的敏感患者信息和商业数据，要求部署方案必须满足高安全性和数据隔离标准。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | DTP 药房的 SOP、质量手册可能包含大量图片或扫描件，单文件较大。 |
| `maxContext` | `1000–1200 字符` | 质量文档通常逻辑严谨，上下文关联性强，需要较长的上下文窗口以理解完整语境。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 复杂 PDF 文档解析耗时较长，避免因超时导致文件导入失败。 |
| `分段长度` | `400 字符` | 保证单个文本段落包含足够信息，同时避免过长导致语义分散，便于召回。 |
| `召回条数` | `前 8 条` | 质量文档查询通常需要多角度信息支持，增加召回条数提高相关性。 |
| `相似度阈值` | 按实测标定 `0.75–0.85` | 确保召回内容的精准性，规避低相关度信息干扰，可根据实际测试结果微调。 |

## 容易做错的三处

*   新版本部署后，嵌入式前端页面无法显示或功能异常，现象是浏览器控制台显示 `404` 错误或 CORS 跨域错误。原因是部署时未正确配置前端静态资源路径，或 `CORS_ALLOWED_ORIGINS` 环境变量未包含药房前端系统的域名。
*   导入大量质量文档后，部分查询结果出现药品批号或剂量单位混淆，现象是返回的数值与文档原文不符或单位错误。原因是文档预处理时未对特定格式的数字和单位进行标准化处理，导致向量化时语义丢失。
*   系统升级后，原有的自动化文档同步任务失败，现象是日志显示 `API Key invalid` 或 `Connection refused`。原因是升级过程中配置文件被覆盖，或服务端口发生变化，导致 API 凭证或网络配置失效。

## 怎么确认配好了

*   选择一份包含药品批号、有效期和储存条件的 SOP 文档，上传至 FastGPT，并尝试提问相关信息，核对返回结果中的批号、日期和温度单位是否准确无误。
*   模拟一个 GSP 检查场景，提出关于冷链管理、药品出入库流程等复杂问题，检查 FastGPT 返回的回答是否完整、逻辑清晰，并且引用了正确的质量管理手册章节。
*   通过 API 接口尝试从外部系统触发一次文档更新，观察更新后的文档内容是否能在 FastGPT 中被及时索引并正确检索，确保数据同步机制工作正常。
