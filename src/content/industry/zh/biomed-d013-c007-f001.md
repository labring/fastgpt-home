# GMP 合规质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

GMP 合规相关的质量文档通常包括标准操作程序（SOP）、批生产记录、检验记录、验证报告、偏差处理报告、变更控制文件等。这些文档的来源多样，主要由企业内部各部门（如生产、质量控制、质量保证）在日常运营中生成。文档更新频率不一，SOP 和验证报告可能每年或根据变更需求修订，而批生产记录和检验记录则随批次生产实时生成，更新频率极高。文档结构通常高度标准化，例如 SOP 会有固定的章节标题和内容格式，批生产记录则包含大量表格数据、签名栏和时间戳。字段与单位方面，涉及大量化学物质名称、浓度、批号、生产日期、有效期、温度、压力、pH 值等，单位必须严格遵循药典或行业标准，如 mg/L、℃、kPa 等，并常包含特定的编码规则，例如批号可能包含生产地点、年份和序列号的复合结构。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

GMP 合规文档的数据特征对 HTTP 接口与外部系统提出了具体约束。实时生成的批生产记录和检验记录要求接口具备高并发处理能力和低延迟响应，以确保生产流程不中断。标准化文档结构意味着接口在解析时可以依赖预定义的模板或字段映射，提高处理效率和准确性，但也要求接口能处理不同文档版本间的微小差异。字段与单位的严格性要求接口具备强类型校验能力，防止数据录入错误或单位混淆。例如，对于温度字段，必须校验其是否为数字且在合理区间内，并识别单位如“℃”或“K”。此外，部分文档可能以 PDF 或扫描件形式存在，需要通过 OCR 服务转换为可结构化数据，这引入了额外的预处理步骤和可能的文件大小限制。文档更新频率差异要求系统能够灵活配置触发机制，例如，对于实时数据可采用消息队列推送，而对于定期修订的 SOP 可采用定时抓取或版本控制系统钩子触发。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `50 MB` | GMP 文档常包含大量图片或扫描件，单文件大小可能较大，此值需高于一般办公文档 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | OCR 或复杂结构化解析耗时较长，需要足够长的超时时间以避免中断 |
| `HTTP_CLIENT_TIMEOUT_MS` | `10000 毫秒` | 外部系统响应可能受限于其内部处理负载，需要适当延长客户端超时 |
| `CHUNK_SIZE` | `800–1200 字符` | 保留文档上下文完整性，避免关键信息被截断，特别是批记录中的操作步骤描述 |
| `METADATA_FIELDS_TO_EXTRACT` | `批号, 产品名称, 生产日期, 有效期, 文档类型` | 这些是 GMP 文档中用于检索和合规性审计的核心元数据 |
| `RETRY_ATTEMPTS` | `3 次` | 外部系统偶尔出现瞬时故障，重试机制可提高数据同步的健壮性 |

## 容易做错的三处

*   上传 PDF 文件后，自定义解析服务接口长时间无响应并最终超时，原因在于 `PARSE_FILE_TIMEOUT_SECONDS` 设置过短，未能覆盖 OCR 和复杂结构化解析的实际耗时。
*   API 调用知识库应用后，返回内容未包含知识库信息，现象为回复泛泛而谈，原因在于 API 调用时未正确传递 `knowledge_base_id` 或 `use_knowledge_base` 参数，导致知识库未被激活。
*   外部系统回调接口接收到的数据中，某些关键字段（如“批号”或“生产日期”）为空，原因是 `METADATA_FIELDS_TO_EXTRACT` 配置不全或文档解析器未能正确识别这些字段的抽取规则。

## 怎么确认配好了

*   上传一份包含复杂表格和多页内容的 GMP SOP PDF 文件，观察其是否能在 `PARSE_FILE_TIMEOUT_SECONDS` 设定的时间内完成解析，并检查解析结果是否包含所有预期章节。
*   通过 API 调用已配置知识库的应用，使用特定 GMP 合规问题进行提问，确认返回内容中是否引用了知识库中的相关文档片段，且引用的 `knowledge_base_id` 正确。
*   模拟外部系统通过 HTTP 接口提交一份完整的批生产记录数据，检查系统日志中是否有数据接收成功的记录，并核对抽取出的 `METADATA_FIELDS_TO_EXTRACT` 字段值是否准确无误。
