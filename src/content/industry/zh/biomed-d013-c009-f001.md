# II-III 期临床质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样
II-III 期临床试验的质量文档数据来源多样，主要包括临床试验方案、研究者手册、知情同意书、伦理审批文件、试验记录表（CRF/eCRF）、实验室检测报告、影像学数据、统计分析计划及报告、以及不良事件（AE/SAE）报告。这些文档通常以 PDF、DOCX、XLSX 等格式存储，部分数据可能以结构化数据库记录形式存在。更新频率方面，方案修订、CRF 填写、AE/SAE 报告等在试验进行中持续发生，而统计分析报告等则在特定里程碑节点生成。文档结构复杂，包含大量专业术语和缩写。字段与单位方面，涉及剂量（mg/kg）、时间点（小时/天）、生物标志物（ng/mL）、疗效指标（百分比变化、绝对值）等，且不同文档可能存在同一概念的不同表达。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
II-III 期临床质量文档的复杂性与多样性对 HTTP 接口与外部系统集成提出了特定要求。首先，文档格式的多样性意味着接口需支持多种文件类型上传与解析，并能从非结构化文本中准确提取关键信息。其次，持续更新的性质要求接口具备增量同步和版本管理能力，确保平台内知识库的时效性。例如，新的不良事件报告需及时更新到知识库。文档中的专业术语和缩写，以及不同表达方式，要求在数据预处理阶段进行标准化和实体识别，以提高后续检索和问答的准确性。最后，涉及的字段与单位的严谨性，使得接口在数据传输和存储时必须保持数据类型和单位的一致性，避免因单位转换或数据类型不匹配导致的错误，这在与外部数据库系统对接时尤为关键。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `4096 tokens` | 确保能够承载复杂的临床试验方案或研究者手册的关键上下文。 |
| `UPLOAD_FILE_MAX_SIZE` | `200 MB` | 覆盖大型影像报告或包含大量图表的 PDF 文档上传需求。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 为大型、结构复杂的临床文档提供充足的解析时间。 |
| `分段长度` | `800–1200 字符` | 平衡上下文完整性与检索效率，适应临床文档的段落结构。 |
| `相似度阈值` | `0.75` | 提高针对专业术语和关键信息的召回精度，减少无关结果。 |
| `API_KEY_CHECK_MODE` | `strict` | 对外部系统调用进行严格的身份验证，保障数据安全。 |

## 容易做错的三处
*   调用接口后收到 `{"code":514,"statusText":"unAuthApiKey","message":"common:code_error.e` 报错，原因是 `Authorization` 请求头中未提供有效的 `API_KEY` 或 `API_KEY` 已过期。
*   上传大型临床试验方案 PDF 后，长时间未见知识库更新，且无任何错误提示，通常是 `PARSE_FILE_TIMEOUT_SECONDS` 配置过低导致文件解析超时。
*   通过 API 检索时，发现相关不良事件报告未能被召回，但日志显示知识库已更新，现象是 `相似度阈值` 设置过高，导致语义相近但并非完全匹配的文档被过滤。

## 怎么确认配好了
*   上传一份包含专业术语的 II-III 期临床试验方案 PDF，通过 API 调用 `/api/v1/chat/completions` 接口，验证是否能准确回答文档内容。
*   使用不同的 `chatId` 参数多次调用 API，检查 FastGPT 后台的对话日志，确认每次对话是否正确关联到对应的 `chatId`。
*   模拟外部系统通过 HTTP 接口提交一份新的不良事件报告，并立即通过检索接口验证报告内容是否可被召回，并检查 `召回条数` 是否符合预期。
