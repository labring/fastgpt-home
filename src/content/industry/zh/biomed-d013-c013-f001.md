# mRNA 疫苗质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

mRNA 疫苗的质量文档核心数据来源于生产批次记录、原辅料检测报告、中间产品放行检测、终产品质量控制报告、稳定性研究数据以及偏差处理与变更控制记录。这些数据通常以结构化（如 LIMS 系统导出报告、GMP 生产执行系统日志）和非结构化（如 Word、PDF 格式的分析报告、实验记录）的形式存在。数据更新频率高，尤其是在研发和临床试验阶段，新的批次数据和分析结果会持续生成。文档结构复杂，包含大量专业术语、图表和数据表格，涉及分子生物学、免疫学和药学等多个领域。字段和单位具有严格的规范性，例如 mRNA 纯度（%）、脂质纳米粒（LNP）粒径（nm）、内毒素含量（EU/mg）以及 RNA 完整性（%）。批次信息、生产日期、有效期等关键字段是数据关联和追溯的基础。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

mRNA 疫苗质量文档数据的高更新频率要求 HTTP 接口具备高效的轮询机制或Webhook回调能力，以确保新数据的及时同步。文档的复杂结构和专业字段，意味着外部系统在解析和处理时需要强大的语义理解能力和定制化的数据抽取规则，常规的通用解析器可能无法准确识别关键信息。例如，`LNP 粒径分布`这类数据可能以图表形式存在，需要图像识别与数据提取技术。严格的字段规范性要求接口返回的数据类型和单位必须与预期严格匹配，任何不一致都可能导致下游分析错误。批次数据关联的必要性，使得 HTTP 请求在携带 `batch_id` 或 `lot_number` 等参数时，需要确保其在外部系统中具有唯一性和可查询性，以实现不同文档间的有效链接。处理非结构化文档时，接口的响应负载可能较大，需要考虑网络带宽和超时设置。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `600 秒` | 应对大体积非结构化文档解析和数据抽取可能产生的较长等待时间，避免过早超时。 |
| `MAX_RETRIES` | `3 次` | 鉴于生物医药外部系统可能存在瞬时网络波动或服务繁忙，适当重试有助于数据成功获取。 |
| `AUTH_HEADER_NAME` | `X-API-Key` | 多数生物医药数据平台采用 API Key 或 Token 进行身份验证，这是常见且安全的实践。 |
| `JSON_PATH_FOR_BATCH_ID` | `$.data.batchInfo.batchId` | 确保从外部系统返回的 JSON 响应中准确提取批次ID，以用于后续关联和过滤。 |
| `POLLING_INTERVAL_SECONDS` | `3600 秒` | 考虑到生产批次数据更新周期通常以小时计，此间隔可在保证及时性与降低系统负载间取得平衡。 |
| `ERROR_CODE_FOR_DATA_NOT_FOUND` | `404` 或 `204` | 明确区分接口调用失败与请求资源不存在或无内容的情况，便于错误处理逻辑。 |

## 容易做错的三处

*   HTTP 请求返回 `500 Internal Server Error`，但外部系统日志中未见明显异常。这通常是因为外部系统处理了请求，但在构建响应体时因数据格式不符或内部逻辑错误导致服务崩溃。
*   接口调用成功，但返回的 `mRNA_Purity` 字段值为空或数据类型错误。这表明外部系统的数据抽取规则未能正确识别或转换质量报告中的特定字段。
*   多个并发请求导致部分批次数据获取失败，返回 `429 Too Many Requests`。这是由于外部系统对API调用频率有限制，未对并发量进行有效控制。

## 怎么确认配好了

*   针对一个已知批次的质量文档，通过 HTTP 接口发起请求，检查返回的 `batchId`、`mRNA_Purity` 和 `LNP_Size` 等关键字段是否与原始文档一致。
*   模拟外部系统更新一个批次的稳定性数据，并观察系统是否在 `POLLING_INTERVAL_SECONDS` 设定的时间窗内成功拉取并更新了数据。
*   使用一个不合法的 `X-API-Key` 发起请求，确认接口返回 `401 Unauthorized` 错误。
*   构造一个包含大量文本的非结构化文档请求，验证在 `HTTP_REQUEST_TIMEOUT_SECONDS` 设置内能否成功完成数据处理和返回。
