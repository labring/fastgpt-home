# 临床决策支持质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

临床决策支持系统（CDSS）的质量文档主要来源于权威医学指南、临床路径、药品说明书、疾病诊疗规范、以及医学文献数据库。这些文档以结构化和半结构化数据为主，例如 XML、JSON、PDF、Word 文档等。更新频率相对较高，特别是针对新药上市、诊疗方案调整、指南修订等情况，可能需要每周甚至每日更新。文档内部包含大量的医学术语、计量单位（如 mg/dL、mmol/L、IU/mL）、诊断代码（如 ICD-10）、药物代码（如 ATC）等专业字段。数据量通常庞大，一份指南可能包含数百页，且内部交叉引用复杂。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

CDSS 质量文档的高更新频率要求 HTTP 接口具备高效的数据同步机制，例如支持增量更新或带有版本控制的拉取。大量的专业术语和代码需要接口在数据传输时保持其语义完整性，避免因字符编码或数据类型转换错误导致信息失真。文档内部复杂的结构和交叉引用，对接口的数据解析能力提出挑战，需要能够处理嵌套 JSON、XML 结构，并能正确识别并关联不同文档间的引用关系。此外，文档中包含的计量单位和代码，要求 HTTP 请求模块能够配置自定义解析器或预处理脚本，确保数据在导入 FastGPT 后能被正确识别和应用。庞大的数据量也对接口的传输效率和稳定性有较高要求，需要支持分块传输或断点续传。

## 配置怎么定

| 配置项                       | 建议取法                                 | 这样取的依据                                                                 |
| :--------------------------- | :--------------------------------------- | :--------------------------------------------------------------------------- |
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `600 秒`                                 | 应对大型医学指南下载或复杂数据解析可能产生的长时间连接需求                     |
| `MAX_FILE_SIZE_MB`           | `200 MB`                                 | 单个临床指南 PDF 或 Word 文档可能较大，避免因文件过大导致上传失败            |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒`                                 | 复杂结构化文档（如 XML、JSON）解析耗时较长，预留足够时间                     |
| `CHUNK_SIZE_TOKENS`          | `800–1200 字符`                          | 平衡语义完整性和模型处理效率，避免切片过小丢失上下文或过大超出模型上下文窗口 |
| `RECALL_TOP_K`               | `按实测标定`                             | 临床决策支持对信息准确性要求高，需通过测试确保召回覆盖关键信息               |
| `ENABLE_COOKIE_PERSISTENCE`  | `true`                                   | 部分医学数据库或认证接口可能依赖 Cookie 维持会话状态                         |

## 容易做错的三处

*   HTTP 请求返回 401 或 403 错误码，原因在于未正确配置认证信息或 API 密钥，导致无法访问受保护的医学知识库接口。
*   导入的文档内容中出现乱码或特殊符号无法识别，原因在于 HTTP 响应头未正确指定字符编码（如 `Content-Type: application/json; charset=UTF-8`），或 FastGPT 未能正确解析。
*   部分字段（如疾病代码、药物剂量单位）在导入后为空或格式错误，原因在于 HTTP 请求模块的响应解析配置不当，未能正确提取或转换 JSON/XML 中的嵌套数据或特定计量单位。

## 怎么确认配好了

*   通过 FastGPT 的 HTTP 请求模块，成功获取并预览一份完整的临床指南 PDF 或结构化 JSON 文档，检查内容是否正确无误，无乱码。
*   模拟一次知识库更新操作，检查 FastGPT 中的知识分段数量和内容更新时间戳，确保与源系统数据同步。
*   配置一个包含特定医学术语或代码的查询，验证 FastGPT 能否准确召回相关文档片段，并通过日志确认召回条数和相似度阈值符合预期。
