# 健康管理质量文档的工具调用与插件

## 这个品类的数据长什么样

健康管理领域的质量文档通常包含服务协议、操作规程、风险评估报告、用户健康档案、随访记录、设备校准记录以及合规性审计报告。数据来源多样，包括医疗设备、传感器、用户手动输入、医生诊断记录和第三方检测机构。数据更新频率不一，用户健康档案和随访记录可能每日或每周更新，而操作规程和合规性报告则可能按季度或年度修订。文档结构上，常采用结构化与非结构化混合形式，例如健康档案可能包含血压、血糖等结构化指标，也包含医生问诊记录的非结构化文本。字段与单位具有行业特异性，如血压（mmHg）、血糖（mmol/L）、心率（bpm），并且常常涉及医学术语和缩写。

## 这些特征在「工具调用与插件」这一环带来什么约束

健康管理质量文档的工具调用与插件面临多重约束。数据来源多样性和更新频率差异，要求工具能灵活对接多种数据接口（如 HL7 FHIR、RESTful API）并支持定时数据同步，以确保知识库内容的实时性和准确性。文档结构复杂性意味着需要高级文本处理能力，例如从非结构化文本中提取关键结构化信息，并进行语义理解。字段与单位的特异性，则要求工具调用时能正确解析和处理这些医学专用数据，避免单位混淆或数据误读。例如，当调用健康评估插件时，必须确保血压、血糖等参数能够被正确识别并传递给插件进行计算。此外，合规性要求也意味着对数据隐私和安全有更高标准，插件调用必须符合 HIPAA 或 GDPR 等法规，并对敏感数据进行脱敏处理。

## 配置怎么定

| 配置项             | 建议取法       | 这样取的依据                                   |
| :----------------- | :------------- | :--------------------------------------------- |
| `maxContext`       | `4096 tokens`  | 兼顾长文档理解与模型响应速度，避免上下文溢出。 |
| `召回条数`         | `10 条`        | 覆盖多维度信息，提升检索全面性。             |
| `相似度阈值`       | `0.75`         | 确保召回内容的关联度，避免无关信息干扰。     |
| `重排返回条数`     | `3 条`         | 精炼最终输出，聚焦最相关内容。               |
| `PARSE_FILE_TIMEOUT_SECONDS` | `180 秒` | 处理大型健康报告或操作手册可能需要较长时间。 |
| `tool_response_timeout` | `60 秒` | 多数健康服务API响应时间，避免长时间等待。    |

## 容易做错的三处

*   模型回答速度慢或无响应，原因是工具调用返回的数据量过大，超过了模型处理的上下文限制。
*   知识库检索结果与用户问题不符，原因是文本分段策略不合理，导致医学术语或关键指标被错误切分。
*   工具调用失败并返回 `400 Messages with role 'tool' must be a response to a preceding message` 错误，原因是插件在没有收到模型请求时尝试发送响应，或者响应格式不符合预期。

## 怎么确认配好了

*   通过测试用例验证，输入包含特定健康指标的问题，观察模型能否正确调用工具并返回准确的计算结果。
*   检查日志输出，确认关键医学字段和单位在数据传输和处理过程中是否保持一致且无丢失。
*   模拟多种健康管理场景，例如风险评估、用药提醒，观察工具调用流程是否顺畅，并检查最终输出是否符合预期。
*   对比原始文档与模型基于工具调用生成的摘要或分析，评估信息提取和处理的准确性。
