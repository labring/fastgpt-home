# 冷链物流质量文档的文档解析与分块

## 这个品类的数据长什么样
冷链物流的质量文档主要包括温湿度记录、设备校准证书、验证报告、SOP（标准操作规程）以及偏差处理记录等。数据来源多样，涵盖传感器自动记录、人工填写表单和第三方检测机构出具的报告。更新节奏因文档类型而异：温湿度数据可能是分钟级或小时级，SOP 和验证报告则通常是季度或年度更新，或在发生变更时更新。文档结构上，PDF 报告常见表格、图表和文本混排；SOP 则多为章节式、带有明确的步骤和责任人定义。字段和单位方面，温度常以摄氏度（℃）或华氏度（℉）表示，湿度以百分比（%RH）表示，时间戳精确到秒，涉及设备型号、批次号等标识符。

## 这些特征在「文档解析与分块」这一环带来什么约束
冷链物流质量文档的特性对文档解析与分块提出了具体要求。首先，温湿度记录中的时间序列数据和数值型数据密集，需要解析器能准确识别并提取数字和单位，避免将连续数据误分为多个独立块。其次，SOP 文档的层级结构和步骤描述，要求分块逻辑能保持指令的完整性，不应在关键步骤中间截断。再次，大量表格和图表的存在，意味着增强型 PDF 解析能力至关重要，以确保表格结构不被破坏，图表描述文字能被关联。最后，文档更新频率的差异，要求在分块后能有效识别文档版本，并支持增量更新，避免重复处理大量未变动内容，特别是对于日志类数据，需要按时间范围或事件进行有效切分。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `分段长度` | `800–1200 字符` | 适应SOP中较长的步骤描述和验证报告中的段落，确保上下文完整性。 |
| `最大段落深度` | `3` | 匹配SOP文档常见的三级标题结构，如“章节-子章节-具体步骤”。 |
| `启用PDF增强解析` | `是` | 确保表格和图表中的文本内容及结构能被正确识别和提取。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 应对包含大量图表或扫描件的报告，避免解析超时。 |
| `索引大小` | `128` | 平衡索引粒度和召回效率，适用于包含多种信息类型的质量文档。 |
| `API_FILE_CHUNK_SIZE` | `2000000 字节` | 适应单个温湿度记录文件可能较大的情况，避免API上传限制。 |

## 容易做错的三处
*   解析结果中表格数据错乱或缺失：原因在于未启用或配置不当的增强型 PDF 解析功能，导致解析器无法正确识别表格的行与列结构。
*   SOP 文档的步骤说明被截断，导致语义不完整：原因在于 `分段长度` 设置过小，或分块策略未考虑段落的完整性，在关键指令中间进行了切分。
*   通过 API 上传文档时出现 `413 Payload Too Large` 错误：原因在于 `API_FILE_CHUNK_SIZE` 或服务器端的 `client_max_body_size` 配置小于实际上传的文件大小。

## 怎么确认配好了
*   选取包含复杂表格和图表的验证报告，上传后检查分块结果，确认表格内容是否完整且结构清晰。
*   选择一份典型的 SOP 文档，查看解析后的文本块，确保每个操作步骤的描述作为一个完整语义单元被保留，没有出现不自然的截断。
*   上传一个大小接近 `UPLOAD_FILE_MAX_SIZE` 限制的温湿度记录文件，观察是否能正常完成解析并生成索引，检查日志中是否有文件大小相关的警告或错误。
*   针对不同更新频率的文档，例如频繁更新的温湿度日志和不常更新的SOP，分别进行上传和解析，验证系统对增量更新和版本管理的表现。
