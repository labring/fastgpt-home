# 减毒灭活疫苗质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样
减毒灭活疫苗的质量文档数据主要来源于研发、生产、质检、批签发等环节。其数据更新频率相对较低，通常随批次生产和监管要求进行更新，例如每批次生产记录、检验报告、偏差处理报告等。文档结构以结构化和半结构化数据为主，常见格式包括 PDF、Word、Excel，其中包含大量表格和图表。关键字段包括批号、生产日期、有效期、检验项目、检验结果、限度、设备校准记录、偏差描述、变更控制编号等。单位方面，涉及浓度（IU/ml、μg/ml）、效价（TCID50/ml、PFU/ml）、pH值、温度（℃）、压力（kPa）等，对精度要求高。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
减毒灭活疫苗质量文档的低更新频率意味着外部系统同步时无需高频轮询，可以采用事件驱动或定时批量同步，以减少资源消耗。文档中复杂的表格和图表结构，对HTTP接口的数据解析能力提出要求，需要支持多种文件格式的解析，并能准确提取表格数据。多样的字段和严格的单位要求，在数据传输时需要确保字段类型和值范围的校验，避免因数据格式不匹配导致的解析错误。例如，效价数据可能包含科学计数法，接口需能正确处理。此外，大量历史批次数据意味着单次请求的数据量可能较大，需要考虑HTTP请求体大小限制和分块传输机制。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :------------------------------- | :------------------- | :----------------------------------------------------------- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 考虑到单个批次文档集合可能较大，预留充足的文件上传上限。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 复杂PDF或Word文档解析耗时较长，避免因超时导致解析失败。 |
| `分段长度` | `800–1200 字符` | 兼顾语义完整性和向量检索效率，避免过长或过短的文本段落。 |
| `相似度阈值` | `0.75` | 确保召回的质量文档与查询高度相关，过滤无关信息。 |
| `请求超时时间` | `120 秒` | 处理外部系统响应慢或数据量大时的潜在延迟。 |
| `批处理间隔` | `按实测标定` | 根据外部系统负载和数据更新频率，动态调整批次同步间隔。 |

## 容易做错的三处
*   调用接口出现 `413 Request Entity Too Large` 错误，原因在于单次HTTP请求上传的文档大小超过了服务器或网关配置的限制。
*   访问登录接口时出现 `URIError: URI malformed` 报错，通常是由于URL参数中包含了未正确编码的特殊字符。
*   接收到 `400 Bad Request` 响应，但请求体看似正确，原因可能在于请求头中的 `Content-Type` 与实际发送的数据格式不匹配，或者请求体内部某个字段的格式不符合API预期。

## 怎么确认配好了
*   通过HTTP接口上传一个包含复杂表格和图表的减毒灭活疫苗批生产记录PDF文件，检查是否能正常解析并入库。
*   使用一个包含特殊字符（如批号中的斜杠）的查询，通过HTTP接口调用知识库，验证召回结果的准确性。
*   模拟一个超过 `UPLOAD_FILE_MAX_SIZE` 的文件上传请求，确认系统返回预期的错误码，例如 `413`。
*   检查外部系统日志，确认数据同步任务按照预设的批处理间隔正常触发，并且没有出现连接超时或数据解析错误。
