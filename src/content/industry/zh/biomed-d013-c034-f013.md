# 医药电商质量文档的知识库检索与召回

## 这个品类的数据长什么样

医药电商的质量文档主要来源于药监部门的法规政策、平台自身的质量管理体系文件、供应商资质证明、药品批次检验报告、冷链物流监控记录以及用户反馈与投诉记录。这些数据更新频率较高，法规政策可能每年修订，药品批次报告随采购入库实时生成，用户反馈则持续涌入。文档结构上，法规文件通常是层级清晰的PDF或Word，平台内部SOP（标准操作规程）则以图文并茂的飞书文档或Confluence页面为主，包含流程图、表单模板和操作截图。检验报告多为结构化或半结构化的Excel、PDF，字段包括批号、生产日期、有效期、检测项目及结果，单位涉及毫克、毫升、百分比等。

## 这些特征在「知识库检索与召回」这一环带来什么约束

医药电商质量文档的频繁更新要求知识库具备高效的文档同步与增量索引能力，确保检索结果的时效性。多样的文档格式，特别是包含图片、表格和流程图的飞书文档，对文档解析器的识别能力提出挑战，需准确提取文本内容并保留关键上下文信息。检验报告中包含的批号、日期、检测结果等结构化信息，要求知识库在向量化时能有效捕捉这些关键实体，并在检索时支持基于字段的精确过滤或聚合查询。冷链数据等时序性强的数据，需要支持时间范围的检索，确保能快速定位特定时间段内的异常记录。此外，对于用户反馈，需要能从非结构化文本中识别出与特定药品或流程相关的质量问题，并关联到相应的质量文档。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `分段长度` | `500-800 字符` | 平衡上下文完整性与向量召回精度，避免单个分段过大稀释关键信息，或过小丢失上下文。 |
| `分段重叠长度` | `80-120 字符` | 确保相邻分段之间的语义关联，避免因分段截断导致关键信息被分割。 |
| `召回条数` | `前 10-15 条` | 考虑到医药电商文档的复杂性与多样性，适当增加召回数量以提高相关性覆盖。 |
| `相似度阈值` | `按实测标定` | 针对具体文档类型和查询场景，通过测试集调整，确保高召回率同时控制误报。 |
| `重排返回条数` | `前 5 条` | 在召回结果基础上，利用Reranker模型精细排序，提升最终返回结果的准确性与用户体验。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 应对大型PDF或包含复杂图表的飞书文档解析耗时，避免因超时导致解析失败。 |

## 容易做错的三处

*   现象：知识库新建后，部分文档内容缺失或格式错乱。原因：文档解析器对飞书文档中的嵌入图片、复杂表格或流程图识别能力不足，导致文本提取不完整或结构信息丢失。
*   现象：用户查询“某药品批次检验结果”时，无法召回相关检验报告。原因：知识库在导入结构化或半结构化文档时，未对批号、生产日期等关键字段进行有效提取和索引，导致基于这些字段的查询无法命中。
*   现象：上传大文件时出现超时错误或文件上传失败。原因：`UPLOAD_FILE_MAX_SIZE` 或 `PARSE_FILE_TIMEOUT_SECONDS` 参数设置过小，无法支持医药电商中常见的大型法规文件或批次报告的上传与解析。

## 怎么确认配好了

*   选择代表性的法规、SOP、检验报告等文档，导入知识库后，通过后台预览功能逐一核对文档内容是否完整、格式是否正确。
*   针对不同类型的查询（如法规条款、SOP步骤、药品批次号、异常反馈），编写测试用例，执行查询并评估召回结果的相关性与排名，确保能准确命中目标文档。
*   模拟高并发场景下的文档上传与解析操作，监控系统日志和资源使用情况，确认 `PARSE_FILE_TIMEOUT_SECONDS` 等参数设置能有效应对实际业务负载，且无文件处理失败记录。
