# 双特异性抗体质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

双特异性抗体的质量文档数据通常来源于研发、生产和质控环节，包括批次分析报告、稳定性研究数据、原辅料检测报告、工艺验证报告等。数据更新频率较高，尤其是在研发和临床试验阶段，可能每周甚至每天都有新的批次或分析结果产生。文档结构复杂，常包含大量图表、光谱数据和实验方法描述。字段方面，涉及分子量、纯度、效价、杂质谱、糖基化模式等特有指标，单位包括 `kDa`、`%`、`EU/mg` 等。部分数据以专有格式存储，如 `CDF` (Chromatography Data File) 或 `mzXML` (Mass Spectrometry XML)。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

双特异性抗体质量文档的数据来源分散和更新频率高，要求 HTTP 接口具备高并发处理能力和实时数据同步机制。复杂的文档结构和特有字段，意味着接口需要支持多种数据类型和嵌套结构，例如 JSON 或 XML 格式的数据传输，并且要能解析包含特殊字符或二进制数据的字段。专有数据格式的存在，可能需要通过外部系统进行预处理或格式转换，再通过 HTTP 接口传输标准化的元数据和文件链接。大量图表和光谱数据则要求接口支持大文件传输或提供文件存储服务的直链。单位的标准化处理在数据交换时尤为关键，避免因单位不一致导致的数据误解。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `batchSize` | `50–100` | 兼顾并发性能与单次请求处理量，避免过大的请求体导致超时。 |
| `maxPayloadSize` | `10 MB` | 适应包含图表和报告的文档大小，防止因负载过大被拒绝。 |
| `requestTimeout` | `600 秒` | 应对外部系统处理复杂数据或大文件传输可能产生的延迟。 |
| `fileExtensionWhitelist` | `pdf, docx, xlsx, json, xml` | 确保只接收合规的文档格式，避免上传非业务相关文件。 |
| `maxRetries` | `3` | 应对网络瞬时抖动或外部系统短暂不可用情况。 |
| `rateLimitPerMinute` | `120` | 控制对外部系统的请求频率，防止触发对方的限流机制。 |

## 容易做错的三处

*   HTTP 接口返回 `413 Payload Too Large` 状态码，原因是文档中包含大型光谱图或高分辨率图片，导致单次请求体超出服务器限制。
*   外部系统返回的数据中，某些关键指标的数值为空或格式错误，原因是没有针对 `CDF` 或 `mzXML` 等专有格式进行预处理或解析。
*   文档内容检索结果与实际预期不符，原因是 `maxContext` 或 `召回条数` 设置不当，未能充分获取和处理包含复杂实验方法描述的长文本上下文。

## 怎么确认配好了

*   通过模拟高并发请求，检查 HTTP 接口响应时间是否稳定在阈值以内。
*   上传包含各类图表和专有格式数据的双特异性抗体质量文档，验证数据字段和单位是否能被正确解析和显示。
*   使用包含特定分子量、纯度等指标的查询语句，验证系统能否准确召回相关文档，并检查召回条数是否满足业务需求。
