# 合理用药质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

合理用药的质量文档数据，其核心是药品说明书、临床指南、用药医嘱、不良反应报告以及相关法规条文。这些数据来源多样，包括国家药监局、医院药事管理系统、医学期刊数据库等。更新频率方面，药品说明书和临床指南通常按季度或年度更新，不良反应报告则可能实时产生。文档结构上，药品说明书具有固定的章节划分，如适应症、用法用量、禁忌症、不良反应等；临床指南则多为结构化的文本，包含诊断标准、治疗方案、药物选择等。字段与单位方面，涉及剂量（如 `mg/kg`、`片`）、频率（如 `次/日`）、疗程（如 `天`、`周`），以及特定疾病的诊断指标（如 `mmol/L`）。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

合理用药质量文档的数据特征对 HTTP 接口与外部系统集成提出了具体要求。多样的文档来源决定了需要配置多个数据源接口，并可能涉及不同的认证方式。例如，部分数据库可能需要 `API Key` 或 `OAuth2` 认证。较低的更新频率意味着数据拉取策略可以以定时任务为主，无需频繁轮询，但不良反应报告等实时性数据则需要支持事件驱动或更短的拉取间隔。固定的文档结构和丰富的字段信息，要求接口返回的数据能够被有效解析，并能映射到 FastGPT 的知识库字段，尤其是在处理剂量、频率等带有单位的数值型字段时，需要确保数据类型和单位的准确性，避免在后续的 RAG 检索中产生歧义。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `API_ENDPOINT` | 按实际数据源 API 地址配置 | 确保指向正确的外部系统接口 |
| `AUTH_HEADER` | `Bearer YOUR_API_KEY` 或 `Basic Base64(username:password)` | 根据外部系统要求的认证方式配置 |
| `UPDATE_INTERVAL_HOURS` | `24` 小时或 `168` 小时 | 药品说明书和临床指南更新频率较低 |
| `REALTIME_DATA_POLLING_SECONDS` | `300` 秒 | 针对不良反应报告等实时性要求较高的数据 |
| `RESPONSE_PARSE_SCHEMA` | 按外部 API 返回 JSON Schema 定义 | 确保正确解析返回的文档结构和字段 |
| `MAX_RETRIES_ON_FAILURE` | `3` 次 | 应对网络波动或外部系统暂时性故障 |

## 容易做错的三处

*   接口调用返回 `HTTP 401 Unauthorized` 或 `HTTP 403 Forbidden` 错误。这通常是由于 `AUTH_HEADER` 配置的 `API Key` 或 `Token` 不正确、过期，或者权限不足导致。
*   拉取的数据中，关键字段（如药品名称、剂量单位）为空或格式错误。这往往是 `RESPONSE_PARSE_SCHEMA` 定义与外部 API 返回的实际数据结构不符，或者解析规则未充分考虑字段类型与单位。
*   外部系统数据更新后，FastGPT 中知识库内容未同步。这可能是 `UPDATE_INTERVAL_HOURS` 或 `REALTIME_DATA_POLLING_SECONDS` 设置过长，未能及时触发数据同步，或者外部系统未提供有效的更新通知机制。

## 怎么确认配好了

*   通过 FastGPT 后台的“知识库”模块，手动触发一次数据同步，并检查日志输出，确认 HTTP 请求成功发出且返回状态码为 `200 OK`。
*   在知识库中随机抽取 5-10 条已同步的合理用药文档，检查其核心字段（如 `药品名称`、`适应症`、`用法用量`）是否完整、准确，并核对剂量、频率等数值字段的单位是否正确。
*   模拟一次合理用药咨询，提问包含特定药品、疾病和用量的问题，验证 FastGPT 基于新同步的知识库能否给出准确且包含关键细节的回答，并评估其与预期回答的相似度。
