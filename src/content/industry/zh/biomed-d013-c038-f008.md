# 合理用药质量文档的工具调用与插件

## 这个品类的数据长什么样

合理用药质量文档主要包含药品说明书、临床指南、用药方案、药物相互作用数据库、不良反应报告以及药师审核记录等。这些文档的来源多样，包括国家药监局、药典委员会、医院药事管理部门、国内外权威医学期刊及药学数据库。更新频率方面，药品说明书和临床指南通常按季度或年度修订，而药物相互作用数据和不良反应报告则可能实时或每日更新。文档结构以半结构化或非结构化文本为主，例如药品说明书包含适应症、用法用量、禁忌、注意事项等固定字段，但具体描述为自由文本。字段与单位方面，涉及剂量（如毫克、克）、频率（如每日一次、每小时）、疗程（如天、周）等，且存在大量医学术语缩写。

## 这些特征在「工具调用与插件」这一环带来什么约束

合理用药文档的半结构化特性要求工具调用能够灵活处理文本解析和信息提取，例如从自由文本中识别剂量、频率等关键信息。多源异构的数据来源和不同的更新频率，意味着工具需要具备动态加载和版本管理能力，确保调用的是最新、最权威的数据。例如，查询药物相互作用时，需确保调用的是实时更新的数据库接口。文档中大量的医学术语和缩写，对模型的理解能力提出高要求，可能需要定制化的词汇表或领域嵌入模型。此外，由于用药决策的严谨性，工具调用返回的结果需要高度可靠和可溯源，对失败处理和错误提示的准确性要求极高，不能出现模糊或误导性信息，例如剂量单位不匹配时的明确提示。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `16000 tokens` | 合理用药文档信息密度高，需更大上下文窗口以保证信息完整性，避免关键信息丢失。 |
| `toolCallThreshold` | `0.75` | 确保工具调用的准确性，降低误调用的风险，尤其在涉及用药安全时。 |
| `embeddingModel` | `text-embedding-ada-002` 或领域定制模型 | 处理医学术语和缩写，提高语义理解和召回准确性。 |
| `maxRetryAttempts` | `3` | 应对外部 API 偶尔出现的瞬时网络波动或服务不可用，增加工具调用成功率。 |
| `timeoutSeconds` | `60 秒` | 多数外部药学数据库响应时间较长，预留足够时间避免请求超时。 |
| `fallbackAction` | `返回用户提示并建议人工审核` | 工具调用失败时，优先保障用药安全，提示用户进行人工干预。 |

## 容易做错的三处

1.  现象：工具调用返回结果中关键剂量或频率信息缺失。原因：文档解析插件未针对合理用药文档的半结构化特点进行优化，未能从自由文本中正确提取所有必要字段。
2.  现象：模型在合理用药场景下频繁触发不相关的通用工具，例如网络搜索。原因：`toolCallThreshold` 设置过低，模型对工具调用的置信度要求不足，导致泛化性工具被误用。
3.  现象：调用外部药品数据库 API 时出现 `HTTP 504 Gateway Timeout` 错误。原因：`timeoutSeconds` 配置过短，未能充分考虑外部药学数据库的响应延迟，导致请求在等待期间超时。

## 怎么确认配好了

*   针对不同药品说明书和临床指南，通过模拟真实用药咨询场景，验证工具能否准确识别并调用相应的知识库或外部 API，并提取出正确的用药剂量、频率等关键信息。
*   检查日志中工具调用的成功率和失败原因，特别是关注 `toolCallThreshold` 导致的未调用或误调用情况，并根据实际业务场景调整阈值。
*   测试在网络波动或外部 API 暂时不可用时，系统是否能按照 `fallbackAction` 的设定进行优雅降级处理，并向用户提供明确的错误提示。
