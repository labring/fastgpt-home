# 呼吸系统质量文档的部署与升级

## 这个品类的数据长什么样

呼吸系统疾病的质量文档主要来源于临床指南、药物说明书、诊疗规范、病历模板、科研文献以及药监部门发布的法规文件。这些数据更新频率不一，临床指南和药物说明书通常每年或每两年修订，而科研文献则持续发布。文档结构上，常包含大量医学术语、缩写、剂量单位、检验指标范围及诊断标准。字段方面，常见的有疾病诊断（ICD-10 编码）、药物名称（通用名、商品名）、剂量（mg/kg、ml/h）、给药途径、频率、疗程、不良反应、禁忌症、治疗流程图、风险评估表等。单位涉及多种国际标准单位和特定医学单位，如 L/min、mmHg、mmol/L。

## 这些特征在「部署与升级」这一环带来什么约束

呼吸系统质量文档的数据特性对部署与升级提出了具体要求。文档更新频率不一，需要系统具备灵活的增量更新机制，以应对部分文档的频繁修订。医学术语和缩写密集，要求文本处理模块具备高精度的分词和实体识别能力，防止语义丢失。文档中包含大量结构化和半结构化数据（如剂量表、流程图），部署时需考虑如何有效解析并存储这些信息，以便后续检索和问答。此外，多样的计量单位和复杂的字段关联，对知识库的构建和查询理解提出挑战，需要配置合适的向量化模型和相似度算法，以确保检索结果的准确性。在升级过程中，旧数据与新数据的兼容性、模型微调以适应新知识的能力，以及私有化部署环境下多模型API的管理，都是需要重点关注的环节。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 呼吸系统相关文献和指南常包含大量图片、图表，单个文件大小可能较大。 |
| `maxContext` | `800–1200 字符` | 确保在处理复杂医学概念或长句时，上下文信息能被充分保留。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 处理大型 PDF 文档或包含复杂表格的指南时，解析耗时可能较长。 |
| `分段长度` | `300 字符` | 兼顾语义完整性和片段召回效率，避免将关键医学概念拆分。 |
| `相似度阈值` | `0.75–0.85` | 医疗领域对检索精度要求高，确保召回的文档片段与查询高度相关。 |
| `召回条数` | `前 10 条` | 增加召回范围，覆盖更多潜在相关的医学信息，提高问答准确性。 |

## 容易做错的三处

*   知识库更新后，部分查询结果出现医学术语理解偏差或关键信息缺失，原因在于新旧文档版本间的术语定义不一致，或增量更新机制未完全覆盖所有相关联的文档。
*   系统重启后，之前配置的模型API凭证失效，导致模型调用失败，现象是日志中出现 `401 Unauthorized` 错误，这是因为私有化部署时 `CHAT_API_KEY` 未持久化存储或配置方式不兼容重启后的环境。
*   上传大型诊疗指南文件时，长时间无响应或出现 `504 Gateway Timeout` 错误，原因通常是 `PARSE_FILE_TIMEOUT_SECONDS` 配置过低，未能给文件解析留出足够的时间。

## 怎么确认配好了

*   上传一份包含复杂医学术语和表格的呼吸系统诊疗指南，检查文件是否成功解析并能被检索，同时核对关键字段和单位是否正确提取。
*   使用不同版本的呼吸系统疾病指南，进行增量更新操作，然后验证系统能否同时检索到新旧版本中的信息，并区分其版本差异。
*   通过API调用FastGPT，使用多个配置了不同 `CHAT_API_KEY` 的模型组合进行问答测试，确保所有模型都能正常响应，且无 `401` 或 `403` 错误码。
*   模拟系统重启，验证私有化部署环境下所有配置（包括模型API凭证）是否保持不变，并且工作台功能正常，分享链接可访问。
