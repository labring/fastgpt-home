# 基因治疗 AAV质量文档的部署与升级

## 这个品类的数据长什么样

基因治疗 AAV（腺相关病毒）的质量文档主要包括生产批记录、检测报告、稳定性研究数据、原辅料放行单、设备校准记录和偏差处理报告等。数据来源广泛，涉及内部LIMS系统、ELN电子实验记录本、质量管理系统（QMS）和供应商提供的 CoA（Certificate of Analysis）。文档形式多样，PDF、Word、Excel、图片扫描件均有。更新节奏相对稳定，批记录随生产批次生成，检测报告随检测项目完成而更新，稳定性数据则按预设时间点周期性产生。字段与单位具有高度专业性，例如病毒滴度单位为 `vg/mL`，宿主细胞 DNA 残留量单位为 `ng/mg`，内毒素单位为 `EU/mL`。文档结构通常遵循 GMP 规范，包含固定模板和可变数据区域。

## 这些特征在「部署与升级」这一环带来什么约束

AAV 质量文档的专业性和多样性对 FastGPT 的部署提出特定要求。文档多为 PDF 格式，包含大量表格和图片，需要高效的 OCR 和表格解析能力。数据更新的周期性要求知识库具备增量更新机制，避免全量重新导入。特定字段和单位的存在，意味着在向量化和检索过程中，需要对这些专业术语有准确的理解和匹配，以确保问答的精确性。例如，检索“批次号为 `AAV2023001` 的病毒滴度”时，系统需要准确识别批次号并关联到对应的滴度值。文档的敏感性意味着部署环境需满足严格的数据安全和权限管理要求。私有化部署是应对这些约束的常见选择，确保数据不出本地网络，并能与现有 QMS 系统进行集成。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | AAV 质量文档常包含大量图表和附件，单个文件大小可能较大。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大型 PDF 文件 OCR 和表格解析耗时，需要更长的处理时间。 |
| `分段长度` | `800–1200 字符` | 兼顾语义完整性和向量召回效率，避免长段落稀释关键信息。 |
| `召回条数` | `前 8 条` | 确保覆盖文档中可能分散的关键信息，提高相关性。 |
| `相似度阈值` | `0.75–0.85` | 针对专业术语的精确匹配要求，设定较高阈值以减少误召回。 |
| `重排返回条数` | `前 4 条` | 在高召回率基础上，通过重排精选最相关的片段。 |

## 容易做错的三处

*   知识库点击报错，显示 `Failed to load knowledge base`：通常是私有化部署时，`STORAGE_DRIVER` 或 `DB_URL` 配置不正确，导致 FastGPT 无法连接到存储或数据库服务。
*   问答结果中特定字段（如批号、滴度）为空或不准确：原因在于文件预处理时，OCR 识别或表格解析对 AAV 文档中特殊格式的表格和专业术语处理不佳，导致关键信息提取失败。
*   升级后简易应用出现未捕获异常：通常是由于 Docker 容器缓存未清理，或者新版本与旧版本的数据模型存在不兼容，导致升级脚本执行不完整或服务启动异常。

## 怎么确认配好了

*   上传一个包含表格和特殊单位的 AAV 批记录 PDF 文件，检查知识库中是否正确解析出表格数据和病毒滴度、宿主细胞 DNA 残留量等专业字段。
*   使用包含 AAV 批号、检测项目和结果的查询语句进行测试，例如“查询批号 `AAV2023001` 的内毒素检测结果”，验证系统能否从相关文档中准确抽取出对应信息。
*   模拟并发用户查询，观察系统响应时间是否在可接受范围内，并检查日志中是否有大量内存溢出或数据库连接错误。
*   执行一次小版本升级操作，确认升级脚本无报错，且升级后所有原有知识库和应用功能正常运行。
