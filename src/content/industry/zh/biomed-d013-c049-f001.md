# 小分子化药质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

小分子化药的质量文档通常包括原材料检测报告、中间体分析数据、成品放行检验记录、稳定性研究报告、批生产记录等。数据来源多样，涵盖实验室信息管理系统（LIMS）、电子批记录系统（EBR）及纸质文档扫描件。这些文档更新频率较高，尤其是在生产批次频繁、研发阶段变更较多时。文档结构标准化程度高，例如批生产记录遵循 GMP 规范，包含特定的章节和字段。字段单位严格，如含量百分比、杂质 ppm、重金属 ppb 等，且常伴随检测方法、仪器型号等元数据。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

小分子化药质量文档的高度标准化和严格单位要求，使得 HTTP 接口在数据解析时需要精确匹配字段和单位，避免因数据类型不符或单位转换错误导致的数据偏差。高更新频率要求接口具备高效的数据同步能力，确保外部系统获取到的是最新版本文档。文档来源多样性意味着接口需要支持多种数据格式的解析，例如 PDF、XML、JSON，甚至图像识别（OCR）后的文本。特定的元数据（如检测方法、仪器型号）必须通过接口完整传递，以维持数据的可追溯性和合规性。数据量通常较大，对接口的响应速度和并发处理能力提出更高要求。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `1500 tokens` | 兼顾信息密度与模型处理效率，避免上下文溢出 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 应对大型 PDF 文档或复杂结构 XML 文件的解析耗时 |
| `分段长度` | `800 字符` | 保留上下文语义完整性，适用于化药文档段落结构 |
| `召回条数` | `前 10 条` | 确保相关质量控制指标和批次信息被充分检索 |
| `相似度阈值` | `0.75` | 提高检索精准度，匹配关键质量参数，避免不相关内容干扰 |
| `http_timeout` | `120 秒` | 应对外部 LIMS 或 EBR 系统响应延迟，防止请求过早中断 |

## 容易做错的三处

*   HTTP 请求返回 `504 Gateway Timeout` 错误，原因在于外部系统处理数据量过大或网络延迟，导致 FastGPT 接口等待超时。
*   外部系统接收到的文档字段数据为空，原因是 FastGPT 接口在解析 PDF 扫描件时，OCR 识别错误或未正确映射到目标字段 `batch_number`。
*   API 输出的响应速度过慢，原因是工作流中包含了多个复杂的文档解析和数据校验步骤，且未进行异步优化。

## 怎么确认配好了

*   通过 FastGPT 的调试界面，检查 `HTTP 请求` 模块的 `响应状态码` 是否为 `200`，并确认 `响应体` 中包含预期的字段 `assay_result`。
*   在外部系统中，随机抽取 5-10 个批次的化药质量文档，比对其关键字段 `purity_percentage`、`impurity_A_ppm` 是否与 FastGPT 提供的接口数据一致。
*   使用 FastGPT 的 API 接口进行压力测试，模拟 50 并发用户请求，观察平均响应时间是否在 5 秒以内，并检查日志中是否存在 `HTTP 5xx` 错误。
*   定期检查 FastGPT 日志，确认 `PARSE_FILE_TIMEOUT_SECONDS` 配置的超时时间内没有出现大量解析失败记录。
