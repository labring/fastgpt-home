# 工艺验证质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

工艺验证质量文档主要包括验证方案、验证报告、偏差处理记录、变更控制记录等。这些文档通常来源于生产现场的设备数据采集系统、实验室信息管理系统（LIMS）以及人工填写的纸质记录数字化后形成的结构化或半结构化数据。数据更新频率在验证周期内较为密集，尤其是在执行阶段，可能每天都有新的批次数据或检测结果录入。文档结构严谨，遵循 GMP/GLP 规范，包含批次信息、设备参数、操作规程、检测方法、统计分析结果等关键字段。字段单位多样，如温度（℃）、压力（kPa）、时间（min）、浓度（mg/L），且常伴随特定的批号、序列号等标识符。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

工艺验证文档的严格结构和多源性，要求 HTTP 接口具备强大的数据解析能力，以处理来自不同系统的数据格式，包括 XML、JSON 或 CSV。文档更新的密集性意味着接口需要支持高并发的数据写入，并具备有效的数据去重和版本控制机制，避免重复录入或覆盖错误。大量带单位的数值字段和批号等标识符，对接口的参数校验提出了高要求，确保数据类型、范围和格式的正确性。例如，批号可能包含字母和数字，且有固定长度限制。文档往往包含大量图片、图表和原始数据文件，接口需要支持大文件上传，并能妥善存储和管理这些附件，同时提供可访问的 URL。

## 配置怎么定

| 配置项                   | 建议取法                                      | 这样取的依据                                                 |
| :----------------------- | :-------------------------------------------- | :----------------------------------------------------------- |
| `UPLOAD_FILE_MAX_SIZE`   | `1000 MB`                                     | 工艺验证报告常包含大量图片、图表和原始数据，文件体积较大。   |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`                                      | 大型验证报告或包含复杂数据的文档解析耗时较长，需要充足时间。 |
| `maxContext`             | `8000 tokens`                                 | 确保能一次性处理较长的验证方案或报告文本，保持上下文完整性。 |
| `分段长度`               | `800–1200 字符`                               | 兼顾语义完整性和处理效率，适应不同章节内容的长度。           |
| `相似度阈值`             | 按实测标定                                    | 确保精确召回与工艺验证相关的文档片段，避免无关信息干扰。     |
| `API_KEY_ROTATION_PERIOD` | `90 天`                                       | 定期更换 API 密钥，增强外部系统访问接口的安全性。            |

## 容易做错的三处

*   上传大文件时收到 400 错误，原因通常是接口或服务器层面的文件大小限制未调整，导致请求体过大。
*   上传图片后无法通过 API 路径获取可访问 URL，原因可能是文件存储配置错误或图片路径转换逻辑缺失。
*   接口返回数据流后未正确解析，导致无法提取有效信息，原因在于对流式响应的数据处理方式不熟悉或缺少相应的解码逻辑。

## 怎么确认配好了

*   通过 HTTP 客户端工具，模拟上传一个包含大文件附件的工艺验证报告，检查是否能成功接收并返回正确的存储路径。
*   使用不同格式（JSON、XML）的结构化验证数据调用接口，验证数据是否能被正确解析，并按照预期字段存储。
*   从外部系统中手动触发数据同步，检查工艺验证文档的更新频率和数据一致性，确认版本控制机制有效。
*   上传一个包含特定批号和单位的验证数据，然后通过查询接口检索，确认字段值和单位是否准确无误。
