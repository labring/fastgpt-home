# 工艺验证质量文档的工具调用与插件

## 这个品类的数据长什么样

生物医药行业的工艺验证文档，其数据主要来源于生产过程中的批记录、检验报告、设备校准记录、人员培训记录以及风险评估报告等。这些文档通常以 PDF、Word、Excel 等格式存在，部分数字化平台可能提供结构化的数据导出。更新频率方面，核心验证方案和报告通常在工艺开发阶段完成并经批准，变更时才会更新；而批次生产记录和检验数据则随批次生产实时生成。文档结构高度规范化，遵循 GMP/GLP 法规要求，包含明确的章节标题、数据表格、图表和签名页。字段方面，涉及批次号、产品代码、设备编号、操作员ID、关键工艺参数（如温度、压力、时间、搅拌速度）、关键质量属性（如含量、纯度、溶出度、微生物限度）、偏差记录、CAPA 编号等。单位则严格按照国际单位制或行业标准（如 °C, kPa, min, rpm, %, CFU/g, mg/mL）进行标注。

## 这些特征在「工具调用与插件」这一环带来什么约束

工艺验证数据的规范性和严格性，对工具调用与插件的设计提出了高要求。首先，文档的法规遵循性意味着任何自动化的数据提取和分析都需具备高准确性，容错率极低，因为错误可能导致合规风险。其次，多样的文档格式和半结构化数据，要求工具调用具备强大的文档解析能力，能够从复杂的表格和文本中准确识别并提取关键字段。例如，从 PDF 报告中提取特定批次的 `溶出度` 数据。再次，数据更新频率的差异性，要求工具调用能区分历史稳定数据与实时更新的批次数据，确保在执行验证分析时，总是引用最新或指定版本的数据。最后，涉及的专业术语和计量单位，要求插件在处理数据时能正确理解其含义，例如，区分 `湿度` 的相对湿度与绝对湿度，避免单位转换错误。对偏差记录和 CAPA 编号的关联分析，也需要工具调用能识别这些特定标识符并进行交叉查询。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `maxContext` | `8000` tokens | 确保能够处理包含多个表格和图表的复杂验证报告文本，减少截断导致的信息缺失。 |
| `maxIterations` | `5` | 限制工具调用链的深度，防止无限循环或过长思考时间，尤其在处理复杂逻辑判断时。 |
| `toolCallTimeout` | `600` 秒 | 应对从外部系统（如 LIMS 数据库）查询大量历史批次数据或执行复杂计算可能产生的延迟。 |
| `chunkSize` | `500` 字符 | 优化长文档分段，确保每个分段包含足够上下文以理解关键工艺参数或偏差描述。 |
| `embeddingModel` | `text-embedding-ada-002` | 兼顾准确性和成本，适用于生物医药领域专业术语的语义理解。 |
| `failRetryCount` | `3` | 针对网络波动或外部 API 临时故障，提供重试机制，提高任务成功率。 |

## 容易做错的三处

*   调用外部 API 返回 `Invalid JSON: Bad control chara` 错误：通常是由于外部系统返回了非标准 JSON 格式的响应体，可能包含特殊控制字符，导致解析器失败。
*   工具调用节点无法添加连接线：这通常发生在工具调用节点配置不完整或存在逻辑错误时，系统判定该节点无法正常输出，因此不允许连接后续节点。
*   模型在执行任务时思考时间过长：这可能源于 `maxContext` 设置过大，导致模型处理的上下文信息量过载，或工具调用链设计过于复杂，导致模型需要进行过多推理步骤。

## 怎么确认配好了

*   通过模拟提交包含关键工艺参数和质量属性的文档，验证工具调用能否准确提取 `批次号`、`产品代码` 和 `关键质量属性` 字段。
*   针对偏差记录和 CAPA 编号，测试工具调用能否正确识别并触发关联查询，核对返回结果是否包含相关联的详细信息。
*   观察工具调用日志，确认在处理包含多个表格的 PDF 文档时，未出现 `Context window exceeded` 警告，且关键数据提取无误。
*   使用包含特定计量单位（如 `mg/mL`、`CFU/g`）的文档进行测试，确保工具调用在数据处理过程中单位未被错误解释或转换。
