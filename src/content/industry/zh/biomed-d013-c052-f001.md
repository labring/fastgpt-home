# 干细胞治疗质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样
干细胞治疗领域的质量文档主要包括细胞制备SOP、检验批记录、临床试验方案、伦理审查文件及GCP/GMP符合性报告等。数据来源通常是实验室管理系统（LIMS）、电子批记录系统（EBR）、临床试验管理系统（CTMS）以及机构内部的飞书、Confluence等知识管理平台。这些文档的更新频率相对较低，但一旦更新，往往涉及核心流程或法规变动，影响范围广。文档结构通常高度规范化，包含大量结构化或半结构化数据，如批次号、细胞类型、供者信息、质控参数及检测结果。字段中常见特定生物学单位，如细胞活率（%）、细胞计数（cells/mL）、内毒素单位（EU/mL）及病毒载量（copies/mL）。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
干细胞治疗质量文档的低更新频率意味着实时同步需求不高，但对数据完整性和版本控制要求极高。文档中特有的生物学单位和专业术语，要求外部系统在解析时具备高准确性，避免语义偏差。严格的结构化特征，如表格数据和特定字段，决定了接口在数据提取时需精确匹配预定义模板或采用高级模式识别。多源头的数据聚合，需要HTTP接口能够处理不同系统的认证机制和数据格式差异（例如XML、JSON或PDF）。此外，文档通常包含敏感的患者信息或商业机密，对接口的安全性、传输加密和访问控制提出了严苛要求，确保数据传输过程中的合规性。

## 配置怎么定

| 配置项                       | 建议取法                                 | 这样取的依据                                                 |
| :--------------------------- | :--------------------------------------- | :----------------------------------------------------------- |
| `FETCH_INTERVAL_SECONDS`     | `86400 秒`                               | 干细胞质量文档更新不频繁，每日同步足以满足需求，减少系统负载。 |
| `MAX_FILE_SIZE_MB`           | `500 MB`                                 | 考虑到包含图片、图表和详细批记录的PDF文件大小，确保能上传大型文档。 |
| `PARSING_TIMEOUT_SECONDS`    | `600 秒`                                 | 复杂结构文档和大量生物学数据解析耗时较长，预留充足处理时间。 |
| `HTTP_AUTH_METHOD`           | `OAuth2 或 API Key`                      | 确保外部系统访问的安全性，符合生物医药领域的数据安全要求。   |
| `CHUNK_SIZE_CHARACTERS`      | `1000–1500 字符`                         | 平衡语义完整性和检索效率，确保每个分段包含足够的上下文。     |
| `METADATA_EXTRACT_FIELDS`    | `批次号, 细胞类型, 制备日期, 质控结果` | 提取关键元数据，提升检索精度和信息关联性。                 |

## 容易做错的三处
*   外部系统返回 `Request failed with status code 400`：通常是由于HTTP请求体中的JSON格式错误，或必填字段缺失，特别是在上传带有生物学单位的特定参数时，数据类型不匹配。
*   文档内容解析后，关键质控参数字段为空或数值异常：接口配置的解析规则未能准确识别PDF或Excel文档中的特定表格结构和单位，导致数据提取失败或误读。
*   更新文档后，旧版本信息仍在检索结果中出现：外部系统未正确触发版本更新机制，或接口配置的`FETCH_INTERVAL_SECONDS`过长，导致新旧数据未能及时同步。

## 怎么确认配好了
*   通过API客户端，模拟上传一个包含多种生物学单位和表格的典型干细胞制备SOP文档，检查返回状态码是否为 `200 OK`。
*   在知识库中搜索该SOP文档中的关键质控参数（如“细胞活率 95%”），验证检索结果能准确指向该文档，并核对提取的元数据字段内容是否完整且正确。
*   修改已上传文档中的某个批次号或制备日期，然后触发一次同步，验证知识库中该文档的版本信息和对应字段值是否已更新到最新。
