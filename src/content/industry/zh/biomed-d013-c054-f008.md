# 康复设备质量文档的工具调用与插件

## 这个品类的数据长什么样

康复设备，作为医疗器械的重要组成部分，其质量文档具有鲜明的特点。数据来源主要包括产品设计规范、生产工艺规程、检验检测报告、风险管理文件、临床评价报告以及用户反馈记录。这些文档的更新频率，特别是涉及法规变更、产品迭代或批次质量问题时，可能较为频繁，但核心设计文件相对稳定。文档结构通常遵循医疗器械注册与生产质量管理规范（如 ISO 13485、GMP）的要求，包含详细的章节和附件。字段方面，常涉及设备型号、序列号、批次号、生产日期、有效期、关键部件供应商、性能指标（如功率、频率、治疗模式）、安全参数（如漏电流、绝缘电阻）等。单位则严格按照国际单位制（SI）或行业标准，如 `W`（瓦特）、`Hz`（赫兹）、`V`（伏特）、`Ω`（欧姆）、`mm`（毫米）等。

## 这些特征在「工具调用与插件」这一环带来什么约束

康复设备质量文档的特性，对工具调用与插件的配置提出了具体要求。首先，文档中包含大量结构化数据和半结构化数据，例如检验报告中的数值型指标和合格判定，这要求工具能够准确解析并提取这些数据，例如通过正则表达式或特定字段解析插件。其次，文档更新的周期性与触发性，意味着需要设计定时或事件驱动的工具调用策略，以确保知识库的时效性，例如当新的检验报告上传时自动触发数据抽取与更新。此外，文档中涉及的专业术语和计量单位，要求在工具调用中对这些实体进行标准化处理，避免因单位不一致导致的数据误判或计算错误。对于风险管理文件中的故障模式及影响分析（FMEA）表格，需要插件具备处理表格数据并进行逻辑判断的能力，以支持缺陷追溯或风险评估。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `4000` | 质量文档通常较长，确保上下文完整性，避免关键信息截断。 |
| `分段长度` | `500 字符` | 兼顾语义完整性和检索效率，避免过长分段稀释关键信息。 |
| `相似度阈值` | `0.75` | 医疗器械质量文档对精度要求高，提高阈值减少不相关召回。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 针对大型 PDF 或扫描件，预留充足时间完成解析，避免超时失败。 |
| `toolCallTimeout` | `120 秒` | 数据库查询或外部 API 调用可能涉及复杂逻辑或大量数据，确保完成。 |
| `重排返回条数` | `前 5 条` | 保证最终呈现的答案聚焦于最相关的少数几条高质量信息。 |

## 容易做错的三处

*   工具调用节点执行后无响应或停滞，原因通常是外部服务接口响应超时或返回格式不符合预期，导致 Agent 无法继续处理。
*   图片 Base64 编码在 Markdown 渲染中无法正常显示，原因可能是编码字符串中含有特殊字符未正确转义，或者图片大小超出渲染限制。
*   数据库连接工具报错 `404`，原因可能是 OneAPI 中配置的阿里云百炼 API 地址或鉴权信息有误，未能正确访问目标服务。

## 怎么确认配好了

*   上传一份包含结构化数据的检验报告 PDF，验证工具能否准确提取出设备型号、序列号、关键性能参数及对应单位，并将其写入指定数据库表，检查数据库中字段值是否正确。
*   模拟一个产品批次出现质量问题的场景，触发包含风险评估逻辑的工具链，检查系统是否能根据文档内容自动识别风险等级并输出相应的处理建议，比对输出结果与预期逻辑。
*   针对一份包含复杂图表的文档，测试其 Base64 编码的图片在知识库问答中是否能正常渲染，验证图片是否清晰可辨，并检查渲染后的图片内容是否与原图一致。
