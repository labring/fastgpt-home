# 影像设备质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样
影像设备的质量文档主要包括设计验证报告、生产批次记录、校准证书、维护保养手册、故障诊断与维修记录等。这些文档通常以 PDF、Word、或结构化 XML 格式存在，部分数据可能存储在专用的质量管理系统（QMS）中。数据更新频率不一，设计文档相对稳定，而批次记录和维修日志则随生产和使用持续产生。字段方面，常涉及设备型号、序列号、生产日期、校准日期、测量参数（如 kVp、mA、曝光时间）、诊断结果、维修部件编码等，单位严谨，如 kV、mA、ms、mm，且常伴有公差范围。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
影像设备文档的来源多样性，要求 HTTP 接口具备灵活的文件上传与解析能力，能处理 PDF 和 XML 等多种格式。校准证书和维修记录的持续更新，意味着需要配置定时任务或 webhook 机制，以周期性或事件驱动地触发数据同步。文档中包含的设备序列号、测量参数等字段，在通过 HTTP 接口传输时，需要确保数据类型和格式的准确匹配，避免因单位或精度问题导致解析失败。对于存储在 QMS 中的结构化数据，API 接口设计需要适配 QMS 的数据模型，可能涉及复杂查询参数和认证机制。此外，文档中常见的图片（如故障部位照片）也要求接口支持多模态数据传输。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `datasource_type` | `http` 或 `webhook` | 依据数据来源是主动拉取还是外部系统推送决定 |
| `max_file_size_mb` | `50 MB` | 影像设备文档可能包含大量图片，文件较大 |
| `chunk_size_tokens` | `800–1200 字符` | 确保上下文完整性，兼顾大模型处理能力 |
| `parse_timeout_seconds` | `180 秒` | 处理复杂 PDF 或大型 XML 文件可能需要更长时间 |
| `headers` | 包含 `Authorization` 或 `X-API-Key` | 访问 QMS 或其他外部系统通常需要认证 |
| `retry_attempts` | `3` | 外部系统可能存在瞬时网络波动或服务不可用 |

## 容易做错的三处
*   API 调用返回 403 Forbidden 错误，通常是由于 `Authorization` 头信息缺失或令牌过期。
*   上传图片后，模型无法识别图像内容，可能是因为接口配置不支持多模态输入，或者 `Content-Type` 不匹配。
*   日志显示文件解析超时，原因可能是 `parse_timeout_seconds` 设置过短，无法处理大型或结构复杂的影像设备文档。

## 怎么确认配好了
*   上传一份包含设备序列号和校准参数的 PDF 文档，验证文档内容是否被正确提取和索引。
*   配置一个外部系统 webhook，触发数据更新后，检查知识库中相关文档是否已同步。
*   通过 API 调用查询特定设备型号的维修记录，验证返回结果的字段完整性和数据准确性。
