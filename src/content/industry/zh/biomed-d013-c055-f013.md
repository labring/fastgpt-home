# 影像设备质量文档的知识库检索与召回

## 这个品类的数据长什么样

影像设备的质量文档主要包括设计输入与输出、风险管理、验证确认、生产过程控制、售后服务记录等。这些文档通常以 PDF、Word、Excel 等格式存储，来源多样，包括研发部门、生产车间、质量管理部门、法规注册部门等。文档的更新频率受产品生命周期、法规变更、市场反馈等因素影响，例如设计文档在产品开发阶段更新密集，而风险管理文档则会根据上市后监督结果进行定期或不定期修订。文档内部结构规范，常包含大量的图表、检测数据、标准条款引用。字段方面，常见有设备型号、序列号、生产批次、检测参数（如 kVp、mA、曝光时间）、测量单位（如 mm、Hz、Gy），以及符合性声明、缺陷代码等。

## 这些特征在「知识库检索与召回」这一环带来什么约束

影像设备质量文档的规范性和结构化特点，要求知识库在分块时需兼顾文档的逻辑完整性。例如，一份风险分析报告中的危害识别、风险评估与风险控制措施通常紧密关联，如果分块过细可能导致检索时信息割裂。文档更新频繁的特性，对知识库的增量更新与版本管理能力提出要求，确保召回的信息始终是最新的合规版本。大量的图表和专业术语，使得纯文本向量化检索面临挑战，需要更精细的文本预处理和嵌入模型。此外，对检测参数和单位的准确识别，直接影响召回结果的可用性，这要求知识库具备一定的实体识别能力，并能处理数值范围和单位换算。文档间的引用关系，如某个测试报告引用了特定的操作规程，也要求知识库在召回时能建立上下文关联。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 影像设备质量文档，特别是包含大量图像和图表的 PDF 文件，文件体积通常较大，需要更高的上传上限。 |
| `分段长度` | `800–1200 字符` | 兼顾文档逻辑完整性与检索效率，避免过短分段丢失上下文，或过长分段引入过多无关信息。 |
| `召回条数` | `前 8 条` | 质量文档的检索通常需要更全面的上下文来判断合规性或问题根源，适当增加召回数量有助于提高覆盖率。 |
| `相似度阈值` | `0.75–0.85` | 针对专业性强、术语密集的文档，较高的相似度阈值有助于过滤掉语义上不相关的结果，提高精准度。 |
| `重排返回条数` | `前 5 条` | 在初步召回的基础上，通过重排模型进一步优化排序，聚焦最相关的几条，减少工程师的筛选工作量。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 大型 PDF 文件解析耗时较长，需要更长的解析超时时间以避免因超时而解析失败。 |

## 容易做错的三处

*   现象：上传大型 PDF 文件时，系统提示 `HTTP 413 Payload Too Large` 错误。原因：Web 服务器或应用服务器的请求体大小限制低于实际文件大小，例如 Nginx 的 `client_max_body_size` 参数设置过小。
*   现象：检索“设备校准参数”时，召回结果中包含大量无关的生产流程说明。原因：`相似度阈值`设置过低，导致语义上关联度不高的文档块也被召回。
*   现象：更新了某个设备的最新版验证报告后，检索仍然优先返回旧版本信息。原因：知识库未正确配置文档版本管理或增量更新策略，旧版本文档块未被及时替换或标记为过时。

## 怎么确认配好了

*   选择一份包含复杂图表和专业术语的影像设备质量文档，进行上传和解析，核对解析后的文本内容是否完整、无乱码，并检查分段逻辑是否合理。
*   针对特定设备型号、故障代码或法规条款，执行检索操作，检查召回结果的 `召回条数` 是否符合预期，并评估前几条结果的语义相关性与准确性。
*   模拟一次文档更新，例如替换一份设备的风险管理报告，然后再次检索相关内容，确认知识库已正确索引新版本文档，并优先召回最新信息。
