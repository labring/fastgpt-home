# 心血管质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

心血管疾病相关的质量文档，其数据来源多样。临床试验方案、研究报告、病例报告表（CRF）、药品说明书、指南共识等是常见文档类型。数据更新频率相对稳定，新药研发周期长，指南共识数月至数年更新一次。文档结构通常包含严谨的医学术语、剂量单位、诊断标准、治疗流程等。核心字段包括患者ID、诊断编码（如 ICD-10）、药物名称、剂量（mg、μg）、给药途径、频率、实验室检查结果（mmol/L、mmHg、bpm）等。文档中常出现复杂的表格、图表和嵌套结构，对文本抽取和结构化处理提出挑战。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

心血管质量文档的专业性与结构复杂性，对HTTP接口的数据传输和外部系统集成有特定要求。高频出现的医学术语和单位，需要接口支持UTF-8编码以避免乱码，并确保外部系统能正确解析。文档中大量存在的表格和图表，要求接口能够处理非纯文本数据，可能需要先进行OCR识别或PDF解析。由于数据更新频率相对稳定，接口设计时可考虑周期性全量或增量同步机制，避免资源浪费。严格的字段校验和单位转换是集成成功的关键，例如血压值 `mmHg`、心率 `bpm` 等，需要外部系统能准确识别并进行数值范围校验。

## 配置怎么定

| 配置项                   | 建议取法                                  | 这样取的依据                                                 |
| :----------------------- | :---------------------------------------- | :----------------------------------------------------------- |
| `UPLOAD_FILE_MAX_SIZE`   | `200 MB`                                  | 心血管领域文档（如临床试验报告）可能包含大量图片和图表，文件体积较大。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`                                  | 处理复杂的PDF文档和图像识别需要较长时间，避免因超时导致解析失败。 |
| `maxContext`             | `8000 tokens`                             | 心血管指南和研究报告通常包含长篇幅的专业论述，需要更大的上下文窗口。 |
| `分段长度`               | `800–1200 字符`                           | 确保医学概念的完整性，避免因切分过细导致语义丢失。           |
| `相似度阈值`             | `0.75`                                    | 医学术语的精确匹配至关重要，较高的阈值有助于召回更相关的专业内容。 |
| `HTTP_REQUEST_RETRY_COUNT` | `3 次`                                    | 外部系统集成时网络波动常见，适当重试次数可提高稳定性。       |

## 容易做错的三处

*   HTTP请求返回 `4xx` 或 `5xx` 错误码，原因可能是外部系统接口鉴权失败或请求参数格式不符合预期。
*   文档解析后关键字段（如药物剂量、检查结果）为空或格式错误，原因在于文档中存在多种表达方式或单位，解析器未能全面覆盖。
*   通过API访问时，全局变量未被正确识别或应用，原因在于接口参数传递方式与应用配置的变量类型不匹配。

## 怎么确认配好了

*   上传一份包含复杂表格和图表的PDF心血管指南，检查解析后文档内容是否完整，关键字段是否被正确提取。
*   通过HTTP接口调用，传入包含医学术语和特殊单位的测试数据，验证外部系统是否能正确接收并处理。
*   使用不同类型的查询，例如包含ICD编码或药物名称的查询，观察召回结果的相关性和准确性。
*   检查系统日志，确认文件上传、解析及外部系统调用的响应时间是否在预期范围内，没有出现超时或错误。
