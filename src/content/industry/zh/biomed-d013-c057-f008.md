# 心血管介入质量文档的工具调用与插件

## 这个品类的数据长什么样

心血管介入医疗器械的质量文档主要包括设计开发文档、生产过程记录、检验报告、风险管理文件、临床评价报告、法规符合性声明以及上市后监督数据。这些文档的来源多样，包括企业内部研发部门、生产车间、质量控制实验室以及外部临床试验机构和监管机构。文档更新频率相对稳定，通常与产品生命周期阶段、法规更新或重大质量事件相关联，例如设计变更或不良事件报告可能触发相关文档的修订。文档结构多为层级分明的 PDF、Word 或扫描件，其中包含大量结构化数据（如检验参数、批次信息、序列号）和非结构化描述（如临床观察、风险评估）。字段与单位具有高度专业性，例如“支架直径”通常以毫米（mm）为单位，“扩张压力”以大气压（atm）或兆帕（MPa）为单位，“疲劳测试循环次数”则为纯数字。

## 这些特征在「工具调用与插件」这一环带来什么约束

心血管介入质量文档的复杂数据特征对工具调用与插件功能提出了特定要求。首先，文档来源多样且格式异构，要求插件具备强大的文件解析能力，能够处理 PDF、Word 等多种格式，并准确抽取结构化与非结构化信息。对于扫描件，则需要 OCR 插件的支持。其次，文档中包含大量专业术语和计量单位，这要求工具调用时能正确识别并理解这些领域特定知识，例如在检索“支架直径”时，需要区分其与“导管直径”的细微差异，避免混淆。高频率的文档修订和版本管理，意味着插件需要支持版本追踪，并能在调用时指定或默认最新版本。此外，由于数据敏感性，工具调用与插件在数据处理过程中需满足严格的安全与合规性要求，确保数据不泄露、不篡改，并能追溯操作。

## 配置怎么定

| 配置项                       | 建议取法                                        | 这样取的依据                                                 |
| :--------------------------- | :---------------------------------------------- | :----------------------------------------------------------- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`                                        | 心血管介入文档可能包含大量图表与复杂排版，解析耗时较长。     |
| `maxContext`                 | `3000 Tokens`                                   | 确保能一次性处理较长的段落，包含完整的测试报告或风险评估。   |
| `file_upload_limit`          | `100 MB`                                        | 应对包含高分辨率图片或大量附件的质量文档。                   |
| `similarity_threshold`       | `0.8`                                           | 确保召回的文档片段与查询高度相关，减少领域术语误判。         |
| `return_top_k`               | `前 5 条`                                       | 兼顾检索效率与信息完整性，确保关键信息不遗漏。               |
| `document_chunk_size`        | `800–1200 字符`                                 | 适应文档中长句和专业描述，保证切片语义完整性。               |

## 容易做错的三处

*   插件在工作流中不显示输入和输出参数：通常是插件定义文件 `plugin.json` 中的 `parameters` 或 `outputs` 字段格式不正确，或者 `manifest.json` 文件中 `api` 定义缺失。
*   上传文件后文档解析工具报错：经常是文件格式不支持，或 `UPLOAD_FILE_MAX_SIZE` 配置过小导致文件上传失败，文件路径 `file_path` 传递不正确。
*   外部平台调用聊天接口响应慢：多半是 FastGPT 部署的服务器资源不足，或者 `MAX_TOKENS` 设置过大导致模型推理时间过长，也可能是数据库查询优化不足。

## 怎么确认配好了

*   上传一份包含图片和表格的 PDF 文档，检查 `Document` 页面文件解析状态是否为“成功”，并查看分段结果是否符合预期，特别是表格和图片附近文本的分段。
*   在工作流中添加一个定制插件，检查插件的输入 `params` 和输出 `outputs` 字段是否在界面上正确显示，且类型与定义一致。
*   通过 API 接口上传一个 `50 MB` 的大型 Word 文档，观察上传过程是否顺利，并检查日志中是否有 `file upload success` 相关的记录。
*   执行一个包含工具调用的问答，验证工具是否能正确识别并调用插件，检查插件的返回结果是否符合预期，尤其是带有特定计量单位的数值。
