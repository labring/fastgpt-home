# 患者援助质量文档的工具调用与插件

## 这个品类的数据长什么样

患者援助项目（PAP）的质量文档主要包括项目方案、患者招募与筛选标准、药品管理细则、数据收集与隐私保护协议、以及项目审计报告等。这些文档的数据源头通常是制药企业、临床研究机构和第三方项目管理机构。更新频率相对稳定，通常在项目启动、重大变更或年度审计后进行修订，更新周期在数月至一年不等。文档结构以规范化的文本为主，常包含大量的条款、编号列表和表格。字段与单位具有高度专业性，例如药品批号、有效期、存储条件（如 `2-8°C`）、患者 ID、诊断代码（如 `ICD-10`）、剂量（如 `mg/kg`）以及项目阶段标识符。

## 这些特征在「工具调用与插件」这一环带来什么约束

PAP质量文档的专业性与规范性，要求工具调用时能精确解析特定字段和结构化信息。例如，对药品批号或患者诊断代码的模糊匹配可能导致严重的项目合规风险。文档更新频率决定了知识库的刷新策略，频繁的更新会增加工具调用时的缓存失效和数据不一致风险。大量条款和表格的存在，使得传统的文本分块方法可能不足以捕捉完整的语义，需要工具支持表格内容解析和跨段落的上下文关联。对存储条件等带有单位的数值型字段，工具需要能够识别并进行单位转换或范围判断，避免因单位不匹配导致的错误信息召回，例如将 `2-8°C` 误读为纯数字。

## 配置怎么定

| 配置项                   | 建议取法       | 这样取的依据                                   |
| :----------------------- | :------------- | :--------------------------------------------- |
| `maxContext`             | `2048`         | 确保能完整覆盖单个条款或小节的上下文。       |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600` 秒       | 处理大型 PDF 或包含复杂表格的文档解析耗时。  |
| `分段长度`               | `800-1200` 字符 | 兼顾语义完整性与召回效率，适应条款式文本。   |
| `相似度阈值`             | `0.75`         | 过滤掉低相关性结果，减少误报风险。             |
| `重排返回条数`           | `5` 条         | 保留高质量结果，避免过多干扰信息。             |
| `toolCallConcurrency`    | `10`           | 平衡系统资源与响应速度，适应并发查询需求。   |

## 容易做错的三处

*   工具调用返回 `HTTP 429 Too Many Requests` 状态码，原因是没有合理设置并发量或频率限制，导致对外部API的请求超过了配额。
*   从工作流中获取的谷歌搜索结果是 `array<object>` 类型，后续工具无法直接处理，原因是没有在中间步骤使用合适的转换工具将结构化数据格式化为可读文本。
*   提示词调用 MCP 后图片显示不全，原因是图片URL或内容在传输过程中被截断，或者渲染工具不支持特定图片格式。

## 怎么确认配好了

*   针对关键条款或数据点，构造查询，检查返回结果是否包含预期的条款编号、药品批号或患者诊断代码，并确认其上下文完整性。
*   上传一份包含复杂表格的质量文档，观察其解析耗时是否在 `PARSE_FILE_TIMEOUT_SECONDS` 配置范围内，并检查表格内容的召回准确性。
*   模拟高并发查询场景，监控工具调用接口的响应时间和错误率，确保 `toolCallConcurrency` 配置能支撑实际业务负载。
