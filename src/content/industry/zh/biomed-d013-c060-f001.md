# 感染性疾病质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

感染性疾病领域的质量文档数据，主要来源于临床诊断报告、实验室检测结果、流行病学调查数据、以及药物不良反应报告。这些数据更新频率较高，部分实验室结果甚至可达到小时级更新，以应对疫情动态变化。文档结构上，常见 PDF 格式的指南、标准操作规程（SOP），以及结构化数据存储的病例报告表单。字段方面，特异性病原体名称、感染部位、耐药谱、宿主免疫状态等是核心信息。单位则涉及微生物载量（如 `copies/mL`）、抗体滴度（如 `IU/mL`）、以及药物最小抑菌浓度（MIC，单位 `μg/mL`），这些都需要准确解析。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

感染性疾病数据的高更新频率要求 HTTP 接口具备高效的拉取机制，以确保 FastGPT 知识库的时效性。例如，疫情动态或新发病原体信息需要快速同步，避免提供过时信息。文档中包含大量结构化与非结构化混合数据，要求外部系统在数据抽取时能有效识别并处理，例如从 PDF SOP 中提取关键步骤，或从病例报告中解析特定字段。病原体名称、耐药谱等高度专业化的字段，对数据清洗和标准化提出要求，需要通过外部系统进行预处理，以避免 FastGPT 在召回时出现歧义。各类微生物载量、抗体滴度等数值型数据，其单位的准确性对后续分析至关重要，要求接口传输时能保留或正确转换单位信息，例如 `copies/mL` 不应被误读为 `copies/L`。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `FETCH_INTERVAL_SECONDS` | `3600 秒` | 多数质量文档的更新周期在小时级别，例如新的诊疗指南发布。 |
| `MAX_FILE_SIZE_MB` | `100 MB` | 感染性疾病的指南或报告可能包含大量图表和详细描述，文件较大。 |
| `HTTP_TIMEOUT_SECONDS` | `60 秒` | 考虑到外部系统可能需要处理复杂数据抽取或转换，预留充足响应时间。 |
| `CHUNK_SIZE_TOKENS` | `800–1200 字符` | 确保 FastGPT 能捕捉到感染性疾病文档中较长的上下文片段，例如临床路径描述。 |
| `METADATA_FIELDS_TO_EXTRACT` | `病原体名称, 诊断依据, 耐药情况` | 这些字段是感染性疾病文档的核心标签，用于精准检索和问答。 |
| `ERROR_RETRY_COUNT` | `3` | 应对外部系统偶尔的网络波动或瞬时服务不可用，提高数据同步成功率。 |

## 容易做错的三处

*   HTTP 接口返回 `404 Not Found` 错误，常见原因是外部系统对特定病原体或疾病的文档路径配置不正确。
*   FastGPT 在问答中无法识别文档中的特定微生物名称，这是由于外部系统在数据抽取时未能将非结构化文档中的专业术语正确提取为可检索的元数据。
*   同步的数据中，特定检测结果的数值字段为空，原因多是外部系统在解析原始报告时，未能正确匹配或转换不同报告模板中的数值字段，导致数据丢失。

## 怎么确认配好了

*   在 FastGPT 知识库中随机抽取 5–10 篇已同步的感染性疾病文档，检查其元数据字段（如 `病原体名称`、`耐药情况`）是否完整且准确，与原始文档进行比对。
*   通过 FastGPT 接口触发一次手动数据同步，并观察外部系统日志，确认 HTTP 请求状态码为 `200 OK`，且没有 `Timeout` 错误。
*   向 FastGPT 提问关于最近更新的感染性疾病疫情信息，核对回答中引用的文档是否为最新版本，以验证 `FETCH_INTERVAL_SECONDS` 配置的有效性。
*   查询 FastGPT 中关于某个特定检测项目（如 `HIV 病毒载量`）的文档，检查返回结果中数值和单位（例如 `copies/mL`）是否与原始文档一致，验证数据解析的准确性。
