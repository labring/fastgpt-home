# 感染性疾病质量文档的工具调用与插件

## 这个品类的数据长什么样

感染性疾病领域的质量文档数据来源多样，主要包括国家卫健委发布的诊疗指南、疾病预防控制中心（CDC）的监测报告、药监局的药品说明书、医院内部的感染控制手册以及临床路径文件。这些文档的更新频率不一，诊疗指南通常每年或每两年修订，而疫情相关数据可能实时更新。文档结构上，指南类文件常采用章节式排版，包含病原学、流行病学、临床表现、诊断标准、治疗方案等固定字段。监测报告则多为表格数据与统计图表，字段涉及发病率、死亡率、病原体分布等。药品说明书有严格的格式要求，包含适应症、用法用量、不良反应等。单位方面，常见有 `mg/kg`、`IU/mL`、`%`、`例`、`天` 等。

## 这些特征在「工具调用与插件」这一环带来什么约束

感染性疾病数据的多样性对工具调用提出了精细化要求。例如，实时更新的疫情数据需要通过外部 API 调用获取最新信息，以确保决策基于最新事实，这就要求插件支持灵活的 API 密钥管理和动态参数传递。文档结构化的特点，如诊疗指南中的诊断标准或治疗方案，使得精确抽取特定信息成为可能，但需要工具调用能够解析复杂的文档结构，并支持 XPath 或 JSONPath 等查询语言。字段与单位的规范性，特别是药品剂量或检验指标，要求工具在调用外部计算或转换服务时，能够准确识别并处理单位，避免混淆。例如，在处理 `mg/kg` 这种复合单位时，需要插件能正确识别并传给外部计算服务。此外，对于某些需要授权访问的数据库，工具调用需要支持 OAuth2 或其他认证机制。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `2000 字符` | 感染性疾病指南篇幅较长，需要更多上下文理解疾病全貌。 |
| `召回条数` | `前 8 条` | 确保覆盖到诊断、治疗、预防等多个关键环节的信息。 |
| `相似度阈值` | `0.75` | 疾病名称、病原体名称相似但含义可能不同，需较高阈值保证精准匹配。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 应对大型诊疗指南或多份报告合并解析时的耗时。 |
| `插件超时时间` | `60 秒` | 外部疫情数据接口或药物相互作用查询服务可能响应较慢。 |
| `HTTP_PROXY` | `http://proxy.example.com:8080` | 当外部 API 访问受限于网络策略时，需要配置代理。 |

## 容易做错的三处

*   调用外部数据库时，返回结果为空或不完整。原因在于 SQL 语句中的表名或字段名与实际数据库不符，或者缺少必要的 WHERE 条件过滤。
*   插件执行后，返回的药物剂量单位与预期不符。原因在于插件在传递参数给外部计算工具时，未明确指定单位转换规则或外部工具默认单位与文档不一致。
*   发送邮件插件无法正常发送邮件，日志显示 `SMTP 认证失败`。原因在于 `SMTP_USERNAME` 或 `SMTP_PASSWORD` 配置错误，或者邮件服务器要求更高级的认证方式。

## 怎么确认配好了

*   针对关键疾病（如流感、结核病），使用包含典型症状、诊断标准和治疗方案的查询，验证工具调用是否能准确返回诊疗指南中的相关章节。
*   模拟一次新发传染病疫情数据查询，核对插件调用外部 API 后返回的发病率、死亡率等数据是否与官方数据源一致，并检查 `response.status_code` 是否为 `200`。
*   执行一次药物相互作用查询，验证插件是否能正确识别药物名称和剂量，并返回预期的相互作用提示，检查返回的 JSON 结构是否包含 `interaction_level` 字段。
