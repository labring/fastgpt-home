# 手术机器人质量文档的工作流编排

## 这个品类的数据长什么样

手术机器人的质量文档主要包括设计开发文档、风险管理报告、测试验证报告、生产过程控制记录、上市后监管文件等。数据来源多样，涵盖研发部门的设计数据、实验室的测试数据、生产线的工艺参数、临床试验的随访数据以及市场反馈。这些文档的更新频率不一，设计文档可能在产品迭代时集中更新，而生产记录则按批次实时生成。文档结构通常遵循医疗器械行业规范，例如 ISO 13485 标准，包含明确的版本号、修订历史、审批流程及责任人。字段包括但不限于部件序列号、批次号、检验结果、测试方法、合格判据、校准日期等，单位精确到毫米、微米、牛顿、毫伏、摄氏度等，对精度要求极高。

## 这些特征在「工作流编排」这一环带来什么约束

手术机器人质量文档的复杂性和高精度要求，对工作流编排提出了严格约束。首先，多源异构的数据导致数据集成复杂，需要工作流能有效处理不同格式和来源的文档。其次，严格的合规性要求使得文档审批流程必须固化且可追溯，工作流需支持多级审批、条件分支和状态流转。高频次的生产记录更新和产品迭代，要求工作流具备自动化触发和增量更新能力，以避免人工干预导致的延迟和错误。精度相关的字段，如测量值和公差，在工作流中进行提取和比对时，需要确保数值类型和单位的一致性，防止数据解析错误。此外，关键质量文档的变更会触发一系列关联文档的修订，工作流需能自动识别并联动更新。

## 配置怎么定

| 配置项             | 建议取法       | 这样取的依据                                       |
| :----------------- | :------------- | :------------------------------------------------- |
| `maxContext`       | `8192 token`   | 适应长篇幅设计规范和测试报告，保证上下文完整性。 |
| `召回条数`         | `前 10 条`     | 覆盖关联文档和法规条款，提高召回准确率。           |
| `相似度阈值`       | `0.78–0.85`    | 平衡召回率与精确率，避免无关文档干扰。             |
| `分段长度`         | `500–800 字符` | 兼顾语义完整性和向量化效率，减少分段碎片化。       |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`       | 应对大型 PDF 或 CAD 图纸解析，防止超时中断。       |
| `变量更新策略`     | `按会话更新`   | 确保每次查询结果基于最新上下文，避免旧变量污染。   |

## 容易做错的三处

*   代码运行时输出变量 `resultTimes` 或 `trafficFlowCounts` 等字段为空，通常是由于工作流中数据提取节点配置的 JSON Path 或正则表达式与实际文档结构不匹配，导致未能正确解析目标值。
*   知识库搜索节点在 V4.8.10 版本中未能处理搜索结果为空的逻辑，可能导致后续节点因输入缺失而报错，原因是工作流设计时未添加条件判断节点对搜索结果进行空值校验。
*   变量更新机制理解偏差，未将全局默认不变的变量设置为 `持久化变量` 或在每次会话开始时重新初始化，导致变量值在不同对话轮次中丢失或被错误覆盖。

## 怎么确认配好了

*   针对关键质量文档，手动模拟多轮问答，验证工作流能否准确提取并引用文档中的关键参数、标准和测试结果，并检查日志输出，确认各节点变量传递无误。
*   上传一份包含已知错误或缺陷的测试文档，观察工作流是否能正确识别并触发预设的异常处理流程，如通知相关责任人或标记为待审核。
*   在工作流中集成版本号为 V4.8.12 的知识库搜索功能，并使用查询词测试，确保知识库在没有匹配结果时能够返回预期的空值或特定提示信息。
*   通过追踪工作流执行历史，检查 `PARSE_FILE_TIMEOUT_SECONDS` 参数设置下，大型设计图纸或报告文件是否能在规定时间内完成解析，未出现因超时导致的解析失败。
