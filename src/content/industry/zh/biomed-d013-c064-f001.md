# 抗体偶联药物 ADC质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

抗体偶联药物（ADC）的质量文档具有高度专业性和结构化特点。数据来源主要包括药物研发阶段的实验报告、生产过程中的批记录、质量控制（QC）检测数据以及稳定性研究报告。更新频率通常与药物的开发、生产批次及监管要求相关，例如批记录随生产批次实时生成，稳定性数据按计划定期更新。文档结构严谨，常包含批号、生产日期、有效期、检测项目、检测方法、检测结果、判定标准、偏差处理等字段。字段内容复杂，例如检测结果可能包含光谱数据、色谱图、纯度百分比、杂质含量（ppm、ppb）、抗体-药物比率（DAR值）等，单位多样且精确度要求高。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

ADC质量文档的专业性和结构化特点，要求HTTP接口具备强大的数据解析和验证能力。高更新频率的数据，例如生产批记录，需要外部系统能够支持高并发的API调用，并具备高效的增量同步机制，避免全量同步带来的性能瓶颈。复杂的文档结构和多样化的字段，特别是包含光谱、色谱图等二进制或大文本数据，对HTTP请求体的大小和数据类型提出了特殊要求，需要支持 `multipart/form-data` 或 `application/octet-stream` 等格式。精确的单位和判定标准，意味着API返回的数据必须保持原始精度，防止在传输或处理过程中丢失有效信息，同时对错误处理机制要求严格，能够清晰指示数据校验失败的具体原因。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxPayloadSize` | `50 MB` | ADC检测报告可能包含大型二进制文件（如原始光谱数据），需要支持大文件传输。 |
| `timeoutSeconds` | `300 秒` | 复杂文档解析和数据校验耗时较长，避免因超时导致连接中断。 |
| `concurrencyLimit` | `按实测标定` | 生产批记录更新频繁，需根据实际系统负载和外部API速率限制确定并发数。 |
| `authMethod` | `OAuth2` | 确保数据传输的安全性与合规性，OAuth2提供更细粒度的权限控制。 |
| `retryAttempts` | `3 次` | 外部系统偶发性网络波动或服务暂时不可用时，增加请求的成功率。 |
| `dataEncoding` | `UTF-8` | 确保所有字符（包括特殊符号和多语言描述）能够正确传输和解析。 |

## 容易做错的三处

*   HTTP请求返回 `404 Not Found` 错误，原因可能是外部系统API路径配置错误或参数名与API文档不符。
*   同步过来的批记录数据中，某些关键字段（如DAR值）显示为空或格式异常，原因可能是外部系统返回的数据结构与预期不符，或解析器未能正确处理特定数据类型。
*   大量数据同步时出现连接超时或 `504 Gateway Timeout` 错误，原因可能是 `timeoutSeconds` 参数设置过短，或外部系统处理请求时间过长，未能及时响应。

## 怎么确认配好了

*   通过API调用获取单个ADC批次的质量文档，核对返回数据中的 `batchId`、`productionDate`、`DARValue` 等关键字段是否与源系统一致，并检查数值精度。
*   上传一份包含复杂数据类型（如二进制文件）的测试文档，确认 `maxPayloadSize` 设置是否足以支撑，并且外部系统能够正确接收和解析。
*   模拟高并发请求场景，观察外部系统日志，确认 `concurrencyLimit` 设置下API调用是否稳定，没有出现大量 `429 Too Many Requests` 或 `503 Service Unavailable` 错误。
