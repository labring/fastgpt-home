# 护理管理质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

护理管理质量文档主要包含护理规章制度、操作流程、应急预案、质量检查表、不良事件报告、培训记录以及患者满意度调查等。这些数据通常来源于医院信息系统（HIS）、电子病历系统（EMR）、护理管理系统（NMS）以及纸质文档扫描件。更新频率因文档类型而异，规章制度可能每年修订，操作流程按需更新，而质量检查表和不良事件报告则实时或每日生成。文档结构多为半结构化，包含标题、段落、列表、表格等。关键字段包括 `文档编号`、`版本号`、`发布日期`、`修订日期`、`适用范围`、`主要内容`、`责任人`、`审核人`、`执行科室`。单位通常是日期、文本、数字或百分比。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

护理管理文档的半结构化特性要求 HTTP 接口在数据解析时具备一定的灵活性，能够处理 JSON、XML 或 HTML 等多种格式，并准确抽取关键信息。文档更新频率的差异意味着接口需要支持定时同步（如每月同步规章制度）和事件驱动同步（如不良事件报告实时上传）。例如，从 HIS 系统获取更新的护理排班表，可能通过 RESTful API 定期拉取 JSON 数据。大量的历史纸质文档扫描件需要 OCR 识别，这要求外部系统接口具备文件上传和识别能力，并能处理识别结果中的噪声和格式不一致。同时，对 `版本号` 和 `修订日期` 等字段的精确识别，对于确保知识库的时效性和准确性至关重要，需要在接口参数中明确指定这些字段的匹配规则。

## 配置怎么定

| 配置项                       | 建议取法                               | 这样取的依据                                                                                             |
| :--------------------------- | :------------------------------------- | :------------------------------------------------------------------------------------------------------- |
| `API_ENDPOINT`               | `https://your-his-api/nursing/docs`    | 指向医院信息系统或护理管理系统的文档接口，确保数据源的权威性。                                           |
| `REQUEST_METHOD`             | `POST` 或 `GET`                        | 依据目标系统 API 文档，`GET` 用于拉取，`POST` 用于上传或触发。                                           |
| `AUTH_TOKEN`                 | 按实测标定                             | 确保接口调用的安全性，通常为 JWT 或 OAuth token。                                                        |
| `INTERVAL_SECONDS`           | `3600` 秒（针对规章制度）              | 规章制度更新频率较低，每小时检查一次足以捕获修订。                                                       |
| `FILE_UPLOAD_MAX_SIZE_MB`    | `100` MB                               | 应对扫描件和 PDF 文档的大小限制，确保大型文档能够上传。                                                  |
| `PARSE_TIMEOUT_SECONDS`      | `600` 秒                               | 考虑到大型文档（如包含多页扫描件）的解析耗时，预留充足时间以防超时。                                     |
| `JSON_PATH_FOR_VERSION`      | `$.data.document.version`              | 精确提取 JSON 响应中的 `版本号` 字段，确保知识库内容的版本控制。                                         |

## 容易做错的三处

*   HTTP 请求返回 `software.amazon.awssdk.services.bedrockruntime.model.BadRequestException`，通常是由于 `Content-Type` 不匹配或请求体格式错误。
*   接口调用返回 `aiPointsNotEnough`，表明账户资源不足以支持当前请求，需要检查 FastGPT 平台内的点数余额。
*   从 HTTP 请求获得的 JSON 数据在输入给另一个 HTTP 请求时出现多余的反斜杠，这是因为 JSON 字符串在传输或存储过程中被错误地转义，需要在处理前进行反转义操作。

## 怎么确认配好了

*   通过 FastGPT 的工具调试界面，模拟调用配置的 HTTP 接口，检查返回的 `status code` 是否为 `200` 或 `20x`，并确认响应数据结构与预期一致。
*   上传一个测试用的护理操作流程文档（PDF 或 Word 格式），观察其在知识库中是否被正确解析，并检查 `文档编号`、`版本号` 等关键字段是否被准确提取。
*   配置一个定时任务，例如每小时同步一次最新的护理不良事件报告，然后检查知识库中是否有新增或更新的报告条目，并核对 `发布日期` 字段是否正确。
