# 护理管理质量文档的工作流编排

## 这个品类的数据长什么样

护理管理领域的质量文档主要包括规章制度、操作规范、护理记录、风险评估表、培训材料和检查报告等。数据来源多样，涵盖医院信息系统（HIS）、电子病历（EMR）、护理文书系统以及纸质文档扫描件。更新频率因文档类型而异，操作规范和规章制度可能每半年至一年修订一次，而护理记录、风险评估表则为实时或每日生成。文档结构通常包含标题、版本号、修订历史、适用范围、职责、流程步骤、附录等标准化字段。字段单位多为文本描述、日期、时间、数值（如体温摄氏度、血压毫米汞柱）以及布尔值（如是否合格）。

## 这些特征在「工作流编排」这一环带来什么约束

护理管理质量文档的多元来源和更新频率，要求工作流编排具备灵活的数据摄取能力。实时或每日更新的护理记录和风险评估表，需要触发式或定时任务来保证知识库的时效性，例如通过 API 接口定时同步数据。文档中包含大量标准化字段和专业术语，使得工作流在文档解析环节需重点关注命名实体识别和字段提取的准确性，以确保信息能够被正确索引。此外，文档修订历史和版本号的存在，对工作流中的知识更新策略提出要求，需处理好新旧版本的替换与关联，避免信息混淆。数值型字段和布尔值在检索时可能需要特定的过滤或聚合逻辑，工作流设计需预留相应的处理节点。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `分段长度` | `500 字符` | 护理管理文档段落通常较长，500 字符可兼顾完整性和检索粒度。 |
| `召回条数` | `前 8 条` | 确保覆盖多角度信息，特别是当用户问题涉及多个操作规范时。 |
| `相似度阈值` | `0.75` | 针对专业术语多的文档，高阈值可提高召回精确度，减少无关信息。 |
| `maxContext` | `3000 tokens` | 保证模型能处理较长的护理流程描述和背景信息。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 处理大型 PDF 格式的规章制度或培训手册，防止解析超时。 |
| `RECALL_STRATEGY` | `Hybrid Search` | 结合关键词与向量搜索，应对用户提问的多样性，包含精确查询和模糊查询。 |

## 容易做错的三处

*   知识库查询结果为空或不准确，原因在于知识库中问题分类过于宽泛，导致相关文档未能被准确索引。
*   工作流中代码运行节点无法获取到知识库引用内容，原因是节点配置时未正确将知识库召回结果映射到代码变量。
*   API 创建工作流后运行时报错，现象为 `Redis connection error`，原因是 `REDIS_URL` 环境变量配置不正确或 Redis 服务不可达。

## 怎么确认配好了

*   上传典型护理管理文档，例如一份操作规范和一份风险评估表，确保文档解析无报错，且内容能在知识库预览中完整显示。
*   模拟用户提问，输入涉及操作流程、规章制度或常见风险处理的问题，验证工作流能够召回相关文档片段，并生成符合预期的回答。
*   检查工作流日志，确认各节点执行状态均为成功，特别是数据同步和知识库更新节点，确保没有超时或错误信息。
*   针对包含数值型字段的文档，通过提问验证工作流能否正确提取并解释这些数值，例如查询特定指标的正常范围。
