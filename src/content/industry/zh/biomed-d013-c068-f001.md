# 智能导诊质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

生物医药领域的智能导诊质量文档，通常指医疗机构内部用于规范导诊流程、疾病知识、诊疗路径和患者沟通策略的文本资料。数据来源多样，包括临床指南、专家共识、药品说明书、病案记录摘要和内部培训手册。更新频率相对较高，尤其是涉及新药上市、诊疗方案更新或政策法规调整时，可能每周或每月进行修订。文档结构以层级分明的章节为主，包含大量医学术语、缩写和特定格式的表格。字段可能包括疾病名称、症状描述、推荐科室、检查项目、治疗方案、注意事项等。单位使用国际标准单位或医学领域常用单位，例如 `mg`、`ml`、`μg/kg`、`次/日`。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

智能导诊质量文档的复杂结构和高更新频率对 HTTP 接口设计提出具体要求。文档中的层级结构和嵌套信息，要求接口能支持灵活的 JSON 或 XML 数据格式，以准确映射文档的复杂关系。医学术语的专业性，需要外部系统具备强大的文本处理能力，例如通过命名实体识别（NER）技术提取关键信息。高更新频率意味着接口需要支持增量更新和版本控制，避免每次更新都进行全量数据同步。此外，涉及患者隐私和诊疗数据的部分，虽然质量文档本身不直接包含患者个人信息，但其内容敏感性，要求 HTTP 接口必须符合严格的安全规范，如 HTTPS 协议和 OAuth2.0 认证机制。字段与单位的标准化，要求外部系统在数据解析时能正确识别和转换，确保信息准确性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `HTTP_TIMEOUT_SECONDS` | `60 秒` | 处理复杂文档解析和外部知识库调用可能耗时较长，避免频繁超时 |
| `MAX_RETRIES` | `3` | 应对网络波动或外部服务瞬时故障，提高数据同步成功率 |
| `CHUNK_SIZE_TOKENS` | `512 tokens` | 平衡上下文长度与处理效率，确保单个数据块内容完整性 |
| `API_KEY_HEADER` | `X-API-KEY` | 行业通用实践，提高接口安全性与可维护性 |
| `BATCH_UPDATE_INTERVAL_HOURS` | `24 小时` | 兼顾文档更新频率与系统负载，支持每日批量更新 |
| `ERROR_NOTIFICATION_EMAIL` | `devops@example.com` | 及时通知故障，便于快速定位问题 |

## 容易做错的三处

*   HTTP 请求返回 500 错误码，但日志中没有明确的错误信息。这通常是外部系统处理复杂文档结构时，内部逻辑错误导致服务崩溃，未能正确捕获异常并返回详细错误信息。
*   部分导诊结果的关键字段（如推荐科室、治疗方案）为空或不完整。原因在于外部系统对文档中非标准格式的医学术语或表格解析失败，未能正确提取所需信息。
*   文档更新后，智能导诊的响应内容未及时同步。这往往是由于增量更新机制未正确配置或触发，导致外部系统未能拉取到最新版本的质量文档。

## 怎么确认配好了

*   通过外部系统手动触发一次全量文档同步，并检查同步日志，确保所有文档均已成功导入，无报错信息。
*   随机选取若干更新频率较高的文档，修改其内容，然后通过 HTTP 接口触发增量更新，确认更新后的内容能在智能导诊中正确反映。
*   对包含复杂医学术语和多层级结构的文档进行查询测试，核对智能导诊返回的关键字段（例如疾病名称、推荐科室、注意事项）是否与原文一致，并检查单位是否正确识别。
