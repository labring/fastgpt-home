# 生物制药设备质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

生物制药设备的质量文档涵盖了设备的设计、制造、安装、运行、维护、校准与报废等全生命周期数据。其数据源头多样，包括供应商提供的设备说明书、图纸、FAT/SAT 报告、校准证书，以及企业内部生成的 SOP、批记录、偏差调查报告、变更控制文件等。文档格式以 PDF、Word、Excel 为主，部分设备可能提供 XML 或 JSON 格式的数字化日志。更新频率不一，设计文档相对稳定，而维护、校准记录则随设备运行周期实时更新。字段与单位具有高度专业性，例如“校准周期”可能以“月”或“年”计，而“验证批次”则涉及具体批号与生产日期。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

生物制药设备质量文档的特性对 HTTP 接口与外部系统集成提出了特定要求。首先，文档来源多样且格式复杂，需要接口具备强大的文件解析能力，尤其是对 PDF 和 Word 等非结构化文档的文本提取与结构化处理。其次，文档更新频率的差异性，要求接口设计支持定时同步与事件驱动两种触发机制，以确保关键校准与维护记录的及时导入。字段与单位的专业性，意味着在数据传输与处理过程中需要严格的数据类型校验与单位转换机制，避免因数据格式不匹配导致的信息失真。此外，合规性要求使得数据传输必须高度安全，需采用 HTTPS 协议，并考虑数据加密与访问控制。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `API_URL` | 具体外部系统接口地址 | 外部系统提供的数据接口地址，确保可访问性 |
| `HTTP_METHOD` | `POST` 或 `GET` | 根据外部系统接口要求选择，通常用于数据提交 |
| `HEADERS` | `Content-Type: application/json`, `Authorization: Bearer <TOKEN>` | 确保数据格式正确，并提供认证凭证进行安全访问 |
| `BODY_TEMPLATE` | `{"设备ID": "{{device_id}}", "文档类型": "{{doc_type}}", "文件内容": "{{file_base64}}", "更新时间": "{{update_timestamp}}", "校准周期": "{{calibration_period_months}}"}` | 结构化地映射设备文档的关键字段，支持模板变量替换 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 应对大型 PDF 或 Word 文档的解析耗时，避免超时中断 |
| `RETRY_ATTEMPTS` | `3 次` | 应对网络波动或外部系统临时故障，增加传输成功率 |

## 容易做错的三处

*   HTTP 请求发送后，外部系统返回 500 状态码或空响应体，通常是由于 `BODY_TEMPLATE` 中的字段名与外部系统接口要求不符，或数据类型转换错误。
*   文档内容无法被正确索引，或者索引结果缺失关键信息，可能 `PARSE_FILE_TIMEOUT_SECONDS` 设置过低，导致大型文档解析未完成即被截断。
*   流式输出时出现数据断裂或响应延迟，这与 `API_URL` 地址配置不当，指向了错误的接口地址，或者外部系统接口响应速度慢有关。

## 怎么确认配好了

*   通过 FastGPT 的 HTTP 模块测试功能，模拟发送包含典型设备文档字段的请求，检查外部系统是否成功接收并处理。
*   在外部系统日志中查找 FastGPT 发送的请求记录，核对 `HEADERS` 和 `BODY_TEMPLATE` 中的数据是否完整且格式正确。
*   从外部系统拉取已导入的设备文档数据，验证关键字段（如“校准周期”、“更新时间”）的值与单位是否与原始文档一致。
*   上传一份超大容量的设备说明书 PDF，观察 FastGPT 的日志，确认 `PARSE_FILE_TIMEOUT_SECONDS` 配置能支持完成文件解析。
