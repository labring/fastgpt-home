# 生物等效性质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样
生物等效性（BE）研究的质量文档，主要包含方案、报告、原始数据、统计分析文件等。数据来源通常是临床研究机构、CRO 公司及药企内部的研发部门。文档更新频率相对较低，主要集中在项目启动、中期修订和结题报告提交时。文档结构复杂，常包含大量表格、图表和统计数据。字段方面，常见的有受试者编号、给药时间、采血时间、药物浓度（Cmax、AUC等）、Tmax、不良事件记录等。单位标准化程度高，如浓度单位为 `ng/mL` 或 `μg/mL`，时间单位为 `小时` 或 `分钟`，数量单位为 `mg`。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
生物等效性文档的数据量通常较大，单个报告文件可能包含数百页，且内部结构复杂，影响文件解析的效率和准确性。文档更新频率低，意味着对实时同步的要求不高，但对数据完整性和版本控制有较高要求。字段标准化程度高，便于通过结构化提取进行数据关联和校验，但也要求接口在数据解析时能准确识别这些特定字段及其单位。由于涉及原始数据和受试者信息，数据传输和存储的安全性是核心考量，需要确保 HTTP 接口支持加密传输，并对外部系统访问进行严格的身份验证和权限控制。对于报告中的图表，需要接口具备一定的图像解析能力，或依赖OCR服务进行文本提取。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 生物等效性报告文件可能包含大量图片和数据，文件体积较大。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 复杂PDF文档解析耗时较长，需要足够的处理时间。 |
| `分段长度` | `800 字符` | 确保单个分段能包含完整的表格行或关键结论，避免语义割裂。 |
| `相似度阈值` | `0.75` | 保证召回结果与生物等效性专业术语和数据高度相关。 |
| `maxContext` | `32000 tokens` | 完整理解复杂的研究方案和报告，提供足够的上下文窗口。 |
| `HTTP_REQUEST_TIMEOUT` | `120 秒` | 外部系统数据同步可能涉及大量数据传输，需要较长的超时时间。 |

## 容易做错的三处
*   外部系统调用接口时返回 `400 Bad Request` 错误，常见原因是请求体中的 JSON 格式不符合 API 规范，如缺少必需字段 `file_type` 或 `app_id`。
*   上传大型生物等效性报告文件后，系统长时间无响应或最终显示 `504 Gateway Timeout`，原因可能是 `PARSE_FILE_TIMEOUT_SECONDS` 配置过低，未能给文件解析留足时间。
*   通过 API 提交文档后，检索结果中关键数据（如 `Cmax` 值）缺失或错误，原因可能是文档解析器未能正确识别报告中的表格结构或特定单位 `ng/mL`。

## 怎么确认配好了
*   上传一份包含复杂表格和图表的生物等效性报告 PDF 文件，观察文件处理状态是否正常完成，并检查知识库中是否已生成对应的分段。
*   通过 API 接口上传一份测试文档，检查 API 返回的状态码是否为 `200 OK`，并验证文档内容是否成功入库。
*   针对报告中的特定药物浓度值或统计结果，进行检索测试，确认能准确召回包含该信息的原始文本段落。
*   模拟外部系统通过 HTTP 接口拉取数据，验证数据格式、字段完整性以及数据一致性是否符合预期，例如 `patient_id` 字段是否正确映射。
