# 病历质控质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

病历质控的数据主要来源于医院信息系统（HIS）、电子病历系统（EMR）以及医嘱系统等。这些数据通常以结构化或半结构化的形式存在，包括患者基本信息、诊断、治疗方案、用药记录、检查检验结果、手术记录、护理记录等。更新频率方面，门诊病历可能在就诊结束后即时更新，住院病历则在患者住院期间持续更新，出院后进行终末质控。文档结构上，病历质控文档通常遵循医疗行业的标准化模板，如病案首页、入院记录、出院记录、手术记录等，其中包含大量文本描述和规范编码的字段。字段内容涉及医学术语、计量单位（如 `mg`、`ml`、`mmol/L`），以及诊断编码（如 `ICD-10`）和手术编码。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

病历质控数据来源多样且更新频率不一，要求HTTP接口具备高并发处理能力和实时或近实时的数据同步机制。病历文档的标准化结构和大量医学术语，决定了接口在数据传输时需支持复杂JSON或XML格式，并能处理嵌套结构。字段中包含的 `ICD-10` 编码和各类计量单位，要求外部系统在数据解析时具备严格的数据类型校验和单位转换功能，以避免数据歧义。此外，历史病历数据量庞大，对接口的查询效率和分页能力提出较高要求。由于病历数据的敏感性，HTTP接口必须强制使用HTTPS协议，并实施严格的身份认证和访问控制，确保数据传输的安全性与合规性。文档中可能包含图片（如影像报告），要求接口支持二进制文件传输或提供稳定的文件存储服务。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `requestTimeout` | `60000 ms` | 确保能够处理病历文档解析和结构化所需的时间，避免因数据量大导致超时。 |
| `maxConnections` | `按实测标定` | 根据医院HIS/EMR系统并发请求量，保障数据同步效率。 |
| `payloadSizeLimit` | `10 MB` | 病历文档可能包含大量文本和少量嵌入图片，需支持大文件传输。 |
| `authHeaderName` | `Authorization` | 遵循OAuth 2.0或JWT等主流认证标准，保障接口安全。 |
| `responseSchema` | `JSON Schema` | 定义严格的响应数据结构，确保病历数据字段的完整性和准确性，便于下游系统解析。 |
| `fileUploadMethod` | `multipart/form-data` | 支持上传影像报告等图片文件，确保文件内容完整传输。 |

## 容易做错的三处

*   在调用接口时，返回状态码 `400 Bad Request`，原因是请求体中缺少必要的 `patientId` 字段或 `ICD-10` 编码格式错误。
*   上传图片文件后，外部系统接收到的文件链接无法访问，这是因为 FastGPT 内部文件存储路径是相对路径，需要额外配置 `BASE_URL` 或进行文件代理。
*   处理大量历史病历数据时，HTTP 接口经常出现 `504 Gateway Timeout` 错误，原因在于单个API调用处理的数据量过大或业务逻辑过于复杂，导致执行时间超过了网关或服务器的默认超时限制。

## 怎么确认配好了

*   通过 Postman 或 curl 工具，使用一个包含完整病历结构和标准编码的示例数据进行接口调用，检查返回状态码是否为 `200 OK`，并验证响应数据结构与预期 `JSON Schema` 是否一致。
*   上传一个包含图片附件的病历文档，检查 FastGPT 中文件链接是否可访问，并确认外部系统能够正确解析并显示该图片。
*   模拟高并发请求，使用压力测试工具对接口进行测试，观察接口响应时间是否在合理范围内，并检查错误日志中是否存在 `timeout` 或 `connection refused` 等异常信息，以此来标定 `maxConnections` 和 `requestTimeout` 的合理阈值。
