# 监护设备质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

监护设备质量文档主要涵盖产品设计规范、测试验证报告、生产工艺流程、风险管理报告、用户手册以及合规性证书等。数据来源多样，包括内部研发系统、生产管理系统、质量管理系统（QMS）、以及外部法规数据库。这些文档的更新频率各异，例如产品设计规范在产品生命周期内可能更新较少，而测试报告和生产批次记录则会频繁生成。文档结构通常高度标准化，符合医疗器械行业特有的QMS要求，如ISO 13485或FDA 21 CFR Part 820。字段内容严谨，常包含设备型号、序列号、批次号、测试结果、偏差说明、审批人、审批日期等，且存在大量数值型数据，如测量精度（单位：%FS）、校准周期（单位：月）、故障率（单位：ppm），以及特定法规代码和版本号。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

监护设备质量文档的标准化结构和高合规性要求，对HTTP接口的数据格式和验证机制提出了严格约束。例如，文档中包含的序列号、批次号等关键标识符，在接口请求时必须精确匹配，区分大小写，并符合预定义的正则表达式。频繁更新的测试报告和生产记录，要求HTTP接口能够处理高并发的写入或查询请求，并确保数据一致性。文档中大量的数值型数据，如测量精度或校准周期，需要接口在数据传输时保持其原始精度，避免浮点数精度丢失，并确保单位信息的正确传递。此外，涉及外部法规数据库的查询，要求HTTP接口具备强大的安全性，支持OAuth 2.0等认证协议，确保数据传输加密（如TLS 1.2+），并能处理外部系统可能返回的各种错误码，例如 `401 Unauthorized` 或 `404 Not Found`。

## 配置怎么定

| 配置项                       | 建议取法                                 | 这样取的依据                                                                         |
| :--------------------------- | :--------------------------------------- | :----------------------------------------------------------------------------------- |
| `requestTimeoutSeconds`      | `600 秒`                                 | 应对外部系统响应慢或处理复杂查询（如多文档关联查询）的情况，避免请求超时中断。     |
| `maxConnections`             | `20`                                     | 兼顾并发处理能力与外部系统承载能力，防止因连接数过多导致外部系统拒绝服务。       |
| `retryAttempts`              | `3`                                      | 针对网络瞬时抖动或外部系统短暂不可用，提供容错机制，提高请求成功率。             |
| `headers.Authorization`      | `Bearer <YOUR_TOKEN>`                    | 采用标准的OAuth 2.0 Bearer Token认证方式，确保接口调用的安全性。                   |
| `responseContentType`        | `application/json` 或 `application/xml`  | 匹配监护设备文档数据常用的结构化格式，便于后续解析和处理。                         |
| `errorHandling.statusCodes` | `[400, 401, 403, 404, 500, 502, 503, 504]` | 明确处理常见的HTTP错误状态码，以便进行针对性的错误日志记录和重试策略。             |

## 容易做错的三处

*   调用外部系统接口时，返回 `401 Unauthorized` 或 `403 Forbidden`。原因通常是 `headers.Authorization` 中的凭证过期、格式错误或权限不足，未能通过外部系统的身份验证或授权检查。
*   从外部系统获取的数值型数据与预期不符，例如 `测量精度` 字段的值出现截断或精度丢失。原因可能是HTTP接口在数据序列化/反序列化过程中，未正确处理浮点数类型，或未指定足够的精度。
*   HTTP请求长时间无响应，最终导致 `requestTimeoutSeconds` 错误。原因往往是外部系统处理复杂查询（如跨多个历史批次文档的聚合查询）耗时过长，超出了接口配置的等待时间。

## 怎么确认配好了

*   通过模拟请求，验证HTTP接口能够成功调用外部系统并返回 `200 OK` 状态码，且返回数据结构与预期一致。
*   针对包含数值型数据的关键字段，例如 `校准周期`（单位：月），通过实际查询比对，确认接口返回的值与外部系统原始数据完全匹配，无精度损失或单位错误。
*   通过触发外部系统可能出现的错误场景（如提供无效凭证或查询不存在的文档ID），验证HTTP接口的错误处理逻辑，确认能够正确捕获并记录 `404 Not Found` 或 `401 Unauthorized` 等错误码。
