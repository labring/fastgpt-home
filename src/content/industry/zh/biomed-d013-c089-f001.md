# 苗头化合物筛选质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

苗头化合物筛选过程中的质量文档主要包括化合物结构式文件（如 `.sdf`、`.mol`）、高通量筛选（HTS）原始数据报告（如 `.csv`、`.xlsx`）、活性验证报告（如 `.pdf`、`.docx`）以及批次分析证书（如 `.xml`）。这些文档的来源通常是自动化筛选平台、实验室信息管理系统（LIMS）或合作方提供的文件服务器。数据的更新频率与筛选批次紧密相关，可能每周或每两周更新一批，涉及数千至数万个化合物记录。文档结构方面，结构式文件遵循特定化学信息学标准；HTS 报告包含化合物 ID、测试批次、IC50 值、EC50 值、选择性等字段，单位多为纳摩尔（nM）或微摩尔（μM）；批次分析证书则详细列出纯度、手性、杂质含量等指标。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

苗头化合物筛选数据的多源性和异构性，要求 HTTP 接口具备灵活的文件类型识别和解析能力。高通量数据的批量性和更新频率，对接口的并发处理能力和传输效率提出了要求，需要支持大数据流传输或分批次上传。结构化与非结构化文档并存的特点，意味着接口在接收数据后，需能触发不同的解析流程，例如对 `.sdf` 文件进行结构解析，对 `.xlsx` 文件进行数值抽取，对 `.pdf` 文件进行文本识别。活性值等关键字段的单位统一性（如 nM、μM）需要后端在数据摄入时进行标准化处理或单位转换。此外，批次分析证书通常包含敏感信息，要求接口具备严格的鉴权机制和数据加密传输，确保数据安全。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `API_KEY_MANAGEMENT_STRATEGY` | 统一密钥服务 | 插件调用第三方 API 的鉴权密钥安全管理 |
| `FILE_UPLOAD_ALLOWED_EXTENSIONS` | `sdf,mol,csv,xlsx,pdf,docx,xml` | 覆盖苗头化合物筛选所需的所有文档类型 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 应对大型高通量筛选报告文件的解析耗时 |
| `MAX_REQUEST_BODY_SIZE_MB` | `100 MB` | 支持上传包含大量化合物记录的原始数据文件 |
| `DOCUMENT_FIELD_MAPPING` | 按实测标定 | 映射 HTS 报告中的 IC50、EC50 等关键字段 |
| `DATA_UNIT_STANDARDIZATION_RULES` | `nM -> uM` | 统一处理活性值单位，确保数据一致性 |

## 容易做错的三处

*   文件上传后，特定格式文档（如 `.sdf` 或 `.xml`）未被正确解析，导致核心字段缺失。原因在于 `FILE_UPLOAD_ALLOWED_EXTENSIONS` 未包含该文件类型，或 `DOCUMENT_FIELD_MAPPING` 未针对其内部结构进行正确配置。
*   调用外部 API 时，返回 `HTTP 401 Unauthorized` 错误码。原因在于 `API_KEY_MANAGEMENT_STRATEGY` 未能正确传递或刷新鉴权密钥，或者密钥配置与第三方系统不匹配。
*   对话接口在处理图文请求时，返回结果为空。原因在于 `MAX_REQUEST_BODY_SIZE_MB` 设置过小，导致包含嵌入图片信息的请求体被截断或拒绝，或者 `DOCUMENT_FIELD_MAPPING` 未能识别图片关联的描述性文本。

## 怎么确认配好了

*   上传一批包含 `.sdf`、`.xlsx` 和 `.pdf` 文件的测试数据集，检查每个文档的核心字段（如化合物结构、IC50 值、纯度）是否均被正确抽取并展示。
*   通过 HTTP 接口调用一个外部化合物数据库的查询功能，确保 API 密钥能成功鉴权，并返回预期的化合物信息。
*   检查系统日志，确认在处理高通量筛选报告时，没有出现 `PARSE_FILE_TIMEOUT_SECONDS` 超时错误，且数据摄入速率符合预期。
*   向对话接口发送包含苗头化合物结构图片（以图文请求形式）的问题，验证接口能够结合图片信息，给出相关的筛选建议或化合物性质描述。
