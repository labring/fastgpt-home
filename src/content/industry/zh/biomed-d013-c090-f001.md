# 药物经济学质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样
药物经济学质量文档通常包含临床试验数据、真实世界证据、成本效益分析模型、敏感性分析结果、卫生技术评估报告以及各类政策法规文件。数据来源广泛，包括公共数据库、期刊文献、药品注册资料、医院财务数据和临床路径。更新频率不一，临床指南和政策法规可能每年或每季度更新，而药品价格和医保支付标准可能每月变动。文档结构复杂，常包含大量图表、附录和交叉引用。字段方面，涉及药品通用名、适应症、治疗方案、疗效指标（如 QALY、DALY）、成本构成（直接成本、间接成本）、效应单位和贴现率。单位多样，如美元、人民币、生命年、质量调整生命年等，且不同来源的数据单位可能需要统一转换。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
药物经济学数据的多样性和复杂性，要求 HTTP 接口具备强大的数据解析和处理能力。多源异构数据意味着在调用外部系统接口时，需要针对不同数据源设计特定的请求参数和响应解析逻辑。例如，从公共数据库获取临床数据与从政府网站抓取政策文件，其 API 接口格式和认证方式可能完全不同。数据更新的频繁性，尤其是药品价格和医保支付标准，要求外部系统接口具备高并发和低延迟的特性，以确保获取的数据实时有效。文档中包含的图表和复杂结构，使得传统文本解析方式不足以完全提取有效信息，可能需要结合图像识别或结构化文档解析服务。此外，字段和单位的标准化是关键，HTTP 接口在数据传输过程中需要定义清晰的转换规则，避免因单位不一致导致的数据错误。超长的文档内容也对接口的请求体大小和响应时间提出了挑战。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `requestTimeout` | `600 秒` | 药物经济学报告常包含大量图表与复杂文本，解析时间较长，避免请求超时。 |
| `maxChunkSize` | `800–1200 字符` | 确保单个分段包含足够的上下文信息，同时避免过大的分段影响检索效率。 |
| `fileSizeLimit` | `100 MB` | 应对包含多媒体或高分辨率图表的质量文档，允许上传大文件。 |
| `concurrentRequests` | `按实测标定` | 确保在获取多源数据时，系统能平衡性能与稳定性，避免外部系统过载。 |
| `responseSchemaValidation` | `严格校验` | 确保从外部接口获取的数据结构符合预期，避免因格式变动导致解析失败。 |
| `retryAttempts` | `3 次` | 应对外部服务瞬时故障或网络波动，提高数据获取的成功率。 |

## 容易做错的三处
*   HTTP 请求在 `60 秒` 后返回超时错误。原因在于默认的接口超时时间过短，未能覆盖大型药物经济学文档的完整处理周期。
*   从外部系统获取的成本数据字段为空。原因在于外部接口返回的 JSON 结构与预期不符，或者缺少了关键的单位转换逻辑。
*   多个文件作为参数传递给 AI Agent 时，只处理了第一个文件。原因在于接口参数设计未充分考虑多文件上传场景，导致后续文件未被正确识别或处理。

## 怎么确认配好了
*   对不同大小和复杂度的药物经济学文档执行多次上传与处理操作，检查接口返回的状态码是否为 `200` 或 `201`。
*   随机抽取处理后的文档，核对其中关键的成本、疗效指标等字段，确认其数值和单位是否与原始文档一致。
*   模拟高并发场景，观察接口的响应时间及错误率，确保在压力下系统仍能稳定运行，并根据实际负载情况调整 `concurrentRequests` 参数。
