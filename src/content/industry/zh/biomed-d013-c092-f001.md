# 血液肿瘤质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样
血液肿瘤领域的质量文档，其数据来源主要包括临床试验报告、药物生产批次记录、不良事件监测报告以及法规符合性审计文件。这些文档的更新频率较高，特别是临床试验数据和不良事件报告，可能按周或按月更新。文档结构上，常以结构化表格（如 CSV、Excel）与半结构化文本（如 PDF 格式的报告）混合存在。字段方面，特有字段包括 `ICD-O-3` 肿瘤形态学编码、`WHO 疾病分类`、`RECIST 评估标准`、`药物批号`、`患者ID`、`剂量单位`（如 `mg/kg`）等。单位的精确性和一致性在质量文档中至关重要，例如药物浓度通常精确到 `ng/mL`，时间点精确到 `天` 或 `小时`。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
血液肿瘤质量文档的混合数据结构对接口设计提出了要求。结构化数据需要直接映射到 JSON 或 XML 字段，半结构化文本则需预处理提取关键信息。高更新频率意味着外部系统需要支持周期性或事件驱动的接口调用，例如，每当新的临床试验数据导入时触发一次同步。特有字段的存在要求接口能够灵活处理自定义字段的映射和验证，特别是对于 `ICD-O-3` 编码这类具有层级关系的字段。此外，单位的精确性要求接口在数据传输时保持单位的完整性，避免因单位丢失或误解导致的数据质量问题，例如，`剂量` 字段必须与其 `单位` 字段关联传递。对 HTTP 接口而言，这意味着需要定义清晰的数据模型和验证规则，以确保传入数据的准确性和完整性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `800–1200 字符` | 确保能够捕获血液肿瘤报告中关键的诊断描述和治疗方案细节。 |
| `分段长度` | `300 字符` | 兼顾语义完整性与召回效率，避免过度截断关键医学术语。 |
| `召回条数` | `前 5 条` | 考虑到血液肿瘤文档的专业性和关联性，适当增加召回量以覆盖更多相关信息。 |
| `相似度阈值` | `0.75` | 保证召回结果与血液肿瘤查询意图高度相关，减少无关信息的干扰。 |
| `HTTP_REQUEST_TIMEOUT` | `600 秒` | 应对外部系统在处理大量临床数据或生成复杂报告时可能出现的延迟。 |
| `webhookUrl` | `按实测标定` | 需根据实际业务系统提供的回调地址进行配置和验证。 |

## 容易做错的三处
*   外部系统返回 `HTTP 500` 错误或空响应体，原因常是请求体中的 `ICD-O-3` 编码格式不符合目标系统预期的数据校验规则。
*   调用 FastGPT API 后，输出的 `治疗方案` 字段内容包含了上一个 `诊断结论` 字段的部分文本，原因在于上下文管理配置不当，导致变量污染。
*   Webhook 配置后无法触发，检查发现 `Content-Type` 头未设置为 `application/json`，导致外部系统无法正确解析请求体。

## 怎么确认配好了
*   对核心的血液肿瘤文档（如诊断报告、用药记录）执行一次知识库导入，检查是否有解析错误或字段缺失。
*   模拟一次外部系统的数据更新，通过 HTTP 接口触发知识库同步，检查 `更新时间` 字段是否正确反映变化。
*   针对血液肿瘤的典型问题（例如“XX 基因突变患者的治疗方案”），进行至少 5 次问答测试，评估返回结果的相关性和准确性，确保 `RECIST 评估标准` 等关键信息能被正确召回。
*   检查外部系统日志，确认 FastGPT 发出的 HTTP 请求是否成功被接收，且响应码为 `HTTP 200 OK`。
