# 血液肿瘤质量文档的工具调用与插件

## 这个品类的数据长什么样

血液肿瘤领域的质量文档具有其特有的数据结构与更新频率。数据来源主要包括临床试验报告、药品注册批件、生产工艺规程、质量标准、检验报告、不良事件报告以及法规指南。这些文档通常以 PDF、Word、Excel 等格式存储，部分数据通过 LIMS（实验室信息管理系统）或 QMS（质量管理系统）接口获取。更新节奏方面，临床试验数据随试验进展实时更新，法规指南则依据药监部门发布周期进行修订，生产工艺和质量标准通常在变更控制流程下进行更新，频率相对较低。文档结构上，常包含大量表格、图表，文本内容涉及专业术语、缩写以及剂量、浓度、时间等带有特定单位的数值，例如 `mg/kg`、`nM`、`μg/mL`、`天`、`周`。字段名称标准化程度较高，但不同文档间仍可能存在细微差异。

## 这些特征在「工具调用与插件」这一环带来什么约束

血液肿瘤质量文档的特性对工具调用与插件的设计提出了具体要求。首先，文档中包含的表格和图表数据，要求工具能够解析多样的结构化和半结构化信息，例如从 PDF 中准确提取药物剂量曲线数据或批次检验结果。其次，专业术语和缩写的使用，使得对外部医学词典或本体论服务的调用成为必要，以确保语义理解的准确性。再者，数据更新频率的不一致性，意味着工具调用需要支持定时同步或事件触发机制，例如当新的临床试验数据发布时，自动触发数据抽取和知识库更新流程。对于带有特定单位的数值，工具需要具备单位识别和转换能力，避免因单位不一致导致的数据误读。此外，法规遵循性要求工具调用过程中对数据溯源和版本控制的支持，确保所有操作可审计。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `8000` | 血液肿瘤文档专业性强，上下文长度需足以覆盖复杂逻辑和多重因果关系。 |
| `分段长度` | `500–800 字符` | 确保每个分段包含足够语义信息，同时避免过长导致信息冗余或模型处理效率下降。 |
| `召回条数` | `前 10 条` | 提高相关信息召回率，应对文档中可能存在的关联性较弱但重要的细节。 |
| `相似度阈值` | `0.78` | 兼顾召回精度与广度，有效过滤不相关内容，同时不遗漏潜在重要信息。 |
| `HTTP_TIMEOUT_SECONDS` | `60 秒` | 外部系统如 LIMS 或医学知识库响应时间可能较长，需预留足够超时时间。 |
| `IMAGE_RECOGNITION_ENABLED` | `true` | 血液肿瘤文档常含图表，启用图像识别插件可提取图表中的关键数据。 |

## 容易做错的三处

*   调用外部API时出现 `HTTP 504 Gateway Timeout` 错误，原因在于外部医学影像分析服务处理大型图像文件耗时过长，超出了默认的请求超时时间。
*   从 PDF 报告中提取的药物浓度值 `100`，但未附带单位，原因在于解析工具未能正确识别单位 `nM`，导致数值语义不完整。
*   工作流中调用了外部的临床数据库查询工具，但返回结果的 `data` 字段为空，原因在于数据库接口的认证令牌 `X-API-KEY` 已过期，导致权限验证失败。

## 怎么确认配好了

*   通过调用外部医学词典插件，验证血液肿瘤相关专业术语（如 `CAR-T`、`CRISPR`）的解释是否准确且一致。
*   上传包含复杂表格的检验报告 PDF，测试知识库能否正确抽取并结构化表格中的多行多列数据，尤其关注剂量 `mg/kg`、时间 `天` 等带单位数值的提取。
*   模拟外部临床试验数据更新事件，检查自动化工具调用流程是否被正确触发，并能将新数据同步至知识库，验证数据更新的及时性。
*   执行一次包含图像识别插件的查询，确认图表中关键数据点（如肿瘤标志物随时间的变化趋势）是否能被成功识别并作为上下文提供给模型。
