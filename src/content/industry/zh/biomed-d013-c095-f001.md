# 质量文档管理质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

生物医药领域的质量文档，例如 SOP（标准操作规程）、批生产记录、检验报告等，通常以结构化或半结构化的文本形式存在。这些文档多数来源于企业内部系统，如 EDM（电子文档管理系统）或 LIMS（实验室信息管理系统），并由人工或专业软件定期更新。更新频率较低，通常为季度或年度修订，但遇法规变动或工艺优化时会进行即时更新。文档结构严谨，包含版本号、生效日期、修订历史、审批流程、正文内容、附件等固定字段。其中，正文内容多为叙述性文本，可能包含工艺参数（如 `温度：25 ± 2 ℃`）、分析方法（如 `HPLC`）和结果数据（如 `纯度 ≥ 99.5 %`），字段与单位严格遵循行业规范和法规要求。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

质量文档的严格结构和低更新频率，要求 HTTP 接口设计时需重点考虑数据的准确性和版本控制。由于文档内容涉及专业术语和计量单位，接口在接收和解析数据时，需要具备对特定文本模式的识别能力，以确保字段提取的准确性。例如，提取 `批次号` 或 `有效期` 等关键信息。更新频率低意味着接口不应频繁轮询源系统，而应更多依赖事件驱动机制，如通过 Webhook 接收文档更新通知。文档中嵌入的参数和单位，如 `pH 值`、`浓度单位`，在通过 HTTP 请求传递时，需要统一编码标准，以避免解析错误。此外，外部系统在调用接口时，必须严格遵守鉴权机制，确保数据安全性和合规性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `AIPROXY_API_ENDPOINT` | `https://your-internal-ai-service.com/api` | 指定内部 AI 服务接口地址，确保数据不外泄，符合行业数据安全规范。 |
| `AIPROXY_API_TOKEN` | `Bearer your_secure_jwt_token` | 使用 JWT 或其他安全令牌进行身份验证，保障对敏感质量文档的访问权限。 |
| `MAX_BODY_SIZE_MB` | `100 MB` | 考虑到SOP或批记录可能包含大量文本和嵌入图片，预留足够大的请求体大小。 |
| `PARSE_TIMEOUT_SECONDS` | `180 秒` | 复杂质量文档解析耗时较长，提供充足的解析时间，避免超时。 |
| `WEBHOOK_RETRY_COUNT` | `3 次` | 确保在网络波动或外部系统暂时不可用时，文档更新通知能够可靠送达。 |
| `CUSTOM_HEADER_AUTH` | `X-API-Key: YOUR_STATIC_API_KEY` | 对于特定外部系统，通过自定义请求头传递额外认证信息，增强安全性。 |

## 容易做错的三处

*   HTTP 请求返回 401 或 403 错误码，现象是无法访问外部文档或无法提交更新。原因通常是 `AIPROXY_API_TOKEN` 配置错误或已过期，导致身份验证失败。
*   工作流中 HTTP 请求的 `body` 参数在运行时为空或格式不正确。原因常常是未正确使用 FastGPT 内置的变量表达式，导致动态数据（如 `批次号` 或 `修订人`）无法传入请求体。
*   文档内容解析后部分关键字段缺失或提取错误。这可能是由于外部接口返回的 JSON 结构与预期不符，或在 FastGPT 中配置的 JSON Path 表达式不准确。

## 怎么确认配好了

*   在 FastGPT 工作流中，通过测试 HTTP 请求，观察返回的 HTTP 状态码是否为 200 或 204。
*   检查外部系统日志，确认是否有来自 FastGPT 的请求记录，并比对请求体内容与预期是否一致。
*   在 FastGPT 知识库中，导入测试性质的质量文档，并使用“预览”功能验证文档内容的关键字段（如 `版本号`、`生效日期`）是否被正确识别和提取。
