# 质量文档管理质量文档的工具调用与插件

## 这个品类的数据长什么样

生物医药行业的质量文档，其数据来源主要为内部质量管理体系的记录、外部法规要求与行业标准。这些文档的更新频率取决于其类型，例如标准操作规程（SOP）可能每年修订一次，批生产记录则随批次实时生成。文档结构通常高度标准化，例如遵循 GMP（良好生产规范）或 GLP（良好实验室规范）要求，包含明确的标题、版本号、生效日期、修订历史、责任人、审批流程、正文及附件等字段。字段内容可能涉及特定的化学物质名称、批号、设备参数、检测结果等，且常伴随精确的计量单位，如 `mg/L`、`kPa`、`℃`。文档格式以 PDF、Word、Excel 居多，部分系统会生成结构化 XML 数据。

## 这些特征在「工具调用与插件」这一环带来什么约束

质量文档的高度标准化结构和严格的版本控制，要求工具调用与插件在数据提取时，必须能够精准识别特定字段，例如 `文档编号`、`生效日期`、`修订历史`。文档内容的专业性与计量单位的精确性，约束了插件在处理数据时需具备单位转换或校验能力，避免因单位混淆导致错误。更新频率方面，对于实时生成的批生产记录，插件需支持高频触发与快速响应，以确保数据时效性。法规合规性要求插件在与外部系统交互时，必须符合数据安全与审计追踪的规范，例如记录每次工具调用的 `请求参数` 和 `响应结果`。由于文档多为非结构化或半结构化格式，插件需要更强的文档解析能力，例如能够从 PDF 中准确提取表格数据。

## 配置怎么定

| 配置项             | 建议取法                               | 这样取的依据                                                                 |
| :----------------- | :------------------------------------- | :--------------------------------------------------------------------------- |
| `maxContext`       | `8192 token`                           | 确保能完整加载典型质量文档的关键段落，兼顾效率                               |
| `分段长度`         | `500 字符`                             | 平衡语义完整性与召回精度，避免长段落信息丢失或噪音过多                       |
| `召回条数`         | `前 8 条`                              | 覆盖相关度较高的信息片段，减少无关信息干扰                                   |
| `相似度阈值`       | `0.75`                                 | 过滤掉低相关性结果，提升召回质量，按实测标定                                 |
| `重排返回条数`     | `前 3 条`                              | 精炼最终输出，确保核心信息突出                                               |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒`                               | 应对大型质量文档的解析耗时，避免解析中断                                     |

## 容易做错的三处

*   调用工具时 `文档编号` 或 `批次号` 等关键参数为空，导致工具执行失败并返回 `400 Bad Request` 错误，原因是没有从用户问题或上下文准确提取必要参数。
*   插件返回的数据与预期不符，例如数值缺少单位或单位错误，原因是没有在工具定义中明确参数的 `type` 或 `format`，或未在插件逻辑中进行单位转换。
*   长时间没有收到工具调用结果，最终显示 `Gateway Timeout`，原因通常是外部系统接口响应慢，或者插件内部处理逻辑耗时过长，未能及时返回。

## 怎么确认配好了

*   针对不同类型的质量文档，构造典型查询，检查工具调用是否能准确识别并提取 `文档编号`、`版本号` 等关键字段。
*   设计包含计量单位的查询，验证插件在调用外部系统时，能否正确传递带单位的数值，并对返回结果进行单位校验。
*   模拟高并发场景，检查插件对实时批生产记录的查询响应时间是否在可接受范围内，确保 `PARSE_FILE_TIMEOUT_SECONDS` 等配置合理。
