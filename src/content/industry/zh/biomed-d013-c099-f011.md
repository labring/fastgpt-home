# 远程医疗质量文档的文档解析与分块

## 这个品类的数据长什么样

远程医疗服务涉及的质量文档种类繁多，主要包括服务协议、操作规范、诊疗指南、风险评估报告、患者反馈记录和设备维护手册等。这些文档的来源通常是医疗机构内部规章制度、行业监管要求、以及医疗设备供应商的技术说明。文档更新频率相对稳定，一般遵循年度审核或政策变动时更新的节奏，但紧急情况下的临时修订也并不少见。文档结构上，多数采用章节式或清单式布局，包含大量专业术语、医学缩写、以及特定的计量单位，例如药品剂量单位（mg、ml）、时间单位（小时、天）和医学影像参数（分辨率、像素）。部分文档可能包含表格、图表或扫描图像。

## 这些特征在「文档解析与分块」这一环带来什么约束

远程医疗质量文档的专业性与结构化特点，对文档解析提出了更高的要求。其中涉及的医学专业术语和缩写，需要解析器具备准确识别和上下文理解的能力，以避免错误分词或关键信息丢失。文档中常见的章节、子章节、列表和表格结构，要求解析器能够精准识别逻辑边界，确保分块内容的完整性和语义连贯性。更新频率虽然不算极高，但任何政策或规范的修订，都可能导致关联文档内容的变化，这就需要解析系统能够处理文档的版本管理，并支持对更新内容的增量解析。部分文档可能以扫描件形式存在，OCR识别的准确性直接影响后续解析质量。文档中出现的特定计量单位，要求分块时能够保留其数值与单位的对应关系，避免语义破碎。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `UPLOAD_FILE_MAX_SIZE` | `100 MB` | 远程医疗文档通常较大，尤其是包含大量图片或扫描件的报告。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 处理大型或复杂文档，特别是需要OCR的扫描件，解析时间可能较长。 |
| `分段长度` | `800–1200 字符` | 确保每个分段包含足够的上下文信息，便于理解专业术语和诊疗流程。 |
| `分段重叠长度` | `100 字符` | 增加分段之间的重叠，有助于在检索时捕获跨分段的关联信息。 |
| `maxContext` | `4000 字符` | 远程医疗文档的复杂性要求模型能处理较长的上下文窗口。 |
| `CONCURRENT_FILE_PARSING_LIMIT` | `3` | 平衡系统资源占用与解析效率，避免因文件过大或并发过多导致超时。 |

## 容易做错的三处

*   文件解析长时间无响应或报错 `504 Gateway Timeout`：这通常是由于 `PARSE_FILE_TIMEOUT_SECONDS` 设置过短，无法完成对大型文档（如数百页的PDF）的解析，或者 `CONCURRENT_FILE_PARSING_LIMIT` 过低导致队列积压。
*   检索结果中专业术语或计量单位的上下文缺失：原因可能是 `分段长度` 设置过短，导致关键信息被截断，或 `分段重叠长度` 不足，使得相关内容在不同分段间无法有效衔接。
*   解析扫描件PDF时内容识别错误或遗漏：这指向OCR引擎的识别能力不足，或文档质量（如扫描清晰度）不佳，导致文本提取不准确。

## 怎么确认配好了

*   选取各类代表性文档（如诊疗规范、患者病历、设备手册），上传并观察其解析状态，确保所有文档都能在合理时间内完成解析，且无明显报错。
*   针对解析完成的文档，通过关键词检索，核对返回分段的完整性与语义连贯性，特别是关注涉及专业术语、计量单位和多步骤流程的描述。
*   检查文档分块预览，确保章节、标题、列表等结构化元素在分块时得到正确识别和保留，没有出现不自然的截断或合并。
*   使用包含表格或图表的文档进行测试，验证解析器对非文本内容的识别处理情况，确保关键数据在文本化后可被检索。
