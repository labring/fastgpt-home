# 院感管理质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

院感管理的数据主要来源于医疗机构内部的HIS、LIS、PACS系统，以及手工填报的感染报告、消毒记录等。这些数据更新频率较高，部分实时数据（如病患体征异常）可能每分钟更新，而周报、月报类文档则有固定更新周期。文档结构通常为半结构化，包含大量的文本描述、表格数据和附件。关键字段包括病患ID、感染部位、病原体、抗生素使用情况、医嘱、处理措施、消毒日期、设备批次号等。单位涉及剂量、时间、频率、数量等多种类型，需注意数值的精度与单位的标准化。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

院感管理数据的高更新频率要求HTTP接口设计具备高并发处理能力和低延迟响应。半结构化文档的特点使得传统的固定字段解析方式不足以覆盖所有信息，需要更灵活的文本抽取与解析策略。例如，感染报告中的自由文本描述可能包含关键的感染源或传播路径信息，这些信息需通过高级文本处理技术提取。多源数据集成意味着需要处理不同系统的数据格式差异和数据质量问题，确保数据在传输和存储过程中的完整性与一致性。此外，敏感的医疗数据对接口的安全性、鉴权机制和合规性提出了严格要求，传输过程需加密，访问权限需精细控制。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| :----- | :------- | :----------- |
| `maxContext` | `2000–4000 字符` | 院感文档的描述性内容较多，需要较长的上下文长度来理解复杂情况。 |
| `chunkSize` | `800–1200 字符` | 平衡召回效率与上下文完整性，确保单个块包含足够信息。 |
| `overlapSize` | `100–200 字符` | 保证分块间的语义连续性，避免关键信息被切割。 |
| `requestTimeout` | `30000 毫秒` | 考虑到外部系统查询、数据处理和网络延迟，预留充足的响应时间。 |
| `maxRetries` | `3 次` | 应对外部系统瞬时故障或网络抖动，提高接口调用的鲁棒性。 |
| `API_KEY_HEADER` | `Authorization` | 遵循行业标准的安全认证机制，确保接口访问的安全性。 |

## 容易做错的三处

*   HTTP 接口返回 `500 Internal Server Error` 状态码，通常是由于外部系统处理请求时发生未捕获的异常，需要检查外部系统日志定位具体错误。
*   部分关键字段（如 `病原体类型` 或 `抗生素名称`）在解析后为空，原因可能在于文档中这些信息的表述方式多样，现有解析规则未能完全覆盖。
*   数据更新后，AI 模型的回答仍基于旧数据，这通常是由于外部系统的数据同步机制未按预期触发，或缓存刷新策略配置不当。

## 怎么确认配好了

*   通过调用接口，检查返回数据的 `status` 字段是否为 `success`，并比对随机抽取的 5-10 条记录，确认关键字段（例如 `感染部位`、`处理措施`）的提取准确性，准确率应高于特定阈值。
*   模拟高并发请求，观察接口响应时间是否稳定在 `500 毫秒` 以内，并检查外部系统资源利用率，确保系统在高负载下仍能正常运行。
*   定期触发数据同步任务，并验证最新生成的院感报告中的信息是否能被模型正确引用，这需要检查更新数据的引用时间戳。
