# 院感管理质量文档的文档解析与分块

## 这个品类的数据长什么样

院感管理的数据主要来源于医院内部的规章制度、操作规范、病例数据、监测报告以及国家或地方发布的法律法规与指导文件。这些文档更新频率不一，政策法规类文档更新周期较长，而院内操作规范和监测报告可能按季度或年度更新。文档结构上，规章制度通常采用章节式组织，包含大量定义、流程描述和责任划分；操作规范则侧重于步骤化指导，常伴有图表、附录。病例数据和监测报告则多为结构化或半结构化数据，包含具体指标和数值。字段与单位方面，涉及微生物名称、感染部位、药品名称、剂量单位（如 `mg`、`ml`）、时间单位（如 `天`、`小时`）以及风险等级等。

## 这些特征在「文档解析与分块」这一环带来什么约束

院感管理文档的复杂性和多样性，对文档解析与分块提出了特定要求。首先，章节式规章制度需要保留其层级结构，避免因过度分块而割裂语境，导致检索时无法获取完整的政策依据。其次，操作规范中的步骤描述和图表，需要解析器能够准确识别文本与非文本元素，并尽可能提取图表内容的关键信息，或至少保留其原始上下文链接。病例数据和监测报告中的结构化信息，要求解析器能识别并提取关键字段值，例如感染类型、病原体、耐药情况等，以支持精准查询。此外，文档中常见的医学术语和缩写，需要解析过程能够正确识别，避免因词汇理解偏差导致分块错误或语义丧失。文档更新频率的不一致性，也要求解析流程具备增量更新和版本管理能力，确保知识库的时效性。

## 配置怎么定

| 配置项                   | 建议取法                               | 这样取的依据                                                                                                                              |
| :----------------------- | :------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------- |
| `UPLOAD_FILE_MAX_SIZE`   | `500 MB`                               | 院感管理文档，特别是包含大量图表和扫描件的 PDF，文件体积可能较大。                                                                        |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`                               | 复杂结构文档、大文件解析耗时较长，预留充足时间避免解析中断。                                                                              |
| `分段长度`               | `800–1200 字符`                        | 院感规章制度的条款通常较长，保持适当分段长度有助于维持语义完整性，避免割裂关键信息。                                                    |
| `重叠长度`               | `100–200 字符`                         | 确保相邻分段之间有足够的上下文重叠，有助于在检索时捕获跨分段的关联信息，尤其适用于流程描述。                                            |
| `启用图片文字识别`         | 启用                                   | 院感文档常包含流程图、表格截图，OCR 能力对于提取这些非文本信息至关重要。                                                                  |
| `分段策略`               | `按标题、段落、列表层级`               | 院感规章制度和操作规范通常有清晰的标题和段落结构，按此策略分段能更好地保留原始文档的逻辑层次。                                            |

## 容易做错的三处

*   上传文件后提示 `413 Request Entity Too Large` 错误，原因通常是文件大小超出了服务器或网关配置的最大限制，需要调整 `UPLOAD_FILE_MAX_SIZE` 参数或相关代理服务器配置。
*   飞书或在线文档解析后内容缺失，特别是多级目录或复杂表格，原因可能是解析器未能有效识别并提取这些复杂结构中的所有文本，或对内嵌对象支持不足。
*   通过 API 调用解析成功但未回传结果，可能由于 API 调用返回的 HTTP 状态码表示成功，但实际解析过程可能因文件内容异常、解析超时或后端处理逻辑错误而未能生成可用的分块数据。

## 怎么确认配好了

*   选择一份具有代表性的院感规章制度（包含多章节、复杂条款）和一份操作规范（包含流程图、表格），进行解析并查看分块结果，核对分块是否合理、语境是否完整。
*   上传一份包含手写批注或扫描件的 PDF 文档，检查图片文字识别功能是否有效，能否提取出关键文本内容。
*   通过知识库检索功能，尝试使用文档中的关键术语、法规编号或特定操作步骤进行查询，评估召回结果是否准确且包含完整上下文，以此反推分块质量。
