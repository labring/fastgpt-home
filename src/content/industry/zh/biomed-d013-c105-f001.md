# 骨科植入质量文档的HTTP 接口与外部系统

## 这个品类的数据长什么样

骨科植入器械的质量文档主要包括设计验证报告、生产工艺规程、批生产记录、检验报告、风险管理报告、临床评价报告以及上市后监督文件。这些文档通常以 PDF、Word、Excel 等格式存储，部分数据可能以结构化数据库（如 SQL Server 存储的批次追溯数据）形式存在。更新频率方面，设计文档在产品生命周期内相对稳定，但批生产记录和检验报告则随生产批次实时生成，风险管理报告和临床评价报告可能每年或根据监管要求进行更新。文档结构严谨，字段包括产品型号、批号、生产日期、有效期、检验结果、材料成分、尺寸公差等，单位涉及毫米（mm）、牛顿（N）、兆帕（MPa）、微克（μg）等。特定文档如产品说明书和标签，还会包含二维码或条形码信息。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束

骨科植入器械质量文档的特点决定了 HTTP 接口设计需要高度重视数据完整性与实时性。批生产记录和检验报告的实时生成，要求 API 具备高并发写入能力，并能处理结构化与非结构化数据的混合上传。多样的文档格式和包含的特定字段，例如产品批号 `Batch_ID`、生产日期 `Prod_Date`，需要接口支持灵活的元数据提取和解析，以便于后续的精确检索。此外，监管机构对数据可追溯性的要求，使得每次数据操作都需记录详细的日志，并与外部的质量管理系统（QMS）进行数据同步，确保数据一致性。文档中包含的特殊单位和技术术语，要求在数据传输和解析时有严格的校验机制，防止单位混淆或数据类型错误。

## 配置怎么定

| 配置项                       | 建议取法                               | 这样取的依据                                   |
| :--------------------------- | :------------------------------------- | :--------------------------------------------- |
| `UPLOAD_FILE_MAX_SIZE`       | `200 MB`                               | 应对大型设计验证报告或影像数据，避免上传失败。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒`                               | 确保复杂 PDF 文档或多页扫描件有足够时间完成解析。 |
| `maxContext`                 | `32000 token`                          | 覆盖长篇临床评价报告或风险管理报告的上下文。     |
| `分段长度`                   | `500 字符`                             | 平衡文本语义完整性与召回效率，适用于各类文档。 |
| `相似度阈值`                 | `0.75`                                 | 确保检索结果高度相关，减少非关键信息干扰。     |
| `HTTP_REQUEST_TIMEOUT_SECONDS` | `300 秒`                               | 与外部 QMS 系统进行数据同步时，应对网络延迟或大数据量传输。 |

## 容易做错的三处

*   HTTP 接口调用返回 504 Gateway Timeout，原因在于外部系统处理耗时过长，而接口超时时间设置过短。
*   对话输出的批号 `Batch_ID` 与实际文档中的批号不一致，原因在于文档解析时未正确识别或提取结构化数据中的关键字段。
*   API 调用后，对话日志中显示的数据详情为空或不完整，原因在于流式输出模式下，部分数据在传输过程中被截断或未能正确拼接。

## 怎么确认配好了

*   上传一份包含多页图表和文字的 PDF 文档，检查知识库索引状态，确认文档能够完整解析并成功入库。
*   通过 API 调用查询特定批号 `Batch_ID` 的检验报告，核对返回结果中的批号、生产日期等字段与原始文档内容是否完全一致。
*   模拟高并发场景下连续上传多份批生产记录，观察系统响应时间与错误日志，确保接口在高负载下运行稳定。
