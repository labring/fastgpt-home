# 幼儿园家园共育沟通的业务依据查询：上下文与 token

## 这个品类的数据长什么样

本页围绕幼儿园家园共育沟通中的业务依据查询，材料来自本园现行保教记录、家园联系册、通知回执、观察记录与家长诉求登记。更新节奏按日或按周，字段包括承诺事项与回应时间、幼儿表现描述、家长诉求分类、通知送达状态。这些材料进入上下文与 token 功能时，各自角色不同：承诺事项与回应时间用于核对是否回应，幼儿表现描述用于比对观察记录，家长诉求分类用于判断反馈是否归类，通知送达用于确认通知是否到达。查询时需将跨材料条目对齐，形成可回指原文的依据条目。

## 配置怎么定

这一环由应用设置（回复上限等）执行，输出单次回答长度与可容纳的上下文范围。「可回指原文的依据条目」由模型接着完成。回复上限用滑块控制单次回答的长度，设置过低回答会被截断，设置过高会增加消耗。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 回复上限 | 与页面要求的回答长度匹配 | 在应用设置里核对开关与滑块位置，并确认 `maxResponse` 取值与所需篇幅一致 |
| 承诺事项与回应时间 | 承诺未回应时能定位到原文条目 | 抽取本园材料中的承诺与回应时间，逐条比对是否已有回应记录 |
| 幼儿表现描述 | 表述与观察记录是否相符 | 将描述与观察记录并排，核对 `maxContext` 可容纳的上下文范围是否覆盖两份材料 |
| 家长诉求分类 | 反馈是否已归类 | 检查诉求登记中的分类字段，确认未归类条目能回指到原始诉求文本 |

## 容易做错的三处

- 现象：家长问承诺事项是否回应，回答只给结论不给原文。原因：跨材料条目未对齐，回指链断裂。
- 现象：幼儿表现描述与观察记录不一致，回答未指出差异。原因：上下文范围未覆盖两份材料，比对缺失。
- 现象：家长诉求未归类，回答却按已归类作答。原因：反馈分类字段未进入查询范围，依据不完整。

## 怎么确认配好了

本功能验收：提一个需要长回答的问题，看结尾是否完整，并核对 `maxResponse` 与 `quoteMaxToken` 的预算是否匹配；引用条数单独记录，不与引用内容预算做相等比较。

业务测试：问一个跨材料的依据问题，看回答是否给出可回指的出处，并确认出处能对上本园现行材料原文。

- 在应用设置里核对回复上限开关与滑块位置，确认 `maxResponse` 与页面所需回答长度匹配。
- 对比两次运行的用量，确认上限调整后单次用量变化，并检查较长回答结尾是否完整。
