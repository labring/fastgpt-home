# 高校就业签约与毕业去向统计的业务依据查询：文档解析与分块

## 这个品类的数据长什么样

本页聚焦高校就业签约与毕业去向统计品类，材料来源为校级就业管理部门、院系归档与用人单位回执，更新节奏按毕业季批次滚动。就业协议书、毕业去向登记表、用人单位证明三类材料进入文档解析与分块功能时，各自承担不同角色：就业协议书提供签约主体与签章字段，毕业去向登记表提供去向类别与日期字段，用人单位证明提供接收意见与回执字段。材料经解析分块后立即落库为可见数据行并绑定唯一数据标识，字段特征包括名称、数量、日期与签字，供后续检索与依据条目生成使用。

## 配置怎么定

这一环由解析与训练任务（服务端任务）执行，输出数据行与索引状态（已解析、索引中、已完成）。「可回指原文的依据条目」由检索与后续处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 就业协议书 | 字段须含签约主体、日期与签字，且与现行版本一致 | 打开数据行核对 `chunkSize` 与 `chunkSplitter` 分块后字段是否完整落入原文区间 |
| 毕业去向登记表 | 去向类别、数量与日期须与同批材料对得上 | 分别核对文件记录与数据行，确认 `trainingType` 对应处理模式与索引状态 |
| 用人单位证明 | 接收意见、回执与签字不得缺失 | 查看数据行状态是否为 parsed / indexing / indexed，并回指原文段落 |
| 数据行状态 | 处于三态之一且与界面显示一致 | 打开数据行核对状态，确认待索引数据不参与召回 |

## 容易做错的三处

- 现象：同一记录在就业协议书与毕业去向登记表里的名称、数量、日期对不上。原因：两份材料字段口径未统一，解析分块后未回指原文比对。
- 现象：用人单位证明缺签字或回执，仍进入待索引数据。原因：解析完成即落库为可见数据行，签字缺失未被字段核对拦截。
- 现象：刚上传的材料搜不到。原因：数据行处于 indexing 状态，待索引数据在检索层天然隔离不被召回，解析成功不等于检索命中。

## 怎么确认配好了

本功能验收：上传一份材料，看数据行状态流转与重建任务的覆盖范围，确认状态为 parsed / indexing / indexed，且重建只覆盖已完成索引的数据。

业务测试：问一个跨材料的依据问题，看回答是否给出可回指的出处，并核对引用条数与引用文本 tokens 分别记录。

- 打开数据行核对状态是否为 parsed / indexing / indexed，并确认与界面显示一致。
- 分别核对文件记录与数据行，确认重建任务只覆盖已完成索引的数据。
