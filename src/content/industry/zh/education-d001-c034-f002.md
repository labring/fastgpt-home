# 职业技能等级认定社会评价的业务依据查询：上下文与 token

## 这个品类的数据长什么样

本页面向职业技能等级认定社会评价中的业务依据查询，材料包括评价实施方案、考生报名表、考评员派遣表。评价实施方案给出认定职业、等级、科目与评价方式，是依据条目的主来源；考生报名表记录考生身份、申报条件与材料清单，用于核对依据与个人对应关系；考评员派遣表记录考评员资格、派遣日期与签字，用于核对评价过程依据。材料按批次归档，更新节奏与认定公告同步，字段含名称、数量、日期、签字与回执。材料进入本功能时，实施方案作为依据正文，报名表与派遣表作为交叉核对材料，三者共同支撑可回指原文的依据条目。

## 配置怎么定

这一环由应用设置（回复上限等）执行，输出单次回答长度与可容纳的上下文范围。「可回指原文的依据条目」由模型接着完成。回复上限用滑块控制单次回答的长度，设置过低回答会被截断，设置过高会增加消耗。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 评价实施方案 | 依据来自相关材料、版本是现行、条目能对上原文 | 在应用设置里核对 `maxResponse` 与 `maxContext` 是否匹配长依据回答；翻到方案原文核对职业、等级、科目与日期 |
| 考生报名表 | 名称、数量、日期与实施方案对得上，签字与回执齐全 | 逐条比对考生姓名、申报条件、材料数量与方案中的认定范围；核对签字与回执位置 |
| 考评员派遣表 | 考评员资格、派遣日期与方案批次一致，签字完整 | 核对派遣表与实施方案的批次日期、考评员数量；缺签字或回执时回指原文标注 |
| 引用条目 | 数组条数单独记录，`quoteMaxToken` 只核引用文本的 tokens | 记录引用数组长度与引用文本 tokens，不把两者做相等比较 |

## 容易做错的三处

- 现象：同一考生姓名在报名表与实施方案中写法不同。原因：两份材料录入时未统一名称，导致依据条目对不上原文。
- 现象：派遣表日期与实施方案批次日期不一致。原因：版本未同步，旧版派遣表混入现行批次。
- 现象：报名表缺签字或回执，依据条目无法回指。原因：材料归档时未补齐签字与回执，核对链断裂。

## 怎么确认配好了

本功能验收：提一个需要长回答的问题，看结尾是否完整，并核对 `maxResponse` 与 `maxContext` 设置。

业务测试：问一个跨材料的依据问题，看回答是否给出可回指的出处，并记录引用数组条数与 `quoteMaxToken` 预算。

- 在应用设置里核对回复上限开关与滑块位置，确认与页面要求的回答长度匹配。
- 提一个需要长回答的依据问题，检查回答结尾是否完整，对比两次运行的用量变化。
