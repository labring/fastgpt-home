# 职业培训补贴申领的业务依据查询：上下文与 token

## 这个品类的数据长什么样

职业培训补贴申领的行业问题页，材料来自本机构培训台账，含培训开班备案、签到记录、结业考核表三类。开班备案记录班次名称、职业工种、开班日期、授课教师与审批签字；签到记录按日登记学员姓名、出勤状态与本人签字；结业考核表登记考核日期、成绩、考评员签字与机构回执。三类材料按月归集，遇班次调整或补录时同步更新版本。进入本功能后，备案提供班次与工种口径，签到提供出勤与日期口径，考核表提供结业与签字口径，三者共同支撑可回指原文的依据条目。

## 配置怎么定

这一环由应用设置（回复上限等）执行，输出单次回答长度与可容纳的上下文范围。「可回指原文的依据条目」由模型接着完成。回复上限用滑块控制单次回答的长度，设置过低回答会被截断，设置过高会增加消耗。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 培训开班备案 | 班次名称、职业工种、开班日期、审批签字与现行版本能对上原文 | 在应用设置里核对开关与滑块位置，回指备案原文条目并记录版本号，核对 `maxContext` 是否容得下所引材料范围 |
| 签到记录 | 学员姓名、出勤状态、签到日期、本人签字与备案班次一致 | 逐日比对签到日期与备案开班日期，回指签到原文条目，核对 `quoteMaxToken` 是否覆盖引用文本的 tokens |
| 结业考核表 | 考核日期、成绩、考评员签字、机构回执与备案班次对应 | 核对考核日期与签到结束日期，回指考核表原文条目，核对 `maxResponse` 是否匹配该问题的回答长度 |
| maxContext、quoteMaxToken、maxResponse | 上下文范围、引用内容预算与单次回答长度各自独立记录 | 在应用设置里核对滑块位置，引用文本的 tokens 单独核，数组条数单独记录 |

## 容易做错的三处

- 现象：同一班次在备案与签到里的名称对不上。原因：两份材料各自录入，未按统一班次编号归集。
- 现象：签到日期与考核日期跨月对不上。原因：补录时未同步更新版本，旧版材料仍被引用。
- 现象：结业考核表缺考评员签字或机构回执。原因：材料归档时未逐项核对签字栏与回执栏。

## 怎么确认配好了

本功能验收：提一个需要长回答的问题，看结尾是否完整，并核对 `maxResponse` 与 `quoteMaxToken` 是否匹配该问题的长度与引用预算。

业务测试：问一个跨材料的依据问题，看回答是否给出可回指的出处，并核对 `maxContext` 是否容得下所引材料范围。

- 在应用设置里核对回复上限开关与滑块位置，确认单次回答长度与页面要求匹配。
- 提一个需要长回答的问题，看结尾是否完整，并对比两次运行的用量变化。
