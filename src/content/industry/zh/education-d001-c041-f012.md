# 企业合规与安全培训的业务依据查询：文档解析与分块

## 这个品类的数据长什么样

企业合规与安全培训材料，来源为合规培训课件、安全操作规程、考试记录三类，按季度或制度修订更新。课件含条款编号与生效日期，规程含操作步骤、责任人及签字栏，考试记录含考生、成绩、日期与回执。材料进入文档解析与分块功能时，课件与规程作为依据源被切分为可检索片段，考试记录作为佐证材料同步落库，各自绑定唯一数据标识。字段特征集中在名称、数量、日期、签字与版本号，同一记录在不同材料中常出现名称或日期不一致，版本未同步或缺少签字回执，需在解析后按数据行状态核对，确保依据来自相关材料且版本为现行。

## 配置怎么定

这一环由解析与训练任务（服务端任务）执行，输出数据行与索引状态（已解析、索引中、已完成）。可回指原文的依据条目由检索与后续处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 合规培训课件 | 条款编号、生效日期、版本号与签字栏齐全，且与现行制度一致 | 打开数据行核对状态是否为 parsed 或 indexed，检查课件名称、条款数量、日期与另一份材料是否对得上，并核对 `chunkSize` 与 `chunkSplitter` 的取值 |
| 安全操作规程 | 操作步骤、责任人、日期与回执签字完整，版本为现行 | 分别核对文件记录与数据行，确认规程版本号与考试记录中的名称、数量、日期一致，缺签字或回执则标记，并核对 `trainingType` 字段 |
| 考试记录 | 考生、成绩、日期与回执签字可回指原文，且与课件版本同步 | 核对数据行状态流转，确认记录中的日期与课件生效日期不冲突，回执缺失时单独记录，状态只认 parsed、indexing、indexed |
| 数据行 | 处于 parsed / indexing / indexed 三态之一且与界面显示一致 | 查看重建任务覆盖的数据行，确认只覆盖 indexed 数据，初次训练覆盖待索引与索引中数据，核对 `chunkSize`、`chunkSplitter`、`trainingType` 字段 |

## 容易做错的三处

- 现象：同一记录在课件与考试记录里的名称、数量、日期对不上。原因：两份材料各自独立录入，未在解析后做字段级比对与回指核对。
- 现象：规程版本未同步，旧版条款仍被当作现行依据。原因：材料更新后未触发索引重建，待索引数据与已完成索引数据混用。
- 现象：考试记录缺签字或回执，依据条目无法回指原文。原因：解析只落库可见数据行，未校验签字栏与回执字段的完整性。

## 怎么确认配好了

本功能验收：上传一份材料，看数据行状态流转与重建任务的覆盖范围，确认只对 indexed 数据触发重建，待索引数据不参与召回，并核对 `chunkSize`、`chunkSplitter`、`trainingType` 三个字段。

业务测试：问一个跨材料的依据问题，看回答是否给出可回指的出处，核对引用条数与引用文本 tokens 是否分别记录。

- 打开数据行核对状态是否为 parsed、indexing 或 indexed，并与界面显示一致。
- 分别核对文件记录与数据行，确认重建任务只覆盖已完成索引的数据，初次训练覆盖待索引与索引中数据。
