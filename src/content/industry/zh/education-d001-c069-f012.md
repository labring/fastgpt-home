# 期刊出版许可与年度核验的业务依据查询：文档解析与分块

## 这个品类的数据长什么样

本页围绕期刊出版许可与年度核验的业务依据查询，材料包括期刊出版许可证、年度核验表、整改报告三类。来源为出版管理材料与年度报送回执，更新节奏按年度核验周期与整改节点推进。字段特征集中在许可证号、刊期、主办单位、核验年度、签字与回执日期。材料进入解析与训练任务时，各自作为独立数据行落库，绑定唯一数据标识，分别承担许可资质、年度核验结论、整改闭环的角色，供后续检索与依据条目回指原文使用。

## 配置怎么定

这一环由解析与训练任务（服务端任务）执行，输出数据行与索引状态（已解析、索引中、已完成）。「可回指原文的依据条目」由检索与后续处理接着完成。解析分块在解析完成后立即落库为可见数据行并绑定唯一数据标识，索引按三态流转，待索引数据不参与召回。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 期刊出版许可证 | 字段含许可证号、刊期、主办单位与签字日期，需与年度核验表逐项对齐 | 核对许可证号、刊期、主办单位与签字日期；查看数据行状态是否为 parsed / indexing / indexed |
| 年度核验表 | 核验年度、刊期数量与回执日期需与许可证及整改报告一致 | 核对核验年度、刊期数量与回执日期；检查 `trainingType` 与 `chunkSize` 对应的分块是否覆盖该年度 |
| 整改报告 | 整改事项、完成日期与签字回执需能回指许可证与核验表原文 | 核对整改事项、完成日期与签字回执；确认 `chunkSplitter` 切分后条目可回指原文 |
| 数据行 | 处于三态之一且与界面显示一致，文件记录与数据行身份分得开 | 打开数据行核对状态；分别核对文件记录与数据行，看重建任务覆盖的数据行 |

## 容易做错的三处

- 现象：同一记录在许可证与核验表里的刊期数量对不上。原因：两份材料名称、数量、日期未逐项对齐，解析后各自成行未做交叉核对。
- 现象：年度核验表用了旧版模板，整改报告却按新版填写。原因：版本未同步，材料进入解析时未标注现行版本，索引状态虽为 indexed 但内容口径不一。
- 现象：整改报告缺签字或回执日期，检索仍能命中。原因：解析成功不等于检索一定命中，索引状态与签字字段未联动校验，缺项未被拦截。

## 怎么确认配好了

本功能验收：上传一份材料，看数据行状态流转与重建任务的覆盖范围。状态应为 parsed / indexing / indexed，重建只覆盖已完成索引的数据，初次训练覆盖待索引与索引中的数据。

业务测试：问一个跨材料的依据问题，看回答是否给出可回指的出处。例如问年度核验表中的刊期数量与许可证是否一致，回答需给出材料名称与原文位置。

- 打开数据行核对状态是否为 parsed / indexing / indexed，并分别核对文件记录与数据行，确认重建任务只覆盖已完成索引的数据。
- 核对许可证、核验表、整改报告的字段、日期与签字，确认同一记录的名称、数量、日期在三份材料间一致，缺签字或回执的条目单独标记。
