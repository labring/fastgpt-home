# 技工院校学制教育管理的材料核对与差异定位：上下文 token

## 这个品类的数据长什么样

技工院校学制教育管理涉及学籍注册表、教学计划、技能训练记录三类材料。学籍注册表记录学生身份、注册日期与学籍状态，通常按学期初集中更新；教学计划规定课程名称、课时数量与实施日期，随专业方案调整而改版；技能训练记录登记训练项目、完成数量与指导教师签字，按周或按模块滚动录入。三类材料进入材料核对与差异定位功能时，学籍注册表作为学籍基准，教学计划作为课程与课时基准，技能训练记录作为过程与签字基准。同一学生在三份材料中的姓名、学号、课程名称、课时数量、训练日期、签字与回执状态需要逐项比对。字段特征包括文本型名称、数值型数量、日期型节点与签字回执状态，更新节奏不同导致版本容易错位，需要按对象与字段建立差异清单。

## 配置怎么定

这一环由应用设置（回复上限等）执行，输出单次回答长度与可容纳的上下文范围。差异清单由模型接着完成，入口与授权由发布服务与文件权限负责。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 学籍注册表 | 学生姓名、学号、注册日期与学籍状态在两份材料中一致，签字与回执齐全 | 对照教学计划与技能训练记录，逐字段核对姓名、学号、日期，记录不一致项 |
| 教学计划 | 课程名称、课时数量、实施日期与版本号在两份材料中一致，缺签字或回执需标注 | 对照学籍注册表与技能训练记录，核对课程名称、数量、日期，检查版本是否同步 |
| 技能训练记录 | 训练项目、完成数量、训练日期与指导教师签字在两份材料中一致 | 对照教学计划与学籍注册表，核对项目名称、数量、日期与签字回执，定位差异字段 |
| 回复上限 | 与页面要求的回答长度匹配，在应用设置里核对开关与滑块位置 | 检查单次回答长度与可容纳的上下文范围，确认 `maxResponse` 与 `maxContext` 的滑块位置，记录 `quoteMaxToken` 的引用内容预算 |

## 容易做错的三处

- 现象：同一学生在学籍注册表与技能训练记录里的姓名或学号对不上。原因：两份材料录入时间不同，未做版本同步与字段级比对。
- 现象：教学计划中的课时数量与技能训练记录里的完成数量不一致。原因：计划改版后未回写台账，旧版本仍被引用。
- 现象：技能训练记录缺指导教师签字或回执。原因：过程材料未按节点收齐，核对时只看了名称与日期，漏检签字状态。

## 怎么确认配好了

本功能验收：提一个需要长回答的问题，看结尾是否完整，确认单次回答长度与可容纳的上下文范围符合页面要求。

业务测试：用一条真实记录找出与台账不一致的字段，形成差异清单并交复核人确认后回写。

- 在应用设置里核对回复上限开关与滑块位置，确认 `maxResponse` 与 `maxContext` 的取值与页面要求的回答长度匹配。
- 对同一学生的学籍注册表、教学计划与技能训练记录逐字段比对名称、数量、日期与签字回执，将不一致项写入差异清单并标注版本。
