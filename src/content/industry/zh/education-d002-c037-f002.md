# 职业培训补贴申领的材料核对与差异定位：上下文与 token

## 这个品类的数据长什么样

本页聚焦职业培训补贴申领中的三类材料：培训开班备案、签到记录、结业考核表。开班备案由培训机构在开班前提交，含课程名称、学员名单、课时与负责人签字，更新节奏为开班前一次报备、变更时补交。签到记录按日产生，含学员姓名、日期、签到状态与带班人确认，每日或每期汇总。结业考核表在考核后形成，含学员姓名、考核科目、成绩、日期与考评员签字。三类材料进入本功能时，备案作为基准源，签到与考核表作为比对源，逐字段核对同一学员的名称、数量、日期与签字是否一致，定位差异后生成差异清单，交复核人确认并回写台账。

## 配置怎么定

这一环由应用设置（回复上限等）执行，输出单次回答长度与可容纳的上下文范围。差异清单由模型接着完成。回复上限用滑块控制单次回答的长度，设置过低回答会被截断，设置过高会增加消耗。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 培训开班备案 | 与签到记录、结业考核表比对学员姓名、课程名称、日期与负责人签字是否一致 | 在应用设置里核对回复上限开关与滑块位置，确认 `maxResponse` 与 `maxContext` 的取值；再逐字段比对备案与签到、考核表的名称、数量、日期 |
| 签到记录 | 与开班备案、结业考核表比对同一学员的签到日期、数量与带班人确认签字是否一致 | 提一个需要长回答的问题看结尾是否完整，确认回答未被截断；再核对签到日期与备案课程日期是否落在同一区间 |
| 结业考核表 | 与开班备案、签到记录比对学员姓名、考核科目、成绩、日期与考评员签字是否一致 | 对比两次运行的用量，观察回复上限调整后单次用量变化；再核对考核表签字与回执是否齐全 |
| 差异清单 | 同一对象在两份材料里的名称、数量、日期一致，且签字与回执齐全 | 记录引用文本的 tokens 与数组条数，`quoteMaxToken` 单独核对；将差异字段交复核人确认并回写 |

## 容易做错的三处

- 现象：同一学员在签到记录与结业考核表里的姓名或日期对不上。原因：两份材料分别录入，未以开班备案为基准逐字段核对。
- 现象：开班备案已更新，签到记录仍沿用旧版学员名单。原因：版本未同步，变更后未重新比对名称与数量。
- 现象：结业考核表缺考评员签字或回执。原因：签字与回执未纳入核对项，仅核对了成绩与日期。

## 怎么确认配好了

本功能验收：提一个需要长回答的问题，看结尾是否完整，确认回复上限未导致回答在句子中间断开。

业务测试：用一条真实记录找出与台账不一致的字段，核对该学员在开班备案、签到记录、结业考核表中的名称、数量、日期与签字。

- 在应用设置里核对回复上限开关与滑块位置，确认 `maxResponse` 与 `maxContext` 的取值与页面要求的回答长度匹配。
- 记录引用文本的 tokens 与数组条数，`quoteMaxToken` 单独核对，不将数组条数与引用预算做相等比较。
