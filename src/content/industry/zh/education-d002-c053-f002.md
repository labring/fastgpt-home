# 高校招生体检组织的材料核对与差异定位：上下文与 token

## 这个品类的数据长什么样

高校招生体检组织在招生季集中处理三类材料：体检表、复检申请、受限专业告知。体检表来自各体检站，按批次汇总，字段含姓名、考生号、体检结论、受限代码、日期与医师签字；复检申请由考生或中学提交，字段含申请事由、原检日期、复检项目与回执；受限专业告知由招生办依结论生成，字段含专业名称、受限依据、告知日期与考生签收。三类材料更新节奏不同：体检表随批次滚动，复检申请随个案即时进入，告知书按录取节点批量回写。材料进入核对功能时，体检表作为基准台账，复检申请与告知书作为待核对象，各自提供名称、数量、日期与签字字段，供逐项比对与差异定位。

## 配置怎么定

这一环由应用设置（回复上限等）执行，输出单次回答长度与可容纳的上下文范围。「差异清单」由模型接着完成。回复上限用滑块控制单次回答的长度，设置过低回答会被截断，设置过高会增加消耗；上下文范围由 `maxContext` 与 `maxResponse` 共同界定，引用内容预算由 `quoteMaxToken` 单独控制。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 体检表 | 同一记录在体检表与复检申请里的名称、数量、日期一致 | 核对姓名、考生号、体检结论、受限代码、日期与医师签字，逐字段比对 |
| 复检申请 | 申请事由、原检日期、复检项目与回执齐全，版本与台账同步 | 核对申请事由、原检日期、复检项目与回执，检查缺签字或回执 |
| 受限专业告知 | 专业名称、受限依据、告知日期与考生签收与结论一致 | 核对专业名称、受限依据、告知日期与签收，确认版本未同步项 |
| 上下文与 token | 单次回答长度与可容纳的上下文范围匹配页面要求 | 在应用设置里核对回复上限开关与滑块位置，记录 `maxContext`、`quoteMaxToken`、`maxResponse` |

## 容易做错的三处

- 现象：同一考生在体检表与复检申请里的姓名或考生号对不上。原因：录入时未按台账字段回填，差异未被定位。
- 现象：受限专业告知的专业名称与体检结论版本未同步。原因：告知书按旧结论批量生成，未随复检结果回写。
- 现象：复检申请缺签字或回执，告知书缺考生签收。原因：材料流转节点未收齐回执，核对时未标记缺失项。

## 怎么确认配好了

本功能验收：提一个需要长回答的问题，看结尾是否完整，确认回复上限与 `maxResponse` 匹配页面要求，回答不在句子中间断开。

业务测试：用一条真实记录找出与台账不一致的字段，写入差异清单并交复核人确认后回写。

- 在应用设置里核对回复上限开关与滑块位置，对比两次运行的用量变化
- 核对引用文本的 tokens 与 `quoteMaxToken`，数组条数单独记录，不与预算做相等比较
