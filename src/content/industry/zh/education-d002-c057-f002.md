# 国家重点研发计划项目申报的材料核对与差异定位：上下文 tok

## 这个品类的数据长什么样

国家重点研发计划项目申报涉及项目申报书、预算申报书、合作协议三类材料。项目申报书由牵头单位撰写，含项目名称、课题分解、考核指标与实施周期；预算申报书由财务与课题负责人共同编制，含科目金额、测算依据、配套资金与年度拨付计划；合作协议由多家参与单位签署，含任务分工、经费分配、知识产权归属与签字盖章页。三类材料按申报指南批次更新，常见版本并行与补签回执。材料进入本功能时，项目申报书与预算申报书作为主比对源，合作协议作为交叉校验源，字段以名称、数量、日期、签字为锚点，逐条对齐。

## 配置怎么定

这一环由应用设置（回复上限等）执行，输出单次回答长度与可容纳的上下文范围。「差异清单」由模型接着完成。回复上限用滑块控制单次回答的长度，设置过低回答会被截断，设置过高会增加消耗。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 项目申报书 | 项目名称、课题数量、实施周期起止日期与合作协议一致 | 逐项核对名称、数量、日期，标记不一致字段并记录行号 |
| 预算申报书 | 科目金额、配套资金、年度拨付日期与项目申报书对应 | 对照预算科目与项目周期，列出金额或日期差异项 |
| 合作协议 | 参与单位名称、任务分工、签字盖章与回执齐全 | 检查签字页与回执，缺失项单独列出 |
| 上下文与 token | 单次回答长度与可容纳的上下文范围匹配页面要求 | 在应用设置里核对 `maxResponse` 与 `maxContext`，引用预算看 `quoteMaxToken` |

## 容易做错的三处

- 现象：同一课题在两份材料里名称或数量对不上。原因：版本未同步，一方沿用旧稿，字段未随最新申报书更新。
- 现象：预算科目金额与项目申报书日期不一致。原因：编制与复核分属不同环节，修改后未回写台账。
- 现象：合作协议缺签字或回执。原因：参与单位签署流程未闭环，扫描件与原件未对齐。

## 怎么确认配好了

本功能验收：提一个需要长回答的问题，看结尾是否完整，确认 `maxResponse` 与 `maxContext` 设置合适。

业务测试：用一条真实记录找出与台账不一致的字段，形成差异清单交复核人确认并回写。

- 在应用设置里核对回复上限滑块位置，确认与页面要求的回答长度匹配。
- 对比两次运行的用量，确认上限调整后单次用量变化在预期内。
