# 国家重点研发计划项目申报的材料核对与差异定位：文档解析与分块

## 这个品类的数据长什么样

国家重点研发计划项目申报涉及项目申报书、预算申报书、合作协议三类材料，分别由牵头单位、参与单位与财务部门提供，随申报节点分批上传，版本更迭频繁。项目申报书含项目名称、课题设置、参与人员、起止日期与签章页；预算申报书含科目金额、资金来源、拨付计划与签字栏；合作协议含合作方名称、任务分工、经费分配、签署日期与回执。三类材料进入解析与训练任务后，各自成为独立数据行，共同支撑后续检索比对。字段特征表现为同一记录在多份材料中重复出现，名称、数量、日期与签字状态需逐项对齐。材料来源分散、更新节奏不一，版本未同步与缺签字或回执是主要差异来源。

## 配置怎么定

这一环由解析与训练任务（服务端任务）执行，输出数据行与索引状态（已解析、索引中、已完成）。「差异清单」由检索与后续处理接着完成。解析分块在解析完成后立即落库为可见数据行并绑定唯一数据标识，索引按三态流转，待索引数据不参与召回。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 项目申报书 | 名称、数量、日期与签字栏在三份材料中逐项对齐 | 按字段核对项目名称、课题数量、起止日期与签章页，确认数据行状态为 parsed / indexing / indexed，核对 `chunkSize` 与 `chunkSplitter` 的分块结果 |
| 预算申报书 | 科目金额、资金来源、拨付计划与签字栏与项目申报书、合作协议一致 | 对照预算科目与合作协议经费分配，核对日期与签字栏，确认数据行状态与界面显示一致，核对 `trainingType` 对应处理模式 |
| 合作协议 | 合作方名称、任务分工、经费分配、签署日期与回执齐全 | 分别核对文件记录与数据行的身份标识，确认合作方名称与数量在两份材料中一致，检查回执是否缺失 |
| 数据行状态 | 处于三态之一且与界面显示一致 | 打开数据行核对状态，确认待索引数据不参与召回，换模型只对已完成索引的数据重建 |

## 容易做错的三处

- 现象：同一项目名称在项目申报书与合作协议中写法不同，数量与日期对不上。原因：材料由不同单位提供，版本未同步，解析后未逐字段比对。
- 现象：预算申报书科目金额与合作协议经费分配不一致，拨付计划日期错位。原因：两份材料更新节奏不同，旧版本仍处于索引中状态被误用。
- 现象：合作协议缺签字或回执，数据行仍显示已完成索引。原因：签字栏未纳入字段核对，解析成功不等于检索命中，索引状态未复核。

## 怎么确认配好了

本功能验收：上传一份材料，看数据行状态流转与重建任务的覆盖范围，确认 parsed / indexing / indexed 三态与界面显示一致，重建只覆盖已完成索引的数据。

业务测试：用一条真实记录找出与台账不一致的字段，分别核对文件记录与数据行的身份标识，记录不一致字段并交复核人确认回写。

- 打开数据行核对状态，确认处于 parsed / indexing / indexed 之一，待索引数据不参与召回。
- 分别核对文件记录与数据行的身份标识，检查重建任务覆盖的数据行是否只含已完成索引的数据。
