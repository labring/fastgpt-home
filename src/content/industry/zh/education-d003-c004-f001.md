# 幼儿园家园共育沟通的问答受理与缺项补问：HTTP 接口

## 这个品类的数据长什么样

幼儿园家园共育沟通的问答受理与缺项补问，材料来自家长提交的问句、班级通知与幼儿观察记录。家长问句先进入受理环节，用于识别诉求分类与关键信息是否齐全；班级通知用于核对承诺事项与回应时间；幼儿观察记录用于比对家长表述是否与日常表现一致。材料更新节奏随每日沟通与周记录滚动，字段特征集中在承诺事项、回应时间、幼儿表现描述、家长诉求分类、通知送达五类。进入 HTTP 接口与外部系统时，家长问句是触发受理的输入，通知与观察记录是补问与依据判断的参照，各自承担不同角色。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「受理记录与补齐的问项」由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 模块向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 家长问句 | 诉求分类与关键信息是否齐全，缺项能否被识别并追问 | 在请求预览里看渲染后的完整地址，核对请求体字段与外部接口约定一致，用一条样例请求比对返回 |
| 班级通知 | 承诺事项与回应时间是否被回应，通知送达是否可追溯 | 核对请求头名称与取值来源，确认鉴权信息按外部系统要求传入，检查占位变量能否解析成实际值 |
| 幼儿观察记录 | 幼儿表现描述与家长表述是否一致，反馈是否归类 | 在变量面板核对每个占位的来源，确认 `variables` 与 `responseData` 能追到具体出处，用样例比对返回字段 |
| 外部系统返回 | 状态码与返回字段是否支持后续解析与转承办人处理 | 核对 `Authorization` 传入方式，检查返回字段是否含受理记录与补齐问项所需内容 |

## 容易做错的三处

- 现象：家长问句缺关键信息却直接作答。原因：受理环节未先识别缺项并追问，承诺事项与回应时间未进入判断。
- 现象：家长表述与幼儿观察记录不符。原因：补问时未调取观察记录比对，幼儿表现描述字段未作为依据。
- 现象：反馈未归类导致转承办人处理混乱。原因：家长诉求分类与通知送达字段未在返回中区分，后续节点难以解析。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果。

业务测试：提一个缺关键信息的问句，看是否先追问再作答。

- 核对请求地址与路径参数，确认占位变量能解析成实际值。
- 核对请求头与请求体，确认字段与外部接口约定一致且变量来源可追。
