# 义务教育控辍保学的问答受理与缺项补问：HTTP 接口

## 这个品类的数据长什么样

本页面向义务教育控辍保学场景，材料来自辍学风险台账、劝返记录、家访记录三类。台账提供学生基础信息与风险等级，劝返记录承载每次劝返的日期、参与人与结果，家访记录补充家庭情况与签字回执。三者进入问答受理与缺项补问功能时角色不同：台账是主索引，劝返记录与家访记录作为佐证材料被检索引用。字段特征集中在姓名、学籍号、日期、劝返次数、签字与回执状态。更新节奏按周或按事件触发，新记录进入后需与既有版本对齐。材料进入该功能后，先被解析成可检索片段，再由 HTTP 节点向外部系统发请求，把受理记录与补齐的问项交给后续节点或外部系统处理。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「受理记录与补齐的问项」由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点只负责发请求与取回结果，不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 辍学风险台账 | 字段含姓名、学籍号、风险等级、日期与签字，同一记录在两份材料里的名称与日期需一致 | 在变量面板核对每个占位的来源，比对台账与劝返记录的名称、数量、日期 |
| 劝返记录 | 劝返次数、日期、参与人与回执状态需与台账对齐，版本未同步时以最新签字版本为准 | 用一条样例请求比对返回，核对请求体字段与外部接口约定是否一致 |
| 家访记录 | 家访日期、签字与回执缺项会被识别为待补问项 | 核对请求头名称与取值来源，确认鉴权信息按外部系统要求传入 |
| HTTP 请求预览 | 请求地址与路径参数中的占位变量能解析成实际值 | 在请求预览里看渲染后的完整地址，确认 `variables` 与 `responseData` 字段可追溯 |

## 容易做错的三处

- 现象：同一学生在台账与劝返记录里的姓名或日期对不上。原因：两份材料分别录入，未做名称与日期一致性核对，版本未同步。
- 现象：家访记录缺签字或回执，仍被当作完整材料引用。原因：缺项未被识别为待补问项，受理记录未触发追问。
- 现象：请求返回 401 或外部系统收到空字段。原因：`Authorization` 取值来源未核对，请求体字段与外部接口约定不一致。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；确认 `Authorization`、`variables`、`responseData` 均可追溯。

业务测试：提一个缺关键信息的问句，看是否先追问再作答。

- 在变量面板核对每个占位的来源，确认请求地址、请求头与请求体三处变量都能解析成实际值。
- 用一条样例请求比对返回，核对请求体字段与外部接口约定是否一致，并记录数组条数与引用文本的 tokens。
