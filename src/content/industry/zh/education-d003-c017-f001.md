# 本科专业设置与动态调整的问答受理与缺项补问：HTTP 接口

## 这个品类的数据长什么样

本科专业设置与动态调整的受理材料，包括专业设置申请表、人才培养方案、专家论证意见三类。申请表来自教务处受理窗口，按学年申报批次更新；培养方案由学院随培养周期滚动修订；论证意见由专家组会议后补录。三类材料进入该功能时角色不同：申请表提供拟设专业名称、代码、学位授予门类与负责人签字；培养方案提供课程结构、学分学时与开课学期；论证意见提供专家名单、论证日期与签字。字段特征集中在名称、数量、日期与签字四类，同一记录在三份材料里需逐项对齐，版本同步与回执留存是受理与补齐问项的基础。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。受理记录与补齐的问项由后续节点解析响应，或外部系统按约定处理接着完成。请求地址与路径参数、请求头、请求体三处均可用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 专业设置申请表 | 名称、数量、日期与签字是否与培养方案、论证意见逐项对齐 | 在请求预览里核对渲染后的完整地址与请求体字段，比对申请表与培养方案的专业名称、专业代码、学位授予门类，核负责人签字与日期 |
| 人才培养方案 | 课程结构、学分学时与开课学期是否与申请表、论证意见一致 | 核对请求头名称与取值来源，比对培养方案与论证意见的课程门数、总学分与论证日期，检查版本号是否同步 |
| 专家论证意见 | 专家名单、论证日期与签字是否齐全且与申请表对应 | 在变量面板核对每个占位的来源，检查论证意见的专家人数、签字与回执，确认与申请表记录无名称或日期冲突 |
| 受理记录与补齐问项 | 缺项是否被识别并追问，回答是否有材料依据 | 用一条样例请求比对返回，核 `responseData` 字段是否含缺项清单与追问项，核 `variables` 与 `Authorization` 的取值来源 |

## 容易做错的三处

- 现象：同一专业在申请表与培养方案里的名称或代码对不上。原因：两份材料由不同经办人分别填报，未做逐字段比对与回执确认。
- 现象：培养方案版本未同步，论证意见仍引用旧版课程结构。原因：修订后未更新版本号，受理时未核版本与日期。
- 现象：专家论证意见缺签字或回执，受理记录仍显示已收。原因：扫描件与纸质件混用，签字页未逐项核验。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；核 `responseData` 是否含缺项与追问项，核 `variables` 与 `Authorization` 来源。

业务测试：提一个缺关键信息的问句，看是否先追问再作答。

- 在请求预览里核对渲染后的完整地址与请求体字段，确认占位变量解析成实际值。
- 在变量面板核对每个占位的来源，确认 `variables` 与 `Authorization` 可追溯。
