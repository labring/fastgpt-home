# 研究生招生复试录取的问答受理与缺项补问：HTTP 接口

## 这个品类的数据长什么样

本页面向研究生招生复试录取品类，聚合复试方案、考生成绩表、调剂名单三类材料。复试方案来自招生单位发布，随批次调整更新，字段含专业方向、复试比例、时间地点、签字栏；考生成绩表由初试与复试评分汇总，字段含考生编号、科目成绩、总分、排名、日期与审核签字；调剂名单由调剂系统导出，字段含调剂志愿、初试成绩、拟录取状态与回执。三类材料进入问答受理与缺项补问功能时，复试方案充当规则依据，考生成绩表与调剂名单充当个案事实来源；受理记录与补齐的问项由后续节点解析响应或外部系统按约定处理完成。材料常见名称、数量、日期对不上，版本未同步，缺签字或回执，需在受理环节先识别缺项再追问。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。受理记录与补齐的问项由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 复试方案 | 方案中的专业方向、复试比例、时间地点与签字栏是否与受理问项对应 | 核对方案版本日期与签字栏，把方案字段映射到问项清单，检查名称与数量是否与成绩表一致 |
| 考生成绩表 | 考生编号、科目成绩、总分、排名、日期与审核签字是否齐全 | 逐条比对成绩表与调剂名单中的同名考生，核日期与签字，缺项写入待补问项 |
| 调剂名单 | 调剂志愿、初试成绩、拟录取状态与回执是否与成绩表对得上 | 核对名单版本与回执，检查同一记录在两份材料里的名称、数量、日期是否一致 |
| HTTP 节点请求 | 请求地址与路径参数、请求头、请求体中的占位变量能否解析成实际值 | 在请求预览里看渲染后的完整地址，核对 `Authorization` 请求头与 `variables` 来源，用样例请求比对 `responseData` 返回字段 |

## 容易做错的三处

- 现象：同一考生在成绩表与调剂名单里的名称、数量、日期对不上。原因：两份材料分别录入，未做交叉核对，受理时直接引用单侧数据。
- 现象：复试方案版本未同步，问项依据旧版比例与时间。原因：方案更新后未重新导入，受理记录仍引用旧版本字段。
- 现象：成绩表或调剂名单缺签字、缺回执，受理后无法转承办人。原因：材料流转环节未收齐签字，缺项未被识别并追问。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；确认 `Authorization`、`variables`、`responseData` 三处取值与外部接口约定一致。

业务测试：提一个缺关键信息的问句，看是否先追问再作答。

- 在请求预览里核对渲染后的完整地址、请求头名称与取值来源，确认每个占位变量都能追到全局变量、系统变量或前方节点输出。
- 用一条样例请求比对返回，检查请求体字段与外部接口约定一致，缺项被识别并追问后再转承办人处理。
