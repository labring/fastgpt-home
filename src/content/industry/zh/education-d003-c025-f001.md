# 研究生培养过程管理的问答受理与缺项补问：HTTP 接口

## 这个品类的数据长什么样

研究生培养过程管理以培养计划、开题报告、中期考核表为核心材料。培养计划记录课程学分与培养环节安排，开题报告记录选题、导师意见与开题日期，中期考核表记录阶段性成果、考核结论与签字。三类材料进入问答受理与缺项补问功能时角色不同：培养计划用于比对课程与环节是否齐全，开题报告用于核对选题与日期，中期考核表用于确认考核结论与签字。材料随学期推进分批提交，更新节奏与培养环节节点同步。字段特征集中在名称、数量、日期与签字四类，同一记录在不同材料里可能出现名称、数量、日期对不上，版本未同步，或缺签字与回执。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「受理记录与补齐的问项」由后续节点解析响应，或外部系统按约定处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 培养计划 | 课程名称、学分数量与培养环节日期是否与开题报告、中期考核表一致 | 在请求预览里核对渲染后的地址与请求体字段，用一条样例请求比对返回，确认名称与数量对得上 |
| 开题报告 | 选题名称、开题日期与导师签字是否齐全，是否与中期考核表版本同步 | 核对请求头 `Authorization` 与变量来源，检查返回字段里日期与签字字段是否为空 |
| 中期考核表 | 考核结论、考核日期与签字回执是否完整，是否与培养计划版本同步 | 在变量面板核对每个占位的出处，确认 `variables` 与 `responseData` 能追到具体来源 |
| HTTP 接口与外部系统 | 请求地址、路径参数与请求体字段是否与外部接口约定一致 | 在请求预览里看渲染后的完整地址，用一条样例请求比对返回字段与状态码 |

## 容易做错的三处

- 现象：同一课程名称在培养计划与中期考核表里对不上。原因：两份材料分别提交，名称未按同一口径填写，版本未同步。
- 现象：开题日期与中期考核日期在同一记录里数量或日期对不上。原因：材料分批录入，日期字段未回填，签字或回执缺失。
- 现象：请求返回 401 或外部系统收到空字段。原因：`Authorization` 取值来源有误，或占位变量未解析成实际值。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `variables` 与 `responseData` 能追到具体出处。

业务测试：提一个缺关键信息的问句，看是否先追问再作答。

- 在请求预览里核对渲染后的完整地址、请求头名称与取值来源，确认 `Authorization` 按外部系统要求传入。
- 在变量面板核对每个占位的来源，用一条样例请求比对返回字段，确认 `variables` 与 `responseData` 与外部接口约定一致。
