# 职业院校专业设置备案的问答受理与缺项补问：HTTP 接口

## 这个品类的数据长什么样

职业院校专业设置备案的问答受理与缺项补问，材料来源为专业设置备案表、人才需求论证、师资设备清单。三类材料进入功能时角色不同：备案表提供专业名称与签字栏，论证材料提供行业需求与日期，师资设备清单提供数量与规格。更新节奏按年度备案与补充材料滚动，字段特征集中在名称、数量、日期与签字四类。同一记录在两份材料里名称、数量、日期对不上时，先追问再作答。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。受理记录与补齐的问项由后续节点解析响应，或外部系统按约定处理接着完成。请求地址、请求头与请求体三处均可用变量占位。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 专业设置备案表 | 名称、日期与签字栏须与论证材料一致 | 核对备案表专业名称与签字日期，比对论证材料对应字段 |
| 人才需求论证 | 行业需求日期与备案表申报日期不得冲突 | 抽取论证日期与备案表日期，逐条比对并记录差异 |
| 师资设备清单 | 数量与规格须与备案表描述对得上 | 核对清单数量与备案表数量，检查版本号与回执 |
| HTTP 请求与响应 | 占位变量能解析成实际值，返回字段与约定一致 | 在请求预览里看渲染后的完整地址，用 `Authorization` 核对请求头，用 `variables` 核对变量来源，用 `responseData` 核对返回字段 |

## 容易做错的三处

- 现象：同一记录在备案表与论证材料里名称、日期对不上。原因：两份材料分别填写，版本未同步，缺回执。
- 现象：师资设备清单数量与备案表数量不一致。原因：清单更新后未回写备案表，签字栏空白。
- 现象：请求返回 401 或外部系统收到空字段。原因：请求头鉴权信息未按外部系统要求传入，变量来源未核对。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；用 `Authorization` 核对请求头，用 `variables` 核对变量来源，用 `responseData` 核对返回字段。

业务测试：提一个缺关键信息的问句，看是否先追问再作答。

- 在变量面板核对每个占位的来源，确认能追到全局变量、系统变量或前方节点输出。
- 用一条样例请求比对返回，检查请求体字段与外部接口约定是否一致。
