# 职业技能等级认定社会评价的问答受理与缺项补问：HTTP 接口

## 这个品类的数据长什么样

本页面向职业技能等级认定社会评价的问答受理与缺项补问，材料来自评价实施方案、考生报名表、考评员派遣表三类。评价实施方案给出认定职业、等级与流程框架；考生报名表承载考生身份、申报条件与联系方式；考评员派遣表记录考评人员、日期与签字回执。三类材料进入功能时，各自角色不同：实施方案作为判定依据，报名表与派遣表作为待核对象，用于识别缺项并生成追问。材料随批次更新，字段特征集中在名称、数量、日期与签字栏，同一记录在两份材料间常出现名称、数量、日期对不上，或版本未同步、缺签字与回执。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。受理记录与补齐的问项由后续节点解析响应，或外部系统按约定处理接着完成。路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 评价实施方案 | 字段、日期与签字是否与报名表、派遣表一致 | 逐项比对职业名称、等级、认定日期与签批栏，记录差异位置 |
| 考生报名表 | 名称、数量、日期能否与实施方案、派遣表对齐 | 抽取考生姓名、申报等级、报名日期，与另两份材料交叉核对 |
| 考评员派遣表 | 签字与回执是否齐全，版本是否同步 | 检查考评员姓名、派遣日期、签字栏与回执，标注缺失项 |
| HTTP 请求 | 路径参数、请求头与请求体占位能否解析为实际值 | 在请求预览看渲染后的完整地址，核对 `Authorization` 与 `variables` 来源 |

## 容易做错的三处

- 现象：同一考生在两份材料里的名称或申报等级对不上。原因：报名表与实施方案未同步，字段口径不一致。
- 现象：考评员派遣表缺签字或回执，追问后仍无法补齐。原因：材料流转环节未回传，版本未同步。
- 现象：请求返回 401 或外部系统收到空字段。原因：`Authorization` 取值来源错误，或请求体字段与外部接口约定不一致。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对 `responseData` 结果。

业务测试：提一个缺关键信息的问句，看是否先追问再作答。

- 在变量面板核对每个占位的来源，确认路径参数、请求头与请求体都能追到全局变量、系统变量或前方节点输出。
- 用一条样例请求比对返回字段与外部接口约定，检查 `Authorization`、`variables` 与 `responseData` 是否一致。
