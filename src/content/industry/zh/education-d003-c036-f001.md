# 专业技术人员职业资格考试报名审核的问答受理与缺项补问：HTT

## 这个品类的数据长什么样

专业技术人员职业资格考试报名审核，材料通常包括报名表、学历证明与工作年限证明。报名表承载身份、报考科目与单位意见；学历证明用于核对毕业院校、专业与证书编号；工作年限证明用于核对起止日期、岗位与签字。三类材料进入问答受理与缺项补问功能时，分别承担身份锚点、资格锚点与经历锚点。材料来源多为申报人上传的扫描件或外部系统回传的结构化字段，更新节奏随报名批次与补正通知变化。字段特征集中在名称、数量、日期与签字：同一记录在两份材料里的名称、数量、日期对不上，版本未同步，缺签字或回执，都会使缺项识别与追问失去依据。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「受理记录与补齐的问项」由后续节点解析响应，或外部系统按约定处理接着完成。请求地址、路径参数、请求头与请求体三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 报名表 | 身份、报考科目与单位意见字段齐全，日期与签字可核 | 逐项比对报名表上的名称、数量、日期与签字，定位缺项 |
| 学历证明 | 毕业院校、专业与证书编号同报名表一致 | 把学历证明的编号与日期同报名表交叉核对，标记不一致 |
| 工作年限证明 | 起止日期、岗位与签字回执完整 | 核对工作年限证明的日期区间与签字，识别缺签字或回执 |
| HTTP 请求 | `variables` 占位能解析，`Authorization` 按外部系统要求传入 | 在请求预览里看渲染后的完整地址，用样例比对 `responseData` 返回字段 |

## 容易做错的三处

- 现象：同一记录在两份材料里的名称、数量、日期对不上，追问指向不明。原因：报名表与学历证明、工作年限证明未做交叉核对，缺项识别只按单份材料判断。
- 现象：材料版本未同步，补正后的回执仍被当作旧版处理。原因：外部系统回传与上传件未按批次标记版本，受理记录引用了过期字段。
- 现象：缺签字或回执未被追问，直接进入承办环节。原因：缺项补问规则未覆盖签字与回执字段，HTTP 节点返回的字段未被后续节点逐项解析。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `variables` 占位解析、`Authorization` 传入与 `responseData` 字段一致。

业务测试：提一个缺关键信息的问句，看是否先追问再作答，并确认追问指向报名表、学历证明或工作年限证明的具体缺项。

- 在变量面板核对每个占位的来源，确认来自全局变量、系统变量或前方节点输出。
- 用一条样例请求比对返回，核对请求体字段与外部接口约定一致，并记录数组条数与引用文本 tokens。
