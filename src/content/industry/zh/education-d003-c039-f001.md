# 考务组织与违纪处理的问答受理与缺项补问：HTTP 接口

## 这个品类的数据长什么样

考务组织与违纪处理的材料以考务手册、考场记录单、违纪事实记录为主。考务手册提供流程与字段口径，考场记录单承载当场时间、座位与监考签字，违纪事实记录承载行为描述、证据与承办签字。材料来自考务部门与考点回传，按场次更新，遇补录或更正再同步版本。进入问答受理与缺项补问功能时，考场记录单用于核对日期与签字，违纪事实记录用于核对名称、数量与回执，考务手册用于判定问项是否属于受理范围。三类材料在字段、日期与签字上互为参照，缺一即触发追问。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「受理记录与补齐的问项」由后续节点解析响应，或外部系统按约定处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 考务手册 | 字段口径与日期规则是否与问项一致 | 对照手册章节核对问项字段名、日期格式与签字要求 |
| 考场记录单 | 名称、数量、日期与签字是否与违纪事实记录对得上 | 逐项比对两份材料的名称、数量、日期，并检查监考签字与回执 |
| 违纪事实记录 | 版本是否同步、承办签字是否齐全 | 核对记录版本号与承办签字，缺项记入待补问项 |
| HTTP 节点 | 占位变量能否解析为实际值 | 在请求预览核对渲染后的完整地址，并核对 `Authorization` 请求头与 `variables` 来源 |

## 容易做错的三处

- 现象：同一记录在考场记录单与违纪事实记录里的名称、数量对不上。原因：两份材料分别录入，未做字段级比对。
- 现象：考务手册版本未同步，问项按旧口径受理。原因：手册更新后未回传至受理环节。
- 现象：违纪事实记录缺承办签字或回执。原因：材料回传时未附签字页，受理时未识别。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；同时核对 `responseData` 中的返回字段与 `variables` 来源。

业务测试：提一个缺关键信息的问句，看是否先追问再作答。

- 在变量面板核对每个占位的来源，确认 `Authorization` 与 `variables` 取值可追溯。
- 用一条样例请求比对返回字段，检查外部系统是否收到空字段或返回 401。
