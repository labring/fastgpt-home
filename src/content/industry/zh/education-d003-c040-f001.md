# 企业新员工入职培训的问答受理与缺项补问：HTTP 接口

## 这个品类的数据长什么样

企业新员工入职培训涉及三类核心材料：入职培训计划、课程签到表、岗位说明书。入职培训计划通常包含培训批次、课程名称、起止日期、讲师与场地等字段，来源为培训部门按季度或月度发布，更新节奏随课程调整而变。课程签到表由现场或线上签到系统生成，含学员姓名、工号、课程名称、签到日期与本人签字或电子回执。岗位说明书由用人部门与人力资源共同维护，含岗位名称、所属部门、职责条目、任职要求与双方签字。三类材料进入问答受理与缺项补问功能时角色不同：培训计划作为受理问句的参照基准，签到表用于判定学员是否完成课程，岗位说明书用于核对岗位与培训内容的对应关系。字段特征上，日期格式、姓名写法、课程简称与全称、签字有无常存在差异，需在受理环节先识别缺项再追问。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。受理记录与补齐的问项由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 模块向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 入职培训计划 | 培训批次、课程名称、起止日期、讲师与场地字段是否齐全，日期格式是否统一 | 在请求预览里看渲染后的完整地址，核对计划字段与外部接口约定是否一致 |
| 课程签到表 | 学员姓名、工号、课程名称、签到日期与签字或电子回执是否完整，同一记录在两份材料里的名称与日期是否对得上 | 核对请求头名称与取值来源，用一条样例请求比对返回的签到字段 |
| 岗位说明书 | 岗位名称、所属部门、职责条目、任职要求与双方签字是否具备，版本是否与培训计划同步 | 在变量面板核对每个占位的来源，确认岗位字段能追到具体出处 |
| HTTP 节点配置 | 请求地址与路径参数中的占位变量能解析成实际值，请求头鉴权信息按外部系统要求传入 | 在请求预览里看渲染后的完整地址，核对 `Authorization` 与 `variables` 的取值来源 |

## 容易做错的三处

- 现象：同一学员的课程名称在培训计划与签到表里写法不同。原因：两份材料由不同部门维护，简称与全称未统一，版本未同步。
- 现象：岗位说明书缺双方签字或回执，培训计划日期与签到日期对不上。原因：材料流转环节未收齐签字，日期录入时未按统一格式。
- 现象：请求返回 401 或外部系统收到空字段。原因：请求头鉴权信息未按外部系统要求传入，或请求体字段与接口约定不一致。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；同时核对 `responseData` 中的字段名与外部接口约定是否一致。

业务测试：提一个缺关键信息的问句，看是否先追问再作答。

- 在变量面板核对每个占位的来源，确认能追到全局变量、系统变量或前方节点输出。
- 用一条样例请求比对返回，核对请求头名称与取值来源，确认鉴权信息按外部系统要求传入。
