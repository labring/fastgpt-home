# 企业合规与安全培训的问答受理与缺项补问：HTTP 接口

## 这个品类的数据长什么样

本页面向企业合规与安全培训的问答受理与缺项补问场景，材料包括合规培训课件、安全操作规程、考试记录三类。课件用于确认课程名称、版本日期与适用岗位；规程用于核对操作步骤、生效日期与签字栏；考试记录用于比对人员名单、成绩、日期与回执。材料按批次更新，常见字段有材料名称、数量、日期、版本号、签字与回执。进入该功能时，课件与规程作为追问依据，考试记录作为缺项判定来源，三者共同支撑受理记录与补齐的问项。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「受理记录与补齐的问项」由后续节点解析响应，或外部系统按约定处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 合规培训课件 | 课件名称、版本日期与适用岗位在受理问项中可追溯 | 核对课件字段与日期，比对两份材料里的名称与版本是否一致 |
| 安全操作规程 | 规程步骤、生效日期与签字栏在追问中可引用 | 检查签字或回执是否齐全，用样例请求比对返回字段 |
| 考试记录 | 人员名单、成绩、日期与回执在缺项判定中可对应 | 核对数量与日期，确认同一记录在两份材料里是否对得上 |
| HTTP 请求配置 | 路径参数、请求体与请求头中的占位能解析成实际值 | 在变量面板核对 `variables` 来源，预览渲染后的地址与请求头 `Authorization` |

## 容易做错的三处

- 现象：同一记录在两份材料里的名称、数量、日期对不上。原因：课件与考试记录未按同一批次同步更新，字段取值来源不同。
- 现象：版本未同步，追问引用了旧版规程。原因：材料更新后未重新进入受理流程，占位变量仍指向旧输出。
- 现象：缺签字或回执，受理记录仍被转出。原因：缺项判定未覆盖签字栏，追问环节未先补问关键信息。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；同时核对 `responseData` 与 `variables` 的取值来源。

业务测试：提一个缺关键信息的问句，看是否先追问再作答，确认缺项被识别并追问、回答有材料依据。

- 在变量面板核对每个占位的来源，确认路径参数、请求体与请求头三处变量能解析成实际值。
- 用一条样例请求比对返回字段与状态码，检查外部系统是否收到空字段或返回 401。
