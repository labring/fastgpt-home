# 培训机构招生咨询转化的问答受理与缺项补问：HTTP 接口

## 这个品类的数据长什么样

培训机构招生咨询转化场景里，材料以招生简章、咨询记录、试听课安排三类为主。招生简章给出课程名称、班型、开课日期与费用口径；咨询记录承载学员姓名、联系方式、意向课程与沟通时间；试听课安排记录试听时间、校区、授课人与回执签字。三类材料来源不同：简章由市场或教务发布，咨询记录由招生顾问逐条录入，试听安排由教务排课生成。更新节奏上，简章随班期调整，咨询记录随每次沟通追加，试听安排按周排布。字段特征集中在名称、数量、日期与签字四类，同一学员的意向课程在两份材料里可能写法不同，班期日期与试听日期可能错位，回执缺少签字。进入该功能时，简章与试听安排作为外部系统侧数据，咨询记录作为受理输入，由 HTTP 接口按约定取回，缺项在追问环节补齐。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。受理记录与补齐的问项由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 模块向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 招生简章 | 课程名称、班型、开课日期与费用口径在简章与咨询记录中是否一致 | 取简章字段与咨询记录逐项比对，日期与数量对不上的先标记缺项 |
| 咨询记录 | 学员姓名、意向课程、沟通时间是否齐全，是否留有顾问签字或回执 | 按字段清单核对，缺联系方式或意向课程时进入追问，缺签字单独记录 |
| 试听课安排 | 试听时间、校区、授课人与简章班期是否同步，版本是否最新 | 核对排课版本与简章版本，日期错位或版本未同步的列为待补问项 |
| HTTP 请求配置 | 请求地址、请求头与请求体中的占位变量能否解析成实际值 | 在请求预览看渲染后的完整地址，核对请求头名称与取值来源，用样例请求比对返回，确认 `Authorization`、`variables`、`responseData` 与接口约定一致 |

## 容易做错的三处

- 现象：外部系统收到空字段。原因：请求体占位变量未解析，前方节点输出名称与接口约定不一致，字段名对不上。
- 现象：请求返回 401。原因：请求头鉴权信息未按外部系统要求传入，Authorization 取值来源错误或未随环境切换。
- 现象：同一学员的意向课程与班期日期在两份材料里对不上。原因：简章版本未同步，咨询记录沿用旧班期，试听安排缺回执签字。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；确认 `variables` 与 `responseData` 的取值与接口约定一致，状态码为 200 时再转承办人处理。

业务测试：提一个缺关键信息的问句，看是否先追问再作答。

- 在变量面板核对每个占位的来源，确认来自全局变量、系统变量或前方节点输出，并在请求预览看渲染后的完整地址。
- 用一条样例请求比对返回字段，核对请求头名称与取值来源，确认 `Authorization` 与接口约定一致后再转承办人处理。
