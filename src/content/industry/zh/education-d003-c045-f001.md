# 校外培训合规备案与处罚应对的问答受理与缺项补问：HTTP 接

## 这个品类的数据长什么样

本页围绕校外培训合规备案与处罚应对，把办学许可证、课程备案材料、收费公示三类材料接入问答受理与缺项补问流程。办学许可证用于核对名称、证号、有效期与签字；课程备案材料用于核对课程名称、课时数量、备案日期与签章；收费公示用于核对收费项目、金额、公示日期与回执。材料来源为机构提交的扫描件与外部系统推送的结构化字段，更新节奏随备案变更与处罚通知触发。材料进入该功能时，许可证与备案材料作为问项依据，收费公示作为一致性比对基准，由 HTTP 接口把问句与材料字段发往外部系统，返回缺项与追问清单。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「受理记录与补齐的问项」由后续节点解析响应，或外部系统按约定处理接着完成。请求地址、路径参数、请求头与请求体中的占位变量，来自全局变量、系统变量或前方节点输出，可在请求预览里核对渲染后的完整地址与取值来源。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 办学许可证 | 名称、证号、有效期与签字是否与备案记录一致 | 在请求体样例中比对许可证字段与外部系统返回字段，核对 `Authorization` 请求头取值来源 |
| 课程备案材料 | 课程名称、课时数量、备案日期与签章是否对得上 | 用一条样例请求比对返回，检查同一记录在两份材料里的数量与日期是否一致 |
| 收费公示 | 收费项目、金额、公示日期与回执是否齐全 | 核对请求头名称与取值来源，确认公示字段与外部接口约定一致 |
| HTTP 节点输出 | 响应体、状态码与返回字段是否可被后续节点解析 | 在变量面板核对每个占位的来源，用 `variables` 与 `responseData` 追踪字段出处 |

## 容易做错的三处

- 现象：同一课程在两份备案材料里的名称、数量、日期对不上。原因：材料版本未同步，旧版字段被当作现行值传入请求体。
- 现象：外部系统收到空字段或返回鉴权失败。原因：请求头取值来源未核对，`Authorization` 未按外部系统要求传入。
- 现象：收费公示缺签字或回执，追问清单仍被放行。原因：缺项识别未覆盖签字与回执字段，版本更新后未重新比对。

## 怎么确认配好了

本功能验收：在请求预览里看渲染后的完整地址，核状态码与返回字段，再对一条样例请求比对结果，确认 `Authorization`、`variables`、`responseData` 的取值与出处。

业务测试：提一个缺关键信息的问句，看是否先追问再作答，并检查追问项是否对应办学许可证、课程备案材料、收费公示中的缺项。

- 在变量面板核对每个占位的来源，确认请求地址、路径参数、请求头与请求体中的变量都能解析成实际值。
- 用一条样例请求比对返回字段与外部接口约定，检查同一记录在两份材料里的名称、数量、日期是否一致。
