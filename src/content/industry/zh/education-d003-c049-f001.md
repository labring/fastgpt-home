# 国际学生招生与学籍管理的问答受理与缺项补问：HTTP 接口

## 这个品类的数据长什么样

国际学生招生与学籍管理品类下，招生简章、录取通知书、签证申请表三份材料各自承担不同角色。招生简章给出专业、学制、申请截止日与费用口径，是受理问项的第一依据；录取通知书承载录取结论、报到日期与签字回执，用于确认学籍起点；签证申请表记录护照信息、签证类型与签字栏，是入境与注册衔接的关键材料。材料来自招生系统导出、扫描件上传与外部系统回传，更新节奏随批次与签证进度变化。字段特征集中在姓名拼写、日期格式、数量口径与签字栏：同一记录在三份材料里的名称、数量、日期可能对不上，版本未同步或缺签字回执。材料进入问答受理与缺项补问功能时，简章用于比对条件，通知书用于核对结论，申请表用于校验身份与签字，缺项由追问补齐后转承办人处理。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。受理记录与补齐的问项由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 模块向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 招生简章 | 专业、学制、截止日与费用口径是否与受理问项一致 | 核对简章字段与日期，比对同一记录在通知书里的名称与数量 |
| 录取通知书 | 录取结论、报到日期与签字回执是否齐全 | 核对签字栏与回执，检查版本是否与简章同步 |
| 签证申请表 | 护照信息、签证类型与签字栏是否与通知书对应 | 比对申请表与通知书中的日期与姓名拼写，确认无缺项 |
| HTTP 请求 | 请求地址、请求头与请求体能否解析成实际值 | 在请求预览里看渲染后的完整地址，核对请求头名称与取值来源，用一条样例请求比对返回 |

## 容易做错的三处

- 现象：同一记录在简章与通知书里的名称、数量、日期对不上。原因：两份材料各自维护，未按同一口径校对。
- 现象：签证申请表缺签字或回执，受理问项无法闭环。原因：材料收集环节未检查签字栏与回执状态。
- 现象：请求返回 401 或外部系统收到空字段。原因：鉴权信息未按外部系统要求传入，占位变量未解析成实际值。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；核对 `Authorization`、`variables`、`responseData` 是否按约定出现。

业务测试：提一个缺关键信息的问句，看是否先追问再作答

- 在变量面板核对每个占位的来源，确认 `variables` 能追到全局变量、系统变量或前方节点输出
- 核对请求头名称与取值来源，确认 `Authorization` 按外部系统要求传入，并用一条样例请求比对返回
