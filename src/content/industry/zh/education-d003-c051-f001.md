# 普通高考报名资格审核的问答受理与缺项补问：HTTP 接口

## 这个品类的数据长什么样

普通高考报名资格审核的问答受理与缺项补问，围绕高考报名表、户籍学籍证明、随迁子女材料三类材料展开。高考报名表承载考生基本信息与报考科目，字段含姓名、身份证号、学籍号、报考类别、签字与日期；户籍学籍证明由户籍地与就读学校出具，字段含户籍地址、迁入日期、学籍起止与学校盖章；随迁子女材料含居住证、社保缴纳记录、父母就业证明，字段含证件编号、有效期与经办签字。材料来源为考生提交与外部系统回传，更新节奏按报名批次与审核节点推进，补正材料在追问后回流。三类材料进入该功能时，报名表作为主记录，户籍学籍证明与随迁子女材料作为佐证件，用于比对同一记录的名称、数量、日期与签字回执是否一致。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。受理记录与补齐的问项由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点只负责把问句与材料字段按约定发出，不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 高考报名表 | 姓名、身份证号、报考类别、签字与日期在各栏位一致，缺项能被识别为待补问项 | 在变量面板核对占位来源，预览渲染后的请求体字段，比对返回字段与样例 |
| 户籍学籍证明 | 户籍地址、迁入日期、学籍起止与学校盖章的日期和签字齐全，与报名表同一记录对得上 | 核对请求头里的 `Authorization` 取值来源，用一条样例请求比对返回字段 |
| 随迁子女材料 | 居住证编号、社保缴纳记录、父母就业证明的有效期与经办签字不缺，数量与日期不冲突 | 检查请求体字段与外部接口约定一致，确认 `variables` 与 `responseData` 的映射关系 |
| HTTP 节点 | 请求地址、路径参数、请求头与请求体中的占位变量都能解析成实际值 | 在请求预览里看渲染后的完整地址，核对每个占位的出处 |

## 容易做错的三处

- 现象：同一考生姓名在报名表与户籍学籍证明里写法不同。原因：两份材料由不同经办环节录入，名称与日期未做一致性比对。
- 现象：随迁子女材料的居住证有效期与社保记录日期对不上。原因：版本未同步，补正后的材料未回流到主记录。
- 现象：报名表缺考生签字或回执，仍被当作完整材料受理。原因：缺项识别未覆盖签字与回执字段，追问环节未触发。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；确认 `Authorization`、`variables`、`responseData` 三处标识符在请求头、变量来源与返回字段中的对应关系。

业务测试：提一个缺关键信息的问句，看是否先追问再作答。

- 在请求预览里核对渲染后的完整地址与路径参数，确认占位变量能解析成实际值。
- 在变量面板核对每个占位的来源，确认请求体字段与外部接口约定一致，并用一条样例请求比对返回。
