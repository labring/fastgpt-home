# 成人高考报名与录取管理的问答受理与缺项补问：HTTP 接口

## 这个品类的数据长什么样

成人高考报名与录取管理涉及报名表、照顾加分材料与录取名册三类材料。报名表由考生填报，字段含姓名、身份证号、报考层次与签字栏；照顾加分材料由考生提交，含证明名称、发证日期与审核签字；录取名册由承办环节整理，含考生姓名、录取专业、录取日期与负责人签字。三类材料在问答受理与缺项补问中角色不同：报名表是身份与报考信息的基准，照顾加分材料用于核对加分依据，录取名册用于确认录取结果。材料随报名批次与录取批次更新，同一记录在报名表与录取名册中的姓名、日期、签字可能不一致，需逐项比对。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。受理记录与补齐的问项由后续节点解析响应，或外部系统按约定处理接着完成。请求地址、路径参数、请求头与请求体均可通过 `variables` 引用全局变量、系统变量或前方节点输出，返回的 `responseData` 供后续节点使用。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 报名表 | 姓名、身份证号、报考层次与签字栏是否齐全，日期是否在报名批次内 | 核对报名表字段与签字，比对报名表与录取名册中的姓名、日期 |
| 照顾加分材料 | 证明名称、发证日期与审核签字是否一致，是否缺回执 | 核对材料名称与发证日期，检查审核签字与回执是否齐全 |
| 录取名册 | 录取专业、录取日期与负责人签字是否完整，版本是否同步 | 核对录取名册字段，比对报名表与名册中的姓名、数量、日期 |
| HTTP 请求 | `Authorization` 是否按外部系统要求传入，`variables` 占位是否解析成实际值 | 在请求预览里看渲染后的完整地址，核对请求头名称与取值来源 |

## 容易做错的三处

- 现象：同一记录在报名表与录取名册里的姓名或日期对不上。原因：两份材料由不同环节录入，未做逐项比对。
- 现象：照顾加分材料版本未同步，审核签字或回执缺失。原因：材料更新后未回传，受理时未核签字栏。
- 现象：请求返回 401 或外部系统收到空字段。原因：`Authorization` 取值来源有误，`variables` 占位未解析。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；确认 `Authorization`、`variables`、`responseData` 均能追到具体出处。

业务测试：提一个缺关键信息的问句，看是否先追问再作答。

- 在变量面板核对每个占位的来源，确认请求地址与路径参数能解析成实际值。
- 用一条样例请求比对返回，核对请求体字段与外部接口约定一致。
