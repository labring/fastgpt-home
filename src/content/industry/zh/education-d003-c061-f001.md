# 科研成果登记与知识产权管理的问答受理与缺项补问：HTTP 接

## 这个品类的数据长什么样

科研成果登记与知识产权管理涉及成果登记表、专利交底书、软件著作权材料三类材料。成果登记表记录成果名称、完成人、日期与签字，用于受理登记与承办分派；专利交底书承载技术方案、发明人、申请节点与签字回执，用于判断知识产权类型与补齐项；软件著作权材料包含源代码、说明书、版本号与签章，用于核对版本与权属。三类材料在问答受理环节共同构成缺项识别依据：登记表定主体与日期，交底书定技术内容与签字，著作权材料定版本与回执。材料以表单与附件形式进入，更新节奏随成果推进与版本迭代变化，字段特征集中在名称、数量、日期、签字与回执五类，任一处不一致都会触发补问。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。受理记录与补齐的问项由后续节点解析响应，或外部系统按约定处理接着完成。请求地址、路径参数、请求头与请求体均可通过 `{{}}` 引用 `variables`，变量来自全局变量、系统变量或前方节点输出；`Authorization` 按外部系统要求传入，返回的 `responseData` 由后续节点解析。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 成果登记表 | 名称、数量、日期与签字须与交底书、著作权材料互相对齐，任一字段对不上即列为缺项 | 调取登记表与交底书，逐字段比对名称、数量、日期，核对签字栏与回执是否齐全 |
| 专利交底书 | 技术方案、发明人、申请日期与签字回执须与登记表一致，版本号不得滞后 | 用一条样例请求比对返回字段，核 `responseData` 中的名称与日期，检查签字与回执 |
| 软件著作权材料 | 源代码、说明书、版本号与签章须与登记表及交底书同步，版本未同步即追问 | 核对版本号与签章，在变量面板确认每个占位的来源，检查 `variables` 与 `Authorization` 取值 |
| HTTP 请求返回 | 状态码与返回字段须与外部接口约定一致，空字段与超时须单独记录 | 在请求预览里看渲染后的完整地址，核对请求头名称与取值来源，用样例请求比对结果 |

## 容易做错的三处

- 现象：同一记录在两份材料里的名称、数量、日期对不上。原因：登记表与交底书分别录入，未做字段级比对。
- 现象：版本未同步，著作权材料与交底书版本号不一致。原因：材料分批提交，更新节奏未对齐。
- 现象：缺签字或回执，受理记录仍被推进。原因：缺项识别未覆盖签字栏与回执字段。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；检查 `responseData` 字段与 `variables` 来源。

业务测试：提一个缺关键信息的问句，看是否先追问再作答。

- 在请求预览里核对渲染后的完整地址与请求头名称，确认 `Authorization` 取值来源。
- 在变量面板核对每个占位的出处，用样例请求比对返回字段与状态码。
