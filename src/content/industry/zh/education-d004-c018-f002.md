# 本科培养方案修订的材料起草与责任交接：上下文与 token

## 这个品类的数据长什么样

本页面向本科培养方案修订中的材料起草与责任交接，品类材料包括培养方案、课程大纲、学分结构表三类。培养方案承载专业方向与总学分框架，课程大纲承载课程目标与考核方式，学分结构表承载各模块学分与比例。材料来源为院系教学委员会、专业负责人与教务办公室，更新节奏按修订批次推进，通常在春季学期集中起草、秋季学期前定稿。字段特征集中在课程名称、课程代码、学分、学时、开课学期、修订日期与签字栏。进入本功能时，培养方案作为主文件，课程大纲与学分结构表作为附件与对照表，三者共同构成可签发的草稿与交接记录。

## 配置怎么定

这一环由应用设置（回复上限等）执行，输出单次回答长度与可容纳的上下文范围。「可签发的材料草稿与交接记录」由模型接着完成。回复上限用滑块控制单次回答的长度，设置过低回答会被截断，设置过高会增加消耗；入口与授权由发布服务与文件权限负责，回复上限与上下文长度不决定访问授权，也不生成业务成品。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 培养方案 | 课程名称、课程代码、学分、修订日期与签字栏齐全，且与课程大纲、学分结构表一致 | 在应用设置里核对回复上限开关与滑块位置，检查 `maxResponse` 与 `maxContext` 是否匹配长文起草需求 |
| 课程大纲 | 课程目标、考核方式、学时与开课学期与培养方案逐项对齐，版本号与日期同步 | 核对 `quoteMaxToken` 对应的引用文本 tokens，数组条数单独记录，不将条数与预算做相等比较 |
| 学分结构表 | 各模块学分、比例与总学分合计无误，签字或回执完整 | 对比两次运行的用量，确认上限调整后单次用量变化，并检查较长回答结尾是否完整 |
| 交接记录 | 责任人、签收时间、版本与日期一致，缺项被拦截 | 按模板起草一份并走完一次交接，看缺项是否被拦住 |

## 容易做错的三处

- 现象：同一课程在两份材料里的名称或学分对不上。原因：起草时未以培养方案为基准同步更新课程大纲与学分结构表。
- 现象：修订日期与版本号在两份材料中不一致。原因：版本未同步，旧稿覆盖新稿或附件未随主文件更新。
- 现象：交接记录缺签字或回执。原因：签收环节未按模板逐项核对，责任人栏与日期栏留空。

## 怎么确认配好了

本功能验收：提一个需要长回答的问题，看结尾是否完整，确认回复上限与页面要求的回答长度匹配，并核对 `maxResponse` 与 `maxContext` 的取值。

业务测试：按模板起草一份并走完一次交接，看缺项是否被拦住。

- 在应用设置里核对回复上限开关与滑块位置，确认单次回答长度与起草任务匹配。
- 对比两次运行的用量，检查上限调整后单次用量变化，并确认较长回答结尾完整。
