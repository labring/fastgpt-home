# 职业院校专业设置备案的材料起草与责任交接：上下文 token

## 这个品类的数据长什么样

职业院校专业设置备案的材料起草与责任交接，涉及专业设置备案表、人才需求论证、师资设备清单三类材料。备案表来自院校申报口径，按学年更新，字段含专业名称、代码、学制、招生人数、签字；人才需求论证来自行业调研与区域产业数据，按论证周期更新，字段含岗位名称、需求数量、调研日期、论证人；师资设备清单来自人事与资产台账，按学期更新，字段含教师姓名、职称、设备名称、数量、购置日期。三类材料进入本功能时，备案表作为主记录，论证与清单作为支撑附件，其名称、数量、日期须与主记录逐项对齐。

## 配置怎么定

这一环由应用设置（回复上限等）执行，输出单次回答长度与可容纳的上下文范围。「可签发的材料草稿与交接记录」由模型接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 专业设置备案表 | 专业名称、代码、学制、招生人数、签字与日期齐全，且与论证、清单逐项一致 | 在应用设置里核对回复上限开关与滑块位置，用 `maxResponse` 确认单次回答长度，再比对备案表字段 |
| 人才需求论证 | 岗位名称、需求数量、调研日期、论证人签字与备案表口径一致 | 提一个需要长回答的问题看结尾是否完整，核对论证中的岗位与数量是否与备案表对得上 |
| 师资设备清单 | 教师姓名、职称、设备名称、数量、购置日期与备案表版本同步 | 检查清单中的设备数量与日期是否与备案表一致，确认交接回执已签收 |
| 上下文与 token | 单次回答长度与可容纳的上下文范围匹配页面要求，引用条数单独记录 | 对比两次运行的用量，核对 `maxContext` 与 `quoteMaxToken` 的预算是否被引用文本 tokens 撑满 |

## 容易做错的三处

- 现象：同一专业名称在备案表与论证里写法不同，数量与日期对不上。原因：两份材料各自维护，未做逐项对齐。
- 现象：师资设备清单已更新，备案表仍为旧版本，交接时未同步。原因：版本未同步，缺回执确认。
- 现象：材料草稿有字段但缺签字或回执，下一环节拒收。原因：责任人未明确，交接记录不完整。

## 怎么确认配好了

本功能验收：提一个需要长回答的问题，看结尾是否完整，并核对 `maxResponse` 与 `maxContext` 的取值是否匹配页面要求的回答长度。

业务测试：按模板起草一份并走完一次交接，看缺项是否被拦住。

- 在应用设置里核对回复上限开关与滑块位置，确认单次回答长度与页面要求匹配。
- 对比两次运行的用量，记录引用条数与引用文本的 tokens，确认 `quoteMaxToken` 预算未被撑满。
