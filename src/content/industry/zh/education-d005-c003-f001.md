# 幼儿园卫生保健与膳食管理的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

本页面向幼儿园卫生保健与膳食管理场景，材料包括食材名称与规格、留样时间与批次、消毒时段、缺勤病因归类等台账与记录。这些材料来自保健室、食堂与班级日常填报，更新节奏为每日或每餐次，字段特征为批次号、时段与归类码。进入 HTTP 接口与外部系统这一功能时，食材规格与留样批次作为请求体字段，消毒时段与缺勤病因作为路径参数或查询变量，各自承担向外部系统传递现行版本与变更记录的角色，确保现行版本唯一、旧版可追、引用同步。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。版本台账与变更记录要由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点只负责按约定发出请求，不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 食材名称与规格 | 请求体字段与外部接口约定一致，且与食谱、采购品类对应 | 用一条样例请求比对返回，核对食材名称与规格是否与采购品类一致 |
| 留样时间与批次 | 路径参数或请求体中的批次号能解析成实际值，且与单据批次对得上 | 在请求预览里看渲染后的完整地址，核对留样时间与批次是否与单据一致 |
| 消毒时段 | 请求头与请求体字段覆盖完整时段，不出现缺时段 | 核对请求头名称与取值来源，检查消毒记录是否缺时段 |
| 缺勤病因归类 | 变量来源可追，归类码与外部系统约定一致 | 在变量面板核对每个占位的来源，确认缺勤病因归类字段非空 |

## 容易做错的三处

- 现象：单据与留样批次对不上。原因：请求体中的批次号取自前方节点输出，未与单据实际批次同步，导致外部系统收到空字段或旧批次。
- 现象：食谱与采购品类不一致。原因：食材名称与规格在请求体中写死，未引用变量，更新一处内容后引用未同步更新。
- 现象：消毒记录缺时段。原因：路径参数或请求体未覆盖全部消毒时段，HTTP 节点按约定发出请求后外部系统按缺时段数据落库。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；核对 `variables` 中每个占位的来源，确认 `Authorization` 请求头按外部系统要求传入，并检查返回 `responseData` 字段与约定一致。

业务测试：改一处内容，看版本号与引用是否同步更新

- 在请求预览里核对渲染后的完整地址与请求头，确认占位变量能解析成实际值
- 在变量面板核对每个占位的来源，确认 `variables`、`Authorization` 与 `responseData` 字段与外部接口约定一致
