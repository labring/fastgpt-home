# 幼儿园安全防护与应急演练的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

本页面向幼儿园安全防护与应急演练场景，材料包括隐患排查台账、整改通知与闭环记录、演练方案与签到表、门禁与校车检查表、责任人签字页。这些材料进入 HTTP 接口与外部系统功能时，分别承担不同角色：台账与整改记录是版本比对主体，演练方案与签到表用于核对人数与流程一致性，门禁校车检查表用于确认检查项无漏项，签字页用于确认责任人确认。来源为园所日常巡检、专项演练与外部检查反馈，更新节奏按学期、演练轮次与整改时限滚动，字段特征包含隐患项、整改期限、演练人数、签到状态、检查项编号与签字栏。材料进入该功能后，由 HTTP 节点向外部系统发起请求，把版本台账与变更记录作为请求体或路径参数传递，响应体、状态码与返回字段交由后续节点解析，用于更新知识库或对外文档，保证现行版本唯一、旧版可追、引用同步。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「版本台账与变更记录」由后续节点解析响应，或外部系统按约定处理接着完成。请求地址、路径参数、请求头与请求体均可通过 `{{}}` 引用变量，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 请求地址与路径参数 | 占位变量能解析成实际值，且与隐患项、整改期限字段对应 | 在请求预览里看渲染后的完整地址，核对 `variables` 来源 |
| 请求头 | 鉴权信息按外部系统要求传入，`Authorization` 取值来源可追 | 核对请求头名称与取值来源，确认与外部接口约定一致 |
| 请求体 | 字段与外部接口约定一致，覆盖演练人数、签到与检查项 | 用一条样例请求比对返回，检查 `responseData` 字段是否齐全 |
| 变量来源 | 每个占位都能追到全局变量、系统变量或前方节点输出 | 在变量面板核对每个占位的来源，确认无空字段 |

## 容易做错的三处

- 现象：隐患未闭环，旧版整改记录仍被引用。原因：版本台账未按整改期限更新，引用同步未触发。
- 现象：演练记录与方案不符，签到人数对不上。原因：请求体字段与外部接口约定不一致，返回字段未回写。
- 现象：门禁与校车检查项漏项，责任人签字缺失。原因：路径参数占位解析为空，外部系统收到空字段。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `Authorization`、`variables`、`responseData` 三处可追。

业务测试：改一处内容，看版本号与引用是否同步更新，确认现行版本唯一、旧版可追。

- 在请求预览里核对渲染后的完整地址与路径参数，确认占位变量解析成实际值。
- 用一条样例请求比对返回体字段，确认隐患项、整改期限、演练人数、签到与检查项无漏项。
