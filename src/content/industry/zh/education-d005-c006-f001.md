# 幼儿园办园行为与质量自评的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

幼儿园办园行为与质量自评涉及自评报告、问题清单、整改计划三类材料，字段包含指标名称、自评结论、问题描述、整改措施、责任人、完成日期与签字回执。材料来源多为园所自填、责任督学反馈与系统导出，更新节奏跟随自评周期与整改节点，常出现同一记录在两份材料里的名称、数量、日期对不上，版本未同步，缺签字或回执。三类材料进入 HTTP 接口与外部系统时角色不同：自评报告作为主记录承载结论，问题清单作为子项承载待办，整改计划作为跟踪项承载时限与责任人。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「版本台账与变更记录」由后续节点解析响应，或外部系统按约定处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 自评报告 | 指标名称、自评结论、签字回执在三类材料间一致 | 取一条自评记录，比对问题清单与整改计划中的名称、数量、日期，核对签字与回执是否齐全 |
| 问题清单 | 问题描述、责任人与完成日期可追到现行版本 | 在请求体里以 `variables` 引用前方节点输出，比对返回字段与清单原文 |
| 整改计划 | 整改措施与时限引用同步，旧版可追 | 改一处内容后，核 `responseData` 里版本号与引用字段是否同步更新 |
| 请求头 | 鉴权信息按外部系统要求传入 | 核对 `Authorization` 名称与取值来源，确认非空且未过期 |

## 容易做错的三处

- 现象：同一记录在自评报告与问题清单里的名称、数量、日期对不上。原因：两处各自维护，未以现行版本为唯一引用源。
- 现象：整改计划改了内容，自评报告仍引用旧版。原因：版本号未随变更递增，引用未同步更新。
- 现象：外部系统收到空字段或缺签字回执。原因：请求体字段与接口约定不一致，或签字回执未随材料一并提交。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `variables` 与 `responseData` 字段可解析。

业务测试：改一处内容，看版本号与引用是否同步更新。

- 在变量面板核对每个占位的来源，确认请求地址、请求头与请求体三处占位都能解析成实际值。
- 用一条样例请求比对返回，核对字段与外部接口约定一致，并记录现行版本号与变更时间。
