# 中小学学籍建立与异动的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

本页面向中小学学籍建立与异动场景，材料包括学籍档案、转学申请、休复学材料，来源为学校、学籍管理员与外部业务系统，更新节奏随学期初建籍、学期中异动、学期末归档而变。字段特征集中在姓名、身份证件号、学籍号、班级、日期、签字与回执。学籍档案是主记录，转学申请是触发异动的凭据，休复学材料是状态变更的依据。三类材料进入 HTTP 接口与外部系统这一功能时，各自承担不同角色：学籍档案提供基准字段，转学申请提供异动原因与去向，休复学材料提供起止日期与审批签字。资料版本与变更维护要求现行版本唯一、旧版可追、引用同步，更新知识库或对外文档时，改一处内容需看版本号与引用是否同步更新。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。版本台账与变更记录要由后续节点解析响应，或外部系统按约定处理接着完成。请求地址与路径参数、请求头、请求体三处均可用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 学籍档案 | 字段、日期与签字是否与转学申请一致 | 核对姓名、身份证件号、学籍号、班级与建籍日期；检查签字与回执是否齐全；在变量面板核对 `variables` 来源 |
| 转学申请 | 同一记录在两份材料里的名称、数量、日期是否对得上 | 比对转入转出学校、异动日期与学籍号；确认无缺签字或回执；查看请求预览渲染后的完整地址 |
| 休复学材料 | 起止日期、审批签字与学籍档案状态是否同步 | 核对休学与复学日期、审批人签字、回执；确认版本号与引用同步更新；比对返回字段 `responseData` |
| 请求头与请求体 | 鉴权信息与字段约定是否按外部系统要求传入 | 核对 `Authorization` 名称与取值来源；用一条样例请求比对返回字段与状态码 |

## 容易做错的三处

- 现象：同一记录在学籍档案与转学申请里的姓名、日期对不上。原因：两份材料分别维护，未以现行版本为准做字段比对。
- 现象：休复学材料已更新，学籍档案仍显示旧状态。原因：版本未同步，引用未随内容变更而更新。
- 现象：转学申请缺签字或回执，外部系统收到空字段。原因：材料未齐备即发起请求，请求体字段与约定不一致。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；在变量面板核对 `variables` 与 `responseData` 是否可追到具体出处。

业务测试：改一处内容，看版本号与引用是否同步更新；确认现行版本唯一、旧版可追、引用同步。

- 在请求预览里看渲染后的完整地址，核对路径参数占位变量能解析成实际值。
- 核对请求头名称与取值来源，确认 `Authorization` 按外部系统要求传入；用一条样例请求比对返回字段。
