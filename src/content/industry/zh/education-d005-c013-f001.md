# 中小学教师培训学分管理的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

本页围绕中小学教师培训学分管理，聚焦培训通知、学分认定表、参训名单三类材料的版本与变更维护。培训通知由培训管理部门起草，载明培训名称、起止日期、学时与学分折算规则；学分认定表由参训教师所在学校或培训机构填写，含姓名、身份证号、培训项目、认定学分、签字与日期；参训名单由组织方汇总，含姓名、单位、参训状态与回执。三类材料字段交叉引用，同一教师、同一项目在两份材料里的名称、数量、日期必须一致。材料更新节奏受培训批次、政策调整与补录影响，旧版需可追溯，现行版本唯一。进入 HTTP 接口与外部系统后，培训通知与参训名单常作为请求体字段来源，学分认定表作为核对依据，变量从前方节点输出或全局变量注入。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。版本台账与变更记录由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点只负责按约定发出请求，不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 培训通知 | 培训名称、起止日期、学时与学分折算规则须与现行版本一致，旧版可追 | 核对请求体字段是否引用现行通知的日期与学分规则，比对 `responseData` 中返回的版本标识 |
| 学分认定表 | 姓名、身份证号、培训项目、认定学分、签字与日期须与参训名单对得上 | 用一条样例请求比对返回字段，检查认定学分与参训名单数量是否一致，缺签字或回执时标记异常 |
| 参训名单 | 姓名、单位、参训状态与回执须与培训通知批次同步 | 在变量面板核对 `variables` 中名单来源，确认请求头 `Authorization` 取值来源符合外部系统要求 |
| HTTP 节点输出 | 响应体、状态码与返回字段可被后续节点解析，引用同步更新 | 预览渲染后的请求，核状态码与返回字段，改一处内容后看版本号与引用是否同步更新 |

## 容易做错的三处

- 现象：同一教师在两份材料里的姓名或学分数量对不上。原因：培训通知与学分认定表各自维护，未以现行版本为唯一引用源。
- 现象：旧版通知已变更，参训名单仍引用旧日期。原因：版本未同步，HTTP 请求体字段未随版本台账更新。
- 现象：学分认定表缺签字或回执，外部系统收到空字段。原因：请求体字段与外部接口约定不一致，变量来源未核对。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `variables`、`Authorization`、`responseData` 三处标识符均能追到具体出处。

业务测试：改一处内容，看版本号与引用是否同步更新。

- 在变量面板核对每个占位的来源，确认请求地址、请求头与请求体中的变量能解析成实际值。
- 用一条样例请求比对返回字段，检查现行版本唯一、旧版可追、引用同步，缺签字或回执时记录变更。
