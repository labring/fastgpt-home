# 学校德育与班主任工作的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

本页面向学校德育与班主任工作场景，材料包括主题班会方案、学生综合素质记录、家访记录。主题班会方案含活动目标、流程、日期与班主任签字；学生综合素质记录含学期、指标、数量与家长回执；家访记录含访问时间、对象、内容与双方签字。来源为各班级提交与德育处归档，更新节奏按学期初、期中、期末三轮推进。材料进入该功能时，方案作为版本主件、记录作为引用附件、回执作为签字凭据，各自承担不同角色，用于生成版本台账与变更记录。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「版本台账与变更记录」由后续节点解析响应，或外部系统按约定处理接着完成。请求地址、路径参数、请求头与请求体都能用 `variables` 占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 主题班会方案 | 同一方案在两份材料里的名称、日期与签字是否一致 | 在请求预览里核对渲染后的完整地址与请求体字段，确认方案名称、日期与签字来源可追 |
| 学生综合素质记录 | 学期、指标、数量与家长回执是否对得上 | 用一条样例请求比对返回，核对记录字段与外部接口约定一致，回执有无缺失 |
| 家访记录 | 访问时间、对象、内容与双方签字是否同步 | 在变量面板核对每个占位的来源，确认家访时间与签字字段取自现行版本 |
| HTTP 模块 | 请求地址与路径参数、请求头、请求体三处占位能否解析成实际值 | 核对 `Authorization` 请求头名称与取值来源，检查返回字段是否含 `responseData` |

## 容易做错的三处

- 现象：同一份家访记录在班级台账与德育处汇总里名称、数量对不上。原因：两处各自维护，未以现行版本为准做引用同步。
- 现象：主题班会方案改了内容，版本号与引用未同步更新。原因：变更记录未随请求体字段一并提交，旧版仍被引用。
- 现象：学生综合素质记录缺家长回执或班主任签字。原因：请求体字段为空，外部系统收到空字段后仍按约定处理。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；确认 `variables` 占位解析成实际值、`Authorization` 按外部要求传入、返回含 `responseData`。

业务测试：改一处内容，看版本号与引用是否同步更新

- 在请求预览里核对渲染后的完整地址与请求体字段，逐项追到全局变量、系统变量或前方节点输出
- 用一条样例请求比对返回，核对请求头名称与取值来源，确认外部接口字段约定一致
