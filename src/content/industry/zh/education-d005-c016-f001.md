# 学校安全隐患排查与校园事件上报的资料版本与变更维护：HTTP

## 这个品类的数据长什么样

学校安全隐患排查与校园事件上报，材料分三类：安全检查表、隐患整改台账、突发事件报告。安全检查表按周或月由值班人员填写，含检查项、部位、日期与签字；隐患整改台账按隐患编号逐条登记，含整改责任人、期限、验收结果与回执；突发事件报告按事件编号归集，含时间、地点、涉及人员、处置经过与签字。三类材料在字段上共享隐患编号、日期与签字栏，但名称、数量、日期常在两份材料里对不上。材料进入 HTTP 接口时，安全检查表提供检查项与日期，隐患整改台账提供编号与整改状态，突发事件报告提供事件编号与处置字段，各自作为请求体或路径参数的来源，由外部系统按约定处理。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。版本台账与变更记录由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 模块向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 安全检查表 | 检查项、部位、日期与签字栏在请求体字段中逐项对应，日期与签字不缺失 | 取一条样例请求，比对请求体字段与安全检查表原件，核对日期与签字来源 |
| 隐患整改台账 | 隐患编号、整改期限、验收结果与回执在返回字段中可追溯，编号与名称在两份材料里一致 | 用一条样例请求比对返回，核对隐患编号与整改台账原件是否同名同数同日 |
| 突发事件报告 | 事件编号、时间、涉及人员与处置经过在路径参数与请求体中可解析 | 在请求预览里看渲染后的完整地址，核对路径参数取值与报告原件 |
| 请求头 | 鉴权信息按外部系统要求传入，`Authorization` 取值来源可追 | 核对请求头名称与取值来源，在变量面板核对每个占位的出处 |

## 容易做错的三处

- 现象：同一隐患在两份材料里的名称、数量、日期对不上。原因：安全检查表与隐患整改台账各自维护，未以隐患编号做统一引用。
- 现象：改一处内容后版本号与引用未同步更新。原因：版本台账与变更记录未随请求体字段变更一起维护，旧版无法追溯。
- 现象：突发事件报告缺签字或回执。原因：报告字段未在请求体中完整传递，后续节点解析响应时无法补齐签字栏。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；同时核对 `variables`、`responseData` 与 `Authorization` 三处占位的来源与取值。

业务测试：改一处内容，看版本号与引用是否同步更新，并核对现行版本唯一、旧版可追、引用同步。

- 在变量面板核对每个占位的来源，确认路径参数、请求体与请求头三处变量均能解析成实际值。
- 取一条样例请求比对返回，核对安全检查表、隐患整改台账与突发事件报告的字段、日期与签字栏是否一致。
