# 本科专业设置与动态调整的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

本科专业设置与动态调整的品类材料包括专业设置申请表、人才培养方案、专家论证意见三类。专业设置申请表记录专业名称、代码、修读年限、学位授予门类，含负责人与院系签章日期；人才培养方案载明培养目标、课程体系、学分学时与毕业要求，附审定人签字；专家论证意见记录论证结论、专家名单、论证日期与专家签名。材料来源为校内教学管理部门与院系报送，更新节奏随申报周期、培养方案修订与论证会召开而变动。进入本功能时，专业设置申请表提供申报数据与日期字段，人才培养方案提供课程与学分字段，专家论证意见提供论证结论与签字信息，三者共同支撑版本台账与变更记录。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。版本台账与变更记录由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 专业设置申请表 | 字段、日期与签字须与人才培养方案、专家论证意见对得上 | 核对专业名称、专业代码、修读年限、学位授予门类、负责人签章与日期，比对另两份材料同一记录的字段取值 |
| 人才培养方案 | 课程体系、学分学时与审定签字须与申请表、论证意见一致 | 核对培养目标、课程设置、学分学时、毕业要求与审定人签字，检查同一记录的名称、数量、日期是否一致 |
| 专家论证意见 | 论证结论、专家名单与论证日期须与申请表、培养方案同步 | 核对论证结论、专家姓名、论证日期与专家签名，确认缺签字或回执时标记为待补 |
| HTTP 请求配置 | 占位变量能解析成实际值，字段与外部接口约定一致 | 在请求预览里看渲染后的完整地址，核对 `Authorization` 请求头取值来源，用一条样例请求比对返回，在变量面板核对 `variables` 与 `responseData` 的来源 |

## 容易做错的三处

- 现象：同一专业在申请表与培养方案里的名称、修读年限对不上。原因：两份材料由不同人员维护，更新时未做字段级比对。
- 现象：旧版培养方案仍被引用，现行版本不唯一。原因：版本号未随内容变更同步，引用未指向现行版本。
- 现象：专家论证意见缺专家签名或回执。原因：论证会记录未回传，签字页未随材料归档。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `responseData` 字段与外部接口约定一致。

业务测试：改一处内容，看版本号与引用是否同步更新。

- 在变量面板核对每个占位的来源，确认 `variables` 与 `Authorization` 取值可追溯。
- 用一条样例请求比对返回字段，检查外部系统是否收到空字段或出现请求超时。
