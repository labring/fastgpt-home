# 本科培养方案修订的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

本科培养方案修订涉及培养方案、课程大纲、学分结构表三类材料。培养方案为总纲，课程大纲支撑课程设置，学分结构表核定学分分布。材料来源为教务系统导出与院系提交的修订稿，更新节奏按学期或修订批次推进，字段包含课程名称、学分、学时、开课学期、修订日期与签字栏。材料进入 HTTP 接口与外部系统这一功能时，培养方案作为主记录被引用，课程大纲与学分结构表作为附属材料提供字段级依据，三者共同构成版本台账与变更记录的基础。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。版本台账与变更记录由后续节点解析响应，或外部系统按约定处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 培养方案 | 课程名称、学分、修订日期与签字栏在培养方案与课程大纲中是否一致 | 核对两份材料同一记录的字段取值与签字回执，比对修订日期 |
| 课程大纲 | 课程名称、学时、开课学期与学分结构表是否对得上 | 用样例请求比对返回字段，核对名称、数量与日期 |
| 学分结构表 | 学分总数与分布是否与培养方案现行版本同步 | 核对版本号与引用关系，确认旧版可追溯 |
| 请求头 | 鉴权信息按外部系统要求传入 | 核对请求头名称与取值来源，确认 `Authorization` 取值正确 |

## 容易做错的三处

- 现象：同一课程在两份材料里的名称、数量或日期对不上。原因：培养方案与课程大纲分别维护，未做字段级比对。
- 现象：旧版培养方案仍被外部系统引用。原因：版本未同步，引用关系未随修订更新。
- 现象：材料缺签字或回执。原因：修订流程未闭环，签字栏与回执未随版本一并归档。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；核对 `responseData` 与 `variables` 的取值来源。

业务测试：改一处内容，看版本号与引用是否同步更新。

- 在变量面板核对每个占位的来源，确认 `variables` 与 `responseData` 能追到具体出处。
- 用一条样例请求比对返回字段，确认外部系统收到非空字段且无 401 与超时。
