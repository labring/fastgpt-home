# 选课排课与教室资源调度的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

本页面向选课排课与教室资源调度场景，材料包括开课计划、排课表、选课规则三类。开课计划提供课程名称、课程代码、学分与开课学期；排课表提供上课时间、教室编号、教师与周次；选课规则提供选课容量、优先级与退改选日期。这些材料进入 HTTP 接口与外部系统时，分别承担请求体字段来源、路径参数取值与请求头鉴权依据的角色。更新节奏按学期与校历节点推进，字段特征以日期、教室编号、课程代码与签字栏为主。资料版本与变更维护要求现行版本唯一、旧版可追、引用同步，使同一记录在开课计划、排课表与选课规则中的名称、数量、日期保持一致，并保留签字或回执。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。版本台账与变更记录由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 开课计划 | 课程代码、课程名称、学分与开课学期在排课表与选课规则中一致，且签字栏完整 | 核对请求体字段与开课计划字段逐项对齐，检查课程代码在排课表与选课规则中一致 |
| 排课表 | 上课时间、教室编号、周次与教师姓名在开课计划与选课规则中一致，且回执可查 | 核对路径参数与请求头取值来源，用样例请求比对返回的教室编号与周次 |
| 选课规则 | 选课容量、优先级与退改选日期在开课计划与排课表中一致，且版本号唯一 | 核对请求体字段与选课规则约定一致，检查退改选日期与容量是否同步更新 |
| 变量来源 | 每个占位变量能追到全局变量、系统变量或前方节点输出，且解析值非空 | 在变量面板核对每个占位的来源，确认 `variables` 与 `responseData` 可解析 |

## 容易做错的三处

- 现象：同一课程在开课计划与排课表里的名称、学分或日期对不上。原因：两份材料分别维护，未按同一版本号同步更新。
- 现象：外部系统收到空字段或旧值。原因：请求体占位变量未解析，或版本未同步导致旧版内容被引用。
- 现象：排课表缺签字或回执，选课规则无确认记录。原因：变更记录未随版本台账归档，引用链断在中间节点。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；同时检查 `Authorization`、`variables`、`responseData` 是否按约定出现。

业务测试：改一处内容，看版本号与引用是否同步更新

- 在请求预览里查看渲染后的完整地址，核对路径参数占位已解析成实际值
- 核对请求头名称与 `Authorization` 取值来源，确认鉴权信息按外部系统要求传入
