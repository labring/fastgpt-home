# 成绩录入与学分认定的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

成绩录入与学分认定涉及成绩单、缓考申请、补考安排三类材料。成绩单由任课教师提交，含课程名称、学分、成绩、日期与签字；缓考申请由学生提交，含课程、原因、申请日期与审批签字；补考安排由教务生成，含课程、时间、地点与回执。三类材料进入 HTTP 接口与外部系统时，成绩单作为成绩写入依据，缓考申请作为状态变更凭证，补考安排作为考试通知来源。更新节奏为每学期成绩录入、缓考审批、补考排定后各同步一次。字段特征：课程名称、学分、成绩、日期、签字、回执。常见不一致：同一课程在两份材料里的名称、学分、日期对不上；版本未同步；缺签字或回执。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。版本台账与变更记录由后续节点解析响应，或外部系统按约定处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 成绩单 | 字段、日期与签字需与缓考申请、补考安排一致 | 核对课程名称、学分、成绩、日期、签字；用 `responseData` 比对返回字段 |
| 缓考申请 | 字段、日期与签字需与成绩单、补考安排一致 | 核对课程、原因、申请日期、审批签字；用 `variables` 追踪占位来源 |
| 补考安排 | 字段、日期与回执需与成绩单、缓考申请一致 | 核对课程、时间、地点、回执；用 `Authorization` 核对鉴权信息 |
| HTTP 节点 | 请求地址、请求头、请求体与变量来源可核 | 在请求预览里看渲染后的完整地址与返回字段 |

## 容易做错的三处

- 现象：同一课程在成绩单与补考安排里的名称、学分、日期对不上。原因：两份材料各自维护，未做字段比对与版本同步。
- 现象：缓考申请已更新，成绩单仍引用旧版，版本未同步。原因：变更后未更新知识库或对外文档，引用未同步。
- 现象：成绩单缺签字，补考安排缺回执。原因：材料流转环节未收齐签字与回执，直接进入接口。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；检查 `Authorization`、`variables`、`responseData` 是否可追溯。

业务测试：改一处内容，看版本号与引用是否同步更新

- 在变量面板核对每个占位的来源，确认请求地址、请求头、请求体三处占位能解析成实际值。
- 用一条样例请求比对返回字段，核对请求头名称与取值来源，确认字段与外部接口约定一致。
