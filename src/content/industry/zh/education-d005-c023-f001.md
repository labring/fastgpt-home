# 学生处分与申诉处理的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

本页面向学生处分与申诉处理场景，聚焦违纪事实材料、处分决定书、申诉书三类品类材料的资料版本与变更维护。违纪事实材料记录行为经过、时间地点与证据清单；处分决定书承载处分依据、决定内容、生效日期与签字盖章；申诉书包含申诉请求、事实理由、提交日期与回执信息。三类材料在提交、送达、归档、复核各环节分批产生，更新节奏由处分流程节点驱动。材料进入 HTTP 接口与外部系统功能时，各自承担不同角色：违纪事实材料作为事实底稿供比对，处分决定书作为现行版本主记录，申诉书作为程序性回执凭据。字段特征集中在名称、数量、日期、签字与回执编号，任一处变更都需同步版本台账与引用位置。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。版本台账与变更记录由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 模块向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 违纪事实材料 | 名称、数量、日期与签字须与处分决定书一致 | 取一条记录，比对两份材料中的名称、数量、日期与签字栏，核对 `variables` 占位来源 |
| 处分决定书 | 现行版本唯一，旧版可追，引用同步 | 在版本台账中确认现行版本号唯一，检查旧版归档与引用位置是否同步更新 |
| 申诉书 | 申诉请求、日期与回执信息齐全 | 核对申诉书提交日期、回执编号与签字，确认 `responseData` 返回字段与约定一致 |
| 请求头与请求体 | 鉴权信息与字段约定一致 | 核对 `Authorization` 请求头取值来源，用一条样例请求比对返回字段 |

## 容易做错的三处

- 现象：同一记录在违纪事实材料与处分决定书中名称、数量、日期对不上。原因：两份材料分别录入，未以现行版本为基准做字段比对。
- 现象：处分决定书已更新，知识库或对外文档仍引用旧版。原因：版本台账未同步，引用位置未随版本号变更而更新。
- 现象：申诉书缺签字或回执编号。原因：提交环节未校验签字与回执字段，后续节点解析响应时未拦截空字段。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `variables` 与 `responseData` 取值正确。

业务测试：改一处内容，看版本号与引用是否同步更新

- 在变量面板核对每个占位的来源，确认请求地址、请求头与请求体中的变量能解析成实际值。
- 用一条样例请求比对返回字段，检查现行版本唯一、旧版可追、引用同步。
