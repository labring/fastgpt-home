# 职业院校人才培养方案制定的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

职业院校人才培养方案制定涉及人才培养方案、课程标准、岗位能力分析表三类材料，字段含专业名称、课程名称、学时学分、岗位名称、能力条目、制定日期与签字栏。材料来自教务、二级学院与行业企业调研，更新节奏随专业调整、课程改革与岗位能力变化触发。进入 HTTP 接口与外部系统环节时，人才培养方案作为主记录承载版本号与生效日期，课程标准与岗位能力分析表作为引用材料挂接其下，三者字段须在名称、数量、日期与签字上一致，方可形成现行版本唯一、旧版可追、引用同步的版本台账与变更记录。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「版本台账与变更记录」由后续节点解析响应，或外部系统按约定处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 人才培养方案 | 版本号、生效日期与签字栏须与课程标准、岗位能力分析表引用一致 | 在请求体里带方案编号与版本号，核返回字段中的版本与日期 |
| 课程标准 | 课程名称、学时学分与方案中的课程列表逐项对得上 | 把课程条目作为变量传入，比对返回的课程字段与方案记录 |
| 岗位能力分析表 | 岗位名称、能力条目数量与方案中的培养目标表述一致 | 用一条样例请求比对返回的能力条目数与签字回执字段 |
| 请求头与变量来源 | 鉴权信息按外部系统要求传入，每个占位能追到出处 | 核对 `Authorization` 名称与取值来源，在变量面板检查 `variables` 与 `responseData` |

## 容易做错的三处

- 现象：同一课程在两份材料里的名称或学时对不上。原因：课程标准更新后未同步回人才培养方案，引用未随版本刷新。
- 现象：旧版方案仍被外部系统取用，现行版本不唯一。原因：变更记录未回写，版本号与生效日期未随改动作废旧版。
- 现象：岗位能力分析表缺签字或回执，台账无法闭环。原因：外部系统按约定处理时未把签字字段纳入返回，后续节点无从校验。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `Authorization`、`variables`、`responseData` 三处占位均解析成实际值。

业务测试：改一处内容，看版本号与引用是否同步更新。

- 在请求预览里看渲染后的完整地址，核对路径参数、请求头与请求体三处占位是否解析成实际值。
- 用一条样例请求比对返回，确认人才培养方案、课程标准、岗位能力分析表的名称、数量、日期与签字字段一致。
