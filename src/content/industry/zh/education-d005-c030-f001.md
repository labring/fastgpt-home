# 职业学校学生实习管理的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

职业学校学生实习管理涉及实习协议、实习计划、实习日志三类核心材料。实习协议含单位与监护人签字、起止日期；实习计划含岗位、轮岗安排与指导教师；实习日志含每日记录、周签字与回执。材料来源分散在教务、二级学院与实习单位，更新节奏随学期与岗位变动。进入 HTTP 接口与外部系统功能时，协议作为外部审批回执的比对基准，计划作为排程字段的来源，日志作为过程数据回写对象。三者字段、日期与签字需在版本台账中保持现行版本唯一、旧版可追、引用同步，避免同一记录在两份材料里的名称、数量、日期对不上，或版本未同步、缺签字与回执。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。版本台账与变更记录由后续节点解析响应，或外部系统按约定处理接着完成。请求地址、路径参数、请求头与请求体均可用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 实习协议 | 字段、日期与签字是否与外部回执一致 | 核对请求体字段与协议签字日期，用样例请求比对返回，检查 `responseData` 中回执字段 |
| 实习计划 | 岗位、轮岗与指导教师字段是否与外部排程一致 | 在请求预览中看渲染后的完整地址，核对路径参数与请求体字段，确认 `variables` 来源 |
| 实习日志 | 每日记录、周签字与回执是否与外部系统一致 | 核对请求头名称与取值来源，确认 `Authorization` 鉴权信息按外部系统要求传入 |
| 请求地址与路径参数 | 占位变量能解析成实际值 | 在请求预览里看渲染后的完整地址，比对样例请求返回 |

## 容易做错的三处

- 现象：同一记录在协议与日志里的名称、数量、日期对不上。原因：两处字段来源不同且未在版本台账中做引用同步。
- 现象：旧版协议仍被外部系统引用，现行版本不唯一。原因：版本未同步，变更后未更新知识库或对外文档。
- 现象：外部系统收到空字段或请求返回 401。原因：占位变量未解析、鉴权信息未按外部系统要求传入或请求超时。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `responseData`、`variables` 与 `Authorization` 均按约定出现。

业务测试：改一处内容，看版本号与引用是否同步更新

- 在变量面板核对每个占位的来源，确认全局变量、系统变量或前方节点输出可追溯
- 用一条样例请求比对返回，核对请求头名称与取值来源，确认字段与外部接口约定一致
