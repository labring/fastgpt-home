# 技工院校学制教育管理的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

技工院校学制教育管理涉及学籍注册表、教学计划、技能训练记录三类核心材料，各自含字段、日期与签字要素。学籍注册表记录学生身份与在读状态，教学计划规定课程与课时安排，技能训练记录反映实训项目与考核结果。材料来源为教务系统、教学部门与实训车间，更新节奏随学期注册、计划调整与训练进度变化。材料进入 HTTP 接口与外部系统功能时，节点只输出响应体、状态码与返回字段，版本台账与变更记录由后续节点解析响应，或外部系统按约定处理接着完成。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「版本台账与变更记录」由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 学籍注册表 | 字段含学生姓名、学号、注册日期与签字栏，日期与签字须与教务系统一致 | 在请求体里比对学号、注册日期与签字回执字段，核`variables`来源 |
| 教学计划 | 字段含课程名称、课时数量、生效日期与审批签字，数量与日期须与教学部门版本一致 | 在请求头传入`Authorization`，核课程名称与课时数量是否与现行版本相同 |
| 技能训练记录 | 字段含训练项目、完成数量、考核日期与指导教师签字，数量与日期须与实训车间记录一致 | 在请求预览里看渲染后的完整地址，核`responseData`返回字段与样例比对 |
| 请求地址与路径参数 | 占位变量能解析成实际值，路径参数与外部接口约定一致 | 在请求预览里看渲染后的完整地址，核占位变量是否解析成实际值 |

## 容易做错的三处

- 现象：同一学籍记录在注册表与教学计划里的姓名、学号或日期对不上。原因：两处材料各自维护，未以现行版本为唯一基准做字段比对。
- 现象：教学计划调整后技能训练记录仍引用旧版课程名称与课时数量。原因：版本未同步，旧版未标记失效，引用未随现行版本更新。
- 现象：技能训练记录缺指导教师签字或回执，外部系统收到空字段。原因：签字与回执未纳入接口字段校验，请求体字段与约定不一致。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认`responseData`与样例一致。

业务测试：改一处内容，看版本号与引用是否同步更新，并核学籍注册表、教学计划、技能训练记录的字段、日期与签字。

- 在变量面板核对每个占位的来源，确认`variables`、`Authorization`与`responseData`均有明确出处。
- 用一条样例请求比对返回，核请求头名称与取值来源，并检查请求体字段与外部接口约定一致。
