# 职业院校技能竞赛组织的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

职业院校技能竞赛组织的资料版本与变更维护，核心材料是竞赛规程、报名表与训练计划。竞赛规程来自主办方发布，含赛项名称、组别、日期、场地与签字栏；报名表来自参赛队提交，含选手姓名、身份证号、组别与领队签字；训练计划来自指导教师，含阶段安排、课时与负责人签字。三类材料在赛事筹备、报名截止、赛前集训三个节点更新。字段特征上，同一记录的名称、数量、日期在两份材料里容易对不上，版本未同步时旧版仍被引用，缺签字或回执导致材料不完整。材料进入 HTTP 接口与外部系统时，竞赛规程作为基准版本源，报名表作为校验输入，训练计划作为过程记录，各自承担不同角色，通过接口把版本台账与变更记录推送到外部系统。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「版本台账与变更记录」由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 模块向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 竞赛规程 | 赛项名称、组别、日期与签字栏在现行版本中唯一且可追溯 | 核对请求体字段与规程原文是否一致，用一条样例请求比对返回 |
| 报名表 | 选手姓名、数量、组别与领队签字在两份材料里对得上 | 核对请求头 `Authorization` 与请求体字段来源，确认无空字段 |
| 训练计划 | 阶段安排、课时与负责人签字与现行版本同步 | 核对变量面板中每个占位的出处，确认 `variables` 与 `responseData` 可追 |
| 版本台账 | 旧版可追、引用同步，改一处内容后版本号与引用同步更新 | 预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果 |

## 容易做错的三处

- 现象：同一记录在竞赛规程与报名表里的名称、数量、日期对不上。原因：两份材料各自维护，未以现行版本为基准做字段比对。
- 现象：旧版训练计划仍被外部系统引用，版本未同步。原因：变更后未推送新版本，引用方仍按旧版处理。
- 现象：报名表缺领队签字或回执，材料不完整。原因：提交环节未校验签字栏，回执未随请求体一并传递。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；确认 `Authorization`、`variables`、`responseData` 三处占位可追。

业务测试：改一处内容，看版本号与引用是否同步更新。

- 在请求预览里看渲染后的完整地址，核对路径参数占位变量能解析成实际值。
- 在变量面板核对每个占位的来源，确认请求头名称与取值来源符合外部系统要求。
