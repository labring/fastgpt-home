# 职业技能等级认定社会评价的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

职业技能等级认定社会评价涉及评价实施方案、考生报名表、考评员派遣表等材料。这些材料来自评价机构内部编制与外部报送，需按批次更新并维护版本台账。评价实施方案含评价职业、等级、科目、日期与考评方式；考生报名表含姓名、身份证号、申报等级、工作年限与签字；考评员派遣表含考评员姓名、证书编号、派遣日期与签字。材料进入 HTTP 接口时，评价实施方案作为请求体主体，考生报名表与考评员派遣表作为附件字段或路径参数引用，各自承担不同角色。更新节奏随政策调整或批次变更触发，要求现行版本唯一、旧版可追、引用同步。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。版本台账与变更记录由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 评价实施方案 | 字段、日期与签字需与考生报名表、考评员派遣表一致 | 核对方案中的职业名称、等级、评价日期与签字栏，比对报名表和派遣表对应字段 |
| 考生报名表 | 姓名、数量、日期与实施方案、派遣表对不上即为不一致 | 抽取一条报名记录，在实施方案与派遣表中查找同名同数量记录，核日期与签字回执 |
| 考评员派遣表 | 派遣日期、考评员数量与实施方案、报名表需同步 | 核对派遣表签字与回执，检查版本号是否与现行实施方案一致 |
| 请求地址与路径参数 | 占位变量能解析成实际值 | 在请求预览里看渲染后的完整地址 |

## 容易做错的三处

- 现象：同一考生姓名在报名表与派遣表里写法不同。原因：两份材料分别录入，未做字段对齐与版本同步。
- 现象：评价日期在实施方案与报名表中相差数日。原因：版本未同步，旧版引用未更新，导致日期对不上。
- 现象：考评员派遣表缺签字或回执。原因：外部系统未按约定回传，HTTP 节点只输出响应体与状态码。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果。检查 `Authorization` 请求头、`variables` 变量来源与 `responseData` 返回字段。

业务测试：改一处内容，看版本号与引用是否同步更新

- 在变量面板核对每个占位的来源，确认 `variables` 能追到全局变量、系统变量或前方节点输出
- 用一条样例请求比对返回，检查 `responseData` 字段与外部接口约定一致，并记录数组条数
