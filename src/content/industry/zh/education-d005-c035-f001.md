# 企业自主技能人才评价的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

企业自主技能人才评价涉及三类材料：评价备案表、评价规范、考生花名册。备案表含评价机构、职业名称、等级、批次与日期，需签字或回执；评价规范含考核方式、权重与评分细则；花名册含考生姓名、证件号、申报等级与数量。材料来自申报、审核与考务环节，更新节奏随批次调整、规范修订与人员变更而变。进入 HTTP 接口与外部系统功能时，备案表用于触发备案状态同步，评价规范用于拉取或推送版本号与生效日期，花名册用于批量校验与回执确认。字段、日期与签字是核验要点，同一记录在两份材料里的名称、数量、日期对不上，或版本未同步、缺签字或回执，都会导致台账与变更记录失真。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。版本台账与变更记录由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点只负责发请求与接收返回，不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 评价备案表 | 备案表字段、日期与签字须与评价规范、花名册一致，且现行版本唯一 | 核验请求体中的备案表字段与签字回执，比对返回字段与本地台账 |
| 评价规范 | 规范版本号与生效日期须与备案表、花名册引用同步，旧版可追 | 核验请求地址与路径参数中的版本占位，用 `variables` 追每个占位来源 |
| 考生花名册 | 花名册姓名、数量与日期须与备案表、规范一致，缺签字或回执即异常 | 核验请求头 `Authorization` 与请求体字段，比对 `responseData` 中的回执状态 |
| HTTP 请求预览 | 请求地址、请求头与请求体三处占位变量能解析成实际值 | 在请求预览里看渲染后的完整地址，核对请求头名称与取值来源 |

## 容易做错的三处

- 现象：同一考生在花名册与备案表里的姓名或数量对不上。原因：两份材料各自维护，未在请求体里统一引用同一变量源。
- 现象：评价规范已修订，但外部系统仍按旧版处理。原因：版本未同步，请求地址或请求体中的版本占位未随台账更新。
- 现象：备案表缺少签字或回执，返回字段却显示成功。原因：请求头鉴权信息与外部系统约定不一致，或请求体字段为空。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；同时核对请求头 `Authorization`、变量 `variables` 与返回 `responseData` 是否一致。

业务测试：改一处内容，看版本号与引用是否同步更新。

- 在变量面板核对每个占位来源，确认请求地址、请求头与请求体三处变量都能解析成实际值。
- 用一条样例请求比对返回，核验返回字段中的版本号、日期与签字回执是否与台账一致。
