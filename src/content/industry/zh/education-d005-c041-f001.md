# 企业合规与安全培训的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

企业合规与安全培训场景中，合规培训课件、安全操作规程、考试记录是三类核心材料。课件按法规更新节奏迭代，规程随设备与工艺变更调整，考试记录则按批次归档。这些材料进入 HTTP 接口与外部系统的环节时，各自承担不同角色：课件与规程作为版本台账的受控对象，其名称、生效日期、修订标识需在请求体中准确传递；考试记录作为回执类材料，需携带签字状态与归档日期。材料来源分散在文档库、培训系统与考试平台，更新节奏受监管要求驱动，字段特征集中在版本号、生效日期、签字栏与引用关系上。进入该功能后，请求负责把材料标识与变更信息送往外部系统，响应则回传落库结果与引用同步状态。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。版本台账与变更记录由后续节点解析响应，或外部系统按约定处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 合规培训课件 | 版本号、生效日期与签字栏需与台账一致 | 核请求体中的版本字段与课件签批日期，比对返回的落库标识 |
| 安全操作规程 | 修订标识与引用关系需同步更新 | 核请求头中的 `Authorization` 取值来源，确认规程引用路径随版本变更 |
| 考试记录 | 名称、数量、日期与回执签字需对得上 | 核 `variables` 面板中每个占位的出处，比对样例请求返回的签字状态 |
| 请求地址与路径参数 | 占位变量能解析成实际值 | 在请求预览里看渲染后的完整地址，核 `responseData` 中的引用同步字段 |

## 容易做错的三处

- 现象：同一考试记录在两份材料里的名称与日期对不上。原因：请求体字段未按外部接口约定映射，占位变量取自不同节点输出。
- 现象：课件版本已更新，外部系统仍引用旧版。原因：变更记录未随请求发出，引用同步依赖后续节点解析响应后处理。
- 现象：考试记录缺签字或回执。原因：请求头鉴权信息与外部系统要求不一致，返回字段中签字状态为空。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果。

业务测试：改一处内容，看版本号与引用是否同步更新。

- 在变量面板核对每个占位的来源，确认 `variables` 与 `Authorization` 取值可追溯。
- 用一条样例请求比对返回，检查 `responseData` 中版本台账与变更记录字段是否完整。
