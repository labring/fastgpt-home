# 自费出国留学申请服务的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

自费出国留学申请服务的材料以留学服务合同、学校申请表、个人陈述为主，字段涵盖名称、数量、日期与签字，来源多为顾问录入、学生回传与校方模板。更新节奏受申请轮次与截止日期驱动，合同条款、表格字段与文书段落会在不同节点反复修订。材料进入 HTTP 接口与外部系统这一环时，合同承担条款与签收依据，学校申请表承担字段与日期基准，个人陈述承担内容版本与引用来源，三者共同决定资料版本与变更维护能否做到现行版本唯一、旧版可追、引用同步。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。版本台账与变更记录由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 模块向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 留学服务合同 | 名称、数量、日期与签字须与学校申请表一致，缺签字或回执即视为未生效 | 核对合同字段与申请表字段逐项比对，检查签字与回执是否齐全 |
| 学校申请表 | 字段、日期与签字须与个人陈述引用的记录对齐，同一记录名称与数量不得对不上 | 用一条样例请求比对返回，查看日期与数量字段是否与合同一致 |
| 个人陈述 | 内容版本须与现行版本唯一对应，旧版可追，引用同步更新 | 改一处内容后查看版本号与引用是否同步，并核对 `variables` 来源 |
| HTTP 请求配置 | 请求地址与路径参数能解析成实际值，请求头鉴权按外部系统要求传入 | 在请求预览里看渲染后的完整地址，核对请求头名称与取值来源 |

## 容易做错的三处

- 现象：同一记录在合同与申请表里的名称、数量、日期对不上。原因：两处材料各自修订，未做字段级比对与回执核验。
- 现象：个人陈述改了内容，版本号与引用未同步。原因：变更记录未随请求体一起提交，旧版无法追溯。
- 现象：请求返回 401 或外部系统收到空字段。原因：请求头鉴权信息与请求体字段未按外部接口约定传入，占位变量来源不明。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；在变量面板核对每个占位来源，确认 `Authorization`、`variables`、`responseData` 可追溯。

业务测试：改一处内容，看版本号与引用是否同步更新。

- 在请求预览里看渲染后的完整地址，核对请求头名称与取值来源
- 用一条样例请求比对返回，检查请求体字段与外部接口约定是否一致
