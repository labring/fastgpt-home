# 国际学生招生与学籍管理的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

国际学生招生与学籍管理涉及招生简章、录取通知书、签证申请表三类材料，字段包含姓名、护照号、专业、学制、报到日期、签字与回执。招生简章发布课程与费用框架，录取通知书锁定个人录取信息，签证申请表承载使领馆所需字段。材料来源为招生办公室、院系与签证事务岗，更新节奏随招生批次、录取轮次与签证政策调整。进入 HTTP 接口与外部系统环节时，简章提供版本基线，通知书与申请表提供记录级字段，三者共同构成版本台账与变更记录的比对对象。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「版本台账与变更记录」由后续节点解析响应，或外部系统按约定处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 国际学生招生简章 | 简章字段、日期与签字在版本间一致，旧版可追 | 取简章现行版与上一版，比对课程名称、费用项、日期与签字位，核对 `variables` 占位来源 |
| 录取通知书 | 通知书与简章、签证申请表的名称、数量、日期对得上 | 抽一条录取记录，在三份材料里比对姓名拼写、专业名称、报到日期与回执状态 |
| 签证申请表 | 申请表字段与使领馆约定一致，签字与回执齐全 | 用一条样例请求比对返回字段，核对 `Authorization` 请求头取值来源 |
| HTTP 接口与外部系统 | 响应体、状态码与返回字段可解析，引用同步更新 | 在请求预览里看渲染后的完整地址，核对 `responseData` 字段与版本号 |

## 容易做错的三处

- 现象：同一记录在简章与通知书里的专业名称、报到日期对不上。原因：两处字段各自维护，未以同一版本台账为基线比对。
- 现象：旧版简章仍被外部系统引用，现行版本不唯一。原因：变更记录未同步，引用方未按版本号重新拉取。
- 现象：签证申请表缺签字或回执，外部系统收到空字段。原因：请求体字段与外部接口约定不一致，变量占位未解析。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `responseData` 与 `variables` 占位解析正确。

业务测试：改一处内容，看版本号与引用是否同步更新

- 在变量面板核对每个占位的来源，确认 `Authorization` 请求头与请求体字段取值可追。
- 取一条样例请求比对返回，记录数组条数与引用文本的 tokens，分开登记引用条数与引用内容预算。
