# 成人高考报名与录取管理的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

成人高考报名与录取管理涉及三类核心材料：报名表、照顾加分材料、录取名册。报名表由考生填报，字段含姓名、身份证号、报考层次、科类、学习形式、联系电话、签字确认；照顾加分材料由考生提交证明并附审核签字与回执；录取名册由招生部门按批次生成，含考生号、录取专业、录取日期、经办签字。三类材料进入资料版本与变更维护功能时，报名表作为基准记录源，照顾加分材料作为条件变更源，录取名册作为结果输出源。更新节奏随报名、审核、录取三阶段推进，字段特征集中在名称、数量、日期与签字回执。同一记录在三份材料中须保持一致，版本变更后引用同步更新。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「版本台账与变更记录」由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 模块向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位；变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 报名表 | 字段、日期与签字是否与现行版本一致 | 核对姓名、身份证号、报考层次、签字日期，确认现行版本唯一 |
| 照顾加分材料 | 名称、数量、日期是否与报名表对得上 | 比对加分项目名称、证明份数、审核日期与回执签字 |
| 录取名册 | 录取记录与报名表、加分材料是否同源 | 核对考生号、录取专业、录取日期与经办签字 |
| HTTP 节点输出 | 响应体字段与外部接口约定是否一致 | 预览渲染后的请求，核对 `Authorization`、`variables`、`responseData` 与状态码 |

## 容易做错的三处

- 现象：同一考生在两份材料里的名称、数量、日期对不上。原因：报名表与照顾加分材料各自维护，变更未回写基准记录。
- 现象：旧版材料仍被引用，现行版本不唯一。原因：版本未同步，引用未随变更更新，台账缺少变更记录。
- 现象：材料缺签字或回执，录取名册无法追溯。原因：审核环节未回传签字结果，外部系统未按约定处理。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `Authorization`、`variables`、`responseData` 与约定一致。

业务测试：改一处内容，看版本号与引用是否同步更新

- 在变量面板核对每个占位的来源，确认路径参数、请求体与请求头变量能解析成实际值
- 用一条样例请求比对返回，核对请求头名称与取值来源，记录引用文本的 tokens 与数组条数
