# 科研经费预算调整与报销的资料版本与变更维护：文档解析与分块

## 这个品类的数据长什么样

本页面向科研经费预算调整与报销场景，材料来自预算调整申请、报销单、合同发票三类，更新节奏随预算周期与报销批次推进，字段包含名称、数量、日期、签字与回执。预算调整申请承载调整事由与额度变动，报销单承载费用明细与审批流，合同发票承载交易凭证与开票信息。三者进入文档解析与分块功能时，各自被切分为可检索的数据行，并绑定唯一数据标识；同一记录在多份材料中的名称、数量与日期需保持一致，版本台账与变更记录由检索与后续处理完成，确保现行版本唯一、旧版可追、引用同步。

## 配置怎么定

解析与训练任务（服务端任务）只输出数据行与索引状态（已解析、索引中、已完成），版本台账与变更记录要由检索与后续处理接着做。解析分块在解析完成后立即落库为可见数据行并绑定唯一数据标识，索引按已解析、索引中、已完成三态流转，待索引数据不参与召回，换模型只对已完成索引的数据重建。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 预算调整申请 | 名称、数量、日期与签字需与报销单、合同发票逐项一致，缺签字或回执视为不完整 | 打开数据行核对状态是否为 parsed / indexing / indexed，并分别核对文件记录与数据行 |
| 报销单 | 同一记录在三份材料中的名称、数量、日期对不上时，以现行版本为准并记录变更 | 核对重建任务覆盖的数据行，确认只覆盖已完成索引的数据 |
| 合同发票 | 版本未同步时旧版可追但不可召回，引用需指向现行版本 | 检查 `chunkSize` 与 `chunkSplitter` 设置后，核对引用文本的 tokens 与数组条数分别记录 |
| 数据行 | 处于三态之一且与界面显示一致，训练失败数据可直接编辑或删除 | 核对 `trainingType` 与索引状态流转，确认待索引数据不参与召回 |

## 容易做错的三处

- 现象：刚上传的材料搜不到。原因：数据行处于待索引状态，检索层天然隔离不被召回，需等待索引完成。
- 现象：同一记录在两份材料里的名称、数量、日期对不上。原因：版本未同步，旧版可追但引用仍指向旧版，缺少签字或回执。
- 现象：训练失败后留下空数据行。原因：初次训练覆盖待索引与索引中的数据，重建只针对已完成索引的数据，两者不能互换。

## 怎么确认配好了

本功能验收：上传一份材料，看数据行状态流转与重建任务的覆盖范围，确认 parsed / indexing / indexed 三态与界面显示一致，重建只覆盖已完成索引的数据。

业务测试：改一处内容，看版本号与引用是否同步更新，并核对 `chunkSize`、`chunkSplitter`、`trainingType` 三个标识符对应的数据行与索引状态。

- 打开数据行核对状态是否为 parsed / indexing / indexed，并分别核对文件记录与数据行
- 查看重建任务覆盖的数据行，确认只覆盖已完成索引的数据，待索引数据不参与召回
