# 学术不端举报调查处理的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

本页面向学术不端举报调查处理场景，材料包括举报材料、调查报告、专家鉴定意见三类。举报材料由受理方登记编号、日期与回执；调查报告由调查组填写结论、签字与附件清单；专家鉴定意见由专家签署并注明日期。三类材料在版本台账中各自承担不同角色：举报材料作为原始依据，调查报告作为过程结论，专家鉴定意见作为专业支撑。更新节奏随调查阶段推进，每次补正或复核均产生新版本。字段特征集中在名称、数量、日期、签字与回执，需保证现行版本唯一、旧版可追、引用同步。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「版本台账与变更记录」由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点只负责按约定发请求，不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 举报材料 | 字段、日期与签字是否与台账一致 | 核名称、数量、日期、签字与回执，比对 `responseData` 返回字段 |
| 调查报告 | 版本号是否唯一且旧版可追 | 核现行版本号与历史版本，检查 `variables` 占位来源 |
| 专家鉴定意见 | 引用是否同步更新 | 改一处内容后比对引用文本与 `Authorization` 请求头鉴权结果 |
| HTTP 请求体 | 字段与外部接口约定一致 | 用样例请求比对返回，核 `responseData` 字段 |

## 容易做错的三处

- 现象：同一记录在举报材料与调查报告里的名称、数量、日期对不上。原因：两处各自录入，未以台账为唯一来源。
- 现象：调查报告更新后专家鉴定意见仍引用旧版。原因：版本未同步，引用未随变更刷新。
- 现象：举报材料缺回执或调查报告缺签字。原因：流转环节未校验签字与回执字段。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果。

业务测试：改一处内容，看版本号与引用是否同步更新。

- 在变量面板核对每个占位的来源，确认请求地址与路径参数能解析成实际值。
- 核对请求头名称与取值来源，确认请求体字段与外部接口约定一致。
