# 高校实验室安全分级分类的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

高校实验室安全分级分类涉及实验室分级分类表、危险源清单、安全责任书三类材料。分级分类表记录实验室名称、房间号、危险等级与判定日期；危险源清单记录危险源名称、数量、存放位置与更新日期；安全责任书记录责任人、签字与回执日期。材料来自资产、保卫与院系三方，按学年或危险源变动触发更新。进入 HTTP 接口与外部系统功能时，分级分类表作为主数据提供实验室标识与等级，危险源清单提供分级依据字段，安全责任书提供责任人与签字状态。三类材料需保持同一实验室的名称、数量与日期一致，旧版可追溯，引用同步到知识库或对外文档。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。版本台账与变更记录由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 实验室分级分类表 | 实验室名称、房间号、危险等级与判定日期在三类材料中一致，现行版本唯一 | 在请求体与路径参数中用 `variables` 引用分级分类表字段，预览渲染后比对返回字段 |
| 危险源清单 | 危险源名称、数量、存放位置与更新日期与分级分类表引用同步 | 核对请求头 `Authorization` 取值来源，用一条样例请求比对危险源数量与日期 |
| 安全责任书 | 责任人、签字与回执日期齐全，旧版可追 | 在变量面板核对每个占位来源，检查 `responseData` 中签字与回执字段是否返回 |
| 请求地址与路径参数 | 占位变量能解析成实际值，地址与外部接口约定一致 | 在请求预览里看渲染后的完整地址，核对路径参数取值 |

## 容易做错的三处

- 现象：同一实验室在分级分类表与危险源清单里的名称、数量对不上。原因：两份材料各自维护，未通过 HTTP 接口同步引用字段。
- 现象：安全责任书缺签字或回执，版本未同步。原因：变更后未重新发起请求，旧版仍被引用。
- 现象：请求返回 401 或外部系统收到空字段。原因：请求头鉴权信息未按外部系统要求传入，变量占位未解析成实际值。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；检查 `Authorization`、`variables`、`responseData` 三处取值与来源。

业务测试：改一处内容，看版本号与引用是否同步更新。

- 在变量面板核对每个占位的来源，确认来自全局变量、系统变量或前方节点输出。
- 用一条样例请求比对返回字段与三类材料的名称、数量、日期，记录数组条数与引用文本 tokens。
