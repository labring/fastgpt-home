# 实验室危化品采购与台账的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

实验室危化品采购与台账涉及采购申请、领用登记、库存台账三类材料。采购申请含品名、规格、数量、申请日期与审批签字；领用登记含领用人、领用日期、用途与回执；库存台账含结存数量、存放位置与盘点日期。材料来自采购系统、仓储记录与人工填报，更新节奏随每次采购、领用与盘点变动。字段特征为名称、数量、日期、签字四类信息分散在多份材料中。进入该功能时，采购申请与领用登记作为请求体字段来源，库存台账作为外部系统返回字段的比对依据，三者在版本台账与变更记录中各自承担源数据、流转记录与结果核对的角色。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。版本台账与变更记录由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 模块向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 采购申请 | 名称、数量、日期与签字在申请与台账中一致 | 取一条采购申请，比对申请日期、审批签字与库存台账入库日期 |
| 领用登记 | 领用人、领用日期、数量与回执在登记与台账中对应 | 取一条领用登记，核对领用数量与台账出库数量、回执签字 |
| 库存台账 | 现行版本唯一，旧版可追，引用同步 | 改一处数量，看版本号与引用该数量的材料是否同步更新 |
| HTTP 请求 | 请求地址、请求头与请求体中的占位变量能解析成实际值 | 在请求预览里看渲染后的完整地址，核对 `Authorization` 与 `variables` 来源 |

## 容易做错的三处

- 现象：同一采购记录在申请与台账里的数量、日期对不上。原因：两份材料各自维护，未以同一版本号同步更新。
- 现象：旧版领用登记仍被引用，现行版本不唯一。原因：变更后未更新版本台账，引用未同步替换。
- 现象：领用登记缺领用人签字或回执。原因：领用流程未闭环，登记材料未按字段要求补齐。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `responseData` 中字段与约定一致。

业务测试：改一处内容，看版本号与引用是否同步更新。

- 在变量面板核对每个占位的来源，确认来自全局变量、系统变量或前方节点输出。
- 取一条样例请求比对返回字段，核对请求体字段与外部接口约定一致。
