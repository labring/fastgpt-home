# 学术期刊来稿初审的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

学术期刊来稿初审环节，材料通常包括投稿稿件、作者信息表、查重报告三类。稿件承载正文与题录，作者信息表承载署名、单位、联系方式与签字，查重报告承载检测时间、重复率区间与回执。三类材料来源不同：稿件由投稿系统或邮箱进入，作者信息表随稿件附带或单独补交，查重报告由检测工具导出。更新节奏上，稿件可能因修回产生新版本，作者信息表可能因署名调整重签，查重报告可能因复检重新出具。字段特征集中在名称、数量、日期与签字四类：稿件标题与作者信息表标题须一致，作者数量与署名顺序须对应，收稿日期、修回日期与查重日期须能串成时间线，签字与回执须可追。材料进入 HTTP 接口与外部系统时，各自承担不同角色：稿件提供版本比对基准，作者信息表提供身份与授权凭据，查重报告提供外部检测结论，三者共同支撑版本台账与变更记录的形成。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。版本台账与变更记录由后续节点解析响应，或外部系统按约定处理接着完成。请求地址与路径参数、请求头、请求体三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 投稿稿件 | 标题、收稿日期、修回日期与版本号须与作者信息表、查重报告对得上 | 在请求预览里看渲染后的完整地址，核对稿件标题与日期占位是否解析成实际值 |
| 作者信息表 | 作者名称、数量、署名顺序与签字须与稿件题录一致 | 核对请求头名称与取值来源，确认鉴权信息按外部系统要求传入，并比对作者字段 |
| 查重报告 | 检测日期、重复率区间与回执须与稿件版本对应 | 用一条样例请求比对返回，核对查重字段与外部接口约定是否一致 |
| 请求变量 | 每个占位都能追到具体出处 | 在变量面板核对每个占位的来源，确认来自全局变量、系统变量或前方节点输出 |

## 容易做错的三处

- 现象：同一篇稿件在作者信息表与查重报告里的标题、作者数量或收稿日期对不上。原因：两份材料分别维护，未以同一版本号作为比对基准。
- 现象：稿件已修回并产生新版本，作者信息表与查重报告仍停留在旧版。原因：版本变更未同步到全部材料，台账未记录变更时间与责任人。
- 现象：作者信息表缺少签字，或查重报告缺少回执。原因：材料流转环节未设置签字与回执的完整性核对，导致后续节点无法确认授权。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；同时确认 `Authorization`、`variables`、`responseData` 三处引用可追。

业务测试：改一处内容，看版本号与引用是否同步更新

- 在变量面板逐项核对占位来源，确认请求地址与路径参数、请求头、请求体中的变量都能解析成实际值
- 用一条样例请求比对返回字段，确认外部系统收到的作者名称、数量、日期与签字字段非空且与材料一致
