# 学术期刊经营合作管理的资料版本与变更维护：HTTP 接口

## 这个品类的数据长什么样

学术期刊经营合作管理涉及经营合作协议、广告审查表、发行合作材料三类材料。经营合作协议含合作方名称、合作期限、分成比例、签字与盖章日期；广告审查表含广告主、刊期、版面、审查意见与签字；发行合作材料含发行渠道、数量、起止日期与回执。材料来自编辑部、广告部与发行部，按刊期或月度更新。进入 HTTP 接口与外部系统功能时，三类材料各自作为请求体字段来源：协议提供合作方与期限，广告审查表提供刊期与版面，发行合作材料提供渠道与数量。字段特征为名称、数量、日期、签字四类需与外部系统记录逐项对齐，版本号与引用关系需随内容变更同步维护。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。版本台账与变更记录由后续节点解析响应，或外部系统按约定处理接着完成。请求地址、路径参数、请求头与请求体三处均可用 `variables` 占位，鉴权信息按外部系统要求放入 `Authorization`。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 经营合作协议 | 合作方名称、合作期限、分成比例、签字与盖章日期需与外部系统记录一致 | 在请求预览里看渲染后的完整地址与请求体，核对协议字段与 `variables` 来源 |
| 广告审查表 | 广告主、刊期、版面、审查意见与签字需与刊期记录对齐 | 用一条样例请求比对返回的 `responseData`，核对刊期与版面字段 |
| 发行合作材料 | 发行渠道、数量、起止日期与回执需与协议记录对齐 | 核对请求头名称与取值来源，确认 `Authorization` 按外部系统要求传入 |
| 版本台账与变更记录 | 现行版本唯一、旧版可追、引用同步 | 改一处内容后查看版本号与引用是否同步更新，并记录数组条数与引用文本的 tokens |

## 容易做错的三处

- 现象：同一记录在经营合作协议与发行合作材料里的名称、数量、日期对不上。原因：两份材料各自维护，未以现行版本为唯一来源。
- 现象：内容已改，版本号与引用未同步。原因：变更只落在单份材料，未触发版本台账更新。
- 现象：广告审查表缺签字或回执。原因：审查意见未回填，请求体字段为空导致外部系统收到空字段。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；确认 `variables` 与 `Authorization` 取值来源可追。

业务测试：改一处内容，看版本号与引用是否同步更新。

- 在变量面板核对每个占位的来源，确认请求地址、路径参数、请求头与请求体中的 `variables` 均能解析成实际值。
- 用一条样例请求比对返回的 `responseData`，核对字段与外部接口约定一致，并记录数组条数与引用文本的 tokens。
