# 中小学招生入学组织的进度记录与统计核对：HTTP 接口

## 这个品类的数据长什么样

中小学招生入学组织的进度记录与统计核对，材料来自招生方案、报名材料清单、录取名单三处。招生方案定日程与批次，报名材料清单列证件与回执，录取名单载学生与签字。材料按周更新，字段含名称、数量、日期、签字状态。进入 HTTP 接口与外部系统这一功能时，招生方案作请求路径参数与请求体的依据，报名材料清单提供请求头鉴权与字段校验，录取名单作为响应体返回字段的比对源。统计口径说明写在进度表表头，记录数与统计数逐周对账。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「进度表与统计口径说明」由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 招生方案 | 字段、日期与签字须与报名材料清单、录取名单逐项对齐 | 在请求预览里看渲染后的完整地址，核路径参数与请求体字段是否取自方案 |
| 报名材料清单 | 名称、数量、日期、回执须与录取名单一致 | 核对请求头名称与取值来源，用一条样例请求比对返回字段 |
| 录取名单 | 签字与日期在名单与进度表表头口径一致 | 在变量面板核对每个占位的来源，确认 `variables` 可追到名单字段 |
| HTTP 节点 | 只输出响应体、状态码与返回字段，不写库不审批 | 核 `responseData` 字段与 `Authorization` 请求头，再对一条样例比对结果 |

## 容易做错的三处

- 现象：同一记录在报名材料清单与录取名单里的名称、数量对不上。原因：两处字段来源未统一，请求体与响应体字段映射错位。
- 现象：招生方案版本未同步，进度表仍按旧批次统计。原因：请求路径参数引用了过期变量，未随方案更新。
- 现象：录取名单缺签字或回执，统计合计仍计入。原因：请求头鉴权通过但返回字段未含签字状态，后续节点未校验例外。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；检查 `responseData` 与 `Authorization` 是否按约定解析。

业务测试：用一周记录核对合计，看口径与例外是否写清；引用条数与 `quoteMaxToken` 分别记录，核引用文本的 tokens。

- 在请求预览里看渲染后的完整地址，核对路径参数与请求体字段是否与招生方案、报名材料清单一致。
- 在变量面板核对每个占位的来源，确认 `variables` 能追到全局变量、系统变量或前方节点输出。
