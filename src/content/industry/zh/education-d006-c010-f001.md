# 中小学课程表与课后服务排课的进度记录与统计核对：HTTP 接

## 这个品类的数据长什么样

本页面向中小学课程表与课后服务排课的进度记录与统计核对材料，涵盖总课表、教师任课表、课后服务项目表三类来源。总课表提供班级与节次基准，教师任课表提供任课人与课时依据，课后服务项目表提供项目名称、参与人数与日期。材料按周更新，月末汇总，字段包含课程名称、任课教师、班级、日期、节次、项目名称、参与人数、签字与回执。材料进入 HTTP 接口与外部系统时，各自承担数据源角色：总课表用于核对周合计，教师任课表用于核对任课一致性，课后服务项目表用于核对项目统计口径。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「进度表与统计口径说明」由后续节点解析响应，或外部系统按约定处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 总课表 | 字段是否含班级、节次、日期与签字，日期与教师任课表是否一致 | 抽取一周总课表，核对班级、节次与日期字段，检查签字与回执是否齐全 |
| 教师任课表 | 任课教师名称与数量是否与总课表同一记录对得上，版本是否同步 | 用一周记录核对教师任课表与总课表的名称、课时数量，标记不一致项 |
| 课后服务项目表 | 项目名称、参与人数、日期与签字是否与统计口径说明表头一致 | 核对项目表与进度表合计，检查例外项是否在口径说明中写明 |
| HTTP 节点请求 | 请求地址与路径参数占位变量能否解析成实际值，请求头与请求体字段是否与外部接口约定一致 | 在请求预览里查看渲染后的完整地址，核对 `Authorization` 与 `variables`，用一条样例请求比对 `responseData` 返回字段 |

## 容易做错的三处

- 现象：同一记录在总课表与教师任课表里的课程名称、课时数量对不上。原因：两份材料更新节奏不同，版本未同步，缺少统一核对节点。
- 现象：课后服务项目表与统计口径说明的日期、参与人数不一致。原因：口径未写到表头，例外项未标注，后续节点解析时直接按默认字段取值。
- 现象：周报或月报中缺签字或回执，统计合计与记录数对不上。原因：材料流转时未检查签字字段，外部系统回执未按约定返回。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `responseData` 中字段与外部接口约定一致。

业务测试：用一周记录核对合计，看口径与例外是否写清，检查总课表、教师任课表、课后服务项目表的记录数与统计数是否对得上。

- 在变量面板核对每个占位的来源，确认 `Authorization` 与 `variables` 能追到全局变量、系统变量或前方节点输出。
- 用一条样例请求比对返回，检查请求体字段与外部接口约定一致，避免外部系统收到空字段。
