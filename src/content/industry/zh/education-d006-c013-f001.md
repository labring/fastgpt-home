# 中小学教师培训学分管理的进度记录与统计核对：HTTP 接口

## 这个品类的数据长什么样

中小学教师培训学分管理涉及培训通知、学分认定表、参训名单三类材料。培训通知给出项目名称、起止日期与参训对象；学分认定表承载学时、学分与认定结论；参训名单提供人员身份与签到依据。三类材料通常按培训批次产生，随培训结束、认定审核、名单确认分批更新，字段包含教师姓名、身份证件号、项目编号、课程名称、学时数、认定日期、签字与回执。进入进度记录与统计核对功能时，培训通知作为项目口径来源，学分认定表作为学分数量来源，参训名单作为人数与身份来源，三者共同支撑进度表与统计口径说明的生成。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「进度表与统计口径说明」由后续节点解析响应，或外部系统按约定处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 培训通知 | 项目名称、起止日期与参训对象在通知与认定表间须一致，签字与回执齐全 | 比对通知与认定表的项目编号、日期字段，查看签字栏与回执附件 |
| 学分认定表 | 学时、学分与认定日期在认定表与参训名单间须对得上，版本须同步 | 逐条核对认定表与名单的姓名、数量、日期，检查版本号与签字 |
| 参训名单 | 人员身份与签到记录须与认定表一致，缺签字或回执须标注 | 用名单核对认定表人数与日期，查看回执与签字是否缺失 |
| HTTP 节点 | 请求地址与路径参数中的 `variables` 能解析成实际值，`Authorization` 按外部系统要求传入 | 在请求预览里看渲染后的完整地址，核对请求头名称与取值来源，用一条样例请求比对返回的 `responseData` |

## 容易做错的三处

- 现象：同一记录在通知与认定表里的名称、数量、日期对不上。原因：两份材料分别维护，未做字段级比对与版本同步。
- 现象：参训名单与认定表人数不一致，缺签字或回执。原因：名单更新后未回写认定表，签字环节未闭环。
- 现象：请求返回 401 或外部系统收到空字段。原因：`Authorization` 取值来源有误，或 `variables` 占位未解析成实际值。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `variables`、`Authorization`、`responseData` 均符合约定。

业务测试：用一周记录核对合计，看口径与例外是否写清。

- 在变量面板核对每个占位的来源，确认请求地址、请求头与请求体中的占位都能追到全局变量、系统变量或前方节点输出。
- 用一条样例请求比对返回字段，检查请求体字段与外部接口约定一致，并记录数组条数与引用文本的 tokens 预算。
