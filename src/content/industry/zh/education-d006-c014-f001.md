# 学校德育与班主任工作的进度记录与统计核对：HTTP 接口

## 这个品类的数据长什么样

学校德育与班主任工作里，主题班会方案、学生综合素质记录、家访记录是三类基础材料，来源为班主任日常填写、年级组汇总与德育处归档，更新节奏按周或按月。三类材料字段各有侧重：主题班会方案含主题、日期、签字；学生综合素质记录含姓名、数量、日期、签字；家访记录含对象、日期、回执。进入 HTTP 接口与外部系统功能时，主题班会方案作为进度表主体，学生综合素质记录作为统计口径来源，家访记录作为例外核对依据，三者共同支撑记录数与统计数对得上、口径写到表头。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「进度表与统计口径说明」由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 模块向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 主题班会方案 | 名称、日期与签字在进度表中可追溯 | 在请求预览里看渲染后的完整地址，核对 `variables` 来源 |
| 学生综合素质记录 | 数量与统计口径写到表头，与记录数对得上 | 核对请求头名称与取值来源，确认 `Authorization` 传入 |
| 家访记录 | 日期与回执字段与外部接口约定一致 | 用一条样例请求比对返回，检查 `responseData` 字段 |
| 请求地址与路径参数 | 占位变量能解析成实际值 | 在变量面板核对每个占位的来源 |

## 容易做错的三处

- 现象：同一记录在两份材料里的名称、数量、日期对不上。原因：统计口径未写到表头，进度表与原始记录各自维护。
- 现象：版本未同步，旧版方案与新记录混用。原因：材料更新节奏不统一，未按周或按月核对。
- 现象：缺签字或回执，记录无法追溯。原因：家访记录与班会方案未按字段要求逐项确认。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果。

业务测试：用一周记录核对合计，看口径与例外是否写清。

- 在变量面板核对每个占位的来源，确认 `variables` 与 `Authorization` 可追到具体出处。
- 用一条样例请求比对返回，检查 `responseData` 字段与外部接口约定一致。
