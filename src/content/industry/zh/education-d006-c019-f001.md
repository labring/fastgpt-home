# 选课排课与教室资源调度的进度记录与统计核对：HTTP 接口

## 这个品类的数据长什么样

选课排课与教室资源调度的材料分三层：开课计划、排课表、选课规则。开课计划来自教务与院系，含课程名称、课程号、学期、起止日期与签字栏；排课表来自排课岗，含教室、周次、节次、任课教师与回执；选课规则来自选课管理，含选课人数上限、先修要求与例外说明。三类材料按周更新，学期初集中修订。进入进度记录与统计核对功能时，开课计划充当课程基准，排课表充当教室与时间基准，选课规则充当人数与例外基准；三者字段、日期与签字需逐项对齐，才能形成进度表与统计口径说明，供周报或月报引用。

## 配置怎么定

工作流里的 HTTP 节点只输出响应体、状态码与返回字段，进度表与统计口径说明要由后续节点解析响应，或外部系统按约定处理接着做。HTTP 模块向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 开课计划 | 课程名称、课程号、学期与起止日期须与排课表逐项一致，签字栏完整 | 在变量面板核对每个占位的来源，确认开课计划字段进入请求体后与排课表同名同值 |
| 排课表 | 教室、周次、节次与任课教师须与选课规则中的时间地点描述一致，回执齐全 | 用一条样例请求比对返回，检查排课表日期与选课规则日期是否对得上 |
| 选课规则 | 选课人数上限、先修要求与例外说明须与开课计划容量字段一致，版本同步 | 核对请求头名称与取值来源，确认选课规则版本与开课计划版本同步 |
| 请求地址与路径参数 | 占位变量能解析成实际值，路径参数与外部接口约定一致 | 在请求预览里看渲染后的完整地址，核对 `variables` 与 `responseData` 字段 |

## 容易做错的三处

- 现象：同一课程在开课计划与排课表里名称、数量、日期对不上。原因：两份材料由不同岗位维护，未做字段级比对。
- 现象：选课规则已更新，排课表仍用旧版本，统计合计出现偏差。原因：版本未同步，缺少统一更新节点。
- 现象：排课表缺签字或回执，进度表无法确认教室占用。原因：签字环节未纳入核对清单，回执未随请求返回。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；在变量面板核对 `variables` 与 `responseData` 的来源。

业务测试：用一周记录核对合计，看口径与例外是否写清，核对开课计划、排课表、选课规则的字段、日期与签字。

- 在请求预览里看渲染后的完整地址，核对 `Authorization` 请求头名称与取值来源。
- 用一条样例请求比对返回，检查请求体字段与外部接口约定是否一致。
