# 成绩录入与学分认定的进度记录与统计核对：HTTP 接口

## 这个品类的数据长什么样

成绩录入与学分认定涉及成绩单、缓考申请、补考安排三类材料，来源为教务系统导出、任课教师提交与学院汇总，更新节奏按周推进，字段特征含课程名称、学分、成绩、日期与签字栏。成绩单是主记录，缓考申请是例外来源，补考安排是后续修正依据；三者进入进度记录与统计核对功能时，分别承担基准、例外与调整角色，需在进度表与统计口径说明中各自落位。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「进度表与统计口径说明」由后续节点解析响应，或外部系统按约定处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 成绩单 | 课程名称、学分、成绩、日期与签字是否与缓考申请、补考安排对得上 | 逐条比对三份材料里的名称、数量与日期，缺签字或回执的标记出来 |
| 缓考申请 | 缓考课程与成绩单中的记录是否同一名称、同一数量、同一日期 | 核对申请日期与签字栏，确认版本与当前进度表同步 |
| 补考安排 | 补考后的成绩是否回写成绩单，日期与签字是否齐全 | 用补考安排逐条核对成绩单更新记录，检查回执是否留存 |
| HTTP 请求 | `Authorization`、`variables` 与 `responseData` 是否按约定传入与返回 | 在请求预览里看渲染后的完整地址，核对请求头名称与取值来源 |

## 容易做错的三处

- 现象：同一记录在成绩单与缓考申请里的名称、数量、日期对不上。原因：两份材料各自录入，未按同一口径对齐字段。
- 现象：补考安排已更新，成绩单仍是旧版本，版本未同步。原因：更新节奏不同，缺少统一的进度表与统计口径说明。
- 现象：缓考申请或补考安排缺签字或回执，无法核对合计。原因：材料流转环节未要求签字回执，记录数与统计数对不上。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；检查 `Authorization`、`variables`、`responseData` 是否按约定出现。

业务测试：用一周记录核对合计，看口径与例外是否写清，确认记录数与统计数对得上。

- 在变量面板核对每个占位的来源，确认请求地址、请求头与请求体中的变量能解析成实际值。
- 用一条样例请求比对返回，核对字段与外部接口的约定是否一致。
