# 培训机构招生咨询转化的进度记录与统计核对：HTTP 接口

## 这个品类的数据长什么样

培训机构招生咨询转化涉及招生简章、咨询记录、试听课安排三类材料。招生简章由市场或教务提供，含课程名称、班型、日期与签章；咨询记录由咨询师逐条登记，含学员姓名、意向课程、联系方式与跟进日期；试听课安排由教务排期，含试听时间、授课教师、签到与回执。材料按周汇总、按月归档，字段名称与数量在简章、记录、安排之间需保持一致，签字与回执缺一不可。进入进度记录与统计核对功能时，简章作为口径来源，咨询记录作为明细来源，试听课安排作为例外与核销来源，三者共同支撑进度表与统计口径说明的生成。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「进度表与统计口径说明」由后续节点解析响应，或外部系统按约定处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 招生简章 | 课程名称、班型、日期与签章在各材料间一致 | 取简章与咨询记录逐字段比对，核对名称、数量、日期与签字 |
| 咨询记录 | 同一记录在简章与试听安排中的名称、数量、日期对得上 | 按学员与日期排序，抽查三条记录核对字段与回执 |
| 试听课安排 | 试听时间、授课教师、签到与回执齐全且版本同步 | 核对排期版本号与签到回执，确认无缺签字 |
| HTTP 节点 | 请求地址、请求头与请求体按外部接口约定传入 | 在请求预览里看渲染后的完整地址，核对 `Authorization` 与 `variables` 来源 |

## 容易做错的三处

- 现象：同一学员在咨询记录与试听安排里的名称、数量、日期对不上。原因：两份材料各自登记，未按统一口径核对字段。
- 现象：简章版本更新后咨询记录仍引用旧班型与旧日期。原因：版本未同步，材料之间缺少比对环节。
- 现象：试听安排缺签到或回执，进度表无法确认例外。原因：签字与回执未随记录归档，统计口径未写到表头。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `responseData` 与 `variables` 取值一致。

业务测试：用一周记录核对合计，看口径与例外是否写清，确认记录数与统计数对得上。

- 在变量面板核对每个占位的来源，确认 `Authorization` 与 `variables` 能追到具体出处。
- 用一条样例请求比对返回，核对请求体字段与外部接口约定一致，避免外部系统收到空字段。
