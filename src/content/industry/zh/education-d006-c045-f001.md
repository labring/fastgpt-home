# 校外培训合规备案与处罚应对的进度记录与统计核对：HTTP 接

## 这个品类的数据长什么样

校外培训合规备案与处罚应对场景中，材料主要来自办学许可证、课程备案材料、收费公示三类。办学许可证提供机构名称、地址、有效期与发证日期；课程备案材料记录课程名称、课时、开课日期与签字；收费公示对应收费项目、金额、退费规则与公示日期。三类材料按周或按月更新，字段特征为名称、数量、日期、签字、回执。材料进入进度记录与统计核对功能时，办学许可证作为主体身份基准，课程备案材料作为课程进度与统计对象，收费公示作为收费口径与例外说明来源。HTTP 模块负责向外部系统发起请求，把三类材料中的字段与日期作为变量传入，供后续节点解析响应后生成进度表与统计口径说明。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「进度表与统计口径说明」由后续节点解析响应，或外部系统按约定处理接着完成。请求地址、请求头与请求体三处均可用 `variables` 占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 办学许可证 | 机构名称、地址、有效期、发证日期与签字是否与课程备案材料一致 | 在请求预览里看渲染后的完整地址，核对许可证字段与课程备案材料对应字段的日期与签字 |
| 课程备案材料 | 课程名称、课时、开课日期与签字是否与收费公示中的名称、数量、日期对得上 | 用一条样例请求比对返回，核对课程备案材料与收费公示的字段、日期与签字 |
| 收费公示 | 收费项目、金额、退费规则与公示日期是否与课程备案材料版本同步 | 核对请求头名称与取值来源，比对收费公示与课程备案材料的版本与回执 |
| HTTP 请求变量 | 每个占位能追到具体出处，`Authorization` 与 `responseData` 字段来源明确 | 在变量面板核对每个占位的来源，确认请求头与请求体字段与外部接口约定一致 |

## 容易做错的三处

- 现象：同一记录在办学许可证与课程备案材料里的名称、数量、日期对不上。原因：两份材料各自维护，未在请求前统一字段口径与日期格式。
- 现象：收费公示与课程备案材料版本未同步，进度表与统计数出现差异。原因：HTTP 请求引用的变量来自旧版本节点输出，未更新到最新材料。
- 现象：课程备案材料缺签字或回执，统计核对时无法确认记录有效。原因：材料流转环节未把签字与回执作为必填字段传入请求体。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `Authorization` 与 `responseData` 字段符合约定。

业务测试：用一周记录核对合计，看口径与例外是否写清，确认记录数与统计数对得上、口径写到表头。

- 在请求预览里核对渲染后的完整地址、请求头与请求体，确认每个占位变量能解析成实际值。
- 用一条样例请求比对返回，核对办学许可证、课程备案材料与收费公示的字段、日期与签字是否一致。
