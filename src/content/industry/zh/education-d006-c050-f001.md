# 外籍教师聘任与课程安排的进度记录与统计核对：HTTP 接口

## 这个品类的数据长什么样

外籍教师聘任与课程安排涉及三类材料：聘任合同、工作许可材料、课程安排表。聘任合同载明聘期、课时与签字页；工作许可材料含证件号、许可期限与回执；课程安排表记录任课教师、班级、周次与日期。材料来自人事与外事岗位，按周更新，字段以名称、数量、日期、签字为特征。进入本功能时，三类材料各自作为独立记录源：合同提供聘任关系与课时基数，工作许可材料提供合法任教期限，课程安排表提供实际排课明细。三者作为请求体与请求头的取值来源，由 HTTP 节点向外部系统发出，进度表与统计口径说明由后续节点或外部系统按约定完成。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。进度表与统计口径说明由后续节点解析响应，或外部系统按约定处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 聘任合同 | 字段须含教师名称、聘期起止日期与签字页；同一记录在合同与课程安排表中的名称、日期须一致 | 在请求预览里看渲染后的完整地址，核对合同字段是否随请求体发出 |
| 工作许可材料 | 字段须含证件号、许可期限与回执；同一记录在许可材料与合同中的日期须对得上 | 核对请求头名称与取值来源，确认鉴权信息按外部系统要求传入 |
| 课程安排表 | 字段须含任课教师、班级、周次与课时数；同一记录在安排表与合同中的课时数须一致 | 用一条样例请求比对返回，确认字段与外部接口的约定一致 |
| 变量来源 | 每个占位都能追到具体出处，`variables` 中的取值可回溯 | 在变量面板核对每个占位的来源，确认 `Authorization` 与 `responseData` 的引用路径 |

## 容易做错的三处

- 现象：同一记录在合同与课程安排表里的教师名称、课时数对不上。原因：两份材料各自录入，未按同一口径核对。
- 现象：工作许可材料版本未同步，许可期限与合同聘期出现错位。原因：更新节奏不同，旧版本仍被引用。
- 现象：合同缺签字或回执，记录数与统计数对不上。原因：签字页未回传，统计时把未生效记录计入合计。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；核 `Authorization`、`variables`、`responseData` 三处引用是否可追溯。

业务测试：用一周记录核对合计，看口径与例外是否写清；核对记录数与统计数是否对得上，口径是否写到表头。

- 核对请求头名称与取值来源，确认鉴权信息按外部系统要求传入。
- 用一条样例请求比对返回，确认字段与外部接口的约定一致。
