# 高校实验室安全分级分类的进度记录与统计核对：HTTP 接口

## 这个品类的数据长什么样

高校实验室安全分级分类，材料来自实验室分级分类表、危险源清单与安全责任书。分级分类表按实验室房间与类别逐条登记，危险源清单记录种类、数量与存放位置，安全责任书落到责任人与签字日期。更新节奏上，分级分类表随实验室调整或学期复核更新，危险源清单随采购、领用、处置变动，责任书随人员变更或年度签订刷新。字段特征集中在名称、数量、日期与签字四类，同一实验室在不同材料里的叫法、计数与生效日期需要能对上。材料进入进度记录与统计核对功能时，分级分类表提供实验室维度与类别，危险源清单提供数量与位置，责任书提供签字与回执状态，三者共同构成进度表与统计口径说明的原始依据。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。进度表与统计口径说明由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 实验室分级分类表 | 名称、类别与生效日期要与危险源清单、安全责任书对得上 | 逐条比对同一实验室在三份材料里的名称与日期，不一致处标记后回查原始登记 |
| 危险源清单 | 数量与存放位置在统计口径里要落到表头，并注明例外 | 按周汇总数量，核对合计与逐条记录是否一致，例外单独列出 |
| 安全责任书 | 签字与回执状态要能追溯到责任人与签订日期 | 检查签字栏与回执记录，缺签字或回执的条目单独列出并注明原因 |
| HTTP 请求 | 请求地址、请求头与请求体中的变量占位能解析成实际值 | 在请求预览里看渲染后的完整地址，核对 `Authorization` 请求头与 `variables` 来源，比对一条样例的 `responseData` |

## 容易做错的三处

- 现象：同一实验室在分级分类表与危险源清单里的名称不一致。原因：两份材料由不同人员在不同时间登记，未做统一命名与同步核对。
- 现象：危险源数量在清单与统计表里对不上。原因：领用或处置后只更新一处，版本未同步，统计时仍取旧数据。
- 现象：安全责任书缺签字或回执。原因：人员变更后未及时补签，或回执未归档，核对时无法追溯责任人。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；确认 `Authorization`、`variables` 与 `responseData` 三处可追溯。

业务测试：用一周记录核对合计，看口径与例外是否写清；记录数与统计数对得上，口径写到表头。

- 在变量面板核对每个占位的来源，确认请求地址、请求头与请求体中的变量能解析成实际值。
- 用一条样例请求比对返回字段，检查外部系统是否收到空字段或返回 401，并记录超时情况。
