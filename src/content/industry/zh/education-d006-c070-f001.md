# 学术期刊经营合作管理的进度记录与统计核对：HTTP 接口

## 这个品类的数据长什么样

本页面向学术期刊经营合作管理中的进度记录与统计核对，材料来自经营合作协议、广告审查表、发行合作材料三类。经营合作协议提供合作方名称、合作期限、费用与签字栏，是进度表的主线来源；广告审查表提供广告批次、审查日期与回执签字，用于核对投放进度；发行合作材料提供发行渠道、数量、日期与签收记录，用于核对发行统计。三类材料按周或按月进入工作流，字段特征集中在名称、数量、日期、签字与回执。材料进入该功能时，各自承担不同角色：协议定口径与周期，审查表定广告节点，发行材料定数量与签收，三者共同支撑进度表与统计口径说明的生成与核对。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「进度表与统计口径说明」由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 模块向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 经营合作协议 | 字段、日期与签字是否与进度表一致 | 核对协议名称、合作期限、费用与签字栏，用一条样例比对返回字段 |
| 广告审查表 | 广告批次、审查日期与回执签字是否对得上 | 核对审查表批次与日期，检查回执签字，确认与协议口径一致 |
| 发行合作材料 | 发行渠道、数量、日期与签收是否与统计口径一致 | 核对发行数量与签收日期，检查缺签字或回执，确认与协议名称一致 |
| HTTP 请求与变量 | 占位变量能否解析成实际值 | 在请求预览里看渲染后的完整地址，核对 `Authorization`、`variables` 与 `responseData` 的来源 |

## 容易做错的三处

- 现象：同一记录在协议与发行材料里的名称、数量对不上。原因：两份材料各自维护，未按统一口径同步更新。
- 现象：广告审查表版本未同步，旧批次仍留在进度表。原因：外部系统未按约定回传最新版本，后续节点未覆盖旧记录。
- 现象：发行材料缺签字或回执，统计合计与记录数对不上。原因：签收环节未闭环，外部系统未回传确认字段。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `responseData` 与 `Authorization` 取值来源正确。

业务测试：用一周记录核对合计，看口径与例外是否写清。

- 在变量面板核对每个占位的来源，确认 `variables` 能追到全局变量、系统变量或前方节点输出。
- 用一条样例请求比对返回字段，检查请求头名称与取值来源，确认外部系统收到非空字段。
