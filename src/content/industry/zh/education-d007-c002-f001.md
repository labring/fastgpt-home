# 幼儿园游戏活动组织的异常追溯与人工复核：HTTP 接口

## 这个品类的数据长什么样

幼儿园游戏活动组织的异常追溯与人工复核，材料来自观察记录、区域计划、材料投放清单、活动目标表与反思转下周计划表。观察记录按活动场次实时产生，区域计划按周更新，材料投放数量随区域调整变动，活动目标在学期初设定并允许微调。这些材料进入 HTTP 接口与外部系统时角色不同：观察记录与区域计划作为比对源，材料投放数量作为核验项，活动目标与反思转下周计划作为复核结论的支撑。字段特征包括活动编号、区域名称、材料名称与数量、观察时间、目标条目、复核人签字位。异常追溯要求每条异常能追到源头材料，复核结论需有原始记录与签字，再交负责人处置。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。异常清单与复核结论由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 模块向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 观察记录与区域计划 | 观察到的区域活动与当周区域计划是否对应 | 取一条观察记录，比对其活动编号与区域计划中的区域名称、计划周次，在变量面板核对占位来源 |
| 材料投放数量 | 清单数量与现场实际投放是否一致 | 用一条样例请求比对返回字段中的材料名称与数量，核对请求体字段与外部接口约定是否一致 |
| 活动目标达成 | 观察记录中的行为表现与活动目标条目是否相符 | 在请求预览里看渲染后的完整地址，核对目标条目字段来源，比对返回的 `responseData` |
| 反思转下周计划 | 反思内容是否已转入下周计划并更新 | 核对请求头名称与取值来源，确认 `Authorization` 按外部系统要求传入，检查计划更新字段 |

## 容易做错的三处

- 现象：异常清单里材料数量与现场不符。原因：材料投放数量未随区域调整更新，清单仍用旧值，导致追溯时对不上源头材料。
- 现象：复核结论显示目标达成，观察记录却无对应行为。原因：活动目标与观察记录未按同一活动编号关联，目标与观察不符。
- 现象：下周计划仍沿用旧区域安排。原因：反思内容未转入下周计划，计划未更新，异常追溯找不到计划变更记录。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；同时核对 `variables` 中每个占位的来源，确认 `Authorization` 与 `responseData` 取值正确。

业务测试：造一条异常记录，看能否追到源头材料，并确认复核人签字位与负责人处置去向完整。

- 在变量面板核对每个占位的来源，确认路径参数、请求体与请求头中的变量都能解析成实际值。
- 用一条样例请求比对返回字段与外部接口约定，检查请求头名称与取值来源是否符合外部系统要求。
