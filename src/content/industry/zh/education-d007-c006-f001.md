# 幼儿园办园行为与质量自评的异常追溯与人工复核：HTTP 接口

## 这个品类的数据长什么样

本页围绕幼儿园办园行为与质量自评，材料包括自评报告、问题清单与整改计划。自评报告按学期或学年形成，字段含园所名称、指标项、自评结论、日期与签字；问题清单逐条记录问题描述、涉及指标、发现方式、责任人与整改期限；整改计划承接问题清单，记录措施、完成时间与回执。三类材料进入异常追溯与人工复核功能时，自评报告作为源头依据，问题清单作为异常线索，整改计划作为处置凭据，三者字段、日期与签字需交叉比对，形成异常清单与复核结论。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。异常清单与复核结论由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 自评报告 | 报告中的指标项与结论需与问题清单逐条对应，日期与签字齐全 | 取一条自评结论，核对指标名称、数量、日期与签字，再与问题清单比对 |
| 问题清单 | 问题描述、涉及指标与整改计划中的措施、期限需一致 | 用一条问题记录追到自评报告原文，核对名称、数量与日期是否对得上 |
| 整改计划 | 措施、完成时间与回执需与问题清单版本同步 | 核对版本号与回执签字，检查是否缺签字或回执 |
| HTTP 请求 | 请求地址、请求头与请求体中的占位变量能解析成实际值 | 在请求预览里看渲染后的完整地址，核对 `Authorization` 与 `variables` 来源，比对 `responseData` 字段 |

## 容易做错的三处

- 现象：同一问题在自评报告与问题清单里的名称、数量对不上。原因：两份材料分别录入，未做字段级比对。
- 现象：整改计划已更新，问题清单仍引用旧版本。原因：版本未同步，缺少统一版本标识。
- 现象：复核结论缺签字或回执。原因：人工复核环节未强制留痕，签字与回执未纳入核验。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `responseData` 中字段与外部接口约定一致。

业务测试：造一条异常记录，看能否追到源头材料，核对名称、数量、日期与签字。

- 在变量面板核对每个占位的来源，确认来自全局变量、系统变量或前方节点输出。
- 用一条样例请求比对返回，检查请求头名称与取值来源，排查 401 与空字段。
