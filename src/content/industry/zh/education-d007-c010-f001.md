# 中小学课程表与课后服务排课的异常追溯与人工复核：HTTP 接

## 这个品类的数据长什么样

本页面向中小学课程表与课后服务排课的异常追溯与人工复核，材料包括总课表、教师任课表、课后服务项目表，来源为教务系统导出、年级组上报与课后服务项目台账，更新节奏按周或按次调整。总课表提供班级与节次基准，教师任课表提供任课教师与学科对应，课后服务项目表提供项目名称、参与人数与场地。三类材料进入该功能时，分别作为异常清单的比对源与复核依据，字段涵盖名称、数量、日期与签字，用于定位同一条记录在不同材料间的差异。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。异常清单与复核结论由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 总课表 | 班级、节次、日期与签字是否与教师任课表一致 | 在请求预览里看渲染后的完整地址，核对总课表字段与返回字段 |
| 教师任课表 | 任课教师、学科、数量是否与课后服务项目表对应 | 核对请求头名称与取值来源，用一条样例请求比对返回 |
| 课后服务项目表 | 项目名称、参与人数、场地与回执是否缺签字 | 在变量面板核对每个占位的来源，确认 `variables` 与 `responseData` 可追溯 |
| HTTP 节点 | 路径参数、请求体与请求头三处占位变量能否解析成实际值 | 核对 `Authorization` 传入方式，在请求预览里看渲染后的完整地址 |

## 容易做错的三处

- 现象：同一记录在总课表与教师任课表里的名称、数量、日期对不上。原因：两份材料由不同环节维护，未按统一口径比对。
- 现象：课后服务项目表版本未同步，旧版仍被引用。原因：更新节奏不一致，缺少版本核对与回执确认。
- 现象：复核结论缺签字或回执，无法交负责人处置。原因：异常清单未附原始记录，签字环节被跳过。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `responseData` 与 `variables` 可追溯。

业务测试：造一条异常记录，看能否追到源头材料，核对总课表、教师任课表、课后服务项目表的日期与签字。

- 在变量面板核对每个占位的来源，确认路径参数、请求体与请求头三处变量来自全局变量、系统变量或前方节点输出。
- 用一条样例请求比对返回，核对请求头名称与取值来源，确认 `Authorization` 按外部系统要求传入。
