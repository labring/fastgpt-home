# 中小学考试命题阅卷的异常追溯与人工复核：HTTP 接口

## 这个品类的数据长什么样

本页面向中小学考试命题阅卷场景，材料包括命题双向细目表、试卷与评分细则，来源为教研组与命题组，更新节奏随考试批次与修订版本变化。字段特征集中在名称、数量、日期与签字，同一记录在三份材料中须一致。材料进入 HTTP 接口与外部系统时，双向细目表提供考点与分值分布，试卷承载题目与分值，评分细则给出给分点与复核依据。三者共同支撑异常追溯与人工复核，异常清单与复核结论须有原始记录支撑并由复核人签字，最终交负责人处置。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。异常清单与复核结论由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 命题双向细目表 | 名称、数量、日期与签字在三份材料中一致，版本同步 | 在请求预览里核对渲染后的完整地址，用 `variables` 核对占位来源，比对细目表与试卷的考点名称、数量与日期 |
| 试卷 | 题目名称、数量与日期与细目表、评分细则对得上，无缺签字 | 用一条样例请求比对返回，核 `responseData` 字段与试卷题目、分值是否一致，检查签字与回执 |
| 评分细则 | 给分点名称、数量与日期与试卷一致，版本未错位 | 核 `Authorization` 请求头取值来源，比对评分细则与试卷的给分点名称、数量与日期 |
| 异常清单与复核结论 | 异常有原始记录支撑，复核人签字齐全 | 在变量面板核对每个占位的来源，确认异常记录能追到源头材料 |

## 容易做错的三处

- 现象：同一记录在细目表与试卷里的名称、数量、日期对不上。原因：两份材料修订不同步，字段未按同一版本对齐。
- 现象：评分细则版本未同步，给分点与试卷题目错位。原因：修订后未更新接口请求体字段，外部系统收到空字段。
- 现象：复核结论缺签字或回执，异常无法交负责人处置。原因：请求返回 401 或请求超时，后续节点未解析响应。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `responseData` 与 `variables` 来源可追。

业务测试：造一条异常记录，看能否追到源头材料，核异常清单与复核结论是否有原始记录支撑并签字。

- 在请求预览里核对渲染后的完整地址与路径参数占位是否解析成实际值
- 在变量面板核对每个占位的来源，确认 `Authorization` 与 `variables` 取值来源正确
