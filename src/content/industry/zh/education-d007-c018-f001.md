# 本科培养方案修订的异常追溯与人工复核：HTTP 接口

## 这个品类的数据长什么样

本科培养方案修订涉及培养方案、课程大纲、学分结构表三类材料，来源为教务系统导出、院系提交与会议纪要附件。培养方案给出专业方向与总学分框架，课程大纲承载课程目标与考核方式，学分结构表锁定各模块学分与学期分布。材料按学年修订节奏更新，字段含课程名称、课程代码、学分、学时、开课学期、签字与日期。同一课程在培养方案与课程大纲中的名称、学分、学期须一致，学分结构表汇总值须与培养方案总学分对齐。进入异常追溯与人工复核功能时，三份材料各自作为原始记录支撑，供比对与定位差异。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。异常清单与复核结论由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 培养方案 | 课程名称、学分、总学分与签字日期须与课程大纲、学分结构表一致 | 抽取课程名称与学分字段，比对三份材料的同名课程记录，核对签字与日期 |
| 课程大纲 | 课程目标、考核方式与学分学时须与培养方案对应课程一致 | 逐条比对课程代码、学分与开课学期，检查版本号与回执 |
| 学分结构表 | 各模块学分汇总须与培养方案总学分对齐，日期与签字齐全 | 核对模块学分合计、版本日期与签字栏，标记缺签字或版本未同步项 |
| HTTP 请求 | 请求地址与路径参数、请求头、请求体、变量来源均可追溯 | 在请求预览中查看渲染后的完整地址，核对 `Authorization` 与 `variables`，比对返回字段 `responseData` |

## 容易做错的三处

- 现象：同一课程在培养方案与课程大纲中的名称、学分对不上。原因：两份材料分别修订，未做字段级比对与版本同步。
- 现象：学分结构表汇总值与培养方案总学分不一致。原因：模块学分调整后未回写另一份材料，版本未同步。
- 现象：复核结论缺签字或回执。原因：异常清单流转时未绑定原始记录与签字栏，人工复核环节遗漏。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；确认 `Authorization`、`variables`、`responseData` 均能追到来源。

业务测试：造一条异常记录，看能否追到源头材料。

- 在变量面板核对每个占位的来源，确认请求头名称与取值来源符合外部系统要求。
- 用一条样例请求比对返回字段，检查请求体字段与外部接口约定是否一致。
