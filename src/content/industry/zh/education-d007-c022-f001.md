# 学生奖助贷与困难认定的异常追溯与人工复核：HTTP 接口

## 这个品类的数据长什么样

学生奖助贷与困难认定场景里，材料分三类：家庭经济困难认定表、奖助学金申请表、贷款回执。认定表由学生填报、班级评议、院系审核，字段含家庭人口、收入来源、困难等级与评议意见；申请表记录奖项名称、金额、学年与签字栏；贷款回执由经办银行或生源地机构出具，含合同编号、放款日期与回执状态。三类材料按学年或批次更新，认定表与申请表随评议周期调整，回执随放款进度回传。进入异常追溯与人工复核功能时，认定表作为困难等级判定依据，申请表作为奖助项目与金额依据，回执作为贷款到账与合同履约依据，三者通过学号、姓名、学年等字段关联，形成可追溯的原始记录链。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。异常清单与复核结论由后续节点解析响应，或外部系统按约定处理接着完成。请求地址、路径参数、请求头与请求体均可用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 家庭经济困难认定表 | 家庭人口、收入来源、困难等级与评议签字是否齐全，日期是否落在评议周期内 | 在变量面板核对占位来源，用 `variables` 引用前方节点输出，比对认定表字段与请求体约定 |
| 奖助学金申请表 | 奖项名称、金额、学年与签字栏是否与认定表困难等级一致 | 预览渲染后的请求，核 `responseData` 返回字段是否含申请表关键字段，再对一条样例比对结果 |
| 贷款回执 | 合同编号、放款日期与回执状态是否与申请表学年匹配，回执是否缺签字 | 核对请求头 `Authorization` 与取值来源，确认回执字段按外部接口约定传入 |
| 异常记录关联 | 同一记录在认定表、申请表、回执中的姓名、金额、日期是否对得上 | 用一条异常记录追到源头材料，核三份材料字段与版本是否同步 |

## 容易做错的三处

- 现象：同一学生在认定表与申请表里的姓名、金额或日期对不上。原因：两份材料分别录入，未按学号与学年做关联校验。
- 现象：回执版本未同步，旧合同编号仍出现在异常清单里。原因：回执更新后未回传，请求体仍引用旧变量。
- 现象：认定表或申请表缺签字、贷款回执缺盖章。原因：材料流转环节未校验签字栏与回执状态，异常记录缺原始记录支撑。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；确认 `responseData` 含异常清单所需字段，`variables` 与 `Authorization` 来源可追。

业务测试：造一条异常记录，看能否追到源头材料，核认定表、申请表与回执的字段、日期与签字是否一致。

- 在变量面板核对每个占位的来源，确认 `variables` 能解析成实际值，请求头 `Authorization` 按外部系统要求传入。
- 用一条样例请求比对返回，核 `responseData` 字段与外部接口约定一致，异常清单与复核结论交负责人处置。
