# 职业学校学生实习管理的异常追溯与人工复核：HTTP 接口

## 这个品类的数据长什么样

本页聚焦职业学校学生实习管理中的异常追溯与人工复核，材料来源为实习协议、实习计划、实习日志三类原始记录，按批次或学期更新，字段涵盖学生姓名、实习单位名称、岗位、起止日期、签到数量、带教签字与单位回执。异常清单与复核结论进入该功能时，协议承担约定主体与期限的比对基准，计划承担岗位与时间安排的比对基准，日志承担逐日记录与签字的比对基准；三者名称、数量、日期与签字须相互印证，任一处对不上即触发追溯。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「异常清单与复核结论」由后续节点解析响应，或外部系统按约定处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 实习协议 | 主体名称、实习起止日期、签字与回执须与计划、日志一致 | 比对同一学生在三份材料中的单位名称与日期，缺签字或回执即标记异常 |
| 实习计划 | 岗位、批次与时间安排须与协议约定及日志记录对应 | 逐条核对计划中的岗位与日期，出现版本未同步时以最新回执版本为准 |
| 实习日志 | 逐日记录的数量、日期与带教签字须可追到源头材料 | 抽取一条日志记录，回溯其对应的协议与计划条目，核数量与日期是否吻合 |
| HTTP 节点 | 请求地址、请求头与请求体中的占位变量能解析成实际值 | 在请求预览里看渲染后的完整地址，核对 `Authorization` 与 `variables` 的取值来源 |

## 容易做错的三处

- 现象：同一学生在协议与日志里的实习单位名称不一致。原因：两份材料由不同环节录入，未按统一名称回写。
- 现象：计划中的岗位数量与日志逐日记录对不上。原因：计划版本更新后未同步到日志侧，版本未同步。
- 现象：日志缺带教签字或单位回执。原因：材料收集环节未校验签字字段，异常记录缺原始支撑。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `responseData` 中异常清单字段与原始记录一致。

业务测试：造一条异常记录，看能否追到源头材料

- 在变量面板核对每个占位的来源，确认路径参数、请求体与请求头中的变量均能追到全局变量、系统变量或前方节点输出
- 用一条样例请求比对返回字段，核对 `Authorization` 与 `variables` 的传入是否符合外部系统约定
