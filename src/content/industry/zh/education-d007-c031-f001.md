# 现代学徒制与订单班管理的异常追溯与人工复核：HTTP 接口

## 这个品类的数据长什么样

现代学徒制与订单班管理的材料包括校企合作协议、订单班培养方案、师傅带徒记录，三者共同约束同一批学徒的岗位、周期与考核。校企合作协议确定合作主体与期限，订单班培养方案写明课程与轮岗安排，师傅带徒记录逐次登记带徒日期、师傅姓名与学徒签字。材料按学期或批次更新，字段上以学徒姓名、订单班名称、师傅姓名、日期、数量、签字与回执为主。进入异常追溯与人工复核功能时，合作协议与培养方案作为比对基准，带徒记录作为被追溯的原始记录；三者名称、数量、日期不一致或版本未同步、缺签字回执时，形成异常清单并交复核人签字确认，再交负责人处置。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。异常清单与复核结论由后续节点解析响应，或外部系统按约定处理接着完成。请求地址、路径参数、请求头与请求体均可通过 `variables` 引用全局变量、系统变量或前方节点输出，鉴权信息按外部系统要求放入请求头，例如 `Authorization`。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 校企合作协议 | 协议中的合作主体、期限与订单班名称，需与培养方案、带徒记录逐项对应，日期与签字不得缺项 | 按学徒姓名与订单班名称检索协议，核对签署日期、有效期与双方签字回执 |
| 订单班培养方案 | 方案中的课程、轮岗批次与学徒数量，需与协议约定及带徒记录中的实际批次一致 | 抽取方案中的批次与人数，与带徒记录逐条比对，标记数量或日期对不上的条目 |
| 师傅带徒记录 | 每条记录应有师傅姓名、带徒日期、学徒签字与回执，且名称写法与协议、方案保持同一版本 | 以一条异常记录为入口，回溯其引用的协议条款与方案批次，查看原始材料扫描件 |
| HTTP 请求返回 | 响应体中的 `responseData` 字段应含异常标识与原始记录指针，状态码为成功返回 | 在请求预览中核对渲染后的地址与请求体，确认 `responseData` 能定位到源头材料 |

## 容易做错的三处

- 现象：同一学徒在协议与带徒记录中的姓名写法或人数对不上。原因：两份材料分别录入，未按统一字段与版本核对。
- 现象：培养方案已更新，带徒记录仍引用旧批次日期。原因：版本未同步，异常追溯时取到过期基准。
- 现象：带徒记录缺学徒签字或回执，复核无法闭环。原因：材料归档时未检查签字项，复核人无法签字确认。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，确认响应体含 `responseData` 与异常标识，再对一条样例比对结果。

业务测试：造一条异常记录，看能否追到源头材料，并核对复核人签字与负责人处置去向。

- 在变量面板核对每个占位的来源，确认路径参数、请求头与请求体中的 `variables` 均能解析成实际值
- 核对请求头名称与取值来源，确认鉴权信息按外部系统要求传入，避免返回 401 或空字段
