# 考务组织与违纪处理的异常追溯与人工复核：HTTP 接口

## 这个品类的数据长什么样

考务组织与违纪处理品类，材料含考务手册、考场记录单、违纪事实记录。考务手册定流程与字段口径，考场记录单记当次异常与监考签字，违纪事实记录记事实、数量、日期与复核签字。材料来自考务组织方与考点，按场次或批次更新，字段含名称、数量、日期、签字与回执。进入异常追溯与人工复核功能时，考务手册作比对基准，考场记录单与违纪事实记录作异常来源与原始记录，供追到源头材料并形成异常清单与复核结论。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。异常清单与复核结论由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 考务手册 | 字段口径、日期规则与签字要求应作为比对基准 | 核对手册版本与生效日期，确认名称、数量、日期字段定义 |
| 考场记录单 | 异常记录的名称、数量、日期须与违纪事实记录一致 | 逐条比对两份材料的名称、数量与日期，查缺签字或回执 |
| 违纪事实记录 | 复核结论须有原始记录支撑并由复核人签字 | 追到源头材料，核对复核人签字与处置去向 |
| HTTP 节点 | 请求地址、请求头与请求体按外部接口约定发出 | 在请求预览看渲染后地址，核对 `Authorization` 与 `variables` 来源 |

## 容易做错的三处

- 现象：同一异常在两份材料里的名称、数量或日期对不上。原因：各材料按各自口径填写，未做逐字段比对。
- 现象：考务手册版本未同步，旧口径仍被引用。原因：手册更新后未核对生效日期与引用版本。
- 现象：违纪事实记录缺复核人签字或回执。原因：复核环节未留痕，签字与回执未随材料归档。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，并核对 `responseData` 字段。

业务测试：造一条异常记录，看能否追到源头材料。

- 在变量面板核对每个占位的来源，确认能追到 `variables` 具体出处。
- 用一条样例请求比对返回字段与外部接口约定，并核对 `Authorization` 请求头。
