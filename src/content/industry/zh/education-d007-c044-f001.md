# 培训机构教务排课与消课的异常追溯与人工复核：HTTP 接口

## 这个品类的数据长什么样

培训机构教务排课与消课场景下，进入异常追溯与人工复核功能的材料主要有三类：课表、消课记录与调课申请。课表通常按周或按月更新，字段含课程名称、上课日期、授课教师、班级与签字栏；消课记录随每次课后登记产生，含学员姓名、消课数量、消课日期与回执；调课申请由教务或教师发起，含原上课日期、调整后日期、调课原因与审批签字。三类材料在异常追溯中角色不同：课表是基准参照，消课记录是被核对的执行凭证，调课申请是解释日期或数量差异的补充依据。材料更新节奏受排课调整与补录影响，需按批次归档并保留原始版本，便于后续逐条追到源头材料。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「异常清单与复核结论」由后续节点解析响应，或外部系统按约定处理接着完成。请求地址、路径参数、请求头与请求体均可通过 `variables` 引用全局变量、系统变量或前方节点输出，鉴权信息按外部系统要求放入 `Authorization`。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 课表 | 课程名称、上课日期、授课教师与签字栏是否与调课申请一致 | 取同一班级同一日期的课表与调课申请逐字段比对，核对日期与签字栏是否齐全 |
| 消课记录 | 学员姓名、消课数量、消课日期与回执是否与课表匹配 | 用一条样例请求比对返回，检查消课数量与消课日期是否对得上，回执是否缺失 |
| 调课申请 | 原上课日期、调整后日期与审批签字是否与课表版本同步 | 在变量面板核对每个占位来源，确认调课申请版本与课表版本未错位 |
| HTTP 请求 | 请求地址、请求头与请求体字段是否与外部接口约定一致 | 在请求预览里看渲染后的完整地址，核对 `Authorization` 与 `responseData` 返回字段 |

## 容易做错的三处

- 现象：同一消课记录在课表与消课记录里的学员姓名或消课数量对不上。原因：两份材料录入时间不同，未做逐字段比对。
- 现象：调课申请已更新，课表仍是旧版本，日期与教师对不上。原因：版本未同步，缺少按批次归档与版本核对。
- 现象：消课记录缺回执或调课申请缺审批签字，异常无法闭环。原因：签字与回执未纳入复核清单，源头材料不完整。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `responseData` 中异常清单字段与原始记录一致。

业务测试：造一条异常记录，看能否追到源头材料，核对课表、消课记录与调课申请三处日期、数量与签字是否可追溯。

- 在变量面板核对每个占位的来源，确认 `variables` 能解析成实际值，并核对请求头名称与取值来源。
- 用一条样例请求比对返回，检查请求体字段与外部接口约定一致，异常清单与复核结论交负责人处置。
