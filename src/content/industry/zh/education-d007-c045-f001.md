# 校外培训合规备案与处罚应对的异常追溯与人工复核：HTTP 接

## 这个品类的数据长什么样

本页聚焦校外培训合规备案与处罚应对中的异常追溯与人工复核，核心材料包括办学许可证、课程备案材料、收费公示三类。办学许可证由审批机关核发，载明机构名称、地址、办学内容与有效期限，是主体资格的原始凭证；课程备案材料由机构提交，含课程名称、课时、授课对象、教材版本与备案日期，反映实际开设内容；收费公示由机构对外发布，含收费项目、标准、退费规则与公示日期，体现价格合规。三类材料按学期或变更节点更新，字段以名称、数量、日期、签字、回执为特征。进入异常追溯与人工复核功能时，办学许可证作为主体锚点，课程备案材料作为内容比对源，收费公示作为价格与公示时序的核对依据，三者共同支撑异常清单与复核结论的生成。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。异常清单与复核结论由后续节点解析响应，或外部系统按约定处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 办学许可证 | 机构名称、地址、办学内容、有效期限与审批签字是否与课程备案材料、收费公示逐项一致 | 调取许可证原始扫描件，比对课程备案材料中的机构名称与地址，核对收费公示中的主体名称，记录日期与签字差异 |
| 课程备案材料 | 课程名称、课时、授课对象、教材版本与备案日期是否与收费公示、实际排课记录对得上 | 以课程名称为键，比对收费公示中的收费项目与课时，检查备案日期是否早于公示日期，核对版本号与回执 |
| 收费公示 | 收费项目、标准、退费规则与公示日期是否有原始记录支撑且签字齐全 | 调取公示原始发布记录，比对课程备案材料中的课时与收费项目，检查退费规则回执，确认公示日期与签字 |
| 异常清单与复核结论 | 每条异常能否追到源头材料，复核人是否签字 | 按异常编号回查原始记录，核对 `responseData` 中的字段与源材料，确认复核人签字后交负责人处置 |

## 容易做错的三处

- 现象：同一课程在备案材料与收费公示里的名称、课时数量对不上。原因：两份材料由不同岗位维护，更新时未做交叉核对，导致字段取值不一致。
- 现象：办学许可证已换发新版本，课程备案材料仍引用旧版本号。原因：版本同步机制缺失，变更后未触发关联材料的联动更新与回执确认。
- 现象：收费公示缺少退费规则签字或回执，异常记录无法追到源头。原因：公示发布环节未留存签字与回执，原始记录不完整，复核结论缺乏支撑。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；检查 `Authorization` 与 `variables` 是否按约定传入，确认 `responseData` 字段与外部接口一致。

业务测试：造一条异常记录，看能否追到源头材料，核对办学许可证、课程备案材料、收费公示的名称、数量、日期与签字，确认复核人签字后交负责人处置。

- 在变量面板核对每个占位的来源，确认请求地址、路径参数、请求头与请求体中的占位都能解析成实际值，鉴权信息按外部系统要求传入。
- 工作流里的 HTTP 节点只输出响应体、状态码与返回字段，异常清单与复核结论要由后续节点解析响应，或外部系统按约定处理接着做。
