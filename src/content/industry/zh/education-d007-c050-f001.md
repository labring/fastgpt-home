# 外籍教师聘任与课程安排的异常追溯与人工复核：HTTP 接口

## 这个品类的数据长什么样

外籍教师聘任与课程安排场景中，核心材料为聘任合同、工作许可材料与课程安排表。聘任合同含教师姓名、岗位、聘期起止、薪酬与双方签字；工作许可材料含许可编号、国籍、证件号、有效期与签发回执；课程安排表含课程名称、班级、周次、课时数与排课人签字。三类材料由人事、外事与教务分别维护，更新节奏随审批与排课变动，字段命名与日期格式常不统一。材料进入异常追溯与人工复核功能时，聘任合同作为身份与聘期基准，工作许可材料作为合规与有效期依据，课程安排表作为课时与排课事实来源，三者按教师与课程编号关联，供后续比对与复核。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。异常清单与复核结论由后续节点解析响应，或外部系统按约定处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 聘任合同 | 教师姓名、聘期起止与签字是否与工作许可材料一致 | 核对合同字段、日期与签字，在变量面板确认占位来源 |
| 工作许可材料 | 许可编号、有效期与回执是否完整并同步 | 比对许可编号与有效期，检查回执是否缺签字 |
| 课程安排表 | 课程名称、班级、课时数与排课日期是否与合同聘期相符 | 核对课程字段与日期，确认排课人签字 |
| 请求与响应 | 请求地址、请求头与请求体是否按约定渲染 | 在请求预览看渲染后完整地址，核 `Authorization` 与 `responseData` |

## 容易做错的三处

- 现象：同一教师姓名在聘任合同与工作许可材料中写法不同，追溯时无法关联。原因：两份材料各自录入，未按统一字段与编号对齐。
- 现象：课程安排表版本未同步，课时数与最新排课不一致。原因：教务修改后未回写，旧版本仍被引用。
- 现象：工作许可材料缺签字或回执，复核结论无法落笔。原因：材料流转环节未收齐，签字栏与回执未归档。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；确认 `variables` 占位均能解析，`Authorization` 按外部系统要求传入，`responseData` 字段与约定一致。

业务测试：造一条异常记录，看能否追到源头材料

- 在变量面板核对每个占位的来源，确认来自全局变量、系统变量或前方节点输出
- 用一条样例请求比对返回，检查请求头名称与取值来源是否符合外部接口约定
