# 高校招生体检组织的异常追溯与人工复核：HTTP 接口

## 这个品类的数据长什么样

高校招生体检组织材料以体检表、复检申请、受限专业告知三类为主，来源为校医院与招生办各环节，按批次和考生逐份更新。体检表记录身高体重、既往病史、医师结论与签字；复检申请记录复检项目、日期与申请人签字；受限专业告知记录受限专业名称、告知日期与考生或家长回执。进入异常追溯与人工复核功能时，体检表充当原始记录，复检申请充当变更依据，受限专业告知充当告知凭证，三者按考生标识与日期串成证据链，供复核人比对名称、数量、日期与签字是否一致。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「异常清单与复核结论」由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 模块向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 体检表 | 名称、日期与签字三者要与复检申请、受限专业告知对得上 | 取一条异常记录，核体检表里的考生名称、体检日期与医师签字，再与另两份材料逐项比对 |
| 复检申请 | 复检项目、申请日期与申请人签字要与体检表结论衔接 | 核复检申请的项目与日期是否落在体检表结论之后，签字栏是否为空 |
| 受限专业告知 | 受限专业名称、告知日期与回执要与体检表结论一致 | 核告知里的受限专业名称与体检表结论是否同名，回执是否缺失 |
| 请求体与变量来源 | 字段与外部接口约定一致，每个占位能追到出处 | 用一条样例请求比对返回，在变量面板核对 `variables` 与 `Authorization` 的来源 |

## 容易做错的三处

- 现象：同一考生在两份材料里的名称、数量或日期对不上。原因：录入时未按同一标识与日期口径回填，原始记录与变更依据脱节。
- 现象：受限专业告知的版本与体检表结论未同步。原因：告知先出、结论后改，两处未按同一批次重新对齐。
- 现象：复检申请或告知回执缺签字。原因：流转环节未收齐签字即进入复核，证据链在签字处断开。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；同时核 `responseData` 里返回的字段是否与外部接口约定一致。

业务测试：造一条异常记录，看能否追到源头材料，即由异常清单回溯到体检表、复检申请与受限专业告知的对应条目。

- 在请求预览里看渲染后的完整地址，核对路径参数与请求头取值来源，确认 `Authorization` 与 `variables` 的占位都能解析成实际值。
- 用一条样例请求比对返回字段，逐项核对请求体与外部接口约定是否一致，并记录数组条数与引用文本的 tokens 预算。
