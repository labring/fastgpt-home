# 国家重点研发计划项目申报的异常追溯与人工复核：HTTP 接口

## 这个品类的数据长什么样

国家重点研发计划项目申报涉及项目申报书、预算申报书、合作协议三类材料。项目申报书由牵头单位撰写，含研究内容、考核指标、参与单位与任务分工；预算申报书由财务与课题负责人编制，含经费科目、各科目金额与测算依据；合作协议由合作方签署，含任务分工、经费分配、知识产权归属与签字盖章页。三类材料从申报系统导出或线下签署后上传，进入 HTTP 接口与外部系统环节。更新节奏跟随申报节点：预申报、正式申报、预算评审、任务书签订，每次调整产生新版本。字段特征集中在名称、数量、日期、签字四类：同一参与单位在项目申报书与合作协议中的名称需一致，同一设备在预算申报书与项目申报书中的数量与单价需对应，起止日期与签字日期需落在申报周期内。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。异常清单与复核结论由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 项目申报书 | 参与单位名称与合作协议一致，起止日期与签字日期落在申报周期内 | 核对项目申报书参与单位名称、任务起止日期、签字页；在请求预览里看渲染后的完整地址，比对返回字段 |
| 预算申报书 | 经费科目金额与项目申报书任务量对应，设备数量与单价一致 | 核对预算申报书科目金额、设备数量、测算依据；用一条样例请求比对返回，核 `responseData` 字段 |
| 合作协议 | 合作方名称、任务分工、经费分配与项目申报书一致，签字盖章齐全 | 核对合作协议签字页与回执；核请求头名称与取值来源，鉴权信息按外部系统要求传入 `Authorization` |
| HTTP 请求变量 | 路径参数、请求体与请求头占位能解析成实际值 | 在变量面板核对每个占位的来源，变量来自全局变量、系统变量或前方节点输出，核 `variables` 来源 |

## 容易做错的三处

- 现象：同一参与单位在项目申报书与合作协议里名称写法不同，外部系统收到后无法匹配。原因：两份材料分别填写，未做名称与统一社会信用代码比对。
- 现象：预算申报书设备数量与项目申报书任务量对不上，返回字段与样例不一致。原因：版本未同步，修改后只更新一份材料，另一份仍为旧版。
- 现象：合作协议缺签字或回执，外部系统收到空字段。原因：签署流程未走完即上传，请求体字段与外部接口约定不一致。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `responseData` 与 `variables` 取值来源可追。

业务测试：造一条异常记录，看能否追到源头材料，异常有原始记录支撑、复核人签字，交负责人处置。

- 核对请求地址与路径参数占位变量能解析成实际值，在请求预览里看渲染后的完整地址。
- 核对请求头名称与取值来源，鉴权信息按外部系统要求传入，确认请求体字段与外部接口约定一致。
