# 学术不端举报调查处理的异常追溯与人工复核：HTTP 接口

## 这个品类的数据长什么样

本页面向学术不端举报调查处理场景，聚焦异常追溯与人工复核。材料分三类：举报材料（含举报人陈述、证据清单、回执）、调查报告（含调查经过、事实认定、处理建议）、专家鉴定意见（含鉴定方法、结论、专家签字）。来源为受理登记、调查组提交、专家库反馈，更新节奏随复核节点推进。三类材料进入 HTTP 接口时角色不同：举报材料提供原始记录锚点，调查报告提供比对基准，专家鉴定意见提供专业判断依据。字段特征集中在名称、数量、日期与签字四类，跨材料比对时最易暴露不一致。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。异常清单与复核结论由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 模块向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 举报材料 | 名称、数量、日期与签字是否与调查报告一致 | 调取原始记录，比对同一记录在两份材料里的名称、数量、日期，核回执是否齐全 |
| 调查报告 | 版本是否同步、签字是否完整 | 核对报告版本号与提交日期，检查调查人与复核人签字栏，确认无缺签 |
| 专家鉴定意见 | 鉴定结论与报告事实认定是否对应 | 比对鉴定方法、结论与报告事实认定，核专家签字与日期，标记差异项 |
| HTTP 请求 | 占位变量能否解析成实际值 | 在请求预览里看渲染后的完整地址，核对 `Authorization` 请求头与请求体字段，在变量面板核对 `variables` 来源 |

## 容易做错的三处

- 现象：同一记录在举报材料与调查报告里的名称、数量对不上。原因：两份材料分别录入，未做跨材料比对。
- 现象：调查报告版本未同步，旧版结论仍被引用。原因：版本号未随复核节点更新，缺少版本核对动作。
- 现象：专家鉴定意见缺签字或回执。原因：材料流转环节未校验签字栏，回执未随材料归档。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；同时核 `Authorization`、`variables` 与 `responseData` 是否按约定出现。

业务测试：造一条异常记录，看能否追到源头材料

- 在变量面板核对每个占位的来源，确认请求地址、请求头与请求体三处变量都能追到具体出处
- 用一条样例请求比对返回字段，核对外部接口约定与响应体结构是否一致
