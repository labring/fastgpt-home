# 高校实验室安全分级分类的异常追溯与人工复核：HTTP 接口

## 这个品类的数据长什么样

高校实验室安全分级分类管理，日常材料包括实验室分级分类表、危险源清单、安全责任书。分级分类表记录实验室名称、房间号、危险等级与调整日期；危险源清单登记危险源名称、数量、存放位置与更新日期；安全责任书载明责任人、签字与回执日期。这些材料按学期或学年更新，字段以名称、数量、日期、签字为核心。进入异常追溯与人工复核功能时，分级分类表用于定位实验室与等级，危险源清单用于核对异常涉及的物品与数量，安全责任书用于确认责任人与签字状态，三者共同支撑异常清单与复核结论的生成。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「异常清单与复核结论」由后续节点解析响应，或外部系统按约定处理接着完成。请求地址、路径参数、请求头与请求体均可用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 实验室分级分类表 | 名称、房间号、危险等级与调整日期须与危险源清单、安全责任书一致，签字栏不得空缺 | 在变量面板核对占位来源，预览渲染后的请求地址，比对返回字段中的名称与日期 |
| 危险源清单 | 危险源名称、数量、存放位置与更新日期须与分级分类表对应记录吻合，版本须同步 | 用一条样例请求比对返回，核对`responseData`中数量与日期字段是否与清单一致 |
| 安全责任书 | 责任人、签字与回执日期须完整，缺签字或回执视为复核不通过 | 核对请求头中的`Authorization`取值来源，确认外部系统返回的签字状态字段 |
| HTTP 节点输出 | 状态码与返回字段须能支撑异常清单与复核结论的追溯 | 在请求预览里查看渲染后的完整地址，核对`variables`中每个占位的出处 |

## 容易做错的三处

- 现象：同一危险源在分级分类表与危险源清单里的名称或数量对不上。原因：两份材料由不同人员维护，更新时未做交叉核对。
- 现象：异常记录引用的分级分类表版本与安全责任书版本未同步。原因：材料更新后未统一推送，旧版本仍在流转。
- 现象：复核结论缺少签字或回执。原因：安全责任书签字栏未填写，或回执未随异常记录一并归档。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；同时核对`Authorization`、`variables`、`responseData`三个标识符在请求与响应中的位置。

业务测试：造一条异常记录，看能否追到源头材料，确认异常有原始记录支撑、复核人签字。

- 在变量面板核对每个占位的来源，确认请求地址、路径参数、请求头与请求体中的变量均能解析成实际值。
- 用一条样例请求比对返回，检查外部系统是否收到空字段，并核对返回字段与约定是否一致。
