# 中小学心理健康筛查与转介的授权访问与对外服务：HTTP 接口

## 这个品类的数据长什么样

本页面向中小学心理健康筛查与转介场景，材料来自心理筛查方案、访谈记录、转介单三类。心理筛查方案给出量表名称、筛查日期与班级范围，是入口与授权范围的依据；访谈记录承载学生姓名、访谈时间与心理教师签字，用于核对个体信息；转介单记录转介对象、转介日期、接收方与回执签字，是对外服务的凭据。三类材料按学期与转介批次更新，字段以姓名、日期、数量、签字为核心。材料进入 HTTP 接口时，筛查方案决定可见范围，访谈记录与转介单作为请求体字段来源，供外部系统按约定读取。

## 配置怎么定

工作流里的 HTTP 节点只输出响应体、状态码与返回字段，可对外的入口与授权范围要由后续节点解析响应，或外部系统按约定处理接着做。HTTP 模块向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 心理筛查方案 | 筛查方案中的量表名称、筛查日期与班级范围，要与对外可见范围一致 | 核对请求地址与路径参数，在请求预览里看渲染后的完整地址，确认占位变量能解析成实际值 |
| 访谈记录 | 访谈记录中的学生姓名、访谈时间与心理教师签字，要与筛查方案里的名称、日期对得上 | 核对请求头名称与取值来源，确认鉴权信息按外部系统要求传入，并在变量面板核对每个占位的来源 |
| 转介单 | 转介单中的转介对象、转介日期、接收方与回执签字，要与访谈记录里的名称、数量、日期一致 | 用一条样例请求比对返回，确认请求体字段与外部接口的约定一致，并检查返回字段是否含 `responseData` |
| 变量来源 | 每个占位都能追到具体出处，鉴权信息与请求体字段不出现空值 | 在变量面板核对 `Authorization` 与 `variables` 的来源，确认请求体字段与外部接口约定一致 |

## 容易做错的三处

- 现象：同一学生在访谈记录与转介单里的姓名、日期对不上。原因：两份材料各自录入，未按筛查方案统一核对名称与日期。
- 现象：转介单缺少接收方签字或回执。原因：对外服务完成后未回填签字，材料版本未同步到最新批次。
- 现象：请求返回 401 或外部系统收到空字段。原因：请求头鉴权信息与请求体字段未按外部接口约定传入，占位变量未解析成实际值。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，确认 `responseData` 与 `Authorization`、`variables` 的来源可追，再对一条样例比对结果。

业务测试：用受限身份访问一次，看可见范围是否符合设定

- 在请求预览里核对渲染后的完整地址与路径参数，确认占位变量能解析成实际值
- 在变量面板核对 `Authorization` 与 `variables` 的来源，并用一条样例请求比对返回字段
