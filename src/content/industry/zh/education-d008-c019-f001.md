# 选课排课与教室资源调度的授权访问与对外服务：HTTP 接口

## 这个品类的数据长什么样

选课排课与教室资源调度品类，材料含开课计划、排课表、选课规则三类，来源为教务系统与人工确认件，更新节奏按学期与轮次推进。开课计划列出课程名称、班级与容量；排课表登记上课日期、节次与教室编号；选课规则写明开放对象与可选范围。三类材料进入 HTTP 接口与外部系统这一功能时，分别承担请求体字段来源、路径参数取值依据与鉴权范围判定依据。字段特征上，同一课程在两份材料里的名称、数量、日期需逐项对齐，版本以最新签字或回执为准。对外入口与授权范围由此功能输出，访问者身份与可见范围须匹配，越权不可见。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。可对外的入口与授权范围由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点向目标地址发请求，路径参数、请求体与请求头三处都能用变量占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 开课计划 | 课程名称、班级与容量在计划与排课表两份材料里须一致，日期与签字齐全 | 在请求预览里核对渲染后的完整地址与请求体字段，比对两份材料的课程名称与数量 |
| 排课表 | 上课日期、节次与教室编号在排课表与选课规则里须对齐，版本同步且有回执 | 核对请求头名称与取值来源，确认 `Authorization` 按外部系统要求传入 |
| 选课规则 | 开放对象与可选范围须与访问者身份匹配，越权不可见 | 在变量面板核对每个占位的来源，确认 `variables` 与 `responseData` 可追溯到具体出处 |
| HTTP 节点输出 | 响应体、状态码与返回字段与外部接口约定一致 | 用一条样例请求比对返回，检查返回字段是否含空值或缺失 |

## 容易做错的三处

- 现象：请求返回 401。原因：鉴权信息未按外部系统要求放入请求头，或 `Authorization` 取值来源指向了过期变量。
- 现象：同一课程在开课计划与排课表里的名称、数量或日期对不上。原因：两份材料版本未同步，缺签字或回执。
- 现象：外部系统收到空字段。原因：请求体字段与外部接口约定不一致，或 `variables` 占位未解析成实际值。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `responseData` 与约定一致。

业务测试：用受限身份访问一次，看可见范围是否符合设定，越权不可见。

- 在请求预览里看渲染后的完整地址，核对路径参数与请求体字段是否与开课计划、排课表一致。
- 核对请求头名称与取值来源，确认鉴权信息按外部系统要求传入，并检查变量面板中每个占位的出处。
