# 职业技能等级认定社会评价的授权访问与对外服务：HTTP 接口

## 这个品类的数据长什么样

本页面向职业技能等级认定社会评价的授权访问与对外服务，材料包括评价实施方案、考生报名表、考评员派遣表。评价实施方案确定评价的职业、等级与流程，是授权范围与对外入口的设定依据；考生报名表记录报考信息与签字回执，是访问者身份与可见范围的匹配来源；考评员派遣表记录派遣日期与签字，是访问者可见范围的另一来源。材料来自评价机构内部归档与业务系统导出，更新节奏随批次认定与人员调整同步。字段特征为名称、数量、日期、签字与回执，进入该功能时分别作为授权范围、身份匹配与可见范围判定的输入。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。可对外的入口与授权范围由后续节点解析响应，或外部系统按约定处理接着完成。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 评价实施方案 | 名称、数量、日期与签字在方案与报名表、派遣表之间对齐，授权范围与对外入口按方案设定 | 核对方案中的职业、等级、批次与签字日期，比对报名表与派遣表对应字段 |
| 考生报名表 | 访问者身份与可见范围匹配，越权不可见，报名表名称、数量、日期与签字回执完整 | 用受限身份访问一次，核报名表字段与回执，检查可见范围是否符合设定 |
| 考评员派遣表 | 派遣表名称、数量、日期与签字与方案、报名表一致，版本同步 | 核对派遣表签字与日期，比对方案与报名表的同名记录 |
| HTTP 请求配置 | 请求地址与路径参数占位变量能解析成实际值，请求头鉴权信息按外部系统要求传入，请求体字段与外部接口约定一致 | 在请求预览里看渲染后的完整地址，核对请求头名称与取值来源，用一条样例请求比对返回 |

## 容易做错的三处

- 现象：同一记录在评价实施方案与考生报名表里的名称、数量、日期对不上。原因：两份材料分别维护，未做字段对齐与交叉核对。
- 现象：考评员派遣表版本未同步，签字或回执缺失。原因：更新节奏不一致，旧版材料仍被引用。
- 现象：请求返回 401，外部系统收到空字段或请求超时。原因：鉴权信息未按外部系统要求传入，变量来源未追到具体出处。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；在变量面板核对 `variables`、`Authorization`、`responseData` 的来源与取值。

业务测试：用受限身份访问一次，看可见范围是否符合设定。

- 核对请求地址与路径参数占位变量能否解析成实际值，在请求预览里看渲染后的完整地址。
- 核对请求头名称与取值来源，确认鉴权信息按外部系统要求传入，并检查请求体字段与外部接口约定一致。
