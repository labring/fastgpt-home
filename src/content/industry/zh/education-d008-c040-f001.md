# 企业新员工入职培训的授权访问与对外服务：HTTP 接口

## 这个品类的数据长什么样

企业新员工入职培训材料由入职培训计划、课程签到表、岗位说明书三类构成。入职培训计划来自培训负责人，按批次更新，字段含课程名称、日期、讲师、参训岗位；课程签到表来自现场组织者，按场次更新，字段含姓名、部门、签到时间、签字；岗位说明书来自用人部门，按岗位版本更新，字段含岗位名称、职责、汇报关系、签字。三类材料进入授权访问与对外服务功能时，入职培训计划提供对外入口的课程与日期范围，课程签到表提供受限身份可见的到岗记录，岗位说明书提供岗位维度的授权边界。材料之间常出现同一记录名称、数量、日期对不上，版本未同步，缺签字或回执。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。可对外的入口与授权范围由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 模块向目标地址发请求，路径参数、请求体与请求头三处都能用 variables 占位，变量来自全局变量、系统变量或前方节点输出。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 入职培训计划 | 课程名称、日期与参训岗位在对外入口与计划原件一致 | 核对请求体字段与计划字段，确认日期与岗位无错位，并核对 `responseData` 返回字段 |
| 课程签到表 | 受限身份可见的签到记录与签到表原件姓名、数量一致 | 用受限身份请求一次，比对返回字段与签到表记录条数，确认状态码为 200 |
| 岗位说明书 | 岗位授权边界与说明书职责、汇报关系一致 | 核对 `Authorization` 取值来源与岗位范围，确认越权不可见 |
| 请求地址与路径参数 | 占位变量能解析成实际值 | 在请求预览里看渲染后的完整地址与 `responseData` 字段 |

## 容易做错的三处

- 现象：同一记录在入职培训计划与课程签到表里的名称、数量、日期对不上。原因：两份材料各自维护，未按同一批次同步字段。
- 现象：岗位说明书版本未同步，对外入口仍按旧岗位范围放行。原因：用人部门更新后未回传版本号，授权范围沿用旧值。
- 现象：课程签到表缺签字或回执，受限身份仍能看到该场次。原因：签到表未完成确认即进入对外服务，可见范围未按签字状态收敛。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果；同时核对 `variables` 来源与 `responseData` 字段是否与外部接口约定一致。

业务测试：用受限身份访问一次，看可见范围是否符合设定

- 核对请求头名称与 `Authorization` 取值来源，确认鉴权信息按外部系统要求传入
- 在变量面板核对每个占位的来源，确认路径参数、请求体与请求头中的 `variables` 都能追到全局变量、系统变量或前方节点输出
