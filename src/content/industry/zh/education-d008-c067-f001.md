# 同行评议组织的授权访问与对外服务：HTTP 接口与外部系统

## 这个品类的数据长什么样

本页面向同行评议组织的授权访问与对外服务，整理的材料包括审稿邀请、专家审稿意见、作者修改说明，以及授权范围设定与受限身份记录。材料来源为组织内部评议流程与对外服务约定，更新节奏跟随评议轮次与版本变更。这些材料进入 HTTP 接口与外部系统功能时，各自角色不同：审稿邀请决定访问者身份与可见范围，专家审稿意见与作者修改说明作为对外服务的内容依据，授权范围设定约束入口可见字段。字段特征集中在名称、数量、日期与签字或回执，同一记录在两份材料里必须一致，版本同步后才能进入对外入口。

## 配置怎么定

这一环由工作流里的 HTTP 节点执行，输出响应体、状态码与返回字段。「可对外的入口与授权范围」由后续节点解析响应，或外部系统按约定处理接着完成。HTTP 节点不代替外部系统写库或审批。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 审稿邀请 | 访问者身份与可见范围匹配，越权不可见；名称、数量、日期与签字或回执在两份材料里一致 | 核对请求头名称与取值来源，确认 `Authorization` 按外部系统要求传入 |
| 专家审稿意见 | 字段、日期与签字齐全，版本与当前评议轮次同步 | 在变量面板核对每个占位的来源，确认 `variables` 能追到具体出处 |
| 作者修改说明 | 字段与外部接口的约定一致，回执或签字不缺 | 用一条样例请求比对返回，检查 `responseData` 字段是否与约定一致 |
| 请求地址与路径参数 | 占位变量能解析成实际值，授权范围与受限身份匹配 | 在请求预览里看渲染后的完整地址 |

## 容易做错的三处

- 现象：同一记录在审稿邀请与专家审稿意见里的名称、数量或日期对不上。原因：两份材料各自维护，未按同一版本同步。
- 现象：作者修改说明缺少签字或回执，对外入口仍可见。原因：授权范围未按受限身份过滤，材料状态未回写。
- 现象：请求返回 401，外部系统收到空字段或请求超时。原因：请求头鉴权信息未按外部系统要求传入，变量占位未解析成实际值。

## 怎么确认配好了

本功能验收：预览渲染后的请求，核状态码与返回字段，再对一条样例比对结果，确认 `responseData` 与约定一致。

业务测试：用受限身份访问一次，看可见范围是否符合设定，越权内容不可见。

- 在变量面板核对每个占位的来源，确认 `variables` 与 `Authorization` 取值来源正确。
- 用一条样例请求比对返回，检查请求体字段与外部接口约定一致。
