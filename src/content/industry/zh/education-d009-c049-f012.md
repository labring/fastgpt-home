# 国际学生招生与学籍管理的多语资料与术语处理：文档解析与分块

## 这个品类的数据长什么样

国际学生招生与学籍管理涉及招生简章、录取通知书、签证申请表三类材料，来源为各校国际学生办公室与招生系统，更新节奏随招生批次与签证政策调整。招生简章含专业名称、学费、申请截止日期、签字栏；录取通知书含学生姓名、学号、录取专业、报到日期、签字与回执；签证申请表含护照姓名、出生日期、签证类型、签字。三类材料进入本功能后，招生简章与录取通知书承担术语来源与对照底稿角色，签证申请表承担字段核验与回指角色，同一术语需全篇一致且译名能回指原文，字段、日期与签字须跨材料对齐。

## 配置怎么定

这一环由解析与训练任务（服务端任务）执行，输出数据行与索引状态（已解析、索引中、已完成）。「统一术语表与对照稿」由检索与后续处理接着完成。解析分块在解析完成后立即落库为可见数据行并绑定唯一数据标识，待索引数据不参与召回。

| 对象 | 判断 | 核验动作 |
| --- | --- | --- |
| 招生简章 | 同一术语全篇一致且译名能回指原文，字段、日期与签字齐全 | 核对专业名称、学费、申请截止日期与签字栏；检查 `chunkSize` 与 `chunkSplitter` 对术语切分是否完整 |
| 录取通知书 | 学生姓名、学号、录取专业、报到日期与回执在招生简章中可对应 | 分别核对文件记录与数据行，确认同一记录的名称、数量、日期在两份材料中一致，检查 `trainingType` 取值 |
| 签证申请表 | 护照姓名、出生日期、签证类型与签字能回指原文 | 核对数据行状态处于 parsed / indexing / indexed 之一且与界面显示一致，检查签字与回执是否缺失 |
| 数据行 | 状态与界面显示一致，重建范围只覆盖已完成索引的数据 | 打开数据行核对状态，看重建任务覆盖的数据行是否只含 indexed 状态 |

## 容易做错的三处

- 现象：同一学生在录取通知书与签证申请表里的姓名、出生日期对不上。原因：同一记录在两份材料里的名称、数量、日期未做跨材料对齐。
- 现象：招生简章已更新，录取通知书仍引用旧专业名称。原因：版本未同步，旧版材料未随新批次替换。
- 现象：签证申请表缺签字或回执，材料被退回。原因：签字与回执字段未在解析后核验，缺项未被发现。

## 怎么确认配好了

本功能验收：上传一份材料，看数据行状态流转与重建任务的覆盖范围；确认状态按 parsed / indexing / indexed 流转，重建只针对已完成索引的数据，初次训练覆盖待索引数据。

业务测试：抽三条术语查全篇写法是否一致，并确认译名能回指原文。

- 打开数据行核对状态是否处于 parsed / indexing / indexed 之一且与界面显示一致
- 分别核对文件记录与数据行，确认文件记录与数据行各自的身份分得开
