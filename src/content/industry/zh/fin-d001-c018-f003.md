# 养殖业农业保险应用的分享与嵌入：作用域、免登录与边界

## 这个品类每天在处理什么材料
这个品类日常处理的材料包括养殖户资料、承保清单、耳标、个体识别或批次资料、存栏记录、检疫材料、死亡及扑杀证明、无害化处理证明、查勘定损和赔款资料。数据主要来自养殖场或农户、畜牧兽医及检疫资料、个体识别和存栏系统、无害化处理记录、农险系统。不同材料的形态与更新逻辑存在差异：存栏记录随生产过程动态变动，个体识别资料在动物新增、出栏或死亡时触发更新，检疫材料仅在检疫事件发生时生成，死亡、扑杀及无害化处理证明则在出险事件发生后同步产生。

## 这些材料在「分享与嵌入」这一环带来什么约束
多类型的业务文档要求嵌入的应用需支持解析多种格式的材料，适配不同来源的数据源接入。动态更新频率要求嵌入后的组件需支持按需或增量同步数据，避免因数据滞后导致核验错误。个体与死亡、无害化处理的强关联关系要求分享的功能需保留跨文档的关联查询能力，确保不同材料间的匹配逻辑完整。敏感类材料如赔款资料要求嵌入时需配置权限控制，避免未授权访问。同时，免登录的分享场景需兼顾数据安全与使用便捷性，平衡开放权限与敏感信息保护。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 常见取法，需按单份文档大小和解析复杂度标定 |
| `召回条数` | 前8–12条 | 常见取法，需按关联文档的关联密度调整 |
| `相似度阈值` | 0.72–0.85 | 常见取法，需按文档的字段匹配精度要求调整 |
| `分段长度` | 1000–1500 字符 | 常见取法，需按文档的字段分布和关联逻辑调整 |
| `重排返回条数` | 前3–5条 | 常见取法，需按核心核验环节的关键材料数量调整 |
| `maxContext` | 8000–12000 字符 | 常见取法，需按关联文档的总字符量标定 |

## 最耗时的环节会卡在哪
第一个环节为将承保清单与存栏、个体识别或批次资料交叉核验，该功能可自动匹配清单内个体与存栏、识别记录的关联信息，替代人工逐一核对的基础步骤，但无法替代现场核实个体实际存活状态的环节。若配置失误，可能出现召回不到对应存栏记录、抽取字段为空、结果与原件对不上的问题。第二个环节为查明死亡、疫病或扑杀原因及保险责任，功能可关联检疫、无害化处理记录匹配对应责任条款，但无法替代现场确认疫病类型与扑杀流程合规性的环节，配置不当可能导致超时中断、召回不到对应检疫材料、结果与条款匹配偏差。第三个环节为核对死亡个体、检疫或无害化处理与赔款对象，功能可自动关联耳标、无害化记录与赔款资料的主体信息，但无法替代核实赔款对象身份真实性的环节，配置失误可能出现抽取身份字段为空、结果与原件对不上、需要人工回退重做的问题。

## 做错了会怎样
该功能环节出错会引发多维度的不良后果。业务层面可能因虚构存栏、重复承保或死亡原因误判造成损失；合同层面可能因保险个体和责任认定错误引发争议；监管层面可能因虚假承保理赔被处理；农户层面可能因漏赔或身份匹配错误引发投诉。易引发此类后果的配置失误包括分段长度过短切断关联条款、召回条数过低漏掉关键材料、未开启溯源导致答复无法回原件核对、相似度阈值设置偏差导致匹配错误。

## 与相邻品类的区别
与种植业农业保险相比，本品类的核心主键为“动物/批次—存栏—检疫—死亡—无害化”，核心关联逻辑围绕个体动物的全生命周期标识与处理流程展开。种植业的核心关联逻辑则围绕地块、种植周期、遥感数据等展开，直接套用本品类的配置至种植业场景会导致核心关联核验环节失效。

## 还需要按机构实际情况确认的
- 耳标并非所有养殖险种唯一识别方式，不同地区、不同险种的标识规则存在差异，需按机构实际承保规则确认。
- 无害化处理作为理赔条件的具体适用范围需按地方政策和保险条款核实，不同地区的政策及不同险种的条款要求存在差异，需结合机构实际承保范围确认。
