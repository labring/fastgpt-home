# 工程保险承保与理赔应用的分享与嵌入：作用域、免登录与边界

## 这个品类每天在处理什么材料
工程保险承保与理赔场景日常处理的材料包含工程合同、施工组织设计、工程量及进度、地质资料、现场查勘、保险合同、事故记录、修复方案及理算资料。数据来源覆盖建设/施工方项目资料、监理记录、现场查勘、气象地质、工程造价和设备价格。不同材料的更新频率存在差异：工程进度数据按项目节点更新，监理与施工数据随施工过程实时更新，灾害及事故数据在事件触发时同步，工程造价数据仅在工程或理赔测算时更新。各类材料形态差异显著，既有专业勘测类的地质资料，也有表格形式的工程量及进度文件，还有文字类的事故记录与修复方案。

## 这些材料在「分享与嵌入」这一环带来什么约束
工程保险相关材料的多类型、动态更新与敏感属性，为分享与嵌入环节带来多重约束。首先，不同文档的格式与结构差异极大，嵌入解析时需适配专业技术文档、表格、文字报告等多种形态，避免丢失关键信息。其次，部分数据如工程进度、事故记录需随项目阶段实时更新，静态嵌入的内容无法匹配动态变化的业务需求。此外，部分材料涉及项目变更、事故细节等敏感内容，分享与嵌入时需严格控制访问权限，避免未经授权的信息泄露。同时，不同项目的文档差异显著，通用的分享嵌入规则难以覆盖所有场景。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `分段长度` | `800–1200 字符` | 工程类文档多为长文本，该分段长度可保留语义完整性，为常见取法，需按实际材料长度标定 |
| `召回条数` | `前 5 条` | 工程险核心材料关联度较高，召回前5条可覆盖主要业务场景，为常见取法，需按实际材料关联度调整 |
| `相似度阈值` | `0.75–0.85` | 平衡精准度与召回率，适配工程类文档的专业术语特征，为常见取法，需按实际业务需求标定 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 大型工程文档解析耗时较长，该时长可覆盖多数场景，为常见取法，需按实际文档大小调整 |
| `重排返回条数` | `前 3 条` | 聚焦最相关的核心内容，避免信息过载，为常见取法，需按实际业务场景调整 |
| `maxContext` | `8000–12000 字符` | 保留足够的上下文以支撑复杂的风险判断与理赔测算，为常见取法，需按实际材料总长度标定 |

## 最耗时的环节会卡在哪
三个最耗时的环节中，分享与嵌入功能可覆盖部分辅助工作，但仍存在无法替代的人工环节。第一个环节为阅读施工、设计和技术资料识别高风险工序，功能可自动提取高风险工序关键词并召回对应保险条款，但若未匹配到精准条款或召回内容不全，会出现召回不到对应条款、结果与原件对不上的问题，需人工补充核验。第二个环节为随工程阶段核对保险标的、风险暴露和重大变更，功能可自动比对当前工程材料与初始投保资料的差异，若抽取的变更字段为空，会导致需要人工回退重做。第三个环节为事故后区分原有缺陷、事故损失、修复范围和费用，功能可自动提取事故记录、修复方案中的关键信息，若解析超时中断，会导致流程停滞，且无法结合地质资料准确判断原有缺陷，需人工介入修正。

## 做错了会怎样
功能配置失误可能引发多重不良后果。业务层面可能出现重大施工风险漏识别或修复费用判断错误；合同层面可能引发工程范围、缺陷与保险事故边界的争议；监管层面可能因承保理赔管理问题被处理；客户层面可能出现赔款不足或责任争议。易引发这些后果的配置失误包括：分段长度设置过短导致条款被切断，语义不完整；召回条数过低导致关键材料被遗漏；未开启溯源功能导致答复无法回原件核对；相似度阈值设置过高导致高风险内容未被召回。

## 与相邻品类的区别
工程保险与企业财产险存在核心差异。工程保险的保险标的、工程价值和风险暴露随施工、安装、试车阶段动态变化，施工和工程进度类材料是核心业务支撑。而企业财产险的标的相对固定，核心依赖静态财产清单与场地信息。因此，针对工程险优化的分享与嵌入配置，如侧重施工进度材料的召回与动态更新适配，无法直接适配企业财产险的静态业务场景。

## 还需要按机构实际情况确认的
- 工程险具体技术文档随项目类型差异极大，不同机构承接的项目类型不同，文档格式、内容结构差异显著，需针对机构常用项目类型调整分享与嵌入的配置规则。
- 行业协会来源可确认工程类保险真实存在，但不能据此证明所有公司使用完全相同底稿，不同机构的内部文档模板、审核流程存在差异，需结合机构实际文档规范调整相关设置。
