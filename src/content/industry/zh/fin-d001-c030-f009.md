# 工程保险承保与理赔答复的溯源：引用范围、角标与原文定位

## 这个品类每天在处理什么材料
这个品类日常处理的材料包括工程合同、施工组织设计、工程量及进度、地质资料、现场查勘、保险合同、事故记录、修复方案及理算资料。主要数据来源涵盖建设/施工方项目资料、监理记录、现场查勘、气象地质、工程造价和设备价格。各类材料的更新频率存在差异：工程进度数据按项目节点更新，监理与施工数据随施工过程动态更新，灾害或事故数据于事件触发时同步，造价数据则在工程或理赔测算时更新。不同材料的形态差异显著，既有结构化的工程量表格，也有图文结合的施工日志，还有格式统一的保险合同文档。

## 这些材料在「引用来源与溯源」这一环带来什么约束
不同材料的特征为溯源环节带来多重约束。工程类文档形态差异显著，既有结构化表格也有非结构化文本，需适配不同格式的解析与引用规则；数据更新频率各异，工程进度按节点更新、监理数据随施工动态更新，需关联对应时间节点的最新版本，避免引用过时内容；数据来源分散，涵盖施工方、监理方等多渠道，溯源时需准确匹配各来源的标识信息；部分材料涉及项目专属细节，需灵活调整匹配逻辑以覆盖个性化内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | `前6-10条` | 常见取法，需按实际材料的数量与相关性标定 |
| `相似度阈值` | `0.72-0.85` | 区分有效与无关文档的常见取值，需按材料的专业术语密度调整 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300-600秒` | 处理大型工程文档的常见超时设置，需按文件总大小调整 |
| `分段长度` | `1000-1500字符` | 保留完整条款或工序描述的常见取法，需按文档的段落结构调整 |
| `重排返回条数` | `前3-5条` | 优先展示最相关溯源内容的常见配置，需按业务需求调整 |

## 最耗时的环节会卡在哪
第一个环节为阅读施工、设计和技术资料识别高风险工序，溯源功能可召回关联高风险工序的文档片段，但无法自动完成风险等级判定，若召回不到对应工序的资料，会导致漏识别风险。第二个环节为随工程阶段核对保险标的、风险暴露和重大变更，溯源可定位对应阶段的更新文档，但需人工关联不同版本的变更记录，若抽取不到对应变更的字段，会导致核对缺失。第三个环节为事故后区分原有缺陷、事故损失、修复范围和费用，溯源可定位事故前后的相关文档，但无法自动划分责任边界，若结果与原件内容不符，需人工回退重做。

## 做错了会怎样
溯源环节出错会引发多重后果。业务层面可能出现重大施工风险漏识别或修复费用判断错误；合同层面可能引发工程范围、缺陷与保险事故边界的争议；监管层面可能因承保理赔管理问题被处理；客户层面可能出现赔款不足或责任争议。易引发此类后果的配置失误包括召回条数过低漏掉关键材料、分段长度太短切断条款、未开启溯源功能导致无法回查原件、相似度阈值设置不当导致召回错误文档。

## 与相邻品类的区别
与企业财产险不同，工程保险的保险标的、工程价值和风险暴露随施工、安装、试车过程动态变化，因此施工和工程进度材料是核心溯源内容。企业财产险的标的相对固定，无需频繁关联多阶段进度文档，若直接套用工程险的溯源配置，会因核心参考材料的差异导致匹配精度下降，无法满足对应品类的业务需求。

## 还需要按机构实际情况确认的
- 工程险具体技术文档随项目类型差异极大，不同机构的项目文档格式、字段规则存在显著区别，需适配各自的文档解析与匹配逻辑。
- 行业协会来源可确认工程类保险真实存在，但不能据此证明所有公司使用完全相同底稿，各机构的内部文档模板与业务流程存在差异，需验证自身的溯源匹配规则。
