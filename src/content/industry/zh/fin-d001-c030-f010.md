# 工程保险承保与理赔场景的数据库与运维：连接、备份与容量

## 这个品类每天在处理什么材料
日常处理的材料包括工程合同、施工组织设计、工程量及进度、地质资料、现场查勘、保险合同、事故记录、修复方案及理算资料，数据来源涵盖建设/施工方项目资料、监理记录、现场查勘、气象地质、工程造价和设备价格。各类材料的更新频率存在差异：工程进度数据按项目节点更新，监理与施工数据随施工过程动态更新，灾害或事故数据在事件触发时同步，造价数据仅在工程或理赔测算时更新。不同材料的形态差异明显，既有结构化的工程量表格，也有图文结合的施工组织设计与现场查勘记录。

## 这些材料在「数据库与运维」这一环带来什么约束
多类型混合的材料要求数据库兼容结构化与非结构化数据的写入、读取与关联查询；不均的更新频率需要支持按需同步与增量更新机制，适配节点触发、过程更新与事件触发的不同节奏；多来源的数据需要统一的元数据管理，避免数据孤岛导致的信息割裂；部分材料存在强关联关系，如事故记录与修复方案，需要支持跨表关联的高效查询；项目周期内数据规模随施工进度持续增长，需要合理的容量规划与归档策略。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300–600 秒` | 工程类文档通常结构复杂，部分地质资料、施工组织设计篇幅较长，常见取法需按实际材料标定 |
| `召回条数` | `8–12 条` | 需覆盖多来源的关联材料，常见取法需按项目文档规模调整 |
| `相似度阈值` | `0.72–0.85` | 需区分高风险工序相关的技术细节与普通施工内容，常见取法需按实际风险识别需求标定 |
| `maxContext` | `12000–18000 字符` | 需完整承载关联的工程合同与事故记录内容，常见取法需按实际文档组合长度调整 |
| `增量同步间隔` | `15–60 分钟` | 适配不同更新频率的施工数据与事件触发的灾害数据，常见取法需按项目进度节奏调整 |

## 最耗时的环节会卡在哪
第一个环节为阅读施工、设计和技术资料识别高风险工序，该环节可通过检索关联文档完成初步筛选，但无法替代人工结合项目场景的风险判断，若召回条数过低或相似度阈值设置不当，会出现高风险工序文档遗漏的情况。第二个环节为随工程阶段核对保险标的、风险暴露和重大变更，可自动关联进度文档与保险条款，但无法完成跨阶段的标的变更逻辑校验，若关联召回错误或抽取字段为空，需人工回退重做。第三个环节为事故后区分原有缺陷、事故损失、修复范围和费用，可检索关联的事故与修复资料，但无法界定缺陷与损失的边界，若召回资料不完整或未开启溯源，会导致结果与原件对不上。

## 做错了会怎样
操作失误可能引发多重后果：业务层面出现重大施工风险漏识别或修复费用判断错误；合同层面出现工程范围、缺陷与保险事故边界的争议；监管层面可能因承保理赔管理问题被处理；客户层面出现赔款不足或责任争议。易引发此类后果的配置失误包括：召回条数过低导致关键材料遗漏，相似度阈值设置不当导致边界判断偏差，分段长度过长切断关键条款，未配置增量同步导致变更信息未更新，备份缺失导致数据丢失引发监管问题。

## 与相邻品类的区别
与企业财产险不同，工程保险的保险标的、工程价值和风险暴露随施工、安装、试车过程动态变化，施工和工程进度类材料是核心处理对象。企业财产险的标的相对固定，无需频繁关联阶段变化的施工数据，因此工程险场景下的数据库连接、同步与召回配置，无法直接适配企业财产险场景，否则会出现资源冗余或关键信息召回不足的问题。

## 还需要按机构实际情况确认的
- 工程险具体技术文档随项目类型差异极大，不同项目对应的文档格式、内容结构存在明显区别，需针对自身业务覆盖的项目类型调整配置。
- 行业协会来源可确认工程类保险真实存在，但不能据此证明所有公司使用完全相同底稿，不同机构的文档底稿存在差异，需验证自身的文档处理规则是否适配。
