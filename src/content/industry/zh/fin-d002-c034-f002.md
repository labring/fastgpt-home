# 慈善信托长材料的上下文与截断：引用上限与分段送入

## 这个品类每天在处理什么材料
日常处理的材料包含慈善信托合同、设立与变更备案文件、慈善项目方案、受益对象资料、拨款申请和凭证、事务处理及财务报告、信息公开底稿。数据主要来自委托人及慈善组织资料、民政备案与慈善信息平台、银行账户、信托财务系统、项目执行数据。不同材料的更新频率存在差异：备案与变更随事项触发更新，项目拨款随项目事件更新，财务账目随交易更新，年度及重大事项公开则按现行法规规定执行。各类材料形态差异明显，既有结构化的备案表单，也有非结构化的项目方案、零散的拨款凭证。

## 这些材料在「上下文与 token」这一环带来什么约束
多来源的异构材料需要整合到统一上下文窗口，不同文档的长度与token消耗差异较大，长文档容易超出模型限额，需通过分段处理适配。动态更新的材料要求上下文能够及时刷新，避免使用过期数据影响判断。不同材料间的关联关系复杂，例如信托合同与备案文件强关联，受益对象资料与项目方案直接绑定，若无法准确召回关联材料，会导致上下文信息缺失或冗余，既浪费token资源，也可能引发判断偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 常见取法，需按实际处理的材料总长度标定，适配多数大语言模型的上下文限额 |
| `分段长度` | `800–1200 字符` | 常见取法，适配单份长文档的token拆分需求，需按单份文档平均长度调整 |
| `召回条数` | `前6–8条` | 常见取法，覆盖核心关联材料的上下文需求，需按业务场景的材料关联复杂度调整 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300–600 秒` | 常见取法，适配非结构化长文档的解析耗时，需按文档复杂度调整 |
| `相似度阈值` | `0.75–0.85` | 常见取法，平衡召回精度与覆盖范围，需按业务对材料关联度的要求标定 |

## 最耗时的环节会卡在哪
最耗时的三个环节中，该功能环节可分别覆盖部分工作，但仍存在无法替代的部分。审查项目及受益对象合规性环节，功能可自动召回信托条款与对应材料，但如果召回条数不足，会遗漏关键约束条款，出现召回不到对应条款的情况，需人工回退补充。核验拨款与执行证据环节，功能可抽取凭证核心信息，但如果分段截断了票据编号或执行记录，会导致抽取字段为空，无法完成核验，结果与原件对不上时需重新处理。编制备案与公开信息环节，功能可自动整理材料生成初稿，但如果超时设置过短，会出现超时中断，若未正确匹配时限规则，需人工重做。

## 做错了会怎样
操作失误可能引发多重风险：业务层面可能出现资金使用偏离慈善目的的情况，合同层面可能因上下文缺失违反信托文件造成受托责任，监管层面可能因未依法备案、公开或管理被处罚或采取监管措施，受益人及公众层面可能出现错拨、漏披露等损害公益财产和信任的问题。容易引发这些后果的配置失误包括：分段长度设置过短切断关键条款，导致上下文不完整；召回条数设置过低漏掉核心关联材料；未开启溯源功能导致生成的内容无法与原件核对，出现结果与原件对不上的情况。

## 与相邻品类的区别
与家族信托相比，慈善信托的信托目的必须为公益慈善，存在民政备案和社会信息公开的法定责任，其材料链包含独立的公益项目和受助对象文档。家族信托的材料多围绕家族财产安排，无此类公开与备案环节，两类场景的材料结构、更新逻辑与合规要求存在明显差异，因此针对慈善信托的上下文配置无法直接适配家族信托场景。

## 还需要按机构实际情况确认的
- 具体项目尽调、绩效评价和拨款审核模板因信托及公益项目不同，需结合机构服务的具体公益项目类型调整配置，不同项目的材料结构和审核重点存在差异。
- 法定公开时限应以2026年现行规则逐事项执行，需根据机构所在地区的最新监管要求确认相关配置中的时限匹配项，不同地区的监管规则可能存在差异。
