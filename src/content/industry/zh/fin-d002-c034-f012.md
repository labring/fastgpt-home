# 慈善信托材料的模型接入：上下文长度、工具调用与渠道配置

## 这个品类每天在处理什么材料
日常处理的材料包括慈善信托合同、设立变更备案文件、慈善项目方案、受益对象资料、拨款申请及凭证、事务处理及财务报告、信息公开底稿。数据主要来自委托人及慈善组织资料、民政备案/慈善信息平台、银行账户、信托财务系统、项目执行数据。各类材料形态差异显著，既有标准化备案表单，也有非结构化的项目方案、扫描类拨款凭证，数据更新频率各不相同，备案及变更随事项触发，项目拨款随项目事件更新，财务账随交易更新，年度及重大事项公开则按现行法规规定执行。

## 这些材料在「模型接入与配置」这一环带来什么约束
不同类型的材料对模型接入带来多重约束。多源数据来源需要配置多渠道对接能力，适配不同数据格式的解析需求；更新频率的差异要求支持事件触发的同步机制，避免数据滞后或冗余；材料间的关联关系，如备案文件与信托合同的绑定、拨款凭证与项目方案的对应，需要模型具备上下文关联能力；部分材料的非结构化属性，如扫描类凭证，需要适配OCR及结构化抽取配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 覆盖单份核心文档的完整语义，常见取法需按实际材料长度标定 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120–180 秒` | 处理多页的财务报告、项目方案等非结构化文档，常见取法需按实际材料大小标定 |
| `recall_top_k` | `10–15 条` | 覆盖关联材料的上下文，避免遗漏受益对象资料、备案条款等关键信息，常见取法需按实际检索范围标定 |
| `rerank_top_n` | `5–8 条` | 聚焦高相关度的核心材料，避免冗余信息干扰，常见取法需按实际业务场景标定 |
| `tool_call_max_step` | `3–5 步` | 完成拨款核验、备案信息抽取等多步骤工具调用，常见取法需按实际流程复杂度标定 |
| `channel_sync_trigger` | `事件触发模式` | 匹配备案、拨款等按事项触发的更新频率，常见取法需按机构数据同步规则标定 |

## 最耗时的环节会卡在哪
第一个耗时环节为审查项目及受益对象是否符合慈善目的和信托文件，模型可快速检索信托文件的慈善目的条款并匹配受益对象资料，但无法替代人工核实受益对象的具体资质与项目的匹配度，若召回不到对应条款则会导致漏审。第二个环节为核验拨款、票据和项目执行证据，模型可抽取凭证的核心信息并比对项目数据，但无法验证票据的物理真实性，若抽取字段为空或结果与原件对不上则需人工回退。第三个环节为编制备案、事务财务报告及法定公开信息并核对期限，模型可自动整理内容，但无法确认法定时限的最新要求，若超时中断则需重新执行流程。

## 做错了会怎样
配置失误可能引发多重后果。若分段长度不足切断信托文件的慈善目的条款，可能导致资金使用偏离慈善目的；若召回条数过低漏掉受益对象资料或备案要求，可能违反信托文件或未依法备案；若未开启溯源功能导致结果无法回原件核对，可能出现错拨或漏披露。监管层面可能因未按要求公开或备案被处罚，公众及受益人则可能因错拨、漏披露损害公益财产与信任。

## 与相邻品类的区别
与家族信托的关键差别在于，慈善信托的目的须为公益慈善，存在民政备案及社会信息公开责任，且公益项目与受助对象资料形成独立文档链。家族信托无需适配民政备案流程与公开信息处理，其核心文档多围绕家族财产规划，因此慈善信托的模型接入配置无法直接沿用家族信托的设置。

## 还需要按机构实际情况确认的
- 具体项目尽调、绩效评价和拨款审核模板因信托及公益项目不同存在差异，不同机构的公益项目类型各异，模板需求无法统一。
- 法定公开时限应以2026年现行规则逐事项执行，监管规则可能随地区或政策调整，需结合机构实际情况逐一确认。
