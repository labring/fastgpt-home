# 公募 REITs 投资与运营材料的检索与召回：分段、阈值与重排取法

## 这个品类每天在处理什么材料
该品类日常处理的文档包括招募说明书、基础设施尽调、评估报告、运营报告、现金流预测、专项计划文件、分配及信息披露材料，数据来源涵盖项目经营收费系统、权属和合同、财务账套、交易所REITs信息、评估及运营管理数据。各类材料的更新节奏存在差异：项目经营数据随收费或经营动作实时更新，财务数据按项目核算周期更新，估值与评估数据按适用规则及产品安排更新，重大运营事件相关材料则在事件触发后同步更新。不同来源的材料形态也存在区别，既有结构化的财务账套数据，也有非结构化的尽调、评估报告文本，以及交易所公开披露的标准化文件。

## 这些材料在「知识库检索与召回」这一环带来什么约束
该品类的材料特征对检索召回环节形成多重约束：首先，多类型文档混合存在，需适配结构化与非结构化内容的解析与召回逻辑；其次，数据来源分散且更新节奏不一，需支持跨系统数据整合与增量更新配置；第三，核心资料链围绕权属、合同、评估与现金流展开，要求召回结果需关联跨文档的核心关联内容；最后，部分材料涉及合规性要求，需保证召回内容的准确性与完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `分段长度` | 800–1200 字符 | 常见取法，需按实际材料的段落长度标定，避免切断完整条款 |
| `召回TopK` | 前 10–15 条 | 常见取法，覆盖核心关联材料，避免过多冗余信息干扰业务审阅 |
| `相似度阈值` | 0.72–0.85 | 常见取法，平衡精准召回与覆盖范围，需按项目资料的语义相似度调整 |
| `重排返回条数` | 前 5–8 条 | 常见取法，聚焦核心资料，符合业务人员的信息审阅密度需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 常见取法，适配大型尽调、评估报告的解析时长 |
| `maxContext` | 8000–12000 字符 | 常见取法，匹配业务查询的上下文关联需求，需按实际场景调整 |

## 最耗时的环节会卡在哪
穿透核验底层项目权属、合同和运营资质环节中，该功能可自动召回权属文件、合同条款与资质证明材料，快速定位关联内容，但无法替代人工核验签章合规性与跨文件权属关联逻辑，若召回不到对应资质文件则会导致流程中断，抽取信息不完整则需人工回退重做。重建经营收入、成本及可供分配现金流环节中，可自动从财务账套、运营报告等材料中召回相关数据片段，但无法核对不同来源数据的核算口径一致性，若抽取字段为空或召回数据与原件不符，则需重新处理。持续核对项目运营、评估、基金/专项计划数据和收益分配环节中，可自动关联展示各环节材料片段，但无法人工核对分配比例与合规性，若召回材料关联性弱则需回退，超时则中断流程。

## 做错了会怎样
该功能出错会带来多重影响：业务层面，运营或现金流数据错误会导致估值与分配偏差；合同层面，底层权利与运营合同瑕疵信息未被召回会影响收益实现；监管层面，重大事项披露材料漏召回可能导致运作问题受处理；持有人层面，错误分配或信息缺失会损害持有人权益。常见的配置失误包括：分段切断完整条款导致关键信息丢失，召回条数过低漏掉核心材料，相似度阈值过高遗漏相关文件，未开启溯源功能导致无法回查原件核对，重排逻辑未考虑关联度导致核心材料靠后。

## 与相邻品类的区别
与普通股票债券基金相比，公募REITs的底层资产为实际运营的基础设施，核心资料链围绕产权、运营合同、评估与可供分配金额展开。普通品类的检索召回多聚焦于公开披露的公告与财务报告，核心关注市值与持仓信息，而REITs需穿透底层资产的跨文档关联内容，因此检索召回的配置需更注重跨文件的关联性匹配。

## 还需要按机构实际情况确认的
- 不同基础设施行业经营指标和评估模型差异较大：不同机构涉及的基础设施类型不同，经营指标的定义、评估模型的参数存在区别，需调整检索的关键词与召回规则。
- 具体数据采集频率需按项目核实：不同项目的核算周期、更新触发条件不同，需调整知识库的增量更新配置与召回的时效性要求。
