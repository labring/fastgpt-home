# 公募 REITs 投资与运营场景的部署与版本升级：变更窗口与回退准备

## 这个品类每天在处理什么材料
该品类日常处理的材料包括招募说明书、基础设施尽调、评估报告、运营报告、现金流预测、专项计划文件、分配及信息披露材料，材料形态涵盖结构化合规文档、非结构化文本、图文结合内容等多种类型。数据来源涵盖项目经营收费系统、权属和合同、财务账套、交易所REITs信息、评估及运营管理数据，其中项目经营数据随收费或经营动作实时更新，财务数据按项目核算周期更新，估值与评估数据按适用规则及产品安排更新，重大运营事件相关数据则在事件触发时同步更新。

## 这些材料在「部署与升级」这一环带来什么约束
多类型、多形态的业务材料要求部署阶段完成多种文档解析规则的适配配置；多数据源的接入需求，需在升级环节完成不同系统接口的兼容性调试。不同更新频率的数据需要设置差异化的同步触发机制，避免数据同步冲突。核心资料链的严谨性要求，变更窗口需避开项目核算周期与重大信息披露节点，防止升级过程干扰正常业务数据流转。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600–900 秒 | 针对多类型长文档的常见取法，需按实际材料长度标定 |
| `召回条数` | 前 8–12 条 | 覆盖核心资料链的常见取法，需按项目资料量调整 |
| `相似度阈值` | 0.75–0.85 | 平衡精准度与召回完整性的常见取法，需按文档特征标定 |
| `分段长度` | 1000–1500 字符 | 适配单份文档核心段落的常见取法，需按资料粒度调整 |
| `重排返回条数` | 前 3–5 条 | 聚焦高关联内容的常见取法，需按业务需求标定 |

## 最耗时的环节会卡在哪
穿透核验底层项目权属、合同和运营资质环节，功能可自动抽取权属文件、合同条款的关键信息，但无法自主判断资质的合规性，若召回不到对应资质文件，会出现核验环节中断。重建经营收入、成本及可供分配现金流环节，功能可整合多源数据生成现金流框架，但无法适配不同基础设施的专属经营指标，若抽取字段为空，会导致现金流模型偏差。持续核对项目运营、评估、基金/专项计划数据和收益分配环节，功能可自动比对多源数据的一致性，但无法处理跨系统的格式差异，若结果与原件对不上，需人工回退重做。

## 做错了会怎样
错误可能引发多维度影响：业务层面出现运营或现金流数据错误导致估值与分配偏差；合同层面出现底层权利和运营合同瑕疵影响实际收益；监管层面因重大事项披露或基金运作问题可能受到处理；持有人层面出现错误分配或信息缺失。易引发此类后果的配置失误包括：分段长度过短切断完整条款导致召回信息不完整，召回条数过低漏掉关键材料，未开启溯源功能导致答复无法回查原件核对，相似度阈值过高漏掉低关联但核心的资料。

## 与相邻品类的区别
与普通股票债券基金相比，该品类的底层资产为实际运营的基础设施，产权、运营合同、评估和可供分配金额是核心资料链。普通品类侧重二级市场交易相关数据的处理，而该品类需聚焦实体资产的权属、运营、评估类资料，因此同一套配置若迁移至相邻品类，会因核心资料类型与处理逻辑的差异无法适配业务需求。

## 还需要按机构实际情况确认的
- 不同基础设施行业经营指标和评估模型差异较大，不同机构涉及的基础设施类型不同，需针对专属行业调整文档抽取与数据计算规则，因此需按机构实际情况确认。
- 具体数据采集频率需按项目核实，不同项目的核算周期、运营节奏存在差异，数据同步的触发频率需结合项目实际情况调整，因此需按机构实际情况确认。
