# 货币市场基金投资与运营长材料的上下文与截断：引用上限与分段送入

## 这个品类每天在处理什么材料
这个品类日常处理的材料包括交易指令、到期结构表、流动性监测、估值及收益核算、申赎数据、定期报告。数据主要来自货币市场、同业存单/短期债券、存款报价、托管估值、申赎系统，不同材料的更新节奏存在差异：市场与申赎数据随交易或业务事件实时更新，持仓期限结构随交易和到期动态调整，估值收益则按照基金核算安排定期生成。各类材料的格式与结构也存在区别，部分为结构化表格，部分为时序性报告，部分为实时推送的业务数据流。

## 这些材料在「上下文与 token」这一环带来什么约束
多源多类型的材料会带来总token消耗波动，实时更新的材料需要动态纳入上下文，超出模型窗口的长文档需进行截断处理。不同材料的关联度存在差异，申赎数据与估值报告、交易指令的关联较强，若无法精准召回关联材料，会导致上下文割裂。不同材料的更新频率不同，需区分静态与动态数据的加载优先级，避免陈旧数据干扰当前业务判断。长周期的定期报告与实时交易指令的处理逻辑存在差异，需适配不同的上下文窗口要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 覆盖多数单批次材料总长度，常见取法，需按实际材料总token量标定 |
| `分段长度` | `1000–1500 字符` | 适配长文档拆分，避免单段超出模型窗口，常见取法，需按文档结构调整 |
| `召回条数` | `前6–8条` | 覆盖核心关联材料，常见取法，需按业务关联度调整 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300–600 秒` | 适配批量材料解析耗时，常见取法，需按文档大小调整 |
| `相似度阈值` | `0.75–0.85` | 过滤低关联召回结果，常见取法，需按业务精度要求标定 |
| `重排返回条数` | `前3–5条` | 聚焦高关联核心材料，常见取法，需按业务场景调整 |

## 最耗时的环节会卡在哪
安排申赎和现金头寸环节，需关联申赎数据、货币市场报价与头寸信息，该功能环节可自动召回关联材料并抽取关键字段，但如果召回不到对应条款或抽取字段为空，将无法完成头寸计算，需人工回退重做。跟踪短期限资产到期、交易对手和组合流动性环节，需匹配到期结构表与交易对手信息，若分段切断关键内容或超时中断，将无法准确跟踪到期节点，导致遗漏风险提示。复核估值、收益分配及持有人份额数据环节，需比对多份材料的数值一致性，若结果与原件对不上，将无法快速完成复核，增加人工核对成本。

## 做错了会怎样
出错会引发多维度影响：业务层面可能出现流动性不足、交易对手风险或核算错误；合同层面可能因突破基金合同约束产生责任；监管层面可能因流动性或估值问题被处理；持有人层面可能出现赎回及收益分配受影响的情况。配置失误易引发此类后果，包括分段切断条款导致关键信息丢失、召回条数过低漏掉核心材料、未开启溯源导致答复无法回原件核对等。

## 与相邻品类的区别
与普通债券基金相比，该品类更强调短期限、高流动性、现金头寸和持续申赎管理。普通债券基金的核心收益来源与长久期、信用风险相关，处理的材料多为中长期债券相关文档，上下文窗口与拆分逻辑与本品类存在差异，因此本品类的上下文与截断配置无法直接适配普通债券基金场景。

## 还需要按机构实际情况确认的
- 具体头寸管理阈值和资产到期结构属于管理人内部制度，因不同机构的风控要求、产品规模、业务流程存在差异，需结合机构实际情况确认。
- 三项耗时环节的排序无统一公开数据，需结合各机构的实际业务流程统计确定，无法直接套用通用标准。
