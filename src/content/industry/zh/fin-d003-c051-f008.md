# 货币市场基金投资与运营场景的工具调用：入参校验与失败处理

## 这个品类每天在处理什么材料
这个品类日常处理的材料包括交易指令、到期结构表、流动性监测、估值及收益核算、申赎数据、定期报告。数据来源覆盖货币市场、同业存单/短期债券、存款报价、托管估值、申赎系统。其中市场与申赎数据随交易或业务事件实时更新，持仓期限结构随交易和到期动态变化，估值收益数据按基金核算安排定期产出。各类材料形态差异明显，既有结构化表单与批量报表，也有实时数据流与标准化披露文档。

## 这些材料在「工具调用与插件」这一环带来什么约束
各类材料的特征对工具调用与插件环节带来多重约束。实时更新的申赎与市场数据要求插件支持低延迟触发，动态变化的期限结构数据需要适配灵活的定时扫描机制，定期产出的估值收益数据需适配批量解析流程。多源数据来源需要插件完成跨系统对接，不同形态的材料需要配置差异化的解析规则。部分材料的实时性要求会限制工具调用的超时设置，批量材料则需要调整并发处理参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 适配批量文档解析的常见取法，需按单份材料大小和复杂度实际标定 |
| `召回条数` | 前3–5条 | 针对短期限资产关键词匹配的常见取法，需按机构内部数据量调整 |
| `分段长度` | 800–1200 字符 | 适配结构化报表和文本类文档的常见取法，需按材料字段长度实际调整 |
| `相似度阈值` | 0.75–0.85 | 用于匹配交易指令和申赎数据的常见取法，需按业务校验精度要求调整 |
| `maxContext` | 10000–15000 字符 | 整合多源数据上下文的常见取法，需按插件调用的上下文限制调整 |
| `插件重试次数` | 2–3次 | 应对系统临时波动的常见取法，需按数据来源的稳定性调整 |

## 最耗时的环节会卡在哪
最耗时的三个环节各有卡点。安排申赎和现金头寸环节，工具调用可自动拉取申赎数据与市场报价完成入参校验，但无法实时获取跨系统的全量头寸余额，若抽取的申赎字段为空或头寸计算结果与托管估值对不上，需人工回退重做。跟踪短期限资产到期、交易对手和组合流动性环节，工具可自动扫描到期结构表与交易指令，但无法识别交易对手的隐性风险预警，若召回不到到期条款或调用超时，会导致流程中断。复核估值、收益分配及持有人份额数据环节，工具可自动匹配报表与份额数据，但无法判断核算规则的合规性，若结果与原件对不上，需人工重新校验。

## 做错了会怎样
出错的后果覆盖业务、合同、监管与持有人维度。业务层面可能出现流动性不足、交易对手风险或核算错误；合同层面可能因突破基金合同约束产生责任；监管层面可能因流动性或估值问题被处理；持有人层面可能出现赎回及收益分配受影响的情况。配置失误易引发此类问题，包括分段长度过短切断估值核算条款、召回条数过低漏掉关键申赎数据、未开启插件溯源导致结果无法回原件核对、相似度阈值过高过滤有效校验规则。

## 与相邻品类的区别
与普通债券基金相比，货币市场基金投资与运营更强调短期限、高流动性、现金头寸和持续申赎管理。普通债券基金的工具调用配置多针对长久期报表与低频申赎流程，无法适配货币市场基金高频实时数据校验、短期限资产快速匹配的需求，直接迁移配置会导致校验效率不足或误判率上升。

## 还需要按机构实际情况确认的
- 具体头寸管理阈值和资产到期结构属于管理人内部制度，不同机构的风控要求存在差异，需结合实际业务规则校准工具调用的校验逻辑。
- 三项耗时环节的排序无统一公开数据，不同机构的业务流程差异会导致各环节耗时占比不同，需结合实际场景调整工具调用的优先级配置。
