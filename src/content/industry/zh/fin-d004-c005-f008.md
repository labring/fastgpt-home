# 不良资产收购与处置场景的工具调用：入参校验与失败处理

## 这个品类每天在处理什么材料
日常处理的材料包括资产包清单、债权合同、担保合同、尽调和估值报告、收购方案、债权转让、催收、诉讼执行、重组及资产处置方案，形态覆盖结构化表格、制式合同文本、综合分析报告、司法公文等多类。数据来源涵盖原债权档案、工商征信司法、法院执行/拍卖、不动产和担保登记、债务人财务、评估和潜在买方数据。债权余额与回收数据随回款事件更新，诉讼执行数据随司法事件更新，抵押资产数据随处置或估值事件更新，债务人财务数据在取得时更新，无统一周期。

## 这些材料在「工具调用与插件」这一环带来什么约束
多类型混合的材料要求工具适配不同的解析规则，需配置针对制式合同、司法文书、分析报告的专项解析插件，确保不同形态的材料均可被正确抽取关键信息。跨多源的数据来源要求调用不同的数据源插件，实现原债权档案、工商征信、司法执行等多类信息的拉取整合。无固定更新周期的数据需要支持事件触发的校验逻辑，适配不同数据的更新节奏，不依赖固定定时任务。单资产关联多份材料的特性，要求工具能精准关联同一标的的所有关联文档，避免上下文割裂影响校验准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 常见取法，需按单份材料最大体量实际标定 |
| `召回条数` | 前3–5条 | 常见取法，需按材料关联密度调整 |
| `相似度阈值` | 0.75–0.85 | 常见取法，需按合同条款严谨性调整 |
| `分段长度` | 800–1200 字符 | 常见取法，需按单份文档的段落结构调整 |
| `重排返回条数` | 前2–4条 | 常见取法，需按处置路径对比的维度调整 |
| `maxContext` | 4000–6000 字符 | 常见取法，需按单资产关联材料总量调整 |

## 最耗时的环节会卡在哪
第一个环节为逐户核对债权本金利息、合同、担保、诉讼执行和权利瑕疵，工具可调用解析插件抽取合同条款、司法文书关键信息，但无法自动核实权利瑕疵的司法时效，失败形态包括召回不到对应担保条款、抽取的利息字段为空。第二个环节为估算抵押物、企业重整和不同情景下可回收现金，工具可基于评估报告和财务数据生成基础估算，但无法适配特殊重整情景，失败形态包括超时中断、结果与原件估值数据对不上。第三个环节为比较处置路径并执行，工具可调用历史数据对比不同路径的收益，但无法结合机构内部规则调整，失败形态包括未召回对应政策导致结果偏差、需人工回退重做。

## 做错了会怎样
错误操作可能导致业务层面买入瑕疵债权或回收估值过高造成收购亏损，合同与司法层面出现债权担保或程序瑕疵降低追索回收，监管层面因收购处置不符合规则被处理，债务人及相关方层面因错误追偿或资产处置产生争议。易引发此类后果的配置失误包括分段切断关键条款导致校验遗漏、召回条数过低漏掉核心材料、未开启文档溯源导致无法核对原件、相似度阈值过低混入无关材料。

## 与相邻品类的区别
本场景的标的一般已经风险化，核心工作是确认现有债权能否依法主张以及最终可回收多少。正常信贷品类的核心判断逻辑为是否新放贷款，校验维度与本场景的瑕疵核实、可回收估算完全不同，因此本场景的工具调用配置无法直接适配正常信贷品类。

## 还需要按机构实际情况确认的
- 各类不良债权诉讼时效，需逐资产依据合同和司法事实核实，不同机构的债权档案完整度与尽职调查标准存在差异，核实的具体尺度需按机构实际情况调整。
- 担保权的司法后果，需结合当地司法实践确认，不同地区的裁判规则存在区别，无法通过统一配置覆盖所有场景。
- 权利灭失的推定不能统一套用规则，需按单资产的实际合同与司法事实确认，不同机构的风险把控偏好不同，确认标准存在差异。
