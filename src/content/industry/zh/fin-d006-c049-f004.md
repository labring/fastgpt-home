# 证券经纪业务知识库的向量与索引：维度、重建与迁移代价

## 这个品类每天在处理什么材料
本品类日常处理的材料包括开户及身份资料、风险揭示、委托成交、权限变更、客户回访、异常交易核查、投诉及营销合规材料。数据主要来自交易所行情成交、中国结算账户信息、券商柜台、CRM、适当性/反洗钱系统。不同材料的更新频率存在差异：委托成交、行情数据在交易时段实时更新，账户信息随事件触发更新，异常监控数据随交易触发生成，客户回访频率则按机构内部制度执行。各类材料涵盖结构化业务数据与非结构化文档两类，适配的索引与向量处理逻辑需兼顾两类形态的特征。

## 这些材料在「向量模型与索引」这一环带来什么约束
各类材料的特征对向量与索引环节带来多重约束。实时更新的委托成交与行情数据，要求索引支持低延迟增量更新以匹配业务时效要求。事件触发的账户信息、交易触发的异常监控数据，需适配增量索引构建逻辑，避免全量重建带来的性能损耗。非结构化的合规材料与客户回访记录，需要适配长文本的向量建模与分段处理规则。多源异构的数据来源，要求统一的向量映射与索引结构，确保不同系统导出的材料可被统一处理。客户回访频率随机构制度差异较大，需支持自定义的更新调度配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `分段长度` | 800–1200 字符 | 常见取法，需按实际材料的文本密度、语义完整性标定 |
| `召回条数` | 前 5–10 条 | 常见取法，需按业务场景的关键信息覆盖范围调整 |
| `相似度阈值` | 0.75–0.85 | 常见取法，需结合业务合规要求的匹配精度调整 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 常见取法，需按大型合规文档的解析耗时标定 |
| `maxContext` | 8000–12000 字符 | 常见取法，需按模型的上下文窗口限制调整 |

## 最耗时的环节会卡在哪
审查账户和身份资料及权限环节，向量索引可快速召回关联的开户资料、权限变更文档，但无法自动完成人工复核的合规校验，若召回不到对应权限变更记录，会导致权限校验遗漏，需人工回退重做。监控异常委托、账户使用和交易行为环节，索引可快速关联历史成交与异常交易数据，但无法判断交易行为的主观异常性，若抽取的异常触发字段为空，会导致监控规则失效，结果无法匹配业务阈值。处理交易差错、费用、账户权限和客户争议环节，索引可快速召回委托成交、费用合规材料，但无法完成争议双方的诉求梳理，若超时中断解析流程，会导致争议处理延迟，需重新发起检索。

## 做错了会怎样
向量与索引环节配置失误会引发多重不良后果。业务层面，交易差错或系统处理错误可能造成损失，若分段切断合规条款或召回条数过低，会引发交易相关损失。合同层面，委托和费用争议可能出现，若抽取的费用字段为空，无法匹配原始凭证。监管层面，实名制、适当性或交易管理不规范可能被处理，若未召回足够合规材料支撑审查。客户层面，错误交易、权限限制直接产生赔偿或投诉，若相似度阈值设置过高导致关键条款未被召回。常见配置失误包括分段不合理切断语义单元、召回条数过低遗漏材料、未开启溯源无法核对原件、超时设置过短导致解析中断。

## 与相邻品类的区别
本品类与投顾品类存在关键差异。证券经纪业务的核心是账户服务与执行客户委托，研究判断并非主要责任链。投顾品类需处理大量研究报告、客户投资咨询需求相关材料，其向量与索引配置需侧重研报语义理解与投资建议匹配。本品类的配置需侧重账户数据、交易记录的快速检索与合规材料的精准匹配，同一套配置迁移至投顾品类会因核心业务场景差异导致检索精度不足。

## 还需要按机构实际情况确认的
- 开户复核的具体内部触发阈值未公开统一，不同机构的合规审查标准存在差异，需结合自身监管要求确定。
- 客户回访与异常交易调查的具体内部触发阈值未公开统一，不同机构的业务规模、客户服务要求存在差异，需结合自身运营情况定制。
