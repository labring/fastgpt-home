# IPO 保荐承销材料的模型接入：上下文长度、工具调用与渠道配置

## 这个品类每天在处理什么材料
该品类日常处理的材料包括招股说明书、保荐工作报告、发行保荐书、尽调底稿、问询回复、工作日志、三会资料、客户供应商和资金流水核查材料，形态覆盖结构化账套数据、非结构化文档、访谈函证扫描件等。主要数据来源涵盖发行人ERP/账套/流水、工商司法信息、交易所审核系统、客户供应商访谈函证及行业及市场数据。数据更新频率存在差异：企业财务和经营数据按内部账期更新，工商司法及重大事项随事件触发更新，审核问询随审核事件触发更新，市场询价仅在发行阶段更新。

## 这些材料在「模型接入与配置」这一环带来什么约束
多类型混合材料的解析需求提升了配置复杂度，需适配结构化账套、非结构化文档等不同格式的解析规则。不同数据源的更新频率差异，要求配置动态触发的同步机制，避免无效全量拉取。材料间的勾稽关联需求，需要配置跨文档的召回与关联校验逻辑。部分材料体积较大，对模型上下文窗口和解析超时设置提出了更高要求。跨来源数据的整合，需要工具调用配置支持不同系统间的数据提取与关联。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–16000 字符 | 常见取法，需按单份核心文档（如招股书章节）的实际长度标定，避免截断关键勾稽内容 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 常见取法，适配尽调底稿、流水核查材料等大体积文档的解析耗时 |
| `recall_top_k` | 前 8–12 条 | 常见取法，覆盖多来源的关联材料，需按项目勾稽需求调整 |
| `similarity_threshold` | 0.75–0.85 | 常见取法，平衡精准召回与覆盖度，避免漏过跨文档关联内容 |
| `rerank_top_k` | 前 3–5 条 | 常见取法，聚焦高关联度材料，减少人工核验负担 |
| `enable_dynamic_sync` | 事件触发模式 | 常见取法，适配不同数据源的更新频率要求 |

## 最耗时的环节会卡在哪
穿透核验收入成本、流水、客户供应商和关联关系环节，可自动关联流水与客户供应商数据、提取关联方信息，若配置失误则会出现召回不到对应流水条目、抽取字段为空的问题，复杂关联逻辑仍需人工判断。把财务、法律、业务底稿与申报文件逐项勾稽环节，可自动匹配底稿与申报文件的对应条款，若配置不当则会出现结果与原件对不上、需要人工回退重做的问题，跨品类合规性判断无法自动完成。逐轮起草、取证并复核审核问询回复环节，可基于历史问询回复生成初稿，若超时设置过短则会出现超时中断的问题，针对发行人具体情况的个性化调整仍需人工完成。

## 做错了会怎样
配置失误可能引发多重风险。业务层面会导致审核受阻、发行延期或失败；合同层面会引发中介责任及发行协议争议；监管层面会因尽调和披露不充分被采取监管措施或处罚；客户及投资者层面会因虚假或遗漏信息导致投资损失和索赔。常见配置失误包括`maxContext`设置过低导致关键条款被截断、`recall_top_k`过低漏掉关联材料、未开启溯源功能导致答复无法回查原件、解析超时设置过短导致大体积文档无法完成解析。

## 与相邻品类的区别
与再融资品类相比，IPO保荐承销需覆盖未上市企业从设立到申报全周期的历史沿革材料，客户供应商、资金流水及股权历史底稿的核查深度与广度要求更高。再融资品类仅需针对已上市企业的后续融资需求，无需追溯完整历史信息链，因此配置需适配全周期材料的关联召回与校验，无法直接复用再融资的配置逻辑。

## 还需要按机构实际情况确认的
- 不同发行人的流水核查范围、函证比例不存在统一公开工作量标准，需根据项目规模、监管要求调整配置的召回与校验范围，因机构项目类型、客户资质不同存在差异。
- 三项耗时排序属行业作业判断，不同机构的作业流程差异会影响配置的优先级，需结合内部作业流程标定参数取值。
