# 上市公司再融资应用的分享与嵌入：作用域、免登录与边界

## 这个品类每天在处理什么材料
该品类日常处理的材料包括募集说明书、发行方案、保荐文件、尽调底稿、前次募集资金使用报告、问询回复、董事会及股东会资料。数据来源覆盖历史公告、交易所审核信息、公司账套、募集资金专户、工商司法和行业数据。不同材料的更新触发逻辑存在差异：上市公司公告随法定或事件披露要求更新，申报问询材料随审核事件触发更新，财务资料按定期报告周期更新，发行市场数据则在发行阶段实时更新。材料形态涵盖结构化财务数据、非结构化公告文本、审核动态文件等多种类型，部分需按固定周期同步，部分随业务进程动态调整。

## 这些材料在「分享与嵌入」这一环带来什么约束
多类型混合的材料结构要求分享嵌入时需适配不同格式的权限控制规则，避免敏感信息泄露。不同更新频率的数据源，要求嵌入后的同步策略需匹配对应材料的更新触发逻辑，保障信息时效性。部分审核阶段的材料涉及未公开的审核细节，分享嵌入需设置严格的访问边界，仅对授权主体开放。材料间存在强关联属性，嵌入后的上下文关联逻辑需确保跨文件的信息衔接准确，避免割裂业务逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | 前5-8条 | 常见取法，需按实际材料关联密度标定 |
| `相似度阈值` | 0.75-0.85 | 常见取法，需按材料文本复杂度调整 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300-600秒 | 常见取法，需按单份材料最大体积标定 |
| `分段长度` | 800-1200字符 | 常见取法，需按材料语义单元长度调整 |
| `重排返回条数` | 前3-5条 | 常见取法，需按用户查询的精准度要求调整 |
| `maxContext` | 4000-6000字符 | 常见取法，需按单轮对话的上下文承载量标定 |

## 最耗时的环节会卡在哪
核对前次募集资金用途及历史公告环节，该功能可自动拉取历史公告与前次报告进行比对，替掉逐页核对的基础工作，但无法识别公告中的歧义表述，失败形态为召回不到对应公告条款、抽取的用途字段为空。论证本次募投项目、融资规模和效益假设环节，功能可调取历史财务数据与行业数据辅助测算，替掉基础数据整理工作，但无法结合业务逻辑判断合理性，失败形态为结果与原件对不上、需要人工回退重做。将申报文件与既往定期/临时公告逐项勾稽环节，功能可自动匹配文件间的关联条款，替掉逐项查找工作，但无法处理跨文件的复杂关联，失败形态为超时中断、漏勾关键条款。

## 做错了会怎样
该功能应用失误会引发多维度后果：业务层面可能导致发行延迟或审核受阻，合同层面可能引发发行与募集资金使用争议，监管层面可能因前后披露不一致或核查不足被处理，投资者层面可能因信息错误影响认购判断。易引发此类后果的配置失误包括：分段长度设置不当导致关键条款被切断，召回条数过低漏掉核心材料，未开启溯源功能导致答复无法回查原件核对，相似度阈值设置偏差导致匹配结果不准确。

## 与相邻品类的区别
与IPO场景相比，该品类的核心工作为验证本次融资事项，并确保新申报材料与持续信息披露一致，无需从零核查企业全部历史。因此该场景的分享与嵌入配置可聚焦于本次融资相关的材料集合，无需覆盖企业全量历史披露内容。若直接套用IPO场景的配置，会出现召回冗余或关键信息遗漏的问题，适配逻辑无法匹配业务需求。

## 还需要按机构实际情况确认的
- 不同再融资工具的发行环节和材料存在差异，因不同工具对应的审核要求、材料格式不同，各机构的适配逻辑需结合工具类型单独调整。
- 三项耗时排序未找到统一统计，不同机构的业务流程、人员配置存在差异，耗时环节的优先级各不相同，需结合实际业务场景标定。
