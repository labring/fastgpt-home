# 公司债券承销与业务系统对接：接口、鉴权与回传口径

## 这个品类每天在处理什么材料
本品类日常处理的材料包括募集说明书、尽调底稿、承销协议、财报、评级资料、偿债保障文件、簿记发行资料、存续期文件。数据来源覆盖发行人财报、交易所债券系统、评级和债券市场数据、工商司法及募集资金账户。不同材料的形态存在差异，财报为结构化报表，募集说明书、承销协议为长文本文档，簿记发行资料为时点性表单，存续期文件则多为规则绑定的周期性文档。数据更新频率按类型区分：财报与评级按披露及评级跟踪周期更新，市场利率与成交数据在交易时段实时更新，重大事项随事件触发更新，存续期文件按适用规则定期更新。

## 这些材料在「HTTP 接口与外部系统」这一环带来什么约束
不同材料的特征会对HTTP接口与外部系统对接环节带来多重约束。多源数据需适配不同系统的鉴权规则，如交易所债券系统需专用API密钥，第三方工商司法数据需授权访问凭证；不同更新频率要求配置差异化的同步触发机制，实时类数据需接口支持轮询或回调，周期性数据可配置定时调用。多格式材料需接口兼容PDF、结构化表格、JSON等多种传输格式，回传口径需匹配各外部系统的字段规范，避免因格式不兼容导致数据丢失或校验失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600–900 秒` | 适配长文档解析的常见取法，需按实际材料复杂度标定 |
| `maxContext` | `8000–12000 字符` | 覆盖单份核心文档上下文的常见取法，需按实际文档长度调整 |
| `召回条数` | `前 8–12 条` | 平衡检索完整性与效率的常见取法，需按材料总量标定 |
| `相似度阈值` | `0.75–0.85` | 过滤低相关检索结果的常见取法，需按业务核查需求调整 |
| `重排返回条数` | `前 3–5 条` | 聚焦核心核查材料的常见取法，需按实际业务场景调整 |
| `分段长度` | `1000–1500 字符` | 避免条款被截断的常见取法，需按文档排版特征标定 |

## 最耗时的环节会卡在哪
三个最耗时的环节中，接口环节可覆盖部分自动化工作，但仍存在无法替代的人工环节。重建现金流、债务结构和偿债压力环节，接口可自动抽取财报、债券市场数据中的本息字段，但无法适配发行人定制化偿债安排，失败形态包括抽取字段为空、结果与原件对不上。核验募集资金用途及重大债务事项环节，接口可自动比对募集资金账户流水与说明书条款，但无法识别隐性关联交易，失败形态包括召回不到对应条款、超时中断。协调发行窗口、簿记定价及存续责任文件环节，接口可获取交易所系统的时段信息，但无法替代人工沟通协调，失败形态包括需要人工回退重做。

## 做错了会怎样
操作失误会带来多维度风险。业务层面可能因信用风险误判造成承销或投资风险；合同层面可能引发债券及担保条款争议；监管层面可能因尽调、募集说明书、募集资金或存续管理不规范被处理；投资者层面可能因重大遗漏影响定价和受偿预期。易引发此类后果的配置失误包括：分段长度设置过短导致条款被截断，召回条数过低漏掉关键核查材料，未开启溯源功能导致答复无法回原件核对，鉴权配置错误导致接口调用失败无法获取核心数据。

## 与相邻品类的区别
与股权发行品类相比，本场景核心核查债务偿付、本息安排、担保条款及募集资金用途，存续期偿债事项为持续工作对象。股权发行品类需聚焦股权结构、股权变更及股权类募资用途，因此本场景的接口配置、检索逻辑及核查规则无法直接适配股权发行场景，需针对业务重点调整参数与对接逻辑。

## 还需要按机构实际情况确认的
- 具体簿记工作时点由发行安排决定：不同机构的发行流程节点存在差异，需结合自身业务流程确认接口触发时机。
- 未找到公开依据证明三项为统一前三耗时：各机构的业务流程优先级不同，耗时环节排序可能存在差异，需结合内部业务数据验证。
