# 信用卡场景的日志与审计：留存范围与访问边界

## 这个品类每天在处理什么材料
日常处理的材料包含信用卡申请、授信审批、账单、分期协议、交易争议资料、调额记录、反欺诈处置、催收及投诉记录。数据来源覆盖信用卡交易系统、个人征信、商户/收单数据、反欺诈系统、客服投诉系统。各类材料形态存在差异，交易系统数据为结构化流水，征信报告为制式文本，分期协议属于合同类文档，投诉记录则为工单形式。数据更新频率各有不同，交易数据实时生成，账单按账期更新，征信数据按授权和管理需要更新，欺诈预警随交易触发，调额复核频率因机构而异。

## 这些材料在「对话日志与审计」这一环带来什么约束
不同材料的更新节奏要求审计链路匹配对应频率，实时交易数据需要同步关联审计日志，账期类材料需按周期完成汇总审计。不同来源的数据敏感程度存在差异，征信、投诉记录涉及客户隐私，需严格限制访问边界。部分材料如分期协议、催收记录存在明确的留存周期要求，需在审计环节匹配对应留存规则。多源数据的关联逻辑复杂，需在审计时完成跨系统数据的溯源校验，确保日志与原始材料一一对应。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `分段长度` | 800–1200 字符 | 适配信用卡类文档的段落结构，常见取法，需按实际材料的排版密度标定 |
| `召回条数` | 前6–8条 | 覆盖核心交易、账单等关键材料的关联信息，常见取法，需按业务审计的覆盖范围调整 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 处理大额分期协议、投诉记录等长文档，常见取法，需按单份文档的平均大小调整 |
| `maxContext` | 15–20 轮对话 | 保留完整的审计链路上下文，常见取法，需按业务的审计回溯周期调整 |
| `相似度阈值` | 0.75–0.85 | 匹配交易流水、征信报告等结构化数据的关联关系，常见取法，需按数据字段的匹配精度调整 |
| `重排返回条数` | 前3–5条 | 优先展示最相关的审计材料，常见取法，需按业务的核心审计维度调整 |

## 最耗时的环节会卡在哪
在高频交易中识别盗刷、套现等异常环节，该功能可关联交易系统与反欺诈系统的日志，召回对应交易的审计材料，若配置失误会出现召回不到对应交易记录、抽取字段为空的问题，但无法自主完成异常交易的合规性判定，需人工结合规则复核。持续评估额度、账单和还款风险环节，可按账期召回账单、授信审批、调额记录，若超时设置过短会出现超时中断，若召回条数不足会导致结果与原件对不上，但无法动态调整风险评估模型，需结合历史数据人工复核。处理拒付、分期、息费、盗刷和催收争议环节，可召回投诉记录、分期协议、交易争议资料，若分段长度过短会切断关键条款，导致需要人工回退重做，但无法直接生成争议处理结果，需人工核对原始材料。

## 做错了会怎样
操作失误可能引发多类后果：业务层面可能因欺诈识别疏漏、过度授信或错误交易处理造成损失；合同层面可能因账单、息费及分期约定的审计疏漏产生争议；监管层面可能因授信、营销、催收环节的不规范操作被处理；客户层面可能因盗刷、错误扣款或不当催收直接引发投诉。容易引发这些后果的配置失误包括：分段长度过短切断分期协议等关键条款，召回条数过低漏掉核心交易或投诉记录，未开启溯源导致答复无法与原始文档核对，相似度阈值设置不当导致匹配错误的关联材料，超时设置过短导致长文档解析失败。

## 与相邻品类的区别
与个人消费贷款相比，信用卡是持续存在的循环授信及支付账户，核心数据包含逐笔交易、账单、额度和争议处理内容。个人消费贷款的核心数据为一次性贷款申请、放款及还款记录，两类场景的审计维度与关联数据逻辑存在差异，因此同一套配置无法直接适配。信用卡需按账期完成交易汇总审计，而个人消费贷款仅需围绕单笔贷款的全流程开展审计。

## 还需要按机构实际情况确认的
- 本轮未取得直接定义信用卡完整运营流程的单一一手规则，不同机构的运营流程存在差异，需结合自身机构的实际制度确认审计边界。
- 异常交易规则、调额和催收流程主要取决于机构制度，不同机构的规则标准不同，审计的留存范围与访问权限需按自身机构的制度调整。
