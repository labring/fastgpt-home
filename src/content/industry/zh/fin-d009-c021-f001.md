# 固定资产贷款与业务系统对接：接口、鉴权与回传口径

## 这个品类每天在处理什么材料
该品类日常处理的材料包括可研或投资方案、依法需要的审批核准备案及许可材料、资本金证明、工程及采购合同、授信调查报告、提款材料、工程进度及贷后检查资料。数据来源覆盖企业及项目资料、发改和行业主管部门公开信息、银行信贷系统、工程进度资料、不动产及担保登记、工商征信。不同材料的更新频率存在差异：信贷系统数据随事件触发更新，项目审批许可数据随事项变更触发更新，工程进度数据按项目节点更新，外部登记数据在查询时获取，机构复核无统一公开要求。各类材料形态涵盖结构化审批文件、非结构化合同文本、动态更新的进度数据等，差异明显。

## 这些材料在「HTTP 接口与外部系统」这一环带来什么约束
多类型材料要求接口兼容多种MIME格式，支持结构化数据拉取与非结构化文件上传。多数据源对接需求需要统一的鉴权体系，适配发改、工商、登记机构等不同外部系统的权限规则。不同更新频率要求接口同时支持事件回调与按需查询两种模式，满足实时同步与临时调取的需求。提款、贷后材料的时效性要求接口具备稳定的响应能力与可靠的回传机制，避免因接口延迟导致流程中断。各类材料的校验逻辑需通过接口完成数据比对，确保外部系统返回的信息与内部材料一致。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 处理大额审批文件的常见超时设置，需按实际材料大小标定 |
| `recall_top_k` | 前 5-8 条 | 覆盖核心审批材料的常见召回量，需按项目材料总量调整 |
| `chunk_size` | 800-1200 字符 | 平衡上下文完整性和检索效率的常见分段长度，需按文档结构调整 |
| `chunk_overlap` | 50-100 字符 | 避免分段截断关键条款的常见重叠设置，需按文档复杂度调整 |
| `api_retry_times` | 3 次 | 应对外部接口临时波动的常见重试次数，需按对接系统稳定性调整 |
| `webhook_timeout` | 30 秒 | 确保回传请求正常完成的常见超时设置，需按回传数据量调整 |

## 最耗时的环节会卡在哪
核实项目总投资、资本金及依法需取得的审批许可条件环节，可通过接口拉取发改备案、工商征信、信贷系统的存量数据自动匹配材料数值，若召回不到对应审批文件、抽取字段为空则无法完成自动校验，需人工补全。复核投资回报和借款人整体偿债来源环节，可拉取授信报告、工程进度数据自动计算回收周期，若接口超时中断、返回结果与原件数据对不上则需人工复核。按工程/采购进度核验提款及支付对象环节，可拉取进度资料、采购合同自动比对申请信息，若需人工回退重做、抽取的支付对象字段错误则无法直接通过校验。跨行业具体审批规则、宏观偿债环境判断、线下交易背景核实等内容无法通过接口自动完成。

## 做错了会怎样
操作失误可能导致业务损失、合同争议、监管措施及客户资金安排受影响。配置失误易引发这类问题：`chunk_size`设置过小切断审批许可条款，导致建设条件、资本金判断错误；`recall_top_k`设置过低漏掉关键资本金证明材料，引发投资收益判断偏差；未开启溯源功能导致回传数据无法与原件核对，产生合同争议；`webhook_timeout`设置过短导致回传失败，延误提款流程。

## 与相邻品类的区别
与项目融资相比，固定资产贷款范围更广，不要求每笔贷款都主要依赖该项目自身未来收入偿债。与流贷相比，固定资产贷款围绕长期资产投资、项目总投资和建设进度开展。两类相邻品类的业务逻辑与材料重点不同，项目融资需更聚焦项目自身现金流的检索配置，流贷则围绕短期资金周转需求设计接口与校验规则，因此同一套配置无法适配相邻品类。

## 还需要按机构实际情况确认的
- 各行业具体审批许可和资本金要求需按项目类型核实，不存在统一“四证齐全”口径。不同行业的监管要求存在差异，各机构内部评审标准也有所不同，需结合项目所属行业与机构规则确认。
- 前三耗时环节的排序未找到统一公开依据。不同机构的业务流程、人员配置存在差异，耗时环节的优先级会随实际业务情况变化，需结合本机构的业务数据确认。
