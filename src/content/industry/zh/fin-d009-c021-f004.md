# 固定资产贷款知识库的向量与索引：维度、重建与迁移代价

## 这个品类每天在处理什么材料
该品类日常处理的材料包含可研或投资方案、依法需取得的审批核准备案及许可材料、资本金证明、工程及采购合同、授信调查报告、提款材料、工程进度及贷后检查资料。数据来源覆盖企业及项目资料、发改和行业主管部门公开信息、银行信贷系统、工程进度资料、不动产及担保登记、工商征信。不同来源的材料形态存在差异，信贷系统数据多为结构化格式，审批文件、工程合同等多为非结构化电子或纸质文档，更新频率也各有不同：信贷系统数据随事件触发更新，项目审批许可材料随事项变更更新，工程进度资料按项目节点更新，外部登记信息则在查询时获取，机构复核频率无统一要求。

## 这些材料在「向量模型与索引」这一环带来什么约束
不同类型材料的格式差异要求索引系统适配多源解析逻辑，确保非结构化文档的关键信息可被有效抽取。多数据来源带来的分散性，需要统一的索引维度覆盖企业、项目、监管、担保等多类信息。不同更新频率要求区分全量与增量索引策略，对实时性要求较高的提款材料、工程进度资料需配置准实时更新逻辑。部分材料需在查询时动态获取，索引系统需预留动态数据接入接口。不同材料的重要性层级不同，需支持按材料类型调整权重配置，保障核心审批、资本金相关材料的召回优先级。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `分段长度` | 800–1200 字符 | 常见取法，需按实际材料的段落密度、关键信息粒度标定 |
| `召回条数` | 前 5–8 条 | 常见取法，需按项目材料的关键信息覆盖度标定 |
| `相似度阈值` | 0.75–0.85 | 常见取法，需按不同文档类别的重要性调整 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300–600 秒 | 常见取法，需按大型可研报告的解析时长标定 |
| `maxContext` | 8000–12000 字符 | 常见取法，需按单轮问答的上下文承载量标定 |

## 最耗时的环节会卡在哪
核实项目总投资、资本金及依法需取得的审批许可条件这一环节，向量索引可召回相关可研、审批材料并抽取关键数据，但无法替代人工核对具体条款细节，若召回不到对应审批文件或抽取资本金字段为空，将导致核实工作停滞。复核投资回报和借款人整体偿债来源环节，索引可整合授信报告、征信数据辅助分析，但无法完成跨部门的整体偿债能力校验，若解析超时或结果与原件对不上，需重新执行检索流程。按工程/采购进度核验提款及支付对象环节，索引可匹配进度资料与提款材料，但无法确认支付对象的合规性，若召回不到对应采购合同，需人工回退重做检索。

## 做错了会怎样
该功能环节出错将引发多重后果：业务层面因建设条件、资本金或投资收益判断错误形成损失；合同层面因提款条件未满足仍放款产生争议；监管层面因违反固定资产贷款规则被采取监管措施；客户层面因错放或停放影响项目资金安排。易引发此类后果的配置失误包括：分段长度设置不当切断关键条款，召回条数过低漏掉核心审批材料，未开启溯源导致答复无法回原件核对，相似度阈值设置不合理导致召回无关或冗余信息。

## 与相邻品类的区别
与项目融资相比，固定资产贷款范围更广，不要求每笔贷款都主要依赖该项目自身未来收入偿债。与流贷相比，固定资产贷款围绕长期资产投资、项目总投资和建设进度展开。两类相邻品类的核心材料、信息关注点均存在差异，因此同一套向量与索引配置无法直接适配，需针对各自的业务逻辑调整参数。

## 还需要按机构实际情况确认的
- 各行业具体审批许可和资本金要求需按项目类型核实，不存在统一“四证齐全”口径，不同行业、区域的监管要求存在差异，需结合当地规则调整索引的匹配逻辑。
- 最耗时环节的排序未找到统一公开依据，不同机构的业务流程、人员配置不同，耗时优先级可能存在变化，需结合实际业务场景校准检索优先级。
