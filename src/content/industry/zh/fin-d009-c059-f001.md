# 项目融资与业务系统对接：接口、鉴权与回传口径

## 这个品类每天在处理什么材料
日常处理的材料包括项目融资方案、可研、项目合同、特许经营协议、资本金证明、项目现金流模型、建设及运营合同、提款条件清单、贷后项目监测表。数据来源涵盖项目建设运营资料、项目合同及付费机制、行业价格/需求数据、银行信贷系统、项目账户流水、担保和保险资料。不同材料形态差异明显，既有非结构化的长文本协议，也有结构化的表格类文档与流水数据，部分材料需结合多来源数据联动更新，更新频率随类型区分：建设进度与项目账户随项目节点或交易更新，运营收入按结算周期更新，宏观及行业数据按公开发布周期更新，统一复核频率未找到公开要求。

## 这些材料在「HTTP接口与外部系统」这一环带来什么约束
多类型材料要求接口支持多格式解析与上传，适配非结构化文本、结构化表格等不同形态的资料；多数据来源需对接多个外部系统，要求接口兼容多种鉴权方式；不同更新频率需要支持定时拉取与实时触发两种接口模式，匹配项目节点、结算周期等不同更新节奏；长文本类材料如项目合同、可研需要支持大文件上传接口，避免传输中断；提款条件清单、贷后项目监测表等需实时校验的材料，要求接口具备低延迟响应能力，保障业务流程顺畅。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600–900 秒 | 针对大额结构化模型文件与长文本合同，常见取法，需按实际材料大小与解析复杂度标定 |
| `chunk_size` | 800–1200 字符 | 适配长文本合同与现金流模型的分段解析，常见取法，需按文档排版结构调整 |
| `top_k` | 5–10 条 | 召回核心条款与数据字段，常见取法，需按检索精度需求调整 |
| `rerank_top_n` | 3–5 条 | 重排关键匹配结果，常见取法，需按业务核心资料优先级设定 |
| `api_request_timeout` | 30–60 秒 | 适配外部系统数据拉取与回传流程，常见取法，需按对接系统响应速度调整 |
| `max_context_tokens` | 8000–12000 | 承载多来源关联数据，常见取法，需按业务上下文规模标定 |

## 最耗时的环节会卡在哪
建立建设期至运营期全生命周期现金流模型环节，可通过接口自动拉取项目账户流水、建设进度数据更新模型节点，但无法自主完成交易结构适配的参数调整，做不好会出现抽取的现金流数据缺失、结果与原件不符，需人工回退重做。核对项目合同、资本金、建设和提款前提环节，可自动拉取银行信贷系统的资本金证明与合同条款，但无法完成法律逻辑校验，做不好会出现召回不到对应条款、抽取字段为空，导致核对流程中断。持续验证项目收入、成本、覆盖倍数及重大风险变化环节，可按结算周期拉取运营收入数据，但无法识别突发政策变化，做不好会出现超时中断验证、结果与实际情况偏差。

## 做错了会怎样
出错后果涵盖多方面：业务层面项目收入预测偏差或建设延期可直接削弱偿债能力；合同层面项目合同、担保或提款条件错误影响权利实现；监管层面调查和风险管理不符合规则可被监管纠正；客户层面提款延误可影响工程安排。易引发此类后果的配置失误包括：分段长度设置过短切断合同条款导致召回不全，召回条数过低漏掉关键材料，未开启文件溯源导致无法核对结果与原件，接口超时设置过短导致数据拉取中断。

## 与相邻品类的区别
相较一般固定资产贷款，项目融资更依赖特定项目未来收益偿债，项目合同、现金流模型和运营期监测是核心资料链。不是所有固定资产贷款都属于项目融资，一般固定资产贷款的核心资料聚焦抵押物与企业财报，无需专门对接现金流模型与提款条件清单的接口，因此本环节的配置无法直接适配相邻品类。

## 还需要按机构实际情况确认的
- 项目融资具体无追索/有限追索程度依交易结构而异，不同机构的交易结构设计存在差异，需适配不同的接口校验逻辑。
- 未找到公开依据证明三项工作统一构成行业前三耗时，不同机构的作业流程与资源配置不同，耗时排序可能存在差异，需结合自身业务验证。
