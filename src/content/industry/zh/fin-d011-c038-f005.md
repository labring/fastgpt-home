# 消费者权益保护与投诉处理材料的多轮问答与提示词：口径固化与变量传递

## 这个品类每天在处理什么材料
该品类日常处理的材料包括投诉工单、录音、聊天记录、合同及产品材料、交易记录、销售留痕、调查记录、回复函、调解、和解材料、整改报告。数据主要来自客服投诉系统、业务交易系统、销售留痕、合同和产品库、监管转办材料，不同材料的更新频率存在差异：投诉工单为事件触发更新，通话与交易记录为实时或业务触发更新，整改跟踪材料按案件及机构制度更新，具体处理期限需按现行适用投诉规则逐案核实。各类材料形态涵盖结构化工单、非结构化音视频、文档类文本，需适配不同的解析与调用逻辑。

## 这些材料在「多轮对话与提示词」这一环带来什么约束
该场景的多轮对话与提示词环节受材料特征带来多重约束。首先，材料类型覆盖结构化与非结构化内容，需适配不同的解析与召回逻辑；其次，数据来源跨多个业务系统，多轮对话需联动跨源调取关联证据；第三，不同材料的更新频率差异较大，需支持按需同步最新的投诉、交易与整改材料；最后，材料间存在强关联逻辑，多轮对话需逐步还原事实链条，提示词需明确每一轮的调用目标与口径要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `分段长度` | 800–1200 字符 | 适配多数消保文档的段落语义完整性，常见取法，需按实际材料长度标定 |
| `召回条数` | 前6–8条 | 覆盖核心证据材料的关联内容，常见取法，需按投诉案件复杂度调整 |
| `相似度阈值` | 0.72–0.80 | 平衡精准召回与漏召回风险，常见取法，需按机构口径要求调整 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配长文档、音视频材料的解析时长，常见取法，需按单文件最大体积调整 |
| `maxContext` | 前15–20轮对话 | 保留投诉处理的完整上下文，常见取法，需按对话链路长度调整 |

## 最耗时的环节会卡在哪
最耗时的三个环节中，该功能可分别覆盖部分工作。调取合同、交易、录音和销售记录还原事实环节，可自动跨系统召回关联材料，减少人工查找时间，但无法自动完成音视频内容的精准匹配，若召回条数过低会出现召回不到对应条款的问题。协调业务、合规和分支机构判断责任并拟定答复环节，可通过提示词固化责任认定口径，自动生成初步答复框架，但无法替代跨部门的权责判断，若未开启溯源会导致结果与原件对不上，需要人工回退重做。跟踪重复投诉、重大投诉和整改闭环环节，可自动标记重复投诉的关联工单，跟踪整改节点，但无法自动完成整改闭环的合规校验，若超时设置过短会出现超时中断的问题。

## 做错了会怎样
做错后会带来多维度的不良影响。业务层面，错误处置可扩大损失；合同层面，责任认定不当可能进入调解、仲裁或诉讼；监管层面，投诉机制及消保义务不符合要求可能被整改或处罚；客户层面，答复错误或拖延直接导致升级投诉。容易引发这些后果的配置失误包括：分段切断条款导致口径偏差，召回条数过低漏掉关键证据材料，未开启溯源导致答复无法与原件核对，相似度阈值设置不当导致召回无关内容，超时设置过短导致解析中断。

## 与相邻品类的区别
与一般客服问答品类的关键差别在于，本场景核心是证据调取、责任认定、正式回复和整改留痕，且往往跨多个业务系统和责任部门。一般客服问答多为单轮或短上下文的即时答复，无需跨系统调取多类证据，也无需完成责任认定与整改留痕，因此该场景的配置需适配跨源召回、多轮上下文关联与合规口径固化，无法直接复用一般客服问答的配置。

## 还需要按机构实际情况确认的
- 2026年投诉处理规则处于修订过程，本表不擅自使用征求意见稿时限替代现行有效要求，需按各机构现行有效规则确认处理期限。
- 不同机构的投诉分级标准待核实，需结合机构内部的投诉分级规则调整配置参数。
