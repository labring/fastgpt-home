# 监管统计与数据报送材料的多轮问答与提示词：口径固化与变量传递

## 这个品类每天在处理什么材料
本品类日常处理的材料包括监管统计报表、指标口径说明、数据映射表、数据质量校验记录、差错更正说明、报送审批及留痕。主要数据来源涵盖核心系统、信贷/交易/财务/风险数据仓库、监管统计制度和监管报送平台。各类材料形态差异明显：监管统计报表多为结构化表格，指标口径说明为规范性文本，数据映射表为字段对应清单，数据质量校验记录为异常台账，差错更正说明为修正文档，报送审批及留痕为流程记录。业务源数据随交易更新，各监管报表按具体统计制度规定的报送期更新，口径变更随监管制度发布触发，不存在统一的更新周期。

## 这些材料在「多轮对话与提示词」这一环带来什么约束
多轮对话与提示词环节受材料特征带来多重约束。跨系统字段映射、多业务线数据关联要求对话需持续保留历史口径、映射、差错记录的上下文，确保信息连贯。材料更新周期不统一，需动态适配不同报表的口径时效，提示词需支持按报送期触发内容更新。异构材料的格式差异要求提示词适配结构化表格与非结构化文本的抽取逻辑，避免信息提取偏差。跨业务的横向数据责任链要求对话覆盖多业务线的关联材料，防止上下文遗漏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | 前5-8条 | 常见取法，需按实际材料的跨表勾稽关联数量标定，覆盖多份关联文档 |
| `相似度阈值` | 0.75-0.85 | 常见取法，需按口径说明、映射表的文本相似度精度要求标定，避免误召回无关材料 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300-600秒 | 常见取法，需按单份大型监管报表、制度文档的解析时长标定，避免超时中断 |
| `maxContext` | 8000-12000字符 | 常见取法，需按多轮对话需保留的历史口径、映射、差错记录总长度标定 |
| `重排返回条数` | 前3-5条 | 常见取法，需按最相关的口径、映射文档数量标定，优先展示核心关联内容 |
| `分段长度` | 1000-1500字符 | 常见取法，需按单份口径说明、制度文档的段落结构标定，避免切断关键条款 |

## 最耗时的环节会卡在哪
最耗时的三个环节中，该功能可分别覆盖部分工作。跨系统字段映射环节，功能可快速召回对应数据映射表与口径说明，辅助匹配字段，但无法确认跨系统字段的实际业务含义，做不好时会出现召回不到对应条款、抽取字段为空的问题。跨表勾稽与数据质量校验环节，功能可调用数据质量校验记录辅助排查，但无法判断异常值的业务背景合理性，做不好时会出现结果与原件对不上、需人工回退的问题。复核报送环节，功能可生成初步解释文本，但无法完成监管合规判断，做不好时会出现超时中断、需人工重做的问题。

## 做错了会怎样
出错后果包括错误数据影响内部及监管判断，迟报、错报、漏报或统计造假可能被监管处理，严重数据问题可能间接影响客户分类和服务。易引发该后果的配置失误包括：分段长度设置不当切断关键口径条款，召回条数过低漏掉核心关联材料，未开启溯源功能导致答复无法回原件核对，超时设置过短导致解析中断。

## 与相邻品类的区别
本品类为跨贷款、存款、保险等业务的横向数据责任链，核心对象是指标口径、字段映射、报表勾稽和报送责任。相邻品类多聚焦单一业务线的业务产品流程，无法覆盖跨业务的横向数据关联需求，因此同一套配置无法适配跨业务的字段映射、勾稽校验等场景。

## 还需要按机构实际情况确认的
- 每张监管报表的具体报送周期需逐套报表制度二次核实，无法通过《监管统计管理办法》统一推导，因不同机构覆盖的监管报表范围存在差异。
- 每张监管报表的字段定义需逐套报表制度二次核实，无法通过《监管统计管理办法》统一推导，因不同监管主体的报表要求存在差异。
