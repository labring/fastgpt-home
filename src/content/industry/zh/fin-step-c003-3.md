# 上市公司再融资的将申报文件与既往定期/临时公告逐项勾稽：哪一部分能交给系统

## 这一步现在是怎么做的
常见做法为将申报文件与历史披露材料逐项拆解比对，先梳理申报文件中的募集说明书、发行方案、保荐文件等核心内容，再从历史公告、交易所审核信息等数据源中调取对应披露信息。人工主要耗时在定位差异项、核实披露一致性，涉及前次募集资金使用报告、问询回复、董事会及股东会资料等多类材料的交叉核对，需结合公司账套、募集资金专户等数据验证披露内容的真实性。

## 哪一部分能交给系统
可通过检索、抽取、比对、生成能力承接部分环节：一是基于检索能力，从历史公告、交易所审核信息等数据源中召回与申报内容相关的披露条款；二是通过文档抽取能力，从申报文件与历史公告中抽取指定字段，如募投项目名称、融资规模、前次募资余额等；三是通过结构化比对能力，自动核对两类材料中相同字段的一致性；四是通过内容生成能力，整理比对出的差异项形成待核实清单。

## 哪一部分交不了
需由人工判断或确认的环节包括：差异项的定性判断，如区分披露笔误与实质性披露不一致；结合业务场景验证披露内容的合理性，如募投项目效益假设与历史披露的匹配性；以及最终的审核签字确认环节。系统无法理解业务实质，无法判断监管合规性的定性，且无法替代人工承担业务权责确认的要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `公告数据源范围` | 近3年上市公司公告+当期交易所审核信息 | 常见取法，需按实际标定 |
| `字段抽取相似度阈值` | ≥0.85 | 常见取法，需按实际标定 |
| `比对规则集合` | 按再融资工具类型预设匹配项 | 适配不同发行环节的材料差异 |
| `RAG检索召回上限` | 前20条结果 | 常见取法，需按实际标定 |

## 做不好会以什么形式暴露
- 召回不到对应条款：通常由`公告数据源范围`配置过窄，未覆盖所需披露周期导致
- 抽取字段为空：通常由`字段抽取相似度阈值`设置过高，或未配置对应文档类型的抽取规则导致
- 结果与原件对不上：通常由`比对规则集合`未覆盖特定字段匹配要求，或数据源未包含最新披露信息导致
