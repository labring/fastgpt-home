# 保险资产管理的将保险负债久期、现金流：哪一部分能交给系统

## 这一步现在是怎么做的
该环节需先整合多源数据，从保险负债和现金流数据、投资风险系统提取核心指标，结合委托投资合同、资产配置、信用尽调、投资决策文档明确资产准入范围与限额，再对接银行间/交易所市场数据、发行人财报、托管机构数据校验资产匹配度，过程中需反复核对估值及风险报告、资管产品披露信息。常见做法下，多数耗时集中在跨系统数据整理、不同来源信息的交叉比对，以及非标资产相关的底稿核对。

## 哪一部分能交给系统
可通过向量检索能力从委托投资合同、资产配置文档中快速召回允许的资产类型、久期区间、集中度限额等条款；可通过结构化抽取能力从保险负债数据、估值报告中自动提取久期、现金流节点、资本约束指标；可通过多源数据比对能力，将市场交易数据、发行人财报与负债要求的匹配度进行自动校验；可通过规则生成能力，基于上述结果生成初步的资产配置条件清单。各环节分别对应检索、抽取、比对、生成的系统能力，减少手动整理的重复工作量。

## 哪一部分交不了
需由人判断的部分包括：不同机构非标尽调底稿的实质风险判定，结合最新监管事件调整配置的合规判断，以及委托投资合同超范围投资的责任界定。由于不同保险公司的资产负债管理模型和限额体系不统一，系统无法直接适配所有机构的内部规则；非标尽调底稿存在显著机构差异，系统难以统一识别所有非标资产的风险细节，需结合从业团队的专业经验完成最终审核与签字确认。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `负债久期匹配阈值` | ±10%区间 | 常见取法，需按实际业务标定 |
| `现金流覆盖周期` | 1-10年区间 | 匹配保险负债久期特征，常见取法需按实际标定 |
| `数据更新触发规则` | 交易时段/事件、估值日、财报发布日 | 对应各数据源的更新频率，符合业务数据同步要求 |
| `非标资产校验模板` | 匹配机构内部通用格式 | 适配待核实的机构底稿差异，需按实际调整 |

## 做不好会以什么形式暴露
- 检索结果召回不到对应委托投资合同条款，通常由向量库未完整导入指定文档导致
- 抽取的负债久期或现金流字段为空，通常由抽取模型未适配保险负债数据格式导致
- 系统处理超时中断，通常由数据同步范围设置过大或触发规则不合理导致

## 还需要按机构实际情况确认的
- 不同保险公司的资产负债管理模型和限额体系不公开统一，需结合机构内部规则调整系统配置
- 非标尽调底稿存在显著机构差异，需适配不同机构的底稿格式与校验逻辑
