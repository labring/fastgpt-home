# 债券基金投资与运营的跟踪评级、重大事项、市场价格和流动性：哪一部分能交给系统

## 这一步现在是怎么做的
常见做法为，先从指定数据源拉取主体、债项信用报告、评级跟踪、久期分析、投决记录、成交单、估值表、流动性及定期报告等材料，逐一核对评级跟踪报告的更新情况，提取重大信用事件信息，比对市场成交数据与托管估值系统的估值结果，跟踪单只债券的流动性指标。该环节的主要耗时点在于跨多个数据源手动汇总信息，核对不同来源数据的一致性，以及排查异常数据的来源。

## 哪一部分能交给系统
可由系统承接的部分包括：一是实时同步行情、收益率数据，对应数据拉取能力，对接银行间和交易所债券市场、托管估值系统，实现交易时段的自动更新；二是事件触发式检索评级跟踪、重大事项文档，对应关键词匹配与文档抽取能力，自动识别并提取更新内容；三是结构化字段比对，对应结构化数据抽取与比对能力，核对成交单与估值表的核心数据；四是定期报告关键信息提取，对应文本抽取能力，快速定位偿债能力相关内容。此类自动化动作可替代重复的手动核对与信息汇总工作，压缩环节耗时。

## 哪一部分交不了
必须由人工判断或签字的部分包括：一是内部信用评级的调整逻辑，不同机构的内部评级方法无统一公开模板，需结合行业经验与持仓情况判断；二是重大事项的影响评估，需结合组合久期、信用暴露比例等参数评估对净值的实际影响，无法通过系统自动完成；三是异常数据的溯源核实，当不同数据源出现信息不一致时，需人工确认原始凭证与业务背景。此类工作涉及投资决策与合规判断，无法由系统完全替代。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `数据源对接范围` | 银行间市场、交易所市场、发行人财报、评级资料、托管估值系统 | 覆盖主要业务数据来源，常见取法需按实际机构的可用数据源标定 |
| `数据更新触发规则` | 行情/收益率：交易时段实时更新；评级和重大信用事件：事件触发更新；财报：定期更新；估值：基金估值日更新 | 匹配行业通用的数据更新频率，常见配置需按机构运营周期调整 |
| `文档抽取字段` | 主体评级、债项评级、重大事项类型、成交价格、流动性指标、估值净值 | 覆盖核心业务跟踪需求，需按实际持仓跟踪的具体字段标定 |
| `超时阈值` | 10-30秒 | 应对多数据源拉取的延迟风险，常见取法需按机构系统响应要求调整 |
| `召回匹配阈值` | 0.85-0.95 | 平衡信息召回率与准确性，需按实际业务的容错要求标定 |

## 做不好会以什么形式暴露
- 召回不到对应评级更新条款，通常由`数据源对接范围`未配置评级资料源，或`召回匹配阈值`设置过高导致信息过滤过度。
- 抽取的估值字段为空，通常由`文档抽取字段`未包含对应估值项，或`数据更新触发规则`未配置估值日同步导致数据未及时拉取。
- 任务超时中断，通常由`超时阈值`设置过短，或`数据源对接范围`包含过多未优化的外部数据源导致系统响应延迟。

## 还需要按机构实际情况确认的
- 债券基金内部信用评级方法和跟踪触发条件无行业统一公开模板。
- 耗时排序待管理人实证。
