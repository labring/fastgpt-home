# 养殖业农业保险的查明死亡、疫病或扑杀原因及保险责任：哪一部分能交给系统

## 这一步现在是怎么做的
常见做法为，先调取养殖户提交的出险相关全套材料，结合查勘定损资料，从个体识别系统、存栏系统提取对应个体的存栏状态，核对耳标等识别信息与承保清单的一致性，比对检疫记录、死亡扑杀证明与无害化处理证明的关联关系，再对照保险条款梳理责任边界。该环节的主要耗时点在于跨数据源的信息核对，以及不同材料间的匹配校验，用到的材料包括养殖户资料、承保清单、耳标、个体识别或批次资料、存栏记录、检疫材料、死亡扑杀证明、无害化处理证明、查勘定损和赔款资料。

## 哪一部分能交给系统
可通过系统承接的环节包括：一是文档内容抽取，从各数据源提取个体识别信息、存栏状态、检疫记录、死亡扑杀时间、无害化处理编号等关键字段；二是多文档比对，将提取的识别信息与承保清单做一致性校验，核对无害化处理记录与出险事件的匹配度；三是主键关联，按照“动物/批次—存栏—检疫—死亡—无害化”的核心逻辑关联各环节信息；四是条款初步检索，根据出险原因匹配对应保险条款的责任范围。上述环节分别对应文档抽取、多源比对、实体关联、知识库检索等系统能力。

## 哪一部分交不了
必须由人工完成的环节包括：一是死亡、疫病或扑杀的定性判断，系统仅能基于提交的书面材料进行校验，无法替代人工对现场实际情况的核实；二是免责情形的认定，如是否存在故意造成损失等主观因素，系统无法识别材料之外的隐含信息；三是本地化政策与条款的适配判断，不同地区的无害化处理适用规则存在差异，需结合当地政策和具体保险条款完成最终确认。此外，部分需要人工签字确认的查勘环节，无法由系统直接承接。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `知识库检索阈值` | 0.7-0.9 | 常见取法，需按实际业务条款匹配精度标定 |
| `实体抽取字段集` | 个体标识、存栏状态、检疫时间、死亡时间、无害化处理编号 | 覆盖核心数据关联所需的关键信息 |
| `多源比对匹配度` | 0.85以上 | 常见取法，需按实际跨文档校验的精度要求调整 |
| `主键关联规则` | 按“动物/批次—存栏—检疫—死亡—无害化”链路配置 | 符合该品类的核心数据关联逻辑 |
| `检索召回条数` | 3-5条 | 常见的条款匹配检索范围，需按实际条款数量调整 |

## 做不好会以什么形式暴露
- 对应条款召回偏差，通常由知识库检索阈值设置不合理导致，阈值过高会遗漏相关条款，阈值过低会引入无关内容
- 关键实体抽取缺失，通常由实体抽取字段集配置不全，未覆盖核心识别信息导致
- 跨文档比对结果异常，通常由多源匹配度阈值设置不当，或主键关联规则配置错误导致

## 还需要按机构实际情况确认的
- 耳标并非所有养殖险种唯一识别方式，需结合实际承保的险种类型确认可用的个体识别手段
- 无害化处理作为理赔条件的具体适用范围，需按地方政策和保险条款逐一核实
