# 固定资产贷款的按工程/采购进度核验提款及支付对象：哪一部分能交给系统

## 这一步现在是怎么做的
常见做法为，先归集项目相关的全套文档与数据，包括可研或投资方案、依法需要的审批核准备案及许可材料、资本金证明、工程及采购合同、授信调查报告、提款材料、工程进度及贷后检查资料，再逐一核对提款申请的金额与工程/采购实际进度的匹配度，核验支付对象与合同约定主体的一致性，最后整理核验结果并提交审核。该环节的主要耗时点在于跨系统调取分散的项目资料、手动比对多份文档的信息一致性，以及针对不同项目的特殊要求调整核验逻辑。

## 哪一部分能交给系统
可通过系统承接的部分包括：跨源检索项目所需的审批许可、资本金证明、工程进度等资料，对应跨源数据检索能力；从提款材料、工程进度资料中抽取提款金额、完成进度比例、支付对象名称等结构化字段，对应文档信息抽取能力；比对已完成进度与提款申请金额的匹配度、支付对象与采购合同乙方的一致性，对应规则比对能力；生成标准化的核验记录清单，对应内容生成能力。系统可自动完成资料归集、信息提取与基础校验的重复动作，减少人工的机械性工作量。

## 哪一部分交不了
需由人工判断或签字的部分包括：各行业细分的审批许可与资本金要求的适配判断，因无统一口径，系统无法覆盖所有细分项目的特殊规则；结合线下贷后检查信息判断提款申请的业务实质合理性，系统无法获取实地核验的直观判断依据；最终核验结果的合规签字确认，需由业务人员承担相应责任，系统无法完成合规责任的认定。这些环节依赖专业判断与合规权责，无法完全由系统替代。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `跨源数据召回阈值` | 0.75-0.85 | 常见取法，需按项目复杂度标定 |
| `文档抽取字段匹配阈值` | 0.8-0.9 | 常见取法，需按字段重要性调整 |
| `规则比对触发条件` | 按提款金额占总投资比例分级，单笔超授信额度占比触发全量比对 | 常见取法，需按机构授信政策调整 |
| `生成内容模板` | 固定格式包含进度匹配度、支付对象核验结果、资料完整性说明 | 常见取法，需按机构内部文档规范调整 |

## 做不好会以什么形式暴露
- 召回不到对应审批许可材料，通常由跨源数据召回阈值设置过高导致，部分低匹配度的必要文档未被成功拉取。
- 抽取的支付对象字段为空，通常由文档抽取字段匹配阈值设置过高导致，无法识别非标准格式的合同主体信息。
- 核验流程超时中断，通常由规则比对触发条件设置过于宽松导致，大量低优先级提款申请触发全量比对，超出系统处理上限。

## 还需要按机构实际情况确认的
- 各行业具体审批许可和资本金要求需按项目类型核实，不存在统一“四证齐全”口径。
- 前三耗时排序未找到统一公开依据。
