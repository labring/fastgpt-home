# 基金估值核算与托管对账的把交易、公司行动、费用：哪一部分能交给系统

## 这一步现在是怎么做的
常见做法为，先归集交易确认、资金交收、TA数据（申赎业务触发更新）、银行及托管对账单等材料，逐笔匹配不同系统的交易明细，完成交易入账；再识别公司行动事件，调整对应资产的估值参数；核算各类运营费用并计入对应账项；最后生成估值表草稿，结合资产负债表、净值披露底稿等完成初步估值，再核对各类账项的勾稽关系，整理估值差错处理记录。该环节中，人工主要耗时在跨系统数据的手动匹配、异常交易或特殊公司行动的判断，以及差错记录的整理与复核。

## 哪一部分能交给系统
可通过系统承接的环节包括：多源数据的结构化抽取，从管理人交易系统、交易所/中国结算数据、行情数据源中提取交易明细、市场价格等核心字段，其中交易和交收数据按事件触发同步，市场价格按交易时段更新；跨系统基础数据的自动比对，匹配管理人账、托管账、资金账的条目信息；估值表初稿的自动生成，基于入账的交易、费用、公司行动数据完成初步估值，按基金估值日触发；历史估值差错处理记录的自动检索归集，辅助异常排查。各环节分别对应文档结构化抽取、多源数据比对、结构化内容生成、知识库检索等能力。

## 哪一部分交不了
部分环节仍需人工判断或操作，比如特殊公司行动的估值调整合理性判断，需结合产品合同条款确认；跨账项差异的最终判定，需结合机构内部规则确认是否属于可容忍范围；估值结果的最终复核与签字，需符合机构内部的层级要求；差错处理的SLA落地，需匹配机构的业务流程。这些环节涉及合同约定、内部合规要求及主观判断，若系统替代人工判断失误，可能引发净值差错、资金交收差异、投资者赔偿争议及监管合规问题，无法通过系统完全替代。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `多源数据同步间隔` | 1分钟-5分钟 | 常见取法，需按机构业务实时性要求标定 |
| `结构化抽取字段模板` | 交易日期、成交价格、证券代码、费用类型等 | 常见取法，需按产品核算规则调整 |
| `跨账项差异容忍阈值` | 按机构内部规则设定区间 | 常见取法，需结合合同及监管要求确认 |
| `估值生成触发节点` | 估值日当日收盘后 | 符合行业通用估值周期，需按产品类型调整 |
| `差错告警触发比例` | 单笔差异超过核定比例 | 常见取法，需按机构风控要求标定 |

## 做不好会以什么形式暴露
-  抽取字段为空，通常因`结构化抽取字段模板`未配置对应业务所需的字段，未按产品核算要求更新配置。
-  多源数据比对超时中断，通常因`多源数据同步间隔`设置过长，未及时拉取全量业务数据导致比对超时。
-  生成的估值结果与原件对不上，通常因`跨账项差异容忍阈值`配置偏差，未触发异常校验导致未修正数据差异。

## 还需要按机构实际情况确认的
-  管理人与托管人的差异容忍阈值的具体设定标准
-  估值复核层级及差错处理SLA的统一落地规则
