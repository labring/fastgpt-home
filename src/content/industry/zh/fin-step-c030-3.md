# 工程保险承保与理赔的事故后区分原有缺陷、事故损失、修复范围：哪一部分能交给系统

## 这一步现在是怎么做的
本环节为工程保险承保与理赔事故处理的核心耗时环节之一，同品类另外两个耗时环节为阅读施工、设计和技术资料识别高风险工序，以及随工程阶段核对保险标的、风险暴露和重大变更，本页不展开相关内容。该环节核心动作包括：收集整合工程合同、施工组织设计、工程量及进度、地质资料、现场查勘记录、保险合同、事故记录、修复方案及理算资料；对照历史缺陷记录与现场查勘情况，逐一区分标的原有缺陷与事故导致的损失；核对修复方案的覆盖范围与理算费用，匹配保险合同约定的责任边界。从业人员主要耗时在跨文档的信息比对，需逐一核对监理记录、施工进度数据与现场情况的差异，同时结合工程造价数据校验修复费用的合理性，分散的信息来源与复杂的边界判定是耗时的主要原因。

## 哪一部分能交给系统
可由系统承接的环节包括三类：一是文档检索与信息抽取，可自动从工程合同、保险合同中提取标的范围、原有缺陷约定等结构化信息，对应文档检索、实体抽取能力；二是多源数据比对，可将现场查勘数据与工程量进度、监理记录进行匹配，区分事故前后的标的状态，对应多源数据关联比对能力；三是规则化内容生成，可基于匹配后的信息生成初步的损失范围与费用校验清单，对应模板生成能力。系统可自动整合建设/施工方项目资料、监理记录、现场查勘等数据来源，减少人工重复检索与核对的工作量。

## 哪一部分交不了
部分环节无法由系统独立完成，需由从业人员判断或签字确认。一是原有隐性缺陷的定性判定，部分隐蔽的技术瑕疵需结合专业工程经验与现场实测结果综合判断，系统无法识别非结构化的技术细节；二是保险责任边界的合规判定，需结合核保规则与监管要求确认修复范围是否属于保险责任，系统无法承担责任判定的专业责任；三是最终结果的签字确认环节，需符合机构内部的合规流程要求，无法由系统替代。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回相似度阈值` | 0.75-0.85 | 常见取法，需按机构实际文档特征标定 |
| `抽取字段置信度阈值` | 0.80-0.90 | 常见取法，需按业务字段重要性调整 |
| `多源数据合并超时时间` | 30-60秒 | 常见取法，需按机构服务器负载调整 |
| `知识库同步触发规则` | 按项目节点/事件触发 | 依据数据更新频率规则，工程进度按节点更新、事故数据按事件触发 |

## 做不好会以什么形式暴露
-  检索结果中遗漏关键保险合同条款，通常由`召回相似度阈值`设置过低，无法匹配到关联度符合要求的关联文档。
-  抽取的原有缺陷字段为空，通常由`抽取字段置信度阈值`设置过高，导致符合业务要求的结构化信息未被成功提取。
-  多源数据比对环节超时中断，通常由`多源数据合并超时时间`设置过短，无法完成跨来源的信息整合校验。

## 还需要按机构实际情况确认的
-  工程险具体技术文档随项目类型差异极大，需结合机构服务的项目类型调整系统的检索与抽取配置。
-  行业协会来源可确认工程类保险真实存在，但不能据此证明所有公司使用完全相同底稿，需按机构内部文档规范校准系统的抽取规则。
