# 风险处置服务信托的依信托/重整文件计算回收款和各受益人分配：哪一部分能交给系统

## 这一步现在是怎么做的
这一步需先归集信托合同、债权、受益权清单、重整计划、债权确认、抵债资产清单、处置方案、分配表、受托报告等材料，先核对债权主体、金额、顺位与受益权的映射关系（其余同品类耗时环节暂不展开），再依据处置节点的回款数据，结合信托文件的分配规则核算回收款总额，随后拆分至各受益人。过程中需跟进债权确认、资产处置等事件触发的更新数据，手工校验数据一致性，调整分配计算逻辑，整体耗时占该环节的主要部分。

## 哪一部分能交给系统
可交由系统处理的部分包含三类。第一类是文档结构化抽取：从信托合同、重整计划、债权确认等文档中提取分配规则、债权明细、受益权份额等核心信息，对应文档抽取与结构化提取能力。第二类是数据比对校验：将抽取的债权数据与债权申报、企业资产负债数据匹配，校验主体、金额、顺位的一致性，对应实体比对能力。第三类是规则计算与方案生成：结合回款、债权确认等事件触发的资金数据，按照提取的分配规则自动核算各受益人应得金额，生成初步分配草案，对应规则引擎与批量生成能力。

## 哪一部分交不了
部分环节无法交由系统自动完成。当涉及破产重整、市场化纾困等特殊法律程序时，需结合实际司法进程判断分配规则的适用性，系统无法自主识别场景差异。当出现债权确认争议、资产处置异常等非常规情况时，需人工核实后调整分配逻辑。最终分配方案的合规确认与签字环节，需由具备履职权限的人员完成，无法由系统替代。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `文档分块大小` | 500-1000字符 | 常见取法，需按实际处理的文档长度标定 |
| `知识库召回TopK` | 3-5 | 常见取法，可覆盖核心分配规则与债权数据，需按文档复杂度调整 |
| `实体抽取模型` | 金融垂类抽取模型 | 适配信托、司法类文档的常见配置 |
| `数据同步触发规则` | 事件触发（回款/债权确认完成） | 匹配行业数据更新的非定期特性 |
| `结果校验匹配阈值` | 90%-98% | 常见的人工复核分界值，需按机构合规要求调整 |

## 做不好会以什么形式暴露
- 召回不到对应分配规则条款，通常因知识库召回TopK设置过低，或文档分块阈值过大导致关键规则被拆分遗漏。
- 抽取的债权金额、受益权份额字段为空，通常因实体抽取模型未适配金融垂类文档，或未针对信托合同、重整计划做专项配置。
- 计算结果与原件核对存在大量偏差，通常因数据同步触发规则未覆盖全部事件节点，或校验阈值设置不合理导致部分有效数据未纳入计算。

## 还需要按机构实际情况确认的
- 破产重整、市场化纾困等场景的法律程序差异，需结合机构实际服务的场景确认适配的分配规则。
- 业务不存在统一处理周期和处置方式，需按实际项目的司法进程与资产处置节奏调整系统配置。
