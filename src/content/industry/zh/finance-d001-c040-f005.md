# 受益所有人KYC 的多轮对话与提示词

## 这个品类的数据长什么样
受益所有人数据的来源包括工商行政管理部门公示信息、客户提交的股权架构说明文件、尽职调查工作底稿。更新节奏随客户股权结构变动、年度KYC复核触发。文档多为结构化表格附带补充说明，包含受益所有人姓名、实际持股比例、实际控制关系链、身份证明文件编号、最后更新日期等字段，字段格式统一为标准文本、百分比、YYYY-MM-DD日期格式。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
受益所有人数据包含多层控制关系与明确的格式要求，多轮对话需分层引导用户补充信息，避免一次性索要过多字段导致用户困惑。数据更新节奏不固定，提示词需加入定期复核的提醒，确保核验信息的时效性。字段格式要求严格，提示词需内置格式校验逻辑，对不符合要求的输入引导修正。同时需兼容外部数据源的调用，确保对话过程中能实时获取最新的工商核验数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 受益所有人数据包含多层股权关系文本与历史对话，需保留完整上下文避免关键信息截断 |
| `promptTemplate` | 按「先核验核心持股比例→追溯间接控制人→校验身份证明格式」的顺序生成多轮引导 | 适配受益所有人分层核验的业务逻辑，避免一次性输出过多信息导致用户混淆 |
| `maxTurns` | `5–7 轮` | 受益所有人核验需补充多层控制关系细节，过多轮次会增加用户负担，过少无法覆盖必要信息 |
| `similarityThreshold` | `0.75–0.85` | 需准确匹配受益所有人的身份证明与股权比例数据，阈值过低会引入无关核验结果，过高会遗漏有效匹配 |
| `fileParseTimeout` | `300 秒` | 受益所有人相关的工商档案文件通常体积较大，需预留足够解析时间 |
| `retryCount` | `2 次` | 处理格式校验失败的用户输入时，允许有限次重试修正，避免直接中断对话 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 对话返回`401 No auth credentials found`报错。原因：未配置受益所有人核验所需的第三方工商查询接口的认证密钥，或密钥过期，导致对话调用外部数据源时权限校验失败。
- 多轮对话中用户补充的持股比例无法被正确识别。原因：提示词未明确要求用户输入百分比格式的数值，且未加入格式校验引导，导致系统无法匹配字段要求。
- 对话轮次达到上限后直接终止，未提示用户补充完整信息。原因：未将`maxTurns`配置适配受益所有人的多层核验需求，或未配置轮次耗尽时的兜底引导话术。

## 怎么确认配好了
- 触发一次模拟的受益所有人核验对话，检查上下文窗口是否保留了所有历史对话与上传的文档内容。
- 输入不符合格式的持股比例数值，检查系统是否会触发格式修正的引导提示。
- 调用外部工商查询接口，检查是否能正常获取受益所有人数据且无权限报错。
- 测试对话轮次达到预设上限时，系统是否会给出兜底引导，或是直接终止对话。
