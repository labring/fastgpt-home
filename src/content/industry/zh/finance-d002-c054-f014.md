# 多应用路由一体化 AI 平台的表单与交互

## 这个品类的数据长什么样
多应用路由的数据来源于平台内已创建的AI应用配置、外部接入的应用密钥及调用规则。更新节奏为路由规则保存或同步时触发，无固定全量更新周期。文档结构为结构化键值对集合，包含路由唯一标识、关联应用列表、触发匹配规则、流量分配参数等字段。字段无强制单位，仅按配置规则赋值，其中触发匹配规则为字符串格式的匹配表达式，流量分配参数为正整数类型的比例标识。

## 这些特征在「表单与交互」这一环带来什么约束
这些特征在表单与交互环节带来明确约束：由于数据来源于平台内已创建的AI应用，关联应用选择项只能从平台现有应用列表中下拉选取，不支持手动输入未完成配置的应用标识。触发匹配规则为字符串格式的匹配表达式，表单需提供实时语法校验与提示，避免输入非法格式的规则内容。流量分配参数为正整数类型，表单需限制输入范围为正整数，拒绝负数、零或非数字字符。同时，因数据更新仅在规则保存时触发，表单提交后需自动触发关联应用配置的同步校验，确保关联应用未被删除或配置变更。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `关联应用列表` | 从平台现有AI应用列表选择2个及以上 | 多应用路由需实现流量分发，仅单个应用无法形成路由逻辑 |
| `触发匹配规则` | 编写基于用户输入字段的匹配表达式 | 可精准匹配对应业务场景的请求，触发指定应用处理 |
| `流量分配权重` | 1-100的正整数 | 覆盖不同业务的流量分配需求，符合参数类型限制 |
| `路由生效状态` | 开启或关闭 | 便于在测试与正式环境间切换路由规则 |
| `调用超时时间` | 30-60秒 | 适配多数AI应用的响应时长，避免请求过早中断 |
| `同步校验开关` | 开启 | 确保关联应用配置变更时，路由规则及时同步最新信息 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：配置自定义路由渠道后调用返回`undefined model`错误。原因：未正确填写关联应用的模型参数，或使用了平台未支持的模型标识。
- 现象：路由规则保存后，无请求匹配对应路由。原因：触发匹配规则的语法格式不符合平台要求，或匹配条件过于严格。
- 现象：调用路由时出现请求超时。原因：调用超时时间设置过短，未适配关联应用的实际响应时长。

## 怎么确认配好了
- 查看平台路由列表的状态标识，确认路由规则的生效状态为开启。
- 模拟符合触发匹配规则的请求，查看路由日志，确认请求被正确分配至关联应用。
- 检查关联应用的调用日志，确认路由转发的请求参数与配置一致。
- 调整流量分配权重，查看路由统计数据，确认流量分配比例符合预期设置。
