# 多应用路由一体化 AI 平台的部署与升级

## 这个品类的数据长什么样
面向金融保险理财场景的多应用路由，核心数据来源于各业务子应用的注册信息、运维配置的流量转发规则、应用健康状态上报内容。数据更新节奏随配置变更实时同步，健康状态数据按需触发上报。数据文档为结构化JSON格式，包含应用标识集合、流量分配规则、匹配条件字段、健康检查参数字段。其中`app_identifiers`为字符串数组，`traffic_allocation`为正整数序列，`match_condition`为正则表达式字符串，`health_check_interval`为正整数，单位为秒。

## 这些特征在「部署与升级」这一环带来什么约束
多应用路由的数据依赖子应用的注册标识与健康状态，部署阶段需提前完成各关联子应用的接入注册，否则无法生成有效转发规则。数据的JSON格式要求严格的语法校验，升级过程中若存在旧版配置的格式兼容问题，需提前导出配置备份并完成格式转换。实时同步的流量规则要求部署节点具备低延迟的配置同步能力，升级期间需避免中断配置同步链路。健康检查参数的配置依赖集群的网络访问策略，升级时需同步更新节点的端口放行与访问权限配置，确保健康上报链路正常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `ROUTE_SYNC_INTERVAL` | `10–30 秒` | 平衡流量同步的实时性与集群通信负载，过短会增加节点间通信开销，过长会导致流量分配滞后 |
| `HEALTH_CHECK_TIMEOUT` | `5–10 秒` | 适配多应用的常规响应时长，避免误判正常运行的子应用为异常状态 |
| `MAX_ROUTE_RULES` | `50 条` | 限制单实例的路由规则总量，防止配置过载引发性能波动 |
| `ROUTE_FAILOVER_SWITCH` | `开启` | 当子应用健康状态异常时自动切换流量至备用应用，保障业务连续性 |
| `CONFIG_BACKUP_PATH` | `/opt/fastgpt/backup/route` | 指定私有化部署下的配置备份路径，便于升级时快速恢复原有配置 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：升级后访问多应用关联的知识库文件详情，界面显示“Invalid dataset file key ”报错。原因：升级过程中未同步更新多应用路由关联的数据集配置密钥，导致密钥校验不通过。
- 现象：sandbox环境中部署多应用路由组件时，启动失败并提示node版本不兼容。原因：未将sandbox镜像内的node版本升级至20.20.0，组件依赖该版本的内置API。
- 现象：v4.11.0版本中配置多应用路由关联的大模型转发规则时，返回404状态码且无响应体。原因：该版本未内置对应模型的路由转发适配逻辑，导致请求无法正确转发至模型服务节点。

## 怎么确认配好了
- 运行内置的配置校验工具，验证多应用路由的所有配置项格式正确、关联的子应用标识有效。
- 发起一条匹配路由规则的测试请求，确认请求被正确转发至目标子应用并返回预期结果。
- 查看集群节点的日志，确认路由同步与健康检查的任务无异常报错。
- 核对配置备份文件的存储路径与内容，确认升级前的原有配置已完整导出。
