# 用量统计一体化 AI 平台的工具调用与插件

## 这个品类的数据长什么样
该品类的数据来源于一体化AI平台的调用链路日志、资源消耗统计模块，以及各应用的插件执行记录。数据更新节奏为分钟级，支持按小时、天维度聚合导出。文档结构包含基础维度字段：应用标识、统计周期、工具调用总次数、插件执行成功/失败次数、单插件平均执行时长，字段单位分别为字符串、时间区间、次、次、秒，部分字段支持自定义扩展维度。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据的分钟级更新节奏要求工具调用与插件执行时，需实时拉取最新的统计维度配置，避免使用过期的聚合规则。多维度字段的结构要求插件入参需明确指定应用标识、统计周期等基础参数，否则无法生成对应维度的统计数据。字段单位的严格对应要求插件输出的统计值需匹配预设单位，例如将执行时长统一转换为秒后写入统计字段，避免单位不匹配导致的统计偏差。同时，失败次数的统计字段要求插件需捕获执行异常状态，并将失败标识同步至统计链路，确保数据完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `usage_collection_interval` | `60 秒` | 匹配该品类分钟级的数据更新节奏，平衡统计实时性与系统资源占用 |
| `statistic_dimension_schema` | `["app_id", "stat_period", "tool_total", "plugin_success", "plugin_fail"]` | 对应该品类的标准文档结构字段，确保统计数据的维度完整性 |
| `plugin_unit_conversion` | `{"duration": "second", "count": "integer"}` | 统一插件输出值与统计字段的单位与数据类型，避免统计偏差 |
| `failure_trigger_tag` | `["plugin_exception", "api_call_failed"]` | 覆盖该品类统计所需的异常状态类型，确保失败数据被完整采集 |
| `statistic_query_timeout` | `30 秒` | 限制统计数据拉取的超时时间，避免工具调用链路阻塞 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工作流发起用户提问后，工具调用环节直接返回`400 Bad Request`错误。原因是未在工具调用配置中绑定该品类的统计维度参数，导致请求缺失必要的`app_id`与`stat_period`字段。
- 现象为插件中配置的全局变量初始值未生效，变量更新后统计数据未同步更新。原因是未开启统计数据的自动同步开关，导致变量修改未触发统计链路的重新采集。
- 现象为代码执行组件无法调用第三方API，HTTP请求模块未返回Set-Cookie字段。原因是未在HTTP请求配置中开启Cookie持久化参数，导致响应头中的Cookie信息未被保留。

## 怎么确认配好了
- 触发一次工具调用与插件执行，查看平台日志中是否生成对应维度的统计记录，核对字段是否与预设的`statistic_dimension_schema`一致。
- 调整插件的单位转换配置，验证统计数据的数值是否匹配转换后的单位，确认`plugin_unit_conversion`配置生效。
- 模拟插件执行异常，查看统计链路是否捕获异常状态并更新失败次数字段，确认`failure_trigger_tag`配置覆盖了异常类型。
- 检查统计数据拉取接口的返回时长，确认未超过`statistic_query_timeout`的配置阈值，确保工具调用链路无阻塞。
