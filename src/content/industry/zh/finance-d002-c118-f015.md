# 统一入口一体化 AI 平台的部署与升级

## 这个品类的数据长什么样
统一入口的数据来源于金融保险理财场景下的各AI应用调用日志、用户交互终端的操作记录，以及跨应用的权限绑定元数据。数据更新节奏分为两类：调用时实时生成单次调用的链路数据，每日定时同步权限配置与应用元数据快照。数据文档为结构化键值对格式，包含`app_id`、`user_id`、`invoke_duration`、`response_code`等字段，单位为毫秒、次。

## 这些特征在「部署与升级」这一环带来什么约束
统一入口对接多业务系统的数据源，部署时需配置跨系统的网络代理与数据加密规则，确保敏感权限数据传输符合合规要求。数据包含实时调用链路与定时同步的元数据，部署需支持热加载配置，避免重启中断核心服务。由于对接的AI应用存在版本差异，升级时需开启版本兼容校验，确保各应用可正常接入统一入口。金融场景的高并发调用需求，要求部署时配置负载均衡与超时参数，保障服务稳定性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPSTREAM_APP_WHITELIST` | 所有已对接的应用ID列表 | 限制未授权应用接入统一入口，符合金融场景的权限管控要求 |
| `INVOKE_TIMEOUT` | `30000 毫秒` | 匹配金融场景下各AI应用的平均响应时长，避免超时导致调用失败 |
| `CONFIG_SYNC_INTERVAL` | `3600 秒` | 平衡权限配置同步的实时性与系统资源占用，适配每日定时同步的元数据更新节奏 |
| `LOG_ENCRYPTION_KEY` | 按合规要求生成的32位密钥 | 加密调用日志中的敏感身份与权限字段，满足金融数据安全规范 |
| `VERSION_COMPATIBILITY_CHECK` | `开启` | 校验接入应用与统一入口的版本兼容性，避免升级后出现调用异常 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：在Windows Server 2022环境部署统一入口时，启动失败并提示`端口占用冲突`。原因：未指定`SERVER_PORT`参数的自定义取值，使用默认端口与其他系统服务冲突。
- 现象：基于V4.6.7版本部署的统一入口，无法启用联网查询功能，调用时返回`400 Bad Request`。原因：未在部署配置中开启`ENABLE_ONLINE_SEARCH`参数，且未升级依赖的联网模块版本。
- 现象：统一入口调用rerank模块时，返回结果为空，日志显示版本不匹配。原因：未对齐统一入口与rerank模块的版本号，导致接口协议不兼容。

## 怎么确认配好了
- 调用统一入口的健康检查接口，确认返回状态码符合预期，且列出的所有对接应用状态正常。
- 提交包含合法身份标识的测试调用，核对返回的可用应用列表与配置的权限规则匹配。
- 查看部署日志，确认`CONFIG_SYNC_INTERVAL`参数对应的定时任务正常执行，无同步失败报错。
- 完成版本升级后，逐一验证各对接应用的调用链路，确认无版本兼容导致的错误。
