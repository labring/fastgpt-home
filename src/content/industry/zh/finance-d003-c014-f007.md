# 保障责任保险理赔初审的工作流编排

## 这个品类的数据长什么样
保障责任数据主要来自保险公司核心业务系统的结构化存储，以及理赔申请人上传的保单PDF、投保确认书等纸质材料扫描件的解析文本。数据随理赔案件创建时同步拉取，案件存续期间仅当保单批改时更新。结构化数据包含保障责任ID、对应险种名称、赔付限额、免赔额、责任范围说明；非结构化数据为对应保单条款的解析文本段落。赔付限额、免赔额均以人民币元为单位，责任范围说明为纯文本段落。

## 这些特征在「工作流编排」这一环带来什么约束
结构化保障责任数据的精准字段要求，要求工作流前置配置字段校验节点，对赔付限额、免赔额等数值类字段做合法性校验，避免非合规数值进入后续计算环节。非结构化的保单条款解析文本存在格式差异，要求工作流配置关键词提取节点，精准定位责任范围相关段落。数据随理赔案件实时更新的特性，要求工作流每次执行时调用最新的保单接口拉取数据，不启用本地缓存。字段以人民币元为单位的要求，要求工作流中金额计算节点统一使用元作为计价单位，避免跨单位转换导致的误差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 保障责任相关的保单PDF通常页数有限，常规解析耗时不超过5分钟 |
| `RECALL_TOP_K` | `前3条` | 保障责任相关的保单条款核心内容集中在前3段解析结果，过多召回会引入冗余信息 |
| `UPLOAD_FILE_MAX_SIZE` | `20 MB` | 单份常规保单PDF的文件大小通常不超过20MB，超出该范围的文件多为非标准材料 |
| `WORKFLOW_CONTEXT_MODE` | `仅当前节点上下文` | 保障责任理赔初审的工作流节点无需跨节点共享上下文，避免冗余历史信息干扰 |
| `API_REQUEST_TIMEOUT` | `60 秒` | 保单接口与文件解析接口的常规响应时长不超过1分钟，超时会导致工作流执行中断 |
| `MAX_RETRIES` | `2次` | 文件上传或接口调用偶发失败时，重试即可恢复，过多重试会延长工作流执行时长 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流执行时出现`Failed to create post presigned url`报错，无法完成理赔相关文件上传。原因：未将`UPLOAD_FILE_MAX_SIZE`配置为适配保单大小的取值，或存储桶权限配置错误导致预签名URL生成失败。
- 现象：工作流中调用知识库节点时，检索结果包含无关保单的保障责任数据。原因：未将当前理赔案件的保单ID作为前置参数传入知识库检索节点，导致检索范围未限定到对应保障责任数据。
- 现象：工作流中多个节点输出包含无关的历史理赔案件信息。原因：未将`WORKFLOW_CONTEXT_MODE`配置为仅当前节点上下文，启用了全局上下文共享，导致上下文冗余。

## 怎么确认配好了
- 上传一份常规大小的保单PDF，验证文件上传节点无报错，解析结果包含保障责任相关字段。
- 触发工作流执行，检查知识库召回结果仅返回当前理赔案件对应的保障责任数据。
- 查看工作流日志，确认API请求超时时间与重试次数符合预设配置，无异常报错。
- 调整`WORKFLOW_CONTEXT_MODE`配置，验证多节点执行时无跨节点上下文干扰。
