# 保障责任保险理赔初审的工具调用与插件

## 这个品类的数据长什么样
保障责任的数据主要来源于保险核心业务系统的产品报备条款、投保时录入的保单约定，以及理赔阶段上传的诊断证明、事故认定书等附件解析内容。数据更新节奏为触发式，仅在理赔申请发起时调取对应保单的责任配置与现场提交的佐证材料。文档结构包含责任唯一编码、责任名称、赔付比例规则、免赔额、除外责任范围、适用险种字段，字段单位涵盖百分比、货币元、标准日期格式等。

## 这些特征在「工具调用与插件」这一环带来什么约束
保障责任的触发式调取要求工具调用需绑定唯一保单ID作为入参，无法使用通用缓存数据，需在理赔申请发起后实时拉取对应责任配置。责任字段包含动态规则，需结合保单场景计算具体数值，无法直接返回静态结果。附件解析的病症与责任匹配环节，需调用术语映射插件完成关联，且需校验除外责任范围，增加了工具调用的链路长度。同时数据来源于核心业务系统，工具调用需携带合规鉴权参数，避免越权访问。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `MCP_CALL_TIMEOUT` | `600 秒` | 保障责任初审需拉取核心系统数据、解析理赔附件，链路环节较多，默认超时时间无法覆盖全流程，延长至10分钟适配实际调用需求 |
| `WORKFLOW_TRIGGER_POLICY` | `保单提交后触发` | 保障责任数据仅在理赔申请提交后生成，需绑定保单ID作为入参，按申请触发可确保数据时效性与准确性 |
| `TOOL_INPUT_SCHEMA` | `包含保单ID、理赔申请ID、附件哈希值` | 保障责任数据依赖保单唯一标识，需携带附件哈希值确保解析的是当前提交的佐证材料，避免数据混淆 |
| `PARSE_FILE_MAX_SIZE` | `10 MB` | 理赔附件多为诊断书、事故认定书等文档，单文件大小通常处于合理区间内，设置10 MB可覆盖绝大多数场景 |
| `MCP_PLUGIN_WHITELIST` | `医学术语映射、除外责任校验、核心系统接口` | 保障责任初审仅需三类核心工具，限制白名单可提升调用安全性与链路效率 |
| `WORKFLOW_EXECUTION_LOG_LEVEL` | | | 用于排查工具调用环节的异常日志 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工具调用返回`504 Gateway Timeout`错误，或工作流执行状态显示超时。原因：未调整`MCP_CALL_TIMEOUT`参数，默认超时时间过短，无法覆盖核心系统数据拉取与附件解析的全链路耗时。
- 现象：工作流中添加MCP工具节点后无法触发调用，或提示未绑定有效插件。原因：未将目标MCP插件添加至`MCP_PLUGIN_WHITELIST`配置项，或未在工作流输入中携带保单ID等必填参数。
- 现象：调用外部接口触发工作流时返回工作流ID不存在错误。原因：误将应用ID当作`WORKFLOW_ID`使用，未从工作流管理界面复制正确的唯一标识。

## 怎么确认配好了
- 在工作流测试界面上传模拟理赔附件，输入有效保单ID触发执行，核对返回的责任配置字段是否与保单预设规则匹配。
- 进入工作流日志面板，查看`MCP_CALL_TIMEOUT`参数是否生效，工具调用耗时是否符合预期区间。
- 调用外部接口触发工作流，传入正确的`WORKFLOW_ID`与保单参数，确认接口返回合法的执行ID，无参数报错。
- 查看鉴权日志，确认核心系统接口调用已携带合规鉴权参数，无越权拦截记录。
