# 保障责任保险理赔初审的引用来源与溯源

## 这个品类的数据长什么样
保障责任的数据主要来源于保险产品正式条款文本、投保时的告知确认文档、监管发布的险种规范文件。数据更新节奏随产品条款修订、监管政策调整触发，无固定周期，单次修订可能覆盖单条或多条责任项。单条数据的文档结构包含结构化标识字段与自然语言描述两部分，结构化字段包括责任名称、赔付比例、免赔限额、适用险种范围，自然语言描述为责任的具体触发条件与赔付规则，字段单位涵盖百分比、人民币元、自然天数等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
保障责任的结构化与非结构化混合特征，要求溯源信息需同时覆盖结构化字段的来源编号与自然语言描述的具体段落位置。数据更新无固定周期，需绑定对应版本的条款文件，避免引用旧版失效内容。理赔初审场景下，每份保单对应专属的保障责任组合，溯源信息需关联保单编号与对应责任版本，确保审核依据与当前保单的责任配置完全匹配。此外，单条责任文本长度差异较大，长文本需精准定位引用段落，避免溯源信息覆盖无关内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | `前8条` | 单份保单的保障责任项通常不超过10项，8条可覆盖全部主要责任内容，避免冗余召回 |
| `相似度阈值` | `0.75–0.85` | 保障责任文本表述标准化程度高，阈值过低会混入同险种其他责任的无关内容，过高会遗漏相似但表述有差异的责任项 |
| `contextWindow` | `1200–1800 字符` | 单条完整保障责任的条款描述通常在1000-1500字符区间，该窗口可完整承载责任内容与溯源标识 |
| `引用来源展示开关` | `开启` | 理赔初审需合规留存审核依据，开启后可返回条款编号、生效日期等溯源信息 |
| `知识库版本绑定` | `绑定当前保单的条款版本` | 保障责任随条款更新迭代，绑定版本可避免引用已失效的旧版责任内容 |
| `溯源字段映射` | `映射条款号、生效日期` | 理赔审核需明确责任对应的具体条款版本与生效时间，确保溯源信息可追溯至原始文件 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工作流调用知识库搜索后，返回结果附带知识库搜索的input和response原始日志。原因是未关闭`引用原始调用日志`配置项，导致非必要的调用信息被展示。
- 现象为动态指定知识库时，引用变量下拉框无可选值。原因是未在全局变量中配置类型为知识库ID的变量，或变量未绑定对应知识库的访问权限。
- 现象为召回的保障责任条款与当前保单的责任配置不匹配。原因是未绑定知识库版本，或相似度阈值设置过高，导致仅召回完全匹配的少量内容。

## 怎么确认配好了
- 发起一次模拟理赔初审请求，查看返回结果的引用来源字段，确认包含条款号、生效日期等明确的溯源信息。
- 进入知识库搜索节点的变量配置界面，确认动态指定的知识库变量可在下拉选择框中正常显示。
- 关闭`引用原始调用日志`开关后，再次发起测试请求，确认返回结果仅展示答案与合规溯源信息，无额外的调用日志内容。
- 模拟条款版本更新操作，验证召回结果自动关联最新版本的保障责任条款，无旧版内容混入。
