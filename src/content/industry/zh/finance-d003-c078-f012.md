# 既往症判定保险理赔初审的模型接入与配置

## 这个品类的数据长什么样
既往症判定的数据主要来源于理赔申请人提交的既往病历、医保结算明细、投保告知文件，随单案理赔申请同步更新。文档结构包含就诊时间、诊断结论、标准化疾病编码、用药记录、就诊医疗机构信息等字段，部分文本包含多段就诊详情，字段单位多为标准日期格式、通用货币单位或医疗行业统一疾病编码规则。

## 这些特征在「模型接入与配置」这一环带来什么约束
该品类数据来源分散且格式多样，包含非结构化病历文本与结构化结算数据，要求模型接入环节支持多格式文件解析与混合数据对齐。长文本病史可能超出单轮模型上下文窗口，需配置分段召回或长文本处理逻辑。标准化疾病编码的字段校验需求，要求模型接入时同步配置字段提取的规则匹配参数，确保关键诊断信息被准确识别。同时随案实时提交的数据，要求模型调用链路支持低延迟响应，避免拉长理赔初审流程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–16000 字符` | 既往症判定需覆盖完整的多段就诊病历文本，避免关键诊断信息被截断 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 长病历、多页PDF类文件解析耗时较长，避免提前终止解析流程 |
| `召回条数` | `前3–5 条` | 优先匹配与当前理赔申请关联度最高的既往病史记录，平衡信息完整性与模型负载 |
| `相似度阈值` | `0.75–0.85` | 过滤非相关的医疗记录，保留疑似既往症的匹配结果，减少模型无效推理 |
| `TOOL_CALL_MAX_STEPS` | `2 次` | 既往症判定仅需调用病历解析、疾病编码匹配两类工具，无需多轮迭代 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 适配理赔申请中常见的病历文件大小，避免无效的超大文件上传请求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为本地部署4.8.22版本的FastGPT无法调用第三方模型，返回`Invalid API Key`报错，原因是未正确配置第三方模型的API密钥与接入域名，未遵循平台要求的请求头格式。
- 现象为长病历解析后丢失关键诊断编码信息，原因是`相似度阈值`设置过高，过滤了部分低匹配度但关键的既往症记录。
- 现象为理赔初审流程超时，原因是`PARSE_FILE_TIMEOUT_SECONDS`设置过短，长病历未完成解析就终止了流程。

## 怎么确认配好了
- 上传单份标准既往病历文件，核对解析后的文本完整性，确认解析结果与源文件内容一致。
- 发起模拟理赔初审请求，查看模型调用日志，确认工具调用次数与返回格式符合配置要求。
- 使用内置的API测试工具，发起第三方模型的单次调用，验证接口连通性与密钥配置有效。
- 调整核心配置参数的取值区间，对比不同配置下的模型输出，确认匹配业务判定逻辑。
