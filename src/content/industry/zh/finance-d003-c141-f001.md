# 身份与时效保险理赔初审的HTTP 接口与外部系统

## 这个品类的数据长什么样
身份与时效类保险理赔初审数据，主要来源于公安身份核验接口、理赔申请人提交的初审材料、保单核心系统的出险记录与时效台账。数据更新节奏分为两类：身份信息在核验请求发起时实时同步更新，时效类数据随理赔流程节点触发更新，如提交申请、材料审核、赔付打款等环节。文档结构为标准化JSON格式，核心字段包含`identity_card`（18位字符串）、`real_name`（中文姓名）、`claim_apply_time`（ISO8601格式时间戳）、`claim_deadline`（时效截止时间戳），字段单位统一为时间戳格式或纯文本字符串，无嵌套复杂层级。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
身份信息的实时核验需求，要求HTTP接口必须支持低延迟请求，否则会阻塞理赔初审流程。时效数据随流程节点动态更新，无法通过固定缓存长期复用，需配置实时调用或异步回调机制。字段格式的严格要求，要求接口请求前需完成格式校验，避免无效调用占用第三方接口配额。同时，身份核验接口通常带有调用频率限制，需根据第三方接口规则调整请求频次，防止触发限流拦截。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `REQUEST_TIMEOUT` | `30 秒` | 身份核验接口响应通常较快，超时过长会阻塞理赔初审流程 |
| `API_CALL_RATE_LIMIT` | `100 次/分钟` | 公安身份核验接口普遍设置调用频率限制，该取值可适配多数第三方接口配额 |
| `CACHE_TTL` | `5 分钟` | 身份信息短时间内不会发生变更，缓存可减少重复调用第三方接口的成本 |
| `VALIDATE_SCHEMA` | `开启严格校验` | 身份与时效数据字段格式要求严格，严格校验可过滤无效请求 |
| `CALLBACK_URL` | `填写理赔系统的回调地址` | 时效数据随理赔流程动态更新，异步回调可保证数据与理赔系统实时同步，该配置在V4.9.7及以上版本支持 |
| `MAX_RETRY_TIMES` | `2 次` | 接口偶发网络异常时，有限重试可提升调用成功率，重试过多会增加第三方接口压力 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：接口返回`429 Too Many Requests`状态码，原因：未配置合理的`API_CALL_RATE_LIMIT`，并发请求超出第三方接口的调用阈值。
- 现象：身份核验字段为空或格式不符合要求，原因：未开启`VALIDATE_SCHEMA`严格校验，未对提交的身份数据做前置格式过滤。
- 现象：理赔流程出现超时阻塞，原因：配置`REQUEST_TIMEOUT`取值过大，未匹配身份核验接口的实际响应时长。

## 怎么确认配好了
- 调用测试身份核验接口，检查返回状态码为`200 OK`且核心字段格式符合预设要求。
- 模拟并发100次请求，确认未触发`429 Too Many Requests`限流报错。
- 查看接口调用日志，确认重复的身份核验请求未重复调用第三方接口，`CACHE_TTL`配置生效。
- 配置`CALLBACK_URL`后，触发一次理赔时效更新，确认回调接口收到包含`claim_apply_time`、`claim_deadline`的有效数据。
