# 身份与时效保险理赔初审的多轮对话与提示词

## 这个品类的数据长什么样
本品类数据主要来自公安身份核验接口、保险业务系统内部流程节点日志、第三方出行/物流时效溯源接口。数据更新节奏分为实时与定时两类：身份核验数据在用户提交理赔材料后即时同步，流程时效数据每小时同步一次。文档以结构化JSON格式存储，包含身份核验字段（姓名、身份证号、核验状态、核验时间）与时效字段（报案时间、出险时间、材料提交时间、各审核节点截止时间），字段单位统一为ISO 8601时间格式或18位纯字符串身份标识。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
本品类的结构化字段多、数据源分实时与定时两类，对多轮对话与提示词带来三项核心约束：需严格对齐身份与时效的专属字段名，避免混淆姓名、身份证号与报案时间、审核截止时间等字段；实时身份核验数据需在对话发起时即时调用接口，提示词需明确禁止缓存旧核验结果；时效字段需严格校验ISO 8601格式，多轮对话需引导用户输入规范时间，或自动解析非标准格式输入。同时需限制历史上下文长度，避免重复拉取过时的流程时效数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 800–1200 字符 | 本品类需传递的身份与时效字段较多，过长上下文会导致模型混淆字段归属，过短则丢失历史对话的核验请求记录。 |
| `apiRequestTimeout` | 15 秒 | 身份核验接口依赖实时响应，15秒超时可平衡接口调用成功率与用户等待时长。 |
| `structuredOutput` | 开启 | 身份与时效数据为结构化字段，开启后可强制模型返回符合预设字段的结果，避免遗漏关键信息。 |
| `fieldWhitelist` | 仅包含`姓名`、`身份证号`、`报案时间`、`审核截止时间` | 限制模型可调用的字段范围，防止调用无关数据源导致数据混乱。 |
| `contextRefreshInterval` | 1 小时 | 流程时效数据每小时同步，设置该间隔可确保对话中使用最新的流程节点时间。 |
| `promptTemplate` | 按「先核验身份，再校验时效，最后生成初审结果」的顺序编写 | 符合保险理赔初审的业务逻辑，引导模型按固定流程处理对话请求。 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工作流中配置的身份核验表单输入无法在对话界面显示，交互内容为空。原因是未在`promptTemplate`中添加表单字段的唤起指令，或未开启对话模块的表单渲染开关。
- 现象为AI对话返回`504 Gateway Timeout`错误。原因是未设置合理的`apiRequestTimeout`参数，身份核验接口调用超时未被正确处理。
- 现象为对话中模型无法正确区分用户输入与系统提示的时效校验规则。原因是未正确配置对话的`systemRole`参数，导致角色权限与逻辑边界模糊。

## 怎么确认配好了
- 触发一次身份核验请求，核对对话界面是否显示预设的表单输入字段。
- 查看对话模块的运行日志，确认每次身份核验请求都调用了配置的数据源接口。
- 提交符合与不符合ISO格式的时间输入，核对模型是否能正确识别并处理时效字段。
- 检查对话的`systemRole`配置，确认其中明确标注了身份核验与时效校验的业务逻辑顺序。
