# 身份与时效保险理赔初审的工具调用与插件

## 这个品类的数据长什么样
数据来源为保险理赔初审环节的身份核验材料（如居民身份证、户籍证明）与时效关联字段，更新节奏为单笔理赔单生成时同步录入，时效字段随初审流程节点推进实时更新。文档结构包含结构化字段与附件文件，结构化字段包括身份类型、身份号码、出险时间、材料提交时限等，附件为单页或少量页数的扫描件，时间字段采用ISO 8601格式，身份号码字段为18位或15位标准居民身份证格式。

## 这些特征在「工具调用与插件」这一环带来什么约束
身份与时效类数据包含结构化字段与附件文件，要求工具调用同时支持结构化数据库查询与文件解析插件联动。时效字段随流程实时更新，要求工具调用每次触发时拉取最新数据，不可依赖本地缓存。单笔理赔单的身份材料附件多为短时长解析任务，要求文件解析插件适配较低的超时阈值。同时身份字段的格式校验要求工具调用前置完成格式检查，减少无效请求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 身份与时效类材料附件多为单页证件文档，解析耗时较短，300秒可覆盖绝大多数场景 |
| `FUNCTION_CALL_MAX_RETRIES` | `2 次` | 结构化查询与身份校验请求不易出现重复失败，2次重试可平衡成功率与耗时 |
| `UPLOAD_FILE_MAX_SIZE` | `10 MB` | 身份材料多为证件扫描件，单文件大小通常不超过10 MB |
| `maxContext` | `800–1200 字符` | 需保留的时效与身份字段上下文需适配初审人员的阅读习惯，该区间可覆盖核心信息 |
| `RECALL_TOP_K` | `前 3 条` | 单笔理赔单的关联数据量有限，召回3条即可覆盖全部关联时效与身份信息 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为调用文件上传接口后返回成功，但后续调用文件解析工具时返回文件不存在。原因是未等待`file_parse_done`事件触发，未确认文件解析与索引完成即触发后续流程。
- 现象为大模型回答中未引用数据库查询的原文片段，仅返回结构化字段的摘要。原因是未将工具返回的完整结构化数据挂载到对话上下文，或未开启上下文保留配置。
- 现象为工具调用返回`413 Request Entity Too Large`状态码。原因是上传的身份材料文件大小超过了`UPLOAD_FILE_MAX_SIZE`的配置阈值。

## 怎么确认配好了
- 上传单份身份材料文件，等待解析完成后，验证工具调用能否正常读取并返回解析后的内容。
- 发起结构化数据库查询请求，验证返回结果包含预设的身份与时效相关字段。
- 调整工具调用的上下文参数，验证大模型在回答时可关联工具返回的完整原文片段。
- 检查工作流的超时配置，确保单次工具调用的时长符合当前流程的节点要求。
