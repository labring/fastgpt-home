# 内部制度合规的HTTP 接口与外部系统

## 这个品类的数据长什么样
内部制度合规场景的数据主要来自企业内部合规管理系统、纸质制度扫描件、监管机构公开的合规指引文档。数据更新节奏随监管政策调整、内部管理修订不定期触发，无固定周期。文档结构多为层级化章节，包含制度编号、生效日期、适用范围、条款细则、违规对应处罚条款等字段。单份文档长度跨度较大，条款以条、款、项为细分单位，部分关联监管要求的制度会附带对应法规文号。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
层级化的制度文档结构要求接口支持按条款层级召回，确保合规问答时可以精准定位对应条款，避免仅返回全文内容导致的定位偏差。不定期更新的数据要求接口支持实时拉取或灵活配置同步周期，避免依赖固定离线同步导致内容滞后。结构化字段（如生效日期、制度编号）要求接口开放字段级筛选能力，提升召回精准度。单份文档长度跨度较大，接口需要配置合理的解析超时与内容截断阈值，防止请求超时或资源占用异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300-600 秒` | 内部制度文档通常包含较多层级条款，该范围可覆盖多数单份制度的解析需求 |
| `RECALL_CHUNK_SIZE` | `800-1200 字符` | 内部制度条款多为短段落组合，该长度可完整保留单条款的语义完整性 |
| `FIELD_FILTER_ENABLE` | `开启` | 内部制度包含制度编号、生效日期等结构化字段，开启后可通过字段精准筛选合规相关文档 |
| `SYNC_FREQUENCY` | `按需触发` | 内部制度更新无固定周期，按需同步可避免无效请求与内容滞后 |
| `MAX_DOCUMENT_SIZE_PER_REQUEST` | `50 MB` | 单份内部制度文档通常不会超过该大小，可限制异常大文件占用接口资源 |
| `RECALL_SCORE_THRESHOLD` | `0.75-0.85` | 合规问答需要较高的匹配精准度，该区间可过滤低相关的召回结果 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：召回结果未包含重排后的精准条目，或重排接口调用失败。原因：未配置重排模型的API密钥与调用参数，或未启用重排功能，导致召回结果未经过二次筛选。
- 现象：调用对话接口后客户端断开SSE连接，数据库未保存聊天记录。原因：未启用会话持久化配置，或接口超时设置过短，导致请求中断后未完成数据落库。
- 现象：配置模型API密钥后调用接口返回401错误。原因：未将密钥配置到对应模型的专属配置项中，错误使用通用接口配置，或密钥格式不符合平台要求。

## 怎么确认配好了
- 上传一份内部制度文档，检查解析后的文本是否按章节、条款拆分，验证文本拆分逻辑是否符合配置要求。
- 手动触发一次制度同步，查看同步日志确认同步流程是否按配置的触发规则执行，验证内容更新是否及时。
- 调用接口传入结构化字段筛选条件，检查返回结果是否仅包含符合条件的制度文档，验证字段筛选功能是否生效。
- 模拟客户端断开SSE连接的场景，查看数据库中是否生成对应会话记录，验证会话持久化配置是否生效。
