# 操作规程合规的工具调用与插件

## 这个品类的数据长什么样
操作规程数据主要来自企业内部合规部、运营部发布的正式制度文件，更新节奏随监管政策调整或内部流程优化不定期触发。文档按章节结构组织，包含文号、生效日期、适用岗位、操作步骤、违规判定标准、责任条款等字段，单份文档篇幅跨度较大，部分跨岗位的关联规程会附带交叉引用标识，无统一固定的单位格式，部分字段会附带岗位编号、业务场景代码等自定义标识。

## 这些特征在「工具调用与插件」这一环带来什么约束
由于规程文档结构固定且包含生效日期、适用岗位等字段，工具调用时需基于这些字段做精准过滤，避免召回非生效或不适用的内容。文档篇幅跨度大且可能存在交叉引用，工具调用的召回范围需支持多章节关联检索，同时需适配长文本上下文。更新节奏不定期的特点，要求工具调用关联的知识库需支持灵活的同步周期配置，适配不同的更新频率需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | `前8-12条` | 操作规程文档章节较多，过多召回会超出上下文窗口，过少会遗漏关联合规条款 |
| `similarityThreshold` | `0.75-0.85` | 合规内容需较高匹配精度，避免误召回无关制度条款 |
| `syncCron` | `0 0 2 * * *` | 每日凌晨2点执行同步，适配不定期的合规文档更新需求 |
| `contextWindowSize` | `8000-12000 字符` | 单份操作规程文档可能较长，需容纳多章节的召回内容 |
| `toolCallTimeout` | `60 秒` | 合规文档检索需跨多章节关联，预留足够的响应时间 |
| `filterByField` | `["生效日期", "适用岗位"]` | 基于规程的生效时间和适用范围过滤结果，确保返回内容合规有效 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用外部工作流API时返回无上下文结果，原因是未在API请求中携带`chatId`或`sessionId`参数，导致工作流无法关联会话上下文。
- 调用MySQL工具时返回`400 status code (no body)`错误，原因是未正确配置数据库连接的`connectionString`参数，或请求体中未携带合法的SQL查询字段。
- 调用工具时`model`参数配置错误，原因是混淆了工作流分类节点的模型与问答节点的模型，未明确`model`参数对应执行分类还是生成任务。

## 怎么确认配好了
- 发起单轮API测试请求，传入包含特定合规场景的问题，核对返回的工具调用结果是否匹配对应操作规程的生效条款。
- 进入知识库管理界面，查看同步任务的执行记录，确认配置的同步周期是否按预期触发。
- 构造包含无效数据库连接参数的调用请求，验证是否返回对应错误提示，确认工具调用的异常处理配置生效。
- 传入包含多个适用岗位的问题，核对召回结果是否自动过滤了非适用岗位的操作规程条款。
