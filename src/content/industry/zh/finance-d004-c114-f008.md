# 监管办法合规的工具调用与插件

## 这个品类的数据长什么样
监管办法类数据主要来自官方监管机构公开公告、行业自律组织正式规范文件。更新节奏随新规发布、修订不定期调整。文档多为章节式结构，包含发文单位、文件文号、生效日期、条款编号等字段，条款按“条、款、项”层级划分，生效日期以标准日期格式标注，条款内容明确合规边界与执行要求，无自定义单位或复杂计量字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
官方数据源的权威性要求工具调用时需限定仅接入经校验的官方归档数据源，避免非合规来源的内容被调用。不定期更新的特性要求配置自动同步任务，定期拉取最新版本文件。长章节结构与多层级条款设计，要求插件处理时需适配分段召回的长度限制，同时在字段提取环节需精准匹配文号、生效日期、条款编号等专属字段，避免泛化提取导致合规内容错位。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| :---- | :---- | :---- |
| `recall_top_k` | 前 8–12 条 | 监管办法条款层级多、内容密集，需召回足够数量的相关条目覆盖完整合规场景 |
| `chunk_max_length` | 800–1200 字符 | 适配监管办法单条款的常规长度，避免拆分破坏合规逻辑的完整性 |
| `plugin_tool_timeout` | 600 秒 | 监管办法文档篇幅较长，工具调用需足够时间完成解析与字段提取 |
| `file_sync_cron` | 0 0 2 * * * | 每日凌晨同步最新版本的监管办法文件，适配其不定期更新的特性 |
| `plugin_field_filter` | ["发文单位", "文号", "生效日期", "条款编号"] | 精准提取监管办法的核心标识字段，避免无关内容干扰工具调用结果 |
| `similarity_threshold` | 0.75–0.85 | 过滤低相关性的非合规条款，确保工具调用返回的内容符合监管场景需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：API调用返回的合规建议与在线聊天结果差异显著，在线聊天正确率更高。原因：API调用未配置`recall_top_k`与`similarity_threshold`的匹配参数，默认召回条数与阈值设置与在线聊天不一致，导致内容覆盖不全。
- 现象：调用基础图表插件生成监管数据可视化时，返回报错提示“字段格式不匹配”。原因：未配置`plugin_field_filter`提取监管办法的专属字段，插件尝试使用非合规字段生成图表，触发格式校验失败。
- 现象：工具调用超时，返回状态码`504 Gateway Timeout`。原因：未调整`plugin_tool_timeout`的取值，默认超时时间不足以解析长篇幅的监管办法文档，导致调用中断。

## 怎么确认配好了
- 执行一次工具调用测试，核对返回内容中是否包含预设的`plugin_field_filter`字段，确认字段提取逻辑生效。
- 查看知识库同步日志，确认`file_sync_cron`配置的定时任务按计划执行，无失败记录。
- 调整`similarity_threshold`的取值，对比不同阈值下的召回结果，确认符合监管场景的相关性要求。
- 模拟API调用与在线聊天的相同输入，核对两者的召回条数与相似度阈值设置一致，确保结果对齐。
