# 交易规则客户服务的HTTP 接口与外部系统

## 这个品类的数据长什么样
交易规则类数据主要来源于持牌金融机构的核心交易系统、合规管理文档库与业务规则配置中心。数据更新无固定周期，仅在监管政策调整、业务流程优化时触发更新。单条规则文档通常包含适用客群、生效失效时间、触发条件、操作指引、例外场景与官方咨询口径等字段，核心字段包含规则唯一标识、触发阈值（单位为元、次/日等）、合规依据编号，部分规则会附带多语言版本的解释文本。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
由于交易规则更新无固定周期且依赖实时合规性，HTTP接口需支持按规则ID、生效时间范围、适用客群等多维度查询，避免缓存过期导致的规则版本不一致。由于单条规则包含多类单位的触发阈值，接口返回字段需严格映射预设的标准化字段，避免单位混淆。同时，规则关联的合规依据编号需随接口返回，支撑客户服务环节的溯源展示。外部系统对接时，需兼容单次返回多条规则的分页参数，适配知识库批量同步的需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `external_api_timeout` | `30 秒` | 交易规则外部接口响应通常不超过20秒，预留10秒缓冲时间 |
| `rule_cache_ttl` | `4 小时` | 交易规则更新无固定周期，缓存时长覆盖多数业务调整间隔 |
| `api_filter_params` | `["rule_id", "effective_time"]` | 交易规则查询需按唯一标识与生效时间精准匹配查询条件 |
| `response_field_mapping` | `{"trigger_threshold":"threshold","compliance_code":"basis_id"}` | 将外部接口字段映射为FastGPT内部标准化字段，避免字段名冲突 |
| `batch_sync_max_size` | `50 条/请求` | 单批次同步规则数量不宜过多，避免接口超时 |
| `error_retry_times` | `2 次` | 偶发网络波动不影响规则查询，重试可降低失败率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用外部接口后返回空规则列表，或知识库同步后无交易规则内容。原因：未配置`api_filter_params`的生效时间过滤条件，拉取了尚未生效或已失效的规则。
- 现象：接口调用卡住10秒后返回超时错误。原因：`external_api_timeout`配置小于实际接口响应时长，且未开启重试机制，导致偶发网络延迟触发超时。
- 现象：客户咨询时展示的规则单位与官方文档不符。原因：未配置`response_field_mapping`，直接使用外部接口的非标准化字段，导致阈值单位解析错误。

## 怎么确认配好了
- 调用配置完成的外部接口，核对返回字段与预设的映射关系是否匹配。
- 手动触发知识库同步任务，查看同步日志中记录的拉取规则数量，与外部接口返回的总条数是否一致。
- 发起模拟客户咨询请求，确认返回的交易规则内容包含生效时间、触发条件等核心字段。
- 模拟短暂网络延迟，检查接口调用是否按配置执行重试，未直接返回超时错误。
