# 交易规则客户服务的表单与交互

## 这个品类的数据长什么样
交易规则的数据来源于持牌金融机构官方发布的交易细则文档，更新随监管政策调整、业务流程优化不定期推进。文档多为结构化的章节式文本，包含交易品种范围、申报规则、费率标准、交割流程等模块，字段涵盖交易代码、单笔限额、费率比例、执行时效等，单位包含百分比、元、股、自然日等。

## 这些特征在「表单与交互」这一环带来什么约束
交易规则数据来源分散且更新无固定周期，要求交互环节支持多源文档的批量导入与增量同步校验。文档章节多、字段复杂，交互需针对不同交易品种预设对应字段的输入校验规则，避免单位不匹配、参数超限。同时，长文档的查询需支持精准定位到对应章节，避免用户在冗余内容中检索，提升交互效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 交易规则文档通常篇幅较长，需预留足够时间完成结构化解析 |
| `RECALL_TOP_N` | 前 8–12 条 | 交易规则字段密集，召回过多内容会增加交互负担，过少则无法覆盖完整规则 |
| `SIMILARITY_THRESHOLD` | 0.75–0.85 | 区分用户查询与交易规则的匹配度，避免低匹配结果干扰客户咨询 |
| `AUTO_UNIT_CONVERT` | 开启 | 交易规则包含多种单位（百分比、元、股），自动转换可降低用户输入错误 |
| `INCREMENTAL_SYNC_INTERVAL` | 每日凌晨 2 点 | 适配监管政策的不定期更新，每日同步可保证规则数据的时效性 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 容纳多份完整的交易规则文档，支持批量导入 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用模型时返回 400 状态码，仅在输入包含具体交易相关数字（如“350”）时触发。原因：未设置合理的`SIMILARITY_THRESHOLD`，导致无关片段被召回，叠加模型输入上下文超限引发报错。
- 现象：导入交易规则文档后，部分费率、限额字段的单位未自动对齐。原因：未开启`AUTO_UNIT_CONVERT`配置，或未覆盖文档中出现的全部单位类型。
- 现象：知识库中的交易规则长时间未更新。原因：`INCREMENTAL_SYNC_INTERVAL`配置周期过长，且未配置手动触发同步的入口，导致新规则无法及时生效。

## 怎么确认配好了
- 上传一份完整的交易规则文档，检查解析后的字段是否完整覆盖原文档的交易品种、费率、申报规则模块。
- 输入包含具体交易参数的查询，核对召回结果的匹配度是否符合预设的`SIMILARITY_THRESHOLD`区间。
- 手动触发一次增量同步，检查知识库中的规则是否更新为最新版本。
- 模拟包含不同单位的查询，确认系统是否自动完成单位转换，避免输入错误。
