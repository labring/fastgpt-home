# 产品咨询客户服务的知识库检索与召回

## 这个品类的数据长什么样
数据来源为官方产品说明书、费率公示文档、经标注的客服历史交互记录。更新节奏随产品上线、监管政策调整触发，无固定周期，紧急更新需在24小时内同步。单篇文档多为结构化内容，包含产品名称、产品类型、起投金额、期限、收益规则、赎回要求等字段，其中金额字段以元为单位，期限字段以自然日或自然年为单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
结构化字段明确的特征要求检索需同时匹配语义与字段关键词，避免返回无关产品的信息。更新频率不固定的特点要求配置支持增量文档同步，减少全量检索的资源消耗。金额、期限等带单位的字段，需在召回环节保留原始单位标注，避免用户获取的信息出现单位偏差。大量标注的历史交互记录，要求召回模型优先匹配高频咨询的产品问题，提升命中效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `召回条数` | 前8-12条 | 产品咨询的问题多为精准匹配，过多条目会增加上下文拼接压力，过少则可能遗漏有效产品信息 |
| `相似度阈值` | 0.75-0.85 | 产品信息的准确性要求高，阈值过低会引入无关内容，过高则可能无法召回相似产品的咨询问题 |
| `分段长度` | 600-800字符 | 产品文档多为结构化段落，分段过长会丢失字段关联信息，过短则会破坏产品规则的完整性 |
| `增量同步触发间隔` | 15-30分钟 | 产品更新无固定周期，短间隔可及时同步新内容，过长则会导致信息滞后 |
| `重排返回条数` | 前3-5条 | 客服人员仅需查看最相关的3-5条结果即可完成咨询，过多结果会增加筛选成本 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300秒 | 产品文档多包含长表格与结构化内容，解析耗时较长，超时会导致文档上传失败 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为上传产品文档时返回“Request failed with status code 400”，原因为文档中包含未转义的特殊符号或字段格式不符合解析要求。
- 现象为调用外部知识库API时自动携带Bearer令牌导致认证失败，原因为未关闭自动令牌注入配置，导致请求头重复携带认证信息。
- 现象为检索结果未包含产品标题相关的咨询内容，原因为未配置标题字段的召回权重，导致标题信息未被优先召回。

## 怎么确认配好了
- 上传一篇测试产品文档，检查解析后是否保留了所有字段与单位信息，无格式错乱。
- 发起一条包含产品名称与具体规则的咨询，检查召回结果的前3-5条是否包含匹配的文档片段。
- 模拟紧急更新一篇产品文档，查看是否在设定的同步间隔内完成更新，无延迟。
- 检查外部API配置项，确认自动令牌注入功能已关闭，避免认证错误。
