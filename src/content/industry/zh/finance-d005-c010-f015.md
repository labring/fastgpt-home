# 产品咨询客户服务的部署与升级

## 这个品类的数据长什么样
产品咨询的数据主要来源于金融产品官方手册、监管合规公示文档、历史用户咨询沉淀的FAQ库。数据分为结构化参数与非结构化说明两类，结构化部分包含产品编号、产品类型、年化收益率、投保年龄区间、保障额度范围、缴费期限等字段，单位对应百分比、万元、年等；非结构化部分包含投保须知、理赔流程、产品更新说明等文本。数据更新随对应金融产品的迭代节奏触发，核心条款、费率调整时会触发全量同步，日常小更新则采用增量同步。

## 这些特征在「部署与升级」这一环带来什么约束
结构化与非结构化混合的数据特征，要求部署阶段配置分层解析规则，适配不同格式的产品文档。产品更新节奏不固定且关联合规要求，升级阶段需支持增量同步机制，避免全量拉取占用过多系统资源。字段包含标准化金融参数，部署时需配置字段校验规则，确保导入数据符合监管格式要求。升级过程中需保留旧版字段映射兼容逻辑，防止存量配置失效，保障服务连续性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_STRUCTURED` | 开启 | 产品咨询数据包含大量标准化金融参数，开启结构化解析可提升召回准确率 |
| `SYNC_MODE` | 增量同步 | 产品更新节奏不固定，增量同步可降低部署与升级阶段的资源占用 |
| `VALIDATE_FIELDS` | 校验产品编号、年化收益率、保障额度 | 金融产品数据需符合合规格式，字段校验可避免错误数据流入知识库 |
| `BATCH_SYNC_SIZE` | 50–100 条/次 | 控制单次同步的数据量，防止接口超时 |
| `MAX_DOC_PARSE_TIMEOUT` | 300 秒 | 适配长文档的解析时长，避免金融产品详细条款无法完整导入 |
| `COMPATIBLE_OLD_CONFIG` | 开启 | 升级版本时保留旧版解析与同步配置，避免存量服务中断 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：部署后台的发布渠道选项中无前端嵌入页面入口，仅展示API调用地址。原因：升级过程中未勾选前端模块打包选项，默认仅启用API部署模式。
- 现象：启动Docker Compose服务时返回`PORT_CONFLICT`错误码，容器状态为exited。原因：本地端口与配置文件中指定的`SERVER_PORT`参数重复，未修改对应配置项。
- 现象：执行对话查询时发现存量对话记录无法通过后台界面批量清除。原因：未配置对话数据自动清理规则，且未手动执行容器内的数据库清理脚本。

## 怎么确认配好了
- 执行增量同步任务，查看同步日志中是否包含`SYNC_SUCCESS`标识，核对同步的数据条数与预期范围一致。
- 发起模拟产品咨询请求，检查返回结果中是否包含预设的产品参数字段，且格式符合合规要求。
- 验证前端嵌入模块（若启用）是否可正常加载，且能正确调取知识库内的产品信息。
- 触发一次版本升级流程，检查旧版配置是否仍可正常运行，无兼容性报错。
