# 投诉工单客户服务的工作流编排

## 这个品类的数据长什么样
投诉工单的数据来源于金融机构的客服交互系统、客户账户管理后台及监管投诉报送端口。数据更新节奏为实时提交，处理节点同步更新状态。单条工单文档包含固定字段：工单唯一标识字符串、关联客户账户编号、投诉分类标签、用户诉求原文、提交时间戳、当前处理进度编码、关联交易流水号。字段单位遵循行业通用系统规范，时间字段采用ISO 8601格式，文本字段无固定长度限制，进度字段为枚举字符串值。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据接入要求工作流配置跨系统数据拉取节点，需支持按工单ID精准匹配不同端口的工单数据。实时更新节奏要求工作流触发方式采用实时事件触发，适配工单提交后立即启动处理的场景。固定字段结构要求工作流中设置变量映射规则，将不同来源的工单字段统一映射为标准变量，避免字段不匹配导致的处理中断。富文本诉求内容要求工作流前置文本清洗节点，过滤无效格式字符，确保后续AI处理的准确性。枚举进度字段要求工作流配置分支判断节点，按进度状态执行对应处理逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `triggerMode` | `event` | 适配投诉工单实时提交的更新节奏，确保工单生成后立即启动处理流程 |
| `maxContextChars` | `1200–1800 字符` | 投诉工单诉求内容通常包含完整事件经过，该区间可覆盖多数单条诉求的核心信息，避免截断关键细节 |
| `multiSourceVarMap` | `按工单ID匹配字段` | 工单数据来自客服系统、CRM等多端口，需通过唯一标识统一映射为工作流可用的标准变量 |
| `progressBranchRule` | `按progress枚举值分支` | 工单进度为固定枚举类型，可精准触发对应处理分支，如待审核、待跟进、已办结 |
| `aiCallHistoryLimit` | `前 3 条历史记录` | 投诉工单处理仅需关联当前诉求及少量同类型参考，过多上下文会干扰核心判断 |
| `nodeTimeout` | `300 秒` | 投诉工单处理涉及多系统交互与AI调用，该时长可覆盖多数常规处理流程，避免超时中断 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流A调用工作流B后，工作流B内`userSelect`节点之后的所有节点未执行。原因：未配置`userSelect`节点的默认分支或回调触发规则，导致流程卡在等待用户选择的状态，未向下流转。
- 现象：调用`updateVar`节点尝试将变量值更新为空，界面显示变量仍保留原值。原因：未开启`allowEmptyValue`配置项，系统默认过滤空值更新，无法将变量重置为空。
- 现象：通过应用链接传递自定义参数，工作流全局变量未获取到传入值。原因：未在工作流触发配置中开启`urlParamBind`开关，导致外部传入的参数无法映射到全局变量。

## 怎么确认配好了
- 提交一条测试工单，查看工作流触发日志，确认触发模式与配置项一致。
- 手动导入多源测试数据，核对字段映射是否符合配置规则。
- 触发空值更新测试，查看变量状态是否符合预期。
- 通过外部链接传入预设参数，核对全局变量是否正确绑定参数值。
