# 专业连锁投研知识库建设的引用来源与溯源

## 这个品类的数据长什么样
专业连锁的数据源覆盖连锁总部ERP系统、POS收银系统、线下巡检报表及行业协会区域经营监测数据。数据更新节奏存在差异：单日客流、营收数据每日更新，区域汇总报表每周更新，供应链库存数据每3天更新。文档分为单门店经营台账与区域连锁汇总报表两类，单门店文档包含门店编号、日均客流、单客消费额、坪效数值等字段，区域文档包含覆盖门店数、总营收、平均坪效等字段。字段单位统一为人次、元、元/平方米、件等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
专业连锁的数据来源覆盖多系统，多源异构的特性要求溯源环节需关联各系统的元数据标识，避免混淆不同系统的同名称字段。不同数据的更新节奏差异明显，单日客流数据每日更新、区域汇总报表每周更新，溯源需强制绑定数据采集时间戳，防止引用过期信息。单门店与区域汇总的文档结构差异较大，溯源需匹配内容层级，确保引用内容与所属文档类型对应。字段单位统一校验的需求也更为突出，不同门店的坪效、消费额单位需保持一致，否则溯源无法准确关联对应数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `reference_source_enable` | 开启 | 投研场景需严格保证数据可追溯，开启后可强制为回答绑定溯源信息 |
| `reference_max_count` | 前3条 | 专业连锁核心经营数据通常集中在少数核心文档，过多引用会分散投研注意力 |
| `reference_time_range` | 近90天 | 连锁行业经营数据短期波动较大，超过90天的数据参考价值降低 |
| `metadata_require_fields` | `["门店编号", "采集时间", "数据单位"]` | 专业连锁数据存在层级与单位差异，需通过这些字段准确匹配溯源内容 |
| `reference_deny_empty_source` | 开启 | 投研结论需可验证，无来源的内容无法满足专业场景要求 |
| `reference_export_with_source` | 开启 | 投研报告需留存溯源依据，导出时携带来源可方便后续复核 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：配置`reference_max_count`为`前2条`后，搜索结果的引用条数仍超过2条。原因：未同步配置`reference_time_range`过滤过期数据，系统优先召回了过期文档，占用了引用配额。
- 现象：生成的投研回答末尾显示“没有权限操作此对话记录”作为引用提示。原因：未配置对话的公开溯源权限，或未开启`reference_export_with_source`的本地存储模式，导致无法生成可访问的溯源信息。
- 现象：上传连锁经营文档后，部分文档无法被索引为知识库条目。原因：上传的文档缺少`metadata_require_fields`中配置的`门店编号`或`采集时间`字段，系统校验不通过导致溯源配置失效。

## 怎么确认配好了
- 上传一份标准的单门店经营文档，触发一次投研问答，检查回答末尾是否显示对应的溯源信息，包括文档来源、采集时间和数据字段。
- 进入系统的配置管理页面，查看`reference_source_enable`、`metadata_require_fields`等核心参数的取值是否与预设配置一致。
- 导出一份投研问答结果，检查导出文件中是否包含完整的引用溯源条目，且无权限报错信息。
- 模拟导入外部工作流，检查关联的知识库引用配置是否能正常加载，无插件或字段不匹配的提示。
