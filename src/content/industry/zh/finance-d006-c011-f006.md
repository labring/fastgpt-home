# 休闲食品投研知识库建设的对话日志与审计

## 这个品类的数据长什么样
休闲食品投研数据来源包括线下商超POS动销数据、头部电商平台商品评论与销量数据、行业协会月度产销报告、上游谷物油脂等原材料期货行情数据、品牌方公开财报与新品公告。文档结构覆盖结构化销量数据表、非结构化消费者评论文本、PDF格式行业研报、表格化原材料价格曲线。字段包含SKU编号、销售门店数量、月度销售额、消费者评论点赞数、原材料采购价、食品添加剂使用标准编号。动销数据日更，行业研报周/月更，原材料行情实时更新，评论数据实时爬取。

## 这些特征在「对话日志与审计」这一环带来什么约束
休闲食品投研的多来源、多格式数据特征，要求对话日志同时记录结构化参数与非结构化文本的调用上下文，避免溯源时混淆数据类型。不同更新频率的数据源要求审计系统绑定调用时间戳，确保实时更新的原材料数据版本可追溯。SKU、销售区域等细分字段，要求日志关联对应标识，便于按商品或区域拆分审计范围。食品添加剂相关字段则要求审计覆盖合规类对话，符合食安监管的留存要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `chatId` | 必传且绑定SKU/区域标识 | 用于关联对话与具体投研场景的商品或区域，解决chatId未在日志中显示的问题 |
| `LOG_RETENTION_DAYS` | 180 天 | 覆盖行业研报的月度更新周期，同时满足食安监管的审计留存要求 |
| `LOG_EXPORT_FIELD_WHITELIST` | `["chatId", "skuCode", "salesRegion", "timestamp", "query", "answer"]` | 仅保留投研相关核心字段，避免冗余数据占用存储，符合数据治理要求 |
| `AUDIT_TRIGGER_CONDITION` | 当`query`包含「添加剂」「合规」「SKU」关键词时触发 | 针对休闲食品的食安合规场景，自动触发审计校验 |
| `MAX_CHAT_LOG_SIZE` | 2000 字符/条 | 适配非结构化评论文本的长度，避免单条日志溢出 |
| `LOG_PRESERVE_WHEN_USER_DELETE` | 开启 | 避免免登录用户删除对话后后台日志同步清除，符合审计留存要求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：免登录用户删除对话后，后台对应日志同步消失。原因：未开启`LOG_PRESERVE_WHEN_USER_DELETE`配置项，导致用户端删除操作同步清除后台日志。
- 现象：API调用时传入`chatId`参数，但日志中未显示该字段。原因：API请求参数名拼写错误，或未在FastGPT开源版V4.9.7后台开启`CHAT_ID_RECORD_ENABLE`开关。
- 现象：调用日志接口返回`500 Internal Server Error`，提示获取数据异常。原因：未设置`LOG_DB_QUERY_TIMEOUT`参数，或取值过短导致日志查询超时。

## 怎么确认配好了
- 生成一条携带`chatId`与SKU标识的测试对话，查看后台日志是否正确记录`chatId`与`skuCode`字段。
- 触发一次包含「添加剂」关键词的查询，确认审计系统是否自动生成对应校验记录。
- 模拟免登录用户删除一条测试对话，检查后台日志是否仍保留该记录。
- 调用`/api/chat/log`接口，确认返回状态码为200且无数据超时报错。
