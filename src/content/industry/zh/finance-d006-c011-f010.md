# 休闲食品投研知识库建设的数据库与运维

## 这个品类的数据长什么样
休闲食品投研数据主要来自经销商进销存台账、线下终端POS销售流水、第三方电商平台销售榜单、行业协会月度供需报告及上游原材料采购报价。数据更新节奏差异明显：终端动销数据按日同步，进销存台账按周更新，行业报告按月发布。单条数据条目包含SKU编码、产品名称、净含量、销售区域、进货价、零售价、库存周转天数等字段，净含量单位多为克或千克，价格单位为元，周转天数单位为自然日。

## 这些特征在「数据库与运维」这一环带来什么约束
多源异构的数据来源要求数据库支持多格式批量导入与API增量拉取能力。日更的终端动销数据体量较大，需配置分片集群分摊写入压力，同时针对SKU编码与时间范围建立联合索引加速查询。周更的进销存台账需通过定时任务触发同步，需配置任务调度与失败重试的运维接口。字段包含多类单位与唯一标识SKU，需在入库前完成单位校验与主键去重，避免脏数据进入知识库。此外，部分区域终端数据缺失，需配置空值填充规则，保证知识库数据完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `mongodb_shard_count` | 3–5个分片 | 日更终端动销数据体量较大，3-5分片可平衡写入性能与运维复杂度 |
| `mysql_batch_insert_size` | 1000–2000 条/批次 | 休闲食品SKU数量较多，批量插入可降低数据库连接开销与写入延迟 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 部分行业供需报告文档篇幅较长，需预留足够的文件解析时间 |
| `recall_top_k` | 前 8–12 条 | 投研场景需兼顾信息全面性与上下文承载量，过多召回会超出大模型上下文限制 |
| `db_connection_timeout` | 15 秒 | 多源数据库连接需控制超时阈值，避免单节点异常导致整体任务阻塞 |
| `field_validation_enabled` | 开启 | 需校验字段格式与单位合规性，避免脏数据进入投研知识库 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
-  界面显示`1045 Access denied`报错，数据库连接失败。原因是未正确配置docker部署的MongoDB或MySQL账密，或账密未被授予对应数据库的读写权限。
-  大模型返回的投研结果未附带MySQL数据库的原文片段。原因是未开启Function CALL的结果片段提取配置，或未指定返回字段的原始内容字段名。
-  定时数据同步任务出现`504 Gateway Timeout`状态码，任务执行失败。原因是未根据单批次数据体量调整`mysql_batch_insert_size`参数，单次插入数据量超出数据库负载上限。

## 怎么确认配好了
-  执行单批次SKU数据导入测试，检查数据库写入日志无报错，验证字段映射与单位校验规则生效。
-  发起模拟投研对话，触发Function CALL调用MySQL销售数据，检查返回结果包含指定字段的原始内容片段。
-  查看数据库监控面板，确认分片集群的写入负载处于稳定区间，无节点过载情况。
-  手动触发周度进销存同步任务，检查任务执行日志无超时或失败记录，数据同步流程正常完成。
