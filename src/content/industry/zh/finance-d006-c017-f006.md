# 光学光电子投研知识库建设的对话日志与审计

## 这个品类的数据长什么样
光学光电子领域的投研数据主要来源于行业协会公开报告、上游晶圆厂与器件厂商的规格文档、专利数据库、产线监测日志及学术论文。行业研报按月更新，专利文档随申请实时入库，器件规格书随新品发布同步更新。文档结构包含长文本分析章节、结构化参数表格与时序监测数据片段，字段涵盖器件型号、工作波长（单位纳米）、响应速度、良品率、专利申请日期等，部分文档单篇长度可达数百页。

## 这些特征在「对话日志与审计」这一环带来什么约束
光学光电子投研对话常涉及长文档召回、精确参数匹配与多源数据交叉验证，因此对话日志需完整记录交互上下文、数据源版本及参数调用细节。频繁更新的数据源要求审计环节关联对话记录与知识库版本变更，避免因数据迭代导致决策追溯失效。结构化参数与时序数据的存在，要求日志同时支持自然语言交互与结构化字段的留存，满足合规审计的多维度核查需求。投研场景的多人协作特性，还要求审计日志具备用户权限隔离能力，防止敏感投研数据泄露。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `log_retention_days` | 180 天 | 光学光电子投研涉及长期供应链与专利追踪，需保留至少半年审计记录以满足行业合规要求，同时控制存储成本 |
| `audit_log_include_context` | 开启 | 投研对话常关联长文档召回与参数匹配，完整记录上下文可追溯决策依据，避免信息断层 |
| `api_conversation_log_switch` | 开启 | 需同步记录API调用与页面端对话的日志，覆盖全渠道交互的审计需求 |
| `max_log_entry_size` | 2048 KB | 应对长文本交互与结构化参数日志的存储需求，避免截断关键投研数据 |
| `log_export_format` | JSON + CSV 双格式 | 满足合规审计的结构化导出与人工核查的表格化需求 |
| `user_conversation_visible_only` | 开启 | 限制用户仅查看自身对话，符合投研数据的隐私保护要求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：对话日志中无法显示工作流模块的console.log输出，仅能在容器内部控制台查看。原因：未开启工作流节点的日志回写配置，未将内部控制台日志同步至FastGPT审计日志系统。
- 现象：批量清理对话日志后，部分通过API创建的对话记录未被删除。原因：未配置批量清理范围覆盖API端对话，仅清理了页面端生成的对话条目。
- 现象：不同用户登录后可查看彼此的历史对话内容。原因：未开启`user_conversation_visible_only`配置，未限制对话的用户访问权限。

## 怎么确认配好了
- 发起一次API创建的对话，检查审计日志列表中是否包含该对话的完整交互记录，包含上下文、参数调用与数据源关联信息。
- 以测试用户身份发起对话，切换至其他用户账号，验证无法查看测试用户的历史对话内容。
- 触发包含console.log的工作流节点，检查FastGPT审计日志中是否存在对应输出条目。
- 尝试执行日志导出操作，验证导出格式包含JSON与CSV两种类型，且内容完整无截断。
