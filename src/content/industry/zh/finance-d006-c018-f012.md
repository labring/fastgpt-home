# 光模块投研知识库建设的模型接入与配置

## 这个品类的数据长什么样
数据源包括通信行业标准规范文档、光模块厂商公开的产品规格书、行业监测数据。文档多为结构化技术手册，包含封装形式、传输速率、功耗、工作波长、接口类型等核心字段，传输速率单位为Gbps，功耗单位为W，工作波长单位为nm，工作温度范围标注为℃。更新随光模块新品发布、行业标准修订、市场动态更新而调整，无固定统一周期，部分厂商会同步更新兼容适配的系统要求文档。

## 这些特征在「模型接入与配置」这一环带来什么约束
光模块数据的结构化特征要求模型接入时配置支持单位化数值解析的规则，避免混淆Gbps、W、nm等单位对应的参数含义；多来源数据存在标准规范与厂商文档的差异，需配置数据源优先级参数，确保优先采信行业标准内容；更新节奏随新品发布、标准修订动态调整，需配置知识库的增量同步触发规则，适配非固定周期的内容更新；部分厂商文档包含长段落的测试流程描述，需配置合理的分段与召回参数，避免截断关键技术细节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | 前8-12条 | 光模块投研数据包含多维度技术参数，8-12条可覆盖核心参数的上下文，避免冗余信息干扰 |
| `相似度阈值` | 0.75-0.85 | 光模块技术参数表述相对规范，该阈值可过滤低匹配度的无关文档，保留精准匹配的技术内容 |
| `分段长度` | 800-1200字符 | 光模块文档的技术段落多为连贯的参数说明，该长度可保留单组完整参数的上下文，避免拆分跨参数的段落 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300秒 | 光模块厂商规格书多为多页结构化文档，300秒可覆盖完整解析时长，避免大文件解析超时 |
| `model_api_prefix` | 带`/v1`后缀的API地址 | 适配行业通用的大模型API调用格式，兼容中转平台的接口规范 |
| `索引模型` | 专业文本嵌入模型 | 光模块技术术语较多，专业嵌入模型可更精准地编码技术参数与行业术语 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：4.8.20版本后调用大模型时提示配置无效，原OneApi本地配置文件无生效。原因：该版本后模型配置迁移至前端页面管理，本地config文件的配置不再被读取。
- 现象：上传光模块规格书后，大模型提示「null未上传」，但文件可正常下载。原因：文件解析环节未正确关联上传的文件元数据，导致模型调用时无法获取文件索引。
- 现象：配置索引模型后，检索结果无法匹配光模块的专业参数。原因：未选择专业文本嵌入模型，或未将索引模型配置为知识库绑定的检索模型。

## 怎么确认配好了
- 进入模型配置页面，核对API地址是否添加了`/v1`后缀，与中转平台的配置一致。
- 上传一份光模块厂商规格书，等待解析完成后，查看解析后的分段是否保留了完整的参数组，无截断情况。
- 发起一次投研查询，核对返回的检索结果条数是否符合预设的召回条数配置。
- 查看知识库的索引模型绑定状态，确认已选择与光模块投研适配的嵌入模型。
