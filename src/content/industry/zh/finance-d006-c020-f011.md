# 兵器装备投研知识库建设的文档解析与分块

## 这个品类的数据长什么样
兵器装备投研数据主要来自国防军工行业公开研报、军工集团官方公告、行业技术标准文档、装备招投标公示文件及官方技术手册。更新节奏随行业动态调整，季度行业研报定期更新，重大装备技术迭代或采购政策调整时会有临时文档发布。文档多为带多页图表的PDF格式，包含装备型号参数、性能指标、测试数据等结构化字段，单位涉及毫米、千米、千克、每分钟射速等专业军工计量单位，部分文档内嵌装备拆解示意图、性能曲线等非文本元素。

## 这些特征在「文档解析与分块」这一环带来什么约束
兵器装备投研文档多内嵌装备示意图、性能曲线等非文本元素，需支持图片文本提取以完整召回参数信息。文档包含大量带专业单位的结构化参数，分块时需避免拆分数值与对应单位，防止参数信息失效。部分招投标类文档篇幅较长，需适配长文本解析逻辑，同时季度更新的行业研报与临时技术公告要求解析流程具备高效性。不同文档的章节层级差异较大，需保留原始文档的结构关联，避免跨章节的参数混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_IMAGE_ENABLE` | 开启 | 兵器装备文档内嵌大量装备示意图、性能曲线等非文本元素，需提取图片内的参数文本以完整召回信息 |
| `PARSE_CHUNK_SIZE` | 800–1200 字符 | 文档包含大量带专业单位的结构化参数，该区间可避免拆分数值与对应单位，同时保留上下文关联 |
| `PARSE_CHUNK_OVERLAP` | 10–15% | 保留参数段落前后的关联信息，防止跨块的性能指标、型号信息断裂 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 适配大型招投标文档、年度行业白皮书等长篇幅文件的上传需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 为大尺寸PDF的图片解析与文本提取预留充足处理时间 |
| `TEXT_SPLITTER_MODE` | 按段落+语义分割 | 保留装备参数的段落完整性，避免拆分同类型的技术指标块 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：知识库召回结果中未包含PDF内嵌的装备示意图文本，或图片文本提取不完整。原因：未开启`PARSE_IMAGE_ENABLE`配置项，导致系统仅提取纯文本内容，遗漏图片中的参数信息。
- 现象：分块结果拆分了数值与专业单位，或同一段性能指标被分割到两个块中。原因：未明确分块长度的统计单位，误将token数量作为分段依据，或分段长度设置过短导致参数拆分。
- 现象：大型招投标文档解析失败，返回`413 Request Entity Too Large`状态码或解析超时提示。原因：未调整`UPLOAD_FILE_MAX_SIZE`与`PARSE_FILE_TIMEOUT_SECONDS`配置，超出系统默认限制。

## 怎么确认配好了
- 上传一份包含内嵌图片的兵器装备技术手册PDF，检查解析结果是否包含图片中的文本参数。
- 查看分块后的文本片段，确认同一段带专业单位的参数未被拆分到不同块中。
- 上传一份超过默认上传限制的大型文档，确认上传与解析流程可正常完成。
- 查看系统日志或解析任务详情，确认相关配置项的实际生效状态。
