# 农商行投研知识库建设的对话日志与审计

## 这个品类的数据长什么样
农商行投研知识库的数据主要来源于内部信贷审批档案、辖内涉农经营主体的月度经营报表、地方金融监管局发布的区域产业政策文件、央行县域金融运行报告，以及自身代销的理财产品档案。数据更新节奏存在差异：内部信贷数据每日更新，涉农经营报表按季度更新，监管政策文件按发布节点更新。文档结构分为两类：结构化表格类文档包含统一社会信用代码、授信余额、担保方式等字段，单位为万元；政策类文档包含文号、发布日期、适用区域等字段，以条款式排版为主。

## 这些特征在「对话日志与审计」这一环带来什么约束
农商行投研数据的多来源、多更新节奏特征，要求对话日志必须关联对应数据的来源标识与更新时间，避免混淆不同批次的政策或信贷数据。结构化的字段特征要求日志需记录用户调用时匹配的具体字段，如授信主体代码、产业占比数值，便于审计时追溯数据调用逻辑。由于数据涉及涉农经营主体的敏感经营信息与信贷额度，对话日志需符合金融数据安全规范，需加密存储并限制访问权限。同时，监管要求的审计留存周期，要求日志系统需保留至少半年的完整对话记录，不得随意删除。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `LOG_RETENTION_DAYS` | `180 天` | 符合农商行金融监管的审计留存要求，覆盖季度与半年度审计周期 |
| `API_CHAT_ID_REQUIRED` | `开启` | 强制要求调用API时传递chatId参数，避免日志无关联标识，解决对话溯源困难问题 |
| `LOG_ENCRYPTION_ENABLE` | `开启` | 对存储的对话日志进行加密，符合金融数据安全合规要求，保护信贷与客户敏感信息 |
| `DELETE_CHAT_LOG_PERMISSION` | `仅管理员可操作` | 限制普通用户与免登录用户的日志删除权限，避免审计数据丢失 |
| `CHAT_ID_BIND_PREFIX` | `绑定内部客户ID前缀` | 关联农商行内部客户标识，便于按业务线追溯对话日志 |
| `PARSE_LOG_STORAGE_PATH` | `合规加密对象存储路径` | 确保日志存储介质符合金融数据安全存储规范，防止数据泄露 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用API传递chatId参数后，后台对话日志未显示该参数，日志中无chatId字段。原因：未开启`API_CHAT_ID_REQUIRED`配置项，系统自动忽略传入的chatId参数，导致日志无法关联对话上下文。
- 现象：免登录链接用户删除对话后，后台存储的对应对话日志同步被删除。原因：未配置`DELETE_CHAT_LOG_PERMISSION`为仅管理员可操作，开放了所有用户的日志删除权限，导致审计数据丢失。
- 现象：发起模型调用后，日志页面报错返回500状态码，提示获取数据异常。原因：未正确配置`LOG_ENCRYPTION_ENABLE`的存储密钥，导致系统无法解密读取已存储的日志数据。

## 怎么确认配好了
- 调用API发起投研相关对话，携带合法chatId参数，查看后台日志列表是否存在该chatId字段，验证配置生效。
- 使用免登录链接发起对话后，尝试执行删除操作，检查管理员后台是否仍保留该对话日志，验证权限配置。
- 发起模型调用后，查看日志页面是否正常加载数据，无报错提示，验证存储与加密配置。
- 检查日志存储路径的访问权限，确认只有授权角色可访问加密后的日志文件，验证存储合规性。
