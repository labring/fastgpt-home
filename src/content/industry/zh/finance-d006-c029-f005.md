# 包装印刷投研知识库建设的多轮对话与提示词

## 这个品类的数据长什么样
包装印刷投研数据来源涵盖行业协会月度原辅材料报价、上市印刷企业季度财报、海关包装制品进出口数据、印刷设备厂商技术手册及包装订单样本档案。更新节奏分为三类：原辅材料报价每日更新，行业分析报告按季度发布，企业财报与设备参数文档按年度或重大技改节点更新。文档结构包含单页结构化报价表、长篇行业分析报告、批量订单台账，字段单位多采用g/㎡（纸张克重）、万色令/年（产能）、色令（印刷工作量单位）等行业专用标准。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多源异构的数据类型要求多轮对话需区分实时报价、静态报告、台账数据的召回优先级，避免无关数据干扰上下文逻辑。专用单位与字段容易在跨数据源匹配时出现歧义，提示词需强制要求统一单位表述，否则会导致投研结论出现偏差。长文档与批量台账的混合输入会占用上下文窗口，需在多轮对话中自动截断非核心历史内容，保留关键投研信息。不同更新频率的数据需在对话中标注时间戳，确保投研人员获取的信息为最新有效版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | 12000-15000 字符 | 平衡包装印刷行业长报告与批量报价表的上下文承载需求，避免上下文溢出 |
| `recallTopK` | 前 8-12 条 | 覆盖原辅材料报价、企业财报、行业分析三类核心投研数据，避免召回冗余 |
| `similarityThreshold` | 0.72-0.78 | 区分包装印刷行业近似字段（如157g/㎡与200g/㎡的纸张），降低误召回概率 |
| `systemPrompt` | 强制统一使用包装印刷行业标准单位，回复需标注数据时间戳 | 解决专用单位歧义与数据时效性问题 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 适配大型印刷设备手册、批量订单台账的解析耗时需求 |
| `toolCallTimeout` | 600 秒 | 适配原辅材料报价接口的同步查询耗时，适配开源版V4.9.7的工具调用规范 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：配置MySQL工具调用后执行返回400 status code (no body)。原因：未在工具配置中正确指定包装印刷行业专用数据库字段（如印刷产能、原辅材料库存字段），导致参数校验失败。
- 现象：工作流节点无法加载之前对话中保存的全局变量。原因：未开启对话上下文同步配置，且未将包装印刷投研的企业ID、报告期数等变量标记为可跨对话复用。
- 现象：发布免登录链接后，删除对话内容时后台日志同步被清除。原因：未关闭“对话删除同步清除日志”的开关，导致投研操作记录丢失。

## 怎么确认配好了
- 发起包含包装印刷专用术语与单位的多轮连续提问，核对回复中未出现单位混用情况。
- 触发MySQL工具调用，检查返回结果包含预设的包装印刷行业数据库字段。
- 执行对话删除操作，核对后台日志是否保留投研相关的操作记录。
- 在新对话中尝试调用历史对话保存的全局变量，核对变量内容正确加载。
