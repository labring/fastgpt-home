# 化纤投研知识库建设的对话日志与审计

## 这个品类的数据长什么样
化纤行业投研数据主要来自上游石油石化中间体报价、中国化纤工业协会月度供需台账、上市公司定期报告、现货交易平台实时报价。数据更新节奏分为三类：现货价格按交易日实时更新，行业供需报告按月度发布，上市公司财报按季度更新。单篇文档长度差异较大，研报类可达数万字符，现货报价单仅数百字符。文档字段包含产品品类、纤度单位dtex、价格元/吨、产能万吨、生产工艺参数等核心信息。

## 这些特征在「对话日志与审计」这一环带来什么约束
化纤投研数据的多更新节奏、跨度型文档长度、标准化字段与多源特性，对对话日志与审计环节形成多重约束。实时更新的现货数据要求日志关联对话发起时间与对应数据源版本，避免引用过期信息。长研报与短报价单的尺寸差异，要求日志完整记录召回的文档片段与引用位置，防止关键参数被截断。纤度dtex、价格元/吨等固定字段单位，要求审计环节校验对话中引用的单位与数据源一致，防范单位偏差。多源数据叠加的场景，需在日志中留存每条调用的数据源来源与更新时间，支撑投研结论回溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `LOG_RETENTION_DAYS` | `90 天` | 覆盖至少一个完整财报周期，满足季度级投研结论的审计回溯需求 |
| `MAX_LOG_CHARACTERS_PER_SESSION` | `20000 字符` | 适配化纤研报与报价单的长度差异，完整记录对话与文档引用片段 |
| `DATA_SOURCE_VERSION_TRACKING` | `开启` | 关联对话发起时间与对应数据源版本，避免引用过期的现货或财报数据 |
| `LOG_FIELD_VALIDATION_ENABLE` | `开启` | 校验对话中引用的纤度dtex、价格元/吨等字段单位，防范投研参数偏差 |
| `AUDIT_LOG_EXPORT_FORMAT` | `JSON + CSV 双格式` | 兼顾程序解析与人工审计的存档需求，适配不同合规场景 |
| `LOG_ERROR_STACK_TRACE` | `开启` | 留存文档解析或调用异常的堆栈信息，快速定位投研数据调用问题 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：配置`LOG_STORAGE_TYPE`为MongoDB后，无法在对应数据库集合中查询到对话历史记录。原因：未开启`LOG_PERSISTENCE_ENABLE`开关，或未配置MongoDB连接字符串的读写权限。
- 现象：发起投研对话后，日志中未记录引用的化纤产品参数与对应单位。原因：未开启`LOG_FIELD_RECORD_ENABLE`开关，或配置的召回字段未覆盖dtex、价格等核心投研信息。
- 现象：上传化纤工艺文档后，日志显示上传成功，但对话中无法调用该文档内容。原因：未配置`PARSE_FILE_TIMEOUT_SECONDS`为适配长文档的取值，或文档格式不符合系统解析规则。

## 怎么确认配好了
- 进入日志管理模块，选择任意投研会话，核对日志中是否留存对话发起时间、关联的数据源版本、引用的化纤产品参数与对应单位。
- 触发审计日志导出操作，确认导出文件包含预设的字段清单，且格式符合配置要求。
- 发起一次包含多源数据调用的对话，检查日志中是否完整记录每条数据的来源与更新时间。
- 验证MongoDB连接配置的读写权限，确认日志数据能够正常写入指定数据库集合。
