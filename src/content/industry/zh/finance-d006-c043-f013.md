# 商业地产投研知识库建设的知识库检索与召回

## 这个品类的数据长什么样
商业地产投研数据主要来自项目运营台账、商圈客流监测系统、官方租金报价数据库、商业用地规划政策文件、第三方业态调研报告。更新节奏：租金单价数据月度更新，客流监测数据周度更新，年度项目年报每年更新，政策文件随发布节奏不定期更新。文档结构包含结构化字段与非结构化内容：结构化字段包括项目名称、商圈等级、租金单价、空置率、客流人次；非结构化内容包括数万字的项目业态分析PDF、长文档的商圈发展调研报告。

## 这些特征在「知识库检索与召回」这一环带来什么约束
结构化字段占比高，要求检索环节同时支持精确匹配与模糊匹配，避免因字段单位或名称不一致导致检索偏差。不同数据源更新频率差异大，需要配置分批次的增量更新任务，避免全量刷新占用过多资源。非结构化调研报告篇幅较长，需合理控制分段长度，保障检索召回的上下文逻辑完整。地域与商圈维度多，需支持按城市、商圈类型等维度过滤召回结果，提升检索精准度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | `前10-15条` | 商业地产投研数据包含结构化字段与非结构化长文档，过多召回内容会超出上下文窗口，过少会遗漏关键业态分析与租金数据 |
| `相似度阈值` | `0.72-0.85` | 结构化租金、空置率字段需要较高匹配精度，非结构化调研报告需保留一定模糊匹配空间，避免漏召回行业政策与客流分析内容 |
| `分段长度` | `800-1200字符` | 商业地产单篇调研报告可达数万字，分段过长会导致上下文冗余，过短会破坏业态走势、租金分析的完整逻辑 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600秒` | 大型商业地产项目的全套台账、调研报告PDF解析耗时较长，默认超时时间无法覆盖完整解析流程 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 单份商业地产项目的全套运营数据、监测报告文件体积较大，需放宽上传限制以支持完整文件导入 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 上传商业地产的Markdown业态分析文件时，界面提示解析失败或解析后内容缺失。原因是Markdown文件包含未闭合的表格、代码块，或采用非UTF-8编码，导致解析插件无法正确提取文本内容。
- 本地调试预览时检索结果匹配准确，部署到自有业务页面后检索返回空结果或结果不相关。原因是上线环境的向量库同步任务未配置，或跨域访问权限未正确设置，导致检索请求无法关联到完整的知识库向量数据。
- 检索结果中展示的商业地产项目实景图、商圈地图无法加载，控制台返回403或404错误。原因是图片链接使用了私有存储桶权限，未配置公开访问权限，或链接有效期已过期。

## 怎么确认配好了
- 上传一份标准商业地产项目的Markdown文档，查看解析后的文本片段是否完整保留了租金、空置率等结构化字段，以及业态分析的完整段落。
- 发起一次检索请求，输入包含结构化字段的查询词，核对返回结果是否优先匹配目标字段，且召回结果的数量符合配置要求。
- 等待配置的增量更新任务触发，查看知识库的更新日志是否显示对应数据源的增量同步成功，无超时或解析失败记录。
- 插入一张公开可访问的商业地产图片链接，验证检索结果中图片是否正常加载，无报错提示。
