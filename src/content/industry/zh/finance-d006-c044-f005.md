# 商业物业投研知识库建设的多轮对话与提示词

## 这个品类的数据长什么样
商业物业投研数据主要来自项目内部运营台账、合作方业态规划文件、属地商圈监测平台公开信息。更新节奏分为三类：租赁合同、租金调整记录随签约、调价实时更新；项目出租率、坪效等运营指标每月更新；商圈人流、竞品布局数据每季度更新。文档结构包含结构化的运营报表（含可租面积、租金单价、出租率相关字段）、非结构化的业态分析报告、现场勘查影像资料。字段与单位方面，可租面积单位为平方米，租金单价单位为元/平方米/日，租期单位为月，业态类型为文本分类字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
商业物业投研数据的更新节奏差异、混合结构与复杂字段，对多轮对话与提示词配置带来多重约束。首先，实时更新的租赁合同与月度运营数据，要求多轮对话支持实时数据拉取，提示词需明确区分实时运营数据与历史调研数据的调用优先级。其次，包含平方米、元/平方米/日等多类单位的字段，要求提示词内置单位校验规则，避免对话中出现单位换算错误。此外，结构化报表与非结构化报告混合的数据结构，要求多轮对话支持上下文关联的切换查询，比如从整体出租率追问单楼层业态数据。最后，跨项目与商圈的联动分析需求，要求提示词配置跨数据源的关联逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 商业物业投研对话需保留多轮运营数据、业态分析的上下文关联，足够的窗口可避免关键信息丢失 |
| `recall_top_k` | `前 6–8 条` | 商业物业投研数据包含多类结构化报表与非结构化报告，需召回足够条目覆盖租户、租金、商圈等多维度投研需求 |
| `similarity_threshold` | `0.75–0.85` | 平衡精准匹配租金单价、出租率等核心字段与覆盖不同业态的分析需求，避免召回冗余或缺失关键数据 |
| `prompt_template` | 预设为「请结合商业物业的运营数据与商圈信息，按用户提问的上下文逐步分析，明确标注引用数据的更新时间」 | 引导模型关联多轮对话的上下文与数据时效性，符合商业物业投研对数据新鲜度的要求 |
| `file_parse_chunk_size` | `1000–1500 字符` | 商业物业的运营分析报告篇幅较长，该分段长度可兼顾语义完整性与单段召回的精度 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：对话开场白的快捷按键点击后无响应。原因：未在提示词模板中配置快捷按键关联的触发指令，或快捷按键的参数绑定未指向正确的知识库分类。
- 现象：无登录状态下查看对话历史时，内嵌的运营报表图片无法加载。原因：未配置公共访问权限的图片存储路径，或图片链接的有效期设置过短，导致未登录状态下无法获取资源。
- 现象：嵌套调用其他已配置的应用时，被调用应用未记录当前对话的上下文日志。原因：未开启被调用应用的上下文继承配置项，导致对话日志仅保留在父工作流中。

## 怎么确认配好了
- 发起包含多维度需求的连续提问，比如先查询整体出租率，再追问特定业态的租金数据，确认对话可保留上下文并关联不同类别的投研信息。
- 测试不同单位的字段查询，比如分别询问对应不同计价周期的租金数据，确认模型可正确识别单位并匹配对应字段。
- 触发嵌套调用其他应用的流程，确认被调用应用可同步获取当前对话的上下文信息并生成关联分析结果。
- 切换至无登录状态查看对话历史，验证内嵌的运营报表图片可正常加载，确认存储权限与链接有效期配置符合要求。
