# 商业物业投研知识库建设的对话日志与审计

## 这个品类的数据长什么样
商业物业投研的核心数据来源包括自持与租赁物业的租约台账、月度租金流水、日度客流统计、业态经营报告，以及周边同商圈竞品的经营调研数据。数据更新节奏差异明显：租约台账在签署或变更时实时更新，租金流水按月度更新，客流统计按日更新，竞品调研数据按季度更新。文档结构包含结构化表格与非结构化文档，字段单位统一使用平方米、元/平方米/天、人次等行业标准单位。

## 这些特征在「对话日志与审计」这一环带来什么约束
商业物业投研数据的多源异构性要求对话日志需区分结构化数据查询与非结构化文档问答的类型标签，避免日志混淆不同数据来源的调用记录。高频更新的客流、租金数据需在日志中记录查询时刻的知识库快照版本，防止因数据迭代导致的审计溯源偏差。涉及租户隐私、租金成本的敏感数据，审计环节需完整记录每一次调用的主体、时间、参数与返回结果，同时支持敏感字段的自动脱敏。多部门协同的投研场景下，日志需关联项目唯一标识，确保跨角色的操作可完整溯源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `API_CHAT_LOG_ENABLE` | 开启 | 适配V4.9.7及以上版本，商业物业投研常通过API批量调用知识库，开启后可记录所有API发起的对话，满足跨部门审计需求 |
| `LOG_RETENTION_DAYS` | 180 天 | 商业物业投研数据需留存至少一个完整财年，符合行业审计与合规要求 |
| `CHAT_LOG_INCLUDE_CHATID` | 开启 | 商业物业投研对话常关联特定项目的租约、客流数据，开启后可在日志中携带chatId参数，实现单项目全链路对话的溯源 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 商业物业的业态分析报告、竞品调研文档通常篇幅较长，解析耗时较长，避免因超时中断导致日志缺失 |
| `LOG_AUDIT_MASK_FIELDS` | ["租赁面积", "租金单价", "租户名称"] | 商业物业的租金、租户信息属于敏感数据，配置该参数可在审计日志中自动隐藏对应字段，满足数据合规要求 |
| `MAX_CONTEXT` | 前10条历史对话 | 投研对话需关联过往的项目分析，过多历史会增加日志冗余，同时保证上下文连贯 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用OneAPI生成的对话日志未出现在后台日志列表中，原因是未启用`API_CHAT_LOG_ENABLE`配置项，导致API发起的对话未被写入审计日志系统。
- 现象：后台对话日志的使用者字段为空，或未显示传入的chatId参数，原因是未开启`CHAT_LOG_INCLUDE_CHATID`配置，或调用API时未按规范传递chatId字段。
- 现象：通过免登录链接发起的对话被用户删除后，后台审计日志同步被清除，原因是未配置`LOG_PRESERVE_DELETED_CHAT`参数，默认逻辑会同步删除关联的日志记录。

## 怎么确认配好了
- 发起一次OneAPI调用，携带chatId参数与商业物业项目相关的查询内容，检查后台日志是否显示该chatId字段，确认`CHAT_LOG_INCLUDE_CHATID`配置生效。
- 创建一条包含租约分析的对话，手动删除该对话后，检查后台日志是否仍保留该对话的完整记录，确认`LOG_PRESERVE_DELETED_CHAT`配置生效。
- 上传一份商业物业的业态分析报告，等待解析完成后，检查日志是否记录了解析耗时、文件大小等参数，确认`PARSE_FILE_TIMEOUT_SECONDS`配置合理。
- 发起一次包含租金单价查询的对话，检查脱敏后的日志是否隐藏了租金单价字段，确认`LOG_AUDIT_MASK_FIELDS`配置生效。
