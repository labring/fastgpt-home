# 多元金融投研知识库建设的知识库检索与召回

## 这个品类的数据长什么样
多元金融投研的数据来源包括公开监管披露文件、第三方行业研报、机构内部投研纪要、产品募集与存续公告。更新节奏随内容类型差异，监管文件随事件触发发布，行业研报按固定周期更新，内部纪要按需生成。文档包含结构化与非结构化两类，结构化文档包含产品编码、存续规模、净值基准等字段，单位涵盖元、亿元等；非结构化文档以段落式文字为主，附带标注的标的名称、评级结论等元数据。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多源异构的数据结构要求检索召回环节同时支持向量语义匹配与关键词精确匹配的混合逻辑，避免结构化字段如产品编码的漏召回。更新节奏的差异要求支持按事件触发的增量同步机制，适配监管文件的实时更新需求，同时保留全量同步选项用于历史数据补全。标准化字段的存在需要配置针对编码、标的名称的精确匹配规则，提升特定标的相关内容的召回准确率。文档长度跨度大的特征，要求可配置的分段参数适配不同文档的内容密度，避免长文档关键信息被截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | `前10-15条` | 多元金融投研文档覆盖研报、公告、纪要等多类内容，需保证召回足够的关联信息，避免过少遗漏关键标的相关内容 |
| `相似度阈值` | `0.72-0.85` | 投研场景对内容关联度要求较高，该区间可过滤低相关的泛匹配结果，同时保留足够的有效召回内容 |
| `分段长度` | `800-1200 字符` | 多元金融文档长度跨度大，该分段长度可平衡上下文完整性与局部语义关联，适配研报与纪要的内容密度 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 长文档如完整行业研报的解析耗时较长，该时长可避免因超时导致解析失败，适配多元金融文档的体量特征 |
| `精确匹配字段` | `产品编码、标的代码` | 投研场景需精准召回特定标的的关联文档，针对标准化字段配置精确匹配可提升召回准确率 |
| `增量同步触发规则` | `按文件更新时间触发` | 多元金融数据更新节奏差异显著，按更新时间触发可精准同步最新的监管文件与研报，避免无效同步 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：无法在检索界面一次性选择多个指定文件进行检索，仅支持全库或单文件检索。原因：未开启知识库的批量检索配置，FastGPT默认检索模式未适配投研场景下按需选取部分标的关联文档的需求。
- 现象：配置飞书数据源后无法自动同步，仅能手动上传文件。原因：未配置按文件更新时间触发的增量同步规则，仅使用全量同步模式，无法适配多元金融数据的差异化更新节奏。
- 现象：检索请求返回报错，提示请求频次超限。原因：未配置检索请求的限流规则，未考虑投研场景下批量检索的高频请求特征，导致触发系统默认的频次限制。

## 怎么确认配好了
- 进入知识库的数据源管理页面，确认飞书等外部数据源的同步状态为已连接，且增量同步触发规则已设置为按文件更新时间触发。
- 输入特定标的代码进行检索，核对召回结果中是否包含该标的的关联文档，且结果条数与配置的`召回条数`一致。
- 上传一篇长度超过万字的研报文档，查看解析完成后是否被正确分段，未出现关键内容截断的情况。
- 发起多次连续检索请求，确认未返回频次超限类的报错，系统可正常处理批量检索需求。
