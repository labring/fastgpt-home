# 大气治理投研知识库建设的引用来源与溯源

## 这个品类的数据长什么样
大气治理投研的数据来源包括环境监测站实时采集数据、气象卫星遥感影像、企业排放台账、行业排放标准文档、环评批复文件等。更新节奏覆盖实时（污染物浓度数据）、每日（气象扩散数据）、季度（行业减排报告）、年度（治理成效评估文档）。文档结构包含结构化的监测点位经纬度、污染物类型、浓度数值、采集时间，以及非结构化的政策文本、项目方案，字段单位多为μg/m³、mg/m³、吨/年、立方米每秒等。

## 这些特征在「引用来源与溯源」这一环带来什么约束
多源异构的数据结构要求溯源系统需同时支持结构化数据的字段级溯源与非结构化文档的文件级溯源。实时更新的监测数据要求溯源信息绑定精确的采集时间戳，避免混淆不同时段的排放数据。特定的字段与单位要求溯源时需验证单位一致性，防止将不同标准的污染物浓度数据混淆。长段落的政策与方案文档要求分段解析时保留上下文关联，确保溯源内容与原始文档的逻辑对应。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `recall_top_k` | 前8条 | 大气治理监测数据单点位单次采集量小，需召回足够条目覆盖多维度污染物指标与关联政策 |
| `similarity_threshold` | 0.72–0.78 | 大气治理术语专业性强，阈值过低会引入无关环保政策文档，过高会遗漏同领域的监测数据与治理方案 |
| `source_trace_field` | `pollutant_type,collect_time,monitoring_point` | 按大气治理数据核心字段绑定溯源信息，确保每条召回内容的采集主体、时间与污染物类型可查 |
| `parse_chunk_size` | 1000–1200 字符 | 大气治理的排放标准文档段落较长，分段过长会导致上下文断裂，过短会拆分同一治理方案的关联内容 |
| `file_upload_max_size` | 2000 MB | 支持批量上传年度排放台账CSV包与大型环评报告PDF，适配行业数据批量导入需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：召回结果仅显示引用标识，无对应内容文本。原因：未配置`source_trace_field`绑定大气治理数据的核心元数据字段，导致解析后未生成可关联内容的溯源信息。
- 现象：在工作流中引用知识库插件后执行关联步骤时返回`400 Bad Request`错误。原因：未将大气治理台账的标准化字段映射到工作流参数，导致调用时缺失必要的溯源关联信息。
- 现象：知识库容量统计值与实际上传文档量存在偏差。原因：未启用`file_size_tracking`参数，未对结构化CSV格式的大气治理台账进行容量统计。

## 怎么确认配好了
- 上传一份标准化的大气治理监测点位CSV文件，查看解析后的元数据面板，确认`pollutant_type`、`collect_time`、`monitoring_point`字段已被自动提取并关联至溯源信息。
- 发起包含“PM2.5减排措施”的投研查询，查看返回结果的引用栏，确认每条召回内容都显示对应的监测点位、采集时间与污染物类型。
- 调整`similarity_threshold`至0.75，发起两次查询，分别验证低阈值与高阈值下的召回条数差异，确认配置生效。
- 上传一份1.8GB的年度排放台账压缩包，验证上传进度正常，且知识库容量统计面板显示准确的占用容量。
