# 工业金属投研知识库建设的对话日志与审计

## 这个品类的数据长什么样
工业金属投研数据主要来自伦敦金属交易所（LME）、上海期货交易所（SHFE）的官方行情接口，行业协会的供需分析报告，以及现货贸易商的每日报价。更新节奏覆盖多个维度：期货行情按交易时段实时更新，行业供需报告按周、月周期发布，现货报价每日更新。文档结构包含合约标识、交割标准、基准报价、结算价格、库存总量、仓单数量等字段，单位多为元/吨、吨、交易手数。

## 这些特征在「对话日志与审计」这一环带来什么约束
工业金属数据的高频更新、多维度来源与严格的字段规范，对对话日志与审计环节带来多重约束。首先，实时行情数据的快速迭代要求审计必须留存查询时的数据源快照，避免因后续数据更新导致投研结论无法追溯。其次，多周期的文档更新节奏需要审计记录对话引用的文档版本与发布时间，确保使用的是符合投研时点的有效数据。最后，统一的字段与单位要求需要审计环节自动校验对话中引用的字段合法性，防止因单位错误或字段混淆影响投研判断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `ENABLE_CHAT_LOG` | `开启` | 工业金属投研对话涉及高频行情查询，需完整留存交互记录用于审计 |
| `LOG_DATA_SNAPSHOT_ENABLE` | `开启` | 工业金属行情数据更新频繁，需保存查询时的数据源快照，避免审计时出现数据版本不一致 |
| `LOG_RETENTION_DAYS` | `180 天` | 符合投研行业合规审计的常规回溯周期，覆盖季度、半年度的投研复盘需求 |
| `AUDIT_FIELD_CHECK` | `开启` | 工业金属数据存在严格的字段与单位规范，自动校验对话中引用的字段合法性 |
| `LOG_QUERY_FILTER_FIELDS` | `合约代码、报价时间、库存数据` | 工业金属投研对话常涉及大量无关字段，配置过滤规则可减少日志冗余，便于审计聚焦核心内容 |
| `CHAT_LOG_EXPORT_FORMAT` | `CSV + JSON 双格式` | CSV格式便于人工审计，JSON格式便于自动化脚本处理审计数据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：对话日志中包含大量无关字段，审计时需要花费大量时间筛选核心内容。原因：未配置`LOG_QUERY_FILTER_FIELDS`参数，未开启日志字段过滤，导致日志冗余度过高。
- 现象：对话日志详情页未显示数据源快照，审计无法追溯查询时的行情版本。原因：未开启`LOG_DATA_SNAPSHOT_ENABLE`配置项，仅留存了对话文本未保存对应数据源的快照信息。
- 现象：多用户对话日志无法按用户ID筛选，所有用户的聊天记录混合显示。原因：未配置`MULTI_USER_LOG_SEPARATE`参数，未开启多用户日志隔离功能，导致审计无法精准定位单用户的交互记录。

## 怎么确认配好了
- 进入FastGPT系统设置的日志管理页面，查看聊天日志开关状态，确认`ENABLE_CHAT_LOG`配置项为开启。
- 发起一次工业金属行情查询，在对话日志详情页中检查是否包含数据源快照、查询时间戳与字段校验结果，确认`LOG_DATA_SNAPSHOT_ENABLE`与`AUDIT_FIELD_CHECK`配置生效。
- 尝试按用户ID筛选对话日志，确认多用户日志隔离功能正常，可精准定位指定用户的交互记录。
- 导出指定时间段的对话日志，检查导出格式是否符合配置要求，确认导出流程无超时错误。
