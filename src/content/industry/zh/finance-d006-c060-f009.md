# 工程咨询投研知识库建设的引用来源与溯源

## 这个品类的数据长什么样
工程咨询类投研数据主要来自行业官方定额手册、项目可行性研究报告、地方住建与发改部门发布的政策文件、现场踏勘记录等。数据更新节奏随类型不同有所差异，定额类按年度更新，政策类按季度或专项发布调整，项目文档随项目周期同步更新。单份文档通常包含项目编号、适用区域、造价指标、规范条款、发布文号等字段，单位涉及平方米造价、工期天数、材料单价等专业计量标准，文档结构以章节式为主，部分包含内嵌表格与附图。

## 这些特征在「引用来源与溯源」这一环带来什么约束
工程咨询数据的官方文号与发布单位属性，要求溯源环节需精准绑定对应元数据，避免混淆不同发布主体的合规内容。单份文档篇幅较长且包含专业细分内容，分段处理后需保留完整的上下文关联与元数据标识，否则溯源无法定位到具体条款。数据更新频率差异大，需在溯源环节关联最新版本的文档信息，避免引用过期内容。多字段的专业属性要求召回时需匹配对应字段，仅依赖文本关键词会出现匹配偏差，影响溯源准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `相似度阈值` | `0.6–0.7` | 工程咨询文档多为专业术语，阈值过低会引入无关内容，过高会遗漏相关合规条款 |
| `召回TopK` | `前8–12条` | 工程咨询文档单条内容较长，过多召回会超出上下文限制，过少无法覆盖多来源合规依据 |
| `分段最大长度` | `800–1200 字符` | 工程咨询文档包含大量表格和规范条款，分段过长会丢失上下文关联，过短会破坏专业表述完整性 |
| `引用来源字段` | `发布文号、发布单位、文档类型` | 工程咨询的合规性依赖官方发布渠道，需通过固定字段完成精准溯源 |
| `上下文窗口大小` | `4000–6000 字符` | 单轮投研需要整合多份可研报告和定额数据，窗口过小无法承载完整引用链 |
| `API溯源开关` | `开启` | 工程咨询项目需可追溯的合规依据，关闭后无法验证内容准确性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为知识库搜索返回结果中引用来源字段为空，原因是未配置`引用来源字段`参数，未指定需要保留的元数据字段。
- 现象为API调用返回的语料未关联溯源信息，原因是未开启`API溯源开关`，仅提取了文本内容未绑定文档元数据。
- 现象为设置`召回TopK`为10000后仍无法召回目标内容，原因是未调整`相似度阈值`，高召回上限配合过低阈值会触发冗余过滤，或目标内容的语义匹配度未达到配置阈值。

## 怎么确认配好了
- 上传一份工程咨询的定额文件，发起检索，查看返回结果中是否包含配置的`引用来源字段`内容。
- 调用知识库API接口，检查返回的语料是否附带文档元数据字段，确认溯源信息完整。
- 调整`相似度阈值`，观察召回结果的数量变化，验证配置生效。
- 上传多份同类型不同版本的工程咨询文档，确认检索结果能区分不同发布单位和文号的内容。
