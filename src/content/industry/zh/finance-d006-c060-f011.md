# 工程咨询投研知识库建设的文档解析与分块

## 这个品类的数据长什么样
工程咨询的核心数据来源于金融机构基建项目投研所需的项目可研报告、造价估算文件、招标工程量清单、行业技术规范、项目进度台账等。文档形式涵盖带官方目录的长PDF、带多级合并表头的Excel表格、结构化Word项目报告以及扫描版技术图集。数据更新节奏随项目阶段推进，可研、送审、定稿阶段会生成多版文档，行业规范每季度或年度更新。文档字段包含项目编号、造价金额（单位为元/㎡、工日、立方米等）、进度日历天、规范文号等专业信息。

## 这些特征在「文档解析与分块」这一环带来什么约束
工程咨询文档的多类型、强专业属性对解析分块提出明确约束。带目录的长PDF需按官方书签拆分章节，避免硬切破坏专业逻辑；带合并表头的Excel表格需保留层级结构，否则解析后字段映射混乱；扫描版技术图集需通过OCR识别文字并保留图表位置，否则核心技术数据丢失；大型归档文档体积较大，需适配更长的解析超时时间，避免任务中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_OCR_ENABLE` | 开启，针对扫描版文档 | 工程咨询文档包含大量扫描版技术规范、造价图纸，需通过OCR提取文字内容 |
| `PDF_PARSE_USE_BOOKMARK` | 开启 | 工程咨询PDF多带官方目录书签，按书签分块可保证章节完整性 |
| `CHUNK_SIZE` | 800–1200 字符 | 工程咨询文档含专业公式、表格与术语，过长分块会丢失上下文关联，过短会破坏专业逻辑 |
| `EXCEL_PARSE_MERGE_CELL` | 保留合并单元格层级 | 工程咨询Excel造价表多存在多级合并表头，保留层级可避免字段映射错误 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 单份数百页的工程可研PDF解析耗时较长，默认超时时间无法覆盖完整解析流程 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 单份大型项目归档文档体积可达数百兆，需适配较大的上传体积限制 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：上传Excel造价表后，向量化索引出现字段为空或单位丢失的情况。原因：未开启`EXCEL_PARSE_MERGE_CELL`配置，合并单元格的表头层级未被保留，导致解析后字段映射混乱。
- 现象：扫描版工程规范PDF上传后，解析结果无有效文字或出现大量乱码。原因：未开启`PARSE_OCR_ENABLE`配置，或未指定适配专业领域的OCR词库，无法识别工程类专业术语。
- 现象：调用API上传大型工程PDF后，解析任务提前超时。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`至600秒以上，默认超时时间不足以完成数百页文档的解析。

## 怎么确认配好了
- 上传单份扫描版工程规范PDF，验证解析结果是否包含完整可识别的专业文字，确认OCR解析配置已启用。
- 上传带多级合并表头的Excel造价明细表，验证解析后的字段是否保留原表头层级，确认Excel合并单元格解析配置已正确设置。
- 上传数百页的项目可研PDF，验证分块结果是否按文档自带目录拆分章节，确认目录识别配置已启用。
- 调用上传API时，检查请求参数是否包含对应配置项，确认API调用参数与界面配置保持一致。
