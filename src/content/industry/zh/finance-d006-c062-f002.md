# 广告营销投研知识库建设的上下文与 token

## 这个品类的数据长什么样
广告营销投研的数据来源包括广告投放后台报表、媒介监测API数据、竞品广告素材库、行业广告趋势研报、平台规则文档等。更新节奏以小时级到日级为主，部分实时投放数据为分钟级更新。文档结构通常包含投放时段、曝光量、点击量、转化成本、素材类型、投放平台、预算分配等字段，单位涵盖千次曝光、单次点击成本、金额、素材尺寸等，单份文档的字段组合密度较高，部分素材类文档还包含多模态内容的元数据。

## 这些特征在「上下文与 token」这一环带来什么约束
广告营销投研的高频实时数据、多字段高密度文档及多模态素材元数据，会对上下文与token管理带来多重约束。高频更新的数据需要频繁召回，若上下文窗口过大，会快速消耗token配额导致溢出；多字段组合的文档拆分时需保留字段关联，否则会破坏投研分析的逻辑完整性，导致分段后的上下文关联失效；多模态素材的元数据及解析后的内容会额外消耗token，若未单独限制多模态token上限，会导致上传或解析失败。此外，投研分析通常需要同时参考多组竞品与自身数据，召回条数过多会超出上下文窗口的token承载能力。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContextTokens` | 8000-10000 tokens | 适配广告投研多字段文档的单次召回总字符数，避免上下文窗口溢出 |
| `chunkSize` | 800-1200 字符 | 匹配广告投研文档的字段组合密度，避免拆分后丢失投放数据与素材信息的关联 |
| `recallTopK` | 前6-8 条 | 平衡投研分析所需的多源数据参考与上下文token占用，避免过多召回超出窗口限制 |
| `multimodalMaxTokens` | 1500-2000 tokens | 适配广告素材图片、视频片段的多模态解析需求，单独限制避免多模态内容消耗过多token |
| `uploadFileMaxSize` | 20-50 MB | 适配广告素材包包含高清图片、片段视频的文件大小，避免上传时触发token超限报错 |
| `responseMaxTokens` | 2000-3000 tokens | 满足投研分析的完整策略输出需求，同时避免响应占用过多上下文窗口 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：上传高清广告素材图片时触发上传失败，部分低分辨率图片可正常上传。原因：未配置`multimodalMaxTokens`或取值过低，高分辨率图片的多模态解析token消耗超出配置上限。
- 现象：配置`responseMaxTokens`为3500 tokens后，部分投研分析的响应长度仅为200 tokens。原因：上下文窗口中已加载的投研文档占用过多token，剩余可用token不足以支撑预设的响应上限。
- 现象：接入微信公众号云空间部署版本后，无法在接入页配置token相关参数。原因：云空间部署版本的token参数默认继承全局配置，需通过全局设置页完成修改。

## 怎么确认配好了
- 上传单份最大尺寸的广告素材包，检查系统日志中是否存在token超限相关报错，调整相关配置至符合当前场景的取值。
- 发起包含多组竞品投放数据的投研提问，核对召回的文档条数是否与`recallTopK`配置一致，确认上下文窗口未被过度占用。
- 发起长文本投研分析请求，检查响应长度是否接近预设的`responseMaxTokens`，确认上下文窗口的token分配合理。
- 查看全局配置页的`maxContextTokens`参数，确认其取值大于单次召回文档总token数与响应token数的总和。
