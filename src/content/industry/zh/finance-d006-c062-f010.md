# 广告营销投研知识库建设的数据库与运维

## 这个品类的数据长什么样
数据主要来自广告投放平台后台、第三方媒体监测工具、竞品投放素材库、行业营销白皮书及受众画像数据集。更新节奏覆盖实时（投放效果数据）、小时级（渠道流量波动）、日更（竞品素材更新）、周更（行业报告）。单条文档包含投放计划标识、媒体渠道分类、素材格式、曝光量、点击量、转化成本、投放时段、目标受众覆盖人数等字段，单位涵盖次、元、人，采用结构化键值对存储，无过度嵌套的子文档。

## 这些特征在「数据库与运维」这一环带来什么约束
实时投放数据的高频写入要求数据库具备高吞吐写入能力，避免数据堆积影响后续投研查询。多源异构数据的接入需要支持结构化指标数据与非结构化素材文件的混合存储，适配不同类型数据的存储需求。字段维度多且更新频繁，需针对常用查询字段建立复合索引，降低大范围查询的延迟。投研场景下的历史数据回溯需求，要求数据库支持按投放计划标识进行快速范围查询，同时需匹配数据更新节奏配置分层备份策略，保障不同周期的历史数据可追溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_URI` | `mongodb://admin:yourpass@mongodb-host:27017/fastgpt_marketing?authSource=admin` | 遵循标准MongoDB连接格式，适配多源营销数据接入的权限管控与数据库路由 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 覆盖主流长视频广告素材、高清图文素材的上传需求，避免大文件上传失败 |
| `RECALL_TOP_K` | `10–20` | 平衡投研查询的全面性与处理效率，避免过多召回结果增加上下文窗口压力 |
| `DB_WRITE_TIMEOUT` | `30 秒` | 匹配实时投放效果数据的写入延迟容忍度，防止高频写入场景下的连接超时 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 适配长视频广告素材的OCR与文本解析耗时，避免解析中途中断 |
| `SEARCH_SIMILARITY_THRESHOLD` | `0.75–0.85` | 过滤低相关的竞品素材或行业报告片段，提升投研结果的精准匹配度 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：Windows 10本地部署MongoDB后，连接时返回`Connection refused`错误。原因：未开放MongoDB默认端口27017的系统防火墙权限，或`MONGODB_URI`配置中未正确指定本地主机地址与认证参数。
- 现象：投研对话历史无法在MongoDB的`chat_histories`集合中查询到对应数据。原因：未开启`ENABLE_CHAT_HISTORY`配置项，或数据库用户未被授予`chat_histories`集合的写入权限。
- 现象：工具调用时，知识库召回结果条数与配置的`RECALL_TOP_K`不符，且返回结果相关性偏差较大。原因：未同步更新知识库的召回阈值配置，或同时开启了多级过滤规则导致有效匹配结果被提前剔除。

## 怎么确认配好了
- 执行`mongo`命令连接配置的`MONGODB_URI`，验证数据库连接是否正常，根据返回的连接状态调整防火墙与权限配置。
- 上传单份符合`UPLOAD_FILE_MAX_SIZE`限制的广告素材文件，检查上传进度与解析状态，确认文件存储与解析流程无异常。
- 发起一条包含投放指标查询的投研对话，检查返回结果的召回条数是否与配置的`RECALL_TOP_K`匹配，根据匹配结果调整相似度阈值。
- 查看数据库监控面板，确认写入操作的延迟低于配置的`DB_WRITE_TIMEOUT`值，验证高频写入场景下的吞吐能力。
