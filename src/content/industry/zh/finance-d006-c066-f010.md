# 房建工程投研知识库建设的数据库与运维

## 这个品类的数据长什么样
房建工程投研的数据来源涵盖项目施工图PDF、造价清单Excel、施工日志文档、材料质检报告、标段结算文件等。更新节奏随项目阶段触发，地基、主体、装饰等关键节点会同步更新对应阶段的文档，同时材料价格数据按月度更新。单份文档结构包含项目编号、标段名称、施工部位、材料型号、检测数值、造价明细等字段，单位涉及平方米、立方米、吨、元/平方米、毫米等，部分半结构化文档存在字段嵌套与单位不统一的情况。

## 这些特征在「数据库与运维」这一环带来什么约束
房建工程数据的多源异构特性要求数据库支持多格式解析与灵活的schema映射，避免结构化数据导入时出现格式错位。非固定周期的更新节奏需要配置增量同步机制，平衡实时性与服务器资源占用。文档体积差异较大，单份施工图可达数百MB，需适配大文件上传与解析。字段与单位的不统一特性，要求数据库运维环节增加标准化校验与映射规则，确保检索结果的一致性。同时多工程师同时发起投研查询的场景，对数据库并发处理能力提出了更高要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_MAX_SIZE` | `1000 MB` | 房建施工图PDF单份可达数百MB，超大文件需放宽解析限制 |
| `UPLOAD_CHUNK_SIZE` | `8 MB` | 房建文档多为大文件，分块上传可避免单次上传超时 |
| `DB_CONNECTION_TIMEOUT` | `300 秒` | 跨服务器拉取造价数据库时，复杂查询耗时较长，需延长超时阈值 |
| `RECALL_TOP_K` | `10–15 条` | 房建投研需兼顾全面性与检索效率，过多结果会增加后续处理负担 |
| `SQL_SERVER_ENABLED` | `开启` | 行业存量数据多存储于SQL Server数据库，需兼容对接 |
| `INCREMENTAL_SYNC_INTERVAL` | `1 小时` | 房建项目数据更新无固定周期，增量同步可平衡实时性与资源占用 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：API调用返回`503 Service Unavailable`状态码，且日志显示数据库连接池耗尽。原因：未针对房建项目多并发查询的场景配置连接池上限，导致大量请求抢占数据库资源。
- 现象：无法定位检索结果对应的数据源表，查询时返回“未找到关联表元数据”的报错。原因：未为房建项目的结构化文档配置表级元数据映射，导致无法关联原始数据库表。
- 现象：无法通过插件调用指定SQL Server数据库的表数据。原因：未开启`SQL_SERVER_ENABLED`配置项，或未正确配置数据库连接字符串中的实例名与访问权限。

## 怎么确认配好了
- 上传一份单份超过500MB的房建施工图PDF，验证解析任务未触发超时报错，确认`PARSE_FILE_MAX_SIZE`配置符合业务需求。
- 发起10次以上并发的API检索请求，观察数据库连接池状态，确认连接池上限配置可支撑业务峰值。
- 配置SQL Server数据库连接插件，尝试查询存量造价清单表，验证可正常返回结构化数据，确认连接参数正确。
- 导入一份包含单位不统一的材料数据文档，验证系统自动完成单位标准化转换，确认字段映射规则生效。
