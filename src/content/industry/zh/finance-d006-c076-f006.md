# 文娱用品投研知识库建设的对话日志与审计

## 这个品类的数据长什么样
文娱用品投研数据主要来自供应链台账、行业研报、电商销售监测及专利合规文档。更新节奏随新品上市、季度财报发布、电商大促节点波动，日常按周或月迭代。文档结构以图文结合为主，供应链类文档包含SKU编号、材质、单价、产能、合规认证编号等字段，单位涵盖件、元、台、平方米等，部分长文档包含多组对比表格。

## 这些特征在「对话日志与审计」这一环带来什么约束
文娱用品投研数据的多字段、高频更新及多源特性，对对话日志与审计带来多重约束。需精准记录SKU编码与对应数据的更新时间，确保审计时可溯源具体投研结论的数据源。高频更新要求日志保存周期匹配数据迭代节奏，避免审计时无法调取对应周期的历史数据。长文档与多组参数的引用，要求日志需过滤冗余上下文，同时保留核心查询与响应内容，防止日志存储过载。多源接口调用则要求完整记录报错信息与请求参数，便于排查数据获取异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `CHAT_RECORD_EXPIRE_DAYS` | `30–90 天` | 文娱用品投研数据更新周期多为月度至季度，审计需覆盖至少一个完整的数据迭代周期 |
| `MAX_CONTEXT_SAVE_LENGTH` | `1000 字符` | 文娱用品研报常包含长表格与SKU参数，过长上下文会增加日志存储与检索成本 |
| `AUDIT_REQUIRED_FIELDS` | `["query", "response", "sku_code", "data_update_time"]` | 需溯源具体SKU的查询请求与对应数据的更新时间，满足合规审计要求 |
| `LOG_ERROR_THRESHOLD_MS` | `600 毫秒` | 文娱用品数据多来自多源供应链接口，超时报错需完整记录以排查数据获取异常 |
| `CHAT_LOG_SAMPLING_RATE` | `15%` | 投研对话量较大，抽样覆盖核心SKU查询可平衡审计成本与覆盖范围 |
| `ENABLE_AUDIT_ALERT` | `开启` | 针对SKU异常查询、日志缺失等情况触发告警，及时修正投研数据调用问题 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用供应链接口后返回`500 Internal Server Error`，但日志仅记录通用报错信息，无具体请求参数。原因：未配置`AUDIT_REQUIRED_FIELDS`包含接口请求参数，导致审计无法定位报错根源。
- 现象：本地部署后发现超过设定天数的对话日志全部丢失。原因：误将`CHAT_RECORD_EXPIRE_DAYS`设置为过短的周期，未匹配文娱用品投研数据的审计要求。
- 现象：对话日志中SKU字段为空，无法关联对应投研数据。原因：未在对话配置中要求AI返回SKU编码，或未开启日志自动抓取预设字段的功能。

## 怎么确认配好了
- 进入系统日志管理界面，查看`CHAT_RECORD_EXPIRE_DAYS`的配置值，确认其匹配文娱用品投研数据的审计周期。
- 发起一条包含具体SKU编码的投研查询，核对日志中是否包含预设的核心字段。
- 模拟一次超出阈值的接口请求，检查日志是否完整记录报错信息与请求参数。
- 触发一次异常查询，确认审计告警功能是否正常触发。
