# 水产养殖投研知识库建设的知识库检索与召回

## 这个品类的数据长什么样
水产养殖投研数据来源包括现场养殖终端采集的塘口监测数据、行业协会公开的养殖技术文档、卫星遥感的水域环境影像、养殖企业内部的日志记录。数据更新节奏存在差异：现场监测数据每日更新，行业技术文档按季度更新，遥感影像按周更新。单篇文档多为结构化参数集合或非结构化技术说明文本，包含塘口ID、养殖周期起始日期、水温、溶氧量、pH值、饲料投喂量等字段，其中水温单位为摄氏度，溶氧量单位为毫克每升，饲料投喂量单位为千克。

## 这些特征在「知识库检索与召回」这一环带来什么约束
多来源且更新节奏差异大的数据，要求检索系统支持按数据类型配置不同的更新周期，避免陈旧数据混入实时查询结果。文档包含结构化监测字段与非结构化技术文本，需要针对不同文档类型设置差异化的分段规则，避免长文本分块破坏结构化字段的语义关联。水产养殖数据存在严格的单位规范，检索时需统一单位转换逻辑，防止因单位不匹配导致召回结果偏差。实时性较强的塘口监测数据，要求召回链路支持低延迟的增量检索，以保障查询结果的时效性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `ENABLE_DOCX_IMAGE_OCR` | 开启 | 水产养殖文档常包含塘口水质监测实拍图、病害症状照片，开启后可提取图片中的文字信息用于检索 |
| `maxContext` | 800–1200 字符 | 水产养殖单篇监测文档多为结构化参数集合，过长的上下文会引入无关字段，该区间可保留核心参数与关联技术说明 |
| `召回条数` | 前 6–8 条 | 水产养殖检索需求多为精准匹配塘口参数或特定病害方案，少量精准召回可避免结果冗余 |
| `相似度阈值` | 0.72–0.80 | 养殖数据字段关联性强，较低的阈值会引入不匹配的塘口数据，该区间可平衡召回精度与覆盖范围 |
| `知识库最大引用` | 前 3–4 条 | 单条查询涉及的养殖场景参数有限，少量引用可确保回答聚焦当前塘口或病害问题 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 秒 | 水产养殖文档常包含多张高清监测图片，OCR处理耗时较长，该时长可避免大型文档解析超时 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：AI生成的回答末尾固定携带未在知识库中出现的系统介绍文案。原因：未配置专属系统提示词，或未覆盖平台默认的内置介绍文本。
- 现象：使用Docker Compose部署后，重启容器导致知识库与工作流配置丢失，但API接口可正常响应请求。原因：未将数据库存储目录映射到宿主机持久化路径，容器重启后临时存储的数据被清空。
- 现象：上传包含塘口监测实拍图的docx文档后，检索结果未覆盖图片中的文字信息。原因：未开启`ENABLE_DOCX_IMAGE_OCR`配置项，未对docx内的图片执行OCR文本提取。

## 怎么确认配好了
- 上传包含塘口水质监测实拍图的docx文档，等待解析任务完成后，检索“塘口溶氧量”关键词，确认召回结果包含文档内容。
- 配置专属系统提示词后，发起测试查询，检查生成的回答末尾未携带未预设的固定文案。
- 调整`相似度阈值`参数，发起多组不同精准度要求的查询，核对召回结果的匹配精度符合当前业务需求。
- 查看数据库持久化目录的文件修改记录，确认知识库增量更新任务按预设节奏执行。
