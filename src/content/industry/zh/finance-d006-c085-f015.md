# 水泥投研知识库建设的部署与升级

## 这个品类的数据长什么样
水泥行业投研数据主要来自中国建筑材料联合会发布的行业运行通报、水泥生产企业公开财报、熟料生产线实时监测平台及地方住建部门的建材需求数据。数据更新节奏存在差异：出厂价格、窑炉运转率等实时指标按日更新，行业产能、区域库存数据按月更新，年度行业白皮书按季度或年度发布。文档结构以结构化表格为主，包含水泥标号（如P.O42.5、P.C32.5）、产地、出厂单价、库存量、单位能耗等字段，单位涵盖元/吨、万吨、千瓦时/吨等。

## 这些特征在「部署与升级」这一环带来什么约束
水泥投研数据的多源异构特性要求部署阶段需配置多数据源同步任务，适配不同更新频率的定时调度规则。实时类数据的高频接入需求，要求部署时预留专用端口用于数据拉取，升级过程中需避免中断实时同步链路，否则会导致最新价格、运转率数据缺失。结构化字段多且细分品类明确的特征，要求知识库向量库需支持多字段联合索引，升级时需同步更新索引规则，否则会降低细分品类的召回精度。此外，大型行业报告的单篇体积较大，部署时需调整文件处理的资源阈值，避免批量上传时触发系统限流。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 水泥行业研报、大型产能报表单篇长度较长，需足够时间完成解析 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 适配大型行业白皮书、季度产能统计报表的上传需求 |
| `RECALL_TOP_N` | 前 8 条 | 水泥数据细分参数较多，需覆盖足够多的维度以匹配精准需求 |
| `SIMILARITY_THRESHOLD` | 0.75–0.85 | 平衡召回精度与覆盖范围，避免冗余结果或漏匹配细分品类 |
| `ONEAPI_BASE_URL` | 本地部署的 oneapi 服务地址加端口 | 离线部署场景下需调用本地大模型接口，避免依赖公共网络 |
| `NEXT_PUBLIC_DISABLE_LOGIN` | false | 4.8.15 及以上版本支持配置身份验证开关，需开启后配置用户权限 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用大模型返回500状态码，界面提示“上游服务不可用”。原因：未正确配置`ONEAPI_BASE_URL`，使用了默认的公共地址，未使用本地离线部署的oneapi服务地址。
- 现象：批量上传水泥行业文档时，部分长财报解析失败，状态显示“超时”。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`，沿用默认的较短超时值，无法处理长文档解析。
- 现象：知识库召回结果中细分水泥品类匹配度低，结果条数不符合预期。原因：未根据水泥数据的细分特性调整`SIMILARITY_THRESHOLD`和`RECALL_TOP_N`的取值，导致过滤过严或召回覆盖不足。

## 怎么确认配好了
- 访问`ONEAPI_BASE_URL`对应的接口地址，测试接口连通性，确认配置的地址与本地部署的oneapi服务一致。
- 上传一篇单篇长度超过5000字符的水泥行业研报，查看解析状态，确认解析任务未触发超时。
- 发起一次知识库召回测试，输入细分水泥品类关键词，核对召回结果的条数与匹配度，确认配置的`RECALL_TOP_N`和`SIMILARITY_THRESHOLD`符合预期。
- 查看系统版本信息，确认当前运行的版本为4.8.15及以上，验证身份验证配置模块已加载。
