# 涂料油墨投研知识库建设的上下文与 token

## 这个品类的数据长什么样
数据主要来自中国涂料工业协会公开报告、原材料供应商官方报价系统、上市涂料企业年度/季度财报、合规检测机构出具的性能检测报告。更新节奏：原材料价格类数据周度更新，行业政策与合规标准每季度更新，企业产品配方与性能参数按需更新。文档结构多为结构化表格（含产品型号、原材料配比、粘度、耐候等级等字段）、PDF格式的检测报告、Excel格式的供应链数据。字段与单位包括：粘度（cps）、固含量（%）、附着力（MPa）、保质期（月）、原材料采购价（元/吨）等。

## 这些特征在「上下文与 token」这一环带来什么约束
结构化表格多字段的文档，单条内容的token占用量高于通用文本，若召回多条关联文档，易超出模型上下文token上限。原材料价格类数据周度更新的特性，要求上下文召回需关联最新的知识库版本，若未配置版本绑定的上下文召回逻辑，会召回过时数据影响投研准确性。长文档的PDF检测报告拆分时，若未保留表格结构完整性，会导致上下文信息断裂，同时增加无效token消耗。不同文档间存在单位差异的字段，需额外的语义对齐处理，进一步占用token配额。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 涂料油墨投研文档单条chunk常含多字段参数，8000–12000字符可覆盖3-5条完整的原材料价格或性能参数条目，避免超出模型token上限 |
| `chunkSize` | `1000–1500 字符` | 结构化表格的单页内容约1000字符，拆分后可保留表格完整性，减少无效token消耗 |
| `similarityTopK` | `前 3–5 条` | 单条涂料油墨文档token占用较高，过多召回会超出上下文配额，同时保证召回信息的相关性 |
| `rerankTopN` | `前 2–3 条` | 重排步骤仅需筛选最相关的投研数据，过多会增加token消耗与处理延迟 |
| `PARSE_TABLE_STRICT` | `开启` | 强制保留结构化表格的完整格式，避免拆分后表格信息断裂，减少无效token消耗 |
| `contextRefreshInterval` | `7 天` | 匹配原材料价格数据周度更新的节奏，保证上下文召回的时效性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中调用工具节点时返回`Invalid JSON: Bad control character`错误。原因：未对涂料油墨文档中的特殊字符（如表格内的换行符、单位符号）做转义处理，导致生成的上下文JSON格式异常。
- 现象：AI聊天返回的投研结果中出现单位不一致的参数（如同时出现cps和mPa·s）。原因：未配置字段单位对齐的上下文预处理逻辑，召回的不同文档参数未统一单位，导致token消耗增加且信息混乱。
- 现象：配置`maxContext`为16000字符后，模型返回上下文超出限制的报错。原因：未考虑涂料油墨单条文档的token占用量高于通用文本，16000字符的上下文实际占用超过模型的token上限。

## 怎么确认配好了
- 上传一份典型的涂料油墨原材料报价文档，查看解析后的chunk是否保留了表格结构，无信息断裂。
- 发起一次投研查询，核对返回的上下文内容的单位是否统一，无格式混乱。
- 查看知识库的刷新日志，确认原材料价格类数据按设定的间隔自动更新。
- 测试工具节点调用，确认生成的上下文JSON无格式错误，无控制字符导致的解析失败。
