# 消费建材投研知识库建设的部署与升级

## 这个品类的数据长什么样
消费建材的数据源涵盖厂商公开的产品检测报告、行业协会季度调研数据、招投标平台实时中标信息、终端零售动销报表。文档结构差异明显：产品检测报告多为结构化表格，含厚度、抗压强度、环保等级等参数，单位多为mg/m³、MPa；招投标公告含项目地点、预算、中标单位等文本字段；动销报表按区域、SKU、销量分类。数据更新节奏不同：新品检测报告随产品上线更新，招投标信息实时发布，行业调研数据按季度更新。

## 这些特征在「部署与升级」这一环带来什么约束
多源异构的文档格式要求部署时适配多种解析引擎，分别处理结构化表格、长文本公告和分类报表。不同数据源的更新频率差异，要求升级时调整增量同步任务的间隔配置，避免同步频率过高浪费资源或过低导致数据滞后。专属的字段与单位要求预设元数据映射规则，防止解析时出现单位混淆或字段缺失。长文档占比高的情况，要求升级时优化分段与召回的参数阈值，避免上下文截断导致信息丢失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 消费建材的招投标公告常附带多张CAD图纸或检测报告附件，单文件体积可能超过通用上限 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `900 秒` | 大型批量招投标文档或多页检测报告的解析耗时较长，避免中途强制终止解析 |
| `maxContext` | `8000–12000 字符` | 消费建材产品参数常包含多组关联数据，足够的上下文可保留完整的参数逻辑链 |
| `召回条数` | `前 8–12 条` | 投研需覆盖产品、招投标、动销等多维度数据，数量过多会导致上下文过载，过少则信息不全 |
| `相似度阈值` | `0.72–0.78` | 消费建材SKU相似度较高，阈值过低会召回无关竞品数据，过高则遗漏有效关联信息 |
| `增量同步间隔` | `5 分钟–1 小时` | 不同数据源更新频率差异大，招投标实时数据用5分钟间隔，行业调研数据用1小时间隔 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：阿里云RDS数据库连接失败，返回错误码1045或2003。原因：未将FastGPT部署节点的公网IP或容器网络段添加至RDS实例的白名单配置中。
- 现象：解析消费建材的PDF检测报告时，出现环保等级、抗压强度等专属字段为空的情况。原因：未配置针对建材行业的专属解析规则，通用解析引擎无法识别行业专属字段与单位。
- 现象：升级至v4.8.20-fix版本后，自定义的增量同步配置未生效，日志提示无法读取配置文件。原因：未将旧版`config.json`中的配置迁移至新版的环境变量或可视化配置界面，部分新版版本不再自动加载本地config.json文件。

## 怎么确认配好了
- 上传一份典型的消费建材检测报告PDF，查看解析后的字段是否包含厚度、抗压强度、环保等级等专属参数，核对字段单位是否符合行业规范。
- 配置阿里云RDS连接后，执行数据库连通性测试，查看是否能正常读写预设的建材知识库元数据表。
- 启动增量同步任务，查看是否能自动拉取最新的招投标公告或动销数据，核对同步日志中的数据源匹配情况。
- 调用知识库检索接口，输入行业专属检索词，查看返回结果的数量与相关性符合预设配置。
