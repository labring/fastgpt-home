# 炼化投研知识库建设的数据库与运维

## 这个品类的数据长什么样
炼化投研的数据来源包括勘探开发技术报告、炼化装置工艺规程、原油质检批次数据、成品油出厂指标文档、行业供需分析周报，以及实时采集的装置运行参数。更新节奏差异较大，静态的工艺手册、规程类文档更新频率较低，批次质检数据随生产周期更新，实时运行参数按秒级推送，行业周报按周更新。文档格式包含PDF格式的长文本技术文档、CSV格式的结构化质检数据、API接口推送的实时时序数据，字段包含装置负荷、原油密度、产品辛烷值等，附带明确的单位标识。

## 这些特征在「数据库与运维」这一环带来什么约束
长文本技术文档占比高，需要支持大容量非结构化数据存储与高效分词索引。结构化的批次质检数据与实时运行参数需要强一致性的事务处理与高并发写入能力。多类数据源带来的元数据复杂度提升，需要统一的字段与单位管理机制。备份恢复时需兼顾非结构化文档与结构化数据库元数据，单一的文件备份无法覆盖完整的知识库状态。实时数据的高频写入与历史文档的批量检索并存，需要合理配置数据库连接池与并发处理策略。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 炼化工艺文档通常篇幅较长，单次解析耗时较长，避免超时中断解析任务 |
| `UPLOAD_FILE_MAX_SIZE` | 2000 MB | 包含完整装置流程图与长段落描述的PDF文档体积较大，允许更大的单文件上传上限 |
| `MAX_CHUNK_LENGTH` | 1500–2000 字符 | 炼化技术文档包含长段落的工艺描述，拆分后保留足够上下文用于投研场景的精准检索 |
| `DB_CONNECTION_POOL_SIZE` | 32 | 兼顾实时运行参数写入和历史文档检索的并发需求，避免连接耗尽导致任务失败 |
| `RECALL_TOP_K` | 10–15 | 炼化投研需覆盖工艺参数、行业报告、质检数据等多类信息，召回数量过少会导致检索覆盖不足，过多会增加检索延迟 |
| `BACKUP_RESTORE_STRATEGY` | 全量文件备份+PG数据库元数据增量备份 | 兼顾非结构化文档与结构化知识库元数据的恢复完整性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：执行知识库问答拆分时报错`Invalid array length`，必现。原因：恢复备份时仅导入了项目文件，未同步恢复PG数据库的知识库元数据数组字段，导致字段为空引发校验失败。
- 现象：批量导入结构化质检数据或实时运行参数时，出现数据库连接耗尽报错。原因：未调整数据库连接池大小，并发写入任务占用过多连接，导致索引构建等核心任务无法获取数据库连接。
- 现象：通过docker部署修改数据库或服务密码后，重启容器无法生效。原因：未通过docker启动命令的环境变量或挂载的配置文件传入新密码，直接修改容器内配置文件会在容器重启后被还原。

## 怎么确认配好了
- 上传单份体积超过1000MB的炼化工艺PDF文档，检查解析任务无超时报错。
- 批量导入100条结构化质检数据，确认数据库写入无连接耗尽报错。
- 执行知识库问答拆分操作，检查无`Invalid array length`类字段校验报错。
- 修改数据库连接密码后重启服务，确认可正常连接数据库并检索知识库内容。
