# 焦炭投研知识库建设的对话日志与审计

## 这个品类的数据长什么样
焦炭相关数据主要来自国内期货交易所实时行情、中国炼焦行业协会月度产能库存报告、沿海港口现货报价系统及第三方行业研报。实时行情数据按分钟更新，现货报价每日更新，行业月度报告于每月5日前发布。数据文档包含结构化行情表，字段包含交易日期、结算价、持仓量（单位：元/吨、手），库存数据字段包含港口库存、钢厂库存（单位：万吨），同时配套非结构化的行业分析文档，包含供需逻辑、政策解读内容。

## 这些特征在「对话日志与审计」这一环带来什么约束
实时行情的分钟级更新要求对话日志记录调用时刻的精确时间戳至秒级，并留存对应数据的快照版本，避免审计时无法匹配调用时的实际行情。结构化数据包含多单位字段，日志需完整记录字段名与对应单位，确保审计时可还原数据的真实含义。混合结构化与非结构化数据的召回场景，日志需区分召回类型，分别记录结构化数据的字段ID与非结构化文档的唯一标识。产业链关联数据较多，日志需额外记录上下游关联数据源的溯源ID，方便跨环节审计追溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `LOG_RECORD_LEVEL` | `info` 及以上级别 | 焦炭投研对话需完整覆盖用户提问、数据召回、模型响应全流程，info级别可留存足够审计所需的上下文信息 |
| `LOG_SNAPSHOT_ENABLE` | `开启` | 实时行情数据按分钟更新，开启快照可留存调用时刻的精确数据版本，满足审计追溯需求 |
| `LOG_EXPIRE_DAYS` | `180 天` | 金融合规要求留存至少半年的操作记录，匹配焦炭投研的审计周期需求 |
| `MONGO_LOG_COLLECTION_PREFIX` | `fastgpt_coke_research_` | 区分焦炭品类与其他行业的日志集合，避免跨品类数据混淆，便于单独检索审计 |
| `LOG_RECALL_DATA_DETAIL` | `开启` | 焦炭数据包含多单位结构化字段，开启后可完整记录召回字段名、数值与单位，还原审计场景的真实数据 |
| `LOG_ERROR_STACK_ENABLE` | `开启` | 投研场景对问题排查要求较高，完整错误堆栈可快速定位日志异常与调用失败原因 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：MongoDB 中无法检索到焦炭投研应用的对话日志，查看详情页仅显示基础会话信息。原因：未配置`MONGO_LOG_COLLECTION_PREFIX`，或配置的前缀与实际写入集合的前缀不匹配，导致日志写入错误集合。
- 现象：对话日志中未留存实时行情的快照数据，审计时无法匹配调用时刻的焦炭结算价。原因：未开启`LOG_SNAPSHOT_ENABLE`，导致仅记录了数据索引，未记录具体数值快照。
- 现象：对话详情页无法查看用户修改备注、查看历史记录的操作日志。原因：未开启`LOG_RECALL_DATA_DETAIL`，未记录用户交互中的自定义操作上下文，导致详情页无对应内容。

## 怎么确认配好了
- 登录MongoDB管理控制台，检索前缀为`fastgpt_coke_research_`的集合，确认存在对话日志数据。
- 发起一次焦炭投研相关的对话，查看对话详情页，确认已记录用户提问、召回的焦炭数据字段与模型响应内容。
- 查看后台配置界面，确认`LOG_SNAPSHOT_ENABLE`与`LOG_RECALL_DATA_DETAIL`均处于开启状态。
- 模拟调用失败场景，确认日志中已记录完整的错误堆栈信息与调用上下文。
