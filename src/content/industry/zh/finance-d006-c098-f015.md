# 煤化工投研知识库建设的部署与升级

## 这个品类的数据长什么样
煤化工投研数据主要来自煤炭工业行业协会公开报告、煤化工企业公开财报、焦炉及气化炉工况实时监测数据、大宗商品行情平台、专利及环评公开文档。数据更新节奏差异较大：行业产能、政策类数据按季度更新，产品现货价格按日更新，工况监测数据为分钟级更新。文档包含结构化产能台账、长文本研报、半结构化工况参数表，字段含产品牌号、设计产能、实际运行负荷、单位产品能耗，单位多为万吨/年、元/吨、千瓦时/吨标准煤。

## 这些特征在「部署与升级」这一环带来什么约束
煤化工投研数据的多源异构、更新节奏差异大、字段单位特定的特征，对部署与升级环节带来多重约束。多源数据包含结构化台账、实时工况数据与长文本研报，部署时需配置适配不同解析格式的预处理流水线，升级时需兼容新增的数据源类型。不同更新频率的数据需差异化同步策略，部署时需预设调度规则，升级时需支持动态调整同步间隔以适配业务变化。特定的字段与单位要求部署时配置标准化映射规则，升级时需兼容新增的煤化工细分产品字段，避免数据解析异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 长文本行业研报及结构化产能台账的解析需较长处理时间，避免超时中断任务 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 包含多页结构化数据的大型煤化工研报文件通常不超过该阈值，满足全量文档上传需求 |
| `chunkSize` | `1000–1200 字符` | 平衡长文本语义完整性与向量召回精度，适配煤化工行业研报的段落结构特征 |
| `RECALL_TOP_N` | `前 10 条` | 覆盖不同数据源的有效信息，避免遗漏细分工况、产品价格等关键投研数据 |
| `CLICKHOUSE_CONNECTION_POOL_SIZE` | `10–15` | 适配煤化工实时工况数据的并发查询需求，避免连接池耗尽导致检索失败 |
| `RE_RANK_TOP_N` | `前 3 条` | 聚焦核心煤化工产品的关键信息，提升最终检索结果的相关性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 从4.8.17升级到4.8.20启动容器后执行初始化脚本返回`exit code 1`报错。原因是新版本的数据库初始化脚本新增了对Clickhouse连接参数的校验，未提前配置对应环境变量导致校验失败。
- 接入SearXNG后测试检索无结果，后台返回`504 Gateway Timeout`错误。原因是未调整SearXNG的查询超时参数，煤化工行业多源数据的跨源检索需更长响应时间，默认超时设置不足以覆盖全量数据源请求。
- 配置Clickhouse数据源后无法召回历史工况数据，检索结果中煤化工相关字段为空。原因是未配置标准化字段映射规则，未将Clickhouse中的`product_brand`、`operating_load`等字段映射为知识库可识别的统一字段，导致数据无法被正确索引。

## 怎么确认配好了
- 上传一份包含结构化产能台账的煤化工研报，检查解析后文本的字段完整性，确认所有预设的映射字段均被正确提取。
- 执行一次手动数据同步任务，查看同步日志中是否存在连接超时或解析失败类错误，确认数据源同步链路正常。
- 发起一次针对煤化工产品的检索测试，检查返回结果的召回条数是否符合预设的召回配置，无异常报错。
- 启动容器并执行初始化脚本，确认脚本执行返回`exit code 0`，无参数校验类报错。
