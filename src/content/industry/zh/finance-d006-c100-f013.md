# 物业管理投研知识库建设的知识库检索与召回

## 这个品类的数据长什么样
物业管理投研的数据来源包括在管项目的运维台账、业主报修工单档案、物业项目运营月报、行业监管政策文件、物业服务合同范本。更新节奏为：日常运维记录每日同步，项目月报每月更新，合同与政策文件按需更新。文档结构分为三类：单条工单详情（含楼宇编号、运维区域、故障类型）、批量运营报表（按项目维度汇总）、政策与合同类结构化文档。字段包含楼宇ID、处理耗时、报修频次、服务等级，单位为小时、平方米、次。

## 这些特征在「知识库检索与召回」这一环带来什么约束
单条运维工单的短文本与批量运营报表的长文本混合输入，要求检索链路适配不同长度的内容，避免短文本被截断或长文本超出上下文限制。每日更新的运维记录需要增量同步机制，降低全量索引的资源占用。楼宇编号、运维区域这类精准属性字段，需要支持属性过滤检索，不应仅依赖语义匹配。物业项目的地域属性明确，需按属地维度过滤召回结果，适配不同区域的服务标准与政策要求。细分故障类型标签需绑定专属检索权重，提升同类型有效工单的召回匹配度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | `前8–12条` | 物业管理投研数据包含工单、报表等多类型内容，8-12条可覆盖常见检索场景的信息需求，避免过多结果干扰判断 |
| `相似度阈值` | `0.72–0.80` | 物业工单的故障描述存在大量同义表述，阈值过低会引入无关结果，过高则可能遗漏同类型有效工单 |
| `分段长度` | `800–1200 字符` | 批量运营报表的单页内容较长，分段长度适配报表的段落结构，避免跨段落丢失上下文关联 |
| `增量同步间隔` | `每6 小时` | 日常运维记录的更新频率为每日，每6小时增量同步可平衡实时性与索引资源占用 |
| `属性检索开关` | `开启` | 楼宇编号、运维区域等精准字段可通过属性检索快速过滤无关结果，提升检索效率 |
| `重排返回条数` | `前3–5条` | 投研场景需要精准结果，重排后返回3-5条可帮助快速定位核心信息 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：检索返回的工单结果与实际故障类型不匹配，答案不准确。原因：未开启`属性检索开关`，仅依赖语义匹配导致楼宇、区域等关键维度未被过滤。
- 现象：全局变量中「选择知识库」的动态赋值未生效，检索范围超出指定项目。原因：未将动态变量绑定至知识库筛选规则，或变量传递的参数格式不符合接口要求。
- 现象：上传运维台账文件时显示上传失败。原因：未调整`UPLOAD_FILE_MAX_SIZE`参数，单个台账文件大小超出平台限制，或文件格式未被支持。

## 怎么确认配好了
- 检索指定楼宇编号的工单，核对返回结果是否仅包含该楼宇的内容，确认属性检索开关生效。
- 上传一份测试用的运维报表，核对分段后的文本块是否符合设定的`分段长度`范围。
- 触发增量同步任务，核对索引日志中仅显示新增的运维记录，确认增量同步配置正确。
- 模拟全局变量动态赋值，检索指定项目的知识库，核对返回结果是否限定在该项目范围内。
