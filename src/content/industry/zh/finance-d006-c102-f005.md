# 特钢投研知识库建设的多轮对话与提示词

## 这个品类的数据长什么样
特钢投研的数据主要来自中国特钢企业协会公开报告、钢厂出厂价台账、海关进出口报关系统、现货市场报价平台。更新节奏分为三类：出厂价台账每日更新，行业供需报告按月度或季度发布，海关数据按周度滞后更新，现货报价实时更新。文档结构包含结构化报表（含牌号、规格、产地、吨价、库存量等字段）、非结构化研报（含政策解读、供需分析）、报关单文档（含HS编码、进出口数量、原产国等字段），字段单位统一使用毫米、元/吨、天等标准工业单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
实时更新的现货价与出厂价要求多轮对话必须优先召回最新文档，避免使用过期数据；多结构文档需要提示词区分结构化报表与非结构化研报的解析逻辑，确保字段提取的准确性；多字段的结构化数据要求多轮对话中保留上下文的牌号、规格等关键信息，避免跨轮匹配错误；单位的严格要求需要提示词强制统一使用元/吨等标准单位，防止数据混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 特钢数据包含多字段的结构化内容，多轮对话需保留用户指定的牌号、规格等关键上下文，避免信息丢失 |
| `RECALL_TOP_N` | `前8–12 条` | 特钢的规格与牌号绑定紧密，过多召回会导致上下文过载，过少则无法覆盖相关数据条目 |
| `PARSE_STRUCTURED_TABLE_MAX_ROWS` | `500 行` | 特钢出厂价报表通常包含数百条规格数据，需完整解析结构化内容以保留完整的字段关联 |
| `SIMILARITY_THRESHOLD` | `0.75–0.85` | 特钢的牌号与规格有强匹配要求，阈值过低会引入其他品类钢材的无关数据，过高则无法召回有效内容 |
| `CHUNK_SIZE` | `600–800 字符` | 特钢的结构化文档拆分后需保留完整的规格-价格对应关系，避免拆分破坏字段关联 |
| `PROMPT_TEMPLATE` | 按用户指定的特钢牌号、规格匹配对应数据，优先使用最新更新的文档，统一使用元/吨作为价格单位 | 特钢的价格与规格绑定紧密，需明确数据时效性与单位标准，避免返回错误信息 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：上传特钢的出厂价报表后，发起统计总结对话时，模型未使用上传文件中的数据。原因：未将上传文件加入知识库绑定的向量库，或未配置结构化文档的解析规则导致数据未被正确拆分入库。
- 现象：使用本地部署的大模型搭配特钢知识库进行多轮对话时，出现`504 Gateway Timeout`错误或响应延迟超过30秒。原因：召回条数设置过高，或未启用上下文缓存机制，导致每次对话都重新检索全量特钢数据。
- 现象：多轮对话中，模型返回的特钢规格与价格不匹配，或混用了不同牌号的数据。原因：提示词未明确限定匹配特钢的牌号与规格字段，上下文窗口设置过小导致丢失了首轮对话中指定的关键信息。

## 怎么确认配好了
- 上传一份特钢出厂价报表，发起包含统计需求的对话，核对模型是否使用上传文件中的数据完成计算。
- 发起两轮连续对话，首轮指定特钢的具体牌号与规格，第二轮询问相关参数，核对模型是否保留了首轮的关键信息。
- 查看知识库的解析日志，确认上传的特钢文档已被正确拆分并生成向量嵌入，无解析失败的条目。
- 调整相似度阈值后，发起包含其他品类钢材关键词的查询，核对模型是否未返回无关的钢材数据，阈值需根据实际匹配精度调整。
