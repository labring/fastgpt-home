# 特钢投研知识库建设的知识库检索与召回

## 这个品类的数据长什么样
特钢投研数据主要来自行业协会公开报告、特钢厂商出厂价台账、期货交易所特钢品种行情数据、专利文献及下游制造企业采购台账。数据更新节奏差异明显：出厂价每日更新，行业供需报告按季度发布，专利文献实时新增。文档结构包含牌号、化学成分、力学性能、生产工艺参数、下游应用场景等字段，单份行业研报篇幅较长，单份产品参数表结构规整，字段对应明确的物理量单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
特钢数据的多来源、差异化更新节奏，要求检索环节支持按更新时间增量索引，避免高频更新的出厂价数据被低频更新的行业报告覆盖。不同文档的长度差异显著，短参数表与长行业研报的召回权重需区分设置，避免短文档在召回结果中占比过低。字段附带明确物理量单位，检索时需支持单位匹配逻辑，确保用户搜索特定参数时返回对应格式的结果。下游应用场景文档多绑定具体牌号，召回环节需建立牌号与应用场景的关联索引，提升精准匹配度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | `前10-15条` | 特钢数据包含短参数表和长研报，过多召回会导致上下文过长，过少则覆盖不全相关文档 |
| `相似度阈值` | `0.75-0.85` | 特钢参数类文档的语义相似度较高，阈值过低会引入无关结果，过高则遗漏部分匹配的专业文档 |
| `分段长度` | `800-1200字符` | 特钢行业研报篇幅较长，分段长度适配单份研报的核心段落，同时避免参数表被过度拆分 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600秒` | 部分大型行业研报解析耗时较长，需预留足够时间完成文本拆分与索引构建 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 单份特钢行业研报可能超过常规文档大小，需放宽上传上限以支持完整数据导入 |
| `重排返回条数` | `前5条` | 特钢投研场景下用户更关注最相关的核心数据，重排后返回少量高精准结果即可 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用对话接口时返回“未选择知识库”错误，但在调试预览界面可正常召回知识库内容。原因：接口调用时未正确携带`kbIds`参数，或参数格式不符合接口要求，导致系统无法识别绑定的知识库。
- 现象：通过网页链接导入知识库时，返回内容为空或提示无法访问目标页面。原因：目标链接需登录权限，未配置爬虫代理或登录态传递参数，导致无法抓取受保护的页面内容。
- 现象：检索结果中仅返回长行业研报，未包含特钢产品参数表。原因：`分段长度`设置过小，将参数表拆分为多个片段后，语义匹配权重被分散，导致短文档无法进入召回结果。

## 怎么确认配好了
- 上传一份特钢产品参数表与一份行业研报，触发文本解析，确认解析任务无超时报错，且文档已成功存入知识库。
- 发起检索请求，输入特钢牌号与力学性能关键词，核对召回结果中是否包含对应字段的文档，调整参数直至结果符合预期。
- 调用对话接口，携带正确的知识库标识参数，确认返回结果中包含知识库召回的内容，无“未选择知识库”类报错。
- 导入需登录权限的特钢行业报告网页链接，确认抓取任务完成后，知识库中已生成对应页面的解析内容。
