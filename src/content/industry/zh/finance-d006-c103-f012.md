# 环境监测投研知识库建设的模型接入与配置

## 这个品类的数据长什么样
环境监测的数据源包含国控自动监测站点、企业端排污监测设备、卫星遥感反演数据、移动监测巡检记录。更新节奏从秒级实时颗粒物浓度数据，到日级多站点汇总报表不等。单条结构化文档包含监测点ID、经纬度、监测时间、各污染物浓度值、设备运行状态字段，颗粒物浓度单位为μg/m³，气态污染物浓度单位为mg/m³，部分文档附带校准日志等附件文件。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源异构的数据来源与差异化更新节奏，要求模型接入时适配不同的触发频率，实时数据需配置小时级的知识库刷新周期，日级报表可按日更新。长时序的序列数据特征，要求配置合适的上下文窗口与分段规则，避免割裂监测数据的时序关联。多字段与统一单位的要求，需在解析与召回环节配置字段对齐规则，确保模型调用时不会混淆不同污染物的单位与监测点位信息。大体积的卫星遥感影像文件，要求调整上传与解析的超时参数，适配大容量数据的处理需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunk_size` | 800–1200 字符 | 环境监测数据包含长时序序列与多污染物字段，分段过长会丢失时序关联，过短会割裂单组监测数据的完整性，800-1200字符可覆盖单监测点1小时的连续数据 |
| `similarity_top_k` | 前6–8条 | 投研场景需关联多时段、多站点的监测数据，召回过少无法覆盖关联逻辑，过多会引入无关监测点数据 |
| `score_threshold` | 0.72–0.85 | 环境监测数据的数值特征明确，阈值过低会引入非匹配的监测时段数据，过高会遗漏关键关联的低分值序列 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 单份监测报表可能包含多站点的日汇总数据，解析耗时较长，300秒可覆盖多数大体积结构化文档的解析流程 |
| `UPLOAD_FILE_MAX_SIZE` | 2000 MB | 卫星遥感监测的原始影像数据体积较大，需适配大文件上传的限制 |
| `model_max_tokens` | 16384 及以上 | 投研分析需调用连续的监测序列数据，16384 tokens可覆盖1小时以上的时序数据上下文，避免截断关键分析依据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：模型调用返回`413 Request Entity Too Large`错误，原因：未调整`UPLOAD_FILE_MAX_SIZE`参数，上传的卫星遥感监测影像超出默认文件大小限制。
- 现象：召回的监测数据字段缺失`monitoring_time`或`device_id`，原因：未在解析配置中开启结构化数据的字段提取开关，导致时序关联逻辑失效。
- 现象：工作流执行后未输出不合理引用的具体监测时段，原因：未在模型节点中配置引用校验的提示词，未绑定知识库的引用溯源字段。

## 怎么确认配好了
- 上传单份包含1小时连续监测数据的结构化文档，查看解析后的分段是否完整覆盖单监测点的所有字段，调整对应参数直至分段无割裂。
- 触发多次模型调用，核对返回结果中引用的监测数据单位是否统一，调整相似度阈值直至无跨单位的异常召回。
- 上传最大体积的卫星遥感影像文件，查看解析任务是否在设定的超时时间内完成，无超时报错。
- 配置引用校验工作流，上传包含错误关联的监测数据文档，验证是否能输出对应的不合理引用条目。
