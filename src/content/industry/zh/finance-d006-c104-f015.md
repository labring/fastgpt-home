# 玻璃投研知识库建设的部署与升级

## 这个品类的数据长什么样
玻璃投研数据主要来自行业协会的窑炉开工率监测、上游纯碱原料报价数据库、下游光伏组件与建筑工程的订单数据，以及第三方机构的出厂价实时监测。更新节奏覆盖日度、周度、月度：日度更新浮法玻璃原片出厂价，周度更新各产区窑炉运行数据，月度发布行业产能与供需平衡报告。文档结构分为结构化参数表、研报摘要、上下游联动数据，字段包含厚度（mm）、密度（g/cm³）、出厂价（元/重量箱）、窑炉日熔量（吨/天）等，部分文档附带区域标签与时间戳。

## 这些特征在「部署与升级」这一环带来什么约束
玻璃投研数据的多频率更新、结构化字段多、区域标签明确的特征，对部署与升级带来明确约束。日度高频数据需要配置稳定的定时同步任务，升级过程中需保留同步链路避免数据断档。多字段结构化文档要求部署时预设字段映射规则，确保不同来源的厚度、价格数据统一匹配标准单位。区域标签关联的向量检索需求，需在部署阶段配置对应维度的索引，升级时需保留原有索引结构防止数据关联偏移。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300-600 秒` | 玻璃行业的结构化参数表、长周期研报文档较长，需适配更长的解析时长 |
| `UPLOAD_FILE_MAX_SIZE` | `200-500 MB` | 部分区域窑炉运行的历史监测数据集体积较大，需放宽上传上限 |
| `maxContext` | `800-1200 字符` | 玻璃投研核心数据字段集中，过长上下文会引入冗余信息影响检索精度 |
| `召回条数` | `前8-12条` | 玻璃投研需兼顾上下游关联数据，过多召回会导致结果分散 |
| `SYNC_INTERVAL` | `3600 秒` | 日度更新的浮法玻璃出厂价数据需每小时同步一次，保障数据时效性 |
| `VECTOR_DB_INDEX_TYPE` | `IVFFlat` | 适配玻璃行业多区域、多维度的向量检索需求，平衡检索速度与精度 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：创建知识库时返回`worker terminated due to reaching memory limit`报错。原因：未针对玻璃行业的大体积结构化文档调整内存阈值，默认内存配置不足以支撑多文档并行解析。
- 现象：迁移原有部署至新服务器后，定时同步任务无法触发。原因：未迁移本地配置文件与向量库索引文件，仅迁移容器镜像未保留本地数据映射路径。
- 现象：升级至4.14.0版本后，上传研报文档返回`Failed to create post presigned url`报错。原因：未更新对象存储的访问密钥配置，或未适配新版本的存储接口参数。

## 怎么确认配好了
- 上传单份大体积的玻璃行业监测数据文档，核对解析任务是否在预设超时时间内完成，超时阈值需匹配文档解析时长需求。
- 手动触发定时同步任务，核对知识库中新增的最新价格数据是否与外部数据源一致，同步周期需匹配数据更新频率。
- 检索区域玻璃产品关键词，核对召回结果的条数与相关性是否符合预设配置，召回规则需适配投研数据的关联需求。
- 切换至非x86架构服务器，验证服务部署与启动流程是否正常，镜像适配需匹配服务器架构类型。
