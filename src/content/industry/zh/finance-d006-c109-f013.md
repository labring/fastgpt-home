# 电子元件投研知识库建设的知识库检索与召回

## 这个品类的数据长什么样
电子元件投研数据主要来源于原厂官方 datasheet、行业供应链数据库、合规认证公告、季度行业供需报告。数据更新节奏差异显著：原厂规格文档随新品发布或参数调整更新，供应链报价数据每日更新，合规认证文件随法规修订同步更新。单份文档多为结构化段落，包含元件型号、封装类型、额定电压、工作温度范围、引脚定义等字段，单位涵盖欧姆、法拉、摄氏度、毫米等标准化计量标识，部分文档附带多语言版本与替代料关联信息。

## 这些特征在「知识库检索与召回」这一环带来什么约束
电子元件投研数据的多维度结构化特征，要求检索环节优先匹配精准参数，规避泛文本内容，避免无关结果干扰。不同数据源的更新频率差异，要求检索系统支持分批次增量召回，避免全量检索占用过多系统资源。多语言与替代料关联信息，要求召回逻辑同时覆盖同源关联条目，确保投研人员获取完整供应链信息。文档内标准化字段的统一计量要求，需要检索系统支持单位自动转换与匹配，例如将毫欧转换为欧姆后进行参数比对，避免因单位不一致导致匹配失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `retrieve_top_k` | 前10-15条 | 电子元件参数维度多，需保留足够候选条目以覆盖不同筛选条件 |
| `similarity_threshold` | 0.75-0.85 | 结构化参数匹配要求较高，阈值过低会引入大量无关结果，过高则遗漏有效匹配 |
| `structured_field_weight` | 0.6-0.8 | 结构化参数是电子元件检索的核心判断依据，权重高于全文检索分数 |
| `chunk_size` | 800-1200字符 | 原厂datasheet的参数段落长度集中在该区间，可保证单段内参数信息完整 |
| `incremental_update_interval` | 每12小时/每日 | 适配供应链报价数据的更新频率，兼顾实时性与系统负载 |
| `parse_file_timeout` | 600秒 | 部分大型合规认证文档解析耗时较长，避免提前终止解析流程 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：上传元件数据时返回`403 Forbidden`错误，部分私有供应商数据无法被检索到。原因：未配置基于企业标识符的访问控制规则，未将私有数据绑定至指定授权范围。
- 现象：检索结果中，全文检索分数为1.2717的条目排在分数为0.5208的参数匹配条目之前。原因：未为结构化参数配置专属权重，全文检索分数干扰了最终排序逻辑。
- 现象：上传Excel格式的元件清单时提示`unsupported file format`，导入csv文件后仅保留两列数据。原因：未开启结构化解析插件，未配置数据库同步接口以支持批量结构化数据导入。

## 怎么确认配好了
- 上传一份标准电子元件datasheet，检查解析后提取的`rated_voltage`、`package_type`等结构化字段是否完整且无格式错误。
- 输入一个具体元件型号与参数要求，检查检索结果的排序是否优先匹配参数匹配度更高的条目，避免仅按全文检索分数排序。
- 尝试上传Excel格式的元件库存清单，检查是否能正常解析并导入至知识库，无格式报错或字段缺失。
- 在检索界面配置文件夹筛选规则，检查检索结果是否仅包含指定文件夹内的元件相关文档，无跨文件夹无关条目。
