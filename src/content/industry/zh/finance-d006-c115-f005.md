# 种植业投研知识库建设的多轮对话与提示词

## 这个品类的数据长什么样
种植业投研数据来源涵盖农业农村部公开监测数据、地方农科院作物试验报告、田间农户种植日志、农产品现货报价数据与气象站点逐小时观测数据。数据更新节奏差异明显，气象数据为每日或逐小时更新，作物试验报告为季度或年度更新，现货报价为每日更新，农户日志为定期上传。文档类型包含数万字的年度种植区划报告、上千行的作物病虫害防治excel表格、单页的作物种植规范word文档。字段包含作物品种、生育期、亩产量、病虫害等级、气象阈值等，单位多为公斤/亩、毫米、摄氏度等农业生产标准单位。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
种植业数据的多维度与更新频率差异，要求多轮对话必须保留作物品种、种植区域、生育期等核心上下文参数，避免跨品类的模糊匹配。长文档与大型结构化表格的存在，要求提示词需明确指定字段格式与单位，防止AI输出混用单位或遗漏关键数据。不同更新节奏的数据需要在提示词中区分静态历史数据与动态实时数据，确保AI优先调用最新的气象与报价数据。同时，大型文件的处理会增加上下文窗口的压力，需限制单轮对话的上下文长度，避免token溢出。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `CORS_ALLOW_ORIGINS` | 配置为前端访问域名（如`https://your-agri-platform.com`） | 解决前端调用对话接口的跨域请求报错问题 |
| `maxContext` | 8000–12000 字符 | 适配种植业多轮对话的上下文保留需求，避免核心种植参数丢失 |
| `chunk_size` | 800–1000 字符 | 拆分长文档与大型excel，平衡单段信息完整性与召回精度 |
| `top_k` | 前 6 条 | 覆盖气象、病虫害、产量等多维度数据的召回需求，避免关键信息遗漏 |
| `rerank_top_k` | 前 3 条 | 过滤冗余的同类型种植方案数据，提升对话响应速度 |
| `UPLOAD_FILE_MAX_SIZE` | 2000 MB | 支持10万中文字档与15000行excel的上传与解析 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配大型结构化表格的解析耗时，避免解析失败 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：前端调用`/api/v1/chat/completions`接口返回CORS相关报错或403状态码。原因：未正确配置`CORS_ALLOW_ORIGINS`参数，或配置值未覆盖前端访问的域名。
- 现象：对话响应耗时超过30秒，或出现`504 Gateway Timeout`状态码。原因：`top_k`与`rerank_top_k`取值过高，或未调整`PARSE_FILE_TIMEOUT_SECONDS`参数适配大型文件解析需求。
- 现象：导入10万中文字档或15000行excel后，召回结果无法匹配用户查询。原因：`chunk_size`取值不合理，或未配置`UPLOAD_FILE_MAX_SIZE`允许大文件上传。

## 怎么确认配好了
- 访问前端配置的域名，发起包含“冬小麦亩产”“近期降水数据”的测试对话，确认无跨域报错。
- 上传15000行结构化excel与10万中文字档，查看知识库解析日志，确认无超时或解析失败记录。
- 发起两轮关联对话，如先查询“玉米种植密度”，再追问“对应区域的气象建议”，确认上下文参数被正确保留。
- 查看后台对话日志，确认每次对话的token消耗被完整记录，可通过对应接口提取计算数据。
