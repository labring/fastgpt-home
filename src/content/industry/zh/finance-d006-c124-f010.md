# 自动化设备投研知识库建设的数据库与运维

## 这个品类的数据长什么样
自动化设备投研数据主要来自厂商官方技术手册、行业机械运维标准、设备传感器实时采集日志、第三方性能检测报告。更新节奏覆盖实时（传感器运行数据）、季度（行业标准更新）、不定期（厂商固件迭代）。文档分为两类：一类为结构化参数表，包含设备型号、额定功率、转速、故障代码等字段；另一类为非结构化运维规程，包含长文本的故障排查步骤、备件更换流程。字段单位多采用机械行业通用标准，如功率以kW为单位、转速以rpm为单位、运行时长以h为单位。

## 这些特征在「数据库与运维」这一环带来什么约束
结构化参数与非结构化文档混合的数据源，要求同时支持向量检索与结构化条件查询，需兼顾两种查询的性能优化。实时采集的高频数据会带来高并发写入压力，需配置足够的数据库连接资源。设备型号多、字段差异大的特征，要求数据库支持动态元数据管理或灵活的表结构适配。同时，部分场景需规避开源与国外组件，需提前完成国产化数据库与驱动的适配验证。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `mongodb.maxPoolSize` | `50–80` | 自动化设备数据写入并发较高，避免连接池耗尽导致请求失败 |
| `pg_vector.recall_count` | `10–15` | 设备参数匹配需兼顾精度与响应速度，召回过多会增加检索延迟 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 大型设备运维手册文档较长，解析耗时高于通用知识库文档 |
| `contextWindow` | `8000–12000 字符` | 设备文档篇幅较长，需保留足够上下文以处理连续投研提问 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 厂商提供的完整设备手册体积较大，需适配大文件导入需求 |
| `queryThreshold` | `0.75–0.85` | 设备参数匹配精度要求较高，避免低相似度结果干扰投研判断 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 触发连续追问时返回答非所问内容，上下文丢失。原因是未配置`contextWindow`参数适配长文档，或上下文窗口设置过小，无法保留前序设备运维问题的关联信息。
- 高并发检索时返回`503 Service Unavailable`状态码。原因是未调整`mongodb.maxPoolSize`参数，数据库连接池耗尽导致请求无法被及时处理。
- 导入数据库时提示`unsupported driver`错误。原因是未使用国产化数据库驱动替代官方开源驱动，未完成国产数据库的适配配置。

## 怎么确认配好了
- 导入单份完整的设备运维手册，检查解析完成后数据库中生成的向量字段与结构化字段均无缺失。
- 发起多轮连续检索，核对每次检索结果均关联前序提问的设备型号与参数上下文。
- 模拟峰值并发请求，核对数据库连接池监控指标未触发阈值，无请求超时报错。
- 替换开源数据库驱动为国产化适配版本，核对能正常写入与查询设备参数数据。
