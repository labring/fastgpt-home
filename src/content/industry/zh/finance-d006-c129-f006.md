# 融资租赁投研知识库建设的对话日志与审计

## 这个品类的数据长什么样
融资租赁投研数据来源包括内部租赁合同档案、租赁物运维台账、央行征信系统公示的企业信用信息、行业协会发布的租赁品类供需数据、厂商公开的设备报价文档。更新节奏存在差异：租赁合同档案在签约完成后实时更新，租赁物运维台账按周更新，行业供需数据按月度更新。文档分为结构化表格类与非结构化文档类：结构化文档包含合同编号、承租人统一社会信用代码、租赁物原值、每期租金金额、租期时长等字段；非结构化文档包含租赁项目尽调报告、行业趋势分析，字段包括项目编号、报告发布日期、核心结论。字段单位：原值以万元为单位，租金金额以元为单位，租期时长以月为单位。

## 这些特征在「对话日志与审计」这一环带来什么约束
融资租赁投研数据的结构化占比高且字段复杂度高，要求对话日志需完整记录每一次调用匹配的字段名称与匹配结果，避免字段映射错误。不同数据源更新节奏差异明显，审计环节需关联日志时间戳与对应数据源的更新时间，确保回溯时使用的是项目发起时的有效数据。非结构化文档篇幅较长，日志需记录召回片段的起始与结束位置，便于快速定位审计依据。此外，融资租赁行业的合规审计要求留存全链路操作痕迹，日志需包含调用参数、返回结果、用户触发动作的完整信息，不得遗漏关键环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `LOG_RETENTION_DAYS` | `90 天` | 匹配融资租赁行业合规审计的常规留存周期 |
| `AUDIT_LOG_INCLUDE_CONTEXT` | `开启` | 完整记录对话上下文，满足全链路审计的回溯需求 |
| `MAX_LOG_ENTRY_SIZE` | `20480 字节` | 适配融资租赁长文档的日志记录需求，避免截断关键信息 |
| `LOG_ERROR_STACK_TRACE` | `开启` | 完整捕获调用报错的堆栈信息，便于问题排查 |
| `EXPORT_AUDIT_LOG_FORMAT` | `CSV` | 便于导入合规审计系统进行标准化整理 |
| `CONTEXT_RECALL_LOG_ENABLE` | `开启` | 记录召回的知识库片段信息，支撑投研数据的溯源审计 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用日志返回`500 Internal Server Error`，提示“获取对话数据异常”，原因：未配置`LOG_RETENTION_DAYS`的合理取值，导致日志文件占用存储过多引发读取失败。
- 现象：Docker Compose部署后无法清除指定对话记录，界面显示记录仍存在，原因：未挂载日志持久化卷，删除容器后临时存储的对话记录未被清理，或未执行`docker compose down -v`命令移除匿名卷。
- 现象：网页分享应用后无法取回历史对话记录，日志中显示`missing session_id`字段，原因：未开启`SESSION_PERSISTENCE_ENABLE`配置，导致对话会话未被持久化存储。

## 怎么确认配好了
- 执行`docker logs fastgpt-app`命令，检查日志中是否包含`audit log initialized successfully`的提示，确认日志服务正常启动。
- 发起一次投研相关的对话调用，查看后台日志是否包含匹配的字段信息、召回文档片段的位置记录，确认日志记录完整。
- 进入系统设置的日志管理页面，尝试导出指定时间段的审计日志，确认导出格式与配置项一致。
- 手动删除一条测试对话记录，检查对应存储目录或数据库中是否已移除该会话数据，确认清理逻辑生效。
