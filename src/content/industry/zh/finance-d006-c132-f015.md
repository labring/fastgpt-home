# 计算机设备投研知识库建设的部署与升级

## 这个品类的数据长什么样
计算机设备投研数据主要来自硬件厂商官方规格文档、第三方测试报告、行业标准规范、设备运维日志与实时性能监控数据。更新节奏分两类，基础硬件参数更新周期较长，固件、驱动及兼容适配文档更新频率较高。单份文档多以设备型号为核心维度，包含核心硬件参数、适配操作系统列表、固件版本变更记录等字段，参数字段统一使用国际标准单位，如GHz、GB、W、bps等。

## 这些特征在「部署与升级」这一环带来什么约束
计算机设备投研数据的多源异构特性，要求部署阶段预留兼容多格式文档的解析接口，避免新增数据源时重构解析逻辑。基础参数与适配文档的更新频率差异，要求配置分层增量同步任务，优先同步高频更新的固件与运维数据。以型号为核心的文档结构，要求知识库索引按型号维度聚合，升级阶段需兼容旧版本索引结构，避免破坏原有历史检索链路。带标准单位的参数字段，要求解析环节增加单位校验逻辑，防止因单位不统一导致检索匹配失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 计算机设备文档可能包含大量硬件参数表格与多页内容，600秒可覆盖完整解析流程，避免中途超时中断 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 硬件厂商的规格文档可能包含高清测试图表与完整版本包，1000 MB可容纳单份完整文档资源 |
| `召回条数` | `前10-15条` | 投研场景需覆盖同型号多版本参数对比，该范围可兼顾检索覆盖率与推理延迟控制 |
| `相似度阈值` | `0.75-0.85` | 硬件参数的字段匹配需较高精度，该区间可过滤无关匹配结果，同时保留有效适配型号的参数 |
| `PARSE_CHUNK_SIZE` | `800-1200 字符` | 计算机设备文档的参数段落多为紧凑技术描述，该分段长度可保留单组参数的完整上下文 |
| `RE_RANK_TOP_N` | `前5条` | 投研场景需精准匹配核心型号参数，重排后保留前5条可兼顾召回覆盖率与结果精度 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：升级至指定版本后执行初始化脚本返回404错误，知识库无法正常响应查询。原因：升级过程中未正确更新静态资源映射配置，导致初始化脚本的接口路径与新版本服务路由不匹配。
- 现象：创建知识库时无法选择本地部署的模型，界面模型列表为空。原因：本地模型接入配置未正确映射至服务的模型调用接口，或`config.json`中的模型配置字段格式不符合当前版本要求。
- 现象：上传的硬件规格文档解析后，关键参数条目被拆分或格式混乱。原因：分段长度配置过小，导致硬件参数的完整段落被拆分，检索时无法关联匹配完整参数组。

## 怎么确认配好了
- 执行初始化脚本，检查返回状态码为200，无404或500错误，确认部署链路正常。
- 上传一份典型的计算机设备规格文档，等待解析完成后，检查知识库中是否生成对应型号的参数条目，确认解析逻辑生效。
- 发起一次硬件参数检索查询，核对返回结果的数量与配置的召回条数一致，确认检索规则生效。
- 升级至目标版本后，重启服务并检查日志中无配置加载失败的报错，确认升级后的配置已正常加载。
