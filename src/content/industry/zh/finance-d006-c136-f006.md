# 贵金属投研知识库建设的对话日志与审计

## 这个品类的数据长什么样
贵金属投研数据主要来自交易所实时行情、行业协会供需报告、专业研报及政策公告。实时行情数据每分钟更新，供需报告按周发布，研报多为单日更新。文档结构包含合约基础信息、实时报价快照、供需平衡表、政策解读四类，字段包含合约代码、最新成交价、涨跌幅、持仓量、库存数据，单位多为元/克、美元/盎司或吨。

## 这些特征在「对话日志与审计」这一环带来什么约束
实时行情的高频更新要求对话日志必须绑定每一次查询的时间戳与对应行情节点版本，确保审计时可溯源准确的数据源。多频次更新的研报与报告要求日志关联文档版本号，避免审计时混淆不同周期的分析依据。字段与单位的多样性要求日志记录调用时指定的单位参数，审计环节需校验参数与返回数据的单位一致性。多轮投研对话的连贯性要求日志保存上下文关联ID，确保可完整回溯推导过程。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `logRetentionDays` | `365 天` | 贵金属投研数据需长期合规留存审计记录，满足行业监管要求 |
| `enableAuditTrail` | `开启` | 完整记录对话全链路操作，支持投研过程的合规溯源 |
| `maxContext` | `8000–12000 字符` | 覆盖多轮投研对话的行情对比、研报引用等完整上下文 |
| `auditLogFields` | `["query", "response", "docVersion", "timestamp", "unit"]` | 记录核心审计字段，匹配贵金属数据的版本、单位等特征 |
| `logStorageQuota` | `按本地存储容量标定` | 控制日志存储占用，避免磁盘资源耗尽影响服务运行 |
| `failedLogAlert` | `开启` | 及时发现审计日志生成异常，保障合规记录完整性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：界面提示“没有权限操作此对话记录”，无法查看历史投研对话。原因：未配置对话日志的访问权限规则，或权限范围未覆盖贵金属投研知识库的审计场景。
- 现象：对话日志中无法关联到对应贵金属研报或行情数据的版本号。原因：未开启`auditLogFields`的`docVersion`字段配置，导致审计日志未记录文档版本信息。
- 现象：Docker部署环境下磁盘占用持续升高，触发告警。原因：未设置`logStorageQuota`参数，或保留时长配置过长，未结合贵金属数据的更新频率调整日志留存周期。

## 怎么确认配好了
- 进入系统设置的日志审计模块，查看已保存的对话日志，确认包含`query`、`response`、`docVersion`、`timestamp`、`unit`等核心字段。
- 发起一次贵金属行情查询对话，检查审计日志是否生成且关联了正确的文档版本与单位参数。
- 查看日志存储目录的占用情况，确认未超出预设的`logStorageQuota`阈值。
- 测试权限控制规则，验证不同角色是否可按配置访问对应对话日志。
