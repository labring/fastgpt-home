# 贵金属投研知识库建设的知识库检索与召回

## 这个品类的数据长什么样
贵金属投研数据主要来自官方交易所行情接口、行业协会报告、宏观经济数据库三类来源。行情类数据包含实时或分钟级的品种报价（如AU9999、伦敦金）、成交量、持仓量；研报类数据包含行业供需分析、政策解读、关联市场联动分析；宏观关联数据包含美元指数、原油价格等联动指标。文档结构分为结构化行情快照、半结构化研报片段、非结构化行业动态三类，字段单位存在差异，国内报价以元/克为单位，国际报价以美元/盎司为单位，持仓量以吨为单位。数据更新节奏随类型不同，行情数据分钟级更新，研报类每日更新，宏观联动数据按日更新。

## 这些特征在「知识库检索与召回」这一环带来什么约束
贵金属数据的多来源、多单位特性要求检索环节先完成单位统一映射，否则会出现同一品种报价混乱的问题。实时行情的高频更新要求知识库增量更新频率匹配，否则召回的旧数据无法满足投研时效性需求。多类型文档并存的结构，要求检索系统同时支持结构化数据的精确匹配与非结构化文本的语义匹配，单一匹配逻辑无法覆盖全部数据场景。此外，贵金属行情波动与宏观政策关联紧密，用户检索通常需要同时关联行情与研报内容，召回结果的排序需优先匹配最新数据与核心关联字段，否则会降低投研参考价值。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | 前10-15条 | 贵金属数据密度较高，过多召回内容会超出上下文窗口，影响后续生成逻辑 |
| `相似度阈值` | 0.75-0.85 | 结构化行情数据特征明确，阈值过低会引入无关数据，过高则可能漏召回有效行情快照 |
| `分段长度` | 800-1200字符 | 适配研报与解析后行情文本的长度，避免截断关键的供需分析或报价数据 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300秒 | 大型行业研报文档解析耗时较长，默认超时时间不足以完成完整解析 |
| `增量更新频率` | 5分钟（行情数据）、每日（研报数据） | 匹配贵金属实时行情与研报的发布更新节奏，确保召回数据的时效性 |
| `maxContext` | 8000-12000字符 | 覆盖多字段关联的贵金属数据上下文，支持同时召回行情、研报与宏观联动数据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用API返回的检索结果与平台测试结果不一致。原因：API调用时未正确关联目标知识库，或生产环境与测试环境的相似度阈值、召回条数配置存在差异。
- 现象：检索结果中出现单位不统一的贵金属报价。原因：未配置字段统一映射规则，导致不同来源的行情数据（如国内元/克与国际美元/盎司）未被对齐。
- 现象：检索返回空结果或返回504超时状态码。原因：增量更新频率设置过高，导致检索时加载过多实时行情数据，超出系统处理阈值。

## 怎么确认配好了
- 上传一份包含最新国内AU9999与伦敦金报价的文档，执行检索，核对召回结果包含统一单位后的完整报价数据。
- 调整相似度阈值并执行多次检索，观察召回结果的相关性变化，确认阈值配置符合当前数据特征。
- 调用API传递与平台测试完全一致的参数，对比两次检索的返回结果是否一致。
- 查看知识库的增量更新日志，确认行情数据与研报的更新频率符合预设配置。
