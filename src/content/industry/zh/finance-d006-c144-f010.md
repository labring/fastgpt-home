# 通信服务投研知识库建设的数据库与运维

## 这个品类的数据长什么样
通信服务投研的数据主要来自通信设备供应商公开技术文档、运营商运营后台导出数据、行业协会监测报告、频谱分配公告。更新节奏存在差异：实时运营数据按分钟级推送，行业监测数据按周更新，设备参数文档按季度更新。文档多为结构化表格与时序数据，字段包含设备型号、频段范围、传输速率、覆盖区域、运行时长，单位多为MHz、Gbps、平方公里、小时，无统一的非结构化文本格式。

## 这些特征在「数据库与运维」这一环带来什么约束
通信服务投研数据的特征对数据库与运维环节带来多重约束。首先，分钟级实时运营数据要求数据库支持高并发写入与低延迟查询，需适配时序存储引擎的格式要求。其次，多源异构数据的字段差异要求数据库支持灵活的schema变更，避免硬编码字段限制数据接入。第三，历史投研数据的回溯需求需要建立时间维度的二级索引，缩短复杂查询的响应时间。第四，不同数据源的更新频率差异，需配置冷热数据分离的存储策略，降低热数据存储成本同时保障查询效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGO_URI` | `mongodb://<user>:<pass>@<host>:<port>/fastgpt?authSource=admin` | 适配FastGPT官方默认的MongoDB连接格式，支持权限验证与指定业务数据库 |
| `DATA_SYNC_INTERVAL` | `300 秒` | 适配通信服务行业监测数据的更新粒度，平衡数据同步延迟与服务器负载 |
| `MAX_CONCURRENT_QUERIES` | `50–80` | 适配通信实时运营数据的高并发查询需求，避免数据库连接耗尽 |
| `PARSE_DOC_TIMEOUT` | `600 秒` | 适配长文档（如通信设备白皮书）的解析耗时需求，避免超时中断解析流程 |
| `RECALL_CHUNK_SIZE` | `1000–1200 字符` | 适配通信技术文档的段落长度特征，保障召回内容的完整性 |
| `DB_INDEX_EXPIRY_DAYS` | `180 天` | 适配投研数据的回溯周期，自动清理过期索引节省存储空间 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：启动后出现`connection refused to mongo`报错，原因：未正确配置`MONGO_URI`中的主机地址与权限参数，导致无法建立数据库连接。
- 现象：知识库召回结果为空，原因：未配置外部数据接口的请求超时与重试策略，导致本地调用外部服务时因网络波动失败，未返回有效数据。
- 现象：v4.9.14版本下出现`503 Service Unavailable`报错，原因：未调整`MAX_CONCURRENT_QUERIES`参数，默认并发数不足以支撑通信实时数据的高查询需求，导致请求队列溢出。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证`MONGO_URI`配置可正常读写数据，核对返回字段匹配通信服务数据的格式要求。
- 发起外部数据接口调用测试，验证配置的请求参数与超时时间可正常获取通信行业数据源，无网络异常报错。
- 模拟高并发查询请求，观察数据库连接数与响应时间，确认`MAX_CONCURRENT_QUERIES`的取值可覆盖实际业务峰值。
- 查看知识库解析日志，确认`PARSE_DOC_TIMEOUT`配置未触发长文档解析超时，返回完整的结构化数据。
