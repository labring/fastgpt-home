# 通用设备投研知识库建设的向量模型与索引

## 这个品类的数据长什么样
通用设备投研数据主要来自行业协会发布的月度运行简报、上市公司季度财报、设备供应商的技术参数手册、招投标项目文档以及设备终端的实时工况日志。数据更新节奏存在差异：行业报告与财报按季度或年度更新，技术参数手册为静态更新，工况日志则为实时新增。文档结构包含结构化参数表（含设备型号、生产厂商、额定参数等）、非结构化技术分析长文、招投标需求文档三类，字段多带有明确单位，例如额定功率以千瓦为单位、运行效率以百分比为单位、服役年限以年为单位。

## 这些特征在「向量模型与索引」这一环带来什么约束
通用设备投研数据的混合结构与多单位字段特征，要求向量模型支持多字段加权嵌入，避免因单位混淆导致相似度计算偏差。实时工况日志的高频新增需求，要求索引支持增量更新，减少全量重建的资源占用。结构化参数表的精确匹配需求，要求索引同时支持向量召回与精确查询，适配混合数据的检索需求。长文本技术分析文档的分段需求，要求合理设置分段长度，避免破坏参数与说明的上下文关联，同时保证嵌入后的向量可完整承载技术细节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `EMBEDDING_MODEL` | 支持多字段加权嵌入的外接向量模型 | 通用设备投研数据包含结构化参数与非结构化分析内容，多字段加权嵌入可提升参数匹配精度 |
| `CHUNK_SIZE` | 800–1200 字符 | 通用设备技术文档多包含连续的参数说明与技术细节，该分段长度可平衡上下文完整性与嵌入效率 |
| `INDEX_TYPE` | PGVector 复合索引 | 兼顾结构化参数表的精确匹配与非结构化文本的向量召回需求，适配混合数据结构 |
| `RECALL_TOP_K` | 前10条 | 投研场景需要兼顾召回全面性与处理效率，过多召回会增加后续分析开销 |
| `SIMILARITY_THRESHOLD` | 0.72–0.80 | 设备参数的精确匹配需要较高相似度阈值，避免无关型号设备被误召回 |
| `INCREMENTAL_UPDATE_INTERVAL` | 3600 秒 | 平衡工况数据的实时性与索引更新的资源占用，适配行业报告的季度更新周期 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：PG数据库docker部署时，索引创建失败，日志返回 `index creation timed out`。原因：未将结构化参数表与非结构化文本分开建立索引，单次索引数据量超出默认超时阈值。
- 现象：导入飞书Excel与多维文档后，召回结果无匹配内容，解析字段为空。原因：未配置`EXCEL_PARSE_SCHEMA`匹配设备参数的预设字段名，导致解析后的文本未正确生成向量。
- 现象：arm软路由部署外接向量API时，频繁出现`504 Gateway Timeout`报错。原因：软路由网络带宽不足，无法支撑向量API的高频调用，且未延长`API_REQUEST_TIMEOUT`的超时设置。

## 怎么确认配好了
- 上传单份设备参数Excel文件，查看解析后的字段是否包含`设备型号`、`额定功率`等预设字段，确认解析配置生效。
- 输入包含明确参数的查询文本，例如「额定转速1500转的通风设备」，查看召回结果的相似度得分是否落在预设阈值区间内，确认相似度阈值配置正确。
- 提交新增的工况日志数据，查看索引更新日志仅包含新增数据，无全量重建记录，确认增量更新规则生效。
- 检查外接向量API的调用日志，确认无`429 Too Many Requests`报错，确认硬件资源与API调用阈值匹配。
