# 通用设备投研知识库建设的知识库检索与召回

## 这个品类的数据长什么样
通用设备投研数据来源包括行业协会发布的行业季报、设备厂商公开的产品技术手册、设备运维团队的运行日志、专利文档、第三方检测机构的性能检测报告。更新节奏随数据源类型差异明显，厂商手册随型号迭代半年至一年更新一次，行业季报按季度发布，运维日志实时产生，专利文档随申请实时更新。文档结构通常包含设备型号、核心技术参数、适用工况、故障代码对照表、维护周期等字段，参数字段多附带标准化单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
通用设备投研数据的多来源与多结构特征，对检索召回环节提出多重约束。多字段且带标准化单位的参数内容，要求检索支持精准字段匹配与单位校验，避免模糊匹配导致的参数错位。异构数据类型（短参数条目、长故障手册、图片图表）要求检索支持分段适配与多模态召回。不同更新频率的数据源，要求检索系统支持增量索引与定时全量更新的混合配置，兼顾数据时效性与检索效率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunk_size` | 800–1200 字符 | 通用设备既有短参数条目，也有长故障排查手册，该分段长度可覆盖完整参数组与逻辑段落 |
| `recall_top_k` | 前10–15条 | 投研场景需覆盖型号、参数、故障案例等多维度召回结果，该范围可兼顾全面性与检索效率 |
| `similarity_threshold` | 0.72–0.85 | 参数类内容需高相似度匹配以避免参数错位，故障案例需保留一定容错空间适配模糊查询 |
| `field_weight_config` | 按实测标定 | 不同字段（如设备型号、额定功率、故障代码）的权重需适配投研场景的查询优先级 |
| `index_update_interval` | 86400 秒（1天） | 行业报告季度更新、厂商产品迭代周期较长，该间隔可平衡数据时效性与索引构建成本 |
| `parse_image_embed` | 开启 | 产品手册中参数图表需嵌入检索向量，适配包含图片描述的投研查询 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：上传的Markdown文件中设备参数图片无法加载，知识库检索时无对应图片结果。原因：未配置图片路径替换规则，本地相对路径未映射到知识库存储的公共访问地址。
- 现象：检索时仅能调用默认文本理解模型，无法选择新增的多模态模型。原因：未在检索任务配置中绑定新增模型的接入密钥与模型标识，仅开放了默认模型的调用权限。
- 现象：导入知识库时生成的索引未包含自定义筛选字段（如设备型号）。原因：未在文档解析环节开启字段提取配置，未指定需提取的投研核心字段规则。

## 怎么确认配好了
- 上传一份包含设备型号、参数图表与故障案例的Markdown测试文件，核对解析后的字段是否完整提取。
- 发起包含设备型号、功率参数的精准查询，核对召回结果的条数与相似度是否符合预设配置。
- 触发增量索引更新任务，核对索引更新日志中的更新时间与更新文档数量是否匹配配置的更新间隔。
- 发起包含图片描述的查询，核对是否返回了对应参数图表的检索结果。
