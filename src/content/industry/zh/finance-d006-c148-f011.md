# 酒店餐饮投研知识库建设的文档解析与分块

## 这个品类的数据长什么样
酒店餐饮投研的数据来源包含行业分析报告、单店运营台账、供应链采购价目表、OTA平台客流与营收数据、餐饮卫生监管政策文件等。数据更新节奏差异明显：行业报告按季度或半年度更新，单店运营数据按日或周更新，供应链采购价目按日或实时更新。文档结构包含纯文本分析、结构化表格、混合格式的PDF文档，其中结构化表格包含坪效、客单价、食材成本等字段，单位多为元/平方米/天、元/千克、人次/日等。

## 这些特征在「文档解析与分块」这一环带来什么约束
酒店餐饮投研文档的混合格式特征要求解析工具同时支持纯文本提取与结构化表格识别，避免丢失采购价目、营收明细等关键结构化内容。不同更新节奏的数据对应不同的解析触发需求，高频更新的供应链数据需要适配实时解析流程，低频的行业报告则可按固定周期触发解析。餐饮行业文档中的专业术语如翻台率、账期天数需要在分块时保留完整性，不能被截断导致语义断裂。长文本的年度拓店规划报告需要合理设置分块参数，避免破坏业务逻辑的连贯性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_MODE` | `auto` | 酒店餐饮文档混合结构化表格、图表与纯文本内容，自动模式可同时识别各类格式 |
| `CHUNK_SIZE` | `800–1200 字符` | 餐饮行业的结构化表格行内容多在300-800字符，长文本分析报告段落多在600-1000字符，该区间可保留上下文完整性 |
| `TABLE_PARSE_ENABLE` | `true` | 酒店餐饮投研文档包含大量采购价目表、营收明细表格，启用后可保留完整的行列结构 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 大型连锁餐饮的年度报告PDF页数多在50-100页，300秒可覆盖完整解析时长 |
| `CHUNK_OVERLAP` | `100–150 字符` | 长文本分块时保留重叠部分可避免上下文断裂，适配餐饮行业报告的逻辑连贯性 |
| `PARSER_ENGINE` | `marker` | 酒店餐饮文档包含成本测算公式与图表，marker引擎可更好识别此类内容 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用解析工具时返回`504 Gateway Timeout`错误，原因：未将`PARSE_FILE_TIMEOUT_SECONDS`配置为适配大型餐饮报告的时长，导致解析超时未完成。
- 现象：上传的采购价目表PDF解析后表格字段为空，原因：未启用`TABLE_PARSE_ENABLE`配置，仅提取纯文本导致结构化内容丢失。
- 现象：本地部署的解析工具无法正常识别成本测算公式，原因：使用了与线上版本不匹配的解析镜像版本，如使用`v0.1`版本的marker镜像，未适配酒店餐饮文档中常见的公式格式。

## 怎么确认配好了
- 上传一份包含结构化表格的酒店餐饮采购价目表PDF，检查解析结果中是否保留完整的行列结构。
- 上传一份包含成本测算公式的餐饮运营报告PDF，检查解析结果中公式是否可正常识别与展示。
- 调整分块参数后，查看分块结果的上下文连贯性，确认无关键术语被截断的情况。
- 查看系统日志，确认解析工具的调用未出现超时或报错状态码。
