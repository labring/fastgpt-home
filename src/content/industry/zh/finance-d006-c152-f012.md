# 鞋类投研知识库建设的模型接入与配置

## 这个品类的数据长什么样
鞋类投研数据主要来自品牌官方供应链台账、行业协会发布的品类趋势报告、跨境电商平台的销售监测数据、海关进出口品类统计文件。数据更新节奏随场景变化：供应链台账随新品投产、库存调整实时更新，行业趋势报告按季度发布，电商销售数据每日同步。文档结构分为三类：SKU参数文档（含鞋码对应表、材质成分、鞋底耐磨指数等字段）、竞品对标文档（含定价区间、渠道布局）、终端动销分析文档。字段与单位存在明确规范，鞋码标注同时包含US、CN、EU三种制式，材质占比以百分比为单位，鞋底耐磨性能以万次为单位，单款鞋的重量以克为单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
鞋类投研数据的多制式字段、细分品类参数要求，要求模型接入时需适配多字段解析与标准化转换。实时更新的供应链数据要求配置的召回逻辑支持高频增量同步，避免模型调用过时的库存或新品信息。多文档分类的结构要求，需在模型接入环节配置适配品类的文档分块规则，确保SKU参数与动销数据不会被错误拼接。同时，鞋类数据存在大量跨制式的单位转换需求，需在模型配置中预设标准化映射规则，避免因单位不匹配导致的分析偏差。此外，电商监测数据的每日同步特性，要求模型的上下文窗口配置适配高频数据的批量处理能力，防止单次调用超时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 鞋类SKU参数文档单篇长度多在1000-3000字符，结合多文档召回的需求，预留足够上下文空间 |
| `RECALL_TOP_N` | `前 8–12 条` | 鞋类投研需同时参考SKU参数、竞品数据与动销信息，过多召回会稀释有效信息，过少则覆盖不全分析维度 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 鞋类供应链台账常包含批量SKU参数表，单文件解析耗时较长，需延长超时阈值避免解析失败 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 行业趋势报告常包含高清图表与批量数据，需支持较大文件上传 |
| `SIMILARITY_THRESHOLD` | `0.75–0.85` | 鞋类SKU参数存在大量相似字段，需提高阈值过滤低匹配度的无关文档，确保召回内容精准匹配投研需求 |
| `PROXY_URL` | 按部署环境填写专属代理地址 | 需对接本地部署的大模型或第三方API，需配置正确的代理链路确保模型调用稳定 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 模型测试时提示「这个是图像模型，为什么不支持打开图像选项」，原因是未在模型接入环节配置图像模型专属的输入格式开关，默认仅启用文本模型的调用逻辑。
- 本地部署重启后模型调用失败，返回`504 Gateway Timeout`错误，原因是未将部署的大模型服务与FastGPT容器配置为随系统自启动，重启后服务链路中断，导致模型调用超时。
- 自定义模型接入后召回结果条数异常，仅返回1-2条内容，原因是未调整相似度阈值至适配鞋类数据的区间，过高的阈值过滤了大部分有效召回内容。

## 怎么确认配好了
- 上传一份鞋类SKU参数文档，检查解析后的字段是否完整包含鞋码制式、材质占比等专属字段，确认解析规则适配品类数据结构。
- 发起一次包含鞋类参数查询的模型调用，核对返回内容是否覆盖SKU、竞品、动销等多维度投研信息，确认召回逻辑符合配置预期。
- 查看模型调用日志，确认代理地址配置正确，无连接超时或认证失败的报错，验证模型接入链路正常。
- 调整召回条数参数，测试不同取值下的返回结果，确认内容数量符合投研分析的需求。
