# 饲料投研知识库建设的对话日志与审计

## 这个品类的数据长什么样
饲料投研的数据覆盖原料行情、养殖端数据、行业政策与公开研报四类，来源包括行业协会公开数据、期货交易所行情、第三方调研机构公开报告、饲料企业内部生产记录。现货行情类数据每日更新，期货行情随交易日实时更新，养殖存栏数据月度更新，行业政策与研报不定期发布。结构化文档包含明确的字段与数值单位，非结构化研报包含数据引用标注与来源说明。

## 这些特征在「对话日志与审计」这一环带来什么约束
饲料投研数据的多来源、多更新节奏与结构化特征，对对话日志与审计提出多重约束。首先，多类数据源需在日志中完整记录调用标识，确保审计可溯源。其次，不同数据更新频率差异明显，日志需同步记录问答触发时的数据源版本或发布时间，避免引用过期信息。最后，结构化数据包含明确的数值单位，日志需捕获问答中使用的单位字段，防止单位转换错误影响投研结论。非结构化研报的引用标注需在日志中关联对应内容，满足合规审计要求。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `LOG_RETENTION_DAYS` | 365 天 | 饲料投研场景需满足年度合规审计要求，需留存至少一年的问答与操作记录 |
| `ENABLE_THINKING` | false | 饲料投研审计仅需记录问答结果与溯源信息，无需展示中间思考过程，避免日志冗余 |
| `LOG_CAPTURE_USER` | true | 需在日志中记录发起问答的用户标识，满足岗位操作溯源与责任认定需求 |
| `LOG_CAPTURE_SOURCE` | true | 饲料投研数据来源多样，需在日志中关联每条问答调用的数据源标识，便于合规审计与错误溯源 |
| `LOG_MAX_CONTENT_LENGTH` | 2000 字符 | 饲料投研问答通常包含多组原料或养殖数据，需容纳完整的结果与溯源信息，避免截断关键内容 |
| `AUDIT_AUTO_TRIGGER` | 每日 00:00 | 匹配饲料行业月度/年度审计周期，每日自动汇总前一日日志便于定期核查 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：开启思考过程配置后，对话历史记录中未展示思考过程内容。原因：未同步启用日志捕获思考过程的参数，或前端展示规则默认过滤了中间步骤字段。
- 现象：对话日志中无法关联发起问答的用户身份。原因：未开启`LOG_CAPTURE_USER`配置项，或调用接口时未传入合法的用户标识字段。
- 现象：无法自动化提取单条问答的推理耗时数据。原因：未启用`LOG_CAPTURE_DURATION`参数，导致日志未记录问答的开始与结束时间戳，无法计算耗时。

## 怎么确认配好了
- 发起一条测试问答，查看后台日志详情，确认已捕获数据源标识、用户标识与问答耗时字段。
- 手动触发一次审计汇总任务，验证是否生成包含指定字段的日志汇总文件。
- 测试删除单条对话记录，确认该记录在前台列表与后台日志中均被正确移除或标记。
- 调整日志保留时长参数，验证后台日志管理页面的保留期限提示是否同步更新。
