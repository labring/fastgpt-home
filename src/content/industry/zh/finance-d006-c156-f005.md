# 黑色家电投研知识库建设的多轮对话与提示词

## 这个品类的数据长什么样
黑色家电投研数据主要来源于行业协会公开报告、品牌官方技术规格文档、电商平台销售参数页、第三方检测机构的性能与能效报告、上游供应链原材料报价数据。数据更新节奏随新品发布、行业标准调整波动，新品上市时同步更新核心参数，行业报告按季度更新，原材料价格每日更新。文档结构包含标准化技术参数表、竞品对比文档、营销宣传内容与售后反馈数据，字段包含SKU编号、上市日期、制冷量、能效等级、整机尺寸、建议零售价等，对应单位分别为瓦特、等级、毫米、人民币元。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
黑色家电投研数据包含多维度标准化参数与非标准化市场内容，多轮对话需区分用户的技术参数查询、竞品对比或市场动态需求，提示词需明确绑定历史对话中的SKU标识以避免混淆不同型号。数据更新节奏不固定，需在多轮对话中提示调用最新的数据源，避免引用过时的产品参数。字段存在单位混用可能，提示词需自动校准单位转换逻辑。多轮对话常涉及多轮参数对比，需保留足够的历史上下文以支撑连续的投研提问。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `maxContext` | `8000–12000 字符` | 黑色家电技术文档单篇长度较长，多轮对话需保留足够的历史SKU编号、能效等级等关键信息，避免上下文溢出导致关键数据丢失。 |
| `recallTopK` | `前10–15 条` | 黑色家电投研数据包含多维度参数，过多召回会干扰对话逻辑，过少则无法覆盖用户需要的竞品对比与技术细节。 |
| `similarityThreshold` | `0.75–0.85` | 过滤与黑色家电参数无关的通用家电文档，精准匹配制冷量、尺寸等细分投研字段，减少无效召回内容。 |
| `rerankTopN` | `前5–8 条` | 重排后保留最相关的技术报告与竞品数据，适配多轮对话中逐步深入的投研提问，避免冗余信息干扰。 |
| `systemPrompt` | 按实测标定 | 需明确区分技术参数查询、竞品对比、市场动态三类投研场景，绑定历史对话中的SKU标识，统一单位转换逻辑。 |
| `historyWindowSize` | `10–15 轮` | 黑色家电投研对话常涉及多轮参数对比，保留足够历史可避免重复询问用户已提供的型号与参数信息。 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 配置`maxContext`取值过小，对话超过阈值后历史SKU编号丢失，界面提示无法识别当前讨论的家电型号。原因是未适配黑色家电多轮对话需保留SKU标识的需求，未匹配该品类的长上下文要求。
- 调用数据库工具时返回`400 status code (no body)`错误。原因是未正确格式化包含黑色家电SKU编号的查询语句，或数据库连接的超时设置过短，导致请求未完成即中断。
- 未设置`historyWindowSize`导致对话历史溢出，后续提问无法关联之前提及的能效等级数据。原因是未考虑黑色家电投研对话的长上下文特性，未保留足够的历史对话轮次。

## 怎么确认配好了
- 发起包含具体SKU编号的多轮提问，核对后续对话是否能自动关联之前提及的型号参数，无需重复询问型号信息。
- 调用数据库工具执行包含黑色家电SKU字段的查询，确认返回结果无`400 status code (no body)`错误。
- 查看对话历史的上下文长度，确认超过`maxContext`阈值后仍能保留关键的技术参数与SKU信息。
- 触发知识库手动刷新，确认更新后的新品数据能被多轮对话正确召回，用于后续的投研对比提问。
