# 黑色家电投研知识库建设的对话日志与审计

## 这个品类的数据长什么样
黑色家电投研的数据来源涵盖行业协会公开月度/季度运行简报、品牌方年度/半年度财报、主流电商平台的SKU销售台账、上游供应链厂商的出货明细，以及家电技术专利数据库文档。数据更新节奏存在分层：行业报告按季度更新，电商销售数据每日同步，财报类文档按披露周期更新，专利文档实时新增。单份文档包含标准化字段：SKU编码、能效等级、制冷/制热功率（单位为瓦）、外形尺寸（单位为毫米）、上市时间、测试报告编号等，部分技术文档包含长文本的电路设计说明与性能测试数据。

## 这些特征在「对话日志与审计」这一环带来什么约束
黑色家电投研数据多源且更新节奏差异大，要求对话日志需关联数据源版本标识与时间戳，确保审计时可追溯数据来源的更新周期。单份文档包含多类标准化字段与长文本技术说明，对话日志需记录被引用的SKU编码、字段名称与具体取值，便于审计时定位投研结论的依据。频繁更新的电商销售数据会导致对话中调用的数据集版本存在差异，审计环节需核对日志中记录的数据集构建时间与实际数据更新时间的匹配性。长文本技术文档易触发长度超限问题，日志需留存分段切割的起始与结束位置，辅助排查上下文丢失导致的对话偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 字符 | 黑色家电技术文档单份长度多在5000-10000字符，该设置可完整保留核心上下文，避免分段切割导致语义断裂 |
| `分段长度` | 1500–2000 字符 | 黑色家电投研文档的核心段落长度集中在1000-1800字符，该取值可保留段落语义完整性，同时降低索引超限概率 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 长文本技术文档与多页财报的解析耗时通常在300-500秒，该设置可避免因解析超时导致索引失败 |
| `UPLOAD_FILE_MAX_SIZE` | 200 MB | 单份黑色家电行业报告、技术手册的常见大小不超过200 MB，该取值可覆盖绝大多数文档上传需求 |
| `召回条数` | 前 10 条 | 黑色家电投研需关联多维度数据，10条召回结果可覆盖核心参考依据，避免遗漏关键SKU参数或销售数据 |
| `相似度阈值` | 0.75–0.85 | 黑色家电投研数据的字段与参数相似度较高，该阈值可过滤无关文档，同时保留相关度较高的投研参考内容 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：索引过程中弹出“文档长度超限”报错，或对话返回内容被截断。原因：未将`分段长度`调整至适配黑色家电长文本技术文档的取值，导致单段文本超出模型上下文限制。
- 现象：对话详情页仅展示用户与助理的交互文本，无法查看数据集召回、模型调用的内部执行记录。原因：未开启日志采集的对应开关，或未配置日志存储的必要参数。
- 现象：MongoDB 数据库中未查询到对话历史记录，或记录的`chat_history`字段为空。原因：未正确配置日志存储的连接字符串参数，或数据库读写权限未开放，导致日志无法正常写入。

## 怎么确认配好了
- 进入数据集管理页面，查看已上传的黑色家电文档的分段预览，核对分段长度是否符合预期设置。
- 发起一次针对特定SKU参数的对话，进入对话详情页，确认是否展示数据集召回的文档ID与调用参数。
- 登录MongoDB数据库，查询`fastgpt_chat_history`集合，确认是否存在对应对话的记录与`source_data`字段。
- 模拟触发长文本文档的索引流程，检查是否出现异常报错，验证配置的合理性。
