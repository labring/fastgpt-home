# IT 服务收益率的表单与交互

## 这个品类的数据长什么样
IT服务的收益率与行情日报数据，主要来自内部IT服务计费系统、对接的金融行情数据源接口，以及每日生成的服务交易结算日志。数据更新节奏为每日固定批次生成，覆盖前一自然日的全量服务运行与收益数据。文档结构以结构化字段集成为主，包含服务唯一标识、核算周期范围、基准收益核算值、当日行情波动参考值等核心字段。字段单位包含服务编码的字符串类型、核算周期的日期区间类型、收益核算值的数值类型、波动参考值的相对数值类型。

## 这些特征在「表单与交互」这一环带来什么约束
多源数据接入的特征要求表单支持多数据源的切换与映射配置，避免不同系统字段命名差异导致的解析错误。固定更新节奏要求表单内置定时触发选项，匹配日报的生成周期，无需手动触发。结构化字段的特征要求表单配置字段校验规则，确保必填项完整、数据格式匹配系统要求。金融场景下的收益数据敏感性要求交互环节增加预览校验步骤，在提交前确认数据范围与字段完整性。数据更新的批次性要求表单支持批量数据导入的交互选项，适配全量日报数据的提交需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `datasource_switch` | 开启 | 数据来源包含IT服务计费系统与行情接口，需切换拉取不同数据源 |
| `field_mapping_rule` | 预设IT服务日报字段模板 | 不同数据源字段命名存在差异，预设模板可减少配置工作量 |
| `schedule_cron_expression` | `0 0 2 * * ?` | 日报覆盖前一日数据，需在当日凌晨固定时间生成 |
| `form_required_fields` | `服务编码、核算周期、基准收益值` | 这三类为日报核心标识与计算依据，缺失会导致数据无效 |
| `data_pull_timeout` | `300 秒` | 多数据源拉取需预留足够时间，避免超时中断 |
| `preview_before_submit` | 开启 | 金融场景需确认数据准确性后再生成日报 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用接口设置`stream: true`时，无法正确接收最后结果。原因：未配置`stream_final_collect`参数，仅接收流式片段未聚合完整结果。
- 现象：表单中知识库选择字段无法关联指定数据源。原因：未配置`field_mapping_rule`，未完成表单字段与知识库数据源的绑定映射。
- 现象：表单提交后生成的日报数据出现字段缺失。原因：未开启`form_required_fields`校验，未拦截必填项为空的提交请求。

## 怎么确认配好了
- 进入数据源管理界面，确认已绑定IT服务计费系统与行情接口的数据源，且字段映射规则已生效。
- 手动触发表单提交流程，检查是否弹出预览弹窗，确认核心字段完整展示。
- 配置定时触发任务后，验证触发逻辑是否匹配预设的更新节奏。
- 调用开放接口提交测试数据，确认接口返回的结果包含所有配置的必填字段。
