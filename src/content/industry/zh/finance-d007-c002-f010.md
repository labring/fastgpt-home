# 专业服务收益率的数据库与运维

## 这个品类的数据长什么样
数据来源为合规的金融市场公开行情接口、机构托管报告接口；更新节奏为每个交易日收盘后T+1日完成全量日报更新，部分日内高频行情子项为盘中实时推送快照；文档结构为按统计周期、产品分类分层的结构化CSV或关系型数据表；字段包括产品唯一标识、产品全称、产品类型、统计周期起始日、统计周期终止日、收益测算值、托管机构代码；单位为年化收益基点或单位净值变动值。

## 这些特征在「数据库与运维」这一环带来什么约束
多数据源同步要求配置优先级与冲突解决规则，避免不同接口的数据差异影响准确性；T+1更新的紧凑时间窗口，需优化批量导入的并发数与超时设置，同时配置定时任务调度规则避开金融市场交易时段；结构化字段多且需适配新增产品品类，要求数据库表预留扩展列或支持动态字段；实时子项的低延迟写入需求，需配置消息队列缓冲写入请求，避免耗尽数据库连接；同时需配置数据完整性校验与告警机制，确保日报数据无缺失或错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DB_BATCH_INSERT_SIZE` | 500-800 条/批次 | 适配T+1批量更新的行情数据量，避免单次写入触发数据库锁表 |
| `DATA_SYNC_TIMEOUT` | 1800 秒 | 覆盖全量数据同步的完整时间窗口，避免任务中途超时终止 |
| `MULTI_SOURCE_CONFLICT_POLICY` | 以官方公开接口数据为准 | 遵循金融专业服务的数据权威性要求，解决多数据源的数值差异 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 适配大型结构化行情数据表的解析耗时，避免大文件导入失败 |
| `DB_CONNECTION_POOL_SIZE` | 20-30 个 | 平衡实时子项写入与批量任务的连接需求，避免连接池耗尽 |
| `UPLOAD_FILE_MAX_SIZE` | 2000 MB | 支持全量行情数据文件的批量导入，适配大型日报数据集 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为Docker部署启动后抛出`Access denied for user 'root'@'localhost'`报错，原因是未修改`MG_DB_CONN_STR`、`MG_DB_PASSWORD`等环境变量，指向外部合规的行情数据库，仍使用内置测试数据库。
- 现象为批量同步T+1日报时任务超时终止，原因是未调整`DATA_SYNC_TIMEOUT`参数至适配全量数据同步的时长，默认值不足以覆盖完整同步流程。
- 现象为实时行情子项推送后出现`request timeout`状态码504，且数据库监控显示连接数达到上限，原因是未调低`DB_BATCH_INSERT_SIZE`参数，单次写入数据量过大导致数据库阻塞。

## 怎么确认配好了
- 执行预设的T+1批量同步任务，核对任务执行日志中的成功记录数，调整校验规则至匹配业务数据量要求。
- 发起单条实时行情写入请求，查看数据库连接状态监控，确认连接池未被耗尽，按需调整连接池参数。
- 导入标准格式的行情测试文件，检查解析后的字段完整性，调整文件解析相关参数至符合数据结构。
- 触发多源数据同步流程，查看冲突处理日志，确认数据按预设规则完成合并，无异常数据残留。
