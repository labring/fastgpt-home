# 专用设备收益率的模型接入与配置

## 这个品类的数据长什么样
专用设备收益率与行情日报的数据来源包含设备内置的运行传感器、对接的第三方金融行情接口，以及本地存储的历史交易日志。数据更新节奏分为实时行情与日报两类：实时行情每10秒刷新一次，每日收益率日报于凌晨2点前生成完成。单份日报文档为结构化格式，包含`device_id`、`collect_time`、`daily_return_value`、`market_fluctuation`四个核心字段，其中`collect_time`采用ISO8601格式时间戳，`daily_return_value`为浮点数类型，无强制百分比单位要求。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据拉取的需求要求配置多接口并发控制参数，避免同时请求设备传感器与第三方行情接口时触发限流。批量生成日报的场景要求配置较长的超时阈值，覆盖多设备数据汇总与模型推理的全流程耗时。固定的字段结构要求配置精准的输入映射规则，确保模型能正确识别设备编号、采集时间等核心字段。高频实时行情的拉取需求要求配置合理的请求频率限制，避免超出第三方接口的限流阈值。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `REQUEST_TIMEOUT` | `600 秒` | 适配单台设备收益率数据的拉取与模型推理时长，避免单请求超时中断 |
| `BATCH_EXECUTE_TIMEOUT` | `1200 秒` | 匹配每日批量生成收益率日报的全流程耗时，覆盖多设备数据拉取与汇总 |
| `FIELD_MAPPING_RULE` | `按采集时间、设备编号、当日收益率顺序映射` | 专用设备数据字段固定顺序，确保模型输入格式与设备上报结构一致 |
| `RATE_LIMIT_PER_MINUTE` | `30 次` | 匹配第三方金融行情接口的默认限流阈值，避免请求被拦截 |
| `LOG_REQUEST_ID_ENABLE` | `开启` | 记录每个模型请求的唯一标识，用于排查超时或异常问题 |
| `MAX_RETRY_TIMES` | `2 次` | 应对临时网络波动导致的设备数据拉取失败，减少手动干预 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：模型调用分组配置为1组，但单条请求耗时超过600秒，且未触发平台超时报错。原因：未正确配置`BATCH_EXECUTE_TIMEOUT`参数，平台默认超时阈值未覆盖专用设备批量数据拉取的耗时。
- 现象：调用自定义数据解析接口时，返回`408 Request Timeout`错误，且报错文案提示超时超过60000ms。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认阈值不足以适配专用设备大体积日报数据的解析。
- 现象：批量执行节点在线调试可完成全流程，但通过API调用时仅执行部分任务。原因：未配置`BATCH_REQUEST_MAX_WORKERS`参数，API调用时默认并发数低于在线调试的调试环境并发设置，导致任务堆积未完成。

## 怎么确认配好了
- 查看平台的参数配置界面，确认`REQUEST_TIMEOUT`、`BATCH_EXECUTE_TIMEOUT`等参数的取值与专用设备数据的实际耗时匹配。
- 发起单条设备数据的模型调用请求，通过日志获取`requestid`，核对请求耗时与配置的`REQUEST_TIMEOUT`阈值。
- 发起批量调用请求，核对所有设备任务的执行状态，确认未出现任务中断或超时的情况。
- 检查字段映射配置，确保模型输入的字段与专用设备上报的字段完全一致，无缺失或错位。
