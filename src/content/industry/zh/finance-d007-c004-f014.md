# 专用设备收益率的表单与交互

## 这个品类的数据长什么样
面向金融租赁、资产管理场景的专用设备，其收益率与行情数据来源包括嵌入式采集终端、工业物联网运维台账、对应品类的行业行情数据库。日度汇总数据每日凌晨3点前完成更新，单台设备的实时运行收益数据每10分钟同步一次。数据文档采用结构化JSON或CSV格式，包含设备唯一标识、统计周期、累计运行时长、合格产出量、单位耗材成本、总营收、收益率指标、所属行业行情基准字段。运行时长单位为小时，合格产出量单位为件，总营收单位为人民币元，收益率指标为无量纲系数。

## 这些特征在「表单与交互」这一环带来什么约束
多来源、双更新节奏的数据特征要求表单支持切换统计维度与刷新频率，避免加载冗余数据。多维度结构化字段的存在要求表单支持分组展示，降低用户查找成本。不同设备型号的自定义字段差异要求交互支持动态挂载专属字段，适配个性化配置需求。实时数据的同步延迟要求表单配置加载状态提示，避免用户重复提交请求。行业行情基准字段的差异要求交互支持自定义基准值的输入与匹配，保障数据对比的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `dataset_sync_interval` | 600 秒（实时模式）、86400 秒（日度模式） | 匹配专用设备的双更新节奏，精准控制数据同步频率 |
| `form_field_group` | 「基础设备信息」「运行参数」「收益核算」 | 适配专用设备多维度字段的展示逻辑，优化表单可读性 |
| `dynamic_form_switch` | 开启 | 支持按设备型号挂载自定义字段，覆盖专用设备的个性化配置场景 |
| `form_submit_validate` | 开启必填项校验 | 避免无效表单提交，保障收益数据的字段完整性 |
| `loading_timeout` | 30 秒 | 适配多数据源聚合的加载时长，防止超时中断数据获取 |
| `refresh_trigger_mode` | 手动触发+定时触发双模式 | 兼顾实时监控与日报播报的交互需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：提交表单后无响应或未触发后续流程。原因：未配置`form_submit_validate`的回调逻辑，或`refresh_trigger_mode`设置为仅定时触发，未匹配手动提交场景。
- 现象：加载的收益数据字段为空。原因：未配置`data_source_filter`或配置范围过窄，未包含专用设备的实际数据源类型，导致数据拉取失败。
- 现象：实时数据更新延迟超过设定阈值。原因：`dataset_sync_interval`设置为86400秒，误将日度同步参数用于实时模式，未区分统计周期配置。

## 怎么确认配好了
- 进入应用的表单配置界面，核对字段分组与`form_field_group`的配置内容是否一致，确认`dynamic_form_switch`处于开启状态。
- 提交一条包含测试设备信息的表单，查看是否弹出校验提示（若开启必填项），并确认触发预设的后续回调逻辑。
- 切换统计周期为实时模式，检查数据刷新间隔是否匹配`dataset_sync_interval`的预设取值，加载超时提示是否正常触发。
- 手动触发一次数据拉取，确认返回的数据集包含专用设备的专属字段，无缺失或无关数据。
