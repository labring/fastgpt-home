# 个护用品收益率的部署与升级

## 这个品类的数据长什么样
个护用品的收益率相关数据来源包括品牌公开的月度成本结构报表、电商平台的SKU级销售流水、线下商超的POS机零售数据。数据更新节奏分为两类：当日SKU的单量与营收数据每日更新，覆盖全渠道的毛利率、库存周转相关的收益率统计每周更新。单条数据文档包含SKU唯一标识、品牌归属、销售渠道、统计周期、单位进货成本、当期销售额、当期运营成本、当期利润额字段，其中销售额、运营成本、利润额单位为人民币元，单位进货成本单位为人民币元/件。

## 这些特征在「部署与升级」这一环带来什么约束
多源分散的数据来源要求部署阶段配置多接口对接的权限与超时参数，避免因不同数据源的接口规范差异导致同步失败。不同更新频率的数据源需要区分定时任务的调度周期，升级阶段需新增兼容日更增量与周更全量数据的适配逻辑。细粒度的SKU级数据包含多字段关联，部署时需配置精准的字段映射规则，防止单位不匹配引发的收益率计算错误。零售数据的实时性波动要求部署阶段添加数据校验阈值，升级阶段需优化异常数据的过滤与补全逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DATA_SYNC_TIMEOUT` | `300 秒` | 个护SKU数据单条体量较小，多源同步的平均耗时在120-180秒，预留合理缓冲时间避免同步中断 |
| `PARSE_FIELD_MAPPING` | 按SKU标识、销售周期、销售额、利润额映射为标准知识库字段 | 个护数据的核心字段与标准检索字段需明确对应，避免检索时出现字段缺失或匹配错误 |
| `SCHEDULE_CRON` | `0 0 1 * * *` 与 `0 0 * * * *` | 周更全量数据在每周一凌晨执行，日更增量数据在每日凌晨执行，贴合个护数据的官方更新节奏 |
| `MAX_CONTEXT_LENGTH` | `800-1200 字符` | 个护收益率数据的单条详情包含多字段，该区间可覆盖核心信息且符合模型输入的常规限制 |
| `RECALL_TOP_K` | `前3条` | 个护SKU的收益率数据相关性较强，过多召回会引入冗余信息，3条可覆盖核心对比维度 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 个护的月度销售报表单份体量通常在100-300 MB，预留合理缓冲空间适配批量上传需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：执行`docker-compose up`后出现`connection refused`报错，原因：未提前启动依赖的数据源代理容器，个护数据同步需要对接电商与监测平台接口，依赖容器未启动会阻断数据拉取。
- 现象：模型管理页面未显示配置的第三方模型，仅修改`BASE_URL`参数未生效，原因：未同步更新`MODEL_PROVIDER_CONFIG`中的所有关联配置项，或未重启容器加载新配置，个护收益率播报对模型接口稳定性要求较高，配置未生效会导致检索失败。
- 现象：知识库仅支持加载最多30个SKU数据文件，无法添加更多个护品类数据，原因：开源版默认配置了`MAX_UPLOAD_FILE_COUNT`为30，未调整该参数以适配个护多SKU的批量上传需求。

## 怎么确认配好了
- 执行`docker-compose ps`，查看所有相关容器的状态均为`Up`，确认部署的服务正常运行。
- 进入知识库管理页面，手动上传一份测试用的个护销售数据文件，查看解析后的字段与预设的`PARSE_FIELD_MAPPING`配置一致。
- 触发一次手动数据同步，查看同步日志中无超时或字段不匹配的报错，确认数据源对接正常。
- 在模型测试页面输入与个护收益率相关的查询，查看返回结果中包含符合配置的召回条数，确认检索逻辑正常。
