# 休闲食品收益率的分享与嵌入

## 这个品类的数据长什么样
休闲食品的收益数据来源包含线下连锁商超POS结算数据、主流电商平台店铺销售数据、品牌方供应链采购台账。数据更新节奏存在分层：线下商超数据每周更新一次，电商平台实时交易数据每日更新，品牌方月度台账数据每月更新。文档多采用CSV或JSON格式，每条记录对应单个SKU的单周期收益信息，字段包含商品标识、商品名称、包装规格、统计周期、终端售价（单位：元/件）、原料总成本（单位：元/件）、单位利润（单位：元/件），无百分比类数值字段。

## 这些特征在「分享与嵌入」这一环带来什么约束
休闲食品品类的多更新节奏、多SKU属性及差异化字段，会对分享与嵌入环节带来多重约束。首先，分层更新的数据源需要匹配不同的同步频率配置，实时分享电商端数据需启用流式协议，而线下周更数据则可采用定时批量同步。其次，单条记录字段较多且SKU数量庞大，分享接口需支持按SKU标识、统计周期等多维度过滤，嵌入页面的检索组件需适配多字段的筛选逻辑。此外，非百分比的单位利润字段，需要在嵌入页面的展示组件中提前配置单位映射，避免展示信息歧义。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 休闲食品收益数据单条记录字段较多，需容纳多SKU的完整收益信息 |
| `召回条数` | `前15–20 条` | 休闲食品品类SKU数量较多，需覆盖足够多的相关商品数据 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 批量导入多SKU的收益文档时，单文件数据量较大，需延长解析超时时间 |
| `SSE_PROTOCOL_ENABLE` | `true` | 支持流式推送实时更新的电商端收益数据，适配高频行情播报需求 |
| `enable_external_image_preview` | `true` | 让嵌入网页的聊天机器人回复中的图片在外部窗口放大缩小，避免iframe内查看受限 |
| `API_SHARE_ENABLED` | `true` | 开启知识库分享API功能，支持将收益查询结果对外输出用于嵌入场景 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用分享API时返回`400 Bad Request`，提示“仅支持stdio进程”。原因：未开启`SSE_PROTOCOL_ENABLE`配置，导致分享接口无法识别流式协议请求，无法适配实时行情的推送需求。
- 现象：调试页面可召回知识库的休闲食品收益数据，但分享API调用后返回空结果。原因：分享API未关联对应知识库的权限配置，或未开启`API_SHARE_ENABLED`开关，导致接口无法调用知识库内的收益数据。
- 现象：嵌入网页的聊天机器人回复中带有收益相关的图表图片，仅能在iframe内部缩放查看，无法全屏或外部放大。原因：未开启`enable_external_image_preview`配置，导致图片预览被限制在iframe容器内。

## 怎么确认配好了
- 调用分享API接口，传入休闲食品SKU查询关键词，检查返回结果是否包含对应商品的收益数据，确认配置生效。
- 打开嵌入聊天机器人的测试页面，发送包含多个SKU的查询，检查返回结果的上下文是否足够容纳多组收益数据，确认配置适配当前数据量。
- 在测试页面发送包含收益图表的查询，点击回复中的图片，检查是否可在外部窗口打开并自由缩放，确认配置生效。
- 导入批量休闲食品收益文档，检查解析进度是否正常完成，未出现超时报错，确认配置适配当前文档规模。
