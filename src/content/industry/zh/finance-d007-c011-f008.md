# 休闲食品收益率的工具调用与插件

## 这个品类的数据长什么样
休闲食品的收益率与行情数据主要来自线下商超POS终端、线上电商平台销售接口、供应链上游原料报价数据库。数据更新节奏分两类：线下零售数据每日凌晨更新前一日全量数据，线上电商数据每小时刷新实时成交价。单条数据文档包含商品唯一标识、品类细分标签、包装规格、计价单位、当日终端售价、进货成本价、渠道来源字段，其中计价单位包含元/袋、元/千克、元/箱等多种细分单位，进货成本价字段关联对应批次的原料采购价格，需通过批次ID关联获取完整核算所需的基准值。

## 这些特征在「工具调用与插件」这一环带来什么约束
休闲食品的多源数据来源、差异化更新节奏与多计价单位特征，对工具调用环节带来明确约束。线下零售数据接口设有每日调用限额，需配置请求间隔参数避免触发限流。不同包装规格对应元/袋、元/千克等多种计价单位，工具调用时需传入商品规格参数匹配对应计价逻辑，否则无法完成收益率的准确核算。实时电商数据每小时刷新，调用频率需与更新节奏对齐，避免拉取过期的当日成交价数据。进货成本价字段关联采购批次，调用时需传入批次ID才能获取基准核算值，否则返回的行情数据无法完成有效收益率计算。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `TOOL_REQUEST_INTERVAL` | `30 秒` | 匹配线下零售数据接口的每日调用限额，避免触发限流 |
| `TOOL_REQUIRED_PARAMS` | `["商品ID", "包装规格", "采购批次ID"]` | 休闲食品数据需多参数匹配才能获取完整的计价与成本核算字段 |
| `TOOL_REQUEST_TIMEOUT` | `60 秒` | 覆盖多源数据聚合时的网络延迟，避免中途中断请求 |
| `RESPONSE_PARSE_RULE` | `按计价单位分组计算收益率` | 适配休闲食品多计价单位的特征，统一核算逻辑 |
| `TOOL_CALL_MAX_RETRIES` | `3 次` | 应对网络波动导致的请求失败，减少无效重试次数 |
| `STREAM_OUTPUT_FILTER` | `仅保留核算后收益率字段` | 过滤工具返回的原始行情数据，仅输出播报所需内容 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用`api/v1/chat/completions`接口获取流数据时，返回的分段数据未按字段拼接，导致收益率播报内容混乱。原因：未配置`STREAM_OUTPUT_FILTER`参数，未过滤原始行情字段，直接拼接流数据片段。
- 现象：工具调用完成后，界面同时显示工具调用日志与AI播报内容，不符合仅输出播报结果的需求。原因：未启用`STREAM_OUTPUT_FILTER`配置，未屏蔽工具调用的原始请求与响应内容。
- 现象：搭建智能体时调用上传文件接口返回`413 Request Entity Too Large`错误，无法获取商品进货的CSV文件数据。原因：未配置`UPLOAD_FILE_MAX_SIZE`参数，或设置的阈值小于文件实际大小，导致文件上传被拦截。

## 怎么确认配好了
- 发起一次工具调用请求，检查返回的字段是否包含所有配置的必填参数，核对计价单位与商品规格是否匹配。
- 查看工具调用日志，确认请求间隔符合配置的`TOOL_REQUEST_INTERVAL`值，未触发限流报错。
- 测试流数据返回，检查输出内容仅包含AI播报所需的收益率信息，无原始工具调用内容。
- 上传测试用的商品报价文件，确认工具可以读取并关联采购批次ID完成核算。
