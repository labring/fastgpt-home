# 住宅开发收益率的对话日志与审计

## 这个品类的数据长什么样
住宅开发品类的数据主要来自房企项目管理系统、财务核算台账与销售回款系统，按项目开发节点更新，月度归集单项目月度收支数据，每季度更新整体收益测算数据。单项目数据为独立结构化文档，包含项目基础标识、各阶段成本明细、分周期回款记录、资金占用台账、静态回报周期测算字段，字段单位统一为万元、平方米、月等标准工程与财务单位，无自定义非标字段。

## 这些特征在「对话日志与审计」这一环带来什么约束
单项目独立文档的特征要求对话日志绑定唯一项目ID，避免跨项目数据调用混淆；按节点更新的节奏要求日志记录数据调用时的版本标识，审计时可溯源对应周期的原始数据；多系统来源的字段特征要求日志完整记录调用的字段范围与数据链路，确保审计可追溯数据来源；工程与财务混合字段的特征要求日志保留字段单位的匹配记录，避免单位转换错误导致的审计偏差。同时，住宅开发项目周期通常较长，对话日志需保留全周期的调用记录，支持跨周期的审计追溯。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `SESSION_LOG_RETENTION_DAYS` | `365 天` | 住宅开发项目周期通常跨1-3年，需保留全周期审计记录 |
| `LOG_DATA_SOURCE_TRACE_ENABLE` | `开启` | 住宅开发数据来自项目管理、财务、销售多系统，需溯源确保数据链路可查 |
| `MAX_SESSION_CONTEXT_LENGTH` | `8000–12000 字符` | 单项目数据文档包含多阶段成本、回款明细，需完整保留上下文用于审计 |
| `PARSE_PROJECT_DATA_TIMEOUT` | `300 秒` | 单项目数据文档字段较多，需足够时间完成结构化解析与日志记录 |
| `AUDIT_LOG_EXPORT_FORMAT` | `CSV` | 符合财务审计的通用归档格式，便于后续审计校验 |
| `LOG_FIELD_UNIT_VALIDATE` | `开启` | 住宅开发数据包含万元、平方米、月等多类单位，需校验避免单位匹配错误 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：查看单项目对话日志详情时返回`500 Internal Server Error`，容器日志显示`cannot read properties of undefined (reading 'project_id')`。原因：未配置`LOG_RECORD_FIELDS_WHITELIST`或白名单遗漏`project_id`字段，导致日志加载时无法匹配项目标识。
- 现象：上传住宅开发项目的月度成本明细文件后，大模型回复未引用上传数据内容。原因：未开启会话上下文自动关联上传数据的配置，或上传数据未绑定当前项目ID。
- 现象：对话日志中无法记录操作人的身份信息，审计无法追溯具体操作主体。原因：未配置渠道的用户标识同步参数，或未开启操作信息日志记录开关。

## 怎么确认配好了
- 执行单项目对话日志查询，核对日志中是否包含项目标识、操作时间、调用字段范围等预设核心内容，确认字段白名单配置生效。
- 上传单项目数据文件后，触发大模型查询该项目的相关数据，核对回复是否引用上传文件中的明细内容，确认上下文关联配置生效。
- 查看系统后台的审计日志模块，确认已记录数据来源链路信息，验证数据源溯源配置生效。
- 导出审计日志，核对导出格式符合预设要求，确认导出格式配置生效。
