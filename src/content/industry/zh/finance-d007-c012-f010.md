# 住宅开发收益率的数据库与运维

## 这个品类的数据长什么样
住宅开发收益率相关数据主要来源于房企内部ERP成本系统、不动产登记网签接口、项目工程管理平台三类数据源。数据更新节奏为自然月度固定节点更新，单份数据文档对应单个住宅开发项目，包含项目立项编号、规划计容面积、各阶段成本明细、当期销售及回款数据、融资明细等字段。部分字段带有行业通用计量单位，如土地出让金总额、工程进度款累计支付额的计量单位为元，规划计容面积的计量单位为平方米。

## 这些特征在「数据库与运维」这一环带来什么约束
多源数据接入的需求要求数据库支持跨系统字段映射与增量同步能力，避免重复全量导入数据。月度固定更新的节奏要求运维脚本配置定时触发任务，确保数据更新的一致性与及时性。单项目数据包含多维度明细字段的结构，要求数据库表结构合理拆分，避免单表字段过多导致查询效率下降。同时，数据涉及房企内部敏感经营信息，要求数据库配置严格的权限管控规则，限制非授权访问。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DB_SYNC_INTERVAL` | `2592000 秒` | 匹配住宅开发收益率数据的月度更新节奏，避免频繁同步占用系统资源 |
| `PARSE_DATA_BATCH_SIZE` | `100 条` | 单项目数据明细较多，批量过大会导致内存溢出，批量过小会延长同步时长 |
| `DB_INDEX_FIELDS` | `["project_id", "update_time", "sales_amount"]` | 日常查询多按项目ID、更新时间筛选，以及销售金额聚合，建立对应索引可提升查询效率 |
| `DATA_CLEAN_RULES` | `{"field_mapping": {"land_cost": "土地出让金总额"}, "null_value_handle": "default_zero"}` | 多源系统字段命名不一致，需统一映射；空值需补零避免后续计算异常 |
| `DB_BACKUP_CRON` | `0 0 2 1 * *` | 每月1号凌晨2点触发备份，在月度数据更新完成后留存全量数据副本 |
| `CONNECTION_TIMEOUT` | `30 秒` | 内部系统接口响应存在一定延迟，超时过短会导致数据同步任务失败 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 安装数据库连接插件时提示`500 Internal Server Error`，未配置数据库连接的环境变量`MONGO_URI`，导致插件初始化时无法建立有效连接。
- 月度数据同步完成后，部分住宅开发项目的融资明细字段为空，未配置`DATA_CLEAN_RULES`中的字段映射规则，不同内部系统的字段命名差异导致数据无法正确写入目标表。
- 数据库扫描触发已知安全漏洞告警，提示当前MongoDB版本`5.0.18`存在高危漏洞，未升级至官方发布的修复版本。

## 怎么确认配好了
- 执行一次手动数据同步任务，查看同步日志中是否存在字段映射失败、连接超时的报错信息，确认无异常后检查目标数据库中新增的项目数据是否完整。
- 登录数据库管理界面，查看`project_id`和`update_time`字段的索引是否已创建，确认索引状态为正常启用。
- 触发数据库备份任务，检查备份文件的生成路径和文件大小是否符合预期，确认备份流程无中断。
- 访问FastGPT的数据库连接插件管理页面，查看插件状态为已连接，无异常告警提示。
