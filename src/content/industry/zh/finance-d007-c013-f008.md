# 保险收益率的工具调用与插件

## 这个品类的数据长什么样
保险收益率数据主要来自保险公司官方产品公告、银保监会监管公示平台及第三方合规聚合渠道。更新节奏因产品类型存在差异：万能险结算收益率每日更新，分红险收益率按季度披露，传统寿险收益率按年度披露。数据文档多为结构化表格或标准化JSON格式，核心字段包含产品唯一标识、报告周期、收益率基准值、最低保障收益、产品风险等级、承保主体名称，无统一的字段命名规范。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据源分散且更新节奏差异大，要求工具调用支持动态配置多数据源切换，并需适配不同产品的拉取周期。字段命名与结构不统一，要求工具调用的参数映射模块支持自定义字段匹配规则，避免因数据源差异导致解析失败。部分数据源为非结构化的监管公示文档，要求工具调用前增加格式校验步骤，过滤无效或不规范的数据。部分接口需携带合规认证参数，要求插件配置中支持自定义请求头与鉴权参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `pullFrequency` | `86400 秒` | 适配万能险每日更新的披露节奏，平衡数据时效性与接口调用频次 |
| `fieldAliasMap` | `{"结算收益率":"年化收益","承保公司":"发行主体"}` | 匹配不同数据源的字段命名差异，统一输出格式 |
| `apiTimeout` | `30 秒` | 覆盖保险数据接口的常规响应时长，避免因接口延迟导致调用失败 |
| `retryTimes` | `2 次` | 应对接口临时波动，减少单次调用失败的概率 |
| `dataSourceWhitelist` | `["银保监会公示平台","保险公司官方公告"]` | 确保数据源合规，避免调用非授权接口 |
| `parseStrictMode` | `false` | 兼容部分数据源的轻微格式不规范，提升解析成功率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用第三方API后返回的Set-Cookie字段无法被解析，工具调用节点报错提示“响应字段未匹配”。原因：默认的HTTP请求组件未开启`parseSetCookie`参数，未启用Cookie解析配置。
- 现象：工作流发起请求后直接报错，状态码返回400。原因：未配置`requestHeader`中的`Content-Type`为`application/json`，或未将请求参数序列化为正确格式。
- 现象：全局变量初始值设置后未生效，变量更新后无变化。原因：未开启`persistGlobalVar`参数，或未在工作流入口节点配置变量初始化触发条件。

## 怎么确认配好了
- 发起一次手动触发的工具调用，检查返回结果中是否包含预期的保险收益率字段，字段名称与`fieldAliasMap`中的配置一致。
- 查看工具调用节点的日志，确认请求耗时未超过`apiTimeout`的配置值，无超时报错。
- 检查全局变量的存储面板，确认初始值已被正确写入，且后续更新操作能同步修改变量值。
- 对比数据源返回的原始数据与解析后的结果，确认字段映射规则已生效，无遗漏或错误匹配的字段。
