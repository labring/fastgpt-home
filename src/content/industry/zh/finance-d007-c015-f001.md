# 储能收益率的HTTP 接口与外部系统

## 这个品类的数据长什么样
储能相关的收益率与行情日报数据，主要来源于国内区域电力现货交易市场公开API、储能电站本地SCADA监控系统、电网调度并网平台三类数据源。数据更新节奏为T+1日终更新，即每日凌晨完成前一自然日的全量数据核算与发布，部分实时充放电节点数据每15分钟刷新，但日报仅取日终汇总值。数据文档采用标准JSON格式，包含电站唯一标识、装机额定功率、当日充放电总电量、当日上网结算电价、运维成本分摊、当日收益核算值等字段。功率单位为千瓦，电量单位为千瓦时，电价单位为元/千瓦时，收益核算值单位为元。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源数据的对接需求要求配置多套鉴权参数与请求地址，需分别适配电力交易平台、电站监控系统的不同接口规范。T+1的更新节奏要求定时同步任务的触发时间需晚于行业通用的凌晨2点数据发布时间，避免请求时数据尚未生成。JSON格式的固定字段结构要求接口请求需携带电站ID列表作为查询参数，且返回字段需严格匹配预设键名，否则会导致数据解析失败。收益核算值以元为单位且涉及财务对账，要求外部系统对接时保留足够的数值精度，否则会引发对账偏差。部分电网平台的公开API存在QPS限流限制，需配置合理的请求频率，避免触发限流导致接口调用失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `external_api_timeout` | `30 秒` | 储能数据源接口多为企业内部或电网平台，响应延迟通常在10-25秒，设置30秒可覆盖正常请求且避免长时间阻塞 |
| `api_auth_type` | `API_KEY 鉴权` | 多数储能交易与监控平台要求使用固定API密钥进行身份验证，符合行业通用对接规范 |
| `request_rate_limit` | `10 请求/分钟` | 电网调度平台的公开API通常限制单密钥每分钟请求不超过15次，设置10次可避免触发限流 |
| `data_sync_cron` | `0 3 1 * * ?` | 对应每日凌晨3点触发T+1数据同步，匹配储能日报的更新节奏 |
| `response_field_mapping` | `{"电站ID":"station_id","当日收益":"daily_profit"}` | 匹配储能数据文档的标准字段名，避免字段不匹配导致数据解析失败 |
| `precision_keep_digits` | `2` | 储能收益核算值以元为单位，保留两位小数可满足财务对账的精度要求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用储能数据接口返回401 Unauthorized状态码，未正确配置`api_auth_type`为API_KEY鉴权，或传入的密钥与平台要求不匹配。
- 定时同步任务执行后返回空数据，`data_sync_cron`设置早于储能平台的日报更新时间，导致请求时数据尚未生成。
- V4.9.3版本的本地部署实例在Ubuntu Server 24.04环境中调用外部接口时出现连接超时，未在系统防火墙规则中开放对应接口的出站端口，导致请求无法到达外部数据源。

## 怎么确认配好了
- 手动调用配置好的HTTP接口，检查返回的JSON字段是否包含预设的`station_id`、`daily_profit`等键名，且数值格式符合单位要求。
- 查看定时任务日志，确认每日凌晨的同步任务在储能平台更新时间后执行，且无报错记录。
- 在外部系统的测试环境中导入接口返回的测试数据，核对收益核算值的精度是否符合预期。
- 调整`request_rate_limit`的取值至低于限流阈值，触发限流后检查FastGPT的限流日志是否正常生成。
