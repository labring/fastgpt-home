# 光伏收益率的HTTP 接口与外部系统

## 这个品类的数据长什么样
光伏项目收益率相关数据主要来自光伏电站的SCADA监控系统、电网并网调度平台两类数据源，用于金融机构的项目收益率日报播报。数据更新节奏为每日凌晨完成前一日全量统计，单条数据为结构化JSON格式。核心字段包含电站唯一标识、统计日期、当日总发电量、并网售电量、自发自用电量、单位装机发电量，各字段均对应明确物理单位，例如发电量以千瓦时为单位，单位装机发电量以千瓦时每千瓦为单位，无额外格式化修饰字段。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
用于金融机构的光伏项目收益率日报播报，多源数据需求要求HTTP接口需支持对接至少两个不同的外部系统，需配置跨源请求的认证参数。日更的更新节奏决定了HTTP拉取无需高频执行，定时任务的间隔需匹配数据更新周期，避免无效请求占用金融系统的资源。字段携带明确单位的特征，要求接口返回需保留单位信息，或下游系统需统一解析单位字段，防止数据使用时出现单位混淆影响报表准确性。按电站维度的聚合需求，要求HTTP接口需支持按电站ID作为过滤参数，实现单电站数据的精准拉取。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `request_timeout` | `300-600 秒` | 光伏跨源数据拉取需对接逆变器平台与电网接口，总耗时较长，需覆盖全流程耗时 |
| `retry_count` | `2-3 次` | 电网接口可能出现临时波动，重试可降低单次请求失败率 |
| `filter_param_key` | `station_id` | 光伏数据按电站维度聚合，需按电站ID过滤返回结果，精准匹配单电站数据 |
| `response_parse_mode` | `json_path` | 光伏数据返回为结构化JSON格式，需提取指定字段用于日报生成与下游流转 |
| `schedule_interval` | `86400 秒` | 光伏收益率数据为日更维度，无需高频拉取，匹配每日更新节奏 |
| `max_response_size` | `100 MB` | 单电站全量历史数据的单次返回上限，避免工作流节点出现内存溢出 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为HTTP请求返回数据后，下游节点无法获取提取的变量，原因是未正确配置`response_parse_mode`为`json_path`，或未填写符合格式的JSONPath表达式。
- 现象为定时任务触发后返回400状态码，原因是未在请求参数中携带`station_id`字段，无法匹配光伏电站的维度过滤规则。
- 现象为HTTP请求超时或被接口限流，原因是误将`schedule_interval`设置为小于86400秒，高频拉取触发外部系统的访问限制。

## 怎么确认配好了
- 手动触发HTTP请求节点，查看返回结果是否包含预期的光伏数据字段，核对字段单位与数据源定义一致。
- 检查工作流的定时任务日志，确认每日凌晨按设定间隔触发请求，无重复或遗漏执行记录。
- 验证提取的变量是否能正确传递到下游日报生成节点，无空值或格式错误问题。
- 模拟接口延迟场景，调整`request_timeout`为较短值，确认重试机制正常触发且无数据丢失。
