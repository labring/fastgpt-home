# 光模块收益率的工作流编排

## 这个品类的数据长什么样
光模块的行情与收益率数据主要来自金融终端的通信元器件板块行情接口、证券市场公开交易数据接口，以及头部光模块厂商的官方报价更新。更新节奏为：实时行情每5分钟同步一次，日收益率汇总数据在每个交易日收盘后1小时内完成更新。文档结构为结构化数据集，包含光模块型号、品牌厂商、当日成交均价、当日价格变动额、累计持仓收益额、当日成交量，单位分别为元/件、元/件、元、件。

## 这些特征在「工作流编排」这一环带来什么约束
多数据源的存在导致字段格式存在差异，因此工作流需要配置多源数据对齐节点，统一字段映射规则。不同更新节奏的数据源要求工作流设置双定时触发规则，分别适配5分钟级实时同步和收盘后的日度汇总。光模块品类的型号维度较多，单批次数据集的字段数量较多，工作流需要配置数据分片节点，避免单次处理数据量过大导致超时。不同数据源的调用频次限制存在差异，工作流需要配置请求限流参数，适配各接口的调用配额，避免触发调用限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `定时触发间隔` | `300 秒`（实时行情）、`3600 秒`（日度汇总） | 光模块实时行情每5分钟更新一次，日度汇总数据在收盘后1小时内完成 |
| `数据库连接端口` | `3306`（MySQL）、`5432`（PostgreSQL） | 主流结构化数据库的默认端口，适配光模块行情数据的持久化存储 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 光模块行情数据集的文件体积通常较大，需要足够的解析时长 |
| `REQUEST_RATE_LIMIT` | `10 次/分钟` | 多数公开通信行业数据接口的默认调用配额，避免触发`429 Too Many Requests`错误 |
| `多源数据字段映射规则` | 按`光模块型号`作为主键对齐字段 | 光模块品类的型号具有唯一性，可作为跨数据源的数据关联依据 |
| `文件上传允许格式` | `.csv`、`.json` | 光模块行情数据通常以结构化格式导出，适配工作流的批量数据导入测试 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：数据库连接节点无法输入端口号，配置保存失败。原因：未展开高级配置面板，默认隐藏了端口号配置项。
- 现象：发布的工作流无法生成多人扫码的分享链接，仅支持单用户直接调用。原因：未开启工作流的公开分享权限，默认仅开放私有调用权限。
- 现象：测试环节无法上传文件触发工作流，无文件选择入口。原因：未启用工作流的文件上传测试开关，默认关闭了该功能。

## 怎么确认配好了
- 核对定时触发规则，确认包含适配不同数据更新节奏的多个触发周期，触发间隔与对应数据源的更新频率匹配。
- 测试数据库连接，确认端口号等配置项正确，可正常拉取光模块行情数据集。
- 启用文件上传测试功能，上传对应格式的测试文件，确认工作流可正常接收并解析文件内容。
- 模拟工具调用流程，确认请求限流参数设置合理，无高频调用报错。
