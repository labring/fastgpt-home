# 光模块收益率的数据库与运维

## 这个品类的数据长什么样
光模块收益率相关数据的来源包括光模块厂商生产台账、行业现货交易平台报价、运营商采购订单数据库三类。更新节奏按数据类型区分：现货报价每小时更新一次，生产台账每日更新，采购订单数据每周同步。单条数据文档包含光模块型号、厂商名称、采购单价、出货单价、传输速率、单位功耗、生产批次、出货日期八个核心字段，其中单价单位为元/个，速率单位为Gbps，功耗单位为瓦，日期采用ISO 8601格式。

## 这些特征在「数据库与运维」这一环带来什么约束
多源异构的数据源与差异化更新节奏，要求配置多任务同步机制，区分实时行情数据与离线业务数据的存储优先级。核心字段以光模块型号为唯一业务标识，需建立全局唯一索引避免重复录入，同时多维度字段（成本、售价、性能）需支持联合查询，因此需要合理设计表结构与联合索引策略。部分数据源存在字段缺失情况，需配置默认填充规则处理异常数据。高并发的行情查询需求，要求数据库采用分片部署模式均衡负载，同时设置合理的超时阈值避免请求阻塞。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `db_sync_interval` | `300-3600 秒` | 光模块现货报价每小时更新、生产数据每日更新，该区间兼顾实时性与服务器资源占用 |
| `db_shard_key` | `model_code` | 光模块以型号为核心业务标识，按型号分片可均衡跨节点的查询与写入负载 |
| `data_source_whitelist` | `['vendor_api', 'spot_market_api', 'procurement_db']` | 限定合法数据源范围，避免非授权数据写入数据库 |
| `query_timeout` | `10-30 秒` | 光模块数据涉及多表关联查询，该时长可覆盖多数正常查询场景 |
| `backup_cron` | `0 2 * * *` | 每日凌晨2点系统负载最低，此时执行全量备份可降低业务影响 |
| `null_field_policy` | `fill_default` | 部分数据源缺失生产批次字段，填充默认值可避免查询时出现空指针异常 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：查询数据库返回的光模块数据为原生JSON格式，需额外编写代码解析。原因：未配置数据库返回格式为结构化行数据，默认将存储的序列化文档直接返回。
- 现象：并发调用量达每秒2-3次时，数据库查询返回空结果或`504`状态码。原因：未按`model_code`设置分片键，高并发下单节点负载过载导致请求被丢弃或超时。
- 现象：数据库写入失败，提示主键重复错误。原因：未建立`model_code`字段的唯一索引，同型号不同批次的光模块数据被识别为重复条目。

## 怎么确认配好了
- 执行单条光模块型号的精准查询，核对返回字段与预设的业务字段完全匹配，确认数据结构配置正确。
- 模拟设定并发量的请求，查看数据库监控面板的CPU、内存与连接数指标，确认未出现过载情况。
- 查看数据同步任务的运行日志，确认多源数据按配置的时间间隔正常写入，无异常报错信息。
- 测试携带缺失字段的光模块数据写入，确认系统按配置策略完成处理，无写入失败记录。
