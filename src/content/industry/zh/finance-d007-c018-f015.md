# 光模块收益率的部署与升级

## 这个品类的数据长什么样
光模块收益率相关数据的来源包括通信行业大宗商品交易平台的成交报价、上游光芯片及结构件的采购成本数据、厂商公开的出货统计。数据每日凌晨更新前一日的全量数据集，以结构化JSON或CSV格式输出。文档每行对应单一型号光模块，包含`module_model`、`daily_avg_price`、`raw_material_cost`、`daily_shipping`四个核心字段，其中价格与成本字段单位为元/只，出货量单位为只，无百分比类量化指标。

## 这些特征在「部署与升级」这一环带来什么约束
光模块数据多源分散的特征，要求部署阶段需对接至少3类不同数据源的接口，需配置统一的数据格式转换逻辑，避免字段不匹配导致的计算偏差。每日全量更新的节奏，要求定时任务需设置凌晨时段触发，且需配置批量数据导入的超时阈值，防止单批次数据处理超时。多型号数据条目较多的特点，要求升级阶段需同步优化数据库索引配置，避免后续行情查询出现延迟。量化字段无冗余非结构化内容的特征，简化了数据清洗环节，但需严格校验字段的单位一致性，防止单位转换错误影响收益率计算。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `SYNC_DATA_CRON` | `0 0 2 * * *` | 匹配光模块收益率日报的每日更新节奏，凌晨时段触发可避开业务高峰 |
| `BATCH_DATA_IMPORT_LIMIT` | `6000 条` | 适配多数部署场景的服务器性能，覆盖主流光模块型号的全量数据导入需求 |
| `FIELD_VALIDATION_MODE` | `strict` | 光模块数据字段的单位与定义固定，严格校验可避免数据计算错误 |
| `MODEL_INVOKE_KEY` | 按数据源分类配置 | 不同数据源需调用独立API密钥，隔离调用权限与限额 |
| `API_CALL_RETRY_MAX` | `2–3 次` | 覆盖多数多源数据接口的临时抖动问题，避免重复请求过载 |
| `WORKFLOW_DEBUG_DISPLAY` | `开启` | 光模块收益率计算涉及多步骤数据转换，开启可快速排查异常 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流编排调试阶段，代码运行步骤不显示在调试面板中。原因：`WORKFLOW_DEBUG_DISPLAY`配置项被误设为关闭状态，导致调试界面隐藏代码执行步骤。
- 现象：调用光模块行情数据源时，输入特定型号查询返回400错误。原因：传入的查询参数未匹配光模块数据的字段格式，触发API参数校验失败。
- 现象：数据同步任务启动后，部分光模块型号的收益率数据缺失。原因：`BATCH_DATA_IMPORT_LIMIT`设置过低，超出限制的型号数据未被完整导入，导致日报数据不完整。

## 怎么确认配好了
- 查看定时任务日志，确认每日凌晨触发的数据同步任务正常启动，核对任务完成时间与`SYNC_DATA_CRON`配置的触发时间一致。
- 随机选取不同型号的光模块，手动触发数据导入流程，核对导入的字段与`FIELD_VALIDATION_MODE`的校验规则匹配。
- 进入工作流调试界面，确认代码运行步骤正常显示在调试面板中，验证`WORKFLOW_DEBUG_DISPLAY`配置生效。
- 调用模型接口测试光模块收益率计算，确认返回结果无字段缺失或单位异常，核对`MODEL_INVOKE_KEY`配置的权限正常。
