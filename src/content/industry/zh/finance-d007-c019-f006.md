# 免税收益率的对话日志与审计

## 这个品类的数据长什么样
这个品类的数据来自免税零售门店POS系统、离岛免税监管平台的每日经营上报，更新节奏为每日凌晨完成前一日全量数据同步。单份日报文档按门店、商品大类分组，包含门店编码、商品大类编码、当日营收总额、当日营业成本总额、当日客流总量、单位客流营收额6个核心字段。营收总额、营业成本总额以人民币元为单位，客流总量以人次为单位，单位客流营收额以元/人次为单位。单份日报的条目数随门店与商品大类覆盖范围变化，无固定上限。

## 这些特征在「对话日志与审计」这一环带来什么约束
每日全量更新的数据源特征要求对话日志需记录调用数据的日期戳与数据源标识，确保审计时可回溯数据来源的时效性。按门店与商品大类分组的文档结构，要求日志同步记录对话中设置的筛选条件（如指定门店编码、商品大类），便于匹配对话请求与返回数据的范围。多字段且带差异化单位的设计，要求日志完整记录每个返回字段的单位信息，避免审计中出现单位混淆。条目数无固定上限的特征，要求日志记录返回条目总数，便于核对对话返回结果的完整性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `LOG_RETENTION_DAYS` | `30–90 天` | 免税零售的经营审计通常覆盖月度至季度周期，保留30到90天可满足常规审计需求，同时避免存储占用过高 |
| `MAX_SESSION_LOGS` | `500–1000 条` | 单会话中关于免税收益率的查询通常不会超过500条，超出阈值可自动截断或归档，防止单会话日志过大 |
| `LOG_INCLUDE_FIELDS` | `["session_id", "query_time", "data_date", "filter_conditions", "return_entry_count", "unit_info"]` | 需要覆盖对话请求、数据日期、筛选条件、返回条目数与单位信息，满足审计溯源需求 |
| `LOG_AUDIT_WHITELIST` | `["/api/v1/chat/completions", "/api/v1/finance/report", "/api/v1/oneapi/completions"]` | 仅记录与收益率行情查询、大模型调用相关的API请求，过滤无关日志，提升审计效率 |
| `LOG_CLEAN_TRIGGER_SIZE` | `100 GB` | 按每日日志生成量估算，100 GB的阈值可预留足够的缓冲空间，避免存储溢出 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：执行`docker-compose up`后aiproxy_pg服务退出，日志显示“permission denied for log directory”。原因：未将日志挂载目录的权限配置为FastGPT运行用户可读写，导致数据库日志无法写入。
- 现象：对话返回的免税收益率数据单位与预期不符，部分字段显示为空。原因：未在`LOG_INCLUDE_FIELDS`中配置`unit_info`字段，导致审计时无法核对单位，且日志未记录缺失字段的原因。
- 现象：通过OneAPI调用大模型发起对话后，无法在FastGPT后台找到对应会话日志。原因：未将`/api/v1/oneapi/completions`加入`LOG_AUDIT_WHITELIST`配置项，导致相关请求未被记录。

## 怎么确认配好了
- 确认当前FastGPT版本为v4.9.7及以上，该版本新增了日志字段自定义与数据源标识记录的功能，可满足本次场景的配置需求。
- 登录FastGPT后台的日志管理页面，查看是否有指定门店与商品大类的对话日志，核对日志中是否包含`data_date`、`filter_conditions`等预设字段。
- 执行一次免税收益率查询对话，检查返回结果的字段单位是否与配置的`unit_info`一致，同时查看日志中是否记录了返回条目总数。
- 调用OneAPI接口发起大模型对话，检查后台是否生成对应的会话日志，确认白名单配置正确。
