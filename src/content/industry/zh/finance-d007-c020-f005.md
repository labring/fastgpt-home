# 兵器装备收益率的多轮对话与提示词

## 这个品类的数据长什么样
兵器装备收益率相关数据主要来自国防军工行业公开信息平台、军工集团官方披露的运营数据、行业协会发布的配套市场报告。更新节奏为月度更新核心配套业务的收益率相关数据，季度更新列装相关的整体收益指标。单条数据文档结构包含装备型号标识、统计周期范围、关联生产主体、投入核算字段、产出核算字段、对应收益核算字段。投入与产出字段的单位为万元，收益核算字段的单位为万元/单位产能。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据按月度和季度分周期更新，多轮对话中需要明确指定统计周期，否则模型无法匹配最新或指定范围的收益数据。单条数据包含多个关联字段，包括装备型号、生产主体等，提示词需要预设筛选规则，引导用户逐步明确具体筛选条件，避免返回跨品类或跨主体的混淆信息。收益核算字段的单位与其他金融品类的百分比类收益率不同，提示词需要明确标注单位规则，确保对话中对收益指标的理解一致。公开数据的披露存在批次性，多轮对话中需要确认用户所需的列装批次或配套环节，缩小数据范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 兵器装备收益率数据包含多维度字段，多轮对话需保留完整的筛选条件与历史交互信息，避免上下文溢出导致内容截断 |
| `systemPrompt` | 预设固定筛选规则：仅返回兵器装备配套业务的收益率数据，需明确指定统计周期、装备型号、生产主体后再输出结果，收益指标单位为万元/单位产能 | 该品类数据需严格匹配指定维度，预设规则可减少无效交互，统一对话输出的格式与范围 |
| `chatHistoryMaxTokens` | `2000–4000 字符` | 多轮对话中用户仅需补充逐步明确的筛选条件，保留前两轮的交互信息即可满足上下文需求，避免占用过多token配额 |
| `temperature` | `0.1–0.3` | 兵器装备收益率数据来自公开披露信息，需保持输出的准确性，不宜生成偏离事实的内容 |
| `fileUploadEnabled` | 开启 | 支持用户上传本地军工行业报告片段作为补充数据源，适配多轮对话中的个性化数据需求 |
| `toolChoice` | `auto` | 允许模型自主判断是否调用数据检索工具获取最新的兵器装备收益率数据，适配动态变化的对话需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用对话接口上传本地军工报告后，模型未提取其中的兵器装备收益率相关内容。原因：未将`fileUploadEnabled`参数设置为开启，或系统提示词未明确要求模型解析上传文件的指定字段。
- 现象：多轮对话中，模型无法复用用户之前指定的装备型号或统计周期条件。原因：`chatHistoryMaxTokens`参数取值过小，导致历史交互的筛选条件被截断，无法被模型读取。
- 现象：编排多个大模型对话工作流时，不同会话的兵器装备收益率数据出现交叉混淆。原因：未为每个会话配置独立的上下文参数，或未启用会话隔离设置，导致token池共享超出预期范围。

## 怎么确认配好了
- 发起单轮测试对话，输入“查询兵器装备的收益率数据”，检查模型是否提示需要补充统计周期、装备型号、生产主体等信息，验证系统提示词的规则是否生效。
- 上传一份模拟的军工行业报告文件，发起对话要求提取其中的收益率数据，检查模型是否能正确关联上传文件的内容，验证文件上传配置是否生效。
- 发起两轮连续对话，第一轮指定某装备型号与月度周期，第二轮仅提及“该装备的收益情况”，检查模型是否能复用第一轮的筛选条件，验证上下文保留配置是否生效。
- 调用会话接口`/api/v1/chat/completions`，检查请求参数中是否包含`systemPrompt`字段，且内容与预设的筛选规则一致，验证接口参数配置是否正确。
