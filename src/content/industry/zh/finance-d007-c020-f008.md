# 兵器装备收益率的工具调用与插件

## 这个品类的数据长什么样
兵器装备相关的收益与行情数据来源包括国防军工行业公开交易数据集、兵器装备相关主体的定期及临时公告、行业监测机构的公开披露内容。更新节奏分为两类：日度行情数据于每个交易日收盘后完成更新，临时经营数据随对应公告发布即时同步。文档结构为标准化结构化数据集，包含资产唯一标识、装备细分品类分类标签、统计周期标识、周期收益数值、数据更新时间戳、数据溯源字段。字段与单位方面，`asset_unique_id`为资产唯一标识，无单位；`equipment_subcategory`为装备细分品类标签，无单位；`cycle_return`为周期收益数值，单位为对应统计周期的收益变动单位；`update_time`为数据更新时间戳，单位为毫秒级Unix时间戳。

## 这些特征在「工具调用与插件」这一环带来什么约束
兵器装备相关数据的多源分散特性，要求工具调用插件支持多API端点聚合配置，需分别配置不同数据源的鉴权参数与解析规则。日度与临时触发的双更新节奏，要求插件支持定时拉取与事件触发两种调用模式，需配置触发条件的匹配规则。装备细分品类的分类字段，要求工具调用时需传入对应品类的过滤参数，避免返回非目标品类的收益数据。毫秒级的时间戳要求，要求插件的请求超时设置需匹配数据更新延迟，避免因超时过早终止请求导致数据缺失。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `tool_call_timeout` | `120 秒` | 兵器装备数据更新延迟通常在60-90秒，设置120秒可覆盖多数场景 |
| `tool_filter_fields` | `["asset_unique_id", "equipment_subcategory", "cycle_return", "update_time"]` | 仅保留核心字段，减少返回数据量，适配日报播报的内容需求 |
| `tool_trigger_mode` | `["scheduled", "event"]` | 支持日度定时拉取与临时公告触发两种调用模式，覆盖日报与临时播报场景 |
| `api_request_retry_count` | `3 次` | 多源数据接口可能存在临时波动，重试可提升调用成功率 |
| `plugin_field_mapping` | `{"cycle_return": "收益数值", "equipment_subcategory": "装备品类"}` | 统一字段名，适配下游播报系统的展示逻辑 |
| `tool_call_max_results` | `前 20 条` | 日报播报通常仅需核心数据，过多条目会增加播报负荷 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工具调用返回`400 Bad Request`错误，原因是未正确配置`equipment_subcategory`过滤参数，请求携带了非预设的装备品类标签。
- 现象为工具调用日志中未显示完整的`request_body`内容，原因是未开启完整请求日志记录配置，仅记录了部分核心参数。
- 现象为工具调用返回的收益数据字段缺失，原因是未正确配置`plugin_field_mapping`参数，未将数据源的原始字段映射为下游可用的字段名。

## 怎么确认配好了
- 发起一次手动工具调用，检查返回结果中是否包含预设的`equipment_subcategory`过滤后的装备品类数据。
- 查看工具调用的日志记录，确认`request_body`字段完整记录了所有配置的参数与请求内容。
- 配置定时触发任务，等待下一个更新周期，检查是否自动拉取到带有最新`update_time`的数据。
- 模拟临时事件触发，检查插件是否能正确响应并拉取对应公告的临时收益数据。
