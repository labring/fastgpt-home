# 动力煤收益率的对话日志与审计

## 这个品类的数据长什么样
动力煤行情与收益率数据主要来自国内大宗商品交易平台、行业监测机构及港口现货报价系统。更新节奏为每日固定时段推送当日结算数据，部分现货行情按小时更新。数据文档包含交易代码、当日结算价、当日价格变动幅度、现货基准价、港口库存等字段，单位分别为元/吨、元/吨、元/吨、吨。数据格式会因数据源不同存在细微差异，需统一映射后用于对话播报。

## 这些特征在「对话日志与审计」这一环带来什么约束
动力煤数据的多源更新特性，要求对话日志需按数据更新时段分类存储，区分日结行情与小时级现货行情的记录条目，避免跨时段数据混淆。多字段的文档结构，要求审计环节需校验每条日志的必填字段完整性，包括交易代码、结算价等核心字段，缺失字段的日志需自动标记异常。不同数据源的字段格式差异，要求日志需完成统一的字段映射，确保审计时可跨来源比对数据一致性。对话中涉及的行情请求需绑定精准时间戳，便于回溯时定位对应时段的数据源版本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `LOG_RETENTION_DAYS` | `90 天` | 动力煤行情审计需覆盖常规合规周期，90天可满足季度级回溯需求 |
| `TOKEN_STATISTICS_DIMENSION` | `application` | 细分场景需按应用维度统计token消耗，适配多播报节点的成本核算 |
| `CALL_LOG_ENABLED` | `开启` | 动力煤行情播报的调用链路需完整记录，确保审计可追溯每一次数据请求 |
| `LOG_FIELD_MAPPING_RULES` | 按实测标定 | 动力煤数据来自多源平台，需自定义映射规则统一字段格式 |
| `LOG_TIMEOUT_THRESHOLD` | `30 秒` | 动力煤实时行情的响应窗口通常较短，超时日志需标记为异常 |
| `AUDIT_FIELD_MISS_ALERT` | `开启` | 核心字段缺失会导致行情播报出错，需自动触发审计告警 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：对话日志丢失，无法回溯历史行情请求记录。原因：未在docker配置文件中正确挂载日志存储卷，导致日志数据随容器销毁丢失。
- 现象：调用工作流后，昨日与今日的对话日志为空。原因：未开启`CALL_LOG_ENABLED`配置项，系统未生成对话日志记录。
- 现象：模型提供商页面未显示调用日志。原因：未配置`LOG_FIELD_MAPPING_RULES`，日志字段未完成标准化映射，无法在前端页面展示。

## 怎么确认配好了
- 登录系统后台，查看`LOG_RETENTION_DAYS`的配置值，确认其与业务审计周期的要求匹配。
- 发起一次动力煤实时行情查询请求，检查后台生成的日志是否包含所有预设的核心字段，确认字段映射规则生效。
- 进入调用日志页面，验证当日与历史请求的日志均正常展示，确认`CALL_LOG_ENABLED`配置生效。
- 模拟触发字段缺失的日志场景，检查是否触发审计告警，确认`AUDIT_FIELD_MISS_ALERT`配置生效。
