# 动力煤收益率的部署与升级

## 这个品类的数据长什么样
动力煤行情与收益率数据主要来自国内大宗商品现货交易平台、郑州商品交易所动力煤期货合约接口。数据更新节奏为每个交易日收盘后完成一次当日全量更新，部分现货报价数据每间隔固定时段同步更新。单条数据文档包含合约标识、交割月份、基准价格、当日成交均价、当日最高成交价、当日最低成交价、持仓总量、成交总量、价格变动额等字段。价格类字段单位为元/吨，成交量与持仓量单位为交易通用手数。

## 这些特征在「部署与升级」这一环带来什么约束
动力煤数据的多交割月份字段、固定更新窗口，要求部署时配置与交易所收盘时间对齐的定时任务，避免数据滞后或重复拉取。解析规则需适配多合约字段，升级时不能直接复用其他品类的字段映射配置，否则会出现字段匹配失败。每日仅更新一次的特性，要求配置合理的缓存保留时长，避免频繁拉取占用资源。ARM架构部署场景下，需确认数据源接口与镜像架构兼容，升级时需同步更新适配ARM的依赖库，否则会出现运行异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `SCHEDULE_CRON_EXPR` | `0 18 * * 1-5` | 匹配动力煤交易日收盘后1-3小时的更新窗口，确保获取当日最新行情 |
| `DATA_PARSE_FIELD_MAPPING` | 按实测标定 | 动力煤数据包含交割月份等专属字段，需与数据源返回的字段名一一对应 |
| `CACHE_EXPIRE_TIME` | `86400 秒` | 每日仅更新一次行情数据，缓存保留24小时即可避免重复拉取 |
| `DOCKER_PLATFORM` | `linux/amd64` 或 `linux/arm64` | 适配不同部署架构，满足ARM架构部署需求 |
| `PARSE_WORKFLOW_TIMEOUT` | `300 秒` | 动力煤数据解析需匹配多合约字段，预留足够的解析时间 |
| `POST_PRESIGNED_URL_EXPIRE` | `3600 秒` | 确保上传的行情数据源文件在有效期内完成解析，避免过期报错 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：升级至4.14.0版本后，工作流上传动力煤行情数据源文件时，界面返回`Failed to create post presigned url`错误。原因：未在升级后重新配置对象存储的签名有效期参数，新版本默认签名有效期与旧版本不一致，导致上传请求过期。
- 现象：ARM架构部署时，无法拉取官方适配的docker镜像。原因：未指定正确的镜像平台参数，默认拉取的amd64镜像无法在ARM架构设备上运行。
- 现象：从4.9.0版本升级到4.12.3版本后，动力煤数据解析失败，字段匹配为空。原因：升级过程中未保留旧版的字段映射配置，新版本的解析规则默认适配其他品类，未针对动力煤的交割月份等专属字段做调整。

## 怎么确认配好了
- 手动触发绑定动力煤行情的工作流，核对返回结果是否包含交割月份、基准价格、价格变动额等专属字段。
- 查看定时任务执行日志，确认在交易日指定时间自动完成数据拉取与解析，无超时异常。
- 测试上传动力煤行情数据源文件，确认无`Failed to create post presigned url`报错，文件可正常解析入库。
- 在ARM架构部署环境中启动测试实例，确认工作流可正常拉取并解析动力煤数据。
