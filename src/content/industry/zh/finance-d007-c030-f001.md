# 化妆品收益率的HTTP接口与外部系统

## 这个品类的数据长什么样
化妆品品类的收益率与行情数据主要来自电商平台销售接口、品牌方经销商进销存接口及第三方行业监测接口。数据以JSON格式封装，核心字段包含`sku_id`（SKU唯一标识）、`brand_name`（品牌名称）、`product_category`（产品细分品类）、`reference_price`（基准价格，单位元）、`current_price`（当日售价，单位元）、`price_change_value`（价格变动额，单位元）、`update_time`（ISO格式时间戳）。数据更新节奏为每日凌晨汇总前一自然日的全量数据，促销时段会追加增量更新，覆盖临时调价的SKU信息。

## 这些特征在「HTTP接口与外部系统」这一环带来什么约束
化妆品品类的SKU数量较多，单次请求需支持批量拉取或分页参数，避免因单次请求数据量过大触发第三方接口限流。数据存在全量与增量两种更新模式，接口需支持按时间戳筛选数据范围，以适配日常全量拉取与促销时段的增量同步需求。部分小众品牌的SKU可能缺少部分行业监测字段，接口需兼容空值返回，避免解析时出现异常。此外，数据更新时间固定，外部系统需配置定时任务在每日固定时段触发拉取，确保获取最新的前一日汇总数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `HTTP_REQUEST_TIMEOUT` | `30 秒` | 化妆品品类数据接口多为批量SKU查询，30秒可覆盖多数场景的请求耗时，避免超时中断数据拉取 |
| `BATCH_REQUEST_SIZE` | `50-80` | 化妆品SKU数量较多，50-80的单次批量请求可平衡接口负载与拉取效率，避免触发第三方接口限流 |
| `INCREMENTAL_SYNC_ENABLE` | `开启` | 化妆品存在促销时段的临时价格调整，开启增量同步可仅拉取更新时段的数据，减少全量拉取的资源占用 |
| `REQUIRED_RESPONSE_FIELDS` | `sku_id, current_price, price_change_value, update_time` | 收益率播报需依赖这四个核心字段，强制校验可避免缺失关键数据导致的播报异常 |
| `API_AUTH_MODE` | `API_KEY` | 多数化妆品行业数据接口采用API密钥鉴权，配置为API_KEY鉴权可确保请求合法性 |
| `PARSE_RESPONSE_UNIT` | `自动匹配` | 化妆品价格字段的单位为元，自动匹配可避免手动配置单位带来的数值计算错误 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：升级到4.8.18版本后，拉取化妆品数据接口时无法返回历史同期价格数据。原因：新版本默认关闭了历史数据回溯的配置开关，未手动启用对应的参数项。
- 现象：调用化妆品数据接口时返回`400 Bad Request`错误，提示缺少必填字段。原因：未在`REQUIRED_RESPONSE_FIELDS`中配置全量必填字段，导致接口校验失败。
- 现象：定时拉取任务触发后，部分促销SKU的价格数据未更新。原因：未配置`INCREMENTAL_SYNC_ENABLE`为开启，仅拉取了全量数据但未覆盖增量更新的时段。

## 怎么确认配好了
- 发送测试请求到配置的化妆品数据接口，校验返回的`sku_id`、`current_price`、`update_time`字段是否完整且符合预期格式。
- 查看定时拉取任务的运行日志，确认请求的时间范围参数与预设的更新时段一致。
- 触发一次批量拉取请求，检查返回的HTTP状态码为`200 OK`，且返回条数符合`BATCH_REQUEST_SIZE`的配置范围。
- 对比第三方接口返回的价格数值与系统内解析后的数值，确认单位转换无误。
