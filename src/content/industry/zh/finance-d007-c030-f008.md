# 化妆品收益率的工具调用与插件

## 这个品类的数据长什么样
化妆品收益率相关数据主要来自电商平台公开销售数据、美妆品牌官方披露的进销存数据、第三方美妆行业监测机构的公开报告。更新节奏存在差异：电商销售数据每日更新，品牌内部进销存数据按周同步，第三方监测数据每两周更新一次。单条数据条目包含SKU编码、产品名称、所属品牌、销售渠道、统计周期、总营收、总成本、总毛利、关联热门成分占比数值。字段包括`sku_code`（字符串）、`product_name`（字符串）、`total_revenue`（浮点数，单位：人民币元）、`total_profit`（浮点数，单位：人民币元）、`hot_ingredient_ratio`（浮点数，区间0-1）。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散的特征要求插件支持多源数据聚合调用，需分别对接电商平台、品牌方、第三方监测机构的不同接口，同时处理各接口的权限校验差异。更新节奏的差异要求配置差异化的定时触发规则，针对日更的电商数据设置每日触发，针对周更的品牌进销存数据设置每周触发，避免拉取过时数据。字段结构的特殊性要求插件的输入输出映射需单独配置，例如化妆品的`hot_ingredient_ratio`采用0-1区间的浮点数格式，需在插件返回后完成格式校验与转换，无法直接复用其他品类的映射逻辑。单款化妆品SKU数量较多，工具调用时需设置合理的分页参数，避免返回数据量过大导致接口超时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `plugin_trigger_cron` | `0 0 1 * * *`（每日触发）、`0 0 0 * * 0`（每周触发） | 适配化妆品不同数据源的更新节奏，日更电商数据用每日触发，周更进销存数据用每周触发 |
| `plugin_data_fetch_timeout` | `600 秒` | 化妆品相关数据接口多来自第三方平台，响应延迟较高，600秒可覆盖多数正常响应时长 |
| `plugin_batch_size` | `前 50 条` | 单批次数据量过大易导致接口超时，50条可平衡数据完整性与响应速度 |
| `plugin_input_mapping_mode` | `custom_field_mapping` | 化妆品数据包含`hot_ingredient_ratio`等专属字段，需自定义映射规则适配 |
| `plugin_cache_expire_time` | `86400 秒` | 电商销售数据每日更新，缓存一天可避免重复拉取浪费接口资源 |
| `plugin_publish_scope` | `private_community` | 化妆品专属插件需仅对美妆行业用户开放，避免通用场景用户误用 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：非工具调用模式下配置了网络搜索接点，但最终播报内容未包含化妆品收益率的实时行情数据。原因：非工具调用模式下大模型仅能使用内置上下文与历史数据，无法主动调用外部接点拉取实时数据，需切换至工具调用模式触发接点。
- 现象：上传插件后无法在社区插件列表中检索到对应条目。原因：未将`plugin_publish_scope`配置为符合社区发布要求的取值，或未完成平台的插件资质校验流程。
- 现象：在插件输入配置中选择JSON输入框后，无法在调用时选择预设的全局变量。原因：当前JSON输入框暂不支持直接绑定全局变量，需通过字符串序列化的方式将变量参数传入JSON结构中。

## 怎么确认配好了
- 手动触发插件调用，检查返回数据的字段是否包含`sku_code`、`total_profit`等化妆品专属字段，且数值格式符合预设规则。
- 查看插件的定时触发日志，确认不同数据源的触发时间与配置的`plugin_trigger_cron`表达式一致。
- 尝试在调用环节绑定全局变量到插件输入，检查JSON输入框能否正确接收变量参数并完成序列化。
- 发布插件后在社区搜索对应插件名称，确认条目正常展示且权限配置符合预期。
