# 化妆品收益率的部署与升级

## 这个品类的数据长什么样
化妆品收益率相关数据主要来源于品牌公开季度财报、美妆行业垂直监测数据库、头部电商平台的销售复盘报告。数据更新频率分为月度常规更新与核心SKU周度更新两类。单条数据文档包含品牌标识、SKU编码、细分品类（护肤/彩妆/洗护等）、盈利水平数值、渠道销售占比数值、竞品对标区间数值。其中盈利水平数值单位为百分点，渠道销售占比数值以十分制计量，无百分比类表述。

## 这些特征在「部署与升级」这一环带来什么约束
化妆品品类的数据多源、更新频率分层且SKU基数大，对部署与升级环节带来多重约束。多源数据拉取需要配置适配不同接口格式的解析规则，避免字段映射错误。分层更新频率要求部署时配置差异化的定时任务调度，区分核心SKU与常规品类的拉取周期。SKU数量庞大则要求升级时兼容批量数据导入的内存阈值设置，避免导入过程中服务卡顿。同时，字段单位的差异化要求在数据清洗环节配置统一的格式转换规则，确保后续播报数据的一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `BATCH_IMPORT_SIZE` | `500 条/次` | 化妆品SKU基数大，单批次500条可平衡导入速度与服务内存占用 |
| `DATA_UNIT_CONVERT` | `开启` | 化妆品数据包含百分点与十分制两类单位，需开启转换确保播报数据格式统一 |
| `SYNC_TASK_CRON` | `0 0 2 * * ?`（核心SKU）、`0 0 1 * * ?`（常规品类） | 匹配核心SKU周度更新与常规品类月度更新的业务节奏 |
| `MAX_IMPORT_MEMORY` | `2048 MB` | 批量导入大量SKU数据时，该阈值可避免服务出现内存溢出 |
| `DATA_DUPLICATE_CHECK` | `开启` | 多源拉取易产生重复SKU数据，开启去重可保障数据准确性 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 适配批量导入大量SKU数据的解析时长，避免出现超时报错 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：Docker部署后无法修改登录密码，界面无密码修改入口。原因：未挂载`./data`目录到宿主机，导致配置文件无法持久化，密码修改未生效。
- 现象：批量导入化妆品SKU数据时，服务返回`504 Gateway Timeout`。原因：`PARSE_FILE_TIMEOUT_SECONDS`参数设置过短，未适配大量SKU数据的解析时长。
- 现象：通过ngrok暴露外网后，iOS设备访问出现白屏，macOS与Windows设备正常。原因：未配置跨域资源共享规则，iOS的WebView对跨域请求的校验更严格。

## 怎么确认配好了
- 执行一次批量导入测试，查看导入日志中是否存在单位转换失败的报错，确认数据格式转换配置生效。
- 查看定时任务管理界面，确认核心SKU与常规品类的同步任务调度时间与业务更新节奏匹配。
- 检查端口映射与跨域配置，使用不同终端设备访问暴露后的服务地址，验证页面加载与数据展示正常。
- 查看数据去重日志，确认重复SKU数据被自动过滤，无重复条目出现在最终数据集中。
