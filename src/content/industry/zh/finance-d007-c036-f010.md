# 半导体收益率的数据库与运维

## 这个品类的数据长什么样
半导体领域收益率与行情相关数据，来源包括国内证券交易所公开行情接口、半导体行业监测平台的公开数据集。数据更新节奏分为两类，每日收盘后完成全量日报数据同步，实时行情节点每15分钟更新一次数据。单条数据文档为结构化格式，包含交易日期、证券代码、半导体产品类别、平均交易单价、当日交易量、行业增长指数等字段。单价单位为元/单位产品，交易量单位为万件，行业增长指数为无量纲数值。每条记录对应单一交易日内单品类的交易与行情信息。

## 这些特征在「数据库与运维」这一环带来什么约束
半导体领域的行情与收益率数据存在双更新节奏，需要同时支持每日全量批量同步与每15分钟的实时增量拉取，对数据库的并发读写能力提出要求。数据包含多维度分类字段，需建立复合索引以支持按产品类别、交易日期的快速查询。每日全量同步的数据规模较大，需配置合理的批量写入阈值，避免单次写入操作超时。高频实时更新产生大量小数据包，需开启数据库的批量写入优化以降低IO开销。不同字段的单位差异与格式要求，需在数据入库前完成校验规则配置，防止脏数据流入数据库。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `database_type` | 选用国产化适配的关系型或文档型数据库 | 满足国产化替代要求，规避境外组件使用限制 |
| `db_batch_insert_size` | 500–1000 条/次 | 适配每日全量同步的数据规模，平衡写入效率与单次IO开销 |
| `real_time_sync_interval` | 900 秒 | 匹配半导体行情数据15分钟的更新节奏，预留合理缓冲时间 |
| `maxContext` | 8000–12000 字符 | 支持半导体行情数据的长文档上下文关联，避免连续追问丢失语义 |
| `api_rate_limit` | 100 请求/分钟 | 适配高频实时行情的调用需求，缓解并发受限问题 |
| `query_index_fields` | `["trade_date", "product_category"]` | 匹配多维度查询场景，提升复合查询的响应速度 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：知识库无法正常加载半导体行情数据，控制台报错显示“不支持的数据库类型”。原因：未将`database_type`配置为国产化适配的数据库类型，直接使用境外开源组件。
- 现象：连续追问半导体收益率相关问题时，后续回答无法关联前序问题的证券代码或产品品类，出现答非所问。原因：`maxContext`参数取值过小，未预留足够的上下文存储空间。
- 现象：并发查询实时行情时，频繁返回`429 Too Many Requests`错误。原因：未配置合理的`api_rate_limit`参数，未限制接口调用频率，超出平台限流阈值。

## 怎么确认配好了
- 执行一次全量数据同步任务，查看数据库写入日志，确认单次写入的批次数量与配置的`db_batch_insert_size`参数一致。
- 发起两轮连续的半导体行情相关查询，检查后续回答是否关联前一轮查询的关键词，确认上下文配置生效。
- 发起多并发的实时行情查询请求，查看接口返回状态码，确认未触发限流类错误。
- 执行按交易日期和产品品类的复合查询，检查返回结果的匹配范围，确认索引配置生效。
