# 卫星通信收益率的工具调用与插件

## 这个品类的数据长什么样
卫星通信收益率与行情的数据来源包括卫星运营商公开运营报表、地面测控站实时链路数据、行业协会统计汇总。更新节奏分为日度批量报表每日零点更新，实时链路收益数据每10分钟刷新一次。文档结构为结构化表格形式，每条记录包含卫星轨道位置、转发器频段、租用客户标识、计费基准单位、当日累计收益、链路负载占比。字段单位方面，计费基准单位为Mbps·小时，当日累计收益为万元，链路负载占比以0到1的小数记录。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散且格式异构，要求工具调用插件支持多源接口鉴权与字段映射配置，适配不同运营商接口的鉴权规则与字段命名差异。更新节奏包含日度批量拉取和实时增量刷新，需要区分配置定时触发与实时触发的调用间隔阈值，避免频繁调用超出接口限流规则。非标准化的客户标识与频段字段，要求工具调用时内置参数校验规则，过滤无效的请求参数。链路负载占比的小数格式，要求插件内置格式转换逻辑，适配下游报表生成的统一数据要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `tool_call_timeout` | 600 秒 | 卫星通信数据接口多为跨地域部署，平均响应延迟较高，600秒可覆盖多数接口返回周期 |
| `reranker_top_n` | 前3条 | 卫星通信行情字段数量有限，重排后保留前3条即可满足收益率计算的核心数据需求 |
| `rag_recall_threshold` | 0.75 | 卫星通信行业知识库的专业术语密度较高，0.75可过滤低相关性的通用检索结果 |
| `plugin_auth_type` | API_KEY鉴权 | 卫星运营商接口多采用API_KEY鉴权方式，适配公开数据源的调用要求 |
| `schedule_cron` | 0 0 0 * * * | 日度收益率报表的定时触发配置，对应每日零点更新的数据源节奏 |
| `fallback_response` | 「暂无当日卫星通信收益率相关数据」 | 当工具调用无有效返回或知识库无匹配内容时，使用预设固定回复 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用bge-reranker模型时，GPU显存占用随调用次数快速增长并稳定在6-7G，多GPU节点下各卡均出现占用。原因：未配置模型的显存释放参数，导致每次调用后未主动清理中间张量缓存。
- 现象：工具调用返回有效数据后，系统未优先使用工具结果，而是直接返回知识库检索内容。原因：未配置工具调用的优先级高于知识库检索的触发逻辑。
- 现象：使用Java调用FastGPT对话应用时，返回401未授权错误。原因：误将appId作为调用密钥使用，未正确获取并配置应用的API_KEY。

## 怎么确认配好了
- 执行单次工具调用测试，查看接口返回数据的字段格式与配置的字段映射规则是否一致。
- 查看系统日志中的工具调用记录，确认调用超时次数符合预期，未出现频繁超时的情况。
- 触发定时任务，检查是否在指定的Cron时间自动拉取数据并生成对应报表。
- 模拟无匹配知识库内容的查询场景，验证是否返回预设的fallback回复。
