# 厨卫电器收益率的HTTP 接口与外部系统

## 这个品类的数据长什么样
厨卫电器的收益率与行情数据主要来自品牌方进销存系统、电商平台交易后台及线下零售终端的汇总报表。数据更新节奏为每日凌晨完成前一日全量数据同步，部分高流转单品的实时毛利波动每小时更新。单条数据文档包含SKU编码、产品型号、进货成本单价、实际成交单价、当日出货量、毛利额、收益率数值等字段，其中SKU编码为13位数字字符串，产品型号由字母与数字组合构成，收益率数值为0至1区间的浮点数。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
由于数据来源包含进销存、电商后台与线下终端三类系统，HTTP接口需支持多数据源的聚合请求，避免外部系统重复调用多个独立接口。每日全量更新与每小时实时波动的双重更新节奏，要求接口同时支持全量拉取与增量同步两种调用模式。SKU编码的固定13位数字格式，要求接口的查询参数需对输入值做格式校验，不符合规则的请求直接返回`400 Bad Request`状态码。收益率数值的浮点数类型，要求接口返回字段需严格定义为数值类型，避免字符串格式导致下游系统解析异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `SYNC_DATA_FULL_CRON` | `0 2 * * *` | 匹配每日凌晨2点执行全量数据同步，适配厨卫电器前一日销售数据的更新节奏 |
| `SYNC_DATA_INCREMENTAL_CRON` | `0 * * * *` | 每小时执行一次增量同步，覆盖高流转单品的实时毛利波动更新 |
| `SKU_CODE_VALIDATOR` | `^\d{13}$` | 匹配厨卫电器SKU编码的13位数字格式，过滤无效请求 |
| `API_RESPONSE_FIELD_TYPE` | `number` | 收益率数值为浮点数，统一返回数值类型避免下游解析错误 |
| `API_REQUEST_TIMEOUT` | `600 秒` | 多数据源聚合请求需预留足够的等待时间，避免超时中断 |
| `MAX_BATCH_SIZE` | `500` | 单批次拉取数据量适配厨卫电器SKU总量的常规规模，避免接口过载 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用接口返回`400 Bad Request`状态码，且响应体包含`invalid sku format`提示。原因：未按照13位数字格式校验SKU编码参数，传入了非13位数字的字符串。
- 增量同步接口返回的收益率数据为空。原因：未配置增量同步的时间戳校验参数，导致无法识别新增或更新的数据条目。
- 外部系统调用接口后出现`504 Gateway Timeout`错误。原因：将`API_REQUEST_TIMEOUT`配置为低于600秒的取值，多数据源聚合请求未完成就被中断。

## 怎么确认配好了
- 调用接口传入符合13位数字格式的SKU编码，检查响应体中是否包含收益率数值字段，且字段类型为数值型。
- 配置全量同步任务后，等待定时任务触发，检查外部系统接收的数据量与当日厨卫电器SKU总量匹配。
- 配置增量同步任务后，手动触发一次同步，检查是否仅返回近一小时内更新的数据条目。
- 调用接口传入不符合格式的SKU编码，检查是否返回`400 Bad Request`状态码及对应格式校验提示。
