# 品牌代运营收益率的工作流编排

## 这个品类的数据长什么样
品牌代运营的经营数据主要来自电商平台后台API、广告投放平台API、品牌方ERP系统三类渠道。数据更新节奏分为两类：全量经营数据每日凌晨完成前一日的同步更新，实时投放消耗数据每小时刷新一次。单条数据对应单个代运营账号的单日经营记录，文档结构以代运营主体、品牌名称、运营渠道为分组维度，包含代运营账号ID、当日成交金额、渠道投放成本、基础服务费、绩效结算金额、账号运行状态等字段，所有数值类字段的单位均为人民币元，状态字段为固定枚举字符串。

## 这些特征在「工作流编排」这一环带来什么约束
多数据源的接入需求要求工作流配置多组独立的API鉴权凭证，适配不同平台的鉴权规则。每日全量同步与小时级实时刷新的双重节奏，要求工作流同时包含定时触发节点与定时轮询节点，避免数据延迟或重复拉取。按账号分组的文档结构，要求工作流在数据处理环节加入分组过滤节点，确保不同代运营账号的数据不会混淆。跨数据源的字段关联需求，要求工作流配置数据合并节点，基于代运营账号ID与日期作为匹配键，关联营收、成本等不同来源的字段，完成净收益的计算。日报播报的输出需求，要求工作流最后接入格式化节点，将结构化数据转换为可直接用于播报的格式。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `定时任务 cron 表达式` | `0 0 2 * * *` | 匹配品牌代运营日报T+1的更新节奏，避免触发时段干扰当日业务数据 |
| `API 请求超时时间` | `300 秒` | 覆盖多数电商、投放平台API的正常响应时长，避免中途中断数据拉取流程 |
| `全局变量传参方式` | `请求体 JSON 格式` | 适配多数第三方经营数据API的传参规范，便于后续字段提取与计算 |
| `HTTP 请求文件传输类型` | `multipart/form-data` | 支持txt格式的日报文档上传，适配文件传递的实际需求 |
| `日志留存时长` | `90 天` | 覆盖代运营经营数据的常规对账周期，便于后续排查异常与追溯数据 |
| `工作流节点并行数` | `前 10 个账号` | 控制单批次处理的账号规模，避免超出第三方API的调用限额 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：HTTP请求节点返回`415 Unsupported Media Type`错误。原因：未将文件传输类型设置为`multipart/form-data`，直接使用JSON格式传递txt文件，不符合后端接口的接收要求。
- 现象：部分代运营账号的净收益计算结果为空。原因：未配置`数据合并匹配键`为代运营账号ID+日期，导致不同账号的营收、成本数据无法正确关联，出现字段匹配失效。
- 现象：定时触发的工作流未按预设时间执行。原因：`定时任务 cron 表达式`的参数设置错误，例如将小时位设置为动态通配符，导致触发频率不符合日报更新的固定时段要求。

## 怎么确认配好了
- 手动触发一次工作流，逐一核对各数据源节点的返回数据与对应平台的后台数据是否一致。
- 查看工作流运行日志，确认所有节点的运行状态均为成功，无超时、报错或字段缺失的情况。
- 抽取3-5个代运营账号的单日数据，手动计算净收益并与工作流输出结果对比，确认关联逻辑正确。
- 验证定时任务的触发记录，确认工作流在预设时段自动启动并完成全量数据的处理流程。
