# 商业物业收益率的对话日志与审计

## 这个品类的数据长什么样
这个品类的数据主要来自物业运营管理系统的租金收缴台账、运维成本结算单据、公共配套（停车场、广告位）营收报表。更新节奏为月度，对应自然月的运营周期完成核算后生成单条数据。单条数据的标准结构包含项目编码、项目坐落地址、核算月度、可出租建筑面积、实收租金总额、运维成本总额、公共区域营收、调整项金额等字段。建筑面积单位为平方米，各类收支金额单位为人民币元。

## 这些特征在「对话日志与审计」这一环带来什么约束
月度更新的特征要求对话日志需按核算月度归档，便于按周期回溯运营数据的审计轨迹。多字段且跨系统来源的结构，要求日志需记录每一次数据调用的数据源节点、字段取值的来源链路，避免数据溯源时出现断点。项目维度的独立数据，要求日志需关联项目编码作为唯一标识，确保不同物业项目的日志互不干扰。同时，审计场景下需留存字段调整的完整链路，因此日志需记录每一次对收支、调整项的修改操作及操作人信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `logRetentionDays` | `365 天` | 商业物业运营审计需覆盖完整年度周期，需留存至少一年的对话及数据调用日志 |
| `logFilterByProject` | `启用` | 商业物业存在多项目并行运营的场景，按项目过滤可快速定位指定物业的审计轨迹 |
| `dataSourceTraceLogEnabled` | `启用` | 商业物业数据跨租金、运维、公共营收多系统来源，需完整记录数据调用链路以满足审计溯源要求 |
| `fieldChangeLogEnabled` | `启用` | 商业物业的收支、调整项存在常态化调整需求，需记录每一次字段修改的操作人、修改时间及修改内容 |
| `maxLogQueryTimeRange` | `365 天` | 商业物业审计需支持跨年度的日志查询，需放宽最大查询时间范围至完整年度 |
| `mongodbLogCollectionPrefix` | `commercial_property_audit_log_` | 区分不同品类的日志集合，避免与其他业务场景的日志数据混淆 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：MongoDB 存储的对话日志集合与其他业务混淆，无法单独筛选商业物业相关日志。原因：未配置`mongodbLogCollectionPrefix`为专属前缀，日志被写入通用默认集合。
- 现象：对话详情页仅展示用户与助手的交互文本，未显示内部数据调用的完整链路。原因：未启用`dataSourceTraceLogEnabled`配置，未开启数据源链路的日志采集。
- 现象：超过设定天数的对话日志无法被检索到，审计时缺失历史记录。原因：`logRetentionDays`配置值设置低于审计所需的周期，日志被自动清理。

## 怎么确认配好了
- 执行一次包含数据调用的对话，查看`mongodbLogCollectionPrefix`指定的集合中是否生成对应日志条目。
- 进入对话详情页，确认页面展示了数据源调用链路、字段修改记录等内部操作信息。
- 调整日志查询的时间范围，确认可查询到覆盖完整年度周期的历史日志。
- 选择指定物业项目，通过项目过滤功能，确认仅展示该项目的对话日志。
