# 商用车收益率的HTTP 接口与外部系统

## 这个品类的数据长什么样
商用车收益率相关数据主要来源于车载OBD终端、车队管理系统、能源补给平台及维保服务商。核心日度收益率汇总数据每日凌晨更新前一日的运营数据，实时运营状态数据每15分钟推送一次，仅用于辅助当日收益率计算。数据采用标准JSON格式封装，字段包含`vehicle_vin`（商用车唯一识别码）、`daily_revenue`、`daily_operating_cost`、`total_mileage`、`operating_duration`，其中金额类字段单位为元，里程类字段单位为公里，时长类字段单位为小时。部分数据源支持按车队或线路分组返回聚合数据。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
日度汇总数据体量较大且支持批量查询，要求对接的HTTP接口支持分页或批量拉取参数，避免单次请求返回过多数据触发限流或超时。数据字段包含唯一的`vehicle_vin`标识，要求外部系统在存储与关联数据时需以该字段为唯一标识，避免不同车辆的数据混淆。金额、里程、时长字段均携带固定单位，要求接口返回时明确标注单位或采用预设固定单位，减少外部系统的单位转换成本。实时与日度数据更新节奏不同，需区分两种接口类型分别配置，避免因请求类型错误导致数据获取异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `auth_type` | `header` | 匹配多数商用车车队管理系统的鉴权规范，支持传入自定义鉴权头 |
| `request_timeout` | `30 秒` | 商用车数据源的接口响应通常在10-25秒区间，30秒可覆盖多数正常请求，避免超时中断 |
| `batch_fetch_size` | `50 条/请求` | 单批次拉取50条日更数据可平衡接口负载与传输效率，避免单次数据过大触发限流 |
| `field_mapping_strategy` | `精准匹配` | 商用车收益率数据字段命名存在固定规范，精准匹配可避免字段映射错误 |
| `unit_verification` | `开启` | 校验返回字段的单位与预设规则一致，避免外部系统因单位不匹配导致计算偏差 |
| `max_retries` | `2 次` | 针对商用车数据源偶发的网络波动，2次重试可降低接口调用失败率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用接口返回`Key is error. You need to use the app key rather than the account key`报错。未正确配置鉴权密钥，使用了全局账号密钥，未使用对应商用车数据源的应用级密钥。
- 接口调用返回`413 Request Entity Too Large`状态码。单次拉取的日更数据量超过数据源接口的限流阈值，未设置合理的批量拉取参数。
- 对接后系统展示的商用车收益率数据字段为空。未配置正确的字段映射规则，未将数据源返回的`daily_revenue`字段映射到系统预设的目标字段。

## 怎么确认配好了
- 调用测试接口，检查响应头中包含配置的自定义鉴权标识，确认鉴权参数生效。
- 拉取单台商用车的单日收益率数据，核对返回字段与预设的映射规则完全一致。
- 模拟批量拉取请求，确认接口返回的数据量符合配置的批量拉取大小。
- 查看系统运行日志，确认无鉴权失败、超时或字段解析异常等报错记录。
