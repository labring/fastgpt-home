# 商用车收益率的工作流编排

## 这个品类的数据长什么样
商用车收益率相关数据主要来自车载T-BOX终端、物流订单管理系统、能源补给站结算系统三类数据源。实时位置与能耗数据每30秒更新一次，单日运营汇总数据于每日凌晨2点生成并推送。数据采用结构化JSON格式存储，包含`vehicle_id`（车辆识别码，字符串）、`daily_mileage`（单位公里，数字）、`fuel_consumption_rate`（单位升/百公里，数字）、`order_revenue`（单位元，数字）、`maintenance_cost`（单位元，数字）、`idle_duration`（单位分钟，数字）、`operating_period`（字符串，时段范围）等字段，其中空载时长、运营时段为商用车特有的统计维度。

## 这些特征在「工作流编排」这一环带来什么约束
车载数据的高频更新要求工作流支持高频定时触发或增量拉取模式，避免全量拉取导致的系统负载过高。单日汇总数据的固定更新节奏，要求工作流包含夜间定时触发环节，适配数据生成的时间窗口。商用车特有的空载时长、运营时段字段，需要工作流支持自定义字段映射规则，无法直接复用通用品类的字段模板。多源数据的跨系统整合需求，要求工作流内置数据合并节点，处理不同系统间字段命名的差异，确保收益率计算的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `定时触发间隔` | `30 秒` | 匹配车载T-BOX终端实时数据的更新频率，避免拉取重复或遗漏数据 |
| `数据拉取批次大小` | `80–120 条` | 适配商用车单批次运营数据的量级，平衡拉取效率与系统负载 |
| `字段映射规则` | 按实测标定 | 需映射商用车特有字段如`idle_duration`、`operating_period`，无法使用通用模板 |
| `节点超时时间` | `600 秒` | 跨能源补给站、订单系统的数据合并环节需较长处理时长 |
| `全局变量初始化` | `初始值为 { "total_revenue": 0, "total_cost": 0 }` | 提前预留收益率计算的统计容器，避免运行时变量未赋值 |
| `异常告警触发条件` | `字段为空率 ≥ 10%` | 商用车数据异常（如车载终端离线）会导致字段缺失，需及时触发告警 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：代码运行节点的日志面板无打印信息，单独调试节点也无法查看输出。原因：未开启`代码节点日志输出`开关，或日志等级设置为高于`INFO`的级别，过滤了普通打印内容。
- 现象：自定义组件的参数修改后无法保存，重启流程后恢复默认值。原因：未进入组件的配置弹窗进行修改，直接在画布上调整参数，未提交组件配置变更。
- 现象：数据面板组件获取全局变量时，返回未赋值的空值。原因：变量赋值节点未在按钮触发前执行，全局变量未在流程启动阶段完成初始化。

## 怎么确认配好了
- 手动触发一次工作流，查看`日志面板`中是否包含代码节点的打印信息，确认日志输出配置生效。
- 进入自定义组件的配置弹窗，修改参数后保存，重新打开配置弹窗确认参数已更新，确认组件修改流程正常。
- 模拟触发按钮事件，查看全局变量面板中对应变量的取值，确认变量在触发前已完成赋值。
- 拉取一批测试用的商用车运营数据，运行工作流后查看数据合并节点的输出，确认多源字段已正确对齐。
