# 商用车收益率的工具调用与插件

## 这个品类的数据长什么样
商用车收益率相关的日报数据，主要来源于车队管理系统、货运交易结算平台、车载终端监测设备三类数据源。数据更新节奏为每日凌晨完成前一日全量数据汇总，部分实时运营指标如油耗、行驶时长支持小时级刷新，但日报维度仅按自然日更新。单条数据文档结构包含车辆识别码、当日运营总里程、当日营收总额、当日固定与变动成本、当日运营时长等字段，其中里程单位为公里，营收与成本单位为人民币元，运营时长单位为小时，未包含百分比类统计字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源分散的数据来源要求工具调用需支持跨平台拉取与格式兼容，避免因数据源格式差异导致字段解析失败。每日固定时间更新的特性要求工具调用需配置定时触发逻辑，且触发频率不宜过高，防止重复拉取未更新的历史数据。字段包含多类运营相关指标且附带明确单位，要求工具调用的参数映射需严格匹配字段名与单位，否则会导致收益率计算的基础数据失真。实时指标与日报数据的更新节奏差异，要求插件链中需区分实时拉取与批量汇总的处理步骤，避免混合调用导致数据时效性不符要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DATA_SOURCE_SYNC_INTERVAL` | `86400 秒` | 匹配商用车日报数据每日更新的固定节奏，避免重复拉取历史数据 |
| `PLUGIN_CHAIN_TIMEOUT` | `300 秒` | 覆盖跨数据源拉取、字段映射与单位转换的全流程处理时间，防止超时中断 |
| `FIELD_MAPPING_RULE` | `严格匹配字段名+单位校验` | 商用车数据字段多且关联紧密，严格匹配可避免基础数据错位 |
| `UNIT_CONVERSION_SWITCH` | `开启` | 兼容不同数据源的里程、成本单位差异，确保字段值统一 |
| `UNRECOGNIZED_FIELD_HANDLING` | `标记为空并触发告警` | 缺失核心字段会直接影响收益率计算，告警可及时排查数据异常 |
| `MAX_RETRY_TIMES` | `2 次` | 平衡数据拉取成功率与重复请求的资源消耗 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用工具时返回`400 Bad Request`，提示`invalid parameter`。原因：未区分本地部署大模型与线上API的参数差异，例如本地模型默认不支持`stream`参数的启用状态，直接沿用线上API的参数配置导致校验失败。
- 插件调用时文件类型变量返回空值。原因：未在API请求的`form-data`中正确携带`file`字段的`filename`与`content-type`参数，导致平台无法识别文件类型与名称。
- 工具调用后出现`data_mismatch`错误。原因：未开启`UNIT_CONVERSION_SWITCH`，不同数据源的里程单位（公里/英里）未统一，导致字段值对比异常。

## 怎么确认配好了
- 触发一次手动工具调用，查看返回结果是否包含预设的`vehicle_vin`、`daily_revenue`、`daily_cost`等核心字段，且字段单位符合预设要求。
- 查看工具调用的日志记录，确认`PLUGIN_CHAIN_TIMEOUT`未触发超时告警，且重试次数未超过`MAX_RETRY_TIMES`的配置值。
- 模拟单条数据缺失字段的场景，确认平台是否触发`UNRECOGNIZED_FIELD_HANDLING`的告警逻辑，生成异常提示。
- 导出单台车辆的手动统计数据，与工具调用返回的对应字段值进行对比，确认数据一致性。
