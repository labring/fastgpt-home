# 商用车收益率的数据库与运维

## 这个品类的数据长什么样
商用车收益率数据主要来源于车载T-BOX终端、车队管理系统、货运订单平台、能源补给平台。数据按单车唯一标识VIN码和运营日期维度组织，每条文档包含单车当日的订单总量、行驶里程、能源消耗成本、维保支出、平台佣金、挂靠费用等明细项，以及汇总的总收入、总成本。数据更新节奏为每日凌晨批量同步前一日全量运营数据，同时支持当日临时订单、补录数据的实时写入。

## 这些特征在「数据库与运维」这一环带来什么约束
多源数据同步带来高频并发写入需求，需适配不同终端和平台的写入时间差。按VIN码和运营日期的联合查询为高频场景，需建立联合索引以降低查询延迟。每日批量更新的数据量较大，需支持批量写入操作以避免单次写入阻塞数据库。运营数据存在事后补录的可能，需支持UPSERT操作避免重复数据生成。日报播报的实时性要求，需控制数据库查询延迟，合理配置缓存策略以降低直接查询数据库的频率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `mongo.connectionPoolSize` | `100-150` | 适配商用车多源数据同步的并发写入需求，满足每日批量更新时的数据库连接占用 |
| `batchInsertBatchSize` | `500-1000条/次` | 匹配每日批量更新的单车数据量，避免单次写入过大导致数据库锁表 |
| `index.jointKey` | `["vehicle_id", "operating_date"]` | 覆盖按单车和运营日期的高频查询场景，联合索引可大幅降低查询延迟 |
| `dataUpsertEnable` | `true` | 支持运营数据的事后补录与修正，避免重复插入冗余数据 |
| `cache.ttl` | `3600 秒` | 匹配日报数据每日更新的周期，减少重复查询数据库的开销 |
| `query.maxTimeout` | `30 秒` | 适配AI播报的实时响应要求，避免请求超时中断导致数据未落库 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为调用生成收益率日报的API后，客户端断开连接，数据库中未生成对应日报数据，原因为未配置`query.maxTimeout`适配批量写入时长，导致请求超时中断，未触发数据落库的回调逻辑。
- 现象为启动Docker容器后，3000端口无法访问，日志输出`MongoConnectionError`，原因为`mongo.connectionString`中的账号密码或主机地址配置错误，未正确配置容器间网络连通性。
- 现象为每日批量更新后，部分车辆的收益率数据缺失或重复，原因为未正确设置`index.jointKey`联合索引，导致数据库在执行UPSERT操作时无法快速定位已存在的数据，出现遗漏或重复插入。

## 怎么确认配好了
- 执行数据库索引查询命令，确认联合索引已按配置创建。
- 提交单条或批量的模拟运营数据，调用补录接口后验证数据是否正确更新，无重复或遗漏条目。
- 查看系统运行日志，确认数据库连接无认证失败或超时报错。
- 发起模拟的日报生成请求，验证请求响应时长符合业务预期阈值。
