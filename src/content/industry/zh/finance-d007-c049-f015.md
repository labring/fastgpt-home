# 基建工程收益率的部署与升级

## 这个品类的数据长什么样
基建工程收益率相关数据来源于项目财务核算系统、工程监理进度报告及属地住建部门的项目备案数据。数据更新节奏为月度同步，每个自然月的结算周期结束后2至3个工作日完成全量更新。数据文档为结构化表格格式，包含项目唯一标识、标段位置、当期完成工程量、当期投入成本、当期单位投入收益额、累计单位投入收益额、成本分项占比等字段。工程量单位为立方米、平方米，成本与收益单位为元，分项占比为小数形式。

## 这些特征在「部署与升级」这一环带来什么约束
基建工程收益率数据的多源接入特性要求部署阶段需配置多数据源的并行同步接口，避免单一数据源故障导致整体播报中断。月度更新的节奏要求定时同步任务需匹配项目结算周期，不宜设置过短的同步间隔，否则会占用不必要的系统资源。结构化表格的固定字段格式要求配置精准的字段映射规则，无法直接使用通用文档解析模板。多样的单位类型要求部署阶段配置单位转换逻辑，确保不同分项数据可统一为系统可识别的格式。升级阶段需支持动态字段扩展，适配基建项目新增的环保、安全等成本分项字段，避免硬编码字段列表导致升级后数据解析失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DATA_SYNC_CRON` | `0 0 2 1 * *` | 匹配基建项目月度结算周期，每月1日凌晨2点执行同步，不占用业务时段 |
| `PARSE_FIELD_MAPPING` | `{"project_id":"项目唯一标识","current_output":"当期完成工程量","current_cost":"当期投入成本","current_profit":"当期单位投入收益额"}` | 匹配基建工程收益率文档的标准字段名，确保数据源输出与系统解析规则一致 |
| `DATA_UNIT_CONVERT_ENABLE` | `true` | 适配文档包含的立方米、元等多样单位，统一转换为系统默认的计量与计价单位 |
| `SYNC_RETRY_TIMES` | `3 次` | 应对基建数据源可能出现的临时网络波动，降低首次同步失败概率 |
| `UPGRADE_FIELD_AUTO_ADD` | `true` | 支持基建项目新增的成本分项字段自动加载，无需手动修改配置 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 部署后`oneapi`容器持续重启，容器日志返回`exit code 137`或`OOM killed`。原因：未限制`oneapi`容器的内存配额，本地模型加载占用内存超出分配上限。
- 配置外部数据库连接后，知识库列表无新增数据，前端界面显示`empty data`提示。原因：未配置数据库同步的增量拉取规则，仅执行全量拉取导致首次同步超时失败。
- 配置外部网站作为知识库数据源后，检索结果为空，系统日志返回`request timeout`错误。原因：未配置防火墙或代理规则，导致FastGPT无法访问外部网站的公开数据接口。

## 怎么确认配好了
- 查看定时同步任务的执行日志，确认最近一次同步任务的状态为`success`，核对同步数据的条数与数据源输出条数一致。
- 手动触发一次数据同步任务，检查系统返回的字段是否与配置的`PARSE_FIELD_MAPPING`完全匹配，无缺失或错误字段。
- 调用收益率播报接口，确认返回结果包含配置的所有字段，单位转换符合预期。
- 检查系统升级后的界面，确认新增的成本分项字段已自动加载，无需手动修改配置项。
