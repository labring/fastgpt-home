# 多元控股收益率的HTTP 接口与外部系统

## 这个品类的数据长什么样
多元控股的收益率与行情日报数据来源为集团内部各业务单元的核算系统、外部行情数据源的汇总整合。更新节奏为每个交易日收盘后固定时段完成全量更新，仅在交易日生成当日日报文档。文档结构为嵌套JSON格式，顶层包含控股主体标识、报告日期字段，下层嵌套各下属业务单元的独立收益与行情数据。核心字段包括`holding_id`（控股主体唯一编码）、`subsidiary_code`（子业务单元标识）、`daily_return_value`（当日收益数值）、`benchmark_index_code`（关联行情基准代码），其中`daily_return_value`单位为基准收益单位，`benchmark_index_price`单位为点位单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
由于数据为多业务单元汇总结果，接口需支持按多个`holding_id`批量查询，避免单次调用仅返回单主体数据的低效请求。固定的更新节奏要求外部系统调用接口的时间窗口需限定在每日收盘后，避免获取未完成更新的旧数据。嵌套的文档结构要求接口响应需保留层级字段，不可强制扁平化转换，否则会丢失子业务单元的关联信息。跨业务单元的数据属性要求接口需配置层级权限校验，仅允许授权主体访问对应控股范围的数据，同时批量查询的耗时高于单品类接口，需调整超时阈值以避免请求被提前中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `batch_query_max_count` | `10-20` | 多元控股下属子单元数量通常处于该区间，批量查询过多会增加接口响应耗时 |
| `cors_allow_origins` | `企业内部可信域名列表` | 限定外部调用的可信来源，规避跨域安全风险 |
| `request_timeout` | `600 秒` | 多子单元数据汇总需遍历多个内部系统，耗时显著高于单业务品类接口 |
| `auth_resource_scope` | `holding_level` | 按控股主体层级配置权限，避免不同集团主体的数据越权访问 |
| `upload_file_max_size` | `200 MB` | 日报附带的行情图表、核算附件通常不超过该大小，超出会触发存储限制 |
| `date_query_range` | `当日-7日` | 日报类数据仅需近7日的历史查询需求，超出范围的请求可直接返回空数据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：使用`fetch`调用`api/v1/chat/completions`接口时返回跨域错误，提示`No 'Access-Control-Allow-Origin' header is present on the requested resource`，状态码为`403`或`0`。原因：未配置`cors_allow_origins`参数或取值未包含调用方所在域名。
- 现象：上传文件名超过255字符的文件时，接口返回`400 Bad Request`错误。原因：接口默认限制文件名长度为255字符，超出后无法正确解析文件存储路径。
- 现象：通过Markdown上传图片后，无法获取匹配`/api/system/img/`前缀的可访问URL。原因：未开启图片上传的路径映射配置，未将上传文件的存储路径绑定到指定接口前缀。

## 怎么确认配好了
- 使用`curl`工具发起合法的批量查询请求，传入多个有效`holding_id`与`report_date`参数，检查返回数据包含各下属子单元的收益字段。
- 将本地开发域名添加到`cors_allow_origins`配置中，使用`fetch`发起跨域请求，确认无跨域错误且正常返回数据。
- 上传文件名长度为300字符的测试文件，检查返回状态码为`200`且无`400`错误提示。
- 上传测试图片并通过Markdown语法插入，检查图片可正常加载且URL路径包含`/api/system/img/`前缀。
