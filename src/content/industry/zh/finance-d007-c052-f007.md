# 多元控股收益率的工作流编排

## 这个品类的数据长什么样
多元控股的行情与收益率数据来自旗下各全资、控股子公司的业务系统接口、交易所挂牌主体的公开披露接口、合规的金融数据聚合渠道。数据更新节奏为每日收盘后1小时内完成全量子板块拉取，月度末补充合并报表维度的核算数据。单份日报文档包含头部合并统计字段、各子板块明细字段、基准对比字段三个模块，涉及字段包括`合并主体标识`、`子板块归属`、`当日收益变动值`、`期末持仓市值`、`基准参考值`，单位分别为字符串、分类标签、元/单位份额、万元、点位。

## 这些特征在「工作流编排」这一环带来什么约束
多源异构的数据来源要求工作流配置多并行拉取节点，适配不同接口的鉴权方式、请求头与返回格式。固定的收盘后更新窗口要求工作流的定时触发节点设置精准的执行时段，且配置全局超时阈值，避免超过更新窗口导致日报延迟。多子板块的明细数据要求工作流集成循环遍历节点，批量处理各板块的字段映射与清洗。统一的文档结构要求工作流内置标准化输出节点，将清洗后的数据按固定模块拼接，确保日报格式一致。不同子板块的单位差异要求工作流添加统一转换节点，消除格式偏差，保障后续数据使用的一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `scheduleCron` | `0 18 * * *` | 匹配多元控股每日收盘后1小时的更新窗口，确保数据拉取在合规时段内完成 |
| `parallelTaskLimit` | `3-5` | 适配多子板块的数据拉取需求，避免超过第三方数据接口的并发限制 |
| `field_mapping_template` | `按板块预设模板匹配` | 解决各子板块字段名不一致的问题，统一数据格式 |
| `workflow_total_timeout` | `3600 秒` | 匹配1小时的更新窗口要求，避免工作流超时导致日报延迟 |
| `unit_conversion_config` | `批量转换为指定单位` | 统一各子板块的收益单位，消除格式差异 |
| `api_auth_strategy` | `多鉴权混合配置` | 适配不同数据源的鉴权要求，确保数据拉取合规 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 工作流运行后全局变量未被API链接赋值，对应字段为空。原因是未正确配置API调用的响应映射，未将返回字段绑定到预设的全局变量。
- 工作流执行超时，返回`504 Gateway Timeout`状态码。原因是未设置合理的`workflow_total_timeout`参数，或并行节点数超过第三方接口的并发限制。
- 导出的工作流配置文件无法正常导入。原因是导出时未选择正确的文件格式，或未勾选完整的节点配置项。

## 怎么确认配好了
- 手动触发工作流一次，核对各数据节点的返回字段是否覆盖所有预设的子板块明细。
- 查看工作流的运行日志，确认无未处理的异常报错。
- 导出工作流配置文件，导入至测试环境，验证所有配置项是否完整保留。
- 调用工作流的API访问链接，检查返回数据的格式是否符合预设的文档结构。
