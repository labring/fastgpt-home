# 多元控股收益率的表单与交互

## 这个品类的数据长什么样
多元控股的收益率与行情日报数据来源包含集团内部核算系统、各子公司经营上报数据、第三方金融行情接口。数据更新节奏为每日收盘后统一汇总生成，当日数据需完成全板块的核对校验后对外发布。文档结构以业务板块为核心拆分单元，每份日报包含板块标识、当日盈亏情况、累计收益规模、持仓资产净值等结构化字段，字段单位统一使用法定货币计价单位，附带各板块当日行情异动的简短备注。

## 这些特征在「表单与交互」这一环带来什么约束
由于数据来自多源且按业务板块拆分，表单交互需支持多数据源的字段映射配置，确保不同来源的板块数据能统一展示。数据更新存在固定时段，交互环节需限制查询触发的有效时间范围，避免用户获取未完成校验的过期数据。多板块的明细字段会增加信息总量，表单需支持板块筛选与字段自定义展示，避免界面过载。同时，由于数据层级包含集团整体与各子板块，交互需支持层级展开查看明细，确保用户可按需获取对应粒度的信息。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `recallCount` | 前8-12条 | 多元控股日报包含多业务板块的行情数据，需覆盖足够板块以满足常规查询需求，避免遗漏核心信息 |
| `maxContext` | 8000-12000 字符 | 集团级日报的明细数据较多，需承载完整的板块字段与备注内容，适配大模型的上下文承载上限 |
| `SIMILARITY_THRESHOLD` | 0.72-0.80 | 需区分不同业务板块的收益数据，避免低相关的板块信息混入查询结果，提升信息精准度 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 多元控股日报通常附带多份子公司的明细报表，整体解析耗时较长，需预留足够的文档处理时间 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 日报文档可能包含多份附件与明细表格，整体体积较大，需适配大容量文件的上传需求 |
| `SCHEDULER_CRON` | 0 18 * * * | 国内金融市场每日15点收盘，预留3小时的数据汇总与校验时间，设置每日18点触发自动更新任务 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用`gpt-4o-mini`时输入特定板块数值触发400报错，更换其他模型后恢复正常。原因：未配置针对大模型的上下文截断规则，导致请求体超出模型支持的token上限。
- 现象：语音输入后返回的播报内容与日报数据不匹配，出现无关板块的收益信息。原因：未将语音识别后的文本与预设的业务板块字段做映射校验，直接传入大模型导致语义混淆。
- 现象：挂载本地部署的LLM后，交互返回结果与知识库内容无关，使用本地推理工具时表现正常。原因：未配置模型的上下文召回参数，导致知识库内容未被正确加载到模型推理环节。

## 怎么确认配好了
- 上传一份测试用的多元控股日报文档，检查解析后的字段是否包含业务板块标识、当日盈亏金额等预设字段，无解析异常提示。
- 发起包含特定业务板块名称的查询，核对返回结果中仅包含对应板块的收益数据，无其他无关板块的信息混入。
- 设置定时触发任务，在每日收盘后检查自动生成的播报内容是否包含最新的更新时间戳，确认数据时效性。
- 测试语音输入功能，确认识别后的文本能正确匹配到预设的板块与数值字段，无语义偏差或字段错位。
