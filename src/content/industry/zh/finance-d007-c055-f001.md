# 大气治理收益率的HTTP 接口与外部系统

## 这个品类的数据长什么样
大气治理项目的收益率与行情日报数据，主要来自现场监测传感器、企业环保运营台账、地方生态环境部门的减排核算系统。数据更新分为两个节奏：实时监测点位的污染物浓度每5分钟刷新一次，用于日报的全量统计数据则在每日凌晨完成前一日的核算更新。标准数据文档为JSON格式，包含监测点位编码、PM2.5/PM10/SO2/NOx浓度值、治理设备启停时长、能耗数据、减排量核算值、对应补贴或收益金额等字段，其中`monitor_point_id`为16位字符串标识，`daily_income`为当日收益金额，单位为元。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
大气治理数据的多节奏更新特性，要求HTTP接口同时支持实时单点查询和批量日报拉取两种模式。多字段的复杂数据结构，要求接口支持字段过滤功能，避免无效数据传输占用带宽。减排收益与官方核算凭证绑定的特性，要求外部系统调用接口时必须携带凭证参数，否则接口会过滤相关数据。每日凌晨的全量更新峰值，要求接口限流配置需匹配该时段的请求压力，避免外部系统在高峰时段被拦截。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `API_REQUEST_TIMEOUT` | `10 秒` | 实时监测数据的传输延迟通常在5秒内，超时设置可避免阻塞外部系统的请求队列 |
| `BATCH_FETCH_SIZE` | `50 条/次` | 大气治理监测点位数量通常在数十到数百区间，单次拉取50条可平衡传输效率与服务器负载 |
| `FIELD_SELECTION_ENABLED` | `开启` | 大气治理数据字段较多，开启后可按需返回`monitor_point_id`、`daily_income`等核心字段，降低带宽占用 |
| `RATE_LIMIT_PER_MINUTE` | `100次` | 每日凌晨更新时段的峰值请求量约为80次/分钟，预留合理缓冲以避免限流拦截 |
| `VOUCHER_REQUIRED` | `开启` | 减排收益数据需关联官方核算凭证，开启后可拦截未携带有效凭证的无效请求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用接口返回`400 Bad Request`，提示`invalid field filter`。原因是未开启`FIELD_SELECTION_ENABLED`配置，直接传入了自定义字段列表，导致接口无法识别请求参数。
- 每日凌晨拉取日报数据时频繁超时。原因是未调整`RATE_LIMIT_PER_MINUTE`配置，在峰值时段超出接口限流阈值，被服务端拦截。
- 外部系统接收的`daily_income`字段为空。原因是未开启`VOUCHER_REQUIRED`配置，未携带核算凭证ID，接口过滤了无凭证的收益数据。

## 怎么确认配好了
- 调用配置后的接口，检查返回字段是否与预设的`FIELD_SELECTION_ENABLED`配置匹配，确认仅返回指定的核心字段。
- 在每日凌晨的峰值时段发起批量请求，检查接口返回状态码是否均为`200 OK`，确认限流配置生效。
- 传入带有合法核算凭证ID的请求，检查返回的`daily_income`字段是否存在有效值，确认数据校验配置正常。
- 发起实时数据查询请求，检查返回延迟是否符合预期，确认超时配置合理。
