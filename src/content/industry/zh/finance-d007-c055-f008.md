# 大气治理收益率的工具调用与插件

## 这个品类的数据长什么样
大气治理相关的收益率与行情数据主要来源于全国碳排放权交易市场公开成交数据、地方生态环境部门的监测台账、第三方大气治理运营机构的上报数据。数据更新节奏分为三类：碳排放交易成交数据每日收盘后同步更新，实时监测数据每小时更新，项目运营类数据每月更新。单条数据文档包含`数据上报时间`、`业务场景编码`、`核心污染物类型`、`当日收益额`、`成本占比`、`区域编码`六个核心字段，其中`当日收益额`单位为元，`成本占比`以小数形式表示，`业务场景编码`为6位数字字符串。

## 这些特征在「工具调用与插件」这一环带来什么约束
这些特征对工具调用与插件环节带来多维度约束。多更新节奏的数据源要求工具调用需支持按数据类型配置触发时机，避免拉取过时的小时级监测数据或延迟的月度运营数据。固定的字段格式要求工具参数校验规则需匹配`业务场景编码`的6位数字格式、`当日收益额`的非负数值范围。多源数据的权限差异要求插件需支持配置不同数据源的认证参数，如碳排放交易市场接口的API密钥。单条数据字段明确且数量有限，要求工具调用的返回模板需严格映射指定字段，避免引入无关信息干扰后续处理。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `tool_call_max_retries` | `2 次` | 大气治理数据源接口存在临时波动，重试2次可覆盖多数临时故障，避免过度消耗资源 |
| `plugin_exec_timeout` | `30 秒` | 实时监测数据接口响应通常在10秒内，月度运营数据接口响应较慢，30秒可覆盖多数场景的超时需求 |
| `tool_param_validation` | `开启` | 需校验`业务场景编码`的6位数字格式与`当日收益额`的非负数值范围，避免无效调用 |
| `tool_param_schema` | `{"business_code": "regex:^\\d{6}$", "income_amount": "min:0"}` | 匹配大气治理数据的字段格式要求，过滤不符合规范的参数输入 |
| `max_context_window` | `800–1200 字符` | 单条大气治理数据文档长度较短，该区间可容纳足够的历史上下文，同时符合多数大语言模型的窗口限制 |
| `plugin_auth_method` | `api_key` | 多数大气治理数据源的公开接口采用API密钥认证，匹配插件的配置逻辑 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工具调用未触发，大语言模型直接生成自然语言回答，日志中无工具调用请求。原因：未正确配置`tool_param_schema`的校验规则，模型生成的参数不符合`业务场景编码`的6位数字格式要求，被系统拦截后跳过工具调用环节。
- 现象：插件返回结果中`当日收益额`字段为空，或字段格式不符合预设要求。原因：未在`tool_param_schema`中开启必填字段校验，或数据源接口返回的字段名与预设模板不匹配，导致数据映射失败。
- 现象：插件执行超时，界面显示请求超时，日志中返回`504`状态码。原因：`plugin_exec_timeout`参数取值过短，未覆盖月度运营数据接口的响应时长，导致工具调用未完成即被系统终止。

## 怎么确认配好了
- 发起一次测试调用，传入符合`业务场景编码`格式的参数，检查日志中是否存在工具调用请求与对应的返回数据。
- 手动修改参数为不符合格式的内容，确认系统是否拦截工具调用并返回参数错误提示。
- 调整`plugin_exec_timeout`为不同取值，测试不同数据源的接口响应，确认超时逻辑符合预期。
- 上传一份大气治理项目文档至Doc2x插件，确认插件能否正确解析并返回结构化数据。
