# 小家电收益率的工作流编排

## 这个品类的数据长什么样
小家电收益相关数据主要来自垂直IoT运维平台、二手家电交易API及地方家电补贴系统。数据更新节奏为每日凌晨批量生成前一日的统计结果，仅覆盖已完成当日交易或运维的设备型号。单条数据文档为结构化JSON格式，包含`device_id`（字符串，设备唯一标识）、`standard_device_model`（字符串，统一型号名称）、`daily_income`（元，单位人民币）、`total_usage_hours`（小时）、`trade_times`（整数，交易次数）等字段，无嵌套复杂结构，单条数据量较小但整体数据集随型号覆盖范围扩大而线性增长。

## 这些特征在「工作流编排」这一环带来什么约束
小家电收益数据的多数据源接入特性要求工作流需配置多个独立的数据拉取节点，分别对接不同的第三方API，并为每个节点配置专属的鉴权参数。日更的更新节奏要求工作流触发节点需设置为定时触发，避免实时拉取导致的无效请求与资源浪费。多字段的格式差异要求数据清洗节点需配置统一的字段映射规则，将不同数据源的非标准型号字段转换为通用的`standard_device_model`格式。此外，小家电型号覆盖范围广，单批次拉取的数据量较大，需配置批量处理分片参数，避免单次处理导致的节点超时或内存溢出。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `trigger_type` | 定时触发（每日02:00） | 匹配小家电收益数据的日更更新节奏，避免拉取未完成的当日数据 |
| `api_concurrent_limit` | 3 并发/平台 | 小家电数据源多为垂直限流API，该取值可避免触发`429 Too Many Requests`限流错误 |
| `timeout_threshold` | 600 秒 | 单批次拉取多型号数据耗时较长，预留足够超时时间以覆盖全量数据拉取需求 |
| `data_mapping_rule` | 按`origin_model`映射为`standard_device_model` | 统一多数据源的型号字段格式，适配后续的日报播报逻辑 |
| `batch_size` | 200 条/批 | 平衡数据处理效率与节点负载，避免单次处理数据量过大导致的运行异常 |
| `retry_count` | 2 次 | 应对临时API波动，减少无效重试对数据源的额外压力 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中的数据库连接节点显示`connect ETIMEDOUT`错误，本地可正常访问数据库。原因：工作流容器的网络模式未配置为与本地一致，或容器内的数据库访问白名单未添加FastGPT容器IP。
- 现象：调用工作流时返回参数缺失提示，无法正常触发执行。原因：未在工作流的`input_schema`配置中声明必填字段，或调用时未传入对应参数。
- 现象：多节点部署后，部分节点无法加载最新的工作流配置文件。原因：未将配置文件挂载到共享存储，或未配置`SHARED_DATA_DIR`环境变量实现节点间的数据同步。

## 怎么确认配好了
- 手动触发工作流一次，检查拉取到的小家电数据字段是否与预设的标准字段一致。
- 查看工作流的运行日志，确认未触发限流或超时类错误。
- 等待定时触发节点的执行时间，确认无手动干预的情况下自动生成日报数据。
- 检查多节点部署的共享目录，确认所有节点均可访问到最新的工作流配置文件。
