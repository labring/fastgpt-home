# 小家电收益率的工具调用与插件

## 这个品类的数据长什么样
小家电收益率与行情数据主要来源于国家能效标识公开数据库、第三方家电零售监测接口及厂商供货价文档。数据更新节奏为每日凌晨2点至4点完成前一日全品类全量数据更新，热门SKU每6小时补充一次实时调价的增量数据。数据以结构化JSON格式存储，单条数据包含固定字段：`sku_id`（12位数字字符串）、`product_name`（中文产品名称）、`purchase_price`（浮点型，单位：元）、`retail_price`（浮点型，单位：元）、`hourly_energy_use`（浮点型，单位：千瓦时）、`market_avg_price`（浮点型，单位：元）、`daily_energy_saving`（浮点型，单位：元）。数据字段均为扁平结构，无嵌套复杂层级。

## 这些特征在「工具调用与插件」这一环带来什么约束
小家电数据的多源属性、分层更新节奏及扁平结构化特征，对工具调用与插件配置带来明确约束。多源数据源要求插件支持并行调用多个接口并合并去重结果，防止单一数据源异常导致数据缺失。每日全量更新搭配热门SKU每6小时增量更新的节奏，要求插件配置混合定时任务：每日执行全量拉取任务，每6小时执行热门SKU增量拉取任务，同时需限制单批次请求的SKU数量，避免接口超时。扁平JSON结构要求插件字段映射无需处理嵌套层级，但需严格匹配字段名与数据类型，否则会导致后续收益计算逻辑出错。庞大的SKU总量要求插件配置分页拉取参数，防止单次请求返回数据量过大。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `tool_call_timeout` | `300 秒` | 小家电数据接口响应通常在120秒内，预留足够缓冲避免因数据拉取超时导致任务失败 |
| `plugin_max_parallel` | `3–5 个` | 小家电SKU数量较多，并行调用过多会触发接口限流，过少则会延长全量数据拉取时长 |
| `page_size` | `50–100 条` | 单页数据量过大易导致接口响应超时，过小则会增加请求次数，需按实测标定合适的区间 |
| `retry_times` | `2 次` | 小家电数据接口偶发网络波动，重试次数过多会延长任务周期，过少则无法覆盖临时异常 |
| `field_mapping_strict` | `开启` | 小家电数据字段格式固定，严格匹配可避免字段解析错误导致的收益计算偏差 |
| `scheduled_task_cron` | `0 2 * * *` | 数据源每日凌晨完成全量数据更新，此时拉取可获取最新完整数据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为插件调用返回`400 Bad Request`，配置的`daily_energy_saving`字段返回为空。原因是未严格按照配置的字段映射规则匹配数据源字段，将`daily_energy_saving`误写为`energy_saving`导致解析失败。
- 现象为定时任务仅拉取到部分SKU数据，未完成全量更新。原因是未配置`page_size`参数，或取值超出接口单次返回上限，导致分页逻辑中断。
- 现象为调用自定义Python脚本插件时无有效返回结果。原因是未将Python脚本部署为可访问的接口服务，或未在FastGPT插件配置中正确填写接口地址与请求参数，对应社区中常见的自定义插件连接Python代码的问题。

## 怎么确认配好了
- 进入FastGPT的插件调试页面，手动触发一次插件调用，检查返回数据是否包含所有配置的字段，字段值与数据源公开信息一致。
- 查看定时任务执行日志，确认每日全量拉取任务与每6小时增量拉取任务均正常执行，无超时或报错记录。
- 模拟多轮工具调用场景，验证插件在并行调用多个数据源时的结果合并是否正确，无重复或缺失数据。
- 断开其中一个数据源接口触发异常场景，验证插件的重试机制与异常处理逻辑是否生效，无任务中断。
