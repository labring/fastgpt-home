# 工程咨询收益率的对话日志与审计

## 这个品类的数据长什么样
面向金融、理财、保险行业的工程咨询收益率与行情数据，来源于建筑装饰行业造价管理机构发布的当期建材价格指数、项目现场的成本归集台账与公开招投标报价数据。更新节奏为每日凌晨更新前一日的全品类行情数据，项目级日报随项目周度进度节点同步。单条数据文档结构包含项目编码、项目名称、工程类型、当日单位造价、累计造价、基准收益率、当日造价波动值、关联建材品类清单。字段单位分别为：单位造价元/平方米，累计造价万元，收益率为无量纲小数，波动值元/平方米。

## 这些特征在「对话日志与审计」这一环带来什么约束
多源数据的获取要求对话日志必须记录每一次数据调用的溯源标识，审计环节可快速核对数据来源合规性。每日高频更新的特性要求日志保留精确到秒的调用时间戳，避免跨版本数据比对出现偏差。多字段与关联建材清单的结构要求日志完整记录上下文筛选条件，包括工程类型、建材品类范围。多样的单位体系要求日志自动校验并记录字段单位，审计环节可直接核验单位匹配性。建筑装饰工程审计的合规要求，要求日志留存完整的模型调用参数与结果校验记录，留存周期符合行业常规要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `LOG_RETENTION_DAYS` | `90 天` | 匹配建筑装饰工程审计的常规留存周期，覆盖完整的季度审计流程 |
| `LOG_INCLUDE_SOURCE` | `开启` | 适配多源数据的溯源需求，需记录每一条数据调用的原始来源标识 |
| `MAX_CONTEXT_TOKENS` | `8000–12000` | 工程咨询数据包含多字段与关联建材清单，需保留完整上下文用于审计回溯 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 工程咨询文档通常包含多标段数据，解析耗时较长，避免超时截断日志 |
| `AUDIT_LOG_ENABLE` | `开启` | 满足合规审计要求，需单独留存对话交互的完整审计链路记录 |
| `LOG_LEVEL` | `DEBUG` | 需记录详细的调用参数与结果，便于审计时排查数据异常与链路问题 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用关联的推理服务返回`500 Internal Server Error`，系统日志未显示具体报错堆栈。原因：未配置`LOG_LEVEL`为`DEBUG`，仅留存基础日志层级，无法捕获推理服务的详细异常信息。
- 现象：第三方渠道的交互消息未出现在对话日志中，后台配置显示消息发送成功。原因：未开启`LOG_INCLUDE_SOURCE`，未记录第三方交互的溯源标识，导致日志缺失完整链路。
- 现象：对话日志中未记录字段单位信息，审计校验时无法匹配业务规则。原因：未开启字段元数据的日志记录，未配置`LOG_LEVEL`为`DEBUG`，导致单位信息未被完整留存。

## 怎么确认配好了
- 查看`LOG_LEVEL`的配置项，确认当前取值为`DEBUG`，可通过系统日志面板查看是否包含详细的调用堆栈信息。
- 进入对话日志列表，随机选择一条交互记录，确认包含数据源标识、字段单位、调用参数等完整元数据。
- 开启审计日志开关，查看独立的审计链路页面，确认包含完整的对话交互与数据调用的全流程记录。
- 模拟一次数据调用，检查日志中是否记录了精确到秒的时间戳，覆盖完整的上下文参数。
