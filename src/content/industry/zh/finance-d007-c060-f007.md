# 工程咨询收益率的工作流编排

## 这个品类的数据长什么样
工程咨询的收益数据来源包括内部造价测算台账、行业协会发布的建筑装饰造价参考指标、委托方提供的项目投资计划书。数据更新节奏随项目推进阶段调整，方案阶段每两周更新一次，施工图阶段每周更新，结算阶段实时同步。文档采用结构化表格形式，包含项目唯一标识、咨询服务范围、基准收益参数、测算依据文件编号、各阶段收益测算值、数据校验标记。字段包括`project_id`（字符串类型）、`benchmark_return`（比例值，无单位）、`stage_return`（比例值，无单位）、`verify_flag`（布尔类型）。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散要求工作流配置多数据源拉取节点并实现数据对齐；分阶段的更新节奏要求工作流支持按项目阶段触发执行，避免固定定时触发的冗余执行；结构化的表格文档要求工作流配置专门的表格解析节点，提取指定字段；字段的唯一性要求工作流加入字段校验节点，过滤重复或无效数据；多角色并行测算的场景要求全局变量支持按用户隔离，避免数据冲突。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `trigger_mode` | 按`project_id`绑定的阶段触发 | 适配工程咨询项目分阶段更新的节奏，避免固定定时触发的冗余执行 |
| `data_source_pull_count` | 前3个数据源 | 覆盖内部台账、行业指标、委托方文件三类核心数据源，避免过多数据源导致执行超时 |
| `field_extract_batch_size` | 1200 字符 | 匹配工程咨询测算文档的单页表格长度，保障字段提取完整性 |
| `global_var_scope` | 按`user_id`隔离 | 适配多咨询工程师并行测算的场景，避免不同用户的全局变量互相干扰 |
| `post_prompt_template` | 「请结合本次测算的{stage_return}值，补充说明造价调整要点」 | 匹配工程咨询场景的业务引导需求，替代系统默认引导 |
| `workflow_timeout` | 600 秒 | 覆盖多数据源拉取和表格解析的耗时需求，避免执行中断 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用工作流API时返回`context_invalid`状态码，返回结果缺失历史对话上下文。原因：未将工作流的`context_scope`配置为绑定`user_id`，导致上下文未按用户隔离，不同请求的上下文互相覆盖。
- 现象：工作流执行后无法加载历史保存的全局变量，全局变量字段显示为空。原因：未配置全局变量的加载触发节点为会话启动时加载，仅在当前会话初始化变量，无法跨会话复用历史数据。
- 现象：AI回复后仅显示系统默认的猜你想问引导语，未生成定制化业务引导内容。原因：未在工作流的`post_prompt_template`中配置自定义引导语模板，沿用了系统默认配置。

## 怎么确认配好了
- 发起一次携带测试`user_id`和`project_id`的请求，检查返回结果中是否包含正确的上下文信息。
- 发起两次携带相同`user_id`的请求，检查两次请求的全局变量是否保持一致，不同`user_id`的请求的全局变量是否互不干扰。
- 触发工作流执行后，检查AI回复后是否显示配置的自定义引导语模板内容。
- 查看工作流执行日志，确认触发模式、数据源拉取数量、超时设置均符合配置项的取值。
