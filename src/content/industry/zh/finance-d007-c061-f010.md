# 工程机械收益率的数据库与运维

## 这个品类的数据长什么样
工程机械收益率相关数据来源于工程设备物联网平台、企业ERP系统、设备租赁结算系统及燃油补给记录系统。核心统计维度覆盖单台设备单日的作业时长、燃油消耗、维保支出、租赁收入与直接运营成本。文档结构为单条记录对应单台设备单日经营数据，包含设备唯一标识、归属项目标识、统计日期等标识字段，以及量化的作业、成本、收入类字段。更新节奏分为两类：核心经营数据每日凌晨同步前一日全量记录，实时运行类数据每15分钟同步一次，用于辅助精细化收益率计算。字段单位统一采用国际通用计量标准，如作业时长单位为小时，燃油消耗单位为升，收入与成本单位为元。

## 这些特征在「数据库与运维」这一环带来什么约束
多源数据的异构性带来数据清洗约束：需统一不同系统采集的字段格式与单位，避免计算偏差。每日批量同步的全量经营数据体量较大，需配置按日期分区的存储策略，降低单表查询压力。实时运行数据的高频写入需求，要求数据库支持低延迟的流式写入能力，同时需与批量同步的日结数据做关联校验。单条记录的字段维度丰富，需为高频查询的字段建立联合索引，提升查询效率。部分量化字段存在合理范围限制，需配置数据校验规则，过滤异常录入的无效数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `mongo_write_concern` | `w:1` | 平衡高频小批量实时写入的延迟与数据可靠性，适配多源数据同步场景 |
| `pgvector_max_connection` | `200` | 匹配200并发的查询请求，避免连接池耗尽导致服务中断 |
| `batch_process_size` | `800–1200 条` | 适配每日批量同步的日结数据体量，避免单次处理超时 |
| `data_cleanup_policy` | `保留180 天原始数据，聚合数据保留365 天` | 平衡存储成本与历史数据查询需求 |
| `stream_process_timeout` | `600 秒` | 适配实时数据流的处理窗口，避免中途中断导致的数据丢失 |
| `ollama_model_context_window` | `32768 令牌` | 适配大模型的输入长度要求，支持完整的设备经营数据上下文 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 出现`MongoConnectionTimeoutError`报错，无法完成日结数据同步：原因是未调整数据库连接池参数适配并发请求，导致连接耗尽无法建立新会话。
- 进入pgvector容器后无法执行SQL命令，提示`invalid input syntax for type numeric`：原因是未统一多源数据的字段单位，导致清洗后的数值格式不符合数据库字段要求。
- 实时运行数据同步出现丢包，部分设备的作业时长字段为空：原因是`stream_write_batch_size`参数设置过大，导致部分写入请求被数据库拒绝。

## 怎么确认配好了
- 执行按设备ID与统计日期的联合查询，核对返回结果的条数与预期覆盖的设备数量一致：阈值需根据实际部署的设备规模调整。
- 查看数据库运维日志，确认批量同步任务按预设周期完成，无超时或连接失败记录：需核对任务执行时间与日结生成节奏的匹配性。
- 发起对应并发规模的查询请求，确认无连接耗尽或服务中断报错：需按实际业务的并发峰值调整测试参数。
- 手动录入超出合理范围的量化字段值，确认系统自动拦截无效数据：需结合设备额定运行参数设定校验规则。
