# 工程机械收益率的模型接入与配置

## 这个品类的数据长什么样
工程机械收益率相关数据主要来源于设备厂商运维后台、工程租赁平台台账、工程结算系统三类渠道。单日作业数据每日更新，包含单台设备的作业时长、台班单价、燃油消耗、当日营收等明细；月度租赁结算数据每月更新，包含设备整月的营收、成本与累计收益。数据以结构化CSV或JSON格式存储，每条记录对应单台设备单日收益明细，字段包含设备唯一标识、设备型号、作业参数、成本项、收益项，单位统一为小时、元等基础计量单元，无聚合类百分比统计内容。

## 这些特征在「模型接入与配置」这一环带来什么约束
多字段关联的收益计算逻辑要求模型接入时配置多源数据的关联匹配规则，避免单字段计算的误差。不同数据源的更新节奏差异，需要配置增量拉取与全量拉取的切换参数，区分每日作业数据和月度结算数据的拉取周期。设备型号与作业场景对应的字段取值差异较大，需要配置型号与字段映射的规则，统一不同设备的统计口径。分散的数据源接入需要配置多路由的请求分发参数，确保不同来源的数据准确汇入收益计算流程。数据的时效性要求配置合理的拉取超时阈值，避免因拉取旧数据导致日报内容失真。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `vectorModel` | `bge-large-zh-v1.5`（本地部署）或`text-embedding-3-small`（云端） | 该模型对结构化数值与文本混合字段的向量编码适配性较好，匹配工程机械收益率数据的字段特征 |
| `recallTopK` | 前8条 | 工程机械收益率数据的关联字段较多，召回8条可覆盖核心关联维度，避免遗漏关键计算参数 |
| `similarityThreshold` | 0.72–0.78 | 该区间可过滤低关联度的设备数据，同时保留同型号设备的收益对比数据，适配多型号并行计算的需求 |
| `dataSourceRefreshInterval` | 每600秒 | 匹配工程机械单日作业数据的更新频率，确保每日收益数据的实时性 |
| `multiSourceMatchThreshold` | 0.85 | 用于匹配不同数据源中的同一设备ID，确保租赁数据与运维数据的关联准确性 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300秒 | 适配结构化数据解析的耗时需求，避免因多字段解析导致的超时失败 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：测试模型调用返回403 status code (no body)，原因：未配置正确的模型接入密钥与请求域名白名单，本地部署时未开放对应端口的访问权限。
- 现象：收益率计算结果出现字段为空或数值异常，原因：未配置多源数据的匹配阈值，导致不同数据源的设备ID无法正确关联，遗漏核心计算字段。
- 现象：提示词无法识别输入中的空格分隔的设备型号，原因：未在提示词模板中配置空格作为分隔符的识别规则，导致模型无法正确拆分多设备标识。

## 怎么确认配好了
- 执行单台设备的收益计算测试，核对模型输出的收益率结果与手动计算的基准值是否一致，调整相似度阈值与召回条数至匹配结果符合预期。
- 查看数据源刷新日志，确认每日作业数据与月度结算数据的拉取时间符合配置的刷新间隔，无超时或拉取失败记录。
- 测试多设备并行计算的场景，核对模型是否能正确关联不同数据源的设备数据，无字段缺失或匹配错误。
- 调用模型接口测试包含空格的设备型号输入，确认模型能正确识别并处理输入内容。
