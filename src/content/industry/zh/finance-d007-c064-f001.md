# 影视院线收益率的HTTP 接口与外部系统

## 这个品类的数据长什么样
影视院线的收益率数据主要来自院线内部POS结算系统、第三方影视数据服务接口，更新节奏为每日营业结束后1至2小时内完成当日数据同步。单条数据文档包含影院编码、影片唯一标识、当日累计票房、当日排片场次、场均观影人次、单厅单日营收等字段，字段单位统一为人民币元、场次、人次，无嵌套层级，每条数据对应单影院单影片的当日经营数据。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
数据源分散且更新时段集中，要求HTTP接口需支持峰值时段的批量请求，避免接口阻塞。单条数据字段扁平且无嵌套，无需复杂的JSON解析逻辑，但需严格匹配字段名与单位，否则会导致数据匹配失败。每日数据同步窗口固定，外部系统需在同步时段内完成数据拉取，否则会获取到延迟数据。部分第三方数据源存在接口限流，需配置合理的请求间隔，避免触发限流机制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `external_api_request_timeout` | `30 秒` | 适配影视院线数据源的常规响应时长，避免超时错过固定同步窗口 |
| `max_batch_request_size` | `150 条/次` | 匹配单批次拉取的影院-影片数据规模，降低接口负载 |
| `api_request_rate_limit` | `8 请求/分钟` | 符合多数第三方影视数据接口的限流规则，适配每日批量拉取需求 |
| `field_strict_match` | `启用` | 影视院线数据字段扁平且单位固定，严格匹配可避免解析偏差 |
| `scheduled_sync_time` | `每日 20:30-21:30` | 对应院线营业结束后的常规数据更新时段，获取最新当日数据 |
| `retry_max_attempts` | `2 次` | 应对临时接口波动，避免重复请求触发限流 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用外部接口返回`Api response error: undefined`，无具体错误信息。原因：未启用`field_strict_match`参数，导致接口返回的字段单位与预期不符，解析过程中抛出未捕获异常。
- 现象：每日同步任务超时失败，返回`504 Gateway Timeout`状态码。原因：同步窗口配置过晚，错过数据源的更新时段，拉取延迟数据导致请求时长超出阈值。
- 现象：拉取的数据字段缺失，仅包含部分基础标识字段。原因：未设置`max_batch_request_size`参数，单次请求数据量过大，第三方接口截断返回不完整数据。

## 怎么确认配好了
- 发起单次小批量测试请求，检查返回数据的字段与配置的`field_strict_match`规则是否一致。
- 在配置的`scheduled_sync_time`窗口内手动触发同步任务，核对拉取到的数据是否为当日最新的院线经营数据。
- 查看接口调用日志，确认请求频率未超出配置的`api_request_rate_limit`阈值，无`403 Forbidden`或`504 Gateway Timeout`类错误日志。
- 对比第三方数据源的官方文档，确认拉取到的字段单位与配置的解析规则完全匹配。
