# 房建工程收益率的工作流编排

## 这个品类的数据长什么样
房建工程的收益率相关数据主要来自造价管理系统、施工进度台账数据库、区域建材报价平台。数据更新节奏为月度同步，匹配当期施工进度款的核算周期。单份数据文档包含项目唯一标识、工程分项名称、施工区域、当期完成工程量、单位工程量成本、累计投入资金、当期营收预估等字段，字段单位涵盖元、平方米、立方米、万元等实物计量与计价单位。

## 这些特征在「工作流编排」这一环带来什么约束
房建工程数据的月度更新节奏，要求工作流触发周期需严格匹配月度核算节点，避免频繁执行造成资源浪费。多分项、多字段的结构，要求工作流的数据清洗环节需增加字段校验逻辑，区分实物计量与计价单位，防止计算混淆。来自多系统的数据源，要求工作流配置跨库数据关联步骤，通过项目唯一标识完成数据对齐。单份数据文档的体积与条目规模，要求工作流的批量处理模块设置合理的分片阈值，避免单次执行超时。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `workflow_trigger_cron` | `0 0 2 1 * ?` | 匹配月度核算的滞后窗口期，确保拉取到上月完整的施工与造价数据 |
| `database_batch_fetch_size` | `5000 条` | 适配房建工程台账的单表条目规模，避免单次拉取触发系统超时限制 |
| `data_cleaning_field_check` | 启用 | 房建工程数据包含多类单位字段，需校验单位一致性以保障计算准确性 |
| `workflow_timeout_seconds` | `1800 秒` | 预留足够时长处理大体积的分项工程数据与跨库关联操作 |
| `cross_db_join_mode` | 内连接 | 仅保留匹配到项目唯一标识的有效数据，排除无效冗余条目 |
| `log_output_destination` | 系统日志中心+自定义存储 | 留存代码运行模块的输出日志，便于后续排查问题 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：连接MSSQL数据库时出现`Failed to connect to jyfkk:1433 - 38BBDDC3AF7F0000`报错。原因：未配置数据库访问白名单，或工作流中填写的数据库实例名称与实际部署的不一致。
- 现象：代码运行模块的`console.log`日志无法在界面控制台查看。原因：未开启工作流的详细日志采集开关，日志仅输出至系统后台日志中心。
- 现象：处理10万条级别的房建工程台账数据时出现执行超时。原因：未设置数据库批量拉取的分片阈值，单次拉取全部数据超出系统处理上限。

## 怎么确认配好了
- 查看工作流的定时触发日志，确认触发节点与月度核算周期对齐。
- 执行单次测试运行，验证数据拉取环节可成功获取项目标识、工程量、成本等核心字段。
- 登录系统日志管理界面，确认代码运行模块的输出日志已正常留存。
- 抽取单条测试数据，核对工作流生成的收益率计算结果与手动核算结果一致。
