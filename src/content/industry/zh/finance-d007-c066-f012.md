# 房建工程收益率的模型接入与配置

## 这个品类的数据长什么样
房建工程的造价收益率相关数据主要来自项目BIM成本台账、月度施工进度款结算文件、区域住建部门发布的工程材料计价指数。数据更新节奏按项目节点划分：单体项目的周度进度款结算完成后更新当期投入与结算数据，区域级行业数据按月度更新。文档多为结构化Excel或CSV格式，包含项目编号、工程部位、当期投入、累计投入、对应计价项的基准价、当期结算价等字段，字段单位包含元/平方米、万元、自然月，无统一的标准化命名规则。

## 这些特征在「模型接入与配置」这一环带来什么约束
房建工程数据的多源属性要求配置支持多数据源接入的适配规则，避免因不同来源的文档格式差异导致解析失败。数据更新的分周期节奏，要求配置可自定义触发频率的定时同步任务，适配周度单体项目与月度区域数据的更新需求。结构化文档的非标准化字段命名，要求配置灵活的字段映射规则，确保解析后的数据字段与模型输入要求匹配。不同计价项的单位差异，要求配置单位归一化参数，避免模型混淆不同单位的数值计算。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_FILE_FIELD_MAPPING` | 按实际结算文档列名映射为`project_id, location, current_input, total_input, benchmark_price, current_settlement_price` | 匹配房建工程结算文档的标准字段定义 |
| `DATA_REFRESH_CRON` | `0 0 2 * * ?`（每日2点触发）或`0 0 1 * * ?`（每月1号触发） | 适配房建工程周度/月度数据更新的节奏 |
| `MAX_CONTEXT_LENGTH` | `8000-12000 字符` | 适配单份房建工程结算文档的平均解析长度 |
| `SIMILARITY_THRESHOLD` | `0.75-0.85` | 区分不同工程部位的计价差异，提升召回精度 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 覆盖单项目大型结算文件的常见大小 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 适配大型结构化文档的解析耗时 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：模型返回结果仅包含思考过程，无最终收益率数值。原因：未将`model_output_format`参数配置为同时输出思考过程与结构化结果。
- 现象：结构化文件解析后出现字段缺失或错位。原因：未按房建工程结算文档的实际列名配置`PARSE_FILE_FIELD_MAPPING`参数，默认映射规则与文档字段不匹配。
- 现象：上传结算文件时界面显示`413 Request Entity Too Large`报错。原因：未将`UPLOAD_FILE_MAX_SIZE`配置为适配房建工程大型文件的取值，超出平台默认限制。

## 怎么确认配好了
- 上传单份房建工程结算文档，核对解析后的字段列表与配置的`PARSE_FILE_FIELD_MAPPING`是否一致，不一致则调整映射规则。
- 手动触发一次数据同步任务，核对更新后的数据时间戳与配置的`DATA_REFRESH_CRON`触发规则是否匹配，不匹配则调整 cron 表达式。
- 发起模型调用请求，核对返回内容是否包含预期的思考过程与收益率相关结果，格式不符合则调整`model_output_format`参数。
- 上传超出预设大小的测试文件，确认平台返回的报错信息符合配置的`UPLOAD_FILE_MAX_SIZE`限制，不符合则调整参数取值。
