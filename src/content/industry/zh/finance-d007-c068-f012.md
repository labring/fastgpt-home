# 投资平台收益率的模型接入与配置

## 这个品类的数据长什么样
投资平台的行情与收益率数据主要来源于交易所公开行情接口、持有的底层资产数据接口。数据更新节奏为交易日开盘后逐笔推送实时行情，收盘后生成全量当日日报文档。单篇日报文档包含多条标的记录，每条记录的固定字段包括标的代码、产品名称、当日收益率、累计收益率、成交量、成交额、单位净值，其中收益率以百分比为单位，成交量以股为单位，成交额以人民币元为单位。不同投资平台的字段命名可能存在小幅差异，但核心标识字段均为标的代码。

## 这些特征在「模型接入与配置」这一环带来什么约束
行情与收益率数据的实时性要求较高，因此需要匹配高频的定时拉取频率，避免数据滞后影响播报准确性。多标的的批量数据结构要求配置字段映射规则，确保模型能准确提取对应字段。不同投资平台的字段命名差异，要求配置数据源适配参数以统一数据格式。日报文档的生成时间固定在交易日收盘后，因此需要限定定时任务的触发范围为交易日，避免非交易时段生成无效播报。同时，行情接口存在限流规则，批量拉取的规模需要匹配接口限制，避免触发限流报错。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `workflow_trigger_cron` | `0 18 * * 1-5` | 投资平台当日日报通常在交易日18点生成，匹配该时间触发拉取与播报任务 |
| `datasource_update_interval` | `300 秒` | 行情数据在交易日每5分钟更新一次，该间隔可保证播报数据的实时性 |
| `batch_fetch_size` | `20 条/次` | 单条标的数据量较小，该批量规模可避免触发行情接口的限流限制 |
| `field_mapping_rule` | `按标的代码唯一匹配` | 标的代码为投资平台数据的唯一标识，可避免不同标的的数据混淆 |
| `response_timeout` | `10 秒` | 主流行情接口的响应延迟通常在5秒以内，该取值可预留合理冗余避免超时 |
| `data_cleanup_rule` | `过滤非业务字段` | 接口返回的调试、元数据等冗余字段会干扰模型输出，需配置清理规则 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：模型生成的播报内容中出现无关的0值字段或调试信息。原因：未配置`data_cleanup_rule`参数，未过滤接口返回的冗余非业务字段。
- 现象：定时播报任务在非交易时段触发并生成无效内容。原因：`workflow_trigger_cron`参数未限定交易日范围，全量每日触发任务。
- 现象：拉取的行情数据与实际持仓收益率不匹配。原因：`field_mapping_rule`未绑定标的代码与持仓ID的对应关系，导致数据张冠李戴。

## 怎么确认配好了
- 手动触发一次数据拉取任务，检查返回的字段是否与投资平台的日报文档结构一致。
- 查看工作流运行日志，确认定时任务在交易日的指定时间正常触发，无超时或限流报错。
- 调用模型生成测试播报内容，检查是否仅包含合法的收益率与行情字段，无冗余无关信息。
- 临时调整`datasource_update_interval`参数为`60 秒`，验证拉取频率是否按预期更新。
