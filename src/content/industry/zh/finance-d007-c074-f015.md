# 教育服务收益率的部署与升级

## 这个品类的数据长什么样
数据来源为持牌金融信息服务机构的公开行情接口与官方披露文件。更新节奏为每日收盘后完成当日全量标的数据抓取，次日凌晨完成日报内容整合与校验，确保每日仅发布一次完整日报。文档结构为单条结构化记录，包含标的类别、标的唯一标识、标的全称、统计周期、收益数值、参考基准标识、数据溯源标识。单篇完整日报文档包含50至200条标的记录，字段包括`标的唯一标识`、`统计日期`、`收益数值`、`参考基准`，其中收益数值的单位为非百分比类的标准化金融计量单元，所有记录均包含明确的统计周期与数据溯源信息，避免出现无来源的收益数据。

## 这些特征在「部署与升级」这一环带来什么约束
数据依赖第三方接口的特征要求部署时需配置合法的API访问权限与密钥，且需预设字段校验规则，避免因接口变更导致解析失败。每日固定更新的节奏要求部署时配置精准的定时触发任务，触发时间需晚于第三方数据源的常规更新窗口，确保获取到完整当日数据。单篇文档包含多量标的记录的特征，要求部署时配置合理的批量处理阈值，避免单次处理超时。升级环节中，若第三方数据源调整字段命名或结构，需快速更新字段映射规则，因此部署时需预留可配置的字段映射模块，避免硬编码解析逻辑。教育服务场景下的日报需确保数据溯源的准确性，部署时需配置数据校验环节，对`数据溯源标识`字段进行合法性校验，避免引入非合规数据源的内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `CRON_EXPRESSION` | `0 30 1 * * *` | 第三方数据源通常在当日23点前完成当日数据更新，凌晨1点30分触发可确保获取完整当日数据 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 单篇日报文档包含多量标的记录，解析耗时较长，600秒可覆盖大部分场景的解析需求 |
| `MAX_BATCH_PROCESS_COUNT` | `100 条/批次` | 单篇文档包含50至200条标的记录，分批次处理可避免单次请求超时 |
| `FIELD_MAPPING_RULE` | 按数据源返回结构配置 | 需将第三方接口返回的字段映射至平台预设的播报字段，确保内容生成逻辑正确 |
| `UPLOAD_FILE_MAX_SIZE` | `800 MB` | 单篇结构化日报文档的存储大小通常不超过400 MB，预留合理上限避免上传失败 |
| `NOTIFICATION_WEBHOOK` | 配置内部运营通知地址 | 需在日报生成完成或异常时发送通知，便于及时处理异常情况 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：部署时使用`v4.8.15-fix2`版本的Docker镜像，执行拉取命令后返回镜像无法找到的报错。原因：该版本为临时修复版本，未同步至官方镜像仓库的公开可拉取目录。
- 现象：海外部署版本配置免登录分享链接后，访问时返回`403 Forbidden`状态码。原因：未正确配置海外节点的跨域访问白名单与免登录令牌的有效时长。
- 现象：生成的日报内容中出现重复的标的记录与资讯片段。原因：未开启批量处理的去重校验规则，导致同一数据源的重复数据被多次解析并纳入最终内容。

## 怎么确认配好了
- 执行手动触发定时任务的操作，核对任务执行时间与`CRON_EXPRESSION`配置的表达式是否匹配，确认任务是否成功拉取数据源数据。
- 上传一份测试用的结构化日报文档，检查解析后的字段是否与预设的映射规则一致，确认字段提取无异常。
- 访问配置的免登录分享链接，检查页面加载状态与内容展示是否正常，确认跨域与令牌配置符合当前部署环境要求。
- 查看系统运行日志，检查是否存在数据解析或接口调用的异常报错，确认配置的校验规则已生效。
