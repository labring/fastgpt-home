# 普钢收益率的数据库与运维

## 这个品类的数据长什么样
普钢收益率数据主要来自行业现货交易平台、期货交易所公开行情接口及钢厂出厂价公示渠道。数据更新节奏为每日固定时段刷新一次，覆盖热轧卷板、螺纹钢等主流普钢品类。单条数据文档为结构化JSON格式，包含品种编码、产地、规格型号、当日结算价、前一日结算价、涨跌幅基准值、当日成交量等字段。价格字段单位为元/吨，涨跌幅字段为无量纲百分比基准值，未包含跨品类聚合统计类数据。

## 这些特征在「数据库与运维」这一环带来什么约束
每日固定时段更新的特性要求运维环节配置定时拉取任务，避免高频调用导致接口限流。结构化固定字段的特征要求数据库表结构需提前定义必填字段，避免无意义的字段冗余。价格与涨跌幅的固定单位要求存储时统一格式，无需额外转换环节。多来源的数据特性要求增加前置校验步骤，对跨渠道的同品类数据进行一致性比对，过滤异常值。同时，不同细分规格的普钢数据需单独存储，避免字段冲突导致的查询异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DATA_SYNC_CRON` | `0 15 16 * * ?` | 普钢数据每日16:00左右完成更新，提前15分钟触发可确保获取最新完整数据 |
| `DB_BATCH_INSERT_SIZE` | `500` | 单批次插入500条普钢数据可平衡写入性能与事务稳定性，避免单次插入数据过多导致超时 |
| `DATA_VALIDATE_THRESHOLD` | `0.9` | 对多来源的普钢价格数据进行一致性校验，当跨源数据偏差小于0.9倍时判定为有效数据 |
| `DB_CONNECTION_POOL_SIZE` | `10-15` | 普钢数据拉取与查询的并发量适中，10-15个连接池可满足日常运维与业务查询需求，避免连接耗尽 |
| `PARSE_DATA_TIMEOUT` | `60 秒` | 单批次500条普钢数据的解析与校验耗时通常在30-45秒，设置60秒超时可覆盖正常处理时长，避免任务中断 |
| `LOG_RETENTION_DAYS` | `90 天` | 普钢行情数据的运维日志需保留至少90天用于异常排查，符合行业数据留存规范 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用数据库节点查询普钢行情后，返回结果为原始JSON数组，无法直接提取字段值。原因：未配置数据库节点的结果解析规则，默认返回未处理的查询结果。
- 现象：定时拉取任务在每日高峰时段触发时，返回空结果或状态码503。原因：未设置数据源接口的限流保护，高频调用触发第三方接口的限流机制。
- 现象：并发调用工作流时，MCP节点返回none值，无有效数据返回。原因：未配置MCP节点的重试机制，当并发请求超过接口承载上限时，首次请求失败未触发自动重试。

## 怎么确认配好了
- 查看定时任务日志，确认每日指定时段触发数据拉取任务，无失败记录。
- 随机抽取多条普钢数据记录，核对数据库中存储的字段与数据源返回的字段一致，单位匹配。
- 模拟日常并发请求，检查数据库查询接口的连接数未超过配置的连接池上限。
- 触发一次数据校验任务，确认异常数据被过滤，无脏数据写入数据库。
