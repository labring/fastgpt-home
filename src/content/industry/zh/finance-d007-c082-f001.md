# 水产养殖收益率的HTTP 接口与外部系统

## 这个品类的数据长什么样
水产养殖的行情与收益率数据来源包括区域水产批发市场每日成交记录、养殖塘口的物联网监测终端、农业农村部门公开的养殖成本指导价。数据更新节奏为每日凌晨完成前一日全量汇总更新，单个塘口的实时投料、水质、存活数据同步间隔为15分钟。文档为JSON格式数组，每个条目包含养殖品类、塘口唯一标识、当日投料总量、平均存活苗种与投放苗种的数量比、单位产量、市场收购单价、各项成本单价等字段，单位分别为千克、无（数量比）、千克/亩、元/千克、元/亩、元/千克。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
水产养殖的数据特征对HTTP接口与外部系统环节带来多重约束。多源数据接入要求接口支持多数据源鉴权与聚合，需为每个数据源配置独立的API密钥与鉴权规则，避免跨塘口数据权限泄露。双更新节奏（每日全量汇总与15分钟实时同步）要求接口同时支持定时批量拉取与实时回调两种模式，需匹配不同的轮询间隔与回调地址配置。多字段与多样单位的文档结构，要求接口支持自定义字段返回与单位说明携带，避免外部系统因单位不统一导致计算错误。按塘口与养殖品类的多维度查询需求，要求接口请求参数支持多条件过滤，需配置对应的默认过滤规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `dataSourceAuth` | 为每个数据源配置独立API密钥与鉴权方式 | 区分多源数据权限，避免跨塘口数据泄露 |
| `pollingInterval` | 15 分钟 | 匹配塘口实时数据的同步间隔 |
| `batchPullSize` | 500 条/请求 | 平衡接口负载与数据同步效率 |
| `returnFieldWhitelist` | `["养殖品类","塘口ID","单位产量","收购单价","总成本"]` | 仅返回外部系统所需核心字段，减少传输开销 |
| `filterParams` | 按`养殖品类`、`塘口ID`配置默认过滤规则 | 匹配外部系统按维度查询的需求 |
| `responseUnitField` | 开启 | 携带单位说明，避免外部系统解析数值错误 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用接口返回的收益率数据混杂多个塘口的记录，无法按指定塘口ID过滤。原因：未配置`filterParams`参数，未在请求中携带塘口ID作为过滤条件。
- 现象：接口请求返回状态码413，数据同步失败。原因：`batchPullSize`配置值过大，超出接口单次请求的最大数据量限制。
- 现象：外部系统无法正确换算成本与收益数值，返回字段未附带单位说明。原因：未开启`responseUnitField`配置，未在返回结果中携带单位信息。

## 怎么确认配好了
- 调用配置好的HTTP接口，传入指定的塘口ID与养殖品类参数，核对返回结果仅包含对应塘口与品类的数据。
- 查看接口返回的字段，确认每个数值字段都附带了对应的单位说明。
- 模拟每日凌晨的批量拉取请求，核对返回的数据量与配置的`batchPullSize`匹配。
- 配置实时回调地址，发送测试数据，确认外部系统能正常接收回调请求。
