# 水务收益率的HTTP 接口与外部系统

## 这个品类的数据长什么样
水务收益率相关数据主要来自地方住建部门公用事业监测平台、水务运营企业公开运营台账。更新节奏为每个自然日18点前完成前一日数据的汇总发布。单条数据文档包含项目编码、所属行政区、供水/污水处理量、直接运营成本、营收总额字段，单位分别为编码无、平方千米（行政区）、立方米、元、元，无百分比类统计指标。数据结构固定，无动态新增字段，单条数据的字段数量稳定在5个以内。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
水务数据的固定更新时间要求接口需将拉取时机设置在每日18点之后，避免拉取未完成的临时数据。字段结构固定且无动态变化，要求接口请求需使用固定的参数格式，无需动态适配字段。大额数值字段的传输要求接口需支持大整数类型解析，避免数值精度丢失。数据来源为官方或企业公开台账，接口需配置白名单校验，确保调用主体符合合规要求。同时，日更的更新频率意味着无需高频调用接口，可降低外部系统的调用成本与压力。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `request_timeout` | `30 秒` | 水务数据接口返回的数据包大小适中，30秒足够完成数据拉取与解析，避免超时中断 |
| `polling_interval` | `86400 秒` | 水务收益率数据每日更新一次，该间隔可匹配更新节奏，降低接口调用压力 |
| `response_parse_mode` | `json_schema` | 水务数据接口返回的字段结构固定，使用json_schema可精准提取目标字段，减少解析误差 |
| `max_concurrent_requests` | `50–100` | 水务数据源接口的并发承载能力为中等规模，该区间可避免触发限流规则 |
| `field_mapping` | 按实测标定 | 不同水务数据源的字段命名存在差异，需根据实际接口返回调整原始字段与系统内部字段的对应关系 |
| `error_retry_threshold` | `3 次` | 网络波动或接口临时故障较为常见，3次重试可覆盖大部分临时异常，减少人工介入 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：接口返回状态码429，请求被限流。原因：未设置合理的并发请求数，调用频率超出水务数据源接口的承载上限。
- 现象：拉取到的水务数据字段为空。原因：未正确配置`field_mapping`参数，未将接口返回的原始字段与系统内部字段建立对应关系。
- 现象：定时拉取任务在每日17点触发，无法获取最新数据。原因：未根据水务数据的更新时间调整拉取时机，过早触发导致数据未完成更新。

## 怎么确认配好了
- 调用配置好的接口，查看返回的原始数据包，确认所有配置的字段均能正常提取。
- 等待一个完整的更新周期后，检查拉取到的数据是否为前一日的运营数据，确认更新时机符合预期。
- 模拟多次连续调用，观察系统是否触发重试机制，确认异常处理逻辑生效。
- 对比手动导出的水务运营数据与接口拉取的内容，确认字段值匹配无误。
