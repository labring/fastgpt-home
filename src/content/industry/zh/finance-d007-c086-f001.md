# 汽车服务收益率的HTTP 接口与外部系统

## 这个品类的数据长什么样
汽车服务收益率的数据来自线下门店的工单系统、进销存管理系统与客户关系管理系统，更新节奏为每日完成当日核算后，于次日凌晨生成前一日的收益率汇总数据。文档采用结构化批量记录格式，每条记录包含门店标识、服务品类、营收总额、成本总额、核算日期等字段，金额单位为人民币元，核算日期采用标准日期格式，未包含预设的统计数值或百分比标注。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多门店的异构数据源要求接口支持动态配置不同的鉴权方式，适配不同门店系统的接入要求。每日T+1的更新节奏要求定时同步任务的调度周期匹配该节奏，避免无效的重复请求。结构化的多维度字段要求配置字段映射规则，将外部系统的字段转换为FastGPT可识别的标准化格式。数据量随门店数量增长的特点要求接口支持分页拉取，降低单次请求的负载。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `external_data_source_auth_type` | `api_key` | 汽车服务外部门店系统多采用API密钥鉴权，适配通用接入要求 |
| `data_sync_schedule` | `cron表达式为0 0 1 * * ?` | 匹配汽车服务数据T+1的更新节奏，每日凌晨1点完成同步 |
| `api_request_timeout` | `1200 秒` | 处理多门店批量数据时，避免单次请求超时中断同步流程 |
| `field_mapping_rule` | 按门店标识、服务品类、营收总额的顺序映射 | 匹配汽车服务收益率的核心统计维度，便于后续分析 |
| `pagination_enable` | `true` | 适配多门店数据量较大的场景，降低单次接口请求的负载 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 支持上传批量汽车服务数据文件，满足大文件同步需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为HTTP接口调用返回`504 Gateway Timeout`状态码，原因是未配置合理的请求超时时间，单次拉取的多门店数据量超出接口允许的响应时长。
- 现象为工作流API调用文件上传时返回`413 Request Entity Too Large`错误，原因是未调整`UPLOAD_FILE_MAX_SIZE`配置项，上传文件大小超过接口限制。
- 现象为AI回答中未显示语料出处，上下文变量中`source_info`字段为空，原因是未配置字段映射规则，未将外部数据的来源信息同步至FastGPT上下文变量。

## 怎么确认配好了
- 手动触发一次外部数据同步接口，检查返回字段与外部系统字段是否匹配，确认字段映射配置生效。
- 查看定时任务日志，确认每日凌晨的同步任务按时执行，无超时或失败记录。
- 上传测试用汽车服务数据文件，检查工作流是否正常触发并解析文件内容，确认文件上传配置生效。
- 查看工作流上下文变量，确认`source_info`字段已携带外部数据来源信息，可用于后续追溯。
