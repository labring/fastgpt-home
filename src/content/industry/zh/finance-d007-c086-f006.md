# 汽车服务收益率的对话日志与审计

## 这个品类的数据长什么样
该品类的数据主要来自线下门店经营管理系统、第三方支付对接接口。更新节奏为每日凌晨同步前一日全量经营数据，实时完成的服务订单会在15分钟内追加至当日统计文档。文档为结构化JSON或CSV格式，单条数据包含门店唯一标识、统计日期、服务分类代码、营收总额、成本总额、毛利总额、服务订单数量、客单价金额。金额单位为人民币元，订单数量为正整数，统计日期采用YYYY-MM-DD格式。

## 这些特征在「对话日志与审计」这一环带来什么约束
该品类的数据特征对对话日志与审计环节带来多项约束。双数据源的获取逻辑要求日志完整记录门店管理系统、支付接口的调用时间、请求参数与返回结果，确保经营数据可完整溯源。每日全量与实时增量的更新节奏，要求日志区分两类请求的触发条件，避免混淆当日统计的基础数据来源。单条数据包含多个经营字段，审计环节需校验日志提取的播报内容与原始接口返回字段的匹配度，确保未出现字段遗漏或取值偏差。高频的实时订单同步会产生大量短周期日志，需配置合理的日志采样与存储策略，避免资源占用过高。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `log_retention_days` | `90 天` | 匹配汽车服务行业经营数据审计的常规合规留存周期 |
| `sampling_rate` | `0.05–0.2` | 平衡高频实时日志的存储占用与审计溯源的完整度 |
| `multi_source_log_association` | `开启` | 该品类数据来自门店管理系统与支付接口双数据源，需关联两类调用日志完成完整溯源 |
| `field_audit_checklist` | `配置门店标识、统计日期、营收总额、成本总额` | 覆盖该品类核心经营审计字段，确保播报数据的字段完整性 |
| `request_timeout` | `600 秒` | 全量经营数据的接口调用耗时通常较长，避免提前超时导致日志缺失 |
| `daily_full_sync_log_enable` | `开启` | 每日全量数据是收益率日报的核心基础，需单独留存全量同步日志用于审计 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用经营数据接口时报错`401 Unauthorized`，日志中显示请求令牌为固定的`fastgpt`字符串。原因：未正确配置数据源的令牌映射规则，调用时默认使用了内置测试令牌，未使用预设的业务令牌。
- 现象：日志显示在非营业时间有大量高频接口调用请求，导致调用额度超额。原因：未设置调用时段过滤规则，全量数据同步任务默认在任意时段执行，触发了不必要的高频调用。
- 现象：导出对话日志时仅返回部分门店的记录，无法获取全量数据。原因：未正确配置分页查询的参数阈值，接口自动截断了超出默认条数的日志条目。

## 怎么确认配好了
- 查看日志列表，确认双数据源的调用记录均被关联展示，可通过门店标识与统计日期快速定位单条经营数据的完整溯源链路。
- 触发一次全量数据同步任务，检查日志中是否单独留存了该任务的完整调用参数与返回结果，确认配置生效。
- 模拟非营业时间的接口调用请求，检查日志是否被过滤，确认调用时段过滤规则已正确配置。
- 调用对话日志导出接口，确认可获取指定周期内的日志数据，分页参数的阈值可按实际审计需求调整。
