# 汽车服务收益率的模型接入与配置

## 这个品类的数据长什么样
汽车服务领域的收益率与行情数据主要来源于门店财务核算系统、主机厂返利后台、汽车后市场行情接口。数据更新节奏为每日T+1凌晨完成全量同步，单批次数据的完整同步周期不超过2小时。文档结构多为结构化CSV或JSON格式，包含门店唯一标识、车型款型编码、服务品类编码、核算日期、单车收益贡献值、单店月度累计收益、服务人次等字段。字段单位分别为字符串、字符串、字符串、日期格式、元、万元、人次，未采用百分比类标准化单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
每日T+1的更新节奏要求模型任务触发时间需晚于数据同步完成节点，避免调用未完成更新的残缺数据。结构化字段包含多维度编码的特征，要求配置精准的字段映射规则，确保模型能关联门店、车型与收益数据的对应关系。单批次数据的体量范围，要求调整向量入库的批量处理参数，防止单次处理超时。多数据源接入的需求，要求配置兼容不同系统鉴权方式的参数，同时设置数据校验规则，过滤格式异常的字段内容。此外，日报类数据的时间维度强关联属性，要求在召回环节配置按核算日期的过滤参数，确保模型仅调用对应周期的行情数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `scheduleTriggerTime` | `每日03:00` | 汽车服务类数据通常在每日02:00前完成T+1同步，该时间可确保调用最新完整数据 |
| `fieldMappingRule` | `按门店ID+车型款型编码+核算日期关联匹配` | 该品类数据的核心关联维度为门店、车型与核算周期，可避免数据错位 |
| `vectorBatchSize` | `50 条/批次` | 单批次数据体量适配FastGPT的向量入库并发上限，防止处理超时 |
| `dataSourceAuthType` | `按数据源分别配置API密钥` | 多系统接入需独立鉴权，保障数据访问安全 |
| `recallFilterRule` | `仅保留核算日期为对应周期的条目` | 该场景为收益率日报播报，仅需当日最新行情数据 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 单批次数据处理需完整解析多维度字段，预留足够的解析时长 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：模型接入测试返回`404 status code (no body)`报错。原因：未正确配置数据源的API接口路径，或接口访问权限未开放至FastGPT调用节点。
- 现象：上传汽车服务营收数据文件后，部分批次未被大模型自动解析。原因：未配置`PARSE_FILE_EXTENSION_WHITELIST`参数，或文件格式不在允许的白名单范围内，FastGPT 4.8.9简易模式下未触发自动解析逻辑。
- 现象：非工具调用模式下，大模型输出未包含网络搜索获取的汽车行情数据。原因：未开启`enable_web_search`配置项，或系统提示词未明确要求调用外部数据源补充行情信息。

## 怎么确认配好了
- 执行一次手动数据同步任务，检查数据同步日志中是否存在字段格式异常或鉴权失败的提示，确认数据源配置有效。
- 发起一次模型调用测试，查看召回结果中是否仅包含对应核算日期的汽车服务收益数据，确认过滤规则生效。
- 查看向量数据库的入库记录，确认批量处理的条目数符合配置的`vectorBatchSize`参数，无超时或入库失败记录。
- 开启非工具调用模式并触发测试，检查模型输出是否包含预设的行情数据引用，确认网络搜索配置生效。
