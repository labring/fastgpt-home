# 涂料油墨收益率的数据库与运维

## 这个品类的数据长什么样
数据来源包括大宗商品现货交易平台公开报价、行业协会的采样统计数据、生产企业的出厂报价公示。更新节奏为每日固定时点完成当日全品类行情更新，部分高频流通原料数据每小时同步一次。单条数据文档对应单一规格型号的涂料油墨产品或核心原料，包含产品名称、产地标识、规格参数、计价单位、最新成交报价、较上一统计周期的报价差额、统计覆盖范围等字段。

## 这些特征在「数据库与运维」这一环带来什么约束
多源异构的数据来源要求数据库层支持多源数据的格式对齐与冲突校验，需针对计价单位、统计周期等字段配置标准化转换规则。分层更新节奏要求运维层配置差异化的定时调度任务，高频数据采用小时级增量同步，全量日报数据采用每日固定时点批量写入。单一产品多维度字段的组合查询需求，要求数据库建立联合索引覆盖产品名称、产地与规格型号，避免全表扫描。不可篡改的行情历史数据要求写入操作采用追加模式，禁止直接修改已入库记录，需通过新增修正记录的方式处理数据误差。每日汇总播报的业务需求，要求配置定时聚合任务生成标准化的播报数据集，减少实时查询的计算开销。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGODB_CONNECTION_POOL_SIZE` | `100–150` | 适配多源数据同步与每日批量聚合的并发请求，避免连接耗尽 |
| `DATA_SYNC_JOB_CRON` | `0 2 * * * 全量同步, 0 * * * * 增量同步` | 匹配涂料油墨行情的分层更新节奏，平衡数据新鲜度与系统负载 |
| `DB_INDEX_CONFIG` | `["product_name", "origin", "spec"]` | 覆盖核心查询维度，提升组合查询的响应速度 |
| `DATA_VALIDATION_THRESHOLD` | `按实测标定` | 校验报价差额的合理范围，过滤异常数据源的错误数据 |
| `MONGO_REPLICA_SET_ENABLED` | `true` | 保障数据写入的高可用性，避免单节点故障导致行情数据中断 |
| `BACKUP_CRON_EXPRESSION` | `0 3 * * *` | 每日凌晨3点执行全量备份，避开业务高峰时段 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：MongoDB连接报错提示“Connection refused”或“max open connections reached”，界面显示数据同步失败。原因：未配置合理的连接池大小，或未为MongoDB实例挂载持久化存储卷，导致重启后数据丢失无法建立连接。
- 现象：查询行情数据时返回空结果或字段缺失。原因：未配置正确的联合索引，或未对多源数据的计价单位进行标准化转换，导致数据无法匹配查询条件。
- 现象：工作流调用行情数据时TPS未达标。原因：未配置数据库读取偏好为`secondaryPreferred`，所有请求均命中主库，导致主节点负载过高，响应延迟。

## 怎么确认配好了
- 执行数据库连接测试脚本，验证连接池配置的并发请求可以正常处理，无连接耗尽报错。
- 触发全量同步任务，检查同步后的数据库中是否包含所有配置的产品品类的完整字段，无单位不统一的异常数据。
- 查看定时任务日志，确认分层同步任务与备份任务均按预设时间正常执行，无失败记录。
- 发起组合查询请求，验证返回结果的响应时间符合业务需求，无全表扫描的日志记录。
