# 消费建材收益率的工具调用与插件

## 这个品类的数据长什么样
消费建材收益率相关数据的来源为国内区域建材现货流通平台、建材流通行业协会的公开监测数据接口。数据更新节奏分为两类：区域终端报价每12小时同步一次，行业整体收益率统计数据每自然日更新。数据文档为标准JSON结构，包含四个核心字段：`region`（字符串，标注省份与地级城市）、`base_price`（浮点数，单位元/平方米）、`change_value`（浮点数，单位元/平方米）、`stat_date`（ISO 8601格式日期字符串）。数据不包含跨品类汇总统计，单条数据仅对应单一建材细分品类在指定区域的单周期收益变动情况。

## 这些特征在「工具调用与插件」这一环带来什么约束
该品类的数据特征对工具调用与插件配置带来三项核心约束。第一，数据更新节奏分为两类周期，工具调用的定时触发需设置为每12小时与每日各执行一次，避免高频调用触发接口限流。第二，字段单位为元/平方米，插件的结果格式化模块需自动绑定单位至对应字段，避免数值与单位不匹配的展示错误。第三，单条数据仅对应单一区域单一品类，工具调用时需强制传入`region`与品类名称参数，否则将返回空结果集。此外，数据无跨品类汇总字段，插件需支持用户自定义筛选条件，仅返回指定品类与区域的结果。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `trigger_cron` | `0 */12 * * *` 与 `0 0 * * *` | 匹配数据每12小时、每日的更新节奏，避免无效调用 |
| `param_schema` | 包含`region`（string，示例值`浙江省杭州市`）、`product_category`（string，示例值`陶瓷地砖`） | 匹配数据字段要求，确保传入参数能命中目标数据集 |
| `response_parser` | `jsonpath`语法，提取`$.[*].region, $.[*].base_price, $.[*].change_value, $.[*].stat_date` | 精准匹配数据文档结构，避免解析错误 |
| `request_timeout` | `600 秒` | 覆盖接口响应的最大耗时，防止中途中断 |
| `enable_cache` | `true`，缓存时长`43200 秒` | 匹配12小时的更新周期，减少重复调用次数 |
| `connection_mode` | `sse` 或 `npx`（根据部署方式） | 适配不同的MCP服务部署形式，确保通信正常 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用工具时返回`400 Bad Request`，提示缺少必填参数。原因：未在`param_schema`中配置`region`与`product_category`参数，导致工具无法接收筛选条件。
- 现象：工具返回的结果仅展示纯数字数值，未附带单位。原因：未配置结果格式化模板，未将`元/平方米`与对应数值绑定。
- 现象：使用npx部署的MCP服务无法被添加到工具集，提示连接异常。原因：未将`connection_mode`设置为`npx`，默认使用`sse`连接方式，未适配服务部署形式。

## 怎么确认配好了
- 进入工具配置管理页面，核对`param_schema`的配置项，确认包含`region`与`product_category`参数，参数类型与数据字段要求对齐。
- 发起单次工具调用，传入已验证的区域与品类参数，检查返回结果的字段名称与格式是否与数据文档匹配。
- 查看工具调用日志，确认触发间隔与设置的`trigger_cron`表达式一致，无高频触发记录。
- 检查缓存配置项，确认缓存时长与数据更新周期匹配，避免使用过期数据。
