# 消费建材收益率的模型接入与配置

## 这个品类的数据长什么样
消费建材的行情数据主要来自国内大宗商品建材交易平台公开报价、区域建材经销商上报数据、行业协会每日汇总数据。数据更新节奏为每日更新，当日的全品类行情数据于次日凌晨完成汇总发布。单份日报文档的结构包含品类名称、规格型号、产地、区域、当日挂牌价、前一日基准价、统计时段等字段。计价单位根据品类不同存在差异，瓷砖、涂料等品类以元/平方米为单位，管材、防水材料等品类以元/吨为单位，小型辅料以元/件为单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
消费建材的多源数据格式差异较大，部分数据源包含冗余字段，因此模型接入时需要配置精准的字段过滤与映射规则，确保输入模型的字段符合任务要求。每日更新的发布节奏要求配置固定的定时拉取周期，避免数据滞后或重复拉取。不同品类的计价单位存在差异，需要配置单位标准化的转换参数，统一数据口径。日报文档的统计时段固定为自然日，因此需要配置数据时间戳的校验规则，确保仅纳入对应周期的有效数据。此外，单份日报包含的细分品类较多，需要配置合理的召回条数限制，避免无关数据干扰模型的日报生成逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `scheduleCron` | `0 0 6 * * *` | 消费建材日报通常在每日凌晨5点前完成汇总，提前1小时拉取可获取最新完整数据 |
| `fieldMapping` | `{"品类名称":"category","规格型号":"spec","当日挂牌价":"current_price","前一日基准价":"base_price"}` | 统一模型输入的字段命名规则，适配后续的价格对比与日报生成逻辑 |
| `unitConvertRule` | `{"元/平方米":1,"元/吨":0.001,"元/件":1}` | 将不同品类的计价单位转换为统一基数，消除单位差异对模型分析的干扰 |
| `maxRecallCount` | `前20条` | 单份消费建材日报的有效数据条目通常在15-25条之间，召回20条可覆盖主要细分品类 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 单份消费建材日报的解析开销较低，300秒的超时时间可覆盖批量拉取与解析的延迟 |
| `similarityThreshold` | `0.75` | 过滤与行情日报任务关联度较低的冗余数据，保留核心的价格与品类信息 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
-  接入模型测试时返回`404 status code (no body)`。未正确配置模型的API地址或密钥权限，导致请求无法到达目标模型服务。
-  简易模式下上传消费建材日报文件，部分文件未被模型自动解析。未开启自动解析开关或配置的`UPLOAD_FILE_MAX_SIZE`参数值小于上传文件的实际大小。
-  非工具调用模式下生成行情日报，大模型未引用实时网络搜索的消费建材数据。未开启`enable_web_search`参数，或未在系统提示词中明确要求模型调用搜索工具获取最新行情信息。

## 怎么确认配好了
-  执行模型接入测试请求，检查返回的响应状态码是否符合预期，确认API配置正确。
-  上传一份标准格式的消费建材日报测试文件，查看系统解析后的字段是否与配置的`fieldMapping`规则一致。
-  手动触发一次定时拉取任务，检查拉取到的数据是否包含当日的有效价格信息，且单位已完成标准化转换。
-  开启测试模式生成单份日报，核对生成内容是否覆盖了配置的`maxRecallCount`参数指定的条目范围。
