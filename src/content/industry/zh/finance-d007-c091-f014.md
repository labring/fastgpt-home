# 消费建材收益率的表单与交互

## 这个品类的数据长什么样
消费建材的收益率相关数据主要来源于国内建材流通协会的公开监测台账、头部厂商的出货结算记录、线下零售终端的扫码上报数据。数据更新节奏分为三类：出厂结算价每7天更新一次，终端零售价每日更新，月度汇总数据每次月5日前发布。数据以结构化CSV格式存储，包含固定字段：品类编码、规格型号、出厂结算价、终端零售价、统计周期、数据来源标识，其中价格类字段的单位为元/平方米或元/吨。

## 这些特征在「表单与交互」这一环带来什么约束
消费建材的多SKU属性与分周期更新特征，对收益率与行情日报播报的表单与交互环节带来多重约束。需支持按品类编码、规格型号双维度检索，避免单靠名称混淆大量相似SKU。需区分出厂价、零售价两类数据的查询入口，匹配二者不同的更新周期，防止用户获取跨周期的非目标数据用于收益率计算。需在交互界面展示当前数据的统计周期，明确告知用户数据的覆盖时段，确保日报播报的时效性准确。需支持批量导入多品类查询条件，适配用户单次查询多个SKU的高频场景。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `fieldMapping` | `{"sku_code":"品类编码","spec":"规格型号","factory_price":"出厂结算价","retail_price":"终端零售价","stat_date":"统计周期"}` | 匹配消费建材数据的标准字段格式，避免知识库解析时出现字段错位 |
| `batchQueryMaxSize` | `20 条/次` | 消费建材SKU数量较多，单次批量查询20条可平衡接口响应速度与查询效率 |
| `apiTimeout` | `30 秒` | 对接第三方建材数据平台时，30秒可覆盖多数接口的正常响应时长 |
| `systemPrompt` | `需基于消费建材的出厂结算价与终端零售价，计算单品类的价差相关数据，仅使用用户提供的结构化字段内容作答，不添加额外信息` | 限定回答范围，匹配场景需求，避免生成无关内容 |
| `recallTopK` | `前 8 条` | 消费建材SKU相似度较高，召回前8条可覆盖核心相关数据，避免冗余结果 |
| `iframeAllowOrigins` | `["https://your-domain.com"]` | 配置前端嵌入的合法域名，确保iframe交互的安全跨域访问 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：前端iframe能正常展示回答，但后端接口无法获取返回内容。原因：未配置`iframeAllowOrigins`或配置的域名与前端实际域名不一致，导致跨域请求被拦截。
- 现象：AI识别采购信息时，误将建材的包装规格判定为额外产品信息。原因：系统提示词未明确限定仅识别指定字段内容，或字段映射配置与实际数据格式不匹配。
- 现象：问题分类模块无法准确识别建材品类的查询请求。原因：未使用消费建材的专属术语构建分类规则，分类知识库未覆盖该品类的专属字段与场景。

## 怎么确认配好了
- 提交单条SKU的查询请求，检查返回结果是否仅使用配置的字段内容作答，无额外无关信息。
- 嵌入iframe到前端测试页面，通过浏览器开发者工具查看跨域请求的响应状态码，确认无403或跨域相关错误。
- 导入批量SKU的查询条件，检查接口返回的结果条数与配置的`batchQueryMaxSize`是否匹配。
- 模拟不同场景的查询请求，检查问题分类模块是否能准确将请求归类到消费建材收益率相关场景。
