# 消费建材收益率的部署与升级

## 这个品类的数据长什么样
消费建材收益率相关数据主要来自全国建筑材料流通协会的每日监测数据、区域线下建材市场的实时交易接口，以及头部品牌厂商的出货报价数据库。数据更新节奏为每日凌晨同步前一日的全量统计结果。单份日报文档为结构化格式，包含6个核心字段：`product_code`（6位字符串产品编码）、`product_name`（产品全称，如“通体大理石地砖”）、`base_price`（单位：元/平方米）、`daily_change`（单位：元/平方米）、`region`（区域标识，如“华东区域”）、`stat_date`（YYYY-MM-DD格式统计日期）。单份文档体积通常在10至50MB之间，无复杂嵌套结构。

## 这些特征在「部署与升级」这一环带来什么约束
消费建材的多源数据来源、固定字段结构与每日全量更新的特征，对部署与升级环节带来三项具体约束。其一，多源数据拉取需配置差异化超时阈值，因行业协会接口与区域零售接口的响应时长存在明显差异，单一超时参数易导致部分数据源拉取失败。其二，每日凌晨的全量数据更新需匹配调度规则，升级过程中需临时关闭非必要的定时任务，避免数据写入冲突导致的数据库锁表。其三，固定字段的校验规则需随部署配置固化，升级后的数据解析模块需自动映射核心字段，避免因字段不匹配导致的解析失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 消费建材单日报表文件通常小于50MB，300秒可覆盖全量解析流程，避免小文件超时 |
| `UPLOAD_FILE_MAX_SIZE` | `50 MB` | 匹配消费建材日报的常规文件体积，避免无效大文件占用存储与带宽 |
| `API_KEY_EXPIRE_DAYS` | `1` | 消费建材收益率播报仅需每日调用，设置1天有效期可降低密钥泄露风险 |
| `API_KEY_MAX_CALLS` | `10 次/天` | 每日仅需1次数据拉取与播报，限制调用次数可防止非预期滥用 |
| `CRON_SCHEDULE` | `0 2 * * *` | 每日凌晨2点触发数据更新，避开业务高峰，确保前一日数据的及时同步 |
| `DATA_VALIDATION_RULES` | `必填字段: product_code, base_price; 数值校验: base_price > 0` | 过滤缺失核心标识或无效价格的消费建材数据，保障播报内容的准确性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：部署社区版时数据拉取任务无响应，界面显示超时错误。原因：未针对消费建材的多源数据源调整`PARSE_FILE_TIMEOUT_SECONDS`参数，使用默认的120秒超时，导致部分区域数据源拉取耗时超出阈值。
- 现象：API密钥无法设置使用时长与调用次数，保存后配置失效。原因：未开启`ENABLE_API_KEY_LIMIT`配置项，默认状态下该功能未启用，导致无法配置密钥的时长与次数限制。
- 现象：私有化部署升级版本后，点击知识库的文件详情显示`Invalid dataset file key`报错。原因：升级过程中未同步更新消费建材数据的文件密钥映射规则，旧版本的密钥格式与新版本不兼容，导致文件校验失败。

## 怎么确认配好了
- 手动触发一次数据拉取任务，查看任务日志中是否包含消费建材的核心字段记录，无缺失或异常数值。
- 生成测试用API密钥，配置时长与调用次数，验证密钥在有效期与调用次数内可正常调用数据接口，超出限制后返回权限错误。
- 检查定时任务的调度日志，确认每日凌晨2点自动触发数据更新，无延迟或失败记录。
- 上传测试用的消费建材日报文件，验证数据校验规则可过滤掉缺失核心字段或无效价格的记录。
