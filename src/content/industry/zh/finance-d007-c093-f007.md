# 游戏收益率的工作流编排

## 这个品类的数据长什么样
游戏收益率相关数据主要来源于自研游戏运营后台、第三方游戏数据服务商接口两类。数据更新节奏分为两类：全量日报数据每日凌晨生成前一日的统计结果，实时子数据如单服即时营收每小时刷新一次。数据文档多为结构化JSON或CSV格式，单条数据包含游戏唯一标识、统计日期、服务器分组、核心付费道具营收、运营成本、投入产出比等字段。其中投入产出比字段的单位为无量纲数值，无百分比类表述，数据维度覆盖单服、全服、单道具等多个层级。

## 这些特征在「工作流编排」这一环带来什么约束
游戏收益率数据的多来源属性要求工作流支持混合数据源适配，需同时配置REST API接口调用与批量文件解析的适配规则。更新节奏的差异要求工作流支持两种触发模式，定时触发用于每日全量日报，事件触发用于实时子数据的同步处理。多维度的数据字段要求工作流支持变量的多映射规则，需将不同维度的字段分别绑定到对应工作流变量。异常数据的存在要求工作流内置字段校验环节，需过滤营收为0、投入产出比异常等无效数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `TRIGGER_CRON_EXP` | `0 0 2 * * *` | 匹配游戏日报数据的每日凌晨生成时间 |
| `DATA_SOURCE_ADAPTER` | `REST API + FTP 混合` | 适配自研后台的实时接口与第三方服务商的批量CSV文件 |
| `PARSE_FILE_TIMEOUT` | `300 秒` | 满足批量全量数据的解析耗时需求 |
| `VALIDATION_ENABLE` | 开启 | 过滤营收为0、投入产出比异常的无效数据 |
| `GLOBAL_VAR_BIND` | 绑定游戏ID与服务器ID | 实现多维度数据的变量映射与统一调用 |
| `MULTI_VAR_MERGE_STRATEGY` | 按统计日期聚合 | 匹配日报数据的时间维度整合需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用文件上传工具时，传入自定义变量后工具返回参数校验失败，无法正常加载数据。原因：该工具仅支持传入公开可访问的文件链接，不支持引用本地变量作为文件路径。
- 现象：多个变量更新节点执行完成后，AI回复仅展示最后一个节点的变量内容，其余节点的产出数据未被整合。原因：未配置多变量聚合的合并规则，工作流默认仅保留最新更新的单变量数据。
- 现象：拉取游戏数据时，请求未携带全局配置的游戏标识参数，导致返回空数据或权限错误。原因：未在工作流入口绑定全局变量，请求参数未自动注入全局配置项。

## 怎么确认配好了
- 触发工作流一次，查看数据源返回的原始数据，核对字段名称与配置的变量映射规则是否一致。
- 检查定时任务的触发日志，确认工作流在指定时间自动启动，无超时或执行失败的记录。
- 触发多变量更新节点，查看AI回复是否整合了所有节点的变量数据，无遗漏或覆盖的情况。
- 调用工作流的测试接口，确认请求参数中自动注入了配置的全局游戏标识参数。
