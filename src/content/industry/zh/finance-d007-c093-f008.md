# 游戏收益率的工具调用与插件

## 这个品类的数据长什么样
游戏收益率相关数据主要来源于游戏官方运营后台的付费流水接口、第三方游戏数据聚合平台的公开API。更新节奏分为两类：日报类数据为统计周期结束后T+1更新，实时交易类收益率数据每5分钟刷新一次，活动专属收益率随活动周期每日更新。数据文档多为结构化JSON格式，包含`game_id`、`server_zone`、`stat_date`、`total_revenue`、`total_cost`、`profit_rate`、`update_timestamp`等字段，其中`total_revenue`与`total_cost`单位为人民币元，`profit_rate`为无量纲比例值，`stat_date`采用ISO标准时间字符串格式。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源多为第三方接口，需配置签名验证逻辑，避免接口调用被拦截。更新节奏存在差异，需根据数据类型设置不同的触发频率，避免过度调用或更新不及时。数据按服务器分区存储，工具调用时需传入分区参数过滤目标数据，否则返回结果冗余。不同游戏厂商的返回字段名存在差异，需配置字段映射规则，确保数据解析的准确性。游戏数据时效性强，接口调用超时时间需控制在合理范围内，保障播报及时性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `request_timeout` | `15-30 秒` | 游戏数据接口响应普遍较快，超时过长会影响播报时效性 |
| `signature_method` | `HMAC-SHA256` | 游戏官方接口普遍使用该签名方式保障接口调用安全 |
| `polling_interval` | `300 秒`（实时行情）或`86400 秒`（日报） | 匹配对应数据类型的更新节奏，避免超出接口调用频率限制 |
| `filter_params` | `["game_id", "server_zone"]` | 游戏数据按服务器分区存储，需指定参数过滤目标业务数据 |
| `field_mapping` | 按实测标定 | 不同游戏厂商的接口返回字段名存在差异，需匹配自身业务的字段定义 |
| `response_parse_mode` | `JSON_PATH` | 游戏数据接口返回结构化JSON格式，该模式可精准提取目标字段 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：自定义插件调用游戏数据接口后，提取的`profit_rate`字段为空。原因：未配置正确的字段映射规则，未将接口返回的目标字段与工具变量做绑定。
- 现象：插件配置界面无法找到`函数调用`模块入口。原因：未在系统设置中开启「自定义插件高级功能」开关，该模块默认隐藏。
- 现象：调用接口返回`429 Too Many Requests`报错。原因：轮询间隔设置过短，超出游戏数据接口的调用频率限制。

## 怎么确认配好了
- 手动触发插件调用，查看返回的原始响应内容，确认接口可以正常获取游戏数据。
- 检查工具变量的绑定关系，确认提取的字段与业务需求的字段名称一致。
- 查看定时任务的运行日志，确认触发频率与数据更新节奏匹配。
- 验证字段解析结果，确认提取的数值符合业务场景的合理范围。
