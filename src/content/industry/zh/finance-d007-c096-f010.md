# 焦炭收益率的数据库与运维

## 这个品类的数据长什么样
焦炭的行情与收益率数据主要来自大连商品交易所公开行情接口、国内焦炭主产区现货报价平台。实时行情每5秒推送一次，日收益率相关数据于每个交易日17:00后完成更新。文档为结构化时序数据，包含品种代码、交易日期、结算价、持仓量、现货基准价等字段。价格类字段单位为元/吨，成交量与持仓量单位为手。

## 这些特征在「数据库与运维」这一环带来什么约束
实时行情的高频更新要求数据库链路具备低延迟写入能力，避免数据堆积导致的播报延迟。日批量数据更新需要配置专属的调度窗口，避开交易高峰时段防止资源冲突。多维度的时序字段需要建立联合索引，提升按交易日期、品种代码的查询效率。多数据源接入需要配置数据校验规则，过滤异常值保证收益率计算的准确性。长期行情数据的留存需要配置冷热存储策略，降低运维成本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `MONGO_CONNECTION_POOL_SIZE` | 10–20 | 适配焦炭实时行情每5秒的写入频率，避免连接耗尽导致的写入失败 |
| `DATA_SYNC_INTERVAL` | 5 秒 | 匹配大连商品交易所实时行情的推送间隔，保证数据时效性 |
| `BATCH_INSERT_SIZE` | 50–100 | 平衡写入性能与内存占用，适配单批次的实时行情数据量 |
| `INDEX_EXPIRE_AFTER_SECONDS` | 86400 秒 | 对实时行情临时数据设置自动过期，减少无效存储占用 |
| `DAILY_DATA_UPDATE_TIME` | 17:30 | 匹配焦炭交易日收盘后的数据更新窗口，避免与实时行情推送冲突 |
| `DATA_VALIDATION_LEVEL` | strict | 校验所有接入的焦炭行情字段，过滤异常值保证数据准确性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：MongoDB连接报错`Connection refused`，系统界面显示数据库连接失败。原因：未正确配置`MONGODB_URI`参数，本地Windows环境下未开放MongoDB的默认端口27017，或防火墙拦截了外部连接请求。
- 现象：收益率播报工作流的运行TPS偏低，日志显示数据写入队列堆积时长超出预期。原因：未根据焦炭实时行情的更新频率调整`BATCH_INSERT_SIZE`和`MONGO_CONNECTION_POOL_SIZE`参数，导致写入吞吐量无法匹配数据更新节奏。
- 现象：调用数据库查询接口后返回的字段不完整，无法生成完整的焦炭收益率播报内容。原因：未在数据库中建立覆盖交易日期、品种代码的联合索引，或配置的`DATA_VALIDATION_RULES`错误过滤了核心业务字段。

## 怎么确认配好了
- 执行数据库连接测试命令，验证`MONGODB_URI`配置的连接地址是否可正常访问。
- 提交模拟的焦炭实时行情数据，查看写入日志，确认数据写入延迟符合业务要求。
- 调用数据库查询接口，查询指定交易日的焦炭数据，确认返回的字段覆盖业务所需的全部内容。
- 查看数据库元数据管理页面，确认可以查看焦炭行情数据表的完整字段定义与索引配置。
