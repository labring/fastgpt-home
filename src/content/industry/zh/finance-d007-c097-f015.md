# 焦煤收益率的部署与升级

## 这个品类的数据长什么样
焦煤行情与收益率数据来源于国内大宗商品期货交易所公开行情接口，更新节奏为每个交易日15:00收盘后约2小时完成当日全量数据更新。文档采用结构化JSON或CSV格式，包含合约代码、交割月份、基准结算价、当日成交均价、当日价格变动额、持仓总量等字段，单位分别为字符串、年月格式、元/吨、元/吨、元/吨、手。数据仅覆盖大连商品交易所上市流通的焦煤期货合约，无额外衍生统计字段。

## 这些特征在「部署与升级」这一环带来什么约束
这些数据特征会对部署与升级环节带来三点核心约束。第一，数据源为专用期货行情接口，需配置专属鉴权参数，且调用频次需匹配交易所限流规则，部署时需额外配置请求限流中间件，避免触发接口封禁。第二，数据每日固定时间更新，部署时需配置定时拉取任务的触发时间，需与交易所数据发布时间对齐，避免拉取未完成更新的空数据。第三，字段包含合约代码、交割月份等结构化标识，部署时需配置数据校验规则过滤无效数据，升级时需同步更新最新的焦煤期货合约列表，确保覆盖所有上市合约。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `CRON_EXPRESSION` | `0 18 * * *` | 焦煤期货交易日15:00收盘后约2小时完成数据发布，该定时表达式可确保每日18点拉取完整当日数据 |
| `EXTERNAL_DATA_SOURCE_API_KEY` | 交易所申请的专属鉴权密钥 | 专用行情接口需鉴权访问，有效密钥可确保数据拉取权限 |
| `PARSE_DATA_VALIDATION_RULES` | `["contract_code", "settlement_price", "daily_change"]` | 确保核心数据字段完整，过滤缺失关键信息的无效数据 |
| `MONGODB_MAX_POOL_SIZE` | `20` | 焦煤行情数据量适中，20连接池可满足并发拉取与存储需求 |
| `RATE_LIMIT_REQUESTS_PER_MINUTE` | `30` | 匹配国内大宗商品交易所行情接口的限流阈值，避免触发封禁 |
| `UPDATED_DATA_SYNC_INTERVAL` | `86400 秒` | 焦煤行情每日仅需更新一次，该间隔可避免重复拉取冗余数据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为Docker Compose部署后执行`pnpm dev`显示MongoDB连接超时，原因是未在`.env`文件中配置正确的`MONGODB_URI`参数，或本地MongoDB服务未启动且未启用容器内MongoDB镜像。
- 现象为定时拉取的焦煤行情数据字段为空，原因是配置的`CRON_EXPRESSION`早于交易所数据发布时间，导致拉取到未更新的空数据。
- 现象为部署后调用行情接口返回403 Forbidden错误，原因是未配置`EXTERNAL_DATA_SOURCE_API_KEY`参数，或使用了无效的鉴权密钥。

## 怎么确认配好了
- 执行`docker compose up -d`后查看容器日志，确认MongoDB连接日志无超时报错。
- 手动触发一次定时拉取任务，查看解析后的焦煤行情数据是否包含必填字段。
- 调用行情接口测试，确认返回的状态码为200且数据字段完整。
- 检查定时任务的触发日志，确认每日18点左右有数据拉取记录。
