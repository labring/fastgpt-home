# 燃气收益率的数据库与运维

## 这个品类的数据长什么样
燃气收益率相关数据主要来自国内能源交易中心的燃气挂牌报价、各地市政公用事业的运营调度报表，以及区域燃气用户的用气统计数据。数据更新节奏为每日T+1更新，用于生成当日收益率日报。单条数据对应单个行政区域单日的收益率指标，文档结构包含`stat_date`、`region_code`、`region_name`、`factory_purchase_price`、`terminal_sale_price`、`transmission_cost`、`gross_profit_per_cbm`等字段，其中价格类字段单位为元/立方米，区域编码为6位行政区划代码，日期格式为YYYY-MM-DD。

## 这些特征在「数据库与运维」这一环带来什么约束
多源数据接入的需求要求数据库支持跨源连接与数据整合，对连接池的并发配置提出更高要求。固定T+1的批量更新节奏，需要控制单批次写入的数据量，避免频繁触发数据库锁表或IO峰值。按区域和日期的高频查询场景，需要为`region_code`与`stat_date`字段建立联合索引，同时需按日期分区存储历史数据，以降低查询时的扫描范围。字段的标准化要求需严格控制返回字段的范围，避免冗余数据增加上下文处理负担。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `mongodb_connection_timeoutMS` | `30000 毫秒` | 燃气数据的批量写入存在一定网络延迟，该取值可避免正常连接被误判为超时 |
| `mysql_batch_insert_size` | `200-500 条/次` | 单批次数据量适中，可平衡数据库写入性能与锁表风险 |
| `db_index_expire_days` | `180 天` | 日报数据的查询热点集中在近90天，过期索引可释放存储资源并优化查询速度 |
| `multi_source_db_enable` | `开启` | 燃气收益率数据需同时对接能源交易平台与本地运营报表数据源，多源配置可实现数据整合 |
| `db_partition_strategy` | `按stat_date按日分区` | 数据按日期批量更新，分区存储可大幅提升按日期范围查询的效率 |
| `connection_pool_max_size` | `20-30` | 适配多源连接的并发需求，避免连接耗尽导致的服务中断 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用MySQL工具时返回400状态码且无响应体，原因是未正确配置`mysql_connection_string`的权限参数，导致数据库连接校验失败，请求被拦截。
- 本地开发环境执行`pnpm dev`时显示MongoDB连接超时，原因是`mongodb_connection_timeoutMS`配置值设置过小，且本地开发环境的网络延迟高于默认值，导致连接建立失败。
- 数据库查询返回冗余字段，导致关联的模型调用token消耗与实际API不符，原因是未配置`db_query_field_whitelist`，返回了未使用的业务外字段，增加了上下文处理长度。

## 怎么确认配好了
- 运行内置的数据库连通性测试工具，验证所有配置的数据源均可正常建立连接，无超时或权限报错。
- 提交一批模拟的燃气日报数据，观察数据库的写入性能，确认未出现锁表或超时情况。
- 检查数据库的分区配置，确认数据按`stat_date`进行了分区存储。
- 配置字段过滤规则，验证查询返回的字段仅包含预设的业务指标，无冗余数据。
