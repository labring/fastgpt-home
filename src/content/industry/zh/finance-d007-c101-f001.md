# 物流收益率的HTTP 接口与外部系统

## 这个品类的数据长什么样
物流品类的收益率数据主要来自物流企业的运输管理系统、第三方运价公示平台及结算对账系统。数据更新节奏分为两类：干线运输收益率按自然日更新，同城配送的实时单收益率按小时更新。单条数据文档包含运单唯一标识、起运地、目的地、运输车型、单位运输成本、营收总额、核算周期、运输收益率等字段，其中单位运输成本单位为元/吨公里，营收总额单位为元，核算周期以自然日或自然周为基准。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多来源的数据需要配置多接口并行拉取，对应接口超时时间需适配不同来源的响应延迟，避免因超时中断数据拉取。按小时更新的实时数据要求接口轮询间隔不超过30分钟，避免数据滞后影响播报准确性。运单唯一标识作为数据定位的核心字段，需在接口请求参数中作为必传项，否则无法返回单条有效数据。不同运输场景存在字段差异，干线运输需额外传递载重参数，同城配送需传递配送半径，要求接口请求体支持动态字段适配。结算周期的不同会导致返回数据的聚合维度差异，需在接口请求中指定聚合参数以匹配业务需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `HTTP_REQUEST_TIMEOUT` | 60-120 秒 | 适配第三方运价平台及企业内部系统的响应延迟，避免因超时中断数据拉取 |
| `RETRY_TIMES` | 2-3 次 | 应对网络波动或临时接口限流，减少单次请求失败率 |
| `REQUEST_INTERVAL` | 30-60 分钟 | 匹配同城配送实时收益率的更新频率，避免过度调用接口触发限流 |
| `REQUIRED_REQUEST_PARAMS` | `["waybill_id", "transport_type"]` | 运单ID与运输类型为定位单条收益率数据的必传参数，缺失将无法返回有效结果 |
| `RESPONSE_PARSE_RULE` | 按`transport_yield`字段提取 | 物流收益率数据统一以该字段命名，需指定解析规则提取目标值 |
| `DYNAMIC_FIELD_SUPPORT` | 开启 | 适配干线与同城配送的不同字段需求，避免因字段缺失导致请求失败 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用HTTP接口时返回`400 Bad Request`，日志显示参数解析正常但接口未执行。原因：未配置`REQUIRED_REQUEST_PARAMS`中的必传字段，导致接口校验失败。
- 现象：定时拉取数据时频繁触发`503 Service Unavailable`报错。原因：`REQUEST_INTERVAL`设置过短，超过接口限流阈值，触发平台拦截。
- 现象：拉取的收益率数据为空，或字段与预期不符。原因：未开启`DYNAMIC_FIELD_SUPPORT`，无法适配不同运输场景的字段差异。

## 怎么确认配好了
- 手动触发一次HTTP请求，检查返回结果中是否包含预期的`transport_yield`字段及对应数值。
- 查看接口调用日志，确认请求参数与配置的`REQUIRED_REQUEST_PARAMS`完全匹配。
- 对比连续两次拉取的时间间隔与`REQUEST_INTERVAL`的设置，确认轮询节奏符合数据更新频率。
- 模拟限流场景，验证`RETRY_TIMES`的重试机制是否正常触发并恢复请求。
