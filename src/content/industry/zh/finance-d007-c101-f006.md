# 物流收益率的对话日志与审计

## 这个品类的数据长什么样
物流收益率相关数据主要来源于企业内部运输结算系统、第三方物流行情接口。数据更新节奏为每日凌晨批量同步前一日全量运营数据，部分热门干线线路的实时行情每小时更新。单条数据包含线路起止点、承运主体标识、当日营收、当日运营成本、利润额、同线路基准价格等字段，营收与成本单位为元，利润额单位为元，基准价格单位为元/公里。数据文档通常以结构化表格形式存储，按线路与时间维度分类归档。

## 这些特征在「对话日志与审计」这一环带来什么约束
物流收益率相关数据的多来源、分频次更新与结构化特征，对对话日志与审计环节带来多项约束。多来源数据需要在日志中区分内部运营数据与第三方行情数据的调用链路，便于回溯数据真实性。分频次更新要求日志携带数据的更新时间戳，避免审计时混淆新旧数据。结构化的多字段数据需要在日志中记录完整的查询维度，便于定位异常调用的范围。同时，单日数据量较大的特性要求日志系统支持按时间与维度的快速过滤，避免审计时出现查询延迟。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `LOG_RETENTION_DAYS` | `90 天` | 符合物流行业合规审计的常规留存周期 |
| `AUDIT_DATA_WHITELIST` | `["carrier_id", "line_start", "line_end", "daily_profit"]` | 仅允许审计与物流收益率核心计算相关的字段，规避敏感运营数据泄露 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 适配物流行情报表的常规单文件体积上限 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 满足大体积物流数据解析的耗时需求 |
| `MAX_CONTEXT_TOKENS` | `8000–12000` | 支持关联多日多线路的物流行情数据对话 |
| `LOG_ACCESS_PERMISSION` | 按部门角色划分 | 匹配物流企业不同岗位的审计权限范围 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 上传物流行情报表时界面提示`503 Service Unavailable`，但后台日志显示文件上传成功。原因是`PARSE_FILE_TIMEOUT_SECONDS`配置值小于实际解析耗时，后台完成解析但前端请求超时未收到响应。
- 尝试通过变量更新统计某线路的收益率查询次数时，变量值未按预期累加。原因是未开启对话上下文的变量持久化配置，导致每次会话的变量状态被重置。
- 普通运营人员尝试查看跨部门的物流对话日志时，提示`没有权限操作此对话记录`。原因是`LOG_ACCESS_PERMISSION`配置仅开放了本部门的日志访问权限，未配置跨部门审计的角色规则。

## 怎么确认配好了
- 上传一份符合物流行情报表格式的测试文件，核对后台日志是否记录了文件上传、解析的完整时间戳与状态码。
- 发起一次包含多线路收益率查询的对话，核对日志中是否记录了完整的查询参数与返回内容范围。
- 使用非管理员角色登录系统，尝试访问对应权限范围内的对话日志，验证权限拦截是否生效。
- 配置变量更新规则后，重复发起相同查询，核对变量值是否按预期累加。
