# 玻璃收益率的部署与升级

## 这个品类的数据长什么样
玻璃收益率相关行情数据来源于国内建材流通协会的每日市场监测，更新节奏为每日凌晨同步前一交易日的全量数据。数据以结构化JSON格式存储，单条记录包含报告日期、玻璃品类、基准报价、区域划分、库存周转天数、市场供需指数等字段。基准报价单位为元/重量箱，库存周转天数单位为自然日，所有字段均对应单一品类的单区域市场表现，未包含百分比类统计指标。

## 这些特征在「部署与升级」这一环带来什么约束
玻璃行情数据的第三方接口权限需单独申请，部署时需配置专属API密钥与接口白名单，否则无法拉取有效数据。每日凌晨的定时更新任务需匹配数据更新节奏，任务间隔需设为24小时，避免频繁调用触发接口限流。由于数据包含多区域、多品类字段，部署时需配置维度筛选规则，确保仅加载目标区域与品类的行情数据。不同品类玻璃的报价单位统一为元/重量箱，升级时需校验数据解析逻辑，避免与其他建材品类的单位转换规则冲突。同时，历史日报数据的格式需保持兼容，升级过程中不能破坏已有数据的读取路径。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `DATA_SYNC_CRON` | `0 2 * * *` | 匹配玻璃日报每日凌晨更新的节奏，避开业务高峰调用第三方接口 |
| `API_KEY_WHITELIST` | `["建材监测平台专属域名"]` | 限制仅允许授权的第三方数据接口拉取数据，防止未授权调用 |
| `PARSE_FIELD_MAPPING` | `{"基准报价":"price", "区域":"area", "品类":"category"}` | 将第三方数据的中文字段映射为系统可识别的标准化字段，适配收益率计算逻辑 |
| `MAX_SYNC_RETRY_TIMES` | `3` | 应对第三方接口临时波动，避免单次同步失败导致数据缺失 |
| `DATA_SYNC_TIMEOUT` | `600 秒` | 适配玻璃数据单批次拉取量较大的特点，预留足够的超时时间防止提前中断 |
| `RECALL_FILTER_RULE` | `{"category": ["浮法玻璃"], "area": ["华东区域"]}` | 聚焦目标细分市场的行情数据，避免无关数据干扰收益率计算 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：新部署后调用数据接口返回403 Forbidden，无法拉取行情数据。原因：未配置`API_KEY_WHITELIST`，未将授权的第三方数据接口加入白名单。
- 现象：系统生成的收益率播报内容缺失核心字段，显示为空。原因：`PARSE_FIELD_MAPPING`配置错误，未正确映射第三方数据的基准报价、品类等核心字段。
- 现象：执行`docker run --gpus all -itd -p 7231:7231`启动容器后立即退出，查看日志显示配置缺失。原因：4.9.0版本新增了`DATA_SYNC_CRON`的强制配置项，未设置则无法启动数据同步服务。

## 怎么确认配好了
- 查看系统定时任务日志，确认`DATA_SYNC_CRON`对应的任务已按每日凌晨的节奏执行。
- 调用数据拉取接口，检查返回的字段是否与`PARSE_FIELD_MAPPING`中的配置一一对应。
- 检查容器的环境变量，确认`API_KEY_WHITELIST`已配置授权的第三方接口域名。
- 手动触发一次数据同步，查看是否能正常拉取并解析玻璃行情数据，无报错信息。
