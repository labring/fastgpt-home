# 电力收益率的工作流编排

## 这个品类的数据长什么样
电力收益率相关数据主要来自省级电力交易中心公开API、电网调度报送的结构化运行数据。数据更新节奏为每日T+1更新前一交易日的全量交易信息。文档结构为按交易主体分组的JSON数组，核心字段包括交易主体编码、交易时段、结算电价、边际成本、核算收益率。其中结算电价单位为元/兆瓦时，边际成本单位为元/兆瓦时，核算收益率为无量纲数值。数据按发电类型分为火电、风电、光伏等子类，每个子类包含独立的交易记录条目。

## 这些特征在「工作流编排」这一环带来什么约束
电力数据的多源异构特性要求工作流需配置多个API拉取节点，分别对接不同交易主体的接口，并统一字段命名与单位。每日T+1的更新节奏要求工作流需设置定时触发规则，避免在数据未更新时执行任务。字段的专业属性要求工作流需加入校验节点，过滤异常的结算电价与收益率数值，防止无效数据进入后续计算环节。不同发电类型的计算逻辑存在差异，需在工作流中配置分支节点，按交易类型分流执行不同的收益率核算规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `定时触发配置` | `每日02:00 触发，重试次数设为2次` | 电力收益率日报为T+1数据，需在交易中心数据更新后执行，重试机制应对接口临时波动 |
| `多源API节点映射规则` | `将不同接口返回的`结算电价`字段统一映射为`trade_price`，单位统一为元/兆瓦时` | 电力数据来自多交易主体接口，字段命名不统一，需标准化处理 |
| `字段校验阈值` | `过滤`trade_price`小于0的条目，`核算收益率`取值区间设为0-2` | 电力交易结算电价不会为负，收益率处于合理区间，避免无效数据进入后续流程 |
| `知识库关联datasetID` | `填入对应电力交易规则知识库的datasetID，通过全局变量`{{dataset_id}}`引用` | 解决无法直接引用全局变量的问题，需在节点配置中绑定变量映射 |
| `节点输出隐藏配置` | `将数据清洗节点的输出设为不对外展示` | 仅保留最终播报节点的输出，符合内部工作流的信息精简需求 |
| `用户级变量作用域` | `开启工作流的用户级变量开关，将`user_id`绑定为作用域变量` | 不同使用者的配置需隔离，避免全局变量冲突 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中知识库检索节点返回结果为空，日志显示`dataset_id`字段未找到。原因：未将全局变量正确映射到节点的datasetID配置项，仅在全局变量面板设置未绑定到具体节点。
- 现象：基于问题分类的工作流测试时，仅第一个问题触发知识库引用，后续问题无返回结果。原因：未设置循环触发节点的上下文重置规则，前一次检索的上下文残留导致后续请求被拦截。
- 现象：配置多AI对话节点后，其中一个节点的输出仍展示在最终结果中。原因：未开启该节点的`隐藏输出`配置项，默认保留所有节点的输出内容。

## 怎么确认配好了
- 查看工作流的定时触发日志，确认每日指定时间有执行记录，无接口报错或超时提示。
- 手动触发工作流，检查字段校验节点的输出，确认异常数据已被过滤，标准化字段与预期格式一致。
- 使用不同用户ID触发工作流，确认用户级变量的取值相互隔离，无跨用户数据共享情况。
- 查看最终播报节点的输出内容，确认仅保留需要展示的信息，隐藏节点的输出未出现在结果中。
