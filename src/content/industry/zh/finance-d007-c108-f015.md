# 电商服务收益率的部署与升级

## 这个品类的数据长什么样
电商服务的收益率与行情日报数据，主要来自电商平台开放的商家经营数据接口、合作的电商数据服务供应商的批量导出文件。更新节奏为每日固定时段同步前一日的经营数据，用于生成当日经营日报。数据文档为结构化表格，按商家与经营品类分组，包含统计日期、商家标识、经营品类、成交总额、成交单量、经营利润率、客单价、复购频次等字段。成交总额单位为元，成交单量单位为笔，客单价单位为元，复购频次单位为次。

## 这些特征在「部署与升级」这一环带来什么约束
该品类的数据来源包含API接口与批量导出文件，部署时需同时适配两种数据接入方式，配置对应的格式校验规则。固定的每日更新节奏，要求部署时配置与数据源同步窗口匹配的定时任务触发参数。批量数据文件可能存在较大体积，需调整文件解析与上传的相关限制参数。多商家多品类的分组结构，要求配置字段映射规则，匹配不同商家的自定义字段。升级过程中需保证数据同步不中断，需采用灰度发布或滚动更新策略，避免影响当日日报生成。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `1200 秒` | 电商批量数据文件通常体积较大，需预留足够解析时间 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 支持较大体积的批量数据文件导入 |
| `CRON_EXPRESSION` | `0 2 * * *` | 匹配多数电商平台凌晨2点完成前一日数据导出的同步窗口 |
| `maxContext` | `8000 字符` | 适配单条日报文档的内容长度需求 |
| `RECALL_TOP_N` | `前10条` | 匹配单商家日报的核心数据条目数量 |
| `DATA_SOURCE_TYPE` | `混合模式` | 同时支持API拉取与本地文件导入两种数据接入方式 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：本地部署后服务启动失败，日志返回内存不足报错。原因：未根据电商批量数据的处理需求调整内存分配参数，默认配置不足以支撑大体积数据解析。
- 现象：非Docker部署的服务无法按时同步日报数据。原因：未配置系统级定时任务，仅手动运行同步脚本，无法实现每日自动更新。
- 现象：私有化部署更新到最新版本后，团队版功能无法启用。原因：未将本地部署的授权文件复制到新版本的部署目录，导致授权校验失败。

## 怎么确认配好了
- 手动上传一份模拟的电商日报数据文件，检查解析后的字段是否与配置的映射规则一致。
- 手动触发一次定时同步任务，确认数据是否在预设时间内完成拉取或导入，无超时报错。
- 查看服务的监控面板，确认文件上传、数据解析的成功率达到预设标准。
- 检查授权文件的部署位置，确认团队版功能的校验状态正常。
