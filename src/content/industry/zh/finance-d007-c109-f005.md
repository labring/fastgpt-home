# 电子元件收益率的多轮对话与提示词

## 这个品类的数据长什么样
电子元件的行情与收益率数据主要来源于原厂公开指导价、现货交易平台实时报价、行业第三方数据库三类渠道。实时现货报价每小时更新一次，原厂指导价每日更新，行业周报数据每周更新。单份标准文档包含元件型号、封装规格、当前报价、7日均价、涨跌幅、供货周期、厂商库存余量等字段，报价单位多为人民币/颗或美元/片，部分精密元件会附带公差参数与测试报告编号。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
多数据源与差异化更新频率要求多轮对话需先明确用户所需的数据类型与时间范围，避免混淆实时与历史数据。字段数量多且单位多样的特征，要求提示词必须精准指定需提取的字段与输出单位，防止生成内容缺失关键信息或单位错误。元件型号数量庞大且存在相似命名规则的特点，要求对话上下文需保留用户指定的具体型号，避免后续查询出现品类混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `2000–3000 字符` | 电子元件行情数据包含多组字段与型号信息，需保留足够上下文以避免丢失用户指定的查询条件 |
| `temperature` | `0.1–0.3` | 收益率与行情播报需保证数值与格式的准确性，不宜出现随机生成的偏差内容 |
| `prompt_template` | 「请先确认查询的元件型号、数据类型（实时/历史）与时间范围，再提取对应字段并按【型号：XXX，当前报价：XXX，单位：XXX，涨跌幅：XXX】格式返回」 | 电子元件数据字段多且单位多样，明确的提示词可规范输出格式与提取范围 |
| `PARSE_FILE_MAX_LENGTH` | `1500 字符` | 单份电子元件行情文档通常包含多组型号数据，限制解析长度可避免截断关键信息 |
| `relevance_threshold` | `0.85` | 需精准匹配用户指定的元件型号，过滤无关品类的行情数据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用文本内容提取模块时，传入代码块格式的提示词后，完整响应显示代码块为undefined。原因：未在提示词中明确指定代码块的包裹标记与提取范围，导致模块无法识别有效提取内容。
- 现象：设置变量引用后，温度设置按钮消失，无法调整`temperature`参数。原因：变量引用模式下默认继承全局对话配置，未切换至单轮对话配置面板。
- 现象：对话生成的Markdown内容无回车换行，复制时需手动选择文字。原因：提示词未明确要求用换行符分隔每条元件的行情数据，导致输出格式紧凑无分段。

## 怎么确认配好了
- 发起包含多个元件型号与数据类型的测试对话，核对上下文是否保留了所有用户指定的查询条件。
- 生成行情播报内容，核对输出格式是否符合预设的提示词要求，字段与单位是否匹配数据源规范。
- 调用接口测试工作流，查看对话日志中的运行数据是否包含完整的模块执行记录与返回内容。
- 调整`temperature`参数后，验证生成内容是否保持稳定的格式与数值准确性，无随机偏差。
