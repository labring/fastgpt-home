# 电子元件收益率的部署与升级

## 这个品类的数据长什么样
电子元件的行情与收益率相关数据主要来自三类公开数据源：原厂官方报价页面、垂直元器件供应链数据接口、行业现货交易平台。数据更新节奏存在差异：现货交易报价每自然日更新，原厂指导价每7个自然日更新，库存余量数据每24小时更新。单条标准数据包含元件型号、厂商名称、批次编号、交易单价、库存数量、更新时间等字段，其中单价字段附带计价单位，如元/件、元/盘。批量数据通常以JSON或CSV格式封装，以元件型号加批次作为唯一识别标识。

## 这些特征在「部署与升级」这一环带来什么约束
多数据源与差异化更新节奏要求部署阶段需适配多接口鉴权规则与独立调度配置，避免因统一调度导致数据拉取异常。字段包含单位信息且存在唯一标识，要求部署时配置统一的字段映射规则与去重逻辑，防止数据混乱与重复入库。不同数据源的访问权限存在差异，部分接口要求配置IP白名单，部署时需提前完成白名单配置。升级阶段需兼容旧版配置格式，避免因配置文件迁移失败导致数据拉取中断，同时需确保新版本的调度逻辑与旧版数据源适配。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DATA_SOURCE_TYPE` | `["official_quote", "spot_trade", "inventory"]` | 覆盖原厂指导价、现货报价、库存三类核心业务数据来源 |
| `SCHEDULER_CRON_EXPRESSION` | 现货任务：`0 0 1 * * ?`，原厂指导价任务：`0 0 2 * * 1` | 匹配对应数据源的实际更新频率，避免无效拉取 |
| `FIELD_MAPPING_RULES` | `{"元件型号":"sku","厂商名称":"manufacturer","单价":"price","单位":"unit"}` | 统一不同数据源的原始字段到系统标准字段，避免单位混乱 |
| `DATA_CLEAN_DUPLICATE_ENABLE` | `true` | 以元件型号加批次为唯一标识，自动过滤重复数据 |
| `API_WHITELIST_IP` | `["数据源服务商官方出口IP段"]` | 满足部分数据源接口的IP访问限制要求 |
| `CONFIG_MIGRATION_MODE` | `auto` | 版本升级时自动迁移旧版配置，减少手动操作成本 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用数据源接口返回403 Forbidden状态码，或云数据库连接失败。原因：未配置数据源或数据库要求的访问白名单，或白名单IP配置不准确。
- 现象：拉取的电子元件数据缺失单位字段，或单位格式不一致。原因：未配置字段映射规则，未将数据源的原始单位字段映射到系统标准字段。
- 现象：升级到v4.8.20-fix版本后，系统启动时提示配置文件缺失或格式错误。原因：未按照升级文档执行配置迁移，仍依赖旧版config.json文件的配置格式。

## 怎么确认配好了
- 执行一次手动触发的数据拉取任务，检查返回的电子元件数据是否包含配置的所有标准字段，字段格式与单位是否符合预期。
- 查看定时任务调度日志，确认不同数据源的拉取任务按照配置的周期按时执行，无异常报错记录。
- 测试配置的白名单IP有效性，通过调用数据源接口验证访问权限是否正常。
- 升级版本后，查看系统配置面板，确认旧版config.json中的配置项已自动迁移至新的配置存储位置，无配置丢失或错误。
