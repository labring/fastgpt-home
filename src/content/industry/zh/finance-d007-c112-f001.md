# 白色家电收益率的HTTP 接口与外部系统

## 这个品类的数据长什么样
白色家电收益率相关数据主要来源于公开家电产业零售数据库、线下零售POS数据汇总及上游大宗商品交易联动数据源。数据更新节奏为每日凌晨同步前一自然日的全量行情与收益率信息。单条数据文档以JSON格式组织，包含`sku_id`（字符串，产品唯一标识）、`product_category`（字符串，如壁挂式空调）、`daily_gross_margin`（数值，单位为元）、`raw_material_cost_proportion`（数值，单位为百分比）、`retail_volume_change`（数值，单位为百分比）。数据整体按产品品类分组，每个分组包含当日全量SKU的收益率关联指标，无额外嵌套层级。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
白色家电收益率数据的多源分散特征，要求外部系统对接多个独立数据源的HTTP接口，需配置统一的请求头与鉴权参数以兼容不同平台的接入规则。每日更新的节奏要求定时拉取任务需匹配数据源的更新窗口，避免在数据未完成同步时发起请求，导致返回空数据或旧数据。按品类分组的文档结构，要求接口配置按`product_category`字段的过滤参数，同时需建立字段映射规则，将不同数据源的异名字段统一为内部标准格式。多指标字段的返回要求配置字段筛选参数，仅拉取所需的收益率关联指标，降低数据传输开销。此外，零售数据的不确定性要求配置超时与重试机制，应对接口调用失败的情况。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `external_api_timeout` | `30 秒` | 覆盖多数家电数据源的正常响应时长与轻微网络波动，避免超时中断请求 |
| `external_api_retry_times` | `3 次` | 应对临时网络抖动，降低单次调用失败导致的数据同步失败概率 |
| `sync_schedule` | `0 1 * * *` | 匹配多数家电数据源的每日凌晨数据更新窗口，确保拉取最新全量数据 |
| `field_mapping_rule` | 按数据源预设规则自动匹配 | 兼容不同家电数据源的异名字段，减少手动配置的工作量 |
| `api_auth_type` | `bearer_token` | 符合多数公开家电产业数据源的鉴权规范，简化接入配置 |
| `return_field_filter` | `["sku_id", "product_category", "daily_gross_margin", "raw_material_cost_proportion"]` | 仅拉取收益率播报所需的核心字段，降低数据传输与处理开销 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用外部数据源接口返回`400 Bad Request`状态码，日志显示指定字段不存在。原因：未配置正确的字段映射规则，导致数据源返回的异名字段无法被内部系统识别。
- 现象：定时同步任务执行后返回空数据列表。原因：同步时间设置在数据源更新前的时段，尚未获取到当日最新的收益率数据。
- 现象：调用接口耗时超过系统默认限制，触发超时报错。原因：未调整`external_api_timeout`参数至合理时长，默认超时时间不足以覆盖家电数据源的响应周期。

## 怎么确认配好了
- 发起一次手动同步请求，检查返回的JSON数据是否包含配置的`return_field_filter`中的所有字段，且字段值符合预期格式。
- 查看定时任务的执行日志，确认任务在预设的`sync_schedule`时间点成功执行，未出现鉴权或超时类报错。
- 调用接口时，检查返回的结果是否按`product_category`字段正确分组，符合文档结构的预设要求。
- 配置完成后发起一次鉴权测试请求，确认返回的状态码为`200 OK`，未出现鉴权失败的提示。
