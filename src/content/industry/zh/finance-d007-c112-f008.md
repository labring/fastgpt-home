# 白色家电收益率的工具调用与插件

## 这个品类的数据长什么样
数据来自家电厂商月度供货台账、主流电商平台的实时销售快照、行业监测机构的线下终端采样数据。更新节奏为：线上零售数据每日更新，线下终端数据每周更新一次，促销活动数据随活动周期同步发布。文档以结构化CSV或JSON格式存储，包含SKU编码、产品型号、额定功率、供货单价、终端零售单价、库存周转天数等字段，单位分别为无、无、千瓦时、元/台、元/台、天。无额外非结构化附加内容，字段命名随数据源不同存在细微差异。

## 这些特征在「工具调用与插件」这一环带来什么约束
多源数据的更新节奏差异要求工具调用支持按数据源配置不同的触发频率，避免高频拉取低频更新的线下数据导致资源浪费。不同数据源的字段命名差异需要配置统一的映射规则，确保工具返回的字段与业务需求一致。结构化数据的字段固定性要求工具解析环节开启严格模式，过滤非预期字段，避免结果混入无关内容。跨数据源的字段关联需求需要插件支持多源数据的联动调用，整合不同来源的业务数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `TOOL_DATA_SOURCE_LIST` | `["ecommerce_snapshot", "manufacturer_inventory", "industry_monitor"]` | 覆盖线上零售、厂商供货、行业监测三类核心数据来源 |
| `TOOL_UPDATE_FREQUENCY` | `24 小时` | 匹配线上零售数据的每日更新节奏 |
| `FIELD_MAPPING_RULES` | `{"ecommerce_snapshot.retail_price": "terminal_retail_price", "manufacturer_inventory.supply_price": "supply_unit_price"}` | 统一不同数据源的字段命名差异 |
| `TOOL_TIMEOUT` | `600 秒` | 匹配结构化数据拉取与解析的平均耗时区间 |
| `PARSE_STRICT_MODE` | `开启` | 过滤非预期的非结构化字段，保证结果一致性 |
| `MCP_SERVER_WHITELIST` | `["white_appliance_data_provider"]` | 限制工具调用的合法服务端范围 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工具调用后提取的字段为空或与实际值不符，原因是未配置`FIELD_MAPPING_RULES`，导致不同数据源的字段名不匹配，无法正确映射目标字段。
- 现象为工具调用的执行日志和原始结果被直接输出到对话界面，原因是未开启`TOOL_HIDE_EXECUTION_LOG`配置项，或工具调用结束节点的触发条件未正确绑定。
- 现象为无法向执行中的MCP工具发送终止命令，或命令无响应，原因是未在`MCP_SERVER_CONFIG`中开启`allow_terminate`参数，或未正确配置工具调用的终止触发条件。

## 怎么确认配好了
- 调用测试工具拉取单条数据源的结构化数据，核对映射后的字段名称与预设的业务字段一致。
- 查看工具调用的日志，确认拉取的数据更新时间戳与对应数据源的更新节奏匹配。
- 触发工具调用后，检查对话界面是否隐藏了执行日志，符合配置要求。
- 模拟工具执行超时或异常，确认终止命令可以正常发送并停止工具运行。
