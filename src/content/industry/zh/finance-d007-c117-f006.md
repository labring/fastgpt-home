# 纺织制造收益率的对话日志与审计

## 这个品类的数据长什么样
纺织制造的收益率与行情数据主要来源于企业ERP生产模块、原料大宗商品行情接口。数据按自然日汇总更新，每日凌晨完成前一日全量数据的整合。单份数据文档以生产批次、车间为核心维度，包含生产批次号、车间编码、原料品类、单位用量、单位成本、销售单价、当日产量、当日销售额等字段，单位涵盖千克、米、平方米、元等品类适配的计量标准。

## 这些特征在「对话日志与审计」这一环带来什么约束
数据按自然日汇总更新的特性，要求对话日志需同步记录请求发起时间与数据生效周期，避免跨日调用时混淆新旧数据。多维度多字段的文档结构，要求日志需完整记录请求携带的筛选参数，包括生产批次、车间编码、原料品类等，确保审计时可精准匹配对应数据范围。多单位并行的字段设计，要求日志中需附带每个数值字段的计量标准，防止跨单位计算引发的审计偏差。批量生成日报的场景，要求日志拆分并记录每个子请求的执行状态与返回结果，便于定位单条数据异常的源头。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `logRetentionDays` | `90 天` | 纺织制造的审计合规要求通常覆盖季度周期，90天可满足常规审计追溯需求 |
| `auditLogIncludeParams` | `生产批次号、车间编码、原料品类` | 匹配该品类数据的核心筛选维度，确保审计时可精准关联对应数据范围 |
| `maxContext` | `前4轮对话 + 1000 字符数据摘要` | 纺织制造收益率分析需关联原料行情、生产数据的历史上下文，4轮对话可覆盖必要的逻辑关联，1000字符摘要可避免上下文溢出 |
| `apiRequestTimeout` | `600 秒` | 批量生成多车间、多品类的收益率日报时，数据拉取与计算耗时较长，600秒可覆盖多数场景的执行周期 |
| `errorLogLevel` | `DEBUG` | 该品类数据字段复杂，DEBUG级别可记录完整的参数解析与数据匹配过程，便于定位审计异常 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：审计日志中出现非工作时段的异常调用记录，余额消耗异常。原因：未配置`apiRequestWhitelist`，外部未授权请求可直接调用收益率播报接口，导致非工作时段的无效调用。
- 现象：调用接口后无法获取全量车间的收益率数据，返回结果条数不足。原因：未调整`batchLogSplitThreshold`参数，批量请求的拆分阈值设置过低，导致部分车间的数据未被纳入返回结果。
- 现象：对话界面提示令牌错误，但关联的日志平台显示令牌为`fastgpt`。原因：未在FastGPT的`apiAuthToken`配置中设置专属令牌，使用默认令牌时与其他系统的令牌冲突，导致认证失败。

## 怎么确认配好了
- 发起一个包含指定生产批次、车间编码的对话请求，检查审计日志中是否完整记录了请求发起时间、筛选参数与返回结果的字段单位。
- 模拟非工作时段的请求，验证`apiRequestWhitelist`配置是否生效，未授权请求是否被拦截并记录到错误日志。
- 查看日志保留目录，确认超过`logRetentionDays`的旧日志已被自动清理或归档。
- 发起批量请求，验证返回结果的条数与筛选维度的匹配度，确认`batchLogSplitThreshold`的设置符合当前业务规模。
