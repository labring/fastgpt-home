# 耐火材料收益率的数据库与运维

## 这个品类的数据长什么样
耐火材料收益率相关数据的来源包括国内耐火材料行业协会的原料与成品报价数据库、生产企业的MES系统台账、大宗商品现货交易平台的原料行情数据。更新节奏存在差异：原料现货报价每日更新，成品出厂结算价每周更新，单批次生产的能耗数据随生产完成同步上传。单条数据记录包含批次编号、原料类型、原料采购单价、单位能耗成本、成品出厂结算价、核算周期六个核心字段。原料单价单位为元/吨，能耗成本单位为元/吨成品，出厂结算价单位为元/吨成品，核算周期以自然周或自然月为单位。

## 这些特征在「数据库与运维」这一环带来什么约束
多源数据的更新频率差异，要求搭建分层同步机制，避免高频的原料数据同步占用过多服务器资源，同时保障低频的出厂价数据及时入库。单条数据关联多个独立来源的字段，需要建立批次编号作为全局主键，否则无法完成跨源的收益率准确核算。每日与每周的批量数据更新会带来写入峰值，需要配置合理的批量写入阈值，避免单次写入超时导致数据丢失。不同来源的数据格式存在差异，部分平台使用原料中文名称，部分使用国标代码，需要前置配置统一的映射规则，否则会出现字段不匹配的问题。数据量随生产批次持续增长，需要定期归档历史核算数据，避免存储资源过度占用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `batch_write_threshold` | `500 条/次` | 耐火材料单批次生产数据的批量上传峰值约为400条/小时，500条的阈值可避免单次写入超时 |
| `data_clean_rule_timeout` | `120 秒` | 多源数据格式转换需要处理原料代码、单位对齐等步骤，120秒可覆盖多数清洗场景 |
| `index_rebuild_interval` | `7 天` | 耐火材料收益率数据的关联字段每周新增约10%，7天重建索引可平衡查询效率与维护成本 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 单份耐火材料行情日报文档包含约2000条数据，600秒可完成全量解析与入库 |
| `召回条数` | `前 10 条` | 耐火材料行情播报需要覆盖主要原料与成品品类，10条召回结果可满足日报播报的信息密度要求 |
| `相似度阈值` | `0.75` | 需要区分同类型不同批次的耐火材料数据，0.75的阈值可避免冗余召回同时覆盖有效关联数据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：多源同步后出现原料单价与出厂价的关联字段为空。原因：未配置多源数据的主键匹配规则，导致不同来源的批次编号无法对齐，无法完成关联核算。
- 现象：开启混合检索的问题优化与结果重排后，单条查询耗时超过30秒。原因：召回条数设置超出业务需求的覆盖范围，且未限制重排返回条数，导致解析与检索链路阻塞。
- 现象：本地部署后无法创建收益率数据库实例。原因：未提前配置数据库的存储路径权限，或未初始化数据库的关联索引表，导致写入请求被拒绝。

## 怎么确认配好了
- 执行一次多源数据同步任务，查看同步日志中是否存在格式转换失败的报错，确认`data_clean_rule_timeout`的取值覆盖了当前清洗流程的实际耗时。
- 发起一次耐火材料收益率的查询请求，查看返回结果的字段完整性与信息密度，确认`召回条数`与`相似度阈值`的取值符合当前行情播报的需求。
- 检查数据库的索引状态，确认`index_rebuild_interval`的配置已按计划触发索引维护，且查询延迟符合业务要求。
- 查看本地部署的数据库服务日志，确认无权限报错或初始化失败的提示，验证数据库实例创建流程正常。
