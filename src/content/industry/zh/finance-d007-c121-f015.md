# 耐火材料收益率的部署与升级

## 这个品类的数据长什么样
耐火材料收益率与行情日报的数据来源为行业自律监测机构、大宗商品现货交易市场公开报价及下游生产企业采购台账数据。更新节奏为每日凌晨同步前一日全量数据，单份日报文档大小稳定在500-800KB。文档按产品品类拆分，包含产品名称、规格型号、生产企业、当日成交价、当日批发价、周度均价、月度均价字段，成交价与批发价单位为元/吨，周度及月度均价按连续7日、30日的成交均价计算。

## 这些特征在「部署与升级」这一环带来什么约束
多源数据拉取的需求要求部署时配置多数据源鉴权与重试机制，避免单一数据源故障导致数据中断。每日固定时间更新的节奏要求定时任务配置需避开行业数据接口的峰值时段，防止拉取失败。按品类拆分的文档结构要求分块规则需匹配产品分类维度，避免跨品类的上下文混淆。字段包含规格型号等非标信息，要求实体抽取的匹配阈值需适配非标字段的识别精度。升级环节需保留原有多源对接与定时任务配置，同时暂停临时拉取任务以避免数据覆盖冲突。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 耐火材料日报单份文档大小为500-800KB，常规解析耗时2-4分钟，300秒可覆盖全量解析流程 |
| `CRON_SCHEDULE` | `0 2 * * *` | 每日凌晨2点避开行业数据接口的峰值时段，保障数据拉取的稳定性 |
| `KNOWLEDGE_BASE_CHUNK_SIZE` | `800–1200 字符` | 单条产品数据约100字符，按品类分块的800-1200字符长度可覆盖单品类完整信息 |
| `MULTI_SOURCE_RETRY_TIMES` | `3 次` | 多数据源拉取存在接口波动风险，3次重试可平衡成功率与任务耗时 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 批量导入多品类日报时，单批次打包文件的最大合理上限 |
| `ENTITY_EXTRACT_THRESHOLD` | `0.75` | 适配耐火材料非标规格型号字段的识别，兼顾精度与召回率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：拉取耐火材料日报数据后，日志显示`'usage' KeyError`。原因：未配置多数据源的字段校验逻辑，部分数据源返回的响应缺失非必填字段，触发键值读取异常。
- 现象：使用docker-compose部署v4.8.9版本后，新建知识库弹出报错提示。原因：未正确配置容器挂载的存储目录权限，导致系统无法写入分块后的文档数据。
- 现象：定时拉取任务执行后，知识库返回的结果条数为0。原因：`CRON_SCHEDULE`配置的触发时段与行业数据接口的维护时段重叠，导致拉取的响应内容为空。

## 怎么确认配好了
- 执行单次数据拉取任务，查看系统日志是否存在字段缺失或超时报错，核对拉取到的文档字段与预设字段是否一致。
- 进入知识库管理界面，查看分块后的文档数量与实际导入的文档数量是否匹配，确认分块规则已生效。
- 检查定时任务的执行日志，确认每日凌晨的拉取任务是否正常触发，无失败重试次数超限的记录。
- 测试实体抽取功能，输入耐火材料的规格型号字段，确认系统可正确识别对应的实体信息。
