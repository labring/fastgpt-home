# 能源金属收益率的HTTP 接口与外部系统

## 这个品类的数据长什么样
能源金属行情数据来自大宗商品现货、期货交易市场的公开接口及行业自律组织的标准化报送数据，更新节奏匹配对应交易市场的交易时段，日间交易时段按市场公开节奏推送数据，盘后生成当日结算维度的完整数据集。数据以JSON格式封装，包含品种标识、交易市场标识、最新成交价格、当日结算价格、当日累计成交量等字段，计价单位统一为元/吨或千克级标准单位。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
由于数据来源覆盖多类交易市场，不同数据源的认证要求、字段命名存在差异，外部系统需适配多套认证逻辑并完成字段映射。更新节奏随交易时段变化，需配置时段化的拉取任务以避免非交易时段的无效请求，同时需控制请求频率以匹配数据源的限流规则。能源金属品类覆盖多个细分品种，接口需支持批量查询以降低外部系统的请求负载，此外跨市场的时间戳转换需统一处理，避免因时区差异导致的数据时间异常。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `request_interval` | `10-30 秒` | 匹配能源金属日间交易时段的行情更新节奏，避免超出数据源的调用频率限制 |
| `auth_type` | `按数据源配置` | 不同行情数据源的认证要求不同，部分为公开接口无需认证，部分需要API密钥 |
| `fetch_time_window` | `9:00-17:00（对应国内主要交易时段）` | 适配能源金属的交易时段，减少非交易时段的无效请求 |
| `field_mapping_rule` | `按品种对应标准字段映射` | 不同数据源的字段命名存在差异，统一映射为内部标准字段格式 |
| `retry_max_times` | `3 次` | 应对临时网络波动或数据源临时限流的场景，避免重复请求导致的资源浪费 |
| `timeout_threshold` | `15 秒` | 匹配行情数据的实时性要求，超过阈值的请求直接终止并触发告警 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
-  请求超时后未触发重试，导致外部系统无限等待。现象为外部系统日志出现`ETIMEDOUT`状态码，进程持续占用资源无法释放。原因是未配置`retry_max_times`参数，或重试间隔设置过长，未匹配行情数据的实时性要求。
-  字段映射错误导致收益率相关数据为空。现象为外部系统接收的JSON字段中`price_change`字段为空，无法生成对应播报内容。原因是未按照`field_mapping_rule`配置进行统一映射，直接使用数据源的非标准字段名。
-  在非交易时段发起请求导致触发限流。现象为HTTP接口返回`429 Too Many Requests`状态码，后续请求被临时封禁。原因是未配置`fetch_time_window`参数，在盘后或休市时段持续发起请求。

## 怎么确认配好了
-  发起单次测试请求，检查返回的JSON字段是否包含标准行情字段，字段单位是否符合预期，根据实际数据源调整`field_mapping_rule`配置。
-  配置时段化的拉取任务，在交易时段和非交易时段分别发起请求，检查非交易时段的请求是否被拦截，交易时段的请求是否正常返回数据。
-  模拟请求超时场景，检查是否触发预设的重试机制和告警规则，根据`timeout_threshold`和`retry_max_times`调整参数。
-  对比多个数据源的返回数据，检查字段映射是否统一，避免出现不同数据源的字段格式不一致的问题。
