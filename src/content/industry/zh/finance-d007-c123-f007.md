# 能源金属收益率的工作流编排

## 这个品类的数据长什么样
能源金属的行情与收益率数据主要来自国内大宗商品期货交易所、现货贸易平台及行业库存数据库。更新节奏分为两类：日度汇总数据在每个交易日收盘后1小时内完成更新，日内分时行情每5分钟刷新一次。数据文档多为结构化JSON或CSV格式，包含交易日期、品种标识、结算价、涨跌幅、现货基准价、库存总量等字段。价格单位为元/吨，涨跌幅单位为百分比，持仓量单位为手，库存数据单位为吨。

## 这些特征在「工作流编排」这一环带来什么约束
数据源分散要求工作流配置多节点并行拉取，需添加字段对齐节点统一不同数据源的格式；固定的更新节奏要求定时触发节点设置精准的执行时间，避免非交易时段的无效调用；多字段的结构化数据需配置字段筛选节点，仅保留收益率、行情核心字段以减少处理开销；跨数据源的期货与现货数据合并，需设置联合主键匹配规则，防止因字段顺序差异导致合并失败；日报播报需汇总多源数据，需配置聚合节点完成数据整理。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `trigger_type` | 定时触发，执行时间设为每日17:30 | 匹配能源金属交易日收盘后1小时的常规数据更新节奏 |
| `parallel_data_nodes` | 2-3个并行拉取节点 | 覆盖期货行情、现货报价、行业库存三类核心数据源 |
| `field_filter_list` | 保留`trade_date`、`product_code`、`settle_price`、`change_rate`、`spot_price`字段 | 仅保留日报播报所需的核心业务字段，减少后续处理数据量 |
| `merge_match_key` | 以`trade_date`和`product_code`作为联合主键 | 确保跨数据源的行情与现货数据准确匹配 |
| `node_timeout` | 600秒 | 预留足够时间完成多数据源拉取与格式转换 |
| `error_retry_times` | 2次 | 应对单次数据源临时波动导致的调用失败 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：发起提问后进入工具调用环节直接返回`504 Gateway Timeout`状态码。原因：未设置合理的超时阈值，多数据源并行拉取时超出节点允许的响应时间。
- 现象：配置的全局变量未生效，播报内容中核心字段为空。原因：未在工作流启动节点中初始化全局变量的默认值，变量未完成赋值即被引用。
- 现象：工作流中引用的变量无法正确渲染到播报内容的正文区域。原因：未使用平台规定的变量引用语法，或变量作用域未覆盖当前播报节点。

## 怎么确认配好了
- 查看定时触发节点的执行时间，确认与能源金属数据更新节奏匹配。
- 运行一次测试工作流，检查拉取到的数据字段是否与预设的筛选列表一致。
- 传入模拟的能源金属数据，验证变量引用是否能正确渲染到播报正文。
- 查看工作流的执行日志，确认多数据源拉取节点未出现超时或合并失败的记录。
