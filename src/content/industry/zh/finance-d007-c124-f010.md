# 自动化设备收益率的数据库与运维

## 这个品类的数据长什么样
自动化设备的收益率与行情数据来源包括内置运行参数采集接口、对接的金融行情数据源接口，以及设备执行交易后的收益核算模块。数据更新节奏以每日凌晨的批量全量更新为主，部分实时监控场景下按分钟推送临时波动数据。文档采用结构化JSON或CSV格式，包含设备ID、采集时间戳、设备运行状态码、关联交易标的代码、当日收益率、累计收益率、持仓量、交易笔数等字段。时间戳采用Unix毫秒级格式，收益率为无量纲小数，持仓量为整数单位，交易笔数为正整数。

## 这些特征在「数据库与运维」这一环带来什么约束
每日批量更新与分钟级临时数据的混合更新模式，要求数据库支持分时分区存储，避免单表数据量持续膨胀。字段包含设备ID、交易标的代码等关联维度，需建立联合索引以提升多条件查询效率。实时写入的分钟级数据要求数据库连接池具备足够的并发处理能力，防止写入阻塞。固定结构的字段要求提前预留扩展字段，避免后续数据迭代时频繁修改表结构。临时波动数据的时效性要求运维监控配置分钟级的写入延迟告警，确保数据及时入库。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_POOL_MAX_CONNECTIONS` | `20–30 个` | 适配自动化设备的分钟级实时写入与每日批量导入的并发负载，避免连接池耗尽 |
| `DB_TABLE_PARTITION` | `按自然日分区` | 匹配每日更新的收益率日报数据周期，优化单表查询与归档效率 |
| `BATCH_INSERT_SIZE` | `500–1000 条/次` | 平衡单次写入的网络开销与数据处理延迟，适配自动化设备的批量数据输出 |
| `WRITE_TIMEOUT_MS` | `30000 毫秒` | 处理大体积的每日批量数据导入，防止超时中断写入流程 |
| `INDEX_CREATION_DELAY` | `600 秒` | 在批量数据写入完成后再创建联合索引，避免影响实时写入性能 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：偶现SQL查询成功返回数据，部分同语句查询失败，返回`504 Gateway Timeout`或空字段。原因：数据库连接池并发上限设置过低，批量写入任务占用全部连接，导致查询请求无法获取可用连接。
- 现象：工具调用节点执行后流程停滞，无报错日志或仅显示`ETIMEDOUT`。原因：数据库写入超时配置小于批量数据的处理时长，触发超时后未配置自动重试，导致流程挂起。
- 现象：在容器内执行`npm list mongoose`无输出，但`package.json`中存在依赖声明。原因：容器内未全局安装npm依赖包，仅在项目目录下安装了依赖，导致全局npm命令无法识别指定包的版本。

## 怎么确认配好了
- 执行单次设备数据导入脚本，查看数据库连接日志，确认活跃连接数未超出配置的最大连接数。
- 执行批量数据导入任务，核对导入完成时长与配置的写入超时设置的匹配情况。
- 检查数据库表结构，确认已创建对应关联字段的联合索引。
- 查看运维监控指标，确认数据写入延迟处于预设的可接受范围。
