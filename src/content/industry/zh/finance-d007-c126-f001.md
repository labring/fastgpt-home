# 航空机场收益率的HTTP 接口与外部系统

## 这个品类的数据长什么样
航空机场收益率相关数据的来源包括民航行业公开统计接口、机场运营管理系统的内部结算数据。数据更新节奏为每日凌晨完成前一日全量运营数据的汇总生成。文档结构为结构化JSON格式，包含机场三字代码、当日起降架次、旅客吞吐量、起降费收入、非航业务收入、单架次平均收益、单位旅客收益等字段。字段单位分别为：起降架次为架次，旅客吞吐量为人次，收入类字段为人民币元，单位收益类字段为元/架次或元/人次。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
数据来源包含民航公开接口与机场内部系统两类，要求外部系统支持多源数据拉取与合并校验，避免单一数据源失效导致的播报中断。每日仅更新一次全量数据，要求HTTP接口的轮询周期需匹配数据更新节奏，不宜设置短于24小时的轮询间隔，避免触发第三方接口的限流规则。字段包含特定单位的数值类内容，要求接口请求与返回的字段校验规则需严格绑定预设字段名与单位，避免单位转换导致的收益率计算偏差。部分偏远机场的非航收入数据存在归集延迟，要求外部系统需兼容空字段的场景，避免因字段缺失导致的接口调用失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `external_api_poll_interval` | 86400 秒 | 匹配航空机场收益率数据每日更新一次的节奏，避免重复请求触发第三方接口限流 |
| `external_api_source_mode` | 双源拉取 | 对接民航公开统计接口与机场内部运营系统，保障单一数据源故障时仍可获取有效数据 |
| `field_unit_validation` | 开启 | 校验接口返回字段的单位与预设规则匹配，避免单位转换导致的收益率计算偏差 |
| `empty_field_policy` | 保留空值并标记 | 兼容偏远机场非航收入数据归集延迟的场景，避免强制填充导致的播报误差 |
| `request_timeout` | 300 秒 | 适配机场内部系统数据汇总的耗时，避免因请求超时中断数据拉取流程 |
| `rate_limit_quota` | 12 次/天 | 匹配民航行业公开接口的官方调用频次限制，防止接口被封禁 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：接口返回状态码429，且日志显示请求频次超限。原因：未匹配民航公开接口的调用频次限制，设置了短于24小时的轮询周期。
- 现象：播报内容中的单位收益字段出现单位格式混淆的情况。原因：未开启字段单位校验配置，擅自转换了接口返回的单位格式。
- 现象：部分偏远机场的收益率数据为空，导致HTTP接口调用失败。原因：未配置空字段兼容策略，强制要求所有字段非空导致校验失败。

## 怎么确认配好了
- 发起一次模拟请求，检查接口返回的字段是否包含预设的机场代码、起降架次、收益类字段，且单位与预设规则一致。
- 查看外部系统的调用日志，确认请求频次未超过配置的限流阈值，且轮询周期符合每日一次的要求。
- 模拟空字段的接口返回，检查系统是否按照配置的策略处理，未出现调用失败或错误播报。
- 切换至单一数据源进行测试，确认系统在单一数据源故障时仍可正常拉取备用数据源的数据。
