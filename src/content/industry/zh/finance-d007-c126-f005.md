# 航空机场收益率的多轮对话与提示词

## 这个品类的数据长什么样
航空机场收益率相关数据主要来源于公开民航运行监测平台、机场官方运营公示及第三方民航数据服务接口。更新节奏分为日度、周度与月度：日度数据每日更新当日起降架次、旅客吞吐量等核心运营指标，周度汇总周度收益相关统计值，月度出具完整运营收益报告。单条数据文档包含统计日期、机场标识、起降架次、旅客吞吐量、单架次营收、非航收入金额等字段，其中起降架次单位为次，旅客吞吐量单位为人次，单架次营收与非航收入金额单位为元。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
日度更新的特征要求多轮对话必须明确锚定统计日期，避免跨日期的指标混淆；多字段的文档结构要求提示词需清晰定义每个字段的指代范围，防止模型混淆主业营收与非航收入。高频更新的数据源需要匹配的知识库同步周期，确保召回内容为最新数据。多轮上下文需保留前序问题的机场与日期信息，当用户连续对比不同机场或不同周期的收益时，避免上下文串扰导致的结果错误。同时，用户可能同时提问多个维度的指标，提示词需明确引导模型仅使用当前问题关联的知识库条目，不引入无关数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 前1200–1500 字符 | 航空机场数据字段较多，需保留足够上下文区分不同日期、机场的指标，避免上下文溢出导致混淆 |
| `recallTopK` | 前6–8 条 | 单条机场日报数据量适中，召回过多会引入无关信息，过少无法覆盖用户所需的对比维度 |
| `similarityThreshold` | 0.72–0.80 | 匹配机场名称、日期关键词，阈值过低会召回无关机场数据，过高可能遗漏同机场不同日期的有效内容 |
| `reRankTopN` | 前3–4 条 | 聚焦核心日期与机场的收益数据，过滤冗余的历史非核心条目 |
| `detail` | 开启 | API调用时需返回完整引用字段，便于验证召回内容与用户问题的匹配度，适配v4.9.14版本参数规则 |
| `knowledgeBaseSyncInterval` | 每日1次 | 匹配机场日报的日度更新节奏，确保知识库始终包含最新的当日收益数据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：API调用返回结果未关联新建的机场收益率知识库。原因：未通过对话接口绑定对应知识库ID，或知识库创建时未配置正确的数据源同步规则。
- 现象：提示词与知识库引用配置的内容匹配度不足。原因：混淆了「引用内容模板」与「引用模板提示词」的作用边界，前者用于格式化召回的知识库文本，后者用于引导模型聚焦指定的收益指标维度。
- 现象：v4.9.14版本下同时发起多个对话请求时出现504超时错误。原因：未适配该版本默认的对话并发上限，未配置请求限流或队列等待机制。

## 怎么确认配好了
- 发起API调用，检查返回结果中是否包含指定的知识库引用字段，核对`detail`参数是否开启，确保返回内容与在线对话一致。
- 连续发起多轮不同日期、不同机场的提问，检查每轮结果是否锚定当前问题的日期与机场标识，无跨上下文串扰。
- 查看知识库同步日志，确认同步周期匹配机场数据的更新节奏，确保最新的日报数据已被召回。
- 对比在线对话与API调用的返回结果，确认`stream`与`detail`参数配置一致，无结果差异。
