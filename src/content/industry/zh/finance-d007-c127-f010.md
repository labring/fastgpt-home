# 航空装备收益率的数据库与运维

## 这个品类的数据长什么样
航空装备收益率相关数据的来源包括航空装备制造商的公开运维台账、民航运营主体的季度营收披露、第三方航空产业数据平台的结构化数据集。更新节奏为每日生成当日运营收益明细快照，每周汇总周度收益率，核心主力机型的实时能耗关联收益数据每4小时更新。单条数据文档包含装备唯一标识、运营周期、直接营收、间接成本、核算周期标识等字段，字段单位涵盖元、天等通用计量标准，未使用百分比类占比表述。

## 这些特征在「数据库与运维」这一环带来什么约束
每日增量更新与每4小时的高频数据推送，要求数据库配置支持低延迟的批量写入与定时同步任务，避免全量重导导致的资源占用过高。装备唯一标识与核算周期的联合字段需求，需要建立联合唯一索引，防止重复录入同周期同装备的收益数据。多源异构的数据格式，包括结构化台账、公开报表、实时传感数据，要求数据库前置支持轻量的数据格式转换规则，适配不同来源的字段映射。长期留存的运维数据需求，需要配置冷热数据分层存储策略，将超过180天的历史数据迁移至低成本存储介质。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_BATCH_INSERT_SIZE` | `500–800 条/批次` | 适配航空装备每日约600条增量收益数据的写入需求，平衡写入性能与网络资源占用 |
| `DB_UNIQUE_INDEX_FIELDS` | `["aircraft_id", "accounting_period"]` | 建立联合唯一索引，防止重复录入同周期同装备的收益数据，加速按维度查询 |
| `DATA_SYNC_CRON` | `0 */4 * * *` | 适配核心机型每4小时的实时数据更新需求，确保数据同步时效性 |
| `COLD_DATA_RETENTION_DAYS` | `180 天` | 符合航空装备运维数据的长期存档要求，将超过该周期的数据迁移至低成本存储 |
| `DATA_PARSE_MAPPING_RULES` | 按实测标定 | 适配多源异构的航空装备数据格式，需提前配置字段映射规则以兼容不同来源的数据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：执行`SELECT * FROM aircraft_revenue WHERE aircraft_id = 'B-XXXX' AND accounting_period = '2024Q2'`时，部分请求返回`Query execution timed out`错误，部分请求正常返回结果。原因：未配置联合唯一索引，并发查询量升高时触发全表扫描，导致部分请求超时。
- 现象：在工具调用节点执行数据库查询后，流程执行至该节点即停止，无报错日志返回。原因：未配置`DB_CONNECTION_TIMEOUT`参数或取值设置过短，高频写入时连接池耗尽，新请求无法获取数据库连接。
- 现象：导入航空装备的结构化运维日志数据时，部分字段为空或无法正确映射。原因：未配置`DATA_PARSE_MAPPING_RULES`，未将code类型的日志字段映射到数据库对应列。

## 怎么确认配好了
- 执行批量写入测试，核对写入条数与配置的`DB_BATCH_INSERT_SIZE`取值范围匹配。
- 发起多频次的联合查询，确认响应时间符合业务需求阈值，无超时现象。
- 检查数据库存储目录，确认超过配置阈值的历史数据已迁移至冷存储介质。
- 测试多源格式的数据导入，确认所有字段均能正确映射至数据库目标表。
