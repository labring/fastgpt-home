# 航空装备收益率的部署与升级

## 这个品类的数据长什么样
航空装备收益率相关数据来源包括军工行业公开披露的装备造价、年度维护定额、飞行时长统计、航材采购成本公示，以及部分运维平台的实时运行数据。核心运维数据按小时更新，年度成本与收益核算数据按季度更新。数据以结构化表格形式存储，包含装备型号、出厂成本、年均维护支出、年度飞行小时、单小时运营成本、单位飞行时长收益等字段，各字段对应单位分别为万元、万元/年、小时、元/小时、元/小时。

## 这些特征在「部署与升级」这一环带来什么约束
实时运维数据的小时级更新要求，需配置精准的定时拉取任务间隔，避免资源冗余或更新延迟。多字段结构化数据的存储与解析，需开启严格的字段校验规则，防止格式不匹配导致的解析失败。不同航空装备型号的字段差异，需配置动态字段适配逻辑，支持自定义字段映射。季度批量核算数据的处理，需预留足够的计算资源，避免任务超时。升级过程中需兼容旧版本的字段映射配置，防止历史数据导入异常。多数据源同步的场景下，需配置重试机制以应对临时网络波动，保障数据拉取成功率。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `SCHEDULE_INTERVAL` | `3600 秒` | 匹配航空装备实时运维数据的小时级更新节奏，避免更新间隔过长导致数据滞后，过短引发资源浪费 |
| `FIELD_VALIDATION_STRICT` | `开启` | 针对结构化字段多的特征，严格校验确保数据格式与预设字段一致，防止解析错误影响后续分析 |
| `DYNAMIC_FIELD_MAPPING` | `开启` | 适配不同航空装备型号的字段差异，支持自定义映射规则，覆盖多型号数据接入需求 |
| `BATCH_TASK_MEMORY_LIMIT` | `4096 MB` | 满足季度批量核算数据的处理资源需求，避免任务因内存不足超时中断 |
| `UPGRADE_COMPATIBILITY_MODE` | `v3 兼容模式` | 升级过程中保留旧版本字段映射配置，确保历史数据导入正常，减少升级后的适配成本 |
| `DATA_SOURCE_SYNC_RETRY` | `3 次` | 应对多数据源同步时的临时网络波动，保障数据拉取成功率，避免单次失败导致数据更新中断 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：Docker部署后前端页面持续转圈，无法加载内容。原因：未正确配置`NEXT_PUBLIC_API_BASE_URL`参数，导致前端无法连接后端服务地址。
- 现象：开源版知识库数量被限制为30个，无法新增更多。原因：未修改`MAX_KNOWLEDGE_BASE_COUNT`的默认配置值，未重新构建镜像或重启服务以生效新配置。
- 现象：实时运维数据拉取失败，日志显示`408 Request Timeout`错误。原因：`SCHEDULE_INTERVAL`配置过短，导致任务频繁触发占用系统资源，引发请求超时。

## 怎么确认配好了
- 执行定时任务测试脚本，核对拉取的实时数据与数据源的更新时间是否匹配，调整`SCHEDULE_INTERVAL`至符合业务节奏的取值。
- 导入不同型号的航空装备数据，校验字段解析是否完整，确认`FIELD_VALIDATION_STRICT`与`DYNAMIC_FIELD_MAPPING`的配置可适配多型号数据的字段差异。
- 提交批量核算任务，监控系统资源占用情况，调整`BATCH_TASK_MEMORY_LIMIT`至满足任务运行的合理取值。
- 重启服务后访问前端页面，确认页面加载正常，验证`NEXT_PUBLIC_API_BASE_URL`的配置正确性。
- 查看系统运行日志，确认多数据源同步任务的重试次数符合`DATA_SOURCE_SYNC_RETRY`的配置，无频繁失败记录。
