# 融资租赁收益率的多轮对话与提示词

## 这个品类的数据长什么样
融资租赁收益率日报的数据来自内部项目管理系统、租赁资产登记公示平台及第三方行业数据服务商。数据更新节奏为每日更新前一自然日的全量项目数据，按结构化表格形式存储。单条数据包含项目唯一标识、租赁物类别、起租时间、合同期限、年化收益率数值、剩余本金金额、还款周期等字段。金额单位为元，收益率以小数形式呈现，时间字段采用YYYY-MM-DD格式。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
数据的多源来源要求多轮对话需配置多源数据的召回优先级，确保优先调用内部项目的准确数据。每日更新的特性要求提示词强制指定使用当日生成的日报数据，禁止调用历史旧数据。结构化字段较多的特点要求提示词明确映射字段与用户问题的对应关系，避免模型混淆字段含义。多轮对话中用户可能反复切换筛选条件，需保留会话上下文直至用户明确修改，减少重复提问。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ------ | -------- | ------------ |
| `maxContext` | `前 1500–2000 字符` | 融资租赁项目数据单条记录字段较多，过长上下文会导致模型混淆，1500-2000字符可覆盖3-5个典型项目的完整数据，同时适配多数模型的上下文窗口限制。 |
| `recallTopK` | `前 8–12 条` | 日报数据包含大量项目条目，召回过多会增加模型推理负担，召回过少则无法覆盖用户关注的项目范围，8-12条可平衡召回精度与效率。 |
| `similarityThreshold` | `0.75–0.85` | 融资租赁项目的筛选条件多为精确匹配，阈值过低会召回无关项目，过高则可能遗漏符合条件的条目，该区间可兼顾精确性与召回率。 |
| `promptTemplate` | `固定前缀+用户问题+上下文数据` | 需明确指定使用当日生成的收益率日报数据，禁止调用历史数据，同时要求模型按项目维度整理结果，确保输出符合业务逻辑。 |
| `chatId` | `按用户会话生成唯一标识` | 需保留多轮对话的上下文，不同用户的会话需隔离，唯一标识可确保对话历史不被混淆，符合API调用的标准参数要求。 |
| `globalVariableLoadMode` | `按会话加载` | 用户可能在对话中切换不同的筛选条件，按会话加载可确保每个会话的全局变量独立生效，避免跨会话数据干扰。 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用API传入`chatId`参数后，后台对话日志未关联对应会话标识，多轮对话上下文丢失。原因：未在平台配置中开启会话ID绑定功能，或传入的`chatId`格式不符合平台要求。
- 现象：使用开源版V4.9.7的免登录链接时，用户删除本地对话后，后台留存的操作日志同步被清除。原因：未配置后台日志与用户会话的独立存储规则，将前端会话删除逻辑同步到了后台日志库。
- 现象：工作流节点无法在新对话中加载之前会话保存的全局变量。原因：全局变量加载模式未设置为按会话加载，默认按全局共享模式读取，导致新会话无法获取历史会话的变量数据。

## 怎么确认配好了
- 发起包含多轮筛选条件的对话，核对模型返回的结果是否符合之前指定的日期、租赁物类型等条件，确认上下文被正确保留。
- 调用API传入自定义`chatId`，查看后台日志是否显示该会话标识，确认参数生效。
- 测试免登录链接用户删除本地对话后，后台是否仍留存对应操作日志，确认存储规则配置正确。
- 在新会话中触发全局变量加载动作，核对是否能获取之前会话保存的变量数据，确认加载模式配置正确。
