# 计算机设备收益率的工作流编排

## 这个品类的数据长什么样
面向金融行业的计算机设备收益率行情数据来源于公开IT设备交易行情接口、企业内部资产管理台账、第三方硬件估值平台。数据更新节奏为每日一次，于凌晨完成前一日行情的汇总与更新。单条数据的文档结构包含设备唯一标识、采购时点成本、当前时点估值、持有时长、关联运维日志ID等字段。字段单位方面，采购成本与当前估值采用货币单位，持有时长采用自然日单位，收益率字段以标准化数值格式存储。

## 这些特征在「工作流编排」这一环带来什么约束
多数据源的接入需求要求工作流配置独立的鉴权节点，分别适配第三方行情接口与内部台账的鉴权规则。每日更新的特性要求工作流触发节点设置为定时触发，需避开接口访问峰值时段。设备唯一标识字段的存在要求配置去重规则，避免重复计算单台设备的收益率。持有时长字段的时间格式差异要求配置统一的格式转换规则，确保数据计算的准确性。跨字段的关联计算要求工作流支持节点间的参数传递，将拉取到的设备数据同步至后续的AI播报与知识库检索环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `TRIGGER_CRON_EXPRESSION` | `0 2 * * *` | 每日凌晨2点触发，避开多数行情接口的访问峰值，保障数据拉取稳定性 |
| `DATA_SOURCE_AUTH_CONFIG` | 配置IT设备行情接口API_KEY与企业资产管理系统账号密码 | 数据源包含第三方行情接口与内部台账，需分别配置对应鉴权信息 |
| `DUPLICATE_REMOVAL_FIELD` | `device_unique_id` | 数据包含设备唯一标识字段，以此为依据去重可避免重复计算单台设备收益率 |
| `AI_CHAT_PROMPT_TEMPLATE` | `基于以下设备数据生成标准化收益率日报：{{device_data}}` | 需将结构化的设备数据转换为自然语言播报内容，适配AI对话模块的输入要求 |
| `KNOWLEDGE_BASE_ID` | 按全局变量动态赋值 | 需根据不同业务场景切换对应行业知识库，避免硬编码导致的维护成本增加 |
| `RECALL_TOP_K` | `前2条` | 计算机设备行情数据的核心信息集中在前2条检索结果，过多召回会增加处理延迟 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工作流触发后返回HTTP 429状态码，无有效数据返回，原因是`TRIGGER_CRON_EXPRESSION`设置为高频触发，超出行情接口的调用频次限制。
- 现象为AI对话模块返回的内容不符合播报格式，原因是未正确配置`AI_CHAT_PROMPT_TEMPLATE`，未为结构化数据添加明确的解析指引。
- 现象为全局变量无法正确关联对应知识库，原因是未配置`GLOBAL_VAR_ASSIGN_RULE`参数，未指定知识库ID与业务场景的映射规则。

## 怎么确认配好了
- 手动触发工作流一次，检查拉取到的设备数据字段是否包含`device_unique_id`与收益率相关字段，核对字段格式是否符合预设要求。
- 查看工作流运行日志，确认触发时间与`TRIGGER_CRON_EXPRESSION`设置的定时任务一致，无高频触发的异常记录。
- 测试全局变量赋值逻辑，切换不同业务场景，确认`KNOWLEDGE_BASE_ID`参数自动更新为对应场景的知识库ID。
- 检查AI对话模块的输出结果，确认生成的日报内容符合预设的播报格式，无冗余或缺失的设备信息。
