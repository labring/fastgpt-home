# 计算机设备收益率的工具调用与插件

## 这个品类的数据长什么样
计算机设备收益率与行情数据，来源包括硬件厂商的设备性能监控API、金融交易系统的设备负载统计接口、第三方金融IT运维数据平台。更新节奏为每小时增量同步，每日凌晨生成全量日报文档。文档结构包含设备唯一标识、连续运行时长、单笔交易响应耗时、单日运维收益、异常运行时长字段。字段与单位：设备唯一标识为字符串格式，连续运行时长单位为小时，单笔交易响应耗时单位为毫秒，单日运维收益单位为元，异常运行时长单位为分钟。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据来源分散的特征，要求工具调用支持多API聚合配置，避免单次调用遗漏数据源。每小时增量更新的节奏，要求插件的定时触发间隔不超过1小时，且支持断点续传处理增量数据。每日全量日报的生成节点，要求工具调用模块可配置每日固定时间触发全量拉取任务。字段包含设备唯一标识、运维收益等，要求插件的参数映射需严格匹配字段名，避免因字段错位导致数据解析失败。单位包含毫秒、元等，要求工具调用时自动携带单位转换逻辑，确保下游展示的数值一致性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `pluginTriggerInterval` | `3600 秒` | 匹配数据每小时增量更新的节奏，确保及时拉取最新数据 |
| `apiRetryTimes` | `3 次` | 应对多API调用可能出现的临时网络波动，提升调用成功率 |
| `fieldMappingStrict` | `开启` | 严格匹配设备唯一标识、运维收益等字段名，避免数据解析错位 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 适配全量日报文档的大小上限，防止大文件上传失败 |
| `toolCallTimeout` | `600 秒` | 覆盖多API聚合调用的耗时需求，避免因超时终止任务 |
| `unitAutoConvert` | `开启` | 自动转换毫秒、元等单位，确保下游展示的数值格式统一 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用`apiCollection`接口时返回`Invalid URL`错误，状态码500。原因：未正确配置聚合数据源的完整URL路径，或URL包含非法字符导致解析失败。
- 现象：上传日报文档时触发`Multimodal file size is`类截断错误提示。原因：未调整`UPLOAD_FILE_MAX_SIZE`配置项，文档大小超出系统默认上限。
- 现象：工作流中工具调用模块的输出无法取消，强制展示在最终回复中。原因：未关闭`toolCallOutputVisible`配置项，默认开启了工具调用结果的直接展示。

## 怎么确认配好了
- 手动触发一次工具调用，检查返回的数据源是否包含全部配置的聚合接口数据，核对字段名与配置的映射规则一致。
- 查看定时任务日志，确认插件触发间隔符合配置的`pluginTriggerInterval`值，增量数据拉取频率匹配数据源更新节奏。
- 上传测试用的日报文档，确认上传成功且无文件大小相关报错，验证`UPLOAD_FILE_MAX_SIZE`配置生效。
- 关闭工具调用输出开关后，运行工作流，确认最终回复中未展示工具调用的原始结果。
