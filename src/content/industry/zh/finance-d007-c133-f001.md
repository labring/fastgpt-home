# 证券收益率的HTTP 接口与外部系统

## 这个品类的数据长什么样
证券收益率数据的数据源包括交易所官方行情接口、合规金融数据服务接口。更新节奏为交易日交易时段实时推送逐笔成交对应的收益率数据，收盘后生成当日全量汇总数据集。文档结构多为结构化JSON或CSV格式，包含证券代码、证券简称、统计周期、当日收益率、累计收益率等核心字段，字段单位为无量纲的收益率数值，部分接口会附带成交量、成交额等辅助统计字段。非交易日无有效行情数据，接口会返回空数据集或提示信息。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
实时逐笔数据的高频更新要求接口支持低延迟回调或高频轮询，避免数据延迟导致的信息滞后；收盘后全量汇总数据体积较大，接口需要支持分页查询或分市场拉取，避免单次请求超时。收益率字段为无量纲数值的要求，需要在接口参数中明确不返回百分比格式的字段，避免下游系统解析错误。交易日的区域性要求接口支持按交易所交易时段筛选查询，同时处理非交易日返回的空数据集。不同市场的证券代码规则存在差异，接口需要兼容A股、港股等不同编码格式的证券代码参数，避免格式校验失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `api_request_timeout` | `30 秒` | 证券全量数据接口的响应时间通常在10-25秒之间，30秒可覆盖绝大多数正常请求，避免过早超时 |
| `batch_query_max_count` | `200 条` | 单批次查询过多证券代码会导致接口返回体积过大，引发下游系统解析失败，200条为平衡效率与稳定性的合理区间 |
| `update_frequency` | `3 秒` | A股实时行情的更新频率为每3秒推送一次最新成交数据，3秒轮询可确保数据时效性 |
| `response_format` | `raw_json` | 证券收益率数据包含多维度结构化字段，raw_json格式可完整保留原始字段，避免格式转换丢失信息 |
| `api_auth_type` | `api_key_header` | 多数合规金融数据接口采用请求头携带API密钥的认证方式，可避免密钥在URL中泄露 |
| `non_trading_day_behavior` | `return_empty_array` | 非交易日无行情数据，返回空数组可让下游系统统一处理空数据集，避免异常报错 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用接口返回`400 Bad Request`错误，且日志显示`invalid security code format`。原因：未适配不同市场的证券代码规则，例如将A股代码传入港股接口，导致代码格式校验失败。
- 现象：接口返回的收益率字段为空，或数值与实际行情不符。原因：未设置正确的交易日筛选参数，请求了非交易日的行情数据，或轮询频率与数据源更新节奏不匹配，导致拉取到未更新的缓存数据。
- 现象：调用外部接口时返回`format mismatch`报错，且返回字段与预期结构不一致。原因：未正确配置`response_format`参数，导致接口返回的JSON结构与下游系统的解析规则不匹配。

## 怎么确认配好了
- 发起单次单只证券的查询请求，核对返回字段与配置的`response_format`参数一致，确认无格式转换错误。
- 按配置的`update_frequency`参数发起多轮轮询请求，核对返回的收益率数值随交易时段更新，确认更新节奏匹配。
- 传入非交易日的查询参数，核对返回结果符合`non_trading_day_behavior`的配置，确认非交易日处理逻辑正确。
- 发起批量查询请求，传入配置的`batch_query_max_count`上限数量的证券代码，核对接口返回完整且无超时错误，确认批量查询配置合理。
