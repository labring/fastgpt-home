# 证券收益率的数据库与运维

## 这个品类的数据长什么样
数据来源为交易所官方行情接口、合规第三方行情数据源，更新节奏随交易时段波动，交易时段内高频更新，盘后生成全量日度数据集。单条数据文档包含证券唯一标识代码、全称、交易日期、开盘价、收盘价、收益率指标、成交规模类字段。字段中收益率为标准化浮点值，价格类字段采用计价单位对应数值，成交规模字段包含原始成交笔数与金额数值。

## 这些特征在「数据库与运维」这一环带来什么约束
高频实时更新的行情数据会带来持续的写入压力，要求数据库集群具备高吞吐写入能力，适配突发的交易时段流量峰值。全量日度数据集的批量生成与同步，需配置高效的批量写入与增量数据校验逻辑，避免数据重复或丢失。收益率字段的高精度浮点存储需求，需匹配对应的数值类型参数，避免精度损耗影响后续计算。同时证券数据需满足合规留存要求，数据库需支持按周期归档历史数据并保留完整溯源链路，运维操作需避开交易时段以避免影响实时业务。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `DB_WRITE_BATCH_SIZE` | `50–200 条/批` | 适配证券高频数据的批量写入，平衡写入效率与事务开销 |
| `QUERY_TIMEOUT_SECONDS` | `30–60 秒` | 覆盖全量标的的长耗时查询，避免中途超时中断 |
| `FLOAT_PRECISION` | `10 位小数` | 匹配证券收益率的高精度存储需求，避免数值偏差 |
| `DATA_ARCHIVE_RETENTION_DAYS` | `365–730 天` | 满足证券数据合规留存的周期要求 |
| `CONNECTION_POOL_MAX_SIZE` | `20–50 个` | 适配交易时段的并发查询请求，避免连接耗尽 |
| `INCREMENTAL_SYNC_INTERVAL` | `10–30 秒` | 匹配证券实时行情的更新频率，保证数据时效性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：执行SQL查询时偶发执行失败，返回`504 Gateway Timeout`状态码。原因：未适配证券数据的流量峰值，连接池配置过小，交易时段并发请求耗尽连接导致超时。
- 现象：工具调用节点执行到数据库环节后无响应，流程中断。原因：未配置数据库连接超时参数，或超时阈值设置过短，长耗时的全量行情查询未完成即被终止。
- 现象：导入证券代码类型数据时出现格式报错，字段无法正常存储。原因：未使用匹配的字符串类型字段存储证券代码，误用数值类型导致前导零丢失。

## 怎么确认配好了
- 执行单次全量标的查询，核对返回字段的精度与原始数据源一致，根据业务要求调整对应参数。
- 在交易时段模拟并发请求，监控数据库连接池使用率，根据峰值情况调整连接池配置参数。
- 触发增量同步任务，核对同步间隔与行情更新频率匹配，根据数据时效性要求调整同步间隔参数。
- 检查数据库归档链路，确认历史数据按配置周期自动归档，根据合规要求调整留存周期参数。
