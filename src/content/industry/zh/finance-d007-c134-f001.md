# 调味品收益率的HTTP 接口与外部系统

## 这个品类的数据长什么样
调味品收益率数据主要来自国内食品饮料行业监测数据库、线下零售终端采样系统及品牌方公开经营数据。更新节奏为核心SKU每日更新前一日的收益率数据，小众SKU每3日更新一次。数据文档采用标准JSON格式，单条数据包含`sku_id`（6位数字字符串）、`product_name`（产品名称字符串）、`report_date`（ISO格式日期）、`benchmark_return`（相对基准的变动浮点数）、`update_time`（ISO格式时间戳）。字段单位中，`benchmark_return`采用相对基准的变动幅度数值，无百分比标注。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
调味品品类的数据特征会对HTTP接口调用带来多重约束。多源数据拼接需求要求接口支持并行调用多个数据源接口，合并后统一返回标准化结果。每日固定时段更新的特性，需要配置定时拉取的时间区间，避开数据同步高峰以避免返回延迟或空值数据。字段包含`sku_id`、`product_name`等精准标识，接口请求需支持按`sku_id`进行参数过滤，返回结果需保留指定核心字段。部分小众SKU更新频率较低，需要配置字段缺失时的默认填充规则，避免下游系统解析失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `request_timeout` | `300 秒` | 调味品数据源接口的响应延迟通常在120-200秒，预留足够缓冲时间避免超时中断 |
| `retry_times` | `2 次` | 部分小众SKU数据源偶尔会出现临时连接失败，重试可降低数据丢失概率 |
| `response_parse_mode` | `json_object` | 数据源返回格式为标准JSON，需直接解析为结构化数据供下游系统使用 |
| `filter_params` | `["sku_id", "report_date", "benchmark_return"]` | 下游系统仅需核心业务字段，过滤冗余字段可提升传输效率 |
| `schedule_cron` | `0 8 * * *` | 数据每日早8点完成更新，定时拉取可获取最新的完整数据集 |
| `default_fill_value` | `null` | 小众SKU数据更新频率较低，空值标记可提示下游系统处理缺失情况 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用HTTP接口后返回结果无法匹配预期的结构化格式，界面无强制JSON解析的配置选项。原因：未将`response_parse_mode`配置为`json_object`，系统默认采用文本解析模式。
- 现象：调用本地部署的数据源接口时返回`{"error": "connection refused"}`状态码。原因：未配置接口的访问白名单，或本地接口未开放跨域访问权限，FastGPT服务无法直接访问本地网络资源。
- 现象：尝试通过HTTP接口传递或返回二进制文件时，接口调用失败。原因：FastGPT的HTTP工具默认不支持二进制文件作为入参或返回值，需额外配置对应请求头或中转接口。

## 怎么确认配好了
- 手动触发一次HTTP调用，查看返回结果的字段是否包含配置的`filter_params`列表中的内容。
- 检查定时任务的执行日志，确认在数据更新时段后是否成功拉取到非空数据集。
- 模拟字段缺失的场景，确认系统是否按照配置的`default_fill_value`进行填充处理。
- 断开数据源连接后再次调用接口，确认是否按配置的`retry_times`执行重试操作。
