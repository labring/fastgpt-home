# 调味品收益率的部署与升级

## 这个品类的数据长什么样
面向金融理财场景的调味品收益率与行情日报数据主要来自线下商超POS采集数据、品牌方官方经营披露、第三方行业监测平台。更新节奏为每日更新一次，当日数据于次日凌晨完成同步。单份数据文档包含监测品类名称、包装规格、当日终端售价、上期基准售价、收益率变动幅度、数据采集渠道、更新时间戳等字段。单位方面，售价以元/千克或元/500克为基准，收益率变动幅度以相对上期的百分比变动为表述单位，字段均为文本或数值格式。

## 这些特征在「部署与升级」这一环带来什么约束
每日更新的数据源要求部署时配置固定频率的定时同步任务，避免数据延迟或重复拉取。多源数据采集的场景要求配置多源校验逻辑，确保不同渠道数据的一致性。包装规格字段的多样性要求解析环节适配不同规格的匹配规则，避免品类识别偏差。收益率计算依赖历史基准数据，因此需要配置合理的历史数据存储周期，确保计算逻辑可追溯。同时，数据文档的字段标准化程度较高，部署时提前定义字段映射规则可减少后续解析的适配成本。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 调味品数据多为结构化表格，解析耗时较短，300秒可覆盖多源校验的额外耗时 |
| `SYNC_DATA_INTERVAL` | `86400 秒` | 匹配数据源每日更新的节奏，避免数据延迟或重复拉取 |
| `MULTI_SOURCE_VALIDATION_THRESHOLD` | `0.85` | 多源数据一致性校验的合理阈值，避免误判正常的渠道数据差异 |
| `FIELD_MAPPING_RULES` | 按预设结构化字段模板配置 | 调味品数据字段标准化程度较高，预设模板可减少自定义配置成本 |
| `HISTORY_DATA_STORAGE_DAYS` | `30 天` | 支撑收益率计算所需的历史基准数据，同时控制存储资源占用 |
| `UPLOAD_FILE_MAX_SIZE` | `100 MB` | 适配批量导入调味品数据文档的合理上限，避免上传超时 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：本地部署版本上传调味品数据文档后，解析节点返回空结果，无明确报错日志。原因：未配置`FIELD_MAPPING_RULES`，无法识别调味品特有的包装规格字段，导致有效数据被跳过。
- 现象：构建部署镜像时出现依赖冲突报错，错误码`E4001`。原因：未指定适配结构化表格解析的依赖包版本，导致调味品数据的字段提取模块加载失败。
- 现象：定时同步任务执行后，收益率计算结果为空，字段`yield_rate`显示为`null`。原因：未配置`HISTORY_DATA_STORAGE_DAYS`，无法获取历史基准数据完成收益率计算逻辑。

## 怎么确认配好了
- 手动上传一份测试用调味品数据文档，核对解析后的字段是否包含预设的品类名称、包装规格等内容。
- 查看定时同步任务的执行日志，确认每日凌晨的同步动作是否正常触发，无超时或失败记录。
- 运行一次收益率计算任务，核对`yield_rate`字段是否生成有效数值，无空值或异常标记。
- 检查多源校验模块的日志，确认不同渠道的调味品数据是否被正常匹配，无大量校验失败记录。
