# 贵金属收益率的HTTP 接口与外部系统

## 这个品类的数据长什么样
贵金属行情数据主要来自全球权威贵金属交易市场的公开接口，包括伦敦金银市场协会、上海黄金交易所等机构。数据随交易时段实时更新，非交易时段按固定周期同步。标准返回格式为JSON数组，每个元素对应单一贵金属品种，包含`symbol`（品种代码）、`bid`（买入报价）、`ask`（卖出报价）、`fixing_time`（官方定盘时间）等字段。报价单位通常为美元/盎司或人民币/克，定盘价仅在每日固定时段推送。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
贵金属数据源多跨时区部署，需处理时区转换适配国内业务场景；不同交易市场的字段命名、单位存在差异，需统一映射规则避免数据解析异常。实时行情的更新频率随交易时段波动，需配置动态调整的请求间隔，避免频繁请求触发限流。同时，权威数据源多要求签名认证，需在接口请求中携带合规的身份验证参数，保障数据获取权限。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `request_interval` | 30–60 秒（交易时段）、3600 秒（非交易时段） | 适配贵金属行情更新频率，避免频繁请求触发限流，同时保证数据时效性 |
| `auth_sign_type` | `HMAC-SHA256` | 多数权威贵金属数据源采用该签名方式保障接口安全 |
| `field_mapping` | 按目标品种预设映射表（如XAUUSD→黄金现货） | 统一不同数据源的字段命名差异，适配系统内部数据格式 |
| `timezone_convert` | 转换为 UTC+8 时区 | 适配国内业务场景的时间展示需求 |
| `retry_threshold` | 3 次重试，间隔 5 秒 | 应对临时网络波动或接口短暂不可用，避免重复请求过多触发风控 |
| `unit_convert_rule` | 按目标场景转换（如美元/盎司转人民币/克） | 统一数据单位，降低外部系统接入成本 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用接口返回`502 Bad Gateway`状态码。原因：未适配贵金属数据源的跨区访问限制，未配置代理或正确的请求头，导致中间网关转发失败。
- 现象：同步后字段为空或格式异常。原因：未配置`field_mapping`参数，直接使用原始数据源字段，未处理不同品种的字段差异，导致内部系统无法识别。
- 现象：定时任务频繁触发导致接口限流。原因：未按交易时段和非交易时段调整`request_interval`取值，非交易时段仍使用短间隔请求，超出数据源调用限额。

## 怎么确认配好了
- 调用测试接口，返回的JSON数据包含预设的`symbol`、`bid`、`ask`字段，且单位符合配置的转换规则。
- 查看定时任务日志，确认交易时段内请求间隔符合`request_interval`设置，非交易时段请求间隔自动调整。
- 模拟网络波动场景，确认触发`retry_threshold`后自动重试，最终成功获取数据且无重复请求。
- 对比官方数据源的定盘价，确认同步后的`fixing_time`字段时区转换正确，数值匹配。
