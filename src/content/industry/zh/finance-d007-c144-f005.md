# 通信服务收益率的多轮对话与提示词

## 这个品类的数据长什么样
通信服务品类的行情与收益率数据来源为公开证券行情接口、行业运营报送接口。更新节奏为交易日每10分钟刷新一次实时点位与异动数据，非交易日每日更新全量行业日报文档。文档为结构化格式，包含行业基准标识、当日基准值、成分股异动项、资金流入流出规模等字段，字段单位分别为点、万元等。数据维度覆盖当日行情汇总、成分股表现、行业资金流向三类核心信息，无冗余非结构化内容，可直接用于对话场景的信息提取。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
通信服务数据的高时效性要求对话上下文需限制有效周期，避免旧数据干扰当前查询结果。结构化的字段特征要求提示词需明确指定字段提取规则，防止混淆其他行业的品类数据。多轮对话中需明确引导用户指定查询的交易日，避免跨周期数据混叠。同时，日报文档的批量加载需求要求对话流程需按轮次关联对应时间段的解析文档，防止上下文过载。此外，实时数据的更新频率要求系统需定期刷新召回的知识库文档，确保对话使用的信息为最新状态，避免提供过时的行情数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `2000–3000 字符` | 通信服务行情数据时效性强，过长上下文会引入旧数据干扰，限制上下文长度可确保对话仅关联最近的有效行情信息。 |
| `PARSE_FILE_CHUNK_SIZE` | `800–1200 字符` | 通信服务日报文档包含结构化字段与明细数据，该分段长度可保留字段完整性，避免拆分后丢失关联信息。 |
| `RECALL_TOP_K` | `前 4–6 条` | 行情数据字段集中，过多召回结果会导致提示词过载，限定召回条数可聚焦有效信息。 |
| `SIMILARITY_THRESHOLD` | `0.75–0.85` | 区分通信服务与其他行业的行情数据，避免召回非目标品类的文档。 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 10M级别的通信服务日报文档包含多份明细数据，延长超时时间可确保完整解析。 |
| `SYSTEM_PROMPT_TEMPLATE` | `固定指定通信服务品类、限定查询周期、明确字段提取规则` | 匹配通信服务数据的结构化特征，避免混淆其他行业的行情信息。 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 对话界面的思考过程显示连续竖线分隔符，无法隐藏。原因是未在系统提示词中配置禁用中间思考步骤的格式化输出，默认保留了调试用的分隔符。
- 调用知识库关联接口时返回空结果。原因是未在请求参数中指定目标知识库的`kbId`字段，或召回阈值设置过高导致无匹配文档。
- 10M级别的Word文档解析耗时过长。原因是未调整`PARSE_FILE_CHUNK_SIZE`参数为合理分段长度，且未开启并行解析配置，导致单段解析占用过多资源。

## 怎么确认配好了
- 发起包含通信服务行情关键词的查询，核对返回结果仅包含通信服务品类的信息，无其他行业数据。
- 上传10M级别的通信服务日报文档，查看解析进度在合理时间内完成，无超时报错。
- 调用对话接口时，检查返回结果中包含`context`字段的有效召回文档，且数量符合配置的召回条数范围。
- 观察对话界面的输出格式，无多余的竖线分隔符，输出内容符合预设的字段提取规则。
