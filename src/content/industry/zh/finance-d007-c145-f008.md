# 通信设备收益率的工具调用与插件

## 这个品类的数据长什么样
通信设备收益率与行情数据的来源包括厂商运维收益台账、公开通信行业板块行情接口、第三方行业数据服务商的监测数据集。更新节奏分为两类：实时行情数据每15分钟推送一次，单日收益率日报数据集于每日固定时段完成更新。文档采用结构化格式，分为批量数据文件与单条设备详情接口，批量文件按部署区域与设备型号分组。字段包含`device_serial`（设备唯一序列号，字符串类型）、`daily_return_amount`（单日收益差额，单位为元）、`market_correlation`（与板块行情的关联系数，浮点数）、`deployment_region`（部署区域，字符串类型）。

## 这些特征在「工具调用与插件」这一环带来什么约束
实时行情数据每15分钟更新一次，要求工具调用的间隔不得超过该周期，否则将获取过期数据。单日收益率日报每日固定时段更新，插件的定时任务需设置为该时段后执行，确保拉取到完整当日数据。结构化文档按部署区域与设备型号分组，插件需支持按`deployment_region`或`device_serial`作为查询参数进行过滤。关联系数字段为浮点数类型，插件的参数解析需支持浮点数接收与校验，避免默认按整数处理导致的数据异常。不同数据源的字段命名存在差异，插件需配置字段映射规则以兼容多源数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `tool_call_interval` | `600 秒` | 通信设备行情数据每15分钟更新，设置10分钟的调用间隔可保证获取最新数据且避免频繁请求 |
| `plugin_schedule_cron` | `0 30 0 * * *` | 单日收益率日报于每日凌晨0点更新，设置该cron表达式可在半小时后拉取完整当日数据 |
| `tool_request_timeout` | `30 秒` | 通信行业数据源的响应速度通常在10-20秒，设置30秒的超时时间可避免正常请求被误判为超时失败 |
| `tool_param_filter_fields` | `["device_serial", "deployment_region"]` | 通信设备数据按设备序列号与部署区域分组，需支持按这两个字段过滤查询 |
| `max_batch_tool_requests` | `50` | 单次批量请求数据量过大可能触发接口限流，50条的批量规模可平衡查询效率与稳定性 |
| `plugin_schema_import_mode` | `auto_match` | 不同数据源的字段命名存在差异，自动匹配模式可减少手动映射的工作量 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：打开插件管理页面后无法找到自定义插件的导入选项，界面未展示上传入口。原因：使用的FastGPT版本低于4.8.17，该版本之前的插件导入路径存在调整。
- 现象：调用工具时，用户提问中的设备型号未被正确提取到`q`参数中，工具返回的结果与指定设备无关。原因：未配置工具调用的参数提取规则，未将用户查询中的设备序列号映射到`q`参数。
- 现象：批量调用工具时返回的结果条数不足预期，部分设备的收益率数据未被获取。原因：未调整`max_batch_tool_requests`的配置值，默认批量数量小于需要查询的设备总数。

## 怎么确认配好了
- 手动触发一次工具调用，核对返回结果的字段与配置的映射规则是否一致，确认包含指定设备的收益率数据。
- 查看工具调用日志，确认未出现频繁的请求限流报错，验证`tool_call_interval`的设置符合数据源的更新频率。
- 检查定时任务执行日志，确认每日凌晨的插件任务按时触发并完成数据拉取。
- 测试修改参数过滤字段，验证工具调用仅返回符合指定部署区域或设备序列号的结果。
