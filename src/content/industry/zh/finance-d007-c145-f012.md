# 通信设备收益率的模型接入与配置

## 这个品类的数据长什么样
通信设备的收益率相关数据常用于金融行业的行情日报播报，数据来源于设备内置的运行数据采集模块、运营商业务支撑系统的计费接口，以及第三方通信行业运维数据平台。更新节奏为每10分钟推送一次增量数据，每日凌晨生成当日全量汇总文档。单条明细数据的文档结构为结构化JSON格式，包含`device_sn`（设备序列号，字符串类型）、`collect_time`（采集时间，ISO 8601格式字符串）、`daily_revenue`（当日累计收益贡献，单位：元）、`hourly_gain`（小时级收益增量，单位：元/小时）、`uptime_duration`（设备在线时长，单位：分钟）。全量汇总文档则按设备分组，包含当日所有采集周期的收益数据汇总值。

## 这些特征在「模型接入与配置」这一环带来什么约束
通信设备的多源高频数据特性，要求模型接入环节配置批量拉取的定时任务，避免单条请求超出超时限制，确保日报播报的实时性。字段包含设备序列号、时间戳及多维度收益指标，需要明确指定字段映射规则，确保模型仅使用收益相关字段进行计算，避免非目标字段干扰日报的准确性。每日凌晨生成的全量汇总文档，需要配置定时触发的全量同步任务，覆盖前一日全量数据，确保日报播报的完整性。设备采集时间存在小幅偏移，需要配置时间窗口参数，合并同时间段的增量数据，避免重复计算或数据遗漏影响日报精度。不同数据来源的单位存在差异，需要配置统一的单位转换规则，确保收益指标的计算一致性，提升日报的可读性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `batch_fetch_interval` | `600 秒` | 匹配通信设备每10分钟的增量数据推送节奏，避免请求过于频繁或遗漏数据 |
| `field_mapping` | `{"daily_revenue":"revenue_contribution", "device_sn":"device_id"}` | 匹配通信设备数据的字段命名规则，确保模型正确识别收益相关字段 |
| `full_sync_cron` | `0 2 * * *` | 匹配每日凌晨2点生成全量汇总文档的时间，触发前一日全量数据同步 |
| `time_window_offset` | `±300 秒` | 抵消设备采集时间的小幅偏移，合并同时间段的增量数据 |
| `max_batch_size` | `500` | 适配通信设备批量数据的规模，避免单次请求超出接口限制 |
| `request_timeout` | `30 秒` | 适配高频数据拉取的响应速度，避免因网络延迟导致任务失败 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为调用模型时返回`400 Bad Request`，提示“invalid function call format”。原因是未正确配置通信设备数据的字段映射规则，导致模型无法识别收益相关字段的格式。
- 现象为批量拉取数据时频繁触发超时错误，日志中显示`ETIMEDOUT`。原因是未根据通信设备的批量数据规模调整`max_batch_size`参数，单次请求数据量过大超出接口限制。
- 现象为使用ollama部署的模型时，无法触发function call，返回`null`的工具调用结果。原因是未在模型接入配置中开启`enable_function_call`参数，且未正确配置代理地址，导致工具调用请求无法正常转发。

## 怎么确认配好了
- 查看数据同步任务的运行日志，确认增量拉取任务的执行频率与配置的`batch_fetch_interval`一致，无失败记录。
- 手动触发一次全量同步任务，核对拉取到的字段与配置的`field_mapping`规则匹配，无字段缺失或映射错误。
- 发起单设备的模型调用请求，验证模型能够正确处理该设备的收益数据，生成符合预期的输出。
- 检查模型接入的代理配置，确认请求能够正常到达目标模型服务，无连接异常或权限报错。
