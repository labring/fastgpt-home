# 通信设备收益率的部署与升级

## 这个品类的数据长什么样
通信设备的收益率与行情日报数据主要服务于金融理财场景，来源包括运营商运营支撑系统、基站性能采集终端，更新节奏为每日凌晨批量生成前一日的全量数据。单设备的日报文档包含设备唯一标识、当日总营收、单位流量营收、异常运维时长、核心指标波动幅度等内容，字段包括`device_serial`、`daily_total_revenue`、`per_gigabyte_revenue`、`anomaly_duration_hours`，其中`daily_total_revenue`单位为人民币元，`per_gigabyte_revenue`单位为元/GB，`anomaly_duration_hours`单位为小时。单份批量汇总文档的体积随接入设备数量增长，通常单批次导入数据可达数百MB级别。

## 这些特征在「部署与升级」这一环带来什么约束
多源数据接入的需求要求部署阶段需配置多接口对接的超时与重试规则，避免因第三方系统响应延迟导致数据导入中断。每日固定时段的批量更新需求，要求部署时需匹配数据生成节奏配置定时任务，避免与其他系统的批量任务抢占系统资源。字段的定制化特征要求升级阶段需兼容新增的运维指标字段，避免原有解析规则失效。数据体积较大的特性要求部署时需配置适配的向量库存储与分片策略，保障检索与写入的并发性能。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `schedule_cron` | `0 2 0 * * ?` | 通信设备日报的生成通常在凌晨0点前完成，延后2分钟触发可避免读取未完全生成的数据源 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 单份批量汇总文档包含数百条设备数据，解析耗时较长，避免因超时中断导入流程 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 批量导入的全量设备日报数据体积较大，适配多批次导入的需求 |
| `field_mapping_rule` | 按实测标定 | 不同运营商的设备日报字段命名存在差异，需匹配自有系统的字段标识完成映射 |
| `vector_db_shard_count` | `8 分片` | 通信设备的总数据量较大，分片存储可提升检索与写入的并发性能 |
| `similarity_threshold` | `0.75` | 过滤低相关的设备营收数据，提升检索结果的匹配精度 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用文档解析接口时返回`Cannot read properties of undefined (reading 'daily_total_revenue')`。原因：未配置`field_mapping_rule`，系统无法识别设备日报文档中的营收字段，尝试读取未定义的字段值。
- 现象：升级到4.9.0版本后，原有的分享链接鉴权配置无法生效。原因：未查阅版本变更说明，该版本调整了分享鉴权的参数配置逻辑，原有配置未同步更新。
- 现象：批量导入设备日报数据后，检索返回的有效结果条数远低于预期。原因：未调整`similarity_threshold`的取值，过高的阈值过滤了大量符合要求的设备营收数据。

## 怎么确认配好了
- 手动触发一次配置的定时任务，查看系统日志中是否存在字段读取失败或解析超时的报错。
- 导入一份测试用的设备日报文档，检查知识库中提取的字段是否与预期的业务标识一致。
- 发起针对特定设备营收的检索请求，核对返回的结果条数是否符合配置的召回规则。
- 登录向量库管理界面，确认存储分片的数量与配置的`vector_db_shard_count`取值一致。
