# 钢铁贸易收益率的HTTP 接口与外部系统

## 这个品类的数据长什么样
钢铁贸易收益率相关数据来源于国内大宗商品现货交易的公开行业数据源，更新节奏为每日固定时段更新前一交易日的全量数据集。数据文档为结构化JSON数组格式，每个条目包含交易品种代码、品种名称、当日成交均价、上游原料成本均价、当日进销毛利额、统计覆盖的贸易区域范围。其中成交均价、成本均价的单位为元/吨，毛利额的单位为元/吨，区域字段按国内主要钢材贸易集散地划分。数据不包含实时行情，仅支持按自然日回溯获取历史统计结果。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
由于数据为每日全量更新的历史统计结果，接口无需支持实时增量拉取，适合配置定时批量拉取任务，仅需按固定时段调用即可。由于数据包含多品种、多区域的细分字段，接口需支持按品种代码、贸易区域进行筛选的参数，以缩小返回数据的范围。由于数据单位统一为元/吨，接口返回的数值字段无需额外转换，但需校验数值的合法性。同时，全量数据的单次返回量较大，接口需支持分页或按批次拉取的参数，避免请求负载过高。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `external_api_request_timeout` | `600 秒` | 钢铁贸易品类的全量数据拉取包含多品种多区域内容，接口响应耗时较长，需匹配最大拉取耗时 |
| `external_api_batch_size` | `50 条/请求` | 单请求返回数据量过大易触发超时，按品类的常规品种数量拆分请求，平衡负载与效率 |
| `api_rate_limit_quota` | `10 次/小时` | 数据每日仅更新1次，该配额可覆盖定时拉取需求，同时避免触发外部数据源的限流规则 |
| `external_api_response_schema_check` | `启用` | 钢铁贸易数据包含固定格式的字段，启用校验可过滤格式异常的返回结果，避免后续流程出错 |
| `cache_expire_time` | `22 小时` | 略短于数据更新周期，确保每次拉取都能获取最新的当日统计数据 |
| `api_error_retry_max_times` | `3 次` | 该配置为V4.9.7版本新增的重试控制项，外部数据源可能出现临时波动，有限重试可降低拉取失败概率，同时避免重复请求占用资源 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：接口返回429 Too Many Requests状态码，或返回“请求频率超限”的报错文案。原因：未根据数据更新频率配置合理的调用配额，高频发起拉取请求触发外部数据源的限流规则。
- 现象：拉取的数据中`进销毛利额`字段为空或格式异常。原因：未启用`external_api_response_schema_check`配置，未校验返回字段的合法性，导致错误数据流入后续处理流程。
- 现象：连续多日拉取到相同的旧数据，未获取当日更新的最新行情。原因：缓存时长设置超过24小时，未匹配数据每日更新的周期，导致缓存未及时刷新。

## 怎么确认配好了
- 发起单次拉取请求，检查返回的字段是否包含预设的交易品种、成交均价、贸易区域等信息，核对字段单位是否符合品类要求。
- 配置定时拉取任务，等待一个数据更新周期后，对比两次拉取的结果，确认数据已完成更新。
- 发起3次以上并发请求，检查是否触发限流报错，确认调用配额符合实际使用需求。
- 查看系统日志，确认接口请求在临时失败时自动触发重试逻辑，无手动干预的必要。
