# 钢铁贸易收益率的工作流编排

## 这个品类的数据长什么样
钢铁贸易的收益率数据来源涵盖国内钢铁现货交易平台的每日报价、钢厂出厂价公告、贸易企业内部进销存台账、银行融资利率公示。更新节奏为：现货报价每工作日更新1-2次，出厂价随生产计划不定期调整，台账数据每日结算后更新，融资利率按季度调整。数据以结构化JSON数组或CSV格式返回，每个条目包含贸易品类编码、品名、规格型号、进货单价、出货单价、运输成本、仓储成本、融资利息分摊额、当日成交量。字段单位默认采用元/吨（单价、成本）、吨（成交量），部分第三方平台报价单位为元/千克，需完成格式转换。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且更新节奏不一致，要求工作流需支持多数据源拉取，并按数据更新频率分阶段触发任务，避免全量重复执行低频环节。不同数据源的字段单位存在差异，需在工作流中加入统一转换环节，否则会导致进销差价计算错误。钢铁贸易品类繁多且成本构成存在差异，工作流需按品类设置分支条件，优先处理高频交易品类以提升执行效率。此外，贸易数据涉及企业内部台账，需在工作流中加入数据校验环节，拦截缺失值、异常值等无效数据，保障收益率计算的准确性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `workflow_trigger_mode` | 按数据更新事件触发+每日定时补全 | 现货报价实时更新需事件触发，融资利率等低频数据每日定时补全即可覆盖需求 |
| `data_source_merge_strategy` | 按品名+规格作为联合主键合并 | 不同数据源的条目需通过唯一标识对齐，避免重复计算同一品类的收益率 |
| `unit_conversion_factor` | 1000 | 多数第三方平台报价单位为元/千克，乘以该系数可转换为贸易常用的元/吨单位 |
| `branch_condition_max_count` | 前20个高频品类 | 钢铁贸易品类较多，优先处理占比最高的品类可提升工作流整体执行效率 |
| `workflow_debug_timeout` | 600秒 | 多数据源拉取和多分支计算的总耗时通常在10分钟以内，预留足够调试时间 |
| `global_variable_persist_strategy` | 按工作流实例持久化 | 每个贸易批次的收益率计算需独立使用全局变量，避免批次间数据污染 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：在版本4.9.13及以上的环境中运行工作流时，弹出「Dangerous behavior」报错，日志中显示截断的错误信息。原因：未在工作流的安全设置中配置允许访问的外部数据源白名单，直接调用钢铁现货平台的API触发了安全校验拦截。
- 现象：点击数据面板的按钮后，获取的全局变量为空值。原因：未将全局变量的持久化策略设置为按工作流实例保存，导致变量在工作流节点切换时被重置。
- 现象：工作流生成的收益率计算结果偏差较大。原因：未配置单位转换规则，直接使用第三方平台的元/千克报价计算进销差价，导致单位未统一。

## 怎么确认配好了
- 运行单品类的测试工作流，核对拉取的数据源字段是否覆盖进货单价、出货单价、各类成本项。
- 点击工作流调试界面的数据面板按钮，确认能获取到当前实例已赋值的全局变量。
- 模拟缺失报价、单位错误等异常数据，检查工作流是否触发预设的校验环节并返回明确提示。
- 导出工作流的配置文件，确认所有配置项的取值与预设方案匹配。
