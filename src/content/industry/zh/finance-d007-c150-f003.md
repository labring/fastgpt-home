# 铁矿石收益率的分享与嵌入

## 这个品类的数据长什么样
铁矿石的行情与收益率数据来源为大宗商品期货交易所，更新节奏为交易日交易时段内每数秒刷新盘口数据，每日开盘前发布前一交易日的结算数据。数据文档包含合约代码、交割月份、最新成交价、结算价、涨跌额、持仓量、成交量等基础字段，部分衍生字段如基差、远期升贴水需基于基础字段计算生成，所有价格类字段的单位统一为元/吨，无百分比类的相对收益直接展示字段。

## 这些特征在「分享与嵌入」这一环带来什么约束
铁矿石品类的实时盘口数据更新频率较高，要求嵌入页面无法使用过长的缓存周期，否则会导致展示数据滞后于市场行情。多合约、多字段的文档结构，要求分享链接需支持传递合约代码、展示字段等自定义参数，否则会出现信息过载或无关数据展示的问题。价格类字段统一为元/吨的特性，要求嵌入配置中需固定显示单位，避免因自动转换导致的单位混乱。同时，大宗商品数据的专业性较强，分享页面需保留参数筛选入口，方便用户调整查看的合约与字段，适配不同的业务场景。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `embed_language` | `en`（针对海外嵌入场景） | 满足嵌入网页统一语言的需求，覆盖非中文用户的查看习惯 |
| `share_expire_time` | `7200 秒` | 铁矿石行情数据时效性强，过长的过期时间会导致展示数据滞后，2小时的时长兼顾安全性与实时性 |
| `embed_show_custom_vars` | `true` | 需要传递合约代码、交割月份等自定义参数，确保分享页面加载对应品类的精准行情数据 |
| `embed_cache_ttl` | `30 秒` | 铁矿石盘口数据每数秒更新，30秒缓存平衡了加载速度与数据新鲜度 |
| `share_chat_id_persistence` | `true` | 保持同一会话的上下文，支持多次发送信息，符合用户的连续查询需求 |
| `embed_enable_voice_input` | `按场景开启` | 按需开启可减少不必要的网络资源占用，避免因非必要功能导致的语音输入延迟问题 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：免登录分享页面无法保留历史会话上下文，多次发送查询后之前的对话内容丢失。原因：未开启`share_chat_id_persistence`配置，会话ID未持久化存储，每次访问均生成新会话。
- 现象：嵌入页面的部分控件、提示文字未统一为预设语言，仍显示默认中文。原因：未正确设置`embed_language`参数，或参数值拼写错误，导致配置未生效。
- 现象：免登录页面的语音输入时长显示为00:00，长按输入后无响应或发送失败。原因：`embed_enable_voice_input`配置未适配网络带宽，或浏览器的麦克风权限未正确授予，导致音频流上传失败。

## 怎么确认配好了
- 打开生成的嵌入链接或分享页面，检查页面的控件、提示文字是否符合预设的语言配置，确认所有文本均为目标语言。
- 向对话窗口发送与铁矿石行情相关的查询，等待30秒后再次发送同品类的其他查询，检查历史对话内容是否保留，确认会话上下文正常。
- 刷新嵌入页面，检查展示的行情数据是否更新至最新状态，确认缓存配置生效且数据新鲜度符合要求。
- 测试语音输入功能，长按输入控件确认时长正常递增，发送后检查音频是否成功上传并触发查询，确认浏览器权限已正确授予。
