# 铁矿石收益率的对话日志与审计

## 这个品类的数据长什么样
铁矿石行情数据主要来源于国内大宗商品期货交易所的铁矿石期货合约交易数据，更新节奏为每个交易日收盘后1小时内完成当日全量数据更新，非交易日无新增数据。数据文档为结构化的单品种日报表，包含合约代码、品种名称、当日结算价格、当日成交均价、当日成交量、持仓总量、基准期价格等字段。其中，价格类字段单位为元/吨，成交量与持仓量单位为交易手数。

## 这些特征在「对话日志与审计」这一环带来什么约束
铁矿石数据的交易日更新节奏，要求对话日志必须精准匹配交易日维度，审计时需过滤非交易日的无效调用。结构化的单品种日报表结构，要求日志中需完整记录请求的合约代码、数据维度等参数，避免跨品种数据混淆。固定的单位规则要求审计环节需校验返回数据的单位一致性，防止单位转换错误导致的日志异常。此外，收盘后1小时的更新窗口，要求对话日志需记录数据请求的时间戳，用于核对请求是否在数据更新完成后发起，避免获取未更新的旧数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `AUDIT_LOG_RETENTION_DAYS` | `90 天` | 大宗商品行业审计合规要求需保留至少90天的对话与调用日志，匹配铁矿石期货交易的监管审计周期 |
| `LOG_RECORD_REQUEST_PARAMS` | `开启，记录合约代码、请求时间戳、数据类型` | 铁矿石数据需按合约与时间维度溯源，确保审计时可精准匹配对应行情数据 |
| `LOG_RESPONSE_FIELD_VALIDATION` | `开启，校验元/吨、手数单位一致性` | 铁矿石数据的固定单位要求，防止日志中出现单位异常导致审计失败 |
| `DATA_REQUEST_TIMEOUT` | `30 秒` | 铁矿石行情数据更新窗口为1小时内，超时重试可避免因数据未同步导致的请求失败日志 |
| `LOG_FILTER_NON_TRADING_DAY` | `开启，过滤非交易日的无效请求日志` | 铁矿石仅在交易日更新数据，非交易日的请求属于无效调用，需从审计日志中排除 |
| `MAX_LOG_ENTRY_SIZE` | `800–1200 字符` | 铁矿石日报表的结构化数据长度适中，限制日志条目大小可避免存储溢出 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：配置正确的访问令牌后，对话日志中仍显示令牌为`fastgpt`，且聊天界面报错。原因：未将FastGPT的默认令牌配置替换为业务专属令牌，导致日志记录的是内置默认值。
- 现象：审计日志显示非交易时段（如凌晨）有大量铁矿石行情请求，账户余额异常消耗。原因：未开启`LOG_FILTER_NON_TRADING_DAY`配置，未过滤非交易日的无效请求，导致恶意或误触发的调用未被拦截。
- 现象：尝试使用对话日志训练模型时，无法提取有效行情数据。原因：未开启`LOG_RECORD_REQUEST_PARAMS`配置，日志未记录请求的合约代码与数据维度，导致训练数据缺乏有效标识。

## 怎么确认配好了
- 发起一笔符合交易日时段的铁矿石行情请求，核对日志是否完整记录请求的合约代码、时间戳与响应数据字段。
- 在非交易日发起任意请求，确认系统是否自动将该请求的日志从审计清单中排除。
- 登录审计日志管理界面，验证保留时长是否与配置项`AUDIT_LOG_RETENTION_DAYS`的取值一致。
- 构造包含非标准单位的模拟响应，确认系统是否触发字段校验提示。
