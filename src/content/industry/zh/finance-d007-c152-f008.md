# 鞋类收益率的工具调用与插件

## 这个品类的数据长什么样
鞋类收益率相关数据主要来自国内纺织服饰专业B2B批发平台与跨境电商公开销售数据集。国内线下批发档口的报价数据每日9点前完成更新，跨境电商平台的售价数据每3小时同步一次。数据以结构化JSON格式返回，单条数据包含`sku_id`、`goods_name`、`brand`、`supply_price`、`retail_price`、`update_time`字段，其中`supply_price`与`retail_price`的单位为人民币元/双，`update_time`为UTC时间戳格式，无额外的聚合统计字段。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据源分为线下批发与跨境电商两类，对应不同的接口地址与鉴权规则，因此工具调用需配置多组独立的MCP服务参数。更新频率的差异要求调用间隔匹配对应数据源的更新节奏，避免无效请求或数据滞后于日报播报的发布时间。结构化的固定字段要求工具返回的schema严格匹配数据源文档，否则会出现字段缺失或格式错误，导致无法生成准确的收益率播报内容。鞋类SKU品类细分较多，批量拉取时需限制单次返回条数，防止请求超时影响工具调用稳定性。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `mcp_request_timeout` | 线下数据源设为`30 秒`，跨境数据源设为`15 秒` | 线下接口响应通常较慢，跨境接口返回数据量较大但响应更快 |
| `tool_call_interval` | 线下数据源设为`86400 秒`，跨境数据源设为`10800 秒` | 匹配对应数据源的更新频率，避免无效调用 |
| `mcp_auth_type` | 线下数据源选`api_key`，跨境数据源选`none` | 线下B2B平台需要密钥验证，跨境公开接口无需鉴权 |
| `batch_fetch_max_size` | `50 条/次` | 鞋类SKU批量拉取时，单次返回数据量适中，避免超时 |
| `tool_response_schema` | 按`sku_id, goods_name, supply_price, retail_price, update_time`的顺序配置 | 严格匹配数据源的标准文档结构，确保字段匹配 |
| `enable_cache` | `开启` | 相同SKU的价格数据在更新周期内无需重复拉取，降低接口调用次数 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工具调用返回`502 Bad Gateway`错误。原因：未正确配置MCP服务的通信协议，FastGPT默认使用SSE协议，若接入NPX启动的本地MCP服务，未添加端口转发或协议转换配置。
- 现象：工具返回的`supply_price`字段为空。原因：未正确匹配数据源的字段名，误将其他字段名作为配置项，未按数据源实际结构调整`tool_response_schema`。
- 现象：工具调用频繁触发超时。原因：将跨境数据源的调用间隔设置为与线下数据源相同的`86400 秒`，未根据更新频率调整`tool_call_interval`，导致单次请求数据量过大。

## 怎么确认配好了
- 进入FastGPT的工具管理页面，选中对应鞋类收益率工具，点击「测试调用」，输入合法SKU ID，查看返回的结构化数据是否包含预期字段。
- 查看工具的调用日志，确认每次调用的间隔符合配置的`tool_call_interval`，无异常4xx或5xx错误码。
- 检查工具的缓存开关状态，确认相同SKU的调用结果在更新周期内重复调用时，返回的`update_time`未发生变化。
- 切换不同数据源配置，分别测试线下和跨境接口的调用结果，确认鉴权配置生效，无鉴权失败提示。
