# 饰品收益率的部署与升级

## 这个品类的数据长什么样
国内饰品行业的公开报价平台、品牌方每日发布的批发与零售价格为主要数据来源，更新节奏为每个交易日结束后1.5小时内完成全量更新，非交易日无更新。数据文档采用结构化表格格式，包含字段：饰品材质标识、当日挂牌零售价、当日回收指导价、前一交易日基准价，部分细分品类如镶嵌类饰品会附带主石基准参考价字段，计价单位统一为元/克。

## 这些特征在「部署与升级」这一环带来什么约束
固定交易日更新的节奏要求部署时配置的定时拉取任务需匹配国内饰品交易市场的闭市时间，避免在非交易时段拉取无效数据。细分品类包含带附加字段的镶嵌类饰品，要求部署时配置可动态适配字段的解析规则，适配不同品类的字段差异。数据来源为公开第三方平台，部署时需配置合法的访问权限与请求频率限制，避免触发反爬机制。数据单位统一为元/克，升级时需校验格式化输出的单位一致性，避免出现单位混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `CRON_EXPRESSION` | `0 18 * * 1-5` | 国内饰品交易日为周一至周五17:00闭市，闭市后1.5小时拉取数据，18:00触发任务刚好覆盖更新完成 |
| `PARSE_FIELD_MAPPING` | `{"材质标识":"material","零售价":"retail_price","回收价":"recycle_price","基准价":"prev_price","主石价":"stone_price"}` | 匹配饰品行情数据的标准字段名，适配不同数据源的字段转换需求 |
| `REQUEST_INTERVAL` | `600 秒` | 公开平台的反爬限制为每分钟不超过2次请求，600秒的间隔确保合规 |
| `DYNAMIC_FIELD_ENABLE` | `true` | 镶嵌类饰品包含额外的主石价字段，需开启动态字段解析适配 |
| `OUTPUT_UNIT` | `元/克` | 匹配饰品行情数据的标准计价单位，确保播报内容的单位一致性 |
| `TIMEOUT_THRESHOLD` | `30 秒` | 公开数据源的响应平均时长为10-15秒，30秒可覆盖网络波动场景 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：执行`docker-compose up -d`后容器启动失败，日志返回`404 Not Found`，查看挂载的配置文件仅包含一行错误提示。原因：下载的配置文件未完成完整拉取，仅缓存了404错误页面内容，导致配置文件无效。
- 现象：更新镜像版本并重启容器后，历史存储的行情数据丢失。原因：未配置数据持久化挂载目录，容器重启后临时存储的数据库文件被清空。
- 现象：调用Laf函数拉取饰品行情数据时，在第三方托管环境中返回`未知错误`，本地环境调用正常。原因：未在第三方托管环境中配置Laf函数的访问凭证，默认仅支持托管环境的内置凭证。

## 怎么确认配好了
- 手动触发配置的定时拉取任务，查看拉取得到的结构化数据是否包含预设的所有字段。
- 查看容器运行日志，确认无`请求超时`、`字段解析失败`或`权限拒绝`类报错。
- 生成一份测试版的日报内容，核对计价单位与配置项的设定保持一致。
- 模拟非交易日场景，验证任务是否按配置逻辑跳过执行或生成无数据提示。
