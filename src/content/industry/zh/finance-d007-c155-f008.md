# 饲料收益率的工具调用与插件

## 这个品类的数据长什么样
饲料行业的数据源主要包括全国畜牧总站发布的官方监测数据、大宗商品现货交易平台的公开报价接口。单一饲料原料（如豆粕、鱼粉）的报价数据每日更新，配合饲料产品的市场报价每周更新1次，行业整体流通与成本结构数据每旬发布。数据文档为结构化表格形式，包含`饲料品类`、`原料配比`、`报告日期`、`单位成本`、`市场流通量`等字段，单位多为元/千克、吨/批次。不同数据源的字段命名存在细微差异，部分接口会将“单位成本”标注为“现货报价”。

## 这些特征在「工具调用与插件」这一环带来什么约束
不同更新周期的数据源要求工具调用区分触发频率，单一原料数据需每日拉取，配合饲料数据仅需每周同步，避免无效调用占用资源。字段命名的差异要求插件配置支持自定义字段映射，避免因字段名不匹配导致数据提取失败。结构化数据的条目较多，单次请求返回量较大，需要调整请求超时与批量拉取参数，平衡数据完整性与调用效率。品类细分的特性要求插件支持按`饲料品类`进行过滤，确保播报内容精准匹配目标受众需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `timeout` | `30–60 秒` | 饲料数据源返回的结构化数据条目较多，30秒基础时长可覆盖多数单品类拉取，复杂多品类场景可延长至60秒 |
| `content_type` | `application/json` | 多数公开饲料行业API采用JSON格式传输数据，统一配置可避免解析失败 |
| `filter_field` | `饲料品类` | 饲料品类包含猪、禽、反刍等细分类型，按该字段过滤可精准匹配目标播报内容 |
| `max_retries` | `2 次` | 公开数据源可能存在临时波动，2次重试可降低单次请求失败概率，避免重复调用占用资源 |
| `response_batch_size` | `100 条/请求` | 饲料行业数据单请求返回量适中，100条可平衡请求效率与数据完整性 |
| `parse_mode` | `structured_table` | 饲料数据为标准化结构化格式，采用表格解析模式可直接提取目标字段，无需额外清洗 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：HTTP插件调用饲料数据源API返回502错误。原因：未配置正确的请求头`User-Agent`，部分饲料行业API会拦截无合法标识的请求，导致网关报错。
- 现象：在工作流中引用配置好的插件后，运行节点触发输入报错。原因：未在插件配置中声明必填参数`饲料品类`，调用时未传入对应参数值，导致参数校验失败。
- 现象：调用搜索插件获取饲料行情信息后，仅返回简易摘要，无法获取原始网页完整内容。原因：未开启插件的网页内容提取配置项，仅抓取了页面元数据，未提取正文内容。

## 怎么确认配好了
- 进入插件配置页面，检查`timeout`参数取值是否与目标数据源的响应时长匹配。
- 发起一次测试请求，查看返回结果中是否包含预设的核心字段。
- 在工作流中调用该插件，传入测试用的品类参数，确认运行日志中无参数校验错误。
- 查看插件的`max_retries`配置，确认重试次数与数据源的稳定性要求一致。
