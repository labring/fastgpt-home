# 饲料收益率的数据库与运维

## 这个品类的数据长什么样
饲料收益率相关数据主要来自国内大宗商品现货交易所的原料报价、饲料生产企业的生产台账及行业协会的公开调研数据。数据更新节奏为每日早间更新前一交易日的全量行情，每周会进行一次全品类数据的校准修正。单条数据文档包含原料名称、产地、报价单位、当日成交价、前一日成交价、环比变动值、对应饲料成品的配方占比、统计周期等字段，其中配方占比字段用于标注该原料在对应成品饲料中的添加比例，为饲料收益率计算的核心关联字段。

## 这些特征在「数据库与运维」这一环带来什么约束
饲料收益率相关数据的特征直接约束数据库与运维环节的设计。每日定时批量更新的行情数据，要求数据库支持低延迟的批量写入与定时任务调度能力。关联配方占比字段需与饲料品类主表建立关联，要求数据库支持外键或联合索引以保证跨表数据一致性。每周的全品类数据校准需要回溯修改历史分区数据，要求数据库支持分区表的灵活修改与事务支持。多源数据源的同步需配置数据校验规则，避免不同渠道的报价偏差导致数据异常，同时需预留数据清洗环节以修正格式不统一的字段内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `MONGODB_CONNECTION_POOL_SIZE` | `10-15` | 适配饲料每日批量行情写入的并发需求，避免连接池耗尽同时提升写入效率 |
| `DATA_SYNC_CRON_EXPRESSION` | `0 0 7 * * *` | 匹配饲料行情数据每日早间更新的节奏，确保当日数据在早8点前完成入库 |
| `PARTITION_DATE_FIELD` | `stat_date` | 饲料数据按统计日期分区存储，该字段为每条数据的核心分区依据，便于历史数据校准与快速查询 |
| `DATA_CLEAN_THRESHOLD` | `±50元/吨` | 用于过滤不同数据源间报价偏差超出该范围的异常数据，适配饲料原料报价的合理波动区间 |
| `DB_BACKUP_CRON` | `0 0 2 * * 0` | 匹配每周一次的全量数据校准需求，备份数据可用于校准失败后的回滚操作 |
| `MAX_BATCH_INSERT_SIZE` | `200` | 适配单批次每日更新的饲料数据量规模，平衡写入效率与数据库负载 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：本地开发环境执行`pnpm dev`时显示数据库连接超时，日志中出现`ETIMEDOUT`错误码。原因：未配置正确的mongodb连接串，或本地开发环境未开通对应端口的出站权限，导致无法与远程mongodb实例建立稳定连接。
- 现象：在饲料数据查询场景中，返回的数据库查询结果包含大量冗余字段，导致模型调用的token消耗与实际API账单存在偏差。原因：未配置字段过滤规则，默认拉取了全量字段内容，其中配方占比、产地编码等非核心字段增加了prompt的token占用量。
- 现象：数据库连接模块中未展示Oracle选项，无法直接配置Oracle数据源。原因：当前版本的FastGPT数据库驱动未内置Oracle连接支持，仅内置了主流的数据库类型适配，饲料场景若需对接Oracle需手动安装对应驱动插件。

## 怎么确认配好了
- 执行定时同步任务，查看数据库中是否生成当日的饲料行情数据条目，核对`stat_date`字段与当前日期是否一致。
- 手动导入一组报价偏差超出预设异常阈值的测试数据，确认系统是否自动过滤该类数据。
- 调用数据库查询接口，验证返回的字段仅包含配置中指定的核心字段，无冗余内容。
- 执行一次全量备份与恢复操作，确认备份文件可正常恢复至测试数据库实例。
