# 饲料收益率的模型接入与配置

## 这个品类的数据长什么样
饲料收益率与行情日报的数据主要来自国内畜牧行业公开监测平台、地方农业农村部门的每日采样数据。数据更新节奏为当日行情于次日上午发布，支持按产区、饲料品类筛选查询。文档格式多为结构化CSV或JSON，单条记录包含以下字段：品类名称、产区、批发单价（单位元/千克）、零售单价（元/千克）、上市量（单位吨）、监测日期。无额外非结构化文本内容，字段定义统一且无歧义。

## 这些特征在「模型接入与配置」这一环带来什么约束
饲料行情数据的多字段结构化特征，要求模型接入环节需配置精准的字段映射规则，确保模型能准确识别各数据维度，避免混淆不同品类或产区的行情信息。每日更新的节奏要求定时拉取任务需匹配T+1的更新周期，避免频繁请求超出数据源接口限制。结构化的CSV/JSON格式要求启用专门的结构化数据解析开关，无需依赖通用文本解析流程，同时需配置单位标准化处理步骤，统一不同字段的计量规则，防止模型因单位差异产生错误计算。此外，饲料品类与其他农林牧渔品类的字段差异较大，需避免直接复用其他品类的字段映射配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `field_mapping` | 将数据源的“品类名称”映射为`product_name`，“产区”映射为`producing_area`，“批发单价”映射为`wholesale_price`，“零售单价”映射为`retail_price`，“上市量”映射为`market_volume`，“监测日期”映射为`monitor_date` | 匹配饲料行情数据的标准字段名，确保模型能准确识别各数据维度 |
| `parse_structured_data` | `true` | 饲料行情数据为标准化CSV/JSON格式，启用后可直接提取字段值，无需额外文本清洗 |
| `api_request_timeout` | `30 秒` | 结构化数据的批量拉取可能需要更长处理时间，避免因超时中断请求 |
| `scheduled_fetch_interval` | `86400 秒` | 饲料行情数据每日更新一次，按日拉取可保证数据时效性，避免重复请求 |
| `system_prompt_template` | 该模型为饲料行情日报播报助手，需基于提供的{context}数据，按品类、产区整理当日行情信息 | 明确模型的任务范围，限定其仅使用传入的饲料数据生成内容，避免无关信息干扰 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用模型API返回404 status code (no body)。原因：未正确配置`API_BASE_URL`为对应模型的官方接入地址，或未添加正确的接口路径后缀。
- 现象：模型生成内容未引用传入的饲料行情数据，仅输出通用话术。原因：未启用`parse_structured_data`开关，或`field_mapping`配置错误导致模型无法识别有效数据字段。
- 现象：本地部署模型测试时提示“Message field is required”报错。原因：未在请求参数中正确填充`messages`字段，或字段格式不符合模型要求的数组结构。

## 怎么确认配好了
- 进入FastGPT的模型测试界面，输入包含饲料品类关键词的查询，核对返回结果中是否包含配置的字段映射信息。
- 查看定时任务日志，确认每日拉取数据的请求是否成功返回结构化数据，无超时或格式错误。
- 检查API密钥配置项，确认密钥未过期且拥有对应数据源的访问权限。
- 调整系统提示词模板，验证模型是否严格按照模板要求生成内容，未引入无关信息。
