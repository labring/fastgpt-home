# 饲料收益率的部署与升级

## 这个品类的数据长什么样
饲料收益率相关数据主要来自农业农村部畜牧兽医局饲料监测系统、国内大型饲料生产企业的公开报价端口，以及区域性农贸批发市场的每日采样数据。数据更新节奏为每日16:00至18:00完成当日全量更新，单次更新覆盖全国31个省级行政区的饲料品类报价。单份标准文档包含饲料品类名称、产区信息、批发与零售单价、原料成本占比参考字段，单位统一为元/千克，部分批量汇总文档会附带区域价差对比的原始记录项。

## 这些特征在「部署与升级」这一环带来什么约束
饲料品类数据的固定更新窗口、结构化字段与批量文档特征，对部署与升级环节带来多重约束。每日16:00至18:00的集中更新要求定时拉取任务需匹配该时段，避免拉取未完成的临时数据。结构化的产区、单价字段需要在分块时保留字段关联关系，防止拆分后丢失数据关联逻辑。批量汇总文档的长度较高，需调整分块参数避免截断关键信息。每日全量更新带来的稳定数据增量，要求升级时预留足够的向量数据库存储空间，避免触发容量限制。同时，多来源的数据格式差异，需要在部署阶段配置统一的解析规则，避免不同来源的文档解析结果不一致。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 单份批量饲料汇总文档的解析耗时通常超过默认阈值，延长超时时间可避免解析中断 |
| `分段长度` | `1200–1500 字符` | 饲料文档包含多字段关联内容，该区间可保留字段关联关系，避免过度拆分 |
| `召回条数` | `前 8 条` | 饲料数据的区域价差项需要足够的召回量覆盖多区域信息，避免关键数据遗漏 |
| `相似度阈值` | `0.72–0.78` | 饲料品类名称与产区的关联度较高，该阈值可过滤无关的非饲料品类数据 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 批量饲料汇总文档的平均大小符合该区间，避免上传被系统拦截 |
| `DOCKER_RESTART_CONDITION` | `on-failure:3` | 匹配饲料数据每日更新的定时任务场景，失败时自动重启最多3次，避免服务停滞 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为使用OceanBase版本的compose.yml部署时，其他容器正常启动，仅FastGPT容器持续退出且无日志输出。原因是未正确配置`DB_HOST`环境变量指向OceanBase服务，导致数据库连接失败。
- 现象为使用4.9.6版本上传包含多列的饲料报价表格时，部分字段无法被正确分块提取，仅保留零散文本。原因是未将`分段长度`调整至适配表格列宽的区间，导致表格拆分时丢失列关联关系。
- 现象为本地修改了配置文件后，使用docker部署时修改未生效。原因是未重新构建镜像或未挂载本地配置文件到容器内的对应路径，导致容器使用默认镜像配置。

## 怎么确认配好了
- 执行docker compose ps命令，确认FastGPT容器状态为healthy，关联的数据库、向量数据库容器状态均正常。
- 上传一份标准饲料报价文档，查看知识库解析日志，确认无超时或解析失败报错。
- 发起一次收益率查询请求，核对返回结果包含预设的饲料品类、产区、单价等字段，无缺失或异常内容。
- 修改一项配置参数后重启服务，确认配置项在后台管理界面的对应位置显示为修改后的值。
