# 专用设备智能尽调报告的工作流编排

## 这个品类的数据长什么样
专用设备智能尽调报告的数据主要来自三类渠道：设备出厂合格证与技术说明书、设备全生命周期运维日志、行业监管部门的合规备案文件。基础出厂数据为静态文档，包含设备型号、序列号、额定功率、额定转速等字段，单位分别为型号编码、无单位序列号、kW、r/min；运维日志为季度更新的结构化记录，包含单次运行时长、累计运行小时数；合规备案数据为年度更新的批量文件，包含设备年检合格标识字段。

## 这些特征在「工作流编排」这一环带来什么约束
专用设备尽调数据的多源多更新节奏特征，对工作流编排带来三点核心约束。第一，需拆分静态与动态数据调用节点，基础出厂数据仅需首次拉取并缓存，运维日志与合规备案数据按各自更新周期触发增量拉取，避免资源浪费。第二，运维日志为结构化CSV格式，需配置格式解析节点，将原始表格数据转换为适配检索的结构化文本。第三，字段单位存在明确行业规范，需配置单位校验节点，确保跨数据源的功率、时长等字段单位统一，避免后续分析出现偏差。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `知识库召回条数` | `前8–12条` | 专用设备尽调需覆盖出厂参数、运维记录、合规信息多维度内容，8-12条可平衡检索覆盖度与响应速度 |
| `分段长度` | `900–1100 字符` | 运维日志单条记录包含多组运行参数，该分段长度可保留单条记录的语义完整性 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 年度合规备案数据多为批量大文件，600秒超时可覆盖完整的文件解析与索引构建流程 |
| `全局变量知识库绑定规则` | `按设备型号匹配对应知识库ID` | 不同型号专用设备的尽调数据存储于独立知识库，全局变量传递型号参数可精准调用 |
| `插件参数 fallback 策略` | `优先读取全局变量值，未获取则启用插件默认配置` | 适配不同设备的个性化参数需求，同时保留异常场景下的兜底能力 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流调用知识库检索时返回「未找到匹配知识库」报错，状态码404。原因：未按设备型号配置全局变量绑定对应知识库ID，误使用通用知识库ID，未使用专属知识库ID。
- 现象：工作流运行后返回的尽调报告字段单位混乱，出现不同单位混用的情况。原因：未配置单位校验节点，未对跨数据源的参数字段进行单位统一转换。
- 现象：插件参数未按预期读取全局变量，直接使用了插件默认配置。原因：未正确配置全局变量的传递路径，变量未被正确注入到插件参数的绑定位置。

## 怎么确认配好了
- 执行单次测试运行，查看工作流日志中知识库调用的返回ID与当前设备型号绑定的知识库ID是否一致。
- 上传一份模拟运维日志文件，检查解析后的文本分段是否符合预设的分段长度范围。
- 模拟变量未传递的异常场景，确认插件是否自动启用了预设的默认配置。
- 查看索引更新记录，确认合规备案数据按设定的更新周期完成了全量索引更新。
