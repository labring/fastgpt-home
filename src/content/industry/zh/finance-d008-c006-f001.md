# 中药智能尽调报告的HTTP 接口与外部系统

## 这个品类的数据长什么样
面向金融机构的中药智能尽调报告的数据主要来源于国家药典、中药材溯源管理平台、产地质检机构出具的批次检测报告。数据更新节奏分两类：公开标准数据定期更新，批次溯源数据随中药材采收、加工批次实时更新。文档结构以结构化字段为主，包含基原名称、性状参数、含量测定值、炮制工艺、性味归经、功能主治、禁忌人群等字段。含量测定字段单位多为mg/g，性状字段单位包含厘米、克等物理量单位，部分字段为文本描述类内容。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
中药尽调报告的数据特征对接口调用带来多重约束。结构化字段多且附带物理量单位，要求外部接口返回的数据需严格匹配预设字段名与单位，否则无法直接用于报告生成。批次溯源数据实时更新的特性，要求HTTP接口需支持按批次号、采收时间等参数精准拉取最新数据，避免使用缓存过旧的批次信息。公开标准数据存在版本差异，要求接口需支持指定标准版本号，确保尽调报告引用的标准版本一致。文本描述类字段内容较长，接口返回的单条数据量可能超出常规阈值，需配置适配的请求超时与数据接收长度限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `HTTP_REQUEST_TIMEOUT` | `300 秒` | 中药尽调报告的接口返回数据包含长文本描述与多组检测参数，单次请求数据量较大，需预留充足响应时间 |
| `MAX_RESPONSE_CONTENT_LENGTH` | `2097152 字节` | 单份中药材批次报告的结构化数据加文本描述通常不超过该阈值，避免截断有效内容 |
| `RESPONSE_CACHE_TTL` | `3600 秒` | 公开药典标准数据更新频率低，批次溯源数据缓存时长可匹配多数产地平台的更新周期 |
| `VALIDATE_RESPONSE_FIELDS` | `开启字段校验` | 需校验接口返回的字段名与单位是否符合中药尽调报告的标准格式，避免数据格式错误 |
| `RETRY_ON_FAILURE` | `失败重试2次` | 中药材溯源接口可能因网络波动出现临时请求失败，重试可降低无效请求率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用接口返回`500 do request failed: Post "https://xxx" tls: failed to verify certificate`，原因是未配置信任自定义SSL证书，或接口使用的SSL证书未通过系统根证书校验。
- 接口返回的含量测定字段为空，或单位与预期不符，原因是未开启响应字段校验，未对返回数据的字段名与单位做强制校验。
- 接口请求在凌晨高频触发导致余额耗尽，原因是未配置接口调用频率限制，未设置合理的限流规则。

## 怎么确认配好了
- 发起单次测试请求，校验返回数据的字段名、单位是否匹配中药尽调报告的标准格式，根据校验结果调整字段校验配置。
- 模拟批量请求，观察系统日志中的调用记录，确认限流规则生效后，结合实际业务调用量调整频率限制参数。
- 测试不同时间发起的批次数据请求，确认返回的溯源数据为最新批次内容，根据缓存配置验证数据更新逻辑。
- 检查接口调用的错误日志，确认未出现SSL验证失败、请求超时等报错，根据报错信息调整超时与证书配置。
