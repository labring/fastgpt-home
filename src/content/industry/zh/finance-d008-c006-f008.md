# 中药智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
中药智能尽调报告的数据主要来源于国家药品监督管理局公开数据库、中药材流通追溯公共服务平台、国家药典委员会公开标准文件。数据更新节奏随对应标准修订周期调整，药典标准每5年集中更新，流通溯源数据每日同步。单份尽调文档结构固定，包含基原信息、性状描述、理化鉴别项、含量测定结果、炮制规范、性味归经、功能主治、用法用量及贮藏要求等字段。含量测定字段单位多为mg/g，性状描述中涉及尺寸的单位为厘米，重量单位为克。

## 这些特征在「工具调用与插件」这一环带来什么约束
中药尽调数据的固定专业字段与多来源属性，要求工具调用需精准匹配标准化字段名，避免泛化查询导致结果偏差。多数据源依赖要求插件需分别对接国家药监局数据库、药典标准库及溯源平台，需单独配置每个数据源的鉴权参数。含量测定、性状描述的固定单位规则，要求工具调用结果需校验单位一致性，防止单位转换错误。定期更新的标准要求插件需配置自动同步机制，确保调用的标准版本与最新公开内容一致。长文档结构也要求工具调用的上下文窗口需适配完整字段读取，防止关键信息被截断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `tool_call_max_retries` | `2 次` | 中药尽调数据校验需避免单次调用失败导致流程中断 |
| `plugin_timeout` | `300 秒` | 对接多数据源需预留足够的请求响应时间 |
| `tool_field_matching_mode` | `精准匹配` | 中药字段专业性强，泛化匹配易导致结果偏差 |
| `plugin_auto_sync_interval` | `7 天` | 适配药典标准日常更新节奏，无需高频同步 |
| `tool_result_unit_validate` | `开启` | 中药数据包含固定单位规则，需校验单位一致性 |
| `max_tool_call_context` | `8000 字符` | 适配单份中药尽调报告的完整字段长度 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 出现`InternalError.Algo.InvalidParameter`报错，提示工具调用参数非法。原因是未严格按照中药字段的固定名称发起调用，使用了泛化字段名导致参数不匹配。
- 出现`The tool call is not supported`报错。原因是未在平台内启用对应数据源的插件，或插件鉴权配置未生效。
- 工具返回的含量测定结果单位混乱，比如出现“克”，未使用“mg/g”作为标准单位。原因是未开启`tool_result_unit_validate`配置，未校验返回结果的单位一致性。

## 怎么确认配好了
- 发起一次针对指定中药材的工具调用请求，检查返回结果的字段名称与尽调文档的标准字段完全一致。
- 查看插件管理界面，确认所有对接的数据源插件均处于启用状态，且鉴权配置无缺失。
- 触发一次自动同步任务，检查插件是否能成功拉取最新的药典标准数据。
- 调用工具获取含量测定结果，手动校验返回结果的单位是否符合中药数据的固定规则。
