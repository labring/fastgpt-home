# 休闲食品智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
休闲食品智能尽调报告的数据主要来自国家食品安全抽样检验信息系统、食品生产企业公开的产品合规文档、供应链原料溯源平台及电商平台的产品详情页。数据更新节奏分为三类：监管抽检数据按月更新，企业新品文档随产品上市同步更新，电商销售关联数据按周同步。文档结构以结构化表格为主，包含产品名称、配料成分、过敏原标识、生产许可证编号、保质期、储存条件、原料批次号等字段，其中保质期单位为天或月，储存条件为枚举值，原料批次号为字符串格式。

## 这些特征在「工具调用与插件」这一环带来什么约束
休闲食品数据的多源属性要求工具调用时配置跨源数据去重规则，避免同一产品的重复信息干扰尽调结果。监管抽检数据按月更新的特性，要求工具调用时指定最近30天的数据源过滤参数，仅调用最新的合规检测结果。过敏原字段的枚举格式，要求插件在提取配料信息时匹配预设的过敏原列表，确保识别结果符合合规要求。原料批次号的字符串格式，要求工具调用时配置字段校验逻辑，过滤无效字符的批次信息。电商关联数据的按周更新节奏，要求插件的定时拉取任务设置为每周执行一次，避免重复拉取旧数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `plugin_call_timeout` | `300 秒` | 休闲食品跨源数据拉取与整合通常耗时100-250秒，预留足够时间完成全流程调用 |
| `data_source_filter_days` | `30 天` | 监管抽检数据按月更新，仅需调用最近30天的最新合规检测结果 |
| `field_validation_enabled` | `开启` | 原料批次号为字符串格式，需校验字段格式合法性，过滤无效信息 |
| `plugin_schedule_interval` | `7 天` | 电商关联数据按周同步，无需高频拉取重复的旧数据 |
| `rag_recall_top_k` | `前 3 条` | 休闲食品尽调报告需聚焦核心合规信息，过多召回结果会干扰内容生成 |
| `max_context_length` | `1200 字符` | 单份休闲食品产品文档的核心信息通常在800-1000字符范围内，避免上下文溢出 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工具调用返回`408 Request Timeout`错误码，调用任务显示失败状态。原因：未配置`plugin_call_timeout`为足够时长，跨源拉取休闲食品多源数据时耗时超过默认设置，导致调用中断。
- 现象：插件执行顺序错乱，先获取电商销售数据后获取监管抽检数据，导致尽调报告中合规信息滞后于销售数据。原因：未配置`plugin_execution_order`绑定执行依赖关系，未按数据源优先级设置执行顺序，导致工具调用顺序随机。
- 现象：尽调报告中出现无效的过敏原信息，包含未定义的枚举值或空字段。原因：未开启`field_validation_enabled`配置，未校验过敏原字段的合法性，导致识别到非预设的异常内容。

## 怎么确认配好了
- 进入FastGPT的工具调用日志页面，查看最近的插件调用记录，确认所有调用均未出现超时报错，核对调用时长是否符合实际数据拉取需求。
- 手动触发一次全量数据拉取任务，核对返回的原料批次号字段格式是否符合预设规则，无无效字符或异常内容。
- 查看插件执行顺序配置页面，确认各工具的执行优先级与依赖关系已按数据源要求绑定，无错乱情况。
- 生成一份测试用的休闲食品尽调报告，核对过敏原、保质期等字段的内容是否符合预设的枚举或格式要求。
