# 休闲食品智能尽调报告的引用来源与溯源

## 这个品类的数据长什么样
休闲食品的数据源包含供应商资质文件、第三方批次质检报告、供应链溯源台账、电商平台销售数据及行业协会抽检公告。更新节奏随数据类型差异调整：第三方质检报告随生产批次更新，供应链台账随供货周期动态调整，电商销售数据每日同步更新。文档结构分为标准化报告与非标准化台账两类：标准化质检报告包含批次号、生产日期、检测项及对应数值，非标准化台账包含供应商名称、供货批次、对应原料信息。字段与单位存在专属规则：菌落总数以CFU/g为单位，食品添加剂含量以mg/kg为单位，批次号为带字母前缀的字符串格式，部分电商数据会附带消费者评价与退货记录，用于补充尽调维度。

## 这些特征在「引用来源与溯源」这一环带来什么约束
休闲食品的数据特征对溯源环节带来多重约束。多源异构的数据需要精准匹配批次信息，否则溯源结果会混淆不同生产批次的产品检测数据。不同更新频率的数据源要求知识库同步策略差异化，每日更新的电商数据需配置定时同步任务，季度更新的质检报告仅需在批次生产前完成导入。文档结构的差异要求解析规则适配PDF扫描件、Excel台账等多种格式，避免解析后丢失批次号等关键字段。专属的字段与单位需要在溯源标注中准确呈现，否则会导致尽调报告中的数据参考出现歧义。多环节的供应链溯源需要关联多个文档的批次信息，因此召回的文档需按批次优先级排序，确保核心溯源信息优先展示。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | 前8条 | 休闲食品尽调所需的溯源文档数量适中，过多会导致报告冗余，过少则无法覆盖关键检测与供应链信息 |
| `相似度阈值` | 0.75 | 过滤匹配度低于该值的无关文档，避免召回非目标批次的休闲食品检测报告或供应链数据 |
| `分段长度` | 1000-1200字符 | 适配休闲食品质检报告与供应链台账的段落长度，保留完整的批次号、检测项等核心字段 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 秒 | 预留足够时间解析大型供应链台账或多页质检报告PDF，避免解析超时报错 |
| `重排返回条数` | 前5条 | 优先展示与当前尽调批次最相关的溯源文档，确保报告核心引用信息清晰聚焦 |
| `是否显示引用来源` | 按场景开启 | 适配不同尽调场景的展示需求，支持按需关闭或开启引用来源标注 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：生成的尽调报告中未显示任何引用来源标注，或标注内容缺失批次号信息。原因：未配置`引用来源显示格式`参数，或未在格式中绑定`batch_num`等批次相关变量。
- 现象：对话时强制显示引用来源，无法按需隐藏。原因：未将`是否显示引用来源`参数设为关闭，或未在对话流配置中禁用引用展示模块。
- 现象：解析大型质检报告时返回504超时错误。原因：`PARSE_FILE_TIMEOUT_SECONDS`设置值过短，未预留足够时间完成多页文档的解析与嵌入。

## 怎么确认配好了
- 上传一份带明确批次号的休闲食品质检报告，发起针对该批次的尽调查询，检查返回结果中是否包含带有批次号的来源标注。
- 调整`相似度阈值`为0.6和0.9，对比两次召回的文档数量，确认阈值调整后召回结果发生对应变化。
- 上传一个超过100MB的供应链台账Excel文件，等待解析完成后检查文件状态，确认未出现超时报错。
- 调用知识库搜索模块，查看返回的变量列表中是否包含`source_file`、`batch_num`等字段，确认变量绑定配置生效。
