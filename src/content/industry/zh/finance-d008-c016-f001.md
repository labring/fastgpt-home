# 光伏智能尽调报告的HTTP 接口与外部系统

## 这个品类的数据长什么样
光伏智能尽调报告的数据主要来自光伏电站SCADA监控系统、并网调度平台、组件运维台账及区域气象站。运行类数据如实时发电量、辐照强度每5分钟更新一次，台账类数据如装机容量、组件型号按月度更新。单份报告对应单座或多座电站，文档结构包含电站基本信息、设备参数、发电绩效、运维记录四大模块，字段含装机容量（单位MWp）、日发电量（单位kWh）、辐照强度（单位W/㎡）、逆变器编号等，单份完整报告的文本长度通常为数万字符。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
光伏数据的高频更新需求要求接口支持短间隔请求，需配置合理的请求频率限制避免触发外部接口限流。多字段且带专属单位的特征要求接口返回的结构化数据需严格匹配预设字段名与单位，否则会导致尽调报告数据失真。长文本与多电站数据的组合，要求HTTP接口支持分页返回或批量请求，否则单次请求会因数据量过大触发超时。同时金融尽调场景对数据可信度要求高，接口需支持TLS证书验证，部分自签名的运维平台接口还需特殊配置。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `HTTP_REQUEST_TIMEOUT` | `300 秒` | 光伏尽调数据接口常返回多电站批量数据，300秒可覆盖完整数据拉取流程 |
| `RESPONSE_PARSE_FIELD_LIST` | `["电站ID", "装机容量", "日发电量", "辐照强度"]` | 仅解析尽调报告必需的核心字段，避免冗余数据占用解析资源 |
| `REQUEST_RATE_LIMIT` | `10 次/分钟` | 多数光伏电站SCADA接口的默认限流阈值为10-15次/分钟，匹配该值可避免被封禁 |
| `CERT_VERIFY_MODE` | `strict` | 金融尽调场景需保证数据来源可信，严格验证TLS证书可防止数据被篡改 |
| `CUSTOM_VAR_MAPPING` | `{"电站名称":"station_name", "发电量":"power_gen"}` | 匹配外部接口返回的字段名与尽调报告的自定义变量，确保数据正确填充 |
| `PARSE_HTTP_RESPONSE_TYPE` | `json` | 光伏运维平台与并网接口多返回结构化JSON格式，适配该类型可简化解析流程 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用外部接口返回`429 Too Many Requests`错误，未配置合理的请求频率限制，超出光伏数据接口的官方限流阈值。
- 日志显示`tls: failed to verify certificate: x509: certificate has expired or is not yet valid`，未正确处理光伏运维平台的自签名证书，强制跳过验证会降低数据可信度。
- 自定义输入变量接收后字段为空，未配置`CUSTOM_VAR_MAPPING`规则，未将外部接口返回的光伏字段与尽调报告的变量名对齐。

## 怎么确认配好了
- 发起一次测试请求，检查返回的结构化数据是否包含预设的`电站ID`、`装机容量`等核心字段，且单位符合光伏行业标准。
- 连续发起15次请求，检查是否触发`429`错误，验证`REQUEST_RATE_LIMIT`配置生效。
- 查看接口调用日志，确认TLS证书验证流程正常，或在使用自签名证书时已正确配置对应参数。
- 输入预设的自定义变量，检查生成的尽调报告中是否正确填充了外部接口返回的光伏数据字段。
