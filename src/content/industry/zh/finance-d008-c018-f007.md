# 光模块智能尽调报告的工作流编排

## 这个品类的数据长什么样
光模块的核心数据来自通信设备厂商出厂参数文档、运营商集采招标公示、光通信行业标准规范及第三方检测报告。数据更新节奏随厂商固件迭代、行业标准更新或集采计划变动，无固定周度或月度周期。单份尽调文档通常包含型号标识、传输速率、工作功耗、工作温度范围、接口类型、合规认证编号等字段，速率单位为Gbps，功耗单位为瓦特，温度单位为摄氏度，部分文档附带链路测试的误码率原始数据。

## 这些特征在「工作流编排」这一环带来什么约束
数据来源分散且无固定更新周期，要求工作流需支持多源数据拉取节点的灵活配置，可按需调用厂商数据接口、公开招标平台爬虫及标准文档解析工具。字段包含多类带固定单位的技术参数，要求工作流内置单位校验节点，对输入的速率、功耗等参数做格式匹配。部分文档附带原始测试数据，要求工作流包含数据清洗节点，对误码率等非结构化原始数据做标准化转换，同时需适配不同厂商文档的排版差异，避免解析后字段错位。

## 配置怎么定

| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `RAG召回条数` | 8–12 条 | 光模块技术文档参数较多，需召回足够条目覆盖型号、速率、功耗等核心字段，避免关键参数遗漏 |
| `数据库连接超时时间` | 600 秒 | 光模块数据部分存储于企业级供应链数据库，需适配长连接场景，避免因数据拉取过久触发超时 |
| `MCP工具调用重试次数` | 2 次 | 部分厂商API接口存在临时限流，设置有限重试可降低调用失败概率，无需过高次数避免触发二次限流 |
| `工作流节点超时阈值` | 900 秒 | 包含多源数据拉取与文档解析的工作流，需预留足够时间完成标准文档的结构化转换 |
| `分享链接鉴权开关` | 按团队权限开启 | 尽调报告涉及敏感技术参数，需通过鉴权控制访问范围，对应配置项位于工作流发布页的「分享设置」模块 |
| `插件导出格式` | JSON 结构化格式 | 光模块参数需跨工具流转，JSON格式可保留字段与单位信息，避免解析丢失 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流运行后返回的光模块参数存在单位错误或字段错位。原因：未配置`字段校验规则`节点，未对RAG召回的文档参数做单位匹配与字段映射，导致不同厂商的参数格式混同。
- 现象：v4.9.11版本中无法在工作流分享配置页面找到鉴权开关。原因：该版本的鉴权开关默认折叠在「高级分享设置」面板内，未展开该面板则无法看到对应配置项。
- 现象：新版FastGPT中数据库连接插件调用耗时远超旧版，旧版仅需0.2秒。原因：未调整`数据库连接超时时间`配置，新版默认超时阈值与旧版不同，且工作流未配置并行数据拉取节点，导致多源数据串行执行。

## 怎么确认配好了
- 手动触发一次工作流，查看返回的参数列表，确认包含型号、传输速率、工作功耗等核心字段，且单位符合光模块技术规范。
- 检查工作流的分享设置面板，确认鉴权开关的状态与团队访问权限要求一致，可通过非授权账号测试访问验证。
- 查看工作流运行日志，确认数据库连接节点的耗时符合预期，无连续超时报错，可对比同类型工作流的运行日志调整配置。
- 导出单个插件并导入至测试工作流，确认关联的数据库连接信息与参数配置完整保留，无丢失情况。
