# 免税智能尽调报告的HTTP接口与外部系统

## 这个品类的数据长什么样
免税智能尽调报告的数据主要来自海关总署离岛免税监管系统、财政部免税政策公告库、离岛免税店的经营备案接口。更新节奏存在差异：离岛店备案信息实时更新，免税限购额度按季度调整，政策公告为不定期发布。文档结构包含免税品10位品类编码、离岛店备案编号、年度免税额度、单件限购数量、备案有效期字段，单位分别为无、无、元、件、YYYY-MM-DD格式，字段包含专属的免税监管标识，用于区分普通商贸商品数据。

## 这些特征在「HTTP接口与外部系统」这一环带来什么约束
多数据源对接需求明确，需同时对接海关、财政部、门店系统三个接口，需处理跨源字段的统一映射与格式对齐。不同数据源的更新周期从实时到季度不等，需适配差异化的轮询和缓存策略，避免数据滞后或冗余调用。免税品类编码、备案编号有固定监管格式，接口需增加专属校验逻辑，防止无效数据流入尽调报告。海关类接口通常有严格的调用频次限制，需控制并发请求数量，避免触发限流规则。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `external_api_timeout` | `300 秒` | 免税数据需拼接多源接口返回内容，单次请求耗时较长，默认超时时间不足 |
| `request_retry_count` | `3 次` | 海关监管接口存在临时波动，多次重试可降低临时异常导致的请求失败 |
| `external_cache_ttl` | `86400 秒` | 常规免税政策更新频率为每日，过长缓存会导致数据滞后，过短则增加接口调用压力 |
| `field_validation_mode` | `strict` | 免税字段包含专属监管编码，严格校验可过滤无效数据，保证尽调报告准确性 |
| `concurrent_request_limit` | `2 个` | 海关接口有调用频次限制，控制并发可避免触发限流规则 |
| `error_notify_webhook` | `指定内部告警地址` | 免税数据异常会直接影响尽调报告有效性，需及时接收告警通知 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用外部接口返回`403 Forbidden`状态码，原因：未配置免税专属接口的白名单权限，海关或免税店系统仅允许备案的合作IP访问。
- 现象：尽调报告中免税额度字段为空，原因：未调整`field_validation_mode`为宽松模式，自定义的免税编码校验规则过滤了有效备案数据。
- 现象：定时拉取的免税政策数据未同步更新，原因：设置了过长的`external_cache_ttl`，超过了政策实际更新的频率，缓存未自动刷新。

## 怎么确认配好了
- 调用配置的外部接口，校验返回的免税品编码、额度等字段是否符合预设的格式要求。
- 查看接口调用日志，确认重试次数和超时设置与配置项一致，无异常重试或超时中断。
- 对比实时拉取的政策数据与官方发布的最新免税规则，确认缓存时间设置适配实际更新频率。
- 触发接口异常测试，确认`error_notify_webhook`能正常接收告警通知。
