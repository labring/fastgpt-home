# 农商行智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
农商行智能尽调报告的数据来源包括内部信贷管理系统、人行征信查询接口、国家企业信用信息公示系统、属地政务服务平台的经营备案数据。更新节奏为内部业务数据每日同步，外部公开数据按季度更新。文档多为结构化表格拼接非结构化的风险评估说明，字段包含统一社会信用代码、企业名称、授信额度、贷款余额、经营流水金额等，单位多为万元、笔次。

## 这些特征在「工具调用与插件」这一环带来什么约束
内部数据每日更新的特性要求工具调用支持高频合规接口调用，需配置鉴权与审计日志留存规则。外部公开数据按季度更新的特性可通过缓存机制减少重复调用，降低接口调用成本。字段多为标准化但存在接口差异的特性，要求工具调用环节配置统一的字段映射规则，避免因字段名称不匹配导致数据提取失败。非结构化的风险评估说明则要求插件支持文本解析与关键信息提取能力，适配尽调报告的多类型数据处理需求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `tool_call_max_retries` | `2–3 次` | 农商行尽调数据接口多为内部合规接口，重试次数过多会触发风控拦截 |
| `plugin_cache_ttl` | `86400 秒` | 外部公开数据按季度更新，内部数据每日更新，缓存时长设置为1天平衡调用效率与数据新鲜度 |
| `field_mapping_rule` | 按接口文档预设字段映射 | 农商行尽调数据字段多为标准化但存在接口差异，预设映射可避免字段不匹配 |
| `tool_call_timeout` | `30 秒` | 内部接口响应受合规校验影响，超时设置过短会导致有效调用失败 |
| `plugin_audit_log_enabled` | 开启 | 农商行尽调业务需留存操作日志满足合规要求 |
| `max_tool_call_per_round` | `5 次` | 尽调报告生成需调用不超过5个不同数据源的工具，避免无意义的重复调用 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用本地创建的MCP服务时返回`404 Not Found`错误，原因为未在FastGPT插件配置中填写本地服务的局域网访问地址与端口映射规则。
- 开启工具调用后，模型输出仅包含工具调用参数，无自然语言思考过程，原因为未开启`tool_call_think_step`配置项，或模型版本不支持带思考的工具调用格式。
- 调用外部数据源接口返回的尽调数据条数与预期不符，原因为未正确设置`max_tool_return_items`参数，或字段映射时遗漏了部分必填字段。

## 怎么确认配好了
- 发起一次测试调用，查看FastGPT的插件调用日志，确认接口请求参数与预设的字段映射规则一致。
- 对比工具返回的原始数据与尽调报告中提取的字段，确认单位与字段名称匹配。
- 检查审计日志是否完整记录了每次工具调用的时间、参数与返回结果。
- 模拟高频调用场景，确认工具调用的重试与缓存逻辑符合预设配置。
