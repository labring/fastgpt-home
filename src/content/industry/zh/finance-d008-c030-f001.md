# 化妆品智能尽调报告的HTTP 接口与外部系统

## 这个品类的数据长什么样
化妆品智能尽调的数据源主要来自国家药品监督管理局化妆品备案公开数据库、第三方合规检测机构报告、品牌方官方公示资料。数据更新节奏：备案信息随产品上市备案完成实时更新，检测报告随每批次产品送检结果更新，电商平台商品参数每日同步。文档以结构化表格为核心载体，包含产品备案编号、产品名称、品牌归属、生产企业信息、成分清单、备案状态、有效期限等字段，成分清单字段仅标注国际化妆品原料名称（INCI），无额外量化标注，各字段均为字符串或枚举值类型。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源异构的数据源要求HTTP接口支持自定义请求头与响应解析模板，适配不同数据源的返回格式；唯一的产品备案编号作为核心标识，要求接口支持精准查询参数，避免批量拉取时的数据重复；不同数据源的更新节奏差异，要求配置差异化的定时同步周期，区分备案数据与检测数据的拉取频率；成分清单无量化标注的特征，要求接口无需传递含量相关的请求参数，简化请求体结构；批量尽调场景下单批次产品数量较多，要求HTTP接口支持分页请求与并发控制参数，避免单次请求过载或触发接口限流。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `apiRequestTimeout` | 600 秒 | 化妆品尽调数据需对接多源接口，单次请求包含多组数据源查询，较长超时时间避免中途中断 |
| `batchTaskConcurrency` | 5-8 | 化妆品数据源接口多为企业级合规接口，并发过高会触发限流，该取值适配多数合规接口的调用限制 |
| `requestRetryTimes` | 3 次 | 合规数据源接口偶发网络波动，有限重试可降低批量任务失败率 |
| `responseParseTemplate` | 按备案编号、产品名称、成分清单字段映射 | 化妆品尽调数据的核心字段固定，模板化解析可统一结构化输出格式 |
| `batchRequestPageSize` | 10 条/页 | 单页数据量过大易触发接口限流，该取值适配多数化妆品备案接口的分页限制 |
| `authType` | API 密钥鉴权 | 化妆品合规数据接口需身份验证，API 密钥鉴权符合行业合规要求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：批量执行节点在线调试正常，但通过API调用时任务执行不完整。原因：未配置`batchTaskConcurrency`参数，API调用时默认并发数与在线调试环境不一致，触发数据源接口限流。
- 现象：接口调用工作流后，对话日志中运行数据为空。原因：未开启`responseParseTemplate`的字段映射配置，接口返回的原始数据未被结构化提取，导致日志无有效运行数据。
- 现象：开启文件上传功能的API接口无法接收外部传入的化妆品备案文档。原因：未配置`UPLOAD_FILE_ALLOW_EXT`参数允许PDF、Excel格式的备案报告，外部文档无法被接口识别。

## 怎么确认配好了
- 发起单款化妆品的API调用，检查返回结果中是否包含预设的核心字段，核对字段映射是否与配置的`responseParseTemplate`一致。
- 提交批量任务，查看接口返回的状态码，确认未出现429 Too Many Requests错误，调整`batchTaskConcurrency`参数至符合当前接口限流要求。
- 上传化妆品备案报告文档至API接口，检查文件是否被成功解析并纳入尽调数据，确认`UPLOAD_FILE_ALLOW_EXT`参数覆盖对应文件格式。
- 模拟接口调用失败场景，检查是否触发`requestRetryTimes`配置的重试机制，确认任务自动恢复执行。
