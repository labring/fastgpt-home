# 医美智能尽调报告的多轮对话与提示词

## 这个品类的数据长什么样
医美尽调数据主要来自医美机构的执业备案材料、当地卫健部门的医美项目公示数据库、医生执业资质档案、耗材供应商的溯源文件，以及行业协会的合规检查记录。更新节奏为机构自行报备的材料实时更新，监管公示信息每季度同步。文档结构分为资质类、项目类、人员类、耗材类四个模块，每个模块包含唯一编码字段、生效日期字段、有效期字段，字段多为字符串格式的编号或日期格式，无数值型量化字段。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
医美尽调数据分四大模块且含唯一编码与日期字段，要求多轮对话需按模块拆分提问并保留上下文关联，避免跨模块混淆。字段多为编码与日期格式，提示词需明确指定每个字段的提取规则，防止生成不符合格式的内容。数据更新节奏分实时与季度同步，对话中需支持确认数据的最新同步状态，避免使用过期备案信息。模块间存在关联关系，如医师资质与执业机构需绑定，多轮对话需允许回溯之前的查询结果完成关联校验。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxHistory` | 前3条对话 | 医美尽调数据分为四大模块，3条上下文可覆盖资质、项目、人员的关联查询，避免冗余信息干扰 |
| `contextTokenLimit` | 8000–12000 字符 | 单份医美尽调文档约2000-3000字符，多模块关联查询需保留2-3份文档的上下文，该区间可覆盖需求且避免token溢出 |
| `promptTemplate` | 按模块提取医美尽调字段，资质类需包含执业许可证号与有效期，项目类需包含备案编号与生效日期，日期格式为YYYY-MM-DD | 医美尽调字段格式明确，模板可约束生成结果的格式与模块划分，避免混淆不同类别的数据 |
| `historySaveDuration` | 90 天 | 医美监管公示信息每季度更新，90天可覆盖最新的季度更新周期，同时避免过期数据占用存储 |
| `fileParseTimeout` | 300 秒 | 医美尽调文档多为多页合规材料，解析时长较长，300秒可覆盖完整解析流程 |
| `UPLOAD_FILE_MAX_SIZE` | 100 MB | 医美尽调文档多为扫描件或PDF，单份大小通常不超过50MB，该取值可覆盖多数场景 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中配置文件上传节点后，调用文档解析工具报错。原因：未调整`UPLOAD_FILE_MAX_SIZE`参数，上传的医美尽调文档大小超出默认限制。
- 现象：多次使用同一ID访问工作流，第一个模型调用的上下文未保留有效信息。原因：`maxHistory`参数设置为1，仅保留最后1轮对话，无法关联之前的查询条件。
- 现象：生成的尽调报告中日期字段格式混乱，包含中文日期或错误的数值。原因：未配置针对性的`promptTemplate`，未明确指定日期格式要求。

## 怎么确认配好了
- 上传单份医美尽调文档，触发工作流运行，核对对话上下文是否保留了预设轮次的历史信息。
- 发起多轮关联查询，核对模型生成的尽调字段是否符合预设的格式与模块划分规则。
- 查看对话历史管理界面，核对已保存的对话记录是否在预设的时长范围内。
- 上传符合常规大小的医美尽调文档，验证文档解析流程无报错，生成结果完整。
