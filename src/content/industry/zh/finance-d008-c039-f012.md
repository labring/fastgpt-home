# 厨卫电器智能尽调报告的模型接入与配置

## 这个品类的数据长什么样
厨卫电器的智能尽调数据来源包括品牌官方公开的产品规格书、电商平台的商品详情页参数、第三方质检机构的检测报告、售后维修的故障记录。数据更新节奏为新品上市时全量更新机型参数，固件升级时更新功能参数，日常无重大变更时每季度同步一次。单机型参数文档结构分为基础信息、核心参数、功能模块、售后信息。字段与单位包括额定功率（瓦）、外形尺寸（毫米）、能效等级（1级、2级、3级、噪音（分贝）、净重（千克）。

## 这些特征在「模型接入与配置」这一环带来什么约束
多源数据的格式差异要求配置统一的字段映射规则，对齐不同来源的参数字段，避免格式不一致导致模型解析错误。更新节奏不固定，要求配置定时同步任务与手动触发更新的开关，适配新品或固件升级后的参数更新。机型文档长度差异大，部分机型的功能参数较多，要求配置动态分段长度，适配长文档的拆分，避免拆分过细导致上下文割裂。多单位字段要求配置单位自动识别与转换规则，确保模型能正确解析功率、尺寸等参数的单位。精准的参数校验要求配置召回规则，仅召回与目标机型相关的核心参数，避免冗余内容干扰模型判断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `chunkSize` | 800–1200 字符 | 厨卫电器参数文档多为结构化内容，该长度可完整覆盖单组核心参数，避免拆分过细导致上下文割裂 |
| `retrievalTopK | 前6–8条 | 智能尽调需精准匹配机型参数，召回过多会引入无关内容，过少则无法覆盖全部核心参数 |
| `similarityThreshold` | 0.75–0.85 | 机型型号匹配要求较高，该阈值可过滤非目标机型的参数内容，提升查询精度 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 单份参数文档包含多组结构化参数，该时长可避免解析超时 |
| `UPLOAD_FILE_MAX_SIZE` | 20 MB | 厨卫电器参数文档包含规格书与质检报告，该大小可容纳完整的单机型文档 |
| `autoUnitConversion` | 按实测标定 | 适配多源数据的单位差异，确保模型正确解析功率、尺寸等参数的单位 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用模型后出现上下文溢出报错，或返回内容为空。原因：未正确配置`maxContext`参数，导致多轮对话中累积的上下文超过模型支持的最大长度，引发异常。
- 现象：混合检索耗时超过10秒，无法在商用场景下使用。原因：未调整`retrievalTopK设置过高，同时未配置`rerankTopK参数，导致召回与重排的计算量过大，超出响应超时。
- 现象：解析后的参数文档出现字段缺失或格式混乱。原因：未开启字段映射配置，未对齐不同来源的参数字段，导致多源数据的字段无法正确匹配。

## 怎么确认配好了
- 上传单机型参数文档，查看解析后的分段内容，确认分段长度符合`chunkSize`的配置，检查是否完整覆盖核心参数。
- 发起针对特定机型的参数查询，查看召回的结果条数符合`retrievalTopK`的设置，检查相似度是否符合`similarityThreshold`的阈值。
- 模拟多轮对话，检查模型是否能正确识别参数的单位，确认不同来源的参数字段已正确映射。
- 上传一份较大的参数文档，查看解析耗时是否在`PARSE_FILE_TIMEOUT_SECONDS`的范围内。
