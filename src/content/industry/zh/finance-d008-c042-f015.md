# 品牌代运营智能尽调报告的部署与升级

## 这个品类的数据长什么样
品牌代运营智能尽调报告的数据来源包括品牌方电商后台销售数据、社交媒体舆情数据、第三方竞品监测工具公开数据、品牌方线下运营记录。数据更新节奏为每日同步核心销售指标，每周输出阶段性运营周报，每月生成完整尽调报告。文档结构固定分为品牌基础信息、销售表现分析、舆情监测、竞品对比、合规风险、优化建议六大模块，字段包含`GMV`（单位：万元）、`舆情提及量`（单位：条）、`合规违规次数`（单位：次）、`代运营服务周期`（单位：月）等，部分自定义字段需适配不同品牌客户的需求。

## 这些特征在「部署与升级」这一环带来什么约束
多源数据接入的需求要求部署时配置跨平台数据拉取的权限与格式适配规则；每日/每周的更新节奏要求配置精准的定时同步任务，避免数据滞后或重复拉取；长文档与多附件的报告结构要求调整大文件处理与解析的超时设置；自定义字段的适配需求要求部署时预留字段映射的配置入口，升级时需兼容不同客户的字段差异。此外，品牌代运营的报告需同时支持内部使用与客户交付，部署时需配置双格式导出的相关参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 月度尽调报告通常包含多份附件，单份报告文件体积可达1.5GB左右 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `900 秒` | 长文档解析需处理大量表格与舆情数据，避免超时中断 |
| `DATA_SYNC_INTERVAL` | `86400 秒` | 销售数据需每日同步更新，确保报告数据时效性 |
| `MAX_CONTEXT_LENGTH` | `120000 字符` | 尽调报告正文通常包含8-12万字的分析内容，需适配长文本处理 |
| `CUSTOM_FIELD_MAPPING_ENABLE` | 开启 | 不同品牌代运营客户的报告字段存在差异，需支持自定义字段映射 |
| `REPORT_EXPORT_FORMAT` | `docx + pdf` | 品牌代运营客户通常需要两种格式的报告用于内部汇报和客户交付 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 执行`docker build`时报错`failed to solve: failed to comput`，原因是未正确挂载品牌代运营的数据源配置目录，导致构建时无法读取预置的字段映射规则文件。
- 部署后处理尽调报告时出现`413 Request Entity Too Large`状态码，原因是未调整`UPLOAD_FILE_MAX_SIZE`参数，导致超过默认限制的大文件无法上传。
- 本地部署后运行速度缓慢，原因是未开启长文本批量处理优化，同时未配置本地缓存加速多源数据拉取。

## 怎么确认配好了
- 上传一份模拟的月度尽调报告文件，检查上传进度条是否正常完成，无中断提示。
- 执行一次手动数据同步任务，核对同步后的销售数据字段与品牌方后台导出的格式一致。
- 触发一次报告导出任务，确认生成的docx和pdf文件包含所有配置的自定义字段。
- 查看系统日志，确认定时同步任务按配置的间隔自动执行，无报错记录。
