# 商业物业智能尽调报告的部署与升级

## 这个品类的数据长什么样
商业物业智能尽调报告的数据来源包括属地住建部门备案系统、物业方月度租金台账、水电能耗缴费凭证、周边商圈客流监测数据、不动产产权登记文件。更新节奏存在差异：租金台账月度更新，产权信息每季度更新，周边客流数据周度更新。单份报告通常包含产权概况、租金流水、运维记录、周边配套四个核心模块，每个模块下有细分字段。字段与单位遵循行业通用规范：建筑面积以平方米为单位，单月租金以元/平方米/月为单位，产权登记编号为带字母和数字的组合字符串，能耗数据以千瓦时为单位。

## 这些特征在「部署与升级」这一环带来什么约束
多来源、不同更新节奏的数据要求部署阶段配置多数据源同步规则，需区分全量与增量同步的触发逻辑，避免资源浪费。长文档结构要求适配的切片与上下文参数，确保核心模块信息不被割裂。多字段的文档结构要求知识库字段映射规则与报告模块一一对应，避免数据混乱。第三方客流数据的接入需配置稳定的重试与超时机制，应对外部接口的不稳定情况。升级阶段需兼容旧版同步脚本，确保不同更新节奏的数据链路不中断，同时需新增敏感信息过滤规则，符合数据合规要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 商业物业尽调报告单份常达数十页，单文件体积通常不超过1000MB |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 长文档解析需较长时间，避免因超时中断解析流程 |
| `maxContext` | `8000–12000 字符` | 适配长文档切片后的上下文关联，覆盖完整模块信息 |
| `召回条数` | `前 8–10 条` | 商业物业数据字段多，需足够召回量覆盖核心模块内容 |
| `增量同步间隔` | `3600 秒` | 匹配租金台账月度更新的最小粒度，兼顾实时性与资源消耗 |
| `敏感词过滤规则` | `按产权、业主信息触发过滤` | 避免敏感字段泄露，符合数据合规要求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：文件上传后解析失败，界面显示`504 Gateway Timeout`错误。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，长文档解析超出默认超时限制。
- 现象：知识库召回结果无法覆盖租金流水模块，核心数据未被检索到。原因：设置的`召回条数`参数过低，未匹配商业物业报告的多字段需求。
- 现象：所有模型调用均报错，无法正常生成尽调报告。原因：未配置第三方客流数据接口的密钥，或密钥过期导致数据链路中断，引发连锁报错。

## 怎么确认配好了
- 上传一份标准商业物业尽调报告，检查解析进度是否在设定的超时时间内完成。
- 发起一次针对报告核心模块的问答，核对召回结果是否覆盖产权、租金、运维、周边四个模块。
- 查看数据源同步日志，确认增量同步任务按设定间隔自动触发并完成数据更新。
- 测试团队成员权限配置，确认成员可访问部署后的尽调报告应用并调用相关功能。
