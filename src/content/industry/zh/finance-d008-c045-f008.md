# 商用车智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
商用车智能尽调的数据来源包括车载T-BOX终端、车管所机动车登记系统、货运调度平台、线下维修厂管理系统。数据更新节奏覆盖实时（位置、油耗）、小时级（运营时长、订单数据）、日级（维保记录、违章数据）。文档结构分为结构化台账与非结构化附件，结构化字段包含车辆识别码VIN、总质量（单位kg）、轴距（mm）、运营时长（小时）、违章次数（次），非结构化附件包括维修工单、年检报告、货运合同。

## 这些特征在「工具调用与插件」这一环带来什么约束
多数据源跨域关联的需求，要求工具调用需同时对接登记系统、运营平台、维修系统三类接口，单次调用需处理多接口响应拼接。实时与日级混合更新的数据，要求工具调用的缓存策略需区分字段类型，避免缓存过期或数据过时。商用车专属的合规字段如总质量、轴荷限值，要求工具调用的入参与出参需匹配专属字段定义，避免通用字段无法覆盖尽调需求。VIN作为唯一标识的特性，要求工具调用需强制绑定VIN作为查询入参，避免不同车辆的数据混淆。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `tool_call_timeout` | 300–600 秒 | 商用车尽调需跨多数据源查询，单次工具调用需覆盖多接口响应时长，避免中途超时中断 |
| `max_tool_calls_per_round` | 3–5 次 | 商用车尽调需依次查询维保、违章、运营、登记四类数据，合理控制调用次数避免链路负载过高 |
| `plugin_cache_ttl` | 1800 秒 | 商用车运营数据更新频率为小时级至日级，该缓存时长匹配数据更新周期，兼顾时效性与接口调用成本 |
| `required_input_fields` | `["vin", "vehicle_license_plate"]` | 商用车以VIN与车牌作为唯一标识，强制要求输入可避免多车辆数据混淆，提升查询精准度 |
| `rerank_top_k` | 5–8 条 | 商用车尽调文档包含多维度字段，重排后保留Top 5-8条结果可确保核心合规与运营信息不遗漏 |
| `custom_tool_schema` | 按商用车专属字段定义 | 需匹配总质量、运营时长等专属字段，确保工具调用参数符合数据源格式要求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工具调用返回`400 Bad Request`错误，日志显示`missing_required_param`字段。原因：未配置`required_input_fields`强制校验VIN与车牌，导致多车辆数据无法精准匹配。
- 现象：工具调用返回的运营数据与最新记录不符，结果滞后超过24小时。原因：`plugin_cache_ttl`设置为86400秒，超过商用车数据日级更新周期，缓存未及时刷新。
- 现象：工作流中工具调用未按分类后的场景触发，所有分支调用同一套工具。原因：未配置条件触发参数，导致工具调用逻辑未绑定对应分类分支。

## 怎么确认配好了
- 输入测试用的商用车VIN与车牌，触发工具调用，检查返回结果是否包含对应车辆的维保、违章与运营数据。
- 查看工具调用详细日志，确认每次调用的入参均包含`vin`与`vehicle_license_plate`字段。
- 手动更新测试车辆的运营数据，调整`plugin_cache_ttl`为1800秒，验证工具调用返回最新数据。
- 触发多轮工具调用流程，确认在`max_tool_calls_per_round`设置范围内，未出现链路超时或调用中断。
