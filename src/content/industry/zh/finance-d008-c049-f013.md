# 基建工程智能尽调报告的知识库检索与召回

## 这个品类的数据长什么样
基建工程智能尽调报告的数据主要来源于工程立项审批文件、施工图设计文件、施工日志、监理月报、造价结算书及招投标档案。数据更新节奏随项目阶段变化，立项阶段一次性同步基础信息，施工阶段按月更新进度与成本数据，竣工后归档最终结算资料。单份尽调报告文档结构包含项目基本信息、参建单位资质、进度节点、材料用量清单、造价明细等字段，单位多采用万元、日历天、立方米、吨等工程行业标准单位。

## 这些特征在「知识库检索与召回」这一环带来什么约束
基建工程尽调数据的多来源异构特征，要求检索环节支持跨格式文档的统一字段解析，避免因文档结构差异导致关键信息丢失。单份文档篇幅较长且包含大量细分字段，要求召回环节优先匹配项目编号、参建单位资质、造价明细等核心检索字段，同时需限制单段召回长度，避免冗余信息干扰。数据更新节奏随项目阶段动态变化，要求召回逻辑支持按项目进度节点过滤有效数据，防止召回过期的施工日志或未结算的造价数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 基建工程文档多包含长表格与工程图纸，解析耗时较长，300秒可覆盖多数大型项目归档文档的解析需求 |
| `maxContext` | `1000–1500 字符` | 基建工程核心检索内容多集中在段落与表格行，该区间可保留完整的造价明细或进度节点信息，避免截断关键数据 |
| `召回条数` | `前 8 条` | 基建工程尽调报告的核心信息分散在多个文档片段，8条可覆盖参建单位、进度、造价等多维度检索需求 |
| `相似度阈值` | `0.72–0.8` | 基建工程专业术语较多，较低阈值易引入无关文档，较高阈值可能遗漏相关监理报告内容，该区间可平衡召回精度与覆盖范围 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 单份基建工程归档文档可能包含多份图纸与附件，500 MB可覆盖多数中型以上项目的资料导入需求 |
| `分段长度` | `800 字符` | 基建工程文档的专业表述连贯性较强，800字符的分段可保留完整的技术说明或造价条款 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：配置知识库后返回418错误，前端界面显示知识库加载失败。原因：未正确配置`UPLOAD_FILE_MAX_SIZE`参数，基建工程的大型归档文档超出默认限制，导致系统拒绝加载文档。
- 现象：检索结果仅返回少量条目，且未包含参建单位资质相关内容。原因：未调整`相似度阈值`至合理区间，误将专业术语匹配的阈值设为过高，过滤了相关监理报告文档。
- 现象：导入微信公众号文章后无法检索到有效内容。原因：未开启结构化解析配置，默认解析仅提取纯文本，丢失了文章内的项目进度表格与造价明细字段。

## 怎么确认配好了
- 上传一份典型的基建工程尽调文档，查看解析后的字段列表，确认参建单位、造价明细等核心字段被正确提取。
- 发起一次针对专业术语的检索，核对返回结果的匹配度，调整`相似度阈值`至符合业务需求的区间。
- 上传一份更新后的项目文档，查看知识库的更新记录，确认增量更新逻辑按预设规则触发。
- 检查知识库的资源使用情况，确认当前导入的文档未超出配置的存储与数量限制。
