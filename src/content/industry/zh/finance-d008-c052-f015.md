# 多元控股智能尽调报告的部署与升级

## 这个品类的数据长什么样
多元控股智能尽调报告的数据来源涵盖集团内部各子公司的财务台账、股权穿透文档、关联交易记录，以及外部工商公示、监管披露公告。数据更新节奏以季度财报周期为基础，伴随股权变更、重大交易等临时事件触发更新。文档结构包含结构化的股权比例表、财务明细表格，以及非结构化的公告PDF、关联方说明文件。核心字段包括持股主体名称、持股比例、子公司营收规模、关联交易金额、股权变更日期，单位涵盖百分比、万元、日期格式。

## 这些特征在「部署与升级」这一环带来什么约束
多元控股的多源异构数据结构与较大的数据体量，对部署环节的文件解析适配性提出更高要求。不同子公司的文档格式差异较大，需预设多种解析规则适配不同子公司的上报格式。数据更新频率包含固定周期与临时触发，部署时需配置增量同步机制避免全量重跑占用过多资源。升级环节需兼容历史尽调数据集的解析逻辑，避免因版本更新导致旧数据解析失效。同时，控股类尽调涉及的关联交易、股权穿透等复杂关联逻辑，需在升级后验证插件系统的关联查询能力，确保数据关联关系正确。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 多元控股的尽调报告通常包含多份子公司文件，单文件解析耗时较长，默认超时时间不足以完成完整解析 |
| `UPLOAD_FILE_MAX_SIZE` | `1000 MB` | 控股类尽调报告可能包含多份财报、公告的批量文件包，单批次上传体积远超常规单公司尽调场景 |
| `maxContext` | `8000–12000 字符` | 尽调报告的关联逻辑需要更长的上下文关联，避免关键的跨子公司关联信息被截断 |
| `召回条数` | `前 15 条` | 控股类尽调涉及多维度关联数据，需召回足够多的关联片段支撑跨主体的推理分析 |
| `相似度阈值` | `0.75–0.85` | 平衡关联数据的精准度与召回完整性，避免遗漏跨子公司的潜在关联信息 |
| `PLUGIN_RUN_TIMEOUT` | `120 秒` | 股权穿透、关联交易查询等插件逻辑需遍历多份子公司数据，默认超时时间无法覆盖完整流程 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：升级至4.9.13及以上版本后，模型对话返回结果末尾出现`[参考规则]`类符号。原因：新版本默认开启了规则追溯展示开关，未关闭全局配置中的`SHOW_REFERENCE_RULE`项。
- 现象：本地部署4.10.0版本的插件系统后，提示minio存储无法访问。原因：4.10.0版本将minio作为插件存储的默认依赖，要求服务可被公网访问以完成插件分发，内网环境未配置内网穿透或替代存储方案。
- 现象：本地部署的AIproxy调用Gemini API时返回403错误。原因：未正确配置API密钥的权限范围，或未适配Gemini的接口版本参数，导致请求被拦截。

## 怎么确认配好了
- 上传一份包含多份子公司财报的批量文件包，检查解析任务状态为`成功`，且结构化字段如持股比例、营收规模被正确提取。
- 触发一次增量同步任务，确认仅更新了近7天内的临时公告数据，未全量重跑历史数据集。
- 调用插件系统执行股权穿透查询，检查返回结果包含关联子公司的完整信息，无字段缺失或关联错误。
- 查看模型返回结果，确认末尾未出现额外的规则展示符号，且上传的多模态文件被正确识别并引用。
