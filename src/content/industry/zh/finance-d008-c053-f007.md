# 多元金融智能尽调报告的工作流编排

## 这个品类的数据长什么样
这个品类的数据主要来源于监管机构公开披露的非银金融机构报送文件、标的主体官方披露文档、第三方征信机构合规数据及尽调团队现场访谈转写文件。常规披露文件按季度、年度更新，临时公告随事件触发更新，现场访谈数据按需提交。文档包含结构化财务数据表、非结构化访谈纪要、质押担保类扫描件、关联方关系图谱等模块。结构化字段包含统一社会信用代码、净资产、关联方数量等，其中净资产单位为万元，关联方数量为整数，扫描件多为PDF或图片格式。

## 这些特征在「工作流编排」这一环带来什么约束
多元金融尽调数据的多源分散特性，要求工作流配置多源数据接入节点，适配结构化数据表、非结构化文本、图片扫描件等多种格式。数据更新存在定时触发与事件触发两种场景，需支持定时调度与Webhook触发两种工作流启动方式。单份文档长度跨度大且包含图片类附件，需配置自适应分段解析参数，搭配OCR节点处理扫描件。字段存在固定单位要求，需配置标准化字段映射规则，确保提取的字段符合监管披露的标准格式，避免单位不匹配。批量处理多份尽调报告时，需合理配置并发执行参数，避免资源过载。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 多元金融尽调报告包含长文档及图片扫描件，解析耗时较长，600秒可覆盖绝大多数常规场景 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 单份完整版尽调报告可能包含多份附件，总大小可达较高阈值，2000 MB可满足批量处理需求 |
| `context_scope` | `current_node` | 多元金融尽调报告的节点处理需聚焦当前环节的解析结果，避免全局上下文干扰字段提取准确性 |
| `BATCH_CONCURRENCY_LIMIT` | `3–5 个并发` | 批量处理多份尽调报告时，过多并发会触发接口限流，3-5个可平衡处理效率与资源占用 |
| `OCR_ENABLED` | `true` | 尽调报告包含质押公告、现场照片等图片格式附件，需通过OCR提取文本内容 |
| `FIELD_MAPPING_RULE` | `按监管披露字段匹配` | 多元金融尽调报告的字段需符合监管披露的固定格式，确保提取的净资产、担保金额等字段单位统一 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用工作流API上传图片解析时返回参数错误，或解析结果为空。原因：未以form-data格式传递图片文件，或未正确匹配接口要求的文件字段名。
- 现象：大模型节点提取的尽调字段混入历史任务数据，与当前输入不符。原因：未限定上下文范围为当前节点，使用全局上下文导致不同任务的数据串扰。
- 现象：工作流节点返回`500 Gateway forwarding error because service is disconnected`报错。原因：配置的大模型服务连接中断，或节点调用超时未配置自动重试逻辑。

## 怎么确认配好了
- 上传一份符合常规规模的尽调报告附件，验证OCR节点能否正确提取图片中的文本内容。
- 配置单节点测试运行，确认大模型节点仅使用当前输入的上下文完成字段提取，无历史数据串扰。
- 提交批量任务，观察工作流的并发执行数量是否符合预设的资源配置要求。
- 调用工作流API传递图片文件，验证接口能否正常接收参数并返回预期的解析结果。
