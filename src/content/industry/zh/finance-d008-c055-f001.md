# 大气治理智能尽调报告的HTTP 接口与外部系统

## 这个品类的数据长什么样
金融领域大气治理智能尽调报告的数据来源包括属地生态环境监测平台、企业治污设施PLC运行数据、第三方大气巡检报告，为金融机构授信审批提供支撑。更新节奏为小时级实时数据与日度汇总数据结合，单份报告覆盖多个监测点位的完整信息。文档结构包含点位基础信息、污染物监测数据、治污设施运行参数、区域大气治理项目明细。字段含点位编码、污染物浓度、设备运行时长、达标判定标识等，其中污染物浓度单位为μg/m³，运行时长单位为小时，达标判定为布尔型标识。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
金融领域大气治理尽调数据的多源异构特性要求HTTP接口支持自定义字段映射，适配不同数据源的命名差异，满足金融机构的标准化数据要求。小时级更新的实时数据场景下，接口需具备高频调用兼容性，同时超时设置需覆盖多源数据拉取的整体耗时，避免影响授信审批流程。单份报告包含多点位多类型数据，接口需支持按点位ID、时间粒度筛选返回内容，减少传输冗余，降低金融系统的存储压力。此外，字段单位的标准化要求需在接口层强制校验，避免非标准单位导致外部系统解析异常，同时需适配不同外部系统的鉴权规则，符合金融机构的安全合规要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `HTTP_REQUEST_TIMEOUT` | 600 秒 | 大气治理数据多来自多源异构系统，部分老旧监测平台响应较慢，超时设置需覆盖全量数据拉取场景 |
| `FIELD_MAPPING_RULE` | 按点位编码、污染物类型映射 | 大气治理数据含多类污染物与点位，自定义映射可适配不同数据源的字段命名差异 |
| `RESPONSE_UNIT_CHECK` | 开启强制校验 | 避免非标准单位（如mg/m³替代μg/m³）导致外部系统解析异常 |
| `API_AUTH_TYPE` | 混合鉴权（API密钥+签名） | 部分企业治污设施系统采用签名校验，监管平台采用API密钥，适配多源接入需求 |
| `ERROR_RETRY_TIMES` | 3 次 | 高频拉取小时级数据时，临时网络波动可能导致请求失败，重试可降低数据缺失率 |
| `DATA_FILTER_BY_TIME` | 按小时/日粒度筛选 | 匹配大气治理数据的更新节奏，避免拉取冗余历史数据 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用外部大气监测平台接口返回`401 Unauthorized`，原因：未适配海外版平台的鉴权协议，错误使用国内版的API密钥配置逻辑。
- 现象：部署后关联数据库接口返回`1045 Access denied`，原因：未正确配置数据库连接参数，未添加部署节点的IP到数据库访问白名单。
- 现象：外部系统接收的尽调数据中污染物浓度字段为空，原因：未配置`FIELD_MAPPING_RULE`，未将数据源的原始字段正确映射为尽调报告所需的标准字段。

## 怎么确认配好了
- 调用配置好的HTTP接口，拉取单点位的小时级数据，核对返回字段是否包含标准的点位编码、污染物浓度及对应单位。
- 模拟高频请求（每10秒1次），检查接口响应状态码均为`200 OK`，无连续超时报错。
- 对接企业内部SCADA系统，验证自定义字段映射规则是否将数据源的原始字段正确转换为尽调报告所需的标准字段。
- 触发错误重试逻辑，模拟临时网络中断，检查接口自动重试后可正常返回完整数据。
