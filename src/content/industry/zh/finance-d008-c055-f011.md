# 大气治理智能尽调报告的文档解析与分块

## 这个品类的数据长什么样
大气治理智能尽调报告的数据来源包括环保主管部门公开的监测公报、大气治理企业报送的运行台账、第三方检测机构的现场检测报告、项目环评及整改批复文件。数据更新节奏依类型区分：监测类数据按月或季度更新，项目类台账按年度更新，环评与批复文件为一次性提交并附带后续整改补充文档。文档结构包含结构化的污染物浓度报表、半结构化的治理设施运行日志、非结构化的技术方案与整改说明，字段涵盖污染物浓度（单位为mg/m³）、治理设施运行时长（单位为小时）、项目总投资（单位为万元）等，部分文档附带监测数据可视化图表。

## 这些特征在「文档解析与分块」这一环带来什么约束
上述数据特征对文档解析与分块环节形成多重约束。多来源的文档格式差异较大，既有纯文本运行日志，也有复杂表格的监测报表与带图表的环评报告，需适配多种格式的内容解析。不同类型文档的长度跨度大，短则数页的单次检测报告，长则数十页的年度治理方案，分块时需兼顾短文档完整性与长文档检索粒度。特定字段的单位标识固定，解析时需准确识别并保留浓度、时长、金额等单位，避免数据混淆。此外，尽调报告需关联同一点位的多组监测数据，分块时需保留上下文关联，防止跨分块的数据断裂影响检索精度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_TABLE_ENABLE` | 开启 | 大气治理尽调报告包含大量结构化监测报表与台账表格，需完整提取单元格内的污染物浓度、运行时长等数据 |
| `MAX_PARSE_CHUNK_SIZE` | 800–1200 字符 | 大气治理文档既有短至数页的单次检测报告，也有长至数十页的年度治理方案，该区间可平衡上下文完整性与检索精度 |
| `PARSE_IMAGE_OCR_ENABLE` | 开启 | 部分报告包含手绘或导出的监测数据图表，需通过OCR提取图表内的数值与标注信息 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 年度大气治理项目尽调报告可能包含多份附件文件，需支持较大容量的文件上传 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 长文档与多附件组合的解析需更长处理时间，避免因超时中断解析流程 |
| `CHUNK_OVERLAP_RATE` | 10%–15% | 需保留跨分块的上下文关联，避免同一监测点位的多组数据被拆分至不同分块 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为上传PDF格式的监测报告后，解析节点显示「解析失败」且返回状态码413，原因是未调整`UPLOAD_FILE_MAX_SIZE`配置，文件大小超出平台限制。
- 现象为上传结构化监测表格后，解析结果中表格字段为空，原因是未开启`PARSE_TABLE_ENABLE`配置，导致表格内容未被识别提取。
- 现象为长文档分块后，同一治理项目的多组关联数据被拆分至不同分块，原因是`CHUNK_OVERLAP_RATE`设置过低，未保留足够的上下文重叠。

## 怎么确认配好了
- 上传单页结构化监测报表PDF，检查解析结果中是否完整提取表格内的污染物浓度与对应单位，确认`PARSE_TABLE_ENABLE`与`PARSE_IMAGE_OCR_ENABLE`配置生效。
- 上传一份包含监测数据图表的年度整改报告，查看分块结果中是否保留图表旁的技术说明上下文，确认`MAX_PARSE_CHUNK_SIZE`与`CHUNK_OVERLAP_RATE`配置适配文档长度。
- 上传超出常规单页大小的附件文件，检查上传与解析流程是否正常完成，确认`UPLOAD_FILE_MAX_SIZE`配置覆盖目标文件大小。
- 查看解析日志，确认无超时报错，确认`PARSE_FILE_TIMEOUT_SECONDS`配置设置合理。
