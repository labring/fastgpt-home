# 小家电智能尽调报告的多轮对话与提示词

## 这个品类的数据长什么样
金融、保险、理财领域的小家电智能尽调数据主要来源于品牌官方参数页、电商平台商品详情页、国家强制性产品认证（3C）报告、能效标识文件及售后维修手册。数据更新节奏随新品上线调整，常规在售型号的参数每季度更新一次。单份尽调文档包含基础属性、性能参数、合规认证、售后条款四类结构，字段涵盖额定功率（单位：瓦）、产品尺寸（单位：毫米）、整机重量（单位：千克）、认证编号、上市时间等，厨房小家电等细分品类还会包含加热功率、转速等专项参数。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
小家电参数的细分化与多维度特征，要求多轮对话需引导用户聚焦具体SKU型号，避免泛化查询导致的参数匹配错误。单份文档的长度与字段密度，要求提示词需明确指定提取字段的优先级，防止上下文溢出导致的信息丢失。不同型号参数的差异性，要求多轮交互需绑定对应SKU的专属参数库，避免跨型号的参数混淆。合规类字段如3C认证编号为强制提取项，多轮对话需设置确认环节，确保无遗漏。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 小家电尽调文档单篇通常包含2000-5000字符的参数内容，多轮交互需保留完整的参数片段与对话历史 |
| `CHAT_FILE_EXPIRE_TIME` | `7 天（平台默认上限）` | 小家电尽调文件多为临时分析用途，7天过期符合常规使用周期，如需延长需提交调整申请 |
| `PARSE_SEGMENT_LENGTH` | `1000–1500 字符` | 小家电参数包含多维度关联信息，分段过长会破坏参数间的逻辑关联，过短会导致字段拆分不完整 |
| `RECALL_TOP_K` | `前6–8 条` | 小家电参数字段数量较多，需召回足够的关联片段以覆盖基础属性、性能参数、合规认证三类核心内容 |
| `SIMILARITY_THRESHOLD` | `0.75–0.85` | 小家电型号名称相似度较高，需过滤低匹配度的无关参数文档，避免提取错误的型号数据 |
| `LOG_USER_ID_ENABLE` | `开启` | 需绑定用户标识以追踪对应尽调对话的日志，满足后续问题排查与权限管理需求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：对话文件在7天内被自动清理，无法调取历史尽调记录。原因：未调整`CHAT_FILE_EXPIRE_TIME`参数，或设置值超出平台允许的最大上限。
- 现象：批量执行的分工AI对话节点出现参数提取错位，不同型号的小家电参数被混同。原因：未为每个对话节点绑定独立的SKU参数上下文，导致多轮交互的上下文交叉污染。
- 现象：对话日志无法关联到发起尽调的具体用户。原因：未开启`LOG_USER_ID_ENABLE`配置项，导致系统未记录用户标识字段。

## 怎么确认配好了
- 发起一次针对指定小家电型号的多轮对话，检查上下文是否保留了完整的参数片段，无截断或混淆情况。
- 上传小家电尽调文档后，查看解析后的分段内容，确认分段长度符合配置要求。
- 查看对话日志，确认每条记录都关联了对应的用户标识字段。
- 测试批量并行对话节点，确认每个节点返回的参数仅对应指定的小家电SKU，无交叉错误。
