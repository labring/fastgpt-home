# 工程咨询智能尽调报告的文档解析与分块

## 这个品类的数据长什么样
工程咨询的智能尽调报告数据主要来源于建筑装饰类项目的可研文件、造价核算书、现场勘查记录、招投标合规文件等。数据更新节奏随项目阶段推进，可研阶段生成初版报告，施工阶段随进度更新补充内容，竣工阶段生成最终定稿。文档整体结构固定，包含项目概况、造价明细、合规条款、现场检测数据等章节，其中包含大量结构化表格与专业术语字段，单位涵盖平方米、元、天、兆帕等工程专业单位。

## 这些特征在「文档解析与分块」这一环带来什么约束
工程尽调报告的长文本与结构化表格特征，对解析分块环节提出多重约束。首先，单份报告篇幅跨度大，短则数十页长则超百页，分块长度需兼顾上下文完整性与检索效率，不能过短导致专业关联断裂，也不能过长超出模型上下文窗口。其次，报告内包含大量造价表、检测数据表等结构化内容，分块时需避免拆分表格单元，否则会破坏数据关联性。此外，专业字段的单位不统一问题，需在解析阶段完成单位校准，否则分块后的内容会出现单位混乱，影响后续检索与应用。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxChunkSize` | 800–1200 字符 | 工程尽调报告包含大量专业段落与表格片段，该长度可保留单份造价明细或合规条款的完整上下文，避免拆分断裂 |
| `chunkOverlap` | 100–150 字符 | 跨分块的专业术语关联紧密，重叠部分可维持上下文连贯性，减少检索时的信息断层 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 单份大型工程尽调报告文件体积较大，解析流程耗时较长，该时长可覆盖多数常规项目文档的解析需求 |
| `enable_table_parse` | 开启 | 工程尽调报告包含大量结构化造价表、检测数据表，开启后可保留表格原始行列结构，避免解析后内容混乱 |
| `UPLOAD_FILE_MAX_SIZE` | 500 MB | 大型工程的全周期尽调报告文件体积较大，该阈值可覆盖多数常规上传场景 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用FastGPT 4.8.10版本API获取分块内容时，返回结果中无分块索引标识字段。原因：未在系统配置中开启分块索引输出，或API请求参数未指定返回索引字段。
- 现象：上传工程尽调报告后，解析生成的表格数据出现单元格截断或合并错误。原因：未开启`enable_table_parse`配置，或`maxChunkSize`设置过小导致表格被强行拆分。
- 现象：页面触发复制功能时，弹出“无法使用浏览器自动复制，请手动复制下面内容”的提示。原因：部署环境存在跨域限制，或前端脚本未正确绑定复制事件。

## 怎么确认配好了
- 上传预设的测试用工程尽调报告，核对解析生成的分块列表，确认分块长度符合`maxChunkSize`的配置范围。
- 查看解析后的结构化表格内容，确认表格行列结构与原始文档一致，无单元格截断或合并错误。
- 调用对应API接口，确认返回结果包含分块索引相关字段，符合预期配置。
- 在部署环境中测试复制功能，确认无跨域限制导致的异常提示。
