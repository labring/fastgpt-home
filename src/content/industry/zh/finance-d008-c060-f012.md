# 工程咨询智能尽调报告的模型接入与配置

## 这个品类的数据长什么样
工程咨询的智能尽调报告数据主要来源于项目立项审批文件、施工图设计文档、现场勘查记录、造价核算台账、合规性审查报告等。数据更新节奏随项目推进阶段调整，立项初期更新频率较高，施工阶段按节点更新，竣工后归档冻结。文档结构通常包含项目概况、技术参数表、进度节点明细、成本核算条目、合规条款清单、风险提示等模块，字段包含建筑面积、造价、施工周期、合规项编号等，对应单位为平方米、万元、日历天等工程专业单位。

## 这些特征在「模型接入与配置」这一环带来什么约束
工程尽调报告的专业字段与单位要求模型输入需保留结构化信息，因此需配置专属的提示词模板与字段映射规则。文档体积大、分段多的特征，要求调整上传文件大小、解析超时与上下文窗口参数，避免解析失败或上下文截断。数据更新无固定周期的特征，要求配置按项目节点触发的增量同步规则，无需固定周期同步。合规条款与技术参数的精准匹配需求，要求调整相似度阈值与召回条数，确保检索结果的相关性与全面性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 工程尽调报告单份文档常包含多页技术参数与合规条款，需完整加载核心内容以支撑模型推理 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 工程类文档如施工图PDF、勘查测绘文件单体积常达数百MB，需放宽上传上限 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `1200 秒` | 大型工程文档需解析大量嵌套表格与图纸元数据，常规解析耗时远超通用文档 |
| `similarityThreshold` | `0.75–0.85` | 需精准匹配工程专业字段与合规条款，避免召回低相关的通用内容 |
| `topN` | `前 8–10 条` | 工程尽调需覆盖技术、成本、合规多维度数据，过多召回会超出上下文窗口限制 |
| `chunkSize` | `1500–2000 字符` | 工程文档包含长段技术说明与明细条目，需适当加长分段以保留上下文逻辑 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用模型接口返回`400 Bad Request`，提示“模型输入格式错误”。原因：未针对工程尽调报告的专业字段与单位配置专属提示词，导致模型无法正确解析结构化数据。
- 现象：部署后加载大型工程文档时触发`504 Gateway Timeout`错误。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时长不足以完成复杂文档的解析与向量生成。
- 现象：在系统模型选择列表中无法找到通过openapi配置的本地大模型。原因：未在模型接入配置中开启对应渠道的前端可见性，或配置的模型标识与系统内注册的唯一标识不匹配。

## 怎么确认配好了
- 上传一份标准工程尽调报告文档，检查解析后生成的分段内容是否保留了专业字段与单位，可通过解析日志核对分段长度是否符合配置的`chunkSize`范围。
- 发起一次模型调用请求，检查接口返回的响应时长是否在配置的`maxContext`与`PARSE_FILE_TIMEOUT_SECONDS`范围内，无超时报错。
- 在系统模型选择界面查看已配置的模型列表，确认通过openapi接入的本地大模型已显示在列表中，可正常选中并发起测试调用。
- 配置相似度阈值与召回条数后，发起一次知识库检索，检查返回的结果条数与相关性是否符合业务需求，可通过调整参数重新验证。
