# 房建工程智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
房建工程智能尽调的数据主要来自住建部门项目备案系统、施工单位的施工日志与材料检测报告、监理单位的验收记录三类官方与第三方数据源。数据更新节奏随项目阶段变化，开工阶段每周更新施工进度，竣工后完成备案则不再高频更新。单份尽调文档包含项目基本信息、施工进度明细、材料检测报告、造价核算表、验收意见书五个核心模块，字段包含建筑面积（单位：平方米）、工程造价（单位：万元）、开工/竣工日期（格式：YYYY-MM-DD）、监理单位资质编号等，部分字段存在通用缩写与标准名称的变体。

## 这些特征在「工具调用与插件」这一环带来什么约束
房建工程尽调数据的多源异构特性要求工具调用需同时对接住建备案接口、施工单位内部系统与监理数据平台，需为每个数据源配置独立的鉴权参数。阶段性更新的节奏要求插件支持增量拉取模式，避免全量拉取导致的请求体积过大与超时风险。多模块多字段的文档结构要求工具调用需精准指定返回字段，防止冗余数据占用传输带宽与解析资源。字段单位与格式的固定要求插件需内置校验逻辑，对传入的参数与返回的结果进行格式匹配，避免因单位错误或格式不符导致的尽调报告无效。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 房建工程尽调文档通常包含多份施工日志与检测报告，解析耗时较长 |
| `tool_call_timeout` | `600 秒` | 对接多源外部接口时，单次调用需覆盖住建备案、监理数据的拉取与整合时间 |
| `external_tool_max_retries` | `2 次` | 避免重复调用触发外部接口的限流规则，同时保障数据拉取的稳定性 |
| `field_matching_threshold` | `0.85` | 房建工程字段存在相似命名（如「建筑面积」与「规划建筑面积」），需较高的匹配精度 |
| `plugin_request_batch_size` | `5 条/次` | 单次拉取过多项目数据会超出超时阈值，限制批量拉取的数量保障调用稳定性 |
| `response_field_filter` | `指定项目ID、建筑面积、工程造价、验收状态` | 仅返回尽调报告所需的核心字段，减少数据传输与解析的开销 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用MCP插件时返回`504 Gateway Timeout`错误码，工作流节点显示超时。原因：未调整`tool_call_timeout`配置，房建工程多源数据拉取耗时超过平台默认阈值。
- 现象：工作流调用外部插件后返回空的核心字段，尽调报告无法生成有效内容。原因：未配置`response_field_filter`，返回了与尽调需求无关的冗余字段，导致核心数据被过滤或未被正确提取。
- 现象：使用API调试工具调用工作流失败，返回`400 Bad Request`错误码。原因：未复制工作流发布后系统生成的唯一ID，直接使用自定义名称作为调用参数，导致平台无法识别目标工作流。

## 怎么确认配好了
- 进入FastGPT工作流的工具配置页面，查看`tool_call_timeout`与`PARSE_FILE_TIMEOUT_SECONDS`的取值，核对是否覆盖房建工程多源数据拉取的所需时间。
- 发起一次测试调用，查看返回结果的字段列表，确认仅包含`response_field_filter`中指定的核心字段，无冗余内容。
- 调用MCP插件拉取单条房建项目的完整数据，检查是否出现`504 Gateway Timeout`错误码，确认超时配置生效。
- 复制工作流发布后系统生成的唯一ID，使用API调试工具发起调用，确认返回正确的工作流执行状态。
