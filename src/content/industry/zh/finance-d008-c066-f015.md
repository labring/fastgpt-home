# 房建工程智能尽调报告的部署与升级

## 这个品类的数据长什么样
房建工程智能尽调报告的数据主要来源于项目施工日志、监理旁站记录、造价核算文件、规划测绘图纸及竣工验收档案。数据更新随项目进度节点触发，主体结构封顶、外立面施工、竣工结算等关键节点完成后同步更新。单份报告文档长度跨度较大，短则数十页长则数百页，核心字段包含单体建筑面积（单位：㎡）、分项工程造价（单位：万元）、施工周期（单位：天）、隐蔽工程验收编号等，部分字段需关联外部政务审批系统数据。

## 这些特征在「部署与升级」这一环带来什么约束
房建工程尽调报告的长文档跨度、多来源格式及阶段性更新特征，对部署与升级环节提出明确约束。长文档需适配更长的解析超时与上下文窗口配置，避免解析中断或内容截断。多格式混合输入要求部署时预设多种文件解析引擎的联动配置，避免造价Excel、施工日志PDF等不同格式无法统一解析。阶段性更新模式要求升级环节支持增量同步配置，减少全量重跑的资源消耗。关联外部政务审批数据的字段，需在部署时配置接口重试与熔断机制，保障数据拉取稳定性。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
|---|---|---|
| `PARSE_FILE_TIMEOUT_SECONDS` | 600 秒 | 房建工程尽调报告最长可达数百页，完整解析需充足时长，600秒可覆盖绝大多数长文档解析需求 |
| `UPLOAD_FILE_MAX_SIZE` | 1000 MB | 完整竣工档案包含多页图纸与造价明细，1000 MB可覆盖绝大多数项目报告的上传上限 |
| `chunkSize` | 1000–1200 字符 | 房建报告字段密集，分段长度适配该区间可平衡信息完整性与上下文调用效率 |
| `RECALL_TOP_N` | 前 8 条 | 尽调报告核心信息分散在不同章节，8条召回可覆盖主要合规、造价与进度字段 |
| `MODEL_API_TIMEOUT` | 120 秒 | 长文档向量召回后需生成结构化报告，120秒可避免模型调用超时中断 |
| `AUTO_PARSE_ENABLE` | 开启 | 房建报告包含PDF、Excel、CAD导出文件等多种格式，自动解析可适配多类型文件的解析规则 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：上传房建工程尽调报告后显示解析失败，日志包含`File parse timeout`字段。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数至适配长文档的取值，默认超时时长无法完成数百页报告的完整解析。
- 现象：工作流运行时生成`gpt-4o-mini API call failed`日志，但未触发实际模型调用请求。原因：工作流节点的超时配置短于模型生成所需时长，或未正确绑定模型接口的环境变量，导致前置步骤未完成即触发后续逻辑。
- 现象：配置本地推理服务后无法完成模型调用，控制台返回`connection refused`错误。原因：未将模型接入地址配置为服务的实际监听IP与端口，或未开放对应端口的网络访问权限。

## 怎么确认配好了
- 上传一份典型长度的房建工程尽调报告，核对解析状态是否显示完成，查看解析后的文本片段是否包含核心字段。
- 触发一次工作流测试，核对日志中是否无超时或接口调用失败的报错信息，确认模型调用链路正常。
- 检查配置文件或界面设置项，确认`UPLOAD_FILE_MAX_SIZE`、`PARSE_FILE_TIMEOUT_SECONDS`等核心参数的取值符合项目文档的实际需求。
- 接入本地推理服务后，调用测试接口验证模型响应是否正常，确认网络访问与端口配置无误。
