# 服装家纺智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
服装家纺领域的尽调数据来源包括品牌方内部SKU管理系统、第三方面料检测机构、电商平台销售后台、行业协会公开文档。数据分为结构化台账与非结构化文件两类：结构化数据包含款号、面料成分、克重、生产批次、质检编号等字段，单位涉及g/㎡、件、批次编号等；非结构化数据多为多页PDF格式的质检报告、供应链溯源文件。SKU台账数据每周更新，质检报告随生产批次同步更新，销售数据每日更新，行业产能相关数据每季度更新。

## 这些特征在「工具调用与插件」这一环带来什么约束
结构化数据的单位特异性要求工具调用时自动匹配并校验字段单位，避免因单位不匹配导致的参数错误。非结构化的多页PDF质检报告，需要插件集成OCR与结构化解析能力，适配长文档的解析时长与格式。不同数据源的更新节奏差异大，需区分触发工具调用的时机，例如实时调用销售数据、按需调用质检报告解析。数据源分散的特点，要求工具调用支持多API的独立鉴权与批量配置，覆盖全量尽调所需的数据源。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `apiCollection` | 绑定面料检测API、SKU台账API、电商销售API的集合 | 覆盖服装家纺尽调所需的全量数据源 |
| `UPLOAD_FILE_MAX_SIZE` | 200 MB | 适配多页PDF质检报告的上传需求 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 120 秒 | 适配多页PDF的OCR与结构化解析时长 |
| `apiAuthType` | 按各API分别配置API Key鉴权 | 适配不同数据源的独立鉴权规则 |
| `triggerCondition` | 按数据类型触发：结构化查询触发台账API，多模态文件触发OCR解析插件 | 匹配不同数据的调用时机 |
| `unitAutoMatch` | 开启 | 自动校验并匹配面料克重、件数等单位字段，避免参数不匹配错误 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用apiCollection接口返回message: Invalid URL, code: 500。原因：未校验对接的第三方API的域名白名单，或API接口路径配置错误，导致请求无法正常路由。
- 现象：报错InternalError.Algo.InvalidParameter: Multimodal file size is [具体数值]。原因：未配置`UPLOAD_FILE_MAX_SIZE`参数，或上传的质检报告PDF超过默认限制，导致多模态解析失败。
- 现象：工具调用模块的输出无法取消，非预期结果被返回。原因：未配置输出过滤规则，或误将工具的原始调试输出设为必返项，未开启结果截断配置。

## 怎么确认配好了
- 发起单条SKU台账的API调用，检查返回结果是否包含正确的款号、面料成分、克重等字段，且单位匹配预期。
- 上传单页及多页PDF质检报告，检查解析后的结构化字段是否完整，无乱码或缺失。
- 模拟触发不同类型的数据调用，确认仅对应数据源的API被调用，无冗余请求。
- 配置输出过滤规则后，检查工具调用的结果是否仅返回尽调所需字段，无原始调试信息。
