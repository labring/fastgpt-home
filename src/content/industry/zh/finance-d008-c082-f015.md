# 水产养殖智能尽调报告的部署与升级

## 这个品类的数据长什么样
水产养殖智能尽调报告的数据来源包括塘口在线监测设备的实时水质数据、每日饲料投喂与苗种投放台账、季度病害检测报告、区域水产行业协会的收购指导价文档。数据更新节奏：水质数据每小时同步，生产台账每日更新，检测报告与指导价按季度或月度更新。文档结构分为塘口基础信息、周期生产记录、合规检测附件、供应链对接档案，字段包含溶氧浓度（单位mg/L）、pH值、氨氮含量（单位mg/L）、亩均投喂量（单位千克/亩）、亩均养殖产量（单位千克/亩）。

## 这些特征在「部署与升级」这一环带来什么约束
上述数据特征对部署与升级环节带来多重约束。高频实时的水质数据需要适配高并发的向量检索配置，避免同步延迟。多源异构的数据格式，需要在部署时预设适配不同数据源的解析规则，升级时需兼容旧版解析模板并支持新增字段的映射。不同更新节奏的数据源要求配置差异化的同步周期，升级环节需支持动态调整任务调度参数。水产养殖文档常附带高清检测照片与长文本台账，部署时需调整文件上传与解析的超时阈值，升级时需兼容大体积附件的批量处理逻辑。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 水产养殖尽调报告常包含高清检测照片、塘口监控片段，需适配大体积文件上传 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 长周期生产台账与多页合规检测报告需要更长的解析处理时间 |
| `SYNC_TASK_CONCURRENCY` | `8–12` | 每小时同步的水质数据量较大，适度并发可避免数据同步堆积 |
| `RECALL_TOP_N` | `10–15` | 水产养殖尽调数据包含多维度字段，需召回足够数量的结果以覆盖完整塘口信息 |
| `SIMILARITY_THRESHOLD` | `0.72–0.85` | 水质指标（如溶氧、pH）的特征相似度较高，需设置合理阈值过滤无关匹配结果 |
| `PLUGIN_REGISTER_PATH` | `./packages/plugins/register` | 系统插件需按标准路径注册，缺失该文件会导致插件无法正常加载 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：执行docker部署流程后，系统插件配置界面无法正常加载，控制台提示“plugin register file not found”。原因：未在部署目录下创建`packages/plugins/register`文件，或未正确配置`PLUGIN_REGISTER_PATH`参数指向该文件的实际路径。
- 现象：本地部署的工作流配置界面中，添加超过20个节点后，输入节点参数时出现明显卡顿，输入延迟超过1秒。原因：未开启前端节点渲染的懒加载机制，或未限制页面的节点缓存数量，导致大量DOM元素占用前端资源。
- 现象：执行`docker compose pull`升级命令并重启容器后，容器启动失败，日志显示“port already in use”或“missing required env variable”。原因：升级前未停止原有容器导致端口冲突，或未更新`.env`配置文件以适配新版本的参数要求。

## 怎么确认配好了
- 上传单个体积较大的水产检测报告附件，确认上传与解析流程无报错，根据实际附件规格调整对应参数。
- 手动触发一次高频水质数据的同步任务，查看同步日志确认任务执行状态符合预设配置，无堆积或超时提示。
- 进入系统插件配置界面，确认插件列表正常加载，无注册文件相关的报错提示，验证插件注册路径配置正确。
- 拖拽添加多个工作流节点并输入参数，确认页面响应无明显延迟，根据实际节点数量调整前端渲染配置。
