# 水处理智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
这个品类的数据主要来自生态环境部门公开水质监测站数据、水务运营方内部运维系统、第三方检测机构正式报告。更新节奏分为三类：实时水质参数每小时同步，日常运维日志每日归档，合规类检测报告随项目周期或季度更新。单份尽调报告文档结构固定为项目概况、核心水质指标、工艺运行数据、合规检测结果、运维异常记录、整改建议六个章节。核心字段包含COD浓度、总氮浓度、处理规模、污泥含水率，其中浓度类参数单位为mg/L，处理规模单位为立方米每日，含水率以小数形式记录。

## 这些特征在「工具调用与插件」这一环带来什么约束
实时水质参数每小时更新的特征，要求工具调用需配置定时拉取任务，避免使用超过1小时的缓存数据，确保尽调报告的时效性。核心字段带固定单位的特征，要求插件需内置参数校验逻辑，对传入的浓度、规模类参数做单位匹配验证，防止数据误用。固定文档结构的特征，要求工具调用需按预设章节顺序提取内容，避免跨章节抓取导致的字段错位。批量合规报告的处理需求，要求插件支持多文件并行解析，适配不同来源的报告格式差异。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 水处理尽调报告常包含多页检测报告、运维日志，单份文件最大可达500MB，覆盖常见场景 |
| `TOOL_CALL_TIMEOUT` | `300 秒` | 水处理数据拉取、报告解析需耗时较长，300秒可覆盖多数合规报告的解析流程 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120 秒` | 单份水处理报告的文本解析需处理大量表格数据，120秒可完成完整解析 |
| `MCP_TOOL_RETRY_COUNT` | `3 次` | 网络波动或第三方数据源临时不可用，3次重试可降低临时失效的影响 |
| `WORKFLOW_VAR_ENABLE_UPLOAD` | `开启` | 需支持将流程变量绑定至上传参数，适配动态文件调用场景 |
| `TOOL_PARAM_VALIDATE_MODE` | `严格匹配单位` | 水处理数据字段需严格匹配mg/L、立方米每日等单位，避免数据错误 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用MCP工具时返回`504 Gateway Timeout`错误，或提示「工具调用失败」。原因：未配置`MCP_TOOL_RETRY_COUNT`参数，或重试次数设置为0，未覆盖临时网络波动或数据源延迟场景。
- 现象：上传水处理检测报告时提示「文件大小超出限制」，日志中显示`File size exceeds 2097152 bytes`。原因：未修改`UPLOAD_FILE_MAX_SIZE`配置项，沿用默认的2MB限制，无法适配单份大型检测报告。
- 现象：在自定义工作流中配置上传文件参数时，无法选择流程变量作为上传源，仅支持输入文件链接。原因：未开启`WORKFLOW_VAR_ENABLE_UPLOAD`配置项，系统未开放变量绑定至上传参数的功能。

## 怎么确认配好了
- 上传一份符合水处理尽调报告格式的测试文件，检查上传进度与结果，确认文件上传流程正常。
- 调用MCP工具拉取实时水质数据，等待配置的超时时间后查看返回结果，确认未出现超时类报错。
- 在自定义工作流中配置上传参数，尝试绑定流程变量作为上传源，确认变量选项可正常选中并调用。
- 调用工具传入带单位的水处理参数，检查工具返回结果是否正确校验了参数格式与单位。
