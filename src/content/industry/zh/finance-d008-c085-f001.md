# 水泥智能尽调报告的HTTP 接口与外部系统

## 这个品类的数据长什么样
水泥智能尽调报告的数据来自水泥生产企业的窑炉、粉磨设备采集的实时参数、批次质检实验室的检测数据，以及仓储物流的出入库记录，用于金融机构的企业授信尽调场景。生产参数每15分钟更新一次，批次质检数据随每批次生产完成同步生成，库存数据每日更新。文档包含结构化的批次基础信息表、检测参数附件、库存台账，字段包括熟料标号、比表面积、抗压强度、出库量，单位分别为无、平方米每千克、兆帕、吨。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
水泥尽调数据的多类型更新节奏要求接口支持高频短周期请求与批量定时同步两种模式；附件类的质检报告需支持二进制流传输，适配外部系统的文件解析需求；不同标号水泥的动态字段结构要求接口支持灵活的字段映射；企业内部ERP系统的自定义鉴权逻辑，要求HTTP接口适配非标准的鉴权配置，避免对接失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 单批次水泥质检报告及附属检测数据的总大小通常不超过500 MB |
| `PARSE_FILE_TIMEOUT_SECONDS` | `300 秒` | 水泥批次数据包含多份结构化检测附件，完整解析流程需较长耗时 |
| `API_REQUEST_RATE_LIMIT` | `80 次/分钟` | 水泥生产参数每15分钟更新一次，控制速率可避免触发企业外部系统限流 |
| `DYNAMIC_FIELD_MAPPING` | `开启` | 不同标号水泥的检测字段存在差异，需动态适配接口返回的字段映射规则 |
| `AUTH_CUSTOM_HEADER` | `按企业ERP系统要求填写` | 水泥企业内部ERP系统多采用自定义鉴权头，需适配非标准鉴权逻辑 |
| `SCHEDULED_SYNC_INTERVAL` | `86400 秒` | 水泥库存数据为每日更新，无需高频同步 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用外部接口传输水泥尽调数据时返回413状态码。原因：未调整`UPLOAD_FILE_MAX_SIZE`配置，导致单请求数据超过企业系统允许的上限。
- 现象：获取水泥批次检测数据时部分字段为空。原因：未开启`DYNAMIC_FIELD_MAPPING`，无法适配不同标号水泥的动态字段结构。
- 现象：通过HTTP接口获取上传的水泥质检报告文件时，无法直接获取二进制数据流。原因：未启用文件二进制返回配置，仅返回了文件访问链接，未返回原始字节数据。

## 怎么确认配好了
- 发起单次测试请求，传入单批次水泥尽调数据，检查接口返回的状态码是否符合预期，调整`API_REQUEST_RATE_LIMIT`至适配企业系统的取值。
- 上传一份水泥质检报告PDF，调用文件解析接口，检查返回的字段是否覆盖了当前标号水泥的所有检测项，确认`DYNAMIC_FIELD_MAPPING`配置生效。
- 配置定时同步任务，等待一个同步周期后，检查外部系统是否收到了最新的水泥库存数据，调整`SCHEDULED_SYNC_INTERVAL`至匹配数据更新频率的取值。
- 调用鉴权接口，传入自定义请求头，检查是否能成功获取水泥生产参数数据，确认`AUTH_CUSTOM_HEADER`配置正确。
