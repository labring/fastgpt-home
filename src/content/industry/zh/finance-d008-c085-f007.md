# 水泥智能尽调报告的工作流编排

## 这个品类的数据长什么样
水泥尽调报告的数据来源主要包括建材行业协会发布的月度统计公报、水泥厂出厂台账、供应链提货单、第三方质检机构出具的检测报告。数据更新节奏分为两类：出厂批次数据每日更新，行业统计数据按月更新。文档结构通常包含批次编号、强度等级、3天抗压强度、28天抗折强度、供应商名称、生产日期等字段，单位统一采用兆帕（MPa）与标准日期格式，部分报告还会附带质检环节的图像照片。

## 这些特征在「工作流编排」这一环带来什么约束
水泥数据的多字段高精度要求，使得工作流需拆分文本提取、字段校验、多模态适配等独立节点，避免单一节点处理过多内容导致精度下降。每日更新的出厂数据要求工作流支持定时触发拉取，无法依赖静态本地数据源。字段间的关联逻辑（如生产日期与批次编号的匹配），要求工作流内置关联校验环节，防止无效数据进入报告生成环节。多类型数据（文本台账与质检图像）的混合输入，要求工作流支持按数据类型分配不同处理模型。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `900 秒` | 水泥尽调报告多包含多页质检数据与台账，解析耗时较长 |
| `TEXT_EXTRACT_MIN_CONFIDENCE` | `0.85` | 水泥字段精度要求高，需过滤低置信度的提取结果 |
| `WORKFLOW_TRIGGER_CRON` | `0 0 2 * * ?` | 水泥出厂数据每日更新，需定时拉取最新批次数据 |
| `MULTIMODAL_MODEL_SWITCH` | `按输入数据类型自动切换` | 水泥数据包含文本台账与质检图像，需适配不同模型能力 |
| `TOOL_CALL_RETRY_TIMES` | `3 次` | 供应链溯源数据拉取可能因接口波动失败，需设置重试机制 |
| `UPLOAD_FILE_MAX_SIZE` | `50 MB` | 单份完整水泥尽调报告的文件体积通常较大 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：工作流中调用供应链数据接口时返回`504 Gateway Timeout`错误。原因：未设置`TOOL_CALL_RETRY_TIMES`参数，或重试次数不足，导致接口波动时直接失败。
- 现象：文本内容提取节点返回空字段，未触发预设的提示回复。原因：未配置`TEXT_EXTRACT_MIN_CONFIDENCE`阈值，或阈值设置过高，导致正常提取结果被过滤。
- 现象：工作流中同时传入质检图像与文本台账时，纯文本未被分配至工具调用节点。原因：未开启`MULTIMODAL_MODEL_SWITCH`的自动切换规则，导致所有数据被统一分配至单一模型。

## 怎么确认配好了
- 上传一份标准水泥质检PDF文件，查看文本提取节点的输出字段，确认所有必填字段均被正确提取。
- 配置定时触发任务，等待预设时间后查看工作流执行日志，确认任务自动启动并拉取最新数据。
- 分别传入纯文本台账与质检图像，查看工作流的节点分配结果，确认数据类型与模型匹配。
- 模拟接口波动场景，调用工具节点，查看是否触发重试机制并最终执行成功。
