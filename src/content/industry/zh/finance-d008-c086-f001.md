# 汽车服务智能尽调报告的HTTP 接口与外部系统

## 这个品类的数据长什么样
汽车服务智能尽调报告的数据主要来源于车辆管理部门登记系统、合作维修厂工单系统、合作保险机构理赔系统及二手车交易数据源。数据更新节奏存在差异：车辆基础登记信息实时同步，维修记录随工单完成更新，保险理赔数据于结案后24小时内同步，二手车交易数据每日批量更新。单份尽调报告文档结构固定，包含VIN码、注册日期、累计行驶里程、维修项目明细、理赔金额、过户次数等字段，其中里程单位为km，金额单位为元，过户次数为整数计数。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
多源异构数据源的接入需要兼容不同的鉴权协议，部分车管数据源仅支持OAuth2.0鉴权，维修厂接口则采用静态API密钥验证，需在HTTP接口配置中分别适配。不同更新节奏要求接口调用周期差异化配置，实时同步的登记数据需通过webhook触发拉取，批量更新的二手车数据需配置每日定时拉取任务。字段格式存在特殊要求，VIN码需校验17位字符规则，累计行驶里程可能存在空值，需在接口请求中配置字段校验与空值处理逻辑。单份尽调报告可能包含多笔维修明细，接口返回数据量较大，需调整分页参数以避免请求超时。批量导入大量尽调报告时，需适配单次上传的文档数量限制，避免触发内容长度超限错误。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_BATCH_SIZE` | `50–100 个/次` | 汽车服务尽调报告单份文档包含多笔维修明细，单次上传过多会触发`MAX_CONTENT_LENGTH`错误，该取值适配批量导入场景的合理负载 |
| `HTTP_SYNC_INTERVAL` | `实时/每日 按需配置` | 不同数据源更新节奏不同，实时登记数据配置`0 秒`拉取间隔，批量二手车数据配置`86400 秒`拉取间隔 |
| `API_AUTH_TYPE` | `OAuth2.0/API_KEY 按需选择` | 对接不同数据源需匹配对应鉴权方式，车管系统使用OAuth2.0，维修厂接口使用API_KEY |
| `VIN_VALIDATION_ENABLE` | `开启` | 汽车服务数据核心字段VIN码为17位固定格式，开启校验可过滤无效数据 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 单份尽调报告包含多笔维修明细，解析时长较长，需延长超时时间避免请求中断 |
| `MAX_RESPONSE_BODY_SIZE` | `10 MB` | 批量导入的尽调报告集合数据量较大，需调整响应体大小限制适配批量请求 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 发起批量导入请求时返回`413 Request Entity Too Large`错误。原因是未调整`UPLOAD_BATCH_SIZE`配置，单次上传的文档数量超过系统默认限制，同时未设置`MAX_RESPONSE_BODY_SIZE`适配批量数据。
- 嵌入业务系统后调用工作流HTTP接口返回`401 Unauthorized`错误。原因是未配置`WORKFLOW_HTTP_AUTH`参数，未将业务系统用户身份令牌带入请求头，导致FastGPT平台无法验证请求合法性。
- 对接SQL数据库查询车辆数据时返回`Empty Result Set`错误。原因是未配置正确的数据库表字段映射，或未在请求中带入VIN码等核心查询条件，导致无法匹配目标数据。

## 怎么确认配好了
- 发起一次单文档的HTTP导入请求，检查返回状态码为`200 OK`，且文档内容正确同步至知识库。
- 调用工作流HTTP接口，携带业务系统用户身份令牌，检查返回状态码为`200 OK`且能触发对应工作流。
- 执行SQL数据库查询请求，检查返回结果包含匹配VIN码的车辆数据，且字段格式符合预期。
- 发起批量导入测试，检查未触发`413`或`MAX_CONTENT_LENGTH`相关错误，且所有文档均成功导入。
