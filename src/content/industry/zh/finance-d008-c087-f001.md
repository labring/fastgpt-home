# 汽车零部件智能尽调报告的HTTP 接口与外部系统

## 这个品类的数据长什么样
汽车零部件智能尽调报告的数据主要来源于金融机构对接的企业内部供应链ERP系统、第三方零部件目录库、主机厂BOM清单及第三方质检机构报告。数据更新节奏随车型量产周期调整，量产车型的基础数据更新频率较低，新供应商、改款车型的零部件数据更新频率较高。单份尽调报告文档包含零部件编号、中英文名称、材质、尺寸公差、抗拉强度、适配车型、供应商信息、批次号等字段，字段单位多为毫米、兆帕、千克等工业通用单位，部分字段需附带检测报告编号作为关联标识。

## 这些特征在「HTTP 接口与外部系统」这一环带来什么约束
汽车零部件数据的多来源属性要求接口需兼容多种鉴权方式，适配不同企业内部系统的对接规范。字段的专业属性要求接口返回的字段需严格匹配行业通用命名，避免映射错误导致尽调报告内容失真。数据更新的非均匀节奏要求采用增量同步的对接逻辑，避免使用全量同步的方式，减少带宽占用与处理耗时。带单位的数值字段需额外校验格式，防止接口返回的单位与系统预设单位不匹配，影响后续分析与展示。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `API_REQUEST_TIMEOUT` | `600 秒` | 汽车零部件数据包含多维度质检参数，单接口返回数据量较大，需预留足够响应时间 |
| `SYNC_INCREMENTAL_FLAG` | `true` | 零部件数据按批次、改款更新，全量同步会占用过多带宽与处理资源 |
| `FIELD_MAPPING_RULE` | 按`零部件编号→part_no, 材质→material, 抗拉强度→tensile_strength`的格式映射 | 遵循行业通用字段命名规范，避免接口返回字段与系统预设字段不匹配 |
| `RESPONSE_VALIDATION_SCHEMA` | 按`{part_no: string, material: string, tensile_strength: number, unit: string}`配置 | 校验零部件数据的字段格式与单位合法性，防止无效数据流入尽调报告 |
| `AUTHENTICATION_TYPE` | `API_KEY` | 企业内部供应链系统多采用API密钥做接口鉴权，适配通用的外部系统对接场景 |
| `MAX_RETRY_TIMES` | `3 次` | 网络波动可能导致接口调用失败，有限重试可提升同步成功率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：API调用工作流时，文本拼接的变量字段为空，但调试阶段正常。原因：未在`API_REQUEST_BODY_TEMPLATE`中正确配置变量占位符的格式，导致外部调用时未传递对应参数。
- 现象：知识库返回的阅读链接点击后返回`Only support .txt, .m`错误。原因：未将外部系统返回的链接格式转换为符合平台要求的可访问格式，或链接未经过合法的签名校验。
- 现象：4.9.0版本调用外部接口时返回代理配置异常。原因：未在系统配置中启用`aiproxy`相关参数，或未正确配置代理的地址与端口。

## 怎么确认配好了
- 调用测试接口，检查返回的字段是否与预设的`FIELD_MAPPING_RULE`完全匹配。
- 模拟增量同步场景，检查仅更新的零部件数据是否被正确拉取。
- 触发多次接口调用，检查是否按`MAX_RETRY_TIMES`的配置进行重试。
- 验证鉴权配置，检查未携带合法密钥的调用是否被拦截。
