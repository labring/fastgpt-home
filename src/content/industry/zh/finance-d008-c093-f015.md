# 游戏智能尽调报告的部署与升级

## 这个品类的数据长什么样
游戏智能尽调报告的数据主要来源于游戏版号审批文件、研发进度文档、营收监测数据、用户行为报告及合规备案材料。数据更新节奏随项目阶段变化：版号信息按季度更新，研发进度随版本迭代实时更新，营收与用户数据按月度更新。单份报告文档结构包含版号编号、研发主体全称、上线备案时间、核心玩法描述、营收预估区间、注册用户规模字段，其中用户规模以“万”为单位，营收以“万元”为单位，版号编号采用国家出版主管部门统一格式。

## 这些特征在「部署与升级」这一环带来什么约束
游戏尽调报告的数据来源分散且更新频率差异大，部署环节需支持多数据源的批量接入配置，避免因单数据源故障影响全量报告生成。文档长度普遍较长，部分包含研发文档附件，需适配大文件上传与长文本解析的资源配置。字段结构存在自定义扩展需求，需支持自定义字段的存储与检索配置。更新环节需支持增量同步，避免全量重导带来的资源占用过高，同时需兼容不同版本的字段格式变更，防止升级后数据解析异常。此外，游戏项目的合规性数据需实时校验，部署时需配置实时接口调用的负载均衡策略，保障请求响应速度。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 游戏尽调报告可能包含研发文档、合规备案扫描件等大体积附件 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `900 秒` | 游戏尽调报告的长文本解析耗时较长，需延长超时阈值 |
| `分段长度` | `1000–1200 字符` | 游戏尽调报告字段较多，分段需覆盖完整字段组以保障检索完整性 |
| `LOAD_BALANCER_ENABLED` | `开启` | 需分摊多渠道模型的尽调报告生成请求，保障并发处理能力 |
| `split_mode` | `paragraph_first` | 适配v4.9.10版本的段落优先拆分模式，接口创建文本集合需指定该参数 |
| `ARM64_DEPLOY_SUPPORT` | `开启` | 适配华为openEuler Linux的arm64架构部署环境 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：部署在华为openEuler Linux的arm64架构环境时，容器启动失败，返回“unsupported platform”报错。原因：未开启arm64架构的部署配置项，默认仅支持x86架构。
- 现象：从v4.9.0升级到v4.9.10后，调用接口创建知识库集合返回400状态码。原因：未按新版本要求传递`split_mode`参数，旧版本接口参数格式不兼容。
- 现象：生成游戏尽调报告时出现请求超时，返回504状态码。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时阈值不足以覆盖长文本解析耗时。

## 怎么确认配好了
- 执行`docker ps`命令，查看所有FastGPT相关容器处于运行状态，确认arm64部署配置生效。
- 调用创建知识库集合的接口，传入`{"split_mode": "paragraph_first"}`参数，返回200状态码则参数配置正确。
- 上传一份包含研发文档附件的测试文件，查看解析日志，确认上传文件大小未触发`UPLOAD_FILE_MAX_SIZE`限制。
- 查看模型请求转发日志，确认多渠道模型的请求被均匀分摊，负载均衡配置生效。
