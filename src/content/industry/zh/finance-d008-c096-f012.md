# 焦炭智能尽调报告的模型接入与配置

## 这个品类的数据长什么样
焦炭相关尽调数据的来源包括大连商品交易所公开结算数据、沿海主要港口现货报价、钢铁行业协会采购统计、第三方大宗商品资讯平台的公开接口。更新节奏分为多个层级：现货价格每日更新，港口库存每两日更新，月度行业报告每月发布，期货结算价在每个交易日收盘后更新。数据文档包含结构化的CSV/Excel格式报表与半结构化的行业研报PDF，核心字段包括产地挂牌价（单位元/吨）、港口库存总量（单位万吨）、铁路发运量（单位万吨）、下游钢厂采购量（单位万吨），无自定义单位字段。

## 这些特征在「模型接入与配置」这一环带来什么约束
焦炭尽调数据的多来源、多更新节奏、混合格式与固定字段特征，对模型接入与配置带来多重约束。多平台公开接口的数据源要求配置多供应商的模型调用隔离规则，避免参数冲突；不同更新频率的数据源需匹配对应的定时调度参数，确保调用时机与数据更新节奏对齐；固定的字段与单位要求配置数据校验规则，过滤异常输入；混合的结构化与半结构化文档格式，需配置适配两种格式的解析节点，提升数据提取效率；长文档研报的存在，要求调整模型的上下文窗口参数，覆盖更长的输入内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `modelProviderConfig` | 为同一模型分配唯一UUID作为模型ID，不同供应商的同模型使用不同UUID | 符合平台对模型ID唯一性的要求，避免多供应商同模型的配置冲突 |
| `maxContextWindow` | 8000–16000 字符 | 覆盖焦炭尽调报告从每日现货简报到月度研报的多数输入长度需求 |
| `errorCatchEnable` | 开启 | 捕获模型请求的超时、空返回等报错，触发重试或异常告警流程 |
| `thinkingModeSwitch` | 默认开启，可通过节点参数临时调整 | 尽调报告生成需多步推理，默认开启思考可提升输出准确性，临时调整适配快速查询场景 |
| `apiRequestTimeout` | 30 秒 | 适配焦炭数据接口的稳定响应时长，避免无效等待 |
| `parseStructuredData` | 开启，指定字段映射规则 | 自动提取结构化报表中的核心字段，提升模型输入的精准度与效率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：模型节点返回状态码500，提示“model id duplicate”。原因：未为不同供应商的同模型分配唯一标识，导致平台无法区分不同供应商的配置。
- 现象：生成的尽调报告中未显示思考过程，但后台仍在执行推理步骤。原因：仅关闭了“显示思考”的界面开关，未调整控制推理逻辑的配置项。
- 现象：模型调用出现异常但无对应日志记录。原因：未开启`errorCatchEnable`参数，导致请求错误时未捕获异常，无法生成日志。

## 怎么确认配好了
- 进入模型供应商配置页面，核对同一模型在不同供应商下的ID是否唯一，确认配置已成功保存。
- 触发一次测试调用，查看日志中是否包含错误捕获的相关记录，验证报错处理逻辑生效。
- 上传一份焦炭月度研报，查看模型输入的内容长度是否符合预期，验证`maxContextWindow`配置生效。
- 调整`thinkingModeSwitch`参数，生成测试报告，确认思考过程的显示状态与配置一致。
