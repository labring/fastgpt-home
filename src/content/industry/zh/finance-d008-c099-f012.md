# 燃气智能尽调报告的模型接入与配置

## 这个品类的数据长什么样
燃气智能尽调报告的数据主要来自燃气运营企业的台账、管网巡检档案、气源采购协议、终端用气统计报表及属地监管部门的安全备案文件。数据更新节奏为月度运营数据按月更新，季度巡检档案每季度归档，年度合作协议及备案文件按周期更新。文档结构分为企业资质模块、管网参数模块、用气统计模块、安全巡检模块，字段包含管道公称直径（单位mm）、日均用气量（单位万立方米）、管网压力值（单位MPa）、巡检点位坐标等，单份完整报告的文本长度通常处于数万字符区间。

## 这些特征在「模型接入与配置」这一环带来什么约束
燃气尽调数据的多字段专业单位、长文本结构及分周期更新的特征，会对模型接入与配置环节带来多重约束。多字段带专业单位的结构，要求配置字段标准化映射规则，避免向量召回时的单位歧义。单份报告数万字符的长度，要求调整上下文窗口与分段参数，防止核心合规与运营数据被截断。分周期更新的数据源，要求配置增量同步的触发逻辑，匹配月度运营数据、季度巡检档案的更新节奏。经纬度类点位字段的向量建模需求，要求指定适配空间特征的embedding模型参数。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 适配单份燃气尽调报告数万字符的长度，避免核心合规与运营数据被截断 |
| `chunkSize` | `1500–2000 字符` | 覆盖燃气尽调报告中管网参数、用气统计等完整专业模块，避免拆分关键字段 |
| `embeddingModel` | `text-embedding-3-large` | 对结构化数值、专业单位及经纬度点位的向量表征效果稳定，适配燃气数据的专业特征 |
| `RECALL_TOP_N` | `前 8–10 条` | 覆盖资质、运营、安全三类核心数据模块，避免召回结果遗漏关键细分维度 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 适配单份完整燃气尽调报告的压缩包体积，预留合理缓冲空间 |
| `SYNC_INCREMENTAL_INTERVAL` | `720 小时` | 匹配月度运营数据的更新节奏，确保召回数据的时效性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：在4.9.12版本的平台中，调用知识库后输出内容包含“引用标记：［1］”字样。原因：未关闭知识库召回结果的引用标记输出开关，或未配置引用标记的自动过滤规则。
- 现象：上传燃气尽调报告后，部分经纬度字段为空或解析错误。原因：未配置针对经纬度格式的字段解析规则，或分段长度设置过小导致经纬度坐标被拆分截断。
- 现象：数据同步任务超时，返回状态码504。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，默认超时时间不足以处理数万字符的长文本报告解析。

## 怎么确认配好了
- 上传单份完整燃气尽调报告，检查解析后的字段列表是否包含预设专业字段，核对字段单位是否与原始数据一致。
- 发起一次测试调用，输入燃气尽调相关的查询，检查输出内容是否存在有效信息丢失，调整对应配置参数直至符合需求。
- 查看数据同步日志，确认增量同步任务按预设周期触发，且最新的运营数据已完成召回更新。
- 测试调用时检查输出内容，确认无多余的非预期标记，调整引用标记相关配置项直至符合要求。
