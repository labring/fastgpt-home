# 物流智能尽调报告的工作流编排

## 这个品类的数据长什么样
物流智能尽调报告的数据主要来自物流运单管理系统、仓储WMS系统、GPS定位终端、海关报关单及货运代理提单。数据更新节奏分两类：运单轨迹、揽收派送节点实时更新，仓储库存、报关核验信息按报关批次或每日固定时段更新。单份标准尽调报告通常包含运单编号、货物品类、实际重量（单位：千克/吨）、货物体积（单位：立方米）、始发地与目的地、运输方式、承运商资质、时效节点记录及异常处置记录等字段。

## 这些特征在「工作流编排」这一环带来什么约束
多源数据的接入需求要求工作流配置多个异构数据源对接节点，需分别适配运单API、WMS接口、PDF报关单解析工具的调用格式。实时轨迹数据的高频更新要求触发节点设置合理的拉取间隔，避免超出接口调用限额。字段单位不统一的问题要求编排中加入标准化转换环节，统一重量、体积的计量口径。部分异常记录字段存在缺失的情况，需在流程中加入空值校验与补全逻辑。PDF格式的报关单需先完成OCR解析，需在流程起始节点配置文件解析步骤。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `trigger_interval` | `300–1800 秒` | 平衡物流轨迹数据的实时性要求与接口调用限额，避免过于频繁触发超出限制，同时保证数据更新时效 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120 秒` | 覆盖PDF格式报关单的常规OCR解析时长，避免超时中断流程 |
| `HTTP_REQUEST_TIMEOUT` | `60 秒` | 适配跨区域承运商API接口的常规响应延迟，避免因网络波动导致请求失败 |
| `field_mapping_strategy` | 按字段名匹配+单位转换 | 适配物流数据字段命名的差异，统一重量、体积等核心字段的计量口径 |
| `max_retries` | `2–3 次` | 应对接口临时波动，避免重试过多占用调用配额 |
| `workflow_error_notify` | 触发异常时推送至指定Webhook | 满足物流尽调流程的时效性要求，异常发生时可及时通知处理人员 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 错误配置文件链接变量的绑定逻辑，导致解析节点无法读取目标文件。现象是节点日志显示「未找到指定文件」或返回空解析结果。原因是未将文件存储节点的输出变量正确绑定至解析节点的文件链接参数，或变量作用域配置错误。
- HTTP请求节点的body参数配置错误，导致接口调用失败。现象是返回400 Bad Request状态码，或接口返回「参数缺失」的报错文案。原因是误将文件链接的文件名作为参数名，未使用接口要求的参数名，且未正确传递文件的base64编码内容。
- 4.6.9版本编排中判断器节点未传递原始用户问题至后续AI对话节点。现象是AI对话节点返回的结果与初始尽调需求无关，无法匹配物流尽调的具体要求。原因是未将流程起始的用户输入变量绑定至AI对话节点的上下文参数，导致AI仅使用预设提示词生成内容。

## 怎么确认配好了
- 触发一次测试流程，查看各节点的日志输出，确认文件解析节点成功读取目标报关单或运单数据，无超时或解析失败提示。
- 调用测试接口，查看HTTP请求节点的返回结果，确认body参数与接口要求的参数名、参数值匹配，无参数缺失或格式错误。
- 针对4.6.9版本的编排界面，确认判断器节点的输出变量已正确挂载至AI对话节点的上下文参数，无变量作用域错误。
- 查看标准化后的字段数据，确认重量、体积等单位已统一为预设口径，无单位混乱问题。
