# 物流智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
物流智能尽调报告的数据主要来自物流企业的运单管理系统、仓储WMS系统、干线运输调度平台，以及公开的货运时效公示数据。数据更新节奏为单批次运单完成后实时更新，月度汇总数据按自然月结束后24小时内更新。文档结构以结构化表格为主，包含运单编号、始发地、目的地、运输方式、实际运输时长、签收状态、单件运费、总运输费用等字段，单位涵盖公里、件、元、小时等，部分场景会附带运输轨迹的时序数据。

## 这些特征在「工具调用与插件」这一环带来什么约束
物流智能尽调报告的数据多来源、实时更新且字段结构复杂的特性，对工具调用与插件环节带来多重约束。多系统数据源要求支持并行调用不同接口，避免单接口超时拖累整体流程。实时运单数据要求插件请求间隔适配业务更新节奏，防止数据滞后。字段多且单位多样的特点，要求工具调用时需配置明确的字段映射与单位转换规则，避免参数不匹配。时序运输轨迹的调用则需支持分页拉取，防止单次返回数据量过大触发系统限制。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `HTTP_REQUEST_TIMEOUT` | 600 秒 | 适配物流运单数据接口的平均响应时长，避免因接口调用超时导致任务失败 |
| `PLUGIN_PARALLEL_LIMIT` | 3 个 | 平衡多数据源调用的效率与系统负载，防止并发过高触发限流 |
| `FIELD_MAPPING_RULE` | 按接口返回字段名与尽调报告字段一一映射 | 匹配物流数据多字段的结构化特性，确保数据准确提取 |
| `UNIT_CONVERSION_SWITCH` | 开启 | 适配物流数据中公里、元、小时等多单位的统一转换需求，避免字段单位混乱 |
| `RESPONSE_PAGINATION_ENABLE` | 开启 | 适配运输轨迹等大体积时序数据的拉取，防止单次返回数据量超限 |
| `PLUGIN_CACHE_TTL` | 300 秒 | 匹配物流实时数据的更新节奏，平衡数据时效性与接口调用频率 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工具调用返回`504 Gateway Timeout`错误，但使用Postman调用对应接口可正常获取结果。原因是未在FastGPT的`HTTP_REQUEST_TIMEOUT`配置中设置足够长的超时时间，导致接口未完成响应就被强制中断。
- 现象为基础图表插件生成的物流尽调可视化结果缺少运输时效字段。原因是未配置`UNIT_CONVERSION_SWITCH`，导致插件无法正确转换公里、小时等单位，无法识别标准化后的字段内容。
- 现象为调用重排序插件时返回`false`结果，但接口调用日志显示返回了有效数据。原因是未开启插件的结果解析开关，导致插件无法将接口返回的结构化数据转换为可识别的输入格式。

## 怎么确认配好了
- 调用单条运单数据的测试接口，核对工具返回的字段与尽调报告要求的字段完全一致。
- 模拟批量运输轨迹数据的调用，检查插件是否自动分页拉取并完整返回所有数据。
- 查看插件运行日志，确认所有并发请求均在预设超时时间内完成响应。
- 生成可视化图表，检查所有物流数据的单位均已统一转换为报告要求的标准单位。
