# 特钢智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
特钢智能尽调报告的数据主要来自特钢生产企业内部ERP系统、第三方行业资讯平台公开披露数据、下游客户验收报告。更新节奏分为三类：生产工艺与出厂数据每日更新，行业统计数据周度更新，下游履约记录月度更新。单份报告的文档结构包含批次明细页、性能检测页、履约台账页三个核心模块，字段包含唯一批次标识、生产参数、检测指标、交货重量、履约周期，单位统一为公制单位，其中重量为吨，强度类指标为兆帕。

## 这些特征在「工具调用与插件」这一环带来什么约束
特钢数据的多源多周期更新特性，要求工具调用需配置多任务定时拉取，每个任务对应不同数据源的拉取间隔。嵌套的性能检测子字段与标准化公制单位，要求插件需支持结构化字段解析与格式校验，避免传入非标准单位数据。数据量随生产批次增长的特性，要求插件需配置分页拉取参数，防止单次请求数据量过大触发接口限流或超时。此外，特钢行业存在自定义字段命名变体，要求工具调用需支持字段映射配置，适配不同数据源的字段差异。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `plugin_api_timeout` | 300 秒 | 特钢尽调数据接口通常包含多批次检测数据，单次请求返回量较大，300秒可覆盖完整拉取流程 |
| `embedding_dimension` | 1024 | 适配bge-large-zh-1.5的嵌入维度，确保向量匹配精度，兼容同维度的其他嵌入模型 |
| `plugin_request_content_type` | application/json, application/x-www-form-urlencoded | 特钢数据源接口存在两种传参格式，支持双格式可适配不同第三方接口要求 |
| `plugin_pagination_size` | 500 条 | 单批次拉取数据量适配接口限流阈值，避免因单次请求数据过多触发限流 |
| `tool_call_max_retries` | 2 次 | 特钢数据源接口偶发波动，重试两次可覆盖大部分临时异常，避免重复拉取导致数据重复 |
| `parse_field_mapping` | 按实测标定 | 特钢行业字段命名存在自定义变体，需将接口返回字段映射为尽调报告标准字段 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用外部嵌入模型接口返回400错误，提示维度不匹配。原因：未指定与bge-large-zh-1.5一致的1024维嵌入参数，直接使用默认维度发起请求。
- 现象：插件发送请求后第三方接口返回参数解析失败。原因：未配置`plugin_request_content_type`为对应格式，仅使用默认的application/json，无法适配部分特钢数据源的application/x-www-form-urlencoded传参要求。
- 现象：前端调用智能问答接口返回502错误，本地测试正常但线上环境失败。原因：未配置接口跨域白名单，或未将线上域名添加至允许调用的域名列表中。

## 怎么确认配好了
- 查看插件执行日志，确认单次请求耗时未超过配置的`plugin_api_timeout`。
- 核对嵌入模型的调用日志，确认返回的向量维度与配置的`embedding_dimension`一致。
- 发起多轮工具调用测试，检查分页拉取的结果是否完整覆盖全量数据。
- 检查跨域配置，确认线上域名已添加至允许调用的域名列表中。
