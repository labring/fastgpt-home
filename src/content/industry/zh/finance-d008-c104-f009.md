# 玻璃智能尽调报告的引用来源与溯源

## 这个品类的数据长什么样
玻璃智能尽调报告的数据源主要包含批次出厂检测报告、供应链溯源台账、国家建筑材料行业标准文档。出厂检测报告随每批次玻璃生产完成同步更新，包含批次号、公称厚度、透光率、抗冲击强度等字段，单位为毫米、百分比、兆帕。供应链台账记录玻璃从生产厂到项目现场的流转节点，国家建筑材料行业标准文档每1-2年更新一次版本，格式多为PDF或结构化表格。

## 这些特征在「引用来源与溯源」这一环带来什么约束
玻璃品类的批次唯一标识特性，要求引用溯源环节必须绑定对应批次的检测报告与台账，无法通过通用关键词完成匹配。多字段带固定单位的检测数据，要求召回时需同时匹配字段名与单位，否则无法定位准确来源。供应链流转节点多的特征，要求溯源需关联生产、运输、验收等多环节文档，增加了召回范围的复杂度。行业标准文档版本更新频繁，要求溯源环节需校验文档版本，避免引用过时标准内容。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | `前6–10条` | 玻璃检测报告与台账文档内容较丰富，需覆盖多环节来源，避免遗漏关键溯源信息 |
| `相似度阈值` | `0.72–0.88` | 玻璃字段多且单位严格，需平衡召回精度与覆盖范围，避免误召回非对应批次的文档 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `240–360 秒` | 玻璃检测报告多为多页结构化文档，解析耗时较长，需预留足够解析时间 |
| `分段长度` | `700–1300 字符` | 玻璃检测数据字段紧凑，分段过长会丢失字段关联信息，过短则增加召回冗余 |
| `版本校验开关` | `开启` | 玻璃行业标准更新频繁，需校验引用文档的版本号，确保使用现行有效标准 |
| `引用源字段白名单` | `批次号、检测参数、流转节点` | 减少溯源展示的冗余信息，聚焦玻璃尽调核心溯源字段 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：界面显示引用源链接无法下载，返回404错误。原因：未配置本地文件存储路径或云存储权限，玻璃检测报告的结构化文件未正确同步至可访问目录。
- 现象：4.8.22版本中解析多页玻璃检测报告时，引用源列表丢失部分字段。原因：该版本的结构化解析插件对多页表格的字段提取存在兼容问题，需升级解析插件版本。
- 现象：召回结果包含非对应批次的玻璃检测报告。原因：相似度阈值设置过低，或未绑定批次号作为召回过滤条件，导致误召回其他批次的文档。

## 怎么确认配好了
- 上传单批次玻璃检测报告与对应供应链台账，触发尽调问答，核对返回的引用源是否包含对应批次的文档与流转节点信息。
- 调用获取引用源的API接口，检查返回字段是否包含预设的玻璃溯源核心字段，无缺失或冗余内容。
- 模拟行业标准版本更新，上传新版与旧版标准文档，验证溯源环节是否自动过滤旧版文档，仅展示现行有效版本。
- 调整相似度阈值，观察召回结果的批次匹配精度，确认符合业务对溯源准确性的要求。
