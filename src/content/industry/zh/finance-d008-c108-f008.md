# 电商服务智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
电商服务的尽调数据来源包括电商平台开放API、第三方经营数据接口，以及公开的店铺经营公示信息。核心经营指标按自然日更新，库存、实时流量数据每小时更新，资质文件随商家提交后同步更新。文档结构分为结构化字段包与附件包，结构化字段包含店铺主体信息、商品上架清单、经营流水明细，附件包含资质扫描件、物流合作协议等。字段单位方面，经营流水以「元」为单位，订单量以「单」为单位，资质编号、店铺ID为无单位字符串。

## 这些特征在「工具调用与插件」这一环带来什么约束
数据源多且更新频率不一，要求工具调用需区分实时指标与T+1指标的触发时机，避免因调用时机错误获取过期或未更新的数据。结构化与附件结合的文档结构，要求插件同时支持结构化数据拉取与非结构化文件解析，需配置两套不同的调用逻辑。字段单位不统一的特征，要求工具调用后需添加单位转换与标注规则，避免报告中出现金额、数量单位混乱的问题。多SKU、多条目的数据量特征，要求批量拉取工具需配置分页参数，控制单批次返回的数据量，避免超时或返回内容过载。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `customToolVars` | 绑定店铺ID、SKU范围、资质类型三类变量 | 电商尽调需按特定店铺或商品维度拉取数据，避免跨主体数据混淆 |
| `functionCallTriggerMode` | 按结构化数据拉取触发函数调用，附件解析单独触发 | 电商数据分结构化经营流水与非结构化附件，需区分调用逻辑 |
| `PARSE_FILE_TIMEOUT` | `600 秒` | 资质文件、物流协议等附件可能较大，解析耗时较长 |
| `batchPullSize` | `前 200 条` | 电商经营流水明细条目较多，批量拉取需控制单批次数据量避免超时 |
| `embeddingModelType` | 按实测标定 | 结构化字段与附件文本的向量表征需求不同，需匹配对应模型类型 |
| `maxContext` | `8000–12000 字符` | 电商尽调报告需整合多维度数据，上下文长度需覆盖完整的经营明细与资质内容 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
-  现象为调用工具后返回无关店铺的经营数据，原因是未在`customToolVars`中配置目标店铺ID变量，导致工具拉取了默认范围的全量数据。
-  现象为侧边栏找不到函数调用模块，原因是未在应用的功能配置中开启函数调用开关，或未使用支持工具调用的应用版本。
-  现象为调用VL模型解析商品资质图片时返回乱码，原因是未将VL模型的输入配置为图片URL，错误传入了文本字段，导致模型无法正确解析图像内容。

## 怎么确认配好了
- 在应用调试面板中输入自定义工具变量的测试值，触发工具调用，检查返回数据是否匹配目标店铺的信息。
- 开启函数调用开关后，查看侧边栏的工具模块是否显示，确认功能已启用。
- 上传一份电商资质附件，触发VL模型解析，检查返回的文本内容是否与附件内容一致。
- 调用embedding模型接口，传入电商经营流水的文本片段，检查返回的向量数据是否符合预期维度。
