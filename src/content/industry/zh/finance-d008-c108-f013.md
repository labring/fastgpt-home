# 电商服务智能尽调报告的知识库检索与召回

## 这个品类的数据长什么样
电商服务智能尽调报告的数据主要来自合作电商店铺的经营台账、合规备案文件、用户反馈记录。数据更新节奏为每日同步当日经营明细，每季度更新合规资质档案。文档结构包含结构化的店铺基础信息表、交易明细清单，以及非结构化的用户评价文本、资质扫描件。字段包含店铺唯一标识、经营类目、交易总笔数、合规凭证编号、用户反馈关键词等，部分字段的统计维度随店铺经营类目变化。

## 这些特征在「知识库检索与召回」这一环带来什么约束
电商服务尽调数据的结构化占比高且字段维度随类目变化，要求检索环节需支持按指定字段精准匹配，避免模糊召回导致无关结果混入。数据更新频率较高，需配置增量同步机制，确保召回的内容与店铺当前经营状态一致。非结构化的用户评价文本篇幅较短但数量庞大，需设置合理的分段长度，避免单段内容过长影响召回精度。同时，不同经营类目的店铺字段差异明显，需在召回前按类目维度过滤无关知识库条目，缩小检索范围。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `召回条数` | `前10-15条` | 电商尽调数据条目数量较多，过多召回会增加上下文处理压力，过少则可能遗漏关键经营或合规信息 |
| `相似度阈值` | `0.75-0.85` | 电商尽调数据多为精准匹配类字段，阈值过低会引入无关店铺的冗余数据，过高会导致合规凭证等关键信息召回失败 |
| `分段长度` | `800-1200字符` | 电商尽调中的非结构化评价文本多为短片段，过长分段会混入无关语义内容，过短则会破坏评价的完整语义 |
| `增量同步间隔` | `每6小时` | 电商经营数据更新频率较高，间隔过长会导致召回内容滞后于店铺当前状态，过短会增加服务器同步负载 |
| `多字段召回开关` | `开启` | 电商尽调数据包含店铺ID、经营类目、交易笔数等多维度字段，开启后可按多个字段同时匹配，提升召回精准度 |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600秒` | 电商尽调包含资质扫描件等大文件，600秒的超时设置可确保大文件完整解析，避免解析中断 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：知识库内的电商资质扫描件类图片全部加载失败，界面返回404状态码。原因：未配置图片资源的跨域访问权限，导致FastGPT无法从电商服务后台接口拉取图片文件。
- 现象：当知识库中无匹配的尽调条目时，工作流仍调用大模型生成回答，返回与目标店铺无关的内容。原因：未设置知识库为空时终止检索的触发规则，或触发条件配置错误。
- 现象：关闭“问题优化”界面开关后，召回结果仍被补充了非知识库内的信息。原因：未同步关闭全局上下文补全设置，或工作流中保留了自动补全的节点配置。

## 怎么确认配好了
- 上传一份电商店铺的经营台账文件，查看解析后的字段是否完整覆盖预设的检索维度，确认分段与解析结果符合配置要求。
- 模拟输入包含店铺唯一标识的检索请求，核对召回的条目数量、相似度是否符合预设的配置范围。
- 手动清空知识库测试数据，触发检索流程，确认工作流在无匹配条目时终止并返回预设提示。
- 检查知识库图片资源的访问日志，确认无404报错，FastGPT可正常拉取资质扫描件文件。
