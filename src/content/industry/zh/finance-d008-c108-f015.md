# 电商服务智能尽调报告的部署与升级

## 这个品类的数据长什么样
电商服务智能尽调报告的数据主要来自电商平台开放API、商家后台导出的运营报表、第三方电商合规监测工具。数据更新节奏分两类：交易流水、用户评价数据按小时同步更新，商品基础信息、商家资质文件按自然日更新。单份尽调报告文档结构包含商家主体信息、SKU清单、近90天交易数据、合规资质扫描件、用户差评聚类标签等字段，字段单位统一为元（交易金额）、件（库存数量）、条（评价数量）。

## 这些特征在「部署与升级」这一环带来什么约束
电商服务尽调数据的多源接入与高频更新特性，对部署环节提出并行数据同步的配置要求，需预留足够的并发处理资源。单份报告包含大量SKU条目与高清资质扫描件，单文档体积超出通用文档的平均水平，部署时需调整解析模块的内存分配阈值。升级环节需保证实时交易数据同步链路不中断，同时兼容旧版资质文件的解析逻辑，避免更新后出现历史数据解析失败。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 电商尽调报告包含大量SKU与高清资质文件，解析耗时远超通用文档 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 单份尽调报告的资质扫描件与交易数据汇总文件体积较大 |
| `VECTOR_DB_BATCH_INSERT_SIZE` | `500 条` | 小时级更新的交易数据条目较多，批量插入可提升同步效率 |
| `SYNC_DATA_INTERVAL` | `3600 秒` | 匹配交易流水数据按小时同步的更新需求 |
| `MAX_DOCUMENT_CHUNK_SIZE` | `1500 字符` | 适配SKU清单与交易数据的字段密度，避免分段过长影响召回精度 |
| `DB_CONNECTION_POOL_SIZE` | `20–30` | 支撑多源数据接入的并发请求量 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：本地开发环境部署时，数据库安装步骤自动跳转Docker Compose部署后出现连接超时报错。原因：未提前配置Docker镜像加速源，导致基础镜像拉取超时。
- 现象：删除知识库中文档数量较大的文件夹时，报错`timeout of 60000ms exceeded`。原因：未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，大文件夹内的文档批量删除触发默认超时限制。
- 现象：实时同步交易数据后，尽调报告的最新交易金额字段为空。原因：未配置`SYNC_DATA_INTERVAL`参数与数据源的更新频率匹配，导致同步链路中断。

## 怎么确认配好了
- 执行本地Docker Compose部署脚本，检查所有容器的启动状态，确认数据库、向量库、解析服务的端口未被占用。
- 上传一份包含1000条SKU的测试尽调报告，查看解析进度与日志，确认解析耗时未超出预设阈值。
- 配置小时级数据同步任务，等待1个同步周期后，核对数据源的最新交易数据是否同步至知识库。
- 删除包含500条文档的测试文件夹，查看操作日志，确认未触发超时报错。
