# 电子元件智能尽调报告的工作流编排

## 这个品类的数据长什么样
电子元件的数据源包含原厂公开规格书、授权分销商报价库、行业标准文档、海关通关数据与客户BOM清单。数据更新节奏分两类：原厂规格书按产品迭代周期更新，授权分销商报价数据每周同步，行业标准文档按年度修订。单份文档结构固定，包含封装类型、额定参数、工作温度范围、引脚参数、合规标识等字段，参数单位多为欧姆、法拉、摄氏度、毫米等物理单位，部分字段附带公差标注。

## 这些特征在「工作流编排」这一环带来什么约束
电子元件数据的多源异构特征要求工作流配置多节点并行拉取不同数据源，避免单源数据滞后或缺失。不同数据源的更新节奏差异，要求工作流设置差异化的定时触发间隔，例如原厂规格书数据每7天拉取一次，报价数据每24小时同步。固定的文档结构但多物理单位字段，要求工作流加入参数校验节点，自动识别单位并转换为统一格式，避免后续分析出现单位不匹配的问题。多字段的批量处理需求，要求工作流配置批量解析节点，支持按字段分组提取关键信息，适配电子元件尽调报告的结构化输出要求。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 电子元件规格书通常包含大量引脚参数与合规细节，解析时长较长，600秒可覆盖完整解析流程 |
| `UPLOAD_FILE_MAX_SIZE` | `500 MB` | 单份原厂规格书合集或批量BOM清单的体积通常不超过500 MB，避免上传超时 |
| `maxContext` | `800–1200 字符` | 电子元件参数字段多为短文本，该区间可完整覆盖单组参数的上下文信息，避免截断关键数据 |
| `召回条数` | `前 8 条` | 电子元件尽调需覆盖封装、参数、合规三个核心维度，前8条可覆盖主流供应商的有效信息 |
| `相似度阈值` | `0.75` | 电子元件型号命名规则统一，0.75可准确匹配同型号不同批次的参数数据，避免误匹配相似型号 |
| `WORKFLOW_TRIGGER_MODE` | `按文件上传触发` | 电子元件尽调通常以用户上传的BOM清单或规格书为起点，按上传触发可自动启动解析流程 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 调用API触发工作流时返回`400 Bad Request`错误，提示`missing required field: kb_id`。原因是未在API请求体中正确传入全局知识库ID，仅在平台设置中配置全局变量未同步至工作流触发参数。
- 配置文档上传解析节点后，部分电子元件参数字段为空。原因是未设置字段映射规则，工作流未按电子元件文档的固定结构提取对应字段，导致关键参数未被抓取。
- 工作流执行超时，无法完成批量电子元件规格书的解析。原因是未调整`PARSE_FILE_TIMEOUT_SECONDS`参数，沿用通用品类的低时长配置，无法覆盖电子元件文档的复杂解析需求。

## 怎么确认配好了
- 调用工作流触发API，检查请求体中是否包含`kb_id`字段，且字段值与平台配置的全局知识库ID一致。
- 上传一份标准电子元件规格书，查看解析后的字段是否覆盖封装类型、额定参数、合规标识等核心内容。
- 查看工作流执行日志，确认多源数据拉取节点是否按预设间隔同步数据，无失败重试记录。
- 调整测试用例的参数单位，确认工作流的参数校验节点可自动识别并转换单位，无报错。
