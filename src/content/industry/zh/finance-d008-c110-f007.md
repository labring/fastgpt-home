# 电网设备智能尽调报告的工作流编排

## 这个品类的数据长什么样
电网设备数据主要来自设备出厂质检档案、电网运维巡检台账、在线监测系统及行业设备档案库。静态档案如出厂参数随设备投产更新一次，运维巡检数据按每日或每周频次同步，在线监测数据实时推送。单份尽调文档结构包含设备基础信息、运行参数、缺陷记录、检修历史四类模块，字段含额定电压（单位kV）、运行时长（单位小时）、绝缘电阻（单位MΩ）、缺陷等级等。

## 这些特征在「工作流编排」这一环带来什么约束
电网设备数据的静态与动态混合、多源异构的特征，对工作流编排带来三项核心约束。其一，需区分静态档案调用与实时监测数据拉取的触发时机，避免超时或数据滞后；其二，多字段带专属单位，需在工作流中配置单位标准化转换节点，确保不同来源数据的字段可对齐；其三，单份尽调文档字段数量较多，需限制单轮上下文长度，防止模型输出冗余或超出上下文窗口。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | 8000–12000 字符 | 电网设备尽调文档字段多、单份数据量较大，需匹配足够上下文窗口容纳多模块数据 |
| `召回条数` | 前6–8条 | 单份设备档案包含多类参数，召回过多会导致上下文溢出，过少则丢失关键检修记录 |
| `相似度阈值` | 0.75–0.85 | 需区分同型号设备的不同批次档案，阈值过低会引入无关设备数据，过高则无法匹配同型号的运维记录 |
| `PARSE_FILE_TIMEOUT_SECONDS` | 300 秒 | 出厂质检报告多为PDF格式，页数较多，需预留足够解析时间 |
| `工具调用超时时间` | 120 秒 | 在线监测数据需实时拉取，超时会导致尽调报告缺失最新运行参数 |
| `变量映射规则` | 按字段单位对齐 | 不同来源的额定电压字段可能标注为kV或V，需通过变量映射统一为kV单位，确保数据一致性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象为工作流中工具调用模块状态显示为未执行，无工具调用日志。原因是未在工作流中配置工具调用的触发条件，或工具的绑定权限未关联当前工作流。
- 现象为知识库检索节点返回空数组，或召回内容包含非目标电网设备的档案。原因是未将设备唯一标识作为检索关键词传入知识库模块，或未配置针对电网设备档案的检索过滤规则。
- 现象为代码执行模块抛出ModuleNotFoundError，或下游节点接收的变量值为空。原因是代码执行依赖的第三方库未安装到FastGPT容器的全局Python环境，或未在工作流中配置变量的映射与传递规则。

## 怎么确认配好了
- 手动触发工作流，查看工具调用模块的日志，确认所有绑定的工具均被正常调用，无超时或未执行记录。
- 检索知识库模块，输入单台电网设备的型号，核对召回的档案内容是否包含该设备的基础参数、运维记录，数量符合配置的召回条数要求。
- 运行代码执行模块，验证依赖库是否可正常导入，变量传递是否符合预设的映射规则。
- 生成单份尽调报告，核对报告中的字段单位是否统一，是否包含所有配置的必填模块内容。
