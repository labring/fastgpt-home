# 畜禽养殖智能尽调报告的工作流编排

## 这个品类的数据长什么样
畜禽养殖尽调数据主要来源于养殖企业的批次养殖档案、官方畜牧检疫平台的公开记录、饲料采购台账与防疫日志。数据更新节奏覆盖日度存栏变动、周度防疫记录、月度出栏计划。文档以养殖批次为核心单元，包含耳标编号、品种、养殖周期（天）、饲料消耗（千克）、疫苗接种次数、检疫合格状态等字段，字段绑定明确的物理单位，无模糊数值表述。

## 这些特征在「工作流编排」这一环带来什么约束
养殖数据按批次拆分的结构要求工作流必须配置分组节点，确保同批次的档案、检疫证明、台账数据统一整合。多频次的更新节奏要求工作流支持定时触发与增量拉取，避免重复处理全量历史数据。明确的字段单位要求工作流嵌入校验节点，对饲料消耗、养殖周期等字段的单位与数值合法性进行验证。多类型文档的混合输入要求工作流先做文件解析与字段提取，再进入知识库召回与尽调内容生成环节。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `workflow_trigger_type` | 按`schedule + incremental_update` | 匹配畜禽养殖数据按日/周增量更新的节奏，减少冗余计算 |
| `batch_split_rule` | 按`ear_tag_id`分组 | 对应养殖档案按批次（耳标ID）拆分的文档结构，确保同批次数据统一处理 |
| `similarity_threshold` | 0.75–0.85 | 适配畜禽养殖专业术语的密度，过滤低相关的知识库召回结果 |
| `HTTP_REQUEST_TIMEOUT` | 600 秒 | 适配养殖数据解析、检疫证明OCR的长耗时场景，避免中途超时 |
| `rag_top_k` | 前3条 | 控制合规校验、专家解读的知识库召回条数，避免冗余信息干扰尽调结论 |
| `fallback_response_config` | 触发预设合规提示文案 | 匹配用户提问与知识库无关时的分支处理要求，确保尽调报告的合规性 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：HTTP节点返回`400 Bad Request`，自定义变量未被正确解析。原因：未在工作流变量映射面板中绑定养殖数据的字段名，导致接口无法识别传入参数。
- 现象：尽调报告内容未按业务制度、专家解读、合规校验分类展示，不同知识库的召回结果混杂。原因：未在工作流中设置按知识库标签分流的分支节点，导致召回结果未做归类处理。
- 现象：工作流运行超过预设时长后触发超时报错。原因：未针对畜禽养殖的长文档解析、多批次数据处理调整超时阈值，导致批量任务无法完成。

## 怎么确认配好了
- 触发一次测试工作流，查看变量映射面板，确认养殖数据的字段已正确绑定到HTTP节点的输入参数中。
- 模拟与知识库无关的测试提问，确认工作流触发预设的fallback回复，此时不调用知识库生成内容。
- 查看工作流运行日志，确认每个批次的养殖数据均被正确分组处理，未出现超时或字段缺失的报错。
- 导出测试版尽调报告，确认内容按业务制度、专家解读、合规校验的分类正确展示，对应不同知识库的召回结果。
