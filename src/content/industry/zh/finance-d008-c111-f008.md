# 畜禽养殖智能尽调报告的工具调用与插件

## 这个品类的数据长什么样
畜禽养殖智能尽调的数据主要来自规模化养殖场的养殖台账、畜禽防疫档案、出栏检疫证明、饲料采购记录，以及养殖环节物联网监测设备的实时数据。数据更新节奏分两类：养殖台账、免疫记录按每日或批次更新，检疫证明、出栏检测报告随出栏批次同步更新。单份尽调文档包含批次畜禽品种、存栏量、饲料消耗总量、免疫日期、疫病检测结果等字段，存栏量单位为头或羽，饲料消耗单位为千克或吨，免疫日期采用YYYY-MM-DD格式。

## 这些特征在「工具调用与插件」这一环带来什么约束
畜禽养殖数据的多源异构特征，要求工具调用插件支持结构化表格、非结构化文档、图片类检疫证明的混合解析，需适配不同数据源的接口格式。批次化的数据结构要求工具调用必须传入批次号作为过滤参数，避免跨批次数据混淆。实时物联网监测数据的高频更新，要求插件支持按小时级定时拉取的配置。字段单位的多样性，要求工具调用模块内置单位转换逻辑，或允许传入单位映射参数，确保下游分析的字段一致性。同时，不同类型数据的更新节奏差异，要求插件调用周期需匹配对应数据的更新频率，避免拉取过时或未更新的数据。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `UPLOAD_FILE_MAX_SIZE` | `200 MB` | 畜禽养殖尽调文档包含多份批次报告、高清检疫图片，单份上传文件最大可设为200 MB |
| `PARSE_FILE_TIMEOUT_SECONDS` | `120 秒` | 多份畜禽养殖文档合并解析时，需处理表格提取、OCR识别，120秒可覆盖多数常规解析场景 |
| `apiCollection.max_retries` | `2 次` | 畜禽数据源接口可能受养殖场网络波动影响，2次重试可覆盖临时网络异常场景 |
| `toolCall.input_mapping` | 按批次号、检测日期过滤字段 | 畜禽养殖数据按批次和日期区分，需将用户输入的尽调需求映射为对应批次的查询参数 |
| `multimodal_parse.enable` | 开启 | 畜禽尽调包含检疫证明图片、免疫记录手写文档等非结构化多模态数据，需启用多模态解析 |
| `toolCall.output_filter` | 仅返回存栏量、饲料消耗、疫病结果字段 | 畜禽尽调需聚焦核心业务字段，过滤无关冗余信息 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：调用`apiCollection`接口时返回`Invalid URL, code: 500`报错。原因：未正确配置畜禽养殖数据源的API基础地址，或传入的批次查询参数未匹配接口要求的格式，导致接口无法正常解析请求。
- 现象：上传畜禽检疫证明图片时返回`400 InternalError.Algo.InvalidParameter: Multimodal file size is`报错。原因：上传的图片文件超过了配置的多模态文件大小阈值，或未开启多模态文件解析开关导致格式校验失败。
- 现象：用户输入文字为“分享”，传入工具调用后变为“分交”。原因：工具调用的输入参数未经过输入校验或预处理，未过滤输入中的形近字混淆或转写误差，导致字段映射错误。

## 怎么确认配好了
- 上传畜禽养殖尽调的典型文档，核对解析结果是否包含批次号、存栏量、饲料消耗等核心业务字段，确认多模态解析功能是否按配置启用。
- 传入测试批次号调用工具插件，核对返回结果是否仅包含预设的核心字段，确认输出过滤规则是否按配置生效。
- 模拟临时网络异常场景调用工具接口，核对是否触发了配置的重试次数，确认重试逻辑是否正常运行。
- 上传超出常规文档大小的测试文件，核对系统是否按配置拦截超出阈值的上传请求。
