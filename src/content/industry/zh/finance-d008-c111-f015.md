# 畜禽养殖智能尽调报告的部署与升级

## 这个品类的数据长什么样
畜禽养殖尽调数据来源包括养殖主体日常台账、属地农业农村部门月度监测报表、第三方畜牧监测机构公开数据；更新节奏分两类：基础存栏、出栏数据按周更新，防疫、成本类数据按月更新；文档结构多为结构化表格搭配文字说明，核心字段包含养殖主体名称、存栏量（单位：头/羽）、出栏周期（单位：天）、饲料采购总量（单位：吨）、防疫批次、单头养殖成本（单位：元/头）；部分历史文档为扫描件格式，需经OCR识别后提取结构化字段。

## 这些特征在「部署与升级」这一环带来什么约束
畜禽养殖尽调数据的多来源、分频率更新、字段单位差异及格式混合特征，对部署与升级环节带来多重约束。需同时对接结构化台账、扫描件报表、第三方API三类数据源，部署阶段需配置OCR识别与结构化解析模块；周度存栏数据与月度成本数据的更新节奏差异，要求升级时兼容多频率定时同步任务的调度逻辑；不同养殖主体的存栏单位存在局部差异，需预设单位转换映射规则；部分数据源部署在内网环境，需提前配置内网访问权限，避免升级后同步中断。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| --- | --- | --- |
| `PARSE_FILE_TIMEOUT_SECONDS` | `600 秒` | 畜禽养殖尽调报告常包含扫描件OCR与多表格解析，耗时较长，600秒可覆盖完整解析流程 |
| `UPLOAD_FILE_MAX_SIZE` | `2000 MB` | 规模化养殖的月度报表包含多批次防疫记录扫描件，单文件体积可达1.5GB以上 |
| `SYNC_CRON_EXPR` | `0 0 2 * * *`、`0 0 4 * * *` | 周度存栏数据需在每周二凌晨同步，月度成本数据需在每月4日凌晨同步，适配双频率更新节奏 |
| `FIELD_UNIT_MAPPING` | `{"存栏量": ["头", "羽"], "单头成本": "元/头"}` | 不同养殖主体的存栏单位存在局部差异，需预设转换规则统一字段格式 |
| `INTRANET_ACCESS_ENABLE` | `true` | 多数养殖主体的数据源部署在内网环境，需开启内网访问权限以保障数据同步 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：执行`git pull`拉取最新代码升级至4.9.0版本后，服务启动失败。原因：未提前适配新版本的配置项默认值，原有的`PARSE_FILE_TIMEOUT_SECONDS`参数配置与新版本校验规则冲突。
- 现象：执行Docker build命令时出现`ERROR: failed to solve: archive/tar: unknown file mod`报错。原因：导入的养殖尽调报告扫描件包含非标准文件权限的嵌入资源，打包镜像时未过滤异常权限文件。
- 现象：API请求返回`404 - 未找到资源`错误。原因：未配置内网数据源的访问白名单，或定时同步任务的`SYNC_CRON_EXPR`参数格式错误导致服务未触发数据拉取。

## 怎么确认配好了
- 执行本地文件解析测试，上传一份包含扫描件和结构化表格的养殖尽调报告，核对解析耗时是否符合预设的`PARSE_FILE_TIMEOUT_SECONDS`参数范围。
- 手动触发一次定时同步任务，检查数据源的拉取日志是否显示周度、月度数据均成功同步。
- 查看字段映射配置页面，确认`FIELD_UNIT_MAPPING`参数已覆盖所有需要转换的单位字段。
- 在内网环境下测试数据源访问，确认`INTRANET_ACCESS_ENABLE`参数开启后可正常拉取数据。
