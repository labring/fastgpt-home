# 耐火材料智能尽调报告的多轮对话与提示词

## 这个品类的数据长什么样
耐火材料智能尽调报告的数据主要来自行业标准规范文档、生产厂商的出厂质检文件、窑炉运行工况监测数据。更新节奏分为两类：行业标准文档按季度或年度更新，厂商质检文件随生产批次同步更新，工况数据实时采集。文档结构通常包含材质标识、理化性能参数、应用适配范围、检测编号与生产批次信息。字段与单位存在明确规范，例如耐火度以摄氏度为单位，体积密度以克每立方厘米为单位，应用温度区间以温度范围标注。

## 这些特征在「多轮对话与提示词」这一环带来什么约束
耐火材料的数据来源分散且格式差异明显，多轮对话需关联不同来源的参数信息，提示词需明确区分行业标准、厂商质检与工况监测类文档的召回规则。不同数据的更新节奏差异较大，实时工况数据需高频更新召回，行业标准文档需固定引用，提示词需配置优先级区分机制。字段与单位存在明确规范，多轮对话中需统一单位转换逻辑，避免参数混淆，提示词需强制指定参数的标准单位格式。文档包含生产批次与检测编号，多轮追问需关联对应标识匹配精准参数，提示词需加入标识筛选指令。

## 配置怎么定
| 配置项 | 建议取法 | 这样取的依据 |
| ---- | ---- | ---- |
| `maxContext` | `8000–12000 字符` | 耐火材料尽调报告需关联多组理化参数与批次信息，足够的上下文窗口可保留多轮追问的关联逻辑 |
| `recall_top_k` | `前 8–12 条` | 耐火材料文档包含多维度参数，需召回足够数量覆盖材质、检测、工况等不同字段 |
| `similarity_threshold` | `0.75–0.85` | 过滤与目标材质无关的冗余文档，避免多轮对话中出现答非所问的结果 |
| `prompt_template_custom` | 优先引用行业标准参数，结合生产批次与检测编号筛选目标文档 | 耐火材料数据来源差异明显，明确提示词规则可统一多轮对话的召回与引用逻辑 |
| `parse_chunk_size` | `600–800 字符` | 耐火材料文档的理化参数段落较长，该分段长度可保留参数组的完整性，避免拆分后关联断裂 |
| `tool_call_context` | 保留前 3 轮对话的参数上下文 | 多轮追问需关联之前提及的生产批次与检测编号，传递上下文可保证追问逻辑连贯 |

> 本页给出的参数取值均为常规建议，用于确定配置的起点。实际取值受材料形态、数据量与业务规则影响，具体问题需具体分析，建议在自有样本上实测后再定。

## 容易做错的三处
- 现象：多轮对话中第二个问题开始答非所问，无法关联前一轮提及的生产批次。原因：未配置`maxContext`参数或取值过小，未保留足够的对话上下文。
- 现象：无法指定召回特定厂商的质检文档，模型随机召回无关内容。原因：未在自定义提示词中加入文档来源或批次的筛选指令，或`similarity_threshold`设置不合理。
- 现象：无法使用自定义提示词模板，界面无对应配置项。原因：使用的开源版本低于`V4.9.0`，该功能在低版本中未开放。

## 怎么确认配好了
- 发起两轮连续追问，先查询指定生产批次的耐火材料理化参数，再基于该批次发起进一步的工况适配查询，核对模型是否关联前一轮提及的批次信息。
- 尝试指定特定文档类型或来源发起查询，核对模型是否仅召回对应类别的文档内容。
- 检查当前使用的开源版本，确认自定义提示词、上下文保留等配置项处于可编辑状态。
- 查看单次对话的召回结果条数，调整对应配置项的取值以覆盖所需的参数维度。
